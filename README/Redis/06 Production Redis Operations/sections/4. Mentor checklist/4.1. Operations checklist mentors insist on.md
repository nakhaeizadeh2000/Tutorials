## 1. Every instance is observable (INFO scraped — blind production returned)

**Definition** — the visibility line on every instance: INFO scraped ([1.1](<../../sections/1. Observe/1.1. Observability with INFO and metrics.md>)) — sections polling (server/clients/memory/persistence/stats — gauges trending (thresholds alerting — lead time growing); SLOWLOG reading ([1.2](<../../sections/1. Observe/1.2. Slow log and latency diagnosis.md>) — culprits naming (durations stating — fixes placing (profiling targeting — blindness declining); hit rates justifying (effectiveness numeric — caches earning (misses alerting — losers retiring). "Observable" means a reviewer can point at any instance and open its dashboards (metrics graphed — thresholds firing — blindness absent).

**What problem it solves** — the blind-production trio: *sections unscraped* (INFO unpolled (gauges untrended — thresholds unfiring (visibility absent — lead time zero (incidents immediate — context missing); *slowness unattributed* (SLOWLOG unread (culprits hiding — fixes random (profiling blind — evidence absent (guesses optimizing — remedies missing); *effectiveness unmeasured* (hit rates unknown (caches assuming worth — RAM burning (value unproven — losers subsidizing (retirement never — waste structural). Observed instances converting blindness to lead time (sections trending — culprits naming — effectiveness proving); reviewers checking dashboards, not confidence (visibility graphed → verifiable; healthy-hoped → returned).

**Modern guidance** — the visibility lines per instance (review-enforced): *INFO polling* (sections scraping — gauges trending (thresholds alerting — lead time growing (incidents preventing — surprises eliminating); *SLOWLOG reading* (entries reviewing — culprits naming (fixes placing — profiling targeting (blindness declining — evidence driving); *rates justifying* (hits trending — misses alerting (caches earning — losers retiring (effectiveness numeric — value proving); *blind returning* (unscraped instances failing review (visibility demanded — dashboards required (production observing — hope declining).

```bash
# GOOD: visibility graphed — sections polling, culprits naming, effectiveness proving (shapes verified).
# INFO scraped per subsystem (gauges trending — thresholds alerting — lead time growing, incidents preventing)
# SLOWLOG reviewed per spike (culprits naming — fixes placing — profiling targeting, blindness declining)
# Hit rates justifying per cache (effectiveness numeric — losers retiring — value proving, waste ending)
```

```bash
# BAD: production blind — sections unscraped, slowness unattributed, effectiveness unmeasured (real failure shapes).
# INFO unpolled (lead time zero — incidents immediate — context missing (visibility absent — thresholds unfiring).
# SLOWLOG unread (fixes random — guesses optimizing — evidence absent (profiling blind — culprits hiding).
# Caches assuming worth (RAM burning — losers subsidizing — retirement never). Scrape; read; justify.)
```

**Common confusion** — *"dashboards equal observability (graphs proving health)."* Dashboards displaying (metrics graphing — visibility surfacing (trends watching — thresholds firing (lead time growing — incidents preventing); thresholds deciding (alerts paging — humans acting (signal firing — noise declining (fatigue managing — attention investing); runbooks responding ([3.1](<../../sections/3. "Equal" describing displays (graphs surfacing — visibility starting); observability describing loops (metrics → thresholds → runbooks (sensing deciding acting — health managing). Graph metrics (visibility surfacing); close loops (thresholds paging — runbooks executing).

**Performance note** — visibility economics: INFO costing microseconds (sections polling — gauges trending (lead time growing — incidents preventing); SLOWLOG costing comparisons (culprits naming — fixes placing (profiling targeting — blindness declining); dashboards costing scrapes (metrics graphing — visibility surfacing (trends watching — thresholds firing); blind equivalents costing surprise incidents (lead time zero — recovery improvising). Observe cheaply (microseconds — visibility); loop fully (metrics → runbooks — health managing).

**Mentor note** — teach "no dashboard, no deploy" (juniors scraping INFO per instance design observed production on first hearing; blind instances interrogated ("graphs where?" — visibility demanded per instance). Review drill: new instance without dashboards returned automatically (observability structural — checklists enforced, never remembered). Scrape sections; close loops — visibility discipline in two habits, reviewed per instance.

## 2. Every instance is bounded (memory/timeouts/maxclients — unbounded operation scheduled never)

**Definition** — the bound line on every instance: memory + connections + clients capped ([2.1](<../../sections/2. Tune/2.1. Memory and encoding tuning.md>)/[2.2](<../../sections/2. Tune/2.2. "Bounded" means a reviewer can point at any instance and read its limits (memory/timeouts/clients stated — unbounded failing review structurally).

**What problem it solves** — the unbounded trio: *memory unconfigured* (maxmemory unset (killer murdering — processes dying (retention deciding — crashes scheduling (policy absent — murder governing); *connections leaking* (timeouts zero (dead lingering — fds exhausting — limits approaching (reaping absent — discipline declining (visibility delayed — rejections looming); *clients flooding* (maxclients unexamined (connections multiplying — pressure building (availability threatening — bounding missing (saturation hoping — culls absent). **Modern guidance** — the bound lines per instance (review-enforced): *memory capping* (maxmemory setting — eviction composing (murder declining — retention deciding (policy owning — crashes preventing (safety structuring — cliffs forecasting); *timeouts setting* (quiet closing — fds bounding (dead recycling — leaks capping (discipline enforcing — resources freeing (permissiveness examining — negligence declining); *clients capping* (maxclients bounding — floods limiting (pressure bounding — availability preserving (saturation alerting — culls acting (rejections declining — service sustaining); *defaults examining* (zeros justifying — policies matching (workloads calibrating — negligence declining (honesty explicit — discipline designing).

# timeout 0 unexamined (dead lingering — fds exhausting — limits approaching (reaping absent — discipline declining).

**Common confusion** — *"bounds constrain growth (limits capping success)."* Bounds protecting availability (eviction sustaining — timeouts recycling (service serving — pressure relieving (limits guarding — growth continuing (protection enabling — success sustaining); unbounded risking murder (killer deciding — processes dying (availability destroying — growth ending (limits absent — protection voiding); bounds raising deliberately (limits renegotiating — capacity adding (growth accommodating — purchases timing (protection scaling — success funding). "Constrain" describing unexamined caps (limits choking — growth throttling); deliberate bounds describing protection (availability sustaining — growth continuing). **Performance note** — bound economics: maxmemory costing policy CPU (availability sustaining — murder declining (retention deciding — policy owning); timeouts costing cycle checks (fds bounding — dead recycling (discipline cheap — resources freeing); maxclients costing counter checks (floods limiting — pressure bounding (availability preserving — rejections declining); unbounded equivalents costing murder + leaks + floods (availability destroying — pressure peaking). **Mentor note** — teach "every finite resource, a bound" (juniors capping memory/timeouts/clients design bounded operation on first hearing; unbounded instances interrogated ("limit where?" — bounds demanded per instance). ## 3. Every failure has a runbook (procedures written — improvisation priced, never planned)

**Definition** — the procedure line on every failure class: runbooks written ([3.1](<../../sections/3. Runbooks/3.1. **What problem it solves** — the unscripted trio: *improvisation planned* (incidents extemporizing (steps inventing — order discovering (stress deciding — quality varying (recovery gambling — practice absent (procedures missing — panic directing); *owners unnamed* (incidents paging nobody (responsibility diffusing — responses delaying (escalation wandering — decisions stalling (ownership absent — action hoping); *drills undated* (procedures aging (systems evolving — evidence expiring (confidence decaying — demonstrations dating (honesty perishing — proof lapsing). **Modern guidance** — the procedure lines per failure class (review-enforced): *steps ordering* (runbooks sequencing (drains settling — promotions directing (relief compounding — improvisation declining (recovery executing — panic ending); *owners naming* (responders designating (responsibility owning — responses speeding (escalation directing — decisions landing (ownership explicit — action guaranteeing); *drills dating* (rehearsals scheduling (evidence freshening — procedures proving (confidence earning — demonstrations recurring (honesty continuing — hope declining); *improvisation pricing* (extemporizing costing (quality varying — recovery gambling (practice absent — panic directing (unscripted failing — incidents teaching).
