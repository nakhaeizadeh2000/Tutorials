# 5.1. Common interview QA operations

## 1. Observability live (INFO sections, hit rates, saturation — measured answers, not vibes)

**Definition** — the observability answer interviewers grade: given a production Redis, name what's measured with numbers ([1.1](<../../sections/1. Observe/1.1. Observability with INFO and metrics.md>)) — INFO sections scraped (server/clients/memory/persistence/stats — gauges trending (thresholds alerting — lead time growing); hit rates computed (hits/misses justifying — caches earning (misses alerting — losers retiring); saturation tiered (70/85/95 memory — maxclients-nearing — lag-breaching (pages actionable — cliffs forecasting). "Under pressure" means follow-ups demand numbers (hit rate? memory headroom? blocked clients? — answers measured, never vibed).

**What problem it solves** — the vibes-answer trio: *metrics recited without numbers* (INFO named (sections unlisted — gauges unstated (follow-ups collapsing — pressure revealing recitation (understanding absent — monitoring unjustified); *effectiveness unpriced* (hit rates unmentioned (caches assuming worth — RAM burning (value unproven — losers subsidizing (retirement never — waste structural); *saturation unowned* (thresholds unstated (cliffs undiscovered — lead time zero (incidents surprising — paging absent (alerts hoping — prevention missing). Measured answers converting vibes to numbers (sections listing — rates computing — thresholds tiering); interviewers grading measurement (numbers + trends + pages → hired; healthy-hoped → rejected).

**Modern guidance** — the observability lines (interview-enforced): *sections listing* (INFO scraping — gauges trending (thresholds alerting — lead time growing (visibility continuous — surprises eliminating); *rates computing* (hits/misses justifying — caches earning (misses alerting — losers retiring (effectiveness numeric — value proving); *saturation tiering* (70/85/95 paging — maxclients watching (lag bounding — pages actionable (cliffs forecasting — incidents preventing); *follow-ups answering numerically* (rate? headroom? blocked? — numbers stating (trends showing — pages linking (measurement owning — vibes declining).

```bash
# GOOD: observability measured — sections listing, rates computing, saturation tiering (interview-grade shape).
# "INFO stats trending (commands counted — throughput planning on numbers, growth forecasting honestly).
# Hit rate 97% on sessions, 41% on recommendations → sessions earning, recommendations retiring-or-retuning.
# Memory 70/85/95 paging (cliffs forecasting — upgrades scheduling calmly, incidents preventing)."
# BAD: vibes answer — metrics named, numbers absent, saturation unowned (real rejection shape).
# "We monitor Redis." (What sections? which thresholds? — gauges unstated — follow-ups collapsing (recitation transparent).
# "Cache hit rate is good." (97%? 41%? — effectiveness unmeasured — losers subsidizing (retirement never — waste structural).
# State sections; compute rates; tier saturation.)
```

**Common confusion** — *"monitoring tools answer observability (Datadog proving health)."* Tools displaying (dashboards graphing — metrics surfacing (visibility starting — questions directing (tools serving — judgment owning); engineers interpreting (trends reading — thresholds setting (pages designing — runbooks linking (decisions owning — health managing (tools informing — humans deciding); vendors selling (features listing — coverage claiming (observability marketing — depth varying (evaluation requiring — trials proving). "Proving" describing loops (metrics → thresholds → runbooks — health managing); tools describing displays (graphs surfacing — visibility starting). Instrument tools (displays serving — visibility starting); interpret engineers (decisions owning — health managing).

**Performance note** — observability-interview economics: sections costing recall (INFO listing — gauges trending (knowledge structural — preparation compounding); rates costing division (hits computing — caches justifying (arithmetic trivial — effectiveness numeric); tiers costing judgment (70/85/95 stating — pages actionable (calibration demonstrating — incidents preventing); vibes answers costing offers (recitation rejected — measurement hired). List sections (knowledge structural — preparation compounding); compute live (arithmetic trivial — effectiveness numeric).

**Mentor note** — teach "sections, rates, tiers — in that order" (juniors answering all three place observability on first hearing; tool-naming interrogated ("which numbers?" — measurement demanded per answer). Mock drill: interviewer demanding numbers per claim (rate? headroom? blocked? — pressure practiced, not theorized). Measure everything; vibe nothing — observability judgment in three habits, reviewed per answer.

## 2. Slowness diagnosed live (SLOWLOG, latency, O(N) — culprits named with fixes, priced)

**Definition** — the slowness-diagnosis answer interviewers grade: given lag symptoms, name the source with fix and price ([1.2](<../../sections/1. Observe/1.2. Slow log and latency diagnosis.md>)) — slow commands logging (SLOWLOG naming — durations stating (O(N) fixing — payloads shrinking (executions quickening); loops stalling sampling (LATENCY tracking — forks suspecting (scheduling timing — blocking surfacing (visibility pricing — diagnosis owning); O(N) remediating (SCAN paging — HSCAN streaming (Lua bounding — loops freeing (service serving — freezes ending). "Live" means diagnosed with fixes (symptoms → source → remedy → price — chains complete).

**What problem it solves** — the symptom-only trio: *lag undescribed* ("Redis slow" (source unnamed — SLOWLOG unexamined (culprits hiding — fixes random (profiling blind — evidence absent); *stalls unrecognized* (forks pausing called "slow queries" (loops unconsidered — latency unsampled (blocking unowned — scheduling guilty (diagnosis wrong — remedies failing); *O(N) unowned* (KEYS surviving (scans freezing — loops holding (paging unconsidered — bounding unoffered (freezes scheduled — service sacrificing). Diagnosed slowness converting incidents to sources (symptoms mapping — fixes matching — prices explicit); interviewers grading diagnosis (source + fix + price → hired; symptoms-only → rejected).

**Modern guidance** — the diagnosis lines (interview-enforced): *commands logging* (SLOWLOG reading — culprits naming (O(N) fixing — payloads shrinking (executions quickening — slowness curing); *loops sampling* (LATENCY enabling — stalls tracking (forks suspecting — scheduling timing (blocking surfacing — visibility pricing); *O(N) remediating* (SCAN paging — HSCAN streaming (Lua bounding — loops freeing (service serving — freezes ending); *prices stating per fix* (paging free — bounding refactoring (sampling priced — visibility owning (costs explicit — fixes adopted, not feared). Symptoms → source → fix → price (chains complete — pressure survivable).

```bash
# GOOD: diagnosed with fix and price — symptoms mapping to sources (interview-grade answer shape).
# "p99 spikes → SLOWLOG showing KEYS * (culprits naming — SCAN fixing: cursors paging, loops freeing).
# Spikes without SLOWLOG entries → fork stalls (BGSAVE correlating — off-peak moving, loops freeing).
# Big-hash fetches → HSCAN streaming (payloads sizing — transfers capping, loops freeing)."
# BAD: symptoms only — source absent, fixes random (real rejection shape).
# "Redis is slow — we scaled up." (SLOWLOG unexamined — forks unconsidered — causes persisting at larger cost
# (provisioning absorbing, not fixing — diagnosis absent). KEYS surviving (paging unconsidered — freezes scheduled).
# Diagnose sources; match fixes; confirm post-deploy.)
```

**Common confusion** — *"scaling fixes slowness (bigger instances speeding)."* Scaling absorbing symptoms (faster CPUs hurrying — bigger RAM holding (causes persisting — KEYS freezing (loops holding — slowness returning (bottlenecks moving — incidents recurring (expenses growing — diagnosis declining); fixing curing sources (SCAN paging — forks moving (culprits remediating — loops freeing (causes ending — incidents closing (expenses zeroing — diagnosis paying); scaling timing (growth accommodating — headroom restoring (capacity honesting — purchases timing (fixes sequencing — sources first (scaling second — order mattering). "Fixes" describing remediation (sources ending — incidents closing); scaling describing capacity (headroom restoring — growth accommodating). Fix sources (remediation — incidents closing); scale capacity (headroom — growth accommodating).

**Performance note** — diagnosis economics: SLOWLOG reads costing scrapes (culprits naming — fixes placing (attribution cheap — profiling targeted); LATENCY costing sampling (stalls isolating — blocking naming (visibility priced — diagnosis owning); remediation costing refactors (loops freeing — service serving (fixes landing — incidents ending); scaling-first costing instances (causes persisting — incidents recurring (expenses growing — diagnosis declining). Diagnose cheaply (scrapes — attribution); fix structurally (remediation — incidents ending).

**Mentor note** — teach "symptoms → source → fix → price" (juniors chaining per lag diagnose slowness on first hearing; symptom-only answers interrogated ("source? fix? price?" — chains demanded per lag). Reproduce one spike once (KEYS freezing in staging, SCAN freeing (diagnosis tangible — fixes structural, never random). Diagnose sources; match fixes — slowness judgment in three habits, reviewed per incident.

## 3. Runbooks live (restart, failover, OOM — procedures stated, never hoped)

**Definition** — the procedure answer interviewers grade: given failure scenarios, name the runbook with steps ([3.1](<../../sections/3. Runbooks/3.1. Production runbooks.md>)) — restarts ordering (drain → snapshot → verify (loss minimizing — grace honoring (procedures sequencing — improvisation declining); failovers directing (promote → redirect → verify (automation executing — humans verifying (exceptions handling — judgment requiring); OOM escalating (evict → scale → shard (relief compounding — limits renegotiating (pressure relieving — growth freeing). "Live" means procedures stated (steps ordering — owners naming — drills dating (readiness evidenced — hope absent).

**What problem it solves** — the hope-procedure trio: *steps unstated* ("restart carefully" (order absent — drains missing (snapshots hoping — verifies skipping (procedures vague — improvisation planning (recovery gambling — practice absent); *owners unnamed* (incidents paging nobody (responsibility diffusing — responses delaying (escalation wandering — decisions stalling (ownership absent — action hoping); *drills undated* (rehearsals aging (systems evolving — evidence expiring (confidence decaying — demonstrations dating (honesty perishing — proof lapsing). Stated procedures converting hope to readiness (steps ordering — owners naming — drills dating); interviewers grading readiness (procedures + owners + dates → hired; careful-hoped → rejected).

**Modern guidance** — the procedure lines (interview-enforced): *restarts ordering* (drain → snapshot → verify (loss minimizing — grace honoring (procedures sequencing — improvisation declining (recovery executing — panic ending); *failovers directing* (promote → redirect → verify (automation executing — humans verifying (exceptions handling — judgment requiring (succession completing — panic ending); *OOM escalating* (evict → scale → shard (relief compounding — limits renegotiating (pressure relieving — growth freeing (structures relieving — guessing ending); *follow-ups answering* (owner? dated? (names stating — dates evidencing (readiness proving — hope declining (procedures current — confidence earning).

```bash
# GOOD: readiness evidenced — steps ordering, owners naming, drills dating (interview-grade answer shape).
# "Restart: drain writes (PEL/LLEN → 0), BGSAVE ok, verify counts (loss minimizing — procedures sequencing).
# Failover: Sentinel promotes freshest, clients rediscover, probe writes (automation executing — humans verifying).

# "Failover is automatic." (Verify where? owner who? — direction missing — exceptions unhandled (judgment absent).
# State steps; name owners; date drills.)
```

**Common confusion** — *"runbooks are junior crutches (experts improvising)."* Runbooks stabilizing experts (steps ordering — panic declining (quality steadying — stress immunizing (procedures guiding — improvisation ending (experience encoding — knowledge persisting); improvisation varying (stress deciding — quality fluctuating (recovery gambling — practice absent (expertise evaporating — teams depending (heroes bottlenecking — buses endangering); experts writing runbooks (judgment encoding — novices executing (knowledge transferring — teams scaling (mastery multiplying — heroism retiring). "Crutches" describing dependence (scripts blindly — judgment surrendering); runbooks describing preparation (routine directing — novelty freeing). Script routine (quality steadying — panic declining); reserve judgment (novelty handling — expertise mattering).

**Performance note** — procedure economics: writing costing documentation (steps ordering — panic declining (recovery executing — quality stabilizing); naming costing assignment (responsibility owning — responses speeding (escalation directing — decisions landing); drilling costing staging quarterly (evidence freshening — confidence earning (demonstrations recurring — honesty continuing); hope equivalents costing panic + delay + decay (quality varying — recovery gambling). Write cheaply (documentation — panic declining); drill recurrently (evidence freshening — confidence earning).

**Mentor note** — teach "steps, owners, dates — every answer" (juniors answering all three per scenario place readiness on first hearing; vague answers interrogated ("steps? owner? drilled?" — evidence demanded per scenario). Pressure drill: interviewer stacking failures (restart-during-failover-during-OOM — ladders composing live (readiness tangible — procedures compounding, never collapsing). State steps; date drills — readiness judgment in two habits, reviewed per scenario.
