# 5.1. Common interview QA messaging

## 1. Lists vs streams placed (simple queues vs durable consumption — judgment, not fashion)

**Definition** — the vehicle-placement answer interviewers grade: given a workload, name the vehicle with its recovery contract ([1.2](<../../sections/1. Streams/1.2. Lists as simple queues vs streams.md>)) — lists where loss is acceptable (ephemeral thumbnails (re-driveable cheaply — at-most-once explicit (simplicity winning); transient signals (freshness replacing recovery — redelivery pointless); prototypes (durability premature — YAGNI honored). Streams where loss is unacceptable (orders/payments (crashes costing money — at-least-once explicit (PEL tracking — redelivery managed); audit trails (history required — replays owned); parallel pipelines (groups partitioning ([2.1](<../../sections/2. Reliable consumption/2.1. Consumer groups.md>) — scaling structural). "Under pressure" means follow-ups attack the choice (crash mid-processing? replay needed? parallel consumers? — answers priced, never hoped).

**What problem it solves** — the fashion-answer trio: *vehicles recited without contracts* (streams named (recovery unstatable — follow-ups collapsing (pressure revealing recitation (understanding absent — choices unjustified); *trade-offs unpriced* (streams chosen "for reliability" (PEL RAM + ACK commands + idempotency lookups unmentioned — durability priced nowhere (ceremony unbought benefit — costs hidden); *workloads unmatched* (lists for orders (crashes losing silently (money vanishing — vehicles defaulted (recovery hoped). Placed vehicles convert recitation to judgment (workload → vehicle → contract → price — each link defensible); interviewers grading chains, not names (placement reasoned → hired; recited → rejected).

**Modern guidance** — the placement lines (interview-enforced): *ephemeral → lists* (loss acceptable — recomputation cheap (at-most-once explicit — simplicity winning); *money/audit → streams* (loss unacceptable — redelivery managed (at-least-once explicit — durability priced); *parallel → groups* (partitioning needed — coordination server-side (scaling structural — head-of-line decoupled); *follow-ups answered with prices* (crash → lists lose / streams redeliver (behaviors stated); replay → lists impossible / streams XRANGE (capabilities stated); parallel → lists race / groups partition (coordination stated). Every placement carrying contract + price (judgment demonstrable — pressure survivable).

```bash
# GOOD: placement reasoned — workload → vehicle → contract → price (interview-grade answer shape).
# "Order pipeline, crashes cost money → streams + groups + ACKs (at-least-once explicit — PEL tracking —
# redelivery managed — handlers idempotent (duplicates absorbed). Crash mid-processing → PEL redelivers
# (losses impossible — stalls claimed via XAUTOCLAIM). Parallelism → XREADGROUP partitioning (scaling structural)."
# BAD: fashion answer — vehicle named, contract absent (real rejection shape).
# "We use streams for everything." (Ephemeral thumbnails paying PEL/ACK ceremony (complexity priced, value absent).
# "Lists are simpler." (For orders? crashes losing silently — recovery hoped.) Follow-ups collapse recitation.)
# Name vehicles with contracts and prices; survive follow-ups.)
```

**Common confusion** — *"streams are strictly better than lists (superset functionality)."* Superset priced in ceremony (PEL RAM per pending (visibility priced — memory transient (unacked accumulating — monitoring required); ACK commands per entry (throughput taxed — completion priced (granularity exact — cost real); idempotency required (handlers guarding (correctness priced in lookups — absorption designed); lists costing O(1) with zero ceremony (simplicity free — durability absent (at-most-once explicit — acceptable where stated). "Strictly better" ignores prices (memory + commands + lookups — streams costing all three); lists winning ephemeral workloads structurally (simplicity free — ceremony unbought). Better per workload (judgment); strictly never (fashion).

**Performance note** — placement economics: lists cost O(1) ops, zero ceremony (simplicity free — durability absent); streams cost PEL RAM + ACK commands + dedupe lookups (durability priced — losses impossible); fashion answers cost offers (recitation rejected — judgment hired). Place per workload (contracts stated — prices explicit); recite never (fashion transparent under pressure).

**Mentor note** — teach "loss acceptable?" per queue (juniors answering with vehicles place messaging on first hearing; vehicle-only answers interrogated ("crash then? replay then?" — contracts demanded per placement). Mock drill: interviewer attacking each choice (crash/replay/parallel follow-ups — pressure practiced, not theorized). Place by workload; price every choice; survive follow-ups — vehicle judgment in three habits, reviewed per placement.

## 2. Groups and PEL live (partitioning, acking, claiming — diagnosed with fixes, priced)

**Definition** — the failure-diagnosis answer interviewers grade: given symptoms, name the mechanism with fix and price — unconsumed growth (PEL climbing (members stalled or producers surging — XPENDING distinguishing (idleities naming holders — responsibility explicit; fix: XAUTOCLAIM stalled + scale members ([2.1](<../../sections/2. Reliable consumption/2.1. Consumer groups.md>) — recovery automated, parallelism added); duplicate processing (crash-after-processing redelivering (handlers non-idempotent — double-applying; fix: NX dedupe guards ([2.2](<../../sections/2. Reliable consumption/2.2. Delivery semantics and idempotency.md>) — absorption structural, effects once); slow consumer (one member lagging (PEL concentrating — head-of-line within group (throughput capped by slowest; fix: more members + COUNT tuning (partitioning finer — lag distributing). "Live" means diagnosed with fixes (symptoms → mechanism → remedy → price — chains complete).

**What problem it solves** — the symptom-only trio: *stalls undescribed* ("queue slow" (mechanism unnamed — PEL unexamined (holders unknown — claims unoffered (diagnosis absent — fixes random); *duplicates unrecognized* (double-charges called "DB issues" (redelivery unconsidered — idempotency unexamined (guards unoffered — correctness hoped); *lag unowned* (slow members unidentified (PEL concentration unmeasured — scaling unconsidered (partitioning unoffered — throughput hoped). Diagnosed failures convert incidents to mechanisms (symptoms mapping to causes — fixes structural — prices explicit); interviewers grading diagnosis (mechanism + fix + price → hired; symptoms-only → rejected).

**Modern guidance** — the diagnosis lines (interview-enforced): *PEL climbing* (stalls or surges (XPENDING distinguishing — idle entries naming crashed holders (claims fixing); fresh entries naming throughput gaps (members scaling — parallelism fixing); *duplicates appearing* (redelivery without absorption (handlers non-idempotent — NX guards fixing (effects once — deliveries many); *lag concentrating* (slow members holding (PEL per-consumer skewing — members adding + COUNT tuning (partitions finer — lag distributing); *prices stated per fix* (XAUTOCLAIM scans negligible — NX guards O(1) — members cheap (costs explicit — fixes adopted, not feared). Symptoms → mechanism → fix → price (chains complete — pressure survivable).

```bash
# GOOD: diagnosed with fix and price — symptoms mapping to mechanisms (interview-grade answer shape).
# "PEL climbing, XPENDING showing idle 20min for c3 → crashed member holding entries (stall, not surge).
# Fix: XAUTOCLAIM reassigning (recovery automated — negligible scan cost) + alert on idle > 5min
# (visibility pre-incident — stalls self-healing post-deploy). Duplicates? handlers NX-guarded (effects once)."
# BAD: symptoms only — mechanism absent, fixes random (real rejection shape).
# "Queue is slow — we added more workers." (PEL unexamined — crashed holder still holding (stall persisting at
# larger cost — scaling absorbing, not fixing — diagnosis absent). Duplicates called "DB issues" (redelivery
# unconsidered — guards unoffered). Diagnose mechanisms; price fixes; confirm post-deploy.)
```

**Common confusion** — *"more consumers fix all stream problems (parallelism universal)."* Consumers fixing throughput (partitioning dividing — parallel members processing (lag distributing — scaling structural (throughput problems yielding); stalls persisting (crashed holders keeping PEL (members added idling — claims unfixed (recovery unowned — stalls permanent regardless of count); duplicates persisting (handlers non-idempotent (members multiplying double-apply (absorption absent — parallelism amplifying (more members, more duplicates). "Universal" misses mechanisms (throughput yielding — stalls/duplicates resisting (fixes mismatched — scaling absorbing, never fixing); diagnosis directing (PEL distinguishing — claims/guards fixing (mechanisms matched — fixes structural). Scale throughput (members — partitioning); claim stalls (XAUTOCLAIM — recovery); guard handlers (NX — absorption).

**Performance note** — diagnosis economics: XPENDING checks cost scrapes (visibility cheap — stalls early); XAUTOCLAIM cycles cost O(PEL) scans (recovery negligible — frequency tuned); NX guards cost O(1) per event (absorption priced — throughput taxed lightly); member scaling costs processes (throughput gained — stalls/duplicates unfixed); undiagnosed equivalents cost frozen work + double-charges (prices unbounded — customers discovering). Diagnose cheaply (scrapes — visibility); fix structurally (claims/guards/scale — mechanisms matched).

**Mentor note** — teach "symptoms → mechanism → fix → price" (juniors chaining per failure diagnose groups/PEL on first hearing; symptom-only answers interrogated ("mechanism? fix? price?" — chains demanded per failure). Reproduction drill: crashed member holding PEL in staging, XAUTOCLAIM recovering (mechanisms tangible — trust earned by watching recovery, not by documentation claims). Diagnose mechanisms; fix structurally; confirm post-deploy — failure judgment in three habits, reviewed per incident.

## 3. PubSub vs streams live (ephemeral broadcast vs durable log — loss tolerance stated, not hoped)

**Definition** — the broadcast-placement answer interviewers grade: given a signal, name the vehicle with its loss contract ([3.1](<../../sections/3. Broadcast/3.1. PubSub fire-and-forget.md>)) — PubSub where loss is tolerable (live ticks (missed frames superseded — recovery natural); presence (state re-queried — gaps self-healing); invalidation hints (TTL-bounded downstream — loss absorbed). Streams where loss is intolerable (order events (missed orders losing money — history required); audit feeds (gaps illegal — completeness mandated); catch-up audiences (late consumers onboarding — replays owned). "Live" means tolerance stated (loss priced per signal — vehicles matched — hope absent).

**What problem it solves** — the broadcast-fashion trio: *vehicles recited without tolerance* (PubSub named (loss unstatable — offline gaps surprising (follow-ups collapsing — pressure revealing recitation); *durability unpriced* (streams chosen "for safety" (ceremony unmentioned — PEL/ACK priced nowhere (ephemera slowed — costs hidden); *audiences unmatched* (catch-up needing history on PubSub (replays impossible — late consumers empty (vehicles defaulted — onboarding hoped). Placed broadcasts convert recitation to judgment (signal → vehicle → tolerance → price — each link defensible); interviewers grading tolerance (loss priced → hired; recited → rejected).

**Modern guidance** — the broadcast lines (interview-enforced): *tolerable → PubSub* (loss absorbed downstream — ticks superseded (contracts stated — ephemerality explicit); *intolerable → streams* (history required — replays owned (contracts stated — durability explicit); *split → hybrid* (live + catch-up — PubSub ticking + streams recording (consumers choosing — composition deliberate (boundaries clean); *follow-ups answered* (offline → PubSub misses / streams replays (behaviors stated); PUBLISH→0 → nobody listening (counts observed — audiences gauged (verified live shape — zero-counts informative). Every broadcast carrying tolerance + price (judgment demonstrable — pressure survivable).

```bash
# GOOD: tolerance stated — signal → vehicle → loss contract (interview-grade answer shape).
# "Live scores → PUBLISH (missed frames superseded — loss tolerated, recovery natural — PUBLISH→0 alerting
# where audiences required). Order events → XADD + groups (loss intolerable — history required — late
# consumers replaying). Feed → hybrid (ticks ephemeral + record durable — consumers choosing per presence)."
# BAD: fashion answer — vehicle named, tolerance absent (real rejection shape).
# "We use PubSub for notifications." (Offline users missing — gaps surprising — tolerance unexamined.)
# "Streams for everything." (Ticks paying ceremony — value absent — durability unbought benefit.)
# State tolerance; match vehicles; survive follow-ups.)
```

**Common confusion** — *"Kafka comparison decides (Redis streams vs Kafka trivia)."* Comparisons grading understanding (log abstractions shared (append-only + consumer positions — concepts transferring (mechanics differing — retention/partitioning/scale diverging); trivia reciting (feature matrices memorized — workloads unmentioned (comparisons detached — judgment absent (names dropped — placements missing); placement deciding (loss tolerance + scale + ops (vehicles chosen per need — Redis streams where stack unified (ops single — latency minimal); dedicated brokers where scale demands (throughput partitioning — retention longer). "Vs" describes curiosity (concepts transferring — mechanics differing); interviews grading placement (tolerance stated — vehicles matched — judgment demonstrated). Transfer concepts (logs universal); place per need (tolerance + scale + ops).

**Performance note** — broadcast-interview economics: PubSub costs O(receivers) transient (idle free — tolerance priced in loss); streams cost ceremony durable (history owned — tolerance priced in retention); hybrid costs both deliberately (audiences split — composition clean); fashion answers cost offers (recitation rejected — tolerance hired). State tolerance (loss priced — vehicles fit); compare conceptually (logs universal — mechanics differing).

**Mentor note** — teach "missed message costs what?" per broadcast (juniors answering with vehicles place broadcast on first hearing; tolerance-absent answers interrogated ("offline then?" — loss demanded per signal). Disconnect drill: subscriber dropping mid-PubSub (messages missed — tolerated or catastrophic (tolerance tangible — trust earned by watching loss, not by documentation claims). State tolerance; match vehicles — broadcast judgment in two habits, reviewed per signal.
