# 1.1. Streams as append-only logs

## 1. XADD appends, IDs order (auto `*` IDs time-ordered — entries immutable, history replayable)

**Definition** — streams: append-only logs of field-value entries (XADD key `*` field value... — `*` auto-generating time-ordered IDs (`<millis>-<seq>` — verified live: `1791027212242-0` then `1791027212365-0` (ordering structural — later appends sorting later, always); entries immutable (no update command exists — corrections appended as new entries (history honest — overwrites impossible structurally, never declined politely); explicit IDs allowed (`XADD key 1526569495631-0 ...` — ordering enforced (IDs must exceed last (backwards appends rejected — time flowing one direction, enforced server-side).

**What problem it solves** — the mutable-history trio: *overwrites destroying evidence* (hashes updated in place (prior states vanishing — audits reconstructing from backups (history hoped (corrections indistinguishable from tampering — honesty unprovable); *ordering hoped* (timestamps client-generated (clocks skewing — order disputed (producers disagreeing — sequence unowned (sorting approximate — "roughly ordered" wearing correctness); *replays impossible* (lists popped destructively (consumed entries gone — reprocessing requiring re-production (replays unowned — new consumers starting empty (history absent). Appended streams convert mutation to history (entries immutable — order server-assigned — replays reading old ranges); consumers arriving late reading everything (history replayable — onboarding free).

**Modern guidance** — the append lines per stream (review-enforced — verified live shapes on Redis 8.0.2): *auto IDs* (`*` per XADD (time-ordered — ordering server-assigned (clock skew irrelevant — producers agreeing structurally); *field-value entries* (flat maps per event (order-id, item, qty — schemas per stream (documented where produced — consumers parsing, never guessing); *immutable corrections* (no UPDATE existing (compensating entries appended (cancellations as events — history honest (state derived, never edited); *explicit IDs only for migration* (backfills preserving original order (IDs chosen carefully — monotonicity enforced (rejected appends surfacing immediately — mistakes loud, never silent).

```bash
# GOOD: append-only log — auto IDs, immutable entries, history replayable (verified live: 8.0.2).
# XADD dd:orders '*' item book qty 2  → 1791027212242-0 (time-ordered ID — ordering structural)
# XADD dd:orders '*' item pen qty 5   → 1791027212365-0 (later append sorting later — always)
# XRANGE dd:orders - +                 → both entries (history replayable — late consumers reading everything)
```

```bash
# BAD: mutable history — hashes updated in place, order hoped (real failure shapes).
# HSET dd:order:7 status shipped (prior state vanishing — audits reconstructing from backups (history hoped —
# corrections indistinguishable from tampering — honesty unprovable). Client timestamps ordering (clocks skewing —
# order disputed — sequence unowned). LPOP consuming destructively (replays impossible — new consumers starting
# empty). Mutate nothing; append everything.)
```

**Common confusion** — *"streams are just fancy lists (ordered strings either way)."* Lists store sequences (LPOP destroying (consumption destructive — history absent (replays impossible — late consumers empty); no IDs (positions shifting (entries unaddressable — acknowledgment unowned (redelivery untrackable); reads consuming (RPOP removing — inspection destroying). Streams store logs (reads non-destructive (XRANGE slicing — inspection free); entries ID-addressed (acknowledgment trackable — PEL owned (redelivery managed); history retained (replays reading old ranges — onboarding free). "Fancy lists" misses durability (consumption semantics differing structurally — lists for ephemeral handoffs ([1.2](<../../sections/1. Streams/1.2. Lists as simple queues vs streams.md>)), streams for durable logs). Lists hand off; streams record.

**Performance note** — append economics: XADD costs O(1) amortized (listpack-encoded small streams — memory compact (verified family: listpack shapes in [Domain 01 §2.2](<../../../01 Redis Foundations and Mental Model/sections/2. Core structures/2.2. Choosing structures by access.md>)); auto IDs cost a clock read (microseconds — ordering free with appends); immutable corrections cost compensating entries (history growing — trimmed per promise 3 (growth bounded — honesty priced in retention); mutable equivalents cost audit reconstruction (backups replayed — history hoped). Append cheaply (O(1) — ordering free); trim structurally (retention bounded — growth never hoped).

**Mentor note** — teach "append, never edit" (juniors XADDing corrections as events design honest history on first hearing; updating leaves interrogated ("where is the old state?" — immutability demanded per stream). Demonstrate XRANGE replay once (late consumer reading everything — verified live pattern above (tangibility converting permanently — history concrete, never abstract). Append everything; edit nothing — log discipline in two habits, reviewed per stream.

## 2. Reads slice without consuming (XRANGE/XREVRANGE/XREAD — cursors client-side, streams never drained by reading)

**Definition** — non-destructive reads: XRANGE (ID-range slices (`-`/`+` bounds — verified live: both entries returned (inspection complete — stream intact (XLEN unchanged by reading — consumption absent structurally); XREVRANGE (newest-first slices (recent history without full scans — tails read cheaply); XREAD (live tailing (`BLOCK` option waiting for new entries (polling loops declined — consumers idling efficiently (no busy-wait — wakeups server-pushed); cursors client-side (`$` = new only, IDs = resume points (positions owned by readers — server tracking nothing (state minimal — cursors surviving consumer restarts (resume exact, never approximate).

**What problem it solves** — the destructive-inspection trio: *reads destroying evidence* (pops consuming (monitoring draining queues (observability eating workload — inspection priced in data loss (debugging deleting); *polling loops burning* (LRANGE polling (empty reads per interval (CPU + RTTs wasted — wakeups unowned (latency spiking with interval — freshness priced per poll); *positions unowned* (offsets server-side-or-absent (restarts reprocessing-or-skipping (resume approximate — duplicates-or-gaps hoped (correctness unowned). Non-destructive reads convert inspection to freedom (XRANGE slicing — stream intact; XREAD BLOCK waiting — wakeups pushed; cursors client-held — resumes exact); observers observing without effect (monitoring free — debugging safe).

**Modern guidance** — the read lines per consumer (review-enforced): *inspect with XRANGE* (ID ranges slicing (debugging/adhoc reads — streams intact (XLEN unchanged — inspection free); *tail with XREAD BLOCK* (live consumption waiting (blocking milliseconds — wakeups server-pushed (polling loops declined structurally — CPU idle, latency minimal); *cursor explicitly* (`$` for new-only (fresh consumers ignoring history — onboarding current); explicit IDs for resume (restarts continuing exactly (positions persisted — duplicates-or-gaps declined); *COUNT bounding* (batch sizes capped (transfer bounded — full streams never fetched for tails (memory protected — pages sized, never hoped).

```bash
# GOOD: reads slice — inspection free, tails pushed, cursors explicit (verified live shapes: 8.0.2).
# XRANGE dd:orders - +        → both entries, stream intact (XLEN unchanged — consumption absent)
# XREVRANGE dd:orders + - COUNT 1 → newest entry only (tails cheap — full scans declined)
# XREAD BLOCK 5000 STREAMS dd:orders $ → waits for new (wakeups pushed — polling loops declined)
```

```bash
# BAD: destructive inspection — pops consuming, loops polling, positions hoped (real failure shapes).
# Monitoring via LPOP (observability eating workload — debugging deleting (inspection priced in data loss).
# LRANGE polling per second (empty reads burning CPU + RTTs — freshness priced per poll — latency spiking).
# Restarts reprocessing-or-skipping (resume approximate — duplicates-or-gaps hoped). Slice, never drain.)
```

**Common confusion** — *"XREAD BLOCK is just polling with extra steps (still waiting)."* Polling wakes per interval (empty reads burning (CPU + RTTs per tick — cost continuous (freshness priced per poll — intervals trading latency for waste); BLOCK wakes per entry (zero reads while idle (CPU sleeping — wakeups server-pushed (cost per event, not per tick — latency minimal, waste zero). "Extra steps" misses push-vs-pull (blocking server-held — clients idle (efficiency structural, not incremental); intervals tuning eliminated (no freshness/waste trade-off — BLOCK both fresh and free). BLOCK tails (push — idle free); poll never (pull — waste continuous).

**Performance note** — read economics: XRANGE costs O(N) in returned entries (slices sized via COUNT — transfer bounded); XREAD BLOCK costs nothing while idle (server-held waits — wakeups per event (efficiency structural); client cursors cost persistence per checkpoint (positions stored — resumes exact (cheap writes buying exactness); polling equivalents cost RTTs per interval (waste continuous — freshness priced); destructive reads cost data (inspection priced in loss). Slice boundedly (COUNT — transfer capped); BLOCK tails (idle free — wakeups pushed).

**Mentor note** — teach "reading is free, cursors are owned" (juniors XRANGE-inspecting live streams design fearless observability on first hearing; popping-to-inspect interrogated ("stream intact?" — non-destruction demanded per read). Demonstrate XLEN-before-and-after once (unchanged — verified live pattern above (tangibility converting permanently — non-destruction concrete, never claimed). Slice reads; own cursors — consumption discipline in two habits, reviewed per consumer.

## 3. Trim to bound memory (XTRIM MAXLEN/MINID — retention enforced, unbounded growth capped)

**Definition** — retention enforcement: XTRIM (entries evicted by count (`MAXLEN 10000` — verified live: `MAXLEN 1` trimming 2→1 (oldest evicted — bound structural (memory capped — growth never hoped); or by ID (`MINID` — entries below ID purged (time-windowed retention — age-based eviction (old history expiring structurally); approximate trimming (`MAXLEN ~ 10000` — efficiency over exactness (trimming amortized — count approximate (bounds soft, CPU minimal — precision priced out deliberately); CAPPED XADD (`XADD ... MAXLEN ~ 1000` — trim-on-write (retention automatic — unbounded growth impossible structurally (every append enforcing — discipline built-in, never remembered).

**What problem it solves** — the unbounded-log trio: *history growing forever* (trims unscheduled (streams accumulating (memory climbing — OOM reviewing retention (eviction by murder — [Domain 02 §3.1](<../../../02 Caching Patterns at Scale/sections/3. Memory governance/3.1. Eviction policies and memory safety.md>) violated structurally (bounds unconfigured — growth hoped); *manual purges forgotten* (cleanup cronned (jobs failing silently — retention hoped (growth resuming — discipline remembered, never enforced); *exactness overpriced* (exact MAXLEN per append (trimming CPU per write (precision unbought benefit — approximate declining (efficiency refused — cost continuous). Trimmed streams convert growth to retention (bounds configured — enforcement automatic — memory capped); reviewers checking policies, not sizes (retention stated → verifiable; unstated → returned).

**Modern guidance** — the retention lines per stream (review-enforced): *MAXLEN set* (counts bounded (verified live pattern — oldest evicted structurally (memory capped — growth never hoped); *MINID where age matters* (time-windowed retention (old history expiring — windows stated (audit/compliance horizons honored — age-based eviction); *approximate by default* (`~` trimming (efficiency structural — bounds soft (CPU minimal — exactness priced out deliberately); *CAPPED XADD where discipline must be automatic* (trim-on-write (retention built-in — unbounded growth impossible (every append enforcing — discipline never remembered); *gauged* (XLEN monitored (retention observed — unexpected growth investigating (trims failing or producers surging — visibility pre-incident).

```bash
# GOOD: retention enforced — bounds configured, trimming automatic, growth capped (verified live: 8.0.2).
# XTRIM dd:orders MAXLEN 1   → 1 (verified live output — oldest evicted structurally)
# XLEN dd:orders             → 1 (verified live output — bound holding, memory capped)
# XADD dd:events MAXLEN ~ 1000 '*' ... (trim-on-write — retention automatic — discipline built-in)
```

```bash
# BAD: unbounded logs — trims unscheduled, purges cronned, growth hoped (real failure shapes).
# Streams accumulating forever (memory climbing — OOM reviewing retention (eviction by murder — bounds
# unconfigured — growth hoped). Cleanup cronned (jobs failing silently — retention hoped (growth resuming —
# discipline remembered, never enforced). Exact MAXLEN per append (precision unbought benefit — efficiency
# refused). Bound every stream; automate trims; gauge XLEN.)
```

**Common confusion** — *"trimming loses history (dangerous by definition)."* Trimming discards *retained-beyond-policy* entries (bounds configured (oldest evicted — policy honored (history within window intact — loss designed, never surprising); consumers tracking cursors (processed positions persisted — trimmed entries already handled (loss irrelevant — work complete); replays reading retained ranges (windows sufficient — onboarding within policy). "Loses history" describes untrimmed hope (infinite retention assumed (memory unbounded — OOM deciding retention eventually (eviction by murder — loss surprising); trimming loses *expired* history (policy-stated — expected); unboundedness loses *everything* (OOM killing processes — loss total). Trim per policy (loss designed); unbound never (loss total).

**Performance note** — trim economics: approximate XTRIM costs amortized O(1) (efficiency structural — bounds soft (CPU minimal); exact MAXLEN costs per-append trimming (precision priced — continuous CPU (approximate declining — savings structural); CAPPED XADD costs nothing extra (trim piggybacked — discipline free with appends); unbounded equivalents cost OOM kills (eviction by murder — loss total). Trim approximately (CPU minimal — bounds soft); cap on write (discipline automatic — growth impossible); gauge XLEN (retention observed — surprises never).

**Mentor note** — teach "every stream has a retention policy" (juniors stating MAXLEN/MINID per stream design bounded logs on first hearing; untrimmed streams interrogated ("bound where?" — retention demanded per stream). Demonstrate XTRIM live once (2→1 — verified live pattern above (tangibility converting permanently — bounds concrete, never abstract). Bound streams; automate trims; gauge lengths — retention discipline in three habits, reviewed per stream.
