# 1.2. Lists as simple queues vs streams

## 1. Lists coordinate simply (LPUSH producers + BRPOP consumers — blocking pops idling efficiently)

**Definition** — lists-as-queues: producers appending (RPUSH jobs render-a render-b render-c — verified live: 3 queued (order preserved — sequence structural); consumers popping (BLPOP/BRPOP with timeouts — verified live: `BRPOP dd:empty 1` returning nil after 1s (idle efficient — no polling loops (wakeups server-pushed — CPU sleeping while empty); orientation choosing semantics (RPUSH+BLPOP = FIFO (producers right, consumers left — order preserved); LPUSH+BRPOP = FIFO mirrored; RPUSH+BRPOP = LIFO stack (verified live shape — tail popped first (stacks valid where order irrelevant, queues never).

**What problem it solves** — the coordination trio: *polling loops burning* (LRANGE/LEN polling (empty reads per interval (CPU + RTTs wasted — wakeups unowned (latency spiking with interval — freshness priced per poll); *unbuffered handoffs* (direct calls coupling (producers waiting consumers (backpressure by blocking — bursts failing (capacity unowned — spikes scheduled); *ordering hoped* (unordered sets queuing (sequence lost — processing scrambled (order unowned — correctness hoped). Blocking pops convert polling to waiting (BRPOP idling — wakeups pushed (CPU free, latency minimal); lists buffering (bursts absorbed — producers decoupled (capacity explicit — LLEN gauged).

**Modern guidance** — the queue lines per workload (review-enforced — verified live shapes on Redis 8.0.2): *FIFO orientation* (RPUSH producers + BLPOP consumers (order preserved — sequence structural (stacks declined where order matters — orientation reviewed); *blocking timeouts* (BRPOP/BLOPOP seconds-bounded (liveness guaranteed — consumers never stuck forever (dead producers surfacing via nil (timeouts handled — crashes visible); *lengths gauged* (LLEN monitored — verified live: 3 observed (depth visible — backlogs alerting pre-incident (growth unbounded → streams ([1.1](<../../sections/1. Streams/1.1. Streams as append-only logs.md>) — overflow policy stated); *single-consumer-or-partitioned* (competing consumers racing (same entry popped once (at-most-once structural — duplicates impossible, losses possible (crash mid-processing losing entries — priced next promise).

```bash
# GOOD: simple queue — FIFO orientation, blocking pops, lengths gauged (verified live: 8.0.2).
# RPUSH dd:jobs render-a render-b render-c  → 3 (verified live — order preserved structurally)
# BLPOP dd:jobs 5                           → head entry or nil after 5s (idle efficient — wakeups pushed)
# LLEN dd:jobs                              → depth gauged (backlogs alerting — overflow policy stated)
```

```bash
# BAD: polling handoffs — LRANGE loops, unbuffered calls, order hoped (real failure shapes).
# LRANGE polling per second (empty reads burning CPU + RTTs — freshness priced per poll — latency spiking).
# Direct-call handoffs (producers waiting consumers — bursts failing (capacity unowned — spikes scheduled).
# LIFO where FIFO matters (RPUSH+BRPOP scrambling order — verified live shape misapplied (orientation unreviewed).
# Coordinate with blocking pops; gauge depths; orient deliberately.)
```

**Common confusion** — *"BRPOP makes lists reliable queues (blocking = durable)."* Blocking waits efficiently (idle free — wakeups pushed (liveness improved — reliability unchanged); pops still destroying (consumed entries gone (crash mid-processing losing work (at-most-once structural — losses possible (duplicates impossible — exactly-once absent); no history (replays impossible — new consumers starting empty (onboarding history-less). "Reliable" describes waiting (efficiency — CPU sleeping); durability absent (acknowledgment unowned — PEL nonexistent — redelivery impossible). BRPOP idles (efficiency); streams insure (durability — next promise performs). Efficient, never durable.

**Performance note** — list-queue economics: BRPOP costs nothing while idle (server-held waits — wakeups per push (efficiency structural); RPUSH costs O(1) (appends cheap — order free); LLEN costs O(1) (depth free — gauging continuous); crash losses cost entries (at-most-once — work priced in redrives (losses possible — duplicates impossible). Idle free (blocking — wakeups pushed); appends cheap (O(1) — order structural); losses priced (crashes losing — durability absent).

**Mentor note** — teach "blocking waits, streams insure" (juniors BLPOPing simple queues design efficient handoffs on first hearing; reliability-claiming interrogated ("crash mid-processing?" — at-most-once demanded per queue). ## 2. Streams add durability (history + acknowledgment + groups — at-most-once upgraded to at-least-once)

**Definition** — the durability delta: what streams add over lists (history retained (reads non-destructive ([1.1](<../../sections/1. Streams/1.1. Streams as append-only logs.md>)) — replays reading old ranges (late consumers onboarding free — lists starting empty); acknowledgment tracked (PEL per group (pending entries listed (XPENDING — unacked work visible (crashes surfacing — losses impossible structurally, redelivery managed); groups partitioning (XREADGROUP per consumer ([2.1](<../../sections/2. Reliable consumption/2.1. Consumer groups.md>)) — each entry to exactly one member (parallelism safe — competing consumers coordinated server-side). At-most-once upgraded (losses possible → redelivery managed (duplicates possible — absorbed per [2.2](<../../sections/2. Reliable consumption/2.2. Delivery semantics and idempotency.md>) — exactly-once approximated via idempotency, never guaranteed).

**What problem it solves** — the at-most-once trio: *crash losses* (workers dying mid-processing (popped entries gone (work lost silently — redrives manual (losses discovered by customers — visibility absent); *replay impossibility* (new consumers starting empty (history absent — onboarding history-less (backfills re-producing — replays unowned); *uncoordinated parallelism* (competing BLPOP consumers racing (same-queue parallelism unpartitioned (one slow consumer blocking all (head-of-line coupling — scaling hoped). Durable streams convert losses to redeliveries (PEL tracking — crashes surfacing (work reassigned — losses impossible); history to replays (ranges readable — onboarding free); racing to partitioning (groups dividing — parallelism coordinated).

**Modern guidance** — the durability lines per workload (review-enforced): *crashes matter → streams* (PEL tracking (losses impossible — redelivery managed (duplicates absorbed — [2.2](<../../sections/2. Reliable consumption/2.2. Delivery semantics and idempotency.md>) performing); *replays needed → streams* (history retained (ranges readable — onboarding free (backfills natural — replays owned); *parallelism needed → groups* (XREADGROUP partitioning ([2.1](<../../sections/2. Reliable consumption/2.1. Consumer groups.md>)) — coordinated server-side (head-of-line decoupled — scaling structural); *neither → lists* (simplicity winning (durability unbought benefit — complexity declined (at-most-once acceptable — priced explicitly). Durability chosen, never defaulted (price per workload — next promise prices).

```bash
# GOOD: durability chosen — streams where crashes/replays/parallelism matter (shapes verified).
# Crash-sensitive orders → XADD + XREADGROUP + XACK (losses impossible — redelivery managed — [2.1]/[2.2]).
# Ephemeral thumbnails → RPUSH + BLPOP (simplicity winning — at-most-once acceptable, priced explicitly).
# Replayable events → XRANGE history (onboarding free — backfills natural — replays owned).
```

```bash
# BAD: durability defaulted — streams everywhere, lists where crashes matter (real mispricing).
# Streams for ephemeral thumbnails (groups/PEL/ACKs unbought benefit — complexity priced, value absent).
# Lists for crash-sensitive orders (crash losses silent — redrives manual — losses discovered by customers).
# Uncoordinated BLPOP parallelism (head-of-line coupling — scaling hoped). Price durability per workload.)
```

**Common confusion** — *"streams guarantee exactly-once (ack = once)."* ACK tracks completion (PEL clearing — delivery recorded (redelivery managed — duplicates possible (crash-after-processing redelivering (processed twice — applied twice where handlers non-idempotent (exactly-once absent — at-least-once honest); ordering per consumer (groups partitioning — global order unguaranteed (parallel members interleaving — sequence per-shard, never global). "Exactly-once" describes aspiration (systems approximating via idempotency ([2.2](<../../sections/2. Reliable consumption/2.2. Delivery semantics and idempotency.md>) — duplicates absorbed — effects once, deliveries many); streams guaranteeing at-least-once (losses impossible — duplicates possible — honesty priced). At-least-once guaranteed (losses impossible); exactly-once approximated (idempotency absorbing — effects once).

**Performance note** — durability economics: PEL tracking costs memory per pending entry (unacked work stored — monitored via XPENDING (visibility priced in RAM); XACK costs a command per processed entry (completion priced — throughput taxed lightly); idempotency costs dedupe checks per handler ([2.2](<../../sections/2. Reliable consumption/2.2. Delivery semantics and idempotency.md>) — duplicates absorbed (correctness priced in lookups); at-most-once equivalents cost silent losses (price unbounded — customers discovering). Track pending (RAM — visibility); ack explicitly (commands — completion); absorb duplicates (lookups — correctness).

**Mentor note** — teach "lists lose, streams redeliver" (juniors choosing per crash-sensitivity design durability judgment on first hearing; defaulted choices interrogated ("crashes cost what?" — durability priced per workload). ## 3. Choose by recovery needs (simple/ephemeral → lists; acknowledged/replayable → streams — priced per datum)

**Definition** — the placement answer: given a workload, name the vehicle with its recovery contract — lists where loss is acceptable (ephemeral thumbnails (re-driveable cheaply — crashes costing recomputation (price bounded — simplicity winning); transient signals (presence heartbeats (stale data worthless — loss irrelevant (freshness replacing recovery — redelivery pointless); low-ceremony prototypes (durability premature — complexity unbought benefit (YAGNI honored — streams later, never first). Streams where loss is unacceptable (orders/payments (crashes costing money — redelivery managed (losses impossible — durability priced); audit trails (history legally required — replays owned (retention enforced — [1.1](<../../sections/1. Streams/1.1. Streams as append-only logs.md>) trimming); parallel pipelines (groups partitioning — scaling structural (coordination server-side — throughput designed).

**What problem it solves** — the misplacement trio: *streams for ephemera* (groups/PEL/ACKs unbought benefit (complexity priced — value absent (ceremony slowing prototypes — durability premature); *lists for money* (crash losses silent (orders vanishing — redrives manual (losses discovered by customers — durability hoped); *no contract stated* (vehicles chosen by habit (recovery unexamined — crashes surprising (contracts absent — incidents discovering placement). Placed vehicles convert habit to judgment (workload → vehicle → contract → price — each link defensible); reviewers grading chains, not names (placement reasoned → approved; defaulted → returned).

**Modern guidance** — the placement lines (review-enforced): *ephemeral → lists* (loss acceptable — recomputation cheap (contracts stated — at-most-once explicit); *money/audit → streams* (loss unacceptable — redelivery managed (contracts stated — at-least-once explicit); *parallel → groups* (partitioning needed — coordination server-side ([2.1](<../../sections/2. Reliable consumption/2.1. Consumer groups.md>) — contracts stated — scaling structural); *migrate when needs change* (prototypes growing teeth (lists → streams migration planned (vehicles evolving — contracts tightening (growth honored — rewrites scheduled, never surprised). Every placement carrying contract + price (judgment demonstrable — crashes survivable).

```bash
# GOOD: placement reasoned — workload → vehicle → contract → price (judgment demonstrable).
# Thumbnails (re-driveable, cheap) → RPUSH + BLPOP (at-most-once explicit — simplicity winning).
# Orders (crashes cost money) → XADD + XREADGROUP + XACK (at-least-once explicit — durability priced).
# Prototype → lists now, streams when crashes matter (migration planned — contracts tightening with growth).
```

```bash
# BAD: placement defaulted — vehicles by habit, contracts absent (real failure shapes).
# Streams for heartbeats (stale data worthless — redelivery pointless (ceremony priced, value absent).
# Lists for payments (orders vanishing silently — durability hoped (losses discovered by customers).
# No contract stated (recovery unexamined — crashes surprising). Place per recovery needs; price every choice.)
```

**Common confusion** — *"one vehicle per system (consistency demands uniformity)."* Uniformity taxes fit (ephemera paying durability ceremony (complexity unbought — prototypes slowing); money risking at-most-once (losses unpriced — uniformity endangering); vehicles composing (lists feeding streams (simple ingest → durable processing — handoffs designed (boundaries clean — each vehicle where fit). "Consistency" describes interfaces (contracts uniform — at-most/at-least stated per queue (clarity preserved — reviewers reading contracts, not vehicles); implementations varying (fit per workload — simplicity where acceptable, durability where required). Contracts uniform (stated per queue); vehicles varied (fit per workload).

**Performance note** — placement economics: lists cost O(1) ops with zero ceremony (simplicity free — durability absent); streams cost PEL RAM + ACK commands + idempotency lookups (durability priced — losses impossible); misplacement costs ceremony-without-value or losses-without-visibility (prices unbounded — incidents discovering); migration costs rewrites (vehicles evolving — planned cheap, surprised expensive). Place per workload (contracts stated — prices explicit); migrate planned (growth honored — rewrites scheduled).

**Mentor note** — teach "loss acceptable?" per queue (juniors answering with vehicles design placement judgment on first hearing; unanswerable queues interrogated ("crashes cost what?" — contracts demanded per queue). Place per recovery; price every choice — vehicle judgment in two habits, reviewed per queue.
