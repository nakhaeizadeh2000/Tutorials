# 4.1. Messaging checklist mentors insist on

## 1. Every stream is trimmed (MAXLEN/MINID retention — unbounded growth scheduled never)

**Definition** — the retention line on every stream: which bound owns it ([1.1](<../../sections/1. Streams/1.1. Streams as append-only logs.md>)) — MAXLEN counts (oldest evicted structurally — memory capped); MINID age-windows (history expiring by time — horizons honored); CAPPED XADD trim-on-write (retention automatic — discipline built-in, never remembered); XLEN gauged (retention observed — unexpected growth investigating). "Trimmed" means a reviewer can point at any stream and read its bound (count, age, or capped-write — documented where the stream is produced, not in runbooks nobody opens).

**What problem it solves** — the unbounded-stream trio: *retention unowned* (trims unscheduled (streams accumulating (memory climbing — OOM reviewing retention (eviction by murder — bounds unconfigured — growth hoped); *purges cronned* (cleanup jobs failing silently (retention hoped — growth resuming (discipline remembered, never enforced); *growth ungauged* (XLEN unmonitored (surges invisible — producers flooding (trims failing — causes unknown (visibility absent — incidents surprising). Trimmed streams convert growth to retention (bounds configured — enforcement automatic — memory capped); reviewers checking policies, not sizes (retention stated → verifiable; unstated → returned).

**Modern guidance** — the retention lines per stream (review-enforced): *MAXLEN set* (counts bounded — oldest evicted (memory capped — growth never hoped); *MINID where age matters* (time-windowed retention — horizons stated (audit/compliance honored — age-based eviction); *approximate by default* (`~` trimming — efficiency structural (CPU minimal — exactness priced out); *CAPPED XADD where automatic* (trim-on-write — discipline built-in (unbounded growth impossible — every append enforcing); *XLEN gauged* (lengths monitored — unexpected growth investigating (trims failing or producers surging — visibility pre-incident). Untrimmed streams failing review structurally (hope is not retention).

```bash
# GOOD: retention stated — bounds configured where streams are produced (shapes verified).
# XADD dd:events MAXLEN ~ 10000 '*' ... (trim-on-write — retention automatic — discipline built-in)
# XLEN gauged per stream (unexpected growth investigating — trims failing or producers surging surfacing)
# BAD: retention hoped — trims unscheduled, purges cronned, growth ungauged (real failure shapes).
# Streams accumulating forever (OOM reviewing retention — bounds unconfigured — growth hoped).
# Cleanup cronned (jobs failing silently — discipline remembered, never enforced). Bound every stream.)
```

**Common confusion** — *"retention is ops' job after launch (developers ship streams)."* Bound *definitions* live with design (which MAXLEN/MINID (decided per stream — developers knowing horizons — bounds calibrated, not defaulted); trimming automation lives with producers (CAPPED XADD — discipline built-in (enforcement where knowledge lives — ops never paged for growth; gauges/alerts operated jointly (XLEN firing — runbooks executing — interface, not handoff (definitions from designers, operation from SRE — joint ownership, never abdication). "Ops' job" describes operation (gauges/runbooks — SRE-owned); bounds belong to designers (retention chosen per stream — unbounded-by-design streams unoperable in production). Define with design; operate jointly.

**Performance note** — retention economics: approximate trims cost amortized O(1) (efficiency structural — bounds soft); CAPPED XADD costs nothing extra (trim piggybacked — discipline free); XLEN gauges cost O(1) scrapes (retention observed — surprises never); unbounded equivalents cost OOM kills (eviction by murder — history total-loss). Bound cheaply (O(1) — discipline automatic); gauge continuously (visibility pre-incident).

**Mentor note** — teach "point at any stream, read its bound" (juniors stating MAXLEN/MINID per stream design retention discipline on first hearing; unbound streams interrogated ("bound where?" — retention demanded per stream). Review drill: new stream without bound returned automatically (retention structural — checklists enforced, never remembered). Bound streams; automate trims; gauge lengths — retention discipline in three habits, reviewed per stream.

## 2. Every consumer acknowledges (XACK per processed ID — PEL monitored, stalled entries claimed)

**Definition** — the completion line on every consumer: process-then-ack ordering ([2.1](<../../sections/2. Reliable consumption/2.1. Consumer groups.md>)) — work before XACK (crashes redelivering — losses impossible); PEL monitored (XPENDING gauged — stalls visible — claims triggering); claimers running (XAUTOCLAIM supervising — stalls self-healing — toil eliminated). "Acknowledges" means a reviewer can point at any consumer and read its completion contract (ordering stated — monitoring owned — recovery automated).

**What problem it solves** — the unacked trio: *acks before work* (completion reversed (crashes losing acked-unprocessed work (losses silent — delivery mistaken for durability (ordering violated — honesty broken); *PEL unmonitored* (stalls accumulating (crashed members holding entries forever (work stuck — visibility absent (losses-by-stall scheduled); *claims manual* (ops reassigning (toil per crash — recovery unowned (stalls paging people — labor priced per incident). Acknowledging consumers convert delivery to completion (process-then-ack — losses impossible (PEL monitored — stalls visible (claimers running — recovery automatic); reviewers checking contracts, not code paths (completion stated → verifiable; unstated → returned).

**Modern guidance** — the completion lines per consumer (review-enforced): *process-then-ack* (work before XACK — crashes redelivering (losses impossible — duplicates absorbed ([2.2](<../../sections/2. Reliable consumption/2.2. Delivery semantics and idempotency.md>)); *PEL gauged* (XPENDING per consumer — stalls alerting (idle thresholds breaching — claims triggering (visibility pre-incident); *XAUTOCLAIM supervising* (automation owning recovery — stalls self-healing (toil eliminated — thresholds stated (patience priced); *unacked bounded* (PEL ceilings alerting — growth investigating (members stalled or producers surging — causes distinguished). Unacknowledging consumers failing review structurally (hope is not completion).

```bash
# GOOD: completion contracted — ordering stated, PEL gauged, recovery automated (shapes verified).
# [process fully] → XACK per processed ID (losses impossible — duplicates absorbed — ordering honest)
# XPENDING gauged per consumer (stalls visible — idle thresholds breaching — claims triggering)
# XAUTOCLAIM supervising (stalls self-healing — toil eliminated — thresholds stated, patience priced)
```

```bash
# BAD: completion hoped — acks reversed, PEL blind, recovery manual (real failure shapes).
# XACK before processing (crashes losing acked-unprocessed work — delivery mistaken for durability).
# PEL unmonitored (work stuck — visibility absent — losses-by-stall scheduled).
# Ops claiming manually (toil per crash — recovery unowned). Process, then ack; gauge PEL; automate claims.)
```

**Common confusion** — *"monitoring PEL is premature optimization (watch when stuck)."* PEL gauges costing scrapes (XPENDING cheap — visibility continuous (stalls surfacing early — fixes calm (lead time measured in thresholds, not pages); stuck discovering costing incidents (work frozen — customers noticing (visibility absent — recovery rushed (fixes panicked — causes unknown); thresholds tuning freely (patience priced per workload — claims triggering correctly (automation reliable — toil zero). "Premature" describes unmeasured work (optimization without data — guessing); PEL monitoring measuring (stalls visible — data driving (claims triggering — recovery designed). Gauge continuously (visibility cheap — stalls early); discover never (incidents expensive — recovery panicked).

**Performance note** — completion economics: XACK costs a command per call (batched multi-ID — RTTs amortized); PEL gauges cost XPENDING scrapes (visibility cheap — stalls early); XAUTOCLAIM cycles cost O(PEL) scans (frequency tuned — overhead negligible); unacked equivalents cost frozen work (price unbounded — progress zero). Complete explicitly (commands batched — losses impossible); gauge continuously (stalls early — recovery calm).

**Mentor note** — teach "delivery is provisional, ACK is final" (juniors process-then-acking design honest completion on first hearing; ack-first handlers interrogated ("crash between?" — ordering demanded per consumer). Review drill: consumer without PEL gauge returned automatically (visibility structural — checklists enforced). Process first; ack after; claim stalls — completion discipline in three habits, reviewed per consumer.

## 3. Every handler is idempotent-or-fenced (duplicates absorbed — redelivery safe by construction, never by hope)

**Definition** — the safety line on every handler: either idempotent (dedupe NX guards ([2.2](<../../sections/2. Reliable consumption/2.2. Delivery semantics and idempotency.md>)) — redeliveries skipping (effects once — deliveries many (absorption structural); natural overwrites (same value rewritten — effects identical (dedupe free)) or fenced (monotonic tokens ([2.2](<../../sections/2. Reliable consumption/2.2. Delivery semantics and idempotency.md>)) — stale writes rejected (ordering structural — zombies defanged (locks declined — coordination cheap). "Idempotent-or-fenced" means a reviewer can point at any handler and read its safety (absorption stated — fencing stated — hope absent).

**What problem it solves** — the unsafe-handler trio: *redeliveries double-applying* (handlers non-idempotent (crash-after-processing replaying (charges doubling — correctness hoped (contracts unread); *zombies overwriting* (stale writers clobbering (partitions healing dangerously (recency unowned — ordering hoped (last-writer-wins by timing); *safety unowned* (handlers assuming once (semantics unexamined — redelivery unconsidered (guarantees hoped — contracts absent). Safe handlers convert redelivery to routine (duplicates absorbed — stale rejected (effects correct — deliveries many); reviewers checking safety, not logic (guarantees stated → verifiable; unstated → returned).

**Modern guidance** — the safety lines per handler (review-enforced): *idempotent where effects repeat* (NX guards claiming (first OK processing — second nil skipping (absorption automatic — applied-twice impossible); *fenced where order matters* (tokens monotonic (stale rejected — fresh winning (ordering structural — locks declined); *TTL covering horizons* (dedupe EX exceeding PEL idle (coverage complete — memory bounded (retention priced); *safety stated per handler* (guarantees documented where effects run (reviewers verifying absorption matches semantics (mismatches returned — safety structural). Unsafe handlers failing review structurally (hope is not safety).

```bash
# GOOD: safety stated — idempotency or fencing per handler (shapes verified).
# Charge handler: SET dd:dedupe:<id> done NX EX 3600 (first OK — redeliveries nil-skipping — effects once)
# Shared state: Lua fencing tokens (stale rejected — fresh winning — ordering without locks)
# Dedupe TTL covering PEL idle thresholds (coverage complete — memory bounded)
```

```bash
# BAD: safety hoped — handlers assuming once, zombies writing, guarantees absent (real failure shapes).
# Non-idempotent charges on streams (redeliveries double-charging — correctness hoped — contracts unread).
# Unfenced shared state (stale writers clobbering — ordering hoped — last-writer-wins by timing).
# No safety stated (semantics unexamined — redelivery unconsidered). Absorb duplicates; fence order.)
```

**Common confusion** — *"idempotency covers ordering too (safe = ordered)."* Idempotency absorbing repeats (same effect twice → once (duplication handled — order unaddressed (stale-after-fresh applying (recency unknown — ordering hoped (absorption blind to sequence); fencing ordering writes (tokens comparing — stale rejected (sequence enforced — duplicates orthogonal (fenced replays re-rejected — properties composing (safety complete — absorption + ordering); both required where repeats meet races (redelivered stale writes (absorption passing — fencing rejecting (layers cooperating — correctness composed). "Safe" describing absorption (duplicates handled); ordered describing fencing (sequence enforced). Absorb repeats (idempotency); order writes (fencing) — both where both threaten.

**Performance note** — safety economics: NX guards cost O(1) per event (absorption priced — throughput taxed lightly); fencing costs Lua microseconds per write (ordering priced — races impossible); TTLs cost nothing extra (coverage priced in retention — memory bounded); unsafe equivalents cost double-charges/clobbered state (prices unbounded — customers discovering). Absorb cheaply (O(1) — effects once); fence cheaply (microseconds — order structural).

**Mentor note** — teach "redelivered then? stale then?" (juniors answering both per handler design handler safety on first hearing; unanswerable handlers interrogated ("duplicate? zombie?" — safety demanded per handler). Safety drill: redelivery double-applying then absorbed; stale write clobbering then fenced (guarantees tangible — trust earned by watching safety hold, not by documentation claims). Absorb duplicates; fence order — handler safety in two habits, reviewed per handler.
