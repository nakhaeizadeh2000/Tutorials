# 3.1. PubSub fire-and-forget

## 1. Publish reaches the connected (PUBLISH/SUBSCRIBE — no history, offline subscribers missing messages by design)

**Definition** — Pub/Sub: ephemeral broadcast (SUBSCRIBE dd:news registering (connection holding subscription (channels per connection — subscriptions dying with disconnects (presence required — offline missing everything); PUBLISH dd:news hello → 1 — verified live: one subscriber receiving (count returned = receivers reached (delivery confirmed per publish — receivers counted, never named); PUBLISH dd:nobody hi → 0 — verified live: no subscribers, message dropped (fire-and-forget honest — undelivered vanishing (history absent — replays impossible (loss by design, never by accident).

**What problem it solves** — the broadcast-overkill trio: *streams for ephemera* (durable logs carrying presence (groups/PEL/ACKs unbought benefit (ceremony priced — value absent (heartbeats persisted — history pointless); *polling for signals* (keyspace polling (empty reads burning (latency spiking — wakeups unowned (signals delayed by interval — freshness priced per poll); *durability assumed* (subscribers expecting history (offline gaps surprising (messages missed — replays requested (impossibility discovered in production — contracts unread). Ephemeral broadcast converts ceremony to signal (publish reaching connected — offline missing (contracts honest — loss designed); subscribers present receiving instantly (latency minimal — overhead zero).

**Modern guidance** — the broadcast lines per signal (review-enforced — verified live shapes on Redis 8.0.2): *connected-only audiences* (presence required (subscribers holding connections (disconnects unsubscribing — offline missing by design (gaps expected — replays never requested); *counts checked* (PUBLISH returns receivers (verified live: 1 reached, 0 dropped (delivery visible — zero-receiver publishes surfacing (nobody listening — signals unheard (alerts where audiences required); *ephemeral signals only* (cache invalidations, presence, live ticks (loss tolerable — missed signals superseded (fresh state re-read — recovery natural (durability unbought benefit — ceremony declined).

// PUBLISH dd:nobody hi → 0 (verified live — no subscribers, message dropped — fire-and-forget honest)

**Common confusion** — *"PUBLISH returning 0 is an error (delivery failed)."* Zero counting receivers (nobody subscribed — signal unheard (information, never failure (audiences optional — presence unknown (publishers decoupled — subscribers independent); errors surfacing separately (connection failures throwing (failures loud — zero-counts quiet (distinction structural — counts informing, errors alarming); zero-receiver alerts designed (audiences required → alerting (invalidation with nobody listening surfacing — gaps visible (monitoring per signal — required audiences gauged). Handle errors (exceptions — loud); observe counts (zero — informative).

**Performance note** — broadcast economics: PUBLISH costs O(N) in receivers (fan-out linear — subscribers counted (delivery instant — overhead zero while idle); SUBSCRIBE costs a connection held (presence priced — connections cheap (idle free — signals pushed); zero-receiver publishes cost nothing (messages dropped — waste zero (fire-and-forget honest — undelivered vanishing); durable equivalents cost PEL/ACK ceremony (unbought benefit — ephemera slowed). **Mentor note** — teach "connected means receiving, disconnected means missing" (juniors publishing invalidation signals design ephemeral broadcast on first hearing; history-expecting interrogated ("offline then?" — loss demanded per signal). Demonstrate PUBLISH→0 once (verified live pattern above — message dropped visibly (tangibility converting permanently — ephemerality concrete, never abstract). Reach connected; drop rest — broadcast discipline in two habits, reviewed per signal.

## 2. Patterns fan out (PSUBSCRIBE glob channels — one subscription covering keyspaces, priced per match)
