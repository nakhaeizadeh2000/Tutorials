# 5.1. Common interview QA partitioning

## 1. Slots and tags placed (distribution vs colocation — judgment, not fashion)

**Definition** — the partition-placement answer interviewers grade: given scale needs, name the mechanism with its contract ([1.1](<../../sections/1. Slots/1.1. Hash slots and key distribution.md>)/[1.2](<../../sections/1. Slots/1.2. Hash tags for colocation.md>)) — slots distributing (16384 hashing — writes scaling (ownership explicit — skew measured); tags colocating (families sharing — transactions spanning (spans legal — guarantees holding); untagged defaulting (independents distributing — colocation declining (uniformity winning — simplicity preserving). "Under pressure" means follow-ups attack the choice (hot keys? multi-key transactions? rescale plan? — answers priced, never hoped).

**What problem it solves** — the fashion-answer trio: *mechanisms recited without contracts* (slots/tags named (distribution unstatable — follow-ups collapsing (pressure revealing recitation (understanding absent — choices unjustified); *trade-offs unpriced* (tags chosen "for transactions" (hotspots unmentioned — concentration unmeasured (balance unbought cost — colocation pricing nowhere); *workloads unmatched* (tags everywhere (families fattening — hotness concentrating (celebrity centralizing — balance hoping (skew unmeasured). Placed mechanisms convert recitation to judgment (need → mechanism → contract → price — each link defensible); interviewers grading chains, not names (placement reasoned → hired; recited → rejected).

**Modern guidance** — the placement lines (interview-enforced): *scale → slots* (writes distributing (ownership explicit — skew measured (growth planned — masters numbered); *transact → tags* (families sharing (spans legal — guarantees holding (hotness priced — concentration watched); *read-mostly → untagged* (independents distributing (uniformity winning — simplicity preserving (colocation declining — spans trivial); *follow-ups answered* (hot → split tags (families subdividing — heat spreading (balance restoring); multi-key → shared slot (spans legal — CROSSSLOT never (colocation planned); rescale → slot moves (trickling online — downtime zero). Every placement carrying contract + price (judgment demonstrable — pressure survivable).

```javascript
// GOOD: placement reasoned — need → mechanism → contract → price (interview-grade answer shape).
// "Write scale 3× → 3 shards, slots split (writes distributing — ownership explicit — skew measured quarterly).
// Order transactions → {order:} tags (families sharing — spans legal — hotness priced, celebrity watched).
// Hot leaderboard → regional sub-tags (heat spreading — reads aggregating — balance composing)."
// BAD: fashion answer — mechanism named, contract absent (real rejection shape).
// "We shard with tags." (Which families? hot keys? — concentration unmeasured — follow-ups collapsing.)
// "16384 slots." (So what? owned how? balanced when? — distribution unstatable — recitation transparent.)
// Name mechanisms with contracts and prices; survive follow-ups.)
```

**Common confusion** — *"sharding is just more servers (capacity adding)."* Servers adding instances (copies multiplying — replicas guarding (availability stacking — survival composing (capacity same — data whole (scaling vertical — durability deepening); shards partitioning disjointly (ranges splitting — writes distributing (ownership dividing — throughput multiplying (scaling horizontal — capacity summing (dimensions differing — totals composing); tags colocating transactions (spans sharing — wholes holding (guarantees buying — concentration pricing (design enabling — balance watching). "More servers" describing replicas (copies — survival); shards describing partitions (distribution — capacity). Copy survival (replicas — vertical); partition capacity (shards — horizontal).

**Performance note** — placement economics: slots costing map lookups (routing stateless — distribution structural); tags costing bytes + concentration (colocation priced — hotness watched); untagged costing nothing (uniformity free — simplicity preserving); fashion answers costing offers (recitation rejected — judgment hired). Place per need (contracts stated — prices explicit); recite never (fashion transparent under pressure).

**Mentor note** — teach "scale, transact, or read — then place" (juniors answering need → mechanism place partitioning on first hearing; mechanism-only answers interrogated ("hot then? spans then?" — contracts demanded per placement). Mock drill: interviewer attacking each choice (hotspot/transaction/rescale follow-ups — pressure practiced, not theorized). Place by need; price every choice; survive follow-ups — partition judgment in three habits, reviewed per placement.

## 2. Resharding live (migrations, ASK, balance — diagnosed with fixes, priced)

**What problem it solves** — the symptom-only trio: *skew undescribed* ("one shard hot" (mechanism unnamed — tags unexamined (families unfound — splits unoffered (diagnosis absent — fixes random); *storms unrecognized* (migrations stalling called "network issues" (pacing unconsidered — retries unexamined (throttling unoffered — transience hoped); *stalls unowned* (migrations wedging (states unchecked — progress unowned (completion hoping — ownership dividing (coverage risking). **Modern guidance** — the diagnosis lines (interview-enforced): *skew symptoms* (heat concentrating (tags fattening — counts diverging (splits fixing — families subdividing (balance restoring — moves trickling); *storm symptoms* (ASK multiplying (moves unpaced — retries looping (throttling fixing — pacing backgrounding (storms preventing — clients breathing); *stall symptoms* (states wedged (progress unchecked — inspection fixing (states verifying — moves closing (ownership settling — coverage preserving); *prices stated per fix* (moves trickling — throttling free (splits rescoping — balance priced (costs explicit — fixes adopted, not feared). **Common confusion** — *"adding shards fixes skew (capacity absorbing)."* Shards adding capacity (slots dealing — ranges splitting (counts evening — heat persisting (tags fattening — accesses concentrating (hotness moving wholly — families homing (skew transferring — balance deceiving); splits fixing (families subdividing — heat spreading (tags narrowing — concentration pricing (balance composing — moves targeting (hotness dividing — skew dissolving); counts deceiving (cardinality evening — accesses skewing (uniformity insufficient — hotspots hiding (math balancing — loads unbalancing). **Mentor note** — teach "symptoms → mechanism → fix → price" (juniors chaining per migration diagnose resharding on first hearing; symptom-only answers interrogated ("mechanism? fix? price?" — chains demanded per migration). **Definition** — the robustness answer interviewers grade: given topology changes, name the handling with guarantees ([3.1](<../../sections/3. Clients/3.1. **What problem it solves** — the hope-client trio: *redirects unhandled* (MOVED fataling (maps absent — handling missing (topology fluid — clients rigid (migrations breaking — robustness hoped); *semantics conflated* (ASK cached (maps poisoning — topologies diverging (transience persisting — ownership mislearned (caches lying — permanence misattributed); *modes naive* (single-node clustering (redirects crashing — pools funneling (awareness absent — brittleness structural (handling missing — robustness hoped). **Modern guidance** — the robustness lines (interview-enforced): *MOVED refreshing* (maps updating (ownership learning — routes correcting (tracking continuous — divergence closing (permanence handling — caching correct); *ASK bounding* (retries single (transience landing — maps untouched (preambles announcing — protocol honoring (storms declined — patience succeeding); *modes enabling* (libraries configuring (maps caching — redirects handling — pools spreading (awareness built-in — robustness structural); *hardcoded refusing* (addresses discovering (topologies following — migrations surviving (resilience structural — coupling declined). Every client carrying handling + semantics + mode (judgment demonstrable — pressure survivable).
