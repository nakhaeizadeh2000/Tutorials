## 1. Jitter desynchronizes expiry (randomized TTL ±10% — herds dispersed structurally)

## 3. Locks serialize rebuilds (SET NX mutex per key — one rebuilder, rest waiting with timeout)

**Definition** — the rebuild mutex: cache misses serialized per key via SET NX PX (verified live below — first acquirer rebuilding (exclusive recompute rights — duplicate work eliminated structurally); rest waiting with timeout (polling with backoff (bounded waits — liveness preserved (waiters failing fast past lock expiry (stuck rebuilders never blocking forever — TTL bounding mutexes); Lua-checked release (verified live: wrong-token release refused (0), right-token released (1) — ownership enforced (only builders releasing (stolen releases impossible — correctness under crash scenarios; Redlock/fencing depth in Domain 03 (forward — unbuilt).

**What problem it solves** — the rebuild race trio: *duplicate rebuilds* (concurrent misses each recomputing (expensive aggregations computed N times concurrently (CPU saturating on identical work — waste scaling with concurrency (thundering compute); *stale-serving races* (rebuilds completing out of order (older computation overwriting newer (freshness inverted — last-finisher-wins regardless of recency (correctness scheduled by timing luck); *stuck rebuilders* (crashed holders blocking waiters indefinitely (mutexes without TTL (deadlock by omission — liveness requiring manual intervention (3 a.m. DEL commands — toil scheduled).
