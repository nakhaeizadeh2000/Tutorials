## 1. maxmemory bounds datasets (limits set per instance — OOM killer never the policy)

## 2. Policies match workloads (volatile-lru/ttl, allkeys-lru, noeviction scoped — never defaulted)

**Definition** — eviction policies as workload contracts (reviewed per dataset, never defaulted): **volatile-lru/ttl** (expirable keys evicted least-recently/least-TTLs (cache workloads with TTL discipline (transients churning — hot data surviving (working set protected structurally — verified pattern family below); **allkeys-lru/lfu** (any keys evicted (sessions/unkeyed workloads (TTL discipline absent-or-partial — uniform eviction (hot data surviving via recency/frequency — working set protected statistically); **noeviction** scoped narrowly (billing Ledgers... billing-critical writes where eviction equals data loss AND persistence + capacity headroom guarantee space (narrow scope — writes failing loudly preferred over silent eviction (errors explicit — capacity managed — policy chosen eyes-open, never defaulted). Policies matched (workload → policy — TTL'd caches volatile-*, unkeyed sessions allkeys-*, critical writes noeviction-scoped); defaults declined (noeviction-global failing review structurally — availability cliffs scheduled).

**What problem it solves** — the policy-mismatch trio: *volatile policies on TTL-less datasets* (nothing expirable (eviction finding no candidates (writes failing despite policy configured (misconfiguration wearing configuration — policy present, candidates absent (effectiveness zero — availability cliff with extra steps); *allkeys policies on persistent datasets* (hot primaries evicted (working data discarded (cache-miss storms on primary data (regeneration impossible — evicted primaries unrecoverable (data loss wearing eviction — durability violated structurally); *noeviction globally* (writes failing at ceiling across all workloads (caches AND sessions AND queues erroring uniformly (availability cliff fleet-wide — eviction declined globally (protection theater — errors celebrated as "safe" while availability dies). Matched policies convert mismatch to fit (TTL'd→volatile-* (candidates existing — eviction effective); unkeyed→allkeys-* (uniform protection — hot surviving); critical-narrow→noeviction-scoped (errors explicit — capacity managed).

**Modern guidance** — the policy lines per dataset (review-enforced): *TTL'd caches* (volatile-lru default (transients churning — hot surviving (verified family: TTL discipline from [Domain 01 §1.2](<../../../01 Redis Foundations and Mental Model/sections/1. Strings keys and expiry.md>) — candidates existing (eviction effective); volatile-ttl where expiry order matters (soonest-expiring first (TTL-shaped eviction — freshness-ordered discarding); *unkeyed sessions* (allkeys-lru (uniform protection — hot surviving statistically (recency approximating value — LFU variants where frequency signals (hot keys accessed often (frequency beating recency — workload-measured choice, never defaulted); *critical narrow* (noeviction scoped (billing/ledger paths where eviction equals loss (errors explicit — capacity headroom guaranteeing space (headroom monitored — errors never reached in practice (policy as backstop, not plan); *reviewed* (policies matched per dataset (workload → policy mapping documented — mismatches returned (volatile on TTL-less failing review structurally).

**Common confusion** — *"eviction loses data (dangerous by definition)."* Eviction discards *regenerable* data (cache entries rebuildable from primaries (miss cost bounded — recomputation priced (TTL windows refilling — availability preserved); volatile policies evicting expirable keys (hot data surviving — working set protected); allkeys policies evicting statistically-cold keys (recency/frequency approximating value — cold evicted, hot surviving). "Loses data" describes primaries evicted (misconfiguration — allkeys on persistent datasets (durability violated — policy mismatched, reviewable); evicting caches loses *warmth*, never *truth* (primaries intact — misses bounded — regeneration priced). Evict caches (regenerable); persist primaries (irreplaceable — Domain 04 owns); confuse never.

**Performance note** — policy economics: volatile/allkeys sampling costs O(samples) per eviction (approximate algorithms — bounded CPU (exact tracking declined structurally — memory overhead per access avoided); noeviction-scoped costs errors on overflow (explicit failures — capacity managed (headroom monitored — errors never reached in practice); mismatched policies cost ineffectiveness (volatile on TTL-less (eviction finding nothing — writes failing despite policy); allkeys on primaries (hot data discarded — miss storms on unrecoverable data). Match policies (workloads mapped — effectiveness structural); scope noeviction narrowly (errors explicit — capacity managed).

**Mentor note** — teach "which keys may die?" per dataset (juniors answering with eviction policies design memory safety on first hearing; unanswered policies interrogated ("evict what?" — discardability demanded per dataset). Policy/workload matching drills (TTL'd→volatile, unkeyed→allkeys, critical→scoped-noeviction — placements timed, mismatches failing rounds). Match policies; scope narrowly; review per dataset — eviction discipline in three habits, reviewed per instance.
