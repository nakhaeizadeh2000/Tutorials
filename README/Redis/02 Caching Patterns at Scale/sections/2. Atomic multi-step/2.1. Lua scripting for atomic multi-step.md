# 2.1. Lua scripting for atomic multi-step

## 1. Scripts execute atomically (EVAL runs to completion — no interleaving)

**Definition** — Lua scripts (`EVAL "script" keys args`): logic shipped to the server, executed atomically — all commands in the script run without interleaving (no other client observing intermediate states — check-and-set safe structurally (read-decide-write in one indivisible unit — races impossible by execution model, not by locking). Atomicity per script (single script = single atomic unit — multi-key invariants held without distributed locks (WATCH-less coordination for scriptable logic — [2.2](<2.2. Transactions MULTI EXEC WATCH.md>) covers optimistic batching where scripts don't fit).

**What problem it solves** — the client-side check-and-set race (GET balance → decide → DECRBY in application code (concurrent deciders interleaving (both reading 5, both decrementing 3 → 2 instead of -1-rejected (oversold inventory — correctness evaporating under concurrency (verified live pattern below inverted: scripted version deciding atomically — take-3 succeeds (5→2), take-9 refused (-1) — no interleaving possible); and the multi-round-trip tax (read + decide + write = 3 round trips per conditional mutation (latency tripled — network dominating simple decisions (microseconds of logic, milliseconds of transport). Server-side scripts convert races to atomicity (decisions executing where data lives — interleaving impossible) and round trips to one (logic shipped once — network crossed once).

**Modern guidance** — the scripting lines per conditional mutation (review-enforced — verified live shapes on Redis 8.0.2): *check-and-set scripted* (read-decide-write in one EVAL (verified live: stock 5, take 3 → 2 (atomic decrement); take 9 → -1 refusal (overdraft rejected structurally); *keys/args separated* (KEYS for key names (cluster routing — keys declared (slot calculation correct); ARGV for values (injection impossible structurally (values never concatenated into scripts — parameters bound, always); *deterministic scripts only* (no random/time/ordering dependence (replication replaying scripts (effects replicated, not operations — nondeterminism diverging replicas (time/random/calls breaking consistency — determinism required, enforced by review (RAND/SMEMBERS-iteration flagged).

```bash
# GOOD: check-and-set atomic — read, decide, write in one indivisible unit (verified live: 8.0.2).
$ redis-cli SET dd:inv:widget 5                                    # OK (verified — stock 5)
$ redis-cli EVAL "local s = tonumber(redis.call('GET', KEYS[1]));
  if s >= tonumber(ARGV[1]) then return redis.call('DECRBY', KEYS[1], ARGV[1])
  else return -1 end" 1 dd:inv:widget 3                            # 2 (verified — atomic take-3)
$ redis-cli EVAL "...same..." 1 dd:inv:widget 9                    # -1 (verified — overdraft refused)
# Concurrent deciders interleaving: impossible (script atomic — races eliminated structurally).
```

```bash
# BAD: client-side check-and-set — races scheduled, round trips tripled (real failure shapes).
# stock = GET inv:widget  # 5 (two concurrent deciders reading 5 simultaneously)
# if stock >= 3: DECRBY inv:widget 3  # both decrementing (5→2→-1 (oversold — correctness evaporating
# under concurrency (interleaving scheduled — races inherent to separated read/decide/write).
# Round trips tripled (read + decide locally + write (latency ×3 — network dominating microsecond logic).
# Races inherent; latency tripled. Script atomically.)
```

**Common confusion** — *"Lua scripts block Redis (single-threaded danger)."* Scripts block *per execution duration* (fast scripts — microseconds (O(1)-ish logic — blocking negligible (event loop yielding between commands — throughput unaffected); slow scripts — O(N) scans/large loops inside EVAL (blocking seconds (all clients hanging — latency cliffs official). "Block" describes duration, not mechanism (fast scripts harmless — atomicity free; slow scripts harmful — monopolies scheduled). Keep scripts small and fast (next promise prices it — O(1)-ish logic, bounded loops, no KEYS * inside). Atomicity free for fast scripts; monopolies dear for slow ones — size scripts, never fear atoms.

**Performance note** — scripting economics: atomic scripts cost one round trip (vs three client-side (latency thirded — network crossed once); server CPU per script (microseconds for O(1) logic — throughput unaffected at scale (100k+ scripted ops/sec routinely); slow scripts cost event-loop monopoly (seconds blocked — all clients hanging — latency cliffs fleet-wide). Fast scripts free-ish (atomicity + latency wins — adopt eagerly); slow scripts dear (monopolies scheduled — bound strictly ([promise 2 below](#2-keep-scripts-small-and-fast-o1-ish-logic--long-scripts-blocking-the-event-loop-priced))). Atomicity priced per script duration — size scripts, never fear atoms.

**Mentor note** — teach "read-decide-write ships together" (juniors scripting conditional mutations design race-free logic on first hearing; client-side check-and-set interrogated ("atomic how?" — interleaving demanded per separated read/decide/write). Demonstrate races eliminated live once (concurrent decrements without oversell — verified live pattern above (take-3 succeeding, take-9 refusing — atomicity tangible — trust earned by watching indivisibility work, not by documentation claims). Ship logic; eliminate races; halve round trips — scripting discipline in three habits, reviewed per conditional mutation.

(script lifecycle unowned — archaeology scheduled). **Modern guidance** — the sizing lines per script (review-enforced): *O(1)-ish* (key lookups + arithmetic + conditionals (microseconds — event loop yielding between commands (throughput unaffected); *bounded loops* (fixed small N (top-K trims — loop bounds constant (unbounded iteration rejected structurally — KEYS */huge-collection scans failing review (monopolies scheduled); *time-limited* (lua-time-limit configured (long scripts interrupted — monopolies killed (liveness preserved — timeouts bounding execution (runaways impossible past limit); *logic-placed* (atomic decisions in scripts (check-and-set, token issues, counter guards — indivisibility required); orchestration in clients (workflows composing script calls (scripts deciding, clients composing — logic testable in application languages (debuggers/breakpoints/profilers — development velocity preserved).

## 3. Cache scripts with EVALSHA (SHA-addressed execution — bandwidth saved, NOSCRIPT handled)

**Definition** — the loading discipline: scripts cached server-side (`SCRIPT LOAD` returning SHA1 (verified live: `e0e1f9...` — content-addressed identity); `EVALSHA <sha>` executing cached scripts (verified live: returns 1 — bandwidth saved (script body unshipped per call — SHA reference only (large scripts × high call rates — transfer minimized); `NOSCRIPT` fallback handled (unknown SHA erroring (verified live pattern family: bogus SHA failing — clients catching NOSCRIPT → `SCRIPT LOAD` → retry EVALSHA (self-healing execution — deploys/restarts/flushes tolerated (cache emptiness handled, never assumed); `SCRIPT EXISTS` probing (verified live: 1 0 — presence checked per SHA batch (reconciliation without execution — drift detected cheaply).

**What problem it solves** — the uncached-script duo: *bandwidth waste* (multi-KB scripts shipped per call (large Lua bodies × millions of calls (transfer billed per execution — bandwidth dominating microsecond logic (network dwarfing compute — waste scaling with call rate); and *NOSCRIPT crashes* (EVALSHA against flushed/restarted servers (script cache emptied on restart/failover/FLUSH (clients erroring — executions failing post-restart (availability coupled to script-cache warmth — cold caches breaking hot paths (restarts scheduled incidents). Cached execution with fallback converts both (bandwidth saved per call (SHA references — transfer minimal); NOSCRIPT handled structurally (catch → LOAD → retry (self-healing — restarts tolerated (cache emptiness handled, never assumed).

**Modern guidance** — the caching lines per script (review-enforced — verified live shapes on Redis 8.0.2): *load once* (`SCRIPT LOAD` at deploy/startup (SHAs recorded — versions pinned (script bodies versioned with code — SHA drift detected (content changes → new SHA — deployments explicit); *execute by SHA* (EVALSHA per call (bandwidth saved — script bodies unshipped (transfer minimal — high-rate paths economized); *fallback structured* (NOSCRIPT → LOAD → retry EVALSHA (verified live pattern family: bogus SHA failing — self-healing execution (restarts/flushes tolerated — cache emptiness handled); *verify presence* (`SCRIPT EXISTS` batch checks (verified live: 1 0 — presence probed per SHA set (reconciliation cheap — drift detected without execution); *flush scoped* (SCRIPT FLUSH only on scratch/development (production cache shared — flush nuking all cached scripts (outage-inducing (NOSCRIPT storms fleet-wide — flushes gated, never casual — verified live cleanup used FLUSH on probe only (scratch-isolated, safe).

```bash
# GOOD: scripts cached with fallback — bandwidth saved, NOSCRIPT handled (verified live: 8.0.2).
$ redis-cli SCRIPT LOAD "return 1"   # e0e1f9fabfc9d4800c877a703b823ac0578ff8db (verified — SHA identity)
$ redis-cli EVALSHA e0e1f9... 0      # 1 (verified — cached execution (bandwidth saved — body unshipped))
$ redis-cli EVALSHA 0000...0 0       # (error) NOSCRIPT (verified pattern — unknown SHA failing loudly)
$ redis-cli SCRIPT EXISTS e0e1f9... 0000...0  # 1 0 (verified — presence probed per SHA batch)
# Fallback: catch NOSCRIPT → SCRIPT LOAD → retry EVALSHA (self-healing — restarts tolerated).
# Flush: scratch-only (verified live cleanup used FLUSH on probe (isolated, safe — production never).
```
