# 4.1. Durability checklist mentors insist on

## 1. Every instance persists deliberately (RDB or AOF configured — unpersisted production returned)

**Definition** — the persistence line on every instance: RDB or AOF (or both) configured deliberately ([1.1](<../../sections/1. On-disk persistence/1.1. RDB snapshots.md>)/[1.2](<../../sections/1. On-disk persistence/1.2. AOF logs and fsync policies.md>)) — save points scheduling (dumps automatic — discipline built-in); fsync policies pricing (windows stated — durability bought); unpersisted only where declared (caches with sources of truth elsewhere (loss tolerable — honesty explicit (defaults examined — adjunct declined knowingly, never accidentally). "Deliberately" means a reviewer can point at any instance and read its persistence decision (mechanism + window — documented where deployed, not discovered at restart).

**What problem it solves** — the unpersisted-production trio: *defaults keeping* (appendonly no unexamined (probes shipping (caches promoted — production losing everything on restart (deploys rebooting — data loss scheduled (volatility unowned); *mechanisms unchosen* (RDB-vs-AOF undecided (recovery unowned — windows unstated (precision hoped — schedules unread (durability accidental); *honesty absent* (loss intolerable + unpersisted (money on defaults (contracts violated — incidents discovering (configurations lying — safety theatrical). Deliberate persistence converting accidents to decisions (mechanisms chosen — windows stated — honesty explicit); reviewers checking decisions, not defaults (persistence decided → verifiable; defaulted → returned).

**Modern guidance** — the persistence lines per instance (review-enforced): *RDB minimum* (save points scheduling (dumps automatic — loss bounded (coarse honesty — recovery fast); *AOF where precision* (logs recording (replays exact — windows priced (durability bought — money/audit covered); *unpersisted only declared* (caches with truth elsewhere (loss tolerable — honesty explicit (defaults examined — adjunct declined knowingly); *decisions documented* (mechanisms + windows where deployed (reviewers verifying fit (mismatches returned — durability structural). Unpersisted production failing review structurally (hope is not persistence).

```bash
# GOOD: persistence decided — mechanisms chosen, windows stated, honesty explicit (shapes verified).
# Production orders → RDB + AOF everysec (dumps fast — logs precise — windows stated, durability bought)
# Ephemeral cache → unpersisted declared (loss tolerable — truth elsewhere — defaults examined knowingly)
# Decisions documented per instance (reviewers verifying fit — mismatches returned — durability structural)
```

```bash
# BAD: persistence defaulted — appendonly unexamined, mechanisms unchosen, honesty absent (real failure shapes).
# Probes shipping to production (restarts wiping — deploys rebooting — data loss scheduled (volatility unowned).
# RDB-vs-AOF undecided (windows unstated — precision hoped — durability accidental (designs absent).
# Money on defaults (contracts violated — incidents discovering — configurations lying). Decide per instance.)
```

**Common confusion** — *"persistence slows Redis (disk on the hot path)."* RDB backgrounding (forks snapshotting ([1.1](<../../sections/1. On-disk persistence/1.1. RDB snapshots.md>) — parents serving (dumps free of stalls — hot path unblocked (CoW sharing — steady cheap); AOF everysec backgrounding ([1.2](<../../sections/1. On-disk persistence/1.2. AOF logs and fsync policies.md>) — syncs threading (writes flowing — throughput preserved (safety cheap — production default); always pricing (per-write syncing — throughput halved (safety bought — money priced (disks bounding — choice explicit, never blanket). "Slows" describes always-everywhere (dogma pricing — safety overbought); RDB + everysec preserving (hot path unblocked — safety cheap). Persist backgrounded (hot path free); price always (money only).

**Performance note** — persistence economics: RDB costs forks + periodic I/O (hot path unblocked — dumps cheap); AOF everysec costs background syncs (throughput preserved — safety cheap); always costs per-write syncs (throughput halved — safety priced (money only); unpersisted equivalents cost total loss on restart (price unbounded — deploys wiping). Persist backgrounded (hot path free — dumps cheap); always selectively (money priced — safety bought).

**Mentor note** — teach "point at any instance, read its persistence" (juniors deciding RDB/AOF per instance design deliberate durability on first hearing; defaulted production interrogated ("restart then?" — decisions demanded per instance). Review drill: new instance without persistence decision returned automatically (deliberation structural — checklists enforced, never remembered). Persist deliberately; declare exceptions — persistence discipline in two habits, reviewed per instance.

## 2. Every primary has replicas-or-backups (copies existing — single-node data loss scheduled never)

**Definition** — the copy line on every primary: replicas or backups (or both) existing ([2.1](<../../sections/2. Copies/2.1. Replication async and replicas.md>) — replicas streaming (copies converging — lag bounded (failovers promoting — succession designed); backups versioned off-host (snapshots surviving node loss — retention tested (restores rehearsed — survival guaranteed); lone primaries labeled temporary (verified live probe shape — single-copy honesty (risks stated — copies pending, never absent-by-design). "Replicas-or-backups" means a reviewer can point at any primary and read its survival story (copies existing — restoration owned — loss scheduled never).

**What problem it solves** — the single-copy trio: *lone primaries permanent* (solitude shipping (nodes failing totally — data vanishing (backups absent — replicas missing (loss scheduled — durability hoped); *replicas unmonitored* (copies existing (lag unmeasured (staleness invisible — failovers promoting stale (recency unchecked — losses scheduled); *backups fictional* (dumps existing (restores never run (corruption hiding — recovery hoped (incidents discovering — honesty absent). Copied primaries converting solitude to survival (replicas streaming — backups versioned (losses bounded — restores rehearsed); reviewers checking copies, not nodes (survival owned → verifiable; solitary → returned).

**Modern guidance** — the copy lines per primary (review-enforced): *replicas where uptime* (failovers promoting ([2.2](<../../sections/2. Copies/2.2. Sentinel failover.md>) — succession designed (outages bounded — automation proven); *backups where history* (dumps versioned off-host (node loss surviving — retention tested (restores rehearsed — survival guaranteed); *both where money* (copies streaming + snapshots versioned (layers redundant — survival engineered — durability composed); *lag/restores gauged* (offsets compared — drills timed (copies live — survival demonstrated (honesty continuous — hope absent). Solitary primaries failing review structurally (hope is not survival).

```bash
# GOOD: copies existing — replicas streaming, backups versioned, survival demonstrated (shapes verified).
# Production primary → 2 replicas + versioned dumps (succession designed — node loss surviving — layers redundant)
# Replica lag gauged (offsets compared — staleness bounded — failovers informed — recency checked)
# Restore drills timed (dumps loading — procedures owned — incidents executable — survival demonstrated)
```

```bash
# BAD: copies absent — primaries solitary, replicas unmonitored, backups fictional (real failure shapes).
# Lone primary permanent (nodes failing totally — data vanishing — loss scheduled (durability hoped).
# Lag unmeasured (failovers promoting stale — recency unchecked — losses scheduled (staleness invisible).
# Dumps never restore-tested (corruption hiding — recovery hoped — incidents discovering). Copy everything primary.)
```

**Common confusion** — *"replicas are backups (copies serving both roles)."* Replicas serving uptime (failovers promoting — succession designed (copies live — lag bounded (recency priced — survival instant); backups serving history (dumps versioned — point-in-time returning (corruption/ deletion recovering — accidents undoable (retention deep — survival across time); replicas replicating corruption (bad writes streaming (copies corrupting — history absent (undo impossible — recency only); backups isolating (offline copies — corruption contained (recovery possible — time travel owned). "Backups" describes history (versioned — restorable — undoable); replicas describing availability (live — promotable — instant). Replicate uptime (failovers — succession); back up history (versions — undo).

**Performance note** — copy economics: replicas cost instances per copy (uptime priced — succession designed (lag bounded — recency checked); backups cost storage + drill time (history priced — survival guaranteed (restores rehearsed — procedures owned); both cost redundancy (money covered — layers composed (durability engineered — survival certain); solitary equivalents cost total loss (price unbounded — nodes failing). Copy per need (uptime/history — survival priced); drill always (restores proven — hope absent).

**Mentor note** — teach "replicas for uptime, backups for history" (juniors copying per need design survival on first hearing; copy-less primaries interrogated ("node dies then?" — survival demanded per primary). Review drill: new primary without replicas-or-backups returned automatically (copies structural — checklists enforced). Replicate uptime; back up history — copy discipline in two habits, reviewed per primary.

## 3. Every window is stated and tested (loss bounded numerically — crash drills demonstrating, never hoping)

**Definition** — the honesty line on every deployment: windows stated + tested ([3.1](<../../sections/3. Crash truth/3.1. Crash semantics and durability windows.md>)) — numbers documented (RDB/AOF/lag per layer — totals composed (stakeholders calibrated — adjectives banned (durable/safe unquantified failing); drills demonstrating (kill -9 executing — losses measuring (totals verifying — honesty earning); records reviewed (gaps closing — procedures evolving (demonstrations recurring — confidence earning). "Stated and tested" means a reviewer can point at any deployment and read its loss number + last drill date (honesty current — evidence fresh, never historical).

**What problem it solves** — the untested-honesty trio: *windows unstated* (losses unmeasured (expectations uncalibrated — stakeholders expecting zero (incidents disappointing — contracts missing); *drills absent* (recovery fictional (restores never run — failovers never observed (procedures unowned — incidents improvising (practice priced in outages); *records stale* (drills historical (systems evolving — procedures aging (evidence expiring — confidence decaying (honesty dated — demonstrations once, never recurring). Stated-and-tested windows converting claims to evidence (numbers documented — drills executing — records fresh); reviewers checking dates, not adjectives (evidence current → verifiable; historical → returned).

**Modern guidance** — the honesty lines per deployment (review-enforced): *numbers documented* (windows numeric per layer — totals composed (stakeholders calibrated — adjectives banned (honesty explicit — calibration complete); *drills scheduled* (kill -9 quarterly — failovers observed (losses measuring — totals verifying (practice recurring — confidence earning); *records fresh* (dates reviewed (systems evolving — procedures current (evidence recent — demonstrations repeating (honesty continuous — hope absent); *gaps closing* (drill findings fixing (procedures evolving — systems hardening (reviews acting — evidence improving).

```bash
# GOOD: honesty evidenced — numbers documented, drills scheduled, records fresh (shapes verified).
# Loss ≤ ~33s stated per pipeline (windows numeric — totals composed — stakeholders calibrated)
# kill -9 quarterly + failover observed (losses measuring — automation proven — honesty earning)
# Drill records dated this quarter (evidence recent — procedures current — confidence earning)
```

```bash
# BAD: honesty claimed — windows unstated, drills absent, records stale (real failure shapes).
# "Durable setup." (Adjectives unquantified — expectations uncalibrated — incidents disappointing.)
# Recovery never rehearsed (procedures unowned — incidents improvising — practice priced in outages).
# Last drill 2 years ago (systems evolving — evidence expiring — confidence decaying). State; drill; refresh.)
```

**Common confusion** — *"passing drills once proves durability (certified forever)."* Systems evolving (configs drifting — versions upgrading (procedures aging — evidence expiring (confidence decaying — demonstrations dating (honesty perishable — freshness required); drills recurring (quarterly cadence — records fresh (procedures current — evidence recent (confidence earning — demonstrations repeating); incidents teaching (drill findings fixing (gaps closing — systems hardening (reviews acting — evidence improving). "Proven" describing current evidence (drills recent — procedures owned — confidence earning); history describing decay (systems evolved — demonstrations dated — proof expired). Drill recurrently (evidence fresh — confidence earning); certify never (systems evolving — proof expiring).

**Performance note** — honesty economics: stating costs documentation (numbers free — calibration priceless); drills cost staging time quarterly (procedures owned — recovery proven (practice priced — incidents executable); fresh records cost review cadence (evidence current — confidence earning (honesty continuous — hope absent); untested equivalents cost mid-outage discovery (improvisation priced — customers drilling (trust burning). State freely (numbers cheap — calibration priceless); drill recurrently (evidence fresh — recovery proven).

**Mentor note** — teach "last drill date, loss number" (juniors answering both per deployment design evidenced honesty on first hearing; undated answers interrogated ("drilled when? loses what?" — evidence demanded per deployment). Calendar drill: quarterly crash rehearsals scheduled with owners (recurrence structural — evidence fresh — confidence earning). State numbers; drill quarterly — honesty discipline in two habits, reviewed per deployment.
