# 5.1. Common interview QA durability

## 1. RDB vs AOF placed (snapshots vs logs — recovery needs deciding, not fashion)

**Definition** — the persistence-placement answer interviewers grade: given durability needs, name the mechanism with its window ([1.1](<../../sections/1. On-disk persistence/1.1. RDB snapshots.md>)/[1.2](<../../sections/1. On-disk persistence/1.2. AOF logs and fsync policies.md>)) — RDB where coarse suffices (caches/sessions (minutes-old restores acceptable — dumps compact (loads fast — recovery quick); AOF where precision matters (money/audit (replays exact — windows priced (fsync chosen — durability bought); both where recovery must be quick AND exact (snapshots loading — logs tailing (speed + precision — durability composed). "Under pressure" means follow-ups attack the choice (crash loses what? restart takes how long? fsync which? — answers numeric, never hoped).

**What problem it solves** — the fashion-answer trio: *mechanisms recited without windows* (RDB/AOF named (loss unstatable — follow-ups collapsing (pressure revealing recitation (understanding absent — choices unjustified); *trade-offs unpriced* (AOF chosen "for safety" (fsync unmentioned — throughput unmeasured (precision unbought benefit where RDB suffices — costs hidden); *workloads unmatched* (AOF-always for caches (fsync taxing — safety unbought (durability overpriced — performance paying (freshness funding safety nobody needs). Placed mechanisms convert recitation to judgment (need → mechanism → window → price — each link defensible); interviewers grading chains, not names (placement reasoned → hired; recited → rejected).

**Modern guidance** — the placement lines (interview-enforced): *coarse → RDB* (caches/sessions (minutes acceptable — dumps compact (loads fast — recovery quick); *precise → AOF* (money/audit (replays exact — fsync priced (windows chosen — durability bought); *both → critical* (speed + precision (snapshots fast — tails exact (recovery composed — durability complete); *follow-ups answered numerically* (crash → ≤ window (numbers stated); restart → minutes per GB (times budgeted); fsync → zero/one/unbounded (policies matched). Every placement carrying window + price (judgment demonstrable — pressure survivable).

```bash
# GOOD: placement reasoned — need → mechanism → window → price (interview-grade answer shape).
# "Session store, minutes tolerable → RDB save-points (loss ≤ ~5min — dumps compact — restarts fast).
# Ledger, precision required → RDB + AOF always (snapshots fast — logs exact — windows zero — SSDs priced).
# Restart budget → minutes per GB measured in drills (recovery timed — budgets honest — incidents executable)."
# BAD: fashion answer — mechanism named, window absent (real rejection shape).
# "We use AOF for durability." (Fsync which? windows what? — precision unstatable — follow-ups collapsing.)
# "RDB is enough." (For money? minutes-old restores — recency losing — needs unmatched (follow-ups collapsing).)
# Name mechanisms with windows and prices; survive follow-ups.
```

**Common confusion** — *"both RDB+AOF is strictly best (maximum durability always)."* Both composing optimally (snapshots fast — logs precise (recovery composed — durability complete (costs both — disk + I/O + complexity (prices real — benefits bought (critical datasets justifying — money covering); caches overpaying (fsync taxing — logs ballooning (safety unbought — performance funding (freshness paying — durability unneeded); simplicity winning small (RDB-only starting (coarse honest — complexity deferred (needs growing — mechanisms adding (evolution planned — overengineering declined). "Strictly best" ignores prices (disk + I/O + complexity — both costing all three); RDB-only winning tolerable workloads structurally (honesty cheap — precision unbought). Best per need (judgment); strictly never (fashion).

**Performance note** — placement economics: RDB costs forks + periodic I/O (dumps cheap — windows coarse); AOF costs appends + fsync policies (precision priced — throughput measured); both cost composition (disk + I/O + complexity — recovery complete); fashion answers cost offers (recitation rejected — judgment hired). Place per need (windows stated — prices explicit); recite never (fashion transparent under pressure).

**Mentor note** — teach "window + price per placement" (juniors answering need → mechanism → window → price place persistence on first hearing; mechanism-only answers interrogated ("loses what? costs what?" — windows demanded per placement). Mock drill: interviewer attacking each choice (crash/restart/fsync follow-ups — pressure practiced, not theorized). Place by need; price every choice; survive follow-ups — persistence judgment in three habits, reviewed per placement.

## 2. Replication and failover live (async lag, split-brain, quorum — diagnosed with fixes, priced)

**Definition** — the failure-diagnosis answer interviewers grade: given symptoms, name the mechanism with fix and price — lagging replicas (INFO offsets diverging (async structural ([2.1](<../../sections/2. Copies/2.1. Replication async and replicas.md>) — staleness bounded (reads misrouted — critical on replicas (routing fixing — tolerance deciding); split-brain (partitions each primarying (minority promoting (quorum absent — writes diverging; fix: quorum-gated Sentinel ([2.2](<../../sections/2. Copies/2.2. Sentinel failover.md>) — minorities forbidden (agreement structural — decisions backed); failed failover (primary dead, no promotion (Sentinels few — quorum unreachable (detection solitary — automation absent; fix: ≥3 Sentinels + odown gating (majorities deciding — succession designed). "Live" means diagnosed with fixes (symptoms → mechanism → remedy → price — chains complete).

**What problem it solves** — the symptom-only trio: *lag undescribed* ("replicas slow" (mechanism unnamed — async unconsidered (offsets uncompared — routing unoffered (diagnosis absent — fixes random); *splits unrecognized* (divergence called "data issues" (quorum unconsidered — agreement unexamined (gating unoffered — consistency hoped); *failovers unowned* (dead primaries lingering (detection solitary — automation absent (promotion manual — toil priced per incident). Diagnosed failures convert incidents to mechanisms (symptoms mapping — fixes structural — prices explicit); interviewers grading diagnosis (mechanism + fix + price → hired; symptoms-only → rejected).

**Modern guidance** — the diagnosis lines (interview-enforced): *lag symptoms* (stale reads on replicas (async structural — offsets compared (routing fixing — tolerance deciding (critical to primary — lag priced); *split symptoms* (divergent writes post-partition (quorum absent — minorities promoting (gating fixing — agreement structural (decisions backed — splits safe); *failover symptoms* (dead primary unpromoted (detection solitary — Sentinels adding (quorum reaching — succession designed (automation proven — toil absent); *prices stated per fix* (routing free — Sentinels lightweight — quorum packets trivial (costs explicit — fixes adopted, not feared). Symptoms → mechanism → fix → price (chains complete — pressure survivable).

```bash
# GOOD: diagnosed with fix and price — symptoms mapping to mechanisms (interview-grade answer shape).
# "Stale money reads → async lag, critical misrouted (offsets diverging — routing fixing: money to primary,
# lag priced, tolerance deciding). Split writes diverging → quorum absent (minorities promoting — gating fixing:
# 2-of-3 Sentinel, agreement structural). Dead primary lingering → detection solitary (Sentinels adding)."
# BAD: symptoms only — mechanism absent, fixes random (real rejection shape).
# "Replication laggy — we added replicas." (Offsets uncompared — routing unexamined — lag persisting at larger
# cost (scaling absorbing, not fixing — diagnosis absent). Divergence called "data issues" (quorum unconsidered —
# gating unoffered). Diagnose mechanisms; price fixes; confirm post-deploy.)
```

**Common confusion** — *"synchronous replication fixes lag (WAIT everywhere)."* WAIT correlating availability (primaries waiting replicas (outages spreading — throughput coupling (safety priced in uptime — latency per write (freshness guaranteed — costs real); lag persisting structurally (replicas applying — networks delivering (delay shrinking, never zeroing (physics bounding — synchrony narrowing (windows tightening — absence unguaranteed); selective buying (critical WAITing — routine flowing (safety priced per write — sync bought where needed ([2.1](<../../sections/2. Copies/2.1. Replication async and replicas.md>) — guarantees physical (copies confirmed — routine unburdened). "Fixes" describes narrowing (windows tightening — lag shrinking); elimination describing unavailability (sync correlating — outages joining). Narrow selectively (WAIT critical — safety priced); eliminate never (physics bounding — availability joining).

**Performance note** — diagnosis economics: offset checks cost scrapes (visibility cheap — lag bounded); quorum packets cost heartbeats (agreement trivial — splits safe); WAIT costs latency per critical write (safety priced — routine flowing); undiagnosed equivalents cost stale money + divergent writes + lingering primaries (prices unbounded — customers discovering). Diagnose cheaply (scrapes — visibility); fix structurally (routing/quorum/automation — mechanisms matched).

**Mentor note** — teach "symptoms → mechanism → fix → price" (juniors chaining per failure diagnose replication on first hearing; symptom-only answers interrogated ("mechanism? fix? price?" — chains demanded per failure). Reproduction drill: lagged replica serving stale in staging, routing fixing (mechanisms tangible — trust earned by watching diagnosis close, not by documentation claims). Diagnose mechanisms; fix structurally; confirm post-deploy — failure judgment in three habits, reviewed per incident.

## 3. Crash windows live (loss bounded per layer — honesty under pressure, not hope)

**Definition** — the honesty answer interviewers grade: given crash scenarios, name the loss number with composition ([3.1](<../../sections/3. Crash truth/3.1. Crash semantics and durability windows.md>)) — kill -9 primary (unflushed buffers dying (AOF window losing — RDB schedule losing — total summing (numbers stated — worst cases bounding); failover during lag (promoted copies tailed (offsets missing — recency priced (loss measured — honesty additive); queue + crash combined (drains unflushed + syncs unsynced (layers summing — totals exceeding parts (comfort absent — calibration complete). "Live" means numbers stated (loss bounded — totals composed — hope absent).

**What problem it solves** — the hope-answer trio: *losses unstated* ("durable setup" (numbers absent — adjectives unquantified (follow-ups collapsing — pressure revealing recitation); *layers alone* (AOF claiming totals (queues uncounted — tails ignored (honesty partial — comfort false (totals understated); *drills missing* (recovery unrehearsed (procedures unowned — incidents improvising (evidence absent — demonstrations never (confidence hoped). Composed windows converting hope to calibration (numbers stated — layers summing — drills proving); interviewers grading honesty (numbers + composition + evidence → hired; adjectives → rejected).

**Modern guidance** — the honesty lines (interview-enforced): *numbers per layer* (RDB/AOF/lag numeric — windows stated (adjectives banned — calibration explicit (honesty priced — comfort absent); *totals composed* (drains + syncs + lags summing (worst cases bounding — end-to-end honest (single-layer claims returned); *drills evidenced* (kill -9 quarterly — failovers observed (losses measuring — totals verifying (practice proving — confidence earning); *follow-ups answered* (crash → ≤ total (numbers stated); combined → summed (composition honest); drilled → dated (evidence fresh). Every scenario carrying number + composition + evidence (judgment demonstrable — pressure survivable).

```bash
# GOOD: honesty evidenced — numbers stated, totals composed, drills dated (interview-grade answer shape).
# "kill -9 primary → ≤ AOF everysec 1s + drain 30s + lag 2s ≈ 33s worst case (layers summing — comfort absent).
# Failover during lag → promoted tail missing (offsets measured — recency priced — loss bounded, minimized).
# Drills quarterly, last 2026-09 (evidence fresh — procedures owned — confidence earning)."
# BAD: hope answer — adjectives unquantified, layers alone, drills missing (real rejection shape).
# "Durable with AOF." (Queues uncounted — tails ignored — honesty partial (comfort false — totals understated).
# Recovery never rehearsed (procedures unowned — incidents improvising — evidence absent.) Numbers beat adjectives.)
# State numbers; sum layers; date drills.)
```

**Common confusion** — *"zero data loss is achievable (with enough layers)."* Zero costing synchrony (WAIT every write (availability correlating — throughput coupling (safety priced in uptime — layers paying (latency per mutation — outages joining); hardware bounding (disks lying — power dying (physics limiting — guarantees stacked (software + hardware — certainty asymptotic (loss approaching, never reaching — honesty physical); business pricing (downtime vs loss (tolerances deciding — nines costing (zero-loss + available contradicting — trade-offs explicit (judgment business, never technical). "Achievable" describes budgets (synchrony + hardware + drills — loss minimized (approaching zero — reaching never); zero describing absolutes (physics denying — certainty unbuyable (honesty asymptotic). Minimize deliberately (layers stacking — loss approaching); promise never (physics bounding — certainty asymptotic).

**Performance note** — honesty economics: stating costs documentation (numbers free — calibration priceless); composing costs arithmetic (totals free — honesty additive (comfort absent — expectations real); drills cost staging quarterly (evidence fresh — recovery proven (practice priced — incidents executable); hope answers cost offers (adjectives rejected — numbers hired). State freely (numbers cheap — calibration priceless); prove recurrently (drills fresh — confidence earning).

**Mentor note** — teach "number, composition, drill date" (juniors answering all three per scenario place honesty on first hearing; adjective answers interrogated ("how many seconds? summed how? drilled when?" — evidence demanded per scenario). Pressure drill: interviewer stacking failures (crash-during-drain-during-lag — totals summing live (honesty tangible — trust earned by watching composition, not by documentation claims). State numbers; sum honestly — honesty judgment in two habits, reviewed per scenario.
