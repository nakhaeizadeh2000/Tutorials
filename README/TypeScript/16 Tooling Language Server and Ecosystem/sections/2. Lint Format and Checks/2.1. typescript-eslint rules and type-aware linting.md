## 2.1. `typescript-eslint` — rules and type-aware linting

### 1) **Recommended sets** (tiers: recommended, type-checked, strict)

**Definition** — three config tiers: `recommended` (syntax-only rules — no type information needed, fast, safe everywhere); `recommended-type-checked` (adds checker-backed rules — needs `projectService`/`project` wiring, slower lint runs); `strict` (+ stylistic-consistency rules — opinionated extras beyond correctness). Tiers compose (strict ⊃ type-checked ⊃ recommended — each level adds checking cost and rule coverage).

**What problem it solves / history** — flat all-on configs (every rule enabled — stylistic wars in review, 10-minute lint runs, rule *noise* burying real findings) versus no-config linting (syntax errors tsc already catches — lint adding zero value). Tiered adoption matches cost to value: recommended everywhere day one (free correctness), type-checked where check time allows (checker-backed findings), strict where teams want stylistic uniformity (opinionated consistency).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), start `recommended` (zero type-checking cost — pure syntax wins); graduate to `recommended-type-checked` with `projectService` (checker-backed rules — the rules that justify linting TypeScript at all, see promise 2); adopt `strict` selectively (extend strict, disable per-team objections with recorded reasons — uniformity where wanted, never imposed blindly).

**Runnable example** — tiers illustrated via the code they govern (good vs bad, `tsc --strict`):

```typescript
// good — recommended-tier clean (no-var, prefer-const, no-explicit-any-adjacent basics — syntax wins, zero type cost)
const role = "admin"; // prefer-const (never reassigned — const by rule, not vigilance)
function greet(name: string): string { return `hi ${name}`; } // explicit types where lint demands (configs vary — see promise 3 triage)
console.log(greet(role.toUpperCase())); // ADMIN — recommended-clean (fast lint, safe everywhere)
// bad — var role = "admin" (no-var violation — function-scoped hoisting hazards the rule deletes mechanically)
// fix — recommended tier day one (syntax correctness automated — reviewers never discuss var/const again)
```

```typescript
// good — type-checked-tier territory (rules needing checker facts — floating promises, misused promises, unnecessary conditions)
// (async examples below need type-aware rules to lint: no-floating-promises catches un-awaited rejections tsc accepts)
async function fetchId(): Promise<string> { return "u1"; }
async function use(): Promise<string> {
  return fetchId(); // awaited-or-returned (type-aware lint verifies promise handling — plain ESLint cannot see this)
}
console.log("typed-tier"); // type-checked rules (checker-backed findings — the tier justifying typescript-eslint over tsc-alone)
// bad — recommended-only linting (floating promises passing silently — the incident class type-aware rules exist to catch)
// fix — recommended-type-checked with projectService (checker-backed linting — cost measured, findings unique)
```

```typescript
// good — strict-tier extras (stylistic uniformity — consistent-type-imports, no-non-null-assertion where teams adopt)
// (strict extends type-checked with opinions: import kinds, assertion bans, naming shapes — uniformity, not correctness)
export interface Role { name: string } // local declaration (kind-stated imports per consistent-type-imports shown in 1.1/1.2 fences)
const r: Role = { name: "admin" };
console.log(r.name.toUpperCase()); // ADMIN — strict-tier shape (opinions encoded — uniformity automated)
// bad — strict-tier adopted blindly (opinion wars in review — strict rules need per-team recorded objections, not defaults)
// fix — extend strict, disable with reasons (uniformity where wanted — recorded objections, never imposed blindly)
```

**Common confusion** — "lint duplicates tsc" — recommended duplicates *little* (tsc checks types; lint checks *style/correctness-hygiene* tsc never flags — unused vars, ban patterns, import discipline); type-checked duplicates *nothing* (checker-*backed* rules tsc doesn't run — floating promises, unnecessary conditions). "type-aware lint is too slow" — `projectService` scopes checking incrementally (lint only changed files with cached programs — seconds, not minutes, post-warmup). "strict tier is strictly better" — strict adds *opinions* (stylistic uniformity — valuable where teams want it, friction where they don't — adopt selectively with recorded reasons).

**Performance note** — recommended tier adds seconds to lint runs (syntax-only — fast); type-checked adds checker time (program load + type queries — measured per repo, cached incrementally via projectService); strict adds rule-evaluation only (same program cost as type-checked). Measure lint time per tier before adopting (cost visible, findings compared).

**Mentor note** — enable tiers progressively on one package (recommended → type-checked → strict, measuring lint time + findings per tier) — cost-vs-value per tier made visible in one afternoon. Exercise: triage ten new findings per tier upgrade (real bugs vs style nits — findings classified, rules kept/killed per class). Review gate: un-triaged tier upgrades fail review (findings classified first).

### 2) **Type-aware rules that matter** (checker-backed findings plain ESLint can't express)

**Definition** — rules needing type information: `no-floating-promises` (un-awaited rejections — see 5.1 promise 2's incident), `no-misused-promises` (async functions in boolean/void positions — `if (asyncFn)` always-truthy bugs), `no-unnecessary-condition` (branches provably dead/alive by types — dead code and redundant guards flagged), `no-unnecessary-type-assertion` (casts narrowing nothing — laundering theater flagged), `await-thenable`/`require-await` (async shape discipline).

**What problem it solves / history** — plain ESLint sees *syntax* (un-awaited call looks identical awaited-or-not — `fetchData()` parses the same either way); only the *checker* knows it's a `Promise` (type facts distinguishing handled from floating). Type-aware rules convert checker facts into lint findings: floating promises flagged (not crashed on), unnecessary conditions flagged (not maintained forever), misused async flagged (not shipped as always-truthy branches).

**Modern guidance** — as of TypeScript 5.9 era, enable the five rules above first (highest incident-yield per rule — each maps to a production incident class in this track's pitfalls); fix findings structurally (await/catch floats; branch async predicates; delete dead conditions; remove theater casts); measure rule value quarterly (findings per rule — disabling zero-yield rules, keeping incident-preventing ones with evidence).

**Runnable example** — checker-backed findings (good vs bad, `tsc --strict`):

```typescript
// good — awaited promises (no-floating-promises satisfied — rejections handled, never floating)
async function load(id: string): Promise<string> { return `data:${id}`; }
async function use(): Promise<string> {
  return load("a"); // returned (handled by caller — no-floating-promises satisfied via return-chain)
}
console.log("handled"); // rule satisfied (rejections flow to callers — local handling, never floating)
// bad — load("a"); (floating promise — rejection unobserved → unhandledRejection → process crash in production)
// fix — await/return/catch every promise (handling explicit — no-floating-promises enforced as error, not warning)
```

```typescript
// good — conditions carrying information (no-unnecessary-condition satisfied — branches provable live)
function label(s: string | null): string {
  return s === null ? "none" : s.toUpperCase(); // necessary (union members distinguished — condition proves)
}
console.log(label(null), label("a")); // none A — live conditions (each branch reachable — rule silent correctly)
// bad — if (typeof "literal" === "string") (provably-true condition — dead logic maintained forever, readers confused)
// fix — delete provable conditions (no-unnecessary-condition flags them — dead branches removed, live ones kept)
```

```typescript
// good — assertions adding information (narrowing casts kept; theater casts flagged by no-unnecessary-type-assertion)
function narrow(x: unknown): string {
  if (typeof x !== "string") throw new Error("want-string"); // narrowed (assertion-free — predicate proves)
  return x.toUpperCase(); // narrowed string (no cast needed — rule would flag `x as string` here as theater)
}
console.log(narrow("hi")); // HI — theater-free assertions (casts only where narrowing can't reach — evidenced per cast)
// bad — (x as string).toUpperCase() after typeof-narrowing (theater cast — rule flags: assertion narrowing nothing, laundering risk)
// fix — no-unnecessary-type-assertion as error (theater casts deleted — remaining casts evidenced per site)
```

**Common confusion** — "type-aware lint duplicates tsc errors" — tsc errors on *type violations* (assignability, arity, exhaustiveness); type-aware lint flags *suspicious-but-legal* code (floating promises compile; dead conditions compile; theater casts compile) — legal-but-dangerous is lint's entire jurisdiction. "rules slow CI prohibitively" — projectService incrementalizes (changed files + cached programs — seconds post-warmup); measure before assuming (most repos: lint time dominated by parse, not types). "warnings suffice" — warnings *accumulate* (unread backlogs — findings rot); errors *block* (fixed or explicitly disabled with reason per line).

**Performance note** — type-aware rules cost program load + type queries per linted file (incremental via projectService — seconds, not minutes); findings prevent incidents (floating-promise crashes, dead-code maintenance, theater-cast laundering — unbounded upside per rule).

**Mentor note** — enable the five rules on one package and triage every finding (incident-preventing vs noise — per-rule evidence in one afternoon). Exercise: write one floating promise and watch no-floating-promises flag it (checker-backed finding demonstrated, not described). Review gate: disabled type-aware rules require recorded reason + metric (zero-yield evidence, not preference).

### 3) **Rule triage and exemptions** (warn-vs-error policy, disables with reason, baselines)

**Definition** — triage policy: errors block (violations fail CI — fixed or explicitly disabled per line with reason comments); warnings dashboard (counted, triaged quarterly — never ignored into backlog oblivion); disables carry justification (`// eslint-disable-next-line rule -- reason: <why>` — reasoned, dated where temporary); baselines for legacy adoption (`--max-warnings` ceilings that ratchet down, or baseline files exempting pre-existing violations while blocking new ones).

**What problem it solves / history** — warn-everything configs (hundreds of warnings, zero readers — findings rotting visibly while breaking nothing) and disable-comments without reasons (`// eslint-disable-next-line` bare — future authors afraid to remove, past reasons unrecoverable) both decayed lint from enforcement to decoration. Triage policy makes lint *binding*: errors block, warnings trend, disables justify — each state accountable.

**Modern guidance** — as of TypeScript 5.9 era, errors for correctness/safety rules (type-aware five, security, boundary conventions); warnings dashboarded with quarterly triage (count falling or rules re-tuned — never flat-and-ignored); disables reasoned inline (rule + why + date where temporary); baselines for legacy (`--max-warnings=N` ratcheting down per quarter, or flat-baseline files for pre-existing only).

**Runnable example** — triage states modeled (good vs bad, `tsc --strict`):

```typescript
// good — justified disable (reasoned, scoped, dated where temporary)
// eslint-disable-next-line @typescript-eslint/no-explicit-any -- TODO(Q4): scheduler API untyped upstream (issue #12)
export function legacy(task: unknown): string { return String(task); } // disable reasoned (boundary documented — see 13/1.2 explicit-any policy)
// fix — reasoned disables (rule + why + date — future authors remove confidently when reasons expire)
console.log(legacy("x").toUpperCase()); // X — justified escape (visible, dated, reviewable — not hidden)
```

```typescript
// good — warning dashboard shape (counts tracked — triage scheduled, never ignored)
// (dashboard config, documented as process: warnings: { count: 12, trend: "falling", review: "quarterly" })
// fix — dashboarded warnings (counted + triaged quarterly — falling or re-tuned, never flat-and-ignored)
export function clean(n: number): number { return n; } // warning-free code (dashboard green for this file — per-file progress visible)
console.log(clean(1).toFixed(0)); // 1 — clean files (triage progress measurable per file, not just globally)
// bad — warn-everything configs (hundreds of warnings, zero readers — findings rotting visibly while breaking nothing)
// fix — errors block, warnings trend, disables justify (three states, each accountable — lint binding, not decorative)
```

```typescript
// good — baseline ratchet (ceilings falling per quarter — legacy exempted, new code clean)
// (CI: --max-warnings 12 → 8 → 4 → 0 quarterly — ratchet documented in contributing guide, progress automatic)
// fix — ratcheting ceilings (legacy violations grandfathered precisely, new violations blocked absolutely)
export function fresh(s: string): string { return s.trim(); } // new code (zero warnings tolerated — baseline covers legacy only)
console.log(fresh("  y  ")); // y — ratchet working (new code clean — legacy shrinking on schedule)
// bad — bare disables (// eslint-disable-next-line with no reason — future authors afraid to remove, past reasons unrecoverable)
// fix — reasoned disables (rule + why + date — removability designed in from day one)
```

**Common confusion** — "disables are cheating" — *reasoned* disables are documentation (rule acknowledged, reason recorded, expiry dated — reviewable decisions); *bare* disables are cheating (acknowledgment without reasoning — unremovable by future authors). "baselines excuse legacy forever" — baselines *ratchet* (ceilings falling quarterly — legacy shrinking on schedule); flat baselines excuse forever (rejected — ratchet or remove). "warnings don't matter" — undashboarded warnings don't matter (invisible); dashboarded warnings trend (visible → triaged → falling or re-tuned).

**Performance note** — lint triage costs review minutes per finding class (one-time per class); un-triaged lint costs incident recurrence (same classes re-shipped quarterly); baselines cost CI seconds (ceiling checks — trivial). Triage economics favor completion heavily.

**Mentor note** — dashboard warnings quarterly live (counts + trends + per-rule decisions — triage as ceremony with data). Exercise: justify-or-delete five bare disables (reasoned + dated, or removed with fixes) — disable hygiene in under an hour. Review gate: bare disables fail review; un-triaged warning growth fails review.
