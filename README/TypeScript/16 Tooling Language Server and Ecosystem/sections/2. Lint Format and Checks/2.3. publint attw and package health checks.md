## 2.3. `publint`, `attw`, and package health checks

### 1) **`publint` packaging lint** (exports/types/files correctness pre-publish)

**Definition** — `publint` (Björn Carlo Funk's packaging linter) checks published package shape: `exports` map completeness (every public subpath mapped), `types` conditions present per subpath, `files` including needed outputs (no missing declarations at publish), dual ESM/CJS hazards (main/module/types coherence). Packaging bugs as lint errors *pre-publish* instead of consumer incidents post-release (see 12/5.1 promise 4's untyped-subpath class).

**What problem it solves / history** — packaging mistakes (unmapped subpaths resolving `any`, missing `types` conditions, `files` excluding `dist/*.d.ts`, dual-shape default hazards) shipped green CI and broke consumers (each a support ticket + patch release cycle). `publint` converts the 12/3.3 publishing checklist into automation: `npx publint` (local) + CI gate (blocking) — packaging verified like code, not hoped.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), run `publint` locally pre-publish (pack + lint the tarball — what ships is what's checked, not the working tree); gate in release CI (blocking — packaging errors fail like type errors); fix by mapping (exports/types/files corrected — never by consumer workarounds documented in READMEs).

**Runnable example** — packaging verified pre-publish (good vs bad, `tsc --strict`):

```typescript
// good — mapped package shape (publint-clean: exports + types + files coherent — the 12/3.3 wiring, linted)
// package.json shape (documented as config — publint reads it, not tsc):
// { "name": "calc", "types": "./dist/index.d.ts",
//   "exports": { ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" } },
//   "files": ["dist"] }
// (above: coherent wiring (types per subpath, files including outputs — publint verifies, CI gates)
export function add(a: number, b: number): number { return a + b; } // mapped export (types travel with the path)
console.log(add(20, 22).toFixed(0)); // 42 — packaged surface (wired + linted — consumers resolve typed, always)
// bad — unmapped public subpaths (JS emit without types conditions — consumer any-infection per unmapped path)
// fix — exports map with types per subpath + publint gate (wiring verified, not hoped — see 12/3.3 full treatment)
```

```typescript
// good — files including outputs (declarations shipped — no missing-.d.ts releases)
// package.json shape: { "files": ["dist"], ... } (dist/*.d.ts included — publint flags exclusions)
// (above: inclusion verified (publint checks tarball contents — what ships is what's checked, never the working tree)
export function sub(a: number, b: number): number { return a - b; }
console.log(sub(5, 3).toFixed(0)); // 2 — outputs shipped (declarations present — consumers check, never any-fall)
// bad — files excluding dist/*.d.ts (.npmignore legacy excluding declarations — JS ships, types missing — any-infection release)
// fix — files: ["dist"] with declarations emitted (inclusion verified — publint gates the tarball, not intentions)
```

```typescript
// good — dual-shape coherence (main/module/types agreeing — no consumer-kind surprises)
// package.json shape: { "main": "./dist/cjs.js", "module": "./dist/esm.js", "types": "./dist/index.d.ts",
//   "exports": { ".": { "types": "./dist/index.d.ts", "import": "./dist/esm.js", "default": "./dist/cjs.js" } } }
// (above: dual coherence (import/require/types aligned per subpath — publint verifies cross-condition agreement)
export function mul(a: number, b: number): number { return a * b; }
console.log(mul(6, 7).toFixed(0)); // 42 — coherent dual (every consumer kind resolves typed + runnable)
// bad — main/module/types disagreeing (CJS consumers loading ESM, types pointing at missing files — kind-specific breakage per consumer)
// fix — publint dual checks (cross-condition agreement verified — coherence proven pre-publish, not post-ticket)
```

**Common confusion** — "publint replaces tsc" — publint checks *packaging* (maps/conditions/files coherence); tsc checks *programs* (types/assignability) — complementary gates (both blocking, neither substituted). "publint is release-only" — run locally pre-publish (pack + lint loop — seconds) *and* in CI (blocking gate — drift caught even when locals skip). "packaging bugs are minor" — untyped subpaths infect *consumer* codebases with `any` (blast radius unbounded across dependents — packaging bugs are supply-chain incidents).

**Performance note** — publint runs in seconds (tarball pack + rule checks); attw adds resolution matrix time (per subpath × importer kind — seconds); combined gates add <1min to release CI vs patch-release cycles (days + trust) per escaped packaging bug.

**Mentor note** — pack + publint one release live (tarball contents listed, rules passing — what-ships-is-checked demonstrated in under a minute). Exercise: run publint on the repo's packages and triage each finding (unmapped paths, missing conditions, file exclusions — packaging backlog made countable). Review gate: releases without publint gates fail review (packaging verified, not hoped).

### 2) **`attw` resolution checks** (consumer-equivalent types resolution per importer kind)

**Definition** — `attw` (are-the-types-wrong — Andrew Branch's resolution checker) imports every package subpath *as each consumer kind would* (Node ESM `import`, CJS `require`, bundler, and `moduleResolution` variants) and reports resolution failures (untyped subpaths, wrong-condition types, false ESM/CJS duals). Consumer-equivalent verification: the package checked *the way dependents resolve it*, not the way its own tsconfig does.

**What problem it solves / history** — self-consistent packages (tsc green on sources, publint green on maps) still broke consumers (bundler resolving untyped fallback while Node resolved typed entry — kind-specific breakage invisible to single-perspective checks). `attw` multiplies perspectives (per subpath × per importer kind — the resolution matrix) — kind-specific failures surface pre-publish instead of per-consumer post-release.

**Modern guidance** — as of TypeScript 5.9 era, run `attw --pack` in release CI (tarball resolution matrix — blocking gate alongside publint); fix kind-specific failures at the map (conditions per subpath per kind — never consumer-side workarounds); re-run on dependency/toolchain upgrades (resolution behavior shifts per Node/bundler/tsc versions — matrix re-verified, not assumed stable).

**Runnable example** — consumer perspectives multiplied (good vs bad, `tsc --strict`):

```typescript
// good — dual-consumable surface (import + require resolving typed — matrix green across kinds)
// package.json shape: dual conditions per subpath (import → .mjs + types; require → .cjs + types — kind-specific correctness)
export function kind(): string { return "dual"; } // dual-shape export (both importer kinds served — attw verifies each)
console.log(kind()); // dual — matrix green (Node-ESM + CJS + bundler resolving typed — consumer-equivalent proof)
// bad — import-only testing (require consumers resolving untyped/wrong entries — kind-specific breakage invisible to single-perspective CI)
// fix — attw matrix (per subpath × per kind — kind-specific failures surface pre-publish, not per-consumer post-release)
```

```typescript
// good — subpath matrix (every public path resolved per kind — no untyped publics hiding behind root-only testing)
export function sub(): string { return "sub"; } // subpath export (types condition present — attw checks per path, not just root)
// (attw shape: root + every exports subpath × {node-esm, cjs, bundler} — matrix complete, failures located per cell)
// fix — subpath smoke per release (strict imports per public path — 12/3.3 promise 3's gate, attw-automated here)
console.log(sub()); // sub — subpath matrix (coverage complete — root-green/subpath-red classes eliminated)
// bad — root-only resolution testing (subpaths resolving any/fallback — untyped publics shipping behind green root checks)
// fix — matrix per subpath (attw enumerates — coverage complete across paths AND kinds simultaneously)
```

```typescript
// good — false-dual detection (CJS-named-ESM mismatches flagged — kind confusion caught pre-publish)
export function real(): string { return "real"; } // honestly-shaped export (ESM syntax in .mjs, CJS in .cjs — shapes matching conditions)
// (attw shape: false-dual detection (masquerading entries flagged — kind confusion surfaced with fix pointers)
// fix — honest duals (matching shapes per condition — attw verifying, not hoping, per subpath per kind)
console.log(real()); // real — kind-honest packaging (consumers resolve what conditions promise — verified per cell)
// bad — .js-dual masquerade (CJS syntax under import conditions — Node-ESM consumers crashing on require-of-ESM errors)
// fix — attw false-dual checks (masquerades flagged with pointers — honesty enforced per condition per subpath)
```

**Common confusion** — "attw duplicates publint" — publint checks *map coherence* (conditions present, files included, duals agreeing); attw checks *resolution outcomes* (per subpath per kind, actually importing — behavioral verification vs structural lint). "matrix testing is slow" — seconds per package (tarball pack once, resolution matrix cached per run); consumer tickets cost days each (matrix time vs ticket time — orders apart). "green attw means perfect packaging" — green means *resolvable+typed per matrix cell* (content correctness — APIs, semantics, versions — still needs the 12/3.3 gates + tests).

**Performance note** — attw runtime seconds per package (pack + matrix resolution); findings prevent per-consumer incidents (unbounded downstream debugging per escaped kind-specific breakage). Matrix verification is the cheapest consumer-equivalence available.

**Mentor note** — run attw on one dual package live (matrix cells green/red per subpath per kind — consumer perspectives made visible in one table). Exercise: break one condition deliberately (remove a subpath types entry) and watch attw locate the exact failing cells (failing-cell precision vs "consumers report any" vagueness). Review gate: releases without attw matrix fail review (consumer-equivalent proof required).

### 3) **Health-gate composition** (publint + attw + smoke — release proof, not hope)

**Definition** — composed release gates: `publint` (packaging coherence) + `attw` (resolution matrix) + per-subpath strict smoke imports (consumer-equivalent typecheck) — all blocking in release CI, in that order (coherence → resolution → consumption). Green across all three proves consumer outcomes (typed, resolvable, checkable per subpath per kind); any red blocks publish (packaging bugs fail like type errors — release-stopping, not advisory).

**What problem it solves / history** — single-gate releases (tsc-only: programs green, packaging broken; publint-only: maps coherent, resolution kind-broken; smoke-only: root typed, subpaths any) each missed the classes the other gates catch — defense in depth with single-point gaps. Composed gates cover packaging × resolution × consumption jointly: escaping requires defeating all three (independent failure modes — combined coverage, no single gap).

**Modern guidance** — as of TypeScript 5.9 era, gate all three in release CI (publint + attw + smoke matrix — blocking, ordered coherence→resolution→consumption); fix per failing gate (map errors → 12/3.3 wiring; resolution errors → conditions per kind; smoke errors → declarations per subpath); version gates with the repo (new failure modes append gates — checklist grows with incident history, see 11's stamp playbook pattern).

**Runnable example** — composed proof (good vs bad, `tsc --strict`):

```typescript
// good — gate trio green (coherence + resolution + consumption proven — release ships on proof)
// (CI shape: publint (maps coherent) → attw (matrix green) → smoke (subpaths check) — ordered, blocking, automated)
export function shipped(): string { return "s"; } // gated surface (all three gates green — consumer outcomes proven)
console.log(shipped()); // s — proof composed (packaging × resolution × consumption — no single gap remaining)
// bad — tsc-only releases (programs green, packaging/resolution unchecked — consumer incidents per un-gated class)
// fix — trio gates (independent failure modes covered jointly — escaping requires defeating all three simultaneously)
```

```typescript
// good — gate failure routing (each gate's failures map to fixes — no generic "packaging broken" tickets)
export function routed(): string { return "r"; } // (publint fails → 12/3.3 wiring; attw fails → conditions per kind; smoke fails → declarations per subpath)
// fix — per-gate fix routing (failure kinds locate fixes — debugging directed, not archaeological)
console.log(routed()); // r — routed gates (each failure maps to its fix layer — triage instant, not investigative)
// bad — single packaging gate (publint-only: kind-specific resolution breakage ships behind coherent maps)
// fix — composed trio (joint coverage — single gates leave single gaps; trios leave none unaddressed)
```

```typescript
// good — gates versioned with incident history (new failure modes append gates — checklist grows, coverage compounds)
export const gates = ["publint", "attw", "smoke"] as const; // gate list (versioned — new classes append, never replace)
console.log(gates.join("+")); // publint+attw+smoke — composed proof (coverage compounding per incident class learned)
// bad — frozen gate sets (checklists never growing — novel failure modes shipping through gates designed for old ones)
// fix — incident-driven gate growth (each packaging incident appends a gate/check — 11's stamp playbook applied to releases)
```

**Common confusion** — "three gates slow releases" — seconds combined (pack + matrix + smoke, parallelizable); escaped packaging bugs cost patch cycles (days + trust each). "gates duplicate each other" — coherence (maps), resolution (per-kind outcomes), consumption (strict typecheck) — independent failure modes (each gate catches classes others miss by construction). "small packages skip gates" — gates scale with zero human steps (automation per release); hope scales with forgetting (incidents per un-gated class, regardless of size).

**Performance note** — trio runtime seconds-to-minute (parallelizable); incident cost days + consumer trust per escaped class. Composed gates are the cheapest release insurance in typed-package practice.

**Mentor note** — break one gate deliberately (unmap a subpath) and watch the trio locate it (publint flags coherence, attw flags cells, smoke fails imports — layered location vs single-point vagueness). Exercise: audit the last three releases against all three gates retroactively (misses found = gates' ROI, receipt included). Culture pattern: same as 11's enum stamp (measured behavior, celebrated prevention).
