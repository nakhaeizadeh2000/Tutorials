## 1.3. Inlay hints, hover, and signature help

### 1) **Inlay hints as inline documentation** (parameter names, inferred types, annotations)

**Definition** — inlay hints render *inferred* information inline (parameter names at call sites `fetch(/* url */ "…")`, inferred return types after function signatures, variable annotations where widening matters) — editor-virtual text (zero file bytes — display only, never committed). Hints make the checker's knowledge visible *where it's used* instead of requiring hover round-trips per question.

**What problem it solves / history** — positional call sites (`connect("h", 80, true)` — which is which? readers jumped to declarations per argument) and widened-variable surprises (`let x = "a"` inferred `string` — discovered only when literal behavior was expected) taxed comprehension per occurrence. Inlay hints answer inline (parameter labels per argument, inferred types per declaration) — declaration knowledge displayed at use sites automatically.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), enable inlay hints selectively (parameter names + variable types on; noisy return-type hints off where signatures already declare); write code *as if* hints show (labeled params, descriptive names — hints amplify good naming, don't rescue bad); disable per-workspace where noise exceeds signal (hint configuration is personal-environment, team-shared defaults).

**Runnable example** — hints make inference visible (good vs bad, `tsc --strict`):

```typescript
// good — labeled params + descriptive names (hints amplify clarity — inlay shows what code already says)
function connect(host: string, port: number, secure: boolean): string {
  return `${secure ? "https" : "http"}://${host}:${port}`; // inlay: host/port/secure labels per argument at call sites
}
console.log(connect("h", 80, false)); // http://h:80 — hints label each positional (no declaration jump needed)
// bad — (h: string, p: number, s: boolean) cryptic params (hints display cryptic labels — garbage in, garbage displayed)
// fix — descriptive params (hints amplify naming — good names displayed inline, bad names exposed inline)
```

```typescript
// good — inferred types visible where widening matters (variable hints preempt literal surprises)
const method = "get"; // inlay: string (widened — visible before exhaustiveness is expected downstream)
const fixed = "get" as const; // inlay: "get" (narrow — visible precision, no hover round-trip needed)
console.log(method.toUpperCase(), fixed); // GET get — hints showing widening vs narrowing inline (diagnosis without hovering)
// bad — discovering widening at the exhaustiveness error (declaration far from symptom — inlay would have shown it inline)
// fix — variable-type hints on (widening visible at declaration — surprises preempted, not debugged)
```

```typescript
// good — return-type hints where signatures are absent (inferred returns displayed — explicitness decided per function)
function doubled(n: number) { return n * 2; } // inlay: `: number` (inferred — hint shows what annotation would state)
console.log(doubled(21).toFixed(0)); // 42 — hinted return (callers read the type inline — no jump to implementation)
// bad — explicit `: number` everywhere hints already show (annotation noise duplicating display — code bloat for zero information)
// fix — annotate public boundaries (contracts explicit), hint internals (inference displayed — explicitness where it contracts)
```

**Common confusion** — "hints replace annotations" — hints *display* inference (virtual, personal, unsettable per repo); annotations *contract* (bytes, shared, reviewable) — display vs contract differ (public boundaries annotate regardless of hints). "hints slow the editor" — hint computation reuses checked types (marginal cost on already-checked programs); noisy hints cost *attention*, not performance (configure per signal, not per speed). "hints teach types" — hints *reveal* inference (widening visible); understanding still requires the vocabulary (03's widening rules explain what hints display).

**Performance note** — hint rendering costs editor cycles per visible line (bounded by viewport — large files unaffected off-screen); check cost unchanged (hints read computed types, never recompute). Configure per attention budget (signal-rich hints on, noise off).

**Mentor note** — toggle hints on/off beside widened vs narrowed declarations (invisible surprise vs inline diagnosis — inlay value in one toggle). Exercise: read three call sites with hints hidden (jump per argument) vs shown (labels inline) — comprehension time measured per mode. Review gate: cryptic params/names fail review (hints amplify naming — garbage displayed is still garbage).

### 2) **Hover reading discipline** (expanded types, JSDoc rendering, type-definition jumps)

**Definition** — hover discipline: read *expanded* types (alias references expanded to structures — `Partial<User>` as `{ id?: string }`, not the alias name), JSDoc rendering (documented contracts displayed with signatures — `@param`/`@returns`/`@example`), and jump *from* hovers (go-to-type-definition for deep dives — hover first for orientation, jump for depth). [09/1.1](<../../../09 Utility Types and Type Transformations/sections/1. Mapped Types/1.1. Mapped type fundamentals homomorphic mapping over keys.md>) promise 3 owns result-first hover reading for transforms; this promise generalizes it repo-wide.

**What problem it solves / history** — alias-name hovers (`Partial<User>` displayed unexpanded — readers guessing member optionality) and undocumented signatures (hover showing `(x: T) => U` with zero contract context) forced jumps for every question (depth-first navigation for orientation-level needs). Expanded hovers + JSDoc answer orientation inline (structures visible, contracts readable); jumps reserved for depth (implementations, call graphs, cross-file flows).

**Modern guidance** — as of TypeScript 5.9 era, expand hovers before judging (alias → structure via expansion controls); document public signatures with JSDoc (`@param` per parameter, `@returns`, `@example` per non-obvious function — hover-rendered contracts); jump from hovers for depth (go-to-type-definition on expanded members — orientation first, depth second).

**Runnable example** — hover-first reading (good vs bad, `tsc --strict`):

```typescript
// good — JSDoc contracts render in hovers (signatures + docs, orientation inline)
/** Doubles non-negative inputs; throws on negatives (contract documented where hovered). */
function doubled2(n: number): number {
  if (n < 0) throw new Error("negative"); // documented throw (hover shows contract — callers prepared before calling)
  return n * 2;
}
console.log(doubled2(21).toFixed(0)); // 42 — hovered signature (docs + types inline — jump only for implementation depth)
// bad — undocumented public signatures (hover shows (n: number) => number — contract invisible, jump required per question)
// fix — JSDoc per public function (@param/@returns/@throws — hover-rendered contracts, orientation inline)
```

```typescript
// good — expanded mapped types read as structures (result-first hover discipline per 09/1.1 generalizes here)
interface Profile { name: string; age?: number }
type Flex = Partial<Profile>; // hover Flex → { name?: string; age?: number } (expanded — optionality visible per member)
const f: Flex = {};
console.log(Object.keys(f).length); // 0 — expanded hover (structure read — alias name never the answer)
// bad — trusting alias names (Partial "means optional" — which members? how deep? — alias-level reading, structure unknown)
// fix — expand hovers (result-first reading — structures verified, not assumed from names)
```

```typescript
// good — go-to-type-definition from hovers (orientation → depth in one jump, back to return)
export interface OrderT { id: string }
export function totalT(o: OrderT): number { return o.id.length; } // hover totalT (signature inline — orientation complete)
// (go-to-type-definition on OrderT jumps to its declaration — depth on demand, orientation preserved via go-back)
// fix — hover first (orientation inline), jump for depth (implementations/flows), go-back to return (disorientation-free)
const o: OrderT = { id: "ab" };
console.log(totalT(o).toFixed(0)); // 2 — hover-first flow (inline orientation, on-demand depth, stacked returns)
// bad — jumping for every question (depth-first navigation for orientation needs — disorientation per jump, context rebuilt per return)
```

**Common confusion** — "hover shows everything" — hovers show *signatures + docs* (orientation); implementations/flows need jumps (depth) — orientation-first, depth-second, always in that order. "JSDoc duplicates types" — JSDoc documents *contracts* (throws, edge cases, examples — untypeable knowledge); types document *shapes* (checkable structure) — complementary, never duplicated. "expanded hovers are verbose" — verbosity *on demand* (expand per question); alias names stay compact by default — expand deliberately, not globally.

**Performance note** — hover computation reads indexed/cached types (milliseconds — same cost class as navigation); JSDoc rendering parses comments per hover (trivial); expansion renders on demand (large mapped results expand slowly — verify with small instantiations per 09/1.1 guidance).

**Mentor note** — hover one undocumented vs one JSDoc'd signature side by side (bare types vs contract — documentation value in one comparison). Exercise: document five public functions (JSDoc with @param/@returns/@example/@throws) and hover-verify each renders (contracts visible inline — orientation complete without jumping). Review gate: public functions without JSDoc fail review (hover-rendered contracts are API documentation).

### 3) **Signature help at call sites** (overload navigation, active-parameter tracking)

**Definition** — signature help (parameter info on `(` — overload list navigable, active parameter highlighted, documented per overload via JSDoc) guides calls *as typed*: which overload applies (arity/shape matching), which parameter is active (position tracked through commas/nesting), what each expects (types + docs inline). Overloaded and optional-heavy APIs become callable without memorizing signatures.

**What problem it solves / history** — overloaded APIs called blind (`fetch(url, {...})` — which overload? what options? readers jumped to `.d.ts` per call, memorizing overload lists that changed per release) produced wrong-arity/wrong-shape calls caught only at check time (edit-compile cycles per argument). Signature help answers inline (applicable overloads filtered as you type — valid calls composed without leaving the call site).

**Modern guidance** — as of TypeScript 5.9 era, read signature help per unfamiliar call (overload ←/→ navigation, active parameter tracking, JSDoc per overload); write overloads with distinguishable first parameters (help filters usefully — identical prefixes render indistinguishable lists); document overloads independently (JSDoc per signature — help displays per-candidate contracts).

**Runnable example** — help-guided calls (good vs bad, `tsc --strict`):

```typescript
// good — distinguishable overloads (help filters usefully — first parameters differ per candidate)
function get(path: string): string;
function get(path: string, opts: { raw: boolean }): string;
function get(path: string, opts?: { raw: boolean }): string { return opts?.raw ? `raw:${path}` : path; }
// (signature help on get( shows both candidates; typing "{" filters to the second — applicable overload composed inline)
console.log(get("/a"), get("/b", { raw: true })); // /a raw:/b — help-guided calls (overloads navigated, not memorized)
// bad — (path: string, opts?: object) single wide signature (help shows one uninformative candidate — options undiscoverable)
// fix — overloads with distinguishable shapes (help filters per candidate — discoverability designed, not hoped)
```

```typescript
// good — labeled optional params (help tracks active parameter through commas — position always known)
function openDb(host: string, port?: number, secure?: boolean): string {
  return `${secure ? "https" : "http"}://${host}:${port ?? 80}`; // help highlights host→port→secure per comma (active parameter tracked)
}
console.log(openDb("h"), openDb("h", 1, true)); // http://h:80 https://h:1 — tracked calls (position known per argument)
// bad — options-bag-only APIs for 1-2 params (help shows one bag shape — per-argument guidance lost for trivial arity)
// fix — positional params for small arity (help tracks per argument); bags past ~4 params (help shows bag keys instead)
```

```typescript
// good — JSDoc per overload (help displays per-candidate contracts — documented overloads callable without source dives)
/** Fetch text (simple call — returns body). */
function fetchText(url: string): string;
/** Fetch with options (configured call — timeout + retries honored). */
function fetchText(url: string, opts: { timeout: number }): string;
function fetchText(url: string, opts?: { timeout: number }): string { return `${url}:${opts?.timeout ?? 0}`; }
console.log(fetchText("/x"), fetchText("/y", { timeout: 5 })); // /x:0 /y:5 — documented candidates (help shows per-overload docs)
// bad — undocumented overloads (help lists bare signatures — contracts invisible, source dive per candidate)
// fix — JSDoc per overload signature (help-rendered contracts — overloads callable without leaving the call site)
```

**Common confusion** — "signature help replaces reading `.d.ts`" — help *orients* (applicable candidates per call); `.d.ts` reading *audits* (full surface review) — orientation vs audit differ. "more overloads help more" — overloads past ~4 candidates overwhelm help lists (indistinguishable shapes render noise) — union params or options bags past complexity thresholds (see 05/2.1 judgment). "help works without JSDoc" — works *mechanically* (signatures listed); contracts need JSDoc (undocumented overloads list bare shapes — callable, not comprehensible).

**Performance note** — signature help computes per keystroke (filtered overload lists — milliseconds on indexed programs); JSDoc rendering parses per candidate (trivial); overload-heavy files slow help marginally (candidate enumeration per `(` — keep overload sets small for editor responsiveness too).

**Mentor note** — trigger help on one overloaded call live (candidates navigated, active parameter tracked — calling guided without memorization). Exercise: document three overload sets (JSDoc per signature) and call each via help only (no source dives — help-composed calls). Review gate: public overloads without per-signature JSDoc fail review.
