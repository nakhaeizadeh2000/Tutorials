## 1.3. Inlay hints, hover, and signature help

### 1) **Separate displayed information from source contracts**

Inlay hints display information such as parameter names or inferred types near source text. Hover shows type information and documentation for a selected expression. Signature help shows callable signatures and the parameter being entered. They answer related reading questions, but displaying information does not add a type annotation, change an argument or verify a documented behavior.

Use **TypeScript 7.0.2** and emitted ES2022 modules on **Node.js 20.20.2** for this fixture. Save the following file in an empty directory without a `tsconfig.json`. Compile with `tsc --strict --target es2022 --module nodenext --outDir dist hints.mts`, then run `node dist/hints.mjs`. The formatting function performs no network operation.

```typescript
// file: hints.mts
const method = "get";
let mutable = "get";
const settings = { method: "get" };
const fixed = { method: "get" } as const;
/** Format a local address; this function opens no connection. */
function connect(host: string, port: number, secure: boolean) {
  return `${secure ? "https" : "http"}://${host}:${port}`;
}
/** Return a local label. */
function choose(kind: "name"): string;
/** Return a local count. */
function choose(kind: "count"): number;
function choose(kind: "name" | "count"): string | number { return kind === "name" ? "local" : 2; }
const value = choose("count");
console.log(method, mutable, settings.method, fixed.method, connect("host", 80, false), value);
const literal: "get" = method;
console.log(literal);
// const wrongVariable: "get" = mutable; // TS2322: this variable's type is string.
// const wrongProperty: "get" = settings.method; // TS2322: this property is mutable and inferred as string.
// fixed.method = "post"; // TS2540: the const assertion gives a readonly property type.
// choose("other"); // TS2769: neither declared overload accepts this argument.
```

Expected output:

```text
get get get get http://host:80 2
get
```

`method` already has the literal type `"get"`; a const assertion is not required for that scalar constant. The let variable and the mutable object property are inferred as string. The const-asserted property retains the literal and is readonly in checked code. These are type-system facts that can be tested independently of what an editor chooses to display. [Inference and contextual typing](<../../../03 Basic Types and Annotations/sections/3. Annotations Inference and Literals/3.2. Type inference widening and contextual typing.md>) owns those mechanics in full.

### 2) **Read hints and hover with their configuration in mind**

The native 7.0.2 hover responses for the fixture reported:

| Selected expression | Type information in the response |
|---|---|
| method declaration | `const method: "get"` |
| mutable declaration | `let mutable: string` |
| settings.method use | property method has type string |
| fixed.method use | property method has type `"get"` |
| connect declaration | string parameters/number/boolean parameters, string return, plus its JSDoc |

The variable and property results explain why identical runtime strings need not have identical static types. A missing hint is not evidence of a widened type: with the tested preferences, the server produced a string variable hint for mutable but no variable-type hint for the simple method constant. Hover and a targeted assignment probe supplied the answer.

With parameter-name hints and relevant type hints enabled, the tested server returned host, port and secure labels for the connect call, an inferred string return hint for connect and a number variable hint for value. Other calls can also generate labels, which is why enabling every category may add noise. Choose the display that helps the reader rather than assuming every omitted annotation needs a hint or every hint should become source text.

[VS Code's editing guide](https://code.visualstudio.com/docs/typescript/typescript-editing) documents current settings including `js/ts.inlayHints.parameterNames.enabled`, `js/ts.inlayHints.variableTypes.enabled` and `js/ts.inlayHints.functionLikeReturnTypes.enabled`. In this headless test, the native server's workspace configuration enabled parameter names as all, variable types and inferred return types. Another client may map its settings differently. Confirm the active provider and configuration when reproducing a display difference.

Hover text can use aliases, formatting choices or truncated representations. It is not a promise to expand every conditional or mapped type completely. Inspect relevant members, navigate to a declaration or use a small assignability probe when a displayed name is insufficient. An explicit annotation can establish a stable checked boundary or reveal a mismatch; it is not redundant merely because a personal editor preference displays the current inference.

### 3) **Use signature help to guide a call, then check the call**

At the call `choose("count")`, the tested native response listed both declared overloads, their separate JSDoc descriptions and an active signature index of 1 with active parameter 0. Those are zero-based indexes, so the active signature was the count overload and the active parameter was kind. The inferred value type was number, confirmed separately by a compiler assignment probe.

This does not mean that typing automatically removes every inapplicable overload from the displayed list: both appeared in this response. The implementation signature accepting the union is also not an extra public call overload. The compiler rejects `choose("other")`. [The overload lesson](<../../../05 Functions and Callable Types/sections/2. Overloads and Generics/2.1. Function overloads call signatures and implementation compatibility.md>) owns implementation compatibility and call selection.

JSDoc adds meaning that a signature alone may omit, such as whether a helper formats an address or actually opens a connection. It remains a claim written by an author. A comment promising retries or a timeout does not implement them, and displayed documentation is not evidence that they ran. Keep the description aligned with the invoked body and observed behavior.

The verification used actual native hover, inlay-hint and signature-help requests plus compiler/runtime checks. Editor rendering, toggles and keyboard interaction were not automated. As a reading exercise, hide the hints, predict each type and argument meaning, then compare the provider's responses. If a complex call is hard to understand, consider a better API shape or explicit source contract; there is no fixed overload-count or parameter-count threshold that settles that design.

### 4) **Common confusion**

Const does not widen a standalone string constant to string in this example, while const on an object binding does not make its properties readonly. A const assertion changes the checked property representation; it does not freeze the runtime object. Use the [object modifier owner](<../../../04 Objects Interfaces and Type Aliases/sections/1. Object Type Fundamentals/1.2. Optional readonly and index signatures.md>) for mutation and runtime evidence.

Hover, hints, documentation and signature help are different presentations of information. They do not replace the function body, semantic checking or runtime validation. A selected help candidate is useful guidance, not permission to pass an argument the declared signatures reject.

### 5) **Performance note**

A request can need project loading, type analysis and construction of display data, while rendering is separate client work. Caching and computation vary by implementation and project state. This fixture establishes returned information and runtime output, not fixed response time, viewport-bounded computation or zero additional checking cost. If hints or hover are slow, compare the actual request and loaded project before attributing the delay to visual clutter alone.

### 6) **Mentor note**

Ask the learner to predict the four method types before inspecting hover, then activate the compiler negative cases one at a time. Explain why no hint appeared for one constant and why both overloads remained in signature help. Finish by comparing connect's documentation with its implementation. A strong answer separates inferred type, source contract, provider presentation and behavior that was actually executed.
