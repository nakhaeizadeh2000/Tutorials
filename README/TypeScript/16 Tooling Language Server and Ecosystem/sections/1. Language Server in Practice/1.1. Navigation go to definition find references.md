## 1.1. Navigation — go to definition, find references

### 1) **Ask a specific question about a loaded project**

Go to Definition asks where a selected symbol is declared. Go to Type Definition asks for its type's declaration, while an implementation query asks for implementations supported by the provider. A semantic reference query follows a symbol's identity rather than simply matching its spelling. These are useful ways to explore code, but their answers depend on the server version, loaded files, configuration and available package artifacts.

This example uses **TypeScript 7.0.2** and **Node.js 20.20.2**. TypeScript 7 supplies a native language server using LSP; it is distinct from older JavaScript `tsserver` clients and compiler API integrations. Select an editor integration that supports the installed server and confirm its active version/project. The [release announcement](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/) explains the transition; the exact selection UI is editor-specific.

Save these files together in an empty directory. Compile with `tsc -p tsconfig.json` and run `node dist/app.mjs`. No dependencies are required. The comment identifying each filename is not part of the JSON file.

```json
// file: tsconfig.json
{
  "compilerOptions": {
    "strict": true,
    "target": "ES2022",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "verbatimModuleSyntax": true,
    "outDir": "dist"
  },
  "files": ["core.mts", "contract.d.mts", "app.mts"]
}
```

```typescript
// file: core.mts
export function compute(value: number): number { return value * 2; }
export function publicHook(): string { return "external callers may use this"; }
```

```typescript
// file: contract.d.mts
export interface Contract { label: string }
```

```typescript
// file: app.mts
import { compute as double } from "./core.mjs";
import type { Contract } from "./contract.mjs";
function compute(value: number): number { return value + 10; }
const routeKey = "compute";
const item: Contract = { label: "local" };
console.log(double(21), compute(1), routeKey, item.label);
```

```typescript
// file: outside.mts
import { compute } from "./core.mjs";
console.log(compute(5));
```

Expected runtime output is `42 11 compute local`. The declaration-only Contract import is erased; no `contract.mjs` runtime provider is needed. `outside.mts` exists on disk but is not a configured root and is not imported by the listed files. Its presence lets us vary the server's loaded project set separately from the batch command.

### 2) **Trace definitions and compare reference scope**

On `double(21)`, ask for Go to Definition. The native 7.0.2 server returned the declaration of `compute` in `core.mts`. On the Contract annotation, it returned `contract.d.mts`. The first target has an implementation; the second describes a type. Their file extensions do not establish ownership: declaration files can belong to your own package, and JavaScript can have inferred or JSDoc-based types.

For a package, inspect its resolved declaration, source availability and declaration maps before explaining a source jump. A declaration map can route a client to available original sources; it does not create missing source files or guarantee identical behavior in every editor. [Public declaration surfaces](<../../../12 Modules Namespaces and Declaration Files/sections/3. Declaration Files in Practice/3.1. Authoring d.ts public API surface.md>) and [project references](<../../../13 Configuration and Compiler Options/sections/3. Modules Emit and Projects/3.2. declaration composite project references.md>) own the full artifact setup.

For `core.mts`'s exported compute, the headless reference request with `includeDeclaration: true` returned four locations: its declaration, the imported name, its local alias and the alias call. It did not include the unrelated local `compute`, the string `"compute"` or the unopened outside file. Opening `outside.mts` through the same server added its import and call, producing six locations. These counts describe this fixture and request, not a universal editor reference-count convention.

This contrast is useful before an API change. Check which project the query covers, inspect aliases and compare textual matches where strings, registration keys, templates or generated consumers may matter. A reference search is not a proof that all external package consumers are known. Even an export with no other returned locations, such as publicHook in the configured project, can be used by a consumer outside this workspace. Review the public contract before deleting it.

The [Knip maintainer's analysis of reference traversal](https://knip.dev/blog/slim-down-to-speed-up) gives a concrete historical example of the work needed to follow aliases and exported members. Its 2023 implementation and measurements do not establish the cost or completeness of this server query.

### 3) **Use search and peek without confusing them with proof**

A workspace-symbol query for `compute` returned the two declarations named compute in this fixture. That search locates candidates; selecting a candidate determines which binding subsequent definition or reference requests inspect. Approximate matching and ranking depend on the provider. Do not rely on an invented fuzzy abbreviation as a portable guarantee.

In an editor, use Peek Definition when an inline view answers the question, jump when you need surrounding code, and return through the navigation history. [VS Code's navigation documentation](https://code.visualstudio.com/docs/typescript/typescript-editing#_code-navigation) lists the command names. Keybindings vary by platform and user configuration. Reading a file, browsing directories and searching text remain useful when you do not yet know a symbol's name or when investigating a string-based protocol.

The fixture was checked with the native server's definition, reference, document-symbol and workspace-symbol requests. The editor's peek rendering and keybindings were not automated. A successful `tsc` run or console output alone would not verify any navigation result; conversely, successful navigation does not prove the emitted program's behavior.

Practice by opening only core/app first, finding the exported symbol's references, then opening outside and repeating the request. Explain why the local same-name function and route string need a different investigation. If results differ, first record the active server, project membership and query options before assuming a compiler defect.

### 4) **Common confusion**

Definition, type-definition and implementation requests ask different questions. A declaration file is a contract representation, not evidence that the package is yours or someone else's. A JavaScript target is not inherently untyped.

Semantic references and textual search also answer different questions. The former can follow the aliased binding without counting an unrelated local name; the latter can reveal protocol strings and files outside the loaded program. Neither alone certifies deletion safety or every future consumer.

### 5) **Performance note**

Navigation can trigger project loading, module resolution and semantic analysis. Query time and memory depend on project size, state, configuration and implementation; there is no guaranteed constant-time lookup or fixed millisecond response. This fixture measures returned locations, not latency or productivity. If responsiveness is a problem, record the slow operation and distinguish cold project loading from repeated queries before tuning it.

### 6) **Mentor note**

Ask the learner why two same-name functions have different reference sets, why the imported alias belongs to the exported function's set, and what opening outside changed. Then ask whether publicHook is safe to remove and what a declaration-only target tells them. A sound answer names the loaded scope, the symbol identity, the artifact layer and the evidence still needed for external consumers.
