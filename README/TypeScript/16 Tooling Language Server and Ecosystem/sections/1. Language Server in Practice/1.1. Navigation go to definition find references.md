## 1.1. Navigation — go to definition, find references

### 1) **Go-to-definition across layers** (sources, declarations, `node_modules`)

**Definition** — go-to-definition jumps a symbol to its *declaration*: local sources (same-file bindings), project sources (cross-file imports), `.d.ts` declarations (library APIs — signatures without bodies), or `node_modules` JS (untyped fallbacks — implementation without types). *Where* the jump lands diagnoses the layer: sources mean owned code, declarations mean consumed contracts, JS means untyped dependencies.

**What problem it solves / history** — file-scan comprehension (reading directories top-down hoping to find definitions — O(files) per question, stale mental maps) versus jump-driven comprehension (one keystroke per question — O(1) with always-current answers). [01/2.3](<../../../01 Fundamentals and Mental Model/sections/2. How TypeScript doesnt execute/2.3. The language server editor superpowers that justify TypeScript.md>) motivates the server; this promise operationalizes it: navigate before reading, always.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), jump before scanning (definition first, context after — every comprehension task); read landing layers diagnostically (sources → owned logic; `.d.ts` → consumed contracts; JS → untyped gaps to shim per 12/2.3); enable `declarationMap` in libraries (jumps land in sources, not stubs — see 12/3.1 + 13/3.2).

**Runnable example** — jump targets reveal layers (good vs bad, `tsc --strict`):

```typescript
// good — named exports jump precisely (one declaration per symbol — navigation O(1), always current)
export interface Bookmark { url: string }
export function open(b: Bookmark): string { return `open:${b.url}`; }
const bm: Bookmark = { url: "x.io" };
console.log(open(bm)); // open:x.io — go-to-definition on open lands HERE (owned source — logic readable)
// bad — default-anonymous exports (jump lands on `default` keyword — which export? grep to discover)
// fix — named exports (one name per symbol — jumps precise, references greppable, renames safe per 12/1.1)
```

```typescript
// good — declaration jumps reveal consumed contracts (library APIs as signatures — fast to read, versioned by package)
// (node_modules case: go-to-definition on library symbols lands in .d.ts (signatures without bodies — contracts, not logic))
// fix — declarationMap in owned libraries (jumps land in sources — depth on demand, stubs never terminal)
export interface LocalApi { v: number }
export function useLocal(a: LocalApi): string { return `v${a.v}`; } // local-API equivalent (jump lands HERE — owned source)
const la: LocalApi = { v: 1 };
console.log(useLocal(la)); // v1 — owned-source jumps (logic readable — .d.ts landings for foreign packages only)
export const nav = true;
console.log(nav ? "jump-first" : "no"); // jump-first — navigation before scanning (comprehension per jump, not per scan)
interface Bookmark { url: string } // re-declared? no — same file (single declaration — jumps stay local here)
console.log("local-jump"); // local-jump — same-file symbols resolve without leaving the editor
```

```typescript
// good — type-definition jumps (go to TYPE definition vs value definition — universes navigated separately)
export type StatusT = "a" | "b";
export const STATUS_V = "a";
const st: StatusT = STATUS_V as StatusT; // value-to-type flow (universes crossed explicitly — see 02/2.1)
console.log(st.toUpperCase()); // A — go-to-type-definition lands on StatusT (type universe); go-to-definition on STATUS_V (value universe)
// bad — navigating values to understand types (universes conflated — jump lands on data where the contract lives elsewhere)
// fix — universe-matched navigation (types via go-to-type, values via go-to-def — 02's ontology operationalized as keystrokes)
```

**Common confusion** — "jump targets don't matter" — landing layers diagnose (sources → owned logic to read; `.d.ts` → contracts to respect; JS → gaps to shim) — each landing answers "whose code is this?" before reading begins. "peeking equals jumping" — peek shows *context* (inline preview — orientation preserved); jump *relocates* (full file context — depth-first comprehension); go-back returns (navigation stack — disorientation impossible with the return keystroke). "large files defeat navigation" — large files *need* navigation most (symbols scattered across thousands of lines — jumps beat scrolling by orders).

**Performance note** — navigation queries cost indexed lookups (tsserver symbol tables — milliseconds); file scans cost human minutes per question (unbounded, compounding per unfamiliar file). Navigation-first comprehension is the highest-ROI editor habit by time saved.

**Mentor note** — watch a newcomer scan for a definition (minutes, stale map) vs jump (seconds, current answer) — pair the observation once; the habit follows. Exercise: answer five "where is X defined/used?" questions by jumps only (no file-tree scanning — navigation vocabulary under test). Review gate: "I couldn't find the definition" reports fail process review (jump first, always).

### 2) **Find-all-references audits** (rename impact, dead code, API surfaces)

**Definition** — find-all-references lists *every* use of a symbol (reads, writes, type positions, re-exports — across the program): rename-impact audits (all sites a rename touches), dead-code detection (zero-reference exports are deletable candidates), API-surface enumeration (public references vs internal — consumers counted per export).

**What problem it solves / history** — grep-based impact analysis (`symbol` text search — comments, strings, unrelated identifiers polluting results; namespaced/destructured uses missed) under-counted renames (missed sites breaking silently) and over-counted dead code (text matches blocking deletions). Semantic references (checker-resolved, per *binding* not per *text*) answer exactly: every true use, nothing else.

**Modern guidance** — as of TypeScript 5.9 era, audit references before renames (count + skim every site — mechanical impact analysis); before deletions (zero references = candidate — plus `export` visibility check for public APIs); before API changes (consumer count per export — blast radius enumerated, migration sized). Prefer rename-symbol (next leaf) for the edit itself; references for the *audit*.

**Runnable example** — references as codebase queries (good vs bad, `tsc --strict`):

```typescript
// good — single export, countable references (audit before rename/delete/change)
export function compute(n: number): number { return n * 2; }
const a = compute(21);
console.log(a.toFixed(0)); // 42 — find-all-references on compute: 2 hits (declaration + this call — complete, semantic)
// bad — text-grep audits ("compute" matching comments/strings/unrelated locals — over-counted; namespaced uses missed — under-counted)
// fix — semantic references (per-binding resolution — every true use, nothing else — audits trustworthy)
```

```typescript
// good — dead-export detection (zero references = deletion candidate — verified, not hoped)
export function live(): string { return "live"; }
export function orphan(): string { return "gone?"; } // zero references (candidate — plus public-API check before deleting)
console.log(live()); // live — references: live×1, orphan×0 (orphan deletable pending API-surface review)
// bad — deleting by grep-absence (text search missing dynamic/namespace uses — deletions breaking hidden consumers)
// fix — references + export-visibility check (semantic zero + surface review — deletion proven safe, not hoped)
```

```typescript
// good — API-surface enumeration (public references counted per export — blast radius enumerated pre-change)
export interface PublicApi { v: number }
export function useApi(p: PublicApi): string { return `v${p.v}`; }
const p: PublicApi = { v: 1 };
console.log(useApi(p)); // v1 — references on PublicApi: declaration + useApi param + this annotation (3 hits — surface enumerated)
// bad — changing exported shapes without reference audits (consumers breaking silently per uncounted use — migration sized by hope)
// fix — references per changed export (count + skim — blast radius enumerated, migration sized before editing)
```

**Common confusion** — "references equal grep" — references resolve *bindings* (renames tracked, shadowing distinguished, re-exports followed); grep matches *text* (comments/strings pollute, aliased uses hide). "zero references means dead" — means *unreferenced in-program* (public APIs need surface review — external consumers invisible to the program); combine zero-references with export-visibility before deleting. "references replace tests" — references enumerate *impact* (what changes); tests verify *behavior* (what breaks) — audit then test, in that order.

**Performance note** — reference queries cost indexed symbol lookups (milliseconds — tsserver-maintained tables); manual audits cost minutes per symbol (human grep + judgment per hit). References-first auditing is the highest-ROI pre-change habit after navigation-first comprehension.

**Mentor note** — audit one rename live (references listed, sites skimmed, edit applied, tests green — impact analysis in under two minutes). Exercise: find three zero-reference exports and verify deletability (references + surface review each — deletions proven safe). Review gate: renames/deletions/API-changes without reference audits fail review (blast radius enumerated first).

### 3) **Workspace symbols and peek flows** (fuzzy search, context-preserving previews)

**Definition** — workspace-symbol search (`Ctrl+T`/`Cmd+T` — fuzzy matching across the program: `fbusr` finds `fetchUserById`) locates *declarations* by approximate name; peek-definition shows them *inline* (preview editor — context preserved, no tab switch); peek-references lists uses inline (audit without leaving the call site). Search + peek compose: locate approximately, inspect without disorienting, jump only for depth.

**What problem it solves / history** — file-tree navigation (directory spelunking for guessed filenames — O(directories) per question, wrong guesses compounding) and tab-switch jumps (context lost per navigation — back-and-forth disorientation) taxed unfamiliar-codebase work heaviest (onboarding, incident response, cross-team reviews). Symbol search + peek collapse both: name-approximate location plus context-preserving inspection, disorientation-free by construction.

**Modern guidance** — as of TypeScript 5.9 era, search symbols by approximation (partial/substring/fuzzy — names remembered vaguely locate exactly); peek before jumping (preview answers 80% of questions — jump only for depth); keep peek flows short (preview → answer → close; lingering previews accumulate like tabs). Learn the three keystrokes (search/jump-back/peek-close) before any other editor customization.

**Runnable example** — search + peek vocabulary (good vs bad, `tsc --strict`):

```typescript
// good — greppable names (symbol search finds what naming makes findable — conventions is tooling)
export function fetchUserById(id: string): string { return `user:${id}`; } // searchable (fetch+User+ById tokens — fuzzy finds per token)
export function fetchOrderById(id: string): string { return `order:${id}`; }
console.log(fetchUserById("u").toUpperCase()); // USER:U — `fbusr` fuzzy-matches fetchUserById (naming serving search)
// bad — abbreviated cryptic names (fubid indistinguishable from fobid — search fails where naming failed first)
// fix — token-rich names (fetch+User+ById — searchability designed, not hoped — conventions serving tooling)
```

```typescript
// good — peek-able call sites (signatures self-describing — preview answers without jumping)
export function transfer(from: string, to: string, amount: number): string {
  return `${from}>${to}:${amount}`; // labeled params (peek shows from/to/amount — context preserved while reading)
}
console.log(transfer("a", "b", 1)); // a>b:1 — peek-definition answers (signature + docs inline — jump only for depth)
// bad — (a: string, b: string, c: number) positional puzzles (peek shows slots, not meaning — preview wasted on deciphering)
// fix — labeled params + JSDoc (peek content designed — previews answer, jumps deepen)
```

```typescript
// good — references peeked inline (audit without leaving the call site — context preserved through review)
export function shared(n: number): number { return n; }
const r1 = shared(1);
const r2 = shared(2);
console.log((r1 + r2).toFixed(0)); // 3 — peek-references on shared lists both uses inline (audit without tab-switching)
// bad — jump-per-reference audits (tab per use — context lost per navigation, orientation rebuilt per return)
// fix — peek flows (preview → answer → close — disorientation-free auditing by construction)
```

**Common confusion** — "search replaces file structure" — search *locates* (names known approximately); structure *organizes* (discoverability for unknown unknowns — both needed: search what you can name, browse what you can't). "peek replaces jumps" — peek *previews* (80% of questions); jumps *relocate* (depth work — full file context); go-back *returns* (navigation stack — the trio composed, never substituted). "fuzzy search excuses bad names" — fuzzy search *rewards* token-rich names (more tokens → more match paths) and *punishes* cryptic ones (fewer matchable substrings) — naming discipline amplified, not replaced.

**Performance note** — symbol indexes update incrementally (per-edit reindex bounded — large programs stay interactive); peek editors render on demand (no tab allocation per preview); fuzzy matching costs keystrokes-only (milliseconds per query). Navigation tooling is performance-positive by construction (seconds replacing minutes per question).

**Mentor note** — time one "find the definition" by file-tree vs symbol search (minutes vs seconds — tooling dividend measured once, believed forever). Exercise: answer five codebase questions by search+peek only (no file-tree, no grep — navigation vocabulary under test). Review gate: "I couldn't find X" reports fail process review (search → peek → jump, in that order).
