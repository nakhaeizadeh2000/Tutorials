## 2.2. `emitDecoratorMetadata` and design types

### 1) **Run a real legacy metadata producer and reader**

`emitDecoratorMetadata` asks TypeScript to emit selected runtime representations of annotated types at eligible decorated declarations. A runtime library can record those representations so a consumer can read them later. This is a lossy communication channel, not full type reflection or automatic validation. A consumer still needs a policy for interpreting a constructor such as `Object`.

Use **TypeScript 7.0.2**, **Node.js 20.20.2** and **reflect-metadata 0.2.2** for this complete example. It deliberately uses legacy decorators, with both `experimentalDecorators` and `emitDecoratorMetadata` enabled. The [compiler option reference](https://www.typescriptlang.org/tsconfig/emitDecoratorMetadata.html) shows the generated `__metadata` calls. The [library's own documentation](https://github.com/microsoft/reflect-metadata) supplies its bootstrap and reading APIs; those APIs are separate from the [standard metadata channel](<./2.3. Symbol.metadata and the metadata proposal.md>).

Create an empty directory, run `npm init -y` followed by `npm install --save-exact reflect-metadata@0.2.2`, and save the following files. The comments label file destinations; omit the label comment when saving JSON.

```json
// file: tsconfig.json
{
  "compilerOptions": {
    "strict": true,
    "target": "es2022",
    "module": "nodenext",
    "moduleResolution": "nodenext",
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true,
    "noEmitOnError": true,
    "outDir": "dist"
  },
  "include": ["model.mts", "early.mts", "missing.mts", "late.mts"]
}
```

The model imports only the package's type declarations. That import is erased; it deliberately does not install the runtime APIs. No-op legacy decorators mark the declarations where the compiler should emit metadata. Their bodies do not manually write the design keys.

```typescript
// file: model.mts
import type {} from "reflect-metadata";
function marked(_value: Function): void {}
function property(_target: object, _key: string | symbol): void {}
function method(_target: object, _key: string | symbol, _descriptor: PropertyDescriptor): void {}
export class Repo { read(): string { return "repo"; } }
class Other {}
export interface Port { value: string }
@marked
export class Service {
  constructor(public repo: Repo, public port: Port) {}
  run(): string { return this.repo.read() + ":" + this.port.value; }
}
export class Types<T extends Repo> {
  @property repo!: Repo;
  @property iface!: Port;
  @property union!: Repo | Other;
  @property nullable!: Repo | null;
  @property strings!: "a" | "b";
  @property mixed!: string | number;
  @property tuple!: [string, number];
  @property generic!: T;
  @method run(_value: string): number { return 1; }
  plain(_value: string): number { return 1; }
}
function nameOf(value: unknown): string {
  if (value === undefined) return "undefined";
  if (typeof value === "function") return value.name;
  throw new Error("unexpected metadata value");
}
function namesOf(value: unknown): string {
  if (!Array.isArray(value)) return "undefined";
  return value.map(nameOf).join(",");
}
export function report(): void {
  console.log("constructor", namesOf(Reflect.getOwnMetadata("design:paramtypes", Service)));
  for (const key of ["repo", "iface", "union", "nullable", "strings", "mixed", "tuple", "generic"]) {
    console.log(key, nameOf(Reflect.getOwnMetadata("design:type", Types.prototype, key)));
  }
  console.log("method",
    nameOf(Reflect.getOwnMetadata("design:type", Types.prototype, "run")),
    namesOf(Reflect.getOwnMetadata("design:paramtypes", Types.prototype, "run")),
    nameOf(Reflect.getOwnMetadata("design:returntype", Types.prototype, "run")));
  console.log("plain", nameOf(Reflect.getOwnMetadata("design:type", Types.prototype, "plain")));
}
export function makeService(port: Port): Service { return new Service(new Repo(), port); }
```

The definite-assignment assertions on the sample properties permit declarations for inspection; they do not initialize the properties. No `Types` instance is needed to read metadata attached to its prototype. `report` treats library reads as values to inspect, rather than claiming an unchecked generic return validates them.

```typescript
// file: early.mts
import "reflect-metadata";
import { report, makeService } from "./model.mjs";
report();
console.log(makeService({ value: "configured" }).run());
// constructor Repo,Object
// repo Repo
// iface Object
// union Object
// nullable Object
// strings String
// mixed Object
// tuple Array
// generic Object
// method Function String Number
// plain undefined
// repo:configured
// makeService({ value: 3 }); // TS2322: the explicit Port contract requires a string.
```

Run `tsc -p tsconfig.json`, then `node dist/early.mjs`. The bootstrap executes before the model evaluates, so the emitted metadata calls can record values. Constructor metadata lives on `Service`. Instance-member metadata lives on `Types.prototype` under the member key. `getOwnMetadata` avoids silently substituting inherited entries; `getMetadata` instead searches the prototype chain, as the library reference explains.

The decorated method records three different things: its kind is represented by `Function`, its parameter list contains `String`, and its annotated return is represented by `Number`. The undecorated `plain` method has no own design metadata. These observations require both the compiler producer and the runtime store.

### 2) **Interpret the approximation before assembling dependencies**

The outputs describe this program on the stated compiler. `Repo` retains a constructor value. The interface, heterogeneous unions, nullable class union and constrained generic parameter in this fixture become `Object`. A string-literal union becomes `String`, so “every union becomes Object” is also incorrect. A tuple becomes `Array`, losing its positions and element types. `Object` cannot tell a container which implementation satisfies `Port`, and `Array` cannot validate the tuple's contents.

The compiler emits constructor references or broad built-ins; it does not serialize a complete schema. Metadata is not a record of the actual argument passed on a later invocation. Passing a structural test double does not rewrite the declaration's metadata. A container must supply a binding policy, and ambiguous values need an explicit token, factory or other consumer-supported configuration.

`makeService` demonstrates a typed construction recipe: it explicitly creates `Repo` and receives the `Port` implementation as an argument. It does not pretend that reading `[Repo, Object]` is enough to infer that binding. The consumer gets `repo:configured`, and changing the supplied implementation is ordinary constructor substitution. A typed token and container design, including caching and replacement, belongs to [3.3](<../3. Patterns in Practice/3.3. Dependency injection with decorators.md>); a string key plus `get<T>()` assertion would not prove type-safe resolution.

For application-oriented backend work, follow the planned NestJS route with its Fastify adapter and the framework's supported decorator configuration. This project runs no NestJS, ORM, HTTP or framework-container integration. Framework-specific injection decorators require their actual consumer; they are not language-level replacements for these three emitted design keys.

### 3) **Distinguish absent recording, late setup and forward references**

The generated helper checks whether `Reflect.metadata` exists before calling it. Missing runtime setup therefore does not inherently crash the decorated class definition. It can leave no records. An unguarded call to an absent reader API is a separate failure.

```typescript
// file: missing.mts
import { Service } from "./model.mjs";
console.log(Service.name, typeof Reflect.metadata);
try { Reflect.getOwnMetadata("design:paramtypes", Service); }
catch (error) { console.log(error instanceof TypeError); }
// Service undefined
// true
```

Run `node dist/missing.mjs` as a fresh process. The class definition completes with no recording API. The subsequent reader call throws and is caught. These statements concern TypeScript's guarded helper, not every decorator implementation: a custom decorator that directly calls a missing API can fail during definition.

Installing the library later supplies its APIs, but does not replay already evaluated decorator calls:

```typescript
// file: late.mts
import { Service, Types } from "./model.mjs";
await import("reflect-metadata");
console.log(typeof Reflect.metadata,
  Reflect.getOwnMetadata("design:paramtypes", Service) === undefined,
  Reflect.getOwnMetadata("design:type", Types.prototype, "repo") === undefined);
// function true true
```

Run `node dist/late.mjs` separately. The model evaluates before the dynamic bootstrap, and the emitted metadata was skipped. Importing the same cached module again would not rerun its definition. Establish setup before the actual decorated graph evaluates, including each independent worker or test entry that needs it. This lesson does not impose a universal rule forbidding libraries from bootstrapping their documented dependency.

Metadata also introduces runtime value reads where a type annotation alone might erase. Save this separate failure fixture outside the configured include set:

```typescript
// file: forward.mts
import "reflect-metadata";
function marked(_value: Function): void {}
@marked
class Before { constructor(public later: Later) {} }
class Later {}
console.log(Before.name, Later.name);
```

Compile it with `tsc --ignoreConfig --strict --experimentalDecorators --emitDecoratorMetadata --target es2022 --module nodenext --outDir forward-dist forward.mts`, then run `node forward-dist/forward.mjs`. Compilation succeeds on TypeScript 7.0.2; execution fails with `ReferenceError` because emitted `design:paramtypes` reads `Later` before its class initialization. Move `Later` before `Before`, rebuild and rerun: it prints `Before Later`. The [library's forward-reference warning](https://github.com/microsoft/reflect-metadata#notes) is a runtime dependency concern, not proof that the full program was safely reflected by passing the checker. Real cycles can require a consumer-specific deferred token or a different assembly boundary.

A stale emitted artifact can also contain old metadata, just as it can contain old executable behavior or old explicit-token code. Rebuild the actual entry and inspect the artifact in use. Tokens are not immune to serving stale JavaScript, and periodic forced builds do not replace diagnosing a missing input or wrong entry path. [Project references](<../../../13 Configuration and Compiler Options/sections/3. Modules Emit and Projects/3.2. declaration composite project references.md>) owns build-graph verification.

### 4) **Common confusion**

Enabling the flag does not install a runtime library. The emitted `__metadata` helper can skip recording when its API is absent; a later bootstrap provides readers without recovering the missed records. Disabling `emitDecoratorMetadata` likewise removes the compiler producer even when the library is installed. Neither case is equivalent to proving that a consumer's expected metadata exists.

`Symbol.metadata` and `reflect-metadata` are separate channels with different setup and APIs. The standard channel also needs runtime support or initialization of its symbol in the tested runtimes; its name does not prove native availability. Finally, `Object` in metadata is an approximation, not an instruction to inject an arbitrary object or a guarantee that all union forms serialize identically.

### 5) **Performance note**

The emitter adds definition-time helper calls and runtime constructor references; the library retains metadata for readers. Application cost depends on the decorated surface, store, and how often a consumer queries or resolves it. This project measures no startup time, memory amount or container lifetime. In particular, metadata does not determine whether resolution is singleton, transient or request-scoped. Inspect the emitted dependency edges and measure the actual consumer before claiming a negligible startup-only cost.

### 6) **Mentor note**

Ask the learner to locate the constructor and member stores in the emitted JavaScript, then predict the outputs of the early, missing and late entries. A correct answer separates API availability from record existence. Next, ask which provider `[Repo, Object]` identifies for `Port`: the answer requires an explicit binding policy, not a cast. Finally, move `Later` and explain why a type annotation has created a definition-time value dependency.
