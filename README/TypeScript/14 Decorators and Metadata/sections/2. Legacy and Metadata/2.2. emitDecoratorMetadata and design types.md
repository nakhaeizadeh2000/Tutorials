## 2.2. `emitDecoratorMetadata` and design types

### 1) **What the flag emits** (design:type/paramtypes/returntype facts as metadata)

**Definition** — `emitDecoratorMetadata: true` (with `experimentalDecorators`) makes the compiler emit `Reflect.metadata("design:type", …)` / `("design:paramtypes", …)` / `("design:returntype", …)` for decorated declarations: the *declared* parameter types, return type, and property type recorded as runtime values alongside the class. Requires the `reflect-metadata` polyfill import (the `Reflect.metadata` API surface) — emit without the polyfill crashes at definition time.

**What problem it solves / history** — DI containers need constructor parameter *types* at runtime (`new UserService(repo)` — which class is `repo`?) — but types erase (see 01/2.1), leaving constructors reflection-blind. Design-time metadata bridges erasure selectively: the compiler (which knows the types) records them where the container (running later) can read them — explicit, opt-in reflection for decorated classes only.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), enable the flag only where a metadata-consuming framework requires it (NestJS/TypeORM-era stacks — recorded per tsconfig with the framework reason); import `reflect-metadata` once at the application entry (before any decorated class evaluates); treat emitted metadata as *framework input* (containers read it — application code reads explicit tokens instead, see 3.3 promise 2).

**Runnable example** — metadata emitted, read explicitly (standard-runnable sketches; legacy emit described):

```typescript
// good — explicit token map (the portable pattern: no metadata emit needed, works standard + legacy)
const TOKENS = new Map<string, new () => object>();
function injectable(name: string) {
  return function <T extends new (...args: any[]) => object>(target: T): T {
    TOKENS.set(name, target as unknown as new () => object); // explicit registration (portable — no emit flag)
    return target;
  };
}
@injectable("svc")
class Svc {
  run(): string { return "ran"; }
}
console.log(TOKENS.has("svc"), new (TOKENS.get("svc") as new () => { run(): string })().run()); // true ran — explicit tokens (no metadata magic)
// legacy emit form (requires --experimentalDecorators + emitDecoratorMetadata + reflect-metadata import):
// @Injectable() class Svc2 { constructor(private repo: Repo) {} } // design:paramtypes [Repo] emitted (container resolves without tokens)
```

```typescript
// good — design:type sketch (property type recorded where the flag is on; read by validators/ORMs)
// legacy emit (commented: needs experimentalDecorators + emitDecoratorMetadata + reflect-metadata):
// class Entity {
//   @Column()
//   name!: string; // design:type String emitted (ORM maps column type from metadata, not declarations)
// }
// standard-portable equivalent (explicit, flag-free):
function column(type: string) {
  return function (value: undefined, context: ClassFieldDecoratorContext<object, unknown>): void {
    void value; void context; void type; // type passed EXPLICITLY (portable — no emit flag, no staleness class below)
  };
}
class Entity2 {
  @column("text") name = "n";
}
console.log(new Entity2().name.toUpperCase()); // N — explicit column types (portable across standard/legacy)
// bad — depending on emitted metadata without the flag (undefined metadata reads — silent, definition-time, untestable in type tests)
```

```typescript
// good — returntype metadata sketch (frameworks typing RPC surfaces from implementations)
// legacy emit (commented: design:returntype recorded per decorated method under the flag):
// class Api {
//   @Get()
//   list(): string[] { return []; } // design:returntype Array emitted (docs generator reads response shape)
// }
// standard-portable equivalent (explicit return schemas — see 3.1's validation pattern for the full treatment):
function returns(type: string) {
  return function <This, Args extends unknown[], Ret>(
    fn: (this: This, ...args: Args) => Ret,
  ): (this: This, ...args: Args) => Ret {
    void type; // schema passed explicitly (portable — documented at the declaration, readable without emit)
    return fn; // observe-only (registration shape — behavior untouched)
  };
}
class Api2 {
  @returns("string[]")
  list(): string[] { return []; }
}
console.log(new Api2().list().length); // 0 — explicit schemas (portable — no emit flag, no reflect polyfill)
// bad — metadata-read application logic (business rules branching on Reflect.getMetadata — untestable without emit setup, invisible in reviews)
```

**Common confusion** — "metadata reflects runtime values" — reflects *declared types* (design-time facts — `design:paramtypes` of `(repo: Repo)` is `[Repo]` even when called with a subclass instance). "standard decorators emit metadata" — standard has *no* `emitDecoratorMetadata` equivalent (the flag pairs with legacy emit only) — standard metadata travels via `Symbol.metadata` (see 2.3) and explicit tokens. "missing metadata is a bug" — absent without the flag + polyfill *by design* (opt-in reflection — application code must never assume metadata presence; frameworks guard or require explicitly).

**Performance note** — metadata emit adds per-decorated-declaration calls (`Reflect.metadata(...)` at class-definition time — startup cost per decorated class, trivial); `reflect-metadata` polyfill adds WeakMap storage per metadata entry (bounded by decorated surface — small). Standard-portable explicit tokens cost one map insert per registration (identical profile, zero polyfill).

**Mentor note** — `console.log(Reflect.getMetadata("design:paramtypes", Svc))` with and without the flag (`[Function]` vs `undefined`) — opt-in reflection demonstrated in one call. Exercise: convert one metadata-read to an explicit token and delete the flag dependency for that path — portability gained per conversion. Rule: application logic never reads `Reflect.getMetadata` (frameworks only); business rules stay in explicit code.

### 2) **How DI containers consume it** (constructor types resolved at runtime)

**Definition** — NestJS-style containers read `design:paramtypes` at class registration (`@Injectable() class Svc { constructor(repo: Repo) }` → paramtypes `[Repo]` → container instantiates `Repo` (resolving *its* params recursively) and calls `new Svc(repoInstance)`). The decorator marks participation; the metadata supplies the dependency graph; the container owns construction order, singleton scope, and test-double substitution.

**What problem it solves / history** — manual wiring (`new Svc(new Repo(new Db(conn)))` — construction order hand-threaded, test doubles requiring call-site surgery) scaled with graph depth (each new dependency re-threaded through every construction site). Metadata-driven DI inverts control: classes declare needs (constructor params), containers satisfy them (recursive resolution) — adding a dependency edits one constructor, tests substitute one binding.

**Modern guidance** — as of TypeScript 5.9 era, use framework DI where the framework owns it (NestJS modules/providers — idiomatic, tested, documented); prefer *explicit tokens* (`@Inject(TOKEN)`) over bare `design:paramtypes` reliance (unions/interfaces/primitives record `Object`/useless metadata — tokens stay precise where emit degrades — see promise 3); test via container overrides (provider substitution, not constructor surgery).

**Runnable example** — container resolves, tokens stay precise (standard-runnable sketches; legacy emit described):

```typescript
// good — hand-rolled token container (the pattern frameworks automate; explicit, portable, testable)
type Ctor<T = object> = new (...args: never[]) => T;
class Container {
  private bound = new Map<string, Ctor>();
  bind<T>(token: string, ctor: new (...args: never[]) => T): void {
    this.bound.set(token, ctor as unknown as Ctor); // token → constructor (explicit map, no metadata magic)
  }
  get<T>(token: string): T {
    const C = this.bound.get(token);
    if (!C) throw new Error(`unbound:${token}`);
    return new (C as new () => T)(); // zero-arg construction (tokens for values; factories for parameterized — see 3.3)
  }
}
const c = new Container();
c.bind("svc", class Svc3 { run(): string { return "ran"; } });
console.log(c.get<{ run(): string }>("svc").run()); // ran — explicit tokens (portable across standard/legacy, testable via rebind)
// legacy metadata form (commented: design:paramtypes auto-wiring under --experimentalDecorators + emitDecoratorMetadata):
// @Injectable() class Svc { constructor(private repo: Repo) {} } // container reads [Repo] (no tokens written — magic with prerequisites)
```

```typescript
// good — test doubles via container rebinding (substitution without surgery)
class Container { // re-declared: fences compile standalone (minimal token map)
  private bound = new Map<string, new (...args: never[]) => object>();
  bind(token: string, ctor: new (...args: never[]) => object): void { this.bound.set(token, ctor); }
  get<T>(token: string): T {
    const C = this.bound.get(token);
    if (!C) throw new Error(`unbound:${token}`);
    return new (C as new () => T)();
  }
}
class Real {
  data(): string { return "real"; }
}
class Fake {
  data(): string { return "fake"; }
}
const t = new Container();
t.bind("repo", Real);
console.log(t.get<{ data(): string }>("repo").data()); // real — production binding
t.bind("repo", Fake); // rebind (test setup: one line, no constructor surgery anywhere)
console.log(t.get<{ data(): string }>("repo").data()); // fake — test double via container (substitution point centralized)
// bad — new Svc(new Repo(new Db())) per test (construction surgery per suite — graph depth re-threaded per test file)
// fix — container overrides (bind test doubles once per suite — construction logic lives in one place: the container)
```

```typescript
// good — explicit constructor tokens where metadata degrades (unions/interfaces need tokens — see promise 3)
class Container { // re-declared: fences compile standalone (minimal token map)
  private bound = new Map<string, new (...args: never[]) => object>();
  bind(token: string, ctor: new (...args: never[]) => object): void { this.bound.set(token, ctor); }
}
const TOKEN = { repo: "repo" } as const; // token constants (typo-proof keys, grep-able bindings)
class Holder {
  constructor(public t: string) {}
}
const h = new Container();
h.bind(TOKEN.repo, class R { } as unknown as new (...args: never[]) => object);
console.log(typeof TOKEN.repo); // string — token-based wiring (precise where design:paramtypes records Object)
// bad — relying on emitted metadata for union/interface params (records Object — container resolves garbage; see promise 3's incident)
// fix — @Inject(TOKEN) explicit tokens (precision where emit degrades — portable across proposals)
```

**Common confusion** — "DI removes constructors" — DI *calls* constructors (with resolved arguments — classes still declare needs via params; containers satisfy them). "containers replace imports" — containers resolve *runtime instances*; imports resolve *code* (both needed — import the class (code), inject the instance (runtime)). "test doubles need DI" — doubles need *substitution points* (constructor params work without containers; containers centralize substitution at scale — small graphs wire manually just fine).

**Performance note** — container resolution runs once per singleton lifetime (startup cost — graph traversal trivial vs application boot); per-request scoped resolution costs per scope (bounded by graph size — factory-cached after first resolution). DI overhead is startup-shaped, never hot-path (resolve once, inject everywhere).

**Mentor note** — rebind one token live (Real → Fake) and rerun the consumer (behavior flips without touching consumer code — inversion of control demonstrated in two lines). Exercise: convert one manual-wiring chain (`new A(new B(new C()))`) to container bindings and count the construction sites deleted — wiring centralized per conversion. Review gate: `new Svc(new Repo(...))` chains past depth 2 fail review (container or factory).

### 3) **Limits and staleness** (erased unions become `Object`; metadata needs the polyfill)

**Definition** — two hard limits: *degradation* (unions → `Object`, interfaces → `Object`, generics → constraint-or-`Object`, literals → base constructors — erased specifics collapse to `Object`/`Array`/`String`; see 5.1 promise 2's incident) and *staleness* (metadata recorded at *decoration* (class-definition time) — later type changes re-emit only on rebuild; stale `.js` serving fresh `.ts` intents in incremental/watch misconfigurations). Plus the polyfill prerequisite (no `reflect-metadata` import → `Reflect.metadata` undefined → definition-time crash).

**What problem it solves / history** — `design:paramtypes`-driven containers injected *wrong* services for union/interface params (`Object` resolved as garbage dependency — boot-time misbehavior with green types) and crashed on missing polyfills (`Reflect.metadata is not a function` at first decorated class — import-order incidents). Naming both limits routes union/interface params to explicit tokens (precision where emit degrades) and polyfill imports to entry-point checklists (prerequisite verified, not assumed).

**Modern guidance** — as of TypeScript 5.9 era, tokenize every non-class param (unions, interfaces, primitives, literals — `@Inject(TOKEN)` explicit; bare metadata only for concrete class params); import `reflect-metadata` first in the application entry (before any decorated module evaluates — import-order lint or entry-template enforcement); treat metadata as *hint* (containers validate resolved instances — `instanceof` checks at resolution, never blind trust).

**Runnable example** — degrade honestly, tokenize precisely (standard-runnable sketches; legacy emit described):

```typescript
// good — tokens where metadata degrades (unions/interfaces/primitives NEVER bare-injected)
// legacy emit reality (commented): constructor (repo: Repo | Mock) records [Object] (erased union — garbage if trusted)
// class Svc4 { constructor(public repo: unknown) {} } // unknown param (honest: container CANNOT infer — token required)
const TOK = "repo";
class Registry {
  private m = new Map<string, unknown>();
  set(k: string, v: unknown): void { this.m.set(k, v); }
  get<T>(k: string): T { return this.m.get(k) as T; } // token-keyed (precision explicit — no emit to degrade)
}
const r = new Registry();
r.set(TOK, { q: 1 });
console.log((r.get<{ q: number }>(TOK).q).toFixed(0)); // 1 — tokens precise where metadata degrades (the rule in one map)
// bad — bare-injecting union params under metadata emit (Object resolved as garbage dependency at boot — 5.1 promise 2's incident)
// fix — @Inject(TOK) explicit tokens (precision where emit degrades — portable across proposals, testable via rebind)
```

```typescript
// good — polyfill prerequisite checked (entry imports reflect-metadata before decorated modules evaluate)
// (entry shape documented; runnable fence demonstrates the consumer side without the polyfill dependency):
function needsMeta(): string { return "meta-channel"; } // standard code (no polyfill needed — Symbol.metadata is runtime-native)
console.log(needsMeta()); // meta-channel — standard metadata channel needs NO polyfill (legacy reflect-metadata does)
// bad — legacy emit without reflect-metadata import (Reflect.metadata undefined → definition-time crash at first decorated class)
// fix — entry-template enforcement (polyfill import line 1 of main.ts — prerequisite verified, not assumed)
```

```typescript
// good — staleness guarded by rebuild discipline (metadata recorded at decoration — rebuild on type change)
// (watch-mode note: emitDecoratorMetadata re-emits per rebuild; stale .js + fresh .ts intents diverge ONLY when builds skip)
// Standard-portable staleness-proofing (explicit tokens never stale — source of truth is code, not emit):
const T2 = "svc";
const table = new Map<string, string>([[T2, "ready"]]);
console.log(table.get(T2)?.toUpperCase()); // READY — explicit tables (no emit to go stale — source IS the truth)
// bad — trusting week-old emit after type-only changes (incremental/watch misconfigurations serving stale metadata — rebuild discipline, not flag blame)
// fix — clean builds on type-change deploys (CI --force periodically) + explicit tokens (staleness-proof by construction)
```

**Common confusion** — "metadata staleness is a flag bug" — staleness is *build hygiene* (incremental emit caching across type changes — `tsc --build --force` periodically; clean CI builds on release branches). "unions will improve" — erasure is *structural* (union members don't exist at runtime — no future emit can record what isn't there; tokens are the permanent answer, not a workaround). "polyfill once covers all runtimes" — polyfill per *entry point* (each application entry — main, worker, test bootstrap — imports before decorated modules; shared-library code must NOT import it — host owns prerequisites).

**Performance note** — metadata storage per decorated member (WeakMap entries — bounded by decorated surface, small); token maps one entry per binding (identical profile, zero polyfill); stale-metadata incidents cost boot-misbehavior debugging (unbounded — rebuild discipline is free insurance).

**Mentor note** — log `design:paramtypes` for a union param live (`[Object]` — degradation demonstrated, not described) — tokens-from-here-on-out in one log line. Exercise: tokenize three bare-injected union/interface params and delete the metadata reliance (precision restored per conversion). Rule: non-class DI params carry `@Inject(TOKEN)` or fail review.
