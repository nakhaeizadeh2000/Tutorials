## 3.1. Editor Integration and Auto-Types

### 1) **Feature** (auto import)

**Definition** — Editor TS server provides: auto-imports, code actions (`fix all`), inlay hints, hover types, go-to-definition via `declarationMap`, and status for errors before `tsc` run. Stable as of 5.6 with `projectService` auto-discovery.

Features to enable:

- **Auto-import** — as soon as you type `User`, suggest import from `@/models/user.js`; manage organize-imports.
- **Inlay hints** — show inferred types for params/returns (`paramHints`, `variableTypes`).
- **Code actions** — "Add missing import", "Fix all", "Convert to `import type`".
- **Auto .d.ts acquire** — for JS libs without `@types`, VS Code auto-acquires via `AT` (Automatic Type Acquisition).

```jsonc
// .vscode/settings.json
{
  "editor.defaultFormatter": "biomejs.biome",
  "editor.formatOnSave": true,
  "editor.codeActionsOnSave": {
    "source.organizeImports.biome": "explicit",
    "source.fixAll.biome": "explicit"
  },
  "typescript.preferences.importModuleSpecifier": "non-relative", // uses paths alias
  "typescript.preferences.autoImportFileExcludePatterns": ["**/dist/**"]
}
```

  return `Hi ${name}`;

`biome` VS Code extension + `typescript` built-in: keep both. `typescript` for types, `biome` for format/lint. Disable `editor.defaultFormatter: prettier` if using Biome.

Integrate `verbaitmModuleSyntax` — auto-import inserts `import type` when appropriate.

### 3) **Mentor** (onboarding DX)

**Mentor checklist:**

- Commit `.vscode/settings.json` + `.vscode/extensions.json` (`recommendations: ["biomejs.biome", "ms-vscode.vscode-typescript-next"]`) so new dev gets auto on clone.
- Commit `biome.json` + `eslint.config.js` — CI fails if editor would format differently.
- Document `Cmd+.` (quick fix) and `F12` (go to definition via `declarationMap`) in onboarding doc.
- Setting `typescript.tsdk: "node_modules/typescript/lib"` ensures editor uses repo's 5.6, not bundled older version.

```jsonc
// .vscode/extensions.json
{
  "recommendations": ["biomejs.biome", "yoavbls.pretty-ts-errors", "ms-vscode.vscode-typescript-next"]
}
// onboarding MD snippet:
// - Open VS Code → Command Palette → TypeScript: Select TypeScript Version → Use Workspace Version
// - Settings → Editor: Format On Save (biome)
// - Hover types to learn narrowing (02 2.3) live
```

**Common confusion** —

- "Editor shows no error but tsc does" — usually different `tsconfig` (editor uses `tsconfig.json` auto, tsc uses explicit `project` param). Align via `projectService`.

**Performance note** —

VS Code `projectService` (TS 5.x) watches many files — on large monorepo, set `typescript.tsserver.maxTsServerMemory`.

VS Code settings + Biome recommended extension guarantee `import type` and sorted imports land correctly before push.
