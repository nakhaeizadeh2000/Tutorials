## 1.2. Consistent Code and Import Sort

### 1) **Rule** (import sort)

**Rule — deterministic ordering prevents churn:**

- Imports sorted: builtins (`node:*`) → external → internal alias (`@/*`) → relative (`./`).
- No unused imports/vars (type-aware).
- No `import type` mixed with value when `verbatimModuleSyntax` expects separation.

```jsonc
// biome.json import handling (Biome sorts via assist)
{
  "assist": { "actions": { "source": { "organizeImports": "on" } } },
  "linter": { "rules": { "correctness": { "noUnusedImports": "error" } } }
}
// eslint equivalent (with `eslint-plugin-import` or `perfectionist`):
// rules: { "perfectionist/sort-imports": ["error", { "partitionByNewLine": true }] }
```

Correct order example:

```typescript
// 1) builtins
import { readFile } from "node:fs/promises";
// 2) externals
import express from "express";
import { z } from "zod";
// 3) internal alias
import { config } from "@/config.js";
import type { User } from "@/models/user.js";
// 4) relative
import { helper } from "./helper.js";
import type { Local } from "./local.js";
```

---

### 2) **Example** (biome check)

```bash
# single command — lint + format + sort
biome check --write ./src

# CI gate (no write)
biome check ./src
# or with eslint typed subset
eslint --max-warnings=0 ./src
biome check ./src
tsc --noEmit --project tsconfig.json
```

```typescript
// before biome check
import { helper} from "./helper.js"
import  express from "express"
import { z  } from "zod"
import { readFile } from "node:fs/promises"
import { config } from "@/config.js"

// after
import { readFile } from "node:fs/promises";
import express from "express";
import { z } from "zod";
import { config } from "@/config.js";
import { helper } from "./helper.js";
```

For `verbatimModuleSyntax`, `import type` must be separate from value imports when type-only — `biome`/`eslint` `--fix` will split.

### 3) **Link** (to Production Toolchain)

Consistent code is team infra, not just style:

- Formatter + lint as pre-commit/husky → see [Production Toolchain track](<../../../ProductionToolchain/README.md>) — CI/CD, caching, pre-commit hooks.
- Editor integration (`editor.defaultFormatter`, `biome` VS Code extension) → [3.1 Editor](<../3.%20Editor%20and%20DX/3.1.%20Editor%20Integration%20and%20Auto-Types.md>).
- Type-aware lint's `no-unchecked` parity with `noUncheckedIndexedAccess` — keep both enabled.

**Common confusion** —

- "`import type` and `import` can mix arbitrarily under isolatedModules" — no, `verbatimModuleSyntax` requires explicit `type` keyword.

**Performance note** —

`biome check` single pass ~0.3s per 1k files vs `eslint --fix` ~3s. For large monorepos, saving is minutes per CI.

**Mentor note** —

Enforce `biome check --write` on pre-commit (`husky`/`lint-staged`). Churn from unsorted imports wastes more review time than any formatting debate.
