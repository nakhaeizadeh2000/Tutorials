## 1.1. ESLint + typescript-eslint vs Biome

### 1) **Comparison** (Biome speed)

**Comparison (5.6 era):**

| Tool | Scope | Speed | Type-aware lint? |
|------|-------|-------|-------------------|
| **`typescript-eslint`** (ESLint) | Lint only (format via Prettier) | slower (needs `parserOptions.project`) | yes — uses `tsc` program |
| **`Biome`** (ex-Rome) | Lint + Format + Import sort + `check` | ~10–100× faster (Rust, single binary) | partial (fast checker, not full `tsc`) |
| `prettier` + `eslint` | Format + Lint (2 tools) | slower | via plugin |

**Recommendation:**

- Greenfield / monorepo large files → **Biome** default (`biome check --write` lints+formats+sorts in one pass). Keeps CI fast.
- Need deepest type-aware rules (e.g., `no-floating-promises`, `await-thenable`, `no-misused-promises`) → keep **`typescript-eslint` + `parserOptions.project: true`** for those rules; run alongside Biome or replace Biome lint subset.

Many 2025+ repos run **both**: Biome for format + fast lint, `typescript-eslint` for typed rules only.

```jsonc
// eslint.config.js (5.6 era — flat config)
import tseslint from "typescript-eslint";
export default tseslint.config(
  { ignores: ["dist"] },
  ...tseslint.configs.recommendedTypeChecked,
  {
    languageOptions: { parserOptions: { projectService: true } },
    rules: { "@typescript-eslint/no-floating-promises": "error" }
  }
);
// biome.json
{
  "$schema": "https://biomejs.dev/schemas/2.0.0/schema.json",
  "linter": { "enabled": true, "rules": { "recommended": true, "correctness": { "noUnusedVariables": "error" } } },
  "formatter": { "enabled": true, "indentStyle": "space", "indentWidth": 2 }
}
```

### 2) **Config** (typed lint)

Type-aware lint requires `tsconfig` project info — slowest part.

```jsonc
// enable type-aware lint: tsconfig for lint (may extend app tsconfig)
{
  "compilerOptions": { "strict": true },
  "include": ["src"],
  "files": [] // or use projectService (TS 5.x) for auto-discovery
}

// eslint.config — projectService (recommended for reference-based monorepos)
{
  "languageOptions": { "parserOptions": { "projectService": true, "allowDefaultProject": ["eslint.config.js"] } }
}

// biome's type-aware subset: still evolving — check biome docs for noUncheckedIndexedAccess parity
```

Run order in CI:

```bash
# fast first, typed second
biome check ./src        # fast lint+format
tsc --noEmit             # full typecheck (always)
eslint --max-warnings=0  # type-aware subset (if used)
```

### 3) **Bad** (no type-aware lint)

**Bad — lint without type info misses promise bugs:**

```typescript
// bad: no-floating-promises off → bug slips
async function load(): Promise<string> { return "hi"; }
load(); // floating promise — unhandled rejection risk; with rule, error forces await/return/void

// bad: eslint without projectService — rule silently disabled
// await-thenable would catch: await 42 (non-thenable); without typed lint, no warning

// bad: formatting drift from mixing prettier+eslint without integration — use biome check or prettier eslint-config
async function badNoAwait(x: Promise<string>) {
  let v = await x; // ok
  await "literal"; // bad — awaited non-promise (typed lint would flag via no-misused-promises style)
  return v;
}
```

### Mentor note

Default policy: `biome check` for DX speed, `typescript-eslint` typed rules for correctness, `tsc --noEmit` as source of truth. Document which rule comes from which tool in CONTRIBUTING.

### Common confusion

- "Biome replaces tsc" — no. Biome's checker is partial; `tsc --noEmit` remains required for full types.

### Performance note

`allowDefaultProject` vs `projectService`: projectService respects project references and incremental, far faster for large monorepos.
