## 1.1. Primitives (string, number, boolean, bigint, symbol)

### 1) **Definition** (JS primitives mapped to TS)

**Definition** — TypeScript's primitive type names are lowercase and correspond 1:1 to JavaScript's runtime primitives (via `typeof`):

- `string` — `typeof x === "string"`
- `number` — `typeof x === "number"` (all JS numbers, including `NaN`, `Infinity`, `-0`)
- `boolean` — `typeof x === "boolean"`
- `bigint` — `typeof x === "bigint"` (requires `target >= es2020` / `lib: ["es2020"]`)
- `symbol` — `typeof x === "symbol"`
- `null` / `undefined` — each is both a value and (under `strictNullChecks`) its own type.

Special primitives: `null`, `undefined`, `void` (no return), `never` (unreachable), `unknown`/`any` (top types) are covered in later sections.

```typescript
// primitive annotations — lowercase
let s: string = "hello";
let n: number = 42;       // includes NaN, Infinity
let b: boolean = true;
let big: bigint = 9007199254740991n;
let sym: symbol = Symbol("id");
let u: undefined = undefined;
let nu: null = null;

console.log(typeof s, typeof n, typeof big, typeof sym); // string number bigint symbol
```

### 2) **Literal** ("GET" vs string)

Each primitive has a *literal type* subtype: the value itself as a type. `"GET"` is assignable to `string` but not vice versa. This drives union-literal patterns (preferred over enums — see [3.1 Enums vs Union Literals](<../3.%20Enums,%20Tuples%20and%20Special%20Primitives/3.1.%20Enums%20vs%20Union%20Literals%20when%20enums%20hurt.md>)).

```typescript
type Method = "GET" | "POST" | "DELETE";
let m: Method = "GET"; // ok
// m = "PATCH"; // error: not in union
// let m2: Method = "GET" as string; // widens to string, error

// literal inference needs help — see 1.2 for as const
let method = "GET"; // inferred as string (widened)
const method2 = "GET"; // inferred as "GET" (literal)
```

### 3) **Bad** (Object wrapper types)

**Bad practice — never use uppercase wrappers:**

| Bad | Why | Good |
|-----|-----|------|
| `String` | wrapper object type — accepts `new String("a")` object, not primitive | `string` |
| `Number` | same | `number` |
| `Boolean` | same, also truthiness confusion | `boolean` |
| `Symbol` | object wrapper | `symbol` |
| `BigInt` | object wrapper | `bigint` |

```typescript
// bad: wrapper accepts object wrapper, not primitive
let sBad: String = "hi"; // String is object-like
// sBad = "hi"; // actually allowed, but sBad has methods like .valueOf oddly
let sGood: string = "hi"; // correct

function greetBad(x: String) { return x.length; }
greetBad(new String("hi")); // accepts object wrapper — unexpected allocation

function greetGood(x: string) { return x.length; }
// greetGood(new String("hi")); // error — not a string primitive

// also bad: Object, {} — see domain 03
let oBad: Object = "hi"; // accepts almost anything — use object or specific shape
```

### Mentor note

Ban uppercase primitives with `typescript-eslint` rule `no-wrapper-object-types` (or Biome's `noWrapperObjectTypes`). One lint rule eliminates a class of subtle overload bugs.

### Common confusion

- "`string` and `String` are the same" — they aren't. Lowercase is the primitive; uppercase is the legacy object wrapper from JS boxing.
- "`number` excludes `NaN`" — no, `NaN` is a `number`. Narrow with `Number.isNaN` if you need to exclude it.
