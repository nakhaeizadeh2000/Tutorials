## 1.2. Literal Types and const Assertions

### 1) **Definition** (value as type)

**Definition** — A literal type is the exact value as a type: `"GET"` (string literal), `42` (numeric literal), `true` (boolean literal). It is the narrowest form of a primitive. Combine with unions to model finite states without enums.

```typescript
type Direction = "north" | "south" | "east" | "west";
type Status = "idle" | "loading" | "success" | "error";
type Dice = 1 | 2 | 3 | 4 | 5 | 6;

function move(d: Direction) { /* exhaustive switch in 2.1 → */ }
move("north"); // ok
// move("up"); // error

// boolean literals are just true | false narrowed
type Verbose = true; // only true allowed
let v: boolean = true; // widened
let v2: true = true; // literal
```

### 2) **Example** (as const narrowing)

By default variables widen; `const` and `as const` preserve literals:

```typescript
// widening: let widens to primitive
let m1 = "GET"; // type string
const m2 = "GET"; // type "GET" — const preserves literal

// object/array widening surprises
let cfg1 = { method: "GET", retry: 3 }; // { method: string; retry: number }
const cfg2 = { method: "GET", retry: 3 } as const; // { readonly method: "GET"; readonly retry: 3 }

// practical use — derive union from const array
const METHODS = ["GET", "POST", "DELETE"] as const;
type Method = typeof METHODS[number]; // "GET" | "POST" | "DELETE"

// without as const, Method would be string
const METHODS2 = ["GET", "POST", "DELETE"];
type Method2 = typeof METHODS2[number]; // string — lost!

console.log(METHODS.includes("GET" as Method)); // true
```

`satisfies` (TS 4.9) checks without widening — see [06 3.1 Utility](<../../../06%20Advanced%20Types%20Conditional%20Mapped%20Template%20Literal/sections/3.%20Utilities%20and%20Branding/3.1.%20Utility%20Types%20Partial%20Required%20Pick%20Omit%20etc..md>) for contrast.

### 3) **Mistake** (widening surprises)

**Common mistakes:**

- Expecting `let x = "hello"` to be `"hello"` — it's `string`. Use `const` or `as const` or annotate `let x: "hello" = "hello"`.
- Mutating a `const` object still widens inner properties unless `as const` — `const o = { k: "a" }` has `k: string`, not `"a"`.
- Over-using `as const` where a type annotation suffices — `as const` makes everything `readonly`, which may fight mutating APIs.

```typescript
// bad: relies on widened type, loses exhaustiveness
let status: string = "idle";
status = "loading"; // any string allowed — bug if typo
// status = "lodading"; // no error, but runtime bug

// good: union literal constrains
let status2: Status = "idle";
// status2 = "lodading"; // error: typo caught
status2 = "loading"; // ok

// bad: const array without as const → string[]
const roles = ["admin", "user"];
function needsAdmin(r: "admin" | "user") {}
// needsAdmin(roles[0]); // error: roles[0] is string, not "admin"|"user"

// good: as const
const roles2 = ["admin", "user"] as const;
function needsAdmin2(r: typeof roles2[number]) {}
needsAdmin2(roles2[0]); // ok — "admin"
```

### Mentor note

Teach `as const` as "freeze the type." Show before/after hover types in VS Code — the visual widen vs literal click is instant. Pair with ESLint `prefer-const`.

### Common confusion

- "`as const` is a cast" — it's an *assertion* that narrows and adds `readonly`; it doesn't change runtime.
- "`satisfies` vs `as const` vs annotation" — annotation widens unless literal; `as const` narrows+readonly; `satisfies` checks without changing inferred type.
