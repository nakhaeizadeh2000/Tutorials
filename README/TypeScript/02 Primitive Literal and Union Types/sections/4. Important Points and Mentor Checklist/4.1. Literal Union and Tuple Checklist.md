## 4.1. Literal Union and Tuple Checklist

### 1) **Definition** (what senior must enforce — literals, unions, tuples)

**Definition** — The primitives/literals domain establishes three invariants:

- **Literals over wrappers** — `string` not `String`, `number` not `Number`; enforce via `no-wrapper-object-types`.
- **Union discipline** — discriminated unions with `kind` + `never` exhaustiveness; prefer union literals over `enum`.
- **Tuples are `readonly` by default** — `readonly [A,B]` prevents `push` length violation; label tuples for hover docs.

```typescript
type Method = "GET" | "POST" | "DELETE"; // literal union — preferred
const METHODS = ["GET","POST","DELETE"] as const;
type M = typeof METHODS[number]; // "GET"|"POST"|"DELETE"

type Shape = { kind: "circle"; r: number } | { kind: "square"; s: number };
function area(shape: Shape): number {
  switch (shape.kind) {
    case "circle": return Math.PI * shape.r ** 2;
    case "square": return shape.s ** 2;
    default: { const _ex: never = shape; throw new Error("unhandled"); }
  }
}
```

### 2) **Checklist** (PR gate: as const, discriminant, readonly)

**Mentor checklist — reject unless:**

- `let x = "hi"` widening fixed with `const` or `as const` + `satisfies` where literal needed.
- Every `A|B` with object members has `kind` discriminant.
- Tuple leaves use `readonly` + labeled `[start: number, end: number]`.

### 3) **Mentor** (how to teach widening)

**Mentor note** — Demo `as const` as "freeze the type": show `let` vs `const` hover in VS Code. Pair with `prefer-const` lint. For `const enum` trap, show why union literal wins under `isolatedModules` (see [10 3.1](<../../../10%20Migration%20Interop%20and%20Runtime%20Gaps/sections/3.%20Performance%20and%20Emit%20Gaps/3.1.%20Const%20Enum%20Erased%20Types%20and%20Perf%20Traps.md>)).

**Common confusion** —

- "`as const` is a cast" — it's narrow+`readonly`, not runtime.
- "`enum` is type-only" — no, emits object; union erases.

**Performance note** — Union literals zero-cost; `enum` emits IIFE + reverse map. Keep `as const` objects `readonly` — no allocation overhead.
