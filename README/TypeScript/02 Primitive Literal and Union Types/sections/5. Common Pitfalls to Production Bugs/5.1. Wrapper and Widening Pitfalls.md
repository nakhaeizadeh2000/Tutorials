## 5.1. Wrapper and Widening Pitfalls

### 1) **Pitfall** (wrapper types and widening)

**Pitfall — two most common bugs:**

- **Wrapper `String`/`Number`** — `let s: String = "hi"` accepts `new String("hi")` object, not primitive; `.valueOf` surprises and hidden allocation.
- **Widening** — `let m = "GET"` inferred `string` not `"GET"`; `if (m === "PATCH")` never narrow, typo not caught.

```typescript
let sBad: String = "hi"; // wrapper
let sGood: string = "hi"; // primitive

let m = "GET"; // string
// if (m === "POST") ... // m is string — any string allowed, typo slips
let m2: "GET" | "POST" = "GET"; // good — literal union
```

### 2) **Consequence** (runtime wrong branch, any hiding)

**Consequence** — Widened string allows typo `"lodading"` to pass `tsc` but render wrong UI; wrapper object `new String` truthiness `if (new String(""))` is true, not falsy.

```typescript
let status: string = "idle";
status = "lodading"; // typo — no error, bug at render
let status2: "idle" | "loading" = "idle";
// status2 = "lodading"; // error — caught
```

### 3) **Guard** (lint + as const)

**Fix — enforce `string` primitive + `as const` + union literals:**

```typescript
// biome/eslint: noWrapperObjectTypes, no-explicit-any
const ROLES = ["admin","user"] as const;
type Role = typeof ROLES[number]; // "admin"|"user"
function needsAdmin(r: Role) {}
needsAdmin("admin"); // ok
```

**Common confusion** —

- "`number` excludes `NaN`" — no, `NaN` is `number`.
- "`let` literal is literal" — no, `let` widens, `const` preserves.

**Performance note** — Wrapper objects allocate; primitives don't. Prefer literals.

**Mentor note** — Ban `String` via lint; demo `let` vs `const` hover.
