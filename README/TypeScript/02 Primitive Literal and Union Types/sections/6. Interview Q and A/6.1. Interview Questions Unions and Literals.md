## 6.1. Interview Questions Unions and Literals

### 1) **Q: Union `A|B` vs intersection `A&B`?** (or vs and)

**Answer** — `A|B` = either A *or* B (needs common members to access safely); `A&B` = both A *and* B (merge props). For primitives, `string & number` is `never`.

```typescript
type U = { a: string } | { a: string; b: number };
declare const u: U;
u.a; // common — ok
// u.b // error — not in every member, need narrow
```

---

### 2) **Q: Why does `ToArray<string|number>` become `string[]|number[]`?** (distributive)

**Answer** — Naked `T extends` distributes: `T extends unknown ? T[] : never` loops over union members. Wrap `[T]` to keep whole.

```typescript
type ToArray<T> = T extends unknown ? T[] : never;
type D = ToArray<string|number>; // string[]|number[]
type NonDist<T> = [T] extends [unknown] ? T[] : never;
type ND = NonDist<string|number>; // (string|number)[]
```

---

### 3) **Q: When `enum` vs union literal?** (union preferred)

**Answer** — Union literal erases, tree-shakable; `enum` emits object + reverse map. Use union by default; `enum` only for runtime `Object.values` + bidirectional map and whole-program emit.

**Common confusion** —

- "`enum` is type-only" — no, emits.
- "`const enum` zero-cost always" — only whole-program, breaks `isolatedModules`.

**Performance note** — Union zero emitted helpers; `enum` IIFE.

**Mentor note** — Require `kind` discriminant for any `A|B` with both object shapes.
