## 2.3. Control-Flow Narrowing (if, in, typeof)

### 1) **Mechanism** (control flow analysis)

**Definition** — TypeScript's control-flow analysis *narrows* a wide type to a narrower one after a runtime check. The checker tracks type per code path.

Narrowing forms (checked at 5.6):

- `typeof x === "string"` / `"number"` / `"bigint"` / `"symbol"` / `"boolean"` / `"object"` / `"function"` / `"undefined"`
- `x instanceof Class`, `Array.isArray(x)`, `x === null`, truthiness (`if (x)`), `in` (`"prop" in x`), `===` discriminant, `switch` on discriminant
- User-defined predicates (`x is T`) and assertion functions (`asserts x is T`) — expert form below

```typescript
type Value = string | number | null;

function format(v: Value): string {
  if (v === null) return "(null)"; // v is null here
  if (typeof v === "string") return v.toUpperCase(); // v is string here
  return v.toFixed(2); // v is number here — remaining member
}

type Payload = { kind: "text"; text: string } | { kind: "image"; url: string };
function render(p: Payload): string {
  if ("text" in p) return p.text; // narrows to first member
  return `<img src="${p.url}">`;
}
```

### 2) **Example** (typeof guard)

```typescript
function parse(input: string | string[]): string[] {
  if (typeof input === "string") {
    // input: string
    return [input];
  }
  // input: string[]
  return input;
}

// type guard function — reusable narrowing
function isStringArray(v: unknown): v is string[] {
  return Array.isArray(v) && v.every(x => typeof x === "string");
}

function handle(v: unknown) {
  if (isStringArray(v)) {
    console.log(v.length, v[0].toUpperCase()); // v is string[] — safe
  }
}

// assertion function — throws if check fails, narrows in caller
function assertIsString(v: unknown): asserts v is string {
  if (typeof v !== "string") throw new TypeError("expected string");
}
function shout(v: unknown) {
  assertIsString(v);
  console.log(v.toUpperCase()); // v is string after assertion
}
```

### 3) **Expert** (assertion functions)

Senior-level guards:

- Prefer `value is T` over `boolean` return — the latter doesn't narrow.
- Use `asserts value is T` for throw-on-fail APIs (like Zod's `parse` without library).
- Combine with `noUncheckedIndexedAccess` — narrowing also affects indexed access results (see [08 1.2 Strict](<../../../08%20Configuration%20Strictness%20and%20Build%20Pipeline/sections/1.%20tsconfig%20Foundations/1.2.%20Strict%20Family%20strict%20noImplicitAny%20strictNullChecks.md>)).

```typescript
// bad: boolean guard — no narrowing
function isStringBad(v: unknown): boolean {
  return typeof v === "string";
}
function useBad(v: unknown) {
  if (isStringBad(v)) {
    // v still unknown — no narrowing!
    // console.log(v.toUpperCase()); // error
  }
}

// good: type predicate
function isStringGood(v: unknown): v is string {
  return typeof v === "string";
}
function useGood(v: unknown) {
  if (isStringGood(v)) {
    console.log(v.toUpperCase()); // ok — narrowed to string
  }
}

// asserts vs predicate choice
function assertNonNull<T>(v: T | null | undefined): asserts v is T {
  if (v == null) throw new Error("null");
}
function useAssert(v: string | null) {
  assertNonNull(v);
  console.log(v.length); // v is string — narrowed even though no if branch
}
```

### Mentor note

Live-demo the narrowing in VS Code: hover `v` before vs after `if`. The type-in-hover visibly changes — that tangible feedback teaches CFA faster than words. Enforce eslint `strict-boolean-expressions` for consistent truthiness checks.

### Common confusion

- "`instanceof` narrows unions" — only for class constituents; for plain object unions use discriminant or `in`.
- "`x && x.prop` narrows" — yes for truthiness, but explicit `x != null` is clearer and catches `""`/`0` correctly.
