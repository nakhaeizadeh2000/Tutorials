## 2.1. Union Types and Discriminants

### 1) **Definition** (A | B)

**Definition** — `A | B` means "either A or B." The value must satisfy at least one member. You can only access members common to *all* members without narrowing.

```typescript
type StringOrNumber = string | number;
type Result = { ok: true; value: string } | { ok: false; error: string };

function describe(x: StringOrNumber): string {
  if (typeof x === "string") return `str:${x}`;
  return `num:${x.toFixed(2)}`;
}

// common members only before narrowing
type U = { a: string } | { a: string; b: number };
declare const u: U;
u.a; // ok — common
// u.b // error — not in every member
```

### 2) **Good** (discriminant property)

**Good practice — discriminated union:** add a literal `kind`/`type`/`status` field shared across members with distinct literal values. The checker narrows on that field with `switch` exhaustiveness.

```typescript
type Shape =
  | { kind: "circle"; radius: number }
  | { kind: "square"; size: number }
  | { kind: "rect"; w: number; h: number };

function area(s: Shape): number {
  switch (s.kind) {
    case "circle": return Math.PI * s.radius ** 2;
    case "square": return s.size ** 2;
    case "rect":   return s.w * s.h;
    default: {
      const _exhaustive: never = s; // compile error if new kind added and not handled
      throw new Error("unhandled");
    }
  }
}

// good: discriminant enables autocomplete + exhaustive check
const c: Shape = { kind: "circle", radius: 2 };
console.log(area(c)); // 12.56...
```

Why good: single property check, zero runtime library, pairs with `never` exhaustiveness to make adding a variant a compile error.

### 3) **Bad** (non-discriminated unions)

**Bad — non-discriminated union forces brittle checks:**

```typescript
// bad: union without discriminant — shape inferred from presence of props
type BadShape = { radius: number } | { size: number };
// how to tell which? 'radius' in s is fragile if shapes evolve to both have radius

// bad: mixed discriminant values with wrong types
type Bad2 = { kind: "a"; x: string } | { kind: string; x: number }; // kind too wide (string) — never narrows

// good vs bad stringified
type ApiResponseGood = { status: "success"; data: string } | { status: "error"; error: string };
type ApiResponseBad  = { data?: string; error?: string }; // optional mix — both could be present/absent

function handleBad(r: ApiResponseBad) {
  // if (r.data) ... else ... — no exhaustiveness, typos not caught
}
function handleGood(r: ApiResponseGood) {
  if (r.status === "success") console.log(r.data); // narrowed, data guaranteed
  else console.log(r.error);
}
```

### Mentor note

Require every union with >1 object member to have a discriminant. Enforce with code review checklist: "if you write `A | B` with both object shapes, where is `kind`?" Exceptions only for trivial `string | number` where `typeof` is the discriminant.

### Common confusion

- "Union means both" — that's intersection (`&`). `A | B` is *or*.
- "`{ kind: string } | { kind: string }` is discriminated" — no, `kind` must be *literal* types to discriminate (`"a"` vs `"b"`), not broad `string`.

### Performance note

Discriminated checks compile to one property load + string compare — cheapest possible branching. `instanceof` or `Array.isArray` chains are slower and not exhaustive.
