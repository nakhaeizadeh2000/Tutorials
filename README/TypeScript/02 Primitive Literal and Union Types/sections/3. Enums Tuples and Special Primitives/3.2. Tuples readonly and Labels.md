## 3.2. Tuples, readonly and Labels

### 1) **Definition** (fixed-length arrays)

**Definition** — A tuple is a fixed-length array where each position has a distinct type: `[string, number]`. It is more precise than `Array<string | number>` (which allows any length/order).

```typescript
type Point = [number, number];
type Entry = [string, number]; // [key, value]

let p: Point = [10, 20];
p[0]; // number
p[1]; // number
// p[2] // error — out of bounds (Tuple length checked)
// p.push(3) // careful — see readonly below

// rest elements (variadic tuples — TS 4.0)
type Args = [string, ...number[]]; // first is string, rest are numbers
function call(...args: Args) {}
call("hi", 1, 2, 3); // ok
// call(1, 2) // error — first must be string

// optional elements
type Opt = [string, number?]; // second optional
const a: Opt = ["hi"];
const b: Opt = ["hi", 42];
```

### 2) **Example** (labeled tuples)

Labels are documentation for checker hover + errors (TS 4.0+), no runtime effect:

```typescript
// labeled
type Range = [start: number, end: number];
type Result = [ok: true, value: string] | [ok: false, error: string];

function inRange(...r: Range): boolean {
  return r[0] <= r[1];
}
inRange(1, 5); // ok — hover shows start, end

// readonly tuple — prevents mutation
type RO = readonly [number, number];
const ro: RO = [1, 2];
// ro.push(3); // error — readonly
// ro[0] = 9; // error

// as const makes literal readonly tuple
const entry = ["key", 42] as const; // readonly ["key", 42]
type EntryType = typeof entry; // readonly ["key", 42]

// tuple vs array assignability
let arr: number[] = [1, 2, 3];
let tup: [number, number] = [1, 2];
// arr = tup; // ok — tuple is subtype of array (if readonly variance respected)
// tup = arr; // error — array may not have length 2
```

### Mentor note

Default to `readonly` tuples for any tuple that leaves module boundary: `readonly [string, number]`. Mutable tuples tempt `push` which breaks length guarantee and defeats the reason you chose tuple over array.

### Common confusion

- "`[number, number]` allows `push`" — at type level, yes (unless `readonly`), but `push` breaks length invariant; `readonly` prevents it.
- "Tuple labels affect runtime" — no, erased. They only improve error messages.

### Performance note

Tuples emit as plain arrays — same allocation as `Array`. The benefit is static checking, not runtime speed. Avoid large tuples (>4 elements) — use object with named props for readability/optimization (hidden class friendly).
