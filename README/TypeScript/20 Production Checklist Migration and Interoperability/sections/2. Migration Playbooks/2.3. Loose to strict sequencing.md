## 2.3. Loose to strict sequencing

### 1) **Choose an order from actual diagnostics and dependencies**

Stricter checking changes which programs are accepted. Start by identifying the current configuration, selected files and exposed contracts; then compare candidate checks on the same inputs. A staged migration can reduce review complexity, while a small clean project may adopt strict directly. There is no universal requirement to fix nullability before implicit any or function variance. The [effective audit](<../1. Production Checklist/1.2. Strictness and configuration audits.md>) demonstrates why an inherited strict flag and a green child command are insufficient evidence of identical checking.

Distinguish policy order from a real option dependency. `strictPropertyInitialization` requires strictNullChecks; function-parameter checking and implicit-any reporting can be investigated independently. `noImplicitOverride` is a separate option outside the strict family. Strict also retains explicit any escapes and method-related variance exceptions; it is not complete soundness or runtime validation. The detailed [configuration owner](<../../../13 Configuration and Compiler Options/README.md>) owns those semantics.

Use TypeScript **7.0.2** and Node **20.20.2**, verified 2026-10-17. Create src in a disposable directory and save `tsconfig.json`:

```json
{
  "compilerOptions": {
    "strict": false,
    "target": "es2022",
    "module": "nodenext",
    "lib": ["es2022"],
    "types": [],
    "rootDir": "src",
    "noEmitOnError": true,
    "noEmit": true
  },
  "include": ["src/**/*.mts"]
}
```

Save `src/contracts.mts`:

```typescript
export function label(value) { return value.name.toUpperCase(); }
export function firstA(values: readonly string[]): string {
  const selected = values.find(value => value.startsWith("a"));
  return selected.toUpperCase();
}
export interface Animal { name: string }
export interface Dog extends Animal { bark(): void }
const dogOnly = (value: Dog): void => { value.bark(); };
export const acceptAnimal: (value: Animal) => void = dogOnly;
export class Box { value: string }
class Base { view(): string { return "base"; } }
export class Derived extends Base { view(): string { return "derived"; } }
```

Each defect has a distinct contract: label lacks a checked input shape; a search can find nothing; a consumer promising to handle any Animal cannot require bark; Box promises a string field without initializing it; and the project may require explicit override intent. Run each command independently, expecting the failures listed below:

```bash
tsc -p tsconfig.json
tsc -p tsconfig.json --noImplicitAny
tsc -p tsconfig.json --strictNullChecks
tsc -p tsconfig.json --strictFunctionTypes
tsc -p tsconfig.json --strictPropertyInitialization
tsc -p tsconfig.json --strictPropertyInitialization --strictNullChecks
tsc -p tsconfig.json --noImplicitOverride
```

| Selected change | Observed result |
|---|---|
| Loose base only | Exit 0; it has not established the stricter contracts. |
| noImplicitAny only | Exit 1, TS7006 for label's value. |
| strictNullChecks only | Exit 1, TS18048 for selected. |
| strictFunctionTypes only | Exit 1, TS2322 for the callback assignment. |
| strictPropertyInitialization without null checks | Exit 1, TS5052 option dependency. |
| Initialization and null checks | Exit 1, TS2564 for Box.value and TS18048 for selected. |
| noImplicitOverride only | Exit 1, TS4114 for Derived.view. |

These observations are local to the explicit project and version. Error totals are not a portable effort estimate or a proof that diagnostic categories never overlap. The [function-parameter reference](https://www.typescriptlang.org/tsconfig/strictFunctionTypes.html), [initialization reference](https://www.typescriptlang.org/tsconfig/strictPropertyInitialization.html) and [override reference](https://www.typescriptlang.org/tsconfig/noImplicitOverride.html) explain their different checks.

### 2) **Repair the intended behavior and verify the complete target**

Choose what absence means before inserting a nullish fallback. Here firstA deliberately returns undefined when there is no matching string; this changes its declared return contract so callers must handle absence. The general Animal callback uses only the promised Animal shape, and the constructor initializes Box before its value is read. Replace contracts.mts with:

```typescript
export function label(value: { name: string }): string { return value.name.toUpperCase(); }
export function firstA(values: readonly string[]): string | undefined {
  const selected = values.find(value => value.startsWith("a"));
  return selected?.toUpperCase();
}
export interface Animal { name: string }
export interface Dog extends Animal { bark(): void }
export const acceptAnimal = (value: Animal): void => { value.name.toUpperCase(); };
export class Box {
  value: string;
  constructor(value: string) { this.value = value; }
}
class Base { view(): string { return "base"; } }
export class Derived extends Base { override view(): string { return "derived"; } }
```

Save `tsconfig.strict.json`:

```json
{
  "extends": "./tsconfig.json",
  "compilerOptions": {
    "strict": true,
    "noImplicitOverride": true,
    "noEmit": false,
    "outDir": "dist",
    "declaration": true
  }
}
```

Save `verify.mjs` in the root:

```javascript
import assert from "node:assert/strict";
import { label, firstA, acceptAnimal, Box, Derived } from "./dist/contracts.mjs";
assert.equal(label({ name: "Ada" }), "ADA");
assert.equal(firstA(["beta", "alpha"]), "ALPHA");
assert.equal(firstA([]), undefined);
assert.equal(firstA(["beta"]), undefined);
assert.doesNotThrow(() => acceptAnimal({ name: "generic animal" }));
assert.equal(new Box("ready").value, "ready");
assert.equal(new Derived().view(), "derived");
console.log("strict contracts verified");
```

Run the full target:

```bash
tsc -p tsconfig.strict.json --showConfig
tsc -p tsconfig.strict.json
node verify.mjs
```

All exit 0; the verifier prints `strict contracts verified`. The explicit inherited rootDir keeps this emitting configuration's output layout defined; a green no-emit stage alone does not verify emitting configuration constraints. Inspect dist/contracts.d.mts: firstA returns string | undefined, while Box takes a required string constructor argument. These deliberate API changes need caller review. A definite-assignment assertion would silence initialization checking without creating a value, so it is not an equivalent repair.

For a meaningful regression, replace only `selected?.toUpperCase()` with `selected.toUpperCase()`. Full strict checking fails TS18048 again. Restore it. Next remove only `this.value = value;`: checking fails TS2564. Restore the assignment, compile and run again. Separate checks for the target settings and runtime cases prevent one previously green wave from standing in for the final contract.

### 3) **Roll out with explicit exceptions and coverage**

Select an independently reviewable project or coherent dependency group, record the relevant changes and choose checks that expose unintended weakening. A pilot can reveal useful patterns, but it is not automatically the fastest rollout. Automation can assist a well-understood rewrite; optional chaining, defaults, assertions and widening all express different behavior or contracts. Review their meaning and execute relevant cases instead of treating a codemod as proof.

For existing diagnostics, a baseline can document accepted exceptions and their owners/removal conditions. Counts, including counts per category, cannot prove no new error appeared: fixing one nullability error and adding another in the same category preserves the total. Compiler diagnostics do not provide an automatic organization-specific “accepted errors” mechanism; implementing one requires a real parser/comparison policy and verification. The [baseline/gate owner](<../../../17 Testing Types/sections/3. Type Tests in Practice/3.3. CI gates running type tests with unit tests.md>) explains identity/context and scope limits. This fixture uses clean commands, not a baseline tool.

Do not obtain a green wave by silently dropping source or probes. A selected strict project can be useful during migration, but imported legacy files can re-enter its program, and omitted behavior remains uncovered. The effective audit supplies a concrete excluded-probe false green. Show the full target command passing before declaring that target complete; a partial wave or explicit any does not mean the whole repository is strict.

The [file migration playbook](<./2.1. JavaScript to TypeScript file by file.md>) compares checked JavaScript, typed conversion and the historical project-wide automation alternative. Use those options according to actual ownership and tooling constraints. Plan reviews, support and restoration of source/configuration/dependencies where needed, without promising a completion date or mandating one organizational ceremony.

### 4) **Common confusion**

A sequence is a project decision; an option dependency is a compiler constraint. This fixture independently exposes variance and implicit-any problems before null checks are enabled, while initialization checking requires null checks. noImplicitOverride needs its own explicit setting in the final target.

Adding a fallback can change meaning, and widening a return can change the public API. Fixing a diagnostic is not automatically a behavior-preserving migration. A green baseline total or reduced source set can likewise conceal a new defect or lost coverage.

### 5) **Performance note**

The fixture reports actual diagnostics, emitted declarations and selected runtime assertions. It measures no check-time speedup, per-error repair cost or team rollout efficiency. Additional checking can add work, and staged projects can repeat dependencies. Preserve selected scope and compare the actual commands if migration cost becomes a concern; do not infer effort or benefit from the number of flag waves.

### 6) **Mentor note**

Ask the learner to choose an order for this small project and justify it from the diagnostics and API effects. Accept multiple orders that honor real dependencies and reach the tested full target. Then ask why changing Box.value to a definite-assignment assertion would fail to establish the constructor's runtime contract.

For a rollout review, replace one accepted diagnostic with another in the same category and ask why the unchanged count is insufficient. Require the learner to identify omitted source and remaining exceptions before declaring completion. The goal is a defensible contract and evidence, not recitation of a universal flag order.
