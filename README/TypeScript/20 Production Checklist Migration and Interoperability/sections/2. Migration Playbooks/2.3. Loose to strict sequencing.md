## 2.3. Loose to strict sequencing

### 1) **Flag-by-flag ordering** (nullability first, any second, variance third)

**Definition** — *sequencing* (13/4.1 ordered as playbook): (1) `strictNullChecks` (nullability — biggest correctness win, mechanical `?.`/`??`/guards fixes); (2) `noImplicitAny` (declarations — signatures annotated, inference explicit); (3) `strictFunctionTypes` + `strictPropertyInitialization` + `noImplicitOverride` (variance/init/override — design-level fixes: branding, definite assignment, override corrections). Each flag a wave (enable → fix class → green → next — momentum compounding, never stalled).

**What problem it solves / history** — `strict: true` big-bangs (10k errors day one — teams drowning, strictness abandoned as "impractical"): waves converting avalanches into backlogs (hundreds per wave — triaged, fixed, merged; each wave green before next — 13/4.1 sequencing restated as team playbook).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), order nullability → any → variance (correctness-per-effort descending — wins first); wave per flag (enable, fix, green, next — momentum compounding); never skip waves (variance fixes needing nullability-clean code — foundations first, always).

**Runnable example** — waved strictness (good vs bad, `tsc --strict`):

```typescript
// good — wave-1 nullability (mechanical guards — biggest win first)
export {}; // module marker (consistent module scope across fences)
export function wave1(input: string | null): string {
  return input ?? "default"; // nullability handled (?. / ?? / guards — mechanical fixes, wave 1 shape)
}
console.log(wave1(null)); // default — nullability wave (correctness-per-effort highest — first for a reason)
// bad — strict-true day one (10k errors — drowning, abandonment, "strictness impractical" folklore)
// fix — waves (nullability → any → variance — avalanches converted to backlogs, momentum compounding)
```

```typescript
// good — wave-2 declarations (signatures annotated — inference explicit, any budgeted)
export {}; // module marker (consistent module scope across fences)
export function wave2(items: string[]): string {
  return items.join(","); // annotated (noImplicitAny satisfied — declarations real, inference explicit per 03/3.1)
}
console.log(wave2(["a"])); // a — declaration wave (signatures proving — any absent or budgeted with expiry)
// bad — any-sweep conversions (errors silenced — strictness theater, debt compounding per 17/5.1)
// fix — annotate waves (real types — any only budgeted-expiring, tests green per file per 2.1 loops)
```

**Common confusion** — "waves prolong migration" — waves *complete* migrations (big-bangs stalling at month three — steady waves shipping green monthly; duration measured to done, not to start). "flag order arbitrary" — order = correctness-per-effort (nullability catching real bugs immediately; variance polishing designs last — value sequencing, not ritual). "waves need freezes" — waves need *baselines* (per-class ratchets per 17/3.3 — features shipping throughout, strictness tightening alongside).

**Performance note** — wave fixes minutes-per-error-class (mechanical — nullability/any waves tool-assisted; variance waves design-flavored, slower but last).

**Mentor note** — kickoff question: "which wave?" (nullability first — always; teams proposing variance-first redirected to value-ordering).

### 2) **Per-class baselines** (error counts per flag, ratchets shrinking)

**Definition** — *class baselines* (17/3.3 part 3 applied to strictness): error counts per flag wave (`strictNullChecks: 41`, `noImplicitAny: 87` — classes, not totals — fixes directed, progress attributed); ratchets shrinking (current ≤ baseline — growth red, shrinkage updating down); graduation per wave (count zero → flag locked on, baseline file pruned for that class — 17/3.3 graduation restated for strictness).

**What problem it solves / history** — total-count baselines hiding class-shifts (nullability fixed, `any` grown — net zero, understanding negative per 17/3.3): per-class attribution directing effort (fix the class, watch its number — progress honest, gaming impossible).

**Modern guidance** — baseline per flag wave (classes separate — attribution precise); review class-shrink PRs fast (progress rewarded — momentum compounding); graduate classes at zero (flags locked — files pruned, ceremonies held per 17/3.3).

**Runnable example** — attributed strictness (good vs bad, `tsc --strict`):

```jsonc
// good — per-class baselines (attribution precise — effort directed, progress honest)
// strict-baseline.json (labeled config doc — wave artifact):
// { "strictNullChecks": 41, "noImplicitAny": 87, "strictFunctionTypes": 3, "updated": "2026-09-01" }
// CI rule: current[class] <= baseline[class] (class-shifts visible — net-zero gaming impossible)
```

```typescript
// good — class-shrink contribution (nullability fixes — attributed progress)
export {}; // module marker (consistent module scope across fences)
export function shrunk(value: number | undefined): number {
  return value ?? 0; // one fewer nullability error (class count decrementing — progress attributed, momentum compounding)
}
console.log(shrunk(undefined)); // 0 — class fixes (per-error progress — baselines shrinking one guard at a time)
// bad — total-count baselines (class-shifts hidden — net-zero gaming, understanding negative)
// fix — per-class ratchets (attribution precise — fix the class, watch its number)
```

**Common confusion** — "baselines bless laxity" — baselines *contain* laxity (bounded, shrinking, visible — 17/3.3 honesty restated; unbounded invisible laxity the alternative). "per-class overkill" — per-class *directs* (totals hiding shifts — precision proportional to value, gaming impossible). "graduation ceremony silly" — ceremonies *signal* (strictness milestones celebrated — culture compounding like code).

**Performance note** — baseline compares milliseconds (per-class integers — cheapest gate; class-shift gaming prevented quarters of misdirected effort).

**Mentor note** — sprint metric: class counts plotted (downward slopes — migration story leadership-visible without flag-days).

### 3) **Team rollout** (pilot partition, codemods, mandate pacing)

**Definition** — *rollout*: pilot partition first (one team/project enabling the wave — playbook debugged, codemods built, docs written from experience); codemods second (mechanical fixes automated — `?.` insertion, annotation scaffolds — toil deleted); mandate last (org-wide wave with support staffed — office hours, review SLA, rollback paths — adoption paced, never decreed).

**What problem it solves / history** — decreed migrations (org-wide flag-days announced — support unstaffed, codemods absent, teams blocked simultaneously): paced rollouts converting mandates into pull (pilot proving, codemods easing, mandate formalizing completed adoption — decree following reality, not preceding it).

**Modern guidance** — pilot self-selected teams (enthusiasts debugging playbooks — experience authoring docs); codemod mechanical classes (toil automated — humans deciding, machines rewriting); mandate with support (office hours + SLA + rollback — paced adoption, staffed help, measured progress per 17/3.3 dashboards).

**Runnable example** — paced adoption (good vs bad, `tsc --strict`):

```typescript
// good — pilot-proven pattern (playbook debugged — codemods built from experience)
export {}; // module marker (consistent module scope across fences)
export function pilotProven(id: string | undefined): string {
  return `user:${id ?? "anon"}`; // pilot idiom (nullish patterns proven — codemods replicating, docs quoting real fixes)
}
console.log(pilotProven(undefined)); // user:anon — pilot value (experience authoring — mandate following reality)
// bad — org-wide decrees (flag-days announced — support unstaffed, teams blocked simultaneously, rollbacks chaotic)
// fix — pilot → codemod → mandate (pull over push — decree formalizing completed adoption)
```

**Common confusion** — "pilots delay rollout" — pilots *accelerate* rollout (playbooks debugged — org-wide avoiding pilot-discovered pitfalls; decreed rollouts stalling on undebugged toil). "codemods replace thinking" — codemods replace *toil* (mechanical rewrites — humans reviewing diffs, deciding edge cases; toil deleted, judgment kept). "mandates ensure completion" — mandates ensure *resentment* without support (staffed help completing — office hours + SLA the actual completion mechanism).

**Performance note** — pilot costs one team-weeks (playbook debugged — org-wide savings multiples); codemods amortize (mechanical classes automated once — N teams benefiting).

**Mentor note** — rollout retro: pilot lessons documented (playbooks written from experience — next wave starting from docs, not from zero).
