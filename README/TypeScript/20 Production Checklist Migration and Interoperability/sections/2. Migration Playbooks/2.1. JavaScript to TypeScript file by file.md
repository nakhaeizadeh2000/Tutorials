## 2.1. JavaScript to TypeScript file by file

### 1) **`allowJs` bridging phase** (mixed programs, inventoried boundaries, no big-bangs)

**Definition** — *bridging*: `allowJs: true` (+ `outDir`, `rootDir` spanning both) compiling `.js` alongside `.ts` (one program — imports crossing languages freely, JS checked loosely or per `checkJs`, TS strictly): boundaries inventoried (which JS modules remain — migration backlog explicit, see 17/3.3 baselines applied to file counts), progress measured (JS-file count shrinking — ratchet, never growing).

**What problem it solves / history** — big-bang rewrites (feature freeze for quarters — 5.1 incident 2: two-quarter stall abandoned mid-flight): bridging migrating incrementally (features shipping throughout — each file converted, tested, merged independently; velocity with safety, the 2.3 sequencing philosophy at file scale).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), enable `allowJs` + `checkJs: false` first (compilation unified — behavior unchanged, program whole); inventory JS boundaries (counts baselined — backlog shrinking per PR); convert leaf-ward (dependencies before dependents — bottom-up, like 2.1 reference direction: stable first).

**Runnable example** — bridged programs (good vs bad, `tsc --strict`):

```jsonc
// good — bridge configuration (mixed programs — behavior unchanged, migration measurable)
// tsconfig.migrate.json (labeled config doc): { "compilerOptions": { "allowJs": true, "checkJs": false,
//   "outDir": "lib", "rootDir": "src", "strict": true } }
// (JS compiling alongside TS — imports crossing freely; strict applying where annotations exist)
```

```typescript
// good — converted leaf (bottom-up — dependencies first, dependents following)
// file: utils/format.ts (converted leaf — previously format.js, types added at conversion)
export function formatId(id: string | number): string {
  return `id:${String(id)}`; // converted (JS behavior preserved — String() coercion made explicit, implicit coercion removed)
}
console.log(formatId(7)); // id:7 — file-by-file (leaves first — dependents converting onto typed leaves)
// bad — big-bang rewrites (feature freeze quarters — stalls abandoned mid-flight per 5.1)
// fix — bridging (allowJs + inventory + leaf-ward loops — velocity with safety, always)
```

**Common confusion** — "`allowJs` migrates" — `allowJs` *bridges* (mixed compilation — migration = renames + tightening per part 2's loops; bridge without loops stagnating). "mixed programs are impure" — mixed programs are *transitional* (inventory shrinking — purity at the end, velocity throughout; permanent mixed states needing justification). "convert top-down" — dependents-first converting onto untyped leaves (annotations guessing — leaf-ward bottom-up converting onto contracts, see 2.1 reference direction).

**Performance note** — `allowJs` programs check JS loosely (cheap — strictness applying to TS; conversion tightening per file — cost proportional to progress).

**Mentor note** — migration metric: JS-file count (ratchet shrinking — backlog visible on dashboards, progress celebrated per file).

### 2) **Rename-and-tighten loops** (js to ts per file, errors fixed per file, tests green)

**Definition** — *the loop*: pick one leaf `.js` file → rename to `.ts` → fix its `noImplicitAny`/strict errors (annotations added — implicit made explicit) → run its tests (green throughout — behavior preserved) → merge → repeat. Each loop independent (one file, one PR — reviewable, revertable, shippable; velocity compounding as typed leaves ease later conversions).

**What problem it solves / history** — conversion stalls (hundred-file PRs unreviewable — feedback never arriving, branches rotting): loops keeping PRs small (one file — review minutes, merge daily; 200 files = 200 merges, momentum compounding instead of stalling).

**Modern guidance** — loops per file (rename → tighten → test → merge — independence total); fix errors with annotations (explicit types — `any` only with 17/2.1 budgeting + expiry); keep tests green per loop (behavior preserved — red tests meaning behavior changed, loop aborted and split).

**Runnable example** — looped conversion (good vs bad, `tsc --strict`):

```typescript
// good — tightened conversion (implicit made explicit — annotations added, behavior preserved)
export {}; // module marker (consistent module scope across fences)
export function totalOf(items: Array<{ price: number; qty: number }>): number {
  return items.reduce((sum, it) => sum + it.price * it.qty, 0); // tightened (shapes annotated — implicit-any errors fixed with types, not suppressions)
}
console.log(totalOf([{ price: 3, qty: 2 }])); // 6 — looped conversion (one file green — behavior preserved, types added)
// bad — annotation-by-any conversions (errors silenced with any — strictness theater, 200 anys compounding per 17/5.1)
// fix — tighten loops (annotations real — any budgeted with expiry, tests green per file)
```

**Common confusion** — "loops are slow" — loops are *steady* (one file daily = 200 files per engineer-year with zero stalls — big-bangs stalling at month three with zero files shipped). "tests suffice without tightening" — untyped conversions preserving *behavior* but adding no *safety* (migration's value IS the types — any-conversions motion without progress). "loops need permission per file" — loops need *process* (backlog + ratchet — files self-served, progress dashboarded).

**Performance note** — per-file loops minutes-to-hours (reviewable units — throughput steady; big-bang quarters with zero shipped — velocity comparison decisive).

**Mentor note** — conversion onboarding: first loop paired (rename-tighten-test-merge demonstrated — subsequent loops self-served, momentum compounding).

### 3) **JSDoc as a halfway house** (typed JS without migration, value first)

**Definition** — *JSDoc typing*: `@param`/`@returns`/`@typedef`/`@template`/`@type` annotations in `.js` comments, verified by `tsc` under `checkJs` (typed JavaScript — value without migration: editor hovers, refactoring renames, call-site checks — 80% of migration value at 20% of conversion cost). *Halfway*: JSDoc'd files converting trivially later (annotations mapping 1:1 to TS syntax — mechanical renames, see 3.1 graduation criteria).

**What problem it solves / history** — all-or-nothing migration framing (files either `.ts` or untyped — holdouts staying untyped for years): JSDoc typing the middle (holdouts gaining safety now — conversion later mechanical, value immediate).

**Modern guidance** — JSDoc hot holdouts (frequently-edited JS — safety where churn is, conversion where scheduled); `checkJs` on JSDoc'd files (verification — annotations checked, not decorative); graduate to `.ts` when generics/conditional shapes strain JSDoc (3.1 criteria — complexity thresholds, not vibes).

**Runnable example** — typed JS (good vs bad, `tsc --strict`):

```typescript
// good — TS equivalent of JSDoc'd JS (annotations mapping 1:1 — graduation mechanical)
// (real JSDoc form: /** @param {string} id @returns {string} */ function formatId(id) { ... } in .js — checked via checkJs, see 3.1)
export {}; // module marker (consistent module scope across fences)
export function formatId(id: string): string {
  return `id:${id}`; // graduated (JSDoc @param/@returns mapping directly — conversion trivial after JSDoc value captured)
}
console.log(formatId("x")); // id:x — halfway value (safety now — conversion later mechanical, never blocked)
// bad — untyped holdouts for years ("we'll convert someday" — churn unprotected, conversions never scheduled)
// fix — JSDoc now (value immediate — graduation mechanical when thresholds met per 3.1)
```

**Common confusion** — "JSDoc equals migration" — JSDoc equals *safety* (hovers, checks, renames); migration equals *ergonomics* (generics, mapped types, ecosystem — 3.1 criteria deciding graduation). "JSDoc verbose" — JSDoc verbose *per annotation* (mechanical, greppable); untyped verbose *per incident* (debugging dynamic shapes — verbosity priced differently). "checkJs slows JS" — `checkJs` verifies JSDoc'd files (unchecked JS unaffected — verification proportional to annotation, opt-in per file).

**Performance note** — JSDoc checking per annotated file (proportional — unannotated JS unchecked-cheap; value concentrated where churn is).

**Mentor note** — holdout review: "JSDoc or convert?" (churn demanding one — untyped churn rejected like untested code).
