## 1.2. Strictness and configuration audits

### 1) **Flag audit** (strict family on, trio enforced, pairing per runtime)

**Definition** — *flag audit*: release-signoff verification that `strict` (full family — no per-flag carve-outs without recorded reason), erasable trio (`isolatedModules` + `verbatimModuleSyntax` + `erasableSyntaxOnly` per 13/2.3), and module/resolution pairing per runtime (13/3.1 table — Node/bundler/edge each paired) hold across every shipped `tsconfig` (apps + leaves + tools — audit scope = release scope, no unexamined projects).

**What problem it solves / history** — config drift between environments (dev-strict, CI-loose, prod-unchecked — "works on my machine" elevated to release policy): audits converting drift into red signoffs (parity verified — 13/4.1 checklist signed per release, carve-outs recorded with reasons + expiry, see 2.3 sequencing).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), audit per release cut (flags diffed against the 13/4.1 checklist — deviations listed, reasons attached, expiries set); inherit configs (`extends` chains — base flags single-sourced, per-project deltas minimal and reviewed); fail open-flag PRs (strict-off without reason + expiry blocked like `any` — same severity).

**Runnable example** — audited strictness (good vs bad, `tsc --strict`):

```typescript
// good — strict-assumed code (audit passing — nullability honest, any absent, variance sound)
export {}; // module marker (consistent module scope across fences)
export function audited(input: string | null): string {
  return input ?? "default"; // strictNullChecks honesty (audit assuming — code written for strict, flags confirming)
}
console.log(audited(null)); // default — strictness audited (flags signed — code and config agreeing at the cut)
// bad — audit-theater configs (strict in base, strict:false overrides scattered — signoffs green, code loose)
// fix — override inventory (every strict-off listed with reason + expiry — deviations deliberate, expiring, reviewed)
```

```jsonc
// good — flag audit shape (deviations listed — reasons attached, expiries set)
// flag-audit.json (labeled config doc — release signoff artifact):
// { "strict": true, "trio": true, "overrides": [{ "project": "legacy-app", "flag": "strictNullChecks=false",
//   "reason": "migration wave 2", "expires": "2026-12-01" }] }
// (overrides expiring — unrenewed deviations red at the next cut, see 2.3 sequencing)
```

**Common confusion** — "audits duplicate CI" — CI *runs* flags (checking under them); audits *verify* flags (the flags themselves correct — different layers: execution vs configuration). "temporary overrides harmless" — overrides fossilize (14-month `any`-exemptions per 17/5.1 part 2 — expiries converting temporaries into scheduled work). "small services exempt" — small services drifting identically (audits proportional — one-line signoffs, never exempt).

**Performance note** — audits cost review-minutes per release (config diffs — cheapest signoff); drift incidents cost postmortems (unstrict nullability per 13/5.1 — most expensive config class).

**Mentor note** — release-signoff line: "flags audited, overrides expiring" (deviations deliberate — temporaries scheduled, never fossilized).

### 2) **Exemption inventory** (expect-error any disables counted, shrinking never growing)

**Definition** — *exemption inventory*: counted `// @ts-expect-error` locks (legitimate — 17/1.3 rejection probes, distinguished from debt), `as any`/explicit-`any` occurrences, and lint-disable comments — baselined per 17/3.3 part 3 (current ≤ baseline — growth red, shrinkage updating down). Locks vs debt distinguished (probes documented with reasons — debt carrying expiries per part 1).

**What problem it solves / history** — exemption creep (suppressions compounding silently — 200 `any`s becoming 400 with no single culprit, see 19/1.2 commons tragedy): inventories attributing growth (which partition, which PR — owners notified, ratchets enforced — collective suppression managed like instantiations).

**Modern guidance** — count three classes (`@ts-expect-error` total vs probe-documented, `any` occurrences, lint-disables — each baselined separately; probe-locks exempt from debt counts where reason-commented — testing distinguished from suppressing); review growth with traces (evidence per 19/1.1 — features shipping with numbers); celebrate shrinkage (ratchet-down PRs fast-tracked — progress rewarded).

**Runnable example** — counted exemptions (good vs bad, `tsc --strict`):

```typescript
// good — probe-lock distinguished from debt (reason-commented locks exempt — suppression counted separately)
export {}; // module marker (consistent module scope across fences)
export function validated(n: number): number {
  if (!Number.isInteger(n)) throw new Error("int-only"); // invariant (probed per 17/1.3 — locks testing, not suppressing)
  return n;
}
// lock illustration — in real test-d files: "@ts-expect-error — integers only" above validated(1.5) (probe-lock, reason-attached — inventory-exempt)
console.log(validated(3)); // 3 — locks vs debt (probes documented — suppressions counted, testing excluded)
// bad — undifferentiated suppression counts (probes + debt lumped — testing penalized, suppressing hidden)
// fix — three-class inventories (locks exempt-with-reason — debt baselined, growth red)
```

```jsonc
// good — exemption baselines (per-class ceilings — growth loud per owner)
// exemptions.json (labeled config doc — ratchet artifact):
// { "any": 12, "lintDisable": 5, "unexplainedExpectError": 0, "updated": "2026-09-01" }
// CI rule: current <= baseline per class (probe-locks with reasons excluded from unexplained counts)
```

**Common confusion** — "counting probes punishes testing" — reasoned probes *excluded* (testing distinguished — inventories counting suppression, not verification). "zero exemptions realistic" — zero *unexplained* realistic (probes + expiring migrations legitimately nonzero — honesty, not purity, the goal). "inventories blame teams" — inventories *attribute* growth (owners notified with traces — management, not blame, per 19/1.2).

**Performance note** — inventory compares milliseconds (count greps + integer compares — cheapest gate; creep prevented quarters of suppression-debt).

**Mentor note** — growth-PR question: "probe or debt?" (testing excluded — suppressions evidenced; undifferentiated growth rejected).

### 3) **Environment parity** (dev CI prod configs identical, drift red)

**Definition** — *parity*: dev/CI/prod `tsconfig`s deriving from one base (`extends` — flags single-sourced; per-environment deltas: `sourceMap` dev-only, `declaration` packaging-only — deltas minimal, listed, reviewed). Drift = unlisted delta (dev-relaxed flag absent in CI — "green locally, red remotely" or worse, the reverse). Parity verified by config diffing in CI (base + deltas declared — undeclared differences red).

**What problem it solves / history** — environment-specific configs copied-and-diverged (three `tsconfig`s drifting over quarters — strict locally, loose in CI, unchecked in Docker builds): inheritance single-sourcing (deltas declared — drift structurally unrepresentable outside the delta list).

**Modern guidance** — one base config (flags once — environments extending, never copying); deltas declared per environment (dev: sourcemaps/watch; CI: noEmit/incremental-cache; prod: declarations/emit — each delta justified in comments); CI config-diff gate (effective configs compared — unlisted deltas red, see 17/5.1 part 4 parity lesson).

**Runnable example** — parity single-sourced (good vs bad, `tsc --strict`):

```jsonc
// good — inheritance chain (flags once — deltas declared, drift unrepresentable)
// tsconfig.base.json (labeled config doc): { "compilerOptions": { "strict": true, "target": "ES2022" } }
// tsconfig.dev.json (labeled config doc): { "extends": "./base", "compilerOptions": { "sourceMap": true } }
// tsconfig.ci.json (labeled config doc): { "extends": "./base", "compilerOptions": { "noEmit": true } }
// (deltas: sourcemaps/watch vs noEmit/cache — each justified; unlisted deltas red via config-diff gate)
```

```typescript
// good — parity-assumed code (identical flags everywhere — behavior uniform across environments)
export {}; // module marker (consistent module scope across fences)
export function parity(input: unknown): string {
  if (typeof input !== "string") throw new Error("string-only"); // unknown-narrowing (strict everywhere — dev/CI/prod agreeing, no environment-conditional behavior)
  return input.toUpperCase();
}
console.log(parity("ok")); // OK — parity proving (flags identical — "works locally" meaning "works in CI/prod")
// bad — copied configs drifting (three tsconfigs diverging — strictness varying per environment, behavior unportable)
// fix — extends chains (single source — deltas declared, drift red)
```

**Common confusion** — "per-env configs need independence" — environments need *deltas* (sourcemaps vs emit — independence via inheritance + declared deltas, not copies). "parity gates are bureaucracy" — parity gates preventing the most confusing failure class (green-here-red-there — 17/5.1 part 4 evidencing). "Docker builds exempt" — Docker builds *most* need parity (furthest from laptops — production configs audited hardest).

**Performance note** — inheritance zero-cost (config resolution — one base read; drift incidents hours of green-here-red-there debugging — cheapest prevention).

**Mentor note** — config-PR review: "delta or drift?" (declared deltas approved — undeclared differences rejected with extends-suggestions).
