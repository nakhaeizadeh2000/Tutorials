## 1.3. Observability hooks error reporting and health

### 1) **Typed error reporting** (taxonomies flowing to reporters, sampled not dumped)

**Definition** — *typed reporting*: 15/2.2 error hierarchies (`AppError` → domain errors, `cause` chains) serialized into reporter payloads (Sentry/Datadog/OTel — name/message/cause/fingerprint as typed fields, PII scrubbed by schema — reporting contracts versioned like APIs). *Sampled*: high-volume expected errors sampled (rates configured — 100% fatals, 1% transient 503s — reporter budgets respected, signal preserved).

**What problem it solves / history** — string-dumped errors (`report(String(e))` — taxonomies flattened, causes lost, PII leaked into logs, reporter quotas blown by retry storms): typed payloads preserving causality (aggregations by class — fingerprints stable, triage by hierarchy) + sampling bounding volume (signal affordable at scale).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), report `Error` instances (never strings — classes + causes flowing); fingerprint by `(name, site)` (stable aggregation — message-varies grouping); sample by severity (fatals always, transients fractionally — budgets configured, reviewed quarterly).

**Runnable example** — causality preserved (good vs bad, `tsc --strict`):

```typescript
// good — typed report payload (hierarchy + cause flowing — aggregation by class)
export {}; // module marker (consistent module scope across fences)
class AppError extends Error {
  constructor(msg: string, public code: string, options?: { cause?: unknown }) {
    super(msg, options); this.name = "AppError"; // cause chain (15/2.2 — causality preserved into reporters)
  }
}
interface Report { name: string; code: string; cause: string } // payload contract (versioned — reporters typed like APIs)
function toReport(e: AppError): Report {
  return { name: e.name, code: e.code, cause: e.cause instanceof Error ? e.cause.message : String(e.cause ?? "none") }; // narrowed cause (unknown handled — PII scrubbed by schema, not by hope)
}
const r = toReport(new AppError("down", "E503", { cause: new Error("conn") }));
console.log(`${r.name}:${r.code}:${r.cause}`); // AppError:E503:conn — typed reporting (causality flowing — triage by hierarchy)
// bad — string dumps (report(String(e)) — classes flattened, causes lost, PII leaking, quotas blown)
// fix — payload contracts (taxonomies flowing — aggregation stable, volume sampled)
```

**Common confusion** — "report everything" — reporting budgets exist (quotas + noise — fatals always, transients sampled; undifferentiated volume drowning signal). "causes are verbose" — causes *diagnose* (chain shortened triage from hours to minutes — verbosity priced against incidents). "fingerprints need ML" — fingerprints need `(name, site)` (stable keys — aggregation working without intelligence).

**Performance note** — reporting serialization microseconds per error (rare path — exceptions exceptional; hot-path failures as `Result` per 15/2.1, reported as metrics not errors).

**Mentor note** — error-PR review: "reportable?" (classes + causes flowing — string-dumps rejected like `any`).

### 2) **Health and readiness types** (dependency checks typed, degraded modeled)

**Definition** — *health typing*: readiness/liveness probes with typed results (`Health = { ok: true } | { ok: false; degraded: Service[]; reason: string }` — degraded states *modeled*, not booleaned): orchestrators routing on shape (degraded → shed load, down → restart — responses driving automation, not dashboards alone). Dependency checks per backing service (DB/queue/cache — each check typed, timeouts bounded per 18/2.2).

**What problem it solves / history** — boolean health (`/health → 200` always — degraded dependencies invisible, orchestrators blind, cascading failures undetected until users report): modeled degradation driving automation (shed/shift/restart by shape — health as control plane, not status page).

**Modern guidance** — model three states (healthy/degraded/down — booleans insufficient; degraded shedding load, down restarting); bound check timeouts (2.2 signals — checks never hanging the probe); expose per-dependency detail (shapes typed — on-call reading structure, not tea leaves).

**Runnable example** — degradation modeled (good vs bad, `tsc --strict`):

```typescript
// good — health as discriminated union (degraded modeled — automation routing on shape)
export {}; // module marker (consistent module scope across fences)
type Health = { ok: true } | { ok: false; degraded: string[]; reason: string }; // three states in two members (healthy vs degraded/down — shape driving automation)
async function checkHealth(deps: Record<string, boolean>): Promise<Health> {
  const down = Object.entries(deps).filter(([, up]) => !up).map(([name]) => name); // per-dependency detail (typed — on-call reading structure)
  return down.length === 0 ? { ok: true } : { ok: false, degraded: down, reason: `${down.length}-down` };
}
const h = await checkHealth({ db: true, queue: false });
console.log(h.ok ? "healthy" : `degraded:${h.degraded.join(",")}`); // degraded:queue — modeled health (shed/shift/restart by shape — control plane, not status page)
// bad — boolean health (200-always — degraded invisible, orchestrators blind, cascades user-reported)
// fix — union health (states modeled — automation routing, on-call reading structure)
```

**Common confusion** — "health checks need no types" — health *drives automation* (shapes contractual — orchestrators depending; untyped health stringly-typed control planes). "liveness equals readiness" — liveness (restart me?) vs readiness (send traffic?) differing (degraded = alive-but-unready: liveness green, readiness red — states distinguished, actions differing). "checks can hang" — checks bounded (timeouts per 18/2.2 — hanging probes failing closed, never open).

**Performance note** — health checks milliseconds (bounded — probes cheap; expensive deep-checks cached on intervals, not per-probe).

**Mentor note** — deploy review: "degraded path demoed?" (three states exercised — boolean health rejected like untyped errors).

### 3) **Graceful-shutdown phases** (stop drain exit, SIGTERM tested)

**Definition** — *shutdown phases* (18/3.3 drains practiced at release): stop-accepting (health flipping unready — load balancers draining) → drain in-flight (tracked work completing — 18/3.3 inventory patterns, bounded by timeouts) → exit (process terminating — exit codes typed: 0 clean, 1 error — orchestrators reading codes, not logs). *SIGTERM tested* (17/2.3 doubles driving handlers — drains asserted: in-flight completing, bounds holding, exit timely).

**What problem it solves / history** — SIGTERM-ignorant deploys (5.1 incident 4: 400 checkouts severed — exit-during-flight, partial writes, severed responses): phased shutdown completing work before exit (deploys graceful — users unaffected, data consistent; 18/3.3 lifetime honesty at release scale).

**Modern guidance** — implement three phases (stop → drain → exit — each awaited, each bounded); test handlers (SIGTERM doubles per 17/2.3 — drains asserted, bounds verified); monitor shutdown duration (histograms — phases timed, regressions alerted like latency).

**Runnable example** — phased exit (good vs bad, `tsc --strict`):

```typescript
// good — shutdown phases typed (stop, drain, exit — graceful as phased procedure)
export {}; // module marker (top-level await below needs module scope)
let live = 0;
async function serve(): Promise<string> {
  live++; // admission inventoried (drain observing — work counted)
  await new Promise<void>((r) => setTimeout(r, 1));
  live--;
  return "served";
}
async function shutdown(): Promise<number> {
  // phase 1: stop-accepting (health unready — balancers draining; modeled, not shown)
  while (live > 0) { await new Promise<void>((r) => setTimeout(r, 1)); } // phase 2: drain (in-flight completing — bounded by 18/2.2 timeouts in production)
  return 0; // phase 3: exit code (0 clean — orchestrators reading codes)
}
console.log(await serve(), await shutdown()); // served 0 — phased shutdown (work completing before exit — deploys graceful)
// bad — exit-during-flight (process.exit mid-request — 400 severed checkouts per 5.1, partial writes, retry storms)
// fix — three phases (stop → drain → exit — shutdown as typed procedure, tested per 17/2.3)
```

**Common confusion** — "orchestrators handle shutdown" — orchestrators *signal* (SIGTERM); apps *drain* (in-flight completing — unhandled signals defaulting to immediate exit, work severed). "drains delay deploys" — drains bound (timeouts per 18/2.2 — graceful within seconds; unbounded drains the actual delay risk, bounded drains the fix). "shutdown untestable" — SIGTERM doubles testing handlers (17/2.3 pattern — drains asserted like any async path).

**Performance note** — drain latency = slowest in-flight op (bounded — timeouts composing per 18/2.2; shutdown histograms monitored like request latency).

**Mentor note** — deploy-readiness demo: SIGTERM path exercised live (phases timed — undemoed shutdowns failing at 3am per 18/3.3).
