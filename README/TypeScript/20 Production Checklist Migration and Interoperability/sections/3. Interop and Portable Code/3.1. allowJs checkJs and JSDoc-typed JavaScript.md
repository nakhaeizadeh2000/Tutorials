## 3.1. allowJs checkJs and JSDoc-typed JavaScript

### 1) **`allowJs` + `checkJs` semantics** (JS in-program, loosely or strictly checked)

**Definition** — *semantics*: `allowJs: true` admitting `.js` into the program (imports crossing freely — 2.1 bridging); `checkJs: false` (JS parsed, loosely checked — syntax + obvious errors only); `checkJs: true` (JS fully checked — JSDoc types enforced, `noImplicitAny` applying to unannotated JS); `declaration` emitting `.d.ts` from JS (typed-JS publishing declarations — consumers receiving types from JSDoc'd sources).

**What problem it solves / history** — JS/TS program splits (separate pipelines — imports unresolvable across languages, editor jumps dying at boundaries): unified programs (one `tsc` — cross-language navigation, refactoring, checking; boundaries inventoried per 2.1, tightened per file).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), `allowJs` during migrations (bridging — 2.1 playbook); `checkJs` on JSDoc'd files (verification — annotations enforced, see part 2); `declaration` for published JS (consumers typed — JSDoc'd libraries shipping `.d.ts` without TS sources).

**Runnable example** — unified programs (good vs bad, `tsc --strict`):

```jsonc
// good — bridge semantics (mixed programs — imports crossing, strictness per language)
// tsconfig.bridge.json (labeled config doc): { "compilerOptions": { "allowJs": true, "checkJs": false,
//   "strict": true, "outDir": "lib" } }
// (TS strict, JS loose — boundaries inventoried per 2.1; JSDoc'd JS verified where annotated per part 2)
```

```typescript
// good — TS consuming bridged JS shapes (unified program — cross-language imports typed at the TS side)
export {}; // module marker (consistent module scope across fences)
interface JsShape { id: string } // TS-side contract (JS modules shaped here until converted — boundary inventoried, tightening scheduled per 2.1 loops)
export function useJsShape(s: JsShape): string { return s.id; } // consumption typed (TS strictness guarding JS-origin values — boundaries honest)
console.log(useJsShape({ id: "j1" })); // j1 — unified programs (imports crossing — strictness per language, verification total)
// bad — split pipelines (JS/TS compiled separately — cross imports unresolvable, jumps dying, checks partial)
// fix — allowJs programs (one tsc — navigation, refactoring, checking unified across languages)
```

**Common confusion** — "`allowJs` weakens TS" — `allowJs` *admits* JS (TS files unaffected — strictness per language; weakening only where JS stays unconverted, inventoried per 2.1). "`checkJs` equals conversion" — `checkJs` *verifies* JSDoc (safety — conversion adding ergonomics per 2.1 part 3; verified JS valuable indefinitely). "declarations need TS sources" — `declaration` emits from JSDoc'd JS (typed-JS libraries publishing types — sources staying JS by choice, see part 3 graduation).

**Performance note** — JS checking cheaper than TS (loose by default — program cost ∝ annotation density; `checkJs` full on JSDoc'd files — verification priced where value is).

**Mentor note** — bridge review: "allowJs + inventory?" (bridging with backlogs — programs unified, tightening scheduled; bridges without loops stagnating per 2.1).

**Cross-links** — bridging playbook → [2.1. JS to TS](<../2. Migration Playbooks/2.1. JavaScript to TypeScript file by file.md>); JSDoc syntax → part 2 below (same leaf — annotation vocabulary).

### 2) **JSDoc type syntax** (param returns typedef template, verified annotations)

**Definition** — *JSDoc vocabulary*: `@param {T} name` (parameter types), `@returns {T}` (return types), `@typedef`/`@property` (object shapes), `@template T` (generics), `@type {T}` (variable types), `@satisfies`/`@import` (contracts/imports) — verified under `checkJs` (annotations enforced — wrong args erroring like TS; unannotated positions `any`-implicit per `noImplicitAny`).

**What problem it solves / history** — untyped JS churn (holdouts from 2.1 part 3 — edits unprotected, refactors blind): JSDoc safety (hovers, call-checks, renames — 80% migration value at 20% cost; graduation mechanical per 2.1 part 3 when complexity strains syntax).

**Modern guidance** — annotate hot JS (churn demanding safety — params/returns first, typedefs for shapes, templates where genericity exists); verify with `checkJs` (annotations enforced — decorative JSDoc rejected by verification); graduate past complexity (nested generics/conditionals straining syntax → `.ts` per part 3 criteria).

**Runnable example** — verified annotations, shown as TS equivalents (good vs bad, `tsc --strict`):

```typescript
// good — JSDoc-mapped signatures (vocabulary 1:1 — params/returns/typedefs verified)
// (real .js form — checked via checkJs:
// /** @typedef {{ id: string }} JsUser */
// /** @param {JsUser} u @returns {string} */
// function label(u) { return u.id; })
export {}; // module marker (consistent module scope across fences)
interface JsUser { id: string } // typedef equivalent (shapes named — JSDoc @typedef mapping directly)
export function label(u: JsUser): string { return u.id; } // param/returns equivalent (@param/@returns mapping — verification identical under checkJs)
console.log(label({ id: "j" })); // j — vocabulary mapped (JSDoc↔TS 1:1 — graduation mechanical, safety immediate)
// bad — decorative JSDoc (annotations unchecked — checkJs off, wrong args passing, safety theater)
// fix — checkJs verification (annotations enforced — decorative rejected, safety real)
```

```typescript
// good — generic JSDoc (templates — genericity expressed, graduation threshold visible)
export {}; // module marker (consistent module scope across fences)
// (real .js form: /** @template T @param {T[]} xs @returns {T|undefined} */ — checked via checkJs)
export function head<T>(xs: T[]): T | undefined { return xs[0]; } // template equivalent (@template mapping — genericity straining JSDoc past this complexity per part 3)
console.log(head([5])); // 5 — templates working (generics expressible — graduation when conditionals/mapped join per part 3)
// bad — any-typed JS generics (unannotated type params — implicit-any, call sites unchecked, churn unprotected)
// fix — @template annotations (genericity stated — verification covering generic JS like generic TS)
```

**Common confusion** — "JSDoc second-class" — JSDoc *verified* (checkJs enforcing — safety equal for expressible shapes; ergonomics differing past complexity thresholds). "templates equal TS generics" — templates covering *simple* genericity (params/returns; conditional/mapped shapes straining syntax — graduation criteria per part 3). "JSDoc unmaintainable" — JSDoc *greppable* (mechanical syntax — codemods updating; untyped JS unmaintainable, JSDoc'd JS maintained).

**Performance note** — JSDoc checking per annotated file (proportional — value where churn is; unannotated files unchecked-cheap).

**Mentor note** — holdout checklist: "JSDoc'd + checkJs'd, or conversion scheduled?" (churn protected one way or the other — untyped churn rejected).

### 3) **Graduation criteria** (JSDoc sufficiency vs TS payoff, complexity thresholds)

**Definition** — *graduation*: converting JSDoc'd `.js` to `.ts` when complexity crosses thresholds — nested generics, conditional/mapped shapes, declaration emit needs, contributor ergonomics (TS-native contributors slowed by JSDoc verbosity), ecosystem expectations (published packages shipping `.d.ts` from TS sources preferred). Sufficiency below thresholds (params/returns/typedefs/templates — JSDoc serving indefinitely, no graduation pressure).

**What problem it solves / history** — premature conversion (simple JSDoc'd files converted for uniformity — toil without payoff) vs overdue holdouts (conditional-heavy JSDoc unmaintainable — syntax straining, verification weakening): thresholds deciding per file (complexity measured, ergonomics weighed — graduation scheduled, never vibed).

**Modern guidance** — graduate on: conditional/mapped shapes in JSDoc (syntax straining — TS ergonomics paying), published `.d.ts` needs (sources preferred per 12/3.1 derive-rules), contributor friction (TS-native teams slowed — verbosity taxing). Keep JSDoc where: shapes simple (params/returns/typedefs serving), churn low (stable utilities — conversion toil exceeding safety delta).

**Runnable example** — threshold decisions (good vs bad, `tsc --strict`):

```typescript
// good — graduated complexity (conditional shapes — TS ergonomics paying past threshold)
export {}; // module marker (consistent module scope across fences)
export function first<T>(xs: T[]): T | undefined {
  return xs[0]; // plain generic (below threshold alone — graduate when conditionals/mapped join per criteria)
}
type Defined<T> = T extends undefined ? never : T; // conditional (threshold-crossing shape — JSDoc straining, TS paying)
type D = Defined<string | undefined>; // string (graduation evidence — shapes beyond JSDoc vocabulary living here)
console.log(first([9]), "graduated"); // 9 graduated — thresholds applied (complexity deciding — scheduled, never vibed)
// bad — thresholdless conversion ("everything .ts eventually" — toil without payoff on simple stable files)
// fix — criteria per file (complexity + ergonomics + publishing — graduation scheduled where thresholds met)
```

**Common confusion** — "graduation inevitable" — graduation *conditional* (simple stable JSDoc serving indefinitely — inevitability vibes, thresholds decisions). "JSDoc files are tech debt" — *unverified* JSDoc is debt (decorative — checkJs distinguishing debt from safety per part 2). "thresholds bureaucratic" — thresholds *focusing* (conversion toil where payoff is — effort concentrated, uniformity theater deleted).

**Performance note** — conversion toil hours per file (payoff-gated — thresholds ensuring returns; uniform conversion toiling without returns on simple files).

**Mentor note** — file review: "past threshold?" (complexity/ergonomics/publishing — graduation scheduled on yes, JSDoc respected on no).
