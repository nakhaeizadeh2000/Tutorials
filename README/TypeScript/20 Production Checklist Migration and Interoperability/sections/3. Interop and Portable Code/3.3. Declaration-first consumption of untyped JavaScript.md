## 3.3. Declaration-first consumption of untyped JavaScript

### 1) **Ambient declarations as trust boundaries** (minimal honest shims, deletion-on-arrival)

**Definition** — *trust boundaries*: `declare module "legacy-lib" { ... }` shims asserting the *minimal used surface* (imported names only — every declaration a claim the team defends; unused names undeclared — surface minimal by construction) with *deletion-on-arrival* (shims carrying TODO + upstream-issue links — real types arriving deleting shims same-PR, see 12/2.3 resolution-order rules).

**What problem it solves / history** — `any`-shimmed dependencies (whole libraries `any` — call sites unchecked, upgrades silently breaking: 5.1 incident 3's analytics-SDK class): minimal shims bounding lies (used surface typed — however narrowly; unused surface absent — upgrades breaking loudly at the shim, not silently at 40 call sites).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), shim minimally (used names only — honesty over completeness); link upstream issues (TODO + tracker — deletion scheduled, not hoped); test shimmed calls (17/2.1 typeof-pins on shimmed signatures — lies breaking tests first).

**Runnable example** — minimal honest shims (good vs bad, `tsc --strict`):

```typescript
// good — minimal shim (used surface only — honesty over completeness, deletion scheduled)
export {}; // module marker (consistent module scope across fences)
declare function legacyParse(raw: string): { ok: boolean }; // minimal ambient (used name only — TODO: replace with typed SDK per tracker #1234)
// (real form: declare module "legacy-lib" { export function legacyParse(raw: string): { ok: boolean } } — ambient module shim)
const r = legacyParse("x"); // consumed (surface minimal — upgrades breaking HERE, not at 40 call sites)
console.log(r.ok); // false — trust bounded (claims defended — unused surface absent by construction)
// bad — any-shimmed libraries (declare module "x": any — call sites unchecked, upgrades silently breaking everywhere)
// fix — minimal shims (used names typed — lies bounded, deletions scheduled with tracker links)
```

**Common confusion** — "complete shims safer" — complete shims *claim* unverified behavior (untested declarations — lies at scale; minimal shims claiming only used+tested surface). "shims permanent" — shims *transitional* (TODO + tracker + deletion-on-arrival — permanence requiring justification, see 12/3.2 fork-PR-replace exits). "shimmed code untestable" — shimmed calls pinned like mocks (17/2.1 typeof-pins — lies breaking tests first, upgrades loudly).

**Performance note** — shims zero-cost (declarations erased — 01/2.1); any-shims costing call-site checking everywhere (40 sites unchecked — incident-class exposure per untyped call).

**Mentor note** — shim review: "used names only? tracker linked? tests pinned?" (three questions — honesty, scheduling, verification per shim).

### 2) **Progressive precision** (shim to any-with-tests to precise, trust earned)

**Definition** — *precision ladder*: (1) minimal shim (used names, narrow types — trust thin); (2) `unknown`-ingesting wrappers (15/3.3 parse discipline — runtime validation discharging `unknown` into proven types); (3) precise community/vendor types (`@types/*`, bundled declarations — trust transferred to maintainers). Trust *earned* per rung (tests + versions evidencing — never assumed by popularity/star-count).

**What problem it solves / history** — hopeful `any` permanence (5.1 incident 3 — analytics SDK `any`-shimmed forever, payloads widening silently): ladders converting permanence into progression (rungs scheduled — precision deepening per quarter, trust transferring with evidence).

**Modern guidance** — climb per dependency value (hot paths precise first — usage-weighted precision, not alphabetical); wrap unknowns at boundaries (parse-don't-validate per 15/3.3 — validation discharging where shims end); transfer trust explicitly (vendored → DefinitelyTyped → bundled — each transfer reviewed, versions pinned).

**Runnable example** — trust earned per rung (good vs bad, `tsc --strict`):

```typescript
// good — parsed boundary over shims (unknown in, proven types out — 15/3.3 discipline where shims end)
export {}; // module marker (consistent module scope across fences)
declare function legacyFetch(id: string): unknown; // rung-1 shim (unknown-returning — honest about ignorance)
interface Item { id: string } // rung-2 precision (proven shape — validation discharging below)
function getItem(id: string): Item {
  const raw: unknown = legacyFetch(id); // unknown ingested (boundary — validation next, assumption never)
  if (typeof raw === "object" && raw !== null && "id" in raw && typeof raw.id === "string") {
    return { id: raw.id }; // narrowed (no casts — `in` + typeof refining to string, see 07/3.1 `in` narrowing)
  }
  throw new Error("bad item"); // rejected (unshaped payloads thrown — rung-2 precision earned, not assumed)
}
console.log(getItem("a").id); // a — progressive precision (shim → parse → proven — trust earned per rung)
// bad — hopeful any permanence (any-shimmed forever — payloads widening silently per 5.1 incident 3)
// fix — ladders (rungs scheduled — precision deepening quarterly, trust transferring with evidence)
```

**Common confusion** — "wrappers duplicate SDKs" — wrappers *validate* SDKs (boundaries proving — duplication-as-detection per 17/1.3; unwrapped trust hoping). "precision rungs bureaucratic" — rungs *schedule* trust (shim→parse→precise — permanence requiring justification, progression the default). "`as` after validation fine" — `as` after validation *usually* avoidable (`in`+`typeof` narrowing — casts signaling incomplete narrowing; audit each one).

**Performance note** — validation microseconds per boundary call (parse discipline — test-time + runtime cheap; hopeful-any costing incidents — asymmetry always favoring validation).

**Mentor note** — dependency review: "which rung?" (shim/parse/precise — rungs stated per untyped dep; permanence justifying like `any`).

### 3) **Fork-PR-replace exits** (upstreaming types, vendored sunsets, DT contributions)

**Definition** — *exits*: shim endpoints — (1) *fork* (vendored `@types`-style declarations in-repo — immediate precision, owned maintenance); (2) *PR* (DefinitelyTyped/upstream contributions — trust transferred to community, maintenance shared); (3) *replace* (dependency swapped for typed alternatives — ecosystem voting with feet). *Sunsets*: vendored shims deleted on upstream arrival (deletion-on-arrival per part 1 — exits completing, never lingering).

**What problem it solves / history** — permanent vendored shims (in-repo declarations rotting as upstreams evolve — drift silently, maintenance forgotten): exits converting vending into transition (fork now → PR next → replace/sunset on arrival — maintenance flowing toward owners, never pooling in consumers).

**Modern guidance** — fork for speed (vendored precision today — tracker-linked, sunset-scheduled); PR for sharing (upstream contributions — maintenance transferred, community reviewing); replace where ecosystem offers typed options (swap evaluated like all deps — migration cost vs shim-maintenance cost, see 2.2 sequencing thought applied to deps).

**Runnable example** — exits completing (good vs bad, `tsc --strict`):

```typescript
// good — vendored fork with sunset (immediate precision — owned maintenance, scheduled exit)
export {}; // module marker (consistent module scope across fences)
// vendored/shims/analytics.d.ts (fork — TODO(#1234): replace with @types/analytics when published, sunset Q1)
// (fork content: minimal used-surface declarations per part 1 — precision now, maintenance owned, exit dated)
export interface AnalyticsEvent { name: string } // forked contract (vendored — sunset scheduled, not hoped)
export function track(e: AnalyticsEvent): void { console.log(`track:${e.name}`); } // forked API (used surface — exits completing via PR/replace)
console.log("forked"); // forked — fork velocity (precision today — sunset dated, maintenance owned meanwhile)
// bad — permanent vending (shims rotting as upstreams evolve — drift silent, maintenance forgotten, exits never)
// fix — fork-PR-replace (transition, not residence — maintenance flowing to owners)
```

**Common confusion** — "forks fork maintenance burden" — forks *schedule* burden (sunset-dated — permanence the burden, transitions the relief). "PRs too slow" — PRs parallelize (vendored working meanwhile — fork now, PR next, replace on arrival; slowness costing nothing while forked). "replace churns deps" — replace *evaluated* (migration-vs-maintenance math — churn only where maintenance exceeds migration, see 2.2 sequencing).

**Performance note** — vendored declarations check-time like all types (budgeted per 19/1.2 — partitions equal); rotting shims costing drift-incidents (silence priced in postmortems).

**Mentor note** — shim age review: vendored shims older than 2 quarters need exit plans (PR opened, replace evaluated, or sunset dated — residence justifying like `any`).
