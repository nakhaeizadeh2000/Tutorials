## 3.2. Environment-portable code node browser edge

### 1) **Environment guards** (typeof narrowing selecting implementations per runtime)

**Definition** — *guards*: `typeof process !== "undefined"` (Node present), `typeof window !== "undefined"` (browser present), `typeof EdgeRuntime !== "undefined"` (edge present — `declare const EdgeRuntime: string | undefined` ambient per 12/2.2 patterns) — 07 narrowing mechanics selecting implementations (branches typed per environment — unreachable branches eliminated by bundlers via dead-code paths, see 13/2.x erasable notes).

**What problem it solves / history** — unconditional environment APIs (`process.env` in browser bundles — build-time crashes; `window` in Node SSR — runtime ReferenceErrors): guards selecting implementations (each branch environment-correct — bundlers pruning unreachable, types narrowing reachable).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), guard at seam modules (one `env.ts` per partition — detection centralized, branches reviewed together); prefer dependency injection over guards where seams allow (17/2.2 fakes proving portability — guards at edges, injection inside); declare exotic globals minimally (ambient per 12/2.3 — deletion-on-arrival when standardized).

**Runnable example** — guarded environments (good vs bad, `tsc --strict`):

```typescript
// good — centralized env detection (one seam — branches reviewed together, bundlers pruning)
export {}; // module marker (consistent module scope across fences)
declare const EdgeRuntime: string | undefined; // minimal ambient (12/2.3 trust boundary — standardized names preferred where they exist)
declare const process: { versions?: { node?: string } } | undefined; // minimal ambient (no @types/node in scope — shape declared, not installed)
export type Runtime = "node" | "browser" | "edge" | "unknown";
export function detectRuntime(): Runtime {
  if (typeof EdgeRuntime !== "undefined") return "edge"; // edge first (narrowest global — checked before wider ones)
  if (typeof process !== "undefined" && process.versions?.node) return "node"; // node (versions-guarded — bundler-defined process shims distinguished)
  if (typeof window !== "undefined") return "browser"; // browser (window presence — SSR-safe via typeof, never direct access)
  return "unknown";
}
console.log(detectRuntime()); // node — guards selecting (branches typed per environment — unreachable pruned by bundlers)
// bad — direct global access (window.location in shared code — SSR ReferenceErrors, edge crashes, unportable by construction)
// fix — typeof-guarded seams (detection centralized — direct access unrepresentable outside env.ts)
```

**Common confusion** — "`typeof` guards are boilerplate" — guards are *seams* (one module — branches together; scattered `typeof window` ternaries the actual boilerplate). "bundlers handle environments" — bundlers *prune* guarded branches (dead-code elimination needing guards — unguarded code unprunable, shipped everywhere). "process.version checks suffice" — bundler `process` shims existing (define-provided — `versions?.node` distinguishing real Node from shims).

**Performance note** — guards nanoseconds (typeof reads — detection once, cached per module lifetime; branches pruned at build — zero runtime cost post-bundle).

**Mentor note** — shared-code review: environment globals outside `env.ts` rejected (detection centralized — direct access unrepresentable, portability structural).

### 2) **Lib-split partitions** (per-runtime lib, mistakes loud, shared portable)

**Definition** — *lib splits* (18/3.1 applied at release): per-runtime `tsconfig`s (Node: `ESNext` + `@types/node`; browser: `ESNext` + `DOM`; edge: `ESNext` + `DOM` minimal + workers-types) + *shared* partition (portable code — no environment globals, `lib: ESNext` bare — importing into every runtime; violations failing in all consumers identically). Mistakes loud (Node API in shared — every consumer red, not just one runtime).

**What problem it solves / history** — shared-code environment leaks (`fs` imported in "shared" utils — browser builds failing, edge crashing): lib splits surfacing leaks where introduced (shared partition compiling under bare `ESNext` — environment names unresolvable, leaks red at authoring, not at browser-build time).

**Modern guidance** — three-plus-one layout (node/browser/edge apps + shared partition — runtimes with libs, shared bare); shared importing nothing environmental (pure TS + injected seams per 17/2.2 — portability by construction); CI compiling all four (leaks red somewhere always — shared leaks red everywhere, the loudest signal).

**Runnable example** — splits surfacing leaks (good vs bad, `tsc --strict`):

```jsonc
// good — three-plus-one libs (runtimes with libs, shared bare — leaks red at authoring)
// tsconfig.shared.json (labeled config doc): { "compilerOptions": { "lib": ["ESNext"] } }
// tsconfig.node.json (labeled config doc): { "extends": "./shared", "compilerOptions": { "lib": ["ESNext"], "types": ["node"] } }
// tsconfig.browser.json (labeled config doc): { "extends": "./shared", "compilerOptions": { "lib": ["ESNext", "DOM"] } }
// (shared under bare ESNext — fs/window unresolvable there, leaks red where introduced)
```

```typescript
// good — portable shared code (no environment names — seams injected, runtimes abstracted)
export {}; // module marker (consistent module scope across fences)
export interface Clock { now(): number } // seam (injected — 17/2.2 FixedClock pattern at partition scale)
export function isStale(clock: Clock, at: number, ttl: number): boolean {
  return clock.now() - at > ttl; // portable (Date.now never referenced — runtimes providing clocks, shared consuming seams)
}
console.log(isStale({ now: () => 1000 }, 0, 500)); // true — portability constructed (seams injected — environment names absent by design)
// bad — environment imports in shared (fs/window in "shared" — browser/edge builds failing, leaks discovered downstream)
// fix — lib splits (bare-ESNext shared — leaks red at authoring, mistakes loud in all consumers)
```

**Common confusion** — "splits quadruple configs" — splits *inherit* (extends chains per 1.2 part 3 — one base, three deltas; configuration single-sourced, deltas declared). "shared bare is restrictive" — bare shared *is* portability (restrictions defining the property — environment names absent proving portable). "CI × 4 is slow" — four small programs checking in parallel (faster than one mega-program — 19/2.3 matrices + up-to-date skipping compounding).

**Performance note** — split programs smaller each (check-time ∝ partition — parallel CI faster than monolithic; leaks caught at authoring — downstream build failures deleted).

**Mentor note** — shared-PR review: "environment names?" (fs/window/process in shared diffs rejected — seams injected, runtimes abstracted).

### 3) **Portable abstractions** (storage clock network seams, fakes proving)

**Definition** — *portable abstractions*: environment capabilities behind interfaces (Storage `get/set`, Clock `now`, Fetch `request`, Random `bytes` — seams injected per 17/2.2, fakes proving substitutability per 17/2.2 part 3's behavesLike suites): shared code depending on seams (runtimes implementing — Node `fs`-backed storage, browser `localStorage`-backed, edge KV-backed; portability tested, not hoped).

**What problem it solves / history** — capability-coupled shared code (direct `fetch`/`crypto`/`fs` calls — untestable without environments, unportable without rewrites): seams decoupling (shared logic pure over interfaces — environments adapting at edges, fakes substituting in suites — 17/2.2 economics at partition scale).

**Modern guidance** — seam every environment capability (storage/clock/network/random — interfaces in shared, implementations per runtime); prove with behavesLike suites (contract suites per 17/2.2 part 3 — every runtime implementation passing identical assertions); default to Web-standard seams where they exist (`fetch`, `crypto.subtle`, `Blob` — runtimes converging, seams thinning over time).

**Runnable example** — capabilities seamed (good vs bad, `tsc --strict`):

```typescript
// good — storage seam (shared logic pure — runtimes adapting at edges, fakes substituting in suites)
export {}; // module marker (consistent module scope across fences)
export interface KV { get(k: string): string | null; set(k: string, v: string): void } // seam (capability interfaced — environments implementing)
class MemKV implements KV {
  private m = new Map<string, string>();
  get(k: string): string | null { return this.m.get(k) ?? null; }
  set(k: string, v: string): void { this.m.set(k, v); }
}
export function cached(kv: KV, k: string, make: () => string): string {
  const hit = kv.get(k);
  if (hit !== null) return hit; // shared logic (pure over seams — portable by construction)
  const v = make(); kv.set(k, v); return v;
}
console.log(cached(new MemKV(), "a", () => "fresh")); // fresh — seamed capabilities (fakes proving — runtimes adapting at edges)
// bad — direct capability calls (localStorage in shared — Node/edge crashing, suites needing environments)
// fix — seams + behavesLike (capabilities interfaced — portability tested per runtime implementation)
```

**Common confusion** — "seams over-abstract" — seams abstract *capabilities* (5–6 interfaces per app — storage/clock/network/random/timers; domain logic untouched, edges adapted). "Web standards remove seams" — standards *thin* seams (fetch converging — runtimes still differing at edges: Node fs, browser storage, edge KV; seams shrinking, never vanishing). "fakes per runtime double work" — behavesLike suites *share* work (one contract suite — N implementations asserting identically per 17/2.2).

**Performance note** — seams one indirection per capability call (nanoseconds — inlining candidates; portability dividends quarters of unblocked runtimes).

**Mentor note** — capability review: "seam or direct?" (environment capabilities seamed — direct calls rejected outside runtime partitions).
