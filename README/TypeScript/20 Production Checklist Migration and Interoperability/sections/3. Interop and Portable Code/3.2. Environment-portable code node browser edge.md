## 3.2. Environment-portable code node browser edge

### 1) **Select capabilities and test the actual hosts**

A runtime name is a clue about capabilities, not a proof. Window is absent in browser workers, process can be shimmed, and an ambient declaration does not install an edge-specific global. A typeof guard can avoid reading an absent binding, but it does not prove the API works, confer permission or guarantee a bundler removes the other branch. Prefer explicit wiring where the application already knows its host, and check a capability when that capability is the actual requirement.

Portability has several contracts: accepted source, module loading, available APIs, permissions and behavior. A common interface describes selected operations; a fake checks the model it implements. Evidence from one host cannot certify another host's adapter or service. The [actual fake contracts](<../../../17 Testing Types/sections/2. Typed Test Doubles/2.2. Spies stubs and fakes over generics.md>) explain that boundary. Here the new application runs one shared cache contract in Node and a real browser.

Use TypeScript **7.0.2**, Node **20.20.2**, npm **10.8.2**, @types/node **20.19.43**, Google Chrome **151.0.7922.173** and Python **3.14.4**, verified on Linux 2026-10-17. Chrome and Python serve only the local browser test. No edge provider or deployment is tested. Create src in a disposable directory and save `package.json`:

```json
{"name":"portable-contract","version":"1.0.0","private":true,"devDependencies":{"@types/node":"20.19.43"}}
```

Save `tsconfig.base.json`:

```json
{
  "compilerOptions": {
    "strict": true,
    "target": "es2022",
    "module": "nodenext",
    "lib": ["es2022"],
    "types": [],
    "rootDir": "src",
    "noEmitOnError": true
  }
}
```

Save `tsconfig.shared.json`, `tsconfig.node.json` and `tsconfig.browser.json` respectively:

```json
{"extends":"./tsconfig.base.json","compilerOptions":{"noEmit":true},"files":["src/shared.mts","src/contract.mts"]}
```

```json
{"extends":"./tsconfig.base.json","compilerOptions":{"types":["node"],"outDir":"dist-node"},"files":["src/shared.mts","src/contract.mts","src/node.mts"]}
```

```json
{"extends":"./tsconfig.base.json","compilerOptions":{"lib":["es2022","dom"],"outDir":"dist-browser"},"files":["src/shared.mts","src/contract.mts","src/browser.mts"]}
```

The separate shared check deliberately uses types: [] so installed Node globals do not enter automatically. This limits ambient assumptions, not arbitrary import behavior, assertions or runtime availability. The [library/runtime owner](<../../../18 Async Types and Standard Library/sections/3. Standard Library in Practice/3.1. lib settings and built-in async types.md>) demonstrates why library declarations do not install implementations.

### 2) **Run the same behavior contract through two actual adapters**

Save `src/shared.mts`:

```typescript
export interface TextStore {
  read(key: string): Promise<string | undefined>;
  write(key: string, value: string): Promise<void>;
}
export async function loadOrCreate(store: TextStore, key: string, make: () => string): Promise<string> {
  const hit = await store.read(key);
  if (hit !== undefined) return hit;
  const value = make();
  await store.write(key, value);
  return value;
}
```

Promise results allow an adapter whose storage operations are asynchronous. An empty string is a present value, not a miss. This algorithm makes no atomicity or deduplication promise: concurrent misses can both call make and write. Storage errors reject the returned promise; an interface does not erase them. It is I/O through a supplied capability, not a pure function merely because globals are absent.

Save the reusable test `src/contract.mts`:

```typescript
import { loadOrCreate, type TextStore } from "./shared.mjs";
export async function exercise(store: TextStore, key: string): Promise<void> {
  if (await store.read(key) !== undefined) throw new Error("contract needs a fresh key");
  let made = 0;
  const first = await loadOrCreate(store, key, () => { made++; return ""; });
  const second = await loadOrCreate(store, key, () => { made++; return "wrong"; });
  if (first !== "" || second !== "" || made !== 1 || await store.read(key) !== "") {
    throw new Error("empty-string cache contract failed");
  }
}
```

Save `src/node.mts`:

```typescript
import { exercise } from "./contract.mjs";
import type { TextStore } from "./shared.mjs";
const values = new Map<string, string>();
const store: TextStore = {
  async read(key) { return values.get(key); },
  async write(key, value) { values.set(key, value); }
};
await exercise(store, "lesson-key");
console.log("Node memory contract verified");
```

This adapter provides process-local memory, not persistence. Save `src/browser.mts`:

```typescript
import type { TextStore } from "./shared.mjs";
export function browserStore(storage: Storage): TextStore {
  return {
    async read(key) { return storage.getItem(key) ?? undefined; },
    async write(key, value) { storage.setItem(key, value); }
  };
}
```

The browser adapter translates localStorage's null miss into the interface's undefined miss. Wrapping its synchronous methods in async functions supplies the promised result form; it does not make the underlying storage nonblocking. The [HTML storage standard](https://html.spec.whatwg.org/multipage/webstorage.html#the-localstorage-attribute) describes origin-scoped storage and policy failures. Access or writes can fail; handle those according to the application's contract rather than promising every browser always permits persistence.

Save `browser.html` in the root:

```html
<!doctype html>
<meta charset="utf-8">
<title>Portable storage contract</title>
<output id="result">RUNNING</output>
<script type="module">
import { browserStore } from "./dist-browser/browser.mjs";
import { exercise } from "./dist-browser/contract.mjs";
const result = document.getElementById("result");
const key = `typescript-lesson-${crypto.randomUUID()}`;
try {
  await exercise(browserStore(window.localStorage), key);
  result.textContent = "PASS";
} catch (error) {
  result.textContent = `FAIL: ${String(error)}`;
} finally {
  window.localStorage.removeItem(key);
}
</script>
```

Build and run the nonbrowser checks:

```bash
npm install --ignore-scripts --no-audit --no-fund
tsc -p tsconfig.shared.json
tsc -p tsconfig.node.json
tsc -p tsconfig.browser.json
node dist-node/node.mjs
```

All exit 0; Node prints `Node memory contract verified`. Start the local static server in another terminal from the same root:

```bash
python3 -m http.server 8765 --bind 127.0.0.1
```

Open http://127.0.0.1:8765/browser.html in Chrome and observe PASS. The verified automated Linux path used a fresh temporary profile and checked the actual returned page state:

```bash
ts_port_profile=$(mktemp -d)
google-chrome --headless=new --no-first-run --user-data-dir="$ts_port_profile" --virtual-time-budget=2000 --dump-dom http://127.0.0.1:8765/browser.html > browser-result.html
node --input-type=module -e 'import {readFileSync} from "node:fs"; if (!readFileSync("browser-result.html","utf8").includes("<output id=\"result\">PASS</output>")) throw new Error("browser contract failed"); console.log("Chrome storage contract verified");'
rm -rf "$ts_port_profile"
```

The assertion prints `Chrome storage contract verified`. Chrome's process exit alone would not prove the page's contract passed, since a page can render FAIL while Chrome exits 0. Stop the static server after testing. The test only removes its own generated key/profile; it needs no access to an existing browsing profile.

### 3) **Challenge ambient and behavioral portability separately**

Temporarily append `export const nodeVersion = process.version;` to shared.mts. The independent shared and browser checks fail for an unavailable process declaration, while the Node program still checks. An environment leak therefore need not fail every consumer identically. Restore the file and rebuild. Similarly a DOM global in shared can pass a DOM-enabled consumer while failing the isolated shared check. An interface, import policy and runtime test each add different evidence.

For an actual adapter regression, change the browser read expression from `storage.getItem(key) ?? undefined` to `storage.getItem(key) || undefined`. Checking still passes, but the browser contract displays FAIL because the stored empty string is treated as missing. The DOM assertion exits 1. Restore the nullish mapping, rebuild and rerun to get PASS. The Node memory contract remains green throughout this browser-only error, showing why a fake or another host cannot certify that adapter.

For an edge target, identify the provider and its real APIs, compatibility settings, bindings and error/consistency behavior. [Cloudflare's runtime overview](https://developers.cloudflare.com/workers/runtime-apis/) describes web-interoperable APIs, a subset of Node compatibility and compatibility dates/flags. DOM typings or a fabricated EdgeRuntime declaration are not substitutes for those contracts. A remote key/value binding might fit the async shape above while offering different consistency or failure behavior. Add the provider's actual adapter, appropriate types and relevant local/deployed tests before claiming support. This fixture establishes Node memory and the stated Chrome origin case only.

### 4) **Common confusion**

A common signature does not make persistence, permission, timing, concurrency or consistency identical. A Map and browser localStorage pass the selected sequential absence/empty-value contract but have different storage lifetimes and operational behavior. A fake's green result adds no evidence about an unexecuted browser or edge adapter.

Using only ECMAScript declarations reduces accidental host assumptions, but does not prove portability. types: [] is deliberate because visible ambient packages can otherwise widen available names. A typeof guard prevents particular absent-name reads; it is neither a universal runtime detector nor a dead-code-elimination guarantee.

### 5) **Performance note**

No host speed, checking-speed or adapter-indirection benchmark was run. async wrappers do not convert synchronous localStorage operations into nonblocking storage. Split programs may repeat checking, and parallel execution can compete for resources. Introduce an abstraction where it clarifies a needed contract; neither a fixed number of seams nor banning every direct standard API improves performance by itself.

### 6) **Mentor note**

Ask the learner why changing nullish to truthy miss detection passes checking but fails only the browser contract. A sound answer tracks the empty string through the actual adapter and recognizes the limits of the Node result.

Then add the process leak and ask which configs fail and why. Finish by asking what is still missing for a named edge provider: relevant implementation, compatibility/bindings, failure semantics and actual host evidence. Reward a bounded support claim rather than treating the word “shared” or a matching interface as proof.
