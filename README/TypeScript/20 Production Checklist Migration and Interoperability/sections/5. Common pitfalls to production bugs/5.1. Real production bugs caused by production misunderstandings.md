### 1) **Advisory packaging gate shipped `any` to every consumer** (attw warned, release proceeded)

**Definition** — the incident: a minor release's `exports` map omitted the `types` condition on one subpath (copy-paste from a JS-only example — 12/3.3 wiring rules violated): `attw --pack` *warned* (advisory gate — warnings non-blocking by policy): release proceeded (pressure + green unit tests): every consumer resolving `any` for that subpath (downstream `any`-infection at scale — discovered via consumer issues, fixed by patch + policy promoting packaging warnings to blockers).

**What problem it solves / history** — advisory packaging gates (warnings shippable — humans overriding under pressure): blockers holding under pressure (1.1 part 2 policy — packaging red blocking publish; warnings-to-blockers the incident's one-line generalization).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), packaging gates blocking (publish conditional — pipeline YAML enforcing, 1.1 part 2 sequence); gate logs pasted in release PRs (evidence — 16/2.3 mentor note); policy retro after every warning-shipped incident (warnings promoted — advisories shrinking to zero over time).

**Runnable example** — blockers holding (good vs bad, `tsc --strict`):

```text

// release job (labeled CLI doc — ordered, conditional):
// $ npm pack && npx attw --pack ./pkg/*.tgz && npx publint ./pkg/*.tgz && npm publish ./pkg/*.tgz
// (publish conditional — gates green, and only then; pressure proceduralized per 1.1)
```

```typescript
// good — subpath coherence pre-verified (every exports condition serving types — proven on tarball)
export {}; // module marker (consistent module scope across fences)
export interface SubApi { ping(): string } // subpath surface (types condition present — attw verifying per importer kind)
```

**Common confusion** — "packaging warnings are minor" — packaging warnings *are* consumer breakage (any-infection at scale — severity equal to red unit tests, see 17/4.1 part 4 parity). "humans judge warnings better" — humans override warnings *under pressure* (judgment degrading exactly when gates matter — pipelines holding where humans fold). "one subpath minor" — subpaths consumed independently (one broken condition breaking its consumers fully — severity per affected consumer, not per package).

**Performance note** — blocker promotion zero-cost (policy line — incident-class prevention free; tarball gates seconds per 1.1 part 2).

**Mentor note** — incident epitaph: "packaging warnings are blockers" (1.1 policy generalized — never re-debated, quoted at every warning-override request).

### 3) **Untyped analytics SDK widened event payloads silently** (hopeful any shim, ladder adopted)

**Modern guidance** — shim minimally (used names — 3.3 part 1); parse at boundaries (unknown in, proven out — 3.3 part 2); climb quarterly (precision deepening — trust transferring with evidence); monitor payload acceptance (server-side rates alerting — finance/analysts never the detectors again).

### 4) **SIGTERM-ignorant deploy severed 400 in-flight checkouts** (no drains, runbook added)

**Definition** — the incident: rolling deploy SIGTERMing pods with 400 in-flight checkouts (no drain phases — 1.3 part 3's prevented class, unprevented: exit-during-flight default): responses severed mid-payment (partial writes, double-charge retries, support crisis): fix — phased shutdown (stop→drain→exit per 1.3 part 3 + 18/3.3) + SIGTERM tests (17/2.3 doubles) + shutdown-duration monitoring (histograms alerting like latency).

**What problem it solves / history** — unhandled SIGTERM defaults (immediate exit — work severed): phased drains completing work (graceful deploys — users unaffected, data consistent; 1.3 part 3 practiced at release scale, 18/3.3 lifetime honesty restated as incident response).

**Modern guidance** — three phases (stop-accepting → drain → exit — each awaited, each bounded per 18/2.2); SIGTERM tests (doubles driving handlers — 17/2.3 pattern, drains asserted); duration monitoring (histograms — phases timed, regressions alerted).

**Runnable example** — drains completing (good vs bad, `tsc --strict`):

```typescript
// good — phased shutdown (work completing — deploys graceful, checkouts whole)
export {}; // module marker (top-level await below needs module scope)
let live = 0;
async function checkout(): Promise<string> {
  live++; // inventoried (drain observing — work counted per 1.3 part 3)
  await new Promise<void>((r) => setTimeout(r, 1));
  live--;
  return "charged";
}
async function graceful(): Promise<number> {
  while (live > 0) { await new Promise<void>((r) => setTimeout(r, 1)); } // drain (in-flight completing — bounded per 18/2.2 in production)
  return 0; // exit code (clean — orchestrators reading codes per 1.3 part 3)
}
console.log(await checkout(), await graceful()); // charged 0 — phased exit (400-checkout class structurally prevented)
// bad — exit-during-flight (SIGTERM defaulting to immediate exit — severed responses, partial writes, retry storms)
// fix — three phases + tests + monitoring (stop → drain → exit — shutdown as typed procedure per 1.3 part 3)
```

**Common confusion** — "orchestrators drain for us" — orchestrators *signal* (SIGTERM); apps *drain* (in-flight completing — 1.3 part 3 restated as incident response). "drains slow deploys" — drains bound (seconds with timeouts — severed-checkout incidents slowing business quarters; bounded drains the fast safe path). "shutdown paths untestable" — SIGTERM doubles testing (17/2.3 — drains asserted like any async path).

**Performance note** — drain latency = slowest in-flight op (bounded — timeouts composing; 400 severed checkouts costing support crises + double-charge reversals).

**Mentor note** — deploy-readiness: SIGTERM demoed (phases timed — 1.3 part 3 practiced, undemoed shutdowns failing at 3am).
