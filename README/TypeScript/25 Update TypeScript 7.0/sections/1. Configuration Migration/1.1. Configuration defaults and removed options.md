## 1.1. Configuration defaults and removed options

A compiler upgrade can change the files your deployment loads even when the source stays unchanged. This lesson migrates a small Node package from TypeScript 5.9.3 through 6.0.3 to 7.0.2, preserving its `dist/index.js` entry point. It assumes you can read a tsconfig and run npm commands. Ordinary configuration mechanics remain in [domain 13](<../../../13 Configuration and Compiler Options/README.md>).

### 1) **Identify the transition you are testing**

TypeScript 6 changed several defaults before the native compiler arrived. Its release notes describe `strict: true`, `module: esnext`, `target: es2025`, and `types: []` as new defaults. With a tsconfig, the default `rootDir` is its containing directory; command-line compilation without a config still infers the source root. Explicit old settings can preserve supported behavior. Options deprecated in 6 and removed in 7 require replacements. The [6.0 migration notes](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-6-0.html) provide the broader checklist.

We explicitly set strictness, target and module settings so that this exercise isolates output layout and global declarations. The CommonJS package below uses the `nodenext` pair; changing the compiler does not require changing that package's module format. Runtime API support remains a separate decision.

### 2) **Reproduce the old build and inspect the new artifacts**

Use an empty directory on Linux with Node 20.20.2 and npm 10.8.2. Save this root `package.json`. npm aliases install the older compilers alongside the new one. Invoke their files directly because all three packages offer a `tsc` executable name.

```json
{
  "private": true,
  "type": "commonjs",
  "devDependencies": {
    "typescript": "7.0.2",
    "ts5": "npm:typescript@5.9.3",
    "ts6": "npm:typescript@6.0.3",
    "@types/node": "20.19.0"
  }
}
```

```bash
npm install
node node_modules/ts5/lib/tsc.js --version
node node_modules/ts6/lib/tsc.js --version
node node_modules/typescript/bin/tsc --version
mkdir -p before/src after/src
```

The version commands must print 5.9.3, 6.0.3 and 7.0.2 respectively. Keep the generated lockfile for subsequent `npm ci` runs. Save `before/src/index.ts`:

```typescript
export const greeting = `hello ${process.env.USER ?? "reader"}`;
console.log(greeting);
```

Save `before/tsconfig.json`:

```json
{
  "compilerOptions": {
    "strict": true,
    "target": "es2022",
    "module": "nodenext",
    "moduleResolution": "nodenext",
    "outDir": "dist",
    "declaration": true
  },
  "include": [
    "src/**/*.ts"
  ]
}
```

Before each build, remove only this scratch project's output so an old artifact cannot masquerade as new output:

```bash
rm -rf before/dist
node node_modules/ts5/lib/tsc.js -p before/tsconfig.json --listEmittedFiles
rm -rf before/dist
node node_modules/ts6/lib/tsc.js -p before/tsconfig.json --listEmittedFiles
rm -rf before/dist
node node_modules/typescript/bin/tsc -p before/tsconfig.json --listEmittedFiles
```

The latter two commands are intentional failures. Run them separately and inspect each exit status and emitted-file list.

| Compiler | Observed exit | Diagnostic | Emitted paths under `before` |
|---|---|---|---|
| 5.9.3 | 0 | None | `dist/index.js`, `dist/index.d.ts` |
| 6.0.3 | 2 | TS5011: set `rootDir` explicitly | `dist/src/index.js`, `dist/src/index.d.ts` |
| 7.0.2 | 2 | TS5011: set `rootDir` explicitly | `dist/src/index.js`, `dist/src/index.d.ts` |

These are actual results from the declared fixture. The compiler reports a migration problem and still emits files: a nonzero exit and an output directory can coexist. Continuing deployment after this failure would leave the old `dist/index.js` entry point missing. Ignoring the exit status is therefore an observable bad practice, not merely a style violation.

### 3) **Preserve the intended layout and declaration environment**

Copy the same source to `after/src/index.ts`. Save this repaired `after/tsconfig.json`:

```json
{
  "compilerOptions": {
    "strict": true,
    "target": "es2022",
    "module": "nodenext",
    "moduleResolution": "nodenext",
    "outDir": "dist",
    "declaration": true,
    "rootDir": "src",
    "types": [
      "node"
    ]
  },
  "include": [
    "src/**/*.ts"
  ]
}
```

`rootDir: "src"` makes the output path explicit. `types: ["node"]` includes the installed Node global declarations, including `process`. It does not supply a Node runtime or install its types package; `@types/node` is already a declared dependency above.

```bash
cp before/src/index.ts after/src/index.ts
rm -rf after/dist
node node_modules/ts5/lib/tsc.js -p after/tsconfig.json --listEmittedFiles
USER=Ada node after/dist/index.js
rm -rf after/dist
node node_modules/ts6/lib/tsc.js -p after/tsconfig.json --listEmittedFiles
USER=Ada node after/dist/index.js
rm -rf after/dist
node node_modules/typescript/bin/tsc -p after/tsconfig.json --listEmittedFiles
USER=Ada node after/dist/index.js
```

All three repaired builds exit 0, emit `dist/index.js` and `dist/index.d.ts`, and print `hello Ada` when run.

For a focused diagnostic, temporarily remove `types` from the repaired config and run each new compiler with `-p after/tsconfig.json --noEmit`. TypeScript 6.0.3 reports TS2591 and exits 2; 7.0.2 reports TS2591 and exits 1. Restore the setting afterward. Merely having the types dependency installed no longer includes this global automatically.

Now remove only `rootDir`, leaving `types` intact. Both new compilers pass `--noEmit`, but an emitting build reports TS5011 and writes `dist/src/index.js`. Restore `rootDir`, clean the output and rebuild. This isolates why a checking-only migration gate does not establish artifact compatibility.

### 4) **Replace removed options and defend the migration**

Save this root `legacy.json` as a separate diagnostic exercise:

```json
{
  "compilerOptions": {
    "strict": true,
    "target": "es5",
    "module": "commonjs",
    "moduleResolution": "node10",
    "types": [
      "node"
    ],
    "ignoreDeprecations": "6.0",
    "noEmit": true
  },
  "files": [
    "after/src/index.ts"
  ]
}
```

```bash
node node_modules/ts6/lib/tsc.js -p legacy.json
node node_modules/typescript/bin/tsc -p legacy.json
```

The first exits 0. The second exits 1 with TS5108 for both `target=ES5` and `moduleResolution=node10`. `ignoreDeprecations` allows the TypeScript 6 transition; it cannot restore removed functionality in 7. For this Node package, the repaired `es2022`/`nodenext` config supplies a tested replacement. A real application that needs ES5 output must assess its target platforms and an appropriate additional transform rather than copying this Node choice.

Exercise: review a proposed upgrade that changes only the compiler dependency. Require evidence that the deployed entry path remains present, Node globals are included deliberately, removed options have replacements, and the built program runs. Explain which check would catch each failure here.

The solution is the repaired config plus a clean emitting build and its consumer command. The emitting build catches the layout change; the global-declaration probe catches the missing `process` type; the legacy config catches removed options; running `dist/index.js` checks the expected artifact. A defensible review records both the old and new results and a way to restore the prior dependency/configuration together.

For larger configuration graphs, [Andrew Branch's ts5to6 tool](https://github.com/andrewbranch/ts5to6) demonstrates automating explicit `rootDir` preservation and `baseUrl` migration, including related configs. Its documented scope is those two changes, so automation still needs a reviewed diff and the project's real build/consumer tests. The tool was consulted, but was not executed in this exercise.

### 5) **Common confusion**

An omitted option and an explicitly chosen option are different promises. Omitting `rootDir` delegates the output layout to compiler defaults; explicitly setting it states the package's intent. Likewise, `types` controls global declaration inclusion rather than every imported dependency's typing. Adding all ambient packages indiscriminately may conceal a missing environment decision.

A successful check is evidence about the checked program. It does not prove the emitting command succeeds, the deployment path is unchanged, or the new compiler works with tools that consume its API. Keep those claims attached to their actual tests.

### 6) **Performance note**

These settings primarily establish correctness and compatibility. `rootDir` changes output organization rather than making the emitted greeting algorithm faster. Choosing global declaration packages deliberately changes checker inputs and may affect build/editor work, but this tiny exercise does not measure that cost. Compare representative builds before promising a speedup from either configuration changes or the native compiler.

### 7) **Mentor note**

Ask a learner to explain how TS5011 can coexist with emitted JavaScript, then predict what a deployment looking for `dist/index.js` would do. A sound answer separates diagnostics, emit and consumer behavior. Next remove one repaired setting at a time; require the learner to identify which command must change before accepting their explanation.
