## 5.1. Real production bugs caused by misunderstanding fundamentals

### 1) **Assuming types guard at runtime** (the "but it typed correctly" incident)

**Incident** — Team ships `fetchUser` that casts `await res.json() as User` without validation. Upstream API adds a new error envelope `{ error: "rate_limited" }`. Client calls `user.name.toUpperCase()` and production throws `Cannot read properties of undefined (reading 'toUpperCase')` for 2% of requests — all rate-limited responses. TypeScript was silent because `as User` promised the shape.

**Root cause** — Trusting `as` at the boundary (see [2.2. Static vs runtime](<../2. How TypeScript doesnt execute/2.2. Static checking vs runtime reality trust but verify.md>)).

**Fix (parse, don't assert)** —

```typescript
type User = { id: number; name: string };
function isUser(v: unknown): v is User {
  return typeof v === "object" && v !== null && "name" in v && typeof (v as Record<string, unknown>).name === "string";
}
async function fetchUser(id: number): Promise<User> {
  const raw: unknown = await fetch(`/users/${id}`).then(r => r.json());
  if (!isUser(raw)) throw new Error(`Invalid user shape: ${JSON.stringify(raw)}`); // fail fast with context
  return raw;
}
```

**Detection** — Add CI check: count `as` at boundaries (`grep -n "as " src/api/*.ts`). Zero `as` on any `unknown` or `res.json()` path is the gate.

---

### 2) **Using `enum` then hitting native stripping** (deploys break under `--experimental-strip-types`)

**Incident** — Library publishes `enum Status { Pending, Done }`. Consumers on Node 23's native stripping (`node --experimental-strip-types`) get `SyntaxError: Unexpected token 'enum'` at startup — deploy rollback. Local `tsx` had hidden the failure because `tsx` transpiles `enum` via esbuild.

**Fix** — Replace with union + const object (erasable) — see [3.3. Choosing erasable syntax](<../3. Running TypeScript today/3.3. Choosing erasable syntax the zero-cost interop rule.md>):

```typescript
const Status = { Pending: "pending", Done: "done" } as const;
type Status = typeof Status[keyof typeof Status];
```

Enable `erasableSyntaxOnly: true` so the error surfaces at `tsc` time, not at deploy time. Add `npx tsc --erasableSyntaxOnly --noEmit` as a separate CI job.

### 3) **Treating `any` as "I don't know yet"** (it silences the checker forever and leaks)

**Incident** — Migrating JS file, developer annotates `function process(data: any) { return data.items.map(...) }`. Downstream `const items: Item[] = process(raw)` passes checking because `any` is compatible with `Item[]`. `raw` was actually `{ items: null }`, production throws `Cannot read properties of null`.

**Fix** — Use `unknown` for "I don't know yet" — it forces validation before use:

```typescript
// bad: any silences everything
function processBad(data: any): unknown { return data.items; } // caller is also fooled

// good: unknown forces a proof
function processGood(data: unknown): string[] {
  if (typeof data !== "object" || data === null || !("items" in data)) throw new Error("invalid");
  const rest = (data as Record<string, unknown>).items; // narrowed after object check
  if (!Array.isArray(rest) || !rest.every(x => typeof x === "string")) throw new Error("invalid");
  return rest;
}
```

Enable `noImplicitAny: true` (via `strict: true`) and treat every `any` as a budgeted exception with a TODO comment.

### 4) **Conflating checking and emitting** (CI passes check but deploys stale `dist/`)

**Incident** — `package.json` has only `"build": "tsc"`. CI runs `npm run build` which emits *and* checks in one step; type error blocks emit, so the previous `dist/` remains on disk. Deploy step copies stale `dist/` — type bug ships with old JavaScript, no error surfaces until runtime behavior diverges.

**Fix** — Separate `check` and `build` (see [3.1. Compilation pipeline](<../3. Running TypeScript today/3.1. The compilation pipeline tsc emit declarations and source maps.md>)): `tsc --noEmit` for checking, `tsc -b` or esbuild for emit, and clean `dist/` before emit (`rm -rf dist && tsc`). CI fails if `check` fails, even if `build` would have emitted something else.

---

### 5) **Mentor note**

Each incident maps to one question: "where did a type disappear without proof?" Train students to ask that after every runtime error — the answer will point to either an `as` at a boundary, an `enum` under stripping, an `any` leak, or a stale `dist/`. Review exercise: run `grep -R " as " src/ --include="*.ts" | head` on a production repo and classify each as "justified by predicate" or "TODO".
