## 4.1. Type-testing checklist — mental models mentors insist on

### 1) **Assert identity, not assignability** (Equal pins contracts, extends hides drift)

**Definition** — the first check: every public return/parameter/transform carries an `Equal<Actual, Expected>` probe (1.1), not an assignability probe (`const x: Expected = ...`). Identity fails on widening/narrowing/optionality moves; assignability passes on all three — the checklist's highest-leverage line.

**What problem it solves / history** — widened returns (`"a"|"b"` → `string`) passing assignability suites while downstream switches go non-exhaustive (the incident class 5.1 dissects). Identity probes convert the widening into a red line at the declaration (minutes to fix at authoring, postmortem at discovery).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), one inline `Equal` per public signature (contract advertises its pin) + matrices in `test-d` (union/never/unknown/any classes per 3.1). Review gate: public-type PRs without pins are incomplete.

**Runnable example** — the check applied (good vs bad, `tsc --strict`):

```typescript
// good — identity on the public return (widening breaks HERE)
export {}; // module marker (top-level await below needs module scope)
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
async function loadRole(id: string): Promise<"admin" | "user"> { return id === "a" ? "admin" : "user"; }
assertType<Equal<Awaited<ReturnType<typeof loadRole>>, "admin" | "user">>(); // identity (awaited shape pinned)
console.log(await loadRole("a")); // admin — contract pinned (string-widening breaks the probe, loudly)
// bad — assignability probe (const r: string = await loadRole(...) — widening invisible, switches rotting)
// fix — Equal on awaited returns (async shapes pinned through Awaited — see 08/2.3 positions)
```

```typescript
// good — containment where identity is too strict (directional checks, deliberately chosen)
type Extends<A, B> = A extends B ? true : false;
declare function assertType<T extends true>(): void;
assertType<Extends<"a", string>>(); // containment (intentional widening contracts use Extends — documented choice)
console.log("containment-ok"); // containment-ok — directional probes (identity default, containment deliberate)
// bad — identity everywhere (intentional widenings failing — probes fighting documented contracts)
// fix — Equal default, Extends deliberate (each containment probe comments WHY widening is the contract)
```

**Common confusion** — "identity probes are brittle" — brittle to *contract moves* (the point — moves should break); robust to cosmetics (aliases, rendering — 3.1 snapshot contrast). "one probe per file suffices" — per *contract* (each public signature — coarse probes localize nothing).

**Performance note** — inline `Equal` probes cost one conditional instantiation each (microseconds); matrices stay representative (branch-changing classes — 3.1 discipline).

**Mentor note** — teach with the widening demo (literal → `string`, assignability green, `Equal` red): one red line converts skeptics permanently.

### 2) **Lock rejections, not just acceptances** (every no a test)

**Definition** — the second check: every public rejection rule carries a negative probe (`@ts-expect-error` lock per 1.3, or `expectError` per 1.2). Acceptances prove the happy path; rejections prove the boundary — untested rejections re-admit silently (the fraud-queue incident class).

**What problem it solves / history** — validation bypasses reintroduced by well-meaning loosenings (string widenings re-admitting malformed input — behavior tests green on valid inputs, production discovering the bypass). Negative probes break the build at the loosening (red before review ends).

**Modern guidance** — one `@ts-expect-error` per validation branch (rejection rules enumerated like boundary inventories — 15/3.3); reason comments on every lock (intent surviving cleanups — 1.3 discipline); `ban-ts-comment` for `@ts-ignore` (16/2.1 tier — suppression debt unrepresentable).

**Runnable example** — locks beside acceptances (good vs bad, `tsc --strict`):

```typescript
// good — acceptance AND rejection tested (both sides of the boundary)
export {}; // module marker (consistent module scope across fences)
function toAge(n: number): number {
  if (!Number.isInteger(n) || n < 0) throw new Error("bad age");
  return n;
}
// lock illustration — in real test-d files: "@ts-expect-error — ages are numeric" above toAge("3") (rejection pinned)
console.log(toAge(30)); // 30 — acceptance proven (behavior); rejection locked (statics) — the boundary fully tested
// bad — acceptance-only (toAge("3") re-admitted silently after any widening — bypass discovered in production)
// fix — negative probe per branch (every no a test — boundaries tested both directions)
```

**Common confusion** — "negative tests double test count" — negative probes are one line each (cheapest tests written); bypass incidents are postmortems each (most expensive outcomes). "locks rot" — locks rot *loudly* (unused-directive red on contract change — self-maintaining, see 1.3).

**Performance note** — directives cost one diagnostic slot each (negligible); bypass incidents cost queues, fraud review, postmortems (unbounded — always pay the line).

**Mentor note** — PR rule: validation-branch PRs without negative probes are incomplete (request changes — mechanical, non-negotiable).

### 3) **Doubles carry signatures** (no any mocks, fakes prove contracts)

**Definition** — the third check: every test double annotated with its real signature (`const mock: Sig` per 2.1, `implements Seam` per 2.2), zero `any` in double files (lint-enforced per 2.1 part 3). Doubles that cannot carry signatures are redesigned (missing seam → interface + injection, see 2.1 part 2).

**What problem it solves / history** — `any`-mocked cores silencing whole call chains (renamed fields slipping 40 sites — 5.1 incident): the suite green, the contract untested. Signature-carrying doubles break at every stale call (drift red at the seam, minutes to fix).

**Modern guidance** — `typeof`-pin doubles (`const d: typeof f`), `Record`-exhaustive stub tables (2.2 part 2), `implements`-checked fakes (2.2 part 3); grep `any` in double files per review (blocking — seam files carry the most leverage).

**Runnable example** — signature discipline (good vs bad, `tsc --strict`):

```typescript
// good — double pinned by typeof (stale calls break HERE)
export {}; // module marker (consistent module scope across fences)
function notify(user: string, msg: string): string { return `${user}:${msg}`; }
const double: typeof notify = (user, msg) => `mock:${user}:${msg}`; // pinned (param renames break here)
console.log(double("u", "hi")); // mock:u:hi — doubles carrying signatures (contracts enforced at seams)
// bad — any double (every downstream expression any — assertions vacuous, drift invisible)
// fix — typeof pins (one annotation per double — infection impossible by construction)
```

**Common confusion** — "test doubles deserve looser rules" — doubles ARE the contract's enforcement (loose doubles enforce nothing — strictest files in the suite, not loosest). "typeof pins couple tests to implementation" — pins couple tests to *signatures* (the seam's contract — coupling intended, drift detected).

**Performance note** — `typeof` queries cost one lookup each (negligible); `any`-double incidents cost postmortems (asymmetric — always pin).

**Mentor note** — the review grep (`any` in `__mocks__`/doubles) blocks PRs until typed — no exceptions, ever.

### 4) **Gate statically and behaviorally** (red type test blocks like red unit test)

**Definition** — the fourth check: three required gates (3.3 — `noEmit`, `tsd`/typecheck, unit), triaged statics-first (contracts before symptoms), baselined legacy shrinking (ratchet, never growing). Type reds carry identical severity to behavior reds (merge blocked, triage immediate).

**What problem it solves / history** — optional statics (skipped gates — drift compounding into flag-days) and unit-first debugging under red statics (symptom hunts ending at one-line type moves). Equal severity + ordered triage converts both into minute-level fixes at authoring time.

**Modern guidance** — branch protection on all three gates (required, not advisory); runbooks stating triage order (typecheck → typetest → unit); baselines per error class with shrink-only semantics (3.3 part 3 — legacy honest, progress visible).

**Runnable example** — gate parity (good vs bad, `tsc --strict`):

```typescript
// good — static and behavioral proof together (shapes AND values, every merge)
export {}; // module marker (top-level await below needs module scope)
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
function ship(weight: number): string { return weight > 0 ? `ship:${weight}` : "invalid"; }
assertType<Equal<ReturnType<typeof ship>, string>>(); // static gate (shape pinned)
console.log(ship(2)); // ship:2 — behavioral gate (value proven) — both greens required, neither optional
// bad — behavioral-only merging (shapes drifting silently — flag-days compounding invisibly)
// fix — three required gates (parity enforced by branch protection — culture as configuration)
```

**Common confusion** — "statics slow merging" — statics *accelerate* merging (drift caught in minutes at authoring vs days in flag-day migrations — net velocity positive by the second quarter). "small PRs don't need gates" — small PRs move contracts most often (one-line widenings — gates matter MORE per line changed, not less).

**Performance note** — parallel gates wall-time ≈ slowest (not sum — split gates often faster to green than lumped jobs); triage order costs nothing (reading sequence).

**Mentor note** — culture line: "a red type test pages like a red unit test" (severity parity stated, tooled, reviewed — the sentence that ends optional-statics debates).
