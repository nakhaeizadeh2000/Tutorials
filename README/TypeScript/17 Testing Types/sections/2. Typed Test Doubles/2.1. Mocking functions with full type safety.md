## 2.1. Mocking functions with full type safety

### 1) **Signature-preserving mocks** (vi.fn generics keeping arity and return)

**Definition** — a typed mock carries the mocked signature as a type argument: `vi.fn<typeof fetchUser>()` (vitest) or `jest.fn<Return, Args>()` — calls are checked (arity, argument types), returns are checked (mock implementations must satisfy the return type), and `.mockResolvedValue` variants enforce the awaited shape. The mock *is* the signature's test double, not an `any`-shaped hole.

**What problem it solves / history** — `jest.fn()` untyped (implicit `any` implementation, unchecked calls) lets refactors slip: renaming a required field still passes 40 call sites because the mock never required it (the 5.1 incident class). Signature-preserving mocks break at every stale call (the mock's type argument disagrees with the new signature — red before review).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS; vitest 3.x), always pass the explicit type argument (`vi.fn<typeof f>()`, never bare `vi.fn()`); enable `no-explicit-any` on test doubles via the 16/2.1 lint tier so untyped mocks fail lint, not production. Prefer injected fakes over module mocks where the seam allows (part 2).

**Runnable example** — mocks carrying signatures, shown dependency-free (good vs bad, `tsc --strict`):

```typescript
// good — mock typed by the real signature (arity + return enforced at every call)
export {}; // module marker (top-level await below needs module scope)
type FetchUser = (id: string) => Promise<{ name: string }>;
const seen: string[] = [];
const mockFetch: FetchUser = async (id) => { seen.push(id); return { name: id }; };
console.log((await mockFetch("u1")).name); // u1 — mock calls checked (arity/args), returns checked (name: string)
// bad — untyped mock (any implementation, unchecked calls — renamed fields slip 40 call sites)
// fix — annotate every mock with its real signature (stale calls break at the mock, loudly)
```

```typescript
// good — mock implementation must satisfy the return (wrong shapes error at creation, not at assertion)
type GetConfig = () => { host: string; port: number };
const mockCfg: GetConfig = () => ({ host: "h", port: 80 }); // return checked (missing port errors HERE)
// const badCfg: GetConfig = () => ({ host: "h" }); // ❌ errors when uncommented (port missing — caught at creation)
console.log(mockCfg().port); // 80 — implementations verified where written (not where asserted)
// bad — mock returning partials cast as full (as Config lies — consumers read undefined.port at runtime)
// fix — constructor-checked implementations (the factory's T constrains the impl — lies impossible)
```

```typescript
// good — async mock values typed through the awaited shape (resolve-values checked, not any)
export {}; // module marker (top-level await below needs module scope)
type Lookup = (id: string) => Promise<number>;
const mockLookup: Lookup = async (id) => id.length; // resolve-value checked (must be number — see 08/2.3 infer positions)
console.log(await mockLookup("abc")); // 3 — resolve-values flow typed (Awaited<ReturnType<T>> in factory spelling)
// bad — mockResolvedValue(anything) (untyped resolutions — shape drift invisible until consumers crash)
// fix — resolves typed as Awaited<Return> (resolution shapes pinned like returns)
```

**Common confusion** — "mocks should be loose to keep tests flexible" — loose mocks test *nothing about the contract* (flexibility hiding drift); strict mocks pin the seam (the seam's whole purpose). "typing mocks costs more than it saves" — one type argument per mock vs one production incident per untyped seam (the 5.1 forty-call-site class settles the math). "mock the module, not the signature" — module mocks rewire imports (blast radius per test file); signature mocks constrain calls (precision per seam) — part 2 compares.

**Performance note** — generic mock factories instantiate per mocked signature (one function type each — trivial); untyped `any` mocks *defer* cost to production incidents (unbounded). Prefer fewer, seam-level mocks over per-test re-mocking (setup cost once, reuse everywhere).

**Mentor note** — grep test suites for bare `vi.fn()`/`jest.fn()` with no type argument in review (each one a future incident); the fix is mechanical (add `typeof f`) — approve-after-fix, never approve-as-is.

### 2) **Mocked modules vs injected fakes** (rewiring blast radius vs seam precision)

**Definition** — *module mocks* (`vi.mock("./user")` — rewiring the import graph for a test file) replace the module for every importer in the file; *injected fakes* (constructor/function parameters typed as interfaces — `new Service(fakeRepo)`) substitute one seam for one consumer. Blast radius differs by orders of magnitude: file-wide rewiring vs single-seam substitution.

**What problem it solves / history** — module-mocked suites couple every test to the mock registry (reordering imports breaks tests, parallel files need identical registries, refactors of module shape break dozens of files at once). Injected fakes localize substitution (the seam is a parameter — typed, visible, per-consumer); module mocks remain only where no seam exists (third-party SDKs, env singletons).

**Modern guidance** — design seams for injection (depend on `UserRepo` interface, not `./user-repo` module — SOLID dependency inversion per track mission); reserve `vi.mock` for unseamed boundaries (network SDKs, `Date`/`Math.random`, env reads). When module-mocking, co-locate the factory with the test file (reviewed together, deleted together).

**Runnable example** — seam precision vs rewiring (good vs bad, `tsc --strict`):

```typescript
// good — injected fake (one seam, one consumer, fully typed)
export {}; // module marker (top-level await below needs module scope)
interface UserRepo { find(id: string): Promise<{ name: string } | null> }
class FakeRepo implements UserRepo {
  constructor(private rows: Record<string, { name: string }>) {}
  async find(id: string): Promise<{ name: string } | null> { return this.rows[id] ?? null; }
}
class Service {
  constructor(private repo: UserRepo) {}
  async label(id: string): Promise<string> { return (await this.repo.find(id))?.name ?? "anon"; }
}
console.log(await new Service(new FakeRepo({ u1: { name: "ada" } })).label("u1")); // ada — seam substituted (typed, local, reviewable)
// bad — module-mocked repo for a seam that could inject (file-wide rewiring for a single consumer — blast radius)
// fix — inject the seam (parameterized, typed, per-consumer — rewiring only where no seam exists)
```

```typescript
// good — interface seam proving the contract (fake must satisfy UserRepo — drift breaks the fake first)
interface Clock { now(): number }
class FixedClock implements Clock { constructor(private t: number) {} now(): number { return this.t; } }
function isExpired(clock: Clock, deadline: number): boolean { return clock.now() > deadline; }
console.log(isExpired(new FixedClock(100), 50)); // true — time injected (deterministic, typed, parallel-safe)
// bad — Date.now mocked globally per test (parallel tests racing the same global — flaky + untyped)
// fix — Clock seam (time as a dependency — determinism without globals)
```

**Common confusion** — "injection means DI frameworks" — injection means *parameters* (constructor/function args — no container needed; 14/3.3 frameworks only past complexity thresholds). "module mocks are easier" — easier to *write*, harder to *maintain* (registry coupling compounds per file — injection pays back by the third test). "fakes duplicate production code" — fakes implement the *interface* minimally (in-memory rows, fixed clocks — contract-proving, not logic-duplicating).

**Performance note** — injected fakes allocate per test (tiny objects — negligible); module-mock registries re-evaluate module graphs per file (seconds at suite scale — another reason to prefer injection).

**Mentor note** — architecture review: every `vi.mock` of a *first-party* module is a missing-seam smell (request the interface + parameter instead); `vi.mock` of *third-party* modules is expected (no seam to own).

### 3) **Untyped-mock infection** (one any double silencing a call chain)

**Definition** — *mock infection*: a mock typed (or inferred) as `any` propagates `any` through every expression touching it (calls return `any`, properties are `any`, assertions on `any` pass vacuously — see 03/2.1's infection mechanics). One untyped double can silence type-checking across an entire test file — the suite green, the contract untested.

**What problem it solves / history** — suites with an `any`-mocked core helper (`mockApi` returning `any`) approve everything downstream: renamed fields, narrowed unions, new required params — all green, all broken. The infection is invisible (no red, no warning) until production. Typed mocks (part 1) + lint bans (16/2.1) contain it structurally.

**Modern guidance** — ban `any` in test files with the same severity as `src/` (`no-explicit-any: error` — tests are contracts too); add one CI check grepping `as any` in test doubles (each occurrence needs a justification comment + expiry). Treat a red lint on a mock as blocking (same severity as a red type test — see 3.3).

**Runnable example** — infection contained (good vs bad, `tsc --strict`):

```typescript
// good — typed double keeping the chain checked (downstream mistakes error)
function parseAmount(raw: string): number { const n = Number(raw); if (Number.isNaN(n)) throw new Error("nan"); return n; }
type ParseAmount = typeof parseAmount;
const strictDouble: ParseAmount = (raw) => raw.length; // checked (signature enforced — wrong impl errors HERE)
console.log(strictDouble("42")); // 2 — chain stays typed (callers of the double still checked)
// bad — any-typed double (const looseDouble: any = ... — every downstream expression any, every assertion vacuous)
// fix — typeof-pinned doubles (the real signature as the double's type — infection impossible by construction)
```

```typescript
// good — unknown-ingesting double forcing validation (15/3.3 parse discipline inside tests)
function parseUser(raw: unknown): { name: string } {
  if (typeof raw !== "object" || raw === null || !("name" in raw)) throw new Error("bad user");
  const name = (raw as { name: unknown }).name;
  if (typeof name !== "string") throw new Error("bad name");
  return { name };
}
console.log(parseUser({ name: "ada" }).name); // ada — test fixtures validated (doubles ingest unknown, prove types)
// bad — fixtures cast as domain types (as User on hand-written JSON — malformed fixtures compiling green)
// fix — parse fixtures (unknown in, proven types out — the 15 discipline applied to test data)
```

**Common confusion** — "test code quality matters less" — test code *is* the contract's enforcement (untyped tests enforce nothing — quality matters *more* per line). "`as any` in tests is harmless" — `as any` in tests silences the exact checks the test exists to perform (self-defeating by construction). "lint on tests is noise" — lint on tests catches infection at write time (seconds) vs incident time (postmortems).

**Performance note** — `unknown`-ingesting parsers add validation cost per fixture (microseconds — test-time only); `any` doubles cost nothing at test time and everything at incident time (asymmetric — always pay the microseconds).

**Mentor note** — the one-line review grep: `any` in `__mocks__`/test-utils blocks the PR until typed (no exceptions — the seam files carry the most leverage).
