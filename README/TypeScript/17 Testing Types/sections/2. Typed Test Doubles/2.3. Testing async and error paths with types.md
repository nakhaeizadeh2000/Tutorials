## 2.3. Testing async and error paths with types

### 1) **Typed rejection tests** (rejects matchers plus Result-union assertions)

**Definition** — async failure tests assert *typed* rejections: `await expect(p).rejects.toThrow(RetryableError)` (error *class* + message, not bare strings) for throw-style code, and discriminated narrowing (`if (!r.ok) ...` — 15/2.1 `Result` unions asserted branch-by-branch) for value-style code. Both pin the failure *type*, not just its occurrence.

**What problem it solves / history** — `try { await op(); assert.fail() } catch { /* anything */ }` passes on *any* throw (wrong error class, wrong message, programmer bug — all green). Typed rejection tests distinguish expected failures (domain errors asserted by class) from bugs (unexpected throws failing the test) — the 15 throw-vs-return discipline enforced in suites.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS; vitest 3.x), assert rejection *classes* (`rejects.toThrow(ValidationError)`), never bare `.rejects.toThrow()` (any throw passes) or string-only matching (message refactors breaking unrelated tests). For `Result` code, assert *both* branches (ok-values and err-values typed — branch coverage on the union, not just the happy member).

**Runnable example** — rejections pinned by class and branch (good vs bad, `tsc --strict`):

```typescript
// good — error class asserted (wrong-class throws fail the test, as designed)
export {}; // module marker (top-level await below needs module scope)
class ValidationError extends Error { constructor(msg: string) { super(msg); this.name = "ValidationError"; } }
async function save(input: string): Promise<string> {
  if (input === "") throw new ValidationError("empty");
  return `saved:${input}`;
}
async function rejectsWith(fn: () => Promise<unknown>, Ctor: new (...a: never[]) => Error): Promise<string> {
  try { await fn(); return "no-throw"; }
  catch (e) { return e instanceof Ctor ? `caught:${(e as Error).name}` : `wrong-class:${e instanceof Error ? e.name : typeof e}`; }
}
console.log(await rejectsWith(() => save(""), ValidationError)); // caught:ValidationError — class pinned (message refactors don't break it)
// bad — catch-anything assertions (any throw green — programmer bugs masked as expected failures)
// fix — instanceof-class gates (expected classes caught, unexpected classes reported as wrong-class)
```

```typescript
// good — Result branches asserted separately (ok-shape AND err-shape pinned)
type Result<T, E> = { ok: true; value: T } | { ok: false; error: E };
function divide(a: number, b: number): Result<number, "zero"> {
  return b === 0 ? { ok: false, error: "zero" } : { ok: true, value: a / b };
}
const bad = divide(1, 0);
const good = divide(1, 2);
console.log(bad.ok ? "unexpected-ok" : bad.error); // zero — err branch asserted (literal pinned, not string-matched loosely)
console.log(good.ok ? good.value : "unexpected-err"); // 0.5 — ok branch asserted (both members covered, union-tested)
// bad — ok-only assertions (err branch untested — error shapes drifting until consumers crash)
// fix — per-branch assertions (unions tested member-by-member — the 07 narrowing discipline in suites)
```

**Common confusion** — "string-matching errors is precise" — messages refactor (wording, i18n); classes persist (hierarchy is the contract — assert the stable half). "no-throw needs no assertion" — un-awaited promises *cannot* throw into the test (floating — part 2); asserting resolution (`await expect(p).resolves...`) proves the await happened. "Result code needs no rejection tests" — `Result` still throws on bugs (programmer errors); assert the err-branch *and* keep unexpected-throw detection (both layers).

**Performance note** — `instanceof` per rejection is one prototype walk (nanoseconds); class-hierarchy depth costs nothing measurable — assert classes freely.

**Mentor note** — forbid bare `catch {}` and bare `.rejects.toThrow()` in review (both pass on any throw — the two masks hiding bugs); the mechanical fix (add the class) takes seconds.

### 2) **Floating-promise detection in suites** (no-floating-promises on test files)

**Definition** — a *floating promise* is a created-but-unawaited `Promise` (no `await`, no `return`, no `.catch`): rejections escape to `unhandledrejection` (crashing processes per 15/5.1), and the test finishes before the work (assertions running against incomplete state — false green). `no-floating-promises` (typescript-eslint, checker-backed — see 16/2.1) errors on every unhandled promise expression, *including* in test files.

**What problem it solves / history** — fire-and-forget test helpers (`save(data); expect(...)` — assertion racing the save) produce order-dependent suites (green solo, red in CI parallelism) and swallowed rejections (failing operations asserting nothing). The lint rule converts the race into a compile error (every promise awaited/returned/void-marked — no third state).

**Modern guidance** — enable `no-floating-promises` on test files with zero exemptions (test files race *more* than src, not less); mark intentional fire-and-forget with `void` + a comment (`void metrics(data); // intentional — best-effort, rejection-handled inside`) — explicitness reviewed, not assumed. Pair with `no-misused-promises` (async callbacks where sync expected — `forEach(async ...)` — same tier).

**Runnable example** — floats surfaced and fixed (good vs bad, `tsc --strict`):

```typescript
// good — every promise settled (awaited or returned — no floats)
export {}; // module marker (top-level await below needs module scope)
async function save(data: string): Promise<string> { return `saved:${data}`; }
const receipt = await save("order-1"); // awaited (rejections throw HERE — test red on failure, as designed)
console.log(receipt); // saved:order-1 — settled promises (assertions run after completion, never racing)
// bad — floating save (save("order-1"); expect(...) — assertion racing the write, rejection unhandled)
// fix — await/return every promise (lint-enforced — floats are compile errors, not review nits)
```

```typescript
// good — intentional fire-and-forget marked void (explicit, rejection-handled inside)
export {}; // module marker (consistent module scope across fences)
async function bestEffortMetrics(_event: string): Promise<void> { /* swallowed internally by design */ }
void bestEffortMetrics("suite-end"); // void-marked (intentional float — reviewed, rejection-owned inside)
console.log("marked"); // marked — explicit floats (the void operator documents intent per call)
// bad — bare floating calls (intent ambiguous — race or design? reviewers cannot tell)
// fix — void + comment (intentional floats declared; all others lint errors)
```

**Common confusion** — "awaiting slows suites" — awaiting *orders* suites (correctness first); parallelism comes from `Promise.all` (explicit concurrency — see 18/async patterns), not from floats (accidental concurrency). "lint on tests is strict" — test files need *stricter* async discipline (more promises, more races, more flakes — strictness proportional to risk). "`void` swallows errors" — `void` marks *intent* (the callee still owns rejections — mark only rejection-handled callees).

**Performance note** — `await` per operation serializes (correct by default); batch with `Promise.all` where independent (explicit, typed as tuple — see 18/awaited patterns); lint rule cost is checker-backed per file (16/2.1 tier math — worth it on test files).

**Mentor note** — flaky-suite triage step one: enable `no-floating-promises` on the suite and fix every red line — half of all flakes are floats (empirical, repeatable).

### 3) **Timeout and abort doubles** (AbortSignal fakes plus typed fake timers)

**Definition** — time and cancellation as injectable seams: `AbortSignal` fakes (`AbortController` per test — real signals, test-owned lifetimes) for cancellation paths, and typed fake timers (`vi.useFakeTimers()` — clock mocked, `advanceTimersByTime` typed in ms) for timeout/debounce paths. Tests assert timing *logic* without waiting wall-clock time.

**What problem it solves / history** — wall-clock timing tests (`await sleep(2000)` per case — minutes per suite, flakes under CI load) decay until developers delete them (coverage lost) or lengthen timeouts (suites slower yearly). Fake timers collapse waits to zero (logic tested, clock injected); abort fakes make cancellation deterministic (signal fired exactly when the test says).

**Modern guidance** — inject `AbortSignal` as a parameter (cancellation as data — the 18/async pattern); drive timers via fake clocks in tests (real clocks in production — seam, not fork). Always `restore` real timers per test (`afterEach(vi.useRealTimers)` — leaked fakes poisoning unrelated suites is the classic fake-timer incident).

**Runnable example** — deterministic time and cancellation (good vs bad, `tsc --strict`):

```typescript
// good — abort as a parameter (cancellation deterministic, test-owned)
export {}; // module marker (top-level await below needs module scope)
async function fetchWithCancel(url: string, signal: AbortSignal): Promise<string> {
  if (signal.aborted) throw new Error("aborted");
  return `data:${url}`; // (real fetch omitted — seam demonstrated, not network)
}
const ctrl = new AbortController();
ctrl.abort(); // test fires cancellation exactly here (deterministic — no races)
try { await fetchWithCancel("x", ctrl.signal); console.log("unexpected"); }
catch { console.log("aborted-ok"); } // aborted-ok — cancellation path asserted (signal injected, timing exact)
// bad — cancellation untested (abort paths compiling, never exercised — production aborts crashing unhandled)
// fix — signal parameters + per-test controllers (every cancellable function tested cancelled AND completed)
```

```typescript
// good — injectable clock seam (fake timers substitute THIS, not Date globally)
export {}; // module marker (consistent module scope across fences)
interface Clock { now(): number }
function isStale(clock: Clock, updatedAt: number, ttlMs: number): boolean {
  return clock.now() - updatedAt > ttlMs; // logic over the seam (fake or real clocks — same assertion)
}
console.log(isStale({ now: () => 1000 }, 0, 500)); // true — timing logic tested (zero wall-clock wait, zero flakes)
// bad — Date.now embedded in logic (untestable without global mocking — parallel suites racing one clock)
// fix — Clock parameters (fake-timer/doubled clocks inject here — determinism by construction)
```

**Common confusion** — "fake timers test nothing real" — fake timers test *logic over time* (ordering, debounce, expiry — the parts that break); wall-clock tests timing *infrastructure* (CI speed — the part that flakes). "abort testing needs network" — abort is a *signal check* (pre/post-operation `aborted` reads — unit-testable without I/O). "restore is boilerplate" — unrestored fakes leak across files (global clock stuck — hundreds of false failures from one missing restore).

**Performance note** — fake-timer suites run in milliseconds regardless of simulated durations (hours simulated free); wall-clock equivalents cost real seconds per case (suite time linear in timeouts — the decay curve fakes delete).

**Mentor note** — suite-speed review: any `sleep(`/real-timeout in tests is a fake-timer candidate (mechanical conversion — clock seam + fake advance); track suite wall-time monthly (rising means new wall-clock tests slipped in).
