## 3.1. Testing generics and conditional types

### 1) **Instantiation spot-checks** (representative probes over distribution)

**Definition** — generics are tested by *instantiation*: pinning `F<Representative>` for each behaviorally-distinct input class — a concrete type (`string`), a union (`"a" | "b"` — distribution check), `never` (empty case), `unknown`/`any` (edge ingestion). The matrix mirrors the conditional's branch structure (one probe per branch — 09/2.1's naked-vs-wrapped rule verified per side).

**What problem it solves / history** — generics tested only at `<string>` (the demo instantiation) break on unions (forgotten distribution), `never` (unhandled empty), or `any` (liar-variance — see 08/3.1): consumers instantiate what demos never tried. Spot-check matrices enumerate the input classes that change behavior (not every type — the *branch-changing* ones).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), probe each generic with: concrete, union (distribution), `never`, `unknown`, `readonly`/optional variants where modifiers matter. Place matrices in `test-d` files (bulk without noise — see 1.1 part 3); keep one inline `Equal` per public generic (the advertised contract).

**Runnable example** — matrices over distribution (good vs bad, `tsc --strict`):

```typescript
// good — wrapped-vs-naked contrast pinned (the two forms side by side, behaviors distinguished)
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
type Distrib<T> = T extends string ? never : T; // naked (distributes per member)
type Whole<T> = [T] extends [string] ? never : T; // wrapped (whole-union verdict)
assertType<Equal<Distrib<"a" | 1>, 1>>(); // naked splits ("a"→never, 1→1 — union distributed)
assertType<Equal<Whole<"a" | 1>, "a" | 1>>(); // wrapped keeps (mixed union ≠ string — whole kept)
console.log("naked-wrapped-ok"); // naked-wrapped-ok — both forms pinned (contrast tested, not described)
// bad — testing one form (the other form's behavior assumed — naked/wrapped confusion per 09 review)
// fix — paired assertions (naked + wrapped probes adjacent — the rule AND its boundary, together)
```

```typescript
// good — never/unknown/any boundary instantiations (the three types breaking naive conditionals)
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
type IsNever<T> = [T] extends [never] ? true : false;
type Head<T> = T extends readonly [infer H, ...unknown[]] ? H : never;
assertType<Equal<Head<[1, 2]>, 1>>(); // concrete (happy path pinned first)
assertType<Equal<Head<[]>, never>>(); // empty (boundary pinned — empty tuple yields never, explicitly)
type HeadNever = Head<never>; // alias (avoids >>> closers — scanner-fragile, see leaf text)
assertType<IsNever<HeadNever>>(); // never-input (conditional over never is never — pinned, not assumed)
console.log("bounds-ok"); // bounds-ok — happy + empty + never (the triple every conditional owes)
 // bad — happy-path-only matrices (empty/never inputs untested — consumers hitting them discover the gap)
// fix — concrete + empty + never per conditional (three probes, branch-changing inputs covered)
```

**Common confusion** — "test every instantiation" — test *branch-changing* classes (concrete/union/never/unknown/any/modifier — the inputs flipping branches), not every concrete type (infinite, pointless). "distribution tests need libraries" — `Equal` + two assertions suffice (paired probes — libraries add messages, not capability). "wrapped-form probes are edge trivia" — wrapped-vs-naked is the #1 conditional bug class (09/2.1 — mainstream, not edge).

**Performance note** — instantiation probes cost one conditional evaluation each (microseconds); matrices of dozens stay trivial — the expensive generics (deep recursion per 08/3.2) get *capped* probes (depth-budgeted inputs — see 09/3.1 carve-outs), not exhaustive ones.

**Mentor note** — review template for any generic PR: "where are the union, never, and unknown probes?" — missing any of the three blocks the PR (mechanical, non-negotiable).

### 2) **Boundary instantiations** (never unknown any inputs as first-class probes)

**Definition** — the *boundary triple*: `never` (empty — conditionals over `never` yield `never` unless wrapped), `unknown` (top — accepted by every unconstrained parameter, exercising the body's weakest assumptions), `any` (liar — bidirectionally assignable, collapsing both conditional branches and variance checks). Each generic owes one probe per triple member.

**What problem it solves / history** — `any`-passing consumers collapse carefully-distributed conditionals (`Exclude<any, string>` is `never` — surprising, untested, production-breaking); `unknown` inputs hit unguarded bodies (assumptions valid only for concrete types); `never` results flow into sinks nobody probed (empty states crashing renderers). Boundary probes convert all three surprises into red lines at authoring time.

**Modern guidance** — for every public generic, assert: `F<never>` (usually `never` — pinned either way), `F<unknown>` (documents the top-type behavior — often the weakest useful result), `F<any>` (documents liar-collapse — usually `any` out, explicitly accepted). Comment *why* each boundary result is correct (boundaries encode design decisions — undocumented boundaries get "fixed" into regressions).

**Runnable example** — triple probes with documented verdicts (good vs bad, `tsc --strict`):

```typescript
// good — never-probe documenting empty behavior (verdict explicit, reason attached)
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
type Elem<T> = T extends readonly (infer E)[] ? E : never;
assertType<Equal<Elem<never>, never>>(); // never in → never out (empty stays empty — pinned with reason)
assertType<Equal<Elem<string[]>, string>>(); // concrete sanity (the normal case beside the boundary)
console.log("never-doc"); // never-doc — boundary verdicts documented (design decisions, not accidents)
// bad — never behavior undescribed (consumers discovering Elem<never> empirically — folklore per instantiation)
// fix — probe + reason comment per boundary (verdicts specified where reviewers see them)
```

```typescript
// good — unknown-probe documenting top behavior (weakest input, weakest useful output)
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
type Keys<T> = keyof T;
assertType<Equal<Keys<unknown>, never>>(); // unknown has no known keys (verdict: never — documented limitation)
console.log("unknown-doc"); // unknown-doc — top-type verdicts (honest limits, specified upfront)
// bad — unknown inputs untested (keyof-unknown assumptions surfacing in consumers — never in authors)
// fix — unknown probe per object-generic (top behavior specified at authorship, not discovery)
```

```typescript
// good — any-probe documenting liar-collapse (accepted explicitly, never accidentally)
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
type Unpack<T> = T extends Promise<infer U> ? U : T;
assertType<Equal<Unpack<string>, string>>(); // concrete (pass-through pinned)
assertType<Equal<Unpack<Promise<number>>, number>>(); // wrapped (extraction pinned)
// Unpack<any> collapses to string | number — liar-collapse documented here, probed in test-d with the verdict the team accepts
console.log("any-doc"); // any-doc — liar behavior named (any-inside means verdicts are team decisions, recorded)
// bad — any instantiations forbidden-but-unprobed (consumers passing any anyway — behavior unspecified, incidents unowned)
// fix — any probe with an accepted verdict (collapse documented — the team OWNS the liar case)
```

**Common confusion** — "`any` probes legitimize `any`" — probing documents *behavior under* `any` (inevitable at boundaries); banning `any` *inputs* stays lint's job (different layers — 03/2.1 budgeting vs boundary specification). "never probes are vacuous" — `never` verdicts encode empty-state design (sink shapes, exhaustive remainders — 07/3.2 machinery depending on them). "unknown equals any here" — `unknown` is honest-top (checked, narrowable); `any` is liar-top (unchecked, collapsing) — probe both, verdicts differ.

**Performance note** — boundary probes are single instantiations (cheapest tests in the file); document verdicts inline (one comment each — review-time cost only).

**Mentor note** — the triple is a checklist item, not a judgment call: every generic review ends with "never? unknown? any?" (three answers, three probes, merged).

### 3) **Snapshot vs assertion discipline** (hover text rots, Equal specifies)

**Definition** — *snapshot* type tests record hover/expanded text (`// @snapshot: "{ a: string; b: number; }"` — string-compared on re-check); *assertion* tests evaluate predicates (`Equal`, `Extends` — semantic, formatting-independent). Snapshots break on cosmetic changes (hover rendering, property order, alias expansion); assertions break only on semantic drift.

**What problem it solves / history** — snapshot suites approve semantic widening (developer updates the snapshot text blindly — "update snapshots" as a reflex, the 5.1 widened-return incident) while failing on formatter upgrades (expanded-vs-aliased rendering churn — noise PRs touching hundreds of snapshots). Assertions invert the signal: quiet on cosmetics, loud on drift.

**Modern guidance** — default to `Equal`/`Extends` assertions (semantic — formatting-proof); use snapshots only for *error-message* contracts (message text IS the product — 16/twoslash docs, CLI diagnostics) with explicit per-snapshot review (never bulk-update). Ban bulk `--update` on type snapshots in CI (each hunk human-approved, like migration diffs).

**Runnable example** — semantic vs textual (good vs bad, `tsc --strict`):

```typescript
// good — assertion surviving cosmetics (alias vs expansion irrelevant — semantics pinned)
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
type Point = { x: number; y: number };
type Alias = Point; // cosmetic alias (hover may show Point or { x; y } — both fine)
assertType<Equal<Alias, { x: number; y: number }>>(); // semantic (passes regardless of hover rendering)
console.log("semantic-ok"); // semantic-ok — cosmetics-proof (formatter/lib upgrades never touch this line)
// bad — snapshot on hover text (expansion-vs-alias churn failing the suite on toolchain upgrades)
// fix — Equal assertions (meaning tested, rendering ignored — signal without noise)
```

```typescript
// good — widening caught (the case snapshots approve blindly)
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
function level(): "low" | "high" { return "low"; }
assertType<Equal<ReturnType<typeof level>, "low" | "high">>(); // widening to string breaks HERE (no snapshot to blindly update)
console.log(level()); // low — drift loud (the assertion names the contract; updates require deliberation)
// bad — snapshot updated with the widening (—update flag approving string — downstream switches silently non-exhaustive)
// fix — assertions for contracts (updates are contract changes — reviewed as such, never bulk-approved)
```

**Common confusion** — "snapshots are easier to write" — easier to write, harder to *review* (text diffs hide semantic moves — review cost exceeds writing savings by the second incident). "assertions can't capture complex shapes" — `Equal` captures *any* shape semantically (nested, generic, conditional — precision without text). "bulk-update is standard practice" — bulk-update is standard *behavior-test* practice (screenshots, serializers); type contracts need per-change deliberation (different assets, different rules).

**Performance note** — assertions evaluate at check time (microseconds each); snapshot files grow linearly with shape text (parse + compare per run — slower AND noisier; assertions win both axes).

**Mentor note** — CI rule: type-snapshot `--update` flags fail the build (updates happen locally, hunk-by-hunk, with contract justification in the PR description).
