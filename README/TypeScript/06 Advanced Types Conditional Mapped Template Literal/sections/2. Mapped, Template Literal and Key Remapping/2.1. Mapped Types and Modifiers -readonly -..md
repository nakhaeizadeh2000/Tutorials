## 2.1. Mapped Types and Modifiers (-readonly, -?)

### 1) **Definition** ({[K in keyof T]: ...})

**Definition** — A mapped type iterates `keyof T` and transforms each property: `{ [K in keyof T]: U }`. With modifiers `readonly`, `?`, `-readonly`, `-?` you can add/remove them.

```typescript
type User = { id: string; name: string; age: number; };

// Partial homomorphic (preserves optionality structure)
type MyPartial<T> = { [K in keyof T]?: T[K] };
type MyReadonly<T> = { readonly [K in keyof T]: T[K] };

// remove modifiers (minus prefix)
type Mutable<T> = { -readonly [K in keyof T]: T[K] };
type RequiredLike<T> = { [K in keyof T]-?: T[K] }; // remove ?
let m: Mutable<Readonly<User>> = { id: "1", name: "Ava", age: 30 };
m.name = "Ada"; // now writable after -readonly

// homomorphic vs non-homomorphic
type Homomorphic<T> = { [K in keyof T]: T[K] }; // homomorphic — preserves optional/readonly from T
type NonHomomorphic = { [K in "a" | "b"]: number }; // not iterating keyof, fresh
```

Homomorphic mapped types preserve `?`/`readonly` unless modified — key for `Partial` semantics vs fresh object.

### 2) **Example** (Partial impl)

```typescript
type UserOpt = Partial<User>; // { id?: string; name?: string; age?: number }

// manual equivalent:
type ManualPartial<T> = { [K in keyof T]?: T[K] };

// as const + mapped modifiers for readonly tuple of objects
type Freeze<T> = { readonly [K in keyof T]: T[K] };
let frozen: Freeze<User> = { id: "1", name: "Ava", age: 30 } as Freeze<User>;
// frozen.name = "Ada"; // error — readonly

// add getters
type Getters<T> = { [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K] };
type UserGetters = Getters<User>; // getId, getName, getAge (with Key Remapping — see 2.3)

// preserve modifiers explicitly via +? / -?
type Concrete<T> = { [K in keyof T]-?: T[K] }; // remove all ?
let concrete: Concrete<Partial<User>> = { id: "1", name: "Ava", age: 30 } as Concrete<Partial<User>>; // now required
```

### 3) **Use** (homomorphic)

Use homomorphic mapping when you want utility types that feel native (`Partial` keeps optionality vs Required removing it). Non-homomorphic (`Record`) is for fresh shapes:

```typescript
// homomorphic preserves readonly — good for Reflect utilities
type ROUser = Readonly<User>; // homomorphic behind
type MutableUser = { -readonly [K in keyof ROUser]: ROUser[K] };

// Record (non-homomorphic) — creates new dict type, doesn't preserve
type Dict = Record<"a"|"b", number>; // { a: number; b: number } fresh

// bad: manually rewriting instead of mapped type — drifts
type ManualUserPartial = { id?: string; name?: string; age?: number }; // duplicates User
// good: derive
type Derived = Partial<User>; // synced
```

### Common confusion

- "`-?` removes undefined" — no, it removes *optional* flag (`?:`). `string | undefined` stays.
