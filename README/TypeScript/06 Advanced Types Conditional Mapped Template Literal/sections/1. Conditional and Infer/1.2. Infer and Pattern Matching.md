## 1.2. Infer and Pattern Matching

### 1) **Definition** (infer R)

**Definition** — `infer` inside a conditional `extends` captures the *inferred* type that makes the pattern match: `T extends (infer U)[] ? U : never` extracts array element `U`. It is pattern-matching at type level.

```typescript
// ReturnType (from lib) — infer the return
type MyReturnType<T> = T extends (...args: unknown[]) => infer R ? R : never;
type A = MyReturnType<() => string>; // string
type B = MyReturnType<(x: number) => number[]>; // number[]

// Param extraction
type FirstArg<T> = T extends (x: infer A, ...args: unknown[]) => unknown ? A : never;
type F = FirstArg<(x: string, y: number) => void>; // string

// Array element (distributive variant)
type Elem<T> = T extends (infer U)[] ? U : T;
type E = Elem<string[]>; // string
type E2 = Elem<number>;  // number (no match → fallback)
```

Position matters — `infer` must be inside the `extends` pattern's *success branch*.

### 2) **Example** (ReturnType)

```typescript
// ReturnType vs manual
function foo(): { id: string; name: string } { return { id: "1", name: "Ava" }; }
type FooReturn = ReturnType<typeof foo>; // { id: string; name: string }

// Promise unwrap
type AwaitedNice<T> = T extends Promise<infer U> ? AwaitedNice<U> : T;
type P = AwaitedNice<Promise<string>>; // string
type P2 = AwaitedNice<Promise<Promise<number>>>; // number (recursive infer)

// tuple head/tail
type Head<T extends readonly unknown[]> = T extends readonly [infer H, ...unknown[]] ? H : never;
type Tail<T extends readonly unknown[]> = T extends readonly [unknown, ...infer R] ? R : [];
type H = Head<[1,2,3]>; // 1
type T2 = Tail<[1,2,3]>; // [2,3]

// string parsing (template literal + infer)
type ExtractId<S> = S extends `user:${infer Id}` ? Id : never;
type Id = ExtractId<"user:123">; // "123"
type Id2 = ExtractId<"post:123">; // never (no match)
```

### 3) **Bad** (infer in wrong position)

**Bad — placing `infer` outside pattern or in fallback:**

```typescript
// bad: infer not in extends pattern
// type Bad<T> = infer U extends T ? U : never; // syntax error

// bad: using infer in else branch — never captures
type Bad2<T> = T extends string ? string : infer U; // error — infer only in success pattern

// bad: infer without constraining shape — captures too wide
type CapturesWide<T> = T extends infer U ? U : never; // U is just T (no parsing)
type C = CapturesWide<string | number>; // string | number — pointless

// good: infer with structure
type CapturesRight<T> = T extends { data: infer D } ? D : never;
type CR = CapturesRight<{ data: string }>; // string
// type CR2 = CapturesRight<{ value: string }>; // never — pattern didn't match

// bad: greedy infer hides distribution — wrap if needed
type ToPromise<T> = T extends unknown ? Promise<T> : never;
type TP = ToPromise<string | number>; // Promise<string> | Promise<number> (distributed)
// if you wanted single Promise<string|number>, wrap T in tuple: [T] extends [unknown] ...
```

### Common confusion

- "`infer` declares a generic" — no, it's a *capture* inside the conditional. You can't reuse `infer X` outside that branch.
