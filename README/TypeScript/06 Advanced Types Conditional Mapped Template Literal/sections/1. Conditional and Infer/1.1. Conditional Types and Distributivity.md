## 1.1. Conditional Types and Distributivity

### 1) **Definition** (T extends U ? X : Y)

**Definition** — `T extends U ? X : Y` is a type-level `if`. The killer detail: *naked* type parameters distribute over unions (`T` alone on left of `extends`).

```typescript
type IsString<T> = T extends string ? true : false;

type A = IsString<string>; // true
type B = IsString<number>; // false
type C = IsString<"hi">;   // true (literal extends string)

// distributive: union members evaluated separately
type ToArray<T> = T extends unknown ? T[] : never;
type D = ToArray<string | number>; // string[] | number[] (not (string|number)[])
```

Distribution vs non-distribution table:

```typescript
type Dist<T> = T extends string ? "yes" : "no";
type A1 = Dist<"a" | 1>; // "yes" | "no" (distributed)

type NonDist<T> = [T] extends [string] ? "yes" : "no";
type A2 = NonDist<"a" | 1>; // "no" — wrapped in tuple, no distribution

// intentional vs accidental distribution
type FilterString<T> = T extends string ? T : never; // distributive — extracts strings from union
type F = FilterString<"a" | 1 | "b" | true>; // "a" | "b"
```

---

### 2) **Distributive** (naked T distributes)

The rule: when checking `T extends U ? X : Y`, if `T` is a *naked* type parameter (just `T`, not `[T]`/`T&...`), the union distributes. This is how built-ins like `Exclude`/`Extract` work:

```typescript
// Exclude implementation (from lib)
type MyExclude<T, U> = T extends U ? never : T;
type E = MyExclude<"a" | "b" | 1, string>; // 1 (strings excluded via distributive never)

// control distribution with brackets
type ToNonDist<T> = [T] extends [string] ? true : false;
type ND = ToNonDist<"a" | 1>; // false — whole union checked as one

// distributive with inferred helpers (see 1.2)
type ElementType<T> = T extends (infer U)[] ? U : never;
type Elem = ElementType<string[] | number[]>; // string | number (distributive over union of arrays)
```

---

### 3) **Mistake** (forgot bracket)

**Common mistakes:**

- Forgetting distributivity produces surprising union explosion.
- Wanting to keep union whole but writing naked `T extends ...`.
- Misreading `never` on distribution — when a branch yields `never`, it disappears from the union (so `Exclude` can filter).

```typescript
// bad: expected whole-union check but got distribution
type IsNeverBad<T> = T extends never ? true : false;
type X1 = IsNeverBad<never>; // never (!) — distributive over empty union yields never, not true
// good: wrap to keep whole
type IsNeverGood<T> = [T] extends [never] ? true : false;
type X2 = IsNeverGood<never>; // true

// bad: distribution when you wanted mapping
type BadBox<T> = T extends unknown ? { value: T } : never;
type B1 = BadBox<string | number>; // {value:string} | {value:number} — maybe you wanted {value: string|number}
type GoodBox<T> = { value: T }; // keep whole

// symptom: type collapses to never unintentionally
type Bug<T> = T extends string ? T : never;
type B2 = Bug<string | number>; // string (number dropped) — often intent, but surprise if you expected string|number itself
```

**Common confusion** — See pitfalls in this leaf; reinforce with targeted PR comment.

**Performance note** —

Deeply nested distributive conditionals can blow recursion limit (default 100 in `tsc`); keep depth shallow or use tail-recursion via tuple accumulation.

**Mentor note** —

Teach distributivity with a visual: "naked T = loop over union members." Show `ToArray<string|number>` before/after bracketing — one demo locks the concept.
