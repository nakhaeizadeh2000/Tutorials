## 3.1. this Parameter and Callback Variance

### 1) **Definition** (this: void)

**Definition** — Every function type can declare a fake first param `this:` to state what `this` must be when called. It is erased at emit and affects checking only. Use `this: void` to forbid `this` usage (e.g., callbacks that should not rely on dynamic `this`).

```typescript
// this param — erased, not a real argument
function greet(this: { name: string }, greeting: string): string {
  return `${greeting} ${this.name}`;
}
const ctx = { name: "Ava", greet };
console.log(ctx.greet("Hi")); // this is ctx
// greet("Hi"); // error — this not provided
// greet.call({ name: "Ada" }, "Hello"); // ok — provided via call

// callback that must not use this
type NoThisCb = (this: void, x: number) => void;
function forEachNum(arr: number[], cb: NoThisCb): void {
  for (const n of arr) cb(n);
}
forEachNum([1,2], function (this: void, n) {
  console.log(n); // this is void — using this is error
});

// useDefineForClassFields affects this in classes — see 05
```

With `noImplicitThis` (in `strict`), missing `this` annotation where `this: any` would otherwise be inferred becomes an error.

### 2) **Pitfall** (this loss in callback)

```typescript
class Counter {
  count = 0;
  increment() { this.count++; } // method uses this
  // bad: pass method as callback — this lost
  getCallbackBad(): () => void {
    return this.increment; // caller does: const f = counter.getCallbackBad(); f() — this is undefined in strict
  }
  // good: arrow captures this lexically
  incrementArrow = () => { this.count++; };
  // good: bind
  getCallbackGood(): () => void {
    return this.increment.bind(this);
  }
}

const c = new Counter();
const bad = c.getCallbackBad();
// bad(); // TypeError or count is NaN — this not Counter
const good = c.incrementArrow;
good();
console.log(c.count); // 1

// lint trap: type system can't prevent all this-loss; prefer arrow/bind pattern
type Method = (this: Counter, x: number) => void;
function takes(cb: Method): void { /* ... */ }
// takes(c.increment) // error — unbound method not compatible with this: Counter unless bound
```

### 3) **Fix** (arrow or bind)

**Fix rules:**

- For callbacks passed around, use arrow functions or `.bind(this)`.
- Type callbacks with `this: void` if they must be context-free (pure).
- In classes, prefer arrow fields for handlers passed to event emitters (`onClick = () => {}`) — trades per-instance allocation for correctness (see 05 for perf trade).
- Enable `strict` + `noImplicitThis` — checker flags `this: any`.

```typescript
// fix: arrow vs bind
class Emitter {
  handlers: ((this: void, x: number) => void)[] = [];
  on(handler: (this: void, x: number) => void): void { this.handlers.push(handler); }
  emit(x: number): void { for (const h of this.handlers) h(x); }
}
class Listener {
  id = "L1";
  // bad method — would need bind
  onEventBad(x: number): void { console.log(this.id, x); }
  // good arrow — no this param needed beyond class
  onEventGood = (x: number): void => { console.log(this.id, x); };
}
const emitter = new Emitter();
const listener = new Listener();
// emitter.on(listener.onEventBad); // error — this mismatch if emitter expects this: void
emitter.on(listener.onEventGood); // ok — arrow ignores this
emitter.on(function(this: void, x) { console.log("plain", x); }); // ok
```

Demo `this` loss with a failing test in watch mode — the fix (arrow) is one character. Once students see arrow vs method allocation trade, they stop cargo-culting either.

### Common confusion

- "`this` param passed at call" — no, it's never an argument; `fn.call(thisArg, ...args)` supplies it. Arrow functions have no `this` param.
