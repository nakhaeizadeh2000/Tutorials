## 3.2. Async Functions and Promise Typing

### 1) **Definition** (Promise<T>)

**Definition** — `async` function always returns `Promise<T>` where `T` is the `return` type; `await` unwraps `Promise<U>` to `U`. `Promise` is generic — avoid `Promise<any>`.

```typescript
async function fetchUser(id: string): Promise<{ id: string; name: string }> {
  const res = await fetch(`/api/users/${id}`);
  const data: unknown = await res.json();
  // validate (see 01 2.2)
  if (typeof data !== "object" || data === null || !("name" in data)) throw new Error("bad");
  return { id, name: (data as { name: string }).name };
}
// inferred return Promise<{ id: string; name: string }>
let p: Promise<{ id: string; name: string }> = fetchUser("1");

// non-async promise creator
function delay(ms: number): Promise<void> {
  return new Promise(resolve => setTimeout(resolve, ms));
}

// await in async context
async function demo(): Promise<void> {
  await delay(10);
  const user = await fetchUser("1");
  console.log(user.name);
}

// then chaining — type flows
fetchUser("1").then(u => u.name.toUpperCase()); // u inferred
```

### 2) **Example** (typed async)

```typescript
// typed async with error handling
type Result<T> = { ok: true; value: T } | { ok: false; error: string };

async function safeFetchUser(id: string): Promise<Result<{ name: string }>> {
  try {
    const res = await fetch(`/api/users/${id}`);
    if (!res.ok) return { ok: false, error: `HTTP ${res.status}` };
    const data: unknown = await res.json();
    if (typeof data !== "object" || data === null || !("name" in data)) {
      return { ok: false, error: "invalid shape" };
    }
    return { ok: true, value: { name: (data as { name: string }).name } };
  } catch (e) {
    return { ok: false, error: String(e) };
  }
}

// Promise combinators typed
async function combined(): Promise<void> {
  const [a, b] = await Promise.all([fetchUser("1"), fetchUser("2")]); // [User, User]
  const first = await Promise.race([fetchUser("1"), delay(100).then(() => ({ id: "3", name: "Race" }))]);
  console.log(a.name, b.name, first.name);

  const settled = await Promise.allSettled([fetchUser("1"), fetchUser("bad")]);
  for (const s of settled) {
    if (s.status === "fulfilled") console.log(s.value.name);
    else console.error(s.reason);
  }
}
```

### 3) **Mistake** (Promise<any>)

**Bad patterns:**

- `Promise<any>` — disables checking downstream `.then` and `await`.
- Forgetting `await` — `const user = fetchUser("1")` is `Promise<User>`, not `User`; accessing `user.name` is error/undefined.
- `async` without `await` returning `Promise<Promise<T>>` nesting (async automatically unwraps).

```typescript
// bad: any propagates
async function bad(): Promise<any> { return { name: "Ava" }; }
let x = await bad(); // any — x.name not checked
// x.nonexistent // no error — bug

// good: explicit Promise<T>
async function good(): Promise<{ name: string }> { return { name: "Ava" }; }
let y = await good(); // { name: string }
y.name.toUpperCase(); // checked

// bad: missing await
function forgot(): void {
  const userPromise = fetchUser("1"); // Promise<User>
  // console.log(userPromise.name); // error — property name missing on Promise — but if typed any, slips
  userPromise.then(u => console.log(u.name)); // correct
}

// bad: double promise from async wrapping
async function doubleBad(): Promise<Promise<string>> {
  return Promise.resolve("hi"); // actually Promise<string> (async unwraps)
}
// good: just Promise<string>
async function doubleGood(): Promise<string> {
  return "hi"; // auto-wrapped
}
```

### Mentor note

Require every `async` PR to show either `Result<T>` pattern or `try/catch` with typed error handling. Raw `Promise<T>` with unhandled rejection is a production incident waiting.

### Common confusion

- "`await` blocks thread" — no, it yields microtask queue (see JS 13); `async` makes sequential code ergonomic, not multi-threaded.
