## 2.1. Overload Signatures (when overloads help)

### 1) **Definition** (multiple call shapes)

**Definition** — An overload set declares multiple *call signatures* + one *implementation signature* that must be compatible with all overloads. At call site, checker picks the matching overload for return type narrowing.

```typescript
// overloads — caller sees precise return per arity
function format(value: string): string;
function format(value: number): string;
function format(value: Date): string;
function format(value: string | number | Date): string {
  if (value instanceof Date) return value.toISOString();
  return String(value);
}
format("hi"); // string
format(42);   // string
// format(true) // error — not in overload set, even though impl accepts Date|...

// generic without overload would widen return
function formatLoose(value: string | number | Date): string { return String(value); }
// no per-input narrowing — always string anyway here, but for differing returns overload matters:
function pick(value: string): string;
function pick(value: number): number;
function pick(value: string | number): string | number { return value; }
const s = pick("hi"); // string, not string|number
const n = pick(123);  // number
```

Overload vs generic vs union param decision: union param returns union; overload returns precise per input; generic captures caller literal.

### 2) **Good** (narrow overloads)

**Good — overloads when return or behavior changes with args:**

```typescript
// good: overload narrows return
function parse(input: string): string[];
function parse(input: string[]): string[];
function parse(input: string | string[]): string[] {
  return typeof input === "string" ? [input] : input;
}
const a = parse("hi"); // string[]
const b = parse(["hi"]); // string[]

// good: arity-based overload instead of optional ambiguous
function makeRange(from: number, to: number): number[];
function makeRange(count: number): number[];
function makeRange(a: number, b?: number): number[] {
  if (b === undefined) return Array.from({ length: a }, (_, i) => i);
  return Array.from({ length: b - a + 1 }, (_, i) => a + i);
}
makeRange(3);     // [0,1,2]
makeRange(2, 5);  // [2,3,4,5]

// good: branded overload for precision
type UserId = string & { __brand: "UserId" };
function find(id: UserId): { id: UserId; name: string } | undefined;
function find(name: string): { id: UserId; name: string } | undefined;
// impl combines with union and refines by check
```

Order overloads from most specific → most general (checker picks first match).

### 3) **Bad** (overload for union)

**Bad — overloading where union param suffices:**

```typescript
// bad: two overloads that both return same type — just use union param
function greetBad(name: string): void;
function greetBad(name: string | null): void;
function greetBad(name: string | null): void { console.log(name); }
// simpler:
function greetGood(name: string | null): void { console.log(name); }

// bad: overload to fake optional param
function fetchBad(url: string): Promise<string>;
function fetchBad(url: string, timeout: number): Promise<string>;
function fetchBad(url: string, timeout?: number): Promise<string> { /* ... */ return Promise.resolve(""); }
// better: optional param + default
function fetchGood(url: string, timeout = 5000): Promise<string> { return Promise.resolve(""); }

// bad: overload that accepts any via implementation loophole — implementation signature not checked as overload
function anyBad(x: string): string;
function anyBad(x: number): number;
function anyBad(x: any): any { return x; } // any leaks — should be (x: unknown) handling
// good impl:
function anyGood(x: string): string;
function anyGood(x: number): number;
function anyGood(x: string | number): string | number { return x; }
```

### Mentor note

Prefer union param when return doesn't change; overload when it does. Lint `unified-signatures` (typescript-eslint) flags unnecessary overloads.

### Common confusion

- "Overload impl signature is callable" — not directly. Only declared overloads are visible to callers; impl signature is internal and must be compatible with all overloads.
