## 2.2. Generic Functions and Constraints

### 1) **Definition** (<T extends string>)

**Definition** — Generics parameterize a function over types: `<T>` is a type argument supplied at call site (often inferred). `extends` constrains what `T` may be.

```typescript
function identity<T>(x: T): T { return x; }
let a = identity<string>("hi"); // explicit
let b = identity("hi");         // inferred T = string (literal "hi" unless widens)

function first<T>(arr: T[]): T | undefined { return arr[0]; }
let n = first([1, 2, 3]); // number | undefined

// constraint
function longest<T extends { length: number }>(a: T, b: T): T {
  return a.length >= b.length ? a : b;
}
longest("hi", "hello"); // string
longest([1,2], [1,2,3]); // number[]
// longest(1, 2) // error — number has no length

// default
type Result<T = string> = { value: T };
function wrap<T = string>(v: T): Result<T> { return { value: v }; }
wrap(42); // Result<number>
wrap(); // error unless overload/default handles absence — default only for omitted type arg
```

### 2) **Example** (generic factory)

```typescript
// factory that preserves literal types with constrained generic
function makePair<const T extends string, const U extends number>(a: T, b: U): [T, U] {
  return [a, b];
}
const p = makePair("GET", 200); // ["GET", 200] (const generic preserves literals — TS 5.0)

// constraint with keyof
function get<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}
const user = { id: "1", name: "Ava", age: 30 };
let n2 = get(user, "name"); // string
// get(user, "missing") // error — key not in User

// generic with intersection composition (03)
function withTimestamps<T extends object>(o: T): T & { createdAt: Date } {
  return { ...o, createdAt: new Date() };
}
let u = withTimestamps({ id: "1", name: "Ava" }); // { id, name } & { createdAt }
```

`const` type params (TS 5.0) infer `as const` automatically — avoids widening (see [02 1.2 as const](<../../../02%20Primitive%20Literal%20and%20Union%20Types/sections/1.%20Primitives%20and%20Literals/1.2.%20Literal%20Types%20and%20const%20Assertions.md>)).

**Common confusion** —

- "`<T extends string>` means T is subclass of string" — for primitives, it means "string literal subtype" (`"a"` extends `string` because literal is narrower).
- "Must always write `<T>` explicitly" — rarely. Let inference do the work; annotate only at boundaries.

**Performance note** —

Generics are erased; but complex generic instantiation depth affects `tsc` time (especially recursive conditionals — see 06). Keep constraints simple for hot type-level code.

**Mentor note** —

Teach generics as "type-level function parameters" — draw parallel `function f(x: string){}` vs `type F<T extends string> = ...`. Overload is about multiple call *shapes*, generic about *parameterizing* one shape.
