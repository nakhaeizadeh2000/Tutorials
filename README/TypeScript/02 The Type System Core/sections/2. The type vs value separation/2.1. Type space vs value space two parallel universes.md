## 2.1. Type space vs value space — two parallel universes

### 1) **Two spaces** (type names live in type space; values live in value space — they never collide)

**Definition** — TypeScript maintains two parallel namespaces. *Type space* contains `type` aliases, `interface` declarations, and type parameters. *Value space* contains `const`/`let`/`var` bindings, `function` declarations, and runtime objects. A name in one space shadows rather than collides with the same name in the other.

```typescript
// Two spaces, same identifier, no collision
type Config = { host: string; port: number }; // type space
const Config = { host: "localhost", port: 5432 }; // value space — different universe
// typeof Config in type space would query the VALUE's type; Config in value space is the object

// Access is space-dependent:
// type T = Config;        // type space — refers to interface shape
// const x = Config;       // value space — refers to object
```

This separation is why `type User = ...` and `const User = ...` can coexist in the same module (they inhabit different spaces) but `type User = ...` and `interface User = ...` conflict (both are type-space declarations).

### 2) **Same identifier, different meaning** (`class Point` declares both a value and a type simultaneously)

`class` is the canonical dual-declaration: it creates *both* a value (the constructor function + prototype) and a type (the instance shape). This is why `class` can appear in either space without qualification.

```typescript
class Point { constructor(public x: number, public y: number) {} }

// Value use: new Point(1, 2) — calls the constructor function
const p = new Point(1, 2);

// Type use: (pos: Point) — refers to instance shape { x: number; y: number }
function distance(a: Point, b: Point): number { return Math.hypot(b.x - a.x, b.y - a.y); }

// The two "Point" names are distinct but linked: the type IS the instance type of the value's construct
```

Other dual declarations: `enum E` (value object + type of its members, but non-erasable — avoid), `namespace` (value object + type space, also legacy). Prefer `class` as the only intentional dual-case; `interface`/`type` remain type-only.

### 3) **What can appear where** (type space allows `string`, `number`, `extends`; value space allows runtime expressions)

| Position | What is legal | Example |
|---|---|---|
| Type position (`: T`, `extends T`) | Type names, literal types, `keyof`, `typeof` (type query), `T[K]` | `type X = Pick<User, "name">` |
| Value position (`= expr`, `()` call) | Value names, expressions, `typeof` (JS operator) | `const y = typeof x` |

The keyword `typeof` is the notorious bridge with *two* meanings depending on space (see [2.3. Type queries](<./2.3. Type queries typeof keyof and indexed access.md>)):

```typescript
const user = { name: "Ada", age: 36 };
// Value typeof: runtime operator → "object"
const kind: string = typeof user; // kind = "object" at runtime
// Type typeof: type query → { name: string; age: number }
type User = typeof user; // captures the variable's type — erased after emit
```

### 4) **Runnable example** — using both spaces correctly (good + bad)

```typescript
// good — leverage dual declaration for typed factories
class Cache { constructor(public size: number) {} }
function makeCache(size: number): Cache { // return type refers to instance type
  return new Cache(size); // value refers to constructor
}

// bad — confusing spaces: trying to use a type as a value
type Status = "pending" | "done";
// const s = Status; // error TS2693: 'Status' only refers to a type, but is being used as a value here.
// fix: use value space
const StatusValues = { Pending: "pending", Done: "done" } as const;
type Status = typeof StatusValues[keyof typeof StatusValues]; // type query bridges value → type

// bad — confusing value as type
const config = { host: "localhost" };
// type T = config; // error: 'config' refers to a value, but is being used as a type here.
// fix: query the type of the value
type Config = typeof config; // { host: string } — type query lifts value shape to type
```

### 5) **Common confusion**

- "`type` and `const` with the same name collide" — they don't. The spaces are distinct; `type X` and `const X` coexist as type and value bindings for the same identifier.
- "`class` is just a value" — it's both. `class Foo {}` creates a value `Foo` (constructor) and a type `Foo` (instance). `typeof Foo` is the *constructor type*; `Foo` alone in a type position is the *instance type*.
- "`typeof` does a runtime check" — only in value space. In type space, `typeof x` *captures* the static type of `x` without evaluating `x` at runtime — it erases.

### 6) **Performance note**

Type-space queries (`typeof`, `keyof`, `T[K]`) are zero-cost at runtime (erased). Overusing deeply nested queries (e.g., `typeof largeObj["deeply"]["nested"]["type"]`) can produce large hover types that slow the language server; naming intermediate `type` aliases keeps hovers concise (see [01/2.3 Language server](../../01%20Fundamentals%20and%20Mental%20Model/sections/2.%20How%20TypeScript%20doesnt%20execute/2.3.%20The%20language%20server%20editor%20superpowers%20that%20justify%20TypeScript.md>)).

### 7) **Mentor note**

Teach with "which space is this identifier in?" quizzes. Show a line and ask: "is `Point` here a type or a value?" — students who can answer instantly stop writing `typeof Point` when they meant `Point` and vice versa. Exercise: given `class Foo { }`, ask "what does `type X = Foo` vs `type Y = typeof Foo` mean?" — X is instance shape, Y is constructor shape.
