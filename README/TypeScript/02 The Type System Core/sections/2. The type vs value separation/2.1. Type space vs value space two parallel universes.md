## 2.1. Type space vs value space — two parallel universes

### 1) **Identify which meaning a use requires**

A type name describes a checked shape; a value name supplies something the program can evaluate. The same spelling can have both meanings. In `const selected: Config = Config`, the first Config is a type annotation and the second is a value expression. A type alias and a const with that name can coexist; two aliases with that name in the same scope cannot simply create two independent types.

Ask what the surrounding syntax requires before looking up the name. A parameter annotation needs a type. A function call or constructor invocation needs a value. Names also have scopes and declaration-combination rules; the two-space model does not mean every pair of declarations is permitted. The [declaration-space owner](<./2.2. Declaration spaces type value and namespace.md>) supplies those rules and namespace meanings.

### 2) **A class supplies an instance type and a constructor value**

A class declaration supplies an instance type in annotations and a constructor value in expressions. `typeof AppCache` in a type position queries the constructor's checked type. AppCache alone in a type position names its instances. Neither query constructs an object. The [declaration-file deep dive](https://www.typescriptlang.org/docs/handbook/declaration-files/deep-dive.html) uses these multiple meanings to explain exported APIs; this example observes them in an ordinary program.

Save `spaces.ts` in a directory without a tsconfig. Use TypeScript **7.0.2 / Node 20.20.2**, verified 2026-10-13:

```typescript
export {};
type Config = { host: string; port: number };
const Config = { host: "localhost", port: 5432 };
const selected: Config = Config;
console.log(selected.host, selected.port);

class AppCache {
  size: number;
  constructor(size: number) { this.size = size; }
}
function makeCache(size: number): AppCache { return new AppCache(size); }
type CacheConstructor = typeof AppCache;
const constructor: CacheConstructor = AppCache;
console.log(makeCache(3).size, new constructor(4).size);

const Status = { Pending: "pending", Done: "done" } as const;
type Status = typeof Status[keyof typeof Status];
const currentStatus: Status = Status.Done;
console.log(currentStatus);

const user = { name: "Ada", age: 36 };
type User = typeof user;
const second: User = { name: "Grace", age: 37 };
console.log(typeof user, second.name);
```

Run:

```bash
tsc --strict --target es2022 --module commonjs --lib es2022,dom --outDir dist spaces.ts
node dist/spaces.js
```

Both commands exit 0. Output:

```text
localhost 5432
3 4
done
object Grace
```

The module marker keeps these names local. AppCache avoids the unrelated browser Cache declaration. There is exactly one Status alias: its values come from the real const Status object. Using that one spelling in a type and a value position is intentional; declaring the alias again would be a different same-space collision.

Classes and ordinary enums supply type and value meanings. A namespace supplies qualified names, and may supply a runtime container when it contains values. It does not automatically supply a standalone type for the namespace itself. Save `namespace.ts`:

```typescript
export {};
namespace Protocol { export interface Message { text: string } }
const message: Protocol.Message = { text: "ping" };
console.log(message.text);
namespace RuntimeBox { export const value = 1; }
console.log(RuntimeBox.value);
```

Compile and run with the same flags, replacing spaces.ts with namespace.ts. Both commands exit 0 and the runtime prints `ping`, then `1`. Inspect `dist/namespace.js`: Protocol is absent, while RuntimeBox is emitted. The exported interface requires no runtime container; the exported value does. Checking namespace.ts with `tsc --strict --erasableSyntaxOnly --noEmit namespace.ts` reports TS1294, exit 1, at the value-bearing RuntimeBox. The same gate accepts spaces.ts. Use the [namespace owner](<../../../12 Modules Namespaces and Declaration Files/sections/2. Namespaces and Ambient Contexts/2.1. Namespaces organization and when to avoid.md>) for full namespace organization and migration.

### 3) **Type queries bridge meanings without runtime evaluation**

In spaces.ts, `type User = typeof user` captures the checked shape of a value. The runtime expression `typeof user` instead evaluates to the string `"object"`. They share a keyword, but their results belong to different parts of the program. The full `typeof`/`keyof`/indexed-access synthesis belongs to [type queries](<./2.3. Type queries typeof keyof and indexed access.md>).

Save `misuse.ts` as a separate rejection probe:

```typescript
export {};
type State = "pending" | "done";
const state = State;
const settings = { host: "localhost" };
type Settings = settings;
```

`tsc --strict --noEmit misuse.ts` reports TS2693 for State used as a value and TS2749 for settings used as a type, exit 1. This probe intentionally fails checking and is not a runnable example. Supply a real value when the program needs one; use `typeof settings` when the desired contract is the type of that value. Do not turn a type query into a runtime read of an erased alias.

### 4) **Common confusion**

A matching name does not guarantee matching content. The Config value is checked against its separately declared Config type at the assignment in this example; spelling alone does not make every runtime value satisfy a type. A class's constructor and instance are related but distinct contracts, so use `typeof AppCache` for the constructor and AppCache for an instance.

Namespace, type and value meanings also differ. A type-only namespace can qualify an interface without creating an object. If code needs a runtime property, its provider must actually exist. The [declaration-merging reference](https://www.typescriptlang.org/docs/handbook/declaration-merging.html) establishes the meanings of declaration kinds and legal combinations; do not infer merging from a name that happens to appear twice.

### 5) **Performance note**

Type aliases and type-position queries are erased, so they add no runtime object or query. The const objects, class construction and runtime typeof expression above still execute. A value-bearing namespace also contributes emitted JavaScript. No compiler/editor timing was measured; naming an intermediate type can improve explanation, but it is not a universal guarantee of faster checking. Investigate a measured build/editor problem in its owning tooling lesson.

### 6) **Mentor note**

Have the learner label each occurrence of Config, AppCache and Status in spaces.ts as a type or value use before running it. Then ask which of Protocol and RuntimeBox appears in JavaScript and why. A sound answer follows declarations and uses instead of treating every capitalized name as a runtime constructor.

During review, identify scope and required meaning before proposing an assertion or a rename. Ask the learner to repair the two rejected statements and explain whether the repair creates a value, captures a type or changes the contract. Reopening declarations and class API design need their linked owners rather than a blanket “names never collide” rule.
