## 2.3. Type queries — typeof, keyof, and indexed access

### 1) **Type-position typeof versus runtime typeof**

JavaScript's expression `typeof value` executes and returns a string. TypeScript's type-position `typeof value` refers to the value's static type at that program location. It creates no runtime inspection. A runtime condition can give the checker evidence to narrow a variable; the JavaScript engine does not change or maintain TypeScript types.

Compare `console.log(typeof config)` with `type Config = typeof config` in the complete example below. The first logs `object`. The second supplies a reusable type that disappears from JavaScript. Type queries are limited to supported identifier/property forms; `typeof makeConfig()` is not the syntax for obtaining a function's return type. The [primary typeof reference](https://www.typescriptlang.org/docs/handbook/2/typeof-types.html) explains that boundary.

### 2) **Keyof and indexed access**

`keyof T` describes keys available in the static contract `T`. `T[K]` obtains the type of a member or union of members selected by a key type. Neither operation enumerates an object's runtime properties.

For `{ 0: string }`, the key type is the numeric literal `0`, rather than all numbers. A numeric index signature instead gives `number`; a string index signature gives `string | number`. Declared symbol keys can contribute their symbol types. These distinctions follow the [keyof reference](https://www.typescriptlang.org/docs/handbook/2/keyof-types.html). A class's declared prototype methods can also belong to its instance key type, so “own enumerable keys” is the wrong model. The [object-query application](<../../../04 Objects Interfaces and Type Aliases/sections/2. Composition and Declaration Merging/2.3. Type queries on objects keyof indexed access and typeof capture.md>) develops enumeration and ownership in detail.

### 3) **Synthesis**

Use TypeScript 7.0.2 and Node.js 20.20.2. Save `queries.mts` in an empty directory. The small `Equal`/`Expect` helpers make the intended type results checked assertions; they are not runtime tests.

```typescript
// queries.mts
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
const config = { host: "localhost", port: 5432 } as const;
type Config = typeof config;
type Keys = keyof Config;
type Values = Config[Keys];
type KeyCheck = Expect<Equal<Keys, "host" | "port">>;
type ValueCheck = Expect<Equal<Values, "localhost" | 5432>>;
type NumericLiteral = Expect<Equal<keyof { 0: string }, 0>>;
type NumericIndex = Expect<Equal<keyof { [key: number]: string }, number>>;
type StringIndex = Expect<Equal<keyof { [key: string]: boolean }, string | number>>;
const key = "port";
type Port = Config[typeof key];
type PortCheck = Expect<Equal<Port, 5432>>;
const port: Port = config[key];
console.log(typeof config, port, Object.isFrozen(config));

function describe(value: unknown): string {
  if (typeof value === "number") {
    type Inside = Expect<Equal<typeof value, number>>;
    return value.toFixed(1);
  }
  type Outside = Expect<Equal<typeof value, unknown>>;
  return "other";
}
console.log(describe(42), describe("42"));
```

```sh
tsc --strict --target ES2022 --module NodeNext --noEmitOnError --outDir dist queries.mts
node dist/queries.mjs
```

Output:

```text
object 5432 false
42.0 other
```

`typeof config` captures the readonly literal property view produced by `as const`. `keyof` obtains the two key literals; indexed access collects their value types. `typeof key` supplies a type for the value named `key`. By contrast, `config[key]` is executed JavaScript that reads 5432. The runtime guard and `toFixed` call also remain in the output.

The `false` establishes that `as const` did not freeze the object. Literal precision is useful for a fixed table, but a contract intended to accept several ports should not require only 5432. Const assertions and widening have their [own lesson](<../../../03 Basic Types and Annotations/sections/3. Annotations Inference and Literals/3.3. Literal types and const assertions.md>).

Append one independent negative probe at a time, compile, then restore the original:

```typescript
type Missing = Config["debug"];
```

This reports TS2339 for a member absent from the contract, consistent with the [indexed-access reference](https://www.typescriptlang.org/docs/handbook/2/indexed-access-types.html). The following reports TS2322 because numeric literal key `0` does not include `1`:

```typescript
const wrongKey: keyof { 0: string } = 1;
```

A value name is not automatically a type name. This separate probe reports TS2538 and TS2749:

```typescript
type WrongIndex = Config[key];
```

Use `typeof key` as in the working program to obtain its type. Deriving a key type from a known value does not validate an arbitrary input string; the later object-query lesson supplies a bounded runtime membership example.

### 4) **Common confusion**

Type queries reuse static information, including narrowing known at a particular location. They do not recover hidden runtime fields, enumerate prototypes or construct a value from a type. For a literal `{ name: string }`, the declared key is `name`; that does not mean every possible object type excludes inherited methods.

Similarly, `Config[Keys]` is a type union, while `config[key]` is a value access. Reading a type expression aloud as a JavaScript operation obscures which work actually executes.

### 5) **Performance note**

Type aliases, queries and type assertions erase. Object construction, `Object.isFrozen`, runtime `typeof`, indexing and formatting still execute in this example. No checker or editor performance measurement was made. Naming a derived type can clarify intent, but is not by itself a demonstrated optimization.

### 6) **Mentor note**

Ask the learner to mark each `typeof` occurrence as an executed operation or an erased query. Then ask why `Config[typeof key]` accepts a value name indirectly while `Config[key]` fails. A sound explanation separates expressions from types and can identify the particular selected literal without relying on hover output.
