## 2.3. Type queries — typeof, keyof, and indexed access

### 1) **`typeof` in type space vs value space** (value `typeof x === "string"` is a runtime check; type `typeof x` is a type query)

**The ambiguous `typeof`** — The same keyword has two meanings distinguished by *position*:

| Position | Meaning | Produces | Erased? |
|---|---|---|---|
| Value position: `typeof x === "string"` | JS runtime operator | `string` value `"string"` at runtime | No — emitted as `typeof x` |
| Type position: `type T = typeof x` | Type query (capture the static type of `x`) | Type `T` | Yes — erased |

```typescript
const user = { name: "Ada", age: 36 };
// Value typeof: runtime check → "object" | "string" | ...
if (typeof user.name === "string") { /* narrow to string at runtime */ }

// Type typeof: static query → { name: string; age: number }
type User = typeof user; // query captures user’s inferred type (erased after emit)
// emit: const user = { name: "Ada", age: 36 }; — type User gone
```

Junior heuristic: if `typeof` appears *after `:`/`extends`/`= type`*, it's a type query; if it appears *before `===`/`!==`/in an expression*, it's the runtime operator.

### 2) **`keyof` and indexed access `T[K]`** (produce union of keys, or member type — two primitive type-level operators)

- **`keyof T`** — union of `T`'s own keys as string literal types (plus `number`/`symbol` for non-string keys).
- **`T[K]`** — indexed access; the type of member `K` of `T` (when `K extends keyof T`).

Together they are the atom of type-level programming because they *reflect* on a type without runtime cost.

```typescript
type User = { name: string; age: number; active: boolean };
type Keys = keyof User; // "name" | "age" | "active"
type NameType = User["name"]; // string
type AgeType = User["age"];   // number

// Generic pluck: composition of keyof + indexed access
function pluck<T, K extends keyof T>(obj: T, key: K): T[K] { return obj[key]; }
const u: User = { name: "Ada", age: 36, active: true };
const n = pluck(u, "name"); // type T[K] → string (checker proves pluck(u,"name") is string)
```

When combined with `typeof` + `as const`, they round-trip values to types without declarations:

```typescript
const DirectionValues = { Up: "Up", Down: "Down" } as const;
type Direction = typeof DirectionValues[keyof typeof DirectionValues]; // "Up" | "Down"
```

Every construct here erases — runtime still sees only `DirectionValues` as a plain object.

### 3) **Synthesis** (how `typeof`, `keyof`, `T[K]` and `as const` together enable type-level programming without runtime cost because they erase)

```typescript
// End-to-end: value → type → new type → back to value, all erased except the object
const StatusMap = { pending: 0, done: 1, failed: 2 } as const;
// typeof StatusMap → { readonly pending: 0; readonly done: 1; readonly failed: 2 }  (type query)
// keyof typeof StatusMap → "pending" | "done" | "failed"                           (keys)
// typeof StatusMap[keyof typeof StatusMap] → 0 | 1 | 2                             (member values)
// All three lines erase — runtime sees only const StatusMap = { pending: 0, done: 1, failed: 2 };
type StatusKey = keyof typeof StatusMap; // "pending" | "done" | "failed" — erased
type StatusVal = typeof StatusMap[StatusKey]; // 0 | 1 | 2 — erased
```

Modern guidance — prefer `as const` + `typeof`/`keyof`/`T[K]` over duplicated string unions for enumerations (erasable and starving-safe, see [01/3.3](../../01%20Fundamentals%20and%20Mental%20Model/sections/3.%20Running%20TypeScript%20today/3.3.%20Choosing%20erasable%20syntax%20the%20zero-cost%20interop%20rule.md>)).

### 4) **Runnable example** — `typeof`/`keyof`/`T[K]` trio (good + bad)

```typescript
// good — precise typed access via trio (zero runtime overhead)
const config = { host: "localhost", port: 5432, debug: false } as const;
type Config = typeof config;            // { readonly host: "localhost"; readonly port: 5432; ... }
type ConfigKeys = keyof Config;         // "host" | "port" | "debug"
function get<K extends keyof Config>(key: K): Config[K] { return config[key]; }
const host = get("host"); // type "localhost" (literal) — precise, not string
const port = get("port"); // type 5432

// bad — widening via missing as const, then losing precision
const configWidened = { host: "localhost", port: 5432 }; // widens to { host: string; port: number }
type ConfigWidened = typeof configWidened; // { host: string; port: number } — less precise than literal
// getWidened("host") is string, not "localhost" — lost literal via widening at declaration time

// bad — confusing value typeof with type query after runtime check
const x: unknown = 42;
if (typeof x === "number") { // value typeof guard — runtime narrow, x is number inside
  type T = typeof x; // captures the NARROWED type inside the block: number
}
// Outside the guard, typeof x is still unknown at the type level
```

### 5) **Common confusion**

- "`keyof` includes `toString`" — `keyof` for a plain `{ name: string }` returns only own keys (`"name"`), not prototype keys. For `keyof` on types with `number`/`symbol` keys, numeric keys appear as `number` and unique `symbol` keys as the specific `symbol` type.
- "`T[K]` allocates an object" — it's a type operator, erased. `T[K]` reads the member's type, not its runtime value.
- "`as const` allocates a different object" — `as const` is a type assertion that narrows the inferred literal type; runtime object is identical to plain `const` (just immutably typed).

### 6) **Performance note**

Deeply nested `T[K]` over recursive types (`DeepPartial<LargeConfig>[keyof DeepPartial<...>]`) can produce large union types that expand in hover and slow completions. Name intermediate results (`type PartialConfig = DeepPartial<LargeConfig>`) rather than nesting operators inline.

### 7) **Mentor note**

Teach `typeof` by position: show the same keyword first in `if (typeof x === ...)` and then in `type T = typeof x` and ask "which one erases?" — students who answer correctly stop confusing the two. Exercise: given `const obj = { a: 1, b: 2 } as const`, ask students to produce the union `"a" | "b"` and `1 | 2` in one line each — they should reach `keyof typeof obj` and `typeof obj[keyof typeof obj]`.
