## 7.1. Boundaries — what is covered elsewhere

### 1) **JavaScript mechanics** — [JavaScript track](../../JavaScript/README.md)

Value semantics, coercion, closure, prototype, iterables — the runtime behaviors that TypeScript types describe. For those mechanics themselves, use the JavaScript track: [03 Values Types and Coercion](../../JavaScript/03%20Values%20Types%20and%20Coercion/README.md), [04 Variables Scope and Closures](../../JavaScript/04%20Variables%20Scope%20and%20Closures/README.md), [06 Objects in Depth](../../JavaScript/06%20Objects%20in%20Depth/README.md), [07 Prototypes and Classes](../../JavaScript/07%20Prototypes%20and%20Classes/README.md). This domain describes their *type shapes*; it does not re-teach their execution.

### 2) **Basic type inventory** (`string`, `number`, `any`/`unknown`/`never`/`void`, literal types) — [03 Basic Types and Annotations](../03%20Basic%20Types%20and%20Annotations/README.md) (textual forward until it lands)

Primitive and special types (`any`, `unknown`, `never`, `void`, `object`, `unknown` narrowing) and annotation forms (`:` and inference, `as`, `satisfies`, `!`) will be inventoried in 03. This domain already introduced their *role* in the system (see [01/3.1](../../01%20Fundamentals%20and%20Mental%20Model/sections/1.%20What%20TypeScript%20is/1.2.%20Design%20goals%20and%20non-goals%20what%20TypeScript%20intentionally%20does%20not%20do.md) non-goals, [3.3. Unsound spots](<../3. Soundness and variance/3.3. Unsound by design spots budgeted risks.md>)), but leaves the per-type catalogue to 03 — no duplication.

### 3) **Utility types and type transformations** (mapped, conditional, `infer`, template literals) — [09 Utility Types and Type Transformations](../09%20Utility%20Types%20and%20Type%20Transformations/README.md) (textual forward)

Mapped types (`{ [K in keyof T]: ... }`), conditional types (`T extends U ? X : Y`), `infer`, and template literal types enable type-level computation on the shapes described here. Those operators live in 09; this domain only owns the *primitive* operators (`typeof`, `keyof`, `T[K]` — see [2.3.](<../2. The type vs value separation/2.3. Type queries typeof keyof and indexed access.md>)) and the variance model that constrains them.

### 4) **Configuration and variance flags** (`strictFunctionTypes`, `strictPropertyInitialization`, `noImplicitAny`, `exactOptionalPropertyTypes`) — [13 Configuration and Compiler Options](../13%20Configuration%20and%20Compiler%20Options/README.md) (textual forward)

Flags that change the system's strictness will be inventoried in 13. This domain notes the ones that affect variance and soundness (`strictFunctionTypes`, `strict` as a bundle) but leaves the per-flag trade-offs there. Until 13 lands, assume `strict: true` baseline (see [01/3.3](../../01%20Fundamentals%20and%20Mental%20Model/sections/3.%20Running%20TypeScript%20today/3.3.%20Choosing%20erasable%20syntax%20the%20zero-cost%20interop%20rule.md>)).

### 5) **Where this domain stops** (stop-list)

- **Stop:** Do not duplicate JavaScript mechanics, per-type inventories, utility-type transformations, or `tsconfig` flag catalogue.
- **Start here:** the assignability relation, freshness boundary, branding model, type/value/namespace separation, `typeof`/`keyof`/`T[K]` operators, and variance/soundness decisions — every later domain's formalism rests on these.
