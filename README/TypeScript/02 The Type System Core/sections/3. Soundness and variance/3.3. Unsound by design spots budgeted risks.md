## 3.3. Unsound by design spots — budgeted risks

### 1) **Array covariance** (`Dog[]` → `Animal[]` then `push(cat)` breaks `Dog[]` — `readonly` arrays are the safe alternative)

**The classic hole** — `Array<T>` is invariant in a sound system (reads covariantly, writes contravariantly). TypeScript treats `Dog[] ≤ Animal[]` as valid (covariant) for ergonomics, so mutating through the wider alias breaks the narrower one.

```typescript
// Covariant assignment permitted (unsound)
type Dog = string & { __brand: "Dog" };
type Animal = string;
let dogs: Dog[] = ["dog1" as Dog];
let animals: Animal[] = dogs; // ok (unsound — treated as covariant)
animals.push("animal" as Animal); // mutates dogs via alias
// dogs now contains a non-Dog Animal — downstream Dog-only code reads non-Dog as Dog

// fix: readonly prevents writes through covariant alias
let readonlyDogs: readonly Dog[] = dogs;
let readonlyAnimals: readonly Animal[] = readonlyDogs; // ok — reading Dogs as Animals is safe (covariant reads)
 // readonlyAnimals.push("x"); // error: push doesn't exist on readonly
```

Modern guidance — use `readonly` arrays at covariant boundaries (function parameters, returns, `ReadonlyArray<T>`). Keep `Array<T>` invariants inside the function that owns mutation.

### 2) **`any` and `as` escapes** (disable checking; `unknown` + predicate is the disciplined alternative)

| Escape | Effect | Budget |
|---|---|---|
| `any` | Compatible with every type; downstream also becomes `any` — leak is transitive | Count `any` per file; `// TODO(any)` with ticket |
| `value as T` | Replaces inferred type `typeof value` with `T` — trusted, not validated | One trusted site per `as`, justified by a predicate |

`unknown` is the budgeted alternative: it *forces* validation (see [01/2.2 Static vs runtime](../../01%20Fundamentals%20and%20Mental%20Model/sections/2.%20How%20TypeScript%20doesnt%20execute/2.2.%20Static%20checking%20vs%20runtime%20reality%20trust%20but%20verify.md>)).

### 3) **Type assertion narrowing** (type predicates `value is T` must be *proven* at runtime — a lying predicate breaks soundness globally)

A predicate is a promise that "if this returns true, `value` has type `T`". If the predicate lies, the liar infects every call site (transitive unsoundness). Treat predicates as security-critical code: test them, never write them as `return true as any` placeholders.

```typescript
// lying predicate — adds no runtime validation, promises everything is Dog
function isDogLying(value: unknown): value is string & { __brand: "Dog" } {
  return typeof value === "string"; // no Dog-specific check → lies for plain strings
}
// Every downstream `if (isDogLying(x)) { handleDog(x) }` is now unsound

// honest predicate — proves brand via prefix or lookup
function isDog(value: unknown): value is string & { __brand: "Dog" } {
  return typeof value === "string" && value.startsWith("dog-");
}
```

---

### 4) **Runnable example** — the three budgeted risks in one file (good + bad)

```typescript
// bad — three holes leaking at once
type Dog = string & { __brand: "Dog" };
function adoptAny(animals: string[]): void { // string[] is used where Dog[] expected via any
  const dogs: Dog[] = animals as unknown as Dog[]; // double escape via any/unknown
  dogs.push("any-string-not-a-dog" as Dog); // mutation through covariant alias
  for (const dog of dogs) console.log(dog.toUpperCase()); // may be non-Dog at runtime
}

// good — budgeted risks constrained: readonly + unknown + honest predicate
function isDog(value: unknown): value is Dog {
  return typeof value === "string" && value.startsWith("dog-");
}
function adoptChecked(input: unknown): readonly Dog[] {
  if (!Array.isArray(input)) throw new Error("not an array");
  // validate each element — array covariance doesn't matter because we don't alias mutably
  const dogs: Dog[] = [];
  for (const item of input) {
    if (!isDog(item)) throw new Error(`not a Dog: ${String(item)}`);
    dogs.push(item);
  }
  return dogs as readonly Dog[]; // widen to readonly for safe covariant return
}

// At runtime, adoptChecked("not-an-array" as unknown) fails fast; adoptAny silently corrupts
```

### 5) **Common confusion**

- "I've enabled `strict` so my code is sound" — `strict` closes `any`/`Function` leaks partially but leaves array covariance and `as` escapes. Soundness is a budget, not a flag.
- "Lying predicates are rare" — they happen when a predicate is written to satisfy the compiler (`return true`) then the runtime check is added later "when needed" and forgotten. Require tests per predicate at review.
- "`readonly` fixes covariance completely" — `readonly` fixes *array* covariance; nested mutable members (`{ value: T }` with read+write) still need `in out` or read-only wrappers (see [3.1. Covariance, contravariance](<./3.1. Covariance contravariance and invariance who varies which way.md>)).

### 6) **Performance note**

`readonly` has zero runtime cost (erased) and reduces checker work at call sites because the checker can treat the argument covariantly without checking invariant equivalence. Prefer `readonly` parameters on hot-path functions called with large array literals.

### 7) **Mentor note**

Treat unsoundness as a *budget review*: each PR, count `any`, `as`, mutable covariant array aliases, and predicates without tests. The same three questions repeat: "can this be `unknown` instead of `any`?", "can this be `readonly`?", "is this predicate proven?" Students who answer those correctly have internalized TypeScript's trust model. Exercise: given `dogs: Dog[]` passed to `fn(animals: Animal[])`, ask "does `fn` get to `push`?" — answer reveals whether they model array variance as covariant (yes, mutably, unsound) or as readonly.
