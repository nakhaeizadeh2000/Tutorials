## 1.1. Structural assignability — shape, not name

### 1) **Assignability by shape**

An assignment asks whether the source can supply the operations required by the target type. For ordinary object properties, the source needs each required property with an assignable type. Two interfaces can therefore be compatible without sharing a name or an inheritance declaration. This fits JavaScript APIs that accept objects created in many different ways.

This is an introduction to object compatibility, rather than a universal safety theorem. Function parameters, mutable aliases and private class members have additional rules. The [primary compatibility reference](https://www.typescriptlang.org/docs/handbook/type-compatibility.html#starting-out) explains the member comparison; the later variance lessons examine its limits.

### 2) **Width subtyping**

A source with additional properties can usually flow into a target that requires fewer properties. The narrower type exposes fewer operations to the checker. Assignment does not remove properties, clone the object or validate data arriving from an external system.

Use TypeScript 7.0.2 and Node.js 20.20.2. Save this complete program as `shape.mts` in an empty directory; no dependencies are needed.

```typescript
// shape.mts
interface Named { name: string }
interface Labeled { name: string }
function greet(value: Named): string { return `hi ${value.name}`; }

const detailed = { name: "Ada", role: "admin" };
const named: Named = detailed;
const labeled: Labeled = named;
console.log(greet(labeled));
console.log(named === detailed, "role" in named);

class Member {
  name: string;
  constructor(name: string) { this.name = name; }
}
console.log(greet(new Member("Lin")));

interface Config { server: { host: string } }
const extended = { server: { host: "localhost", port: 8080 } };
const config: Config = extended;
console.log(config.server.host, config.server === extended.server);
```

```sh
tsc --strict --target ES2022 --module NodeNext --noEmitOnError --outDir dist shape.mts
node dist/shape.mjs
```

Output:

```text
hi Ada
true true
hi Lin
localhost true
```

`Named` and `Labeled` describe the same required property. The `Member` instance also supplies it without an `implements` declaration. The two `true` values on the second line show that the narrower view still refers to the original object with its `role` property. Accessing `named.role` directly is nevertheless rejected, because the variable's declared type does not expose that property.

A directly written object literal receives an additional excess-property check. That creation-site check helps detect misspellings; it does not make every object type exact. [Freshness](<./1.2. Excess property checks and freshness.md>) owns the literal, spread and variable distinctions.

### 3) **Depth subtyping**

The checker also compares nested property types. `extended.server` supplies a string `host`, so the `Config` assignment succeeds. The final `true` shows that the nested object is shared too. Extra depth is not a reason to ignore incompatible members.

For separate negative checks, append **one** of the following lines to the working program, run the compiler command, and restore the original before trying another. Each check exits nonzero and `--noEmitOnError` prevents new output; previously emitted files can still exist.

```typescript
const missing: Named = { role: "admin" };
```

This reports TS2353 for the directly written unknown property. To isolate the missing required member from freshness, use this alternative instead:

```typescript
const source = { role: "admin" };
const missing: Named = source;
```

It reports TS2741 for the absent `name`. These additional independent checks report TS2322 and TS2339 respectively:

```typescript
const conflict: Config = { server: { host: 123 } };
```

```typescript
console.log(named.role);
```

Annotating a class with `implements Named` checks its instance shape and can catch a missing member at the class declaration. It does not add that member. A class `extends` clause also establishes JavaScript inheritance at runtime; do not describe it as an erased shape assertion. Interfaces can extend other interfaces without creating runtime inheritance.

### 4) **Common confusion**

A different alias name does not create a different identity: `type UserId = string` and `type OrderId = string` remain compatible strings. [Branding](<./1.3. Nominal typing techniques branding and opaque types.md>) introduces a deliberate distinction and a construction policy. Conversely, private/protected class members can constrain compatibility even when public properties look alike.

“More properties are accepted” also does not mean every mutation through a narrower view is safe. Shared mutable objects and arrays can invalidate assumptions held by another alias. [Variance](<../3. Soundness and variance/3.1. Covariance contravariance and invariance who varies which way.md>) develops that consequence. Start by asking which operations the receiving function actually needs; a small read-oriented contract is often easier to satisfy and review.

### 5) **Performance note**

The type annotation and compatibility check do not generate an object conversion. The assignment in the example shares the existing object. Actual copies, validation and class construction have their own runtime costs. Checker work depends on the compared types and project; neither a fixed member count nor a fixed nesting depth predicts its cost. Use the [measurement workflow](<../../../19 Performance Project References and Scaling/sections/1. Check-Time Performance/1.1. Measuring with extendedDiagnostics and traces.md>) before changing a design for compiler performance.

### 6) **Mentor note**

Ask the learner to name the source and target of `const named: Named = detailed`, then predict identity, the presence of `role` at runtime, and whether `named.role` checks. A sound answer distinguishes the original value from the narrower static view. Next change only the nested `host` to a number and ask which required operation becomes invalid; this tests reasoning beyond counting property names.
