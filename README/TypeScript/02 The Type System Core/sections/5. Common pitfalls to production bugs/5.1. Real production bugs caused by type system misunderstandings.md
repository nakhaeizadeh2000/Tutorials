## 5.1. Real production bugs caused by type system misunderstandings

### 1) **Fresh-vs-stale freshness escape** (excess property missed because it went through a variable)

**Incident** — API client builds request options with a typo: `const opts = { host, portt: 5432 }` (notice double `t`). Passed via `const merged = { ...defaults, ...opts }` into `connect(merged as Options)`. No checker error — freshness didn't apply (non-literal) and `as` suppressed the rest. Production connects to default port, not 5432; bug hides for weeks because the error path is "wrong port but still connects".

**Fix** — Type the intermediate: `const opts: Options = { host, portt: 5432 }` would fail immediately at the assignment, not at the distant `connect` call. Prefer fresh literals at call/return sites so excess checks fire.

### 2) **Covariant array mutation** (`Dog[]` → `Animal[]` then `push` breaks downstream `Dog`-only code)

**Incident** — Service returns `readonly Dog[]` but caching layer widens to `Animal[]` for a generic utility, then `animals.push(genericAnimal)` where `genericAnimal` is not a `Dog`. Dogs array now contains a non-Dog. Next `dogs.forEach(dog => dog.breed.toUpperCase())` throws `Cannot read properties of undefined`.

**Fix** — Use `readonly`:

```typescript
function cacheAnimals(animals: readonly string[]): void { /* reads only — safe covariant */ }
// callers cannot push through readonly — bug shifts from runtime error to compile-time error
```

### 3) **Predicate lies** (`value is T` that returns true for non-`T` — every downstream consumer inherits the lie)

**Incident** — `isUser(value: unknown): value is User { return typeof value === "object" && value !== null; }` — no member checks. Callers `if (isUser(payload)) { payload.email.send(...) }` assume `email` exists; 30% of payloads lack `email`, production throws.

**Fix** — Predicates must prove *all* members the downstream code accesses. Add tests per predicate and run them in CI as unit tests that assert predicate truth coincides with actual shape.

### 4) **Confusing `typeof` spaces** (`typeof x === "string"` guard vs `type T = typeof x` — mixing the two)

**Incident** — Refactor changes `type Config = typeof defaultConfig` after `defaultConfig` widens from `as const` to plain `const`. `Config` silently widens from `"localhost"` literal to `string`, breaking a discriminated default-port lookup that matched on `"localhost"` exactly. No checker error, runtime falls through to default port.

**Fix** — Retain `as const` on source values that feed `typeof` queries, or explicitly annotate the type where literal narrowing matters (e.g., `type Config = { host: "localhost" | string; }`).

### 5) **Mentor note**

Each incident maps to one checklist question (see [4.1. Checklist](<../4. Important points to remember/4.1. Type system core checklist mental models mentors insist on.md>)): "was freshness given a chance?", "is this array `readonly` at the covariant boundary?", "is this predicate proven?", "is this `typeof` in the intended space?" Train students to ask those after every runtime error — the answer points to the domain rule that was violated.
