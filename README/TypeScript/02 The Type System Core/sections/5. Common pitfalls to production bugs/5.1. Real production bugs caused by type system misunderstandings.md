## 5.1. Real production bugs caused by type system misunderstandings

These local reproductions show four failure patterns; they do not claim incident rates or a particular team's production history. Use TypeScript **7.0.2 / Node 20.20.2**, verified 2026-10-13. Save this complete program as `pitfalls.ts` in a directory without a tsconfig:

```typescript
export {};
type Options = { host: string; port?: number };
function portOf(options: Options): number { return options.port ?? 80; }
const typo = { host: "localhost", portt: 5432 };
console.log("variable port:", portOf(typo));
const checked = { host: "localhost", port: 5432 } satisfies Options;
console.log("checked port:", portOf(checked));

interface Animal { name: string }
interface Dog extends Animal { breed: string }
const dogs: Dog[] = [{ name: "Rex", breed: "lab" }];
const animals: Animal[] = dogs;
animals.push({ name: "Milo" });
try { for (const dog of dogs) console.log(dog.breed.toUpperCase()); }
catch (error: unknown) {
  if (!(error instanceof TypeError)) throw error;
  console.log("mutable alias: TypeError");
}
const freshDogs: Dog[] = [{ name: "Rex", breed: "lab" }];
const view: readonly Animal[] = freshDogs;
freshDogs.push({ name: "Dot", breed: "collie" });
console.log("readonly view length:", view.length);

type User = { email: string };
function isUserBad(value: unknown): value is User {
  return typeof value === "object" && value !== null;
}
function isUser(value: unknown): value is User {
  return typeof value === "object" && value !== null
    && "email" in value && typeof value.email === "string";
}
const raw: unknown = { error: "missing email" };
if (isUserBad(raw)) {
  try { console.log(raw.email.toUpperCase()); }
  catch (error: unknown) {
    if (!(error instanceof TypeError)) throw error;
    console.log("predicate: TypeError");
  }
}
console.log("checked predicate:", isUser(raw));

type Host = "localhost" | "remote";
function configuredPort(host: Host): number { return host === "localhost" ? 5432 : 443; }
const narrow = { host: "localhost" } as const;
const wide = { host: "localhost" };
console.log("same value:", narrow.host === "localhost" ? 5432 : 0,
            wide.host === "localhost" ? 5432 : 0);
wide.host = "other";
console.log("changed value:", wide.host === "localhost" ? 5432 : 0);
console.log("explicit contract:", configuredPort("remote"));
```

Run:

```bash
tsc --strict --target es2022 --module commonjs --lib es2022,dom --outDir dist pitfalls.ts
node dist/pitfalls.js
```

Both commands exit 0; the intentional runtime failures are caught. Output:

```text
variable port: 80
checked port: 5432
LAB
mutable alias: TypeError
readonly view length: 2
predicate: TypeError
checked predicate: false
same value: 5432 5432
changed value: 0
explicit contract: 443
```

### 1) **Fresh-vs-stale freshness escape**

The typo object supplies host but no port. It can flow through a variable into Options because the required shape fits; the optional port is absent, so portOf selects 80. No assertion is necessary for that escape. The corrected satisfies literal supplies port and returns 5432. Diagnose the object's actual keys, then check the literal where it is created.

A separate fresh-literal probe, `const options: Options = { host: "localhost", portt: 5432 };`, reports TS2561 under `tsc --strict --noEmit`, exit 1. It names a misspelled explicit property; a value carrying additional properties can still be structurally assignable. The [freshness owner](<../1. Structural typing/1.2. Excess property checks and freshness.md>) supplies the full contract. A spread is not a universal waiver for directly written excess properties; inspect which members are spread and which are newly written.

### 2) **Covariant array mutation**

The reproduced hazard starts with **mutable** Dog[]. TypeScript permits assigning it to Animal[], after which pushing an Animal without breed changes the same underlying array. The Dog-typed loop first prints LAB, then throws on the inserted value. That is the actual mutation path; it does not begin with an unchecked readonly-to-mutable assignment.

Changing the starting declaration to readonly Dog[] and assigning it to mutable Animal[] produces TS4104, exit 1. A push through a readonly array view produces TS2339, exit 1. A reader accepting `readonly Animal[]` therefore cannot perform that checked mutation through its parameter. It does not freeze the array: the remaining freshDogs alias pushes a real Dog, and the readonly view observes length 2.

Use readonly inputs for readers, and define ownership or copying when a stable snapshot is required. The [readonly-array reference](https://www.typescriptlang.org/docs/handbook/2/objects.html#the-readonlyarray-type) establishes the assignment direction; the [variance owner](<../3. Soundness and variance/3.1. Covariance contravariance and invariance who varies which way.md>) develops the broader compatibility reasoning.

### 3) **Predicate lies**

isUserBad accepts any non-null object while promising an email string. The error envelope passes that test, so the narrowed field access compiles and then throws. The complete isUser implementation checks the required field and rejects the same payload. The type predicate's declared return is trusted; its name or annotation does not prove the body.

Test every promised field with valid and invalid examples. Do not validate only the property the next caller happens to read if the returned type promises more. [Dan Vanderkam's predicate analysis](https://effectivetypescript.com/2024/02/27/type-guards/) also motivates verifying what a false result means. Full boundary/predicate reasoning belongs to [static checking and runtime evidence](<../../../01 Fundamentals and Mental Model/sections/2. How TypeScript doesnt execute/2.2. Static checking vs runtime reality trust but verify.md>) and the linked narrowing owner.

### 4) **Confusing a type change with a runtime value change**

The narrow and wide initializers both contain the same host value, so both runtime branches return 5432. Removing as const can change the inferred type; its erased syntax does not itself change the stored string. This fixture then makes the runtime cause explicit: wide.host is changed to other, and the branch returns 0.

For a contract that permits exactly localhost or remote, Host is a finite union. Assigning other to Host reports TS2322, exit 1. Writing `"localhost" | string` instead would collapse to string and admit every string; a live equality probe confirms that result on 7.0.2. Choose the intended values rather than suggesting a union that cannot express the restriction.

The [const-assertion reference](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-3-4.html#const-assertions) establishes the type-level behavior. The [type-query owner](<../2. The type vs value separation/2.3. Type queries typeof keyof and indexed access.md>) explains how typeof captures that inferred type. A runtime branch failure still needs an actual value or operation that causes it.

### 5) **Common confusion**

Readonly means a checked view cannot make certain writes; another mutable reference can still change the object. As const is also not a runtime freeze. Specify whether a consumer needs a reader view, a copy or runtime immutability, then verify that mechanism.

A successful type check can coexist with a runtime failure through mutable covariance or a trusted predicate. Conversely, a proposed incident may not compile at all, as the readonly-to-mutable case shows. Keep compiler rejection and executed mutation distinct when diagnosing a bug.

### 6) **Performance note**

The type declarations, readonly modifiers and assertions are erased. The ordinary runtime work remains: this fixture mutates arrays, checks a property and runs branches. Copying a collection or validating each element would add work proportional to what is processed, but no timing or universal checker-cost estimate was measured. Choose ownership and validation to establish the contract first; investigate a performance problem with representative measurements.

### 7) **Mentor note**

Ask the learner to trace which reference changes the dogs array and to identify the exact runtime operation responsible for the port fall-through. Then change only one starting condition: readonly source, complete predicate or finite host type. A sound explanation predicts the diagnostic or output for that specific change.

Review an incident description against an executable reproduction. Require the initial types, flags, mutation and failure site; reject explanations that attribute runtime changes to erased syntax or quote an error the shown program does not produce.
