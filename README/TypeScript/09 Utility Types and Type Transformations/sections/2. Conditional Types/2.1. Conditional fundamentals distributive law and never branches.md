## 2.1. Conditional fundamentals — distributive law and `never` branches

### 1) **The distributive law, completely** (naked `T` maps member-by-member)

**Definition** — `T extends U ? X : Y` distributes when `T` is a *naked* type parameter: with `T = A | B`, the checker evaluates `(A extends U ? X : Y) | (B extends U ? X : Y)` — each member decides independently and survivors reunite in a union. [08 Generics](<../../../08 Generics Deep Dive/README.md>) previewed the rule in [2.3. infer](<../../../08 Generics Deep Dive/sections/2. Constraints Defaults and Inference Control/2.3. infer conditional inference and distributive preview.md>); this leaf makes it operational: the `Exclude` proof, the whole-union escape, and the accident pattern.

**What problem it solves / history** — union filtering before distributive conditionals (TS 2.8, 2018) needed per-member overloads or chained `Extract` calls that grew with the union — every new variant meant a new branch. Distribution turned filtering into mapping: one line handles any present *or future* member, so adding `"archived"` to a status union flows through existing filters without edits.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), write member-wise filters naked (`T extends U ? never : T` drops matches; `T extends U ? T : never` keeps them) and whole-union tests wrapped (`[T] extends [never]` for emptiness). Read any conditional by asking first: "is `T` naked here?" — the answer predicts distribution before any evaluation.

**Runnable example** — distribution vs whole-union (good vs bad, `tsc --strict`):

```typescript
// good — naked T: each member filtered independently (this IS Exclude)
type NoStrings<T> = T extends string ? never : T;
type N = NoStrings<"a" | 1 | "b" | true>; // number | boolean — strings dropped one by one
const n: N = 1;
console.log(n.toFixed(0)); // 1

// good — wrapped [T]: the whole union tested at once
type IsNever<T> = [T] extends [never] ? true : false;
console.log("empty-never:", true); // IsNever<never> = true
const e: IsNever<string> = false;
console.log(e); // false — whole string (not never) fails at once

// bad — expecting distribution from a wrapped check
type KeepStrings<T> = [T] extends [string] ? T : never;
type K = KeepStrings<"a" | 1>; // never — whole union ("a" | 1) is not string
// const k: K = "a"; // error — correctly never; author wanted the naked form below
type KeepStringsFixed<T> = T extends string ? T : never; // naked: distributes
const kf: KeepStringsFixed<"a" | 1> = "a"; // "a" — survivor kept
console.log(kf.toUpperCase()); // A
```

**Common confusion** — "every conditional distributes" — only naked-`T` distributes; `Array<T>`, `[T]`, `Box<T>`, `keyof T` wrappers test whole (see promise 3). "distribution preserves order" — survivors reunite as a *union* (order-free, deduped) — member sequence is lost, member set kept. "`Exclude` is compiler magic" — `Exclude<T, U> = T extends U ? never : T`, one naked line — distribution does the work (see [2.2. Stdlib under the hood](<../2. Conditional Types/2.2. Exclude Extract NonNullable Pick Omit under the hood.md>)).

**Performance note** — distribution multiplies check cost by member count (N members × conditional body, cached per instantiation) — a 200-member literal union through nested distributive filters checks 200 branches per reference. Filter large unions once into named aliases; reference the result at 50 call sites instead of re-filtering.

**Mentor note** — the naked-vs-wrapped pair (`KeepStrings` vs `KeepStringsFixed` on `"a" | 1`) is the whole lesson in two hovers — `"a"` vs `never` from one bracket pair. Exercise: implement `Exclude` from memory, break it with `[T]`, explain the `never` — proves distribution understood, not memorized. Review gate: custom union filters must state naked-or-wrapped intent in a comment.

### 2) **`never` as the filter sink** (false-branch `never` drops members)

**Definition** — `never` is the empty union: mapping a member to `never` removes it from the reunited result (`"a" | never` collapses to `"a"`). Filtering *is* mapping-to-`never` — `Exclude` maps matches to `never`, `NonNullable` maps `null | undefined` to `never`, `Extract` maps non-matches to `never` (same mechanic, swapped branches).

**What problem it solves / history** — pre-`never`-sink code expressed "drop" as overload exclusions or post-filter runtime checks (`states.filter(s => s !== "archived")` at runtime *and* a separate type) — the type and the runtime list drifted. The `never` sink unifies them: the type computes the surviving set, so a new member is either kept (flows through) or explicitly sunk (one branch documents the exclusion).

**Modern guidance** — as of TypeScript 5.9 era, return `never` for "drop this member" and the member type for "keep" — never `null`, never a sentinel object (both pollute the reunited union with inhabited members). When *everything* sinks (result `never`), treat it as a design signal: the filter contradicts the input — either the input union or the predicate is wrong, and `never` assignments downstream will error loudly (see [2.3. never and void](<../../../03 Basic Types and Annotations/sections/2. The Special Types/2.3. never and void bottom vs deliberate nothing.md>)).

**Runnable example** — sink drops, survivors reunite (good vs bad, `tsc --strict`):

```typescript
// good — NonNullable: null and undefined sunk, the rest reunited
type Clean<T> = T extends null | undefined ? never : T;
type C = Clean<string | null | number | undefined>; // string | number
const c: C = "hi";
console.log(c.toUpperCase()); // HI

// good — everything sunk means never: the checker says the filter contradicts input
type Impossible = Clean<null | undefined>; // never — honest "nothing survives"
// const x: Impossible = "hi"; // error TS2322 — never accepts nothing (correctly)

// bad — sentinel instead of never pollutes the union
type KeepBad<T> = T extends string ? T : "dropped"; // "dropped" is a REAL member now
type B = KeepBad<"a" | 1>; // "a" | "dropped" — downstream switches must handle a fake case
// fix — T extends string ? T : never: dropped members vanish instead of haunting switches
type KeepGood<T> = T extends string ? T : never; // "a" — clean
const g: KeepGood<"a" | 1> = "a";
console.log(g.toUpperCase()); // A
```

**Common confusion** — "`never` in a union errors" — `never` absorbs silently (`A | never` is `A`) — only *assigning to* `never` errors, which is the exhaustiveness feature, not a bug. "sinking everything is always a bug" — sometimes the honest answer (empty permission set, fully-filtered event log) — `never` then *propagates* correctly through downstream mappings instead of crashing. "`null` works as a sink" — `null` is inhabited (assignable, comparable, JSON-able) — only `never` vanishes from unions.

**Performance note** — sunk members cost one conditional evaluation each and vanish from downstream checks (smaller unions check faster) — aggressive-but-correct filtering *reduces* total check cost. The cliff is filtering huge unions repeatedly per call site — filter once, name it.

**Mentor note** — contrast `KeepBad` vs `KeepGood` hovers (`"a" | "dropped"` vs `"a"`) — the fake member in the switch statement that follows makes the cost visceral. Exercise: feed both into an exhaustive switch and count the extra `case "dropped"` the sentinel forces — ceremony created by one wrong branch.

### 3) **Non-distributive escapes** (testing the whole union at once)

**Definition** — wrapping either side disables distribution: `[T] extends [U]` compares whole-to-whole (tuple types never distribute), `T extends [U]` tests whether `T` *is* a tuple, and `T extends any[]` checks array-ness without distributing over members. Use escapes when the question concerns the *union as a value* (emptiness, exact shape, count) rather than its members.

**What problem it solves / history** — `IsNever<T> = T extends never ? …` *distributes over nothing* (naked `T` with `never` input yields `never`, not the true branch — the famous empty-union trap): every hand-rolled `IsEmpty`/`IsAny` returned wrong answers until the `[T]` wrap became standard lore. The escape is now the documented pattern for whole-union predicates — emptiness, `any`-detection, exact-equality.

**Modern guidance** — as of TypeScript 5.9 era, reach for `[T] extends [U]` when asking about the union itself (`IsNever`, `IsAny` via `0 extends 1 & T`, exact `Equal<X, Y>` via mutual assignability); stay naked when transforming members. Memorize the `IsNever` trap specifically — it is the most re-asked conditional question in reviews and interviews (see [6.1. Interview QA](<../6. Interview questions and answers/6.1. Common interview QA utility types and transformations.md>)).

**Runnable example** — the `never` trap and its escape (good vs bad, `tsc --strict`):

```typescript
// good — wrapped: whole-union emptiness tested correctly
type IsNever<T> = [T] extends [never] ? true : false;
const a: IsNever<never> = true;
const b: IsNever<string> = false;
const c: IsNever<string | never> = false; // string | never IS string — not empty
console.log(a, b, c); // true false false

// bad — naked against never: distributes over zero members, yields never (not false)
type IsNeverBad<T> = T extends never ? true : false;
type D = IsNeverBad<never>; // never — NOT false; the branch never evaluates
// const d: D = false; // error TS2322 — never accepts nothing; the "answer" is unusable
// fix — IsNever<T>: wrap to test whole instead of distributing over nothing
const fixed: IsNever<never> = true; // usable boolean
console.log(fixed); // true
```

**Common confusion** — "`T extends never` should be true for `never`" — naked distribution over an empty union evaluates the conditional *zero* times and returns `never` (no members to reunite) — the intuition "vacuous truth" does not apply; wrapping does. "`[T]` changes assignability semantics" — single-element tuples compare structurally like their element for most purposes *except* distribution — the wrap is behavior-preserving everywhere else. "escapes are hacks" — documented patterns (stdlib `Equal`, `IsAny` use mutual-`extends` and `0 extends 1 & T`) — whole-union questions need whole-union syntax.

**Performance note** — wrapped checks cost O(1) (one comparison, no per-member walk) — cheaper than distributive equivalents. Prefer whole-union predicates as early guards (`IsNever` first, distribute after) to skip N-member walks on degenerate inputs.

**Mentor note** — demo the trap live: hover `IsNeverBad<never>` (`never`) vs `IsNever<never>` (`true`) — identical except brackets, opposite usability. The gasp is the lesson. Exercise: implement `IsAny` (`0 extends 1 & T ? true : false`) and explain why *it* must not be naked — same trap, new angle.
