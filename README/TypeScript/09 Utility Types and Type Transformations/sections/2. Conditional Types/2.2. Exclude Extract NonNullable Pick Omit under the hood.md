## 2.2. Exclude, Extract, NonNullable, Pick and Omit — under the hood

Choose a utility by the relationship it computes. Exclude and Extract filter union members using assignability. Pick and Omit select property contracts. NonNullable intersects with the non-nullish type {} in the current library. These operations do not validate values, delete fields or automatically preserve every alternative in an object union.

The verified baseline is TypeScript 7.0.2. The first file definitions.ts contains only compile-time checks: run `tsc --strict --exactOptionalPropertyTypes --noUncheckedIndexedAccess --erasableSyntaxOnly --target es2022 --module commonjs --lib es2022,dom --noEmit definitions.ts`. For the two runtime programs, use the same flags with --removeComments --outDir dist instead of --noEmit, then run `node dist/FILE.js` with Node.js 20.20.2. Activate commented negatives independently.

### 1) **Read the actual contracts and constraints**

These teaching aliases reproduce the relevant installed lib.es5.d.ts definitions. Read them to connect familiar names to the [conditional law](<./2.1. Conditional fundamentals distributive law and never branches.md>) and [mapped-property relationships](<../1. Mapped Types/1.1. Mapped type fundamentals homomorphic mapping over keys.md>). Use the public standard names in ordinary code when they express the intended operation.

Save as definitions.ts.

```typescript
type Drop<T, U> = T extends U ? never : T;
type Keep<T, U> = T extends U ? T : never;
type NonNull<T> = T & {};
type Select<T, Keys extends keyof T> = { [K in Keys]: T[K] };
type Remove<T, Keys extends keyof any> = Select<T, Exclude<keyof T, Keys>>;
type StrictOmit<T, Keys extends keyof T> = Omit<T, Keys>;
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type Status = "idle" | "loading" | "done" | "archived";
type LiveStatus = Exclude<Status, "archived">;
type D = Expect<Equal<Drop<Status, "archived">, "idle" | "loading" | "done">>;
type K = Expect<Equal<Keep<Status, "done" | "archived">, "done" | "archived">>;
type N = Expect<Equal<NonNull<0 | false | "" | null | undefined>, 0 | false | "">>;
interface DocumentModel { readonly id: string; title?: string; secret: string; }
type P = Expect<Equal<Select<DocumentModel, "id" | "title">, Pick<DocumentModel, "id" | "title">>>;
type O = Expect<Equal<Remove<DocumentModel, "secret">, Omit<DocumentModel, "secret">>>;
type Typo = Expect<Equal<Omit<DocumentModel, "secrect">, DocumentModel>>;
// type WrongPick = Pick<DocumentModel, "secrect">; // TS2344
// type WrongStrict = StrictOmit<DocumentModel, "secrect">; // TS2344
```

Six live probes compile. Pick constrains its keys to keyof T, but Omit admits any PropertyKey through keyof any. Consequently, misspelling a removed key can silently leave the source unchanged. StrictOmit adds a useful existing-key requirement for some APIs; Omit's more permissive contract is also useful when a computed removal set can contain keys absent from a particular input.

Exclude<DocumentModel, "secret"> would compare the whole object type to the string literal secret, rather than remove its property. Apply Exclude to keyof DocumentModel when filtering key names. Conversely, Record<Keys, Value> creates a property contract from Keys and Value; it does not take an input object to project. The [standard utility reference](https://www.typescriptlang.org/docs/handbook/utility-types.html#omittype-keys) describes the public contracts, while the installed declarations establish these precise parameter constraints.

### 2) **Decide whether object alternatives must be transformed separately**

For an object union, keyof exposes keys supported across the alternatives. Standard Omit computes that common key set and feeds it to Pick; it does not introduce a conditional that distributes the whole object union. Fields exclusive to one alternative can disappear from the result. If the API needs a union of transformed alternatives, distribute explicitly before applying Omit.

Save as alternatives.ts.

```typescript
type Identity =
  | { kind: "user"; name: string; secret: string }
  | { kind: "service"; token: string; secret: string };
type Common = Omit<Identity, "secret">;
type OmitEach<T, Keys extends PropertyKey> = T extends unknown ? Omit<T, Keys> : never;
type PublicIdentity = OmitEach<Identity, "secret">;
const incomplete: Common = { kind: "user" }; // Accepted: variant-only fields are not required here.
console.log(Object.keys(incomplete).join(","));
// incomplete.name; // TS2339
// type UnsupportedPick = Pick<Identity, "name">; // TS2344: name is not a common key
// const missing: PublicIdentity = { kind: "user" }; // TS2322
function describe(value: PublicIdentity): string {
  return value.kind === "user" ? value.name.toUpperCase() : value.token;
}
console.log(describe({ kind: "user", name: "Ada" }), describe({ kind: "service", token: "s1" }));
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type CommonKeys = Expect<Equal<keyof Identity, "kind" | "secret">>;
type CommonResult = Expect<Equal<Common, { kind: "user" | "service" }>>;
type Alternatives = Expect<Equal<PublicIdentity, { kind: "user"; name: string } | { kind: "service"; token: string }>>;
```

The output is `kind`, then `ADA s1`. Common accepts a tag with no matching payload. PublicIdentity retains the payload requirements and allows narrowing by kind. These are different useful contracts; adding distribution changes the result rather than merely making a faster or slower equivalent alias.

Pick does not become distributive just because its selected keys are written through a parameter. Source modifier preservation and distribution across object alternatives are separate features. The [modifier lesson](<../1. Mapped Types/1.2. readonly and optional modifiers with plus and minus.md>) demonstrates the former. [Union structure](<../../../07 Unions Intersections and Narrowing/sections/1. Union Types/1.1. Union fundamentals member access and the common property rule.md>) owns shared versus exclusive member access.

### 3) **Preserve non-nullish values and construct actual projections**

In the current library, NonNullable<T> is T & {}. Here {} means a non-nullish value, including primitives; it does not mean only object instances. In particular, NonNullable<unknown> is {}, while a simple conditional that removes null and undefined from a bare unknown input leaves unknown. Do not assume those definitions produce identical results for every input just because ordinary explicit unions often agree. The [primary intersection changes](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-8.html#improved-intersection-reduction-union-compatibility-and-narrowing) explain the current form and generic nullish checks.

Save as values.ts.

```typescript
function requireValue<T>(value: T): NonNullable<T> {
  if (value === null || value === undefined) throw new Error("missing value");
  return value;
}
console.log(requireValue(0), requireValue(false), JSON.stringify(requireValue("")));
try { requireValue(null); }
catch (error) { console.log(error instanceof Error ? error.message : "unexpected error"); }
type ConditionalClean<T> = T extends null | undefined ? never : T;
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type Current = Expect<Equal<NonNullable<unknown>, {}>>;
type Conditional = Expect<Equal<ConditionalClean<unknown>, unknown>>;
type Empty = Expect<Equal<NonNullable<never>, never>>;
const present: NonNullable<unknown> = 0;
// const nullish: NonNullable<unknown> = null; // TS2322

interface Doc { id: string; title: string; secret: string; }
type Safe = Omit<Doc, "secret">;
const original: Doc = { id: "1", title: "t", secret: "private" };
const view: Safe = original;
function toPublic(doc: Doc): Safe { return { id: doc.id, title: doc.title }; }
const projected = toPublic(original);
console.log(JSON.stringify(view));
console.log(JSON.stringify(projected), projected === original, present);
// const exposed: Safe = { id: "1", title: "t", secret: "private" }; // TS2353
```

The output is `0 false ""`, `missing value`, `{"id":"1","title":"t","secret":"private"}`, then `{"id":"1","title":"t"} false 0`. The nullish check accepts zero, false and empty string. It does not use truthiness as a substitute for presence. Three probes check the current NonNullable boundary cases.

The Safe view still serializes the original secret because it is the same object. A rejected fresh literal does not guarantee that all values assignable to Safe lack extra runtime keys. The explicit projection constructs the object without secret. Choose and verify an actual serialization boundary; a type alias alone cannot redact data. [Object composition](<../../../04 Objects Interfaces and Type Aliases/sections/2. Composition and Declaration Merging/2.1. Intersection vs extends composing object types.md>) owns broader shape/identity relationships.

Prefer a domain name when it adds meaning: LiveStatus and PublicIdentity communicate useful contracts. Prefer a standard utility when it already names the operation clearly. Teaching copies can expose the mechanics, and custom aliases can express stricter keys or intentional distribution. None of these naming choices is evidence of a universal cross-file cache advantage or editor-display behavior.

### 4) **Common confusion**

Removing a union member is different from removing a property contract. Omit computes common keys for an object union; its ordinary definition does not preserve every branch's private payload field. Explicitly distributing can recover those separate contracts. A Pick-style mapping can preserve readonly/optional modifiers without automatically distributing across those alternatives.

NonNullable excludes nullish values, including when the input is unknown; it does not require a truthy object. Finally, omitted static keys can remain on a value assigned through the reduced view. Check actual construction before treating a public type as a redaction mechanism.

### 6) **Mentor note**

Ask the learner to expand keyof Identity before expanding Omit, and explain why a tag-only Common value compiles. Then require a prediction of view's JSON output before running it. These two questions expose separate misconceptions about type computation and runtime projection.

For practice, add audit: boolean to Doc and audit: true to original. The Omit-based Safe now includes audit, so toPublic's existing result is incomplete. If the public contract should remain only id/title, choose Pick<Doc, "id" | "title"> instead. Verify that the projection still contains exactly those two keys, while merely assigning original to view still retains its private runtime properties. A fresh Safe literal with audit must be rejected. This makes source evolution an explicit public-boundary decision rather than automatic exposure of every new internal field.
