## 2.3. Infer pipelines — ReturnType, Parameters and Awaited

An extraction pipeline derives one contract from another: obtain a function's return type, model its awaited result, then inspect an element type. Each step has a supported input shape and its own limits. The types do not call the function, set its runtime arity, execute a promise or guarantee that an indexed element exists.

Use TypeScript 7.0.2 and Node.js 20.20.2. Save the three independent fences as named below. Compile with `tsc --strict --exactOptionalPropertyTypes --noUncheckedIndexedAccess --erasableSyntaxOnly --removeComments --target es2022 --module commonjs --lib es2022,dom --outDir dist FILE.ts`, then run `node dist/FILE.js`. Activate commented negatives separately with those flags and --noEmit instead of --outDir dist. Async work runs inside explicit functions, so no top-level await or module-loader setup is required.

### 1) **Extract callable metadata without changing the callable**

The installed ReturnType declaration constrains its argument to a callable and uses a conditional infer R pattern, with any as its fallback branch. Parameters also constrains its input and infers the argument tuple, with never as its fallback. ConstructorParameters similarly requires an abstract construct signature and infers its arguments. These are different from unconstrained teaching aliases that silently return never for invalid inputs. Standard ReturnType<number> and Parameters<string> fail their constraints.

For an overloaded function, extraction reads the last public overload signature, not the implementation signature hidden from callers. A particular call still selects its matching overload. For a universally generic identity function, metadata extraction has no single concrete type argument and yields unknown-based results; direct calls can retain their own relationships. The [primary utility guidance](https://www.typescriptlang.org/docs/handbook/utility-types.html#returntypetype) and [overload owner](<../../../05 Functions and Callable Types/sections/2. Overloads and Generics/2.1. Function overloads call signatures and implementation compatibility.md>) explain those boundaries.

Save as callables.ts.

```typescript
function fetchUser(id: string, verbose: boolean): Promise<{ id: string; verbose: boolean }> {
  return Promise.resolve({ id, verbose });
}
function logged(...args: Parameters<typeof fetchUser>): ReturnType<typeof fetchUser> {
  console.log("fetch", args[0]);
  return fetchUser(...args);
}
console.log(fetchUser.length, logged.length);
// logged("u1"); // TS2554
// type NotCallable = ReturnType<number>; // TS2344
// type NotParameters = Parameters<string>; // TS2344

function convert(value: string): number;
function convert(value: number): string;
function convert(value: string | number): string | number {
  return typeof value === "string" ? value.length : `n${value}`;
}
console.log(convert("hey"), convert(7));
// const mismatch: ReturnType<typeof convert> = convert("hey"); // TS2322
// const wrongTail: Parameters<typeof convert> = ["hey"]; // TS2322
function identity<T>(value: T): T { return value; }
console.log(identity("a").toUpperCase(), identity(1).toFixed(0));
class User {
  id: string;
  constructor(id: string) { this.id = id; }
}
function construct(...args: ConstructorParameters<typeof User>): User { return new User(...args); }
console.log(construct("u2").id.toUpperCase());
// construct(42); // TS2345

type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type Args = Expect<Equal<Parameters<typeof fetchUser>, [id: string, verbose: boolean]>>;
type TailReturn = Expect<Equal<ReturnType<typeof convert>, string>>;
type TailArgs = Expect<Equal<Parameters<typeof convert>, [value: number]>>;
type GenericReturn = Expect<Equal<ReturnType<typeof identity>, unknown>>;
type GenericArgs = Expect<Equal<Parameters<typeof identity>, [value: unknown]>>;
type ConstructArgs = Expect<Equal<ConstructorParameters<typeof User>, [id: string]>>;
async function main(): Promise<void> {
  const user = await logged("u1", true);
  console.log(user.id, user.verbose);
}
void main().catch(error => { console.log("unexpected failure", error); });
```

The output is `2 0`, `3 n7`, `A 1`, `U2`, `fetch u1`, then `u1 true`. Six probes compile. The rest wrapper's JavaScript length is zero even though its static tuple requires two arguments. It actually forwards both arguments when invoked. The implementation's broad string | number result does not replace the last public overload's string metadata.

This wrapper deliberately targets one ordinary, receiver-independent signature. Receiver binding, overload preservation and generic input/output relationships require their own supported wrapper design. [Variadic composition](<../../../08 Generics Deep Dive/sections/3. Variance and Advanced Generic Patterns/3.3. Variadic tuple generics pipe concat and rest capture.md>) demonstrates captured contracts and real wrapper behavior without promising to preserve every callable feature.

### 2) **Model awaited results and observe actual adoption separately**

Awaited recursively examines a compatible callable then member and the fulfillment callback's value. Null and undefined pass through, and non-thenable values remain unchanged. In the installed 7.0.2 definition there is no separate native-Promise fast path; the structural conditional handles the relevant promise-like shape. A malformed callable-then shape whose fulfillment parameter is not callable can produce never.

This operation is not a recursive traversal of every property. An object containing a value: Promise<number> field remains that object when awaited; accessing and awaiting value is a separate step. A non-callable then property also does not turn an object into a thenable. The [primary Awaited introduction](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-5.html#the-awaited-type-and-promise-improvements) presents the intended promise/await model.

Save as awaited.ts.

```typescript
const trace: string[] = [];
const thenable = {
  then(resolve: (value: number) => void): void { trace.push("then"); resolve(42); }
};
const plain = { then: 3 };
const wrapper = { value: Promise.resolve(7) };
type Once<T> = T extends Promise<infer Item> ? Item : T;
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type Nested = Expect<Equal<Awaited<Promise<Promise<string>>>, string>>;
type Custom = Expect<Equal<Awaited<typeof thenable>, number>>;
type Shallow = Expect<Equal<Once<Promise<Promise<string>>>, Promise<string>>>;
type NotAPromise = Expect<Equal<Once<typeof thenable>, typeof thenable>>;
type NonCallableThen = Expect<Equal<Awaited<typeof plain>, typeof plain>>;
type NotCallableCallback = Expect<Equal<Awaited<{ then(onfulfilled: number): void }>, never>>;
type Null = Expect<Equal<Awaited<null>, null>>;
type Field = Expect<Equal<Awaited<typeof wrapper>, typeof wrapper>>;
type Loop = PromiseLike<Loop>;
// type Overflow = Awaited<Loop>; // TS2589
async function main(): Promise<void> {
  trace.push("before");
  const pending = Promise.resolve(thenable);
  trace.push("after");
  const value = await pending;
  trace.push(`value:${value}`);
  console.log(trace.join(","));
  console.log((await plain) === plain, (await wrapper) === wrapper, await wrapper.value);
  console.log(await Promise.resolve(Promise.resolve("native")));
}
void main().catch(error => { console.log("unexpected failure", error); });
```

The output is `before,after,then,value:42`, `true true 7`, then `native`. Eight probes compile. The actual then call occurs through runtime adoption, not by evaluating Awaited. Native promise resolution adopts another promise instead of producing a second promise object that must be manually awaited again. The nested Promise<Promise<string>> fixture is a static shape used to test recursive extraction, not a claim that Promise.resolve creates a permanently nested runtime result.

The malformed callback example is a type-only probe; it is not executed as a promise operation. Activating Overflow reproduces TS2589. Awaited is not an unlimited-depth promise and should not be replaced with a silently capped alias just to retain a claim of equivalent behavior. The [recursive generic owner](<../../../08 Generics Deep Dive/sections/3. Variance and Advanced Generic Patterns/3.2. Recursive generic types and self-referential patterns.md>) separates finite stopping policies from compiler limits; [async types](<../../../18 Async Types and Standard Library/README.md>) owns the broader operational contracts.

### 3) **Compose from a real source and keep absence visible**

Read the pipeline inside out: typeof listUsers is a callable type, ReturnType obtains its promise contract, Awaited obtains its readonly array result, and [number] obtains the element type. That final type says what a present element can be; indexing an actual array can still return undefined under unchecked-index checking.

Save as pipeline.ts.

```typescript
function listUsers(): Promise<readonly { id: string }[]> {
  return Promise.resolve([{ id: "u1" }]);
}
type List = Awaited<ReturnType<typeof listUsers>>;
type User = List[number];
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type Items = Expect<Equal<List, readonly { id: string }[]>>;
type Item = Expect<Equal<User, { id: string }>>;
// type BeforeAwait = ReturnType<typeof listUsers>[number]; // TS2537
async function main(): Promise<void> {
  const users = await listUsers();
  const first = users[0];
  // const assumed: User = users[0]; // TS2322
  // console.log(users[0].id); // TS2532
  console.log(first?.id.toUpperCase() ?? "no users");
}
void main().catch(error => { console.log("unexpected failure", error); });
```

The output is U1, and both probes compile. This function returns locally constructed data, so the example tests extraction, awaiting and index absence without claiming an external service was validated. Deriving User does not itself fetch data or make the first element required.

Name a useful intermediate result such as List when it makes the relationship easier to inspect or reuse. Inline a short pipeline when it reads clearly. There is no fixed third-use naming rule, layer-count readability cliff or measured cache advantage. When a result surprises, check each input and output relationship separately instead of assuming an editor's expansion proves it.

### 4) **Common confusion**

Parameters describes a tuple contract, not Function.length. ReturnType on an overload reads the last public signature, while a call selects an overload. Extraction from a universally generic callable can lose a concrete relationship without affecting the precision of its direct calls.

Awaited models adoption of compatible thenables; it does not execute them or recursively unwrap arbitrary object fields. The runtime array's possible absence also remains after its element type has been extracted. These distinct boundaries need different checks.

### 5) **Performance note**

Extraction utilities erase. The examples retain real rest forwarding, object construction, promise resolution, thenable execution and asynchronous continuations. No native-Promise type fast path, fixed safe nesting depth, universal per-layer cache reuse or alias speed advantage was established. Use [compiler diagnostics and traces](<../../../19 Performance Project References and Scaling/sections/1. Check-Time Performance/1.1. Measuring with extendedDiagnostics and traces.md>) for a real checking issue. Runtime timing was not benchmarked; only the shown operation order was observed.

### 6) **Mentor note**

Ask the learner to predict both logged.length and the rejected logged call with one argument. For convert, ask why the result of its string call cannot be assigned to its extracted ReturnType. For the asynchronous fixture, identify the expression that actually invokes then, and distinguish the wrapper object's promise field from a thenable contract.

For practice, make listUsers accept an include boolean and return null when it is false. Derive User through NonNullable<Awaited<ReturnType<typeof listUsers>>> before indexing, but also guard null at runtime before reading users[0]. Verify true prints U1 and false prints no users. NonNullable changes the derived element contract; it does not remove the null branch from the actual returned value. A solution needs both changes.
