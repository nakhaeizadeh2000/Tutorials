## 6.1. Common interview QA — utility types and transformations

Explain the relationship a utility computes, predict a concrete result, then change an assumption. A good answer distinguishes a static contract from the runtime operation that establishes it. These questions synthesize the domain; their links own the full worked mechanisms.

Use TypeScript 7.0.2 and Node.js 20.20.2. Save each fence as named below. For the runtime files mapping.ts and handlers.ts, compile with `tsc --strict --exactOptionalPropertyTypes --noUncheckedIndexedAccess --erasableSyntaxOnly --removeComments --target es2022 --module commonjs --lib es2022,dom --outDir dist FILE.ts`, then run `node dist/FILE.js`. For the type-only file conditional.ts, use the same flags with --noEmit instead of --outDir dist; successful compilation checks its probes, with no runtime output. Activate commented negatives independently.

### 1) **How does Partial compute its result and what is preserved?**

Its mapped declaration visits keyof T, retains each property's T[K] type and adds ?. The generic full-key form also preserves source readonly modifiers and has specialized array/tuple behavior. Homomorphic mapping is more than a label for optional/readonly memory, and modifier preservation is not exclusive to one spelling: a constrained Pick-style subset can preserve it too.

In mapping.ts below, both patch and selected reject an id write. A tuple mapping keeps ordered positions while transforming element types. None of these declarations copies an object or loops over its runtime properties. Use [mapping foundations](<../1. Mapped Types/1.1. Mapped type fundamentals homomorphic mapping over keys.md>) for the full examples.

For a follow-up, ask whether Pick over an object union preserves each alternative's exclusive payload. It does not automatically do so: computing common keys differs from distributing the object alternatives. The [utility owner](<../2. Conditional Types/2.2. Exclude Extract NonNullable Pick Omit under the hood.md>) demonstrates the distinction.

### 2) **What makes Exclude distribute and why does never remove a member?**

The checked left operand is the bare parameter T in T extends U ? never : T. Each input union member is tested separately; matching members contribute never, which vanishes when the results unite. Wrapping the checked T tests a different whole-type relationship. A tuple or array only on the right does not disable distribution.

Save as conditional.ts.

```typescript
type Drop<T, U> = T extends U ? never : T;
type WholeDrop<T, U> = [T] extends [U] ? never : T;
type IsNever<T> = [T] extends [never] ? true : false;
type RightPattern<T> = T extends [string] ? "tuple" : "other";
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type D = Expect<Equal<Drop<"a" | 1 | "b", string>, 1>>;
type W = Expect<Equal<WholeDrop<"a" | 1, string>, "a" | 1>>;
type N = Expect<Equal<Drop<never, string>, never>>;
type Empty = Expect<Equal<IsNever<never>, true>>;
type R = Expect<Equal<RightPattern<[string] | number>, "tuple" | "other">>;
// const removed: Drop<"a" | 1, string> = "a"; // TS2322
// const noValue: Drop<never, string> = 1; // TS2322
```

Five probes compile. For a follow-up, compare Exclude<{ kind: "archived" }, "archived"> with a matching object-shape pattern. A sound answer compares the actual member type to the supplied pattern rather than assuming Exclude inspects kind automatically. No type-level filtering deletes elements from a runtime array. [Conditional fundamentals](<../2. Conditional Types/2.1. Conditional fundamentals distributive law and never branches.md>) owns the complete any/unknown/never and value-filter distinctions.

### 3) **Why does Awaited recurse and what can prevent a useful result?**

Awaited models recursive adoption of compatible thenables: inspect a callable then member, infer the fulfillment value, recurse, and pass through supported non-thenable values and nullish inputs. A single Promise<infer Value> match unwraps only one static layer. The installed definition has no separate native-Promise fast path.

A self-referential thenable type can fail with TS2589; having a base branch does not prove every admitted input reaches it. Awaited also does not recursively unwrap arbitrary promise-valued object fields. Native runtime promise resolution adopts another promise rather than requiring an additional manual await for a permanently nested result. See [callable and awaited pipelines](<../2. Conditional Types/2.3. infer pipelines ReturnType Parameters Awaited.md>) for actual operation traces and source definitions.

The async example under question five derives its ready payload from a real function and calls the resulting handler. For a follow-up, ask what a non-callable then property does, or why selecting a ReturnType does not itself call the function. Require a runtime operation and a separate type relationship in the explanation.

### 4) **How do modifier operators interact with source structure?**

Plus adds a modifier and minus removes it; bare readonly or ? means plus. With no override, supported mapping forms can preserve source modifiers. A fresh Record has no source modifiers to inherit, while a constrained Pick can retain them. Inspect the whole form instead of assuming every occurrence of keyof has the same behavior.

Save as mapping.ts.

```typescript
interface Config { readonly id: string; count?: number; }
type Strip<T> = { -readonly [K in keyof T]-?: T[K] };
const patch: Partial<Config> = {};
const selected: Pick<Config, "id" | "count"> = { id: "a" };
const stripped: Strip<Config> = { id: "a", count: 1 };
stripped.id = "b";
console.log(patch.id ?? "absent", selected.id, stripped.id.toUpperCase(), stripped.count);
// patch.id = "a"; // TS2540
// selected.id = "b"; // TS2540
// const missing: Strip<Config> = { id: "a" }; // TS2741
// const invalid: Strip<Config> = { id: "a", count: undefined }; // TS2322

type Nullable<T> = { [K in keyof T]: T[K] | null };
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type Tuple = Expect<Equal<Nullable<readonly [string, number]>, readonly [string | null, number | null]>>;
type RequiredCount = Expect<Equal<Strip<Config>["count"], number>>;
```

The output is `absent a B 1`; both probes compile. The readonly error is TS2540 here. Removing ? also affects undefined semantics; optional fields with explicitly allowed undefined need the exact-optional mode specified. Removing readonly changes a view, not a frozen object's runtime descriptors or its ownership. The [modifier owner](<../1. Mapped Types/1.2. readonly and optional modifiers with plus and minus.md>) contains the flag comparison, shared-alias failure and actual copy exercise.

For a follow-up, ask whether Partial<typeof constSnapshot> is a useful editing API. It may preserve singleton values and readonly members too narrowly. A domain patch can intentionally admit broader edits; the [snapshot lesson](<../3. Transformations in Practice/3.3. satisfies and as const preserving literals through transforms.md>) demonstrates that choice.

### 5) **How do generated handler names retain their payload relationship?**

Map each source key to its generated name while indexing the original payload at that same key. The result checks the provided object's names and values; it does not generate functions, install observers or validate a dynamic dispatch. K & string filters numeric and symbol key types in this template form rather than rejecting a mixed source loudly.

Save as handlers.ts.

```typescript
function loadUser(): Promise<{ id: string }> { return Promise.resolve({ id: "u1" }); }
type Ready = Awaited<ReturnType<typeof loadUser>>;
interface Events { ready: Ready; error: { message: string }; }
type Handlers<T> = { [K in keyof T as `on${Capitalize<K & string>}`]: (payload: T[K]) => void };
const handlers: Handlers<Events> = {
  onReady: payload => console.log(`ready:${payload.id}`),
  onError: payload => console.log(`error:${payload.message}`)
};
// const missing: Handlers<Events> = { onReady: handlers.onReady }; // TS2741
// handlers.onReady({ message: "oops" }); // TS2353
// type NonCallable = ReturnType<number>; // TS2344

type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type Payload = Expect<Equal<Ready, { id: string }>>;
type Nested = Expect<Equal<Awaited<Promise<Promise<string>>>, string>>;
type Null = Expect<Equal<Awaited<null>, null>>;
type Loop = PromiseLike<Loop>;
// type NonTerminating = Awaited<Loop>; // TS2589
async function main(): Promise<void> {
  handlers.onReady(await loadUser());
  handlers.onError({ message: "oops" });
}
void main().catch(error => { console.log("unexpected failure", error); });
```

The output is `ready:u1`, then `error:oops`; three probes compile. Awaiting loadUser actually obtains the payload before invoking its callback. The object contains actual functions checked against their generated contracts. The nonterminating type probe is intentionally not evaluated in the positive program; activate it separately to reproduce the compiler failure.

For a follow-up, add an event or introduce keys that collide after casing. Explain missing required handlers, per-key payloads and possible merged output keys as distinct outcomes. Template literal composition Capitalize handlers and routes.md>) own those full experiments.

### 6) **Common confusion**

Modifier preservation and distribution across object alternatives are separate features. A matched shape can preserve a member contract while a common-key utility omits exclusive fields. Neither behavior constructs a runtime projection. A generated handler map also requires actual callbacks and calls before any event processing occurs.

An Awaited base branch does not imply unlimited termination for every recursive input. A cap would change a transformation's result rather than transparently fixing all failures. Use the [deep-policy owner](<../3. Transformations in Practice/3.1. Deep transforms DeepPartial DeepReadonly and the budget.md>) when that stopping contract is part of the design.

### 7) **Performance note**

The utility definitions and probes erase. The runtime programs retain objects, writes, promise resolution and explicit handler calls. No per-key instantiation count, shared-cache benefit, fixed safe nesting depth or automatic speed advantage was measured. Discuss performance using [diagnostics and traces](<../../../19 Performance Project References and Scaling/sections/1. Check-Time Performance/1.1. Measuring with extendedDiagnostics and traces.md>) when there is a concrete problem; do not confuse a smaller or weaker result with an equivalent faster implementation.

### 8) **Mentor note**

Ask for a prediction, an explanation and a changed-assumption follow-up. Evaluate the connection between the declaration and observed outcome, not whether a candidate volunteers a particular label or resembles an interview stereotype. A good explanation names what is preserved, where evidence comes from and what the runtime body does.

For practice, add progress: { percent: number } to Events. The existing handlers object must fail until onProgress is supplied. Have that callback print progress:50 when invoked with { percent: 50 }, while ready/error behavior remains. Passing { message: "oops" } to onProgress must fail. This demonstrates source propagation and payload preservation without pretending the mapped type registered an observer.
