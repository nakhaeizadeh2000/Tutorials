## 3.3. Satisfies and as const — preserving literals through transforms

Choose the source contract to match the consumer's job. A literal snapshot is useful for deriving exact keys or values, while an update API may need the broader permitted domain. Preserving every singleton literal through Partial can make a patch too restrictive. Checking, inference, transformation and runtime copying are separate operations.

Examples use TypeScript 7.0.2 and Node.js 20.20.2. Save each independent fence as named below. Compile with `tsc --strict --exactOptionalPropertyTypes --noUncheckedIndexedAccess --erasableSyntaxOnly --removeComments --target es2022 --module commonjs --lib es2022,dom --outDir dist FILE.ts`; run `node dist/FILE.js`. Activate commented negatives independently with the same flags and --noEmit instead of --outDir dist.

### 1) **Inspect both the source and the transform's value expression**

Partial preserves the property types it receives while making omission possible. A method: string source remains broad, while a method: get source stays that literal. The same preservation can be wrong for an editing contract: Partial<typeof fixed> below allows the original retry count 3, but not the valid alternative 2. It also inherits readonly modifiers. Partial<Route> instead expresses allowed changes in the domain.

Not every mapper preserves value precision. A value expression that deliberately returns string instead of T[K] changes the result itself. Diagnose both the input and the transform before blaming an upstream declaration.

Save as sources.ts.

```typescript
interface Route { method: "get" | "post"; path: string; retries: number; }
const wide = { method: "get", path: "/", retries: 3 };
const fixed = { method: "get", path: "/", retries: 3 } as const satisfies Route;
type WidePatch = Partial<typeof wide>;
type FixedPatch = Partial<typeof fixed>;
const literalPatch: FixedPatch = { method: "get", retries: 3 };
// const changedLiteral: FixedPatch = { method: "post" }; // TS2322
// const changedCount: FixedPatch = { retries: 2 }; // TS2322
// literalPatch.retries = 3; // TS2540: readonly inherited even for the same value
const domainPatch: Partial<Route> = { method: "post", retries: 2 };
console.log(literalPatch.method, literalPatch.retries, domainPatch.method, domainPatch.retries);

type StringValues<T> = { [K in keyof T]: string };
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type Wide = Expect<Equal<WidePatch["method"], string | undefined>>;
type Narrow = Expect<Equal<FixedPatch["method"], "get" | undefined>>;
type Flexible = Expect<Equal<Partial<Route>["method"], "get" | "post" | undefined>>;
type Count = Expect<Equal<FixedPatch["retries"], 3 | undefined>>;
type DeliberateChange = Expect<Equal<StringValues<typeof fixed>["retries"], string>>;
```

The output is `get 3 post 2`; five live probes compile. StringValues describes string-valued properties but performs no runtime serialization. The flexible patch is intentionally broader than the current snapshot, while the snapshot remains useful for exact derivation. [Mapped modifiers](<../1. Mapped Types/1.2. readonly and optional modifiers with plus and minus.md>) owns the inherited readonly/optional rules, and [inference](<../../../08 Generics Deep Dive/sections/1. Generic Fundamentals/1.2. Inference from arguments and explicit type arguments.md>) owns source evidence and widening.

### 2) **Account for contextual inference and legal const assertions**

Satisfies checks compatibility without replacing the result with the whole target type. Its target also supplies context that can affect inference. A boolean property initialized with true can stay literal true under a satisfies check, even without as const. An annotation can be the better choice when later permitted mutations should use the broader target contract.

Save as checking.ts.

```typescript
const ordinary = { enabled: true };
ordinary.enabled = false;
const checked = { enabled: true } satisfies { enabled: boolean };
checked.enabled = true; // Writable, but its value contract is literal true.
// checked.enabled = false; // TS2322
const flexible: { enabled: boolean } = { enabled: true };
flexible.enabled = false;
console.log(ordinary.enabled, checked.enabled, flexible.enabled);
interface RouteShape { method: "get" | "post"; path: string; }
const snapshot = { method: "get", path: "/" } as const satisfies RouteShape;
// const invalid = { method: "gett", path: "/" } as const satisfies RouteShape; // TS2820
// const reversed = ({ method: "get", path: "/" } satisfies RouteShape) as const; // TS1355
console.log(snapshot.method, Object.isFrozen(snapshot));
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type Context = Expect<Equal<typeof checked.enabled, true>>;
type Snapshot = Expect<Equal<typeof snapshot.path, "/">>;
```

The output is `false true false`, then `get false`; two probes compile. Checked is not readonly, yet false is rejected because its inferred property type is true. The snapshot's const assertion supplies readonly literal properties but does not freeze its runtime object. The [primary contextual-inference explanation](https://github.com/microsoft/TypeScript/issues/55189) clarifies why satisfies can affect a literal's inferred result.

A const assertion must apply to a supported literal expression. Applying it to the whole satisfies expression, as in reversed, is rejected; it is not a second legal order that merely checks at a different precision. Use as const satisfies when both retained literal precision and compatibility checking serve the intended contract. Neither operator substitutes for checking an unknown runtime value. The [object checking owner](<../../../04 Objects Interfaces and Type Aliases/sections/3. Advanced Object Types/3.3. satisfies assertions and narrowing on object shapes.md>) owns assertions, fresh-object checks and runtime readonly distinctions.

### 3) **Preserve honest relationships without erasing useful patterns**

A generic helper can return a template relationship when its body constructs exactly that relationship. A broad helper returning `${string} ${string}` loses the particular method/path literals, but it still requires a space separator. That pattern is not identical to plain string, nor is it a complete route grammar: many unrelated two-part strings satisfy it.

Save as patterns.ts.

```typescript
function combine<Method extends string, Path extends string>(method: Method, path: Path): `${Method} ${Path}` {
  return `${method} ${path}`;
}
function broad(method: string, path: string): `${string} ${string}` { return `${method} ${path}`; }
const exact = combine("get", "/users");
const patterned = broad("get", "/users");
const unrelated: `${string} ${string}` = "something else";
console.log(exact, patterned, unrelated);
// const lost: "get /users" = patterned; // TS2322
// const noSeparator: `${string} ${string}` = "single"; // TS2322
function normalize(value: string): string { return value.toUpperCase(); }
console.log(normalize("get"));
// function dishonest<T extends string>(value: T): T { return value.toUpperCase(); } // TS2322

type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type Exact = Expect<Equal<typeof exact, "get /users">>;
type Pattern = Expect<Equal<typeof patterned, `${string} ${string}`>>;
type NotAllStrings = Expect<Equal<Equal<typeof patterned, string>, false>>;
```

The output is `get /users get /users something else`, then `GET`; three probes compile. Equal runtime text does not imply equal static contracts. Normalize honestly returns a string whose value may differ from the input literal; returning T would falsely promise every caller's original subtype. A generic parameter is useful only when the body preserves its stated relationship.

Templates and deliberate output transformations have their own semantics. The [constraint owner](<../../../08 Generics Deep Dive/sections/2. Constraints Defaults and Inference Control/2.1. Constraints extends narrowing inside the body.md>) explains returning a supplied subtype versus constructing a changed result. [Template composition](<./3.2. Template literal composition Capitalize handlers and routes.md>) owns valid combination rules and actual runtime dispatch checks.

### 4) **Common confusion**

Maximum literal precision is not always the right API contract. Partial of one const snapshot can forbid every intended edit and retain readonly properties. Use the domain type to express allowed variation, and the snapshot type when the original exact values are the intended contract.

Satisfies can influence inference through context without converting data or exposing the entire target type. As const neither freezes values nor legally applies to arbitrary expressions. A broad template pattern may also retain a real restriction even after losing particular literals; inspect its actual structure instead of treating every broad template as string.

### 5) **Performance note**

The checks, const assertions, probes and templates erase. Actual object construction, copying and string operations remain. No universal speed advantage follows from narrower types, a const-asserted table or parameter-returning helpers. No fixed table-size threshold or per-call union cost was measured. Use [diagnostics and traces](<../../../19 Performance Project References and Scaling/sections/1. Check-Time Performance/1.1. Measuring with extendedDiagnostics and traces.md>) when checking performance is an actual issue; choose precision from the required contract first.

### 6) **Mentor note**

Ask which type should accept post and retry count 2: the existing literal snapshot or the Route domain. Require the learner to explain the rejection before changing the alias. Then ask why checked.enabled is writable yet false is rejected, and why patterned accepts something else but rejects single.

For practice, implement updateRoute(base: Route, patch: Partial<Route>): Route by returning a fresh object with the base and patch spread in that order. Under the declared exact-optional mode, the typed patch can omit fields but cannot supply undefined where the domain forbids it. Starting from fixed, update method to post and retries to 2; the new object must change while fixed remains get/3 and identities differ. An invalid delete method must be rejected. This primitive-field example is a shallow update, not a generic deep merge or input validator.
