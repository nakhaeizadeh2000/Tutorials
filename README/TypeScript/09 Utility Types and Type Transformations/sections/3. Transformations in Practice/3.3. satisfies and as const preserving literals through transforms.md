## 3.3. `satisfies` and `as const` — preserving literals through transforms

### 1) **Where transforms widen** (the source, not the mapper, is usually at fault)

**Definition** — mapped/conditional output preserves literals *it was given*: `Partial<{ method: "get" }>` keeps `"get"`, but `Partial<{ method: string }>` yields `string` — the mapper cannot recover precision the source never carried. Widening-through-transforms almost always traces to a widened *source* (`let`, un-annotated `string` fields, JSON-shaped `Record<string, …>` inputs), not to the utility.

**What problem it solves / history** — "Partial widened my literal" reports recurred because the widening happened two declarations earlier (`method: string` in the source interface) while the symptom appeared at the transform — developers patched the mapper (`as const` on the *output*, explicit arguments around the utility) instead of the source. Source-first diagnosis (hover the input, confirm the literal, then blame the mapper only if the input was narrow) ends the cycle.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), declare literal-carrying sources narrowly (`method: "get" | "post"`, `as const` tables) *before* transforming — `Partial`/`Pick`/`Omit` then preserve automatically. When the source is genuinely wide (`string` from user input), narrow explicitly at validation (guard/schema producing the literal union) and transform *after* — never widen-then-recover.

**Runnable example** — narrow source survives, wide source cannot (good vs bad, `tsc --strict`):

```typescript
// good — narrow source: Partial preserves "get" end to end
interface Route { method: "get" | "post"; path: string; }
type RP = Partial<Route>;
const r: RP = { method: "get" };
function handle(m: "get" | "post" | undefined): string { return m ?? "none"; }
console.log(handle(r.method)); // get — literal survived Partial

// bad — wide source: no transform can recover what was never there
interface Loose { method: string; path: string; }
type LP = Partial<Loose>;
const l: LP = { method: "get" }; // method: string | undefined — exhaustiveness dead
// handle(l.method); // error TS2345 — string not assignable to literals (correctly!)
// fix — narrow the SOURCE (Route), not the transform; LP is honest about Loose
console.log(l.method?.toUpperCase() ?? "NONE");
```

**Common confusion** — "the utility should infer literals back" — utilities transform *types*, and `string` contains infinitely many members — recovery would require values the type never had. "`as const` on the output fixes widening" — `as const` narrows *values*; applied to an already-`string`-typed result it narrows that value instance, not the type pipeline — fix the source declaration instead. "widening is the mapper's default" — mappers are precision-transparent; `T[K]` of `"get"` is `"get"` — blame flows upstream.

**Performance note** — narrow sources *reduce* check cost downstream (literal unions narrow switches to O(variants) instead of `string`-wide fallthroughs) — precision is a performance practice at scale, not just correctness.

**Mentor note** — trace widening backwards (hover the transform output → hover the source field → find `string`) as the standard debugging narrative — students learn to read hovers upstream, not patch downstream. Exercise: widen one source field deliberately and count how many downstream switches go silent — blast radius made visible.

### 2) **`as const` sources + `satisfies` contracts** (narrow input, checked shape)

**Definition** — the precision pair for transform inputs: `as const` narrows values to literals (`{ method: "get" }` keeps `"get"` instead of widening to `string`); `satisfies Contract` verifies the narrowed value still matches the intended shape (typos error, excess sneaks caught) *without* widening it back. Together: `typeof` the satisfied const gives a narrow, checked source that transforms preserve exactly.

**What problem it solves / history** — `as const` alone preserved literals but skipped validation (a typo'd `"gett"` narrowed faithfully into the pipeline and errored far downstream); annotations alone validated but widened (`: Route` erases `"get"` to… actually keeps it via literal-typed fields — but plain `: Config` with `string` fields widens). The pair (TS 4.9 `satisfies` completing the 3.4 `as const` story) gives both: `const t = {…} as const satisfies RouteTable` — typo-caught *and* literal-kept, with `typeof t` as the transform source.

**Modern guidance** — as of TypeScript 5.9 era, declare config/route/theme tables as `as const satisfies Contract`, derive working types with `typeof` + utilities (`Partial<typeof table>`, `keyof typeof table`), and let exhaustiveness consume the literals. Order matters: `as const` first (narrow), `satisfies` second (check) — reversed, the annotation widens before narrowing.

**Runnable example** — pair keeps literals checkable (good vs bad, `tsc --strict`):

```typescript
// good — as const narrows, satisfies checks, typeof + Partial transforms losslessly
interface RouteShape { method: "get" | "post"; path: string; }
const table = { home: { method: "get", path: "/" }, users: { method: "post", path: "/u" } } as const satisfies Record<string, RouteShape>;
// const badTable = { home: { method: "gett", path: "/" } } as const satisfies Record<string, RouteShape>; // error TS2353 — typo caught at the source
type T = typeof table;
type P = Partial<T["home"]>; // { method?: "get"; path?: "/" } — literals intact
const p: P = { method: "get" };
console.log(p.method?.toUpperCase() ?? "NONE"); // GET

// bad — annotation-only source widens before the transform runs
const loose2: Record<string, RouteShape> = { home: { method: "get", path: "/" } };
type L2 = Partial<typeof loose2.home>; // method?: "get" | "post" — widened at declaration
// fix — as const satisfies: narrow first, check second, transform third
console.log(loose2.home.method.toUpperCase()); // GET — value fine, type already widened
```

**Common confusion** — "`satisfies` narrows" — `satisfies` *checks* without changing the inferred (narrow, thanks to `as const`) type — narrowing comes from `as const`, validation from `satisfies`. "order is cosmetic" — `({…} satisfies C) as const` narrows *after* checking against possibly-wide `C` — legal but the check ran on different precision; `as const satisfies` checks the narrow value — prefer it. "`typeof` snapshots validate" — `typeof` captures whatever precision exists — pair it with the check or the snapshot bakes in typos (see [2.3. Type queries](<../../../04 Objects Interfaces and Type Aliases/sections/2. Composition and Declaration Merging/2.3. Type queries on objects keyof indexed access and typeof capture.md>)).

**Performance note** — `as const` deep-narrows large tables (every leaf becomes a literal + `readonly` — bigger cached types) — fine for curated config (hundreds of leaves), heavy for generated data (thousands — prefer explicit literal-typed interfaces there instead of const-asserting bulk output).

**Mentor note** — typo-drill: write `"gett"` in the table and compare errors with vs without `satisfies` (immediate TS2353 vs downstream exhaustiveness silence) — the check's value in one keystroke. Rule: every `as const` table gets a `satisfies` contract; every `satisfies` table meant for transforms gets `as const` first.

### 3) **Return-the-parameter through transforms** (thread `M`, not the constraint)

**Definition** — generic wrappers around utilities must return the *parameter* (`M`), not the constraint or the utility's input: `function pick<M extends string>(m: M): M` preserves `"get"` through any downstream `Partial`/`Pick`; `function pick(m: string): string` widens before the transform runs. [08/2.1](<../../../08 Generics Deep Dive/sections/2. Constraints Defaults and Inference Control/2.1. Constraints extends narrowing inside the body.md>) proved the rule for constraints — this promise applies it inside utility pipelines, where one widened joint collapses the whole chain's literals.

**What problem it solves / history** — `register(method: string): Route` helpers sat between literal sources and template-literal route tables: the source was narrow, the table derivation was exact, but the helper's `string` return widened the middle — generated `` `${method} ${path}` `` keys collapsed to `` `${string} ${string}` `` = `string`, and 200 route keys became one uncheckable type. Returning `M` keeps the chain narrow at every joint.

**Modern guidance** — as of TypeScript 5.9 era, audit every generic joint in a transform pipeline (helpers, middleware, wrappers) for parameter-vs-constraint returns — one `string` where `M` belongs collapses all downstream literals. Test joints with literal probes: `register("get")` must hover `"get"`, not `string`, before the pipeline is trusted.

**Runnable example** — narrow joints keep generated keys exact (good vs bad, `tsc --strict`):

```typescript
// good — M threaded through: generated route keys stay literal
function reg<M extends string, P extends string>(m: M, p: P): `${M} ${P}` { return `${m} ${p}`; }
const route = reg("get", "/users"); // "get /users" — literal key, hover it
function serve2<R extends string>(r: R): string { return `serving ${r}`; }
console.log(serve2(route)); // serving get /users

// bad — string joint collapses the whole downstream key set
function regBad(m: string, p: string): `${string} ${string}` { return `${m} ${p}`; }
const routeBad = regBad("get", "/users"); // `${string} ${string}` = string — 200 keys became one
// const check: "get /users" = routeBad; // error — string is not the literal (precision already lost)
// fix — return M/P (parameters), never string (the constraint), at every joint
```

**Common confusion** — "template output preserves regardless" — `` `${M} ${P}` `` with `M = string` yields `string` — templates preserve *what they are given*; widened joints give `string`. "one wide joint is harmless if the table re-narrows" — re-narrowing a widened `string` requires a runtime check per value — compile-time precision, once lost, is only recoverable at runtime cost. "constraints cause the widening" — constraints *admit*; `string` *annotations* widen — `M extends string` returning `M` stays narrow.

**Performance note** — literal-keyed tables (200 exact keys) check call sites precisely but each call verifies against 200 members — fine. The collapsed `string` version checks trivially but verifies nothing — precision costs linear member checks; collapse costs correctness. Prefer precision; split tables when call-site checks slow.

**Mentor note** — hover-probe every pipeline joint in review (`reg("get")` → `"get"`? or `string`?) — one probe per joint finds the collapse in seconds. Exercise: widen one joint deliberately and count the downstream keys before/after (200 → 1) — blast radius of a single annotation made visible.
