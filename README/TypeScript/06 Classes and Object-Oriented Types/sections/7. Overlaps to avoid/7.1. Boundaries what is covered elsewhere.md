## 7.1. Boundaries — what is covered elsewhere

### 1) **JavaScript runtime mechanics** (prototype chain, super, new.target, field initialization order) — [JavaScript 07 Prototypes and Classes](<../../../../JavaScript/07 Prototypes and Classes/README.md>)

**Definition** — this domain owns *static class types* (instance vs constructor, modifiers, extends/implements, abstract/override, this, mixins, queries). Runtime mechanics — `prototype`, `[[Prototype]]`, `super` binding, `new.target`, private `#field` slot semantics, field initializer ordering — are covered in JavaScript 07, not repeated here.

**What problem it solves** — avoids duplicating descriptor/prototype emission details already owned by JavaScript track.

**Modern guidance** — read JS 07 for `super()` ordering and `new.target`; this domain assumes that foundation.

**Runnable example** — boundary (good vs bad, `tsc --strict`):

```typescript
// good — runtime leak check: #private not enumerable (JS mechanic) but type-level brand here
class Hard { #x = 1; get x(): number { return this.#x; } }
const h = new Hard();
console.log(Object.keys(h as any)); // [] — runtime, not type — owned by JS 07
// this domain owns that #x brands structurally (type) and hides (checked)
```

**Cross-links** → [JavaScript 07 Prototypes and Classes](<../../../../JavaScript/07 Prototypes and Classes/README.md>).

### 2) **Object types and declaration merging** (structural object shapes, interface merging, extends vs & on objects) — [04 Objects, Interfaces and Type Aliases](<../04 Objects Interfaces and Type Aliases/README.md>)

**Definition** — [04 Objects](<../../../04 Objects Interfaces and Type Aliases/README.md>) owns object-type model: structural shape, freshness, `extends` vs `&` on object types, declaration merging, type queries `keyof`/`T[K]`. This domain only reaches class-specific extensions of those (class instance as object shape, `implements` as object check).

**What problem it solves** — avoids re-teaching object shapes under class names.

**Modern guidance** — for `extends` vs `&` on plain objects, read 04; for `class Foo extends Bar` vs `class Foo implements Iface`, stay here.

**Runnable example** — boundary (good vs bad, `tsc --strict`):

```typescript
// good — object shape owned by 04, class instance reuses it
type Shape = { x: number; y: number };
class Point { constructor(public x: number, public y: number) {} }
const p: Shape = new Point(1,2); // structural — owned by 04's rule, class instance is shape
```

**Cross-links** → [04 Objects](<../../../04 Objects Interfaces and Type Aliases/README.md>).

### 3) **Functions and callable types** (this parameter, callback variance, overloads, generics on functions) — [05 Functions and Callable Types](<../05 Functions and Callable Types/README.md>)

**Definition** — [05 Functions](<../../../05 Functions and Callable Types/README.md>) owns callable-type model: `this` parameter, `strictFunctionTypes` variance, overloads, rest/tuple, predicates/asserts. This domain only reaches `this` inside class methods and `override`'s call compatibility.

**What problem it solves** — avoids duplicating function variance catalog.

**Modern guidance** — for `this: void` on detached callbacks or `isT` predicates, read 05; for `method(): this` polymorphic clone, stay here.

**Runnable example** — boundary (good vs bad, `tsc --strict`):

```typescript
// good — function this param owned by 05, method this by this domain
class Repo { table = "users"; find(this: Repo, id: string): string { return this.table; } }
function use(cb: (id: string) => string) { cb("u"); }
// use(new Repo().find); // error TS2345 — this mismatch — owned by 05's variance, applied to class method
```

**Cross-links** → [05 Functions](<../../../05 Functions and Callable Types/README.md>).

### 4) **Unions, intersections, and narrowing** (discriminated unions, control-flow narrowing, exhaustiveness) — [07 Unions, Intersections and Narrowing](<../07 Unions Intersections and Narrowing/README.md>) (textual forward)

**Definition** — [07 Unions](<../../../07 Unions Intersections and Narrowing/README.md>) will own union/intersection composition, discriminant unions, `in`/`is` guards, exhaustiveness `never`. This domain only reaches class hierarchies as union members (`Dog | Cat extends Animal`) and `instanceof` narrowing.

**What problem it solves** — class hierarchies are one source of unions — full narrowing catalog lives in 07.

**Modern guidance** — for `if (x instanceof Dog)` full control-flow catalog, read 07 when it lands.

**Runnable example** — boundary (good vs bad, `tsc --strict`):

```typescript
// good — class union narrowing via instanceof (preview)
abstract class AnimalB { constructor(public name: string) {} abstract speak(): string; }
class DogB extends AnimalB { speak(): string { return "woof"; } }
class CatB extends AnimalB { speak(): string { return "meow"; } }
function handle(a: DogB | CatB): string {
  if (a instanceof DogB) return a.speak(); // narrowing owned by 07
  return a.speak();
}
```

**Cross-links** → [07 Unions](<../../../07 Unions Intersections and Narrowing/README.md>) (textual).

### 5) **Decorators and metadata** (class/method/field decorators) — [14 Decorators and Metadata](<../../../14 Decorators and Metadata/README.md>) (textual forward; this domain only reaches override/abstract/static)

**Definition** — [14 Decorators](<../../../14 Decorators and Metadata/README.md>) will own `@decorator` syntax, `ClassDecorator`, `MethodDecorator`, metadata emission. This domain stops at `override`/`abstract`/`static` which are modifiers, not decorators.

**What problem it solves** — avoids premature decorator teaching before class model is solid.

**Modern guidance** — for `@Component`/`@Injectable`/`@Log` patterns, read 14 when it lands; for access control and mixins, stay here.

**Runnable example** — boundary (good vs bad, `tsc --strict`):

```typescript
// good — this domain owns override, not @decorator
abstract class BaseD { abstract handle(): void; }
class ChildD extends BaseD {
  override handle(): void { console.log("handled"); } // modifier — here
  // @Log handle2(): void {} // decorator — owned by 14
}
```
