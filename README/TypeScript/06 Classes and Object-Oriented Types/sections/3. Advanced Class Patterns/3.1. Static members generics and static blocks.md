## 3.1. Static members — generics and static blocks

Static members belong to a class constructor. Instance members belong to objects created through that constructor. A generic class can describe different instance value types while still having one shared constructor at runtime. Static initialization therefore needs its own state and ordering model.

Examples use TypeScript 7.0.2 and Node 20.20.2, verified 2026-10-15. Save each named file in a fresh directory without tsconfig.json. Build with `tsc --strict --noImplicitOverride --exactOptionalPropertyTypes --erasableSyntaxOnly --target es2022 --module commonjs --lib es2022,dom --outDir dist FILE.ts`, then run `node dist/FILE.js`. Activate only one marked negative line in a separate copy and replace --outDir dist with --noEmit to check an intentional failure. Ordinary fields and constructor assignments keep these examples within the declared erasable-syntax gate.

### 1) **Constructor members and independent static generics**

Box.value is an instance contract whose T comes from constructing that particular typed value. Box.kind and Box.of are constructor members. The static method declares its own U because it can be called without any existing Box instance or chosen instance T. The [static type-parameter reference](https://www.typescriptlang.org/docs/handbook/2/classes.html#type-parameters-in-static-members) explains why a class-level T cannot supply a shared static slot.

Save `sides.ts`:

```typescript
export {};
class Box<T> {
  value: T;
  constructor(value: T) { this.value = value; }
  static kind = "box";
  static of<U>(value: U): Box<U> { return new Box(value); }
}
const numberBox: Box<number> = Box.of(42);
const textBox: Box<string> = Box.of("hi");
console.log(Box.kind, numberBox.value, textBox.value);
console.log("constructor:", numberBox.constructor === textBox.constructor);
// numberBox.kind; // TS2576: static member accessed through an instance.
// Box.value; // TS2339: instance member accessed through the constructor.
// class Invalid<T> { static value: T; } // TS2302: class T in a static member.

class Counter<T> {
  static total = 0;
  value: T;
  constructor(value: T) { this.value = value; Counter.total++; }
}
new Counter<number>(1);
new Counter<string>("x");
console.log("shared total:", Counter.total);
```

This prints `box 42 hi`, `constructor: true` and `shared total: 2`. The numeric and string Box instances do not create different runtime class constructors. Counter.total likewise counts both typed constructions. If the application needs a separate count per category, introduce a real runtime key and corresponding data structure; a generic argument is erased and cannot partition the state by itself.

Static state is appropriate when sharing is intentional, such as a documented registry. Instance state is appropriate when each object should own an independent value. Avoid treating a static mutable container as automatically safe or automatically wrong: define its ownership, clearing policy and callers. The [generic-scope owner](<../../../08 Generics Deep Dive/sections/1. Generic Fundamentals/1.3. Generic scope per-call vs per-value and declaration sites.md>) explains fixed container parameters versus independently generic operations in more depth.

### 2) **Class inference and minimal instance constraints**

Constructor arguments provide inference evidence. Mapping a Box<number> through a callback returning string produces Box<string>. An explicit argument is useful when the intended contract is broader than the current value, as with an initially null box that may later hold text. These are checked type relationships, not runtime specialization or input validation.

Save `inference.ts`:

```typescript
export {};
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
class Box<T> {
  value: T;
  constructor(value: T) { this.value = value; }
  map<U>(fn: (value: T) => U): Box<U> { return new Box(fn(this.value)); }
}
const numberBox = new Box(42);
const textBox = numberBox.map(value => value.toFixed(1));
const nullBox = new Box(null);
const editable = new Box<string | null>(null);
type NumberValue = Expect<Equal<typeof numberBox.value, number>>;
type TextValue = Expect<Equal<typeof textBox.value, string>>;
type NullValue = Expect<Equal<typeof nullBox.value, null>>;
type EditableValue = Expect<Equal<typeof editable.value, string | null>>;
console.log(numberBox.value, textBox.value, nullBox.value, editable.value);
editable.value = "ready";
console.log(editable.value.toUpperCase());
// nullBox.value = "ready"; // TS2322: inferred null contract.
// numberBox.map<string>(value => value); // TS2322: callback must return string.

class Repo<T extends { id: string }> {
  private items: readonly T[];
  constructor(items: readonly T[]) { this.items = items; }
  find(id: string): T | undefined { return this.items.find(item => item.id === id); }
  static fromArray<U extends { id: string }>(items: readonly U[]): Repo<U> {
    return new Repo(items);
  }
}
const repo = Repo.fromArray([{ id: "u1", name: "Ada" }]);
const user = repo.find("u1");
console.log(user?.name, repo.find("missing"));
// new Repo([{ name: "Ada" }]); // TS2353: missing required id contract.
```

The output is `42 42.0 null null`, `READY` and `Ada undefined`. The four equality assertions check the inferred value contracts. The Repo constraint includes id because its find implementation needs id. The inferred result still retains name and allows absence. Requiring an unrelated email field would exclude otherwise usable records without helping this implementation.

A type annotation permits values that meet its declared shape; it does not prove that an external record is valid. Use a checked boundary before constructing application data. The [generic-function owner](<../../../05 Functions and Callable Types/sections/2. Overloads and Generics/2.2. Generic functions inference constraints defaults and scope.md>) covers evidence and constraints; [inference and NoInfer](<../../../08 Generics Deep Dive/sections/1. Generic Fundamentals/1.2. Inference from arguments and explicit type arguments.md>) covers competing inputs and widened sources.

### 3) **Fields and blocks initialize in declaration order**

Static fields and static blocks execute interleaved in their declaration order during class evaluation. A block can use super.property to reach inherited static behavior. Its this is the class constructor, not an instance; super() constructor invocation is a different form and is rejected inside a static block. The [ECMAScript class-evaluation algorithm](https://tc39.es/ecma262/2026/multipage/ecmascript-language-functions-and-classes.html#sec-runtime-semantics-classdefinitionevaluation) accumulates static fields and blocks in one ordered list and evaluates that list against the constructor.

Save `blocks.ts`:

```typescript
export {};
const order: string[] = [];
class Base {
  static registry = new Map<string, string>();
  static get label(): string { return "base"; }
}
class Child extends Base {
  instanceField = 1;
  static first = (order.push("first"), 1);
  static #state = "initial";
  static {
    order.push("block:" + super.label + ":" + this.first);
    this.#state = "loaded";
    super.registry.set("child", this.#state);
    // this.instanceField; // TS2339: constructor has no such instance member.
    // super(); // TS2337: constructor call not permitted here.
  }
  static last = (order.push("last"), 2);
  static { order.push("second:" + this.last); }
  static readState(): string { return Child.#state; }
}
console.log(order.join(","));
new Child(); new Child();
console.log("after instances:", order.length, Child.first, Child.last, Child.readState());
console.log("inherited registry:", Child.registry === Base.registry,
  Object.hasOwn(Child, "registry"), Base.registry.get("child"));

function loadPort(text: string): number {
  const value = Number(text);
  if (!Number.isInteger(value) || value < 1 || value > 65535) throw new Error("invalid port");
  return value;
}
class Config {
  static port = 0;
  static {
    try { this.port = loadPort("oops"); }
    catch { this.port = 3000; }
  }
}
console.log("handled fallback:", Config.port);
try {
  class Failed {
    static { throw new Error("initialization failed"); }
  }
  console.log(Failed.name); // Not reached.
} catch (error: unknown) {
  console.log(error instanceof Error ? error.message : "unexpected error");
}
```

The output is `first,block:base:1,last,second:2`, `after instances: 4 1 2 loaded`, `inherited registry: true false loaded`, `handled fallback: 3000` and `initialization failed`. The first block sees the preceding first field. The second block sees last. Two new Child calls do not rerun those blocks. Child inherits the same registry object from Base; mutating it changes that shared object without installing an own registry property on Child.

Static private state is initialized before the block that writes it, and readState accesses it through its declaring class. The [access owner](<../1. Class Type Fundamentals/1.3. Access modifiers and encapsulation public private protected readonly.md>) covers private names and target-specific emission. This example targets ES2022 and retains the static block syntax; it makes no promise about other transforms or direct source execution.

The two failure cases show why a static block is not automatically exception-safe. Config handles its error and deliberately chooses a fallback. Failed lets its error escape, so evaluation exits to the surrounding catch and its following log is not reached. In production, decide whether a fallback is actually valid; hiding a required configuration failure can be worse than failing initialization. A static block is synchronous; an asynchronous initialization operation needs an explicit completion contract outside this block, as developed in the [async-return owner](<../../../18 Async Types and Standard Library/sections/1. Promise Types/1.3. async function return-type contracts.md>).

### 4) **Common confusion**

Changing Box<number> to Box<string> does not create another static storage area. A static method's own generic parameter is separate from the class's instance parameter. A static block does not wait until all later fields initialize and does not run per instance. Super property access can work there even though a super constructor call cannot. Finally, a block can organize a try/catch, but the error is handled only when the code actually handles it.

### 5) **Performance note**

Generic parameters and equality probes erase. Class evaluation still performs every static initializer and block operation, including registry mutations or validation. Repeated class evaluation would repeat that work; ordinary instance construction does not rerun these static blocks. Static containers can retain their contents while reachable, so choose a suitable lifecycle instead of assuming every static lives forever. No constant-time cache, linear instantiation-count formula, optimizer behavior or negligible-cost guarantee was measured. Use the [measurement workflow](<../../../19 Performance Project References and Scaling/sections/1. Check-Time Performance/1.1. Measuring with extendedDiagnostics and traces.md>) for checker concerns and measure actual startup/allocation behavior separately.

### 6) **Mentor note**

Before running blocks.ts, ask the learner to place the four order entries and predict whether new Child changes them. Then ask whether Child owns registry and whether mutating the inherited Map affects Base. A sound answer separates inheritance of a property from mutation of its referenced object. For generics, explain why a new string Counter increments the same total as a numeric Counter and why static of needs its own parameter. Finish by removing Config's catch in a separate experiment and predicting where initialization stops; the Failed example supplies the observed comparison.
