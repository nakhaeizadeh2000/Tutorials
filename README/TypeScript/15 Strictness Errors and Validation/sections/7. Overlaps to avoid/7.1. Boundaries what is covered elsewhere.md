### 5) **Async error propagation and runtime handling** (rejections, backstops, top-level architecture) — [18 Async Types and Standard Library](<../../../18 Async Types and Standard Library/README.md>)

**Definition** — async error *transport* (rejected promises ≈ throws; `Result`-valued resolutions ≈ returns — same categories, async syntax), floating-promise discipline (`no-floating-promises` + `void`+.catch), and runtime-level handling (per-entry backstops, `unhandledRejection` architecture) live in domain 18 — this domain *synchronously* practiced the same categories (throw-vs-return discipline, never-throw contracts, top-level handler shapes) that 18 transports asynchronously.

**What problem it solves / history** — 15 owns "which errors throw vs return?"; 18 owns "how do rejections propagate through async graphs?" — categories vs transport, composed at every async boundary (15's discipline deciding, 18's mechanics delivering). Sync-first mastery (this domain) transfers directly (same categories, `await` transparently rethrowing into local `try/catch`).

**Modern guidance** — as of TypeScript 5.9 era, decide sync categories here (throw-vs-return per function — 2.1 promise 3's rule); transport via 18 (`await` rethrows into local catches — sync-shaped reasoning preserved; floating promises handled via `void`+.catch — never bare). Until 18 lands: `await` every promise (containment by construction) + backstops per entry (report + degrade — 2.3 promise 3's architecture, async-applied).

**Runnable example** — sync discipline, async transport (good vs bad, `tsc --strict`):

```typescript
// good — awaited async with local containment (sync-shaped reasoning preserved across transport)
export {}; // module marker for top-level await in this runnable snippet
async function fetchAge(ok: boolean): Promise<number> {
  if (!ok) throw new Error("fetch failed"); // async throw (transport — same category as sync throw, delivered via rejection)
  return 36;
}
async function age(): Promise<string> {
  try {
    return (await fetchAge(true)).toFixed(0); // awaited (rejection lands locally — containment by construction)
  } catch {
    return "unknown"; // contained (never-throw handler contract per 2.3 promise 1 — fallback served)
  }
}
console.log(await age()); // 36 — categories (15) transported (18-preview mechanics — same discipline, async syntax)
// bad — floating promises (unawaited rejections bypassing local catches — process-level crashes for locally-handleable errors)
// fix — await (containment by construction) or void+.catch (explicit float handling) — never bare floats (see 5.1 promise 2)
```

```typescript

export {}; // module marker (each fence compiles standalone — markers repeated per fence needing top-level await)
async function lookupAsync(id: string): Promise<{ ok: true; value: string } | { ok: false }> {
  return id === "a" ? { ok: true, value: "A" } : { ok: false }; // Result resolution (expected miss — value, not rejection)
}
const la = await lookupAsync("zzz");
console.log(la.ok ? la.value : "missing"); // missing — routine miss (handled per call site — transport-agnostic discipline)
// bad — rejecting routine misses (async throws for expected failures — every consumer try/catches per lookup or crashes)
// fix — Result resolutions (expected→values across transport — same categories as sync 2.1 promise 3, async syntax)
```

```typescript

  throw new Error("boot failed"); // unexpected failure (programmer bug — backstop territory, not local handling)
}
const out = await mainAsync().catch((e: unknown) => `reported:${e instanceof Error ? e.message : "?"}`); // backstop at entry (report + degrade — last resort, tested by fault-injection)
console.log(out); // reported:boot failed — entry backstop (async-applied 2.3 architecture — faults reported, never silent)
// bad — no entry backstop (first unhandled rejection crashes the process with default logging — worst diagnostics at worst moment)
// fix — backstop per async entry (report + degrade — 2.3 promise 3's shapes transported asynchronously)
```

**Common confusion** — "async needs different error rules" — same categories (expected→values, bugs→throws), different *transport* (rejections ≈ throws; Result-resolutions ≈ values) — discipline transfers directly, syntax adapts. "top-level await removes handling needs" — `await` *contains* (rejection lands locally); un-awaited top-level expressions still float (position changes nothing about handling). "backstops replace handling" — backstops catch *unknown* failures (last resort); known async work handles explicitly (primary handling per promise — backstops never substitute).

**Performance note** — async transport costs microtask hops per await (nanoseconds — same as sync calls for practical purposes); unhandled rejections cost process crashes (unbounded — all in-flight work lost per float). Handling discipline is pure incident prevention at zero steady cost.

**Mentor note** — remove one `await` and crash a dev process via unhandledRejection (float-to-crash in one deletion — handling proven load-bearing). Exercise: enable `no-floating-promises` and fix each error (await/catch per float — at-risk list pre-triaged). Review gate: floating promises fail review unconditionally.
