## 1.3. `satisfies` as a validation gate

### 1) **`satisfies` checking without widening** (contracts verified, literals preserved)

**Definition** — `const t = {...} satisfies Contract` verifies the value matches `Contract` *without* widening its inferred type (literals stay literal, excess members error, missing members error — checking without conversion). [04/3.3](<../../../04 Objects Interfaces and Type Aliases/sections/3. Advanced Object Types/3.3. satisfies assertions and narrowing on object shapes.md>) owns object mechanics; [07/3.3](<../../../07 Unions Intersections and Narrowing/sections/3. Control Flow Narrowing/3.3. Custom narrowers predicates asserts and type guards on unions.md>) owns union narrowing; [09/3.3](<../../../09 Utility Types and Type Transformations/sections/3. Transformations in Practice/3.3. satisfies and as const preserving literals through transforms.md>) owns transform preservation — this promise owns *gating practice*: `satisfies` as the validation step before values flow into checked pipelines.

**What problem it solves / history** — annotations validated *by widening* (`const t: Contract = {...}` — literals widened to constraint types, exhaustiveness downstream dead) while `as const` narrowed *without checking* (typos preserved literally into pipelines, erroring far downstream). `satisfies` (TS 4.9) gives both: checked against the contract *and* inferred narrowly — typo-caught *and* literal-kept, with `typeof` downstream seeing the narrow truth.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), gate config/table/route declarations with `as const satisfies Contract` (narrow first via `as const`, check second via `satisfies` — order matters, see 09/3.3); derive working types with `typeof` + utilities (unions, keys, mapped transforms preserving literals end to end); prefer `satisfies` over annotations wherever downstream exhaustiveness matters.

**Runnable example** — checked narrow, derived exactly (good vs bad, `tsc --strict`):

```typescript
// good — as const narrows, satisfies checks, typeof derives (precision pipeline, fully gated)
interface RouteShape { method: "get" | "post"; path: string }
const table = {
  home: { method: "get", path: "/" },
  users: { method: "post", path: "/u" },
} as const satisfies Record<string, RouteShape>; // typo-caught AND literal-kept (both guarantees, one expression)
type Home = (typeof table)["home"]; // { readonly method: "get"; readonly path: "/" } — narrow derivation
const h: Home = { method: "get", path: "/" };
console.log(h.method.toUpperCase()); // GET — literals flowing (exhaustiveness consumable downstream)
// const bad = { home: { method: "gett", path: "/" } } as const satisfies Record<string, RouteShape>; // error TS2353 (typo caught at source)
```

```typescript
// good — annotation widens where satisfies preserves (exhaustiveness alive vs dead downstream)
interface RouteShape { method: "get" | "post"; path: string } // re-declared: fences compile standalone
const wide: RouteShape = { method: "get", path: "/" }; // method: "get" | "post" (widened — union, not literal)
function handle(m: "get"): string { return m; }
// handle(wide.method); // error TS2345 (widened union not assignable to literal — exhaustiveness dead at declaration)
// fix — as const satisfies (narrow preserved — downstream literals provable, switches exhaustible)
const narrow = { method: "get", path: "/" } as const satisfies RouteShape;
console.log(handle(narrow.method)); // get — preserved literal (gate kept precision the annotation surrendered)
```

```typescript
// good — excess members caught (annotations allow excess via freshness gaps in some positions; satisfies never does)
// const cfg = { host: "h", port: 80, extra: true } as const satisfies { host: string; port?: number }; // error TS2353 (excess "extra" rejected — contract-exactness enforced)
// (annotations sometimes pass excess through freshness gaps; satisfies checks exactness — gates, not suggestions)
// fix — satisfies for exactness (typos AND excess caught — contract gates, not suggestions)
interface CfgGate { host: string; port?: number }
const g: CfgGate = { host: "h" };
console.log(g.host.toUpperCase()); // H — gated config (checked shape, narrow literals, derived freely)
```

**Common confusion** — "`satisfies` narrows" — `satisfies` *checks* (validation without type change); narrowing comes from `as const` (or literal-typed sources) — pair them deliberately (`as const satisfies`), order fixed (narrow-then-check). "order is cosmetic" — `({...} satisfies C) as const` narrows *after* checking a possibly-wide value (check ran on different precision); `as const satisfies` checks the narrow value — prefer narrow-first always. "annotations suffice with literals" — annotations *widen* to the constraint (`: RouteShape` yields `"get" | "post"`) — exhaustiveness needs the literal `satisfies` preserves.

**Performance note** — zero emit delta (`satisfies` erases fully); check cost one contract verification per declaration (trivial); downstream switches stay narrow (fewer members = faster checks — precision dividends, not costs).

**Mentor note** — typo-drill (`"gett"` with vs without `satisfies` — immediate TS2353 vs downstream exhaustiveness silence) — the gate's value in one keystroke. Rule: every `as const` table gets a `satisfies` contract; every `satisfies` table meant for transforms gets `as const` first (narrow-then-check, always in that order).

### 2) **Gating config and tables** (typo-proof narrow tables feeding transforms)

**Definition** — config/route/theme tables declared `as const satisfies Contract` serve as *gated sources*: typos caught at declaration (TS2353), literals preserved for derivation (`typeof` + indexed access + mapped transforms), excess rejected (contract-exactness). Downstream pipelines (unions, handler maps, template tables, exhaustive switches) consume derived narrow types — precision end to end from one gated declaration.

**What problem it solves / history** — ungated tables failed two ways silently (typos preserved literally into pipelines — erroring far downstream at exhaustiveness switches with no pointer to the source; widened tables killing exhaustiveness at the declaration — no error anywhere, just dead switches). Gating fixes both at the source: typos error where typed, literals flow where derived — one declaration, two guarantees.

**Modern guidance** — as of TypeScript 5.9 era, gate every curated table (config, routes, themes, permissions, statuses) with `as const satisfies <Contract>`; derive working sets (`typeof t[number]`, `keyof typeof t`, mapped projections) instead of re-listing; consume through exhaustive switches (literals provable — coverage enforced downstream of gated sources).

**Runnable example** — gated source, derived consumers (good vs bad, `tsc --strict`):

```typescript
// good — gated theme table (typo-proof, narrow, derivable — one declaration serving tokens + switches)
interface ThemeShape { bg: string; fg: string }
const theme = { dark: { bg: "#000", fg: "#fff" }, light: { bg: "#fff", fg: "#000" } } as const satisfies Record<string, ThemeShape>;
type ThemeName = keyof typeof theme; // "dark" | "light" — derived (never listed — drift impossible)
function css(t: ThemeName): string { return theme[t].bg; }
console.log(css("dark")); // #000 — gated source (typos caught) + derived consumers (literals preserved)
// const badTheme = { dark: { bg: "#000", fg: "#fff" }, dakr: { bg: "x", fg: "y" } } as const satisfies Record<string, ThemeShape>; // hmm — excess keys allowed by index signature (contract-exactness needsika stricter shapes; excess against object types errors — see below)
// (above: index-signature contracts accept extra keys — exactness enforced via object-type contracts + excess checks per 04 freshness rules)
```

```typescript
// good — gated status table feeding an exhaustive switch (literals alive end to end)
const STATUSES = ["idle", "done"] as const satisfies readonly string[]; // gated (array-shape checked, literals kept)
type Status = (typeof STATUSES)[number]; // "idle" | "done" — derived union (narrow — exhaustiveness consumable)
function next(s: Status): Status {
  switch (s) {
    case "idle": return "done";
    case "done": return "idle";
    default: { const n: never = s; throw new Error(`unhandled:${String(n)}`); } // sunk (new status breaks HERE — see 07/3.2)
  }
}
console.log(next("idle")); // done — gated source (typo-proof) + exhaustive consumer (coverage-proven)
// bad — ungated string[] table (literals widened at declaration — derived union is string — switches unprovable)
// fix — as const satisfies (narrow preserved — downstream exhaustiveness alive, not dead on arrival)
```

```typescript
// good — contract sizing (wide contracts accept; narrow values preserve — both guarantees composed)
interface Loose { path: string; method?: string }
const routes = { a: { path: "/a" } } as const satisfies Record<string, Loose>; // wide contract (flexible) + narrow values (preserved)
type R = keyof typeof routes; // "a" — derived key set (exact — excess rejected, typos caught, literals kept)
console.log(routes.a.path.toUpperCase()); // /A — wide acceptance (contract) + narrow preservation (values) composed
// bad — annotation-only tables (contract accepted, literals widened — half the guarantees surrendered at declaration)
// fix — gate (as const satisfies): acceptance AND preservation (both guarantees, one expression, zero trade-offs)
```

**Common confusion** — "wide contracts defeat gating" — wide contracts accept flexibly *while* narrow values preserve precisely (acceptance vs preservation compose — `Record<string, Loose>` accepts broadly, `as const` keeps literally). "gated tables can't evolve" — evolve by editing (additions checked against the contract instantly — gated evolution is *safer* evolution, not slower). "derivation obscures" — `typeof t[number]` reads as "the table's members" (one hop, greppable) — re-listed unions obscure *more* (two sources, drift-prone).

**Performance note** — gated tables cost one contract check per declaration (trivial); derived unions cache per access (one computation each); narrow switches check per member (fast for curated sets). Precision dividends (incident prevention) dwarf check costs.

**Mentor note** — typo one table key with and without the gate (immediate TS2353 vs downstream exhaustiveness silence) — gating value in one keystroke. Exercise: gate three ungated tables and count downstream exhaustiveness revivals (dead switches re-armed per table). Review gate: curated tables without `as const satisfies` fail review.

### 3) **`satisfies` vs `as` vs annotation** (check-and-keep vs override vs widen)

**Definition** — three intents, three syntaxes, zero interchange: `satisfies C` = check-against-C-keep-my-type (validation without conversion — literals preserved, excess rejected); `as T` = override-to-T (assertion *replacing* the checker's view — laundering unless evidence-backed); `: T` annotation = widen-to-T (contract acceptance with literal loss — exhaustiveness surrendered). Choosing by intent (validate? override? accept?) — never by habit.

**What problem it solves / history** — syntax confusion (`as` where `satisfies` belonged — laundering instead of checking; annotations where `satisfies` belonged — widening instead of preserving; `satisfies` where `as` belonged — checking uncheckable dynamics) produced three incident flavors per misuse (unchecked typos, laundered mismatches, dead exhaustiveness). Intent-first selection (validate → satisfies; override-with-evidence → as; accept-and-widen → annotation) routes each case correctly.

**Modern guidance** — as of TypeScript 5.9 era, default to `satisfies` (check without conversion — safest); reach for annotations when widening serves (general-string returns, normalized outputs); reach for `as` only with evidence (narrowed-unknown post-validation, single contained site — never chains). Review each `as` for evidence (validation before it?) and each annotation for intent (widening deliberate?).

**Runnable example** — intent selects syntax (good vs bad, `tsc --strict`):

```typescript
// good — satisfies validates (literals kept, excess rejected — check without conversion)
interface Cfg3 { host: string }
const cfgClean = { host: "h" } as const satisfies Cfg3; // exact (checked + narrow — validation complete)
console.log(cfgClean.host.toUpperCase()); // H — checked narrow (literals preserved for downstream exhaustiveness)
// bad — as Cfg3 on { host: 42 } (laundering: wrong-typed value blessed — check skipped, crash downstream)
// fix — satisfies (validation without conversion — typos/wrongs error, literals preserved)
```

```typescript
// good — annotation widens where generality serves (normalized outputs, general-string returns)
function normalize(port: number | undefined): string {
  const p: string = port === undefined ? "default" : String(port); // annotation widens deliberately (general contract published)
  return p;
}
console.log(normalize(undefined), normalize(80)); // default 80 — widening by design (downstream unions unaffected — generality intended)
// bad — satisfies where widening was intended (literals preserved into general pipelines — over-narrowing downstream unions)
// fix — annotations publish generality (string returns for string positions — precision where consumed, generality where published)
```

```typescript
// good — as with evidence (single contained assertion post-validation — laundering nowhere else)
function parsePort(raw: unknown): number {
  if (typeof raw !== "number") throw new Error("port must be number"); // evidence (validation first — throws on mismatch)
  return raw as number; // hmm — raw already narrowed to number (assertion redundant — kept to show the pattern's shape, harmless)
}
console.log(parsePort(80).toFixed(0)); // 80 — evidence-backed assertion (single site, post-validation — the only honest as)
// bad — raw as number without validation (laundering: unvalidated unknown blessed — malformed payloads crash downstream confidently)
// fix — validate-then-assert (evidence first, assertion second, single site — laundering nowhere else, ever)
```

**Common confusion** — "`satisfies` replaces annotations" — `satisfies` *checks* (keeps types); annotations *accept* (widens to contracts) — different intents (validate vs publish-generality). "`as` is satisfies-plus" — `as` *overrides* (replaces the checker's view — evidence required); `satisfies` *verifies* (confirms against contracts — evidence produced as errors). "one syntax suffices with discipline" — discipline *is* choosing per intent (three intents, three syntaxes — uniform syntax forces two intents into lying shapes).

**Performance note** — all three erase fully (zero emit delta); check cost one verification/override/widening per site (trivial each); incident cost concentrates in misused `as` (laundering) and misused annotations (dead exhaustiveness) — intent-matched selection deletes both classes.

**Mentor note** — present one value needing all three treatments (validate a config + override a parsed boundary + widen a return) and assign syntaxes per intent (satisfies/as/annotation — intent-first selection in one value). Exercise: convert three misused syntaxes (as→satisfies where checking served; annotation→satisfies where literals died; satisfies→as where dynamics needed override) — intent matched per site. Review gate: unevidenced `as` fails review; exhaustiveness-killing annotations fail review.
