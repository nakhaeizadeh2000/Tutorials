## 1.2. Type predicates vs assertions — caller vs thrower

### 1) **Predicates narrow callers** (boolean-returning type tests for recoverable paths)

**Definition** — `function isString(x: unknown): x is string` returns `boolean` and narrows *the caller's* flow (inside `if (isString(x))`, `x` is `string`; in `filter(isString)`, output is `string[]`). No throwing — `false` is a normal outcome the caller handles (skip, default, alternate branch). [05/3.3](<../../../05 Functions and Callable Types/sections/3. Advanced Callable Patterns/3.3. Type guards predicates asserts and satisfies on functions.md>) + [07/3.3](<../../../07 Unions Intersections and Narrowing/sections/3. Control Flow Narrowing/3.3. Custom narrowers predicates asserts and type guards on unions.md>) own mechanics; this promise owns *practice*: where predicates (not assertions) belong.

**What problem it solves / history** — recoverable filtering without predicates needed casts per consumer (`users.filter(u => u.kind === "admin")` staying `User[]`, then `as Admin[]` at every use — each cast a lie the filter already proved unnecessary) or `any`-shaped helpers (filtering precisely at runtime, typing nothing). Predicates fuse the runtime test with the type claim: one function, tested once, narrowing everywhere it's used as a guard.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), write predicates for recoverable decisions (filtering, finding, optional handling, discriminating mixed inputs); name them `isX`/`hasX`/`canX` (recognition vocabulary — reviewers read intent from names); test both branches (true-narrows *and* false-excludes — predicate tests cover the type claim in both directions).

**Runnable example** — callers narrow without throwing (good vs bad, `tsc --strict`):

```typescript
// good — predicate fuses runtime test with type claim (tested once, narrowing everywhere)
interface User { kind: string }
interface Admin extends User { kind: "admin"; level: number }
function isAdmin(x: User): x is Admin {
  return x.kind === "admin"; // runtime test (kind check) + type claim (Admin) in one function
}
const users: User[] = [{ kind: "user" }, { kind: "admin", level: 2 } as Admin];
const admins: Admin[] = users.filter(isAdmin); // Admin[] (narrowed by the predicate — no cast downstream)
console.log(admins.map((a) => a.level.toFixed(0)).join(",")); // 2 — filtered + narrowed (fused, tested once)
// bad — filter + cast per consumer (runtime test without type claim — each use re-asserts what the filter proved)
// fix — isAdmin predicate (claim travels with the test — consumers narrow, never cast)
```

```typescript
// good — find-narrowing for optional handling (absence stays recoverable, never thrown)
interface Config { host?: string }
function hasHost(c: Config): c is Required<Config> {
  return typeof c.host === "string"; // guard proving full shape (Required — all fields present per check)
}
function addr(c: Config): string {
  return hasHost(c) ? c.host.toUpperCase() : "localhost"; // narrowed branch (full Config) + fallback (recoverable)
}
console.log(addr({}), addr({ host: "h" })); // localhost H — recoverable paths (no throw for missing config)
// bad — asserting optional config (throwing on missing host — recoverable absence escalated to crash)
// fix — predicates for recoverable (filter/find/default); assertions for invariants (see 1.1) — decision per call site
```

```typescript
// good — both predicate branches tested (true-narrows AND false-excludes verified)
function isNonEmpty(s: string | null): s is string {
  return s !== null && s !== ""; // two conditions, one claim (empty AND null excluded together)
}
console.log(isNonEmpty("a"), isNonEmpty(""), isNonEmpty(null)); // true false false — both branches covered
// const xs: (string | null)[] = ["a", "", null];
// console.log(xs.filter(isNonEmpty).map((s) => s.toUpperCase()).join(",")); // A — filtered + narrowed (fused)
// bad — testing true-branch only (false-excludes unverified — predicate lies dormant until the first excluded input)
// fix — both branches per predicate test (claim verified in both directions — narrowing AND exclusion proven)
console.log(["a", "", null].filter(isNonEmpty).map((s) => s.toUpperCase()).join(",")); // A — fused in action
```

**Common confusion** — "predicates validate" — predicates *test* (boolean claim about the value — caller decides recovery); validators *prove-or-throw* (assertions) or *parse* (schemas producing new values) — test vs prove vs produce differ. "boolean-returning helpers narrow" — only `x is T`-annotated returns narrow (plain `boolean` returns narrow nothing — the annotation *is* the narrowing contract). "predicates replace assertions" — recoverable paths (filter/find/default) vs invariants (must-hold-or-crash) — complementary tools (see the decision rule in promise 3), never substitutes.

**Performance note** — predicate calls cost one function + test per element (identical to inline conditions — abstraction without overhead); filtered arrays allocate per `filter` (standard); both-branches testing costs two assertions per predicate (trivial, permanent).

**Mentor note** — convert one filter+cast pair to a predicate live (cast deleted, filter narrowed — fusion made visible in one edit). Exercise: audit `as` casts after `filter`/`find` calls (each a missing predicate — convert and delete the cast). Review gate: casts downstream of guardable filters/finds fail review (predicates fuse test + claim).

### 2) **Assertions narrow throwers** (fused enforcement for invariants)

**Definition** — `asserts x is T` (and `asserts condition`) fuses check + narrow + named failure: failing *throws* (never returns normally), succeeding narrows the caller's flow to `T` (or truthiness) with no remaining branch. [1.1. Assertion signatures](<./1.1. Assertion signatures asserts condition and asserts x is T.md>) owns shapes and libraries; this promise owns *placement*: where throwers (not predicates) belong — invariants, capabilities, state transitions, exhaustiveness sinks.

**What problem it solves / history** — invariant enforcement via predicates (`if (!isReady(svc)) throw …` — check and enforcement split across two statements verified together per site) drifted per call site (check right, throw missing/delayed/generic — half-enforced invariants passing review). Assertion form fuses both (one call enforces *and* narrows with a named failure) — half-enforcement structurally impossible (the call does both or neither).

**Modern guidance** — as of TypeScript 5.9 era, assert invariants (service readiness, admin capability, config presence, state legality, exhaustiveness unreachability); predicate recoverables (filtering, finding, defaulting, discriminating mixed inputs); never assert user input (recoverable by definition — parse/narrow it) and never predicate invariants (half-enforcement by construction — fuse them).

**Runnable example** — fused enforcement (good vs bad, `tsc --strict`):

```typescript
// good — readiness asserted once (enforcement + narrowing fused, message named)
interface Service { ready: boolean; run(): string }
function assertReady(s: Service): asserts s is Service & { ready: true } {
  if (!s.ready) throw new Error("service not ready"); // named failure (diagnosable per domain)
}
const svc: Service = { ready: true, run: () => "ran" };
assertReady(svc); // enforced (throws when unready) + narrowed (ready: true downstream — no branch)
console.log(svc.run()); // ran — fused (one call, two guarantees — half-enforcement impossible)
// bad — if (!svc.ready) throw ... per call site (check + enforcement split — drift per site: check right, throw generic?)
// fix — assertReady (fused: enforcement and narrowing travel together, message named once)
```

```typescript
// good — exhaustiveness sinks assert unreachability (new members break loudly — see 07/3.2 mechanics, 15 placement)
// (assertNever from 1.1: shared helper — placement rule here is sink every behavior switch over finite sets)
type Mode = "on" | "off";
function flip(m: Mode): Mode {
  switch (m) {
    case "on": return "off";
    case "off": return "on";
    default: { const n: never = m; throw new Error(`unhandled:${String(n)}`); } // fused unreachability proof
  }
}
console.log(flip("on")); // off — sinked switch (member addition breaks HERE — placement: every behavior switch)
// bad — default: return m (unproven fallthrough — new members flow through silently as stale values)
// fix — never-sink defaults (placement: behavior switches over finite sets sink, unconditionally)
```

```typescript
// good — user input NEVER asserted (parsed/narrowed recoverably — invariants vs inputs distinguished)
function handleAge(raw: unknown): string {
  if (typeof raw !== "number") return "invalid age"; // recoverable (predicate-style narrowing — no throw for user data)
  return `age:${raw.toFixed(0)}`; // narrowed (number proven — user input handled, never asserted)
}
console.log(handleAge("x"), handleAge(21)); // invalid age age:21 — recoverable paths (parse/narrow, never assert-throw)
// bad — assert(typeof raw === "number") on user input (400-errors-as-crashes — recoverable absence escalated to throw)
// fix — predicates/unions for inputs (recoverable); assertions for invariants (must-hold-or-crash) — decision per call site
```

**Common confusion** — "assertions validate input" — assertions enforce *invariants* (programmer-context truths: readiness, capability, configuration, unreachability); *input* validates via parse/narrow (recoverable by definition — throwing on user data is a bug, not strictness). "fused calls hide logic" — fused calls *name* logic (assertReady states the invariant — clearer than inline `if-throw` spelling it per site). "throwing is always bad practice" — throwing *invariants* is design (fail-fast with named errors); throwing *recoverables* is the bug — throw by category, not by habit.

**Performance note** — assertions cost one branch per call (negligible); throws exceptional (stack capture on violation only — the design point). Fused vs split identical runtime (one check either way — fusion saves statements, not cycles).

**Mentor note** — convert one predicate+throw pair to `asserts` live (two statements → one call, message named once) — fusion made visible in one edit. Exercise: classify ten checks by invariant-vs-recoverable (assert vs predicate — decision per call site, documented). Review gate: predicate+manual-throw pairs fail review (fused assertions); assertions on user input fail review (parse/narrow instead).

### 3) **Choosing per call site** (recoverable → predicate; invariant → assertion)

**Definition** — the decision rule: can the caller *recover* (skip, default, retry, alternate branch)? → predicate (`is`/`has` returning boolean — caller branches). Must the program *halt* that path (invariant violated — proceeding corrupts)? → assertion (`asserts` throwing named error — no branch remains). User input is *always* recoverable (parse/narrow — never assert-throw); unreachability is *always* assert (never-sink — see 07/3.2).

**What problem it solves / history** — uniform checking style (everything predicates — invariants half-enforced via forgotten throws; or everything assertions — user input crashing as 500s) mismatched half the call sites by construction (one tool for two jobs). Per-site decisions match tool to category: predicates where recovery exists, assertions where halting is correct — each call site independently right, reviewably so.

**Modern guidance** — as of TypeScript 5.9 era, ask per check: "on failure, does the caller *continue differently* (predicate) or *stop this path* (assertion)?" Document borderline calls (config-missing at startup: assert (cannot proceed); config-missing at request: predicate + default (proceed degraded)). Never assert-throw across trust boundaries to users (400-responses via parse/narrow, never 500s via assertion).

**Runnable example** — decisions per site (good vs bad, `tsc --strict`):

```typescript
// good — predicate (recoverable: skip + default) AND assertion (invariant: halt path) composed correctly
function isLong(s: string): s is string {
  return s.length > 3; // predicate (recoverable — caller filters/defaults, never throws)
}
function assertConfigured(port: number | undefined): asserts port is number {
  if (port === undefined) throw new Error("missing:PORT"); // assertion (invariant — cannot serve without port)
}
const names = ["ab", "abcd"];
console.log(names.filter(isLong).map((s) => s.toUpperCase()).join(",")); // ABCD — predicate recovery (filter path)
// assertConfigured(undefined); // throws missing:PORT (invariant path — halt, don't default a port)
// fix — per-site decisions (filter with predicates, enforce with assertions — tools matched to categories)
function boot(port: number | undefined): string {
  assertConfigured(port); // halt path (no port → no server — correct category for assertion)
  return `:${port}`; // port: number (narrowed — invariant proven, no branch remaining)
}
console.log(boot(80)); // :80 — composed correctly (recoverable filtered, invariants asserted)
```

```typescript
// good — borderline documented (startup config asserts; request config predicates — same data, different paths)
function getPort(env: Record<string, string | undefined>, required: boolean): number | undefined {
  const raw = env["PORT"];
  if (required) {
    if (raw === undefined) throw new Error("missing:PORT (startup — cannot proceed)"); // documented borderline (startup asserts)
  }
  return raw === undefined ? undefined : Number(raw); // request path degrades (predicate-style recovery)
}
console.log(getPort({}, false) ?? "default", getPort({ PORT: "1" }, false)); // default 1 — borderline decided per path (documented in code)
// bad — one rule globally (always-assert (request crashes) or always-predicate (startup boots unconfigured) — category error)
// fix — decide per PATH (same check, different contexts — startup halts, requests degrade, documented inline)
```

```typescript
// good — never-sink always asserts (unreachability is invariant by definition — no recoverable reading exists)
function assertNever(x: never): never { throw new Error(`unreachable:${String(x)}`); }
type Sig = "x" | "y";
function sig(s: Sig): number {
  switch (s) {
    case "x": return 1;
    case "y": return 2;
    default: return assertNever(s); // unreachability asserts (no recovery possible — halt with proof)
  }
}
console.log(sig("x")); // 1 — sinked (member addition breaks here — placement: every behavior switch, unconditionally)
// bad — default: return -1 (unreachable coded as a value — new members flow into -1 silently, callers trusting the type)
// fix — assertNever defaults (unreachability is invariant — assert, never default-value it away)
```

**Common confusion** — "predicates are safer (no throws)" — predicates are *recoverable-path* tools (safe where recovery exists; half-enforcement where invariants need halting) — safety follows category-match, not tool choice. "assertions are stronger (always throw)" — assertions on recoverable paths *crash servable requests* (strength misapplied — 500s for 400-situations). "borderlines need team policy" — borderlines need *inline documentation* (startup-asserts vs request-degrades decided per call site, commented) — policy can't enumerate paths, comments can.

**Performance note** — predicates cost branches per use (callers branch — expected); assertions cost branches per call + throws on violation (exceptional — fail-fast economics). Decision quality affects incidents, never steady-state speed.

**Mentor note** — classify ten existing checks live (recoverable→predicate? invariant→assert? borderline→document?) — decision drill transferring in under an hour. Exercise: find one asserted-recoverable (user-input throw → parse/narrow) and one predicated-invariant (half-enforced → fused assert) — both misdecisions corrected per rule. Review gate: user-input assertions fail review; unfused invariant checks fail review.
