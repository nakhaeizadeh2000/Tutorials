## 3.1. Hand-rolled schemas — parse, validate, narrow

### 1) **Parse functions returning unions** (validation discharging `unknown` honestly)

**Definition** — `parseUser(raw: unknown): User | ParseError[]` — validation *produces* typed values from unknown (success) or structured errors (failure), discharging `unknown` honestly: no `as` casts downstream of real parsers, ever. Parse (unknown→typed-or-errors) differs from validate (typed→checked, see 14/3.1) in input kind — unknown boundaries parse, typed values validate.

**What problem it solves / history** — `as`-cast ingestion (`JSON.parse(raw) as User` — assertion without evidence; malformed payloads crashing downstream with confident types) made every boundary a lie agreed upon by both sides (producer unvalidated, consumer trusting). Parse functions convert the lie into a contract: unknown in, `User | Error[]` out — malformed payloads surface as *values* (error lists) at the boundary, never as crashes downstream.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), parse at every unknown boundary (network, storage, env, CLI, workers — enumerated, none assumed); return unions (`T | ParseError[]` — failures as values, composable); keep parsers pure (input in, result out — no mutation, no I/O, trivially testable). Never `as`-cast parsed results (casts after parsing prove the parser lied — fix the parser, not the call site).

**Runnable example** — unknown discharged honestly (good vs bad, `tsc --strict`):

```typescript
// good — parse produces typed values or structured errors (unknown honestly discharged)
interface User { name: string; age: number }
type ParseError = { path: string; reason: string };
function parseUser(raw: unknown): User | ParseError[] {
  if (typeof raw !== "object" || raw === null) return [{ path: "", reason: "not-object" }];
  const r = raw as Record<string, unknown>; // single contained cast (evidence-gathering, not laundering)
  const errs: ParseError[] = [];
  if (typeof r["name"] !== "string") errs.push({ path: "name", reason: "want-string" });
  if (typeof r["age"] !== "number") errs.push({ path: "age", reason: "want-number" });
  return errs.length > 0 ? errs : { name: r["name"] as string, age: r["age"] as number }; // proven fields (narrowed per check)
}
const p1 = parseUser(JSON.parse('{"name":"a","age":1}'));
console.log(Array.isArray(p1) ? p1.map((e) => e.path).join(",") : p1.name.toUpperCase()); // A — parsed (zero casts downstream)
// bad — JSON.parse(raw) as User (assertion without evidence — malformed payloads crash downstream confidently)
// fix — parseUser (evidence-backed narrowing — contained casts inside, zero casts outside, errors as values)
```

```typescript
  const r = raw as Record<string, unknown>;
```

```typescript
}
function greet(u: User): string { return `hi ${u.name}`; } // typed consumer (trusts parse output — justifiably)
const p3 = parseUser({ name: "x", age: 2 });
if (!Array.isArray(p3)) console.log(greet(p3)); // hi x — un-asserted flow (parser proved, consumer trusts)
// bad — greet(p3 as User) after failed parse check skipped (cast after parsing proves the parser lied — fix parser, not call site)
// fix — narrow (Array.isArray check), never cast post-parse (honest parsers need no downstream assertions)
```

**Common confusion** — "parsers validate" — parsers *produce* (unknown→typed-or-errors); validators *check* (typed→verified, see 14/3.1) — produce vs check differ in input kind (unknown vs typed). "contained casts are still casts" — evidence-gathering casts (`raw as Record` *before* per-field narrowing) differ from laundering casts (`raw as User` *instead of* narrowing) — position relative to evidence decides honesty. "parse functions are verbose" — verbose *once* per boundary type (shared parsers); `as`-casts are terse *per lie* (paid per incident downstream).

**Performance note** — parsing costs per-field checks per boundary crossing (trivial vs I/O — network/storage dominate); shared parsers (one function per type) vs inline checks (duplicated per site) — centralize for consistency, not speed. Unvalidated `as`-casts cost incidents (unbounded) while saving microseconds (nothing).

**Mentor note** — feed one malformed payload through `as`-cast vs parse-function paths (confident crash vs error list — honesty demonstrated in one input). Exercise: convert three `as`-cast ingestions to parse functions and delete downstream defensive checks the casts required (honesty upstream deletes paranoia downstream). Review gate: `as` on parsed/ingested values fails review (parse, don't assert).

### 2) **Composing small parsers** (field → object → array, bottom-up, tested per unit)

**Definition** — parser combinators hand-rolled: field parsers (`parseString`, `parseNumber` — unknown→typed-or-error per primitive), object parsers (field map → object result, errors path-tagged), array parsers (element parser mapped with index tags). Bottom-up construction (primitives first, objects from fields, arrays from elements) with per-unit tests — each parser independently verifiable, composed without re-verification.

**What problem it solves / history** — monolithic validators (one 200-line `validateUser` — untestable per field, unreusable per shape, duplicated per endpoint) rotted on every schema change (three copies drifting: create/update/patch variants). Composed parsers share primitives (one `parseString` serving every shape) and compose shapes (object combinators over field parsers) — change once (the primitive), propagate everywhere (all compositions).

**Modern guidance** — as of TypeScript 5.9 era, build field parsers first (`string`, `number`, `literal-union`, `optional` wrappers — tested per primitive); compose objects via field maps (path-tagged errors per field); compose arrays via element parsers (index-tagged errors per element); share across shapes (one primitive library per codebase — never per-form validators). Adopt Zod/Valibot past complexity thresholds (see 3.2) — hand-rolled combinators teach the pattern libraries productize.

**Runnable example** — bottom-up composition, tested per unit (good vs bad, `tsc --strict`):

```typescript
// good — primitives composed into shapes (one library, unbounded compositions)
type PE = { path: string; reason: string };
function pStr(x: unknown, path: string): string | PE[] {
  return typeof x === "string" ? x : [{ path, reason: "want-string" }]; // primitive (tested alone — truth table per type)
}
function pNum(x: unknown, path: string): number | PE[] {
  return typeof x === "number" ? x : [{ path, reason: "want-number" }];
}
function pObj(raw: unknown): { name: string; age: number } | PE[] {
  if (typeof raw !== "object" || raw === null) return [{ path: "", reason: "not-object" }];
  const r = raw as Record<string, unknown>;
  const name = pStr(r["name"], "name"); // composed (field parsers reused — no re-derivation per shape)
  const age = pNum(r["age"], "age");
  const errs: PE[] = [
    ...(Array.isArray(name) ? name : []),
    ...(Array.isArray(age) ? age : []),
  ];
  return errs.length > 0 ? errs : { name: name as string, age: age as number }; // proven fields (narrowed post-collection)
}
const o = pObj({ name: "a", age: 1 });
console.log(Array.isArray(o) ? o.length : o.name.toUpperCase()); // A — composed parsing (primitives shared, shapes composed)
// bad — monolithic per-shape validators (200-line validateUser × create/update/patch variants — drift per copy)
// fix — combinator kit (primitives once, compositions per shape — change primitives once, propagate everywhere)
```

```typescript
// good — arrays parsed per element with index tags (locators, not just messages)
type PE = { path: string; reason: string }; // re-declared: fences compile standalone (minimal error shape)
function pStr(x: unknown, path: string): string | PE[] { // re-declared: fences compile standalone
  return typeof x === "string" ? x : [{ path, reason: "want-string" }];
}
function pArr<T>(xs: unknown, parse: (x: unknown, path: string) => T | PE[]): T[] | PE[] {
  if (!Array.isArray(xs)) return [{ path: "", reason: "want-array" }];
  const out: T[] = [];
  const errs: PE[] = [];
  xs.forEach((x, i) => {
    const r = parse(x, `[${i}]`); // index-tagged (locators per element — forms highlight precisely)
    if (Array.isArray(r)) errs.push(...r);
    else out.push(r);
  });
  return errs.length > 0 ? errs : out; // complete element errors (all violations, located per index)
}
const mixed: unknown[] = ["a", 1];
const parsed = pArr(mixed, (x, p) => pStr(x, p));
console.log(JSON.stringify(parsed)); // [{"path":"[1]","reason":"want-string"}] — error list with index locator (not partial results)
```

```typescript
// good — optional wrapper (present-or-absent without conflating missing and invalid)
type PE = { path: string; reason: string }; // re-declared: fences compile standalone (minimal error shape)
function pStr(x: unknown, path: string): string | PE[] { // re-declared: fences compile standalone
  return typeof x === "string" ? x : [{ path, reason: "want-string" }];
}
function pOpt<T>(x: unknown, path: string, parse: (x: unknown, path: string) => T | PE[]): T | undefined | PE[] {
  if (x === undefined) return undefined; // absent → undefined (omittable — distinct from invalid)
  return parse(x, path); // present → parsed (invalid values error — absence never masks invalidity)
}
console.log(pOpt(undefined, "nick", pStr) ?? "absent", pOpt(42, "nick", pStr)); // absent [...] — absent vs invalid distinguished (omittable ≠ malformed)
// bad — optional-as-nullable conflation (missing and malformed sharing one code path — PATCH semantics destroyed)
// fix — pOpt (absent→undefined, present→parsed-or-errors — three outcomes, honestly distinguished)
```

**Common confusion** — "combinators are library territory" — hand-rolled kits teach the *pattern* (compose/parse/narrow) that libraries productize (Zod/Valibot add ecosystems: error messages, async refinements, performance); small codebases run hand-rolled indefinitely (few shapes — kit overhead unjustified). "per-unit tests over-test" — primitive truth tables (string/number/edge per parser) catch exactly the coercion bugs (`typeof null === "object"`, `NaN` passing `typeof === "number"`) that integration tests miss. "composition duplicates Zod" — hand-rolled *precedes* Zod adoption (pattern understood → library evaluated on merits, not magic).

**Performance note** — composed parsing costs per-field checks once per boundary (trivial vs I/O); shared primitives (one function per type — JIT-optimized hot paths); error-list allocation per failure (exceptional-ish at boundaries — forms/APIs handle lists routinely).

**Mentor note** — build one parser bottom-up live (primitive → object → array, testing each unit before composing) — composition confidence in 20 minutes. Exercise: extract shared primitives from two monolithic validators (deduplication made visible per primitive). Review gate: monolithic per-shape validators fail review past 3 shapes (combinator kit by then).

### 3) **Narrowing after parse** (parsed values flow un-asserted, ever)

**Definition** — post-parse discipline: parsed `User` flows into `greet(user)` with zero casts (parser proved — consumer trusts); failed parses branch on the error list (forms render, APIs respond 422, CLIs exit 2 — never throw into generic handlers). `as` appearing downstream of a real parser proves *the parser lied* (incomplete narrowing) — fix the parser (narrower output type), never the call site (casts compound per consumer).

**What problem it solves / history** — parse-then-cast pipelines (`parseUser(raw) as User` — parser *plus* assertion, belt-and-suspenders that belted nothing: the cast overrode the parser's own error branch, malformed payloads flowing as `User` with green types) made parsers decorative (honest work inside, laundered outside). Narrow-only downstream (branch on the union — `Array.isArray` check, `ok` discriminant) keeps parsers load-bearing: unparseable input *cannot* reach typed consumers, structurally.

**Modern guidance** — as of TypeScript 5.9 era, narrow parse results (union checks, `ok` discriminants, `Array.isArray` on error lists — never `as`); keep parse output types *exact* (narrow enough that consumers need no casts — parser incompleteness surfaces as consumer-cast demand, fixed at the parser); treat downstream `as` as parser-bug reports (each cast a ticket against the parser, not a pattern to repeat).

**Runnable example** — narrow-only downstream (good vs bad, `tsc --strict`):

```typescript
// good — parse → narrow → flow (zero casts downstream — parser load-bearing end to end)
interface Account { id: string }
function parseAccount(raw: unknown): Account | string {
  if (typeof raw !== "object" || raw === null) return "not-object"; // error as string (simple failure channel here)
  const r = raw as Record<string, unknown>;
  if (typeof r["id"] !== "string") return "bad-id";
  return { id: r["id"] }; // proven Account (narrowed per field — consumers trust structurally)
}
const acc = parseAccount({ id: "a1" });
console.log(typeof acc === "string" ? acc : acc.id.toUpperCase()); // A1 — narrowed (no cast downstream, ever)
// bad — parseAccount(raw) as Account (cast overriding the error branch — malformed payloads flowing as Account confidently)
// fix — narrow (typeof-check on the union — unparseable input cannot reach typed consumers, structurally)
```

```typescript
// good — incomplete parsers surface as cast demand (fix the parser — demand is the diagnostic)
function parseLite(raw: unknown): { id: unknown } {
  return typeof raw === "object" && raw !== null ? (raw as { id: unknown }) : { id: undefined }; // hmm — id: unknown (incomplete narrowing — consumers WILL cast)
}
const lite = parseLite({});
console.log(typeof lite.id); // undefined — incomplete parser (cast demand downstream diagnoses parser gaps — fix here, not at call sites)
// fix — narrow fully in the parser (id: string proven — consumers cast nothing when parsers prove everything)
```

```typescript
// good — exhaustive handling of parse unions (both branches consumed — no silent drops)
interface Account { id: string } // re-declared: fences compile standalone (minimal shape)
function parseAccount(raw: unknown): Account | string {
  if (typeof raw !== "object" || raw === null) return "not-object";
  const r = raw as Record<string, unknown>;
  if (typeof r["id"] !== "string") return "bad-id";
  return { id: r["id"] };
}
function use(raw: unknown): string {
  const r = parseAccount(raw);
  if (typeof r === "string") return `err:${r}`; // error branch (handled — forms/APIs/CLIs consume per surface)
  return `ok:${r.id}`; // success branch (typed — flows un-asserted into typed consumers)
}
console.log(use({}), use({ id: "z" })); // err:bad-id ok:z — both branches consumed (exhaustive handling, never silent)
// bad — success-only handling (error branch unhandled — malformed input falling through to default-typed paths)
// fix — exhaustive parse-union handling (both branches, every call site — unhandled parse errors fail review)
```

**Common confusion** — "narrowing parsed results is verbose" — one branch per call site (vs one cast + unbounded downstream risk) — verbosity that proves vs terseness that lies. "exact parsers over-constrain" — exact output types *guide* consumers (fields proven present — no defensive `?.` chains on parsed data); loose parsers push checks downstream (defense distributed, coverage unprovable). "cast demand means complex data" — cast demand means *incomplete parsers* (narrow fully at the source — demand vanishes when parsers prove everything).

**Performance note** — narrowing branches cost one check per use (trivial); `as`-casts cost zero checks (and unbounded incident surface) — narrowing is the cheapest correctness available. Exact parsers cost per-field checks once per boundary (vs per-use defensive checks downstream — centralized beats distributed).

**Mentor note** — grep `as` downstream of parse calls (each a parser-bug ticket — fix parsers until grep is empty). Exercise: remove all post-parse casts in one module by narrowing parsers fully (cast count → zero — parser honesty proven by absence of downstream assertions). Review gate: `as` on parsed values fails review (narrow-only downstream, always).
