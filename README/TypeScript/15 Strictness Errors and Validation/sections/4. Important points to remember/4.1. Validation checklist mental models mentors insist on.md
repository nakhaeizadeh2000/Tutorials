## 4.1. Validation checklist — mental models mentors insist on

### 1) **Narrow with predicates, enforce with assertions** (recoverable vs invariant, decided per site)

**Definition** — the call-site decision rule restated as habit: recoverable paths (filtering, finding, defaulting, discriminating mixed inputs, parsing user data) narrow via predicates/unions (`is`/`has`, `Array.isArray`, `typeof` branches — caller continues differently); invariants (readiness, capability, configuration presence, unreachability) enforce via assertions (`asserts` throwing named errors — path halts). User input always recoverable; unreachability always asserted; borderlines documented inline per path.

**What problem it solves / history** — uniform checking style (everything predicates — invariants half-enforced; or everything assertions — user input crashing as 500s) mismatched half the call sites by construction. Per-site decisions match tool to category (see 1.2 promise 3's full treatment): predicates where recovery exists, assertions where halting is correct — each call site independently right, reviewably documented.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), ask per check: "on failure, does the caller *continue differently* (predicate) or *stop this path* (assertion)?" Document borderlines (startup-asserts vs request-degrades for the same datum, decided per path). Never assert-throw across trust boundaries to users (400s via parse/narrow, never 500s via assertion).

**Runnable example** — decisions per site (good vs bad, `tsc --strict`):

```typescript
// good — predicate recovery AND assertion enforcement composed correctly (tools matched to categories)
function isLong(s: string): s is string {
  return s.length > 3; // predicate (recoverable — caller filters, never throws)
}
function assertPort(p: number | undefined): asserts p is number {
  if (p === undefined) throw new Error("missing:PORT"); // assertion (invariant — halt, don't default a port)
}
console.log(["ab", "abcd"].filter(isLong).map((s) => s.toUpperCase()).join(",")); // ABCD — predicate path
function boot(port: number | undefined): string {
  assertPort(port); // halt path (no port → no server — correct category for assertion)
  return `:${port}`; // narrowed (invariant proven — no branch remaining)
}
console.log(boot(80)); // :80 — composed correctly (recoverable filtered, invariants asserted)
// bad — asserted user input (parse/narrow recoverable crashed as 500) or predicated invariants (half-enforced, drift per site)
// fix — per-site decisions (filter with predicates, enforce with assertions — tools matched to categories, documented)
```

```typescript
// good — borderline documented per path (same datum, different contexts, explicit decisions)
function getPort(env: Record<string, string | undefined>, required: boolean): number | undefined {
  const raw = env["PORT"];
  if (required && raw === undefined) throw new Error("missing:PORT (startup — cannot proceed)"); // documented borderline
  return raw === undefined ? undefined : Number(raw); // request path degrades (predicate-style recovery)
}
console.log(getPort({}, false) ?? "default", getPort({ PORT: "1" }, false)); // default 1 — borderline decided per path (documented inline)
// bad — one rule globally (always-assert crashes requests; always-predicate boots unconfigured — category error either way)
// fix — decide per PATH (startup halts, requests degrade — same check, different contexts, documented decisions)
```

```typescript
// good — never-sink always asserts (unreachability is invariant — no recoverable reading exists)
function assertNever(x: never): never { throw new Error(`unreachable:${String(x)}`); }
type Sig = "x" | "y";
function sig(s: Sig): number {
  switch (s) {
    case "x": return 1;
    case "y": return 2;
    default: return assertNever(s); // unreachability asserts (halt with proof — member addition breaks here)
  }
}
console.log(sig("x")); // 1 — sinked (placement: every behavior switch, unconditionally — see 07/3.2 mechanics)
// bad — default: return -1 (unreachable coded as a value — new members flow into -1 silently, callers trusting the type)
// fix — assertNever defaults (unreachability is invariant — assert, never default-value it away)
```

**Common confusion** — "predicates are safer (no throws)" — safe *where recovery exists*; half-enforcement where invariants need halting — safety follows category-match, not tool choice. "assertions are stronger" — strength misapplied crashes servable requests (500s for 400-situations) — throw by category (invariants), never by habit. "borderlines need team policy" — borderlines need *inline documentation* (startup-asserts vs request-degrades per call site) — policy can't enumerate paths, comments can.

**Performance note** — predicates cost branches per use (callers branch — expected); assertions cost branches per call + throws on violation (exceptional — fail-fast economics). Decision quality affects incidents, never steady-state speed.

**Mentor note** — classify ten existing checks live (recoverable→predicate? invariant→assert? borderline→document?) — decision drill transferring in under an hour. Exercise: find one asserted-recoverable (user-input throw → parse/narrow) and one predicated-invariant (half-enforced → fused assert) — both misdecisions corrected per rule. Review gate: user-input assertions fail review; unfused invariant checks fail review.

### 2) **Return expected failures, throw programmer errors** (Results for predictable, throws for bugs)

**Definition** — error-style discipline: *expected* failures (missing records, invalid input, timeouts, conflicts — valid programs encounter routinely) → `return` Results/optionals (typed, composable, handled per call site); *programmer* errors (invariant violations, unreachable branches, contract misuse — no valid program continues) → `throw` named errors (fail-fast, crash-reportable). Mixed discipline (throwing lookups, returning bugs) mismatches both halves.

**What problem it solves / history** — undisciplined error styles (throwing `NotFound` forcing try/catch per lookup; returning `null` for contract violations flowing corruption downstream) made callers guess per function (try/catch? null-check? both? — each guess wrong half the time). Discipline makes style *predictable from category*: expected→Result, bug→throw, documented per function — callers never guess.

**Modern guidance** — as of TypeScript 5.9 era, classify per function (expected-failure → Result/optional return; programmer-error → named throw; uncertain → Result (safer default — callers handle; throws surprise)); document per public signature (JSDoc states throw-vs-return — callers read, never guess); never throw across user trust boundaries (400s via Results; 500s reserved for bugs).

**Runnable example** — discipline per category (good vs bad, `tsc --strict`):

```typescript
// good — expected miss returns (routine absence — typed, handled, composable)
type Result<T, E> = { ok: true; value: T } | { ok: false; error: E }; // re-declared: fences compile standalone (minimal shape)
function lookup(ids: Map<string, string>, id: string): Result<string, { kind: "missing" }> {
  const v = ids.get(id);
  return v === undefined ? { ok: false, error: { kind: "missing" } } : { ok: true, value: v }; // expected (misses happen — returned)
}
const found = lookup(new Map([["a", "A"]]), "zzz");
console.log(found.ok ? found.value : "not-found"); // not-found — routine miss (handled per call site, never thrown)
// bad — throw new Error("missing") on lookup miss (expected absence as exception — callers try/catch per lookup or crash)
// fix — Result returns (misses compose; throws reserved for bugs — discipline per category, predictable per function)
```

```typescript
// good — programmer error throws (contract violated — no valid continuation exists)
function divide(a: number, b: number): number {
  if (b === 0) throw new Error("divide by zero (validate inputs before calling)"); // bug (caller violated contract — fail-fast named)
  return a / b;
}
console.log(divide(6, 3).toFixed(0)); // 2 — valid call (invalid calls throw loudly — never silently NaN)
// bad — return NaN on zero-divide (bug flowing as a value — NaN poisons downstream arithmetic silently for pages)
// fix — throw programmer errors (fail-fast named — bugs crash loudly at cause, never flow as values)
```

```typescript
// good — per-function documentation (callers read throw-vs-return — never guess)
function parsePort3(raw: string): number | undefined { // documented: undefined-means-invalid (lightweight Result — stated choice)
  const n = Number(raw);
  return Number.isNaN(n) ? undefined : n; // expected failure as undefined (callers handle — documented discipline)
}
console.log(parsePort3("x") ?? "bad-port", parsePort3("80")); // bad-port 80 — documented (JSDoc states — callers handle, never guess)
// bad — undocumented mixed surfaces (some functions throw misses, some return null — callers try/catch AND null-check defensively)
// fix — JSDoc per function (throws-X / returns-Y stated — discipline visible at every signature)
```

**Common confusion** — "Results everywhere (never throw)" — programmer errors *must* throw (returning bugs flows corruption — fail-fast exists because some paths lack valid continuations). "throws everywhere (simpler)" — expected failures as throws force try/catch per call (ceremony) or crash routine misses (incidents). "async changes the rule" — async *transports* identically (rejections ≈ throws; Result-resolutions ≈ returns — same categories, same discipline — see domain 18).

**Performance note** — throws cost stack capture per throw (exceptional paths only — reserved for bugs by design); Results cost one wrapper object per call (routine failures stay cheap). Discipline aligns cost with frequency automatically.

**Mentor note** — classify ten throwing/returning functions live (expected→Result? bug→throw? mixed→document?) — decision drill transferring in under an hour. Exercise: convert three throwing lookups to Results and three returning-bugs to throws (both misdirections corrected per rule). Review gate: throwing expected failures fails review; returning programmer errors fails review.

### 3) **Parse unknown once at every boundary** (unknown in, proven types out)

**Definition** — boundary discipline: every unknown-entry (network, storage, env, CLI, workers, third-party callbacks) parsed *once* at entry (unknown→typed production via 3.1–3.2 parsers/schemas); parsed values flow trusted downstream (no re-validation, no defensive narrowing on proven fields, no `as` casts — ever); downstream `as`/re-guards treated as parser-bug reports (narrow the parser until demand vanishes).

**What problem it solves / history** — unparsed boundaries (`as`-cast ingestion, implicit-`any` flows, unvalidated `process.env` reads) alongside re-validated pipelines (proven data re-checked per consumer) combined both failure modes (lies at entries, taxes downstream — worst of both). Parse-once inverts both: entries honest (parsed once — trust created), pipelines trusting (zero re-validation tax — trust spent freely).

**Modern guidance** — as of TypeScript 5.9 era, enumerate boundaries (inventory per 3.3 promise 2 — entry → parser → type per boundary); parse each with shared combinators (3.1's kit or 3.2's objects — no ad-hoc per-boundary validators); trust parsed values downstream unconditionally (re-validation is a parser-bug smell — fix parsers, not consumers). Nested trust domains parse per domain (service + module boundaries each — different trusts, composed explicitly).

**Runnable example** — boundaries parsed, pipelines trusting (good vs bad, `tsc --strict`):

```typescript
// good — env boundary parsed once (entry honest — downstream trusts unconditionally)
function parseEnv(raw: Record<string, string | undefined>): { port: number } {
  const p = raw["PORT"];
  if (p === undefined) return { port: 80 }; // absent → default (documented behavior)
  const n = Number(p);
  if (Number.isNaN(n)) throw new Error("bad-port (boundary parse — fail-fast with named error)");
  return { port: n }; // proven (consumers trust — zero downstream checks on port)
}
console.log(parseEnv({}).port.toFixed(0), parseEnv({ PORT: "1" }).port.toFixed(0)); // 80 1 — parsed once (trust created at entry)
// bad — Number(process.env["PORT"]) inline per file (unparsed env reads scattered — NaN flowing as port silently)
// fix — parseEnv (one entry, shared parser, derived type — inventory row complete, audited quarterly)
```

```typescript
// good — ticket parsed once (pipeline trusts — no re-validation tax downstream)
interface Ticket { id: string; qty: number } // re-declared: fences compile standalone (minimal shape)
function parseTicket(raw: unknown): Ticket | undefined {
  if (typeof raw !== "object" || raw === null) return undefined; // boundary parse (unknown discharged once, here)
  const r = raw as Record<string, unknown>;
  if (typeof r["id"] !== "string" || typeof r["qty"] !== "number") return undefined;
  return { id: r["id"], qty: r["qty"] }; // proven Ticket (consumers trust — zero downstream checks)
}
function total(t: Ticket): number { return t.qty * 10; } // trusts (no guards — parser proved, consumer flows)
const tk = parseTicket({ id: "t", qty: 2 });
console.log(tk === undefined ? "bad" : total(tk).toFixed(0)); // 20 — parse-once (boundary proves, pipeline trusts)
// bad — total() re-validating (proven data re-checked per consumer — distrust distributed, coverage unprovable)
// fix — parse-once (boundary proves once — downstream trusts unconditionally; re-validation is a parser-bug smell)
```

```typescript
// good — downstream as-casts treated as parser bugs (demand diagnoses gaps — fix parsers, not call sites)
function parseId(raw: unknown): string | undefined {
  return typeof raw === "string" ? raw : undefined; // narrow parser (proven output — consumers cast nothing)
}
const id = parseId("u1");
console.log(id?.toUpperCase() ?? "bad"); // U1 — narrowed use (no cast — parser proved everything needed)
// bad — id as string post-parse (cast demand = parser gap — call-site casts compound per consumer, gaps persist)
// fix — narrow parser output types until cast demand hits zero (demand-driven parser completeness — grep as-downstream-of-parse)
```

**Common confusion** — "trusting downstream is naive" — trusting *parsed* downstream is engineered (parser proved per field — trust earned once, spent freely); trusting *unparsed* is naive (the actual bug — inventory catches it). "nested domains duplicate work" — nested trusts parse per domain (service + module — each proves its own; shared sub-parsers compose without duplicating per-field logic). "re-validation is defense in depth" — defense-in-depth applies to *independent* mechanisms (validation + authz + rate-limiting); re-validation duplicates the *same* mechanism (parser checked twice — second check proves nothing new).

**Performance note** — parse-once costs per-field checks once per boundary (vs per-use re-validation — N× savings downstream); downstream trust costs zero checks (unconditional flow — fastest possible consumption); nested parses cost per domain (bounded, explicit, reviewable).

**Mentor note** — grep `as` downstream of parse calls (each a parser-bug ticket — fix parsers until grep is empty). Exercise: delete re-validation across one parsed pipeline (narrow-only downstream — trust restored per deletion). Review gate: `as`/re-guards on parsed values fail review (narrow parsers until demand vanishes); unparsed unknown flows fail review (inventory + parse at boundaries).

### 4) **No `as` downstream of real validation** (casts after parsing prove the parser lied)

**Definition** — the rule restated as prohibition: `as` appearing downstream of a real parser/validator proves *the parser* incomplete (output type insufficiently narrow for proven data) — fix the parser (narrower output type until cast demand vanishes), never the call site (casts compound per consumer while the gap persists for all). Cast-free downstream is the *metric* of parser completeness (grep-able, countable, trending to zero).

**What problem it solves / history** — parse-then-cast pipelines (`parseUser(raw) as User` — parser *plus* assertion, belt-and-suspenders belting nothing: the cast overrode the parser's own error branch, malformed payloads flowing as `User` with green types) made parsers decorative (honest work inside, laundered outside). Narrow-only downstream keeps parsers load-bearing: unparseable input *cannot* reach typed consumers, structurally (no cast to smuggle it through).

**Modern guidance** — as of TypeScript 5.9 era, narrow parse results (union checks, `ok` discriminants, `Array.isArray` on error lists — never `as`); keep parse output types *exact* (narrow enough that consumers need no casts — incompleteness surfaces as cast demand, fixed at the parser); treat each downstream `as` as a filed ticket against the parser (demand-driven completeness — grep as-downstream-of-parse quarterly).

**Runnable example** — narrow-only downstream (good vs bad, `tsc --strict`):

```typescript
// good — parse → narrow → flow (zero casts downstream — parser load-bearing end to end)
interface Account { id: string } // re-declared: fences compile standalone (minimal shape)
function parseAccount(raw: unknown): Account | string {
  if (typeof raw !== "object" || raw === null) return "not-object"; // error channel (typed failure — see 2.1 Results)
  const r = raw as Record<string, unknown>;
  if (typeof r["id"] !== "string") return "bad-id";
  return { id: r["id"] }; // proven Account (narrowed per field — consumers trust structurally)
}
const acc = parseAccount({ id: "a1" });
console.log(typeof acc === "string" ? acc : acc.id.toUpperCase()); // A1 — narrowed (no cast downstream, ever)
// bad — parseAccount(raw) as Account (cast overriding the error branch — malformed payloads flowing as Account confidently)
// fix — narrow (typeof-check on the union — unparseable input cannot reach typed consumers, structurally)
```

```typescript
// good — exact parsers eliminate cast demand (completeness proven by grep-emptiness)
function parseId(raw: unknown): string | undefined {
  return typeof raw === "string" ? raw : undefined; // narrow parser (proven output — consumers cast nothing)
}
const id2 = parseId("u1");
console.log(id2?.toUpperCase() ?? "bad"); // U1 — narrowed use (no cast — parser proved everything needed)
// bad — id as string post-parse (cast demand = parser gap — call-site casts compound per consumer, gaps persist)
// fix — narrow parser output types until cast demand hits zero (demand-driven parser completeness — grep as-downstream-of-parse)
```

```typescript
// good — cast-demand metric tracked (grep count trending to zero — parser completeness measured, not hoped)
function demand(): string { return "grep-as-downstream-of-parse (count → 0 — completeness proven by absence of demand)"; }
console.log(demand()); // metric stated (quarterly grep — demand falling means parsers completing; flat means gaps accepted)
// bad — cast demand ignored (parsers frozen incomplete — consumers casting forever, gaps permanent by neglect)
// fix — demand-driven completeness (each cast a parser ticket — fix parsers until grep is empty, then keep it empty)
```

**Common confusion** — "narrowing parsed results is verbose" — one branch per call site (vs one cast + unbounded downstream risk) — verbosity that proves vs terseness that lies. "exact parsers over-constrain" — exact output types *guide* consumers (fields proven present — no defensive `?.` chains on parsed data); loose parsers push checks downstream (defense distributed, coverage unprovable). "zero-cast is asymptotic" — zero-cast is *measurable* (grep count — trending to zero quarterly, held at zero by review).

**Performance note** — narrowing branches cost one check per use (trivial); `as`-casts cost zero checks (and unbounded incident surface) — narrowing is the cheapest correctness available. Exact parsers cost per-field checks once per boundary (vs per-use defensive checks downstream — centralized beats distributed).

**Mentor note** — grep `as` downstream of parse calls (each a parser-bug ticket — fix parsers until grep is empty). Exercise: remove all post-parse casts in one module by narrowing parsers fully (cast count → zero — parser honesty proven by absence of downstream assertions). Review gate: `as` on parsed values fails review (narrow-only downstream, always).
