## 4.1. Basic types checklist — mental models mentors insist on

### 1) **Primitives are unboxed** (`string` not `String` — wrappers allocate objects and break strict equality)

**Check** — can you explain why `const s: String = "hi"` compiles but is wrong? Structural leniency lets primitives pass where `String` is expected, but it signals " boxed object" to readers and linters (`@typescript-eslint/no-wrapper-object-types`). Never accept `String`/`Number`/`Boolean` in code review — always lowercase.

- Run: `grep -R ":\s*String\b|:\s*Number\b|:\s*Boolean\b" --include="*.ts"` should return zero hits on `main`.
- Hover test: `let x = "hi"` vs `new String("hi")` — `typeof x === "string"` vs `typeof new String("hi") === "object"`. Reviewers must articulate that `Map<string, T>` with `new String("a")` as key misses (`object !== primitive`).

### 2) **Nullability is explicit under strict** (`string` excludes `null`/`undefined`; optionality has three spellings with different assignability)

- **The three spellings** — `prop?: string` (may be missing), `prop: string | undefined` (must be present, may be `undefined`), `prop: string | null` (must be present, may be `null`). With `exactOptionalPropertyTypes:true`, `prop?: string` does *not* allow `{ prop: undefined }` — need `prop?: string | undefined`.
- **Check** — every function touching external data declares `| null | undefined` until narrowed (`if (x == null) return`). `strictNullChecks: true` (via `--strict`) is non-negotiable; `JSON.stringify` strips `undefined` properties but preserves `null` — model the wire type as sent.
- **Exercise** — write `type Config = { title?: string }` and ask what `JSON.stringify({ title: undefined })` produces (`{}`) vs `{ title: null }` (`{"title":null}`) — then decide which spelling the API actually promises.

### 3) **any leaks unknown contains** (default to `unknown` at boundaries; exhaust `never` for completeness)

- **any is debt** — `any` disables checking bidirectionally and infects callers (`any[]` → each element `any`). Budget it with a CI count (`grep -R ":\s*any\b" | wc -l` trending down) and contain it at the edge (`type LegacyHandler = (e: any) => void` wrapped to `(e: unknown) => void`).
- **unknown forces proof** — `unknown` is the safe top: `let u: unknown = 123; let s: string = u;` errors until `if (typeof u === "string")`. At every boundary (`JSON.parse`, `fetch`, `catch`), `unknown` enters and a guard/predicate/schema (`isUser`, `zod`) proves it. `as User` on the same line as `JSON.parse` is a red flag — ask "where's the proof?".
- **never is exhaustiveness** — `const _ex: never = remaining` in a `default` after switching over a literal union forces the checker to error when a new member is added. `never` has no inhabitant; `void` is "return ignored" — don't conflate them (see [2.3. never and void](<../2. The Special Types/2.3. never and void bottom vs deliberate nothing.md>)).

### 4) **Annotate contracts infer locals** (review signal: exported types are documented; local types are inferred)

- **Contracts** — exported functions, public properties, and boundary types have explicit annotations (`export function getUser(id: string): User | null`). Locals inside the body infer (`const raw = localStorage.getItem(...)` → `string | null` via lib types; no extra `: string | null` needed).
- **Why it matters for tooling** — explicit exported return types enable `isolatedDeclarations` parallel `.d.ts` generation (TS 5.5+) without re-analyzing call graphs — each file emits from signatures alone. Locals annotated redundantly create drift (implementation changes, annotation stale) and hide inference bugs.
- **Check** — remove an annotation: if no call-site error changes, the annotation was noise (keep the contract, delete the noise). `satisfies` preserves literal identity while checking shape (`{ method: "get" } satisfies Route` keeps `"get"` literal, vs `as Route` widens); `as const` freezes literals + `readonly` for derived unions (`typeof ids[number]`).

### 5) **Runnable checklist demo** (one file that exercises all four models)

```typescript
// primitives unboxed — wrapper check
function greet(name: string): void { console.log(`hi ${name}`); }
greet("Ada"); // string primitive — ok
// greet(new String("Ada")); // compiles but flagged — use string

// nullability explicit — three spellings
type InputA = { title?: string };                 // may be missing
type InputB = { title: string | undefined };     // always key, may be undefined
type InputC = { title: string | null };          // always key, may be null
const a: InputA = {}; // ok — missing allowed
const b: InputB = { title: undefined }; // ok — explicit undefined required
const c: InputC = { title: null }; // ok — null required
console.log(JSON.stringify(a)); // {}
console.log(JSON.stringify(b)); // {"title":undefined} → actually {} (undefined stripped)
console.log(JSON.stringify(c)); // {"title":null}

// any leaks vs unknown contains
function parseUnknown(json: string): unknown { return JSON.parse(json); }
const raw: unknown = parseUnknown('{"name":"Ada"}');
function isNamed(v: unknown): v is { name: string } {
  return typeof v === "object" && v !== null && "name" in v && typeof (v as any).name === "string";
}
if (isNamed(raw)) console.log(raw.name.toUpperCase()); // ADA

// never exhaustiveness + annotate contracts / infer locals
type Status = "idle" | "loading" | "done";
export function handleStatus(s: Status): string { // exported — annotate param + return
  switch (s) {
    case "idle": return "wait";
    case "loading": return "...";
    case "done": return "done";
    default: { const _ex: never = s; return _ex; }
  }
}

// literal preservation via satisfies + as const
type Route = { path: string; method: "get" | "post" };
const route = { path: "/users", method: "get" } satisfies Route; // method stays "get"
const ids = ["low", "med", "high"] as const;
type Id = typeof ids[number]; // "low"|"med"|"high"
const idGood: Id = "high"; // ok
console.log(route.method, idGood); // get high
```

### 6) **Mentor checklist**

Ask the student to hover each variable in the demo and explain the displayed type. Then add a new `Status` member `"retrying"` — does the `never` branch error exactly in `default`? Remove the `Status` annotation from `handleStatus` — does the caller lose exhaustiveness protection? Replace `unknown` with `any` in `parseUnknown` and attempt `raw.missing` — does the checker still force a proof? The answers confirm primitives, nullability, top/bottom, and annotation judgment.
