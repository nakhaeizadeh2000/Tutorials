## 1.2. bigint and symbol the ES-era primitives

### 1) **Bigint is its own lane**

`bigint` describes JavaScript arbitrary-precision integer values such as `123n`. It is distinct from `number`: arithmetic such as `1n + 1` is rejected by TypeScript and throws in JavaScript. Explicit conversion requires a policy. Converting a large bigint to number may lose precision; converting an already rounded number to bigint cannot recover the original digits.

Bigint is useful when an API requires integer arithmetic or representation beyond number's safe range. It can also be appropriate for smaller values when the surrounding API uses bigint. It does not represent fractions: `7n / 2n` produces `3n`, truncating toward zero. Monetary calculations still require explicit units and rounding rules.

Compiler target, library declarations and runtime support are separate. The [target reference](https://www.typescriptlang.org/tsconfig/target.html) explains emit choices and default libraries. Adding a library declaration does not implement an API or lower bigint operations for an older host. The example below deliberately targets ES2022 and runs on a declared Node version.

### 2) **Symbol and unique symbol**

A symbol is a primitive suitable for a property key or protocol identity. `Symbol("id")` creates a fresh identity; its description is a debugging label, not its key identity. `Symbol.for("id")` instead retrieves a shared registry entry. Choose the intended sharing policy.

The general `symbol` type accepts any symbol. A `unique symbol` type refers to a declaration-specific identity, with `typeof key` naming the particular type. A directly initialized const can infer that type, including a const initialized by `Symbol.for`. The [primary reference](https://www.typescriptlang.org/docs/handbook/symbols.html#unique-symbol) establishes declaration-specific identity. Static declaration identity and runtime registry identity answer different questions; the compiler does not treat all equal registry strings as one shared declaration.

Use TypeScript 7.0.2 and Node.js 20.20.2. Save the complete program as `exotic.mts` in an empty directory.

```typescript
// exotic.mts
const precise = BigInt("9007199254740993");
console.log((precise + 1n).toString(), (7n / 2n).toString());
console.log(BigInt(Number(precise)).toString());
function fromSafeNumber(value: number): bigint {
  if (!Number.isSafeInteger(value)) throw new Error("unsafe integer");
  return BigInt(value);
}
console.log(fromSafeNumber(42).toString());
let rejected = 0;
for (const value of [1.5, Infinity, Number.MAX_SAFE_INTEGER + 1]) {
  try { fromSafeNumber(value); } catch { rejected++; }
}
if (rejected !== 3) throw new Error("conversion contract failed");
console.log("rejected", rejected);
let jsonFailed = false;
try { JSON.stringify({ id: precise }); }
catch (error) { jsonFailed = error instanceof TypeError; }
if (!jsonFailed) throw new Error("expected bigint JSON failure");
console.log("JSON TypeError", jsonFailed);
console.log(JSON.stringify({ id: precise.toString() }));

const key = Symbol("id");
const another = Symbol("id");
type Box = { [key]: string; name: string };
const box: Box = { [key]: "metadata", name: "Ada" };
const sameKey: typeof key = key;
const general: symbol = key;
console.log(box[sameKey], typeof general, Object.is(key, another));
console.log(JSON.stringify(box), Object.getOwnPropertySymbols(box).length);
const first = Symbol.for("lesson-id");
const second = Symbol.for("lesson-id");
console.log("registry", Object.is(first, second));
```

```sh
tsc --strict --target ES2022 --module NodeNext --noEmitOnError --outDir dist exotic.mts
node dist/exotic.mjs
```

Output:

```text
9007199254740994 3
9007199254740992
42
rejected 3
JSON TypeError true
{"id":"9007199254740993"}
metadata symbol false
{"name":"Ada"} 1
registry true
```

The lost digit appears only after converting to number. The checked conversion rejects unsafe or non-integer numbers before creating a bigint. Plain JSON serialization throws for this bigint input, following [SerializeJSONProperty](https://tc39.es/ecma262/multipage/structured-data.html#sec-serializejsonproperty). The explicit wire object uses a decimal string; a receiver must interpret and check that contract rather than assume JSON recreates a bigint.

The symbol key is skipped by JSON serialization but is discoverable through reflection. It is not a secret. A second fresh symbol with the same description is different, while the two registry calls share a runtime value. The readonly or phantom brands used elsewhere are separate type-design choices; symbols themselves can be ordinary runtime values.

### 3) **API trade-offs**

Append one independent negative probe at a time, compile, then restore the original:

```typescript
const mixed = 1n + 1;
```

```typescript
const wrongNumber: number = 1n;
```

```typescript
const wrongKey: typeof key = another;
```

These report TS2365, TS2322 and TS2322 respectively. This further probe reports TS7053 because a general symbol is not evidence for the box's particular declared key:

```typescript
console.log(box[general]);
```

Compile the original program with `--target ES2015 --lib ES2022,DOM` instead of `--target ES2022`. Bigint literals still report TS2737: supplying newer API declarations does not enable downlevel bigint syntax. Keep the successful command for runtime execution.

An API may need bigint, a decimal string or a bounded number. Choose from precision, arithmetic and serialization needs. A symbol may suit an internal protocol key, while an external identifier generally needs a serializable representation. Neither type is universally preferable, rare by rule or a substitute for a validated domain contract.

### 4) **Common confusion**

Different numeric types can participate in some comparisons even though mixed arithmetic is forbidden. The statement “bigint never interacts with number” is too broad. Equally, a conversion that compiles is not proof of preserved precision.

A unique symbol type can be widened to `symbol`, losing its particular static identity. Its runtime value remains the same. A type-only brand declaration need not allocate a runtime symbol, but the actual `Symbol` calls in this program do execute.

### 5) **Performance note**

Bigint arithmetic processes integer values whose sizes can grow; conversions and serialization also execute. Actual cost depends on operand sizes, operations and runtime implementation. This lesson measures no slowdown factor or allocation threshold. Unique-symbol type information erases while runtime symbol creation and reflection remain. Preserve required precision and identity before measuring a real bottleneck.

### 6) **Mentor note**

Ask where the digit was lost and why applying `BigInt` afterward cannot repair it. Then ask why JSON omits metadata while reflection finds it. A sound answer separates precision, serialization and visibility. For the registry calls, explain why runtime sharing and declaration-specific static types are distinct; use the same exported key declaration when callers need one shared typed protocol identity.
