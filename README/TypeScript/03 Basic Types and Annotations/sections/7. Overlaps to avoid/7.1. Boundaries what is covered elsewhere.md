## 7.1. Boundaries — what is covered elsewhere

### 1) **JavaScript language mechanics** (values, wrappers, coercion, and runtime types)

- **Not in this domain** — `typeof` runtime quirks (`typeof null === "object"`, `NaN !== NaN`, `0 === -0`), prototype lookups, boxed wrapper runtime behavior, and `Symbol.for` registry mechanics are owned by the [JavaScript track](<../../../../JavaScript/README.md>) — especially [03 Values, Types, and Coercion](<../../../../JavaScript/03 Values Types and Coercion/README.md>), [12 Numbers Dates Math and Temporal](<../../../../JavaScript/12 Numbers Dates Math and Temporal/README.md>), and [17 Metaprogramming Symbols Proxy Reflect](<../../../../JavaScript/17 Metaprogramming Symbols Proxy Reflect/README.md>). This domain adds *static* primitives (`string` vs `String`, `bigint` vs `number`) and assumes you already know the runtime `typeof` table — it never re-teaches it.

---

### 2) **Objects, interfaces, and type aliases** (shape beyond primitives)

- **Where it lives** — primitive literals are the leaves; composite shapes (`{ name: string }`, `interface User`, `type Aliased = {}`) with modifiers (`readonly`, `?`, index signatures, declaration merging) are owned by [04 Objects, Interfaces and Type Aliases](../04\ Objects\ Interfaces\ and\ Type\ Aliases/README.md) (textual forward until that domain lands). That domain owns `object` vs `Object` vs `{}`, excess-property vs structural assignability at object level (see also [02/1.2. Excess property checks](<../../../02 The Type System Core/sections/1. Structural typing/1.2. Excess property checks and freshness.md>)), and `interface` vs `type` style. This domain treats objects only as the *container* for primitive properties (e.g., `{ name: "Ada" } as const` widening rule) — not as a shape system.

---

### 3) **Unions, intersections, narrowing, and type guards** (control-flow analysis — how broad becomes narrow)

- **Where it lives** — discriminated unions, `in`/`instanceof`/`typeof` narrowing, exhaustive `never` switches, and type predicates (`x is T`) are owned by [07 Unions, Intersections and Narrowing](../07\ Unions\ Intersections\ and\ Narrowing/README.md) (textual forward). This domain introduced `unknown` narrowing (see [2.2. unknown](<../2. The Special Types/2.2. unknown the type-safe top type.md>)) only as the *minimal proof* to leave `unknown`; the full narrowing catalog and closed-world vs open-world union design belongs to 07. Likewise string literal unions (`"a" | "b"`) were introduced here as the erasable enum shape, but their composition into template literals, conditional filtering, and mapped unions belongs to 07/08/09.

---

### 4) **Enums and their non-erasable cost** (why `enum` is mostly legacy)

- **Where it lives** — the emission and pitfalls of `enum` (`enum E { A, B }` → runtime object, namespace-like scoping, `const enum` inlining, and why it fails `--erasableSyntaxOnly`) are centered in [01 Fundamentals 3.3 Choosing erasable syntax](<../../../01 Fundamentals and Mental Model/sections/3. Running TypeScript today/3.3. Choosing erasable syntax the zero-cost interop rule.md>) with the domain-level verdict: *prefer literal unions* (`"a" | "b"`) for erasable, exhaust-checkable enums. The remaining `enum` details (numeric vs string enums, computed members, declaration emit) are owned by [11 Enums and Literal Types](../11\ Enums\ and\ Literal\ Types/README.md) (textual forward). This domain referenced `enum` only to contrast literal unions as the modern, erasable choice — it does not teach `enum` completeness.

---

### 5) **Generics, utility types, and type transformations** (where literals compose into programs)

- **Where it lives** — generic param creation (`<T>`), variance annotations (`in`/`out`), conditional types (`T extends U ? never : T`), `infer` on string literals, `keyof`/`typeof` synthesis, mapped types, and template literal types (`` `on${Capitalize<"click">}` `` → `"onClick"`) are owned by [08 Generics Deep Dive](../08\ Generics\ Deep\ Dive/README.md) and [09 Utility Types and Type Transformations](../09\ Utility\ Types\ and\ Type\ Transformations/README.md) (textual forwards). This domain proved `as const` preserves literals for `typeof ids[number]` → `"a" | "b"` but leaves `Exclude`, `Extract`, `ReturnType`, `Pick`, recursive `DeepPartial`, and `--isolatedDeclarations` parallel emit to 08/09.

---

### 6) **Configuration and variance flags deep dive** (why `strict` matters more than it seems)

- **Where it lives** — the full `tsconfig` flag matrix (`strict`, `strictNullChecks`, `noImplicitAny`, `useUnknownInCatchVariables`, `exactOptionalPropertyTypes`, `isolatedDeclarations`, `erasableSyntaxOnly`, and the upcoming TS 6.0/7.0 defaults) is owned by [13 Configuration and Compiler Options](../13\ Configuration\ and\ Compiler\ Options/README.md) (textual forward). This domain used flags only to *explain primitives* (`strictNullChecks` for nullish, `noImplicitAny` for empty arrays, `useUnknownInCatchVariables` for `catch unknown`, `erasableSyntaxOnly` for `enum` vs literal union). It does not teach config composition (`extends`, project references) — see [01/3.1. The compilation pipeline](<../../../01 Fundamentals and Mental Model/sections/3. Running TypeScript today/3.1. The compilation pipeline tsc emit declarations and source maps.md>) for pipeline context and 13 for the flag-by-flag deep dive.

---

If a review comment argues about `enum` completeness, literal union exhaustiveness belongs here — but the *enum runtime object* argument belongs to 01/11. If a review debates `type` vs `interface` for an object that holds primitives, that design trade-off belongs to 04 — not here.
