## 7.1. Boundaries — what is covered elsewhere

### 1) **JavaScript language mechanics**

JavaScript owns the runtime values, wrapper behavior, coercion and key identity that TypeScript describes. The basic-type lessons retain small runtime contrasts where they explain a static mistake, such as a broad String annotation containing a primitive. Follow [JavaScript values](<../../../../JavaScript/03 Values Types and Coercion/README.md>) for the complete model, [numbers](<../../../../JavaScript/12 Numbers Dates Math and Temporal/README.md>) for numeric operations and [metaprogramming](<../../../../JavaScript/17 Metaprogramming Symbols Proxy Reflect/README.md>) for symbol protocols and reflection.

### 2) **Objects, interfaces and aliases**

[Objects](<../../../04 Objects Interfaces and Type Aliases/README.md>) owns composite shapes, member modifiers, index signatures, composition and declaration merging. This domain introduces primitive members and the distinction between an omitted property and a nullish value because those affect the basic contract. It does not duplicate full shape design. The [core model](<../../../02 The Type System Core/README.md>) supplies required-member comparison and creation-site freshness; the object domain applies those rules to composite APIs.

### 3) **Unions, narrowing and guards**

The unknown and never lessons introduce just enough checking evidence and impossible-case reasoning to use the basic types. [Unions and narrowing](<../../../07 Unions Intersections and Narrowing/README.md>) owns full control-flow design, discriminants, predicate contracts and exhaustive variant handling. A literal union introduced here is a finite static vocabulary, not a runtime enumeration or external-input validator.

### 4) **Enums and runtime representation**

[Enums and Literal Types](<../../../11 Enums and Literal Types/README.md>) owns numeric/string enums, members, runtime objects, const-enum choices and compatibility trade-offs. [Syntax choices](<../../../01 Fundamentals and Mental Model/sections/3. Running TypeScript today/3.3. Choosing erasable syntax the zero-cost interop rule.md>) owns the bounded stripping and declaration-tool restrictions. A literal union can suit a type-only vocabulary; changing an existing enum API may also change runtime behavior. This domain supplies the literal building blocks without declaring every enum obsolete or promising a mechanical replacement.

### 5) **Queries, generics and transformations**

[Primitive type queries](<../../../02 The Type System Core/sections/2. The type vs value separation/2.3. Type queries typeof keyof and indexed access.md>) owns typeof, keyof and indexed access. [Object-query applications](<../../../04 Objects Interfaces and Type Aliases/sections/2. Composition and Declaration Merging/2.3. Type queries on objects keyof indexed access and typeof capture.md>) distinguishes static contracts from enumeration and runtime membership. The tuple-derived vocabulary here is a small application of those operators.

[Generics](<../../../08 Generics Deep Dive/README.md>) owns type-parameter relationships and inference. [Type transformations](<../../../09 Utility Types and Type Transformations/README.md>) owns mapped/conditional composition, template literal transformations and utilities. Keep a short local explanation when a basic lesson needs a type expression, then follow the precise owner for its full mechanism.

### 6) **Configuration and current setup**

[Configuration](<../../../13 Configuration and Compiler Options/README.md>) owns flag composition, project boundaries and declaration constraints. This domain explicitly selects flags to observe a particular primitive or inference behavior. Strict null checking affects nullish uses; exact optional checking affects certain property writes; noImplicitAny reports particular missing inference; none installs a runtime validator.

The [compilation pipeline](<../../../01 Fundamentals and Mental Model/sections/3. Running TypeScript today/3.1. The compilation pipeline tsc emit declarations and source maps.md>) owns artifacts and source maps. Follow the [current 7.0 route](<../../../25 Update TypeScript 7.0/sections/6. Overlaps and Update Route/6.1. Overlaps and the current learning route.md>) for the versioned native migration after the appropriate prerequisites. The current checked compiler baseline is 7.0.2; example-specific runtime and command requirements remain explicit.

### 7) **Common confusion**

A runtime operation and its static signature can require different owners. JavaScript explains why a wrapper object is a different Map key; this domain explains why a string parameter rejects a String wrapper. Likewise, the role of never is introduced here, but designing a complete discriminated-union switch belongs in the narrowing domain. Compiler flags such as isolatedDeclarations affect tooling constraints; they are not utility types simply because both involve declarations.

### 8) **Performance note**

This navigation leaf introduces no executable operation, so its ownership boundaries have no direct runtime performance effect. Primitive annotations erase, while an actual wrapper constructor, parser or collection operation has its runtime cost. Use the operation's owner and a suitable measurement when cost matters. Following a documentation link does not remove work from the compiler or prove a faster build; no such measurement was performed here.

### 9) **Mentor note**

Give the learner three review comments: a wrapper Map key misses, a callback needs exhaustive variant handling, and a project option changes declaration output. Ask for the owner and the next useful observation. A sound answer routes runtime key equality to JavaScript collections, full union design to 07 and compiler-option mechanics to 13, while keeping the basic signature or never explanation here. Require a reason for the route rather than memorized domain numbers.
