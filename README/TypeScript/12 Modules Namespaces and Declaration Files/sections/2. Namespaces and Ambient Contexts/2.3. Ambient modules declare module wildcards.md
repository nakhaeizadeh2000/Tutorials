## 2.3. Ambient modules — `declare module` wildcards

### 1) **`declare module "name"` for untyped packages** (minimal honest shims)

**Definition** — `declare module "leftpad" { const pad: (s: string, n: number) => string; export = pad; }` (in a global `.d.ts`) types an untyped package: imports check against the shim until upstream ships real types. Minimal shims type *used* members precisely and leave the rest undeclared (erroring on use — honest about coverage); `any`-shaped shims (`const x: any`) type nothing and hide everything.

**What problem it solves / history** — untyped dependencies forced `// @ts-ignore` per import or `any`-typed wrappers that laundered every call (argument counts, return types, option shapes all unchecked — the dependency's API evolution invisible to consumers). Minimal shims restore checking per *used* member: declared members verify, undeclared members error (prompting shim extension, not silent `any`).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), shim only what you consume (2–3 members, precisely typed); mark the shim with the upstream issue (`// TODO: remove when pkg ships types (issue #…)`); delete the shim the release upstream types land (real `.d.ts` beats ambient shim in resolution order — next promise). Never `export = any` shims for packages with knowable APIs (laziness laundered as pragmatism).

**Runnable example** — shimmed precisely, deleted on arrival (multi-file sets):

```typescript
// file: shim.d.ts
declare module "pad-mini" {
  function pad(s: string, n: number, ch?: string): string;
  export = pad; // minimal honest surface (used members only, precisely typed)
}
// file: app31.ts
/// <reference path="./shim.d.ts" /> // global shim enters via include/reference (tsconfig includes .d.ts automatically)
import pad = require("pad-mini"); // resolves to the ambient shim (no runtime: type demo)
console.log("shim-declared"); // shim presence proven by checking (runtime ships the package)
// pad(42); // error TS2345 — shim checks arguments (any-shim would stay silent)
```

```typescript
// file: shim2.d.ts
declare module "fmt-mini" {
  export function eur(n: number): string;
  export function usd(n: number): string; // consumed members only (rest undeclared → errors guide extension)
}
// file: app32.ts
/// <reference path="./shim2.d.ts" />
import { eur } from "fmt-mini";
console.log(eur(9)); // checked call (shim types what we use, nothing more)
// import { gbp } from "fmt-mini"; // error TS2305 — undeclared (extend the shim deliberately, don't widen it)
// fix — add gbp to the shim with its real signature (coverage grows deliberately, never via any)
```

```typescript
// file: shim3.d.ts
declare module "legacy-blob" {
  const anything: any; // opaque-package escape (documented last resort: // TODO type properly)
  export = anything;
}
// file: app33.ts
/// <reference path="./shim3.d.ts" />
import blob = require("legacy-blob");
console.log("opaque-shim"); // compiles everything (honest ONLY via the TODO + narrow usage)
// bad — opaque shims for knowable APIs (two-member packages typed any "temporarily", permanently)
// fix — minimal precise shims (promises 1–2); opaque only for genuinely opaque binaries
```

**Common confusion** — "shims validate the package" — shims *declare* (trust without evidence — wrong signatures compile callers into runtime errors); validation needs tests exercising the boundary (shim + contract test, not shim alone). "ambient shims override real types" — resolution prefers real `.d.ts` (shim silently ignored once upstream types land — delete it then, don't maintain both). "`any`-shims are pragmatic" — pragmatic *once* (unblocking today with a TODO + issue link); permanent `any`-shims are laundering with documentation.

**Performance note** — zero emit (declarations erase); ambient shims add one resolution candidate per import (negligible); real types arriving delete the shim (resolution simplifies). No runtime profile — shims are purely a checking asset.

**Mentor note** — `npm ls` untyped deps quarterly, shim-or-replace each (minimal shim + TODO + upstream issue, or typed alternative) — the untyped-dependency backlog made countable. Rule: new `any`-shaped shims fail review; precise minimal shims pass with TODO + issue link.

### 2) **Wildcard declarations** (asset imports typed once per extension)

**Definition** — `declare module "*.png" { const src: string; export default src; }` types *every* matching import path (bundler asset loaders: images, styles, workers, wasm): the wildcard's declared shape applies per extension, so `import logo from "./logo.png"` checks without per-file declarations. One declaration per loader contract — the bundler's runtime behavior transcribed once into types.

**What problem it solves / history** — asset imports (`import "./app.css"`, `import logo from "./logo.png"`) errored TS2307 (untyped paths) in every new bundler project — fixed per-project by copying framework boilerplate (`vite/client`, `next-env`) nobody understood, then breaking when loaders changed (CSS modules' `{ [class]: string }` shape vs plain CSS's side-effect-only shape confused freely). Explicit wildcards state each loader's contract (`*.css` side-effect-only vs `*.module.css` class-map) — loader changes update one declaration, visibly.

**Modern guidance** — as of TypeScript 5.9 era, declare one wildcard per loader contract in the project (`*.png` → default string; `*.module.css` → class map; `*.svg` → component-or-URL per bundler); prefer framework-provided ambient packages (`vite/client` types) over hand-rolled wildcards where they exist (maintained with the bundler); review wildcard edits like loader-config edits (same blast radius — every matching import re-checks).

**Runnable example** — loader contracts typed once (multi-file sets):

```typescript
// file: assets.d.ts
declare module "*.png" {
  const src: string;
  export default src; // file-loader contract: default export is the URL string
}
declare module "*.module.css" {
  const classes: Record<string, string>;
  export default classes; // css-modules contract: default export maps class names
}
// file: app34.ts
/// <reference path="./assets.d.ts" />
console.log("wildcards-declared"); // contracts typed (bundler resolves values at build; types describe shapes)
// import logo from "./logo.png"; // checks as string (needs bundler + file present — types describe, build provides)
```

```typescript
// file: side35.d.ts
declare module "*.css"; // side-effect-only contract (no exports — bare import for global styles)
// file: app35.ts
/// <reference path="./side35.d.ts" />
console.log("css-side-effect-typed"); // import "./app.css" checks (no bindings to misuse)
// bad — declare module "*.css" { const x: any; export default x; } (bindings that don't exist — imports invent values)
// fix — bare declare (no exports) for side-effect loaders; shaped declarations for value loaders
```

```typescript
// file: worker36.d.ts
declare module "*?worker" {
  const WorkerFactory: new () => Worker;
  export default WorkerFactory; // bundler worker-query contract (Vite ?worker suffix)
}
// file: app36.ts
/// <reference path="./worker36.d.ts" />
console.log("worker-query-typed"); // suffix imports check (bundler provides the constructor at build)
// bad — untyped ?worker imports (TS2307 on every worker file — toil per file instead of one declaration)
```

**Common confusion** — "wildcards validate loader output" — describe (wrong shapes compile importers into runtime mismatches — e.g. declaring `string` where the loader emits `{ default }` objects); validate with build smoke tests (import each asset kind once in CI). "framework ambient packages replace understanding" — `vite/client` *is* wildcards maintained upstream (prefer it, but know it *is* this pattern — debugging loader-type issues needs the pattern, not just the package). "one wildcard covers all assets" — per-*contract* declarations (`*.css` ≠ `*.module.css` ≠ `*.png` — different shapes, different declarations; merging them types lies).

**Performance note** — zero emit; wildcard resolution adds one pattern-match per matching import (negligible); wrong-shaped wildcards cost runtime mismatches (unbounded) — precision here is pure incident prevention.

**Mentor note** — break one wildcard shape deliberately (default `string` → `{ src: string }`) and count the erroring imports (each a caller depending on the contract) — loader contracts made visible via breakage. Rule: new asset kinds get wildcard declarations in the same PR as the loader config (config + types land together, always).

### 3) **Ambient module resolution order** (real types beat shims — delete on arrival)

**Definition** — for `import x from "pkg"`, the checker tries in order: real declarations (`node_modules/pkg/*.d.ts`, `@types/pkg`, `paths`-mapped sources) *before* ambient `declare module "pkg"` shims — first hit wins, silently. When upstream ships types, the shim becomes dead text (still parsed, never consulted) — harmless until it *contradicts* the real types (stale signatures misleading readers while checking against the truth).

**What problem it solves / history** — post-arrival shims (kept "just in case") contradicted real types in the worst way: readers trusted the visible shim (wrong signatures), the checker used invisible real types (right ones) — code written to the shim failed against reality with errors pointing nowhere near the stale declaration. Deleting on arrival (verified by the errors that *don't* appear after deletion) keeps one source of type truth per package, permanently.

**Modern guidance** — as of TypeScript 5.9 era, treat upstream-types releases as shim-deletion events (bump dep → delete shim → `tsc` green means clean; new errors mean the shim was *masking* drift — fix call sites, don't restore the shim); track shims in one directory (`types/shims/`, one file per package with TODO + issue) so arrival audits are `ls`, not archaeology. Never maintain shim and real types in parallel (two truths diverge by definition).

**Runnable example** — arrival deletes the shim (multi-file sets):

```typescript
// file: shim37.d.ts
declare module "calc-mini" {
  export function add(a: number, b: number): number; // shim truth (until upstream ships types)
}
// file: app37.ts
/// <reference path="./shim37.d.ts" />
import { add } from "calc-mini";
console.log(add(2, 3).toFixed(0)); // 5 — checked against the shim (only truth available)
// upstream ships types → DELETE shim37.d.ts → tsc green means real types agree; errors mean drift to fix
```

```typescript
// file: types38/check.ts
// Resolution order demo (no runtime — compile-time rule):
// 1. ./node_modules/pkg/*.d.ts (bundled types — highest priority)
// 2. ./node_modules/@types/pkg (DefinitelyTyped fallback)
// 3. tsconfig paths mappings (monorepo source redirects)
// 4. ambient declare module "pkg" shims (last resort — consulted only if 1–3 miss)
export const order = ["bundled", "at-types", "paths", "ambient-shim"] as const;
console.log(order.join(" > ")); // bundled > at-types > paths > ambient-shim — priority made explicit
// bad — editing the shim when real types exist (changes nothing — shim unconsumed; edit the real source or reconfigure)
```

```typescript
// file: shim39.d.ts
declare module "old-lib" {
  export function run(): void; // stale shim (upstream v2 changed run(): to run(opts))
}
// file: app39.ts
/// <reference path="./shim39.d.ts" />
import { run } from "old-lib";
run(); // checks against STALE shim (real v2 types, if present, are ignored?? NO — real beats shim: this errors if real types landed)
// fix — delete shim39.d.ts on v2 upgrade: real types surface the signature change as errors at call sites (the honest signal)
console.log("shim-deleted-on-arrival"); // deletion + green tsc = clean handoff
```

**Common confusion** — "keeping shims is harmless backup" — harmless only while agreeing (then redundant); harmful once drifting (readers trust visible-shim, checker uses invisible-real — worst-of-both debugging). "deletion risks breakage" — deletion *reveals* (errors = drift the shim masked — fix sites, productively); breakage already existed (masked). "ambient order is configurable" — fixed priority (bundled → @types → paths → shim) — configurable *inputs* (which exist), never the *order*.

**Performance note** — fewer resolution candidates per import (deleted shims skip a lookup tier) — trivially faster resolution; the real dividend is single-truth debugging (one declaration to read per package, always the consulted one).

**Mentor note** — `npm outdated` + `ls types/shims/` quarterly (arrived upstream types = deletion PRs) — the shim backlog made countable. Exercise: delete one long-kept shim and triage the resulting errors (masked drift surfacing = the shim's hidden cost, receipt included). Rule: shim files carry TODO + upstream issue; arrivals trigger deletions, never parallel maintenance.
