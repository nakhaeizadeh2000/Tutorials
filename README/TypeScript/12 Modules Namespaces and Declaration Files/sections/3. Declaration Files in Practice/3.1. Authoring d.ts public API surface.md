## 3.1. Authoring `.d.ts` — public API surface

### 1) **What belongs in `.d.ts`** (public types + signatures, nothing else)

**Definition** — a declaration file describes a module's *public contract*: exported types, function signatures, class shapes, const values' types — with all implementations stripped. Private helpers, test-only shapes, internal overloads, and comments about *how* (vs *what*) do not belong: every extra declaration is API surface consumers can depend on (and you must then support forever).

**What problem it solves / history** — hand-maintained `.d.ts` files drifted two ways: *over-inclusion* (internal helpers exported "just in case" — consumers depended on them, blocking refactors) and *under-inclusion* (new exports missing — consumers `any`-patched around the gap). Generated declarations (`declaration: true` from source) eliminate both: the compiler derives exactly what the source exports, nothing more, on every build.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), generate declarations from source (`declaration: true` + `declarationMap` for go-to-definition); hand-write `.d.ts` only for untyped foreign code (shims per 2.3) and ambient globals (per 2.2). Review generated `.d.ts` diffs in PRs (new public exports appear as added lines — the API-evolution audit, free with generation).

**Runnable example** — surface derived, not declared (multi-file sets):

```typescript
// file: src.ts
export interface User { id: string }
export function get(id: string): User { return { id }; }
function helper(x: number): number { return x * 2; } // private (never leaves the module)
export const helper2 = helper(21);
console.log(get("u").id, helper2.toFixed(0)); // u 42
// generated src.d.ts contains: User, get, helper2 (NOT helper) — surface derived from source
// file: con40.ts
import { get } from "./src.js";
console.log(get("a").id.toUpperCase()); // A — public contract consumed (helper unreachable by construction)
```

```typescript
// file: shapes41.ts
export interface Circle { r: number }
export interface Square { s: number }
export type Shape = Circle | Square; // public union (consumers narrow over it)
export function area(s: Shape): number { return "r" in s ? Math.PI * s.r ** 2 : s.s ** 2; }
// file: con41.ts
import { area, type Shape } from "./shapes41.js";
const sh: Shape = { s: 2 };
console.log(area(sh).toFixed(0)); // 4 — union + narrowing cross the boundary intact
// bad — exporting internal Tag types "for consumers' convenience" (surface creep: convenience imports become support contracts)
```

```typescript
// file: versioned42.ts
export const VERSION = "2.1.0"; // public const (literal type preserved in declarations)
export function greet(n: string): string { return `hi ${n}`; }
// file: con42.ts
import { VERSION, greet } from "./versioned42.js";
console.log(VERSION, greet("ada").toUpperCase()); // 2.1.0 HI ADA — consts + functions cross cleanly
// bad — export const DEBUG = globalThis.__D (internal wiring in the public surface — consumers read it, support owns it)
```

**Common confusion** — "hand-written `.d.ts` is more precise" — hand-written is more *editable* (drift in both directions); generated is more *accurate* (derived from the checked source on every build) — precision follows derivation, not authorship. "private helpers leak through declarations anyway" — non-exported declarations never appear in generated `.d.ts` (module privacy enforced by generation); only `export`ed names cross — the export list *is* the surface decision. "declarationMap is optional polish" — without it, consumer go-to-definition lands in `.d.ts` (signatures without bodies — debugging blind); with it, navigation reaches source (when sources ship or sourcemaps map) — developer-experience infrastructure, not polish.

**Performance note** — generated declarations speed *consumer* checks (`.d.ts` skips implementation bodies — checker reads signatures only); `declarationMap` adds map files (bytes, debug-time only). Hand-maintained declarations cost review time per export (human derivation, human drift) — generation converts O(exports) review to O(diff) review.

**Mentor note** — diff generated `.d.ts` before/after adding one export (single added block = the API delta, nothing else) — derivation made visible in one diff. Exercise: find one hand-maintained `.d.ts` and regenerate from source — the diff *is* the drift report (over-inclusions to trim, under-inclusions that were silently `any`d). Review gate: hand-edited generated declarations fail review (fix the source, regenerate).

### 2) **`export` discipline in declarations** (named by default; default mirrors implementation)

**Definition** — declaration exports mirror implementation exports one-to-one: named implementations → named declarations; default implementations → default declarations. The discipline question is asked at the *source* (which form does this module publish?) — declarations merely transcribe the answer. Mixed or mismatched declaration exports (declaring a default the source lacks) compile consumers into runtime `undefined`.

**What problem it solves / history** — hand-written `.d.ts` with invented defaults (`export default` over a named-export implementation) compiled importers (`import X from`) into `undefined`-at-runtime (the default slot doesn't exist in the implementation — fulfillment gap invisible to types). Generation eliminates the class (transcription can't invent); hand-written declarations need the mirror rule enforced by review (diff declarations against source exports per PR).

**Modern guidance** — as of TypeScript 5.9 era, publish named exports by default (one name everywhere — same rule as 1.1, now at the package surface); publish a default only mirroring a default-exporting implementation (single-purpose modules: plugins, pages, config factories); never declare exports the source lacks (transcribe, don't invent — generation guarantees this; hand-writing must be diffed).

**Runnable example** — mirror, don't invent (multi-file sets):

```typescript
// file: lib43.ts
export function run(): string { return "ran"; } // named implementation…
export default { run }; // …plus deliberate default mirror (dual shape, owned by the source)
// file: con43.ts
import bundle, { run } from "./lib43.js"; // both forms transcribe into lib43.d.ts on generation
console.log(bundle.run(), run()); // ran ran — dual consumption, source-owned duality
```

```typescript
// file: single44.ts
export default function serve(port: number): string { return `:${port}`; } // single-purpose: default mirrors reality
// file: con44.ts
import serve from "./single44.js";
console.log(serve(80)); // :80 — default where the module IS one thing (pages, plugins, factories)
// bad — export default function + export { serve } (dual without need: two names, one entity, alias drift)
```

```typescript
// file: named45.ts
export const a = 1;
export const b = 2;
// file: con45.ts
import { a, b } from "./named45.js"; // named transcription (generation writes exactly these lines)
console.log((a + b).toFixed(0)); // 3 — multi-export modules stay named end to end
// bad — hand-written named45.d.ts adding `export default { a, b }` (invented slot: importers compile, runtime undefined)
// fix — generate (transcription can't invent) or diff hand-written declarations against source exports per PR
```

**Common confusion** — "declaration defaults are harmless conveniences" — unmirrored defaults compile importers into `undefined` (runtime hole with type-level blessing — the worst failure mode: green CI, broken import). "dual shapes double maintenance" — dual *owned by source* (one declaration site) costs one extra export line; dual *invented in declarations* costs a fulfillment gap — ownership decides. "barrels need defaults" — barrels re-export *named* (explicit lists per 1.1 promise 2) — barrel defaults hide which module provides what (surface opacity for zero gain).

**Performance note** — named-only declarations tree-shake per symbol for consumers (bundlers drop unused named exports); default-slot declarations shake as one unit — export discipline has bundle effects past library scale (same rule as 1.1, now at the published surface).

**Mentor note** — diff one hand-written `.d.ts` against its source exports (invented defaults/omitted members surface immediately) — transcription auditing in one diff. Rule: generated declarations (no review of *form*, review of *diff*); hand-written declarations (diff against source exports per PR, no exceptions).

### 3) **Keeping declarations in sync** (generate; review diffs, not forms)

**Definition** — sync strategy: `declaration: true` (+ `declarationMap`, `emitDeclarationOnly` for type-only packages) in every library tsconfig; generated `.d.ts` committed or built (committed for reviewable API diffs, built for clean repos — team choice, documented); CI verifies generation is current (regenerate + `git diff --exit-code` — drift fails the build, not the customer). Hand-sync (editing `.d.ts` beside `.ts`) is the banned practice — two truths diverge by definition.

**What problem it solves / history** — hand-synced declarations rotted both directions simultaneously (new exports missing → consumers `any`-patched; removed internals lingering → consumers depended on ghosts — each direction invisible until it bit). Generated-plus-verified makes drift a *build failure* (CI regenerates, diffs, errors on delta) instead of a *customer discovery* (types lie until someone trips over them).

**Modern guidance** — as of TypeScript 5.9 era, generate everywhere (`declaration: true` in library configs; `composite`/`project references` propagate declarations across monorepo packages — see [19 Performance](<../../../19 Performance Project References and Scaling/README.md>) textual forward); verify in CI (regenerate-and-diff job); review `.d.ts` diffs as API-evolution records (added lines = new public API — needs API review, not just code review).

**Runnable example** — generation derives, CI verifies (multi-file sets):

```typescript
// file: api46.ts
export interface Req { path: string }
export function handle(r: Req): number { return r.path.length; } // adding `export function retry` here regenerates api46.d.ts with +3 lines (API delta visible)
// file: con46.ts
import { handle, type Req } from "./api46.js";
const req: Req = { path: "/a" };
console.log(handle(req).toFixed(0)); // 2 — consumer checks against generated (current-by-construction) declarations
```

```typescript
// file: pkg47.ts
export function v1(): string { return "v1"; }
// export function v2(): string { return "v2"; } // uncommenting adds v2 to pkg47.d.ts on next build (diff reviews the API addition)
// file: con47.ts
import { v1 } from "./pkg47.js";
console.log(v1()); // v1 — generated surface tracks source exactly (no hand-sync step to forget)
// bad — hand-adding v2 to pkg47.d.ts without implementing (declaration promises what source lacks — fulfillment gap)
```

```typescript
// file: internal48.ts
export function pub(): string { return "pub"; }
function priv(): string { return "priv"; } // unexported (never appears in generated .d.ts — privacy by generation)
export const alsoPub = pub();
console.log(alsoPub.toUpperCase()); // PUB — public surface derived (pub, alsoPub — never priv)
// bad — exporting priv "for tests" (test-only shape in the public surface: consumers depend, support owns it forever)
// fix — test internals via source imports (same-package test files import .ts directly, never .d.ts)
```

**Common confusion** — "committed declarations pollute diffs" — declaration diffs *are* API-evolution records (review gold — every public-API change visible as added/removed lines); built-only declarations hide the record (cleaner diffs, blind API review) — choose deliberately per repo (libraries: commit; apps: build). "CI regeneration is slow" — declaration emit incrementalizes with project references (changed packages only — see domain 19); full-regen cost is linear in sources (seconds, not minutes, for most repos). "hand-sync is fine for small packages" — small packages grow (hand-sync scales with exports × time — generation scales with zero human steps at any size).

**Performance note** — consumers check against `.d.ts` (signatures only — faster than source bodies); declaration emit adds one pass to library builds (incrementalized via project references); CI regenerate-and-diff costs one emit (seconds) — drift detection at build speed instead of incident speed.

**Mentor note** — show one `.d.ts` diff from a feature PR (added export = added API lines — review the *surface*, not just the logic) — API-evolution review in one diff. Exercise: hand-sync one package for a quarter (count drift incidents) vs generate-and-verify (count zero) — the experiment nobody needs twice. Gate: hand-edited generated files fail review; unverified hand-written declarations fail review.
