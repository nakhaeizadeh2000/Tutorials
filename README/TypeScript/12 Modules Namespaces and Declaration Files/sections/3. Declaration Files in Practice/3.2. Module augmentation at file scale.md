## 3.2. Module augmentation at file scale

### 1) **Augmenting shipped packages** (filling gaps upstream missed, with drift discipline)

**Definition** — `declare module "pkg" { interface Opts { retries?: number } }` (in a global `.d.ts`, importing the package at least once so the augmentation *attaches* rather than *shadows*) adds members to a shipped package's types: routes the library supports but doesn't declare, options it reads but doesn't type, overloads it implements but omits. [04/2.2](<../../../04 Objects Interfaces and Type Aliases/sections/2. Composition and Declaration Merging/2.2. Declaration merging and module augmentation.md>) owns merging mechanics; this promise owns *file-scale* practice (where the augmentation lives, how it tracks versions, when it deletes).

**What problem it solves / history** — missing upstream members forced per-use `as` casts (50 call sites casting the same options object — each hiding the gap independently) or local forks (vendored package copies diverging from upstream). One augmentation file centralizes the gap: declared once, checked everywhere, deleted when upstream fills it — casts and forks both retire.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), augment in one `augmentations/<pkg>.d.ts` per package (importing the package for attachment + version-pinned comment + upstream issue link); add only what you consume (minimal surface, precisely typed — never `any` blankets); delete on upstream fix releases (bump → tsc green means clean; new errors mean the augmentation *masked* drift — fix call sites).

**Runnable example** — gap centralized, deleted on arrival (multi-file sets):

```typescript
// file: fake-lib.d.ts
// (stands in for node_modules/pkg/index.d.ts: real types, missing one option)
declare module "fake-lib" {
  export interface Opts { host: string }
  export function connect(o: Opts): string;
}
// file: aug49.d.ts
import "fake-lib"; // attachment import (augmentation ATTACHES; without it, this shadows!)
declare module "fake-lib" {
  interface Opts { retries?: number } // gap filled (library reads it; types missed it)
}
// file: app49.ts
/// <reference path="./fake-lib.d.ts" />
/// <reference path="./aug49.d.ts" />
import { connect } from "fake-lib";
console.log(connect({ host: "h", retries: 3 })); // retries checked (augmentation serving every call site)
// upstream adds retries → DELETE aug49.d.ts → green means agreement (duplicate interface members must be identical or error)
```

```typescript
// file: fake-lib2.d.ts
declare module "fake-lib2" {
  export function run(mode: string): string;
}
// file: aug50.d.ts
import "fake-lib2";
declare module "fake-lib2" {
  export function run(mode: string, verbose: boolean): string; // overload ADDED (implementation supports it; types omitted it)
}
// file: app50.ts
/// <reference path="./fake-lib2.d.ts" />
/// <reference path="./aug50.d.ts" />
import { run } from "fake-lib2";
console.log(run("x", true)); // verbose overload checked (one augmentation, every caller covered)
// bad — per-use (opts as { retries?: number }) casts at 50 call sites (gap hidden 50 times, never tracked)
```

```typescript
// file: fake-lib3.d.ts
declare module "fake-lib3" {
  export interface Cfg { a: string }
}
// file: aug51.d.ts
import "fake-lib3";
declare module "fake-lib3" {
  interface Cfg { b?: number } // conflicting? NO — identical-kind merge (both partial-capable members combine)
}
// file: app51.ts
/// <reference path="./fake-lib3.d.ts" />
/// <reference path="./aug51.d.ts" />
import type { Cfg } from "fake-lib3";
const c: Cfg = { a: "x" }; // b optional (merged surface usable immediately)
// bad — interface Cfg { b: number } (REQUIRED conflicting member: breaks existing { a } constructions — augmentations must widen, never narrow)
// fix — optional/additive members only (augmentation widens the contract or it breaks consumers)
```

**Common confusion** — "augmentation without the attachment import works" — without importing the package, `declare module "pkg"` *shadows* (replaces the whole module type — real members vanish!) instead of *augmenting* — the import line is load-bearing, not ceremonial. "augmentations can narrow" — additive-only (optional members, new overloads, new methods) — required members or conflicting types *break* existing consumers (augmentation is widening by contract). "upstream arrival is automatic" — arrival *orphans* the augmentation (duplicate identical members are legal — silently redundant; conflicting members error) — delete proactively per the TODO, don't wait for conflicts.

**Performance note** — zero emit (declarations erase); augmentation adds one merge per member (cached once) — trivial. The cost axis is drift-tracking (TODO + issue + version pin per file) — process overhead preventing masked-drift incidents.

**Mentor note** — delete the attachment import live and watch the module's real members vanish (shadow vs attach in one deletion) — the load-bearing line teaches itself. Exercise: audit augmentations quarterly against installed versions (upstream-filled gaps = deletion PRs; remaining = still-needed with fresh issue links). Rule: augmentation files carry package import + version pin + upstream issue, or fail review.

### 2) **Ambient vs local augmentation** (blast radius compared)

**Definition** — *ambient* augmentation (global `.d.ts`: affects every file importing the package — one gap-fill serving all consumers) vs *local* augmentation (module-scoped `declare module` inside a feature file: affects that file's view — experimental, contained). Ambient is the norm (shared truth); local serves migration spikes (one feature needs the gap filled *now*, global review pending).

**What problem it solves / history** — global-only augmentation forced a choice between blocking a feature on shared-types review (slow) and polluting global scope with experimental members (risky) — teams picked per temperament, inconsistently. Local augmentation (module-scoped `declare module` blocks) gives the third option: contained experimentation (one file sees the gap filled) graduating to ambient (shared file, reviewed) when proven — spike locally, land globally.

**Modern guidance** — as of TypeScript 5.9 era, spike locally (feature-file augmentation with a `// TODO: promote to augmentations/<pkg>.d.ts` comment), land globally on proof (move to the shared file, review, delete the local block). Never ship local augmentations permanently (two truths per package — the file's view vs everyone else's — diverge by definition). Never ambient-augment experimentally (global blast radius for unproven members).

**Runnable example** — spike contained, landing shared (multi-file sets):

```typescript
// file: fake-lib4.d.ts
declare module "fake-lib4" {
  export function get(id: string): string;
}
// file: spike.ts
/// <reference path="./fake-lib4.d.ts" />
import "fake-lib4";
declare module "fake-lib4" {
  export function getBulk(ids: string[]): string[]; // LOCAL spike (this file's view only)
}
import { getBulk } from "fake-lib4";
console.log(getBulk(["a"]).length); // 1 — experiment contained (no other file sees getBulk)
// TODO: promote to augmentations/fake-lib4.d.ts after API review (graduation path documented in place)
```

```typescript
// file: fake-lib5.d.ts
declare module "fake-lib5" {
  export const V: number;
}
// file: landed.d.ts
import "fake-lib5";
declare module "fake-lib5" {
  export const NAME: string; // LANDED (shared file, reviewed — every importer sees NAME)
}
// file: app53.ts
/// <reference path="./fake-lib5.d.ts" />
/// <reference path="./landed.d.ts" />
import { V, NAME } from "fake-lib5";
console.log(V.toFixed(0), NAME.toUpperCase()); // shared truth (reviewed surface, global blast radius earned)
// bad — permanent local augmentations in 12 feature files (12 truths for one package — divergence guaranteed)
```

```typescript
// file: fake-lib6.d.ts
declare module "fake-lib6" {
  export function ping(): string;
}
// file: exp.ts
/// <reference path="./fake-lib6.d.ts" />
import "fake-lib6";
declare module "fake-lib6" {
  export function pong(): string; // experimental member (unproven — stays local until proven)
}
import { ping, pong } from "fake-lib6";
console.log(ping(), pong()); // local view complete (global view untouched — blast radius: one file)
// bad — ambient-augmenting pong on day one (global contract for an experiment — every consumer inherits the guess)
// fix — spike → prove → land: blast radius grows with evidence, never ahead of it
```

**Common confusion** — "local augmentation hides from other files safely" — hides *types*, not runtime (the member must exist at runtime regardless — local blocks never substitute for library support). "landing is bureaucratic" — landing *is* the review (shared truth deserves shared scrutiny — the spike already proved utility; review proves shape). "ambient files can't scope" — ambient is global by definition (that's the point *and* the hazard — scope control happens via landing discipline, not syntax).

**Performance note** — identical check profile (merges cached once per member regardless of file) — blast-radius discipline is a correctness/review-scaling practice, not a performance one.

**Mentor note** — show both views side by side (spike file sees `getBulk`, neighbor doesn't — same package, two truths) — containment made visible. Rule: local blocks carry promote-or-delete TODOs with dates; permanent local augmentations fail review; unreviewed ambient experiments fail review.

### 3) **When augmentation is wrong** (fork, patch upstream, or widen — the three exits)

**Definition** — augmentation is wrong when: the gap is *behavioral* (needs runtime code — fork or wrap the package instead); the gap belongs *upstream* with a willing maintainer (PR the types — augmentation robs the ecosystem of the fix); or the gap is *total* (package effectively untyped — `any`-shaped augmentation launders everything; write real declarations or replace the dep). Three exits: fork/wrap, upstream PR, full types-or-replace — augmentation is the fourth option for none of these.

**What problem it solves / history** — augmentation-as-habit papered over fork-worthy divergences (behavioral patches in type clothing — runtime still broken, types now claiming otherwise), starved upstream (every local augmentation is a types-PR never sent — ecosystem improves nowhere), and laundered opaque deps (`any`-augmentations blessing unchecked hundreds of call sites). Naming the exits routes each gap honestly: behavior→fork, upstream-shaped→PR, total→types-or-replace, declaration-shaped→augment.

**Modern guidance** — as of TypeScript 5.9 era, ask in order: does it need *runtime*? (yes → fork/wrap — types can't ship behavior); does upstream accept types PRs? (yes → send it — augmentation robs the commons); is the package *substantially* untyped? (yes → full declarations or replacement — augmentation scales to gaps, not absences); else augment (declaration-shaped gap, unmaintained/slow upstream — the honest remainder).

**Runnable example** — exits chosen honestly (multi-file sets):

```typescript
// file: fake-lib7.d.ts
declare module "fake-lib7" {
  export function base(): string;
}
// file: wrap.ts
/// <reference path="./fake-lib7.d.ts" />
import { base } from "fake-lib7";
export function extended(): string { return `${base()}+ext`; } // WRAP (behavioral gap: runtime code, not types)
console.log(extended()); // behavioral gaps get wrappers (augmentation can't ship runtime)
// bad — declare module "fake-lib7" { export function extended(): string } (claims runtime that doesn't exist — fulfillment lie)
```

```typescript
// file: fake-lib8.d.ts
declare module "fake-lib8" {
  export interface Opts { host: string } // upstream accepts PRs (maintained, typed, welcoming)
}
// file: aug58.d.ts
import "fake-lib8";
declare module "fake-lib8" {
  interface Opts { retries?: number } // PR-worthy gap (send upstream AND augment meanwhile with linked TODO)
}
// file: app58.ts
/// <reference path="./fake-lib8.d.ts" />
/// <reference path="./aug58.d.ts" />
import type { Opts } from "fake-lib8";
const o: Opts = { host: "h" };
console.log(o.host.toUpperCase()); // augmentation WITH upstream PR linked (commons enriched, gap tracked)
// bad — permanent local augmentation for PR-able gaps (ecosystem never improves; every consumer re-augments)
```

```typescript
// file: fake-lib9.d.ts
declare module "fake-lib9" {
  const all: any; // total absence (opaque package — augmentation CANNOT fix this honestly)
  export = all;
}
// file: app59.ts
/// <reference path="./fake-lib9.d.ts" />
import all = require("fake-lib9");
console.log("opaque"); // any-shaped: every use unchecked (augmenting members here is lipstick on any)
// fix — full minimal declarations (per 2.3 promise 1: used members, precisely typed) or REPLACE the dependency
// bad — declare module "fake-lib9" { export function precise(): string } (precise leaf on an any trunk — siblings still launder)
```

**Common confusion** — "augmentation is always safer than forking" — safer for *declaration* gaps (no runtime delta); *dangerous* for behavioral gaps (claims runtime that doesn't exist — fork/wrap instead). "upstream PRs are slow, augmentation is fast" — both (augment *meanwhile* with the PR linked — speed now, commons later — not either/or). "replacing deps is dramatic" — opaque deps cost every call site its checking (hundreds of unchecked uses); replacement is arithmetic, not drama — count unchecked uses to justify.

**Performance note** — exit choice has no check-time delta worth measuring (merges cached identically) — the economics are maintenance (fork upkeep vs PR latency vs laundering incidents) — decide on ownership grounds, never performance ones.

**Mentor note** — run the four-question exit drill per gap (runtime? upstream-able? total? else augment) — routing in under a minute per gap. Exercise: classify the repo's augmentations into the four exits — misrouted ones (behavioral augmentations especially) are the refactoring backlog, self-prioritized.
