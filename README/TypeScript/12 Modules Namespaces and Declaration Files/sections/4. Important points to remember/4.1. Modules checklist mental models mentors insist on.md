## 4.1. Modules checklist — mental models mentors insist on

### 1) **ES modules by default, namespaces almost never** (modules for code; corners for namespaces)

**Definition** — every application file is an ES module (file scope, explicit imports/exports, tree-shakeable, erasable); `namespace` appears only in three recorded corners (ambient foreign declarations, generated single-file output, deliberately non-erasable grouping with a dated reason). The default serves the 99%; the corners carry comments naming theirs.

**What problem it solves / history** — namespace-by-habit code paid the triple tax per use (IIFE bytes, un-erasability blocking toolchain adoption, un-shakeable retention) for organization modules provide free — each namespace a small permanent cost with zero unique benefit in application code. The default-plus-corners rule concentrates namespaces where they earn costs and deletes them everywhere else (see [2.1. Namespaces](<../2. Namespaces and Ambient Contexts/2.1. Namespaces organization and when to avoid.md>)).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), lint new application namespaces out; record corner reasons in place; migrate legacy namespaces per directory (module + barrel, tests green throughout). See promises 2–4 for the traffic, ambient, and publishing thirds of the checklist.

**Runnable example** — module default, namespace corner (multi-file sets):

```typescript
// file: shapes60.ts
export interface Dot { x: number } // module default (file scope does the grouping)
export function zero(): Dot { return { x: 0 }; }
// file: app60.ts
import { zero, type Dot } from "./shapes60.js";
const d: Dot = zero();
console.log(d.x.toFixed(0)); // 0 — erasable, shakeable, no namespace costs
```

```typescript
// file: corner60.d.ts
declare namespace Legacy { const V: number } // corner (ambient foreign): recorded reason, stays
// file: app61.ts
/// <reference path="./corner60.d.ts" />
console.log("ambient-corner"); // foreign truth needs SOME typed home (this one, commented)
// bad — namespace Util { ... } in application source (triple tax for module-doable grouping)
```

```typescript
// file: barrel60.ts
export interface A { a: string }
// file: barrel60b.ts
export interface B { b: string }
// file: idx60.ts
export type { A } from "./barrel60.js";
export type { B } from "./barrel60b.js"; // explicit barrel (public surface curated, internals direct)
// file: app62.ts
import type { A, B } from "./idx60.js";
const ab: A & B = { a: "x", b: "y" };
console.log(ab.a.toUpperCase(), ab.b.toUpperCase()); // X Y — curated surface, direct internals
```

**Common confusion** — "lint bans ambient namespaces too" — `no-namespace` allows `declare namespace` (ambient foreign description survives the rule by design) — configure, don't blanket-ban. "migration changes behavior" — namespace-to-module preserves values (same functions, new paths) — only the grouping mechanism changes. "corners need no comments" — unrecorded corners rot into habits (the next author copies the form without the reason) — record or migrate, no third option.

**Performance note** — each migrated namespace deletes its IIFE (bytes + evaluation) and unlocks per-symbol shaking — migration dividends compound per directory (measure bundle deltas per migration PR).

**Mentor note** — migrate one directory live (tests green throughout) — mechanical, reviewable, dividend-visible. Metric: application-namespace count per quarter (falling = default working).

**Cross-links** — namespaces → [2.1. Namespaces](<../2. Namespaces and Ambient Contexts/2.1. Namespaces organization and when to avoid.md>); export forms → [1.1. import and export forms](<../1. ES Modules/1.1. import and export forms named default star re-export.md>).

### 2) **Type traffic travels `import type`** (enforced, stripping-safe, weight-free)

**Definition** — every type-only import written `import type` (stated erasability), enforced by `verbatimModuleSyntax` (TS1484 on guessing), verified by dual-pipeline CI (tsc + stripping agree). The discipline makes type traffic weight-free (zero bytes, zero load edges), cycle-safe (type-space cycles never load), and toolchain-universal (every syntax-only consumer processes identically).

**What problem it solves / history** — value-syntax type imports created phantom runtime edges (bundler weight, circular-load crashes, toolchain-divergent elision — the 5.1-adjacent barrel-cycle class) that `import type` deletes by construction. Enforcement converts discipline from convention (decays) to compiler behavior (compounds) — TS1484 *is* the erasability audit, automated per import.

**Modern guidance** — as of TypeScript 5.9 era, `import type` every type-only name (lint `consistent-type-imports` so the discipline holds without vigilance); fix TS1484s by converting (stating), never by value-using (fraud against the flag). See [1.2. import type](<../1. ES Modules/1.2. import type and verbatimModuleSyntax erasable imports.md>) for the full trio treatment.

**Runnable example** — stated traffic, zero weight (multi-file sets):

```typescript
// file: m63.ts
export interface Item { sku: string }
// file: svc63.ts
import type { Item } from "./m63.js"; // stated (verbatimModuleSyntax-honest, stripping-safe)
export function label(i: Item): string { return i.sku.toUpperCase(); }
// file: app63.ts
import { label } from "./svc63.js";
console.log(label({ sku: "k" })); // K — svc63.js carries no m63.js runtime edge
```

```typescript
// file: m64.ts
export interface Cfg { host: string }
export const DEF_PORT = 80; // value (kept) beside types (erased) — split traffic per universe
// file: svc64.ts
import type { Cfg } from "./m64.js";
import { DEF_PORT } from "./m64.js"; // one line per universe, each honest about emit
export function addr(c: Cfg): string { return `${c.host}:${DEF_PORT}`; }
// file: app64.ts
import { addr } from "./svc64.js";
console.log(addr({ host: "h" })); // h:80 — types erased, values kept, bundler sees one edge
// bad — import { Cfg, DEF_PORT } (single value-syntax import: TS1484 under verbatimModuleSyntax)
```

```typescript
// file: cycA.ts
import type { B } from "./cycB.js"; // type-space cycle (legal — values never load)
export interface A { b?: B }
// file: cycB.ts
import type { A } from "./cycA.js";
export interface B { a?: A }
console.log("type-cycle-safe"); // compiles AND loads (no runtime cycle exists to break)
// bad — value-syntax type cycle (runtime edges circle: import-time undefined crashes under some loaders)
// fix — import type: cycles in type space are free; cycles in value space are incidents
```

**Common confusion** — "elision already handles this" — elision *guesses* (correct usually, wrong across re-exports/isolated declarations); `import type` *declares* (always right, toolchain-independent). "splitting imports doubles lines" — two honest lines beat one ambiguous line (reviewers read emit-intent per line; bundlers process it correctly). "type cycles indicate bad design" — *value* cycles indicate bad design; type-space cycles (A-refs-B-refs-A in types only) are normal domain modeling — `import type` keeps them free.

**Performance note** — erased edges cost zero bytes/zero loads (bundlers skip them); value edges cost evaluation (side effects run, graph grows) — per-import honesty is bundle diet at scale (hundreds of type-only cross-imports).

**Mentor note** — enable `verbatimModuleSyntax` Friday, triage TS1484s Monday (each a phantom edge deleted) — the audit the codebase needed, automated. Exercise: grep value-imported type-only names quarterly (lint does this continuously once enabled — the exercise is installing the lint).

**Cross-links** — type imports → [1.2. import type](<../1. ES Modules/1.2. import type and verbatimModuleSyntax erasable imports.md>); type/value spaces → [2.1. Type space vs value space](<../../../02 The Type System Core/sections/2. The type vs value separation/2.1. Type space vs value space two parallel universes.md>) (in 02).

### 3) **Ambient declarations describe foreign truth** (mirror exactly, trust explicitly, delete on arrival)

**Definition** — ambient contexts (`declare global`, `declare module`, ambient namespaces, ambient enums) *describe* code someone else emits: mirror exactly (explicit initializers matching foreign values — never auto-increment against foreign tables), trust explicitly (provider comments, narrow types, no blankets), delete on arrival (upstream real types orphan shims — deletion PRs, never parallel maintenance).

**What problem it solves / history** — undescribed foreign code spread `any` (per-use casts, index blankets, untyped requires — checking surrendered at every boundary); over-described foreign code (hand-mirrors drifting from vendor updates) compiled callers into runtime mismatches. Exact-mirror ambient declarations thread the needle: full checking against current foreign truth, with TODOs + issues + version pins tracking the trust's expiry.

**Modern guidance** — as of TypeScript 5.9 era, centralize ambient declarations (globals.d.ts, shims/ per package, ambient namespaces beside their consumers); type narrowly (unions over `string`, signatures over `any`, per-flag fields over index blankets); audit quarterly (provider alive? upstream types arrived? vendor renumbered?). See [2.2. declare global](<../2. Namespaces and Ambient Contexts/2.2. declare global and global augmentation.md>) + [2.3. Ambient modules](<../2. Namespaces and Ambient Contexts/2.3. Ambient modules declare module wildcards.md>).

**Runnable example** — mirrored, trusted, deletable (multi-file sets):

```typescript
// file: vend65.d.ts
declare module "vend-lib" {
  export function ping(): string; // exact mirror (narrow signature, no blankets)
}
// file: app65.ts
/// <reference path="./vend65.d.ts" />
import { ping } from "vend-lib";
console.log(ping().toUpperCase()); // checked against the mirror (trust explicit, coverage exact)
// upstream ships types → DELETE vend65.d.ts → green means agreement (see 2.3 promise 3)
```

```typescript
// file: glob65.d.ts
export {};
declare global {
  var __BUILD: string; // provider: CI template (documented — trust has a name)
}
// file: app66.ts
/// <reference path="./glob65.d.ts" />
console.log(globalThis.__BUILD.length); // typed global (narrow string, not any)
// bad — (globalThis as any).__BUILD (per-use escape hiding at every site — centralize once)
// fix — glob65.d.ts: one typed home, every use checked, provider documented
```

```typescript
// file: wild65.d.ts
declare module "*.txt" {
  const text: string;
  export default text; // per-loader contract (raw-loader shape, typed once)
}
// file: app67.ts
/// <reference path="./wild65.d.ts" />
console.log("txt-contract-typed"); // loader contract centralized (config + types land together)
// bad — untyped asset imports per file (TS2307 toil per file instead of one declaration)
```

**Common confusion** — "ambient declarations validate providers" — describe, never verify (missing scripts still crash — types narrow contracts, runtimes own presence). "narrow mirrors cost maintenance" — narrow mirrors *surface* vendor drift as errors (the maintenance is the feature — blankets hide drift until incidents). "deletion is risky" — deletion *reveals* (errors = masked drift surfacing productively); parallel maintenance guarantees divergence eventually.

**Performance note** — zero emit (all declarations erase); resolution adds one candidate tier per import (negligible); deleted-on-arrival shims simplify resolution permanently.

**Mentor note** — `ls types/shims/` + `npm outdated` quarterly (arrivals = deletion PRs) — the trust backlog made countable. Exercise: delete one long-kept shim and triage resulting errors (masked drift surfacing = hidden cost receipt). Rule: ambient blocks carry provider + TODO/issue, or fail review.

### 4) **Publish generated declarations, tested on three pipelines** (universality proof before release)

**Definition** — release gate: declarations generated current (regenerate-diff clean), `exports` mapped with `types` conditions (no unmapped public paths), triple-pipeline smoke passing (tsc + bundler + stripping on the same test import), support policy stated (minimum TS, variants justified). Four gates, automated, blocking — hope replaced by proof at every release.

**What problem it solves / history** — untyped-subpath releases (consumer `any`-infection), stale-declaration releases (fulfillment gaps), and pipeline-specific releases (tsc-green, esbuild-red — the const-enum class) each shipped green CI and broke consumers. Gates convert release hope into release proof: emit-current (no drift), mapped (no untyped paths), triple-smoke (no pipeline surprises), policy-stated (no guessing support).

**Modern guidance** — as of TypeScript 5.9 era, automate all four in release CI; review gate output (which gates ran — unconfigured gates pass vacuously); version the checklist with incident history (new failure modes append gates). See [3.3. Publishing types](<../3. Declaration Files in Practice/3.3. Publishing types exports map and typesVersions.md>) + [3.1. Authoring d.ts](<../3. Declaration Files in Practice/3.1. Authoring d.ts public API surface.md>).

**Runnable example** — gates green, release ships (multi-file sets):

```typescript
// file: lib68.ts
export function total(xs: number[]): number { return xs.reduce((a, b) => a + b, 0); }
// file: con68.ts
import { total } from "./lib68.js";
console.log(total([1, 2]).toFixed(0)); // 3 — smoke import (same file, three pipelines in CI)
// tsc: typecheck green — bundler: bundles (no const-enum/namespace traps) — stripping: executes (erasable syntax)
```

```typescript
// file: api69.ts
export interface Req69 { path: string }
// file: con69.ts
import type { Req69 } from "./api69.js"; // type-only smoke (erased identically on all three pipelines)
const r: Req69 = { path: "/x" };
console.log(r.path.toUpperCase()); // /X — declarations current (regenerate-diff clean in CI)
// bad — tsc-only CI (pipeline-specific breakage ships to bundler/stripping consumers undetected)
```

```typescript
// file: pol70.ts
export const policy = { minTS: "5.0", smoke: ["tsc", "esbuild", "strip"] } as const; // stated policy (auditable)
// file: con70.ts
import { policy } from "./pol70.js";
console.log(policy.smoke.join("+")); // tsc+esbuild+strip — Gates named, run, and blocking (not hoped)
 // bad — unstated policy (minimum unknown, pipelines assumed, enums drift in — three unknowns compounding)
```

**Common confusion** — "gates slow releases" — seconds automated (emit + smoke parallelized) vs days per incident — automation inverts the speed argument permanently. "small packages skip gates" — gates scale with zero human steps (hope scales with forgetting) — install at package birth. "green CI equals gates passing" — green means *configured* gates passed (audit gate presence, not color).

**Performance note** — gate runtime seconds (parallel emit + smoke); incident cost days + trust — cheapest release insurance in typed-package practice.

**Mentor note** — ship one release with a deliberately-broken gate (stale declaration) and watch CI block it — proof beats policy documents. Culture pattern: same as 11's enum stamp (measured behavior, celebrated prevention).
