## 1.1. Class Types, public private protected

### 1) **Definition** (class as type + value)

**Definition** — A `class` is both a value (constructor + prototype at runtime) and a type (instance shape at checker). Modifiers control visibility:

- `public` (default) — visible everywhere.
- `private` — visible only inside declaring class (TS-private, structural nominal leak — see note).
- `protected` — visible inside class + subclasses.
- `#private` (JS private) — truly private at runtime (hard brand, no structural leak).

```typescript
class User {
  public name: string;          // default public
  private _id: string;          // TS private
  #token: string;                // JS private (hard)
  protected role: string;       // subclass-visible

  constructor(name: string, id: string, token: string) {
    this.name = name;
    this._id = id;
    this.#token = token;
    this.role = "member";
  }

  public getId(): string { return this._id; }
  // #token only accessed inside class
  private rotateToken(newToken: string): void { this.#token = newToken; }
}

const u = new User("Ava", "1", "s3cr3t");
u.name; // ok
// u._id // error — private
// u.#token // error — syntax error even outside
```

Type side:

```typescript
// class as type:
let u2: User = new User("Ada", "2", "t2");
// structural check uses instance members (public shape)
type HasName = { name: string };
let h: HasName = u2; // ok — User has name (structural), private not in HasName
```

---

### 2) **Modifier** (private vs #private)

Difference matters for nominal behavior + emit:

```typescript
class A { private x = 1; }
class B { private x = 1; }
let a: A = new A();
// let b: A = new B(); // error — even though shapes identical, private from different declarations makes A vs B incompatible (nominal leak)
// let b2: A = { x: 1 } as unknown as A; // bypass — still notion

// JS private (#) is hard — no compatible structural leak, truly separate
class C { #x = 1; }
class D { #x = 1; }
// new C() not assignable to D — each #x is unique

// emit:
// private → regular property (this.x) — no runtime privacy
// #x → WeakMap-backed private field (requires target >= es2015 with proper helpers)
```

Also shorthand `public` in ctor params:

```typescript
class Point {
  constructor(public x: number, public y: number, private id: string) {}
}
let p = new Point(1, 2, "id1");
p.x; // 1
```

---

### 3) **Bad** (private for encapsulation only)

**Bad — relying on `private` for security:** `private` is erased + structural trick only. At runtime `obj["privateField"]` is accessible. Use `#private` when secrecy needed, or `WeakMap` branding.

```typescript
class Bad {
  private secret = "123"; // not secret at runtime
}
const bad = new Bad();
console.log((bad as unknown as Record<string, unknown>)["secret"]); // "123" — leak

class Good {
  #secret = "123"; // truly private
}
const good = new Good();
// (good as unknown as Record<string, unknown>)["#secret"] // undefined

// also bad: over-using private for API shape — prefer public interface and keep class as impl
// export class User { private x; } forces consumers to care about private nominal identity
// better: export interface IUser { id: string; name: string } and class implements it
```

**Common confusion** —

- "`private` makes property hidden at runtime" — no, only `#` does.
- "Class structural = interface structural" — mostly yes, but `private`/`protected` create nominal separation.

**Performance note** — Types are erased (zero emit); checker cost dominates. For this feature, keep types shallow and measure `tsc --extendedDiagnostics` if checker slows.

**Mentor note** —

Prefer `public`/`protected` for API shape, `#private` for secrets, and avoid mixing TS `private` with `#` in same codebase without documented policy — reviewers get confused.
