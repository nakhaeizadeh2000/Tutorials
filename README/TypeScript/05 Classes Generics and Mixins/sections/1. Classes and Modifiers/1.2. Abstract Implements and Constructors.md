## 1.2. Abstract, Implements and Constructors

### 1) **Definition** (abstract class vs interface)

**Definition:**

- `abstract class` — cannot be instantiated; may have abstract members (no body) and concrete members (with body). Subclass must implement abstract members.
- `interface` vs `implements` — class can `implements` interface/structure to declare conformance; checked structurally, not inheritance-based.
- Constructors typed with `new (...) => T` or `abstract new`.

```typescript
abstract class Animal {
  abstract makeSound(): string; // no body — subclass must implement
  move(): string { return "moving"; } // concrete
  constructor(public name: string) {}
}
// const a = new Animal("x"); // error — abstract

class Dog extends Animal {
  makeSound(): string { return "woof"; }
}
let d = new Dog("Buddy");
console.log(d.makeSound(), d.move()); // woof moving

interface Runnable { run(): void; }
class Robot implements Runnable {
  run(): void { console.log("running"); }
}

// abstract constructor for factory
type Ctor<T> = new (...args: unknown[]) => T;
abstract class Base { constructor(public id: string) {} }
function create<T extends Base>(Ctor: new (id: string) => T, id: string): T {
  return new Ctor(id);
}
```

### 2) **Example** (implements)

```typescript
// implements checks shape but does not inherit implementation
interface HasId { id: string; }
interface Timestamped { createdAt: Date; }

class User implements HasId, Timestamped {
  constructor(public id: string, public createdAt: Date, public name: string) {}
}
// User must have id + createdAt (from interfaces) + name
let u: HasId = new User("1", new Date(), "Ava"); // ok — User is HasId

// implements vs extends
interface Entity { id: string; }
abstract class BaseEntity implements Entity {
  constructor(public id: string) {}
  abstract validate(): boolean;
}
class Concrete extends BaseEntity {
  validate(): boolean { return !!this.id; }
}

// mixing implements with optionality
interface WithConfig { config?: { debug: boolean }; }
class Service implements WithConfig {
  constructor(public config?: { debug: boolean }) {}
}
```

Subtle: `implements` is *not* inherited check for subclasses' private members; it enforces `public` shape only.

### 3) **Tradeoff** (abstract vs composition)

**Tradeoff:**

- `abstract class` — hard inheritance, carries runtime prototype chain, supports `instanceof` and shared concrete logic. Tight coupling.
- `interface` + composition — flat; testable; favors `type &` composition. No runtime chain.

```typescript
// abstract coupling trap
abstract class BadBase {
  abstract save(): Promise<void>;
  log(): void { console.log("saving"); } // concrete — subclasses forced to inherit log
}
// Prefer strategy/composition (SOLID ISP/DIP):
type Saver = { save(): Promise<void> };
type Logger = { log(msg: string): void };

function makeService(saver: Saver, logger: Logger) {
  return { async doWork() { logger.log("start"); await saver.save(); } };
}

// when to abstract: shared state + template method pattern with shared ctor
abstract class Template {
  constructor(protected db: { query(sql: string): Promise<unknown> }) {}
  abstract getKey(): string;
  async load(): Promise<unknown> { return this.db.query(`SELECT * WHERE id=${this.getKey()}`); }
}
```

Rule: use `abstract class` only when you need shared *state* + *instanceof* semantics; otherwise `interface` + function factories win (see [03 3.1 Composition](<../../../03%20Objects%20Interfaces%20and%20Type%20Aliases/sections/3.%20Composition%20and%20Utility%20Basics/3.1.%20Composition%20over%20Inheritance%20intersection%20for%20extension.md>)).

### Mentor note

Default to `implements interface` for test mocks: `class Mock implements ServiceInterface {}` gives compile errors when interface changes — cheap regression guard.

### Common confusion

- "`implements` inherits" — no, it only checks shape; runtime inheritance is `extends`.
- "abstract method must have body" — no, abstract means no body; concrete subclass provides it.
