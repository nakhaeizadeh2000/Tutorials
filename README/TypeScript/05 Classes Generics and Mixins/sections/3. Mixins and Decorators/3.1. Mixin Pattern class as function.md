## 3.1. Mixin Pattern (class as function)

### 1) **Pattern** (Ctor<T>)

**Pattern** — A mixin is a function taking a constructor and returning an extended constructor: `<TBase extends Ctor>(Base: TBase) => class extends Base { ... }`. It composes behavior without static inheritance chain.

```typescript
type Ctor<T = object> = new (...args: unknown[]) => T;

function Timestamped<TBase extends Ctor>(Base: TBase) {
  return class extends Base {
    createdAt = new Date();
    touch(): void { this.createdAt = new Date(); }
  };
}

class User {
  constructor(public name: string) {}
}

const TimestampedUser = Timestamped(User);
let u = new TimestampedUser("Ava");
console.log(u.name, u.createdAt, u.touch());

// chaining mixins
function SoftDeletable<TBase extends Ctor>(Base: TBase) {
  return class extends Base {
    deletedAt: Date | null = null;
    softDelete(): void { this.deletedAt = new Date(); }
  };
}
const FullUser = SoftDeletable(Timestamped(User));
let fu = new FullUser("Ada");
fu.touch(); fu.softDelete();
```

### 2) **Example** (Timestamped mixin)

```typescript
// typed mixin helper
type AbstractCtor<T = object> = abstract new (...args: unknown[]) => T;

function WithId<TBase extends Ctor>(Base: TBase) {
  return class extends Base {
    id = Math.random().toString(36).slice(2);
  };
}

// mixin preserves instance type via intersection
function Named<TBase extends Ctor<{ name: string }>>(Base: TBase) {
  return class extends Base {
    displayName(): string { return `User:${this.name}`; }
  };
}

// usage with generics + constraints
class Entity { constructor(public id: string) {} }
const NamedEntity = Named(class extends Entity {
  constructor(id: string, public name: string) { super(id); }
});
let ne = new NamedEntity("1", "Ava");
console.log(ne.displayName(), ne.id);

// type of instance:
type TimestampedUserInstance = InstanceType<typeof TimestampedUser>; // User & { createdAt: Date }
```

### 3) **Bad** (mixin over inheritance)

**Bad — over-using mixin:**

- Mixin chains longer than 2 steps become opaque — `A(B(C(D)))` type errors unreadable.
- Mixins capture `this` as intersection — IDE hover grows to `User & Timestamped & SoftDeletable & ...`.
- For shared behavior without instance state, favor plain functions/composition (SOLID).

```typescript
// bad: deep mixin chain hard to debug
const Monster = SoftDeletable(Timestamped(WithId(class { constructor(public name: string) {} })));
// hover type: Monster & WithId & Timestamped & SoftDeletable — error traces deep

// bad: mixin for what should be strategy
function Payable<TBase extends Ctor>(Base: TBase) {
  return class extends Base { pay(amount: number): void { /* ... */ } };
}
// good: composition — pay is a service, not a trait
type Payer = { pay(amount: number): void };
function makePayable(user: User, payer: Payer) {
  return { user, pay: payer.pay };
}

// good threshold: use mixin only when you need class identity + instanceof + constructor chain
// e.g., ORM base model with timestamps + soft-delete + versioning
```

### Mentor note

Limit mixin chain to 1–2; beyond that model as `type &` + helper functions. Name mixins `With*`/`Timestamped` consistently; require doc comment stating what it adds.

### Common confusion

- "Mixin is inheritance" — no, it's function composition returning a class. No static `extends` at author site.
