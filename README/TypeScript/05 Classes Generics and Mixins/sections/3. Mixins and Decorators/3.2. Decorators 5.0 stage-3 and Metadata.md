## 3.2. Decorators 5.0 (stage-3) and Metadata

### 1) **Definition** (decorator as function)

**Definition** — Decorator is a function called at definition time that can wrap/replace a class, method, getter, setter, property, or parameter. TS 5.0 aligns with TC39 Stage-3 (ES spec) — *new* decorator shape (different from legacy `experimentalDecorators`).

```typescript
// Stage-3 decorator (5.0+ — no experimentalDecorators needed for this shape)
function logged<This, Args extends unknown[], Return>(
  method: (this: This, ...args: Args) => Return,
  context: ClassMethodDecoratorContext<This, (this: This, ...args: Args) => Return>,
): (this: This, ...args: Args) => Return {
  const name = String(context.name);
  return function(this: This, ...args: Args): Return {
    console.log(`enter ${name}`);
    const r = method.apply(this, args);
    console.log(`exit ${name}`);
    return r;
  };
}

class Service {
  @logged
  find(id: string): string { return `user:${id}`; }
}
let s = new Service();
console.log(s.find("1")); // enter find → exit find → user:1

// class decorator
function sealed<T extends { new (...args: unknown[]): unknown }>(Ctor: T, _ctx: ClassDecoratorContext): T {
  Object.seal(Ctor);
  Object.seal(Ctor.prototype);
  return Ctor;
}
@sealed
class Entity { constructor(public id: string) {} }
```

Requires `--target es2022`+ and `lib: ["es2022"]` for native decorators; emitted as plain JS class wrappers.

### 2) **Modern** (TC39 vs legacy)

| Aspect | Stage-3 (TS 5.0) | Legacy (`experimentalDecorators`) |
|--------|-------------------|-----------------------------------|
| Syntax | `context` second param, return replacement | `(target, key, descriptor)` |
| Config | no flag (standard) | `experimentalDecorators: true` + `emitDecoratorMetadata` |
| Metadata | `Symbol.metadata` (`--esnext` / `reflect-metadata` v2) | `Reflect.metadata` API (legacy transformers) |
| Interop | NestJS/Fastify decorators migrating — check lib docs | Most existing libs still use legacy |
| Future | stable, works with `esbuild`/`swc` stage-3 | deprecated path, will be removed |

**Modern guidance** (5.6 era):

- For greenfield, use stage-3 decorators **only** for simple AOP (logging, caching, validation wrapper). The API is intentionally minimal — no `descriptor` mutation.
- For NestJS/TypeORM still on legacy, keep `experimentalDecorators: true` until ecosystem migrates; don't mix styles in one project.
- Prefer *functions over decorators* for most cases — decorator magic hides control flow. A wrapper function is clearer than `@logged`.

```typescript
// modern caution: context kind check
function bound<This, Args extends unknown[], Return>(
  method: (this: This, ...args: Args) => Return,
  context: ClassMethodDecoratorContext<This, (this: This, ...args: Args) => Return>,
): (this: This, ...args: Args) => Return {
  if (context.private) throw new Error("cannot decorate private with this helper");
  return method.bind as unknown as (this: This, ...args: Args) => Return; // sketch — real impl stores bound per instance
}
```

### 3) **Link** (to Tooling for lint)

Decorators affect lint/DX:

- ESLint `no-experimental` vs stage-3: configure `@typescript-eslint/no-invalid-this` correctly for decorator-wrapped methods (see [09 1.1 ESLint](<../../../09%20Tooling%20ESLint%20Biome%20and%20Type-Level%20Testing/sections/1.%20Lint%20and%20Format/1.1.%20ESLint%20+%20typescript-eslint%20vs%20Biome.md>)).
- `emitDecoratorMetadata` emits design-time types (`design:type` via `reflect-metadata`) — only needed for legacy DI (NestJS). Stage-3 uses `Symbol.metadata` instead — separate polyfill.
- `target`/`useDefineForClassFields` interaction — see [08 1.1 Target/Module](<../../../08%20Configuration%20Strictness%20and%20Build%20Pipeline/sections/1.%20tsconfig%20Foundations/1.1.%20Target%20Module%20Lib%20and%20Emit.md>).

**Cross-links:** `useDefineForClassFields` → [08 1.1](<../../../08%20Configuration%20Strictness%20and%20Build%20Pipeline/sections/1.%20tsconfig%20Foundations/1.1.%20Target%20Module%20Lib%20and%20Emit.md>); class fields vs `#` private → [1.1 Class types](<../1.%20Classes%20and%20Modifiers/1.1.%20Class%20Types%20public%20private%20protected.md>).

### Mentor note

Default advice: don't use decorators for business logic. Reserve for cross-cutting infra with tests. In PR, ask "could this be a plain higher-order function?" If yes, prefer it.

### Common confusion

- "`@decorator` mutates descriptor" — that was legacy. Stage-3 returns replacement; old `descriptor.value` pattern no longer applies.

### Performance note

Decorator wraps one extra function call per invocation — negligible unless hot loop wrapping tight numeric kernel. For hot path, inline helper.
