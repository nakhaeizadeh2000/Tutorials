## 2.1. Type Parameters, Defaults and Constraints

### 1) **Definition** (<T = string>)

**Definition** — Generics on types/classes/interfaces mirror function generics: `<T>` parameter, `extends` constraint (upper bound), `= Default` fallback when argument omitted. Constraints propagate — e.g., `class Box<T extends { id: string }>`.

```typescript
// interface with constraint + default
interface Response<T = string> { data: T; ok: boolean; }
let r1: Response = { data: "hi", ok: true }; // T = string default
let r2: Response<number> = { data: 42, ok: true };

class Repository<T extends { id: string }> {
  constructor(private items: T[]) {}
  find(id: string): T | undefined { return this.items.find(x => x.id === id); }
}
type User = { id: string; name: string };
let repo = new Repository<User>([{ id: "1", name: "Ava" }]);

// default with constraint: must satisfy constraint
type Cache<K extends string = "default", V = unknown> = Map<K, V>;
let c: Cache = new Map(); // Map<"default", unknown>

// generic type alias defaults cascade
type Pair<T = string, U = number> = [T, U];
let p: Pair = ["a", 1];
let p2: Pair<boolean> = [true, 42]; // T=boolean, U default number
```

TS 5.0 `const` generics also for types (`<const T extends string>` preserves literal).

### 2) **Example** (default)

```typescript
// example: typed event emitter with default
type Listener<T = unknown> = (payload: T) => void;
class Emitter<T = string> {
  private handlers: Listener<T>[] = [];
  on(fn: Listener<T>): void { this.handlers.push(fn); }
  emit(v: T): void { for (const h of this.handlers) h(v); }
}
let e = new Emitter(); // Emitter<string> default
e.on(s => s.toUpperCase()); // s inferred string
e.emit("hi");
// let e2 = new Emitter<number>(); // Emitter<number>
let e2 = new Emitter<number>();
e2.on(n => n.toFixed()); // number

// constraint narrows helper
function pluck<T, K extends keyof T>(obj: T, key: K): T[K] { return obj[key]; }
const user = { id: "1", name: "Ava", age: 30 };
let name = pluck(user, "name"); // string
// pluck(user, "missing") // error

// default + overload interplay
type Maybe<T, WithDefault extends boolean = false> =
  WithDefault extends true ? T : T | undefined;
```

### 3) **Mistake** (unconstrained any)

**Bad — unconstrained generic leaks `unknown`/`any`:**

```typescript
// bad: T unconstrained — caller can pass anything, impl uses as if T has props
function getIdBad<T>(x: T): string { return (x as unknown as { id: string }).id; } // lies

// good: constrained
function getIdGood<T extends { id: string }>(x: T): string { return x.id; }
getIdGood({ id: "1", name: "Ava" }); // ok
// getIdGood({ name: "Ava" }) // error

// bad: default hides error
type Bad<T = unknown> = T extends string ? true : false;
type Test = Bad; // unknown -> false — did you mean string default?
// good: default that satisfies intent
type Good<T extends string = string> = T extends string ? true : false;

// also bad: using any as constraint
function anyBad<T extends any>(x: T): T { return x; } // any disables check
function unknownGood<T>(x: T): T { return x; } // unknown implicit bound is fine
```

### Mentor note

Default generously but constrain minimally: default helps callers omitting args; constraint catches misuse. Pair with doc comment explaining when default applies.

### Common confusion

- "`T = string` means T is string" — no, it's fallback when omitted. `Foo<number>` still overrides.
- "`extends` means subclass" — for type param, means "assignable to" (so `T extends string` allows literal `"a"`).
