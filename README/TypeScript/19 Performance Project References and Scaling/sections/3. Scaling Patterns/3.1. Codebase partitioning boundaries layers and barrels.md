## 3.1. Codebase partitioning boundaries layers and barrels

### 1) **Layered boundaries** (domain app infra layering, inward imports, path enforcement)

**Definition** — *layering*: directories assigned to layers (domain ← app ← infra... precisely: inner layers imported by outer — domain knows nothing of app/infra; app knows domain; infra knows all): enforcement via `tsconfig` `paths` scoping + lint `no-restricted-imports` (illegal directions red at authoring — architecture as errors, not diagrams); tests per layer (unit inward, integration at seams).

**What problem it solves / history** — big-ball-of-mud imports (everything importing everything — change blast radius = repo, layer violations discovered in postmortems): layers bounding blast radius (domain changes safe by construction — nothing outer imported; infra changes contained — layers limiting fallout structurally).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), layer at partition scale (3+ partitions — 2.1 references carrying layers; small repos convention-only); enforce with lint (restricted-imports — violations red pre-merge); document layers in domain READMEs (one diagram per partition — 3.2/7.1 boundary style restated as layer maps).

**Runnable example** — inward imports (good vs bad, `tsc --strict`):

```typescript
// good — domain inward-pure (no outer imports — blast radius bounded by construction)
// file: domain/user.ts (inner — imports nothing outer)
export interface User { id: string }
export function isPrivileged(u: User): boolean { return u.id.startsWith("admin:"); } // pure domain (testable without app/infra — layers paying immediately)
console.log(isPrivileged({ id: "admin:1" })); // true — inward purity (domain safe — outer changes never invalidating inner)
// bad — domain importing app (inward violation — app edits invalidating domain caches, blast radius = repo)
// fix — lint-enforced directions (violations red pre-merge — architecture as errors)
```

```typescript
// good — app composing inward (outer knowing inner — dependence explicit, direction lawful)
export interface DomainUser { id: string } // domain shape (inner — defined here for standalone checking; lives in domain/ in real repos)
export interface Session { user: DomainUser; token: string } // app layer (composing domain shapes — lawful dependence, downward only)
declare const s: Session;
console.log(s.token.length > 0 ? "session" : "anon"); // session — lawful composition (outer composing inner — blast radius directed)
// bad — infra types in domain (outer leaking inward — every infra change rippling to domain caches)
// fix — dependency inversion (domain defining ports, infra implementing — 14/3.3 DI thresholds at layer scale)
```

**Common confusion** — "layers slow small teams" — layers *constrain* only violations (legal imports unaffected — friction proportional to architectural breakage, zero otherwise). "lint replaces layer thinking" — lint *enforces* decided layers (thinking first — layer maps drawn, then tooled; unthinking layers linting arbitrary lines). "domain purity impractical" — purity pays at first test (domain suites dependency-free — speed + determinism immediately, scale dividends compounding).

**Performance note** — layering costs nothing at check-time (import direction — same program, ordered thinking); violations cost cache invalidation (outer-tainted inner caches — 2.1 change-rate partitioning defeated by inward leaks).

**Mentor note** — layer-PR review: import arrows drawn (inward-only evidenced — outward arrows rejected with the layer map attached).

### 2) **Barrel discipline at scale** (cycle-surface control, curated vs deep imports)

**Definition** — *barrel discipline* (12/1.1 applied at scale): partition barrels curated (public surface re-exported deliberately — additions reviewed); *cycle-surface* (barrel-to-barrel import potential — curated barrels minimizing cross-partition edges); *deep imports* (`pkg/dist/internal` — bypassing barrels for leaves — allowed where barrels would cycle, banned where barrels suffice — per-partition policy).

**What problem it solves / history** — barrel cycles at scale (5.1 incident 4: "harmless" re-export creating app↔domain cycle — startup crash): curation bounding surface (reviewed additions — cycle-surface minimal by default); deep-import policy handling exceptions (leaves reachable without barrel cycles — escape hatch documented, not hacked).

**Modern guidance** — curate barrels per partition (additions reviewed — public surface deliberate); lint cycle-surface (import-graph checks per 2.1 part 3 — cycles red pre-merge); allow deep imports for leaves (documented policy — barrels for contracts, deep paths for internals where cycles threaten).

**Runnable example** — curated surfaces (good vs bad, `tsc --strict`):

```typescript
// good — curated barrel (surface deliberate — additions reviewed, cycles minimal)
// file: domain/index.ts (barrel — curated: User + guards only, internals unexported)
export interface PublicUser { id: string } // surfaced (deliberate — reviewed addition)
export function isPublic(u: PublicUser): boolean { return u.id.length > 0; } // surfaced (contract — barrel carrying API, not internals)
console.log(isPublic({ id: "u" })); // true — curation paying (surface minimal — cycle-surface bounded by default)
// bad — star-barrels (export * from everything — internals surfaced accidentally, cycles one re-export away)
// fix — curated lists (additions reviewed — surfaces deliberate, cycle-surface minimal)
```

**Common confusion** — "barrels always cycle" — *uncurated* barrels cycle (star-exports surfacing internals — curation preventing, 12/1.1 mechanics). "deep imports are hacks" — deep imports are *policy* (documented leaf access — barrels for contracts, paths for internals; undocumented deep imports the actual hack). "barrel lint slows PRs" — barrel lint reviews *surface changes* (additions — the exact PRs needing architectural eyes anyway).

**Performance note** — barrels add re-export edges (checker-resolvable — dozens trivial; star-barrels multiplying edges × internals — curation bounding graph size too).

**Mentor note** — barrel-PR review: "contract or internal?" (contracts surfaced — internals staying deep; the question keeping surfaces minimal).

### 3) **API-layer typing** (public contracts per partition, surface probes scoped)

**Definition** — *API layers*: per-partition public contracts (types + functions surfaced — versioned per partition, probed per 17/3.2 scoped per reference): consumers depending on contracts (implementations substitutable — fakes per 17/2.2 proving substitutability); *surface probes scoped* (17/3.2 import-from-package probes run per partition — contract moves red per owner).

**What problem it solves / history** — implementation-coupled partitions (consumers importing internals — every refactor breaking strangers): API layers decoupling (contracts stable — implementations churning freely; moves versioned per partition, probed per owner — 17/3.2 break-detection at partition scale).

**Modern guidance** — define API types per partition (public contracts — versioned, probed, documented); test substitutability (fakes implementing contracts — 17/2.2 behavesLike suites per seam); scope probes per reference (moves red per owner — attribution per 1.2 budgets restated for contracts).

**Runnable example** — contracts decoupling (good vs bad, `tsc --strict`):

```typescript
// good — partition contract (public types versioned — implementations substitutable)
export {}; // module marker (consistent module scope across fences)
export interface BillingApi { charge(cents: number): Promise<string> } // contract (versioned — consumers depending, implementations churning)
class FakeBilling implements BillingApi {
  async charge(cents: number): Promise<string> { return `receipt:${cents}`; } // fake proving (substitutability tested — 17/2.2 pattern)
}
const api: BillingApi = new FakeBilling();
console.log(await api.charge(100)); // receipt:100 — contracts decoupling (implementations substitutable — refactors unblocking strangers)
// bad — internal imports across partitions (refactors breaking strangers — coupling by convenience, breakage by surprise)
// fix — API layers (contracts per partition — probed, versioned, substitutable)
```

**Common confusion** — "API layers over-abstract" — layers abstract *stability* (contracts changing slower than implementations — abstraction proportional to consumer count). "probes per partition duplicate" — probes attribute (moves red per owner — shared probes localizing nothing, see 1.2 budgets). "fakes per seam double work" — fakes pay at second implementation (17/2.2 behavesLike economics — contract suites reused, divergence impossible).

**Performance note** — contract layers zero runtime cost (types erased — 01/2.1); probe suites seconds per partition (scoped — full truth on schedule per 2.3).

**Mentor note** — partition review: "contract? probes? fake?" (three artifacts per seam — stability evidenced, not asserted).
