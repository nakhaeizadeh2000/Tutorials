## 5.1. Real production bugs caused by scaling misunderstandings

### 1) **Unbudgeted mapped type took CI from 4 to 47 minutes** (key-count multiplication, carve-out fix)

**Definition** — the incident: a codegen-fed `Normalized<ApiSpec>` (deep mapped type over a 12k-key OpenAPI union — outer keys × inner optionality-removal × 3 conditional layers ≈ 100k+ instantiations per use, used in 40 files): CI check time creeping 4 → 47 minutes over 6 weeks (no single culprit — commons tragedy per 1.2 part 3). Fix: carve-out per 09/3.1 (endpoint-domain slices + `CappedPartial` depth-3) + per-package instantiation budget (growth red with traces — 1.2 part 3 ratchet).

**What problem it solves / history** — unmeasured breadth (keys × layers uncounted — 1.2 arithmetic never done): budgets + carve-outs converting blowups into scoped shapes (slices imported per route — breadth scoped to consumers per 1.3 part 2).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), count keys before fresh mappings (1.2 arithmetic — budgets consulted); split generated unions by domain (1.3 part 2 — slices, not wholes); budget per package (ceilings — growth loud per owner).

**Runnable example** — blowup carved (good vs bad, `tsc --strict`):

```typescript
// good — sliced mapping (domain slices — breadth scoped, counters flat)
export {}; // module marker (consistent module scope across fences)
interface UserApi { id: string; name: string } // slice (domain-scoped — 2 keys, mapped trivially)
type RO<T> = { readonly [K in keyof T]: T[K] }; // homomorphic (fast path — linear per 1.3 part 1)
declare const u: RO<UserApi>;
console.log(u.id); // id — scoped breadth (slices mapped — wholes never distributed)
// bad — whole-spec deep mapping (12k keys × 3 layers × 40 files — 100k+ instantiations per use, CI 4→47 minutes)
// fix — slices + caps + budgets (breadth scoped, depth capped, growth loud — the incident's triple fix)
```

**Common confusion** — "codegen output is free" — codegen output *scales* (key counts × layers — generated breadth budgeted like handwritten, see 1.2). "one big type is simpler" — one big type centralizes *cost* (every consumer paying full breadth — slices distributing cost to users).

**Performance note** — sliced mapping linear per slice (trivial — CI-minutes deleted by scoping); budget gates milliseconds (integer compares — tragedies prevented cheapest).

**Mentor note** — codegen-PR review: key counts quoted (breadth stated — slices required past thousands, budgets attached).

**Cross-links** — carve-out catalog → [3.1. Deep transforms](<../../../09 Utility Types and Type Transformations/sections/3. Transformations in Practice/3.1. Deep transforms DeepPartial DeepReadonly and the budget.md>); instantiation budgets → [1.2. Budgets](<../1. Check-Time Performance/1.2. Instantiation budgets and TS2589 carve-outs.md>).

### 2) **Cyclic project references deadlocked `tsc -b` on release day** (graph unchecked, DAG enforced after)

**Definition** — the incident: `apps` referenced `leaves`, and a "temporary" `leaves`→`apps` reference (shared test helper — convenience over architecture) created a cycle: `tsc -b` deadlocking (ordering uncomputable — 2.1 part 3's prevented class, unprevented: no graph checks in CI). Release blocked 5 hours (cycle discovered in the release pipeline — untangled under pressure, helper duplicated properly postmortem).

**What problem it solves / history** — unchecked graphs (references added without `--dry` proof — cycles landing silently): DAG enforcement converting cycles into pre-merge errors (graph checks per PR — 2.1 part 3 hygiene; `--dry` ordering evidenced like type changes).

**Modern guidance** — graph checks in CI (cycles red pre-merge — DAG enforced, never assumed); `--dry` in reference PRs (ordering proof — 2.1 part 3 review); shared helpers in leaves (direction lawful — test utilities downstream of nobody, see 3.1 layers).

**Runnable example** — DAG enforced (good vs bad, `tsc --strict`):

```text
// good — dry-run proof in reference PRs (ordering evidenced — cycles red pre-merge, never on release day)
// $ tsc -b --dry (labeled CLI doc — prints order; cycles error HERE, at authoring — 5-hour release blocks structurally prevented)
```

```typescript
// good — shared helpers placed downward (leaves owning utilities — direction lawful, cycles unrepresentable)
export {}; // module marker (consistent module scope across fences)
export function sharedId(prefix: string): string { return `${prefix}-1`; } // leaf utility (downstream of nobody — apps importing, never reversed)
console.log(sharedId("t")); // t-1 — lawful placement (helpers in leaves — temporary reversals never landing)
// bad — "temporary" upward references (leaves→apps for one helper — cycle created, deadlock on release day)
// fix — graph CI + helper placement (cycles pre-merge red — temporaries rejected like any other cycle)
```

**Common confusion** — "temporary cycles are harmless" — temporary cycles *ship* (deadlines preserving temporaries — DAG enforced unconditionally, no temporary exceptions). "small graphs need no checks" — small graphs *grow* (checks cheap from day one — 5-hour blocks prevented for milliseconds per PR). "untangling is easy" — untangling under release pressure is not (cycles fixed leisurely pre-merge, painfully on release day — timing dominating difficulty).

**Performance note** — graph checks milliseconds (static — per-PR); deadlocks hours (release-day — prevention ratio astronomical, see 2.1 part 3).

**Mentor note** — "temporary" reference PRs rejected on sight (temporaries shipping — DAG unconditional, exceptions never).

### 3) **Stale `.tsbuildinfo` shipped week-old declarations downstream** (incremental-only CI, clean schedules added)

**Definition** — the incident: incremental-only CI (no clean schedules — 2.2 part 3's prevented class, unprevented) served week-old `leaves` declarations to `apps` builds (config edit unbusting caches — key statically versioned per 2.2's warned-against pattern): downstream compiling against phantom APIs (removed functions "present", new functions "missing" — consumers broken both directions for a week before a clean rebuild exposed the drift).

**What problem it solves / history** — truth never reconciled (incremental green ≠ sources green — poisoning windows unbounded without cadence): clean `--force` schedules bounding windows (nightly truth — 2.2 part 3 triad; divergence alerting proving schedules' worth).

**Modern guidance** — hash-keyed CI caches (lockfile + TS-version + tsconfig — shape changes busting per 2.2 part 3); nightly `--force` full builds (truth cadence — windows ≤24h); divergence alerts (incremental-green + clean-red = poisoning caught — metric justifying schedules).

**Runnable example** — truth reconciled (good vs bad, `tsc --strict`):

```text
// good — nightly force schedule (truth cadenced — poisoning windows bounded, divergence alerted)
// schedule (labeled config doc): nightly `tsc -b --force` (clean truth — incremental green + clean red alerting as poisoning)
// cache key (labeled config doc): hash(lockfile, ts-version, tsconfig**) — shape changes busting, stale unreachable
```

```typescript
// good — cache-bug triage runbook (force distinguishing — one command, seconds)
export {}; // module marker (consistent module scope across fences)
export function truthProbe(): string { return "clean-build-verified"; } // probe (clean schedules verifying — truth reconciled on cadence, not on incident)
console.log(truthProbe()); // clean-build-verified — scheduled truth (poisoning bounded — drift exposed nightly, never weekly)
// bad — incremental-only CI (stale green shipping — week-old declarations downstream, both-directions breakage)
// fix — triad (hash keys + gitignore + schedules — stale unreachable, windows bounded, truth evidenced)
```

**Common confusion** — "clean schedules waste resources" — schedules cost minutes nightly (releases costing far more — 2.2 insurance arithmetic). "force fixes poisoning" — force *reveals* (diagnosis); keys + schedules *prevent* (unreachable + bounded — layers per 2.2 part 3). "phantom errors are flaky tests" — phantom errors are *cache bugs* (`--force` distinguishing in seconds — 2.2 mentor note restated as incident response).

**Performance note** — clean schedules minutes-per-night (amortized insurance); poisoning weeks of phantom APIs (both-directions breakage — most confusing failure class, cheapest prevention).

**Mentor note** — "incremental green + clean red means?" (poisoning — the on-call answer distinguishing cache bugs from real ones instantly).

### 4) **Barrel-cycle crash at startup after a "harmless" re-export** (surface grown silently, lint added)

**Definition** — the incident: `domain/index.ts` adding `export * from "./internal"` ("harmless" — one line, unreviewed barrel change): `internal` importing `app/config` (transitive edge — barrel surfacing a cycle: app→domain→internal→app): runtime cycle (module init order — `undefined` imports at startup, crash on boot, 2-hour outage). Fix: curated barrels (3.1 part 2 — additions reviewed) + cycle lint (graph checks — 2.1 part 3 at barrel granularity).

**What problem it solves / history** — unreviewed surfaces (star-exports surfacing internals — cycle-surface growing silently per 3.1 part 2): curation bounding surface (additions reviewed — deliberate surfaces) + lint bounding cycles (edges checked — crashes pre-merge red).

**Modern guidance** — curated barrel lists (additions reviewed — 3.1 part 2; star-exports banned in barrels); import-graph lint per PR (cycles red — 2.1 part 3); startup smoke tests (boot exercised in CI — cycle crashes caught pre-deploy even when lint misses).

**Runnable example** — surfaces curated (good vs bad, `tsc --strict`):

```typescript
// good — curated barrel (deliberate surface — additions reviewed, cycles bounded)
export {}; // module marker (consistent module scope across fences)
export interface BarrelApi { start(): void } // surfaced (reviewed — contract, not internals)
export function boot(api: BarrelApi): string { api.start(); return "booted"; } // surfaced behavior (deliberate — cycle-surface minimal by default)
console.log(boot({ start() {} })); // booted — curation paying (surfaces deliberate — "harmless" re-exports reviewed as architecture)
// bad — star-barrel additions (export * — internals surfaced, transitive cycles one line away, startup crashes)
// fix — curated lists + graph lint + smoke tests (three layers — surfaces deliberate, cycles red, boots exercised)
```

**Common confusion** — "re-exports can't crash" — re-exports create *edges* (graph edges — cycles via transitivity, init-order crashes at runtime, not check time). "lint catches all cycles" — lint catches *static* cycles (dynamic/lazy cycles escaping — smoke tests backstopping, see 12/3.3 gates philosophy). "small barrels need no review" — small barrels *grow* (additions reviewed from day one — curation habit, not threshold).

**Performance note** — curated barrels bounding graph edges (checker-resolvable graphs staying small — 3.1 part 2's dual dividend: fewer cycles AND faster checks).

**Mentor note** — barrel-diff review: "contract or internal?" (3.1 question restated as incident response — "harmless" re-exports never merging unreviewed again).
