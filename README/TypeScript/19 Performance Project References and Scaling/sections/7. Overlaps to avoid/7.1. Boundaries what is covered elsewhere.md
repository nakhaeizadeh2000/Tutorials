## 7.1. Boundaries — what is covered elsewhere

Scaling work starts with a concrete program, a reproducible workload and a contract to preserve. This domain owns the investigation of checking/build costs and project structure. Use the neighboring owners for configuration semantics, tool interfaces, type behavior and release evidence; a smaller counter or faster command cannot replace those contracts.

Record the actual command and mode before comparing results. The verified current-configuration fixture shows a check-only invocation passing while an emitting invocation exposes an output-layout problem. The native-build fixture in [native build/watch measurements](<../../../25 Update TypeScript 7.0/sections/3. Native Build and Watch/3.1. A result from a different mode or graph is not automatically a performance comparison for the command the team runs.

Configuration changes can alter which errors or sources are visible. Before accepting an apparent improvement, establish that the relevant files and required correctness checks still participate. Keep the option's semantics at its owner rather than repeating a flag catalog in every optimization proposal.

When reporting an optimization, state the original problem, changed representation or graph, correctness checks and comparable measurement. If only local checking was measured, keep deployment, editor and runtime claims outside the result. Follow the existing owner for any additional evidence the decision actually needs.

### 6) **Common confusion**

A failed early check can report a smaller counter than a completed check. A bounded transform can be cheaper while accepting a different contract. Native CLI success does not establish compatibility with a JavaScript compiler API consumer. A clean source check does not prove the output graph or package surface works. These distinctions help explain why an apparently green or faster command can still leave the original problem unresolved.

### 7) **Performance note**

This routing page introduces no runtime operation or new benchmark. Its linked experiments have declared compilers, commands, inputs and limits. Explanation ownership does not divide checker time into independent domain costs, and removing duplicated prose does not imply a measured speedup. Compare equivalent work and distinguish complete checking, failed checking, cache state and artifact consumption before interpreting a result.

### 8) **Mentor note**

Use three cases. First, a TS2589 run reports fewer instantiations than a successful bounded version: route to the measured budget fixture and explain early failure plus the changed stopping contract. Second, a native source check passes but an embedded tool calls an absent createProgram: route to the interface fixture and preserve a supported tool/compiler pairing. Third, a source package checks but its fresh consumer cannot find declarations: route to the artifact assessment and inspect the packed files.

A sound answer identifies the measured operation, the missing evidence and the semantic contract that a proposed fix must preserve. It does not approve a cap solely for a smaller number, treat a tool-loading failure as a type-complexity problem or infer consumer compatibility from a source-only check.
