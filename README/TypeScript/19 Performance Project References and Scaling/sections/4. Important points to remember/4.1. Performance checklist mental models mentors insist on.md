## 4.1. Performance checklist — mental models mentors insist on

### 1) **Measure before cutting** (diagnostics plus traces first, folklore ignored)

**Definition** — the first check: every perf effort opening with diagnostics baselines (1.1 counters) + traces for localization (1.1 bars) + predictions (which counters move, how much) — folklore refactors blocked at review regardless of plausibility (no numbers, no merge).

**What problem it solves / history** — superstition-optimization (quarters vaporized on ±2% churn — 1.1's folklore class): measure-first converting perf into science (hypothesis → numbers → verdict — failed hypotheses reverted per 1.1 part 3).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), perf PRs carrying three artifacts (baseline + prediction + verification — 1.1 template); CI counter budgets (growth loud — 1.2 part 3 ceilings); quarterly trace rituals (top-5 bars, one fix each — 1.1 mentor note).

**Runnable example** — measured effort (good vs bad, `tsc --strict`):

```typescript
// good — counted generic (branches × members stated — arithmetic upfront, counters confirming)
export {}; // module marker (consistent module scope across fences)
type Filter<T, U> = T extends U ? never : T; // 1 conditional (branches: 2 — arithmetic stated in the PR)
type Equal<X, Y> = (<T>() => T extends X ? 1 : 2) extends (<T>() => T extends Y ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
assertType<Equal<Filter<"a" | 1, string>, 1>>(); // 2 evaluations (members: 2 — counted, trivial, merged with numbers)
console.log("counted"); // counted — measure-first (arithmetic stated — counters confirming in CI)
// bad — "generics are slow" PRs (unmeasured avoidance — expressiveness abandoned over dread)
// fix — arithmetic + counters (per-site numbers — fear replaced by math)
```

**Common confusion** — "measurement overhead" — diagnostics ~1–2% (always-on-safe); traces targeted (investigations — cost proportional to insight per 1.1). "small changes exempt" — small changes moving counters most insidiously (budgets catching what reviews cannot — 1.2 part 3).

**Performance note** — measurement directing effort to wide bars (80/20 — folklore effort deleted, net velocity up by quarters).

**Mentor note** — "show me the delta" (perf-review opener — numbers or no review, permanently).

### 2) **Partition by change-rate** (stable leaves, churning apps, references as architecture)

**Definition** — the second check: programs partitioned by change frequency (2.1 — stable leaves referenced by churning apps, DAG direction enforced, composite+declaration mechanics, graph hygiene in CI). References as architecture (build order + cache boundaries + layer carriers — paperwork never, structure always).

**What problem it solves / history** — monolithic rechecks (edit latency = repo size — velocity throttled by redundancy): partitioning converting rechecks into affected-subgraph work (leaves cached — latency proportional to change scope).

**Modern guidance** — partition at 3+ engineers/2k+ files (thresholds — small repos monolithic correctly); coarse first (3–7 projects — splits measured per 1.1); DAG + composite + maps (hygiene triple — order, speed, navigation per 2.1 part 2–3).

**Runnable example** — change-rate layering (good vs bad, `tsc --strict`):

```typescript
// good — stable leaf contract (rarely touched — cached downstream)
export {}; // module marker (consistent module scope across fences)
export interface StableConfig { retries: number } // leaf (stable — quarterly edits, emitted once)
export function withDefaults(c: Partial<StableConfig>): StableConfig {
  return { retries: c.retries ?? 3 }; // leaf logic (checked once — downstream reading declarations per 2.1 part 2)
}
console.log(withDefaults({}).retries); // 3 — stable leaves (emitted once — downstream speed from upstream emit)
// bad — churning code in leaves (daily edits invalidating stable caches — partitioning defeated by placement)
// fix — change-rate placement (stable ← churning imports — invalidation toward stability)
```

**Common confusion** — "partitions are paperwork" — partitions are *cache boundaries* (invalidation scoped — paperwork zero, structure all). "fine splits faster" — reference overhead taxing fine splits (measure before splitting — 1.1 traces deciding, not enthusiasm).

**Performance note** — subgraph rechecks seconds vs monolithic minutes (10×–50× — partitioning's dividend, proportional to stability skew).

**Mentor note** — "draw the graph" (3 boxes minimum — direction arrows mandatory; cycles rejected before discussion).

### 3) **Budget instantiations and program size** (ceilings enforced, growth loud)

**Definition** — the third check: per-package instantiation ceilings (1.2 part 3 — attributed, CI-enforced, ratcheting) + per-project program-size ceilings (3.3 part 1 — files/symbols scoped, bloat loud). Growth loud (red with traces — owners notified, evidence attached); shrinkage updating files down (ratchets living, not stone).

**What problem it solves / history** — commons tragedies (check-time + program-size creeping ownerlessly — 47-minute CIs, 50k-file programs, no single culprit): budgets attributing (which partition grew — owners, traces, evidence — collective resources managed).

**Modern guidance** — ceilings per reference/project (proportional — small tight, large roomy, all explicit); growth PRs with traces (evidence attached — features shipping with numbers); quarterly ratchets (ceilings shrinking with carve-outs — 17/3.3 graduation discipline for perf).

**Runnable example** — attributed ceilings (good vs bad, `tsc --strict`):

```typescript
// good — scoped utility (K-bounded breadth — budget impact stated: |K|)
export {}; // module marker (consistent module scope across fences)
type PickK<T, K extends keyof T> = { [P in K]: T[P] }; // K-scoped (instantiations = |K| — breadth declared at use, budgeted per package)
interface Rec { a: string; b: number; c: boolean }
type Slim = PickK<Rec, "a">; // 1 instantiation (stated — budget impact: 1, approved silently)
declare const s: Slim;
console.log(s.a); // a — budgeted breadth (declared — growth attributed, commons managed)
// bad — unscoped utilities over huge unions (breadth unbudgeted — CI creeping ownerlessly, commons tragic)
// fix — K-scoping + ceilings (breadth declared, growth loud — management by numbers)
```

**Common confusion** — "budgets punish features" — budgets punish *unmeasured* growth (measured growth updating ceilings — features with evidence, see 1.2 part 3). "global budgets suffice" — global hiding attribution (per-package localizing — owners notified).

**Performance note** — budget compares milliseconds (integer compares — cheapest gate); tragedies prevented quarters (47-minute class — highest-ROI check).

**Mentor note** — growth template: feature + trace + budget delta (three artifacts — commons managed with evidence).

**Cross-links** — instantiation budgets → [1.2. Budgets](<../1. Check-Time Performance/1.2. Instantiation budgets and TS2589 carve-outs.md>); editor budgets → [3.3. Editor scale](<../3. Scaling Patterns/3.3. Editor performance at scale budgets and tuning.md>).

### 4) **Cache honestly, verify cleanly** (incremental for speed, clean schedules for truth)

**Definition** — the fourth check: incremental/watch/`-b` modes matched per workflow (2.2 part 2 — speed) + `.tsbuildinfo` gitignored + hash-keyed CI caches (2.2 part 3 — honesty) + clean `--force` schedules (nightly truth — 2.2 part 3) + affected-only PRs with full-schedule truth (2.3 part 3 — velocity with completeness). Both halves, never either-or (speed without truth poisoning; truth without speed throttling).

**What problem it solves / history** — speed-vs-truth false choice (incremental-only poisoning per 17/5.1; clean-only throttling per 2.2): duality done right (fast PRs affected + cached; true repos scheduled + forced — velocity with truth, structurally).

**Modern guidance** — modes per workflow (watch local, `-b` CI, incremental one-shots — 2.2 part 2); hash keys + gitignore (honesty — 2.2 part 3); clean cadences (truth — nightly minimum); affected PRs (velocity — 2.3 part 3).

**Runnable example** — speed with truth (good vs bad, `tsc --strict`):

```typescript
// good — mode-matched development (watch locally — instant; truth on schedule — nightly)
export {}; // module marker (consistent module scope across fences)
export function fastIter(n: number): number { return n + 1; } // edited under watch (re-emit milliseconds — velocity)
console.log(fastIter(1)); // 2 — local speed (modes matched — truth scheduled separately, never skipped)
// bad — incrementals-only CI (stale green shipping — poisoning unbounded, truth never reconciled)
// fix — duality (fast + true — affected PRs, forced schedules, hash keys — all three, always)
```

**Common confusion** — "schedules waste CI" — schedules cost minutes nightly (poisoning costing releases — insurance arithmetic per 2.2 part 3). "affected-only misses" — full schedules catching cross-cutting (scoping for velocity, schedules for completeness — 2.3 part 3 duality).

**Performance note** — incremental seconds (PRs fast); clean minutes nightly (truth amortized — insurance, not overhead).

**Mentor note** — "fast PRs, true repos" (the duality slogan — speed with truth as team norm, tooled in CI).
