## 1.3. Hot-spot discipline mapped conditional and union cost

### 1) **Mapped-type cost control** (homomorphic vs fresh mapping, key-count multiplication)

**Definition** — mapped-type cost = keys × per-key work: *homomorphic* (`{ [K in keyof T]: F<T[K]> }` — key-count linear, checker-optimized fast path) vs *fresh* (`{ [K in K2]: ... }` over remapped/filtered key sets — key computation + mapping, costlier) vs *nested* (mapped-inside-mapped — multiplicative: outer keys × inner keys). Modifier arithmetic (`readonly`/`?` `+`/`-` per 09/1.2) adds constant factors, not multipliers.

**What problem it solves / history** — nested-mapped explosions (`DeepReadonly<ApiResponse>` over 10k-key API unions — outer × inner × depth, CI 4→47 minutes per 5.1): cost control converting blowups into budgeted shapes (homomorphic where possible, carved where not — 09/3.1 carve-outs restated as cost control).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), prefer homomorphic mappings (fast path — `keyof T` iteration); count keys before fresh/remapped mappings (budgets per 1.2 — large sets carved); never nest mappings over large unions without traces (multiplicative costs measured, not hoped).

**Runnable example** — linear vs multiplicative (good vs bad, `tsc --strict`):

```typescript
// good — homomorphic fast path (key-count linear — checker-optimized)
interface Small { a: string; b: number } // 2 keys (mapped cost = 2 — trivial by arithmetic)
type RO<T> = { readonly [K in keyof T]: T[K] }; // homomorphic (fast path — linear, unbudgeted-safe)
declare const s: RO<Small>;
console.log(s.a); // a — cheap mappings (homomorphic over small keys — diagnostics confirming trivial)
// bad — nested mappings over huge unions (outer × inner × depth — multiplicative blowups, CI-minutes)
// fix — homomorphic-first (fast paths default — fresh/nested measured with traces per 1.1)
```

```typescript
// good — modifier arithmetic as constants (plus/minus factors — additive, not multiplicative)
type Mutable<T> = { -readonly [K in keyof T]: T[K] }; // minus-modifier (constant factor — cost ≈ plain mapping)
interface M { readonly x: number }
declare const m: Mutable<M>;
console.log(m.x); // x — modifier costs (additive constants — modifiers never the blowup; keys are)
// bad — blaming modifiers for key-count blowups ("-readonly is slow" folklore — 10k keys slow, modifiers innocent)
// fix — count keys (blowups keyed by key-count — modifiers acquitted by arithmetic)
```

**Common confusion** — "mapped types are slow" — *large/nested* mappings are slow (keys × depth — small homomorphic mappings trivial; the 1.1 folklore class restated). "modifiers multiply cost" — modifiers add constants (plus/minus arithmetic — key-count dominating by orders of magnitude). "fresh mappings equal homomorphic" — fresh key-sets compute keys first (extra evaluation — homomorphic fast-pathed, fresh measured).

**Performance note** — homomorphic ≈1 instantiation/key (linear — thousands fine); nested ≈ product (10k × 100 = millions — budgeted/carved, never hoped).

**Mentor note** — mapping review: "homomorphic? key count?" (two questions — fast-path confirmed, keys counted — merged).

### 2) **Union-size discipline** (distribution costs, splitting, indexing, caching)

**Definition** — union costs: *distribution* (naked conditional over N members = N evaluations per 09/2.1); *discriminant narrowing* (cheap — literal comparisons, no instantiation); *exhaustive switches* over huge unions (per-member control-flow analysis — linear, usually fine); *union-indexed mapped types* (`{ [K in Union]: ... }` — N instantiations — the 10k-member API-union blowup class). Controls: splitting (sub-unions per module), indexing (Record lookups replacing distribution), caching (named aliases per 1.1 part 1).

**What problem it solves / history** — generated mega-unions (OpenAPI codegen emitting 10k-member string unions distributed through 3 conditional layers — 30k+ evaluations per use, CI-minutes): splitting by endpoint domain (sub-unions imported per route — breadth scoped), indexed access replacing distributive filters (lookup O(1) vs distribution O(N)).

**Modern guidance** — split generated unions by domain (per-module sub-unions — breadth scoped to consumers); replace distributive filtering with indexed lookups where shapes allow (`Table[K]` beats `Extract<Union, ...>` at scale — O(1) vs O(N)); name and reuse large unions (one instantiation site — cache hits downstream per 1.1).

**Runnable example** — breadth scoped (good vs bad, `tsc --strict`):

```typescript
// good — split unions per domain (breadth scoped — consumers importing slices)
type UsRoutes = "/us/a" | "/us/b"; // sub-union (domain slice — 2 members, distribution trivial)
type EuRoutes = "/eu/a" | "/eu/b"; // sub-union (slice — breadth scoped to importers)
function usLabel(r: UsRoutes): string { return r.toUpperCase(); } // narrow distribution (2 evaluations — scoped)
console.log(usLabel("/us/a")); // /US/A — split breadth (domains sliced — mega-unions never distributed whole)
// bad — mega-union distributed whole (10k members × 3 layers — 30k evaluations per use, CI-minutes)
// fix — split by domain (slices imported — breadth scoped to consumers, never global)
```

```typescript
// good — indexed lookup replacing distribution (O(1) access — breadth unbothered)
interface Handlers { a: () => string; b: () => string } // table (keys finite — lookup replacing filter)
type Get<K extends keyof Handlers> = Handlers[K]; // indexed (O(1) — no distribution, no per-member evaluation)
declare const h: Get<"a">;
console.log(h()); // handler — lookups over tables (breadth-irrelevant cost — indexed access scaling flat)
// bad — Extract over mega-unions per call site (O(N) distributions — per-use breadth costs, caches missing)
// fix — tables + indexed access (lookup shapes — distribution reserved for genuinely-conditional logic)
```

**Common confusion** — "unions are cheap" — *narrow* unions cheap (discriminants, switches — linear small); *mega*-unions distributed expensively (N evaluations per naked conditional — breadth priced per use). "splitting loses exhaustiveness" — split unions rejoin at boundaries (`UsRoutes | EuRoutes` — exhaustiveness over the join preserved, distribution over slices cheap). "indexed access always wins" — indexed needs *tables* (finite key sets — genuinely-conditional logic still distributing, correctly).

**Performance note** — distribution O(members × layers) per use (10k × 3 = 30k — budgeted per 1.2); indexed O(1) (flat — tables scaling free); splitting divides N per consumer (breadth scoped — sums, not products).

**Mentor note** — codegen review: generated unions arrive split (per-domain files — mega-union files rejected like mega-functions).

### 3) **Hover-budget readability** (display types vs computation types, restraint)

**Definition** — *hover budget*: the cognitive + tooling cost of expanded types (10k-character hovers slowing editors, reviewers, and `tsc` pretty-printing — 16/1.3 hover discipline restated as cost control). *Display types* (named aliases, `NoInfer`-style pins — hovers showing intent) vs *computation types* (deeply-nested conditionals expanding in every tooltip — precision nobody reads). Restraint: alias early, expand never in public positions.

**What problem it solves / history** — tooltip-hell codebases (hovers spanning screens — onboarding impossible, editor completions lagging on pretty-printing): named aliases restoring readability (hovers showing `Status` not 40-line expansions — comprehension at a glance, tooling unloaded).

**Modern guidance** — alias public/returned types (named — hovers intent-labeled); keep computations internal (helpers unexported — expansion contained); measure hover cost via editor latency (16/3.1 responsiveness triage — pretty-printing as a profiled cost, not an aesthetic gripe).

**Runnable example** — readable hovers (good vs bad, `tsc --strict`):

```typescript
// good — named alias at the boundary (hover shows Status — intent, not expansion)
export {}; // module marker (consistent module scope across fences)
type Status = "active" | "suspended"; // named (hover: Status — one word, full meaning)
export function current(): Status { return "active"; } // alias return (display type — computation hidden)
console.log(current()); // active — readable hovers (reviewers glancing — tooling unloaded)
// bad — 40-line expansions in public returns (hovers spanning screens — comprehension impossible, completions lagging)
// fix — alias boundaries (names at exports — expansions internal, hovers budgeted)
```

**Common confusion** — "precision requires expansion" — precision requires *correctness* (aliases equally precise — names abbreviating without losing meaning). "hover cost is cosmetic" — pretty-printing costs editor latency (16/3.1 profiled — wide hovers slowing completions measurably). "aliases hide information" — aliases *label* information (jump-to-definition revealing — one hop to full detail, zero hops to intent).

**Performance note** — pretty-printing wide types costs milliseconds per hover/completion (editor latency — 16/3.1 triage measuring); aliases one identifier (free — readability AND tooling winning).

**Mentor note** — export review: "would I read this hover?" (no → alias — readability as a merge criterion, not a nit).
