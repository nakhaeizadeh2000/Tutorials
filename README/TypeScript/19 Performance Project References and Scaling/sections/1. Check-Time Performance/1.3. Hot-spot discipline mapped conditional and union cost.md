## 1.3. Hot-spot discipline mapped conditional and union cost

An expensive type relationship is a hypothesis to investigate, not a reason to replace every mapped or conditional type. Locate the actual checking work, define the contract that must remain valid, and compare candidate representations. A simpler-looking declaration can change optionality, accepted variants or inference even when it compiles faster.

Use **TypeScript 7.0.2** and **Node.js 20.20.2**, verified 2026-10-17. The complete fixture below checks contracts and actual constructed values. It does not measure which representation is faster or promise a checker-complexity class.

### 1) **Preserve semantics before changing a mapped form**

A generic mapping over keyof T can preserve source modifiers and special array/tuple structure. A newly constructed key set can produce different required or writable properties. These are semantic distinctions; they are not a proof of one reported instantiation per property, constant-cost modifiers, or a universal homomorphic fast-path ranking. The [mapping foundations](<../../../09 Utility Types and Type Transformations/sections/1. Mapped Types/1.1. Mapped type fundamentals homomorphic mapping over keys.md>) and [modifier owner](<../../../09 Utility Types and Type Transformations/sections/1. Mapped Types/1.2. readonly and optional modifiers with plus and minus.md>) own those details.

In the fixture, Mirror<Config> retains readonly id and optional retries. Fresh uses a literal key union and indexed property values: it requires retries and permits id writes. The value type of retries includes undefined, but a required property containing undefined is different from a property that may be omitted. Replacing Mirror with Fresh would therefore alter this API before any performance claim is considered.

Save:

```typescript
// file: shapes.mts
interface Config { readonly id: string; retries?: number }
type Mirror<T> = { [K in keyof T]: T[K] };
type Fresh = { [K in "id" | "retries"]: Config[K] };
export const mirrored: Mirror<Config> = { id: "source" };
export const fresh: Fresh = { id: "fresh", retries: undefined };
fresh.id = "changed";
// mirrored.id = "changed";
// const missing: Fresh = { id: "fresh" };

export interface Events {
  login: { kind: "login"; user: string };
  logout: { kind: "logout"; reason: string };
}
export type Event = Events[keyof Events];
export type FromUnion<K extends Event["kind"]> = Extract<Event, { kind: K }>;
export type FromTable<K extends keyof Events> = Events[K];
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type Login = Expect<Equal<FromUnion<"login">, FromTable<"login">>>;
type Both = Expect<Equal<FromUnion<keyof Events>, FromTable<keyof Events>>>;
type Selected = Expect<Equal<FromTable<"login">, { kind: "login"; user: string }>>;
export function login(user: string): FromTable<"login"> { return { kind: "login", user }; }
// const wrong: FromTable<"login"> = { kind: "logout", reason: "bye" };
// type MissingKey = FromTable<"missing">;

export type Status = "active" | "suspended";
export function current(): Status { return "active"; }
```

Compile with `tsc --strict --exactOptionalPropertyTypes --target es2022 --module nodenext --declaration --outDir dist shapes.mts`. The three alias-only gates check selected relationships without calling a nonexistent assertion helper. Uncomment each negative independently: the readonly write, missing required property, wrong event and invalid table key should all fail checking. Restore them before running the positive fixture.

### 2) **Compare a union filter with an indexed representation**

FromUnion selects variants by a discriminant. FromTable looks up the corresponding type in an explicit event table. For this finite table, the gates establish matching results for login and for both keys, plus the precise selected payload. The ordinary login function returns a real object; declaring its result type would not create that object by itself.

Changing FromTable to Events[keyof Events] loses the key-to-payload relationship: the selected Login gate catches the widened result. This is why a candidate representation needs probes for relevant keys and boundaries before its timing is compared. The [conditional-law owner](<../../../09 Utility Types and Type Transformations/sections/2. Conditional Types/2.1. Conditional fundamentals distributive law and never branches.md>) explains distribution. This lesson applies that knowledge to a concrete alternative rather than reteaching every conditional form.

Do not label one expression O(1) and the other O(N) from surface syntax alone. Checker work includes constructing, reducing and relating types, demand-driven evaluation, reuse and library work. A table lookup can still involve a large union key. Splitting source into modules also does not automatically isolate checking work if consumers import and recombine the same graph. Narrower model boundaries can be useful when callers truly need less information; dropping supported variants is a contract change.

The [primary performance guide](https://github.com/microsoft/TypeScript/wiki/Performance#writing-easy-to-compile-code) presents candidate changes for complex types, unions and naming, explicitly allowing exceptions. Its naming example explains an opportunity for more compiler reuse, not a guarantee that every alias is computed once. Reproduce the actual expensive relationship with the [diagnostics and trace workflow](<./1.1. Measuring with extendedDiagnostics and traces.md>), then compare successful checks of equivalent required contracts.

Save this actual consumer and run `node verify.mjs` after compilation:

```javascript
// file: verify.mjs
import assert from "node:assert/strict";
import { readFileSync } from "node:fs";
import { mirrored, fresh, login, current } from "./dist/shapes.mjs";
assert.deepEqual(mirrored, { id: "source" });
assert.equal(Object.hasOwn(mirrored, "retries"), false);
assert.deepEqual(fresh, { id: "changed", retries: undefined });
assert.equal(Object.hasOwn(fresh, "retries"), true);
assert.deepEqual(login("Ada"), { kind: "login", user: "Ada" });
assert.equal(current(), "active");
const declarations = readFileSync("dist/shapes.d.mts", "utf8");
assert.match(declarations, /export declare function current\(\): Status;/);
assert.match(declarations, /export type Status = "active" \| "suspended";/);
console.log("mapping presence, event payload and named declaration passed");
```

The final message confirms the value/presence assertions and the emitted declaration check. As a deliberate behavioral mutation, return a different user string from login without changing its type. Compilation still passes; the consumer fails. Static shape agreement is one part of the contract, not a substitute for behavior.

### 3) **Name a contract without promising a particular hover**

A meaningful alias can communicate domain intent and let readers find one definition. An annotation can also keep declaration output from exposing an unintentionally large inferred implementation detail. In the fixture, current explicitly returns Status, and the consumer inspects that emitted declaration. This is declaration evidence, not an observation of a hover UI or its latency.

A language server may display a name, an expansion or an abbreviation depending on context. Naming a helper does not ensure its computation disappears, and making a helper unexported does not ensure dependent public declarations never expose or require it. The [actual hover/signature fixture](<../../../16 Tooling Language Server and Ecosystem/sections/1. Language Server in Practice/1.3. Inlay hints hover and signature help.md>) separates displayed information from source contracts and compiler checks.

NoInfer is an inference-control utility, not a general display abbreviation or performance switch. The [inference owner](<../../../08 Generics Deep Dive/sections/1. Generic Fundamentals/1.2. Inference from arguments and explicit type arguments.md>) demonstrates competing candidates and its accepted/rejected calls. Adding it merely to shorten a tooltip can change what callers can infer.

When a hover or completion is actually slow, reproduce that particular request and program. A CLI phase timing cannot certify that request's latency. Readability remains a valid reason to choose a clear name, provided the explanation does not claim a measured speed improvement that was never tested.

### 4) **Common confusion**

Key count suggests possible breadth but is not the compiler's reported instantiation formula. A depth cap can still involve broad data and changes the contract where it stops; the [budget owner](<./1.2. Instantiation budgets and TS2589 carve-outs.md>) tests that consequence. Similarly, a union filter and a table lookup only match when their definitions preserve the same relationships.

Aliases are useful names, not automatic zero-cost display or cache guarantees. All type-only mappings erase, while the constructed objects, assignments and function calls in the fixture remain real JavaScript. Ambient declarations would describe values without supplying implementations, so they are inappropriate substitutes for this runtime demonstration.

### 5) **Performance note**

This fixture verifies semantics and declaration output, not a speed ranking. For a reported hot spot, pin the compiler, options and input graph; verify correctness; inspect actual diagnostic/trace evidence; and time comparable successful commands separately. A tiny example's short duration or library-dominated counter cannot justify a universal rule about mapped, indexed or conditional types. Keep broader measurement and budget tooling in its canonical owners.

### 6) **Mentor note**

Ask the learner whether Mirror<Config> and Fresh can be exchanged without changing accepted values or writes. Then ask why both event selection methods match in this table and which gate detects ignoring K. A sound answer demonstrates the changed relationships before discussing speed. For a proposed alias-only performance fix, request the actual slow operation and comparable measurements while retaining any separate readability benefit.
