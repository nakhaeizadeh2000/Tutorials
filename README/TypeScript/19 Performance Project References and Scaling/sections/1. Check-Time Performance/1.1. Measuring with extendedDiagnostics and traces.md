## 1.1. Measuring with extendedDiagnostics and traces

### 1) **`--extendedDiagnostics` reading** (files symbols types instantiations, signal vs noise)

**Definition** — `tsc --extendedDiagnostics` prints program counters: `Files`, `Lines`, `Identifiers`, `Symbols`, `Types`, `Instantiations`, plus phase timings (`Check time`, `Emit time`) and cache statistics (`Assignments/assignability cache size/hits`). Signal counters: `Instantiations` (type-level work volume), `Types` (distinct types materialized), `Check time` (wall-clock truth); noise: `Lines`/`Identifiers` (scale context, not cost drivers).

**What problem it solves / history** — "tsc is slow" folklore (optimization by superstition — splitting files, banning generics, `--skipLibCheck` cargo-culting — each "fix" unmeasured, most counterproductive): diagnostics convert complaints into counters (instantiations concentrated? assignability cache missing? phases dominated by check vs resolve?), routing effort to the measured 5% instead of the imagined 95%.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), record diagnostics baselines per repo (CI artifact — counters tracked like bundle sizes); compare before/after every perf refactor (numbers, not feelings — the refactor justified by deltas); read `Instantiations` first (type-computation volume — 1.2 budgets), `Check time` second (wall truth), cache-hit rates third (reuse health).

**Runnable example** — counters guiding effort, shown as annotated CLI docs plus type fences (good vs bad, `tsc --strict`):

```typescript
// good — instantiation-light transform (measured shape — counters staying flat)
// A mapped type over a 3-key object: 3 instantiations (linear — the cheap case, see 1.3 for the expensive one)
interface Cfg { a: string; b: number; c: boolean }
type ReadonlyCfg = { readonly [K in keyof Cfg]: Cfg[K] }; // 3 instantiations (one per key — linear, unbudgeted-safe)
const cfg: ReadonlyCfg = { a: "x", b: 1, c: true };
console.log(cfg.a); // x — light transforms (key-count linear — diagnostics confirming trivial cost)
// bad — optimizing light transforms (rewriting 3-key mappings "for performance" — effort on noise, hot spots untouched)
// fix — diagnostics first (counters routing — 3 instantiations never the problem; millions are)
```

```text
// good — diagnostics baseline command (measured, recorded, compared)
// $ tsc --extendedDiagnostics --noEmit > perf-baseline.txt (labeled CLI doc — counters artifact, CI-tracked)
// Files: 1240, Types: 89312, Instantiations: 412007, Check time: 8.2s (example numbers — YOUR counters differing)
// (refactor PRs attaching before/after deltas — numbers justifying, folklore ignored)
```

```typescript
// good — cache-friendly repetition (identical instantiations reused — assignability cache hitting)
type Box<T> = { value: T };
function wrap(s: string): Box<string> { return { value: s }; } // Box<string> instantiated once (cache hit on repeat — reuse health)
function wrap2(s: string): Box<string> { return { value: s }; } // same instantiation (cache serving — counters flat across call sites)
console.log(wrap("a").value, wrap2("b").value); // a b — reuse healthy (identical types computed once — cache counters confirming)
// bad — structurally-duplicated mega-types (10k-line unions re-instantiated per use — cache missing, counters exploding)
// fix — named aliases reused (one instantiation, N references — cache hits by construction)
```

**Common confusion** — "fewer files means faster" — check time follows *instantiations*, not files (one file with a million-instantiation mapped type beats a thousand trivial files — counters, not globs). "`--skipLibCheck` fixes slowness" — skips *declaration* checking (helps lib-heavy programs marginally; hides real errors — 13/3.3's warning restated; measure first, skip deliberately). "diagnostics slow the build" — diagnostics *report* (counters collected during normal checking — overhead negligible; `--generateTrace` heavier, see part 2).

**Performance note** — diagnostics overhead ~1–2% (counter increments — always-on-safe for baselines); trace generation heavier (file I/O per event — targeted runs, not every build).

**Mentor note** — perf-review opener: "show me the diagnostics delta" (no numbers, no review — the sentence ending folklore-optimization permanently).

### 2) **`--generateTrace` flame analysis** (hot files costing 80 percent)

**Definition** — `tsc --generateTrace traceDir` emits chrome-trace-compatible events (check durations per file/symbol, `checkSourceFile` spans, `resolveModuleName` costs): opened in `edge://tracing`/`chrome://tracing` or `Perfetto` (flame charts — wide bars = hot files, the 80/20 made visible). Analysis target: the widest bars (files/symbols dominating wall time — optimization candidates in rank order).

**What problem it solves / history** — aggregate-only numbers (8.2s check time — *where*? diagnostics totals hiding distribution): traces localize (3 files of 1240 costing 6s — barrel re-exports, mega-unions, deep generics made visible as wide bars), converting "slow repo" into "3 files to fix" (effort concentrated, payoff immediate).

**Modern guidance** — trace on demand (slow-CI investigations, quarterly perf reviews — not every build); fix in bar order (widest first — rank-ordered effort, diminishing returns respected); re-trace after fixes (bars shrinking — verification, not hope; traces as before/after evidence in perf PRs).

**Runnable example** — hot-file thinking, shown as CLI docs plus a union-cost fence (good vs bad, `tsc --strict`):

```text
// good — trace command and reading order (targeted, rank-ordered, verified)
// $ tsc --generateTrace ./trace --noEmit (labeled CLI doc — trace dir artifact, opened in Perfetto)
// reading: widest checkSourceFile bars first (files) → widest checkExpression bars (symbols) → fix → re-trace
// (3 files of 1240 costing 6s of 8.2s — effort concentrated where bars are widest)
```

```typescript
// good — narrow hot union (trace-identified wide bar — split, indexed, cached per 1.3)
type Small = "a" | "b" | "c"; // 3 members (narrow — distribution cheap, see 09/2.1)
function label(s: Small): string { return s.toUpperCase(); } // cheap distribution (3 branches — trace bars thin)
console.log(label("b")); // B — narrow unions (hot-file fixes starting with member counts — splitting per 1.3)
// bad — "optimize the 1237 thin files" (effort on noise — wide bars untouched, wall time unmoved)
// fix — bar order (widest first — rank-ordered fixes, re-traced verification)
```

**Common confusion** — "traces replace diagnostics" — diagnostics *quantify* (counters — what kind of work); traces *localize* (bars — where the work is) — complementary, used together (counters first, bars second). "trace every build" — traces cost I/O + analysis time (targeted runs — investigations and reviews, not pipelines). "wide bars mean bad code" — wide bars mean *expensive* code (sometimes justified — central domain models; budgets per 1.2 deciding, not bar width alone).

**Performance note** — trace generation adds seconds + hundreds of MB (event volume — targeted use; `traceDir` gitignored, CI-artifacted on perf jobs only).

**Mentor note** — quarterly ritual: trace, top-5 bars, one fix each (compounding 80/20 — check times ratcheting down like test baselines per 17/3.3).

### 3) **Measure-first discipline** (baselines before refactors, numbers not folklore)

**Definition** — *measure-first*: no perf refactor merges without (a) baseline diagnostics/trace (before numbers), (b) predicted counter movement (which counters, by how much, why), (c) post-change verification (after numbers matching prediction — or revert). Folklore ("generics are slow", "interfaces beat types" — unmeasured claims) blocked at review regardless of plausibility.

**What problem it solves / history** — folklore refactors (quarter-long "perf migrations" moving wall time ±2% — effort vaporized, code churned, morale taxed): measure-first converting perf work into science (hypothesis → numbers → verdict — failed hypotheses reverted, not shipped as "probably helping").

**Modern guidance** — perf PR template: baseline attachment + prediction + verification (three artifacts — review checking all three); revert unpredicted outcomes (neutral-or-worse deltas reverted — churn without payoff deleted); track counters in CI (17/3.3-style baselines for `Instantiations`/`Check time` — growth loud, drift blocked).

**Runnable example** — disciplined numbers (good vs bad, `tsc --strict`):

```typescript
// good — alias reuse with measurable effect (named types computed once — counters evidencing)
type Status = "active" | "suspended"; // named (one instantiation — N references reusing, see part 1 caches)
function isActive(s: Status): boolean { return s === "active"; } // reuse (cache hits — counters flat per call site)
function describe(s: Status): string { return isActive(s) ? "on" : "off"; } // reuse again (same instantiation — cache serving)
console.log(describe("active")); // on — measured reuse (diagnostics evidencing — hypothesis verified, not assumed)
// bad — folklore refactors ("type→interface for speed" without numbers — churn without payoff, shipped as probably-helping)
// fix — measure-first template (baseline + prediction + verification — science, not superstition)
```

```jsonc
// good — CI counter budgets (growth loud — perf drift blocked like type drift)
// perf-budget.json (labeled config doc — CI compares, blocks growth):
// { "checkSeconds": 12, "instantiations": 500000, "updated": "2026-09-01" }
// CI rule: current <= budget (grow → red with trace attached; shrink → PR updates the file down)
```

**Common confusion** — "measurement slows velocity" — measurement *directs* velocity (effort on wide bars — folklore effort deleted, net velocity up by quarters). "small PRs exempt" — small PRs move counters most insidiously (one mapped type × 10k keys — budgets catching what reviews cannot). "budgets freeze design" — budgets freeze *unmeasured growth* (intentional growth updating budgets with traces attached — evolution with evidence).

**Performance note** — measurement overhead diagnostics-negligible + trace-targeted (always-on counters, on-demand traces — cost proportional to insight).

**Mentor note** — team norm: "numbers or it didn't happen" (perf claims without counters closed as folklore — kindness as rigor).
