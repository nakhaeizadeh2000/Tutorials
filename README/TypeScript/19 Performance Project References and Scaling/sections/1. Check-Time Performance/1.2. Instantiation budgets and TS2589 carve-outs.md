## 1.2. Instantiation budgets and TS2589 carve-outs

### 1) **Instantiation counting** (conditional mapped infer evaluations, measured not guessed)

**Definition** — one *instantiation* = one evaluation of a generic type with concrete arguments (conditional branch taken, mapped-type key pass, `infer` binding, intrinsic application — 08/09 mechanics each ticking the counter). Depth = nesting level (recursion counting down toward the `TS2589` limit, default 100... precisely: `instantiationDepth` limit with `TS2589: Type instantiation is excessively deep and possibly infinite` tripping past it).

**What problem it solves / history** — "complex types are slow" hand-waving (effort scattered — developers avoiding all generics instead of the 2% that recurse): counting localizing cost to *evaluations* (which conditional over which union size, which mapped type over how many keys — per-site arithmetic replacing global fear).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), estimate instantiations per new generic (branches × union members × keys — back-of-envelope before merge); measure via diagnostics after (counters confirming estimates — 1.1 discipline); budget per package (ceilings in CI — part 3's `perf-budget.json` extended with instantiation caps).

**Runnable example** — counting by arithmetic (good vs bad, `tsc --strict`):

```typescript
// good — linear instantiation shape (branches × members small — arithmetic favorable)
type NoNull<T> = T extends null ? never : T; // 1 conditional (per instantiation — branches: 2, members: counted per use)
type Equal<X, Y> = (<T>() => T extends X ? 1 : 2) extends (<T>() => T extends Y ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
assertType<Equal<NoNull<string | null>, string>>(); // 2 member-evaluations (union of 2 — linear, trivial)
console.log("linear"); // linear — counted cost (2 evaluations — arithmetic done, trivial confirmed)
// bad — generic fear (avoiding all conditionals "for performance" — expressiveness abandoned over unmeasured dread)
// fix — per-site arithmetic (branches × members × keys — numbers, not fear, deciding)
```

```typescript
// good — key-count-aware mapping (keys counted before mapping — budgets consulted)
interface Flags { a: boolean; b: boolean } // 2 keys (mapped cost = 2 instantiations — counted upfront)
type Mutable<T> = { -readonly [K in keyof T]: T[K] }; // homomorphic (key-count linear — 09/1.1 mechanics, cheap by arithmetic)
declare const f: Mutable<{ readonly a: boolean; readonly b: boolean }>;
console.log(f.a); // true — key-count discipline (small unions mapped freely — large ones budgeted per part 3)
// bad — 10k-key mappings uncounted (API-response unions mapped wholesale — millions of instantiations, CI from 4 to 47 minutes per 5.1)
// fix — count keys first (large key sets carved per 09/3.1 — mapping budgeted, not hoped)
```

**Common confusion** — "instantiations equal lines of type code" — instantiations equal *evaluations* (one generic × N uses = N instantiations — reuse via named aliases per 1.1 part 1). "depth equals cost" — depth limits *recursion* (TS2589 — part 2); breadth (union members × keys) usually dominates wall time (wide, not deep, costing most). "counting requires tooling" — back-of-envelope suffices (branches × members × keys — estimates within 2×, enough for budgeting).

**Performance note** — counting costs nothing (arithmetic at authoring); uncounted breadth costs CI-minutes (millions of evaluations — the 5.1 incident arithmetic).

**Mentor note** — generic-review: "branches × members × keys?" (one arithmetic question — estimates stated in the PR, counters confirming in CI).

### 2) **`TS2589` depth-limit diagnosis** (excessively deep instantiations, fix ladder)

**Definition** — `TS2589` fires when instantiation *depth* exceeds the limit (default 100 — deeply-nested/recursive evaluation, usually runaway recursion or accidental exponential breadth-at-depth): the checker *stops* (returning `any` at the hot site — correctness degrading silently past the error). Fix ladder: (1) cap recursion (tuple-counter per 08/3.2), (2) carve out special cases (Date/functions/Maps per 09/3.1), (3) scope narrowing (fewer members/keys through the recursion).

**What problem it solves / history** — `DeepPartial<T>` over recursive domain models (company → departments → teams → members → ... — depth unbounded, TS2589 at 3am CI): the ladder converting a cryptic error into ordered fixes (cap → carve → scope — each step shrinking depth measurably, see 09/3.1's `CappedPartial` pattern).

**Modern guidance** — read TS2589 as *depth* (recursion/capping question — not breadth; breadth slows without erroring); climb the ladder in order (cap first — cheapest; carve second — surgical; scope third — contractual); probe capped shapes (17/3.1 boundary discipline — `never`/`unknown` inputs through capped generics pinned).

**Runnable example** — ladder applied (good vs bad, `tsc --strict`):

```typescript
// good — capped recursion (depth bounded — TS2589 structurally impossible)
type CappedPartial<T, Seen extends 0[] = []> = Seen["length"] extends 5 ? T : T extends object
  ? { [K in keyof T]?: CappedPartial<T[K], [...Seen, 0]> } // depth counted (tuple-counter per 08/3.2 — 5 levels max, then identity)
  : T; // (09/3.1 pattern restated as the cap fix — ladder step 1)
interface Org { name: string; child?: Org }
type SafeOrg = CappedPartial<Org>; // bounded (depth ≤5 — checker terminating, quickly)
declare const o: SafeOrg;
console.log(o.name); // name? — capped shapes (depth budgeted — deep models terminating by construction)
// bad — unbounded DeepPartial over recursive models (depth infinite — TS2589 + silent any past the error)
// fix — ladder in order (cap → carve → scope — each step measured via diagnostics per 1.1)
```

```typescript
// good — carve-outs for opaque leaves (Date/functions excluded — recursion stopping at leaves)
type Smart<T> = T extends Date | ((...a: never[]) => unknown) ? T // carve-out (opaque leaves untouched — ladder step 2, see 09/3.1)
  : T extends object ? { [K in keyof T]?: Smart<T[K]> } : T;
interface Event { at: Date; meta: { tag: string } }
type SmartEvent = Smart<Event>; // Date carved (no recursion into Date internals — depth saved where it matters)
declare const e: SmartEvent;
console.log(e.meta?.tag); // tag? — carved recursion (leaves opaque — depth spent on domain shapes, not stdlib internals)
// bad — recursing into Date/Map/Promise internals (depth wasted — stdlib shapes exploding key counts at depth)
// fix — carve lists (opaque-by-construction leaves — recursion stopping where semantics stop)
```

**Common confusion** — "TS2589 means infinite types" — TS2589 means *depth exceeded* (often finite-but-deep — 200-level legitimate nesting tripping a 100-limit; caps/scopes fixing without redesign). "raising the limit fixes it" — flag-raising (`instantiationDepth`) delays (depth growing past any limit — ladder fixing structure, flags buying time; document raised limits with traces). "any past TS2589 is fine" — post-TS2589 `any` infects silently (03/2.1 mechanics — the error's shadow cost exceeding its noise).

**Performance note** — caps convert depth-overflow into constant work (5 levels — terminates fast); carve-outs prune subtrees (Date/Map branches deleted — depth saved multiplicatively).

**Mentor note** — TS2589 review: "cap, carve, or scope?" (ladder order — cap-first answers merging fastest; scope-change answers needing contract review).

### 3) **Budgeting per boundary** (instantiation ceilings per package, CI-enforced)

**Definition** — *instantiation budgets*: per-package ceilings on `Instantiations`/`Types` counters (17/3.3-style ratchets for check-time — current ≤ budget, growth red with traces attached, shrinkage updating the file down). Boundaries = packages/partitions (2.1 references — budgets per reference, hot spots localized to owners).

**What problem it solves / history** — tragedy-of-the-commons check times (every team adding "one more mapped type" — CI creeping 4→47 minutes with no single culprit): budgets attributing growth (which partition grew — owners notified, traces attached — collective resource managed like bundle size).

**Modern guidance** — budget per reference (ceilings proportional to partition size — small packages tight, large packages roomy, all explicit); review budget-growth PRs with traces (growth justified by features — evidence attached, folklore rejected); ratchet down quarterly (ceilings shrinking with carve-outs — 17/3.3 graduation discipline for perf).

**Runnable example** — budgets attributing (good vs bad, `tsc --strict`):

```typescript
// good — budgeted utility (narrow generic — counter impact stated in the PR)
type Pick2<T, K extends keyof T> = { [P in K]: T[P] }; // scoped mapping (K-bounded — instantiations = |K|, stated upfront)
interface User { id: string; name: string; email: string; age: number }
type Public = Pick2<User, "id" | "name">; // 2 instantiations (K of 2 — budget impact: 2, approved silently)
declare const u: Public;
console.log(u.id); // id — budgeted generics (K-scoped — breadth declared at the use site, not discovered in CI)
// bad — unscoped utilities over huge unions (Pick over 10k-member API unions — breadth unbudgeted, CI creeping ownerlessly)
// fix — K-scoped picks + per-package ceilings (breadth declared, growth attributed — commons managed)
```

```jsonc
// good — per-package budgets (attributed ceilings — growth loud per owner)
// perf-budget.json (labeled config doc — per-reference ceilings):
// { "packages/api": { "instantiations": 80000 }, "packages/app": { "instantiations": 300000 } }
// CI rule: per-package current <= ceiling (growth red with trace — owner notified, evidence attached)
```

**Common confusion** — "budgets punish features" — budgets punish *unmeasured* growth (measured growth updating ceilings with traces — features shipping with evidence, not permission slips). "one global budget suffices" — global budgets hide attribution (which partition grew — per-package ceilings localizing owners). "budgets are static" — budgets ratchet (quarterly shrink-with-carve-outs — living ceilings, not stone tablets).

**Performance note** — budget comparison integer-compares (milliseconds); attribution saving quarters (47-minute-CI class prevented — the highest-ROI check in the pipeline).

**Mentor note** — growth-PR template: feature + trace + budget delta (three artifacts — owners approving with evidence, commons staying managed).
