## 2.1. Composite partitioning and references architecture

### 1) **Partitioning by change-rate** (stable leaves vs churning apps, DAG direction)

**Definition** — *change-rate partitioning*: splitting a program into projects by how often each part changes — stable leaves (domain types, utils — rarely touched) referenced by churning apps (features, UI — daily edits), references flowing *toward* stability (apps → leaves, never reverse — DAG direction). Payoff: editing apps rechecks apps only (leaves verified via emitted declarations — 13/3.2 emit-once mechanics at architectural scale).

**What problem it solves / history** — monolithic programs rechecking everything per keystroke (10k files × every save — editors crawling, CI re-verifying unchanged code): partitioning converting whole-program checks into affected-subgraph checks (leaves cached, apps fresh — edit latency proportional to change scope, not repo size).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), partition at 3+ engineers or 2k+ files (thresholds where whole-program costs bite); draw references along dependency arrows (importers reference exporters — direction enforced, cycles rejected per part 3); keep partitions coarse first (3–7 projects — fine splits after measurement per 1.1, not before).

**Runnable example** — change-rate layers, shown as labeled config docs plus type fences (good vs bad, `tsc --strict`):

```jsonc
// good — references following stability (apps → leaves — DAG direction, cycles unrepresentable)
// tsconfig.leaves.json (labeled config doc — stable: { "compilerOptions": { "composite": true, "declaration": true } })
// tsconfig.app.json (labeled config doc — churning: { "references": [{ "path": "../leaves" }] })
// (app edits recheck apps — leaves served from declarations, see 13/3.2 emit-once mechanics)
```

```typescript
// good — leaf stability (domain types rarely touched — cached downstream)
// (leaves package: domain contracts changing quarterly — apps changing daily)
// file: leaves/user.ts (stable — emitted once, checked against downstream via declarations)
export interface User { id: string; role: "admin" | "user" }
export function isAdmin(u: User): boolean { return u.role === "admin"; }
console.log(isAdmin({ id: "u", role: "admin" })); // true — stable leaves (emitted once — downstream speed from upstream emit)
// bad — app types imported by leaves (references reversed — churning code invalidating stable caches daily)
// fix — DAG direction (stable ← churning imports — invalidation flowing toward stability, never from it)
```

```typescript
// good — coarse partitions first (3 projects — splits measured, not imagined)
export {}; // module marker (consistent module scope across fences)
type Leaf = { id: string }; // leaf contract (stable — rarely edited)
type App = { user: Leaf; view: string }; // app composing (churning — daily edits rechecking apps only)
declare const app: App;
console.log(app.user.id); // id — coarse layering (leaves cached — edit latency proportional to change scope)
// bad — 40 micro-projects day one (reference overhead dwarfing check savings — orchestration without measurement)
// fix — 3–7 partitions first (splits after traces per 1.1 — architecture measured, not imagined)
```

**Common confusion** — "more partitions always faster" — partitions add *reference overhead* (declaration emit + resolution per edge — fine splits paying coordination tax; measure per 1.1 before splitting further). "references enforce architecture" — references enforce *build order* (DAG — layer rules need lint/paths too, see 3.1). "partitioning is premature at small scale" — partitioning at 2k+ files/3+ engineers is *scheduled* (thresholds, not vibes — small repos staying monolithic correctly).

**Performance note** — app-edit rechecks scale with subgraph (leaves cached — 10k-file repos editing in seconds, not minutes); reference edges cost declaration I/O each (dozens of edges trivial — hundreds measured).

**Mentor note** — architecture review: draw the reference graph (3 boxes minimum — direction arrows mandatory; cycles rejected before discussion continues).

### 2) **`composite` + `declaration` mechanics at scale** (emit once, check against declarations)

**Definition** — the scale mechanics (13/3.2 configured, applied here): `composite: true` (project marked referenceable — enforces `declaration`, `rootDir` discipline, file-list determinism) + `declaration` emit (upstream `.d.ts` artifacts — downstream checking *declarations*, not sources — sources skipped entirely when signatures unchanged). Scale effect: downstream check cost ∝ declaration size (small), not source size (large).

**What problem it solves / history** — source-chasing downstream checks (app re-verifying leaf *implementations* per edit — bodies rechecked though contracts unchanged): declaration-mediated checking skipping bodies (signatures sufficient — 01/2.1 erasure philosophy at build scale: types flowing, implementations cached).

**Modern guidance** — `composite` on every referenced project (enforcement — the flag's constraints ARE the hygiene); `declarationMap` for navigation (sources reachable via jump-through-declarations — 16/1.1 navigation preserved across references); never disable `declaration` on referenced projects (sources leaking downstream — speed and encapsulation both lost).

**Runnable example** — emit-once downstream speed (good vs bad, `tsc --strict`):

```typescript
// good — declaration-mediated consumption (downstream checking signatures — bodies skipped)
// upstream (leaves): export function total(xs: number[]): number (declaration: total(xs: number[]): number — signature only)
// downstream (apps): import { total } from "leaves" (checking the .d.ts line — implementation unexamined)
export function total(xs: number[]): number { return xs.reduce((a, b) => a + b, 0); } // leaf impl (checked once — downstream reading declarations)
console.log(total([1, 2])); // 3 — emit-once (bodies cached — downstream cost ∝ signatures, not sources)
// bad — declaration disabled upstream (downstream chasing sources — bodies rechecked per edit, speed + encapsulation lost)
// fix — composite + declaration everywhere referenced (signatures flowing — implementations cached)
```

```jsonc
// good — composite discipline (constraints as hygiene — rootDir, declaration, determinism enforced)
// tsconfig.leaves.json (labeled config doc): { "compilerOptions": { "composite": true, "declaration": true, "declarationMap": true, "rootDir": "src", "outDir": "lib" } }
// (composite enforcing: declaration on, paths rooted, lists deterministic — hygiene by flag, not by review)
```

**Common confusion** — "`composite` slows builds" — `composite` *enables* incremental/reference speedups (constraints paying for caching — upfront discipline, ongoing dividends). "declarations duplicate sources" — declarations *summarize* sources (signatures — downstream reading summaries, the 01 erasure philosophy at scale). "declarationMap optional" — maps preserving navigation (jump-through-declarations — 16/1.1 workflows intact across references; without maps, navigation landing on `.d.ts` stubs).

**Performance note** — downstream checking ∝ declaration size (10×–100× smaller than sources — the scale dividend); emit cost once per upstream change (amortized across downstream edits — stable leaves nearly free).

**Mentor note** — reference hygiene = composite hygiene (flag constraints doing review work — unenforced projects unreferenced, always).

### 3) **Reference-graph hygiene** (DAG enforcement, layer rules, barrel review)

**Definition** — *graph hygiene*: references forming a DAG (cycles rejected by `tsc -b` — build order computable); *layer rules* (which partitions may reference which — 3.1 boundaries, enforced via lint `no-restricted-imports` or `tsconfig` paths scoping); *barrel review* (re-export surfaces per partition curated per 12/1.1 — cycle-surface controlled at boundaries).

**What problem it solves / history** — reference cycles (`tsc -b` deadlocking on release day — 5.1 incident 2: app↔leaves cycle unnoticed without graph checks): hygiene converting cycles into build errors at authoring (DAG enforced — cycles red pre-merge, never on release day).

**Modern guidance** — CI graph checks (cycle detection per PR — `madge`-style or `tsc -b --dry` ordering proof); layer lint (restricted imports per partition — 3.1 boundaries tooled); barrel curation per reference (public surfaces reviewed — cycle-surface minimal by default).

**Runnable example** — DAG by construction (good vs bad, `tsc --strict`):

```typescript
// good — layered imports flowing inward (direction enforced — cycles unrepresentable)
// layers: app → domain → utils (each importing downward only — DAG by rule)
// file: app/order.ts importing domain/user.ts importing utils/id.ts (arrows inward — build order computable)
export interface OrderId { order: string } // app layer (imports domain — downward only)
console.log("layered"); // layered — DAG direction (references following imports — order computable, cycles rejected)
// bad — upward imports (utils importing app — cycle created, tsc -b deadlocking on release day per 5.1)
// fix — graph checks in CI (cycles red pre-merge — DAG enforced, never assumed)
```

```text
// good — dry-run ordering proof (build order computable — DAG evidenced)
// $ tsc -b --dry (labeled CLI doc — prints build order without building; cycles error here, pre-merge)
// (ordering proof per PR touching references — graph changes evidenced like type changes)
```

**Common confusion** — "`tsc -b` allows cycles" — `tsc -b` *rejects* cycles (ordering uncomputable — the deadlock class prevented by construction, see 5.1's pre-hygiene incident). "layers slow development" — layers slow *violations* (legal imports unaffected — friction only where architecture breaks). "barrels cause cycles" — *uncurated* barrels surface cycles (12/1.1 curation — barrels minimal, cycle-surface reviewed).

**Performance note** — graph checks milliseconds (static analysis — per-PR cheap); cycle deadlocks hours (release-day — prevention-to-cost ratio astronomical).

**Mentor note** — reference-PR review: graph attached (`--dry` output — ordering evidenced; cycles rejected before discussion).
