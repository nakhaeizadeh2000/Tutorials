## 1.2. Parameters — optional, default, rest and destructuring

A parameter contract answers two different questions: which argument positions callers must supply, and which values may occupy each position. A default adds runtime behavior; rest collects arguments into an array; destructuring binds fields from an argument. Keep those operations separate when diagnosing a missing argument or an unexpected undefined value.

Examples use TypeScript 7.0.2 / Node 20.20.2, verified 2026-10-14. Save each named file in a new directory without a tsconfig.json. Run `tsc --strict --exactOptionalPropertyTypes --erasableSyntaxOnly --target es2022 --module commonjs --lib es2022,dom --outDir dist FILE.ts`, then `node dist/FILE.js`, replacing FILE with parameters, properties, rest or destructuring. Intentional failures are commented. Activate one line and use the same flags with `--noEmit` instead of `--outDir dist`. For the stated optional-property comparison, also check that single activated line without `--exactOptionalPropertyTypes`.

### 1) **Optionality matrix: positions, values and default behavior**

| Parameter form | Call-site position | Body value or behavior |
|---|---|---|
| name?: string | May be omitted | string or undefined; explicit undefined is accepted |
| name: string or undefined | Required | string or undefined; absence must occupy the position |
| name = "guest", trailing | May be omitted | Omission or undefined evaluates the default |
| name = "guest", before a required suffix | Position remains required | Pass undefined in that position to request the default |

In code, the required-undefined spelling is `name: string | undefined`. An optional parameter must not precede a required parameter. A default-initialized parameter may precede one, but callers still need that leading position. The [primary optional/default guide](https://www.typescriptlang.org/docs/handbook/functions.html#optional-and-default-parameters) distinguishes trailing defaults from defaults before a required parameter.

Save `parameters.ts`:

```typescript
export {};
function optional(name?: string): string { return `hi ${name ?? "guest"}`; }
function required(name: string | undefined): string { return `hi ${name ?? "guest"}`; }
function timeout(ms = 1000): number { return ms; }
function leading(name = "guest", suffix: string): string { return name + suffix; }
console.log(optional(), optional(undefined), optional("Ada")); // hi guest hi guest hi Ada
console.log(required(undefined)); // hi guest
console.log(timeout(), timeout(undefined), timeout(0)); // 1000 1000 0
console.log(leading(undefined, "!"), leading("Ada", "!")); // guest! Ada!
let calls = 0;
function next(value = ++calls): number { return value; }
console.log(next(), next(), next(10), calls); // 1 2 10 2
// required(); // uncomment: TS2554
// leading("Ada"); // uncomment: TS2554
// timeout(null); // uncomment: TS2345
// function illegalOptional(first?: string, second: string): void {} // uncomment: TS1016
// function illegalDefault(value?: string = "guest"): void {} // uncomment: TS1015
```

The five documented lines show omitted and explicit undefined producing the same greeting, a required slot explicitly supplied with undefined, zero retained rather than replaced by a timeout default, and a leading default requested with undefined. The next example's counter reaches two: the default expression executes separately on the two omitted calls and is skipped when ten is supplied. A default is runtime code rather than merely an optional type annotation.

Activate required() or leading("Ada") to see TS2554. The leading function does not move the single string to suffix or silently create a missing position. Null does not trigger the numeric default and is rejected with TS2345. Combining ? with an initializer yields TS1015; placing an optional parameter before a required one yields TS1016. Use one precise contract rather than adding optional markers to silence an unintended omission.

ExactOptionalPropertyTypes does not reject optional(undefined). The flag concerns optional object properties. The parameter program passes with and without the flag; the property comparison below establishes the actual difference.

Save `properties.ts`:

```typescript
export {};
type Optional = { timeout?: number };
type RequiredUndefined = { timeout: number | undefined };
const omitted: Optional = {};
const provided: Optional = { timeout: 3000 };
const explicit: RequiredUndefined = { timeout: undefined };
console.log(Object.hasOwn(omitted, "timeout"), Object.hasOwn(provided, "timeout"), Object.hasOwn(explicit, "timeout")); // false true true
// const optionalUndefined: Optional = { timeout: undefined }; // uncomment: TS2375 only in exact mode
// const missingRequired: RequiredUndefined = {}; // uncomment: TS2741 in both modes
```

The output is `false true true`: the omitted object has no own timeout field, while both supplied objects have that field. Activate optionalUndefined: exact mode rejects it with TS2375, but the default strict mode accepts it. Activate missingRequired: both modes reject the missing required property with TS2741. The [option reference](https://www.typescriptlang.org/tsconfig/exactOptionalPropertyTypes.html) and [object-property owner](<../../../04 Objects Interfaces and Type Aliases/sections/1. Object Type Fundamentals/1.2. Optional readonly and index signatures.md>) describe those property contracts. Do not transfer the property flag's restriction onto optional parameters.

### 2) **Rest as a collection and as a positional tuple**

A homogeneous rest parameter accepts any number of values of its element type. A tuple rest states positional requirements; labels document the meaning of those positions without becoming runtime names. At a call, spread supplies arguments from an iterable source. The checker still needs evidence that a fixed positional contract is met.

Save `rest.ts`:

```typescript
export {};
function sum(...values: number[]): number { return values.reduce((total, value) => total + value, 0); }
function format(...args: [label: string, count: number]): string { return `${args[0]} x${args[1]}`; }
console.log(sum(), sum(1, 2, 3)); // 0 6
console.log(format("apple", 3)); // apple x3
const pair = ["banana", 5] as const;
console.log(format(...pair)); // banana x5
function join(...parts: readonly string[]): string { return parts.join("/"); }
function mutableRest(...parts: string[]): string { parts.push("c"); return parts.join("/"); }
const source: readonly string[] = ["a", "b"];
console.log(join(...source), mutableRest(...source), source.join("/")); // a/b a/b/c a/b
const bag: (string | number)[] = ["apple", 3];
// sum(1, "2"); // uncomment: TS2345
// format("apple"); // uncomment: TS2554
// format("apple", "3"); // uncomment: TS2345
// format(...bag); // uncomment: TS2556
// function changeReadonly(...parts: readonly string[]): void { parts.push("c"); } // uncomment: TS2339
```

The output is `0 6`, `apple x3`, `banana x5` and `a/b a/b/c a/b`. Sum has an explicit zero accumulator, so its empty call is defined. Format requires a label and count; the readonly pair supplies both positions. The bag's open array type does not promise the necessary two slots, even though its current initializer happens to have two elements. Activate its spread to observe TS2556; missing count yields TS2554 and string-valued numbers yield TS2345.

The two rest bodies have different mutation permissions. Join's readonly rest disallows push, while mutableRest appends to the new rest array gathered for its invocation. Spreading the readonly source is accepted for both calls; mutating that gathered array leaves source as a/b. This is distinct from assigning the original readonly array to a mutable array variable. The fuller [tuple forwarding owner](<../2. Overloads and Generics/2.3. Rest parameters tuple types and variadic composition.md>) develops that distinction and generic parameter-list capture.

Use number[] for an arbitrary numeric bag and a tuple for meaningful positions. Use unknown[] for a deliberately open input only when the body checks values before operating on them. An any[] parameter suppresses useful element checks; it does not validate the collected arguments. The [unknown owner](<../../../03 Basic Types and Annotations/sections/2. The Special Types/2.2. unknown the type-safe top type.md>) explains the required body evidence.

### 3) **Destructured parameters: type the whole argument**

In `function connect({ host, port }: ConnectOptions)`, the pattern names runtime bindings; the type after the colon describes the whole argument object. A default on port initializes that binding when its value is undefined. A default on the whole parameter supplies an object when the argument is omitted or undefined. They answer different questions.

Save `destructuring.ts`:

```typescript
export {};
type ConnectOptions = { host: string; port?: number; retries?: number };
function connect({ host, port = 5432, retries = 3 }: ConnectOptions): string {
  return `${host}:${port} retries=${retries}`;
}
console.log(connect({ host: "localhost" })); // localhost:5432 retries=3
console.log(connect({ host: "db", port: 3306, retries: 0 })); // db:3306 retries=0
const options: ConnectOptions = { host: "cache", retries: 1 };
console.log(connect(options)); // cache:5432 retries=1
type DefaultOptions = { host?: string; port?: number };
function withDefaults({ host = "localhost", port = 5432 }: DefaultOptions = {}): string {
  return `${host}:${port}`;
}
console.log(withDefaults(), withDefaults(undefined), withDefaults({ host: "db" })); // localhost:5432 localhost:5432 db:5432
// connect(); // uncomment: TS2554
// connect({ port: 80 }); // uncomment: TS2741
// connect({ host: "db", extra: true }); // uncomment: TS2353
// connect({ host: "db", port: undefined }); // uncomment: TS2379 only in exact mode
```

The first three lines are `localhost:5432 retries=3`, `db:3306 retries=0` and `cache:5432 retries=1`. The required host contract remains required even though port and retries have body defaults. Omitting the whole connect argument yields TS2554; supplying only port yields TS2741. A written extra field is still checked against the object contract and yields TS2353.

The final line is `localhost:5432 localhost:5432 db:5432`. WithDefaults deliberately allows the entire bag to be omitted: its outer empty object default then allows the property defaults to run. Connect has no outer default and cannot be called without its required bag. Exact mode separately rejects a written port:undefined property with TS2379 for the shown ConnectOptions contract, even though the whole withDefaults(undefined) argument is legal. Do not confuse parameter optionality with the fields of an options object.

Name an options type when it is reused or gives the object contract a useful name. Keep the required fields visible to callers, and place a whole-argument default only when omission has a deliberate meaning. Full freshness and optional-property mechanics remain in the [object shape owner](<../../../04 Objects Interfaces and Type Aliases/sections/1. Object Type Fundamentals/1.1. Object types structural shape and excess property checks.md>); runtime parameter mechanics belong in the [JavaScript parameter lesson](<../../../../JavaScript/05 Functions Deep Dive/sections/2. Parameters and arguments/2.1. Defaults destructuring rest and the arguments object.md>).

### 4) **Common confusion**

Optional parameters accept explicit undefined even under exact optional property checking. A default before a required parameter retains its position; a trailing default can be omitted. Null and zero do not request a default. A readonly spread source and a readonly rest body describe different arrays. Finally, a default on a destructured field does not create a missing whole argument unless the function also supplies an outer default.

### 5) **Performance note**

Parameter and tuple type annotations are erased, but default expressions, rest collection, spreading and destructuring remain runtime operations. The counter example observes default evaluation; it is not a speed measurement. No checker complexity, tooltip-size threshold or runtime ranking was measured here. Choose clear contracts and measure an actual hot workload before replacing its parameter handling. Use the [compiler measurement workflow](<../../../19 Performance Project References and Scaling/sections/1. Check-Time Performance/1.1. Measuring with extendedDiagnostics and traces.md>) for a slow type-checking case.

### 6) **Mentor note**

Ask the learner which calls can omit a position: optional(), required(), timeout() and leading("Ada"). A sound answer permits the first and third, requires an explicit slot for the second and requires both positions for the fourth. Then enable exact optionality and compare optional(undefined) with the object timeout:undefined assignment. Finish by asking why withDefaults(undefined) works while connect() is rejected, and why mutableRest's push leaves its spread source unchanged.
