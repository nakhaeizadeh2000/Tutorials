## 6.1. Common interview QA — functions and callable types

### 1) **When does an overload beat a union param?** (caller experience vs maintainability — hover and error-message budget)

**Answer** — overload wins for 2–3 fixed variants with distinct returns where hover `pick("hi"): string` and error `pick(true)` are worth the extra signatures. Union + conditional wins for `n` keys or dynamic args: `get<K extends keyof Store>(key: K): Store[K]` covers `n` keys with one signature and handles `get(dynamicKey)` where overloads need a catch-all. Trade-off: overload = crisp caller UX, more signatures; generic = scalable, one hover line.

```typescript
// overload — crisp per-literal return
function pick(value: string): string;
function pick(value: number): number;
function pick(value: string | number): string | number { return value as string | number; }
pick("hi"); // string — hover shows overload 1

// generic — one signature for n keys
type Store = { users: { id: string }[]; posts: { title: string }[] };
function get<K extends keyof Store>(key: K): Store[K] { return null as unknown as Store[K]; }
```

### 2) **Why does `strictFunctionTypes` reject a callback assignment that worked before?** (contravariance — caller supplies supertype)

**Answer** — params are contravariant: a function that accepts `Animal` cannot be substituted where a function accepting `Dog` is expected, because the caller will supply `Dog` but the handler expects to handle `Cat` too. `handleDog((a: Animal)=>...)` is rejected; `handleAnimal((d: Dog)=>...)` also rejected if mismatched. Returns stay covariant. Fix: widen callback param to expected type or use `this: void` / branded guards — don't disable `strictFunctionTypes`.

```typescript
type Animal = { kind: string };
type Dog = Animal & { bark(): void };
function handleDog(cb: (d: Dog) => void): void {
  cb({ kind: "dog", bark() {} });
}
// handleDog((a: Animal) => {}); // error — Animal not assignable to Dog under contravariance
handleDog((d: Dog) => d.bark()); // ok
```

### 3) **What does `this: void` on a callback buy you?** (proves callback does not use `this` — safe to detach and store)

**Answer** — `this: void` is a type-level proof that the callback never reads `this`, so it is safe to `queue(cb)`, `setTimeout(cb,0)`, or store in an array without binding. Without it, a `function(){ this.cache }` callback with untyped `this` (`any`) would be accepted and then crash when detached. `this: void` plus `noImplicitThis` makes the checker reject `this`-using callbacks.

```typescript
type Safe = (this: void, x: number) => void;
const safe: Safe = (x) => console.log(x); // ok — arrow this is void
// const unsafe: Safe = function (x) { console.log(this); }; // error — this: void inside
function queue(cb: Safe): void { setTimeout(() => cb(42), 0); } // detached safe
```

### 4) **How does `x is T` differ from `asserts x is T`?** (returning boolean vs throwing — caller narrows in `if` vs after call)

**Answer** — `x is T` returning `boolean` narrows inside `if (isDog(a))` only; `asserts x is T` returning `void` narrows for the *rest* of the scope after `assertIsDog(a)` or throws. Use predicate for branching; assertion for flat invariant validation.

```typescript
type Dog = { kind: "dog"; bark(): void };
type Animal = Dog | { kind: "cat"; meow(): void };
function isDog(a: Animal): a is Dog { return a.kind === "dog"; }
function assertIsDog(a: Animal): asserts a is Dog {
  if (a.kind !== "dog") throw new Error();
}
function use(a: Animal): void {
  if (isDog(a)) a.bark(); // if-branch only
  assertIsDog(a); // rest of scope narrowed
  a.bark();
}
```

### 5) **`satisfies` vs `as` on a function value** (preserved arity/literal vs widened and silenced)

**Answer** — `satisfies Handler` checks assignability while preserving the source literal's param tuple and literal types for downstream inference; `as Handler` widens to `Handler` and disables excess/arity checks at the literal. Use `satisfies` on handler tables and exported literals; reserve `as` for airlocks with comments.

```typescript
type Handler = (x: number) => string;
const viaSatisfies = ((x: number) => String(x)) satisfies Handler; // preserves (x: number) literal
const viaAs = ((x: number) => String(x)) as Handler; // widens to Handler, literal lost
// satisfies catches // ((x: string, y: number)=>{}) satisfies Handler error (extra param); as silences
```
