## 3.1. Recursive object types and self-referential structures

Recursive object types model data that contains *itself* — trees, linked lists, nested comments, JSON, and DOM-like hierarchies. A single non-recursive `type Node = { value: number; next: { value: number; next: ... } }` would need a fresh literal per depth; recursion lets one declaration describe arbitrary depth. This leaf covers where the checker embraces recursion, where two types chase each other, and how to keep recursion readable and bounded.

---

### 1) **Self-reference** (`type Tree = { value: number; children: Tree[] }` — how the checker handles recursion and where it gives up)

**Definition** — a *self-referential* (recursive) object type is one whose member types name the enclosing type. `type Tree = { value: number; children: Tree[] }` says "a `Tree` has a `number` value and an array whose elements are again `Tree`". The same shape as an `interface` is `interface Tree { value: number; children: Tree[] }`. The reference must be *wrapped* inside an object property, array, tuple, or union branch — the type does not alias itself directly (`type Bad = Bad` is illegal — see Runnable).

**What problem it solves / history** — without recursion every nested structure was `any` or a fixed-depth copy-paste: `type Tree0 = { value: number }; type Tree1 = { value: number; children: Tree0[] }; type Tree2 = { value: number; children: Tree1[] }` — add a level, add a type, forget a union branch and the deepest comment thread slips to `any` at runtime. Recursive object types existed from TypeScript 0.9, but the *generic* recursion story evolved: TS 3.7 (2019) re-enabled recursive `type` aliases *only when the self-reference is wrapped in an object/array* (`type Node = { next: Node | null }` ok, `type Loop = Loop` still errors `TS2456` — circular alias), and TS 4.1–5.9 progressively capped *instantiation depth* (default ~50) so a missing base case no longer hangs the language server (it now reports `TS2589: Type instantiation is excessively deep and possibly infinite`).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS):

- **Wrap the recursion** — always `type Tree = { value: number; children: Tree[] }` or `type Linked<T> = { value: T; next: Linked<T> | null }` — array/property/union-wrapped. An unwrapped `type A = A` or `type A = A[]` at the top level is a *circular directly-referencing alias* (`TS2456`) — not a shape, not checkable.
- **Terminate explicitly** — every recursive object type needs at least one *base-case branch* that does **not** recurse (`| null`, `| undefined`, `children: []` base via empty array, `JsonValue` includes `string`/`number` leaves). Without a base case the type is *inhabited only by infinite values* and every assignment becomes a depth probe — the checker will eventually give up with `TS2589`.
- **Prefer `interface` for plain recursive shapes** (rationale in §3) — `interface Node { value: number; children: Node[] }` displays as `Node` in hover; `type Node = { value: number; children: Node[] }` displays identically but a `type`-based generic recursion (`type Deep<T> = T extends object ? { [K in keyof T]: Deep<T[K]> } : T`) is more prone to alias-expansion lag (see Performance).
- **Know where the checker gives up** — structural assignability on recursive types is evaluated *lazily / on demand* — `tree.children[0].children[1].value` checks only as deep as the property chain you read. The checker gives up when it must *fully expand* the type: assigning a huge literal tree past ~15–20 nested levels, or instantiating a *mapped recursive utility* to depth >~30 without a depth counter. The diagnostic is `TS2589` (excessively deep), `TS2502` (circular alias), or a truncated hover — all say "add a base case or a depth budget".

**Runnable example** — self-reference with wrapped recursion, terminating branches, and the two checker give-up cases — good vs bad (`tsc --strict` — error lines commented so the fence still compiles):

```typescript
// good — wrapped self-reference, explicit termination via array + | null base
interface Tree {
  value: number;
  children: Tree[]; // recursion wrapped in array element type — checker allows
}
const leaf: Tree = { value: 1, children: [] };
const node: Tree = { value: 2, children: [leaf, { value: 3, children: [] }] };
console.log(node.children.length); // 2

// good — same shape as type alias — also wrapped, also allowed (type alias recursion ok when wrapped)
type TreeT = { value: number; children: TreeT[] };
const leafT: TreeT = { value: 4, children: [] };
console.log(leafT.value); // 4

// good — linked list: null terminates the chain — finite inhabitant exists
interface Linked<T> {
  value: T;
  next: Linked<T> | null; // union with null is the base case
}
const list: Linked<string> = { value: "a", next: { value: "b", next: null } };
console.log(list.next?.value); // b

// good — JSON is the canonical recursive object type — union leaves terminate recursion
type JSONValue = string | number | boolean | null | JSONValue[] | { [key: string]: JSONValue };
const doc: JSONValue = { user: { name: "Ada", tags: ["admin", "editor"], meta: null } };
console.log(typeof doc); // object

// bad — unwrapped circular alias — not a wrapped property, checker rejects immediately
// type Loop = Loop; // error TS2456: Type alias 'Loop' circularly references itself.
// type DirectArray = DirectArray[]; // error TS2456: Type alias 'DirectArray' circularly references itself.
// fix — wrap in a property so the type is an object shape, not an alias of itself
type WrappedLoop = { self: WrappedLoop | null }; // ok — recursion inside property
const wrapped: WrappedLoop = { self: null };
console.log(wrapped.self); // null

// bad — missing base case: type inhabitable only by infinite values — checker will eventually TS2589 on deep literals
type NoBase = { next: NoBase }; // ok syntactically (wrapped), but no leaf value exists
// const impossible: NoBase = { next: { next: { next: /* ... infinite */ } } }; // any finite literal is "missing next" at the deepest leaf
// fix — add the base case:
type WithBase = { next: WithBase | null };
const finite: WithBase = { next: null }; // ok — terminates

// where the checker gives up #1: excessively deep literal nesting (hover truncates, then TS2589 on assignment)
function sumTree(t: Tree): number {
  return t.value + t.children.reduce((acc, c) => acc + sumTree(c), 0);
}
console.log(sumTree(node)); // 6
// const tooDeep: Tree = { value:0, children:[{value:0, children:[{value:0, children:[{value:0, children:[/* ... past 30 levels the literal errors TS2589 */]}]}]}]};
// fix — don't hand-write depth-30 literals; build iteratively or validate at runtime.

// where the checker gives up #2: generic mapped recursion without a depth cap hits TS2589
type DeepFreeze<T> = T extends object ? { readonly [K in keyof T]: DeepFreeze<T[K]> } : T;
// This crude DeepFreeze recurses without a budget — on a 30-level nested object it expands to TS2589:
// type DeepNested = { a: { b: { c: { d: { e: { f: { g: { h: string }}}}}}}};
// type Frozen = DeepFreeze<DeepNested>; // may error TS2589: Type instantiation is excessively deep and possibly infinite.
// fix — add a depth counter (see §3 practical guard)
```

```typescript
// bad — confusing "interface and type are identical here so either unwrap is fine" — unwrap still illegal on both
// interface BadI = BadI; // syntax error — interface body must be a shape, not an alias
// type BadT = BadT | string; // error TS2456 even though union wraps — top-level alias is still directly circular on the left branch
// fix — object wrapper again:
type GoodBranch = string | { branch: GoodBranch };
const goodBranch: GoodBranch = { branch: "leaf" };
console.log(goodBranch);

// good — self-reference stays structural (name doesn't matter) — depth checked on access, not on declaration
interface A_Shape { value: number; children: A_Shape[] }
interface B_Shape { value: number; children: B_Shape[] }
const aShape: A_Shape = { value: 1, children: [] };
const bShape: B_Shape = aShape; // ok — same structure, different name (see 02 1.1)
console.log(bShape.value); // 1
```

**Common confusion** — "`type Tree = { children: Tree[] }` creates infinite runtime objects" — no — types erase (see [2.1. Type erasure](<../../../01 Fundamentals and Mental Model/sections/2. How TypeScript doesnt execute/2.1. Type erasure what survives compilation.md>)); only values you construct exist. "`Tree` and `{ value: number; children: Tree[] }` are checked infinitely deep on every assignment" — the checker is lazy — depth follows the property chain you actually touch; hovering `node.children[0]` does not expand 50 levels. "`type Loop = Loop` should be allowed because it is self-referential" — an alias with no object wrapper is a *type-level infinite loop* with no structural contract — TS rejects it with `TS2456`; wrap it (`{ self: Loop | null }`) to give it a membership test. "`|` with recursion needs the recursive branch last" — order doesn't matter — `type X = X[] | string` still circular (top-level `X` unwrapped in union); make *every* `X` occurrence wrapped in a property: `type X = { items: X[] } | string`.

**Performance note** — a plain recursive object type (`Tree`, `Linked<T>`, `JSONValue`) is `O(depth touched)` — cheap. The cost appears with *mapped* recursion: `type Deep<T> = { [K in keyof T]: Deep<T[K]> }` forces the checker to allocate one `Deep` instantiation per level per property — `O(properties × depth)`. A 50-property API type recursed to depth 10 allocates ~500 type nodes per check; depth 50 hits the instantiation limit and fails with `TS2589` while dragging language-server `quickInfo` to 80+ ms. No runtime, no allocation, no GC — purely checker graph. Measure with `tsc --extendedDiagnostics` and `tsc --generateTrace trace/` — optimize by naming intermediates and capping depth (see §3). Splitting a `JSONValue`-like union into named `type JSONLeaf / JSONArray / JSONObject` memoizes and shortens hovers.

**Mentor note** — teach with the `null` base case first — draw one box `Linked { value, next }` with an arrow to the same shape and a `null` terminator — ask "what finite value inhabits this?" — only after they answer `null` do you show `Tree` (array-terminated). Review checklist: any recursive `type`/`interface` without `| null`, `| undefined`, or an empty-array leaf must have a `// base: ...` comment justifying termination; flag `type X = X` / `type X = X[]` with `TS2456` and require a wrapper. Exercise: give `type Comment = { text: string; replies: ThreadComment[] }` and ask to (a) construct a 3-level literal, (b) write `function depth(c: Comment): number`, and (c) explain which `TS` code appears if the `replies` wrapper is removed (answer: `TS2456` on the alias line, not `TS2589`).

### 2) **Mutual recursion** (two types naming each other — `type A = { b: B }` / `type B = { a: A }` — termination and depth limits)

**Definition** — *mutual recursion* is a cycle over ≥2 declarations: `A` mentions `B`, `B` mentions `A` (or `A → B → C → A`). The minimal object form is `type A = { b: B | null }` / `type B = { a: A | null }` or the `interface` equivalent `interface A { b: B | null }` / `interface B { a: A | null }`. Like §1, each edge must be wrapped in a property/union — `type A = B` / `type B = A` (bare) is a direct circular alias (`TS2456`) even though two names are involved.

**What problem it solves / history** — real domains are mutually referential: `Category` has `Category[]` children *and* `User` has `Profile` has `User`; AST nodes `Expression` contains `Statement` contains `Expression`; `Tree` vs `Forest = Tree[]` is a mutual pair via array. Before `type` recursion was tightened (pre-3.7) mutual object cycles sometimes fell through to `any`; after 3.7 they are first-class but still bounded: the checker tracks *instantiation identity* to avoid infinite loops (it remembers "I already saw `A` on this branch"), and when a *generic* mutual recursion lacks a budget it terminates with `TS2589` rather than hanging (same cap as §1, default depth ~50 since TS 4.5+, shared with conditional `infer` recursion).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS):

- **Need mutual object recursion** → declare mutual `interface`s or wrapped `type`s with an explicit base branch on at least one edge (`| null` / `| undefined` / optional property). `interface NodeA { b: NodeB | null }` / `interface NodeB { a: NodeA | null }` is the canonical review-passing shape.
- **Need generic mutual recursion** (`type DeepA<T> = ... DeepB<T[key]> ...`) → add a *depth counter* tuple `D extends unknown[]` or numeric `Depth extends number` with a stop condition (`D extends [unknown, unknown, unknown, unknown, unknown] ? T : ...`). Without a counter any generic mutual pair that recurses on every branch *will* hit `TS2589` when deeply instantiated.
- **Need mutual via arrays/tuples/maps** → still wrapped — `interface Tree { forest: Forest }` / `type Forest = Tree[]` is mutual through `[]`; `type A = { b: Map<string, B> }` is wrapped through `Map`. The wrapping rule does not require a plain object — any container type counts.
- **Termination rule** — the checker terminates *structurally*: if it revisits the same type *with identical type arguments* on a branch, it reuses the identity rather than re-expanding. That is why `A ↔ B` with concrete `null` leaves converges; `DeepA<T> ↔ DeepB<T>` where `T` changes each step (`T[K]`) does not converge until the depth budget stops it.

**Runnable example** — mutual object pair, bare mutual (error), and generic mutual hitting the depth cap — good vs bad (`tsc --strict` — error lines commented so the fence compiles):

```typescript
// good — mutual recursion through properties, each edge wrapped, null terminates
interface Category {
  name: string;
  parent: Category | null; // self, but mutual via Team below also works
  teams: Team[];
}
interface Team {
  label: string;
  category: Category | null; // mutual: Team → Category → Team
}
const eng: Category = { name: "eng", parent: null, teams: [] };
const backend: Team = { label: "backend", category: eng };
eng.teams.push(backend);
console.log(eng.teams[0].category?.name); // eng — finite, terminates at null

// good — minimal mutual pair A ↔ B with two names, both wrapped
type NodeA = { id: string; b: NodeB | null };
type NodeB = { id: string; a: NodeA | null };
const a: NodeA = { id: "a1", b: { id: "b1", a: null } };
console.log(a.b?.id); // b1

// good — mutual via array wrapper counts as wrapped as well
interface DocTree { title: string; children: DocForest }
type DocForest = DocTree[]; // DocForest element type is DocTree → mutual through []
const forest: DocForest = [{ title: "root", children: [{ title: "leaf", children: [] }] }];
console.log(forest[0].children.length); // 1

// bad — bare mutual aliases without wrapping — direct circular alias even through two names
// type A = B; // error TS2456: Type alias 'A' circularly references itself.
// type B = A; // error TS2456
// type BareMutual = BareMutual | string; // error TS2456 — top-level BareMutual unwrapped on one branch
// fix — wrap every occurrence in a property/union-kind that gives a structural test:
type FixedA = { b: FixedB | null };
type FixedB = { a: FixedA | null };
const fixedA: FixedA = { b: null };
console.log(fixedA.b); // null
```

```typescript
// good — generic mutual recursion WITH a depth budget (terminates, no TS2589)
type Leaf = string | number | boolean | null;

// Budget via tuple length — depth 0..5 only; past 5 returns the input unchanged (stops recursion)
type DeepFreezeMutual<T, D extends unknown[] = []> =
  D["length"] extends 5 ? T :
  T extends Leaf ? T :
  T extends Map<infer K, infer V> ? Map<K, DeepFreezeMutual<V, [...D, unknown]>> :
  T extends (infer E)[] ? DeepFreezeMutual<E, [...D, unknown]>[] :
  T extends object ? { readonly [K in keyof T]: DeepFreezeMutual<T[K], [...D, unknown]> } :
  T;

type Nested = { a: { b: { c: { d: { e: { f: string } } } } } };
type Frozen = DeepFreezeMutual<Nested>; // ok — caps at depth 5 (which covers this 5-deep shape)
const frozen: Frozen = { a: { b: { c: { d: { e: { f: "hi" } } } } } } as Frozen;
// frozen.a.b.c.d.e.f = "x"; // error TS2540: Cannot assign to 'f' because it is a read-only property.

console.log(frozen.a.b.c.d.e.f.toUpperCase()); // HI

// bad — same generic mutual WITHOUT a budget — hits TS2589 when instantiated deeply enough
type DeepNoBudget<T> =
  T extends Leaf ? T :
  T extends (infer E)[] ? DeepNoBudget<E>[] :
  T extends object ? { [K in keyof T]: DeepNoBudget<T[K]> } : T;
// type AlsoDeep<T> = DeepNoBudget<T> & { __tag?: string }; // mutual flavour via intersection
// type VeryNested = { a:{b:{c:{d:{e:{f:{g:{h:{i:{j:string}}}}}}}}}};
// type Exploded = DeepNoBudget<VeryNested>; // error TS2589: Type instantiation is excessively deep and possibly infinite. (when depth > ~50)
// fix — use DeepFreezeMutual<T> above with the tuple counter, or limit recursion to known keys.

// bad — teaching the checker loop: mutual generic that never changes its argument never terminates without a counter
// type LoopA<T> = { next: LoopB<T> }; // ok syntax (wrapped)
// type LoopB<T> = { next: LoopA<T> }; // mutual, but T never shrinks — instantiating LoopA<{x:{y:{...}}}> expands one layer per hop forever
// type BadMutualGeneric = LoopA<{ a:{b:{c:string}}}>; // with no budget this still converges because checker caches LoopA<T> identity
// The danger is when the recursive call CHANGES the argument: LoopA<T[K]> — then identity never matches and TS2589 follows without a depth guard.
```

**Common confusion** — "`A = { b: B }` / `B = { a: A }` needs no base case because two types already terminate each other" — false — two names without `| null` is still *infinite* (every `A` needs a `B`, every `B` needs an `A` — no finite inhabitant). "`TS2456` and `TS2589` are the same depth error" — `TS2456` ("circularly references itself") fires at the *declaration* for an unwrapped alias (`type A = A`, `type A = B`/`B = A` bare); `TS2589` ("excessively deep") fires at the *use* site for a wrapped recursion that instantiated too deep (>~50). "`interface A { b: B }` / `interface B { a: A }` forbids mutual cycles" — interfaces follow the same wrapping rule, but two `interface`s with mutual properties *are* allowed when each property is wrapped — the `interface` heritage clause cannot be cyclic, the *property* can. "`DeepFreezeMutual` needs numeric `Depth extends number`" — tuple `[...D, unknown]` is the idiomatic 5.9-era counter (type-level Peano) — numeric depth counters require `Depth extends [infer N]` arithmetic via template/mapped gaps; the tuple-length budget is cheaper and memoizes.

**Performance note** — two concrete types `A ↔ B` with `| null` leaves are identical to §1 cost — `O(depth touched)`. The explosion is *generic* mutual recursion where the argument *changes* each hop (`T[K]`, `T extends Map<k,v>` → `v`). Each hop instantiates a new `DeepX<NewArg, [...D]>` — the checker allocates a distinct type node per `D` length — `O(branches × depth)` as in §1, but doubled because two names interleave. A 100-property API recursed through `A↔B` without a cap can instantiate 100 × 50 nodes before hitting `TS2589`, blocking the language server for >150 ms (seen via `tsc --generateTrace`). No runtime cost — mutual types erase — the budget is checker time. Keep the cap ≤5–8 for mapped mutuals; deeper caps (≥10) rarely add value and linearly increase check time. Measure: `tsc --extendedDiagnostics` (instantiations count) and `trace.json` `types` phase.

**Mentor note** — draw two boxes `A` and `B` with arrows `A.b → B` and `B.a → A` and a `null` off-ramp from each — ask "which arrow *leaves* the system?" — only answers with `null` are correct. Exercise: give `type Expr = { kind: "lit"; value: number } | { kind: "bin"; left: Expr; op: string; right: Expr }` and `type Stmt = { kind: "expr"; expr: Expr } | { kind: "block"; stmts: Stmt[] }` and ask which is self vs mutual (answer: `Expr` self, `Stmt` mutual via `Expr`). Review checklist: any mutual pair lacking `| null`/`| undefined`/`?` on at least one edge is flagged "no finite inhabitant"; any generic mutual `type X<T> = ... X<T[K]>` without a tuple counter is flagged "needs depth budget" — require the `D extends unknown[]` cap before approval.

### 3) **Practical guard** (prefer `interface` for recursive object shapes; keep recursion shallow and expose a depth budget in code review)

**Definition** — a *practical guard* is the team rule that makes recursion *reviewable*: (a) **prefer `interface` for recursive object shapes** — the Display-Readability-and-Interning rule; (b) **keep recursion shallow** — don't allow call-site literals or generic wrappers to recurse past 5–8 levels implicitly; (c) **expose a depth budget** — either a *type-level* counter (`TupleDepth extends unknown[]`) or a *code-level* constant (`MAX_COMMENT_DEPTH = 6`) plus a runtime validator at ingestion boundaries.

**What problem it solves / history** — the failure mode is not the declaration — it is the *call site* months later. `interface Node { child: Node }` was always readable (hover shows `Node`), but `type Node = { child: Node } & Timestamped & Audited & Brand` buries the recursion under `&` expansions; `type Deep<T> = { [K in keyof T]: Deep<T[K]> }` silently recurses to depth 20 when someone passes `ApiResponse` and the next `tsc` upgrade from 5.5→5.9 tightens the `TS2589` threshold — a previously-green CI starts failing on a type line the PR didn't touch. TS 5.8's `--erasableSyntaxOnly` and `--isolatedDeclarations` made `interface`/`type` erasure explicit but did not fix depth failures; the community answer ( handbook 5.9, google "typescript recursive depth limit" ) converged on: model recursion with `interface`, bound generic depth with a counter, and gate deep payloads with a runtime guard so the type's promise matches the ingest validation.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS):

- **Recursive object shape with no operators → `interface`** — `interface Tree { value: number; children: Tree[] }`, `interface ThreadComment { text: string; replies: ThreadComment[] }`, mutual pairs `interface Category`/`interface Team` — `interface` interns one nominal symbol, hover shows `Category`, `extends` errors are local, and the language server caches the shape. A `type` spelling is not wrong, just noisier (`type Tree = { value: number; children: Tree[] }` hover still shows `Tree`, but `type Tree = Base & TreeBranch` expands `&` on every hover).
- **Recursive shape that needs `|`, `&`, mapped, or `Omit` → `type` — but split the recursion from the operators** — derive `interface TreeCore { value: number; children: TreeCore[] }` and then `type PublicTree = Omit<TreeCore, "children"> & { children: PublicTree[] }` is unnecessary nesting — instead `type Jsonish = TreeCore | string` uses `type` only for the union top. Keep the recursive *core* as `interface`.
- **Keep recursion shallow (default cap 5–6, max 8 in app code)** — if your domain naturally nests to 12 (filesystem, AST), *chunk* it: `type CommentThread = Comment` where runtime caps `replies` to `MAX_DEPTH` and validation truncates. The type agreeing to depth 50 while `json-api` rejects depth >6 is an honesty bug.
- **Expose the budget** — two budgets, pick one (or both):
  - *Type-level* — `DeepPartialCapped<T, D extends unknown[] = []>` (see Runnable) — code review sees `extends 6` in the hover; CI fast-fails with `TS2589` only when the cap is exceeded, which is the intended signal.
  - *Value-level* — `const MAX_COMMENT_DEPTH = 6` + `function assertDepth(node: Comment, depth=0)` — the type says `Comment`, the runtime says "beyond 6, reject/truncate" — the honest contract is `Comment` *as validated to ≤6* (document in JSDoc).
- **Lint & CI** — enable `@typescript-eslint/consistent-type-definitions` with `interface` preference for plain objects (so recursive shapes default to `interface`), flag any `type X = ... X<...> ...` without `...Depth...` or `...D["length"] extends` via a custom lint or grep in review (`grep -R "Deep.*<T.*X<"`), and add `tsc --noEmit --extendedDiagnostics` to CI to catch `TS2589` early.

| Situation | Spelling | Depth rule | Review artifact |
|---|---|---|---|
| Plain tree / list / comment | `interface Node { child: Node | null }` | no generic depth — rely on `| null` base | one symbol, hover = `Node` |
| Mutual domain (Category ↔ Team) | two `interface`s | `| null` on at least one edge | mutual `null` visible |
| Utility that recurses (`DeepPartial`, `DeepFreeze`) | `type Deep<T, D extends unknown[] = []>` | `D["length"] extends 6 ? T : ...` | cap number is the budget |
| Deep payload from network/storage | `interface` + runtime `assertDepth` | `MAX_DEPTH = 6` constant + validator | validator file owns the number |

Both spellings erase — the guard is about checker latency, diagnostic locality, and API honesty — not emit (see [2.1. Type erasure](<../../../01 Fundamentals and Mental Model/sections/2. How TypeScript doesnt execute/2.1. Type erasure what survives compilation.md>)).

**Runnable example** — team rule in code: `interface`-preferred recursion, shallow caps, and depth budgets type-level + value-level — good vs bad (`tsc --strict` — error lines commented):

```typescript
// good — recursive core as interface — hover is short, interning is cheap, erasableSyntaxOnly ok
interface ThreadComment {
  id: string;
  text: string;
  replies: ThreadComment[]; // array terminates at [] — base case
}
const thread: ThreadComment = {
  id: "1",
  text: "root",
  replies: [{ id: "2", text: "reply", replies: [] }],
};
console.log(thread.replies[0].text); // reply

// good — mutual domain stays as interfaces as well — two symbols, clear hover
interface CategoryIR { name: string; parent: CategoryIR | null; teams: TeamIR[] }
interface TeamIR { label: string; category: CategoryIR | null }
const cat: CategoryIR = { name: "platform", parent: null, teams: [] };
console.log(cat.name); // platform

// contrast — same recursion as type alias: works, but hover expands through & later and generic recursion is costlier
type CommentT = { id: string; text: string; replies: CommentT[] }; // ok — wrapped
const threadT: CommentT = { id: "1", text: "root", replies: [] };
console.log(threadT.id); // 1 — not wrong, just noisier at scale (see Performance)
// Rule: for plain shapes default to interface; reach for type only when the shape needs |/&/mapped (see table above)

// good — value-level depth budget: honest contract + runtime guard (mirrors the type's shallow promise)
const MAX_COMMENT_DEPTH = 6;
function assertCommentDepth(node: ThreadComment, depth = 0): void {
  if (depth > MAX_COMMENT_DEPTH) throw new Error(`comment depth ${depth} exceeds ${MAX_COMMENT_DEPTH}`);
  for (const reply of node.replies) assertCommentDepth(reply, depth + 1);
}
assertCommentDepth(thread); // ok — depth 1
console.log("depth guard ok");

// bad — deep literal with no runtime guard — type accepts arbitrarily deep but API will truncate at depth 3 in production
// const sneakyDeep: ThreadComment = { id:"1", text:"a", replies:[{ id:"2", text:"b", replies:[{ id:"3", text:"c", replies:[{ id:"4", text:"d", replies:[{ id:"5", text:"e", replies:[{ id:"6", text:"f", replies:[{ id:"7", text:"g", replies:[] }]}]}]}]}]}]};
// assertCommentDepth(sneakyDeep); // throws at depth 6 — would have slipped to truncated storage without the validator
// fix — always validate ingested recursion to the same MAX_COMMENT_DEPTH that the type's reviewers assume

// good — type-level depth budget for generic utilities: capped DeepPartialDeepFreeze with tuple counter
type DeepPartialCapped<T, D extends unknown[] = []> =
  D["length"] extends 6 ? T : // budget 6 — stop recursing past depth 6, return T as-is
  T extends Map<infer K, infer V> ? Map<K, DeepPartialCapped<V, [...D, unknown]>> :
  T extends (infer E)[] ? DeepPartialCapped<E, [...D, unknown]>[] :
  T extends object ? { [K in keyof T]?: DeepPartialCapped<T[K], [...D, unknown]> } :
  T;

type ApiConfig = {
  server: { host: string; port: number; tls: { cert: string; key: string; ca?: string } };
  retries: number;
};
type PartialCapped = DeepPartialCapped<ApiConfig>; // ok — depth 3 within budget 6
const partialCapped: PartialCapped = { server: { host: "localhost" } }; // deep optional honoured
console.log(partialCapped.server?.host); // localhost

// Deep nesting to 8 would hit the cap: shape past depth 6 is left as-is (not made deeply partial) — honest truncation, not TS2589
type Deep8 = { a:{b:{c:{d:{e:{f:{g:{h:{i:string}}}}}}}}}; // 8 deep
type Capped8 = DeepPartialCapped<Deep8>; // ok — no TS2589, past depth 6 remainder stays required (graceful)
// type Uncapped8 = DeepNoBudget<Deep8>; // error TS2589 if DeepNoBudget recurses without a cap (see §2 bad)
// fix — keep the cap, document that depth>6 partiality is intentionally shallow — reviewers see `extends 6`

// bad — mixing interface-vs-type religiously: plain recursive shape forced to type for "consistency" breeds hover noise
// type CategoryBad = { name: string; parent: CategoryBad | null; teams: { label: string; category: CategoryBad | null }[] }
// No checker error, but mutual now lives in ONE anonymous expansion — hover is a single 80-char line.
// fix — split into two interfaces (Category / Team) as above — two named symbols, two-line hover.

// good — union recursion as type is fine: the recursive core is still an object shape
type Jsonish =
  | string
  | number
  | boolean
  | null
  | Jsonish[]
  | { [k: string]: Jsonish };
const j: Jsonish = { a: [1, "hi", { nested: true }] };
console.log(Array.isArray((j as {a: unknown}).a)); // true — runtime check mirrors type honesty

// All above are erasable — npx tsc --strict --erasableSyntaxOnly --noEmit → ok (no TS1294)
// The one non-erasable contrast would be enum-as-recursive-enum — not expressible — enum is the wrong tool here.
```

// bad — generic recursion without an exposed budget passes review until the next consumer nests it once more
type DeepOmit<T, K extends PropertyKey> =
  T extends object ? Omit<{ [P in keyof T]: DeepOmit<T[P], K> }, K> : T;
// const probe: DeepOmit<{ a:{b:{c:{d:string}}}}, "never"> = { a:{b:{c:{d:"hi"}}}}; // works at depth 3, but at depth 12 with broad unions it approaches TS2589
// The bug — budget is invisible: reviewer cannot tell where TS2589 will fire.
// fix — add the tuple counter and JSDoc the budget:
/**
 * DeepOmit capped to 6 levels — deeper levels are returned as-is.
 * Budget: 6 — see MAX_COMMENT_DEPTH for value-level counterpart.

type DeepOmitCapped<T, K extends PropertyKey, D extends unknown[] = []> =
  D["length"] extends 6 ? T :
  T extends object ? Omit<{ [P in keyof T]: DeepOmitCapped<T[P], K, [...D, unknown]> }, K> : T;
const probeFixed: DeepOmitCapped<{ a:{b:{c:{d:string}}}}, "never"> = { a:{b:{c:{d:"hi"}}}};

**Common confusion** — "`interface` is always faster, so convert every recursive `type` to `interface`" — for the plain recursive *core* yes; for `type Jsonish = string | Jsonish[] | { [k:string]: Jsonish }` the union top *must* be a `type` (interfaces can't be unions) — split, don't force. "`MAX_DEPTH = 6` in code is redundant when the type already caps at 6" — complementary — the type cap prevents `TS2589`; the runtime guard prevents a 20-level payload from crashing `sumTree` with a stack overflow (range `Maximum call stack size exceeded`) even though the type permitted it. "`--erasableSyntaxOnly` changes recursion cost" — no — both spellings remain erasable; the flag only proves the recursion adds no emit — the performance story is checker graph size (see Performance). "`interface` hover `Category` hides the recursion" — hover *name* is short, but expanding (`Ctrl+hover` / `peek definition`) still shows the recursive `children: Comment[]` — visibility is on demand, not hidden.

**Performance note** — a shallow `interface` recursion (`ThreadComment` depth-6 payload) costs ~6 object-type nodes; the `DeepPartialCapped` at budget 6 on a 50-key API shape costs ~300 nodes (50 × 6) per instantiation — well under the ~50-depth `TS2589` ceiling and typically <5 ms in `tsc --extendedDiagnostics` `check time`. Remove the cap and instantiate the same `Deep<T>` on a 12-level `ApiConfig`-derived shape and the node count roughly doubles each level — 50 × 12 ≈ 600 nodes before hitting the ~50 instantiation ceiling, with hover latency jumping 2–3× and `trace.json` showing the type as a top `instantiations` symbol. No runtime, no GC, no allocation beyond checker graph — `interface` interning trims duplicate expansions, tuple-counter memoization trims identical `D` lengths. Guideline — keep app-level generic recursion ≤6–8, expose the number in the type name via JSDoc, and budget runtime recursion (`assertDepth`) to the same number so type and runtime converge.

**Mentor note** — make the budget visible in three places: (1) the type: `D["length"] extends 6` plus JSDoc "Budget: 6"; (2) the value: `MAX_DEPTH = 6` constant exported near the `interface`; (3) the review checklist: "any recursive `interface`/`type` lacking `| null` or `TupleDepth` gets a `// base:` comment". In review, enforce the grease: a PR that adds depth without bumping `MAX_DEPTH` must update both the type cap and the validator — otherwise block as "type/value promise drift". Exercise: hand a PR with `type DeepPick<T, K> = { [P in keyof T]: DeepPick<T[P], K> }` and ask to add a budget — the student should inject `D extends unknown[]` and a `D["length"] extends 6 ? T :` guard and add a `MAX_DEPTH` constant beside the `interface` that consumes it. Close with `tsc --erasableSyntaxOnly` proof — recursive shapes are zero-cost — the guard never jeopardizes stripping.
