## 2.3. Type queries on objects — keyof, indexed access and typeof capture

Type queries derive contracts from existing types or values. keyof supplies a static key union, T[K] reads a member type and type-position typeof captures a value's static type. Use them to keep related declarations aligned, while distinguishing that static view from runtime enumeration and validation.

Examples use TypeScript 7.0.2 and Node 20.20.2, verified 2026-10-13. Save each named file in a new directory without tsconfig.json. Run `tsc --strict --erasableSyntaxOnly --target es2022 --module commonjs --lib es2022,dom --outDir out FILE.ts`, then `node out/FILE.js`, substituting keys, values, capture or boundary. For an intentional rejection, uncomment only the indicated line and use the same compiler flags with `--noEmit` instead of `--outDir out`.

### 1) **Static keys, runtime keys and correlated member access**

A numeric property declared at key 0 contributes the numeric literal 0. A numeric index signature instead admits number keys broadly. A string index signature admits string | number here because numeric object keys can also be accessed through their string representation. The [primary keyof reference](https://www.typescriptlang.org/docs/handbook/2/keyof-types.html) distinguishes literal members and index signatures.

A static instance type can include a declared prototype method. That method need not appear in Object.keys, which enumerates own enumerable string properties. Therefore keyof is not a promise to enumerate only the object's own keys at runtime.

Save `keys.ts`:

```typescript
export {};
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type NumericLiteral = Expect<Equal<keyof { 0: string }, 0>>;
type NumericIndex = Expect<Equal<keyof { [key: number]: string }, number>>;
type StringIndex = Expect<Equal<keyof { [key: string]: number }, string | number>>;
class Example { value = 1; method(): void {} }
type InstanceKeys = Expect<Equal<keyof Example, "value" | "method">>;
const instance = new Example();
console.log("runtime keys:", Object.keys(instance).join(","), Object.hasOwn(instance, "method"), "method" in instance);

function get<T, K extends keyof T>(object: T, key: K): T[K] { return object[key]; }
const user = { id: "u1", age: 30 };
const age = get(user, "age");
const id = get(user, "id");
type Age = Expect<Equal<typeof age, number>>;
type Id = Expect<Equal<typeof id, string>>;
console.log("correlated:", age + 1, id.toUpperCase());
// get(user, "email"); // TS2345: key is not in this contract.
```

The live type assertions pass. Runtime prints `runtime keys: value false true` and `correlated: 31 U1`. The instance's method belongs to its static key union and is found by the in operation, but it is not an own property. get preserves the relationship between the selected key and its result: age is number while id is string. Activate email to observe TS2345 for a key outside this contract.

The [indexed-access reference](https://www.typescriptlang.org/docs/handbook/2/indexed-access-types.html) establishes T[K]. Runtime property ownership/enumeration belongs in [JavaScript objects](<../../../../JavaScript/06 Objects in Depth/sections/2. Properties and descriptors/2.3. Enumerability enumeration order and for-in mechanics.md>). Avoid casting Object.keys to every keyof T merely to quiet a checker: the runtime and static sets require justification. Structural values may also carry extra properties beyond the receiving type, as [object shape](<../1. Object Type Fundamentals/1.1. Object types structural shape and excess property checks.md>) demonstrates.

### 2) **Indexed value unions differ from Object.values calls**

T[keyof T] derives the union of member types described by T. An optional member can contribute undefined to that union because reading it may find no value. This is a type expression, rather than a call that gathers runtime values.

Object.values executes and returns own enumerable string-keyed values. Its library overloads are not universally unknown[]. This compiler's installed lib.es2017.object.d.ts declares a generic dictionary/ArrayLike overload returning T[] and an object fallback returning any[]. The call's input shape determines which useful precision is available.

Save `values.ts`:

```typescript
export {};
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type IsAny<T> = 0 extends (1 & T) ? true : false;
const numeric = Object.values({ a: 1, b: 2 });
type NumericValues = Expect<Equal<typeof numeric, number[]>>;
const mixed = Object.values({ a: 1, b: "x" });
type MixedValues = Expect<Equal<typeof mixed, (number | string)[]>>;
console.log("value arrays:", numeric.join(","), mixed.join(","));
interface Name { name: string }
const named: Name = { name: "Ada" };
const fallback = Object.values(named);
type FallbackElement = Expect<IsAny<typeof fallback[number]>>;
console.log("fallback:", fallback.join(","));

type Optional = { name: string; count?: number };
type ValueUnion = Optional[keyof Optional];
type OptionalValues = Expect<Equal<ValueUnion, string | number | undefined>>;
const read: ValueUnion = undefined;
console.log("optional type union:", read);
```

The assertions confirm number[] for the homogeneous literal, (number | string)[] for the mixed literal and an unchecked element type for this interface-shaped fallback. The output is `value arrays: 1,2 1,x`, `fallback: Ada` and `optional type union: undefined`. Recheck this file with --exactOptionalPropertyTypes: the read-union assertion still passes. That option changes some present-value assignments; it does not eliminate absence from an optional property read.

These overload observations are specific to the tested library and inputs. A precise indexed-access union does not automatically justify an assertion that every runtime value has that type. The [interface/dictionary distinction](<../1. Object Type Fundamentals/1.3. Interfaces vs type aliases when to use which.md>) and [optional/index members](<../1. Object Type Fundamentals/1.2. Optional readonly and index signatures.md>) explain the relevant surrounding contracts. Nicolas Charpentier's original [keys/entries discussion](https://www.charpeni.com/blog/properly-type-object-keys-and-object-entries) usefully highlights the assumptions needed around open object types. Its asserted helpers are not a blanket remedy; the exact current overloads and runtime observations here establish the narrower claims.

### 3) **Capture the static contract you intend**

A const binding preserves the object reference, but ordinary mutable properties can still infer broader primitive types. The exact object below combines as const with a satisfies check: its host/port remain literals and its property view is readonly. Type-position typeof reuses that contract; it does not inspect new runtime data or install a validator.

Save `capture.ts`:

```typescript
export {};
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
const plain = { host: "localhost", port: 5432 };
const exact = { host: "localhost", port: 5432 } as const satisfies { host: string; port: number };
type PlainHost = Expect<Equal<typeof plain.host, string>>;
type ExactHost = Expect<Equal<typeof exact.host, "localhost">>;
type ExactPort = Expect<Equal<typeof exact.port, 5432>>;
type Config = typeof exact;
function getConfig<K extends keyof Config>(key: K): Config[K] { return exact[key]; }
console.log("captured:", getConfig("host").toUpperCase(), getConfig("port") + 1);
function localHost(host: "localhost"): string { return host; }
console.log("literal contract:", localHost(exact.host));
// localHost(plain.host); // TS2345: string is broader than the literal.
// exact.port = 80; // TS2540: readonly view.
```

The output is `captured: LOCALHOST 5433` and `literal contract: localhost`. The assertions distinguish plain.host's string type from exact.host's literal and exact.port's numeric literal. Activate the plain-host call for TS2345, or the readonly write for TS2540. Neither typeof nor as const freezes this runtime object. Use a deliberately wider contract when callers should accept other hosts or ports, rather than treating literal precision as universally better.

Full widening/const-assertion/satisfies reasoning belongs in [literal types](<../../../03 Basic Types and Annotations/sections/3. Annotations Inference and Literals/3.3. Literal types and const assertions.md>) and [checked object contracts](<../1. Object Type Fundamentals/1.1. Object types structural shape and excess property checks.md>). These live assertions demonstrate the concrete captured types without relying on an unverified hover display.

### 4) **Erasure leaves runtime membership work visible**

A finite local table can supply related key and value types. At an untrusted boundary, the key union alone does not prove that input is a member. The following implementation checks a string and own membership against a frozen, locally constructed table. Freezing is an explicit runtime operation here; the const assertion alone would not perform it.

Save `boundary.ts`:

```typescript
export {};
const STATUS_MAP = Object.freeze({ pending: 0, done: 1, failed: 2 } as const);
type StatusMap = typeof STATUS_MAP;
type StatusKey = keyof StatusMap;
type StatusValue = StatusMap[StatusKey];
function isStatusKey(input: unknown): input is StatusKey {
  return typeof input === "string" && Object.hasOwn(STATUS_MAP, input);
}
function handle(input: unknown): StatusValue | undefined {
  if (!isStatusKey(input)) return undefined;
  return STATUS_MAP[input];
}
console.log("valid:", handle("done"));
console.log("inherited rejected:", isStatusKey("toString"), isStatusKey("constructor"));
console.log("malformed rejected:", isStatusKey(null), isStatusKey(1), isStatusKey({ key: "done" }));
console.log("runtime:", typeof STATUS_MAP, Object.isFrozen(STATUS_MAP));
// const wrong: StatusValue = 9; // TS2322: allowed values are 0 | 1 | 2.
```

The output is `valid: 1`, `inherited rejected: false false`, `malformed rejected: false false false` and `runtime: object true`. Activate wrong to observe TS2322. The guard rejects inherited names such as toString and constructor, as well as non-string inputs. It derives its promise from this fixed local table; accepting arbitrary external objects would require a different validation contract.

Inspect out/boundary.js: the StatusMap/StatusKey/StatusValue declarations are absent, while Object.freeze, Object.hasOwn, the guard and the actual value indexing remain. Run `npm exec --yes --package=node@22.18.0 -- node boundary.ts` to reproduce the same output through that tested native source path. No imported graph or unsupported syntax is involved in this particular source file; broader runner constraints have their [execution owner](<../../../01 Fundamentals and Mental Model/sections/3. Running TypeScript today/3.2. Executing TypeScript tsc plus node tsx ts-node and native Node stripping.md>).

For practice, compare changing a declared property, changing runtime ownership and changing an external input. A declared numeric literal member changes the static key union. A prototype method can remain in the static instance type while missing from Object.keys. A malformed external key does not become valid merely because a type alias names the desired keys. Explain the relevant operation before choosing a remedy.

### 5) **Common confusion**

Numeric literal keys and numeric index signatures have different keyof results. A declared prototype member is not necessarily an own enumerable runtime key. Object.values uses library overloads, rather than a universal unknown[] return. Finally, captured literal types, readonly views and runtime frozen objects are separate mechanisms; type queries create none of the runtime checks by themselves.

### 6) **Performance note**

The query declarations and equality probes erase. Enumeration, arrays returned by Object.values, freezing, membership checks and value access still execute. No startup-speed or checker/hover benchmark was measured here, and a key count does not establish a fixed union size or optimization threshold. Use the [measurement workflow](<../../../19 Performance Project References and Scaling/sections/1. Check-Time Performance/1.1. Measuring with extendedDiagnostics and traces.md>) when a derived contract contributes to a real checking problem; preserve its meaning when changing the representation.
