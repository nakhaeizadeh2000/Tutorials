## 3.2. Recursive generic types and self-referential patterns

A recursive data shape describes values containing more of that shape. A recursive type transform computes a new contract from an input type. A runtime traversal follows actual references. All three can involve recursion, but their stopping conditions and failures are different. A generic parameter adds a relationship to carry through the structure; it does not make the runtime graph finite or a type computation terminate.

Examples use TypeScript 7.0.2 and Node.js 20.20.2. Save each independent TypeScript fence under its filename and compile with `tsc --strict --exactOptionalPropertyTypes --noUncheckedIndexedAccess --erasableSyntaxOnly --removeComments --target es2022 --module commonjs --lib es2022,dom --outDir dist FILE.ts`; run `node dist/FILE.js`. Activate commented negatives separately and check with the same flags plus `--noEmit` instead of `--outDir dist`.

### 1) **Legal recursive shapes carry a parameter**

Nested<T> permits a T leaf or an array containing more Nested<T> values. Tree<T> carries the same payload type through its children. These declarations describe accepted structure; they do not eagerly create every level. A bare circular alias supplies no such usable structure and is rejected. The [primary 3.7 notes](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-3-7.html#more-recursive-type-aliases) describe the relaxation for recursive array and tuple aliases.

Save as `shapes.ts`.

```typescript
type Nested<T> = T | Nested<T>[];
const nested: Nested<number> = [1, [2, [3]]];
console.log(JSON.stringify(nested));
interface Tree<T> { payload: T; children: Tree<T>[] }
const root: Tree<string> = { payload: "root", children: [{ payload: "leaf", children: [] }] };
console.log(root.children[0]?.payload.toUpperCase());
// const wrong: Tree<string> = { payload: "root", children: [{ payload: 42, children: [] }] }; // TS2322
// type Bare<T> = Bare<T>; // TS2456
// type BareUnion<T> = T | BareUnion<T>; // TS2456
// type ThroughRecord<T> = Record<string, ThroughRecord<T>>; // TS2456: not every wrapper route is legal

const cycle: Tree<string> = { payload: "cycle", children: [] };
cycle.children.push(cycle); // Accepted finite graph with one object pointing back to itself.
console.log(cycle.children[0] === cycle);
try { JSON.stringify(cycle); }
catch (error) { console.log(error instanceof TypeError ? "cyclic serialization: TypeError" : "unexpected error"); }
```

The output is `[1,[2,[3]]]`, `LEAF`, `true`, then `cyclic serialization: TypeError`. The payload relationship rejects a numeric child in Tree<string>. The cyclic fixture still satisfies that relationship, so recursive typing alone cannot make serialization or a naive traversal terminate.

“Wrap the reference” is a useful starting intuition, not a universal legality or termination rule. The negative Record alias shows a rejected route through another generic alias. Choose a supported direct object/array structure for the model and check the actual declaration. [Recursive objects](<../../../04 Objects Interfaces and Type Aliases/sections/3. Advanced Object Types/3.1. Recursive object types and self-referential structures.md>) owns recursive syntax, finite cycles and runtime traversal policies; reuse its graph/tree distinction rather than assuming every Tree-typed value is acyclic. Validate unknown input separately.

### 2) **Recursive transformations need leaf and container policies**

A mapped recursive type can produce a readonly *view*. It does not freeze its input. A naive object branch also transforms functions and built-in instances as if their properties were plain data, potentially losing their callable contracts. That is a semantic failure, not harmless extra recursion.

Save as `views.ts`.

```typescript
type Naive<T> = T extends object ? { readonly [K in keyof T]: Naive<T[K]> } : T;
type ReadonlyDataView<T> = T extends Date | ((...args: never[]) => unknown) ? T
  : T extends object ? { readonly [K in keyof T]: ReadonlyDataView<T[K]> } : T;
type Config = { db: { host: string; ports: number[] }; format: (value: number) => string; created: Date };
const source: Config = {
  db: { host: "local", ports: [5432] },
  format: value => value.toFixed(0),
  created: new Date("2026-01-01T00:00:00Z"),
};
const naive: Naive<Config> = source;
console.log(typeof naive.format, typeof naive.created.toISOString);
// naive.format(3); // TS2349: mapped properties lost this callable signature
// naive.created.toISOString(); // TS2349: Date's mapped method lost its callable signature
const view: ReadonlyDataView<Config> = source;
console.log(view.format(3), view.created.toISOString(), view.db.ports.join(","));
// view.db.host = "remote"; // TS2540
// view.db.ports.push(1234); // TS2339: homomorphic readonly mapping makes this array readonly
source.db.host = "changed";
view.created.setUTCFullYear(2027); // Date is an explicit unchanged leaf; mutation still exists.
console.log(view.db.host, view.created.getUTCFullYear(), view === source, Object.isFrozen(view));
```

The output is `function function`, `3 2026-01-01T00:00:00.000Z 5432`, then `changed 2027 true false`. The naive view still refers to actual runtime functions, but its static transformation discarded their call signatures. ReadonlyDataView deliberately preserves functions and Date, so those operations remain callable. Its plain object and array branches publish readonly members; the source alias can still mutate the shared object, and Date remains mutable under the chosen leaf policy.

This is a limited demonstration for the shown plain data objects, arrays/tuples, functions and Date leaves. It is not a complete deep-readonly library for Map, Set, custom classes or every callable's attached properties. [Mapped types](<../../../09 Utility Types and Type Transformations/sections/1. Mapped Types/1.1. Mapped type fundamentals homomorphic mapping over keys.md>) owns homomorphic array handling; [deep transforms](<../../../09 Utility Types and Type Transformations/sections/3. Transformations in Practice/3.1. Deep transforms DeepPartial DeepReadonly and the budget.md>) owns fuller leaf/container choices. A generic recursive shape and a recursive mapped computation serve different purposes even when both pass T to another level.

### 3) **A local cap changes the transform's result**

Recursive conditional types can evaluate repeatedly until a non-matching case or an explicit stop. TypeScript 4.1 introduced the direct recursive conditional patterns explained in [its release notes](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-1.html#recursive-conditional-types). A self-referential wrapper can keep matching forever and trigger TS2589 even without a large finite object fixture. Conversely, a small object nesting count is not a universal threshold for that diagnostic.

Save as `budgets.ts`.

```typescript
type Unwrap<T> = T extends PromiseLike<infer Value> ? Unwrap<Value> : T;
type Loop = PromiseLike<Loop>;
// type Runaway = Unwrap<Loop>; // TS2589: this input never leaves the matching wrapper

type Depth = 0 | 1 | 2 | 3;
type Previous = [0, 0, 1, 2];
type BoundedUnwrap<T, D extends Depth = 2> = D extends 0 ? T
  : T extends PromiseLike<infer Value> ? BoundedUnwrap<Value, Previous[D]> : T;
type Deep = Promise<Promise<Promise<number>>>;
type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type Full = Expect<Equal<Unwrap<Deep>, number>>;
type Zero = Expect<Equal<BoundedUnwrap<Deep, 0>, Deep>>;
type Two = Expect<Equal<BoundedUnwrap<Deep>, Promise<number>>>;
type Three = Expect<Equal<BoundedUnwrap<Deep, 3>, number>>;
type StopsOnCycle = BoundedUnwrap<Loop>; // Accepted: the local counter stops the descent.
// type Unsupported = BoundedUnwrap<Deep, number>; // TS2344: supply a supported literal choice
// type Negative = BoundedUnwrap<Deep, -1>; // TS2344
console.log("finite type results checked");
```

The program prints `finite type results checked` after the four live assertions compile. The default two-step transform leaves Promise<number>; a zero-step transform leaves the original Deep type, and three steps reach number. The stop branch returns the remaining T. It does not reject deeper inputs, validate runtime promise depth or necessarily produce a completely unwrapped value.

The small supported Depth set is this teaching API's explicit choice, not a compiler limit or production recommendation. It rejects broad number and negative values rather than silently treating them as an unbounded counter. Standard Awaited is normally the right utility for actual await-result modeling; [infer extraction](<../2. Constraints Defaults and Inference Control/2.3. infer conditional inference and distributive preview.md>) explains its distinction from a shallow Promise matcher.

For a real TS2589 failure, first reproduce the input and decide the result contract. A semantic cap, a different expansion shape or a narrower input scope may help, but none automatically preserves the original result. [Instantiation budgets](<../../../19 Performance Project References and Scaling/sections/1. Check-Time Performance/1.2. Instantiation budgets and TS2589 carve-outs.md>) owns a finite failing fixture, accumulator contrast and measurement workflow. Philipp Dehler's [recursion-workaround article](https://www.esveo.com/en/blog/how-to-workaround-the-max-recursion-depth-in-typescript/) compares expansion shapes and maintainability trade-offs; its historical numeric limits are not a supported depth promise for this compiler or every utility.

### 4) **Common confusion**

A recursive shape can represent a cycle with finitely many objects. A recursive conditional can also fail during checking even when no runtime traversal exists. TS2456 at a circular alias, TS2589 during a computation and TypeError from serializing a cyclic value identify different operations and need different remedies.

Readonly transformation is also not runtime freezing. A Date carve-out preserves useful methods and their mutating capabilities; an alias can retain other write paths. Choose what the transform promises instead of claiming that recursing through every object automatically makes all leaves immutable.

### 5) **Performance note**

Type-level recursion erases. The shape example constructs arrays/objects and attempts JSON serialization; the view example uses the same objects, calls functions and mutates a Date. Those operations are independent of the type computation's cap. Runtime traversal limits still depend on the actual graph and algorithm.

No formula equating source nesting to cached instantiations, property count to checker work or a local cap to a universal timing bound was measured. Width, distribution, deferred evaluation and the operation requesting expansion can matter. Use the measurement owner for actual counters and timings; these examples establish checking results and semantic boundaries only.

### 6) **Mentor note**

Have the learner identify whether each failure belongs to declaration legality, value construction, runtime traversal or type computation before suggesting a fix. Ask why cycle has only one object, yet JSON.stringify fails. Then remove the Date/function leaf branch and explain the rejected method calls without claiming the runtime functions disappeared.

For a cap exercise, compare BoundedUnwrap<Deep, 1> with the shown zero/two/three results. One step must leave Promise<Promise<number>>. Verify that result with a live type assertion and explain the unchanged remainder at the stop branch. Do not describe the cap as a runtime recursion guard or assume it guarantees every other type computation stays below the compiler's safeguards.
