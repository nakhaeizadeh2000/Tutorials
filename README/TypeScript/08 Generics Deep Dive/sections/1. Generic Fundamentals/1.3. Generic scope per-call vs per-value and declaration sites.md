## 1.3. Generic scope — per-call versus per-value and declaration sites

Place a type parameter where the caller should choose it. A generic call signature allows a fresh choice at each call. A container parameter relates its members through a chosen type argument. One API can combine both scopes: a bag keeps its element contract while each map call selects a new result type.

Examples use TypeScript 7.0.2 and Node.js 20.20.2. Save each independent TypeScript fence under its filename and compile with `tsc --strict --exactOptionalPropertyTypes --noUncheckedIndexedAccess --erasableSyntaxOnly --removeComments --target es2022 --module commonjs --lib es2022,dom --outDir dist FILE.ts`. Run `node dist/FILE.js`. Activate each commented negative individually and recheck with the same flags plus `--noEmit` instead of `--outDir dist`.

### 1) **Per-call scope**

The parameter belongs to a generic call signature, even when the callable value is stored in an interface-typed variable. Putting a parameter on the interface itself instead supplies that choice when the interface is used. The [primary generic-types explanation](https://www.typescriptlang.org/docs/handbook/2/generics.html#generic-types) compares these two positions.

Save as `calls.ts`.

```typescript
interface EveryCall { <T>(value: T): T }
interface FixedCall<T> { (value: T): T }
const identity: EveryCall = value => value;
const text = identity("Ada");
const number = identity(42); // The previous call did not lock the signature to string.
const strings: FixedCall<string> = identity;
console.log(text.toUpperCase(), number.toFixed(1), strings("hi").toUpperCase());
// strings(42); // TS2345: the exposed signature accepts string
// const universal: EveryCall = strings; // TS2322: string-only is not every admitted T

function mapValues<T, U>(values: readonly T[], transform: (value: T) => U): U[] {
  return values.map(transform);
}
const names = mapValues([{ name: "Ada" }], value => value.name);
const lengths = mapValues(["a", "bb"], value => value.length);
console.log(names.join(","), lengths.join(","));
// names.map(value => value.toFixed(0)); // TS2551: names contains strings
function uncheckedMap(values: any[], transform: (value: any) => any): any[] {
  return values.map(transform);
}
const unchecked = uncheckedMap([1], value => String(value)); // Actually returns strings.
try { unchecked[0].toFixed(0); }
catch (error) { console.log(error instanceof TypeError ? "unchecked map: TypeError" : "unexpected error"); }
```

The output is `ADA 42.0 HI`, `Ada 1,2`, then `unchecked map: TypeError`. EveryCall supports multiple type choices through the same value. FixedCall<string> exposes only the string contract even though the assigned implementation can do more. MapValues relates input element T, callback input T and callback result U; the actual callback supplies the evidence for U. An unconstrained U is not arbitrary runtime permission to fabricate a result of whichever type a reader requests.

The unchecked mapper's string result is deliberate: calling toFixed on that actual string fails. A mapper returning a number would not demonstrate that failure. [Function generics](<../../../05 Functions and Callable Types/sections/2. Overloads and Generics/2.2. Generic functions inference constraints defaults and scope.md>) owns the basic mapping relationship; [inference control](<./1.2. Inference from arguments and explicit type arguments.md>) owns candidate selection and explicit type arguments.

### 2) **Per-value scope**

A bag's element contract must connect writes with later reads. A reader cannot safely choose a fresh T with no evidence about what an earlier writer stored. The container parameter provides that connection, while a method's own U can describe a transformation or fallback.

Save as `storage.ts`.

```typescript
class Bag<T> {
  private items: T[];
  constructor(items: readonly T[]) { this.items = [...items]; }
  add(value: T): void { this.items.push(value); }
  first(): T | undefined { return this.items[0]; }
  firstOr<U>(fallback: U): T | U {
    const value = this.items[0];
    return value === undefined ? fallback : value;
  }
  map<U>(transform: (value: T) => U): Bag<U> {
    return new Bag(this.items.map(transform));
  }
  // addAnything<U>(value: U): void { this.items.push(value); } // TS2345: fresh U need not be T
}
const numbers = new Bag([1, 2]);
numbers.add(3);
console.log(numbers.first(), numbers.firstOr("none"));
const labels = numbers.map(value => `n=${value}`);
const positives = numbers.map(value => value > 0);
console.log(labels.first(), positives.first());
console.log(new Bag<number>([]).firstOr("none"), new Bag<null>([null]).firstOr("none"));
// numbers.add("old"); // TS2345: this member view still expects number
// labels.add(false); // TS2345: this result bag expects string

class LooseBag {
  private items: unknown[] = [];
  add<T>(value: T): void { this.items.push(value); }
  read<T>(index: number): T | undefined { return this.items[index] as T | undefined; }
}
const loose = new LooseBag();
loose.add("hello");
try { loose.read<number>(0)?.toFixed(1); }
catch (error) { console.log(error instanceof TypeError ? "reader guess: TypeError" : "unexpected error"); }
```

The output is `1 1`, `n=1 true`, `none null`, then `reader guess: TypeError`. Numbers keeps a numeric write/read relationship; its two map calls independently create string and boolean bags. FirstOr treats an undefined indexed result as missing and preserves null as a stored value. If null should also mean missing, that is a separate API policy, not a consequence of generic scope. Empty-array inference is another separate choice, so the empty fixture explicitly supplies number.

LooseBag stores unknown values but lets the reader request number without establishing it. The assertion hides that missing connection. It compiles and then calls a numeric method on the stored string. A fixed container contract is the appropriate repair for a homogeneous bag; a deliberately heterogeneous store would instead need honest unknown results or key-specific runtime evidence.

“Fixed” describes the contract through this typed view. It does not freeze runtime data, attach a runtime type argument or prove every possible alias safe. Assignments between broader/narrower views depend on structural compatibility and [variance](<../../../02 The Type System Core/sections/3. Soundness and variance/3.1. Covariance contravariance and invariance who varies which way.md>); they are not determined by the parameter's name. Through the shown numbers view, numeric values can change while the accepted member type stays number.

### 3) **Choose the declaration site from the relationship**

A generic alias computes a reusable contract at a type reference. A generic function or method allows call-time choices. A generic class or interface can connect multiple members through one supplied type argument. These are composable choices, not a rule that functions are always better than generic classes or every generic method on a non-generic class is wrong.

Save as `design.ts`.

```typescript
type Envelope<T> = { data: T; etag: string };
const response: Envelope<number> = { data: 7, etag: "v1" };
console.log(response.data.toFixed(0), response.etag);

class Formatter<T> {
  private prefix: string;
  private format: (value: T) => string;
  constructor(prefix: string, format: (value: T) => string) {
    this.prefix = prefix;
    this.format = format;
  }
  render(value: T): string { return this.prefix + this.format(value); }
}
const numeric = new Formatter<number>("n:", value => value.toFixed(1));
console.log(numeric.render(2), numeric.render(3)); // Reuses real runtime configuration.
// numeric.render("hello"); // TS2345

class Tools {
  transform<T, U>(value: T, format: (value: T) => U): U { return format(value); }
}
const tools = new Tools();
console.log(tools.transform(3, value => value * 2));
console.log(tools.transform("Ada", value => value.toUpperCase()));
```

The output is `7 v1`, `n:2.0 n:3.0`, `6`, then `ADA`. Formatter has a reason to retain a fixed input contract: it stores a matching callback and prefix for repeated renders. Tools' method has no stored payload contract to preserve, so fresh parameters legitimately connect each input with its transformation. A standalone transform function could express the same operation; choose from the surrounding API's needs rather than assuming the class form is intrinsically unsafe.

The [Golden Rule discussion](https://effectivetypescript.com/2020/08/12/generics-golden-rule/) examines moving an unnecessarily class-wide parameter nearer its use. Apply the underlying relationship question, including stored state and callbacks, rather than extending one example into a ban on configured generic transforms. [Declaration and erasure](<./1.1. Type parameters declaration instantiation and erasure.md>) owns the site inventory and shared runtime constructor proof. A static factory also needs its own parameter, as taught by [static members and generics](<../../../06 Classes and Object-Oriented Types/sections/3. Advanced Class Patterns/3.1. Static members generics and static blocks.md>); it cannot borrow an instance's T.

### 4) **Common confusion**

An interface can contain a generic call signature, and a class can contain a generic method. Their parameters need not be declared on the outer interface or class. Moving a parameter changes which choice is available to the caller; changing its letter does not.

A fixed member contract also does not imply immutability. Numbers can accept another number, and a mapping operation can create a different bag with its own contract. Conversely, a fresh generic read method does not learn what a previous write stored merely because both methods use the name T.

### 5) **Performance note**

All the parameter choices erase. The bag still copies its input array, add still mutates it, map constructs a new result bag, and Formatter still stores runtime configuration and calls its callback. Those operations follow the implementation, not the lifetime of a type parameter.

No cache-entry count, hover-latency ranking or maximum nesting depth was measured here. Reusing an alias may improve readability without proving any checker-speed benefit. For a real performance question use [the measurement owner](<../../../19 Performance Project References and Scaling/sections/1. Check-Time Performance/1.1. Measuring with extendedDiagnostics and traces.md>) and compare the same behavioral contract.

### 6) **Mentor note**

Ask who chooses each parameter and which values it relates. The caller of EveryCall selects a fresh choice; the FixedCall<string> view permits only strings. Bag's T connects stored elements with reads and writes, while map's U comes from that call's callback. LooseBag's reader-selected T has no such evidence.

For a design exercise, add `last(): T | undefined` to Bag and keep the same element contract. Verify an empty bag, the bag after add, and both mapped bags. The implementation should read the existing final element rather than introduce `last<U>()` and ask the reader to guess. Then justify whether a configured formatter in your application benefits from an instance or is clearer as a factory returning a function; both can preserve the same relationship.
