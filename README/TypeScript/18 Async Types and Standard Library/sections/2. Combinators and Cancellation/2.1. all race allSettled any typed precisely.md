## 2.1. all race allSettled any typed precisely

Promise combinators observe supplied values and promises; they do not turn task functions into a scheduler. Calling functions while constructing an input array may already start their work. Choose the aggregate outcome you need, then decide separately how work starts, how much may run together and who owns cleanup.

Use **TypeScript 7.0.2** and **Node.js 20.20.2**, verified 2026-10-17. Create the three named files together in a directory without a tsconfig. Compile each demonstration with `tsc --strict --target es2022 --module nodenext --outDir dist FILE.mts`; its imported control file is included. Run `node dist/FILE.mjs`. All operations are local, controlled promises; there are no network timings to infer.

### 1) **Preserve input positions without claiming atomicity**

For a tuple input, Promise.all maps each position through Awaited and removes readonly from the result tuple. A direct array literal can receive tuple context from its overload; as const is not always required. A previously widened heterogeneous array has already lost those fixed positions.

```typescript
// file: control.mts
export function controlled<T>() {
  let resolve!: (value: T | PromiseLike<T>) => void;
  let reject!: (reason?: unknown) => void;
  const promise = new Promise<T>((yes, no) => { resolve = yes; reject = no; });
  return { promise, resolve, reject };
}
```

```typescript
// file: all.mts
import { controlled } from "./control.mjs";
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
const first = controlled<string>();
const second = controlled<number>();
const completed: string[] = [];
const trackedFirst = first.promise.then((v) => { completed.push("first"); return v; });
const trackedSecond = second.promise.then((v) => { completed.push("second"); return v; });
const inputs = [trackedFirst, trackedSecond] as const;
const aggregate = Promise.all(inputs);
second.resolve(2);
first.resolve("first");
const tuple = await aggregate;
if (completed.join(",") !== "second,first" || tuple[0] !== "first" || tuple[1] !== 2) {
  throw new Error("input order versus completion order");
}
tuple[1] = 3; // The readonly input does not make this result tuple readonly.
if (tuple[1] !== 3) throw new Error("result mutability");
const inline = Promise.all([Promise.resolve("name"), Promise.resolve(2)]);
const widenedInputs = [Promise.resolve("name"), Promise.resolve(2)];
const widened = Promise.all(widenedInputs);
await inline; await widened;
type Shapes = [
  Expect<Equal<typeof aggregate, Promise<[string, number]>>>,
  Expect<Equal<typeof inline, Promise<[string, number]>>>,
  Expect<Equal<typeof widened, Promise<(string | number)[]>>>
];
const starts: string[] = [];
function start(name: string): Promise<string> { starts.push(name); return Promise.resolve(name); }
const alreadyStarted = [start("a"), start("b")];
if (starts.join(",") !== "a,b") throw new Error("start boundary");
await Promise.all(alreadyStarted);
const failing = controlled<never>();
const releaseSibling = controlled<void>();
let sideEffect = false;
const sibling = releaseSibling.promise.then(() => { sideEffect = true; return "sibling done"; });
const failed = Promise.all([failing.promise, sibling]).catch((reason: unknown) => reason);
failing.reject("failed input");
if (await failed !== "failed input" || sideEffect) throw new Error("fail-fast boundary");
releaseSibling.resolve();
if (await sibling !== "sibling done" || !sideEffect) throw new Error("sibling was cancelled");
console.log("completion second,first; tuple first,2; mutable result; sibling continued");
```

The printed line follows all assertions. Input order determines the tuple even though second completes first. The aggregate rejects after the failed input while the controlled sibling remains pending; releasing that sibling still performs its side effect. Promise.all did not cancel it or roll back anything. Fail-fast observation is not a transaction or an all-or-nothing side-effect guarantee.

The starts check occurs before Promise.all receives that array: the calls started the operations. A lazy iterable could start work while being consumed, but the combinator still supplies no concurrency limit. [Jake Archibald's original composition example](https://web.dev/articles/promises) separates mapping operations from collecting their input-ordered results. The [primary all algorithm](https://tc39.es/ecma262/multipage/control-abstraction-objects.html#sec-promise.all) records results by their input indices.

For a static contrast, replace inline's expected tuple in Shapes with Promise<(string | number)[]>: the strict equality gate fails with TS2344. Restore it. Both shapes are useful; the test demonstrates the actual inferred distinction rather than a universal requirement to assert every batch as a tuple.

### 2) **Distinguish first settlement from first fulfillment**

With normally consumed inputs, race observes the first settlement, including rejection. Any waits for a fulfillment unless every input rejects, when it rejects with AggregateError. Their fulfillment types are unions of the awaited input member types, not descriptions of the winner's position or possible rejection classes.

```typescript
// file: outcomes.mts
import { controlled } from "./control.mjs";
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
const early = controlled<string>();
const later = controlled<number>();
const raced = Promise.race([early.promise, later.promise]);
const anySuccess = Promise.any([early.promise, later.promise]);
const raceOutcome = raced.catch((reason: unknown) => reason);
early.reject("early failure");
if (await raceOutcome !== "early failure") throw new Error("race should reject first");
later.resolve(23);
if (await anySuccess !== 23) throw new Error("any should accept later fulfillment");
const a = controlled<never>();
const b = controlled<never>();
const allFailed = Promise.any([a.promise, b.promise]).catch((reason: unknown) => {
  if (!(reason instanceof AggregateError)) throw reason;
  const errors: unknown[] = reason.errors;
  return errors;
});
b.reject("B"); a.reject("A");
const reasons = await allFailed;
if (!Array.isArray(reasons) || reasons.join(",") !== "A,B") throw new Error("input-ordered reasons");

const settledPromise = Promise.allSettled([Promise.resolve("ok"), Promise.reject<number>(17)] as const);
const settled = await settledPromise;
if (settled[0].status !== "fulfilled" || settled[0].value !== "ok") throw new Error("fulfilled member");
if (settled[1].status !== "rejected") throw new Error("rejected member");
const reason: unknown = settled[1].reason;
if (reason !== 17) throw new Error("arbitrary rejection value");
// const uncheckedValue = settled[1].value; // Checking rejects success-only access here.
type Shapes = [
  Expect<Equal<typeof raced, Promise<string | number>>>,
  Expect<Equal<typeof anySuccess, Promise<string | number>>>,
  Expect<Equal<typeof settledPromise, Promise<[PromiseSettledResult<string>, PromiseSettledResult<number>]>>>
];
const emptyAll: [] = await Promise.all([]);
const emptySettled: [] = await Promise.allSettled([]);
if (emptyAll.length || emptySettled.length) throw new Error("empty aggregates");
const emptyAny = await Promise.any([]).catch((error: unknown) => {
  if (!(error instanceof AggregateError)) throw error;
  return error.errors.length;
});
if (emptyAny !== 0) throw new Error("empty any reasons");
let emptyRaceSettled = false;
Promise.race([]).then(() => { emptyRaceSettled = true; }, () => { emptyRaceSettled = true; });
await new Promise<void>((resolve) => setTimeout(resolve, 0));
if (emptyRaceSettled) throw new Error("empty race settled");
const broken: Iterable<Promise<number>> = {
  [Symbol.iterator](): Iterator<Promise<number>> { throw new Error("iterator failed"); },
};
const iterationFailure = await Promise.allSettled(broken).catch((error: unknown) => {
  if (!(error instanceof Error)) throw error;
  return error.message;
});
if (iterationFailure !== "iterator failed") throw new Error("iteration failure not propagated");
console.log("race rejected; any 23; reasons A,B; settled ok/17; empty cases; iterator rejected");
```

Compile and execute outcomes.mts. Its final line is printed. The early rejection settles race while any remains able to use the later success. The total-failure case rejects the inputs in B/A order but receives A/B reasons in input order. Those reasons can be arbitrary values; AggregateError does not turn them all into Error instances.

The example uses no socket or timeout loser. It deliberately completes its controlled inputs. For real work, decide whether a losing operation should continue, be cancelled or finish with independent ownership. A race chooses an aggregate result; cancellation needs cooperation from the operation, as the [signal owner](<./2.2. AbortSignal propagation and cancellation contracts.md>) and [actual cleanup tests](<../../../17 Testing Types/sections/2. Typed Test Doubles/2.3. Testing async and error paths with types.md>) explain.

### 3) **Read allSettled's guarantee at the correct boundary**

AllSettled turns ordinary input rejections into rejected-member records and waits for all inputs to settle. An input that remains pending prevents the complete result from arriving. Its rejected reason field is any in the current standard declaration; the fixture explicitly narrows it through an unknown view before use.

It is not a universal never-rejecting operation. Outcomes.mts supplies a well-typed iterable whose iterator throws; the aggregate rejects with iterator failed. The [specification](https://tc39.es/ecma262/multipage/control-abstraction-objects.html#sec-promise.allsettled) propagates failures while obtaining and consuming the iterable as aggregate rejection. Member failure records and protocol/setup failure are different boundaries. Similar iteration failures can affect the other combinators too.

The empty-input behavior is also part of the contract:

| Operation | Empty input outcome |
|---|---|
| all | Fulfills with an empty array |
| allSettled | Fulfills with an empty array |
| any | Rejects with AggregateError whose errors array is empty |
| race | Remains pending |

The race assertion observes it through a later task; the specification supplies the indefinite pending rule for this empty input. A finite test run alone cannot prove that arbitrary work will remain pending forever. Empty all and allSettled are already fulfilled, while their attached reactions still run asynchronously.

### 4) **Common confusion**

Concurrency, aggregation and transactionality are separate. Promise.all does not execute task functions passed as values, create a concurrency limit or undo completed side effects. Starting many operations in map can create the resource pressure before aggregation begins. Choose sequential or bounded work when dependencies, capacity or ordering require it.

A rejected all result does not expose a list of successful siblings, but those siblings may already have performed useful or harmful work. AllSettled exposes normal per-input outcomes; it does not automatically implement retries, cancellation or a rollback policy. Choose the aggregate from the required information, not an atomic-versus-best-effort slogan.

### 5) **Performance note**

Aggregates retain state and attach reactions to inputs; actual operations consume their own resources. AllSettled waits for every settlement, while race can settle much earlier without stopping other work. This fixture measures no latency sum/max formula, fixed allocation count or universal threshold for pooling. Choose concurrency from dependencies and capacity, then measure actual throughput, latency and memory.

### 6) **Mentor note**

Ask which action starts each operation, why completion order differs from tuple order and what still runs after fail-fast rejection. Then compare early failure under race and any, and distinguish a rejected member from an iterable that throws. Require a prediction and observed assertion for the bounded example, with an explicit limit on what it proves.
