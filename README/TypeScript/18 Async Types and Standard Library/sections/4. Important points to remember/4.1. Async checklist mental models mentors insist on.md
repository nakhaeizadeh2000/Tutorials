## 4.1. Async checklist — mental models mentors insist on

### 1) **Await unwraps, combinators shape** (Awaited at positions, tuples-unions at combinators)

**Definition** — the first check: every `await` position understood as `Awaited<T>` (consumed shapes probed per 1.2 — `Awaited<ReturnType<...>>` identity, not `Promise`-wrapped guesses); every combinator understood as a shape operator (`all`→tuples, `race`/`any`→unions, `allSettled`→settled unions per 2.1). Two mechanics, composed at every async call site.

**What problem it solves / history** — `Promise`-wrapped probes (wrapping asserted, consumption untested) and combinator-shape surprises (`all` expected positional, `race` losers expected cleaned): the check converts both into stated-then-probed contracts (positions unwrapped, shapes named — drift red at the probe).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), probe awaited shapes on every public async export (17/4.1 part 1 for async); annotate combinator results where inference loses positions (explicit tuples over `as const` inputs — 2.1 discipline).

**Runnable example** — positions and shapes stated (good vs bad, `tsc --strict`):

```typescript
// good — awaited probe plus tuple combinator (both mechanics stated — positions unwrapped, shapes positional)
export {}; // module marker (top-level await below needs module scope)
async function a(): Promise<string> { return "a"; }
async function b(): Promise<number> { return 1; }
type Equal<X, Y> = (<T>() => T extends X ? 1 : 2) extends (<T>() => T extends Y ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
type A = Awaited<ReturnType<typeof a>>; // alias (no >>> closers — 17/3.1 lesson)
type B = Awaited<ReturnType<typeof b>>;
assertType<Equal<A, string>>(); // position unwrapped (consumed shape pinned)
assertType<Equal<B, number>>(); // position unwrapped (consumed shape pinned)
const pair = await Promise.all([a(), b()] as const); // tuple (combinator shaping — positional results)
console.log(pair.join(",")); // a,1 — mechanics composed (Awaited at positions, tuples at combinators)
// bad — Promise-probes plus union-results (wrapping asserted, positions lost — consumption untested, slots untyped)
// fix — Awaited probes + tuple combinators (consumed shapes pinned, results positional — both mechanics explicit)
```

**Common confusion** — "one mechanic suffices" — positions (Awaited) and shapes (combinators) compose (unwrapped values flowing into shaped results — each check covering what the other cannot). "inference covers combinators" — inference covers *homogeneous* combinators (unions collapsing); heterogeneous tuples need `as const`/annotations (positions preserved deliberately).

**Performance note** — probes one instantiation each (microseconds); tuple annotations zero-cost (erased — 01/2.1).

**Mentor note** — async-export review: "Awaited-probed? Combinator-shaped?" (two questions — mechanical, blocking).

### 2) **Cancel via signals, never via flags** (propagation typed through parameters)

**Definition** — the second check: every cancellable signature threads `signal?: AbortSignal` (data, not globals — 2.2); every abort carries a reason (causality, not bare `abort()`); every catch routes aborts separately from failures (quiet stops vs loud retries — 2.2 part 2). Flags unrepresentable (no boolean-cancellation in reviewed code).

**What problem it solves / history** — flag-races (set-vs-read interleavings untestable), bare aborts (handlers guessing intent), retried cancellations (abort-retry storms — the classic abort bug): signals + reasons + routing deleting the class structurally.

**Modern guidance** — signal parameters on cancellables (convention — last, optional); `throwIfAborted` at entries (fail-fast); reason-identity in catches (routing); linked trees for shutdown (cascade — 2.2 part 1).

**Runnable example** — signal discipline (good vs bad, `tsc --strict`):

```typescript
// good — cancellable signature (signal threaded — data, not ambient)
export {}; // module marker (top-level await below needs module scope)
async function work(id: string, signal?: AbortSignal): Promise<string> {
  signal?.throwIfAborted(); // fail-fast (aborted-before-start rejecting — causality via reason)
  return `done:${id}`;
}
console.log(await work("w1")); // done:w1 — signals threaded (optional — uncancelled callers unaffected, cancellable callers enabled)
// bad — cancel flags (ambient booleans — races, forgotten resets, untestable interleavings)
// fix — signal parameters (protocol standardized — state + events + reason in one object)
```

**Common confusion** — "signals for internal functions" — signals at *cancellation boundaries* (I/O, timers, cross-module — internal pure computation uncancelled, correctly). "optional signals weaken contracts" — optional signals *widen* acceptance (uncancelled callers compiling — cancellability additive, never required).

**Performance note** — unobserved signals cost one parameter (nothing); `throwIfAborted` nanoseconds (check freely).

**Mentor note** — signature review: cancellable-without-signal is uncancellable (missing parameter = missing feature — request changes).

**Cross-links** — signal mechanics → [2.2. AbortSignal](<../2. Combinators and Cancellation/2.2. AbortSignal propagation and cancellation contracts.md>); abort doubles → [2.3. Async error paths](<../../../17 Testing Types/sections/2. Typed Test Doubles/2.3. Testing async and error paths with types.md>).

### 3) **Parallel by default, sequential by reason** (independence batched, order justified)

**Definition** — the third check: independent operations batched (`Promise.all` — 2.3 part 2 norm); serialization carrying a reason comment (order/quota/dependence — 2.3 part 1); dynamic fan-out bounded (pools past dozens — 2.3 part 3). Performance as a typed decision (latency maxed vs summed vs tuned — each shape chosen, none accidental).

**What problem it solves / history** — habitual serialization (latency summed for no reason — the highest-ROI async refactor class) and unbounded fan-out (collapse at scale — the 5.1 exhaustion class): defaults batching, exceptions justifying, bounds designing.

**Modern guidance** — `Promise.all` default (independence assumed until dependence shown); reason comments on loops (serialization justified in text — surviving parallelization cleanups); pools past dozens (K tuned per downstream — throughput designed).

**Runnable example** — decision shapes (good vs bad, `tsc --strict`):

```typescript
// good — batched independence (latency maxed — default shape)
export {}; // module marker (top-level await below needs module scope)
async function one(n: number): Promise<number> { return n; }
async function two(s: string): Promise<string> { return s; }
const [x, y] = await Promise.all([one(1), two("t")] as const); // batched (independent — parallelism norm)
console.log(x, y); // 1 t — defaults batching (serialization needing reasons, not vice versa)
// bad — habitual serialization (latency summed — independence unexamined, throughput left behind)
// fix — parallel-default (batch first — serialize with documented reasons only)
```

**Common confusion** — "parallel always faster" — parallel faster per *independent* ops (dependent/ordered work serial by semantics — speed comparisons across semantics meaningless). "reason comments noise" — reason comments defend serialization in review (undocumented loops "parallelized" into corruption — 5.1-adjacent class).

**Performance note** — batch latency = max; loop latency = sum; pool latency ≈ ceil(N/K) × single (three shapes, three cost models — chosen per site).

**Mentor note** — multi-await review: "independent, ordered, or huge?" (all → batch; ordered → loop+reason; huge → pool — the three-way question).

**Cross-links** — concurrency patterns → [2.3. Sequential parallel](<../2. Combinators and Cancellation/2.3. Sequential vs parallel patterns and tuple typing.md>); loser cleanup → [2.1. Combinators](<../2. Combinators and Cancellation/2.1. all race allSettled any typed precisely.md>).

### 4) **Lib selected, not assumed** (async surface declared per target)

**Definition** — the fourth check: `lib` set per runtime (Node/edge/worker minimal surfaces — 3.1); `TS2550`/`TS2304` on stdlib names read as configuration (libs first, code second); disposal/timer duality contained in wrappers (3.1 part 3, 3.3 part 1 — environment leaks unrepresentable outside utilities).

**What problem it solves / history** — maximal-lib environment leaks (browser APIs compiling in Node services — failures at runtime, not at check) and lib-gap signature hunts (hours debugging unloaded names): minimal libs failing loudly (architecture as configuration) + config-first diagnosis (minutes, not refactors).

**Modern guidance** — per-runtime tsconfigs (minimal libs — mistakes loud); timer/disposal wrappers (duality contained once — callers never handling); `using` for scoped resources (cleanup as syntax — 3.1 part 3).

**Runnable example** — configuration as architecture (good vs bad, `tsc --strict`):

```typescript
// good — wrapped timers (duality contained — callers timing, never handling)
export {}; // module marker (top-level await below needs module scope)
function delay(ms: number): Promise<void> {
  return new Promise<void>((resolve) => { setTimeout(resolve, ms); }); // encapsulated (one containment point — environment invisible outside)
}
await delay(1);
console.log("wrapped"); // wrapped — lib selected (surface declared — mistakes loud, handles hidden)
// bad — maximal libs + raw handles (environment mistakes compiling — duality leaking per call site)
// fix — minimal libs + wrappers (architecture configured — leaks unrepresentable)
```

**Common confusion** — "lib tweaks trivial" — lib lines scope *every gate* (17/5.1 part 4's lesson restated for async — include/lib diffs reviewed like gate diffs). "wrappers over-abstract" — one wrapper per duality (blast radius proportional — abstraction minimal, leaks zero).

**Performance note** — minimal libs marginally faster to check (smaller programs) AND stricter (both axes winning — no tradeoff).

**Mentor note** — config-review: lib diffs read as architecture diffs (surfaces declared — environment mistakes failing at check, not at 3am).
