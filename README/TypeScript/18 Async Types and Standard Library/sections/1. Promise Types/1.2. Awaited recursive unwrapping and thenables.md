## 1.2. Awaited recursive unwrapping and thenables

Awaited<T> models the value obtained by awaiting a type, including recursive adoption of compatible thenables. It is a type utility, not an instruction the runtime executes. JavaScript already performs promise resolution; TypeScript uses declarations and its checking rules to describe that behavior.

The [TypeScript 4.5 introduction](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-5.html#the-awaited-type-and-promise-improvements) explains the utility and its role in promise inference. The [infer-pipeline owner](<../../../09 Utility Types and Type Transformations/sections/2. Conditional Types/2.3. infer pipelines ReturnType Parameters Awaited.md>) teaches its structural conditional, malformed shapes and recursion limits. This lesson applies it to actual consumption and normalization.

Use **TypeScript 7.0.2** and **Node.js 20.20.2**, verified 2026-10-17. Save each TypeScript file in a directory without a tsconfig. Compile with `tsc --strict --target es2022 --module nodenext --outDir dist FILE.mts`, then run `node dist/FILE.mjs`.

### 1) **Test the wrapped contract and the consumed value deliberately**

ReturnType can describe what a function returns, while Awaited<ReturnType<...>> describes its modeled consumed value. Both can be useful contracts. An equality test on Promise<number> is not intrinsically wrong merely because another test checks the awaited number.

Awaited recurses through the thenable's fulfillment value. It does not recursively visit arbitrary object fields. An object containing a payload promise remains that object when awaited; await the field separately to consume it. A non-callable then property is ordinary data. Null and undefined also pass through. The next complete fixture includes type gates for these distinctions.

### 2) **Observe recursive adoption and distinguish protocol shapes**

A runtime thenable has a callable then member used by promise resolution. PromiseLike<T> is a stronger TypeScript interface describing a generic chaining method whose result is promise-like. A minimal object can participate in await without satisfying that entire interface. Promise<T> requires still more members, such as catch and finally; its annotation is structural API checking, not an implicit instanceof test.

Save:

```typescript
// file: interop.mts
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
const events: string[] = [];
const inner = {
  then(resolve: (value: number) => void): void { events.push("call inner"); resolve(7); },
};
const outer = {
  get then(): (resolve: (value: typeof inner) => void) => void {
    events.push("get outer then");
    return (resolve) => { events.push("call outer"); resolve(inner); };
  },
};
events.push("before");
const pending = Promise.resolve(outer);
events.push("after");
if (events.join("|") !== "before|get outer then|after") throw new Error("getter/call order");
const result = await pending;
if (result !== 7) throw new Error("recursive adoption");
console.log(events.join("|"));

const foreign: PromiseLike<number> = {
  then(onfulfilled, onrejected) { return Promise.resolve(41).then(onfulfilled, onrejected); },
};
async function consume(value: PromiseLike<number>): Promise<number> { return await value; }
if (await consume(foreign) !== 41) throw new Error("promise-like input");
// const needsFullPromise: Promise<number> = foreign; // Missing the fuller Promise API.
// const needsChaining: PromiseLike<number> = inner; // Its then returns void, not a promise-like chain.

const data = { then: 123, payload: Promise.resolve(9) };
if (await data !== data || await data.payload !== 9) throw new Error("object field boundary");
const literal: 42 = await 42;
if (literal !== 42) throw new Error("plain value");
function normalize<T>(value: T): Promise<Awaited<T>> { return Promise.resolve(value); }
const normalized = normalize(Promise.resolve(5));
if (await normalized !== 5) throw new Error("normalized result");
class Specialized<T> extends Promise<T> {}
const native = Promise.resolve(6);
if (Promise.resolve(native) !== native) throw new Error("same-constructor identity");
const specialized = new Specialized<number>((resolve) => resolve(6));
const converted = Promise.resolve(specialized);
if (converted === specialized || await converted !== 6) throw new Error("subclass normalization");

type Contracts = [
  Expect<Equal<typeof pending, Promise<number>>>,
  Expect<Equal<Awaited<typeof outer>, number>>,
  Expect<Equal<Awaited<typeof data>, typeof data>>,
  Expect<Equal<Awaited<null | undefined>, null | undefined>>,
  Expect<Equal<Awaited<Promise<Promise<number>>>, number>>,
  Expect<Equal<typeof normalized, Promise<number>>>
];
console.log("foreign 41; data 9; plain 42; normalized 5; identity true/false");
```

The two output lines are:

```text
before|get outer then|after|call outer|call inner
foreign 41; data 9; plain 42; normalized 5; identity true/false
```

One await consumes both outer and inner. Resolution reads the outer then getter during Promise.resolve; invocation of the returned function occurs later, followed by adoption of inner. Saying that all thenable interactions are deferred would miss the getter's synchronous side effect. The [promise-resolution specification](https://tc39.es/ecma262/multipage/control-abstraction-objects.html#sec-promise-resolve) describes normalization and constructor identity.

Activate each commented assignment independently and compile with noEmit instead of outDir to inspect the missing API and incompatible chaining result. Restore it afterward. Accept PromiseLike when its stated protocol is sufficient; require a fuller API when you actually use it. Returning a native promise often provides convenient interoperability, but neither public-versus-private scope nor a type annotation automatically decides the right protocol for every API.

Promise.resolve returns this ordinary native promise unchanged because its constructor matches Promise. The subclass instance is normalized to a different promise. Cross-realm objects, changed constructors and subclasses need their actual conditions considered; the blanket identity claim for every promise-like input is false.

### 3) **Do not mistake a nested annotation for runtime nesting**

Native resolution recursively adopts returned promises instead of delivering a promise object as a normal fulfillment value. Nevertheless, a declaration or generic return annotation can advertise Promise<Promise<number>>. Awaited can model its consumed number while a then callback's declared parameter is misleading.

Save this intentional mismatch demonstration:

```typescript
// file: nested-annotation.mts
const advertised = new Promise<Promise<number>>((resolve) => resolve(Promise.resolve(5)));
const consumed: number = await advertised;
if (consumed !== 5) throw new Error("awaited value");
const outcome = await advertised.then((value) => value.then((n) => n + 1)).catch((reason: unknown) => {
  if (!(reason instanceof TypeError)) throw reason;
  return "then received a number, not a promise";
});
if (outcome !== "then received a number, not a promise") throw new Error("missing mismatch");
console.log(outcome);
```

It compiles and prints `then received a number, not a promise`. The declared inner Promise type does not cause runtime wrapping; the callback actually receives 5 and its attempted then call fails. This is why a nested annotation is not harmless documentation of extra runtime layers.

The normalize function in interop.mts instead returns Promise<Awaited<T>>, matching its Promise.resolve operation. Its result for a promise input is checked as Promise<number>. Preserve both the declared return and the consumed-value relationships when both matter. Do not write an unwrapping loop for ordinary finite thenables when one await already performs recursive adoption.

### 4) **Common confusion**

Awaited is not a runtime parser or a liveness guarantee. A malformed or self-referential thenable can fail, remain pending or exceed the checker's instantiation limit. The canonical utility owner demonstrates a recursive type hitting TS2589. Neither arbitrary depth nor successful completion follows from spelling Awaited<T>.

A native Promise API type is also not a branding restriction. The foreign example lacks the additional members the full interface promises; that is why its assignment fails. Runtime instanceof checks are a separate choice and can reject values that resolution could adopt.

### 5) **Performance note**

Awaited and its type gates erase, while actual getters, then calls, promise creation and reactions execute. This lesson observes operation order and identity; it measures no microsecond assimilation fee, fixed hops per level or zero-cost native path. A thenable can perform arbitrary work, and cyclic or deep type structures can cost checker work. Measure the relevant runtime or compiler problem instead of assigning a universal safe nesting depth.

### 6) **Mentor note**

Ask why the outer getter appears before after, why one await reaches 7 and why the minimal inner object does not implement all of PromiseLike. Then trace the nested-annotation callback failure and compare it with normalize's return type. A good explanation separates a type's advertised protocol, recursive runtime adoption, getter evaluation and constructor identity.
