## 1.2. Awaited recursive unwrapping and thenables

### 1) **`await` positions unwrap via `Awaited`** (every await an Awaited assertion)

**Definition** — each `await expr` evaluates to `Awaited<typeof expr>`: `Awaited<T> = T extends null | undefined ? T : T extends object & { then(onfulfilled: infer F, ...args: infer _): any } ? F extends (value: infer V, ...args: infer _) => any ? Awaited<V> : never : T` (stdlib's recursive conditional — 09/2.3 proves the recursion; this leaf applies it). Positions: `await` expressions, `async` return wrapping (return `T` becomes `Promise<Awaited<T>>`... precisely, `Promise<T>` where `T` is awaited at consumption), and `Promise.all`-family element handling.

**What problem it solves / history** — nested `Promise<Promise<T>>` (double-wrapped returns from `async` functions returning promises — pre-`Awaited` eras forced manual `Unpack` helpers per codebase, each subtly different). `Awaited` standardizes unwrapping (one recursive definition — `await`, combinators, and userland sharing semantics instead of forking them).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), spell consumed shapes as `Awaited<ReturnType<typeof f>>` (the 3.2/4.1 probe pattern — awaited contracts pinned, not `Promise`-wrapped guesses); never hand-roll unwrap helpers (stdlib `Awaited` — the 09 DRY rule: mechanics owned once).

**Runnable example** — unwrapping at positions (good vs bad, `tsc --strict`):

```typescript
// good — Awaited spelling the consumed shape (probe pins what await delivers)
export {}; // module marker (top-level await below needs module scope)
async function fetchAge(id: string): Promise<number> { return id.length * 10; }
type Age = Awaited<ReturnType<typeof fetchAge>>; // number (unwrapped — the consumed contract, pinned below)
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
assertType<Equal<Age, number>>(); // identity (await delivers number — probe locks the unwrapped shape)
console.log(await fetchAge("u1")); // 20 — Awaited at consumption (positions unwrapping uniformly)
// bad — Promise-probing (Equal<ReturnType<typeof f>, Promise<number>> — wrapping asserted, consumption untested)
// fix — Awaited probes (consumed shapes pinned — what callers actually receive)
```

```typescript
// good — double-wrap collapsing (async returning promises flattens — no nested handling)
export {}; // module marker (consistent module scope across fences)
async function nested(): Promise<Promise<number>> { return Promise.resolve(7); } // double-wrapped declared (legal, flattened)
type Flat = Awaited<ReturnType<typeof nested>>; // number (recursion collapsing — 09 mechanics applied)
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
assertType<Equal<Flat, number>>(); // flat (nesting invisible to consumers — pinned flat)
console.log(await nested()); // 7 — flattening proven (declared-double, consumed-single)
// bad — nested-Promise handling (manual unwrapping layers — fighting the recursion stdlib provides)
// fix — trust Awaited (nesting collapses by definition — declare freely, consume flat)
```

**Common confusion** — "`Awaited` unwraps one level" — `Awaited` recurses (arbitrary nesting → innermost `T`, except `null`/`undefined` passthrough and thenable branches — read the stdlib definition once, see 09/2.3). "`await` on non-promises errors" — `await` accepts any `T` (non-thenables pass through — `await 42` is `42`, typed and legal). "hand-rolled `Unpack` equals `Awaited`" — hand-rolls miss thenable branches (stdlib handles `PromiseLike` — approximations diverging on interop, see part 2).

**Performance note** — `Awaited` instantiates per awaited type (one recursion per nesting level — trivial); deep-nesting probes stay shallow in practice (double-wraps rare, triple-wraps pathological).

**Mentor note** — probe discipline: every public async function gets `Awaited<ReturnType<...>>` identity probes (17/4.1 part 1 restated for async — awaited shapes pinned, wrappings ignored).

### 2) **Thenable assimilation** (non-Promise thenables adopted per await)

**Definition** — a *thenable* is any object with a callable `then` (`{ then(onF, onR): ... }` — the `PromiseLike<T>` interface): `await` (and `Promise.resolve`, combinators) *adopts* thenables (calls their `then`, settling with the outcome — one assimilation level per operation, recursing via `Awaited`). Interop purpose: jQuery deferreds, AngularJS `$q`, cross-realm promises — foreign async shapes joining native flows without conversion.

**What problem it solves / history** — library-ecosystem fragmentation (each framework's promise flavor incompatible by brand — `instanceof Promise` failing across realms/bundlers): thenables standardize by *shape* (structural `then` — the TypeScript structural philosophy at runtime), letting foreign promises assimilate instead of requiring wrapping.

**Modern guidance** — accept `PromiseLike<T>` (not `Promise<T>`) in public async parameters where interop matters (libraries, plugins — wider acceptance, same consumption); return native `Promise<T>` always (producers standardize — consumers diversify). Test interop with a minimal thenable object (one assimilation probe per accepting seam).

**Runnable example** — shape-based interop (good vs bad, `tsc --strict`):

```typescript
// good — PromiseLike accepted (foreign shapes assimilating — structural interop)
export {}; // module marker (top-level await below needs module scope)
async function consume(p: PromiseLike<number>): Promise<number> { return await p; } // PromiseLike param (thenables welcome)
const foreign: PromiseLike<number> = {
  then: (onF) => Promise.resolve(41).then(onF), // minimal thenable (shape only — delegates settlement, no brand needed)
};
console.log(await consume(foreign)); // 41 — assimilation working (foreign then adopted — no wrapping needed)
// bad — Promise-branded params (instanceof-gated acceptance — cross-realm/bundler promises rejected)
// fix — PromiseLike params (structural acceptance — interop by shape, the TS philosophy at runtime)
```

```typescript
// good — native promises produced (producers standardizing on Promise)
export {}; // module marker (consistent module scope across fences)
async function produce(n: number): Promise<number> { return n + 1; } // native return (consumers diversify, producers unify)
const p: Promise<number> = produce(41);
console.log(p instanceof Promise); // true — native brand (produced values brand-carrying — debugging/introspection friendly)
// bad — thenable returns (producers emitting foreign shapes — consumers forced to assimilate your internals)
// fix — Promise out, PromiseLike in (asymmetric rule — Postel's law typed: accept widely, produce standardly)
```

**Common confusion** — "thenables equal promises" — thenables lack `catch`/`finally`/combinators (only `then` — assimilation input, not compositional output). "assimilation is synchronous" — assimilation schedules (thenable `then` called, outcome settled asynchronously — ordering via microtasks, never inline). "`await` requires promises" — `await` requires *thenables-or-values* (the general contract — promises the common case).

**Performance note** — assimilation adds one `then`-call + settlement hop per foreign object (microseconds — interop price, paid only across flavors); native paths unpenalized (brand fast-path, no assimilation overhead).

**Mentor note** — library-API review: `Promise<T>` params accepting only natives (narrow), `PromiseLike<T>` params accepting all (wide) — the question "who calls this?" picks the type (internal → `Promise`, public → `PromiseLike`).

### 3) **Nested-promise flattening** (Promise of Promise collapsing to T)

**Definition** — flattening: `await`/`Promise.resolve`/combinators recursively adopt inner promises (`Promise<Promise<T>>` → `T` at consumption — never observable as nested). Type-level: `Awaited` recursion (part 1); value-level: the spec's `PromiseResolveThenableJob` (assimilation jobs chaining until a non-thenable settles). Declaration consequence: `Promise<Promise<T>>` annotations are legal but pointless (consumers always see `T`).

**What problem it solves / history** — callback-era nesting (`getUser(id, u => getOrders(u, o => ...))` — depth per step) vs flattened async (nesting impossible by construction — composition staying linear no matter how promises wrap). Flattening is what makes `async` composition scale (depth-10 pipelines reading flat).

**Modern guidance** — never annotate `Promise<Promise<T>>` (declare the flattened `Promise<T>` — honesty about consumption); when wrapping foreign nested shapes, `await` once (flattening automatic — no unwrap loops). Probe flattened shapes (part 1's `Flat` pattern — nested declarations pinned flat).

**Runnable example** — nesting impossible by construction (good vs bad, `tsc --strict`):

```typescript
// good — flattened consumption (declared-double, consumed-single — construction honest)
export {}; // module marker (top-level await below needs module scope)
function wrap<T>(v: T): Promise<T> { return Promise.resolve(v); }
const double = wrap(wrap(5)); // Promise<number> (resolve flattens — nesting unrepresentable)
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
assertType<Equal<Awaited<typeof double>, number>>(); // flat (wrapping twice still yields number — pinned)
console.log(await double); // 5 — flattening total (nesting unobservable — composition linear)
// bad — unwrap loops (while (isPromise(x)) x = await x — fighting automatic flattening with manual recursion)
// fix — await once (flattening by definition — loops proving misunderstanding, not thoroughness)
```

**Common confusion** — "`Promise.resolve(p)` wraps" — `Promise.resolve` *adopts* (promise inputs returned/assimilated, never double-wrapped — the flattening entry point). "nested generics nest at runtime" — `Promise<Promise<T>>` exists only textually (values flatten — the annotation lying about consumption). "flattening loses errors" — inner rejections propagate (adoption carrying rejections — flattening values, preserving failures).

**Performance note** — each assimilation level adds microtask hops (linear in nesting depth — depths >2 pathological, not performance-relevant); normal code nests ≤1 (zero flattening cost in practice).

**Mentor note** — the `Promise.resolve(p) === p` identity (native promise inputs returned as-is — assimilation short-circuit; demonstrates flattening cheaper than wrapping).
