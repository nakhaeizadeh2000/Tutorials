## 1.3. async function return-type contracts

### 1) **`async` always returns `Promise<T>`** (returned values wrapped, throws rejecting)

**Definition** — an `async` function declared `async function f(): Promise<T>` wraps every `return v` (where `v: T`) into fulfillment and every `throw e` into rejection — the signature lies *only* if annotated otherwise (annotating `Promise<T>` while returning `U` errors; annotating bare `T` errors always — `async` functions must declare promise returns, `TS1064`-adjacent enforcement... precisely: the return type of an async function must be a valid promise/thenable type).

**What problem it solves / history** — sync/async signature confusion (callers `await`ing sync returns unnecessarily, or forgetting `await` on async ones — 17/2.3 floats): the `async` keyword *plus* the `Promise<T>` annotation make asynchrony visible twice (call-site keyword space, signature type space) — both layers agreeing, floats and double-awaits review-visible.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), annotate every public `async` return explicitly (`Promise<T>` — the 03/3.1 contract-vs-local rule: contracts annotated, locals inferred); never annotate `Promise<Promise<T>>` (flattened by 1.2 — declare honestly); never declare `async` without a promise return (the checker forbids — obey, don't fight).

**Runnable example** — wrapping contracts (good vs bad, `tsc --strict`):

```typescript
// good — explicit Promise return (contract annotated, body inferring into it)
export {}; // module marker (top-level await below needs module scope)
async function getName(id: string): Promise<string> {
  return `user:${id}`; // string body (wrapped automatically — annotation states the eventual shape)
}
console.log(await getName("u1")); // user:u1 — wrapping contract (returned T, consumed T, Promise in between)
// bad — unannotated public async (inference guessing the contract — widening drift invisible, see 03/3.2)
// fix — Promise<T> on every public async (contracts declared — inference for locals only)
```

```typescript
// good — throws becoming rejections (throw inside async rejects — never escapes synchronously)
export {}; // module marker (consistent module scope across fences)
async function strictGet(id: string): Promise<string> {
  if (id === "") throw new Error("empty id"); // rejection (not a sync throw — callers catch via await/catch)
  return `user:${id}`;
}
console.log(await strictGet("u1").catch(() => "fallback")); // user:u1 — throws-as-rejections (async error channel uniform)
// bad — try/catch around the CALL (sync-throw assumption — misses that async throws reject, never throw)
// fix — await/catch at consumption (rejections handled in the async channel — 15/2.3 boundaries respected)
```

**Common confusion** — "`async` functions can return non-promises" — `async` *wraps* (declared `Promise<T>`, body `T` — the wrapping is the contract, not overhead). "double-await is safer" — `await await p` flattens identically (harmless but noisy — review flag, not safety). "async without await needs no Promise" — `async` without `await` still wraps (and lints via `require-await` — 16/2.1 tier deciding per codebase).

**Performance note** — `async` wrapping allocates one promise + schedules microtasks per call (microseconds — the uniformity price); non-`async` promise-returning functions skip one hop (hot paths returning existing promises directly — measure, then choose).

**Mentor note** — signature review: bare-`T` returns on `async` functions are checker errors (non-negotiable); missing `Promise<T>` annotations on public async functions are review errors (contracts declared — same severity class).

### 2) **Explicit vs inferred async returns** (contracts annotated, locals inferred)

**Definition** — the split (03/3.1 applied to async): *public/exported* `async` functions annotate `Promise<T>` explicitly (consumers depending on the declared eventual shape); *local* async closures infer (bodies small, call sites adjacent — inference precise, annotations noise). Inferred async returns widen like all inference (literal returns widening to `string` — 03/3.2 widening at async scale).

**What problem it solves / history** — inferred public async returns drifting (`"ok"` widening to `string` — downstream literal switches rotting, the 5.1 widening class in async clothing): explicit annotations convert drift into red lines at the declaration (minutes at authoring vs quarters in revenue-review).

**Modern guidance** — annotate public `async` (one `Promise<T>` per export — the contract advertised); infer locals (closures, callbacks — adjacency making inference reviewable); probe awaited shapes (`Awaited<ReturnType<...>>` identity per 1.2 — annotated contracts pinned, not merely stated).

**Runnable example** — contract-vs-local split (good vs bad, `tsc --strict`):

```typescript
// good — public annotated, local inferred (each where reviewers look)
export {}; // module marker (top-level await below needs module scope)
export async function fetchStatus(id: string): Promise<"active" | "suspended"> {
  return id === "a" ? "active" : "suspended"; // literal union (annotation preserving narrowness — widening breaks HERE)
}
const probe = await fetchStatus("a"); // inferred local (adjacency — annotation noise avoided where inference suffices)
console.log(probe); // active — split applied (contracts declared, locals flowing)
// bad — public inferred (literal union widening to string silently — switches rotting downstream)
// fix — Promise<literal-union> annotations on exports (narrowness declared — drift red at the source)
```

```typescript
// good — awaited probe pinning the annotation (stated AND tested — 17/4.1 part 1 for async)
export async function roleOf(id: string): Promise<"admin" | "user"> {
  return id === "a" ? "admin" : "user";
}
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends (<T>() => T extends B ? 1 : 2) ? true : false;
declare function assertType<T extends true>(): void;
type Role = Awaited<ReturnType<typeof roleOf>>; // alias (no >>> closers — 17/3.1 lesson applied)
assertType<Equal<Role, "admin" | "user">>(); // awaited identity (annotation pinned — statement plus proof)
console.log(await roleOf("a")); // admin — contracts proven (declared shapes tested, not hoped)
// bad — annotations without probes (statements untested — annotations drifting like comments)
// fix — Awaited probes beside annotations (every public async contract pinned — statement and proof adjacent)
```

**Common confusion** — "inference suffices for publics" — inference *describes* current bodies (drift-prone); annotations *prescribe* contracts (drift-resistant) — describe-vs-prescribe differing per audience (locals vs consumers). "annotations duplicate bodies" — annotations duplicate *intent* (reviewable contracts); bodies implement (changeable internals) — duplication-as-detection per 17/1.3.

**Performance note** — annotations cost zero (erased — 01/2.1); probes cost one instantiation each (microseconds); widening incidents cost postmortems (asymmetric — always annotate publics).

**Mentor note** — export-review checklist: "Promise-annotated? Awaited-probed?" (two questions per public async export — mechanical, blocking).

### 3) **`Promise<void>` vs `Promise<never>` discipline** (fire-and-observe vs never-settling)

**Definition** — the async end of 05/1.3's contract trio: `Promise<void>` (settles with ignored value — event handlers, notifiers, `finally`-adjacent observers); `Promise<never>` (never fulfills — infinite loops, `await new Promise(() => {})` parking, process-lifetime holders); `Promise<undefined>` (settles with an *inspected* undefined — value-carrying, not ignored — distinct from `void`'s purposeful ignorance). Sharp edge (verified via `tsc --strict` in this leaf's fences): unlike sync `() => string` flowing into `() => void`, `() => Promise<string>` does NOT flow into `() => Promise<void>` — void-discard stops at generic boundaries. Annotate void at the source instead of relying on discard.

**What problem it solves / history** — `Promise<any>` event callbacks (ignoring-vs-inspecting undistinguished — `void`-returning callbacks assigned where values flow, the 05 callback-variance hazard async): precise async-void contracts let `() => Promise<void>` accept value-returning callbacks (discard allowed) while `Promise<undefined>` positions demand exactness (inspected values).

**Modern guidance** — type fire-and-forget callbacks as `() => Promise<void>` (callers discarding — the 05 void-callback rule); type parking/lifetime holders as `Promise<never>` (never-settling documented — reviewers seeing intent, not hangs); reserve `Promise<undefined>` for settled-with-undefined values (JSON voids, optional resolutions — inspected, not ignored).

**Runnable example** — void-vs-never at async scale (good vs bad, `tsc --strict`):

```typescript
// good — void observer contract (value discarded by design — 05 rule async)
export {}; // module marker (consistent module scope across fences)
async function notify(msg: string): Promise<void> {
  console.log(`notify:${msg}`); // side channel (no value — void honest)
}
const handler: () => Promise<void> = () => notify("hi"); // exact (source already void — no discard needed)
await handler();
console.log("observed"); // observed — void discipline (observers observing — values flowing nowhere by contract)
// bad — Promise<any> observers (ignoring-vs-inspecting undistinguished — variance hazards async)
// fix — Promise<void> at the source (unlike sync () => string → () => void, Promise<string> does NOT flow into Promise<void> — void-discard stops at generic boundaries, verified via tsc)
```

```typescript
// good — never-settling documented (parking intent explicit — not a hang)
export {}; // module marker (consistent module scope across fences)
function park(): Promise<never> {
  return new Promise<never>(() => {}); // never settles (lifetime holder — documented, deliberate)
}
async function withTimeout<T>(p: Promise<T>, ms: number): Promise<T> {
  const timer = new Promise<never>((_, reject) => setTimeout(() => reject(new Error("timeout")), ms)); // never-fulfills racer (rejects or loses — 2.1 race mechanics)
  return Promise.race([p, timer]); // T (never-branch contributing no fulfillment — union honest)
}
console.log(await withTimeout(Promise.resolve(1), 1000)); // 1 — never-racers (losing branches value-free by type)
// bad — Promise<never> confused with hang-bugs (parkers "fixed" into resolving — lifetime holders broken by helpfulness)
// fix — never documented (parking deliberate — reviewers reading intent, not filing hang bugs)
```

**Common confusion** — "`Promise<void>` equals `Promise<undefined>`" — `void` means *ignored* (discard-allowed callbacks); `undefined` means *inspected-absent* (exact value — assignability differing at callback positions per 05/1.3). "`Promise<never>` never resolves usefully" — `never`-racers *reject* (timeout patterns — fulfillment impossible, rejection intended). "async void functions return undefined" — they *fulfill* undefined (value ignored by contract — consuming it is the smell, not the fulfillment).

**Performance note** — `park()` allocates one unsettled promise (tiny, GC-eligible only via scope loss — lifetime holders intentional leaks, documented); void-vs-undefined costs nothing (type-level distinction only).

**Mentor note** — callback-position quiz: "why does `() => string` assign to `() => void` but `() => Promise<string>` NOT to `() => Promise<void>`?" (discard allowed at direct return positions, blocked through generics — the single most-tested async-variance fact in senior interviews; see 6.1).
