## 3.2. AsyncIterable generators and for-await

An async iterable lets a consumer request successive iterator results over time. An async generator implements that protocol with a body that can await work and pause at yield. TypeScript describes the values moving out, the final return, and values sent back in; the protocol does not by itself prove bounded buffering or resource safety.

Use **TypeScript 7.0.2** and **Node.js 20.20.2**, verified 2026-10-17. Save the complete files below in a fresh directory. The fixture uses controlled promises and instrumented generators; it performs no network or database integration.

### 1) **Keep yielded, returned and sent values distinct**

AsyncGenerator<T, TReturn, TNext> describes yielded values T, the final return TReturn, and arguments sent through next as TNext. Its next method returns Promise<IteratorResult<T, TReturn>>. Check done before treating value as exclusively the yielded or returned type. A for-await loop visits yielded values and discards the final return value.

In the installed library, writing bare AsyncGenerator selects unknown, any and any defaults. That differs from letting TypeScript infer a generator function. The inferred example below yields number and returns string; those channels do not automatically become any. Choose explicit annotations when they establish a useful API contract, rather than requiring three written parameters for every function. The [stricter-generator release explanation](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-3-6.html#stricter-generators) introduces the three channels and done-based narrowing; the installed compiler determines current inference.

```typescript
// file: iteration.mts
export async function* dialogue(): AsyncGenerator<string, number, string> {
  const answer = yield "name?";
  return answer.length;
}
export async function* inferred() {
  yield 1;
  return "done";
}
export async function* paced(log: string[]): AsyncGenerator<number, void, unknown> {
  for (let index = 0; index < 3; index++) {
    log.push("produce:" + index);
    yield index;
  }
}
export async function* closable(
  log: string[], cleanupGate: Promise<void>, started: () => void,
): AsyncGenerator<number, void, unknown> {
  try { yield 1; yield 2; }
  finally {
    log.push("close:start");
    started();
    await cleanupGate;
    log.push("close:end");
  }
}
export async function* pages(total: number, size: number): AsyncGenerator<number[], void, unknown> {
  if (!Number.isSafeInteger(total) || total < 0) throw new RangeError("nonnegative safe total");
  if (!Number.isSafeInteger(size) || size < 1) throw new RangeError("positive safe size");
  let offset = 0;
  while (offset < total) {
    const count = Math.min(size, total - offset);
    yield Array.from({ length: count }, (_, index) => offset + index);
    offset += count;
  }
}
```

Calling dialogue creates a generator without running its body. The first next starts execution and reaches the first yield. Its argument is ignored because no yield was already waiting to receive it. A later next("Ada") supplies the result of that yield expression and produces the final return 3. The current interface also permits a zero-argument next call: TNext alone is not a proof that a caller follows every required protocol step or supplies an answer after startup.

### 2) **Distinguish pulling a result from starting work**

For-await first looks for Symbol.asyncIterator, then falls back to Symbol.iterator. It can therefore consume arrays, strings and synchronous iterables of promises. The fallback awaits yielded promise values. A Promise<T[]> itself is not an iterable: await that promise to obtain its array first. A custom async iterator's result value is not subjected to the same extra unwrapping as the synchronous fallback; type and implement that protocol deliberately.

The loop waits for each next result and each body iteration before requesting another. In paced, production is inside the generator and pauses at yield, so a body pause prevents the next production step. An adapter may nevertheless prefetch, retain a queue or wrap already-started work. An array of pending promises already holds its operations; consuming it in order does not serialize their starts. The [bounded-mapper fixture](<../2. Combinators and Cancellation/2.3. Sequential vs parallel patterns and tuple typing.md>) tests that contrast and owns concurrency limits.

A break from a loop invokes the iterator's return method when present and awaits the closing result. In closable that enters finally and waits for cleanupGate. This is a defined closing path, not proof that every operation or implementation cleans up. A custom iterator may omit return, return without releasing anything, or reject from next without a separate return call. Resource owners must define those failure paths. The [AsyncIteratorClose algorithm](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-asynciteratorclose) explicitly permits an absent return method.

### 3) **Verify the channels, pacing and cleanup**

Compile `iteration.mts` with `tsc --strict --target es2022 --module nodenext --outDir dist iteration.mts`, then run the following consumer with `node verify.mjs`.

```javascript
// file: verify.mjs
import assert from "node:assert/strict";
import { dialogue, inferred, paced, closable, pages } from "./dist/iteration.mjs";
function deferred() {
  let resolve;
  const promise = new Promise(done => { resolve = done; });
  return { promise, resolve };
}
const chat = dialogue();
assert.deepEqual(await chat.next("ignored"), { done: false, value: "name?" });
assert.deepEqual(await chat.next("Ada"), { done: true, value: 3 });
const yielded = [];
for await (const value of inferred()) yielded.push(value);
assert.deepEqual(yielded, [1]); // Final "done" is not an iterated element.
const syncValues = [];
for await (const value of [Promise.resolve(4), Promise.resolve(5)]) syncValues.push(value);
assert.deepEqual(syncValues, [4, 5]);
const dual = {
  *[Symbol.iterator]() { yield "sync"; },
  async *[Symbol.asyncIterator]() { yield "async"; },
};
assert.deepEqual([...dual], ["sync"]);
const selected = [];
for await (const value of dual) selected.push(value);
assert.deepEqual(selected, ["async"]);
const rawValue = Promise.resolve(9);
const custom = {
  [Symbol.asyncIterator]() { return this; },
  async next() { return { done: false, value: rawValue }; },
};
for await (const value of custom) { assert.equal(value, rawValue); break; }
const pause = deferred();
const firstBody = deferred();
const log = [];
const consumption = (async () => {
  for await (const value of paced(log)) {
    log.push("consume:" + value);
    if (value === 0) { firstBody.resolve(); await pause.promise; }
  }
})();
await firstBody.promise;
await new Promise(resolve => setTimeout(resolve, 0));
assert.deepEqual(log, ["produce:0", "consume:0"]);
pause.resolve();
await consumption;
assert.deepEqual(log, ["produce:0", "consume:0", "produce:1", "consume:1", "produce:2", "consume:2"]);
const cleanup = deferred();
const closing = deferred();
const closeLog = [];
let finished = false;
const early = (async () => {
  for await (const value of closable(closeLog, cleanup.promise, closing.resolve)) { break; }
  finished = true;
})();
await closing.promise;
await new Promise(resolve => setTimeout(resolve, 0));
assert.equal(finished, false);
assert.deepEqual(closeLog, ["close:start"]);
cleanup.resolve();
await early;
assert.equal(finished, true);
assert.deepEqual(closeLog, ["close:start", "close:end"]);
let returned = false;
const broken = {
  [Symbol.asyncIterator]() { return this; },
  async next() { throw new Error("next failed"); },
  async return() { returned = true; return { done: true }; },
};
await assert.rejects(async () => { for await (const value of broken) { void value; } }, /next failed/);
assert.equal(returned, false); // next failed; this was not a break from the body.
await broken.return(); // Explicit owner cleanup for this instrumented iterator.
assert.equal(returned, true);
const chunks = [];
for await (const page of pages(5, 2)) chunks.push(page);
assert.deepEqual(chunks, [[0, 1], [2, 3], [4]]);
assert.deepEqual(await pages(0, 2).next(), { done: true, value: undefined });
for (const size of [0, -1, 0.5, NaN, Infinity, Number.MAX_SAFE_INTEGER + 1]) {
  await assert.rejects(pages(5, size).next(), RangeError);
}
for (const total of [-1, 0.5, NaN, Infinity, Number.MAX_SAFE_INTEGER + 1]) {
  await assert.rejects(pages(total, 2).next(), RangeError);
}
console.log("channels, sync fallback, pacing, closing and page boundaries passed");
```

The assertions separate a producer pause from awaited cleanup on break. They also show a failure path where the loop did not call return. As a deliberate mutation, remove await cleanupGate in closable: it still compiles, but the unfinished-cleanup assertion fails. Restore it afterward. The later-task checks allow queued reactions to run; they do not assert a specific timer duration.

The pages example validates arguments when iteration first advances, since a generator body is lazy. Each yielded element is an array, so this consumer needs a nested iteration or another deliberate flattening step to process individual rows. Keeping every page in chunks is intentional for this small assertion; an actual streaming consumer should release pages it no longer needs. Validation prevents a zero-size infinite loop, but valid safe integers do not imply that an enormous allocation will succeed.

Choose a synchronous generator for a naturally synchronous sequence when callers need synchronous iteration. Choose an async iterable for asynchronous arrivals or a uniform async consumer contract. A Promise<T[]> gives the consumer a complete collection after one completion; it can suit a bounded batch needing repeated or indexed access. Paged async iteration can limit materialization when the producer and consumer actually retain only bounded pages. It is not inherently restricted to I/O or automatically preferable for every large input.

### 4) **Common confusion**

The argument to the first next is not an initial answer to the first yield. It is ignored at startup. The final return value is available from a done result but omitted by for-await. These distinctions explain why manually driving a bidirectional generator is sometimes appropriate; manual iteration can also be useful for adapters or inspection, provided the caller owns early closing.

Awaiting each loop step does not mean previously started operations run sequentially, and does not set a source's buffer capacity. AsyncIterable describes a way to obtain an iterator, not a proof about the implementation's memory, cancellation or cleanup policy. Iteration closing also differs from [using-based disposal](<./3.1. lib settings and built-in async types.md>).

### 5) **Performance note**

Async iteration introduces promise and scheduling work, while chunking changes how much data moves per iteration. Larger pages may reduce per-item protocol work while increasing retained data and time before a page is available. Measure the real producer, consumer and buffers; this fixture measures none of those costs. Collecting all yielded pages retains their contents regardless of the producer's lazy implementation. A synchronous generator also has execution and storage costs; avoiding async machinery does not make it free.

### 6) **Mentor note**

Ask the learner to predict the two dialogue results, then identify why for-await cannot send its string answer. Have them pause the first paced body and point to the next line the generator can execute. Finally compare break with a rejected next: a good explanation identifies the closing method, the code responsible for cleanup, and the cases the protocol does not settle for the application.
