## 1.2. Strict Family (strict, noImplicitAny, strictNullChecks)

### 1) **Definition** (strict)

**Definition** — `strict: true` enables ~10 sub-flags (all recommended). Most important for correctness:

- `noImplicitAny` — forbids inferred `any` (requires annotation).
- `strictNullChecks` — `null`/`undefined` are not assignable to other types (see domain `10` boundary).
- `strictFunctionTypes` — enforces contravariant callback check (see 04/05).
- `noUncheckedIndexedAccess` — index access `arr[0]` → `T | undefined` (often still off — enable it).
- `exactOptionalPropertyTypes`, `noImplicitThis`, `strictBindCallApply`, `useUnknownInCatchVariables`.

```jsonc
// strict base (enable always for new code)
{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,     // not in strict — enable explicitly (valuable)
    "exactOptionalPropertyTypes": true    // optional: stricter ? vs |undefined (see 03)
  }
}
```

### 2) **Bad** (non-strict at scale)

**Why non-strict hurts:**

```typescript
// with strict: false (noImplicitAny off):
function getUser(id) { // id inferred any — any propagates downstream
  return { id }; // any leaks
}
let u = getUser(123); // any — no check on u.id

// with strictNullChecks off:
let s: string = "hi";
s = null; // ok in non-strict — null deref bug later
s.toUpperCase(); // runtime TypeError if null leaked

// with strict on — bug caught:
function getUserStrict(id: string): { id: string } { return { id }; }
// getUserStrict(123) // error
let s2: string = "hi";
// s2 = null; // error — must be string | null

// noUncheckedIndexedAccess off:
let arr = [1, 2, 3];
let first = arr[0]; // number (ignores out-of-bounds)
// with flag on: number | undefined — forces guard
first = arr[0] ?? 0; // must handle undefined
```

Teams disabling `strict` ship ~30% more null bugs (observational — track via PR bug categories). Cost is one-time annotation pass.

### 3) **Mentor** (enable strict early)

**Guidance:**

- New project: `strict: true` + `noUncheckedIndexedAccess: true` from day one.
- Existing JS→TS migration: enable file-by-file via per-file `// @ts-check` / `allowJs` → per-package `strict` → monorepo-wide. Enforce `strict: true` in CI even if `skipLibCheck: true`.
- Add lint guards: `no-explicit-any` (`typescript-eslint`) to force `unknown` + guard (see [09 1.1](<../../../09%20Tooling%20ESLint%20Biome%20and%20Type-Level%20Testing/sections/1.%20Lint%20and%20Format/1.1.%20ESLint%20+%20typescript-eslint%20vs%20Biome.md>)).

```typescript
// gradual enable pattern (tsconfig incremental)
{
  "extends": "./tsconfig.strict.json", // strict base
  "include": ["src"],
  "compilerOptions": { "strict": false } // override for migration folder?
}
// better: keep root strict true, add tsconfig.migration.json with strict false for allowJs folder

// demo of exactOptionalPropertyTypes benefit
type Opt = { nickname?: string };
let o: Opt = {}; // ok
// with exactOptionalPropertyTypes: true
// o = { nickname: undefined } // error unless typed as nickname?: string | undefined — separates missing vs undefined
```

### Mentor note

Demo cost of `strict`: annotate a medium module, show red squiggles, fix them live — each squiggle is a bug prevented. Then show PR trend before/after.

### Common confusion

- "`strict` is one flag" — it's a family; `noUncheckedIndexedAccess` outside `strict` is the most missed valuable flag. Enable separately.

### Performance note

`strict` has zero runtime cost — purely checker. But more errors = longer fix time. Batch `tsc --noEmit` with incremental `tsc --build` to keep CI fast.
