## 1.1. Target, Module, Lib and Emit

### 1) **Definition** (target)

**Definition:**

- `target` — JS version emitted (syntax downlevel: arrow → `function`, `??` → helper, class fields behavior via `useDefineForClassFields`). Controls helpers emitted.
- `module` — module emit format (`nodenext`, `esnext`, `commonjs`, `bundler`).
- `lib` — ambient type definitions available (`es2022`, `dom`, `esnext`). Can include features *above* `target` for checking without emitting polyfills.
- `emit` family — `outDir`, `declaration`, `sourceMap`, `declarationMap`, `verbatimModuleSyntax`, `allowJs`/`checkJs`.

```jsonc
// balanced modern app (Node 18+ / bundler)
{
  "compilerOptions": {
    "target": "es2022",          // emit ES2022 syntax (supports class fields, ??, ?. native)
    "lib": ["es2022", "dom"],    // checker knows ES2022 + DOM APIs
    "module": "nodenext",         // emit per Node's ESM/CJS detection (or bundler for web)
    "moduleResolution": "nodenext",
    "outDir": "dist",
    "declaration": true,          // emit .d.ts for libs
    "sourceMap": true,
    "declarationMap": true,
    "verbatimModuleSyntax": true
  }
}
```

`lib` vs `target`: `lib` can be newer than `target` (check with modern lib, emit fallback). `target` can be newer — checker still uses `lib` for available APIs.

### 2) **Example** (es2022)

```typescript
// with target es2022, this class field uses [[Define]] semantics (useDefineForClassFields: true by default for >=es2022)
class Store {
  count = 0; // native define
}

// with target es2017 but lib es2022 — checker knows Array.at exists, but emit may need polyfill
// lib controls find vs runtime
let arr = [1, 2, 3];
arr.at(1); // ok if lib includes es2022, but fails at runtime on Node 16 without polyfill

// module choice impact on emit
// file.ts: export const x = 1;
// target es2022 + module nodenext → ESM (export const x = ...)
// target es2022 + module commonjs → exports.x = ...

// lib for 5.6 Iterator helpers (ESNext)
{
  "compilerOptions": { "lib": ["esnext", "dom"] } // Iterator helpers typing requires esnext as of July 2024
}
```

`useDefineForClassFields` caveat (see mentor note).

### 3) **Tradeoff** (emit vs type-only)

**Tradeoff:**

- Low `target` (`es5`) — maximal compatibility but emits helpers (`__awaiter`, `__spreadArray`), bigger bundle + slower class semantics.
- High `target` (`es2022`/`esnext`) — smaller + native semantics but requires modern runtime or polyfill.
- `lib` high, `target` low — type-check modern APIs while emitting fallback; but runtime failure if polyfill missing. Must align with runtime baseline (Browserslist / `engines`).

```typescript
// tradeoff demo: class fields
// src: class A { x = 1; }
// target es2022 emit: class A { x = 1; }  — native
// target esnext? similar
// target es2017 emit (via helper): class A { constructor(){ this.x = 1; } }  — assign semantics (legacy)

// modern guidance: target es2022 for Node 18+, es2022/es2023 for evergreen web (check baseline via caniuse)
// for libs: ship esnext + separate cjs, declare via exports map (see 08 3.1)
```

### Mentor note

Default to `target: "es2022"` and `useDefineForClassFields: true` (the 5.6 default when target >= es2022). Document polyfill strategy if you use `lib: ["esnext"]`.

### Common confusion

- "`lib` polyfills runtime" — no. `lib` only adds types; runtime polyfill is separate (`core-js` or manual).

### Performance note

Lower target emits helpers that increase bundle size and parse cost. Measure before lowering for "support."
