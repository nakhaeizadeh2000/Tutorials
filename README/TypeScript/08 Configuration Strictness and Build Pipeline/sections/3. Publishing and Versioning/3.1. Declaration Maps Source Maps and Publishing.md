## 3.1. Declaration Maps, Source Maps and Publishing

### 1) **Config** (declarationMap)

**Config:**

- `declaration: true` — emit `.d.ts`.
- `declarationMap: true` — emit `.d.ts.map` (jump-to-source for consumers' go-to-definition).
- `sourceMap: true` — emit `.js.map` (debugger maps to `.ts`).
- `composite` + `declarationMap` for project refs libraries.

```jsonc
// tsconfig for publishable library
{
  "compilerOptions": {
    "target": "es2022",
    "module": "nodenext",
    "declaration": true,
    "declarationMap": true,
    "sourceMap": true,
    "outDir": "dist",
    "composite": true,
    "strict": true
  },
  "include": ["src"]
}
```

Result: `dist/index.js`, `dist/index.js.map`, `dist/index.d.ts`, `dist/index.d.ts.map`, `dist/tsconfig.tsbuildinfo` (if incremental).

### 2) **Example** (npm publish)

```jsonc
// package.json for published library (dual ESM/CJS or ESM-only)
{
  "name": "@repo/mylib",
  "version": "1.2.0",
  "type": "module",
  "main": "./dist/index.js",          // or via exports
  "types": "./dist/index.d.ts",
  "exports": {
    ".": {
      "types": "./dist/index.d.ts",
      "import": "./dist/index.js",
      "default": "./dist/index.js"
    }
  },
  "files": ["dist"],
  "sideEffects": false
}
// build: tsc --build
// publish: npm publish (only dist + maps)

// declarationMap benefit: consumer Cmd+click on greet() jumps to src/greet.ts (via .d.ts.map), not .d.ts
```

Monorepo `reference` libraries use `composite` + `outDir` per package; consumer packages reference via package name.

### 3) **Pitfall** (missing .d.ts)

**Pitfalls:**

- Publishing without `.d.ts` — consumers using TS get `Could not find declaration file` and fallback to `any`.
- `exclude: ["dist"]` but `declaration` emits to `dist` — `tsc` cleans incorrectly if `include` overlaps; use `outDir`.
- `sourceMap: false` — consumers can't debug; library stack traces show `dist` JS lines, not `src`.
- Versioning: breaking type change (e.g., `string` → `Branded string`, or `optional` → `required`) is *major* version bump (SemVer) even if JS runtime unchanged.

```typescript
// bad: published js without types
// package.json: "main": "./dist/index.js" but no types field — consumer TS broken

// good: types field + exports types
// also good: publish declarationMap for DX

// bad: hand-edit .d.ts after emit — next build overwrites
// generate via tsc always; for custom augment, add separate .d.ts hand-authored and include in files

// for untyped dependency, recommend @types/*:
// package.json: "dependencies": { "express": "^4.18.0" }, "devDependencies": { "@types/express": "^4" }
```

### Mentor note

Enforce `files: ["dist"]` and `prepublishOnly: "tsc --build"` (or `prepack`) — prevents publishing `src` accidentally and ensures maps present.

### Common confusion

- "`declarationMap` changes runtime" — no, it's mapping for IDE only.

### Performance note

`declarationMap` adds ~5–10% to publish size; but saves expensive "read .d.ts then guess source" for thousands of consumers — worth it.
