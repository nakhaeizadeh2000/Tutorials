## 2.1. Project References and Composite

### 1) **Definition** (composite)

**Definition** — Project References split a repo into separate TS programs that build incrementally via `tsc --build`. `composite: true` marks a project as reference-able (forces `strict` subset, outDir, rootDir constraints, no `allowJs` without `checkJs` parity).

```jsonc
// tsconfig.json (root)
{
  "files": [],
  "references": [{ "path": "./packages/app" }, { "path": "./packages/shared" }]
}
// packages/shared/tsconfig.json
{
  "compilerOptions": { "composite": true, "outDir": "./dist", "rootDir": "./src", "strict": true },
  "include": ["src"]
}
// packages/app/tsconfig.json
{
  "compilerOptions": { "composite": true, "outDir": "./dist" },
  "references": [{ "path": "../shared" }],
  "include": ["src"]
}
// build all: tsc --build
// build + deps: tsc --build --verbose (skips up-to-date)
```

`composite` also enables `tsc --build` increment with `.tsbuildinfo` cache per project.

---

### 2) **Example** (monorepo refs)

```typescript
// packages/shared/src/utils.ts
export function formatId(id: string): string { return id.toUpperCase(); }

// packages/app/src/index.ts
import { formatId } from "@shared/utils.js"; // paths via project refs + bundler, or package.json exports
console.log(formatId("abc")); // ABC

// alternative to heavy paths — use workspace package names (pnpm/yarn)
// packages/shared/package.json: { "name": "@repo/shared", "exports": "./dist/utils.js" }
// app imports: import { formatId } from "@repo/shared";
```

Project refs give *incremental* type checking per package (faster) and enforce boundary: `app` cannot import from `shared` internals not exported via `shared`'s `index.ts` if `shared` declaration emit controls visibility.

---

### 3) **Link** (to Unified)

Monorepo architecture details beyond `tsconfig`:

- Workspace management (pnpm/yarn), shared code strategy → [UnifiedArchitecture track](<../../../UnifiedArchitecture/README.md>) — monorepo/polyrepo trade, shared libraries.
- `paths` vs references: `paths` is alias within *one* program; `references` are *separate programs* with separate checking/emit. For cross-package, prefer references.
- CI integration: `tsc --build --force` in CI vs incremental cache.

```jsonc
// bad: paths for cross-package without refs — single program, slow check
{ "compilerOptions": { "paths": { "@shared/*": ["../shared/src/*"] } } }
// good: reference + package name
// app imports "@repo/shared" via package.json exports, checked via reference
```

**Common confusion** —

- "References change runtime" — no, only checker/build orchestration. Runtime still via package imports.

**Performance note** —

`composite` incremental `.tsbuildinfo` per project reduces typecheck time 50–80% on unchanged packages. In CI, cache `**/*.tsbuildinfo`.

**Mentor note** —

Default policy: monorepo with >2 packages → use project references. Measure `tsc --build` cold vs incremental — typically 3–5× win.
