## 3.2. Utility Picks (Partial, Pick, Record intro)

### 1) **Use** (Partial for updates)

**Definition** — TypeScript ships built-in mapped utilities (all type-level, zero emit). Intro triad:

- `Partial<T>` — all props optional: `{ [K in keyof T]?: T[K] }` — for update payloads.
- `Pick<T, K>` — subset by keys: `{ [K in K]: T[K] }` — for views.
- `Record<K, V>` — index type `{ [P in K]: V }` — for dictionaries.

```typescript
type User = { id: string; name: string; email: string; age: number };

type UserPatch = Partial<User>; // { id?: string; name?: string; ... }
const patch: UserPatch = { name: "Ada" }; // partial update ok

type UserPreview = Pick<User, "id" | "name">; // { id: string; name: string }
const preview: UserPreview = { id: "1", name: "Ada" };

type Role = "admin" | "member";
type RoleCounts = Record<Role, number>; // { admin: number; member: number }
const counts: RoleCounts = { admin: 1, member: 5 };

// implementations are mapped types — see 06 for mechanics
// type Partial<T> = { [K in keyof T]?: T[K] };
// type Pick<T, K extends keyof T> = { [P in K]: T[P] };
```

### 2) **Bad** (any for missing props)

```typescript
// bad: any for "maybe missing"
function updateBad(user: any) { /* accepts anything */ }
updateBad({ age: "not a number" }); // no error

// bad: manually retyping subset — drifts
type PreviewBad = { id: string; name: string }; // duplicate of Pick
// when User changes, PreviewBad goes stale

// good: derive, don't duplicate
type PreviewGood = Pick<User, "id" | "name">; // stays in sync

// bad: using {} index for dict
type DictBad = { [key: string]: number }; // allows any key, no key set control
// good: Record with literal union keys enforces known keys
type Keys = "a" | "b";
type DictGood = Record<Keys, number>; // { a: number; b: number }
let d: DictGood = { a: 1, b: 2 };
// let d2: DictGood = { a: 1 }; // error — missing b
```

**Common confusion** —

- "`Partial` makes values possibly undefined" — it makes *keys* optional; reading `partial.name` is `string | undefined` but absence and `undefined` differ under `exactOptionalPropertyTypes`.
- "`Record<string, T>` vs `Map<string, T>`" — `Record` is plain object shape (JSON-serializable); `Map` is runtime class with identity semantics.

**Performance note** — Types are erased (zero emit); checker cost dominates. For this feature, keep types shallow and measure `tsc --extendedDiagnostics` if checker slows.

**Mentor note** —

Enforce derivation: any time a PR manually repeats a subset of a type, suggest `Pick`/`Omit`. The one-line comment "derived so it stays synced" teaches the next author.
