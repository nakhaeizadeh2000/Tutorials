## 3.1. Composition over Inheritance (intersection for extension)

### 1) **Pattern** (type = A & B)

**Pattern** — Compose with intersection (`&`), not deep inheritance. A type `T = A & B` requires both `A` and `B` and can be built from small, focused parts. Prefer flat composition over multi-level `extends` chains.

```typescript
type Timestamps = { createdAt: Date; updatedAt: Date };
type SoftDelete = { deletedAt: Date | null };
type HasId = { id: string };

type User = HasId & Timestamps & { name: string; email: string };
type Post = HasId & Timestamps & SoftDelete & { title: string; body: string };

const u: User = { id: "1", name: "Ava", email: "a@b.com", createdAt: new Date(), updatedAt: new Date() };

// extends equivalent (works, but chains grow)
interface IUser extends HasId, Timestamps { name: string; email: string }
// when hierarchy is shallow, intersection is clearer and works for types (not just interfaces)
```

### 2) **Good** (flat types)

**Good — flat, explicit:**

```typescript
// good: small pieces composed at use site — visible dependencies
type Audited<T> = T & Timestamps;
type WithDelete<T> = T & SoftDelete;

type BaseUser = { id: string; name: string };
type StoredUser = Audited<BaseUser>; // { id, name, createdAt, updatedAt }
type StoredPost = WithDelete<Audited<{ title: string }>>;

// bad: deep inheritance hides shape
interface Base { id: string; }
interface AuditedBase extends Base { createdAt: Date; updatedAt: Date; }
interface UserBad extends AuditedBase { name: string; }
// now UserBad's shape requires tracing 3 levels

// good supports union composition; extends does not compose with unions cleanly
type Role = "admin" | "member";
type UserWithRole = User & { role: Role }; // intersection with union member — natural
```

### Mentor note

In code review, ask: "does this `extends` chain also need union/conditional later?" If yes, switch to `type &`. Consistency beats inheritance purity.

### Common confusion

- "`extends` and `&` are identical" — similar, but `interface extends` is open/mergeable and nominal-ish for classes; `type &` is closed and composes with any type operator.
