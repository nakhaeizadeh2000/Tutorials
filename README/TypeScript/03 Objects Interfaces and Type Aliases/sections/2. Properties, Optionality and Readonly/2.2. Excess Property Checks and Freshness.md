## 2.2. Excess Property Checks and Freshness

### 1) **Mechanism** (fresh object checks)

**Definition** — TypeScript is structurally typed, but *fresh* object literals get an extra check: if you assign a literal directly to a typed target, extra properties not in the target are flagged. Once the value passes through a variable, freshness is lost and extra props are allowed (width subtyping).

```typescript
type User = { name: string };

const u1: User = { name: "Ava", age: 30 } // error: Object literal may only specify known properties (fresh)
const tmp = { name: "Ava", age: 30 };
const u2: User = tmp; // ok — tmp not fresh, extra age ignored (structural)

function greet(u: User) { console.log(u.name); }
greet({ name: "Ava", age: 30 }); // error — fresh literal
greet(tmp); // ok
```

Why: catches typos (`colour` vs `color`) without making structural typing nominal.

### 2) **Example** (extra prop error)

```typescript
type Options = { timeout: number; retries?: number };

// typo caught thanks to freshness
// const o: Options = { timeout: 1000, retrys: 3 }; // error: 'retrys' does not exist — caught!

// but staleness bypasses:
const oTmp = { timeout: 1000, retrys: 3 };
const o2: Options = oTmp; // no error — slipping through!
// fixes: use satisfies or explicit check

const o3 = { timeout: 1000, retrys: 3 } satisfies Options // error — still caught via satisfies (checks shape)

// controlling freshness
type Config = { host: string; port: number };
function connect(c: Config) {}

connect({ host: "localhost", port: 5432 }); // ok
// connect({ host: "localhost", port: 5432, ssl: true }); // error — excess ssl
const cfg = { host: "localhost", port: 5432, ssl: true };
connect(cfg); // ok — but did you mean to pass ssl? Bug hides when stale
```

### 3) **Workaround** (intermediate variable)

**When excess check is legit (not a typo), use intentional mechanisms — not blind suppression:**

- Use intermediate variable only if extra props are *intended* (composition).
- Prefer `satisfies` to check without freshness trap.
- For APIs that accept extra props, use index signature or `Record` — don't rely on staleness.

```typescript
type Props = { name: string };

// bad: suppress with as Props — hides typo too
const pBad = { name: "Ava", naem: "typo" } as Props; // typo hidden!

// good: explicit extra props via intersection if intended
type Extended = Props & { age: number };
const pGood: Extended = { name: "Ava", age: 30 };

// good: spread to keep freshness logic clear
const base = { name: "Ava", age: 30 };
const p2: Props = { ...base }; // fresh literal from spread — still checks? Actually spread retains freshness but strips excess? In practice TS still checks literal, but object spread copies age — use explicit pick
const p3: Props = { name: base.name }; // explicit

// pattern: Omit to allow pass-through
type UserWithMeta = Props & { meta: unknown };
function takesProps(p: Props) { console.log(p.name); }
const full: UserWithMeta = { name: "Ava", meta: {} };
takesProps(full); // ok — structural (extra meta ignored) — intent clear via type
```

### Mentor note

Teach freshness as "literal is checked strictly, variable is checked structurally." Demo typo `retris` vs `retries` live — the error appears only on literal. Students then understand why intermediate variables hide bugs.

### Common confusion

- "Why does `const x = { a, b }; fn(x)` pass but `fn({ a, b })` fails?" — freshness loss on variable. It's intentional typo-protection.
- "`as` fixes excess error" — it hides it; prefer fixing the type or picking the property.

### Performance note

Excess checks are compile-time only; stale vs fresh has no emit difference. The cost is PR quality — suppressing with `as` moves bug from compile time to runtime.
