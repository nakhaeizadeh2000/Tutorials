## 2.1. Optional, readonly and Index Signatures

### 1) **Definition** (?: , readonly)

**Definition:**

- `prop?: T` — optional property: may be absent or `T`. Under `exactOptionalPropertyTypes`, `T` vs `T | undefined` differ (see 5.6 note below).
- `readonly prop: T` — property cannot be reassigned after creation (shallow, compile-time only).
- Index signature `[key: string]: T` — object may have arbitrary string keys of type `T`, plus defined props must be compatible.

```typescript
type User = {
  id: string;
  name: string;
  nickname?: string;          // optional
  readonly createdAt: Date;  // readonly
};

let u: User = { id: "1", name: "Ava", createdAt: new Date() };
u.name = "Ada"; // ok
// u.createdAt = new Date(); // error — readonly
// u.nickname is string | undefined when read (even though ? means absent)

type Dict = {
  known: string;
  [key: string]: string; // index: any extra string key → string
};
const d: Dict = { known: "hi", extra: "hey" }; // ok
// d.known must be string — compatible with index type

type ROArray = readonly string[]; // shorthand for ReadonlyArray
let ro: ROArray = ["a", "b"];
// ro.push("c"); // error — readonly
```

`Readonly<T>`, `Partial<T>` etc use mapped-type modifiers — see [06 2.1 Mapped modifiers](<../../../06%20Advanced%20Types%20Conditional%20Mapped%20Template%20Literal/sections/2.%20Mapped,%20Template%20Literal%20and%20Key%20Remapping/2.1.%20Mapped%20Types%20and%20Modifiers%20-readonly%20-..md>).

### 2) **Example** (readonly props)

```typescript
// shallow readonly — nested not frozen
type Config = { readonly db: { host: string } };
let cfg: Config = { db: { host: "localhost" } };
// cfg.db = { host: "remote" }; // error
cfg.db.host = "remote"; // ok — shallow! Deep freeze needs utility type

// deep readonly helper (advanced — see 06)
type DeepReadonly<T> = { readonly [K in keyof T]: DeepReadonly<T[K]> };
let cfg2: DeepReadonly<Config> = { db: { host: "localhost" } } as DeepReadonly<Config>;
// cfg2.db.host = "x"; // error if DeepReadonly applied recursively

// index signature vs Record
type A = { [key: string]: number }; // any string key allowed
type B = Record<string, number>;    // same, but more idiomatic

// numeric index
type ArrLike = { [index: number]: string; length: number };
const a: ArrLike = { 0: "a", 1: "b", length: 2 };
```

### 3) **Mistake** (optional vs | undefined)

**Common mistake: `?:` vs `: T | undefined`:**

```typescript
type WithOptional = { nickname?: string };
type WithUndefined = { nickname: string | undefined };

let o1: WithOptional = {}; // ok — nickname absent
let o2: WithUndefined = {}; // error — nickname required (must be present, may be undefined)
let o3: WithUndefined = { nickname: undefined }; // ok

let u1: WithOptional = { nickname: "Ada" };
let v1: string = u1.nickname ?? "anon"; // u1.nickname is string | undefined

// exactOptionalPropertyTypes (5.6 — stricter)
// with exactOptionalPropertyTypes: true, `?: string` does NOT accept undefined unless | undefined added
type StrictOpt = { nickname?: string };
type StrictOpt2 = { nickname?: string | undefined };
// let s: StrictOpt = { nickname: undefined }; // error under exactOptionalPropertyTypes
let s2: StrictOpt2 = { nickname: undefined }; // ok

// bad: mutable index signature allows widening bugs
type BadDict = { [k: string]: string };
let bad: BadDict = { known: "hi" };
bad.randomProp = "oops"; // allowed — consider stricter known keys via union
```

### Mentor note

Prefer `readonly` for anything crossing module boundaries (config, DTOs). Shallow cost is zero, and it prevents the most common PR mutation: passing `config` and mutating `config.db.host` downstream. Pair with `Readonly<T>` at boundaries.

### Performance note

`readonly` has zero emit cost — erased. Index signatures produce no helpers; they only affect checking. Over-broad `[key: string]: unknown` defeats strict key checking — measure PR-review time lost before adding one.
