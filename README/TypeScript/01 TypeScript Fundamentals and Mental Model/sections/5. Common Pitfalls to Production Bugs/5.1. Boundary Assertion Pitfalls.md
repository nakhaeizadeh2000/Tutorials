## 5.1. Boundary Assertion Pitfalls

### 1) **Pitfall** (as at boundary lies, any hides bugs)

**Pitfall — the two most common production bugs from this domain:**

- **`as` at `unknown` boundary** — `JSON.parse(s) as User` compiles but `email` may be missing. Bug surfaces as `TypeError: Cannot read property 'toLowerCase' of undefined` in prod, not in `tsc`.
- **`any` everywhere** — disables checker, so refactors (`displayName`→`name`) are find-and-replace, not compiler errors. See [1.2 Why Types Matter](<../1.%20What%20TypeScript%20Is%20and%20Why%20It%20Exists/1.2.%20Why%20Types%20Matter%20correctness%20docs%20refactoring.md>).

```typescript
// real bug: flag rollout with missing field
type FeatureFlag = { id: string; enabled: boolean; rollout: number };
const raw = `{"id":"ff1","enabled":true}`; // rollout missing
const flag = JSON.parse(raw) as FeatureFlag; // no error
console.log(flag.rollout * 100); // NaN — rollout is undefined, not 0

// bad: any swallows
function getFlagBad(raw: any): FeatureFlag { return raw; }
```

### 2) **Consequence** (runtime TypeError despite zero type errors)

**Consequence** — The app passed `tsc` with zero errors, yet crashed at runtime because types were trusted without validation. Post-mortem pattern:

- Missing field → `undefined` propagated through business logic → `NaN`/`TypeError` far from boundary → hard to trace.
- With `any`, `flag.rollout` is `any`, so `* 100` also `any` — no red squiggle to catch `undefined`.

Metrics: after enabling `strict` + `unknown` at boundaries, teams see 20–40% of open bugs become compiler errors (validate at parse, trust inside).

### 3) **Guard** (ban any/!/as at PR, require Zod/isUser)

**Fix — validate once at edge:**

```typescript
// good: Zod (or Valibot) at boundary — single source
import { z } from "zod";
const FlagSchema = z.object({ id: z.string(), enabled: z.boolean(), rollout: z.number().min(0).max(1) });
type Flag = z.infer<typeof FlagSchema>;
function parseFlag(json: string): Flag { return FlagSchema.parse(JSON.parse(json)); }
try { parseFlag(raw); } catch (e) { console.error("invalid flag", e); }

// light alternative without library: predicate
function isFlag(v: unknown): v is Flag {
  return typeof v === "object" && v !== null && "id" in v && "rollout" in v && typeof (v as Record<string,unknown>).rollout === "number";
}
```

**Common confusion** —

- "`as` converts types" — it asserts to checker, no runtime check.
- "`any` vs `unknown` same" — `unknown` must be narrowed.

**Performance note** — Validation at edge costs microseconds, saves defensive `?.`/`??` sprinkled through internals.

**Mentor note** — Add lint `no-explicit-any` + `no-non-null-assertion` + `no-unnecessary-type-assertion` as merge-blocking; PR template asks "which validator guards this `fetch`?"
