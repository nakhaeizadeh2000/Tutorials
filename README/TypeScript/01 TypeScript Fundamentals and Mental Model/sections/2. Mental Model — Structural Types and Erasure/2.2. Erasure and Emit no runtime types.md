## 2.2. Erasure and Emit (no runtime types)

### 1) **Definition** (types erased, no reflection)

**Definition** — TypeScript erases *all* type syntax when emitting JavaScript: `type`, `interface`, annotations, generics, and most `declare` forms disappear. There is no runtime representation of an interface to reflect on — `typeof myInterface` is not a thing.

Consequences that surprise newcomers from Java/C#:

- No runtime type parameters (`Array<string>` and `Array<number>` are the same `Array` at runtime).
- `interface` cannot be used as a value (`new MyInterface()` never compiles).
- `enum` *is* the exception — it emits a real object (use union literals instead — see [02 3.1 Enums](<../../../02%20Primitive%20Literal%20and%20Union%20Types/sections/3.%20Enums,%20Tuples%20and%20Special%20Primitives/3.1.%20Enums%20vs%20Union%20Literals%20when%20enums%20hurt.md>)).

```typescript
interface User { id: string; name: string }
type Id<T> = T;

function isUser(value: unknown): value is User {
  // cannot write: if (value instanceof User) — User erased
  return typeof value === "object" && value !== null && "id" in value && "name" in value;
}

// emit is plain JS — verify with tsc --noEmit false or playground
// interface User {}  → (nothing)
// function isUser(value) { ... }
```

### 2) **Problem** (trying to check types at runtime)

**Problem — the runtime gap:** data from `fetch`, `localStorage`, `process.env`, `JSON.parse`, and file I/O is `unknown` at runtime even if you annotate it as `User`. Annotating doesn't validate:

```typescript
// bad: assertion lies — no check happens at runtime
type User = { id: string; email: string };
async function loadBad(): Promise<User> {
  const raw = await fetch("/api/user").then(r => r.json());
  return raw as User; // compiles, crashes later if shape wrong
}

// symptom: runtime bug despite "no type errors"
// loadBad().then(u => console.log(u.email.toLowerCase())) // TypeError if email missing

// good: validate at boundary, then narrow
type UserGood = { id: string; email: string };
function assertIsUser(v: unknown): asserts v is UserGood {
  if (typeof v !== "object" || v === null || !("id" in v) || !("email" in v)) {
    throw new Error("invalid User");
  }
}
async function loadGood(): Promise<UserGood> {
  const data: unknown = await fetch("/api/user").then(r => r.json());
  assertIsUser(data);
  return data; // narrowed — safe downstream
}
```

Expert guard forms: `value is T` (type predicate) and `asserts value is T` (assertion function) are covered in [02 2.3 Narrowing](<../../../02%20Primitive%20Literal%20and%20Union%20Types/sections/2.%20Unions,%20Intersections%20and%20Narrowing/2.3.%20Control-Flow%20Narrowing%20if%20in%20typeof.md>).

### 3) **Good** (use discriminant or codec like Zod)

**Modern guidance — bridge the gap properly:**

- **For unions** — use a discriminant property (`kind: "a" | "b"`) checked with `switch` — no library needed (see [02 2.1 Unions](<../../../02%20Primitive%20Literal%20and%20Union%20Types/sections/2.%20Unions,%20Intersections%20and%20Narrowing/2.1.%20Union%20Types%20and%20Discriminants.md>)).
- **For external data** — use a runtime validator/codec: [Zod](https://zod.dev) / [Valibot](https://valibot.dev) / `arktype`. Schema parses `unknown` → typed value and returns `z.infer` type without duplication (see [10 2.1 Zod bridge](<../../../10%20Migration%20Interop%20and%20Runtime%20Gaps/sections/2.%20Interop%20and%20Boundaries/2.1.%20Zod%20Valibot%20and%20Runtime%20Validation%20TS%20erasure%20bridge.md>)).

```typescript
// codec pattern (Zod sketch — no runtime dependency needed to understand shape)
import { z } from "zod"; // external — see domain 10 for full example
const UserSchema = z.object({ id: z.string(), email: z.string().email() });
type UserZ = z.infer<typeof UserSchema>; // inferred, not duplicated

// const parsed = UserSchema.parse(unknownJson); // throws if invalid, returns UserZ if ok

// light codec without library — discriminated union
type Result<T> = { ok: true; value: T } | { ok: false; error: string };
function parseUser(json: string): Result<UserGood> {
  try {
    const v: unknown = JSON.parse(json);
    assertIsUser(v);
    return { ok: true, value: v };
  } catch (e) {
    return { ok: false, error: String(e) };
  }
}
```

### Mentor note

Demo the gap live: `JSON.parse('{"id":1}') as User` passes `tsc` but fails at `user.email.toLowerCase()`. Then fix with one `isUser` guard. The lesson lands in 60 seconds.

### Common confusion

- "Generics work at runtime" — no. `identity<string>("a")` and `identity<number>(1)` are identical JS.
- "`as` converts types" — it doesn't; it *asserts* to the checker. A wrong `as` is a runtime time bomb.

### Performance note

Validation at boundaries costs CPU, but saves far more by removing defensive `?.`/`??` peppered through internals. Validate once at the edge, trust inside. Profile only the boundary parsers if throughput matters.
