## 4.1. Erasable Mental Model and Strict-First Checklist

### 1) **Definition** (what senior must enforce — erasure, strict, toolchain split)

**Definition** — The fundamentals domain establishes three invariants seniors gate in every PR:

- **Erasure is the mental model** — types are `JS + checker`, not runtime. Demo `.ts → .js` side-by-side; require discriminant or `Zod` at every `unknown` boundary (`fetch`, `JSON.parse`, `env`). See [2.2. Erasure and Emit no runtime types](<../2.%20Mental%20Model%20%E2%80%94%20Structural%20Types%20and%20Erasure/2.2.%20Erasure%20and%20Emit%20no%20runtime%20types.md>).
- **Strict-first** — `strict: true` + `noUncheckedIndexedAccess: true` from day one. No `any`/`!`/`as` at boundaries without validator.
- **Toolchain split** — `tsx` (or `swc`/`esbuild`) for run, `tsc --noEmit` for check — two processes. See [3.1. tsc tsx and ts-node Overview when to use which](<../3.%20Toolchain%20First%20Look/3.1.%20tsc%20tsx%20and%20ts-node%20Overview%20when%20to%20use%20which.md>).

```typescript
// checklist enforced in CI
// tsc --noEmit (or --build) must pass
// banned via eslint/biome: any, !, as across module boundary
type User = { id: string; email: string };
const raw: unknown = JSON.parse(`{"id":"1"}`); // missing email
// const u = raw as User; // reject — lies, email undefined
// good: validate
function isUser(v: unknown): v is User { return typeof v === "object" && v !== null && "id" in v && "email" in v; }
if (!isUser(raw)) throw new Error("invalid");
console.log(raw.email); // safe — narrowed
```

### 2) **Checklist** (PR gate: strict, no any/!/as, Zod at boundary)

**Mentor checklist — reject unless:**

- `any` has `// reason:` + ticket, else `unknown` + guard.
- `!` has preceding `if` guard or `?.`/`??` fallback.
- `as` only inside validator (`z.infer`, `isUser`), not at `fetch` boundary.
- `const enum` not used with `isolatedModules` (prefer union literal).

```typescript
// good PR: boundary validated once, trusted inside
import { z } from "zod";
const UserSchema = z.object({ id: z.string(), email: z.string().email() });
type UserZ = z.infer<typeof UserSchema>;
function parseUser(json: string): UserZ { return UserSchema.parse(JSON.parse(json)); }
```

---

### 3) **Mentor** (how to teach erasure live)

**Common confusion** —

- "Types are removed, so TS is slower" — no, erased zero-cost; slowness is helpers from `target`, not annotations.
- "`tsc` is for emit, `tsx` checks" — opposite: `tsx` transpiles only, `tsc --noEmit` checks.

**Performance note** — `skipLibCheck: true` for apps saves seconds; keep `false` for libs publishing types. Measure `tsc --extendedDiagnostics`.

**Mentor note** — Teach erasure first, 60 seconds:

1. Show `.ts` with `interface User` and emit `.js` where it disappears (playground `Emit`).
2. Show `JSON.parse('{"id":1}') as User` passes `tsc` but fails `user.email.toLowerCase()` at runtime.
3. Fix with one `isUser` guard — lesson lands. Then connect to [10 1.2 any unknown](<../../../10%20Migration%20Interop%20and%20Runtime%20Gaps/sections/1.%20Migrating%20JS%20to%20TS/1.2.%20any%20unknown%20and%20Gradual%20Typing.md>) and [10 2.1 Zod](<../../../10%20Migration%20Interop%20and%20Runtime%20Gaps/sections/2.%20Interop%20and%20Boundaries/2.1.%20Zod%20Valibot%20and%20Runtime%20Validation%20TS%20erasure%20bridge.md>).
