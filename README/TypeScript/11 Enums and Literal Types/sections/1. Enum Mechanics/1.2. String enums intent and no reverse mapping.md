## 1.2. String enums intent and no reverse mapping

A string enum creates named runtime string values and corresponding enum member types. Explicit values can be readable in logs and payloads, but their meaning must still match the external contract. A literal union and ordinary JavaScript values can serve many of the same application needs with a different type/API contract and no enum transformation.

Examples use TypeScript 7.0.2 and Node.js 20.20.2. Save each independent fence under its filename. Compile with `tsc --strict --exactOptionalPropertyTypes --noUncheckedIndexedAccess --removeComments --target es2022 --module commonjs --lib es2022,dom --outDir dist FILE.ts`; run `node dist/FILE.js`. Activate negatives individually with those flags and --noEmit instead of --outDir dist. The enum programs require transformation and fail TS1294 with erasableSyntaxOnly; the final union/const-object program also passes that option.

### 1) **Explicit values and the enum member contract**

A string member needs a supported string initializer, such as a string literal or another string enum member. There is no string auto-increment. Reordering these explicitly initialized declarations leaves their values unchanged; changing an initializer still changes the value contract. The [primary string-enum guide](https://www.typescriptlang.org/docs/handbook/enums.html#string-enums) establishes that behavior. Use the values required by the API or stored format rather than assuming every external value should be converted to a string.

Save as values.ts.

```typescript
export {};
enum Method { Get = "GET", Post = "POST" }
enum Reordered { Post = "POST", Get = "GET" }
function call(method: Method, path: string): string { return `${method} ${path}`; }
console.log(call(Method.Get, "/a"), Reordered.Get);
console.log(JSON.stringify({ method: Method.Post }));
// call("GET", "/a"); // TS2345: a raw literal is not a Method member
// enum MissingInitializer { Get = "GET", Post } // TS1061
type RawMethod = "GET" | "POST";
const raw: RawMethod = Method.Get;
console.log(raw.toLowerCase());
// const intoEnum: Method = "GET"; // TS2322

type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type MemberOut = Expect<Method.Get extends "GET" ? true : false>;
type LiteralIn = Expect<Equal<"GET" extends Method ? true : false, false>>;
```

The output is `GET /a GET`, `{"method":"POST"}`, then `get`; both probes compile. The enum member flows into its corresponding literal contract, but the raw literal is rejected in the reverse direction. An API requiring Method is therefore different from an API accepting the structural union RawMethod. Neither declaration parses unknown data. This example formats a string locally; it does not perform an HTTP call or test a foreign protocol.

### 2) **No generated reverse map does not mean every value lookup must miss**

String members receive forward properties from member names to values, without the numeric enum's additional reverse assignments. Bracket lookup still reads ordinary keys. A value that coincides with a member name can therefore find that forward property; it is not evidence of a generated reverse map. If names are actually needed from values, define an inverse policy and account for absence and duplicate values.

Save as inverse.ts.

```typescript
export {};
enum Method { Get = "GET", Post = "POST" }
console.log(Object.keys(Method).join(","), Reflect.get(Method, "GET"));
// console.log(Method["GET"]); // TS2551: GET is a value, not this enum's member key
const inverse = new Map<string, string>(
  Object.entries(Method).map(([name, value]) => [value, name] as const),
);
console.log(inverse.get("POST"), inverse.get("PATCH"));
enum Mirror { Ready = "Ready" }
console.log(Reflect.get(Mirror, Mirror.Ready));
enum Duplicate { First = "SAME", Second = "SAME" }
const duplicateInverse = new Map<string, string>(
  Object.entries(Duplicate).map(([name, value]) => [value, name] as const),
);
console.log(duplicateInverse.size, duplicateInverse.get("SAME"));
function parseMethod(value: unknown): Method {
  if (value === Method.Get || value === Method.Post) return value;
  throw new Error("invalid method");
}
console.log(parseMethod("GET"));
for (const input of ["Get", "DELETE", 42]) {
  try { parseMethod(input); } catch (error) { console.log(error instanceof Error ? error.message : "unexpected"); }
}
const missingName = inverse.get("PATCH");
// missingName.toUpperCase(); // TS18048

type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type Names = Expect<Equal<keyof typeof Method, "Get" | "Post">>;
type MissingName = Expect<Equal<typeof missingName, string | undefined>>;
```

The output is `Get,Post undefined`, `Post undefined`, `Ready`, `1 Second`, `GET`, followed by three `invalid method` lines; both probes compile. The inverse keeps the last name for a duplicate value, while a missing value stays undefined. Its honest string | undefined read avoids asserting a complete Record for arbitrary strings. If all names for a duplicate value are required, group names into arrays rather than silently choosing one.

ParseMethod actually checks this enum's two admitted values. A key spelling such as Get is not a value spelling such as GET. Adding an enum member does not automatically extend this handwritten parser; test the intended boundary after changing the set. The [numeric reverse-map owner](<./1.1. Numeric enums auto values and reverse mapping.md>) provides the contrasting emitted table, and [Map entry contracts](<../../../10 Arrays Tuples and Collections/sections/3. Collections and Selection/3.1. Map and Set typing generics over collections.md>) owns missing reads and entry conversion.

### 3) **Literal unions can use ordinary runtime defaults, keys and tables**

A type alias erases, but a string literal expression is a runtime value. A const binding initialized to GET retains its literal type in the example below and works as a union-typed default. It does not widen to string merely because it lacks an annotation. A mutable let binding has a different inferred contract. The [inference owner](<../../../03 Basic Types and Annotations/sections/3. Annotations Inference and Literals/3.2. Type inference widening and contextual typing.md>) explains the contexts.

Save as alternatives.ts.

```typescript
export {};
type Method = "GET" | "POST";
const DEFAULT_METHOD = "GET";
function serve(method: Method = DEFAULT_METHOD): string { return `serving ${method}`; }
let mutableDefault = "GET";
// function unstable(method: Method = mutableDefault): string { return method; } // TS2322
const NamedMethod = { Get: "GET", Post: "POST" } as const;
type NamedValue = typeof NamedMethod[keyof typeof NamedMethod];
const counts: Record<NamedValue, number> = { [NamedMethod.Get]: 1, [NamedMethod.Post]: 2 };
console.log(serve(), NamedMethod.Get, counts.POST, Object.values(NamedMethod).join(","));
console.log(serve("POST"));
// console.log(Method); // TS2693: the type alias does not construct a runtime object
// serve("PATCH"); // TS2345

type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type LiteralDefault = Expect<Equal<typeof DEFAULT_METHOD, "GET">>;
type MutableDefault = Expect<Equal<typeof mutableDefault, string>>;
type NamedValues = Expect<Equal<NamedValue, Method>>;
```

The output is `serving GET GET 2 GET,POST`, then `serving POST`; three probes compile. The program supplies runtime defaults, computed keys and enumeration without an enum. It still contains a real NamedMethod object; erasable syntax does not erase ordinary data. A plain union can also use a literal directly as a default when no named table is needed.

Choose from existing API identity, consumer expectations and the execution pipeline. An enum can be appropriate when callers should use its member contract or an existing integration already exposes it. A union can accept matching raw literals; a const object can supply named runtime constants and a derived union. [The union-versus-enum comparison](<../../../07 Unions Intersections and Narrowing/sections/1. Union Types/1.3. Literal unions enums vs unions and exhaustiveness preview.md>) owns the broader distinction, and [migration](<../2. Enums vs Erasable Alternatives/2.2. erasableSyntaxOnly the enum ban and migration.md>) owns changing an existing contract safely.

### 4) **Common confusion**

No generated reverse mapping means no extra reverse assignments, not that a value can never equal a forward key. An explicit inverse can still lose duplicate names and must account for missing reads. A derived construction tracks source entries, but cannot decide which collision policy the application needs.

A union member written in a type is not a runtime object; the corresponding literal used in an expression is a runtime value. A const primitive default can retain its literal without as const. Defaults, computed property names and iteration do not uniquely require enums.

### 5) **Performance note**

String enums initialize runtime objects and access their properties. Const objects, Map inverses, enumeration and JSON serialization also perform real work; union aliases and type queries erase. The local outputs show representations, not a byte-size or speed benchmark. No exact half-size relationship, universal string-versus-number cost or runtime equality between all representation choices was measured. Choose the needed value and API contract first.

### 6) **Mentor note**

Ask why call rejects a raw GET literal while serve accepts it, then ask which expression supplies serve's default at runtime. Have the learner explain Ready's successful lookup and Second's duplicate inverse without claiming that string enums secretly generate reverse maps.

For practice, add Delete = DELETE to Method in inverse.ts and update the Names probe. Initially leave parseMethod unchanged and verify it still rejects DELETE, while Object.keys and the derived inverse already contain the new entry. Extend the actual check to admit Method.Delete, replace DELETE with PATCH in the invalid-input loop and verify DELETE now parses while PATCH still fails. Adding a declaration or asserting the input type would not implement that boundary change.
