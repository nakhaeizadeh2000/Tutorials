### 2) **Separate a mechanism failure from an enum-specific decision**

Consider an inline const object whose Read property contains GET. If a caller confuses the member name Read with the value GET, the [string-enum and object comparison](<../1. Enum Mechanics/1.2. String enums intent and no reverse mapping.md>) supplies the application context. If the question is why keyof or indexed access derives those different types, follow their [object-query owner](<../../../04 Objects Interfaces and Type Aliases/sections/2. Composition and Declaration Merging/2.3. Type queries on objects keyof indexed access and typeof capture.md>). Do not explain GET as though it were a property key merely because its value is a string.

If a new enum member makes a never sink fail, use [enum coverage](<../3. Literals and Nominal Patterns/3.2. Exhaustive switches over enums and unions.md>) for the member extension and parser test. If the learner is unsure how return, break or narrowing affects the remaining type, use the general control-flow owner in the table. Updating the enum switch does not automatically admit the new code in a parser.

If default tsc output runs but native Node 22.18 source execution rejects an enum, first identify the execution mode. The [migration lesson](<../2. Enums vs Erasable Alternatives/2.2. erasableSyntaxOnly the enum ban and migration.md>) then compares before, bridge and final contracts. A failure involving an ambient const enum and a missing runtime export instead belongs to the [actual const-enum publication fixture](<../2. Enums vs Erasable Alternatives/2.1. const enum inlining and isolatedModules danger.md>). Do not infer a universal esbuild/Babel limitation from a different strip-only runtime's error.

These routes preserve a useful distinction: the runner/configuration owner explains supported source processing; this domain explains what its enum choices mean for those consumers. A syntax flag is not a provider, an import resolver or a performance benchmark.

### 3) **Keep review evidence with the changed contract**

For an enum edit, review serialized values, aliases, generated mappings, checked callers and the actual publishing/execution path. For a literal-preservation edit, review the inferred argument and return types without assuming the runtime value is frozen. For a handler-table edit, review required keys separately from callback behavior. The [integrated review](<../4. Important points to remember/4.1. Enums checklist mental models mentors insist on.md>) combines these obligations in one small program.

Practice routing an unfamiliar report: a developer adds a status, fixes the handler's diagnostic and still receives invalid for that status. Start with the enum/parser exercise here, not by changing all compiler flags or reteaching switch syntax. Then ask which parser branch was actually updated and which runtime input was tested. A sound explanation identifies the independent stale parser and can demonstrate the repaired result.

The configuration and module domains are already published. Follow precise routes as prerequisites arise; their position later in the curriculum does not make every leaf a prerequisite to understanding an enum. Conversely, a local working example does not certify every package export map, compiler project or downstream transform. State the boundary the evidence actually covers.

### 4) **Common confusion**

The domain that uses a concept does not automatically own its full explanation. An enum switch applies control-flow narrowing, an enum-keyed Record applies mapped-property coverage, and a const-object migration applies literal inference. Keep enough local context for comprehension, then use the canonical owner for the mechanism.

Shared mechanism also does not mean identical representation. Enum-member admission, raw literal admission, numeric reverse entries and ordinary object reflection can differ even when two functions print the same string. Migration needs the selected contract's tests, not only a routing link.

### 5) **Performance note**

This boundary map changes documentation navigation, not runtime behavior. It establishes no startup saving, checker cache formula or lookup-cost claim. Runtime tables, functions and throws remain when their implementations remain; a type-only derivation erases. Use each detailed owner's actual evidence for the program being assessed rather than adding claimed savings across documentation layers.

### 6) **Mentor note**

Give the learner a failure report and ask for two things: the canonical mechanism owner and the enum-specific contract that still needs review. A strong answer can route a widening question to inference while keeping migration admission changes here, or route a resolution failure to modules while keeping ambient constant publication here. Their explanation should narrow the investigation, not require reading every linked domain before acting.
