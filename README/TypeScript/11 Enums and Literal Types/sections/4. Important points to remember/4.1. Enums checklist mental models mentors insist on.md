## 4.1. Enums checklist mental models mentors insist on

Review finite-value designs by the guarantees each part supplies. A stable serialized number, a complete callback table, a literal-preserving helper and a parser answer different questions. A successful build can prove some relationships while leaving a stale parser or semantically wrong callback untouched.

Use this worked review after the enum mechanics and literal-pattern lessons. It combines their contracts without treating enum count, a mandatory comment stamp or a particular syntax spelling as the quality measure.

### 1) **Run a small finite-action boundary**

Use TypeScript 7.0.2 and Node.js 20.20.2, verified 2026-10-16. Save review.ts in a fresh directory without tsconfig.json. Build with `tsc --strict --noUncheckedIndexedAccess --removeComments --target es2022 --module commonjs --outDir out review.ts`, then run `node out/review.js`. For an intentional negative, activate one comment in a separate copy and replace --outDir out with --noEmit. This fixture deliberately uses a transformed regular enum; adding --erasableSyntaxOnly rejects it with TS1294.

```typescript
export {};
enum WireStatus { Queued = 10, Sent = 20 }
function define<const T extends readonly string[]>(values: T): T { return values; }
const actions = define(["send", "reset"]);
type Action = (typeof actions)[number];
const handlers: Record<Action, (current: WireStatus) => WireStatus> = {
  send: () => WireStatus.Sent,
  reset: () => WireStatus.Queued
};
function parseStatus(value: unknown): WireStatus | undefined {
  return value === WireStatus.Queued ? WireStatus.Queued :
    value === WireStatus.Sent ? WireStatus.Sent : undefined;
}
function unexpected(value: never): never { throw new Error(`unhandled ${String(value)}`); }
function describe(status: WireStatus): string {
  switch (status) {
    case WireStatus.Queued: return "queued";
    case WireStatus.Sent: return "sent";
    default: return unexpected(status);
  }
}
function apply(action: Action, rawStatus: unknown): string {
  const current = parseStatus(rawStatus);
  return current === undefined ? "invalid" : describe(handlers[action](current));
}
const tasks: readonly { action: Action; rawStatus: unknown }[] = [
  { action: "send", rawStatus: 10 },
  { action: "reset", rawStatus: 20 },
  { action: "send", rawStatus: 99 },
  { action: "send", rawStatus: "10" }
];
for (const task of tasks) console.log(task.action, JSON.stringify(task.rawStatus), apply(task.action, task.rawStatus));
console.log(WireStatus.Sent, WireStatus[WireStatus.Sent], Object.isFrozen(actions));
// apply("pause", 10); // TS2345
// actions.push("pause"); // TS2339
// function missing(action: string) { return handlers[action]; } // TS7053
```

The output is `send 10 sent`, `reset 20 queued`, `send 99 invalid`, `send "10" invalid` and `20 Sent false`. Apply's action is a checked local contract; its rawStatus is explicitly parsed. This is a local dispatch simulation, not a network request handler: an unknown external action would need its own admission check too. The const parameter infers a readonly literal tuple for this inline argument, but the runtime array is unfrozen. The enum object and all parsing/dispatch work remain in JavaScript.

### 2) **Ask for evidence at the relevant boundary**

| Review question | Evidence in this program | Limit to keep visible |
|---|---|---|
| Are serialized codes intentional? | Queued=10 and Sent=20 are explicit | Changing an initializer still changes the contract; the compiler does not know stored history |
| Does every declared action have a callback? | Record<Action, ...> requires both keys | A callback can return the wrong status while retaining the same type |
| Where do action literals come from? | The inline tuple determines Action | A prebound string[] would lose the finite set; const inference cannot recover it |
| Does external status data meet the contract? | Actual comparisons reject 99 and the string 10 | The parser can remain incomplete after a new enum member is added |
| Must every status have a label? | Describe has a never sink | It covers the declared input, not arbitrary unchecked runtime values or correct label text |
| Does the execution pipeline support the syntax? | This program is transformed by tsc and its JavaScript is executed | Native strip-only execution needs an explicit enum migration or a supported transform |

A plain union is often enough for finite string arguments. Named const objects can add runtime values or defaults. Enum member APIs or generated numeric mappings can justify an enum in a supporting toolchain. Enums also support direct Exclude and template composition; these are not union-only capabilities. Use the [decision lesson](<../2. Enums vs Erasable Alternatives/2.3. Literal unions as enums the decision rule.md>) for that comparison rather than counting extraction lines or requiring a declaration comment as proof.

For stored or foreign codes, review the actual before/after values, aliases, reverse entries and consumers. Explicit values protect against positional renumbering but cannot prevent a deliberate or accidental value edit. [Numeric mechanics](<../1. Enum Mechanics/1.1. Numeric enums auto values and reverse mapping.md>) owns that experiment. A [migration](<../2. Enums vs Erasable Alternatives/2.2. erasableSyntaxOnly the enum ban and migration.md>) may preserve serialized values while changing accepted callers or Object.keys; test the specific compatibility claim.

### 3) **Separate coverage failures from behavior failures**

First extend only the actions argument to include pause. Record now reports TS2741 because pause has no callback. Adding `pause: current => current` restores coverage and defines a useful local policy: `apply("pause", 20)` returns sent. If pause instead means a new persisted state, returning current would be type-correct but semantically wrong. The product contract must decide which behavior is intended.

Next, in a separate copy of the original fixture, add Paused = 30 to WireStatus. Describe fails with TS2345 until you add its paused case. The build then succeeds, yet `apply("send", 30)` still returns invalid because parseStatus has not changed. Extend the parser with the Paused comparison; send then produces sent from 30, and pause in the combined extension preserves paused. Unknown 99 and the string 10 must remain invalid.

An explained combined solution adds the pause callback returning current, the Paused enum member, a describe case returning paused and the explicit Paused parser branch. Verify `apply("pause", 30)` is paused, `apply("send", 30)` is sent and `apply("pause", 99)` is invalid. Then replace send with a callback returning Queued. It still builds, but the original first result changes from sent to queued. The static coverage check did not prove what send means.

Choose a deliberate policy for ignored inputs or unexpected runtime values. A throwing never helper is useful when adding a declared alternative should force a behavior review, but the helper remains executable JavaScript. Do not claim it removes all runtime default paths or makes every permissive fallback a defect. Full [coverage and numeric-boundary reasoning](<../3. Literals and Nominal Patterns/3.2. Exhaustive switches over enums and unions.md>) owns that distinction.

### 4) **Common confusion**

The table, parser and switch are independent. Updating one does not automatically update the others. A finite Record checks required callback keys; a never sink checks the remaining declared alternatives; neither validates arbitrary unknown data or establishes the meaning of a returned status.

Precision is useful where consumers need it, but it need not survive every function. A formatter may intentionally return string. Ordinary generics already preserve many primitive literals, and const parameters do not freeze arrays or reverse preexisting widening. Use the actual [inference lesson](<../3. Literals and Nominal Patterns/3.1. const type parameters and literal preservation.md>) to inspect the relationship instead of adding const everywhere.

### 5) **Performance note**

Literal aliases, Record and generic annotations erase. The enum table, runtime action array, callbacks, comparisons, switch and throw remain. No timing, byte ratio, per-member checker complexity or incident reduction was measured. The design review here establishes bounded behavior and compatibility evidence; performance work needs the actual workload and artifact.

### 6) **Mentor note**

Ask the learner to add an action and then a status, predicting which check fails in each case. Require them to find a change that builds but violates an expected output. A strong review names both the proof supplied by the compiler and the separate runtime check needed for the intended behavior.
