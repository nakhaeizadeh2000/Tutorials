## 4.1. Enums checklist — mental models mentors insist on

### 1) **Unions by default, enums by recorded reason** (erasure + composition beat emit)

**Definition** — new finite sets start as literal unions (`type S = "a" | "b"` — erasable, composable, exhaustible, zero emit); `enum` requires a comment naming its survivor reason (bit flags, foreign-ambient, non-erasable codebase + date). The default serves the 90%; recorded reasons protect the 10% — judgment moves from every declaration to the exceptional ones.

**What problem it solves / history** — enum-by-default codebases accumulated toolchain lock-in (const-enum pipeline questions), composition preambles (member extraction before every `Exclude`/template), and reverse-map widening — each a recurring tax paid per use. Union-by-default (see [2.3. Decision rule](<../2. Enums vs Erasable Alternatives/2.3. Literal unions as enums the decision rule.md>)) inverts the taxes; the stamp (see 2.3 promise 3) enforces the default where documentation couldn't.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), write unions first; reach for enums with a recorded reason; migrate unrecorded enums opportunistically (per [2.2. Migration](<../2. Enums vs Erasable Alternatives/2.2. erasableSyntaxOnly the enum ban and migration.md>)'s alias-move-delete). Track enum count per quarter — falling or holding, never rising unexplained.

**Runnable example** — default composes, survivor records (good vs bad, `tsc --strict`):

```typescript
// good — union default: filtered, templated, exhausted with zero emit
type St = "idle" | "done";
type LiveSt = Exclude<St, "done">; // "idle" — direct composition, no preamble
const ls: LiveSt = "idle";
console.log(ls.toUpperCase()); // IDLE

// good — survivor recorded: bit flags need combinability (comment earns the enum)
// Why enum: members combine with | (numeric bit math, no union equivalent)
enum Flag { None = 0, A = 1 << 0, B = 1 << 1 }
console.log((Flag.A | Flag.B).toFixed(0)); // 3 — combinability documented

// bad — unrecorded enum surviving on habit (migrates losslessly)
// enum Mode { On = "ON", Off = "OFF" } // why not a union? (silence = migrate)
// fix — type ModeU = "ON" | "OFF": values identical, composition gained
type ModeU = "ON" | "OFF";
const mu: ModeU = "ON";
console.log(mu.toLowerCase()); // on
```

**Common confusion** — "defaults stifle the 10%" — recorded reasons *protect* survivors explicitly (stronger than grandfathering — auditable, dated, re-testable). "unions can't do what my enum does" — values (→ const objects), iteration (→ `Object.values` on const tables), flags/foreign (→ recorded survivors) — each need has a named home; "my enum" fits one of them or migrates.

**Performance note** — unions zero-emit; recorded survivors pay documented table costs knowingly — the checklist makes costs auditable per declaration instead of ambient.

**Mentor note** — audit one enum file with the class (default-migrate each, defend survivors) — the standing survivors teach the rule's boundaries. Metric: enum declarations per quarter, falling or holding.

### 2) **Numeric enums carry two behaviors** (auto-values that renumber + reverse maps that widen)

**Definition** — every numeric enum ships two footguns with its ergonomics: positional auto-values (insertion renumbers followers — persisted data reinterprets) and reverse maps (lookups widen to `string` — control flow built on them proves nothing). Know both before choosing: explicit anchors for anything stored, members (never reverse strings) for logic.

**What problem it solves / history** — renumbering incidents (5.1 promise 1: persisted statuses reinterpreted) and widening incidents (5.1 promise 3: reverse-mapped validation skipped) share one root: numeric-enum behaviors treated as free conveniences instead of priced features. The checklist prices them upfront — anchors cost one `= N` per member; member-switching costs nothing beyond the habit.

**Modern guidance** — as of TypeScript 5.9 era, anchor persisted numeric members explicitly (append-only, never reorder); switch on members with `never` sinks; relegate reverse maps to display formatting. See [1.1. Numeric enums](<../1. Enum Mechanics/1.1. Numeric enums auto values and reverse mapping.md>) + [3.2. Exhaustive switches](<../3. Literals and Nominal Patterns/3.2. Exhaustive switches over enums and unions.md>).

**Runnable example** — anchored storage, member logic (good vs bad, `tsc --strict`):

```typescript
// good — explicit anchors (storage-stable) + member switch (sink-protected)
enum Ord { New = 1, Paid = 2, Shipped = 3 } // anchored: insertion can't renumber
function labelO(o: Ord): string {
  switch (o) {
    case Ord.New: return "new";
    case Ord.Paid: return "paid";
    case Ord.Shipped: return "shipped";
    default: { const n: never = o; throw new Error(`unhandled ${String(n)}`); }
  }
}
console.log(labelO(Ord.Paid), Ord.Shipped); // paid 3 — stable codes, exhaustive logic

// bad — auto-values stored + reverse strings switched (both behaviors biting at once)
enum OrdB { New, Paid, Shipped } // 0,1,2 — position-coupled storage...
function labelBad(code: number): string {
  return OrdB[code] ?? "?"; // ...plus widened display as logic (string, unexhaustive)
}
// fix — anchors + member switch: each behavior priced and paid deliberately
console.log(labelBad(9)); // ? — unknown code, unhandled silently
```

**Common confusion** — "anchors are verbose" — one `= N` per member vs one renumbering incident (data reinterpretation across history) — verbosity is the cheapest insurance in protocol-adjacent code. "reverse maps are harmless for display" — harmless *for display*; the trap is display-strings leaking into logic — keep the boundary (render at leaves, switch on members).

**Performance note** — anchors/reverse tables cost the standard numeric-enum emit (forward + reverse slots) — unchanged by discipline; incidents cost data migrations — anchors are performance-neutral, incident-negative.

**Mentor note** — insert a member into an unanchored persisted enum live and ask "what changed in storage?" (meaning, not schema) — position-coupled persistence in one edit. Pair with the reverse-map hover (`string` vs member literal) — two behaviors, two demos, one checklist item.

### 3) **`const` contexts preserve literals** (sources, params, joints — precision everywhere)

**Definition** — three `const` contexts keep literals alive through pipelines: `as const` sources (narrow tables/unions at declaration), `<const T>` params (declaration-side inference without call-site ceremony), and narrow returns/joints (`` `route:${M}` ``, `M` itself — never `string` mid-pipeline). Precision entered once (source) propagates through every joint that refuses to widen.

**What problem it solves / history** — widen-then-recover cycles (`as const` patches at random pipeline points, explicit `<"get">` rescues per call, re-narrowing after `Record<string>` carriers) scattered precision fixes where one source decision plus narrow joints would have sufficed. The `const`-contexts rule concentrates the discipline: narrow the source, preserve at joints — recoveries become unnecessary rather than frequent.

**Modern guidance** — as of TypeScript 5.9 era, narrow sources (`as const` + `satisfies`), preserve with `<const T>` helpers and `M`-returning joints, verify with literal hover-probes per joint. See [3.1. const type parameters](<../3. Literals and Nominal Patterns/3.1. const type parameters and literal preservation.md>) + [3.3. Literal preservation](<../../../09 Utility Types and Type Transformations/sections/3. Transformations in Practice/3.3. satisfies and as const preserving literals through transforms.md>) (in 09).

**Runnable example** — source narrow, joints narrow, switches exhaustive (good vs bad, `tsc --strict`):

```typescript
// good — const source + const param + literal joint: precision end to end
const TBL = ["get", "post"] as const;
function mk<const M extends string>(m: M): `op:${M}` { return `op:${m}`; }
const k = mk(TBL[0]); // "op:get" — narrow source, narrow joint, literal result
function run(m: "op:get" | "op:post"): number { return m === "op:get" ? 1 : 2; }
console.log(run(k)); // 1 — exhaustiveness consumable downstream

// bad — wide source: no joint can recover what was never there
const WIDE: string[] = ["get", "post"];
// const k2 = mk(WIDE[0]); // error without undefined check; even narrowed, WIDE[0] is string...
// fix — narrow the SOURCE (TBL); joints preserve, never invent
console.log(WIDE.length); // 2 — values fine, types already widened
```

**Common confusion** — "one const context suffices" — source-narrow with wide joints collapses mid-pipeline (`Record<string>` carriers); narrow joints with wide sources invent nothing — all three contexts compose, none substitutes. "hover-probes are busywork" — one probe per joint finds collapses in seconds; unprobed pipelines collapse silently for quarters.

**Performance note** — narrow unions check per member (fast for curated sets); collapsed `string` checks trivially but proves nothing — precision costs linear member checks and buys incident prevention at every switch.

**Mentor note** — trace one literal (`"get"` → `` `op:get` `` → exhaustive case) through source→joint→switch live — the unbroken chain is the precision story in three hovers. Exercise: widen one joint deliberately and count downstream exhaustiveness deaths (each a future unauthenticated-handler class incident).

### 4) **Exhaust every finite set with `never`** (enum or union — the sink proves coverage)

**Definition** — every behavior-driving switch over a finite set (enum members, literal unions, discriminated variants) ends `default: assertNever(x)` — the sink proves coverage today and breaks the build on the next added member. Form-independent (enum/union/discriminant all sink identically — see [3.2. Exhaustive switches](<../3. Literals and Nominal Patterns/3.2. Exhaustive switches over enums and unions.md>) promise 3's parity), cost-free (one line, zero runtime), permanent (protects every future addition).

**What problem it solves / history** — `default: break` switches absorbed new members silently across every finite-set form (enum additions unhandled, union additions falling into `else`, discriminant additions returning stale state — 5.1-adjacent incidents in 07/5.1 and here). The sink converts member-addition from silent gap to compile error enumerating every unhandled site — the compiler writes the migration checklist.

**Modern guidance** — as of TypeScript 5.9 era, sink behavior switches, allow bare defaults only for genuinely open inputs (user strings, foreign numbers — unexhaustible by definition). Share one `assertNever` per project (consistent messages/traces); review unsunk finite switches as defects regardless of current member count.

**Runnable example** — sink proves, break absorbs (good vs bad, `tsc --strict`):

```typescript
// good — shared sink: coverage proven, additions break loudly
function assertNever(x: never): never { throw new Error(`unreachable ${String(x)}`); }
type Op2 = "add" | "sub";
function calc(o: Op2, a: number, b: number): number {
  switch (o) {
    case "add": return a + b;
    case "sub": return a - b;
    default: return assertNever(o); // never — "mul" added later errors HERE
  }
}
console.log(calc("add", 2, 3)); // 5

// bad — else-assumption absorbs new members into stale behavior
function calcBad(o: Op2, a: number, b: number): number {
  if (o === "add") return a + b;
  return a - b; // "sub" assumed by else — "mul" later maps to subtraction silently
}
// fix — sinked switch: discipline (sink), not form, provides the safety
console.log(calcBad("sub", 5, 8)); // -3 — correct today, silent tomorrow
```

**Common confusion** — "two-member sets don't need sinks" — two becomes three eventually (every growing enum/union proves it) — sink cost is one line regardless of size. "sinks replace tests" — sinks prove *coverage* (every member handled *somewhere*); tests prove *correctness* (handled *right*) — complementary, both required. "shared helpers hide intent" — shared `assertNever` standardizes diagnostics; inline equivalents fragment messages — convention over repetition.

**Performance note** — zero runtime cost when covered (unreachable throw, never constructed); compile error when not — cheapest permanent protection in typed codebases by every measure.

**Mentor note** — add a member to each switch live (sunk errors listing the site, unsunk stays green) — coverage-proof vs coverage-theater in one edit. Make unsunk finite switches review defects unconditionally — no member-count exceptions, no "too small to sink" waivers.
