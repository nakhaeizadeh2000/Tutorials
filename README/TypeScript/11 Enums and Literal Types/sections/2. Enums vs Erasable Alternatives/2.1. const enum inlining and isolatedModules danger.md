## 2.1. `const enum` — inlining and `isolatedModules` danger

### 1) **Compile-time inlining** (literals substituted at use sites, zero object)

**Definition** — `const enum E { A, B }` emits *no object*: every `E.A` use compiles to the literal `0` inline. Reads are literal loads (fastest possible), bundle size drops by the whole table, and reverse mapping disappears (nothing exists at runtime to look up). The trade: the value must be knowable per-file at compile time — cross-file knowledge requires whole-program compilation.

**What problem it solves / history** — numeric-enum tables (`var E; (function(E){ E[E["A"] = 0] = "A"; … })(E || {})`) shipped lookup objects for enums used as pure constants (status codes compared, never enumerated) — bytes and indirection for a table nobody read. `const enum` (TS 1.x) deleted the table: constants compile to literals, comparisons to literal checks — enum ergonomics at `#define` cost.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), inline self-contained numeric tables consumed within one compilation unit (solver constants, internal opcodes, same-file state machines). Never export `const enum` from shared libraries (consumers on other pipelines cannot inline — next promise). Never rely on runtime enumeration (`Object.values` over a `const enum` is empty — nothing emitted).

**Runnable example** — table deleted, literals inline (good vs bad, `tsc --strict`):

```typescript
// good — self-contained constants: inlined literals, zero table
const enum Op { Add, Sub }
function apply(op: Op, a: number, b: number): number { return op === Op.Add ? a + b : a - b; }
console.log(apply(Op.Add, 2, 3)); // 5 — Op.Add compiled to 0 inline (verify with tsc --emit)
// Object.values(Op); // error TS2475 — const enum used as value (nothing emitted to enumerate)

// bad — const enum for a table consumers must enumerate
const enum Status { Idle, Done }
// function listAll(): string[] { return Object.values(Status).map(String); } // error TS2475 — no runtime table
// fix — plain enum (or union + as const object) where runtime enumeration is needed
enum StatusPlain { Idle, Done }
console.log(Object.values(StatusPlain).filter((v) => typeof v === "string").join(",")); // Idle,Done
```

**Common confusion** — "`const enum` is just a faster enum" — different semantics (no object, no reverse map, no iteration) — inlining *removes* runtime identity; members become interchangeable literals. "inlined literals bloat bundles" — literals are smaller than table + lookups past a handful of uses; the table pays object overhead once — measure past hundreds of members, prefer `const enum` below. "isolatedModules bans const enums" — *errors* on cross-file const-enum *consumption* by default (next promise) — same-file inlining still compiles everywhere.

**Performance note** — literal loads beat property reads marginally; bundle savings equal the deleted table (halved numeric emit) — meaningful for numeric-heavy embedded/library code, noise for app code. The performance argument is secondary to the *pipeline* argument (next promise) — choose by consumer, not by nanoseconds.

**Mentor note** — emit-compare `enum` vs `const enum` once (`tsc` both, diff the `.js`) — table vs literals in one diff ends abstract debate. Exercise: find one exported `const enum` in a shared package and trace its consumers' pipelines (tsc? esbuild? Babel?) — the incompatible ones are the incident queue.

### 2) **`isolatedModules` breakage** (single-file transpilers cannot inline across files)

**Definition** — `isolatedModules: true` (required by esbuild, swc, Babel, and Next.js/Vite pipelines) compiles each file *independently*: a `const enum` *imported* from another file cannot be inlined (its values live in a file the transpiler never sees) — so TypeScript errors at the import (`TS2748: Cannot access ambient const enums when isolatedModules is enabled`, and cross-file const-enum use generally). Whole-program `tsc` inlines fine; per-file transpilers cannot by architecture.

**What problem it solves / history** — libraries exporting `const enum` compiled under `tsc` and crashed under esbuild (`Direction is not defined` — the import emitted as a value reference to a table that was never emitted) — consumer-pipeline-dependent breakage invisible to library CI. The `isolatedModules` error converts it to a *library-authoring* error: exporting `const enum` from transpiled packages fails fast instead of crashing consumers.

**Modern guidance** — as of TypeScript 5.9 era, never export `const enum` from packages consumed through per-file transpilers (libraries, monorepo shared packages, anything esbuild/swc/Babel touches); use plain enums (small emit cost, universal) or unions + `as const` objects (zero emit, erasable — see [2.2. Migration](<../2. Enums vs Erasable Alternatives/2.2. erasableSyntaxOnly the enum ban and migration.md>)). Keep `const enum` for same-compilation-unit internals where `tsc` owns the whole program.

**Runnable example** — library boundary decides (good vs bad, `tsc --strict`):

```typescript
// good — shared package exports erasable-safe values: union + const object (inlines by hand, no enum)
export const KIND_MAP = { circle: "C", square: "S" } as const;
export type Kind = keyof typeof KIND_MAP; // "circle" | "square" — no enum, no inlining needed
console.log(KIND_MAP.circle); // C — works under tsc, esbuild, Babel alike

// bad — exported const enum: tsc consumers fine, esbuild consumers crash
// export const enum Shared { A, B } // library code (compiles under tsc)...
// import { Shared } from "./lib"; console.log(Shared.A); // esbuild: ReferenceError (no table emitted, nothing to inline from)
// fix — KIND_MAP pattern above, or plain enum (emitted table, universal access)
export enum SharedPlain { A, B }
console.log(SharedPlain.A.toFixed(0)); // 0 — works on every pipeline
```

**Common confusion** — "isolatedModules bans all const enums" — bans *cross-file* const-enum value use (inlining needs the defining file); same-file `const enum` compiles under every pipeline. "type-only imports fix it" — `import type` erases the import (no value to inline *or* crash on) — correct for type positions, useless for value uses (`Shared.A` needs the value). "esbuild is broken for not supporting it" — per-file transpilation *cannot* support cross-file inlining by design (no whole-program knowledge) — the constraint is architectural, shared by swc/Babel/Vite.

**Performance note** — plain-enum tables cost one object per enum (bytes) versus `const enum`'s zero — the library tax for pipeline universality, measured in tens of bytes. Union + const-object costs zero bytes *and* universal access — strictly dominant where nominal member types aren't needed.

**Mentor note** — build one shared `const enum` consumed via esbuild and watch it crash — pipeline-dependent breakage demonstrated beats documented. Rule: `export const enum` in library code fails review unconditionally; same-file `const enum` needs a comment naming its compilation unit.

### 3) **When inlining pays vs burns** (same-unit tables vs shared libraries)

**Definition** — inline when three conditions hold: numeric members (inlining substitutes literals — string members gain little), same compilation unit (definer and users compile under one `tsc` program), and no runtime enumeration (nobody `Object.values` the enum). Burn everywhere else: shared packages, transpiled pipelines, enumerated tables, erasable-syntax codebases — each a documented incident class in 5.1 promise 2.

**What problem it solves / history** — blanket `const enum` adoption ("faster, smaller — always") inlined shared-library enums that crashed esbuild consumers, and blanket bans ("never const enum") left same-unit tables paying object overhead for nothing. The three-condition test routes each enum in thirty seconds: same-unit numeric non-enumerated → inline; anything else → plain enum or union.

**Modern guidance** — as of TypeScript 5.9 era, default new numeric tables to plain `enum` (safe everywhere) and promote to `const enum` only when same-unit + numeric + non-enumerated all hold *and* a comment records the reasoning. Demote on any condition change (package published, pipeline switched, enumeration added) — direction changes are cheap, incidents are not.

**Runnable example** — test routes each enum (good vs bad, `tsc --strict`):

```typescript
// good — same-unit opcode table: numeric, local, never enumerated → inline
const enum Opcode { Nop, Push, Add } // internal to this compilation unit
function run(op: Opcode): string { return op === Opcode.Nop ? "nop" : "work"; }
console.log(run(Opcode.Push)); // work — literals inline, zero table

// bad — shared + enumerated const enum (fails two conditions at once)
// export const enum Pub { A, B } // shared (burns esbuild) + enumerated below (burns everywhere)
// export function listPub(): string[] { return Object.values(Pub).map(String); } // error TS2475
// fix — plain enum (or union): shared tables need runtime identity
export enum PubPlain { A, B }
console.log(Object.values(PubPlain).length); // 4 — forward + reverse entries (numeric table)
```

**Common confusion** — "plain enums are always safer, so const enums are pointless" — same-unit numeric tables gain real bundle savings with zero risk (conditions hold) — pointless only where conditions fail. "conditions never change" — publishing an internal package, switching to esbuild, adding `Object.values` debugging — each flips one condition silently; re-test on change, not just on creation. "unions always beat const enums" — numeric bit flags and reverse-lookup debugging keep legitimate enum territory (see [2.3. Decision rule](<../2. Enums vs Erasable Alternatives/2.3. Literal unions as enums the decision rule.md>)).

**Performance note** — same-unit inlining saves the table object (tens of bytes × enums) plus per-access indirection — real for opcode/flag-dense internals, noise elsewhere. Decision driver remains *correctness across pipelines*, with bytes as a tiebreaker.

**Mentor note** — the three-condition checklist ("numeric? same unit? enumerated nowhere?") fits a review stamp — three yeses inline, any no stays plain. Exercise: audit the repo's `const enum`s against the three conditions — failures are pre-filed incidents; fix by demotion before they ship.
