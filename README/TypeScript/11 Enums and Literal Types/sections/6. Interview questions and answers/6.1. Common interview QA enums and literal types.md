## 6.1. Common interview QA enums and literal types

A useful answer predicts checking and runtime behavior, states its toolchain assumptions and explains which contract is being chosen. Memorized claims such as all const enums disappear, only unions compose or every matching enum string is a reverse lookup fail on small counterexamples.

Use TypeScript 7.0.2 and Node.js 20.20.2, verified 2026-10-16. Save each named program independently in a fresh directory without tsconfig.json. Build with `tsc --strict --noUncheckedIndexedAccess --removeComments --target es2022 --module commonjs --outDir out FILE.ts`, then run `node out/FILE.js`. For a marked rejection, activate one comment in a separate copy and replace --outDir out with --noEmit.

### 1) **Predict enum keys before discussing types**

How many keys exist after aliases collide, and does a string key/value coincidence imply reverse mapping? Save keys.ts:

```typescript
export {};
enum Numeric { First = 10, Alias = 10 }
enum TextCode { Ready = "ready" }
enum Mirror { Ready = "Ready" }
const enum Local { One = 1 }
const names: Record<keyof typeof Numeric, string> = { First: "first", Alias: "alias" };
console.log(Numeric[10], Object.keys(Numeric).join(","), Object.keys(Numeric).length);
console.log(TextCode.Ready, Object.hasOwn(TextCode, "ready"), Mirror["Ready"]);
console.log(names.First, names.Alias, Local.One);
// TextCode["ready"]; // TS2551
// console.log(Object.values(Local)); // TS2475
```

The output is `Alias 10,First,Alias 3`, `ready false Ready` and `first alias 1`. A numeric reverse slot is overwritten by the last alias with that value, so two numeric members do not always yield four distinct keys. Mirror's successful string indexing reads an existing forward key named Ready. It proves no generated value-to-name mapping. The [numeric](<../1. Enum Mechanics/1.1. Numeric enums auto values and reverse mapping.md>) and [string](<../1. Enum Mechanics/1.2. String enums intent and no reverse mapping.md>) owners explain the output and checker contracts.

Inspect the emitted Local declaration and read. Default tsc emit in this fixture removes the const enum and substitutes 1. Rebuild into another output directory with --preserveConstEnums: the object remains while the read is still substituted. Rebuild with --isolatedModules: a runtime object and Local.One read remain. All three modes print the same lines. Object.values(Local) remains illegal TypeScript even with preservation. A strong answer names the mode instead of equating const enum with one universal output shape.

Practice: add Third = 20 to Numeric. The names Record now needs a Third entry; supply third as its label. The first line becomes `Alias 10,20,First,Alias,Third 5`, while the previous reverse alias remains Alias. This distinguishes compile-time named keys from runtime reverse entries.

### 2) **State the exact erasable boundary and derived value contract**

Why does a runtime enum fail the gate while an ambient description can pass? Which type is a member name and which is a serialized value? Save gate.ts:

```typescript
export {};
const Method = { Read: "GET", Write: "POST" } as const;
type MethodName = keyof typeof Method;
type MethodValue = (typeof Method)[MethodName];
declare enum Foreign { Ready = 1 }
namespace Types { export type Packet = { method: MethodValue }; }
const key: MethodName = "Read";
const packet: Types.Packet = { method: "GET" };
console.log(key, Method[key], packet.method, typeof Foreign === "undefined");
// const wrongName: MethodName = "GET"; // TS2322
// enum RuntimeKind { Ready = 1 } // TS1294 with --erasableSyntaxOnly
// const enum RuntimeFast { Ready = 1 } // TS1294 with --erasableSyntaxOnly
```

The output is `Read GET GET true`. This file passes --erasableSyntaxOnly. Its ambient enum and type-only namespace erase, while Method remains an ordinary object. The flag also restricts runtime namespaces, parameter properties and other non-erasable forms; it is not an all-namespace or all-ambient-declaration ban. The [option reference](https://www.typescriptlang.org/tsconfig/erasableSyntaxOnly.html) states the inventory.

The replacement is not automatically equivalent to an enum API: raw GET is accepted here, and keys Read/Write differ from the values GET/POST. An ambient Foreign read would still need an actual provider. The [migration owner](<../2. Enums vs Erasable Alternatives/2.2. erasableSyntaxOnly the enum ban and migration.md>) runs separate before, bridge and final programs and compares native Node 22.18 source stripping with emitted JavaScript. A syntax check alone does not establish resolution or runtime API support.

### 3) **Diagnose const-enum publication from actual supplied artifacts**

Does isolatedModules reject every cross-file const enum? No: ordinary source-defined exported const enums pass in the tested tsc mode, and esbuild/Babel have supported transforms. Ambient const-enum value references are the important isolated restriction, reported as TS2748. A separately transformed consumer may also require a runtime object that an ambient declaration never supplied, or a whole-program build may inline constants that disagree with the runtime package version.

A strong answer first requests the declaration, implementation, consumer import and actual transformation command. Then it distinguishes the [executed source and ambient fixtures](<../2. Enums vs Erasable Alternatives/2.1. const enum inlining and isolatedModules danger.md>). Those examples establish specific esbuild 0.28.2 and Babel 8 results; they do not certify every framework configuration. Native strip-only execution has a different syntax boundary. Import type cannot supply a runtime enum value, and changing a declaration alone cannot create its provider.

### 4) **Choose a status representation from its consumers**

A literal union is often a useful starting point for finite plain string inputs. A const object can supply names, defaults and iteration without enum transformation. An enum's member API, existing consumers or convenient numeric mappings can justify its use in a supporting pipeline. Numeric bit operations do not require an enum; a named numeric const object can perform them too.

Both enum members and literal unions support finite coverage checks and type composition. For example, Exclude<State, State.Done> can filter a string enum directly, and a template can interpolate its values. The [decision owner](<../2. Enums vs Erasable Alternatives/2.3. Literal unions as enums the decision rule.md>) executes that comparison and demonstrates raw-literal versus enum-member admission. Do not substitute an enum-count metric, a mandatory comment date or an unsupported editor-discoverability claim for the API decision. A migration must preserve the intended serialized and runtime contracts or deliberately change them.

### 5) **Find where literal information is actually lost**

Does const change ordinary identity of a string literal, and can it override a broad result annotation? Save inference.ts:

```typescript
export {};
function ordinary<T>(value: T): T { return value; }
function precise<const T>(value: T): T { return value; }
const word: "get" = ordinary("get");
const wide = ordinary({ method: "get" });
const exact = precise({ method: "get" });
const prebound = { method: "get" };
const stillWide = precise(prebound);
function format<const T extends string>(method: T): string { return `route:${method}`; }
const output = format("get" as const);
console.log(word, wide.method, exact.method, stillWide.method, output);
console.log(Object.is(stillWide, prebound), Object.isFrozen(exact));
// const lost: "get" = wide.method; // TS2322
// const notRecovered: "get" = stillWide.method; // TS2322
// const notRescued: "route:get" = output; // TS2322
// exact.method = "get"; // TS2540
```

The output is `get get get get route:get`, then `true false`. Ordinary identity already preserves the primitive get literal. The fresh ordinary object has a string property; const inference preserves the inline object's readonly get property. Prebound already has a widened property type, and the result aliases it. Format explicitly returns string, so its caller's const assertion does not narrow the result to route:get.

A strong answer checks the actual inference position, constraint, preexisting type and published return. Mutable versus readonly array constraints also affect tuple mutability on this baseline; the historical TS 5.0 fallback is not the current result for the tested mutable constraint. The [const-parameter owner](<../3. Literals and Nominal Patterns/3.1. const type parameters and literal preservation.md>) compares actual 5.0.4, 5.3.3 and 7.0.2 declarations and explains that version boundary. A precise literal is already assignable to string; a non-generic string formatter can be the right API when no input/output relationship is needed.

### 6) **Common confusion**

Checking, transformation and execution provide different evidence. Keys.ts needs a transform; gate.ts passes the syntax gate but does not install Foreign; inference.ts retains its functions and objects despite erasing types. Equal output does not imply identical inferred types, and matching strings do not imply identical enum-member admission.

A good interview explanation remains conditional: it names the version/mode and the relevant API contract, then supports its prediction with a diagnostic, emitted shape or actual execution. Avoid accepting confident universals that fail the counterexamples above.

### 7) **Performance note**

No runtime or checker benchmark is established by these questions. Alias collisions change table shape; const-enum modes change emitted data and reads; const inference changes checker relationships while actual objects remain unfrozen. Inspecting those artifacts supports semantic claims, not fixed byte ratios, cache formulas or guaranteed speed rankings.

### 8) **Mentor note**

Ask the candidate to predict the alias count, Mirror lookup and ordinary get literal before running the probes. Then change one condition: add Third, enable isolatedModules or prebind the object. A strong answer revises the model from observed evidence and identifies what remains unverified instead of repeating a memorized rule.
