## 2.1. How to Teach Types (from JS mental model)

### 1) **Approach** (JS → add types)

**Approach — start from JS runtime students already know, then add type layer:**

1. **Show JS behavior** (runtime) → **add TS contract** that describes it. Don't start with abstract type syntax.

```typescript
// step 1: JS behavior (already known)
function greetJS(user) { return `Hi ${user.name}`; }
let jsUser = { name: "Ava", age: 30 };
console.log(greetJS(jsUser)); // Hi Ava

// step 2: same at type level — describe shape already there
type User = { name: string; age: number };
function greet(user: User): string { return `Hi ${user.name}`; }
console.log(greet(jsUser)); // identical runtime, now checked

// step 3: show bug types prevent (rename proof)
type User2 = { displayName: string };
function greet2(user: User2): string { return `Hi ${user.displayName}`; }
// greet2({ name: "Ava" }); // error — contract catches rename mismatch before runtime
```

2. **Curriculum rhythm:** `01→02→03→04` as path: erasure → primitives/literals → objects → functions. Each builds on JS familiarity.

---

### 2) **Example** (workshop)

Workshop `2h` outline (used in mentoring):

| Minutes | Activity | Outcome |
|---------|----------|---------|
| 0–15 | Live JS bug: `formatPrice({ val: 10 })` shows `$undefined` (no type) | Motivate: JS silent |
| 15–30 | Add `type Price = { value: number }` → compiler error before run | Aha: types catch same bug at edit time |
| 30–60 | Hands-on: convert small module with `unknown` + narrow and `satisfies` | Practice |
| 60–85 | Group review: `any` vs `unknown` + `Zod` at fetch boundary | Bridge erasure |
| 85–110 | Toolchain: `tsc --noEmit` + `biome check` in CI pipeline sketch | Production tie |
| 110–120 | Retro: checklist (no `any`, no `as` across modules) → takeaway card |

```typescript
// workshop exercise solution snippet
type Product = { id: string; price: number };
function formatPrice(p: Product): string { return `$${p.price.toFixed(2)}`; }
let p: Product = { id: "1", price: 10 };
console.log(formatPrice(p)); // $10.00
// deliberate error for group: formatPrice({ id: "1", price: "10" }) — should error
```

### 3) **Bad** (start with advanced)

**Bad pedagogical patterns:**

- Starting with `infer`/`distributivity` before primitives — loss of audience.
- Live-coding heavy utility (`DeepReadonly`) before `Pick` passes.
- Showing `tsc` emit flags before `strict` story — tool before purpose.

**Anti-pattern example:**

```typescript
// bad workshop opener
type Magic<T> = T extends infer U ? U extends string ? Uppercase<U> : never : never; // scares juniors
// good opener: literal union + narrow
type Status = "idle" | "loading";
function next(s: Status): string { if (s === "idle") return "start"; return "done"; }
```

Rule: junior-first → senior-last per leaf (as required by `PROMPT.md:16`). Each leaf's first half runnable by junior, second half offers expert nuance.

**Common confusion** —

- "Teaching TS needs separate JS foundation" — assumes not; reuse `README/JavaScript` — link, don't re-teach.

**Performance note** — Types are erased (zero emit); checker cost dominates. For this feature, keep types shallow and measure `tsc --extendedDiagnostics` if checker slows.

**Mentor note** —

Leave workshop with one actionable lint rule: `no-explicit-any` enabled. One rule drives types adoption without lecture overload.
