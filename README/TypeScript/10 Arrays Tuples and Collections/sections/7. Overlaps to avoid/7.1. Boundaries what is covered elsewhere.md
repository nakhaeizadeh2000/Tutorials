## 7.1. Boundaries — what is covered elsewhere

Choose a collection from the contract the consumer needs: element types, positions, keys, mutation permissions and missing-value behavior. This domain teaches those choices and the typed operations on arrays, tuples, Maps and Sets. Its neighbors explain callable argument lists, generic forwarding, type transformations, element shapes, branch narrowing and compiler settings.

Use the actual failed operation to choose a route. A rejected parameter list, an empty index read and an unavailable runtime method can all involve collections while needing different evidence. These links point to published owners; they do not certify every linked lesson or integration.

### 2) **Mapped and conditional transformations over collections**

### 6) **Worked collection behavior and routing practice**

The [Map/Set and iterator-helper owner](<../3. Collections and Selection/3.1. Map and Set typing generics over collections.md>) now provides complete get-or-insert and synchronous iterator-helper examples. It observes eager versus lazy factory calls, existing undefined entries, conversion to objects/JSON, helper completion and limits on input versus output. The [JavaScript iterator protocol](<../../../../JavaScript/10 Iterables Generators and Async Iteration/sections/1. Iterable and iterator protocols/1.2. Use four cases to choose a next observation. A first element is missing: inspect the collection and the index contract, then the value guard. A Map has a present entry whose value is undefined: use the worked owner's has/get/presence contrast rather than treating undefined alone as proof of absence. Symbol-keyed entries disappear from a JSON payload: trace the object's conversion and serialization separately. A filter followed by take still visits many inputs: follow the helper owner's finite input/output-count fixture. Each case has a specific operation to inspect, not a generic instruction to choose a different container.

### 7) **Common confusion**

A readonly view does not freeze the array or its element objects. An optional tuple slot and an open array index describe different position contracts. A static transform does not create an equivalent runtime collection. A method declaration in a standard library file does not prove runtime availability. For the worked Map and iterator cases, distinguish entry presence from its value and output count from input visits.

### 8) **Performance note**

Documentation ownership has no direct runtime effect. Collection traversal, copying, conversion and helper consumption remain runtime work; their type annotations are erased. This lesson measured no speed or memory comparison. There is no additive checker-cost formula or general claim that filter-then-map beats branching established by these routes. Use the [measurement workflow](<../../../19 Performance Project References and Scaling/sections/1. Check-Time Performance/1.1. Measuring with extendedDiagnostics and traces.md>) for a real compiler issue and measure the actual runtime workload before changing its algorithm.

### 9) **Mentor note**

Ask the learner to choose an owner for each practice case and name the next observation. A strong answer checks an actual index result, Map presence separately from get, serialized output separately from object keys, and helper input visits separately from yielded outputs. Then ask whether enabling a lib declaration fixes a missing runtime method: it does not. Evaluate their evidence and proposed check, rather than counting remembered domain numbers.
