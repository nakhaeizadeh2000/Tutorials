## 1.3. Array methods map filter reduce typed precisely

An array method combines a runtime operation with a declared callback contract. Follow both: what the callback's type lets the checker infer, and what its actual condition or return does to the data. A precise result type cannot replace an absence policy, an initial accumulator or an independent copy when one is needed.

Examples use TypeScript 7.0.2 and Node.js 20.20.2. Save each independent fence under its filename. Compile with `tsc --strict --exactOptionalPropertyTypes --noUncheckedIndexedAccess --erasableSyntaxOnly --removeComments --target es2022 --module commonjs --lib es2023,dom --outDir dist FILE.ts`; run `node dist/FILE.js`. Activate negatives individually and use --noEmit instead of --outDir dist. The copying methods in this lesson run on the stated Node version; adding lib declarations does not install methods in an older runtime.

### 1) **Map results, predicate filters and missing finds**

Map builds an output array from callback results. Filter selects original elements; a suitable predicate signature can narrow its result type. That predicate may be inferred from a direct comparison instead of explicitly written. An annotation returning boolean can intentionally hide the stronger signature. [TypeScript 5.5's primary notes](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-5-5.html#inferred-type-predicates) explain the inference conditions and why truthiness needs care.

Save as selection.ts.

```typescript
const words: (string | null)[] = ["a", null, "b", ""];
const inferred = words.filter(value => value !== null);
const explicit = words.filter((value): value is string => value !== null);
const boolOnly = words.filter((value): boolean => value !== null);
const truthy = words.filter(Boolean);
console.log(inferred.map(word => word.toUpperCase()).join("|"), explicit.length, truthy.length);
// boolOnly.map(word => word.toUpperCase()); // TS18047: declared boolean hides the predicate
// truthy.map(word => word.toUpperCase()); // TS18047: Boolean is not a null-exclusion predicate
const numbers: (number | undefined)[] = [0, 2, undefined];
const present = numbers.filter(value => value !== undefined);
const nonzero = numbers.filter(value => !!value);
console.log(present.join(","), nonzero.join(","));
const objects: ({ id: string } | undefined)[] = [{ id: "u1" }, undefined];
const truthyObjects = objects.filter(value => !!value);
console.log(truthyObjects.map(value => value.id).join(","));
const upper = inferred.map(word => word.toUpperCase());
const hit = upper.find(word => word.startsWith("A"));
const missing = upper.find(word => word.startsWith("Z"));
console.log(hit?.toLowerCase() ?? "missing", missing ?? "missing");
// missing.toLowerCase(); // TS18048

type Equal<A, B> =
  (<T>() => T extends A ? 1 : 2) extends
  (<T>() => T extends B ? 1 : 2) ? true : false;
type Expect<T extends true> = T;
type Inferred = Expect<Equal<typeof inferred, string[]>>;
type Explicit = Expect<Equal<typeof explicit, string[]>>;
type BooleanOnly = Expect<Equal<typeof boolOnly, (string | null)[]>>;
type BooleanFiltered = Expect<Equal<typeof truthy, (string | null)[]>>;
type Present = Expect<Equal<typeof present, number[]>>;
type NumericTruthiness = Expect<Equal<typeof nonzero, (number | undefined)[]>>;
type ObjectTruthiness = Expect<Equal<typeof truthyObjects, { id: string }[]>>;
type FindResult = Expect<Equal<typeof missing, string | undefined>>;
```

The output is `A|B| 3 2`, `0,2 2`, `u1`, then `a missing`; eight probes compile. The direct null comparison retains the empty string, while Boolean removes it. The numeric truthiness filter drops zero and does not establish that its false branch contains only undefined. Object truthiness has a different inference result here because the object alternative is always truthy. Do not replace these observations with a rule that every truthiness callback narrows, or none can.

Find returns a matching element or undefined. This example actually searches the uppercase array for A; searching the original lowercase words for uppercase A would miss. The [guard owner](<../../../07 Unions Intersections and Narrowing/sections/3. Control Flow Narrowing/3.3. Custom narrowers predicates asserts and type guards on unions.md>) explains predicate correctness and false-branch obligations without duplicating them here.

### 2) **Choose the accumulator contract and the empty case**

Reduce has overloads for an element accumulator and for a separate accumulator type with an initial value. A seed contributes inference, but an empty [] or {} can be too narrow for the intended writes. An explicit type argument or a typed seed states that intent. A callback must return the next accumulator; pushing into an array and returning push's numeric result would violate an array accumulator contract. [Matt Pocock's original accumulator explanation](https://www.totaltypescript.com/how-to-type-array-reduce) compares useful annotation sites; an assertion is unnecessary here.

Save as accumulation.ts.

```typescript
const sum = (values: readonly number[]): number => values.reduce((acc, value) => acc + value, 0);
console.log(sum([]), sum([1, 2]));
function unseeded(values: readonly number[]): number {
  return values.reduce((acc, value) => acc + value);
}
try { unseeded([]); } catch (error) { console.log("empty reduce", error instanceof TypeError); }
console.log(unseeded([5]));
const words = ["Ada", "Lin"];
const lengths = words.reduce<number[]>((acc, word) => { acc.push(word.length); return acc; }, []);
console.log(lengths.join(","));
// words.reduce((acc, word) => { acc.push(word.length); return acc; }, []); // TS2345: seed inferred never[]
// words.reduce<number[]>((acc, word) => acc.push(word.length), []); // TS2322: number is not number[]
type Region = "eu" | "us";
interface Sale { region: Region; amount: number }
function totals(sales: readonly Sale[]): Record<Region, number> {
  return sales.reduce<Record<Region, number>>((acc, sale) => {
    acc[sale.region] += sale.amount;
    return acc;
  }, { eu: 0, us: 0 });
}
console.log(JSON.stringify(totals([])));
console.log(JSON.stringify(totals([{ region: "eu", amount: 5 }, { region: "eu", amount: 2 }])));
// totals([{ region: "other", amount: 1 }]); // TS2322
const sparse = new Array<number>(2);
let visits = 0;
console.log(sparse.reduce((acc, value) => { visits++; return acc + value; }, 0), visits);
try { unseeded(sparse); } catch (error) { console.log("no present seed", error instanceof TypeError); }
```

The output is `0 3`, `empty reduce true`, `5`, `3,3`, `{"eu":0,"us":0}`, `{"eu":7,"us":0}`, `0 0`, then `no present seed true`. The unseeded overload compiles for number[] without proving that an element exists. At runtime it uses the first present element, skips holes, and throws if none exists. The [reduce reference](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/reduce#exceptions) documents this boundary. A single-element unseeded reduction is legitimate when that is the chosen contract; this ordinary array type does not enforce nonemptiness.

The finite record seed really contains both regions, so every indexed accumulation begins with a number. This is different from asserting that an empty object already contains all required keys. Prefer an operation whose result matches the task: map for direct one-to-one conversion, reduce for accumulating a different summary, or a loop when explicit early exit makes the control flow clearer.

### 3) **Observe each method's mutation and return value**

Sort mutates and returns its receiver. Push mutates and returns the new length; splice mutates and returns removed elements. These are different return contracts. Copying methods such as toSorted and toSpliced create a fresh outer array and are available on readonly arrays with the appropriate library declarations. They do not deep-copy elements or freeze their result.

Save as ordering.ts.

```typescript
const board = [3, 1, 2, 5];
function top3(scores: readonly number[]): number[] {
  // scores.sort(); // TS2339
  return scores.toSorted((a, b) => b - a).slice(0, 3);
}
console.log(top3(board).join(","), board.join(","));
const same = board.sort((a, b) => b - a);
console.log(same === board, board.join(","));
const size = board.push(4);
const removed = board.splice(1, 1);
console.log(size, removed.join(","), board.join(","));
const replaced = board.toSpliced(1, 1, 9);
console.log(replaced.join(","), board.join(","), replaced === board);
const lexical = [10, 2].toSorted();
const numeric = [10, 2].toSorted((a, b) => a - b);
console.log(lexical.join(","), numeric.join(","));
// const wrongReturn: number[] = board.push(6); // TS2322
// board.toSorted((a, b) => a > b); // TS2345: comparator returns number, not boolean
```

The output is `5,3,2 3,1,2,5`, `true 5,3,2,1`, `5 3 5,2,1,4`, `5,9,1,4 5,2,1,4 false`, then `10,2 2,10`. The complete four-element board matters when inspecting mutation; a shortened expected output would conceal the actual state. The [toSorted reference](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Array/toSorted#return_value) specifies the new array result. Numeric data needs a numeric comparator for numeric order.

Keep target and lib separate: this lesson targets ES2022 syntax while requesting ES2023 library declarations. Reducing lib to es2022 makes toSorted/toSpliced unavailable to the checker, even on this capable runtime. Conversely, declarations alone cannot make those calls work on an unsupported runtime. A suitable runtime or polyfill is a deployment requirement, not an emitted TypeScript transformation.

### 4) **Common confusion**

An explicit is annotation is not required for every narrowing filter, and a boolean-returning callback is not automatically a predicate. Inspect both the actual condition and the exposed signature. A truthiness filter also changes data: preserving zero or the empty string may be essential even when all resulting values share one type.

An initial value resolves the runtime empty case only according to that value's semantics; zero is suitable for this sum, not every reduction. A nonempty length with holes still may provide no present seed. A method returning an array also does not imply it returns a new receiver or leaves its input unchanged.

### 5) **Performance note**

Callback checks execute; predicate annotations erase. Map and filter produce result arrays, and copying methods create outer copies. Reduce can reuse a private accumulator, but its callback may still allocate on every step; repeated spreading of a growing accumulator repeats copying. Sorting work depends on the engine, comparator and input, so no universal algorithm, fixed allocation count or timing advantage is claimed. Choose readable semantics first and measure the actual pipeline before fusing operations for speed.

### 6) **Mentor note**

Ask the learner to explain why Boolean drops an empty string while the direct comparison keeps it, then predict the return type of push and splice before running ordering.ts. For reduce, require separate answers for [] and an array containing only holes.

For practice, implement sumPresent(values: readonly (number | undefined)[]): number. Exclude only undefined with a comparison filter, then sum with an initial zero. It must accept [0, 2, undefined], [undefined] and [], returning 2, 0 and 0. Inspect the filtered array and require that it still contains zero; the totals alone would not expose a truthiness filter's data loss. Removing the initial zero must make the empty filtered cases throw, demonstrating why type narrowing does not establish nonemptiness.
