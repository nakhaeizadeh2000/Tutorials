## 2.2. `verbatimModuleSyntax` — predictable emit

### 1) **No guessing, only stating** (type traffic via `import type` or TS1484)

**Definition** — `verbatimModuleSyntax: true` (TS 5.0) disables import-elision *analysis*: type-only names in value imports error (TS1484 — state with `import type`), and emit preserves import statements verbatim (what authors write is what bundlers/strippers process). The compiler stops *inferring* erasability from usage — authors *declare* it per import, the flag polices the declaration. [12/1.2](<../../../12 Modules Namespaces and Declaration Files/sections/1. ES Modules/1.2. import type and verbatimModuleSyntax erasable imports.md>) owns the import discipline; this promise owns *configuring* it (enabling, triaging TS1484s, verifying emit).

**What problem it solves / history** — elision heuristics (`importsNotUsedAsValues: remove`) decided emit from usage analysis — same source emitting different module graphs under tsc (elided) vs esbuild (preserved): side-effect imports dropped by one pipeline, type imports kept by another (the 12/5.1 promise-2 incident class: registration skipped in prod, kept in tests). Verbatim emit unifies pipelines: stated types erase everywhere identically, stated values persist everywhere identically — no analysis, no divergence.

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), enable `verbatimModuleSyntax` in every tsconfig (with `isolatedModules` — the predictable-emit pair); triage each TS1484 by converting to `import type` (stating — never value-using to silence, which reintroduces guessing by hand). Pair with `--erasableSyntaxOnly` where adopted (stated imports + erasable syntax = fully syntax-processable files).

**Runnable example** — stating enforced, guessing refused (multi-file sets; TS1484 demo as commented error):

```typescript
// file: types122.ts
export interface Cfg122 { host: string }
export const DEF122 = 80;
// file: stated122.ts
import type { Cfg122 } from "./types122.js"; // stated (passes verbatim: erased identically everywhere)
import { DEF122 } from "./types122.js"; // value (kept identically everywhere)
export function addr(c: Cfg122): string { return `${c.host}:${DEF122}`; }
// file: app122.ts
import { addr } from "./stated122.js";
console.log(addr({ host: "h" })); // h:80 — stated traffic (zero guessing on any pipeline)
```

```typescript
// file: types123.ts
export interface Opts123 { retries: number }
// file: guess123.ts
// import { Opts123 } from "./types123.js"; // error TS1484 under verbatimModuleSyntax (guessing refused)
// fix — import type { Opts123 } (stating: the flag rewards stating, punishes guessing)
import type { Opts123 } from "./types123.js";
export function tries(o: Opts123): string { return `tries=${o.retries}`; }
// file: app123.ts
import { tries } from "./guess123.js";
console.log(tries({ retries: 3 })); // tries=3 — converted import (audit complete for this file)
```

```typescript
// file: vals124.ts
export interface I124 { x: number }
export function f124(i: I124): number { return i.x; }
// file: app124.ts
import { f124 } from "./vals124.js";
import type { I124 } from "./vals124.js"; // split traffic (values kept, types erased — each honest)
const v: I124 = { x: 2 };
console.log(f124(v).toFixed(0)); // 2 — dual imports, zero ambiguity (verbatim preserves both exactly)
// bad — import { f124, I124 } (single value-syntax import: TS1484 on I124 — one statement, two universes, refused)
```

**Common confusion** — "the flag changes checking" — emit-only (same types, same assignability — new *errors* on guessing patterns, never new *types*). "TS1484 fixes slow adoption" — each TS1484 is a phantom edge deleted (the erasability audit automated) — triage speed scales with codebase honesty (honest codebases: dozens; guessing codebases: hundreds, each worth fixing). "verbatim slows emit" — removes heuristic passes (marginally faster emit logic); cost is authoring precision (stated kinds per import — seconds per declaration, once).

**Performance note** — predictable emit lets bundlers skip re-analysis (statements mean exactly what they say); `import type` edges vanish from graphs (smaller bundles, faster startup — same dividend as 12/1.2 promise 1, now enforced repo-wide).

**Mentor note** — enable Friday, triage TS1484s Monday (each a type-only import masquerading as value traffic — the audit the codebase needed). Rule: TS1484 fixes convert to `import type` (stating); "fixing" by value-using the name is fraud against the flag — review accordingly.

### 2) **Emit preservation semantics** (bundlers see exactly what authors wrote)

**Definition** — under the flag, `tsc` preserves import/export statements *verbatim* in emit (no elision analysis, no rewriting): `import type` lines vanish (stated-erased), value imports persist byte-identical, `export type` re-exports erase cleanly. Downstream tools (esbuild, swc, Babel, Node stripping) therefore process *the author's statements*, never the compiler's guesses — pipeline agreement by construction.

**What problem it solves / history** — elided emit differed per toolchain *by design* (tsc analyzed usage; esbuild preserved syntax; Babel followed plugins) — same source, three module graphs (side effects kept here, dropped there; type imports bundled here, erased there). Debugging meant diffing emit across toolchains per incident. Verbatim emit collapses the three graphs into one: authors state, all pipelines process identically, divergence class deleted structurally.

**Modern guidance** — as of TypeScript 5.9 era, write imports as the emit contract (every statement reviewed for its runtime effect: kept vs erased); verify with dual-pipeline CI (tsc-emit vs esbuild-bundle diffed on entry chunks — divergence fails the build); document the rule once (contributing guide: "imports mean what they say" — the flag enforces the rest).

**Runnable example** — one source, identical graphs (multi-file sets):

```typescript
// file: keep125.ts
export const K125 = "k";
export interface T125 { t: string }
// file: mid125.ts
import { K125 } from "./keep125.js";
import type { T125 } from "./keep125.js"; // stated split (verbatim emit: value line kept, type line erased — every pipeline)
export function use(t: T125): string { return `${t.t}:${K125}`; }
// file: app125.ts
import { use } from "./mid125.js";
console.log(use({ t: "x" })); // x:k — tsc, esbuild, swc, stripping all process identically (no analysis to diverge on)
```

```typescript
// file: side126.ts
console.log("side126 evaluated");
export const V126 = 1;
// file: app126.ts
import "./side126.js"; // bare import (kept verbatim — side effect guaranteed on every pipeline)
import { V126 } from "./side126.js";
console.log(V126.toFixed(0)); // 1 (+ "side126 evaluated" exactly once, everywhere — verbatim preservation)
// bad — value-importing V126 used type-only (elision heuristics drop the load under tsc, keep under esbuild — divergence)
// fix — bare import (loading stated) + import type (typing stated): each job its own statement, each kept/erased verbatim
```

```typescript
// file: re127.ts
export interface R127 { r: number }
export const RV127 = 2;
// file: barrel127.ts
export type { R127 } from "./re127.js"; // stated type re-export (erased identically everywhere)
export { RV127 } from "./re127.js"; // stated value re-export (kept identically everywhere)
// file: app127.ts
import { RV127, type R127 } from "./barrel127.js";
const r: R127 = { r: RV127 };
console.log(r.r.toFixed(0)); // 2 — barrel hops preserve verbatim (stated kinds survive re-export chains)
// bad — export { R127 } (TS1205: ambiguous barrel hop — transpilers guess, tsc refuses under isolatedModules)
```

**Common confusion** — "verbatim means no erasure" — verbatim *preserves statements*, erases *stated types* (`import type` lines vanish — verbatim means "as written", and `import type` as-written means erased). "preservation bloats bundles" — preserved *value* imports were always needed (their removal was the bug); erased *type* imports vanish (verbatim erasure is total for stated types). "dual-pipeline CI doubles costs" — transpile runners execute in milliseconds (no typecheck — checking runs once under tsc); second pipeline verifies emit-divergence for near-zero CI time.

**Performance note** — identical graphs across pipelines eliminate divergence debugging (hours per incident → zero); preserved statements bundle identically everywhere (no per-toolchain surprises in chunk graphs).

**Mentor note** — diff tsc-emit vs esbuild-output on one entry chunk (identical module graphs — verbatim working) vs a guessing-era sample (diverged graphs — heuristics failing) — preservation demonstrated, not asserted. Rule: imports reviewed for runtime effect (kept vs erased) like any other emit-affecting code.

### 3) **Adoption path** (enable + triage TS1484s as the erasability audit)

**Definition** — adoption sequence: enable `verbatimModuleSyntax` (errors appear — the audit inventory), triage TS1484s file by file (convert to `import type` — stating; each conversion deletes a phantom edge), verify with dual-pipeline CI (tsc + a per-file transpiler agreeing post-triage), and lock with lint (`consistent-type-imports` — new guessing fails review). Days for honest codebases, weeks for guessing-heavy ones — bounded, reviewable, compounding.

**What problem it solves / history** — flag-day verbatim adoption (enable + fix 500 TS1484s in one PR) stalled like every flag-day (unreviewable, conflicting, pressuring suppression). Per-directory adoption (new code verbatim-clean, legacy triaged file-by-file with the errors as the work list) compounds: each triaged file stays clean (lint-locked), each TS1484 fixed deletes a phantom edge permanently.

**Modern guidance** — as of TypeScript 5.9 era, adopt per directory (new code clean from day one; legacy triaged with TS1484-count as the progress metric — falling weekly); fix by converting (stating), never by suppressing or value-using (both preserve the guessing the flag exists to delete); pair with `isolatedModules` triage in the same pass (both flags audit transpilability — one pass, two error classes).

**Runnable example** — triage converts guessing to stating (multi-file sets):

```typescript
// file: legacy128.ts
export interface Old128 { a: string }
export const VAL128 = 1;
// file: triaged128.ts
import type { Old128 } from "./legacy128.js"; // triaged (was value-imported, TS1484'd, converted)
import { VAL128 } from "./legacy128.js"; // value traffic kept (was already honest)
export function use(o: Old128): string { return `${o.a}:${VAL128}`; }
// file: app128.ts
import { use } from "./triaged128.js";
console.log(use({ a: "x" })); // x:1 — triaged file (phantom edge deleted, stated traffic in place)
// bad — // @ts-expect-error on the TS1484 (suppression preserves the guessing + deletes its diagnostic — worst of both)
// fix — convert (stating): the error IS the work list (each TS1484 a phantom edge with a fix site)
```

```typescript
// file: legacy129.ts
export interface A129 { a: string }
export interface B129 { b: number }
// file: triaged129.ts
import type { A129, B129 } from "./legacy129.js"; // bulk triage (one statement, all type traffic stated)
export function pair(a: A129, b: B129): string { return `${a.a}:${b.b}`; }
// file: app129.ts
import { pair } from "./triaged129.js";
console.log(pair({ a: "x" }, { b: 2 })); // x:2 — bulk-converted (per-file triage scales linearly, reviewably)
// bad — flag-day single PR (500 conversions, unreviewable, conflicting with feature branches for a quarter)
// fix — per-directory PRs (each green, each reviewable, each locked by lint after)
```

```typescript
// file: locked130.ts
export interface L130 { l: string }
// file: guarded130.ts
import type { L130 } from "./locked130.js"; // lint-locked (consistent-type-imports: new guessing fails review)
export function g(l: L130): string { return l.l.toUpperCase(); }
// file: app130.ts
import { g } from "./guarded130.js";
console.log(g({ l: "y" })); // Y — triaged + locked (audit complete, regression impossible via lint)
// bad — triaged without lint (next quarter reintroduces guessing one import at a time — decay without enforcement)
// fix — consistent-type-imports lint in the same PR as triage completion (audit + lock atomically)
```

**Common confusion** — "triage count measures debt" — measures *audit progress* (falling TS1484 = phantom edges deleted); debt is un-triaged guessing (invisible until incidents) — count the work list, celebrate its shrinkage. "suppression unblocks triage" — suppression *deletes items from the work list without doing the work* (phantom edges persist, diagnostics gone — the exact failure mode triage exists to prevent). "lint-first avoids triage" — lint prevents *new* guessing (essential lock); existing guessing needs triage regardless (lock + audit compose, neither substitutes).

**Performance note** — triage costs authoring minutes per file (one-time); locked discipline costs zero ongoing (lint enforces); un-triaged guessing costs phantom-edge incidents (unbounded, recurring) — audit economics favor completion heavily.

**Mentor note** — graph TS1484 count weekly during adoption (falling line = audit working; flat = stalled class needing pairing). Exercise: triage five files live (convert + explain each phantom edge deleted) — the pattern transfers in under an hour. Gate: suppression of TS1484 fails review unconditionally; triage PRs stay small (per-directory, green each).
