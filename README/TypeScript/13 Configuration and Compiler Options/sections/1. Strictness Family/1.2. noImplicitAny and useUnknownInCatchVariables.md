## 1.2. `noImplicitAny` and `useUnknownInCatchVariables`

### 1) **`noImplicitAny` coverage** (every silent `any` becomes an error with a fix site)

**Definition** — `noImplicitAny: true` (in `strict`) errors where the checker would otherwise *infer* `any`: unannotated function parameters (`function f(x)` → TS7006), evolving `let`/`[]` with no evidence, and untyped callback positions the context doesn't cover. Each error names the fix site (annotate the parameter, declare the element type) — silent holes become loud declarations.

**What problem it solves / history** — implicit-`any` positions were `any`-infection sources with no marker (unannotated params accepting everything, evolving arrays absorbing anything — each a hole invisible in review, each discovered via downstream misuse). The flag converts every hole into an authoring-time error *at the hole*: annotate honestly (`string`), narrow from `unknown`, or declare `any` explicitly (fenced, visible, reviewable — see promise 3).

**Modern guidance** — as of TypeScript 5.9 era (Aug 2026: TS 5.9 stable, 6.0 beta; Node 24 Active LTS), annotate every parameter (no bare `(x)` in committed code — ever); declare evolving state (`const seen: string[] = []`, `let cur: Token | null = null`); type callback positions contextually (the enclosing signature usually covers — annotate only where context runs out). Treat each TS7006/TS7034 as a one-line fix, never a `any`-annotation reflex.

**Runnable example** — holes become declarations (good vs bad, `tsc --strict`):

```typescript
// good — annotated params, declared state: holes closed at authorship
function total(prices: number[]): number {
  return prices.reduce((a, b) => a + b, 0); // contextual params (covered by reduce's signature)
}
const seen: string[] = []; // declared (never[] evolution pre-empted honestly)
console.log(total([1, 2]).toFixed(0), seen.length); // 3 0
// function bad(x) { return x; } // error TS7006 (implicit any param — annotate: (x: string))
// fix — (x: string): the error IS the fix site (one annotation, hole closed)
```

```typescript
// good — callback positions covered by context (annotate only where context ends)
interface Handler { (ev: string, code: number): void }
function on(h: Handler): void { h("click", 200); }
on((ev, code) => console.log(ev.toUpperCase(), code.toFixed(0))); // contextual (ev: string, code: number inferred)
// bad — (ev, code) => ... against (h: Function) (untyped context → implicit any params → TS7006 pair)
// fix — type the context (Handler), not each callback (contextual typing scales; per-callback annotating doesn't)
console.log("contextual-ok");
```

```typescript
// good — empty-object evolution declared (not any-shaped)
const cache: Record<string, number> = {}; // declared (keys/values checked from first write)
cache["a"] = 1;
// cache["b"] = "x"; // error TS2322 (value typed — evolution pre-empted honestly)
console.log(cache["a"]?.toFixed(0) ?? "missing"); // 1 — declared shape, checked writes
// bad — const cache = {} (evolving any: writes unchecked, reads untrusted — the hole that ate refactors)
// fix — Record<string, number> (or Map — see 10/3.1): declare the shape, check every write
```

**Common confusion** — "contextual typing needs no flag" — contextual positions are covered *with or without* the flag (context supplies types either way); the flag guards the *uncovered* positions (bare params, evolving lets) — complementary, not overlapping. "annotating everything is verbose" — annotations on *holes* (params, evolving state) are the highest-density documentation in typed code (one line per contract); contextual positions stay bare (inference does the work). "explicit `any` defeats the flag" — explicit `any` is *visible* (reviewable, greppable, fenceable — see promise 3); implicit `any` was invisible — visibility is the entire point.

**Performance note** — annotated positions check identically to inferred ones (same types, stated vs derived); evolving-`any` positions check *nothing* (holes) while *costing* downstream forensics (misuse errors far from holes) — annotation converts forensics into declarations at zero check cost.

**Mentor note** — uncomment one bare `(x)` and read TS7006 together — "the error is the fix site" in one diagnostic. Exercise: enable the flag on a legacy file and fix each error by annotating (count `any`-annotations chosen vs precise types — precision ratio as team metric). Gate: new explicit `any` requires justification (see promise 3); implicit `any` is impossible under the flag by construction.

### 2) **`useUnknownInCatchVariables`** (catch bindings typed `unknown`, narrowed before use)

**Definition** — `useUnknownInCatchVariables: true` (in `strict`) types `catch (e)` bindings as `unknown` instead of `any`: every use narrows first (`instanceof Error`, `typeof` checks, assertion guards) or errors. Throwables in JS are untyped by specification (anything throwable — strings, numbers, objects, `undefined`) — `unknown` is the honest type; `any` was the convenient lie.

**What problem it solves / history** — `catch (e)` as `any` let handlers read `e.message`/`e.code`/`e.stack` unconditionally — non-Error throws (`throw "oops"`, `throw 42`, `throw undefined` from foreign/minified code) crashed handlers *inside* error handling (the worst place: diagnostics dead exactly when needed). `unknown` forces the shape-check handlers should have had: narrow to `Error` (or the expected shape), handle the rest as unknown (log + rethrow, never property-read blind).

**Modern guidance** — as of TypeScript 5.9 era, narrow catch bindings with `instanceof Error` first (message/stack safe), then expected shapes (`typeof e === "string"` for string-throwing libs), else log-and-rethrow (unknown remainder never property-read). Write a shared `toError(e: unknown): Error` normalizer (one narrowing site per codebase — handlers call it, nobody re-derives). Never `as Error` blindly (assertion without evidence — the `any` habit in new syntax).

**Runnable example** — narrowed handling, never blind reads (good vs bad, `tsc --strict`):

```typescript
// good — normalizer centralizes narrowing (one site, every handler covered)
function toError(e: unknown): Error {
  if (e instanceof Error) return e; // Error shape proven (message/stack safe)
  return new Error(String(e)); // remainder wrapped honestly (never property-read blind)
}
function run(): string {
  try {
    throw "oops-string"; // foreign code throws non-Errors routinely
  } catch (e) {
    return toError(e).message; // narrowed via normalizer (typed end to end)
  }
}
console.log(run()); // oops-string — non-Error throw handled, diagnostics alive
```

```typescript
// good — shape-narrowing for expected non-Error shapes (validation libraries, workers)
function toError(e: unknown): Error {
  return e instanceof Error ? e : new Error(String(e)); // shared normalizer (re-declared: fences compile standalone)
}
function parse(): number {
  try {
    return JSON.parse("42") as number;
  } catch (e) {
    if (e instanceof SyntaxError) return -1; // specific shape (position info available here)
    throw toError(e); // remainder normalized + rethrown (never swallowed silently)
  }
}
console.log(parse().toFixed(0)); // 42 — specific shapes handled specifically, rest normalized
// bad — catch (e) { return e.message; } (any-shaped read: crashes on throw "oops" — diagnostics dead when needed)
```

```typescript
// good — unknown remainder logged + rethrown (never property-read, never swallowed)
function toError(e: unknown): Error {
  return e instanceof Error ? e : new Error(String(e)); // shared normalizer (re-declared: fences compile standalone)
}
function load(): string {
  try {
    throw undefined; // hostile throwables exist (minified libs, foreign runtimes)
  } catch (e) {
    console.log("load failed"); // log without reading e (nothing safe to read on unknown)
    throw toError(e); // rethrow normalized (callers handle Error, not undefined)
  }
}
try {
  console.log(load());
} catch (e) {
  console.log(toError(e).message); // undefined — wrapped honestly (String(undefined), no crash)
}
// bad — catch { /* empty */ } (swallowing: errors vanish, state corrupts silently downstream)
```

**Common confusion** — "`unknown` catch is verbose" — one shared normalizer (`toError`) reduces every handler to one call (less code than per-handler `any`-reads plus their incident follow-ups). "all throws are Errors in practice" — *your* throws are; foreign/minified/generated throws aren't (strings, numbers, `undefined` observed in production) — handlers serve the ecosystem, not your codebase. "narrowing slows hot paths" — `instanceof` is one prototype check per catch (exceptional paths by definition — hot loops never throw in steady state).

**Performance note** — zero steady-state cost (normalizer runs only on throws — exceptional by definition); `instanceof` one prototype walk per catch (trivial vs the throw's own stack-capture cost). Incident deletion (dead-diagnostics class) unbounded upside.

**Mentor note** — `throw "oops"` in a demo and watch `e.message` fail under `unknown` (then pass via normalizer) — honest catch in one throw. Exercise: convert three `any`-shaped catch reads to `toError` + narrowing and delete the blind property accesses — diagnostic reliability in one diff. Gate: `catch (e)` property reads without narrowing fail review; shared normalizer required per codebase.

### 3) **Explicit-`any` policy** (declared `any` stays legal — fence it, don't ban it)

**Definition** — `strict` bans *implicit* `any` (inferred holes) but permits *explicit* `any` (`x: any` written deliberately): escape hatches for genuinely untyped boundaries (migration shims, opaque foreign values, test doubles) where precision is currently impossible. Policy (not compiler) governs: allowed positions enumerated (shim returns, `JSON.parse` results pre-validation, legacy interop), each carrying `// TODO` + justification or a lint suppression with reason.

**What problem it solves / history** — `any`-abolitionism (`no-explicit-any` lint as error, zero tolerance) produced *worse* outcomes: `as unknown as T` laundering chains (longer, equally unchecked, harder to grep than `any`), `@ts-ignore` blankets (suppressing *all* errors per line, not just any-ness), and precision theater (over-fitted types claiming knowledge nobody has). Explicit-`any`-with-policy keeps the honest escape (visible, greppable, counted) while banning the hole (implicit, invisible, uncounted).

**Modern guidance** — as of TypeScript 5.9 era, allow explicit `any` at: migration shims (dated TODOs), opaque foreign values (pre-validation, narrowed immediately after), and test doubles (never production paths). Fence with `no-explicit-any: warn` + justification comments (warnings counted in CI dashboards, not failed builds — visibility without theater). Prefer `unknown` + narrowing wherever the value is *consumed* (explicit `any` for *transit*, `unknown` for *use*).

**Runnable example** — fenced transit, narrowed use (good vs bad, `tsc --strict`):

```typescript
// good — explicit any in transit (dated TODO), unknown + narrowing at use
// TODO(2026-Q4): type scheduler API properly (upstream issue #12) — explicit any fenced here
declare function legacySchedule(task: any): unknown; // transit any (visible, dated, reviewable)
function run(task: string): string {
  const out: unknown = legacySchedule(task); // use as unknown (narrow before touching)
  return typeof out === "string" ? out.toUpperCase() : "pending";
}
console.log(run("x")); // X — transit any (one line) feeding narrowed use (checked everywhere after)
// bad — implicit any evolution (invisible hole: writes unchecked, reads untrusted, zero markers)
// fix — explicit where unavoidable (fenced) + unknown where consumed (narrowed): visibility both halves
```

```typescript
// good — JSON boundary: any parsed, unknown held, schema proven
function parseCfg(raw: string): Record<string, string> {
  const parsed: any = JSON.parse(raw); // parse returns any (honest: JSON is untyped)
  if (typeof parsed !== "object" || parsed === null) throw new Error("bad config");
  return parsed as Record<string, string>; // single assertion post-validation (evidence-backed, one site)
}
console.log(parseCfg('{"a":"b"}').a.toUpperCase()); // B — any→validate→assert pipeline (each step visible)
// bad — const cfg = JSON.parse(raw) (implicit any evolution: every downstream read untrusted silently)
// fix — any (parse) → unknown-ish validation → single assertion (pipeline with visible joints)
```

```typescript
// good — test doubles use any freely (never production paths)
function double(): any { return { run: () => 42 }; } // test-double any (test files exempt from the fence)
console.log(String(double().run())); // 42 — test velocity preserved (fence applies to src/, not test/)
// bad — production code importing test-double anys (fence bypass via shared helpers — audit imports, not just declarations)
// fix — eslint overrides: no-explicit-any warn in src/**, off in test/** (fence scoped, velocity kept)
console.log("fenced");
```

**Common confusion** — "explicit any is always a defect" — explicit `any` at untyped boundaries is *honesty* (claiming exactly the knowledge available: none, yet) — defects are *unfenced* anys (no TODO, no narrowing after, production paths). "`unknown` replaces any everywhere" — `unknown` at *use* (forces narrowing); `any` at *transit* (opaque boundaries pre-validation) — different positions, complementary tools (unknown-everywhere forces casts that any-then-narrow avoids). "lint `any` as error" — error-level bans produce laundering chains (`as unknown as T` — longer, equally unchecked, ungreppable); warn-level + dashboards preserve visibility (counted anys fall quarterly; banned anys hide).

**Performance note** — `any` positions skip checks (faster compile locally, unbounded incident surface globally); `unknown` + narrowing checks per use (trivial cost, proven reads) — explicit-any policy optimizes for incident deletion, never check speed.

**Mentor note** — graph explicit-`any` count quarterly (falling = policy working; rising = new boundaries needing types, not scolding). Exercise: convert three transit-`any`s to `unknown` + narrowing and compare call-site safety (each conversion deletes a laundering vector). Rule: explicit `any` carries TODO + justification or fails review; implicit `any` is impossible under the flag by construction.
