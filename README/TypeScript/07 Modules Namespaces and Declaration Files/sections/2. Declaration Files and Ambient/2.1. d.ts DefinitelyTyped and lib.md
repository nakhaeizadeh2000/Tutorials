## 2.1. d.ts, DefinitelyTyped and lib

### 1) **Definition** (declaration emit)

**Definition** — `.d.ts` files are type-only declarations (no JS emit). `declaration: true` emits them for your package; `@types/*` (DefinitelyTyped) supplies them for untyped JS libs; `lib` controls which ambient standard-library `.d.ts` (DOM, ES2020, ESNext) are included.

```typescript
// src/greet.ts
export function greet(name: string): string { return `Hi ${name}`; }
// emit with declaration: true → src/greet.d.ts
// declare function greet(name: string): string;

// consuming untyped lib: express lacks types? Install @types/express
// npm i -D @types/express  → node_modules/@types/express/index.d.ts
import express from "express"; // types now found via declaration resolution

// lib selection (tsconfig)
{
  "compilerOptions": { "lib": ["es2022", "dom"], "target": "es2022" }
}
// lib determines availability of DOM types, Iterator helpers (esnext, 5.6), etc.
```

`skipLibCheck: true` skips checking `d.ts` files (recommended for apps — speeds build, avoids lib errors).

---

### 2) **Example** (declare module)

```typescript
// ambient declare for untyped JS file: lib.js is plain JS, provide lib.d.ts
// lib.d.ts
declare module "./lib.js" {
  export function oldHelper(x: number): string;
}

// consuming:
import { oldHelper } from "./lib.js"; // types from declare module

// declare global lib augmentation (see 2.2)
// declare const myEnvVar: string;

// manually authored d.ts for a package
// my-lib/index.d.ts
declare namespace MyLib {
  export function greet(name: string): string;
}
export = MyLib;
// or ESM:
// declare module "my-lib" { export function greet(name: string): string; }

// generating correct exports map
// package.json: "exports": { ".": { "types": "./dist/index.d.ts", "default": "./dist/index.js" } }
```

---

### 3) **Bad** (manual any d.ts)

**Bad practices:**

- Hand-authoring `declare module "foo" { const any: any; }` that lies (use `unknown` or correct shape; or install `@types/foo`).
- Copy-pasting `declare var foo: any` for every global — use `declare global` augmentation once, correctly typed (see 2.2).
- Setting `lib: ["es5"]` while using `Promise` — need `lib: ["es2015"]+`.

```typescript
// bad: any everywhere d.ts
declare module "bad-lib" {
  const bad: any;
  export default bad;
}
// good: precise or fallback to unknown
declare module "good-lib" {
  export function helper(x: string): number;
}

// bad: missing lib for feature
// target es5 + using async without lib es2015 → Promise unknown error
// fix: lib includes es2015, es2020, etc.

// bad: committing generated .d.ts without declarationMap — consumers can't jump to source
// good: declarationMap: true → .d.ts.map links to .ts source (see 08 3.1)
```

**Common confusion** —

- "d.ts runs" — never. It's pure types, like interface.

**Performance note** —

Large `@types` (e.g., `@types/node`) dominate checker time if `skipLibCheck: false`. For CI typecheck, `skipLibCheck: true` can halve `tsc --noEmit` time.

**Mentor note** —

Default to `skipLibCheck: true` for apps, `false` for library type-checking before publish. Require `@types` for every untyped dep — ban `declare module "x"` rushing to `any`.
