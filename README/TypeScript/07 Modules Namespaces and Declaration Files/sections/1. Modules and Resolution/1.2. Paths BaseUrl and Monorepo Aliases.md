## 1.2. Paths, BaseUrl and Monorepo Aliases

### 1) **Config** (paths)

**Definition** — `paths` + `baseUrl` map non-relative import specifiers (e.g., `@/utils`) to files at checker + bundler runtime.

```jsonc
// tsconfig.json for alias @/* → src/*
{
  "compilerOptions": {
    "baseUrl": ".",
    "paths": {
      "@/*": ["src/*"],
      "@shared/*": ["../shared/src/*"]
    }
  }
}
// usage
import { User } from "@/models/user.js"; // resolves src/models/user.ts
import { fmt } from "@shared/utils.js";
```

`paths` is checker-only — bundler/Node must also resolve. Configure bundler alias (`vite: resolve.alias`) or Node subpath (`package.json#imports`) to match; otherwise `tsc` passes but runtime fails.

For distribution, `paths` aliases are not emitted as relative — keep them internal builds or use `tsc-alias`/`bundler` translation step.

---

### 2) **Example** (@/* alias)

```typescript
// project structure
// src/models/user.ts
// src/utils/format.ts
// src/index.ts

// src/utils/format.ts
export function formatUser(name: string): string { return name.toUpperCase(); }

// src/index.ts
import { formatUser } from "@/utils/format.js"; // alias via paths
import { User } from "@/models/user.js"; // may be "@shared" for monorepo
console.log(formatUser("Ava"));

// monorepo example: packages/app → packages/shared
// packages/app/tsconfig.json
// { "compilerOptions": { "paths": { "@shared/*": ["../shared/src/*"] } } }
// but runtime Node ESM needs package.json imports field or bundler
```

Monorepo `project references` alternative (safer than raw `paths` cross-package) — see [08 2.1 References](<../../../08%20Configuration%20Strictness%20and%20Build%20Pipeline/sections/2.%20Project%20References%20and%20Build/2.1.%20Project%20References%20and%20Composite.md>).

### 3) **Link** (to Unified Architecture)

Alias strategy belongs to repo layout, not just checker:

- Unified/monorepo deep → [UnifiedArchitecture track](<../../../UnifiedArchitecture/README.md>) — package boundaries, shared code, project references vs pnpm workspaces.
- Publishing types with aliases → [08 3.1 Publishing](<../../../08%20Configuration%20Strictness%20and%20Build%20Pipeline/sections/3.%20Publishing%20and%20Versioning/3.1.%20Declaration%20Maps%20Source%20Maps%20and%20Publishing.md>).
- `baseUrl` without `paths` is legacy; prefer explicit alias to avoid ambiguous bare imports.

```jsonc
// bad: baseUrl only — import "utils/format" ambiguous
{ "compilerOptions": { "baseUrl": "src" } }
// good: explicit alias
{ "compilerOptions": { "baseUrl": ".", "paths": { "@/*": ["src/*"] } } }

// Node native alias (Node 14+): package.json
// { "imports": { "#utils/*": "./src/utils/*" } } — Node resolves, ts needs paths mirror
```

**Common confusion** —

- "`paths` rewrites at emit" — no, it doesn't. Runtime resolver must know the alias.

**Performance note** —

Excess `paths` broad wildcards (`*` → `*`) slow module resolution (checker scans more). Keep list short and ordered specific → generic.

**Mentor note** —

Mirror `paths` in bundler config and document "add alias in two places." Add `eslint-import-resolver-typescript` so imports resolve for lint.
