## 3.1. Built-in narrowers — typeof instanceof in and equality

A guard is an executed JavaScript condition that TypeScript can use to refine a value's static type along a control-flow path. Choose a condition that answers the question your code needs: primitive category, prototype membership, property presence, an exact value or nullish absence. Those questions have different answers even for a value accepted by the same static contract.

The independent examples use TypeScript 7.0.2 and Node.js 20.20.2. Save each TypeScript fence under its stated filename. Compile with `tsc --strict --exactOptionalPropertyTypes --erasableSyntaxOnly --removeComments --target es2022 --module commonjs --lib es2022,dom --outDir dist FILE.ts`, then run `node dist/FILE.js`. Activate each commented negative separately and check with the same flags plus `--noEmit` instead of `--outDir dist`.

### 1) **typeof and instanceof**

Use `typeof value === "string"` to select strings from a string/number union. The lowercase result literal matters; `"String"` is not a possible result. Both `== "string"` and `=== "string"` can narrow this comparison, although the strict form avoids an unnecessary coercion question. A check against `"object"` still admits `null`; the [Handbook's typeof section](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#typeof-type-guards) demonstrates why a separate null check is needed.

Save as `categories.ts`.

```typescript
function format(value: string | number): string {
  if (typeof value === "string") return value.toUpperCase();
  return value.toFixed(2);
}
console.log(format("hello"), format(3.1415));
function sameCategory(value: string | number): string {
  if (typeof value == "string") return value.toUpperCase();
  return value.toFixed(0);
}
console.log(sameCategory("ok"));
function objectSize(value: { size: number } | null): number {
  if (typeof value === "object") {
    // return value.size; // TS18047: this branch still admits null
    if (value !== null) return value.size;
  }
  return 0;
}
console.log(typeof null, objectSize(null), objectSize({ size: 2 }));
// function wrongCase(value: string | number) { return typeof value === "String"; } // TS2367
// function unguarded(value: string | number) { return value.toFixed(2); } // TS2339
```

The output is `HELLO 3.14`, `OK`, then `object 0 2`. The checks permit only the operations justified at that point. An array is also an object at runtime; the string `"object"` alone does not validate an arbitrary object's fields.

`instanceof` normally checks a constructor's prototype in the value's prototype chain. It narrows class unions, but structural compatibility is not a guarantee of prototype membership. Save as `instances.ts`.

```typescript
class Dog { bark(): string { return "woof"; } }
class Cat { meow(): string { return "meow"; } }
type Pet = Dog | Cat;
function speak(pet: Pet): string {
  if (pet instanceof Dog) return pet.bark();
  return pet.meow();
}
console.log(speak(new Dog()), speak(new Cat()));
const structuralDog: Dog = { bark: () => "structural woof" }; // No cast needed.
console.log(structuralDog instanceof Dog);
try {
  console.log(speak(structuralDog)); // Accepted, but the runtime false branch calls meow.
} catch (error) {
  console.log(error instanceof TypeError ? "prototype mismatch: TypeError" : "unexpected error");
}
function speakByCapability(pet: Pet): string {
  if ("bark" in pet) return pet.bark();
  return pet.meow();
}
console.log(speakByCapability(structuralDog));
interface DogShape { bark(): string }
// function erased(value: object) { return value instanceof DogShape; } // TS2693
```

The output is `woof meow`, `false`, `prototype mismatch: TypeError`, then `structural woof`. Use the prototype check when the producer contract actually supplies instances. If compatible plain objects are legitimate inputs, capability checks or an explicit tagged representation can better match that contract. The capability example works for the shown declared union; checking one property on unknown input would not validate the whole `Pet` contract.

Interfaces and type aliases erase, so they supply no constructor for `instanceof`. Broader limits, including modified prototype chains and custom `Symbol.hasInstance`, belong to [class type/value duality](<../../../06 Classes and Object-Oriented Types/sections/1. Class Type Fundamentals/1.1. Class as type and value duality instance vs constructor.md>), rather than a universal promise that `instanceof` validates every structural value.

### 2) **in and property checks**

`"items" in value` asks whether the property exists on the object or its prototype chain. For a declared union it can retain the alternatives having that required or optional key. An optional-key alternative may remain in both branches, because its property can be absent. A required shared key does not distinguish alternatives. These are the [documented in-narrowing rules](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#the-in-operator-narrowing).

Save as `presence.ts`.

```typescript
export {};
type WithItems = { items: string[] };
type WithText = { text: string };
function count(value: WithItems | WithText): number {
  return "items" in value ? value.items.length : value.text.length;
}
class InheritedItems { get items(): string[] { return ["a", "b"]; } }
const inherited: WithItems = new InheritedItems();
console.log(count(inherited), "items" in inherited, Object.hasOwn(inherited, "items"));
console.log(count({ text: "hello" }));

type Required = { item: string; required: true };
type Optional = { item?: string; optional: true };
type Missing = { other: string };
function inspect(value: Required | Optional | Missing): string {
  if ("item" in value) {
    const present: string = value.item; // exactOptionalPropertyTypes excludes present undefined.
    // const onlyRequired: Required = value; // TS2322: Optional remains possible
    return `present ${present}`;
  }
  // const onlyMissing: Missing = value; // TS2322: Optional remains possible here too
  return "item absent";
}
console.log(inspect({ item: "x", optional: true }), inspect({ optional: true }));

type Shared = { common: string; a: number } | { common: string; b: number };
function shared(value: Shared): string {
  if ("common" in value) {
    // return value.a.toFixed(); // TS2339: both alternatives have common
    return value.common;
  }
  return "unreachable for the declared contract";
}
console.log(shared({ common: "same", b: 2 }));
```

The output is `2 true false`, `5`, `present x item absent`, then `same`. The inherited getter satisfies the member contract even though it is not an own property. A false own-property test would not classify that value as the text alternative. `Object.hasOwn` also returns a boolean without automatically narrowing this object union on the declared compiler; see [object-shape narrowing](<../../../04 Objects Interfaces and Type Aliases/sections/3. Advanced Object Types/3.3. satisfies assertions and narrowing on object shapes.md>) for that worked contrast.

Recompile `presence.ts` with `--noEmit` and **omit `--exactOptionalPropertyTypes`**: TS2322 rejects `present`, because `item?: string` can then be present with `undefined`. A declaration `item?: string | undefined` requires a value check even with the flag enabled. Optional alternatives remaining in both branches is separate from whether a present value can be undefined.

For unknown input, presence supplies only a property with an unknown value. Check that value before using string methods. Save as `unknown.ts`.

```typescript
function readName(value: unknown): string | undefined {
  if (typeof value !== "object" || value === null) return undefined;
  if (!("name" in value)) return undefined;
  const raw: unknown = value.name;
  // const unchecked: string = value.name; // TS2322: presence does not prove a string
  return typeof raw === "string" ? raw.toUpperCase() : undefined;
}
console.log(readName({ name: "Ada" }), readName({ name: 42 }), readName(null));
class Named { get name(): string { return "inherited"; } }
console.log(readName(new Named()));
// function primitive(value: string) { return "name" in value; } // TS2322
```

The output is `ADA undefined undefined`, then `INHERITED`. This function deliberately accepts inherited names. If the input format requires an own field, add that policy and retain the value check. It validates only a readable string name; it does not prove an account identity or harden property access against arbitrary getters/proxies. [TypeScript 4.9](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-4-9.html#unlisted-property-narrowing-with-the-in-operator) documents the unlisted-property narrowing used here.

### 3) **Equality and truthiness**

A nullish check preserves zero and empty strings. Truthiness excludes them as well as nullish values. Choose the condition from the accepted-data policy, and make a failure observable rather than comparing two implementations that both happen to return zero.

Save as `equality.ts`.

```typescript
function display(value: string | null | undefined): string {
  if (value != null) return `text:${value.length}`;
  return "missing";
}
function truthyDisplay(value: string | null | undefined): string {
  return value ? `text:${value.length}` : "missing";
}
console.log(display(""), truthyDisplay(""), display(null), display(undefined));
function metric(value: number | null | undefined): string {
  return value !== null && value !== undefined ? `metric:${value}` : "missing";
}
function truthyMetric(value: number | null | undefined): string {
  return value ? `metric:${value}` : "missing";
}
console.log(metric(0), truthyMetric(0));
console.log(metric(NaN), truthyMetric(NaN), Number.isFinite(NaN));

type Result = { ok: true; value: number } | { ok: false; error: string };
function show(result: Result): string {
  if (result.ok) return `ok:${result.value}`; // Valid boolean-literal discriminant narrowing.
  return `error:${result.error}`;
}
console.log(show({ ok: true, value: 0 }), show({ ok: false, error: "offline" }));
function equalValues(left: string | number, right: string | boolean): string {
  if (left === right) return left.toUpperCase(); // Their only common category is string.
  return "different";
}
console.log(equalValues("a", "a"), equalValues(1, true));
// function nullOnly(value: string | null | undefined) { if (value !== null) return value.length; } // TS18048
```

The lines are `text:0 missing missing missing`, `metric:0 missing`, `metric:NaN missing false`, `ok:0 error:offline`, and `A different`. The nullish check admits `NaN`; use an additional numeric policy such as `Number.isFinite` if a metric must be finite. Truthiness is not a finite-number validator either. Zero, negative zero, `NaN`, empty strings, false, zero bigint, null and undefined are falsy in these ordinary Node examples. The unusual browser `document.all` behavior is outside this runtime example.

`value != null` and the strict pair remove both null and undefined for the demonstrated ordinary values. `value !== null` alone leaves undefined when it is in the declared type. Boolean-literal tags can use `if (result.ok)` successfully; the payload's zero does not alter that tag. [Discriminated unions](<../1. Union Types/1.2. Discriminated unions the tagged pattern that scales.md>) develops the representation choice.

### 4) **Common confusion**

Narrowing refines information at a program point; it does not replace the runtime object or validate unrelated fields. `typeof value === "object"` includes null, an `in` test includes inherited properties, and `instanceof` asks about prototype membership. Different answers are expected when those operations ask different questions.

A shared required key supplies no exclusive branch evidence. An optional key can still provide useful information, but its absence does not establish a different alternative. The correct follow-up may be checking the member's value, rather than forcing a branch with an assertion.

### 5) **Performance note**

Annotations erase; the chosen conditions remain in JavaScript. Getter-backed property reads and custom `Symbol.hasInstance` can run application code, so guards are not universally interchangeable constant-cost operations. These examples compare semantics and do not benchmark `typeof`, `in`, equality or prototype tests. Select the required check first; investigate measured hot paths separately instead of claiming a universally faster narrowing style.

### 6) **Mentor note**

Ask what evidence each condition supplies before asking which branch TypeScript selects. Have the learner predict all three results for `inherited`: count, prototype-aware presence and own presence. Then replace `Required` with `Optional` and require an explanation of both branches, including the exact-optional flag's effect on a present value.

For an exercise, accept `number | null | undefined`, preserve zero, reject absent values and reject non-finite numbers. A sound implementation first removes nullish values, then checks `Number.isFinite`, and formats the remaining number. Verify zero, a positive value, null, undefined, `NaN` and infinity; truthiness alone fails that contract.
