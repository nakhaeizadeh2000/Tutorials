## 7.1. Boundaries — what is covered elsewhere

### 1) **Object-type composition details** (freshness, `readonly`/optional, declaration merging)

**Definition** — [04 Objects, Interfaces and Type Aliases](<../../../04 Objects Interfaces and Type Aliases/README.md>) owns the static object-type model — this domain uses it via `&`/`|`, not deep inside it.

- **What belongs in 04, not here** — width/depth subtyping and excess-property freshness (fresh literal vs alias), optional `prop?: T` vs `prop: T | undefined` with `exactOptionalPropertyTypes`, `readonly` vs `Object.freeze`, index signatures vs `Record`/`Map`, `interface extends` vs `type &` composition, declaration merging and `declare global` augmentation — this domain treats `object types` as inputs to `|`/`&` and narrowing.
- **What lives here instead** — `&` distribution over unions, the `never` trap from conflicting keys, impossible-state modeling, and the choice of `&` vs `|` as "both vs either."
- **Handoff example (belongs in 04)** — `interface Audit { createdAt: Date }` and its merging behavior — owned by 04; `type Audited<T> = T & Audit` (the union-aware use) belongs here.
- **Link** — object fundamentals, optional/readonly, index signatures → [04 1.2. Optional readonly](<../../../04 Objects Interfaces and Type Aliases/sections/1. Object Type Fundamentals/1.2. ### 2) **Function-level variance and callable overloads** (contravariance, overloads vs unions on params)

**Definition** — [05 Functions and Callable Types](<../../../05 Functions and Callable Types/README.md>) owns callability — parameter contravariance, overloads, `this` typing, predicates at the callable boundary.

- **What belongs in 05, not here** — `strictFunctionTypes` contravariance for function parameters, method bivariance, `this: void` / `this` parameter, overload signatures vs union-on-param pattern (`fn(x: A|B)` vs two overloads), and call signatures as callable objects.
- **What lives here instead** — predicates/assertions *consumed at* `|`/`&` call sites (`if (isCircle(shape))` narrows `Shape | Square`) — this domain treats `x is T` as the bridge to narrow unions; `05` owns writing the predicate type itself at the callable boundary.
- **Handoff example (belongs in 05)** — `type Handler = { (x: Dog): void } & { (x: Cat): void }` — an overload-shaped type (see [05 2.1](<../../../05 Functions and Callable Types/sections/2. Overloads and Generics/2.1. Function overloads call signatures and implementation compatibility.md>)); this domain's predicate `isDog(x: Animal): x is Dog` enabling `if (isDog(a)) …` lives here.

### 3) **Class hierarchies as union alternatives** (`extends`/`implements`/`abstract` vs discriminated unions)

**Definition** — [06 Classes and Object-Oriented Types](<../../../06 Classes and Object-Oriented Types/README.md>) owns the blueprint as both type and value — `extends`, `implements`, `abstract`, `override`, `InstanceType`.

- **What belongs in 06, not here** — class instance vs static sides, constructors and parameter properties, `private`/`protected`/`readonly` and `#private` erasure, `extends` vs `implements` structural-check tradeoff, `abstract` with shared runtime logic, `override` and polymorphic `this`, mixins and static blocks — this domain does not repeat `instanceof` mechanics; it notes them as a class-backed narrowing alongside discriminant `switch`.
- **What lives here instead** — the choice rule "data-shaped variation via union (`Event = Click|Key`) vs behavior-shaped variation via class hierarchy (`abstract class Event`)"; this domain's leaning is union-first for data merging (serializable, branch-wise exhaustiveness).
- **Handoff example (belongs in 06)** — `abstract class Shape { abstract area(): number }` and its `abstract new` factory — owned by 06; `type Shape = Circle | Square` and its `switch(kind)` belongs here.
- **Link** — class duality and instance vs constructor → [06 1.1 Class as type and value duality](<../../../06 Classes and Object-Oriented Types/sections/1. Class Type Fundamentals/1.1. Class as type and value duality instance vs constructor.md>); inheritance and abstract → [06 2. Inheritance and Polymorphism](<../../../06 Classes and Object-Oriented Types/sections/2. ### 4) **Generics, conditional types, and mapped types over unions** (distributive `T extends U ? …` and `keyof` filtering)

**Definition** — [08 Generics Deep Dive](<../../../08 Generics Deep Dive/README.md>) and [09 Utility Types and Type Transformations](<../../../09 Utility Types and Type Transformations/README.md>) own type-level functions — how a generic's `T` distributes, how `infer` extracts, how mapped types iterate keys — unions are the inputs they transform.

- **What belongs in 08/09, not here** — conditional type distribution on union `T`, variance markers `in`/`out`, `infer` positions, recursive mapped types, template literal propagation over union members, `ReturnType`/`InstanceType` construction over unions — this domain notes them as the deep dive, not this domain's everyday use.
- **What lives here instead** — `Exclude<Union, Member>` / `Extract<Union, Member>` as the everyday read-only filtering of a union — forwarded as the idiomatically literate alternative to `&` literal filters — full type-level filtering lives in 09.
- **Handoff example (belongs in 09)** — `type ToArray<T extends string> = T extends "a" ? ["a"] : never` distributes over a union argument — owned by 08/09; `type NonGuest = Exclude<Role, "guest">` filtering with no authoring of distribution lives here.
- **Link** — generics (constraints, defaults, scope on unions) → [08 Generics Deep Dive](<../../../08 Generics Deep Dive/README.md>) (textual forward until that domain lands); utility transformation, template literal expansion → [09 Utility Types and Type Transformations](<../../../09 Utility Types and Type Transformations/README.md>) (textual forward).

### 5) **Compiler strictness flags** (`strictNullChecks`, `noImplicitAny`, `--strict`) — textual forward

**Definition** — [13 Configuration and Compiler Options](<../../../13 Configuration and Compiler Options/README.md>) owns the compiler flags layer — how `strictNullChecks` reifies `T | null` as a checked branch and how `strictFunctionTypes` tightens `T => void` contravariance.

- **What belongs in 13, not here** — enabling `--strict`, `strictNullChecks`, `exactOptionalPropertyTypes`, `useUnknownInCatchVariables`, `noUnusedLocals`, `erasableSyntaxOnly` (TS 5.8+) and when each flag toggles the union/intersection design — e.g., why `Config.port?: number` vs `Config.port: number | undefined` differs under `exactOptionalPropertyTypes`.
- **What lives here instead** — how `strictNullChecks` makes `T | null` and `T | undefined` the checked contract (checked absent vs incidental absent), how `exactOptionalPropertyTypes` distinguishes missing vs `undefined`, and how `erasableSyntaxOnly` confirms every `|`/`&` syntax is erasable — runtime flags vs call-site invariants.
- **Handoff example (belongs in 13)** — enabling `--strict` in `tsconfig.json` — owned by 13; consuming the resulting `strictNullChecks` guarantee `if (value !== null) value.length` belongs here.
- **Link** — running TS today and erasable inventory → [03 3.3 Choosing erasable syntax](<../../../01 Fundamentals and Mental Model/sections/3. Running TypeScript today/3.3. Choosing erasable syntax the zero-cost interop rule.md>); async stdlib and `Awaited` filtering → [18 Async Types and Standard Library] (textual forward); testing unions vs distribution → [17 Testing Types] (textual forward).
