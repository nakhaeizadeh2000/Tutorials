## 7.1. Boundaries — what is covered elsewhere

A union describes alternatives and an intersection requires a value to meet several contracts. This domain teaches how to model those choices, narrow a value along a branch and detect an unhandled variant. Neighboring domains explain the object members, callable signatures, class construction, type transformations and compiler settings used by those models.

Use the failing operation to choose the next explanation. A missing object member, a callback assignment and an unhandled union variant can appear in one program, but they require different evidence. These routes refer to published owners; a working link does not establish that every example in a linked lesson has been reverified.

### 1) **Object-type composition details**

Start with [object shapes and freshness](<../../../04 Objects Interfaces and Type Aliases/sections/1. Object Type Fundamentals/1.1. Object types structural shape and excess property checks.md>) when an initializer has missing members or a written extra property. Use [optional, readonly and index contracts](<../../../04 Objects Interfaces and Type Aliases/sections/1. Object Type Fundamentals/1.2. Optional readonly and index signatures.md>) to distinguish a missing property, an undefined value and a read-only view. None of those questions is answered merely by adding another union member.

For object parents, [intersection versus extends](<../../../04 Objects Interfaces and Type Aliases/sections/2. Composition and Declaration Merging/2.1. Intersection vs extends composing object types.md>) explains member conflicts and diagnostic locations. [Declaration merging](<../../../04 Objects Interfaces and Type Aliases/sections/2. Composition and Declaration Merging/2.2. Declaration merging and module augmentation.md>) owns multiple declarations of one name; [object queries](<../../../04 Objects Interfaces and Type Aliases/sections/2. Composition and Declaration Merging/2.3. Type queries on objects keyof indexed access and typeof capture.md>) owns capturing keys and member types. They are separate operations even when an editor displays similar resulting shapes.

Return here for the consequence of requiring both contracts or choosing between alternatives. An audit record combined with a click event is an intersection; choosing a click event or key event is a union. The object owner establishes each member contract, while this domain explains how the alternatives interact.

### 2) **Function-level variance and callable overloads**

A function accepting a union input and an overload set exposing separate inputs have different caller contracts. [Overloads](<../../../05 Functions and Callable Types/sections/2. Overloads and Generics/2.1. Function overloads call signatures and implementation compatibility.md>) owns that signature comparison and its implementation requirements. [Callback variance](<../../../05 Functions and Callable Types/sections/3. Advanced Callable Patterns/3.2. Callback variance strictFunctionTypes and bivariance pitfalls.md>) owns callback substitution; [receiver typing](<../../../05 Functions and Callable Types/sections/3. Advanced Callable Patterns/3.1. this parameter explicit typing and arrow vs function capture.md>) owns a callable's this contract.

This domain follows the value after a branch has selected an alternative. Use [custom narrowers on unions](<../3. Control Flow Narrowing/3.3. Custom narrowers predicates asserts and type guards on unions.md>) to examine what callers can use after a predicate or assertion. Check the implementation as well as its declared narrowing result: a signature does not replace runtime evidence. The first [static-versus-runtime boundary example](<../../../01 Fundamentals and Mental Model/sections/2. How TypeScript doesnt execute/2.2. Static checking vs runtime reality trust but verify.md>) demonstrates that distinction with malformed inputs.

### 3) **Class hierarchies as union alternatives**

Use [class type/value duality](<../../../06 Classes and Object-Oriented Types/sections/1. Class Type Fundamentals/1.1. Class as type and value duality instance vs constructor.md>) when a type name, constructor value or instance is being confused. [Inheritance and structural compatibility](<../../../06 Classes and Object-Oriented Types/sections/2. Inheritance and Polymorphism/2.1. Extends implements and structural class compatibility.md>) and [abstract classes](<../../../06 Classes and Object-Oriented Types/sections/2. Inheritance and Polymorphism/2.2. Abstract classes and members when abstract beats interface.md>) own constructing related objects and sharing behavior. Runtime method invocation belongs in the [JavaScript receiver rules](<../../../../JavaScript/05 Functions Deep Dive/sections/3. this binding/3.1. Call-site rules default implicit explicit new and strict mode.md>).

A discriminated union is useful when consumers must select among explicitly described data variants. An abstract class is useful when instances share implemented behavior and construction matters. Choose from the actual consumer operation rather than a rule that every hierarchy should become a union. A plain object with a kind field does not thereby become a class instance; a type-only union does not construct or serialize a value. Return here for [discriminated-union modeling](<../1. Union Types/1.2. Discriminated unions the tagged pattern that scales.md>) and branch exhaustiveness.

### 4) **Generics and transformations over unions**

[Generic scope and inference](<../../../08 Generics Deep Dive/sections/1. Generic Fundamentals/1.2. Inference from arguments and explicit type arguments.md>) explains how a type argument is selected and when a competing input needs NoInfer. The [infer and distribution preview](<../../../08 Generics Deep Dive/sections/2. Constraints Defaults and Inference Control/2.3. infer conditional inference and distributive preview.md>) introduces type-level extraction. [Conditional transforms](<../../../09 Utility Types and Type Transformations/sections/2. Conditional Types/2.1. Conditional fundamentals distributive law and never branches.md>) develops the distribution rule; [Exclude and Extract](<../../../09 Utility Types and Type Transformations/sections/2. Conditional Types/2.2. Exclude Extract NonNullable Pick Omit under the hood.md>) owns selecting the matching library utility.

Using Extract to name a click variant operates on types. An if or switch examining a value's kind operates on runtime control flow and can narrow that value. A filtered type does not execute the check that establishes an external value's variant. Model the alternatives, choose a transformation if one is needed, then inspect the actual control flow that permits member access. Avoid copying a complete conditional-type lesson into each union example.

### 5) **Compiler strictness and diagnosis**

Use the [configuration domain](<../../../13 Configuration and Compiler Options/README.md>) to choose and understand compiler options. [Index and exact optionality options](<../../../13 Configuration and Compiler Options/sections/3. Modules Emit and Projects/3.3. noUncheckedIndexedAccess and exactOptionalPropertyTypes.md>) owns settings for index absence and optional property presence. This domain explains the value-level branch needed once an operation has a nullable or alternative result. An option is checking configuration, rather than a runtime check inserted into that branch.

The [bounded erasable-toolchain lesson](<../../../13 Configuration and Compiler Options/sections/2. Erasable and Isolated Toolchain/2.3. erasableSyntaxOnly and the trio standard.md>) separates syntax checking from source/output resolution. For current configuration and compiler-interface changes, use the [TypeScript 7 learning route](<../../../25 Update TypeScript 7.0/sections/6. Overlaps and Update Route/6.1. Overlaps and the current learning route.md>). Those checks do not establish the validity of external data.

Practice the handoff with three cases. A fresh object has a misspelled field: inspect the object initializer and its target shape. A switch fails at its final never assignment after a variant is added: inspect this domain's [exhaustiveness owner](<../3. Control Flow Narrowing/3.2. Exhaustiveness never and switch narrowing.md>). An explicit type argument still lets malformed JSON reach a field operation: follow the decoder and its runtime checks, starting with [unknown boundaries](<../../../03 Basic Types and Annotations/sections/2. The Special Types/2.2. unknown the type-safe top type.md>). Naming the failed operation is more useful than sending every case to strict configuration.

### 6) **Common confusion**

A union of data alternatives, several overload signatures and a hierarchy of constructor values solve different problems. Distribution transforms a type; it does not narrow a live value or validate parsed JSON. Declaration merging combines compatible declarations of one name; an intersection creates a requirement involving both operand types. When two explanations seem interchangeable, ask what operation the reader is performing and what evidence would make it safe.

### 7) **Performance note**

Choosing the right documentation owner has no direct runtime effect. Union and transformation annotations are erased, while the program's branch checks, parsing and object construction still execute. No checker/editor or runtime comparison was measured for this routing lesson. Use the [measurement workflow](<../../../19 Performance Project References and Scaling/sections/1. Check-Time Performance/1.1. Measuring with extendedDiagnostics and traces.md>) to investigate a real slow workload; do not infer a speed improvement from splitting documentation or renaming a type.

### 8) **Mentor note**

Have the learner choose an owner for each of the three cases above and state the next observation to make. A useful answer identifies the initializer/target pair, the remaining variant at the never assignment, or the missing runtime decoder check. Then ask whether replacing a branch with Extract executes validation: it does not. Assess their explanation of the operation and evidence, rather than how many domain numbers they can recall.
