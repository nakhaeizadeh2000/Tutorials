## 1.1. allowJs, checkJs and JSDoc Migration

### 1) **Path** (JS → JSDoc → TS)

**Path** — Incremental migration without big-bang rewrite:

1. `allowJs: true` + `checkJs: true` (or `// @ts-check` per file) — checker inspects `.js` via type inference + JSDoc.
2. Add `// @ts-check` + `/** @type {import("./types").User} */` JSDoc where it pays off (hot modules first).
3. Rename one file at a time `.js` → `.ts` (or `.js` stays but `checkJs` keeps guard), then enable `strict` package-by-package.

```jsonc
// tsconfig for incremental JS+TS
{
  "compilerOptions": {
    "allowJs": true,
    "checkJs": true,
    "strict": true,
    "noEmit": true
  },
  "include": ["src"]
}
```

```javascript
// src/utils.js — before TS, with JSDoc
// @ts-check
/**
 * @param {{ id: string; name: string }} user
 * @returns {string}
 */
function greet(user) {
  return `Hi ${user.name}`;
}
// @ts-expect-error demo: greet({ name: "hi" }); // error — id missing (checked via JSDoc)

// src/utils.ts — after rename, same logic becomes checked without JSDoc noise
export function greetTS(user: { id: string; name: string }): string {
  return `Hi ${user.name}`;
}
```

### 2) **Example** (// @ts-check)

```javascript
// src/api.js
// @ts-check
import { z } from "zod";

/** @type {import("zod").z.ZodType<{ id: string; name: string }>} */
const UserSchema = z.object({ id: z.string(), name: z.string() });

/**
 * @param {unknown} raw
 * @returns {{ id: string; name: string }}
 */
export function parseUser(raw) {
  return UserSchema.parse(raw); // checked via JSDoc type of UserSchema
}
// rename to .ts later: z.infer<typeof UserSchema> provides same type without JSDoc
```

Gradual file rename:

```bash
# pick hottest/most-buggy file first
git mv src/api.js src/api.ts
#fix types, then: npm run typecheck (incremental)
```

### 3) **Bad** (big-bang rewrite)

**Bad — big-bang rewrite blocks delivery:**

- Renaming entire `src` at once → thousands of errors, PR impossible to review, merge conflicts for weeks.
- Turning off `checkJs` — .js files become invisible; bugs remain during transition.
- Ignoring `allowJs` boundary — importing `.ts` from `.js` without checker path still misses errors.

Better: separate `tsconfig.migration.json` (allowJs) vs `tsconfig.json` (strict) per package, tighten over weeks.

```typescript
// bad tsconfig for migration — never checking js
{
  "compilerOptions": { "allowJs": false } // js ignored
}
// good: check js while migrating
{
  "compilerOptions": { "allowJs": true, "checkJs": true, "strict": true }
}

// bad: // @ts-ignore file wide
// good: // @ts-expect-error with reason per line, or @ts-check + JSDoc
```

### Mentor note

Pick one module that caused the last outage — JSDoc → TS that file. Quick win sells the migration more than a roadmap deck.

### Common confusion

- "`allowJs` compiles JS" — it only allows checking; emit still depends on `transpileModule` / bundler.

### Performance note

`checkJs` adds checker time proportional to JS size — temporary cost; drops once files become `.ts`.
