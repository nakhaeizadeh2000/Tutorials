## 1.2. any, unknown and Gradual Typing

### 1) **Definition** (unknown)

**Definition** — `unknown` is the safe counterpart to `any`:

- `any` — disables checking entirely (both accepts any value *and* allows any operation). Escape hatch that defeats the checker.
- `unknown` — the *checked* top type: accepts any value *but* you must narrow before you can use it. Prefer `unknown` at boundaries.
- `never` — the empty type (no value). `unknown` → any value, `never` → no value.

```typescript
let a: any = "hi";
a.toExponential(); // ok — no check (wrong, but compiles) — runtime error

let u: unknown = "hi";
// u.toExponential(); // error — must narrow
if (typeof u === "string") console.log(u.toUpperCase()); // ok after narrowing

function handle(value: unknown): void {
  if (typeof value === "string") value.slice(1); // string branch
  else if (Array.isArray(value)) value.length; // array branch
  else throw new Error("unsupported");
}

// gradual example: legacy JS interop typed as unknown at boundary
declare function legacyFetch(): unknown;
let raw = legacyFetch();
if (typeof raw === "object" && raw !== null && "id" in raw) {
  console.log((raw as { id: string }).id);
}
```

### 2) **Example** (unknown guard)

```typescript
// boundary parser: unknown → precise
type User = { id: string; email: string };
function isUser(v: unknown): v is User {
  return typeof v === "object" && v !== null && "id" in v && "email" in v &&
         typeof (v as Record<string, unknown>).id === "string";
}

function process(payload: unknown): void {
  if (!isUser(payload)) throw new Error("invalid user");
  console.log(payload.email); // User
}

// generic helper: unknown still flows through generics safely
function jsonParse(json: string): unknown {
  return JSON.parse(json);
}
let parsed = jsonParse(`{"id":"1","email":"a@b.com"}`);
if (isUser(parsed)) console.log(parsed.email);

// contrast any catch (before TS 4.4 any, after unknown):
try { JSON.parse("..."); } catch (e: unknown) {
  // e is unknown — must check before e.message
  if (e instanceof Error) console.log(e.message);
}
```

Enforce via `no-explicit-any` lint (see [09 1.1](<../../../09%20Tooling%20ESLint%20Biome%20and%20Type-Level%20Testing/sections/1.%20Lint%20and%20Format/1.1.%20ESLint%20+%20typescript-eslint%20vs%20Biome.md>)).

### 3) **Mistake** (any as escape hatch)

**Common mistakes:**

- Casting `unknown` → `as` immediately (`JSON.parse(s) as User`) — defeats `unknown` purpose; validate first.
- Using `any[]` for "array with some missing typing" — use `unknown[]` + narrow per element.
- `any` in library public return type — contaminates consumers (they inherit `any`).

```typescript
// bad: any escape at boundary
type Config = { apiUrl: string };
let cfgBad: Config = JSON.parse(process.env.CONFIG as string) as Config; // lies

// good: unknown + validate (see 10 2.1 for Zod)
import { z } from "zod";
const ConfigSchema = z.object({ apiUrl: z.string().url() });
type ConfigGood = z.infer<typeof ConfigSchema>;
let cfgGood: ConfigGood = ConfigSchema.parse(JSON.parse(process.env.CONFIG as string));

// bad: any array
function sumBad(arr: any[]): number { return arr.reduce((s, x) => s + x, 0); }
// good: unknown array with narrow
function sumGood(arr: unknown[]): number {
  return arr.filter((x): x is number => typeof x === "number").reduce((s, x) => s + x, 0);
}
```

### Mentor note

Ban `any` via `typescript-eslint` `no-explicit-any`. In migration, replace `any` with `unknown` first — temporary but safe; then narrow.

### Common confusion

- "`unknown` is like `any` but safer" — correct, but you still must narrow.

### Performance note

Neither affects emit — both erased. But `any` hides bugs that cost runtime defensive code.
