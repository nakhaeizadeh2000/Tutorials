## 2.2. CJS/ESM Interop and Typing External Libs

### 1) **Problem** (interop)

**Problem** — Node/CJS vs ESM boundary: `require` is synchronous + dynamic; `import` static; CJS modules may export `module.exports = fn` or `exports.foo = ...` — mismatch yields `undefined` default.

```typescript
// CJS lib (legacy): module.exports = function greet(name){ return "hi "+name; }
// ESM consumer without esModuleInterop:
// import greet from "legacy"; // greet is undefined (legacy exported = fn, not default)
// ESM consumer with esModuleInterop: import greet from "legacy"; // ok (helper wraps)

// named re-exports differ
// CJS: exports.foo = "bar"
// ESM: import { foo } from "legacy" // works, import foo from "legacy" is undefined without wrapper
```

Also external libs without types (`legacy-lib` plain JS) — need `declare module` or `@types/*`.

---

### 2) **Fix** (esModuleInterop)

**Fix — align `esModuleInterop` + `allowSyntheticDefaultImports`:**

```jsonc
{
  "compilerOptions": { "esModuleInterop": true, "allowSyntheticDefaultImports": true, "moduleResolution": "nodenext" }
}
// then:
import express from "express"; // CJS lib with default wrapper — ok
import * as express2 from "express"; // also ok (namespace)
```

Mapping:

| Lib style | Recommended import (with interop true) |
|-----------|----------------------------------------|
| `module.exports = fn` (default export) | `import fn from "lib"` |
| `exports.foo =` | `import { foo } from "lib"` or `import * as lib from "lib"` |
| untyped JS | add `@types/lib` or `declare module "lib"` shim |

```typescript
// typing external CJS ESM bridge: dynamic import for ESM-only packages (Node >=18)
async function loadCJS(): Promise<void> {
  // ESM packages may only be imported via dynamic import when using CJS emit
  const { default: got } = await import("got"); // ESM-only in recent major
}

// typing external lib without types — local ambient
declare module "legacy-lib" {
  export function helper(x: number): string;
}
import { helper } from "legacy-lib"; // now typed
```

### 3) **Link** (to TSNode track)

JS engine runtime semantics for CJS/ESM split (host resolution, `createRequire`, `.mjs`/`.cjs` shims) lives in TSNode track:

- Runtime deep → [TSNode track](<../../../TSNode/README.md>) — loaders, `esm` hooks, `tsx` vs `ts-node` runtime choice.
- Module resolution config → [07 1.1 ESM](<../../../07%20Modules%20Namespaces%20and%20Declaration%20Files/sections/1.%20Modules%20and%20Resolution/1.1.%20ESM%20vs%20CommonJS%20and%20Module%20Resolution%20node16%20bundler.md>).

**Common confusion** —

- "`allowSyntheticDefaultImports` fixes runtime" — no, it only suppresses checker error; `esModuleInterop` emits helper for runtime.

**Performance note** — Types are erased (zero emit); checker cost dominates. For this feature, keep types shallow and measure `tsc --extendedDiagnostics` if checker slows.

**Mentor note** —

Add `esModuleInterop: true` to every new project; migrating older projects: grep `import * as X from "x"` where `import X` now appropriate — codemod fixes.

**Cross-links:** `esModuleInterop` emit helper `__importDefault` — cost minimal, ensures default interop consistent.
