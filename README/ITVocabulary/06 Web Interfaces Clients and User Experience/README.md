# Web Interfaces Clients and User Experience

Identify the client artifacts and user-facing qualities behind web descriptions. Read Software Execution and Developer Tools and Networks and the Internet first. No frontend framework or prior UI course is required; examples introduce their own platform assumptions and distinguish inspected artifacts from executed behavior.

This domain is in progress: 6 of 9 approved lessons are available.

## 1. Client and server responsibilities

### [1.1. Websites web apps frontend backend and full stack](<sections/1. Client and server responsibilities/1.1. Websites web apps frontend backend and full stack.md>)

1. **Distinguish a web experience from the roles serving it:** interpret website, web app, client and server without enforcing an artificial site/app boundary.
2. **Separate frontend and backend responsibilities from deployment boxes:** trace an example feature across browser interaction and server policy without assuming language or repository placement defines the layer.
3. **Read full-stack and ownership claims as scoped work:** classify a fictional feature failure and request evidence instead of assigning blame from the visible symptom.

## 2. Browser building blocks

### [2.1. HTML CSS DOM JavaScript and browser APIs](<sections/2. Browser building blocks/2.1. HTML CSS DOM JavaScript and browser APIs.md>)

1. **Identify the roles of the browser building blocks:** distinguish HTML structure, CSS presentation, JavaScript behavior, the live DOM and browser-provided interfaces.
2. **Trace a complete source-to-document change:** run a small page and explain its button action, style change and reload without treating DOM edits as saved-file changes.
3. **Attribute behavior and failures to the right capability:** reason through missing styles or scripts and separate language support from host API support.

### [2.2. Rendering navigation CSR SSR SSG and hydration](<sections/2. Browser building blocks/2.2. Rendering navigation CSR SSR SSG and hydration.md>)

1. **Separate content generation from browser display and navigation:** interpret rendering, document changes, SPA and MPA without equating navigation style with the initial content producer.
2. **Locate CSR SSR and SSG on a content timeline:** classify constructed request/build/browser paths and identify what an HTML response alone cannot prove.
3. **Distinguish hydration from content visibility and later updates:** reason about initialization, mismatch and visible-but-inactive controls without assuming a framework-specific guarantee.

## 3. Client platforms and state

### [3.1. Web native hybrid desktop mobile and PWA](<sections/3. Client platforms and state/3.1. Web native hybrid desktop mobile and PWA.md>)

1. **Separate device targets from application implementation:** interpret web, desktop, mobile, native and cross-platform along distinct dimensions.
2. **Recognize web containers and progressive web apps:** distinguish WebViews, hybrid containers, PWA installation and scoped offline/background capabilities.
3. **Read a capability claim as a testable product contract:** rewrite a constructed works-everywhere claim using target environments, checked tasks and useful fallbacks.

### [3.2. Cookies browser storage sessions and local state](<sections/3. Client platforms and state/3.2. Cookies browser storage sessions and local state.md>)

1. **Separate application state from its storage mechanism:** distinguish memory, Web Storage, IndexedDB and cookies by scope and persistence without assuming local data is a server record.
2. **Read cookie and session lifetimes separately:** interpret cookie attributes and partitioning while distinguishing page sessions, cookie lifetimes and application-session validity.
3. **Diagnose a constructed state-loss report:** trace view reset, draft restore and session rejection to separate evidence and revise the diagnosis when the evidence changes.

## 4. Experience and inclusion

### [4.1. UI UX usability accessibility and responsive design](<sections/4. Experience and inclusion/4.1. UI UX usability accessibility and responsive design.md>)

1. **Distinguish the interface from the experience and task success:** interpret UI, UX and usability through users, goals, feedback and task evidence.
2. **Recognize accessibility barriers and the scope of standards:** identify keyboard, naming and assistive-technology concerns while reading WCAG and evaluation claims with explicit limits.
3. **Separate responsive layout from usable interaction:** classify a constructed viewport, keyboard and confirmation report without treating a screenshot or scan as complete workflow evidence.
