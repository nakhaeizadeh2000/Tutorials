# Integration Expert Reading and Mentor Practice

Integrate the preceding vocabulary in unfamiliar artifacts, conflicting evidence and teaching situations. These constructed reading exercises assess defensible reasoning and communication; they do not establish implementation mastery.

This domain is complete: all 7 approved lessons are available.

## 1. Cross-domain artifact reading

### [1.1. Annotate an unfamiliar architecture proposal](<sections/1. Cross-domain artifact reading/1.1. Annotate an unfamiliar architecture proposal.md>)

1. **Read purpose and boundaries before guarantees:** identify actors element types interactions and evidence status
2. **Annotate a cross-domain proposal:** trace identity compute data messaging and operations without inventing behavior
3. **Prioritize review questions:** choose missing evidence that matters to the intended user outcome

### [1.2. Explain a change request and release narrative](<sections/1. Cross-domain artifact reading/1.2. Explain a change request and release narrative.md>)

1. **Trace a requirement into a consumer-visible change:** connect scope dependencies and compatibility to actual artifacts
2. **Separate delivery and recovery evidence:** distinguish built deployed enabled and reversible states
3. **Write two accurate release explanations:** communicate readiness and remaining work without overstating checks

## 2. Failure interpretation

### [2.1. Reconstruct an incident from conflicting messages](<sections/2. Failure interpretation/2.1. Reconstruct an incident from conflicting messages.md>)

1. **Align observations before proposing causes:** separate actors operation identifiers clocks and boundaries
2. **Reconstruct a bounded incident account:** reconcile naming transport application data and telemetry evidence
3. **Choose a discriminating next check:** retain unknown outcomes and separate mitigation from explanation

## 3. Expert source reading

### [3.1. Compare a specification vendor document and marketing claim](<sections/3. Expert source reading/3.1. Compare a specification vendor document and marketing claim.md>)

1. **Identify authority subject and time:** distinguish protocol semantics product guidance and promotional positioning
2. **Compare sources without flattening their claims:** track scope conditions revisions and what each source supports
3. **Write a sourced conclusion with open questions:** avoid inventing implementation guarantees from general language

## 4. Teaching and assessment

### [4.1. Diagnose misconceptions in a technical interview or review](<sections/4. Teaching and assessment/4.1. Diagnose misconceptions in a technical interview or review.md>)

1. **Elicit reasoning before judging knowledge:** use bounded questions and distinguish uncertainty from a misconception
2. **Diagnose and repair a specific mental model:** explain why an inference fails and test a changed condition
3. **Assess explanations with explicit criteria:** reward evidence scope transfer and constructive feedback

### [4.2. Build and teach a team glossary with canonical owners](<sections/4. Teaching and assessment/4.2. Build and teach a team glossary with canonical owners.md>)

1. **Design entries around meaning and context:** separate spelling aliases local conventions and canonical explanations
2. **Resolve competing meanings without duplication:** use precise owners and preserve source status
3. **Teach and maintain the glossary:** repair a junior explanation and assess transfer with a changed artifact

## 5. Overlaps to avoid

### [5.1. Boundaries and continuing learning after this track](<sections/5. Overlaps to avoid/5.1. Boundaries and continuing learning after this track.md>)

1. **State the competence this track develops:** separate interpretation integration source judgment and teaching from implementation mastery
2. **Choose further study from a demonstrated gap:** use existing owners and distinguish available lessons from planned tracks
3. **Maintain and reassess vocabulary knowledge:** update source-dependent claims and test transfer with unfamiliar evidence
