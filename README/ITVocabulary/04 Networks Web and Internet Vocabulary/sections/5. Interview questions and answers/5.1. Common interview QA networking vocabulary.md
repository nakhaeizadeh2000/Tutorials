## 5.1. Common interview Q&A: networking vocabulary

### 1) **DNS in one paragraph**

*What resolves, in what order, why it caches.*

- **Q**: "What happens with DNS when I visit a site?"
- **Model answer**: "The resolver walks root → TLD → authoritative server to translate the name to an IP, caching each answer for its TTL. So first visits pay the full walk, repeat visits hit cache — and DNS changes converge only as old TTLs expire, which is why migrations plan publish-then-wait." (from [1.2](<../1. How messages travel/1.2. DNS names to numbers.md>))
- **What they are really testing**: whether "propagation delay" gets the cache-expiry explanation or the travel-time myth — one sentence separates practiced operators from reciters.

### 2) **HTTP status drills**

*Read the first digit — fault attribution out loud.*

- **Q**: "Your dashboard shows a spike of 502s on /checkout. Walk me through it."
- **Model answer**: "5xx means server-side fault, so I start owner-side: 502 specifically means a gateway got a bad answer upstream — I'd check the upstream service health, then its recent deploys, then leg timings (DNS/connect/work) to split network from app. If it were 4xx instead, I'd flip to caller-side: what changed in client requests." (from [2.1](<../2. Web talk/2.1. HTTP requests verbs and status codes.md>))
- **What they are really testing**: first-digit-first discipline under pressure — candidates who open bodies before classes narrate archaeology; candidates who classify first narrate triage.

### 3) **Latency vs bandwidth — plus rapid-fire drills**

*The highway analogy, done right.*

- **Q**: "Explain latency vs bandwidth."
- **Model answer**: "Latency is delay per trip, bandwidth is data per second — a motorcycle courier (low latency, low bandwidth) vs a cargo plane (high latency, huge bandwidth). Video calls need the courier; backups need the plane. So I quote both numbers, because upgrading the wrong axis is the industry's most reliable wasted purchase." (from [2.2](<../2. Web talk/2.2. Latency vs bandwidth and timeouts.md>))
- **Rapid-fire drills** (one line each):
  - *Protocol?* — "Rules both ends follow so bits become conversation — TCP for correctness, UDP for freshness."
  - *Packet?* — "Header plus payload — the envelope; loss and size explain most flakiness."
  - *Port?* — "Which program on the machine — IP says where, port says whom."
  - *Timeout?* — "A bound on waiting — converts unbounded failure into bounded failure."
  - *Retry with backoff?* — "Re-attempt spaced increasingly with jitter — polite to recovering services."
  - *GET vs POST retry?* — "GET is idempotent, safe to repeat; POST may double-create — guard with idempotency keys."

### 4) **Common confusion**

- "More detail means better answers" — triage order beats volume: class before body, leg before theory, numbers before adjectives.
- "Analogies are unprofessional" — the courier-vs-plane analogy *is* the model compressed; interviewers remember candidates who compress well.
- "I should know every status code" — know the five classes cold and the famous six (200, 201, 301, 401, 403, 404, 500, 502, 503) warm; looking up 418's joke is fine, missing 5xx-vs-4xx is not.

### 5) **Mentor note**

Score mock answers on *order*, not content: did the class come before the body? The leg before the theory? Numbers before adjectives? Vocabulary interviews test sequencing under pressure more than knowledge — train the sequence explicitly and knowledge rides along.
