## 1.1. Networks internet intranets LAN WAN and interfaces

Your laptop can print to an office printer while an external website fails to
open. These observations can both be true. A working local connection is evidence
about a particular path; it is not proof that every remote destination or
application is reachable.

This lesson introduces the scope words used in network reports. The office map
is constructed text, not a discovery of your network. No network settings change
and no traffic is captured.

### 1) **Describe the communicating participants and the network scope**

A **network** connects participants so they can exchange data through communication
links. Participants can include computers, phones, printers and devices that
forward traffic. A link supplies a connection between points; communicating with
a distant participant can require several links and intervening networks.

The **Internet** is the global interconnection of independently operated networks.
It is not one company's server or one wireless service. The Internet Society's
[overview](https://www.internetsociety.org/internet/how-it-works/)
describes that interconnection. An **internet service provider**, or **ISP**,
supplies internet connectivity under a service arrangement. The public Internet
supports many applications; the Web is one of them, not another name for the
entire network.

An **intranet** serves an organization's internal purposes and intended audience.
[RFC 4949's intranet entry](https://www.rfc-editor.org/rfc/rfc4949)
records this organizational meaning. It describes scope and intended access,
not a guarantee that every internal participant is trustworthy or every access
rule is correct. An internal application can use the same general networking
technologies as a public-facing application.

A **local area network** (**LAN**) covers a limited area, such as an office or
campus. A **wide area network** (**WAN**) spans a broader geographic area and can
connect separated sites. Cisco's [LAN explanation](https://www.cisco.com/site/us/en/learn/topics/networking/what-is-a-lan-local-area-network.html)
compares these scopes. There is no useful universal rule that “ten devices make
a LAN” or that a WAN must be the public Internet. A company can connect offices
through a private WAN.

These categories answer different questions. LAN/WAN describe network extent;
intranet describes organizational use; Internet names the global interconnection.
Do not force an office's internal network into only one of those categories.
A scope label alone does not establish which individual destinations a policy
allows or what data protection is in place.

### 2) **Locate the interface and connection role before judging reachability**

A **network interface** is an attachment through which an OS participates in
network communication. It may correspond to physical hardware, such as an
Ethernet adapter, or be virtual. A computer can have several interfaces, and
software can select different paths for different destinations. Linux's
[network-device reference](https://man7.org/linux/man-pages/man7/netdevice.7.html)
separates interface names, indexes, addresses and status flags. These properties
are evidence with different meanings, not interchangeable “internet is working”
flags. An interface is not the same concept as an application's programming
interface, even though both use the word “interface.”

**Ethernet** commonly provides wired local-network links. **Wi-Fi** provides
wireless local-network access. An **access point** connects wireless devices
to a network. A **switch** forwards local-link traffic among connected devices;
a **router** forwards traffic between networks. Cisco's
[networking basics](https://www.cisco.com/site/us/en/learn/topics/small-business/networking-basics.html)
introduces these roles. One physical home gateway may combine several of them;
separate boxes are not required for separate responsibilities.

A Wi-Fi association means the device joined a wireless access network under its
rules. Additional addressing, forwarding, naming and application behavior still
matter for a particular task. Even a strong wireless signal does not show that
the ISP path, a remote host or the requested service works. Conversely, a
machine can use wired access and have no Wi-Fi connection at all.

A virtual interface need not correspond to another cable. Later infrastructure
study adds the mechanisms behind virtual network views. For now, the useful
question is which interface and view the failing process uses, not how many
physical ports are visible on the case.

### 3) **Interpret local success without claiming universal connectivity**

Read this fictional office map. Arrows mean intended connectivity, not verified
availability or unrestricted access:

```text
laptop -- Wi-Fi -- access point -- office LAN -- printer
                                      |
                                   router
                                      |
                                  ISP network -- Internet -- external site
```

The laptop reports a Wi-Fi connection. A print job reaches the printer and
finishes. One external site fails to open. What can you conclude?

The explained answer is that the particular local printing workflow succeeded.
That provides evidence of useful local communication during that attempt. It
does not establish success through the router, provider and remote-site path.
The failed site could involve naming, connectivity or application behavior;
this map and report do not identify the cause. Later lessons separate those
questions explicitly.

A useful report names the task and destinations: “The laptop joined the office
wireless network and completed a job to the local printer at the recorded time.
Opening the specified external site failed with this recorded message.” Ask
whether another intended external destination works and which step of the
failing attempt was observed. Avoid replacing the evidence with “Wi-Fi is broken”
or “the Internet is down.”

Now change the card: only one internal application fails while the printer and
an external site work. The explanation changes too. The wider successful path
does not establish that the internal application is reachable or healthy. Compare
the specific destinations and access context. Rebooting every network device
before recording the failure can erase useful evidence and interrupt unrelated
work without testing a clear hypothesis.

### 4) **Common confusion**

“Connected” needs an object: connected to an access point, an addressed network,
a remote endpoint or an application session? Those are progressively different
claims. An icon can summarize one check while the user's task requires more.

“Internal” is also not a synonym for “secure.” Intended audience and actual
protection must be established separately. Likewise, a LAN can contain many
devices, and sharing a building does not prove they share an allowed communication
path.

### 5) **Performance note**

A scope label or signal-strength indicator is not a throughput measurement.
The application path may include shared wireless access and several other
resources. A local print result cannot establish the rate to a distant site.
This lesson performs no network measurement; later measurement vocabulary will
separate capacity, observed rate and delay.

### 6) **Mentor note**

Ask a learner to underline exactly which part of the map the print result gives
evidence about. Then ask for one sentence describing what remains unknown.
A strong answer names a destination and task, recognizes possible combined device
roles, and avoids diagnosing the entire Internet from one failed page load.
