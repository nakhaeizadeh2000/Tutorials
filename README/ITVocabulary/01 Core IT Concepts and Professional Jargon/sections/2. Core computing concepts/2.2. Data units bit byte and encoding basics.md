## 2.2. Data units: bit, byte, and encoding basics

### 1) **Bit vs byte vs octet**

**Definition** — A *bit* is one binary digit (0 or 1). A *byte* is eight bits — the smallest addressable chunk on most machines. An *octet* is exactly eight bits, always — the unambiguous word networking standards (IETF RFCs, IEEE) prefer because "byte" was historically platform-dependent.

- **What problem it solves**: speeds, sizes, and limits are quoted in all three units, and mixing them up is an 8x error. A "100 Mbps" link moves ~12.5 MB/s; provisioning a download buffer with the wrong unit either starves the transfer or wastes memory by a factor of eight.
- **Modern guidance** — lowercase-b means bits, uppercase-B means bytes (`Mb` vs `MB`), and say "octet" in any networking or protocol context. When someone quotes a number without a unit, the professional reflex is one question: "bits or bytes?"

```text
# Bad: unit-blind (off by 8x, and nobody notices until prod)
"Allocate a 100 MB buffer for the 100 Mb/s stream — one second of data."

# Good: units stated and converted
"100 Mb/s = 12.5 MB/s, so one second of data needs a 12.5 MB buffer.
 Quoting both units so the next reader doesn't re-derive it."
```

### 2) **KB vs KiB is a real distinction**

*KB* (kilobyte) in SI means 1,000 bytes; *KiB* (kibibyte, IEC standard) means 1,024 bytes. Same ladder for MB/MiB, GB/GiB. Operating systems traditionally display binary sizes while drive manufacturers advertise decimal ones — which is why a "1 TB" drive shows up as ~931 GiB.

- **History in one paragraph**: early computing borrowed SI prefixes for nearby powers of two (1 KB = 1,024 bytes) because the numbers were close enough. They diverged as sizes grew — at the tera scale the gap is ~10% — so the IEC standardized KiB/MiB/GiB in 1998. Adoption is uneven: RAM is still sold in binary GB, disks in decimal GB, and both sides call it "GB".
- **Modern guidance** — in specs, quotas, and billing, write the exact byte count or the explicit IEC unit ("512 MiB limit", "1,000,000 bytes max"). Never let "GB" appear in a contract without saying which GB; storage marketing lives in exactly this gap.

### 3) **Encoding turns symbols into bytes**

Text is not bytes until an *encoding* says which bytes. *ASCII* maps 128 English characters to single bytes; *UTF-8* extends that to all of Unicode with one-to-four bytes per character and is byte-compatible with ASCII.

- **Why it matters (correctness)**: every mojibake bug ("Ã©" instead of "é"), every crashed CSV import, every "invalid byte sequence" error is an encoding disagreement — writer and reader assumed different mappings. The text was fine; the *agreement about the text* was missing.
- **Modern guidance** — default to UTF-8 everywhere (source files, databases, HTTP `charset=utf-8`, file reads with explicit encoding), and name the encoding at every boundary where text crosses systems. "Just text" is never just text once it leaves your process.

### 4) **Common confusion**

- "8 bits vs 1 byte — which is bigger?" — identical size; the confusion is purely notational (b vs B).
- "Unicode and UTF-8 are the same thing" — Unicode is the character set (which symbols exist); UTF-8 is one encoding of it (how symbols become bytes). UTF-16 is another.
- "KiB is pedantry" — at GiB scale and above it is money: cloud billing, quotas, and capacity plans all move on the difference.

### 5) **Mentor note**

Make juniors convert units by hand until it is boring: "how many MiB in a 2-hour 5 Mb/s stream?" Anyone who cannot do bits↔bytes↔human-units fluently will misread every dashboard, misconfigure every limit, and misdiagnose every "disk full" page. Fluency here is cheaper than any monitoring tool.
