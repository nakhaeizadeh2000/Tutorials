## 5.1. Common interview Q&A: core IT vocabulary

### 1) **Hardware vs software vs OS**

*The classic opener — answer in one layer-stack sentence.*

- **Q**: "Explain the difference between hardware, software, and the operating system."
- **Model answer**: "Hardware is the physical machine; software is the instructions that run on it; the operating system is the broker in between — its kernel schedules CPU and guards memory so many programs share one machine safely." One sentence per layer, then stop — the interviewer will pull the thread they care about.
- **What they are really testing**: whether you think in layers or in blobs. Follow-ups ("what happens when RAM runs out?", "what is a driver?") all reward the same stack picture from [2.1](<../2. Core computing concepts/2.1. Hardware software OS and platform.md>).

### 2) **Compile vs interpret**

*What the interviewer is really testing: your mental model of execution.*

- **Q**: "What is the difference between compiled and interpreted languages? Where does JavaScript fit?"
- **Model answer**: "Compiling translates source to machine code ahead of time; interpreting executes it line by line at run time. Modern runtimes are hybrids — JavaScript engines parse to bytecode and JIT-compile hot paths during execution, so calling JavaScript purely interpreted is outdated." Then name the consequence: build step vs immediacy, warm-up effects in benchmarks.
- **What they are really testing**: whether your vocabulary predicts behavior — the strong answer connects the words to observable effects (cold start, warm-up, where errors surface), per [2.3](<../2. Core computing concepts/2.3. Programs processes compile vs interpret.md>).

### 3) **API vs SDK — plus rapid-fire acronym drills**

*The most-asked acronym pair — answer with who consumes what.*

- **Q**: "What is the difference between an API and an SDK?"
- **Model answer**: "The API is the contract programs use to talk to a system; the SDK is the developer toolbox — libraries, docs, samples — wrapping that contract for one platform. Every SDK call ends at an API." Then give one example from your own work (from [3.1](<../3. Everyday professional jargon/3.1. Core acronyms API SDK SLA KPI and friends.md>)).
- **Rapid-fire drills** (answer each in one line, consumer-first):
  - *SLA vs SLO?* — "SLA is the contractual promise to customers with penalties; SLO is our internal target with an error budget."
  - *CLI?* — "How humans operate a system from a terminal — first choice for one-off ops."
  - *WIP vs shipped?* — "WIP is unfinished state; shipped means users can touch it — merged is not shipped."
  - *Bit vs byte?* — "Bit is one binary digit, byte is eight; lowercase-b bits, uppercase-B bytes."
  - *Blocked?* — "Cannot proceed without X from Y — always with a named owner and a date."

### 4) **Common confusion**

- "Longer answers score higher" — interviewers score *signal per sentence*; a three-sentence layered answer beats a two-minute ramble that never names the layer.
- "Vocabulary questions are trivia" — they are compression tests: can you deploy the right model under pressure? The drills above are exactly that skill.
- "I can just say 'it depends'" — only after giving the default answer; "it depends" without a baseline reads as evasion.

### 5) **Mentor note**

Drill candidates (and juniors) with referent-questions, not definition-questions: "point to the API/SDK/CLI in our project" beats "define API". Anyone who can map all three onto a real system in under a minute will survive any vocabulary interview — and anyone who cannot has a precise study list, which is the kindest interview feedback there is.
