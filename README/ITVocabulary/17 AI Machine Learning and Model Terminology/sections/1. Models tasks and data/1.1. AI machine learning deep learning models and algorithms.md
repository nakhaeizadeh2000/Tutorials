## 1.1. AI machine learning deep learning models and algorithms

“The AI algorithm understands every support ticket” leaves its task and evidence
unclear. It may classify text into routing categories, generate a suggested reply,
or combine both with ordinary application code. Start with what it receives,
what it produces and how the result will be used.

### 1) **Distinguish a field a method and a fitted artifact**

**Artificial intelligence (AI)** is a broad field concerned with systems performing
tasks associated with intelligence. The label does not identify one architecture
or level of capability. **Machine learning (ML)** develops behavior from data,
rather than specifying every task decision as a handwritten rule. A useful
introductory contrast is a spam filter with explicit word rules versus a classifier
fitted from labeled messages. Real systems can combine rules and learned parts.

**Deep learning** is ML using neural networks with multiple layers of learned
representations. “Deep” concerns the model structure; it does not mean deep human
understanding or guaranteed accuracy. An AI system need not use deep learning,
and an ML system need not generate conversational text.

An **algorithm** is a procedure; an **ML model** in this context is the learned or
fitted artifact used to produce an output. A training procedure can fit different
models from different data or settings. The word model also names a family or
architecture in some discussions, so ask whether a document means the method,
structure, specific fitted version or hosted service. The general
[algorithm owner](<../../../09 Programming Design and Architecture Language/sections/1. Reasoning about programs/1.1. Algorithms data structures complexity and invariants.md>) and architecture-model
owner retain their broader meanings.

[Google's ML introduction](https://developers.google.com/machine-learning/intro-to-ml/what-is-ml)
uses the relationship between data, training and predictions as an entry point.
It does not justify anthropomorphic claims that a fitted model reasons exactly
as a human would or will generalize to every new situation.

### 2) **Name the task before judging capability**

**Classification** predicts a category, such as billing question versus access
question. **Regression** predicts a numerical quantity, such as estimated handling
minutes. This use of regression differs from a software regression, where previously
required behavior fails. **Clustering** groups examples by a selected notion of
similarity without requiring those same predefined category labels. A cluster
number is not automatically a meaningful business category.

**Generation** produces content such as a draft response or image. **Natural
language processing (NLP)** concerns language tasks; **computer vision** concerns
image/video tasks. These task areas can use different techniques and can overlap
in a multimodal system, which processes more than one kind of input or output.
Identifying a language task does not establish the system is a conversational LLM.

**Supervised learning** uses examples with target values. **Unsupervised learning**
looks for structure without those target labels for the stated learning task.
**Reinforcement learning** learns behavior through a reward signal from interaction.
These labels describe learning arrangements, while “generative” describes an
important task/output family. They are not a mutually exclusive four-way product
classification. Details of data use follow in the next lesson.

### 3) **Read an AI system claim in layers**

Consider this original fictional design:

| Component | Supplied behavior |
|---|---|
| Input | A support-message text and its application tenant |
| Fitted classifier C2 | Suggests billing or access category |
| Rule | Routes any payment-refund request to a human review queue |
| Reply generator G4 | Drafts text; staff must approve before sending |
| Service | Applies tenant access checks and stores the approved response |
| Evidence | Twelve selected demonstration messages; no independent task evaluation supplied |

C2 performs classification; G4 performs generation. The refund rule and access
checks are application behavior. Calling the whole service “AI” does not show
that a model enforces those checks. Nor do twelve demonstration messages establish
accuracy across real support traffic or that all drafts are correct.

A supported reading is: “The proposal combines two learned components with routing,
access control and human approval. It demonstrates selected examples, while broader
task quality remains unmeasured.” Ask what data fitted C2, what G4 was evaluated
against, and who handles wrong routes or drafts. Do not infer those answers from
the word intelligence.

Change only the system to handwritten routing rules with no fitted component.
It no longer supplies evidence of ML training, even if a product team still uses
AI as a broad label. Conversely, removing the chat interface does not remove a
learned classifier. Interface appearance and learning method answer different questions.

### 4) **Common confusion**

A model is not the whole deployed application. Storage, permissions, retrieval,
monitoring and people can determine the final outcome. A model version and service
version may also change independently. Always name the component and task behind
“the model improved.”

### 5) **Performance note**

“AI,” “deep” and “large” do not specify latency, throughput, memory use or cost.
Training and using a fitted model are different workloads. Compare a stated model,
hardware, input/output size and task quality; this packet contains no timing or
resource measurements and demonstrates no speed advantage over rules.

### 6) **Mentor note**

Ask the learner to mark every learned component and every application responsibility
in the packet. Then remove the chat interface or substitute rules. A strong answer
updates only the relevant labels and still asks how errors and access boundaries
are checked. Reward the component explanation rather than memorized expansions.
