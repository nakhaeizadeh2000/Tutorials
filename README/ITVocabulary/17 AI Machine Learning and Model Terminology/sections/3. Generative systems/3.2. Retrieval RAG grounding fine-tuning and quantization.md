## 3.2. Retrieval RAG grounding fine-tuning and quantization

“We uploaded the manual, so the model is trained and cannot invent answers.”
Uploading may populate a document store, supply request context or start a training
job. Ask which operation actually happened and what evidence supports the answer.

### 1) **Distinguish information access from parameter changes**

**Retrieval** selects information from a collection, using a query and ranking
method. It can use keyword matching, embedding similarity or combined methods.
Retrieval returns candidates; their presence does not show completeness, truth,
current authority or permission to disclose them.

**Retrieval-augmented generation (RAG)** uses retrieved information as part of a
generation process. The [Lewis and colleagues research abstract](https://arxiv.org/abs/2005.11401)
describes a specific learned retrieval/generation design. Current application
usage of RAG is broader: many systems retrieve passages into a prompt without
retraining the generator on each query. Do not impose that paper's exact model,
index or training recipe on every system using the label.

**Grounding** connects an output to supplied sources or external evidence in a
stated sense. A product may use the word for web search, document context or a
measured source-support check. Ask which meaning applies. A citation marker alone
does not show that the linked passage supports the statement, that the source is
current or that the model followed it accurately.

**Fine-tuning** is additional training adapting learned model behavior using further
data. It changes learned values, potentially through a subset or added adapter
parameters rather than every original weight. Changing a prompt or updating a
retrieval index does not necessarily fine-tune the generator. Conversely, tuning
can affect behavior without making a complete, queryable record of every training
fact. [Google's adaptation overview](https://developers.google.com/machine-learning/crash-course/llm/tuning)
distinguishes additional training from prompt changes. Neither technique guarantees
correctness on an unmeasured task.

### 2) **Identify what representation changes**

**Quantization** represents model values at reduced numerical precision, often to
reduce storage or memory requirements. A value representation and a learned concept
are different things: reducing bits is not deleting half the model's knowledge.
[Hugging Face's overview](https://huggingface.co/docs/transformers/quantization/overview)
describes methods and hardware compatibility. Methods differ in which values they
quantize, preparation, supported operations and quality effects.

Quantization can coexist with fine-tuning and retrieval. None is a replacement
for the others: a smaller representation does not fetch a revised manual, while
a retrieval index update does not establish smaller model memory use. Distinguish
the base model, adapters, index and serving software when recording a version.

### 3) **Trace a knowledge-update proposal**

Read this original fictional packet. It contains no executed model or retrieval run.

| Step | Supplied record |
|---|---|
| Store update | Adds manual revision M8, which changes the refund window to 14 days |
| Index state | Search index still contains only M7, which says 30 days |
| Generation | Receives an M7 passage and produces “30 days [M7]” |
| Model state | Generator weights unchanged |
| Separate experiment | Quantized variant Q proposed; no memory or quality measurements |
| Claim | “M8 trained the model; the citation proves current truth; Q is twice as fast” |

Adding M8 to storage neither updates the stated index nor changes generator
weights. The answer is supported by M7's text but conflicts with the supplied
current revision M8. Its citation can be faithful to a stale source while the
product answer is wrong. “Grounded” therefore needs both source-support and source
selection/authority questions.

First update the index to include M8, then inspect whether retrieval actually
selects the right revision and the answer follows it. Even a recorded M8 retrieval
would establish only that boundary, not the generated conclusion. Access filtering
also belongs in the application: similarity must not allow another tenant's manual
to enter the caller's context.

If a separate training record later shows a completed fine-tuning job, that supports
a parameter-adaptation claim for its identified artifact. It does not fix the stale
index automatically. Likewise, Q's label supplies no twofold speed measurement.
Compare Q and the reference on the same hardware, workload and acceptable task
quality, including overhead and actual memory usage.

Practice: change only the answer to “14 days [M7].” It now agrees with M8's supplied
rule, but the citation does not support it. Correctness and source faithfulness
can fail separately. The useful repair must assess both rather than treating any
citation as a guarantee.

### 4) **Common confusion**

Retrieval can return text without generating anything. RAG adds generation, which
can still make mistakes. Fine-tuning and supplying examples in a prompt are different
data uses even when both improve a demonstration. Quantization is also distinct
from reducing parameter count or shortening prompts.

### 5) **Performance note**

Retrieval adds query and data-transfer work while potentially changing answer
quality. Quantization may reduce memory and can change speed depending on hardware
and kernels; lower precision alone proves no fixed multiplier. The packet measures
none of these costs or trade-offs.

### 6) **Mentor note**

Ask the learner to place each change beside storage, index, prompt, learned values
or numerical representation. Then substitute the unsupported14-day citation. A
strong explanation distinguishes current-rule correctness from source support and
names the evidence needed at each boundary.
