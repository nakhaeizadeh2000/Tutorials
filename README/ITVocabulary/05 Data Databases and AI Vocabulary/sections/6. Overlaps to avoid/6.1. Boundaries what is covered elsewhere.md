## 6.1. Boundaries: what is covered elsewhere

This domain names data and AI — shapes, stores, questions, models, and their failure modes. It deliberately stops at these borders:

1. **Query mechanics** (writing SQL, schema design, migrations, ORMs) — future Databases, DatabaseDesign, and ORM tracks own the practice; this domain owns store/table/query/index as words ([1.2](<../1. Data words/1.2. Database table query and index.md>)).
2. **ML internals** (architectures, loss functions, optimizers, fine-tuning how-to) — future AI topics; training/inference/hallucination stay here as vocabulary ([2.2](<../2. AI words/2.2. Training vs inference and hallucination.md>)), the math lives there.
3. **Data engineering practice** (pipelines, ETL/ELT, warehousing and lakehouse ops) — [Domain 06 Security Cloud and DevOps Vocabulary](<../../../06 Security Cloud and DevOps Vocabulary/README.md>) and future data tracks; the nouns (dataset, pipeline) are planted here.
4. **API and network transport of data** (serialization formats, HTTP verbs, latency) — [Domain 04](<../../../04 Networks Web and Internet Vocabulary/README.md>); this domain names what moves, Domain 04 names how it travels.
5. **Units, encoding, and storage hardware** (bytes, UTF-8, SSD vs HDD) — [Domain 01](<../../../01 Core IT Concepts and Professional Jargon/README.md>) and [Domain 02](<../../../02 Hardware Infrastructure and Platforms/README.md>); this domain assumes those foundations.

If you find yourself writing SQL, deriving gradients, or configuring pipelines inside this domain — stop; name the concept in one line, link the neighbor that owns the practice, and move on.
