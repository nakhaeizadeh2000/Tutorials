## 2.1. Model, token, and prompt

### 1) **Model is frozen learning**

**Definition** — A *model* is trained parameters (*weights*) plus architecture — a function shaped by data, frozen at training's end and executed at inference. *LLM* (large language model) names the text-in/text-out family; *open vs closed* describes weight availability, not intelligence.

- **What problem it solves**: "AI" as a blob word hides every decision that matters — which model (capabilities, cost, data policy), which version (behavior drifts between releases), hosted where (your cloud, their API, on-device). Naming the model like a dependency ("gpt-4o-2024-08, via vendor API, EU data residency") turns magic into inventory.
- **Modern guidance** — pin models like dependencies (exact version, evaluation date, fallback), because vendors ship behavior changes under stable names. "The model got worse" is usually an unpinned version rolling forward — the same class of bug as unpinned npm packages, with weirder symptoms.

```text
# Bad: blob-talk (undebuggable, unrepeatable)
"We use AI for summaries — sometimes quality drops."

# Good: inventory-talk (decisions visible, drift checkable)
"Summaries via vendor-model X version 2024-08 (pinned),
 temp 0.2, eval score 4.1/5 on 200 samples. Quality dip
 on 09-10 traced to vendor-side rollout — pinned version
 unaffected. Fallback: model Y at +30% token cost."
```

### 2) **Token is the billing atom**

A *token* is a word-piece (roughly ¾ of an English word) — the unit models read and write, bills count, and *context windows* (maximum input+output tokens per call) limit. Long inputs, chat histories, and retrieved documents all spend from the same window.

- **Why it matters (money, design)**: every AI feature has a token budget with two edges — cost per call and quality per window (stuffed contexts distract models; relevant context focuses them). "Send the whole ticket history" is simultaneously the most expensive and often the worst-performing option.
- **Modern guidance** — budget tokens like latency: measure per-feature token spend, trim context to the relevant slice (summarize history, retrieve don't dump), and surface costs in dashboards before finance does it for you. Token bills surprise teams exactly once — the ones who instrument survive it.

### 3) **Prompt is programming in prose**

A *prompt* combines instructions, examples (*few-shot*), and context to steer a model — the primary interface skill of the AI era. *System prompts* set persistent role/rules; *user prompts* carry the task; *prompt engineering* is the iterative discipline of improving both against measured evals.

- **What problem it solves**: vague prompts produce vague outputs at scale — and unlike code, prose fails silently (plausible but wrong). Treating prompts as code (versioned, reviewed, evaluated) converts "the AI is flaky" into improvable engineering: change one instruction, re-run the eval set, keep what scores higher.
- **Modern guidance** — version prompts in git, review them like code, evaluate on fixed sample sets before and after every edit. State output format explicitly (JSON schema, length bounds), demand citations/IDs for factual claims, and never accept the first draft of an important prompt — iterate against the evals, not against vibes.

### 4) **Common confusion**

- "Bigger model is always better" — bigger costs more per token and answers slower; the right model is the smallest that clears your eval bar with margin.
- "Tokens equal words" — tokenization splits strangely (code, non-English, and long numbers cost more tokens per character); estimate with a tokenizer, not word counts.
- "Prompting replaces engineering" — prompts are one layer; evals, grounding, guardrails, and fallbacks are the system — prompt-only solutions fail at the first adversarial input.

### 5) **Mentor note**

Review prompts the way you review queries: ask for the eval set first ("what 50 inputs prove this works?"), then read the prose. Juniors who learn evals-before-edits stop prompt-tweaking by feel within weeks — and the eval set they built becomes the regression suite that makes the next model upgrade boring instead of terrifying.
