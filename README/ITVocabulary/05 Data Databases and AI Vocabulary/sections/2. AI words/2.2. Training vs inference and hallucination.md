## 2.2. Training vs inference, hallucination

### 1) **Training learns once, inference answers always**

**Definitions** — *Training* adjusts model weights over a dataset in one expensive batch operation (GPU-weeks, done rarely). *Inference* runs the frozen model per request (milliseconds, done constantly). *Fine-tuning* continues training briefly on your data for specialization — cheaper than training, pricier than prompting.

- **What problem it solves**: cost and cadence confusion — teams propose "retraining" for what prompting solves, or expect training-grade behavior changes from inference-time tweaks. The vocabulary sets the price tags: prompting (cents, minutes), fine-tuning (dollars-to-thousands, days), training (fortunes, months) — pick the cheapest tier that clears the bar.
- **Modern guidance** — climb the ladder only when the lower rung demonstrably fails: prompt well first (with evals), retrieve-and-ground second, fine-tune third, train-from-scratch essentially never (unless models are your product). Each rung up multiplies cost, complexity, and maintenance — skip rungs only with measured justification.

```text
# Bad: ladder-blind (buys the most expensive fix first)
"Support answers are off-tone — let's fine-tune a model."

# Good: cheapest-rung-first (escalate on measured failure)
"Tone fixed via system prompt v3 (eval 4.3/5, +$0 cost).
 Fine-tuning deferred until prompts demonstrably plateau —
 tracked in AI-77 with the eval gap attached."
```

### 2) **Hallucination is fluent fabrication**

*Hallucination* is confident, grammatical, wrong output — fabricated citations, invented APIs, plausible-but-false facts. It is not a bug to patch but the base behavior of prediction machines: models complete patterns, and truth is only one pattern among many.

- **Why it matters (correctness, trust)**: hallucinations fail *upward* — the more fluent, the more believed, by users and by developers skimming outputs. Every AI feature ships with an invisible defect rate; designing as if outputs were reliable (auto-sending, auto-merging, auto-diagnosing) converts model error into system error at scale.
- **Modern guidance** — design for fabrication: constrain outputs to verifiable forms (IDs from your DB, not names from thin air), verify before acting (lookup-then-send, never send-then-hope), and surface uncertainty (citations, confidence, "I don't know" paths). The question is never "does it hallucinate?" — it does — but "what happens here when it does?"

### 3) **Grounding and evals manage the risk**

*Grounding* (retrieval-augmented generation — RAG) feeds the model your documents so answers cite provided sources instead of memory. *Evals* (evaluations) score outputs on fixed sample sets — the test suite for AI behavior, run before and after every prompt/model change.

- **What problem it solves**: raw models answer from training memory (stale, generic, hallucination-prone); grounded models answer from your docs (current, specific, checkable) — RAG converts "fluent guess" into "cited lookup" for knowledge-heavy tasks. Evals convert "seems better" into numbers — without them, every prompt edit is superstition.
- **Modern guidance** — ground knowledge questions (retrieve → cite → answer, with sources shown to users), eval everything that ships (50+ representative inputs, scored consistently, gated in CI like tests), and monitor live (sample production outputs for human review weekly). Trust in AI features is *instrumented* or it is theater.

### 4) **Common confusion**

- "Hallucinations will be fixed next version" — reduced, never removed; prediction machines cannot know what they don't know — design around permanence, not roadmaps.
- "RAG means the answers are correct" — RAG grounds *sources*, but models still misread, overgeneralize, and cite irrelevantly — evals measure the residue.
- "Fine-tuning fixes hallucinations" — fine-tuning teaches style and domain patterns; factual grounding still comes from retrieval — tune for voice, ground for truth.

### 5) **Mentor note**

Ask the hallucination question about every AI proposal: "show me what this does when the model invents facts — trace one fabricated output through the system." Juniors who can walk that path (constraint → verification → fallback) design shippable AI; those who can't are demoing. Make the failure walkthrough a merge requirement, not a nice-to-have.
