# Reading and Using Technical Language

Learn to identify unfamiliar meanings, read technical documents and ask precise
questions. No technical prerequisites are assumed. The worked situations explain
the minimum specialist context needed; later domains develop those topics.

This domain is in progress: 6 of 7 approved lessons are available.

## 1. Words in context

### [1.1. Terms jargon abbreviations and acronyms](<sections/1. Words in context/1.1. Terms jargon abbreviations and acronyms.md>)

1. **Distinguish a technical meaning from its written form:** classify terms, jargon, abbreviations, acronyms and initialisms without treating the categories as exclusive.
2. **Turn an expansion into a usable explanation:** explain a realistic message through actors, actions and missing information.
3. **Choose language that fits the reader and the task:** adapt wording and use an explained exercise to check understanding.

### [1.2. Overloaded words and ambiguous abbreviations](<sections/1. Words in context/1.2. Overloaded words and ambiguous abbreviations.md>)

1. **Recognize when a familiar word has several technical meanings:** distinguish plausible client, service, host, environment and token contexts.
2. **Use evidence to choose a meaning without pretending to know:** ask a question that resolves ambiguity while leaving the failure cause open.
3. **Keep expansions and local meanings explicit:** interpret CD cautiously and record a scoped team definition.

## 2. Reading technical documents

### [2.1. Guides references specifications and release notes](<sections/2. Reading technical documents/2.1. Guides references specifications and release notes.md>)

1. **Choose a document by the question it can answer:** distinguish tutorials, how-to guides, explanations, references, specifications and release records.
2. **Separate an example from a requirement or guarantee:** identify scope and normative versus informative material without equating every RFC with a standard.
3. **Follow a versioned reading route and preserve uncertainty:** resolve a fictional configuration question using matching documentation and stated evidence gaps.

### [2.2. Requirements guarantees defaults and support status](<sections/2. Reading technical documents/2.2. Requirements guarantees defaults and support status.md>)

1. **Read requirement levels within the document that defines them:** interpret conditional MUST, SHOULD and MAY under BCP 14 without relying on capitalization alone.
2. **Keep guarantees distinct from defaults and observations:** identify a promise's conditions and distinguish configured behavior from defaults and a successful example.
3. **Interpret lifecycle and support labels as scoped policies:** distinguish experimental, stable, deprecated, removed and publisher-specific support meanings.

## 3. Speaking and asking precisely

### [3.1. Pronunciation naming and useful clarification questions](<sections/3. Speaking and asking precisely/3.1. Pronunciation naming and useful clarification questions.md>)

1. **Make names recognizable without treating pronunciation as a skill test:** handle acronym sounds and a/an choices while accepting understandable variation.
2. **Preserve exact names when the task depends on identity:** distinguish a nickname, exact identifier and sensitive private value.
3. **Ask for the smallest fact that moves the discussion forward:** state a tentative understanding, ask a focused question and summarize remaining uncertainty.

## 4. Applied reading and review

### [4.1. Turn a jargon-heavy message into a testable statement](<sections/4. Applied reading and review/4.1. Turn a jargon-heavy message into a testable statement.md>)

1. **Separate ambiguous wording from the evidence actually supplied:** classify a constructed readiness message against a supplied observation card.
2. **Produce a scoped statement and an actionable next question:** rewrite technical and stakeholder versions without inventing checked outcomes.
3. **Review the rewrite for hidden additions and useful omissions:** explain unsupported release, failure and timing claims with a reasoned assessment rubric.
