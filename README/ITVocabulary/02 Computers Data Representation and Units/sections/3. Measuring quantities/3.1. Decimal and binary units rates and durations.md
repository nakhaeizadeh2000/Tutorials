## 3.1. Decimal and binary units rates and durations

A connection is described as 100 Mbps, while a download display reports MB/s.
A drive uses GB on its label and a system tool shows GiB. A chart switches from
milliseconds to microseconds. Before concluding that something lost capacity or
became slower, put both observations into comparable units.

Read the bit/byte lesson first. This lesson uses ordinary multiplication and
division, plus a complete optional Python calculation. It does not measure a
real connection or make a hardware recommendation.

### 1) **Distinguish decimal prefixes from binary prefixes**

A **prefix** multiplies a unit. Decimal prefixes use powers of ten; binary prefixes
use powers of two. The multiplier changes the number of bytes described, not
the identity of the byte itself.

| Unit | Name | Exact byte count |
|---|---|---|
| kB | kilobyte | 1,000 |
| KiB | kibibyte | 1,024 |
| MB | megabyte | 1,000,000 |
| MiB | mebibyte | 1,048,576 |
| GB | gigabyte | 1,000,000,000 |
| GiB | gibibyte | 1,073,741,824 |

These distinctions are documented by NIST's
[binary-prefix reference](https://physics.nist.gov/cuu/Units/binary.html), including
the separate IEC binary prefixes. SI means International System of Units; IEC
means International Electrotechnical Commission. Binary prefixes are not SI
prefixes, even though their names were designed to recall the decimal names.

The symbols matter. Lowercase `k` is the SI kilo prefix; uppercase `M` is mega.
The extra `i` distinguishes MiB from MB. Real software sometimes uses an ambiguous
label such as KB or uses MB while calculating binary quantities. Check that
tool's definition or raw byte count rather than silently choosing an interpretation.

For example, one billion bytes is exactly 1 GB and approximately 0.931 GiB.
The quantity has not changed. File-system overhead, reserved areas and occupied
files can also affect usable space, but a unit conversion alone cannot establish
which of those factors applies.

### 2) **Keep capacity rates and elapsed time dimensionally distinct**

**Capacity** describes an amount that can be held, such as bytes of storage.
A **rate** describes an amount per time, such as bytes per second. A **duration**
describes elapsed time. Dividing an amount by a compatible constant rate gives
a duration under the stated model.

Use `B` for bytes and write `bit` when spelling out bits avoids ambiguity.
`Mbps` commonly denotes megabits per second; `MB/s` denotes megabytes per second.
Under decimal definitions, 100 Mbit/s corresponds to 12.5 MB/s because each byte
contains eight bits. That conversion does not establish that an application can
continuously transfer payload data at the full connection rate.

Imagine transferring an unchanged 100 MB payload at a constant payload rate of
100 Mbit/s. Convert the amount to bits: 100 million bytes times eight is 800
million bits. Dividing by 100 million bits per second gives eight seconds.
Change the payload to 100 MiB and the same calculation gives 8.388608 seconds.
The payloads are different sizes despite sharing the number 100.

For duration prefixes, the [BIPM SI-prefix table](https://www.bipm.org/en/measurement-units/si-prefixes)
defines milli as one thousandth, micro as one millionth and nano as one billionth.
Thus 1 ms is 1,000 microseconds, written µs, and 1 µs is 1,000 ns. Plain-text tools
often use `us` for microseconds. State that convention rather than interpreting
it as another standardized SI symbol.

Case is significant: `ms` is milliseconds, while an uppercase mega prefix means
something entirely different. A time value without its unit is incomplete evidence.

### 3) **Check a conversion and state the assumptions behind an estimate**

Tested environment: **Python 3.14.4 on Linux x86_64**. Save this complete example
as `unit_conversions.py`, then run `python3 unit_conversions.py` in the same folder.
It needs no imports or packages. `*` multiplies, `/` divides, and the printed
format requests six digits after the decimal point.

```python
decimal_bytes = 100 * 1_000_000
binary_bytes = 100 * 1_048_576
rate_bits_per_second = 100 * 1_000_000

print("100 MB bytes:", decimal_bytes)
print("100 MiB bytes:", binary_bytes)
print("100 Mbit/s in MB/s:", rate_bits_per_second / 8 / 1_000_000)
print("100 MB ideal seconds:", f"{decimal_bytes * 8 / rate_bits_per_second:.6f}")
print("100 MiB ideal seconds:", f"{binary_bytes * 8 / rate_bits_per_second:.6f}")
print("2.5 ms in microseconds:", 2.5 * 1_000)
```

Observed output:

```text
100 MB bytes: 100000000
100 MiB bytes: 104857600
100 Mbit/s in MB/s: 12.5
100 MB ideal seconds: 8.000000
100 MiB ideal seconds: 8.388608
2.5 ms in microseconds: 2500.0
```

The underscores make Python's integer literals readable without changing their
values. The calculation verifies the unit model; it does not observe network
behavior. A real transfer can also involve setup, protocol overhead, other users,
waiting and varying rates. Compression or another representation can change the
number of bytes actually transferred. State what quantity the rate measures
before using it to predict completion time.

Practice: someone reports a duration of 500 µs and another report says 0.5 ms.
Are the numbers evidence of different speeds? Not by themselves: both represent
the same duration. You would still need the operation, measurement conditions and
whether either value is an average, sample or bound before comparing systems.

### 4) **Common confusion**

MB and Mbit are not different spellings of the same amount. Missing the factor
of eight can make a plausible-looking estimate wrong. MiB and MB introduce a
separate decimal/binary distinction; fixing the bit/byte conversion does not
automatically fix the prefix.

An accurate unit conversion also does not validate the input measurement.
A nominal capacity or advertised maximum rate can be perfectly well specified
while being the wrong quantity for the application question you are answering.

### 5) **Performance note**

Units directly affect how measurements and limits are interpreted. Reporting
microseconds as milliseconds changes the apparent duration by a factor of 1,000;
it does not change the program's actual execution time. Preserve units and
measurement boundaries when collecting data, then convert for comparison. The
example is arithmetic verification, not a throughput benchmark or transfer test.

### 6) **Mentor note**

Ask a learner to write the units beside every step of the eight-second estimate.
The amount in bits divided by bits per second should leave seconds. Then change
MB to MiB or Mbit/s to MB/s and ask which step changes. A sound answer recomputes
the model while still identifying the real-world assumptions it cannot verify.
