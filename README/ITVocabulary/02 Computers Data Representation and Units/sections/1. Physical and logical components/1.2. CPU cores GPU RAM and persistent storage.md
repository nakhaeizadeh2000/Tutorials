## 1.2. CPU cores GPU RAM and persistent storage

A machine description lists a CPU, six cores, a GPU, 16 GB of RAM and a 512 GB
SSD. These are different resources, not five measures of the same kind of speed.
Understanding their roles helps you ask a useful question when a program is slow
or a machine runs out of space.

Read the preceding hardware/software lesson first. The optional observation below
uses an existing Python installation only to report CPU information; no packages,
administrator permissions or hardware changes are required. You can still study
the distinction using the supplied output if Python is unavailable.

### 1) **Distinguish processors and the execution resources they expose**

The **central processing unit**, or CPU, executes program instructions. A
**core** is a physical execution resource within a processor. A multicore
processor has multiple such resources, but applications do not automatically
divide every operation perfectly among them.

An operating system can expose **logical CPUs** as scheduling resources. Some
physical cores support multiple hardware threads, so the number of logical CPUs
can exceed the number of physical cores. A virtualized environment can expose
another configured view. Do not read an arbitrary CPU-count field as a complete
inventory of physical cores, processor sockets or performance.

A **graphics processing unit**, or GPU, is a processor designed around substantial
parallel work, originally strongly associated with graphics. Parallel means that
some work proceeds simultaneously. GPUs are also used for other suitable
computations, but an application needs an appropriate implementation and workload
to benefit. CPUs can also perform parallel work. The names do not divide all
programs into "serial CPU" and "parallel GPU" categories.

NVIDIA's [CPU/GPU explanation](https://blogs.nvidia.com/blog/whats-the-difference-between-a-cpu-and-a-gpu/)
introduces their differing design emphases. Treat generic core-count comparisons
as orientation rather than a prediction for your program: a CPU core and a GPU
execution unit are not interchangeable units of application performance.

### 2) **Distinguish working memory from retained files and capacity from speed**

**RAM**, expanded as random-access memory, commonly refers to the main working
memory used by programs. Ordinary system RAM is volatile: it needs power to
retain its contents. **Persistent storage** is intended to retain stored data
after normal power-off. An SSD is a solid-state drive; an HDD is a hard disk
drive. They use different device technologies to provide storage.

Opening a saved document involves storage, memory and processing. Its saved data
is read from storage; the application works with an in-memory representation;
the CPU executes instructions to process it. Saving writes data back through
the storage path. Unsaved in-memory changes are not guaranteed to survive power
loss merely because an earlier version of the document exists on the drive.

| Resource description | What it describes | What it does not establish |
|---|---|---|
| 16 GB RAM | A memory capacity. | How much free storage is available or how long a task takes. |
| 512 GB SSD | A storage capacity and device category. | The currently free space, access latency or durable preservation of every recent write. |
| 3 GHz CPU clock | A frequency of three billion cycles per second at the stated operating point. | Three billion completed instructions per second for every program. |
| Six physical cores | A count of core resources. | A sixfold improvement for every operation. |

GB is a capacity unit used in the example; later measurement lessons distinguish
decimal and binary units. **Hertz**, abbreviated Hz, means cycles per second;
GHz means billions of cycles per second. Intel's
[clock-speed explanation](https://www.intel.com/content/www/us/en/gaming/resources/cpu-clock-speed.html)
notes that instruction work and cycle counts do not have a fixed one-to-one
relationship. Architecture, instructions, memory access and workload matter.

Kingston's [memory/storage explanation](https://www.kingston.com/en/blog/pc-performance/difference-between-memory-storage)
provides a manufacturer account of the working-memory versus retained-storage
distinction. Its everyday-language contrast is useful, but "retained" does not
mean indestructible. Devices can fail and recent changes can remain unsaved or
not yet durably stored. Capacity, speed and reliability answer different questions.

### 3) **Read a resource report as scoped evidence**

Here is a complete optional observation, tested with **Python 3.14.4 on Linux
x86_64**. Python's standard library provides the functions; install no packages.
Save the following text as `hardware_report.py` in a folder where you can run
Python. The `import` lines make standard-library helpers available, and `print`
displays their returned values. This code reads metadata; it does not change
configuration or run a performance workload.

```python
import os
import platform
import sys

print("Python:", sys.version.split()[0])
print("Platform:", platform.system(), platform.machine())
print("System logical CPUs:", os.cpu_count())
print("Process usable logical CPUs:", os.process_cpu_count())
```

Run it from that folder with:

```bash
python3 hardware_report.py
```

Observed output in the checked environment:

```text
Python: 3.14.4
Platform: Linux x86_64
System logical CPUs: 6
Process usable logical CPUs: 6
```

Your version, platform and counts can differ. Python's
[CPU-count reference](https://docs.python.org/3.14/library/os.html#os.cpu_count)
distinguishes the system's logical count from the logical CPUs usable by the
calling thread of the process. A count can also be undetermined, reported as
`None`. The usable count can be affected by execution restrictions; these
reported values are not a physical hardware inspection.

The two sixes answer different questions even though they happen to match here.
The output does not establish that six physical cores are dedicated to this
program or that it executes six operations at once. `x86_64` identifies a
reported machine-architecture name, not a clock frequency or a count.

Practice: a colleague sees this output and concludes that a slow request needs
more RAM because it uses only one CPU. What is missing? The report contains no
per-request CPU use, memory pressure, workload or waiting-time measurements.
The reported count alone cannot identify the limiting resource.

### 4) **Common confusion**

Deleting saved files can free storage space; it does not directly increase the
installed RAM capacity. Closing an application can release working-memory
resources without deleting its saved files. The actual outcome depends on what
the application and OS do, but the two capacities remain distinct.

Also distinguish installed capacity from available resources. Some memory is
already used, storage can be full, and other programs can share execution
resources. A specification lists capabilities; a scoped observation describes
some part of the current state.

### 5) **Performance note**

A **bottleneck** is the limiting part of a particular workload or path. More of
one resource helps only when it addresses a relevant limit and the software can
use it. A CPU count, a capacity or a frequency is not a benchmark. The optional
script measures no task completion time, so it supports no speed comparison or
hardware purchase recommendation.

### 6) **Mentor note**

Ask a learner to trace opening, editing and saving a document through storage,
RAM and CPU work. Then show the CPU report and ask what it leaves unknown.
A sound answer distinguishes resource roles and logical counts without asserting
an unobserved physical topology or diagnosing a performance problem from a label.
