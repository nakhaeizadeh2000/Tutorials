## 6.1. Boundaries of hardware and representation vocabulary

You can now explain why “64-bit,” “100 MB” and “checksum verified” each need
context. The next step is to recognize which kind of further question you have.
A vocabulary explanation helps you identify the resource, representation or
measurement. Implementing and validating a complete system requires additional,
subject-specific knowledge.

Use this lesson after the domain's applied exercise. It is an ownership and
reasoning exercise, not another hardware inventory or a security procedure.

### 1) **Keep the representation model separate from language mechanics**

This domain owns the general distinctions: a bit pattern needs an interpretation,
text can have different encoded representations, and quantities need compatible
units. When you need to predict a particular language operation, consult that
language's owner rather than extending a generic rule by guesswork.

These routes preserve a useful division. “Hexadecimal displays a value in base
sixteen” is a general explanation. “This API accepts this argument and throws
this exception” needs the API's documented contract and a suitable example.
Do not infer JavaScript arithmetic behavior from the Python examples here.

### 2) **Route implementation and protection questions to their own scope**

A resource description is not a hardware procurement plan. This domain helps you
read CPU, RAM and storage labels; it does not teach motherboard compatibility,
firmware flashing, operating-system installation or device repair. A claim about
a particular machine needs its actual model, environment and evidence.

Similarly, knowing a file format or checksum does not establish a secure download
process. The [formats lesson](<../4. Representing and preserving information/4.1. Formats compression checksums and metadata.md>)
owns representation changes and accidental-change checks here. Later approved
Security Identity and Privacy lessons will distinguish cryptographic goals and
trust. Version Control Releases and Dependencies will put artifact digests and
provenance into a delivery context. Those lessons are future parts of this track,
so this page does not link to unfinished files.

Numerical algorithms, character-segmentation implementations and cryptographic
implementations also exceed this domain. A junior should be able to name the
missing question without pretending to have solved it. “We agree on the bytes,
but have not established who supplied the expected digest” is a useful result.

### 3) **Use a worked handoff without losing the unknowns**

Consider this constructed message:

> The 64-bit server has enough memory. The compressed export has the same text,
> so its SHA-256 must match the original. We can guarantee the transfer time
> from the link speed.

A useful handoff separates three investigations:

1. **Resources:** “64-bit” does not specify installed or available RAM. Record
   the actual memory quantity, process limits where applicable and workload need.
   The [resource lesson](<../1. Physical and logical components/1.2. CPU cores GPU RAM and persistent storage.md>)
   supplies the category distinctions, not a capacity recommendation.
2. **Comparison:** specify whether the digest covers the original export or
   its compressed representation. Equivalent recovered text does not require
   identical packaged bytes. Reuse the format lesson rather than adding a second
   explanation of hashing in the handoff.
3. **Timing:** name the representation size, compatible payload rate, completion
   criterion and stage arrangement. The [transfer exercise](<../5. Applied interpretation/5.1. Read a machine specification and transfer estimate.md>)
   demonstrates why a model estimate is not a measured end-to-end guarantee.

An improved message is: “We need available-memory and workload evidence. Compare
digests of the agreed representation. Treat the link-based calculation as an
estimate until its rate, completion criterion and other stage assumptions are
verified.” This does not invent a failure cause or promise a result you have not
observed.

### 4) **Common confusion**

A cross-link is a route to additional depth, not a reason to leave this domain's
basic explanation incomplete. You should understand what bytes, capacity and a
digest mean before following a language-specific link. Conversely, vocabulary
fluency does not prove that a learner can configure memory limits or design
cryptographic verification correctly.

### 5) **Performance note**

Choosing a learning owner has no direct effect on runtime performance. It helps
avoid acting on the wrong quantity, such as buying storage because a workload
needs more working memory. Any actual improvement still depends on the measured
workload and limiting resource; this boundary exercise measures neither.

### 6) **Mentor note**

Ask a learner to split the constructed message into claims and identify the
smallest evidence needed for each. Then ask which question this domain answers
and which needs deeper study. Reward an accurate handoff with explicit unknowns
rather than a confident recommendation built from isolated specification labels.
