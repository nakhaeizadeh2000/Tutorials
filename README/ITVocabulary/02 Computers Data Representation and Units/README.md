# Computers Data Representation and Units

Connect hardware descriptions and data representations to the resources they describe. Read [Reading and Using Technical Language](<../01 Reading and Using Technical Language/README.md>) before beginning; no hardware purchase, administrator access or programming background is required. Examples distinguish physical components, instructions, data and measurements before discussing their limits.

This domain is complete: all 8 approved lessons are available.

## 1. Physical and logical components

### [1.1. Hardware software firmware and drivers](<sections/1. Physical and logical components/1.1. Hardware software firmware and drivers.md>)

1. **Distinguish physical components from the instructions they execute:** classify hardware, software, operating systems and applications through concrete changes.
2. **Locate firmware and drivers within the software picture:** explain device control versus OS integration without treating the categories as exclusive.
3. **Interpret boot and update descriptions without collapsing the layers:** read separate component versions and explain what a fictional device report leaves unknown.

### [1.2. CPU cores GPU RAM and persistent storage](<sections/1. Physical and logical components/1.2. CPU cores GPU RAM and persistent storage.md>)

1. **Distinguish processors and the execution resources they expose:** separate CPUs, cores, logical CPU counts and GPU design emphasis without assuming automatic parallel speedups.
2. **Distinguish working memory from retained files and capacity from speed:** trace a document through RAM, storage and processing and interpret capacity/frequency limits.
3. **Read a resource report as scoped evidence:** run an optional complete Python metadata example and explain why its logical counts do not diagnose a bottleneck.

## 2. Data representation

### [2.1. Bits bytes binary hexadecimal and machine words](<sections/2. Data representation/2.1. Bits bytes binary hexadecimal and machine words.md>)

1. **Read bits and bytes as patterns with a declared interpretation:** distinguish eight-bit patterns from unsigned, signed and other intended values.
2. **Translate number bases without changing the underlying value:** explain binary and hexadecimal place values, prefixes and display padding.
3. **Ask about width signedness and byte order before interpreting a field:** run a complete conversion and caught-overflow experiment and justify the alternate-endian exercise.

### [2.2. Text characters Unicode and encodings](<sections/2. Data representation/2.2. Text characters Unicode and encodings.md>)

1. **Distinguish a displayed character from code points and code units:** explain why grapheme, point, unit and byte counts can differ.
2. **Separate text from the bytes used to exchange it:** distinguish Unicode, ASCII, UTF encodings and normalization with explicit scope.
3. **Observe distinct counts and decoding failures in a complete example:** run the exact Python observation and explain normalization equality and rejected invalid UTF-8.

## 3. Measuring quantities

### [3.1. Decimal and binary units rates and durations](<sections/3. Measuring quantities/3.1. Decimal and binary units rates and durations.md>)

1. **Distinguish decimal prefixes from binary prefixes:** convert kB/KiB, MB/MiB and GB/GiB and identify ambiguous tool labels.
2. **Keep capacity rates and elapsed time dimensionally distinct:** explain bit/byte rates and ms/us/ns durations with compatible units.
3. **Check a conversion and state the assumptions behind an estimate:** run exact unit arithmetic while separating an ideal transfer model from observed throughput.

## 4. Representing and preserving information

### [4.1. Formats compression checksums and metadata](<sections/4. Representing and preserving information/4.1. Formats compression checksums and metadata.md>)

1. **Distinguish a format from its name and metadata:** identify actual representation rules and embedded or external descriptive fields.
2. **Separate lossless compression from other transformations:** observe exact recovery and the possibility of a larger compressed representation.
3. **Use checksums as evidence of a defined byte sequence:** compare the intended bytes without inferring authenticity from a matching digest.

## 5. Applied interpretation

### [5.1. Read a machine specification and transfer estimate](<sections/5. Applied interpretation/5.1. Read a machine specification and transfer estimate.md>)

1. **Classify each specification before comparing machines:** separate counts, frequency, capacity and rate from unsupported workload conclusions.
2. **Build a transfer estimate with explicit assumptions:** compare overlapping and sequential stages using compatible representation sizes and rates.
3. **Turn an unsupported diagnosis into a useful next question:** identify the modeled bottleneck while distinguishing it from an observed failure cause.

## 6. Overlaps to avoid

### [6.1. Boundaries of hardware and representation vocabulary](<sections/6. Overlaps to avoid/6.1. Boundaries of hardware and representation vocabulary.md>)

1. **Keep the representation model separate from language mechanics:** route bytes, strings and numeric behavior to their existing detailed language owners.
2. **Route implementation and protection questions to their own scope:** identify the limits of resource labels, checksum evidence and vocabulary competence.
3. **Use a worked handoff without losing the unknowns:** split resource, comparison and timing claims into scoped evidence questions.
