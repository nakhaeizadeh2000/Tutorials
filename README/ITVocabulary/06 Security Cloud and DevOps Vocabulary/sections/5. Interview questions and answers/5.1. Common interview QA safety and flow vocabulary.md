## 5.1. Common interview Q&A: safety and flow vocabulary

### 1) **AuthN vs AuthZ**

*Prove-who vs decide-what — with the 401/403 tell.*

- **Q**: "What's the difference between authentication and authorization?"
- **Model answer**: "Authentication proves identity — passwords, SSO, keys: are you who you claim? Authorization decides permissions for that identity — roles and policies: may you do this? HTTP encodes it: 401 means authenticate, 403 means authorized-against. So I debug access failures by asking which half failed — credential reset for AuthN, role grant for AuthZ." (from [1.2](<../1. Safety words/1.2. Auth identity secrets and least privilege.md>))
- **What they are really testing**: the 401/403 tell — candidates who map the numbers to the halves have debugged access for real; candidates reciting definitions have read about it.

### 2) **How do you handle secrets**

*Vaulted, rotated, never in code — the three verbs.*

- **Q**: "How should applications manage secrets and API keys?"
- **Model answer**: "Vault them in a secret manager with audited access — never in code, env files in repos, or chat. Rotate on schedule and on suspicion or departure. On leak: revoke first, then clean history, then postmortem — because git history is forever, deletion without revocation is theater. Prefer short-lived credentials like OIDC over long-lived keys wherever the platform supports it."
- **What they are really testing**: revoke-first order — "delete the commit" answers fail; "invalidate, then clean, then learn" answers pass, because bots harvest leaked keys within minutes.

### 3) **CI/CD and incident walkthrough — plus rapid-fire drills**

*Pipeline in one paragraph, postmortem without blame.*

- **Q**: "Describe your CI/CD pipeline. Then walk me through your last incident."
- **Model answer**: "Every commit builds and tests automatically — unit, integration, e2e — and the same artifact promotes staging to prod; CD-delivery with human release decisions. Last incident: SEV2 checkout errors at 14:20 — declared in 5 min, graded by user impact, traced via metrics to a slow query from that morning's deploy, rolled back in 11 min, postmortem within 48h with three owned actions. No blame: the cause was systemic — missing index plus a gate that didn't check query plans." (from [2.1](<../2. Flow words/2.1. Pipeline observe and incident words.md>))
- **Rapid-fire drills** (one line each):
  - *Threat vs vulnerability?* — "Attacker intent vs my exploitable weakness — risk needs both paired."
  - *CVE vs CVSS?* — "Shared ID vs severity score — name it, then sort by score-times-reachability."
  - *Least privilege?* — "Minimum access for the job — every extra permission is future attacker leverage."
  - *Hotfix vs rollback?* — "Emergency forward (risky) vs emergency reverse (certain) — rollback first, fix calmly."
  - *Runbook?* — "Written playbook for known failures — diagnosis without inventing, rehearsed not shelved."
  - *Postmortem?* — "Blameless systemic learning with owned actions — blame ends reporting."

### 4) **Common confusion**

- "Incident stories should show heroics" — interviewers score declare-grade-communicate-learn, not midnight brilliance; calm process beats dramatic rescue.
- "Secrets answers need tool names" — Vault/AWS SM name-drops without the three verbs score zero; "vaulted, rotated, revoke-first" with zero brands scores full.
- "Postmortem questions invite blame-shifting" — the winning move is systemic framing ("the gate allowed it") with personal ownership of a fix ("I now check plans pre-merge").

### 5) **Mentor note**

Mock the incident walkthrough with a twist: interrupt mid-answer with "users are now tweeting — what changes?" Candidates who re-grade severity and adjust comms cadence (instead of freezing or accelerating blindly) demonstrate operate-temperament — the actual trait behind every vocabulary answer in this domain.
