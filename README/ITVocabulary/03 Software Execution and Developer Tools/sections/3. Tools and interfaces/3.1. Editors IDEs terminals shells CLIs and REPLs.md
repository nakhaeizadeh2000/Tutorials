## 3.1. Editors IDEs terminals shells CLIs and REPLs

A tutorial says “run this in your terminal,” but your screen shows Python's
`>>>` prompt. The window is a terminal, yet Python is currently reading the input.
Typing a shell command there sends it to the wrong interpreter. To recover, first
identify the program currently handling input.

Read the software-role and execution-environment lessons first. You need no paid
editor or IDE for the observation below; a terminal with Python installed is enough.

### 1) **Separate the editing application from the tools it launches**

A code **editor** lets you create and modify source files. An **IDE**, or
**integrated development environment**, combines editing with development
facilities such as project navigation, debugging and build integration. These
are overlapping product descriptions: an extensible editor can provide many
IDE-like capabilities. The useful question is what the installed environment
actually provides for your project.

Editing a file does not execute it. Saving a change also does not prove that a
running application reloaded it. An editor can launch checks or commands for you,
but those actions have their own inputs, configuration and results.

A **terminal emulator** provides a text input/output interface resembling a
terminal device. People commonly shorten this to “terminal.” It may be a standalone
application or a panel embedded in an editor. VS Code's official
[terminal introduction](https://code.visualstudio.com/docs/terminal/getting-started)
describes an integrated terminal that can use different installed shells. The
panel and the shell therefore have different responsibilities.

### 2) **Distinguish command interpretation from a command-line interface**

A **shell** interprets commands and coordinates running programs. Bash, Zsh and
PowerShell are examples with different languages and conventions. Do not assume
that a command written for one shell has identical meaning in another simply
because both appear in a similar-looking terminal window.

**CLI** means **command-line interface**: a way to operate a tool through commands
and arguments. A compiler, package manager or editor can expose a CLI. It need not
be a shell, and it can be invoked by automation without an interactive window.
A graphical application can have both a graphical interface and a CLI.

In `python3 -q`, the shell starts the Python command with the argument `-q`.
Python interprets that argument as “quiet startup.” The terminal displays the
interaction; the shell does not interpret subsequent Python statements while the
foreground Python session is reading them.

This separation also explains why a terminal can show an editor, a shell or a
language prompt at different times. Julia Evans's original
[terminal input investigation](https://jvns.ca/blog/2022/07/20/pseudoterminals/)
shows input and displayed output passing between terminal and running programs.
Its detailed pseudoterminal mechanisms are beyond this vocabulary lesson; the
useful habit is asking which component receives the next input.

### 3) **Recognize a REPL and the state of its session**

A **REPL** is a **read–eval–print loop**. It reads an input, evaluates it, presents
a result where appropriate, and waits for another input. It is often used to
explore a programming language interactively. Assignments may produce no displayed
result even though they change the session's state.

Tested environment: **Bash 5.3.9 and CPython 3.14.4 on Linux x86_64**. At a shell
prompt, run `python3 -q`. At the resulting `>>>` prompt, enter the three lines
shown below one at a time. Type only the text after `>>>`; those symbols are
Python's prompt, not part of the input.

```pycon
>>> value = 6
>>> value * 7
42
>>> exit()
```

The assignment stores `value` in this Python session. The next expression uses
it and displays 42. `exit()` ends the interactive interpreter and returns control
to the launching shell. The [Python interpreter tutorial](https://docs.python.org/3.14/tutorial/interpreter.html#interactive-mode)
documents the interactive prompt and the distinction from executing a script.
Our observed transcript used the basic REPL selected by `PYTHON_BASIC_REPL=1` in
the test environment; presentation can differ in an enhanced REPL, while the
three inputs and the result remain the point of this exercise.

For a fresh Python session, the assignment has to be entered again. State from
one interactive session is not automatically a saved source file. Conversely,
a file's execution context may differ from a REPL's special interactive handling.
Confirm a reported behavior in the actual file or application when that is the
environment you intend to support.

Practice: someone opens an integrated terminal, starts Python and then cannot
run a command intended for Bash. “Reinstall the editor” does not follow from that
evidence. Ask what prompt is visible and which program was started most recently.
If Python is reading the input, exit it before entering a shell command. This is
a change of input interpreter, not a change of terminal application.

### 4) **Common confusion**

Terminal, shell and CLI are not interchangeable names for a black rectangle.
The terminal handles the interaction surface, the shell interprets its own
command language, and a tool's CLI defines commands and arguments for that tool.
The prompt is a clue, but it is configurable; use the surrounding session context
too rather than recognizing software only by a color or symbol.

An editor extension suggesting an operation also does not prove the corresponding
compiler or runtime command succeeded. Locate the tool's actual result and the
version it used before drawing that conclusion.

### 5) **Performance note**

Typing in a terminal rather than clicking a button does not inherently make the
same underlying computation faster. Editor extensions, shell startup and command
execution have distinct costs. This lesson observes an interaction and a result;
it measures neither startup time nor developer productivity. Identify the slow
component before attributing a delay to the entire IDE.

### 6) **Mentor note**

Ask a learner to label three places: where the file is edited, where interaction
is displayed, and which program reads the next command. Then switch from shell
to REPL and back. A sound answer updates the input receiver while keeping the
terminal's role consistent, and explains which session holds `value`.
