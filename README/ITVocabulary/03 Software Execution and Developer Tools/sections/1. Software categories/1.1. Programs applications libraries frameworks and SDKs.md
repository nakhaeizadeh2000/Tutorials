## 1.1. Programs applications libraries frameworks and SDKs

You are asked to “install the SDK and add its library to the application.” That
sentence names different roles. The SDK helps you develop software, the library
supplies reusable behavior, and the application uses that behavior to accomplish
a task. One product can contain several of these things.

Read the first two domains before beginning. No framework installation is needed;
the small Python example below uses only its standard library.

### 1) **Distinguish a runnable purpose from a reusable capability**

A **program** is a set of instructions that a computer can execute through the
appropriate execution environment. An **application** is software organized to
serve a task, such as editing a document or producing a report. An application
can comprise multiple programs and other resources. People also use “program”
and “application” loosely for the same delivered tool; ask about the relevant
boundary rather than insisting every team uses these words identically.

A **library** supplies reusable capabilities for other code. An application might
call a library to calculate a value, decode an image or work with a file. An
**API**, or application programming interface, is a defined way for software to
interact with a capability. A library's callable operations form an API; an API
need not be a website or remote service.

Tested environment: **Python 3.14.4 on Linux x86_64**. Save this complete program
as `square_report.py` and run `python3 square_report.py` in that folder. No packages
need installation.

```python
import math

squares = 81
side = math.isqrt(squares)
print("Squares:", squares)
print("Whole-number side:", side)
```

Observed output:

```text
Squares: 81
Whole-number side: 9
```

The program chooses an input, calls a reusable operation, then prints a result.
`import math` makes Python's math module available; here **module** means a named
unit of code you can import. `math.isqrt` computes the integer square root of a
nonnegative integer, according to the
[Python math reference](https://docs.python.org/3.14/library/math.html#math.isqrt).
We use a perfect square so its result directly gives the side of a square made
of 81 unit squares.

Our tiny program is an application of that library capability. The `math` module
is part of Python's standard library, so it did not require a separate download.
A library being available does not mean your program calls every operation in it,
and a library does not have to be written in the same language as its caller.

### 2) **Recognize a framework by its coordinating role**

A **framework** supplies a structure for an application or a class of tasks.
You provide behavior at defined extension points, and the framework coordinates
when that behavior runs. A test framework, for example, can discover tests, invoke
them and report their results. Your test functions supply the task-specific part.

Compare these explicitly illustrative control descriptions:

| Arrangement | Who chooses the next application step? |
|---|---|
| Application calls a library calculation and uses its result | The application's surrounding code |
| Test framework chooses each discovered test and calls it | The framework's test-running machinery |

This coordinating relationship is a common example of **inversion of control**:
you supply behavior for infrastructure to invoke. Fowler's original
[Inversion of Control explanation](https://martinfowler.com/bliki/InversionOfControl.html)
uses control flow to distinguish framework use from ordinary library calls.
Here the term previews that relationship; design principles and dependency
injection receive their own later vocabulary lesson.

Do not classify every function that accepts another function as a complete
framework. A library can call your supplied function during a particular operation.
The useful question is which part of the application lifecycle and structure the
tool coordinates, not whether any call ever points back toward your code.
A framework can also expose libraries that you call directly.

### 3) **Read SDK and product labels as collections of roles**

**SDK** expands to **software development kit**. It is a collection intended to
help developers build for a platform or integrate a service. Depending on the
publisher, it may contain libraries, build or debugging tools, examples and
supporting material. The label alone does not tell you exactly what is installed
or what must accompany a delivered application.

For a concrete example, the Android SDK consists of multiple packages, including
command-line and build tools, described in the official
[Android tools guide](https://developer.android.com/tools). That does not make an
Android SDK the same thing as the application built with it. We are reading its
component roles here, not installing or configuring Android development tools.

Consider a constructed project note: “The editor is installed, the SDK can build
the project, and the application imports the image library.” These are three
separate facts. The editor lets a person work on files; the SDK supplies relevant
development capabilities; the application uses a library API. The note still does
not say that the application ran successfully or that every destination machine
contains its required execution environment.

A useful clarification is “Which SDK version and components are required to
build, and which library and runtime components are required to run the result?”
Record those requirements separately. Installing a large development kit on every
user machine by habit can conceal an unclear delivery requirement.

### 4) **Common confusion**

Library, framework and SDK are not three mutually exclusive file types. They
describe responsibilities and packaging conventions. A framework can arrive in
a package with supporting libraries; an SDK can include a framework; an
application can expose its own programming interface.

“API” is also broader than an HTTP endpoint. `math.isqrt` is a local programming
interface. Later API lessons add remote-message vocabulary without replacing
this general meaning.

### 5) **Performance note**

These labels do not establish execution cost. Library code may do substantial
work, and a framework may coordinate very little work for a particular request.
To compare cost, identify the executed operations, loading behavior and workload.
The square report verifies a result and call relationship, not speed or a universal
benefit from choosing one product category.

### 6) **Mentor note**

Ask a learner to draw arrows for the square report: application → library →
returned value → application output. Then ask how a test framework's invocation
of a test changes the coordinating role. A sound answer names the responsibility
at each step and allows one delivered product to contain several roles.
