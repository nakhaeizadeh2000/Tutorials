# Software Execution and Developer Tools

Learn what development tools consume, produce and prove, from source code to running software. Read [Reading and Using Technical Language](<../01 Reading and Using Technical Language/README.md>) and [Computers Data Representation and Units](<../02 Computers Data Representation and Units/README.md>) first. Examples introduce their tools without requiring a framework or package-manager setup.

This domain is in progress: 5 of 9 approved lessons are available.

## 1. Software categories

### [1.1. Programs applications libraries frameworks and SDKs](<sections/1. Software categories/1.1. Programs applications libraries frameworks and SDKs.md>)

1. **Distinguish a runnable purpose from a reusable capability:** explain program, application, library and API roles with a complete local example.
2. **Recognize a framework by its coordinating role:** trace which code chooses when application behavior is invoked.
3. **Read SDK and product labels as collections of roles:** separate development components from the requirements for running a delivered application.

### [1.2. Source code executables bytecode and artifacts](<sections/1. Software categories/1.2. Source code executables bytecode and artifacts.md>)

1. **Distinguish source text from execution representations:** compare machine code, executables and bytecode while retaining target requirements.
2. **Observe that preparing code is different from executing it:** run a complete fixed-source experiment without claiming it creates an executable file.
3. **Identify artifacts by their producer and intended consumer:** distinguish build outputs, declarations and reports from evidence of successful application execution.

## 2. From source to execution

### [2.1. Compiling interpreting transpiling and JIT](<sections/2. From source to execution/2.1. Compiling interpreting transpiling and JIT.md>)

1. **Describe compilation and interpretation as implementation steps:** trace input/output representations without assigning mutually exclusive language categories.
2. **Distinguish source transformation from runtime capabilities:** explain transpilation, type erasure and polyfill roles without assuming target support.
3. **Place JIT and failures on the execution timeline:** distinguish compilation timing and observe preparation versus execution failures.

### [2.2. Languages engines runtimes hosts and virtual machines](<sections/2. From source to execution/2.2. Languages engines runtimes hosts and virtual machines.md>)

1. **Separate a language definition from an executing implementation:** identify language, implementation and engine responsibilities without assuming one product per role.
2. **Distinguish runtime host and virtual-machine meanings:** interpret component versus phase and language-VM versus infrastructure-VM wording in context.
3. **Collect identity evidence without treating it as a capability test:** run a small metadata report and explain the operation-specific evidence still needed.

## 3. Tools and interfaces

### [3.1. Editors IDEs terminals shells CLIs and REPLs](<sections/3. Tools and interfaces/3.1. Editors IDEs terminals shells CLIs and REPLs.md>)

1. **Separate the editing application from the tools it launches:** distinguish editor, IDE and integrated terminal responsibilities.
2. **Distinguish command interpretation from a command-line interface:** identify shell language, tool arguments and the program currently receiving input.
3. **Recognize a REPL and the state of its session:** observe interactive evaluation and explain why its state differs from a saved file.
