# 5.1. Common interview QA design foundations

## 1. Method live under pressure (clarify, estimate, review — diagnosed with fixes, priced)

**Definition** — the method answer interviewers grade: given a prompt, run clarify-estimate-review with fixes ([1.1](<../../sections/1. Design thinking/1.1. Clarify estimate design review.md>)) — clarify proving (users naming — flows bounding (non-goals declining — fogging declining (proving owning — assuming declining); estimate proving (rates stating — storage sizing (bandwidth bounding — guessing declining (proving funding — shocking declining); review proving (bottlenecks naming — trade-offs pricing (honesty stating — praying declining (proving earning — bluffing declining). "Live" means diagnosed fixes (scopes naming — numbers stating — binders owning (proof stating — bluffing declining).

**What problem it solves** — the reciting trio: *method unrunning* (steps unlisted — phases unowned (designs diving — structures missing (unrunning billing — mastery failing); *scopes undescribing* (users unnamed — flows unbounded (non-goals undeclined — fog ruling (undescribing serving — hiring failing (knowledge hoping — depth doubting); *reviews unpricing* (bottlenecks unnamed — trade-offs unpriced (honesty unstated — bluffs ruling (unpricing charging — judgment missing). Pressured method converting diving to running (scopes clarifying — loads estimating (designs reviewing — answers holding); interviewers hearing method with numbers, not architectures (running proving → hirable; diving → passed) — drawing on [1.1](<../../sections/1. Design thinking/1.1. Clarify estimate design review.md>).

**Modern guidance** — the method lines (interview-enforced): *clarify scoping* (users naming — flows bounding (non-goals declining — fogging declining (scoping proving — diving refusing); *estimate numbering* (rates stating — storage sizing (bandwidth bounding — guessing declining (numbering funding — hoping refusing); *review owning* (bottlenecks naming — trade-offs pricing (honesty stating — praying declining (owning earning — bluffing refusing). Every answer carrying scope + numbers + review (judgment demonstrable — pressure survivable).

```typescript
// GOOD: method answers — scopes, numbers, reviews with diagnosed fixes (answer shape, hiring-grade).
// "1M readers with read-heavy flows, analytics out (scopes clarifying — fogging declining).
//  1k writes/s with 30-day retention (loads estimating — shocks declining).
//  Write-fanout binds at 10k/s with async fallback (binders naming — bluffing declining).")
```

```typescript
// BAD: method diving — architectures without scopes, claims without numbers (real fail shape).
// // "URL shortener with microservices." (users unnamed — flows unbounded — structures missing).
// // "Scales horizontally." (numbers missing — binders unnamed). Clarify scopes; state numbers; own reviews.)
```

**Common confusion** — *"starting with architecture answers method (boxes stating)."* Stating drawing boxes (diagrams sketching — components naming (flows implying — numbers missing (stating serving — owning failing); method running phases (scopes clarifying — loads estimating (designs reviewing — hope ending (running proving — diving declining). "Answering" describing judgments (users naming — bottlenecks owning); boxes describing pictures (diagrams sketching — meaning missing). Name users (readers counting — fogging ending); review honestly (binders naming — bluffing declining).

**Performance note** — method-answer economics: running costing phases (scopes clarifying — loads estimating (designs reviewing — answers holding); diving equivalents costing doubt (architectures unscoped — numbers missing (depth doubting — hiring failing). Run cheaply (phases — minutes); dive never (boxes — prompts).

**Mentor note** — drill "scope, numbers, review" (candidates answering per prompt with user boxes, load tables, and named binders defend method on first hearing; architecture-first answers interrogated ("users? QPS? binds?" — method demanding per prompt). Rehearse one full method once (clarify-estimate-review tangible (diving ending — running proving permanently). Bound flows; price trade-offs — method answers in three artifacts, reviewed per interview.

## 2. Numbers live under pressure (powers, latencies, quotas — honesty stated, not hoped)

**Definition** — the numbers answer interviewers grade: given a scale, compute it with bounds ([1.2](<../../sections/1. Design thinking/1.2. Back-of-envelope arithmetic.md>)/[2.1](<../../sections/2. Bottleneck thinking/2.1. Bottlenecks finding constraints.md>)) — powers proving (tens rounding — errors bounding (digits dropping — stalling declining (proving owning — modeling declining); latencies proving (nanos naming — millis budgeting (tails pricing — averaging declining (proving funding — guessing declining); quotas proving (QPS multiplying — bytes sizing (machines dividing — blobbing declining (proving earning — hoping declining). "Live" means honesty first (bounds stating — tables quoting — machines dividing (truth proving — precision declining).

**What problem it solves** — the hand-waving trio: *powers waving* (tens unrounded — errors unbounded (digits undropped — stalls scheduling (waving serving — hiring failing (numbers missing — judgment doubting); *latencies forgetting* (nanos unnamed — millis unbudgeted (tails unpriced — averages lying (forgetting owning — hardware failing (silence serving — planning missing); *quotas missing* (QPS unmultiplied — bytes unsized (machines undivided — blobs quotaing (missing charging — capacity hoping (hope serving — calibration failing). Pressured numbers converting waving to rounding (tens working — nanos naming (QPS multiplying — answers holding); interviewers hearing powers with machines, not adjectives (rounding proving → hirable; waving → passed) — drawing on [1.2](<../../sections/1. Design thinking/1.2. Back-of-envelope arithmetic.md>) and [2.1](<../../sections/2. Bottleneck thinking/2.1. Bottlenecks finding constraints.md>).

**Modern guidance** — the numbers lines (interview-enforced): *powers rounding* (tens working — errors bounding (digits dropping — stalling declining (rounding proving — modeling refusing); *latencies quoting* (nanos naming — millis budgeting (tails pricing — averaging declining (quoting funding — guessing refusing); *quotas dividing* (QPS multiplying — bytes sizing (machines dividing — blobbing declining (dividing owning — hoping refusing). Every claim carrying power + latency + machine (judgment demonstrable — pressure survivable).

```typescript
// GOOD: numbers answers — powers, latencies, machines with bounded errors (answer shape, hiring-grade).
// "100k rounded with +/-2x stated (powers rounding — errors bounding).
//  RAM 100ns with p99 at 5x mean (latencies quoting — tails pricing).
//  500 slots into 5 machines of 100 (quotas dividing — capacity planning).")
```

```typescript
// BAD: numbers waving — adjectives without powers, comfort without machines (real fail shape).
// // "High throughput." (tens unrounded — errors unbounded — numbers missing).
// // "A few servers." (machines undivided — blobs quotaing). Round powers; quote latencies; divide machines.)
```

**Common confusion** — *"exact numbers answer arithmetic (precision performing)."* Performing defending decimals (digits displaying — spreadsheets modeling (rigor theatering — speed dying (performing charging — judgment failing); numbers bounding orders (powers rounding — latencies quoting (machines dividing — capacity planning (numbering proving — waving declining). "Exact" describing theater (decimals defending — speed dying); arithmetic describing bounds (tens working — errors stating). Work tens (orders rounding — stalls ending); admit factors (errors bounding — bluffing ending).

**Performance note** — numbers-answer economics: rounding costing seconds (powers working — latencies quoting (machines dividing — answers holding); waving equivalents costing doubt (adjectives floating — numbers missing (judgment doubting — hiring failing). Round cheaply (powers — latencies); wave never (adjectives — quotas).

**Mentor note** — drill "power, latency, machine" (candidates answering per scale with rounded orders, quoted nanos, and divided fleets defend numbers on first hearing; "high throughput" interrogated ("which power? which p99? how many?" — numbers demanding per claim). Rehearse one computation once (power-latency-machine tangible (waving ending — rounding proving permanently). Bound errors; scale tails — numbers answers in three honesty, reviewed per interview.

## 3. Safety live under pressure (points, copies, correlations — ownership stated, not hoped)

**Definition** — the safety answer interviewers grade: given a failure, name the SPOF with copies ([3.1](<../../sections/3. First safety/3.1. Single points removing redundancy.md>)) — points proving (instances counting — zones mapping (blasts sizing — hoping declining (proving owning — hiding declining); copies proving (replicas numbering — failovers rehearsing (brains splitting — singling declining (proving funding — total declining); correlations proving (faults diversifying — deploys staggering (clocks skewing — coupling declining (proving earning — common-moding declining). "Live" means ownership stated (singletons listing — replicas numbering — axes diversifying (proof stating — total declining).

**What problem it solves** — the claiming trio: *points claiming* (singletons unnamed — zones unmapped (blasts unsized — totals risking (claiming serving — hiring failing (names missing — proof doubting); *copies missing* (replicas unnumbered — failovers unrehearsed (brains unsplit — data diverging (missing owning — redundancy bluffing (silence serving — safety theatering); *correlations hoping* (faults undiversified — deploys unstaggered (clocks unskewed — fates coupling (hoping serving — evidence failing). Pressured safety converting claiming to listing (singletons counting — replicas numbering (faults diversifying — answers holding); interviewers hearing points with copies, not assurances (listing proving → hirable; claiming → passed) — drawing on [3.1](<../../sections/3. First safety/3.1. Single points removing redundancy.md>).

**Modern guidance** — the safety lines (interview-enforced): *points listing* (instances counting — zones mapping (blasts sizing — hoping declining (listing proving — hiding refusing); *copies numbering* (replicas provisioning — failovers rehearsing (brains splitting — singling declining (numbering owning — total refusing); *correlations breaking* (faults diversifying — deploys staggering (clocks skewing — coupling declining (breaking owning — common-moding refusing). Every claim carrying point + copy + axis (judgment demonstrable — pressure survivable).

```typescript
// GOOD: safety answers — points, copies, correlations with owned failures (answer shape, hiring-grade).
// "Primary-db solo across 1 zone (points listing — totals risking).
//  Tripled across 3 zones with rehearsed failover (copies numbering — cuts succeeding).
//  Deploys staggered with skewed clocks (correlations breaking — fates decoupling).")
```

```typescript
// BAD: safety claiming — assurances without points, copies without rehearsal (real fail shape).
// // "Highly available." (singletons unnamed — zones unmapped — names missing).
// // "Replicated." (failovers unrehearsed — brains unsplit). List points; number copies; break correlations.)
```

**Common confusion** — *"redundancy answers safety (copies stating)."* Stating counting replicas (numbers floating — rehearsals missing (failovers unproved — cuts fumbling (stating serving — owning failing); safety owning failures (points listing — copies numbering (correlations breaking — totals preventing (owning proving — claiming declining). "Redundancy" describing counts (replicas numbering — rehearsals missing); safety describing proof (failovers rehearsing — axes diversifying). Number odd (quorums requiring — ties breaking); diversify causes (suppliers mixing — fate decoupling).

**Performance note** — safety-answer economics: listing costing rows (points counting — copies numbering (correlations breaking — answers holding); claiming equivalents costing doubt (assurances floating — artifacts missing (proof doubting — hiring failing). List cheaply (points — SPOFs); claim never (assurances — safety).

**Mentor note** — drill "point, copy, axis" (candidates answering per failure with listed singletons, numbered replicas, and broken correlations defend safety on first hearing; "highly available" interrogated ("SPOF? copies? shared fate?" — safety demanding per claim). Rehearse one SPOF story once (point-copy-axis tangible (claiming ending — listing proving permanently). Provision standbys; offset clocks — safety answers in three ownerships, reviewed per interview.
