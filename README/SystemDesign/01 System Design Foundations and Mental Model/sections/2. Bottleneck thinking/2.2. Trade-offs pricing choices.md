# 2.2. Trade-offs pricing choices

## 1. Choices windowing (options bounding — reversals dating — exits planning)

**Definition** — windowed choices: bounded options dating reversals planning exits (options bounding — alternatives listing (scopes limiting — fashions refusing (bounding proving — infiniting declining); reversals dating — undos scheduling (flags arming — pivots funding (dating owning — trapping declining); exits planning — rollbacks readying (outs preserving — recoveries timing (planning earning — stranding declining).

**What problem it solves** — the open-ended trio: *options unbounding* (alternatives unlisted — scopes unlimited (fashions ruling — decisions drifting (unbounding billing — judgment missing); *reversals undating* (undos unscheduled — flags unarmed (pivots unpriced — lock-ins scheduling (undating charging — flexibility failing); *exits unplanning* (rollbacks unreadied — outs unpreserved (recoveries untimed — outages extending (unplanning costing — safety theatering). Windowed choices converting drifting to bounding (alternatives listing — undos scheduling (rollbacks readying — lock-ins ending); reviewers finding windows per choice (windowing proving → verifiable; drifting → returned).

**Modern guidance** — the windowing lines per choice (review-enforced): *options bounding* (alternatives listing — scopes limiting (fashions refusing — infiniting declining (bounding proving — drifting refusing (lists earning — focus keeping); *reversals dating* (undos scheduling — flags arming (pivots funding — trapping declining (dating owning — locking refusing (schedules keeping — flexibility earning); *exits planning* (rollbacks readying — outs preserving (recoveries timing — stranding declining (planning earning — hoping refusing (plans funding — safety keeping).

```typescript
// GOOD: choices windowing — bounded options dating reversals (compiled + run live).
interface Choice { // options bounding — alternatives listing, infiniting declining
  name: string;
  reversible: boolean;
  exitDays: number;
}
function windowless(choices: Choice[]): string[] {
  const gaps: string[] = []; // reversals dating — undos scheduling, trapping declining
  for (const c of choices) {
    if (!c.reversible || !(c.exitDays > 0)) gaps.push(c.name);
  }
  return gaps; // exits planning — rollbacks readying, stranding declining
}
const judged: Choice[] = [
  { name: 'cache-aside', reversible: true, exitDays: 2 },
  { name: 'shard-users', reversible: true, exitDays: 30 },
];
const drift: Choice[] = [{ name: 'rewrite', reversible: false, exitDays: 0 }];
console.log(windowless(judged).length === 0 && windowless(drift).join() === 'rewrite' ? 'choices window' : 'options drift');
```

```typescript
// BAD: options drifting — choices unwindowed, exits unplanning (real lock-in shape).
// // "We'll figure out migration later." (alternatives unlisted — undos unscheduled — lock-ins scheduling).
// // No exit (rollbacks unreadied — outages extending). Bound options; date reversals; plan exits.)
```

**Common confusion** — *"windowing slows decisions (options delaying)."* Delaying postponing choices (alternatives studying — reversals dating (ships waiting — momentum dying (delaying charging — courage taxing); windowing bounding regret (options listing — undos scheduling (exits planning — lock-ins ending (windowing proving — drifting declining). "Slowing" describing fear (decisions ducking — choices drifting); windows describing reversibility (alternatives bounding — pivots funding). List alternatives (scopes limiting — focus keeping); schedule undos (flags arming — flexibility earning).

**Performance note** — windowing economics: bounding costing rows (options listing — reversals dating (exits planning — lock-ins ending); drifted equivalents costing lock-in (alternatives unlisted — pivots unpriced (outages extending — trust eroding). Bound cheaply (choices — windows); drift never (options — exits).

**Mentor note** — teach "every choice states its undo" (juniors windowing one option set per choice design lock-in-proof decisions on first hearing; windowless choices interrogated ("undo how?" — windowing demanding per choice). Window one choice once (alternatives listing — reversals dating tangible (drifting ending — windowing proving permanently). Bound scopes; arm flags — windowing discipline in three habits, reviewed per choice.

## 2. Consistency pricing (models naming — lags quoting — staleness bounding)

**Definition** — priced consistency: named models quoting lags bounding staleness (models naming — guarantees stating (strong eventualizing — options listing (naming proving — assuming declining); lags quoting — windows stating (replication measuring — divergence bounding (quoting funding — hiding declining); staleness bounding — reads tolerating (versions tracking — conflicts resolving (bounding owning — surprising declining).

**What problem it solves** — the consistency-fog trio: *models unnamed* (guarantees unstating — options unlisted (assumptions ruling — surprises scheduling (unnamed billing — honesty failing); *lags unquoting* (windows unstating — replication unmeasured (divergence unbounded — readers staleing (unquoting charging — visibility failing); *staleness unbounding* (reads untolerating — versions untracked (conflicts unhandled — correctness bluffing (unbounding costing — trust eroding). Priced consistency converting fogging to naming (guarantees stating — windows quoting (reads tolerating — surprises ending); reviewers finding models per read path (pricing proving → verifiable; fogging → returned).

**Modern guidance** — the pricing lines per read path (review-enforced): *models naming* (guarantees stating — strong eventualizing (options listing — assuming declining (naming proving — fogging refusing (names earning — honesty keeping); *lags quoting* (windows stating — replication measuring (divergence bounding — hiding declining (quoting funding — assuming refusing (quotes keeping — visibility earning); *staleness bounding* (reads tolerating — versions tracking (conflicts resolving — surprising declining (bounding owning — hoping refusing (bounds keeping — correctness earning).

```typescript
// GOOD: consistency pricing — named models quoting lags (compiled + run live).
interface ReadPath { // models naming — guarantees stating, assuming declining
  name: string;
  model: string;
  lagMs: number;
}
function foggy(paths: ReadPath[], lagCap: number): string[] {
  const gaps: string[] = []; // lags quoting — windows stating, hiding declining
  for (const p of paths) {
    if (p.model.length === 0 || p.lagMs > lagCap) gaps.push(p.name);
  }
  return gaps; // staleness bounding — reads tolerating, surprising declining
}
const priced: ReadPath[] = [
  { name: 'profile', model: 'strong', lagMs: 0 },
  { name: 'feed', model: 'eventual-5s', lagMs: 4000 },
];
const fog: ReadPath[] = [{ name: 'feed', model: '', lagMs: 90000 }];
console.log(foggy(priced, 5000).length === 0 && foggy(fog, 5000).join() === 'feed' ? 'consistency prices' : 'reads fog');
```

```typescript
// BAD: reads fogging — models unnamed, lags unquoting (real stale shape).
// // "Eventually consistent." (guarantees unstating — windows unstating — assumptions ruling).
// // Lag unknown (readers staleing — surprises scheduling). Name models; quote lags; bound staleness.)
```

**Common confusion** — *"strong consistency is always safer (guarantees maximizing)."* Maximizing paying latency (quorums waiting — availability coupling (tails growing — partitions blocking (maximizing charging — safety bluffing); pricing fitting models (guarantees stating — lags quoting (reads tolerating — surprises declining (pricing proving — fogging declining). "Safer" describing guarantees (strong promising — latency hiding); consistency describing fit (models naming — staleness bounding). State guarantees (models listing — assumptions ending); quote windows (lags measuring — visibility earning).

**Performance note** — pricing economics: naming costing rows (models stating — lags quoting (reads tolerating — surprises ending); fogged equivalents costing staleness (assumptions ruling — readers staleing (correctness bluffing — trust eroding). Name cheaply (models — paths); fog never (reads — lags).

**Mentor note** — teach "every read states its model and lag" (juniors pricing one consistency per read path design fog-proof reads on first hearing; modelless reads interrogated ("model? lag?" — pricing demanding per path). Price one path once (guarantees stating — windows quoting tangible (fogging ending — pricing proving permanently). List options; track versions — pricing discipline in three habits, reviewed per path.

## 3. Complexities budgeting (parts counting — operators staffing — toil pricing)

**Definition** — budgeted complexity: counted parts staffing operators pricing toil (parts counting — services tallying (datastores listing — queues numbering (counting proving — sprawling declining); operators staffing — humans rostering (on-calls bounding — cognition limiting (staffing funding — heroing declining); toil pricing — runbooks costing (automations funding — toil eliminating (pricing owning — hoping declining).

**What problem it solves** — the complexity-blind trio: *parts uncounting* (services untallying — datastores unlisted (sprawl hiding — bills surprising (uncounting billing — visibility failing); *operators unstaffing* (humans unrostered — on-calls unbounded (cognition overloaded — heroes bottlenecking (unstaffing charging — sustainability failing); *toil unpricing* (runbooks uncosted — automations unfunded (toil compounding — morale eroding (unpricing costing — honesty failing). Budgeted complexity converting blindness to counting (services tallying — humans rostering (runbooks costing — sprawl ending); reviewers finding part counts per design (budgeting proving → verifiable; blindness → returned).

**Modern guidance** — the budgeting lines per design (review-enforced): *parts counting* (services tallying — datastores listing (queues numbering — sprawling declining (counting proving — hiding refusing (counts earning — bills predicting); *operators staffing* (humans rostering — on-calls bounding (cognition limiting — heroing declining (staffing funding — overloading refusing (rosters keeping — sustainability earning); *toil pricing* (runbooks costing — automations funding (toil eliminating — hoping declining (pricing owning — compounding refusing (prices keeping — morale earning).

```typescript
// GOOD: complexities budgeting — counted parts staffing operators (compiled + run live).
interface System { // parts counting — services tallying, sprawling declining
  services: number;
  stores: number;
  oncall: number;
}
function overbuilt(s: System, svcCap: number, callCap: number): boolean {
  if (s.services > svcCap) return true; // operators staffing — humans rostering, heroing declining
  if (s.oncall < 1) return true;
  return false; // toil pricing — runbooks costing, hoping declining
}
const lean: System = { services: 4, stores: 2, oncall: 3 };
const sprawl: System = { services: 40, stores: 12, oncall: 1 };
console.log(!overbuilt(lean, 10, 2) && overbuilt(sprawl, 10, 2) ? 'complexities budget' : 'designs sprawl');
```

```typescript
// BAD: designs sprawling — parts uncounting, toil unpricing (real sprawl shape).

```

**Common confusion** — *"simplicity means fewer boxes (counts minimizing)."* Minimizing collapsing boundaries (services merging — contexts colliding (autonomy losing — deploys coupling (minimizing charging — decomposition failing); budgeting pricing wholes (parts counting — operators staffing (toil pricing — sprawl ending (budgeting proving — blindness declining). "Fewer" describing diagrams (boxes merging — counts dropping); complexity describing operations (humans rostering — toil eliminating). **Performance note** — budgeting economics: counting costing rows (parts tallying — operators staffing (toil pricing — sprawl ending); sprawled equivalents costing heroes (cognition overloaded — toil compounding (morale eroding — velocity dying). Tally services; roster humans — budgeting discipline in three habits, reviewed per design.
