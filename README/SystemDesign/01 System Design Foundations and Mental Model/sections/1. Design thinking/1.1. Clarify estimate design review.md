# 1.1. Clarify estimate design review

## 1. Scopes clarifying (users naming — flows bounding — non-goals declining)

**Definition** — clarified scope: named users bounding flows declining non-goals (users naming — readers counting (writers scoping — actors listing (naming proving — everybody declining); flows bounding — journeys tracing (reads separating — writes isolating (bounding funding — everything declining); non-goals declining — exclusions stating (v2 deferring — scope protecting (declining owning — creeping declining).

**What problem it solves** — the solve-everything trio: *users unnamed* (readers uncounted — writers unscoped (everybody assumed — nobody served (unnamed billing — designing failing); *flows unbounded* (journeys untraced — reads unseparated (everything in-scope — nothing shippable (unbounded charging — focus failing); *non-goals undeclined* (exclusions unstated — v2 undeferred (scope creeping — interviews derailing (undeclined costing — time bleeding). Clarified scope converting everything to naming (readers counting — journeys tracing (exclusions stating — focus earning); reviewers finding scope boxes per design (clarifying proving → verifiable; everything → returned).

**Modern guidance** — the clarifying lines per design (review-enforced): *users naming* (readers counting — writers scoping (actors listing — everybody declining (naming proving — assuming refusing (names earning — focus keeping); *flows bounding* (journeys tracing — reads separating (writes isolating — everything declining (bounding funding — tracing refusing (bounds owning — shippable earning); *non-goals declining* (exclusions stating — v2 deferring (scope protecting — creeping declining (declining owning — derailing refusing (statements funding — time keeping).

```typescript
// GOOD: scopes clarifying — named users bounding flows (compiled + run live).
interface Scope { // users naming — readers counting, everybody declining
  users: number;
  flows: string[];
  nonGoals: string[];
}
function vague(s: Scope): string[] {
  const gaps: string[] = []; // flows bounding — journeys tracing, everything declining
  if (!(s.users > 0)) gaps.push('users');
  if (s.flows.length === 0) gaps.push('flows');
  if (s.nonGoals.length === 0) gaps.push('non-goals'); // non-goals declining — exclusions stating, creeping declining
  return gaps;
}
const tight: Scope = { users: 1000000, flows: ['read', 'write'], nonGoals: ['analytics'] };
const fog: Scope = { users: 0, flows: [], nonGoals: [] };
console.log(vague(tight).length === 0 && vague(fog).join() === 'users,flows,non-goals' ? 'scopes clarify' : 'designs fog');
```

```typescript
// BAD: designs fogging — users unnamed, non-goals undeclined (real derail shape).
// // "Design Twitter." (readers uncounted — journeys untraced — everything in-scope).
// // No exclusions (scope creeping — interviews derailing). Name users; bound flows; decline non-goals.)
```

**Common confusion** — *"clarifying wastes design time (questions delaying)."* Delaying postponing sketches (questions asking — answers waiting (minutes spending — designs pausing (delaying charging — speed missing); clarifying bounding rework (users naming — flows bounding (non-goals declining — derails preventing (clarifying proving — fogging declining). "Wasting" describing minutes (questions asking — speed missing); scope describing focus (readers counting — journeys tracing). Ask users (actors listing — everybody declining); state exclusions (v2 deferring — scope protecting).

**Performance note** — clarifying economics: naming costing questions (users counting — flows bounding (non-goals declining — focus earning); foggy equivalents costing derails (everything in-scope — nothing shippable (interviews derailing — time bleeding). Ask cheaply (scopes — minutes); fog never (designs — interviews).

**Mentor note** — teach "scope box before sketches" (juniors clarifying one user-flow-exclusion triple per design on first hearing; foggy starts interrogated ("users? flows? non-goals?" — clarifying demanding per design). Clarify one scope once (readers counting — journeys tracing tangible (fogging ending — clarifying proving permanently). ## 2. Loads estimating (rates stating — storage sizing — bandwidth bounding)

**Definition** — estimated load: stated rates sizing storage bounding bandwidth (rates stating — QPS quoting (reads splitting — writes counting (stating proving — guessing declining); storage sizing — bytes multiplying (retention bounding — growth modeling (sizing funding — hoping declining); bandwidth bounding — bits rating (egress pricing — ingress capping (bounding owning — blowing declining).

**What problem it solves** — the numberless trio: *rates unstating* (QPS unquoted — reads unsplit (capacity unplanned — servers surprising (unstating billing — arithmetic failing); *storage unsizing* (bytes unmultiplied — retention unbounded (disks filling — growth hoping (unsizing charging — planning missing); *bandwidth unbounding* (bits unrated — egress unpriced (bills shocking — pipes saturating (unbounding costing — economics bluffing). Estimated loads converting guessing to stating (QPS quoting — bytes multiplying (bits rating — capacity planning); reviewers finding load tables per design (estimating proving → verifiable; numberless → returned).

**Modern guidance** — the estimating lines per design (review-enforced): *rates stating* (QPS quoting — reads splitting (writes counting — guessing declining (stating proving — hoping refusing (quotes earning — capacity planning); *storage sizing* (bytes multiplying — retention bounding (growth modeling — hoping declining (sizing funding — filling refusing (products keeping — disks earning); *bandwidth bounding* (bits rating — egress pricing (ingress capping — blowing declining (bounding owning — shocking refusing (rates funding — economics keeping).

```typescript
// GOOD: loads estimating — stated rates sizing storage (compiled + run live).
function dailyWrites(qps: number): number {
  return qps * 86400; // rates stating — QPS quoting, guessing declining
}
function storageBytes(daily: number, bytesEach: number, days: number): number {
  return daily * bytesEach * days; // storage sizing — bytes multiplying, hoping declining
}
function egressGbps(qps: number, bytesEach: number): number {
  return (qps * bytesEach * 8) / 1e9; // bandwidth bounding — bits rating, blowing declining
}
const writes = dailyWrites(1000);
console.log(writes === 86400000 && storageBytes(writes, 1000, 365) === 86400000 * 1000 * 365 && egressGbps(1000, 1000) === 0.008 ? 'loads estimate' : 'numbers guess');
```

```typescript
// BAD: numbers guessing — rates unstating, bandwidth unbounding (real shock shape).
// // "Lots of traffic." (QPS unquoted — capacity unplanned — servers surprising).
// // Egress unknown (bills shocking — pipes saturating). State rates; size storage; bound bandwidth.)
```

**Common confusion** — *"estimates must be precise (digits demanding)."* Demanding counting exactly (spreadsheets modeling — decimals defending (time spending — accuracy theatering (demanding charging — speed failing); estimating bounding orders (powers rounding — errors stating (digits dropping — decisions funding (estimating proving — guessing declining). "Precise" describing theater (decimals defending — speed failing); loads describing bounds (rates stating — storage sizing). Quote powers (tens working — errors bounding); drop digits (precision declining — decisions funding).

**Performance note** — estimating economics: stating costing arithmetic (QPS quoting — bytes multiplying (bits rating — capacity planning); numberless equivalents costing shocks (servers surprising — disks filling (bills shocking — trust eroding). State cheaply (loads — minutes); shock never (designs — bills).

**Mentor note** — teach "three numbers before sketches" (juniors estimating one rate-storage-bandwidth triple per design design shock-proof loads on first hearing; numberless designs interrogated ("QPS? bytes? bits?" — estimating demanding per design). Estimate one load once (rates stating — storage sizing tangible (guessing ending — estimating proving permanently).
```typescript
// GOOD: designs reviewing — named bottlenecks pricing trade-offs (compiled + run live).
interface Review { // bottlenecks naming — constraints binding, blobbing declining
  bottleneck: string;
  price: number;
  limit: string;
}
function handwaved(reviews: Review[]): string[] {
  const gaps: string[] = []; // trade-offs pricing — choices windowing, handwaving declining
  for (const r of reviews) {
    if (r.bottleneck.length === 0 || !(r.price >= 0) || r.limit.length === 0) gaps.push('vague');
  }
  return gaps; // honesty stating — limits owning, bluffing declining
}
const crisp: Review[] = [{ bottleneck: 'write-fanout', price: 140, limit: '10k-writes/s' }];
const vague: Review[] = [{ bottleneck: '', price: NaN, limit: '' }];
console.log(handwaved(crisp).length === 0 && handwaved(vague).join() === 'vague' ? 'designs review' : 'sketches pray');
```
