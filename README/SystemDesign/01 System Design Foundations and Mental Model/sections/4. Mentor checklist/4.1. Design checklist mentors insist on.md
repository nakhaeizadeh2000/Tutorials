# 4.1. Design checklist mentors insist on

## 1. Every scope clarifying (users naming — loads estimating — designs reviewing)

**Definition** — the scope line on every design: users proving (readers counting — flows bounding (non-goals declining — fogging declining (proving owning — assuming declining); loads proving (rates stating — storage sizing (bandwidth bounding — guessing declining (proving funding — shocking declining); designs proving (bottlenecks naming — trade-offs pricing (honesty stating — praying declining (proving earning — bluffing declining).

**What problem it solves** — the unscoped trio: *users unnamed* (readers uncounted — flows unbounded (non-goals undeclined — fog ruling (unnamed billing — focus failing); *loads unestimated* (rates unstated — storage unsized (bandwidth unbound — shocks scheduling (unestimated charging — arithmetic failing); *designs unreviewed* (bottlenecks unnamed — trade-offs unpriced (honesty unstated — bluffs ruling (unreviewed costing — calibration failing). Clarified scopes converting fogging to proving (readers counting — rates stating (bottlenecks naming — focus earning); reviewers finding scope triples per design (clarifying proving → verifiable; fogging → returned).

**Modern guidance** — the clarifying lines per design (review-enforced): *users proving* ([1.1](<../../sections/1. Design thinking/1.1. Clarify estimate design review.md>) — readers counting (flows bounding — non-goals declining (proving owning — assuming refusing); *loads proving* ([1.1](<../../sections/1. Design thinking/1.1. Clarify estimate design review.md>) — rates stating (storage sizing — bandwidth bounding (proving funding — guessing refusing); *designs proving* ([1.1](<../../sections/1. Design thinking/1.1. Clarify estimate design review.md>) — bottlenecks naming (trade-offs pricing — honesty stating (proving earning — bluffing refusing).

```typescript
// GOOD: every scope clarifying — users, loads, reviews per design (process shape, reviewed).
// - Users named with bounded flows (readers counting — journeys tracing — non-goals declining).
// - Loads estimated with sized storage (rates stating — bytes multiplying — egress bounding).
// - Designs reviewed with named bottlenecks (constraints binding — prices attaching — limits owning.)
```

```typescript
// BAD: scopes fogging — users unnamed, loads unestimated, designs unreviewed (real derail shape).
// // "Design YouTube." (readers uncounted — flows unbounded — fog ruling).
// // No numbers (shocks scheduling — arithmetic failing). Name users; state loads; review designs.)
```

**Common confusion** — *"clarifying is analysis-paralysis (questions delaying)."* Delaying postponing sketches (questions asking — answers waiting (minutes spending — designs pausing (delaying charging — speed missing); clarifying bounding rework (users naming — loads estimating (designs reviewing — derails preventing (clarifying proving — fogging declining). "Paralysis" describing fear (decisions ducking — scopes drifting); scope describing focus (readers counting — journeys tracing). Count readers; state rates — clarifying discipline in three habits, reviewed per design.

**Performance note** — clarifying-check economics: naming costing questions (users counting — loads estimating (designs reviewing — focus earning); fogged equivalents costing derails (everything in-scope — shocks scheduling (bluffs ruling — trust eroding). Ask cheaply (scopes — minutes); fog never (designs — interviews).

**Mentor note** — teach "scope, load, review — every design" (juniors owning per design shock-proof scopes on first hearing; scopeless designs interrogated ("users? numbers? bottleneck?" — clarifying demanding per design). Clarify one scope once (readers counting — rates stating tangible (fogging ending — clarifying proving permanently). Bound flows; price trade-offs — clarifying discipline in three habits, reviewed per design.

Named bottlenecks converting fogging to proving (tiers decomposing — slowest naming (probes planning — focus earning); reviewers finding binders per design (naming proving → verifiable; fogging → returned).

**Common confusion** — *"naming is pessimism (binders depressing)."* Depressing forecasting limits (ceilings stating — cliffs dating (growth bounding — ambition taxing (depressing charging — morale failing); naming focusing effort (slowest owning — optimizers targeting (alarms setting — waste ending (naming proving — diffusing declining). ## 3. Every failure pricing (choices windowing — copies adding — correlations breaking)

**Definition** — the failure line on every design: choices proving (options bounding — reversals dating (exits planning — drifting declining (proving owning — locking declining); copies proving (replicas numbering — failovers rehearsing (brains splitting — singling declining (proving funding — total declining); correlations proving (faults diversifying — deploys staggering (clocks skewing — coupling declining (proving earning — common-moding declining).

**What problem it solves** — the unpriced trio: *choices unwindowed* (options unbounded — reversals undated (exits unplanned — lock-ins scheduling (unwindowed billing — judgment missing); *copies unadded* (replicas unnumbered — failovers unrehearsed (brains unsplit — totals risking (unadded charging — redundancy hoping); *correlations unbroken* (faults undiversified — deploys unstaggered (clocks unskewed — fates coupling (unbroken costing — common-modes hiding). Priced failures converting hoping to proving (options bounding — replicas numbering (faults diversifying — lock-ins ending); reviewers finding priced failures per design (pricing proving → verifiable; hoping → returned).

**Modern guidance** — the pricing lines per design (review-enforced): *choices proving* ([2.2](<../../sections/2. Bottleneck thinking/2.2. Trade-offs pricing choices.md>) — options bounding (reversals dating — exits planning (proving owning — locking refusing); *copies proving* ([3.1](<../../sections/3. First safety/3.1. Single points removing redundancy.md>) — replicas numbering (failovers rehearsing — brains splitting (proving funding — singling refusing); *correlations proving* ([3.1](<../../sections/3. **Common confusion** — *"pricing failures is pessimism (risks depressing)."* Depressing enumerating dooms (failures listing — morale dipping (velocity slowing — ambition taxing (depressing charging — courage failing); pricing bounding regret (options bounding — replicas numbering (faults diversifying — lock-ins ending (pricing proving — hoping declining). "Pessimism" describing mood (dooms listing — morale dipping); failures describing budgets (windows stating — copies provisioning). Bound windows (choices limiting — pivots funding); diversify causes (suppliers mixing — fate decoupling).

**Performance note** — pricing-check economics: bounding costing rows (choices windowing — copies numbering (correlations breaking — lock-ins ending); hoped equivalents costing lock-in (surprises scheduling — totals risking (common-modes hiding — trust eroding). Bound cheaply (failures — designs); hope never (choices — copies).

**Mentor note** — convert this leaf into the team's design runbook: users, loads, reviews, layers, binders, probes, windows, copies, correlations — every design, every bottleneck, every failure. Quiz juniors on sight ("which users? which binder? which SPOF?") until answers are environmental. Watch for checklist decay (design discipline for a sprint, abandoned under deadline — fix with gates as review-blocking) and ceremony-theater ("checklist completed" without artifacts — fix with proof demands per item: scopes clarifying, bottlenecks naming, failures pricing). Review check: scopes clarifying, bottlenecks naming, failures pricing — and the mentor's own designs modeling all three visibly.
