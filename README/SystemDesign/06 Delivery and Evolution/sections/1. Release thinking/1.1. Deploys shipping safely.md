# 1.1. Deploys shipping safely

## 1. Ships sequencing (expands phasing — deploys decoupling — cliffs refusing)

**Definition** — sequenced ships: phasing expands decoupling deploys refusing cliffs (expands phasing — additive shapes first (tables adding — columns nulling (phasing proving — stopping declining); deploys decoupling — code versions overlapping (old tolerating — new requiring (decoupling funding — flagging declining); cliffs refusing — single cutovers declining (fleets fractioning — traffic shifting (refusing owning — scheduling declining).

**What problem it solves** — the cliff-deploy trio: *expands unphasing* (alters locking — writes blocking (downtimes scheduling — users waiting (unphasing billing — availability failing); *deploys coupling* (schema locking code — versions training (ships coordinating — rollbacks panicking (coupling charging — autonomy dying); *cliffs scheduled* (fleets flipping — traffic cutting (releases banging — incidents dating (scheduling costing — safety failing). Sequenced ships converting cliffs to phases (expands adding — deploys overlapping (cuts refusing — downtimes declining); reviewers finding phase rows per release (sequencing proving → verifiable; cliffing → returned).

Discipline/2.2. Migrations basis.md>) — code versions overlapping (old tolerating — new requiring (decoupling funding — flagging refusing (overlaps keeping — atomics ending); *cliffs refusing* ([Microservices 06/1.1](<../../../../Microservices/06 Service Operations and Deployment/sections/1.
```typescript
// GOOD: ships sequencing — expands phasing, deploys decoupling (compiled + run live).
type ShipPhase = 'expand' | 'overlap' | 'contract';
function phaseFor(step: number): ShipPhase {
  if (step <= 0) return 'expand'; // expands phasing — news adding, locks declining
  if (step === 1) return 'overlap'; // deploys decoupling — old tolerating, flagging declining
  return 'contract'; // cliffs refusing — olds removing-last, flipping declining
}
console.log(phaseFor(0) === 'expand' && phaseFor(1) === 'overlap' && phaseFor(2) === 'contract' ? 'ships sequence' : 'ships cliff');
```

```typescript
// // One deploy renames the column (locks holding — mixed versions crashing — flag day scheduled).
// // Schema and code ship atomically (rollbacks panicking — autonomy dying). Phase expands; overlap deploys; refuse cliffs.)
```

**Common confusion** — *"small fleets ship cliffs (phasing skipping)."* Skipping single-instance cliffs (locks unheld — versions unmixed (downtimes unscheduled — rollbacks unpanicked (skipping pricing — rehearsal failing); phasing sequencing everywhere (expands adding — overlaps keeping (cliffs refusing — safety earning (sequencing proving — cliffing declining). "Small" describing topology (instances counting — restarts atoming); phases describing compatibility (shapes adding — versions tolerating). Add first (expands phasing — locks declining); overlap always (deploys decoupling — flagging ending).

**Performance note** — sequencing economics: phasing costing files (expands writing — overlaps holding (cliffs refusing — safety earning); cliffed equivalents costing incidents (locks blocking — versions crashing (downtimes dating — trust eroding). Phase cheaply (ships — rows); cliff never (deploys — flag-days).

**Mentor note** — teach "expand, overlap, contract — every release" (juniors phasing one ship per three stages design cliff-proof delivery on first hearing; single-step ships interrogated ("where is the overlap?" — sequencing demanding per release). Phase one ship once (expands adding — overlaps keeping tangible (cliffing ending — sequencing proving permanently). Add news; remove lasts — sequencing discipline in three habits, reviewed per release.

## 2. Safeties readying (rollbacks keeping — probes answering — drains landing)

**Definition** — readied safeties: keeping rollbacks answering probes landing drains (rollbacks keeping — outs preserving (reverts rehearsing — panics declining (keeping owning — stranding ending); probes answering — healths reporting (readiness proving — traffic accepting (answering funding — blind serving declining); drains landing — accepts stopping (inflight completing — exits timing (landing earning — dropping ending).

**What problem it solves** — the unsafed-ship trio: *rollbacks unkeeping* (outs absenting — reverts hoping (ships stranding — data risking (unkeeping billing — recovery failing); *probes unanswering* (healths silenting — readiness unproven (traffic blinding — broken serving (unanswering charging — routing failing); *drains unlanding* (accepts continuing — inflight dropping (exits rushing — requests losing (unlanding costing — correctness failing). Readied safeties converting hoping to keeping (outs preserving — healths reporting (accepts stopping — losses ending); reviewers finding safety rows per release (readying proving → verifiable; hoping → returned).

**Modern guidance** — the readying lines per release (review-enforced): *rollbacks keeping* ([Microservices 06/1.1](<../../../../Microservices/06 Service Operations and Deployment/sections/1. Releases sequencing safely.md>) — outs preserving (reverts rehearsing — panics declining (keeping owning — hoping refusing (outs earning — stranding ending); *probes answering* ([Microservices 06/1.2](<../../../../Microservices/06 Service Operations and Deployment/sections/1. Deploy thinking/1.2. Health gating traffic.md>) — healths reporting (readiness proving — traffic accepting (answering funding — blinding refusing (reports keeping — broken shedding); *drains landing* ([Microservices 06/1.2](<../../../../Microservices/06 Service Operations and Deployment/sections/1.
```typescript
// GOOD: safeties readying — rollbacks keeping, probes answering (compiled + run live).
interface Safety { outKept: boolean; probeAnswers: boolean; drainLands: boolean }
function readyToShip(s: Safety): boolean {
  return s.outKept && s.probeAnswers && s.drainLands; // rollbacks keeping — outs preserving, hoping declining
} // probes answering — healths reporting, blinding declining (caller asserts below)
const crisp: Safety = { outKept: true, probeAnswers: true, drainLands: true };
const fog: Safety = { outKept: true, probeAnswers: false, drainLands: true };
console.log(readyToShip(crisp) && !readyToShip(fog) ? 'safeties ready' : 'ships hope');
```

```typescript
// BAD: safeties hoping — rollbacks unkeeping, probes unanswering (real hope shape).
// // Rollback is a revert PR (outs absenting — panics scheduled — stranding ruling).
// // Health is the process running (broken serving — inflight dropping). Keep outs; answer probes; land drains.)
```

**Common confusion** — *"rollbacks are reversals (outs reversing)."* Reversing untested downs (scripts rotting — data losing (disasters worsening — reversals hoping (reversing charging — recovery failing); rereleasing forwards fixing (old code tolerating — new shipping (outs preserving — stranding ending (rereleasing earning — reversing declining). "Reversal" describing direction (downs scripting — losses risking); outs describing readiness (outs preserving — forwards fixing). Keep outs (rollbacks keeping — stranding ending); fix forward (forwards shipping — reversing ending).

**Performance note** — readying economics: keeping costing rehearsals (outs preserving — probes answering (drains landing — safety earning); hoped equivalents costing outages (stranding ruling — broken serving (requests losing — trust zeroing). Ready cheaply (safeties — rows); hope never (ships — wishes).

**Mentor note** — teach "no out, no ship — every release" (juniors keeping one out per release design strand-proof shipping on first hearing; outless ships interrogated ("revert rehearsed where?" — readying demanding per release). Keep one out once (outs preserving — probes answering tangible (hoping ending — readying proving permanently). Preserve outs; report health — readying discipline in three habits, reviewed per ship.

## 3. Releases separating (deploys landing — releases flipping — words honoring)

**Definition** — separated releases: landing deploys flipping releases honoring words (deploys landing — bits arriving (pods starting — versions staging (landing proving — merging declining); releases flipping — users reaching (flags toggling — percents ramping (flipping funding — shipping confusing declining); words honoring — deploys distinguishing (releases naming — shipped meaning (honoring owning — lying declining).

**What problem it solves** — the merged-release trio: *deploys unlanding* (bits unarriving — pods unstarting (versions unstaged — fleets unmoved (unlanding billing — delivery failing); *releases unflipping* (users unreaching — flags untoggled (dark shipping — value withheld (unflipping charging — velocity failing); *words unhonoring* (deploys called shipped — merges called done (flags unflipped — plans lying (unhonoring costing — honesty failing). Separated releases converting merging to flipping (bits arriving — users reaching (words distinguishing — lies ending); reviewers finding word rows per change (separating proving → verifiable; merging → returned).

**Modern guidance** — the separating lines per change (review-enforced): *deploys landing* — bits arriving (pods starting — versions staging (landing proving — merging refusing (landings earning — stalls ending); *releases flipping* — users reaching (flags toggling — percents ramping (flipping funding — confusing refusing (flips keeping — value flowing); *words honoring* ([ITVocabulary 03/2.1](<../../../../ITVocabulary/03 Software Development and Engineering Terms/sections/2. Ship words/2.1. Build test release and deploy.md>) — deploys distinguishing (releases naming — shipped meaning (honoring owning — lying refusing (words keeping — plans truthing).

```typescript
// GOOD: releases separating — deploys landing, releases flipping (compiled + run live).
function released(deployed: boolean, flipped: boolean): boolean {
  return deployed && flipped; // releases flipping — users reaching, confusing declining
} // deploys landing — bits arriving, merging declining (caller asserts below)
const dark = released(true, false);
const live = released(true, true);
console.log(!dark && live ? 'words honor' : 'merges lie');
```

```typescript
// BAD: releases merging — deploys unlanding, words unhonoring (real merge shape).
// // Merged Friday (deployed Friday — released Friday — users unreaching, plans lying).
// // Shipped means merged (flags unflipped — value withheld). Land bits; flip flags; honor words.)
```

**Common confusion** — *"deploying is releasing (words merging)."* Merging arrivals with reach (bits landing — users assuming (flags skipping — exposure hoping (merging charging — honesty failing); separating landing from flipping (deploys staging — releases toggling (words distinguishing — lies ending (separating earning — merging declining). "Deployed" describing bits (pods starting — versions staging); shipped describing users (flags toggling — value flowing). Stage bits (deploys landing — stalls ending); flip deliberately (releases flipping — confusing ending).

**Performance note** — separating economics: honoring costing words (deploys naming — releases flipping (plans truthing — risk pricing); merged equivalents costing surprises (unreached assuming — untested exposing (lies compounding — trust eroding). Separate cheaply (releases — flags); merge never (deploys — shippeds).

**Mentor note** — teach "deployed is not shipped — every change" (juniors separating one deploy from one release per change design lie-proof delivery on first hearing; merged ships interrogated ("flag flipped for whom?" — separating demanding per change). Separate one change once (deploys landing — releases flipping tangible (merging ending — separating proving permanently). Land often; release deliberately — separating discipline in three habits, reviewed per change.
