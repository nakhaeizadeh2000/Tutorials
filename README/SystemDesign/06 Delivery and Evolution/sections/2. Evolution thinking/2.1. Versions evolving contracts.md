# 2.1. Versions evolving contracts

## 1. Contracts versioning (prefixes scoping — fields adding — breaks numbering)

**Definition** — versioned contracts: scoping prefixes adding fields numbering breaks (prefixes scoping — versions coexisting (v1 freezing — v2 extending (scoping proving — mixing declining); fields adding — shapes extending (optionals appending — requireds versioning (adding funding — breaking declining); breaks numbering — incompatibles dating (majors bumping — clients migrating (numbering owning — surprising declining).

**What problem it solves** — the unversioned-contract trio: *prefixes unscoping* (versions uncoexisting — v1 unfrozen (clients unmigrated — breakage surprising (unscoping billing — stability failing); *fields unadding* (shapes unextended — requireds unversioned (edits breaking — callers crashing (unadding charging — compatibility failing); *breaks unnumbering* (incompatibles undated — majors unbumped (removals silenting — consumers stranding (unnumbering costing — trust failing). Versioned contracts converting surprising to scoping (versions coexisting — shapes extending (breaks dating — trust earning); reviewers finding version rows per contract (versioning proving → verifiable; surprising → returned).

**Modern guidance** — the versioning lines per contract (review-enforced): *prefixes scoping* ([APIDesign 01/2.2](<../../../../APIDesign/01 API Design Foundations and Mental Model/sections/2. Contract thinking/2.2. Versioning and evolution.md>) — versions coexisting (v1 freezing — v2 extending (scoping proving — mixing refusing (scopes earning — breakage ending); *fields adding* ([DatabaseDesign 05/1.2](<../../../../DatabaseDesign/05 Evolution Growth and Partitioning/sections/1. Schema evolution/1.2. Backward-compatible discipline.md>) — shapes extending (optionals appending — requireds versioning (adding funding — breaking refusing (adds keeping — crashes ending); *breaks numbering* — incompatibles dating (majors bumping — clients migrating (numbering owning — surprising refusing (numbers keeping — strands ending).

} // fields adding — shapes extending, breaking declining (caller asserts below)

  return change === 'optional'; // breaks numbering — incompatibles dating, surprising declining

**Common confusion** — *"versions are forever (prefixes multiplying)."* Multiplying supported majors (v1 serving — v2 serving (v3 serving — matrices testing (multiplying charging — velocity failing); scoping sunsetting versions (prefixes dating — readers counting (breaks migrating — surprises ending (scoping earning — multiplying declining). "Forever" describing comfort (versions unretired — debt accruing); prefixes describing coexistence windows (scopes dating — zeros proving). Freeze olds (prefixes scoping — mixing ending); date ends (breaks numbering — surprising ending).

**Performance note** — versioning economics: scoping costing prefixes (versions coexisting — shapes extending (breaks dating — trust earning); surprised equivalents costing incidents (callers crashing — consumers stranding (trust zeroing — velocity stalling). Scope cheaply (contracts — prefixes); surprise never (edits — in-places).

**Mentor note** — teach "additive default, numbered break — every contract" (juniors versioning one contract per additive-or-break judgment design surprise-proof evolution on first hearing; silent edits interrogated ("prefix? additive?" — versioning demanding per contract). Version one contract once (prefixes scoping — fields adding tangible (surprising ending — versioning proving permanently). ## 3. Breaks announcing (sunsets dating — migrations funding — surprises ending)

**Definition** — announced breaks: dating sunsets funding migrations ending surprises (sunsets dating — removals scheduling (versions freezing — deletions ticketing (dating proving — silenting declining); migrations funding — callers moving (docs guiding — duals running (funding owning — stranding declining); surprises ending — breakage announcing (changelogs stating — consumers readying (ending earning — ambushing declining).

**What problem it solves** — the unannounced-break trio: *sunsets undating* (removals unscheduled — versions unfreezing (deletions unticketed — debt accruing (undating billing — velocity failing); *migrations unfunding* (callers unmoving — docs unguarding (duals unrunning — stragglers stranding (unfunding charging — adoption failing); *surprises unending* (breakage unannounced — changelogs unstated (consumers unready — incidents dating (unending costing — trust failing). Announced breaks converting ambushing to dating (removals scheduling — callers moving (breakage announcing — trust earning); reviewers finding sunset rows per break (announcing proving → verifiable; ambushing → returned).

**Modern guidance** — the announcing lines per break (review-enforced): *sunsets dating* — removals scheduling (versions freezing — deletions ticketing (dating proving — silenting refusing (dates earning — debt ending); *migrations funding* — callers moving (docs guiding — duals running (funding owning — stranding refusing (funds keeping — adoption flowing); *surprises ending* ([APIDesign 01/2.2](<../../../../APIDesign/01 API Design Foundations and Mental Model/sections/2. Contract thinking/2.2. Versioning and evolution.md>) — breakage announcing (changelogs stating — consumers readying (ending earning — ambushing refusing (endings keeping — incidents dating).

```typescript
// GOOD: breaks announcing — sunsets dating, migrations funding (compiled + run live).
interface Sunset { version: string; date: string; migrated: boolean }
function announced(s: Sunset): boolean {
  return s.date.length > 0 && s.migrated; // sunsets dating — removals scheduling, silenting declining
} // migrations funding — callers moving, stranding declining (caller asserts below)

```

**Performance note** — announcing economics: dating costing tickets (removals scheduling — callers moving (breakage announcing — trust earning); ambushed equivalents costing incidents (consumers unready — stragglers stranding (trust zeroing — velocity stalling).
