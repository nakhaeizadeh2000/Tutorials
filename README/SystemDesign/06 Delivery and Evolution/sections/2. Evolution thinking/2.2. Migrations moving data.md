# 2.2. Migrations moving data

## 1. Phases sequencing (expands adding — duals mapping — contracts removing)

**Definition** — sequenced phases: adding expands mapping duals removing contracts (expands adding — additive shapes first (nullables adding — tables adding (adding proving — locking declining); duals mapping — readers adapting (writers doubling — versions tolerating (mapping funding — breaking declining); contracts removing — olds dropping last (nulls enforcing — readers zeroing (removing owning — accruing declining).

**What problem it solves** — the big-bang-migration trio: *expands unadding* (alters locking — writes blocking (flag days dating — users waiting (unadding billing — availability failing); *duals unmapping* (readers unadapting — writers undoubling (versions unmixing — rolling crashing (unmapping charging — compatibility failing); *contracts unremoving* (olds undropping — nulls unenforced (debt accruing — schemas fossilizing (unremoving costing — velocity failing). Sequenced phases converting banging to bridging (additives adding — readers adapting (olds dropping-last — downtimes ending); reviewers finding phase rows per migration (sequencing proving → verifiable; banging → returned).

**Modern guidance** — the sequencing lines per migration (review-enforced): *expands adding* ([DatabaseDesign 05/1.1](<../../../../DatabaseDesign/05 Evolution Growth and Partitioning/sections/1. Schema evolution/1.1. Expand and contract migrations.md>) — additive shapes first (nullables adding — tables adding (adding proving — locking refusing (adds earning — downtimes ending); *duals mapping* ([CA 06/3.1](<../../../../CleanArchitecture/06 Persistence and Framework Isolation/sections/3. Model evolution/3.1. Migrations evolving with models.md>) — readers adapting (writers doubling — versions tolerating (mapping funding — breaking refusing (duals keeping — crashes ending); *contracts removing* ([Databases 04/2.2](<../../../../Databases/04 Node.js Data Access Drivers and Pooling/sections/2. Discipline/2.2. Migrations basis.md>) — olds dropping last (nulls enforcing — readers zeroing (removing owning — accruing refusing (removals keeping — fossils ending).

```typescript
// GOOD: phases sequencing — expands adding, duals mapping (compiled + run live).
type MigPhase = 'expand' | 'dual' | 'contract';
function migPhase(backfilled: boolean, retired: boolean): MigPhase {
  if (!backfilled) return 'expand'; // expands adding — nullables adding, locking declining
  if (!retired) return 'dual'; // duals mapping — readers adapting, breaking declining
  return 'contract'; // contracts removing — olds dropping-last, accruing declining
}
console.log(migPhase(false, false) === 'expand' && migPhase(true, false) === 'dual' && migPhase(true, true) === 'contract' ? 'phases sequence' : 'migrations bang');
```

```typescript
// BAD: phases banging — expands unadding, duals unmapping (real bang shape).
// // Rename the column in one deploy (locks holding — mixed versions crashing — flag day dated).
// // Drop and hope (readers unadapted — debt accruing). Add expands; map duals; remove lasts.)
```

**Common confusion** — *"small tables skip phases (sizes exempting)."* Exempting phasing by size (files unphased — locks unheld (ceremony unneeded — phases unneeded (exempting charging — discipline failing); sequencing phasing by topology (instances overlapping — versions mixing (compatibility demanding — crashes threatening (sequencing earning — exempting declining). "Small" describing ceremony (files lightening — reviews quickening); phases describing compatibility (shapes adding — readers adapting). Lighten ceremony (files sizing — reviews pricing); keep phases (expands adding — contracts removing).

**Performance note** — sequencing economics: adding costing files (expands writing — duals mapping (contracts removing — safety earning); banged equivalents costing flag-days (locks blocking — versions crashing (downtimes dating — trust eroding). Phase cheaply (migrations — stages); bang never (schemas — renames).

**Mentor note** — teach "expand, dual, contract — every migration" (juniors phasing one migration per three stages design bang-proof evolution on first hearing; single-file renames interrogated ("where is the dual?" — sequencing demanding per migration). Sequence one migration once (expands adding — duals mapping tangible (banging ending — sequencing proving permanently). Add nullables; drop lasts — sequencing discipline in three habits, reviewed per migration.

## 2. Windows sizing (versions overlapping — traffic splitting — mixed tolerating)

**Definition** — sized windows: overlapping versions splitting traffic tolerating mixed (versions overlapping — old serving (new staging — fleets straddling (overlapping proving — atoming declining); traffic splitting — requests dividing (percents routing — versions isolating (splitting funding — flooding declining); mixed tolerating — both accepting (old reading — new writing (tolerating owning — crashing declining).

**What problem it solves** — the windowless-migration trio: *versions unoverlapping* (old unserving — new unstaged (fleets unstraddled — cutovers banging (unoverlapping billing — availability failing); *traffic unsplitting* (requests undivided — percents unrouted (versions unisolated — blasts unbounding (unsplitting charging — safety failing); *mixed untolerating* (both unaccepted — old unread (new unwritten — rolling crashing (untolerating costing — compatibility failing). Sized windows converting cutovers to overlaps (old serving — requests dividing (both accepting — crashes ending); reviewers finding window rows per migration (sizing proving → verifiable; cutting → returned).

**Modern guidance** — the sizing lines per migration (review-enforced): *versions overlapping* ([Databases 04/2.2](<../../../../Databases/04 Node.js Data Access Drivers and Pooling/sections/2. Discipline/2.2. Migrations basis.md>) — old serving (new staging — fleets straddling (overlapping proving — atoming refusing (overlaps earning — cutovers ending); *traffic splitting* ([Microservices 06/1.1](<../../../../Microservices/06 Service Operations and Deployment/sections/1. Deploy thinking/1.1. Releases sequencing safely.md>) — requests dividing (percents routing — versions isolating (splitting funding — flooding refusing (splits keeping — blasts bounding); *mixed tolerating* — both accepting (old reading — new writing (tolerating owning — crashing refusing (tolerates keeping — rolls succeeding).

```typescript
// GOOD: windows sizing — versions overlapping, traffic splitting (compiled + run live).
function windowHolds(oldPods: number, newPods: number): boolean {
  return oldPods > 0 && newPods > 0; // versions overlapping — old serving, atoming declining
} // traffic splitting — requests dividing, flooding declining (caller asserts below)
console.log(windowHolds(8, 2) && !windowHolds(0, 10) ? 'windows hold' : 'cutovers bang');
```

```typescript
// BAD: windows cutting — versions unoverlapping, mixed untolerating (real cut shape).
// // Flip all pods at once (old unserved — new unstaged — rolling crashing).
// // Migrate during the cutover (both unaccepted — data risking). Overlap versions; split traffic; tolerate mixed.)
```

**Common confusion** — *"windows double cost (overlaps duplicating)."* Duplicating running fleets (pods doubling — bills doubling (capacity pricing — windows taxing (duplicating charging — value failing); overlapping sizing windows (old serving — new staging (mixed tolerating — crashes ending (overlapping earning — duplicating declining). "Double" describing duration (windows timing — overlaps bounding); duplicates describing waste (fleets idling — bills compounding). Bound durations (windows sizing — taxes capping); tolerate briefly (mixed accepting — crashes ending).

**Performance note** — sizing economics: overlapping costing windows (old serving — requests dividing (both accepting — crashes ending); cut equivalents costing crashes (rolling failing — data risking (trust eroding — downtimes dating). Size cheaply (windows — overlaps); cut never (migrations — flips).

**Mentor note** — teach "every migration names its mixed window — every schema change" (juniors sizing one overlap per migration design cut-proof evolution on first hearing; windowless migrations interrogated ("old pods during new writes?" — sizing demanding per migration). Size one window once (versions overlapping — traffic splitting tangible (cutting ending — sizing proving permanently). Straddle fleets; divide traffic — sizing discipline in three habits, reviewed per migration.

## 3. Rollbacks rereleasing (forwards fixing — reverses refusing — outs preserving)

**Definition** — rereleasing rollbacks: fixing forwards refusing reverses preserving outs (forwards fixing — new shipping (old tolerating — fleets advancing (fixing proving — reversing declining); reverses refusing — downs declining (scripts unrotting — data unlosing (refusing funding — worsening declining); outs preserving — reverts rehearsing (outs readying — panics declining (preserving owning — stranding ending).

**What problem it solves** — the reversal-rollback trio: *forwards unfixing* (new unshipped — old untolerated (fleets unadvanced — bad unlived (unfixing billing — recovery failing); *reverses unrefusing* (downs scripted — data lost (disasters worsened — untested rescuing (unrefusing charging — safety failing); *outs unpreserving* (reverts unrehearsed — outs unready (panics scheduled — ships stranded (unpreserving costing — trust failing). Rereleasing rollbacks converting reversing to fixing (new shipping — downs declining (outs readying — strands ending); reviewers finding out rows per migration (rereleasing proving → verifiable; reversing → returned).

**Modern guidance** — the rereleasing lines per migration (review-enforced): *forwards fixing* ([Databases 04/2.2](<../../../../Databases/04 Node.js Data Access Drivers and Pooling/sections/2. Discipline/2.2. Migrations basis.md>) — new shipping (old tolerating — fleets advancing (fixing proving — reversing refusing (fixes earning — strands ending); *reverses refusing* — downs declining (scripts unrotting — data unlosing (refusing funding — worsening refusing (refusals keeping — losses ending); *outs preserving* ([Microservices 06/1.1](<../../../../Microservices/06 Service Operations and Deployment/sections/1. Deploy thinking/1.1. Releases sequencing safely.md>) — reverts rehearsing (outs readying — panics declining (preserving owning — stranding refusing (outs keeping — dread ending).

```typescript
// GOOD: rollbacks rereleasing — forwards fixing, outs preserving (compiled + run live).
function rollbackFor(failed: boolean, outReady: boolean): 'rerelease' | 'stranded' {
  if (failed && outReady) return 'rerelease'; // forwards fixing — new shipping, reversing declining
  return 'stranded'; // outs preserving — reverts rehearsing, stranding declining (caller asserts below)
}
console.log(rollbackFor(true, true) === 'rerelease' && rollbackFor(true, false) === 'stranded' ? 'rollbacks rerelease' : 'reversals strand');
```

```typescript
// BAD: rollbacks reversing — forwards unfixing, outs unpreserving (real reverse shape).
// // Down-migrate production (scripts untested — data lost — disaster worsened).
// // Rollback unrehearsed (outs unready — ships stranded). Fix forward; refuse reversals; preserve outs.)
```

**Common confusion** — *"down migrations are rollbacks (scripts rescuing)."* Rescuing rotting downs (scripts untested — reversals lossy (disasters excepted — rescues hoped (rescuing charging — recovery failing); rereleasing fixing forwards (new shipping — old tolerating (outs readying — strands ending (rereleasing earning — rescuing declining). "Down" describing aspiration (scripts existing — runs unproven); outs describing readiness (reverts rehearsed — forwards shipping). Rehearse outs (outs preserving — dread ending); ship forwards (fixes earning — strands ending).

**Performance note** — rereleasing economics: preserving costing rehearsals (new shipping — downs declining (outs readying — strands ending); reversed equivalents costing losses (data lost — disasters worsened (trust zeroing — downtimes dating). Preserve cheaply (rollbacks — outs); reverse never (migrations — downs).

**Mentor note** — teach "rollbacks rerelease, never reverse — every migration" (juniors preserving one out per migration design reversal-proof recovery on first hearing; down-script rescues interrogated ("rehearsed when? lossy how?" — rereleasing demanding per migration). Preserve one out once (forwards fixing — outs preserving tangible (reversing ending — rereleasing proving permanently). Ship new; rehearse outs — rereleasing discipline in three habits, reviewed per migration.
