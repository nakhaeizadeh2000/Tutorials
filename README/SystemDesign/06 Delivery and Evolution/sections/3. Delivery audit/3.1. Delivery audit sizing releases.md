# 3.1. Delivery audit sizing releases

## 1. Releases auditing (ships naming — batches proving — safeties checking)

**Definition** — audited releases: naming ships proving batches checking safeties (ships naming — phases stating (expands listing — overlaps listing (naming proving — cliffing declining); batches proving — waves counting (fractions stating — canaries judging (proving funding — flipping declining); safeties checking — outs verifying (probes verifying — drains verifying (checking owning — hoping declining).

**What problem it solves** — the unaudited-release trio: *ships unnaming* (phases unstated — expands unlisted (cliffs unnamed — sequencing unproven (unnaming billing — safety failing); *batches unproving* (waves uncounted — fractions unstated (canaries unjudged — exposure unpriced (unproving charging — blast failing); *safeties unchecking* (outs unverified — probes unverified (drains unverified — ships hoped (unchecking costing — recovery failing). Audited releases converting hoping to naming (phases stating — waves counting (outs verifying — gaps closing); reviewers finding release rows per ship (auditing proving → verifiable; hoping → returned).

**Modern guidance** — the auditing lines per ship (review-enforced): *ships naming* ([1.1](<../1. Release thinking/1.1. Deploys shipping safely.md>) — phases stating (expands listing — overlaps listing (naming proving — cliffing refusing (names earning — bangs ending); *batches proving* ([1.2](<../1. Release thinking/1.2. Rollouts limiting blast.md>) — waves counting (fractions stating — canaries judging (proving funding — flipping refusing (proofs keeping — floods ending); *safeties checking* — outs verifying (probes verifying — drains verifying (checking owning — hoping refusing (checks keeping — strands ending).

```typescript
// GOOD: releases auditing — ships naming, batches proving (compiled + run live).
interface ShipRow { phases: number; waves: number; safeties: number }
function releaseGaps(s: ShipRow): number {
  return (3 - Math.min(s.phases, 3)) + (3 - Math.min(s.waves, 3)) + (3 - Math.min(s.safeties, 3)); // ships naming — phases stating, cliffing declining
} // batches proving — waves counting, flipping declining (caller asserts below)
const crisp: ShipRow = { phases: 3, waves: 3, safeties: 3 };
const fog: ShipRow = { phases: 1, waves: 0, safeties: 1 };
console.log(releaseGaps(crisp) === 0 && releaseGaps(fog) === 7 ? 'releases audit' : 'ships hope');
```

```typescript
// BAD: releases hoping — ships unnaming, safeties unchecking (real hope shape).
// // Ship looks fine (phases unstated — waves uncounted — outs unverified).
// // Rollback probably works (safeties unchecking — strands scheduled). Name ships; prove batches; check safeties.)
```

**Common confusion** — *"audits block shipping (rows delaying)."* Delaying naming rows (phases stating — waves counting (outs verifying — gaps closing (delaying funding — hoping declining); blocking shipping audits (releases gating — ships sequencing (safeties readying — strands ending (blocking earning — cliffing declining). "Block" describing gates (checks holding — bad stopping); rows describing proof (names stating — gaps counting). State phases (ships naming — bangs ending); verify outs (safeties checking — hoping ending).

**Performance note** — auditing economics: naming costing rows (phases stating — waves counting (outs verifying — gaps closing); hoped equivalents costing strands (cliffs unnamed — floods unpriced (trust eroding — incidents dating). Audit cheaply (releases — rows); hope never (ships — probablys).

**Mentor note** — teach "every ship shows its phases, waves, and safeties — every release" (juniors auditing one ship per three rows design hope-proof delivery on first hearing; rowless ships interrogated ("phases? waves? safeties?" — auditing demanding per ship). Audit one ship once (ships naming — batches proving tangible (hoping ending — auditing proving permanently). List phases; count waves — auditing discipline in three habits, reviewed per ship.

## 2. Evolutions auditing (contracts proving — phases checking — windows pricing)

**Definition** — audited evolutions: proving contracts checking phases pricing windows (contracts proving — versions listing (prefixes stating — breaks dating (proving funding — surprising declining); phases checking — expands verifying (duals verifying — contracts verifying (checking owning — banging declining); windows pricing — overlaps timing (splits stating — mixed bounding (pricing earning — cutting declining).

**What problem it solves** — the unaudited-evolution trio: *contracts unproving* (versions unlisted — prefixes unstated (breaks undated — surprises ruling (unproving billing — trust failing); *phases unchecking* (expands unverified — duals unverified (contracts unverified — bangs scheduled (unchecking charging — availability failing); *windows unpricing* (overlaps untimed — splits unstated (mixed unbounded — cuts banging (unpricing costing — compatibility failing). Audited evolutions converting surprising to proving (versions listing — expands verifying (overlaps timing — gaps closing); reviewers finding evolution rows per change (auditing proving → verifiable; surprising → returned).

**Modern guidance** — the auditing lines per change (review-enforced): *contracts proving* ([2.1](<../2. Evolution thinking/2.1. Versions evolving contracts.md>) — versions listing (prefixes stating — breaks dating (proving funding — surprising refusing (proofs keeping — ambushes ending); *phases checking* ([2.2](<../2. Evolution thinking/2.2. Migrations moving data.md>) — expands verifying (duals verifying — contracts verifying (checking owning — banging refusing (checks keeping — flag-days ending); *windows pricing* — overlaps timing (splits stating — mixed bounding (pricing earning — cutting refusing (prices keeping — crashes ending).

```typescript
// GOOD: evolutions auditing — contracts proving, phases checking (compiled + run live).
interface EvoRow { contracts: number; phases: number; windows: number }
function evoGaps(e: EvoRow): number {
  return (3 - Math.min(e.contracts, 3)) + (3 - Math.min(e.phases, 3)) + (3 - Math.min(e.windows, 3)); // contracts proving — versions listing, surprising declining
} // phases checking — expands verifying, banging declining (caller asserts below)
const kept: EvoRow = { contracts: 3, phases: 3, windows: 3 };
const thin: EvoRow = { contracts: 2, phases: 1, windows: 0 };
console.log(evoGaps(kept) === 0 && evoGaps(thin) === 6 ? 'evolutions audit' : 'changes surprise');
```

```typescript
// BAD: evolutions hoping — contracts unproving, windows unpricing (real hope shape).
// // Contract looks compatible (versions unlisted — phases unverified — windows unpriced).
// // Migration during cutover (mixed unbounded — crashes scheduled). Prove contracts; check phases; price windows.)
```

**Common confusion** — *"evolution audits duplicate migration reviews (rows repeating)."* Repeating DDL reviews (scripts reading — locks checking (statements proving — syntax holding (repeating charging — design failing); auditing sizing evolution (contracts listing — phases verifying (windows timing — gaps closing (auditing earning — repeating declining). "Review" describing scripts (DDLs reading — locks checking); audits describing design (versions listing — overlaps timing). Read scripts (reviews checking — syntax holding); audit designs (evolutions proving — surprises ending).

**Performance note** — auditing economics: proving costing rows (versions listing — expands verifying (overlaps timing — gaps closing); hoped equivalents costing surprises (breaks undated — bangs scheduled (trust zeroing — velocity stalling). Audit cheaply (evolutions — rows); surprise never (changes — looks-fines).

**Mentor note** — teach "every change shows its contracts, phases, and windows — every evolution" (juniors auditing one change per three rows design surprise-proof evolution on first hearing; rowless changes interrogated ("contracts? phases? windows?" — auditing demanding per change). Audit one change once (contracts proving — phases checking tangible (surprising ending — auditing proving permanently). List versions; time overlaps — auditing discipline in three habits, reviewed per change.

## 3. Rollbacks auditing (outs naming — rehearsals proving — fixes funding)

**Definition** — audited rollbacks: naming outs proving rehearsals funding fixes (outs naming — reverts listing (rereleases stating — reverses refusing (naming proving — stranding declining); rehearsals proving — drills dating (canaries judging — waves freezing (proving funding — hoping declining); fixes funding — forwards readying (ships advancing — bad outliving (funding owning — stalling declining).

**What problem it solves** — the unaudited-rollback trio: *outs unnaming* (reverts unlisted — rereleases unstated (reverses unrefused — strands scheduled (unnaming billing — recovery failing); *rehearsals unproving* (drills undated — canaries unjudged (waves unfreezing — bad widening (unproving charging — quality failing); *fixes unfunding* (forwards unready — ships unadvanced (bad unlived — rollbacks stalling (unfunding costing — velocity failing). Audited rollbacks converting stranding to naming (reverts listing — drills dating (forwards readying — gaps closing); reviewers finding rollback rows per release (auditing proving → verifiable; stranding → returned).

**Modern guidance** — the auditing lines per release (review-enforced): *outs naming* ([1.1](<../1. Release thinking/1.1. Deploys shipping safely.md>) — reverts listing (rereleases stating — reverses refusing (naming proving — stranding refusing (names keeping — dread ending); *rehearsals proving* ([1.2](<../1. Release thinking/1.2. Rollouts limiting blast.md>) — drills dating (canaries judging — waves freezing (proving funding — hoping refusing (proofs keeping — bad stopping); *fixes funding* ([2.2](<../2. Evolution thinking/2.2. Migrations moving data.md>) — forwards readying (ships advancing — bad outliving (funding owning — stalling refusing (funds keeping — velocity flowing).

```typescript
// GOOD: rollbacks auditing — outs naming, rehearsals proving (compiled + run live).
interface OutRow { outs: number; rehearsals: number; fixes: number }
function outGaps(o: OutRow): number {
  return (2 - Math.min(o.outs, 2)) + (2 - Math.min(o.rehearsals, 2)) + (2 - Math.min(o.fixes, 2)); // outs naming — reverts listing, stranding declining
} // rehearsals proving — drills dating, hoping declining (caller asserts below)
const ready: OutRow = { outs: 2, rehearsals: 2, fixes: 2 };
const hoped: OutRow = { outs: 0, rehearsals: 1, fixes: 2 };
console.log(outGaps(ready) === 0 && outGaps(hoped) === 3 ? 'rollbacks audit' : 'outs strand');
```

```typescript
// BAD: rollbacks hoping — outs unnaming, fixes unfunding (real hope shape).
// // Rollback is the down script (reverts unlisted — rehearsals undated — reversals hoped).
// // Forward fix later (forwards unready — bad unlived). Name outs; prove rehearsals; fund fixes.)
```

**Common confusion** — *"rollback audits need staging miracles (fortunes requiring)."* Requiring mirroring fortunes (clones costing — traffic replaying (fidelity pricing — audits delaying (requiring charging — velocity failing); naming counting outs (reverts listing — drills dating (forwards readying — gaps closing (naming earning — mirroring declining). "Miracle" describing fidelity (mirrors costing — delays dating); audits describing readiness (outs naming — rehearsals proving). List reverts (outs naming — dread ending); date drills (rehearsals proving — hoping ending).

**Performance note** — auditing economics: naming costing rows (reverts listing — drills dating (forwards readying — gaps closing); hoped equivalents costing strands (outs unnamed — bad widened (trust zeroing — downtimes dating). Audit cheaply (rollbacks — rows); strand never (releases — probablys).

**Mentor note** — teach "every release shows its outs, rehearsals, and fixes — every ship" (juniors auditing one release per three rollback rows design strand-proof delivery on first hearing; outless releases interrogated ("outs? rehearsals? fixes?" — auditing demanding per release). Audit one release once (outs naming — rehearsals proving tangible (stranding ending — auditing proving permanently). List reverts; ready forwards — auditing discipline in three habits, reviewed per release.
