# 1.2. Indexes pricing queries

## 1. Queries covering (paths listing — sorts ordering — filters narrowing)

**Definition** — covered queries: listed paths ordering sorts narrowing filters (paths listing — fields naming (accesses enumerating — queries scoping (listing proving — guessing declining); sorts ordering — sequences stating (directions fixing — merges avoiding (ordering owning — scrambling declining); filters narrowing — predicates bounding (selectivity pricing — scans refusing (narrowing earning — sweeping declining).

**What problem it solves** — the uncovered-query trio: *paths unlisting* (fields unnamed — accesses unenumerated (queries unscoping — indexes unshaped (unlisting billing — guessing failing); *sorts unordering* (sequences unstated — directions unfixed (merges ruling — files sorting (unordering charging — spilling failing); *filters unnarrowing* (predicates unbounding — selectivity unpriced (scans ruling — tables sweeping (unnarrowing costing — latency failing). Covered queries converting sweeping to listing (fields naming — sequences stating (predicates bounding — indexes earning); reviewers finding query shapes per index (covering proving → verifiable; assuming → returned).

**Modern guidance** — the covering lines per query (review-enforced): *paths listing* (fields naming — accesses enumerating (queries scoping — guessing declining (listing proving — vibing refusing (lists earning — shapes keeping); *sorts ordering* (sequences stating — directions fixing (merges avoiding — scrambling declining (ordering owning — spilling refusing (orders funding — files ending); *filters narrowing* ([Databases 02/2.2](<../../../../Databases/02 Postgres Deep Dive/sections/2. Shape and speed/2.2. Indexes and EXPLAIN.md>) — predicates bounding (selectivity pricing — scans refusing (narrowing earning — sweeping refusing (bounds keeping — latency bounding).

```typescript
// GOOD: queries covering — listed paths ordering sorts (compiled + run live).
interface Query { // paths listing — fields naming, guessing declining
  fields: string[];
  sortBy: string;
}
function uncovered(queries: Query[], indexed: string[]): string[] {
  const gaps: string[] = []; // sorts ordering — sequences stating, scrambling declining
  for (const q of queries) {
    const keys = q.fields.concat([q.sortBy]);
    if (!keys.every((k) => indexed.indexOf(k) >= 0)) gaps.push(q.sortBy);
  }
  return gaps; // filters narrowing — predicates bounding, sweeping declining
}
const listed: Query[] = [{ fields: ['tenant', 'status'], sortBy: 'created' }];
const idx: string[] = ['tenant', 'status', 'created'];
const wild: Query[] = [{ fields: ['tenant', 'note'], sortBy: 'score' }];
console.log(uncovered(listed, idx).length === 0 && uncovered(wild, idx).join() === 'score' ? 'queries cover' : 'paths sweep');
```

```typescript
// BAD: paths sweeping — fields unlisting, filters unnarrowing (real scan shape).
// // Index the id (fields unnamed — queries unscoping — tables sweeping).
// // Sort in memory (sequences unstated — files sorting). List paths; order sorts; narrow filters.)
```

**Common confusion** — *"indexes always quicken (covering blessing)."* Blessing ignoring burdens (writes unpriced — spaces unrented (maintenance compounding — benefits unmeasured (blessing charging — capacity failing); covering pricing both sides (paths listing — costs stating (receipts keeping — wins proving (covering proving — blessing declining). "Always" describing hope (indexes blessing — burdens ignoring); priced describing math (reads quickening — writes burdening). List paths (fields naming — shapes keeping); price costs (part 2 — receipts keeping).

**Performance note** — covering economics: listing costing shapes (fields naming — sequences stating (predicates bounding — indexes earning); uncovered equivalents costing scans (tables sweeping — files sorting (latency funding — trust eroding). List cheaply (queries — paths); sweep never (tables — guesses).

**Mentor note** — teach "every index names its queries" (juniors covering one query list per index design scan-proof reads on first hearing; queryless indexes interrogated ("which queries?" — covering demanding per index). Cover one query once (paths listing — sorts ordering tangible (sweeping ending — covering proving permanently). Name fields; state sorts — covering discipline in three habits, reviewed per index.

## 2. Costs pricing (reads quickening — writes burdening — spaces renting)

**Definition** — priced costs: quickened reads burdening writes renting spaces (reads quickening — lookups bounding (scans ending — tails shrinking (quickening proving — sweeping declining); writes burdening — inserts taxing (updates maintaining — deletes cleaning (burdening owning — ignoring declining); spaces renting — pages holding (sizes growing — disks charging (renting funding — hoarding declining).

**What problem it solves** — the unpriced-index trio: *reads unquickening* (lookups unbounded — scans unended (tails unshrunk — queries crawling (unquickening billing — latency failing); *writes unburdening* (inserts untaxed — updates unmaintained (deletes uncleaned — primaries surprised (unburdening charging — throughput failing); *spaces unrenting* (pages unheld — sizes ungrown (disks uncharged — bloat ruling (unrenting costing — capacity failing). Priced costs converting blessing to quickening (lookups bounding — inserts taxing (pages holding — nets judging); reviewers finding cost math per index (pricing proving → verifiable; blessing → returned).

**Modern guidance** — the pricing lines per index (review-enforced): *reads quickening* (lookups bounding — scans ending (tails shrinking — sweeping declining (quickening proving — crawling refusing (wins earning — latency bounding); *writes burdening* (inserts taxing — updates maintaining (deletes cleaning — ignoring declining (burdening owning — surprising refusing (taxes stating — throughput keeping); *spaces renting* ([Databases 03/2.2](<../../../../Databases/03 MongoDB Deep Dive/sections/2. Modeling and speed/2.2. Document indexes.md>) — pages holding (sizes growing — disks charging (renting funding — hoarding refusing (rents owning — bloat bounding).

```typescript
// GOOD: costs pricing — quickened reads burdening writes (compiled + run live).
interface IndexCost { // reads quickening — lookups bounding, sweeping declining
  readsSavedMs: number;
  writesTaxedMs: number;
  readsPerSec: number;
  writesPerSec: number;
}
function netWin(c: IndexCost): boolean {
  const gain = c.readsSavedMs * c.readsPerSec; // writes burdening — inserts taxing, ignoring declining
  const tax = c.writesTaxedMs * c.writesPerSec;
  return gain > tax; // spaces renting — pages holding, hoarding declining
}
const winner: IndexCost = { readsSavedMs: 40, writesTaxedMs: 2, readsPerSec: 1000, writesPerSec: 50 };
const loser: IndexCost = { readsSavedMs: 2, writesTaxedMs: 5, readsPerSec: 10, writesPerSec: 1000 };
console.log(netWin(winner) && !netWin(loser) ? 'costs price' : 'indexes bless');
```

```typescript
// BAD: burdens ignoring — writes unburdening, spaces unrenting (real tax shape).
// // Index every column (inserts untaxed — primaries surprised — throughput failing).
// // Disk is cheap (bloat ruling — capacity failing). Quicken reads; burden writes; rent spaces.)
```

**Common confusion** — *"writes are free (taxes forgetting)."* Forgetting skipping maintenance (inserts untaxed — updates unmaintained (deletes uncleaned — primaries surprised (forgetting charging — throughput failing); pricing taxing writes (burdens stating — taxes comparing (nets judging — wins proving (pricing proving — blessing declining). "Free" describing reads-only (writes forgetting — taxes hiding); priced describing totals (gains netting — taxes stating). Tax inserts (writes burdening — throughput keeping); net gains (reads quickening — latency bounding).

**Performance note** — pricing economics: netting costing arithmetic (gains netting — taxes stating (rents owning — wins proving); blessed equivalents costing taxes (writes surprised — bloat ruling (throughput funding — trust eroding). Net cheaply (indexes — arithmetic); bless never (columns — hope).

**Mentor note** — teach "gain minus tax, every index" (juniors pricing one net-win per index design tax-proof writes on first hearing; unpriced indexes interrogated ("gain? tax?" — pricing demanding per index). Price one index once (reads quickening — writes burdening tangible (blessing ending — pricing proving permanently). Bound lookups; tax inserts — pricing discipline in three habits, reviewed per index.

## 3. Receipts keeping (plans reading — deltas proving — dead pruning)

**Definition** — kept receipts: read plans proving deltas pruning dead (plans reading — explains stating (nodes naming — costs quoting (reading proving — tuning declining); deltas proving — befores logging (afters comparing — wins witnessing (proving funding — claiming declining); dead pruning — unused dropping (bloat reclaiming — taxes ending (pruning owning — hoarding declining).

**What problem it solves** — the receiptless-index trio: *plans unread* (explains unstated — nodes unnamed (costs unquoted — queries unmeasured (unread billing — tuning failing); *deltas unproving* (befores unlogged — afters uncompared (wins unwitnessed — claims ruling (unproving charging — evidence failing); *dead unpruning* (unused undropped — bloat unreclaimed (taxes unending — disks filling (unpruning costing — capacity failing). Kept receipts converting claiming to reading (explains stating — befores logging (unused dropping — wins earning); reviewers finding receipts per index change (keeping proving → verifiable; claiming → returned).

**Modern guidance** — the keeping lines per change (review-enforced): *plans reading* ([Databases 02/2.2](<../../../../Databases/02 Postgres Deep Dive/sections/2. Shape and speed/2.2. Indexes and EXPLAIN.md>) — explains stating (nodes naming — costs quoting (reading proving — tuning refusing (plans keeping — measures earning); *deltas proving* (befores logging — afters comparing (wins witnessing — claiming declining (proving funding — shipping refusing (deltas witnessing — evidence keeping); *dead pruning* (unused dropping — bloat reclaiming (taxes ending — hoarding declining (pruning owning — filling refusing (drops funding — capacity earning).

```typescript
// GOOD: receipts keeping — read plans proving deltas (compiled + run live).
interface Receipt { // plans reading — explains stating, tuning declining
  beforeMs: number;
  afterMs: number;
  scans: number;
}
function witnessed(r: Receipt[]): string[] {
  const gaps: string[] = []; // deltas proving — befores logging, claiming declining
  for (let i = 0; i < r.length; i = i + 1) {
    if (!(r[i].beforeMs > r[i].afterMs) || r[i].scans <= 0) gaps.push('q' + i);
  }
  return gaps; // dead pruning — unused dropping, hoarding declining
}
const kept: Receipt[] = [{ beforeMs: 400, afterMs: 12, scans: 9000 }];
const claimed: Receipt[] = [{ beforeMs: 12, afterMs: 400, scans: 0 }];
console.log(witnessed(kept).length === 0 && witnessed(claimed).join() === 'q0' ? 'receipts keep' : 'claims tune');
```

**Performance note** — keeping economics: witnessing costing receipts (plans reading — deltas proving (dead pruning — wins earning); claimed equivalents costing bloat (taxes unending — disks filling (surprises funding — trust eroding). Witness cheaply (indexes — receipts); claim never (speed — feelings).

**Mentor note** — teach "receipt per index, before and after" (juniors keeping one plan-delta pair per change design claim-proof tuning on first hearing; receiptless changes interrogated ("before? after?" — keeping demanding per change). Keep one receipt once (plans reading — deltas proving tangible (claiming ending — keeping proving permanently).
