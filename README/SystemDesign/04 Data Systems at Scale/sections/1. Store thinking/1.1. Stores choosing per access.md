# 1.1. Stores choosing per access

## 1. Accesses shaping (reads counting — writes weighing — joins locating)

**Definition** — shaped accesses: counted reads weighing writes locating joins (reads counting — endpoints tallying (rates numbering — mixes stating (counting proving — guessing declining); writes weighing — burdens stating (locks pricing — contention funding (weighing owning — hoping declining); joins locating — relations proving (locality keeping — scatters refusing (locating earning — assuming declining).

**What problem it solves** — the unshaped-access trio: *reads uncounting* (endpoints untallying — rates unnumbered (mixes unstated — caches unsized (uncounting billing — guessing failing); *writes unweighing* (burdens unstated — locks unpriced (contention unfunded — primaries surprised (unweighing charging — hoping failing); *joins unlocating* (relations unproven — locality unkept (scatters ruling — stores mismatched (unlocating costing — assuming failing). Shaped accesses converting guessing to counting (endpoints tallying — burdens stating (relations proving — choices earning); reviewers finding access shapes per service (shaping proving → verifiable; vibing → returned).

**Modern guidance** — the shaping lines per service (review-enforced): *reads counting* (endpoints tallying — rates numbering (mixes stating — guessing declining (counting proving — averaging refusing (counts earning — caches sizing); *writes weighing* (burdens stating — locks pricing (contention funding — hoping declining (weighing owning — smoothing refusing (weights funding — primaries sparing); *joins locating* ([DatabaseDesign 03/2.2](<../../../../DatabaseDesign/03 Document Modeling for Scale/sections/2. Embed or reference/2.2. Reference when apart.md>) — relations proving (locality keeping — scatters refusing (locating earning — assuming refusing (proofs keeping — mismatches ending).

```typescript
// GOOD: accesses shaping — counted reads weighing writes (compiled + run live).
interface Access { // reads counting — endpoints tallying, guessing declining
  endpoint: string;
  readsPerSec: number;
  writesPerSec: number;
}
function foggy(shapes: Access[]): string[] {
  const gaps: string[] = []; // writes weighing — burdens stating, hoping declining
  for (const s of shapes) {
    if (!(s.readsPerSec >= 0) || !(s.writesPerSec >= 0)) gaps.push(s.endpoint);
  }
  return gaps; // joins locating — relations proving, assuming declining
}
const crisp: Access[] = [{ endpoint: 'catalog-get', readsPerSec: 9000, writesPerSec: 50 }];
const fog: Access[] = [{ endpoint: 'catalog-get', readsPerSec: -1, writesPerSec: -1 }];
console.log(foggy(crisp).length === 0 && foggy(fog).join() === 'catalog-get' ? 'accesses shape' : 'mixes vibe');
```

```typescript
// BAD: mixes vibing — reads uncounting, writes unweighing (real guess shape).
// // "Read-heavy." (endpoints untallying — rates unnumbered — caches unsized).
// // "Some writes." (burdens unstated — primaries surprised). Count reads; weigh writes; locate joins.)
```

**Common confusion** — *"access patterns are obvious (shapes skipping)."* Skipping assuming mixes (endpoints untallying — burdens unstated (relations unproven — stores mismatched (skipping charging — rework failing); shaping counting endpoints (reads tallying — writes weighing (joins locating — choices earning (shaping proving — guessing declining). "Obvious" describing vibes (mixes assuming — stores mismatching); shapes describing counts (endpoints tallying — burdens stating). Tally endpoints (reads counting — caches sizing); state burdens (locks pricing — primaries sparing).

**Performance note** — shaping economics: counting costing tallies (endpoints tallying — writes weighing (joins locating — choices earning); unshaped equivalents costing reworks (stores mismatched — caches unsized (migrations funding — trust eroding). Count cheaply (accesses — endpoints); vibe never (mixes — guesses).

**Mentor note** — teach "reads, writes, joins — every service" (juniors shaping one access triple per service design guess-proof choices on first hearing; unshaped services interrogated ("reads? writes? joins?" — shaping demanding per service). Shape one access once (reads counting — writes weighing tangible (guessing ending — shaping proving permanently). Tally reads; weigh writes — shaping discipline in three habits, reviewed per service.

## 2. Stores matching (relations joining — documents nesting — pairs caching)

**Definition** — matched stores: joining relations nesting documents caching pairs (relations joining — tables linking (joins serving — scatters refusing (joining proving — splitting declining); documents nesting — together keeping (trees storing — joins avoiding (nesting owning — scattering declining); pairs caching — heat serving (keys addressing — lookups bounding (caching earning — scanning declining).

**What problem it solves** — the mismatched-store trio: *relations unjoining* (tables unlinking — joins unscattered (locality unkept — queries fanning (unjoining billing — latency failing); *documents unnesting* (together unkept — trees unstoring (joins unrequired — splits ruling (unnesting charging — roundtrips failing); *pairs uncaching* (heat unserving — keys unaddressed (lookups unbounded — scans ruling (uncaching costing — tails failing). Matched stores converting fanning to joining (tables linking — together keeping (keys addressing — queries serving); reviewers finding store reasons per access (matching proving → verifiable; defaulting → returned).

**Modern guidance** — the matching lines per access (review-enforced): *relations joining* (tables linking — joins serving (locality keeping — scattering declining (joining proving — fanning refusing (links earning — queries serving); *documents nesting* ([DatabaseDesign 03/2.1](<../../../../DatabaseDesign/03 Document Modeling for Scale/sections/2. Embed or reference/2.1. Embed when together.md>) — together keeping (trees storing — joins avoiding (nesting owning — splitting refusing (nests keeping — roundtrips ending); *pairs caching* (heat serving — keys addressing (lookups bounding — scanning declining (caching earning — joining refusing (keys serving — tails bounding).

```typescript
// GOOD: stores matching — relations joining, documents nesting (compiled + run live).
type Store = 'relations' | 'documents' | 'pairs';
function matchStore(joinHeavy: boolean, nestDominated: boolean): Store {
  if (joinHeavy) return 'relations'; // relations joining — locality keeping, scattering declining
  if (nestDominated) return 'documents'; // documents nesting — together keeping, splitting declining
  return 'pairs'; // pairs caching — heat serving, scanning declining
}
console.log(matchStore(true, false) === 'relations' && matchStore(false, true) === 'documents' && matchStore(false, false) === 'pairs' ? 'stores match' : 'stores drift');
```

```typescript
// BAD: stores defaulting — relations unjoining, pairs uncaching (real default shape).
// // Postgres for everything (trees unstoring — roundtrips ruling — joins unrequired).
// // Cache later (heat unserving — tails failing). Join relations; nest documents; cache pairs.)
```

**Common confusion** — *"one store serves all (matching skipping)."* Skipping defaulting singles (tables unlinking — together unkept (heat unserving — queries fanning (skipping charging — rework failing); matching choosing per access (relations joining — documents nesting (pairs caching — queries serving (matching proving — defaulting declining). "One" describing comfort (singles defaulting — rework funding); stores describing access (tables linking — trees storing). Link tables (relations joining — queries serving); nest together (documents nesting — roundtrips ending).

**Performance note** — matching economics: choosing costing reasons (tables linking — together keeping (keys addressing — queries serving); defaulted equivalents costing reworks (queries fanning — roundtrips ruling (migrations funding — trust eroding). Choose cheaply (stores — accesses); default never (singles — comforts).

**Mentor note** — teach "access names the store, never the reverse" (juniors matching one store reason per access design default-proof data on first hearing; storeless reasons interrogated ("which access?" — matching demanding per store). Match one store once (relations joining — documents nesting tangible (defaulting ending — matching proving permanently). Link joins; nest trees — matching discipline in three habits, reviewed per access.

## 3. Splits earning (singles launching — pains measuring — duals pricing)

**Definition** — earned splits: launching singles measuring pains pricing duals (singles launching — one store serving (operations bounding — learning focusing (launching proving — sprawling declining); pains measuring — thresholds judging (join pains quantifying — nest shares logging (measuring funding — vibing declining); duals pricing — syncs costing (consistency naming — toils budgeting (pricing owning — hoping declining).

**What problem it solves** — the unearned-split trio: *singles unlaunching* (stores unchosen — operations unbounding (learning unfocused — pages multiplying (unlaunching billing — toil failing); *pains unmeasuring* (thresholds unjudged — join pains unquantified (nest shares unlogged — splits vibed (unmeasuring charging — sprawl failing); *duals unpricing* (syncs uncosted — consistency unnamed (toils unbudgeted — bugs shipping (unpricing costing — correctness failing). Earned splits converting sprawl to launching (one store serving — thresholds judging (syncs costing — splits earning); reviewers finding split thresholds per ADR (earning proving → verifiable; sprawling → returned).

**Modern guidance** — the earning lines per split (review-enforced): *singles launching* ([Databases 01/3.1](<../../../../Databases/01 Database Foundations and Mental Model/sections/3. Choosing/3.1. Choosing Postgres or MongoDB.md>) — one store serving (operations bounding — learning focusing (launching proving — sprawling refusing (singles keeping — pages bounding); *pains measuring* (thresholds judging — join pains quantifying (nest shares logging — vibing declining (measuring funding — guessing refusing (pains logging — splits gating); *duals pricing* (syncs costing — consistency naming (toils budgeting — hoping declining (pricing owning — adopting refusing (costs stating — bugs preventing).

```typescript
// GOOD: splits earning — singles launching, pains measuring (compiled + run live).
interface SplitGate { // singles launching — one store serving, sprawling declining
  joinPain: number;
  nestShare: number;
  threshold: number;
}
function earned(g: SplitGate): boolean {
  return g.joinPain > g.threshold || g.nestShare > g.threshold; // pains measuring — thresholds judging, vibing declining
} // duals pricing — syncs costing, hoping declining (caller asserts below)
const earned1: SplitGate = { joinPain: 80, nestShare: 10, threshold: 70 };
const early: SplitGate = { joinPain: 5, nestShare: 10, threshold: 70 };
console.log(earned(earned1) && !earned(early) ? 'splits earn' : 'stores sprawl');
```

```typescript
// BAD: stores sprawling — singles unlaunching, duals unpricing (real sprawl shape).
// // Three stores day one (operations unbounding — learning unfocused — pages multiplying).
// // Sync later (consistency unnamed — bugs shipping). Launch single; measure pains; price duals.)
```

**Common confusion** — *"polyglot is mature (splits collecting)."* Collecting multiplying stores (operations unbounding — failure modes unlearned (syncs uncosted — toil compounding (collecting charging — operability failing); earning gating splits (singles launching — pains measuring (duals pricing — splits earning (earning proving — sprawling declining). "Mature" describing counts (stores collecting — toil compounding); earned describing thresholds (pains measuring — syncs costing). Launch one (singles serving — learning focusing); gate splits (thresholds judging — bugs preventing).

**Performance note** — earning economics: gating costing thresholds (singles launching — pains measuring (duals pricing — splits earning); sprawled equivalents costing toil (operations unbounding — pages multiplying (syncs uncosted — trust eroding). Gate cheaply (splits — thresholds); sprawl never (stores — counts).

**Mentor note** — teach "one store until numbers say two" (juniors earning one split threshold per service design sprawl-proof data on first hearing; thresholdless splits interrogated ("which pain? what number?" — earning demanding per store). Earn one split once (singles launching — pains measuring tangible (sprawling ending — earning proving permanently). Serve singly; judge thresholds — earning discipline in three habits, reviewed per split.
