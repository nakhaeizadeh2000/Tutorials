# 2.2. Failovers shifting traffic

## 1. Health deciding (probes splitting — verdicts acting — routes updating)

**Definition** — decided health: split probes acting verdicts updating routes (probes splitting — live cheaping (ready deeping — traffic gating (splitting proving — lying declining); verdicts acting — unready shedding (unlively restarting — orchestrators deciding (acting owning — ignoring declining); routes updating — traffic rerouting (failures avoiding — users serving (updating earning — stalling declining).

**What problem it solves** — the unprobed-failover trio: *probes unsplitting* (live uncheap (ready undeep (verdicts unproved — orchestration blind (unsplitting billing — automation failing); *verdicts unacting* (unready unshed — unlively unrestored (actions untaken — toil ruling (unacting charging — observability theatering); *routes unupdating* (traffic unrerouted — failures arriving (users suffering — continuity failing (unupdating costing — safety bluffing). Decided health converting blindness to splitting (live cheaping — unready shedding (routes updating — traffic flowing); reviewers finding probe splits per failover (deciding proving → verifiable; blindness → returned).

**Modern guidance** — the deciding lines per failover (review-enforced): *probes splitting* ([Fastify 05/2.2](<../../../../Fastify/05 Testing Deployment and Operations/sections/2. Delivery/2.2. Graceful shutdown and probes.md>) — live cheaping (ready deeping — traffic gating (splitting proving — lying refusing (splits earning — misroutes ending); *verdicts acting* (unready shedding — unlively restarting (orchestrators deciding — ignoring declining (acting owning — theater refusing (acts keeping — toil ending); *routes updating* (traffic rerouting — failures avoiding (users serving — stalling declining (updating earning — cutting refusing (updates funding — continuity keeping).

```typescript
// GOOD: health deciding — split probes acting verdicts (compiled + run live).
function route(live: boolean, ready: boolean): string {
  if (!live) return 'RESTART'; // probes splitting — live cheaping, lying declining
  if (!ready) return 'SHED'; // verdicts acting — unready shedding, ignoring declining
  return 'ROUTE'; // routes updating — traffic rerouting, stalling declining
}
console.log(route(true, true) === 'ROUTE' && route(true, false) === 'SHED' && route(false, false) === 'RESTART' ? 'health decides' : 'failovers blind');
```

```typescript
// BAD: failovers blinding — probes unsplitting, routes unupdating (real blind shape).
// // Single health check (verdicts unproved — orchestration blind — automation failing).
// // Traffic unmoved (failures arriving — users suffering). Split probes; act verdicts; update routes.)
```

**Common confusion** — *"probes slow failover (checks delaying)."* Delaying postponing promotion (checks running — verdicts pending (switches waiting — recoveries lagging (delaying charging — speed missing); deciding routing traffic (probes splitting — verdicts acting (routes updating — failures avoiding (deciding proving — blindness declining). "Slowing" describing milliseconds (checks running — speed missing); health describing control (live cheaping — ready deeping). Cheapen live (processes answering — restarts gating); deepen ready (dependencies checking — traffic deserving).

**Performance note** — deciding economics: splitting costing endpoints (probes declaring — verdicts acting (routes updating — traffic flowing); blind equivalents costing misroutes (orchestration blind — failures arriving (users suffering — trust eroding). Split cheaply (probes — verdicts); blind never (health — failovers).

**Mentor note** — teach "split first, then fail over" (juniors splitting one probe pair per failover design blind-proof promotion on first hearing; unsplit health interrogated ("live or ready?" — deciding demanding per failover). Decide one health once (live cheaping — verdicts acting tangible (blindness ending — deciding proving permanently). Prove aliveness; earn traffic — deciding discipline in three habits, reviewed per failover.

## 2. Shifts sequencing (drains landing — primaries demoting — replicas promoting)

**Definition** — sequenced shifts: landed drains demoting primaries promoting replicas (drains landing — accepts stopping (inflight completing — exits timing (landing proving — severing declining); primaries demoting — writers fencing (traffic shedding — roles yielding (demoting owning — clinging declining); replicas promoting — standbys elevating (health confirming — splits deciding (promoting earning — hoping declining).

**What problem it solves** — the unsequenced-shift trio: *drains unlanding* (accepts unsevered — inflight undropped (data lost — clients hanging (unlanding billing — grace failing); *primaries undemoting* (writers unfenced — traffic unshed (roles unyielded — split brains scheduling (undemoting charging — safety failing); *replicas unpromoting* (standbys unelevated — health unconfirmed (splits undecided — takeovers fumbling (unpromoting costing — readiness bluffing). Sequenced shifts converting cutting to landing (accepts stopping — writers fencing (standbys elevating — traffic flowing); reviewers finding shift orders per failover (sequencing proving → verifiable; cutting → returned).

**Modern guidance** — the sequencing lines per failover (review-enforced): *drains landing* ([Express 05/2.2](<../../../../Express/05 Testing Deployment and Operations/sections/2. Delivery/2.2. Graceful shutdown and probes.md>) — accepts stopping (inflight completing — exits timing (landing proving — severing refusing (landings earning — data keeping); *primaries demoting* (writers fencing — traffic shedding (roles yielding — clinging declining (demoting owning — splitting refusing (demotions keeping — brains deciding); *replicas promoting* (standbys elevating — health confirming (splits deciding — hoping declining (promoting earning — fumbling refusing (promotions keeping — takeovers succeeding).

```typescript
// GOOD: shifts sequencing — landed drains demoting primaries (compiled + run live).
function shiftOrder(drained: boolean, fenced: boolean, healthy: boolean): string {
  if (!drained) return 'WAIT-DRAIN'; // drains landing — accepts stopping, severing declining
  if (!fenced) return 'WAIT-FENCE'; // primaries demoting — writers fencing, clinging declining
  if (!healthy) return 'WAIT-HEALTH';
  return 'PROMOTE'; // replicas promoting — standbys elevating, hoping declining
}
console.log(shiftOrder(false, true, true) === 'WAIT-DRAIN' && shiftOrder(true, false, true) === 'WAIT-FENCE' && shiftOrder(true, true, false) === 'WAIT-HEALTH' && shiftOrder(true, true, true) === 'PROMOTE' ? 'shifts sequence' : 'cutovers cut');
```

```typescript
// BAD: cutovers cutting — drains unlanding, primaries undemoting (real cut shape).
// // Kill primary (accepts unsevered — data lost — clients hanging).
// // Promote blind (splits undecided — takeovers fumbling). Land drains; fence writers; confirm health.)
```

**Common confusion** — *"sequencing slows recovery (orders delaying)."* Delaying postponing promotion (drains waiting — fences checking (health confirming — switches pausing (delaying charging — speed missing); sequencing preventing splits (accepts stopping — writers fencing (standbys elevating — brains deciding (sequencing proving — cutting declining). "Slowing" describing seconds (orders waiting — speed missing); shifts describing safety (drains landing — splits deciding). Stop accepts (sockets closing — data keeping); confirm standby (health checking — takeovers succeeding).

**Performance note** — sequencing economics: landing costing order (drains stopping — writers fencing (standbys elevating — traffic flowing); cut equivalents costing splits (data lost — brains undecided — takeovers fumbling — trust eroding). Sequence cheaply (shifts — orders); cut never (primaries — traffic).

**Mentor note** — teach "drain, fence, promote — in that order" (juniors sequencing one shift per failover design cut-proof promotion on first hearing; unordered cutovers interrogated ("drained? fenced?" — sequencing demanding per failover). Sequence one shift once (accepts stopping — writers fencing tangible (cutting ending — sequencing proving permanently). Finish inflight; elevate standby — sequencing discipline in three habits, reviewed per failover.

## 3. Losses bounding (writes fencing — gaps measuring — recencies proving)

**Definition** — bounded failover losses: fenced writes measuring gaps proving recencies (writes fencing — primaries demoting (accepts stopping — splits deciding (fencing proving — diverging declining); gaps measuring — lags quoting (divergences bounding — surprises ending (measuring owning — hiding declining); recencies proving — restores testing (data verifying — trust earning (proving earning — bluffing declining).

**What problem it solves** — the unbounded-loss trio: *writes unfencing* (primaries undemoted — accepts unstopped (divergences growing — splits scheduling (unfencing billing — honesty failing); *gaps unmeasuring* (lags unquoted — divergences unbounded (surprises scheduling — calibration failing (unmeasuring charging — visibility failing); *recencies unproving* (restores untested — data unverified (trust unearned — recovery hoping (unproving costing — confidence bluffing). Bounded losses converting divergence to fencing (primaries demoting — lags quoting (restores testing — gaps ending); reviewers finding loss bounds per failover (bounding proving → verifiable; diverging → returned).

**Modern guidance** — the bounding lines per failover (review-enforced): *writes fencing* (primaries demoting — accepts stopping (splits deciding — diverging declining (fencing proving — cutting refusing (fences keeping — honesty earning); *gaps measuring* (lags quoting — divergences bounding (surprises ending — hiding declining (measuring owning — assuming refusing (measures keeping — calibration earning); *recencies proving* ([Databases 07/1.1](<../../../../Databases/07 Production Data Use and Interview Mastery/sections/1. Production judgment/1.1. Capacity judgment under constraints.md>) — restores testing (data verifying — trust earning (proving earning — bluffing refusing (proofs funding — confidence keeping).

```typescript
// GOOD: losses bounding — fenced writes measuring gaps (compiled + run live).
function lossBound(fenced: boolean, lagMs: number, lagCap: number): string {
  if (!fenced) return 'UNBOUNDED'; // writes fencing — primaries demoting, diverging declining
  if (lagMs > lagCap) return 'STALE'; // gaps measuring — lags quoting, hiding declining
  return 'BOUNDED'; // recencies proving — restores testing, bluffing declining
}
console.log(lossBound(false, 0, 5000) === 'UNBOUNDED' && lossBound(true, 9000, 5000) === 'STALE' && lossBound(true, 200, 5000) === 'BOUNDED' ? 'losses bound' : 'gaps diverge');
```

```typescript
// BAD: gaps diverging — writes unfencing, recencies unproving (real diverge shape).
// // Promote with lag unknown (divergences growing — splits scheduling — honesty failing).
// // Untested restore (trust unearned — recovery hoping). Fence writers; measure gaps; prove recency.)
```

**Common confusion** — *"zero loss is achievable (fences guaranteeing)."* Guaranteeing promising impossibility (writes fencing — lags zeroing (splits deciding — divergences denying (guaranteeing charging — honesty failing); bounding stating windows (primaries demoting — gaps measuring (restores testing — surprises ending (bounding proving — diverging declining). "Zero" describing wishes (losses denying — honesty failing); losses describing bounds (fences keeping — gaps quoting). Fence primaries (writers demoting — splits deciding); quote lags (gaps measuring — calibration earning).

**Performance note** — bounding economics: fencing costing demotions (primaries demoting — lags quoting (restores testing — gaps ending); unbounded equivalents costing divergence (splits scheduling — surprises scheduling (trust eroding — honesty failing). Fence cheaply (writes — primaries); diverge never (gaps — losses).

**Mentor note** — teach "fence first, promote second, measure always" (juniors bounding one loss per failover design diverge-proof promotion on first hearing; unfenced promotions interrogated ("fenced? lag?" — bounding demanding per failover). Bound one loss once (primaries demoting — lags quoting tangible (diverging ending — bounding proving permanently). Demote writers; test restores — bounding discipline in three habits, reviewed per failover.
