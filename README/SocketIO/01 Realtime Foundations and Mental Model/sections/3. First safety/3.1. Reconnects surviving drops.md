# 3.1. Reconnects surviving drops

## 1. Backoffs spacing (delays growing — jitters smoothing — storms bounding)

**Definition** — spaced backoffs: growing delays smoothing jitters bounding storms (delays growing — waits lengthening (attempts counting — patience funding (growing proving — hammering declining); jitters smoothing — randomness spreading (thundering avoiding — spikes flattening (smoothing funding — synchronizing declining); storms bounding — caps stating (maximums holding — fleets surviving (bounding owning — collapsing declining).

**What problem it solves** — the hammering-reconnect trio: *delays ungrowing* (waits unlengthened — attempts uncounted (servers hammered — drops cascading (ungrowing billing — stability failing); *jitters unsmoothing* (randomness unspread — thundering ruling (spikes synchronized — fleets stampeding (unsmoothing charging — capacity failing); *storms unbounding* (caps unstated — maximums unheld (fleets uncollapsed-yet — collapses dating (unbounding costing — availability failing). Spaced backoffs converting hammering to growing (waits lengthening — randomness spreading (caps stating — storms ending); reviewers finding backoff rows per client (spacing proving → verifiable; hammering → returned).

**Modern guidance** — the spacing lines per client (review-enforced): *delays growing* — waits lengthening (attempts counting — patience funding (growing proving — hammering refusing (grows earning — servers breathing); *jitters smoothing* — randomness spreading (thundering avoiding — spikes flattening (smoothing funding — synchronizing refusing (smooths keeping — fleets calming); *storms bounding* — caps stating (maximums holding — fleets surviving (bounding owning — collapsing refusing (bounds keeping — availability earning).

```typescript
// GOOD: backoffs spacing — delays growing, storms bounding (compiled + run live).
import 'reflect-metadata';
import { WebSocketGateway } from '@nestjs/websockets';
const BASE_MS = 1000;
const CAP_MS = 30000; // storms bounding — caps stating, collapsing declining
function backoffMs(attempt: number): number {
  return Math.min(CAP_MS, BASE_MS * 2 ** attempt); // delays growing — waits lengthening, hammering declining
}
@WebSocketGateway({ pingInterval: 25000, pingTimeout: 20000 })
class PatientGateway {
  static backoffFor(attempt: number): number {
    return backoffMs(attempt); // jitters smoothing — randomness spreading, synchronizing declining
  }
}
console.log(backoffMs(0) === 1000 && backoffMs(3) === 8000 && backoffMs(9) === CAP_MS && PatientGateway.backoffFor(1) === 2000 ? 'backoffs space' : 'clients hammer');
```

```typescript
// BAD: backoffs hammering — delays ungrowing, storms unbounding (real hammer shape).
// // Reconnect immediately (waits unlengthened — servers hammered — drops cascading).
// // Retry forever fast (caps unstated — fleets stampeding). Grow delays; smooth jitters; bound storms.)
```

**Common confusion** — *"fast reconnects feel responsive (hammering helping)."* Helping hammering servers (waits unlengthened — drops cascading (servers busier — reconnects failing (helping charging — stability failing); spacing growing backoffs (attempts counting — caps stating (servers breathing — drops ending (spacing earning — helping declining). "Fast" describing clients (reconnects instanting — servers hammering); responsive describing systems (waits growing — storms bounded). Count attempts (delays growing — servers breathing); state caps (storms bounding — collapses ending).

**Performance note** — spacing economics: growing costing waits (waits lengthening — randomness spreading (caps stating — storms ending); hammered equivalents costing cascades (servers hammered — fleets stampeding (collapses dating — trust eroding). Space cheaply (backoffs — exponents); hammer never (clients — immediatelies).

**Mentor note** — teach "double the wait, cap the storm — every client" (juniors spacing one backoff per client design hammer-proof reconnects on first hearing; instant reconnects interrogated ("base? cap? jitter?" — spacing demanding per client). Space one backoff once (delays growing — storms bounding tangible (hammering ending — spacing proving permanently). Lengthen waits; hold maximums — spacing discipline in three habits, reviewed per client.

## 2. Sessions recovering (ids resuming — buffers replaying — gaps closing)

**Definition** — recovered sessions: resuming ids replaying buffers closing gaps (ids resuming — session stating (clients presenting — servers recognizing (resuming proving — strangers declining); buffers replaying — missed queueing (disconnects caching — reconnects flushing (replaying funding — losing declining); gaps closing — sequences checking (ranges filling — holes proving-absent (closing owning — diverging declining).

**What problem it solves** — the dropped-session trio: *ids unresuming* (sessions unstated — clients unpresented (servers unrecognized — strangers ruling (unresuming billing — continuity failing); *buffers unreplaying* (missed unqueued — disconnects uncached (reconnects unflushed — messages lost (unreplaying charging — reliability failing); *gaps unclosing* (sequences unchecked — ranges unfilled (holes unproven — states diverging (unclosing costing — coherence failing). Recovered sessions converting losing to resuming (sessions stating — missed queueing (sequences checking — gaps ending); reviewers finding session rows per gateway (recovering proving → verifiable; losing → returned).

**Modern guidance** — the recovering lines per gateway (review-enforced): *ids resuming* — sessions stating (clients presenting — servers recognizing (resuming proving — strangers refusing (resumes earning — continuity keeping); *buffers replaying* — missed queueing (disconnects caching — reconnects flushing (replaying funding — losing refusing (replays keeping — messages earning); *gaps closing* — sequences checking (ranges filling — holes proving-absent (closing owning — diverging refusing (closes keeping — coherence earning).

```typescript
// GOOD: sessions recovering — ids resuming, buffers replaying (compiled + run live).
import 'reflect-metadata';
import { WebSocketGateway, OnGatewayConnection } from '@nestjs/websockets';
import { Socket } from 'socket.io';
function missedSince(lastSeen: number, ledger: number[]): number[] {
  return ledger.filter((seq) => seq > lastSeen); // gaps closing — sequences checking, diverging declining
}
@WebSocketGateway({ connectionStateRecovery: { maxDisconnectionDuration: 2 * 60 * 1000 } })
class ResumingGateway implements OnGatewayConnection {
  handleConnection(client: Socket): string {
    const sid = (client.handshake.auth as { sid?: string }).sid; // ids resuming — sessions stating, strangers declining
    return sid ? `resumed:${sid}` : 'fresh';
  }
  replayFor(lastSeen: number): number[] {
    return missedSince(lastSeen, [1, 2, 3, 4]); // buffers replaying — missed queueing, losing declining
  }
}
const sgw = new ResumingGateway();
const mk = (sid?: string) => ({ handshake: { auth: { sid } } }) as unknown as Socket;
console.log(sgw.handleConnection(mk('s9')) === 'resumed:s9' && sgw.handleConnection(mk()) === 'fresh' && sgw.replayFor(2).join(',') === '3,4' ? 'sessions recover' : 'drops lose');
```

```typescript
// BAD: sessions dropping — ids unresuming, buffers unreplaying (real drop shape).
// // Fresh state per connect (sessions unstated — missed unqueued — messages lost).
// // Clients refetch everything (gaps unchecked — states diverging). State ids; replay buffers; close gaps.)
```

**Common confusion** — *"recovery needs sticky sessions forever (affinity requiring)."* Requiring permanent affinity (routings pinning — servers statefuling (scale coupling — deploys blocking (requiring charging — flexibility failing); recovering resuming ids (sessions stating — missed queueing (sequences checking — gaps ending (recovering earning — requiring declining). "Sticky" describing routing (pins holding — scale coupling); sessions describing identity (ids resuming — buffers replaying). State session ids (ids resuming — continuity keeping); queue missed (buffers replaying — messages earning).

**Performance note** — recovering economics: resuming costing ids (sessions stating — missed queueing (sequences checking — gaps ending); dropped equivalents costing refetches (messages lost — states diverged (bandwidth burned — trust eroding). Recover cheaply (sessions — ids); drop never (connects — fresh-states).

**Mentor note** — teach "every connection carries a resumable id — every gateway" (juniors recovering one session per gateway design drop-proof continuity on first hearing; idless gateways interrogated ("sid? replay window? gap check?" — recovering demanding per gateway). Recover one session once (ids resuming — buffers replaying tangible (dropping ending — recovering proving permanently). Present ids; flush missed — recovering discipline in three habits, reviewed per gateway.

## 3. Resubscribes idempotencing (joins rejoining — duplicates tolerating — states converging)

**Definition** — idempotent resubscribes: rejoining joins tolerating duplicates converging states (joins rejoining — rooms re-entering (leaves replaying — rosters rebuilding (rejoining proving — ghosting declining); duplicates tolerating — double-joins accepting (sets deduping — counts idling (tolerating funding — erroring declining); states converging — server truthing (rosters reconciling — clients aligning (converging owning — drifting declining).

**What problem it solves** — the naive-resubscribe trio: *joins unrejoining* (rooms unentered — leaves unreplayed (rosters unrebuilt — audiences missing (unrejoining billing — delivery failing); *duplicates untolerating* (double-joins erroring — sets undeduped (counts incrementing — joins crashing (untolerating charging — robustness failing); *states unconverging* (server untruthed — rosters unreconciled (clients unaligned — drifts ruling (unconverging costing — coherence failing). Idempotent resubscribes converting crashing to rejoining (rooms re-entering — double-joins accepting (server truthing — drifts ending); reviewers finding resubscribe rows per client (idempotencing proving → verifiable; crashing → returned).

**Modern guidance** — the idempotencing lines per client (review-enforced): *joins rejoining* ([2.2](<../2. Message thinking/2.2. Rooms scoping audiences.md>) — rooms re-entering (leaves replaying — rosters rebuilding (rejoining proving — ghosting refusing (rejoins earning — delivery keeping); *duplicates tolerating* — double-joins accepting (sets deduping — counts idling (tolerating funding — erroring refusing (tolerates keeping — robustness earning); *states converging* — server truthing (rosters reconciling — clients aligning (converging owning — drifting refusing (converges keeping — coherence earning).

```typescript
// GOOD: resubscribes idempotencing — joins rejoining, duplicates tolerating (compiled + run live).
import 'reflect-metadata';
import { WebSocketGateway, SubscribeMessage, MessageBody } from '@nestjs/websockets';
function rejoinAll(wanted: string[], joined: Set<string>): string[] {
  const added: string[] = [];
  for (const room of wanted) {
    if (!joined.has(room)) { joined.add(room); added.push(room); } // duplicates tolerating — sets deduping, erroring declining
  }
  return added; // joins rejoining — rooms re-entering, ghosting declining
}
@WebSocketGateway()
class RejoinGateway {
  @SubscribeMessage('rooms.resync')
  onResync(@MessageBody() wanted: string[]): string[] {
    return rejoinAll(wanted, new Set<string>()); // states converging — server truthing, drifting declining
  }
}
const jgw = new RejoinGateway();
const have = new Set<string>(['r1']);
console.log(rejoinAll(['r1', 'r2'], have).join(',') === 'r2' && have.size === 2 && jgw.onResync(['a']).join(',') === 'a' ? 'resubscribes idempotent' : 'rejoins crash');
```

```typescript
// BAD: resubscribes crashing — joins unrejoining, duplicates untolerating (real crash shape).
// // Join once, assume kept (rooms unentered-after-drop — audiences missing — delivery failing).
// // Error on double join (double-joins erroring — robustness failing). Rejoin joins; tolerate duplicates; converge states.)
```

**Common confusion** — *"resubscribe storms beat idempotency (joins skipping)."* Skipping rejoining membership (rooms unentered — rosters unrebuilt (audiences missing — delivery failing (skipping charging — correctness failing); idempotencing deduping joins (double-joins accepting — server truthing (states converging — drifts ending (idempotencing earning — skipping declining). "Storm" describing volume (reconnects spiking — joins flooding); idempotency describing safety (sets deduping — errors declining). Re-enter rooms (joins rejoining — delivery keeping); trust server (states converging — coherence earning).

**Performance note** — idempotencing economics: rejoining costing sets (rooms re-entering — double-joins accepting (server truthing — drifts ending); crashed equivalents costing misses (audiences missing — robustness failing (delivery dropping — trust eroding). Idempotence cheaply (resubscribes — sets); crash never (rejoins — errors).

**Mentor note** — teach "rejoin everything, error on nothing — every reconnect" (juniors idempotencing one resubscribe per reconnect design crash-proof recovery on first hearing; erroring rejoins interrogated ("sets? server truth?" — idempotencing demanding per client).
