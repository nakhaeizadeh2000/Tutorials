# 2.2. Rooms scoping audiences

## 1. Rooms joining (names scoping — sockets adding — leaves removing)

**Definition** — joined rooms: scoping names adding sockets removing leaves (names scoping — strings owning (topics naming — collisions refusing (scoping proving — flooding declining); sockets adding — members joining (joins awaiting — rosters growing (adding funding — ghosting declining); leaves removing — quits leaving (parts announcing — rosters shrinking (removing owning — haunting declining).

**What problem it solves** — the roomless trio: *names unscoping* (strings unowned — topics unnamed (everyone served — strangers flooded (unscoping billing — relevance failing); *sockets unadding* (members unjoined — joins unawaited (rosters ungrown — audiences missing (unadding charging — delivery failing); *leaves unremoving* (quits unleaving — parts unannounced (rosters unshrunk — ghosts haunting (unremoving costing — capacity failing). Joined rooms converting flooding to scoping (strings owning — members joining (quits leaving — ghosts ending); reviewers finding room rows per audience (joining proving → verifiable; flooding → returned).

**Modern guidance** — the joining lines per audience (review-enforced): *names scoping* — strings owning (topics naming — collisions refusing (scoping proving — flooding refusing (scopes earning — relevance keeping); *sockets adding* — members joining (joins awaiting — rosters growing (adding funding — ghosting refusing (adds keeping — delivery earning); *leaves removing* — quits leaving (parts announcing — rosters shrinking (removing owning — haunting refusing (removes keeping — capacity earning).

```typescript
// GOOD: rooms joining — names scoping, leaves removing (compiled + run live).
import 'reflect-metadata';
import { WebSocketGateway, SubscribeMessage, MessageBody, ConnectedSocket } from '@nestjs/websockets';
import { Socket } from 'socket.io';
type RoomSocket = Socket & { joined: Set<string> };
@WebSocketGateway()
class RoomGateway {
  @SubscribeMessage('room.join')
  onJoin(@MessageBody() room: string, @ConnectedSocket() client: RoomSocket): string {
    client.joined.add(room); // sockets adding — members joining, ghosting declining
    return `joined:${room}`;
  }
  @SubscribeMessage('room.leave')
  onLeave(@MessageBody() room: string, @ConnectedSocket() client: RoomSocket): string {
    client.joined.delete(room); // leaves removing — quits leaving, haunting declining
    return `left:${room}`;
  }
}
const rgw = new RoomGateway();
const fake = { joined: new Set<string>() } as unknown as RoomSocket;
console.log(rgw.onJoin('r1', fake) === 'joined:r1' && fake.joined.has('r1') && rgw.onLeave('r1', fake) === 'left:r1' && !fake.joined.has('r1') ? 'rooms join' : 'audiences flood');
```

```typescript
// BAD: rooms flooding — names unscoping, leaves unremoving (real flood shape).
// // Everyone in one room (strings unowned — strangers flooded — relevance failing).
// // Never leave (quits unleaving — ghosts haunting). Scope names; add sockets; remove leaves.)
```

**Common confusion** — *"rooms are topics, identical to events (scoping confusing)."* Confusing routing keys (events naming — handlers branching (messages routing — logic deciding (confusing charging — design failing); scoping joining audiences (strings owning — members joining (quits leaving — ghosts ending (scoping earning — confusing declining). "Topic" describing routing (events branching — logic deciding); rooms describing membership (sockets adding — leaves removing). Name events (events spelling — routes keeping); join rooms (sockets adding — delivery earning).

**Performance note** — joining economics: scoping costing sets (strings owning — members joining (quits leaving — ghosts ending); flooded equivalents costing relevance (strangers served — ghosts haunted (bandwidth burned — trust eroding). Join cheaply (rooms — sets); flood never (audiences — everyones).

**Mentor note** — teach "name, join, leave paired — every audience" (juniors joining one room per paired lifecycle design flood-proof scoping on first hearing; leaveless joins interrogated ("leave handler? roster shrinks?" — joining demanding per audience). Join one room once (names scoping — leaves removing tangible (flooding ending — joining proving permanently). Own topics; announce parts — joining discipline in three habits, reviewed per audience.

## 2. Namespaces isolating (paths separating — auths gating — tenants dividing)

**Definition** — isolated namespaces: separating paths gating auths dividing tenants (paths separating — routes owning (/chat isolating — /admin fencing (separating proving — mingling declining); auths gating — handshakes verifying (tokens checking — strangers denying (gating funding — trespassing declining); tenants dividing — fleets parting (data bounding — blasts containing (dividing owning — leaking declining).

**What problem it solves** — the namespaceless trio: *paths unseparating* (routes unowned — /chat unisolated (/admin unfenced — concerns mingling (unseparating billing — clarity failing); *auths ungating* (handshakes unverified — tokens unchecked (strangers undenied — trespass ruling (ungating charging — security failing); *tenants undividing* (fleets unparted — data unbounded (blasts uncontained — leaks dating (undividing costing — safety failing). **Modern guidance** — the isolating lines per tenant (review-enforced): *paths separating* — routes owning (/chat isolating — /admin fencing (separating proving — mingling refusing (paths earning — clarity keeping); *auths gating* — handshakes verifying (tokens checking — strangers denying (gating funding — trespassing refusing (gates keeping — security earning); *tenants dividing* — fleets parting (data bounding — blasts containing (dividing owning — leaking refusing (divides keeping — safety earning).

```typescript
// GOOD: namespaces isolating — paths separating, auths gating (compiled + run live).
import 'reflect-metadata';
import { WebSocketGateway, OnGatewayConnection } from '@nestjs/websockets';
import { Socket } from 'socket.io';
function tenantFor(token: string | undefined): string | null {
  if (token === 'tok-admin') return '/admin'; // auths gating — handshakes verifying, trespassing declining
  if (token === 'tok-chat') return '/chat';
  return null; // strangers refusing — unknowns denying, leaking declining
}
@WebSocketGateway({ namespace: '/chat' })
class ChatNamespace implements OnGatewayConnection {
  handleConnection(client: Socket): string {
    const tenant = tenantFor((client.handshake.auth as { token?: string }).token);
    if (!tenant) { client.disconnect(true); return 'denied'; }
    return `admitted:${tenant}`; // paths separating — routes owning, mingling declining
  }
}
const ngw = new ChatNamespace();
const mk = (t?: string) => ({ handshake: { auth: { token: t } }, disconnect: (_: boolean) => undefined }) as unknown as Socket;
console.log(ngw.handleConnection(mk('tok-chat')) === 'admitted:/chat' && ngw.handleConnection(mk('nope')) === 'denied' ? 'namespaces isolate' : 'tenants mingle');
```

```typescript
// BAD: namespaces mingling — paths unseparating, auths ungating (real mingle shape).
// // One namespace for all (routes unowned — concerns mingling — clarity failing).
// // Auth later (handshakes unverified — trespass ruling). Separate paths; gate auths; divide tenants.)
```

**Common confusion** — *"namespaces are just room prefixes (isolating prefixing)."* Prefixing naming rooms (strings joining — slashes adding (isolation claimed — auths shared (prefixing charging — security failing); isolating separating paths (routes owning — handshakes verifying (tenants dividing — leaks ending (isolating earning — prefixing declining). "Prefix" describing strings (slashes adding — auths shared); namespaces describing gates (paths separating — strangers denying). Own routes (paths separating — clarity keeping); verify handshakes (auths gating — security earning).

**Performance note** — isolating economics: separating costing paths (routes owning — handshakes verifying (fleets parting — leaks ending); mingled equivalents costing leaks (concerns mingled — trespass ruled (trust zeroing — incidents dating). Isolate cheaply (namespaces — paths); mingle never (tenants — prefixes).

**Mentor note** — teach "path, gate, tenant separated — every audience class" (juniors isolating one namespace per tenant class design mingle-proof scoping on first hearing; gateless namespaces interrogated ("auth where? tenant blast?" — isolating demanding per namespace). Isolate one namespace once (paths separating — auths gating tangible (mingling ending — isolating proving permanently). Fence paths; check tokens — isolating discipline in three habits, reviewed per namespace.

**Modern guidance** — the bounding lines per room emit (review-enforced): *members counting* — rosters tallying (sizes stating — blind spots ending (counting proving — assuming refusing (counts earning — surprises ending); *emits multiplying* ([DP 04/2.1](<../../../../DesignPatterns/04 Behavioral Patterns Command and Control/sections/2.
```typescript
// GOOD: fan-outs bounding — members counting, emits multiplying (compiled + run live).
import 'reflect-metadata';
import { WebSocketGateway } from '@nestjs/websockets';
function fanCost(members: number, bytes: number): number {
  return members * bytes; // emits multiplying — messages fanning, free-lunching declining
}
function shedAt(members: number, cap: number): boolean {
  return members > cap; // storms pricing — spikes bounding, flooding declining
}
@WebSocketGateway()
class FanGateway {
  static readonly ROOM_CAP = 10000; // members counting — rosters tallying, assuming declining
}
console.log(fanCost(500, 200) === 100000 && !shedAt(500, FanGateway.ROOM_CAP) && shedAt(20000, FanGateway.ROOM_CAP) ? 'fan-outs bound' : 'storms flood');
```
