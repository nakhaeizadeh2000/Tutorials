# 3.1. Lifecycle audit sizing gates

## 1. Arrivals auditing (handshakes naming — presences proving — contexts checking)

**Definition** — audited arrivals: naming handshakes proving presences checking contexts (handshakes naming — tokens listing (tenants routing — denies stating (naming proving — trusting declining); presences proving — rosters counting (sizes publishing — joins announcing (proving funding — ghosting declining); contexts checking — stashes verifying (sandboxes fencing — handlers freeing (checking owning — rederiving declining).

**What problem it solves** — the unaudited-arrival trio: *handshakes unnaming* (tokens unlisted — tenants unrouted (denies unstated — trusts ruling (unnaming billing — security failing); *presences unproving* (rosters uncounted — sizes unpublished (joins unannounced — ghosts haunting (unproving charging — coherence failing); *contexts unchecked* (stashes unverified — sandboxes unfenced (handlers unfree — work repeating (unchecked costing — efficiency failing). Audited arrivals converting trusting to naming (tokens listing — rosters counting (stashes verifying — gaps closing); reviewers finding arrival rows per gateway (auditing proving → verifiable; trusting → returned).

**Modern guidance** — the auditing lines per gateway (review-enforced): *handshakes naming* ([1.1](<../1. Connection thinking/1.1. Arrivals handling connections.md>) — tokens listing (tenants routing — denies stating (naming proving — trusting refusing (names earning — breaches ending); *presences proving* ([1.1](<../1. Connection thinking/1.1. Arrivals handling connections.md>) — rosters counting (sizes publishing — joins announcing (proving funding — ghosting refusing (proofs keeping — divergence ending); *contexts checking* ([1.1](<../1. Connection thinking/1.1. Arrivals handling connections.md>) — stashes verifying (sandboxes fencing — handlers freeing (checking owning — rederiving refusing (checks keeping — work ending).

```typescript
// GOOD: arrivals auditing — handshakes naming, presences proving (compiled + run live).
interface ArrivalRow { handshakes: number; presences: number; contexts: number }
function arrivalGaps(a: ArrivalRow): number {
  return (3 - Math.min(a.handshakes, 3)) + (3 - Math.min(a.presences, 3)) + (3 - Math.min(a.contexts, 3)); // handshakes naming — tokens listing, trusting declining
} // presences proving — rosters counting, ghosting declining (caller asserts below)
const crisp: ArrivalRow = { handshakes: 3, presences: 3, contexts: 3 };
const fog: ArrivalRow = { handshakes: 1, presences: 0, contexts: 1 };
console.log(arrivalGaps(crisp) === 0 && arrivalGaps(fog) === 7 ? 'arrivals audit' : 'gateways trust');
```

**Common confusion** — *"audits repeat the handshake (rows echoing)."* Echoing restating connects (tokens renamed — rosters relisted (stashes rechecked — time doubling (echoing charging — value failing); auditing sizing arrivals (tokens listing — rosters counting (stashes verifying — gaps closing (auditing earning — echoing declining). "Echo" describing repetition (connects restated — time doubled); audits describing measurement (rows counting — gaps closing). List tokens (handshakes naming — breaches ending); verify stashes (contexts checking — work ending).

**Performance note** — auditing economics: naming costing rows (tokens listing — rosters counting (stashes verifying — gaps closing); trusted equivalents costing breaches (trusts ruling — ghosts haunting (work repeating — trust eroding). Audit cheaply (arrivals — rows); trust never (gateways — fines).

**Mentor note** — teach "every gateway shows handshakes, presences, and contexts — every review" (juniors auditing one gateway per three rows design trust-proof arrivals on first hearing; rowless gateways interrogated ("tokens? roster? stash?" — auditing demanding per gateway). Audit one gateway once (handshakes naming — presences proving tangible (trusting ending — auditing proving permanently). Route tenants; grow sets — auditing discipline in three habits, reviewed per gateway.
