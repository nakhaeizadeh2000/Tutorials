# 4.1. Gateway checklist mentors insist on

## 1. Every arrival handling (handshakes verifying — presences registering — contexts attaching)

**Definition** — the arrival gate: each connect verifying handshakes, registering presences, attaching contexts (handshakes verifying — tokens checking (tenants admitting — strangers denying (verifying proving — trusting declining); presences registering — rosters adding (counts stating — joins announcing (registering funding — ghosting declining); contexts attaching — sockets stashing (data scoping — handlers freeing (attaching owning — rederiving declining).

**What problem it solves** — the ungated-arrival trio: *handshakes unverifying* (tokens unchecked — tenants unadmitted (strangers undenied — trusts ruling (unverifying billing — security failing); *presences unregistered* (rosters unadded — counts unstated (joins unannounced — ghosts haunting (unregistered charging — coherence failing); *contexts unattaching* (sockets unstashed — data unscoped (handlers unfree — work repeating (unattaching costing — efficiency failing). Gated arrivals converting trusting to verifying (tokens checking — rosters adding (sockets stashing — gaps closing); reviewers returning connects missing any row (gating proving → verifiable; trusting → returned).

**Modern guidance** — the gating lines per connect (review-enforced): *handshakes verifying* ([1.1](<../1. Connection thinking/1.1. Arrivals handling connections.md>) — tokens checking (tenants admitting — strangers denying (verifying proving — trusting refusing (verifies earning — breaches ending); *presences registering* ([1.1](<../1. Connection thinking/1.1. Arrivals handling connections.md>) — rosters adding (counts stating — joins announcing (registering funding — ghosting refusing (registers keeping — divergence ending); *contexts attaching* ([1.1](<../1. Connection thinking/1.1. Arrivals handling connections.md>) — sockets stashing (data scoping — handlers freeing (attaching owning — rederiving refusing (attaches keeping — work ending).

```typescript
// GOOD: arrival gate — handshakes verifying, presences registering, contexts attaching (commented shape).
// // 1. Handshake proof (tokens checking — strangers denying):
// //    token read with tenant route — welcomers returned, verified arrivals pass.
// // 2. Presence proof (rosters adding — counts stating):
// //    roster joined with stated size — ghost connects returned.
// // 3. Context proof (sockets stashing — data scoping):
// //    sid stashed with fenced sandbox — rederiving handlers returned.
```

```typescript
// BAD: arrival trusting — handshakes unverifying, contexts unattaching (commented anti-shape).
// // Welcome aboard (tokens unchecked — rosters unadded — stashes unverified).
// // Details later (trusts ruling — ghosts haunting). Verify handshakes; register presences; attach contexts.)
```

**Common confusion** — *"arrival gates slow connects (gates delaying)."* Delaying verifying rows (tokens checking — rosters adding (sockets stashing — gaps closing (delaying funding — trusting declining); rushing gating breaches (strangers admitted — ghosts haunted (work repeated — reworks dating (rushing charging — velocity failing). "Slow" describing rows (checks reading — sets growing); fast describing trusts (welcomes voiced — breaches scheduled). Check tokens (handshakes verifying — breaches ending); stash ids (contexts attaching — work ending).

**Performance note** — gating economics: verifying costing rows (tokens checking — rosters adding (sockets stashing — gaps closing); trusted equivalents costing breaches (trusts ruling — ghosts haunting (work repeating — trust eroding). Gate cheaply (arrivals — rows); trust never (connects — welcomes).

**Mentor note** — teach "no arrival rows, no connect review — every gateway" (juniors gating one arrival per three proofs design trust-proof gateways on first hearing; gateless connects interrogated ("token? roster? stash?" — gating demanding per connect). Gate one arrival once (handshakes verifying — presences registering tangible (trusting ending — gating proving permanently). Admit tenants; announce joins — gating discipline in three habits, reviewed per connect.

## 2. Every message gating (sockets switching — memberships proving — denials throwing)

**Definition** — the message gate: each event switching sockets, proving memberships, throwing denials (sockets switching — hosts adapting (contexts reading — payloads reaching (switching proving — blinding declining); memberships proving — rooms checking (roles deciding — strangers refusing (proving funding — squatting declining); denials throwing — exceptions raising (shapes mapping — clients handling (throwing owning — hanging declining).

**What problem it solves** — the ungated-message trio: *sockets unswitching* (hosts unadapted — contexts unread (payloads unreached — gates blind (unswitching billing — gating failing); *memberships unproving* (rooms unchecked — roles undecided (strangers unrefused — squatters ruling (unproving charging — relevance failing); *denials unthrowing* (exceptions unraised — shapes unmapped (clients unhandled — hangs ruling (unthrowing costing — experience failing). Gated messages converting blinding to switching (hosts adapting — rooms checking (exceptions raising — gaps closing); reviewers returning events missing any row (gating proving → verifiable; blinding → returned).

**Modern guidance** — the gating lines per event (review-enforced): *sockets switching* ([2.1](<../2. Message pipeline/2.1. Guards gating messages.md>) — hosts adapting (contexts reading — payloads reaching (switching proving — blinding refusing (switches keeping — gates seeing); *memberships proving* ([2.1](<../2. Message pipeline/2.1. Guards gating messages.md>) — rooms checking (roles deciding — strangers refusing (proving funding — squatting refusing (proves keeping — relevance earning); *denials throwing* ([2.2](<../2. Message pipeline/2.2. Failures answering errors.md>) — exceptions raising (shapes mapping — clients handling (throwing owning — hanging refusing (throws keeping — hangs ending).

```typescript
// GOOD: message gate — sockets switching, memberships proving, denials throwing (commented shape).
// // 1. Switch proof (hosts adapting — contexts reading):
// //    switchToWs first — HTTP-assumed guards returned, switched guards pass.
// // 2. Membership proof (rooms checking — strangers refusing):
// //    roster consulted per event — arrival-inherited trusts returned.
// // 3. Denial proof (exceptions raising — clients handling):
// //    WsException with code — bare-false denials returned, reasoned denials pass.
```

```typescript
// BAD: message opening — sockets unswitching, denials unthrowing (commented anti-shape).
// // Guarded (hosts unadapted — memberships unproven — denials unthrown).
// // Returns false on deny (clients hanging — reasons missing). Switch sockets; prove memberships; throw denials.)
```

**Common confusion** — *"message gates duplicate arrival auth (gates repeating)."* Repeating checking connects (tokens rechecked — rooms unchecked (work doubled — latency added (repeating charging — efficiency failing); gating proving messages (hosts switching — rooms checking (exceptions raising — gaps closing (gating earning — repeating declining). "Duplicate" describing layers (connects checked — messages assumed); gates describing events (rooms proven — denials thrown). Check arrivals (handshakes verifying — trespass ending); prove messages (memberships proving — squatting ending).

**Performance note** — gating economics: switching costing rows (hosts adapting — rooms checking (exceptions raising — gaps closing); opened equivalents costing squats (gates blind — squatters ruling (hangs ruling — trust eroding). Gate cheaply (messages — rows); open never (events — trues).

**Mentor note** — teach "no message rows, no emit review — every event" (juniors gating one event per three proofs design blind-proof messaging on first hearing; gateless events interrogated ("switch? membership? denial?" — gating demanding per event). Gate one event once (sockets switching — memberships proving tangible (blinding ending — gating proving permanently). Adapt hosts; raise Ws — gating discipline in three habits, reviewed per event.

## 3. Every departure cleaning (leaves announcing — resources freeing — reasons logging)

**Definition** — the departure gate: each disconnect announcing leaves, freeing resources, logging reasons (leaves announcing — quits detecting (rosters pruning — peers notifying (announcing proving — missing declining); resources freeing — timers clearing (subs dropping — memory earning (freeing funding — leaking declining); reasons logging — codes naming (causes classifying — flaps counting (logging owning — shrugging declining).

**What problem it solves** — the ungated-departure trio: *leaves unannounced* (quits undetected — rosters unpruned (peers unnotified — ghosts haunting (unannounced billing — coherence failing); *resources unfree* (timers uncleared — subs undropped (memory unearned — leaks ruling (unfree charging — stability failing); *reasons unlogged* (codes unnamed — causes unclassified (flaps uncounted — blinds dating (unlogged costing — signal failing). Gated departures converting missing to announcing (quits detecting — timers clearing (codes naming — gaps closing); reviewers returning disconnects missing any row (gating proving → verifiable; missing → returned).

**Modern guidance** — the gating lines per disconnect (review-enforced): *leaves announcing* ([1.2](<../1. Connection thinking/1.2. Departures cleaning disconnects.md>) — quits detecting (rosters pruning — peers notifying (announcing proving — missing refusing (announces keeping — ghosts ending); *resources freeing* ([1.2](<../1. Connection thinking/1.2. Departures cleaning disconnects.md>) — timers clearing (subs dropping — memory earning (freeing funding — leaking refusing (frees keeping — bloat ending); *reasons logging* ([1.2](<../1. Connection thinking/1.2. Departures cleaning disconnects.md>) — codes naming (causes classifying — flaps counting (logging owning — shrugging refusing (logs keeping — signal earning).

```typescript
// GOOD: departure gate — leaves announcing, resources freeing, reasons logging (commented shape).
// // 1. Leave proof (quits detecting — rosters pruning):
// //    handler present with roster delete — silent disconnects returned.
```

**Common confusion** — *"departure gates gold-plate disconnects (gates overdoing)."* Overdoing demanding rows (leaves announcing — resources freeing (reasons logging — gaps closing (demanding funding — missing declining); gold-plating polishing trivia (codes decorated — flaps admired (effort spent — value missing (plating charging — velocity failing). "Gold" describing trivia (codes decorated — value missing); gates describing leaks (timers cleared — ghosts pruned). Detect quits (leaves announcing — ghosts ending); count flaps (reasons logging — blinds ending).

**Performance note** — gating economics: announcing costing rows (quits detecting — timers clearing (codes naming — gaps closing); missed equivalents costing leaks (ghosts haunted — bloat ruled (blinds dated — trust eroding). Gate cheaply (departures — rows); miss never (disconnects — rares).

**Mentor note** — teach "no departure rows, no lifecycle pass — every gateway" (juniors gating one departure per three proofs design miss-proof lifecycles on first hearing; rowless disconnects interrogated ("announced? freed? coded?" — gating demanding per disconnect). Gate one departure once (leaves announcing — resources freeing tangible (missing ending — gating proving permanently). Prune members; name codes — gating discipline in three habits, reviewed per disconnect.
