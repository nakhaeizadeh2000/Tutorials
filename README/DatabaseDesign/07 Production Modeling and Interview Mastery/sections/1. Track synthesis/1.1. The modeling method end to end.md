# 1.1. The modeling method end to end

## 1. Seven domains, one sequence (each layer assuming the last)

**Definition** — the track as one method: **01** names what exists and how it relates (entities, keys, cardinality, constraints-as-design); **02** sharpens dependencies (forms 1NF→5NF, anomalies eliminated, violations priced); **03** shapes documents where documents fit (aggregates, access catalogs, embed/reference, patterns, versions); **04** loads relationships for volume (FK discipline, hierarchies, junctions both ways, polymorphism honestly, skew named); **05** designs for change and growth (expand/contract, compatibility, capacity math, pruning keys, archival tiers); **06** shapes for operations (audit, soft-delete, outbox, job tables, flags — every structure gauge-serving). Each layer consumes the previous layer's outputs — dependencies assume entities, junctions assume forms, partitions assume growth math, outboxes assume aggregates. The sequence is a dependency graph, not a suggestion.

**What problem it solves** — fragmentary expertise (normalization scholars who can't name a celebrity, document modelers who've never priced a copy, interview stars who've never run a backfill — each domain mastered alone, none composed). Production schemas demand all seven simultaneously (every feature needs entities AND forms AND scale AND evolution AND operations — the layers co-occur in every table); engineers fluent per-domain but illiterate across them design correct fragments that fail as systems (3NF tables without FK indexes, bounded documents without versions, phased migrations without gauges). The sequence converts seven courses into one practice: model whole features, layer by layer, every time.

**Modern guidance** — run every non-trivial feature through all seven, in order, writing each layer's artifacts (entities list → dependency sentences → document/access decisions where applicable → relationship scale notes → migration phases + capacity row → operations shapes + gauges). Trivial features compress (one-table lookups still get keys + forms + review in minutes — the method scales down to checklist speed); routine features abbreviate documented layers ("standard junction, both indexes per 04 — no skew surface, capped"); novel features expand (new domains of scale get full treatment — the method scales up to design docs). Same sequence always — depth varies, order never does.

```sql
-- GOOD: one feature (paid orders with notifications) through all seven layers, traced.
-- 01: entities (customers, orders, lines) + surrogate keys + NOT NULL/FK sentences.
-- 02: 3NF audit (city with customer; total computed, not stored — or priced copy).
-- 03: N/A relational (documented non-choice — access is transactional, not aggregate).
-- 04: FKs indexed both lenses (policy + volume); junction none (1-N here); skew: none
--     (no social graph — stated, not assumed).
-- 05: capacity row (50k/day, 420B, triggers set); migration phases for email column.
-- 06: outbox table (relay surface), audit mirror (money!), soft-delete with partial
--     UNIQUE, gauges (lag, depth) with owners. (Capstone DDL below — verified PG 16.15.)
CREATE TABLE cap_customers (
  id    BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,  -- 01: surrogate default
  email TEXT UNIQUE NOT NULL                              -- 01: natural UNIQUE beside it
);
```

```sql
-- BAD: single-layer modeling — correct fragment, failing system.
-- 3NF-perfect tables (02: A+) with unindexed FKs (04: absent — parent writes scan),
-- unbounded notification fan-out (03/04: unexamined — N+1 per order event),
-- flag-day email migration (05: unphased — old writers fail mid-rollout),
-- no audit on money tables (06: unasked — first dispute unanswerable).
-- Each layer correct alone; the feature fails everywhere layers meet. Fragments, itemized.
```

**Common confusion** — *"seniors skip steps — method is for juniors."* Seniors *compress* steps (seven layers in minutes — pattern recognition substituting for paperwork), never skip them (skipped layers surface as incidents regardless of seniority — the unindexed FK pages staff engineers identically). Compression without omission is expertise; omission with confidence is risk wearing seniority. Review seniors on omitted layers explicitly ("skew analysis?" — silence fails regardless of level). Method scales with experience; sequence binds all levels equally.

**Performance note** — layered modeling is upstream performance work in total (same argument compounded across six domains: each layer removes one incident class and one tuning burden — entities remove confusion, forms remove anomalies, access removes fan-out, relationships remove scans, capacity removes cliffs, operations removes blindness). Unlayered schemas arrive in performance reviews as mysteries ("slow database" — which layer? — archaeology); layered schemas arrive with layer-labeled metrics (FK scans? junction skew? residency cliff? relay lag? — diagnosis by layer, fixes targeted). Metrics per layer, mysteries never — the method's performance dividend, track complete.

**Mentor note** — teach the sequence as "the seven questions" (what exists? what determines what? documents or rows? what breaks at volume? how does it change and grow? who operates it? — one question per domain, asked in order, every feature). Juniors answering seven questions model completely on the first try; the questions fit an index card; the card belongs in onboarding beside every schema doc from Domains 01–06. Questions over courses, same pedagogy as every selection in this track — seven questions, one method, permanent practice.

## 2. The worked capstone (one feature through all seven lenses)

**Definition** — the capstone exercise: a single feature (paid orders with customer notifications — the track's running example, fully specified below) modeled through every lens, artifacts per layer, decisions recorded with links to home domains. The capstone is the track's graduation proof (performed live in interviews — [3.1](<../3. Interview mastery/3.1. Cross-domain interview synthesis.md>) stages it; taught in onboarding — [4.1](<../4. Mentor checklist/4.1. Mentor checklist for the whole track.md>) assigns it). One feature, seven lenses, zero skipped steps — the method performed whole, witnessed.

**What problem it solves** — the gap between knowing and performing (engineers reciting all seven domains' rules while modeling features single-layered — knowledge tested per domain, performance never integrated). Capstones integrate under observation (mentors watch layers applied in sequence — skipped layers visible instantly: "you priced copies but named no celebrity — back to 04"); interviews simulate them ([3.1](<../3. Interview mastery/3.1. Cross-domain interview synthesis.md>)'s staff loop is a timed capstone); onboarding assigns them (first-month capstone on a real feature — reviewed layer by layer). Knowledge fragments without capstones; capstones compose knowledge into practice — the final pedagogical step, track complete.

**Modern guidance** — the capstone procedure (feature: paid orders + notifications; artifacts per layer — verified DDL shapes on PostgreSQL 16.15): **01** entities (customers, orders, lines — surrogate PKs, email UNIQUE, FK sentences with reverse rules + delete policies); **02** forms audit (city→customer (3NF split); total computed (no stored copy — or priced MV per 02/3.1 with six-field record)); **03** non-choice documented (transactional access — no aggregates; notification *content* snapshotted per order (frozen history — 03/2.1 lens applied relationally)); **04** volume (FKs indexed both lenses; no junctions (1-N — stated); no skew surface (no social graph — asked, answered); fan-out rule noted for reporting (split queries)); **05** change+growth (capacity row: rates/widths/triggers; email migration phased expand/contract); **06** operations (outbox table + relay + purge; audit mirror on money; soft-delete with partial UNIQUE; gauges with owners). Each artifact links its home domain — the capstone reads as seven citations performing one feature.

```sql
-- GOOD: capstone DDL — every line traces to a layer (verified PostgreSQL 16.15).
CREATE TABLE cap_customers (
  id    BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,  -- 01: surrogate; 02: sole key
  email TEXT UNIQUE NOT NULL                              -- 01: natural beside it
);

CREATE TABLE cap_orders (
  id          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  customer_id BIGINT NOT NULL REFERENCES cap_customers (id) ON DELETE RESTRICT,
  -- 01: reverse sentence (orders belong to exactly one customer); 04: RESTRICT + volume note
  total       NUMERIC(12, 2) NOT NULL CHECK (total >= 0),  -- 02: computed-at-write, CHECKed
  placed_at   TIMESTAMPTZ NOT NULL DEFAULT now()          -- 05: partition key candidate
);
CREATE INDEX cap_orders_customer_idx ON cap_orders (customer_id);  -- 04: FK indexed, both lenses

CREATE TABLE cap_outbox (   -- 06: relay surface (pattern: Databases 05/3.1, table: here)
  seq          BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  aggregate    TEXT NOT NULL, aggregate_id TEXT NOT NULL,
  event        TEXT NOT NULL, payload JSONB NOT NULL,
  occurred_at  TIMESTAMPTZ NOT NULL DEFAULT now(), relayed_at TIMESTAMPTZ
);
-- 05: capacity row filed; 06: gauges (lag, depth) owned; audit mirror on money (06/1.1).
```

```sql
-- BAD: the capstone skipped — layers assumed, artifacts absent.
-- (Feature shipped with: entities unlisted (tables accreted per ticket); forms unaudited
-- (city on orders — anomaly live); relationships unloaded (FKs bare — parent writes scan);
-- evolution unphased (flag-day email — old writers failed); operations unshaped (no outbox —
-- dual-write incidents; no audit — first dispute unanswerable; no gauges — relay stalled
-- silently). Seven layers skipped in one sprint; seven incident classes scheduled.
-- Velocity celebrated; ledger pending. The bill arrives layered too.)
```

**Common confusion** — *"capstones are academic — production moves too fast."* Production speed rewards layered fluency (seven layers in minutes for routine features — seniors' compression from promise 1), not layer-skipping (incidents cost quarters; capstone discipline costs minutes). "Too fast to model" inverts causality (skipped layers *cause* the incidents that consume quarters — modeling time blamed for incident time it would have prevented). Fast teams capstone routinely (lightweight per feature — artifacts proportional to novelty); slow teams incident-review repeatedly (heavyweight per outage — ceremonies proportional to skipped layers). Speed with method beats speed without — measured in quarters, not sprints.

**Performance note** — capstone economics: full capstone costs hours (novel features — design doc scale) to minutes (routine features — checklist speed); skipped-layer incidents cost engineer-weeks each (orphan sweeps, ceiling migrations, fan-out reconciliations, flag-day rollbacks, unanswerable disputes, silent relay stalls, sediment cleanups — seven classes, each priced across this track). Capstone ROI exceeds 100× on first prevented incident — the track's closing arithmetic: minutes of method vs quarters of incidents, every feature, forever.

**Mentor note** — assign capstones as onboarding graduation (new hire models one real feature through seven layers, reviewed layer-by-layer by mentor — gaps located precisely ("forms solid, skew unexamined" — targeted coaching, not vague "learn modeling")). Capstone reviews diagnose completely (seven layers checked — strengths and gaps mapped in one session); targeted follow-ups prescribe exactly (drill the gap domain's QA leaf — [Domain 0X §5.1] per gap — autonomous improvement after). Onboard with capstones; coach by gaps; graduate measurably — the track's pedagogy performing whole, mentors equipped.

## 3. Handoff discipline between layers (each domain's output is the next domain's input)

**Definition** — handoffs made explicit: 01 outputs (entity list, key choices, FK sentences with policies) feed 02 (dependency audit needs keys named — [Domain 02 §1.1](<../../../02 Normalization Deep Dive/sections/1. Dependencies and atomicity/1.1. Functional dependencies the one idea behind every normal form.md>) consumes 01's key enumeration); 02 outputs (normal form claimed, priced copies with records) feed 03/04 (documents bend forms knowingly; junctions inherit placement); 03/04 outputs (aggregates/boundaries, indexed relationships, named celebrities) feed 05 (capacity math needs widths + counts + skew surfaces; partition keys need predicates + celebrities); 05 outputs (phases, triggers, tiers) feed 06 (gauges monitor triggers; purge jobs execute tiers; outbox relays serve phased features). Each handoff named, format-specified, review-checked — layers interface like systems, because they are one.

**What problem it solves** — layer amnesia (normalization audits redoing entity discovery — keys unnamed in 01, re-derived in 02 at review cost; capacity models guessing widths — 01's types unmeasured, 05 re-measuring; outbox tables designed without aggregates — 03's boundaries unconsulted, relay surfaces mismatched). Amnesia taxes every layer transition (re-derivation per review, mismatched assumptions per handoff, "which key?" asked six times per feature). Named handoffs with formats eliminate re-derivation (downstream consumes upstream artifacts as inputs — review verifies handoff completeness, not content re-created). Interfaces, not recalls — systems thinking applied to method itself.

**Modern guidance** — the handoff table (format per boundary, checked at review): 01→02 (keys enumerated (PK + alternates) + FK sentences + delete policies — 02's audit consumes directly); 02→03/04 (form claimed + violation records with six fields — documents/junctions bend knowingly, records referenced); 03/04→05 (aggregates/boundaries + widths/counts + skew surfaces + predicates — capacity consumes all four; partition keys derive from predicates + celebrities); 05→06 (triggers with owners + purge windows + retention tiers — gauges monitor triggers, jobs execute tiers, outboxes serve phased rollouts); 06→01 (gauges and incidents feed back — relay lag informs aggregate sizing; purge pain informs lifecycle design — the loop closes: operations experience revises entities). Review checks handoffs (upstream artifact present? format complete? downstream consuming, not re-deriving?) — missing handoff fails review structurally (content unexamined until interfaces complete — same discipline as code API reviews).

```sql
-- GOOD: handoffs named with formats — layers interfacing, not recalling.
-- 01→02: keys {users.id PK, users.email alternate} + FK sentences (policies included).
-- 02→04: 3NF claimed; copy: none (computed totals — no record needed — stated).
-- 04→05: widths (420B measured) + counts (50k/day) + skew (none — asked) + predicates (recency).
-- 05→06: triggers (partition 80M/platform; archive 13mo/data) + purge windows + tiers.
-- 06→01: relay lag nominal (aggregates well-sized — feedback recorded, loop closed).
-- Review: handoffs present, formats complete, downstream consuming. Approve layers.
```

```sql
-- BAD: layer amnesia — each layer re-deriving, mismatching, re-asking.
-- 02 audit: "what are the candidate keys?" (01 named none — re-derive at review cost).
-- 05 capacity: widths guessed (01's types unmeasured — 200B guessed, 420B actual —
-- spreadsheet fiction). 06 outbox: aggregates unconsulted (03's boundaries unknown —
-- relay surface mismatched to aggregate writes). 01 again: gauges unheard (06's relay
-- lag signaling oversized aggregates — unheard, unrevised). Six layers, six memories,
-- zero interfaces. Amnesia itemized; handoffs absent; re-derivation billed per review.
```

**Common confusion** — *"handoffs are process overhead for small teams."* Handoff formats cost lines (keys enumerated: one line; triggers named: one line each — seconds per artifact), while amnesia costs reviews (re-derivation per layer per feature — minutes-to-hours, compounding per hire who wasn't in the room). Small teams suffer amnesia worst (tribal memory walking out with departures — handoffs written survive, recalls don't). Artifacts outlive authors — the smallest teams need written handoffs most (bus factor 1 means memory factor 1 — write it down or lose it with the person). Lines now vs memory later — write the lines.

**Performance note** — handoff economics compound the track's performance argument finally: interfaced layers diagnose by layer (metrics labeled per handoff — FK scans? junction skew? residency cliff? relay lag? — each traceable to its layer's artifacts); amnesiac layers diagnose by archaeology (which assumption? whose recall? — unanswerable post-departure). Debugging interfaced systems is targeted (layer-labeled metrics → layer-owned fixes); debugging amnesiac systems is excavation (quarters per mystery). Interfaces pay in debuggability what they cost in lines — the method's final performance dividend, track complete.

**Mentor note** — teach handoffs as "APIs between thinking steps" (juniors grasping interface discipline from code APIs transfer it instantly — upstream outputs, downstream inputs, formats contracted, completeness reviewed). Review handoffs explicitly ("show me 01's key list feeding 02's audit" — missing link fails structurally). Teams interfacing thought scale thought (new hires consume artifacts, not mentors' time — onboarding via handoffs, not shadowing). Interface thinking; scale understanding; onboard via artifacts — the method teaching itself, mentors facilitating.
