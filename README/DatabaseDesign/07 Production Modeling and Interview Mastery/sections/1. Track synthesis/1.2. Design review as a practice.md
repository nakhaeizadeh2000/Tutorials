# 1.2. Design review as a practice

## 1. One review ritual for all domains (boundaries, catalogs, prices, blessings — unified)

**Definition** — the unified review template: every schema-affecting PR answers the same layered questions regardless of domain — **boundaries** (aggregates/entities named with invariants/lifecycles — which domain's §1 applies); **catalogs** (queries listed with frequencies/shapes/freshness where reads shape — which domain's access lens applies); **prices** (copies/nests/indexes/partitions budgeted with numbers — which domain's ledger applies); **blessings** (deviations recorded with owners/triggers — which domain's register applies). One ritual, seven domains' content — reviewers learn one procedure, authors fill one template, depth varies by novelty (trivial changes answer in lines, novel features in design docs — same questions, scaled answers).

**What problem it solves** — review fragmentation (each domain's checklist applied in isolation — or worse, only the author's home domain reviewed: normalization checked, skew unasked, gauges unmentioned — partial reviews approving partial designs); and review absence disguised as speed ("small PR, quick approve" — small diffs with unpriced consequences: one-line NOT NULL, one nested array, one unindexed FK — each trivial to write, each incident-capable). The unified ritual forces all layers' questions on every schema PR — trivial answers for trivial changes (seconds), deep answers for novel ones (design docs) — but never absent answers. Ritual completeness scales with novelty; ritual presence never waives.

**Modern guidance** — the template, filled per PR (sections omitted only with "N/A because X," never silently): **B**oundaries (entities/aggregates + invariants + lifecycles — links to home-domain leaves); **C**atalog (reads/writes with rates — or "read/write-neutral change," stated); **P**rices (every nest/copy/index/partition/trigger budgeted — numbers or "no new structures"); **B**lessings (deviations with owners/triggers — or "none — 3NF/defaults throughout"). Author fills; reviewer verifies per line; automation checks structure (CI linters from Domains 04–06 — unindexed FKs, unlabeled migrations, unowned flags fail builds); humans check judgment (policies, prices, triggers — mentors own these lines). B-C-P-B: four letters, complete review, every schema PR, forever.

```sql
-- GOOD: the unified review artifact — four letters, all answered (junction + flag PR).
-- B: memberships junction (entities users/groups exist; invariant: one membership per pair).
-- C: reads "my groups" 500k/d + "members" 50k/d; writes 10k/d single-writer (no veto).
-- P: both directions indexed at birth (PK + reverse INCLUDE role); skew: flagship capped,
--    counts cached (04/3.1 ledger referenced); growth: 10k/d × 200B — trigger set.
-- B: none (3NF, defaults, no deviations — stated, not assumed). Verdict: approve layers.
```

```sql
-- BAD: the fragmented review — home domain checked, six others unasked.
-- "Junction looks normalized. +1." (B: entities assumed — invariant unstated. C: reads
-- unlisted — admin screens unborn yet unindexed. P: reverse index unasked — 200M-row
-- scans scheduled. B: skew unexamined — flagship launching at press event.)
-- One domain reviewed; six waived silently; production grades all seven. Partial review,
-- complete consequences. Ritual presence would have cost lines; absence bills quarters.
```

**Common confusion** — *"unified rituals are bureaucracy."* (Asked and answered per-domain; restated finally for the unified form.) Bureaucracy is cost without benefit; ritual lines cost seconds-to-minutes and prevent quarters of incidents — the highest-ROI minutes in schema work, seventh restatement, track complete. Teams calling rituals bureaucracy ship without them exactly until the first preventable outage — then adopt them under incident pressure (worst time to design process). Adopt calmly now (template + automation + judgment split) or adopt frantically later (postmortem action items, resented, half-followed). Calm adoption, permanent value.

**Performance note** — unified review is upstream performance work in total (same argument compounded finally: every layer's performance contribution — residency, pruning, relay scans, claim indexes, cached flags — reviewed at modeling time, never tuned later in panic). Review minutes convert to outage-hours avoided at the track's usual exchange rate — stated seven times because believed zero times by newcomers and seventh-time by practitioners. Minutes now, quarters never — the ritual's economics, track complete.

**Mentor note** — teach B-C-P-B as the review alphabet (juniors spelling reviews letter-by-letter internalize completeness before speed — speed follows repetition, completeness never follows speed-first habits). Post the template where PRs are written (PR template pre-filled with B/C/P/B headings — authors fill, reviewers verify — structure enforced by tooling, judgment by humans). Four letters, one habit, every schema PR — onboarding teaches the alphabet week one; fluency follows within a quarter; mastery reviews others' alphabets within a year.

## 2. Registers are the institutional memory (decisions, blessings, triggers, versions — four ledgers)

**Definition** — the four registers (ledgers maintained per team, reviewed quarterly): **decisions** (ADRs — why shapes are what they are — key choices, denormalizations, partition keys, outbox adoptions — dated, attributed); **blessings** (priced deviations with owners/triggers — denormalization records, skew mitigations, permanent flags — expiring, never fossilizing); **triggers** (metric → threshold → response → owner — capacity, skew, purge, graduation — monitored, firing); **versions** (live schema/document versions with budgets — migration phases in flight, lazy adaptations outstanding, flag lifecycles). Memory that survives departures (written, indexed, reviewed — tribal knowledge institutionalized); amnesia scheduled never (unwritten decisions evaporate with authors — bus factor 1 means memory factor 1).

**What problem it solves** — institutional amnesia (the "why is this like this?" quartet asked per quarter: denormalized why? (unrecorded — re-litigated or "fixed" into regression); trigger for what? (unwritten — fired never, discovered expired); version 2 of what? (undocumented — migration targets uncountable); blessed by whom? (unsigned — fossilized deviations untouchable). Each unanswered question costs re-derivation (hours), wrong-way migration (quarters), or incident (unbounded). Registers answer all four structurally (written at decision time — ten minutes; read in seconds forever; reviewed quarterly — 30 minutes per register). Memory cheap at writing, dear at reconstructing — write early, read always.

**Modern guidance** — the register habit (one habit, four ledgers): *write at decision time* (ADR/blessing/trigger/version recorded in the deciding PR — context hot, cost minutes); *index centrally* (ADRs numbered, blessings searchable by table, triggers dashboarded, versions inventoried — findable in seconds by strangers); *review quarterly* (registers swept with owners present — expired blessings re-priced, fired triggers executed, version budgets enforced, stale decisions superseded — 30 minutes per register, calendared); *cite in reviews* ("per ADR-021" — decisions referenced, not re-argued — re-litigation declined structurally). New hires read registers first week (onboarding via ledgers, not shadowing — institutional memory transferred without mentor-hours). Unwritten decisions don't exist (review mantra — "not in the register, didn't happen" — harsh, effective, true enough to work).

```sql
-- GOOD: registers living — written hot, read always, reviewed quarterly (excerpt).
-- Decisions: ADR-021 (order_totals MV — justification + numbers + owner + 2026-09).
-- Blessings: flagship skew (cached counts, keysets — trigger: 5M members — owner platform).
-- Triggers: partition orders at 80M (dashboarded — current 45M, firing ~month 11).
-- Versions: users v3 current, v2 lazy (budget 2 — v1 rewritten, closed).
-- New hire week 1: reads four registers — productive month 1 (no archaeology required).
```

```sql
-- BAD: tribal memory — decisions in heads, triggers in hopes, versions in vibes.
-- "Why denormalized?" (Author departed 2025 — re-derive or revere blindly.)
-- "Trigger for partitioning?" (Discussed once, written never — table at 400M unpartitioned.)
-- "Which versions live?" (Unknown — migration targets uncountable, readers guessing.)
-- "Who blessed this?" (Unsigned — fossilized, untouchable, feared.) Onboarding: shadow
-- seniors for months (mentor-hours burning); departures: memory walking out quarterly.
-- Amnesia itemized; ledgers absent; re-derivation billed per question, forever.
```

**Common confusion** — *"registers are documentation that rots."* Registers rot only unreviewed (quarterly sweeps prune expired blessings, supersede stale decisions, enforce version budgets, refresh triggers — maintenance calendared, 30 minutes per register). Unreviewed anything rots (code, docs, runbooks — rot is the default state of unmaintained artifacts, not a register-specific disease). "Docs rot" argues for maintained ledgers with owners and calendars (this promise), never for unwritten memory (tribal amnesia, guaranteed). Maintain rhythmically; trust structurally; onboard via ledgers.

**Performance note** — register economics: writing costs minutes per decision (hot context — cheapest knowledge-capture moment); reading costs seconds per question (indexed, searchable — vs hours of archaeology per unrecorded decision); reviewing costs 30 minutes quarterly per register (2 hours/quarter total — one meeting); amnesia costs re-derivation hours + wrong-way migration quarters + incidents unbounded. Ledger ROI exceeds 100× within the first prevented re-litigation — the cheapest knowledge infrastructure in engineering, declined wherever "documentation" is a dirty word. Write hot; read always; review quarterly.

**Mentor note** — model register-writing on your own decisions first (the track's standing lesson, seventh and final domain: authority's example teaches — senior's ADR linked in PR teaches more than any documentation mandate). Start new teams with empty registers and full rituals (write-first culture from day one — no backlog to excuse); inherit messes with register-reconstruction sprints (archaeology once, ledgers forever after — "document what we learn while learning it"). Praise register citations ("per ADR-021 — great, no re-litigation") louder than clever arguments — teams optimize for praised behavior, and re-litigation has had enough enthusiasts.

## 3. Review cadence by lifecycle (per-PR checks, quarterly audits, yearly strategy)

**Definition** — review rhythm in three tempos: **per-PR** (B-C-P-B ritual — minutes, every schema PR — automation checks structure, humans check judgment); **quarterly audits** (registers swept, triggers re-derived, stale flags/blessings reviewed, version budgets enforced, capacity re-plotted — hours, owners present, tickets filed); **yearly strategy** (track-level questions: store choices still fit? topology adequate? team shape serving schema? — days, leadership present, roadmap updated). Tempos nest (PRs feed registers, registers feed audits, audits feed strategy — information flowing up, decisions flowing down); skipped tempos compound (unreviewed PRs → decayed registers → blind audits → strategic surprises — rot flowing down faster than information flows up).

**What problem it solves** — the two rhythm failures: *PR-only reviewing* (tactical excellence, strategic blindness — every PR correct, registers decaying, triggers expiring silently, strategy drifting — death by a thousand correct merges); and *audit-only reviewing* (quarterly heroics on decayed quarters — 200 stale flags, 50 expired blessings, 3M-member unexamined celebrities — audits as archaeology expeditions, findings overwhelming, follow-through failing). Three tempos cover three horizons (PRs: today correct; audits: quarters healthy; strategy: years directed) — missing any tempo blinds its horizon (correct todays accumulating into unhealthy quarters into undirected years — the slow drift no single review catches).

**Modern guidance** — the cadence contract (calendared, owned, never "when time permits"): *per-PR* (template enforced — CI structure + human judgment — every schema PR, no exceptions, no "trivial" waivers — trivial answers, instant approval, ritual presence intact); *quarterly* (register sweep week — four registers, owners present, tickets filed per finding — findings triaged like bugs (P1–P3 with dates), never "accepted" vaguely); *yearly* (strategy offsite input — growth vs topology fit, store choices, team capabilities — roadmap updated with modeling implications — leadership deciding with registers as evidence, not vibes). Skipped sessions rescheduled within two weeks (never dropped — dropped cadence signals optional cadence; optional cadence dies within two quarters — protect the rhythm like production uptime, because it protects production uptime).

```sql
-- GOOD: cadence calendared — three tempos, owners, no gaps (excerpt).
-- Per-PR: B-C-P-B template (CI + humans — every schema PR — trivial answers welcome, absent forbidden).
-- Quarterly (register week, owners present): blessings re-priced, triggers re-derived from fresh
-- rates, flags audited (stale → tickets), versions budgeted (excess → rewrite jobs), capacity
-- re-plotted (cliff dates updated). Yearly (strategy input): store fit? topology adequate?
-- team shape? — roadmap updated, modeling implications attached. Rhythms nested, horizons covered.
```

```sql
-- BAD: arrhythmic reviewing — PRs sometimes, audits never, strategy by surprise.
-- PRs: "looks fine" (template absent — partial reviews, silent waivers for "trivial").
-- Quarterly: unscheduled 6 quarters running (registers decayed — 200 stale flags, blessings
-- fossilized, triggers expired silently, versions drifted to 5 live). Yearly: strategic
-- surprise (topology inadequate — discovered during the outage that needed sharding designed
-- two years prior; store misfit — document shapes forced where relational belonged, vice versa).
-- Correct merges accumulating into unhealthy quarters into undirected years. Rhythm absent;
-- drift present; surprises scheduled (by entropy, dateless, as usual).
```

**Common confusion** — *"cadence is process overhead that slows delivery."* (Asked and answered per-domain and per-tempo; restated finally for rhythm itself.) PR ritual costs minutes (amortized to zero marginal — fluency follows repetition); quarterly audits cost hours per quarter (2-hour register week — cheaper than one incident review); yearly strategy costs days yearly (leadership time — cheapest strategy input available: evidence-rich registers vs consultant vibes). Overhead framing counts ceremony minutes while ignoring drift quarters — full ledger favors rhythm by orders of magnitude, seventh and final restatement, track complete.

**Performance note** — cadence economics close the track's performance argument finally: per-PR review prevents incidents (minutes → quarters-saved, every layer); quarterly audits prevent decay (hours → comprehension preserved, triggers firing, sediment cleared); yearly strategy prevents misfit (days → topology adequate, stores fitting, team capable). Three tempos, three horizons, one ledger — performance delivered at design/review/audit/strategy times, never firefighting time. The method's total dividend: boring operations, comprehensible schemas, directed evolution — track complete, on-call asleep.

**Mentor note** — protect cadence like uptime (skipped sessions rescheduled within two weeks — leaders attending audits signal priority louder than any mandate; audits leaders skip die within two quarters — attendance is the process). Start cadence with the team present (rituals imposed fail; rituals co-designed persist — first register week facilitated, template tuned to team, automation added where toil appears). Rhythm kept for a year becomes culture (new hires inherit cadence as "how we work" — unexplainable, unremovable, invaluable). Culture in three tempos — conduct steadily, mentors.
