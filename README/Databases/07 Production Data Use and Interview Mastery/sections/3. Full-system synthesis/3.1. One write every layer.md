# 3.1. One write, every layer

Tracing one write cradle to grave through every data layer — flags to pool to checkout to constraints to WAL to maps to logs — with budgets per layer and cold narration. Junior read: follow the write, name each layer. Expert read: where budgets bind layers together, and why narration skill predicts incident skill.

## 1) Trace cradle to grave

### 1) **Definition** (the full-passage inventory)

One write inventoried per layer it traverses: invocation flags (pool config, timeouts — which doors opened) → pool checkout (which connection, held how long) → constraint checks (which rules validated) → WAL flush (commit durability) → maps (trace attribution on failure) → logs/profiles (evidence landed). Each layer named with its owning domain (01–06); no layer skipped, none hand-waved.

### What problem it solves (history)

Layer-blind debugging (tuning pools for map failures, re-reading configs for constraint violations, profiling for typos) wasted incidents layer-hopping at random — every layer *can* explain any symptom vaguely, so undisciplined triage picks familiar layers over indicted ones. The cradle-to-grave trace disciplines passage thinking: evidence per layer, in traversal order, skipping none — the indicted layer identified by elimination, not familiarity.

### Modern guidance

Trace per incident (write the layer list before theorizing — seven lines, two minutes); trace per design (new write paths narrate their layers in the design doc — layers named, owners linked); trace per interview (cold narration — part 3's skill, rehearsed here). Layer lists live beside triage (gates 1–6 stage the same passage as assertions — trace narrates what gates verify).

### Runnable example (good — the write trace, budgeted, verified)

```bash
node -e "
const spans = [['flags/pool-checkout',2],['constraint-checks',1],['WAL-flush-commit',4],['map-trace',0.5],['log-profile',1]];
const total = spans.reduce((a, s) => a + s[1], 0);
for (const [n,ms] of spans) console.log(n+':', ms+'ms');
console.log('total:', total+'ms', '| slowest:', spans.reduce((a,b) => a[1]>b[1]?a:b)[0]);"
# flags/pool-checkout: 2ms
# constraint-checks: 1ms
# WAL-flush-commit: 4ms
# map-trace: 0.5ms
# log-profile: 1ms
# total: 8.5ms | slowest: WAL-flush-commit
```

```bash
DATABASE_URL=... node -e "
  await c.connect(); await c.query('BEGIN');
  await c.query(\"INSERT INTO txn_demo ... ON CONFLICT (owner) DO UPDATE ...\");
  await c.query('COMMIT'); await c.end();"
# one-write round trip ms: 55   (handshake + 4 statements — measured, cleaned after: probe row deleted)
```

Verified (local spans + live round trip): illustrative budgets sum to 8.5ms (slowest: WAL flush — durability priced, always the floor); live round trip 55ms (handshake-dominated — pool reuse amortizes it away in production, per [04/1.1](<../../../04 Node.js Data Access Drivers and Pooling/sections/1. Drivers/1.1. pg Pool that serves.md>)). The trace's value isn't the numbers (per-tree) but the *inventory* (per-incident): slowest layer named first, optimization aimed once.

### Common confusion

- **"tracing means distributed tracing"** — distributed tracing (spans across services — OpenTelemetry, Jaeger) tracks *writes across systems*; this trace tracks *work through layers* (flags to logs within one write path). Complementary instruments (write journey vs layer passage); different questions (where slow across services? vs which layer misbehaves here?). Both, never either/or — the layer trace locates, the distributed trace correlates.
- **"one trace covers all failures"** — traces cover *passages* (write, read, migration, restore — each with its layer list); failures select passages (write failure → write trace; restore failure → restore trace). Wrong-passage traces mislead (read layers blamed for write-config faults). Match the trace to the failing unit of work first — passage selection precedes layer analysis.

### Performance note

Trace-inventory cost per incident: minutes (seven lines) against layer-hopping hours (familiar-layer bias per responder). Budgeted traces compound (per-layer numbers accumulate into capacity math — [1.1](<../1. Production judgment/1.1. Capacity judgment under constraints.md>) part 3 consumes them). Inventory is triage performance wearing a documentation costume.

### Mentor note

Whiteboard the trace cold with mentees (no notes, seven layers, owners named): hesitation points reveal knowledge gaps precisely (stumble at WAL → re-teach [05/1.1](<../../../05 Transactions Consistency and Integrity/sections/1. Guarantees/1.1. ACID that holds.md>); stumble at maps → [06-adjacent map discipline]). The whiteboard is a diagnostic instrument for the engineer, not just the system.

## 2) Budgets per layer

### 2) **Definition** (time and bytes accounted)

Each layer carries a budget: pool checkout (microseconds — amortization verified), constraint checks (microseconds — probes gladly paid), WAL flush (milliseconds — durability floor), maps/traces (microseconds per frame — incidents only), logs/profiles (background — pennies). Totals reconcile (sum of layers ≈ observed — unaccounted remainder is the next investigation, never rounding error). Budgets live in ADRs ([1.1](<../1. Production judgment/1.1. Capacity judgment under constraints.md>) part 3); violations page with the layer named.

### What problem it solves (history)

Unbudgeted layers hid regressions (WAL latency creeping per fsync mode change, constraint-check pileups per added rule, pool checkout queues growing per traffic — each invisible until totals breached SLOs with quarters of archaeology: when did it start? — unknowable without history). Per-layer budgets convert total-breaks into layer-breaks (which budget blew? — named owner, named fix, measured receipt). Attribution precedes optimization, always.

### Modern guidance

Budget the passage, not just the request (writes, reads, migrations, restores — every repeated unit of work gets per-layer numbers); reconcile totals per quarter (sum vs observed — drift investigated, budgets refreshed); alarm per layer (thresholds at 80% — pages name layers, responders arrive oriented). Budget reviews ride release trains (numbers refreshed with traffic deltas — stale budgets mislead like stale maps).

### Runnable example (good — reconciliation, verified arithmetic)

```bash
# from the trace above: 2+1+4+0.5+1 = 8.5ms accounted; live round trip measured 55ms
# remainder: handshake (~14ms, per [04/1.1] measurement) + network + client overhead
# → remainder explained (pooled production amortizes handshakes — the 55 shrinks toward ~10)
# anti-example: wall-clock 400ms vs 8.5ms accounted → 391ms unaccounted = the investigation
# (profiler on the write path, per [06/3.1] — hidden layer found, budgeted, owned).
```

### Common confusion

- **"budgets constrain optimization"** — budgets *direct* it (slowest budgeted layer optimized first — guaranteed highest ROI; unbudgeted optimization wanders). Constraint enables focus: the budget names the target, the profile confirms, the fix lands measured. Unfocused optimization polishes fast layers while slow ones bill.
- **"byte budgets are premature"** — byte budgets gate transfers (payload sizes, map files, dump artifacts — registry/deploy costs scale linearly with bytes). Premature for prototypes (unmeasured, unshipped); mandatory for production (measured, shipped, billed per byte per deploy). Budget at the shipping boundary (payload sizes, dump artifacts — registry/deploy costs scale linearly with bytes).

### Performance note

Method cost: one profiled write per hypothesis (seconds) + reading time (minutes) + fix verification run — against days of intuition-led optimization that optimizes cold layers. The receipt requirement (before/after numbers in the commit) is the highest-ROI process in performance work: unmeasured "fixes" that regressed are caught by their own missing numbers.

### Mentor note

The profile-review ritual: every perf PR attaches before/after layers (or time deltas) with the slowest box named. No attachment, no approval — the rule converts optimization from opinion to evidence within a quarter. Mentees learn to *enjoy* being wrong ("hypothesis disproven by trace" beats "fix shipped on hunch" — celebrate the disproof publicly).

## 3) Narrate it cold

### 3) **Definition** (narration as mastery proof)

Whiteboard the full passage — flags to logs, seven layers, owners and budgets named — from memory, aloud, in five minutes, fielding interruptions ("what if the constraint fails here?" — answered with the refusal code, not deflection). Cold narration proves compiled judgment: knowledge retrievable under pressure, organized by traversal, priced per layer. Interviewers hire narrators; incidents obey them.

### What problem it solves (history)

Reference-dependent engineers (fluent with docs open, helpless paged) bottleneck incidents on search speed (grep the runbook while the system burns — minutes lost per lookup, confidence draining per pause). Narrators carry the model internally (layers ordered, owners known, budgets approximate — precise enough to act, honest about approximations). Incidents need actors with models, not readers with bookmarks.

### Modern guidance

Rehearse monthly (five-minute whiteboard, peer-interrupted — the [5.1](<../5. Interview questions and answers/5.1. Common interview QA judgment synthesis.md>) drill doubles as incident training); narrate per incident (timeline spoken in layer terms — responders synchronize on shared vocabulary); teach per quarter (narrate to juniors — transfer proves retention, per [4.1](<../4. Important points to remember/4.1. Mastery checklist habits mentors insist on.md>) part 3).

### Runnable example (good — the narration outline, memorizable)

```markdown
# cold narration (seven beats, five minutes):
# 1. flags open pool doors (URL + max + timeouts — [04/1.1])
# 2. checkout binds the unit (connect → BEGIN — [04/2.1])
# 3. constraints validate (named refusals or passage — [02/2.1])
# 4. WAL flushes commit (durability priced — [05/1.1])
# 5. maps attribute traces (frames name sources — [06-adjacent map discipline])
# 6. logs profile evidence (gates green, counts quoted — [06/4.1])
# 7. budgets reconcile (sum vs observed — [1.1] part 3)
# interruptions welcome — each beat routes to its domain on demand.
```

### Common confusion

- **"narration is performance, not skill"** — narration *demonstrates* compiled judgment (retrieval under pressure with organization intact — the closest observable to incident competence). Memorized scripts shatter on interruption (first "what if" breaks them); modeled understanding routes (every interruption answered from structure). Interviewers interrupt deliberately — they're testing the model, not the recitation.
- **"diagrams replace narration"** — diagrams aid narration (drawn *while* speaking — evidence of generation, not recall); pre-made diagrams substitute poorly (pointing at boxes isn't traversing layers — passive orientation, not active command). Draw live, narrate live, invite interruption — the live trio proves ownership.

### Performance note

Narration practice costs five minutes monthly per engineer (whiteboard + peer) against incident command quality (narrators direct multi-responder incidents coherently — shared vocabulary, ordered stages, no duplicated work). Teams that narrate resolve faster with fewer responders — narration is organizational performance (parallel machine, orchestrated by voice).

### Mentor note

The narration gauntlet graduates seniors (five minutes, three interruptions, all routed — pass/fail with feedback, retake monthly): ceremony creates the skill (deadline + audience + interruption pressure simulate incidents safely). Celebrate first passes publicly (narrator status is team infrastructure — recognize it as such). Re-gauntlet yearly (models decay — refresh or retire).
