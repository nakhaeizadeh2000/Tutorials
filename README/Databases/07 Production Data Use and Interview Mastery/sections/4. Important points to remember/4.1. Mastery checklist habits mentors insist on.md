# 4.1. Mastery checklist (habits mentors insist on)

The fluency inventory for data mastery: six domains plus synthesis, receipts over opinions, teaching as retention. Junior read: work the list top to bottom. Expert read: why each item resists faking, and what "done" evidences per line.

## 1) Six domains, one engineer

### 1) **Definition** (the fluency inventory)

Fluent in all six mechanics domains (foundations, Postgres, MongoDB, access, integrity, operations — operate each unaided) plus synthesis (this domain — judge across them), expert in several (depth provable: plans read, races shut, restores rehearsed, incidents narrated). Fluency evidenced per domain (gate green, artifact built, trace narrated — not claimed); expertise evidenced by teaching (juniors reviewed, game-days led, ADRs authored).

### What problem it solves (history)

T-shaped folklore ("I'm a Postgres person" — documents outsourced to superstition; "I do ops" — transactions a mystery) produced engineers fluent in slices and helpless across boundaries — incidents routing around them instead of through them. The inventory demands breadth first (every domain operable), depth second (several provable), and honesty always (gaps named with learning plans, never hidden behind titles).

### Modern guidance

Self-audit quarterly (per domain: operate unaided? teach simply? — check honestly, two axes each); close one gap per quarter (weakest domain first — deliberate practice with the domain's leaves as curriculum); evidence expertise publicly (review juniors, lead game-days, author ADRs — mastery demonstrated by transfer, per part 3). Titles follow evidence (promotion packets citing gates led and incidents narrated — receipts, not adjectives).

### Runnable example (good — the inventory, counted)

```bash
find README/Databases -name "*.md" | wc -l
# 62 (track README + LOG + 7 domain indexes + leaves — the corpus mastered here, mid-build count)
```

```markdown
# fluency self-audit (quarterly, honest):
# 01 foundations: operate ☐ teach ☐ | 02 postgres: operate ☐ teach ☐
# 03 mongodb: operate ☐ teach ☐ | 04 access: operate ☐ teach ☐
# 05 integrity: operate ☐ teach ☐ | 06 operations: operate ☐ teach ☐
# 07 synthesis: narrate cold ☐ review juniors ☐ author ADRs ☐
# rule: unchecked operate-box = this quarter's curriculum (leaves named, dates set).
```

Verified count this session (62 md mid-build — grows to track-complete as leaves land): the corpus is finite, enumerable, and completable — mastery bounded by a file count, not a feeling. Operate-boxes checked against gates (green output, not memory); teach-boxes checked against humans taught (names, dates — transfer witnessed).

### Common confusion

- **"expert in everything"** — expertise is scarce by definition (several domains deep, all operable — the inventory's actual bar). Claiming all-seven expertise signals Dunning-Kruger to interviewers instantly; naming two depths + four fluencies + one growth area signals calibration (the rarer, hireable trait).
- **"checklists replace judgment"** — checklists *route* to judgment (which domain? which gate? which evidence?) — the inventory tells you where to look, mastery decides what you see there. Inventory without judgment is trivia; judgment without inventory is luck. Both, layered — fluency first, wisdom on top.

### Performance note

Inventory cost: one honest hour quarterly (self-audit + gap plan) against misassigned work (experts-in-name assigned beyond depth — slow delivery, escaped defects, review theater). Calibration is team performance (right engineer, right problem, first try) wearing a humility costume.

### Mentor note

Run the inventory as a 1:1 ritual (reportee self-scores, mentor probes one box with a scenario — "operate transactions? walk me through a lost update" — curiosity, not interrogation): probing keeps audits honest without policing. Growth plans follow gaps (weakest operate-box → domain leaves → dates → re-probe). Ritualize quarterly; mastery compounds yearly.

## 2) Receipts over opinions

### 2) **Definition** (the evidence standard)

Every technical claim ships with its receipt: performance (plans attached, deltas quoted), behavior (gate outputs pasted, exit codes named), capacity (arithmetic shown, sources cited), incidents (timelines with mapped counts). Opinions unaccompanied are hypotheses awaiting evidence — welcome in discussion, inadmissible in decisions. "Measured" outranks "senior" in every forum that matters.

### What problem it solves (history)

Opinion-driven data work (loudest voice decides stores, hottest take sizes pools, longest tenure overrides plans — decisions uncorrelated with reality: re-litigated per quarter, regretted per incident) mistook rank for evidence (seniority as proof — authority substituting for measurement). Receipts discipline converts rank into evidence (junior with a plan outranks senior with a hunch — explicitly, culturally): decisions attributable to data survive personnel changes; decisions attributable to voices don't survive the meeting.

### Modern guidance

Attach receipts by default (PRs: plans/gates/arithmetic linked; design docs: numbers per option; incidents: timelines with counts quoted); challenge receipt-less claims kindly ("help me see the measurement" — curiosity, per [2.1](<../2. Review and design/2.1. Reviewing data code.md>) part 2's tone rule); store receipts with decisions (ADRs cite plans/gates by path — evidence replayable years later, per [1.1](<../1. Production judgment/1.1. Capacity judgment under constraints.md>) part 3).

### Runnable example (good — receipted vs unreceipted, contrasted)

```markdown
# receipted (decidable, replayable):
# "transpile-free pools cut p99: pool-wait 200ms → 5ms (checkout histogram, 2026-09 S4 probe) —
#  recommend max 8 for checkout service. Counter-case welcome with numbers."

# unreceipted (undecidable, unreplayable):
# "pools feel tight, let's double max."
```

Why receipts win: falsifiable (re-run the probe — confirm or refute in minutes), transferable (new engineers read numbers, not lore), and durable (ADRs cite them years later — decisions aging with evidence, not authority). Feelings initiate inquiry; receipts conclude it — confuse the phases and teams oscillate quarterly.

### Common confusion

- **"receipts slow decisions"** — receipts *accelerate* good decisions (measured options decide themselves — debate ends at data) and correctly slow bad ones (unmeasured leaps deserve friction — the slowdown is the safeguard). Fast wrong beats slow right nowhere except demos. Measure, then move — at full speed.
- **"all opinions need plans"** — trivially reversible decisions need logarithmic evidence (naming, formatting — decide and move on); load-bearing decisions need receipts (stores, capacity, architectures — measure first). Evidence proportional to blast radius — the standard scales, never absents.

### Performance note

Receipt culture costs measurement time per decision (minutes-to-hours, priced in [06/3.1](<../../../06 Performance Backup and Operations/sections/3. Visibility/3.1. Observability for data.md>)) against wrong-decision costs (rework, incidents, re-litigation — orders of magnitude larger, unpriced until billed). Highest-ROI culture available: pay per decision, collect per quarter, compound per year.

### Mentor note

Praise receipts publicly ("great plan — decision made") and request them kindly ("what would convince us? — let's measure that"): reinforcement shapes culture faster than policy (behavior rewarded repeats; behavior mandated resists). New hires calibrate within weeks watching receipts decide — the culture teaches itself once seeded.

## 3) Teach to retain

### 3) **Definition** (transfer as mastery proof)

Mastery evidenced by transfer: juniors reviewed kindly (failure-first lens taught, not just applied), game-days led (restore rehearsals, slow-query triage, degradation drills — rehearsals multiplying readiness), ADRs authored (judgment recorded for strangers), narration performed cold (five minutes, interrupted, routed). Retention follows teaching (explaining reorganizes knowledge — gaps surface mid-sentence, the best diagnostic available); titles follow retention (demonstrated, never self-declared).

### What problem it solves (history)

Hoarded expertise (seniors as single points of comprehension — incidents waiting on one human, reviews bottlenecked on one calendar) scaled teams sublinearly (headcount growing, throughput flat — every hard problem queuing for the same hero). Teaching converts heroes into multipliers (juniors deciding independently, game-days run without founders, ADRs answering questions nobody needs to ask twice) — throughput scaling with headcount again.

### Modern guidance

Review juniors kindly (teach the lens per comment — "gates first because…" — juniors taught, not just corrected); lead game-days quarterly (restore rehearsals, plan-reading sessions, degradation drills — rehearsals multiplying readiness); narrate publicly (design reviews, incident retros, onboarding — cold narration as team infrastructure); write ADRs as teaching (context future-strangers need — decisions that educate, not just decide).

### Runnable example (good — the transfer record, kept)

```markdown
# transfer log (per engineer, per quarter):
# - reviewed: 12 PRs (3 with failure-path teaching comments — linked)
# - led: restore-rehearsal game-day 2026-10 (8 attendees, counts matched live)
# - authored: ADR-004..006 (store choice, capacity, backup tiers — all with receipts)
# - narrated: onboarding cold-trace (5 min, 2 interruptions routed)
# mastery evidenced — promotion packet cites this log, not adjectives.
```

### Common confusion

- **"teaching costs delivery"** — teaching *accelerates* delivery (juniors deciding independently within quarters — review load falling, incident competence rising). Hoarding optimizes the sprint (hero fast this week); teaching optimizes the year (team fast every week after). Discount rates decide: quarterly thinkers teach, weekly thinkers hoard.
- **"kindness dilutes rigor"** — kindness *delivers* rigor (taught juniors apply gates-first permanently; shamed juniors comply temporarily). "Kind" modifies delivery (curious tone, public praise, private correction) — never standards (gates still block, numbers still required, failures still reviewed). Rigor with kindness retains; rigor without it repels.

### Performance note

Teaching costs hours quarterly (reviews with lens-comments, game-days led, ADRs written) against hero-bottleneck costs (single-point incidents, review queues, re-explained decisions — priced in delay per occurrence). Multipliers outperform heroes at every team size above three — the math favors teaching from the first hire.

### Mentor note

The mentor's own mastery metric: juniors taught to independence (count the decisions they make without you quarterly — rising = succeeding; flat = hoarding). Optimize the metric explicitly (delegate decisions with guardrails, review outcomes kindly, widen guardrails per success). Mentors measured by transfer produce transfers; mentors measured by output produce bottlenecks.
