# 4.1. Access checklist (habits mentors insist on)

The three habits that keep data access boring: pools sized and drained by numbers, checkouts bound with migrations versioned, resilience budgeted per hop. Junior read: extend the gate with three access stages. Expert read: which incident each stage names, and why shape-checks belong in CI rather than in reviewers' memories.

## 1) Pool sized, drained, witnessed

### 1) **Definition** (numbers over defaults)

Pool `max` derived (slots × headroom, server-share-capped — [1.1](<../1. Drivers/1.1. pg Pool that serves.md>) part 2), drain asserted (`pool.end()` → total 0 — [1.1](<../1. Drivers/1.1. pg Pool that serves.md>) part 3, witnessed), counts monitored (total/idle/waiting dashboarded — drift alarms before exhaustion). Bare `new Pool()` / `new Client()` in request paths fails the gate (stage 40 — unsized, undrained, unwitnessed by construction).

### What problem it solves (history)

Default-shaped pools (bare constructors — `max` defaulted, drain untested, counts unmonitored) scaled connection counts with topology (services × replicas — "too many clients" at quiet hours) and hung exits mysteriously (sockets holding loops past orchestrator grace — SIGKILL finishing uncleanly). Sized/drained/witnessed pools convert both to reviewed numbers (max commented with arithmetic, drain tested with signals, counts alarmed with thresholds).

### Modern guidance

Size per service (arithmetic + server-share cap — commented beside `max`, reviewed per growth); drain per process (SIGTERM → `end()` → exit 0 — tested with kill signals, per [1.1](<../1. Drivers/1.1. pg Pool that serves.md>) part 3); witness per lifecycle (total/idle counts in tests and dashboards — hygiene observable, drift pageable). Bare constructors in committed code are findings (stage 40 fires — size, drain, and witnessagna all absent where the bare call stands).

### Runnable example (good — stage 40, verified)

```bash
#!/bin/bash
# access gate: sized pools + bound units + keyed retries
if grep -rEn 'new (Pool|Client)\(\)' gateacc/ 2>/dev/null; then exit 40; fi
if grep -rEn "pool\.query\('BEGIN'\)" gateacc/ 2>/dev/null; then exit 41; fi
if grep -rEn 'while \(true\)' gateacc/ 2>/dev/null; then exit 42; fi
echo ACCESS-GREEN
```

```bash
./gate4.sh; echo "exit=$?"
# gateacc/dirty.js:1:const pool = new Pool();
# exit=40
# (dirty file removed →)
# ACCESS-GREEN
# exit=0
```

Verified: bare `new Pool()` fires stage 40 with filename + line (evidence, not suspicion); sized pool (`max: 8`) greens. Honest boundary: the grep catches *bare* constructors (unsized by construction); reviewed arithmetic behind sized pools stays human-judged (gates catch absence, reviewers judge numbers — split from [02/4.1](<../../../02 Postgres Deep Dive/sections/4. Important points to remember/4.1. Postgres checklist habits mentors insist on.md>), applied).

### Common confusion

- **"gate green means pools healthy"** — gate green means pools *shaped* (sized, drained-by-construction, witnessed — structural health); runtime health needs *monitoring* (counts dashboarded, waits histogrammed — operational health). Shape gates pre-merge (CI); runtime monitors post-deploy (dashboards). Structural green never implies operational green — both, layered.
- **"one pool check covers all"** — bare-constructor grep covers *sizing-absence* (one of three habits); drain needs signal tests (kill under load — behavioral); witnessing needs dashboards (counts over time — operational). One grep, one habit — three habits need three evidences (stages 40/41/42 pattern per habit, gates per concern).

### Performance note

Gate cost per run: greps (milliseconds) — cheapest stages after version prints. Default-pool cost: quiet-hours pages (topology-scaled counts — incidents per deploy added) + mystery hangs (un-drained exits — minutes per rollout). Sized/drained/witnessed pools cost review minutes once (arithmetic commented, drain tested, dashboards built) — incidents prepaid per service, permanently.

### Mentor note

Audit every repo's pools in sixty seconds (grep constructors, check max comments, verify drain tests exist): missing pieces are findings with fixes attached (size with arithmetic, drain with signal test, witness with dashboard). Mentees inheriting repos run the audit before trusting a single pool — orientation via construction sites, not incidents.

## 2) Checkouts bound, migrations versioned

### 2) **Definition** (units homed, schemas historied)

Transacted units ride explicit checkouts (`pool.connect()` → lifecycle → `release()` — [2.1](<../2. Discipline/2.1. Checkout discipline.md>), never `pool.query` sequences); schema changes ride versioned files (numbered, tracked, rerun-safe — [2.2](<../2. Discipline/2.2. Migrations basis.md>)). Gate stage 41 fires on scattered-unit shape (`pool.query('BEGIN')` — binding absent where units exist); migration review fires on unfiled DDL (console ALTERs — history absent where evolution happened).

### What problem it solves (history)

Unhomed units (scattered `pool.query` transactions — atomicity voided silently, per [2.1](<../2. Discipline/2.1. Checkout discipline.md>) part 1's verified exhibit) plus unhistoried schemas (console ALTERs — drift per environment, restores untrustworthy, per [2.2](<../2. Discipline/2.2. Migrations basis.md>) part 1) combined into data layers nobody could reason about (units unbound *and* schemas undocumented — every incident greenfield archaeology). Binding + versioning convert archaeology to reading (units homed, schemas historied — evidence per layer).

### Modern guidance

Checkout per transacted unit (explicit object — lifecycle unbroken); file per schema change (numbered, tracked, expand/contract phased); gate the shapes (stage 41: scattered-BEGIN grep; migration review: file presence per DDL diff); review the semantics (unit boundaries judged — one fate per intent; phase labels judged — expand vs contract marked).

### Runnable example (good — stage 41 shape, described precisely)

```bash
# stage 41 fires on the scattered-unit shape (pattern — same grep family as verified stage 40/42):
# pool.query('BEGIN'); pool.query('UPDATE ...'); pool.query('COMMIT');
# → exit 41 (each pool.query may borrow differently — unit scattered, atomicity void)
# fixed shape (verified live in [2.1]: checkout 1/0 → conserved 65/85 → released 1/1):
# const c = await pool.connect(); try { BEGIN/WORK/COMMIT } finally { c.release(); }
```

### Common confusion

- **"linters catch scattered units"** — linters parse *syntax* (query strings opaque — `pool.query('BEGIN')` looks identical to `pool.query('SELECT 1')` syntactically; intent invisible without data-flow). Shape-greps catch *patterns* (BEGIN-via-pool — textual signature, no data-flow needed); reviewers catch *units* (unwrapped pairs — semantic judgment). Three layers (lint syntax, grep shapes, review units) — defense in depth, honestly layered.
- **"migration files slow schema work"** — files *record* schema work (seconds per change — numbered, tracked); unfiled work *costs* drift incidents (hours per occurrence — environments disagreeing, restores roulette). Recording is cheaper than remembering (files don't forget across hires, consoles do) — version always, from the second change.

### Performance note

Binding/versioning costs: checkout discipline (parameter passing — free) + migration files (seconds per change — writing + review). Scattered-unit cost: partial-state incidents (hours with misdirection, per occurrence); unfiled-schema cost: drift incidents (hours per occurrence, environments snowflaking). Construction + history: free prevention, cheap recording — fund both permanently.

### Mentor note

Pair the two reviews (checkout-shape grep + migration-file presence — one pass over data PRs): mentees internalize homed-units + historied-schemas together (units homed where executed, schemas historied where evolved — the pair that makes data layers readable). Two checks, one pass, permanent readability — review economics at their finest.

## 3) Resilience budgeted per hop

### 3) **Definition** (timeouts, keys, backoff — gated)

Every hop bounded (statement/topology/socket timeouts set — [3.1](<../3. Resilience/3.1. Retries timeouts and backoff.md>) part 1), every retry keyed (idempotency per action — [03/3.1](<../../../03 MongoDB Deep Dive/sections/3. Writes/3.1. Writes ids and idempotency.md>)), every attempt spaced and capped (backoff+jitter+ceilings — [3.1](<../3. Resilience/3.1. Retries timeouts and backoff.md>) part 3). Gate stage 42 fires on unbounded retry shapes (`while (true)` retry loops — termination absent where attempts live).

### What problem it solves (history)

Unhopped resilience (timeouts defaulted, retries blind, loops unbounded — each default reasonable alone, catastrophic composed: hung slots + duplicate storms + infinite attempts hitting a recovering upstream simultaneously — the outage aftershock bigger than the quake, per [3.1](<../3. Resilience/3.1. Retries timeouts and backoff.md>) part 2's verified reasoning) mistook defaults for design (unconfigured behavior treated as chosen behavior — hope wearing configuration's clothes). Budgeted resilience configures each axis deliberately (bounds set, keys minted, attempts capped — design, not default).

### Modern guidance

Bound per hop class (statements/topology/sockets — timeouts matching blip distributions, reviewed per environment); key per idempotent action (payments/orders/registrations — catch-and-fetch handlers, tested); cap per retry policy (attempts + delays bounded — storms structurally impossible); gate the shapes (stage 42: unbounded loops; timeout presence reviewed humanly — grep assists, judgment decides).

### Runnable example (good — stage 42, pattern-mirrored)

```bash
# stage 42 fires on unbounded retry shape (pattern — same grep family as verified stage 40):
# while (true) { await retry(op); }  →  exit 42 (termination absent — attempts infinite by construction)
# fixed shape: for (let attempt = 1; attempt <= 3; attempt++) { ... backoff ... } + idempotency keys
# (verified backoff shape in [3.1]: [100,200,400,800,1600] — bounded, spaced, capped)
```

### Common confusion

- **"resilience is ops-owned"** — resilience is *authored* (timeouts/keys/caps written in application code — developers own the shapes) and *operated* (thresholds tuned, storms paged — SRE owns the numbers). Unowned middle (code without bounds, ops without levers — each side assuming the other configured) fails at 3 a.m. with no owner. Author bounds, operate thresholds — ownership per layer, explicit.
- **"three gates are gate bloat"** — merge freely (gate1..gate4 → one script, stages 10/11/20/21/30/31/40/41/42, distinct exits — pedagogy splits per domain, operations unifies per repo, per [01/4.1](<../../../01 Database Foundations and Mental Model/sections/4. Important points to remember/4.1. Data checklist habits mentors insist on.md>)).

### Performance note

Resilience-budgeting costs authoring minutes per hop (timeouts set, keys minted, caps written — one-time) against cascade-hours per incident (hung slots + duplicate storms + infinite attempts — compounding per occurrence, fleet-wide). Budgeted hops fail over (bounded, named, routed); unbudgeted hops fail *outward* (cascading, duplicating, lingering). Fund budgets first, features second — availability precedes capability.

### Mentor note

The graduation exercise for this domain: hand the mentee an unwired repo (no pools, no timeouts, no keys, no gates) and gates 1–4. One hour to green-everywhere: sized pools, bounded units, keyed retries, versioned migrations — each artifact citing its leaf. Fluency demonstrated, access internalized, incidents prepaid for the team.
