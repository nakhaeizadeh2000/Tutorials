# 4.1. Integrity checklist (habits mentors insist on)

The three habits that keep consistency boring: lifecycles wired with levels chosen deliberately, constraints declared with anomalies tested, distribution explicit or absent. Junior read: extend the gate with three integrity stages. Expert read: which incident each stage names, and why model-checks belong in CI rather than in reviewers' memories.

## 1) Lifecycle correct, level deliberate

### 1) **Definition** (wired units, chosen levels)

Every transacted unit carries the five-line lifecycle (acquire/BEGIN/work/COMMIT-or-ROLLBACK/release — [02/3.1](<../../../02 Postgres Deep Dive/sections/3. Atomicity/3.1. Transactions basis.md>) part 3, gated below); every service declares its isolation level deliberately (default `read committed` *stated* — verified via `SHOW`, never assumed; escalations evidenced per [1.2](<../1. Guarantees/1.2. Isolation levels and anomalies.md>) part 3's ladder). Lifecycle without levels is 99% (correct units, unpriced interference); levels without lifecycle is theater (models atop scattered units — nothing to isolate).

### What problem it solves (history)

Lifecycle-correct/level-blind services (wired units under default levels — anomalies unmeasured, escalation never debated: non-repeatables misdiagnosed as logic bugs, lost updates patched per incident without level review) plus level-theorized/lifecycle-broken services (SERIALIZABLE declared over scattered `pool.query` sequences — models atop void units: strongest level, no unit to protect) failed opposite halves. The pair (wired lifecycle *and* deliberate level) covers both: units exist, interference bounded — each evidenced separately.

### Modern guidance

Gate the lifecycle (stage 50 below: BEGIN without ROLLBACK path fails the build — abandonment planned, structurally); assert the level (stage 51: `SHOW default_transaction_isolation` matches the declared default — floors verified, drift detected); escalate on receipts (anomaly reproductions committed beside level changes — ladder bottom-up, never theory-first, per [1.2](<../1. Guarantees/1.2. Isolation levels and anomalies.md>) part 3).

### Runnable example (good — the integrity gate, verified)

```bash
#!/bin/bash
# integrity gate: abandonment planned + default deliberate
if grep -rL 'ROLLBACK' gatetxn/*.js 2>/dev/null | grep -q .; then exit 50; fi
docker exec dbprobe psql -U postgres -tAc "SHOW default_transaction_isolation;" | grep -q "read committed" || exit 51
echo INTEGRITY-GREEN
```

```bash
./gate5.sh; echo "exit=$?"
# exit=50        (gatetxn/noabort.js: BEGIN without ROLLBACK path — abandonment unplanned)
# (noabort.js removed →)
# INTEGRITY-GREEN
# exit=0
```

Verified: stage 50 fires on the ROLLBACK-less unit (abandonment unplanned — the pool-poisoning shape from [04/2.1](<../../../04 Node.js Data Access Drivers and Pooling/sections/2. Discipline/2.1. Checkout discipline.md>), gated); stage 51 asserts the deliberate default (read committed — declared, verified, drift-detectable). Honest boundary: stage 50 greps *presence* (ROLLBACK path exists — shape), reviewers judge *correctness* (right ROLLBACK, right place — semantics: gates assist, humans decide).

### Common confusion

- **"lifecycle gates replace level review"** — lifecycle gates assert *wiring* (abandonment planned — structural); level review judges *interference* (anomalies measured — semantic). Wired-but-default-blind services pass stage 50 while exhibiting unmeasured anomalies (correct units, unpriced interference — half covered). Gates wire; reviewers model — both halves, always.
- **"declaring read committed is ceremony"** — declaring *verifies* (SHOW-asserted default — drift detected when providers/drivers change floors silently: assumption made visible, changes caught); ceremony *decorates* (comments restating code — no verification, no drift detection). Asserted declarations catch environment drift (the "works here, anomalies there" class — floors differing, code identical).

### Performance note

Gate cost per run: grep (milliseconds) + SHOW query (milliseconds) — cheapest stages after version prints. Lifecycle-correctness cost: finally-blocks (free) + ROLLBACK paths (tested — seconds per suite). Level-deliberateness cost: SHOW assertion (free) + anomaly probes per escalation (minutes per level-change, evidence-gated). Unwired/unmeasured cost: partial states + unpriced interference (hours with misdirection, per occurrence, both classes).

### Mentor note

Require lifecycle+level evidence in every data PR touching transactions ("show me the ROLLBACK path and the level declaration" — two artifacts, ten seconds to verify): mentees internalize wired-and-deliberate when reviewers ask consistently (three PRs and authors attach both unprompted — the habit that ends unwired units and undeclared levels permanently).

## 2) Constraints first, anomalies tested

### 2) **Definition** (invariants in DDL, races in suites)

Invariants declared as constraints (UNIQUE/CHECK/FK/EXCLUDE — [2.2](<../2. Mechanisms/2.2. Constraints as integrity.md>), reviewed per table); anomalies reproduced as tests (concurrent-client probes per race class — two writers, one survivor + `23505`, committed beside the DDL); isolation models chosen per test outcomes (levels adopted on reproduced anomalies — [1.2](<../1. Guarantees/1.2. Isolation levels and anomalies.md>) part 3's ladder, evidence per rung). Invariants hold regardless of caller; races proven shut regardless of load.

### What problem it solves (history)

Constraint-poor/anomaly-untested services (validity in application code — bypassed per new client; races untested — "works single-threaded" suites green while production concurrently corrupts: duplicates under retry storms, overbooks under flash sales — load-correlated corruption invisible to sequential suites) failed load-dependently (quiet correctness, loud corruption — incidents arriving with traffic, diagnosed as logic bugs). Constraints-first closes validity (store-enforced, caller-independent); anomaly-tests close races (concurrent probes, committed, green).

### Modern guidance

Constrain at CREATE (invariants in DDL — [02/4.1](<../../../02 Postgres Deep Dive/sections/4. Important points to remember/4.1. Postgres checklist habits mentors insist on.md>)'s two-timings rule); race-test per constraint (two-client probes: duplicates refused, overlaps rejected, counts conserved — committed in suites, green per run); level up on reproduced anomalies only (probe-first, theory-never — [1.2](<../1. Guarantees/1.2. Isolation levels and anomalies.md>) part 3 enforced as review policy).

### Runnable example (good — the race test committed, referenced)

```bash
# concurrent-racer shape (verified live in [2.2]: A: 23505 | B: B-inserted, rows: 1):
# two clients, same millisecond, check-then-insert identical keys →
# exactly one survivor + named refusal (TOCTOU shut structurally — committed beside the DDL
# as the race regression test: green suite = race still shut, red = regression, attributed).
```

### Common confusion

- **"constraint tests duplicate suites"** — constraint tests assert *invariants under concurrency* (two-client races — untestable sequentially: sequential suites pass race-broken schemas greenly, always); behavior suites assert *logic* (flows, calculations — single-client adequate). Different axes (concurrency vs logic), different tools (racer probes vs unit tests) — both suites, never either/or.
- **"anomaly tests are flaky by nature"** — racy tests flake (timing-dependent assertions — sleep-calibrated concurrency: red sometimes, green sometimes — worse than absent); *deterministic* anomaly tests synchronize (barrier/ordering primitives forcing interleavings — same schedule per run: green deterministically when shut, red deterministically on regression). Flakiness is a test-design failure (uncontrolled interleaving), never inherent (controlled interleavings decide deterministically).

### Performance note

Constraint-test cost per run (two-client probes — milliseconds, committed in suites); anomaly-suite cost (concurrent scenarios — seconds, scheduled per merge, not per push). Unconstrained-untested cost (duplicates/overbooks/skew discovered downstream — unbounded per occurrence, load-correlated). Races proven shut per merge (deterministic probes) beats races discovered per traffic spike (customer-observed corruption) — fund tests first, incidents never.

### Mentor note

The racer-probe exercise (two clients, same key, same millisecond — predict survivor-count before running: "exactly one + one 23505" — then watch): mentees predicting correctly own TOCTOU permanently (check-act fused at write time — understood kinesthetically, not theoretically). Commit the probe beside the DDL (race coverage living with the rule it guards — coverage that rots never, guards forever).

## 3) Distribute explicitly or not at all

### 3) **Definition** (named coordination per boundary)

Cross-system atomicity named per boundary (single-system default — no coordination; 2PC where genuinely atomic money moves with HA coordinators — [3.1](<../3. Distribution/3.1. Distributed honesty 2PC and sagas.md>) part 1, priced and rare; sagas where business converges stepwise — part 2, compensated; outbox where messaging bridges — part 3, relayed). Unnamed distribution (dual-writes hoped atomic — the densest incident class in backend code) rejected in review regardless of schedule pressure.

### What problem it solves (history)

Implicit distribution (DB+broker dual-writes "probably fine" — committed here, published there, best-effort between: paid-but-unshipped orders discovered by customers asking; saga-less multi-service writes — partial states permanent, discovered per audit quarter) failed at boundaries teams never named (coordination absent where atomicity assumed — hope as protocol, incidents as discovery). Explicit distribution (named per boundary — 2PC/saga/outbox chosen deliberately, reviewed structurally) makes boundaries auditable (coordination present where atomicity required — hope retired).

### Modern guidance

Default single-system (transactions end at the system edge — no accidental distribution: dual-writes reviewed as findings, not patterns); name coordination per crossing (2PC/saga/outbox decided per boundary — recorded in ADRs with prices, reviewed structurally); review dual-writes mechanically (DB+publish pairs flagged — "where's the relay row?" per pair, per [3.1](<../3. Distribution/3.1. Distributed honesty 2PC and sagas.md>) part 3).

### Runnable example (good — the boundary audit, narrated)

```markdown
# boundary audit (per service, quarterly):
# crossings enumerated (DB×broker pairs, service-to-service writes — listed, all of them)
# each named (outbox-relayed / saga-compensated / 2PC-coordinated / single-system — exactly one)
# unnamed crossings → findings (coordination absent where atomicity assumed — fixed this sprint)
# (outbox relay witnessed live in [3.1]: committed-visible 1, relayed {n:1} — the honest shape, referenced)
```

### Common confusion

- **"explicit distribution slows delivery"** — explicitness costs naming minutes per boundary (decision recorded — one-time); implicitness costs dual-write incidents (hours with misdirection, per occurrence — discovered by customers, fixed under pager pressure). Naming is the cheapest reliability practice available (minutes once, incidents never) — slow delivery is unreviewed rework, not deliberation.
- **"sagas everywhere is robust"** — sagas everywhere is *overhead* everywhere (compensations authored per step — unneeded where single-system transactions suffice: local units need lifecycle, not choreography). Robustness placed per boundary (distributed where systems divide — nowhere else): single-system by default (cheap, atomic, sufficient), distributed deliberately (priced, reviewed, rehearsed).

### Performance note

Explicit-distribution cost: decision minutes per boundary + mechanism costs (outbox rows negligible; saga steps local-commits fast; 2PC blocking priced per part 1 — chosen rarely, deliberately). Implicit-distribution cost: dual-write incidents (hours with misdirection + customer harm, per occurrence) + reconciliation toil (undecided boundaries reconciled manually, forever). Name boundaries once (cheap); reconcile unnamed ones forever (dear).

### Mentor note

The graduation exercise for this domain: hand the mentee a repo with four planted faults (unwired unit, undeclared level, unkeyed retry-adjacent race, unnamed dual-write) and gates 1–5. One hour to green-everywhere: lifecycles wired, levels declared, races shut, boundaries named — each artifact citing its leaf. Fluency demonstrated, integrity internalized, incidents prepaid for the team.
