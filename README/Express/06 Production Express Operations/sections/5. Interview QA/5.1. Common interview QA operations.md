## 1. Observability live under pressure (metrics, logs, correlation — measured, not vibed)

**Definition** — the observability answer interviewers grade: given a production Express app, name what's measured with numbers ([1.1](<../../sections/1. Observe/1.1. Request metrics that matter.md>)/[1.2](<../../sections/1. Observe/1.2. "Under pressure" means follow-ups demand numbers (p99? error budget? series count? — answers measured, never vibed).

**What problem it solves** — the vibes-answer trio: *metrics reciting without numbers* (RED naming — rates unstating (durations unbounding — tails unmeasuring (numbers missing — evidence absenting (understanding lacking — pressure collapsing); *logs unjoining* (IDs missing — journeys fragmenting (correlation absenting — debugging haunting (traces breaking — causality hoping (context missing — understanding blocking); *cardinality exploding* (IDs labeling — series multiplying (costs exploding — storage drowning (dimensions unbounding — value diluting (bounding missing — bills shocking). Measured answers converting vibes to numbers (RED emitting — logs joining (cardinality bounding — traffic proving); interviewers grading measurement (numbers + journeys + bounds → hired; healthy-hoping → rejected).

**Modern guidance** — the observability lines (interview-enforced): *metrics emitting* (rates counting — errors ratioing (durations timing — traffic proving (capacity planning — growth forecasting (numbers ruling — hope ending (arithmetic owning — fiction expiring); *logs joining* (IDs issuing — journeys assembling (children scoping — debugging easing (traces following — journeys completing (correlation proving — interleaving ending (understanding owning — causality proving); *cardinality bounding* (paths templating — IDs excluding (series capping — costs controlling (explosions preventing — queries serving (templates owning — precision keeping).

```javascript
// GOOD: observability measured — metrics emitting, logs joining, cardinality bounding (interview-grade shape).
// "RED per route (rates counting — errors ratioing — durations timing, traffic proving, capacity planning).
// Request IDs joining logs (journeys assembling — debugging easing — traces following, causality proving).
// Labels templated, IDs excluded (series capping — costs controlling — explosions preventing, queries serving)."
// BAD: vibes answer — metrics named, numbers absent, cardinality exploding (real rejection shape).
// "We monitor." (What RED? which journeys? — numbers missing — evidence absenting (understanding lacking — pressure collapsing).
// Logs interleaving sans IDs (journeys fragmenting — debugging haunting — traces breaking (correlation absenting — causality hoping).
// ID-valued labels (series multiplying — costs exploding — storage drowning). Measure; join; bound.)
```

**Common confusion** — *"observability questions test tools (APM naming)."* Tools displaying metrics (dashboards graphing — journeys showing (visibility starting — questions directing (tools serving — judgment owning); engineers emitting RED (rates counting — errors ratioing (durations timing — traffic proving (apps owning — evidence producing (instrumentation costing lines — blindness curing); correlation joining journeys (IDs issuing — logs assembling (traces following — debugging easing (correlation proving — interleaving ending). "Testing" describing tools (APMs naming — dashboards reciting); observability describing emission (rates counting — logs joining). Emit basics (apps owning — evidence producing); consume anywhere (vendors scraping — visibility compounding).

**Performance note** — observability economics: emitting costing increments + listeners (rates counting — durations timing (traffic proving — tails bounding (evidence producing — blindness curing); joining costing ID wiring (requests tagging — logs assembling (journeys completing — debugging easing (correlation proving — interleaving ending (understanding owning — causality proving); bounding costing label design (paths templating — IDs excluding (series capping — costs controlling (explosions preventing — queries serving); vibed equivalents costing rejected offers (recitation transparent — measurement unproven). Emit cheaply (increments — evidence); bound always (templates — costs).

**Mentor note** — teach "metrics, journeys, bounds — in that order" (juniors answering all three place observability on first hearing; tool-naming interrogated ("which numbers?" — measurement demanding per answer). Mock drill: interviewer demanding numbers per claim (p99? budget? series? — pressure practiced, not theorized). Measure everything; vibe nothing — observability judgment in three habits, reviewed per answer.

## 2. Performance live under pressure (compression, connections, loops — diagnosed with fixes)

**Definition** — the performance answer interviewers grade: given slow responses, name the lever with prices ([2.1](<../../sections/2. Performance/2.1. "Live" means levers stating (negotiating pricing — persisting reusing (breathing yielding — performance proving).

**What problem it solves** — the slow-response trio: *payloads bloating* (bytes wasting — bandwidth billing (latency dragging — transfer pricing (compression missing — negotiation skipping (savings ignoring — waste normalizing); *handshakes repeating* (connections closing — sockets dying (TLS renegotiating — latency adding (throughput dividing — overhead compounding (reuse declining — efficiency hoping); *loops blocking* (work crunching — requests queuing (latency spiking — availability dipping (yielding missing — stalls hiding (scheduling starving — throughput collapsing). Stated levers converting slowness to pricing (negotiation offering — persistence reusing (yielding breathing — performance proving); interviewers grading levers (negotiating + persisting + breathing → hired; scaling → rejected).

**Modern guidance** — the performance lines (interview-enforced): *compression negotiating* (encodings offering — clients choosing (bytes shrinking — transfer minimizing (bandwidth pricing — performance winning (negotiation owning — CPU spending (savings buying — throughput trading); *connections persisting* (sockets reusing — handshakes skipping (latency cutting — throughput multiplying (efficiency composing — performance winning (reuse owning — waste ending (agents bounding — pressure limiting); *loops breathing* (work yielding — stalls surfacing (latency composing — responsiveness owning (scheduling freeing — throughput keeping (yielding designing — stalls gauging).

```javascript
// GOOD: levers stating — compression negotiating, connections persisting, loops breathing (interview-grade shape).
// "Text over 1KB gzipped (bytes shrinking — transfer minimizing — bandwidth pricing, performance winning).
// Keep-alive reusing (handshakes skipping — latency cutting — throughput multiplying, efficiency composing).
// CPU offloaded to workers (blocking moving — loops freeing — responsiveness keeping, throughput multiplying)."
// BAD: performance hoping — payloads bloating, handshakes repeating, loops blocking (real rejection shape).
// "Add servers." (Payloads wasting — handshakes repeating — loops blocking (levers unexamined — pricing missing (diagnosis absent).
// Megabytes uncompressed (bytes billing — latency dragging — transfer pricing (compression missing — negotiation skipping).
// Sync crypto inline (loops holding — requests queuing — latency spiking). Negotiate; persist; breathe.)
```

**Common confusion** — *"performance questions test scaling (servers adding)."* Scaling adding capacity (instances multiplying — throughput summing (headroom restoring — growth accommodating (purchases timing — capacity honesting (money spending — pressure buying); levers removing waste (bytes shrinking — handshakes skipping (loops breathing — overhead declining (efficiency composing — performance winning (pricing owning — budgets enforcing); interviews grading efficiency (negotiation pricing — persistence reusing (breathing yielding — waste removing (judgment owning — rigor demonstrating). "Testing" describing capacity (instances multiplying — headroom restoring); performance describing levers (bytes shrinking — loops breathing). Remove waste (levers pricing — efficiency composing); scale headroom (instances multiplying — growth accommodating).

**Performance note** — performance economics: negotiating costing CPU per byte (bytes shrinking — transfer minimizing (bandwidth pricing — performance winning (savings buying — throughput trading (negotiation owning — thresholds gating); persisting costing socket holds (handshakes skipping — latency cutting (throughput multiplying — efficiency composing (reuse owning — waste ending (agents bounding — pressure limiting); breathing costing yields (work splitting — loops freeing (latency composing — stalls preventing (responsiveness owning — availability sustaining); hoped equivalents costing waste (bandwidth billing — handshakes repeating). Price levers (CPU/socket/yield — efficiency); remove waste (bytes/handshakes/blocks — performance).

**Mentor note** — teach "bytes, sockets, loops — every performance answer" (juniors levering per bottleneck design efficient responses on first hearing; scaling-only interrogated ("waste?" — levers demanding per bottleneck). Mock drill: interviewer slowing responses deliberately (payload/compression/loop diagnosing live (levers tangible — efficiency proving permanently). Negotiate bytes; free loops — performance judgment in three habits, reviewed per bottleneck.

## 3. Hardening live under pressure (proxies, fingerprints, deps — robustness stated, not hoped)

**Definition** — the hardening answer interviewers grade: given production exposure, name the controls ([3.1](<../../sections/3. Harden/3.1. "Live" means controls stating (trusting counting — minimizing hiding (auditing dating — robustness proving).

**What problem it solves** — the exposed trio: *proxies blind-trusting* (hops uncounting — clients forging (headers lying — attackers impersonating (validation missing — trust defaulting (spoofing succeeding — rates evading); *stacks advertising* (powered-by broadcasting — versions disclosing (attackers targeting — exploits matching (surfaces widening — breaches inviting (hygiene failing — exposure scheduling); *deps rotting* (advisories ignoring — CVEs embedding (exploits awaiting — attackers scanning (audits skipping — blindness ruling (discipline absenting — breaches scheduling). **Modern guidance** — the hardening lines (interview-enforced): *proxies trusting* (hops counting — spoofing declining (rates keying right — truth recovering (validation owning — security composing (precision owning — fairness ensuring); *fingerprints minimizing* (powered-by removing — versions hiding (recon denying — surfaces minimizing (exposure declining — breaches starving (hygiene owning — discipline proving (opacity owning — security composing); *deps auditing* (advisories triaging — updates pricing (supply securing — trust anchoring (reviews scheduling — surprises expiring (discipline proving — confidence earning).
