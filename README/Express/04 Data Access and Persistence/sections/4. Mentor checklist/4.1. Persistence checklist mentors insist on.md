## 1. Every handler delegates (services deciding — queries absent, never inline)

**Definition** — the delegation line on every handler: services deciding ([1.1](<../../sections/1. Service layer/1.1. Service layer extraction.md>)) — requests parsing (params coercing — bodies validating (inputs proving — trust earning (translation owning — HTTP serving); services deciding (use cases executing — rules enforcing (transactions orchestrating — outcomes returning (logic owning — reuse enabling); queries migrating (SQL absenting — ORM missing (persistence declining — layers respecting (separation owning — testing easing). Handlers delegating (requests parsing — services deciding (queries absenting — layers separating).

**What problem it solves** — the fat-handler trio: *queries inlining* (SQL nesting — ORM embedding (persistence tangling — layers merging (testing requiring databases — slowness compounding (separation violating — production misguiding); *HTTP leaking* (statuses in services — req/res threading (layers inverting — reuse blocking (frameworks coupling — logic binding (portability dying — testing mocking http); *logic duplicating* (use cases copying (rules scattering — consistency hoping (drift scheduling — updates missing (coverage gapping (logic repeating — quality averaging). Delegated handlers converting fat to thin (parsing translating — deciding servicing (querying migrating — layers separating); reviewers checking handler brevity, not logic (delegation proving → verifiable; querying → returned).

**Modern guidance** — the delegation lines per handler (review-enforced): *requests parsing* (params coercing — bodies validating (inputs proving — trust earning (translation owning — HTTP serving (handlers slimming — clarity earning); *services deciding* (use cases executing — rules enforcing (transactions orchestrating — outcomes returning (logic owning — reuse enabling (testing mocking — databases skipping (decisions trading — coupling costing); *queries migrating* (SQL absenting — ORM missing (persistence declining — layers respecting (separation owning — testing easing (handlers slimming — services fattening).

```javascript
// GOOD: handlers delegating — requests parsing, services deciding, queries migrating (shapes, runnable).
app.post('/users', async (req, res, next) => { // requests parsing — translation owning, handlers slimming
  try { res.status(201).json(await userService.create(req.body)); } // services deciding — logic owning, reuse enabling
  catch (err) { next(err); }
});
```

```javascript
// BAD: handlers querying — SQL inlining, HTTP leaking, logic duplicating (real failure shape).
// Queries nesting in handlers (persistence tangling — layers merging — testing requiring databases (separation violating).
// Services taking (req, res) (HTTP leaking — frameworks binding — reuse blocking (portability dying — testing mocking).
// Use cases copying per route (rules scattering — consistency hoping — drift scheduling). Thin handlers; fat services.)
```

**Common confusion** — *"delegation slows reviews (layers navigating)."* Delegation clarifying reviews (handlers reading — services owning (translation seeing — logic finding (navigation easing — understanding quickening (clarity earning — reviews speeding); fat handlers slowing reviews (queries nesting — logic drowning (translation hiding — decisions burying (navigation failing — understanding dragging (clarity dying — reviews stalling); tests speeding feedback (mocks substituting — databases skipping (isolation proving — confidence earning (speed funding — quality compounding). "Slowing" describing navigation (layers traversing — understanding seeking); delegation describing clarity (translation reading — logic finding). Delegate always (clarity earning — reviews speeding); navigate layers (translation seeing — logic finding).

**Performance note** — delegation economics: parsing costing request handling (inputs proving — trust earning (translation owning — HTTP serving (handlers slimming — clarity earning); deciding costing service calls (logic owning — reuse enabling (testing easing — quality rising (decisions trading — coupling costing); migrating costing refactors (queries moving — layers separating (testing mocking — databases skipping (slowness ending — velocity compounding); fat equivalents costing untestable slowness (databases requiring — logic duplicating). Delegate cheaply (parsing — clarity); decide in services (calls — testability).

**Mentor note** — teach "handlers translate, services decide — no exceptions" (juniors separating per handler design thin edges on first hearing; querying handlers interrogated ("service where?" — extraction demanding per handler). Review drill: handler with queries returned automatically (delegation structural — checklists enforcing). Parse requests; decide in services — delegation discipline in two habits, reviewed per handler.

## 2. Every tx settles (commit/rollback pairing — leaks declining, never dangling)

**Definition** — the settlement line on every unit: exactly-once commit-or-rollback ([2.2](<../../sections/2. Transactions/2.2. **What problem it solves** — the unsettled trio: *commits missing* (work succeeding — tx dangling (locks holding — connections leaking (units unclosing — resources wasting (cleanup missing — exhaustion scheduling); *rollbacks skipping* (failures succeeding partially — changes persisting (state corrupting — integrity breaking (failures containing never — chaos growing); *double-settling* (commits then rolling back — outcomes flipping (states confusing — integrity violating (decisions duplicating — correctness breaking). **Modern guidance** — the settlement lines per unit (review-enforced): *committing succeeding* (work persisting — units completing (consistency proving — outcomes recording (durability owning — success finalizing (partials declining — atomicity keeping); *rolling backing failing* (changes undoing — state restoring (integrity keeping — corruption preventing (failures containing — chaos bounding (discipline enforcing — monitoring calming); *cleanup owning* (connections releasing — pools returning (resources freeing — leaks ending (hygiene owning — exhaustion scheduling never (bounds enforcing — freshness keeping).

**Common confusion** — *"checklists cover code, not transactions (atomicity untestable)."* Settlement testing deterministically (commits asserting — rollbacks verifying (outcomes proving — leaks detecting (tests awaiting — behavior proving (discipline testing — confidence earning); units scoping observably (requests bounding — work grouping (lifecycles owning — correctness holding (scopes composing — partials declining (boundaries showing — leaks surfacing); leaks detecting via counts (connections tracking — pools asserting (resources proving — exhaustion preventing (hygiene testing — freshness keeping). **Performance note** — settlement economics: committing costing writes (work persisting — units completing (consistency proving — outcomes recording); rolling backing costing undos (changes reverting — state restoring (integrity keeping — corruption preventing); cleanup costing releases (connections freeing — pools returning (resources freeing — leaks ending); unsettled equivalents costing locks + leaks (units unclosing — resources wasting). **Mentor note** — teach "every unit ends exactly once — prove it" (juniors settling per unit design decided outcomes on first hearing; dangling units interrogated ("settled where?" — settlement demanding per unit). Commit success; roll back failure — settlement discipline in two habits, reviewed per unit.
