# 5.1. Common interview QA routing

## 1. Params and validation live (coercion, preloaders, schemas — diagnosed with fixes, priced)

**Definition** — the param-validation answer interviewers grade: given input handling, name the mechanism with fix and price ([1.1](<../../sections/1. Params/1.1. Route params and validation.md>)) — strings coercing (params typing — numbers parsing (validation guarding — trust earning (injection declining — security composing); preloaders centralizing (app.param fetching — handlers receiving (queries declining — duplication ending (consistency holding — errors unifying); schemas proving (shapes declaring — payloads passing (correctness holding — trust earning (libraries serving — errors structuring). "Live" means diagnosed with fixes (symptoms → mechanism → remedy → price — chains complete).

**What problem it solves** — the unvalidated trio: *types assuming* (strings equaling numbers never (lookups missing — results vanishing (coercion forgetting — validation missing (trust defaulting — correctness hoping); *fetches scattering* (handlers querying each (logic duplicating — consistency hoping (errors varying — formats drifting (central missing — duplication ruling); *payloads trusting* (bodies assuming — shapes missing (handlers crashing — injection executing (validation skipping — trust defaulting (security hoping — breaches scheduling). Validated params converting assumption to proof (coercion owning — fetching centralizing (schemas proving — trust earning); interviewers grading validation (mechanism + fix + price → hired; trusting → rejected).

**Modern guidance** — the validation lines (interview-enforced): *coercion owning* (numbers parsing — shapes predicting (injection guarding — trust earning (validation owning — security composing (types proving — correctness holding); *fetching centralizing* (app.param running — handlers receiving (queries declining — duplication ending (consistency holding — errors unifying (loaders owning — logic focusing); *schemas proving* (shapes declaring — payloads passing (correctness holding — trust earning (libraries serving — errors structuring (feedback aiding — contracts teaching).

```javascript
// GOOD: validation proving — coercion owning, fetching centralizing, schemas proving (interview-grade shape).
// "Params arrive strings → Number() + isInteger guard (types owning — comparisons working, trust earning).
// Shared fetches → app.param preloaders (handlers receiving — queries declining, duplication ending).
// Payloads → schema validation, 400s structured (shapes proving — clients fixing, feedback aiding)."
// BAD: inputs trusting — types assuming, fetches scattering, payloads hoping (real rejection shape).
// "req.params.id works directly." (Strings equaling never — lookups missing — coercion forgetting (trust defaulting).
// Handlers fetching each (logic duplicating — consistency hoping — errors varying (central missing — duplication ruling).
// Bodies assuming shapes (handlers crashing — injection executing — validation skipping). Coerce; centralize; prove.)
```

**Common confusion** — *"validation is boilerplate (ceremony slowing)."* Validation proving inputs (shapes declaring — payloads passing (correctness holding — trust earning (security composing — breaches declining (evidence owning — pressure surviving); boilerplate repeating thoughtlessly (code copying — value missing (ceremony performing — understanding absenting (practice wasting — readiness feigning); schemas centralizing (shapes declaring once — payloads proving everywhere (correctness scaling — trust compounding (validation owning — security deepening). "Boilerplate" describing repetition (code copying — value missing); validation describing proof (shapes declaring — trust earning). Prove shapes (schemas declaring — trust earning); repeat never (centralize loaders — schemas sharing).

**Performance note** — validation economics: coercion costing conversions (types owning — comparisons working (trust earning — injection declining); preloaders costing fetches per request (handlers receiving — queries declining (duplication ending — consistency holding); schemas costing parses per payload (correctness holding — trust earning (feedback aiding — contracts teaching); trusted equivalents costing misses + duplication + breaches (results vanishing — logic repeating — injections executing). Prove cheaply (conversions + parses — trust); centralize always (loaders — consistency).

**Mentor note** — teach "coerce, centralize, prove — every input" (juniors validating per param design proven inputs on first hearing; trusting answers interrogated ("validated how?" — proof demanding per input). Mock drill: interviewer handing string-id bugs (coercion fixing — validation proving (diagnosis tangible — fixes structural, never guessing). Coerce types; prove shapes — validation judgment in three habits, reviewed per input.

## 2. Matching and order live (patterns, splats, precedence — judgment, not fashion)

**Definition** — the matching answer interviewers grade: given routing behavior, explain the mechanism with rules ([2.1](<../../sections/2. Matching/2.1. "Live" means rules stating (patterns explaining — order predicting (ambiguity resolving — surprises ending).

**What problem it solves** — the fuzzy-routing trio: *matches assuming* (routes hoping (patterns unexamined — engines unversioned (syntax aging — behavior modernizing (knowledge expiring — matches breaking); *splats swallowing* (catch-alls leading — APIs shadowing (tails eating — handlers hijacking (order ignoring — precision dying (scopes missing — surprises compounding); *order hoping* (generals preceding (literals shadowing — matches surprising (precedence ignoring — declaration unexamined (flow unowned — execution guessing). **Modern guidance** — the matching lines (interview-enforced): *patterns ruling* (engines compiling — strings exacting (params constraining — regex filtering (precision owning — ambiguity declining (matches predicting — surprises ending); *splats trailing* (tails capturing — files nesting (APIs preceding — routes freeing (shadowing declining — surprises ending (order owning — flow examining); *precedence ordering* (specific preceding — routers isolating (fallthrough yielding — matches resolving (shadowing declining — surprises ending (flow examining — execution predicting).

```javascript
// BAD: routing hoping — matches assuming, splats swallowing, order ignoring (real rejection shape).
```

## 3. Async safety live (rejections, joins, timeouts — robustness stated, not hoped)

**Definition** — the async-safety answer interviewers grade: given async pipelines, state the guarantees ([3.1](<../../sections/3. Async safety/3.1. Async pipeline safety.md>)) — rejections forwarding (Express 5 catching — central receiving (swallowing ending — debugging easing (versions advancing — behavior modernizing); joins gating (tasks racing — results composing (latency minimizing — failures structuring (parallelism exploiting — sequential declining); timeouts bounding (races limiting — hangs declining (resources freeing — liveness proving (discipline enforcing — exhaustion scheduling never). "Live" means guarantees stating (forwarding proving — gating designing — bounding enforcing (robustness stating — hope ending).

**What problem it solves** — the hoping-async trio: *rejections vanishing* (awaits throwing (handlers exiting — responses nevering (central missing — forwarding absenting (versions aging — behavior differing (swallowing ruling — debugging haunting); *serial slowing* (awaits chaining (latency summing — responses lagging (parallelism ignoring — performance hoping (independence missing — concurrency declining (gating absenting — joining missing); *hangs leaking* (upstreams stalling — awaits pending forever (workers holding — resources exhausting (bounds missinging — liveness hoping (discipline absenting — timeouts skipping). Guaranteed async converting hoping to stating (forwarding proving — gating designing — bounding enforcing); interviewers grading guarantees (forwarding + gating + bounding → hired; awaiting → rejected).

**Modern guidance** — the safety lines (interview-enforced): *rejections trusting* (async throwing — central catching (handlers receiving — recovery structuring (swallowing ending — debugging easing (versions advancing — behavior modernizing (forwarding proving — hangs declining); *joins gating* (tasks racing — results composing (latency minimizing — failures structuring (parallelism exploiting — sequential declining (independence leveraging — concurrency owning); *timeouts bounding* (races limiting — hangs declining (resources freeing — liveness proving (discipline enforcing — exhaustion scheduling never (bounds setting — SLOs guarding).

```javascript
// GOOD: safety stating — rejections trusting, joins gating, timeouts bounding (interview-grade answer shape).
// "Async throws reach central (Express 5 forwarding — versions advancing — swallowing ending, debugging easing).
// Independents Promise.all (tasks racing — latency minimizing — failures structuring, parallelism exploiting).
// Externals withTimeout raced (bounds enforcing — hangs declining — resources freeing, liveness proving)."
// BAD: async hoping — rejections vanishing, serial slowing, hangs leaking (real rejection shape).
// "Await handles errors." (Central missing — forwarding absenting — versions aging (swallowing ruling — debugging haunting).
// Serial awaits everywhere (latency summing — responses lagging — parallelism ignoring (gating absenting — joining missing).
// No timeouts (workers holding — resources exhausting — bounds missinging). Trust; gate; bound.)
```

**Common confusion** — *"async safety is try-catch (language covering)."* Try-catch handling sync scopes (throws catching — bounds limiting (failures containing — recovery structuring (language serving — central feeding (catches placing — forwarding reaching); Express forwarding async (rejections arriving — handlers receiving (swallowing ending — debugging easing (framework owning — handlers simplifying); timeouts bounding waits (races limiting — hangs declining (resources freeing — liveness proving (discipline enforcing — exhaustion scheduling never). "Covering" describing scopes (throws catching — bounds limiting); safety describing forwarding + gating + bounding (central receiving — results composing — waits capping). Catch scopes (language serving — central feeding); forward async (framework receiving — recovery structuring).

**Performance note** — safety economics: trusting costing hooks (rejections catching — central receiving (overhead trivialing — debugging easing); gating costing slowest-task latency (results composing — parallelism exploiting (sequential declining — performance winning); bounding costing timers (hangs declining — resources freeing (liveness proving — discipline enforcing); hoped equivalents costing hangs + sums + leaks (clients timing out — responses lagging — workers holding). Trust cheaply (hooks — central); bound always (timers — liveness).

**Mentor note** — teach "forward, gate, bound — every async answer" (juniors stating per pipeline design safe async on first hearing; awaiting-only interrogated ("central? joined? bounded?" — guarantees demanding per pipeline). Mock drill: interviewer failing upstream (rejection path tracing — timeout firing (guarantees tangible — robustness proving permanently). Forward rejections; bound waits — safety judgment in three habits, reviewed per pipeline.
