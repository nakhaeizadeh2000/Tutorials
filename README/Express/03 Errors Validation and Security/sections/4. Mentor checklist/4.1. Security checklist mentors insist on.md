# 4.1. Security checklist mentors insist on

## 1. Every error answers safely (messages generalizing — stacks logging, never leaking)

**Definition** — the safe-answer line on every error path: generic client messages + detailed server logs ([1.1](<../../sections/1. Error design/1.1. Central error handling.md>)) — messages generalizing (`boom` answering — internals hiding (queries concealing — stacks omitting (attackers starving — surfaces minimizing); stacks logging (operators reading — debugging enabling (details keeping — clients excluding (visibility splitting — audiences separating); statuses mapping (codes meaning — handling routing (contracts holding — debugging aiding (transparency bounding — betrayal declining). Answers safing (messages generalizing — stacks logging (leaks preventing — debugging enabling).

**What problem it solves** — the leaking-answer trio: *stacks exposing* (details sending — paths revealing (attackers informing — surfaces widening (breaches inviting — reconnaissance gifting (transparency overdoing — helpfulness betraying); *formats varying* (errors shaping per route — bodies confusing (clients guessing — contracts breaking (consistency hoping — discipline scattering); *triage missing* (kinds unbranching — responses uniforming (judgment absenting — rigor missing (operational crashing — bugs responding (decisions hoping — pressure collapsing). Safe answers converting exposure to opacity (messages generalizing — formats unifying (triage branching — consistency holding); reviewers diffing client vs log output, not trusting (split proving → verifiable; echoing → returned).

**Modern guidance** — the safe lines per error path (review-enforced): *messages generalizing* (`boom` answering — internals hiding (queries concealing — stacks omitting (attackers starving — surfaces minimizing (breaches declining — reconnaissance denying); *stacks logging* (operators reading — debugging enabling (details keeping — clients excluding (visibility splitting — audiences separating (specifics persisting — generality clienting); *triage branching* (operational answering — programmer alerting (responses routing — crashes gating (judgment owning — rigor demonstrating (decisions landing — deliberation timing).

```javascript
// GOOD: answers safing — messages generalizing, stacks logging, triage branching (shapes, runnable).
app.use((err, req, res, next) => { // messages generalizing — attackers starving, surfaces minimizing
  console.error(err.stack); // stacks logging — operators reading, debugging enabling, details keeping
  const status = err.trusted ? err.status : 500; // triage branching — responses routing, crashes gating
  res.status(status).json({ error: status < 500 ? err.message : 'boom' });
});
```

```javascript
// BAD: answers leaking — stacks exposing, formats varying, triage missing (real failure shape).
// res.json({ error: err.stack }); // details exposing — attackers informing (surfaces widening — breaches inviting).
// Per-route error shapes varying (bodies confusing — clients guessing — contracts breaking (consistency hoping — discipline scattering).
// All errors 500ing (user mistakes crashing — operational crashing — bugs responding). Generalize; log; triage.)
```

**Common confusion** — *"checklists slow incident response (paperwork delaying)."* Checklists accelerating response (answers shaping — triage branching (decisions landing — panic declining (quality stabilizing — recovery executing (procedures guiding — improvisation ending); incidents delaying unprepared (steps inventing — order discovering (stress deciding — quality varying (recovery gambling — practice absenting (procedures missing — panic directing); drills internalizing (rehearsals practicing — procedures owning (confidence earning — panic inoculating (responses quickening — quality holding). "Slowing" describing learning curves (answers shaping — decisions landing); unprepared describing delays (steps inventing — quality varying). Shape answers (messages generalizing — triage branching); drill checklists (procedures owning — panic declining).

**Performance note** — safe-answer economics: generalizing costing message design (internals hiding — attackers starving (surfaces minimizing — breaches declining); logging costing I/O per error (operators reading — debugging enabling (details keeping — visibility splitting); branching costing property checks (responses routing — crashes gating (judgment owning — rigor demonstrating); leaked equivalents costing breaches (reconnaissance gifting — exploits refining). Generalize cheaply (messages — surfaces); log always (I/O — insight).

**Mentor note** — teach "apologies out, autopsies in" (juniors splitting per audience design safe errors on first hearing; echoing handlers interrogated ("client sees what?" — split demanding per error). Diff once (client vs log differing — split tangible (audiences separating visibly — leaking ending permanently). Generalize outward; detail inward — safe-answer discipline in two habits, reviewed per error path.

## 2. Every input proves shape (schemas declaring — injection declining, trust earning)

**Definition** — the proven-input line on every boundary: schemas declaring ([2.1](<../../sections/2. Input armor/2.1. Inputs proving (schemas declaring — sanitizers encoding (limits bounding — trust earning).

**What problem it solves** — the unproven trio: *shapes assuming* (bodies trusting — fields missing (types wronging — handlers crashing (validation skipping — trust defaulting (correctness hoping — errors surprising); *outputs echoing* (renders reflecting — scripts executing (sessions hijacking — cookies stealing (escaping missing — contexts confusing (neutralization absenting — protection failing); *bounds missing* (sizes unbounding — depths unlimited — rates open (abuse inviting — exhaustion scheduling (limits hoping — availability risking). Proven inputs converting assumption to proof (schemas declaring — sanitizers encoding (limits bounding — trust earning); reviewers checking boundaries, not handlers (proof owning → verifiable; trusting → returned).

**Modern guidance** — the proven lines per boundary (review-enforced): *schemas declaring* (fields typing — formats bounding (payloads proving — correctness holding (trust earning — injection declining (validation owning — security composing); *sanitizers encoding* (outputs neutralizing — scripts inerting (browsers displaying — code declining (contexts owning — protection fitting (defense layering — safety composing); *limits bounding* (sizes capping — depths limiting (windows throttling — abuse costing (DoS declining — availability defending (resources guarding — exhaustion preventing).

```javascript
// GOOD: inputs proving — schemas declaring, sanitizers encoding, limits bounding (shapes, runnable).
// Schemas at every boundary (fields typing — payloads proving — correctness holding, trust earning)
// Outputs escaped per context (scripts inerting — browsers displaying — code declining, XSS preventing)
// express.json({ limit: '100kb' }) + array caps (sizes capping — abuse costing — DoS declining, availability defending)
```

```javascript
// req.body used raw (fields missing — handlers crashing — validation skipping (trust defaulting — correctness hoping).
// Renders echoing unescaped (scripts executing — sessions hijacking — escaping missing (neutralization absenting — protection failing).
// Unlimited bodies (memory exploding — parsers choking — limits hoping). Declare; encode; bound.)
```

**Common confusion** — *"checklists duplicate validation docs (reading repeating)."* Docs describing mechanics (schemas declaring — sanitizers encoding (usage explaining — behavior documenting (knowledge informing — understanding starting); checklists enforcing boundaries (inputs proving — outputs neutralizing (judgment requiring — discipline proving (reviews gating — quality stabilizing (standards holding — consistency enforcing). "Duplicating" describing topics (schemas mentioning — validation naming); checklists describing gates (proof requiring — discipline proving). Read docs (mechanics informing — understanding starting); pass checklists (proof requiring — discipline proving).

**Performance note** — proven-input economics: declaring costing schema code (shapes typing — payloads proving (correctness holding — trust earning); encoding costing replaces per render (scripts inerting — browsers displaying (XSS preventing — injection ending); bounding costing checks (sizes capping — abuse costing (DoS declining — availability defending); assumed equivalents costing crashes + XSS + exhaustion (handlers breaking — sessions hijacking — memory exploding). Declare cheaply (schemas — correctness); bound always (checks — availability).

**Mentor note** — teach "prove in, neutralize out, bound all" (juniors covering per boundary design proven inputs on first hearing; trusting boundaries interrogated ("proven where?" — proof demanding per boundary). Review drill: new endpoint without schema returned automatically (proof structural — checklists enforcing). Declare shapes; encode outputs — proof discipline in two habits, reviewed per boundary.

## 3. Every secret stays secret (logging redacting — rotation dating, never hoping)

**Definition** — the secret line on every app: hygiene owning ([2.2](<../../sections/2. Input armor/2.2. Security headers and secrets.md>)) — logging redacting (keys masking — tokens hashing (outputs cleaning — attackers starving (surfaces minimizing — breaches declining (exposure ending — reconnaissance denying); rotation dating (keys versioning — overlaps windowing (revocations propagating — outages avoiding (secrets cycling — staleness expiring (hygiene compounding — compromise bounding); config gating (schemas proving — crashes earlying (deploys blocking — serving earning (correctness starting — chaos preventing). Secrets hiding (logging redacting — rotation dating (exposure declining — hope ending).

**What problem it solves** — the exposed trio: *logs leaking* (keys printing — tokens persisting (passwords aggregating — attackers grepapping (surfaces widening — breaches inviting (redaction missing — exposure scheduling); *rotation undating* (secrets permanenting — compromises persisting (keys aging — staleness growing (revocation impossibleing — hygiene decaying (planning absenting — breaches extending); *config hoping* (boots defaulting — validation skipping (deploys dying late — users suffering (schemas missing — crashes deferring (failures hiding — feedback delaying). Hygienic secrets converting exposure to opacity (logging redacting — rotation dating (config gating — exposure declining); reviewers grepping logs, not hoping (hygiene owning → verifiable; printing → returned).

**Modern guidance** — the secret lines per app (review-enforced): *logging redacting* (keys masking — tokens hashing (outputs cleaning — attackers starving (surfaces minimizing — breaches declining (exposure ending — reconnaissance denying (redaction owning — hygiene proving); *rotation dating* (keys versioning — overlaps windowing (revocations propagating — outages avoiding (secrets cycling — staleness expiring (hygiene compounding — compromise bounding (planning owning — breaches limiting); *config gating* (schemas proving — crashes earlying (deploys blocking — serving earning (correctness starting — chaos preventing (validation owning — degradation declining).

```javascript
// GOOD: secrets hiding — logging redacting, rotation dating, config gating (shapes, runnable).
// Redact patterns in CI (keys masking — outputs cleaning — attackers starving, exposure ending)
// Rotate quarterly with overlap (keys versioning — outages avoiding — hygiene compounding, compromise bounding)
// boot() gating env (schemas proving — crashes earlying — deploys blocking, serving earning)
```

```javascript
// BAD: secrets hoping — logs leaking, rotation undating, config defaulting (real failure shape).

// Permanent keys since launch (compromises persisting — revocation impossibleing — hygiene decaying (planning absenting — breaches extending).
// SECRET || 'dev' fallback (wrong serving — correctness assuming — chaos creeping). Redact; date; gate.)
```

**Common confusion** — *"checklists cover code, not secrets (hygiene untestable)."* Secrets grepping deterministically (patterns scanning — logs proving (redaction owning — exposure declining (hygiene testing — confidence earning); rotation dating calendrically (versions checking — overlaps verifying (revocations proving — outages avoiding (hygiene compounding — compromise bounding); config gating at boot (schemas proving — crashes earlying (deploys blocking — serving earning (correctness starting — chaos preventing). "Untestable" describing vibes (hygiene hoping — evidence missing); secrets describing scans (patterns proving — redaction owning). Grep logs (patterns scanning — exposure); date rotations (calendars checking — hygiene).

**Performance note** — secret economics: redacting costing scans (outputs cleaning — attackers starving (surfaces minimizing — breaches declining (exposure ending — reconnaissance denying); dating costing calendars (keys versioning — overlaps windowing (hygiene compounding — compromise bounding (planning owning — breaches limiting); gating costing startup checks (config proving — serving earning (crashes earlying — degradation declining); exposed equivalents costing breaches (attackers grepapping — surfaces widening). Redact cheaply (scans — surfaces); date always (calendars — hygiene).

**Mentor note** — teach "grep, rotate, gate — every deploy" (juniors owning per app design secret hygiene on first hearing; printing secrets interrogated ("redacted? rotated?" — hygiene demanding per secret). Grep once in CI (patterns scanning — exposure tangible (redaction proving — leaking ending permanently). Redact logs; date rotations — secret discipline in two habits, reviewed per deploy.
