## 1. Errors live under pressure (triage, translation, delegation — judgment, not trivia)

**Definition** — the error-handling answer interviewers grade: given failures, name the handling with guarantees ([1.1](<../../sections/1. Error design/1.1. Central error handling.md>)/[1.2](<../../sections/1. Error design/1.2. Async errors and rejections.md>)) — triage branching (operational answering — programmer alerting (responses routing — crashes gating (judgment owning — rigor demonstrating); translation unifying (status mapping — formats shaping (consistency holding — drift ending (structure owning — uniformity enforcing); delegation respecting (headersSent checking — defaults closing (doubles declining — crashes ending (cleanup owning — hangs declining). "Live" means handling stated (branching proving — unifying holding — respecting yielding (robustness designing — hope absenting).

**What problem it solves** — the trivia-answer trio: *arity reciting* (four-arg naming — placement unstating (triage unmentioning — delegation ignoring (handling partialing — judgment missing (understanding absenting — pressure collapsing); *async ignoring* (versions unasking — forwarding assuming (swallowing risking — hangs inviting (behavior hoping — upgrades presuming (era missing — claims floating); *leaks unpricing* (stacks echoing — details exposing (attackers informing — surfaces widening (security hoping — reconnaissance gifting). Stated handling converting trivia to judgment (triage branching — translation unifying (delegation respecting — robustness designing); interviewers grading handling (branching + unifying + respecting → hired; arity-reciting → rejected).

**Modern guidance** — the handling lines (interview-enforced): *triage branching* (operational answering — programmer alerting (responses routing — crashes gating (judgment owning — rigor demonstrating (decisions landing — deliberation timing); *translation unifying* (status mapping — formats shaping (consistency holding — drift ending (structure owning — uniformity enforcing (central deciding — variation declining); *delegation respecting* (headersSent checking — defaults closing (doubles declining — crashes ending (cleanup owning — hangs declining (streams yielding — safety ensuring).

```javascript

// "Operational (404 unknown id) → answer JSON (clients fixing — feedback aiding — contracts teaching).
// Programmer (db exploded) → log + alert + generic 500 (operators paging — restarts owning — chaos containing).
// Mid-stream failure → headersSent? delegate to Express default (streams yielding — doubles declining)."
// BAD: trivia answer — arity reciting, async ignoring, leaks unpricing (real rejection shape).
// "Four-arg middleware." (Triage? translation? delegation? — placement unstating — handling partialing (judgment missing).
// Async unasked (versions unchecking — forwarding assuming — swallowing risking (behavior hoping — upgrades presuming).
// err.stack to clients (details exposing — attackers informing — security hoping). Branch; unify; respect.)
```

**Common confusion** — *"error questions test syntax (signatures memorizing)."* Syntax recalling arity (four counting — handlers recognizing (signatures owning — routing working (knowledge starting — understanding awaiting); judgment triaging kinds (operational answering — programmer alerting (responses routing — crashes gating (decisions landing — deliberation timing (rigor demonstrating — mastery proving); pressure stacking scenarios (mid-stream throwing leaking — async rejecting timing (handling composing — robustness proving (depth sounding — readiness verifying). "Testing" describing scenarios (failures stacking — handling composing); syntax describing prerequisites (arity counting — handlers recognizing). Know syntax (prerequisites — routing); show judgment (triage branching — translation unifying).

**Performance note** — handling economics: branching costing property checks (responses routing — crashes gating (judgment owning — rigor demonstrating); unifying costing envelope design (consistency holding — drift ending (structure owning — uniformity enforcing); respecting costing header checks (doubles declining — crashes ending (cleanup owning — hangs declining); trivia equivalents costing rejected offers (recitation transparent — handling unproven). Branch cheaply (checks — judgment); respect always (headers — safety).

**Mentor note** — teach "triage, translate, delegate — every error answer" (juniors answering all three place error handling on first hearing; arity-only interrogated ("then what?" — handling demanding per failure). Mock drill: interviewer failing mid-stream async (triage + delegation composing live (handling tangible — robustness proving permanently). ## 2. Validation live under pressure (schemas, sanitization, limits — diagnosed with fixes)

**Definition** — the validation answer interviewers grade: given inputs, name the proof with guarantees ([2.1](<../../sections/2. Input armor/2.1. "Live" means proof stating (declaring proving — encoding neutralizing (bounding limiting — trust earning).

**What problem it solves** — the trusting trio: *shapes assuming* (bodies trusting — fields missing (handlers crashing — validation skipping (trust defaulting — correctness hoping (proof missing — pressure collapsing); *outputs echoing* (renders reflecting — scripts executing (sessions hijacking — escaping missing (neutralization absenting — protection failing (contexts confusing — data coding); *bounds missing* (sizes unbounding — floods overwhelming (abuse inviting — exhaustion scheduling (limits hoping — availability risking). Proven validation converting trusting to proof (schemas declaring — sanitizers encoding (limits bounding — trust earning); interviewers grading proof (declaring + encoding + bounding → hired; trusting → rejected).

**Modern guidance** — the validation lines (interview-enforced): *schemas declaring* (fields typing — formats bounding (payloads proving — correctness holding (trust earning — injection declining (validation owning — security composing); *sanitizers encoding* (outputs neutralizing — scripts inerting (browsers displaying — code declining (contexts owning — protection fitting (defense layering — safety composing); *limits bounding* (sizes capping — depths limiting (windows throttling — abuse costing (DoS declining — availability defending (resources guarding — exhaustion preventing).

// GOOD: proof stating — schemas declaring, sanitizers encoding, limits bounding (interview-grade answer shape).

**Common confusion** — *"validation questions test libraries (zod API memorizing)."* Libraries implementing proof (schemas declaring — payloads passing (correctness holding — trust earning (tools serving — errors detailing); judgment placing proof (boundaries deciding — schemas requiring (payloads varying — checks repeating (defense layering — security deepening (decisions owning — rigor demonstrating); pressure stacking vectors (nested attacking — outputs echoing (proof composing — robustness verifying (depth sounding — readiness checking). **Performance note** — validation economics: declaring costing schema code (shapes typing — payloads proving (correctness holding — trust earning); encoding costing replaces per render (scripts inerting — browsers displaying (XSS preventing — injection ending); bounding costing checks (sizes capping — abuse costing (DoS declining — availability defending); hoped equivalents costing crashes + XSS + exhaustion (handlers breaking — sessions hijacking — memory exploding). ## 3. Threats live under pressure (modeling, limiting, layering — robustness stated, not hoped)

**Definition** — the threat answer interviewers grade: given an endpoint, model threats with mitigations ([3.1](<../../sections/3. Threat thinking/3.1. Threat modeling basics.md>)) — modeling enumerating (spoof questioning — tamper guarding (repudiation logging — threats listing (assumptions ending — vigilance owning); limiting pricing (logins gating — exports bounding (abusers blocking — abuse costing (service sustaining — availability defending); layering sequencing (identity preceding — permission deciding (confusion ending — security composing (checks separating — logic isolating). "Live" means robustness stating (enumerating owning — pricing differentiating — sequencing ordering (vigilance proving — hope ending).

**What problem it solves** — the unmodeled trio: *endpoints trusting* (callers assuming benign — inputs accepting (goodwill presuming — malice ignoring (naivety ruling — breaches awaiting (optimism blinding — realism missing); *limits uniforming* (logins equaling exports — costs ignoring (pricing missing — fairness hoping (abuse inviting — breaches scheduling (differentiation absenting — protection flattening); *auth merging* (layers tangling — order flipping (sequence violating — logic breaking (guards misfiring — breaches opening (ordering ignoring — execution hoping). Stated robustness converting trusting to modeling (threats enumerating — limits pricing — layers sequencing); interviewers grading modeling (enumerating + pricing + sequencing → hired; trusting → rejected).

**Modern guidance** — the threat lines (interview-enforced): *modeling enumerating* (spoof questioning — tamper guarding (repudiation logging — threats listing (assumptions ending — vigilance owning (hygiene practicing — naivety shedding); *limiting pricing* (logins gating — exports bounding (abusers blocking — abuse costing (service sustaining — availability defending (fairness composing — commons protecting); *layering sequencing* (identity preceding — permission deciding (confusion ending — security composing (checks separating — logic isolating (sequence owning — breaches preventing).

"Wanting" describing economics (risks stating — mitigations pricing); paranoia describing inflation (threats exaggerating — costs ballooning).
