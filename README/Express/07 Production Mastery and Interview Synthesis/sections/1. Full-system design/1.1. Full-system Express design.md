# 1.1. Full-system Express design

## 1. Layers compose vertically (routes → services → data — requests flowing, concerns separating)

**Definition** — the vertical whole: requests flowing through all layers ([Domain 01 §1.2 routing](<../../../01 Express Foundations and Mental Model/sections/1. First app/1.2. Hello API with routing.md>)/[Domain 04 §1.1 services](<../../../04 Data Access and Persistence/sections/1. Service layer/1.1. Service layer extraction.md>)) — routes translating (HTTP parsing — services deciding (queries absenting — layers separating (translation owning — clarity earning); services deciding (rules enforcing — transactions orchestrating (outcomes returning — logic owning (reuse enabling — testing easing); data persisting ([Domain 04 §2.2 tx](<../../../04 Data Access and Persistence/sections/2. Transactions/2.2. Transactions per request.md>) — units bounding (commits deciding — rollbacks structuring (consistency proving — integrity owning). Layers composing (requests flowing — concerns separating (wholes judging — mastery proving).

**What problem it solves** — the unlayered trio: *handlers querying* (SQL nesting — ORM embedding (persistence tangling — layers merging (testing requiring databases — slowness compounding (separation violating — production misguiding); *logic scattering* (rules duplicating — consistency hoping (drift scheduling — updates missing (coverage gapping (ownership missing — judgment absenting); *layers skipping* (routes calling stores — services bypassing (contracts missing — testing impossibleing (separation violating — reuse blocking (boundaries blurring — velocity dying). Composed layers converting tangling to flow (routes translating — services deciding (data persisting — concerns separating); reviewers traversing layers, not sampling (wholes judging → verifiable; flattening → returned).

**Modern guidance** — the vertical lines per system (review-enforced — composition, never repetition): *routes translating* (HTTP parsing — services deciding (queries absenting — layers separating (translation owning — clarity earning (handlers slimming — reviews speeding); *services deciding* (rules enforcing — transactions orchestrating (outcomes returning — logic owning (reuse enabling — testing easing (decisions centralizing — drift ending); *data persisting* (units bounding — commits deciding (consistency proving — integrity owning (scopes owning — partials declining (judgment trading — rigor demonstrating).

```javascript
// GOOD: layers composing — routes translating, services deciding, data persisting (composition, linked).
// POST /orders → handler parsing + validating (translation owning — queries absenting, layers separating)
//   → orders.checkout() service (rules enforcing — transactions orchestrating, outcomes returning)
//   → tx commit + 201 DTO (units bounding — contracts versioning — over-fetching declining, clients trusting)
// BAD: layers flattening — handlers querying, logic scattering, layers skipping (real failure shape).
// Route → SQL strings inline (persistence tangling — layers merging — testing requiring databases (separation violating).
// Rules per route duplicating (consistency hoping — drift scheduling — updates missing (ownership missing — judgment absenting).
// Routes calling stores directly (contracts missing — testing impossibleing — reuse blocking). Layer vertically.)
```

**Common confusion** — *"layering slows small apps (ceremony taxing)."* Layers organizing growth (translation reading — decisions centralizing (clarity earning — velocity compounding (structure scaling — teams aligning (organization owning — mastery approaching); flats entangling early (queries nesting — logic drowning (testing requiring — velocity dragging (separation violating — production misguiding (debt compounding — rewrites looming); ceremony funding speed (tests mocking — refactors containing (isolation proving — confidence earning (speed compounding — quality rising). "Slowing" describing files (modules bounding — navigation costing); flats describing debt (queries nesting — velocity dragging). Layer thinly (translation reading — clarity earning); grow structurally (structure scaling — teams aligning).

**Performance note** — vertical economics: translating costing parses (inputs proving — trust earning (handlers owning — HTTP serving (clarity earning — reviews speeding); deciding costing calls (logic owning — reuse enabling (testing easing — quality rising (decisions trading — coupling costing); persisting costing units (commits deciding — consistency proving (integrity owning — scopes owning (judgment trading — rigor demonstrating); flat equivalents costing untestable slowness (databases requiring — logic duplicating). Layer cheaply (parses + calls — clarity); persist atomically (units — consistency).

**Mentor note** — teach "follow one request through every layer, out loud" (juniors traversing per system design whole-system judgment on first hearing; layer-skipping interrogated ("service? tx?" — traversal demanding per request). Trace once (route → service → tx → DTO flowing tangible (composition visible — wholes judging permanently). Translate, decide, persist — vertical discipline in two habits, reviewed per system.

## 2. Contracts bound horizontally (DTOs shaping — errors mapping — clients trusting)

**Modern guidance** — the horizontal lines per boundary (review-enforced — composition, never repetition): *DTOs shaping* (fields selecting — over-fetching declining (clients trusting — breakage preventing (presentation owning — stability earning (bandwidth pricing — performance winning (contracts bounding — surprises ending); *errors mapping* (status branching — formats unifying (consistency holding — drift ending (translation owning — structure enforcing (clients informing — debugging aiding (triage branching — rigor demonstrating); *clients trusting* (contracts versioning — breakage declining (stability earning — trust compounding (shapes freezing — surprises ending (discipline proving — confidence earning).

**Mentor note** — teach "bound every boundary — responses and errors" (juniors contracting per boundary design trustworthy APIs on first hearing; uncontracted boundaries interrogated ("DTO? status table?" — bounding demanding per boundary). ## 3. Failures compose gracefully (triage branching — fallbacks serving — degradation designing)

**Definition** — graceful composition: failures degrading per layer without cascading ([Domain 03 §1.1 triage](<../../../03 Errors Validation and Security/sections/1. Error design/1.1. **What problem it solves** — the cascading trio: *failures propagating* (errors bubbling unhandled — layers collapsing (outages spreading — availability zeroing (blast expanding — systems falling (triage missing — judgment absenting (rigor declining — pressure collapsing); *fallbacks missing* (degradation unplanned — defaults absenting (outages totaling — availability zeroing (grace missing — panic ruling (robustness hoping — brittleness scheduling (planning absenting — incidents extending); *cascades amplifying* (slow depending slow — waits multiplying (timeouts summing — failures propagating (dependencies chaining — deadlines missing (bounds ignoring — avalanches scheduling). Composed failures converting cascades to grace (triage branching — fallbacks serving (degradation designing — grace owning); reviewers checking degradation paths, not happy paths (composing proving → verifiable; cascading → returned).

**Modern guidance** — the graceful lines per system (review-enforced — composition, never repetition): *triage branching* (operational answering — programmer alerting (responses routing — crashes gating (judgment owning — rigor demonstrating (decisions landing — deliberation timing (failures structuring — recovery owning); *fallbacks serving* (defaults responding — caches answering (staleness accepting — availability sustaining (degradation designing — outages surviving (robustness composing — brittleness declining (grace owning — panic ending); *degradation designing* (partials serving — wholes declining (blast containing — cascades preventing (robustness composing — brittleness declining (grace owning — panic ending (planning owning — incidents surviving).

Degrade visibly (fallbacks serving — statuses informing); never swallow (errors surfacing — visibility keeping).

**Performance note** — graceful economics: branching costing triage checks (responses routing — crashes gating (judgment owning — rigor demonstrating (decisions landing — deliberation timing); serving costing fallback paths (defaults responding — caches answering (availability sustaining — outages surviving (robustness composing — brittleness declining); designing costing degradation planning (partials serving — wholes declining (blast containing — cascades preventing (grace owning — panic ending); cascading equivalents costing total outages (availability zeroing — systems falling). **Mentor note** — teach "fail granularly, degrade visibly" (juniors composing per system design graceful failures on first hearing; cascading designs interrogated ("degraded mode?" — grace demanding per system).
