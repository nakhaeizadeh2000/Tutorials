## 1. Systems designed live (routes + data + delivery — wholes composing under pressure)

**Definition** — the system-design answer interviewers grade: given a product, compose the Express whole live ([1.1](<../../sections/1. Full-system design/1.1. Full-system Express design.md>)/[1.2](<../../sections/1. Full-system design/1.2. Full-system delivery design.md>)) — layers composing (routes translating — services deciding (data persisting — concerns separating (translation owning — clarity earning); contracts bounding (DTOs shaping — errors mapping (clients trusting — breakage preventing (presentation owning — stability earning); delivery gating (tests proving — deploys blocking (drains landing — probes answering (quality defending — confidence earning). Wholes composing (layers stacking — contracts bounding (delivery gating — mastery proving).

**What problem it solves** — the partial-design trio: *single-layer designing* (routes answering only — data assuming (persistence ignoring — wholes fragmenting (judgment partialing — blindness layering (incidents hiding — coverage missing); *mechanics reciting* (middleware listing — designs missing (usage describing — wholes absenting (knowledge displaying — judgment hiding (trivia performing — mastery feigning); *pressure collapsing* (follow-ups breaking — numbers missing — totals unsumming (honesty fragmenting — calibration failing (composure cracking — readiness doubting). Composed wholes converting partials to systems (layers stacking — contracts bounding (delivery gating — mastery proving); interviewers grading wholes under pressure (systems composing → hired; layers reciting → rejected).

**Modern guidance** — the design lines (interview-enforced — capstone, never repetition): *layers composing* (routes translating — services deciding (data persisting — concerns separating (translation owning — clarity earning (handlers slimming — reviews speeding); *contracts bounding* (DTOs shaping — errors mapping (clients trusting — breakage preventing (presentation owning — stability earning (bandwidth pricing — performance winning); *delivery gating* (tests proving — deploys blocking (drains landing — probes answering (quality defending — confidence earning (discipline enforcing — hope ending).

```text
# GOOD: wholes composing — layers stacking, contracts bounding, delivery gating (interview-grade shape).
# "Design URL shortener: POST /urls validating → service creating with collision-checked IDs (translation owning —
# layers separating); GET /:id redirecting + hit counting (contracts bounding — clients trusting); DTOs hiding
# internals; boot-gated config; SIGTERM drains; /live + /ready (delivery gating — readiness demonstrating)."
# BAD: designs partialing — single layers, mechanics reciting, pressure collapsing (real rejection shape).
# "app.get everywhere." (Services unextracting — data unlayering — contracts undesigning (wholes fragmenting — judgment partialing).
# Middleware listing sans design (usage describing — wholes absenting — knowledge displaying (judgment hiding — trivia performing).
# Follow-ups breaking (numbers missing — composure cracking — readiness doubting). Compose wholes; survive pressure.)
```

**Common confusion** — *"system design is architecture diagrams (boxes impressing)."* Diagrams sketching (components placing — relationships drawing (structure communicating — understanding starting (boxes informing — judgment awaiting); numbers deciding (windows stating — totals summing (honesty completing — calibration proving (decisions landing — trade-offs owning); pressure testing (follow-ups stacking — composure keeping (readiness proving — judgment demonstrating (depth sounding — mastery verifying). "Impressing" describing boxes (diagrams sketching — structure communicating); design describing decisions (numbers stating — trade-offs owning). Sketch structure (diagrams communicating — understanding starting); decide numerically (windows stating — judgment demonstrating).

**Performance note** — design economics: layering costing thought per datum (wholes composing — hope absenting (judgment demonstrating — pressure surviving); bounding costing mappings (fields limiting — payloads slimming (bandwidth saving — latency cutting (transfer pricing — performance winning); gating costing checks (tests proving — deploys blocking (drains landing — probes answering (quality defending — confidence earning); partial equivalents costing rejected offers (layers reciting — pressure collapsing). Compose thoughtfully (layers stacking — judgment); number everything (windows stating — pressure surviving).

**Mentor note** — teach "one product, whole Express, out loud" (juniors composing per product design system judgment on first practicing; layer-reciting interrogated ("whole?" — composition demanding per answer). Whiteboard one system once (layers + contracts + delivery composing live — wholes tangible (judgment visible — mastery demonstrating, never reciting). Compose wholes; number totals — design judgment in two habits, reviewed per system.

## 2. Failures handled live (crash, outage, slowness — procedures stated with prices)

**Definition** — the failure-handling answer interviewers grade: given scenarios, state procedures with prices ([2.2](<../../sections/2. Judgment/2.2. Failure rehearsal game-days.md>)/[Domain 05 §3.1](<../../../05 Testing Deployment and Operations/sections/3. Readiness/3.1. Production checklists.md>)) — crashes drilling (kill measuring — losses verifying (totals proving — honesty earning (windows stating — calibration completing); outages degrading (fallbacks serving — availability sustaining (grace owning — panic ending (robustness composing — brittleness declining); slowness bounding (timeouts firing — tails cutting (liveness proving — deadlocks ending (force owning — mercy bounding). Procedures pricing (steps ordering — costs stating (readiness proving — hope ending).

**What problem it solves** — the unhandled-failure trio: *scenarios unanswering* ("we have backups" (procedures missing — steps unordered (owners unnamed — drills undating (readiness feigning — hope hiding (substance absenting — pressure collapsing); *prices missing* (procedures stating sans costs (losses unnumbering — downtimes unbounding (honesty partialing — calibration halving (judgment splitting — wisdom dividing); *automation assuming* (tools handling — humans unready (exceptions unowned — judgment missing (procedures unsupervising — edge cases failing (automation hoping — direction absenting). Priced procedures converting hopes to readiness (steps ordering — costs stating (automation supervising — humans directing); interviewers grading procedures with prices (readiness proving → hired; backups-claiming → rejected).

**Modern guidance** — the handling lines (interview-enforced — capstone, never repetition): *crashes stating* (kill measuring — losses verifying (windows stating — calibration completing (honesty earning — hope ending (drills dating — evidence freshening); *outages degrading* (fallbacks serving — availability sustaining (grace owning — panic ending (robustness composing — brittleness declining (planning owning — incidents surviving); *slowness bounding* (timeouts firing — tails cutting (liveness proving — deadlocks ending (force owning — mercy bounding (SLOs guarding — breaches alerting).

```text
# GOOD: procedures pricing — crashes stating, outages degrading, slowness bounding (interview-grade shape).
# "Kill -9 staging quarterly → drain verified, loss bounded (mechanics testing — totals verifying, honesty earning).
# Dependency outage → fallback serving (availability sustaining — grace owning — panic ending, robustness composing).
# Slow upstream → timeouts firing at budget (tails cutting — liveness proving — deadlocks ending, force owning)."
# BAD: failures hoping — scenarios unanswering, prices missing, automation assuming (real rejection shape).
# "Backups exist." (Steps? owners? drilled? — procedures missing — readiness feigning (hope hiding — substance absenting).
# Procedures sans prices (losses unnumbering — downtimes unbounding — honesty partialing (calibration halving — judgment splitting).
# Tools sans humans (exceptions unowned — judgment missing — edge cases failing). State steps; price costs.)
```

**Common confusion** — *"handling means preventing (failures avoiding)."* Preventing reducing frequency (gauges watching — thresholds paging (incidents declining — surprises ending (vigilance working — blindness curing); handling bounding impact (procedures ordering — costs stating (recovery executing — losses minimizing (readiness proving — hope ending (resilience demonstrating — panic declining); preventing + handling composing (frequency declining — impact bounding (maturity compounding — mastery demonstrating (incidents rareing — recoveries quicking). "Avoiding" describing prevention (frequency declining — vigilance working); handling describing bounding (impact minimizing — recovery executing). Prevent diligently (gauges watching — incidents declining); handle explicitly (procedures ordering — losses minimizing).

**Performance note** — handling economics: stating costing sentences (procedures ordering — readiness proving (hope ending — panic declining); pricing costing numbers (losses bounding — downtimes timing (honesty completing — calibration proving); directing costing assignments (humans verifying — exceptions handling (judgment requiring — edge cases owning); hoped equivalents costing collapsed pressure (substance absenting — readiness feigning). State cheaply (sentences — procedures); price always (numbers — honesty).

**Mentor note** — teach "procedure plus price, every scenario" (juniors stating per failure design priced readiness on first practicing; backups-only interrogated ("steps? costs?" — procedures demanding per scenario). Stack two failures once (crash-during-outage answering — ladders composing live (readiness tangible — procedures compounding, never collapsing). State procedures; price costs — handling judgment in three habits, reviewed per scenario.

**Definition** — the judgment answer interviewers grade: the meta-skill across all scenarios ([3.1](<../../sections/3. Mentor capstone/3.1. **What problem it solves** — the undemonstrated trio: *recitation performing* (mechanisms listing — designs missing (trivia displaying — judgment hiding (knowledge shallowing — mastery feigning (depth absenting — pressure collapsing); *fashion following* (trends adopting — reasons skipping (understanding missing — hype ruling (judgment surrendering — mastery abandoning (independence declining — depth draining); *pressure avoiding* (follow-ups deflecting — numbers dodging (honesty fragmenting — calibration failing (composure cracking — readiness doubting (evidence hiding — rigor missing). **Modern guidance** — the judgment lines (interview-enforced — capstone, never repetition): *trade-offs pricing* (numbers stating — totals summing (honesty completing — calibration proving (decisions landing — deliberation timing (rigor demonstrating — mastery proving); *fashion declining* (recitation refusing — reasons demanding (understanding proving — depth sounding (trends questioning — hype discounting (judgment independent — mastery demonstrating (independence keeping — depth holding); *offers earning* (readiness proving — pressure surviving (evidence presenting — hope absenting (rigor demonstrating — mastery verifying (judgment landing — deliberation timing).

```text
# GOOD: judgment demonstrating — trade-offs pricing, fashion declining, offers earning (capstone, modeled).
# "Why layers over handlers-querying? Testability pricing (mocks substituting — databases skipping — isolation proving).
# Why centrally-caught errors? Consistency pricing (formats unifying — drift ending — structure owning).
# Why per-request loaders? Correctness pricing (tenants isolating — leaks preventing — batches proving)."
# BAD: judgment absenting — recitation performing, fashion following, pressure avoiding (real rejection shape).

# Trends adopting sans reasons (understanding missing — hype ruling — judgment surrendering (mastery abandoning — independence declining).
```

**Performance note** — judgment economics: pricing costing sentences (trade-offs owning — decisions landing (rigor demonstrating — mastery proving); declining costing courage (recitation refusing — reasons demanding (understanding proving — independence keeping (fashion discounting — depth holding); earning costing preparation (readiness proving — pressure surviving (evidence presenting — hope absenting (rigor demonstrating — mastery verifying); absent equivalents costing rejected offers (trivia displaying — pressure collapsing). **Mentor note** — teach "decide out loud with numbers" (mentees pricing per trade-off design demonstrated judgment on first practicing; certain-sounding interrogated ("numbers?" — evidence demanding per claim).
