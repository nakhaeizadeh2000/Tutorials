## 5.1. Common interview QA: DI, repos, pipelines, events, smells

### 1) **DI framework or manual wiring?**

**Definition** — the scale screen: manual composition roots (explicit `new` chains — readable, debuggable, zero magic) vs container-managed graphs (registrations resolved — scales past ~10 types, lifetimes managed, Misses loud). Same constructors either way (explicit parameters — leaf 1.1's non-negotiable); different wiring *scale* (graphs tangling past manual readability → containers; below that → manual roots win on clarity). Decision by graph size, never by fashion.

- **What a good answer sounds like**: threshold reasoning ("below ~10 types manual roots read better than container config; past that, registrations beat nested `new`s; lifetimes managed explicitly either way — singleton/scoped/transient stated per registration"), hiding prohibition ("`get()` at roots only — business logic never imports containers; tests inject directly, container-free"), miss behavior ("unbound keys throw at startup — verified `unbound: missing`; typos fail fast, never downstream as `undefined`").
- **Modern guidance** — interviewers listen for *scale-gated* adoption (threshold named before preference): candidates who count types pass; candidates defaulting either way fail the context follow-up ("3-service CLI tool?" → manual; "200-service platform?" → container). Red flags: "containers always" (ceremony without scale — magic where explicitness sufficed), "manual always" (tangled graphs hand-wired — toil mistaken for clarity), service-locator advocacy (hidden dependencies praised as flexibility).

```bash
# The scale answer, structured (leaf 1.1 as interview response)
#  <= ~10 types: manual roots (explicit new chains — readable, debuggable, zero magic).
#  > ~10 types:  container (registrations resolved — scales, lifetimes managed, misses loud).
#  always: constructors explicit (tests container-free); get() at roots only (hiding forbidden).
```

### 2) **Design an event-driven order flow?**

**Definition** — the systems screen: order lifecycle across services (created → paid → shipped → delivered) via topics (one per transition — producers emit, consumers attach), journals (event-sourced truth — state derived by replay, verified balance-80 pattern), idempotent handlers (dedupe-by-id — redelivery-safe), and saga coordination (distributed transactions as choreographed compensations — each step with inverse, failures triggering backward compensation). Full-stack event design, narrated end to end.

- **What a good answer sounds like**: topology first ("topics per transition — producers name topics, never consumers; schemas versioned per channel"), truth second ("sourced journal — append-only, replayable; projections derived, snapshots bounding"), safety third ("handlers idempotent by event-id — at-least-once behaves exactly-once, verified single-apply pattern"), failure fourth ("saga compensations per step — distributed transactions without 2PC; dead-letters monitored, spikes paging"). Then the trade close (ordering per key, retention bounded, schema evolution planned).
- **Modern guidance** — grade *systems completeness* (topology + truth + safety + failure — all four addressed): candidates covering all four pass; candidates describing pub-sub alone fail the production follow-up ("redeliveries? replays? saga failures?"). Instant fail: exactly-once assumed from brokers (transport myth — idempotence unmentioned), journals omitted (state without provenance — audit/recovery unanswerable).

```bash
# The systems answer, structured (leaf 2.2 as interview response)
#  topology (topics per transition; versioned envelopes) -> truth (sourced journal; replayable; snapshotted).
#  -> safety (idempotent handlers; verified single-apply) -> failure (saga compensations; dead-letters monitored).
```

### 3) **Review this for smells?**

**Definition** — the judgment screen: real code sample reviewed live for catalog entries (god objects counted by reasons — leaf 1.1-of-01; anemic models spotted by logic-location — behavior in services, data naked; shotgun surgery predicted by change-fanout — one requirement, N files; golden hammers questioned by fit — tool chosen for familiarity; premature seams flagged by variation-absence). Findings named per catalog entry with fixes routed (extract/relocate/seam/threshold — each finding actionable, never merely critical).

- **What a good answer sounds like**: named findings with routings ("`OrderManager` handles pricing+persistence+notify — god object (3 reasons) → extract per stakeholder + Facade (leaf 1.1-of-01); `Order{data}` + `OrderService{logic}` — anemic → relocate behavior into Order; tax logic in 6 files → shotgun → strategy seam; Kubernetes for static blog → golden hammer → boring alternative"). Severity ordered (corruption risks first — shared mutability, silent drops; economics second — duplication, ceremony). Tone blameless (structures criticized, authors respected — review culture modeled live).
- **Modern guidance** — listen for *catalog precision* (names + routings, not vibes — "messy" scores zero; "god object, split by X" scores): candidates who name-and-route pass; candidates emoting fail the actionability follow-up ("and you'd fix it by...?"). Red flags: rewrite-everything prescriptions ("burn it down" — strangler economics unconsidered), purity absolutism (patterns everywhere — ceremony without variation), people-blaming ("who wrote this?" — culture signal inverted).

```bash
# The judgment answer, structured (leaf 3.1 as interview response)
#  name per finding (god/anemic/shotgun/hammer/premature — catalog terms, not essays).
#  route per finding (extract/relocate/seam/threshold — actionable, never merely critical).
#  order by severity (corruption first, economics second); tone blameless (structures, not authors).
```

### 4) **Common confusion**

- Candidates who answer scale questions with preferences ("I like containers" — scale decides; taste doesn't transfer across team sizes).
- "Event-driven means no consistency worries" (ordering/idempotence/duplication all need explicit design — asynchrony multiplies consistency questions, never removes them).
- Treating smell-spotting as negativity (naming without routing — critique unaccompanied by fixes demoralizes; name+route builds).

### 5) **Performance note**

Modern QA answers should be compact: wiring scale (two minutes — threshold, hiding prohibition, miss behavior), event systems (three minutes — topology, truth, safety, failure), smell review (three minutes — named findings with routings, severity ordered). Candidates who narrate with verified receipts (unbound errors, replay balances, single-apply proofs) take the same time as generalizers and prove triple — structure is speed, in modern interviews as in analysis.

### 6) **Mentor note**

Use Q1 as the scale screen (threshold-gated adoption, hiding forbidden), Q2 as the systems screen (topology/truth/safety/failure complete), Q3 as the judgment screen (named findings with routings, blameless tone). Rubric: junior — correct pattern names with mechanics shown; mid — trade-offs stated (lifetimes, idempotence, severity) unprompted; senior — systems completeness (all four event pillars), strangler economics, ceremony audits without prompting. Keep the verified receipts ready (unbound errors, replay balances, single-apply) — structure narrated with evidence hires. Red-flag fails: framework absolutism, exactly-once assumptions, rewrite prescriptions, people-blaming.
