## 4.1. Modern checklist (habits mentors insist on)

### 1) **Wire explicitly, persist ignorantly**

**Definition** — composition roots own graphs (leaf 1.1 — registrations + lifetimes declared, `get()` confined to bootstrap/tests); policy sees collections (leaf 1.2 — repositories shaped like `Map`, drivers invisible, queries owned). Explicit wiring converts dependency graphs from archaeology into documentation (registrations read as architecture); persistence ignorance converts policy tests from integration ordeals into millisecond suites (fakes honor contracts).

- **What problem it solves**: implicit wiring hides architecture (service-locator calls scattered — graphs unrecoverable from signatures; string-keyed resolutions invisible to compilers — refactors break silently); persistence-coupled policy slows testing to integration pace (suites needing live stores — run rarely, cover partially; driver upgrades fanning through business rules). Checklist converts both to review items (wiring visible? policy driver-free? — yes/no per PR, gaps named instantly).
- **Modern guidance** — demand constructor-visible dependencies (no container imports in policy — lint-enforced where valuable); demand driver-free policy modules (no SDK/SQL/HTTP imports outside repositories/adapters — enforced identically). Review registrations per boundary (lifetimes stated — capture safety checked; misses loud — typos fail at startup). Test policy with fakes exclusively (in-memory twins — milliseconds, deterministic, complete; parity suites gate real stores separately).

```bash
# GOOD: explicitness audited per PR (wiring + ignorance, both visible)
#  constructors state needs (no container imports in policy — grep verifies).
#  policy driver-free (no SDK/SQL/HTTP outside repos/adapters — lint verifies).
#  fakes back every repository (policy suites milliseconds — speed verifies).
# BAD: "works with the container running" as test strategy ("realistic") —
# slow/flaky/rare suites (coverage rots); hidden wiring (architecture archaeology per change)
```

### 2) **Pipeline with contracts, events with idempotence**

**Definition** — middleware pipelines carry termination contracts (leaf 2.1 — defaults, short-circuits, error lanes, double-`next` guards, all tested); event flows carry idempotence (leaf 2.2 — dedupe-by-id on mutating handlers, versioned envelopes, replayable journals). Contracts convert pipelines from emergent behavior into specified guarantees (ends defined before traffic); idempotence converts redelivery from corruption into no-ops (duplicates safe by construction).

- **Why it matters (correctness)**: uncontracted pipelines lose requests silently (fall-through undefined — decisions on missing data; double-`next` duplicating side effects — charges billed twice); non-idempotent handlers corrupt on redelivery (at-least-once *will* redeliver — partitions guarantee it eventually; double-charges/headline incidents trace here without exception). Each failure is silent-path (no error — absence or duplication discovered downstream). Contracts + idempotence convert both to tested properties.
- **Modern guidance** — contract every pipeline end (default/short-circuit/error-lane — all three green required, not just happy-path). Guard `next()` single-call structurally (verified throw pattern — re-entrancy detected, not debugged). Dedupe every mutating handler (event-id seen-sets with retention bounds — redelivery-safe by construction). Version event envelopes (schema registries — consumers tolerate N/N−1; breaking changes version topics, never sneak fields).

```bash
# GOOD: contracts + idempotence tested (properties, not hopes)
#  pipelines: default/short-circuit/error-lane green (termination proven per pipeline).
#  handlers: double-delivery tests green (idempotence proven per mutating handler).
#  envelopes: versioned (breaking changes version topics — consumers never surprised).
# BAD: "happy path green, ship it" on pipelines/events ("time pressure") —
# termination untested (silent drops scheduled); redelivery unhandled (duplicates corrupt eventually)
```

### 3) **Name smells early, refactor continuously**

**Definition** — catalog vocabulary applied in review (leaf 3.1 — god/anemic/shotgun/hammer/cult/premature named per finding, fixes routed per entry); refactoring continuous (strangler extractions per sprint — incremental, tested-green throughout; never big-bang rewrites without strangler economics proven). Smells named early stay cheap (one-reason extractions, seam insertions, threshold enforcements — small fixes on small smells); smells named late arrive as rewrites (god objects at 2000 lines, shotgun changes across 30 files — archaeology before surgery).

- **Why it hurts when missing (correctness, maintainability)**: unnamed smells compound silently (god files grow per feature — invoices arrive per edit; shotgun changes multiply per quarter — estimates blow structurally; ceremonies accrete per reorg — calendars fill with non-producing rituals). Continuous refactoring without catalog direction churns (motion without routing — refactors that relocate rather than resolve). Named-early + refactored-continuously converts decay curves into maintenance lines (smell density tracked quarterly — trending down by process, not luck).
- **Modern guidance** — name smells in every review (catalog terms required vocabulary — findings stated as names + routings, not essays). Strangle incrementally (extract per reason/seam/threshold — green throughout; big-bang only with strangler economics disproven in writing). Track density quarterly (god-file counts, shotgun frequencies, ceremony audits — metrics trending, not one-time campaigns). Sunset dead flexibility (unused seams/flags/recipes deleted on sight — unpaid-for complexity removed, not maintained).

```bash
# GOOD: smells named early, decay reversed continuously (vocabulary + strangler discipline)
#  reviews: catalog terms per finding (god/anemic/shotgun/hammer named + routed — 30 seconds each).
#  sprints: strangler extractions (one reason/seam/threshold per PR — green throughout).
#  quarters: density metrics trending down (god counts, shotgun frequencies, ceremony audits).
# BAD: "tech debt sprint" twice yearly ("dedicated focus") —
# decay compounds 6 months unopposed (archaeology before surgery); focus without vocabulary misroutes
```

### 4) **Common confusion**

- "Checklists replace modern fluency" — checklists *route* to the right wiring/pipeline/smell response; fluency implements containers/repositories/middleware. Both, in that order.
- "Small services don't need wiring discipline" — small services need *lighter* versions (manual roots, single repositories, 3-layer pipelines), not zero: undisciplined wiring fossilizes as services grow (retrofits under load cost 10×).
- "Idempotence is a broker feature" — idempotence lives in *handlers* (dedupe-by-id — application code); brokers deliver at-least-once (transport reality). Conflating layers assigns responsibility nowhere (both sides assume the other).

### 5) **Performance note**

The checklist costs minutes per wiring/pipeline/smell decision (explicitness audits, contract tests, smell naming) against integration incidents (undecipherable wiring, silent drops, duplicate corruption — hours of debugging answers that aren't errors) and decay curves (god growth, shotgun multiplication, ceremony accretion — quarters of compounding drag). Highest-leverage item is explicitness (wiring + ignorance visible — kills whole incident classes); second is contracts + idempotence (tested properties per pipeline/handler); third is early naming (cheap fixes on small smells). Minutes preventing quarters — modern's best attention rate.

### 6) **Mentor note**

Convert this leaf into the team's wiring runbook: explicit roots, ignorant policy, contracted pipelines, idempotent handlers, named smells — every service, every PR. Quiz juniors on routing ("which checklist item fires for string-keyed resolutions? for uncontracted pipeline ends? for unnamed decay?") until answers are environmental. Watch for checklist decay (wiring discipline for a sprint, abandoned under deadline — fix with lint rules and contract tests as review-blocking) and ceremony-theater ("checklist completed" without evidence — fix with artifact demands per item: registrations shown, contracts green, smells named). Review check: wiring explicit, policy ignorant, pipelines contracted, handlers idempotent, smells named — and the mentor's own wiring code modeling all five visibly.
