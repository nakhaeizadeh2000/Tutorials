## 4.1. Distribution checklist (habits mentors insist on)

### 1) **Traverse uniformly, coordinate centrally**

**Definition** — collections expose iteration protocols (leaf 1.1 — `Symbol.iterator`, lazy generators, caller-owned control); peers coordinate through hubs (leaf 1.2 — star topology, thin routing, explicit delivery). Uniform traversal converts representation changes into non-events (clients loop identically); central coordination converts topology changes into one-file edits (members join without touching peers). Both disciplines checked per use: protocol present? hub thin?

- **What problem it solves**: traversal/mechanics mismatches scatter handling (index loops over custom collections — representation-coupled; peer-to-peer imports — N×M wiring; materialized pipelines — memory avalanches; fat hubs — god-mediators). Checklist converts each to a routing question (protocol? hub? laziness? thinness?) answered before code ships — structural decisions made deliberately instead of inherited from examples.
- **Modern guidance** — demand protocol-first collections (iterate without indexing internals — representation hidden). Demand hub-owned topology (peers address hubs — N×1 onboarding). Prefer lazy pipelines (generate on demand — memory flat). Enforce hub thinness (routing/topology/protocol only — business logic at edges). Test uniformity (same operation across backing structures — protocol proven, not hoped).

```bash
# GOOD: distribution disciplined (protocols + hubs, both checked)
#  collections: Symbol.iterator implemented (uniform traversal); pipelines lazy (memory flat).
#  peers: hub-addressed (N×1 onboarding); hub thin (routing only); delivery explicit.
# BAD: "works peer-to-peer" + "loops via indexes" (unexamined defaults) —
# wiring multiplies; representations leak; laziness absent (three disciplines skipped silently)
```

### 2) **Capture opaquely, chain explicitly**

**Definition** — snapshots stay private (leaf 2.1 — originator-owned formats, branded tokens, validated restores); chains terminate loudly (leaf 2.2 — default handlers, dead-letter monitoring, miss semantics stated). Opaque capture preserves encapsulation across save/restore boundaries (format knowledge confined); explicit termination converts absence into signal (unhandled requests surface *somewhere* loud, never vanish).

- **Why it matters (correctness)**: uncaptured state leaks through getters (privates exposed for snapshotting — invariants bypassable); unterminated chains lose requests silently (fall-through undefined — decisions on missing data). Both failures are silent-value (answers, not errors — wrong restores, vanished requests). Checklist converts both to contract items (opacity asserted, termination tested — verified shapes from leaves 2.1–2.2 as oracle patterns).
- **Modern guidance** — brand snapshot types (construction confined to originators — structural opacity). Validate on restore (version/integrity checked — corrupt tokens rejected loudly). Terminate every chain (default/error/dead-letter — miss meaning varies, miss handling never optional). Bound retention everywhere (snapshot caps + history caps — unbounded is incident scheduled). Test round-trips and misses (save→restore→compare; unmatched→terminated — both green required).

```bash
# GOOD: capture + chains contracted (opacity + termination, both tested)
#  snapshots: branded types (only originators mint); restores validated (versions checked).
#  chains: default handlers mandatory (misses observable); dead-letters monitored (spikes page).
# BAD: "save/load works" + "requests flow" (demo-green) —
# encapsulation unproven (getters exposed?); termination untested (miss path ever run?)
```

### 3) **Visit without modifying**

**Definition** — operations as visitors over closed structures (leaf 3.1 — double dispatch, kind-stable domains, cycle discipline): new operations land in new classes (structures untouched — OCP satisfied structurally); cyclic inputs guarded (visited-sets where graphs possible — termination proven per input class); small languages interpreted through trees (parse/evaluate separated — precedence encoded in grammar). Extension without modification, scaled to operation families.

- **Why it hurts when missing (correctness, maintainability)**: operation switches per node kind scatter (new operations edit all kinds — symmetric pain without visitors); cyclic visitors hang (naive recursion on graphs — stack death misdiagnosed as performance); inline evaluators entangle (precedence bugs, injection holes — no tree to inspect). Each traces to unvisited-visitor territory (operations homeless, cycles unguarded, semantics inline). Visitors house operations; discipline guards traversal.
- **Modern guidance** — group operations per visitor (one class per coherent operation set — eval/print/typecheck separated). Guard cycles explicitly (trees assumed stated; graphs visited-set mandatory). Separate parse from evaluate (trees built once — evaluation pure over structure). Bound visitor scope (kind-stable domains — kind churn favors switches; stated per adoption).

```bash
# GOOD: operations housed, traversal guarded (extension + termination, both designed)
#  new operation: new visitor class (zero node edits — verified 9/print pattern scales).
#  cyclic input: visited-set traversal (termination proven); acyclic: plain recursion (depth budgeted).
# BAD: "visitor for flexibility" on churning kinds ("modern") —
# kind additions update all visitors (tax without stability); switches win where kinds churn
```

### 4) **Common confusion**

- "Checklists replace distribution fluency" — checklists *route* to the right structure with the right contract; fluency implements iterators/mediators/visitors. Both, in that order.
- "Small systems don't need distribution discipline" — small systems need *lighter* versions (protocol iterators, thin hubs, paired lifecycles), not zero: undisciplined distribution fossilizes as it grows (retrofits under load cost 10×).
- "Uniformity constrains performance" — uniformity constrains *interfaces* (traversal shape); implementations optimize freely behind protocols (lazy/generator/vectorized internals — same `for...of`, different engines).

### 5) **Performance note**

The checklist costs minutes per distribution decision (protocol/hub/capture/chain/visitor placement) against traversal incidents (representation-coupled loops, N×M wiring, materialized avalanches), lifecycle incidents (ghost updates, unbounded histories), and extension incidents (scattered operations, cyclic hangs). Highest-leverage item is protocol-first (kills representation coupling structurally); second is lifecycle pairing (prevents leak/growth classes); third is visitor grouping (prevents operation scatter). Minutes preventing rewrites — distribution's best attention rate.

### 6) **Mentor note**

Convert this leaf into the team's distribution runbook: traverse uniformly, coordinate centrally, capture opaquely, chain explicitly, visit without modifying — every collection, hub, snapshot, chain, and operation family. Quiz juniors on routing ("which checklist item fires for peer wiring? for undo needs? for operation growth?") until answers are environmental. Watch for checklist decay (distribution placed by familiarity under deadline — fix with protocol/topology/cycle questions as review-blocking) and uniformity-theater ("iterable" without laziness, "hub" with business logic — fix with property audits per claim). Review check: protocols uniform, hubs thin, captures opaque, chains terminated, visits non-modifying — and the mentor's own distribution code modeling all five visibly.
