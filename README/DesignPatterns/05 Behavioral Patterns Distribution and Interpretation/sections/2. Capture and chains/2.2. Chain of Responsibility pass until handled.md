## 2.2. Chain of Responsibility: pass until handled

### 1) **Handlers decide locally**

**Definition** — Chain passes requests along handler sequences until one handles (verified neg/zero/pos routing — first-match wins; each handler decides *its* slice: negatives/zero/positives handled disjointly, sender ignorant of all). Handlers know successors (linked explicitly — setNext chains) or share dispatchers (array iteration — verified probe shape); either way, handling decisions stay local (no central router reimplementing the chain's logic — distribution preserved).

- **What problem it solves**: request routing without chains centralizes (switch-on-request-type dispatchers — leaf 1.1-of-04's conditional tax wearing routing clothes; middleware baked into callers — ordering fixed at compile, extension edits core). Chains distribute routing to handlers (each decides handle-or-pass — new handlers insert without touching senders *or* siblings; ordering configured at composition — sequence data, not code). Support escalations, validation pipelines, and event bubbling all share the shape.
- **Modern guidance** — reach for Chain on pass-along routing (validators, approvers, middleware, event bubbling — handlers tried in order, first-match or all-match per semantics). Decide per handler locally (handle/pass/transform-and-pass — three verbs, stated per handler; handlers never address siblings directly). Compose chains at roots (ordered arrays — sequence visible, testable, flaggable; insertion order documented as priority). Distinguish first-match (request *classified* — verified neg/zero/pos) from all-match pipelines (request *processed* through every stage — middleware shape, Domain 06).

```typescript
// GOOD: routing distributed, senders ignorant — verified neg/zero/pos + unhandled default
type Handler = (req: number) => string | null;  // null = pass along (local decision, uniform type)
function chain(handlers: Handler[]): (req: number) => string {
  return (req: number) => {
    for (const h of handlers) { const r = h(req); if (r !== null) return r; }  // first-match wins
    return "unhandled";                          // default: explicit miss (never silent drop)
  };
} // h(-2)/h(0)/h(5) -> neg/zero/pos verified (each handler owns its slice, sender knows none).
// BAD: switch-on-request dispatcher ("centralized") —
// new handler kinds edit the dispatcher (OCP violated per addition); ordering buried in branches
```

### 2) **Senders stay ignorant**

**Definition** — senders address the *chain*, never handlers (one entry point — `handle(request)`; handler identities invisible upstream): new handlers insert without touching senders (compose at roots — sequence data changes, client code identical); handler order reconfigures without sender edits (priority shifts are composition edits, not client edits); handler removal degrades gracefully (chain shortens — default handler catches the newly-unhandled, explicitly). Ignorance is structural (type system shows chain interface only — concrete handlers unimportable from client modules).

- **Why it matters (correctness)**: sender-aware routing couples evolution (new handler kind → sender imports update → all call sites touched — shotgun surgery per addition; handler reorder → sender logic edits — priority encoded in client code; handler removal → dangling references — compile errors *or worse*, stale fallbacks silently catching). Ignorant senders absorb all three (insert/remove/reorder behind the chain interface — client code identical across handler evolution). The seam pays per handler-lifecycle-event, forever.
- **Modern guidance** — depend on chain interfaces only (sender imports `HandlerChain`, never `NegHandler` — enforced by lint where valuable: no-restricted-imports on concrete handlers from client modules). Compose chains at roots (ordered arrays from config — sequence flaggable per environment; test/dev chains differ declaratively). Version handler contracts, not senders (handler interface stable — new handler *kinds* implement existing contracts; contract changes version explicitly with migration).

```bash
# GOOD: ignorance structural (senders address chains, never handlers)
#  new handler: append to chain array (senders untouched — zero client edits, verified pattern scales).
#  reorder: sequence data edited (priority shifts without code changes — config, not surgery).
#  remove: chain shortens (default handler catches newly-unhandled — explicit, tested).
# BAD: sender-side handler selection ("flexible routing") —
# per-sender routing tables duplicating chain logic (drift); handler evolution touching all senders
```

### 3) **Chains need termination contracts**

**Definition** — every chain specifies its miss behavior (default handler returning sentinel — verified `unhandled`; throwing `NoHandlerError` where misses are bugs; dead-letter queues where misses need audit): silent drops are *the* chain bug (requests vanishing with no trace — debugging misattributes to senders/receivers, never the gap between handlers). Termination contracts make misses observable (sentinels logged, errors thrown, dead-letters monitored — unhandled requests always surface *somewhere* loud).

- **Why it hurts when missing (correctness, maintainability)**: unterminated chains lose requests silently (fall-through returning `undefined` — callers proceed on garbage; missing handler kinds unnoticed for quarters — feature requests "lost" that were never routable; incident notifications dropped — pagers silent during outages). Each failure is invisible at the chain (no error — just absence) and catastrophic downstream (decisions made on missing data). Termination contracts convert absence into signal (sentinel/error/dead-letter — always *something* observable).
- **Modern guidance** — terminate every chain explicitly (default handler mandatory — sentinel, error, or dead-letter per domain; bare fall-through forbidden in review). Log unhandled at warning+ (misses monitored — dashboards on dead-letter rates; spikes page). Test the miss path deliberately (unmatched requestKind fixtures — termination verified, not assumed). Distinguish miss-semantics per chain (default-value chains return sentinels; validation chains throw; audit chains dead-letter — miss *meaning* varies, miss *handling* never optional).

```typescript
// GOOD: misses observable (termination contracted, never silent)
// return "unhandled" (verified default — sentinel surfaces in logs/tests, never vanishes).
// validation variant: throw new NoHandlerError(kind) (misses are bugs — fail loud).
// audit variant: deadLetter.push(req) + metrics (misses monitored — spikes page).
// BAD: fall-through undefined returns ("falsy is fine") —
// requests vanish (no trace); callers proceed on garbage (decisions on missing data); incidents silent
```

### 4) **Common confusion**

- "Chain is just a loop over handlers" — loops *implement* chains; the pattern adds *local decisions + sender ignorance + termination contracts* (structure with guarantees, not iteration). Loops without contracts are chains without safety.
- "Middleware equals Chain" — middleware chains *process through all stages* (all-match pipelines — Express/Koa, Domain 06); CoR *classifies at first match* (first-match wins — verified neg/zero/pos). Pass-through vs pass-along — opposite termination semantics.
- "Unhandled requests are edge cases" — unhandled paths execute in production constantly (novel inputs, version skew, partial deployments — misses are routine traffic, not rarity). Termination contracts cover the common case wearing edge clothes.
- "Order doesn't matter with disjoint handlers" — order decides *ties and overlaps* (overlapping predicates — first-match wins by position; even disjoint sets evolve overlaps eventually). Sequence documented as priority, always.

### 5) **Performance note**

Chains cost handlers-tried per request (verified probes single-digit ms; first-match exits early — ordering hot handlers first optimizes the common path); miss paths cost full traversal + termination (bounded by chain length — chains sized in dozens, not thousands); sender ignorance costs nothing extra (one interface call — indirection identical to direct). Optimize handler order first (hot-first sequencing — common requests short-circuit), miss handling second (sentinel fast-paths, dead-letter async), traversal mechanics never (linear scan already near floor).

Watch for the dispatcher-centralizer ("one switch to rule them" — fix with per-handler-addition arithmetic: edits × conflicts × tests) and the silent-dropper ("falsy is fine" — fix with dead-letter dashboard demo: misses monitored).
