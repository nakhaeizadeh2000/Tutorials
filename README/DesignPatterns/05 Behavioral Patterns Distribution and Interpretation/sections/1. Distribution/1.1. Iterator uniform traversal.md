## 1.1. Iterator: uniform traversal

### 1) **One protocol for all collections**

**Definition** — Iterator exposes *traversal* while hiding *structure* (one protocol — `Symbol.iterator` yielding elements — clients `for...of` uniformly whether backing is array, tree, generator, or remote pages): collections own internals (arrays/trees/graphs/DB cursors — representation free to change), clients own loops (uniform syntax — representation changes break nothing downstream). Verified: `NumRange(3,6)` yields `3,4,5,6` through the same `for...of` arrays use — protocol identical, structure invisible.

- **What problem it solves**: traversal without iterators couples clients to representations (index loops assume arrays — tree/graph migration rewrites every loop; cursor APIs leak paging (page tokens in business logic — pagination leaking into domain code); callback iteration (`forEach`) surrenders control (no break/return/await composition — internal iteration owns the loop). Uniform protocol decouples (representation changes behind the protocol — clients untouched; control stays caller-side — pause/resume/zip/merge composable).
- **Modern guidance** — implement `Symbol.iterator` on custom collections (generators preferred — `*` methods read as traversal directly; manual `{next()}` objects where state machines demand). Consume uniformly (`for...of`, spread, destructuring — protocol syntax, never index arithmetic on opaque collections). Keep iteration side-effect-free (traversal reads — mutating during iteration invalidates unpredictably; snapshot or version-check where mutation interleaves).

```typescript
// GOOD: structure hidden, control caller-side — verified 3,4,5,6 through uniform syntax
class NumRange {
  constructor(private from: number, private to: number) {}
  *[Symbol.iterator](): Generator<number> {   // lazy: values produced on demand (nothing precomputed)
    for (let i = this.from; i <= this.to; i++) yield i;
  }
}
[...new NumRange(3, 6)];  // 3,4,5,6 verified (spread consumes protocol — backing invisible).
// BAD: index loops over custom collections ("direct") —
// representation coupled (tree migration rewrites loops); control surrendered (no pause/zip/merge)
```

### 2) **Lazy generators traverse free**

**Definition** — generator iterators produce values on demand (suspended execution — `yield` pauses, `next()` resumes; infinite sequences representable — primes/naturals/event-streams as *values*, not buffers): memory `O(1)`-ish regardless of sequence length (one live frame, not materialized arrays); early termination free (`break` abandons the rest — uncomputed work never billed). Verified-shape reasoning: the `NumRange` above allocates nothing per element (generator frame only — range size irrelevant to memory).

- **Why it matters (correctness)**: eager traversal materializes (million-element intermediates per pipeline stage — memory avalanches; infinite sequences unrepresentable — streams buffered until OOM). Lazy pipelines compose (map/filter/take as generator transforms — each stage pulls on demand; terminal operation drives exactly what's consumed). Early exits save proportionally (find-first over infinite streams terminates — eager versions hang forever). Laziness converts traversal from allocation into choreography.
- **Modern guidance** — write traversals as generators by default (lazy until materialization proves necessary — `[...gen]` at boundaries where arrays are genuinely needed). Compose pipeline stages as generator transforms (map/filter/take generators — pull-driven, memory-flat). Terminate explicitly (bounded `take(n)` on infinite sources — unbounded consumption hangs by construction, not by bug). Document laziness at API level (consumers must know values compute on pull — side-effect timing differs from eager).

```typescript
// GOOD: choreography, not allocation (lazy pipeline, pull-driven)
function* naturals(): Generator<number> { let i = 1; while (true) yield i++; }  // infinite, O(1) memory
function* take<T>(xs: Iterable<T>, n: number): Generator<T> { let c = 0; for (const x of xs) { if (c++ >= n) break; yield x; } }
[...take(naturals(), 3)];  // [1,2,3] (infinite tamed by bounded take — termination explicit).
// BAD: materialize-then-process pipelines ("simpler to debug") —
// million-element intermediates per stage (memory avalanches); infinite sources hang (unrepresentable eagerly)
```

### 3) **External iteration beats internal**

**Definition** — external iterators (caller pulls via `next()` — pause/resume/zip/merge under caller control) compose where internal iteration (callee pushes via callbacks — `forEach` owning the loop) cannot: parallel traversal (zip two iterators step-locked — callbacks can't synchronize); early exit with state (break carrying partial results — `forEach` swallows `return`); async interleaving (`for await` sequential pulls — callback hell resurrected otherwise). Control location *is* the distinction (caller-owned loops compose; callee-owned loops isolate).

- **Why it hurts when missing (correctness, maintainability)**: internal-only traversal forces workarounds for control needs (exceptions-as-break — control flow abused; boolean flags across callbacks — state smeared; nested `forEach` for zips — `O(n²)` accidental where step-locked is linear). Each workaround obscures intent (code reads as iteration plus hacks; reviewers verify hacks, not logic). External iteration expresses control directly (break/continue/return/await — language-level, no workarounds).
- **Modern guidance** — expose external iteration on collections (protocol-first — `Symbol.iterator` before convenience methods). Prefer `for...of` over `forEach` where control matters (break/continue/return/await — language constructs, not workarounds). Reserve callbacks for terminal consumption (side-effect sinks — logging/sending per element where control is genuinely unneeded). Test zip/merge/early-exit compositions (multi-iterator choreography — the compositions callbacks cannot express).

```bash
# GOOD: caller-owned loops (control composable)
#  zip(a, b): step-locked pulls (parallel traversal — callbacks cannot synchronize).
#  find-first: break with partial state (early exit carrying results — forEach swallows return).
#  for-await: sequential async pulls (interleaving without nesting — callback hell avoided structurally).
# BAD: "forEach suffices" as traversal policy ("simpler API") —
# pause/zip/merge/async impossible without workarounds (exceptions-as-break, flag smearing, nested hell)
```

### 4) **Common confusion**

- "Generators are slow" — generators cost frame-suspension per yield (nanoseconds — dwarfed by per-element work in real pipelines); materialization costs allocation per element (GC pressure dominating at scale). Laziness wins where allocation dominates (almost everywhere past trivial sizes).
- "for...of works on everything" — `for...of` works on *iterables* (protocol-conformant — arrays/Maps/generators/custom with `Symbol.iterator`); plain objects aren't iterable (no protocol — spread/destructure fail identically). Protocol membership decides, not object-ness.
- "Internal iteration is more functional" — functional style is about *purity/composition*, not push-vs-pull (generator pipelines compose functionally *with* caller control — map/filter/take as lazy transforms). Push/pull is control location; functional is effect discipline.
- "Infinite iterators are dangerous" — unbounded *consumption* is dangerous (materializing infinity hangs — always); infinite *sequences* with bounded takes are safe and expressive (termination explicit at consumption). Danger lives at `[...inf]`, not `inf`.

### 5) **Performance note**

Iterators cost protocol hops per element (nanoseconds — `next()` dispatch, JIT-inlined at monomorphic sites) plus per-element work (dominant — traversal overhead negligible beside it); lazy pipelines cost one live frame per stage (memory flat — allocation avoided structurally); materialization costs full-array allocation per stage (GC pressure scaling with data — the avoided cost). Optimize protocol stability first (monomorphic iteration — megamorphic `next()` sites deopt), allocation avoidance second (lazy default), hop overhead never (nanoseconds, inlined).
