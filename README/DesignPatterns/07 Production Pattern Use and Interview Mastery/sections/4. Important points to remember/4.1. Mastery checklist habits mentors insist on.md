## 4.1. Mastery checklist (habits mentors insist on)

### 1) **Select by constraints, evolve by strangler**

**Definition** — pattern choices constrained first (team/latency/change/regulatory context — leaf 1.1), designs evolved incrementally (seam → migrate → delete — leaf 1.2's strangler with verified 20→18 shape). Selection without constraints is fashion (costs billed silently); evolution without stranglers is gambling (cutovers binary). Both disciplines checked per significant decision (ADRs for selections, tickets for retirements — artifacts, not intentions).

- **What problem it solves**: unconstrained selection misfits systematically (distributed monolith-needs, abstracted script-needs — fashion incidents); unevolved designs fossilize (big-bang rewrites stalled mid-flight, old paths coexisting forever — migration incidents). Constraints-first prevents misfit (context picks patterns); strangler-first prevents fossilization (increments complete — carcass deleted, never parked). The pair covers selection *and* evolution (choose rightly, change safely — full lifecycle discipline).
- **Modern guidance** — state constraints per pattern decision (four answers before shortlisting — team/latency/change/regulatory). Seam before migrating (abstraction over old/new from minute one — traffic controllable immediately). Date retirements at migration start (carcass tickets filed with seam PRs — tracked, evidenced, celebrated). Revisit selections on constraint drift (team ×3? latency ÷10? — choices re-derived, ADRs superseded, never fossilized).

```bash
# GOOD: choose rightly, change safely (selection + evolution disciplined jointly)
#  select: constraints stated -> shortlist -> boring-wins-ties -> ADR recorded (leaf 1.1).
#  evolve: seam -> migrate-by-traffic -> verify-zero -> delete loudly (leaf 1.2; verified 20->18 shape).
# BAD: "standard stack, big rewrite when needed" (fashion + gambling) —
# misfits unbilled until incidents; rewrites binary (cutover risk total); carcasses fossilized (tracked never)
```

### 2) **Review by checklist, design pit-of-success**

**Definition** — pattern reviews gated per family (leaf 2.1 — scoped checklists, smell routings, property tests); APIs guiding correct use (leaf 2.2 — pit-of-success naming, unrepresentable invalidity, instructing errors). Review-by-checklist converts taste into procedure (gates applied uniformly — quality independent of reviewer assignment); pit-of-success converts misuse from likely to awkward (correct paths shortest — newcomers succeed by default; dangerous paths verbose — risk-takers self-identify).

- **Why it matters (correctness)**: ungated reviews approve structural decay (seams unbothered-questioned, lifecycles unasserted, intents unnamed — each PR locally reasonable, globally rotting); neutral APIs misuse at chance rates (boolean blindness, null ambiguity, silent misconfigurations — support load proportional to vagueness). Checklists gate structure (applicable family items, every PR); pit-of-success shapes behavior (correctness by default, danger by deliberation). Prevention beats archaeology on both axes.
- **Modern guidance** — gate family-relevant items per PR (scoped checklists — applicable gates only, never whole-track ceremony). Name smells with routings (catalog terms + fixes — findings self-directing). Prove properties in CI (seams/substitution/lifecycles green-required, not advisory). Name happy paths shortest (frequency inversely proportional to length — obvious correct). Forbid invalid states in types (unions/brands/builders — misuse uncompilable, not documented-against).

```bash
# GOOD: gates + guidance jointly enforced (procedure + design, both green)
#  review: family-scoped gates (checklist per PR scope) + smell names with routings.
#  design: shortest-happy-path + unrepresentable-invalid + instructing-errors (misuse awkward structurally).
# BAD: "careful reviews" + "documented APIs" (culture without mechanics) —
# care varies per reviewer (ungated decay); docs unread under pressure (guidance unenforced)
```

### 3) **Compose knowingly, narrate audibly**

**Definition** — pattern stacks recognized as compositions (leaf 3.1 — MVC/MVP/MVVM decomposed to Observer/Strategy/Composite; frameworks evaluated per piece, migrated per piece); reasoning performed aloud wherever scored (interviews, reviews, incidents — narration as coordination technology). Knowing composition prevents framework mystique (pieces named — strengths/weaknesses separable); audible narration prevents unscored brilliance (thinking visible — hired/shared/debugged).

- **Why it hurts when missing (correctness, maintainability)**: monolith-framework thinking blocks migration (wholesale rewrites where piece-swaps sufficed — quarters wasted; framework bugs blamed on patterns — misattributed, unfixed at the right layer). Silent brilliance blocks careers and coordination (unscored interviews — offers lost; unnarrated incidents — responders uncoordinated; uncommented reasoning — reviewers guessing). Composition recognized + narration performed converts both from liabilities into leverage (migratable systems, scorable thinking).
- **Modern guidance** — decompose frameworks per adoption (pieces named — kept/swapped deliberately, never wholesale by default). Narrate decisions continuously (six-beat interviews, reasoned reviews, modeled incidents — audible reasoning as standing habit). Migrate per piece (strangler discipline applied to frameworks — blast radius bounded per piece). Teach composition explicitly (juniors decompose new frameworks unprompted — the skill that outlives every specific stack).

```bash
# GOOD: stacks known, thinking heard (leverage both directions)
#  compose: frameworks decomposed (pieces named/kept/swapped deliberately); migrations piece-scoped.
#  narrate: beats audible (interviews) + decisions attached (reviews) + models shared (incidents).
# BAD: framework identity ("our stack") + silent brilliance ("code speaks") —
# migrations wholesale-or-never (leverage lost); reasoning unscored/unshared/undebugged (leverage lost)
```

### 4) **Common confusion**

- "Checklists replace mastery" — checklists *route* to masterful behaviors under pressure (selection/evolution/review/composition triggered when clocks run); mastery executes with judgment. Routing first, judgment always.
- "Small teams don't need mastery discipline" — small teams need *lighter* versions (one-page ADRs, strangler-lite migrations, narration in pairing), not zero: undisciplined mastery fossilizes as teams grow (retrofits under load cost 10×).
- "Narration is extroversion" — narration is *procedure* (beats/specs/closes — learnable structure, not personality). Introverts narrate structurally; extroverts ramble without it. Structure decides, temperament doesn't.

### 5) **Performance note**

The checklist costs minutes per significant decision (constraints stated, strangler ticketed, gates applied, composition named, narration performed) against fashion incidents (mispatterned quarters), fossilized migrations (binary cutovers + carcasses), ungated decay (structural rot per PR), and unscored brilliance (offers lost, incidents uncoordinated). Highest-leverage item is constraints-first selection (prevents misfit families); second is strangler-evolution (prevents binary risk + fossils); third is audible narration (converts thinking to scored/shared leverage). Minutes preventing quarters — mastery's best attention rate.

### 6) **Mentor note**

Convert this leaf into the team's mastery runbook: select-by-constraints, evolve-by-strangler, review-by-checklist, design-pit-of-success, compose-knowingly, narrate-audibly — every significant decision, migration, PR, API, stack, and interview. Quiz juniors on routing ("which checklist item fires for framework adoption? for silent brilliance? for carcass code?") until answers are environmental. Watch for checklist decay (mastery performed for a sprint, abandoned under deadline — fix with ADR tickets, gate automation, narration scoring as mechanical teeth) and identity-thinking ("our stack/our way" — fix with piece analysis + constraint arithmetic, unbrandable). Review check: constraints stated, stranglers ticketed, gates applied, APIs guiding, stacks known, narration heard — and the mentor's own mastery modeling all six visibly.
