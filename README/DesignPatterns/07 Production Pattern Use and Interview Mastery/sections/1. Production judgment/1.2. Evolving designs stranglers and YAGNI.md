## 1.2. Evolving designs: stranglers and YAGNI

### 1) **Strangle, don't rewrite**

**Definition** — the strangler pattern migrates behavior incrementally (old + new implementations behind one seam — verified 20→18 across migration flag; traffic moves piece by piece — route, validate, expand; old path deleted only after full migration). Big-bang rewrites bet the system on unproven replacements (flag-day cutovers — rollback means reverting everything; parallel implementations maintained during overlap — double cost with zero traffic evidence). Stranglers convert migration risk from binary (works/fails at cutover) into gradual (each increment independently verified, reversible).

- **What problem it solves**: legacy replacement without stranglers faces two bad options (big-bang rewrite — quarters of parallel work culminating in one terrifying deploy; indefinite coexistence — old system never dies, maintenance split forever). Stranglers add the third path (seam first — abstraction over old/new; migrate incrementally — traffic percentages climbing with confidence; delete old last — carcass removed, never fossilized). Each increment ships independently (value delivered per migrated slice — migration funds itself; rollback scoped to the last increment — blast radius bounded structurally).
- **Modern guidance** — seam before migrating (abstraction over both implementations — verified Strangler class delegating by flag; callers depend on the seam from minute one). Migrate by traffic percentage (1% → 10% → 50% → 100% — confidence earned per stage; metrics compared per increment — behavior parity evidenced, not hoped). Delete the old path loudly (removal celebrated — carcass deletion PRs reviewed with joy; fossilized old paths are stranglers abandoned mid-squeeze — tracked to completion, never parked).

```typescript
// GOOD: migration as traffic control — verified 20 (old) → 18 (new) behind one seam
class Strangler implements Pricing {
  private migrated = false;
  constructor(private oldP: Pricing, private newP: Pricing) {}
  migrate(): void { this.migrated = true; }   // traffic control: flag flips per stage (1%..100% in prod)
  total(items: number[]): number { return (this.migrated ? this.newP : this.oldP).total(items); }
} // before: 20 verified (old serves); after migrate(): 18 verified (new serves; old deletable).
// BAD: big-bang replacement ("cleaner architecture") —
// quarters parallel (double cost, zero traffic evidence); flag-day cutover (binary risk); rollback = everything
```

### 2) **YAGNI with teeth**

**Definition** — You Aren't Gonna Need It, enforced (build for current variation — speculative seams/flags/abstractions deleted on sight, not maintained "just in case"): teeth means *mechanical* (speculative code flagged in review — "which current requirement needs this?" unanswered → removed; YAGNI violations tracked like tech debt — named, dated, retired). Aspirational YAGNI ("keep it simple" as vibe) degrades into permission-to-underbuild (missing seams where roadmaps *do* speak — leaf 1.2-of-01's predicted-variation exception, honored).

- **Why it matters (correctness)**: speculative code bills without users (unexercised paths untested — bugs hibernate until accidental activation; abstraction layers navigated per debug session — comprehension taxed per incident; "flexible" parameters complicating every call site — simple uses pay complexity rents). Underbuilt code bills on arrival (missing seams force invasive edits when variation lands — leaf 1.2-of-01's late-discovery tax). Teeth distinguish (current-variation seams required; speculative variation refused — evidence decides, foresight doesn't).
- **Modern guidance** — demand current-requirement evidence per abstraction ("which shipping feature varies here?" — none named → delete; roadmap-named → seam with ADR). Delete speculative code on sight (unexercised flags/params/layers removed in the PR that finds them — no deprecation process for the never-used). Honor roadmap-spoken variation (predicted kinds with dates get seams — YAGNI waived where roadmaps speak, per leaf 1.2-of-01). Review YAGNI both directions (overbuilt *and* underbuilt flagged — simplicity and readiness balanced per evidence).

```bash
# GOOD: evidence-gated abstraction (current variation required, speculative refused)
#  shipping feature varies by region TODAY -> seam now (evidence: 3 regions live, 2 onboarding).
#  "might need plugins someday" (no roadmap) -> deleted on sight (speculation unpaid-for).
#  roadmap Q3: two vendors (dated) -> seam with ADR (predicted variation honored, not hoped).
# BAD: "flexible for the future" frameworks without customers ("vision") —
# unexercised paths untested (bugs hibernating); navigation taxed per debug; removal feared (sunk-cost shrine)
```

### 3) **Retire on schedule**

**Definition** — migrated old paths deleted on schedule (strangled carcass removal dated at migration start — deprecation warnings → traffic-zero verification → deletion PR → post-removal validation): scheduled retirement prevents fossilization (old code "kept just in case" — maintained accidentally via passing tests nobody owns; dependency drift breaking unmaintained paths silently — security patches missing dead-but-present code). Retirement scheduled is retirement completed (calendar-driven, not courage-driven).

- **Why it hurts when missing (correctness, maintainability)**: fossilized old paths tax comprehension (newcomers map dead code as if live — onboarding includes archaeology; "which implementation runs?" answered by flag archaeology, not docs); tax security (dead paths with live dependencies — CVEs in code nobody maintains but everybody ships); tax velocity (refactors detouring around carcass constraints — living code shaped by dead neighbors). Deletion *is* the migration's final deliverable (migrations ending in coexistence didn't finish — they stalled politely).
- **Modern guidance** — date removal at migration start (carcass deletion ticket filed with the seam PR — tracked from day one, not "later"). Verify traffic-zero before deleting (metrics confirm no calls — evidence, not hope; canary the deletion where feasible). Delete loudly (removal PRs announced — dependents speak now or maintain their own forks; silent deletions strand). Celebrate deletions (net-negative-line quarters — simplicity as team metric; carcass bonfires build deletion culture better than mandates).

```bash
# GOOD: retirement scheduled from day one (tracked, evidenced, celebrated)
#  migration start: carcass-removal ticket filed (dated Q+1; owner named; traffic-zero gate defined).
#  migration end: metrics confirm zero calls -> deletion PR announced -> removed -> validated post-delete.
# BAD: "leave the old path, harmless" (fossilization by comfort) —
# comprehension taxed (archaeology per newcomer); security drifted (dead code, live CVEs); velocity shaped by carcass
```

### 4) **Common confusion**

- "Strangler means slow migration" — strangler means *safe* migration (increments independently verified — speed follows confidence; rushed increments skip verification, slow ones over-verify). Pace set by evidence rate, not pattern name.
- "YAGNI forbids planning" — YAGNI forbids *un evidenced building* (speculative code); planning (ADRs, seams for roadmap variation, strangler tickets) is required *alongside*. Plan on paper, build on evidence.
- "Deletion is risky" — deletion *of verified-zero-traffic code* is the safest change possible (no callers — nothing breaks by definition; metrics prove it). Risk lives in unmeasured deletions (hope-based) — evidence-gated deletions are free correctness.
- "Big rewrites are sometimes necessary" — necessary *only* where strangulation is structurally impossible (irreducible architectural mismatches — vanishingly rare; most "necessary" rewrites needed seams, not greenfields). Necessity claimed per case with strangler-attempt documented.

### 5) **Performance note**

Stranglers cost seam indirection per call during migration (nanoseconds — one delegation; removed with the carcass post-migration — temporary overhead with an expiry date). Big rewrites cost parallel maintenance (double teams/quarters — human pipeline at maximum burn) plus cutover risk (binary outcomes — rollback scope total). YAGNI discipline costs review vigilance (speculative code challenged per PR — minutes) versus speculative maintenance (unexercised code navigated per debug — hours compounded). Fossilized carcasses cost comprehension/security/velocity continuously (unbounded integral — deletion pays once, dividends forever).

### 6) **Mentor note**

Demo migration live (verified 20→18 behind one seam — "traffic moved, old deletable" converts strangling from metaphor to observable). Enforce YAGNI with evidence questions ("which shipping feature varies here?" — silence deletes). Schedule a carcass bonfire quarterly (fossil hunt with deletion PRs — culture built through celebration). Watch for the big-bang romantic ("cleaner" rewrites — fix with cutover-risk arithmetic: binary outcomes × total scope) and the fossil-keeper ("harmless" old paths — fix with comprehension/security/velocity invoices). Review check: seams precede migrations, speculation evidenced-or-deleted, retirements dated, juniors can strangle unprompted.
