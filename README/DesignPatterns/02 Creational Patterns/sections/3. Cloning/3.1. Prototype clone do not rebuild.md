## 3.1. Prototype: clone, don't rebuild

### 1) **Clone configured exemplars**

**Definition** — Prototype creates objects by *copying* preconfigured exemplars (clone the prototype — configured once, duplicated per use) instead of reconstructing (re-running expensive setup per instance — parsing, handshakes, asset loads). `structuredClone` is the modern deep default (verified working — engine-native, handles cycles/Dates/Maps where JSON round-trips corrupt). Expensive setup amortizes across copies (configure once, clone N times — the creational answer to repeated costly construction).

- **What problem it solves**: repeated expensive construction bills per instance (config parsed per request, connection handshakes per task, template compiled per render — identical setup recomputed identically). Prototypes pay setup once (exemplar configured carefully, even slowly) and clone cheaply per use (structured copy — fast, no revalidation needed since the exemplar was valid). Request latency drops by the setup cost; startup complexity stays in one place (the exemplar's construction, reviewed once).
- **Modern guidance** — reach for Prototype on expensive-setup-per-instance shapes (parsed configs, compiled templates, primed connections — setup cost dominating instance cost). Prefer `structuredClone` for deep copies (engine-native — cycles, Dates, Maps, typed arrays handled; JSON round-trip corrupts all four — legacy hack, retired). Keep exemplars immutable (frozen prototypes — clones diverge safely; mutable exemplars drift across clones — shared-state incidents wearing creation clothes).

```typescript
// GOOD: configure once, clone per use — verified independence
const base: Config = { host: "x", ports: [80, 443] };
const d = structuredClone(base); d.ports.push(8080);  // engine-native deep copy (verified 80,443 base intact)
console.log(base.ports.join(","));  // 80,443 verified (exemplar untouched by clone mutation).
// BAD: re-parse/re-handshake per instance ("stateless design") —
// identical setup recomputed per request (latency taxed); exemplar+clone pays once, copies cheap
```

### 2) **Shallow vs deep is the whole question**

**Definition** — shallow copies share nested references (spread/`Object.assign` — top level fresh, depths aliased); deep copies duplicate recursively (independent graphs — mutations isolated). Verified: shallow clone pushing 8080 *mutates the base* (`80,443,8080` — leak demonstrated); deep clone leaves base `80,443` with clone `80,443,8080` (isolation proven). The choice *is* the pattern's correctness content — everything else (registries, exemplars) is organization around it.

- **Why it matters (correctness)**: shallow-by-default clones corrupt shared state silently (two "independent" configs sharing one ports array — port added for staging appears in production; test fixtures leaking across cases — order-dependent suites; nested defaults mutated by consumers — library internals rewritten by callers). The failure is aliasing (two names, one object — JavaScript's reference semantics biting through copy syntax). Depth decided per field (primitives copy free; arrays/objects/maps need explicit depth — the audit checklist per clone site).
- **Modern guidance** — default to deep (`structuredClone` — verified isolation; audit exotic fields it can't carry — functions, DOM nodes, class instances with methods — documented per clone site). Use shallow deliberately where sharing is *intended* (flyweight-style shared substructures — documented aliasing, never accidental; immutable shared depths — safe by construction). Test clone independence explicitly (mutate clone, assert base unchanged — the verified probe as unit test shape; aliasing bugs caught in one assertion).

```typescript
// GOOD: depth decided per field, isolation tested (verified probe as test shape)
const s = { ...base }; s.ports.push(8080);   // SHALLOW: base.ports now 80,443,8080 verified (leak!)
const dd = structuredClone(base); dd.ports.push(8080);  // DEEP: base stays 80,443 verified (isolated).
// test: clone-mutate-assert-base (aliasing caught in one assertion — file per clone site).
// BAD: spread-as-deep-copy habit ("copies everything") —
// top level fresh, depths aliased; nested mutation leaks across "independent" copies silently
```

### 3) **Registries name the prototypes**

**Definition** — Prototype registries map keys to exemplars (clone-by-key: `registry.make("web")` — verified `{"host":"w","ports":[80]}`; unknown keys throw named errors — fail fast on misconfiguration). Configuration catalogs without construction logic (callers name *what*, registry owns *how* — creation knowledge centralized in registrations, not scattered across call sites). Unknown-key errors beat default-guessing (explicit failure over silent wrong-config — the robustness half of the pattern).

- **Why it hurts when missing (correctness, maintainability)**: exemplar scattering (prototypes constructed inline per use — five slightly-different "standard" configs drifting; unknown-key tolerance (default configs silently substituted — wrong environment served without error); construction logic in callers (each call site re-knows setup — changes fan out). Registries centralize all three (one registration per named config — reviewed once; unknown keys throw — misconfiguration loud; callers name keys — creation knowledge stays put).
- **Modern guidance** — register exemplars at startup (named configurations, reviewed together — catalog discipline). Throw on unknown keys (verified `unknown: k` error — loud misconfiguration beats silent wrong-config). Deep-copy on `make()` (registry exemplars stay pristine — clones diverge safely; shallow registry copies reintroduce aliasing at the catalog level). Version catalog entries with the code that consumes them (config/code drift caught by co-review — registries versioned, not ambient).

```typescript
// GOOD: cataloged exemplars, loud misses, pristine registry (verified make + throw shape)
class Registry {
  private protos = new Map<string, Config>();
  register(k: string, c: Config): void { this.protos.set(k, c); }
  make(k: string): Config {
    const p = this.protos.get(k);
    if (!p) throw new Error(`unknown: ${k}`);  // loud miss (no silent defaults)
    return structuredClone(p);                  // deep: registry exemplar stays pristine
  }
} // make("web") -> {"host":"w","ports":[80]} verified.
// BAD: inline exemplar construction per use ("flexible") —
// five drifting "standards"; unknown keys defaulted silently; creation knowledge scattered per caller
```

### 4) **Common confusion**

- "Prototype means `.prototype`" — GoF Prototype means *clone exemplars* (creational pattern); JS `[[Prototype]]` means *delegation chains* (language inheritance — [JavaScript 07](<../../../../JavaScript/07 Prototypes and Classes/README.md>)). Same word, unrelated mechanics — the interview trap this leaf defuses.
- "structuredClone handles everything" — handles data (cycles, Dates, Maps, typed arrays — verified); not functions, DOM nodes, or class instances with methods (throws or strips — documented limits). Exotic fields need custom cloners (stated per site, tested per type).
- "Clone registries are just Maps" — registries add *policy* (unknown-key errors, deep-on-make, catalog review) atop storage. Bare Maps of configs lack all three (silent misses, aliased exemplars, scattered registration).
- "Deep copy is always safer" — deep copy is *isolation*; sharing is sometimes intended (flyweights, immutable shared depths — documented aliasing). Safety = intended sharing + tested isolation, not maximal copying.

### 5) **Performance note**

Cloning costs object-graph size per copy (verified probes single-digit ms at these sizes; structuredClone engine-speed beats manual recursion ~2–5× typically); setup amortization divides exemplar cost by copy count (expensive-once vs expensive-always — the ratio that justifies registries); shallow copies cost top-level only (fast, aliased — speed with sharing semantics attached). Optimize setup-once first (exemplar economics), depth-choice second (deep default, shallow documented), clone mechanics never (engine-native beats hand-rolled).

### 6) **Mentor note**

Demo aliasing live (shallow push mutating base — "80,443,8080 where 80,443 was promised" converts depth-choice from theory to observable). Contrast structuredClone vs JSON round-trip on Dates/Maps/cycles (corruption visible — legacy hacks retired with evidence). Drill registry discipline ("unknown keys: throw or default?" — loud wins, always). Watch for the spread-as-deep habit ("copies everything" — fix with clone-mutate-assert test on their own code) and the rebuild-per-instance default ("stateless" — fix with setup-cost arithmetic per request). Review check: depth decided per field, isolation tested, registries loud on misses, juniors can narrate aliasing unprompted.
