## 4.1. Behavioral checklist (habits mentors insist on)

### 1) **Behavior selected, not branched**

**Definition** — strategies/states over conditionals (leaf 1.1–1.2: runtime choice via composition, condition-driven moves via tables — never switch-on-kind for varying behavior). Selection lives at roots (factories/config/caller choice) or in transitions (event-driven moves) — never scattered per call site. Second conditional on the same axis triggers extraction (mechanical rule — fossilization prevented structurally, not by vigilance).

- **What problem it solves**: behavioral conditionals rot multiplicatively (N kinds × M call sites — each new behavior edits all sites; merge conflicts per addition; test matrices per combination). Selected behaviors isolate (one file per strategy/state — independent review, testing, merging). Runtime selection follows free (configuration/flags/adaptive choice — behavior changes without deploys where selection is data-driven).
- **Modern guidance** — extract at the second conditional on one axis (strategy/state immediately — the rule preventing fossilization). Select at roots/transitions (composition-time choice or event-driven moves — never mid-logic switches). Test per behavior in isolation (contract suites per strategy/state — shared assertions where promised, divergence documented). Delete retired conditionals (dead branches removed with the strategies that replaced them — fossil code confuses).

```bash
# GOOD: selection structured (no behavioral conditionals in client code)
#  strategies injected (caller/config selects — leaf 1.1); states transition on events (leaf 1.2).
#  second conditional on one axis -> extract immediately (rule, not discussion).
# BAD: "one more case" × 15 kinds ("contained switch") —
# contained conditionals grow unbounded; strategies would have flattened at branch two
```

### 2) **Notifications decoupled, lifecycle managed**

**Definition** — observers decoupled both directions (leaf 2.1: subjects never name observers; order-independence contracted; subscribe/unsubscribe paired structurally), commands reified with lifecycles (leaf 2.2: `do`/`undo` pairs shipped together; histories bounded; queues/audits composed). Decoupling without lifecycle leaks (lapsed listeners — pairing enforced); lifecycle without decoupling welds (concrete observers/commands — OCP violated per notification).

- **Why it matters (correctness)**: notification systems fail at lifecycle edges (ghost updates from lapsed listeners — verified-shape risk from leaf 2.1; unbounded histories — memory incidents wearing UX; unpaireable subscriptions — teardown impossible by design). Command systems fail at pairing gaps (undo-less `do()` — tech debt with interest; unbounded queues — backlog memory; opaque payloads — undebuggable backlogs). Checklist covers both jointly because evented systems combine them (observers triggering commands — decoupled *and* reified, each disciplined).
- **Modern guidance** — pair every subscription (disposable returned — teardown unconditional; counts asserted in tests). Pair every `do()` with `undo()` (shipped together — review rejects solos). Bound every history/queue (caps stated — ring buffers/counts; unbounded is incident scheduled). Freeze event payloads (subscriber mutation corrupting siblings — shared-state incident wearing events, prevented structurally).

```bash
# GOOD: decoupling + lifecycle jointly disciplined (both halves green)
#  observers: paired sub/unsub (counts asserted) + order-tolerance contracted + payloads frozen.
#  commands: do/undo shipped together + histories bounded + payloads debuggable.
# BAD: "events work" without pairing/bounding (demo-green) —
# lapsed listeners accumulate; histories grow; payloads mutate (production discovers all three)
```

### 3) **Skeletons documented, hooks explicit**

**Definition** — template sequences final with contracted hooks (leaf 3.1: abstract-required/default-optional/final-closed labeled per member; self-call guarantees stated; Hollywood direction named). Subclasses fill blanks, never reorder (sequence closed — validation steps unskippable); hooks carry contracts (call guarantees, ordering, optionality — API, not archaeology). Undocumented overridables rejected in review (extension surface explicit or absent — no middle ground where fragile-base incidents breed).

- **Why it hurts when missing (correctness, maintainability)**: undocumented skeletons fracture on evolution (base adding steps breaks overrides assuming old sequences — silent behavioral drift; subclasses overriding skeletons bypass validation — security/correctness gates skipped without error). Hook forests grow ungoverned (12 hooks per base — extension surface nobody maps; strategy-shaped needs met with inheritance — wrong pattern by default). Documentation converts both from archaeology into API (labeled members, stated guarantees, named direction).
- **Modern guidance** — label every base member (abstract/virtual/final — three categories, all explicit). State self-call contracts (sequence + guarantees — subclass reliance bounded by statement). Name Hollywood direction (framework-owns-flow vs user-owns-steps — ownership routed on sight). Graduate hook forests to Strategy past ~5 hooks (runtime selection over inheritance hierarchies — binding-time decides pattern).

```bash
# GOOD: skeletons as API (labeled, contracted, directed)
#  abstract buildBody (required) + default header (optional, semantics stated) + final generate (closed).
#  self-calls documented (order + count guaranteed); direction named (framework flows, users step).
# BAD: "extend freely" bases (undocumented overridables) —
# subclasses depend on unstated order; base evolution fractures them silently (fragile, again)
```

### 4) **Common confusion**

- "Checklists replace behavioral fluency" — checklists *route* to the right pattern with the right discipline; fluency implements strategies/observers/commands. Both, in that order.
- "Small event systems don't need lifecycle" — small systems need *lighter* lifecycle (disposable returns, bounded histories — one line each), not zero: undisciplined events leak and grow regardless of scale (lapsed listeners accumulate from day one).
- "Skeletons constrain creativity" — skeletons constrain *sequences* (validation/order invariants); creativity lives in *steps* (hooks filled freely). Constraint where correctness lives, freedom where variation lives.

### 5) **Performance note**

The checklist costs minutes per behavioral decision (selection placement, lifecycle pairing, hook labeling) against conditional fossilization (branch matrices per kind — review/test/merge taxes per addition), lifecycle incidents (ghost updates, unbounded histories — debugging + memory), and skeleton fractures (validation bypasses, order drift — silent behavioral corruption). Highest-leverage item is selection-over-branching (kills fossilization structurally); second is lifecycle pairing (prevents leak/growth classes); third is hook contracts (prevents fragile evolution). Minutes preventing rewrites — behavioral's best attention rate.

### 6) **Mentor note**

Convert this leaf into the team's behavioral runbook: select-don't-branch, pair lifecycles, contract skeletons — every behavior, every event, every hierarchy. Quiz juniors on routing ("which checklist item fires for a third switch branch? for fire-and-forget subscriptions? for overridable sequences?") until answers are environmental. Watch for checklist decay (behavioral discipline for a sprint, abandoned under deadline — fix with extraction rules and pairing asserts as review-blocking) and pattern-theater ("strategy everywhere" without runtime selection — fix with "what selects at runtime here?"). Review check: selection structured, lifecycles paired, skeletons contracted — and the mentor's own behavioral code modeling all three visibly.
