## 1.2. Facade: simplifying the front

### 1) **One call orchestrates subsystems**

**Definition** — Facade provides a simplified entry point over subsystem clusters (video pipeline: decode → filter → encode behind `convert(file)` — verified `mp4[frames(raw.mov)+denoise]`): callers learn one method (not three classes plus ordering rules), orchestration lives in one place (sequence owned, tested, versioned), subsystems keep working independently (facade *coordinates*, never *replaces*). Complexity collapses at the boundary; capability stays intact behind it.

- **What problem it solves**: subsystem clusters burden every caller with orchestration knowledge (decode-then-filter-then-encode ordered correctly by *each* caller — ordering bugs multiply per call site; configuration spread (codec flags, filter params — consistent setup re-derived everywhere); onboarding walls (learn three subsystems to convert one file — expertise taxed per newcomer). Facades centralize the common path (one call does the standard thing — 90% of callers need nothing else) while preserving the full path (power users bypass — next section).
- **Modern guidance** — facade the common path (80/20 orchestration — one method covering standard flows; exotic flows use subsystems directly — both supported, neither forced). Own the sequence explicitly (order + configuration in the facade — callers can't misorder what they never sequence). Name facades after outcomes (`VideoPipeline.convert` — what it achieves; not `VideoFacade` — what pattern it implements). Keep facades thin (delegation + ordering + defaults — logic creep converts facades into god objects wearing simplification clothes, leaf 1.1-of-01 recurring).

```typescript
// GOOD: standard flow, one call — verified mp4[frames(raw.mov)+denoise]
class VideoPipeline {
  constructor(private d = new Decoder(), private f = new Filter(), private e = new Encoder()) {}
  convert(file: string): string { return this.e.run(this.f.apply(this.d.run(file))); }  // order owned HERE
}
// callers: pipeline.convert("raw.mov") (one method, zero ordering knowledge, always correct sequence).
// BAD: every caller sequencing decode/filter/encode ("explicit") —
// ordering bugs per call site (filter-before-decode somewhere); config drift per caller; onboarding walls
```

### 2) **Facades simplify, never hide**

**Definition** — subsystems stay directly reachable *past* the facade (verified: `new Filter().apply(...)` works independently — `frames(raw.mov)+denoise` without the pipeline): simplification without lock-in (standard callers use the front; power callers bypass to subsystems; both supported simultaneously). Hiding facades (private subsystems, facade-only access) convert simplification into restriction (exotic needs unservable — workarounds tunnel around the facade, worse than no facade).

- **Why it matters (correctness)**: lock-in facades fail at the first nonstandard need (custom filter chain unobtainable — callers fork the facade (duplication) or bypass with hacks (unreviewed paths); subsystem upgrades blocked (facade pins versions — security patches wait for facade releases). Open facades degrade gracefully (standard path simple, custom paths possible — the spectrum covered, no cliffs). Simplification that forbids depth is training wheels welded on.
- **Modern guidance** — expose subsystems publicly (facade holds references, never hides them — `pipeline.filter` reachable for custom chains). Document bypass paths (when to skip the facade — custom ordering, exotic configuration, performance-sensitive direct access — guidance, not prohibition). Version facade and subsystems independently (subsystem upgrades flow without facade releases — decoupling preserved in both directions). Test both levels (facade contract tests + subsystem unit tests — simplification verified, depth maintained).

```typescript
// GOOD: front door open, side doors unlocked (simplification without lock-in)
// pipeline.convert(file) for standard flows; pipeline.filter.apply(frames) custom (verified reachable).
// subsystem upgrades (Encoder v2) land without facade edits (decoupled both directions).
// BAD: private subsystems + facade-only API ("clean surface") —
// first custom chain forks the facade (duplication) or tunnels around it (unreviewed paths); clean strangling
```

### 3) **Facade vs mediator split**

**Definition** — Facade simplifies *outward* (one caller → subsystem cluster, unidirectional orchestration — knowledge flows one way); Mediator coordinates *among peers* (many components ↔ central hub, multidirectional protocols — colleagues never address each other, [Domain 05/1.2](<../../../05 Behavioral Patterns Distribution and Interpretation/sections/1. Distribution/1.2. Mediator peers coordinate through hubs.md>)). Same "middle object" shape, opposite communication topologies (fan-in simplification vs peer coordination). Misapplied facades on peer problems centralize what should coordinate (hub bottlenecks with unidirectional tools); misapplied mediators on simplification over-engineer (protocol machinery for one-directional calls).

- **Why it hurts when missing (correctness, maintainability)**: topology mismatch bills structurally (facade-shaped mediator: peers calling through a simplifier lose protocol expressiveness — coordination logic homeless, reimplemented per peer; mediator-shaped facade: single-direction calls burdened with colleague registration, event routing, protocol versions — machinery without users). Each works *initially* (small scales forgive topology errors) and rots characteristically (facade-hubs tangle peer logic centrally; mediator-fronts complicate simple calls ceremonially).
- **Modern guidance** — ask "who talks to whom?" (one→many simplification → Facade; many↔many coordination → [Mediator in Domain 05/1.2](<../../../05 Behavioral Patterns Distribution and Interpretation/sections/1. Distribution/1.2. Mediator peers coordinate through hubs.md>) — topology decides, names follow). Keep facades unidirectional (no peer-to-peer logic inside — coordination needs graduate to mediators explicitly, not accrete). Keep mediators protocol-first (colleague contracts defined — hub routes, never simplifies). Reclassify on drift (facade growing peer logic → extract mediator; mediator serving one direction → collapse to facade).

```bash
# GOOD: topology decides (directionality named per middle object)
#  convert(file) orchestrating decode/filter/encode (one -> many) -> FACADE (simplify outward).
#  chat room routing users-to-users (many <-> many) -> MEDIATOR (Domain 05 leaf 1.2: coordinate peers — live link below).
# BAD: "manager/handler" middle objects with undeclared topology ("flexible") —
# directionality undiscovered until peer logic tangles (facade-hub) or calls ceremonialize (mediator-front)
```

### 4) **Common confusion**

- "Facade hides complexity" — Facade *simplifies access to* complexity (subsystems intact behind — verified reachable); hiding *removes* access (lock-in). Simplification preserves depth; hiding destroys it.
- "Facades are just wrappers" — wrappers *contain* (Adapter translates — leaf 1.1; Decorator extends — leaf 2.1); facades *orchestrate* (multi-object sequences owned). Containment vs orchestration — different jobs sharing delegation syntax.
- "One facade per subsystem" — facades serve *caller workflows* (video conversion, checkout flow — outcome-grouped), not subsystem mirrors (DecoderFacade + FilterFacade + EncoderFacade = indirection without simplification). Workflows decide count.
- "Bypass paths defeat the facade" — bypass paths *complete* it (standard-simple plus custom-possible — spectrum coverage). Unused bypasses cost nothing; missing ones cost forks.

### 5) **Performance note**

Facades cost one delegation layer per call (nanoseconds — inlined at monomorphic sites; orchestration logic identical with or without the front). Duplicated orchestration costs per-caller bugs (ordering/config drift — human pipeline, days). Subsystem-direct power use costs nothing extra (same objects, no facade tax — bypass free by construction). Optimize caller correctness first (single orchestration owner eliminates ordering bugs structurally), delegation overhead never (nanoseconds, optimized away).

### 6) **Mentor note**

Contrast orchestration ownership live (three callers sequencing vs one facade — "count the orderings that can go wrong" converts centralization from taste to arithmetic). Demand reachable subsystems ("show me the bypass" — lock-in refused structurally). Drill topology split ("who talks to whom?" — Facade vs Mediator placed before named). Watch for the sequencer-scatterer ("explicit everywhere" — fix with ordering-bug autopsy on multi-caller code) and the facade-locker ("clean surface," private subsystems — fix with first-custom-chain pain demo). Review check: common path one call, subsystems reachable, topology declared, juniors can place new workflows unprompted.
