# 2.2. Versioning and evolution

## 1. Versions scoping (breaking numbering — additive flowing — clients trusting)

**Definition** — version scope: breaking changes numbered, additive changes flowing unversioned (breaking numbering — majors bumping (releases stating — surprises declining (numbering proving — hoping ending); additive flowing — fields adding (clients unbreaking — trust keeping (flowing funding — flag-day declining); clients trusting — consumers coding (mocks serving — docs reading (trusting earning — discovering ending).

**What problem it solves** — the unversioned trio: *numbers missing* (releases unstated — surprises scheduling (accountability declining — trust eroding (missing billing — archaeology funding); *additives versioning* (fields bumping — majors churning (versions inflating — meaning diluting (versioning charging — clarity declining); *scopes blurring* (breaking hiding — additive blocking (fear owning — velocity dying (blurring billing — judgment missing). Scoped versions converting missing to numbering (breaking bumping — additive flowing (clients trusting — surprises declining); reviewers seeing version decisions per change (scoping proving → verifiable; missing → returned).

**Modern guidance** — the scoping lines per change (review-enforced): *breaking numbering* (majors bumping — releases stating (surprises declining — hoping ending (numbering proving — missing refusing (clarity earning — archaeology declining); *additive flowing* (fields adding — clients unbreaking (trust keeping — flag-day declining (flowing funding — churning declining (growth owning — inflation refusing); *clients trusting* (consumers coding — mocks serving (docs reading — discovering ending (trusting earning — breaking declining (confidence funding — incidents preventing).

```typescript
// GOOD: versions scoping — change kinds routing to same-version or major-bump (compiled + run live).
type Kind = 'add-field' | 'rename-field' | 'remove-field' | 'add-route';
function version(kind: Kind, current: string): string { // breaking numbering — majors bumping, hoping ending
  if (kind === 'rename-field' || kind === 'remove-field') {
    const major = Number(current.slice(1).split('.')[0]) + 1;
    return `v${major}`;
  }
  return current; // additive flowing — fields adding, clients unbreaking
}
const same1 = version('add-field', 'v1');
const same2 = version('add-route', 'v1');
const bump1 = version('rename-field', 'v1');
const bump2 = version('remove-field', 'v2');
console.log(same1 === 'v1' && same2 === 'v1' && bump1 === 'v2' && bump2 === 'v3' ? 'versions scope' : 'numbers miss');
```

```typescript
// BAD: versions missing — numbers unstated, scopes blurring (real unversioned shape).
// // "Just push it." (releases unstated — surprises scheduling — trust eroding).
// // Additive bumping majors (versions inflating — meaning diluting). Number breaking; flow additive; trust clients.)
```

**Common confusion** — *"versions live in headers only (transports hiding)."* Headers versioning invisibly (transports hiding — caches varying (greppability declining — debuggability taxing (hiding charging — clarity declining); paths versioning visibly (routes stating — clients reading (caches keying — greps finding (stating funding — hiding ending). "Headers" describing transports (versions hiding — caches varying); paths describing visibility (routes stating — clients reading). Scope visibly (paths stating — greps finding); hide never (headers obscuring — debugs taxing).

**Performance note** — scoping economics: numbering costing versions (releases stating — surprises declining (trust earning — archaeology declining); missed equivalents costing surprises (releases unstated — trust eroding (support ticketing — archaeology funding). Number cheaply (versions — majors); miss never (numbers — surprises).

**Mentor note** — teach "breaking bumps, additive flows" (juniors scoping one version per change design surprise-free evolutions on first hearing; unscoped changes interrogated ("same or major?" — scoping demanding per change). Scope one change once (breaking numbering — additive flowing tangible (missing ending — scoping proving permanently). Bump breaking; flow additive — scoping discipline in three habits, reviewed per change.

## 2. Evolutions sequencing (expands contracting — deprecations dating — sunsets announcing)

**Definition** — evolution sequencing: expand, deprecate with dates, sunset announced (expands contracting — news adding (olds removing-last (sequencing proving — banging declining); deprecations dating — warnings stating (alternatives naming — migrations funding (dating funding — surprising ending); sunsets announcing — ends declaring (clients migrating — traffic draining (announcing owning — stranding declining).

**What problem it solves** — the surprise-removal trio: *removals surprising* (fields vanishing — clients crashing (migrations unowned — coordination failing (surprising billing — honesty declining); *deprecations eternaling* (warnings lingering — ends unplanned (cruft accumulating — clarity declining (eternaling charging — decisiveness missing); *sunsets unannouncing* (ends arriving — traffic stranding (migrations panicking — trust eroding (unannouncing costing — reliability declining). Sequenced evolutions converting surprising to announcing (expands adding — deprecations dating (sunsets declaring — traffic draining); reviewers seeing sunset dates per deprecation (sequencing proving → verifiable; surprising → returned).

**Modern guidance** — the sequencing lines per deprecation (review-enforced): *expands contracting* (news adding — olds removing-last (sequencing proving — banging declining (phases owning — cliffs refusing); *deprecations dating* (warnings stating — alternatives naming (migrations funding — surprising ending (dating funding — eternaling refusing (deadlines owning — drift declining); *sunsets announcing* (ends declaring — clients migrating (traffic draining — stranding declining (announcing owning — arriving refusing (clarity earning — panic declining).

```typescript
// GOOD: evolutions sequencing — sunset ledger distinguishing upcoming from overdue (compiled + run live).
interface Sunset { // deprecations dating — warnings stating, surprising ending
  route: string;
  sunsetQ: string;
}
function sunsetState(s: Sunset, nowQ: string): string {
  if (s.sunsetQ < nowQ) return 'overdue';
  if (s.sunsetQ === nowQ) return 'due';
  return 'upcoming'; // sunsets announcing — ends declaring, stranding declining
}
const ledger: Sunset[] = [ // expands contracting — news adding, olds removing-last
  { route: 'GET /v1/legacy', sunsetQ: 'Q3' },
  { route: 'GET /v1/aging', sunsetQ: 'Q4' },
  { route: 'GET /v1/fresh', sunsetQ: 'Q5' },
];
const states = ledger.map((s) => sunsetState(s, 'Q4'));
console.log(states.join(',') === 'overdue,due,upcoming' ? 'evolutions sequence' : 'removals surprise');
```

```typescript
// BAD: removals surprising — fields vanishing, sunsets unannouncing (real surprise shape).
// // Field gone Friday (clients crashing — coordination failing — honesty declining).
// // Deprecated forever (cruft accumulating — clarity declining). Expand first; date deprecations; announce sunsets.)
```

**Common confusion** — *"sequencing delays cleanup (phases dragging)."* Sequencing ordering safety (news adding — olds removing-last (downtimes declining — surprises preventing (ordering funding — banging declining); delaying postponing decisions (removals drifting — cruft accumulating (ownership missing — clarity declining (delaying charging — decisiveness missing). "Delaying" describing drift (decisions drifting — removals postponing); sequencing describing order (phases owning — sunsets announcing). Order phases (expands owning — sunsets announcing); drift never (decisions postponing — cruft accumulating).

**Performance note** — sequencing economics: ordering costing stages (news adding — sunsets announcing (surprises declining — trust earning); surprised equivalents costing coordination (clients crashing — migrations panicking (honesty declining — trust eroding). Order cheaply (stages — expands); surprise never (removals — sunsets).

**Mentor note** — teach "every deprecation names its sunset" (juniors dating one sunset per deprecation design surprise-free evolutions on first hearing; dateless deprecations interrogated ("which quarter?" — sequencing demanding per warning). Sequence one evolution once (expands adding — sunsets announcing tangible (surprising ending — sequencing proving permanently). Add news; date ends — sequencing discipline in three habits, reviewed per deprecation.

## 3. Breaks declining (renames versioning — removals deprecating — flags declining)

**Definition** — break decline: renames versioned, removals deprecated, flags avoided (renames versioning — fields adding (olds aliasing — news preferring (versioning proving — crashing declining); removals deprecating — warnings dating (migrations funding — sunsets announcing (deprecating owning — silencing declining); flags declining — releases branching (toggles expiring — debt scheduling (declining funding — accumulating ending).

**What problem it solves** — the casual-break trio: *renames casualing* (fields rebranding — clients crashing (contracts breaking — coordination failing (casualing billing — honesty declining); *removals silencing* (shapes shrinking — calls failing (migrations unowned — incidents arriving (silencing charging — trust eroding); *flags accumulating* (toggles branching — debt compounding (releases forking — cleanup hoping (accumulating billing — simplicity dying). Declined breaks converting casualing to versioning (renames adding — removals dating (flags expiring — crashes declining); reviewers seeing migration paths per break (declining proving → verifiable; casualing → returned).

**Modern guidance** — the declining lines per break (review-enforced): *renames versioning* (fields adding — olds aliasing (news preferring — crashing declining (versioning proving — rebranding refusing (evolution owning — breakage declining); *removals deprecating* (warnings dating — migrations funding (sunsets announcing — silencing declining (deprecating owning — shrinking refusing (caution owning — panic ending); *flags declining* (releases branching — toggles expiring (debt scheduling — accumulating ending (declining funding — forking refusing (hygiene owning — rot declining).

```typescript
// GOOD: breaks declining — rename plans sequencing add, alias, migrate, remove (compiled + run live).
type Step = 'add' | 'alias' | 'migrate' | 'remove';
function plan(hasAlias: boolean, migrated: boolean): Step[] { // renames versioning — fields adding, crashing declining
  const steps: Step[] = ['add'];
  if (hasAlias) steps.push('alias');
  if (migrated) steps.push('migrate', 'remove'); // removals deprecating — warnings dating, silencing declining
  return steps;
}
const full = plan(true, true);
const waiting = plan(true, false);
console.log(full.join(',') === 'add,alias,migrate,remove' && waiting.join(',') === 'add,alias' ? 'breaks decline' : 'renames casual');
```

```typescript
// BAD: breaks casualing — fields rebranding, removals silencing (real casual shape).
// // Renamed overnight (clients crashing — coordination failing — honesty declining).
// // Deleted next sprint (calls failing — incidents arriving). Version renames; deprecate removals; expire flags.)
```

**Common confusion** — *"declining means never breaking (compatibility absoluting)."* Declining routing breaks (versions numbering — migrations funding (surprises declining — trust earning (routing proving — casualing refusing); absoluting freezing evolution (changes declining — progress stopping (models stagnating — value decaying (absoluting charging — agility declining). "Never" describing freeze (evolution stopping — progress ending); declining describing routing (breaks versioning — migrations funding). Route breaks (versions numbering — migrations funding); freeze never (evolution stopping — value decaying).

**Performance note** — declining economics: routing costing versions (renames adding — removals dating (surprises declining — trust earning); casual equivalents costing coordination (clients crashing — incidents arriving (honesty declining — trust eroding). Route cheaply (versions — plans); casual never (renames — surprises).

**Mentor note** — teach "add, alias, migrate, remove" (juniors sequencing one rename per four steps design crash-free evolutions on first hearing; overnight renames interrogated ("where is the alias?" — declining demanding per rename). Decline one break once (renames versioning — removals deprecating tangible (casualing ending — declining proving permanently). Add news; remove lasts — declining discipline in three habits, reviewed per break.
