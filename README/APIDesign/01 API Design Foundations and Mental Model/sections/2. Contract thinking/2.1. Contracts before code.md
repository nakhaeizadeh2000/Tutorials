# 2.1. Contracts before code

## 1. Contracts preceding (docs stating — mocks serving — code following)

**Definition** — contract-first: specifications written, reviewed, and mocked before implementation (docs stating — shapes declaring (errors typing — versions numbering (stating proving — coding following); mocks serving — doubles answering (clients unblocking — servers building (serving funding — waiting declining); code following — implementations honoring (specs proving — drifts failing (following owning — diverging declining).

**What problem it solves** — the code-first trio: *specs trailing* (docs following — shapes guessing (clients discovering — incidents teaching (trailing billing — trust eroding); *mocks handrolling* (doubles drifting — specs contradicting (maintenance doubling — confidence bluffing (handrolling charging — value missing); *drifts landing* (code diverging — docs lying (contracts breaking — clients crashing (landing billing — coordination failing). Preceding contracts converting trailing to stating (docs declaring — mocks answering (code honoring — drifts failing); reviewers approving specs before code per endpoint (preceding proving → verifiable; trailing → returned).

**Modern guidance** — the preceding lines per endpoint (review-enforced): *docs stating* (shapes declaring — errors typing (versions numbering — coding following (stating proving — guessing ending (specs owning — incidents preventing); *mocks serving* (doubles answering — clients unblocking (servers building — waiting declining (serving funding — blocking ending (doubles earning — velocity funding); *code following* (implementations honoring — specs proving (drifts failing — diverging declining (following owning — trailing refusing (honor funding — lies declining).

```typescript
// GOOD: contracts preceding — spec reviewed, mock serving, implementation honoring (compiled + run live).
interface Spec { // docs stating — shapes declaring, coding following
  route: string;
  example: unknown;
}
function mockFor(spec: Spec): (route: string) => unknown { // mocks serving — doubles answering, waiting declining
  return (route: string) => (route === spec.route ? spec.example : { code: 'unknown-route' });
}
function honors(spec: Spec, impl: (route: string) => unknown): boolean { // code following — implementations honoring, drifts failing
  return JSON.stringify(impl(spec.route)) === JSON.stringify(spec.example);
}
const spec: Spec = { route: 'GET /v1/items', example: { items: [] } };
const mock = mockFor(spec);
console.log(honors(spec, mock) && JSON.stringify(mock('GET /v9/nope')) === '{"code":"unknown-route"}' ? 'contracts precede' : 'code trails');
```

```typescript
// BAD: specs trailing — docs following, drifts landing (real code-first shape).
// // "We'll document after launch." (shapes guessing — clients discovering — trust eroding).
// // Hand mocks drifting (specs contradicting — confidence bluffing). State docs; serve mocks; follow specs.)
```

**Common confusion** — *"contract-first slows prototyping (specs blocking)."* Specs unblocking clients (mocks serving — servers building (parallel funding — waiting declining (unblocking proving — blocking ending); blocking gating value (approvals queuing — ships waiting (process taxing — momentum dying (blocking charging — agility declining). "Blocking" describing gates (approvals queuing — value missing); preceding describing parallelism (clients unblocking — servers building). State specs (shapes declaring — clients unblocking); follow code (implementations honoring — drifts failing).

**Performance note** — preceding economics: stating costing spec reviews (shapes declaring — mocks serving (clients unblocking — waiting declining); trailed equivalents costing incidents (clients discovering — incidents teaching (trust eroding — support ticketing). State cheaply (specs — reviews); trail never (code — docs).

**Mentor note** — teach "spec reviewed before code" (juniors stating one contract per endpoint design drift-proof integrations on first hearing; codeless specs interrogated ("where is the mock?" — preceding demanding per endpoint). Precede one contract once (docs stating — mocks serving tangible (trailing ending — stating proving permanently). Declare shapes; unblock clients — preceding discipline in three habits, reviewed per endpoint.

## 2. Shapes freezing (schemas owning — changes reviewing — breaks declining)

**Definition** — shape freezing: schemas versioned and diff-gated, additive by default (schemas owning — fields stating (versions numbering — guesses declining (owning proving — hoping ending); changes reviewing — diffs gating (breaks flagging — merges blocking (reviewing funding — silencing declining); breaks declining — renames versioning (removals dating — crashes preventing (declining owning — hoping ending).

**What problem it solves** — the unreviewed-shape trio: *fields sneaking* (shapes growing — reviews skipping (additions unowned — contracts drifting (sneaking billing — trust eroding); *breaks landing* (renames shipping — clients crashing (migrations unowned — coordination failing (landing charging — honesty declining); *schemas hoping* (versions unstated — diffs unrun (changes invisible — surprises scheduling (hoping costing — evolution bluffing). Frozen shapes converting sneaking to gating (schemas owning — diffs blocking (breaks dating — surprises declining); reviewers seeing diffs per schema change (freezing proving → verifiable; sneaking → returned).

**Modern guidance** — the freezing lines per schema (review-enforced): *schemas owning* (fields stating — versions numbering (guesses declining — hoping ending (owning proving — drifting declining (schemas earning — chaos refusing); *changes reviewing* (diffs gating — breaks flagging (merges blocking — silencing declining (reviewing funding — sneaking ending (vigilance owning — incidents declining); *breaks declining* (renames versioning — removals dating (crashes preventing — hoping ending (declining owning — silencing refusing (honesty funding — coordination sparing).

```typescript
// GOOD: shapes freezing — diffs gating merges with severity and reviewer rules (compiled + run live).
interface Diff { // changes reviewing — diffs gating, silencing declining
  added: string[];
  removed: string[];
}
function gate(diff: Diff): string {
  if (diff.removed.length > 0) return 'block:breaking'; // breaks declining — renames versioning, hoping ending
  if (diff.added.length > 0) return 'pass:additive';
  return 'pass:unchanged';
}
const additive: Diff = { added: ['display'], removed: [] }; // schemas owning — fields stating, hoping ending
const breaking: Diff = { added: [], removed: ['email'] };
console.log(gate(additive) === 'pass:additive' && gate(breaking) === 'block:breaking' ? 'shapes freeze' : 'fields sneak');
```

```typescript
// BAD: shapes sneaking — fields growing, breaks landing (real unreviewed shape).
// // New field Friday, no review (additions unowned — contracts drifting — trust eroding).
// // Removed field Monday (clients crashing — coordination failing). Own schemas; gate diffs; date breaks.)
```

**Common confusion** — *"freezing blocks iteration (schemas ossifying)."* Freezing gating breaks (diffs blocking — renames versioning (surprises declining — trust earning (freezing proving — sneaking ending); ossifying refusing change (fields declining — versions stagnating (evolution stopping — progress ending (ossifying charging — agility declining). "Ossifying" describing refusal (change declining — progress ending); freezing describing review (diffs gating — breaks dating). Gate breaks (diffs blocking — surprises declining); grow additive (fields adding — versions numbering).

**Performance note** — freezing economics: gating costing diff checks (schemas owning — breaks dating (surprises declining — trust earning); sneaked equivalents costing incidents (additions unowned — renames shipping (trust eroding — coordination failing). Gate cheaply (diffs — checks); sneak never (fields — reviews).

**Mentor note** — teach "diff per schema change" (juniors gating one diff per schema design sneak-proof contracts on first hearing; undiffed changes interrogated ("additive or breaking?" — freezing demanding per field). Freeze one schema once (schemas owning — diffs gating tangible (sneaking ending — freezing proving permanently). Own fields; block breaks — freezing discipline in three habits, reviewed per schema.

## 3. Clients mocking (doubles serving — servers unblocking — feedback speeding)

**Definition** — client mocking: generated doubles serving recorded examples, unblocking client work (doubles serving — examples answering (clients coding — servers building (serving funding — waiting declining); servers unblocking — implementations decoupling (teams paralleling — releases decoupling (unblocking owning — queuing declining); feedback speeding — issues surfacing (contracts testing — integrations proving (speeding earning — discovering delaying).

**What problem it solves** — the waiting-client trio: *servers blocking* (clients idling — teams queuing (features stalling — velocity dying (blocking billing — parallelism missing); *doubles handmaking* (mocks drifting — specs contradicting (maintenance doubling — confidence bluffing (handmaking charging — value missing); *feedback delaying* (issues surfacing-late — integrations proving-never (surprises scheduling — incidents arriving (delaying costing — trust eroding). Mocked clients converting blocking to serving (doubles answering — servers decoupling (feedback speeding — waiting declining); reviewers generating mocks per spec (mocking proving → verifiable; blocking → returned).

**Modern guidance** — the mocking lines per spec (review-enforced): *doubles serving* (examples answering — clients coding (servers building — waiting declining (serving funding — blocking ending (doubles earning — idleness declining); *servers unblocking* (implementations decoupling — teams paralleling (releases decoupling — queuing declining (unblocking owning — stalling ending (parallelism funding — velocity earning); *feedback speeding* (issues surfacing — contracts testing (integrations proving — discovering delaying (speeding earning — waiting declining (early owning — late declining).

```typescript
// GOOD: clients mocking — spec-generated doubles serving examples, regenerating on change (compiled + run live).
interface Endpoint { // doubles serving — examples answering, waiting declining
  route: string;
  example: string;
}
function serve(endpoints: Endpoint[], route: string): string {
  const found = endpoints.find((e) => e.route === route);
  return found === undefined ? '{"code":"unknown-route"}' : found.example; // servers unblocking — implementations decoupling, queuing declining
}
const spec: Endpoint[] = [
  { route: 'GET /v1/items', example: '{"items":[]}' },
  { route: 'GET /v1/items/i1', example: '{"label":"book"}' },
];
const known = serve(spec, 'GET /v1/items/i1');
const unknown = serve(spec, 'DELETE /v1/items/i1');
console.log(known === '{"label":"book"}' && unknown === '{"code":"unknown-route"}' ? 'clients mock' : 'servers block');
```

```typescript
// BAD: clients waiting — servers blocking, doubles handmaking (real waiting shape).
// // "Blocked on backend." (teams queuing — features stalling — velocity dying).
// // Hand mocks drifting (specs contradicting — confidence bluffing). Generate doubles; unblock servers; speed feedback.)
```

**Common confusion** — *"generated mocks lie about servers (doubles deceiving)."* Generated proving specs (examples answering — implementations honoring (drifts failing — lies declining (proving funding — deceiving refusing); hand mocks deceiving (specs contradicting — maintenance doubling (confidence bluffing — trust eroding (deceiving charging — value missing). "Lying" describing drift (specs contradicting — confidence bluffing); generated describing proof (examples answering — drifts failing). Generate doubles (examples answering — drifts failing); hand-make never (mocks drifting — confidence bluffing).

**Performance note** — mocking economics: generating costing specs (examples answering — clients coding (waiting declining — velocity funding); blocked equivalents costing velocity (teams queuing — features stalling (idleness billing — momentum dying). Generate cheaply (specs — doubles); block never (servers — clients).

**Mentor note** — teach "mock from spec, never by hand" (juniors generating one double per spec design drift-proof clients on first hearing; hand mocks interrogated ("generated from what?" — mocking demanding per double). Mock one spec once (examples answering — servers unblocking tangible (blocking ending — serving proving permanently). Serve examples; speed feedback — mocking discipline in three habits, reviewed per spec.
