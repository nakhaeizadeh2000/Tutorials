# 4.1. API checklist mentors insist on

## 1. Every contract proving (shapes asserting — versions stating — clients mocking)

**Definition** — the contract gate: each endpoint proving shapes, stating versions, serving mocks (shapes asserting — bodies validating (fields checking — garbage declining (asserting proving — assuming ending); versions stating — numbers owning (releases declaring — surprises declining (stating funding — hoping ending); clients mocking — doubles serving (servers unblocking — feedback speeding (mocking owning — waiting declining).

**What problem it solves** — the unproven trio: *shapes assuming* (bodies hoping — fields unchecking (garbage entering — clients crashing (assuming billing — validity bluffing); *versions unstating* (numbers missing — releases unowned (surprises scheduling — trust eroding (unstating charging — accountability declining); *mocks missing* (clients blocking — servers coupling (features stalling — velocity dying (missing costing — parallelism declining). The gate converting assuming to asserting (shapes validating — versions numbering (mocks serving — surprises declining); mentors asking one question per endpoint ("which contract, which version?" — proving demanding per route).

**Modern guidance** — the gate commands (run per endpoint, enforced in review):

```typescript
// GOOD: contracts gated — shapes asserting, versions stating, clients mocking (checklist shape).
// 1. Shape proof (bodies validating — fields checking):
//    every route asserting request and response shapes — unknown fields rejected, garbage declining.
// 2. Version proof (numbers owning — releases declaring):
//    every breaking change numbered — additive flowing, clients trusting, surprises declining.
// 3. Mock proof (doubles serving — servers unblocking):
//    every spec generating its mock — clients coding, servers building, feedback speeding.
// Assert shapes; state versions; serve mocks.)
```

```typescript
// BAD: contracts unproving — shapes assuming, versions unstating (real unproven shape).
// // "Frontend will adapt." (bodies hoping — clients crashing — validity bluffing).
// // No spec, no mock (servers coupling — velocity dying). Assert bodies; number breaks; mock specs.)
```

**Common confusion** — *"gates slow API work (process throttling)."* Gates preventing incidents (shapes validating — versions numbering (surprises declining — trust earning (preventing funding — throttling declining); missing gates slowing debugging (bodies hoping — versions missing (incidents arriving — support ticketing (missing charging — writing declining). "Throttling" describing ceremony (approvals queuing — value missing); gates describing leverage (proof reusing — incidents preventing). Gate contracts (shapes asserting — versions stating); ship faster (incidents declining — velocity funding).

**Performance note** — contract economics: asserting costing spec reviews (shapes validating — versions numbering (mocks serving — surprises declining); assumed equivalents costing incidents (bodies hoping — clients crashing (trust eroding — support ticketing). Assert cheaply (specs — gates); assume never (shapes — clients).

**Mentor note** — demand "contract link in the PR" (juniors proving one contract per endpoint design assumption-free integrations on first hearing; specless endpoints interrogated ("which shape?" — proving demanding per route). Prove one route once (shapes asserting — versions stating tangible (assuming ending — proving permanently). Validate bodies; number versions — proving discipline in three habits, reviewed per endpoint.

## 2. Every error shaping (codes typing — statuses meaning — leaks declining)

**Definition** — the error gate: each failure typing codes, meaning statuses, declining leaks (codes typing — failures classifying (machines routing — humans recovering (typing proving — prose declining); statuses meaning — behaviors choosing (successes succeeding — failures mapping (meaning funding — lying declining); leaks declining — stacks logging (details genericizing — secrets keeping (declining owning — traveling ending).

**What problem it solves** — the unshaped trio: *codes proseing* (bodies apologizing — machines guessing (parsers bloating — consistency failing (proseing billing — typing declining); *statuses lying* (200 answering — errors hiding (success parsing — failures missing (lying charging — contracts breaking); *leaks traveling* (stacks serializing — secrets broadcasting (internals exposing — trust eroding (traveling billing — safety declining). The gate converting proseing to typing (codes classifying — statuses guiding (leaks declining — breaches preventing); mentors asking one question per failure ("which code, which status?" — shaping demanding per error).

**Modern guidance** — the gate commands (run per error, enforced in review):

```typescript
// GOOD: errors gated — codes typing, statuses meaning, leaks declining (checklist shape).
// 1. Code proof (failures classifying — machines routing):
//    every failure carrying code, remedy, reqId — prose absenting, parsers slimming.
// 2. Status proof (behaviors choosing — successes succeeding):
//    every class mapped to its status — 2xx completing, 4xx guiding, 5xx owning.
// 3. Leak proof (stacks logging — details genericizing):
//    responses grepped for internals — stacks server-side, faces generic, reqIds joining.
// Type codes; mean statuses; decline leaks.)
```

```typescript
// BAD: errors unshaping — codes proseing, statuses lying (real unshaped shape).
// res.status(200).json({ error: '...' }); // errors succeeding — failures hiding, success parsing-failing.
// res.status(500).json({ stack }); // internals exposing — attackers reading, trust eroding.
// } // Gate errors: codes typing, statuses meaning, leaks declining.)
```

**Common confusion** — *"gates police style (lint tyrannizing)."* Gates evidencing contracts (codes typing — statuses meaning (proof reusing — judgment focusing (evidencing funding — slowing declining); policing punishing trivia (styles enforcing — meaning ignoring (punishing serving — value missing (policing charging — morale declining). "Policing" describing punishment (trivia enforcing — meaning ignoring); gates describing evidence (contracts proving — trust earning). Evidence contracts (codes typing — statuses meaning); punish never (trivia enforcing — morale declining).

**Performance note** — error economics: typing costing one envelope (failures classifying — remedies prescribing (reqIds correlating — guesses ending); prosed equivalents costing parsers (bodies apologizing — machines guessing (consistency failing — maintenance doubling). Type cheaply (envelopes — codes); prose never (errors — parsers).

**Mentor note** — demand "code and status per failure" (juniors typing one code per error design prose-free APIs on first hearing; codeless failures interrogated ("which status?" — shaping demanding per error). Type one error once (codes typing — statuses meaning tangible (proseing ending — shaping proving permanently). Classify failures; guide clients — shaping discipline in three habits, reviewed per error.

## 3. Every version scoping (breaking numbering — additive flowing — sunsets announcing)

**Definition** — the version gate: each change numbering breaks, flowing additives, announcing sunsets (breaking numbering — majors bumping (releases stating — surprises declining (numbering proving — missing refusing); additive flowing — fields adding (clients unbreaking — trust keeping (flowing funding — churning declining); sunsets announcing — ends declaring (clients migrating — traffic draining (announcing owning — stranding declining).

**What problem it solves** — the unscoped trio: *breaks silencing* (fields renaming — clients crashing (migrations unowned — coordination failing (silencing charging — honesty declining); *additives churning* (fields bumping — majors inflating (versions diluting — clarity declining (churning billing — judgment missing); *sunsets surprising* (ends arriving — traffic stranding (migrations panicking — trust eroding (surprising costing — reliability declining). The gate converting silencing to numbering (breaks dating — additives flowing (sunsets announcing — surprises declining); mentors asking one question per change ("same or major?" — scoping demanding per field).

**Modern guidance** — the gate commands (run per change, enforced in review):

```typescript
// GOOD: versions gated — breaks numbering, additives flowing, sunsets announcing (checklist shape).
// 1. Break proof (majors bumping — releases stating):
//    every breaking change numbered — renames versioning, removals dating, surprises declining.
// 2. Additive proof (fields adding — clients unbreaking):
//    additions flowing unversioned — trust keeping, flag-days declining, growth owning.
// 3. Sunset proof (ends declaring — clients migrating):
//    every deprecation naming its quarter — traffic draining, stranding declining, clarity earning.
// Number breaks; flow additives; announce sunsets.)
```

```typescript
// BAD: versions unscoping — breaks silencing, sunsets surprising (real unscoped shape).
// // Field removed Friday (clients crashing — coordination failing — honesty declining).
// // No sunset date (traffic stranding — migrations panicking). Number breaking; flow additive; date sunsets.)
```

**Common confusion** — *"gates freeze APIs (versions ossifying)."* Gates reviewing changes (breaks numbering — additives flowing (surprises declining — trust earning (reviewing funding — silencing declining); freezing refusing evolution (changes declining — progress stopping (models stagnating — value decaying (freezing charging — agility declining). "Freezing" describing refusal (evolution stopping — progress ending); gates describing review (changes owning — surprises declining). Review changes (breaks numbering — sunsets announcing); freeze never (evolution stopping — value decaying).

**Performance note** — version economics: numbering costing versions (releases stating — surprises declining (trust earning — archaeology declining); silenced equivalents costing coordination (clients crashing — support ticketing (trust eroding — archaeology funding). Number cheaply (versions — majors); silence never (breaks — crashes).

**Mentor note** — demand "same-or-major per change" (juniors scoping one version per change design surprise-free evolutions on first hearing; unscoped changes interrogated ("breaking?" — scoping demanding per field). Scope one change once (breaking numbering — additive flowing tangible (silencing ending — scoping proving permanently). Bump breaking; announce sunsets — scoping discipline in three habits, reviewed per change.
