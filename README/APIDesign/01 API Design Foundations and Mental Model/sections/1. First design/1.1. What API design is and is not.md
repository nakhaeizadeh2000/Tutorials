# 1.1. What API design is and is not

## 1. Design deciding integration (contracts owning — clients trusting — surprises declining)

**Definition** — API design: integration decisions made explicit before code (contracts owning — shapes stating (errors typing — versions numbering (owning proving — vibing declining); clients trusting — consumers coding (mocks serving — docs reading (trusting funding — incidents declining); surprises declining — changes reviewing (breaks versioning — sunsets announcing (declining proving — hoping ending).

**What problem it solves** — the vibe-integration trio: *contracts missing* (endpoints guessing — shapes hoping (clients discovering — incidents teaching (missing billing — trust eroding); *errors proseing* (200 answering — bodies apologizing (success parsing — failures hiding (proseing charging — machines guessing); *changes silencing* (fields renaming — clients crashing (versions unnumbered — breaks unannounced (silencing billing — coordination failing). Designed contracts converting vibes to ownership (shapes stating — errors typing (changes reviewing — surprises declining); reviewers reading contracts before code per endpoint (designing proving → verifiable; vibing → returned).

**Modern guidance** — the designing lines per API (review-enforced): *contracts owning* (shapes stating — errors typing (versions numbering — vibing declining (owning proving — guessing ending (design funding — hoping declining); *clients trusting* (consumers coding — mocks serving (docs reading — incidents declining (trusting funding — discovering ending (confidence earning — archaeology declining); *surprises declining* (changes reviewing — breaks versioning (sunsets announcing — hoping ending (declining proving — silencing refusing (stability earning — chaos declining).

```typescript
// GOOD: design deciding — contract lint asserting versioned paths and listed errors (compiled + run live).
interface Route { // contracts owning — shapes stating, vibing declining
  path: string;
  errors: string[];
}
function lint(routes: Route[]): string[] {
  const bad: string[] = [];
  for (const r of routes) {
    if (!r.path.startsWith('/v')) bad.push(`unversioned:${r.path}`); // versions numbering — breaks declining, hoping ending
    if (r.errors.length === 0) bad.push(`unlisted:${r.path}`); // errors typing — machines routing, surprises declining
  }
  return bad;
}
const routes: Route[] = [
  { path: '/v1/orders', errors: ['not-found', 'invalid-item'] },
  { path: '/orders', errors: [] },
];
const gaps = lint(routes);
console.log(gaps.join(',') === 'unversioned:/orders,unlisted:/orders' ? 'design decides' : 'vibes integrate');
```

// // Fields renaming silently (clients crashing — coordination failing). Own contracts; type errors; review changes.)

"Documentation" describing words (contracts stating — clients reading); design describing decisions (integration owning — surprises declining). State contracts (shapes stating — errors typing); decide integration (ownership owning — trust funding).

**Performance note** — designing economics: owning costing contract reviews (shapes stating — errors typing (surprises declining — incidents preventing); vibed equivalents costing incidents (clients discovering — incidents teaching (trust eroding — support ticketing). Own cheaply (contracts — reviews); vibe never (guesses — incidents).

**Mentor note** — teach "contract before code" (juniors stating one contract per endpoint design surprise-free integrations on first hearing; codeless-contracts interrogated ("where is the doc?" — designing demanding per endpoint). ## 2. Styles differing (REST resourcing — GraphQL querying — gRPC streaming)

**Definition** — the three styles: REST resourcing nouns with verbs statelessly (resources naming — representations serving (stateless owning — cache funding (resourcing proving — RPC declining); GraphQL querying graphs (schemas typing — clients selecting (resolvers owning — overfetching declining (querying funding — endpoints multiplying-ending); gRPC streaming contracts (protos defining — deadlines bounding (streams owning — payloads compacting (streaming proving — JSON declining).

**What problem it solves** — the one-style trio: *defaults RESTing* (graphs overfetching — streams polling (needs mismatching — costs hiding (defaulting billing — judgment missing); *styles confusing* (queries mutating — verbs tunneling (semantics blurring — caches breaking (confusing charging — performance declining); *needs unmatching* (realtime polling — mobiles overfetching (mismatches billing — experiences degrading (unmatching costing — users leaving). Differing styles converting defaulting to matching (resources serving — graphs answering (streams flowing — needs meeting); reviewers naming the style per need (differing proving → verifiable; defaulting → returned).

**Modern guidance** — the differing lines per need (review-enforced): *REST resourcing* (resources naming — representations serving (stateless owning — cache funding (resourcing proving — RPC declining (nouns owning — verbs mapping); *GraphQL querying* (schemas typing — clients selecting (resolvers owning — overfetching declining (querying funding — endpoints declining (graphs serving — mobiles funding); *gRPC streaming* (protos defining — deadlines bounding (streams owning — payloads compacting (streaming proving — JSON declining (contracts owning — backends serving). Style depth lives in Domains 02–04 (TEXTUAL forward per unbuilt-links rule) — this leaf owns the difference, never the mechanics.

// GOOD: styles differing — workload features routing to styles, needs matching (compiled + run live).
type Style = 'rest' | 'graphql' | 'grpc';
function styleFor(needs: { realtime: boolean; mobile: boolean; internal: boolean }): Style {
  if (needs.realtime && needs.internal) return 'grpc'; // streams flowing — deadlines bounding, payloads compacting
  if (needs.mobile) return 'graphql'; // graphs answering — clients selecting, overfetching declining
  return 'rest'; // resources serving — stateless owning, cache funding
}
const a = styleFor({ realtime: true, mobile: false, internal: true });
const b = styleFor({ realtime: false, mobile: true, internal: false });
const c = styleFor({ realtime: false, mobile: false, internal: false });
console.log(a === 'grpc' && b === 'graphql' && c === 'rest' ? 'styles differ' : 'defaults rule');
```

## 3. Costs pricing honestly (versions billing — breaking charging — judgment funding)

**Definition** — honest API costs: versions billed, breaking changes priced, judgment funded (versions billing — numbers owning (releases stating — surprises declining (billing proving — hoping ending); breaking charging — renames pricing (removals dating — migrations funding (charging owning — silencing declining); judgment funding — trade-offs stating (contexts weighing — dogma refusing (funding proving — vibing declining).

**What problem it solves** — the free-breaking trio: *versions missing* (numbers unstated — releases unowned (surprises scheduling — trust eroding (missing billing — accountability declining); *breaks silencing* (fields renaming — clients crashing (migrations unowned — coordination failing (silencing charging — honesty declining); *prices hiding* (costs unowned — judgments unshared (decisions hoping — trade-offs bluffing (hiding costing — offers declining). Honest pricing converting silencing to billing (versions numbering — breaks dating (judgment funding — surprises declining); reviewers seeing break dates per change (pricing proving → verifiable; silencing → returned).

**Modern guidance** — the pricing lines per change (review-enforced): *versions billing* (numbers owning — releases stating (surprises declining — hoping ending (billing proving — missing refusing (clarity earning — archaeology declining); *breaking charging* (renames pricing — removals dating (migrations funding — silencing declining (charging owning — hoping ending (honesty funding — crashing declining); *judgment funding* (trade-offs stating — contexts weighing (dogma refusing — vibing declining (funding proving — bluffing declining (wisdom owning — reciting declining).

```typescript
// GOOD: costs pricing — shape diffs classifying breaking versus safe (compiled + run live).
interface Shape {
  fields: string[];
}
function breaking(from: Shape, to: Shape): string[] { // breaking charging — renames pricing, silencing declining
  return from.fields.filter((f) => !to.fields.includes(f));
}
const v1: Shape = { fields: ['id', 'handle', 'email'] };
const v2: Shape = { fields: ['id', 'handle', 'email', 'display'] }; // versions billing — numbers owning, surprises declining
const v3: Shape = { fields: ['id', 'handle'] };
const safe = breaking(v1, v2);
const cut = breaking(v1, v3);
console.log(safe.length === 0 && cut.join(',') === 'email' ? 'costs price' : 'breaks silence');
```

// BAD: breaks silencing — fields renaming, versions missing (real silent shape).
// // email removed Friday (clients crashing — coordination failing — honesty declining).

**Common confusion** — *"pricing slows shipping (numbers throttling)."* Pricing informing integrators (versions numbering — breaks dating (surprises declining — trust earning (informing funding — throttling declining); throttling blocking value (approvals queuing — ships waiting (process taxing — momentum dying (throttling charging — agility declining). "Throttling" describing process (approvals queuing — value missing); pricing describing honesty (breaks dating — surprises declining). Bill versions (numbers owning — surprises declining); ship steadily (cadence keeping — momentum funding).

**Performance note** — pricing economics: billing costing numbers (versions owning — releases stating (surprises declining — trust earning); silenced equivalents costing coordination (clients crashing — support ticketing (trust eroding — archaeology funding). Bill cheaply (versions — numbers); silence never (breaks — crashes).

**Mentor note** — teach "every break names its version" (juniors billing one version per breaking change design surprise-free evolutions on first hearing; unversioned breaks interrogated ("which version?" — pricing demanding per removal). Bill one break once (versions numbering — breaks dating tangible (silencing ending — honesty proving permanently). Number versions; date breaks — pricing discipline in three habits, reviewed per change.
