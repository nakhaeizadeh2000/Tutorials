# 3.1. Errors shaped uniformly

## 1. Envelopes unifying (codes typing — remedies stating — reqIds tracing)

**Definition** — error envelope: uniform shape carrying machine code, human remedy, and trace id (codes typing — failures classifying (machines routing — humans skimming (typing proving — prose declining); remedies stating — actions prescribing (clients recovering — support guiding (stating funding — guessing ending); reqIds tracing — requests correlating (logs joining — incidents tracking (tracing owning — searching declining).

**What problem it solves** — the prose-error trio: *shapes varying* (endpoints inventing — clients branching (formats multiplying — parsers bloating (varying billing — consistency failing); *remedies missing* (errors stating — actions absenting (users stucking — support guessing (missing charging — resolution delaying); *traces missing* (logs unjoinable — incidents untrackable (requests anonymous — debugging aching (missing costing — MTTR growing). Unified envelopes converting varying to typing (codes classifying — remedies prescribing (reqIds correlating — guesses ending); reviewers finding one envelope per API (unifying proving → verifiable; varying → returned).

**Modern guidance** — the unifying lines per API (review-enforced): *codes typing* (failures classifying — machines routing (humans skimming — prose declining (typing proving — varying ending (classification owning — parsing declining); *remedies stating* (actions prescribing — clients recovering (support guiding — guessing ending (stating funding — missing refusing (guidance owning — stuckness declining); *reqIds tracing* (requests correlating — logs joining (incidents tracking — searching declining (tracing owning — anonymity ending (correlation funding — MTTR shrinking).

```typescript
// GOOD: envelopes unifying — typed codes, stated remedies, traced requests (compiled + run live).
interface Failure { // codes typing — failures classifying, prose declining
  code: string;
  message: string;
  remedy: string;
  reqId: string;
}
function fail(code: string, message: string, remedy: string, reqId: string): Failure {
  return { code, message, remedy, reqId }; // remedies stating — actions prescribing, guessing ending
}
const e = fail('item-missing', 'no such item', 'list /v1/items', 'r-42');
const keys = Object.keys(e).sort().join(',');
console.log(keys === 'code,message,remedy,reqId' && e.reqId === 'r-42' ? 'envelopes unify' : 'errors prose');
```

// BAD: errors proseing — shapes varying, traces missing (real prose shape).
// res.end('error: something broke, idk'); // bodies apologizing — machines guessing, success parsing-failing.
// // No code, no remedy, no reqId (parsers bloating — support guessing). Type codes; state remedies; trace requests.)
```

**Common confusion** — *"envelopes wrap success too (uniformity absoluting)."* Envelopes typing failures (codes classifying — remedies prescribing (machines routing — humans recovering (typing proving — varying ending); success shaping data (payloads serving — metas paging (reads answering — mutations refusing (shaping funding — wrapping declining). "Wrapping" describing uniformity (success enveloping — clients unwrapping (ceremony billing — value missing); envelopes describing errors (failures typing — traces correlating). Shape data (payloads serving — metas paging); envelope errors (codes typing — reqIds tracing).

**Performance note** — unifying economics: typing costing one interface (failures classifying — remedies prescribing (reqIds correlating — guesses ending); varied equivalents costing parsers (formats multiplying — clients branching (consistency failing — maintenance doubling). Unify cheaply (envelopes — codes); vary never (shapes — parsers).

**Mentor note** — teach "code, remedy, reqId — always" (juniors unifying one envelope per API design prose-free errors on first hearing; codeless errors interrogated ("which code?" — unifying demanding per failure). Unify one error once (codes typing — remedies stating tangible (proseing ending — unifying proving permanently). Type failures; trace requests — unifying discipline in three habits, reviewed per error.

## 2. Statuses meaning (2xx succeeding — 4xx guiding — 5xx genericizing)

**Definition** — status semantics: codes choosing client behavior (2xx succeeding — requests completing (data answering — caches storing (succeeding proving — failing declining); 4xx guiding — clients fixing (errors typing — remedies stating (guiding funding — blaming declining); 5xx genericizing — servers owning (details logging — messages generalizing (genericizing proving — leaking declining).

**What problem it solves** — the lying-status trio: *200 answering everything* (errors succeeding — failures hiding (success parsing — machines guessing (lying billing — contracts breaking); *500 validating* (clients blaming — servers owning (guidance missing — remedies absenting (misusing charging — debugging misdirecting); *codes guessing* (statuses hoping — behaviors assuming (semantics ignoring — clients branching (guessing costing — consistency failing). Meaning statuses converting lying to guiding (2xx completing — 4xx fixing (5xx owning — leaks declining); reviewers mapping error classes per status (meaning proving → verifiable; lying → returned).

**Modern guidance** — the meaning lines per error class (review-enforced): *2xx succeeding* (requests completing — data answering (caches storing — failing declining (succeeding proving — erroring refusing (success owning — confusion declining); *4xx guiding* (clients fixing — errors typing (remedies stating — blaming declining (guiding funding — misusing ending (direction owning — shame declining); *5xx genericizing* (servers owning — details logging (messages generalizing — leaking declining (genericizing proving — exposing refusing (ownership funding — blame declining).

// GOOD: statuses meaning — error classes mapped to codes, clients guided (compiled + run live).
function httpStatus(kind: string): number { // 4xx guiding — clients fixing, blaming declining
  const table: Record<string, number> = {
    'invalid-item': 400,
    unauthorized: 401,
    forbidden: 403,
    'item-missing': 404,
    conflict: 409,
    unprocessable: 422,
  };
  return table[kind] ?? 500; // 5xx genericizing — servers owning, leaking declining
}
const codes = ['invalid-item', 'unauthorized', 'forbidden', 'item-missing', 'conflict', 'unprocessable', 'unknown-bug'].map(httpStatus);
console.log(codes.join(',') === '400,401,403,404,409,422,500' ? 'statuses mean' : 'codes lie');
```

**Common confusion** — *"statuses are transport details (semantics dismissing)."* Statuses choosing behavior (caches storing — retries deciding (clients branching — machines routing (choosing funding — ignoring declining); details hiding irrelevance (trivia burying — value missing (hiding serving — designing declining (details proving — meaning declining). "Details" describing trivia (value missing — design ignoring); statuses describing contracts (behaviors choosing — clients guiding). **Performance note** — meaning economics: guiding costing one table (codes mapping — clients fixing (blame declining — debugging directing); lied equivalents costing misdirection (success parsing — failures missing (machines guessing — incidents hiding). Mean cheaply (tables — codes); lie never (200s — errors).

**Mentor note** — teach "status chooses client behavior" (juniors mapping one class per status design lie-free APIs on first hearing; 200-errors interrogated ("which 4xx?" — meaning demanding per failure). ## 3. Leaks declining (stacks logging — details genericizing — secrets keeping)

**Definition** — leak decline: rich server logs with generic client faces (stacks logging — traces capturing (debugging funding — mysteries declining (logging proving — blindness ending); details genericizing — messages generalizing (codes typing — remedies stating (genericizing owning — exposing refusing); secrets keeping — keys redacting (tokens omitting — paths hiding (keeping funding — broadcasting declining).

**What problem it solves** — the broadcasting trio: *stacks traveling* (traces serializing — internals exposing (attackers reading — trust eroding (traveling billing — safety declining); *SQL surfacing* (queries echoing — schemas leaking (details deciding — injections inviting (surfacing charging — layering breaking); *secrets broadcasting* (keys logging — tokens returning (exposure scheduling — incidents arriving (broadcasting billing — safety declining). Declined leaks converting traveling to logging (stacks capturing — details generalizing (secrets keeping — breaches declining); reviewers grepping responses for internals per edge (declining proving → verifiable; traveling → returned).

**Modern guidance** — the declining lines per edge (review-enforced): *stacks logging* (traces capturing — debugging funding (mysteries declining — blindness ending (logging proving — traveling refusing (server owning — client declining); *details genericizing* (messages generalizing — codes typing (remedies stating — exposing refusing (genericizing owning — leaking declining (faces funding — internals hiding); *secrets keeping* (keys redacting — tokens omitting (paths hiding — broadcasting refusing (keeping funding — incidents declining (safety owning — exposure ending).

// GOOD: leaks declining — internal richness logged, public faces generic, joined by reqId (compiled + run live).
interface Internal { // stacks logging — traces capturing, blindness ending

  sql: string;
  reqId: string;

  remedy: string;
  reqId: string;

  serverLog.push(`${e.reqId} :: ${e.stack} :: ${e.sql}`); // secrets keeping — keys redacting, broadcasting refusing

}

const leaked = JSON.stringify(pub).includes('SELECT') || JSON.stringify(pub).includes('pool.query');
