# 1.2. Four call shapes unary to bidi

## 1. Unary serving (requests answering — responses returning — simplicity funding)

**Definition** — unary calls: single request answered by single response (requests answering — calls completing (errors mapping — deadlines bounding (answering proving — streaming declining); responses returning — values delivering (contracts honoring — clients trusting (returning funding — hanging ending); simplicity funding — shapes defaulting (designs starting — complexities deferring (funding owning — streaming declining).

**What problem it solves** — the streaming-default trio: *streams singletoning* (channels opening — values singularing (overhead paying — simplicity missing (singletoning billing — framing declining); *complexity fronting* (streams designing — debugs multiplying (states owning — lifecycles funding (fronting charging — value missing); *hangs hiding* (responses pending — timeouts missing (calls lingering — resources holding (hiding billing — liveness bluffing). Unary serving converting defaulting to answering (requests completing — responses delivering (simplicity funding — streaming deferring); reviewers defaulting unary per RPC (serving proving → verifiable; streaming → returned).

**Modern guidance** — the serving lines per unary call (review-enforced): *requests answering* (calls completing — errors mapping (deadlines bounding — streaming declining (answering proving — hanging refusing (completion owning — pendency declining); *responses returning* (values delivering — contracts honoring (clients trusting — hanging ending (returning funding — void declining (delivery owning — loss declining); *simplicity funding* (shapes defaulting — designs starting (complexities deferring — streaming declining (funding owning — fronting refusing (simple keeping — clever declining).

```typescript
// GOOD: unary serving — real wire roundtrip proving request-response (compiled + run live).
import * as grpc from '@grpc/grpc-js'; // engine owning — serving funding, mechanics borrowing
import * as protoLoader from '@grpc/proto-loader';
const def = protoLoader.loadSync('/tmp/opencode/api-grpc/shapes.proto', { keepCase: true, longs: String, enums: String, defaults: true, oneofs: true });
const pkg = grpc.loadPackageDefinition(def) as any;

async function run(): Promise<void> {
  const server = new grpc.Server();
  server.addService(pkg.shapes.Pipe.service, {
    Once: (call: any, cb: any) => cb(null, { ok: call.request.id.length > 0 }), // requests answering — calls completing, hanging refusing
    Watch: (call: any) => { call.end(); },
    Collect: (call: any, cb: any) => { call.on('data', () => undefined); call.on('end', () => cb(null, { n: 0 })); },
    Chat: (call: any) => { call.on('data', () => undefined); call.on('end', () => call.end()); },
  });
  const port: number = await new Promise((resolve, reject) => {
    server.bindAsync('127.0.0.1:0', grpc.ServerCredentials.createInsecure(), (err, p) => (err ? reject(err) : resolve(p)));
  });
  const client = new pkg.shapes.Pipe(`127.0.0.1:${port}`, grpc.credentials.createInsecure());
  const res: { ok: boolean } = await new Promise((resolve, reject) => {
    client.Once({ id: 'j1' }, (err: any, r: { ok: boolean }) => (err ? reject(err) : resolve(r)));
  });
  console.log(res.ok === true ? 'unary serves' : 'streams default');
  client.close();
  server.forceShutdown();
}
run();
```

```typescript
// BAD: streams singletoning — channels opening, values singularing (real default shape).
// rpc Watch(...) returns (stream ...) for one value; // overhead paying — simplicity missing, framing declining.
// // No deadlines (calls lingering — resources holding). Serve unary; default simple; defer streams.)
```

**Common confusion** — *"unary equals REST POST (styles equating)."* POST creating resources (subordinates adding — HTTP serving (representations returning — caches declining (creating proving — replacing declining); unary answering RPCs (requests completing — responses delivering (contracts honoring — deadlines bounding (answering funding — streaming declining). "POST" describing HTTP (resources creating — representations returning); unary describing shape (requests answering — responses delivering). Create resources (POST owning — subordinates adding); answer RPCs (unary owning — simplicity funding).

**Performance note** — serving economics: answering costing one roundtrip (requests completing — responses delivering (simplicity funding — framing declining); streamed equivalents costing framing (channels opening — states owning (overhead paying — simplicity missing). Answer cheaply (unary — rounds); stream conditionally (needs — proofs).

**Mentor note** — teach "unary unless proven streaming" (juniors serving one RPC per unary design complexity-proof APIs on first hearing; default streams interrogated ("which flow?" — serving demanding per RPC). Serve one call once (requests answering — responses delivering tangible (streaming ending — serving proving permanently). Complete calls; defer streams — serving discipline in three habits, reviewed per RPC.

## 2. Streams flowing (server pushing — clients uploading — bidi conversing)

**Definition** — streaming shapes: server, client, and bidirectional flows (server pushing — feeds emitting (lists serving — polls declining (pushing proving — unary refusing); clients uploading — batches sending (streams aggregating — summaries returning (uploading funding — chattering declining); bidi conversing — channels dialoguing (messages interleaving — states syncing (conversing owning — polling ending).

**What problem it solves** — the unary-stretch trio: *feeds polling* (clients hammering — servers straining (freshness lagging — loads wasting (polling billing — pushing declining); *uploads chattering* (messages tripping — rounds multiplying (latencies summing — throughput dying (chattering charging — batching declining); *dialogues polling* (states syncing-by-refresh — conflicts hiding (freshness hoping — coherence failing (dialoguing billing — conversing declining). Flowing streams converting stretching to pushing (feeds emitting — batches sending (channels dialoguing — polls declining); reviewers matching flows per need (flowing proving → verifiable; stretching → returned).

**Modern guidance** — the flowing lines per stream (review-enforced): *server pushing* (feeds emitting — lists serving (polls declining — pulling ending (pushing proving — hammering refusing (servers owning — clients waiting); *clients uploading* (batches sending — streams aggregating (summaries returning — chattering declining (uploading funding — tripping refusing (clients owning — rounds collapsing); *bidi conversing* (channels dialoguing — messages interleaving (states syncing — polling ending (conversing owning — refreshing declining (dialogues funding — coherence earning).

```typescript
// GOOD: streams flowing — server-streamed events and client-streamed summary live (compiled + run live).
import * as grpc from '@grpc/grpc-js'; // engine owning — flowing funding, mechanics borrowing
import * as protoLoader from '@grpc/proto-loader';
const def = protoLoader.loadSync('/tmp/opencode/api-grpc/shapes.proto', { keepCase: true, longs: String, enums: String, defaults: true, oneofs: true });
const pkg = grpc.loadPackageDefinition(def) as any;

async function run(): Promise<void> {
  const server = new grpc.Server();
  server.addService(pkg.shapes.Pipe.service, {
    Once: (_call: any, cb: any) => cb(null, { ok: true }),
    Watch: (call: any) => { // server pushing — feeds emitting, polls declining
      for (const seq of [1, 2, 3]) call.write({ seq });
      call.end();
    },
    Collect: (call: any, cb: any) => { // clients uploading — batches sending, chattering declining
      let n = 0;
      call.on('data', () => { n += 1; });
      call.on('end', () => cb(null, { n }));
    },
    Chat: (call: any) => { call.on('data', () => undefined); call.on('end', () => call.end()); },
  });
  const port: number = await new Promise((resolve, reject) => {
    server.bindAsync('127.0.0.1:0', grpc.ServerCredentials.createInsecure(), (err, p) => (err ? reject(err) : resolve(p)));
  });
  const client = new pkg.shapes.Pipe(`127.0.0.1:${port}`, grpc.credentials.createInsecure());
  const seen: number[] = await new Promise((resolve, reject) => {
    const out: number[] = [];
    const call = client.Watch({ topic: 't' });
    call.on('data', (e: { seq: number }) => out.push(e.seq));
    call.on('end', () => resolve(out));
    call.on('error', (e: any) => reject(e));
  });
  const total: number = await new Promise((resolve, reject) => {
    const call = client.Collect((err: any, r: { n: number }) => (err ? reject(err) : resolve(r.n)));
    call.write({ id: 'a' });
    call.write({ id: 'b' });
    call.end();
  });
  console.log(seen.join(',') === '1,2,3' && total === 2 ? 'streams flow' : 'unary stretches');
  client.close();
  server.forceShutdown();
}
run();
```

```typescript
// BAD: streams unshaped — feeds polling, uploads chattering (real stretch shape).
// setInterval(poll, 1000); // clients hammering — servers straining, freshness lagging.
// // Per-message RPCs (rounds multiplying — throughput dying). Push feeds; upload batches; converse bidi.)
```

**Common confusion** — *"streaming is always faster (flows speeding)."* Streaming fitting flows (feeds emitting — batches sending (channels dialoguing — polls declining (fitting proving — stretching declining); speeding assuming throughput (bytes moving — latencies dropping (frames funding — waits ending (assuming charging — measuring declining). "Faster" describing hope (throughput assuming — latencies dropping-unmeasured); streaming describing fit (flows matching — polls declining). Fit flows (feeds emitting — batches sending); measure speed (bytes timing — latencies bounding).

**Performance note** — flowing economics: fitting costing shape choice (feeds emitting — batches sending (polls declining — hammering ending); stretched equivalents costing hammer (clients polling — servers straining (freshness lagging — loads wasting). Fit cheaply (shapes — flows); stretch never (unary — streams).

**Mentor note** — teach "match flow to shape" (juniors flowing one stream per need design stretch-proof APIs on first hearing; default bidi interrogated ("which direction?" — flowing demanding per RPC). Flow one stream once (feeds emitting — batches sending tangible (stretching ending — flowing proving permanently). Push server; upload batches — flowing discipline in three habits, reviewed per RPC.

## 3. Shapes choosing (latencies weighing — complexities pricing — needs matching)

**Definition** — shape choice: unary, server-stream, client-stream, or bidi per need (latencies weighing — rounds counting (budgets bounding — hopes declining (weighing proving — defaulting declining); complexities pricing — states owning (lifecycles funding — debugs multiplying (pricing funding — hiding declining); needs matching — flows fitting (polls declining — chatter ending (matching owning — stretching declining).

**What problem it solves** — the default-shape trio: *bidi defaulting* (channels opening — conversations assuming (states owning — debugs multiplying (defaulting billing — simplicity missing); *needs unmatching* (flows unfitting — polls continuing (mismatches billing — experiences degrading (unmatching costing — users leaving); *costs hiding* (complexities unpriced — states unowned (budgets bluffing — surprises scheduling (hiding charging — pricing declining). Chosen shapes converting defaulting to matching (latencies weighing — complexities pricing (needs fitting — bidi declining-unless-proven); reviewers naming shapes per RPC (choosing proving → verifiable; defaulting → returned).

**Modern guidance** — the choosing lines per RPC (review-enforced): *latencies weighing* (rounds counting — budgets bounding (hopes declining — defaulting ending (weighing proving — assuming refusing (numbers owning — surprises declining); *complexities pricing* (states owning — lifecycles funding (debugs multiplying — hiding declining (pricing funding — defaulting refusing (costs owning — simplicity funding); *needs matching* (flows fitting — polls declining (chatter ending — stretching declining (matching owning — unfitting refusing (fit funding — mismatch declining).

```typescript
// GOOD: shapes choosing — features routing to shapes, flags asserting all four (compiled + run live).
import * as grpc from '@grpc/grpc-js'; // engine owning — choosing funding, mechanics borrowing
import * as protoLoader from '@grpc/proto-loader';
type Shape = 'unary' | 'server-stream' | 'client-stream' | 'bidi';
function choose(feed: boolean, upload: boolean): Shape { // needs matching — flows fitting, stretching declining
  if (feed && upload) return 'bidi'; // latencies weighing — rounds counting, defaulting declining
  if (feed) return 'server-stream';
  if (upload) return 'client-stream';
  return 'unary'; // complexities pricing — states owning, hiding declining
}
const def = protoLoader.loadSync('/tmp/opencode/api-grpc/shapes.proto', { keepCase: true, longs: String, enums: String, defaults: true, oneofs: true });
const pkg = grpc.loadPackageDefinition(def) as any;
const svc = pkg.shapes.Pipe.service;
const flags = `${svc.Once.requestStream}:${svc.Once.responseStream},${svc.Watch.requestStream}:${svc.Watch.responseStream},${svc.Collect.requestStream}:${svc.Collect.responseStream},${svc.Chat.requestStream}:${svc.Chat.responseStream}`;
console.log(choose(false, false) === 'unary' && choose(true, false) === 'server-stream' && choose(false, true) === 'client-stream' && choose(true, true) === 'bidi' && flags === 'false:false,false:true,true:false,true:true' ? 'shapes choose' : 'defaults shape');
```

```typescript
// BAD: shapes defaulting — bidi everywhere, needs unmatching (real default shape).

// // Unary needs unfitted (mismatches billing — experiences degrading). Weigh latencies; price complexity; match needs.)
```

"Superset" describing coverage (cases subsuming — needs fitting); bidi describing cost (states owning — debugs multiplying). Converse dialogues (channels owning — states syncing); default unary (simplicity funding — complexity deferring).

**Performance note** — choosing economics: matching costing decisions (latencies weighing — complexities pricing (needs fitting — bidi declining-unless-proven); defaulted equivalents costing states (channels opening — debugs multiplying (simplicity missing — maintenance growing). Match cheaply (shapes — needs); default never (bidi — cases).
