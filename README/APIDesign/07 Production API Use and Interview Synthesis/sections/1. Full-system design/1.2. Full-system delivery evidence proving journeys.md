# 1.2. Full-system delivery evidence proving journeys

## 1. Gates greening (specs fetching — pacts replaying — diffs passing)

**Definition** — green gates: release-blocking checks proving contracts per build (specs fetching — served reading (examples asserting — drift detecting (fetching proving — tribal declining); pacts replaying — consumers filing (providers matching (skews surfacing — breaks paging (replaying funding — hoping declining); diffs passing — schemas comparing (removals dating — builds gating (passing owning — theater refusing).

**What problem it solves** — the green-but-blind trio: *specs unfetching* (docs claiming — artifacts missing (clients guessing — drift hiding (unfetching billing — proof doubting); *pacts unreplaying* (suites skipping — skews accumulating (breaks shipping — callers paging (unreplaying charging — confidence bluffing); *diffs theatering* (gates passing-blindly — removals hiding (incompatibilities deploying — incidents paging (theatering costing — safety performing). Greened gates converting blindness to fetching (specs reading — pacts matching (diffs gating — hopes ending); reviewers reading gate receipts per merge (greening proving → verifiable; theater → returned).

**Modern guidance** — the greening lines per merge (review-enforced): *specs fetching* ([06/2.1](<../../../06 API Operations/sections/2. Contract operations/2.1. Docs publishing OpenAPI guiding clients.md>) — served reading (examples asserting — drift detecting (fetching proving — claiming refusing (reads owning — tribal declining); *pacts replaying* ([06/2.2](<../../../06 API Operations/sections/2. Contract operations/2.2. Contracts testing pacts catching breaks.md>) — consumers filing (providers matching — skews surfacing (replaying funding — skipping refusing (replays earning — drift failing); *diffs passing* ([06/2.2](<../../../06 API Operations/sections/2. Contract operations/2.2. Contracts testing pacts catching breaks.md>) — schemas comparing (removals dating — builds gating (passing owning — theater refusing (comparisons funding — blindness ending).

```typescript
// GOOD: gates greening — fetched specs with replayed pacts and passing diffs (compiled + run live).
interface Gate { // specs fetching — served reading, tribal declining
  spec: boolean;
  pacts: boolean;
  diff: boolean;
}
function ship(g: Gate): string {
  if (!g.spec) return 'BLOCKED:spec'; // pacts replaying — consumers filing, skipping declining
  if (!g.pacts) return 'BLOCKED:pacts';
  if (!g.diff) return 'BLOCKED:diff'; // diffs passing — schemas comparing, theater declining
  return 'SHIP';
}
const green: Gate = { spec: true, pacts: true, diff: true };
const blind: Gate = { spec: true, pacts: false, diff: true };
console.log(ship(green) === 'SHIP' && ship(blind) === 'BLOCKED:pacts' ? 'gates green' : 'merges blind');
```

**Common confusion** — *"green CI means releasable (suites passing)."* Suites passing units (rules asserting — cores guarding (regressions declining — integration hoping (passing serving — contracts missing); gates proving journeys (specs fetching — pacts replaying (diffs gating — drift failing (proving funding — blindness declining). "Green" describing parts (units passing — cores guarding); greening describing wholes (contracts proving — journeys asserting). Pass units (rules asserting — regressions catching); green gates (specs fetching — diffs passing).

**Performance note** — greening economics: fetching costing reads (specs reading — pacts matching (diffs gating — hopes ending); blind equivalents costing incidents (drift shipping — breaks paging (trust eroding — rollbacks racing). Read cheaply (gates — merges); blind never (releases — drift).

**Mentor note** — teach "merge only on fetched proof" (juniors gating one spec-pact-diff triple per merge design blind-proof delivery on first hearing; unfetched merges interrogated ("spec which?" — greening demanding per merge). Green one gate once (specs fetching — pacts replaying tangible (blindness ending — greening proving permanently). Fetch specs; gate diffs — greening discipline in three habits, reviewed per merge.

## 2. Journeys proving (inject driving — denials asserting — replays catching)

**Definition** — proved journeys: end-to-end client tasks driven headless with asserted denials (inject driving — instances exercising (ports skipping — servers sleeping (driving proving — binding declining); denials asserting — rejects checking (403s mapping — expiries refusing (asserting funding — bluffing declining); replays catching — compositions rechecking (regressions failing — drifts surfacing (catching owning — hoping ending).

**What problem it solves** — the unit-green trio: *journeys undriving* (parts passing — wholes hoping (tasks unexercising — clients discovering (undriving billing — integration missing); *denials unasserting* (gates hoping — rejects unchecked (enforcement bluffing — breaches arriving (unasserting charging — safety theatering); *replays uncatching* (compositions unchecking — regressions hiding (drifts shipping — incidents paging (uncatching costing — confidence lying). Driven journeys converting hoping to asserting (instances exercising — rejects checking (compositions rechecking — clients trusting); reviewers driving journeys per slice (proving revealing → verifiable; unit-green → returned).

**Modern guidance** — the proving lines per journey (review-enforced): *inject driving* ([06/3.1](<../../../06 API Operations/sections/3. Operations vehicle/3.1. ```typescript
// GOOD: journeys proving — driven tasks with asserted denials and replays (compiled + run live).
interface Step { // inject driving — instances exercising, binding declining
  name: string;
  want: number;
  got: number;
}
function journey(steps: Step[]): string {
  for (const s of steps) { // denials asserting — rejects checking, bluffing declining
    if (s.got !== s.want) return `FAIL:${s.name}`;
  }
  return 'JOURNEY-OK'; // replays catching — compositions rechecking, hoping declining
}
const ok: Step[] = [
  { name: 'ping', want: 200, got: 200 },
  { name: 'gated-deny', want: 403, got: 403 },
  { name: 'gated-allow', want: 200, got: 200 },
];
const drift: Step[] = [
  { name: 'ping', want: 200, got: 200 },
  { name: 'gated-deny', want: 403, got: 200 },
];
console.log(journey(ok) === 'JOURNEY-OK' && journey(drift) === 'FAIL:gated-deny' ? 'journeys prove' : 'units green');
```

**Performance note** — proving economics: driving costing injects (instances exercising — rejects checking (replays catching — hopes ending); undriven equivalents costing discoveries (clients discovering — breaches arriving (drifts shipping — trust eroding). Drive cheaply (injects — journeys); discover never (production — clients).

**Mentor note** — teach "prove the journey, not the parts" (juniors driving one journey per slice design gap-proof delivery on first hearing; journey-less suites interrogated ("denied how?" — proving demanding per slice). ## 3. Readiness dating (owners naming — drills timing — launches earning)

**Definition** — dated readiness: launches earned with named owners and timed drills (owners naming — humans answering (escalations routing — diffusion ending (naming proving — shrugging declining); drills timing — scenarios rehearsing (blasts bounding — MTTR stating (timing funding — hoping declining); launches earning — gates passing (evidence checking — confidence compounding (earning owning — assuming ending).

**What problem it solves** — the dateless-launch trio: *owners unnamed* (alerts waking-everyone (responsibility diffusing — responses waiting (unnamed billing — accountability missing); *drills untimed* (scenarios unpracticed — recoveries unmeasured (MTTR unknowning — confidence bluffing (untimed charging — readiness theatering); *launches assuming* (gates unpassing — evidence missing (deploys hoping — incidents discovering (assuming costing — earning absenting). Dated readiness converting hoping to earning (humans answering — scenarios rehearsing (gates passing — launches proving); reviewers finding owners and drill dates per launch (dating proving → verifiable; assuming → returned).

**Modern guidance** — the dating lines per launch (review-enforced): *owners naming* (humans answering — escalations routing (diffusion ending — shrugging refusing (naming proving — everyone declining (names owning — waits bounding); *drills timing* ([2.2](<../../sections/2. // GOOD: readiness dating — named owners with timed drills and earned launches (compiled + run live).
interface Launch { // owners naming — humans answering, shrugging declining
  owner: string;
  drillDaysAgo: number;
  gatesPass: boolean;
}
function ready(l: Launch, maxStale: number): string {
  if (l.owner.length === 0) return 'NOT-READY:owner'; // drills timing — scenarios rehearsing, bluffing declining
  if (l.drillDaysAgo > maxStale) return 'NOT-READY:drill';
  if (!l.gatesPass) return 'NOT-READY:gates'; // launches earning — gates passing, hoping declining
  return 'READY';
}
const earned: Launch = { owner: 'ada', drillDaysAgo: 20, gatesPass: true };
const stale: Launch = { owner: 'ada', drillDaysAgo: 200, gatesPass: true };

```
