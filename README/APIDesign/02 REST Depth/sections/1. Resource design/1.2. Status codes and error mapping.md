# 1.2. Status codes and error mapping

## 1. Statuses choosing (2xx succeeding — 4xx guiding — 5xx owning)

**Definition** — status choice: outcome classes owning codes (2xx succeeding — requests completing (data answering — caches storing (succeeding proving — failing declining); 4xx guiding — clients fixing (errors typing — remedies stating (guiding funding — blaming declining); 5xx owning — servers answering (details logging — messages generalizing (owning proving — leaking declining).

**What problem it solves** — the unchosen trio: *codes defaulting* (200 answering — errors hiding (success parsing — failures missing (defaulting billing — contracts breaking); *classes unmapped* (outcomes guessing — statuses hoping (semantics ignoring — clients branching (unmapped charging — consistency failing); *owners missing* (statuses nobody-choosing — reviews unchecking (ownership absenting — drift growing (missing costing — lying returning). Chosen statuses converting defaulting to owning (outcomes classifying — codes guiding (servers answering — leaks declining); reviewers mapping outcomes per route (choosing proving → verifiable; defaulting → returned).

**Modern guidance** — the choosing lines per outcome (review-enforced): *2xx succeeding* (requests completing — data answering (caches storing — failing declining (succeeding proving — erroring refusing (success owning — confusion declining); *4xx guiding* (clients fixing — errors typing (remedies stating — blaming declining (guiding funding — misusing ending (direction owning — shame declining); *5xx owning* (servers answering — details logging (messages generalizing — leaking declining (owning proving — exposing refusing (ownership funding — blame declining).

```typescript
// GOOD: statuses choosing — outcome classes owning codes across the board (compiled + run live).
function httpStatus(outcome: string): number { // 4xx guiding — clients fixing, blaming declining
  const table: Record<string, number> = {
    created: 201,
    deleted: 204,
    fetched: 200,
    invalid: 400,
    unauthenticated: 401,
    forbidden: 403,
    missing: 404,
    clash: 409,
    unprocessable: 422,
    limited: 429,
  };
  return table[outcome] ?? 500; // 5xx owning — servers answering, leaking declining
}
const row = ['created', 'deleted', 'fetched', 'invalid', 'unauthenticated', 'forbidden', 'missing', 'clash', 'unprocessable', 'limited', 'blew-up'].map(httpStatus);
console.log(row.join(',') === '201,204,200,400,401,403,404,409,422,429,500' ? 'statuses choose' : 'codes default');
```

```typescript
// BAD: codes defaulting — 200 answering, classes unmapped (real default shape).
// res.json({ ok: false, error: '...' }); // errors succeeding — failures hiding, success parsing-failing.
// // No mapping table (outcomes guessing — clients branching). Choose statuses: 2xx succeeding, 4xx guiding, 5xx owning.)
```

**Common confusion** — *"201 vs 200 is bikeshedding (codes nitpicking)."* Nitpicking policing trivia (styles enforcing — meaning ignoring (punishing serving — value missing (nitpicking charging — morale declining); choosing guiding machines (caches storing — retries deciding (clients branching — intermediaries acting (choosing funding — guessing declining). "Bikeshedding" describing trivia (styles enforcing — meaning ignoring); statuses describing contracts (behaviors choosing — clients guiding). Guide machines (codes choosing — caches storing); police never (trivia enforcing — morale declining).

**Performance note** — choosing economics: owning costing one table (outcomes classifying — codes guiding (servers answering — leaks declining); defaulted equivalents costing parsing (success guessing — failures missing (machines branching — incidents hiding). Own cheaply (tables — codes); default never (200s — outcomes).

**Mentor note** — teach "outcome owns its code" (juniors choosing one status per outcome design default-free APIs on first hearing; 200-everything interrogated ("which class?" — choosing demanding per outcome). Choose one code once (outcomes classifying — codes guiding tangible (defaulting ending — choosing proving permanently). Succeed 2xx; guide 4xx — choosing discipline in three habits, reviewed per outcome.

## 2. Errors mapping (classes coding — remedies stating — reqIds tracing)

**Definition** — error mapping: domain failures translated to envelopes plus statuses at the edge (classes coding — failures classifying (codes typing — remedies prescribing (coding proving — prose declining); remedies stating — actions prescribing (clients recovering — support guiding (stating funding — guessing ending); reqIds tracing — requests correlating (logs joining — incidents tracking (tracing owning — searching declining).

**What problem it solves** — the unmapped trio: *throws bubbling* (errors escaping — statuses defaulting (failures unclassifying — clients guessing (bubbling billing — mapping absenting); *internals traveling* (stacks serializing — queries echoing (details exposing — trust eroding (traveling charging — safety declining); *remedies missing* (errors stating — actions absenting (users stucking — support guessing (missing costing — resolution delaying). Mapped errors converting bubbling to coding (classes classifying — remedies prescribing (reqIds correlating — guesses ending); reviewers exhausting domain errors per edge (mapping proving → verifiable; bubbling → returned).

**Modern guidance** — the mapping lines per failure (review-enforced): *classes coding* (failures classifying — codes typing (remedies prescribing — prose declining (coding proving — bubbling ending (classification owning — guessing declining); *remedies stating* (actions prescribing — clients recovering (support guiding — guessing ending (stating funding — missing refusing (guidance owning — stuckness declining); *reqIds tracing* (requests correlating — logs joining (incidents tracking — searching declining (tracing owning — anonymity ending (correlation funding — MTTR shrinking).

```typescript
// GOOD: errors mapping — exhaustive domain mapping with generic 500 fallback (compiled + run live).
interface Mapped { // classes coding — failures classifying, prose declining
  httpStatus: number;
  code: string;
}
function mapFailure(kind: string): Mapped {
  const table: Record<string, Mapped> = {
    'empty-label': { httpStatus: 400, code: 'invalid-item' },
    'no-such-item': { httpStatus: 404, code: 'item-missing' },
    'taken-seat': { httpStatus: 409, code: 'seat-taken' },
  };
  return table[kind] ?? { httpStatus: 500, code: 'internal-error' }; // 5xx owning — servers answering, leaking declining
}
const a = mapFailure('no-such-item');
const b = mapFailure('taken-seat');
const c = mapFailure('weird-unknown');
console.log(a.httpStatus === 404 && a.code === 'item-missing' && b.httpStatus === 409 && c.httpStatus === 500 && c.code === 'internal-error' ? 'errors map' : 'throws bubble');
```

**Common confusion** — *"mappers hide root causes (translations obscuring)."* Mapping owning contracts (codes classifying — remedies prescribing (callers simplifying — layers keeping (mapping funding — switching declining); debugging joining logs (reqIds correlating — traces capturing (mysteries declining — blindness ending (joining proving — obscuring refusing). "Hiding" describing loss (causes dropping — contexts missing); mapping describing translation (failures classifying — clients guiding). Map contracts (codes classifying — remedies prescribing); join logs (reqIds correlating — traces capturing).

**Performance note** — mapping economics: coding costing one table (failures classifying — remedies prescribing (reqIds correlating — guesses ending); bubbled equivalents costing coupling (callers switching — layers breaking (details deciding — coherence failing). Code cheaply (tables — classes); bubble never (throws — edges).

**Mentor note** — teach "exhaust the domain errors" (juniors mapping one failure per class design bubble-free edges on first hearing; unmapped throws interrogated ("which code?" — mapping demanding per throw). Map one failure once (classes coding — remedies prescribing tangible (bubbling ending — mapping proving permanently). Classify domain; genericize unknown — mapping discipline in three habits, reviewed per edge.

## 3. Problem detailing (types stating — titles summarizing — instances identifying)

**Definition** — problem details (RFC 9457): standard fields typing failures (types stating — kinds identifying (docs linking — versions scoping (stating proving — bespoke declining); titles summarizing — humans reading (phrases stating — jargon declining (summarizing funding — proseing ending); instances identifying — occurrences locating (reqIds tracing — logs joining (identifying owning — searching declining).

**What problem it solves** — the bespoke-error trio: *shapes customizing* (endpoints inventing — clients branching (formats multiplying — parsers bloating (customizing billing — consistency failing); *types missing* (kinds unstated — docs unlinked (failures unclassifying — machines guessing (missing charging — standard declining); *instances missing* (occurrences anonymous — logs unjoinable (requests untraceable — debugging aching (missing costing — MTTR growing). Detailed problems converting bespoke to standard (types identifying — titles summarizing (instances locating — guesses ending); reviewers finding RFC shapes per error (detailing proving → verifiable; customizing → returned).

**Modern guidance** — the detailing lines per failure (review-enforced): *types stating* (kinds identifying — docs linking (versions scoping — bespoke declining (stating proving — customizing refusing (standards owning — invention declining); *titles summarizing* (humans reading — phrases stating (jargon declining — proseing ending (summarizing funding — confusing declining (clarity earning — verbosity declining); *instances identifying* (occurrences locating — reqIds tracing (logs joining — searching declining (identifying owning — anonymity ending (traceability funding — aching ending).

```typescript
// GOOD: problems detailing — RFC-shaped failures with versioned types (compiled + run live).
interface Problem { // types stating — kinds identifying, bespoke declining
  type: string;
  title: string;
  httpStatus: number;
  instance: string;
}
function problem(kind: string, reqId: string): Problem {
  const table: Record<string, Omit<Problem, 'instance'>> = { // titles summarizing — humans reading, proseing ending
    'item-missing': { type: '/v1/problems/item-missing', title: 'No such item', httpStatus: 404 },
    'invalid-item': { type: '/v1/problems/invalid-item', title: 'Item invalid', httpStatus: 400 },
  };
  const found = table[kind] ?? { type: '/v1/problems/internal-error', title: 'Internal error', httpStatus: 500 };
  return { ...found, instance: reqId }; // instances identifying — occurrences locating, searching declining
}
const p = problem('item-missing', 'r-9');
const q = problem('mystery', 'r-10');
console.log(p.httpStatus === 404 && p.instance === 'r-9' && q.type === '/v1/problems/internal-error' ? 'problems detail' : 'shapes bespoke');
```

**Performance note** — detailing economics: stating costing standard fields (kinds identifying — titles summarizing (instances locating — guesses ending); bespoke equivalents costing parsers (formats multiplying — clients branching (consistency failing — maintenance doubling).
