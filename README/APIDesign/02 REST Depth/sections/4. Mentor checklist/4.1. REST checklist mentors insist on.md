# 4.1. REST checklist mentors insist on

## 1. Every resource nouning (collections naming — verbs mapping — actions declining)

**Definition** — the noun gate: each route naming nouns, mapping verbs, declining actions (collections naming — sets owning (items listing — members containing (naming proving — verbing declining); verbs mapping — methods fixing (semantics holding — safety proving (mapping funding — misusing declining); actions declining — operations modeling (jobs owning — paths nouning (declining owning — tunneling ending).

**What problem it solves** — the unnouned trio: *paths verbing* (actions tunneling — methods flattening (semantics losing — caches breaking (verbing billing — resourcing declining); *verbs misusing* (POST everythinging — GET bodying (safety bluffing — visibility declining (misusing charging — guarantees blurring); *actions tunneling* (doX posting — jobs missing (processes hoping — polling guessing (tunneling billing — modeling declining). The gate converting verbing to nouning (collections owning — verbs fixing (actions modeling — tunnels declining); mentors asking one question per route ("which noun, which verb?" — nouning demanding per path).

**Modern guidance** — the gate commands (run per route, enforced in review):

```typescript
// GOOD: nouns gated — collections naming, verbs mapping, actions declining (checklist shape).
// 1. Noun proof (sets owning — items listing):
//    every path noun-first plural — verbs absent, members addressed, nests bounded.
// 2. Verb proof (methods fixing — semantics holding):
//    every route on its verb — GET reading, POST creating, PUT replacing, DELETE removing.
// 3. Action proof (operations modeling — paths nouning):
//    async work as job resources — statuses polling, verbs declining, nouns keeping.
// Name nouns; fix verbs; model jobs.)
```

```typescript
// BAD: resources unnouning — paths verbing, verbs misusing (real unnouned shape).
// POST /v1/getOrders // actions tunneling — methods flattening, semantics losing.
// GET /v1/items { body } // bodies smuggling — visibility declining, intermediaries blinding.
// } // Gate nouns: collections naming, verbs mapping, actions declining.)
```

**Common confusion** — *"gates slow route work (process throttling)."* Gates preventing tunnels (nouns naming — verbs mapping (semantics holding — caches funding (preventing funding — throttling declining); missing gates slowing debugging (paths verbing — methods flattening (semantics losing — clients confusing (missing charging — writing declining). "Throttling" describing ceremony (approvals queuing — value missing); gates describing leverage (proof reusing — tunnels preventing). Gate nouns (collections naming — verbs mapping); ship faster (semantics holding — clients trusting).

**Performance note** — noun economics: naming costing plurals (sets owning — members locating (caching funding — guessing declining); verbed equivalents costing cacheability (methods flattening — semantics losing (caching breaking — intermediaries blinding). Name cheaply (nouns — paths); verb never (actions — tunnels).

**Mentor note** — demand "noun and verb per route" (juniors nouning one resource per path design tunnel-proof reviews on first hearing; verbed paths interrogated ("which noun?" — nouning demanding per route). Noun one path once (collections naming — verbs mapping tangible (verbing ending — nouning proving permanently). Name collections; map verbs — nouning discipline in three habits, reviewed per route.

## 2. Every status meaning (codes choosing — errors mapping — details stating)

**Definition** — the meaning gate: each outcome owning codes, mapping errors, stating details (codes choosing — outcomes classifying (behaviors guiding — defaults refusing (choosing proving — guessing ending); errors mapping — failures translating (remedies prescribing — reqIds correlating (mapping funding — bubbling declining); details stating — kinds identifying (titles summarizing — instances locating (stating owning — bespoke declining).

**What problem it solves** — the unmeaning trio: *codes defaulting* (200 answering — errors hiding (success parsing — failures missing (defaulting billing — contracts breaking); *errors bubbling* (throws escaping — internals traveling (failures unclassifying — trust eroding (bubbling billing — mapping absenting); *details bespeaking* (endpoints inventing — types missing (formats multiplying — parsers bloating (bespeaking charging — consistency failing). The gate converting defaulting to choosing (outcomes classifying — errors mapping (details stating — guesses ending); mentors asking one question per outcome ("which code, which type?" — meaning demanding per failure).

**Modern guidance** — the gate commands (run per outcome, enforced in review):

```typescript
// GOOD: meaning gated — codes choosing, errors mapping, details stating (checklist shape).
// 1. Code proof (outcomes classifying — behaviors guiding):
//    every outcome mapped to its status — 2xx succeeding, 4xx guiding, 5xx owning.
// 2. Error proof (failures translating — remedies prescribing):
//    every failure enveloped with code, remedy, reqId — prose absenting, parsers slimming.
// 3. Detail proof (kinds identifying — instances locating):
//    every error carrying RFC type, title, instance — bespoke declining, standards owning.
// Choose codes; map errors; state details.)
```

```typescript
// BAD: statuses unmeaning — codes defaulting, errors bubbling (real unmeaning shape).
// res.json({ ok: false }); // errors succeeding — failures hiding, success parsing-failing.
// throw err; // failures unclassifying — clients guessing, mapping absenting.
// } // Gate meaning: codes choosing, errors mapping, details stating.)
```

**Common confusion** — *"gates police HTTP trivia (codes tyrannizing)."* Gates evidencing contracts (codes choosing — errors mapping (proof reusing — judgment focusing (evidencing funding — slowing declining); policing punishing trivia (styles enforcing — meaning ignoring (punishing serving — value missing (policing charging — morale declining). "Policing" describing punishment (trivia enforcing — meaning ignoring); gates describing evidence (contracts proving — trust earning). Evidence contracts (codes choosing — errors mapping); punish never (trivia enforcing — morale declining).

**Performance note** — meaning economics: choosing costing tables (outcomes classifying — behaviors guiding (servers answering — leaks declining); defaulted equivalents costing parsing (success guessing — failures missing (machines branching — incidents hiding). Choose cheaply (tables — codes); default never (200s — outcomes).

**Mentor note** — demand "code, envelope, type per failure" (juniors choosing one status per outcome design default-free reviews on first hearing; unmapped failures interrogated ("which code?" — meaning demanding per throw). Choose one outcome once (codes choosing — errors mapping tangible (defaulting ending — meaning proving permanently). Classify outcomes; map failures — meaning discipline in three habits, reviewed per outcome.

## 3. Every read paging (cursors anchoring — filters scoping — sorts stabilizing)

**Definition** — the paging gate: each collection anchoring cursors, scoping filters, stabilizing sorts (cursors anchoring — positions holding (inserts surviving — duplicates declining (anchoring proving — offsetting ending); filters scoping — fields allowlisting (operators validating — indexes serving (scoping funding — passing declining); sorts stabilizing — keys ordering (ties breaking — pages freezing (stabilizing owning — shuffling declining).

**What problem it solves** — the unpaged trio: *reads wholing* (lists returning — stores straining (memory bloating — timeouts scheduling (wholing billing — policy declining); *filters passing* (strings concatenating — injections inviting (inputs trusting — breaches scheduling (passing billing — validation missing); *sorts shuffling* (ties unbreaking — pages duplicating (orders nondeterministic — trust eroding (shuffling charging — stability bluffing). The gate converting wholing to paging (cursors holding — filters bounding (sorts freezing — strain declining); mentors asking one question per collection ("which cursor, which filter?" — paging demanding per read).

**Modern guidance** — the gate commands (run per collection, enforced in review):

```typescript
// GOOD: paging gated — cursors anchoring, filters scoping, sorts stabilizing (checklist shape).
// 1. Cursor proof (positions holding — inserts surviving):
//    every collection paged by opaque cursor — offsets declining, duplicates absenting, limits capping.
// 2. Filter proof (fields allowlisting — operators validating):
//    every filter allowlisted with validated operators — strings declining, injections preventing.
// 3. Sort proof (keys ordering — ties breaking):
//    every sort explicit with id tiebreak — pages freezing, shuffles declining, runs repeating.
// Anchor cursors; scope filters; stabilize sorts.)
```

```typescript
// BAD: reads unpaging — lists wholing, filters passing (real unpaged shape).
// GET /v1/items // stores straining — memory bloating, timeouts scheduling.
// ?filter=<raw SQL-ish> // inputs trusting — breaches scheduling, validation missing.
// } // Gate paging: cursors anchoring, filters scoping, sorts stabilizing.)
```

**Common confusion** — *"gates over-engineer reads (checks bureaucratizing)."* Gates evidencing discipline (cursors anchoring — filters scoping (proof reusing — judgment focusing (evidencing funding — slowing declining); bureaucratizing padding ceremony (forms multiplying — value missing (swaps unnamed — comprehension taxing (padding charging — judgment absenting). "Bureaucratizing" describing ceremony (forms multiplying — value missing); gates describing evidence (discipline proving — trust earning). Evidence discipline (cursors anchoring — filters scoping); pad never (forms multiplying — value missing).

**Performance note** — paging economics: anchoring costing cursors (positions holding — stores sparing (timeouts preventing — strain declining); wholed equivalents costing memory (lists returning — stores straining (timeouts scheduling — policy declining). Anchor cheaply (cursors — keys); whole never (lists — reads).

**Mentor note** — demand "cursor, filter, sort per collection" (juniors paging one collection per cursor design strain-proof reviews on first hearing; unpaged collections interrogated ("which cursor?" — paging demanding per read). Page one read once (cursors anchoring — filters scoping tangible (wholing ending — paging proving permanently). Hold positions; bound filters — paging discipline in three habits, reviewed per collection.
