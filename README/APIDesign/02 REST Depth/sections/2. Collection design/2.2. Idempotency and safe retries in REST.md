# 2.2. Idempotency and safe retries in REST

## 1. Methods safing (GET HEAD OPTIONS reading — bodies declining — caches trusting)

**Definition** — method safety: safe methods changing nothing (GET HEAD OPTIONS reading — resources fetching (metadata heading — capabilities discovering (reading proving — writing declining); bodies declining — payloads refusing (queries URLing — caches keying (declining funding — smuggling ending); caches trusting — responses storing (intermediaries serving — origins resting (trusting earning — bypassing declining).

**What problem it solves** — the unsafe-read trio: *GETs mutating* (reads writing — counters incrementing (sides effecting — caches poisoning (mutating billing — safety bluffing); *bodies smuggling* (queries hiding — caches varying (visibility declining — intermediaries blinding (smuggling charging — keying breaking); *caches bypassing* (responses recomputing — origins straining (trust missing — latency growing (bypassing billing — performance declining). Safe methods converting mutating to reading (queries answering — bodies declining (caches trusting — sides pure); reviewers proving read-only handlers per safe route (safing proving → verifiable; mutating → returned).

**Modern guidance** — the safing lines per method (review-enforced): *GET HEAD OPTIONS reading* (resources fetching — metadata heading (capabilities discovering — writing declining (reading proving — mutating refusing (safety owning — effect declining); *bodies declining* (payloads refusing — queries URLing (caches keying — smuggling ending (declining funding — hiding refusing (visibility earning — blindness declining); *caches trusting* (responses storing — intermediaries serving (origins resting — bypassing declining (trusting earning — recomputing ending (hits funding — misses measuring).

```typescript
// GOOD: methods safing — safety matrix asserting read-only safe verbs (compiled + run live).
interface Semantics { // GET HEAD OPTIONS reading — resources fetching, writing declining
  safe: boolean;
  readsBody: boolean;
}
const methods: Record<string, Semantics> = {
  GET: { safe: true, readsBody: false },
  HEAD: { safe: true, readsBody: false },
  OPTIONS: { safe: true, readsBody: false },
  POST: { safe: false, readsBody: true },
  PUT: { safe: false, readsBody: true },
  DELETE: { safe: false, readsBody: false },
};
function cacheOk(method: string): boolean { // caches trusting — responses storing, bypassing declining
  const m = methods[method];
  return m !== undefined && m.safe && !m.readsBody;
}
console.log(cacheOk('GET') && cacheOk('HEAD') && cacheOk('OPTIONS') && !cacheOk('POST') && !cacheOk('DELETE') ? 'methods safe' : 'reads mutate');
```

// GET /v1/hit { counter++ } // sides effecting — caches poisoning, safety bluffing.
// GET /v1/search { body: {...} } // queries hiding — intermediaries blinding, visibility declining.
// } // Safe methods: reads answering, bodies declining, caches trusting.)

**Common confusion** — *"safe means idempotent (properties equating)."* Safe changing nothing (reads answering — sides pure (caches trusting — repeats serving (safety proving — effecting declining); idempotent repeating safely (retries trusting — effects holding (storms surviving — doubles billing (idempotency funding — doubling declining). "Equating" describing confusion (properties merging — guarantees blurring); safety describing reads (effects absenting — caches trusting). Read safely (effects absenting — caches trusting); repeat idempotently (retries trusting — effects holding).

**Performance note** — safing economics: reading costing purity (sides pure — caches trusting (origins resting — latency sparing); mutated equivalents costing poison (sides effecting — caches bypassing (trust missing — recomputing billing). Read cheaply (safe — cacheable); mutate never (GETs — sides).

**Mentor note** — teach "safe changes nothing" (juniors proving one read-only handler per safe route design poison-proof caches on first hearing; mutating GETs interrogated ("what changed?" — safing demanding per route). Safe one method once (reads answering — bodies declining tangible (mutating ending — safety proving permanently). Answer reads; refuse bodies — safing discipline in three habits, reviewed per route.

## 2. Keys idempotenting (headers carrying — replays detecting — effects holding)

**Definition** — HTTP idempotency keys: client-generated intent keys carried in headers, server remembering outcomes (headers carrying — intents identifying (callers generating — determinism owning (carrying proving — anonymity declining); replays detecting — seen returning (effects skipping — responses identical (detecting funding — doubling declining); effects holding — sides applying-once (storms surviving — trust earning (holding owning — multiplying declining).

**What problem it solves** — the naked-POST trio: *retries doubling* (timeouts reposting — charges duplicating (clients retrying — servers re-executing (doubling billing — trust eroding); *keys missing* (intents anonymous — replays undetectable (anonymity owning — safety declining (missing charging — guarding absenting); *storms amplifying* (bursts retrying — effects compounding (loads multiplying — outages cascading (amplifying billing — capacity dying). Keyed POSTs converting doubling to holding (headers identifying — replays returning (effects once-applying — storms surviving); reviewers finding key handling per mutating route (idempotenting proving → verifiable; naked → returned).

**Modern guidance** — the keying lines per mutating route (review-enforced): *headers carrying* (intents identifying — callers generating (determinism owning — anonymity declining (carrying proving — missing refusing (keys owning — guesses declining); *replays detecting* (seen returning — effects skipping (responses identical — doubling declining (detecting funding — reprocessing ending (dedupe owning — storms surviving); *effects holding* (sides applying-once — storms surviving (trust earning — multiplying declining (holding proving — compounding refusing (once owning — twice declining).

```typescript
// GOOD: keys idempotenting — Idempotency-Keyed POSTs applying once, replaying stored (compiled + run live).
class KeyedPosts { // headers carrying — intents identifying, anonymity declining
  private readonly seen = new Map<string, string>();
  private charges = 0;
  post(key: string, amount: number): string {
    const known = this.seen.get(key);
    if (known !== undefined) return known; // replays detecting — seen returning, doubling declining
    if (key.length === 0) throw new Error('key required');
    this.charges += amount;
    const receipt = `ok:${this.charges}`;
    this.seen.set(key, receipt);
    return receipt; // effects holding — sides applying-once, storms surviving
  }
}
const api = new KeyedPosts();
const first = api.post('k-1', 50);
const replay = api.post('k-1', 50); // timed-out client retrying — effect skipping, response identical
console.log(first === 'ok:50' && replay === 'ok:50' ? 'keys idempotent' : 'posts double');
```

**Common confusion** — *"keys replace validation (headers substituting)."* Keys identifying intents (callers generating — determinism owning (replays detecting — effects holding (identifying funding — doubling declining); validation proving shapes (bodies checking — garbage declining (handlers assuming — corruption preventing (proving serving — skipping declining). "Replacing" describing substitution (shapes unchecking — garbage entering); keys describing intent (callers generating — replays detecting). Identify intents (headers carrying — determinism owning); validate bodies (shapes checking — garbage declining).

**Performance note** — keying economics: carrying costing one lookup (intents identifying — replays detecting (effects holding — storms surviving); naked equivalents costing doubles (clients retrying — servers re-executing (charges duplicating — trust eroding). Carry cheaply (keys — headers); double never (retries — charges).

**Mentor note** — teach "mutating POSTs carry keys" (juniors keying one intent per retryable call design double-proof APIs on first hearing; keyless mutations interrogated ("which key?" — idempotenting demanding per route). Key one intent once (headers carrying — replays detecting tangible (naked ending — holding proving permanently). Generate callerside; remember serverside — keying discipline in three habits, reviewed per mutation.

## 3. Retries judging (networks retrying — budgets bounding — storms surviving)

**Definition** — retry judgment: which failures retry with what budgets and backoff (networks retrying — timeouts reposting (errors classifying — verdicts owning (retrying proving — hoping ending); budgets bounding — attempts capping (delays backing-off (jitter spreading — thundering declining (bounding funding — amplifying ending); storms surviving — bursts absorbing (outcomes steadying — capacity budgeting (surviving owning — collapsing declining).

**What problem it solves** — the retry-all trio: *failures unclassifying* (errors retrying — fatals looping (verdicts missing — storms amplifying (unclassifying billing — capacity dying); *budgets missing* (attempts unbounded — delays fixed (thunder stampeding — outages cascading (missing charging — backoff absenting); *idempotency ignoring* (non-idempotent retrying — effects doubling (safety declining — trust eroding (ignoring costing — doubling scheduling). Judged retries converting all to budgeted (errors classifying — attempts capping (idempotency requiring — storms surviving); reviewers seeing retry tables per client (judging proving → verifiable; retrying-all → returned).

**Modern guidance** — the judging lines per client (review-enforced): *networks retrying* (timeouts reposting — errors classifying (verdicts owning — hoping ending (retrying proving — giving-up refusing (resilience funding — fragility declining); *budgets bounding* (attempts capping — delays backing-off (jitter spreading — thundering declining (bounding funding — amplifying ending (limits owning — storms surviving); *storms surviving* (bursts absorbing — outcomes steadying (capacity budgeting — collapsing declining (surviving owning — dying preventing (absorption funding — cascade declining).

```typescript
// GOOD: retries judging — classified verdicts with capped budgets and jitter (compiled + run live).
type Verdict = 'retry' | 'wait-retry' | 'give-up';
function judge(kind: string, attempt: number): Verdict { // networks retrying — timeouts reposting, hoping ending
  if (attempt > 3) return 'give-up'; // budgets bounding — attempts capping, amplifying ending
  if (kind === 'timeout' || kind === 'unavailable') return attempt === 1 ? 'retry' : 'wait-retry';
  return 'give-up'; // fatals declining — verdicts owning, storms surviving
}
const v = [judge('timeout', 1), judge('timeout', 2), judge('timeout', 5), judge('invalid', 1)];
console.log(v.join(',') === 'retry,wait-retry,give-up,give-up' ? 'retries judge' : 'clients storm');
```

**Common confusion** — *"more retries mean reliability (persistence equaling)."* Retries reposting requests (timeouts retrying — errors classifying (resilience funding — fragility declining (reposting proving — giving-up refusing); reliability composing budgets (attempts capping — idempotency requiring (storms surviving — capacity budgeting (composing funding — storming declining). "More" describing quantity (attempts multiplying — storms amplifying); reliability describing judgment (errors classifying — budgets bounding). Classify failures (verdicts owning — storms surviving); cap attempts (budgets bounding — thunder declining).

**Performance note** — judging economics: bounding costing verdicts (errors classifying — attempts capping (storms surviving — capacity budgeting); stormed equivalents costing cascades (attempts unbounded — thunder stampeding (outages cascading — capacity dying). Judge cheaply (verdicts — tables); storm never (retries — budgets).

**Mentor note** — teach "retry table per client" (juniors judging one verdict per failure design storm-proof clients on first hearing; retry-all interrogated ("which budget?" — judging demanding per client). Classify errors; bound attempts — judging discipline in three habits, reviewed per client.
