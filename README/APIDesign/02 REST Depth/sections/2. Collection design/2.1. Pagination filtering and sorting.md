# 2.1. Pagination filtering and sorting

## 1. Pages shaping (cursors anchoring — limits capping — totals skipping)

**Definition** — cursor pages: opaque anchors over stable sort keys with capped limits (cursors anchoring — positions holding (inserts surviving — duplicates declining (anchoring proving — offsetting ending); limits capping — sizes bounding (stores sparing — timeouts preventing (capping funding — unbounded declining); totals skipping — counts omitting (expensive avoiding — pages terminating-null (skipping owning — counting declining).

**What problem it solves** — the offset trio: *offsets drifting* (inserts shifting — items skipping (duplicates arriving — pages lying (drifting billing — stability bluffing); *pages unbounding* (limits missing — stores straining (memory bloating — timeouts scheduling (unbounding charging — policy declining); *totals counting* (counts scanning — queries slowing (expensive funding — value questioning (counting billing — latency growing). Shaped pages converting drifting to anchoring (cursors holding — limits bounding (totals skipping — null terminating); reviewers finding cursor params per collection (shaping proving → verifiable; offsetting → returned).

**Modern guidance** — the shaping lines per collection (review-enforced): *cursors anchoring* (positions holding — inserts surviving (duplicates declining — offsetting ending (anchoring proving — counting refusing (stability owning — drift preventing); *limits capping* (sizes bounding — stores sparing (timeouts preventing — unbounded declining (capping funding — missing refusing (bounds owning — strain declining); *totals skipping* (counts omitting — expensive avoiding (pages terminating-null — counting declining (skipping owning — scanning refusing (thrift funding — latency sparing).

```typescript
// GOOD: pages shaping — cursor-anchored pages stable across mid-read inserts (compiled + run live).
interface Row {
  id: number;
}
function page(rows: Row[], after: number, limit: number): { items: number[]; next: number | null } {
  const capped = Math.min(limit, 100); // limits capping — sizes bounding, unbounded declining
  const items = rows.filter((r) => r.id > after).slice(0, capped); // cursors anchoring — positions holding, inserts surviving
  const ids = items.map((r) => r.id);
  return { items: ids, next: items.length === capped ? ids[ids.length - 1] : null }; // totals skipping — null terminating, counting declining
}
let rows: Row[] = [{ id: 1 }, { id: 2 }, { id: 3 }, { id: 4 }];
const p1 = page(rows, 0, 2);
rows = [...rows.slice(0, 2), { id: 99 }, ...rows.slice(2)]; // insert landing mid-read — stability proving, drift declining
const p2 = page(rows, p1.next as number, 10);
const seen = [...p1.items, ...p2.items];
const dupes = seen.length !== new Set(seen).size;
console.log(p1.items.join(',') === '1,2' && !dupes && seen.includes(99) ? 'pages shape' : 'offsets drift');
```

```typescript
// BAD: pages offsetting — skips counting, inserts shifting (real offset shape).
// SELECT ... LIMIT 20 OFFSET 40 // inserts shifting — items skipping, duplicates arriving.
// // Unbounded limit (stores straining — timeouts scheduling). Anchor cursors; cap limits; skip totals.)
```

**Common confusion** — *"cursors complicate clients (opacity burdening)."* Cursors simplifying resumption (positions holding — inserts surviving (stability owning — drift preventing (simplifying funding — offsetting ending); burden complicating flows (steps multiplying — value missing (complexity charging — patience taxing (burdening serving — simplicity declining). "Burdening" describing complexity (steps multiplying — value missing); cursors describing stability (anchors holding — duplicates declining). Anchor positions (cursors holding — inserts surviving); burden never (complexity multiplying — value missing).

**Performance note** — shaping economics: anchoring costing key comparisons (positions holding — stores sparing (timeouts preventing — strain declining); offsetted equivalents costing scans (skips degrading — duplicates arriving (stability bluffing — latency growing). Anchor cheaply (cursors — keys); offset never (skips — scans).

**Mentor note** — teach "cursor, cap, null" (juniors shaping one page per cursor design drift-proof collections on first hearing; offset params interrogated ("stable under inserts?" — shaping demanding per collection). Shape one page once (cursors anchoring — limits capping tangible (offsetting ending — shaping proving permanently). Anchor positions; cap sizes — shaping discipline in three habits, reviewed per collection.

## 2. Filters scoping (fields selecting — queries bounding — indexes serving)

**Definition** — filter scoping: allowlisted fields with validated operators backed by indexes (fields selecting — allowlists owning (clients choosing — servers permitting (selecting proving — passing declining); queries bounding — operators validating (ranges limiting — combinations capping (bounding funding — exploding declining); indexes serving — plans using (scans declining — latency bounding (serving owning — hoping ending).

**What problem it solves** — the open-filter trio: *queries passing through* (strings concatenating — injections inviting (inputs trusting — breaches scheduling (passing billing — validation missing); *fields unbounding* (columns exposing — internals leaking (access hoping — authorization bypassing (unbounding charging — safety declining); *indexes missing* (filters scanning — tables locking (latency growing — timeouts scheduling (missing costing — performance bluffing). Scoped filters converting passing to selecting (fields allowlisting — operators validating (indexes serving — injections declining); reviewers allowlisting fields per collection (scoping proving → verifiable; passing → returned).

**Modern guidance** — the scoping lines per filter (review-enforced): *fields selecting* (allowlists owning — clients choosing (servers permitting — passing declining (selecting proving — exposing refusing (lists owning — columns hiding); *queries bounding* (operators validating — ranges limiting (combinations capping — exploding declining (bounding funding — passing refusing (bounds owning — injection declining); *indexes serving* (plans using — scans declining (latency bounding — hoping ending (serving owning — missing refusing (performance funding — bluffing declining).

```typescript
// GOOD: filters scoping — allowlisted fields with validated operators, unknowns rejected (compiled + run live).
type Op = 'eq' | 'gt' | 'in';
const allowed: Record<string, Op[]> = { // fields selecting — allowlists owning, passing declining
  level: ['eq', 'in'],
  score: ['eq', 'gt'],
};
function apply(rows: Array<Record<string, number>>, field: string, op: Op, val: number | number[]): number[] {
  if (!(field in allowed) || !allowed[field].includes(op)) throw new Error(`rejected:${field}:${op}`); // queries bounding — operators validating, exploding declining
  if (op === 'eq') return rows.filter((r) => r[field] === val).map((r) => r[field]);
  if (op === 'gt') return rows.filter((r) => r[field] > (val as number)).map((r) => r[field]);
  return rows.filter((r) => (val as number[]).includes(r[field])).map((r) => r[field]); // indexes serving — plans using, hoping ending
}
const rows = [{ level: 1, score: 9 }, { level: 2, score: 4 }];
let rejected = 0;
try { apply(rows, 'password', 'eq', 1); } catch { rejected += 1; }
try { apply(rows, 'score', 'in', [1]); } catch { rejected += 1; }
console.log(apply(rows, 'score', 'gt', 5).join(',') === '9' && rejected === 2 ? 'filters scope' : 'queries pass');
```

```typescript
// // Unindexed columns (filters scanning — latency growing). Allowlist fields; validate operators; serve indexes.)
```

**Common confusion** — *"allowlists limit power users (lists constraining)."* Allowlists scoping access (fields permitting — servers owning (clients choosing — passing declining (scoping proving — exposing refusing); power serving needs (operators validating — indexes funding (queries answering — users trusting (serving owning — constraining declining). "Limiting" describing refusal (needs declining — users frustrating); scoping describing safety (fields permitting — injections declining). Permit explicitly (allowlists owning — clients choosing); pass never (strings concatenating — breaches scheduling).

**Performance note** — scoping economics: allowlisting costing lists (fields permitting — operators validating (injections declining — latency bounding); passed equivalents costing breaches (inputs trusting — filters scanning (latency growing — safety declining). Scope cheaply (lists — fields); pass never (strings — queries).

**Mentor note** — teach "allowlist, operator, index" (juniors scoping one filter per allowlist design injection-proof collections on first hearing; raw query params interrogated ("which allowlist?" — scoping demanding per filter). Scope one field once (fields selecting — operators validating tangible (passing ending — scoping proving permanently). List fields; bound operators — scoping discipline in three habits, reviewed per filter.

## 3. Sorts stabilizing (keys ordering — ties breaking — pages freezing)

**Definition** — stable sorting: explicit keys with unique tiebreaks frozen per pagination (keys ordering — fields stating (directions owning — ambiguity declining (ordering proving — guessing ending); ties breaking — ids deciding (duplicates preventing — pages stabilizing (breaking funding — drifting declining); pages freezing — sorts persisting (params echoing — runs repeating (freezing owning — shifting declining).

**What problem it solves** — the unstable-sort trio: *ties unbreaking* (equals shuffling — pages duplicating (orders nondeterministic — items repeating (unbreaking billing — stability bluffing); *sorts hiding* (orders assuming — params missing (directions hoping — clients guessing (hiding charging — ambiguity growing); *runs shifting* (sorts changing — pages sliding (cursors invalidating — reads corrupting (shifting billing — freezing absenting). Stabilized sorts converting shuffling to breaking (keys ordering — ties deciding (pages freezing — duplicates declining); reviewers finding tiebreaks per sort (stabilizing proving → verifiable; shuffling → returned).

**Modern guidance** — the stabilizing lines per sort (review-enforced): *keys ordering* (fields stating — directions owning (ambiguity declining — guessing ending (ordering proving — hoping refusing (explicit owning — implicit declining); *ties breaking* (ids deciding — duplicates preventing (pages stabilizing — drifting declining (breaking funding — shuffling ending (determinism owning — nondeterminism refusing); *pages freezing* (sorts persisting — params echoing (runs repeating — shifting declining (freezing funding — sliding ending (stability owning — corruption declining).

```typescript
// GOOD: sorts stabilizing — explicit keys with id tiebreaks, pages frozen (compiled + run live).
interface Item { // keys ordering — fields stating, guessing ending
  total: number;
  id: string;
}
function ordered(items: Item[]): string[] {
  return [...items]
    .sort((a, b) => b.total - a.total || (a.id < b.id ? -1 : 1)) // ties breaking — ids deciding, duplicates preventing
    .map((i) => i.id);
}
const items: Item[] = [
  { total: 9, id: 'c' },
  { total: 9, id: 'a' },
  { total: 20, id: 'b' },
];
const run1 = ordered(items).join(',');
const run2 = ordered([...items].reverse()).join(','); // pages freezing — sorts persisting, shifting declining
console.log(run1 === 'b,a,c' && run2 === 'b,a,c' ? 'sorts stabilize' : 'ties shuffle');
```

```typescript
// BAD: sorts unstabling — ties unbreaking, runs shifting (real unstable shape).
// ORDER BY total // equals shuffling — pages duplicating, stability bluffing.
// // Sort params missing (directions hoping — clients guessing). Order keys; break ties; freeze pages.)
```

**Common confusion** — *"tiebreaks overcomplicate sorts (keys multiplying)."* Tiebreaks determining order (ids deciding — duplicates preventing (pages stabilizing — drifting declining (determining funding — shuffling ending); complicating padding ceremony (keys multiplying — value missing (sorts confusing — clarity declining (complicating charging — judgment absenting). "Overcomplicating" describing ceremony (keys multiplying — value missing); tiebreaks describing determinism (ids deciding — duplicates preventing). Break ties (ids deciding — pages stabilizing); multiply never (keys confusing — clarity declining).

**Performance note** — stabilizing economics: breaking costing one key (ids deciding — duplicates preventing (pages stabilizing — drifting declining); shuffled equivalents costing duplicates (equals shuffling — pages duplicating (stability bluffing — trust eroding). Break cheaply (keys — ties); shuffle never (equals — pages).

**Mentor note** — teach "sort key plus id, always" (juniors stabilizing one sort per tiebreak design shuffle-proof pages on first hearing; tiebreakless sorts interrogated ("ties by what?" — stabilizing demanding per sort). Stabilize one sort once (keys ordering — ties breaking tangible (shuffling ending — stabilizing proving permanently). Order explicitly; freeze params — stabilizing discipline in three habits, reviewed per sort.
