# 5.1. Common interview QA choosing and unifying

## 1. Choices live under pressure (needs, prices, defaults — diagnosed with fixes, priced)

**Definition** — choice answers: needs stating, prices attaching, defaults refusing — under pressure (diagnosed with fixes — causes naming (understanding proving — reciting declining); priced with trade-offs — costs owning (judgment funding — dogma refusing (pricing earning — honesty proving).

**What problem it solves** — the reciting trio: *stacks listing* ("we use X" naming — needs missing (vocabulary showing — matching absenting (reciting funding — designing declining); *prices hiding* (costs unstated — reversals unowned (surprises scheduling — pivots dreading (hiding charging — honesty declining); *defaults following* (fashion reciting — pilots skipping (evidence bluffing — independence dying (following billing — reasoning declining). Diagnosed answers converting reciting to justifying (causes naming — fixes stating (needs meeting — prices attaching); interviewers hiring justifiers, not listers (diagnosing proving → hirable; reciting → passed).

**Modern guidance** — answer shape per choice question (diagnose → fix → price):

```typescript
// GOOD: "Which API style?" — diagnosed with fixes, priced (answer shape).
// Diagnose: default stacks (needs unmatching — experiences degrading — judgment missing).
// Fix: needs matching (workloads stating — styles fitting — experiences funding).
// Price: trade-offs judging (costs pricing — reversals naming — vibes declining).
// State needs; attach prices — pressure stated, not hoped.)
```

```typescript
// BAD: choices reciting — stacks listing, prices hiding (real weak shape).
// "REST, obviously." (needs mismatching — experiences degrading — designing declining).
// "GraphQL is modern." (pilots skipping — evidence bluffing — reasoning declining).
// Diagnose workloads; state options; price reversals.)
```

**Common confusion** — *"choice answers need confidence (asserting impressing)."* Confidence asserting picks (conviction stating — doubt hiding (picks owning — evidence missing (asserting serving — proving declining (confidence funding — bluffing risking); answers proving judgment (causes naming — fixes stating (costs pricing — trade-offs owning (proving funding — reciting declining). "Confidence" describing assertion (picks stating — doubt hiding); answers describing justification (needs meeting — prices attaching). Diagnose workloads (causes naming — fixes stating); justify picks (needs meeting — prices attaching).

**Performance note** — answer economics: diagnosing costing one cause per question (understanding proving — reciting declining (hirable funding — chanting ending); recited equivalents costing offers (words owning — needs missing (designing declining — hiring passing). Diagnose cheaply (causes — fixes); recite never (stacks — passes).

**Mentor note** — drill "diagnose, fix, price" (juniors answering one choice question per shape design hirable responses on first hearing; stack-only answers interrogated ("which need?" — diagnosing demanding per answer). Shape one answer once (causes naming — fixes stating tangible (reciting ending — designing proving permanently). State workloads; fund experiences — answering discipline in three habits, reviewed per mock.

## 2. Unifying live under pressure (BFFs, gateways, composition — honesty stated, not hoped)

**Definition** — unifying answers: BFFs shaping, gateways owning, composition proving — honestly (honesty stating — views owning (entries proving — aggregates asserting (stating funding — hoping ending); clients serving (screens shaping — payloads bounding (experiences funding — compromises declining (serving proving — genericing refusing).

**What problem it solves** — the single-gateway trio: *entries multiplying* (gateways spawning — routes duplicating (ownership blurring — maintenance doubling (multiplying billing — unifying declining); *views genericing* (APIs compromising — payloads dumping (mobiles choking — experiences degrading (genericing billing — shaping declining); *composition hoping* (aggregations assuming — shapes unchecking (tests missing — clients discovering (hoping charging — trust eroding). Honest answers converting multiplying to owning (entries proving — views shaping (aggregates asserting — hopes ending); interviewers hiring owners, not multipliers (owning proving → hirable; multiplying → passed).

**Modern guidance** — answer shape per unifying question (own → shape → prove):

```typescript
// GOOD: "Mobile plus web plus partners?" — owned, shaped, proven (answer shape).
// Own: entries proving (routes aggregating — versions scoping — scattering declining).
// Shape: views serving (screens shaping — payloads bounding — experiences funding).
// Prove: aggregates asserting (shapes checking — statuses guiding — responses proving).
// Own entries; shape views — honesty stated, not hoped.)
```

```typescript
// BAD: unifying hoping — entries multiplying, composition assuming (real scattered shape).
// "One gateway routes all." (routes duplicating — ownership blurring — maintenance doubling).
// "Clients adapt." (payloads dumping — experiences degrading — shaping declining).
// Own paths; serve views; assert shapes.)
```

**Common confusion** — *"honesty means hedging scale (hedges performing)."* Honesty owning entries (routes aggregating — versions scoping (views shaping — aggregates asserting (owning proving — hoping ending); hedging dodging numbers (answers qualifying — clarity declining (dodging serving — hiring passing (hedging charging — precision missing). "Hedging" describing dodge (numbers avoiding — clarity declining); honesty describing ownership (entries proving — views shaping). Own paths (routes aggregating — versions scoping); dodge never (numbers avoiding — clarity declining).

**Performance note** — honesty economics: owning costing entries (routes aggregating — versions scoping (views shaping — aggregates asserting); multiplied equivalents costing duplication (gateways spawning — routes duplicating (ownership blurring — maintenance doubling). Own cheaply (entries — paths); multiply never (gateways — routes).

**Mentor note** — drill "own, shape, prove" (juniors answering one unifying question per shape design hirable responses on first hearing; one-gateway answers interrogated ("which view?" — honesty demanding per entry). Shape one answer once (entries owning — views shaping tangible (multiplying ending — owning proving permanently). Aggregate routes; assert shapes — unifying discipline in three habits, reviewed per mock.

## 3. Operations live under pressure (auth, limits, versions — ownership stated, not hoped)

**Definition** — operations answers: auth verifying, limits throttling, versions scoping — ownership stated (edges owning — budgets bounding (releases numbering — breaches declining (owning proving — hoping ending); not hoped (runs asserting — meters reading (dates stating — wishing ending (stating serving — hoping declining).

**What problem it solves** — the open-edge trio: *auth scattering* (handlers branching — logic scattering (audits missing — consistency failing (scattering billing — ownership blurring); *limits missing* (rates uncapped — floods arriving (servers crushing — legit starving (missing charging — policy declining); *versions mixing* (releases unnumbering — clients breaking (surprises scheduling — trust eroding (mixing billing — clarity declining). Owned answers converting scattering to verifying (auth checking — limits capping (versions numbering — breaches declining); interviewers hiring owners, not openers (verifying proving → hirable; scattering → passed).

**Modern guidance** — answer shape per operations question (verify → throttle → scope):

```typescript
// GOOD: "Secure and scale it?" — verified, throttled, scoped (answer shape).
// Verify: auth checking (tokens verifying — scopes bounding — intrusions declining).
// Throttle: limits capping (rates bounding — bursts queuing — fairness funding).
// Scope: versions numbering (breaking bumping — additives flowing — surprises declining).
// Check tokens; cap rates — ownership stated, not hoped.)
```

```typescript
// BAD: operations hoping — auth scattering, limits missing (real open shape).
// "Auth later." (handlers branching — audits missing — consistency failing).
// "Scale when needed." (rates uncapped — floods arriving — policy declining).
// Verify edges; throttle keys; scope releases.)
```

**Common confusion** — *"operations answers test DevOps titles (roles impressing)."* Titles labeling teams (roles stating — duties listing (labeling serving — owning missing (titling funding — deciding declining); answers proving ownership (auth verifying — limits throttling (versions scoping — breaches declining (proving funding — hoping ending). "Titles" describing orgs (teams labeling — duties listing); answers describing edges (auth checking — limits capping). State edges (auth verifying — limits throttling); title never (teams labeling — duties listing).

**Performance note** — operations economics: owning costing edges (auth checking — limits capping (versions scoping — breaches declining); scattered equivalents costing incidents (handlers branching — floods arriving (audits missing — servers crushing). Own cheaply (edges — gates); scatter never (auth — handlers).

**Mentor note** — drill "verify, throttle, scope" (juniors answering one operations question per shape design ownership-stated responses on first hearing; later-answers interrogated ("which edge?" — owning demanding per route). Shape one answer once (auth verifying — limits throttling tangible (scattering ending — owning proving permanently). Guard entries; number releases — operations discipline in three habits, reviewed per mock.
