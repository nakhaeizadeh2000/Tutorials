# 4.1. Choosing checklist mentors insist on

## 1. Every style justifying (needs stating — prices attaching — defaults declining)

**Definition** — the style gate: each adopted style stating needs, attaching prices, declining defaults (needs stating — workloads describing (features listing — experiences funding (stating proving — defaulting declining); prices attaching — costs estimating (reversals naming — vibes declining (attaching funding — hiding ending); defaults declining — fashion refusing (reasons demanding — independence keeping (declining proving — following ending).

**What problem it solves** — the unjustified trio: *styles defaulting* (stacks assuming — needs unmatching (judgment missing — experiences degrading (defaulting billing — stating declining); *prices hiding* (costs unstated — reversals unowned (surprises scheduling — pivots dreading (hiding charging — honesty declining); *fashion following* (slogans reciting — pilots skipping (evidence bluffing — independence dying (following billing — reasoning declining). The gate converting defaulting to justifying (needs stating — prices attaching (defaults refusing — reasons demanding); mentors asking one question per style ("which need, which price?" — justifying demanding per adoption).

**Modern guidance** — the gate commands (run per style, enforced in review):

```typescript
// GOOD: styles gated — needs stating, prices attaching, defaults declining (checklist shape).
// 1. Need proof (workloads describing — features listing):
//    every style matched to stated needs — realtime flagging, mobility marking, internal scoping.
// 2. Price proof (costs estimating — reversals naming):
//    every adoption windowed with build, operate, reverse — vibes declining, judgment funding.
// 3. Default proof (fashion refusing — reasons demanding):
//    no style by default — pilots measuring, sunsets stating, independence keeping.
// State needs; attach prices; decline defaults.)
```

```typescript
// BAD: styles unjustifying — stacks defaulting, prices hiding (real unjustified shape).
// // "Industry standard." (needs unmatching — experiences degrading — judgment missing).
// // No prices (surprises scheduling — pivots dreading). State workloads; window costs; refuse slogans.)
```

**Common confusion** — *"gates slow adoption (process throttling)."* Gates preventing mismatch (needs stating — prices attaching (surprises declining — trust earning (preventing funding — throttling declining); missing gates slowing recovery (styles defaulting — needs unmatching (experiences degrading — rework scheduling (missing charging — writing declining). "Throttling" describing ceremony (approvals queuing — value missing); gates describing leverage (proof reusing — mismatch preventing). Gate styles (needs stating — prices attaching); ship faster (matches owning — rework declining).

**Performance note** — style economics: stating costing needs (workloads describing — features listing (mismatches declining — surprises preventing); defaulted equivalents costing mismatch (needs unmatching — experiences degrading (users leaving — rework funding). State cheaply (needs — lists); default never (stacks — mismatch).

**Mentor note** — demand "need and price per style" (juniors justifying one style per need-set design default-proof choices on first hearing; unjustified stacks interrogated ("which need?" — justifying demanding per adoption). Justify one style once (needs stating — prices attaching tangible (defaulting ending — justifying proving permanently). List workloads; attach costs — justifying discipline in three habits, reviewed per style.

## 2. Every client serving (views shaping — backends fanning — experiences funding)

**Definition** — the serving gate: each client kind shaped views, fanned backends, funded experiences (views shaping — screens serving (payloads bounding — overfetch declining (shaping proving — generic refusing); backends fanning — services composing (calls parallelizing — waits bounding (fanning funding — sequencing declining); experiences funding — clients thriving (latencies bounding — interactions smoothing (funding owning — starving refusing).

**What problem it solves** — the unserved trio: *views genericing* (APIs compromising — payloads dumping (mobiles choking — experiences degrading (genericing billing — shaping declining); *backends sequencing* (calls awaiting — latencies summing (waits adding — users slowing (sequencing charging — parallelizing declining); *duplication forking* (views copying — rules drifting (consistency failing — maintenance doubling (forking billing — sharing declining). The gate converting genericing to serving (views owning — backends racing (experiences funding — compromises declining); mentors asking one question per client ("which view, which fan-out?" — serving demanding per kind).

**Modern guidance** — the gate commands (run per client, enforced in review):

```typescript
// GOOD: clients gated — views shaping, backends fanning, experiences funding (checklist shape).
// 1. View proof (screens serving — payloads bounding):
//    every client kind owning its view — mobiles trimming, webs completing, overfetch declining.
// 2. Fan-out proof (services composing — calls parallelizing):
//    backends racing with budgets — serials declining, waits bounding, partials degrading.
// 3. Duplication proof (copies counting — divergence budgeting):
//    forks inventoried with merge plans — rules owning, drifts pricing, forever declining.
```

```typescript
// BAD: clients unserving — views genericing, backends sequencing (real unserved shape).
// // One payload for all (payloads dumping — mobiles choking — experiences degrading).
// // Serial backends (latencies summing — users slowing). Shape per client; race backends; price copies.)
```

**Common confusion** — *"gates multiply BFFs (backends fragmenting)."* Gates evidencing service (views shaping — backends fanning (proof reusing — judgment focusing (evidencing funding — slowing declining); fragmenting splitting ownership (backends scattering — contracts forking (duplication growing — consistency failing (fragmenting charging — composing declining). "Fragmenting" describing scatter (ownership scattering — contracts forking); gates describing evidence (service proving — experiences funding). Evidence service (views shaping — backends fanning); fragment never (backends scattering — contracts forking).

**Performance note** — serving economics: shaping costing views (screens serving — payloads bounding (mobiles funding — dumping declining); genericed equivalents costing overfetch (payloads dumping — mobiles choking (bandwidth wasting — experiences degrading). Shape cheaply (views — BFFs); generic never (APIs — compromises).

**Mentor note** — demand "view per client kind" (juniors serving one view per client design generic-proof composition on first hearing; one-size payloads interrogated ("which client?" — serving demanding per view). Serve one client once (views shaping — backends fanning tangible (genericing ending — serving proving permanently). Bound payloads; race backends — serving discipline in three habits, reviewed per client.

## 3. Every entry guarding (auth verifying — limits throttling — versions scoping)

**Definition** — the entry gate: each gateway entry verifying auth, throttling limits, scoping versions (auth verifying — tokens checking (scopes bounding — intrusions declining (verifying proving — hoping ending); limits throttling — rates capping (bursts queuing — fairness funding (throttling owning — flooding declining); versions scoping — releases numbering (clients trusting — surprises declining (scoping proving — mixing refusing).

**What problem it solves** — the unguarded trio: *auth scattering* (handlers branching — logic scattering (audits missing — consistency failing (scattering billing — ownership blurring); *limits missing* (rates uncapped — floods arriving (servers crushing — legit starving (missing charging — policy declining); *versions mixing* (releases unnumbering — clients breaking (surprises scheduling — trust eroding (mixing billing — clarity declining). The gate converting scattering to verifying (auth checking — limits capping (versions numbering — breaches declining); mentors asking one question per entry ("who passes, how many, which version?" — guarding demanding per route).

**Modern guidance** — the gate commands (run per entry, enforced in review):

```typescript
// GOOD: entries gated — auth verifying, limits throttling, versions scoping (checklist shape).
// 1. Auth proof (tokens checking — scopes bounding):
//    every entry verifying tokens and scopes — handlers thinning, intrusions declining.
// 2. Limit proof (rates capping — bursts queuing):
//    every key budgeted — floods declining, fairness funding, neighbors protecting.
// 3. Version proof (releases numbering — clients trusting):
//    every route version-scoped — breaking numbering, additives flowing, surprises declining.

```

```typescript
// BAD: entries unguarding — auth scattering, limits missing (real unguarded shape).
// // Open gateway (intrusions arriving — breaches scheduling — safety declining).
// // No limits, no versions (servers crushing — clients breaking). Guard entries; cap rates; scope releases.)
```

**Common confusion** — *"gates centralize failure (single breaking)."* Gates unifying policy (auth verifying — limits throttling (breaches declining — floods preventing (unifying proving — scattering ending); centralizing fragilizing topology (outages owning — blasts bounding (downtimes arriving — redundancy missing (fragilizing charging — resilience declining). "Centralizing" describing topology (outages owning — blasts bounding); gates describing policy (auth checking — limits capping). **Performance note** — guarding economics: verifying costing checks (tokens checking — rates capping (breaches declining — floods preventing); scattered equivalents costing incidents (handlers branching — logic scattering (audits missing — consistency failing). Verify cheaply (edges — gates); scatter never (auth — handlers).

**Mentor note** — demand "auth, limit, version per entry" (juniors guarding one entry per triple design breach-proof gateways on first hearing; open entries interrogated ("who passes?" — guarding demanding per route). Guard one entry once (auth verifying — limits throttling tangible (scattering ending — guarding proving permanently).
