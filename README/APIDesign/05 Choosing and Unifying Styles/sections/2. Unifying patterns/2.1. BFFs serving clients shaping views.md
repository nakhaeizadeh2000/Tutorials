# 2.1. BFFs serving clients shaping views

## 1. Clients serving (views shaping — payloads bounding — experiences funding)

**Definition** — backend-for-frontend: per-client backends shaping views (views shaping — screens serving (payloads bounding — overfetch declining (shaping proving — generic declining); payloads bounding — sizes limiting (bandwidth sparing — mobiles funding (bounding owning — dumping declining); experiences funding — clients thriving (latencies bounding — interactions smoothing (funding owning — starving refusing).

**What problem it solves** — the one-API trio: *clients genericing* (views compromising — payloads dumping (mobiles choking — experiences degrading (genericing billing — shaping declining); *backends dictating* (shapes serving — clients adapting (producers owning — consumers obeying (dictating charging — trusting declining); *views compromising* (screens averaging — nobody delighting (quality blurring — pride declining (compromising billing — excellence missing). Serving BFFs converting genericing to shaping (views owning — payloads bounding (experiences funding — compromises declining); reviewers finding one BFF per client kind (serving proving → verifiable; genericing → returned).

**Modern guidance** — the serving lines per client (review-enforced): *views shaping* (screens serving — payloads bounding (overfetch declining — generic refusing (shaping proving — compromising ending (precision owning — bloat declining); *payloads bounding* (sizes limiting — bandwidth sparing (mobiles funding — dumping declining (bounding owning — bloating refusing (thrift funding — choking declining); *experiences funding* (clients thriving — latencies bounding (interactions smoothing — starving refusing (funding owning — degrading declining (delight earning — churn declining).

```typescript
// GOOD: clients serving — mobile and web views shaped from shared backends (compiled + run live).
interface Backend { // views shaping — screens serving, generic refusing
  profile(handle: string): { handle: string; posts: number; bio: string };
}
const backend: Backend = {
  profile: (handle: string) => ({ handle, posts: 42, bio: '...' }),
};
function mobileView(b: Backend, handle: string): string[] { // payloads bounding — sizes limiting, dumping declining
  const p = b.profile(handle);
  return [p.handle, String(p.posts)];
}
function webView(b: Backend, handle: string): string[] {
  const p = b.profile(handle);
  return [p.handle, String(p.posts), p.bio];
}
const m = mobileView(backend, 'ada');
const w = webView(backend, 'ada');
console.log(m.length === 2 && w.length === 3 && m[0] === 'ada' ? 'clients serve' : 'apis generic');
```

**Common confusion** — *"BFFs duplicate backends (copies multiplying)."* BFFs shaping views (screens serving — payloads bounding (experiences funding — compromises declining (shaping proving — genericing refusing); duplicating copying logic (rules forking — drift growing (guards doubling — consistency failing (duplicating charging — value missing). "Duplicating" describing logic (rules forking — drift growing); BFFs describing views (screens shaping — payloads bounding). Shape views (screens serving — payloads bounding); duplicate never (logic forking — drift growing).

**Performance note** — serving economics: shaping costing views (screens serving — payloads bounding (mobiles funding — dumping declining); genericed equivalents costing overfetch (payloads dumping — mobiles choking (bandwidth wasting — experiences degrading). Shape cheaply (views — BFFs); generic never (APIs — compromises).

**Mentor note** — teach "one BFF per client kind" (juniors shaping one view per client design generic-proof APIs on first hearing; one-size APIs interrogated ("which client?" — serving demanding per view). Serve one client once (views shaping — payloads bounding tangible (genericing ending — serving proving permanently). ## 2. Backends fanning (services composing — calls parallelizing — waits bounding)

**Definition** — backend fan-out: BFFs composing services in parallel with bounded waits (services composing — backends calling (data joining — views building (composing proving — serializing declining); calls parallelizing — requests racing (latencies overlapping — totals shrinking (parallelizing funding — sequencing declining); waits bounding — timeouts capping (slows shedding — hangs declining (bounding owning — lingering refusing).

**What problem it solves** — the serial trio: *calls sequencing* (backends awaiting — latencies summing (waits adding — users slowing (sequencing billing — parallelizing declining); *waits unbounding* (slows blocking — hangs lingering (timeouts missing — liveness bluffing (unbounding charging — reliability declining); *failures cascading* (errors propagating — views breaking (partials missing — resilience bluffing (cascading billing — degrading declining). Fanned backends converting sequencing to parallelizing (services composing — calls racing (waits capping — partials degrading); reviewers bounding fan-out waits per BFF (fanning proving → verifiable; sequencing → returned).

**Modern guidance** — the fanning lines per BFF (review-enforced): *services composing* (backends calling — data joining (views building — serializing declining (composing proving — chaining refusing (aggregation owning — hopping declining); *calls parallelizing* (requests racing — latencies overlapping (totals shrinking — sequencing declining (parallelizing funding — summing refusing (speed owning — slowness declining); *waits bounding* (timeouts capping — slows shedding (hangs declining — lingering refusing (bounding owning — unbounding refusing (caps funding — cascades preventing).

```typescript
// GOOD: backends fanning — parallel calls with timeout budgets, partials degrading (compiled + run live).
async function withTimeout<T>(p: Promise<T>, ms: number, fallback: T): Promise<T> { // waits bounding — timeouts capping, lingering refusing
  let timer: ReturnType<typeof setTimeout> | undefined;
  try {
    return await Promise.race([p, new Promise<T>((_, reject) => { timer = setTimeout(() => reject(new Error('slow')), ms); })]);
  } catch {
    return fallback; // partials degrading — views building, cascades preventing
  } finally {
    if (timer !== undefined) clearTimeout(timer);
  }
}
async function run(): Promise<void> {
  const fast = Promise.resolve('profile');
  const slow = new Promise<string>((resolve) => setTimeout(() => resolve('feed'), 500)); // services composing — backends calling, serializing declining
  const a = await withTimeout(fast, 100, 'fallback');
  const b = await withTimeout(slow, 50, 'fallback'); // calls parallelizing — requests racing, sequencing declining
  console.log(a === 'profile' && b === 'fallback' ? 'backends fan' : 'calls sequence');
}
run();
```

**Common confusion** — *"fan-out means microservices (topology requiring)."* Fan-out composing calls (backends calling — data joining (views building — serializing declining (composing proving — sequencing declining); microservices deploying units (processes scaling — networks calling (operations owning — failures isolating (deploying funding — language declining). "Microservices" describing runtime (processes scaling — failures isolating); fan-out describing composition (services calling — data joining). Compose backends (services calling — views building); deploy pragmatically (units scaling — operations owning).

**Performance note** — fanning economics: parallelizing costing coordination (requests racing — latencies overlapping (totals shrinking — sequencing declining); sequenced equivalents costing sums (waits adding — users slowing (latencies growing — trust eroding). Fan cheaply (parallel — calls); sequence never (backends — sums).

**Mentor note** — teach "parallel with budgets" (juniors fanning one backend set per BFF design serial-proof composition on first hearing; unbounded fan-out interrogated ("which timeout?" — fanning demanding per call). Fan one set once (services composing — waits bounding tangible (sequencing ending — fanning proving permanently). Race calls; shed slows — fanning discipline in three habits, reviewed per BFF.

## 3. Duplication pricing (copies counting — divergence budgeting — merges planning)

**Definition** — BFF duplication pricing: copies counted, divergence budgeted, merges planned (copies counting — BFFs listing (lines measuring — sharing assessing (counting proving — hiding ending); divergence budgeting — drifts pricing (windows bounding — surprises declining (budgeting funding — hoping ending); merges planning — kernels extracting (platforms owning — copies retiring (planning owning — forever declining).

**What problem it solves** — the copy-paste trio: *BFFs duplicating* (views forking — logic copying (rules drifting — consistency failing (duplicating billing — sharing declining); *divergence unbudgeting* (drifts growing — surprises scheduling (ownership missing — quality fading (unbudgeting charging — hoping ending); *merges unplanning* (kernels missing — platforms absenting (copies fossilizing — maintenance doubling (unplanning costing — velocity dying). Priced duplication converting forking to counting (copies listing — divergence budgeting (merges planning — forever declining); reviewers counting copies per BFF set (pricing proving → verifiable; forking → returned).

**Modern guidance** — the pricing lines per BFF set (review-enforced): *copies counting* (BFFs listing — lines measuring (sharing assessing — hiding ending (counting proving — forking refusing (inventory owning — blindness declining); *divergence budgeting* (drifts pricing — windows bounding (surprises declining — hoping ending (budgeting funding — unbudgeting refusing (horizons owning — rot declining); *merges planning* (kernels extracting — platforms owning (copies retiring — forever declining (planning owning — fossilizing refusing (convergence funding — doubling ending).

```typescript
// GOOD: duplication pricing — copy counts gating shared-kernel merges (compiled + run live).
function verdict(copies: number, drifted: number, budget: number): string { // copies counting — BFFs listing, hiding ending
  if (copies === 0) return 'single';
  if (drifted <= budget) return 'keep'; // divergence budgeting — drifts pricing, hoping ending
  return 'merge'; // merges planning — kernels extracting, forever declining
}
const a = verdict(0, 0, 2);
const b = verdict(3, 1, 2);
const c = verdict(3, 5, 2);
console.log(a === 'single' && b === 'keep' && c === 'merge' ? 'duplication prices' : 'copies fork');
```
