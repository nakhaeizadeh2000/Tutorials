# 4.1. GraphQL checklist mentors insist on

## 1. Every field owning (resolvers deciding — parents feeding — N+1 budgeting)

**Definition** — the field gate: each field owned by a resolver, fed by parents, budgeted for N+1 (resolvers deciding — values computing (logic homing — godding declining (deciding proving — centralizing refusing); parents feeding — ancestors supplying (ids passing — contexts scoping (feeding funding — reaching declining); N+1 budgeting — rounds counting (batches funding — waterfalls bounding (budgeting owning — looming declining).

**What problem it solves** — the unowned trio: *resolvers godding* (roots deciding — fields branching (logic centralizing — ownership blurring (godding billing — scaling declining); *parents ignoring* (children reaching — globals fetching (contexts missing — tests heavying (ignoring charging — scoping declining); *N+1 unbudgeting* (rounds uncounted — queries multiplying (latencies summing — regressions hiding (unbudgeting billing — visibility missing). The gate converting godding to owning (resolvers deciding — parents feeding (N+1 budgeting — batches funding); mentors asking one question per field ("which resolver, which batch?" — owning demanding per field).

**Modern guidance** — the gate commands (run per field, enforced in review):

```typescript
// GOOD: fields gated — resolvers deciding, parents feeding, N+1 budgeting (checklist shape).
// 1. Ownership proof (values computing — logic homing):
//    one resolver per field — god functions split, parents fed, children scoped.
// 2. Parent proof (ancestors supplying — ids passing):
//    no global reaches — contexts scoping, tests easing, globals declining.
// 3. Budget proof (rounds counting — batches funding):
//    batch loader per nested field — N+1 counted, waterfalls flattened, latency bounding.
// Own fields; feed parents; budget N+1.)
```

```typescript
// BAD: fields unowning — resolvers godding, N+1 unbudgeting (real unowned shape).
// Query: { everything: async () => { /* ... */ } } // logic centralizing — ownership blurring.
// // Per-item fetches uncounted (rounds multiplying — latencies summing). Own resolvers; feed parents; fund batches.)
```

**Common confusion** — *"gates slow graph work (process throttling)."* Gates preventing N+1 (rounds counting — batches funding (latencies bounding — regressions catching (preventing funding — throttling declining); missing gates slowing users (queries multiplying — waits summing (latencies growing — trust eroding (missing charging — writing declining). "Throttling" describing ceremony (approvals queuing — value missing); gates describing leverage (proof reusing — N+1 preventing). Gate fields (resolvers deciding — batches funding); ship faster (latencies bounding — users trusting).

**Performance note** — field economics: owning costing resolvers (values computing — parents feeding (N+1 budgeting — batches funding); godded equivalents costing scale (logic centralizing — ownership blurring (queries multiplying — latencies growing). Own cheaply (resolvers — fields); god never (roots — branches).

**Mentor note** — demand "resolver and batch per field" (juniors owning one field per resolver design god-proof graphs on first hearing; unbatched nesting interrogated ("which loader?" — owning demanding per field). Own one field once (resolvers deciding — batches funding tangible (godding ending — owning proving permanently). Decide fields; fund batches — owning discipline in three habits, reviewed per field.

## 2. Every query bounding (selections shaping — costs pricing — depths limiting)

**Definition** — the bounding gate: each query shaping selections, pricing costs, limiting depth (selections shaping — requests stating (payloads bounding — waste declining (shaping proving — fixing ending); costs pricing — complexities stating (budgets bounding — surprises declining (pricing funding — hiding ending); depths limiting — levels capping (cycles refusing — stacks protecting (limiting owning — growing declining).

**What problem it solves** — the unbounded trio: *selections unshaping* (fields dumping — payloads bloating (bandwidth wasting — mobiles choking (unshaping billing — precision declining); *costs unpricing* (complexities hiding — budgets bluffing (surprises scheduling — incidents arriving (unpricing charging — honesty declining); *depths uncapping* (queries nesting — cycles looping (stacks overflowing — servers crashing (uncapping billing — limits missing). The gate converting unshaping to bounding (selections stating — costs pricing (depths capping — waste declining); mentors asking one question per query ("which selection, which cost?" — bounding demanding per query).

**Modern guidance** — the gate commands (run per query, enforced in review):

```typescript
// GOOD: queries gated — selections shaping, costs pricing, depths limiting (checklist shape).
// 1. Selection proof (requests stating — payloads bounding):
//    clients selecting needed fields — overfetching declining, bandwidth sparing, mobiles funding.
// 2. Cost proof (complexities stating — budgets bounding):
//    query costs computed pre-execution — expensive rejected, budgets enforcing, surprises declining.
// 3. Depth proof (levels capping — cycles refusing):
//    nesting depth measured and capped — stacks protecting, loops declining, crashes preventing.
// Shape selections; price costs; limit depths.)
```

```typescript
// BAD: queries unbounding — selections unshaping, depths uncapping (real unbounded shape).
// { everything { everything { everything } } } // queries nesting — cycles looping, stacks overflowing.
// // No cost analysis (complexities hiding — budgets bluffing). Shape requests; price complexity; cap levels.)
```

**Common confusion** — *"gates restrict clients (locks limiting)."* Gates bounding abuse (selections shaping — costs pricing (servers protecting — crashes preventing (bounding funding — restricting declining); restricting refusing value (clients declining — needs ignoring (refusing serving — trust eroding (restricting charging — openness declining). "Restricting" describing refusal (clients declining — needs ignoring); gates describing budgets (costs pricing — depths limiting). Bound abuse (selections shaping — costs pricing); serve needs (clients selecting — payloads bounding).

**Performance note** — bounding economics: shaping costing selections (requests stating — payloads bounding (bandwidth sparing — latency bounding); unshaped equivalents costing waste (fields dumping — payloads bloating (mobiles choking — experiences degrading). Shape cheaply (selections — queries); dump never (fields — payloads).

**Mentor note** — demand "selection, cost, depth per query" (juniors bounding one query per triple design abuse-proof graphs on first hearing; unbounded queries interrogated ("which cost?" — bounding demanding per query). Bound one query once (selections shaping — costs pricing tangible (unshaping ending — bounding proving permanently). State selections; cap depths — bounding discipline in three habits, reviewed per query.

## 3. Every mutation sequencing (inputs validating — payloads returning — side-effects ordering)

**Definition** — the sequencing gate: each mutation validating inputs, returning payloads, ordering side-effects (inputs validating — shapes proving (garbage declining — handlers assuming (validating funding — trusting declining); payloads returning — affected stating (errors listing — clients reconciling (returning owning — void declining); side-effects ordering — writes sequencing (reads following — races declining (ordering proving — interleaving refusing).

**What problem it solves** — the unsequenced trio: *inputs trusting* (shapes hoping — garbage entering (validity bluffing — corruption arriving (trusting billing — proving declining); *payloads voiding* (results hiding — errors silencing (clients guessing — reconciliations failing (voiding billing — transparency declining); *effects racing* (writes interleaving — reads confusing (order missing — consistency bluffing (racing charging — sequencing declining). The gate converting trusting to validating (inputs proving — payloads stating (effects ordering — races declining); mentors asking one question per mutation ("which input, which payload?" — sequencing demanding per write).

**Modern guidance** — the gate commands (run per mutation, enforced in review):

```typescript
// GOOD: mutations gated — inputs validating, payloads returning, effects ordering (checklist shape).
// 1. Input proof (shapes proving — garbage declining):
//    every mutation validating its input — unknowns declining, handlers assuming, corruption preventing.
// 2. Payload proof (affected stating — errors listing):
//    every mutation returning payloads — results owning, clients reconciling, void declining.
// 3. Order proof (writes sequencing — reads following):
//    side-effects ordered — races declining, interleaving refusing, consistency earning.
// Validate inputs; return payloads; order effects.)
```

```typescript
// BAD: mutations unsequencing — inputs trusting, payloads voiding (real unsequenced shape).
// mutation { doStuff } // effects confusing — audits blurring, sequencing declining.
// // No input type, no payload (shapes hoping — clients guessing). Type inputs; state payloads; order writes.)
```

**Common confusion** — *"gates bureaucratize mutations (process stiffening)."* Gates evidencing discipline (inputs validating — payloads returning (proof reusing — judgment focusing (evidencing funding — slowing declining); bureaucratizing padding ceremony (forms multiplying — value missing (swaps unnamed — comprehension taxing (padding charging — judgment absenting). "Bureaucratizing" describing ceremony (forms multiplying — value missing); gates describing evidence (discipline proving — trust earning). Evidence discipline (inputs validating — payloads returning); pad never (forms multiplying — value missing).

**Performance note** — sequencing economics: validating costing input types (shapes proving — garbage declining (handlers assuming — corruption preventing); trusted equivalents costing corruption (shapes hoping — garbage entering (validity bluffing — trust eroding). Validate cheaply (inputs — types); trust never (shapes — hope).

**Mentor note** — demand "input, payload, order per mutation" (juniors sequencing one write per input-pair design query-proof mutations on first hearing; void mutations interrogated ("which payload?" — sequencing demanding per write). Sequence one mutation once (inputs validating — payloads returning tangible (trusting ending — sequencing proving permanently). Type inputs; order effects — sequencing discipline in three habits, reviewed per mutation.
