# 3.1. DTOs mapping at service edges

## 1. Edges validating (shapes proving — garbage declining — handlers assuming)

**Definition** — edge validation: every service entry parsing unknown input into typed DTOs before any logic runs (shapes proving — contracts bounding (garbage declining — trust earning (validating funding — assuming enabling); handlers assuming — downstream code trusting parsed shapes (checks centralizing — branches declining (assuming serving — velocity funding).

**What problem it solves** — the unguarded-entry trio: *garbage entering* (any accepting — nulls drilling (shapes unproven — corruption arriving (entering billing — trust eroding); *handlers defending* (every function rechecking — guards duplicating (ownership missing — drift growing (defending multiplying — consistency failing); *types lying* (casts asserting — unknowns smuggling (safety bluffing — runtime breaking (lying charging — crashes scheduling). Validated edges converting garbage to contracts (unknown parsing — DTOs proving (handlers assuming — drift ending); reviewers finding one parse per entry (validating proving → verifiable; defending → returned).

**Modern guidance** — the validating lines per service entry (review-enforced): *shapes proving* (unknown parsing — contracts bounding (garbage declining — trust earning (proving owning — hoping ending (validation funding — corruption preventing); *garbage declining* (invalid throwing — callers fixing (entries guarding — cores shielding (declining proving — entering preventing (discipline owning — breakage declining); *handlers assuming* (parsed trusting — branches declining (downstream speeding — velocity funding (assuming serving — defending ending). Pipe mechanics at the HTTP edge are owned in [NestJS 02/3.1](<../../../../NestJS/02 Controllers Routing and Validation/sections/3. Input proof/3.1. Validation pipes from params to bodies.md>) — this leaf owns service-entry parsing, never the pipes.

```typescript
// GOOD: edges validating — unknown parsed to DTO, garbage rejected (compiled + run live).
interface PageQuery { // DTO carrying — validated shape, handlers assuming
  page: number;
  limit: number;
}
function parsePage(raw: unknown): PageQuery { // edge parsing — shapes proving, garbage declining
  if (typeof raw !== 'object' || raw === null) throw new Error('shape invalid');
  const { page, limit } = raw as { page: unknown; limit: unknown };
  if (!Number.isInteger(page) || (page as number) < 1) throw new Error('page >= 1 required');
  if (!Number.isInteger(limit) || (limit as number) < 1 || (limit as number) > 100) throw new Error('limit 1..100 required');
  return { page: page as number, limit: limit as number };
}
const good = parsePage({ page: 2, limit: 25 });
let rejected = 0;
for (const bad of [{ page: 0, limit: 25 }, { page: 1, limit: 500 }, null]) {
  try { parsePage(bad); } catch { rejected += 1; } // garbage declining — callers fixing, cores shielding
}
console.log(good.page === 2 && good.limit === 25 && rejected === 3 ? 'edges validate' : 'garbage enters');
```

## 2. Mappers translating (DTOs mapping — entities building — layers holding)

**Definition** — mapper: pure function translating one boundary direction (DTOs mapping — shapes converting (edges translating — cores shielding (mapping proving — leaking preventing); entities building — domain constructing from validated shapes (rules guarding — validity holding (building funding — corruption declining); layers holding — secrets staying, methods absenting (holding proving — exposure ending (discipline owning — breach declining).

**What problem it solves** — the scattered-mapping trio: *mapping duplicating* (every caller converting — shapes drifting (ownership missing — inconsistency growing (duplicating multiplying — trust eroding); *entities leaking* (domain serializing — hashes exposing (behavior traveling — secrets broadcasting (leaking billing — exposure scheduling); *directions mixing* (inbound sharing outbound — reads shaping writes (concerns blurring — contracts coupling (mixing charging — evolution blocking). Owned mappers converting scattering to translation (one function owning — directions separating (layers holding — drift ending); reviewers finding each crossing in exactly one mapper (translating proving → verifiable; leaking → returned).

**Modern guidance** — the mapping lines per boundary (review-enforced): *DTOs mapping* (shapes converting — edges translating (cores shielding — leaking preventing (mapping proving — scattering ending (translation owning — drift declining); *entities building* (domain constructing — rules guarding (validity holding — corruption declining (building funding — hoping ending (construction owning — trust earning); *layers holding* (secrets staying — methods absenting (exposure declining — breach preventing (holding proving — leaking ending (discipline owning — safety earning).

```typescript
// GOOD: mappers translating — inbound building entities, outbound dropping secrets (compiled + run live).
interface CreateMemberDto { // inbound carrying — validated shape, handlers assuming
  name: string;
}
interface MemberView { // outbound carrying — safe shape, secrets absenting
  name: string;
}
class Member { // entity deciding — rules living, edges unknown
  constructor(readonly name: string) {
    if (name.length === 0) throw new Error('name required');
  }
}
function toEntity(dto: CreateMemberDto): Member { // inbound translating — domain constructing, validity holding
  return new Member(dto.name.trim());
}
function toView(member: Member, passwordHash: string): MemberView { // outbound translating — secrets staying, layers holding
  void passwordHash; // staying proving — exposure declining, breach preventing
  return { name: member.name };
}
const entity = toEntity({ name: '  ada  ' });
const view = toView(entity, 'ph:9f2c');
console.log(entity.name === 'ada' && view.name === 'ada' && !('passwordHash' in view) ? 'mappers translate' : 'layers leak');
```

## 3. Contracts versioning (fields evolving — breakage preventing — clients trusting)

**Definition** — contract versioning: service shapes evolving additively without breaking callers (fields evolving — optionals adding (clients unbreaking — trust keeping (evolving proving — flag-day declining); breakage preventing — renames versioning, removals deprecating (changes sequencing — migrations staging (preventing funding — incidents declining); clients trusting — old callers serving during transitions (compatibility holding — upgrades boring (trusting earning — fear declining).

**What problem it solves** — the breaking-change trio: *fields renaming* (callers breaking — deploys coordinating (renames billing — flag-days scheduling (breaking charging — trust eroding); *shapes removing* (clients crashing — rollbacks panicking (removals costing — incidents arriving (removing billing — safety declining); *versions forking* (v1 diverging — v2 duplicating (codebases splitting — maintenance doubling (forking multiplying — consistency failing). Versioned contracts converting breaking to evolving (additive growing — deprecate-then-removing (callers serving — trust keeping); reviewers rejecting renames without versions per contract (versioning proving → verifiable; breaking → returned).

**Modern guidance** — the versioning lines per contract (review-enforced): *fields evolving* (optionals adding — clients unbreaking (trust keeping — flag-day declining (evolving proving — breaking ending (growth owning — fear declining); *breakage preventing* (renames versioning — removals deprecating (changes sequencing — migrations staging (preventing funding — incidents declining (caution owning — panic ending); *clients trusting* (old serving — transitions bridging (compatibility holding — upgrades boring (trusting earning — fear declining (stability proving — churn declining). interface MemberV1 { // contract serving — old callers unbreaking, trust keeping
  name: string;
