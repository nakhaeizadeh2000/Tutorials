# 4.1. Services checklist mentors insist on

## 1. Every flow owning intent (services arranging — use cases deciding — edges translating)

**Definition** — the intent gate: each application flow owned by exactly one service arranging and one use case deciding (services arranging — flows sequencing (edges owning — cores serving (arranging proving — scattering declining); use cases deciding — rules homing (ports calling — entities guarding (deciding funding — scripting ending); edges translating — HTTP shaping (DTOs validating — cores shielding (translating owning — deciding declining).

**What problem it solves** — the unowned-flow trio: *services deciding* (rules branching — reuse absenting (domain leaking — tests heavying (deciding billing — arranging missing); *controllers arranging* (HTTP sequencing — flows duplicating (edges deciding — core missing (arranging scattering — ownership blurring); *use cases frameworking* (transports owning — tests heavying (cores obeying — portability dying). The gate converting scatter to ownership (one service arranging — one use case deciding (edges translating — rules homing); mentors asking one question per flow ("who arranges, who decides?" — ownership demanding per service).

**Modern guidance** — the gate commands (run per flow, enforced in review):

```typescript
// GOOD: intent gated — services arranging, use cases deciding, edges translating (checklist shape).
// 1. Arrangement proof (flows owning — rules homing):
//    zero business-rule branches in app services — grep for if/compute guarding domain concepts outside use cases/entities.
// 2. Decision proof (ports calling — entities deciding):
//    every service delegating to exactly one use case per intent — one public method, ports declaring.
// 3. Edge proof (translating owning — deciding declining):
//    controllers shaping only — HTTP parsing, service calling, queries absenting.
// Arrange in services; decide in use cases; translate at edges.)
```

```typescript
// BAD: flows unowned — services deciding, controllers arranging (real unowned shape).
// class Checkout { /* totals computing + discounts branching */ } // domain leaking — tests heavying.
// @Controller() class C { /* transactions branching */ } // edges deciding — core missing, flows duplicating.
// } // Own flows: services arranging, use cases deciding, edges translating.)
```

**Common confusion** — *"checklists replace design sense (process deciding)."* Checklists proving gates (outputs reading — hunts skipping (evidence funding — confidence earning (proving serving — hoping ending); sense placing exceptions (contexts weighing — trade-offs owning (judgment serving — automation grounding (sensing funding — abdication declining). "Replacing" describing abdication (humans skipping — context ignoring); checklists describing leverage (proof reusing — judgment focusing). Gate with checklists (evidence funding — speed earning); design with sense (exceptions pricing — contexts weighing).

**Performance note** — gate economics: checking costing seconds per flow (ownership proving — scattering declining (arranging owning — deciding funding); unowned equivalents costing hunts (reads jumping — edits hunting (ownership blurring — reuse hoping). Gate cheaply (seconds — flows); hope never (scatter — hunts).

**Mentor note** — demand "arranger and decider named" (juniors naming one service + one use case per flow design ownership-carrying reviews on first hearing; unnamed flows interrogated ("who arranges?" — ownership demanding per PR). Name one flow once (services arranging — use cases deciding tangible (scatter ending — ownership proving permanently). Arrange services; decide use cases — intent discipline in three habits, reviewed per flow.

## 2. Every boundary transacting (units scoping — partials declining — compensations naming)

**Definition** — the atomicity gate: each use-case execution scoping its unit of work, each long flow naming its compensations (units scoping — work atomizing (executions bounding — halves refusing (scoping proving — stranding declining); partials declining — all committing or unwinding (wholeness owning — corruption ending (declining funding — trust earning); compensations naming — inverses stating per saga step (undos declaring — retreats ordering (naming owning — hoping ending).

**What problem it solves** — the unscoped trio: *saves scattering* (writes autocommitting — halves persisting (atomicity hoping — integrity doubting (scattering billing — cleanup missing); *sagas inverseless* (steps running — undos unowned (failures stranding — consistency breaking (missing costing — trust eroding); *mechanisms defaulting* (2PC everywhere — rollback hoping (judgment missing — availability taxing (defaulting charging — context ignoring). The gate converting hope to atomicity (boundaries matching — inverses naming (writers judging — mechanisms fitting); mentors asking one question per boundary ("rollback or compensate?" — judging demanding per flow).

**Modern guidance** — the gate commands (run per boundary, enforced in review):

```typescript
// GOOD: atomicity gated — units scoping, partials declining, compensations naming (checklist shape).
// 1. Boundary proof (executions bounding — halves refusing):
//    every mutating use case executing inside one transaction — staged writes committing whole, failures rolling back.
// 2. Inverse proof (undos declaring — retreats ordering):
//    every saga step naming its compensation — reverse-ordered, idempotent, tested by failing mid-flow.
// 3. Judgment proof (writers judging — mechanisms fitting):
//    single-writer rolling back, multi-party compensating — writer count stated per flow, never defaulted.
// Scope units; name inverses; judge writers.)
```

```typescript
// BAD: boundaries hoping — saves scattering, sagas inverseless (real unscoped shape).
// await repo.save(a); await mail.send(); await repo.save(b); // halves persisting — cleanup missing.
// await reserve(); await charge(); await ship(); // undos unowned — failures stranding.
// } // Gate atomicity: units scoping, inverses naming, writers judging.)
```

**Common confusion** — *"gates slow shipping (process taxing)."* Gates catching strands (halves refusing — inverses naming (atomicity proving — trust earning (catching funding — incidents declining); missing gates slowing recovery (failures stranding — cleanups paging (incidents multiplying — velocity dying (missing charging — shipping declining). "Slowing" describing ceremony (meetings multiplying — value missing); gates describing leverage (proof reusing — incidents preventing). Gate boundaries (atomicity proving — trust earning); ship faster (incidents declining — velocity funding).

**Performance note** — atomicity economics: gating costing one boundary check (units scoping — partials declining (trust earning — incidents declining); unscoped equivalents costing incidents (halves persisting — cleanups paging (stranding billing — trust eroding). Gate cheaply (checks — boundaries); strand never (halves — incidents).

**Mentor note** — demand "boundary and inverse stated" (juniors scoping one transaction + one inverse set per flow design incident-proof reviews on first hearing; boundary-less flows interrogated ("what unwinds this?" — atomicity demanding per merge). State one boundary once (units scoping — inverses naming tangible (stranding ending — atomicity proving permanently). Scope work; name undos — atomicity discipline in three habits, reviewed per boundary.

## 3. Every retry idempotenting (keys carrying — effects-once holding — storms surviving)

**Definition** — the retry gate: each retryable intent keyed, each handler replay-safe, each key windowed (keys carrying — intents identifying (callers generating — determinism owning (carrying proving — doubling declining); effects-once holding — replays short-circuiting (sides applying-once — storms absorbing (holding funding — trust earning); storms surviving — bursts steadying (capacity budgeting — collapse declining (surviving owning — dying preventing).

**What problem it solves** — the retry-naive trio: *keys missing* (retries differing — dedupe defeating (anonymity owning — doubles arriving (missing billing — trust eroding); *handlers assuming-once* (effects reapplying — ledgers drifting (assuming costing — consistency breaking (naive charging — storms collapsing); *windows unbounding* (stores growing — memory leaking (horizons missing — costs compounding (unbounding billing — capacity dying). The gate converting naive to guarded (keys identifying — handlers reentering (windows bounding — storms surviving); mentors asking one question per retry ("same intent, same key?" — guarding demanding per call).

**Modern guidance** — the gate commands (run per retryable path, enforced in review):

```typescript
// GOOD: retries gated — keys carrying, handlers reentering, windows bounding (checklist shape).
// 1. Key proof (intents identifying — determinism owning):
//    every retryable call carrying a caller-generated deterministic key — derived from intent fields, stable across retries.
// 2. Handler proof (replays short-circuiting — effects holding):
//    every handler replay-tested — same key twice applying effects once, returning identical outcomes.
// 3. Window proof (memory bounding — risk pricing):
//    dedupe horizons TTL'd per blast radius — unbounded growth rejected, eviction tested.
// Key intents; reenter safely; bound windows.)
```

```typescript
// BAD: retries naive — keys missing, handlers assuming-once (real naive shape).
// const id = uuid(); // randoms per retry — intents unmatching, replays undetecting.
// onMessage((m) => charge(m.amount)); // effects reapplying — ledgers drifting, storms collapsing.
// } // Gate retries: keys carrying, handlers reentering, windows bounding.)
```

**Common confusion** — *"gates replace load testing (checks substituting)."* Gates proving logic (keys identifying — replays returning (correctness owning — doubling declining (proving serving — breaking ending); load proving capacity (bursts absorbing — latencies bounding (throughput owning — collapse declining (proving funding — dying preventing). "Replacing" describing substitution (tests skipping — capacity hoping); gates describing correctness (logic proving — doubles declining). Gate logic (keys carrying — effects holding); load capacity (bursts absorbing — latencies bounding).

**Performance note** — retry economics: gating costing one lookup (keys identifying — replays detecting (effects holding — storms surviving); naive equivalents costing doubles (charges doubling — ledgers drifting (trust eroding — consistency breaking). Gate cheaply (lookups — keys); double never (retries — charges).

**Mentor note** — demand "replay test attached" (juniors redelivering one message per handler design storm-proof reviews on first hearing; replay-untested paths interrogated ("what returns twice?" — guarding demanding per handler). Attach one replay once (keys identifying — outcomes identical tangible (doubling ending — safety proving permanently). Key calls; test replays — retry discipline in three habits, reviewed per path.
