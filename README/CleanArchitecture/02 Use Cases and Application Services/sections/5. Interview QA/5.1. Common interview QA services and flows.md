# 5.1. Common interview QA services and flows

## 1. Flows live under pressure (services, sagas, transactions — diagnosed with fixes, priced)

**Definition** — flow answers: services arranging, sagas staging, transactions scoping — under pressure (diagnosed with fixes — causes naming (understanding proving — reciting declining); priced with trade-offs — boundaries billing (judgment owning — dogma refusing (pricing funding — honesty earning).

**What problem it solves** — the reciting trio: *services listing* ("application service" stating — arranging missing (vocabulary showing — ownership absenting (reciting funding — designing declining); *sagas gesturing* ("compensating" chanting — inverses unnamed (words owning — undos missing (gesturing proving — unwinding declining); *transactions assuming* ("ACID" quoting — boundaries unstated (letters owning — edges missing (quoting proving — scoping declining). Diagnosed answers converting reciting to designing (causes naming — fixes stating (understanding proving — chanting declining); interviewers hiring designers, not chanters (diagnosing proving → hirable; reciting → passed).

**Modern guidance** — answer shape per flow question (diagnose → fix → price):

```typescript
// GOOD: "Where do transactions start?" — diagnosed with fixes, priced (answer shape).
// Diagnose: saves scattering (writes autocommitting — halves persisting — cleanup hoping).
// Fix: use case owning (one execution scoping — app service opening — partials declining).
// Price: one boundary per intent (atomicity proving — stranding ending); runners porting (cores ignorant — fakes sliding).
// Scope executions; port runners — placement stated, not hoped.)
```

```typescript
// BAD: flows reciting — services listing, sagas gesturing (real weak shape).
// "Services handle business logic." (rules branching — arranging missing — designing declining).
// "Sagas manage transactions." (inverses unnamed — writers uncounted — unwinding declining).
// Diagnose causes; state fixes; price honestly.)
```

**Common confusion** — *"flow answers need pattern names (vocabulary impressing)."* Names labeling concepts (words stating — inverses missing (labeling serving — understanding absenting (impressing hoping — hiring declining); answers proving judgment (causes naming — fixes stating (costs pricing — trade-offs owning (proving funding — reciting declining). "Names" describing vocabulary (patterns listing — flows missing); answers describing design (ownership stating — prices itemizing). Diagnose causes (understanding proving — chanting declining); price fixes (judgment owning — dogma refusing).

**Performance note** — answer economics: diagnosing costing one cause per question (understanding proving — reciting declining (hirable funding — chanting ending); recited equivalents costing offers (words owning — flows missing (designing declining — hiring passing). Diagnose cheaply (causes — fixes); recite never (jargon — passes).

**Mentor note** — drill "diagnose, fix, price" (juniors answering one flow question per shape design hirable responses on first hearing; pattern-only answers interrogated ("which cause?" — diagnosing demanding per answer). Shape one answer once (causes naming — fixes stating tangible (reciting ending — designing proving permanently). Diagnose causes; price fixes — answering discipline in three habits, reviewed per mock.

## 2. Failures live under pressure (retries, compensations, partials — honesty stated, not hoped)

**Definition** — failure answers: retries keyed, compensations named, partials refused — honestly (honesty stating — contexts weighing (judgment owning — dogma refusing (stating funding — hoping ending); mechanisms matching (writers counting — flows fitting (routing proving — defaulting declining (matching serving — lockstep sparing).

**What problem it solves** — the hoping trio: *retries assuming-once* (keys missing — effects doubling (anonymity owning — trust eroding (assuming billing — guarding absenting); *failures uncompensated* (inverses unnamed — strands persisting (unwinding absenting — consistency breaking (missing costing — trust eroding); *partials accepted* (halves committing — cleanup paging (declining missing — incidents arriving (accepting charging — atomicity bluffing). Honest answers converting hoping to guarding (keys identifying — inverses naming (partials refusing — mechanisms matching); interviewers hiring realists, not hopers (guarding proving → hirable; hoping → passed).

**Modern guidance** — answer shape per failure question (admit → guard → route):

```typescript
// GOOD: "How do retries stay safe?" — admitted, guarded, routed (answer shape).
// Admit: at-least-once reality (brokers redelivering — timeouts retrying — duplicates arriving).
// Guard: keys identifying (callers generating — replays short-circuiting — effects holding).
// Route: compensations sequencing (inverses naming — reverse unwinding — consistency earning).
// Key intents; name inverses — honesty stated, not hoped.)
```

```typescript
// BAD: failures hoping — retries assuming-once, partials accepted (real hopeful shape).
// "Retries just work." (keys missing — effects doubling — guarding absenting).
// "Transactions handle it." (writers uncounted — parties unbinding — consistency breaking).
// Admit reality; guard retries; route failures.)
```

**Common confusion** — *"honesty means pessimism (gloom performing)."* Honesty pricing failure (keys identifying — inverses naming (partials refusing — mechanisms matching (pricing funding — hoping ending); pessimism declining building (risks listing — ships blocking (gloom serving — value missing (declining charging — progress stopping). "Pessimism" describing gloom (ships blocking — value missing); honesty describing guarding (failures handling — trust earning). Price failures (guards stating — mechanisms matching); ship guarded (trust earning — value funding).

**Performance note** — honesty economics: guarding costing one key per intent (keys identifying — replays detecting (effects holding — storms surviving); hoped equivalents costing doubles (charges doubling — strands persisting (trust eroding — consistency breaking). Guard cheaply (keys — inverses); hope never (doubles — strands).

**Mentor note** — drill "admit, guard, route" (juniors answering one failure question per shape design hirable responses on first hearing; just-works answers interrogated ("what arrives twice?" — guarding demanding per answer). Shape one answer once (reality admitting — guards stating tangible (hoping ending — realism proving permanently). Admit duplicates; guard intents — failure discipline in three habits, reviewed per mock.

## 3. Edges live under pressure (DTOs, mappers, contracts — ownership stated, not hoped)

**Definition** — edge answers: DTOs validating, mappers translating, contracts versioning — ownership stated (crossings homing — layers holding (ownership proving — leaking declining); not hoped (parses proving — tests asserting (evidence funding — wishing ending (stating serving — hoping declining).

**What problem it solves** — the leaking trio: *entries unguarded* (any accepting — garbage entering (shapes unproven — corruption arriving (unguarded billing — trust eroding); *mapping scattered* (callers converting — shapes drifting (ownership missing — inconsistency growing (scattering multiplying — trust eroding); *contracts breaking* (fields renaming — callers crashing (versions unforked — flag-days scheduling (breaking charging — coordination costing). Owned answers converting leaking to translating (parses proving — mappers owning (contracts evolving — layers holding); interviewers hiring owners, not leakers (holding proving → hirable; leaking → passed).

**Modern guidance** — answer shape per edge question (prove → own → evolve):

```typescript
// GOOD: "How do DTOs differ from entities?" — proven, owned, evolved (answer shape).
// Prove: jobs differing (DTOs carrying — entities deciding — purposes separating).
// Own: mappers translating (one function owning — directions separating — layers holding).
// Evolve: contracts versioning (fields adding — callers unbreaking — trust keeping).
// Carry shapes; guard rules — ownership stated, not hoped.)
```

```typescript
// BAD: edges hoping — entries unguarded, contracts breaking (real leaky shape).
// "DTOs are just interfaces." (validation missing — garbage entering — proving declining).
// "We rename fields freely." (callers breaking — coordination costing — evolving absenting).
// Prove jobs; own mappers; evolve additive.)
```

**Common confusion** — *"edge answers test syntax (annotations recalling)."* Syntax stating shapes (interfaces typing — fields naming (stating serving — proving declining (syntax funding — runtime breaking); edges proving ownership (parses validating — mappers translating (contracts evolving — layers holding (proving funding — leaking declining). "Syntax" describing text (annotations typing — checks vanishing); edges describing discipline (validation owning — translation holding). Type shapes (annotations serving — velocity funding); own edges (parses proving — layers holding).

**Performance note** — edge economics: owning costing one mapper per crossing (shapes converting — layers holding (drift ending — safety earning); leaked equivalents costing coordination (callers breaking — flag-days scheduling (breaking charging — trust eroding). Own cheaply (mappers — crossings); leak never (entities — exposure).

**Mentor note** — drill "whose crossing?" (juniors owning one mapper per answer design ownership-stated responses on first hearing; just-interface answers interrogated ("where is the parse?" — owning demanding per edge). Own one crossing once (parses proving — mappers translating tangible (leaking ending — ownership proving permanently). State owners; show parses — edge discipline in three habits, reviewed per mock.
