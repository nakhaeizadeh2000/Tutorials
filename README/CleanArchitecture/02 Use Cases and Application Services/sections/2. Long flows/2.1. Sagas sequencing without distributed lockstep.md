# 2.1. Sagas sequencing without distributed lockstep

## 1. Steps sequencing (flows staging — states persisting — lockstep declining)

**Definition** — saga: long-lived flow staged as local steps with persisted progress, advancing without distributed locks (flows staging — steps ordering (work chunking — locks declining (staging proving — lockstep ending); states persisting — progress journaling per step (recovery owning — restarts resuming (persisting funding — amnesia declining); lockstep declining — parties unblocked, availability kept (coordination refusing — latency sparing (declining proving — throughput earning).

**What problem it solves** — the distributed-atomicity trio: *2PC defaulting* (coordinators locking — participants blocking (availability taxing — latency multiplying (defaulting charging — judgment missing); *hope sequencing* (calls chaining — failures stranding (halves persisting — cleanup missing (hoping billing — consistency breaking); *progress forgetting* (restarts re-running — steps duplicating (journals absenting — recovery guessing (forgetting costing — trust eroding). Staged sagas converting lockstep to progress (steps ordering — states journaling (parties unblocking — consistency earning); reviewers tracing persisted step logs per flow (sequencing proving → verifiable; lockstepping → returned).

**Modern guidance** — the staging lines per long flow (review-enforced): *flows staging* (steps ordering — work chunking (locks declining — availability keeping (staging proving — lockstep ending (progress funding — throughput earning); *states persisting* (progress journaling — restarts resuming (recovery owning — amnesia declining (persisting funding — guessing ending (journals owning — trust earning); *lockstep declining* (parties unblocking — latency sparing (coordination refusing — throughput earning (declining proving — blocking ending).

```typescript
// GOOD: steps sequencing — staged flow advancing, progress journaled, lockstep declined (compiled + run live).
interface Step { // step owning — work stating, inverse naming (compensation owned in section 2 below)
  name: string;
  run(): void;
  compensate(): void;
}
class Saga { // driver sequencing — steps ordering, states persisting
  readonly journal: string[] = []; // progress journaled — restarts resuming, amnesia declining
  constructor(private readonly steps: Step[]) {}
  execute(): string {
    const done: Step[] = [];
    try {
      for (const s of this.steps) {
        s.run();
        done.push(s);
        this.journal.push(`did:${s.name}`);
      }
      return 'completed';
    } catch {
      for (const s of [...done].reverse()) {
        s.compensate();
        this.journal.push(`undid:${s.name}`);
      }
      return 'compensated';
    }
  }
}
function step(name: string, log: string[]): Step {
  return { name, run(): void { log.push(name); }, compensate(): void { log.push(`undo-${name}`); } };
}
const log: string[] = [];
const saga = new Saga([step('reserve', log), step('charge', log), step('ship', log)]);
const outcome = saga.execute();
console.log(outcome === 'completed' && log.join(',') === 'reserve,charge,ship' ? 'steps sequence' : 'flow stalls');
```

```typescript
// coordinator.begin(); /* lock inventory, lock billing, lock shipping */ // availability taxing — latency multiplying.
// // One slow party freezing all parties (participants blocking — throughput dying). Stage steps; persist progress.)
```

**Common confusion** — *"sagas are eventual consistency excuses (correctness declining)."* Sagas guaranteeing convergence (inverses staging — journals persisting (flows unwinding — consistency earning (guaranteeing funding — breaking declining); excuses skipping guarantees (halves persisting — cleanup missing (consistency breaking — trust eroding (skipping charging — correctness declining). "Excuses" describing hope (cleanup missing — halves persisting); sagas describing protocol (steps ordering — inverses naming). Stage flows (progress journaling — parties unblocking); name inverses (failures unwinding — consistency earning).

**Performance note** — staging economics: journaling costing one log per step (progress owning — recovery funding (restarts resuming — amnesia declining); lockstep equivalents costing availability (participants blocking — latency multiplying (throughput dying — judgment missing). Journal cheaply (logs — steps); lockstep never (2PC — blocking).

**Mentor note** — teach "persist progress, never lock parties" (juniors journaling one step log per long flow design lockstep-free sequencing on first hearing; distributed transactions interrogated ("how many writers?" — judging demanding per flow). Stage one flow once (steps ordering — states persisting tangible (lockstep ending — availability proving permanently). Order steps; journal progress — staging discipline in three habits, reviewed per long flow.

## 2. Compensation owning (failures unwinding — inverses naming — consistency earning)

**Definition** — compensation: named inverse per step unwinding completed work in reverse (failures unwinding — done reversing (flows retreating — consistency earning (unwinding proving — stranding ending); inverses naming — every step declaring its undo (undos stating — gaps declining (naming funding — hoping ending); consistency earning — journals proving convergence (progress showing — trust keeping (earning owning — breaking declining).

**What problem it solves** — the uncompensated trio: *inverses missing* (steps running — undos unowned (failures stranding — halves persisting (missing billing — consistency breaking); *order ignoring* (undos sequencing forward — dependencies violating (unwinding breaking — state corrupting (ignoring charging — retreat failing); *compensations throwing* (undos failing — unwinds halting (retreats stopping — journals lying (throwing costing — convergence dying). Named compensation converting stranding to unwinding (inverses stating — reverse ordering (failures retreating — consistency earning); reviewers reading every step's inverse per saga (owning proving → verifiable; missing → returned).

**Modern guidance** — the compensation lines per step (review-enforced): *failures unwinding* (done reversing — flows retreating (consistency earning — stranding ending (unwinding proving — hoping declining (retreats owning — breakage preventing); *inverses naming* (undos stating — gaps declining (steps declaring — hope ending (naming funding — stranding preventing (ownership proving — ambiguity declining); *consistency earning* (journals proving — convergence showing (trust keeping — breaking declining (earning owning — bluffing ending). Compensations idempotent (replays safe — storms surviving) — owned in [2.2](<../../sections/2. Long flows/2.2. Idempotency guarding retries.md>) (forward — resolves as units land); this leaf owns the naming, never the deduping.

```typescript
// GOOD: inverses named — failing step unwinding done work in reverse (compiled + run live).
interface Step {
  name: string;
  run(): void;
  compensate(): void;
}
class Saga {
  readonly journal: string[] = [];
  constructor(private readonly steps: Step[]) {}
  execute(): string {
    const done: Step[] = [];
    try {
      for (const s of this.steps) { s.run(); done.push(s); }
      return 'completed';
    } catch {
      for (const s of [...done].reverse()) { // reverse ordering — dependencies honoring, retreat succeeding
        s.compensate();
        this.journal.push(`undid:${s.name}`);
      }
      return 'compensated';
    }
  }
}
const log: string[] = [];
function ok(name: string): Step {
  return { name, run(): void { log.push(name); }, compensate(): void { log.push(`undo-${name}`); } };
}
const failing: Step = { name: 'charge', run(): void { throw new Error('card declined'); }, compensate(): void { log.push('undo-charge'); } };
const outcome = new Saga([ok('reserve'), failing, ok('ship')]).execute();
console.log(outcome === 'compensated' && log.join(',') === 'reserve,undo-reserve' ? 'inverses unwind' : 'strands persist');
```

```typescript
// BAD: inverses missing — steps running, undos unowned (real uncompensated shape).
// await reserve(); await charge(); await ship(); // failures stranding — halves persisting, cleanup missing.
// // charge throws → reserve held forever (unwinding absenting — consistency breaking). Name inverses; unwind reverse.)
```

**Common confusion** — *"compensation means rollback (mechanisms equating)."* Rollback atomicing units (single-writer unwinding — partials declining (atomic proving — stranding ending (rollback serving — simplicity funding); compensation sequencing inverses (done reversing — flows retreating (consistency earning — lockstep declining (sequencing funding — availability keeping). "Equating" describing confusion (mechanisms merging — contexts ignoring); judgment describing routing (writers counting — flows matching). Atomic singles (rollback owning — simplicity funding); compensate parties (inverses naming — reverse unwinding).

**Performance note** — compensation economics: naming costing one inverse per step (undos stating — gaps declining (unwinding proving — stranding ending); uncompensated equivalents costing strands (halves persisting — cleanup missing (consistency breaking — trust eroding). Name cheaply (inverses — steps); strand never (halves — hope).

**Mentor note** — teach "every step names its undo" (juniors declaring one inverse per saga step design strand-free long flows on first hearing; inverseless steps interrogated ("how does this unwind?" — owning demanding per step). Name one inverse once (undos stating — reverse ordering tangible (stranding ending — consistency proving permanently). Stage forwards; unwind reverse — compensation discipline in three habits, reviewed per saga.

## 3. Orchestration choosing (drivers deciding — choreography reacting — sizes weighing)

**Definition** — the driver choice: orchestration centralizing flow decisions in one driver (drivers deciding — steps commanding (flows owning — visibility earning (deciding proving — scattering declining); choreography reacting — autonomous parties emitting and handling events (reactions decoupling — drivers absenting (reacting funding — coupling declining); sizes weighing — step-count and ownership judging (small owning drivers — sprawling owning reactions (weighing proving — defaulting declining).

**What problem it solves** — the driver-default trio: *gods orchestrating* (drivers commanding dozens — changes funneling (ownership centralizing — teams blocking (godding billing — autonomy dying); *invisible choreographing* (reactions chaining — flows untracing (debugging guessing — ownership diffusing (invisible charging — incidents aching); *events prematureing* (brokers arriving — two-step flows distributing (ceremony billing — comprehension taxing (premature charging — judgment missing). Chosen drivers converting defaulting to weighing (small driving — sprawling reacting (visibility earning — coupling budgeting); reviewers naming the driver per long flow (choosing proving → verifiable; defaulting → returned).

**Modern guidance** — the choosing lines per long flow (review-enforced): *drivers deciding* (steps commanding — flows owning (visibility earning — scattering declining (deciding proving — godding bounding (ownership showing — debugging funding); *choreography reacting* (parties emitting — handlers reacting (drivers absenting — coupling declining (reacting funding — autonomy earning (decoupling owning — scaling serving); *sizes weighing* (step-count judging — ownership tracing (small driving — sprawling reacting (weighing proving — defaulting declining (judgment owning — ceremony refusing). Event choreography depth is owned in Domain 05 (TEXTUAL forward per unbuilt-links rule) — this leaf owns the choice, never the broker mechanics.

```typescript
// GOOD: drivers chosen — step-count and ownership routing orchestration versus choreography (compiled + run live).
type Driver = 'orchestrate' | 'choreograph';
function choose(steps: number, owners: number): Driver { // sizes weighing — step-count judging, defaulting declining
  if (owners > 1 || steps > 7) return 'choreograph'; // sprawling reacting — autonomy earning, coupling declining
  return 'orchestrate'; // small driving — visibility earning, scattering declining
}
const small = choose(3, 1);
const sprawling = choose(12, 4);
console.log(small === 'orchestrate' && sprawling === 'choreograph' ? 'choice weighs' : 'driver defaults');
```
