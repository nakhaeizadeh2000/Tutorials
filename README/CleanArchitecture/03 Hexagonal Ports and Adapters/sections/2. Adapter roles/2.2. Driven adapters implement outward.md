# 2.2. Driven adapters implement outward

## 1. Outward implementing (ports realizing — details serving — cores ignoring)

**Definition** — driven adapter: concrete technology realizing a driven port (ports realizing — needs serving (details plugging — cores ignoring (realizing proving — dictating declining); details serving — vendors obeying (products plugging — cores ruling (serving funding — owning declining); cores ignoring — use cases importing ports (drivers unheard — vendors unknown (ignoring proving — heaviness declining).

**What problem it solves** — the driver-importing trio: *cores importing* (pg drilling — SDKs arriving (vendors owning — policy obeying (importing billing — leverage inverting); *ports unimplemented* (needs unstated — adapters unowned (contracts missing — swaps hoping (unimplemented charging — direction blurring); *details dictating* (vendors deciding — cores obeying (tail wagging — dog following (dictating billing — inversion inviting). Outward implementation converting importing to realizing (details serving — cores ignoring (ports declaring — drivers obeying); reviewers finding driver imports only in adapters per flow (realizing proving → verifiable; importing → returned).

**Modern guidance** — the realizing lines per driven port (review-enforced): *ports realizing* (needs serving — details plugging (cores ignoring — vendors obeying (realizing proving — dictating declining (implementing owning — owning declining); *details serving* (vendors obeying — products plugging (cores ruling — policy deciding (serving funding — dictating ending (plugging earning — lock-in declining); *cores ignoring* (ports importing — drivers unheard (vendors unknown — heaviness declining (ignoring proving — purity keeping (direction holding — leverage owning).

```typescript
// GOOD: outward implementing — two stores realizing one port, core ignorant (compiled + run live).
interface Archive { // driven door — app needing, details serving
  put(id: string): void;
  size(): number;
}
class Register { // core deciding — ports importing, drivers unheard
  constructor(private readonly archive: Archive) {}
  add(id: string): number {
    if (id.length === 0) throw new Error('id required');
    this.archive.put(id);
    return this.archive.size();
  }
}
class MemoryArchive implements Archive { // driven adapter — details serving, cores ignoring
  private ids: string[] = [];
  put(id: string): void { this.ids.push(id); }
  size(): number { return this.ids.length; }
}
class PrefixArchive implements Archive { // second vendor — swapping earning, lock-in declining
  constructor(private readonly inner: Archive) {}
  put(id: string): void { this.inner.put(`v1:${id}`); }
  size(): number { return this.inner.size(); }
}
const a = new Register(new MemoryArchive()).add('x');
const b = new Register(new PrefixArchive(new MemoryArchive())).add('y');
console.log(a === 1 && b === 1 ? 'outward implements' : 'cores import drivers');
```

"Database" describing vendors (products plugging — details serving); driven describing sides (apps commanding — ports declaring). Persist in vendors (details serving — cores ignoring); name sides (apps commanding — details obeying).

**Performance note** — realizing economics: serving costing one implementation (details plugging — cores ignoring (vendors obeying — policy deciding); imported equivalents costing leverage (vendors owning — swaps rewriting (policy obeying — heaviness arriving). Serve cheaply (adapters — details); import never (drivers — cores).

**Mentor note** — teach "drivers live in adapters only" (juniors realizing one driven port per vendor design import-clean cores on first hearing; driver imports in cores interrogated ("which adapter?" — realizing demanding per import). Realize one port once (details serving — cores ignoring tangible (importing ending — direction proving permanently). ## 2. Vendors plugging (databases persisting — mails sending — clocks timing)

**Definition** — vendor plugging: third-party SDKs wrapped at the driven edge, mapped to domain errors (databases persisting — rows storing (queries proving — details serving (persisting funding — owning declining); mails sending — messages delivering (vendors obeying — cores ignoring (sending serving — leaking declining); clocks timing — instants providing (time owning — determinism funding (timing proving — freezing declining).

**What problem it solves** — the SDK-leaking trio: *types smuggling* (vendor shapes drilling — generics infecting (SDKs owning — policy obeying (smuggling billing — leverage inverting); *errors bubbling* (vendor codes surfacing — callers switching (details deciding — cores handling (bubbling charging — layering breaking); *lock-in hardening* (SDKs concreting — swaps rewriting (vendors dictating — migrations fearing (hardening costing — options dying). Plugged vendors converting leaking to wrapping (SDKs edging — errors mapping (details serving — cores ignoring); reviewers finding vendor imports only in wrappers per flow (plugging proving → verifiable; smuggling → returned).

**Modern guidance** — the plugging lines per vendor (review-enforced): *databases persisting* (rows storing — queries proving (details serving — cores ignoring (persisting funding — owning declining (plugging earning — lock-in declining); *mails sending* (messages delivering — vendors obeying (cores ignoring — layers holding (sending serving — leaking declining (delivery owning — exposure ending); *clocks timing* (instants providing — determinism funding (fakes sliding — tests stabilizing (timing proving — freezing declining (time owning — flakiness ending). Vendor error mapping at the wrapper (domain errors owning — SDK codes translating); seam mechanics in [ORM 01/2.2](<../../../../ORM/01 Data Access Foundations and Mental Model/sections/2. ```typescript
// GOOD: vendors plugging — SDK wrapped at the edge, domain errors owning (compiled + run live).
class VendorMailError extends Error {} // SDK owning — codes bubbling, cores handling-absent
interface Mailer { // driven door — app needing, vendors serving
  send(to: string): void;
  sent(): number;
}
class SdkMailer implements Mailer { // wrapper edging — SDK translating, cores ignoring
  private n = 0;
  constructor(private readonly fail: boolean) {}
  send(to: string): void {
    if (this.fail) throw new VendorMailError(`smtp:550 ${to}`); // SDK failing — wrapper translating, layers holding
    this.n += 1;
  }
  sent(): number { return this.n; }
}
function invite(mailer: Mailer, to: string): string { // core deciding — ports importing, SDKs unknown
  try {
    mailer.send(to);
    return 'invited';
  } catch (e) {
    if (e instanceof VendorMailError) throw new Error('mail unavailable'); // domain errors owning — SDK codes translating
    throw e;
  }
}
const ok = new SdkMailer(false);
const bad = new SdkMailer(true);
let mapped = '';
try { invite(bad, 'ops'); } catch (e) { mapped = (e as Error).message; }
console.log(invite(ok, 'ops') === 'invited' && ok.sent() === 1 && mapped === 'mail unavailable' ? 'vendors plug' : 'SDKs leak');
```

## 3. Fakes sliding (doubles honoring — suites headlessing — swaps proving)

**Definition** — fake sliding: in-memory doubles honoring driven ports, substituting vendors in suites (doubles honoring — contracts proving (behaviors matching — drifts detecting (honoring funding — lying declining); suites headlessing — tests running without vendors (servers sleeping — databases stopping (headless proving — flakes declining); swaps proving — replacements earning (vendors trading — confidence funding (proving owning — hoping ending).

**What problem it solves** — the vendor-bound trio: *suites vendoring* (tests booting — SDKs calling (feedback dying — costs billing (vendoring charging — confidence eroding); *mocks overspecifying* (interactions asserting — refactors breaking (couplings testing — behaviors missing (overspecifying billing — value declining); *swaps unproven* (vendors changing — suites databasing (substitutes missing — migrations fearing (unproven costing — lock-in hardening). Sliding fakes converting vendoring to honoring (doubles proving — suites headlessing (swaps earning — lock-in declining); reviewers substituting every driven adapter per suite (sliding proving → verifiable; vendoring → returned).

**Modern guidance** — the sliding lines per driven port (review-enforced): *doubles honoring* (contracts proving — behaviors matching (drifts detecting — lies declining (honoring funding — vendoring ending (fakes owning — mocks declining); *suites headlessing* (servers sleeping — databases stopping (feedback speeding — flakes declining (headless proving — heaviness ending (speed funding — confidence earning); *swaps proving* (replacements earning — vendors trading (confidence funding — hoping ending (proving owning — lock-in declining (trading earning — dread ending). Harness mechanics (module compiling — adapter injecting) are owned in [NestJS 05/1.1](<../../../../NestJS/05 Testing Deployment and Operations/sections/1. Testing heads/1.1. ```typescript
// GOOD: fakes sliding — queue doubles honoring one port, suites headless (compiled + run live).
interface Queue { // driven door — app needing, vendors serving
  publish(topic: string): number;
  pending(): number;
}
function queueSuite(make: () => Queue): boolean { // suite pinning — contracts asserting, swaps trusting
  const q = make();
  return q.publish('a') === 1 && q.publish('b') === 2 && q.pending() === 2;
}
class MemoryQueue implements Queue { // fake sliding — doubles honoring, suites headlessing
  private n = 0;
  publish(_topic: string): number { this.n += 1; return this.n; }
  pending(): number { return this.n; }
}
class BatchQueue implements Queue { // second vendor — swapping earning, lock-in declining
  private batches = 0;
  private count = 0;
  publish(_topic: string): number { this.count += 1; if (this.count % 2 === 0) this.batches += 1; return this.count; }
  pending(): number { return this.count; }
}
console.log(queueSuite(() => new MemoryQueue()) && queueSuite(() => new BatchQueue()) ? 'fakes slide' : 'suites vendor');
```
