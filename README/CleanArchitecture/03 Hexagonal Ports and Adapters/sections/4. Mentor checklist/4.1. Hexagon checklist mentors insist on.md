# 4.1. Hexagon checklist mentors insist on

## 1. Every port facing (sides naming — consumers owning — symmetry holding)

**Definition** — the facing gate: each port naming its side and owner, symmetry holding across the app (sides naming — driving declaring (driven stating — actors owning (naming proving — confusing declining); consumers owning — doors bordering (app centering — outside plugging (owning funding — inverting ending); symmetry holding — halves balancing (halves proving — bias declining (holding owning — breaking ending).

**What problem it solves** — the unfaced trio: *sides unnamed* (ports floating — actors missing (ownership blurring — direction hoping (unnamed billing — reviewing guessing); *adapters owning* (interfaces living outward — consumers obeying (tail wagging — leverage reversing (owning inverting — direction breaking); *halves building* (driving concreting — vendors owning (symmetry breaking — swaps rewriting (halving charging — lock-in scheduling). The gate converting floating to facing (sides naming — consumers owning (symmetry holding — halves declining); mentors asking one question per port ("which side, whose door?" — facing demanding per interface).

**Modern guidance** — the gate commands (run per port, enforced in review):

```typescript
// GOOD: facing gated — sides naming, consumers owning, symmetry holding (checklist shape).
// 1. Side proof (driving declaring — driven stating):
//    every port labeled driving or driven — actors commanding or app commanding, never neither.
// 2. Ownership proof (doors bordering — app centering):
//    every port owned by its consumer — driving by actor needs, driven by app needs, adapters never.
// 3. Symmetry proof (halves balancing — bias declining):
//    every feature naming both sides — driving commanding, driven serving, concrete absenting.
// Name sides; own consumers; hold symmetry.)
```

```typescript
// BAD: ports unfaced — sides unnamed, adapters owning (real unface shape).
// interface Store { /* which side? whose need? */ } // ownership blurring — direction hoping, reviewing guessing.
// // Adapter-owned interfaces (tail wagging — leverage reversing). Name sides; own doors; balance halves.)
```

**Common confusion** — *"gates bureaucratize design (process slowing)."* Gates evidencing facing (sides naming — consumers owning (proof reusing — judgment focusing (evidencing funding — slowing declining); missing gates slowing reviews (ports floating — direction debating (hope funding — erosion scheduling (missing charging — velocity dying). "Bureaucratizing" describing ceremony (meetings multiplying — value missing); gates describing leverage (proof reusing — incidents preventing). Gate facing (evidence funding — speed earning); design freely (exceptions pricing — contexts weighing).

**Performance note** — facing economics: gating costing seconds per port (sides naming — consumers owning (symmetry holding — halves declining); unfaced equivalents costing direction (ports floating — adapters owning (hope funding — erosion scheduling). Gate cheaply (seconds — ports); float never (unnamed — hope).

**Mentor note** — demand "side and owner stated" (juniors naming one side + one consumer per port design face-carrying reviews on first hearing; ownerless ports interrogated ("whose door?" — facing demanding per PR). Name one port once (sides stating — consumers owning tangible (floating ending — facing proving permanently). State sides; own doors — facing discipline in three habits, reviewed per port.

## 2. Every adapter translating (edges owning — cores ignoring — leaks absenting)

**Definition** — the translating gate: each adapter owning its edge translation, cores protocol-free, leaks absent (edges owning — protocols converting (outsides homing — cores shielding (owning proving — drilling declining); cores ignoring — entities consulting (ports calling (frameworks unknown — vendors unheard (ignoring funding — heaviness ending); leaks absenting — shapes staying (secrets keeping — methods missing (absenting proving — exposure ending).

**What problem it solves** — the untranslated trio: *protocols drilling* (HTTP invading — SDKs arriving (transports owning — tests heavying (drilling billing — portability dying); *cores depending* (frameworks importing — vendors dictating (direction reversing — leverage inverting (depending charging — rewrites scheduling); *shapes traveling* (entities serializing — hashes exposing (behavior leaking — secrets broadcasting (traveling billing — exposure scheduling). The gate converting drilling to translating (adapters converting — cores ignoring (leaks absenting — layers holding); mentors asking one question per adapter ("what crosses, what stays?" — translating demanding per edge).

**Modern guidance** — the gate commands (run per adapter, enforced in review):

```typescript
// GOOD: translating gated — edges owning, cores ignoring, leaks absenting (checklist shape).
// 1. Edge proof (protocols converting — cores shielding):
//    protocol and SDK types confined to adapters — grep cores for framework/vendor imports, expect zero.
// 2. Ignorance proof (entities consulting — ports calling):
//    cores importing entities and ports only — direction inward, outward edges absenting.
// 3. Leak proof (shapes staying — secrets keeping):
//    no entity or vendor shape crossing an edge unmapped — DTOs validating, mappers translating, always.
// Translate at edges; ignore in cores; absent leaks.)
```

```typescript
// BAD: adapters untranslating — protocols drilling, shapes traveling (real untranslated shape).
// import { Pool } from 'pg'; // inside the use case — vendors owning, policy obeying.
// return this.repo.find(); // entities traveling — hashes exposing, behavior leaking.
// } // Gate translation: edges owning, cores ignoring, leaks absenting.)
```

**Common confusion** — *"zero-import cores are purism (discipline posturing)."* Purism banning tools (libraries refusing — work rebuilding (posturing serving — value missing (banning charging — pragmatism declining); ignorance deferring frameworks (vendors edging — policy deciding (direction holding — leverage keeping (deferring funding — heaviness ending). "Purism" describing refusal (tools banning — work rebuilding); gates describing direction (frameworks deferring — policy deciding). Defer frameworks (direction holding — leverage keeping); use libraries (tools funding — rules owning).

**Performance note** — translating economics: gating costing one grep (protocols confining — leaks detecting (cores ignoring — layers holding); drilled equivalents costing portability (transports owning — tests heavying (binding billing — reuse dying). Gate cheaply (greps — edges); drill never (protocols — cores).

**Mentor note** — demand "import list per core file" (juniors proving one ignorance list per core design leak-free reviews on first hearing; unexamined cores interrogated ("show me the imports" — translating demanding per file). Prove one core once (entities consulting — ports calling tangible (drilling ending — ignorance proving permanently). Own edges; ignore cores — translating discipline in three habits, reviewed per adapter.

## 3. Every contract pinned (suites asserting — doubles honoring — drift detecting)

**Definition** — the pinning gate: each port contract asserted by a shared suite that every adapter passes (suites asserting — behaviors stating (implementations proving — doubles honoring (asserting funding — bespoke declining); doubles honoring — fakes sliding (vendors substituting — suites headlessing (honoring proving — lying declining); drift detecting — breakages surfacing (changes flagging — silence ending (detecting funding — masking preventing).

**What problem it solves** — the unpinned trio: *suites bespeaking* (per-adapter copies — assertions drifting (maintenance doubling — consistency failing (bespeaking billing — trust eroding); *adapters assuming* (vendors shipping — contracts hoping (behaviors bluffing — swaps fearing (assuming charging — incidents scheduling); *doubles lying* (contracts skipping — behaviors bluffing (suites greening — confidence lying (lying costing — trust eroding). The gate converting bespoke to pinned (suites sharing — adapters proving (doubles honoring — drift detecting); mentors asking one question per vendor ("which suite run?" — pinning demanding per merge).

**Modern guidance** — the gate commands (run per port, enforced in CI):

```typescript
// GOOD: pinning gated — suites asserting, doubles honoring, drift detecting (checklist shape).
// 1. Suite proof (behaviors stating — implementations proving):
//    one shared suite per port — happy path plus error parity, versioned with the port.
// 2. Passage proof (vendors passing — doubles sliding):
//    every adapter green on the suite before merging — fakes, vendors, and replacements alike.
// 3. Drift proof (breakages surfacing — changes flagging):
//    suite failing blocks merges — unproven adapters never shipping, swaps never hoping.
// Assert contracts; pass adapters; detect drift.)
```

```typescript
// BAD: contracts unpinned — suites bespeaking, adapters assuming (real unpinned shape).
// // New vendor merged without suite (implementations assuming — swaps fearing — incidents scheduling).
// // Copies drifting (assertions diverging — maintenance doubling). Pin suites; gate adapters; detect drift.)
```

**Common confusion** — *"pinning slows vendor onboarding (gates blocking)."* Pinning guiding onboarding (suites stating — behaviors showing (vendors implementing — confidence earning (guiding funding — blocking declining); unpinned onboarding slowing debugging (contracts hoping — behaviors bluffing (incidents arriving — recovery paging (slowing charging — shipping declining). "Blocking" describing ceremony (approvals queuing — value missing); pinning describing guidance (contracts stating — adapters proving). Guide with suites (behaviors stating — vendors implementing); onboard faster (confidence earning — incidents declining).

**Performance note** — pinning economics: asserting costing one suite (behaviors stating — adapters proving (drift detecting — incidents declining); unpinned equivalents costing incidents (breakages arriving — confidence lying (trust eroding — recovery paging). Assert cheaply (suites — ports); bespoke never (copies — drift).

**Mentor note** — demand "suite link in the PR" (juniors pinning one contract run per vendor design drift-proof reviews on first hearing; suiteless vendors interrogated ("which run?" — pinning demanding per merge). Pin one contract once (suites asserting — adapters proving tangible (bespoke ending — drift detecting permanently). Share suites; pass adapters — pinning discipline in three habits, reviewed per port.
