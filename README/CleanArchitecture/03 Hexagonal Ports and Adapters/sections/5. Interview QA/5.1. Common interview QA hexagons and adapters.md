# 5.1. Common interview QA hexagons and adapters

## 1. Sides live under pressure (driving, driven, symmetry — diagnosed with fixes, priced)

**Definition** — side answers: driving commanding, driven serving, symmetry holding — under pressure (diagnosed with fixes — causes naming (understanding proving — reciting declining); priced with trade-offs — doors billing (judgment owning — dogma refusing (pricing funding — honesty earning).

**What problem it solves** — the reciting trio: *sides listing* ("driving and driven" stating — actors missing (vocabulary showing — ownership absenting (reciting funding — designing declining); *hexagons drawing* (shapes sketching — doors unowned (pictures serving — symmetry unproven (drawing proving — grounding declining); *symmetry chanting* ("both sides equal" repeating — swaps unnamed (words owning — leverage missing (chanting proving — paying declining). Diagnosed answers converting reciting to designing (causes naming — fixes stating (understanding proving — chanting declining); interviewers hiring designers, not chanters (diagnosing proving → hirable; reciting → passed).

**Modern guidance** — answer shape per side question (diagnose → fix → price):

```typescript
// GOOD: "Driving vs driven?" — diagnosed with fixes, priced (answer shape).
// Diagnose: half-hexagons (controllers porting — repositories concreting — swaps rewriting).
// Fix: driving facing actors (users commanding — CLIs invoking); driven facing details (stores persisting — mails sending).
// Price: two doors per feature (symmetry holding — vendors deferring); swaps named per port (leverage keeping — dread ending).
// Name sides; face ports — symmetry stated, not hoped.)
```

```typescript
// BAD: sides reciting — vocabulary stating, actors missing (real weak shape).
// "Driving is input, driven is output." (actors missing — needs unowned — designing declining).
// "Hexagonal has six sides." (geometry counting — symmetry unproven — grounding declining).
// Diagnose causes; state fixes; price honestly.)
```

**Common confusion** — *"side answers need diagrams (pictures impressing)."* Diagrams picturing symmetry (doors showing — vendors deferring (pictures serving — bias declining (picturing funding — grounding refusing); answers proving judgment (causes naming — fixes stating (costs pricing — trade-offs owning (proving funding — reciting declining). "Diagrams" describing pictures (shapes sketching — doors unowned); answers describing design (ownership stating — prices itemizing). Diagnose causes (understanding proving — chanting declining); price fixes (judgment owning — dogma refusing).

**Performance note** — answer economics: diagnosing costing one cause per question (understanding proving — reciting declining (hirable funding — chanting ending); recited equivalents costing offers (words owning — actors missing (designing declining — hiring passing). Diagnose cheaply (causes — fixes); recite never (jargon — passes).

**Mentor note** — drill "diagnose, fix, price" (juniors answering one side question per shape design hirable responses on first hearing; vocabulary-only answers interrogated ("which actor?" — diagnosing demanding per answer). Shape one answer once (causes naming — fixes stating tangible (reciting ending — designing proving permanently). Diagnose causes; price fixes — answering discipline in three habits, reviewed per mock.

## 2. Adapters live under pressure (translating, plugging, swapping — honesty stated, not hoped)

**Definition** — adapter answers: driving translating, driven plugging, vendors swapping — honestly (honesty stating — contexts weighing (judgment owning — dogma refusing (stating funding — hoping ending); protocols converting (requests shaping — SDKs edging (cores shielding — leaks declining (converting proving — drilling ending).

**What problem it solves** — the handwaving trio: *adapters gesturing* ("thin layer" claiming — translation missing (words owning — protocols drilling (gesturing proving — shielding declining); *vendors assuming* ("we use postgres" stating — ports absenting (products naming — doors missing (assuming billing — symmetry breaking); *swaps hoping* ("we could switch" claiming — suites missing (hope funding — confidence absenting (hoping costing — lock-in hardening). Honest answers converting gesturing to translating (protocols converting — vendors edging (swaps proving — leaks declining); interviewers hiring translators, not gesturers (converting proving → hirable; gesturing → passed).

**Modern guidance** — answer shape per adapter question (show → wrap → prove):

```typescript
// GOOD: "What makes a good adapter?" — shown, wrapped, proven (answer shape).
// Show: translation owning (protocols converting — SDKs edging — cores shielding).
// Wrap: vendors quarantining (imports confining — errors mapping — cores ignoring).
// Prove: suites passing (contracts asserting — adapters proving — swaps trusting).
// Translate edges; quarantine vendors — honesty stated, not hoped.)
```

```typescript
// BAD: adapters handwaving — thin claiming, translation missing (real vague shape).
// "Adapters connect things." (protocols drilling — cores frameworking — shielding declining).
// "We could swap anytime." (suites missing — hope funding — lock-in hardening).
// Show translation; wrap vendors; prove swaps.)
```

**Common confusion** — *"honesty means trashing adapters (cynicism performing)."* Honesty pricing translation (protocols converting — vendors edging (swaps proving — leaks declining (pricing funding — hoping ending); cynicism dismissing work (adapters mocking — effort denying (sneering serving — value missing (dismissing charging — progress stopping). "Cynicism" describing sneer (work mocking — value denying); honesty describing pricing (translation owning — swaps proving). Price translation (protocols converting — cores shielding); respect adapters (edges owning — leaks preventing).

**Performance note** — honesty economics: translating costing one adapter (protocols converting — cores shielding (leaks declining — trust earning); gestured equivalents costing leaks (transports owning — SDKs arriving (portability dying — leverage inverting). Translate cheaply (adapters — edges); gesture never (words — leaks).

**Mentor note** — drill "show, wrap, prove" (juniors answering one adapter question per shape design hirable responses on first hearing; connects-things answers interrogated ("what crosses?" — translating demanding per answer). Shape one answer once (protocols converting — vendors edging tangible (gesturing ending — translating proving permanently). Convert protocols; quarantine vendors — adapter discipline in three habits, reviewed per mock.

## 3. Contracts live under pressure (suites, doubles, drift — ownership stated, not hoped)

**Definition** — contract answers: suites pinning, doubles honoring, drift surfacing — ownership stated (crossings homing — layers holding (ownership proving — bespoke declining); not hoped (runs asserting — failures blocking (evidence funding — wishing ending (stating serving — hoping declining).

**What problem it solves** — the unpinned trio: *suites bespeaking* (copies duplicating — assertions drifting (maintenance doubling — consistency failing (bespeaking billing — trust eroding); *doubles vendor-locking* (suites booting — SDKs calling (feedback dying — costs billing (locking charging — confidence eroding); *drift denying* (changes landing — suites greening (breakages masking — confidence lying (denying costing — incidents scheduling). Owned answers converting bespoke to pinned (suites sharing — adapters proving (doubles honoring — drift detecting); interviewers hiring owners, not hopers (pinning proving → hirable; bespoke → passed).

**Modern guidance** — answer shape per contract question (share → honor → gate):

```typescript
// GOOD: "How do you test ports?" — shared, honored, gated (answer shape).
// Share: one suite per port (behaviors stating — implementations proving — doubles honoring).
// Honor: fakes sliding (contracts proving — suites headlessing — speed funding).
// Gate: adapters passing (vendors proving — swaps trusting — drift detecting).
// Pin contracts; pass adapters — ownership stated, not hoped.)
```

```typescript
// BAD: contracts hoping — suites bespeaking, doubles locking (real hopeful shape).
// "Each adapter has its own tests." (assertions drifting — maintenance doubling — proving declining).
// "Mocks verify calls." (interactions asserting — refactors breaking — behaviors missing).
// Share suites; honor contracts; gate adapters.)
```

**Common confusion** — *"contract answers test process (ceremony recalling)."* Process describing gates (suites asserting — merges blocking (gates serving — incidents declining (process funding — hope ending); contracts describing portability (behaviors stating — adapters proving (swaps trusting — drifts detecting (contracts owning — bespoke declining). "Process" describing enforcement (runs asserting — failures blocking); contracts describing ownership (crossings homing — layers holding). Enforce gates (suites asserting — merges blocking); own contracts (behaviors stating — swaps trusting).

**Performance note** — contract economics: pinning costing one suite (behaviors stating — adapters proving (drift detecting — incidents declining); bespoken equivalents costing maintenance (copies multiplying — assertions drifting (consistency failing — trust eroding). Pin cheaply (suites — ports); bespoke never (copies — drift).

**Mentor note** — drill "share, honor, gate" (juniors answering one contract question per shape design ownership-stated responses on first hearing; own-tests answers interrogated ("which shared suite?" — owning demanding per port). Shape one answer once (suites sharing — adapters proving tangible (bespoke ending — pinning proving permanently). State contracts; show runs — contract discipline in three habits, reviewed per mock.
