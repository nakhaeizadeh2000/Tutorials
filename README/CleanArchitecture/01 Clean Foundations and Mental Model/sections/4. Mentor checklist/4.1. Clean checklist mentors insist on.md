# 4.1. Clean checklist mentors insist on

## 1. Every dependency points inward (imports proving — outward edges absenting — lint confirming)

**Definition** — the direction gate: no merge landing with an outward-pointing dependency (imports proving — edges asserting (direction holding — erosion detecting); outward edges absenting — inner files clean of outer names (ignorance keeping — leverage holding); lint confirming — automation gating, humans judging (CI blocking — reviews trusting).

**What problem it solves** — the unreviewed-arrow trio: *shortcuts landing* ("just this once" importing — precedents multiplying (erosion compounding — rules hollowing); *ownership blurring* (ports living outward — consumers obeying (tail wagging — leverage inverting); *decay scheduling* (arrows reversing file by file — big-balling arriving (discipline fading — rewrites looming). The gate converting hope to proof (graphs asserting — lint blocking (merges proving — decay preventing); mentors asking one question per review ("show me the arrows" — direction demanding per merge).

**Modern guidance** — the gate commands (run per merge, enforced in CI):

```typescript
// GOOD: direction gated — arrows proving, lint confirming, merges blocking (checklist shape).
// 1. Graph check (ownership proving — direction holding):
//    npx depcruise src --config .dependency-cruiser.json  // violations failing — merges blocking.
// 2. Import grep (ignorance keeping — leaks detecting):
//    grep -rn "@nestjs\|typeorm\|express\|fastify" src/domain/ && echo LEAK || echo CLEAN
// 3. Port ownership (consumers owning — providers obeying):
//    every port file imported by its consumer first — adapters second, never first.
// Gate green → merge; gate red → return.)
```

```typescript
// BAD: arrows hoping — shortcuts landing, decay scheduling (real gate-missing shape).
// // "just this once" import (precedents multiplying — erosion compounding — rules hollowing).
// // No CI gate (violations landing — direction blurring — hope funding).
// // Ports living outward (consumers obeying — leverage inverting). Gate merges; prove arrows.)
```

**Common confusion** — *"checklists slow teams down (process taxing)."* Gates speeding reviews (output reading — hunts skipping (evidence funding — confidence earning (speed proving — tax declining); missing gates slowing merges (imports hunting — direction debating (hope funding — erosion scheduling (slowness charging — rewrites looming). "Slowing" describing ceremony (meetings multiplying — value missing); checklists describing leverage (proof reusing — judgment focusing). Gate mechanically (evidence funding — speed earning); judge humanly (exceptions pricing — contexts weighing).

**Performance note** — gate economics: checking costing seconds per merge (graphs asserting — lint blocking (decay preventing — confidence earning); ungated equivalents costing rewrites (shortcuts accumulating — big-balling arriving (erosion scheduling — rewrites looming). Gate cheaply (seconds — merges); hope never (erosion — rewrites).

**Mentor note** — demand "gate output in the PR" (juniors pasting one graph result per merge design proof-carrying reviews on first hearing; arrow claims without evidence interrogated ("gate green?" — proof demanding per PR). Prove one merge once (graphs asserting — lint blocking tangible (hope ending — discipline proving permanently). Show arrows; block red — gate discipline in three habits, reviewed per merge.

## 2. Every use case owns one intent (single public method — ports declaring — framework absenting)

**Definition** — the intent gate: each use-case class owning exactly one intent through one public method (single owning — methods proving (intents homing — sprawl ending); ports declaring — needs stating per consumer (shapes bounding — details deferring); framework absenting — cores import-clean, edges translating (ignorance keeping — portability earning).

**What problem it solves** — the intent-scatter trio: *methods multiplying* (managers managing — helpers helping (ownership blurring — reuse hoping); *cores frameworking* (@Req drilling — @Entity colonizing (transports owning — tests heavying); *ports concretizing* (PgStore importing — fakes declining (vendors owning — swaps rewriting). The gate converting scatter to ownership (one class owning — one method proving (ports declaring — frameworks absenting); mentors asking one question per class ("which intent?" — ownership demanding per file).

**Modern guidance** — the gate commands (run per class, enforced in review):

```typescript
// GOOD: intent gated — methods counting, ports declaring, frameworks absenting (checklist shape).
// 1. Method count (ownership proving — sprawl ending):
//    one public method per use-case class — execute/handle naming, seconds stating intent.
// 2. Port declaration (needs stating — details deferring):
//    every external need behind a consumer-owned interface — adapters implementing, never imported.
// 3. Framework absence (ignorance keeping — portability earning):
//    grep -rn "@nestjs\|typeorm\|express\|fastify\|http" src/core/ && echo LEAK || echo CLEAN
// One intent → own; two intents → split; frameworks → edge.)
```

```typescript
// BAD: intents scattering — methods multiplying, cores frameworking (real scatter shape).
// class OrderManager { create() {} update() {} delete() {} email() {} } // ownership blurring — reuse hoping.
// import { Req } from '@nestjs/common'; // transports owning — tests heavying, portability dying.
// } // Own intents: one class owning, one method proving, ports declaring.)
```

**Common confusion** — *"one method means one line (simplicity confusing)."* One method owning intent (flows composing — decisions delegating (ownership proving — scattering ending (owning funding — sprawl declining); lines following complexity (steps sequencing — ports calling (work serving — intent funding (lines earning — bloat declining). "One line" describing size (brevity measuring — work ignoring); one method describing ownership (intents homing — flows proving). Own intents (methods proving — sprawl ending); spend lines (complexity serving — intent funding).

**Performance note** — intent economics: owning costing one class per intent (flows composing — decisions delegating (ownership proving — scattering ending); scattered equivalents costing hunts (reads jumping — edits hunting (ownership blurring — reuse hoping). Own cheaply (classes — intents); scatter never (managers — hunts).

**Mentor note** — demand "intent in the name" (juniors naming one use case per intent design self-describing cores on first hearing; manager/service names interrogated ("which intent?" — ownership demanding per class). Name one intent once (methods proving — ports declaring tangible (scatter ending — ownership proving permanently). Name intents; absent frameworks — intent discipline in three habits, reviewed per class.

## 3. Every entity guards itself (invariants holding — constructors proving — DTOs translating)

**Definition** — the guarding gate: each entity constructing only valid states and transitioning only legal moves (invariants holding — rules living (validity proving — corruption declining); constructors proving — invalid throwing at birth (states narrowing — auditing declining); DTOs translating — edges validating, mappers building (shapes carrying — layers holding).

**What problem it solves** — the unguarded trio: *construction corrupting* (negative totals — empty names (garbage persisting — trust eroding); *transitions skipping* (setters exposing — states jumping (invariants breaking — bypass funding); *edges leaking* (entities traveling — hashes exposing (behavior leaking — secrets broadcasting). The gate converting corruption to impossibility (constructors throwing — transitions checking (DTOs translating — layers holding); mentors asking one question per model ("how is invalid unbuildable?" — guarding demanding per entity).

**Modern guidance** — the gate commands (run per model, enforced in review):

```typescript
// GOOD: guarding gated — constructors throwing, transitions checking, DTOs translating (checklist shape).
// 1. Construction proof (states narrowing — corruption unborn):
//    every constructor throwing on invalid input — tests asserting throws, never hoping.
// 2. Transition proof (rules living — bypass declining):
//    every mutation a checked method — no public setters on guarded fields, ever.
// 3. Edge proof (layers holding — exposure ending):
//    no entity returned from a controller — DTOs validating, mappers translating, always.
// Invalid unbuildable → guard; setters public → return; entities traveling → map.)
```

```typescript
// BAD: guarding hoping — construction corrupting, edges leaking (real unguarded shape).
// class Seat { constructor(public id: string, public booked = false) {} } // corruption storing — validity hoping.
// return this.seatRepo.find(); // entities traveling — behavior leaking, secrets broadcasting.
// } // Guard models: constructors throwing, transitions checking, DTOs translating.)
```

**Common confusion** — *"guards belong in validation pipes (edges centralizing)."* Pipes validating shapes (contracts bounding — garbage declining (transport serving — handlers assuming (validating proving — trust earning); entities guarding invariants (rules living — states narrowing (policy owning — validity holding (guarding funding — corruption preventing). "Centralizing" describing ownership (rules homing — drift ending); guards describing layers (shapes proving — invariants holding). Pipe shapes (edges validating — garbage declining); guard invariants (entities throwing — corruption unborn).

**Performance note** — guarding economics: proving costing one throw-test per invariant (states narrowing — corruption unborn (guarding funding — auditing declining); unguarded equivalents costing corruption (garbage persisting — queries filtering (validity hoping — trust eroding). Prove cheaply (throws — tests); hope never (scattering — corruption).

**Mentor note** — demand "invalid unbuildable" (juniors throwing one guard per entity design corruption-proof models on first hearing; setter-exposed fields interrogated ("which transition?" — guarding demanding per field). Guard one model once (construction throwing — transitions checking tangible (corruption ending — trust proving permanently). Throw early; translate edges — guarding discipline in three habits, reviewed per model.
