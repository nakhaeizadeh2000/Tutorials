# 3.1. Entities own rules DTOs carry data

## 1. Entities enforce invariants (rules living — constructors guarding — invalid states unrepresentable)

**Definition** — entity: business-rule object with identity, guarding its own invariants (rules living — methods transitioning (logic homing — validity holding (living proving — scattering ending); constructors guarding — invalid construction throwing (states unrepresentable — corruption unborn (guarding funding — trust earning); invalid states unrepresentable (types narrowing — transitions checking (impossible unbuilding — errors unreaching).

**What problem it solves** — the unguarded trio: *states representing invalid* (negative totals persisting — empty names saving (corruption storing — queries filtering-garbage (validity hoping — trust eroding); *validation scattering* (controllers checking — services rechecking (rules duplicating — drift growing (ownership missing — changes multiplying); *guards bypassing* (setters exposing — fields publicing (transitions skipping — invariants breaking (bypass funding — corruption arriving). Guarding entities converting hope to impossibility (constructors guarding — methods transitioning (rules living — states narrowing); reviewers trusting construction, not auditing callers (guarding proving → verifiable; scattering → returned).

**Modern guidance** — the guarding lines per entity (review-enforced): *rules living* (methods transitioning — logic homing (validity holding — scattering ending (living proving — drifting declining); *constructors guarding* (invalid throwing — states narrowing (corruption unborn — trust earning (guarding funding — auditing declining); *invalid states unrepresentable* (types narrowing — transitions checking (impossible unbuilding — errors unreaching (narrowing proving — hoping ending).

```typescript
// GOOD: invariants guarding — construction throwing, transitions checking (compiled + run live).
class Seat { // entity deciding — rules living, invalid states unrepresentable
  private booked = false;
  constructor(readonly id: string) {
    if (id.length === 0) throw new Error('id required'); // constructor guarding — corruption unborn
  }
  book(): void { // transition checking — states narrowing, bypass declining
    if (this.booked) throw new Error('already booked');
    this.booked = true;
  }
  get isBooked(): boolean { return this.booked; }
}
let guards = 0;
try { new Seat(''); } catch { guards += 1; } // invalid unrepresentable — construction throwing
const seat = new Seat('A1');
seat.book();
try { seat.book(); } catch { guards += 1; } // double-book impossible — transition checking
console.log(guards === 2 && seat.isBooked ? 'invariants hold' : 'entity leaks');
```

**Common confusion** — *"entities are database rows (tables modeling)."* Rows storing snapshots (columns persisting — queries returning (storage serving — history keeping (storing funding — deciding declining); entities deciding rules (invariants guarding — transitions checking (policy owning — frameworks ignoring (deciding proving — storing declining). "Rows" describing persistence (tables modeling — mappers translating); entities describing policy (rules living — validity holding). Decide in entities (rules guarding — states narrowing); store in rows (mappers translating — snapshots keeping).

**Performance note** — guarding economics: throwing costing one branch (states narrowing — corruption unborn (guarding funding — auditing declining); unguarded equivalents costing corruption (garbage persisting — queries filtering (validity hoping — trust eroding). Guard cheaply (constructors — branches); hope never (scattering — corruption).

**Mentor note** — teach "make invalid unbuildable" (juniors guarding one constructor per entity design corruption-proof policy on first hearing; public setters interrogated ("which transition?" — guarding demanding per mutation). Guard one entity once (construction throwing — transitions checking tangible (invalid ending — trust proving permanently). Live rules; narrow states — guarding discipline in three habits, reviewed per entity.

## 2. DTOs carry across (shapes validating — mappers translating — layers never leaking)

**Definition** — DTO (data transfer object): validated shape crossing one boundary (shapes validating — edges proving (contracts bounding — garbage declining (validating funding — trust earning); mappers translating (DTO mapping — entities building (translation owning — leaking preventing (mapping proving — coupling declining); layers never leaking (entities staying — ORM hiding (secrets keeping — methods absenting (holding proving — exposure ending).

**What problem it solves** — the leaking trio: *entities traveling* (methods serializing — hashes exposing (behavior leaking — secrets broadcasting (traveling billing — exposure scheduling); *ORM shaping APIs* (columns dictating — relations nesting (vendors owning — clients coupling (persistence deciding — contracts breaking); *validation missing* (any accepting — garbage entering (handlers assuming-broken — corruption arriving (missing charging — trust eroding). Carrying DTOs converting leaking to translating (shapes validating — mappers translating (layers holding — exposure ending); reviewers seeing validation at every edge (carrying proving → verifiable; leaking → returned).

**Modern guidance** — the carrying lines per boundary (review-enforced): *shapes validating* (edges proving — contracts bounding (garbage declining — trust earning (validating proving — assuming funding); *mappers translating* (DTO mapping — entities building (translation owning — leaking preventing (mapping funding — coupling declining (translating owning — exposure ending); *layers never leaking* (entities staying — ORM hiding (secrets keeping — methods absenting (holding proving — exposure ending (discipline owning — breach declining). Pipe mechanics at the Nest edge are owned in [NestJS 02/3.1](<../../../../NestJS/02 Controllers Routing and Validation/sections/3. Input proof/3.1. Validation pipes from params to bodies.md>) — this leaf owns the mapping, never the pipes.

```typescript
// GOOD: shapes carrying — edge validating, mapper translating, layers holding (compiled + run live).
interface CreateOrderDto { // DTO carrying — validated shape, methods absenting
  total: number;
}
class Order { // entity deciding — rules living, edges unknown
  constructor(readonly total: number) {
    if (total <= 0) throw new Error('total must be positive');
  }
}
function toOrder(raw: unknown): Order { // mapper translating — validation owning, leaking preventing
  if (typeof raw !== 'object' || raw === null) throw new Error('shape invalid');
  const total = (raw as { total: unknown }).total;
  if (typeof total !== 'number') throw new Error('total must be a number'); // shapes validating — garbage declining
  return new Order(total); // entities building — layers never leaking
}
const dto: CreateOrderDto = { total: 9 };
let rejected = 0;
try { toOrder({ total: 'nine' }); } catch { rejected += 1; } // garbage declining — validation proving
const order = toOrder(dto);
console.log(rejected === 1 && order.total === 9 ? 'dto carries' : 'boundary leaks');
```

## 3. Anemic models declined (getters-only scattering — behavior homing — richness earning)

**Definition** — anemic model (Fowler's term): data-only object with behavior living in external services (getters scattering — setters exposing (data holding — logic absenting (anemia describing — richness declining); behavior homing (methods transitioning — rules guarding (logic owning — validity holding (homing funding — scattering ending); richness earning (objects deciding — services arranging (deciding proving — scripting declining).

**What problem it solves** — the procedural trio: *services scripting* (managers manipulating — helpers computing (behavior homeless — objects dumb (scripting billing — objects declining); *feature envying* (services reaching — getters feeding (coupling growing — cohesion fading (envy charging — design blurring); *rules duplicating* (every caller rechecking — guards reimplementing (ownership missing — drift growing (duplication multiplying — consistency failing). Rich models converting scripting to homing (behavior owning — data guarding (objects deciding — services arranging); reviewers finding each rule beside its data (homing proving → verifiable; scripting → returned).

**Modern guidance** — the richness lines per model (review-enforced): *getters-only scattering declined* (data hiding — behavior homing (scattering ending — cohesion funding (declining proving — scripting refusing); *behavior homing* (methods transitioning — rules guarding (logic owning — validity holding (homing funding — envy ending (objects deciding — services arranging); *richness earning* (deciding proving — scripting declining (earning owning — anemia refusing (judgment serving — dogma declining). Homing where data lives (transitions beside fields — guards beside constructors); scripting only where flows arrange (use cases orchestrating — entities deciding).

```typescript
// GOOD: behavior homing — cart guarding quantities, computing totals (compiled + run live).
class Cart { // rich model — behavior owning, data guarding
  private lines: Array<{ price: number; qty: number }> = [];
  add(price: number, qty: number): void { // transition owning — rules living, callers trusting
    if (price <= 0 || qty <= 0) throw new Error('positive only');
    if (qty > 99) throw new Error('line cap 99');
    this.lines.push({ price, qty });
  }
  total(): number { // behavior homing — computation owning, envy ending
    return this.lines.reduce((a, l) => a + l.price * l.qty, 0);
  }
}
const cart = new Cart();
cart.add(10, 2);
cart.add(5, 1);
let capped = 0;
try { cart.add(1, 100); } catch { capped += 1; } // guards homing — callers trusting, rechecking absenting
console.log(cart.total() === 25 && capped === 1 ? 'rich decides' : 'model anemic');
```
