# 1.1. What clean architecture is and is not

## 1. Architecture owns decisions (policy separated — frameworks deferring — details depending inward)

**Definition** — clean architecture: business policy (entities deciding — use cases orchestrating) separated from delivery details (frameworks serving — databases persisting) by pointing every dependency inward (outer knowing inner — inner ignorant of outer). Frameworks deferring (NestJS wiring — Fastify serving — vendors plugging, never dictating); details depending inward (adapters implementing ports — ports owned by policy — direction enforcing).

**What problem it solves** — the framework-coupled trio: *rules scattering* (validation in controllers — totals in SQL — discounts in the frontend (ownership missing — changes rippling (edits multiplying — reviews guessing (consistency failing — trust eroding); *vendors dictating* (ORM entities as domain — HTTP shapes as contracts (swap costing rewrites — upgrades breaking (migration fearing — versions pinning (leverage inverting — tail wagging); *tests needing everything* (databases booting — servers listening (suites slowing — flakes growing (feedback dying — coverage lying). Owned policy converting coupling to direction (entities deciding — use cases orchestrating (adapters plugging — frameworks deferring); reviewers checking import arrows, not folder depth (direction proving → verifiable; scattering → returned).

**Modern guidance** — the separation lines per feature (review-enforced): *policy separated* (entities guarding — use cases orchestrating (rules homing — decisions owning (tests running headless — speed funding (ownership proving — drift ending); *frameworks deferring* (NestJS registering — Fastify serving (vendors plugging — details swapping (deferral owning — leverage keeping (upgrades boring — migrations cheap); *details depending inward* (adapters implementing — ports declaring (direction holding — ignorance keeping (enforcement owning — coupling declining).

```typescript
// GOOD: policy deciding — use case depending on a port, adapters plugging in (compiled + run live).
interface OrderStore { // port owned inward — details implementing, never dictating
  save(total: number): void;
  total(): number;
}

class Order { // entity deciding — invariant guarding, frameworks absenting
  constructor(readonly total: number) {
    if (total <= 0) throw new Error('total must be positive'); // invalid states unrepresentable
  }
}

class PlaceOrder { // use case orchestrating — one intent, one public method
  constructor(private readonly store: OrderStore) {}
  execute(total: number): number {
    const order = new Order(total); // entity deciding — use case orchestrating
    this.store.save(order.total);
    return this.store.total();
  }
}

class MemoryStore implements OrderStore { // adapter plugging — swappable behind the port
  private sum = 0;
  save(total: number): void { this.sum += total; }
  total(): number { return this.sum; }
}

const placed = new PlaceOrder(new MemoryStore()).execute(42);
console.log(placed === 42 ? 'policy decides' : 'policy broken');
```

```typescript
// BAD: details deciding — framework imported in the use case, policy obeying (real coupling shape).
// import { Entity, Column } from 'typeorm'; // ORM owning the rule — vendors dictating, policy obeying.
// import { Controller } from '@nestjs/common'; // HTTP owning the intent — handlers deciding, reuse absenting.
// class OrderService { // name promising process — framework delivering, tests needing databases.
//   async place(total: number) { /* raw SQL + res.status(200) inline */ } // layers collapsing — decisions scattering.
// } // Decide inward: entities guarding, use cases orchestrating, adapters plugging.)
```

**Common confusion** — *"clean architecture means many folders (layers multiplying)."* Folders organizing direction (layers separating — arrows pointing inward (structure serving — decisions owning (separation proving — coupling declining); direction owning meaning (outer knowing — inner ignoring (policy deciding — details deferring (inversion funding — swapability earning). "Folders" describing containers (files grouping — names labeling); architecture describing dependencies (imports pointing — knowledge flowing). Point inward (direction enforcing — ignorance keeping); folder honestly (names screaming — use cases shouting).

**Performance note** — separation economics: deciding costing a port interface (methods declaring — adapters implementing (direction holding — swapability earning); coupled equivalents costing rewrites (vendors dictating — migrations fearing (upgrades breaking — leverage inverting). Declare cheaply (interfaces — ports); depend inward (arrows — policy).

**Mentor note** — teach "policy decides, details defer" (juniors drawing one inward arrow per feature design direction-owned code on first hearing; framework imports in use cases interrogated ("which port?" — direction demanding per feature). Decide one policy once (entity guarding — use case orchestrating tangible (coupling ending — ownership proving permanently). Separate policy; defer details — architectural discipline in three habits, reviewed per feature.

## 2. Screaming structure (folders shouting use cases — not frameworks — intent readable)

**Definition** — screaming architecture (Martin's term): a project's top-level folders shouting its intent — `orders/place-order` readable, `controllers/services/entities` silent about purpose (folders shouting use cases — features owning (intent reading — onboarding speeding (screaming proving — guessing ending); frameworks whispering (adapters grouping — vendors naming (details serving — noise declining).

**What problem it solves** — the layered-by-kind trio: *intent hiding* (controllers/ holding forty handlers — services/ holding sixty classes (features scattering — ownership blurring (reads jumping — edits hunting (onboarding aching — velocity dying); *changes rippling* (one feature touching five kind-folders — reviews spanning (blast growing — conflicts rising (isolation missing — cadence coupling); *frameworks shouting* (typeorm/ first — fastify/ loudest (vendors branding — policy whispering (leverage inverting — upgrades fearing). Screaming folders converting hunting to reading (features owning — use cases shouting (adapters grouping — intent proving); reviewers opening one folder per feature (screaming proving → verifiable; scattering → returned).

**Modern guidance** — the screaming lines per feature (review-enforced): *folders shouting use cases* (place-order naming — order owning (intent reading — onboarding speeding (features proving — hunting ending); *frameworks whispering* (adapters grouping — vendors naming (details serving — noise declining (deferral showing — leverage keeping); *intent readable* (names deciding — structures screaming (reviews opening — ownership proving).

```typescript
// GOOD: structure screaming — features shouting use cases, frameworks whispering (compiled + run live).
const layout = [ // folders shouting intent — reviewers reading features, not frameworks
  'orders/place-order.use-case.ts',
  'orders/order.entity.ts',
  'orders/order-store.port.ts',
  'orders/memory-store.adapter.ts',
  'orders/orders.controller.ts',
];
const screaming = layout.filter((f) => f.includes('use-case') || f.includes('entity')).length;
console.log(screaming >= 2 ? 'structure screams' : 'frameworks shout');
```

```typescript
// BAD: kinds shouting — controllers/ holding forty handlers, intent whispering (real sprawl shape).
// controllers/orders.ts + services/orders.ts + entities/order.ts + dto/order.ts (features scattering — ownership blurring).
// One feature touching five kind-folders (changes rippling — reviews spanning). Scream features; whisper frameworks.)
```

**Common confusion** — *"screaming means flat folders (nesting declining)."* Screaming describing names (use cases shouting — intent reading (features owning — hunting ending (screaming proving — guessing ending); nesting organizing size (folders grouping — depth bounding (scale serving — sprawl containing (structure owning — chaos declining). "Flat" describing depth (folders listing — hierarchy skipping); screaming describing vocabulary (names deciding — purpose stating). Name loudly (features shouting — intent reading); nest pragmatically (size organizing — depth bounding).

**Performance note** — screaming economics: shouting costing names (use cases naming — entities owning (intent reading — onboarding speeding); scattered equivalents costing hunts (reads jumping — edits hunting (onboarding aching — velocity dying). Name cheaply (folders — intent); scatter never (kinds — hunts).

**Mentor note** — teach "folders scream features" (juniors naming one feature folder per intent design intent-readable trees on first hearing; kind-folders interrogated ("which feature?" — screaming demanding per folder). Scream one feature once (use case shouting — intent reading tangible (hunting ending — ownership proving permanently). Shout use cases; whisper frameworks — structural discipline in three habits, reviewed per feature.

## 3. Costs priced honestly (indirection billed — small apps declining — growth affording)

**Definition** — the honest bill: every port, adapter, and mapping file costing lines that must earn their keep (indirection billing — files counting (ports declaring — adapters implementing (mappers translating — layers separating (honesty owning — gold-plating declining); small apps declining (CRUD serving — layers skipping (simplicity funding — velocity keeping (declining proving — wisdom owning); growth affording (features multiplying — swaps arriving (tests demanding — direction paying (affording proving — investment returning).

**What problem it solves** — the dishonest-bill trio: *gold-plating* (twelve files serving one field — ports abstracting single callers (ceremony billing — value missing (indirection costing — comprehension taxing (juniors drowning — velocity dying); *big-balling* (zero seams serving fifty features — swaps rewriting (tests needing databases (coupling billing — rewrites scheduling (migration fearing — upgrades pinning); *dogma pricing* (always-layering preaching — context ignoring (sizes dismissing — trade-offs declining (judgment missing — honesty absenting). Honest billing converting dogma to judgment (indirection pricing — sizes weighing (context deciding — growth affording); reviewers asking "what swap does this port buy?" (billing proving → verifiable; ceremony → returned).

**Modern guidance** — the billing lines per feature (review-enforced): *indirection billed* (ports counting — adapters counting (files pricing — swaps naming (honesty owning — ceremony declining (bills itemizing — value proving); *small apps declining* (CRUD serving — layers skipping (simplicity funding — velocity keeping (declining proving — wisdom owning (judgment earning — dogma refusing); *growth affording* (features multiplying — swaps arriving (tests demanding — direction paying (affording proving — investment returning (seams funding — rewrites preventing).

```typescript
// GOOD: costs priced — indirection billed per intent, growth affording (compiled + run live).
const intents = 1; // one use case served
const files = 5; // entity + port + use case + adapter + controller — indirection billed honestly
const perIntent = files / intents;
console.log(`1 intent costs ${perIntent} files — ${perIntent <= 6 ? 'growth affords' : 'gold-plating bills'}`);
```

```typescript
// BAD: ceremony billing — twelve files serving one field, value missing (real gold-plate shape).
// create-user.input.ts + create-user.port.ts + create-user.impl.ts + ... (ports abstracting single callers — ceremony billing).
// Zero swaps named (value missing — comprehension taxing). Bill honestly; decline small-app layering.)
```

**Common confusion** — *"clean architecture is always worth it (layering defaulting)."* Worth depending on swaps (ports buying — adapters swapping (tests demanding — direction paying (value proving — investment returning (affording owning — judgment funding); defaults ignoring context (sizes dismissing — ceremony billing (dogma preaching — honesty absenting (judgment missing — bills hiding). "Always" describing dogma (context ignoring — ceremony billing); worth describing pricing (swaps naming — value proving). Price honestly (bills itemizing — swaps naming); layer conditionally (growth affording — CRUD declining).

**Performance note** — billing economics: pricing costing one question ("what swap?" — ports naming — value proving (honesty owning — ceremony declining); unpriced equivalents costing comprehension (files multiplying — value missing (juniors drowning — velocity dying). Ask cheaply (questions — swaps); plate never (ceremony — gold).

**Mentor note** — teach "every port names its swap" (juniors billing one port per seam design honestly-priced layers on first hearing; unnamed ports interrogated ("which swap?" — billing demanding per interface). Price one seam once (swap naming — value proving tangible (ceremony ending — judgment proving permanently). Bill indirection; decline dogma — economic discipline in three habits, reviewed per feature.
