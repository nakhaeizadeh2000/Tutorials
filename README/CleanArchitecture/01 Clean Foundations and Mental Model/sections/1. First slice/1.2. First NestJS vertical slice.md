# 1.2. First NestJS vertical slice

## 1. Slice cuts vertically (one use case end to end — controller thinning — provider deciding)

**Definition** — vertical slice: one user intent (place an order — register a member — refund a payment) implemented across every layer it touches (controller translating — use case orchestrating — entity deciding — adapter persisting) inside one feature home (folders screaming — intent reading (ownership proving — hunting ending). Controller thinning (HTTP parsing — use case calling (translating owning — deciding declining); provider deciding (rules guarding — ports orchestrating (logic homing — reuse enabling).

**What problem it solves** — the horizontal-layer trio: *kinds grouping* (controllers/ swelling — services/ sprawling (features scattering — ownership blurring (reads jumping — edits hunting (onboarding aching — velocity dying); *big-bang integrating* (layers meeting first at boot — wires crossing (failures surfacing late — causes hiding (debugging guessing — confidence hoping); *thickness growing* (controllers deciding — handlers branching (logic duplicating — tests doubling (decisions scattering — consistency failing). Vertical slicing converting layers to intents (one folder owning — one flow proving (integration earning early — ownership holding); reviewers opening one folder per intent (slicing proving → verifiable; layering → returned).

**Modern guidance** — the slicing lines per intent (review-enforced): *one use case end to end* (entity guarding — port declaring (adapter persisting — controller translating (flow owning — integration proving); *controller thinning* (HTTP parsing — use case calling (translating owning — deciding declining (surfaces bounding — breakage preventing); *provider deciding* (rules homing — logic owning (decisions proving — drift ending).

```typescript
// GOOD: slice cutting vertically — one intent across entity, use case, adapter, controller-shape (compiled + run live).
class Order { // entity deciding — invariant guarding, frameworks absenting
  constructor(readonly total: number) {
    if (total <= 0) throw new Error('total must be positive');
  }
}
interface OrderStore { // port declaring — needs stating, details deferring
  save(total: number): void;
  total(): number;
}
class MemoryStore implements OrderStore { // adapter persisting — swappable behind the port
  private sum = 0;
  save(total: number): void { this.sum += total; }
  total(): number { return this.sum; }
}
class PlaceOrder { // use case orchestrating — one intent, one public method
  constructor(private readonly store: OrderStore) {}
  execute(total: number): number {
    const order = new Order(total);
    this.store.save(order.total);
    return this.store.total();
  }
}
function ordersController(place: PlaceOrder): { status: number; body: string } { // controller-shape thinning — translating, never deciding
  return { status: 200, body: JSON.stringify({ total: place.execute(42) }) };
}
const res = ordersController(new PlaceOrder(new MemoryStore()));
console.log(res.status === 200 && res.body === '{"total":42}' ? 'slice cuts' : 'slice broken');
```

"No sharing" describing isolation (folders owning — intents serving); slices describing organization (features grouping — flows proving). Slice intents (folders owning — flows proving); share deliberately (kernels extracting — coupling budgeting).

**Performance note** — slicing economics: cutting costing one folder (intent owning — flow proving (integration earning — ownership holding); horizontal equivalents costing hunts (reads jumping — edits hunting (onboarding aching — velocity dying). Cut cheaply (folders — intents); layer never (kinds — hunts).

**Mentor note** — teach "one folder per intent" (juniors slicing one use case per feature design intent-owned trees on first hearing; kind-folders interrogated ("which intent?" — slicing demanding per file). Cut one slice once (flow proving — ownership holding tangible (hunting ending — integration earning permanently).
```typescript
// GOOD: Nest wiring the slice — module registering, provider injecting, inject proving headless (compiled + run live).
import 'reflect-metadata';
import { Controller, Get, Injectable, Module } from '@nestjs/common';
import { NestFactory } from '@nestjs/core';
import { FastifyAdapter } from '@nestjs/platform-fastify'; // Fastify underneath — adapter stated, Express declining

class Order { // domain deciding — no framework imports, ignorance keeping
  constructor(readonly total: number) {
    if (total <= 0) throw new Error('total must be positive');
  }
}

@Injectable()
class PlaceOrder { // use case deciding — provider injected, framework absenting
  private sum = 0; // in-memory adapter inline — port extraction lands in 2.2
  execute(total: number): number {
    const order = new Order(total);
    this.sum += order.total;
    return this.sum;
  }
}

@Controller('orders')
class OrdersController { // controller thinning — translating owning, deciding declining
  constructor(private readonly placeOrder: PlaceOrder) {}
  @Get('total')
  total(): object { return { total: this.placeOrder.execute(42) }; }
}

@Module({ controllers: [OrdersController], providers: [PlaceOrder] })
class AppModule {}

async function run(): Promise<void> {
  const app = await NestFactory.create(AppModule, new FastifyAdapter());
  await app.init();
  const http = app.getHttpAdapter().getInstance() as any; // inject proving — instance driving, ports skipping
  const res = await http.inject({ method: 'GET', url: '/orders/total' });
  console.log(res.statusCode === 200 && res.body === '{"total":42}' ? 'slice serves' : 'slice broken');
  await app.close();
}
run();
```
