# 2.2. Use cases as application core

## 1. Use cases orchestrate intent (one public method — ports calling — entities deciding)

**Definition** — use case (application core): one user intent owned by one class with one public method (execute deciding — handle orchestrating (intents owning — flows proving (core serving — scattering ending); ports calling (needs declaring — adapters invoking (dependencies inverting — details deferring); entities deciding (rules guarding — invariants holding (policy owning — orchestration serving). Orchestration arranging (ports sequencing — entities consulting (flows composing — decisions delegating); decision delegating (rules homing — use cases arranging (ownership separating — mixing ending).

**What problem it solves** — the coreless trio: *controllers orchestrating* (handlers sequencing — transactions branching (HTTP owning — reuse absenting (edges deciding — core missing (testing heavying — flows duplicating); *services sprawling* (managers managing — helpers helping (intents scattering — methods multiplying (ownership blurring — reuse hoping); *entities bypassing* (rules skipped — invariants unguarded (policy whispering — corruption arriving (guarding missing — trust eroding). Owned use cases converting sprawl to core (one class owning — one method proving (ports calling — entities deciding); reviewers finding each intent in exactly one class (orchestrating proving → verifiable; sprawling → returned).

**Modern guidance** — the orchestration lines per intent (review-enforced): *one public method* (execute naming — handle sequencing (intents owning — flows proving (core serving — sprawl ending (ownership proving — hunting declining); *ports calling* (needs declaring — adapters invoking (dependencies inverting — details deferring (calling funding — coupling declining); *entities deciding* (rules guarding — invariants holding (policy owning — orchestration serving (deciding proving — bypassing ending).

```typescript
// GOOD: intent orchestrating — one use case sequencing two ports, entities deciding (compiled + run live).
class Order { // entity deciding — invariant guarding, orchestration consulting
  constructor(readonly total: number) {
    if (total <= 0) throw new Error('total must be positive');
  }
}
interface OrderStore { // port declaring — persistence needing, details deferring
  save(total: number): void;
}
interface Notifier { // port declaring — notifying needing, transports deferring
  sent(): number;
  notify(msg: string): void;
}
class PlaceOrder { // use case orchestrating — one intent, one public method
  constructor(private readonly store: OrderStore, private readonly notifier: Notifier) {}
  execute(total: number): string {
    const order = new Order(total); // entity deciding — use case arranging
    this.store.save(order.total); // port calling — adapter invoking
    this.notifier.notify(`placed:${order.total}`); // port calling — transport deferring
    return `placed:${order.total}`;
  }
}
class MemoryStore implements OrderStore {
  saved: number[] = [];
  save(total: number): void { this.saved.push(total); }
}
class MemoryNotifier implements Notifier {
  log: string[] = [];
  notify(msg: string): void { this.log.push(msg); }
  sent(): number { return this.log.length; }
}
const store = new MemoryStore();
const notifier = new MemoryNotifier();
const out = new PlaceOrder(store, notifier).execute(25);
console.log(out === 'placed:25' && store.saved.length === 1 && notifier.sent() === 1 ? 'intent orchestrates' : 'core broken');
```

Orchestrate one intent once (ports calling — entities deciding tangible (sprawl ending — core proving permanently). ## 2. Ports declare needs (interfaces owned inward — adapters implementing — fakes sliding)

**Definition** — port: a role interface declared by its consumer (needs stating — shapes bounding (consumers owning — providers obeying (declaring funding — dictating ending); interfaces owned inward (use cases declaring — adapters implementing (arrows pointing inward — direction holding); adapters implementing (vendors plugging — details serving (implementing proving — owning declining); fakes sliding (doubles honoring — suites headlessing (tests substituting — databases sleeping).

**What problem it solves** — the concrete-depending trio: *classes concretizing* (PgStore importing — constructors coupling (vendors owning — policy obeying (swaps rewriting — tests heavying); *interfaces fattening* (methods accumulating — consumers coupling-unused (surfaces growing — changes rippling (ISP violating — cohesion fading); *doubles missing* (fakes unhonoring — contracts unasserted (suites needing databases — feedback dying). Declared ports converting concrete to roles (needs stating — shapes bounding (consumers owning — providers obeying); reviewers approving each port's size per consumer (declaring proving → verifiable; concretizing → returned).

**Modern guidance** — the port lines per need (review-enforced): *interfaces owned inward* (use cases declaring — consumers owning (arrows pointing inward — direction holding (owning proving — dictating ending); *adapters implementing* (vendors plugging — details serving (implementing proving — owning declining (plugging funding — swapping earning); *fakes sliding* (doubles honoring — suites headlessing (tests substituting — databases sleeping (sliding proving — heaviness ending). One consumer, one role (sizes bounding — cohesion keeping); contract suites running every implementation (honoring proving — drift detecting).

```typescript
// GOOD: needs declaring — one contract suite proving every implementation, fakes sliding (compiled + run live).
interface Counter { // port owned inward — the consumer declaring, details obeying
  add(n: number): void;
  total(): number;
}
function contract(make: () => Counter): boolean { // contract suite — honoring proving, drift detecting
  const c = make();
  c.add(3);
  c.add(4);
  return c.total() === 7;
}
class MemoryCounter implements Counter { // adapter implementing — details serving, owning declining
  private sum = 0;
  add(n: number): void { this.sum += n; }
  total(): number { return this.sum; }
}
class FakeCounter implements Counter { // fake sliding — doubles honoring, suites headlessing
  private calls: number[] = [];
  add(n: number): void { this.calls.push(n); }
  total(): number { return this.calls.reduce((a, b) => a + b, 0); }
}
console.log(contract(() => new MemoryCounter()) && contract(() => new FakeCounter()) ? 'ports hold' : 'ports broken');
```

## 3. Framework stays outside (no HTTP in use cases — no ORM in entities — boundaries holding)

**Definition** — the outside rule: frameworks, transports, and ORMs touching the core only through ports at the edges (HTTP translating — use cases ignoring (edges owning — cores deciding (outside holding — leaking ending); ORM persisting — entities ignoring (details serving — policy deciding (outside holding — dictating ending); boundaries holding (edges translating — cores orchestrating (translation owning — deciding declining (holding proving — collapsing ending). Core importable from any edge (CLI calling — controller calling (frameworks absenting — logic identical (portability proving — coupling declining).

**What problem it solves** — the inside-framework trio: *requests invading* (@Req drilling — headers branching (transports owning — tests heavying (edges deciding — core obeying (invading billing — portability dying); *decorators colonizing* (@Entity owning — @Column typing (ORM owning — policy obeying (vendors deciding — swaps rewriting (colonizing charging — leverage inverting); *edges multiplying* (web needing — CLI duplicating (logic forking — drift growing (cores absenting — consistency failing). Outside frameworks converting invasion to edges (transports translating — cores ignoring (ORM persisting — entities ignoring); reviewers running the core from two edges per feature (outside proving → verifiable; invading → returned).

**Modern guidance** — the outside lines per core file (review-enforced): *no HTTP in use cases* (transports translating — cores ignoring (edges owning — cores deciding (outside holding — leaking ending (portability proving — heaviness declining); *no ORM in entities* (details serving — policy deciding (vendors plugging — rules owning (outside holding — dictating ending (leverage keeping — fear declining); *boundaries holding* (edges translating — cores orchestrating (translation owning — deciding declining (holding proving — collapsing ending (discipline owning — erosion ending). NestJS registration stays the edge vehicle ([1.2](<../../sections/1. First slice/1.2. First NestJS vertical slice.md>) owns the wiring — this leaf owns the absence).

```typescript
// GOOD: outside holding — the same core driven from two edges, frameworks absent (compiled + run live).
class Refund { // core deciding — no HTTP, no ORM, edges unknown
  constructor(readonly amount: number) {
    if (amount <= 0) throw new Error('amount must be positive');
  }
}
class IssueRefund { // use case orchestrating — ports calling, frameworks absenting
  constructor(private readonly ledger: { post(amount: number): void }) {}
  execute(amount: number): string {
    const refund = new Refund(amount);
    this.ledger.post(refund.amount);
    return `refunded:${refund.amount}`;
  }
}
const ledger = { posted: 0, post(a: number): void { this.posted += a; } };
function cliEdge(args: string[]): string { // edge one — CLI translating, core ignoring
  return new IssueRefund(ledger).execute(Number(args[0]));
}
function controllerEdge(body: { amount: number }): string { // edge two — HTTP translating, core ignoring
  return new IssueRefund(ledger).execute(body.amount);
}
const fromCli = cliEdge(['15']);
const fromHttp = controllerEdge({ amount: 15 });
console.log(fromCli === 'refunded:15' && fromHttp === 'refunded:15' && ledger.posted === 30 ? 'outside holds' : 'core leaks');
```
