# 2.2. Eventual consistency judging staleness

## 1. Staleness budgeting (windows bounding — queries pricing — freshness proving)

**Definition** — staleness budget: declared maximum lag per query, priced by criticality (windows bounding — horizons stating (lag limiting — surprises declining (bounding proving — hoping ending); queries pricing — criticality weighing (money tightening — lists loosening (pricing funding — uniform declining); freshness proving — gauges measuring (offsets comparing — windows asserting (proving owning — assuming ending).

**What problem it solves** — the uniform-freshness trio: *freshness assuming* (reads trusting — replicas lagging (staleness invisible — divergence hiding (assuming billing — surprises scheduling); *budgets missing* (windows unstated — queries unpriced (criticality ignoring — critical reading stale (missing costing — incidents arriving); *lag unmeasured* (offsets uncompared — gauges absenting (drift invisible — failovers blind (unmeasured charging — recency hoping). Budgeted staleness converting assuming to bounding (windows stating — queries pricing (freshness proving — surprises declining); reviewers finding lag budgets per query (budgeting proving → verifiable; assuming → returned).

**Modern guidance** — the budgeting lines per query (review-enforced): *windows bounding* (horizons stating — lag limiting (surprises declining — hoping ending (bounding proving — invisible refusing (limits owning — trust earning); *queries pricing* (criticality weighing — money tightening (lists loosening — uniform declining (pricing funding — dogma refusing (weights owning — judgment serving); *freshness proving* (gauges measuring — offsets comparing (windows asserting — assuming ending (proving owning — hoping declining (meters funding — blindness ending). Lag mechanics (offsets comparing — WAIT selecting) are owned in [Redis 04/2.1](<../../../../Redis/04 Persistence Replication and Sentinel/sections/2. Copies/2.1. Replication async and replicas.md>) — this leaf owns the budgets, never the gauges.

```typescript
// GOOD: staleness budgeting — criticality pricing windows, measured lag gating reads (compiled + run live).
function budgetMs(kind: string): number { // queries pricing — criticality weighing, uniform declining
  if (kind === 'balance') return 0; // money tightening — critical reading fresh, incidents declining
  if (kind === 'feed') return 5000; // lists loosening — routine flowing, waiting declining
  return 1000;
}
function serve(kind: string, lagMs: number): string {
  return lagMs <= budgetMs(kind) ? 'serve' : 'stale'; // windows bounding — horizons stating, surprises declining
}
const money = serve('balance', 50);
const list = serve('feed', 3000);
const late = serve('balance', 50);
console.log(money === 'stale' && list === 'serve' && late === 'stale' ? 'budgets bound' : 'freshness assumes');
```

**Common confusion** — *"eventual means eventually broken (consistency doubting)."* Eventual bounding divergence (windows stating — gauges measuring (lag limiting — surprises declining (bounding proving — breaking declining); broken ignoring budgets (windows unstated — lag unmeasured (staleness invisible — surprises scheduling (ignoring charging — trust eroding). "Broken" describing neglect (budgets missing — gauges absenting); eventual describing windows (horizons bounding — freshness proving). Bound windows (horizons stating — surprises declining); measure lag (gauges proving — blindness ending).

**Performance note** — budgeting economics: bounding costing one number (horizons stating — lag limiting (surprises declining — incidents preventing); uniformed equivalents costing incidents (critical reading stale — divergence hiding (trust eroding — surprises scheduling). Bound cheaply (numbers — windows); assume never (freshness — uniformity).

**Mentor note** — teach "every read names its lag" (juniors budgeting one window per query design surprise-free reads on first hearing; unbudgeted reads interrogated ("stale by how much?" — budgeting demanding per query). Bound one window once (horizons stating — queries pricing tangible (assuming ending — bounding proving permanently). State horizons; price criticality — budgeting discipline in three habits, reviewed per query.

## 2. UX tolerating (versions showing — refreshes offering — conflicts resolving)

**Definition** — staleness-tolerant UX: versions displayed, refreshes offered, conflicts resolved (versions showing — as-of stating (readers informing — surprises declining (showing proving — hiding ending); refreshes offering — recency affording (users pulling — waits choosing (offering funding — forcing declining); conflicts resolving — mismatches merging (edits reconciling — losses preventing (resolving owning — overwriting declining).

**What problem it solves** — the silent-stale trio: *staleness hiding* (views asserting — versions missing (readers trusting — surprises arriving (hiding billing — honesty declining); *refreshes missing* (recency unobtainable — waits forcing (users helpless — trust eroding (missing charging — control declining); *conflicts overwriting* (edits clobbering — versions ignoring (losses silencing — work vanishing (overwriting billing — merging absenting). Tolerant UX converting hiding to showing (versions stating — refreshes offering (conflicts resolving — surprises declining); reviewers finding as-of versions per view (tolerating proving → verifiable; hiding → returned).

**Modern guidance** — the tolerating lines per view (review-enforced): *versions showing* (as-of stating — readers informing (surprises declining — hiding ending (showing proving — asserting declining (honesty owning — trust earning); *refreshes offering* (recency affording — users pulling (waits choosing — forcing declining (offering funding — helplessness ending (control returning — patience funding); *conflicts resolving* (mismatches merging — edits reconciling (losses preventing — overwriting declining (resolving owning — clobbering refusing (merges earning — vanishes preventing).

```typescript
// GOOD: UX tolerating — versioned views, conflict responses, losses prevented (compiled + run live).
interface View { // versions showing — as-of stating, readers informing
  data: string;
  version: number;
}
type Outcome = { state: 'saved'; version: number } | { state: 'conflict'; current: View };
function save(view: View, expected: number, data: string): Outcome {
  if (expected !== view.version) return { state: 'conflict', current: view }; // conflicts resolving — mismatches merging, losses preventing
  return { state: 'saved', version: view.version + 1 };
}
const view: View = { data: 'draft', version: 7 };
const fresh = save(view, 7, 'final');
const clash = save(view, 6, 'stale-edit');
console.log(fresh.state === 'saved' && clash.state === 'conflict' ? 'ux tolerates' : 'staleness silences');
```


**Common confusion** — *"versions burden users (complexity taxing)."* Versions informing readers (as-of stating — surprises declining (honesty owning — trust earning (informing funding — hiding declining); burden complicating flows (steps multiplying — value missing (complexity charging — patience taxing (burdening serving — simplicity declining). "Burden" describing complexity (steps multiplying — value missing); versions describing honesty (as-of stating — surprises declining). Show versions (readers informing — surprises declining); resolve conflicts (merges earning — losses preventing).

**Performance note** — tolerating economics: showing costing one number (as-of stating — readers informing (surprises declining — trust earning); hidden equivalents costing losses (edits clobbering — work vanishing (surprises arriving — honesty declining). Show cheaply (versions — views); hide never (staleness — surprises).

**Mentor note** — teach "stale shown beats stale hidden" (juniors versioning one view per screen design honesty-owned UX on first hearing; versionless views interrogated ("as of when?" — tolerating demanding per view). Show one version once (as-of stating — readers informing tangible (hiding ending — honesty proving permanently). State versions; merge conflicts — tolerating discipline in three habits, reviewed per view.

## 3. Consistency judging (reads weighing — writes waiting — contexts deciding)

**Definition** — consistency judgment: per-context choice between strong and eventual, priced openly (reads weighing — criticality judging (money tightening — lists loosening (weighing proving — uniform declining); writes waiting — critical pausing (copies confirming — routine flowing (waiting funding — racing declining); contexts deciding — boundaries ruling (spans owning — flows fitting (deciding owning — defaulting declining).

**What problem it solves** — the one-consistency trio: *strong defaulting* (sync demanding — latency coupling (writes waiting — throughput dying (defaulting charging — availability declining); *eventual defaulting* (money reading-stale — critical hoping (freshness bluffing — incidents arriving (defaulting billing — judgment missing); *contexts ignoring* (spans unowned — flows unfitted (boundaries missing — mechanisms mismatching (ignoring costing — coherence failing). Judged consistency converting defaulting to weighing (reads judging — writes waiting (contexts deciding — uniformity declining); reviewers naming the consistency per context (judging proving → verifiable; defaulting → returned).

**Modern guidance** — the judging lines per context (review-enforced): *reads weighing* (criticality judging — money tightening (lists loosening — uniform declining (weighing proving — dogma refusing (judgment owning — hope ending); *writes waiting* (critical pausing — copies confirming (routine flowing — racing declining (waiting funding — losing ending (patience owning — risk pricing); *contexts deciding* (boundaries ruling — spans owning (flows fitting — defaulting declining (deciding owning — ignoring refusing (ownership proving — mismatch ending). Coordination mechanics (2PC pricing — outbox bridging) are owned in [Databases 05/3.1](<../../../../Databases/05 Transactions Consistency and Integrity/sections/3. Distribution/3.1.
```typescript
// GOOD: consistency judging — criticality routing strong versus eventual (compiled + run live).
type Level = 'strong' | 'eventual';
function judge(kind: string): Level { // contexts deciding — boundaries ruling, defaulting declining
  if (kind === 'ledger' || kind === 'auth') return 'strong'; // writes waiting — critical pausing, risk pricing
  return 'eventual'; // reads weighing — lists loosening, uniform declining
}
const ledger = judge('ledger');
const feed = judge('feed');
const auth = judge('auth');
console.log(ledger === 'strong' && feed === 'eventual' && auth === 'strong' ? 'judgment holds' : 'consistency defaults');
```


**Common confusion** — *"strong is always safer (safety absoluting)."* Strong correlating availability (writes waiting — throughput dying (latency coupling — outages spreading (correlating charging — safety pricing-in-uptime); safety composing per context (critical pausing — routine flowing (risk pricing — guarantees buying (composing funding — absoluting declining). "Always" describing absolutism (contexts ignoring — costs hiding); safety describing composition (reads weighing — writes waiting). Weigh reads (criticality judging — uniform declining); wait selectively (critical pausing — risk pricing).

**Performance note** — judging economics: weighing costing one judgment (criticality judging — money tightening (safety composing — costs revealing); defaulted equivalents costing availability-or-incidents (latency coupling — freshness bluffing (uniformity charging — judgment missing). Judge cheaply (contexts — kinds); default never (uniform — costs).

**Mentor note** — teach "name the consistency per context" (juniors judging one level per context design default-free consistency on first hearing; unjudged contexts interrogated ("strong or eventual?" — judging demanding per boundary). Judge one context once (reads weighing — writes waiting tangible (defaulting ending — judgment proving permanently). Weigh criticality; wait selectively — judging discipline in three habits, reviewed per context.
