# 2.1. Projections folding events

## 1. Folds replaying (events sequencing — states deriving — histories owning)

**Definition** — projection fold: deterministic left fold turning event sequences into view state (events sequencing — facts ordering (logs owning — histories keeping (sequencing proving — guessing declining); states deriving — views computing (folds proving — replays repeating (deriving funding — storing declining); histories owning — logs keeping (audits funding — disputes settling (owning proving — forgetting declining).

**What problem it solves** — the adhoc-state trio: *states computing ad hoc* (queries folding — logic scattering (derivation duplicating — results differing (adhoc billing — determinism bluffing); *replays unrepeating* (folds impure — clocks reading (runs differing — histories untrusted (unrepeating charging — confidence declining); *logs missing* (states storing — facts vanishing (audits guessing — disputes losing (missing costing — truth declining). Folding projections converting adhoc to deterministic (events sequencing — states deriving (histories owning — replays repeating); reviewers replaying logs per view (folding proving → verifiable; adhoc → returned).

**Modern guidance** — the folding lines per view (review-enforced): *events sequencing* (facts ordering — logs owning (histories keeping — guessing declining (sequencing proving — scattering ending (order owning — chaos declining); *states deriving* (views computing — folds proving (replays repeating — storing declining (deriving funding — adhoc ending (folds owning — drift preventing); *histories owning* (logs keeping — audits funding (disputes settling — forgetting ending (owning proving — vanishing declining (journals earning — truth keeping). Fold mechanics (truth appending — balances deriving) are owned in [DP 06/2.2](<../../../../DesignPatterns/06 Modern Patterns and Anti-Patterns/sections/2. Pipelines and events/2.2. Publish-subscribe and event sourcing.md>) — this leaf owns view folds, never the log mechanics.

```typescript
// GOOD: folds replaying — inventory derived twice identically from one log (compiled + run live).
type StockFact = { kind: 'received'; sku: string; qty: number } | { kind: 'sold'; sku: string; qty: number };
function onHand(facts: StockFact[], sku: string): number { // states deriving — views computing, replays repeating
  return facts.reduce((a, f) => {
    if (f.sku !== sku) return a;
    return f.kind === 'received' ? a + f.qty : a - f.qty;
  }, 0);
}
const stockLog: StockFact[] = [ // events sequencing — facts ordering, logs owning
  { kind: 'received', sku: 'book-a', qty: 10 },
  { kind: 'sold', sku: 'book-a', qty: 3 },
  { kind: 'received', sku: 'book-b', qty: 5 },
  { kind: 'sold', sku: 'book-a', qty: 2 },
];
const first = onHand(stockLog, 'book-a');
const replay = onHand(stockLog, 'book-a'); // replays repeating — runs agreeing, histories trusted
console.log(first === 5 && replay === 5 ? 'folds replay' : 'state adhocs');
```

"Duplicating" describing mirrors (rows copying — value missing); projections describing folds (facts ordering — views computing). Derive answers (events sequencing — states deriving); mirror never (rows copying — value missing).

**Performance note** — folding economics: deriving costing one pass (events sequencing — states computing (questions owning — latency sparing); adhoc equivalents costing determinism (derivation duplicating — results differing (trust declining — debugging aching). Fold cheaply (passes — logs); adhoc never (queries — drift).

**Mentor note** — teach "same log, same view, every replay" (juniors folding one view per log design determinism-owned projections on first hearing; impure folds interrogated ("replay it twice?" — folding demanding per projector). Sequence facts; derive views — folding discipline in three habits, reviewed per projection.

## 2. Projectors subscribing (facts reacting — views building — decoupling funding)

**Definition** — projector: subscriber building one view from facts, decoupled from writers (facts reacting — kinds matching (streams consuming — writers ignoring (reacting proving — coupling declining); views building — states folding (answers shaping — queries serving (building funding — loading declining); decoupling funding — emitters unknowing (handlers owning — flows continuing (funding owning — tangling declining).

**What problem it solves** — the writer-building trio: *writers projecting* (emitters shaping — views coupling (concerns mixing — changes rippling (building billing — decoupling dying); *subscriptions missing* (polls looping — views staling (reactions absenting — freshness hoping (missing charging — lag invisible); *failures halting* (poisons crashing — streams stopping (errors killing — views freezing (halting costing — progress ending). Subscribing projectors converting building to reacting (facts consuming — views folding (writers ignoring — flows continuing); reviewers subscribing one projector per view (reacting proving → verifiable; polling → returned).

**Modern guidance** — the subscribing lines per projector (review-enforced): *facts reacting* (kinds matching — streams consuming (writers ignoring — coupling declining (reacting proving — polling ending (subscriptions owning — lag bounding); *views building* (states folding — answers shaping (queries serving — loading declining (building funding — computing ending (views earning — latency sparing); *decoupling funding* (emitters unknowing — handlers owning (flows continuing — tangling declining (funding owning — binding ending (autonomy earning — deploying decoupling). Dedupe on redelivery (ids remembering — replays returning) is owned in [02/2.2](<../../../02 Use Cases and Application Services/sections/2. Long flows/2.2. Idempotency guarding retries.md>) — this leaf owns the subscription, never the dedupe.

```typescript
// GOOD: projectors subscribing — kinds matched, views folded, writers ignored (compiled + run live).
interface Fact {
  kind: string;
  id: string;
}
class CountView { // views building — states folding, queries serving
  private readonly seen = new Set<string>(); // dedupe borrowing — ids remembering, replays returning
  readonly counts: Record<string, number> = {};
  apply(f: Fact): void { // facts reacting — kinds matching, writers ignoring
    if (f.kind !== 'sold') return;
    if (this.seen.has(f.id)) return; // redeliveries skipping — effects holding, storms surviving
    this.seen.add(f.id);
    this.counts.sold = (this.counts.sold ?? 0) + 1;
  }
}
const view = new CountView();
const stream: Fact[] = [{ kind: 'sold', id: 'e1' }, { kind: 'sold', id: 'e2' }, { kind: 'sold', id: 'e1' }];
for (const f of stream) view.apply(f);
console.log(view.counts.sold === 2 ? 'projectors subscribe' : 'writers build');
```

## 3. Rebuilds rehearsing (logs replaying — views regenerating — deploys proving)

**Definition** — rebuild rehearsal: views regenerable from logs, rehearsed before needed (logs replaying — facts re-reading (states rederiving — views refreshing (replaying proving — fearing declining); views regenerating — drops recovering (deploys proving — panics declining (regenerating funding — losing ending); deploys proving — rehearsals passing (staging succeeding — production trusting (proving owning — hoping ending).

**What problem it solves** — the truth-view trio: *views truthing* (reads owning — logs deleting (facts vanishing — audits dying (truthing billing — history losing); *rebuilds untested* (drops fearing — replays hoping (regeneration bluffing — migrations panicking (untested charging — confidence absenting); *versions drifting* (shapes evolving — readers breaking (upcasters missing — replays failing (drifting billing — evolution stopping). Rehearsed rebuilds converting truthing to regenerating (logs replaying — views refreshing (deploys proving — panics declining); reviewers rebuilding views per deploy (rehearsing proving → verifiable; truthing → returned).

**Modern guidance** — the rehearsing lines per view (review-enforced): *logs replaying* (facts re-reading — states rederiving (views refreshing — fearing declining (replaying proving — deleting refusing (logs owning — truth keeping); *views regenerating* (drops recovering — deploys proving (panics declining — losing ending (regenerating funding — truthing refusing (refreshes owning — deletes surviving); *deploys proving* (rehearsals passing — staging succeeding (production trusting — hoping ending (proving owning — panicking declining (evidence funding — fear ending). Event versions bridge replays (upcasters owning — shapes evolving) — version depth in [04/3.1](<../../../04 DDD Tactical Modeling/sections/3. Domain events/3.1. Domain events naming the past.md>); this leaf owns the rehearsal, never the upcasters.

```typescript
// GOOD: rebuilds rehearsing — dropped views regenerating identically from logs (compiled + run live).
interface Fact {
  kind: 'added' | 'removed';
  qty: number;
}
function build(facts: Fact[]): number { // views regenerating — drops recovering, truth refusing
  return facts.reduce((a, f) => (f.kind === 'added' ? a + f.qty : a - f.qty), 0);
}
const journal: Fact[] = [ // logs replaying — facts re-reading, deletes surviving
  { kind: 'added', qty: 10 },
  { kind: 'added', qty: 5 },
  { kind: 'removed', qty: 4 },
];
const live = build(journal);
const dropped = 0; // view dropped — truth refusing, panics declining
const rebuilt = dropped + build(journal); // deploys proving — rehearsals passing, hoping ending
let processed = 0;
for (const _f of journal) processed += 1;
console.log(live === 11 && rebuilt === 11 && processed === 3 ? 'rebuilds rehearse' : 'views truth');
```

"Recovery" describing emergencies (outages owning — backups returning); rebuilds describing discipline (logs replaying — views refreshing). Replay cheaply (passes — logs); truth never (views — deletes).
