# 3.1. Slices scaling reads and writes

## 1. Reads scaling (replicas serving — caches fronting — projections sharding)

**Definition** — read scale-out: load spreading across replicas, caches, and shards (replicas serving — copies answering (primaries writing — followers reading (serving funding — contention declining); caches fronting — hits absorbing (hot answering — stores resting (fronting owning — latency declining); projections sharding — keys routing (partitions owning — workers paralleling (sharding funding — hotspots declining).

**What problem it solves** — the single-reader trio: *stores straining* (reads joining — writes contending (queries queuing — latency growing (straining billing — users waiting (overloading charging — scaling blocking); *caches stampeding* (keys expiring — herds refilling (thundering arriving — stores crushing (stampeding billing — discipline missing); *shards missing* (keys unrouted — partitions absenting (growth hoping — hotspots forming (missing costing — rebalancing dreading). Scaled reads converting straining to spreading (replicas answering — caches absorbing (shards routing — contention declining); reviewers routing keys per projection (scaling proving → verifiable; straining → returned).

**Modern guidance** — the scaling lines per read (review-enforced): *replicas serving* (copies answering — primaries writing (followers reading — contention declining (serving funding — straining ending (reads owning — writes routing); *caches fronting* (hits absorbing — hot answering (stores resting — latency declining (fronting owning — stampeding preventing (absorbing funding — crushing declining); *projections sharding* (keys routing — partitions owning (workers paralleling — hotspots declining (sharding funding — missing ending (routing owning — rebalancing planning). Replica mechanics (offsets comparing — WAIT selecting) are owned in [Redis 04/2.1](<../../../../Redis/04 Persistence Replication and Sentinel/sections/2. Copies/2.1. Replication async and replicas.md>) — this leaf owns the routing, never the replication.

```typescript
// GOOD: reads scaling — deterministic key routing spreading load evenly (compiled + run live).
function shard(key: string, shards: number): number { // keys routing — partitions owning, hotspots declining
  let h = 0;
  for (let i = 0; i < key.length; i += 1) h = (h * 31 + key.charCodeAt(i)) >>> 0;
  return h % shards;
}
const keys = ['o1', 'o2', 'o3', 'o4', 'o5', 'o6', 'o7', 'o8'];
const routes = keys.map((k) => shard(k, 4));
const again = keys.map((k) => shard(k, 4)); // deterministic routing — workers paralleling, rebalancing planning
const spread = new Set(routes).size;
console.log(routes.join(',') === again.join(',') && spread >= 3 ? 'reads scale' : 'stores strain');
```

```typescript
// BAD: readers singling — stores straining, shards missing (real single shape).
// const rows = await primary.query('SELECT ...'); // reads joining — contention growing, latency growing.
// // No replicas, no cache, no shards (growth hoping — hotspots forming). Spread reads; front caches; route keys.)
```

**Common confusion** — *"scaling means replicas (copies equaling)."* Replicas serving copies (primaries writing — followers reading (copies answering — contention declining (serving funding — straining ending); scaling spreading load (caches absorbing — shards routing (replicas answering — hotspots declining (spreading proving — singling declining). "Replicas" describing copies (primaries writing — followers reading); scaling describing spreading (load distributing — contention declining). Serve replicas (copies answering — contention declining); front caches (hits absorbing — latency declining); route shards (keys distributing — hotspots declining).

**Performance note** — read-scaling economics: spreading costing routing (keys distributing — contention declining (latency bounding — users trusting); singled equivalents costing strain (queries queuing — latency growing (overloading charging — scaling blocking). Spread cheaply (routes — keys); single never (stores — strain).

**Mentor note** — teach "route every hot key" (juniors sharding one projection per key-space design strain-proof reads on first hearing; unrouted growth interrogated ("which shard?" — scaling demanding per projection). Route one key once (keys distributing — hotspots declining tangible (straining ending — spreading proving permanently). Serve replicas; shard projections — read-scaling discipline in three habits, reviewed per read.

## 2. Writes guarding (aggregates bounding — commands funneling — contention sparing)

**Definition** — write guarding: one writer per aggregate instance, commands funneled and versioned (aggregates bounding — spans owning (consistency scoping — contention sparing (bounding proving — colliding declining); commands funneling — queues serializing (orders owning — races declining (funneling funding — forking ending); contention sparing — versions sequencing (staleness detecting — conflicts surfacing (sparing owning — blocking declining).

**What problem it solves** — the concurrent-write trio: *writers colliding* (edits racing — versions ignoring (conflicts hiding — losses silencing (colliding billing — integrity bluffing); *commands forking* (paths doubling — ownership blurring (intents scattering — audits confusing (forking charging — consistency failing); *contention serializing* (locks blocking — throughput dying (units queuing — availability declining (serializing costing — scaling failing). Guarded writes converting colliding to funneling (aggregates bounding — commands serializing (versions sequencing — losses declining); reviewers serializing commands per aggregate (guarding proving → verifiable; colliding → returned).

**Modern guidance** — the guarding lines per aggregate (review-enforced): *aggregates bounding* (spans owning — consistency scoping (contention sparing — colliding declining (bounding proving — bloating refusing (ownership earning — grabbing ending); *commands funneling* (queues serializing — orders owning (races declining — forking ending (funneling funding — scattering declining (serials owning — parallels refusing); *contention sparing* (versions sequencing — staleness detecting (conflicts surfacing — blocking declining (sparing owning — locking refusing (optimism funding — pessimism declining).

```typescript
// GOOD: writes guarding — per-aggregate queues serializing commands, versions sequencing (compiled + run live).
class Funnel { // commands funneling — queues serializing, races declining
  private readonly queues = new Map<string, number>();
  submit(id: string, atVersion: number): string {
    const current = this.queues.get(id) ?? 0;
    if (atVersion !== current) return 'stale'; // versions sequencing — staleness detecting, losses declining
    this.queues.set(id, current + 1);
    return 'accepted';
  }
}
const funnel = new Funnel();
const first = funnel.submit('o1', 0);
const replay = funnel.submit('o1', 0); // concurrent edit racing — conflicts surfacing, overwriting declining
const next = funnel.submit('o1', 1);
console.log(first === 'accepted' && replay === 'stale' && next === 'accepted' ? 'writes guard' : 'edits collide');
```

```typescript
// BAD: writes colliding — edits racing, versions ignoring (real concurrent shape).
// await repo.save(a); await repo.save(b); // conflicts hiding — losses silencing, integrity bluffing.
// // No funnel, no versions (races declining-absent — overwrites scheduling). Bound aggregates; funnel commands.)
```

**Common confusion** — *"funnels bottleneck throughput (queues slowing)."* Funnels serializing per aggregate (orders owning — races declining (correctness funding — losses preventing (serializing proving — colliding declining); bottlenecks blocking globally (locks serializing — units queuing (throughput dying — availability declining (blocking charging — scaling failing). "Bottleneck" describing global locks (units queuing — throughput dying); funnels describing per-aggregate order (commands serializing — races declining). Funnel per aggregate (orders owning — correctness funding); lock never globally (units queuing — throughput dying).

**Performance note** — guarding economics: funneling costing queues (orders owning — races declining (correctness funding — losses preventing); collided equivalents costing losses (edits racing — versions ignoring (conflicts hiding — integrity bluffing). Funnel cheaply (queues — ids); collide never (edits — races).

**Mentor note** — teach "one writer per aggregate" (juniors funneling one command stream per aggregate design race-proof writes on first hearing; unversioned writes interrogated ("which version?" — guarding demanding per mutation). Funnel one stream once (queues serializing — versions sequencing tangible (colliding ending — guarding proving permanently). Bound spans; serialize commands — guarding discipline in three habits, reviewed per aggregate.

## 3. Slices owning (features serving — teams answering — deploys decoupling)

**Definition** — slice ownership: feature teams owning read-plus-write slices end to end (features serving — reads answering (writes guarding — users trusting (serving proving — handing declining); teams answering — incidents owning (changes shipping — on-call holding (answering funding — ping-ponging declining); deploys decoupling — pipelines releasing (versions rolling — flags toggling (decoupling owning — coordinating declining).

**What problem it solves** — the layer-team trio: *teams layering* (frontend owning — backend owning (features splitting — handoffs queuing (layering billing — ownership blurring (splitting charging — velocity dying); *deploys coupling* (releases training — versions locking (ships coordinating — rollbacks panicking (coupling billing — autonomy dying (locking charging — frequency declining); *slices handless* (features splitting — nobody answering (incidents bouncing — quality diffusing (handless costing — pride declining). Owned slices converting layering to featuring (teams answering — deploys decoupling (features serving — handoffs declining); reviewers naming one owner per slice (owning proving → verifiable; layering → returned).

**Modern guidance** — the owning lines per slice (review-enforced): *features serving* (reads answering — writes guarding (users trusting — handing declining (serving proving — splitting refusing (features earning — layers declining); *teams answering* (incidents owning — changes shipping (on-call holding — ping-ponging declining (answering funding — bouncing ending (ownership earning — diffusion declining); *deploys decoupling* (pipelines releasing — versions rolling (flags toggling — coordinating declining (decoupling owning — training ending (frequency funding — locking declining).

```typescript
// GOOD: slices owning — registry asserting owner plus read/write models per slice (compiled + run live).
interface Slice { // features serving — reads answering, writes guarding
  feature: string;
  owner: string;
  readModel: string;
  writeModel: string;
}
function owned(slices: Slice[]): boolean {
  return slices.every((s) => s.owner.length > 0 && s.readModel.length > 0 && s.writeModel.length > 0); // teams answering — incidents owning, deploys decoupling
}
const slices: Slice[] = [
  { feature: 'orders', owner: 'team-checkout', readModel: 'OrderViews', writeModel: 'OrderAggregate' },
  { feature: 'billing', owner: 'team-money', readModel: 'LedgerViews', writeModel: 'LedgerAggregate' },
];
console.log(owned(slices) && slices.length === 2 ? 'slices own' : 'layers split');
```

```typescript
// BAD: teams layering — features splitting, deploys coupling (real layer shape).
// frontend-team + backend-team + dba-team // handoffs queuing — ownership blurring, velocity dying.
// // Release trains (ships coordinating — rollbacks panicking). Slice features; answer teams; decouple deploys.)
```

**Common confusion** — *"slices mean microservices (deployables equaling)."* Slices owning features (reads answering — writes guarding (teams answering — deploys decoupling (owning proving — layering declining); services deploying units (processes scaling — networks calling (operations owning — failures isolating (deploying funding — language declining). "Services" describing runtime (processes scaling — failures isolating); slices describing ownership (features serving — teams answering). Own slices (features serving — teams answering); deploy pragmatically (units scaling — operations owning).

**Performance note** — owning economics: serving costing named owners (features answering — teams responding (handoffs declining — velocity funding); layered equivalents costing handoffs (features splitting — releases training (velocity dying — autonomy declining). Own cheaply (slices — names); layer never (teams — handoffs).

**Mentor note** — teach "one owner per slice" (juniors owning one feature end per team design handoff-free delivery on first hearing; ownerless slices interrogated ("who answers?" — owning demanding per slice). Own one slice once (features serving — teams answering tangible (layering ending — velocity proving permanently). Serve features; decouple deploys — owning discipline in three habits, reviewed per slice.
