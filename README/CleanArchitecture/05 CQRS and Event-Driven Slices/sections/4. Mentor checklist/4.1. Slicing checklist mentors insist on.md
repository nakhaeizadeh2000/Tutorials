# 4.1. Slicing checklist mentors insist on

## 1. Every write commanding (intents owning — guards enforcing — reads declining)

**Definition** — the commanding gate: each mutation owned by a guarded command, reads declined (intents owning — flows stating (changes requesting — queries refusing (owning proving — mixing declining); guards enforcing — rules checking (invariants holding — corruption refusing (enforcing funding — hoping ending); reads declining — data withholding (acks answering — shapes unreturned (declining proving — serving refusing).

**What problem it solves** — the uncommanded trio: *writes querying* (lists answering — shapes shaping (reads serving — intents blurring (querying billing — splitting breaking); *guards missing* (rules unchecked — invariants unheld (validity hoping — corruption arriving (missing costing — trust eroding); *intents blurring* (verbs muddying — effects surprising (ownership missing — audits guessing (blurring charging — precision declining). The gate converting querying to commanding (intents owning — guards enforcing (reads declining — acks answering); mentors asking one question per mutation ("which command, which guard?" — commanding demanding per write).

**Modern guidance** — the gate commands (run per write, enforced in review):

```typescript
// GOOD: commanding gated — intents owning, guards enforcing, reads declining (checklist shape).
// 1. Intent proof (flows stating — changes requesting):
//    every mutation behind a named command — verbs owning, effects stating, audits owning.
// 2. Guard proof (rules checking — invariants holding):
//    every command validating and guarding — aggregates consulted, corruption refused, partials declined.
// 3. Ack proof (data withholding — shapes unreturned):
//    commands answering ids or acks — lists unreturned, queries unserved, splits holding.
// Own intents; enforce guards; decline reads.)
```

```typescript
// BAD: writes uncommanding — lists answering, guards missing (real uncommanded shape).
// save(data: any): any[] { /* ... returns rows ... */ } // reads serving — intents blurring, splitting breaking.
// // No validation (rules unchecked — corruption arriving). Command writes; enforce guards; ack only.)
```

**Common confusion** — *"gates slow writes (process throttling)."* Gates preventing corruption (rules checking — invariants holding (incidents declining — trust earning (preventing funding — throttling declining); missing gates slowing recovery (corruption arriving — cleanups paging (incidents multiplying — velocity dying (missing charging — writing declining). "Throttling" describing ceremony (approvals queuing — value missing); gates describing leverage (proof reusing — corruption preventing). Gate writes (guards enforcing — trust earning); ship faster (incidents declining — velocity funding).

**Performance note** — commanding economics: owning costing command handlers (intents stating — guards enforcing (reads declining — mixing ending); uncommanded equivalents costing confusion (lists answering — shapes shaping (intents blurring — audits guessing). Own cheaply (commands — intents); query never (writes — lists).

**Mentor note** — demand "command and guard named" (juniors owning one intent + one guard per mutation design confusion-proof reviews on first hearing; guardless writes interrogated ("which rule?" — commanding demanding per write). Own one write once (intents owning — guards enforcing tangible (querying ending — commanding proving permanently). Name intents; enforce guards — commanding discipline in three habits, reviewed per write.

## 2. Every read projecting (views deriving — staleness budgeting — freshness proving)

**Definition** — the projecting gate: each read derived from folds, budgeted for staleness, proven fresh (views deriving — folds proving (events sequencing — states computing (deriving funding — adhoc ending); staleness budgeting — windows bounding (queries pricing — freshness stating (budgeting owning — hoping ending); freshness proving — gauges measuring (lags asserting — surprises declining (proving funding — assuming declining).

**What problem it solves** — the unprojected trio: *reads mutating* (views editing — sides effecting (purity dying — trust eroding (mutating billing — serving declining); *staleness hoping* (windows unstated — lag unmeasured (surprises scheduling — incidents arriving (hoping costing — budgets missing); *folds impure* (runs differing — histories untrusted (determinism bluffing — confidence declining (impure charging — replay failing). The gate converting mutating to projecting (views deriving — staleness budgeting (freshness proving — sides pure); mentors asking one question per read ("which fold, which lag?" — projecting demanding per query).

**Modern guidance** — the gate commands (run per read, enforced in review):

```typescript
// GOOD: projecting gated — views deriving, staleness budgeting, freshness proving (checklist shape).
// 1. Fold proof (events sequencing — states deriving):
//    every view folded from facts — pure functions, replay-twice identical, logs owned.
// 2. Budget proof (windows bounding — queries pricing):
//    every read naming its staleness window — critical tightening, routine loosening, gauges measuring.
// 3. Purity proof (sides absenting — inputs freezing):
//    queries changing nothing — frozen inputs, copied derives, mutators absent.
// Derive views; budget windows; prove freshness.)
```

```typescript
// BAD: reads unprojecting — views editing, staleness hoping (real unprojected shape).
// view.count += 1; // sides effecting — purity dying, trust eroding.
// const rows = await primary.query(bigJoin); // lag invisible — surprises scheduling, budgets missing.
// } // Gate reads: views deriving, windows bounding, freshness proving.)
```

**Common confusion** — *"gates replace measurement (checks substituting)."* Gates evidencing discipline (views deriving — windows bounding (proof reusing — judgment focusing (evidencing funding — slowing declining); measurement proving numbers (gauges reading — lags asserting (numbers owning — surprises declining (measuring serving — hoping ending). "Replacing" describing substitution (meters skipping — freshness hoping); gates describing evidence (discipline proving — trust earning). Evidence discipline (views deriving — windows bounding); measure freshness (gauges reading — lags asserting).

**Performance note** — projecting economics: deriving costing folds (events sequencing — states computing (questions owning — latency sparing); unprojected equivalents costing surprises (windows unstated — lag unmeasured (incidents arriving — trust eroding). Derive cheaply (folds — views); hope never (staleness — surprises).

**Mentor note** — demand "fold and window stated" (juniors deriving one view + one budget per read design surprise-proof reviews on first hearing; unbudgeted reads interrogated ("which fold, which lag?" — projecting demanding per query). Derive one view once (folds proving — windows bounding tangible (mutating ending — freshness proving permanently). Fold facts; bound windows — projecting discipline in three habits, reviewed per read.

## 3. Every slice owning (features serving — teams answering — deploys decoupling)

**Definition** — the owning gate: each slice serving its feature, answering with a team, deploying decoupled (features serving — reads answering (writes guarding — users trusting (serving proving — handing declining); teams answering — incidents owning (changes shipping — on-call holding (answering funding — bouncing ending); deploys decoupling — pipelines releasing (versions rolling — flags toggling (decoupling owning — training ending).

**What problem it solves** — the unowned trio: *features splitting* (reads answering — writes guarding-elsewhere (users bouncing — handoffs queuing (splitting billing — velocity dying); *teams bouncing* (incidents homeless — changes unowned (ownership missing — quality diffusing (bouncing charging — pride declining); *deploys training* (releases coupling — versions locking (ships coordinating — rollbacks panicking (training billing — autonomy dying). The gate converting splitting to owning (features serving — teams answering (deploys decoupling — handoffs declining); mentors asking one question per slice ("who answers?" — owning demanding per feature).

**Modern guidance** — the gate commands (run per slice, enforced in review):

```typescript
// GOOD: owning gated — features serving, teams answering, deploys decoupling (checklist shape).
// 1. Feature proof (reads answering — writes guarding):
//    every slice serving its feature end to end — queries shaping, commands deciding, users trusting.
// 2. Team proof (incidents owning — changes shipping):
//    every slice naming its owner — on-call holding, ping-pong declining, pride funding.
// 3. Deploy proof (pipelines releasing — versions rolling):
//    every slice deploying decoupled — flags toggling, trains declining, frequency funding.
// Serve features; answer teams; decouple deploys.)
```

```typescript
// BAD: slices unowning — features splitting, deploys training (real unowned shape).
// // No owner, shared deploy (incidents bouncing — releases coupling — velocity dying).
// frontend-team + backend-team + dba-team // handoffs queuing — ownership blurring, pride declining.
// } // Gate owning: features serving, teams answering, deploys decoupling.)
```

**Common confusion** — *"gates replace ownership culture (process substituting)."* Gates evidencing ownership (features serving — teams answering (proof reusing — judgment focusing (evidencing funding — slowing declining); culture living accountability (teams answering — incidents owning (pride funding — quality earning (living serving — bouncing declining). "Replacing" describing substitution (rituals performing — accountability missing); gates describing evidence (ownership proving — trust earning). Evidence ownership (slices serving — teams answering); live accountability (incidents owning — pride funding).

**Performance note** — owning economics: serving costing named owners (features answering — teams responding (handoffs declining — velocity funding); unowned equivalents costing diffusion (incidents bouncing — quality diffusing (pride declining — velocity dying). Own cheaply (slices — names); split never (features — handoffs).

**Mentor note** — demand "owner in the manifest" (juniors owning one slice per team design diffusion-proof reviews on first hearing; ownerless slices interrogated ("who ships?" — owning demanding per slice). Own one slice once (features serving — teams answering tangible (splitting ending — owning proving permanently). Name owners; ship decoupled — owning discipline in three habits, reviewed per slice.
