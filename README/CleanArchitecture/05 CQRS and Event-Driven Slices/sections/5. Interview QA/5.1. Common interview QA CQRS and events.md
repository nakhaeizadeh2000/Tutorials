# 5.1. Common interview QA CQRS and events

## 1. Splits live under pressure (commands, queries, models — diagnosed with fixes, priced)

**Definition** — split answers: commands deciding, queries serving, models funding — under pressure (diagnosed with fixes — causes naming (understanding proving — reciting declining); priced with pressures — ratios owning (judgment funding — dogma refusing (pricing earning — honesty proving).

**What problem it solves** — the reciting trio: *splits chanting* ("CQRS" stating — pressures missing (vocabulary showing — judgment absenting (reciting funding — designing declining); *commands muddying* ("handlers" stating — acks missing (effects blurring — audits guessing (muddying charging — precision declining); *models merging* ("one model" insisting — pressures conflicting (compromise owning — neither serving (merging billing — scaling blocking). Diagnosed answers converting chanting to funding (causes naming — fixes stating (pressures proving — ceremony billing-only-measured); interviewers hiring funders, not chanters (diagnosing proving → hirable; reciting → passed).

**Modern guidance** — answer shape per split question (diagnose → fix → price):

```typescript
// GOOD: "When CQRS?" — diagnosed with fixes, priced (answer shape).
// Diagnose: one model compromising (writes guarding — reads joining — neither serving).
// Fix: commands deciding (intents owning — acks answering); queries serving (views shaping — mutations refusing).
// Price: asymmetry funding (reads multiplying — writes contending — ratios owning — ceremony billing-only-measured).
// Own writes; serve reads — pressure stated, not hoped.)
```

```typescript
// BAD: splits reciting — vocabulary stating, pressures missing (real weak shape).
// "CQRS separates reads and writes." (judgment absenting — ceremony unpriced — designing declining).
// "Eventual consistency everywhere." (critical hoping — incidents arriving — weighing missing).
// Diagnose causes; state fixes; price pressures.)
```

**Common confusion** — *"split answers need pattern names (vocabulary impressing)."* Names labeling separations (words stating — pressures missing (labeling serving — understanding absenting (impressing hoping — hiring declining); answers proving judgment (causes naming — fixes stating (ratios owning — trade-offs pricing (proving funding — reciting declining). "Names" describing vocabulary (patterns listing — models missing); answers describing funding (pressures proving — ceremony pricing). Diagnose causes (understanding proving — chanting declining); price pressures (judgment owning — dogma refusing).

**Performance note** — answer economics: diagnosing costing one cause per question (understanding proving — reciting declining (hirable funding — chanting ending); recited equivalents costing offers (words owning — pressures missing (designing declining — hiring passing). Diagnose cheaply (causes — fixes); recite never (jargon — passes).

**Mentor note** — drill "diagnose, fix, price" (juniors answering one split question per shape design hirable responses on first hearing; vocabulary-only answers interrogated ("which pressure?" — diagnosing demanding per answer). Shape one answer once (causes naming — fixes stating tangible (reciting ending — designing proving permanently). Diagnose causes; fund splits — answering discipline in three habits, reviewed per mock.

## 2. Reads live under pressure (projections, staleness, scaling — honesty stated, not hoped)

**Definition** — read answers: projections folding, staleness budgeting, load spreading — honestly (honesty stating — windows bounding (judgment owning — dogma refusing (stating funding — hoping ending); folds proving (events sequencing — states deriving (determinism owning — adhoc declining (proving serving — bluffing ending).

**What problem it solves** — the handwaving trio: *projections gesturing* ("views" claiming — folds missing (words owning — determinism absenting (gesturing proving — replay failing); *staleness denying* ("real-time" asserting — lag unmeasured (freshness bluffing — surprises scheduling (denying charging — budgets missing); *scaling hoping* ("add replicas" stating — keys unrouted (growth hoping — hotspots forming (hoping billing — routing absenting). Honest answers converting gesturing to proving (folds stating — windows bounding (keys routing — surprises declining); interviewers hiring provers, not gesturers (proving funding → hirable; gesturing → passed).

**Modern guidance** — answer shape per read question (fold → bound → route):

```typescript
// GOOD: "How stay fast at scale?" — folded, bounded, routed (answer shape).
// Fold: projections deriving (events sequencing — states computing — replays repeating).
// Bound: staleness budgeting (windows stating — queries pricing — freshness proving).
// Route: keys distributing (shards owning — hotspots declining — contention sparing).
// Derive views; bound windows; route keys — honesty stated, not hoped.)
```

```typescript
// BAD: reads handwaving — views claiming, staleness denying (real vague shape).
// "Caching solves reads." (windows unstated — invalidation hoping — budgets missing).
// "Replicas scale everything." (keys unrouted — writes ignored — routing absenting).
// Fold facts; budget staleness; route load.)
```

**Common confusion** — *"honesty means hedging capacity (hedges performing)."* Honesty pricing windows (horizons stating — queries pricing (judgment owning — dogma refusing (pricing funding — hoping ending); hedging dodging numbers (answers qualifying — windows blurring (dodging serving — clarity declining (hedging charging — hiring passing). "Hedging" describing dodge (numbers avoiding — clarity declining); honesty describing budgets (windows bounding — freshness proving). Bound windows (horizons stating — surprises declining); price criticality (queries pricing — judgment owning).

**Performance note** — honesty economics: budgeting costing one window (horizons stating — queries pricing (surprises declining — incidents preventing); handwaved equivalents costing surprises (lag unmeasured — freshness bluffing (trust eroding — incidents arriving). Budget cheaply (windows — queries); wave never (hands — surprises).

**Mentor note** — drill "fold, bound, route" (juniors answering one read question per shape design hirable responses on first hearing; caching-only answers interrogated ("which window?" — honesty demanding per answer). Shape one answer once (folds stating — windows bounding tangible (gesturing ending — proving permanently). Derive views; bound staleness — read discipline in three habits, reviewed per mock.

## 3. Slices live under pressure (features, teams, deploys — ownership stated, not hoped)

**Definition** — slice answers: features serving, teams answering, deploys decoupling — ownership stated (slices owning — handoffs declining (velocity funding — diffusion ending (owning proving — splitting refusing); not hoped (manifests asserting — incidents routing (evidence funding — wishing ending (stating serving — hoping declining).

**What problem it solves** — the unowned trio: *features splitting* (reads answering — writes guarding-elsewhere (users bouncing — handoffs queuing (splitting billing — velocity dying); *teams layering* (frontend owning — backend owning (handoffs multiplying — ownership blurring (layering charging — pride declining); *deploys training* (releases coupling — versions locking (ships coordinating — rollbacks panicking (training billing — autonomy dying). Owned answers converting splitting to serving (features owning — teams answering (deploys decoupling — handoffs declining); interviewers hiring owners, not splitters (owning proving → hirable; splitting → passed).

**Modern guidance** — answer shape per slice question (serve → answer → decouple):

```typescript
// GOOD: "How organize for scale?" — served, answered, decoupled (answer shape).
// Serve: features owning (reads answering — writes guarding — users trusting).
// Answer: teams owning (incidents routing — changes shipping — pride funding).
// Decouple: deploys releasing (pipelines owning — flags toggling — trains declining).
// Own features; answer incidents — ownership stated, not hoped.)
```

```typescript
// BAD: slices hoping — features splitting, teams layering (real unowned shape).
// "Full-stack teams." (features unowned — incidents bouncing — proving declining).
// "We deploy together." (releases coupling — autonomy dying — frequency declining).
// Serve features; name owners; decouple deploys.)
```

**Common confusion** — *"slice answers test org charts (structures recalling)."* Charts picturing teams (boxes naming — reports lining (picturing serving — ownership missing (charting funding — serving declining); slices owning delivery (features serving — teams answering (deploys decoupling — handoffs declining (owning proving — splitting refusing). "Charts" describing pictures (teams boxing — reports lining); slices describing accountability (features owning — incidents routing). Picture orgs (boxes naming — reports lining); own slices (features serving — teams answering).

**Performance note** — slice economics: owning costing named owners (features answering — teams responding (handoffs declining — velocity funding); split equivalents costing diffusion (incidents bouncing — quality diffusing (pride declining — velocity dying). Own cheaply (slices — names); split never (features — handoffs).

**Mentor note** — drill "serve, answer, decouple" (juniors answering one slice question per shape design ownership-stated responses on first hearing; full-stack-only answers interrogated ("who answers?" — owning demanding per slice). Shape one answer once (features serving — teams answering tangible (splitting ending — owning proving permanently). State owners; show deploys — slice discipline in three habits, reviewed per mock.
