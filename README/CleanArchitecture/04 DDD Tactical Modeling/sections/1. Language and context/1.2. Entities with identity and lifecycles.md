# 1.2. Entities with identity and lifecycles

## 1. Identity threading (ids tracking — lifecycles spanning — equality keying)

**Definition** — entity identity: immutable id threading one thing through state changes (ids tracking — births assigning (continuity owning — confusion declining (tracking proving — losing ending); lifecycles spanning — states changing (identity holding — history accumulating (spanning funding — resetting declining); equality keying — ids comparing (states ignoring — values declining (keying proving — merging ending).

**What problem it solves** — the idless trio: *equality valuing* (fields comparing — states equating (twins merging — histories confusing (valuing billing — identity missing (comparing charging — continuity breaking); *ids mutating* (keys editing — references dangling (tracking breaking — lookups failing (mutating costing — stability dying (editing charging — trust eroding); *identity fielding* (names keying — emails identifying (attributes shifting — merges colliding (fielding billing — collisions scheduling (keying hoping — uniqueness bluffing). Threaded ids converting confusion to continuity (births assigning — states changing (identity holding — equality keying); reviewers finding id comparison per entity (threading proving → verifiable; valuing → returned).

**Modern guidance** — the threading lines per entity (review-enforced): *ids tracking* (births assigning — continuity owning (confusion declining — losing ending (tracking proving — breaking declining (stability owning — dangling ending); *lifecycles spanning* (states changing — identity holding (history accumulating — resetting declining (spanning funding — forgetting ending (continuity earning — amnesia declining); *equality keying* (ids comparing — states ignoring (values declining — merging ending (keying proving — confusing declining (identity owning — value refusing).

```typescript
// GOOD: identity threading — same id equal across states, different ids unequal (compiled + run live).
class Member { // entity threading — ids tracking, lifecycles spanning
  constructor(readonly id: string, public level: number) {
    if (id.length === 0) throw new Error('id required'); // births assigning — continuity owning, losing ending
  }
  equals(other: Member): boolean { // equality keying — ids comparing, states ignoring
    return this.id === other.id;
  }
}
const a = new Member('m1', 1);
const b = new Member('m1', 5); // same thing, later state — identity holding, history accumulating
const c = new Member('m2', 1); // different thing, same state — twins declining, merges refusing
console.log(a.equals(b) && !a.equals(c) ? 'identity threads' : 'equality values');
```

**Common confusion** — *"database ids are entity identity (storage equaling)."* Storage keys locating rows (tables indexing — queries joining (locating serving — persisting funding (keys owning — rows finding); identity threading lifecycles (births assigning — states changing (continuity owning — history accumulating (threading proving — locating declining). "Database ids" describing storage (rows locating — queries joining); identity describing continuity (things tracking — histories spanning). Locate with keys (storage owning — rows finding); thread with ids (births assigning — equality keying).

**Performance note** — threading economics: keying costing one comparison (ids comparing — states ignoring (continuity owning — confusion declining); valued equivalents costing merges (fields comparing — twins merging (histories confusing — continuity breaking). Key cheaply (ids — births); value never (fields — merges).

**Mentor note** — teach "equal ids, equal things" (juniors keying one id per entity design confusion-proof identity on first hearing; value-compared entities interrogated ("which id?" — threading demanding per equals). ## 2. Lifecycles guarding (states transitioning — rules enforcing — histories keeping)

**Definition** — lifecycle guarding: legal state transitions owned by the entity (states transitioning — moves stating (paths bounding — jumps refusing (transitioning proving — skipping declining); rules enforcing — guards throwing (illegal declining — validity holding (enforcing funding — corruption preventing); histories keeping — moves journaling (audits owning — debugging funding (keeping proving — forgetting ending).

**What problem it solves** — the any-to-any trio: *status stringing* (strings setting — values hoping (states spelling — transitions unowned (stringing billing — validity bluffing); *jumps allowing* (draft shipping — canceled refunding (paths ignoring — rules breaking (allowing charging — integrity failing); *histories forgetting* (moves vanishing — audits guessing (debugging aching — disputes losing (forgetting costing — trust eroding). Guarded lifecycles converting strings to states (moves stating — guards throwing (histories keeping — jumps refusing); reviewers listing legal moves per entity (guarding proving → verifiable; stringing → returned).

**Modern guidance** — the guarding lines per lifecycle (review-enforced): *states transitioning* (moves stating — paths bounding (jumps refusing — skipping declining (transitioning proving — stringing ending (states owning — spells declining); *rules enforcing* (guards throwing — illegal declining (validity holding — corruption preventing (enforcing funding — hoping ending (checks owning — breaks declining); *histories keeping* (moves journaling — audits owning (debugging funding — forgetting ending (keeping proving — vanishing declining (journals earning — disputes winning).

```typescript
// GOOD: lifecycles guarding — legal moves stating, illegal throwing, history kept (compiled + run live).
type Phase = 'draft' | 'placed' | 'shipped';
class Order { // entity guarding — states transitioning, rules enforcing
  private history: Phase[] = ['draft']; // histories keeping — moves journaling, audits owning
  private phase: Phase = 'draft';
  place(): void { this.move('placed', ['draft']); } // moves stating — paths bounding, jumps refusing
  ship(): void { this.move('shipped', ['placed']); }
  private move(next: Phase, from: Phase[]): void {
    if (!from.includes(this.phase)) throw new Error(`illegal: ${this.phase}→${next}`); // guards throwing — illegal declining, validity holding
    this.phase = next;
    this.history.push(next);
  }
  trail(): Phase[] { return [...this.history]; }
}
const order = new Order();
order.place();
order.ship();
let illegal = 0;
const fresh = new Order();
try { fresh.ship(); } catch { illegal += 1; } // jumps refusing — draft shipping declining, integrity holding
console.log(order.trail().join(',') === 'draft,placed,shipped' && illegal === 1 ? 'lifecycles guard' : 'states string');
```

Arrange flows in services (intents sequencing — rules delegating); guard states in entities (moves stating — jumps refusing).

## 3. Entities mutating (changes owning — invariants holding — versions growing)

**Definition** — controlled mutation: entities changing through guarding methods with growing versions (changes owning — methods transitioning (moves stating — setters declining (owning proving — scattering ending); invariants holding — rules checking (validity keeping — corruption refusing (holding funding — breaking declining); versions growing — writes sequencing (staleness detecting — conflicts surfacing (growing proving — overwriting declining).

**What problem it solves** — the wild-mutation trio: *setters exposing* (fields publicing — transitions skipping (guards bypassing — invariants breaking (exposing billing — validity hoping); *versions missing* (writes overwriting — conflicts hiding (staleness ignoring — losses silently (missing costing — integrity bluffing (concurrency hoping — safety declining); *anemia freezing* (models prohibiting — services scripting (behavior homeless — objects dumb (freezing charging — richness declining). Owned mutation converting wildness to control (methods transitioning — versions growing (invariants holding — conflicts surfacing); reviewers finding version checks per mutating flow (owning proving → verifiable; exposing → returned).

**Modern guidance** — the mutating lines per entity (review-enforced): *changes owning* (methods transitioning — moves stating (setters declining — scattering ending (owning proving — exposing refusing (control funding — wildness ending); *invariants holding* (rules checking — validity keeping (corruption refusing — breaks declining (holding funding — hoping ending (guards owning — trust earning); *versions growing* (writes sequencing — staleness detecting (conflicts surfacing — overwriting declining (growing proving — silent-losing ending (concurrency owning — safety funding).

```typescript
// GOOD: entities mutating — guarded methods, versions sequencing, stale writes refused (compiled + run live).
class SeatMap { // entity mutating — changes owning, invariants holding
  private taken = 0;
  private version = 0; // versions growing — writes sequencing, staleness detecting
  constructor(readonly capacity: number) {}
  reserve(atVersion: number): number {
    if (atVersion !== this.version) throw new Error('stale write'); // conflicts surfacing — overwriting declining, safety funding
    if (this.taken >= this.capacity) throw new Error('sold out');
    this.taken += 1;
    this.version += 1;
    return this.version;
  }
  free(): number { return this.capacity - this.taken; }
}
const hall = new SeatMap(2);
const v1 = hall.reserve(0);
let stale = 0;
try { hall.reserve(0); } catch { stale += 1; } // stale refusing — conflicts surfacing, losses declining
hall.reserve(v1);
console.log(hall.free() === 0 && stale === 1 ? 'mutation owns' : 'setters expose');
```
