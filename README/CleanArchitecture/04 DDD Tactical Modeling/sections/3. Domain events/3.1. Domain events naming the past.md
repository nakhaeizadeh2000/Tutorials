# 3.1. Domain events naming the past

## 1. Past naming (facts stating — tenses passing — histories keeping)

**Definition** — domain event: immutable past-tense fact stating what happened in the language (facts stating — changes recording (histories owning — disputes settling (stating proving — commanding declining); tenses passing — verbs ending (placed shipping — paid refunding (passing funding — ordering refusing); histories keeping — sequences journaling (audits owning — debugging funding (keeping proving — forgetting ending).

**What problem it solves** — the command-event trio: *commands eventing* (PlaceOrder publishing — imperatives broadcasting (orders issuing — facts missing (eventing billing — past declining (commanding charging — stating preventing); *events mutating* (facts editing — histories rewriting (immutability breaking — audits lying (mutating costing — trust eroding (editing charging — truth declining); *tech naming* (rows inserting — messages queueing (jargon owning — experts translating (naming billing — speaking declining). Named past converting commanding to stating (verbs passing — facts recording (histories keeping — disputes settling); reviewers reading past-tense business verbs per event (naming proving → verifiable; commanding → returned).

**Modern guidance** — the naming lines per event (review-enforced): *facts stating* (changes recording — histories owning (disputes settling — commanding declining (stating proving — ordering refusing (records owning — instructions declining); *tenses passing* (verbs ending — placed shipping (paid refunding — ordering refusing (passing funding — commanding ending (past owning — imperative declining); *histories keeping* (sequences journaling — audits owning (debugging funding — forgetting ending (keeping proving — vanishing declining (journals earning — disputes winning). Bus and sourcing mechanics are owned in [DP 06/2.2](<../../../../DesignPatterns/06 Modern Patterns and Anti-Patterns/sections/2. Pipelines and events/2.2. Publish-subscribe and event sourcing.md>) — this leaf owns the naming, never the broker.

```typescript
}
class OrderPlaced implements DomainEvent { // tenses passing — verbs ending, ordering refusing

    if (orderId.length === 0) throw new Error('orderId required');

const e = new OrderPlaced('o1', '2026-10-08T12:00:00Z');
const pastTense = /\.placed$|\.shipped$|\.paid$|\.refunded$/; // verbs passed — facts recording, commands declining
console.log(pastTense.test(e.kind) && e.occurredAt.length > 0 ? 'past names' : 'commands event');
```

"Messages" describing transport (bytes carrying — brokers routing); events describing domain (facts stating — past naming). Carry bytes (transports owning — delivery funding); state facts (verbs passing — histories keeping).

**Performance note** — naming economics: stating costing past-tense verbs (facts recording — histories owning (disputes settling — commanding declining); commanded equivalents costing confusion (imperatives broadcasting — facts missing (ordering charging — auditing declining). ## 2. Aggregates publishing (roots emitting — changes announcing — subscribers reacting)

**Definition** — aggregate publishing: roots collecting events during changes, infrastructure dispatching at commit (roots emitting — changes announcing (facts collecting — brokers unknowing (emitting proving — importing declining); changes announcing — subscribers reacting (handlers responding — flows continuing (announcing funding — silencing ending); subscribers reacting — reactions decoupling (emitters ignorant — handlers owning (reacting proving — coupling declining).

**What problem it solves** — the broker-in-entity trio: *entities publishing* (brokers importing — SDKs arriving (vendors owning — policy obeying (publishing billing — ignorance breaking); *events losing* (crashes stranding — commits skipping (dispatch hoping — delivery bluffing (losing costing — consistency breaking (hoping charging — atomicity declining); *subscribers coupling* (emitters naming — handlers depending (reactions binding — flows tangling (coupling billing — autonomy dying). Root publishing converting importing to collecting (roots emitting — commits dispatching (subscribers reacting — brokers edging); reviewers finding zero broker imports in aggregates per flow (publishing proving → verifiable; importing → returned).

**Modern guidance** — the publishing lines per aggregate (review-enforced): *roots emitting* (changes announcing — facts collecting (brokers unknowing — vendors unheard (emitting proving — importing declining (roots owning — SDKs refusing); *changes announcing* (subscribers reacting — handlers responding (flows continuing — silencing ending (announcing funding — hiding declining (facts owning — secrets declining); *subscribers reacting* (reactions decoupling — emitters ignorant (handlers owning — coupling declining (reacting proving — binding ending (autonomy earning — tangling declining).

```typescript
// GOOD: aggregates publishing — roots collecting, commits dispatching, brokers edging (compiled + run live).
interface DomainEvent {
  readonly kind: string;
}
class Order { // root emitting — changes announcing, brokers unknowing
  private readonly staged: DomainEvent[] = []; // facts collecting — commits dispatching, vendors unheard
  constructor(readonly id: string) {}
  place(): void {
    this.staged.push({ kind: 'order.placed' });
  }
  pull(): DomainEvent[] { return this.staged.splice(0); } // commits dispatching — infrastructure owning, entities ignoring
}
function commit(order: Order, dispatch: (e: DomainEvent) => void): number { // UoW owning — boundaries matching, losses declining
  const events = order.pull();
  for (const e of events) dispatch(e); // subscribers reacting — reactions decoupling, coupling declining
  return events.length;
}
const received: string[] = [];
const order = new Order('o3');
order.place();
const before = received.length;
const sent = commit(order, (e) => { received.push(e.kind); });
console.log(before === 0 && sent === 1 && received.join(',') === 'order.placed' ? 'roots publish' : 'brokers import');
```

**Common confusion** — *"publishing needs a broker library (vendors requiring)."* Brokers delivering bytes (transports routing — queues buffering (delivery serving — ordering funding (brokers owning — bytes moving); publishing collecting facts (roots emitting — commits dispatching (subscribers reacting — vendors edging (publishing proving — importing declining). "Broker" describing transport (bytes moving — delivery funding); publishing describing collection (facts collecting — commits dispatching). Collect in roots (facts owning — vendors unheard); deliver at edges (brokers owning — bytes moving).

**Performance note** — publishing economics: collecting costing one list (facts owning — commits dispatching (losses declining — consistency earning); imported equivalents costing ignorance (vendors owning — policy obeying (brokers arriving — heaviness billing). Collect cheaply (lists — roots); import never (brokers — entities).

**Mentor note** — teach "collect in roots, dispatch at commits" (juniors staging one event list per aggregate design loss-proof publishing on first hearing; broker-importing aggregates interrogated ("who dispatches?" — publishing demanding per entity). Collect one fact once (roots emitting — commits dispatching tangible (importing ending — publishing proving permanently). Stage facts; dispatch wholes — publishing discipline in three habits, reviewed per aggregate.

## 3. Events versioning (shapes evolving — consumers tolerating — contracts keeping)

**Definition** — event versioning: facts evolving additively with upcasters bridging old shapes (shapes evolving — fields adding (versions numbering — breaks declining (evolving proving — flag-day ending); consumers tolerating — N/N-1 reading (old accepting — new preferring (tolerating funding — crashing declining); contracts keeping — callers serving (compatibility holding — trust earning (keeping owning — breaking refusing).

**What problem it solves** — the breaking-fact trio: *fields renaming* (consumers crashing — replays failing (renames billing — history breaking (breaking charging — auditing declining); *versions forking* (v1 diverging — v2 duplicating (streams splitting — maintenance doubling (forking multiplying — consistency failing); *upcasters missing* (old unreadable — migrations flagging (shapes freezing — evolution stopping (missing costing — progress ending). Versioned events converting breaking to evolving (fields adding — upcasters bridging (consumers tolerating — contracts keeping); reviewers rejecting renames per event (versioning proving → verifiable; breaking → returned).

**Modern guidance** — the versioning lines per event (review-enforced): *shapes evolving* (fields adding — versions numbering (breaks declining — flag-day ending (evolving proving — renaming refusing (growth owning — fear declining); *consumers tolerating* (N/N-1 reading — old accepting (new preferring — crashing declining (tolerating funding — forking ending (robustness owning — brittleness declining); *contracts keeping* (callers serving — compatibility holding (trust earning — breaking refusing (keeping owning — crashing declining (stability proving — churn declining).

```typescript
// GOOD: events versioning — v1 upcast to v2, consumers reading both (compiled + run live).
interface PlacedV1 { // fact versioning — shapes evolving, breaks declining
  readonly v: 1;
  readonly orderId: string;
  readonly total: number;
}
interface PlacedV2 {
  readonly v: 2;
  readonly orderId: string;
  readonly total: number;
  readonly currency: string; // fields adding — versions numbering, flag-day ending
}
function upcast(e: PlacedV1 | PlacedV2): PlacedV2 { // upcasters bridging — old reading, evolution continuing
  return e.v === 2 ? e : { v: 2, orderId: e.orderId, total: e.total, currency: 'USD' };
}
function summarize(e: PlacedV1 | PlacedV2): string { // consumers tolerating — N/N-1 reading, crashing declining
  const c = upcast(e);
  return `${c.orderId}:${c.total}${c.currency}`;
}
console.log(summarize({ v: 1, orderId: 'o1', total: 44 }) === 'o1:44USD' && summarize({ v: 2, orderId: 'o2', total: 9, currency: 'EUR' }) === 'o2:9EUR' ? 'events version' : 'facts break');
```

```typescript
// BAD: facts breaking — fields renaming, upcasters missing (real break shape).
// { order_id: 'o1' } → { id: 'o1' } // consumers crashing — replays failing, history breaking.
// // No upcaster (old unreadable — migrations flagging). Evolve additive; bridge with upcasters.)
```

**Common confusion** — *"versioning means event sourcing (patterns equaling)."* Versioning evolving facts (fields adding — consumers tolerating (contracts keeping — breaks declining (evolving serving — crashing ending); sourcing deriving state (logs appending — folds replaying (truth owning — audits funding (sourcing funding — updating declining). "Sourcing" describing storage (logs owning — state deriving); versioning describing compatibility (shapes evolving — consumers tolerating). Evolve facts (fields adding — contracts keeping); source where audit pays (logs appending — folds replaying).

**Performance note** — event-versioning economics: bridging costing one upcaster (fields adding — consumers tolerating (evolution continuing — progress funding); broken equivalents costing replays (consumers crashing — histories breaking (auditing declining — trust eroding). Bridge cheaply (upcasters — versions); break never (renames — histories).

**Mentor note** — teach "additive first, upcast always" (juniors bridging one version per event design break-free histories on first hearing; renamed facts interrogated ("which upcaster?" — versioning demanding per change). Bridge one shape once (fields adding — consumers tolerating tangible (breaking ending — evolution proving permanently). Add fields; read both — versioning discipline in three habits, reviewed per event.
