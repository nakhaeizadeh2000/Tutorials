# 5.1. Common interview QA tactical DDD

## 1. Language live under pressure (terms, contexts, maps — diagnosed with fixes, priced)

**Definition** — language answers: terms shared, contexts bounded, maps drawn — under pressure (diagnosed with fixes — causes naming (understanding proving — reciting declining); priced with trade-offs — rigor billing (judgment owning — dogma refusing (pricing funding — honesty earning).

**What problem it solves** — the reciting trio: *terms listing* ("ubiquitous language" stating — experts missing (vocabulary showing — rigor absenting (reciting funding — designing declining); *contexts gesturing* ("bounded" claiming — meanings unscoped (words owning — collisions hiding (gesturing proving — bounding declining); *maps handwaving* ("context map" sketching — relations unnamed (pictures serving — ownership missing (handwaving charging — autonomy declining). Diagnosed answers converting reciting to designing (causes naming — fixes stating (understanding proving — chanting declining); interviewers hiring designers, not chanters (diagnosing proving → hirable; reciting → passed).

**Modern guidance** — answer shape per language question (diagnose → fix → price):

```typescript
// GOOD: "What is ubiquitous language?" — diagnosed with fixes, priced (answer shape).
// Diagnose: translation layers (tech colonizing — experts translating — meetings misaligning).
// Fix: experts naming (code echoing — models speaking — meanings bounding).
// Price: rigor per term (meetings aligning — translating declining); contexts bounding collisions (precision funding — merging breaking).
// Name from experts; echo in code — rigor stated, not hoped.)
```

```typescript
// BAD: language reciting — terms listing, contexts gesturing (real weak shape).
// "Common vocabulary for the team." (experts missing — rigor absenting — designing declining).
// "Microservices have contexts." (meanings unscoped — deployables equaling — bounding declining).
// Diagnose causes; state fixes; price honestly.)
```

**Common confusion** — *"language answers need Evans quotes (authority impressing)."* Quotes reciting definitions (words owning — models missing (reciting serving — understanding absenting (quoting hoping — hiring declining); answers proving rigor (causes naming — fixes stating (costs pricing — trade-offs owning (proving funding — chanting declining). "Quotes" describing authority (definitions reciting — models missing); answers describing design (terms sharing — contexts bounding). Diagnose causes (understanding proving — reciting declining); price fixes (judgment owning — dogma refusing).

**Performance note** — answer economics: diagnosing costing one cause per question (understanding proving — reciting declining (hirable funding — chanting ending); recited equivalents costing offers (words owning — experts missing (designing declining — hiring passing). Diagnose cheaply (causes — fixes); recite never (quotes — passes).

**Mentor note** — drill "diagnose, fix, price" (juniors answering one language question per shape design hirable responses on first hearing; vocabulary-only answers interrogated ("which expert term?" — diagnosing demanding per answer). Shape one answer once (causes naming — fixes stating tangible (reciting ending — designing proving permanently). Diagnose causes; price fixes — answering discipline in three habits, reviewed per mock.

## 2. Models live under pressure (entities, values, aggregates — honesty stated, not hoped)

**Definition** — modeling answers: entities threading, values freezing, aggregates rooting — honestly (honesty stating — contexts weighing (judgment owning — dogma refusing (stating funding — hoping ending); distinctions holding (ids tracking — fields equaling (spans bounding — confusion declining (holding proving — merging breaking).

**What problem it solves** — the muddling trio: *models merging* ("objects" stating — jobs blurring (vocabulary owning — ownership missing (muddling billing — designing declining); *values identifying* (ids numbering — twins confusing (equality bluffing — continuity missing (identifying charging — comparing declining); *aggregates ballooning* (graphs loading — locks contending (thought missing — contention growing (ballooning billing — sizing declining). Honest answers converting muddling to distinguishing (ids threading — fields equaling (spans bounding — confusion declining); interviewers hiring distinguishers, not muddlers (holding proving → hirable; muddling → passed).

**Modern guidance** — answer shape per modeling question (distinguish → own → bound):

```typescript
// GOOD: "Entity vs value object vs aggregate?" — distinguished, owned, bounded (answer shape).
// Distinguish: ids threading (entities tracking — lifecycles spanning); fields equaling (values comparing — ids declining).
// Own: roots guarding (invariants spanning — entries funneling — writes atomizing).
// Bound: spans sizing (consistency scoping — references keying — graphs pruning).
// Thread ids; freeze values; root spans — honesty stated, not hoped.)
```

```typescript
// BAD: models muddling — objects stating, distinctions missing (real muddled shape).
// "Entities have ids, VOs don't, aggregates are big entities." (jobs missing — spans unowned — designing declining).
// "Aggregates group related objects." (invariants homeless — boundaries hoping — sizing declining).
// Distinguish jobs; own spans; bound consistency.)
```

**Common confusion** — *"honesty means hedging (confidence performing)."* Honesty pricing distinctions (ids threading — fields equaling (spans bounding — confusion declining (pricing funding — hoping ending); hedging dodging commitments (answers qualifying — positions blurring (dodging serving — clarity declining (hedging charging — hiring passing). "Hedging" describing dodge (commitments avoiding — clarity declining); honesty describing precision (distinctions holding — trade-offs owning). Hold distinctions (jobs stating — confusion declining); price trade-offs (costs itemizing — judgment owning).

**Performance note** — honesty economics: distinguishing costing one job per block (ids tracking — fields equaling (spans bounding — confusion declining); muddled equivalents costing offers (vocabulary owning — ownership missing (designing declining — hiring passing). Distinguish cheaply (jobs — blocks); muddle never (objects — blur).

**Mentor note** — drill "distinguish, own, bound" (juniors answering one modeling question per shape design hirable responses on first hearing; big-entity answers interrogated ("which span?" — distinguishing demanding per answer). Shape one answer once (jobs stating — spans bounding tangible (muddling ending — distinguishing proving permanently). State jobs; bound spans — modeling discipline in three habits, reviewed per mock.

## 3. Events live under pressure (facts, publishing, versions — ownership stated, not hoped)

**Definition** — event answers: facts naming, roots emitting, versions evolving — ownership stated (changes homing — commits dispatching (shapes bridging — histories keeping (owning proving — silence declining); not hoped (runs asserting — replays proving (evidence funding — wishing ending (stating serving — hoping declining).

**What problem it solves** — the silent trio: *facts commanding* (imperatives broadcasting — histories missing (ordering charging — auditing declining (commanding billing — stating preventing); *brokers importing* (SDKs arriving — vendors owning (ignorance breaking — heaviness billing (importing charging — policy obeying); *versions breaking* (fields renaming — consumers crashing (replays failing — history breaking (breaking charging — evolution stopping). Owned answers converting silence to facts (verbs passing — roots emitting (upcasters bridging — histories keeping); interviewers hiring owners, not hopers (stating proving → hirable; silence → passed).

**Modern guidance** — answer shape per event question (name → emit → evolve):

```typescript
// GOOD: "How do aggregates communicate?" — named, emitted, evolved (answer shape).
// Name: past-tense facts (verbs passing — histories keeping — commands declining).
// Emit: roots collecting (commits dispatching — brokers edging — vendors unheard).
// Evolve: additive shapes (fields adding — upcasters bridging — consumers tolerating).
// State facts; collect roots; bridge versions — ownership stated, not hoped.)
```

```typescript
// BAD: events hoping — facts commanding, brokers importing (real silent shape).
// "Services publish messages." (verbs missing — facts absenting — auditing declining).
// "We use Kafka." (transports owning — domain missing — meaning declining).
// Name facts; emit roots; evolve additive.)
```

**Common confusion** — *"event answers test tooling (brokers recalling)."* Tooling moving bytes (transports routing — queues buffering (delivery funding — ordering owning (tooling serving — meaning declining); events owning history (facts stating — verbs passing (roots emitting — versions evolving (owning funding — silence declining). "Tooling" describing transport (bytes moving — delivery funding); events describing domain (facts naming — histories keeping). Route bytes (transports owning — delivery funding); own history (facts stating — versions evolving).

**Performance note** — event economics: owning costing one fact (verbs passing — roots emitting (histories keeping — audits winning); silent equivalents costing disputes (moves vanishing — audits guessing (truth declining — trust eroding). Own cheaply (facts — events); silence never (changes — disputes).

**Mentor note** — drill "name, emit, evolve" (juniors answering one event question per shape design ownership-stated responses on first hearing; kafka-only answers interrogated ("which fact?" — owning demanding per event). Shape one answer once (facts naming — roots emitting tangible (silence ending — owning proving permanently). State past; bridge versions — event discipline in three habits, reviewed per mock.
