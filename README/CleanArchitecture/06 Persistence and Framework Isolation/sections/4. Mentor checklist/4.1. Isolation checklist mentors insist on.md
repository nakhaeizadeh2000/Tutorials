# 4.1. Isolation checklist mentors insist on

## 1. Every crossing mapping (directions separating — logic declining — layers holding)

**Definition** — the mapping gate: each persistence crossing mapped per direction, logic declined, layers holding (directions separating — inbound building (outbound shaping — god declining (separating proving — sharing ending); logic declining — decisions absenting (branches refusing — services ruling (declining funding — bloating ending); layers holding — crossings owning (translations serving — leaks preventing (holding proving — mixing declining).

**What problem it solves** — the unmapped trio: *directions sharing* (god objects mapping — concerns mixing (changes rippling — ownership blurring (sharing billing — cohesion fading); *logic branching* (mappers deciding — policies duplicating (guards forking — drift growing (branching charging — consistency failing); *layers leaking* (entities traveling — secrets broadcasting (behavior exposing — methods serializing (leaking billing — exposure scheduling). The gate converting sharing to separating (inbound building — outbound shaping (logic declining — layers holding); mentors asking one question per crossing ("which direction, whose logic?" — mapping demanding per mapper).

**Modern guidance** — the gate commands (run per crossing, enforced in review):

```typescript
// GOOD: mapping gated — directions separating, logic declining, layers holding (checklist shape).
// 1. Direction proof (inbound building — outbound shaping):
//    one function per direction per crossing — god mappers split, shapes drifting nowhere.
// 2. Purity proof (deps passing — outputs determining):
//    mappers importing nothing — dependencies argued, globals absent, flakes declining.
// 3. Logic proof (decisions absenting — branches refusing):
//    zero branches per mapper — entities deciding, services ruling, duplication declining.
// Separate directions; argue deps; decline logic.)
```

```typescript
// BAD: crossings unmapping — directions sharing, logic branching (real unmapped shape).
// class Mapper { toEntity() {} toDto() {} toRow() {} decide() {} } // concerns mixing — ownership blurring.
// // Mappers querying repos (I/O hiding — tests heavying). Map per direction; argue deps; decline branches.)
```

**Common confusion** — *"gates slow persistence work (process throttling)."* Gates preventing leaks (shapes staying — errors mapping (exposure declining — breaches preventing (preventing funding — throttling declining); missing gates slowing debugging (entities traveling — secrets broadcasting (leaks hiding — incidents arriving (missing charging — writing declining). "Throttling" describing ceremony (approvals queuing — value missing); gates describing leverage (proof reusing — leaks preventing). Gate crossings (translations owning — leaks preventing); ship faster (incidents declining — velocity funding).

**Performance note** — mapping economics: separating costing functions (inbound building — outbound shaping (layers holding — drift ending); shared equivalents costing ripple (changes breaking — contracts surprising (ownership blurring — trust eroding). Separate cheaply (functions — directions); share never (objects — ripples).

**Mentor note** — demand "direction per function" (juniors separating one crossing per direction design ripple-proof reviews on first hearing; god mappers interrogated ("which direction?" — mapping demanding per function). Separate one crossing once (inbound building — outbound shaping tangible (sharing ending — holding proving permanently). Build inbound; shape outbound — mapping discipline in three habits, reviewed per crossing.

## 2. Every vendor hiding (drivers concealing — cores ignoring — swaps earning)

**Definition** — the hiding gate: each vendor concealed behind ports, cores ignorant, swaps earned (drivers concealing — vendors wrapping (details serving — cores ruling (concealing proving — dictating declining); cores ignoring — ports importing (drivers unheard — vendors unknown (ignoring funding — heaviness declining); swaps earning — replacements proving (vendors trading — confidence funding (earning owning — hoping ending).

**What problem it solves** — the unhidden trio: *drivers typing* (pools declaring — cores importing (vendors owning — policy obeying (typing billing — leverage inverting); *frameworks centering* (structures branding — cores editing (choices earlying — options dying (centering charging — policy whispering); *swaps hoping* (vendors shipping — contracts missing (behaviors bluffing — suites absenting (hoping billing — lock-in hardening). The gate converting typing to concealing (drivers wrapping — cores ignoring (swaps earning — rewrites declining); mentors asking one question per vendor ("which port hides it?" — hiding demanding per driver).

**Modern guidance** — the gate commands (run per vendor, enforced in review):

```typescript
// GOOD: hiding gated — drivers concealing, cores ignoring, swaps earning (checklist shape).
// 1. Signature proof (ports importing — drivers unheard):
//    zero driver names in core signatures — ports declaring, vendors wrapping, leverage keeping.
// 2. Edge proof (frameworks edging — cores ruling):
//    frameworks living in adapters only — upgrades localizing, policies deciding, rewrites declining.
// 3. Swap proof (replacements proving — vendors trading):
//    every vendor rehearsed and stranglable — suites pinning, traffic bleeding, rollbacks readying.
// Conceal drivers; edge frameworks; earn swaps.)
```

```typescript
// BAD: vendors unhiding — drivers typing, frameworks centering (real unhidden shape).
// constructor(private readonly pool: Pool) {} // vendors owning — policy obeying, leverage inverting.
// import { FastifyRequest } from 'fastify'; // inside the use case — choices earlying, options dying.
// } // Gate hiding: drivers concealing, cores ignoring, swaps earning.)
```

**Common confusion** — *"gates distrust vendors (suspicion performing)."* Gates quarantining risks (drivers wrapping — cores ignoring (proof reusing — judgment focusing (quarantining funding — slowing declining); distrust refusing tools (vendors declining — work rebuilding (refusing serving — value missing (distrusting charging — pragmatism declining). "Distrust" describing refusal (tools declining — work rebuilding); gates describing quarantine (vendors containing — cores ruling). Quarantine risks (drivers wrapping — cores ignoring); use vendors (details serving — policy deciding).

**Performance note** — hiding economics: concealing costing wrappers (vendors wrapping — cores ruling (swaps earning — rewrites declining); typed equivalents costing leverage (vendors owning — policy obeying (migrations fearing — upgrades pinning). Conceal cheaply (wrappers — ports); type never (drivers — signatures).

**Mentor note** — demand "port per vendor" (juniors concealing one driver per repository design quarantine-carrying reviews on first hearing; driver-typed cores interrogated ("which adapter?" — hiding demanding per import). Hide one vendor once (drivers wrapping — cores ignoring tangible (typing ending — quarantine proving permanently). ## 3. Every change migrating (shapes evolving — transitions bridging — downtime declining)

**Definition** — the migrating gate: each model change evolving additively, bridging transitions, declining downtime (shapes evolving — fields adding (versions numbering — breaks declining (evolving proving — renaming refusing); transitions bridging — expands contracting (duals mapping — rollbacks keeping (bridging funding — banging declining); downtime declining — deploys overlapping (readers tolerating — writers sequencing (declining owning — windowing refusing).

**What problem it solves** — the unmigrated trio: *shapes renaming* (fields rebranding — readers crashing (contracts breaking — deploys coordinating (renaming billing — flag-days scheduling); *transitions banging* (tables locking — writes blocking (downtimes scheduling — users waiting (banging charging — availability declining); *downtimes windowing* (maintenance announcing — trust taxing (scheduling billing — availability declining (windowing charging — overlapping refusing). The gate converting renaming to evolving (shapes growing — transitions bridging (downtime declining — cuts avoiding); mentors asking one question per change ("which phase, which rollback?" — migrating demanding per model).

**Modern guidance** — the gate commands (run per model change, enforced in review):

```typescript
// GOOD: migrating gated — shapes evolving, transitions bridging, downtime declining (checklist shape).
// 1. Evolution proof (fields adding — versions numbering):
//    models growing additive with numbered versions — renames versioned, readers adapting, breaks declining.
// 2. Transition proof (expands contracting — duals mapping):
//    expand-dual-contract phases sequenced — old removed last, rollbacks kept, downtimes declining.
// 3. Overlap proof (versions coexisting — traffic sharing):
//    old and new serving together — readers tolerating, writers sequencing, windows declining.
// Evolve additive; bridge phases; overlap deploys.)
```

```typescript
// BAD: changes unmigrating — shapes renaming, transitions banging (real unmigrated shape).
// ALTER TABLE ... RENAME ...; // readers crashing — deploys coordinating, flag-days scheduling.
// // Sunday maintenance window (downtimes planning — trust taxing). Grow shapes; bridge transitions; overlap deploys.)
```

**Common confusion** — *"gates replace migration tooling (checks substituting)."* Gates evidencing discipline (shapes evolving — transitions bridging (proof reusing — judgment focusing (evidencing funding — slowing declining); tooling executing mechanics (phases scripting — windows planning (executing serving — stopping declining (tooling funding — banging ending). "Replacing" describing substitution (scripts skipping — phases hoping); gates describing evidence (discipline proving — trust earning). Evidence discipline (shapes evolving — transitions bridging); execute tooling (phases scripting — windows planning).

**Performance note** — migrating economics: evolving costing additive fields (shapes growing — versions numbering (breaks declining — coordination sparing); renamed equivalents costing flag-days (deploys synchronizing — readers crashing (trust eroding — incidents scheduling). Evolve cheaply (fields — versions); rename never (shapes — flags).

**Mentor note** — demand "phase and rollback stated" (juniors evolving one model per three phases design window-free reviews on first hearing; phaseless alters interrogated ("where is the dual?" — migrating demanding per change). Evolve one shape once (fields adding — transitions bridging tangible (banging ending — safety proving permanently). Grow additive; keep rollbacks — migrating discipline in three habits, reviewed per change.
