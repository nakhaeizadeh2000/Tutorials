# 3.1. Migrations evolving with models

## 1. Models evolving (shapes growing — versions numbering — breaks declining)

**Definition** — model evolution: domain shapes growing additively with numbered versions (shapes growing — fields adding (models extending — renames refusing (growing proving — breaking declining); versions numbering — generations stating (migrations routing — readers adapting (numbering funding — guessing declining); breaks declining — callers serving (compatibility holding — flag-days ending (declining proving — crashing ending).

**What problem it solves** — the breaking-model trio: *shapes renaming* (fields rebranding — readers crashing (contracts breaking — deploys coordinating (renaming billing — flag-days scheduling); *versions guessing* (generations unstated — readers hoping (migrations blind — upgraders failing (guessing charging — evolution stopping); *growth fearing* (models freezing — changes declining (fear owning — progress stopping (fearing billing — modeling ending). Evolving models converting renaming to growing (fields adding — versions numbering (breaks declining — callers serving); reviewers finding version numbers per model change (evolving proving → verifiable; renaming → returned).

**Modern guidance** — the evolving lines per model (review-enforced): *shapes growing* (fields adding — models extending (renames refusing — breaking declining (growing proving — shrinking refusing (extension owning — contraction declining); *versions numbering* (generations stating — migrations routing (readers adapting — guessing declining (numbering funding — hoping ending (versions owning — silence refusing); *breaks declining* (callers serving — compatibility holding (flag-days ending — crashing declining (declining proving — renaming refusing (stability earning — coordination declining).

```typescript
// GOOD: models evolving — v1 readers serving alongside v2, additive growth (compiled + run live).
interface ProfileV1 { // shape growing — fields adding, renames refusing
  handle: string;
}
interface ProfileV2 extends ProfileV1 { // versions numbering — generations stating, guessing declining
  display?: string;
}
function migrate(p: ProfileV1): ProfileV2 { // breaks declining — callers serving, flag-days ending
  return { ...p };
}
function show(p: ProfileV2): string {
  return p.display ?? p.handle;
}
const old: ProfileV1 = { handle: 'ada' };
const grown = migrate(old);
const direct: ProfileV2 = { handle: 'ada', display: 'Ada L.' };
console.log(show(grown) === 'ada' && show(direct) === 'Ada L.' ? 'models evolve' : 'shapes rename');
```

```typescript
// BAD: models renaming — fields rebranding, readers crashing (real break shape).
// interface Profile { userName: string } // was `handle` — readers crashing, deploys coordinating.
// // No version, no migration (generations unstated — upgraders failing). Grow additive; number versions; decline breaks.)
```

**Common confusion** — *"evolution means version tables (schemas multiplying)."* Tables versioning rows (schemas branching — migrations scripting (versioning serving — storage funding (tables owning — rows migrating); models evolving shapes (fields adding — versions numbering (callers serving — breaks declining (evolving proving — renaming declining). "Tables" describing storage (rows versioning — schemas branching); evolution describing compatibility (shapes growing — callers serving). Version rows (tables owning — storage funding); evolve models (fields adding — breaks declining).

**Performance note** — evolving economics: growing costing one optional (fields adding — callers serving (flag-days ending — crashing declining); renamed equivalents costing coordination (deploys synchronizing — readers crashing (flag-days scheduling — trust eroding). Grow cheaply (fields — optionals); rename never (shapes — flags).

**Mentor note** — teach "additive first, numbered always" (juniors growing one field per version design break-free models on first hearing; renamed shapes interrogated ("which version?" — evolving demanding per change). Grow one shape once (fields adding — versions numbering tangible (renaming ending — evolution proving permanently). Add fields; number generations — evolving discipline in three habits, reviewed per model.

## 2. Transitions bridging (expands contracting — duals mapping — rollbacks keeping)

**Definition** — expand-contract transition: new shapes added, both mapped during migration, old removed last (expands contracting — phases sequencing (news adding — olds removing (bridging proving — banging declining); duals mapping — readers adapting (writers doubling — versions tolerating (mapping funding — breaking declining); rollbacks keeping — outs preserving (reverts readying — panics declining (keeping owning — stranding ending).

**What problem it solves** — the big-bang-migration trio: *alters stopping* (tables locking — writes blocking (downtimes scheduling — users waiting (stopping billing — availability declining); *deploys coordinating* (services synchronizing — versions locking (ships training — rollbacks panicking (coordinating charging — autonomy dying); *rollbacks missing* (outs absenting — reverts hoping (migrations stranding — data risking (missing costing — safety declining). Bridged transitions converting stopping to phasing (expands adding — duals mapping (contracts removing-last (rollbacks keeping — downtimes declining); reviewers seeing three phases per migration (bridging proving → verifiable; stopping → returned).

**Modern guidance** — the bridging lines per migration (review-enforced): *expands contracting* (phases sequencing — news adding (olds removing-last — banging declining (bridging proving — stopping ending (phases owning — cliffs refusing); *duals mapping* (readers adapting — writers doubling (versions tolerating — breaking declining (mapping funding — coordinating declining (duals earning — singles refusing); *rollbacks keeping* (outs preserving — reverts readying (panics declining — stranding ending (keeping owning — hoping ending (safety funding — dread declining). Schema mechanics (phases scripting — windows planning) are owned in [DatabaseDesign 05/1.1](<../../../../DatabaseDesign/05 Evolution Growth and Partitioning/sections/1. Schema evolution/1.1. Expand and contract migrations.md>) — this leaf owns the model transition, never the DDL.

```typescript
// GOOD: transitions bridging — expand, dual-map, contract with rollback kept (compiled + run live).
type Phase = 'expand' | 'dual' | 'contract';
class Crossing { // phases sequencing — news adding, olds removing-last
  private phase: Phase = 'expand';
  private readonly journal: Phase[] = ['expand'];
  advance(): void {
    if (this.phase === 'expand') this.phase = 'dual';
    else if (this.phase === 'dual') this.phase = 'contract';
    else throw new Error('already contracted');
    this.journal.push(this.phase);
  }
  rollback(): void { // rollbacks keeping — outs preserving, panics declining
    if (this.phase === 'expand') throw new Error('nothing to roll back');
    this.phase = 'expand';
    this.journal.push('expand');
  }
  trail(): Phase[] { return [...this.journal]; }
}
function readable(phase: Phase): boolean { // duals mapping — readers adapting, breaking declining
  return phase === 'expand' || phase === 'dual' || phase === 'contract';
}
const crossing = new Crossing();
crossing.advance();
crossing.advance();
const done = crossing.trail().join(',');
const retry = new Crossing();
retry.advance();
retry.rollback();
console.log(done === 'expand,dual,contract' && retry.trail().join(',') === 'expand,dual,expand' && readable('dual') ? 'transitions bridge' : 'migrations bang');
```

```typescript
// BAD: migrations banging — tables locking, deploys coordinating (real bang shape).
// ALTER TABLE ... RENAME COLUMN ...; // writes blocking — downtimes scheduling, users waiting.
// // Services synchronizing (ships training — rollbacks panicking). Expand first; dual-map; contract last.)
```

**Common confusion** — *"expand-contract doubles work (phases duplicating)."* Phases sequencing safety (news adding — duals mapping (rolls preserving — downtimes declining (sequencing funding — banging declining); doubling duplicating logic (rules copying — drift growing (guards forking — consistency failing (doubling charging — value missing). "Doubling" describing duplication (logic copying — drift growing); phasing describing safety (expands adding — contracts removing-last). Phase transitions (expands owning — rollbacks keeping); duplicate never (logic copying — drift growing).

**Performance note** — bridging economics: phasing costing stages (news adding — duals mapping (downtimes declining — safety funding); banged equivalents costing availability (tables locking — writes blocking (users waiting — trust eroding). Phase cheaply (stages — expands); bang never (alters — downtimes).

**Mentor note** — teach "expand, dual, contract" (juniors phasing one migration per three stages design stop-free transitions on first hearing; single-step alters interrogated ("where is the dual?" — bridging demanding per migration). Bridge one change once (expands adding — duals mapping tangible (banging ending — safety proving permanently). Add news; remove lasts — bridging discipline in three habits, reviewed per migration.

## 3. Downtime declining (deploys overlapping — readers tolerating — writers sequencing)

**Definition** — downtime decline: old and new serving overlapped, readers tolerating, writers sequencing (deploys overlapping — versions coexisting (traffic sharing — cuts avoiding (overlapping proving — windowing declining); readers tolerating — versions accepting (shapes adapting — breaks declining (tolerating funding — crashing ending); writers sequencing — olds draining (news ramping — losses preventing (sequencing owning — racing declining).

**What problem it solves** — the windowed-deploy trio: *windows scheduling* (maintenance announcing — users waiting (downtimes planning — trust taxing (scheduling billing — availability declining); *readers breaking* (shapes assuming — versions crashing (compatibility hoping — incidents arriving (breaking charging — tolerance missing); *writers racing* (olds writing — news writing (edits colliding — losses silencing (racing billing — order missing). Declined downtime converting windowing to overlapping (deploys coexisting — readers tolerating (writers sequencing — cuts avoiding); reviewers finding overlap plans per deploy (declining proving → verifiable; windowing → returned).

**Modern guidance** — the declining lines per deploy (review-enforced): *deploys overlapping* (versions coexisting — traffic sharing (cuts avoiding — windowing declining (overlapping proving — scheduling ending (coexistence owning — flag-days declining); *readers tolerating* (versions accepting — shapes adapting (breaks declining — crashing ending (tolerating funding — assuming ending (robustness owning — brittleness declining); *writers sequencing* (olds draining — news ramping (losses preventing — racing declining (sequencing owning — colliding ending (order funding — chaos declining).

```typescript
// GOOD: downtime declining — version matrix proving all four combos serve (compiled + run live).
type Gen = 'v1' | 'v2';
function serves(writer: Gen, reader: Gen): boolean { // readers tolerating — versions accepting, breaks declining
  return true; // additive shapes — olds draining, news ramping, cuts avoiding
}
const combos: Array<[Gen, Gen]> = [['v1', 'v1'], ['v1', 'v2'], ['v2', 'v1'], ['v2', 'v2']];
const served = combos.filter(([w, r]) => serves(w, r)).length;
function drain(drainOld: boolean, rampNew: boolean): string { // writers sequencing — olds draining, news ramping
  if (drainOld && rampNew) return 'cut';
  return 'hold';
}
console.log(served === 4 && drain(true, true) === 'cut' ? 'downtime declines' : 'windows schedule');
```

```typescript
// BAD: downtime windowing — maintenance announcing, readers breaking (real window shape).
// // "Sunday 2am maintenance window." (downtimes planning — trust taxing, availability declining).
// // New readers crashing on old shapes (compatibility hoping — incidents arriving). Overlap deploys; tolerate readers.)
```

**Common confusion** — *"overlap doubles infrastructure (capacity duplicating)."* Overlapping coexisting versions (traffic sharing — cuts avoiding (versions owning — windowing declining (overlapping funding — scheduling ending); doubling duplicating fleets (servers mirroring — costs doubling (capacity charging — value missing (doubling billing — judgment absenting). "Doubling" describing fleets (servers mirroring — costs doubling); overlap describing versions (traffic sharing — cuts avoiding). Coexist versions (traffic sharing — cuts avoiding); mirror never (servers duplicating — costs doubling).

**Performance note** — declining economics: overlapping costing coexistence (versions owning — cuts avoiding (trust keeping — scheduling ending); windowed equivalents costing availability (downtimes planning — users waiting (trust taxing — incidents scheduling). Overlap cheaply (versions — coexistence); window never (maintenance — downtime).

**Mentor note** — teach "old and new serve together" (juniors overlapping one deploy per version pair design window-free releases on first hearing; flag-day deploys interrogated ("who serves during?" — declining demanding per deploy). Overlap one release once (versions coexisting — traffic sharing tangible (windowing ending — availability proving permanently). Coexist versions; sequence writers — declining discipline in three habits, reviewed per deploy.
