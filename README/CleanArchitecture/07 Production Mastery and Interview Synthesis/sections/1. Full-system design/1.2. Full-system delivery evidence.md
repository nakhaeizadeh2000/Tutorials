# 1.2. Full-system delivery evidence

## 1. Tests gating merges (units proving — contracts asserting — fakes substituting)

**Definition** — merge gating: merges landing only on green unit, contract, and headless suites (units proving — rules asserting (cores guarding — regressions declining (proving funding — hoping ending); contracts asserting — adapters passing (behaviors matching — drifts detecting (asserting owning — assuming declining); fakes substituting — vendors doubling (suites headlessing — feedback speeding (substituting funding — booting declining).

**What problem it solves** — the red-merge trio: *merges hoping* (suites unrun — coverage bluffed (greens assuming — reds landing (hoping billing — incidents scheduling); *vendors unproven* (adapters shipping — contracts missing (behaviors bluffing — swaps fearing (unproven charging — lock-in hardening); *coverage lying* (numbers stating — paths missing (metrics gaming — confidence bluffing (lying costing — trust eroding). Gated merges converting hoping to proving (units asserting — contracts passing (fakes substituting — reds blocking); reviewers seeing gate output per merge (gating proving → verifiable; hoping → returned).

**Modern guidance** — the gating lines per merge (review-enforced): *units proving* (rules asserting — cores guarding (regressions declining — hoping ending (proving funding — bluffing declining (tests owning — faith refusing); *contracts asserting* (adapters passing — behaviors matching (drifts detecting — assuming declining (asserting owning — shipping refusing (suites earning — fear declining); *fakes substituting* (vendors doubling — suites headlessing (feedback speeding — booting declining (substituting funding — heaviness ending (doubles owning — brokers sleeping).

```typescript
// GOOD: tests gating — merge allowed only on all-green suites (compiled + run live).
interface Gate { // units proving — rules asserting, hoping ending
  suite: string;
  green: boolean;
}
function mergeable(gates: Gate[]): boolean {
  return gates.length > 0 && gates.every((g) => g.green); // contracts asserting — adapters passing, assuming declining
}
const green = mergeable([
  { suite: 'unit', green: true },
  { suite: 'contract', green: true },
  { suite: 'headless', green: true },
]);
const red = mergeable([
  { suite: 'unit', green: true },
  { suite: 'contract', green: false },
  { suite: 'headless', green: true },
]); // fakes substituting — vendors doubling, booting declining
console.log(green && !red ? 'tests gate' : 'merges hope');
```

```typescript
// BAD: merges hoping — suites unrun, coverage bluffed (real hope shape).
// // "CI was green last week." (greens assuming — reds landing — incidents scheduling).
// // Vendor merged without suite (behaviors bluffing — swaps fearing). Gate merges; prove units; assert contracts.)
```

**Common confusion** — *"gates slow merging (process throttling)."* Gates preventing incidents (units proving — contracts asserting (reds blocking — incidents declining (preventing funding — throttling declining); missing gates slowing recovery (reds landing — cleanups paging (incidents multiplying — velocity dying (missing charging — merging declining). "Throttling" describing ceremony (approvals queuing — value missing); gates describing leverage (proof reusing — incidents preventing). Gate merges (units proving — contracts asserting); ship faster (incidents declining — velocity funding).

**Performance note** — gating economics: proving costing suite minutes (rules asserting — adapters passing (reds blocking — incidents declining); hoped equivalents costing incidents (greens assuming — reds landing (cleanups paging — trust eroding). Prove cheaply (suites — gates); hope never (merges — reds).

**Mentor note** — teach "gate output in the PR" (juniors proving one suite set per merge design hope-free delivery on first hearing; gateless merges interrogated ("which gates?" — gating demanding per PR). Prove one merge once (units asserting — contracts passing tangible (hoping ending — proving permanently). Assert units; pass contracts — gating discipline in three habits, reviewed per merge.

## 2. Deploys gating serving (phases sequencing — rollbacks readying — probes answering)

**Definition** — deploy gating: serving starting only after phased rollout, ready rollback, and answering probes (phases sequencing — expands contracting (duals mapping — bangs declining (sequencing proving — stopping ending); rollbacks readying — outs preserving (reverts rehearsing (panics declining — stranding ending (readying owning — hoping ending); probes answering — healths reporting (readiness proving — traffic accepting (answering funding — blind serving declining).

**What problem it solves** — the unprobed trio: *deploys flipping* (flags toggling — failures stranding (recoveries missing — downtimes arriving (flipping billing — rehearsals absenting); *rollbacks missing* (outs absenting — reverts hoping (migrations stranding — panics scheduling (missing charging — safety declining); *probes silenting* (healths unreported — traffic blindly (readiness assuming — outages discovering (silenting billing — observability missing). Gated deploys converting flipping to sequencing (phases ordering — rollbacks readying (probes answering — downtimes declining); reviewers seeing probe output per deploy (gating proving → verifiable; flipping → returned).

**Modern guidance** — the deploying lines per release (review-enforced): *phases sequencing* (expands contracting — duals mapping (bangs declining — stopping ending (sequencing proving — flipping refusing (stages owning — cliffs declining); *rollbacks readying* (outs preserving — reverts rehearsing (panics declining — stranding ending (readying owning — hoping ending (safety funding — dread declining); *probes answering* (healths reporting — readiness proving (traffic accepting — blind declining (answering funding — silenting refusing (observability owning — discovery declining). Delivery mechanics (drains landing — probes answering) are owned in [NestJS 07/1.2](<../../../../NestJS/07 Production Mastery and Interview Synthesis/sections/1. Full-system design/1.2. Full-system delivery design.md>) — this leaf owns the gates, never the drains.

```typescript
// GOOD: deploys gating — serving allowed on phased rollout with ready rollback and probes (compiled + run live).
interface Release { // phases sequencing — expands contracting, bangs declining
  phase: string;
  rollbackReady: boolean;
  probesUp: boolean;
}
function servable(r: Release): boolean {
  return r.phase === 'contract' && r.rollbackReady && r.probesUp; // rollbacks readying — outs preserving, hoping ending
}
const ready: Release = { phase: 'contract', rollbackReady: true, probesUp: true };
const norollback: Release = { phase: 'contract', rollbackReady: false, probesUp: true };
const noprobe: Release = { phase: 'contract', rollbackReady: true, probesUp: false }; // probes answering — healths reporting, blind declining
console.log(servable(ready) && !servable(norollback) && !servable(noprobe) ? 'deploys gate' : 'flags flip');
```

```typescript
// // No probes (readiness assuming — outages discovering). Phase rollouts; ready rollbacks; answer probes.)
```

**Common confusion** — *"gates delay shipping (process slowing)."* Gates preventing outages (phases sequencing — rollbacks readying (downtimes declining — trust earning (preventing funding — slowing declining); missing gates delaying recovery (failures stranding — cleanups paging (outages multiplying — velocity dying (missing charging — shipping declining). "Delaying" describing ceremony (approvals queuing — value missing); gates describing leverage (proof reusing — outages preventing). Gate deploys (phases sequencing — probes answering); ship faster (downtimes declining — trust earning).

**Performance note** — deploy economics: sequencing costing stages (phases ordering — rollbacks readying (downtimes declining — trust earning); flipped equivalents costing outages (failures stranding — recoveries missing (downtimes arriving — trust eroding). Sequence cheaply (stages — phases); flip never (flags — outages).

**Mentor note** — teach "probe output per deploy" (juniors sequencing one rollout per release design flip-free delivery on first hearing; probeless deploys interrogated ("which probes?" — gating demanding per release). Sequence one deploy once (phases ordering — probes answering tangible (flipping ending — gating proving permanently). Order phases; ready outs — deploying discipline in three habits, reviewed per release.

## 3. Evidence dating readiness (gates checking — drills timing — owners naming)

**Definition** — dated readiness: release evidence carrying gate results, drill dates, and owners (gates checking — suites asserting (contracts passing — merges proving (checking funding — hoping ending); drills timing — rehearsals dating (game-days owning — staleness declining (timing proving — bluffing ending); owners naming — humans answering (accountability owning — diffusion declining (naming funding — orphaning ending).

**What problem it solves** — the undated trio: *claims undating* (readiness asserting — dates missing (evidence bluffing — freshness hoping (undating billing — trust assuming); *drills bluffing* (rehearsals claiming — calendars emptying (confidence assuming — staleness hiding (bluffing charging — panic scheduling); *owners orphaning* (readiness homeless — incidents bouncing (accountability absenting — quality diffusing (orphaning costing — pride declining). Dated evidence converting asserting to proving (gates checking — drills timing (owners naming — hoping ending); reviewers reading dates per release (dating proving → verifiable; bluffing → returned).

**Modern guidance** — the dating lines per release (review-enforced): *gates checking* (suites asserting — contracts passing (merges proving — hoping ending (checking funding — bluffing declining (evidence owning — faith refusing); *drills timing* (rehearsals dating — game-days owning (staleness declining — bluffing ending (timing proving — panic declining (recency funding — dread ending); *owners naming* (humans answering — accountability owning (diffusion declining — orphaning ending (naming funding — bouncing refusing (people owning — readiness answering).

```typescript
// GOOD: evidence dating — freshness judged against a 90-day drill horizon (compiled + run live).
interface Evidence { // gates checking — suites asserting, hoping ending
  gatesGreen: boolean;
  lastDrillQ: string;
  owner: string;
}
function ready(e: Evidence, nowQ: string): boolean {
  if (!e.gatesGreen || e.owner.length === 0) return false;
  return e.lastDrillQ >= nowQ; // drills timing — rehearsals dating, staleness declining (lexical quarters ordering)
}
const fresh: Evidence = { gatesGreen: true, lastDrillQ: 'Q4', owner: 'team-a' };
const stale: Evidence = { gatesGreen: true, lastDrillQ: 'Q2', owner: 'team-a' }; // drills bluffing — calendars emptying, panic scheduling
const ownerless: Evidence = { gatesGreen: true, lastDrillQ: 'Q4', owner: '' };
console.log(ready(fresh, 'Q4') && !ready(stale, 'Q4') && !ready(ownerless, 'Q4') ? 'evidence dates' : 'claims bluff');
```

```typescript
// BAD: readiness bluffing — dates missing, owners orphaning (real bluff shape).
// // "Production-ready." (evidence bluffing — freshness hoping — trust assuming).
// // No drill date, no owner (calendars emptying — incidents bouncing). Date gates; time drills; name owners.)
```

**Common confusion** — *"evidence is paperwork (forms multiplying)."* Paperwork filing forms (documents owning — value missing (forms serving — shipping declining (filing charging — agility declining); evidence dating readiness (gates checking — drills timing (owners naming — hoping ending (dating funding — bluffing declining). "Paperwork" describing ceremony (forms multiplying — value missing); evidence describing proof (gates asserting — drills dating). Date readiness (gates checking — drills timing); file never (forms multiplying — value missing).

**Performance note** — dating economics: checking costing gate output (suites asserting — drills dating (owners naming — hoping ending); bluffed equivalents costing incidents (evidence bluffing — freshness hoping (trust assuming — panics scheduling). Date cheaply (quarters — owners); bluff never (claims — dates).

**Mentor note** — teach "date, drill, owner per release" (juniors dating one evidence set per release design bluff-proof readiness on first hearing; dateless claims interrogated ("which quarter?" — dating demanding per release). Date one release once (gates checking — drills timing tangible (bluffing ending — proving permanently). Check gates; name owners — dating discipline in three habits, reviewed per release.
