## 1.2. DFS: components, cycles, and topological order

### 1) **Three colors find cycles**

**Definition** — depth-first search paints vertices white (unvisited) → gray (on the current path) → black (finished with all descendants): re-entering a *gray* vertex proves a cycle (the path loops back on itself); black vertices skip safely (their subtrees fully explored — no cycle through them undiscovered). Verified: triangle `1→2→3→1` → `cyc:true`; DAG → `cyc:false`. Undirected graphs need the parent exception (the edge back to the caller isn't a cycle — track it, don't misreport).

- **What problem it solves**: cycle questions without coloring guess — visited-boolean DFS reports false cycles on DAG diamonds (two paths to one node *isn't* a loop — gray/black distinction exists precisely here) or misses real ones (finished-marking without path tracking). Course schedules, dependency validation, deadlock detection, and spreadsheet recalculation all reduce to "does this directed graph loop?" — three colors answer with one traversal, `O(V+E)` time, `O(V)` space (colors + recursion stack).
- **Modern guidance** — implement three colors explicitly (white/gray/black maps — never bare visited-booleans on directed cycle duty; the boolean conflates gray and black, which is the entire bug). Distinguish directed from undirected handling (parent exception for undirected — pass it, document it). Return the cycle itself where debuggability matters (parent pointers reconstruct the loop — "cyclic" plus *which* cycle closes incident tickets faster).

```javascript
// GOOD: gray re-entry proves the loop — verified true on triangle, false on DAG
function hasCycle(adj) {
  const color = new Map();  // absent=white, 1=gray (on path), 2=black (finished)
  function dfs(u) {
    color.set(u, 1);
    for (const v of adj.get(u) || []) {
      if (color.get(v) === 1) return true;        // back to the current path: cycle proven
      if (!color.get(v) && dfs(v)) return true;
    }
    color.set(u, 2);
    return false;
  }
  for (const u of adj.keys()) if (!color.get(u) && dfs(u)) return true;
  return false;
} // O(V+E) time, O(V) space. Undirected: pass parent, exempt the caller edge.
// BAD: visited-boolean DFS for directed cycles ("equivalent") —
// diamond DAGs (two paths, no loop) report false cycles; gray/black exist to separate paths from loops
```

### 2) **Postorder reversed topologically sorts**

**Definition** — on a DAG, emitting vertices in *reverse postorder* (push on finish, read backwards) yields a topological order: every edge `u→v` places `u` before `v` (v finishes first — DFS explores descendants fully before returning — so v precedes u in postorder, follows it reversed). Verified: course graph → order `[4,5,0,2,3,1]`, `cyc:false` — every prerequisite precedes its dependent (5 before 2,0; 4 before 0,1; 2 before 3; 3 before 1). Cycle present → no topological order exists (sorting *requires* acyclicity — detect first via previous section, sort second).

- **Why it matters (correctness)**: ordering problems are topological sorts wearing work clothes — build systems (compile dependencies first), course prerequisites, task schedulers, spreadsheet evaluation, migration ordering. Ad-hoc ordering (priority numbers, manual sequences, timestamp hacks) breaks on diamond dependencies (shared prerequisites ordered twice or never) and circular ones (silently — the schedule *looks* complete). Toposort computes the valid order or proves none exists — total answer, no partial credit needed.
- **Modern guidance** — DFS-postorder for the order *plus* cycle detection in one traversal (gray re-entry aborts with the cycle — sort and validate together, never separately). Kahn's algorithm (indegree peeling with a queue) as the iterative twin — preferred where BFS-shaped code fits better or indegree bookkeeping serves double duty (parallel scheduling levels fall out free). State acyclicity as precondition ("requires DAG — cycle-checked first") — sorting cyclic input is undefined behavior wearing an output.

```javascript
// GOOD: finish-order reversed — verified [4,5,0,2,3,1], prerequisites precede dependents
function topoSort(adj) {
  const color = new Map(), out = []; let cyc = false;
  function dfs(u) {
    color.set(u, 1);
    for (const v of adj.get(u) || []) {
      if (color.get(v) === 1) cyc = true;   // cycle: no topological order exists — record, don't sort
      if (!color.get(v)) dfs(v);
    }
    color.set(u, 2); out.push(u);           // finish: all descendants already emitted
  }
  for (const u of adj.keys()) if (!color.get(u)) dfs(u);
  return { order: out.reverse(), cyc };     // reverse postorder: prerequisites first (verified)
} // O(V+E) time, O(V) space. cyc=true -> order meaningless (checked first, used second).
// BAD: "topological sort" by sorting on numeric IDs ("ordered enough") —
// IDs carry no dependency information; diamonds and chains break identically and silently
```

### 3) **Components fall out free**

**Definition** — unvisited restarts count connected components (undirected) or weakly-connected groups: sweep all vertices, DFS/BFS from each unvisited one, increment per launch — verified: two-disjoint-edges graph → `comp:2` (islands `[1,2]` and `[3,4]`). Flood fill *is* DFS on grid graphs (4/8-connected pixels — paint bucket, island counting, region labeling); strongly-connected components need Kosaraju/Tarjan (two passes or lowlinks — named here, detailed in advanced treatments, the pattern extends).

- **Why it hurts when missing (correctness, maintainability)**: connectivity questions answered per-pair (BFS per query — `O(Q·(V+E))` where one sweep costs `V+E`) or per-assumption ("the graph is connected" — untested, false on real data with isolated vertices). Component labeling answers all pairs at once (label each vertex once — queries become equality checks), and island-counting needs exactly one sweep (verified `comp:2` — the number interviews ask for directly). Sweep-first is the discipline; per-query traversal is the tax.
- **Modern guidance** — sweep-and-label for connectivity batches (components, islands, regions — one traversal answers every membership question thereafter). Flood fill iteratively on large grids (explicit stack — recursion depth equals region size, and regions reach millions of pixels — Domain 01 §2.2's ceiling binds exactly here). Track component IDs in a map (vertex → component — union-find in leaf 2.2 serves dynamic merges; static labeling serves one-shot sweeps). Test disconnected input always (single-component tests prove nothing about the restart loop).

```javascript
// GOOD: one sweep answers all membership — verified comp:2 on disjoint pairs
function components(adj) {
  const comp = new Map(); let n = 0;
  function dfs(u) { comp.set(u, n); for (const v of adj.get(u) || []) if (!comp.has(v)) dfs(v); }
  for (const u of adj.keys()) if (!comp.has(u)) { n++; dfs(u); }  // restart per island
  return { count: n, of: comp };  // queries become equality: of.get(a) === of.get(b)
} // O(V+E) time total (each vertex/edge once across ALL restarts), O(V) space.
// BAD: BFS-per-query connectivity ("on demand") —
// O(Q) traversals where one sweep suffices; demand-driven is supply-ignorant here
```

### 4) **Common confusion**

- "DFS finds shortest paths with depth tracking" — depth-first arrival is arbitrary in distance (leaf 1.1's core warning, restated: DFS explores *a* path fully, not the shortest). Track depth for *cycle/level analysis within DFS* (recursion depth, topological levels), never for shortest claims.
- "Topological order is unique" — valid orders multiply (verified one of several — `[5,4,…]` orderings equally valid where unconstrained). Uniqueness holds only for Hamiltonian-constrained DAGs (each consecutive pair edged — the special case, not the rule).
- "Undirected graphs can't have cycles" — undirected cycles need length ≥ 3 with parent-exemption (triangle `1−2−3−1` cycles; `u−v−u` doesn't). Forgetting the parent exception reports every edge as a cycle.
- "Components need union-find" — static components need one sweep (this leaf); union-find serves *dynamic* merges (leaf 2.2 — edges arriving over time). One-shot questions get sweeps; evolving connectivity gets union-find.

### 5) **Performance note**

DFS costs `V` visits + `E` edge inspections (verified probes single-digit ms) with `O(h)` recursion stack (depth-bounded by longest path — degenerate chains threaten the ceiling; iterative twins exist per Domain 04 §2.2's spine pattern) plus `O(V)` colors. Component sweeps cost one traversal total (restarts share the visited map — no rework across islands). Toposort costs one DFS (cycle detection rides free — same colors, same pass). Optimize color discipline first (correctness before speed — boolean-visited bugs cost incidents), iteration second (depth-risky inputs), restart coverage third (disconnected tests mandatory).

### 6) **Mentor note**

Teach colors with the diamond-vs-triangle pair (DAG diamond: no cycle despite reconvergence — gray/black distinction *visible*; triangle: gray re-entry — cycle *visible*). Derive topo order from postorder live ("descendants finish first, so reverse puts prerequisites first" — the one sentence that replaces memorization). Drill restarts with disconnected input first (single-component demos teach half the loop). Watch for the boolean-visitor ("equivalent" — fix with diamond counterexample on the spot) and the ID-sorter ("ordered enough" — fix with diamond dependency breaking silently). Review check: three colors on directed cycle duty, postorder-reversed for topo with cycle precheck, restarts sweeping disconnected graphs, juniors can trace colors and finish-order aloud.
