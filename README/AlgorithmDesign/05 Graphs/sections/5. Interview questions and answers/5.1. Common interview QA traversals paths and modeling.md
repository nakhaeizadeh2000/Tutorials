## 5.1. Common interview QA: traversals, paths, and modeling

### 1) **Shortest path in a grid with obstacles?**

**Definition** — the modeling screen: grid cells are vertices, 4-moves to free cells are undirected unweighted edges (leaf 3.1's mapping), BFS from the start finds fewest-step paths (first visit proves optimal — leaf 1.1), obstacles excluded at generation (verified neighbor probe: 3 of 4 moves survive). Expected answer derives the model *before* the algorithm ("vertices = free cells, edges = legal moves, unweighted → BFS"), states visited discipline ("mark-on-enqueue"), and handles edges (start/target blocked → impossible; disconnected → unreachable, not error).

- **What a good answer sounds like**: mapping first ("cells vertices, moves edges, unweighted undirected — BFS shortest hops"), discipline stated ("mark-on-enqueue; neighbor legality checked at generation — bounds + obstacles"), complexity closed ("`O(R·C)` time/space — each cell enqueued once"), edges covered unprompted (blocked start/target, unreachable target → defined sentinel, not exception). Then the variation volunteered ("weighted terrain → Dijkstra; fewest *turns* → 0-1 BFS; huge grid → bidirectional").
- **Modern guidance** — grade modeling over mechanics: candidates who write the vertex/edge mapping before touching BFS pass even with shaky loop syntax; candidates who BFS immediately on "graph" without establishing cells-as-vertices fail the translation screen interviews actually test. Red flags: DFS for fewest steps (arbitrary arrival — leaf 1.1's warning, live), Dijkstra on unweighted grids ("general" — heap overhead for hop-counting), no unreachable handling (assumes connectivity — grids disconnect constantly).

```javascript
// gridNbrs(1,1) blocked(1,2) -> 3 neighbors verified (wall excluded at generation, not traversal).
```

### 2) **Course schedule — can you finish?**

**Definition** — the cycle screen: courses are vertices, prerequisites are directed edges (task → prerequisite... or prerequisite → task — direction declared once, used consistently), and "can you finish?" asks acyclicity (three-color DFS — leaf 1.2 — or indegree peeling/Kahn's). Expected answer picks one method *with reason* (colors: cycle + order in one pass; Kahn: level structure free for parallel scheduling), handles the follow-up ("return *an* order" → postorder-reversed, verified `[4,5,0,2,3,1]`), and names the impossible case (cycle → no order exists — detected, reported, not sorted-around).

- **What a good answer sounds like**: direction declared ("edge prerequisite → course: take in topo order"), method chosen with reason ("three-color DFS — cycle detection and ordering in one traversal; verified cyc flag + order"), impossibility handled ("cyc → return []; no topological order exists — checked first, used second"), complexity closed ("`O(V+E)` time, `O(V)` space"). Seniors add Kahn's twin unprompted ("indegree peeling gives the same answer plus parallel levels — BFS-shaped alternative").
- **Modern guidance** — listen for *direction declaration* as the first signal (undeclared edge direction flips all downstream reasoning — candidates who declare pass the modeling sub-screen automatically). Red flags: visited-boolean cycle detection (diamond false-positives — leaf 1.2's canonical trap, live), sorting cyclic input without checking (invalid order emitted silently), "topological sort finds cycles" inverted (detection enables sorting, not vice versa — order requires acyclicity proven first).

```bash
# The cycle answer, structured (leaf 1.2 as interview response)
#  model: vertices courses, edges prereq -> course (directed; declared once).
#  method: three-color DFS (gray re-entry proves; postorder-reversed orders) or Kahn peeling.
#  impossible: cyc -> [] (no order exists — detected, reported, never sorted-around).
#  verified shape: order [4,5,0,2,3,1], cyc:false (prerequisites precede dependents).
```

### 3) **Network delay time?**

**Definition** — the Dijkstra screen: routers are vertices, links are weighted directed edges, "time for all to receive from k" asks single-source shortest paths with the *maximum* over reachable (max of Dijkstra distances — unreachable → −1 specified). Expected answer narrates settling ("cheapest-unsettled finalized — nonnegativity guarantees finality"), states the heap frontier (`O((V+E) log V)`), handles edges (unreachable nodes → −1; negative weights → Bellman-Ford reroute, never Dijkstra-blindness), and closes with the max-reduction (distances computed, answer = max or −1).

- **What a good answer sounds like**: precondition checked ("nonnegative weights? — stated before code; verified settle-2@4-vs-true-2 is why the question matters"), frontier narrated ("min-heap serves cheapest-unsettled; lazy deletion skips corpses — leaf 2.1"), reduction stated ("answer = max distance, −1 if any unreachable"), complexity closed ("`(V+E) log V` time, `V` space"). Then the variation volunteered ("k-th delay percentile → repeated selection, not Dijkstra; all-pairs → run per source or Floyd on dense").
- **Modern guidance** — grade precondition-first behavior (weight-sign audit unprompted — the senior signal), settling narration (finality *proof*, not just order), and unreachable handling (−1 specified, not crashed). Instant fail: BFS on weighted links ("distances small" — hop-counting ignores prices), Dijkstra with negatives unacknowledged (silent wrongness — leaf 2.1's core warning, live), max-without-reachability-check (max over partial distances answers nothing asked).

```bash
# The Dijkstra answer, structured (leaf 2.1 as interview response)
#  audit: weights >= 0? (verified premature-finality is why) -> frontier: min-heap, lazy deletion.
#  settle: cheapest-unsettled finalized (proof by nonnegativity) -> reduce: max(dist) or -1 unreachable.
#  verified shape: 1:0,2:3,3:2,4:6 (order follows distance, not labels).
```

### 4) **Common confusion**

- Candidates who model implicitly ("graph search over the grid" without vertex/edge statements) — translation unstated is translation untested; modeling errors outnumber traversal bugs.
- "BFS/DFS/Dijkstra are interchangeable traversals" — BFS proves hops, DFS proves structure (cycles/order), Dijkstra proves weighted distances. Different guarantees, different questions — interchangeability is the fail mode.
- Treating unreachable as error-case trivia — disconnected inputs are *common* (isolated vertices, blocked regions, partitioned networks); specified sentinels (−1/INF/[]) separate robust answers from crashing ones.

### 5) **Performance note**

Interview answers here should be compact: grid modeling (two minutes — mapping, BFS, discipline, edges, variation), course cycle (two minutes — direction, method-with-reason, impossibility, complexity), network delay (two minutes — audit, frontier, reduction, edges). Candidates who model-then-select take the same time as code-first candidates and prove triple — translation is speed, in interviews as in engineering.

### 6) **Mentor note**

Use Q1 as the modeling screen (vertex/edge statements before algorithm), Q2 as the cycle screen (three colors + impossibility handling), Q3 as the weighted screen (sign audit + settling narration). Rubric: junior — correct algorithms with counting shown; mid — disciplines stated (enqueue/colors/settle), edges covered (blocked/unreachable/negative), mapping explicit; senior — variation fluency (bidirectional, Kahn twin, Bellman-Ford reroute), tightness awareness, borrow-vs-build discipline without prompting. Keep the verified numbers ready (distances, topo order, settle-4-vs-true-2) — receipts separate narrators from memorizers. Red-flag fails: DFS shortest paths, boolean cycle detection, sign-blind Dijkstra, implicit modeling.
