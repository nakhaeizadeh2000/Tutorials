## 5.1. Common interview QA: pointers, windows, and strings

### 1) **Two-sum, three variants**

**Definition** — the pattern screen in three acts: *sorted* (converge opposite ends — verified pair in 4 steps, `O(n)` time `O(1)` space), *unsorted* (hash once — Domain 04: `O(n)` average, order irrelevant), *counting pairs* (sort-then-converge with duplicate-skipping, or hash with multiplicity — the variant that catches memorizers). Same question, three structures, three tools — the candidate who asks "sorted?" before coding passes; the candidate who converges unconditionally fails silently on half the inputs.

- **What a good answer sounds like**: structure first ("is it sorted? — converges if yes, hashes if no, sorts-then-converges if repeated queries amortize the sort"), elimination narrated ("too small kills left for all partners" — the matrix reasoning from leaf 1.1), counting handled (duplicate-skipping on converge: advance past equals after recording; multiplicity maps on hash). Then the trade stated (hash: `O(n)` space for order-freedom; sort+converge: `O(1)` space for `n log n` admission).
- **Modern guidance** — interviewers listen for the *admission question* ("sorted?") as the first signal: asked unprompted → pattern thinking; never asked → shape memory. Red flags: converging unsorted data (silent misses — leaf 1.1's core warning), nesting on sorted data ("simpler" — `n²` where linear applied), hash-everything reflex (space donated where sortedness already paid). Follow-up separating senior: "a billion queries on a static array?" (sort once, converge per query — admission amortized to zero).

```javascript
// The three variants, decided by structure (leaf 1.1's verified machinery)
// sorted   -> converge: twoSumSorted(a, t) -> [2,4] in 4 steps (verified). O(n)/O(1).
// unsorted -> hash: one pass, complements in Map (Domain 04). O(n) avg/O(n).
// counting -> sort + converge with dup-skipping, or multiplicity hash (state both, pick by reuse).
```

### 2) **Longest substring, narrated**

**Definition** — the window screen: "longest substring without repeating characters," narrated with invariants aloud (validity: current window all-distinct; expand right every step; shrink left past the duplicate; record max en route — verified 3/1/0). Graded on *narration of validity* — the candidate who states "window always holds distinct characters because left jumps past repeats" demonstrates windows; the candidate who slides silently demonstrates recall of a shape that breaks on the next variant (shortest-containing inverts everything — leaf 2.2).

- **What a good answer sounds like**: validity-first narration ("my window `s[st..i]` stays duplicate-free: on repeat of `c`, `st` jumps past `c`'s last occurrence — verified `abcabcbb` → 3"), mechanism stated ("each index enters/exits once — `2n` moves, linear by monotonicity"), edges covered unprompted (empty → 0, all-same → 1 — verified), and the inversion named ("shortest-containing flips shrink/record — same skeleton, opposite decisions").
- **Modern guidance** — demand invariant narration, not code recitation: candidates who derive shrink-from-validity adapt to unseen variants; candidates who recall shrink-loops fail the inversion follow-up. Instant fail: nested re-scan per start ("thorough" — `n²` where the interview screens linear), or last-seen map without the `>= st` guard (stale indices shrink backwards — the classic implementation bug the verified probe's guard prevents).

```javascript
// The narration target (leaf 2.2's verified loop — validity aloud, not code alone)
// "Expand i; if s[i] seen at >= st, st jumps past it (validity restored minimally);
//  record i-st+1. Monotone both sides -> 2n moves -> O(n). Empty -> 0, bbb -> 1 verified."
```

### 3) **Why is KMP linear?**

**Definition** — the prefix-table answer: preprocessing builds failure links (`O(m)` — verified table `[0,0,1,2,3,0,1]`), scanning never retreats the text pointer (mismatches jump via table — each step advances text or follows a link, total ≤ `2n`), so combined `O(n+m)` guaranteed. The "why" candidates must articulate: *matched text is never re-examined* — the table remembers partial matches as borders, and borders reattach without rescanning (leaf 3.2's core idea in one sentence).

- **What a good answer sounds like**: two-phase accounting ("table `O(m)` once; scan `≤2n` steps — text pointer monotone, links only shorten the pattern pointer; verified 23 comparisons finding match at 10 vs naive's 176-shape") plus the contrast ("naive rescans A's per alignment — KMP's borders skip exactly the rescan") plus scope honesty ("single-pattern streaming; multi-pattern wants Aho-Corasick — Domain 04; one-offs want builtins"). Table construction sketched (borders = longest proper prefix-suffix — the definition that builds itself).
- **Modern guidance** — listen for *never-re-scan* as the load-bearing phrase: candidates who center it understand; candidates who center "it's faster" memorize. Red flags: "KMP preprocesses the text" (pattern, not text — the table's whole point), no complexity split (table vs scan phases conflated), "always use KMP" (builtin crossover below ~100 chars — leaf 3.2's measured honesty). Follow-up separating senior: "adversarial text against Rabin-Karp?" (forced collisions → KMP fallback — average-case threat models from Domain 01 §1.2).

### 4) **Common confusion**

- Candidates who answer variants with the same code (converge for unsorted two-sum, longest-loop for shortest-containing) — variant blindness reveals template memory; validity reasoning reveals understanding.
- "Windows are always `O(n)`" without monotonicity argument — the mechanism (*why* linear) is the screened knowledge, not the label.
- Treating KMP as "advanced, rarely asked" — prefix reasoning (borders, failure links) recurs in DP string problems (Domain 06) and trie construction (Domain 04). KMP is prerequisite, not elective.

### 5) **Performance note**

Interview answers here should be compact: two-sum variants (two minutes — admission, three tools, trade stated), substring narration (two minutes — validity aloud, mechanism, edges, inversion named), KMP linearity (two minutes — table, monotone scan, scope). Candidates who narrate validity and mechanism take the same time as silent coders and prove triple — structure is speed, in interviews as in analysis.

### 6) **Mentor note**

Use Q1 as the admission screen (asks "sorted?" unprompted), Q2 as the validity screen (narrates invariants, inverts on demand), Q3 as the analysis screen (never-re-scan centered, scope honest). Rubric: junior — correct patterns with counting shown; mid — invariants stated, edges covered (empty/impossible/duplicates), amortization mechanized; senior — variant fluency (inversions derived live), threat models (adversarial inputs named), scope discipline (builtins below crossover, Aho-Corasick above single-pattern) without prompting. Keep the verified numbers ready (4 steps, 3/1/0, 23 vs 176, `[0,0,1,2,3,0,1]`) — receipts separate narrators from memorizers. Red-flag fails: unsorted convergence, nested re-scans, table-less KMP claims, variant-blind templates.
