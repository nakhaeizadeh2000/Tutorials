## 6.1. Boundaries: what is covered elsewhere

### 1) **Every technique underneath**

**Definition** — the complete track map, final: analysis (notation, cases, counting, amortization, space, measurement → [Domain 01](<../../../01 Complexity and Algorithmic Thinking/README.md>)); sorting/searching/selection (→ [Domain 02](<../../../02 Sorting and Searching/README.md>)); pointers/windows/stacks/strings (→ [Domain 03](<../../../03 Linear Structures and Two-Pointer Techniques/README.md>)); hashing/trees/heaps/tries (→ [Domain 04](<../../../04 Hashing Trees and Heaps/README.md>)); graphs (→ [Domain 05](<../../../05 Graphs/README.md>)); paradigms (→ [Domain 06](<../../../06 Dynamic Programming Greedy and Backtracking/README.md>)). This domain orchestrates all six into method, verification, and execution — techniques referenced, never re-taught.

- **Why the boundary matters**: capstone duplication is the most tempting kind (re-explaining DP for interview answers, re-deriving Big-O for estimation questions, re-teaching BFS for grid modeling — each feels self-contained, each rots independently). Single source of truth at track scale: six domains of technique, one domain of orchestration. This leaf is the map that keeps those lines short for the track's final domain — and, as the last boundaries leaf, the map of the whole territory.
- **Modern guidance** — if a passage here needs more than one sentence of any technique, stop and link instead. The one-sentence versions per domain: bounds describe growth (01), sorts compare (02), pointers eliminate (03), maps relate (04), graphs connect (05), tables optimize (06). Everything else here is *method* (solve), *verification* (prove), and *execution* (perform).

### 2) **Platform and language specifics**

**Definition** — judge mechanics (time/memory limits, I/O formats, verdict semantics — documented per platform: Codeforces/LeetCode/AtCoder differ), engine behavior (V8/JSC constants, GC pressure, JIT shapes — measured per runtime, never assumed), and JavaScript mechanics (syntax, methods, classes — [JavaScript track](<../../../../JavaScript/README.md>), all domains). Map-style stop-list (the whole track, final): analysis → 01, sorting → 02, linear → 03, structures → 04, graphs → 05, paradigms → 06, mastery → here (07), mechanics → JavaScript track, words → IT Vocabulary.

- **Why the boundary matters**: platform specifics churn (limit changes, new judges, engine upgrades) while algorithmic truth stands for decades — embedding console paths or engine constants in tutorial leaves guarantees rot within a year. Worse, specifics vary by venue (Codeforces 2s vs LeetCode flexible vs interviews whiteboard — same algorithm, different budgets). Teaching the portable core (method, verification, narration) keeps every leaf durable; linking the specifics keeps every leaf honest.
- **Modern guidance** — name the control, link the venue: "measure at 2·10⁵ inputs (methodology: Domain 01 §3.1; budget: *your* judge's limits)" stays true across platforms; hardcoded "passes in 1s" doesn't. When platform curiosity strikes mid-method ("what are Codeforces limits exactly?"), follow the venue link — this track answers with method plus control names, not navigation.

```bash
# GOOD: portable core, linked specifics (durable across venues and versions)
#  method (solve/verify/narrate) -> this domain (portable: judges, interviews, production alike)
#  budgets (limits/judges/engines) -> venue docs + measured probes (methodology here, numbers there)
# BAD: "passes in 1s on CF" embedded in tutorial leaves —
# accurate until limits change, venue-locked from birth, hardware-bound throughout
```

### 3) **Vocabulary naming**

**Definition** — what process words *mean in a meeting* (WA/TLE/MLE verdicts, stress testing, rubber-ducking, behavioral interviews as vocabulary) belongs to [IT Vocabulary](<../../../../ITVocabulary/README.md>); this track never re-teaches definitions those leaves own. The concept gets its full treatment once, everywhere else one line plus a link — the DRY contract's final application, closing the track exactly as Domain 01 opened it (boundaries as maps, all the way down).

- **Why the boundary matters**: every boundary crossed here is duplication that rots — process glossaries copied into mastery leaves go stale when industry usage shifts, while the words-track stays current. Seven domains, seven maps, zero duplication — that was the design working, from the first boundaries leaf (01 §6.1) to this last one.
- **Modern guidance** — when writing or reviewing Domain 07 content, ask "does a sibling domain, track, or venue own this sentence?" If yes, compress to a link. The domain stops at: solving method, verification discipline, interview execution — everything about *how the techniques work*, *where the consoles live*, or *what the words mean* lives elsewhere.

### 4) **Common confusion**

- "Mastery is where advanced algorithms live" — mastery is *orchestration*; the advanced mechanics distribute across Domains 01–06. This leaf maps the summit; the climbs live below.
- "Boundaries leaves are filler" — they are the DRY contract made visible: each states what its domain deliberately does *not* teach so the repo can teach it once. Seven domains, seven maps, zero duplication — that was the design working.

### 5) **Performance note**

No runtime cost to boundaries — the performance is editorial: one-line links instead of copied sections keep every leaf short, searchable, and single-sourced. When venue limits change, zero leaves update (only venue links); when Domain 01 changes measurement guidance, one domain updates instead of seven.

### 6) **Mentor note**

Use this leaf as the graduation map: hand juniors the seven-domain stop-list and have them place any algorithms question from their week into exactly one bucket — placement accuracy *is* track mastery (Domain 01's review check, now track-wide). Quiz the full arc: analysis (01), sorting (02), linear (03), structures (04), graphs (05), paradigms (06), mastery (07). Correct placement across all seven means the learner sees algorithms as a system, not a trick bag — the outcome this track was built to produce.
