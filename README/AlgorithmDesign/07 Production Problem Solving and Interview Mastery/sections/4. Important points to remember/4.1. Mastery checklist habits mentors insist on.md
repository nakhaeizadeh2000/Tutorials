## 4.1. Mastery checklist (habits mentors insist on)

### 1) **Method before code, always**

**Definition** — clarify → constrain → select → verify (leaves 1.1–2.2's loop, compressed to reflex): examples traced before approaches, limits translated before paradigms, oracles banked before optimization, verdicts classified before fixes. Method-before-code converts problem solving from performance art into procedure — repeatable under pressure, teachable to juniors, auditable in review.

- **What problem it solves**: codeless method talk stays abstract ("think first" — unactionable), while codeless method *checklists* trigger concrete acts (traced examples? translated limits? banked oracle? classified verdict? — yes/no per item, gaps visible instantly). The checklist is method made checkable: skipped steps named (not "be careful" but "edge matrix unwritten"), pressure-proofed by routine (practiced method survives clocks; improvised method doesn't).
- **Modern guidance** — run the loop visibly (traces, translations, oracles, classifications produced as artifacts — interviewers and reviewers see method, not just claims). Time-box per stage (clarify 5 min, constrain 2, select 3, verify continuous — budgets prevent analysis paralysis). Skip stages explicitly, never implicitly ("constraints trivial here because n ≤ 12 — skipping documented" — judged skips differ from forgotten ones).

```bash
# GOOD: method as artifacts (visible, checkable, teachable)
#  clarify: 2 traced examples + restatement (leaf 1.1) / constrain: limits -> rung -> shortlist (leaf 1.2)
#  select:   paradigm with reason (Domain 06 §4.1 fork) / verify: oracle + stress + edges (leaves 2.1-2.2)
# BAD: "understand, then code" as the whole method ("obvious") —
# obvious steps skipped under pressure; checklisted steps survive it
```

### 2) **Oracle everything shippable**

**Definition** — stress harnesses beside every non-trivial solution (brute-force truth + randomized agreement + shrunk regressions — leaf 2.1's methodology as standing policy): shipped code carries its verification (harness files versioned with solutions, CI-runnable where platforms allow, re-run per refactor). Oracles convert "works" from claim into artifact — agreement monitored, not asserted.

- **Why it matters (correctness)**: un-oracled shipping relies on sample agreement (tests cover thoughts; oracles cover shapes — leaf 2.1's distribution argument, restated as policy). Refactors without oracles regress silently (optimized rewrites drift from unrecorded truth — stress would catch, samples don't). Production incidents from "tested" code trace overwhelmingly to un-oracled logic (hand tests green, shapes uncovered). Oracles are the cheapest standing verification per solution — hundreds of trials, seconds of runtime, permanent truth.
- **Modern guidance** — bank oracles with solutions (same commit — truth travels with code, never separately). Run per refactor (agreement re-verified on every change — green maintained, not assumed). Weight generation toward edges (empties/extremes/ties oversampled — where hand tests never reach). Promote shrunk failures to regression tests (minimal reproducers filed — matrix grows per incident, never shrinks).

```bash
# GOOD: truth standing beside solutions (policy, not event)
#  every non-trivial solution ships with: brute oracle + 500-trial stress + edge matrix (leaves 1.1/2.1).
#  refactors re-run green (CI where possible, ritual where not) — agreement maintained continuously.
# BAD: "tested" = samples green, oracle absent ("confident") —
# confidence billing per refactor; oracles amortize truth across all future changes
```

### 3) **Narrate to prove thinking**

**Definition** — reasoning aloud in interviews, reviews, and incidents (six-beat narration — leaf 3.1; stuck specified visibly; closes verified): thinking *performed* is thinking *scored* (hiring), *shared* (reviews), and *debuggable* (incidents narrated coordinate responders). Silence is unscored everywhere it matters — offers, promotions, and incident command all select for audible reasoning.

- **Why it hurts when missing (correctness, maintainability)**: unnarrated brilliance misattributes (reviewers can't distinguish derived from lucky — approvals withheld or misgranted), unnarrated stuckness stalls teams (blocked silently — help arrives late or never), unnarrated incidents confuse responders (parallel debugging without shared model — effort duplicated, contradictions unresolved). Narration is coordination technology wearing communication clothes — teams that narrate debug faster, review better, and hire truer.
- **Modern guidance** — narrate decisions by default (code reviews with reasoning attached — "chose X because Y" per non-obvious line; incidents with thinking aloud — shared model from minute one). Specify stuckness early (blocked 15 minutes → voiced with knowns/gaps — help routed precisely). Close with verification stated (traced, bounded, traded-off — finished means proven, leaf 3.1's ritual as team habit). Practice narration deliberately (mocks, reviews, postmortems — audible reasoning is trained, not gifted).

```bash
# GOOD: thinking performed wherever it counts (hiring, reviews, incidents)
#  interviews: six beats audible (leaf 3.1) / reviews: decisions attached ("chose X because Y")
#  incidents: model shared minute-one (narration coordinates responders)
# BAD: brilliance performed silently ("code speaks for itself") —
# code states conclusions; narration states reasoning — scored, shared, and debugged differently
```

### 4) **Common confusion**

- "Checklists replace mastery" — checklists *route* to mastery behaviors under pressure (method/oracles/narration triggered when clocks run). Mastery executes; checklists ensure execution happens *then*. Both, in that order.
- "Oracles double the work" — oracles halve debugging (truth disambiguates every failure — ambiguous failures cost multiples of harness time). Doubling some work to tenth debugging is arithmetic, not overhead.
- "Narration is extroversion" — narration is *procedure* (six beats, stuck protocol, verification close — learnable structure, not personality). Introverts narrate structurally; extroverts ramble without it. Structure decides, temperament doesn't.

### 5) **Performance note**

The checklist costs minutes per problem (method artifacts, oracle harness, narrated close) against wrong-problem rewrites (tens of minutes), truthless debugging (ambiguous failures per verdict), and unscored brilliance (offers lost to silence). Highest-leverage item is oracle banking (disambiguates all future failures); second is method artifacts (prevents wrong-problem work); third is audible narration (converts thinking to scored/shared/debuggable). Minutes preventing incidents and offers lost — mastery's best attention rate.

### 6) **Mentor note**

Convert this leaf into the team's problem-solving runbook: method artifacts, standing oracles, audible reasoning — every problem, every review, every incident. Quiz juniors on routing ("which checklist item fires for an ambiguous failure? for silence? for samples-only confidence?") until answers are environmental. Watch for checklist decay (method/oracles/narration performed for a sprint, abandoned under deadline — fix with harness files as review-blocking and narration as interview-scoring) and brilliance-privileging ("they're smart, process optional" — fix with unscored-brilliance autopsies). Review check: artifacts produced, oracles green, reasoning audible — and the mentor's own problem-solving modeling all three visibly.
