## 2.2. Diagnosing WA, TLE, and MLE

### 1) **WA is logic or modeling**

**Definition** — Wrong Answer means the program runs but lies: logic faults (recurrence/transitions wrong — substructure misderived), modeling faults (graph mapping, edge semantics, precondition violated — leaf 1.1's translation errors), or edge faults (empty/single/duplicate/extreme unhandled — leaf 1.1's matrix gaps). Diagnosis order: shrink to minimal failure (leaf 2.1's halving — smallest input that still lies), then classify (logic? model? edge? — three buckets, different fixes), then repair with regression filed.

- **What problem it solves**: WA debugging without classification wanders (tweaking code against full failing inputs — fixes address symptoms, alternate inputs fail identically). Shrunk failures classify themselves (3-element lie exposes the violated invariant — recurrence, mapping, or edge — directly). Modeling faults route to leaf 1.1 (re-derive mapping); logic faults route to recurrence audit (transitions vs brute force per state); edge faults route to matrix completion (untested cell now tested). Classification *is* the diagnosis; the fix follows mechanically.
- **Modern guidance** — shrink first, always (halve-until-minimal before reading code — diagnosis starts at the smallest lie). Diff against brute force per state (not just final output — intermediate DP cells, traversal orders, window contents compared — divergence pinpoints the faulty transition). Reproduce deterministically (seeded generation for flaky-looking WA — nondeterminism in tests, not code, is the usual suspect after real nondeterminism is ruled out). File shrunk cases as regression tests (matrix grows; rediscovery ends).

```bash
# GOOD: shrink, classify, repair (WA discipline)
#  fail on 50 elements -> halve -> fails on 4 ([a,a,b,c]: duplicate handling).
#  classify: edge (duplicates) + logic (last-seen guard missing >= st) -> fix + regression filed.
#  re-run stress (500/500 methodology, leaf 2.1) -> green means fixed, not hidden.
# BAD: tweaking transitions against the 50-element failure ("maybe this bound?") —
# symptom-chasing without classification; alternate inputs fail identically next submit
```

### 2) **TLE is complexity or constants**

**Definition** — Time Limit Exceeded splits by doubling experiment (Domain 01 §3.1): ratio matches analysis (correct rung, slow constants — optimize hot loops, I/O, allocation) vs ratio exceeds analysis (wrong rung — hidden nesting, unamortized retreat, exponential blowup — redesign, don't tune). Verified-shape reasoning: linear code timing 2× per doubling with 5× budget headroom passes; quadratic timing on 10⁵ inputs fails structurally. TLE diagnosis *is* rung audit plus constant measurement, in that order.

- **Why it matters (correctness)**: TLE mistreated wastes the fix budget (micro-optimizing quadratic code — 2× speedups on 10⁴× overruns; or redesigning linear code with slow constants — rewrites where profiling sufficed). The doubling experiment separates them in minutes (ratio ≈ predicted → constants; ratio ≫ predicted → rung). Each routes oppositely: constants → profile hot spots (I/O batching, allocation reuse, typed arrays); rung → paradigm change (nesting → pointers/maps, exponential → DP/memo, per-query → preprocessed).
- **Modern guidance** — double first (harness at n and 2n — ratio decides rung-vs-constants before any fix is attempted). Profile constants second (hot-spot ranking — top function owns the verdict; I/O and allocation dominate JS profiles, not arithmetic). Redesign on rung mismatch (paradigm change per ladder — Domain 01 §1.1 applied diagnostically). Re-verify after fixes (doubling green + budget headroom — fixed means measured, not hoped). Common JS-specific constants: string concat in loops (quadratic via immutability — ropes/arrays join), `shift()` queues (`O(n)` per dequeue — head indices), spread-copies in hot loops (allocation avalanches — mutate or pool).

```bash
# GOOD: ratio decides, profile refines (TLE discipline)
#  double: ratio ~2x (predicted linear) -> constants: profile -> hot loop I/O batched -> green with headroom.
#  double: ratio ~8x (predicted linear) -> RUNG: hidden nesting found (includes-in-filter) -> pointers/maps.
# BAD: "-O2 thinking" (micro-tune first: faster I/O, tighter loops) on rung violations —
# 2x speedups on 10^4x overruns; tuning bills hours, redesign was minutes away
```

### 3) **MLE is table unbounded**

**Definition** — Memory Limit Exceeded traces to tables (DP grids, memo maps, frequency structures, queues/frontiers — state count × entry size vs cap): diagnose by accounting (which structure scales with input? — heap snapshots per size double the state count and watch growth), fix by rolling/compressing/streaming (one row instead of grid — leaf: Domain 06 §2.1; bitsets instead of booleans — 8× compression; generators instead of materialization — Domain 05 §3.1's implicit discipline). Verified-shape reasoning: 10⁴×10⁴ int grid ≈ 800MB (exceeds 256MB caps structurally — rolling to one row fits L3).

- **Why it hurts when missing (correctness, maintainability)**: MLE mistreated as "need bigger machine" (caps don't negotiate — judges, containers, and phones enforce; bigger-machine thinking fails identically at the next scale) or as mysterious crashes (OOM kills without stack traces pointing at tables — heap exhaustion looks like flakiness). Accounting first (state-count × entry-size per structure — the number that names the offender), compression second (rolling/bitsets/streaming in that order of invasiveness), redesign third (streaming algorithms where tables fundamentally exceed caps).
- **Modern guidance** — account per structure (states × bytes — name the biggest allocator before touching code). Roll tables by default (one row/rolling pair — Domain 06 §2.1's discipline, restated diagnostically). Bound caches at birth (Domain 01 §2.2's eviction rule — MLE on caches is policy absence, not bad luck). Stream where tables exceed caps fundamentally (generators + frontier-only memory — Domain 05 §3.1's implicit pattern as memory strategy). Re-measure after fixes (heap snapshots at 2× input — growth sublinear or the fix was cosmetic).

```bash
# GOOD: account, then compress (MLE discipline)
#  heap snapshot: dp table 10^4 x 10^4 ints ≈ 800MB vs 256MB cap -> roll to one row (O(n) fits L3).
#  cache growth: unbounded Map over stream -> LRU cap + TTL at birth (policy absence, now present).
#  frontier blowup: materialized states -> generator + visited-set (Domain 05 §3.1 implicit pattern).
# BAD: "increase memory limit" as the fix (caps don't negotiate) or
#      random object pooling ("optimization") without accounting (unnamed offender, unmeasured fix)
```

### 4) **Common confusion**

- "TLE means slow code" — TLE means *over-budget* code (wrong rung or heavy constants — doubling decides which). Slow is a symptom with two opposite cures.
- "WA on hidden tests needs hidden debugging" — hidden tests need *shrunk reproducers* (halve until minimal — hidden inputs aren't special, just unlisted; minimal cases diagnose identically).
- "MLE needs a better machine" — MLE needs *less state* (roll/compress/stream — caps are specifications, Domain 01 §2.2; machines scale slower than inputs grow).
- "One more resubmit might pass" — flaky passes on verdicts indicate nondeterminism (unseeding, races, hash-order dependence) or cliff-edge budgets (passing by milliseconds). Diagnose, don't resubmit-hope.

### 5) **Performance note**

Diagnosis costs minutes per verdict (shrink + classify, double + profile, account + compress) against blind-fix cycles (tweaks per submit — unbounded resubmits with unchanged understanding). Highest-leverage item is verdict classification (WA/TLE/MLE route oppositely — misclassified diagnosis fixes the wrong axis); second is minimal reproducers (diagnosis speed scales with case size inversely); third is doubling/accounting measurement (numbers route fixes). Minutes per verdict, hours saved per incident.

### 6) **Mentor note**

Teach verdict-first debugging ("which verdict? — routes everything" before any code reading). Drill shrinking live (12-element lie → 3-element diagnosis — the transformation teaches itself). Demand doubling on TLE ("ratio first, profile second" — rung-vs-constants as reflex) and accounting on MLE ("name the biggest allocator" — heap snapshots as routine). Watch for the tweaker ("maybe this bound?" — fix with shrink-then-classify discipline) and the resubmit-hoper ("once more" — fix with nondeterminism-or-cliff diagnosis). Review check: shrunk reproducers filed, ratios measured on TLE, allocators named on MLE — and the mentor's own debugging modeling verdict-first visibly.
