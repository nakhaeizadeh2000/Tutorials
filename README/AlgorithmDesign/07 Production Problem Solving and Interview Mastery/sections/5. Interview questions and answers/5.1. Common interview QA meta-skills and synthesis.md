## 5.1. Common interview QA: meta-skills and synthesis

### 1) **Walk me through a problem you failed**

**Definition** — the honesty screen: "describe a problem you got wrong, how you diagnosed it, what you changed." Expected answer narrates *failure mechanics* (which verdict? shrunk to what minimal case? classified as logic/model/edge?) plus *priced lesson* (which checklist item now fires there? what artifact prevents recurrence?). Graded on diagnostic structure, not confessed severity — seniors fail interestingly (novel interactions, tight constraints) and extract runbooks; juniors fail silently or blame tooling.

- **What a good answer sounds like**: verdict-first ("WA on hidden tests — shrunk to 3 elements: duplicate handling in the window guard"), classification ("edge + logic: `>= st` missing — Domain 03 §2.2's verified pattern"), fix with regression ("one-line guard fix, shrunk case filed, stress re-greened 500/500"), lesson priced ("edge matrices now mandatory pre-code — leaf 1.1's discipline adopted team-wide"). Then the meta close ("failures shrink, classify, file — the loop from leaf 2.2, now habit").
- **Modern guidance** — interviewers listen for * loop application under autobiography* (candidates who apply shrink-classify-file to their own history demonstrate internalized method; candidates who narrate outcomes without mechanics demonstrate storytelling). Red flags: never-failed claims (inexperience or dishonesty — both disqualify), tool-blaming (judge/compiler/library faulted — agency outsourced), lesson-free narratives ("learned a lot" without artifacts — sentiment, not method).

```bash
# The failure answer, structured (leaf 2.2's discipline as autobiography)
#  verdict (WA hidden) -> shrink (12 elements -> 3: [a,a,b]) -> classify (edge+logic: guard missing)
#  -> fix (one line) + regression filed + stress green -> lesson priced (edge matrices mandatory).
```

### 2) **Estimate this system's complexity**

**Definition** — the synthesis screen: a full-stack sketch (API → service → database → cache — realistic production shape) with "what's the complexity?" Expected answer bounds *per layer* (request handling `O(1)` amortized per endpoint? query patterns indexed `O(log n)` vs scanning `O(n)`? cache hit-rate effects on averages? fan-out multipliers per request?) then composes (per-request cost × QPS vs capacity — the estimate that sizes machines). Track-wide synthesis: ladder (01), measurement (01 §3.1), space budgeting (01 §2.2), hashing honesty (04 §1.1), queue discipline (03 §3.1) — all firing on one question.

- **What a good answer sounds like**: layered bounding ("endpoint: `O(1)` amortized map lookups (verified flat ns/op, Domain 04 §1.1); DB: indexed `O(log n)` per query × 3 queries; fan-out: 5 downstream calls × p99 latency dominates — capacity math: 10k QPS × 50ms p99 = 500 concurrent slots + headroom"), bottleneck named (fan-out latency, not CPU — the estimate that actually sizes), measurement proposed ("verify with 200k-request probe — leaf 1.2's sanity discipline at system scale"). Then the honesty close ("averages assume uniform keys + warm caches — adversarial/burst cases budgeted separately").
- **Modern guidance** — grade *layered decomposition* (per-component bounds composed — candidates who bound the system as one blob fail the screen) plus *bottleneck identification* (the binding constraint named — latency vs throughput vs memory, exactly one binds first). Red flags: single-number answers ("`O(n)`" for a system — n of *what*? per *which* operation?), average-only reasoning (uniform keys + warm caches assumed silently — Domain 01 §1.2 violated at scale), no measurement proposal (analysis without verification plan — theory unmoored).

```bash
# The synthesis answer, layered (track-wide firing on one question)
#  per-request: endpoint O(1) avg + 3x O(log n) queries + 5x downstream p99 (fan-out dominates).
#  capacity: 10k QPS x 50ms = 500 slots + 2x headroom (verified-probe methodology, system scale).
#  honesty: uniform/warm assumptions stated; adversarial + burst budgeted separately (Domain 01 §1.2).
```

### 3) **Teach me an algorithm in five minutes**

**Definition** — the mastery screen: "explain quicksort/binary search/Dijkstra as if I'm a smart junior" — explanation *is* understanding made audible (Feynman-shaped hiring: teachers debug their own models live; memorizers recite without transfer). Expected arc: problem in one sentence → key idea in one sentence → hand-trace on toy input (verified numbers where known: 19900-collapse, 20/21-ceiling, settle-order) → complexity with case discipline → one honest limitation (pivot collapse? sign audit? instability?).

- **What a good answer sounds like**: quicksort in five minutes ("sort by partitioning around pivots — watch [7,2,9,1,5,8] pivot 5 → [2,1,5,7,9,8] — recurse both sides; `n log n` average, `n²` worst on sorted (verified 19900) — median-of-three + guards fix it; unstable — equals may scramble"). Idea first, trace second, bounds third, limitation fourth — the arc that proves derivation over memorization. Questions welcomed mid-explanation (dialogue, not lecture — teaching *with*, not *at*).
- **Modern guidance** — listen for *verified numbers deployed casually* (19900, 20/21, 2.01/4.06 — measured evidence woven into teaching signals genuine mastery, not slideware). Red flags: definition recitation without traces (jargon without contact), limitation-free explanations ("no downsides" — every algorithm has one; omitting it signals shallow), monologue impervious to questions (teaching *at* — collaboration signal inverted). Follow-up separating staff: "when would you *not* use it?" (constraints decide — the judgment behind the knowledge).

```bash
# The teaching arc, timed (five minutes: idea, trace, bounds, limitation)
#  1 idea ("partition around pivots, recurse sides") -> 1 trace (verified numbers live)
#  -> bounds + cases (avg/worst with collapse mechanism) -> 1 limitation (instability/pivots/signs).
#  questions welcomed throughout (dialogue proves transfer; monologue proves memory).
```

### 4) **Common confusion**

- Candidates who treat meta-questions as softballs (failure stories without mechanics, estimates without layers, teaching without traces) — meta screens grade *structure*, and unstructured answers fail structurally.
- "Synthesis questions have no right answer" — synthesis has *gradable structure* (layers bounded? bottleneck named? honesty stated?) even where numbers vary. Structure scored, values sanity-checked.
- Treating teaching as performance (polish over precision — smooth delivery of approximate content) — precision with verified numbers beats polish; interviewers audit claims, not charisma.

### 5) **Performance note**

Meta-answers should be compact: failure story (two minutes — verdict, shrink, classify, price), system estimate (three minutes — layers, bottleneck, honesty, probe), teaching demo (five minutes — idea, trace, bounds, limitation). Candidates who narrate with receipts take the same time as generalizers and prove triple — structure is speed, in meta-screens as in analysis.

### 6) **Mentor note**

Use Q1 as the honesty screen (mechanics over sentiment — loop applied to autobiography), Q2 as the synthesis screen (layers bounded, bottleneck named, honesty stated), Q3 as the mastery screen (traces with verified numbers, limitations owned, dialogue welcomed). Rubric: junior — structured answers with counting shown; mid — honesty qualifiers (distributions, assumptions, edges) unprompted; senior/staff — trade-offs priced, limitations owned, teaching dialogic. Keep the track's verified numbers ready (interviews quoting measurements hire measurers). Red-flag fails: blameless narratives, single-number systems, limitation-free teaching.
