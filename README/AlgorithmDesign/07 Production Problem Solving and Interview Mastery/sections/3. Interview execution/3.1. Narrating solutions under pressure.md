## 3.1. Narrating solutions under pressure

### 1) **Think aloud in structure**

**Definition** — the six-beat narration interviews score: restate (problem in own words with examples), bound (complexity claimed with cost model — Domain 01 §1.1's ladder applied live), approach (paradigm selected with reason — Domain 06 §4.1's fork, narrated), code (written while narrating decisions, not silently), test (sample traced + edges named — leaf 1.1's matrix, recited), trade-offs (alternatives considered, limits stated). Silence is unscored — interviewers evaluate reasoning they *hear*; brilliant silent code reads as uncertain (or memorized).

- **What problem it solves**: silent solving fails the interview's actual test (thinking made visible — hires are made on reasoning quality, with code as evidence). Candidates who solve silently then explain produce post-hoc rationalizations (smooth stories hiding lucky guesses — interviewers discount them correctly). Narration *during* solving exposes decision points live (why this paradigm? why this bound? — the questions interviewers ask anyway, answered before asked). Structure keeps narration navigable (six beats, in order — interviewers follow along instead of interrupting for orientation).
- **Modern guidance** — narrate decisions, not keystrokes ("choosing hash map here — complements need `O(1)` average lookups" beats "now I write Map"). State bounds before code (ladder applied aloud — "linearithmic ceiling at this `n`, sort-then-scan selected"). Name alternatives briefly (considered-and-rejected in one sentence each — breadth proven without detours). Ask before assuming (ambiguous requirements clarified live — leaf 1.1's habit, performed visibly). Silence only while writing mechanical code (loops, boilerplate — narrate the interesting lines, type the obvious ones).

```bash
# GOOD: six beats, audible (narration structure)
#  restate ("given X, produce Y — e.g. [traced example]") -> bound ("O(n) time, O(n) space, hash lookups")
#  -> approach ("complements remembered — map-first, Domain 04 pattern") -> code (decisions narrated)
#  -> test ("sample traced; empty/single/duplicates named") -> trade-offs ("sorted variant converges O(1) space").
# BAD: silent solving then "any questions?" —
# reasoning unscored (unheard), decisions unprobed, memorization indistinguishable from derivation
```

### 2) **Recover visibly from stuck**

**Definition** — the stuck protocol, performed aloud: state what's known (examples traced, constraints listed — progress banked visibly), name what's missing ("the transition for skips isn't coming" — stuck specified, not wallowed), try small cases (brute force `n=3,4` by hand — patterns surface at toy sizes where abstraction stalls), request calibrated hints ("is the intended paradigm DP?" — hints as routing, not answers). Visible recovery *outscores* smooth sailing with hidden luck (interviewers hire debuggers, not oracles).

- **Why it matters (correctness)**: unstuck-silently candidates fail twice (no progress *and* no signal — interviewers can't distinguish thinking from freezing, so they score both as freezing). Stated stuckness converts dead time into data (interviewers redirect precisely — "try the `n=3` case" lands because the candidate named the gap). Hint-handling is itself scored (hint integrated → solution finished independently after = strong signal; hint needed per step = calibrated weaker — both beat silent stalling). Recovery visible is recovery scorable.
- **Modern guidance** — time-box silent thinking (60–90 seconds max — then narrate *something*: knowns, missing piece, small-case attempt). Shrink to toy inputs when abstract reasoning stalls (`n=3` hand enumeration restarts stuck derivations — small cases teach, large ones intimidate). Accept hints gracefully (integrate immediately, credit explicitly — "good pointer, that unblocks the transition" — hint economics favor the forthright). Never fake progress (confident wrong turns score worse than honest stuckness — integrity is load-bearing in hiring).

```bash
# GOOD: stuck specified, recovery narrated (scorable at every step)
#  "Have examples + constraints; transition for skips isn't coming. Trying n=3 by hand: [traces].
#   Ah — skip means best(i-1), take means best(i-2)+a[i]. Recurrence found via toy case."
# BAD: three silent minutes then "can you give me a hint?" —
# no signal generated (thinking? freezing?), hint lands generically, recovery unscored
```

### 3) **Close with verification**

**Definition** — finished means *proven*: trace the sample through the code (line-by-line on the given example — the implementation *runs* in front of the interviewer), state final bounds (time + space with models — Domain 01 §4.1's habit, performed), name trade-offs and edges (alternatives considered, matrix cells covered — leaves 1.1–1.2's disciplines, recited). Closing converts "code written" into "solution delivered" — the last impression (verification rigor) outweighs the first (problem restatement) in hiring memory.

- **Why it hurts when missing (correctness, maintainability)**: unclosed solutions leave interviewers verifying (they trace it themselves — finding the bug the candidate would have caught, scored accordingly) or trusting (unverified code hired on smoothness — the process failure that ships weak hires). Self-traced samples catch a remarkable fraction of live bugs (off-by-ones, missed edges, wrong bounds — the candidate's own trace is the cheapest test suite ever run). Verification narrated *is* the closing argument for hire.
- **Modern guidance** — trace the given sample aloud (every line, actual values — performance as proof, not ritual). Walk one edge case unprompted (empty/duplicates/extreme — matrix coverage demonstrated, not claimed). Restate bounds finally (time + space, models named — the numbers that close technical evaluation). Name one genuine trade-off ("hash version uses `O(n)` space; sorted variant converges in `O(1)` — chose hash for unsorted inputs" — judgment displayed at close). Ask for feedback on approach (dialogue, not monologue — senior signal in junior interviews).

```bash
# GOOD: proven, not just written (closing ritual)
#  trace sample ([values through each line] -> matches expected) + edge (empty -> specified sentinel).
#  bounds restated (O(n)/O(n), hash lookups). trade-off named (sorted variant converges, O(1) space).
#  "Alternative considered: X (rejected because Y)" — judgment visible at close.
# BAD: "done" + silence (code abandoned at last line) —
# verification outsourced to interviewer; bugs found by them score against, not for
```

### 4) **Common confusion**

- "Narration distracts from coding" — narration *structures* coding (decisions stated before typed — fewer wrong turns, faster overall). Silent speed produces rewrites; narrated pace produces solutions.
- "Hints mean failing" — hints mean *calibration* (integrated hints score problem-solving with assistance — normal engineering; per-step hints score dependence). Only hint-refusal fails (stuck silently = unscored).
- "Verification is the interviewer's job" — verification is the *candidate's* closing argument (self-traced samples prove rigor; outsourced verification proves nothing). Hire-me evidence, self-supplied.
- "Confidence means never stuck" — confidence means *recovering visibly* (stuck specified, toy-cased, hint-integrated). Never-stuck candidates are either lucky or silent — neither hires well.

### 5) **Performance note**

Narration costs breath (seconds per decision — negligible against interview clocks); stuck-protocol costs a minute of structured recovery (vs unbounded silent stalling — the most expensive interview failure mode); closing verification costs two minutes (sample trace + edge + bounds — the highest-signal minutes of the session). Unnarrated brilliance costs the offer (unscored reasoning); narrated recovery earns it (scored resilience). Breath is cheap; silence is expensive — and charged to the silent candidate.

### 6) **Mentor note**

Run mock interviews scored on narration beats (restate/bound/approach/code/test/trade-offs — six checkboxes per candidate, gaps named in feedback). Drill stuck recovery explicitly ("go silent for 90 seconds, then recover aloud" — the skill rehearsed, not hoped). Demand closing verification in every practice ("trace it, bound it, trade it off" — unfinished closes flagged). Watch for the silent solver (brilliant code, unscored reasoning — fix with "narrate decisions, type mechanics silently") and the hint-refuser (stuck silently — fix with stuck-protocol drills). Review check: beats audible, stuck specified, closes verified — and the mentor's own whiteboarding modeling all three visibly.
