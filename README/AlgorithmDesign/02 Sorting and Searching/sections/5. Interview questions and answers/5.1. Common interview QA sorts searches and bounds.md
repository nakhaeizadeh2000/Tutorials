## 5.1. Common interview QA: sorts, searches, and bounds

### 1) **Sort this by hand, narrating costs**

**Definition** — the mechanics screen: a small array, a chosen algorithm, narration of every decision with its price ("partition around 5: three smaller left, two right — linear pass; recurse left…"). Graded on *narration*, not completion — the candidate who partitions once correctly while counting beats the candidate who sorts silently with a memorized script. Follow-ups target the counting: "how many comparisons total?" (sum the levels), "what changes if sorted?" (pivot discipline — leaf 2.2), "stable?" (tie-break audit — leaf 1.1).

- **What a good answer sounds like**: operations with receipts — "Lomuto around last element 5: sweep compares 6 (n−1), places 3 left / 3 right; recurse both; total ≈ `n log n` balanced, `n²/2` degenerate (19900 at n=200 sorted, verified in our leaves)." Then unprompted: pivot choice justification ("median-of-three — sorted input is the common case"), stability note ("unstable — equals may scramble, fine here since keys unique"), threshold note ("insertion below ~16 in production").
- **Modern guidance** — interviewers listen for *cost narration alongside mechanics*: candidates who state prices per step demonstrate analysis; candidates who perform steps silently demonstrate memorization. Red flags: partition without invariant ("swap things around"), no worst-case mention (royalty without liability — leaf 2.2), "I'd just call sort" as the whole answer (library-first is judgment, but the interview screens mechanics — show both: hand-roll narrated, then "in production, the library").

### 2) **Binary search with duplicates — first occurrence?**

**Definition** — the invariant screen: "find the *first* occurrence of `t` in a sorted array with duplicates" (lower bound — leaf 3.1). Expected answer isn't code from memory but *derivation from the invariant*: maintain "answer in `[lo, hi)`," move `hi = m` (not `m−1` — the midpoint may *be* the first occurrence), terminate at empty range. Verified behavior candidates should reproduce: first-`≥` returns the run's start, `upper − lower` counts the run (verified exactly 2 for the 7s).

- **What a good answer sounds like**: invariant first ("first index with `a[i] ≥ t` — everything left is smaller, everything from `hi` qualifies"), updates derived ("`a[m] < t` → answer is right of `m`, `lo = m+1`; else `m` may qualify, `hi = m`"), termination argued ("range shrinks every step; empty range is the answer's address"). Then the boundary matrix unprompted (empty, single, all-equal — leaf 3.1's six cases) and the composition close (membership/run/insertion all reduce here).
- **Modern guidance** — grade derivation over recall: candidates who re-derive `hi = m` from "midpoint may qualify" pass even with shaky syntax; candidates who recite `while (lo <= hi)` closed-range recipes fail at the first duplicate. Instant fail: linear scan "to handle duplicates" (abandons logarithmic on sorted data — the pattern unrecognized), or `indexOf` after finding one (linear walk from a log find — composition missed).

```javascript
// The answer derived, not recalled (leaf 3.1's verified bound)
// invariant: a[0..lo) < t, answer (first >= t) in [lo, hi).
function lowerBound(a, t) { let lo = 0, hi = a.length;
  while (lo < hi) { const m = (lo + hi) >> 1; if (a[m] < t) lo = m + 1; else hi = m; } return lo; }
// first occurrence = lowerBound + equality check; run length = upper - lower (verified 2).
```

### 3) **Why can't we sort faster than `n log n`?**

**Definition** — the lower-bound answer in ninety seconds: comparison sorts decide by pairwise outcomes; `n!` possible orders need distinguishing; a binary decision tree with `n!` leaves stands ≥ `log₂(n!) = Ω(n log n)` tall (Stirling — ~118,000 for `n = 10,001`); therefore merge/quicksort/heapsort sit at the floor — asymptotically optimal, improvable only in constants. Then the scope sentence: "*comparison* sorts — counting/radix/adaptive methods decline the game rather than winning it."

- **What a good answer sounds like**: proof sketch plus escape hatches in one breath — "each comparison is a binary branch; `n!` orders need `log(n!)` height; Stirling gives `n log n`; so our sorts are optimal *among comparators* — faster needs structure (bounded keys → counting `O(n+k)`, digits → radix, presorted → TimSort adaptivity)." Seniors add tightness ("our quicksort runs ~1.4× floor — near-optimal, constants only") and the interviewer's trap-answer ("benchmarks beating it measure constants or broken benchmarks — never asymptotics").
- **Modern guidance** — listen for *scope discipline* (the word "comparison" doing load-bearing work): candidates who bound the claim pass; candidates who declare "sorting can't beat `n log n`" absolutely fail the escape-hatch follow-up. Red flags: confusing the bound with an implementation limit ("computers can't compare faster" — the bound is information-theoretic, not hardware), or no escape hatches offered (theory without engineering exits).

### 4) **Common confusion**

- Candidates who narrate mechanics without prices (partition steps silent on comparisons) — analysis is the screened skill, not typing.
- "Binary search variants are advanced" — lower/upper bounds are *the* binary search (one pattern, six questions — leaf 3.1); single-match search is the special case taught first for pedagogy, not primacy.
- Treating the lower bound as discouragement ("sorting is solved, nothing to learn") — the bound closes asymptotics and *opens* engineering (constants, adaptivity, structure, stability, memory). Solved in theory is where practice begins.

### 5) **Performance note**

Interview answers here should be compact: hand-sort narration (two minutes — mechanics with prices, pivot/stability/threshold close), duplicates bound (90 seconds — invariant, derivation, matrix), lower bound (ninety seconds — branches, leaves, height, exits). Candidates who narrate procedures with receipts take the same time as silent performers and prove triple — structure is speed, in interviews as in analysis.

### 6) **Mentor note**

Use Q1 as the mechanics screen (partition narrated with prices), Q2 as the invariant screen (derivation from contract, not recall), Q3 as the theory screen (proof sketch plus escape hatches). Rubric: junior — correct mechanics with counting shown; mid — cases stated (worst default, pivot defenses named), bounds composed (run length from two searches); senior — lower bound with scope discipline, tightness awareness (~1.4× floor), and escape-hatch fluency without prompting. Keep the verified numbers ready (19900, 20/21, 40188 vs 132877) — receipts separate narrators from memorizers. Red-flag fails: silent sorting, linear scans on sorted data, absolute lower-bound claims, royalty-without-liability quicksort.
