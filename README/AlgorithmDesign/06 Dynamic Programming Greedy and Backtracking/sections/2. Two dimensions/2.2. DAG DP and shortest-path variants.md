## 2.2. DAG DP and shortest-path variants

### 1) **Topological order linearizes DP**

**Definition** — on a DAG, processing vertices in topological order reduces DP to a single relaxation pass: each vertex settles when all predecessors are final (acyclicity guarantees predecessors precede — no heap, no iterations, `O(V+E)` total). Longest paths (NP-hard generally — linear on DAGs), DAG shortest paths (Bellman-Ford's generality without its `V·E` price), and counting DAG paths all reduce here. Verified: longest-path value **11** over the 6-node probe DAG with topo order `[0,1,3,2,4,5]` — one pass, predecessors settled first by construction.

- **What problem it solves**: general-graph DP fights cycles (memoized DFS needs visited-state machinery — gray/black re-derivation per problem; Bellman-Ford iterates `V−1` times for cycles that may not exist). Acyclicity *removes* the fight: topo order is the evaluation order (Domain 05 §1.2's order enabling DP — the cross-link that pays for both domains), and one relaxation pass suffices because no edge points backwards. DAG DP is Bellman-Ford with the iterations proven unnecessary — same relaxation idea, `V+E` instead of `V·E`.
- **Modern guidance** — topologically sort first on DAG-structured DP (task chains, dependency profits, layered graphs — order once, relax once). Generalize the relaxation target (shortest/longest/counting/reachability — same pass, different combine operator: `min`/`max`/`+`/OR). Detect cycles before assuming DAG (three-color check — Domain 05 §1.2; cyclic input makes "topological order" undefined behavior wearing an array). State acyclicity with the complexity ("`O(V+E)` *on DAGs*" — the qualifier that prevents misapplication to general graphs).

```javascript
// GOOD: order once, relax once — verified longest value 11, topo [0,1,3,2,4,5]
// dist[v] = best over predecessors (max for longest): single pass in topo order, O(V+E).
// No heap (order known upfront — Dijkstra's machinery unnecessary), no iterations (acyclicity proven).
// BAD: Bellman-Ford "to be safe" on DAGs ("general") —
// V*E relaxations where V+E suffice; generality bills 100x for cycles that don't exist
```

### 2) **Edit distance aligns optimally**

**Definition** — minimum single-character edits (insert/delete/substitute) transforming A into B: `d[i][j]` over prefixes, recurrence taking the min of three moves (delete from A, insert into A, substitute-or-match), base row/column counting from empty. Verified: `horse→ros` = **3**, `intention→execution` = **5** (the canonical pair — any implementation must reproduce both). `O(nm)` time/space (rolling to two rows — the compression from leaf 2.1, third appearance). KMP's cousin (Domain 03 §3.2): prefix reasoning over *two* strings instead of one.

- **Why it matters (correctness)**: edit distance *is* diff/spellcheck/DNA-alignment infrastructure (diff hunks are edit scripts with context; spell suggestions rank by distance; bioinformatics aligns gigabase strings with affine-gap variants). Naive alignment enumerates exponentially (three choices per position pair — `3^(n+m)` paths); greedy alignment commits locally (first-match anchoring fails where global structure differs — verified `intention→execution` needs non-local decisions no greedy finds). DP over prefix pairs is the only exact polynomial method — the table *is* the alignment search done right.
- **Modern guidance** — implement the three-move recurrence directly (delete/insert/substitute — the operation set *is* the API: domain variants add transpose/affine costs as extra moves). Roll to two rows for distance-only queries (reconstruction needs the full table — store vs recompute decided explicitly, leaf 2.1's rule). Test the canonical pair (3 and 5 — oracle values; any edit-distance code earns trust by reproducing them). For gigabase scales, banded variants (Ukkonen's cutoff — compute near the diagonal only) trade exactness scopes, not correctness.

```javascript
// GOOD: three moves, prefix table — verified 3 and 5 (oracle pair)
// d[i][j] = min(d[i-1][j]+1, d[i][j-1]+1, d[i-1][j-1] + (a[i-1]===b[j-1] ? 0 : 1))
// horse/ros -> 3; intention/execution -> 5. O(nm) time, O(nm) table (two rows rolled for distance-only).
// BAD: greedy alignment ("match greedily, patch rest") —
// local anchors miss global optima (intention/execution needs non-local decisions); exactness requires the table
```

### 3) **LCS finds common structure**

**Definition** — longest common subsequence (not substring — order preserved, contiguity dropped): `l[i][j]` over prefixes, match extends diagonal (`+1`), mismatch takes max of top/left (best without either character). Verified: `abcde`/`ace` → **3** (`ace` itself). `O(nm)` time/space (Hirschberg halves space with divide-and-conquer — linear-space LCS for the memory-bound, named for completeness). Diff engines emit LCS-derived scripts (common backbone + edit hunks — Myers' O(ND) algorithm is the diagonal-specialized descendant for near-identical files).

- **Why it hurts when missing (correctness, maintainability)**: subsequence-vs-substring confusion (contiguous-only "LCS" misses non-adjacent structure — `ace` in `abcde` needs gaps; sliding windows can't express skips — Domain 03 §2.2's admission logic routes here). And naive LCS enumerates `2ⁿ` subsequences (exponential on 30-character strings DP answers in 900 cells). The table *is* the common-structure search — every diff, merge, and plagiarism detector stands on it (or its diagonal-optimized descendants).
- **Modern guidance** — choose subsequence (order-only) vs substring (contiguous — different recurrence: reset-on-mismatch, track max separately) vs edit-distance (cost-weighted) by question (common structure? contiguous block? transformation price? — three questions, three recurrences, one table shape). Reconstruct via backpointers (diagonal-on-match walk — the subsequence itself, not just its length). Prefer Myers O(ND) for near-identical files (diff's actual engine — linear in edits, not inputs; the specialization that ships).

```javascript
// GOOD: order without contiguity — verified 3 (ace itself)
// l[i][j] = a[i-1]===b[j-1] ? l[i-1][j-1]+1 : max(l[i-1][j], l[i][j-1])
// lcs("abcde","ace") = 3 verified. O(nm) time/space (Hirschberg halves space where bound).
// BAD: longest-common-SUBSTRING code answering subsequence questions ("similar") —
// contiguity requirement drops valid structure (ace needs gaps); recurrences differ — pick by question
```

### 4) **Common confusion**

- "DAG DP is just memoized DFS" — memoized DFS *implements* DAG DP with recursion overhead + cycle-detection machinery; topo-order iteration is simpler, stack-safe, and cycle-explicit (order fails loudly on cycles; memo-DFS needs separate colors). Same answers, different engineering envelopes.
- "Edit distance and LCS are interchangeable" — edit distance prices *transformation* (unit costs per op); LCS measures *commonality* (length of shared order). Related (both prefix tables) but answering different questions — transformation price vs shared structure.
- "Topological order is unique" — valid orders multiply (Domain 05 §1.2 — DP works under *any* valid order; uniqueness is unnecessary). Any topo order linearizes; pick by convenience (Kahn's levels for parallel DP waves).
- "2D DP always needs the full table" — rolling rows serve distance/count queries (leaves 1.1, 2.1); full tables serve reconstruction (paths, alignments, subsequences). Table size follows *use* (answers vs artifacts), not dimension count.

### 5) **Performance note**

DAG DP costs `V+E` relaxations (verified probe single-digit ms — linear, the prize for acyclicity); edit/LCS cost `nm` cells (verified 3/5 and 3 at single-digit ms — quadratic in string lengths, the price of pairwise prefixes); banded/Myers variants cost near-linear on similar inputs (specialization pays where inputs cooperate). Optimize acyclicity-detection first (DAG → linear; general → Bellman-Ford rates), table-rolling second (distance-only queries), banded specialization third (similar-input workloads only).

### 6) **Mentor note**

Teach DAG DP as "Bellman-Ford with iterations proven unnecessary" (topo order *is* the evaluation order — the sentence connecting Domains 05 and 06 permanently). Drill the oracle pairs (3/5 edit, 3 LCS — implementations prove themselves against fixed values). Contrast subsequence/substring/edit-distance as one question with three recurrences ("common structure? contiguous block? transformation price?" — pick-by-question drills). Watch for the memo-DFS default on DAGs ("works" — fix with stack-safety + cycle-explicitness arithmetic) and the substring-subsequence conflater ("similar" — fix with `ace`-in-`abcde` on the spot). Review check: acyclicity established (or Bellman-Ford chosen), oracle values green, table sized by use (rolled vs full justified), juniors can derive all three recurrences from prefix reasoning.
