## 3.1. Greedy choices and exchange arguments

### 1) **Greedy needs a proof, not a hope**

**Definition** — greedy algorithms commit to locally-optimal choices without reconsideration (no table, no backtrack — one pass, irrevocable): valid *only* with optimal substructure *plus* the greedy-choice property (some optimal solution contains the greedy choice — proven by *exchange argument*: take any optimal solution, swap in the greedy choice without worsening it, repeat until the greedy construction emerges optimal). Hope is not a paradigm; exchange proofs are the admission ticket (leaf: Domain 06 §4.1).

- **What problem it solves**: DP explores options via stored optima (`O(states × transitions)` — tables for problems greedy answers in one pass). Where greedy holds, it collapses tables to streaming (`O(n log n)` for the sort + `O(n)` scan — activity selection below; Huffman coding; MST via Kruskal/Prim — Domain 05 §2.2's union engine wearing greedy proof). The savings are structural (no table, no reconsideration), but *only* where exchange arguments certify them — uncertified greed is hope billing linearly.
- **Modern guidance** — demand the exchange sketch before shipping greedy ("take any optimal solution; swap its first differing choice for ours; argue no-worse; repeat" — four sentences that separate paradigms from wishes). Prefer greedy where proven (scheduling by earliest-finish, Huffman by frequency-merge, MST by cut property — each carries a classical proof; cite it, don't re-derive). Default to DP where unproven (tables explore what greed assumes — the safe superset; optimize to greedy only with proof in hand).

```javascript
// GOOD: commitment certified (exchange sketch travels with the code)
// "Take any optimal schedule S. Let g = earliest-finishing activity. If g ∉ S, swap S's
//  first activity for g (fits: g ends no later) — S stays optimal and now contains g.
//  Repeat on the remainder: greedy builds an optimal schedule. ∎"
// (Sketch stated once per greedy use — the proof IS the code review.)
// BAD: "greedy seems right here" without exchange ("intuitive") —
// intuition unproven is hope; hope bills at the counterexample (next section, verified 3-vs-2)
```

### 2) **Activity selection is canonical**

**Definition** — maximum compatible activities: sort by finish time, take each activity starting after the last taken (`O(n log n)` sort + `O(n)` scan, `O(1)` extra). Verified: `[[1,4],[3,5],[0,6],[5,7],[8,9],[5,9]]` → `[[1,4],[5,7],[8,9]]` (3 activities — earliest-finish leaves maximal room; longer `[0,6]` and overlapping `[3,5]`,`[5,9]` correctly skipped). Exchange proof (previous section) certifies: earliest-finish-first is optimal, not merely plausible.

- **Why it matters (correctness)**: activity selection is the *template* greedy (sort by a key, scan committing — interval scheduling, meeting rooms with counter augmentation, fractional knapsack by ratio, Huffman by frequency all wear this shape). Learning it deeply teaches greedy recognition generally: "sort by X, commit on condition Y, prove by exchange" transfers to every certified-greedy problem. Shallow learning ("sort by finish, take non-overlapping" memorized) breaks on variants (weighted activities need DP — values defeat pure earliness; resource-counting needs sweep-lines, not selection).
- **Modern guidance** — implement sort-then-scan literally (comparator = finish time; scan condition = `start >= lastEnd`; both visible, both reviewable). Extend by augmentation (meeting-rooms-II: sweep with counter instead of selection — same sort, different accumulation; weighted intervals → DP over sorted ends — values break greed, tables decide). Test the canonical input (verified trio — any implementation must reproduce it) plus the tie case (equal finishes — either choice valid; determinism asserted, not assumed).

```javascript
// GOOD: sort by finish, commit on compatibility — verified trio
function activitySel(iv) {
  const s = [...iv].sort((a, b) => a[1] - b[1]);  // earliest finish first (the greedy key, proven)
  const out = []; let last = -Infinity;
  for (const [st, en] of s) if (st >= last) { out.push([st, en]); last = en; }
  return out;
} // [[1,4],[3,5],[0,6],[5,7],[8,9],[5,9]] -> [[1,4],[5,7],[8,9]] verified. O(n log n) + O(n).
// BAD: sort by START time ("natural order") —
// early-starting long activities block the room; earliness of finish (not start) is what frees capacity
```

### 3) **Greedy fails instructively**

**Definition** — canonical greedy failures, each teaching the boundary: coin change on arbitrary denominations (verified: `[1,3,4]`, amount 6 → greedy `4+1+1` = **3 coins** vs optimal `3+3` = **2** — largest-first commits to 4, blocking the pair of 3s); 0/1 knapsack by ratio (fractional works — ratio-greedy optimal with splitting; 0/1 fails — indivisibility defeats the exchange); longest-path temptation (greedy descents trap locally — needs DP/DFS, Domain 05). Canonical coin systems (`[1,5,10,25]` — verified greedy = DP = **6** at 63) work by *design* (each denomination divides the next — the property that certifies greed, provable per system).

- **Why it hurts when missing (correctness, maintainability)**: uncertified greed ships the classics — change-makers shortchanging on exotic denominations (verified 3-vs-2: customers overpay by coins, incumbents underdeliver by algorithm), schedulers starving on weighted inputs (unweighted logic on valued work — priority inverted silently), Huffman-shaped compressors on non-prefix codes (uniquely-decipherable violations — data corrupts). Each passed tests (canonical inputs agree — verified 6 = 6) and failed the unusual (arbitrary systems diverge — the tests that weren't written). Failure instruction: test greedy against DP on randomized inputs (agreement proves nothing; disagreement locates the boundary).
- **Modern guidance** — test every greedy against DP/brute-force on randomized small inputs (differential testing — disagreements map the validity boundary precisely; the verified 3-vs-2 pair *is* such a differential finding). Prefer canonical structures where greed is certified (canonical coins, matroid settings — MST, scheduling — each with classical proofs cited). Default to DP on arbitrary variants (denominations, weights, constraints — tables explore what greed assumes; optimize to greedy only with exchange in hand). State the certification per use ("canonical system — greedy certified" vs "arbitrary — DP chosen pending proof").

```javascript
// GOOD: boundary located by differential testing — verified 3 vs 2
// greedy([1,3,4], 6) = 3 (4+1+1); dpCoins = 2 (3+3). DISAGREE -> greedy uncertified here -> ship DP.
// greedy([1,5,10,25], 63) = 6 = dpCoins (canonical: agree — certified by divisibility structure).
// Rule: differential-test greedy vs DP on randomized inputs; ship greedy only where they never disagree.
// BAD: largest-first change-maker on arbitrary denominations ("standard algorithm") —
// standard for CANONICAL systems; arbitrary systems need DP (verified overcharge: 3 coins for a 2-coin answer)
```

### 4) **Common confusion**

- "Greedy is faster than DP, so prefer it" — faster *where certified* (linear scans vs tables); wrong where uncertified (verified overcharge). Speed without proof is haste with syntax.
- "Exchange arguments are academic" — exchange arguments are the *only* thing separating greedy from hope (four sentences per use — cheaper than the counterexample incidents they prevent). Academia named the tool; production pays for skipping it.
- "Matroid theory is required" — matroids characterize exactly-where-greedy-works (independence systems with exchange — MST, scheduling); using certified instances needs the *proof sketch*, not the theory. Cite classical proofs; reserve matroids for novel greedy claims.
- "DP always beats greedy" — DP explores (tables cost space/time); certified greedy streams (no table, one pass). Where both valid, greedy wins constants big — validity is the question, not power.

### 5) **Performance note**

Greedy costs sort + linear scan (verified probes single-digit ms: activities trio, coin probes) with `O(1)`–`O(n)` extra (no tables — the structural savings); DP alternatives cost states × transitions (coin DP `O(amount × denoms)` — tables for uncertified cases). Differential testing costs randomized small-input runs (cheap — the boundary-mapping investment). Optimize certification first (exchange sketch or differential agreement — validity gates everything), scan constants second (sort dominates anyway), table-avoidance never (validity, not speed, motivates greed).

### 6) **Mentor note**

Teach exchange with the four-sentence template ("take optimal, swap first-difference, argue no-worse, repeat" — fill per problem until the shape is reflexive). Demonstrate failure live (verified 3-vs-2 — "same question, different denominations, greed breaks" converts certification from pedantry to survival). Drill differential testing as habit (greedy vs DP randomized — disagreements *are* the boundary map). Watch for the hope-shipper ("seems right" — fix with "show me the exchange or the differential") and the DP-default ("tables everywhere" — fix with certified-greedy constants on proven ground). Review check: exchange sketch or differential evidence per greedy use, canonical-vs-arbitrary stated, DP fallback named where uncertified, juniors can sketch exchange for activity selection unprompted.
