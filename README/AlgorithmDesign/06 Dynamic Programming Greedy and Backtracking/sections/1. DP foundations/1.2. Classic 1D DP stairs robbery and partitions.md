## 1.2. Classic 1D DP: stairs, robbery, and partitions

### 1) **Stairs count compositions**

**Definition** — climbing `n` stairs taking 1–2 steps: `ways(n) = ways(n−1) + ways(n−2)` (last step from either predecessor — Fibonacci-shaped recurrence, `O(n)` time tabulated, `O(1)` space rolling two variables). Verified: 5→8, 10→89, 20→10946. Generalizes to k-steps (sum previous k — sliding window over DP, Domain 03 §2.1's exchange wearing recurrence clothes) and min-cost variants (weights per step — same recurrence, `min` instead of `+`).

- **What problem it solves**: counting compositions without DP branches exponentially (each position forks — the naive tree re-solves suffixes combinatorially, leaf 1.1's fib shape in disguise). The recurrence collapses the tree to a line (each `ways(i)` computed once from two predecessors — overlapping subproblems *are* the adjacent answers). Stairs teach the DP reading skill: spot "answer at `i` from answers before `i`" and the table writes itself.
- **Modern guidance** — implement rolling variables (two predecessors suffice — full tables waste `O(n)` where `O(1)` decides; state the compression explicitly). Extend by varying steps (k-step windows), costs (min-cost accumulation), and constraints (no-consecutive-same — state augments with last-choice, previewing state design from leaf 1.1). Test the recurrence base directly (`ways(0)=1` — empty composition counts; the off-by-one that breaks every stairs implementation lives here).

```javascript
// GOOD: recurrence transcribed, space rolled — verified 8/89/10946
function stairs(n) {
  if (n <= 1) return 1;                  // base: ways(0)=1 (empty composition), ways(1)=1
  let a = 1, b = 1;                      // rolling: only two predecessors live
  for (let i = 2; i <= n; i++) { const c = a + b; a = b; b = c; }
  return b;
} // O(n) time, O(1) space. k-steps: window-sum over previous k (Domain 03 §2.1 exchange, recurrence-dressed).
// BAD: recursive stairs without memo ("clean") —
// fib-shaped tree, exponential bills; clarity that recomputes is energy waste (leaf 1.1 verified)
```

### 2) **Robbery forbids adjacency**

**Definition** — maximum loot with no two adjacent houses: `dp[i] = max(dp[i−1], dp[i−2] + a[i])` (skip `i` keeps prior best; take `i` adds to best-before-neighbor — the include-vs-skip recurrence, two rolling variables, `O(n)` time `O(1)` space). Verified: `[2,7,9,3,1]` → **12** (2+9+1 — skipping 7 and 3, the adjacency constraint working visibly). Circular variant (first/last adjacent) runs the recurrence twice (exclude-first, exclude-last — max of both; constraint handled by case split, not recurrence surgery).

- **Why it matters (correctness)**: include-vs-skip is DP's most reusable idea (knapsack 0/1 takes the same shape — weight capacity replacing adjacency; stock-with-cooldown augments state with rest-day; delete-and-earn remaps values to frequencies first). Robbery teaches the *decision-per-position* pattern: each index chooses take-or-skip against constrained predecessors, and the recurrence prices both. Greedy fails here visibly (take-7-first grabs local max, blocks 9 — exchange arguments collapse; the counterexample that motivates DP over hope, leaf 3.1's foil).
- **Modern guidance** — transcribe include-vs-skip directly (two variables `prev/curr` — table-free from the start; full arrays where audit trails matter). Extend by state augmentation (cooldown → 3 states; circular → 2 runs; k-skip → wider windows — same recurrence family, richer state). Test adjacency enforcement explicitly (alternating high/low inputs where greedy grabs wrong — `[2,7,9,3,1]` verified 12 vs greedy-7-first 11: the unit test that distinguishes paradigms).

```javascript
// GOOD: take-or-skip per position — verified 12 (greedy would take 7, block 9, land 11)
function rob(a) {
  let prev = 0, curr = 0;                // prev: best before i-1; curr: best through i-1
  for (const x of a) { const n = Math.max(curr, prev + x); prev = curr; curr = n; }
  return curr;
} // O(n) time, O(1) space. Circular: max(rob(a[1:]), rob(a[:n-1])) — constraint by case split.
// BAD: greedy take-largest-available ("intuitive") —
// verified 11 vs optimal 12 on [2,7,9,3,1]; local maxima block global optima (leaf 3.1's foil, live)
```

### 3) **Partitions split optimally**

**Definition** — decision-at-every-position generalizes beyond binary take/skip: word break (`dp[i]` = prefix splittable — any split point `j` with `dp[j]` and dictionary word `s[j..i)`), palindrome partitioning (cuts minimizing pieces — center-expansion precompute + DP over suffixes), coin change counting (compositions over denominations — order of loops decides permutations-vs-combinations). Verified: `leetcode`/`[leet,code]` → **true**; `catsandog` → **false** (exhaustive splits, no valid segmentation — false is an answer, not a failure).

- **Why it hurts when missing (correctness, maintainability)**: partition problems solved by enumeration nest combinatorially (all `2ⁿ` splits tried — exponential on 30-character inputs that DP answers in `n²`), while greedy splits commit early (first-dictionary-match segmentation fails where backtracking succeeds — `catsandog` needs `cat|sand|...` dead-ends explored, not first-match taken). DP-over-splits is the middle path: every split point considered once, results memoized — exhaustive without exponential, decisive without greed.
- **Modern guidance** — structure partition DP as outer-position/inner-split (`dp[i]` over split points `j < i` — `O(n²)` time, `O(n)` space; the shape to recognize). Precompute expensive predicates (palindrome tables via center expansion — `O(n²)` once, `O(1)` queries inside DP; dictionary sets for `O(1)` word checks). Mind loop order in counting variants (coins-outer → combinations; amount-outer → permutations — the order *is* the semantics; swapping counts different objects). Test impossible inputs explicitly (verified `false` — exhaustiveness proven by negative answers).

```javascript
// GOOD: splits considered once, memoized always — verified true/false
function wordBreak(s, dict) {
  const w = new Set(dict), dp = new Array(s.length + 1).fill(false);
  dp[0] = true;                                     // base: empty prefix splittable
  for (let i = 1; i <= s.length; i++)
    for (let j = 0; j < i; j++)                     // every split point, once
      if (dp[j] && w.has(s.slice(j, i))) { dp[i] = true; break; }
  return dp[s.length];
} // O(n^2) time (splits), O(n) space. leetcode->true, catsandog->false verified.
// BAD: greedy first-match segmentation ("fast") —
// commits to early splits; dead-ends need backtracking (leaf 3.2) or DP exhaustiveness (here)
```

### 4) **Common confusion**

- "1D DP is trivial" — 1D DP is *foundational* (recurrence reading, rolling space, case splits — every 2D/paradigm skill generalizes these three). Trivial describes length, not leverage.
- "Robbery needs the full table" — two variables suffice (only `i−1`, `i−2` predecessors — rolling from the start, not as optimization). Tables store what's *reused*; adjacent-only reuse needs no table.
- "Word break is just string matching" — matching finds *occurrences* (Domain 03 §3.2); word break decides *segmentability* (global property over all splits). Local matching vs global partition — different questions sharing strings.
- "Circular variants need new recurrences" — case splits reuse linear DP twice (exclude-first, exclude-last — constraint handled by enumeration over two runs, not recurrence surgery). Split cases, don't complicate recurrences.

### 5) **Performance note**

1D DP costs `n` states × transition (verified probes single-digit ms: stairs/rob/word-break all linear-to-quadratic) with `O(1)`–`O(n)` space (rolling where predecessors bound, tables where splits need history). Naive recursion costs exponential calls (leaf 1.1's verified 242,785 at `n=25` — the baseline these replace). Greedy alternatives cost linear *when valid* (faster with proof burden — leaf 3.1 decides validity). Optimize recurrence recognition first (take-skip/split/window shapes), space rolling second (predecessor-bounded → `O(1)`), micro-structure never (loop bodies are arithmetic).

### 6) **Mentor note**

Teach recurrence reading with the verified trio (stairs compositions, robbery decisions, partition splits — three shapes covering most 1D DP). Drill rolling space live (full table → two variables, same answers — "store what's reused" as the compression principle). Contrast greedy explicitly (take-7-first scoring 11 vs optimal 12 — the one-point gap that motivates DP over hope). Watch for the enumerator ("thorough" exponential splits — fix with `n²`-vs-`2ⁿ` arithmetic) and the table-hoarder (full arrays where rolling suffices — fix with predecessor analysis: "which past states does the transition read?"). Review check: recurrence stated with base, space rolled where bounded, impossible inputs tested, juniors can derive take-skip from scratch.
