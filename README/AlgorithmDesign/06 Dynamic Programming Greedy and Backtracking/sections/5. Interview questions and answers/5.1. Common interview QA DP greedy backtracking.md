## 5.1. Common interview QA: DP, greedy, and backtracking

### 1) **Climbing stairs, three variants**

**Definition** — the recurrence screen in three acts: *count* ways (1–2 steps → Fibonacci-shaped, verified 8/89/10946, `O(1)` rolling); *min-cost* stairs (price per step → `min` recurrence, same shape, different combine); *k-steps* (sum previous k — sliding window over DP, Domain 03 §2.1's exchange recurring). Same skeleton, three combines (`+`, `min`, window-sum) — the candidate who derives each from "last step partitions all routes" passes; the candidate who memorizes three solutions fails the fourth variant (no-consecutive-same, 3-steps-max — interviewers vary constraints precisely to test derivation).

- **What a good answer sounds like**: recurrence first ("ways(n) from ways(n−1), ways(n−2) — last step partitions compositions disjointly"), base stated ("ways(0)=1 — empty composition counts; the off-by-one that breaks implementations"), rolling noted ("two predecessors live — `O(1)` space"), variant derived live ("min-cost: same positions, `min` combine; k-steps: window sum over k predecessors"). Then the complexity close (`O(n)` time, `O(1)` space — both variants, same envelope).
- **Modern guidance** — interviewers listen for *partition reasoning* ("last step from either predecessor — disjoint, exhaustive") as the transferable skill: candidates who partition derive min-cost/k-step/no-repeat variants on demand; candidates who recite Fibonacci freeze at the first twist. Red flags: recursion without memo ("clean" — exponential, leaf 1.1's verified 242,785 waiting), base-case handwaves (`ways(0)` undefined — cascades through every answer), full tables where rolling suffices (space unconsidered).

```javascript
// The three variants, derived from one partition idea (leaves 1.2 + 3.1 machinery)
// count:    ways(n) = ways(n-1) + ways(n-2), ways(0) = 1 -> 8/89/10946 verified.
// min-cost: cost(n) = price(n) + min(cost(n-1), cost(n-2)) (same positions, min combine).
// k-steps:  ways(n) = sum(ways(n-k..n-1)) (window over DP — Domain 03 §2.1 exchange, recurrence-dressed).
```

### 2) **Coin change: greedy or DP?**

**Definition** — the judgment screen: "fewest coins for amount A" — greedy (largest-first, streaming, no table) or DP (`dp[i]` = min coins for `i`, `O(A·denoms)`) — decided by *denomination structure*, not preference. Canonical systems (`[1,5,10,25]` — each divides the next) certify greed (verified agree: 6 = 6 at 63); arbitrary systems break it (verified: `[1,3,4]` amount 6 → greedy **3** vs DP **2** — largest-first commits to 4, blocking the 3+3 pair). The interview tests fork discipline (leaf 4.1): exchange-or-differential evidence before commitment.

- **What a good answer sounds like**: both implemented, boundary located — "greedy largest-first (streaming, `O(denoms)`); DP table (`O(A·denoms)`); differential test decides: canonical agree (verified 6=6 — ship greedy), arbitrary diverge (verified 3-vs-2 — ship DP)." Then the generalization volunteered ("divisibility structure certifies greed in general — each coin dividing the next; without it, tables explore what greed assumes"). Seniors add counting-vs-min variants (compositions need loop-order discipline — coins-outer for combinations, amount-outer for permutations — leaf 1.2).
- **Modern guidance** — grade *evidence-first* behavior: candidates who propose the differential test ("let me check greedy against DP on samples") demonstrate engineering; candidates who commit to either unconditionally demonstrate dogma (greedy-elegance or DP-safety — both fail half the inputs). Instant fail: greedy on arbitrary denominations without a validation word ("standard algorithm" — standard for canonical systems; the verified overcharge is the rebuttal). Follow-up separating senior: "prove greedy for US coins" (divisibility chain → exchange holds per step — sketch it, don't handwave).

```bash
# The judgment, evidenced (leaf 3.1's differential as interview response)
#  greedy([1,3,4], 6) = 3 (4+1+1) vs dp = 2 (3+3) -> DIVERGE -> ship DP (uncertified greed overcharges).
#  greedy([1,5,10,25], 63) = 6 = dp -> AGREE (canonical divisibility certifies) -> ship greedy (streaming wins).
#  Rule: differential-test on samples; ship greedy only where they never disagree.
```

### 3) **Solve N-queens sketch**

**Definition** — the backtracking screen: place queens row by row with column/diagonal constraints, undo per return, count completions — skeleton narrated (choose → constrain → recurse → unchoose, leaf 3.2), pruning stated (attacked squares never recursed), oracles cited (N=4 → **2**, N=8 → **92** — verified; implementations prove themselves against fixed values). Graded on *skeleton clarity* (four steps visible, undo explicit) plus *pruning awareness* (constraints checked pre-recursion, not post-failure).

- **What a good answer sounds like**: skeleton first ("place per row, `ok()` checks column + diagonals against placed rows, recurse, overwrite-undo"), pruning stated ("attacked squares skipped pre-recursion — dead placements die at depth r, not r+5"), oracles cited ("4→2, 8→92 verified — wrong counts mean broken search or broken constraints"), complexity closed ("output-sensitive: 92 answers via thousands of nodes — pruning grade enormous vs raw `nⁿ`"). Then the generalization volunteered ("same skeleton solves Sudoku/partitions — constraints plug in, structure persists").
- **Modern guidance** — listen for *undo explicitness* (remove/restore or overwrite discipline stated — state leaks corrupt sibling subtrees silently) and *oracle awareness* (fixed counts cited unprompted — testing mindset, not just coding). Red flags: board-copying per recursion ("safer" — memory avalanche, leaf 3.2's warning live), no pruning mention (raw enumeration "works" — N=12 outlives patience), diagonal check omitted (column-only constraints under-constrain — wrong counts with confident code).

### 4) **Common confusion**

- Candidates who answer variants with the base solution (count-code for min-cost questions — combine operators differ; partition reasoning transfers, code doesn't).
- "Greedy vs DP is a style choice" — evidence choice (exchange proof or differential agreement vs table exploration). Style doesn't decide correctness; proofs and tables do.
- Treating N-queens as queens trivia — skeleton transfer is what's screened (Sudoku/partitions share the shape); queens are the example, skeletons the deliverable.

### 5) **Performance note**

Interview answers here should be compact: stairs variants (two minutes — partition, base, rolling, two derivations), coin judgment (two minutes — both implementations, differential evidence, generalization), N-queens sketch (two minutes — skeleton, pruning, oracles, transfer). Candidates who narrate derivations with receipts take the same time as silent coders and prove triple — structure is speed, in interviews as in analysis.

### 6) **Mentor note**

Use Q1 as the recurrence screen (partition reasoning + variant derivation), Q2 as the judgment screen (evidence-first fork discipline), Q3 as the skeleton screen (undo explicit, oracles cited). Rubric: junior — correct recurrences with counting shown; mid — bases stated, space rolled, pruning narrated, edges covered; senior — exchange sketches, differential testing, output-sensitivity, skeleton transfer without prompting. Keep the verified numbers ready (8/89/10946, 3-vs-2, 2/92) — receipts separate narrators from memorizers. Red-flag fails: unmemoized recursion, uncertified greed, board-copying search, variant-blind templates.
