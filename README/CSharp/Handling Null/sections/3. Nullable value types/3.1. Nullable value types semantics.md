## 3.1. Semantics: `int?` is not “an int that can be null” (it’s `Nullable<int>`)

1. **Representation**: `HasValue` + `Value` (and why `Value` can throw).
2. **Lifting rules**: operators and comparisons on nullable value types (and the “null wins” behavior).
3. **Correct defaults**: avoid sentinel values when `T?` models absence more honestly.

### 1) **Representation**: `HasValue` + `Value` (and why `Value` can throw)
`int?` is syntax sugar for `Nullable<int>`. It’s a **value type** wrapper with two parts:
- **`HasValue`**: whether a value is present
- **`Value`**: the underlying `int` (throws if `HasValue` is false)

Key points mentors stress:
- `T?` for `struct` is **not a reference** and does **not allocate** by itself.
- `.Value` is a **sharp edge**: it throws `InvalidOperationException` if empty.

Runnable example:

```csharp
int? maybe = null;
Console.WriteLine(maybe.HasValue); // False

// Avoid: throws InvalidOperationException
// Console.WriteLine(maybe.Value);

Console.WriteLine(maybe.GetValueOrDefault()); // 0
```

**Good to know**
- `Nullable<T>` is often the cleanest way to represent “no measurement yet”, “no date available”, “optional quantity”, etc., without inventing magic numbers.

### 2) **Lifting rules**: operators and comparisons (and the “null wins” behavior)
Most operators on `T?` are **lifted**:
- If any operand is `null`, the result is usually `null` (for arithmetic) or `false`/`null` depending on the operator family.

Example:

```csharp
int? a = 10;
int? b = null;

int? sum = a + b;              // null (lifted +)
bool eq = (a == b);            // false (null comparison rules)
bool? less = (b < a);          // null (lifted comparison yields bool?)
Console.WriteLine(sum);        // (empty)
Console.WriteLine(eq);         // False
Console.WriteLine(less);       // (empty)
```

Mentor guidance:
- Don’t rely on lifted operator behavior unless it improves clarity; many teams prefer explicit `HasValue` checks for domain-critical rules.
- For comparisons, remember:
  - `==` and `!=` yield `bool` (not `bool?`) for nullable value types.
  - `<`, `>`, `<=`, `>=` yield `bool?` when lifted (because “unknown” comparison is itself unknown).

### 3) **Correct defaults**: avoid sentinel values when `T?` models absence honestly
Sentinel values (like `-1`, `0`, `DateTime.MinValue`) are attractive because they’re “just an int”, but they leak ambiguity:
- Is `0` a real value or “missing”?
- Does `-1` ever become valid later?
- Will serialization/DB layers preserve the sentinel reliably?

Prefer:
- `int?` for “optional numeric”
- `DateOnly?` / `DateTimeOffset?` for “optional date/time”
- “Try-pattern” results when absence is *expected control flow* (see `Handling Null/5.1` for API shapes)

**Performance note**
- `T?` itself is allocation-free, but you can still accidentally allocate by:
  - boxing (`object o = (int?)5;`)
  - using non-generic APIs (`IComparable`, `object`, `params object[]`) in hot paths
