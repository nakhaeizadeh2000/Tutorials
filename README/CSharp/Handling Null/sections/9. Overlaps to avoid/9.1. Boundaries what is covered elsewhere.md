## 9.1. Boundaries: what is covered elsewhere in this repo

1. **Generic `T` nullability and constraints** live in `Generics/2.2` (this domain focuses on *using* nullability, not generic constraint theory).
2. **`??=` basics** are introduced in `CSharp language basics/4.2` (this domain goes deeper into design/perf/contract implications).
3. **Boxing deep dives** (including “null + boxing” scenarios) live in `System Object Class/4.*` and `Structures/3.3`.
4. **Overload resolution and ambiguity traps** (common with `null` literals) live in `Methods/5.1`.

### How to use these boundaries (mentor workflow)
- **If you want to understand why the compiler warns** about `T` vs `T?`, `notnull`, and unconstrained generics, go to the Generics deep dive and come back.
- **If you’re debugging allocations** caused by “null + object APIs” (boxing, `params object[]`, non-generic collections), use the boxing sections—they’re the canonical performance reference.
- **If you’re confused by `null` choosing the “wrong overload”**, jump to overload resolution. That is the single canonical place for that topic.
- **If your null bug happens “only sometimes”**, suspect concurrency / memory visibility. This domain gives a practical warning, but the canonical deep theory is in Concurrency.

Mentor rule:
- Treat duplication in docs like duplication in code: it creates contradictions and maintenance debt. Keep one canonical deep explanation per topic, and reference it everywhere else.
