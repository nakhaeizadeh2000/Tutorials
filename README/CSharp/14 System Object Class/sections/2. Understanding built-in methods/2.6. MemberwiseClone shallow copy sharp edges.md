## 2.6. `MemberwiseClone` and copying (shallow copy, sharp edges)

1. **What it does** (shallow copy of fields; reference fields still alias the same objects)
2. **Why “clone” is rarely a great public API** (versioning, invariants, identity, deep-copy ambiguity)
3. **Modern alternatives** (immutability, copy constructors, record `with`, explicit snapshot types)

**Big picture**: `MemberwiseClone()` is a `protected` method on `System.Object` that creates a **shallow copy** of the current object. It’s mostly useful as an implementation tool inside a type hierarchy, not as a public “copy me” API.

### 1. **What it does** (shallow copy of fields; reference fields still alias the same objects)

**Definition**

- `MemberwiseClone()` returns a new object instance of the **same runtime type** as `this`.
- It performs a **field-by-field copy**:
  - **Value-type fields** are copied by value.
  - **Reference-type fields** have their **references copied** (so both objects point at the *same* referenced objects).

That’s what “shallow” means: only the top-level object is duplicated, not the entire object graph.

**Example (runnable)**

```csharp
using System;
using System.Collections.Generic;

public sealed class Order
{
    public int Id { get; init; }
    public List<string> Lines { get; } = new();

    public Order ShallowCopy() => (Order)MemberwiseClone(); // legal because we're inside the type
}

static class Demo
{
    static void Main()
    {
        var original = new Order { Id = 1 };
        original.Lines.Add("A");

        var copy = original.ShallowCopy();
        copy.Lines.Add("B"); // modifies the SAME list as original

        Console.WriteLine(ReferenceEquals(original, copy));           // False (different objects)
        Console.WriteLine(ReferenceEquals(original.Lines, copy.Lines)); // True  (same list!)
        Console.WriteLine(string.Join(",", original.Lines));          // A,B
    }
}
```

**Mentor stress**

- Shallow copies are **dangerous** when your object has any mutable referenced state (lists, dictionaries, arrays, other mutable objects). The copy *looks* independent but isn’t.

**Good to know**

- For **immutable** reference graphs (where referenced objects are immutable too), shallow copying is often fine, but then you usually don’t need cloning at all; you can just reuse the instance.

### 2. **Why “clone” is rarely a great public API** (versioning, invariants, identity, deep-copy ambiguity)

Public “clone” APIs tend to produce long-term maintenance pain:

- **Ambiguity**: What does clone mean—shallow or deep? Which fields? What about caches? What about IDs?
- **Invariants**: A clone can accidentally bypass validation or produce illegal intermediate states if the type’s invariants aren’t enforced.
- **Identity confusion**: For entities, identity matters. A clone might accidentally duplicate identity (e.g., `Id`) when it should not.
- **Versioning hazard**: Adding a new field later—should it be cloned? If yes, how? If it’s mutable, you’ve just created a new aliasing bug class.

**Production rule of thumb**

- If callers need *another object with the same data*, prefer explicit APIs like `Copy`, `WithX(...)`, or a copy constructor that documents what happens.
- If callers need *a “snapshot” view* for concurrency or diagnostics, prefer an explicit **snapshot type** (often immutable).

### 3. **Modern alternatives** (immutability, copy constructors, record `with`, explicit snapshot types)

Pick the alternative that matches the intent (and communicates it):

**A) Immutability (often best)**

- Use `record` / `record struct` for value-like types where structural equality is correct.
- Use init-only setters / private setters and keep the object graph immutable.

**B) Copy constructor or factory**

```csharp
public sealed class Customer
{
    public Guid Id { get; }
    public string Name { get; }

    public Customer(Guid id, string name) => (Id, Name) = (id, name);

    public Customer(Customer other) : this(other.Id, other.Name) { }
}
```

This scales because you decide, explicitly, what “copy” means.

**C) Records + `with`**

```csharp
public sealed record User(Guid Id, string Name);

var u1 = new User(Guid.NewGuid(), "A");
var u2 = u1 with { Name = "B" }; // clear intent: create a new value-like instance
```

**D) Snapshot types (great for thread-safety boundaries)**

- When the original object is mutable or shared across threads, create an immutable snapshot DTO/value object:
  - It’s explicit, predictable, and avoids aliasing.

**Performance note**

- Deep copying large graphs can be expensive (CPU + allocations). If you think you need cloning, first ask:
  - “What problem am I solving?” (immutability? concurrency? caching? safe reuse?)
  - Often a better architecture eliminates the need.
