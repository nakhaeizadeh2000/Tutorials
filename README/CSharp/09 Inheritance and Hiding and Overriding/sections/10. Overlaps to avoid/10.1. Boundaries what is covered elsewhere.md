## 10.1. Boundaries: what is covered elsewhere in this repo

1. **OOP big picture (pillars, composition vs inheritance)** is covered in `CSharp Basic Object Oriented Programming` (this domain focuses on inheritance mechanics)
2. **Constructor deep dive** (constructor kinds, object initialization contracts, DI/serialization patterns) is covered in `Constructors`
3. **General method design** (parameters, overload resolution, ref-like patterns, `this` capturing) is covered in `Methods`
4. **Runtime/JIT/GC fundamentals** are covered in `Fundamental Theories`
5. **Threading/memory model** details are covered in `Cuncurrent & Parallel`

---

### 1) **OOP big picture (pillars, composition vs inheritance)** is covered in `CSharp Basic Object Oriented Programming`
This inheritance domain is intentionally **mechanics-heavy**: hiding vs overriding, `base`, `sealed`, override contracts, and versioning hazards.

For the “mindset” topics (what OOP is, when composition wins, and how to think about coupling), treat the OOP domain as canonical:
- See [03 CSharp Basic Object Oriented Programming](<../../../03 CSharp Basic Object Oriented Programming/README.md>)
- In particular, the “composition over inheritance” and “virtual dispatch performance basics” sections.

---

### 2) **Constructor deep dive** is covered in `Constructors`
This domain explains constructor behavior only as far as it impacts inheritance:
- base/derived construction order
- “no virtual calls in constructors”
- selecting base constructor overloads via `base(...)`

For the full treatment (initialization contracts, `required`, primary constructors, DI/serialization/ORM constraints), use:
- [07 Constructors](<../../../07 Constructors/README.md>)

---

### 3) **General method design** is covered in `Methods`
This domain focuses on inheritance-specific dispatch and modifiers.

For general method design and call-site semantics (parameters, overload resolution, `ref` patterns, `this` capturing, and API hygiene), use:
- [05 Methods](<../../../05 Methods/README.md>)

---

### 4) **Runtime/JIT/GC fundamentals** are covered in `Fundamental Theories`
We mention performance trade-offs (virtual dispatch, devirtualization, inlining) only at a practical level.

For how the runtime works (JIT/tiering/PGO/AOT, GC behavior, deployment knobs), use:
- [01 Fundamental Theories](<../../../01 Fundamental Theories/README.md>)

---

### 5) **Threading/memory model** details are covered in `Cuncurrent & Parallel`
Inheritance itself is not a concurrency feature, but inheritance-based designs can accidentally introduce shared mutable state and race conditions.

For the canonical deep explanations of memory visibility, locks, ThreadPool, and async scheduling, use:
- [29 Cuncurrent & Parallel](<../../../29 Cuncurrent & Parallel/README.md>)
