## 6.1. Boundaries: what is covered elsewhere in this repo

1. **Static fields + memory model + safe publication** are covered deeply in `Fields` and `Cuncurrent & Parallel`
2. **Static methods and pure function design** are covered in `Methods`
3. **Namespaces and `using static` / extension method placement** are covered in `Namespaces`
4. **General type system basics (value vs reference, pattern matching)** are covered across `Fundamental Theories` and `CSharp language basics`

---

This domain focuses on **language constructs** and **API design** around:
`partial` types and methods, `static class` usage, and enums (including `[Flags]`).

It intentionally avoids duplicating deep explanations that already exist elsewhere in this repository. Use this section as your “map” when you need the full treatment of adjacent topics.

### 1) **Static fields + memory model + safe publication**

This domain explains *when* static state is a design smell and *how* to keep static initialization predictable at an architectural level (see `3.3`).

For the deep mechanics and correctness rules, go to:

- Static initialization patterns: `README/CSharp/04 Fields/sections/4. Static fields/4.2. Static initialization type constructors Lazy thread-safety.md`
- Memory visibility and the “why” behind safe publication: `README/CSharp/29 Cuncurrent & Parallel/sections/4. Correctness, Testing, Diagnostics & Debugging in Concurrent Code/4.2. .NET memory model and visibility.md`

### 2) **Static methods and pure function design**

This domain covers `static class` and “static as a design choice” (testability, DI boundaries, global state traps).

For method-level guidance (static methods, local functions, capturing, and performance reality), see:

- `README/CSharp/05 Methods/sections/3. Static methods/3.1. Static methods intent testability performance.md`

### 3) **Namespaces, `using static`, and extension method placement**

Static classes are often used as extension method containers. Import mechanics and pitfalls are covered elsewhere:

- `README/CSharp/11 Namespaces/README.md` (especially `using static` and ambiguity pitfalls)

### 4) **Type system basics and pattern matching**

Enums are often paired with `switch` expressions and pattern matching. This domain focuses on **modeling** and **versioning** rather than re-teaching core syntax.

See:

- `README/CSharp/01 Fundamental Theories/README.md`
- `README/CSharp/02 CSharp language basics/README.md`
