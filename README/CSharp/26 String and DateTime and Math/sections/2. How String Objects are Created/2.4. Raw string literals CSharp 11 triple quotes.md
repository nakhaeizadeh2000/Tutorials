## 2.4. Raw string literals (`""" ... """`) — C# 11+

### Why they exist

1. **Embed** JSON, XML, regex, SQL, or multi-line text **without escape-sequence noise**.
2. **Indentation trimming**: common leading whitespace can be stripped—great for readable embedded payloads.

### Correctness

1. **Delimiters**: choose enough `"` characters so the payload can’t prematurely close the literal.
2. **Newlines**: raw strings preserve line breaks—watch for **accidental** trailing spaces in protocols.
3. **Interpolation**: `$"""..."""` combines raw text with holes—keep holes small and side-effect free.

### Performance

1. **Same string allocation model** as normal literals at runtime (interning rules apply similarly to constants).
2. Prefer **one** raw literal over many concatenations when building static templates.

### When not to use

1. Tiny strings where normal `"..."` or verbatim `@""` is clearer.
2. Extremely large embedded assets—consider **resources** or **files** instead of giant literals.
