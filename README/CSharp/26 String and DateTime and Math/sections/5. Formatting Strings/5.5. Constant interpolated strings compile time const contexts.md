## 5.5. Constant interpolated strings (`const string` with interpolation) — C# 10+

### What changed

1. **C# 10** allows **`const string`** built from **interpolated string expressions** when **all holes are compile-time constants**.
2. This is **not** general interpolation at runtime—it’s a **compile-time concatenation** into a single constant.

### Valid patterns (conceptual)

1. Holes must be **`const`**-compatible (typically `const` strings, numeric literals where allowed, etc.).
2. **Culture**: there is **no runtime culture**—it’s compile-time folding (like string literal concatenation).

### What to avoid

1. Don’t confuse with **runtime** interpolated strings (`$"..."`) that call formatting APIs.
2. Don’t expect **custom format providers**—constants don’t execute code at runtime.

### Performance

1. **Zero runtime cost** beyond loading the already-built string literal.
2. Prefer this over manual `+` chains when it improves readability.
