## 7.1. Boundaries: what is covered elsewhere in this repo

1. **GC basics overview** exists in `Fundamental Theories` (this domain goes deeper on finalizers + disposal patterns)
2. **OOP ownership framing** exists in `CSharp Basic Object Oriented Programming` (this domain focuses on correct patterns + runtime costs)
3. **Threading/memory model** is in `Cuncurrent & Parallel` (only referenced here for perf diagnostics and tail latency context)
4. **Interfaces in general** are in `Abstract Classes and Interfaces` (only `IDisposable`/`IAsyncDisposable` specifics live here)

### 1) **GC basics overview**
This domain intentionally does **not** re-teach the full GC fundamentals that already exist elsewhere in this repo (to keep one single “deep” explanation).

- **See also (full treatment)**:
  - `README/CSharp/01 Fundamental Theories/sections/2. NET architecture/2.3. GC basics for app developers.md`

**What this domain adds beyond that**
- How GC behavior changes when you introduce **finalizers** and why that impacts latency/throughput.
- How to design **deterministic cleanup** (`IDisposable`/`IAsyncDisposable`) so you don’t rely on GC/finalization for correctness.

### 2) **OOP ownership framing**
Ownership is an architectural concept: who creates, who disposes, who may share. This domain applies that idea specifically to disposables and finalizers.

- **See also (full treatment)**:
  - `README/CSharp/03 CSharp Basic Object Oriented Programming/sections/2. Creating classes and objects/2.3. Object creation lifetime GC and deterministic cleanup.md`
  - `README/CSharp/01 Fundamental Theories/sections/4. CSharp fundamentals/4.2. Object lifetime and resource management.md`

### 3) **Threading/memory model**
This domain talks about GC/finalizers in performance terms (tail latency, background threads), but it does not teach the full memory model or async scheduling.

- **See also (full treatment)**:
  - `README/CSharp/29 Cuncurrent & Parallel/README.md` (especially the diagnostics/perf sections)

### 4) **Interfaces in general**
`IDisposable` is an interface, but most interface design topics (polymorphism, default interface members, versioning) belong in the interface domain.

- **See also (full treatment)**:
  - `README/CSharp/10 Abstract Classes and Interfaces/README.md`
