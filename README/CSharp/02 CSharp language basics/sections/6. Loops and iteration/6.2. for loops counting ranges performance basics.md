## 6.2. `for` loops (counting, ranges, performance basics)

1. **Counting loops + inclusive/exclusive bounds**
2. **Loop variables, scope, and mutation**
3. **Mentor notes (prefer `for` when index matters; avoid repeated expensive work inside the condition)**

### 1) **Counting loops + inclusive/exclusive bounds**
**Definition**
- A `for` loop is best when you have a *known counting progression*: an index, a range, or explicit bounds.

**Canonical form**

```csharp
for (int i = 0; i < 10; i++)
{
    Console.WriteLine(i);
}
```

**Inclusive vs exclusive bounds**
- Prefer **exclusive upper bounds** (`i < length`) because they match indexing and are harder to get wrong.
- If you truly need inclusive (`i <= max`), name the variable to make it obvious (`maxInclusive`).

```csharp
var numbers = new[] { 10, 20, 30 };
for (var i = 0; i < numbers.Length; i++)
{
    Console.WriteLine(numbers[i]);
}
```

**Common mistakes**
- Off-by-one errors (`<= Length` instead of `< Length`).
- Mutating the counter inside the loop body without a strong reason (makes reasoning harder).

### 2) **Loop variables, scope, and mutation**
**Scope**
- The variable declared in the `for` initializer (`int i = 0`) is scoped to the loop.
- Keep index variables local; don’t reuse them across unrelated loops.

**Mutation and correctness**
- Avoid mutating the collection you are iterating over in ways that shift indices (removal/insert). It’s a bug magnet.
- If you must remove items in-place, iterate backwards or create a new collection.

```csharp
var list = new List<int> { 1, 2, 3, 4, 5 };
for (var i = list.Count - 1; i >= 0; i--)
{
    if (list[i] % 2 == 0)
        list.RemoveAt(i);
}
```

**Good to know**
- `for` is often a good fit when you need to write to `array[i]` or `span[i]` by index.

### 3) **Mentor notes (index matters, avoid repeated expensive work)**
**Avoid repeated expensive work in the condition**
- This is about correctness and clarity first; performance improvements follow naturally.

```csharp
// Fine:
for (var i = 0; i < text.Length; i++)
{
    // ...
}

// If the condition calls something expensive (DB, I/O, LINQ materialization), cache it:
var n = items.Count; // O(1) for List<T>, not necessarily for all types
for (var i = 0; i < n; i++)
{
    // ...
}
```

**Choose the right loop**
- Use `for` when:
  - you need the index,
  - you mutate by index,
  - bounds must be explicit.
- Use `foreach` when index doesn’t matter; it’s usually the clearest.

Performance note:
- In modern .NET, the performance difference between `for` and `foreach` is often small for arrays and `List<T>`.
- Don’t micro-optimize loop syntax; optimize algorithmic complexity and allocations first (see [6.3](<./6.3. Nested loops correctness first then complexity.md>) for nested-loop pitfalls).
