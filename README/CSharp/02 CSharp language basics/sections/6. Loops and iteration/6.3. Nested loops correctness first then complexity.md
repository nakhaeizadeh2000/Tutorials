## 6.3. Nested loops (correctness first, then complexity)

1. **Examples: grids, tables, and pairwise comparisons**
2. **Big-O intuition (why nested loops can explode)**
3. **Performance notes (break early, reduce allocations, consider better data structures)**

### 1) **Examples: grids, tables, and pairwise comparisons**
**Grid / matrix traversal**

```csharp
for (var row = 0; row < height; row++)
{
    for (var col = 0; col < width; col++)
    {
        // Process cell (row, col)
    }
}
```

**Pairwise comparisons (common beginner trap)**

```csharp
for (var i = 0; i < items.Length; i++)
{
    for (var j = i + 1; j < items.Length; j++)
    {
        // Compare items[i] and items[j] once
    }
}
```

**Mentor note**
- Use `j = i + 1` for pairwise comparisons to avoid duplicate work (`A vs B` and `B vs A`) and self-comparisons.

### 2) **Big-O intuition (why nested loops can explode)**
**The growth problem**
- A single loop over \(n\) items is typically \(O(n)\).
- A nested loop that visits all pairs is typically \(O(n^2)\).

**Concrete feel**
- If \(n = 1,000\), then \(n^2 = 1,000,000\).
- If \(n = 100,000\), then \(n^2 = 10,000,000,000\) (usually too slow).

### 3) **Performance notes (break early, reduce allocations, consider better data structures)**
**Break early**
- If you’re searching for “first match”, don’t scan the whole grid/list.

```csharp
var found = false;
for (var i = 0; i < items.Length && !found; i++)
{
    for (var j = 0; j < items.Length; j++)
    {
        if (items[i] == items[j])
        {
            found = true;
            break;
        }
    }
}
```

Note:
- For `break` and `continue` semantics and best practices, see **[7.1](<../7. Jump statements and flow control/7.1. break and continue clean exits fewer bugs.md>)**:
  - [7.1. break and continue clean exits fewer bugs](<../7. Jump statements and flow control/7.1. break and continue clean exits fewer bugs.md>)

**Avoid hidden work in the inner loop**
- Don’t allocate or format strings repeatedly in the inner loop unless you must.
- Don’t call expensive methods repeatedly if the result is the same for the outer-loop iteration (cache it).

**Consider better data structures**
- Many “nested loop” tasks can become \(O(n)\) or \(O(n \log n)\) with:
  - `HashSet<T>` for membership checks
  - `Dictionary<TKey, TValue>` for lookups
  - sorting + two-pointer techniques

**Mentor rule**
- If you see nested loops and your input can grow, ask: “Is this inherently \(O(n^2)\), or am I missing a better approach?”
