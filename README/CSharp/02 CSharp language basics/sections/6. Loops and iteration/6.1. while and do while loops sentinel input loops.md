## 6.1. `while` and `do/while` loops (sentinel, input loops)

1. **When to use `while` vs `do/while`**
2. **Input-validation loops (including null/empty handling)**
3. **Common pitfalls (infinite loops, off-by-one, modifying loop conditions incorrectly)**

### 1) **When to use `while` vs `do/while`**
**`while` (zero-or-more iterations)**
- Use `while` when the loop body might need to run **zero times**.
- It’s a natural fit for sentinel logic: “keep going while the world still makes sense”.

```csharp
var i = 0;
while (i < 3)
{
    Console.WriteLine(i);
    i++;
}
```

**`do/while` (one-or-more iterations)**
- Use `do/while` when the first attempt should always happen (prompt once, then repeat).

```csharp
int attempts = 0;
string? input;

do
{
    attempts++;
    input = ReadCommand();
} while (string.IsNullOrWhiteSpace(input) && attempts < 3);

static string? ReadCommand() => "run";
```

**Trade-off**
- `do/while` can hide the exit condition at the end; if that makes the loop harder to audit, prefer an explicit `while (true)` with clear `break` points.

### 2) **Input-validation loops (including null/empty handling)**
**Mentor rule**
- Console input is untrusted. Validate at the boundary and keep core logic typed.

This file doesn’t re-teach parsing/culture in depth. For canonical `TryParse` patterns and culture decisions, see **`2.1`**:
- `README/CSharp/02 CSharp language basics/sections/2. Console I-O/2.1. The System.Console class input output formatting.md`

**Pattern: loop until valid or quit**

```csharp
while (true)
{
    Console.Write("Age (empty = quit): ");
    var line = Console.ReadLine();

    if (string.IsNullOrEmpty(line))
        break;

    if (!int.TryParse(line, out var age) || age is < 0 or > 130)
    {
        Console.WriteLine("Invalid age.");
        continue;
    }

    Console.WriteLine($"Accepted: {age}");
    break;
}
```

Performance note:
- Avoid doing expensive work before validation. Validate first, then compute.

### 3) **Common pitfalls (and how to avoid them)**
**Infinite loops**
- Ensure the condition can change, or make exits explicit and easy to see (`break`, `return`).

**Off-by-one**
- `while` is excellent for sentinel loops. For counting/indexing, `for` is often clearer (see `6.2`).

**Modifying loop conditions indirectly**
- Keep the condition simple. Prefer:
  - compute state in the body
  - `continue` on invalid cases
  - `break` when done

**Hidden I/O**
- Avoid calling I/O in the condition (e.g. `while ((line = Console.ReadLine()) != null)`) in beginner code. It’s compact but harder to debug.
