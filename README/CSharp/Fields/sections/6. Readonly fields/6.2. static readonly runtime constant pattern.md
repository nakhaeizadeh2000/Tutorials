## 6.2. `static readonly`: the “runtime constant” pattern

1. **Why it exists** (values not allowed in const: `Guid`, `DateTime`, complex objects, arrays)
2. **Initialization** (static initializer or static ctor; thread-safe publication semantics)
3. **Performance** (one-time allocation; beware large graphs retained for process lifetime)

---

### 1) **Why it exists**
`const` is a **compile-time constant**: the compiler substitutes the literal value into consuming code. That is only possible for a restricted set of types (primitives, `string`, enums, and `null`).

So when you need a value that is *logically constant* but **not** a compile-time constant, you use `static readonly`:

- `Guid`, `DateTime`, `TimeSpan` (and other structs that need constructor logic)
- prebuilt `Regex` instances
- comparer instances (`StringComparer.Ordinal`, etc.)
- immutable collections (`ImmutableArray<T>`, etc.)

**Mentor emphasis**
- `static readonly` is the correct default for **public library constants** that might change, because consumers won’t have the `const` inlining/versioning trap.

---

### 2) **Initialization**
Static initialization is guaranteed to run **once** and be **thread-safe**.

**Preferred: simple static field initializer**

```csharp
using System;

public static class WellKnown
{
    public static readonly Guid TenantId = new("9f1aeb8b-2b43-4f0c-8a1b-8a0f9f5b9e42");
}
```

**Prefer explicit lazy only when needed**
- If creation is expensive and might not be used, prefer `Lazy<T>` (see `README/CSharp/Fields/sections/4. Static fields/4.2. Static initialization type constructors Lazy thread-safety.md`).

**Avoid**
- Doing I/O in static initialization (network/file/DB).
- Blocking on async (`.Result`, `.Wait()`), especially in ASP.NET Core. That can deadlock or create thread-pool starvation.

---

### 3) **Performance**
`static readonly` typically means:
- one-time allocation (if it’s a reference type) or one-time struct initialization,
- then a stable reference/value for the process lifetime.

**Memory note**
- Anything referenced by a static field is strongly rooted for the lifetime of the load context. Keep large graphs bounded; avoid unbounded static caches.

**Good to know**
- For small immutable objects used everywhere (comparers, options, sentinel values), `static readonly` is often both **clean** and **fast**.
