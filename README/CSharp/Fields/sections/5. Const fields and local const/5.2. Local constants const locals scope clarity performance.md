## 5.2. Local constants (`const` locals): scope, clarity, and performance

1. **When it helps** (naming magic numbers, making intent explicit, keeping expressions readable)
2. **Scope discipline** (smallest possible scope beats “constants at top of file”)
3. **Perf reality** (compile-time substitution; choose for readability/maintainability first)

---

### 1) **When it helps**
Local constants are an underrated readability tool. They’re most useful when they:

- remove “magic numbers”,
- give a domain name to a threshold or multiplier,
- reduce cognitive load in a long expression,
- and keep the meaning close to the usage.

**Example: name a policy value**

```csharp
using System;

public static class Program
{
    public static void Main()
    {
        const int maxRetries = 3;

        for (var attempt = 1; attempt <= maxRetries; attempt++)
        {
            Console.WriteLine($"Attempt {attempt}/{maxRetries}");
        }
    }
}
```

**Mentor emphasis**
- A local `const` should represent a **stable rule**, not a tuning knob you expect to change frequently.
  - If it’s a tuning knob, it likely belongs in configuration, options, or a `static readonly` “defaults” holder (see section **6.2** for runtime constants).

---

### 2) **Scope discipline**
Prefer the **smallest scope** that preserves clarity.

- If a constant is used once or twice inside a method, keep it **inside the method**.
- If it’s used across multiple methods in the same type, consider a **private `const` field** (or `static readonly` when `const` is not valid).
- If it’s public and part of a contract, be careful: public constants have versioning implications (see section **5.1**).

**Common mistake**
- Putting “constants” at the top of the file “just because”—this increases distance from usage and makes refactors harder.

---

### 3) **Perf reality**
For primitives and strings, local `const` values are **compile-time substituted**.

- There’s no runtime storage lookup for `const`.
- There’s no allocation caused by `const` itself.

**Performance note**
- Choose local constants for **readability** first. The performance win is usually negligible compared to the wins from:
  - avoiding allocations,
  - avoiding locks/contention,
  - and keeping hot-path code simple.
