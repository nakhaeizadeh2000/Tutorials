## 7.5. Aggregation composition: don't accidentally enumerate multiple times

1. **Each terminal call enumerates**: `Count()`, then `Sum()`, then `Average()` will enumerate repeatedly unless you materialize results once.
2. **Materialize only when needed**: `ToArray`/`ToList` can trade RAM for fewer CPU passes; the right choice depends on sequence cost and size.

---

### 1. **Problem pattern**

```csharp
using System.Linq;

IEnumerable<int> xs = GetRows(); // cold enumerable
if (xs.Count() > 0 && xs.Sum() > 100) { /* ... */ }
```

Two full passes (plus iterator overhead).

---

### 2. **Fixes**

- **Materialize once:** `var m = xs.ToArray();` then aggregate on `m`.
- **Single pass manually:** `foreach` accumulating sum and count together.
- **Use a dedicated reducer** if you need many statistics in one scan.

---

### 3. **When not to materialize**

Small, cheap sequences (in-memory lists) where readability matters and profiling shows no issue.

**Performance note:** materialization is **O(n) time + O(n) memory**; skipping it for multiple terminals can be **O(k·n) time + O(1) extra**—pick based on **`n`** and **measurement**.

**Threading:** materialization gives a **snapshot**; concurrent mutations to underlying mutable collections during enumeration remain unsafe—copy or lock per *Collections* guidance.
