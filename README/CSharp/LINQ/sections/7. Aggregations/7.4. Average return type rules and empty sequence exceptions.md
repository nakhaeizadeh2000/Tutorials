## 7.4. Average: return type rules and empty-sequence exceptions

1. **Average returns floating-point**: for integer inputs, `Average` produces `double` (or `decimal` for `IEnumerable<decimal>` overloads).
2. **Empty sequence throws**: `Average` throws `InvalidOperationException` on empty sequences.
3. **Selector overload costs**: `Average(x => selector(x))` may allocate if the selector creates objects; keep selector work minimal for performance.

---

### 1. **Return types**

- **`int`/`long`** sources → **`double`** average (unless you use **`decimal`** path).
- **`decimal`** sources → **`decimal`** average.

This widening avoids integer division mistakes but introduces **floating-point** semantics for `double`.

---

### 2. **Empty input**

**Throws** `InvalidOperationException`. Unlike `Sum` on some overloads, there is no “default average.”

---

### 3. **Selectors**

`Average(x => x.SubTotal)` evaluates the selector **once per element**—keep it cheap.

```csharp
using System;
using System.Linq;

double a = new[] { 1, 2, 3 }.Average();
try { _ = Array.Empty<int>().Average(); }
catch (InvalidOperationException) { /* empty */ }
```

**Performance note:** single pass, **O(1)** extra memory; combined with **`Where`**, watch for **double enumeration** if you also compute `Count` separately—consider one manual loop for extreme hot paths.
