## 6.2. Select with index: when position matters

1. **Overload includes index**: `source.Select((item, index) => ...)` lets you derive values based on position.
2. **Avoid relying on "materialized index" timing**: index is based on enumeration order; re-enumerating can produce different indices if the source ordering changes.

---

### 1. **API shape**

The overload passes **`index`** starting at **0** in enumeration order—not the original collection’s index unless the source preserves that order without intervening reordering operators.

---

### 2. **Correctness caveats**

If you **`OrderBy`** before `Select` with index, the index reflects **sorted** order, not the source’s pre-sort order. Document which ordering you mean in APIs that expose “index.”

---

### 3. **Use cases**

- Adding **row numbers** for display **(frontend)** or reporting.
- Zip-like scenarios without allocating pairs (sometimes **`Zip`** is clearer).

```csharp
using System.Linq;

var withRank = new[] { "a", "b", "c" }.Select((s, i) => $"{i}:{s}");
```

**Performance note:** index is a cheap `int`; the cost is still dominated by enumeration and selector work.
