## 3.1. First: short-circuiting and exception behavior

1. **Short-circuit enumeration**: `First` stops at the first matching element, which can be CPU-friendly for "find first" scenarios.
2. **Empty sequence throws**: `First` throws `InvalidOperationException` when there are no elements (or no matching elements for the predicate overload).
3. **Predicate overloads still stream**: `source.First(x => predicate(x))` can stop early once the predicate matches.
4. **Side effects matter**: because evaluation is deferred and short-circuiting, your predicate may run fewer times than you expect (especially in tests or when re-enumerating).

---

### 1. **Short-circuit semantics**

`First()` advances the enumerator until it obtains one element, then stops. For expensive sequences, that can save most of the work versus `ToList()[0]`.

---

### 2. **Exceptions**

- No elements / no match → **`InvalidOperationException`** with a message like “Sequence contains no matching element.”
- Design choice: use **`First`** when absence is a **bug**; use **`FirstOrDefault`** when absence is **valid** (see §3.2).

---

### 3. **Predicate form**

`First(predicate)` still short-circuits on the **first** match. It may still scan the whole sequence if no match exists.

---

### 4. **Testing and side effects**

Unit tests that assert “predicate called N times” are fragile under refactoring or provider differences. Prefer **pure** predicates for LINQ.

```csharp
using System;
using System.Linq;

var xs = Enumerable.Range(0, 1_000_000);
int calls = 0;
_ = xs.First(x => { calls++; return x > 10; });
Console.WriteLine(calls); // 12, not 1_000_000
```

**Performance note:** short-circuit helps **CPU**; iterator allocation still applies. In nanosecond-scale hot loops, a raw `for` may win—measure.
