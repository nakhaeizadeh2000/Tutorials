## 4.2. ElementAt vs ElementAtOrDefault: exceptions and bounds

1. **ElementAt throws**: `ElementAt` throws `ArgumentOutOfRangeException` when index is out of bounds (or negative).
2. **ElementAtOrDefault returns default**: `ElementAtOrDefault` returns `default(T)` for out-of-range/negative indices.
3. **Default ambiguity remains**: the same "default means not found" caveat applies to value types.

---

### 1. **`ElementAt`**

Throws **`ArgumentOutOfRangeException`** if `index < 0` or the sequence has fewer than `index + 1` elements. This is stricter than `First` (which uses `InvalidOperationException`)—be consistent in exception handling in your app layer.

---

### 2. **`ElementAtOrDefault`**

Returns **`default(T)`** for invalid indices without throwing. For **`int`**, index `-1` still yields **`0`** result default—not an exception—so validate **`index >= 0`** at API boundaries.

---

### 3. **Value types**

Same guidance as §1.2 and §3.2: if `0` is valid data, **`ElementAtOrDefault`** is a poor “TryGet by index” story; use explicit checks or `T?`.

```csharp
using System;
using System.Linq;

var xs = new[] { 10, 20, 30 };
try
{
    _ = xs.ElementAt(10);
}
catch (ArgumentOutOfRangeException)
{
    // expected
}

int d = xs.ElementAtOrDefault(10); // 0 — indistinguishable from "found 0" if it existed
```

**Performance note:** cost is still **`O(index)`** on non-random-access sequences.
