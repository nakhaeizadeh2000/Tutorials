## 5.2. SingleOrDefault: "0 or 1" with defaulting

1. **Empty means default(T)**: `SingleOrDefault` does not throw on "not found", but still throws if more than one element matches.
2. **Value-type ambiguity**: if `default(T)` can be a legitimate value, represent "not found" explicitly instead of relying on `SingleOrDefault`.

---

### 1. **Semantics**

- **0 matches** → return **`default(T)`** (no throw).
- **1 match** → return that element.
- **2+ matches** → **`InvalidOperationException`**.

This differs from **`FirstOrDefault`**, which returns the first of many.

---

### 2. **Choosing operators**

| Intent | Operator |
|--------|----------|
| Must exist exactly one | `Single` |
| Zero or one expected | `SingleOrDefault` |
| Any first of many OK | `First` / `FirstOrDefault` |

---

### 3. **Nullable and API design**

For reference types, **`null`** usually means “none.” For value types, mirror §1.2: use **`T?`**, tuples, or **`TryGet`**.

```csharp
using System.Linq;

string? tag = new[] { "prod" }.SingleOrDefault(); // "prod"
string? none = Array.Empty<string>().SingleOrDefault(); // null
```

**Performance note:** worst case still **O(n)** to confirm uniqueness when only one tail element matches.
