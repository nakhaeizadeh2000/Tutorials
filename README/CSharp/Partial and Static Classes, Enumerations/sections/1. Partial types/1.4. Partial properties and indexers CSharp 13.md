## 1.4. Partial properties and partial indexers (C# 13+)

### What it is

1. **`partial` properties** and **`partial` indexers** split declaration vs implementation across files—same spirit as partial methods, but for property/indexer bodies.
2. Typical use: **source generators** + hand-written parts; or separating generated vs human-owned code.

### Rules (mental model)

1. **One declaring** part and **one implementing** part (signature must match).
2. You generally **cannot** implement a partial property with a trivial auto-property body on the implementing side in the same way as partial methods—follow compiler errors and the language reference for your SDK version.

### Design guidance

1. Keep **public surface** discoverable—don’t scatter properties across many files without a clear “owner” file.
2. Prefer partials for **generated** boundaries, not as a substitute for cohesion.

### Performance

1. No runtime dispatch difference vs normal properties—this is a **compile-time composition** feature.
2. Still avoid expensive work in **getters**; validate at boundaries.
