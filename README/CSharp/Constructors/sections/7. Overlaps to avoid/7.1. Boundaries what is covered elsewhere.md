## 7.1. Boundaries: what is covered elsewhere in this repo

### 1) Overlaps to avoid (so this domain stays focused)
- Static initialization patterns, `Lazy<T>`, `beforefieldinit`, memory visibility → **`README/CSharp/Fields`**
- OOP fundamentals, invariants, “valid states only”, factories vs constructors (big picture) → **`README/CSharp/CSharp Basic Object Oriented Programming`**
- Overload resolution mechanics, optional parameters, `params`, named arguments → **`README/CSharp/Methods`**
- Threading, synchronization, publication, memory model deep dives → **`README/CSharp/Cuncurrent & Parallel`**
- Runtime/GC/JIT/AOT framing and system-level performance → **`README/CSharp/Fundamental Theories`**

### 2) What *this* Constructors domain owns
- Constructor kinds (instance/static/primary) and their semantics
- Initialization order and correctness hazards
- Designing constructor sets: overloading, chaining, consistent invariants
- Object initializers vs constructors vs `required`/`init` trade-offs
- Framework integration boundaries (DI/serialization/ORM) without weakening your domain model

### 3) Practical rule (mentor-grade)
- If a topic is about **“how state is stored”** → it’s probably `Fields`
- If it’s about **“how objects model the world”** → it’s probably OOP domain
- If it’s about **“call-site syntax and parameter passing”** → it’s probably `Methods`
