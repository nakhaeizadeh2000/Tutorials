## 3.3. Copy constructors and cloning patterns (safe copying without surprises)

1. **Copy intent and API contract**
   - When to provide a copy constructor vs a `Clone`-style method vs “no copying at all”
   - Copying as an invariant boundary (what must remain true in the copy)
   - Make sharing vs copying explicit (call-site clarity)

2. **Shallow vs deep copy (and the traps)**
   - Shallow copy: references copied, graph shared (aliasing risks)
   - Deep copy: cycles, identity loss, shared subgraphs, and performance blow-ups
   - Prefer immutability to avoid needing deep copies

3. **Modern alternatives (C# 15 era)**
   - Records: `with` expressions and value-like copying semantics
   - Explicit “copy-with-changes” APIs (named parameters / builder / factory) when invariants matter
   - “Snapshot” vs “live view” designs (choose intentionally)

4. **Performance notes**
   - Copying large graphs and allocation pressure (GC impact)
   - Defensive copying vs trust boundaries (public API design)
   - Pools/caches: only when measured and bounded (avoid unbounded retention)
