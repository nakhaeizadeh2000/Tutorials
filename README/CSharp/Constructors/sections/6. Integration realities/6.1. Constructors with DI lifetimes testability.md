# 6.1. Constructors with Dependency Injection (DI): correct lifetimes and testability

## What this section covers
- **Constructor injection** as the default (clear dependencies, testability, invariants)
- **Lifetime correctness** (transient/scoped/singleton) and common capture bugs
- **Design boundaries** (domain types vs application services; avoid service locator)

## Key concepts and vocabulary
- **Composition root**
- **Constructor injection** vs property injection vs method injection
- **Captive dependency**
- **Scoped service** vs singleton vs transient

## Best practices (C# 15 era)
- Prefer **explicit dependencies** in constructors (and keep them minimal)
- Validate invariants in constructors; avoid work with **environmental failure modes** (I/O)
- Use **factories** when creation is async or needs complex policies

## Common pitfalls and how to avoid them
- Singleton capturing scoped services (captive dependency)
- Over-injecting (“god constructor”) and how to refactor
- Static/global dependencies hidden behind constructors

## Performance notes
- DI is rarely the bottleneck; focus on **allocations, I/O, caching, and hot paths**
- Avoid per-request expensive initialization hidden in constructors
