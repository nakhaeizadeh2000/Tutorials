# 5.3. Thread-safety and publication: when constructed objects become visible to other threads

## Outline

### 1) Safe publication (the minimum you must know)
- What “publishing an object” means (who can see it, when)
- Don’t let partially constructed objects escape
- Immutable objects are easiest to publish safely

### 2) Common escape paths during construction (bugs)
- Registering `this` into a static cache/event bus inside a constructor
- Starting background work that captures `this` during construction
- Passing `this` to other objects that can call back immediately

### 3) Synchronization tools (overview only; deep dive elsewhere)
- `lock`, `Volatile`, `Interlocked`, concurrent collections
- Avoid DIY double-checked locking patterns unless you fully understand memory ordering

### 4) Performance framing
- Contention and cache-line ping-pong
- Prefer “make it immutable” over “add locks everywhere”

### 5) Where to learn more (repo boundary)
- `Cuncurrent & Parallel` for memory model + synchronization
- `Fields` for static publication and initialization order
