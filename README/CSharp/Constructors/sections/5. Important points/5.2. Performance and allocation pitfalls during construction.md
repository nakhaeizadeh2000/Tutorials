# 5.2. Performance and allocation pitfalls during construction

## What to watch (the short list)
- Hidden allocations in constructors
- Object graph size and “constructor does too much”
- Static/type initialization first-touch costs

## Common hidden allocations
- Lambdas/closures capturing `this`
- `params` arrays (especially on hot paths)
- LINQ in constructors
- String concatenation / interpolation in hot paths

## Design rules for performance
- Keep constructors cheap and predictable
- Move expensive work behind explicit methods (and cache intentionally)
- Prefer immutable initialization when possible (reduces defensive copies and synchronization later)

## Measuring guidance
- Separate cold-start vs steady-state
- Profile allocations (Gen0 churn) and p99 latency
- Don’t optimize “field vs property”; focus on allocations and I/O
