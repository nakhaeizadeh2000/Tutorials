## 2.3. The `field` keyword: compiler-synthesized backing fields in property accessors (C# 13 preview → C# 14+)

### What it is

1. **`field`** is a **contextual keyword** usable inside property accessors to refer to the **compiler-generated backing storage**.
2. It removes boilerplate `_backing` fields when only **one accessor** needs custom logic.

### Example shape (conceptual)

```csharp
public string Message
{
    get;
    set => field = value ?? throw new ArgumentNullException(nameof(value));
}
```

### Correctness

1. **Naming collision**: if a real member is named `field`, disambiguate with `@field` or `this.field` per language rules.
2. **Validation**: keep **expensive work** out of hot accessors—validate at boundaries.

### Versioning note

1. **`field` appeared as a preview** in C# 13 workflows; **finalize** behavior against your **SDK/language version** in CI.
2. Treat accessor bodies as **public contract**—exceptions and side effects should be intentional.

### Performance

1. Same as normal auto-properties when accessors are trivial (JIT can inline).
2. Avoid **locking** in properties unless you’ve documented thread-safety and measured contention.
