This Properties/Indexers domain teaches the *property-first* mental model and the patterns you’ll use in real code, but the full deep comparison of **fields vs properties vs methods** (including binary compatibility/versioning implications) lives elsewhere to avoid duplication.

See for the full treatment:
- `README/CSharp/CSharp Basic Object Oriented Programming/sections/2. Creating classes and objects/2.1. Defining a class fields vs properties vs methods.md`
- `README/CSharp/Fields/sections/1. Field fundamentals/1.3. Fields vs properties boundary and intent.md` (field-focused boundary summary)

Good to know:
- In libraries, **public mutable fields** are almost always a long-term mistake.
- In modern .NET, trivial properties are usually inlined; pick **properties for API design**, not for micro-optimizing.

### 2) **Method-level API design & overloads**
Whenever a “property” would:
- do non-trivial work,
- fail in normal ways,
- or represent an *action*,
prefer a **method** (often with a Try-pattern) instead of hiding behavior behind a `get`/`set`.

See for the full treatment:
- `README/CSharp/Methods/README.md` (domain index)
- `README/CSharp/Methods/sections/1. Method fundamentals/1.2. Encapsulation with methods invariants boundaries.md` (invariants at boundaries)
- `README/CSharp/Methods/sections/6. Parameter modifiers and ref-like patterns/6.3. out parameters multiple returns Try patterns.md` (Try-pattern)
- `README/CSharp/Methods/sections/6. Parameter modifiers and ref-like patterns/6.6. ref returns returning by reference safely.md` (ref returns; relevant to advanced indexers)

Performance note:
- Avoid using exceptions for expected control flow (costly under load). Try-patterns scale better and are easier to reason about.

### 4) **Threading & synchronization**
Properties and indexers do **not** make shared state thread-safe. If state can be accessed concurrently, you must define and implement a synchronization/immutability policy.

See for the full treatment:
- `README/CSharp/Cuncurrent & Parallel/README.md`

Mentor reminder:
- If you find yourself taking locks in getters/setters, reconsider the API shape. Often the correct design is “explicit method does the work” or “immutable snapshot”.
