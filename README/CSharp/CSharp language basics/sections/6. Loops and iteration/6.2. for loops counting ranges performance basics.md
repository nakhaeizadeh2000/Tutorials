## 6.2. `for` loops (counting, ranges, performance basics)

1. **Counting loops + inclusive/exclusive bounds**
2. **Loop variables, scope, and mutation**
3. **Mentor notes (prefer `for` when index matters; avoid repeated expensive work inside the condition)**

### 1) **Counting loops**
**The canonical form**

```csharp
for (int i = 0; i < 10; i++)
{
    Console.WriteLine(i);
}
```

**Inclusive vs exclusive bounds (bug factory)**
- Prefer **exclusive upper bounds** (`i < length`) because they match array/string indexing.
- If you truly need inclusive (`i <= max`), name it so it’s obvious.

```csharp
var numbers = new[] { 10, 20, 30 };
for (var i = 0; i < numbers.Length; i++)
{
    Console.WriteLine(numbers[i]);
}
```

### 2) **Loop variables, scope, and mutation**
**Scope**
- The variable declared in the `for` initializer (`int i = 0`) is scoped to the loop.
- Keep index variables local; don’t reuse them across unrelated loops.

**Mutation and correctness**
- Avoid mutating the collection you are iterating over (especially with `for` where indices can shift).
- If you must remove items, iterate backwards or build a new collection.

```csharp
var list = new List<int> { 1, 2, 3, 4, 5 };
for (var i = list.Count - 1; i >= 0; i--)
{
    if (list[i] % 2 == 0)
        list.RemoveAt(i);
}
```

### 3) **Performance basics (real wins, not myths)**
**Avoid repeated expensive work in the condition**
- This is more about correctness and clarity than micro-optimizing:

```csharp
// Fine:
for (var i = 0; i < text.Length; i++)
{
    // ...
}

// If the condition calls something expensive (DB, I/O, LINQ materialization), cache it:
var n = items.Count; // O(1) for List<T>, not necessarily for all types
for (var i = 0; i < n; i++)
{
    // ...
}
```

**Choose the right loop**
- Use `for` when:
  - you need the index,
  - you need to mutate by index,
  - you want explicit boundaries.
- Use `foreach` for readability when index doesn’t matter (it’s often as fast, and sometimes safer).
