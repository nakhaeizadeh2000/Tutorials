## 6.1. `while` and `do/while` loops (sentinel, input loops)

1. **When to use `while` vs `do/while`**
2. **Input-validation loops (including null/empty handling)**
3. **Common pitfalls (infinite loops, off-by-one, modifying loop conditions incorrectly)**

### 1) **`while` vs `do/while`**
**`while`**
- Checks the condition *before* the body runs.
- Use it when the body might need to run **zero times**.

```csharp
while (true)
{
    // ...
    break;
}
```

**`do/while`**
- Runs the body **at least once**, then checks the condition.
- Use it when the “first attempt” should always happen (prompt once, then repeat on invalid input).

```csharp
string? input;
do
{
    Console.Write("Enter command: ");
    input = Console.ReadLine();
} while (string.IsNullOrWhiteSpace(input));
```

### 2) **Input-validation loops (the real beginner use case)**
**Goal**
- Don’t crash on bad input.
- Don’t use exceptions as normal control flow.
- Handle end-of-input (`null`) cleanly.

```csharp
while (true)
{
    Console.Write("Age (or empty to quit): ");
    var line = Console.ReadLine();

    if (line is null || line.Length == 0)
        break;

    if (int.TryParse(line, out var age) && age is >= 0 and <= 130)
    {
        Console.WriteLine($"Accepted age: {age}");
        break;
    }

    Console.WriteLine("Invalid age. Try again.");
}
```

### 3) **Common pitfalls (and how to avoid them)**
**Infinite loops**
- Always ensure the loop condition can change, or the loop has a clear exit (`break`, `return`).

**Off-by-one**
- When counting or indexing, prefer `for`. `while` loops are excellent for sentinel / “keep going until X” logic.

**Mutating the condition in confusing ways**
- Keep the condition simple; move complex logic into the body with clear `if` checks.
