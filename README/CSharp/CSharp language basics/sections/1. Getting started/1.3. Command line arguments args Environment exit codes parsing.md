## 1.3. Command line arguments (`args`), `Environment`, exit codes, and parsing (C# 15 era)

### Mental model

1. **Entry point contract**: `static void Main(string[] args)` or top-level statements receive **`string[] args`** (never null; may be empty).
2. **What `args` contains**: tokens after the program name—splitting rules depend on the **host shell/OS** (quoting, escaping, Unicode).
3. **Not in `args`**: everything else lives in **`Environment`** (process path, working directory, env vars, special folders).

---

### `args` in practice

1. **Indexing**: `args[0]` is the first argument; guard `args.Length` before access.
2. **Culture / encoding**: arguments are **`string`** in UTF-16; file paths may need normalization (`Path` APIs).
3. **No standard for flags**: `-x`, `/x`, `--x` are conventions—you must define and document them.

**Good to know (perf + correctness)**:

- Avoid parsing `args` in hot paths—parse **once** at startup into a small immutable options object.
- Prefer **structured logging** of raw `args` carefully (may contain secrets).

---

### Exit codes

1. **`Environment.ExitCode`** / `main` return `int` (when using `Main` with `int` return): communicate success/failure to scripts and CI.
2. **Convention**: `0` = success, non-zero = failure (pick a small stable scheme for your CLI).
3. **Do not** use exceptions for normal “usage error” in CLIs; print help and return non-zero.

---

### When `args` is not enough

1. **`Environment.GetCommandLineArgs()`**: returns the full argv vector including the program name at `args[0]` (sometimes useful for diagnostics).
2. **`Environment.ProcessPath`**: path to the running executable (not the same as `args[0]` semantics on all hosts).
3. **Modern apps**: ASP.NET, Windows Services, and containers often use **configuration + env vars**—`args` is only for true CLI tools.

---

### Parsing libraries (mentor default)

1. **Small tools**: manual parsing with `switch` / `switch` expressions is fine.
2. **Growing CLI**: use a **dedicated parser** (e.g. `System.CommandLine` or community packages)—you get help text, `--` handling, and testability.
3. **Avoid** ad-hoc global mutable static state for “current options”; pass options explicitly (testability + thread-safety).
