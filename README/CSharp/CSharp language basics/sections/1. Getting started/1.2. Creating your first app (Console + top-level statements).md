## 1.2. Creating your first app (Console + top-level statements)

1. **Two ways: Visual Studio vs `dotnet new console` (same result, different workflow)**
2. **Top-level statements vs explicit `Main` (what the compiler generates)**
3. **Good defaults (nullable enabled, implicit usings, predictable entry point)**

### 1) **Two ways to create the same app**
**Visual Studio (IDE-first)**
- Create a new project → **Console App** (C#) → choose a modern target framework.
- Good when you want integrated debugging, profiles, and solution navigation.

**dotnet CLI (workflow-first)**

```bash
dotnet new console -n HelloBasics
cd HelloBasics
dotnet run
```

**Mentor note**
- IDE vs CLI is not a “better/worse” debate. You should be comfortable with both because CI/CD and containers are CLI-first.

### 2) **Top-level statements vs explicit `Main`**
**Top-level statements (default template)**

```csharp
Console.WriteLine("Hello, world!");
```

**What the compiler does (conceptual)**
- It generates a `Program` type with an entry point and puts your statements inside it.
- For beginner code, this reduces ceremony. For larger apps, you’ll typically move to explicit methods/types quickly.

**Explicit `Main` (when you want the shape to be obvious)**

```csharp
public static class Program
{
    public static int Main(string[] args)
    {
        Console.WriteLine("Hello, world!");
        return 0;
    }
}
```

**Good to know**
- Top-level statements still allow you to write functions (local functions) and define types in the same file, but don’t let a single file become a “dumping ground”.

### 3) **Good defaults for modern C#**
**Compiler + project defaults (what you want on by default)**
- **Nullable reference types** enabled (prevents a huge class of runtime null bugs).
- **Implicit global usings** enabled (cleaner code in small projects; you can disable if you prefer explicitness in teaching materials).
- Treat warnings as actionable feedback (don’t normalize warning spam).

**Input + parsing**
- If the app reads user input, start with `TryParse` patterns (avoid exceptions for normal control flow).

**Performance framing (beginner-friendly, real-world true)**
- Your first performance wins come from:
  - avoiding repeated work (re-parsing, re-reading, re-allocating),
  - choosing correct algorithms,
  - keeping I/O and formatting out of tight loops.
- Micro-optimizing `Console.WriteLine` is usually meaningless compared to fixing loop design and allocation patterns.
