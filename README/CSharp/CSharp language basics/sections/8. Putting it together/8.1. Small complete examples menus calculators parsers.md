## 8.1. Small, complete examples (menus, calculators, parsers)

1. **Menu-driven console apps with `switch` and loops**
2. **Input parsing with `TryParse` patterns (avoid exceptions for control flow)**
3. **Performance and correctness notes (allocation awareness, avoid repeated parsing, validate once)**

### 1) **A menu loop that doesn’t turn into spaghetti**
**Key goals**
- Keep the loop responsible for *flow*, and move logic into small functions.
- Make “exit” explicit and easy to reason about.
- Keep input parsing centralized.

```csharp
using System.Globalization;

while (true)
{
    Console.WriteLine();
    Console.WriteLine("1) Add two numbers");
    Console.WriteLine("2) Convert Celsius → Fahrenheit");
    Console.WriteLine("0) Exit");
    Console.Write("Choice: ");

    var choice = Console.ReadLine();
    if (choice is null) return; // end-of-input

    switch (choice.Trim())
    {
        case "1":
            AddTwoNumbers();
            break;

        case "2":
            ConvertTemperature();
            break;

        case "0":
            return;

        default:
            Console.WriteLine("Unknown option.");
            break;
    }
}

static void AddTwoNumbers()
{
    if (!TryReadInt("a: ", out var a) || !TryReadInt("b: ", out var b))
        return;

    Console.WriteLine($"Result: {a + b}");
}

static void ConvertTemperature()
{
    if (!TryReadDouble("Celsius: ", out var c))
        return;

    var f = (c * 9.0 / 5.0) + 32.0;
    Console.WriteLine($"Fahrenheit: {f.ToString("0.##", CultureInfo.CurrentCulture)}");
}

static bool TryReadInt(string prompt, out int value)
{
    Console.Write(prompt);
    var text = Console.ReadLine();
    if (!int.TryParse(text, NumberStyles.Integer, CultureInfo.CurrentCulture, out value))
    {
        Console.WriteLine("Please enter a valid integer.");
        value = default;
        return false;
    }
    return true;
}

static bool TryReadDouble(string prompt, out double value)
{
    Console.Write(prompt);
    var text = Console.ReadLine();
    if (!double.TryParse(text, NumberStyles.Float, CultureInfo.CurrentCulture, out value))
    {
        Console.WriteLine("Please enter a valid number.");
        value = default;
        return false;
    }
    return true;
}
```

**Mentor notes**
- `return` as the “exit the app” path is fine in console apps. In larger programs, you’ll usually structure this as a loop that returns a result or calls into an application “runner”.
- Keeping parsing inside `TryRead*` avoids duplicated `if (!TryParse...)` everywhere.

### 2) **Parsing patterns that scale**
**Rule**
- Exceptions are for exceptional situations. User input being invalid is normal, so `TryParse` is the correct tool.

**Prefer**
- `int.TryParse`, `double.TryParse`, `DateTimeOffset.TryParse` (or `TryParseExact` when you require a specific format).
- Explicit culture when data crosses boundaries (files/protocols/logs): `CultureInfo.InvariantCulture`.

### 3) **Performance and correctness notes (what actually matters early)**
**Correctness**
- Validate once, early, and close to the edge (console input). Don’t let invalid data “leak” into deeper functions.
- Prefer `DateTimeOffset` for “real world time points” if you later add timestamps.

**Performance**
- The expensive thing in most console programs is I/O and repeated work.
  - Don’t re-parse the same input repeatedly.
  - Don’t write to the console inside tight loops if you can batch output.
- Don’t prematurely micro-optimize strings; fix algorithmic complexity and repeated allocations first.
