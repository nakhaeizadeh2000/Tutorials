## 4.2. Assignment operators and expression forms

1. **`=`, `+=`, `-=`, `*=`, `/=`, `??=`, and compound assignments**
2. **Increment/decrement (`++x` vs `x++`) and readability**
3. **Mentor notes (avoid cleverness; keep side effects obvious; prefer intent-revealing code)**

### 1) **Assignment operators**
**Basic assignment**
- `x = expr;` assigns the *result* of `expr` to `x`.
- The assignment expression itself has a value (it evaluates to the assigned value), but using that fact often harms readability.

**Compound assignment**
- `x += y` is roughly `x = x + y` but with an important correctness detail: `x` is evaluated once.
- Use compound assignment when it improves clarity (accumulating totals, building counters), not to compress code.

```csharp
var total = 0;
total += 5;
total -= 2;
```

**Null-coalescing assignment (`??=`)**
- `x ??= y` means: *if `x` is null, assign `y` to `x`*.
- Common for lazy initialization of reference types and nullable value types.

```csharp
string? name = null;
name ??= "Anonymous";
Console.WriteLine(name);
```

**Mentor rule**
- `??=` is great when it reads like a sentence. If it hides important work (I/O, expensive computation), make it explicit with `if`.

### 2) **Increment and decrement**
**Pre vs post**
- `++x`: increments first, then yields the new value.
- `x++`: yields the old value, then increments.

```csharp
var x = 0;
Console.WriteLine(++x); // 1
Console.WriteLine(x++); // 1 (prints old), x becomes 2 after
Console.WriteLine(x);   // 2
```

**In loops**
- Use `i++` in `for` loops by habit; it’s idiomatic and clear.
- Outside loops, prefer `x += 1` when you want to emphasize “adding one” rather than “increment semantics”.

### 3) **Expression forms and “don’t be clever” guidance**
**Avoid hiding side effects**
- Avoid assignment inside conditions in normal application code:

```csharp
// Harder to read; easy to get wrong:
// if ((line = Console.ReadLine()) is not null) ...

var line = Console.ReadLine();
if (line is not null)
{
    // ...
}
```

**Prefer clarity over token-golf**
- “Shorter” is not “faster” and rarely “better”.
- The real performance wins come from reducing allocations and work, not from clever operator tricks.

**Correctness note**
- Compound assignments can involve implicit conversions (e.g., `byte b = 1; b += 300;`) that look surprising. If you’re teaching or reviewing, prefer explicit types and explicit conversions so intent is obvious.
