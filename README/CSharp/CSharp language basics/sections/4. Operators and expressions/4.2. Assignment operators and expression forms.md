## 4.2. Assignment operators and expression forms

1. **`=`, `+=`, `-=`, `*=`, `/=`, `??=`, and compound assignments**
2. **Increment/decrement (`++x` vs `x++`) and readability**
3. **Mentor notes (avoid cleverness; keep side effects obvious; prefer intent-revealing code)**

### 1) **`=`, `+=`, `-=`, `*=`, `/=`, `??=`, and compound assignments**
**Basic assignment**
- `x = expr;` assigns the result of `expr` to `x`.
- The assignment expression has a value (it evaluates to the assigned value), but relying on that usually harms readability in application code.

**Compound assignment**
- `x += y` is roughly `x = x + y`, with a real semantic detail: `x` is evaluated once.
- Use compound assignment when it reads like “accumulate”, not to compress logic.

```csharp
var total = 0;
total += 5;
total -= 2;
```

**Null-coalescing assignment (`??=`)**
- `x ??= y` means: if `x` is null, assign `y` to `x`.
- Common for lazy initialization of nullable/reference values.

```csharp
string? name = null;
name ??= "Anonymous";
Console.WriteLine(name);
```

**Trade-offs and common mistakes**
- **Mistake**: hiding expensive work inside `??=`:

```csharp
cache[key] ??= ComputeExpensiveValue(); // This computes every time if you write it wrong elsewhere
```

If “compute” is expensive or has side effects, prefer a clear `if` so review/debugging is obvious.

**Correctness note (implicit conversions)**
- Compound assignment can include an implicit conversion back to the LHS type:

```csharp
byte b = 1;
b += 300; // compiles; wraps/truncates via implicit conversion rules
```

In teaching and code review, prefer explicit conversion (or a wider type) so intent is visible.

### 2) **Increment/decrement (`++x` vs `x++`) and readability**
**Pre vs post**
- `++x`: increments, then yields the new value.
- `x++`: yields the old value, then increments.

```csharp
var x = 0;
Console.WriteLine(++x); // 1
Console.WriteLine(x++); // 1, then x becomes 2
Console.WriteLine(x);   // 2
```

**When to use which**
- In `for` loops, `i++` is idiomatic and clear.
- Outside loops, avoid embedding `++` inside larger expressions (readability and debugging suffer).

Performance note:
- In modern JITs, `i++` vs `++i` rarely matters for `int`. Choose based on clarity.

### 3) **Mentor notes (avoid cleverness; keep side effects obvious; prefer intent-revealing code)**
**Avoid assignment inside conditions (most of the time)**
- C# allows it, but it’s easy to misread and easy to break in refactors.
- Prefer a separate statement unless you have a strong, team-approved style rule.

```csharp
var line = Console.ReadLine();
if (line is null) return;
```
