## 5.3. `switch` and `switch` expressions (modern C#)

1. **`switch` statement basics + `default` and fall-through rules**
2. **`switch` expressions for value-producing decisions (and why they reduce bugs)**
3. **Examples: menu handling, mapping codes → messages, and parsing user input safely**

### 1) **`switch` statement: the essentials**
**What it’s for**
- A `switch` is a clear way to branch based on a single value (often an enum, an int menu choice, or a string command).

**Rules you must know**
- C# does **not** allow accidental fall-through between non-empty cases.
- If you want to reuse logic, use `goto case` intentionally (rare, but legitimate).
- Always consider a `default` branch (or handle all cases explicitly).

```csharp
Console.Write("Choice (1-3): ");
var text = Console.ReadLine();

if (!int.TryParse(text, out var choice))
{
    Console.WriteLine("Invalid number.");
    return;
}

switch (choice)
{
    case 1:
        Console.WriteLine("Create");
        break;
    case 2:
        Console.WriteLine("Update");
        break;
    case 3:
        Console.WriteLine("Delete");
        break;
    default:
        Console.WriteLine("Unknown choice.");
        break;
}
```

### 2) **`switch` expressions: value-producing decisions**
**Why they matter**
- A `switch` expression returns a value. That encourages:
  - **exhaustiveness** (you’re forced to think “what is returned here?”)
  - less duplicated “assign then break” code
  - fewer uninitialized variables and missing branches

```csharp
static string DescribeStatusCode(int code) => code switch
{
    200 => "OK",
    400 => "Bad Request",
    401 => "Unauthorized",
    404 => "Not Found",
    >= 500 and < 600 => "Server Error",
    _ => "Unknown"
};
```

**Mentor note**
- Prefer switch expressions when you’re mapping inputs → outputs.
- Prefer `if`/guard clauses when you’re validating and exiting early.

### 3) **Practical patterns and pitfalls**
**Pattern: menu loops**

```csharp
while (true)
{
    Console.WriteLine("1) Add");
    Console.WriteLine("2) List");
    Console.WriteLine("0) Exit");
    Console.Write("Choice: ");

    var input = Console.ReadLine();
    if (!int.TryParse(input, out var choice))
        continue;

    switch (choice)
    {
        case 0:
            return;
        case 1:
            Console.WriteLine("Adding...");
            break;
        case 2:
            Console.WriteLine("Listing...");
            break;
        default:
            Console.WriteLine("Unknown option.");
            break;
    }
}
```

**Pattern: parsing commands**
- If you branch on strings, normalize once (`Trim`, casing strategy), then `switch`.

```csharp
var command = (Console.ReadLine() ?? "").Trim();

switch (command.ToLowerInvariant())
{
    case "help":
        Console.WriteLine("Commands: help, quit");
        break;
    case "quit":
        return;
    default:
        Console.WriteLine("Unknown command.");
        break;
}
```

**Performance and correctness notes**
- `switch` and `if` are both fast. Pick the construct that makes the logic easiest to audit.
- Prefer `enum` for finite sets of options; it makes invalid states harder to represent.
