## 5.1. `if`, `else if`, `else`: patterns, style, and examples

1. **Canonical forms (simple `if`, `if-else`, `else if` chains, nested `if`)**
2. **Examples: validation, range checks, and early returns**
3. **Best practices (guard clauses, keep nesting shallow, don’t duplicate expensive conditions)**

### 1) **Canonical forms (simple `if`, `if-else`, `else if`, nested `if`)**
**Simple `if`**

```csharp
var isEnabled = true;

if (isEnabled)
{
    Console.WriteLine("Enabled");
}
```

**`if-else`**

```csharp
var age = 17;

if (age >= 18)
    Console.WriteLine("Adult");
else
    Console.WriteLine("Minor");
```

**`else if` chain**
- Best when you’re expressing an ordered set of thresholds or mutually exclusive ranges.

```csharp
var score = 82;

if (score >= 90)      Console.WriteLine("A");
else if (score >= 80) Console.WriteLine("B");
else if (score >= 70) Console.WriteLine("C");
else                  Console.WriteLine("Needs work");
```

**Nested `if`**
- Nested `if` is a tool, not a default. Prefer it only when checks are genuinely dependent.
- For deeper guidance on when nested `if` is appropriate and how to refactor it, see **`5.2`**.

```csharp
User? user = new(isActive: true);

if (user is not null)
{
    if (user.IsActive)
        Console.WriteLine("Active user");
}

public sealed record User(bool IsActive);
```

### 2) **Examples: validation, range checks, and early returns**
**Validation with guard clauses (recommended default)**
- Guards keep the “happy path” straight-line and reduce indentation.

```csharp
static void PrintDiscount(decimal? percent)
{
    if (percent is null)
        return;

    if (percent is < 0 or > 100)
        throw new ArgumentOutOfRangeException(nameof(percent), "Must be 0..100.");

    Console.WriteLine($"Discount: {percent}%");
}
```

**Range checks with patterns**
- Use relational patterns (`is <`, `is >=`) and combined patterns (`or`, `and`) for readability.

```csharp
static bool IsValidPort(int port)
    => port is >= 1 and <= 65_535;
```

**Avoid duplicating expensive work**
- Compute once, then branch on the computed result.

```csharp
static bool IsValidUsername(string? name)
{
    if (string.IsNullOrWhiteSpace(name))
        return false;

    var trimmed = name.Trim(); // compute once
    return trimmed.Length is >= 3 and <= 32;
}
```

### 3) **Best practices (guard clauses, keep nesting shallow, don’t duplicate expensive conditions)**
**Prefer guard clauses**
- Guards make failure paths explicit and reduce nesting.
- They also reduce the chance you accidentally execute expensive work in invalid states.

**Keep conditions “pure”**
- Avoid I/O, mutation, and allocations inside conditions when possible.
- Pure conditions make debugging and performance reasoning much easier.

**Keep nesting shallow**
- If a method needs more than ~2–3 levels of indentation, extract helper methods or refactor to guards.

**Performance note**
- Branch prediction exists, but in most real code your bigger wins come from:
  - fewer allocations,
  - fewer I/O calls,
  - less repeated work.
