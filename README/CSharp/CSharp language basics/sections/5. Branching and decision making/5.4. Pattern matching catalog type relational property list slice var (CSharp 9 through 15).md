## 5.4. Pattern matching catalog (type, relational, property, list, slice, `var`, positional) — C# 9 through C# 15

This file is a **single map** for pattern-matching features that appear across versions. Prefer **`switch` expressions** and **`is` patterns** for readability; reserve complex patterns for cases where they **reduce** branching noise.

---

### 1) Type and declaration patterns

1. **`x is T t`**: combines test + cast; use when you need the typed value.
2. **`var` pattern**: `x is var v` captures without type test (rare; often clearer to use explicit types).
3. **Discard ` _`**: ignore parts you don’t want to bind.

**Perf / correctness**: type tests are cheap; avoid repeating casts in hot loops—bind once.

---

### 2) Relational and logical patterns (`>`, `<`, `and`, `or`, `not`)

1. Use for **numeric ranges** and **comparisons** in `switch`/`is`.
2. **Keep predicates shallow**—extract helpers when logic becomes a sentence.
3. **Nullability**: combine with `is null` / `is not null` for NRT-friendly flow.

---

### 3) Property patterns `{ Prop: pattern, ... }`

1. Great for **small, stable shapes** (DTO-like records).
2. **Nullability**: nested properties can be null—use `null` patterns or `required` models upstream.
3. **Perf**: deep property matching can be expensive; avoid in hot paths without measurement.

---

### 4) Positional patterns / deconstruction patterns

1. Pair with **records** and **tuple** `Deconstruct`/`ValueTuple` shapes.
2. Prefer **positional records** when you want clean `switch` expressions over data.

---

### 5) Tuple patterns (`(a, b)`) — see `Tuples` domain

1. Use **named tuple elements** (`(status: x, code: y)`) for readability.
2. **ValueTuple** is a struct—copying matters for large tuple shapes.

---

### 6) List patterns (C# 11+): `array is [a, b, c]`

1. Match **sequence shape** at the **front** of a list/array.
2. Combine with **slice patterns** (`..`) to match “rest” segments.

---

### 7) Slice patterns (`..`) in `switch`/`is` (C# 11+)

1. **Slice** matches a **middle/rest** segment; pairs naturally with list patterns.
2. **Allocation note**: matching itself doesn’t allocate; converting to **new** arrays/lists can.

---

### 8) `switch` expressions and exhaustiveness

1. Prefer **compiler-checked** cases when domain is closed.
2. Use **`_`** or a **catch-all** when domain is open—but document the intent.

---

### 9) C# 15+ preview: union types and `switch`

1. Union types aim for **exhaustive** `switch` over cases (see language docs).
2. Treat preview features as **toolchain-gated**—validate SDK + analyzer support in CI.
