## 3.1. Variables, identifiers, and assignment fundamentals

1. **Declaration forms (`var`, explicit types, `const`, `readonly`)**
2. **Definite assignment + scope (why the compiler “won’t let you”)**
3. **Mentor notes (readability-first `var`, avoid “stringly typed” flags, prefer small scopes)**

### 1) **Declaration forms**
**Variables are named storage**
- A variable is a *name* bound to a value. In C#, that value is always a **type** (known at compile time).
- The *type* determines how values behave (copying, equality, default values, overflow behavior).

**`var` vs explicit types**
- `var` is **still statically typed**. The compiler infers the type from the right-hand side.
- Prefer `var` when the type is obvious from the expression, and explicit types when it improves clarity.

```csharp
var count = 42;               // int
string name = "Ada";          // explicit can be clearer for APIs
var now = DateTimeOffset.Now; // clearer than DateTime? depends on intent
```

**`const`**
- `const` is **compile-time constant**. The value is baked into *callers* at compile time.
- Great for internal values; be cautious with public `const` in libraries (changing it requires recompiling consumers).

```csharp
const int MaxRetries = 3;
```

**`readonly`**
- `readonly` applies to **fields**, not locals. It means the field can only be assigned in the constructor or initializer.
- Use it to express immutability and help maintain invariants.

```csharp
public sealed class Config
{
    public readonly string EnvironmentName;

    public Config(string environmentName) => EnvironmentName = environmentName;
}
```

### 2) **Definite assignment + scope**
**Why “use of unassigned local variable” exists**
- The compiler enforces **definite assignment** so you don’t read garbage/uninitialized values.
- This prevents subtle runtime bugs and makes refactoring safer.

```csharp
int x;
// Console.WriteLine(x); // error: use of unassigned local variable

if (DateTime.UtcNow.Ticks % 2 == 0)
    x = 1;
else
    x = 2;

Console.WriteLine(x); // ok: assigned on all paths
```

**Scope is a design tool**
- Smaller scope = fewer accidental dependencies = easier reasoning.
- Prefer declaring variables close to first use.

### 3) **Mentor notes**
**Avoid “stringly typed” control flags**
- Don’t use `"admin"`, `"guest"`, `"1"`, `"2"` everywhere. Prefer `enum` or other types as soon as meaning appears.

```csharp
enum UserRole { Guest, Member, Admin }
```

**Performance reality (beginner-friendly)**
- Locals are cheap; *allocations* are what usually matter.
- Don’t “optimize by reusing variables”; optimize by reducing work (loop structure, parsing once, fewer allocations).
