## 3.2. Primitive types and literals (and when overflow matters)

1. **Integral types (`byte`…`long`), floating point (`float`/`double`), and `decimal`**
2. **`char`, `bool`, `string`, `DateTime` vs `DateTimeOffset` (starter guidance)**
3. **Checked vs unchecked arithmetic (correctness first; performance is a second-order effect)**

### 1) **Numeric primitive types**
**Integers (exact)**
- Use **`int`** by default unless you have a specific reason (memory layout, interop, or a real range need).
- Prefer **`long`** when you’re dealing with counts/sizes that can exceed ~2.1B (bytes, ticks, database IDs, etc.).
- Use **unsigned** (`uint`, `ulong`) only when you need their exact semantics (bit work, interop). Unsigned types can make comparisons and APIs harder for humans.

**Floating point (approximate)**
- Use **`double`** as the default for real numbers unless you have memory constraints.
- Don’t compare floats for equality unless you explicitly control tolerances.

**`decimal` (base-10, high precision)**
- Prefer `decimal` for **money** and **human-facing base-10 quantities** where rounding must be predictable.
- `decimal` is slower than `double` and uses more space; that’s fine when correctness is the goal.

### 2) **Literals that communicate intent**
**Numeric literal readability**
- Use `_` separators: `1_000_000`, `0b_1111_0000`, `0x_FF_EC_DE_5E`.
- Use suffixes when they matter: `1_000_000L`, `0.1m`, `1.0f`.

**Avoid “mystery types”**
- `var x = 1;` is `int`.
- `var x = 1.0;` is `double`.
- `var x = 1.0m;` is `decimal`.
- If the suffix affects correctness, consider being explicit for teaching material.

### 3) **`char`, `bool`, `string` and a practical time type**
**`bool`**
- Keep boolean names affirmative and meaningful (`isEnabled`, not `notEnabled`), especially in `if` conditions.

**`char` vs `string`**
- `char` is a **UTF-16 code unit**, not necessarily a full Unicode “character” (grapheme). For beginner basics, treat it as “one code unit”.
- `string` is immutable; concatenation in loops can allocate a lot (prefer `StringBuilder` only when needed).

**`DateTime` vs `DateTimeOffset` (starter guidance)**
- Prefer **`DateTimeOffset`** when you represent a moment in time that will cross machines/time zones.
- Prefer `DateTime` only when you know you’re handling a local concept (like “store opens at 09:00 local time”), and even then be explicit about `Kind`.

### 4) **Overflow: when it matters**
**Key idea**
- Integer overflow can silently produce the wrong result in **unchecked** contexts.
- In a **checked** context, overflow throws an exception, which is slower but correct and visible.

**Example**

```csharp
checked
{
    int bytes = 1_500_000_000;
    int doubled = bytes * 2; // throws OverflowException
}

unchecked
{
    int bytes = 1_500_000_000;
    int doubled = bytes * 2; // wraps around (wrong but “fast”)
}
```

**Mentor guidance**
- For beginners and business logic, prefer correctness and clarity: use `checked` when overflow would be a bug.
- For low-level code (bit manipulation, hashing), wraparound may be intended—make it explicit with `unchecked` so it’s obvious.
