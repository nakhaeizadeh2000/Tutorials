## 7.1. `break` and `continue` (clean exits, fewer bugs)

1. **Using `break` to stop loops early**
2. **Using `continue` to skip work safely**
3. **Best practices (avoid “spaghetti” flow; prefer small helper methods when it gets complex)**

### 1) **Using `break` to stop loops early**
**Definition**
- `break` exits the *nearest* enclosing loop (`for`, `foreach`, `while`, `do`) or `switch`.
- It’s a control-flow tool for “we are done here”.

**When to use**
- **Search**: stop as soon as the answer is known (first match).
- **Validation loops**: stop when you receive a valid value.
- **Menu loops**: exit an infinite loop cleanly.

**Trade-offs**
- `break` can improve clarity (early exit), but too many exits in one loop can harm readability.
- If you need to break out of *multiple* nested loops, consider restructuring (extract a method and `return`, or use a flag carefully).

**Example (find first match)**

```csharp
var numbers = new[] { 3, 7, 10, 12 };
var hasMultipleOfFive = false;

foreach (var n in numbers)
{
    if (n % 5 == 0)
    {
        hasMultipleOfFive = true;
        break;
    }
}

Console.WriteLine(hasMultipleOfFive);
```

Performance note:
- This is a “real” optimization because it can remove entire iterations (CPU + any work inside).

**Common mistakes**
- Breaking in the wrong place (exits only the nearest loop).
- Using `break` as a substitute for structuring code (if the loop does too many jobs, extract methods).

### 2) **Using `continue` to skip work safely**
**Definition**
- `continue` skips the rest of the current iteration and proceeds to the next iteration of the nearest loop.

**When to use**
- Input filtering: invalid input → skip processing and retry.
- Data filtering: skip items that don’t meet criteria, keeping the “happy path” left-aligned.

**Example (filter invalid input)**

```csharp
while (true)
{
    Console.Write("Enter a positive integer (blank = quit): ");
    var line = Console.ReadLine();

    if (string.IsNullOrWhiteSpace(line))
        break;

    if (!int.TryParse(line, out var value) || value <= 0)
    {
        Console.WriteLine("Invalid input.");
        continue;
    }

    Console.WriteLine($"Square: {value * value}");
}
```

Mentor note:
- This file does not re-teach parsing/culture choices. See **`2.1`** for the canonical `TryParse` + culture guidance:
  - `README/CSharp/CSharp language basics/sections/2. Console I-O/2.1. The System.Console class input output formatting.md`

**Common mistakes**
- Using `continue` to jump over cleanup. If you acquire resources in an iteration, ensure cleanup is unconditional (prefer `using`).
- Overusing `continue` (many continues make the loop hard to reason about). Extract helpers when logic grows.

### 3) **Best practices (avoid “spaghetti” flow)**
**Keep loops single-purpose**
- A loop that both *parses input*, *updates state*, and *does business logic* tends to become untestable and fragile.
- Prefer: parse/validate at the boundary → call small functions.

**Prefer guard-style loop bodies**
- Validate early → `continue` or `break`
- Do the work
- Emit the result

**If complexity grows, restructure**
- Extract a method and `return` instead of coordinating multiple break conditions.
- For `goto case` discussion (rarely legitimate), see **`7.2`**:
