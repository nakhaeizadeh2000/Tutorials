## 7.1. `break` and `continue` (clean exits, fewer bugs)

1. **Using `break` to stop loops early**
2. **Using `continue` to skip work safely**
3. **Best practices (avoid “spaghetti” flow; prefer small helper methods when it gets complex)**

### 1) **`break`: stop the loop early**
**What it does**
- `break` exits the *nearest* loop (`for`, `foreach`, `while`, `do`) or `switch` statement.

**Why it’s useful**
- It prevents wasted work and makes “find the first match” logic simple and efficient.

```csharp
var numbers = new[] { 3, 7, 10, 12 };
var found = false;

foreach (var n in numbers)
{
    if (n % 5 == 0)
    {
        found = true;
        break; // stop as soon as we know the answer
    }
}

Console.WriteLine(found);
```

**Mentor note (performance)**
- `break` is one of the cleanest “micro-optimizations” because it often removes *entire iterations* (real CPU + allocation reduction), not just instruction-level tweaks.

### 2) **`continue`: skip the rest of the current iteration**
**What it does**
- `continue` jumps to the next iteration of the nearest loop.

**Common use**
- Filter invalid inputs and keep the “happy path” left-aligned.

```csharp
while (true)
{
    Console.Write("Enter a positive integer (or blank to quit): ");
    var line = Console.ReadLine();

    if (string.IsNullOrWhiteSpace(line))
        break;

    if (!int.TryParse(line, out var value) || value <= 0)
    {
        Console.WriteLine("Invalid input.");
        continue; // retry
    }

    Console.WriteLine($"Square: {value * value}");
}
```

**Mentor note (correctness)**
- `continue` reduces indentation, but don’t use it to “jump over” critical cleanup. If an iteration acquires resources, ensure cleanup is unconditional (e.g., `using`).

### 3) **Best practices**
**Keep flow readable**
- Avoid multiple `break`/`continue` statements in the same loop body unless the loop is small and the exits are obvious.
- If you find yourself tracking a lot of flags, it’s usually a sign to extract a helper method and return early.

**Prefer guard clauses**
- This pattern often reads best:
  - validate → `continue`
  - do work
  - produce result
