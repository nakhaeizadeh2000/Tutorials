## 4.1. Asymmetric accessibility: `public get; private set;` and friends

1. **What’s allowed** (different access levels on `get`/`set`/`init` within language rules)
2. **Common shapes** (`public get; private set;`, `public get; internal set;`, `public get; private init;`)
3. **API design rule** (make the safe thing easy; keep mutation close to invariant logic)

---

### 1) **What’s allowed** (different access levels on `get`/`set`/`init` within language rules)

**Definition**

An *asymmetric* property is one where the `get` and `set` (or `init`) accessors have **different accessibility**. This is one of the most practical C# features for **API shaping**:

- You expose a value for reading publicly (or internally),
- but you restrict who can mutate it.

**Key rule**

- You can make an accessor **more restrictive** than the property itself (e.g., `public` property with `private set`).
- You cannot make an accessor **less restrictive** than the property (e.g., `internal` property with `public set` is not allowed).

**What this buys you**

- **Encapsulation**: mutations are forced to happen inside your type (where invariants live).
- **Maintainability**: you can evolve the internal mutation strategy without changing public surface area.
- **Testability**: you can allow controlled mutation internally (`internal set`) while keeping public callers read-only.

**Good to know**

- Accessor accessibility is a *compile-time* restriction. Reflection can bypass it; don’t use it as a security boundary.

---

### 2) **Common shapes** (`public get; private set;`, `public get; internal set;`, `public get; private init;`)

Below are the shapes you’ll see in production code and what they mean.

#### A) `public T P { get; private set; }`

**Meaning**: Consumers can read, only the type itself can set *after construction*.

Use when:
- the value changes over time,
- but the type must control updates (e.g., `Status`, `Balance`, `LastUpdatedUtc`).

Example (runnable):

```csharp
using System;

public sealed class Order
{
    public string Id { get; }
    public OrderStatus Status { get; private set; } = OrderStatus.Created;
    public DateTimeOffset LastUpdatedUtc { get; private set; } = DateTimeOffset.UtcNow;

    public Order(string id) => Id = string.IsNullOrWhiteSpace(id) ? throw new ArgumentException("Id is required.", nameof(id)) : id;

    public void MarkPaid()
    {
        if (Status is OrderStatus.Cancelled)
            throw new InvalidOperationException("Cancelled orders cannot be paid.");

        Status = OrderStatus.Paid;
        LastUpdatedUtc = DateTimeOffset.UtcNow;
    }
}

public enum OrderStatus { Created, Paid, Cancelled }
```

Mentor note:
- If mutation is meaningful (a “command”), prefer a **method** like `MarkPaid()` over allowing `set` from outside. This keeps invariants and side effects explicit.

#### B) `public T P { get; internal set; }`

**Meaning**: Readable by everyone, settable only inside the assembly.

Use when:
- you want read-only semantics for public consumers,
- but allow a composition layer / infrastructure / tests within the same assembly to mutate.

Mentor rule:
- In libraries, prefer `internal set` sparingly. If callers outside the assembly should never mutate, keep invariants in methods and keep setters private.

#### C) `public T P { get; private init; }` / `public T P { get; init; }`

**Meaning**: Assignment allowed only during object creation (constructor or object initializer).

Use when:
- you’re modeling **construction-time immutability** (typical for DTOs/config/data carriers),
- and you want call-site readability with object initializers.

Deep reference:
- `init` + `required` semantics (and failure modes with serializers) are explained in depth in `README/CSharp/07 Constructors/sections/4. Object initialization styles/4.2. init required and illegal states unrepresentable.md`.

#### D) Computed property with no setter: `public T P => ...;`

**Meaning**: `P` is derived from other state and can’t be assigned.

Use when the value is:
- cheap to compute,
- and semantically a *view* of internal state.

Performance note:
- If the computation is not cheap, **don’t hide it behind a property**. Expose a method (e.g., `ComputeTotal()`), or cache carefully (see `2.1`).

---

### 3) **API design rule** (make the safe thing easy; keep mutation close to invariant logic)

**Mentor checklist**

- Prefer **`public get; private set;`** for mutable domain state that must remain consistent.
- Prefer **`public get; init;` / `required`** for DTO/config shapes where completeness is a call-site goal (not invariant safety).
- Avoid **public setters** on domain entities unless mutation is truly safe and trivial.
- If a setter would need to do meaningful work (I/O, persistence, messaging, locking), it’s not a property setter—make it a **method**.

**Thread-safety reminder**

Accessor accessibility does **not** make mutations thread-safe. If a property can be mutated by multiple threads, choose a synchronization strategy (locks/immutability/confinement). The deep treatment belongs in `README/CSharp/29 Cuncurrent & Parallel`.
