## 9.1. Boundaries: what is covered elsewhere in this repo

1. **OOP big picture (pillars, composition vs inheritance, basic interface usage)** is covered in `CSharp Basic Object Oriented Programming`
2. **Inheritance mechanics (construction order, hiding vs overriding, sealed types, dispatch overview)** is covered in `Inheritance and Hiding and Overriding`
3. **General method design (overloads, ref/out/in, generics basics, Try-patterns)** is covered in `Methods`
4. **Runtime/JIT/GC fundamentals** are covered in `Fundamental Theories`
5. **Threading, async, and the memory model** are covered in `Cuncurrent & Parallel`

### 1) OOP big picture (pillars, composition vs inheritance, basic interface usage)

This domain assumes you already understand the *why* of OOP and the high-level trade-offs between composition and inheritance. It focuses on **C#-specific mechanics and production-grade design** for abstract classes and interfaces.

See the canonical overview in `README/CSharp/CSharp Basic Object Oriented Programming/README.md`.

### 2) Inheritance mechanics (construction order, hiding vs overriding, sealed types, dispatch overview)

We intentionally do **not** re-teach:
- constructor order and the “no virtual calls in constructors” hazard,
- `new` hiding vs `override`,
- when and why to use `sealed` / `sealed override`,
- the general runtime dispatch model at a language level.

See `README/CSharp/Inheritance and Hiding and Overriding/README.md` for the full treatment.  
In this domain, we reference those mechanics only when they directly impact **abstract base class** and **interface** design.

### 3) General method design (overloads, ref/out/in, generics basics, Try-patterns)

We use method design patterns (e.g., Try-patterns, overload sets, generic constraints) but we avoid duplicating the full guidance. For the canonical coverage, see `README/CSharp/Methods/README.md`.

### 4) Runtime/JIT/GC fundamentals

We mention JIT behavior (inlining, devirtualization) and allocation patterns (boxing, iterators) only as needed to make interface/abstract-class decisions. For full runtime fundamentals, see `README/CSharp/Fundamental Theories/README.md`.

### 5) Threading, async, and the memory model

This domain may mention thread-safety and cancellation contracts, but it does not teach concurrency from scratch. For the deep treatment (ThreadPool behavior, async/await correctness, memory visibility), see `README/CSharp/Cuncurrent & Parallel/README.md`.
