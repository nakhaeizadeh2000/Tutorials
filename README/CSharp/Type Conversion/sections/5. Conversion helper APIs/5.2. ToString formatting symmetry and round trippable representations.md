## 5.2. `ToString`/formatting symmetry and round-trippable representations

1. **Round-trip principle** (format then parse should recover the same value)
2. **Stable formats** (InvariantCulture for protocol/storage; CurrentCulture for UI)
3. **Avoid “pretty” strings as data** (logging/display vs storage/wire)
4. **`ISpanFormattable` and `TryFormat`** (where it helps, when it’s overkill)
5. **Allocation control** (format into spans/handlers in hot paths)

---

### 1) **Round-trip principle** (format then parse should recover the same value)

**Definition**

A representation is **round-trippable** when:

- formatting a value to text
- and then parsing that text back

produces the **same value** (or an equivalent one under a clearly documented equivalence rule).

This is not just a “nice to have”. It’s the difference between:

- **display strings** (for humans)
- **data representations** (for storage/wire/protocols)

**Mentor stress**

- If a string is meant to be parsed later, treat it as a **format contract**.
- If a string is meant for humans, treat it as **presentation** and don’t rely on parsing it.

**Example (runnable): stable vs unstable formatting**

```csharp
using System;
using System.Globalization;

static class Demo
{
    static void Main()
    {
        var dto = new DateTimeOffset(2026, 4, 1, 10, 30, 0, TimeSpan.Zero);

        // "O" is round-trip-friendly for DateTime/DateTimeOffset.
        string roundTrip = dto.ToString("O", CultureInfo.InvariantCulture);
        var parsed = DateTimeOffset.ParseExact(roundTrip, "O", CultureInfo.InvariantCulture, DateTimeStyles.RoundtripKind);

        Console.WriteLine(roundTrip);
        Console.WriteLine(dto == parsed);
    }
}
```

**Good to know**

- Round-tripping is easiest when you use **`ParseExact`/`TryParseExact`** with a fixed format string and `InvariantCulture`.

---

### 2) **Stable formats** (InvariantCulture for protocol/storage; CurrentCulture for UI)

**Rule of thumb**

- **UI/user input/output**: use `CultureInfo.CurrentCulture` (or a user-selected culture) to meet user expectations.
- **Protocols/storage/log contracts**: use `CultureInfo.InvariantCulture` and explicit formats.

**Common mistake**

Saving a `ToString()` result to storage (DB/file) without specifying format/culture, then parsing it on another machine. This is the classic “works on my machine” culture bug.

**See full culture guidance**

For the deep reasoning and examples, see `4.2. Culture, IFormatProvider, and deterministic parsing`.

---

### 3) **Avoid “pretty” strings as data** (logging/display vs storage/wire)

**What goes wrong**

“Pretty” formats are often:

- localized (month names, separators)
- ambiguous (MM/dd vs dd/MM)
- lossy (rounding, missing offset/time zone)

That means they should not be used as durable data representations.

**Mentor patterns**

- **For storage/wire**: pick a deterministic format and enforce it (often `TryParseExact`).
- **For logs**: you can still use stable formats so logs are parseable in incident response.
- **For UI**: present localized formatting, but don’t store it.

---

### 4) **`ISpanFormattable` and `TryFormat`** (where it helps, when it’s overkill)

**Definition**

`ISpanFormattable` allows formatting into a destination span, often via:

- `TryFormat(Span<char> destination, out int charsWritten, ...)`

This can eliminate intermediate string allocations when you’re formatting a lot.

**When it helps**

- High-throughput formatting (telemetry, serialization-ish pipelines, protocol writing)
- When you already have a buffer (e.g., stackalloc or pooled arrays)

**When it’s overkill**

- Normal application code where readability matters more and formatting is not a hot path.

**Example (runnable): format into a buffer**

```csharp
using System;

static class Demo
{
    static void Main()
    {
        Span<char> buffer = stackalloc char[32];
        var value = 12345;

        if (value.TryFormat(buffer, out int written))
            Console.WriteLine(buffer[..written].ToString());
    }
}
```

**Performance note**

- `stackalloc` is great for small, bounded buffers. Don’t `stackalloc` huge buffers (risk of stack overflow); prefer pooling or streaming.

---

### 5) **Allocation control** (format into spans/handlers in hot paths)

**Where allocations come from**

- `ToString()` creates a new string (always).
- Interpolated strings create a new string **unless** an API uses interpolation handlers.
- `string.Format` allocates (and often boxes value types).

**Modern guidance**

- If you need a string, `ToString(format, provider)` is fine—just be explicit about format/culture where correctness matters.
- If you’re writing into an existing sink/buffer repeatedly, prefer span-based formatting (`TryFormat`) or APIs that accept `Span<char>`/`IBufferWriter<char>`.

**Cross-reference**

Boxing and `params object[]` pitfalls often show up around formatting/logging. See `3.3. Boxing/unboxing and hidden allocations` for the “why”.
