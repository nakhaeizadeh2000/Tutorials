## 7.1. Anonymous methods (`delegate {}`) vs lambdas (`() => {}`): when each is useful

1. **Historical note** (anonymous methods exist for compatibility; lambdas are the modern default)
2. **Behavior differences** (rare edge cases like parameter typing/inference; readability)
3. **Guidance** (prefer lambdas unless you’re targeting a specific shape or porting old code)

### 1) Historical note (why both exist)
Anonymous methods (`delegate (...) { ... }`) were introduced before lambda expressions existed. Lambdas (`(...) => ...`) became the modern, more expressive syntax and are what you should write in new C# 15 code.

In production code, you mainly see anonymous methods when:
- You’re maintaining older codebases and want minimal diffs
- A library API was written in an older style and examples stayed that way

### 2) Behavior differences (rare, but real)
Most of the time, anonymous methods and lambdas compile to very similar IL and runtime behavior. The important differences today are mostly about **readability**, **target typing**, and some edge cases:

#### Parameter list and typing
- Lambdas are designed for modern target typing and are usually clearer at the call site.
- Anonymous methods can sometimes feel “looser” because they read more like “inline function body”, but they’re not better for inference in modern C#—they’re mostly just older syntax.

#### `static` lambdas (modern advantage)
Lambdas support `static` which **prohibits captures**, preventing accidental allocations and lifetime extension:

```csharp
using System;

Func<int, bool> isEven = static x => (x & 1) == 0;
Console.WriteLine(isEven(42));
```

Anonymous methods cannot express the “no capture allowed” intent as directly. This is a major reason mentor-grade code favors lambdas.

#### Expression trees
Both lambdas and (some) anonymous method forms can be converted to delegates, but expression trees are typically authored with lambda syntax. If your target type is `Expression<Func<...>>`, you’re writing lambdas; see `8.1` for the full delegate vs expression tree distinction.

### 3) Guidance (what to do in C# 15 code)
#### Default: use lambdas
Use lambda expressions for new code. They:
- Read cleaner in modern APIs
- Support `static` to prevent captures
- Fit better with modern patterns (LINQ, `Task` continuations, minimal APIs)

#### Prefer method groups over non-capturing lambdas
If you already have a well-named method and you don’t need captures, prefer a method group:

```csharp
using System;

static void OnTick() => Console.WriteLine("tick");

Action a = OnTick;     // method group
a();
```

It’s often the most readable, gives better stack traces, and makes unsubscribe scenarios easier (events). See `1.3` for the full method group vs lambda guidance.

#### When anonymous methods are acceptable
Use anonymous methods only when:
- You’re porting/maintaining old code and want minimal change surface
- Your team has a strong local convention in a legacy area

**Performance note**
The important performance decision is not “anonymous method vs lambda”, it’s **capturing vs non-capturing**. Capturing creates closure allocations and can keep objects alive. For the full closure and allocation story, see `7.2` and `10.1`.
