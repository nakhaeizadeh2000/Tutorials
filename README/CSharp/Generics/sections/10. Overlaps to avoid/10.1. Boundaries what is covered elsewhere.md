This file is intentionally short.

The goal of the Generics domain is to be **useful without duplicating** the repo’s existing canonical deep dives. When you hit one of these boundary topics while reading Generics, jump to the linked domain/section for the full treatment, then come back.

### Good to know (how to use these boundaries)

- **If you want the “why and rules”**:
  - Variance rules, array covariance hazards, and substitutability → see the variance section in `Type Conversion`.
- **If you want the “where my allocations came from”**:
  - Boxing triggers (especially structs + interfaces + logging) → see the boxing deep dives in `Structures` and `System Object Class`.
- **If you want to understand “why the compiler chose that generic overload”**:
  - Overload resolution and ambiguity traps → see `Methods/5`.
- **If you want “runtime-level generics + JIT/AOT constraints”**:
  - CLR/JIT/tiering/PGO/AOT/trimming mental model → see `Fundamental Theories`.

### Mentor rule

Treat “duplication” as technical debt in documentation too:

- It creates contradictions over time.
- It makes readers unsure which one to trust.
- It increases maintenance effort.

So in this repo, we keep **one canonical place** per deep topic, and everywhere else we reference it.
