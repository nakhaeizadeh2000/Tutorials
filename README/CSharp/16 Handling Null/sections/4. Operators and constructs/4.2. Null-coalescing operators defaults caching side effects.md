## 4.2. Null-coalescing operators (`??`, `??=`): defaults, caching, and side effects

1. **`??`**: choose fallback value when the left side is null (be explicit about semantics).
2. **`??=`**: lazy initialization patterns; be careful with expensive or side-effecting RHS.
3. **Mentor note**: defaulting is a business decision—document it in code via naming and structure.

### 1) **`??`**: defaults are semantics, not just syntax
**Definition**
- `a ?? b` evaluates to `a` if `a` is non-null; otherwise it evaluates to `b`.
- Only the chosen side is evaluated (so `b` is evaluated **only when needed**).

**When to use**
- **Meaningful defaults** where “missing” is expected and acceptable:
  - UI display: `name ?? "(unknown)"` (frontend)
  - Optional configuration with documented defaults
  - Optional enrichment fields in logs/telemetry

**When *not* to use**
- When null indicates **broken invariants** or invalid input. Defaulting there converts a correctness bug into a silent logic bug.

Example (acceptable default at a boundary):

```csharp
public static int ParsePageSize(string? raw)
{
    // boundary: missing pageSize becomes a documented default
    var text = raw ?? "50";
    return int.TryParse(text, out var size) && size is >= 1 and <= 500 ? size : 50;
}
```

Example (bad default hiding an invariant violation):

```csharp
// If CustomerId is required for authorization/routing, defaulting is dangerous:
var customerId = request.CustomerId ?? "unknown"; // bug-masking
```

**Good to know**
- `??` composes well with pattern matching and guards:

```csharp
var value = input is { Length: > 0 } s ? s : null;
var normalized = value ?? "fallback";
```

### 2) **`??=`**: lazy initialization (and why side effects matter)
**Definition**
- `x ??= y` means: if `x` is null, assign `y` to `x`, then return the new value.
- `y` is evaluated **only if** assignment happens.

**Where it shines**
- Lazy initialization of optional cached data in a **single-threaded or thread-confined** context.

```csharp
private string? _displayName;

public string DisplayName => _displayName ??= ComputeDisplayName();
```

**Thread-safety warning**
- `??=` is not magically thread-safe. If multiple threads can access `_displayName`, two threads may compute simultaneously. That might be acceptable or not, depending on:
  - side effects,
  - cost,
  - requirement for single initialization.

If you need strong single-init guarantees, use `Lazy<T>` or a proper synchronization strategy. See also: `README/CSharp/29 Cuncurrent & Parallel` for deep concurrency patterns.

**Common mistake: hiding expensive work**

```csharp
cache[key] ??= ComputeExpensiveValue(); // ok only if ComputeExpensiveValue is pure and occasional duplicates are acceptable
```

Mentor guidance:
- If the RHS is expensive or has side effects, make it explicit with `if` for clarity and observability.

```csharp
if (cache[key] is null)
{
    cache[key] = ComputeExpensiveValue();
}
```

**Performance note**
- `??=` can reduce allocations if it prevents repeated building of the same object (e.g., a formatted string) in a hot path.
- But uncontrolled lazy init in multi-threaded code can increase CPU usage due to duplicate computation and contention.

---

### 3) **Mentor note**: defaulting is a business decision—make it reviewable
Defaulting is a policy. Make it obvious in code:
- **Name the policy**: `GetXOrDefault`, `ResolveX`, `NormalizeX`, `FallbackX`.
- **Localize it**: put defaulting near the boundary or the policy owner, not scattered through core logic.
- **Log/measure when appropriate**: if a default indicates missing upstream data, you often want metrics.

Practical technique: return a structured result instead of defaulting silently when absence matters:

```csharp
public readonly record struct LookupResult<T>(bool Found, T? Value);
```

Then callers choose the default explicitly where it makes sense (UI vs core logic).
