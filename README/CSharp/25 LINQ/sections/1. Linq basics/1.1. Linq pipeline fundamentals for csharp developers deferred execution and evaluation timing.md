## 1.1. LINQ pipeline fundamentals for C# developers (deferred execution + evaluation timing)

1. **Deferred execution by default**: most LINQ-to-Objects operators build an iterator/pipeline and only run when you enumerate (e.g., `foreach`, `ToList`, `ToArray`, `Count`, etc.).
2. **Exceptions happen at enumeration time**: `First`, `Single`, `Min`, `Max`, etc. throw when iterated, not when the query is composed.
3. **Multiple enumeration re-runs the pipeline**: if the source is expensive or stateful, repeating enumeration repeats CPU work and can repeat side effects.
4. **Operator categories (what to expect)**: filtering/quantifiers (`Where`, `Any`, `All`), ordering (`OrderBy`), element access (`First`, `ElementAt`), projection (`Select`), and aggregation (`Count`, `Sum`, etc.).
5. **`Func` vs `Expression<Func<...>>` mental model**: LINQ operators accept delegates, but query providers (e.g., EF Core) may translate expression trees; side effects in lambdas generally break provider translation.

---

### 1. **Deferred execution by default**

LINQ-to-Objects composes **lazy** iterators. A line like `var q = source.Where(x => x > 0).Select(x => x * 2);` does not yet touch most elements of `source`. The work is scheduled in a chain of `IEnumerator<T>` moves.

**When execution happens**

- **Iteration**: `foreach (var x in q) …`
- **Terminal operators**: `ToList`, `ToArray`, `ToHashSet`, `Count()`, `Sum`, `Any`, `First`, etc.

**Good to know:** “Deferred” does not mean “free.” Each operator may add iterator allocation and indirection; in hot paths, hand-written loops can be cheaper after you measure.

---

### 2. **Exceptions happen at enumeration time**

Operators that validate sequence state (e.g., `First` on empty, `Single` when duplicates exist, `Min`/`Max` on empty) typically throw **during enumeration**, not when you build the query. That surprises developers who expect failures at the call site where the query variable is assigned.

**Practical rule:** treat query variables as **plans**, not **results**, until you materialize or enumerate.

---

### 3. **Multiple enumeration re-runs the pipeline**

`IEnumerable<T>` is not a cached snapshot unless you materialize it. Calling `Count()` and later `foreach` on the same query can enumerate twice.

**Mitigation:** materialize once (`ToArray` / `ToList`) when the source is expensive, non-idempotent, or when you need stable multiple passes.

**Performance note:** materialization trades **CPU (single pass)** for **RAM (buffer)**. Pick based on size and measurability.

---

### 4. **Operator categories**

- **Filtering / quantifiers:** short-circuit when possible (`Any`, `All`, `First` with predicate).
- **Ordering:** must see keys (and usually buffer) to produce global order—see §2.x in this domain.
- **Projection:** `Select` is typically streaming and deferred.
- **Aggregation:** `Sum`, `Average`, `Count` (without fast path) scan the sequence.

---

### 5. **`Func` vs `Expression<Func<...>>`**

`IEnumerable<T>` extension methods take **`Func<...>`** delegates: your logic runs in-process as C#.

Providers like **EF Core** overload the same names with **`Expression<Func<...>>`**: the compiler builds an expression tree the provider translates to SQL (or another target). Arbitrary C# in lambdas may not translate.

**Rule:** keep provider queries **pure** (no local method calls that cannot translate) and avoid side effects in lambdas intended for translation.

For delegate semantics (Multicast, variance), see *Delegates and Events*; for `IEnumerable` and iterators, see *Collections*—this file stays focused on LINQ operator timing.

```csharp
using System;
using System.Collections.Generic;
using System.Linq;

var source = new[] { 1, 2, 3 }.AsEnumerable();
IEnumerable<int> plan = source.Where(n => n > 1).Select(n => n * 10);
// No write to console yet:
var q = plan.Select(n => { Console.WriteLine(n); return n; });
foreach (var x in q) _ = x; // writes 20, 30 when enumerated
```
