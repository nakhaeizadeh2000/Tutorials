## 7.3. Sum: numeric overflow and nullable behavior

1. **Sum is a single pass aggregation**: `Sum` enumerates once and computes totals; CPU cost is proportional to sequence length.
2. **Overflow expectations**: for integral types, overflow can throw (e.g., `OverflowException`) depending on numeric type and LINQ implementation details.
3. **Nullable sequences**: `Sum` overloads for nullable numeric types **skip** `null` elements; for `int?` the result is `int`, and an **empty or all-null** sequence yields **`0`**—which can be ambiguous for "no data" vs "sum is zero." Model that in your API or use a different aggregation when you need a third state.

---

### 1. **Checked vs unchecked**

C# integral arithmetic defaults to **unchecked** in most contexts; **`Sum`** for `int`/`long` uses checked accumulation in the **LINQ-to-Objects** implementation—**overflow throws** `OverflowException`. For **`decimal`**, operations are checked in the sense of `decimal` rules.

**Good to know:** if you need saturating or wrapping semantics, use a **`Aggregate`** with explicit rules.

---

### 2. **Floating point**

`Sum` for **`double`/`float`** is subject to rounding; for financial math prefer **`decimal`**.

---

### 3. **Nullable**

For **`IEnumerable<int?>`, `Sum()` returns `int`**: null items are ignored; if there is nothing to add, the sum is **`0`**. Do not use this alone when callers must distinguish **“no inputs”** from **“inputs totaled to zero.”**

```csharp
using System.Linq;

int total = new[] { 1, 2, 3 }.Sum();
int emptySum = Enumerable.Empty<int?>().Sum(); // 0, not null
int?[] onlyNulls = [null, null];
int sumNulls = onlyNulls.Sum(); // 0
```

**Performance note:** single pass, **O(1)** extra memory; pairs well with **`Where`** but remember **double enumeration** if you chain multiple aggregations without materializing.
