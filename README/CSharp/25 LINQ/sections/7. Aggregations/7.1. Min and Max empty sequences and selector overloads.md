## 7.1. Min and Max: empty sequences and selector overloads

1. **Min/Max are aggregations**: they reduce the sequence to a single value and require enumerating the source.
2. **Empty sequence behavior**: `Min`/`Max` throw `InvalidOperationException` when the sequence is empty (or no element matches, for selector/filter compositions).
3. **Selectors and comparers**: you can project keys for `Min/Max` via selectors; choose comparers if ordering/correctness matters (especially for strings).

---

### 1. **Terminal operators**

Aggregations **run the pipeline** to completion (unless an exception short-circuits). They are not lazy past the point of computing the result.

---

### 2. **Empty inputs**

For non-nullable value types, empty → **throw**. For **`float`/`double`**, `NaN` propagation follows IEEE rules—watch for subtle bugs.

**Nullable numerics:** some scenarios use **`Min`/`Max`** on `T?` sequences; verify overload behavior for your TFM.

---

### 3. **Selectors and comparers**

`Max(x => x.Priority)` projects a key per element—**O(n)** key evaluations. For strings, pass **`StringComparer`** overloads when available to match your domain.

```csharp
using System;
using System.Linq;

var xs = new[] { 3, 1, 4 };
int m = xs.Max();
try
{
    _ = Array.Empty<int>().Max();
}
catch (InvalidOperationException) { /* empty */ }
```

**Performance note:** one pass; memory **O(1)** beyond iterators for simple `Min`/`Max` without sorting.
