## 2.1. OrderBy semantics: buffering, key selector costs, and "stable" behavior

1. **Sorting is inherently "buffering"**: `OrderBy` must evaluate all keys and buffer elements to produce globally sorted output (unlike `First`, which can short-circuit).
2. **Time/CPU expectations**: sorting is typically `O(n log n)` comparisons and `O(n)` additional memory for buffered state (plus key selector overhead).
3. **Key selector runs per element**: if your key selector is expensive (e.g., parsing, allocations, database calls in-memory), it directly impacts CPU and allocation rate.
4. **Stability note**: LINQ-to-Objects `OrderBy` is stable for equal keys, but providers may differ; avoid relying on ordering stability for correctness unless you control the implementation.

---

### 1. **Buffering requirement**

Unlike `Where` or `Select`, **sorting needs a global view** of keys. LINQ-to-Objects materializes elements into an internal structure, sorts, then yields. Expect **memory proportional to `n`** for the working set.

**When it hurts:** large in-memory sequences, tight RAM, or unbounded `IEnumerable<T>` you cannot afford to buffer fully.

---

### 2. **Complexity and CPU**

Comparison-based sort is **`O(n log n)`** in typical implementations. Key selector invocations multiply cost—**profile** if keys are non-trivial.

---

### 3. **Key selector cost**

If you compute the same derived key multiple times across operators, **project once** (`Select` into a record/tuple, then `OrderBy`) so the expensive work happens once per element in one pass (still buffered for sort, but avoids redundant key logic).

---

### 4. **Stability**

**LINQ-to-Objects** preserves relative order among equal keys. **EF Core** and other providers may emit SQL `ORDER BY` where tie-breaking is not guaranteed unless you add a deterministic secondary key.

**Rule:** if business logic depends on tie order, add an explicit **`ThenBy`** on a unique or stable key (e.g., primary key).

```csharp
using System;
using System.Linq;

var rows = new[]
{
    (Name: "A", Id: 2),
    (Name: "B", Id: 1),
    (Name: "A", Id: 1),
};

foreach (var r in rows.OrderBy(x => x.Name).ThenBy(x => x.Id))
    Console.WriteLine(r);
```

**Performance note:** prefer **`OrderBy`** + **`ThenBy`** over repeated sorts. For huge datasets, consider database-side ordering or specialized structures (e.g., priority queues) when appropriate.
