## 1.3. Primitive types as structures (what that implies for performance and APIs)

1. **Why “primitives are structs” matters** (copying, boxing, interface calls, generic constraints)
2. **`string` is the exception** (reference type but immutable; how that changes “value-like” reasoning)
3. **Real-world impact** (collections, APIs that take `object`, and “hidden allocations” when values box)

---

### 1. **Why “primitives are structs” matters**

**Definition.** In .NET, most “primitive” types (`int`, `double`, `bool`, `char`, `DateTime`, `Guid`, etc.) are **value types** (structs). That implies:

- **Assignment copies bits** (value semantics), not references.
- In many data structures (arrays, fields), the value is stored **inline**, not as a separate heap object.
- **Boxing is possible** (and expensive) when a value type must be treated as a reference type (`object` or a non-generic interface).

#### When it matters
- **Hot paths**: numeric loops, parsing, formatting, serialization, dictionary lookups.
- **API design**: method signatures and generic constraints can avoid boxing and reduce copying.
- **Collections**: `T[]`, `Span<T>`, `List<T>` store value types inline; this affects cache locality and copying costs.

#### Trade-offs
- **Pros**: inline storage can be cache-friendly; no per-element heap allocation; avoids GC pressure.
- **Cons**: copying can be non-trivial for larger structs; inadvertent boxing creates allocations; interface-based polymorphism can be tricky without generic constraints.

#### Common mistakes
- **Accidentally boxing in logging/formatting**:
  - `object o = 42;` boxes
  - `Console.WriteLine((object)42);` boxes
  - `ILogger.LogInformation("x={x}", x);` *may* box depending on overloads and frameworks (many logging APIs are optimized, but don’t assume—verify).
- **Treating “struct == fast”**: primitives are fast partly because they are small and JIT-special-cased; your custom 128-byte struct won’t behave like `int`.

#### Minimal example: where boxing sneaks in

```csharp
using System;
using System.Collections.Generic;

static class Demo
{
    public static void Main()
    {
        int x = 42;

        object boxed = x;            // boxing allocation
        Console.WriteLine(boxed);    // prints 42

        // Non-generic collections always store elements as object -> boxing for value types
        var legacy = new System.Collections.ArrayList { x }; // boxing

        // Generic collections store int inline -> no boxing for storage
        var modern = new List<int> { x }; // no boxing for storage
        Console.WriteLine(modern[0]);
    }
}
```

**Performance note.** In high-throughput services, a tiny “hidden” boxing allocation per request can dominate CPU due to GC. If you see Gen0 spikes under load, look for boxing in hot paths (and large temporary allocations).

**Good to know.** Boxing is covered in depth in `3.3. Boxing, interfaces, and generics`. This section focuses on why primitives being structs makes that relevant everywhere.

### 2. **`string` is the exception**

**Definition.** `string` is a **reference type** (`sealed class`) but **immutable**, which makes it *behave* value-like in many APIs (you can pass it around without fear of someone mutating its contents).

#### What changes compared to “struct thinking”
- **Assignment copies a reference**, not the characters.
- Most string operations create **new strings** (allocations), unless you use span-based APIs that avoid intermediate allocations.

#### Modern, allocation-aware patterns (C# 15 / .NET 9+)
- Prefer **`ReadOnlySpan<char>`** or **`string.AsSpan()`** for parsing/slicing without allocations.
- Prefer **`int.TryParse(ReadOnlySpan<char>, ...)`**, `Guid.TryParse(ReadOnlySpan<char>, ...)`, etc.
- For building strings, prefer **`string.Create`** or **`ValueStringBuilder`-like patterns** (internal) when you truly need performance; otherwise `string.Concat` / interpolated strings are fine.

#### Common mistakes
- Using `Substring` repeatedly in parsing loops (creates many short-lived strings).
- Splitting (`string.Split`) in hot paths (allocations for array + substrings).

#### Example: parsing without `Substring`

```csharp
using System;

static class Demo
{
    public static void Main()
    {
        var input = "id=12345";
        ReadOnlySpan<char> s = input.AsSpan();

        var eq = s.IndexOf('=');
        if (eq < 0) return;

        ReadOnlySpan<char> value = s[(eq + 1)..]; // slice only; no allocation
        if (int.TryParse(value, out var id))
            Console.WriteLine(id);
    }
}
```

**Performance note.** Spans are stack-only by design; if you need to store data long-term, you must copy to a `string` or array. That “forced copy at the boundary” is a feature: it keeps lifetimes safe.

### 3. **Real-world impact**

This is where the “primitives are structs” detail shows up in production:

- **APIs that accept `object`**: value types will box. Prefer generic overloads or strongly typed APIs.
- **Interfaces**: `IComparable`, `IFormattable`, `IEnumerable` (non-generic) can cause boxing when used through the interface type. Prefer generic interfaces (`IComparable<T>`, `IEnumerable<T>`) or generic methods with constraints.
- **Equality & hashing**: structs used as keys in hash tables should be immutable and implement `IEquatable<T>` to avoid virtual dispatch and reduce overhead.

#### Example: “object-based” APIs cost allocations

```csharp
using System;

static class Demo
{
    static void LogObject(object value) => Console.WriteLine(value);

    static void LogGeneric<T>(T value) => Console.WriteLine(value);

    public static void Main()
    {
        var n = 123;
        LogObject(n);   // boxes
        LogGeneric(n);  // no boxing for the call-site (still formats)
    }
}
```

**Good to know.**
- If you’re designing an API that will be called frequently, **avoid `object`** parameters for value-like data unless you truly need heterogeneity.
- If you must accept heterogeneous values, consider **generic + interface constraints** patterns, or accept a `ReadOnlySpan<char>` (for parsing) and keep your core domain strongly typed.
