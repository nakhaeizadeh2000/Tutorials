## 1.4. “Auto-default” structs and the `default(T)` contract (C# 11+ framing)

### What “auto-default” means

1. The language/runtime guarantee that **any** `struct T` can be produced in the **all-zero** state: `default(T)`.
2. **Parameterless struct constructors** (when present) do **not** remove `default(T)`—callers and generic code can still bypass your ctor.

### Correctness (mentor rule)

1. Decide whether **`default(T)` is valid** in your domain:
   - If **yes**: make it cheap and safe.
   - If **no**: make invalidity **detectable** cheaply and validate at **boundaries** (parsing, deserialization), not on every property access in hot loops.

### Parameterless struct constructors

1. Deep dive: [2.1 Struct constructors rules](<../2. Constructors in structs/2.1. Struct constructors rules.md>).
2. **Never** assume “every instance ran the ctor” unless you fully control creation.

### Performance

1. `default(T)` is essentially free.
2. Repeated invariant checks in accessors **are not**—design boundaries intentionally.
