## 4.3. `ref` fields (C# 11+): `ref struct` fields and ref safety

### What it is

1. A **`ref` field** can store a **managed reference** inside a `ref struct` (subject to ref safety rules).
2. This enables high-performance **view** types (`Span<T>`-like patterns) without exposing raw pointers in C#.

### Safety rules (high level)

1. **`scoped`**: limits how long a ref can escape (prevents returning references to stack memory).
2. **Ref fields** must not outlive what they refer to—compiler enforces **ref safety** (C# 11+ refinements).
3. **Async/iterator restrictions**: `ref struct` still cannot cross `await`/`yield` boundaries.

### Performance

1. **Avoid allocations** when you represent slices/views of buffers.
2. **Cost**: ref safety checks are compile-time; runtime cost is usually **pointer-sized** operations.

### When to use

1. Low-level libraries (parsers, serializers, buffers).
2. If you’re not writing hot-path infra, prefer **normal** `ReadOnlySpan<T>` locals and simpler APIs.
