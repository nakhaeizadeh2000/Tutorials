### 1. **Structured logging with correlation IDs and activity IDs**

**What is structured logging?**

- **Structured logging** uses key-value pairs instead of formatted strings.
- Enables better searching, filtering, and analysis.
- Libraries: **Serilog**, **NLog**, **Microsoft.Extensions.Logging**.

**Correlation IDs**

- **Correlation IDs** track requests across services and threads.
- Each request gets a unique ID that appears in all related log entries.
- Enables tracing a request's journey through the system.

**Example: correlation IDs**

```csharp
using Microsoft.Extensions.Logging;
using System.Diagnostics;

public class CorrelationIdMiddleware
{
    private readonly RequestDelegate _next;
    private readonly ILogger<CorrelationIdMiddleware> _logger;

    public CorrelationIdMiddleware(RequestDelegate next, ILogger<CorrelationIdMiddleware> logger)
    {
        _next = next;
        _logger = logger;
    }

    public async Task InvokeAsync(HttpContext context)
    {
        var correlationId = context.Request.Headers["X-Correlation-ID"].FirstOrDefault() 
            ?? Guid.NewGuid().ToString();
        
        // Store in AsyncLocal for async flow
        CorrelationContext.Current.CorrelationId = correlationId;
        
        context.Response.Headers["X-Correlation-ID"] = correlationId;
        
        using (_logger.BeginScope(new Dictionary<string, object>
        {
            ["CorrelationId"] = correlationId
        }))
        {
            await _next(context);
        }
    }
}

public static class CorrelationContext
{
    private static readonly AsyncLocal<string> _correlationId = new();
    
    public static string? CorrelationId
    {
        get => _correlationId.Value;
        set => _correlationId.Value = value;
    }
}

public class ServiceWithCorrelation
{
    private readonly ILogger<ServiceWithCorrelation> _logger;

    public ServiceWithCorrelation(ILogger<ServiceWithCorrelation> logger)
    {
        _logger = logger;
    }

    public async Task ProcessAsync()
    {
        // CorrelationId automatically included in all log entries
        _logger.LogInformation("Starting processing");
        
        await Task.Run(() =>
        {
            // CorrelationId flows to background thread via AsyncLocal
            _logger.LogInformation("Processing in background thread");
        });
        
        _logger.LogInformation("Completed processing");
    }
}
```

**Activity IDs (System.Diagnostics.Activity)**

- **Activity** provides built-in correlation tracking in .NET.
- Automatically propagates across async boundaries.
- Integrates with OpenTelemetry and distributed tracing.

**Example: using Activity**

```csharp
using System.Diagnostics;

public class ActivityExample
{
    private static readonly ActivitySource ActivitySource = new("MyApp");

    public async Task ProcessAsync()
    {
        using var activity = ActivitySource.StartActivity("Process");
        activity?.SetTag("operation", "process");
        
        await Step1Async();
        await Step2Async();
        
        activity?.SetStatus(ActivityStatusCode.Ok);
    }

    private async Task Step1Async()
    {
        using var activity = ActivitySource.StartActivity("Step1");
        // Activity automatically becomes child of parent
        await Task.Delay(100);
    }

    private async Task Step2Async()
    {
        using var activity = ActivitySource.StartActivity("Step2");
        await Task.Delay(100);
    }
}
```

**Structured logging with Serilog**

```csharp
using Serilog;

public class StructuredLoggingExample
{
    private readonly ILogger _logger;

    public StructuredLoggingExample()
    {
        _logger = new LoggerConfiguration()
            .WriteTo.Console(outputTemplate: 
                "[{Timestamp:HH:mm:ss} {Level:u3}] {CorrelationId} {Message:lj}{NewLine}{Exception}")
            .Enrich.FromLogContext()
            .CreateLogger();
    }

    public async Task ProcessAsync(string userId)
    {
        using (_logger.BeginScope(new Dictionary<string, object>
        {
            ["CorrelationId"] = Guid.NewGuid().ToString(),
            ["UserId"] = userId
        }))
        {
            _logger.Information("Processing started");
            
            await Task.Run(() =>
            {
                _logger.Information("Background work started");
            });
            
            _logger.Information("Processing completed");
        }
    }
}
```

**Mentor emphasis**

- **Use correlation IDs** to track requests across services and threads.
- **Use Activity** for built-in .NET correlation tracking.
- **Use structured logging** for better searchability and analysis.
- **Propagate correlation IDs** across async boundaries using `AsyncLocal` or `Activity`.

### 2. **Tracing async flows across threads and processes**

**The challenge**

- Async code can execute on **different threads**.
- Requests can span **multiple processes** or services.
- Need to **trace** the flow across these boundaries.

**Using Activity for async tracing**

- `Activity` automatically flows across async boundaries.
- Works with `async`/`await` and `Task.Run`.

**Example: tracing async flow**

```csharp
using System.Diagnostics;

public class AsyncTracingExample
{
    private static readonly ActivitySource ActivitySource = new("MyApp");

    public async Task ProcessAsync()
    {
        using var activity = ActivitySource.StartActivity("Process");
        
        // Activity flows to background thread
        await Task.Run(async () =>
        {
            using var childActivity = ActivitySource.StartActivity("BackgroundWork");
            await Task.Delay(100);
        });
        
        // Activity flows back to original context
        await ContinueAsync();
    }

    private async Task ContinueAsync()
    {
        using var activity = ActivitySource.StartActivity("Continue");
        await Task.Delay(100);
    }
}
```

**Tracing across processes (distributed tracing)**

- Use **OpenTelemetry** or **Application Insights** for distributed tracing.
- Propagate trace context via HTTP headers or message properties.

**Example: distributed tracing**

```csharp
using System.Diagnostics;
using System.Net.Http;

public class DistributedTracingExample
{
    private static readonly ActivitySource ActivitySource = new("MyApp");
    private readonly HttpClient _httpClient;

    public async Task CallServiceAsync(string url)
    {
        using var activity = ActivitySource.StartActivity("CallService");
        
        var request = new HttpRequestMessage(HttpMethod.Get, url);
        
        // Inject trace context into HTTP headers
        Activity.Current?.SetBaggage("custom-baggage", "value");
        
        // HttpClient automatically injects trace context headers
        var response = await _httpClient.SendAsync(request);
    }
}
```

**Custom async flow tracking**

```csharp
public class AsyncFlowTracker
{
    private static readonly AsyncLocal<string> _flowId = new();

    public static string? FlowId
    {
        get => _flowId.Value;
        set => _flowId.Value = value;
    }

    public static IDisposable BeginFlow(string flowId)
    {
        var previous = FlowId;
        FlowId = flowId;
        return new FlowScope(previous);
    }

    private class FlowScope : IDisposable
    {
        private readonly string? _previous;

        public FlowScope(string? previous)
        {
            _previous = previous;
        }

        public void Dispose()
        {
            FlowId = _previous;
        }
    }
}

public class ServiceWithFlowTracking
{
    private readonly ILogger _logger;

    public async Task ProcessAsync()
    {
        using (AsyncFlowTracker.BeginFlow(Guid.NewGuid().ToString()))
        {
            _logger.LogInformation("Flow started: {FlowId}", AsyncFlowTracker.FlowId);
            
            await Task.Run(() =>
            {
                // FlowId flows to background thread
                _logger.LogInformation("Background work: {FlowId}", AsyncFlowTracker.FlowId);
            });
        }
    }
}
```

**Mentor emphasis**

- **Use Activity** for automatic async flow tracking.
- **Propagate trace context** across process boundaries.
- **Use AsyncLocal** for custom flow tracking if needed.
- **Log flow IDs** at key points to trace execution.

### 3. **EventSource, ETW, and Activity integration**

**What is EventSource?**

- **EventSource** is .NET's built-in event tracing infrastructure.
- Integrates with **ETW** (Event Tracing for Windows) and **LTTng** (Linux).
- Provides high-performance, structured event logging.

**Creating an EventSource**

```csharp
using System.Diagnostics.Tracing;

[EventSource(Name = "MyApp")]
public class MyAppEventSource : EventSource
{
    public static readonly MyAppEventSource Log = new();

    [Event(1)]
    public void RequestStart(string correlationId)
    {
        WriteEvent(1, correlationId);
    }

    [Event(2)]
    public void RequestStop(string correlationId, long durationMs)
    {
        WriteEvent(2, correlationId, durationMs);
    }

    [Event(3)]
    public void Error(string correlationId, string error)
    {
        WriteEvent(3, correlationId, error);
    }
}

public class ServiceUsingEventSource
{
    public async Task ProcessAsync(string correlationId)
    {
        MyAppEventSource.Log.RequestStart(correlationId);
        var sw = System.Diagnostics.Stopwatch.StartNew();
        
        try
        {
            await DoWorkAsync();
            MyAppEventSource.Log.RequestStop(correlationId, sw.ElapsedMilliseconds);
        }
        catch (Exception ex)
        {
            MyAppEventSource.Log.Error(correlationId, ex.Message);
            throw;
        }
    }

    private async Task DoWorkAsync()
    {
        await Task.Delay(100);
    }
}
```

**Listening to EventSource events**

```csharp
using System.Diagnostics.Tracing;

public class EventSourceListener
{
    public void StartListening()
    {
        var listener = new EventListener();
        listener.EventSourceCreated += (sender, e) =>
        {
            if (e.EventSource.Name == "MyApp")
            {
                listener.EnableEvents(e.EventSource, EventLevel.Informational);
            }
        };
        
        listener.EventWritten += (sender, e) =>
        {
            Console.WriteLine($"{e.EventName}: {string.Join(", ", e.PayloadNames.Zip(e.Payload))}");
        };
    }
}
```

**Activity integration**

- `Activity` can emit EventSource events automatically.
- Enable with `Activity.DefaultIdFormat = ActivityIdFormat.W3C`.

**Example: Activity with EventSource**

```csharp
using System.Diagnostics;
using System.Diagnostics.Tracing;

public class ActivityEventSourceIntegration
{
    private static readonly ActivitySource ActivitySource = new("MyApp");

    public async Task ProcessAsync()
    {
        // Enable Activity events
        Activity.DefaultIdFormat = ActivityIdFormat.W3C;
        
        using var activity = ActivitySource.StartActivity("Process");
        activity?.SetTag("key", "value");
        
        await Task.Delay(100);
    }
}
```

**Using dotnet-trace with EventSource**

```bash
# Collect EventSource events
dotnet-trace collect -p <process-id> --providers MyApp

# View events
dotnet-trace view trace.nettrace
```

**Mentor emphasis**

- **Use EventSource** for high-performance event logging.
- **Integrate with Activity** for automatic correlation.
- **Use ETW/LTTng** for system-wide event collection.
- **Use dotnet-trace** to collect and analyze events.

### 4. **Using dotnet-trace, dotnet-counters, and dotnet-dump**

**dotnet-trace**

- **dotnet-trace** collects runtime events and traces.
- Useful for profiling and diagnosing performance issues.

**Example: collecting traces**

```bash
# Collect trace from running process
dotnet-trace collect -p <process-id> --providers Microsoft-DotNETCore-SampleProfiler

# Collect trace with custom providers
dotnet-trace collect -p <process-id> --providers MyApp:Informational

# View trace
dotnet-trace view trace.nettrace
```

**dotnet-counters**

- **dotnet-counters** monitors performance counters in real-time.
- Useful for monitoring production systems.

**Example: monitoring counters**

```bash
# Monitor all counters
dotnet-counters monitor -p <process-id>

# Monitor specific counters
dotnet-counters monitor -p <process-id> System.Runtime

# Monitor with custom interval
dotnet-counters monitor -p <process-id> --refresh-interval 1
```

**Common counters for concurrency**

- `ThreadPool Thread Count`: Number of ThreadPool threads.
- `ThreadPool Queue Length`: Pending work items.
- `Lock Contention`: Lock contention events.
- `GC Collections`: Garbage collection frequency.

**dotnet-dump**

- **dotnet-dump** creates and analyzes memory dumps.
- Useful for diagnosing deadlocks and hangs.

**Example: creating and analyzing dumps**

```bash
# Create dump
dotnet-dump collect -p <process-id>

# Analyze dump
dotnet-dump analyze dump.dmp

# Commands in analyzer
clrthreads          # List threads
clrstack            # Show call stack
syncblk             # Show lock information
dumpheap            # Show heap information
```

**Mentor emphasis**

- **Use dotnet-trace** for profiling and event collection.
- **Use dotnet-counters** for real-time monitoring.
- **Use dotnet-dump** for post-mortem analysis of deadlocks.
- **Monitor ThreadPool and lock contention** counters in production.

### 5. **Designing logs that help debug concurrency issues (not make them worse)**

**The problem**

- **Poor logging** can make concurrency issues harder to debug.
- **Missing context** makes it impossible to trace execution flow.
- **Excessive logging** can cause performance issues and hide real problems.

**Best practices**

1. **Include correlation IDs** in all log entries.
2. **Log at key boundaries** (method entry/exit, async boundaries).
3. **Include thread IDs** when relevant.
4. **Use structured logging** for better analysis.
5. **Avoid logging in hot paths** without sampling.

**Example: good logging**

```csharp
public class GoodLoggingExample
{
    private readonly ILogger _logger;

    public async Task ProcessAsync(string requestId)
    {
        using (_logger.BeginScope(new Dictionary<string, object>
        {
            ["RequestId"] = requestId,
            ["ThreadId"] = Thread.CurrentThread.ManagedThreadId
        }))
        {
            _logger.LogInformation("Processing started");
            
            await Task.Run(async () =>
            {
                // Log thread switch
                _logger.LogDebug("Switched to background thread {ThreadId}", 
                    Thread.CurrentThread.ManagedThreadId);
                
                await DoWorkAsync();
            });
            
            _logger.LogInformation("Processing completed");
        }
    }
}
```

**Avoiding log-induced performance issues**

- **Don't log in tight loops** without sampling.
- **Use appropriate log levels** (Debug for verbose, Information for important events).
- **Avoid string formatting** in hot paths (use structured logging).

**Example: sampling logs**

```csharp
public class SampledLoggingExample
{
    private readonly ILogger _logger;
    private int _logCounter = 0;

    public void ProcessManyItems(int[] items)
    {
        for (int i = 0; i < items.Length; i++)
        {
            ProcessItem(items[i]);
            
            // Log every 1000th item
            if (Interlocked.Increment(ref _logCounter) % 1000 == 0)
            {
                _logger.LogDebug("Processed {Count} items", _logCounter);
            }
        }
    }

    private void ProcessItem(int item)
    {
        // Fast processing, no logging
    }
}
```

**Logging async boundaries**

```csharp
public class AsyncBoundaryLogging
{
    private readonly ILogger _logger;

    public async Task ProcessAsync()
    {
        _logger.LogDebug("Before await, thread {ThreadId}", 
            Thread.CurrentThread.ManagedThreadId);
        
        await Task.Delay(100);
        
        _logger.LogDebug("After await, thread {ThreadId}", 
            Thread.CurrentThread.ManagedThreadId);
    }
}
```

**Logging lock acquisition**

```csharp
public class LockLoggingExample
{
    private readonly ILogger _logger;
    private readonly object _lock = new();

    public void ProcessWithLock()
    {
        _logger.LogDebug("Attempting to acquire lock, thread {ThreadId}", 
            Thread.CurrentThread.ManagedThreadId);
        
        lock (_lock)
        {
            _logger.LogDebug("Lock acquired, thread {ThreadId}", 
                Thread.CurrentThread.ManagedThreadId);
            
            try
            {
                DoWork();
            }
            finally
            {
                _logger.LogDebug("Releasing lock, thread {ThreadId}", 
                    Thread.CurrentThread.ManagedThreadId);
            }
        }
    }
}
```

**Mentor emphasis**

- **Include correlation IDs** and **thread IDs** in logs.
- **Log at async boundaries** to trace execution flow.
- **Use structured logging** for better analysis.
- **Avoid excessive logging** in hot paths (use sampling).
- **Use appropriate log levels** (Debug vs Information vs Warning).

- **EventSource** provides high-performance event logging.

- **Design logs** to help debug concurrency issues, not make them worse.
