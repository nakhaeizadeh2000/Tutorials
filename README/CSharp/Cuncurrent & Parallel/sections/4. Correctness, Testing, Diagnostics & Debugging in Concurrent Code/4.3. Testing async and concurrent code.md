### 1. **Unit testing async methods with Task and async/await**

**Basic async test pattern**

- Async test methods should return `Task` or `Task<T>`.
- Use `await` to wait for async operations.
- Test frameworks (xUnit, NUnit, MSTest) support async tests natively.

**Example: simple async test**

```csharp
using System;
using System.Net.Http;
using System.Threading.Tasks;
using Xunit;

public class AsyncTests
{
    [Fact]
    public async Task DownloadAsync_ReturnsContent()
    {
        // Arrange
        using var http = new HttpClient();
        var service = new DownloadService(http);

        // Act
        string content = await service.DownloadAsync("https://example.com");

        // Assert
        Assert.NotNull(content);
        Assert.NotEmpty(content);
    }
}

public class DownloadService
{
    private readonly HttpClient _http;

    public DownloadService(HttpClient http) => _http = http;

    public async Task<string> DownloadAsync(string url)
    {
        var response = await _http.GetAsync(url);
        response.EnsureSuccessStatusCode();
        return await response.Content.ReadAsStringAsync();
    }
}
```

- The test method is `async Task`, and we `await` the async operation.
- Test frameworks handle async tests automatically.

**Testing exceptions in async code**

```csharp
[Fact]
public async Task DownloadAsync_ThrowsOnFailure()
{
    // Arrange
    using var http = new HttpClient();
    var service = new DownloadService(http);

    // Act & Assert
    await Assert.ThrowsAsync<HttpRequestException>(
        () => service.DownloadAsync("https://invalid-url-that-does-not-exist.com"));
}
```

- Use `Assert.ThrowsAsync<T>` for async methods that throw exceptions.

**Testing cancellation**

```csharp
[Fact]
public async Task DownloadAsync_RespectsCancellation()
{
    // Arrange
    using var http = new HttpClient();
    var service = new DownloadService(http);
    using var cts = new CancellationTokenSource();
    cts.Cancel(); // Cancel immediately

    // Act & Assert
    await Assert.ThrowsAsync<TaskCanceledException>(
        () => service.DownloadAsync("https://example.com", cts.Token));
}

// Updated service method
public async Task<string> DownloadAsync(string url, CancellationToken cancellationToken = default)
{
    var response = await _http.GetAsync(url, cancellationToken);
    response.EnsureSuccessStatusCode();
    return await response.Content.ReadAsStringAsync();
}
```

- Test cancellation by creating a `CancellationTokenSource` and canceling it.

**Testing multiple async operations**

```csharp
[Fact]
public async Task ProcessMultipleAsync_CompletesAll()
{
    // Arrange
    var service = new ProcessingService();
    var items = new[] { "item1", "item2", "item3" };

    // Act
    var results = await Task.WhenAll(
        items.Select(item => service.ProcessAsync(item)));

    // Assert
    Assert.Equal(3, results.Length);
    Assert.All(results, result => Assert.True(result.Success));
}
```

- Use `Task.WhenAll` to test multiple concurrent operations.

**Testing with ConfigureAwait**

```csharp
[Fact]
public async Task ServiceMethod_UsesConfigureAwaitFalse()
{
    // Arrange
    var service = new LibraryService();

    // Act (should not deadlock even if SynchronizationContext exists)
    var result = await service.GetDataAsync().ConfigureAwait(false);

    // Assert
    Assert.NotNull(result);
}
```

- Test that library code uses `ConfigureAwait(false)` to avoid deadlocks (see 2.3, 4.5).

**Mentor emphasis**

- Always return `Task` from async test methods (never `async void`).
- Use `await` to wait for async operations (never `.Result` or `.Wait()`).
- Test cancellation, exceptions, and concurrent scenarios explicitly.

### 2. **Avoiding async void in testable code**

**Why `async void` is problematic**

- `async void` methods:
  - **Cannot be awaited** (not testable).
  - **Exceptions crash the process** or go to `SynchronizationContext.UnhandledException`.
  - **Cannot be composed** with other async operations.
  - **Difficult to test** (no way to wait for completion).

**The one exception: event handlers**

- UI event handlers (`Button_Click`, etc.) must be `async void` due to language constraints.
- For all other code, **never use `async void`**.

**Example: bad async void**

```csharp
// BAD: Cannot be tested or awaited
public class BadService
{
    public async void ProcessAsync(string data)
    {
        await Task.Delay(100);
        // If this throws, it crashes the process!
        Process(data);
    }
}

// GOOD: Returns Task
public class GoodService
{
    public async Task ProcessAsync(string data)
    {
        await Task.Delay(100);
        Process(data);
        // Exceptions are caught by caller
    }
}
```

**Testing async void (if you must)**

- If you have legacy code with `async void`, you can't easily test it.
- **Refactor** to return `Task` instead.

**Example: refactoring async void**

```csharp
// Before: async void (untestable)
public class LegacyService
{
    public async void StartProcessing()
    {
        await ProcessItemsAsync();
    }

    private async Task ProcessItemsAsync() { /* ... */ }
}

// After: async Task (testable)
public class RefactoredService
{
    public async Task StartProcessingAsync()
    {
        await ProcessItemsAsync();
    }

    private async Task ProcessItemsAsync() { /* ... */ }
}

// UI event handler wraps the testable method
public partial class MainWindow
{
    private readonly RefactoredService _service = new();

    private async void StartButton_Click(object sender, RoutedEventArgs e)
    {
        // UI event handler can be async void, but it calls testable code
        await _service.StartProcessingAsync();
    }
}
```

**Detecting async void in tests**

- Static analyzers (e.g., Roslyn analyzers) can detect `async void` usage.
- Add analyzer rules to prevent `async void` except in event handlers.

**Mentor emphasis**

- **Never use `async void`** except in UI event handlers.
- **Refactor legacy code** to return `Task`.
- **Test async methods** by awaiting them in tests.

### 3. **Controlling time: fake/virtual clocks and timers**

**Why control time?**

- Tests that depend on real time are:
  - **Slow** (waiting for delays).
  - **Flaky** (timing-dependent).
  - **Non-deterministic** (can fail intermittently).

- **Virtual clocks** allow tests to control time and make tests fast and deterministic.

**Abstracting time**

```csharp
public interface IClock
{
    DateTime UtcNow { get; }
    Task DelayAsync(TimeSpan delay, CancellationToken cancellationToken = default);
}

public class SystemClock : IClock
{
    public DateTime UtcNow => DateTime.UtcNow;

    public Task DelayAsync(TimeSpan delay, CancellationToken cancellationToken = default)
        => Task.Delay(delay, cancellationToken);
}

public class FakeClock : IClock
{
    private DateTime _utcNow = new DateTime(2024, 1, 1, 0, 0, 0, DateTimeKind.Utc);
    private readonly List<(DateTime Time, TaskCompletionSource<bool> Tcs)> _delays = new();

    public DateTime UtcNow => _utcNow;

    public Task DelayAsync(TimeSpan delay, CancellationToken cancellationToken = default)
    {
        var targetTime = _utcNow + delay;
        var tcs = new TaskCompletionSource<bool>();
        _delays.Add((targetTime, tcs));
        return tcs.Task;
    }

    public void Advance(TimeSpan amount)
    {
        _utcNow += amount;
        // Complete any delays that are now due
        var completed = _delays.Where(d => d.Time <= _utcNow).ToList();
        foreach (var delay in completed)
        {
            _delays.Remove(delay);
            delay.Tcs.SetResult(true);
        }
    }

    public void AdvanceTo(DateTime targetTime)
    {
        if (targetTime < _utcNow)
            throw new ArgumentException("Cannot go backwards in time");

        Advance(targetTime - _utcNow);
    }
}
```

**Using the clock abstraction**

```csharp
public class TimeBasedService
{
    private readonly IClock _clock;

    public TimeBasedService(IClock clock) => _clock = clock;

    public async Task<string> ProcessWithTimeoutAsync(string data, TimeSpan timeout)
    {
        var startTime = _clock.UtcNow;
        
        // Simulate work
        await _clock.DelayAsync(TimeSpan.FromSeconds(1));
        
        if (_clock.UtcNow - startTime > timeout)
        {
            throw new TimeoutException();
        }

        return $"Processed: {data}";
    }
}
```

**Testing with fake clock**

```csharp
[Fact]
public async Task ProcessWithTimeoutAsync_CompletesWithinTimeout()
{
    // Arrange
    var clock = new FakeClock();
    var service = new TimeBasedService(clock);

    // Act
    var task = service.ProcessWithTimeoutAsync("test", TimeSpan.FromSeconds(5));
    
    // Advance time by 1 second (work completes)
    clock.Advance(TimeSpan.FromSeconds(1));
    
    var result = await task;

    // Assert
    Assert.Equal("Processed: test", result);
}

[Fact]
public async Task ProcessWithTimeoutAsync_ThrowsOnTimeout()
{
    // Arrange
    var clock = new FakeClock();
    var service = new TimeBasedService(clock);

    // Act
    var task = service.ProcessWithTimeoutAsync("test", TimeSpan.FromSeconds(1));
    
    // Advance time beyond timeout
    clock.Advance(TimeSpan.FromSeconds(2));
    
    // Assert
    await Assert.ThrowsAsync<TimeoutException>(() => task);
}
```

**Abstracting timers**

```csharp
public interface ITimer
{
    event EventHandler Elapsed;
    void Start();
    void Stop();
    bool Enabled { get; }
}

public class SystemTimer : ITimer
{
    private readonly System.Timers.Timer _timer;

    public SystemTimer(TimeSpan interval)
    {
        _timer = new System.Timers.Timer(interval.TotalMilliseconds);
        _timer.Elapsed += (sender, e) => Elapsed?.Invoke(sender, e);
    }

    public event EventHandler? Elapsed;
    public void Start() => _timer.Start();
    public void Stop() => _timer.Stop();
    public bool Enabled => _timer.Enabled;
}

public class FakeTimer : ITimer
{
    private readonly FakeClock _clock;
    private readonly TimeSpan _interval;
    private DateTime? _nextElapse;
    private bool _enabled;

    public FakeTimer(FakeClock clock, TimeSpan interval)
    {
        _clock = clock;
        _interval = interval;
    }

    public event EventHandler? Elapsed;

    public void Start()
    {
        _enabled = true;
        _nextElapse = _clock.UtcNow + _interval;
    }

    public void Stop() => _enabled = false;

    public bool Enabled => _enabled;

    public void Advance(TimeSpan amount)
    {
        if (!_enabled || _nextElapse == null) return;

        _clock.Advance(amount);
        
        while (_enabled && _nextElapse <= _clock.UtcNow)
        {
            Elapsed?.Invoke(this, EventArgs.Empty);
            _nextElapse = _nextElapse.Value + _interval;
        }
    }
}
```

**Testing timer-based code**

```csharp
[Fact]
public async Task TimerService_FiresPeriodically()
{
    // Arrange
    var clock = new FakeClock();
    var timer = new FakeTimer(clock, TimeSpan.FromSeconds(1));
    var service = new TimerService(timer);
    int fireCount = 0;
    service.TimerElapsed += (sender, e) => fireCount++;

    // Act
    service.Start();
    clock.Advance(TimeSpan.FromSeconds(3)); // Advance 3 seconds

    // Assert
    await Task.Delay(10); // Small delay to process events
    Assert.Equal(3, fireCount); // Should fire 3 times
}
```

**Mentor emphasis**

- **Abstract time dependencies** (clocks, timers, delays) for testability.
- **Use fake clocks** to make tests fast and deterministic.
- **Never use `Thread.Sleep` or `Task.Delay`** in tests without controlling time.

### 4. **Testing code using Parallel.\* and PLINQ**

**Testing Parallel.For**

```csharp
[Fact]
public void ParallelFor_ProcessesAllItems()
{
    // Arrange
    var items = Enumerable.Range(0, 1000).ToArray();
    var results = new ConcurrentBag<int>();

    // Act
    Parallel.For(0, items.Length, i =>
    {
        results.Add(items[i] * 2);
    });

    // Assert
    Assert.Equal(1000, results.Count);
    Assert.All(results, r => Assert.True(r % 2 == 0));
}
```

- Use `ConcurrentBag` or other thread-safe collections to collect results.
- Verify that all items are processed.

**Testing Parallel.ForEach**

```csharp
[Fact]
public void ParallelForEach_ProcessesAllItems()
{
    // Arrange
    var items = Enumerable.Range(0, 100).Select(i => $"item{i}").ToList();
    var processed = new ConcurrentDictionary<string, bool>();

    // Act
    Parallel.ForEach(items, item =>
    {
        processed[item] = true;
    });

    // Assert
    Assert.Equal(100, processed.Count);
    Assert.All(items, item => Assert.True(processed.ContainsKey(item)));
}
```

**Testing PLINQ**

```csharp
[Fact]
public void PLINQ_ProcessesAndAggregates()
{
    // Arrange
    var numbers = Enumerable.Range(1, 1000);

    // Act
    var sum = numbers.AsParallel()
        .Select(x => x * 2)
        .Sum();

    // Assert
    Assert.Equal(1001000, sum); // Sum of 2, 4, 6, ..., 2000
}

[Fact]
public void PLINQ_MaintainsOrderWhenRequested()
{
    // Arrange
    var numbers = Enumerable.Range(1, 100);

    // Act
    var ordered = numbers.AsParallel()
        .AsOrdered()
        .Select(x => x * 2)
        .ToArray();

    // Assert
    Assert.Equal(Enumerable.Range(1, 100).Select(x => x * 2), ordered);
}
```

**Testing cancellation**

```csharp
[Fact]
public void ParallelFor_RespectsCancellation()
{
    // Arrange
    using var cts = new CancellationTokenSource();
    var items = Enumerable.Range(0, 10000).ToArray();
    int processedCount = 0;

    // Act
    cts.CancelAfter(10); // Cancel after 10ms
    
    try
    {
        Parallel.For(0, items.Length, new ParallelOptions
        {
            CancellationToken = cts.Token
        }, i =>
        {
            Interlocked.Increment(ref processedCount);
            Thread.Sleep(1); // Simulate work
        });
    }
    catch (OperationCanceledException)
    {
        // Expected
    }

    // Assert
    Assert.True(processedCount < items.Length); // Should not process all items
}
```

**Testing with custom ParallelOptions**

```csharp
[Fact]
public void ParallelFor_RespectsMaxDegreeOfParallelism()
{
    // Arrange
    var items = Enumerable.Range(0, 100).ToArray();
    var maxConcurrency = new ConcurrentBag<int>();
    int currentConcurrency = 0;

    // Act
    Parallel.For(0, items.Length, new ParallelOptions
    {
        MaxDegreeOfParallelism = 4
    }, i =>
    {
        var concurrency = Interlocked.Increment(ref currentConcurrency);
        maxConcurrency.Add(concurrency);
        Thread.Sleep(10); // Simulate work
        Interlocked.Decrement(ref currentConcurrency);
    });

    // Assert
    Assert.True(maxConcurrency.Max() <= 4); // Should never exceed 4
}
```

**Testing for race conditions**

- Use stress testing (see 4.4) to expose race conditions.
- Run tests multiple times with different thread counts.

**Mentor emphasis**

- Use **thread-safe collections** (`ConcurrentBag`, `ConcurrentDictionary`) to collect results.
- Test **cancellation** and **parallelism limits** explicitly.
- Use **stress testing** (4.4) to expose race conditions in parallel code.

### 5. **Dealing with flakiness and nondeterminism in tests**

**Why tests are flaky**

- **Timing-dependent**: Tests that rely on specific timing can fail intermittently.
- **Race conditions**: Tests that don't properly synchronize can have race conditions.
- **Resource contention**: Tests that share resources (files, ports, etc.) can interfere.
- **Non-deterministic behavior**: Some operations (e.g., `Parallel.For`) have non-deterministic ordering.

**Making tests deterministic**

1. **Eliminate timing dependencies** (use fake clocks, see above).
2. **Use proper synchronization** in test code.
3. **Isolate resources** (each test gets its own resources).
4. **Avoid shared mutable state** between tests.

**Example: flaky test**

```csharp
// BAD: Flaky test
[Fact]
public async Task FlakyTest()
{
    var service = new Service();
    
    var task1 = service.ProcessAsync("item1");
    var task2 = service.ProcessAsync("item2");
    
    // BUG: Assumes task1 completes first (non-deterministic)
    var result1 = await task1;
    var result2 = await task2;
    
    Assert.Equal("item1", result1);
    Assert.Equal("item2", result2);
}
```

**Fixed: deterministic test**

```csharp
// GOOD: Deterministic test
[Fact]
public async Task DeterministicTest()
{
    var service = new Service();
    
    // Wait for both, then verify results
    var results = await Task.WhenAll(
        service.ProcessAsync("item1"),
        service.ProcessAsync("item2"));
    
    // Verify both results are present (order doesn't matter)
    Assert.Contains("item1", results);
    Assert.Contains("item2", results);
}
```

**Using retries (last resort)**

- **Avoid retries** if possible (fix the root cause).
- If retries are necessary (e.g., for integration tests with external services), use them sparingly.

```csharp
[Fact]
public async Task FlakyIntegrationTest_WithRetry()
{
    // Only use retries for integration tests, not unit tests
    const int maxRetries = 3;
    Exception? lastException = null;

    for (int i = 0; i < maxRetries; i++)
    {
        try
        {
            var result = await CallExternalServiceAsync();
            Assert.NotNull(result);
            return; // Success
        }
        catch (Exception ex)
        {
            lastException = ex;
            if (i < maxRetries - 1)
            {
                await Task.Delay(100 * (i + 1)); // Exponential backoff
            }
        }
    }

    Assert.Fail($"Test failed after {maxRetries} retries: {lastException}");
}
```

**Isolating test data**

```csharp
public class IsolatedTestFixture
{
    private readonly string _testDirectory;

    public IsolatedTestFixture()
    {
        // Each test gets its own directory
        _testDirectory = Path.Combine(Path.GetTempPath(), Guid.NewGuid().ToString());
        Directory.CreateDirectory(_testDirectory);
    }

    public void Dispose()
    {
        Directory.Delete(_testDirectory, recursive: true);
    }

    public string GetTestFilePath(string fileName)
        => Path.Combine(_testDirectory, fileName);
}

[Fact]
public void FileTest_Isolated()
{
    using var fixture = new IsolatedTestFixture();
    var filePath = fixture.GetTestFilePath("test.txt");
    
    File.WriteAllText(filePath, "test");
    var content = File.ReadAllText(filePath);
    
    Assert.Equal("test", content);
}
```

**Mentor emphasis**

- **Eliminate timing dependencies** using fake clocks and controlled delays.
- **Isolate test data** (each test gets its own resources).
- **Avoid shared mutable state** between tests.
- **Use retries only for integration tests**, and fix root causes when possible.
- **Make tests deterministic** by controlling all sources of non-determinism.

---

**Summary**

- Return `Task` from async test methods and use `await`.
- Avoid `async void` except in UI event handlers.
- Use fake clocks and timers to control time in tests.
- Use thread-safe collections when testing parallel code.
- Make tests deterministic by eliminating timing dependencies and isolating resources.
