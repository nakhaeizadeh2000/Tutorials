## 4.9. Making concurrent code more testable and diagnosable

1. **Injecting schedulers, clocks, and executors instead of using static APIs**
2. **Abstracting timers, delays, and background work**
3. **Designing APIs for deterministic tests (no hidden threads/tasks)**
4. **Separating orchestration from core logic**
5. **Adding diagnostic hooks safely (counters, events, probes)**

---

This section covers **design patterns** for making concurrent code testable and diagnosable. Well-designed concurrent code is easier to test, debug, and monitor in production.

### 1. **Injecting schedulers, clocks, and executors instead of using static APIs**

**The problem with static APIs**

- **Static APIs** (`Task.Run`, `Task.Delay`, `DateTime.UtcNow`) are hard to test.
- **Non-deterministic**: Can't control timing or execution order.
- **Hard to mock**: Can't replace with test doubles.

**Solution: dependency injection**

- **Inject** schedulers, clocks, and executors as dependencies.
- **Replace** with test doubles in tests.
- **Control** timing and execution in tests.

**Example: injecting TaskScheduler**

```csharp
public interface ITaskScheduler
{
    Task Run(Action action);
    Task<T> Run<T>(Func<T> function);
}

public class DefaultTaskScheduler : ITaskScheduler
{
    public Task Run(Action action) => Task.Run(action);
    public Task<T> Run<T>(Func<T> function) => Task.Run(function);
}

public class TestTaskScheduler : ITaskScheduler
{
    private readonly Queue<Action> _queue = new();
    private readonly object _lock = new();

    public Task Run(Action action)
    {
        var tcs = new TaskCompletionSource<object>();
        lock (_lock)
        {
            _queue.Enqueue(() =>
            {
                try
                {
                    action();
                    tcs.SetResult(null!);
                }
                catch (Exception ex)
                {
                    tcs.SetException(ex);
                }
            });
        }
        return tcs.Task;
    }

    public Task<T> Run<T>(Func<T> function)
    {
        var tcs = new TaskCompletionSource<T>();
        lock (_lock)
        {
            _queue.Enqueue(() =>
            {
                try
                {
                    tcs.SetResult(function());
                }
                catch (Exception ex)
                {
                    tcs.SetException(ex);
                }
            });
        }
        return tcs.Task;
    }

    public void ExecuteAll()
    {
        while (true)
        {
            Action? action;
            lock (_lock)
            {
                if (_queue.Count == 0) break;
                action = _queue.Dequeue();
            }
            action();
        }
    }
}

public class ServiceWithScheduler
{
    private readonly ITaskScheduler _scheduler;

    public ServiceWithScheduler(ITaskScheduler scheduler)
    {
        _scheduler = scheduler;
    }

    public async Task ProcessAsync()
    {
        await _scheduler.Run(() =>
        {
            // Background work
            Console.WriteLine("Background work");
        });
    }
}
```

**Example: injecting clock**

```csharp
public interface IClock
{
    DateTime UtcNow { get; }
    Task DelayAsync(TimeSpan delay, CancellationToken cancellationToken = default);
}

public class SystemClock : IClock
{
    public DateTime UtcNow => DateTime.UtcNow;
    public Task DelayAsync(TimeSpan delay, CancellationToken cancellationToken = default)
        => Task.Delay(delay, cancellationToken);
}

public class FakeClock : IClock
{
    private DateTime _utcNow = new DateTime(2024, 1, 1, 0, 0, 0, DateTimeKind.Utc);
    private readonly List<(DateTime Time, TaskCompletionSource<bool> Tcs)> _delays = new();

    public DateTime UtcNow => _utcNow;

    public Task DelayAsync(TimeSpan delay, CancellationToken cancellationToken = default)
    {
        var targetTime = _utcNow + delay;
        var tcs = new TaskCompletionSource<bool>();
        _delays.Add((targetTime, tcs));
        return tcs.Task;
    }

    public void Advance(TimeSpan amount)
    {
        _utcNow += amount;
        var completed = _delays.Where(d => d.Time <= _utcNow).ToList();
        foreach (var delay in completed)
        {
            _delays.Remove(delay);
            delay.Tcs.SetResult(true);
        }
    }
}

public class ServiceWithClock
{
    private readonly IClock _clock;

    public ServiceWithClock(IClock clock)
    {
        _clock = clock;
    }

    public async Task ProcessWithTimeoutAsync(TimeSpan timeout)
    {
        var startTime = _clock.UtcNow;
        await _clock.DelayAsync(TimeSpan.FromSeconds(1));
        
        if (_clock.UtcNow - startTime > timeout)
        {
            throw new TimeoutException();
        }
    }
}
```

**Example: injecting executor**

```csharp
public interface IExecutor
{
    void Execute(Action action);
    Task ExecuteAsync(Func<Task> action);
}

public class ThreadPoolExecutor : IExecutor

    public void Execute(Action action) => Task.Run(action);

}

public class SynchronousExecutor : IExecutor
{
    public void Execute(Action action) => action();
    public Task ExecuteAsync(Func<Task> action) => action();
}

public class ServiceWithExecutor

    private readonly IExecutor _executor;

    public ServiceWithExecutor(IExecutor executor)
    {
        _executor = executor;

        {
            // Background work
        });
    }
}
```

**Mentor emphasis**

- **Inject dependencies** instead of using static APIs.
- **Use interfaces** for testability.
- **Provide test doubles** for deterministic tests.
- **Control timing** and execution order in tests.

### 2. **Abstracting timers, delays, and background work**

**The problem**

- **Timers** (`System.Timers.Timer`, `System.Threading.Timer`) are hard to test.
- **Delays** (`Task.Delay`, `Thread.Sleep`) make tests slow and non-deterministic.
- **Background work** is hard to control in tests.

**Solution: abstract timers and delays**

- **Abstract** timers and delays behind interfaces.
- **Replace** with test doubles in tests.
- **Control** timing in tests.

**Example: abstracting timer**

```csharp
public interface ITimer
{
    event EventHandler Elapsed;
    void Start();
    void Stop();
    bool Enabled { get; }
    TimeSpan Interval { get; set; }
}

public class SystemTimer : ITimer
{
    private readonly System.Timers.Timer _timer;

    public SystemTimer(TimeSpan interval)
    {
        _timer = new System.Timers.Timer(interval.TotalMilliseconds);
        _timer.Elapsed += (sender, e) => Elapsed?.Invoke(sender, e);
    }

    public event EventHandler? Elapsed;
    public void Start() => _timer.Start();
    public void Stop() => _timer.Stop();
    public bool Enabled => _timer.Enabled;
    public TimeSpan Interval
    {
        get => TimeSpan.FromMilliseconds(_timer.Interval);
        set => _timer.Interval = value.TotalMilliseconds;
    }
}

public class FakeTimer : ITimer
{
    private readonly IClock _clock;
    private readonly TimeSpan _interval;
    private DateTime? _nextElapse;
    private bool _enabled;

    public FakeTimer(IClock clock, TimeSpan interval)
    {
        _clock = clock;
        _interval = interval;
    }

    public event EventHandler? Elapsed;

    public void Start()
    {
        _enabled = true;
        _nextElapse = _clock.UtcNow + _interval;
    }

    public void Stop() => _enabled = false;

    public bool Enabled => _enabled;

    public TimeSpan Interval { get; set; }

    public void Advance(TimeSpan amount)
    {
        if (!_enabled || _nextElapse == null) return;

        var newTime = _clock.UtcNow + amount;
        while (_enabled && _nextElapse <= newTime)
        {
            Elapsed?.Invoke(this, EventArgs.Empty);
            _nextElapse = _nextElapse.Value + _interval;
        }
    }
}

public class ServiceWithTimer
{
    private readonly ITimer _timer;

    public ServiceWithTimer(ITimer timer)
    {
        _timer = timer;
        _timer.Elapsed += OnTimerElapsed;
    }

    private void OnTimerElapsed(object? sender, EventArgs e)
    {
        // Periodic work
    }
}
```

**Example: abstracting delays**

```csharp
public interface IDelayProvider
{

}

public class SystemDelayProvider : IDelayProvider
{
    public Task DelayAsync(TimeSpan delay, CancellationToken cancellationToken = default)
        => Task.Delay(delay, cancellationToken);
}

public class FakeDelayProvider : IDelayProvider
{
    private readonly IClock _clock;
    private readonly List<(DateTime Time, TaskCompletionSource<bool> Tcs)> _delays = new();

    public FakeDelayProvider(IClock clock)
    {
        _clock = clock;
    }

    public Task DelayAsync(TimeSpan delay, CancellationToken cancellationToken = default)
    {
        var targetTime = _clock.UtcNow + delay;
        var tcs = new TaskCompletionSource<bool>();
        _delays.Add((targetTime, tcs));
        return tcs.Task;
    }

    public void Advance(TimeSpan amount)
    {
        // Advance clock and complete delays (implementation similar to FakeClock)
    }
}

public class ServiceWithDelay
{
    private readonly IDelayProvider _delayProvider;

    public ServiceWithDelay(IDelayProvider delayProvider)
    {
        _delayProvider = delayProvider;
    }

    public async Task ProcessWithDelayAsync()
    {
        await _delayProvider.DelayAsync(TimeSpan.FromSeconds(1));
        // Continue processing
    }
}
```

**Mentor emphasis**

- **Abstract timers and delays** for testability.
- **Use interfaces** to enable test doubles.
- **Control timing** in tests with fake clocks and delays.
- **Make tests fast** by eliminating real delays.

### 3. **Designing APIs for deterministic tests (no hidden threads/tasks)**

**The problem**

- **Hidden threads/tasks** make tests non-deterministic.
- **Background work** can complete at unpredictable times.
- **Race conditions** can cause flaky tests.

**Solution: expose control points**

- **Expose** background work as awaitable operations.
- **Provide** ways to wait for completion in tests.
- **Avoid** hidden threads/tasks.

**Example: exposing background work**

```csharp
// BAD: Hidden background work
public class BadService
{
    public void StartProcessing()
    {
        Task.Run(() => // Hidden task
        {
            ProcessItems();
        });
    }

    private void ProcessItems() { /* ... */ }
}

// GOOD: Exposed background work
public class GoodService
{
    private readonly ITaskScheduler _scheduler;

    public GoodService(ITaskScheduler scheduler)
    {
        _scheduler = scheduler;
    }

    public async Task ProcessAsync() // Exposed as awaitable
    {
        await _scheduler.Run(() =>
        {
            ProcessItems();
        });
    }

    private void ProcessItems() { /* ... */ }
}
```

**Example: providing completion hooks**

```csharp
public class ServiceWithCompletion
{
    private Task? _backgroundTask;

    public void StartProcessing()
    {
        _backgroundTask = Task.Run(() =>
        {
            ProcessItems();
        });
    }

    public async Task WaitForCompletionAsync()
    {
        if (_backgroundTask != null)
        {
            await _backgroundTask;
        }
    }

    private void ProcessItems() { /* ... */ }
}
```

**Example: avoiding hidden threads**

```csharp
// BAD: Hidden thread
public class BadTimerService
{
    public BadTimerService()
    {
        var timer = new System.Timers.Timer(1000);
        timer.Elapsed += (sender, e) => Process(); // Hidden work
        timer.Start();
    }

    private void Process() { /* ... */ }
}

// GOOD: Exposed timer
public class GoodTimerService
{
    private readonly ITimer _timer;

    public GoodTimerService(ITimer timer)
    {
        _timer = timer;
        _timer.Elapsed += OnTimerElapsed;
    }

    public event EventHandler? Processed;

    private void OnTimerElapsed(object? sender, EventArgs e)
    {
        Process();
        Processed?.Invoke(this, EventArgs.Empty);
    }

    private void Process() { /* ... */ }
}
```

**Mentor emphasis**

- **Expose background work** as awaitable operations.
- **Provide completion hooks** for tests.
- **Avoid hidden threads/tasks** that can't be controlled.
- **Make APIs testable** by design.

### 4. **Separating orchestration from core logic**

**The problem**

- **Orchestration** (scheduling, coordination) mixed with **core logic** makes testing hard.
- **Hard to test** core logic without testing orchestration.
- **Hard to test** orchestration without testing core logic.

**Solution: separate concerns**

- **Separate** orchestration from core logic.
- **Test** core logic independently.
- **Test** orchestration with test doubles.

**Example: separating orchestration**

```csharp
// BAD: Mixed concerns
public class BadService
{
    public async Task ProcessAsync()
    {
        var items = await LoadItemsAsync();
        
        await Task.Run(() => // Orchestration mixed with logic
        {
            foreach (var item in items)
            {
                ProcessItem(item); // Core logic
            }
        });
    }

    private void ProcessItem(string item) { /* ... */ }
    private async Task<List<string>> LoadItemsAsync() { /* ... */ }
}

// GOOD: Separated concerns
public class CoreLogic
{
    public void ProcessItem(string item) // Pure logic, easy to test
    {
        // Core logic
    }
}

public class OrchestrationService
{
    private readonly CoreLogic _coreLogic;
    private readonly ITaskScheduler _scheduler;

    public OrchestrationService(CoreLogic coreLogic, ITaskScheduler scheduler)
    {
        _coreLogic = coreLogic;
        _scheduler = scheduler;
    }

    public async Task ProcessAsync() // Orchestration, testable with test doubles
    {
        var items = await LoadItemsAsync();
        
        await _scheduler.Run(() =>
        {
            foreach (var item in items)
            {
                _coreLogic.ProcessItem(item);
            }
        });
    }

    private async Task<List<string>> LoadItemsAsync() { /* ... */ }
}
```

**Example: testing core logic independently**

```csharp
[Fact]
public void CoreLogic_ProcessItem_Works()
{
    var coreLogic = new CoreLogic();
    coreLogic.ProcessItem("test"); // Test core logic directly
    // Assert results
}

[Fact]
public async Task OrchestrationService_ProcessAsync_OrchestratesCorrectly()
{
    var coreLogic = new CoreLogic();
    var scheduler = new TestTaskScheduler();
    var service = new OrchestrationService(coreLogic, scheduler);
    
    await service.ProcessAsync();
    scheduler.ExecuteAll(); // Control execution
    
    // Assert orchestration worked correctly
}
```

**Mentor emphasis**

- **Separate orchestration** from core logic.
- **Test core logic** independently.
- **Test orchestration** with test doubles.
- **Keep concerns** separate for testability.

### 5. **Adding diagnostic hooks safely (counters, events, probes)**

**The problem**

- **Diagnostic code** can affect performance.
- **Diagnostic code** can introduce bugs.
- **Diagnostic code** should be optional.

**Solution: safe diagnostic hooks**

- **Make diagnostics optional** (feature flags, configuration).
- **Use lightweight** diagnostic mechanisms.
- **Don't affect** core logic.

**Example: optional diagnostics**

```csharp
public interface IDiagnostics
{
    void RecordEvent(string eventName, Dictionary<string, object>? properties = null);
    void IncrementCounter(string counterName);
    IDisposable StartTimer(string timerName);
}

public class NullDiagnostics : IDiagnostics
{
    public void RecordEvent(string eventName, Dictionary<string, object>? properties = null) { }
    public void IncrementCounter(string counterName) { }
    public IDisposable StartTimer(string timerName) => new NullTimer();
    
    private class NullTimer : IDisposable
    {
        public void Dispose() { }
    }
}

public class RealDiagnostics : IDiagnostics
{
    public void RecordEvent(string eventName, Dictionary<string, object>? properties = null)
    {
        // Record to EventSource, logging, etc.
    }

    public void IncrementCounter(string counterName)
    {
        // Increment counter
    }

    public IDisposable StartTimer(string timerName)
    {
        return new Timer(timerName);
    }

    private class Timer : IDisposable
    {
        private readonly string _name;
        private readonly System.Diagnostics.Stopwatch _sw;

        public Timer(string name)
        {
            _name = name;
            _sw = System.Diagnostics.Stopwatch.StartNew();
        }

        public void Dispose()
        {
            _sw.Stop();
            // Record timing
        }
    }
}

public class ServiceWithDiagnostics
{
    private readonly IDiagnostics _diagnostics;

    public ServiceWithDiagnostics(IDiagnostics? diagnostics = null)
    {
        _diagnostics = diagnostics ?? new NullDiagnostics();
    }

    public async Task ProcessAsync()
    {
        using (_diagnostics.StartTimer("Process"))
        {
            _diagnostics.IncrementCounter("ProcessStarted");
            
            try
            {
                await DoWorkAsync();
                _diagnostics.RecordEvent("ProcessCompleted");
            }
            catch (Exception ex)
            {
                _diagnostics.RecordEvent("ProcessFailed", new Dictionary<string, object>
                {
                    ["Error"] = ex.Message
                });
                throw;
            }
        }
    }

    private async Task DoWorkAsync() { /* ... */ }
}
```

**Example: feature-flagged diagnostics**

```csharp
public class ServiceWithFeatureFlaggedDiagnostics
{
    private readonly bool _enableDiagnostics;
    private readonly IDiagnostics _diagnostics;

    public ServiceWithFeatureFlaggedDiagnostics(bool enableDiagnostics, IDiagnostics diagnostics)
    {
        _enableDiagnostics = enableDiagnostics;
        _diagnostics = diagnostics;
    }

    public async Task ProcessAsync()
    {
        if (_enableDiagnostics)
        {
            using (_diagnostics.StartTimer("Process"))
            {
                await DoWorkAsync();
            }
        }
        else
        {
            await DoWorkAsync();
        }
    }

    private async Task DoWorkAsync() { /* ... */ }
}
```

**Example: lightweight probes**

```csharp
public interface IProbe
{
    void Record(string name, object value);
}

public class NullProbe : IProbe
{
    public void Record(string name, object value) { }
}

public class ServiceWithProbe
{
    private readonly IProbe _probe;

    public ServiceWithProbe(IProbe? probe = null)
    {
        _probe = probe ?? new NullProbe();
    }

    public void Process(int value)
    {
        _probe.Record("ProcessStarted", value);
        
        // Core logic
        var result = value * 2;
        
        _probe.Record("ProcessCompleted", result);
    }
}
```

**Mentor emphasis**

- **Make diagnostics optional** (null objects, feature flags).
- **Use lightweight** diagnostic mechanisms.
- **Don't affect** core logic performance.
- **Test with and without** diagnostics enabled.

---

**Summary**

- **Inject dependencies** (schedulers, clocks, executors) instead of using static APIs.
- **Abstract timers and delays** for testability.
- **Design APIs** to expose background work and avoid hidden threads/tasks.
- **Separate orchestration** from core logic for independent testing.
- **Add diagnostic hooks** safely with optional, lightweight mechanisms.
