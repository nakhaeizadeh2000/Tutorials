### 1. **Visual Studio async debugging, Tasks window, and Parallel Stacks**

**Tasks window**

- The **Tasks window** (Debug → Windows → Tasks) shows all active `Task` instances.
- Useful for seeing:
  - Which tasks are running, waiting, or faulted.
  - Task status and exceptions.
  - Which thread each task is running on.

**Using the Tasks window**

1. Set a breakpoint in async code.
2. When paused, open **Debug → Windows → Tasks**.
3. See all active tasks with their:
   - **ID**: Task identifier.
   - **Status**: Running, Waiting, Deadlocked, etc.
   - **Location**: Where the task is currently executing.
   - **Task**: The actual `Task` object.

**Example: debugging with Tasks window**

```csharp
public class TaskDebuggingExample
{
    public async Task ProcessMultipleAsync()
    {
        var tasks = new List<Task>();
        
        for (int i = 0; i < 10; i++)
        {
            var task = ProcessItemAsync(i);
            tasks.Add(task);
        }
        
        // Set breakpoint here - Tasks window shows all 10 tasks
        await Task.WhenAll(tasks);
    }

    private async Task ProcessItemAsync(int id)
    {
        await Task.Delay(1000); // Set breakpoint here
        Console.WriteLine($"Processed {id}");
    }
}
```

- When paused at the breakpoint, the Tasks window shows all 10 tasks.
- You can double-click a task to see its call stack.

**Parallel Stacks window**

- The **Parallel Stacks window** (Debug → Windows → Parallel Stacks) shows call stacks for all threads.
- Useful for seeing:
  - Which threads are running what code.
  - Thread relationships and synchronization points.
  - Deadlocks (threads waiting on each other).

**Using Parallel Stacks**

1. Set a breakpoint in parallel code.
2. When paused, open **Debug → Windows → Parallel Stacks**.
3. See a graphical view of all thread call stacks.
4. Switch between **Threads view** and **Tasks view**.

**Example: debugging parallel code**

```csharp
public class ParallelDebuggingExample
{
    public void ProcessParallel()
    {
        Parallel.For(0, 100, i =>
        {
            // Set breakpoint here - Parallel Stacks shows all threads
            ProcessItem(i);
        });
    }

    private void ProcessItem(int id)
    {
        Thread.Sleep(10); // Simulate work
        Console.WriteLine($"Processed {id}");
    }
}
```

- When paused, Parallel Stacks shows all threads executing `ProcessItem`.

**Async call stack**

- The **Call Stack window** shows the **logical call stack** for async methods.
- Includes:
  - **Awaited calls**: Shows what the async method is waiting for.
  - **Continuations**: Shows where execution will resume.

**Example: async call stack**

```csharp
public class AsyncCallStackExample
{
    public async Task MainAsync()
    {
        await ProcessAsync(); // Call stack shows: MainAsync -> ProcessAsync
    }

    private async Task ProcessAsync()
    {
        await Task.Delay(1000); // Call stack shows continuation chain
        await ProcessMoreAsync();
    }

    private async Task ProcessMoreAsync()
    {
        await Task.Delay(1000);
    }
}
```

- When paused in `ProcessMoreAsync`, the call stack shows the full async chain.

**Mentor emphasis**

- **Use Tasks window** to see all active tasks and their status.
- **Use Parallel Stacks** to see all thread call stacks.
- **Understand async call stacks** to trace async execution flow.
- **Set breakpoints strategically** to pause at key points in async/parallel code.

### 2. **Inspecting logical call stacks with async/await**

**What is a logical call stack?**

- The **logical call stack** shows the flow of async execution across `await` points.
- Unlike physical call stacks, it shows **continuations** and **awaited operations**.

**Viewing logical call stacks**

- In Visual Studio, the **Call Stack window** shows logical stacks for async methods.
- Look for entries like:
  - `[External Code]` for framework code.
  - `MoveNext` for async state machine methods.
  - `Awaited` indicators showing what's being awaited.

**Example: logical call stack inspection**

```csharp
public class LogicalCallStackExample
{
    public async Task MainAsync()
    {
        try
        {
            await ProcessAsync(); // Set breakpoint here
        }
        catch (Exception ex)
        {
            // Call stack shows full async chain
            Console.WriteLine(ex.StackTrace);
        }
    }

    private async Task ProcessAsync()
    {
        await Task.Delay(1000); // Set breakpoint here
        await ProcessMoreAsync();
    }

    private async Task ProcessMoreAsync()
    {
        await Task.Delay(1000);
        throw new InvalidOperationException("Error"); // Exception shows full async stack
    }
}
```

- When an exception occurs, the stack trace shows the full async chain.

**Debugging async state machines**

- Async methods are compiled into **state machines**.
- The debugger shows `MoveNext` methods, which are the state machine implementations.
- You can step through state machine code to see how `await` works internally.

**Example: stepping through async code**

```csharp
public async Task<int> CalculateAsync(int value)
{
    var result1 = await Step1Async(value); // Step into shows state machine
    var result2 = await Step2Async(result1); // Step into shows continuation
    return result2;
}

private async Task<int> Step1Async(int value)
{
    await Task.Delay(100);
    return value * 2;
}

private async Task<int> Step2Async(int value)
{
    await Task.Delay(100);
    return value + 10;
}
```

- **Step Over (F10)**: Executes the entire `await` without stepping into the state machine.
- **Step Into (F11)**: Steps into the state machine code (usually not useful).
- **Step Out (Shift+F11)**: Steps out of the current method.

**Inspecting async locals**

- Use **Locals window** to see:
  - **Local variables** in the current async method.
  - **State machine fields** (usually hidden, but can be inspected).
  - **Awaited task** status.

**Example: inspecting async state**

```csharp
public async Task ProcessWithStateAsync()
{
    int localVar = 42; // Visible in Locals window
    var task = SomeOperationAsync();
    
    // Set breakpoint here - inspect localVar and task
    var result = await task;
    
    // Set breakpoint here - inspect result
    Console.WriteLine(result);
}
```

**Mentor emphasis**

- **Understand logical call stacks** to trace async execution flow.
- **Use Call Stack window** to see async continuations.
- **Step carefully** through async code (Step Over is usually better than Step Into).
- **Inspect awaited tasks** in the Locals window to see their status.

### 3. **Debugging PLINQ and Parallel.\* workloads**

**Debugging Parallel.For**

- Use **Parallel Stacks window** to see all threads executing parallel iterations.
- Set breakpoints inside the parallel loop body.
- Use **Threads window** to see which thread is executing which iteration.

**Example: debugging Parallel.For**

```csharp
public class ParallelForDebugging
{
    public void ProcessParallel()
    {
        var results = new ConcurrentBag<int>();
        
        Parallel.For(0, 100, i =>
        {
            // Set breakpoint here - see all threads in Parallel Stacks
            var result = ProcessItem(i);
            results.Add(result);
        });
    }

    private int ProcessItem(int id)
    {
        Thread.Sleep(10); // Set breakpoint here
        return id * 2;
    }
}
```

- When paused, Parallel Stacks shows multiple threads executing `ProcessItem`.
- You can switch between threads to see different iterations.

**Debugging PLINQ**

- PLINQ queries can be debugged by:
  - Setting breakpoints in query operators (Select, Where, etc.).
  - Using **Parallel Stacks** to see parallel execution.
  - Inspecting intermediate results.

**Example: debugging PLINQ**

```csharp
public class PLINQDebugging
{
    public void ProcessPLINQ()
    {
        var numbers = Enumerable.Range(0, 1000);
        
        var results = numbers.AsParallel()
            .Where(x => x % 2 == 0) // Set breakpoint here
            .Select(x => x * 2) // Set breakpoint here
            .ToArray(); // Set breakpoint here
    }
}
```

- Breakpoints in PLINQ operators show parallel execution.
- Use **Parallel Stacks** to see all threads processing different partitions.

**Debugging with custom partitioners**

```csharp
public class CustomPartitionerDebugging
{
    public void ProcessWithCustomPartitioner()
    {
        var numbers = Enumerable.Range(0, 1000);
        var partitioner = Partitioner.Create(numbers, loadBalance: true);
        
        Parallel.ForEach(partitioner, item =>
        {
            // Set breakpoint here - see partition distribution
            ProcessItem(item);
        });
    }

    private void ProcessItem(int item)
    {
        Thread.Sleep(10);
    }
}
```

**Inspecting parallel execution**

- Use **Threads window** to see:
  - Which threads are running.
  - Which threads are waiting.
  - Thread IDs and names.

**Example: thread inspection**

```csharp
public class ThreadInspection
{
    public void ProcessParallel()
    {
        Parallel.For(0, 10, i =>
        {
            // Set breakpoint here
            // Threads window shows: ThreadPool threads executing iterations
            Console.WriteLine($"Thread {Thread.CurrentThread.ManagedThreadId}: {i}");
        });
    }
}
```

**Mentor emphasis**

- **Use Parallel Stacks** to see all threads in parallel execution.
- **Set breakpoints** in parallel loop bodies to inspect execution.
- **Use Threads window** to see thread distribution.
- **Understand partitioning** to debug PLINQ effectively.

### 4. **Stepping through IAsyncEnumerable\<T\> and streams**

**What is IAsyncEnumerable?**

- `IAsyncEnumerable<T>` represents an **asynchronous sequence** of values.
- Used with `await foreach` to consume streaming data.
- See **3.4** and **5.6** for usage patterns.

**Debugging async enumerables**

- Set breakpoints in:
  - The **producer** (method that yields values).
  - The **consumer** (code that uses `await foreach`).
  - **MoveNextAsync** calls (internal to the enumerator).

**Example: debugging async enumerable**

```csharp
public class AsyncEnumerableDebugging
{
    public async Task ProcessStreamAsync()
    {
        await foreach (var item in GenerateItemsAsync()) // Set breakpoint here
        {
            // Set breakpoint here - see each item as it's consumed
            ProcessItem(item);
        }
    }

    private async IAsyncEnumerable<int> GenerateItemsAsync()
    {
        for (int i = 0; i < 10; i++)
        {
            await Task.Delay(100); // Set breakpoint here - see production
            yield return i; // Set breakpoint here - see value yielded
        }
    }

    private void ProcessItem(int item)
    {
        Console.WriteLine($"Processed {item}");
    }
}
```

- Breakpoints show the **producer-consumer flow**.
- You can step through both production and consumption.

**Debugging streaming I/O**

```csharp
public class StreamingIODebugging
{
    public async Task ProcessFileStreamAsync()
    {
        using var fileStream = new FileStream("data.txt", FileMode.Open);
        using var reader = new StreamReader(fileStream);
        
        string? line;
        while ((line = await reader.ReadLineAsync()) != null) // Set breakpoint here
        {
            // Set breakpoint here - see each line as it's read
            ProcessLine(line);
        }
    }

    private void ProcessLine(string line)
    {
        Console.WriteLine(line);
    }
}
```

**Debugging with Channels**

```csharp
using System.Threading.Channels;

public class ChannelDebugging
{
    public async Task ProcessChannelAsync()
    {
        var channel = Channel.CreateUnbounded<int>();
        
        // Producer
        var producer = Task.Run(async () =>
        {
            for (int i = 0; i < 10; i++)
            {
                await channel.Writer.WriteAsync(i); // Set breakpoint here
                await Task.Delay(100);
            }
            channel.Writer.Complete();
        });
        
        // Consumer
        await foreach (var item in channel.Reader.ReadAllAsync()) // Set breakpoint here
        {
            // Set breakpoint here - see consumption
            ProcessItem(item);
        }
        
        await producer;
    }

    private void ProcessItem(int item)
    {
        Console.WriteLine($"Processed {item}");
    }
}
```

**Inspecting async enumerator state**

- Use **Locals window** to see:
  - Current item being processed.
  - Enumerator state.
  - Channel/stream state.

**Mentor emphasis**

- **Set breakpoints** in both producer and consumer code.
- **Use await foreach** to step through async sequences.
- **Understand backpressure** (see 5.6) when debugging streaming code.
- **Inspect enumerator state** to see current position in the sequence.

### 5. **Debugging deadlocks and hangs (dump analysis basics)**

**What is a dump file?**

- A **dump file** is a snapshot of a process's memory at a specific point in time.
- Contains:
  - All threads and their call stacks.
  - Memory contents.
  - Object state.

**Creating dump files**

- **Windows**: Use Task Manager (Create Dump File) or `procdump.exe`.
- **Linux**: Use `dotnet-dump` or `gcore`.
- **Azure**: Use Azure App Service diagnostics.

**Example: creating a dump**

```bash
# Windows: using procdump
procdump -ma <process-id> dump.dmp

# Linux: using dotnet-dump
dotnet-dump collect -p <process-id>

# Or programmatically
using System.Diagnostics;
Process.GetCurrentProcess().Dump("dump.dmp");
```

**Analyzing dumps with Visual Studio**

1. Open the dump file in Visual Studio (File → Open → File).
2. Use **Debug → Windows → Threads** to see all threads.
3. Use **Debug → Windows → Call Stack** to see thread call stacks.
4. Look for:
   - Threads blocked on locks (`Monitor.Enter`, `WaitOne`).
   - Threads waiting on async operations (`.Result`, `.Wait()`).
   - Circular dependencies between threads.

**Example: analyzing a deadlock dump**

- **Thread 1**: Blocked on `lock (_lock2)` while holding `_lock1`.
- **Thread 2**: Blocked on `lock (_lock1)` while holding `_lock2`.
- **Diagnosis**: Classic deadlock from lock ordering.

**Analyzing with WinDbg**

```windbg
# Load dump
.open -a dump.dmp

# See all threads
~*

# See call stack for thread
~0k

# Look for locks
!syncblk
```

**Analyzing with dotnet-dump (Linux)**

```bash
# Analyze dump
dotnet-dump analyze dump.dmp

# See threads
clrthreads

# See call stack
clrstack

# Look for locks
syncblk
```

**Common deadlock patterns in dumps**

1. **Lock ordering**: Threads waiting on locks in different orders.
2. **Sync-over-async**: Threads blocked on `.Result` or `.Wait()`.
3. **UI thread blocking**: UI thread blocked waiting for background thread.

**Example: identifying sync-over-async in dump**

- **ThreadPool thread**: Blocked on `Task.Result` or `.Wait()`.
- **Call stack shows**: `GetDataAsync().Result` or `task.Wait()`.
- **Diagnosis**: Sync-over-async deadlock.

**Debugging hangs**

- **Hangs** are similar to deadlocks but may not involve locks.
- Look for:
  - Threads in infinite loops.
  - Threads waiting on events that never fire.
  - ThreadPool starvation (all threads blocked).

**Example: identifying ThreadPool starvation**

- **All ThreadPool threads**: Blocked on synchronous I/O or locks.
- **New work items**: Queued but not processed.
- **Diagnosis**: ThreadPool starvation.

**Mentor emphasis**

- **Create dumps** when applications hang or deadlock.
- **Analyze dumps** to see thread states and call stacks.
- **Look for patterns**: Lock ordering, sync-over-async, ThreadPool starvation.
- **Use appropriate tools**: Visual Studio for Windows, dotnet-dump for Linux.

- **Logical call stacks**: Trace async execution flow across await points.
- **PLINQ/Parallel debugging**: Use Parallel Stacks to see parallel execution.
- **Async enumerables**: Set breakpoints in producer and consumer code.
- **Dump analysis**: Use dumps to diagnose deadlocks and hangs in production.
