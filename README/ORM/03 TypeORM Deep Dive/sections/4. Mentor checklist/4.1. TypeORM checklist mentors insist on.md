# 4.1. TypeORM checklist mentors insist on

## 1. Decorators reviewed like schema (entities, columns, relations — every decorator earning its place)

**Definition** — the review's first pass over TypeORM code: every decorator justifying itself — entities (table names explicit? ids strategized? lifecycles trivial-or-seamed?); columns (types deliberate? nullability contracted? uniques/defaults/enums stated?); relations (both sides? owner marked? actions stated? 1-1 unique? m-n explicit-or-triggered?); lifecycle columns (timestamps conventionalized? soft-delete designed with partial uniques? versions where contention demands?). Decorators reviewed as schema (DDL consequences per line — types/widths/constraints/indexes flowing to migrations); entities reviewed as code (behavior, naming — DDL-blind code review insufficient, code-blind schema review equally so — both lenses, every entity PR).

**What problem it solves** — the waved entity (decorators unexamined — Int ids capping silently; TEXT-everywhere storage unpriced; stringly-typed statuses accumulating typos; half-declared relations (reverse traversals unservable — migrations later); defaulted actions (runtime surprises scheduled); reflect-metadata assumed (initiation failures in workers/scripts). Each unreviewed decorator bills per row forever (widths × billions), per query eventually (unindexed FKs scanning), per incident quarterly (anomalies/typos/defaults failing). Review minutes per entity PR convert to quarters avoided at the usual rate — highest-ROI minutes in TypeORM operations, permanently true.

**Modern guidance** — the decorator review lines (per entity, review-enforced): *identity* (id type decided — BigInt default (viral-safe), Int justified (bounded), UUID for distributed (topology stated) — width priced); *columns* (types deliberate (natives decided); nullability contracted; uniques/defaults/enums stated — options intentional, never defaulted); *relations* (four parts present (both sides + owner + action); 1-1 unique; m-n explicit-or-triggered; cascade layered correctly (ORM vs DB distinguished); *lifecycle* (timestamps conventionalized; soft-delete designed (partial uniques alongside); versions where contention demands); *entry* (reflect-metadata first line (linted — initiation failures preempted structurally). Missing line → request changes; "just models" framing → schema review invoked (decorators are DDL — waved never).

```typescript
// GOOD: the decorator review artifact — every line earning its place (excerpt).
// TormUser.id: BigInt generated (viral-safe ✓). email: unique (identity enforced ✓).
// role: enum + default USER (closed + defaulted ✓). createdAt: CreateDateColumn (conventional ✓).
// Relations: Author.books ↔ Book.author both sides (navigable ✓); JoinColumn named (explicit ✓);
// onDelete Cascade stated (contained ✓); Enrollment explicit (attributes landable ✓).
// Entry: reflect-metadata first line, linted (initiation preempted ✓). Verdict: approve entities.
```

```typescript
// BAD: the waved entity — decorators unexamined, consequences scheduled (real shapes).
// User.id: Int default (2B cap — viral incident scheduled). email: bare @Column (duplicates
// accumulating — cleaned quarterly). status: open string (typo'd rows — DISTINCT archaeology).
// relations: forward-only (reverse unservable — migrations later). actions: defaulted (NO ACTION
// surprises). createdAt: absent (temporal questions unanswerable). reflect-metadata: hoped
// (workers failing identically — initiation undiscovered). Waved ("just models"); billed quarterly.
```

**Common confusion** — *"decorator review duplicates migration review (same diff twice)."* Decorator review judges *declarations* (types/relations/attributes — right shapes?); migration review judges *transitions* (phases/compatibility/witnesses — safe shipping?). Different subjects (shapes vs changes), different failures (wrong types persist forever; unsafe transitions break deploys once each), both required (right shapes shipped wrongly fail; wrong shapes shipped safely persist). Review declarations at entity PRs (design correctness); review transitions at migration PRs (shipping safety) — two reviews, two subjects, zero duplication (DRY honored — each review owning its questions exclusively — twin of Prisma 02/4.1's verdict, class-flavored).

**Performance note** — decorator-review economics: type widths priced per row × horizon (BigInt-vs-Int decided once — billions affected); FK indexes audited at birth (seconds per index empty — hours CONCURRENTLY under load — birth-indexing enforced); enum natives chosen (storage/index/cache leaner); timestamp indexes where recency filters (hot predicate, cheap index). Unreviewed equivalents bill storage (widths × billions), queries (unindexed scans), quality (typo branches). Review minutes per entity PR (decorators questioned); quarters avoided per incident class (width/scan/typo). Minutes now, quarters never.

**Mentor note** — teach "every decorator earns its place" (juniors questioning entity lines design deliberately from the first model; unwaved entities arriving pre-justified (types reasoned, relations complete, attributes intentional — review accelerating instead of interrogating). Praise justified decorators ("good enum closure with priced reasoning") louder than clever relations — teams optimize for praised behavior, and clever undecorated models have had enough admirers. Earn places; praise justifications; wave never.

## 2. Migrations witnessed end to end (generate, review, run — no step skipped, synchronize never prod)

**Definition** — the review's second pass over TypeORM schema change: generate reviewed (diffs rendered — SQL read fully (BIGSERIAL/PK/UQ visible, downs present — review completeness enforced); run governed (`show` before `run` (state known); pending-only application (history replayed, tracked); `revert` available (reversibility designed per migration); synchronize forbidden past dev (linted — auto-mutation incidents preempted structurally). End-to-end witnessing means every handoff verified (generate→review (diffs read); review→run (approval recorded); run→production (status green, tracked); synchronize absent outside dev (lint passing). Skipped handoffs fail structurally (unreviewed diffs, ungated runs, unwitnessed contracts, hopeful synchronization — each a scheduled incident with unknown date).

**What problem it solves** — the unwitnessed pipeline, TypeORM edition (generate-and-apply without review (flag-day NOT NULLs (blocking rewrites), drop+create renames (history loss), missing FK indexes (parent scans) — velocity without judgment); `synchronize: true` leaking past dev (typo'd decorators dropping production columns (data stranded — review absent by design); concurrent deploys racing schema writes (locks + partial states); history void (applied states unrecorded — environments diverging silently); path-undisciplined runs (migrations resolving from wrong directories ("no pending" with files elsewhere — path lesson verified live this session — runs executing nothing while claiming success). Witnessing converts pipeline stages to checkpoints (generate→reviewed, approved→run, ran→verified, synchronized→never-prod).

**Modern guidance** — the witnessing lines per migration (CI + human enforced): *generate* (diff rendered on owned dev DB (shared-DB fiction diffs declined — drift attributed correctly); *review* (phase named, renames declared, nullability checked, indexes verified, stragglers named — [2.2](<../2. Flavors and migrations/2.2. Migrations generated and governed.md>) performed fully); *run* (show-before-run (state known); pending-only (history replayed, tracked); path-correct (`-d` datasource + `-o` output configured deliberately — files resolving where review approved); *revert-ready* (downs reviewed (destructive downs witnessed — reversibility designed, never hoped); *synchronize-never-prod* (linted — CI failing synchronize-true outside dev — auto-mutation incidents preempted structurally). Missing witness → request changes/block deploys; history bypassed → fiction institutionalized (console DDL instead of run — divergence archaeology scheduled).

```sql
-- GOOD: the witnessing chain — generate→review→run→verify, synchronize absent (excerpt).
-- Generate: diff rendered on owned dev DB (shared fiction declined ✓).
-- Review: phase EXPAND named; renames none; nullability safe; indexes verified ✓.
-- Run: show-before-run (state known ✓); pending-only, path-correct (files resolving ✓).
-- Verify: post-run status green (applied == history ✓). synchronize: false, linted ✓.
-- Verdict: approve pipeline.
```

```sql
-- BAD: the unwitnessed pipeline — stages skipped, synchronization hoped-contained (real shapes).
-- Generate: skipped (hand SQL "faster" — deltas missed (forgotten columns, absent downs)).
-- Review: skipped ("small diff" — flag-day NOT NULL inside (blocking rewrite mid-deploy)).
-- Run: show skipped (pendings unknown — already-applied re-running (duplicates) or missing skipped).
-- synchronize: true in staging "temporarily" (typo'd decorator dropping columns — data stranded;
-- concurrent deploys racing — partial states; history void — environments diverging silently).
-- Stages skipped; witnesses absent; synchronization hoped. Incidents scheduled (dateless, as usual).
```

**Common confusion** — *"small migrations don't need witnessing (overhead)."* Witnessing scales with risk (trivial additive diffs: phase named, witnesses N/A-stated — seconds; breaking changes: full ritual — minutes), never waives structurally (unwitnessed "small" drops breaking dashboards (size of diff ≠ size of consequence — one-line drops deleting histories); ungated "small" runs meeting drift (pendings unexpected — small release, large surprise). Overhead framing counts witnessing seconds while ignoring incident quarters — full ledger favors witnessing by orders of magnitude, permanently. Witness proportionally; waive never.

**Performance note** — witnessing economics: generate/review/run/verify costing minutes per migration (bounded, calm — pipeline steps automated where checkable (status gates, phase linters, synchronize grep — machines tireless); review judgment human (phases, witnesses — mentors precise). Unwitnessed equivalents costing blocking rewrites (unphased flag-days in windows), repair migrations (fiction-built foundations — archaeology quarters), dropped histories (unwitnessed drops — BI/dashboards failing), auto-mutation outages (typo'd decorators — data stranded). Minutes per migration prevent quarters per incident — witnessing ROI exceeding all other migration investments (evidence chains compound; hope chains break).

**Mentor note** — teach "witness every handoff" (juniors checking generate→review→run→verify design pipelines completely on first hearing; handoffs skipped interrogated ("status checked?" — gate demanded; "synchronize off?" — lint demanded). Automate checkable handoffs (status gates, synchronize grep, phase linters — machines tireless); humanize judgment handoffs (phase classification, witness evaluation — mentors precise). Witness handoffs; automate checks; judge transitions — pipeline discipline in three habits, reviewed per migration.

## 3. Loading strategies stated (eager/lazy per relation decided — N+1 counted, magic inventoried)

**Definition** — the review's closing act over data access: every relation states its loading strategy (explicit per query (default prescription — `relations: {...}` where needed, unloaded elsewhere); eager with reason (hot paths — frequency justifying transfer — priced per hot path); lazy almost never (per-access statements — N+1 structural — justified only where single-entity traversals dominate AND counts asserted — rare, documented per relation with reason). Every list asserts its counts (statement bounds per test — N+1 failing builds — detector enforced from adoption). Query logging on in dev/test (every statement visible per render — surprises pre-merge). Strategies stated, counts asserted, logs on — magic inventoried (cascade/lazy/transaction defaults reviewed per major — surprising entries disabled or documented).

**What problem it solves** — the unstrategized client (relations loaded by habit (eager defaults transferring graphs per render — transfer billed per read, unexamined; lazy defaults traversing per access — statements billing per touch — magic billing both ways, strategy neither); counts unasserted (lists green on fixtures — linear in production ten-thousands — latency discovered at scale); logging off (statements invisible — cartesian joins, fan-out transfers — surprises scheduled (p99 cliffs official). Stated strategies convert habit to decision (eager/lazy/explicit per relation — priced, reviewed); asserted counts convert hope to structure (bounds enforced — N+1 impossible silently); logging converts surprises to pre-merge findings (visible statements — reviewed like code). Strategy/counts/logs — complete client review, magic inventoried alongside.

**Modern guidance** — the client review lines per data-access PR: *strategy* (eager/lazy/explicit per relation read — stated explicitly (verified patterns — bare-unloaded, relations-batched, QueryBuilder-joined — unstrategized traversals returned with "which strategy?" — seconds, devastating, effective); *counts* (statement bounds per list test — ≤N derived from shape — N+1 failing builds (asserted, not hoped); *logging* (query logging on (development/test default — every statement visible per render — dark SQL absent); *magic* (per-major inventory (cascade/lazy/transaction defaults reviewed — surprising entries disabled with reason + owner; 1.x idioms current (`.extend()` adopted — removed decorators migrated — version-skew corrected). Missing line → request changes; global defaults → per-relation decisions (one default for all relations fails review structurally).

```typescript
// GOOD: the client review artifact — strategies, counts, logs, magic (excerpt).
// Strategy: order list relations explicitly (stated per query ✓ — lazy absent structurally).
// Counts: ≤3 statements/test asserted (N+1 fails builds ✓ — verified live pattern: bare vs 2).
// Logging: query logging on (statements visible per render ✓).
// Magic: cascades reviewed (surprising entries disabled ✓); .extend() adopted (1.x idiom ✓).
// Verdict: approve client usage.
```

```typescript
// BAD: the unobserved client — strategies unstated, counts unasserted, logs off, magic unknown.
// Strategy: unstated (eager defaults transferring graphs (transfer billed per read, unexamined);
// lazy defaults traversing per access (statements billing per touch — magic both ways).
// Counts: unasserted ("works in staging" — tens of rows hiding ten-thousands of statements).
// Logging: off ("noisy" — surprises scheduled (cartesian joins, fan-out transfers — p99 cliffs).
// Magic: unknown (cascade defaults unexamined (cleanup scripts deleting parents); 0.3 idioms
// persisting (@EntityRepository ghosts — version-skewed code failing confusingly).
// Unobserved clients bill quarterly (linear latencies, magic incidents, upgrade surprises). Observe always.
```

**Common confusion** — *"client review duplicates N+1 testing (same checks twice)."* N+1 testing asserts *counts* (statements bounded — quantitative — tests failing on numbers); client review examines *strategies + magic + logging* (qualitative + infrastructural — includes stated? gauges migrated? defaults inventoried? — judgmental). Counts without strategies pass accidentally-correct queries (bounded today, fragile tomorrow — strategy changes silently reintroducing N+1); strategies without counts pass intended-but-broken queries (includes stated, loops beside them — discipline claimed, N+1 shipped). Both required (quantitative bounds + qualitative strategies + infrastructural logging + versioned magic — four lines, complete client review). Count and strategize; log and inventory.

**Performance note** — client-review economics: strategies stated (minutes per relation — batching designed); counts asserted (milliseconds per test — N+1 structurally impossible); logging on (log volume dev-only — negligible); magic inventoried (minutes per major — upgrades explicitly re-priced). Unobserved equivalents: linear latencies (N+1 at scale — quarters of remediation); upgrade surprises (dead gauges, changed defaults — incidents per major); magic incidents (cascades, fan-outs — data loss + fiction dashboards). Review minutes per data-access PR prevent quarters per incident class — client review ROI exceeding all other TypeORM practices (observed clients never surprise — surprises are the only incidents).

**Mentor note** — teach "strategy/counts/logs/magic" as the client review mantra (juniors reciting per data-access PR internalize completeness before speed — mantra first, fluency follows). Automate counts + logging (assertions in tests, events on by default — machines tireless); humanize strategies + magic (loading decisions, default inventories — mentors precise). Praise observed clients ("great strategy statement with counts" — behavior praised, repeated); interrogate unobserved ones ("which strategy?" — seconds, devastating, effective). Mantra memorized; automation tireless; judgment human — review complete, clients observed, surprises extinct.
