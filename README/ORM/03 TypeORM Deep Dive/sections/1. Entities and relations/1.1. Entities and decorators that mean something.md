# 1.1. Entities and decorators that mean something

## 1. Entities declare tables in classes (names, columns, ids — reviewed like schema)

**Definition** — a TypeORM entity is a decorated class mapping one table (`@Entity({ name })` — explicit table names, never defaulted blindly (naming strategy mismatches across environments bite silently); `@PrimaryGeneratedColumn()` ids (surrogate default per [Database Design §1.2](<../../../../DatabaseDesign/01 Modeling Foundations and Mental Model/sections/2. Identity and keys/2.1. Surrogate versus natural keys.md>)); columns with types/options — the class file as schema declaration, reviewed like schema ([Domain 01 §4.1](<../../../01 Data Access Foundations and Mental Model/sections/4. Mentor checklist/4.1. Data-access checklist mentors insist on.md>) — every decorator earning its place). Entities reviewed as schema (types, nullability, defaults questioned per decorator — class PRs held to schema standards, never waved as "just models").

**What problem it solves** — the undecorated class (plain fields without column intent — types defaulted (varchar(255)? text? — storage unpriced); nullability unconsidered (nullable everywhere — presence contracts absent); ids unstrategized (Int autoincrement defaulted — 2B cap silently scheduled); table names implicit (naming-strategy dependent — environments disagreeing). Each unconsidered decorator bills per row forever (widths × billions), per query eventually (unindexed FKs scanning), per incident quarterly (anomalies/type-typos/defaults failing). Decorated deliberately, entities carry schema intent visibly (reviewed per line — types/nullability/defaults questioned); undecorated, they carry defaults silently (framework choices standing in for design decisions — convenient now, expensive always).

**Modern guidance** — the entity review lines (per class, review-enforced — verified live shapes on TypeORM 1.1.1 this session): *table* (`@Entity({ name })` explicit — naming strategy never trusted across environments (snake vs camel drift — explicit names immune); *id* (`@PrimaryGeneratedColumn()` BigInt default (viral-safe — Int justified only for bounded domains — width priced); *columns* (types deliberate (`varchar` lengths, `timestamptz`, numerics — storage granularity decided); nullability contracted (`nullable: true` = unknown-OK, stated — default non-nullable honored as presence contract); *uniques/defaults* (`unique: true` on identity fields — enforced from row one; `default:` for shape defaults — engine-filled); *timestamps* (`@CreateDateColumn/@UpdateDateColumn` — audit-adjacent convenience (verified live exports present) — trigger mirrors remain the audit story ([Database Design §6.1](<../../../../DatabaseDesign/06 Modeling for Operations/sections/1. History and deletion/1.1. Audit trails that answer questions.md>)), timestamps the convenience).

```typescript
// GOOD: entity declaring intent per decorator (verified live: TypeORM 1.1.1 round-trip on dbprobe).
import "reflect-metadata";   // entry-point first line (undecorated-metadata silently inert — 01/3.1 initiation bug)
import { DataSource, Entity, PrimaryGeneratedColumn, Column, CreateDateColumn } from "typeorm";

export enum Role { USER = "USER", ADMIN = "ADMIN" }  // TS enum (closed set — DB enum/varchar per column type)

@Entity({ name: "torm_users" })   // table named explicitly (strategy-independent — environments agree)
class TormUser {
  @PrimaryGeneratedColumn({ type: "bigint" })   // BigInt default (viral-safe — width priced once)
  id!: number;

  @Column({ unique: true })
  email!: string;   // identity enforced from row one (duplicates impossible, not cleaned)

  @Column({ type: "enum", enum: Role, default: Role.USER })
  role!: Role;      // closed set (typos rejected — verified live: default USER applied)

  @CreateDateColumn()
  createdAt!: Date; // audit-adjacent convenience (trigger mirrors remain the audit story)
}
// Live: save({email}) → defaults applied (role USER, createdAt set — verified output below).
```

```typescript
// BAD: the undecorated class — defaults standing in for design (real failure shapes).
// @Entity()
// class User {
//   @PrimaryGeneratedColumn()   // Int default (2B cap — viral-scale incident scheduled silently)
//   id!: number;
//   @Column()
//   email!: string;             // no unique (duplicates accumulating — cleaned quarterly, forever)
//   @Column()
//   status!: string;            // open stringly-typed ('actvie' rows — typos as data)
//   // no createdAt (temporal questions unanswerable — "when?" asked of every row eventually)
//   // table name implicit (strategy-dependent — environments disagreeing silently)
// }
// Defaults unexamined; intent absent; patches post-incident. Decorators cost lines at authoring;
// absence costs archaeology (which statuses exist? — DISTINCT answering design questions).
```

**Common confusion** — *"entities are just models (any shape works)."* Entities are *schema declarations wearing class syntax* (every decorator a DDL decision — types/widths/constraints/indexes flowing to migrations — reviewed as schema, never as "just models"). "Just models" framing waves schema review (decorators unexamined — defaults standing in for design — storage/quality/incidents billed per row forever). Models reviewed like code (behavior, naming); entities reviewed like schema (types, constraints, widths — DDL consequences). Both lenses, every entity PR — code review + schema review, never either alone.

**Performance note** — entity economics: id widths priced per row × horizon (BigInt 8B vs Int 4B — billions of rows affected); enum-as-varchar vs native PG enum (TypeORM `enum` columns map per driver config — storage/index/cache implications decided, never defaulted); timestamp columns indexed where recency queries filter (hot predicate, cheap index — unindexed temporal scans billed per dashboard). Decorator choices compound per row (widths × billions) — price types at declaration (seconds now) vs storage/index/cache forever. Types chosen deliberately; widths priced honestly.

**Mentor note** — teach "every decorator earns its place" (juniors questioning entity lines design deliberately from the first model; unwaved entities arriving pre-justified (types reasoned, nullability contracted, defaults layered — review accelerating instead of interrogating). Praise justified decorators ("good enum closure with priced reasoning") louder than clever relations — teams optimize for praised behavior, and clever undecorated models have had enough admirers. Earn places; praise justifications; wave never.

## 2. Decorators carry mapping intent (Column options, uniques, defaults, enums — constraints beside fields)

**Definition** — column decorators as contracts (`@Column({ unique, nullable, default, length, type, enum })` — each option a DDL decision recorded inline; `@Index`/`@Unique`/`@Check` decorators (verified live exports present — constraints named, enforced); `@CreateDateColumn/@UpdateDateColumn/@DeleteDateColumn/@VersionColumn` (verified live exports present — lifecycle columns conventionalized — optimistic locking via `@VersionColumn` where contention demands). Intent colocated with fields (reviewed per line — constraints visible where declared, never in separate migration archaeology — same discipline as Prisma attributes ([Domain 02 §1.1](<../../../02 Prisma Deep Dive/sections/1. Schema authoring/1.1. Models fields and attributes.md>)), class-flavored).

**What problem it solves** — the options-absent column (`@Column()` bare everywhere — uniqueness added post-incident (duplicates already corrupting); defaults applied in code (backfills/consoles missing them — NULLs where values assumed); lengths unbounded (TEXT for bounded strings — storage/index unpriced); enums as strings (typo'd statuses accumulating). Options declared upfront convert post-incident patches to pre-merge contracts (uniqueness enforced from row one; defaults engine-filled; lengths bounded honestly; enums closed structurally). Bare decorators cost lines saved at authoring; optioned decorators save quarters of archaeology ("which statuses exist?" — DISTINCT answering design questions — unasked with enums).

**Modern guidance** — the options checklist per column (review-enforced): *uniqueness* (identity fields `unique: true` — emails, slugs — enforced from first migration); *nullability* (`nullable: true` = unknown-OK, stated — default non-nullable honored as presence contract); *defaults* (`default:` for shape defaults — engine-filled (verified live pattern); business defaults in code/services — never smuggled into schema); *lengths* (`length: 300` where bounded (index-efficient, honestly capped) vs unbounded text (unbounded honestly — arbitrary limits declined); *enums* (`type: "enum", enum: Role` — closed sets structurally (typos rejected); open sets as relations (growth accommodated without migrations); *lifecycle* (Create/Update/DeleteDateColumn conventionalized — soft-delete via DeleteDateColumn where undo windows required ([Database Design §6.1](<../../../../DatabaseDesign/06 Modeling for Operations/sections/1. History and deletion/1.2. Soft deletes done deliberately.md>) — partial uniques alongside); *optimistic locking* (`@VersionColumn` where lost-update races threaten (counters, balances — version-checked writes — contention priced, not hoped).

```typescript
// GOOD: options intentional per column (verified live patterns: unique/default/enum applied).
// @Column({ unique: true }) email  — identity enforced (duplicates impossible from row one).
// @Column({ type: "enum", enum: Role, default: Role.USER }) role — closed + defaulted
//   (verified live: USER applied without writer input — typos rejected structurally).
// @Column({ length: 300 }) title — bounded honestly (index-efficient).
// @CreateDateColumn() createdAt — conventionalized (temporal questions answerable always).
// @VersionColumn() version — optimistic locking (lost-update races closed structurally).
```

```typescript
// BAD: options-absent columns — intent undeclared, patches post-incident (real shapes).
// @Column() email  // uniqueness absent (duplicates accumulating — cleaned quarterly, forever)
// @Column() status // open stringly-typed ('actvie' rows — typos as data — DISTINCT archaeology)
// @Column() title  // unbounded TEXT (3MB pastes beside 30-char titles — unexamined)
// // defaults: none (writers required for shape — backfills/consoles missing — NULLs assumed)
// // lifecycle: none (temporal questions unanswerable — "when?" asked of every row eventually)
// Intent undeclared; patches post-incident; typos as data. Options cost lines at authoring;
// absence costs archaeology. Declare deliberately or drift permanently.
```

**Common confusion** — *`synchronize: true` makes options unnecessary (schema follows decorators automatically).* Synchronization *applies* options (DDL generated from decorators — convenient); it never *decides* them (unexamined decorators synchronizing bare columns — TEXT everywhere, no uniques, open strings — automation executing undesigned shapes at machine speed). "Synchronize handles it" confuses execution with design (mechanics automated — judgments absent — auto-applied undesigned schemas failing identically to hand-applied ones, faster). Decide options deliberately (reviewed); execute via migrations (governed — [2.2](<../2. Flavors and migrations/2.2. Migrations generated and governed.md>)); synchronize never past development (auto-mutation forbidden — typo'd decorators dropping columns in production).

**Performance note** — options economics: enums closed (typo'd statuses eliminated — queries branching correctly — correctness incidents prevented); lengths bounded (index prefix efficiency — bounded strings indexing tighter); defaults engine-side (zero writer cost — filled at storage); version columns (optimistic locking without pessimistic locks — contention handled at write cost, not lock-hold cost). Undeclared equivalents bill storage (TEXT/enum-open widths), indexes (unbounded looseness), quality (typo branches), and contention (pessimistic fallbacks — lock-holds vs version-checks). Options priced per column-type once; absence billed per row forever.

**Mentor note** — teach "which option, and why?" per column (juniors answering unique/nullable/default/length/enum per field internalize storage thinking permanently — options chosen, never defaulted). Closed-vs-open drill ("roles: enum or table?" — fixed → enum; growing → relation — decided by growth, not taste — 30-second verdicts, drilled per entity — twin of Prisma 02/1.1's drill, class-flavored). Options decided deliberately; growth examined honestly; typos rejected structurally — decorator discipline in three habits, reviewed per entity PR.

## 3. reflect-metadata is load-bearing (import once at entry — silent failure without it)

**Definition** — the runtime contract: `reflect-metadata` imported once at application entry (before any entity loads — first line of main/data-source module — polyfilling decorator metadata APIs (`Reflect.getMetadata` — TypeORM reading `@Column` options at runtime from emitted metadata). Without it decorators evaluate silently inert (no error at decoration — entities unmapped — `RepositoryNotFoundError`/`No metadata found` at first use — the classic TypeORM initiation failure from [Domain 01 §3.1](<../../../01 Data Access Foundations and Mental Model/sections/3. First contact/3.1. Hello database three ways.md>), structural not situational). Silent-inert decorators are the worst failure class (no signal at cause — error surfaces far downstream naming everything except its cause).

**What problem it solves** — the missing-import outage class (new entry points forgetting the import (workers, scripts, tests booting DataSources independently — each missing it failing identically (metadata absent — repositories unresolvable); ESM import-order hazards (entity modules loading before the polyfill (hoisting subtleties — intermittently unmapped entities — order-dependent passes, "works on my machine" as team process); bundler tree-shaking dropping the side-effect import (production-only metadata absence — staging green (different bundling), production red (shaken) — environment-exclusive failure, hardest to diagnose). Entry-point discipline (import first line, linted — architectural linting, not hope) converts all three (every entry importing — workers/scripts/tests covered; order fixed structurally — first line always; bundlers configured (side-effect retained — explicit, never shaken).

**Modern guidance** — the polyfill contract (enforced, never hoped): *first line* (`import "reflect-metadata"` opening every entry point booting TypeORM (main, workers, scripts, test setup — each independently — missing import failing identically per entry); *linted* (architectural lint rule (import presence checked — machines tireless — humans forgetful); *verified* (startup assertion where cheap (metadata presence probed for registered entities — fail-fast at boot with actionable message ("reflect-metadata missing?" — error naming cause, not symptom); *documented* (onboarding lists it (initiation ritual — first TypeORM lesson, never rediscovered painfully). tsc pairing: `experimentalDecorators` + `emitDecoratorMetadata` (verified passing on TS 7.0.2 — S1–S2 on file — compiler emitting what the polyfill reads — both halves required (emit without polyfill: metadata unread; polyfill without emit: nothing to read).

```typescript
// GOOD: polyfill first line, linted, verified (entry-point discipline — structural).
import "reflect-metadata";   // FIRST LINE (before entities — order fixed structurally, never hoped)
import { DataSource } from "typeorm";
import { OrmUser } from "./entities/OrmUser.js";
// Startup assertion (cheap, actionable — fail-fast naming cause):
// for (const e of [OrmUser]) if (!Reflect.getMetadata("design:type", ...)) throw ...
// Lint rule: reflect-metadata import present in entry files (machines checking — humans forgetting).
// tsc flags: experimentalDecorators + emitDecoratorMetadata (TS 7.0.2 passing — verified S1).
```

```typescript
// BAD: polyfill hoped — missing per entry, ordered by luck, shaken by bundlers.
// main.ts (has import — works); worker.ts (forgotten — RepositoryNotFoundError at 3 a.m. —
// on-call discovering initiation failures in production); test-setup.ts (absent — suites failing
// with metadata errors (onboarding blocked hours on setup); ESM order hazard (entities hoisted
// before polyfill — intermittent unmapping — order-dependent passes); bundler shaking
// (production-only absence — staging green, production red — environment-exclusive mystery).
// Hoped per entry; failed per independence; diagnosed per archaeology. Import first line, always.
```

**Common confusion** — *"standard decorators (TC39) remove this requirement."* Standard decorators (Stage 3/TS-native — metadata via `Symbol.metadata`, not reflect-metadata APIs) change the *mechanism* (different metadata store); TypeORM 1.x reads *legacy* metadata APIs (reflect-metadata required regardless of TS decorator flavor configured — library contract, not language contract — version-labeled as-of-September-2026: TypeORM 1.1.1 + legacy emit). "Standard" describing TS syntax (decorator evaluation) while TypeORM requires legacy metadata (introspection APIs) — orthogonal requirements conflated constantly. Configure per library contract (TypeORM 1.x: legacy emit + polyfill — verified passing), track upstream migration (future TypeORM standard-metadata support — version notes, never assumed). Library contract governs; language defaults don't.

**Performance note** — polyfill economics: import cost once per process (microseconds — metadata APIs defined — negligible); metadata emission cost per entity at load (reflection data built — startup milliseconds on large models — cold-start priced for serverless (entity counts bounded per DataSource where cold matters); absence cost catastrophic (unmapped entities — total failure, not degradation — binary outcome (works/fails), no middle). Binary outcomes demand structural guarantees (first-line + linted + asserted — absence impossible, not unlikely). Microseconds per boot prevent total failures per entry — cheapest insurance in TypeORM operations, permanently.

**Mentor note** — teach reflect-metadata as initiation ritual (first TypeORM lesson — import line one, tsc flags line two, lint rule line three — ritual complete before first entity — initiation failures preempted structurally, never experienced). Demonstrate the failure once (remove import in staging — RepositoryNotFoundError live — error naming everything except cause — diagnosis practiced on schedule, never in production). Ritualize entry (first line always); lint presence (machines checking); assert boot (fail-fast actionable). Initiation complete; failures preempted; metadata present — three verbs, zero 3 a.m. surprises.
