# 5.1. Common interview QA TypeORM

## 1. Entities live (decorated classes on a whiteboard — TypeORM syntax, modeling judgment)

**Definition** — the exercise: *"model users/orders in TypeORM"* (the interview staple). The graded artifact is judgment performed in decorator syntax (entities from nouns ([Database Design §1.3](<../../../../DatabaseDesign/01 Modeling Foundations and Mental Model/sections/3. First design moves/3.1. From requirements to tables.md>) — stated, not skipped); ids per strategy (BigInt default, naturals UNIQUE beside — [1.1](<../1. Entities and relations/1.1. Entities and decorators that mean something.md>) performed); relations both sides with owner + actions ([1.2](<../1. Entities and relations/1.2. Relations the TypeORM way.md>) performed — four parts, stated); reflect-metadata named unprompted (entry-point first line — initiation ritual stated — the expert tell distinguishing practiced TypeORM from tutorial-skimmed). Syntax correct AND judgments stated — either alone halves the score.

**What problem it solves** — the two whiteboard failures: *syntax-only entities* (decorated classes with unexamined ids (Int defaults capping silently), half-declared relations (reverse traversals unservable), defaulted actions (runtime surprises), reflect-metadata unmentioned (initiation failures scheduled for workers/scripts); and *judgment-only modeling* (entities/dependencies narrated without decorator expression ("I'd add a foreign key somehow" — unhirable for a TypeORM role regardless of modeling wisdom). Senior TypeORM loops grade both simultaneously (syntax fluency assumed — judgments volunteered — silence on either interrogated). Perform both, narrate continuously (thinking aloud — decisions audible, always).

**Modern guidance** — the ten-minute shape: (1) *entities* (3 min — nouns to decorated classes, ids per strategy, attributes intentional ([1.1](<../1. Entities and relations/1.1. Entities and decorators that mean something.md>) performed briskly); (2) *relations* (4 min — both sides + JoinColumn + actions per association ([1.2](<../1. Entities and relations/1.2. Relations the TypeORM way.md>)... [1.2](<../1. Entities and relations/1.2. Relations the TypeORM way.md>)); m-n explicit with attributes (growth accommodated); 1-1 via unique FK); (3) *decisions narrated* (3 min — id choice reasoned; action choices reasoned (both lenses); reflect-metadata stated unprompted ("entry-point first line, linted" — initiation ritual performed); synchronize forbidden past dev (stated with the horror story — production seriousness signaled). Syntax written (decorated classes complete); judgments spoken (reasons per choice — silence interrogated).

```typescript
// GOOD (whiteboard, users/orders — 10 min, syntax + judgment performed):
@Entity({ name: "users" })
class User {
  @PrimaryGeneratedColumn({ type: "bigint" })   // "BigInt default (viral-safe — Int caps silently)"
  id!: number;
  @Column({ unique: true })                     // "natural beside it (UNIQUE, unreferenced)"
  email!: string;
  @OneToMany(() => Order, (o) => o.customer)
  orders!: Order[];
}
@Entity({ name: "orders" })
class Order {
  @PrimaryGeneratedColumn() id!: number;
  @ManyToOne(() => User, (u) => u.orders, { onDelete: "RESTRICT" })
  @JoinColumn({ name: "customerId" })           // "owner marked (explicit — strategy-independent)"
  customer!: User;                              // "RESTRICT (history immutable — domain lens)"
}
// + "reflect-metadata first line, linted; synchronize never past dev" (rituals stated unprompted).
```

```typescript
// BAD (whiteboard): syntax without judgment, or judgment without syntax.
// @Entity() class User { @PrimaryGeneratedColumn() id: number; @Column() email: string; }
// (Int cap unexamined; uniqueness absent (duplicates accumulating); relations undescribed;
// reflect-metadata unmentioned (initiation failures scheduled); synchronize unaddressed.)
// Or: "I'd have users and orders with a foreign key, normalized..." (decorators undescribed —
// relations unexpressed in TypeORM terms — unhirable for a TypeORM role regardless of wisdom.)
```

**Common confusion** — *"whiteboard decorators must be perfect (compile-ready)."* Interviewers grade *decisions + fluency* (relations both-sided? actions stated? ids reasoned? rituals named? — judgment), tolerating syntax slips (decorator option names, import paths — corrected casually, unpenalized). Perfectionism wastes time (option-name fussing while judgments unstated — minutes on trivia, silence on substance); fluency with slips passes (judgments performed, syntax approximate — hirable demonstrated). Decide aloud; write fluently; correct slips casually. Judgments hire; typos don't fire.

**Performance note** — volunteer key/decorator decisions unprompted ("BigInt width priced per row-horizon; FK indexes audited at birth; reflect-metadata first-line linted") — performance clauses preempt follow-ups ("what about scale?" — answered before asked). Unvolunteered performance invites probing (reactive answers scoring lower than proactive). Volunteer performance; preempt probing; control narrative — same pattern as every QA leaf, TypeORM edition.

**Mentor note** — drill whiteboard entities timed (10 minutes, entities→relations→decisions — graded: syntax fluent? judgments stated? rituals named?). Time each phase separately (entities 3min, relations 4min, narration 3min — phase scores diagnosing precisely ("fluent syntax, silent judgments" — drill narration, not models). Timed drills convert typists to modelers and theorists to practitioners — both directions, one prescription (perform both, narrate continuously).

## 2. Flavors under questioning (ActiveRecord versus Repository — the jurisdiction answer)

**Definition** — the follow-up: *"ActiveRecord or repositories — which do you use?"* (the jurisdiction filter). The failing answers are absolute ("repositories always — best practice" — ceremony without graphs (trivial tools ceremonied); "ActiveRecord always — simple" — coupling without simplicity (side effects smuggled, tests database-bound). The passing answer is *jurisdiction with triggers* (AR for trivial lifecycles — prototypes/admin/config (exit triggers recorded: side effects? test pain? second store?); repositories for growing domains (side effects present, tests slowing, stores multiplying — graduated deliberately); mixed per bounded context (map documented — boundaries linted — graduation scheduled). Triggers convert absolutes to jurisdictions (decisions with horizons, never dogmas).

**What problem it solves** — flavor questions filter for contextual judgment (most candidates answer tribally ("my team used repositories" — habit reporting; "ActiveRecord is legacy" — fashion reciting (verified false on 1.1.1 — both flavors shipped, maintained). Interviewers listen for triggers (exit conditions stated — side effects/test pain/second store — judgment performing) and mixing discipline (per-context placement — boundaries documented — graduation scheduled). Tribal answers signal tutorial-following (tools used, prices unknown); triggered answers signal production judgment (abstractions adopted deliberately, exits planned). Triggers stated; mix mapped; absolutes declined.

**Modern guidance** — the ninety-second shape: (1) state both flavors honestly ("ActiveRecord: records carry themselves (BaseEntity — trivial lifecycles — verified present, maintained); repositories: mappers own storage (getRepository + .extend() customs — 1.x idiom — verified live)"); (2) place per context ("admin tool (trivial, stable): AR (ceremony unjustified); orders (side effects, tests, growth): repositories (seams explicit, fakes faithful)"); (3) triggers dated ("AR contexts carry exit triggers (side effects? test pain? second store? — graduation scheduled); 0.3 customs migrated (.extend() — verified live — version-skew corrected)"). Flavors honored (both shipped — neither legacy); contexts placed (map documented); triggers dated (graduation scheduled, never hoped).

```typescript
// GOOD (spoken, 90 seconds — flavors honored, contexts placed, triggers dated):
// "Both ship in 1.x (verified: BaseEntity AND getRepository present — neither legacy).
// Trivial lifecycles (admin tools, prototypes): ActiveRecord (ceremony unjustified —
// triggers recorded: side effects? test pain? second store?). Growing domains (orders,
// billing): repositories + .extend() customs (verified live idiom — seams explicit, fakes
// faithful). Mixed per bounded context (map documented — AR entities never imported into
// DM contexts — linted). 0.3 customs migrated (.extend() — version-skew corrected)."
// Honored, placed, dated. No absolutes survived; judgment performed.
```

```typescript
// BAD (spoken): the absolute — tribal, untriggered, context-free.
// "Repositories always — ActiveRecord is an anti-pattern." (Trivial tools ceremonied —
// six files where one class sufficed (indirection without beneficiaries); AR jurisdiction
// denied (simplicity slandered as legacy — fashion, not engineering). Triggers absent
// (graduation vocabulary missing — everything repositories, growth unexamined).)
// Or the mirror: "ActiveRecord — simpler, less code." (Side effects smuggled; tests
// database-bound; second store blocked — coupling scheduled, triggers unrecorded.)
// Absolutes hire nowhere senior — jurisdictions hire everywhere.
```

**Common confusion** — *"interviewers want one answer (pick a side)."* They want *jurisdiction with triggers* (both flavors honored — contexts placed — exits dated — judgment performing under questioning). "Which side" frames tribal answers (picked sides defended passionately, contexts unexamined); "which jurisdiction" frames engineering (triggers stated — verdicts revisable — graduation scheduled). Sides posture; jurisdictions decide. State triggers; map contexts; decline absolutes — interviewed judgment, not debated tribalism.

**Performance note** — volunteer flavor economics ("AR: transparent per-operation, test-drag as lifecycles grow; repositories: zero runtime overhead, suite-seconds via fakes — velocity compounding daily"). Economics with triggers (numbers + exits stated — complete flavor judgment in one extra breath). Unvolunteered economics invites "at scale?" probing (reactive answers scoring lower). Volunteer economics; preempt probing.

**Mentor note** — drill as jurisdiction rapid-fire (ten contexts, ninety seconds each — admin/prototype/orders/billing/config/sessions — flavor + triggers per context — verdicts timed, absolutes failing rounds). Speed forces internalization (jurisdictions reflex, not reference — fashion failing visibly under time pressure). Tribal answers die in drills (absolutes indefensible at speed — triggers demanded, verdicts timed); judgment performs (placed, triggered, dated — hired). Drill jurisdictions; demand triggers; decline absolutes.

## 3. Migrations and N+1 live (generate/run discipline, counted loads — operations answers)

**Definition** — the closer: *"how do you ship schema changes and keep lists fast?"* (two operations questions, one breath). The graded answer pairs disciplines (migrations: generate-reviewed-run-reverted (diffs read fully — verified live shapes cited (BIGSERIAL/UQ/PK visible); show-before-run (state known); synchronize never prod (linted); N+1: strategies stated per relation (relations option — verified live (absent vs 2 books) — counts asserted per list test (01/4.1 detector); QueryBuilder for unmappable (verified live join — loops declined where joins serve). Operations answers cite verified behaviors (generate output quoted, live counts cited (absent-vs-2) — evidence, not slogans).

**What problem it solves** — operations questions filter for production contact (most candidates describe happy paths ("run migrations, eager-load relations" — unreviewed diffs (flag-days scheduled); unstrategized loads (N+1 hoped away); synchronize unaddressed (auto-mutation incidents pending). Interviewers listen for witnessed procedures (diffs read? show run? synchronize linted?) and counted loads (assertions filed? strategies stated? QueryBuilder known?). Happy-path answers hire juniors (commands known); operations answers hire seniors (guards cited, counts enforced, discipline evidenced — verified behaviors referenced, not hypothesized).

**Modern guidance** — the two-minute shape (migrations minute + loads minute): *migrations* ("generate diffs metadata-vs-DB (verified live output quoted: BIGSERIAL/UQ/PK + down present); review fully (phases/witnesses/indexes); show-before-run (state known — verified live read-only); run pending (tracked); synchronize never prod (linted — initiation horror cited briefly)"); *loads* ("strategies per relation (relations option — verified live: absent vs 2); counts asserted per list (01/4.1 detector — N+1 fails builds); QueryBuilder for unmappable (verified live join — loops declined); cascade saves nested (verified live — partial graphs impossible)"). Verified behaviors cited per claim (generate output quoted, live counts referenced — evidence, never slogans); disciplines paired (migrations governed + loads counted — operations complete).

**Common confusion** — *"operations answers need production experience (juniors exempt)."* Operations *judgment* needs study, not tenure (verified behaviors citable from practice environments (staging round-trips, generated diffs read, live counts measured — evidence available pre-production); disciplines performable in exercises (generate/review/run/revert rehearsed on dev databases — procedures identical, stakes lower). "No production yet" excuses unpreparedness never (staging + drills + verified behaviors — preparation available to all levels); experience accelerates (scar tissue prioritizing instantly) but study suffices (evidenced disciplines hiring juniors into senior-track roles). Study verified behaviors; rehearse procedures; cite evidence — operations answers without tenure, hired on merit.

**Performance note** — close with paired economics ("migrations governed (minutes per change — quarters of archaeology avoided); loads counted (milliseconds per test — quarters of linear latency avoided); synchronize linted (seconds per build — data-loss incidents preempted)". Paired disciplines, priced jointly — operations maturity in one extra breath. Economics with evidence (verified outputs cited — numbers, not adjectives); disciplines paired (migrations + loads — operations complete). Price jointly; evidence always.

**Mentor note** — drill operations Q&A (ten scenarios, ninety seconds each — flag-day diff, unbaselined brownfield, synchronize leak, unstrategized list, unmappable aggregation — verdicts timed, evidence cited, procedures named). Speed forces internalization (guards reflex, counts habitual, disciplines performed — fashion failing visibly under time pressure). Scenario drills convert command-knowledge to operations judgment (happy-path reciters becoming guard-citing seniors within weeks). Drill scenarios; cite evidence; name procedures.
