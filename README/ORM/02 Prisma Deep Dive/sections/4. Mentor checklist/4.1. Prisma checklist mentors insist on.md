# 4.1. Prisma checklist mentors insist on

## 1. Schema reviewed like code (models, relations, attributes — every line earning its place)

**Definition** — the review's first pass over Prisma schemas: every model/field/relation/attribute earning its place — models justified (entities with lifecycles — [Database Design §1](<../../../DatabaseDesign/01 Modeling Foundations and Mental Model/README.md>) consumed, not re-derived); fields typed deliberately (BigInt vs Int vs UUID decided — widths priced; nullability contracted — presence decided; defaults layered correctly — shape vs business); relations complete (both sides + actions stated — [1.2](<../1. Schema authoring/1.2. Relations in schema.md>)'s four parts); attributes intentional (uniques/defaults/natives/enums per [1.1](<../1. Schema authoring/1.1. Models fields and attributes.md>) — intent visible per line). Schema files are code with DDL consequences (reviewed rigorously — "config" framing rejected — every line questioned, every answer recorded).

**What problem it solves** — the waved schema (models merged unreviewed ("just Prisma models" — Int ids capping at 2B silently; TEXT-everywhere storage unpriced; stringly-typed statuses accumulating typos; relations half-declared (reverse traversals unservable — migrations later); delete actions defaulted (runtime surprises scheduled)). Each unreviewed line bills per row forever (widths × billions), per query eventually (unindexed FKs scanning), per incident quarterly (anomalies/type-typos/defaults failing). Review minutes per schema PR convert to quarters avoided at the usual rate — highest-ROI minutes in Prisma operations, permanently true.

**Modern guidance** — the schema review lines (per model, review-enforced): *identity* (id type decided — BigInt default (viral-safe), Int justified (bounded domains), UUID for distributed (generation topology stated) — width priced per row × horizon); *fields* (types deliberate (natives where bounded — VarChar/enum/timestamptz decided); nullability contracted (nullable = unknown-OK, stated); defaults layered (shape engine-side, business in code — smuggling absent); *relations* (four parts present (list + back-ref + scalar + @relation); actions stated (Cascade/Restrict/SetNull per relationship — both lenses (domain + volume)); *enums* (closed sets enumerated (DB-native); open sets modeled as relations (growth accommodated — enum-vs-table decided per growth forecast). Missing line → request changes; "Prisma handles it" → tooling executes, reviewers decide (automation never approves judgment).

```prisma
-- GOOD: the schema review artifact — every line earning its place (excerpt).
-- User.id: BigInt autoincrement (viral-safe default — width priced ✓).
-- User.email: String @unique (identity — enforced from row one ✓).
-- User.role: enum Role @default(USER) (closed set — DB-native — typos rejected ✓).
-- User.posts[] + Post.author/authorId @relation(onDelete: Cascade) (both sides + action ✓).
-- Post.title: @db.VarChar(300) (bounded honestly ✓). Verdict: approve schema.
```

```prisma
-- BAD: the waved schema — lines unexamined, consequences scheduled.
-- User.id: Int (2B cap — viral incident scheduled). User.data: Json (untyped payloads —
-- validation hoped, queries unindexed). Post.authorId: bare scalar (unlinked — orphans
-- accumulating, navigation absent). Statuses as String (typo'd rows accumulating).
-- Defaults: none (writers required for shape — backfills/consoles missing). Relations:
-- actions defaulted (NO ACTION surprises scheduled). Waved ("just models"); billed quarterly.
```

**Common confusion** — *"schema review duplicates migration review (same diff twice)."* Schema review judges *design* (types/relations/attributes — right shapes?); migration review judges *change* (phases/compatibility/witnesses — safe shipping?). Different subjects (shapes vs transitions), different failures (wrong types persist forever; unsafe transitions break deploys once each), both required (right shapes shipped wrongly fail; wrong shapes shipped safely persist). Review shapes at schema PRs (design correctness); review transitions at migration PRs (shipping safety) — two reviews, two subjects, zero duplication (DRY honored — each review owning its questions exclusively).

**Performance note** — schema-review economics: type widths priced per row × horizon (BigInt-vs-Int decided once — billions of rows affected); FK indexes audited at birth (seconds per index empty — hours CONCURRENTLY under load — birth-indexing enforced); enum natives chosen (4B OIDs vs TEXT per row — storage/index/cache leaner). Unreviewed equivalents bill storage (widths × billions), queries (unindexed scans), quality (typo'd statuses branching). Review minutes per schema PR (types/relations/attributes questioned); quarters avoided per incident class (width/scan/typo). Minutes now, quarters never.

**Mentor note** — teach "every line earns its place" (juniors questioning schema lines design deliberately from the first model; unwaved schemas arriving pre-justified (types reasoned, relations complete, attributes intentional — review accelerating instead of interrogating). Praise justified lines ("good BigInt default with priced reasoning") louder than clever relations — teams optimize for praised behavior, and clever unpriced schemas have had enough admirers. Earn places; praise justifications; wave never.

## 2. Migrations witnessed end to end (dev generates, review approves, deploy executes)

**Definition** — the review's second pass over schema change: dev generates (diffs rendered — reviewable SQL, drifted DBs refused without reset — verified behaviors), review approves (phases classified, renames declared, nullability checked, indexes verified, witnesses planned — [2.1](<../2. Migrations and client/2.1. Migrate tooling that stays honest.md>) performed), deploy executes (pending-only via `migrate deploy` — status-gated CI — production reproducing history, never improvising). End-to-end witnessing means every handoff verified (generate→review (diffs read fully); review→deploy (approval recorded); deploy→production (status green, checksums matching)). Skipped handoffs fail structurally (unreviewed diffs, ungated deploys, unwitnessed contracts — each a scheduled incident with unknown date).

**What problem it solves** — the unwitnessed pipeline (dev diffs applied directly ("migrate dev worked locally" — unreviewed flag-days reaching staging/production (blocking rewrites, drop+create renames, missing indexes — incidents wearing velocity); deploys ungated (status unchecked — drifted production (hotfixes direct) meeting pending history (conflicts/duplicates — mysterious failures on fiction-built foundations); contracts unwitnessed (drops merged without grep-zero + freeze — dashboards breaking Monday, BI extracts failing silently). Witnessing converts pipeline stages to checkpoints (generate→reviewed, approved→deployed, deployed→verified — each transition evidenced, none hoped). Checkpoints cheap (minutes per handoff); incidents dear (quarters each).

**Modern guidance** — the witnessing lines per migration (CI + human enforced): *generate* (diff rendered on owned dev DB (reset-refusals on shared DBs respected — dev databases owned, never shared); *review* (phase named, renames declared, nullability checked, indexes verified, stragglers named — [2.1](<../2. Migrations and client/2.1. Migrate tooling that stays honest.md>) performed fully); *gate* (status checked in CI (expected pendings matching release — drift failing builds — unexpected pendings investigated, never waved); *deploy* (`migrate deploy` pending-only (history replayed, checksummed, recorded — production reproducible from migrations alone); *verify* (post-deploy status green (applied == history — divergence absent — health confirmed, not hoped). Missing witness → request changes/block deploys; witnessed chain → approve calmly (evidence complete, judgment recorded).

```sql
-- GOOD: the witnessing chain — generate→review→gate→deploy→verify (excerpt).
-- Generate: diff rendered on owned dev DB (reset-refusal respected — shared untouched) ✓.
-- Review: phase EXPAND named; renames none; nullability safe; indexes verified ✓.
-- Gate: status pendings match release (drift absent — CI green structurally) ✓.
-- Deploy: migrate deploy pending-only (history replayed, recorded ✓).
-- Verify: post-deploy status green (applied == history ✓). Verdict: approve pipeline.
```

```sql
-- BAD: the unwitnessed pipeline — stages skipped, history hoped.
-- Generate: migrate dev on shared staging (reset offered — declined nervously — drifted dev DB
-- generating fiction diffs). Review: skipped ("small diff" — flag-day NOT NULL inside).
-- Gate: absent (status unchecked — production drifted via hotfixes — pending history conflicting).
-- Deploy: console DDL "to be quick" (history bypassed — fiction institutionalized).
-- Verify: none (applied hoped — divergence discovered next deploy (mysteriously failing on
-- fiction-built foundations). Stages skipped; witnesses absent; incidents scheduled (dateless).
```

**Common confusion** — *"small migrations don't need witnessing (overhead)." Witnessing scales with risk (trivial additive diffs: phase named, witnesses N/A-stated — seconds; breaking changes: full ritual — minutes), never waives structurally (unwitnessed "small" drops breaking dashboards (size of diff ≠ size of consequence — one-line drops deleting histories); ungated "small" deploys meeting drift (pendings unexpected — small release, large surprise). Overhead framing counts witnessing seconds while ignoring incident quarters — full ledger favors witnessing by orders of magnitude, permanently. Witness proportionally; waive never.

**Performance note** — witnessing economics: generate/review/gate/deploys/verify costing minutes per migration (bounded, calm — pipeline steps automated where checkable (status gates, linter phases — machines tireless); review judgment human (phases, witnesses — mentors precise). Unwitnessed equivalents costing blocking rewrites (unphased flag-days in windows), repair migrations (fiction-built foundations — archaeology quarters), dropped histories (unwitnessed drops — BI/dashboards failing). Minutes per migration prevent quarters per incident — witnessing ROI exceeding all other migration investments (evidence chains compound; hope chains break).

**Mentor note** — teach "witness every handoff" (juniors checking generate→review→gate→deploy→verify design pipelines completely on first hearing; handoffs skipped interrogated ("status checked?" — gate demanded; "contract witnessed?" — evidence demanded). Automate checkable handoffs (status gates, phase linters, drop-witness checks — machines tireless); humanize judgment handoffs (phase classification, witness evaluation — mentors precise). Witness handoffs; automate checks; judge transitions — pipeline discipline in three habits, reviewed per migration.

## 3. Client queries logged and bounded (strategies stated, counts asserted — magic inventoried)

**Definition** — the review's closing act over data access: every relation read states its strategy (include/select per query — [2.2](<../2. Migrations and client/2.2. Client queries and relations.md>) performed — eager by decision, never default); every list asserts its counts (statement bounds per test — [3.1](<../3. Performance discipline/3.1. N+1 strategies and raw escapes.md>) performed — N+1 failing builds); query logging on in dev/test (every statement visible per render — surprises pre-merge); Prisma magic inventoried per major (middleware removal noted (v7 `$use` gone — gauges migrated to events); default behaviors listed (relation loading explicit — no lazy magic — cascade/transaction defaults reviewed); v8 RC watched per track index (majors re-priced on arrival — ledgers living, never fossilized).

**What problem it solves** — the unobserved client (strategies unstated (relations loaded by habit — includes present-or-absent per author mood — N+1 scheduled per unexamined traversal); counts unasserted (lists green on staging tens — linear in production ten-thousands — latency discovered at scale); logging off (statements invisible — surprises scheduled (cartesian includes, fan-out transfers — unobserved until p99 cliffs); magic uninventoried (major upgrades changing defaults silently — v7 middleware removal breaking counters (verified live this session — gauges dead silently post-upgrade — N+1 unobserved from the migration that removed observation). Logged/bounded/inventoried clients convert all four (strategies stated, counts asserted, statements visible, magic listed — surprises structurally impossible, upgrades explicitly re-priced).

**Modern guidance** — the client review lines per data-access PR: *strategy* (include/select per relation read — stated explicitly (verified patterns — batched includes, trimmed selects — unstrategized traversals returned with "which strategy?" — question asked in seconds, answered with includes); *counts* (statement bounds per list test — ≤N derived from shape — N+1 failing builds (asserted, not hoped); *logging* (query events on (v7 `$on("query")` — development/test default — every statement visible per render — dark SQL absent); *magic* (per-major inventory (v7: middleware gone (gauges migrated ✓); no lazy loading (structural immunity ✓); cascade/transaction defaults reviewed (surprising entries disabled ✓); v8 RC watched (track index noted — ledger re-price on stable arrival). Missing line → request changes; v6 idioms → migrate (stale middleware/calls corrected — version-skewed code modernized, never tolerated).

```typescript
// GOOD: the client review artifact — strategies, counts, logs, magic (excerpt).
// Strategy: order list includes lines explicitly (stated per query ✓ — lazy absent structurally).
// Counts: ≤3 statements/test asserted (N+1 fails builds ✓ — verified live pattern: 3 looped vs 2 batched).
// Logging: $on("query") on (v7 idiom — statements visible per render ✓).
// Magic: v7 inventoried (middleware gone — gauges migrated ✓; cascades reviewed ✓; v8 RC watched ✓).
// Verdict: approve client usage.
```

```typescript
// BAD: the unobserved client — strategies unstated, counts unasserted, logs off, magic unknown.
// Strategy: unstated (includes present-or-absent per author — N+1 scheduled per unexamined traversal).
// Counts: unasserted ("works in staging" — tens of rows hiding ten-thousands of statements).
// Logging: off ("noisy" — surprises scheduled (cartesian includes, fan-out transfers — p99 cliffs official).
// Magic: unknown (v6 $use counters dead post-upgrade (verified breakage — gauges absent since migration);
// cascade defaults unexamined (cleanup scripts deleting parents — data loss wearing convenience).
// Unobserved clients bill quarterly (linear latencies, magic incidents, upgrade surprises). Observe always.
```

**Common confusion** — *"client review duplicates N+1 testing (same checks twice)."* N+1 testing asserts *counts* (statements bounded — quantitative — tests failing on numbers); client review examines *strategies + magic + logging* (qualitative + infrastructural — includes stated? gauges migrated? defaults inventoried? — judgmental). Counts without strategies pass accidentally-correct queries (bounded today, fragile tomorrow — strategy changes silently reintroducing N+1); strategies without counts pass intended-but-broken queries (includes stated, loops beside them — discipline claimed, N+1 shipped). Both required (quantitative bounds + qualitative strategies + infrastructural logging + versioned magic — four lines, complete client review). Count and strategize; log and inventory.

**Performance note** — client-review economics: strategies stated (minutes per relation — batching designed); counts asserted (milliseconds per test — N+1 structurally impossible); logging on (log volume dev-only — negligible); magic inventoried (minutes per major — upgrades explicitly re-priced). Unobserved equivalents: linear latencies (N+1 at scale — quarters of remediation); upgrade surprises (dead gauges, changed defaults — incidents per major); magic incidents (cascades, fan-outs — data loss + fiction dashboards). Review minutes per data-access PR prevent quarters per incident class — client review ROI exceeding all other Prisma practices (observed clients never surprise — surprises are the only incidents).

**Mentor note** — teach "strategy/counts/logs/magic" as the client review mantra (juniors reciting per data-access PR internalize completeness before speed — mantra first, fluency follows). Automate counts + logging (assertions in tests, events on by default — machines tireless); humanize strategies + magic (include decisions, default inventories — mentors precise). Praise observed clients ("great strategy statement with counts" — behavior praised, repeated); interrogate unobserved ones ("which strategy?" — seconds, devastating, effective). Mantra memorized; automation tireless; judgment human — review complete, clients observed, surprises extinct.
