# 5.1. Common interview QA Prisma

## 1. Schema design live (models + relations on a whiteboard — Prisma syntax, modeling judgment)

**Definition** — the exercise: *"model users/orders/payments in Prisma"* (the interview staple). The graded artifact is judgment performed in Prisma syntax (entities from nouns ([Database Design §1.3](<../../../DatabaseDesign/01 Modeling Foundations and Mental Model/sections/3. First design moves/3.1. From requirements to tables.md>) — stated, not skipped); keys per strategy (BigInt default, naturals UNIQUE beside — [1.1](<../1. Schema authoring/1.1. Models fields and attributes.md>) performed); relations both sides with actions ([1.2](<../1. Schema authoring/1.2. Relations in schema.md>) performed — four parts, stated); m-n explicit where attributed (junction models with `@@id` — growth accommodated, never migrated later). Syntax correct AND judgments stated — either alone halves the score (syntax without judgment: typist; judgment without syntax: theorist).

**What problem it solves** — the two whiteboard failures: *syntax-only modeling* (Prisma-fluent models with unexamined keys (Int defaults capping silently), half-declared relations (reverse traversals unservable), defaulted actions (runtime surprises) — typist hired as modeler, incidents scheduled); and *judgment-only modeling* (entities/dependencies narrated without Prisma expression (relations undescribed in schema terms — "I'd add a foreign key somehow" — unhirable for a Prisma role regardless of modeling wisdom). Senior Prisma loops grade both simultaneously (syntax fluency assumed — judgments volunteered — silence on either interrogated). Perform both, narrate continuously (thinking aloud — decisions audible, always).

**Modern guidance** — the ten-minute shape: (1) *entities* (2 min — nouns to models, keys per strategy, attributes intentional — [1.1](<../1. Schema authoring/1.1. Models fields and attributes.md>) performed briskly); (2) *relations* (4 min — both sides + actions per association ([1.2](<../1. Schema authoring/1.2. Relations in schema.md>)); m-n explicit with `@@id` + attributes (growth accommodated); 1-1 via unique FK (enforced structurally)); (3) *decisions narrated* (4 min — key choice reasoned ("BigInt default — viral-safe, width priced"); action choices reasoned ("CASCADE lines (contained), RESTRICT orders (history)" — both lenses); m-n explicitness reasoned ("attributes foreseeable — growth accommodated, migration never")). Syntax written (whiteboard Prisma — models complete); judgments spoken (reasons per choice — silence interrogated). Both performed, neither assumed.

```prisma
// GOOD (whiteboard, users/orders — 10 min, syntax + judgment performed):
model User {
  id    BigInt @id @default(autoincrement())  // "BigInt default (viral-safe — Int caps at 2B silently)"
  email String @unique                        // "natural beside it (UNIQUE, unreferenced)"
  orders Order[]
}
model Order {
  id         BigInt @id @default(autoincrement())
  customer   User   @relation(fields: [customerId], references: [id], onDelete: Restrict)
  customerId BigInt  // "both sides + RESTRICT (history immutable — domain lens; erasure ticketed — volume lens)"
  total      Decimal @db.Decimal(12, 2)       // "money exact (float drift declined — natives decided)"
}
```

```prisma
// BAD (whiteboard): syntax without judgment, or judgment without syntax.
// model User { id Int @id @default(autoincrement()); orders Order[] }  // (Int cap unexamined —
// 2B rows scheduled; email absent as identity (natural unconsidered); actions defaulted (NO ACTION
// surprises); decisions unnarrated (silence where judgment belongs — typist, not modeler).)
// Or: "I'd have users and orders with a foreign key, normalized to 3NF..." (Prisma undescribed —
// relations unexpressed in schema terms — judgment floating without syntax — theorist, unhirable here.)
```

**Common confusion** — *"whiteboard syntax must be perfect (compile-ready)."* Interviewers grade *decisions + fluency* (relations both-sided? actions stated? keys reasoned? — judgment), tolerating syntax slips (attribute misspellings, directive order — corrected casually, unpenalized). Perfectionism wastes time (attribute-order fussing while judgments unstated — minutes on trivia, silence on substance); fluency with slips passes (judgments performed, syntax approximate — hirable demonstrated). Decide aloud; write fluently; correct slips casually. Judgments hire; typos don't fire.

**Performance note** — volunteer key/index decisions unprompted ("BigInt width priced per row-horizon; FK indexes audited at birth (seconds empty) — 04/1.1 discipline through tooling") — performance clauses preempt follow-ups ("what about scale?" — answered before asked — control demonstrated). Unvolunteered performance invites probing (interviewer digging — reactive answers scoring lower than proactive ones). Volunteer performance; preempt probing; control narrative — same pattern as every QA leaf, Prisma edition.

**Mentor note** — drill whiteboard modeling timed (10 minutes, entities→relations→decisions — graded: syntax fluent? judgments stated? actions reasoned? m-n placed?). Time each phase separately (entities 2min, relations 4min, narration 4min — phase scores diagnosing precisely ("fluent syntax, silent judgments" — drill narration, not models). Timed drills convert typists to modelers and theorists to practitioners — both directions, one prescription (perform both, narrate continuously). Drill timed; grade phases; prescribe precisely.

## 2. Migration safety under questioning (dev vs deploy, baselines, drift — operations answers)

**Definition** — the follow-up: *"how do you ship schema changes safely?"* (the operations filter). The graded answer separates environments by verb (dev authors (diffs generated, reviewed, resettable — development databases owned); deploy executes (pending history only — status-gated CI — production reproducing history); brownfields baselined (`resolve --applied` — history starting honest); drift reconciled (status/diff scheduled — divergence investigated, never ignored). Environment-verbs stated (author vs execute — different tools, different databases, different failure modes); guards cited from experience (reset-refusal on shared DBs, P3005 without baseline — both verified live this session — tooling protecting data visibly, narrated confidently).

**What problem it solves** — migration questions filter for operations maturity (most candidates describe happy paths ("run migrate dev" — environments unseparated (dev tooling against production imagined-or-worse-practiced); baselines unknown ("what's a brownfield?" — legacy databases unadoptable — greenfield-only thinking); drift unconsidered ("hotfixes?" — blank stares — production reality unacknowledged). Interviewers listen for environment separation (dev vs deploy verbs distinct — maturity), guard awareness (refusals cited — experience), brownfield honesty (baselines named — reality). Happy-path answers hire juniors (commands known); operations answers hire seniors (guards cited, brownfields baselined, drift reconciled).

**Modern guidance** — the ninety-second shape: (1) separate verbs ("dev authors on owned databases (resettable); deploy executes pending history (status-gated CI); never crossed (dev tooling past development is incidents wearing convenience)"); (2) cite guards ("shared DBs refused without reset (verified — protection, not obstruction); unbaselined deploys refused P3005 with baselining pointer (verified — guards firing visibly)"); (3) baseline brownfields ("resolve --applied after reality inventory (history starting honest — normal flow after)"); (4) reconcile drift ("status/diff scheduled (divergence alerting); hotfixes reverse-engineered into migrations (history true throughout)"). Verbs separated, guards cited, brownfields baselined, drift reconciled — operations maturity in ninety seconds.

```sql
-- GOOD (spoken, 90 seconds — verbs, guards, baselines, drift):
-- "Dev authors (owned databases — diffs generated, reviewed, resettable); deploy executes
-- (pending-only via migrate deploy — status-gated CI — production reproducing history).
-- Guards: shared DBs refused without reset (seen live — protection); P3005 without baseline
-- (seen live — baselining pointer included). Brownfields: resolve --applied after inventory
-- (honest start). Drift: status scheduled (divergence alerting — hotfixes reverse-engineered)."
```

```sql
-- BAD (spoken): the happy path — commands known, operations absent.
-- "Run prisma migrate dev, then deploy." (Environments? Unseparated (dev tooling imagined
-- against production — or practiced — either alarming). Guards? Unknown (reset-refusal,
-- P3005 — never encountered — greenfield-only experience showing). Brownfields? Blank
-- ("just migrate" — legacy reality unacknowledged). Drift? Unconsidered (hotfixes invisible
-- to history — fiction scheduled). Commands recited; operations absent. Junior answers.
```

**Common confusion** — *"migration interviews want command memorization."* Commands are checkable in seconds (docs open — memorization unneeded); *judgment* is graded (verbs separated? guards cited? brownfields baselined? drift reconciled? — operations maturity, ungooglable live). "Which command?" answered from docs; "how safely?" answered from experience (or well-studied procedure — indistinguishable live, hired either way). Memorize verbs (dev-authors, deploy-executes — two words); understand guards (refusals experienced-or-studied); baseline honestly. Verbs + guards + honesty — operations answers, not command quizzes.

**Performance note** — volunteer deploy economics ("pending-only application: seconds per deploy, bounded; baselining: hours once per brownfield; improvised history repair: archaeology quarters"). Economics with guards (numbers + refusals cited — complete operations maturity in one extra breath). Unvolunteered economics invites "at scale?" probing (reactive answers scoring lower). Volunteer economics; preempt probing.

**Mentor note** — drill as operations Q&A (ten migration scenarios, ninety seconds each — flag-day NOT NULL, unbaselined brownfield, drifted production, failed migration, rename drop+create — verdicts timed, guards cited, procedures named). Speed forces internalization (verbs reflex, guards recalled, procedures sequenced — fashion failing visibly under time pressure). Scenario drills convert command-knowledge to operations judgment (happy-path reciters becoming guard-citing seniors within weeks). Drill scenarios; cite guards; baseline honestly.

## 3. N+1 with includes (spot, fix with strategy, prevent with assertions — three beats)

**Definition** — the closer: *"this Prisma list endpoint is slow — diagnose"* (the performance filter). The graded performance is three beats (spot: count statements per render — "1 + N (verified live pattern: 3 for N=2 — linear confirmed by counting, not profiling); fix: include per path (batched — verified live: 2 statements regardless of N — recount confirms); prevent: assert bounds per list test + v7 `$on("query")` counters (verified live breakage of `$use` — gauges migrated, discipline intact). Count-fix-prevent with *verified numbers* (3 vs 2 measured live — evidence cited, not hypothesized — the strongest N+1 answer format: measured delta, structural fix, enforced prevention).

**What problem it solves** — N+1 questions filter for measurement discipline (candidates guessing ("add an index?" — unmeasured remedy for uncounted problem — tuning what wasn't counted); candidates theorizing ("probably the database" — blame without counting); candidates counting ("1+N statements — N+1 confirmed (measured live pattern: 3 vs 2) — batch to constant (recount confirms) — assert bounds (immunity designed). Interviewers watch *where eyes go first* (logs/counts → measurers (hired); code staring → guessers (junior); EXPLAIN before counting → premature optimizers (misordered). Counting first is the senior tell — measured beats guessed at every level, always.

**Modern guidance** — the five-minute shape (same count-fix-prevent as [Domain 01 §5.1](<../../01 Data Access Foundations and Mental Model/sections/5. Interview QA/5.1. Common interview QA data-access foundations.md>), Prisma-evidenced): (1) *count* (1 min — "statements per render? 1+N (measured live: 3 for N=2 — linear confirmed — v7 `$on(query)` counters (middleware removed — gauges current)"); (2) *fix* (2 min — "include per path (batched — measured live: 2 regardless of N — recount confirms constant); fan-out split per Database Design 04 (multi-list includes multiplying — cause removed, not DISTINCT-trimmed)"); (3) *prevent* (2 min — "assert ≤N per list test (N+1 fails builds); strategies stated per relation (explicit includes — lazy absent structurally); logging on (surprises pre-merge)"). Measured delta cited (3 vs 2 live — evidence, not theory); structural fix verified (recount confirms); immunity designed (assertions + strategies + logs).

```typescript
// v7 $on(query) counters ($use removed — gauges current). Fix: include per path (batched —
// measured live: 2 regardless of N — recount confirms constant). Prevent: assert ≤N per list
// test (N+1 fails builds); strategies stated per relation (explicit includes — lazy absent
```

```typescript
// BAD (whiteboard): the unmeasured remedy — tuning what wasn't counted, asserting nothing.
// "Add an index on order_lines(order_id)?" (Counted? Never — statements uncounted (maybe 2
// already (no N+1 present — index tuning a healthy query); maybe 10k (N+1 present — index
// irrelevant (counts dominate, not lookups)). Remedy without diagnosis (tuning unmeasured
// paths — premature optimization wearing expertise); prevention unmentioned (next list N+1s
// identically — immunity undesigned). Guess, tune, repeat — performance theater (verified
// numbers absent, structural fixes unattempted, assertions never filed).
```

**Common confusion** — *"Prisma prevents N+1 automatically (no need to count)."* Batching covers *declared includes* (verified live — 2 statements batched); hand loops bypass batching (verified live — 3 statements for N=2 — fully manual N+1); v7 middleware removal broke old counters (gauges dead silently post-upgrade — counting absent since migration — N+1 unobserved exactly when observability lapsed). "Automatically" describes declared paths (true — batched); loops uncounted (manual — framework unable); gauges unmigrated (stale — counting absent). Batching declared; loops counted; gauges migrated — all three, always (verified live numbers cited per claim — evidence, not slogans).

**Performance note** — close with counted math (same pattern as every QA leaf, Prisma-evidenced): "1+N → constant via includes (measured 3→2 live — delta cited); multi-list fan-out split (transfer bounded — cause removed); assertions bound future lists (immunity designed — N+1 fails builds)". Counted math proves measurement (numbers from live runs — strongest evidence format); structural fixes prove competence (batching, not tuning); prevention proves seniority (assertions + strategies + logs). Math + structure + immunity — complete N+1 answer with live evidence, expert depth free.

**Mentor note** — drill count-fix-prevent timed (5 minutes, three beats — graded: counted first? (logs/counters before remedies — order enforced); fixed structurally? (batching, not tuning — remedy classified); prevented explicitly? (assertions + strategies + logs — immunity designed)). Order enforced ruthlessly (remedy-before-count fails the round regardless of correctness — discipline over cleverness, always). Timed drills convert guessers to counters (measurement reflex), tuners to batchers (structural remedies), hopefuls to asserters (immunity designed). Count, batch, assert — drilled to reflex, performed under pressure, hired.
