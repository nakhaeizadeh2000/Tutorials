# 4.1. Production checklist mentors insist on

## 1. Pools sized and monitored (max derived per workload — exhaustion alerted, never discovered)

**Definition** — the review's first pass over production data access: pools sized arithmetically per service (max × instances ≤ limit − headroom — [1.1](<../1. Connections and transactions/1.1. Pool sizing per tool.md>) performed); waits finite (acquire timeouts failing fast — backpressure honest); statements bounded (timeouts per role — runaways killed structurally); depth monitored (pg_stat_activity per application_name — saturation visible pre-incident — gauges owned, thresholds firing). Sized + bounded + monitored, or review fails structurally — unexamined pools (defaults governing — exhaustion scheduled); unbounded waits (hangs scheduled); unmonitored depth (saturation discovered via pages — lead time zero).

**What problem it solves** — the unreviewed pool (max defaulted (10 × replicas × services exceeding limits — "too many clients" pages under load (refused connections — cascading retries amplifying — retry storms converting saturation to outage); waits infinite (requests hanging until gateway timeouts (user-facing hangs — backpressure absent); statements unbounded (runaway queries holding connections indefinitely (pool starvation via one statement — service-wide stalls from minimal cause); depth unmonitored (saturation invisible until refused (lead time zero — incidents immediate, context absent). Sized/bounded/monitored pools convert all four (arithmetic bounding totals — timeouts failing fast — gauges warning early). Review minutes per service convert to outage-quarters avoided at the usual rate — highest-ROI minutes in production data-access, permanently true.

**Modern guidance** — the pool review lines (review-enforced — verified live patterns): *max derived* (peak-concurrency arithmetic (max × instances ≤ limit − headroom — headroom reserved (admin/migrations/monitoring never starved); *per-tool configured* (Prisma adapter Pools / TypeORM extras / Drizzle passthrough — options explicit (sizing owned — defaults declined); *waits finite* (acquire timeouts (backpressure honest — hanging requests absent); *statements bounded* (timeouts per role (verified live enforcement — runaways killed structurally); *depth monitored* (stat_activity gauges (saturation visible — exhaustion alerted, never discovered); *sharing decided* (dedicated pools per workload-class where interference measured (OLTP/analytics/migrations isolated — noisy neighbors separated). Missing line → request changes; defaults governing → classify explicitly (defaults sized (rarely) or sized deliberately (always).

**Common confusion** — *"pool review duplicates load testing (same assurance twice)."* Load tests *validate* sizing under simulated traffic (configurations proven — saturation points measured — breaking points known); reviews *establish* sizing (arithmetic per workload — max/waits/timeouts decided — configurations existing to validate). Unreviewed pools load-test blindly (defaults stressed — failures observed without decisions (tuning unguided — remediation improvised); reviewed pools load-test confirmingly (arithmetic validated — breaking points matching predictions — confidence earned). Review establishes (decisions); testing validates (evidence) — both required, review first (untestable defaults unfixable under load — decide, then prove).

**Performance note** — pool-review economics: arithmetic minutes per service (sizing decided — max/waits/timeouts stated); load-test hours per release (configurations validated — breaking points measured); unreviewed equivalents: exhaustion incidents (refused connections — cascading retries — retry storms); hung requests (gateway timeouts — user-facing hangs); runaway-held pools (service-wide stalls — minimal causes, maximal blast). Review minutes + test hours prevent incident quarters — pool discipline ROI exceeding all other production-data-access investments (bounded concurrency performing boringly; unbounded performing dramatically).

**Mentor note** — teach "max × instances ≤ limit − headroom" (juniors computing per service design bounded concurrency on first hearing; uncomputed pools interrogated ("max? instances? limit? headroom?" — four numbers, seconds each, unexamined pools returned). Demonstrate exhaustion live once (max:1 + concurrent slows — verified live S6U4 pattern (queueing visible — timeouts bounding absorption — tangibility converting permanently). Compute arithmetic; bound waits; verify live — pool discipline in three habits, reviewed per service.

## 2. Transactions bounded and chosen (scopes minimal, isolation deliberate, timeouts enforced)

**Definition** — the review's second pass over units-of-work: scopes minimal (invariant-sized transactions — locks brief ([1.2](<../1. Connections and transactions/1.2. Transaction discipline at scale.md>) — conversational/network-spanning transactions rejected (locks held across latencies — contention serializing); isolation deliberate (read-committed default stated; stronger where anomalies threaten (money-moving check-then-act — repeatable/snapshot with retried serialization failures; contention-critical — serializable with expected failures — priced explicitly); timeouts enforced (statement/transaction/lock bounds — runaway work killed structurally — verified live enforcement ([1.1](<../1. Connections and transactions/1.1. Pool sizing per tool.md>)). Scoped/chosen/bounded, or review fails structurally — sprawling scopes, worshipped defaults, absent timeouts (incidents scheduled per class).

**What problem it solves** — the unreviewed transaction (scopes sprawling (conversational units holding locks across HTTP/user latency (contention serializing — throughput = 1/hold-latency — single slow dependency throttling tables); isolation defaulted (check-then-act raced (overdrafts scheduled — anomalies billing as money); lost updates overwriting (counters drifting — correctness evaporating silently); timeouts absent (runaway statements holding connections indefinitely (pool starvation via one query); abandoned transactions leaking locks (vacuum blocked — bloat accumulating). Scoped/chosen/bounded transactions convert all five (locks brief — contention minimal; anomalies priced (isolation chosen — retries designed); runaways killed (timeouts enforced — blast radius contained).

**Modern guidance** — the transaction review lines (review-enforced): *scopes* (invariant-sized (locks brief — network excluded (fetch-then-transact — conversational rejected structurally); *isolation* (read-committed default stated (tolerance stated for drift-tolerant reads); stronger where threatened (money-moving repeatable/snapshot (retries designed); contention-critical serializable (failures expected — priced); *timeouts* (statement/transaction/lock bounded (runaways killed — abandonments reclaimed — waits diagnosed (verified live enforcement patterns); *rollback verified* (throw-to-abort tested (verified live Drizzle pattern — atomicity demonstrated — abort paths tested per transaction shape). Missing line → request changes (unscoped/defaulted/unbounded transactions failing structurally — incidents scheduled per class).

```typescript
// overwriting (counters drifting). Timeouts: absent (runaways holding connections (pool starvation via one query);
// abandonments leaking locks (vacuum blocked — bloat accumulating). Rollback: untested (abort paths hoped).
// Sprawling scopes; worshipped defaults; absent timeouts. Incidents scheduled per class.)
```

**Common confusion** — *"transaction review duplicates code review (same diff twice)."* Code review examines *logic* (correct branches? right entities? sensible flows?); transaction review examines *atomicity properties* (scopes minimal? isolation chosen? timeouts enforced? rollback tested? — properties invisible to logic review (correct-looking conversational transactions passing logic review while holding locks across networks). Different subjects (logic vs atomicity-properties), different failures (wrong branches vs sprawling locks — both critical, neither subsuming). Review logic per diff (correctness); review atomicity per unit-of-work (scopes/isolation/timeouts/rollback — properties). Two lenses, one diff, zero duplication (DRY honored — each review owning its questions exclusively).

**Performance note** — transaction-review economics: scopes minimal (locks brief — contention minimal — throughput maximal); isolation chosen (anomaly protection priced per transaction — throughput/availability arithmetic, never dogma); timeouts enforced (runaways killed — abandonments reclaimed — waits diagnosed); rollback tested (abort verified — partial states impossible structurally). Unreviewed equivalents: sprawling locks (contention serializing — throughput = 1/hold-latency); worshipped defaults (anomalies billing as money — correctness evaporating); absent timeouts (pool starvation — service-wide stalls); untested aborts (partial graphs persisting — inconsistency scheduled). Review minutes per unit-of-work prevent quarters per incident class.

**Mentor note** — teach "name the invariant" per transaction (juniors stating shared business truths design minimal scopes on first hearing; invariant-less transactions interrogated ("which invariant needs atomicity?" — scope unjustified without named invariant). Demonstrate rollback live once (throw mid-transaction — verified abort — atomicity tangible, not theoretical — trust earned by breaking safely). Name invariants; exclude networks; verify rollbacks — transaction discipline in three habits, reviewed per unit-of-work.

## 3. Upgrades rehearsed and ledgers current (majors practiced, magic inventoried, costs re-priced)

**Definition** — the review's closing act over dependency evolution: majors rehearsed (staging upgrades with inventoried breaking changes — gauges compared pre/post — rollback proven (downgrade tested — reversibility demonstrated, never hoped); magic inventoried (defaults/idioms/APIs re-listed per major — relation strategies re-verified (N+1 posture intact); observability idioms current (counters firing post-upgrade — N+1 observable continuously); ledgers re-priced ([Domain 05 §1.2](<../../../05 Comparing and Choosing/sections/1. Selection by workload/1.2. Cost ledgers per tool.md>) updated — generation/strategies/magic costs presently priced (stale prices misleading — old costs guiding new versions — fiction scheduled). Rehearsed/inventoried/re-priced, or review fails structurally — unrehearsed majors (surprises scheduled), uninventoried magic (defaults flipping silently), fossil ledgers (stale prices deciding).

**What problem it solves** — the unexamined upgrade (majors merged on green tests (behavioral coverage passing — defaults flipping unexamined (N+1 appearing post-upgrade — strategies un re-audited); gauges dead (observability idioms removed — counters absent since migration — N+1 unobserved exactly when observability lapsed); ledgers fossil (costs priced at adoption — versions moving — stale prices guiding new versions (mismatches compounding); rollbacks unknown (downgrade untested — stranded versions (forward-fix under fire — incidents compounding). Rehearsed/inventoried/re-priced upgrades convert surprises to findings (staging surfacing breakage calmly — gauges verified continuously — ledgers current presently — rollbacks proven preemptively).

**Modern guidance** — the upgrade review lines (review-enforced): *rehearsed* (staging upgraded (production-shaped data/load — gauges compared pre/post (deltas investigated — regressions fixed pre-production); *magic inventoried* (defaults/idioms/APIs re-listed (relation strategies re-verified (N+1 posture intact); observability idioms current (counters firing — N+1 observable continuously); *ledgers re-priced* (generation/strategies/magic costs presently priced (stale prices misleading — old costs guiding new versions — fiction scheduled); *rollback proven* (downgrade rehearsed (reversibility demonstrated — failed upgrades reverting cleanly — rollback tested, never hoped); *canaried* (service-by-service rollout (blast radius bounded — gauges compared per wave — promotion gated on evidence ([2.2](<../2. **Common confusion** — *"green tests mean safe upgrades (CI passing suffices)."* Tests assert *old* behaviors (written against previous defaults — passing irrelevantly post-change (strategies unexamined (new defaults untested — coverage green on stale assumptions); gauges unwired to new idioms (counters testing removed APIs (passing vacuously — observability dead silently); flags unexamined (new behaviors untested (default paths uncovered — surprises scheduled). "Green" describes old-behavior conformance (regression absent for tested paths); safety requires new-behavior examination (defaults re-listed, gauges re-verified, flags reviewed — audit beyond green). Green necessary (regressions caught); insufficient alone (novelties unexamined). Green + audit; never green-alone (restated from 06/2.1 — permanent value).

**Performance note** — upgrade-review economics: rehearsals cost staging hours (production-shaped environments — representativeness invested); inventories cost review minutes per major (defaults re-listed — surprises preempted); ledger re-pricing costs minutes (costs updated — decisions evidence-backed); rollback rehearsals cost downgrade drills (reversibility proven — failure recovery tested). Unexamined equivalents cost upgrade incidents (N+1 appearing (strategies un re-audited); gauges dead (observability lapsed); stranded versions (rollback unknown — forward-fix under fire). Rehearsal hours prevent incident quarters — upgrade insurance with the best ratio in operations (practice cheap, drama dear).

**Mentor note** — teach "rehearse before production" (juniors staging majors discover breakage calmly on first hearing; production-first upgrades interrogated ("rehearsed where?" — staging demanded per major). Rehearsal culture compounds (teams rehearsing routinely upgrade fearlessly (evidence-backed confidence — majors boring, never dramatic); teams skipping rehearse fearfully (upgrades dreaded — deferred until forced (stale versions accumulating — upgrade debt compounding). Rehearse routinely; upgrade fearlessly; roll back provenly — upgrade operations in three habits, reviewed per major.
