# 3.1. Slow-query response playbook

## 1. Triage by layer (statement counts first — N+1 vs planner vs contention — measured)

**Definition** — the triage order: slow data-access complaints diagnosed layer-by-layer — **counts first** (statements per render observed (N+1? (1+N pattern — loops beside clients — batching declined); **plans second** (EXPLAIN per slow statement (Seq Scan where index serves? (verified live pattern below — unindexed email lookup scanning 50k rows — planner evidence, not suspicion); **contention third** (locks/pool/wait events observed (`pg_stat_activity` wait events — lock queues, pool exhaustion, replica lag — contention measured, never assumed). Counts → plans → contention (ordered by likelihood AND cheapness — counting free (logs), planning cheap (EXPLAIN), contention diagnosis dearest (wait-event forensics — ordered, never shuffled).

**What problem it solves** — the misdiagnosed slowdown trio: *tuned N+1* (indexes added to looped queries (lookups optimized individually — N+1 intact (50k statements, each fast — slowness structural (counts unexamined — tuning what should be batched); *indexed-missing misread as contention* (pools enlarged for scan-bound queries (concurrency added to sequential scans — contention misdiagnosed (scans saturating I/O — pool growth worsening (more scanners, same missing index); *contention tuned as planner issue* (query rewrites for lock-bound workloads (plans perfected — waits persisting (locks unexamined — lock queues growing while planners optimize). Triage order converts misdiagnosis to sequence (counts eliminate N+1 first (structural); plans eliminate missing indexes second (mechanical); contention examined last (forensic — wait events naming locks/pools/replicas precisely).

**Modern guidance** — the triage lines per slowdown (review-enforced — verified live shapes): *count* (statements per render observed (query events/logging — N+1 pattern: 1+N (loops beside clients — batching declined — fix by strategy ([Domain 02 §3.1](<../../02 Prisma Deep Dive/sections/3. Relational queries and N+1.md>) — never by tuning); *plan* (EXPLAIN per slow statement (verified live: Seq Scan on 50k unindexed email lookup → Bitmap Index Scan post-index — planner evidence, 50k rows scanned vs indexed (measured, not hypothesized); *contend* (`pg_stat_activity` wait events (lock:Lock → locker identified (long transactions? missing indexes locking parents? — [1.2](<../1. **Common confusion** — *"slow queries need faster hardware (scale vertically)."* Hardware helps *resourced* bottlenecks (I/O-bound scans on slow disks (SSDs helping — genuinely); CPU-bound aggregations (cores helping — measurably); but N+1 needs batching (50k statements — hardware irrelevant (statements counted, not timed — faster disks serving 50k round trips marginally better — linear intact); missing indexes need structures (scans → seeks — hardware masking O(N) with constants — data growth outrunning hardware predictably); contention needs scope (locks held — faster CPUs waiting equally (waiting isn't computing — hardware idle during lock waits — scaling idle resources changes nothing). Hardware scales resourced bottlenecks; structure fixes unindexed/unbatched/unscoped ones. Triage first (counts/plans/contention — layer identified); hardware second (resourced bottlenecks only).

**Performance note** — triage economics: counting costs log observation (free — events flowing); planning costs EXPLAIN per slow statement (seconds — evidence immediate); contention forensics costs wait-event analysis (minutes — pg_stat_activity queried — locks/pools/lag named); misordered triage costs tuning quarters (indexes on N+1 loops (wasted); pools on scans (worsening); rewrites on locks (irrelevant). Ordered triage performs (counts→plans→contention — cheapest first, dearest last — evidence accumulating per step); shuffled triage bills (expensive remedies for misidentified layers — quarters per misdiagnosis). Order cheaply; diagnose precisely; remedy structurally.

**Mentor note** — teach "counts, plans, contention — in that order" (juniors triaging slowdowns sequentially design correct diagnoses on first hearing; shuffled triage interrogated ("counted? planned? wait-events checked?" — order demanded per slowdown). Demonstrate misdiagnosis costs once (tuned N+1 (indexes on loops — slowness intact — quarters wasted visibly) — order learned permanently (tuning uncounted paths never again). Count first; plan second; contend third — triage order in three habits, reviewed per slowdown.

## 2. Fix at the owning layer (strategy, shape, or index — causes removed where decided, never patched downstream)

**Definition** — the fix-placement rule: remedies applied where causes were decided (N+1 → loading strategy (includes/relations/with: per query — batching decided ([Domain 02 §2.2](<../../02 Prisma Deep Dive/sections/2. Migrations and client/2.2. Client queries and relations.md>), [Domain 03 §3.1](<../../03 TypeORM Deep Dive/sections/3. Loading and performance/3.1. Loading strategies and N+1.md>), [Domain 04 §3.1](<../../04 Drizzle Deep Dive/sections/3. Relational discipline/3.1. Relational queries and N+1.md>) — strategy fixed, not tuned around); missing index → schema/index review (birth-indexing missed — retrofitted via CONCURRENTLY (Databases 02 mechanics — structures fixed, not cached around); contention → scope/timeouts/pools ([1.1](<../1. Connections and transactions/1.1. Pool sizing per tool.md>)/[1.2](<../1. Connections and transactions/1.2. Transaction discipline at scale.md>) — scopes bounded, waits finite — contention designed out, not scaled over). Causes removed at owning layers (decisions revisited); symptoms patched downstream never (caches bandaging N+1 (stale data serving linear queries faster — wrongness accelerating); pools enlarged for scans (concurrency added to sequential work — worsening); hardware scaled for contention (faster waiting — idle resources scaled).

**What problem it solves** — the downstream-patch trio: *cached N+1* (Redis in front of looped queries (linear statements cached (staleness introduced — invalidation complexity arriving (cache coherence tuned — underlying N+1 intact (cache misses still linear — p99 cliffs on cold keys — wrongness accelerated, not fixed); *pooled scans* (max raised for unindexed queries (concurrency added to sequential scans — I/O saturating faster (more scanners, same missing index — worsening disguised as scaling); *hardware-scaled contention* (bigger instances for lock-bound workloads (faster CPUs waiting equally (waiting isn't computing — contention unscoped (lock windows unchanged — throughput identical at higher cost (bills rising, waits persisting). Owning-layer fixes convert patches to cures (strategies batched (N+1 gone — caches unnecessary); indexes added (scans→seeks — pools adequate); scopes bounded (contention designed out — hardware adequate).

**Modern guidance** — the fix lines per diagnosed layer (review-enforced): *strategy layer* (N+1 → includes/relations/with: per query (batching decided — caches declined (bandaging refused — causes removed); *shape layer* (missing indexes → CONCURRENTLY retrofit + birth-indexing ritual updated (structures fixed — pools re-examined post-fix (adequacy rechecked — scaling reverted where patches compensated); *scope layer* (contention → transaction scopes bounded (timeouts finite — lock windows minimal); pools sized (waits finite — backpressure honest); *verify* (counts re-measured post-fix (N+1 gone structurally — recount confirming); plans re-EXPLAINed (seeks verified — evidence, not hope); contention re-observed (wait events quiet — gauges confirming). Missing owning-layer fix → request changes (downstream patches rejected — caches/pools/hardware proposed for structural causes — cure demanded, bandages declined).

```

// N+1 cached (Redis fronting loops — stale data serving linear queries faster (invalidation complexity
// arriving — underlying N+1 intact (cache misses still linear — p99 cliffs on cold keys).
// Scans pooled (max raised — concurrency added to sequential work — I/O saturating faster).
// Contention hardwared (bigger instances — faster CPUs waiting equally (waiting isn't computing).
// Patches downstream; causes upstream intact; bills compounding (cache ops + pool growth + hardware tiers).
```

**Common confusion** — *"caching fixes slow queries (standard practice)."* Caching *hides* latency (stale data serving fast — staleness priced (invalidation complexity — coherence tuned — thundering herds on expiry); causes persist underneath (N+1 unbatched (cache misses linear — p99 cliffs on cold keys); scans unindexed (cache warming scanning fully — warmup bills); contention unscoped (locks blocking cache fills — waits persisting). "Fixes" describes symptom latency (averages improving — p99 cliffs remaining — staleness billing continuously); causes removed describe cures (strategies batched — structures indexed — scopes bounded — latency correct *and* fresh). Cache deliberately (hot, stable, invalidated-cleanly — performance engineering); cache-as-fix never (structural causes intact — wrongness accelerating). Fix causes; cache deliberately.

**Performance note** — fix-placement economics: owning-layer fixes cost strategy/structure/scope changes (minutes-to-hours once — causes removed permanently); downstream patches cost cache ops (invalidation complexity — coherence tuned continuously); pool growth (concurrency added — I/O saturating faster); hardware tiers (bills rising — waits persisting). Cures priced once (causes removed — latency correct *and* fresh); patches priced continuously (ops tuning + staleness billing + tier climbing — wrongness accelerating). Fix owning layers; patch never as cure (caches deliberate, pools sized, hardware matched — adjuncts, never substitutes).

**Mentor note** — teach "fix where decided" (juniors tracing slowdowns to owning layers design cures on first hearing; downstream patches interrogated ("cause removed or bandaged?" — cures demanded per slowdown). Demonstrate patch-failure once (cached N+1 cold-key cliff (p99 spiking on misses — bandage failing visibly — causes intact underneath — tangibility converting permanently). Fix causes; decline bandages; verify cures — slowdown response in three habits, reviewed per incident.

## 3. Prevent by assertion (regression tests on counts and plans — fixed stays fixed structurally)

**Definition** — the prevention contract: fixed slowdowns stay fixed via regression tests (statement-count assertions per list (N+1 failing builds — [Domain 01 §4.1](<../../01 Data Access Foundations and Mental Model/sections/4. Data-access checklist mentors insist on.md>) — verified live patterns S2–S4 (3-vs-2, absent-vs-2, 3-vs-1 — deltas measured, not hypothesized); plan assertions where supported (query-shape tests (EXPLAIN output matching expected node types (Seq Scan failing where Index Scan designed — planner regressions caught (statistics shifts, version upgrades, data growth changing plans — all detected structurally); performance budgets per endpoint (p95 latency bounds in tests (staging-measured — regressions failing builds (budgets enforced — hope declined). Assertions convert fixes to invariants (fixed stays fixed — regressions failing builds, never paging customers).

**What problem it solves** — the refixed slowdown (N+1 fixed, regressing within quarters (new relations unstrategized (includes absent on new traversals — linearity reintroduced silently (tests green on counts? — unasserted (no bounds — regression invisible until scale); indexes dropped in refactors (migrations removing (unreviewed drops — scans returning (unobserved — planner regressions unnoticed); budgets unowned (p95 creeping per deploy (milliseconds monthly — cliff approaching unmeasured (budgets absent — degradation normalized gradually ("a bit slower" quarterly — boiling-frog latencies). Assertions convert recurrence to build failures (counts bounded — regressions red pre-merge; plans asserted — planner shifts caught; budgets enforced — creep failing loudly). Fixed-once stays fixed-forever (assertions guarding — regressions impossible silently).

**Modern guidance** — the prevention lines per fixed slowdown (review-enforced): *counts asserted* (statement bounds per list test (01/4.1 detector — verified live patterns S2–S4 cited — N+1 failing builds (asserted, not hoped); *plans asserted* (EXPLAIN-shape tests where supported (Seq Scan failing where Index designed (planner regressions caught (statistics/version/data shifts — structural detection, not hope); *budgets enforced* (p95 bounds per hot endpoint (staging-measured — regressions failing builds (budgets owned — creep impossible silently); *strategies documented* (include/select rationale recorded (future developers understanding *why* (batching decided — rationale preventing "simplification" regressions (well-meaning cleanups removing includes — rationale defending). **Common confusion** — *"assertion maintenance costs more than refixing (brittle tests)."* Assertion maintenance costs updates per intentional change (bounds revised with strategies (deliberate — minutes); plan assertions updated per schema evolution (reviewed — current); budget recalibration per growth (triggered — priced). Unasserted refixing costs re-diagnosis per recurrence (triage repeated (counts/plans/contention re-examined — hours each); incidents between (linear latencies paging — quarters each); rationale re-derivation (why was this batched? — archaeology per recurrence). Brittle tests (asserting incidental details — implementation-coupled (refactors breaking spuriously) differ from structural assertions (counts/plans/budgets — behavior-guaranteeing — refactors preserving passing, regressions failing). Assert structurally (bounds/plans/budgets — stable across refactors); avoid brittleness (incidental details unasserted).

**Performance note** — prevention economics: assertions cost test milliseconds (counts/plans/budgets per suite — bounded, fast); rationale docs cost lines (batching reasons recorded — future-proofing); unasserted recurrence costs re-triage hours (diagnosis repeated — counts/plans/contention re-examined) + incident quarters (linear latencies paging — p99 cliffs official) + archaeology (rationale re-derived — why batched? — unanswerable post-departure). Milliseconds in tests prevent hours of re-triage + quarters of incidents — assertion ROI exceeding all other slowdown investments (fixed stays fixed — regressions impossible silently).

**Mentor note** — teach "assert the fix" (juniors adding count/plan/budget assertions per remediation design permanent fixes on first hearing; unasserted fixes interrogated ("regression-proof how?" — assertions demanded per fix). Demonstrate recurrence once (unasserted fix regressing within quarters (linearity returning silently — tests green throughout — embarrassment scheduled (fix celebrated, recurrence unnoticed). Assert fixes; document rationale; enforce budgets — prevention complete only with all three (counts + plans + budgets + rationale — invariants guarding, permanently).
