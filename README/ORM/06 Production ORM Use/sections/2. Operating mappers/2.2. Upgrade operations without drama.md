# 2.2. Upgrade operations without drama

## 1. Rehearse majors on staging (breaking changes inventoried pre-adoption — upgrades practiced)

**Definition** — the rehearsal discipline: mapper major upgrades performed on staging first (breaking-changes inventoried from changelogs (defaults/idioms/APIs changed — listed explicitly); staging upgraded (gauges observed — N+1 appearing? magic flipping? counters working? — behavior compared against baseline (pre-upgrade metrics vs post-upgrade (deltas investigated, never hoped); rollback rehearsed alongside (downgrade path tested — reversibility proven pre-production (rollbacks practiced, never theorized). Rehearsed upgrades proceed on evidence (staging green + gauges nominal + rollback proven); unrehearsed upgrades proceed on hope (production as test environment — customers as QA — drama scheduled).

**What problem it solves** — the unrehearsed major (production upgraded directly (changelog skimmed — breaking changes unlisted (relation defaults flipping (N+1 appearing post-upgrade — strategies un re-audited); observability idioms removed (v7 `$use` gone — counters dead silently (gauges absent since migration — N+1 unobserved exactly when observability lapsed); rollback untested (downgrade path unknown (failed upgrades stranded (forward-fix under fire — incidents compounded (broken version + panicked remediation). Rehearsed majors convert surprises to findings (staging surfacing breakage calmly — fixes applied pre-production — rollback proven before needed); unrehearsed majors convert upgrades to incidents (production discovering — customers impacted — remediation improvised).

**Modern guidance** — the rehearsal lines per major upgrade (review-enforced): *inventory* (breaking changes listed from changelog (defaults/idioms/APIs — each assessed (N+1 posture? gauge idioms? magic defaults? — impact priced per change); *stage* (staging upgraded (production-shaped data + load — toy staging invalidating rehearsal (unrepresentative environments rehearsing fiction — staging mirroring production volumes/distributions/concurrency (imperfectly but honestly); *observe* (gauges compared pre/post (N+1 counts, slow-query rates, error budgets — deltas investigated (regressions fixed pre-production — behavior verified, not hoped); *rollback* (downgrade rehearsed (reversibility proven (failed upgrades reverting cleanly — rollback tested, never theorized — downgrade path documented with data-migration caveats (schema-coupled upgrades rolling back data too — rehearsed end-to-end).

```typescript
// GOOD: majors rehearsed — inventoried, staged, observed, rollback-proven (excerpt).
// Inventory: v7→8 breaking listed (middleware gone (gauges migrated ✓); cascade defaults changed
// (reviewed — surprising entries disabled ✓); adapter APIs shifted (call sites updated ✓).
// Stage: staging upgraded (production-shaped data/load — representative rehearsal ✓).
// Observe: gauges compared (N+1 counts nominal ✓ — slow rates nominal ✓ — errors nominal ✓).
// Rollback: downgrade rehearsed (reversibility proven — rollback documented with caveats ✓).
// Verdict: proceed to canary (evidence complete — rehearsal passing, rollback proven).
```

```typescript
// BAD: majors unrehearsed — changelog skimmed, staging skipped, rollback unknown (real shapes).
// Inventory: skimmed ("looks fine" — breaking changes unlisted (relation defaults flipping (N+1
// appearing post-upgrade — strategies un re-audited); observability idioms removed (counters dead
// silently — gauges absent since migration). Stage: skipped ("staging differs anyway" — rehearsal
// value dismissed with environment imperfections — imperfect rehearsal beating no rehearsal infinitely).
// Rollback: unknown (downgrade path untested — failed upgrades stranded (forward-fix under fire —
// incidents compounding (broken version + panicked remediation). Unrehearsed majors; scheduled drama.)
```

**Common confusion** — *"staging never matches production (rehearsals worthless)."* Imperfect rehearsals catch most breakage (default flips, gauge deaths, API shifts — environment-independent failures (code-level — staging-faithful regardless of data scale); load-shaped issues escape staging (contention/transfer/volume behaviors — production-only realities — canaries catching (next promise — staged rollout with production traffic (rehearsal + canary layered, neither alone sufficient). "Never matches" dismisses partial coverage (imperfect rehearsals catching code-level breakage — majority of upgrade failures); canaries cover load-shaped remainder (production traffic fractions — reality Completing coverage). Rehearse imperfectly (code-level); canary realistically (load-shaped) — layered, never either-alone.

**Performance note** — rehearsal economics: inventory costs changelog hours (breaking sections read fully — surprises preempted); staging costs environment hours (production-shaped data/load — representativeness invested); observation costs comparison minutes (gauges pre/post — deltas investigated); rollback rehearsal costs downgrade drills (reversibility proven — failure recovery tested). Unrehearsed equivalents cost upgrade incidents (N+1 appearing (strategies un re-audited); gauges dead (observability lapsed); stranded versions (rollback unknown — forward-fix under fire). Rehearsal hours prevent incident quarters — upgrade insurance with the best ratio in operations (practice cheap, drama dear).

**Mentor note** — teach "rehearse before production" (juniors staging majors discover breakage calmly on first hearing; production-first upgrades interrogated ("rehearsed where?" — staging demanded per major). Rehearsal culture compounds (teams rehearsing routinely upgrade fearlessly (evidence-backed confidence — majors boring, never dramatic); teams skipping rehearse fearfully (upgrades dreaded — deferred until forced (stale versions accumulating — upgrade debt compounding). Rehearse routinely; upgrade fearlessly; roll back provenly — upgrade operations in three habits, reviewed per major.

## 2. Canary tool upgrades (one service first — blast radius bounded — rollback rehearsed alongside)

**Definition** — canary discipline: mapper upgrades rolling service-by-service (lowest-risk service first (internal tools, low-traffic paths — blast radius minimal (customers few, rollback cheap); gauges compared canary-vs-stable (N+1 counts, slow rates, error budgets — deltas investigated per canary (regression halting rollout — promotion gated on evidence, never schedule); rollback rehearsed alongside (downgrade path proven pre-canary — failed canaries reverting cleanly (reversibility tested, never hoped); full rollout following green canaries (baking periods observed — hours-to-days per wave (patience priced — haste declining). Blast radius bounded per wave (one service — failures contained); rollout gated per evidence (gauges green — promotion earned).

**What problem it solves** — the flag-day upgrade (all services upgraded simultaneously (blast radius total (failures fleet-wide — N+1 appearing everywhere at once (strategies un re-audited globally — gauges dead across services (observability lapsed fleet-wide); rollback impossible (downgrade path untested at fleet scale — stranded versions fleet-wide (forward-fix under fire across all services — incidents compounding geometrically); baking absent (no observation window — failures discovered by customers weeks later (slow-burn regressions — undetected without canary comparison (stable baseline absent — deltas unmeasurable). Canary rollout converts total risk to bounded waves (one service failing safely (rollback proven — blast contained); green canaries promoting (evidence-gated — schedule serving safety, never rushing it).

**Modern guidance** — the canary lines per upgrade (review-enforced): *order* (lowest-risk first (internal tools → low-traffic services → core paths (blast radius ascending — failures contained early (cheap lessons); core protected last (revenue paths upgrading on proven evidence — risk aversion where stakes demand); *compare* (canary vs stable gauges (N+1 counts, slow rates, errors — deltas investigated per wave (regression halting rollout — promotion gated on evidence (green canaries promoting, yellow holding, red reverting); *rollback* (downgrade rehearsed pre-canary (reversibility proven — failed canaries reverting cleanly (rollback tested, never hoped — downgrade documented with data-migration caveats); *bake* (observation windows per wave (hours-to-days — slow-burn regressions surfacing (patience priced — haste declining (schedule serving safety).

```typescript
// GOOD: canary rollout — ordered, compared, rollback-ready, baked (excerpt).
// Order: internal-admin first (blast minimal — failures cheap, lessons full).
// Compare: canary vs stable gauges (N+1 counts nominal ✓ — slow rates nominal ✓ — errors nominal ✓).
// Rollback: downgrade rehearsed (reversibility proven — failed canaries reverting cleanly ✓).
// Bake: 48h per wave (slow-burn regressions surfacing — patience priced ✓).
// Verdict: promote on evidence (green canaries — schedule serving safety, never rushing it).
```

```typescript
// BAD: flag-day upgrades — total blast radius, ungated promotion, unknown rollback (real shapes).
// Order: all services simultaneously (blast total — failures fleet-wide (N+1 appearing everywhere —
// strategies un re-audited globally; gauges dead across services — observability lapsed fleet-wide).
// Compare: none (stable baseline absent — deltas unmeasurable — regressions invisible until customers).
// Rollback: unknown (downgrade untested at fleet scale — stranded versions fleet-wide (forward-fix under
// fire across all services — incidents compounding geometrically). Bake: absent (slow-burn regressions
// surfacing weeks later — undetected without canary comparison). Flag-day drama, itemized.)
```

**Common confusion** — *"canaries slow down upgrades (velocity taxed)."* Canaries *pace* upgrades (waves with baking — schedule predictable (48h per wave — planning reliable); flag-days *risk* velocity (failures fleet-wide — rollbacks chaotic (unrehearsed downgrades failing — forward-fixes under fire (velocity zeroed during incidents — quarters lost to drama). "Slow" describes scheduled pacing (bounded, predictable — business planning around known windows); flag-days gamble velocity (fast when lucky (unexamined upgrades succeeding — luck, not process); zeroed when unlucky (fleet incidents — quarters lost). Pace predictably (canaries — schedule honored); gamble never (flag-days — luck exhausted eventually). Baking is velocity insurance, not tax.

**Performance note** — canary economics: ordered waves cost schedule days (baking per wave — patience priced — slow-burn regressions surfacing); comparisons cost gauge attention (canary-vs-stable deltas — investigated per wave); rollback rehearsals cost downgrade drills (reversibility proven — failure recovery tested); flag-day equivalents cost fleet incidents (N+1 everywhere — strategies un re-audited globally; gauges dead fleet-wide; stranded versions — forward-fix under fire geometrically). Scheduled days prevent chaotic quarters — canary pacing ROI exceeding all other upgrade investments (bounded waves, evidenced promotion, proven rollback).

**Mentor note** — teach "blast radius first" (juniors ordering upgrades by risk design bounded rollouts on first hearing; flag-day plans interrogated ("blast radius?" — bounded waves demanded per upgrade). Bake patience into schedules (48h windows non-negotiable (slow-burn regressions needing time — haste declining explicitly — schedule serving safety). Celebrate uneventful upgrades (boring canaries praised — "green across waves, promoted on evidence" — culture valuing boredom over heroics (heroics signaling process failure — boredom signaling process success). Bound blasts; bake patiently; celebrate boring.

## 3. Ledger re-priced per major (cost lines updated — strategies re-audited, magic re-inventoried)

**Definition** — the re-pricing discipline: cost ledgers ([Domain 05 §1.2](<../../05 Comparing and Choosing/sections/1. Selection by workload/1.2. Cost ledgers per tool.md>)) updated per mapper major (generation costs re-measured (build seconds changing (codegen performance shifting — tax re-budgeted); strategies re-audited (relation defaults flipping (N+1 posture changing — batching re-verified); magic re-inventoried (defaults/idioms/APIs changed (surprises listed — ledger current — stale prices misleading (old costs guiding new versions — fiction scheduled). Re-pricing ritual per major (ledger diffed version-to-version — deltas priced (adopt/skip/defer decided with numbers — upgrades rehearsed per new prices, never hoped per old ones).

**What problem it solves** — the stale-ledger trio: *generation drift* (build costs changing per major (codegen slower/faster — taxes un re-budgeted (CI minutes creeping — budgets blown silently); *strategy drift* (relation defaults flipping (N+1 posture changing — batching un re-verified (strategies stale — linearities scheduled); *magic drift* (defaults/idioms/APIs changing (middleware removed (gauges dead — v7 lesson unapplied to v8 (surprises repeating per major — history unlearned). Stale ledgers misguide (old prices deciding new versions — fiction scheduled (decisions optimized for previous majors — mismatches compounding per upgrade). Re-priced ledgers decide presently (costs current — strategies verified — magic inventoried — versions operated, never assumed).

**Modern guidance** — the re-pricing lines per major (review-enforced): *generation re-measured* (build seconds per schema change (codegen performance shifting — tax re-budgeted (CI minutes updated — budgets current); *strategies re-audited* (relation defaults flipping? (N+1 posture changing — batching re-verified (strategies current — linearities preempted); *magic re-inventoried* (defaults/idioms/APIs changed (surprises listed — ledger current (v7→8 watch active per track index — breaking inventoried pre-adoption); *decisions re-derived* (adopt/skip/defer per major (numbers current — upgrades rehearsed per new prices (old prices retired — fiction declined). Missing re-price → request changes (stale ledgers misleading structurally — costs fossilized, surprises scheduled).

// GOOD: ledger re-priced per major — generation, strategies, magic current (excerpt).
// Generation: 7→8 build delta measured (+2s/build — tax re-budgeted ✓).
// Strategies: relation defaults unchanged (N+1 posture intact — batching re-verified ✓).
// Magic: middleware-removal class checked (v8 idioms current — gauges verified live ✓).

```

// BAD: the fossil ledger — costs priced once, versions moving, decisions stale (real shapes).
// Generation: priced at adoption (v6 numbers guiding v8 (build tax tripled unnoticed — CI minutes

// inventoried at adoption (middleware removed (gauges dead — v7 lesson unapplied to v8 (surprises
// repeating per major — history unlearned). Decisions: renewed never (stale prices deciding new
// versions — fiction scheduled — mismatches compounding). Fossilized ledger; stale decisions.)
```

**Common confusion** — *"re-pricing every major is overhead (majors are compatible-ish)."* "Compatible-ish" hides breaking subtleties (defaults flipping (N+1 posture changing — silently; observability idioms removed (gauges dying — silently; performance characteristics shifting (build/generation costs moving — silently). "Compatible" describes APIs (code compiling — surface stable); costs live beneath APIs (strategies/magic/performance shifting — majors moving what minors promise (stability theater — semver majors *declaring* breakage openly — ignored declarations billing quarterly). Re-price per major (breaking declared — pricing due); skip per minor (usually — vigilance maintained, idioms re-verified where deprecations appear). Majors priced; minors watched.

**Performance note** — re-pricing economics: ledger updates cost review minutes per major (generation measured, strategies audited, magic inventoried — bounded, calm); fossil ledgers cost surprise quarters (build-tax creep (CI minutes compounding — budgets blown); N+1 resurgence (strategies stale — linearities scheduled); magic incidents (defaults flipped — surprises paging). Minutes per major prevent quarters per incident — re-pricing ROI exceeding all other upgrade investments (costs current — decisions evidence-backed — surprises extinct). Price presently; fossilize never.

**Mentor note** — teach "re-price per major" (juniors updating ledgers version-to-version design currency-maintained selections on first hearing; fossil ledgers interrogated ("priced for which version?" — currency demanded per ledger). Version-watch rituals (track index + per-service ledgers reviewed per major release — breaking inventoried, strategies re-audited, magic re-listed — rhythm protected like production uptime). Price presently; watch versions; revise triggeredly — ledger currency in three habits, reviewed per major.
