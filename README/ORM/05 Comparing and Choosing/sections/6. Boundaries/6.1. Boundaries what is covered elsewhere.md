## 3. Production lives in Domains 06–07 (operating the chosen tools — next sessions, not this one)

**Definition** — forward boundary: Domains 06 (Production ORM Use — unbuilt) and 07 (Production Mastery and Interview Synthesis — unbuilt) own operating selected tools (pool sizing per tool in production (max connections vs database limits vs workload concurrency — sized, monitored, alerted); transaction discipline at scale (isolation choices, long-transaction behavior, deadlock handling — priced per workload); observability per mapper (query logging in production (sampled — slow-query alerting — statement budgets enforced continuously); upgrade operations (major migrations executed (rehearsals, canaries, rollbacks — releases boring, never dramatic). Selection decides tools (this domain — verdicts with triggers); production operates them (next sessions — gauges with owners, runbooks with rehearsals). Decide now; operate next — sequence, not substitution.

**What problem it solves** — the operations-blind selection (tools chosen without operability (pool defaults unexamined (exhaustion scheduled — max connections unpriced vs database limits); transaction defaults unconsidered (isolation unchosen — anomalies scheduled (lost updates, phantom reads — levels defaulted, never decided); observability unplanned (logging off by default — surprises scheduled (slow queries invisible — p99 cliffs official); upgrade paths unexamined (majors hoped compatible — breaking changes arriving as surprises). Operations-blind verdicts optimize adoption (DX demos — smooth trials) while scheduling operations debt (pools exhausting, anomalies surfacing, surprises paging, upgrades breaking — quarters each). Operability-aware selection (pools/transactions/observability/upgrades considered per verdict — priced, trigger-dated) decides completely (adoption + operations, both owned).

**Modern guidance** — the forward map (selection now, operations next — textual, no dead links by design): pool sizing per tool → Domain 06 (max connections vs limits vs concurrency — sized per workload — exhaustion designed out); transaction discipline → Domain 06 (isolation levels chosen — anomalies priced — long transactions bounded); production observability → Domain 06 (sampled logging — slow-query alerts — statement budgets enforced continuously); major upgrades → Domain 06 (rehearsals, canaries, rollbacks — releases boring); interview synthesis → Domain 07 (selection narratives performed — positions/matches/triggers under questioning).
