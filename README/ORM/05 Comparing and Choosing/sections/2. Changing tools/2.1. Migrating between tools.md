# 2.1. Migrating between tools

## 1. Triggers fire first (misfit measured — migrate on evidence, never fashion)

**Definition** — migration triggers: measured misfits that justify tool changes — ceremony without graphs (mapper build-times/magic-surface billed quarterly for flat workloads — quantified (build seconds × schema churn; magic inventory hours; upgrade ledgers per major); toil without control (hand-mapping graphs — assembly hours per feature; N+1 incidents per quarter — unbatched traversals billed in latency); coupling without simplicity (side-effect smuggling — untestable suites (minutes per TDD cycle); second-store blocking (sharding/multi-store refactors requiring flavor migration). Triggers measured (numbers with sources — build logs, incident counts, suite timings — evidence, not vibes); migration scheduled on trigger firing (deliberate, planned, reversible-checked — never on fashion cycles (conference-driven rewrites — toil without misfit).

**What problem it solves** — the two migration failures: *fashion migration* (tool switches per hype (Prisma→Drizzle→X — rewrites without misfit (working tools replaced — migration quarters billed, benefits zero (same workloads, new syntax — novelty wearing strategy); team retraining per fashion (fluency reset — velocity cratering during relearning — novelty taxed in quarters); and *sunk-cost stagnation* (misfit tools retained (ceremony/toil/coupling billed quarterly — triggers firing unacknowledged (evidence unexamined — fashion-in-reverse (incumbent comfort as dogma — "we've always used X" blocking measured migration). Triggers measured convert both (fashion declined (no trigger — no migration, regardless of hype); stagnation confronted (trigger firing — migrate deliberately, regardless of comfort).

**Modern guidance** — the trigger format per migration proposal (review-enforced): *misfit measured* (ceremony/toil/coupling quantified with sources (build logs, incident postmortems, suite timings — numbers, not adjectives ("slow" unmeasured is vibe — "12 build-minutes/day on mapper generation for flat shapes" is evidence); *target justified* (candidate tool placed per workload ([1.1](<../1. Selection by workload/1.1. Workload-matched selection.md>) performed on current shapes — jurisdiction match, not fashion (positions mapped — triggers dated); *cost estimated* (migration quarters (rewrite + retrain + dual-run — bounded, scheduled) vs misfit quarters recurring (ceremony/toil/coupling billed per quarter indefinitely — payback computed (migration cost ÷ quarterly misfit = break-even horizon — horizons under a year migrating, over two years monitoring (triggers re-checked, patience priced). Missing numbers → request changes (fashion/habit both rejected — evidence or stasis).

```typescript
// GOOD: the migration trigger — measured misfit, justified target, estimated cost (excerpt).
// Misfit: Prisma generation 12 build-min/day (flat shapes — ceremony without graphs — measured CI logs).
// Target: Drizzle (dynamics earn builders — flat+dynamic workload matched — 1.1 performed).
// Cost: 3 engineer-weeks (rewrite + retrain + dual-run) vs 2 build-hours/day recurring
// (break-even 7 weeks — migrate deliberately). Trigger fired on evidence; fashion absent.
// Verdict: migrate (measured, justified, estimated — evidence over comfort and hype alike).
```

```typescript
// BAD: the unmeasured migration — fashion forward, comfort backward (real failure shapes).
// "Let's move to X (conference demo impressive — new syntax, same flat workload — rewrites
// without misfit (quarters billed, benefits zero — novelty wearing strategy; retraining cratering
// velocity (fluency reset — quarters taxed). Or: "stay on Y forever" (ceremony/toil/coupling billed
// quarterly — triggers firing unacknowledged (evidence unexamined — comfort dogma ("always used X"
// blocking measured migration). Fashion migrating; comfort stagnating; evidence unemployed.)
```

**Common confusion** — *"migrating tools means admitting the first choice was wrong."* First choices made with then-evidence (workloads then-shaped — flat-then-graphs-now (domains growing graphs the way junctions grow attributes — evolution, not error); triggers recorded then (graphs past 2 relations → re-evaluate — foresight, not failure). "Wrong" describes unexamined choices (fashion/habit adoptions — misfits from birth — genuinely wrong, learnable); evolved choices describe growth (workloads shifting — triggers firing as designed — migration executing foresight, not confessing error). Honor past evidence (decisions correct then); follow current triggers (migration correct now). Growth migrates; errors educate — both honored, never shamed.

**Performance note** — trigger economics: measured misfits cost evidence-gathering (build logs, incident counts, suite timings — automated mostly — numbers flowing); fashion migrations cost rewrite quarters + retraining craters (velocity zeroed during relearning — quarters billed, benefits zero); stagnation costs misfit quarters recurring (ceremony/toil/coupling billed per quarter indefinitely — compounding). Evidence cheap (logs exist); fashion dear (rewrites without misfit); stagnation dearest (misfit compounding forever). Measure triggers; migrate deliberately; stagnate never.

**Mentor note** — teach "evidence or stasis" (juniors proposing migrations with measured misfits design deliberate changes on first hearing; fashion/habit proposals interrogated ("numbers?" — evidence demanded per proposal). Trigger reviews quarterly (misfit metrics re-examined — firing acknowledged, dormant monitored — migration scheduled on evidence, never on conference seasons). Evidence demanded; fashion declined; comfort confronted — migration judgment in three habits, reviewed per proposal.

## 2. Strangler pattern applies (new features on new tool, old paths migrated per touch)

**Definition** — the strangler migration (Fowler's pattern, data-access edition): new features built on the target tool (greenfield code correct from birth — new idioms, new tests, new confidence); old paths migrated per touch (modified features rewritten to target (boy-scout rule applied to layers — touched code converted, untouched left running); both tools live during transition (dual dependencies, dual configs — transition period bounded (deadline dated — strangler complete by quarter X, never indefinite); contracts stable throughout (repository seams abstracting tools ([Domain 01 §2.2](<../../../01 Data Access Foundations and Mental Model/sections/2. Mapping patterns/2.2. The repository seam.md>) — consumers unaffected during migration (seams absorbing tool change — policy green throughout).

**What problem it solves** — the big-bang rewrite (all features migrated at once (flag-day tool switch — months of parallel branches (diverging — merge conflicts compounding; untested scope (everything changing — verification impossible — big-bang risk concentrating; rollback impossible (no partial state to return to — all-or-nothing cutover — failure catastrophic, not recoverable); and the permanent dual-run (both tools living indefinitely ("gradual" without deadline — dependencies doubled permanently (upgrades × 2, magic × 2, onboarding × 2 — transition costs fossilized as architecture). Strangler converts big-bang to incremental (touched paths migrated — working software throughout — rollback per path (revert touched feature, not whole system); deadline converts dual-run to transition (bounded coexistence — dual costs temporary, completion dated).

**Modern guidance** — the strangler lines per migration (review-enforced): *new-on-target* (greenfield features target-only from decision date (old tool frozen for new code — linted where feasible (new imports of old tool failing review — transition direction enforced); *touch-migrates* (modified features converted (boy-scout layers — touched paths rewritten to target with tests — scope bounded per PR (migration + feature change reviewed separately (mixed diffs rejected — migration PRs pure, feature PRs following); *seams stable* (repository contracts unchanged throughout (consumers green continuously — tool change invisible to policy — seams absorbing migration (seam value proven in transition — interfaces earning their keep exactly when most needed); *deadline dated* (completion quarter committed (dual-run bounded — dependencies doubled temporarily, never permanently — deadline missed → escalated (transition stalling — attention, not acceptance).

```typescript
// GOOD: strangler executed — new-on-target, touch-migrated, seams stable, deadline dated (excerpt).
// Decision Q1: Drizzle target (trigger fired — measured misfit — evidence filed).
// New features (Q1+): Drizzle only (old-tool imports failing review — direction enforced).
// Touched paths: converted per touch (migration PRs pure — feature changes following separately).
// Seams: repository contracts unchanged (consumers green continuously — tool invisible to policy).
// Deadline: Q3 complete (dual-run bounded — dependencies doubled temporarily).
// Verdict: strangling (incremental, reversible per path, deadline-driven).
```

```typescript
// BAD: big-bang or permanent-dual — all-at-once risk or indefinite duality (real shapes).
// Big-bang: feature-freeze + all-hands rewrite quarter (branches diverging for months —
// merge conflicts compounding; untested scope (everything changing — verification impossible);
// rollback impossible (no partial state — all-or-nothing cutover — failure catastrophic).
// Permanent-dual: "gradual" without deadline (both tools living indefinitely — upgrades × 2,
// magic × 2, onboarding × 2 — transition costs fossilized as architecture — dual-run forever).
// Bang risking; duality fossilizing. Strangle incrementally; deadline firmly.)
```

**Common confusion** — *"strangler doubles work (migrate everything at once, faster)."* Strangler *schedules* work (touched paths per PR — migration cost amortized across feature work (quarters, calmly); big-bang *concentrates* it (dedicated rewrite quarter — velocity zeroed (features frozen — business waiting); risk concentrated identically (all-or-nothing cutover — failure catastrophic). "Faster" confuses calendar compression (one quarter blocked — business stalled) with efficiency (strangler total hours comparable, business unblocked throughout — velocity sustained during migration). Schedule work (strangler — business flowing); concentrate risk never (big-bang — velocity zeroed, failure total). Amortize calmly; cut over reversibly per path.

**Performance note** — strangler economics: incremental migration costs per-touched-path hours (amortized across feature quarters — business unblocked — velocity sustained); big-bang costs blocked quarter + cutover risk (velocity zeroed for months + all-or-nothing failure mode — catastrophic pricing); permanent-dual costs doubled dependencies forever (upgrades × 2 (majors touching both tools — magic × 2 inventoried; onboarding × 2 (idioms doubled — comprehension halved). Deadline bounded (dual costs temporary — completion dated); strangler amortized (migration per touch — business flowing). Incremental + deadline beats bang + duality on every axis (risk, velocity, cost).

**Mentor note** — teach "strangle, never bang" (juniors planning tool migrations incrementally design reversible changes on first hearing; big-bang plans interrogated ("rollback path?" — all-or-nothing cutovers have none — reversibility demanded per migration). Deadline discipline (dual-run bounded — completion dated, slippage escalated — transitions finishing, never fossilizing). Strangle incrementally (reversible per path); deadline firmly (dual costs temporary); celebrate completion (migration closed — old tool removed — dependencies halved — team unblocked fully). Reversible paths; firm deadlines; celebrated completions.

## 3. Schemas migrate once (single DDL history continuous — tools project it differently, never fork it)

**Definition** — the schema-continuity rule: one DDL history across tool migrations (migrations continuous — same tables evolving (tool switch changing *access code*, never *schema lineage — new tool adopting existing migrations history (baselined honestly where formats differ (Prisma history ↔ TypeORM history ↔ kit journal — formats incompatible, lineage continuous (baseline new tooling on current reality — history starting true, normal flow after); DDL forked never (parallel migration histories per tool — drift institutionalized (which history is true? — unanswerable post-fork — environments diverging per tool — fiction squared). Tools project one schema (clients mapping shared tables — projections differing, lineage single); tools never fork it (histories unified — truth singular, always).

**What problem it solves** — the forked-history duo: *parallel migrations* (new tool with fresh migration history from empty (baseline unrecorded — history claiming greenfield on brownfield reality — reproducibility void (fresh environments built from fiction — staging ≠ production structurally); old history abandoned (evolution record severed — past decisions archaeologized (why is this column here? — unanswerable post-fork); and *schema rewrites* ("while migrating tools, redesign tables" — two changes coupled (tool + shape — failures unattributable (tool bug or shape bug? — debugging doubled); rollback impossible (coupled changes unseparable — reverting either reverts both — all-or-nothing squared). Continuity converts both (baselined adoption (history honest from day one); shapes frozen during tool migration (one change at a time — tool first, shapes later (sequenced, never coupled).

**Modern guidance** — the continuity lines per tool migration (review-enforced): *baseline honestly* (new tooling baselined on current reality (diff current schema vs new-tool initial state — match verified, not assumed — history starting true (normal flow after — first commit honest); *freeze shapes* (no DDL redesign during tool migration (tool change only — entities/columns/constraints identical pre/post (diffed to prove — shape changes scheduled after (sequenced, never coupled); *retire old history* (old migration tooling decommissioned post-cutover (single history surviving — fork window bounded (dual histories during strangler — reads converging, writes single-sourced — fork closed at completion (old history archived read-only, new history authoritative). Missing baseline → request changes (fiction institutionalized); coupled redesign → sequence (tool first, shapes later).

```sql
-- GOOD: schema continuity — baselined adoption, frozen shapes, retired forks (excerpt).
-- Baseline: kit history baselined on Prisma-managed reality (diff verified match — history true).
-- Freeze: zero DDL changes during tool migration (tool only — entities identical pre/post (diffed)).
-- Retire: Prisma migrate decommissioned post-cutover (single kit history surviving — fork closed).
-- Shapes later: redesign scheduled post-migration (sequenced — tool first, shapes second).
-- Verdict: continuous history (truth singular — reproducibility intact throughout).
```

```sql
-- BAD: forked history + coupled redesign — truth plural, failures unattributable (real shapes).
-- Fresh kit history from empty (baseline unrecorded — history claiming greenfield on brownfield
-- (reproducibility void — fresh environments fiction-built). Old Prisma history abandoned
-- (evolution record severed — past decisions archaeologized). Redesign coupled ("new tool, new
-- schema" — tool + shape changing together (failures unattributable — tool bug or shape bug?
-- debugging doubled; rollback impossible (coupled changes unseparable — all-or-nothing squared).
-- Forked truth; coupled changes. Continuity declined; archaeology scheduled.)
```

**Common confusion** — *"new tools deserve clean schemas (greenfield migrations)."* Clean schemas deserve *separate* migrations (redesign scheduled post-tool-migration — sequenced improvements, each reviewable); coupled greenfielding confuses tool change with shape change (failures unattributable — successes uncreditable (which change helped? — unknowable post-coupling); rollbacks impossible (reverting tool reverts shapes — all-or-nothing squared). "Clean" describes end-state desirability (tidy schemas wanted); sequencing describes safe arrival (tool first (reversible per strangler), shapes second (reviewed per change) — arrival safe, end-state identical). Sequence changes; share baselines; fork never.

**Performance note** — continuity economics: baselining costs hours once (inventory + resolve — history true forever after); forked histories cost archaeology quarters (divergence untangling — statement-by-statement forensics across tool histories — unanswerable questions billed hourly); coupled redesigns cost unattributable incidents (tool-vs-shape ambiguity — debugging doubled — rollbacks impossible (all-or-nothing squared). Honest baselines price in hours once; fiction prices in quarters recurring. Baseline once; sequence changes; fork never.

**Mentor note** — teach "one history" (juniors baselining new tooling on current reality internalize ledger integrity permanently — history true, tools interchangeable (projections differing, lineage single); forked histories interrogated ("which is true?" — unanswerable post-fork — singularity demanded). Ledger integrity transfers across tracks (Database Design 05/2.1's honesty procedures — same discipline, tool-migration edition). Baseline honestly; sequence changes; retire forks — history integrity in three habits, reviewed per tool migration.
