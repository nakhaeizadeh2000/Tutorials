# 2.2. Polyglot persistence honestly

## 1. Two tools maximum per service (cognitive budget bounded — third tool justified architecturally)

**Definition** — the polyglot budget: at most two data-access tools per service (primary + justified secondary — e.g., Prisma for graphs + Drizzle for dynamic reports; TypeORM for classes + raw for analytics) — third tools requiring architecture-level justification (written ADR with workload evidence — not developer preference (familiarity ≠ jurisdiction — comfort unexamined). Cognitive budget bounded (idioms per service reviewable — onboarding learning two surfaces maximum — upgrades touching at most two ledgers); exceptions architecturally justified (third tool with measured need — review board, not PR author — gravity appropriate to permanence).

**What problem it solves** — the tool-collector service (Prisma + TypeORM + Drizzle + raw + Kysely-experiment — five access idioms in one codebase (readers context-switching per file — comprehension taxed daily); upgrades touching five ledgers (magic × 5 inventoried — majors re-priced quintuply — version churn multiplying); onboarding learning five surfaces (weeks before productive data-access — hiring velocity taxed per head); debugging spanning idioms (N+1 in three syntaxes — detectors tripled, all unowned). Bounded polyglotry converts collector chaos to deliberate duality (two tools maximum — each justified per workload ([1.1](<../1. Selection by workload/1.1. Workload-matched selection.md>)) — boundaries documented (next promise) — upgrades bounded (two ledgers, not five).

**Modern guidance** — the budget lines per service (review-enforced): *primary declared* (one tool owning most access — team default per ADR-001 ([Domain 01 §4.1](<../../../01 Data Access Foundations and Mental Model/sections/4. Mentor checklist/4.1. Data-access checklist mentors insist on.md>)) — default reviewed yearly, exceptions filed); *secondary justified* (one additional tool with workload evidence (dynamics unserved by mappers? analytics unmappable? — measured need, not preference — exception ADR with trigger (secondary removable when workload shifts — exceptions expiring, never fossilizing); *tertiary refused* (third tool failing review structurally — justification escalated to architecture review (evidence + cost + alternatives considered — bar appropriately high (third idiom permanent — cognitive budget exceeded otherwise); *inventory maintained* (tool count per service dashboarded — collector drift visible (counts creeping — audits scheduled quarterly — budgets enforced, never hoped).

```typescript
// GOOD: budgeted polyglotry — primary + justified secondary, boundaries documented (excerpt).
// Primary: Prisma (graphs — team default ADR-001 — most access).
// Secondary: Drizzle (dynamic admin reports — measured need (composable filters unserved by finds) —
// exception ADR-014 filed (trigger: reports static-ified → secondary removed — expiring, never fossilizing).
// Tertiary: refused (Kysely experiment declined — secondary serving (dynamics covered) — bar held).
// Inventory: 2 tools (dashboarded — audits quarterly — budgets enforced).
```

```typescript
// BAD: the collector service — idioms per author, budgets absent (real failure shapes).
// Prisma (graphs) + TypeORM (legacy entities, unmigrated — comfort retained) + Drizzle (one admin
// screen — dynamics invoked for static finds) + raw strings ("quick queries" — untyped, unlogged) +
// Kysely spike (merged accidentally — experiment fossilized). Five idioms (readers context-switching
// per file — comprehension taxed daily); upgrades × 5 (magic quintupled — majors re-priced fivefold);
// onboarding × 5 surfaces (weeks before productive data-access). Collected per author; budgeted never.
```

**Common confusion** — *"polyglot means using the best tool per query (maximal matching)."* Maximal matching optimizes per query (best idiom each time — local optima); budgeted duality optimizes per service (cognitive load bounded — comprehension, upgrades, onboarding priced globally). "Best per query" fragments codebases (five idioms — each query ideal, codebase unmaintainable — local optima composing to global worst); "fitting per service" bounds fragmentation (two tools maximum — each justified — global comprehension preserved). Optimize services (bounded variety — comprehensible), not queries (maximal matching — fragmented). Jurisdiction per workload-center, not per statement.

**Performance note** — budget economics: bounded tools cost onboarding surfaces (two idioms learned — weeks, once) + upgrade ledgers (two magic inventories per major — bounded); collector services cost comprehension daily (context-switching per file — velocity taxed per developer per day) + upgrades quintupled (magic × 5 — majors re-priced fivefold — version churn multiplying) + onboarding surfaces (weeks per head — hiring velocity taxed). Bounded variety performs (comprehension constant — upgrades linear in tools (≤2)); collected variety degrades (comprehension fragmenting — upgrades multiplying). Bound tools; document boundaries; audit counts.

**Mentor note** — teach "two maximum, third architecturally" (juniors proposing second tools with workload evidence design bounded polyglotry on first hearing; third-tool proposals escalated appropriately (architecture review — gravity matching permanence — bar high, reachable with evidence). Tool-count audits quarterly (services listing tools — collector drift visible (counts creeping — exceptions filed or tools removed — budgets enforced). Propose evidenced; escalate thirds; audit counts — polyglot discipline in three habits, reviewed per service.

## 2. Boundaries documented per tool (which tables/queries each owns — overlap forbidden)

**Definition** — the ownership map: per service, which tool owns which tables/queries — stated explicitly (Prisma owns graph entities (users/orders + relations); Drizzle owns dynamic reports (admin lists, analytics composition); raw owns scripts/migrations-adjacent (one-off queries, bulk paths) — overlap forbidden structurally (same table via two tools = dual truth (caching differing, transactions unshared, types diverging — inconsistency scheduled); same query via two tools = unowned performance (tuning neither (optimizations split — neither complete). Boundaries reviewed (ownership map per service — documented, linted where feasible (import rules per boundary — machines tireless).

**What problem it solves** — the overlap duo: *dual-owned tables* (users via Prisma AND TypeORM (caching differing per tool (stale reads one path, fresh another — inconsistency user-visible); transactions unshared (cross-tool atomicity absent — partial writes spanning tools (no shared unit-of-work — integrity hoped); types diverging (same table, two generated shapes — refactors breaking one path (columns renamed — TypeORM stale, Prisma current — drift institutional); and *dual-owned queries* (reports via Drizzle AND raw strings (tuning split (indexes optimized for one path — other regressing); ownership unassigned ("who owns this query?" — both/none — orphans maintained by nobody). Documented boundaries convert overlap to ownership (one tool per table/query — tuning complete, transactions shared, types singular).

**Modern guidance** — the boundary lines per service (review-enforced): *tables assigned* (each table one primary tool (graph entities → Prisma; dynamic-only tables → Drizzle where no graphs exist; scripts → raw (one-off, unowned by tools); *queries assigned* (each read path one tool (admin lists → Drizzle (dynamics); order screens → Prisma (graphs); analytics → raw/Drizzle per mappability); *overlap forbidden* (dual access failing review structurally — exception: strangler transition windows (bounded, dated — [2.1](<2.1. Migrating between tools.md>) — dual access temporary with deadline, never permanent); *linted where feasible* (import rules per boundary (Prisma client imports banned in Drizzle-owned modules and vice versa — machines enforcing documented boundaries tirelessly).

```typescript
// GOOD: ownership mapped — one tool per table/query, overlap forbidden (excerpt).
// Tables: users/orders/lines → Prisma (graphs — primary). reports/* → Drizzle (dynamics — exception ADR-014).
// Queries: order screens → Prisma includes (graphs); admin lists → Drizzle composition (dynamics);
// nightly rollup → raw (scripts — unowned by tools). Overlap: none (dual access failing review —
// exception: strangler windows (bounded, dated — 2.1 performed). Lint: import rules per boundary (enforced).
```

```typescript
// BAD: the overlapped service — dual truths, split tuning, unowned queries (real shapes).
// users via Prisma AND TypeORM (caching differing (stale vs fresh per path — inconsistency user-visible);
// transactions unshared (cross-tool atomicity absent — partial writes spanning tools); types diverging
// (same table, two shapes — refactors breaking one path silently). Reports via Drizzle AND raw strings
// (tuning split (indexes optimized per one path — other regressing); ownership unassigned ("who owns
// this?" — both/none). Overlap everywhere; ownership nowhere. Dual truths; split tuning; orphans.)
```

**Common confusion** — *"boundaries stifle flexibility (use whatever fits per query)."* Flexibility *within* boundaries (tool of ownership used freely per query it owns — full expressiveness, zero friction); anarchy *across* them (any tool per query — overlap scheduled — tuning split, transactions unshared, types diverged). "Flexibility" describes intra-boundary freedom (maximal — encouraged); cross-boundary freedom describes ownership abdication (flexibility without accountability — orphans scheduled). Boundaries channel flexibility (free within, forbidden across); absence dissipates it (flexible everywhere, owned nowhere). Free within; forbidden across — flexibility with accountability, never anarchy.

**Performance note** — boundary economics: documented boundaries cost map lines (ownership table — reviewer-visible — tuning complete per path (indexes optimized per owning tool — single tuning target); overlap costs split tuning (indexes optimized per one path — other regressing — neither complete); dual truths cost inconsistency incidents (stale-vs-fresh reads — support tickets per divergence — trust damaged); unowned queries cost orphans (maintained by nobody — performance decaying unexamined). Map cheaply (lines + lint); overlap dearly (tuning split, truths dual, queries orphaned). Document boundaries; lint imports; forbid overlap.

**Mentor note** — teach "which tool owns this?" per table/query (juniors answering with ownership map design bounded polyglotry on first hearing; unowned tables/queries interrogated ("owner?" — ownership demanded per datum). Ownership maps reviewed quarterly (workloads shifting — tools re-placed per triggers — living document, never fossil). Map ownership; lint boundaries; forbid overlap — bounded polyglotry in three habits, reviewed per service.

## 3. Shared types cross boundaries (domain types owned once — mappers translating to them, never defining)

**Definition** — the type contract across tools: domain types owned once (policy-owned interfaces — `User { id, email }` — defined in domain code, never generated per tool); mappers translating to them (Prisma/TypeORM/Drizzle rows mapped to domain types at repository edges — translation owned per implementation, tested per direction — [Domain 01 §2.2](<../../../01 Data Access Foundations and Mental Model/sections/2. Mapping patterns/2.2. The repository seam.md>) performed); generated types never crossing (Prisma-client types, TypeORM entities, Drizzle inferred rows staying inside infrastructure/ (lint-enforced where feasible — tool types in policy signatures failing review structurally). One domain type, N mapper translations — singularity at the center, adapters at edges.

**What problem it solves** — the type archipelago (each tool defining its shapes (Prisma User vs TypeORM User vs Drizzle UserRow — three "users" (fields diverging (email optional in one, required in others — refactors breaking per tool (columns renamed — TypeORM stale, Prisma current, Drizzle inferred-different); policy branching per tool type (services handling three user shapes — logic triplicated (bugs per variant — fixes applied thrice, missed once); cross-tool flows untypeable (Drizzle-fetched rows passed to Prisma-typed services — casts/any bridging (type safety voided at boundaries — hope as integration). Shared domain types convert archipelagos to continents (one User — mappers translating inward (edges tested) — policy singular (logic once — bugs fixed once).

**Modern guidance** — the type lines per service (review-enforced): *domain owned once* (policy interfaces (`User`, `Order` — plain types, no decorators/client generics — owned by domain, versioned with policy); *mappers translating* (per-tool mapping at repository edges (Prisma row → User (tested); Drizzle row → User (tested); TypeORM entity → User (tested) — translation tested per direction (mapper-row → domain asserted; domain → mapper-input asserted — bugs caught at edges, never in policy); *generated contained* (tool types inside infrastructure/ (linted — Prisma/TypeORM/Drizzle types in policy signatures failing review structurally — containment enforced by machines, judgment by humans); *flows typed end-to-end* (cross-tool data passing domain types (Drizzle-fetched → domain User → Prisma-written — typed throughout (casts absent — `as` suspicious, `any` forbidden — type safety continuous across tools).

```typescript
// GOOD: types owned once — mappers translating inward, policy singular (shapes verified).
// Domain (owned once): interface User { id: number; email: string } (plain — no decorators/generics).
// Prisma edge: toDomain(prismaUser): User (tested per direction — translation asserted).
// Drizzle edge: toDomain(drizzleRow): User (tested — same contract, different mapper).
// Policy: services handling User (singular — logic once — bugs fixed once).
// Tool types: inside infrastructure/ (linted — containment enforced). Flows typed end-to-end (casts absent).
```

```typescript
// BAD: the type archipelago — shapes per tool, policy branching, casts bridging (real shapes).
// Prisma User (generated — email: string) vs TypeORM User (entity — email?: string (nullable drift)) vs
// Drizzle UserRow (inferred — email: string | null (different nullability — three "users", diverging).
// Policy branching (services handling per-tool types (logic triplicated — bugs per variant — fixes applied
// thrice, missed once). Cross-tool flows cast (Drizzle row `as` Prisma input — safety voided at boundaries —
// hope as integration). Archipelago: shapes plural, policy branching, safety casted away.)
```

**Common confusion** — *"shared types mean shared models (one entity class everywhere)."* Shared *interfaces* (plain types — behavior-free contracts — owned by policy); mapping *implementations* per tool (translation code per mapper — tested per direction); entities per idiom where classes fit (TypeORM entities as classes (decorated — tool-side); Prisma/Drizzle rows as data (generated/inferred — tool-side); domain interfaces plain always (behavior in services/functions — policy-owned, tool-free). "Shared" describes contracts (one User interface — singular); implementations multiply per tool (translations N — tested each). Contracts singular; translations plural; casts absent.

**Performance note** — shared-type economics: translation per edge (rows→domain per read — CPU per row, negligible beside I/O — same as all mapping work); singularity saving policy triplication (logic once — bugs fixed once — velocity compounding (triplicated logic tripling fix cost — singularity dividing it); casts avoided (type safety continuous — refactors breaking at compile across tools (columns renamed — all edges erroring simultaneously — guided fixes, never silent drift). Translate per edge (cheap); share centrally (velocity); cast never (safety continuous).

**Mentor note** — teach "one User" (juniors defining domain types once discover singularity tangibly — three mappers translating inward — policy singular, tests focused, refactors guided; archipelagos interrogated ("how many Users?" — plural answered — singularity demanded). Type-counting per service ("count the Users" — one expected — archipelagos visible instantly). Singular contracts; plural translations; zero casts — shared types in three habits, reviewed per service boundary.
