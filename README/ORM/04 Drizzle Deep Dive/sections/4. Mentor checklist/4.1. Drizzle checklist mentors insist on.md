# 4.1. Drizzle checklist mentors insist on

## 1. Schema reviewed as code (tables, columns, relations — every definition earning its place)

**Definition** — the review's first pass over Drizzle schema: every table/column/relation/index definition justifying itself — tables named explicitly (database identifiers decoupled from TS names — renames safe either side); columns typed deliberately (bounds/zones/modes/parsing decided per column — [1.1](<../1. Schema as code/1.1. Schema as code.md>) performed); relations declared both sides + imported from root + registered in schema (triple complete — [1.2](<../1. Schema as code/1.2. Relations declared beside tables.md>) performed); indexes colocated (hot predicates named — FKs/lookups/orderings justified or trigger-dated). Definitions reviewed as code (values named, types inferred — reviewer-visible) *and* as schema (DDL consequences per line — widths/constraints/indexes flowing to kit diffs).

**What problem it solves** — the waved definition (tables unreviewed ("just Drizzle tables" — identity implicit (inserts demanding ids — TS2769 surprising (explicitness unenforced); TEXT-everywhere storage unpriced; stringly-typed statuses accumulating typos; relations half-wired (declared xor imported xor registered — navigation failing confusingly); indexes absent (parent writes scanning — freeze scheduled). Each unreviewed definition bills per row forever (widths × billions), per query eventually (unindexed scans), per incident quarterly (anomalies/typos/defaults failing). Review minutes per table PR convert to quarters avoided at the usual rate — highest-ROI minutes in Drizzle operations, permanently true.

**Modern guidance** — the definition review lines (per table, review-enforced): *identity* (generatedAlwaysAsIdentity explicit (inserts omitting ids — tsc enforcing (TS2769 catching omissions — explicitness compiler-checked); *columns* (types deliberate (bounds/zones/modes decided); nullability contracted; uniques/defaults/enums stated — options intentional, never defaulted); *relations* (triple complete (declared + root-imported + schema-registered — half-wired failing structurally); *indexes* (hot predicates colocated (FKs/lookups/orderings — justified or trigger-dated); *inference* (row types flowing (`$inferSelect` — refactors renaming columns via compiler — end-to-end types without generation). Missing line → request changes; "just tables" framing → schema review invoked (definitions are DDL — waved never).

```typescript
// GOOD: the definition review artifact — every line earning its place (excerpt).
// users.id: bigint number-mode + PK + generatedAlwaysAsIdentity (explicit — inserts omitting ✓).
// email: varchar(255) UNIQUE (bounded + identity ✓). role: pgEnum + default (closed ✓).
// relations: declared + root-imported + registered (triple complete ✓).
// indexes: email lookup colocated (point-fast from birth ✓). Verdict: approve definitions.
```

```typescript
// BAD: the waved definition — values unexamined, consequences scheduled (real shapes).
// id: bigint PK (identity implicit — inserts demanding ids (TS2769 surprising — explicitness absent).
// email: text() (unbounded + unindexed + non-unique — duplicates accumulating, scans scheduled).
// relations: declared-only (import unexamined — root vs pg-core confusion scheduled; registration
// unasked — db.query blind (DrizzleTypeError in production). indexes: absent ("later" unscheduled).
// Waved ("just tables"); billed quarterly (widths, scans, typos, half-wired navigation).
```

**Common confusion** — *"code-first schemas need less review (types enforce correctness)."* Types enforce *consistency* (declared shapes checked — refactors guided); review enforces *judgment* (widths priced? nullability contracted? relations complete? indexes justified? — decisions types can't make (correctly-typed bad designs compiling cleanly — TEXT-everywhere typechecks; half-wired relations typecheck until queried). "Types enforce" credits compilers with judgment (consistency, not wisdom); reviewers supply wisdom (prices, triggers, strategies — human, contextual). Type-check always (consistency free); review judgment always (wisdom priced in minutes, incidents priced in quarters).

**Performance note** — definition-review economics: widths priced per row × horizon (bounds/modes decided once — billions affected); indexes audited at birth (seconds per table empty — hours CONCURRENTLY under load — birth-indexing enforced); enum natives chosen (storage/index/cache leaner); identity explicit (inserts omitting — tsc enforcing). Unreviewed equivalents bill storage (widths × billions), queries (unindexed scans), quality (typo branches). Review minutes per table PR (definitions questioned); quarters avoided per incident class (width/scan/typo). Minutes now, quarters never.

**Mentor note** — teach "every definition earns its place" (juniors questioning table lines design deliberately from the first pgTable; unwaved definitions arriving pre-justified (types reasoned, relations triple-complete, indexes colocated — review accelerating instead of interrogating). Praise justified definitions ("good identity explicitness with priced reasoning") louder than clever compositions — teams optimize for praised behavior, and clever undefined tables have had enough admirers. Earn places; praise justifications; wave never.

## 2. Migrations witnessed end to end (generate, review, apply — no step skipped, push never prod)

**Definition** — the review's second pass over Drizzle schema change: generate reviewed (diffs rendered — SQL read fully (identity forms, constraints, downs-by-new-migration — review completeness enforced); apply governed (pending-only via `migrate` — status/check observed — production reproducing history, never improvising); push bounded (disposable databases only — linted where feasible — production push failing structurally); check scheduled (consistency validated per pipeline — drift failing builds, not deploys). End-to-end witnessing means every handoff verified (generate→review (diffs read); review→apply (approval recorded); apply→production (status green, tracked); push→disposable-only (lint passing). Skipped handoffs fail structurally.

**What problem it solves** — the unwitnessed pipeline, Drizzle edition (generate-and-apply without review (flag-day NOT NULLs (blocking rewrites); drop+create renames (history loss); missing FK indexes (parent scans) — velocity without judgment); push leaking past disposable (unreviewed DDL applied instantly to shared/staging (flag-days at machine speed — incidents automated); check unscheduled (journals unvalidated, drift aged, status unobserved — fiction compounding silently). Witnessing converts pipeline stages to checkpoints (generate→reviewed, approved→applied, applied→verified, push→bounded). Checkpoints cheap (minutes per handoff); incidents dear (quarters each).

**Modern guidance** — the witnessing lines per migration (CI + human enforced): *generate* (diff rendered (SQL read fully — phases named, renames declared, nullability checked, indexes verified); *review* (phase classified per [Database Design §5.1](<../../../DatabaseDesign/05 Evolution Growth and Partitioning/sections/1. Schema evolution/1.1. Expand and contract migrations.md>) — generator output judged, never waved); *apply* (pending-only via `migrate` (history replayed, tracked — production reproducible from files alone); *push-bounded* (disposable databases only — linted where feasible (push commands flagged in CI for protected environments); *check-scheduled* (consistency validated per pipeline — drift failing builds (verified live non-mutating run — snapshots coherent). Missing witness → request changes/block deploys; history bypassed → fiction institutionalized.

```sql
-- GOOD: the witnessing chain — generate→review→apply→verify, push bounded (excerpt).
-- Generate: diff rendered (SQL read fully — phase EXPAND named ✓).
-- Review: renames none; nullability safe; indexes verified ✓.
-- Apply: migrate pending-only (history replayed, tracked ✓). Check: scheduled, clean ✓.
-- Push: disposable-only (linted — production push failing structurally ✓).
-- Verdict: approve pipeline.
```

```sql
-- BAD: the unwitnessed pipeline — stages skipped, push unbounded (real shapes).
-- Generate: skipped (hand SQL "faster" — deltas missed (forgotten columns, absent downs)).
-- Review: skipped ("small diff" — flag-day NOT NULL inside (blocking rewrite mid-deploy)).
-- Apply: push against staging ("faster than migrations" — unreviewed DDL instantly (flag-days
-- at machine speed — incidents automated). Check: unscheduled (journals unvalidated — drift
-- aged — status unobserved — fiction compounding). Stages skipped; witnesses absent; push
-- unbounded. Incidents scheduled (dateless, as usual).
```

**Common confusion** — *"small migrations don't need witnessing (overhead)."* Witnessing scales with risk (trivial additive diffs: phase named, witnesses N/A-stated — seconds; breaking changes: full ritual — minutes), never waives structurally (unwitnessed "small" drops breaking dashboards (size of diff ≠ size of consequence); ungated "small" applies meeting drift). Overhead framing counts witnessing seconds while ignoring incident quarters — full ledger favors witnessing by orders of magnitude, permanently. Witness proportionally; waive never.

**Performance note** — witnessing economics: generate/review/apply/verify costing minutes per migration (bounded, calm — pipeline steps automated where checkable); unvitnessed equivalents costing blocking rewrites (unphased flag-days), repair migrations (fiction-built foundations — archaeology quarters), dropped histories. Minutes per migration prevent quarters per incident — witnessing ROI exceeding all other migration investments (evidence chains compound; hope chains break).

**Mentor note** — teach "witness every handoff" (juniors checking generate→review→apply→verify design pipelines completely on first hearing; handoffs skipped interrogated ("check scheduled?" — consistency demanded; "push bounded?" — lint demanded). Automate checkable handoffs (check scheduled, push linted, phase classified — machines tireless); humanize judgment handoffs (phase classification, witness evaluation — mentors precise). Witness handoffs; automate checks; judge transitions — pipeline discipline in three habits, reviewed per migration.

## 3. Composition over concatenation (dynamic queries built — string branches rejected on sight)

**Definition** — the review's closing act over query construction: every dynamic query built from conditions arrays (branches pushing expressions — parameterized, typed, logged — [2.1](<../2. Composition and migration/2.1. Queries composed, not concatenated.md>) performed); string branches rejected on sight (interpolated filters — injection per branch — `sql.raw` with concatenation failing review structurally, severity-1); emptiness explicit (zero-condition paths separated — degenerate `and()` avoided structurally — empty-filter semantics stated, never accidental); aggregates composed (groupBy/having/orderBy in-builder — analytics typed, transfer O(groups) — application-side sums rejected (transfer wasteful — millions of rows for dashboard numbers).

**What problem it solves** — the concatenated dynamic (string branches per filter (`WHERE 1=1` + appended interpolations — injection per branch (input becoming code); untestable composition (2^n branch combos — tested none); untyped results (raw strings returning `any` — refactors breaking at runtime); and the aggregated-in-application (rows fetched ungrouped, reduced in JavaScript — transfer O(rows) for O(groups) answers (millions for dashboard sums — database microseconds vs application seconds + memory). Composition converts dynamics to data (branches pushing expressions — combinations composed, never concatenated); aggregation converts transfer to groups (database computing — O(groups) shipped, never O(rows) fetched).

**Modern guidance** — the composition lines per dynamic query (review-enforced): *conditions arrays* (branches pushing `eq/like/inArray` expressions (verified live pattern — kind+prefix composing — 1 row returned); *emptiness separated* (zero-condition path explicit (unfiltered call separated — degenerate combinators avoided structurally — empty semantics stated); *parameters bound* (expressions binding values — interpolation absent (injection impossible structurally — string branches rejected on sight, severity-1); *aggregates composed* (groupBy/having/orderBy in-builder (verified live — per-kind counts typed — application-side sums rejected (transfer wasteful); *logs observed* (composed statements visible per render — surprises pre-merge — dynamics observed identically to statics). Missing array → request changes (string branches rejected with prejudice); ungrouped aggregates → compose (database computing, applications rendering).

```typescript
// GOOD: the composition review artifact — arrays, bounds, aggregates (excerpt).
// Filters: conditions array (kind + prefix branches — verified live pattern ✓).
// Emptiness: separate unfiltered path (degenerate combinators avoided ✓).
// Parameters: bound per expression (interpolation absent — injection impossible ✓).
// Aggregates: groupBy/having/orderBy composed (verified live — per-kind counts typed ✓).
// Logs: statements visible per render (surprises pre-merge ✓). Verdict: approve composition.
```

```typescript
// BAD: the concatenated dynamic — branches interpolated, combinations untested (real shapes).
// let q = `SELECT * FROM items WHERE 1 = 1`; if (kind) q += ` AND kind = '${kind}'`;
// (interpolation — injection per branch (input becoming code — 2000s never ended here);
// combinations untestable (2^n paths — tested none); results untyped (any rows — refactors
// breaking). Aggregates in application (rows fetched ungrouped — millions for dashboard sums —
// transfer wasteful, memory heavy). Concatenated dynamics; exiled analytics. Hope scheduled.)
```

**Common confusion** — *"composition review duplicates code review (same diff twice)."* Code review examines *logic* (correct branches? right columns? sensible defaults?); composition review examines *safety shape* (arrays vs strings? parameters bound? emptiness explicit? aggregates composed? — structural properties invisible to logic review (correct-looking interpolated branches passing logic review while injecting). Different subjects (logic vs shape-safety), different failures (wrong filters vs injectable filters — both critical, neither subsuming). Review logic per diff (correctness); review shape per dynamic query (safety) — two lenses, one diff, zero duplication (DRY honored — each review owning its questions exclusively).

**Performance note** — composition-review economics: arrays cost lines per dynamic query (branches as data — reviewer-visible); bound parameters plan-stably (plan reuse across combinations — interpolated strings replanning per text — parse overhead per combination); aggregates composed transfer O(groups) (dashboard sums in rows — database microseconds); application-side sums transfer O(rows) (millions — bandwidth + memory billed per render). Review minutes per dynamic query prevent injection incidents (security quarters) + transfer waste (bandwidth quarters). Compose data; bind values; aggregate in database.

**Mentor note** — teach "branches push, never interpolate" (juniors composing conditions arrays design safe dynamics on first hearing; interpolating branches interrogated ("parameterized how?" — binding demanded per branch). Demonstrate injection once (interpolated filter exploited in staging — faces paling, conversion permanent); composed equivalent immune (bound parameters — same input harmless — contrast tangible). Push conditions; bind values; log statements — dynamics discipline in three habits, reviewed per dynamic query.
