# 5.1. Common interview QA Drizzle

## 1. Tables live (schema-as-code on a whiteboard — Drizzle syntax, modeling judgment)

**Definition** — the exercise: *"model users/orders in Drizzle"* (the interview staple). The graded artifact is judgment performed in code-first syntax (entities from nouns ([Database Design §1.3](<../../../DatabaseDesign/01 Modeling Foundations and Mental Model/sections/3. First design moves/3.1. From requirements to tables.md>) — stated, not skipped); identity explicit (generatedAlwaysAsIdentity stated — inserts omitting ids — explicitness enforced); columns deliberate (bounds/zones/modes decided — [1.1](<../1. Schema as code/1.1. Schema as code.md>) performed); relations triple-complete (declared + root-imported + registered — [1.2](<../1. Schema as code/1.2. Relations declared beside tables.md>) performed); indexes colocated (hot predicates named — birth-indexed). Syntax correct AND judgments stated — either alone halves the score.

**What problem it solves** — the two whiteboard failures: *syntax-only tables* (pgTable-fluent definitions with unexamined identity (generatedAlwaysAsIdentity omitted — inserts demanding ids (TS2769 surprising — explicitness absent); TEXT-everywhere storage unpriced; relations half-wired (declared xor imported xor registered — navigation failing confusingly); indexes absent (parent writes scanning — freeze scheduled); and *judgment-only modeling* (entities/dependencies narrated without code-first expression ("I'd add a foreign key somehow" — unhirable for a Drizzle role regardless of modeling wisdom). Senior Drizzle loops grade both simultaneously (syntax fluency assumed — judgments volunteered — silence on either interrogated). Perform both, narrate continuously.

**Modern guidance** — the ten-minute shape: (1) *tables* (3 min — nouns to pgTable values, identity explicit, columns deliberate ([1.1](<../1. Schema as code/1.1. Schema as code.md>) performed briskly); (2) *relations* (4 min — triple-complete per association (declared + root-imported + registered — [1.2](<../1. Schema as code/1.2. Relations declared beside tables.md>)); references explicit (fields + references named — ownership visible); m-n explicit with attributes (growth accommodated); (3) *decisions narrated* (3 min — identity choice reasoned ("generatedAlwaysAsIdentity explicit — inserts omitting"); mode choices reasoned (number ≤2^53 stated-safe, bigint past); import/registration stated (root import + schema registration — half-wiring pitfalls named unprompted — the expert tell). Syntax written (code-first complete); judgments spoken (reasons per choice — silence interrogated).

```typescript
// GOOD (whiteboard, users/orders — 10 min, syntax + judgment performed):
const users = pgTable("users", {
  id: bigint("id", { mode: "number" }).primaryKey().generatedAlwaysAsIdentity(),
  // "identity explicit (inserts omitting ids — TS2769 enforcing — explicitness compiler-checked)"
  email: varchar("email", { length: 255 }).notNull().unique(),  // "bounded + identity (enforced)"
});
const orders = pgTable("orders", { /* ... customerId + references ... */ });
const usersRelations = relations(users, ({ many }) => ({ orders: many(orders) }));
// + "root import (pg-core lacking verified) + schema registration (db.query served)" (pitfalls named unprompted).
```

```typescript
// BAD (whiteboard): syntax without judgment, or judgment without syntax.
// const users = pgTable("users", { id: bigint("id"), email: text("email") });
// (identity implicit (inserts demanding ids — TS2769 surprising); TEXT unbounded (widths unpriced);
// relations undescribed (navigability unbuilt); indexes absent (scans scheduled); decisions unnarrated.)
// Or: "I'd have users and orders with a foreign key, normalized..." (code-first undescribed —
// relations unexpressed in Drizzle terms — unhirable for a Drizzle role regardless of wisdom.)
```

**Common confusion** — *"whiteboard code must compile (exact API)."* Interviewers grade *decisions + fluency* (identity explicit? columns deliberate? relations triple-complete? indexes colocated? — judgment), tolerating API slips (option names, import paths — corrected casually, unpenalized — verified-live details (root import, schema registration) earning bonus marks when stated, never demanded). Perfectionism wastes time (API fussing while judgments unstated — minutes on trivia, silence on substance); fluency with slips passes (judgments performed, syntax approximate — hirable demonstrated). Decide aloud; write fluently; correct slips casually.

**Performance note** — volunteer key/index decisions unprompted ("identity explicit (inserts omitting); email indexed at birth (point-fast); number-mode ≤2^53 stated-safe" — performance clauses preempt follow-ups ("what about scale?" — answered before asked). Unvolunteered performance invites probing (reactive answers scoring lower than proactive). Volunteer performance; preempt probing; control narrative — same pattern as every QA leaf, Drizzle edition.

**Mentor note** — drill whiteboard tables timed (10 minutes, tables→relations→decisions — graded: syntax fluent? judgments stated? pitfalls named?). Time each phase separately (tables 3min, relations 4min, narration 3min — phase scores diagnosing precisely ("fluent syntax, silent judgments" — drill narration, not tables). Timed drills convert typists to modelers and theorists to practitioners — both directions, one prescription (perform both, narrate continuously).

## 2. Composition under questioning (dynamic filters built live — branches composed, never interpolated)

**Definition** — the follow-up: *"add optional filters to this list query"* (the dynamics filter). The failing answers interpolate (string branches per filter — injection per branch — untestable composition — untyped results); or freeze (static queries only — "filters need raw SQL" — composition unknown — dynamics unserved). The passing answer composes live (conditions array built on whiteboard — branches pushing expressions — emptiness separated — parameters bound — [2.1](<../2. Composition and migration/2.1. Queries composed, not concatenated.md>) performed). Composition performed (not described — code written, branches pushed, emptiness handled — derivation visible); interpolation declined structurally (strings rejected with prejudice — severity-1 stated aloud).

**What problem it solves** — dynamics questions filter for safety thinking (most candidates answer conveniently (interpolated branches — fast to write, injection scheduled; or static-only — safe but unresponsive (filters unserved — features declined). Interviewers listen for parameterized composition (expressions bound — injection impossible — typed throughout — logged like all SQL). Convenient answers signal tutorial-following (strings working in demos); composed answers signal production judgment (branches safe, combinations tested, results typed). Compose safely; interpolate never — dynamics discipline performed live.

**Modern guidance** — the ninety-second shape: (1) conditions array ("branches push eq/like/inArray expressions — verified live pattern (kind+prefix → 1 row)"); (2) emptiness separated ("zero conditions → unfiltered path (degenerate and() avoided — empty semantics stated, never accidental)"); (3) parameters bound ("expressions binding values — interpolation absent (injection impossible — strings rejected with prejudice, severity-1 stated)"); (4) aggregates noted where relevant ("groupBy/having composed in-builder (verified live — per-kind counts) — application-side sums declined (transfer wasteful)"). Branches pushed, emptiness separated, values bound, aggregates composed — dynamics complete in ninety seconds.

```typescript
// GOOD (whiteboard, filtered admin list — 90 seconds, composed live):
// "Conditions array: branches push eq/like expressions (verified live pattern — kind+prefix → 1 row).
// Emptiness: zero conditions → separate unfiltered path (degenerate and() avoided — semantics stated).
// Parameters: expressions binding (interpolation absent — injection impossible — strings rejected,
// severity-1). Aggregates where needed: groupBy/having composed (verified live — per-kind counts)."
// Composed safely; interpolated never; emptiness explicit. Dynamics performed, not described.
```

```typescript
// BAD (whiteboard): the interpolated dynamic — convenient, injectable, untyped (real failure shapes).
// let q = `SELECT * FROM items WHERE 1 = 1`; if (kind) q += ` AND kind = '${kind}'`;
// (interpolation — injection per branch (input becoming code — 2000s never ended here); combinations
// untestable (2^n paths — tested none); results untyped (any rows — refactors breaking). Or: static-only
// ("filters need raw SQL" — composition unknown — dynamics unserved — features declined for unfamiliarity).
// Conveniently injectable; statically safe-but-useless. Compose safely or decline honestly.)
```

**Common confusion** — *"whiteboard dynamics can't be verified (trust the candidate)."* Composition patterns verify structurally (conditions arrays visible (expressions pushed — parameterization readable in the code shape); emptiness handled (separate path present — degenerate avoided); interpolation absent (no string branches — injection surface readable as zero). "Trust" describes interpolated code (correctness unobservable — injection invisible until exploited); composed code self-evidences (arrays + bounds + no-interpolation — safety readable per line). Readable safety > claimed safety — interviewers reading shapes, not trusting assertions. Compose readably; evidence structurally.

**Performance note** — volunteer composition economics ("parameterized branches plan-stably (plan reuse across combinations — interpolated strings replanning per text); typed results refactor safely (column changes breaking at compile); logged statements profiled per combination (hot combos EXPLAINed)"). Economics with dynamics (numbers + stability + observability — complete dynamics judgment in one extra breath). Unvolunteered economics invites "at scale?" probing (reactive answers scoring lower). Volunteer economics; preempt probing.

**Mentor note** — drill dynamics rapid-fire (ten filter sets, ninety seconds each — branches pushed, emptiness separated, values bound — verdicts timed, interpolations failing rounds). Speed forces internalization (composition reflex, not reference — interpolation failing visibly under time pressure). Interpolated answers die in drills (injection indefensible at speed — binding demanded, verdicts timed); composed answers perform (safe, typed, logged — hired). Drill dynamics; demand binding; reject strings.

## 3. Relations and N+1 live (with: batching, counts asserted — operations answers)

**Definition** — the closer: *"this Drizzle list is slow — diagnose"* (the performance filter). The graded performance is three beats (count: statements per render observed — "loop 3 vs with: 1 (verified live numbers — linear confirmed by counting, not profiling); fix: `with:` per path (batched — constant regardless of N — recount confirms); prevent: assert bounds per list test + columns trimmed (transfer intentional — wide rows narrowed). Count-fix-prevent with *verified numbers* (3 vs 1 measured live — evidence cited, not hypothesized — the strongest N+1 answer format: measured delta, structural fix, enforced prevention).

**What problem it solves** — N+1 questions filter for measurement discipline (candidates guessing ("add an index?" — unmeasured remedy for uncounted problem — tuning what wasn't counted); candidates theorizing ("probably the database" — blame without counting); candidates counting ("loop 3 vs with: 1 — measured live pattern — batch to constant (recount confirms) — assert bounds (immunity designed). Interviewers watch *where eyes go first* (logs/counts → measurers (hired); code staring → guessers (junior); EXPLAIN before counting → premature optimizers (misordered). Counting first is the senior tell — measured beats guessed at every level, always.

**Modern guidance** — the five-minute shape (same count-fix-prevent as all QA leaves, Drizzle-evidenced): (1) *count* (1 min — "statements per render? loop 3 vs with: 1 (measured live — linear confirmed via counting wrapper — evidence, not suspicion)"); (2) *fix* (2 min — "`with:` per path (batched — constant regardless of N — recount confirms); columns trimmed (transfer intentional — wide rows narrowed)"); (3) *prevent* (2 min — "assert ≤N per list test (N+1 fails builds); strategies stated per relation (`with:` explicit — lazy absent structurally (no magic traversals in Drizzle — unstrategized access *visible* as hand loops); logging on (surprises pre-merge)"). Measured delta cited (3 vs 1 live — evidence); structural fix verified (recount confirms); immunity designed (assertions + strategies + logs).

```typescript
// GOOD (whiteboard, user list — 5 min, three beats with measured evidence):
// "Count first: loop 3 vs with: 1 statements (measured live — linear confirmed via counting wrapper).
// Fix: with: { orders: true } per path (batched — constant regardless of N — recount confirms);
// columns trimmed (transfer intentional — wide rows narrowed). Prevent: assert ≤N per list test
// (N+1 fails builds); strategies stated per relation (explicit with: — lazy absent structurally
// (no magic traversals — hand loops visible, countable)); logging on (surprises pre-merge)."
// Counted (3 vs 1 live), fixed (batched), immunized (asserted). Evidence cited; structure fixed.
```

```typescript
// BAD (whiteboard): the unmeasured remedy — tuning what wasn't counted, asserting nothing.
// "Add an index on orders(customer_id)?" (Counted? Never — statements uncounted (maybe 1 already
// (no N+1 present — index tuning a healthy query); maybe 10k (N+1 present — index irrelevant
// (counts dominate, not lookups)). Remedy without diagnosis (tuning unmeasured paths — premature
// optimization wearing expertise); prevention unmentioned (next list N+1s identically — immunity
// undesigned). Guess, tune, repeat — performance theater (verified numbers absent, structural fixes
// unattempted, assertions never filed).
```

**Common confusion** — *"Drizzle has no N+1 (explicit queries only)."* Explicitness prevents *magic* N+1 (no lazy loading — traversals never hidden — true, structural); hand loops N+1 identically (per-parent explicit queries — verified live: 3 statements looped — explicit loop, linear cost). "No N+1" credits explicitness with batching (explicit loops still linear — visibility aiding detection (loops seen), not preventing (loops still N+1). Explicitness aids counting (loops visible — countable easily); batching prevents (`with:` — constant); assertions enforce (bounds tested). Visible loops counted; batched paths constant; bounds asserted — explicitness + discipline, never explicitness alone.

**Performance note** — close with counted math (same pattern as every QA leaf, Drizzle-evidenced): "loop 3 → with: 1 (measured live — delta cited); multi-list fan-out split (transfer bounded — cause removed); assertions bound future lists (immunity designed — N+1 fails builds)". Counted math proves measurement (numbers from live runs — strongest evidence format); structural fixes prove competence (batching, not tuning); prevention proves seniority (assertions + strategies + logs). Math + structure + immunity — complete N+1 answer with live evidence, expert depth free.

**Mentor note** — drill count-fix-prevent timed (5 minutes, three beats — graded: counted first? (logs/counters before remedies — order enforced); fixed structurally? (batching, not tuning — remedy classified); prevented explicitly? (assertions + strategies + logs — immunity designed)). Order enforced ruthlessly (remedy-before-count fails the round regardless of correctness — discipline over cleverness, always). Timed drills convert guessers to counters (measurement reflex), tuners to batchers (structural remedies), hopefuls to asserters (immunity designed). Count, batch, assert — drilled to reflex, performed under pressure, hired.
