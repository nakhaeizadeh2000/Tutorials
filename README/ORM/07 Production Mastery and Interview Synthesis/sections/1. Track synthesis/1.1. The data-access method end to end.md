# 1.1. The data-access method end to end

## 1. Six domains, one sequence (workload → layer → tool → operate — each assuming the last)

**Definition** — the track as one method: **01** names layers and patterns (raw/builder/mapper jurisdictions, ActiveRecord/DataMapper positions, cost ledgers, seam contracts — judgments everything later applies); **02–04** operate one tool each deeply (Prisma generated clients, TypeORM decorated classes, Drizzle code-first tables — mechanics executed, strategies implemented, magic inventoried per tool); **05** selects among tools (workload-matched verdicts with measured evidence — positions mapped, ledgers priced, triggers dated); **06** operates selections (pools sized, transactions bounded, queries observed, upgrades rehearsed — production performing boringly). Each layer consumes the previous layer's outputs — patterns positioning tools, tools instantiating patterns, selections pricing tools, operations running selections. The sequence is a dependency graph, not a suggestion.

**What problem it solves** — fragmentary expertise (Prisma-fluent engineers unable to place Drizzle (tool depth without pattern breadth — positions unmapped, jurisdictions guessed); selection experts unversed in operations (verdicts without gauges — pools unsized, upgrades unrehearsed — decisions made, operability hoped); operators innocent of patterns (gauges green on misfit tools — ceremony performing reliably ( superb operations on wrong choices — bills paid superbly). Production data access demands all six simultaneously (every service needs layers AND tools AND selection AND operations — the layers co-occur in every connection string); engineers fluent per-domain but illiterate across them operate correct fragments that fail as systems (strategized queries on misfit tools, gauged pools under wrong abstractions). The sequence converts six courses into one practice: decide layers, operate tools, select deliberately, run boringly — every service, every time.

**Modern guidance** — run every non-trivial data-access decision through all relevant layers, in order, writing each layer's artifacts (layer named per feature ([Domain 01 §1.2](<../../../01 Data Access Foundations and Mental Model/sections/1. Why data-access layers/1.2. Query builders versus ORMs versus raw drivers.md>)) → tool operated per mechanics (Domains 02–04) → selection priced per workload ([Domain 05 §1.1](<../../../05 Comparing and Choosing/sections/1. Selection by workload/1.1. Workload-matched selection.md>)) → operations gauged per path ([Domain 06 §2.1](<../../../06 Production ORM Use/sections/2. Operating mappers/2.1. Production observability per mapper.md>)). Trivial features compress (one-table lookups still get layer + trigger — method scales down to checklist speed); routine features abbreviate documented layers ("standard junction, both indexes" analogues — team defaults applied with triggers); novel features expand (new tools evaluated fully — positions mapped, ledgers priced, operations rehearsed). Same sequence always — depth varies, order never does.

// 05: verdict Drizzle (measured: with: 1 statement — evidence over fashion — trigger dated).
// 06: pools sized (max derived — exhaustion designed out); queries observed (gauges owned).
// Coherence: raw and Drizzle paths returning identical rows (verified live: coherence true, 2 rows).
// Layers interfaced (decisions flowing downstream — judgments upstream constraining operations).
```

// Prisma-fluent service with unplaced layers (ceremony without graphs — flat admin tools under
// generation (build seconds per trivial change — jurisdiction unexamined); unstrategized queries
// (includes present-or-absent per author — N+1 scheduled); uninventoried magic (v7 middleware
// removal breaking gauges silently — versions moving underneath); unexamined pools (adapter-managed
// defaults governing production — exhaustion discovered, not designed). Fluent fragments;
// failing wholes. Layers skipped; incidents scheduled (dateless, as usual).)
// Single-layer brilliance; six-layer system. Fragments graded; wholes failed.
```

**Common confusion** — *"seniors skip steps — method is for juniors."* Seniors *compress* steps (six lenses in minutes — pattern recognition substituting for paperwork — positions mapped instantly, triggers dated reflexively); never skip them (skipped lenses surface as incidents regardless of seniority — unstrategized queries paging staff engineers identically; unexamined pools exhausting under senior-approved defaults). Compression without omission is expertise; omission with confidence is risk wearing seniority. Review seniors on omitted lenses explicitly ("strategies stated?" — silence fails regardless of level). Method scales with experience; sequence binds all levels equally.

**Performance note** — layered data access is upstream performance work in total (same argument compounded across five domains: each layer removes one incident class and one tuning burden — jurisdictions removing misfit drag, strategies removing N+1, ledgers removing surprise upgrades, pools removing exhaustion, gauges removing blindness). Unlayered data access arrives in performance reviews as mysteries ("slow database" — which layer? — archaeology); layered data access arrives with layer-labeled metrics (statement counts? pool depth? relay lag? magic version? — diagnosis by layer, fixes targeted). Metrics per layer, mysteries never — the method's performance dividend, track complete.

**Mentor note** — teach the sequence as "the six questions" (which layer? which tool? what verdict? what triggers? what gauges? what upgrades? — one question per domain, asked in order, every data-access decision). Juniors answering six questions decide completely on the first try; the questions fit an index card; the card belongs in onboarding beside every data-access doc from Domains 01–06. Questions over courses, same pedagogy as every selection in this track — six questions, one method, permanent practice.

## 2. The worked capstone (one feature through all six lenses — the method performed whole)

**Definition** — the capstone exercise: a single feature (order-management API with admin reporting — the track's running synthesis, fully specified below) decided through every lens, artifacts per layer, verdicts recorded with links to home domains. The capstone is the track's graduation proof (performed live in interviews — [3.1](<../3. Interview mastery/3.1. Cross-tool interview synthesis.md>) stages it; taught in onboarding — [4.1](<../4. Mentor checklist/4.1. Mentor checklist for the whole track.md>) assigns it). One feature, six lenses, zero skipped steps — the method performed whole, witnessed.

**What problem it solves** — the gap between knowing and performing (engineers reciting all six domains' rules while deciding data access single-layered — knowledge tested per domain, performance never integrated). Capstones integrate under observation (mentors watch lenses applied in sequence — skipped lenses visible instantly: "you priced tools but named no gauges — back to 06"); interviews simulate them ([3.1](<../3. Interview mastery/3.1. Cross-tool interview synthesis.md>)'s staff loop is a timed capstone); onboarding assigns them (first-month capstone on a real feature — reviewed layer by layer). Knowledge fragments without capstones; capstones compose knowledge into practice — the final pedagogical step, track complete.

**Modern guidance** — the capstone procedure (feature: order-management API + admin reporting; artifacts per layer — coherence verified live this session): **01** layer (graphs earn mappers for order screens (relations traversed); dynamics earn builders for admin lists (filters composed); flat remainder typed raw — jurisdictions placed per surface, triggers dated); **02–04** tool (Prisma for order graphs (explicit includes — N+1 prevented); Drizzle for admin dynamics (conditions arrays — injection impossible); shared domain types across both ([Domain 05 §2.2](<../../../05 Comparing and Choosing/sections/2. Changing tools/2.2. Polyglot persistence honestly.md>) — polyglot bounded, boundaries documented); **05** verdict (measured comparison cited (raw-loop 6 vs batched 1–2 — evidence over fashion); ledgers priced per tool; triggers dated (graphs past 2 relations re-evaluate; yearly revisits calendared); **06** operations (pools sized per tool (max derived — exhaustion designed out); gauges owned (lag, depth, age — dashboarded); upgrades rehearsed (majors practiced — magic re-audited). Each artifact links its home domain — the capstone reads as six citations performing one feature.

**Common confusion** — *"capstones are academic — production moves too fast."* Production speed rewards layered fluency (six lenses in minutes for routine features — seniors' compression from promise 1 of [1.1... promise 1 above); layer-skipping (incidents cost quarters; capstone discipline costs minutes). "Too fast to decide" inverts causality (skipped lenses *cause* the incidents that consume quarters — layered time blamed for incident time it would have prevented). Fast teams capstone routinely (lightweight per feature — artifacts proportional to novelty); slow teams incident-review repeatedly (heavyweight per outage — ceremonies proportional to skipped lenses). Speed with method beats speed without — measured in quarters, not sprints.

**Performance note** — capstone economics: full capstone costs hours (novel features — design-doc scale) to minutes (routine features — checklist speed); skipped-layer incidents cost engineer-weeks each (N+1 avalanches, pool exhaustions, magic upgrades, unindexed scans, flag-day migrations, unobserved relays — six classes, each priced across this track). Capstone ROI exceeds 100× on first prevented incident — the track's closing arithmetic: minutes of method vs quarters of incidents, every feature, forever.

**Mentor note** — assign capstones as onboarding graduation (new hire deciding one real feature through six lenses, reviewed layer-by-layer by mentor — gaps located precisely ("tools solid, gauges unowned" — targeted coaching, not vague "learn data access"). Capstone reviews diagnose completely (six lenses checked — strengths and gaps mapped in one session); targeted follow-ups prescribe exactly (drill the gap domain's QA leaf — autonomous improvement after). Onboard with capstones; coach by gaps; graduate measurably — the track's pedagogy performing whole, mentors equipped.

## 3. Handoff discipline between layers (each domain's output is the next domain's input)

**Definition** — handoffs made explicit: 01 outputs (layer verdicts per feature, pattern positions, cost ledgers, seam contracts — decisions recorded) feed 02–04 (tool operation assumes jurisdictions (mappers operated where graphs earn them — placement inherited, never re-derived); 02–04 outputs (strategies implemented, magic inventoried, versions pinned) feed 05 (ledgers priced from lived mechanics — selection evidenced, never vibed); 05 outputs (verdicts with triggers, polyglot maps, benchmark literacy) feed 06 (pools sized per chosen tool — triggers monitored per verdict — revisits calendared per ledger); 06 outputs (gauges, incidents, upgrade notes) feed back into 01 (magic versions informing patterns — relay lag informing aggregate sizing analogies — the loop closes: operations experience revising foundations). Each handoff named, format-specified, review-checked — layers interface like systems, because they are one.

**What problem it solves** — layer amnesia (tool operation redoing layer placement (jurisdictions re-derived per tool review — positions re-argued (fashion re-litigated — decisions unrecorded upstream); selection re-deriving mechanics (strategies re-examined per verdict — tool behavior re-learned (evidence rebuilt — S2–S4 findings re-discovered); operations ignoring selection (pools sized generically (tool specifics unconsulted — adapter/extras/passthrough differences unexamined (sizing misapplied — exhaustion scheduled). Amnesia taxes every layer transition (re-derivation per review, mismatched assumptions per handoff, "which layer?" asked six times per feature). Named handoffs with formats eliminate re-derivation (downstream consumes upstream artifacts as inputs — review verifies handoff completeness, not content re-created). Interfaces, not recalls — systems thinking applied to method itself.

**Modern guidance** — the handoff table (format per boundary, checked at review): 01→02–04 (layer verdicts + pattern positions (tool operation assumes jurisdictions — placement inherited); 02–04→05 (strategies implemented + magic inventoried + versions pinned (ledgers priced from lived mechanics — selection evidenced); 05→06 (verdicts with triggers + polyglot maps (pools sized per chosen tool — triggers monitored per verdict — revisits calendared per ledger); 06→01 (gauges + incidents + upgrade notes (patterns revised from operations — magic versions informing idioms — loop closed: operations experience revising foundations). Review checks handoffs (upstream artifact present? format complete? downstream consuming, not re-deriving?) — missing handoff fails review structurally (content unexamined until interfaces complete — same discipline as code API reviews).

// S2–S4 findings re-discovered). Operations ignoring selection (pools sized generically (tool specifics
// unconsulted — adapter/extras/passthrough differences unexamined (sizing misapplied). Six layers, six
// memories, zero interfaces. Amnesia itemized; handoffs absent; re-derivation billed per review.)

**Common confusion** — *"handoffs are process overhead for small teams."* Handoff formats cost lines (verdicts recorded, triggers named — seconds per artifact), while amnesia costs reviews (re-derivation per layer per feature — minutes-to-hours, compounding per hire who wasn't in the room). Small teams suffer amnesia worst (tribal memory walking out with departures — handoffs written survive, recalls don't). Artifacts outlive authors — the smallest teams need written handoffs most (bus factor 1 means memory factor 1 — write it down or lose it with the person). Lines now vs memory later — write the lines.

**Performance note** — handoff economics compound the track's performance argument finally: interfaced layers diagnose by layer (metrics labeled per handoff — statement counts? pool depth? relay lag? magic version? — each traceable to its layer's artifacts); amnesiac layers diagnose by archaeology (which assumption? whose recall? — unanswerable post-departure). Debugging interfaced systems is targeted (layer-labeled metrics → layer-owned fixes); debugging amnesiac systems is excavation (quarters per mystery). Interfaces pay in debuggability what they cost in lines — the method's final performance dividend, track complete.

**Mentor note** — teach handoffs as "APIs between thinking steps" (juniors grasping interface discipline from code APIs transfer it instantly — upstream outputs, downstream inputs, formats contracted, completeness reviewed). Review handoffs explicitly ("show me 01's verdict feeding 02's operation" — missing link fails structurally). Teams interfacing thought scale thought (new hires consume artifacts, not mentors' time — onboarding via handoffs, not shadowing). Interface thinking; scale understanding; onboard via artifacts — the method teaching itself, mentors facilitating.
