# 1.2. Review as a practice across tools

## 1. One review ritual for all tools (layer, strategy, counts, magic — unified)

**Definition** — the unified review template: every data-access PR answers the same layered questions regardless of tool — **layer** (raw/builder/mapper placed per feature with jurisdiction reason ([Domain 01 §1.2](<../../../01 Data Access Foundations and Mental Model/sections/1. Why data-access layers/1.2. Query builders versus ORMs versus raw drivers.md>)); **strategy** (relation loading stated per read (include/relations/with: — N+1 prevented structurally); **counts** (statement bounds per list test — N+1 failing builds — [Domain 01 §4.1](<../../../01 Data Access Foundations and Mental Model/sections/4. Mentor checklist/4.1. Data-access checklist mentors insist on.md>)); **magic** (defaults/idioms inventoried per tool per version — surprising entries disabled with reason + owner). One ritual, three tools' content — reviewers learn one procedure, authors fill one template, depth varies by novelty (trivial changes answer in lines, novel features in design docs — same questions, scaled answers).

**What problem it solves** — review fragmentation (each tool reviewed in its idiom — Prisma includes checked, TypeORM relations unexamined, Drizzle composition unreviewed — partial reviews approving partial data access); and review absence disguised as speed ("small PR, quick approve" — small diffs with unpriced consequences: unstrategized traversal, unindexed FK, unexamined default — each trivial to write, each incident-capable). The unified ritual forces all layers' questions on every data-access PR — trivial answers for trivial changes (seconds), deep answers for novel ones (design docs) — but never absent answers. Ritual completeness scales with novelty; ritual presence never waives.

**Modern guidance** — the template, filled per PR (sections omitted only with "N/A because X," never silently): **L**ayer (raw/builder/mapper + jurisdiction reason — links to [Domain 01 §1.2](<../../../01 Data Access Foundations and Mental Model/sections/1. Why data-access layers/1.2. Query builders versus ORMs versus raw drivers.md>)); **S**trategy (relation loading stated — include/relations/with: per read — links to tool domains 02/2.2, 03/3.1, 04/3.1); **C**ounts (statement bounds per list test — N+1 failing builds — links to [Domain 01 §4.1](<../../../01 Data Access Foundations and Mental Model/sections/4. Mentor checklist/4.1. Data-access checklist mentors insist on.md>)); **M**agic (defaults/idioms inventoried per tool per version — links to [Domain 05 §1.2](<../../../05 Comparing and Choosing/sections/1. Selection by workload/1.2. Cost ledgers per tool.md>)). Author fills; reviewer verifies per line; automation checks structure (CI linters — synchronize-true fails, unindexed-FK checks, statement-count assertions — machines tireless); humans check judgment (placement, strategies, magic — mentors own these lines). L-S-C-M: four letters, complete review, every data-access PR, forever.

```typescript
// GOOD: the unified review artifact — four letters, all answered (order-list PR).
// L: Drizzle (dynamics earn builders — flat shapes decline mappers — jurisdiction placed).
// S: with: { lines: true } stated (batched — N+1 structurally absent — strategy performed).
// C: ≤3 statements/test asserted (N+1 fails builds — counts enforced, not hoped).
// M: Drizzle 0.45 inventoried (identity explicit — modes chosen — kit witnessed — magic listed).
// Verdict: approve data access.
```

```typescript
// BAD: the fragmented review — home tool checked, others unasked (real failure shapes).
// "Prisma includes look right. +1." (Layer? Unasked — flat shapes under ceremony (jurisdiction
// unexamined). Strategy beyond Prisma? Unasked — TypeORM relations unstrategized (N+1 scheduled
// per unexamined traversal). Counts? Unasserted ("works in staging" — tens hiding ten-thousands).
// Magic? Uninventoried (v7 middleware removal breaking gauges silently — versions moving underneath).
// One tool reviewed; three unasked. Partial review, complete consequences. Ritual presence would
// have cost lines; absence bills quarters.)
```

**Common confusion** — *"unified rituals are bureaucracy."* (Asked and answered per-domain across both tracks; restated finally for the unified form.) Bureaucracy is cost without benefit; ritual lines cost seconds-to-minutes and prevent quarters of incidents — the highest-ROI minutes in data-access work, seventh domain running, track nearly complete. Teams calling rituals bureaucracy ship without them exactly until the first preventable outage — then adopt them under incident pressure (worst time to design process). Adopt calmly now (template + automation + judgment split) or adopt frantically later (postmortem action items, resented, half-followed). Calm adoption, permanent value.

**Performance note** — unified review is upstream performance work in total (same argument compounded finally: every layer's performance contribution — residency, pruning, relay scans, claim indexes, cached flags, batched relations, sized pools, observed queries — reviewed at decision time, never tuned later in panic). Review minutes convert to outage-hours avoided at the track's usual exchange rate — stated seven times because believed zero times by newcomers and seventh-time by practitioners. Minutes now, quarters never — the ritual's economics, track nearly complete.

**Mentor note** — teach L-S-C-M as the review alphabet (juniors spelling reviews letter-by-letter internalize completeness before speed — speed follows repetition, completeness never follows speed-first habits). Post the template where PRs are written (PR template pre-filled with L/S/C/M headings — authors fill, reviewers verify — structure enforced by tooling, judgment by humans). Four letters, one habit, every data-access PR — onboarding teaches the alphabet week one; fluency follows within a quarter; mastery reviews others' alphabets within a year.

## 2. Registers are the institutional memory (decisions, triggers, versions — three ledgers, one habit)

**Definition** — the three registers (ledgers maintained per team, reviewed quarterly): **decisions** (ADRs — tool selections with reasons/triggers/dates ([Domain 05 §4.1](<../../../05 Comparing and Choosing/sections/4. Mentor checklist/4.1. Selection checklist mentors insist on.md>) — why tools are what they are — dated, attributed); **triggers** (metric → threshold → response → owner — pool depth, N+1 counts, version budgets, migration backlogs ([Domain 06 §2.1](<../../../06 Production ORM Use/sections/2. Operating mappers/2.1. Production observability per mapper.md>) — monitored, firing); **versions** (tool versions pinned with upgrade notes (Prisma 7.10.0 + v8 RC watch; TypeORM 1.1.1 idioms current; Drizzle 0.45.3 + kit 0.31.11 — majors re-priced per [Domain 06 §2.2](<../../../06 Production ORM Use/sections/2. Operating mappers/2.2. Upgrade operations without drama.md>)). Memory surviving departures (written, indexed, reviewed — tribal knowledge institutionalized); amnesia scheduled never (unwritten decisions evaporating with authors — bus factor 1 means memory factor 1).

**What problem it solves** — institutional amnesia (the "why is this like this?" quartet asked per quarter: tools selected why? (unrecorded — re-litigated or "fixed" into regression (fashion re-argued — evidence absent); triggers set where? (unwritten — fired never, discovered expired (saturation surprising — thresholds silent); versions pinned why? (undocumented — upgrades feared (majors deferred — debt compounding (stale versions accumulating — upgrade debt compounding). Each unanswered question costs re-derivation (hours), wrong-way migration (quarters), or incident (unbounded). Registers answer all three structurally (written at decision time — ten minutes; read in seconds forever; reviewed quarterly — 30 minutes per register). Memory cheap at writing, dear at reconstructing — write early, read always.

**Modern guidance** — the register habit (one habit, three ledgers): *write at decision time* (selection/trigger/version recorded in the deciding PR — context hot, cost minutes); *index centrally* (ADRs numbered, triggers dashboarded, versions inventoried — findable in seconds by strangers); *review quarterly* (registers swept with owners present — expired triggers re-priced, fired triggers executed, version budgets enforced — 30 minutes per register, calendared); *cite in reviews* ("per ADR-001" — decisions referenced, not re-argued — re-litigation declined structurally). New hires read registers first week (onboarding via ledgers, not shadowing — institutional memory transferred without mentor-hours). Unwritten decisions don't exist (review mantra — "not in the register, didn't happen" — harsh, effective, true enough to work).

```typescript
// GOOD: registers living — written hot, read always, reviewed quarterly (excerpt).
// Decisions: ADR-001 (Drizzle default — dynamics jurisdiction — reasons + triggers + date).
// Triggers: pool depth >70% (dashboarded — firing scheduled); N+1 counts bounded (asserted);
// version budgets (Prisma 8 watch active — ledger re-price on stable).
// Versions: Prisma 7.10.0 / TypeORM 1.1.1 / Drizzle 0.45.3 + kit 0.31.11 (pinned — upgrades rehearsed).
// New hire week 1: reads three registers — productive month 1 (no archaeology required).
```

```typescript
// BAD: tribal memory — decisions in heads, triggers in hopes, versions in vibes (real shapes).
// "Why Drizzle here?" (Author departed — re-derive or revere blindly (fashion re-argued — evidence absent).
// "Trigger for pools?" (Discussed once, written never — saturation surprising (thresholds silent — pages
// without warning). "Which versions?" (Undocumented — upgrades feared (majors deferred — debt compounding
// (stale versions accumulating — upgrade debt compounding). Onboarding: shadow seniors for months
// (mentor-hours burning); departures: memory walking out quarterly. Amnesia itemized; ledgers absent.)
```

**Common confusion** — *"registers are documentation that rots."* Registers rot only unreviewed (quarterly sweeps pruning expired triggers, superseding stale decisions, enforcing version budgets — maintenance calendared, 30 minutes per register). Unreviewed anything rots (code, docs, runbooks — rot is the default state of unmaintained artifacts, not a register-specific disease). "Docs rot" argues for maintained ledgers with owners and calendars (this promise), never for unwritten memory (tribal amnesia, guaranteed). Maintain rhythmically; trust structurally; onboard via ledgers.

**Performance note** — register economics: writing costs minutes per decision (hot context — cheapest knowledge-capture moment); reading costs seconds per question (indexed, searchable — vs hours of archaeology per unrecorded decision); reviewing costs 30 minutes quarterly per register (90 minutes/quarter total — one meeting); amnesia costs re-derivation hours + wrong-way migration quarters + incidents unbounded. Ledger ROI exceeding 100× within the first prevented re-litigation — the cheapest knowledge infrastructure in engineering, declined wherever "documentation" is a dirty word. Write hot; read always; review quarterly.

**Mentor note** — model register-writing on your own decisions first (the track's standing lesson, seventh and final domain: authority's example teaches — senior's ADR linked in PR teaches more than any documentation mandate). Start new teams with empty registers and full rituals (write-first culture from day one — no backlog to excuse); inherit messes with register-reconstruction sprints (archaeology once, ledgers forever after — "document what we learn while learning it"). Praise register citations ("per ADR-001 — great, no re-litigation") louder than clever arguments — teams optimize for praised behavior, and re-litigation has had enough enthusiasts.

## 3. Review cadence by lifecycle (per-PR checks, quarterly audits, yearly strategy)

**Definition** — review rhythm in three tempos: **per-PR** (L-S-C-M ritual — minutes, every data-access PR — automation checks structure, humans check judgment); **quarterly audits** (registers swept, triggers re-derived, stale tools/flags/versions reviewed, N+1 counts re-baselined — hours, owners present, tickets filed); **yearly strategy** (track-level questions: tool mix still fit? majors adopted? team shape serving data access? — days, leadership present, roadmap updated). Tempos nest (PRs feed registers, registers feed audits, audits feed strategy — information flowing up, decisions flowing down); skipped tempos compound (unreviewed PRs → decayed registers → blind audits → strategic surprises — rot flowing down faster than information flows up).

**What problem it solves** — the two rhythm failures: *PR-only reviewing* (tactical excellence, strategic blindness — every PR correct, registers decaying, triggers expiring silently, strategy drifting — death by a thousand correct merges); and *audit-only reviewing* (quarterly heroics on decayed quarters — 200 stale exceptions, 50 expired triggers, 3M-member unexamined celebrities — audits as archaeology expeditions, findings overwhelming, follow-through failing). Three tempos cover three horizons (PRs: today correct; audits: quarters healthy; strategy: years directed) — missing any tempo blinds its horizon (correct todays accumulating into unhealthy quarters into undirected years — the slow drift no single review catches).

**Modern guidance** — the cadence contract (calendared, owned, never "when time permits"): *per-PR* (template enforced — CI structure + human judgment — every data-access PR, no exceptions, no "trivial" waivers — trivial answers welcome, absent forbidden); *quarterly* (register sweep week — three registers, owners present, tickets filed per finding — findings triaged like bugs (P1–P3 with dates), never "accepted" vaguely); *yearly* (strategy offsite input — tool mix fit? majors adopted? team capabilities? — roadmap updated with data-access implications — leadership deciding with registers as evidence, not vibes). Skipped sessions rescheduled within two weeks (never dropped — dropped cadence signals optional cadence; optional cadence dies within two quarters — protect the rhythm like production uptime, because it protects production uptime).

```typescript
// GOOD: cadence calendared — three tempos, owners, no gaps (excerpt).
// Per-PR: L-S-C-M template (CI + humans — every data-access PR — trivial answers welcome, absent forbidden).
// Quarterly (register week, owners present): triggers re-derived from fresh rates, tools re-matched,
// versions re-pinned, N+1 counts re-baselined (tickets filed per finding — triaged like bugs).
// Yearly (strategy input): tool mix fit? majors adopted? team shape? — roadmap updated, implications attached.
// Rhythms nested, horizons covered. Calm cadence, permanent value.
```

```typescript
// BAD: arrhythmic reviewing — PRs sometimes, audits never, strategy by surprise (real shapes).
// PRs: "looks fine" (template absent — partial reviews, silent waivers for "trivial").
// Quarterly: unscheduled 6 quarters running (registers decayed — 200 stale exceptions, triggers
// fossilized, versions drifted across majors — findings overwhelming, follow-through failing).
// Yearly: strategic surprise (tool mix misfit — discovered during the outage that needed re-selection
// designed two years prior; major skipped so long upgrade is rewrite-class — surprise scheduled).
// Correct merges accumulating into unhealthy quarters into undirected years. Rhythm absent;
// drift present; surprises scheduled (by entropy, dateless, as usual).
```

**Common confusion** — *"cadence is process overhead that slows delivery."* (Asked and answered per-tempo across both tracks; restated finally for rhythm itself.) PR ritual costs minutes (amortized to zero marginal — fluency follows repetition); quarterly audits cost hours per quarter (register week — cheaper than one incident review); yearly strategy costs days yearly (leadership time — cheapest strategy input available: evidence-rich registers vs consultant vibes). Overhead framing counts ceremony minutes while ignoring drift quarters — full ledger favors rhythm by orders of magnitude, seventh and final domain, track nearly complete.

**Performance note** — cadence economics close the track's performance argument finally: per-PR review prevents incidents (minutes → quarters-saved, every layer); quarterly audits prevent decay (hours → comprehension preserved, triggers firing, sediment cleared); yearly strategy prevents misfit (days → tool mix adequate, majors adopted, team capable). Three tempos, three horizons, one ledger — performance delivered at decision/review/audit/strategy times, never firefighting time. The method's total dividend: boring operations, comprehensible data access, directed evolution — track nearly complete, on-call asleep.

**Mentor note** — protect cadence like uptime (skipped sessions rescheduled within two weeks — leaders attending audits signal priority louder than any mandate; audits leaders skip die within two quarters — attendance is the process). Start cadence with the team present (rituals imposed fail; rituals co-designed persist — first register week facilitated, template tuned to team, automation added where toil appears). Rhythm kept for a year becomes culture (new hires inherit cadence as "how we work" — unexplainable, unremovable, invaluable). Culture in three tempos — conduct steadily, mentors.
