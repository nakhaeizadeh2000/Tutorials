## 3.1. Bare node:http servers and clients

### 1) **Server: routes by hand**

**Definition** — `http.createServer((req, res) => ...)` hands you the raw exchange: `req.method` + `req.url` (dispatched manually — if/switch or a tiny route table; no framework magic), `req.headers` (plain object — parsed, lowercased), `res.writeHead/end` (status + headers + body — composed explicitly). Frameworks automate exactly this (routing, parsing, serializing — conveniences atop these primitives). One hand-rolled server per career teaches what every framework hides: the exchange is two streams plus metadata.

- **What problem it solves**: framework-magic thinking (routes as declarations without mechanics — debugging "why 404?" without knowing what matching means; middleware as mystery — ordering effects unexplained). Hand-routing demystifies (matching is string comparison; params are substring ops; 404 is the default arm). Framework code then reads as automation (convenient, optional, replaceable) rather than platform (necessary, opaque, feared).
- **Modern guidance** — route table over if-chains past three routes (`Map` of `METHOD path` → handler — declarative, testable; params via `URL` parsing, point 2's bodies aside). Always end every branch (each handler terminates the response — hanging branches are the bare-server hang; 404 default arm — unmatched never dangles). Set reasoned headers (`content-type` explicit — no sniffing surprises; `content-length` where known — keep-alive friendly).

```javascript
// GOOD: hand-rolled routing, every branch ended — runs on node v20.20.2 (200/200/404 as routed)
const http = require('node:http');
const routes = new Map([['GET /hello', (req, res) => res.end('hi')], ['GET /json', (req, res) => { res.writeHead(200, { 'content-type': 'application/json' }); res.end('{"ok":true}'); }]]);
const server = http.createServer((req, res) => { const route = routes.get(`${req.method} ${new URL(req.url, 'http://x').pathname}`); if (route) return route(req, res); res.writeHead(404); res.end('nope'); }); // 404 arm (never dangles)
server.listen(0, '127.0.0.1', async () => {
  const port = server.address().port; const get = (p) => new Promise((res) => http.get({ port, host: '127.0.0.1', path: p }, (r) => { let b = ''; r.on('data', (c) => b += c); r.on('end', () => res(`${r.statusCode}:${b}`)); }));
  console.log(await get('/hello'), '|', await get('/json'), '|', await get('/missing')); server.close(); // 200:hi | 200:{"ok":true} | 404:nope
});
// BAD: single handler with nested ifs and one forgotten branch ("prototype") —
// the forgotten branch hangs; prototypes become production; hangs become incidents
```

### 2) **Bodies streamed, limits enforced**

**Definition** — requests with bodies are Readables (chunks arrive — buffered by choice, never by default; `Content-Length` advises, chunked encoding streams without it). The discipline: cap before buffering (bytes counted per chunk — past the cap `destroy()` the request with 413; unbounded buffering is the upload OOM — leaf 1.1 of Domain 03's size rule, applied to HTTP), parse after complete (JSON.parse on the joined buffer — inside try/catch; malformed bodies are 400, not 500), backpressure respected (slow consumers pause — `for await` paces; leaf 2.2 of Domain 03, applied).

- **Why it hurts when missing (security, reliability)**: unbounded body buffering (10 GB "JSON" — OOM before parse; the avatar-attack over HTTP; caps make it a 413). Uncaught parse throws (malformed JSON crashing the handler — 500 on client garbage; try/catch routing 400 — client errors stay client-side). Unconsumed request streams stalling keep-alive (body unread — socket unusable for reuse; always consume or destroy — pooling depends on it, leaf 2.2).
- **Modern guidance** — cap every body (1–10 MB default by endpoint — JSON APIs small; uploads stream to disk, never to memory). Destroy past the cap (`req.destroy()` + 413 — connection freed, attacker paced). Parse in try/catch (400 on failure — client garbage, client status). Always consume (read to end, or destroy — sockets return to the pool only when drained; reuse economics, leaf 2.2).

```javascript
// GOOD: capped, parsed, routed — runs on node v20.20.2 (200 echo, 413 oversize, 400 malformed)
const http = require('node:http');
const CAP = 1024; // 1 KB policy for this endpoint (stated, enforced, tested)
const server = http.createServer((req, res) => {
  let bytes = 0; const chunks = []; let dead = false;
  req.on('data', (c) => { bytes += c.length; if (bytes > CAP && !dead) { dead = true; res.writeHead(413); res.end('too big'); req.destroy(); } else if (!dead) chunks.push(c); });
  req.on('end', () => { if (dead) return; try { const body = JSON.parse(Buffer.concat(chunks).toString() || '{}'); res.end(`echo:${body.n ?? '?'}`); } catch { res.writeHead(400); res.end('bad json'); } });
  req.on('error', () => {});
});
server.listen(0, '127.0.0.1', async () => {
  const port = server.address().port; const post = (b) => new Promise((res) => { const r = http.request({ port, host: '127.0.0.1', path: '/', method: 'POST', agent: false }, (r2) => { let d = ''; r2.on('data', (c) => d += c); r2.on('end', () => res(`${r2.statusCode}:${d}`)); }); r.on('error', () => res('destroyed(as-designed)')); r.end(b); }); // agent:false — fresh socket per demo call (a destroyed pooled socket would hang reuse; pooling belongs to managed agents — leaf 2.2)
  console.log(await post('{"n":7}'), '|', await post('x'.repeat(2000)), '|', await post('{oops')); server.close(); // 200:echo:7 | 413:too big | 400:bad json
});
// BAD: `let body = ''; req.on('data', c => body += c); req.on('end', () => JSON.parse(body))` ("standard snippet") —
// uncapped, uncaught, tutorial-grade: copy-pasted into production, OOMs and 500s included free
```

### 3) **Client: fetch and http compared**

**Definition** — two client shapes: global `fetch` (undici — promise-based, ergonomic; `Response` with `.json()`/`.text()`; streaming via `body` ReadableStream; timeouts via `AbortSignal.timeout(ms)`), and `node:http` request (stream-based, controllable; agents, sockets, and reuse tunables exposed; verbose by design). Fetch for convenience (JSON APIs, one-shots, scripts); `http` for control (pools, keep-alive tuning, socket introspection — leaf 2.2's economics). Both need timeouts (no timeless requests — hanging servers hang timeless clients identically).

- **Why it matters (operations)**: timeless clients accumulate (downstream stall — every request hangs; descriptors pool-side exhausted; the outage mirrored upstream). Unpooled fetch per call (default undici dispatcher pools globally — fine; custom dispatchers unconfigured — redial per request; know your defaults). Verbosity avoidance (choosing fetch to dodge `http` ceremony, then needing socket control — rewrite under pressure; choose by control needs upfront).
- **Modern guidance** — default `fetch` with `AbortSignal.timeout()` (one line each — convenience with a deadline; 5–30 s by dependency SLO). Reach for `node:http` when pooling/socket control matters (agents tuned — leaf 2.2; reuse verified — `reusedSocket`). Never request without a timeout (both shapes — timeless is the incident; deadlines are capacity policy). Consume every response body (drained or cancelled — pooled sockets recycle only when read; `res.resume()`/`body.cancel()` the minimum).

```javascript
// GOOD: fetch with deadline vs http with control — runs on node v20.20.2 (both 200, both timed)
const http = require('node:http');
const server = http.createServer((req, res) => res.end('ok')).listen(0, '127.0.0.1', async () => {
  const base = `http://127.0.0.1:${server.address().port}`;
  const f = await fetch(`${base}/a`, { signal: AbortSignal.timeout(2000) }); // deadline (timeless never)
  console.log('fetch:', f.status, await f.text(), '| http:', await new Promise((res, rej) => { const rq = http.get(base + '/b', { agent: new http.Agent({ keepAlive: true }) }, (rs) => { let b = ''; rs.on('data', (c) => b += c); rs.on('end', () => res(`${rs.statusCode}:${b}`)); }); rq.on('error', rej); rq.setTimeout(2000, () => rq.destroy(new Error('deadline'))); }));
  server.close(); // fetch: 200 ok | http: 200:ok (convenience vs control, both delivered)
});
// BAD: `await fetch(url)` with no signal ("fast endpoint") —
// fast until it isn't: one stall cascades; deadlines are written before incidents, not during
```

### 4) **Common confusion**

- "Bare HTTP is only for learning" — bare HTTP serves real niches (health endpoints, webhooks receivers, proxies — few routes, full control; frameworks add value past ~10 routes or with validation needs). Learn first, choose per shape.
- "`req.url` is the path" — `req.url` is origin-form (path + query — parse with `new URL(url, base)`; pathname routed, search validated; raw string compared — query smuggles variants). Parse, never compare raw.
- "Response `end()` flushes synchronously" — `end()` queues the finale (backpressure applies — large bodies drain asynchronously; `finish` event confirms; close-before-finish truncates). Queued, not sent.
- "Fetch replaces `http` entirely" — fetch covers convenience (undici dispatcher tunable but distinct; socket-level introspection thinner; some proxy/TLS shapes still `http` territory). Overlapping, not superseding.

### 5) **Performance note**

Bare-HTTP costs are parse + syscall per exchange: routing by Map lookup (nanoseconds — frameworks add microseconds of middleware dispatch; bare wins measurably past 10k rps, irrelevantly below). Body caps bound memory per request (cap × concurrency — the capacity equation; uncapped is unbounded by definition). Keep-alive amortizes handshakes (leaf 2.2's economics — reuse verified; bare servers keep alive by default with HTTP/1.1). Timeouts bound tail latency (deadline × budget — hanging downstream can't stretch p99 past policy). Optimize routing simplicity first (Map over middleware towers at high rps), body bounds second (caps as capacity policy), timeouts always (tail latency is policy, not luck).

### 6) **Mentor note**

Teach bare HTTP as framework X-ray ("build one server and one capped echo — now explain what Express adds" until framework features map to bare primitives unprompted). Demo the hang (forgotten branch — request dangles; then 404 arm — closed; branches ended, felt). Demo the cap (2 KB over a 1 KB policy — 413 + destroyed; then uncapped version's RSS climb; limits felt). Drill timeouts ("which requests here have deadlines? — all, proven by signal/timeout lines"). Watch for the framework-first learner (Express before `http` — fix with the bare exercise) and the snippet-copier (uncapped echo — fix with the avatar-attack story). Review check: branches ended, bodies capped, parses guarded, deadlines set, juniors route by hand before reaching for routers.
