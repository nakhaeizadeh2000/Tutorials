## 2.1. TCP sockets with net

### 1) **Sockets are Duplex streams**

**Definition** — `node:net` sockets are Duplex streams (readable + writable — every leaf of Domain 03 applies unchanged: `pipeline` for lifecycle, backpressure by protocol, `destroy()` on failure). Data arrives as Buffers (bytes first — leaf 3.1 of Domain 03; framing before parsing — length-prefixes, not delimiters). The uniform interface pays off here hardest: file pipelines, socket relays, and transform chains share one shape — tested with memory streams, deployed on networks.

- **What problem it solves**: socket-special thinking (custom framing per connection, hand-rolled buffering, bespoke error paths — every TCP feature reinvented per service). Stream-shaped sockets inherit the whole discipline (backpressure pacing fast senders — leaf 2.2 of Domain 03; pipeline teardown on reset — no leaked descriptors; transforms parsing frames — tested without networks). Reinvention replaced by application (same interface, new venue).
- **Modern guidance** — treat sockets as streams first (pipe through transforms — framing, parsing, logging as stages; `for await` for paced consumption). Frame bytes before meaning (length-prefix or fixed header — partial TCP segments buffered across `data` events; never parse a segment as a message). Destroy, don't linger (`socket.destroy()` on protocol violation — half-states cleaned; half-open discipline, point 3).

```javascript
// GOOD: echo over TCP, stream-shaped — runs on node v20.20.2 (round trip, then clean close)
const net = require('node:net');
const server = net.createServer((socket) => { socket.on('data', (chunk) => socket.write(`echo:${chunk}`)); }); // Duplex (read + write, one object)
server.listen(0, '127.0.0.1', () => {
  const client = net.connect(server.address().port, '127.0.0.1', () => client.write('hi'));
  client.on('data', (back) => { console.log('round trip:', back.toString() === 'echo:hi'); client.end(); server.close(); }); // true (framed tiny, parsed whole)
});
// BAD: message-per-`data`-event parsing ("TCP preserves writes") —
// segments split and merge arbitrarily; one write ≠ one event — frame by length, never by arrival
```

### 2) **Servers accept, clients connect**

**Definition** — the two roles: servers `listen()` (bind address + port — `0` for ephemeral in tests; `listen` backlog queues handshakes under burst; `server.maxConnections` caps concurrency), clients `connect()` (dial host + port — errors as `error` events: `ECONNREFUSED` fast-fail, `ETIMEDOUT` slow-fail; retries with backoff — leaf 2.2). Connections are accepted sockets (each its own Duplex — per-connection state scoped, never shared; `server.getConnections()` introspects load). Roles fixed per endpoint; a process often plays both (service mesh reality — listen here, dial there).

- **Why it matters (correctness)**: unscoped connection state (shared parser across sockets — interleaved bytes, cross-talk corruption; per-connection closures or objects — isolation by construction). Uncapped accepts (burst opens 10k sockets — memory per connection × burst = OOM; `maxConnections` + load-shed policy — backpressure at the door). Undialed errors (connect without `error` listener — `ECONNREFUSED` throws; every dial guarded from the first line — leaf 1.1's rule, applied).
- **Modern guidance** — scope state per connection (closure per accepted socket — parsers, buffers, timers die with it). Cap and shed (`maxConnections` set — excess refused fast with a status, never queued to death; refusal is a load signal, queuing is a latency lie). Guard every dial (`error` listener before `connect` returns — refused/timeout routed, never thrown). Test with ephemeral ports (`listen(0)` — no port conflicts, parallel-safe suites).

```javascript
// GOOD: scoped state, capped accepts, guarded dial — runs on node v20.20.2 (2 clients, isolated counts, clean close)
const net = require('node:net');
const server = net.createServer((socket) => { let count = 0; // per-connection state (closure-scoped — no cross-talk)
  socket.on('data', () => { count++; socket.write(`n:${count}`); }); socket.on('error', () => {}); });
server.maxConnections = 100; // cap with policy (refuse fast past capacity — shed, don't queue to death)
server.listen(0, '127.0.0.1', () => {
  const port = server.address().port; let seen = [];
  for (const msg of ['a', 'b']) { const c = net.connect(port, '127.0.0.1'); c.on('error', () => {}); // guarded dial (refused routed)
    c.on('connect', () => c.write(msg)); c.on('data', (d) => { seen.push(d.toString()); c.end(); if (seen.length === 2) { console.log('isolated:', seen.join(',')); server.close(); } }); }
}); // isolated: n:1,n:1 (each connection counted alone — scoping proved)
// BAD: module-level `let buffer = ''` shared across sockets ("simpler state") —
// interleaved segments from two clients parse as one stream; corruption without a single error
```

### 3) **Half-open and idle discipline**

**Definition** — TCP connections end in halves (FIN one direction — `end` event: peer done sending; `allowHalfOpen` false (default) auto-ends our side — full close; true keeps our write side for final replies — then we `end()` explicitly). Idle connections consume (file descriptor + memory each — dead peers holding resources; NAT/firewall timeouts killing silent ones mid-transaction). Discipline: `socket.setTimeout(ms)` (idle timer — `timeout` event → destroy or probe), application heartbeats (protocol-level liveness — timeouts distinguish dead from quiet), destroy on violation (unresponsive past grace — reaped, logged, counted).

- **Why it hurts when missing (operations)**: descriptor exhaustion (dead connections never reaped — thousands of zombies; EMFILE under sustained churn; the outage that follows a network blip). Half-open limbo (`allowHalfOpen: true` without explicit end — write side lingers; resources held for peers long gone). Silent middlebox kills (idle past NAT timeout — first write after silence fails; heartbeats keep mappings alive and detect death fast).
- **Modern guidance** — default `allowHalfOpen: false` (full close unless the protocol needs final replies — simplicity first). Set idle timeouts everywhere (`setTimeout` per socket — value from capacity math: timeout × maxConnections < descriptor budget). Heartbeat past middleboxes (interval < NAT timeout, typically 30–60 s — liveness proved, mappings refreshed). Destroy past grace (timeout → one probe → destroy — reaped with a log line; zombie count graphed, not hoped zero).

```javascript
// GOOD: idle timed, death reaped — runs on node v20.20.2 (timeout fired, socket destroyed, server closed)
const net = require('node:net');
const server = net.createServer((socket) => {
  socket.setTimeout(100); // idle budget (100ms here — capacity math in production)
  socket.on('timeout', () => { console.log('idle past budget — reaping'); socket.destroy(); }); // destroy past grace (logged, counted)
  socket.on('error', () => {}); // destroy surfaces here too (guarded — leaf 1.1)
});
server.listen(0, '127.0.0.1', () => {
  const zombie = net.connect(server.address().port, '127.0.0.1'); // connects, then silence (the zombie shape)
  zombie.on('error', () => {}); zombie.on('close', () => { console.log('zombie reaped'); server.close(); });
});
// BAD: no timeouts ("connections close themselves") —
// dead peers don't send FINs; middleboxes kill silently; descriptors accumulate until EMFILE says otherwise
```

### 4) **Common confusion**

- "TCP is message-oriented" — TCP is a byte stream (no message boundaries — writes split/merge in flight; framing is the application's job, always). Sockets stream; messages frame.
- "`close` means both sides done" — `close` fires after full teardown (half-close states precede it — `end` per direction; `allowHalfOpen` shapes the middle; `close` only announces the end). Halves close, close confirms.
- "More concurrent connections need more threads" — connections need descriptors + state (the loop multiplexes thousands — threads only for blocking work; C10K is an fd budget, not a thread count — leaf 5.1 prices it). Multiplex, don't thread.
- "localhost behaves like the network" — loopback hides failures (no loss, no latency, no middleboxes — timeouts never fire, races never appear; staging needs real-network chaos — latency injection, kill -9 peers). Loopback lies by kindness.

### 5) **Performance note**

Socket costs are per-connection state plus per-byte syscalls: idle connections cost an fd + ~KBs (10k idles ≈ tens of MB — fine; 100k needs tuning — `ulimit`, buffer sizes); throughput costs syscalls per flush (Nagle + delayed ACK interplay — disable Nagle (`noDelay`) for low-latency RPC, keep for bulk; measure tail latency, not averages). TIME_WAIT accumulates on closers (short-lived client bursts exhaust ports — reuse via agents/pools, or `SO_REUSEADDR` where correct). Heartbeats cost bytes per interval (negligible — the cheapest liveness there is). Optimize connection count first (pools, multiplexing — fewer, longer connections), syscall rate second (chunking, `cork`/`uncork` for bulk writes), timeouts always (idle budgets bound the worst case).

### 6) **Mentor note**

Teach sockets as streams in a new venue ("same pipeline, network source — swap the source live" until students frame TCP without prompting). Demo the merge/split (one write arriving as two events, two writes as one — message-orientation dead in one terminal). Demo the zombie (silent client, 100 ms timeout — reaped on schedule; then no-timeout version — lingers; discipline felt). Drill scoping ("two clients, one counter each — where does state live?" — closures, shown). Watch for the messager ("TCP preserves writes" — fix with the split demo) and the timeless ("close themselves" — fix with the zombie count). Review check: state scoped, dials guarded, accepts capped, idles timed, juniors frame before parsing.
