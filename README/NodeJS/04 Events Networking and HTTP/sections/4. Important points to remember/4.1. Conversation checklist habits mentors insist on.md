## 4.1. Conversation checklist (habits mentors insist on)

### 1) **Errors listened, emitters bounded**

**Definition** — the event discipline: every emitter constructed with an `error` listener (leaf 1.1 — no unguarded emitters, ever), listener growth budgeted (`maxListeners` set where fan-out is designed — leaf 1.1's tripwire as documentation), async handler errors captured into the channel (leaf 1.2's wrapper — rejections never escape to the process). Three rules covering notification end to end: subscribed safely, grown deliberately, failed loudly. Violations fail review; compliance prevents the crash-and-leak classes.

- **Why it matters (reliability)**: unguarded emitters crash on routine networks (socket reset — the ordinary made fatal); unbounded growth OOMs on traffic (per-request listeners — linear with load); uncaptured async errors bypass every channel (unhandled rejections — the throw nothing catches). Each is a three-line prevention and a three-hour incident — the cheapest asymmetry in backend work.
- **Modern guidance** — wire `error` in factories (emitter returned already guarded — construction-time, race-free). Budget fan-out with comments (`setMaxListeners(n)` — expected count stated; fifty-first investigated). Wrap async handlers once (shared helper routing to `error` — uniform capture; per-handler classification where it differs). Assert counts in tests (listenerCount after setup — growth encoded, drift red).

```javascript
// GOOD: guarded, budgeted, captured — runs on node v20.20.2 (ordered, routed, bounded)
const { EventEmitter } = require('node:events');
const bus = new EventEmitter(); bus.setMaxListeners(20); // budget stated (fan-out designed, not drifted)
bus.on('error', (e) => console.log('routed:', e.message)); // guarded at construction (race-free)
bus.on('task', async (x) => { try { await new Promise((r) => setTimeout(r, 5)); if (x < 0) throw new Error('bad'); console.log('handled:', x); } catch (e) { bus.emit('error', e); } }); // captured (rejections routed)
bus.emit('task', 1); bus.emit('task', -1); // handled: 1, routed: bad (order: timer vs immediate — both observed)
setTimeout(() => console.log('budget:', bus.getMaxListeners()), 30); // 20 (documented)
// BAD: eyeballing emitter hygiene ("small service, few events") —
// small services grow; unguarded emitters crash at scale; budgets document before growth
```

### 2) **Sockets timed, bodies capped**

**Definition** — the network discipline: every socket carries an idle timeout (leaf 2.1 — `setTimeout` per connection, death reaped past grace), every dial a deadline and retry cap (leaf 2.2 — bounded, jittered, classified), every body a size cap (leaf 3.1 — counted per chunk, destroyed past policy). Timeless dials, uncapped buffers, and immortal idles are the resource-exhaustion trio — each bounded by one number set once. Numbers from capacity math (timeout × maxConnections < descriptors; cap × concurrency < memory), never from optimism.

- **Why it matters (operations)**: timelessness accumulates (partial outages holding descriptors per hanging dial — slow-burn EMFILE; uncapped bodies OOM on attacker sizes — fast-burn kill; immortal idles zombie through every network blip — steady-state exhaustion). All three surface as resource alerts with application-code causes — diagnosed via the numbers that were never set. Set numbers bound the worst case by construction.
- **Modern guidance** — time every socket and dial (values documented beside the code — SLO-derived; `timeout` events logged with cause). Cap every body (per-endpoint policy — JSON small, uploads streamed; 413 + destroy past policy). Reap past grace (timeout → probe → destroy — zombies graphed; zero hoped, counted actual). Review the trio per network call site (timed? capped? reaped? — three questions, every socket).

```javascript
// GOOD: timed, capped, reaped — runs on node v20.20.2 (200 small, 413 oversize, zombie reaped)
const net = require('node:net'); const http = require('node:http');
const server = http.createServer((req, res) => { let bytes = 0; const chunks = []; // cap 64 (tiny policy, huge lesson)
  req.on('data', (c) => { bytes += c.length; if (bytes > 64) { res.writeHead(413); res.end(); req.destroy(); } else chunks.push(c); });
  req.on('end', () => res.end(`got:${bytes}`)); req.on('error', () => {}); });
server.listen(0, '127.0.0.1', async () => {
  const port = server.address().port; const post = (b) => new Promise((res) => { const r = http.request({ port, host: '127.0.0.1', method: 'POST', agent: false }, (r2) => { let d = ''; r2.on('data', (c) => d += c); r2.on('end', () => res(`${r2.statusCode}:${d}`)); }); r.on('error', () => res('reaped')); r.setTimeout(2000); r.end(b); });
  console.log(await post('tiny'), '|', await post('x'.repeat(200))); server.close(); // 200:got:4 | 413: (timed, capped)
});
// BAD: "timeouts later, launch now" (the trio deferred — launch without bounds) —
// later arrives as EMFILE at 3 AM; bounds are launch criteria, not polish
```

### 3) **Bare HTTP first, framework second**

**Definition** — the learning order that prevents framework-magic thinking: one hand-rolled server (leaf 3.1 — routed by hand, bodies capped, deadlines set), one raw socket exchange (leaf 2.1 — framed bytes, scoped state), one emitter lifecycle (leaf 1.1 — subscribed, erred, cleaned). Then frameworks read as automation (routing, parsing, middleware — conveniences with understood costs) rather than platform (necessary magic — feared, misused, misblamed). Mechanics first, magic second, judgment always.

- **Why it matters (maintainability)**: framework-first engineers misattribute (slow route blamed on Express — actually a blocked loop; 404 blamed on the app — actually middleware order; uncapped upload blamed on Node — actually default body parsing). Mechanics-first engineers instrument the layer (reproduce on bare `http` — leaf 1.1 of Domain 01's layer rule; blame with evidence). The order compounds (every future framework learned faster — same primitives underneath).
- **Modern guidance** — build the bare trio once per engineer (server + socket + emitter — onboarding exercise, reviewed). Reproduce framework bugs on bare metal (strip to `node:http` — persists: runtime/app; vanishes: framework config — blame assigned by experiment). Choose frameworks per shape (few routes + control → bare serves fine; validation + middleware towers → Express/Fastify; enterprise modules → NestJS — their tracks decide, mechanics inform).

```javascript
// GOOD: the trio in thirty lines — runs on node v20.20.2 (emitter ordered, socket echoed, HTTP 200)
const { EventEmitter } = require('node:events'); const net = require('node:net'); const http = require('node:http');
const bus = new EventEmitter(); bus.on('error', () => {}); bus.on('ping', (x) => console.log('emitter:', x)); bus.emit('ping', 'ok'); // 1) emitter lifecycle
const tcp = net.createServer((s) => { s.on('data', (c) => s.write(c)); s.on('error', () => {}); }).listen(0, '127.0.0.1', () => { // 2) socket exchange
  const c = net.connect(tcp.address().port, '127.0.0.1', () => c.write('sk')); c.on('error', () => {});
  c.on('data', (d) => { console.log('socket:', d.toString() === 'sk'); c.end(); tcp.close(); // 3) HTTP next (leaf 3.1's shape, same primitives)
    const web = http.createServer((req, res) => res.end('up')).listen(0, '127.0.0.1', () => { http.get(`http://127.0.0.1:${web.address().port}/`, (r) => { console.log('http:', r.statusCode === 200); web.close(); }); }); }); });
// BAD: "skip to Express, bare metal is academic" (mechanics skipped — frameworks memorized) —
// memorized frameworks break mysteriously; understood primitives transfer everywhere
```

### 4) **Common confusion**

- "Checklists slow down shipping" — checklists *accelerate* shipping (five minutes per review versus incident-hours per gap; the trio above runs in CI as lint rules — automated, not ceremonial). Slow is debugging at midnight; fast is gating at noon.
- "Small services don't need socket timeouts" — small services share networks with big failures (one partial outage holds every timeless dial — size doesn't bound hanging; timeouts do). Timeouts scale down freely; hangs don't scale up.
- "Framework defaults cover the trio" — defaults cover the common case (Express times out? parses with limits? — know each default, verify each; frameworks configure, engineers decide). Defaults assumed are gaps deferred.
- "One bare server teaches everything" — one server teaches mechanics (routing, caps, deadlines — the primitives); production teaches operations (metrics, progression, rollouts — [Domain 06](<../../../06 Debugging Configuring and Shipping/README.md>)). Mechanics necessary, not sufficient.

### 5) **Performance note**

Checklist items are performance *enablers*: guarded emitters prevent crash-restart cycles (restarts drop connections — throughput cliffs; prevention free). Timed sockets bound tail latency (deadline × budget — p99 as policy, not luck). Capped bodies bound memory per request (cap × concurrency — capacity plannable). Bare-first understanding optimizes framework choice (right tool per shape — middleware towers avoided where Maps suffice; the overhead that never ships). Total runtime cost: timeout timers (cheap), byte counters (free), listener budgets (free). Total avoided cost: the crash/leak/hang/OOM incidents this domain exists to prevent. Measure avoided classes (unguarded-emitter findings, timeless-dial findings — zero after the gate).

### 6) **Mentor note**

Teach the conversation checklist as pre-flight ("recite guarded-timed-capped before first deploy" — ritual beats reminder; students chant it unprompted). Demo each gap once (unguarded crash, timeless zombie, uncapped OOM — three scars from leaves 1.1–3.1, permanent habits). Drill the bare trio as kata (emitter + socket + server in thirty lines — every onboarding, reviewed). Watch for the eyeballer ("looks handled" — fix with "show me the error listener" — absent) and the framework-first learner ("skip to Express" — fix with the bare exercise). Review check: errors listened, growth budgeted, sockets timed, bodies capped, trio built, juniors reproduce on bare metal before blaming frameworks.
