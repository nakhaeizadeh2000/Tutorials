## 4.1. Packaging checklist (habits mentors insist on)

### 1) **Manifest complete, lockfile committed**

**Definition** — the packaging boot discipline: every repo arrives with a manifest serving all three audiences (humans/npm/Node — leaf 1.1), ranges priced per dependency (leaf 1.2), and a committed lockfile with `npm ci` in pipelines (frozen trees — leaf 1.2). Incomplete arrivals bill everyone downstream (missing `engines` → drift archaeology; missing lock → calendar-dependent builds; missing `exports` → encapsulation by accident). Completeness checked at clone time, not incident time.

- **Why it matters (maintainability)**: packaging gaps compound silently (each gap bills a different team — support answers manifest questions, CI eats unlocked trees, consumers trip on internals — nobody sees the whole invoice). The checklist consolidates the cost (one review pass per repo, five minutes; versus hours scattered across quarters). Packaging is infrastructure-as-documentation — reviewed like infra, read like docs.
- **Modern guidance** — probe the manifest programmatically (the snippet below — asserts audiences, engines, lockfile presence; run in CI as a packaging gate). Fail the gate loudly (missing contract = red pipeline — packaging gaps never ride to production). Re-run per dependency change (lock diffs reviewed beside code diffs — supply-chain awareness per PR, not per incident).

```javascript
// GOOD: packaging gate in ten lines — runs on node v20.20.2 (pass on complete repos, names gaps)
const fs = require('node:fs'); const dir = '/tmp/nodeprobe/repro'; // point at any repo root
const m = require(`${dir}/package.json`); const gaps = [];
if (!m.engines?.node) gaps.push('no engines floor'); // audience npm: runtime contract
if (!m.scripts?.test) gaps.push('no test script'); // audience human: workflow contract
if (!fs.existsSync(`${dir}/package-lock.json`)) gaps.push('lockfile uncommitted'); // reproducibility
console.log(gaps.length ? `PACKAGING GAPS: ${gaps.join(', ')}` : 'packaging complete: manifest + scripts + lock');
process.exitCode = gaps.length ? 1 : 0; // numbered outcome (Domain 01/2.1's rule, applied to packaging)
// BAD: eyeballing package.json in review ("looks fine") —
// eyes skip fields; gates don't: automate the checklist, review the exceptions
```

### 2) **Scripts documented, binaries local**

**Definition** — every repeated workflow is a named script (leaf 2.1's project CLI — onboarding runs `npm run` and learns), every tool binary resolves locally (leaf 2.2's ladder — installed-local default, pinned-exec exception, globals audited). Undocumented workflows live in chat history (unsearchable, unreviewed, bit-rotting); ambient tools live on laptops (unpinned, unshared, undebuggable in CI). The checklist moves both into version control — where review, history, and reproduction already work.

- **Why it matters (operations)**: chat-history operations fail the bus test (the keeper leaves — the deploy incantation leaves with them; the replacement reverse-engineers from CI yaml that drifted). Ambient tools fail the reproducibility test (works on two laptops, red on the third — the global nobody declared). Both failures surface during incidents and onboarding — the two moments with least slack. Named scripts and local bins front-load the answers.
- **Modern guidance** — list scripts in the repo README beside `npm run` (two documentation surfaces agreeing — manifest executable, README explanatory). Ban global-dependent scripts in review ("which version runs on CI?" — unanswerable for globals; answered by lockfiles for locals). Audit the exception list quarterly (globals + unpinned execs — each entry re-justifies or uninstalls; entropy grows the list otherwise).

```bash
# GOOD: workflows named, tools local — verified with npm 10.8.2 (surface self-describes)
npm run --prefix /tmp/nodeprobe/scripts # every workflow named (onboarding reads this, not chat)
npm ls --omit=dev --prefix /tmp/nodeprobe/repro # production tools listed (auditable surface per deploy)
# BAD: "ask Sara how to release" (Sara: on vacation; release: blocked) —
# every workflow Sara knows belongs in scripts; every tool she uses belongs in devDependencies
```

### 3) **Resolution explicit, phantoms banned**

**Definition** — every bare specifier in source is declared in the manifest (leaf 3.1's rule — imported means depended-on), resolutions stay printable (`require.resolve` first diagnostic — never guessed), and layouts stay conventional (new hires navigate on day one). Phantom imports are tech debt with a timer (resolving today via hoist luck, breaking on the parent's next major — the calendar as creditor). Explicit resolution pays the debt at authoring time — the cheapest moment.

- **Why it matters (correctness)**: phantom breakage carries empty diffs (your code unchanged — the parent's upgrade moved the hoist; `git bisect` finds nothing because nothing changed *here*). Implicit resolution slows every debug (where does this load from? — guessed through three terminals instead of printed in one). Conventional layout accelerates every onboarding (one navigation model across repos — cognitive budget spent on the problem, not the paths).
- **Modern guidance** — lint declared-ness (extraneous-dependency rules — phantoms fail CI, not production). Print before guessing (`require.resolve` in the bug report — resolution evidence beside stack traces). Keep `npm ci` as the clean-state ritual (ghosts pruned by construction — never debug a veteran `node_modules`; wipe and freeze). Review imports like deps (new bare specifier = manifest entry in the same PR — atomicity enforced).

```bash
# GOOD: declared-ness checked mechanically — verified with npm 10.8.2
node -e "const m = require('/tmp/nodeprobe/bins/package.json'); console.log('declared deps:', Object.keys(m.dependencies ?? {}).join(', '))" # cowsay (declared — compare phantom leaf 3.1)
npm ls --prefix /tmp/nodeprobe/bins 2>&1 | head -4 # tree printed (what resolves, owned by whom)
# BAD: "it resolves, therefore it's fine" (phantom farmer's motto) —
# resolution is today's weather; declaration is the climate — farm climates, not weather
```

### 4) **Common confusion**

- "Checklists slow down shipping" — checklists *accelerate* shipping (five minutes per repo versus incident-hours per gap; aviation ships daily with longer lists). Slow is debugging drift at midnight; fast is gating at noon.
- "Small projects don't need packaging discipline" — small projects become large ones (every production service was once a script; retrofitting manifests/locks/scripts mid-incident costs 10×). Discipline scales down freely; chaos doesn't scale up.
- "The gate script is over-engineering" — ten lines preventing a whole incident class (unpinned runtimes, missing locks, unnamed workflows — each a past outage somewhere). Gates are the cheapest tests a repo owns.
- "Docs duplicate scripts" — docs *narrate*, scripts *execute* (README explains *why* the release works that way; the script performs it — different jobs, agreeing surfaces). Duplication would be two executables; narration is not duplication.

### 5) **Performance note**

Packaging discipline costs at authoring, pays everywhere else: gates run in milliseconds per CI job (versus incident-hours per drift class — six orders of magnitude); `ci` installs beat re-resolving installs (faster *and* frozen — leaf 1.2); local bins skip fetch latency after first install (versus `npx` re-resolution per CI run — minutes per pipeline per tool); curated `files` shrink every downstream install (seconds × consumers). Total authoring cost: one checklist pass per repo. Total avoided cost: the drift/starvation/supply-chain incidents this whole track exists to prevent. Measure avoided classes (drift incidents/quarter, phantom breakages/quarter — both should read zero).

### 6) **Mentor note**

Teach packaging as pre-flight ("read the gate output aloud before first deploy" — ritual beats reminder; students recite manifest-scripts-lock-resolution unprompted). Demo each gap once (missing engines drift, unlocked Friday-red, phantom breakage — three scars, permanent habits; all demonstrated live in leaves 1.1–3.1). Drill the gate as kata (break a fixture repo three ways — students' gates must name all three gaps). Watch for the eyeballer ("looks fine" — fix with "what does the gate say?") and the minimalist ("fewer fields" — fix with the downstream invoice: every missing field bills someone). Review check: gate green, scripts named, bins local, imports declared, juniors run the handshake before debugging installs.
