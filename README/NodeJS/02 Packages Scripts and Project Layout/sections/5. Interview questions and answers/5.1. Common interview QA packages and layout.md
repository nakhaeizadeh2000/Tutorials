## 5.1. Common interview QA: packages and layout

### 1) **"Where does this import resolve?" — trace the walk**

**Definition** — the resolution screen: candidates narrate the lookup for a specifier from a file location. The tested mechanics: relative joins the importer's dir (extensions per loader — leaf 2.2 of Domain 01); bare climbs `node_modules` upward (first match wins — leaf 3.1); `node:` short-circuits to builtins (never the disk). Tracing aloud reveals the model (levels named, first-match stated) or its absence ("uh, node_modules?"). Interviewers escalate with variants (nested copies, phantom present, `exports`-blocked deep path — each a leaf-3.1 section).

- **What problem it solves**: resolution guessers debug by reinstalling (delete `node_modules`, pray — the ritual replacing the diagnosis; works when the tree was corrupt, wastes hours when the specifier was wrong). Tracers print first (`require.resolve` — one line, verdict rendered; then fix the rule violated, not the whole tree). The whiteboard walk is the production debug in miniature — same levels, smaller stakes.
- **Modern guidance** — narrate by rule order ("relative? no — bare: check sub/node_modules, absent; climb to walk/node_modules, hit `a` — first match wins"). State the tool unprompted ("I'd confirm with `require.resolve` from that directory — print, don't guess"). Name the variant answers too ("nested copy under sub/ would shadow the upper one — nearest wins; `exports`-unlisted subpath throws by design — encapsulation, not error").

```javascript
// GOOD: the trace with a printed verdict — verified on node v20.20.2 (walk fixture from leaf 3.1)
const Module = require('node:module');
const reqFromSub = Module.createRequire('/tmp/nodeprobe/walk/sub/fake.js'); // stand at sub/ (no local node_modules)
console.log(reqFromSub.resolve('a')); // /tmp/nodeprobe/walk/node_modules/a/index.js (climbed one level, first match)
// narration: "bare specifier → skip relative join → sub/node_modules absent → walk/node_modules hit `a` →
//  package.json main → index.js. Nearest wins; I'd print this before touching anything."
// BAD: "it's in node_modules" (the whole answer — which level? which copy? main or exports?) —
// geography without coordinates; the follow-up ("two copies — which loads?") needs the walk, not the word
```

### 2) **`npm ci` vs `npm install`: which in CI?**

**Definition** — the reproducibility judgment: interviewers want the contract difference, not the speed trivia. `npm install` resolves (ranges negotiated, lock rewritten — fluid, for development); `npm ci` reproduces (lock installed exactly, mismatch aborts — frozen, for pipelines). The decision factors: determinism (same tree per commit — `ci`), evolution (new versions tried — `install`, locally, lock diff reviewed), failure mode (mismatch: `ci` red immediately; `install` green approximately). Speed (`ci` often faster — no negotiation) is a side effect interviewers mention to test whether you chase it.

- **Why it matters (correctness)**: fluid CI builds calendar-dependent failures (Monday green, Friday red — empty diff; transitive breakage without direct change — leaf 1.2's core lesson). Frozen CI fails only on real changes (lock edited → tree changes → tests judge the change; mismatch → abort naming the drift). The pipeline is a reproducibility instrument first, a speed instrument second — order preserved.
- **Modern guidance** — answer "`ci`, always in pipelines" then price it ("frozen trees per commit; mismatch aborts name drift; local `install` evolves the lock under review"). Name the exception honestly (lockless legacy repos — `install` until the lock is committed; the migration, not the excuse). Mention evidence kept (tree printed post-`ci` — incidents start from recorded trees). Never lead with speed (fast-but-fluid is the failure mode wearing a perk).

```bash
# GOOD: judgment with receipts — verified with npm 10.8.2 (repro fixture from leaf 1.2)
rm -rf /tmp/nodeprobe/repro/node_modules && npm ci --prefix /tmp/nodeprobe/repro 2>&1 | tail -1 # frozen reinstall (identical tree)
npm ls semver --prefix /tmp/nodeprobe/repro # semver@7.8.5 (frozen, not negotiated)
# spoken close: "ci in pipelines — same tree per commit; install locally to evolve, reviewed per PR"
# BAD: "ci because it's faster" (perk as argument — true, irrelevant, and blind to the contract) —
# speed never reproduces anything; frozen contracts do
```

### 3) **Phantom dependency: find and fix**

**Definition** — the layout debugging trace: a bare import resolves but appears in no manifest (hoisted transitive — leaf 3.1's specter). The find: `npm ls <pkg>` (nested under a parent — borrowed, not owned) plus manifest grep (absent from dependencies — undeclared). The fix: declare it (add to `dependencies` — own what you import) or drop it (refactor to the declared API — stop borrowing). The prevention: extraneous-dependency lint in CI (phantoms fail the pipeline, never production). Three steps, one habit.

- **Why it matters (operations)**: phantom breakage ships empty diffs (parent's major drops the transitive — your build reds with nothing changed; `bisect` innocent; the calendar guilty). Borrowed APIs evade review (undeclared means unreviewed — supply-chain surface nobody approved). The interviewer is really asking "have you debugged an empty-diff red build?" — the three steps prove it.
- **Modern guidance** — demonstrate on the real catch (leaf 3.1's `string-width` — resolves, undeclared, nested under cowsay; the story retold in interviews with paths). Fix by declaring (version chosen deliberately — not whatever hoisted today). Prevent by linting (CI fails phantoms — the class retired, not repeated). Mention ghosts beside phantoms (stale `node_modules` vs fresh `ci` — veteran-laptop green, pipeline red; wipe-and-freeze ritual).

```bash
# GOOD: find and fix, three commands — verified with npm 10.8.2 (bins fixture from leaf 2.2)
node -e "console.log('resolves:', !!require('/tmp/nodeprobe/bins/node_modules/string-width'))" # today: yes
node -p "'declared:' + ('string-width' in (require('/tmp/nodeprobe/bins/package.json').dependencies ?? {}))" # declared: false
npm ls string-width --prefix /tmp/nodeprobe/bins 2>&1 | head -3 # nested under cowsay (borrowed)
# fix: npm install --prefix /tmp/nodeprobe/bins string-width@2 # declare it (owned, locked, reviewed) — or drop the import
# BAD: "pin the parent version" (treating the symptom — hoist shape still owns your import) —
# parents evolve; borrowed APIs break; declaration is the only fix that survives upgrades
```

Rapid-fire drills (one sentence each — mechanism named): "`exports`-unlisted deep import?" — throws `ERR_PACKAGE_PATH_NOT_EXPORTED` (encapsulation working — map it or drop it). "Lockfile in `.gitignore`?" — reproducibility hole (trees negotiate per machine — commit it). "`pretest` deploys?" — lifecycle abuse (hooks bracket their workflow — side quests rejected in review). "Two majors of one lib?" — nested copies (ranges honest — `npm ls` names them; dedupe where ranges allow). "Global vitest in scripts?" — ambient coupling (CI runs a stranger's version — local bare-name instead). "`type` absent?" — CJS interpretation (every `.js` flips meaning — pin it explicitly).

### 4) **Common confusion**

- "Interview packaging answers differ from real ones" — the walk *is* the debug (`require.resolve` in incidents; `ci` in pipelines; `explain` in upgrades — every answer here runs in production weekly). Studying "interview npm" separately doubles work, halves each half.
- "Tracing is slower than reinstalling" — tracing is *targeted* (one print names the violated rule; reinstalling re-rolls the dice — fixes corrupt trees, hides wrong specifiers). Print first, wipe second, only when evidence says wipe.
- "Judgment questions want the popular answer" — judgment questions want *priced* answers (`ci` with frozen-tree pricing beats `ci`-because-faster; declaration with calendar-risk pricing beats "declare everything" as dogma). Interviewers score pricing, not picks.
- "Rapid-fire rewards memorization" — rapid-fire rewards *mechanism compression* (each one-liner derives from the walk, the lock, or the manifest — reciters fail the variant with paths changed). Compress mechanisms, not sentences.

### 5) **Performance note**

Interview packaging answers price real costs: frozen `ci` installs skip negotiation (faster *and* deterministic — the rare free lunch, ordered correctly); declared imports keep trees dedupable (fewer copies — smaller images, faster cold starts); curated `files` shrink every consumer install (seconds × installs — the publish-side performance most candidates never mention); printed resolutions shorten debugs (minutes per incident — diagnosis latency as performance). Candidates connecting each answer to a number (install seconds, image megabytes, incident minutes) signal ownership — the trait senior loops hire for. Mechanisms plus measurements, always.

### 6) **Mentor note**

Teach interview prep as incident prep ("every question here is a 3 AM page in a suit" — map each to its leaf: walk→3.1, locks→1.2, scripts→2.1, bins→2.2, manifest→1.1). Drill traces aloud with variants (change the standing directory, add a nested copy, block via `exports` — derivors adapt, reciters collapse; adapt publicly). Drill the phantom story as narrative (found it, proved it, declared it — beginning, middle, end; interviewers remember stories). Watch for the sloganist ("ci faster", "declare everything" — fix with "priced how?") and the reinstaller (wipe-first debugging — fix with "print first"). Review check: walks narrated by rule, judgments priced, phantoms storied, rapid-fire derived, juniors print before wiping.
