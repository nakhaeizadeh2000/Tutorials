## 2.2. API design for Node services

### 1) **Contracts explicit**

**Definition** — service contracts stated where clients read them: statuses meaningful (2xx success shapes stable; 4xx client errors typed — `code` + `message` + `remedy`; 5xx server errors generic — details logged, never leaked), shapes versioned (`/v1/` prefix or media-type versioning — breaking changes new versions, never edits; additive changes compatible by default), errors documented (every code listed — trigger, meaning, action; OpenAPI or README table — clients code against docs, not vibes). Contracts reviewed like code (breaking-change checklist — version bump required; client impact assessed).

- **What problem it solves**: vibe-based integration (status 200 with error bodies — clients parse success from failure by convention; undocumented codes — consumers discovering via incidents; silent shape changes — fields renamed, clients crash). Each ambiguity bills integrators (support tickets per undocumented code; client breakage per silent change; version archaeology per confusion). Explicit contracts shift integration left (coded, tested, mocked — before deployment).
- **Modern guidance** — type errors uniformly (`{ code, message, remedy, reqId }` — every 4xx; machines route on code, humans read remedy, support joins on reqId). Version in the path for HTTP APIs (`/v1/` — visible, cacheable, greppable; version deprecation dated — sunset headers, not surprises). Document before implementing (contract-first — clients mock while servers build; review the doc, then the code). Never leak internals (stack traces, SQL, paths — logged server-side, generic client-side; information discipline).

```javascript
// GOOD: uniform error envelope, versioned route — runs on node v20.20.2 (typed 404, versioned 200)
const http = require('node:http');
function fail(res, status, code, message, remedy, reqId) { res.writeHead(status, { 'content-type': 'application/json' }); res.end(JSON.stringify({ code, message, remedy, reqId })); } // envelope (machines route, humans remedy)
const server = http.createServer((req, res) => { const url = new URL(req.url, 'http://x'); const reqId = 'r-' + Date.now() % 100000;
  if (url.pathname === '/v1/items' && req.method === 'GET') { res.writeHead(200, { 'content-type': 'application/json' }); res.end(JSON.stringify({ items: [], reqId })); return; } // versioned (v1 — additive only)
  fail(res, 404, 'unknown-route', `no ${req.method} ${url.pathname}`, 'see /v1 docs', reqId); }); // typed (code + remedy — actionable)
server.listen(0, '127.0.0.1', async () => {
  const port = server.address().port; const get = (p) => new Promise((res) => http.get({ port, host: '127.0.0.1', path: p }, (r) => { let b = ''; r.on('data', (c) => b += c); r.on('end', () => res(`${r.statusCode}:${b.slice(0, 60)}`)); }));
  console.log(await get('/v1/items')); console.log(await get('/v9/nope')); server.close(); // 200:{...} | 404:{"code":"unknown-route",...} (contracted)
});
// BAD: `res.end('error: something broke, idk')` with status 200 ("fast iteration") —
// clients parsing prose for failures; speed today, integration debt forever
```

### 2) **Streaming where sized**

**Definition** — large payloads served incrementally: pagination (cursor-based — opaque cursors, stable under inserts; offset avoided past small N — skips degrade, duplicates appear), ranges (HTTP Range — resumable downloads; 206 partial — clients resume, servers seek), SSE/websockets for live (event streams — one direction each; chunked framing — leaf 2.1 of Domain 03's transformsfit). Whole-body APIs capped by policy (JSON under ~1 MB — convenience bounded; above streams or pages — leaf 3.1 of Domain 04's caps, applied to responses). Size decides the shape (request and response alike).

- **Why it matters (performance, correctness)**: whole-list endpoints (10k rows per call — memory × latency × timeout; pagination bounds all three). Offset drift (inserts shifting pages — items skipped/duplicated; cursors stable — position anchored, not counted). Unbounded responses (export endpoints OOMing servers — streamed or paged; size policy per route, not per hope).
- **Modern guidance** — paginate past ~100 items (cursor opaque — position encoded; limit capped — max page stated; total optional — counting is expensive, skip unless needed). Range large downloads (Accept-Ranges — resume supported; 206 tested; clients survive disconnects). Stream live data (SSE for server→client — reconnectable with Last-Event-ID; websockets bidirectional — Domain 04 sockets carry them). Cap whole bodies (policy per route — JSON small; streams/pages large).

```javascript
// GOOD: cursor pagination, bounded pages — runs on node v20.20.2 (page1 next, page2 end, capped)
const DB = Array.from({ length: 250 }, (_, i) => ({ id: i + 1 })); // stand-in store (cursor over sorted ids — stable under inserts)
function page(cursor = 0, limit = 100) { const lim = Math.min(limit, 100); // capped (max page stated — policy, not hope)
  const items = DB.filter((r) => r.id > cursor).slice(0, lim); // cursor-anchored (position, not offset — inserts safe)
  return { items: items.map((r) => r.id), next: items.length === lim ? items[items.length - 1].id : null }; } // next cursor (null ends — client stops)
const p1 = page(0); const p2 = page(p1.next);
console.log('page1:', p1.items.length, 'next:', p1.next, '| page2:', p2.items.length, 'next:', p2.next); // 100 items, next 100 | 100 items, next 200 (cursor-anchored pages)
const p3 = page(p2.next); console.log('page3:', p3.items.length, 'next:', p3.next, '(cursor-stable, bounded, terminal)'); // 50, null (complete — 250 across 3 pages)
// BAD: `GET /all` returning the table ("simple API") —
// simple until 10k rows: memory, latency, timeouts — pagination bounds all three from day one
```

### 3) **Failures name remedies**

**Definition** — every error answers three questions: what (typed code — `rate-limited`, `quota-exceeded`, `stale-version`; stable strings, documented), so what (impact scope — this request only, or session-wide; retry safety — idempotent or not), now what (remedy — `retry-after` seconds, upgrade path, docs link, support channel; actionable, not sympathetic). Retryable flagged explicitly (`retryable: true/false` — clients decide without guessing; 429/503 with Retry-After — protocol-level remedies). Generic 500s carry correlation only (reqId logged server-side — details server-side; clients get the id, not the stack).

- **Why it matters (operations)**: remedy-less errors page humans for machine-fixable states (rate limits retried blindly — fixed intervals hammering; stale versions erroring forever — refresh unmentioned; quota hits surprising — upgrade path unstated). Guessed retries amplify (non-idempotent retried — double charges; retryable unflagged — clients either never retry (lost work) or always retry (thundering)). Actionable errors distribute the fix (clients self-heal documented states; humans handle the rest).
- **Modern guidance** — type every error (stable codes — documented table; codes versioned with the API; renamed never, added freely). Flag retryability (explicit boolean — idempotence declared; Retry-After on 429/503 — protocol remedies honored). Link remedies (docs URLs in dev errors — production terse; runbook per server code — on-call follows links). Correlate everything (reqId per error — support joins client report to server trace in one query).

```javascript
// GOOD: failures with remedies — runs on node v20.20.2 (429+retry, 409+refresh, 500+reqId)
function err(code, message, remedy, retryable, reqId) { return { code, message, remedy, retryable, reqId }; } // envelope (what + so-what + now-what)
console.log(JSON.stringify(err('rate-limited', '100/min exceeded', 'retry after 30s or upgrade plan', true, 'r-1'))); // retryable + remedy (client self-heals)
console.log(JSON.stringify(err('stale-version', 'resource changed (v3 vs v7)', 'GET latest, rebase, retry once', true, 'r-2'))); // conflict actionable (refresh named)
console.log(JSON.stringify(err('internal', 'unexpected failure', 'contact support with reqId', false, 'r-3'))); // generic + correlated (details server-side — reqId joins)
// client rule: retryable → backoff+jitter (leaf 2.2 of Domain 04); else → surface remedy (humans handle the rest)
// BAD: `{ "error": "oops" }` status 500 ("don't leak internals") —
// secrecy without correlation: clients can't act, support can't join — opaque to all, useful to none
```

### 4) **Common confusion**

- "REST purity matters most" — usability beats purity (consistent envelopes + versioning + remedies — clients integrate; hypermedia debates entertain; shippable contracts serve). Pragmatic over pure.
- "Versioning is premature" — unversioned is *breaking by default* (first shape change breaks clients — v1 costs one prefix; migration costs quarters; version from the first external client). Prefix early, migrate never.
- "Streaming complicates clients" — unbounded complicates *servers* (OOM, timeouts, retries — pagination/ranges are client-simple with good docs; whole-body is server-dangerous). Bound server risk first.
- "Error details help debugging" — details help *attackers* (stacks map internals; paths name systems; SQL reveals schema; correlate by reqId — details server-side). Debug with ids, not exposures.

### 5) **Performance note**

API design costs are integration + operation, priced per client: envelopes add bytes (negligible — gzip compresses structure; parse once per response). Pagination adds round trips (bounded pages — total latency linear in pages; whole-list faster once, fatal at scale; prefetch + parallel pages where measured). Versioning costs routing branches (Map lookup — nanoseconds; old versions retired on schedule — sunset, not support-forever). Remedies save incidents (self-healing clients — support load down; retry storms prevented by flags + backoff). Optimize payload shape first (pages/ranges — bounded memory and latency), version hygiene second (sunset old — branches pruned), remedy quality always (actionable errors — support load down).

### 6) **Mentor note**

Teach contracts as empathy ("integrate your own API blind — where do you stumble?" until undocumented codes *feel* hostile). Demo pagination drift (offset under inserts — skipped rows observed; then cursor — stable; shapes felt). Drill remedies ("this error at 3 AM — what does the client do?" per code — actionable or reworded). Watch for the purist ("REST says" — fix with "clients say" — usability wins) and the exposer (stacks to clients — fix with "who benefits? — attackers"). Review check: envelopes uniform, versions prefixed, pages cursored, remedies actionable, juniors document before implementing.
