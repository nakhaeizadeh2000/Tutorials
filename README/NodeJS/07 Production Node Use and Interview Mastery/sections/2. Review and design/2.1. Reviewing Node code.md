## 2.1. Reviewing Node code

### 1) **Gates before taste**

**Definition** — review order: mechanical gates first (sync-in-handler, bare `.pipe(`, uncapped bodies, unguarded emitters, `process.exit(` outside main, `setMaxListeners(0)` — grep-able, indisputable), numbers second (pool sizes, caps, timeouts — priced?), failure paths third (errors routed, drains sequenced — approved?), taste last (naming, shape, comments — discussed, never blocking). Gates automate (CI lint rules — findings fail builds; humans never re-check machines' work). Taste debates never block gates passing (approval order explicit — defects over preferences).

- **What problem it solves**: taste-first reviews (naming debates while `process.exit()` sits in a helper — priorities inverted; nits blocking while drains unimplemented — review theater). Ungated merges (mechanical defects reviewed by tired eyes — missed consistently; machines consistent, humans judgmental — each doing their job). Gate-less culture (same defects recurring — review comments repeated per PR; encoded once, enforced forever).
- **Modern guidance** — encode gates as lint/CI (no-sync-in-handlers, no-bare-pipe, no-unbounded-read, no-global-exit — custom rules where plugins lack; findings red, not advisory). Review numbers per PR (new constants challenged — derivation or revision; magic numbers named or removed). Taste last and lightly (suggest, don't block — style guides automate the rest; human taste reserved for API shapes and names).

```javascript
// GOOD: mechanical gate as code — runs on node v20.20.2 (2 findings in dirty, 0 in clean)
const fs = require('node:fs');
const GATES = [[/\.pipe\(/, 'bare .pipe (use pipeline)'], [/process\.exit\(/, 'process.exit outside main (set exitCode)'], [/setMaxListeners\(0\)/, 'tripwire muted (budget instead)']]; // machines' work (encoded once)
function gate(src) { return GATES.flatMap(([re, why]) => re.test(src) ? [why] : []); } // findings (indisputable — patterns, not opinions)
fs.writeFileSync('/tmp/nodeprobe/dirty.cjs', 'src.pipe(dst); process.exit(1);'); fs.writeFileSync('/tmp/nodeprobe/clean.cjs', 'await pipeline(src, dst); process.exitCode = 1;');
console.log('dirty:', gate(fs.readFileSync('/tmp/nodeprobe/dirty.cjs', 'utf8')).length, '| clean:', gate(fs.readFileSync('/tmp/nodeprobe/clean.cjs', 'utf8')).length); // 2 | 0 (gates decide before humans opine)
// BAD: "LGTM, just rename x to y" on a PR with uncapped readFile on uploads ("taste reviewed") —
// renamed variables, shipped OOM; gates first — taste never outranks defects
```

### 2) **Ask for the numbers**

**Definition** — every constant interrogated: pool sizes (cores counted? — `availableParallelism` cited), caps (bytes derived? — endpoint policy stated), timeouts (SLO-derived? — budget fraction named), retries (bounded? jittered? classified? — policy quoted), headroom (explicit? — cliffs avoided). Unpriced numbers challenged (magic constants returned with "derive or remove"; folklore values replaced with measurements). Numbers are design decisions wearing digits (reviewed as decisions — trade-offs stated, alternatives priced).

- **Why it matters (correctness, capacity)**: magic-number drift (timeout 5000 copied across services — suitable nowhere in particular; caps from other teams' incidents — cargo-culted protection). Unbudgeted concurrency (maxSockets 1000 on 2-core boxes — oversubscription by copy-paste; sized per capacity math — leaf 1.2). Unpriced retries (3 attempts, why 3? — unbounded-ish hope; bounded by elapsed budget with jitter rationale — policy, not preference).
- **Modern guidance** — comment derivations beside constants (`timeoutMs: 800 // p99 budget 2s × 0.4 dependency share` — math inline; reviewers verify arithmetic, not authority). Challenge new numbers ("measured where?" — staging numbers or it revises; blog numbers never accepted raw). Re-audit per scaling event (constants expire with traffic — review dates on capacity-sensitive values; yesterday's right, today's guess).

```javascript
// GOOD: numbers derived, derivations inline — runs on node v20.20.2 (arithmetic shown, verdicts stated)
const P99_BUDGET = 2000, DEP_SHARE = 0.4, CORES = 6; // inputs (SLO, architecture, capacity — each sourced)
const depTimeoutMs = Math.floor(P99_BUDGET * DEP_SHARE); // 800 (SLO-derived — budget fraction named)
const poolSize = Math.max(1, CORES - 1); // 5 (cores counted — loop reserved)
console.log(`timeout: ${depTimeoutMs}ms (SLO-derived) | pool: ${poolSize} (core-counted) | headroom: explicit (leaf 1.2)`); // priced (challenged with arithmetic, not authority)
// review question per constant: "measured where?" — staging numbers attached, or the number revises
// BAD: `timeout: 5000, retries: 3, pool: 10` ("sane defaults") —
// sane where? measured when? Sane is unpriced; unpriced is challenged
```

### 3) **Approve the failure paths**

**Definition** — review completes only when failures reviewed: errors routed (every emitter guarded — leaf 1.1 of Domain 04; async captured — leaf 1.2), drains sequenced (SIGTERM → close → flush → exit — leaf 3.1 of Domain 06; tested under load), rollouts asserted (ready-first — zero-drop counted; leaf 5.1 of Domain 06), rollbacks planned (previous version runnable — migration compatibility; revert path tested, not theorized). Happy paths necessary, insufficient (features demoed; failures approved — the review's actual job).

- **Why it matters (reliability)**: happy-path merges (features green, failures unhandled — first incident discovers every gap simultaneously; review approved the demo, production grades the gaps). Untested rollbacks (forward fix assumed — migration incompatible backward; revert impossible mid-incident; rollback planned like rollout). Drain-less approvals (sequence unreviewed — first SIGTERM severs; drains read like code, tested like features).
- **Modern guidance** — require failure tests (error injection per PR touching I/O — kill mid-request, assert routing; drain test per service — SIGTERM under load, zero drops). Read the unhappy diff first (error branches reviewed before features — defects live there; happy paths skimmed after). Plan rollbacks explicitly (backward-compatible migrations — expand/contract; revert rehearsed — rollback tested, not hoped). Approve drains like features (sequence read line by line — close/drain/flush/exit; budget sized; test green).

```javascript
// GOOD: failure path as the reviewed artifact — runs on node v20.20.2 (routed, drained, numbered)
const { EventEmitter } = require('node:events');
const bus = new EventEmitter(); const record = [];
bus.on('error', (e) => record.push(`routed:${e.message}`)); // failure branch (reviewed FIRST — defects live here)
bus.on('task', async () => { try { await new Promise((_, rej) => setTimeout(() => rej(new Error('dep down')), 10)); } catch (e) { bus.emit('error', e); } }); // captured (async routed — leaf 1.2 of Domain 04)
bus.emit('task', 1);
setTimeout(() => console.log(record.join(' | ') === 'routed:dep down' ? 'failure approved (routed, named, testable)' : 'MISSING (review blocks)'), 50); // verdict (failure paths approved, not assumed)
// BAD: approving the feature diff while error branches read "TODO: handle errors" ("ship it, fix forward") —
// TODOs in failure paths are incidents scheduled; forward fixes follow post-mortems
```

### 4) **Common confusion**

- "Review thoroughness means slowness" — thoroughness means *order* (gates automated — humans judge numbers and failures; taste light; ordered reviews complete faster than wandering ones). Slow is re-reviewing; ordered is once.
- "Small PRs don't need failure review" — small PRs need it *most* (one-line changes sever drains — `process.exit` added innocently; size doesn't bound blast radius). Every PR: gates, numbers, failures.
- "Automated gates replace reviewers" — gates replace *checking* (reviewers judge — trade-offs, shapes, names; machines pattern-match, humans weigh). Checking automated; judgment human.
- "Approving fast is kind" — approving *well* is kind (fast rubber-stamps ship on-call burden to teammates; kind reviews protect juniors' sleep; velocity measured per quarter, not per PR). Kind is thorough.

### 5) **Performance note**

Review costs are attention, priced per PR: gates free (CI seconds — machines' work; human re-checking wasted). Numbers minutes (arithmetic verified — cheapest capacity planning there is). Failure paths tens of minutes (unhappy diffs read carefully — incident-hours prevented per catch). Taste unbounded unless timeboxed (style debates capped — guides automate; bikeshedding taxed). Optimize gate coverage first (encoded defects never re-reviewed — attention freed), number challenges second (capacity verified per PR — fleets right-sized), failure approval always (incidents prevented — the expensive direction avoided).

### 6) **Mentor note**

Teach review as gates-numbers-failures-taste ("recite the order per PR" until taste-first *feels* inverted). Demo the gate (dirty vs clean fixtures — 2 vs 0 live; encoded once, enforced forever). Drill number challenges ("measured where?" per constant — derivations demanded kindly, revisions accepted gracefully). Drill failure-first reading (unhappy diff before features — defects found, juniors learn where bugs live). Watch for the nitpicker (taste blocking — fix with "gates pass? numbers priced? failures approved? — then taste suggests") and the rubber-stamp ("LGTM" in minutes — fix with "narrate the failure paths" — silence follows). Review check: gates green, numbers priced, failures approved, taste light, juniors' PRs teach as much as seniors'.
