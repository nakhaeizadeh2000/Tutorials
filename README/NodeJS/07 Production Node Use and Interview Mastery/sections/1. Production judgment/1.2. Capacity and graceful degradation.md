## 1.2. Capacity and graceful degradation

### 1) **Capacity from numbers**

**Definition** — capacity planning as arithmetic: Little's law (concurrent = rps × latency-seconds — the load the system holds at once), memory per unit (bytes per connection × concurrent — the floor; plus headroom), descriptors per unit (sockets + files × concurrent — under `ulimit`), cores from CPU budgets (leaf 1.1's procedure — per-request ms × rps ÷ 1000). Each number measured or ranged (p99 latency, peak rps with growth factor, per-conn state weighed). Headroom explicit (30–50% — bursts absorbed; 100% utilization is a cliff, not a goal).

- **What problem it solves**: hope-sized fleets (instances guessed — saturated at launch or idle at 5%; both billed). Cliff operations (100% target utilization — bursts queue, queues time out, timeouts retry, retries thunder; headroom converts cliffs to slopes). Unweighed state (per-connection memory unknown — OOM at scale events; weighed once, budgeted forever). Arithmetic replaces adjectives (tens of cores, not "enough").
- **Modern guidance** — compute Little's law per endpoint (heaviest first — capacity set by the worst route, not the average). Weigh per-unit state (measure connection memory — real numbers; multiply by concurrent; add headroom). Load-test to validate (staging at 2× expected — numbers confirmed; cliffs found in fixtures, not launches). Recompute per order of magnitude (traffic ×10 re-runs everything — verdicts expire).

```javascript
// GOOD: capacity derived, headroom explicit — runs on node v20.20.2 (numbers, not adjectives)
function capacity({ rps, p99ms, memPerConnKB, cores }) {
  const concurrent = Math.ceil((rps * p99ms) / 1000); // Little's law (load held at once)
  const memMB = Math.ceil((concurrent * memPerConnKB) / 1024); // memory floor (per-unit weighed)
  const withHeadroom = { concurrent: Math.ceil(concurrent * 1.5), memMB: Math.ceil(memMB * 1.5) }; // 50% headroom (bursts absorbed — cliffs avoided)
  return { ...withHeadroom, workers: Math.min(cores, Math.ceil(concurrent / 500)) }; // workers sized (500 conns each — policy, stated)
}
console.log(JSON.stringify(capacity({ rps: 2000, p99ms: 120, memPerConnKB: 64, cores: 8 }))); // {"concurrent":360,"memMB":23,"workers":1} — wait, 240×1.5=360 concurrent, 15.36→23MB, workers ceil(360/500)=1 (fan-out light, CPU decides separately)
// narration: "240 concurrent held, 360 budgeted, 23 MB floored — headroom converts cliffs to slopes"
// BAD: "8 cores should handle it" (cores without concurrency math — memory/descriptors unbudgeted; should handles nothing) —
// arithmetic or anecdote; capacity is computed, never felt
```

### 2) **Degrade by layers**

**Definition** — graceful degradation as ordered shedding: timeouts first (slow dependencies cut — bounded waits; budgets from SLOs), caches second (stale served — TTLs extended under duress; stale beats absent), features third (non-critical disabled — flags flipped; core flows protected), static last (pre-rendered fallbacks — always servable; the floor never fails). Each layer declared in advance (degradation policy reviewed — not improvised at 3 AM). Worse service beats failed service (partial answers retain users; errors retain nobody).

- **Why it matters (operations)**: cliff failures (all-or-nothing under load — 500s for everyone when the recommender lags; degraded recommendations would have served all). Cascading retries (slow dependency — callers wait, callers' callers wait; timeouts break the chain; missing timeouts transmit the outage upward). Improvised shedding (on-call disabling features blindly — untested paths, broken invariants; rehearsed degradation sheds safely).
- **Modern guidance** — order the layers in advance (timeouts → stale cache → features off → static — policy document, reviewed). Timeout every dependency (budgets from SLOs — slow cut, never waited out; leaf 2.2 of Domain 04's discipline, applied). Cache for degradation (stale-while-revalidate — availability through staleness; TTLs sized by freshness needs). Flag features for shedding (kill switches tested — flipped in game days, not discovered in incidents). Serve static at the floor (health + status pages independent — the minimum that never fails).

```javascript
// GOOD: layered degradation as code shape — runs on node v20.20.2 (fresh → stale → static, never error)
async function degradedFetch({ fresh, staleCache, timedOut }) {
  if (!timedOut) return { tier: 'fresh', data: fresh }; // layer 0: full service (budgets met)
  if (staleCache) return { tier: 'stale', data: staleCache, note: 'TTL extended under duress' }; // layer 1: stale beats absent
  return { tier: 'static', data: 'fallback-content' }; // layer 2: floor (pre-rendered — never fails)
}
console.log(JSON.stringify(await degradedFetch({ fresh: null, staleCache: 'cached-v1', timedOut: true }))); // {"tier":"stale",...} (degraded, serving — not 500)
console.log(JSON.stringify(await degradedFetch({ fresh: null, staleCache: null, timedOut: true }))); // {"tier":"static",...} (floor holds — never 500)
// BAD: dependency timeout → 500 for everyone ("honest errors") —
// honest and useless: partial answers retain users; 500s retain nobody — degrade, don't confess
```

### 3) **Limits everywhere, discovers nowhere**

**Definition** — every resource bounded by policy: request caps (body sizes — leaf 3.1 of Domain 04; concurrency per route — queue + shed), pool caps (workers, sockets, DB connections — sized to cores/budgets; queues visible), time caps (timeouts per dependency — SLO-derived; budgets terminating), memory caps (container limits — OOM policy explicit; heap flags sized). Unbounded resources are incidents scheduled (discovered at peak — the worst venue). Limits designed (reviewed numbers), never discovered (post-mortem surprises).

- **Why it matters (reliability)**: unbounded queues (traffic spikes queue infinitely — latency explodes before errors; capped queues shed fast with 503 + Retry-After — clients back off, systems survive). Uncapped concurrency (burst × per-request cost — memory cliff; limits convert cliffs to signals). Limitless time (one slow dependency holding all slots — timeouts bound the blast; missing timeouts transmit). Designed limits fail gracefully (503s with reasons — operators read policy; discovered limits fail mysteriously.
- **Modern guidance** — cap requests, pools, time, memory (four categories — each with a number, each reviewed; unlisted resources audited quarterly). Shed with signals (503 + Retry-After — clients cooperate; silent drops provoke retries). Alarm on approach (80% of any cap — warning before shedding; caps monitored, not just enforced). Document every limit (config comments with derivation — numbers traceable to math, not mood).

```javascript
// GOOD: limits listed, derivation shown — runs on node v20.20.2 (policy as data, reviewed like code)
const LIMITS = { bodyBytes: 1_048_576, concurrency: 360, depTimeoutMs: 800, heapMB: 512 }; // every resource (numbers with reasons — see below)
console.log('limits:', JSON.stringify(LIMITS), '(body: upload policy; concurrency: Little+headroom; timeout: SLO-derived; heap: container-sized)');
// derivation: body ← endpoint policy; concurrency ← leaf arithmetic above; timeout ← p99 budget fraction; heap ← container minus headroom
// audit: Object.keys(LIMITS) covers requests/pools/time/memory (four categories — quarterly review asks "what's missing?")
// BAD: limits discovered in post-mortems ("we didn't know uploads were unbounded") —
// unknown unknowns become known policy: audit quarterly, cap explicitly, alarm at 80%
```

### 4) **Common confusion**

- "Headroom is waste" — headroom is *insurance* (bursts absorbed — cliffs avoided; 50% idle at rest, 0% dropped at peak; utilization optimized against bills, headroom against incidents). Waste idles; insurance absorbs.
- "Degradation means failure" — degradation means *service* (stale answers serve — 500s don't; tiers declared — users informed; graceful worse beats failed best). Failed is binary; degraded is continuous.
- "Limits reject legitimate traffic" — limits *protect* legitimate traffic (shed excess with signals — admitted requests succeed; unlimited systems fail everyone equally). Signals cooperate; cliffs don't.
- "Capacity planning is waterfall" — planning is *arithmetic* (recomputed per magnitude — agile in cadence, rigorous in method; unplanned is not agile, it's hopeful). Cadence flexible, math fixed.

### 5) **Performance note**

Capacity work costs arithmetic + load tests, priced per scaling event: Little's law free (ten lines — recomputed per endpoint; cheapest planning there is). Load tests cost staging time (2× traffic rehearsals — cliffs found in fixtures; cheaper than launch-day discovery). Headroom costs idle spend (30–50% — insurance premium; optimized against bills quarterly). Degradation layers cost fallback maintenance (stale paths tested — game days exercise; untested fallbacks fail when needed). Optimize arithmetic accuracy first (measured inputs — wrong numbers, wrong fleet), headroom second (bursts absorbed — cliffs avoided), fallback testing always (degraded paths proven — not hoped).

### 6) **Mentor note**

Teach capacity as arithmetic ("Little's law on the whiteboard before any instance type" until guessed fleets *sound* negligent). Demo the cliff (unbounded queue under burst — latency explodes; then capped with shed — signals flow; limits felt). Drill degradation order ("timeouts, stale, features, static — recite" — layers declared, not improvised). Watch for the guesser ("should handle it" — fix with "show the math") and the perfectionist (degrade nothing, fail wholly — fix with "stale or 500? — choose"). Review check: numbers derived, headroom explicit, layers ordered, limits listed, juniors compute before provisioning.
