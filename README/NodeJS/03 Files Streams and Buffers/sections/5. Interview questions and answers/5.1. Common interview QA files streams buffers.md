## 5.1. Common interview QA: files, streams, buffers

### 1) **"10 GB file, 512 MB RAM" — design it**

**Definition** — the streaming screen: candidates design a transform over an input that never fits memory. The expected shape: `createReadStream` source (chunked — constant memory), `pipeline` with a streaming transform (line-splitter or record parser — state only for the partial frame), `createWriteStream` sink (flushed incrementally), byte counts reconciled at the end (input size vs output records — completeness proved, not assumed). Numbers named throughout (chunk sizes, memory ceiling, throughput estimate). The interviewer listens for "never whole" in the first sentence.

- **What problem it solves**: whole-read instincts (the candidate reaching for `readFile` on 10 GB — 20× RAM; the design dead on arrival). Streaming design is production design (log processors, ETL jobs, backup tools — all constant-memory or all incidents). The interview answer and the implementation share a shape (`pipeline` with counted bytes — whiteboard today, ship tomorrow). Designing under constraint is the job; RAM is the constraint.
- **Modern guidance** — lead with the memory contract ("constant ~100 MB — chunks in flight only, never the file"). Name the stages (source → split → parse → sink — each bounded, each testable). Reconcile at the end (bytes in vs records out — the completeness proof interviewers grade). State the failure handling (midstream error destroys all — partial outputs renamed only on success; atomic-rename discipline).

```javascript
// GOOD: constant-memory transform at small scale, same shape at 10 GB — runs on node v20.20.2
import { pipeline } from 'node:stream/promises'; import { Transform } from 'node:stream';
import { createReadStream, createWriteStream } from 'node:fs'; import { writeFile } from 'node:fs/promises';
await writeFile('/tmp/nodeprobe/big.txt', 'row\n'.repeat(200000)); // ~800 KB stand-in (shape scales, size doesn't matter)
let lines = 0, tail = ''; const counter = new Transform({ transform(c, _e, cb) { const parts = (tail + c.toString()).split('\n'); tail = parts.pop(); lines += parts.length; cb(); }, flush(cb) { if (tail) lines++; cb(); } });
await pipeline(createReadStream('/tmp/nodeprobe/big.txt'), counter, createWriteStream('/tmp/nodeprobe/big.out'));
console.log('streamed lines:', lines, '(memory flat — chunks only, file never whole)'); // 200000 (reconciled)
// narration: "10 GB identical — same pipeline, larger chunks, same ~100 MB ceiling; rename .out on success only"
// BAD: "read it, split it, map it" (the whole-read reflex — 10 GB into a 512 MB box) —
// correct for kilobytes, fatal at scale; sizing the input precedes choosing the API
```

### 2) **Backpressure: what breaks without it?**

**Definition** — the memory judgment: candidates price the violated protocol. Without backpressure, producer speed × incident duration = queued bytes (fast disk at 500 MB/s against a 50 MB/s socket — 450 MB/s accumulating; minutes to OOM). Symptoms named (RSS climbing linearly — the graph; GC thrashing — the latency; OOM kill — the end). The fix stated per code shape (`pipeline`/`for await` — automatic; manual loops — check returns, await `drain`). The interviewer is really asking "have you watched memory die, and did you learn the protocol?"

- **Why it matters (operations)**: unpressured flows fail steadily, not spikily (no traffic spike needed — sustained ratio mismatch suffices; the 3 AM kill on an ordinary Tuesday). Misdiagnosis wastes the fix window ("memory leak" hunted in application code — actually protocol skipped in I/O glue; heap dumps innocent, `data→write` loop guilty). The judgment answer routes correctly (protocol first, profiler second).
- **Modern guidance** — answer with the equation (queued = (producer − consumer) × time — arithmetic, not adjectives). Name the observation (RSS slope per speed ratio — the graph that proves it). State the fix by shape (pipelined: free; manual: returns + drain — leaf 2.2's three lines). Mention the test (mismatched-speed fixture — fast source, delayed sink, flat-memory assert; the test that retires the class).

```javascript
// GOOD: the equation made visible — runs on node v20.20.2 (queued 640 vs 64 — ratio observed, not theorized)
import { Writable } from 'node:stream';
const sink = new Writable({ highWaterMark: 64, write(_c, _e, cb) { setTimeout(cb, 20); } }); // slow consumer (20ms/chunk)
let queued = 0; for (let i = 0; i < 10; i++) { if (sink.write(Buffer.alloc(64))) queued += 0; else queued += 64; } // 10 fast writes (returns tell the story)
console.log('unpaced queue bytes:', queued, '(protocol ignored — memory grows per write)');
console.log('fix: await drain per false (leaf 2.2) — queue bounded at the mark, ratio irrelevant');
// spoken close: "queued equals speed gap times time — honor the returns, memory goes flat"
// BAD: "add more RAM" (treating the symptom — ratios compound: 10× traffic needs 10× RAM, forever) —
// capacity follows protocol compliance; protocol first, DIMMs never
```

### 3) **`readFile` vs stream vs sync: which and when?**

**Definition** — the API-selection trace: candidates route three scenarios to three APIs with reasons. Small known config (`readFile` — whole, convenient, bounded). Large or untrusted input (stream via `pipeline` — constant memory, backpressure honored). Boot-only one-shot (sync — no loop exists yet, bounded, commented). Each answer priced (memory, loop impact, failure shape). The trace reveals the size rule internalized (leaf 1.1) or memorized (recited thresholds, no reasoning).

- **Why it matters (liveness)**: misrouted APIs fail at scale boundaries (sync in handlers — loop serialized; whole-reads on uploads — OOM on attacker sizes; streams for 2 KB configs — ceremony without benefit, errors harder to read). Selection is architecture at small scale (every I/O call site answers it; wrong answers accumulate into incident surface). Interviewers score the routing logic, not the API trivia.
- **Modern guidance** — route by size and context ("known-small → readFile; unknown/large → pipeline; pre-loop → sync with comment" — the decision tree in one breath). State the loop impact per choice (sync blocks everyone — priced; async frees — default; streams pace — bounded). Name the failure of each misuse (sync stall, whole-read OOM, stream ceremony — one consequence per wrong turn).

```javascript
// GOOD: the decision tree as code — runs on node v20.20.2 (small whole, large piped, boot synced)
import { readFile, stat } from 'node:fs/promises'; import { readFileSync } from 'node:fs';
import { pipeline } from 'node:stream/promises'; import { createReadStream, createWriteStream } from 'node:fs';
async function load(p, limit = 10 * 1024 * 1024) { // the tree (size + context decide)
  const { size } = await stat(p); // metadata first (leaf 1.2)
  if (size > limit) { await pipeline(createReadStream(p), createWriteStream(p + '.bak')); return 'streamed (large)'; }
  return `whole-read (${size} bytes)`; // small: convenience justified
}
console.log(await load('/tmp/nodeprobe/hello.txt')); // whole-read (12 bytes)
console.log('boot config:', readFileSync('/tmp/nodeprobe/hello.txt', 'utf8').length > 0 ? 'sync justified (pre-loop, bounded, commented)' : 'empty');
// BAD: one API for everything ("consistency" — readFile for uploads, sync in handlers, streams for configs) —
// consistency of spelling, chaos of consequences; route per input, not per habit
```

Rapid-fire drills (one sentence each — mechanism named): "`wx` second writer?" — `EEXIST` (kernel exclusivity — no race window). "Missing file read?" — `ENOENT` rejection (routed as expected input, not crashed). "`toString()` on protocol bytes?" — lossy view (mojibake checksums — hash bytes, not views). "`data` listener added?" — flowing mode (unpausable push — `for await` for paced). "`pipeline` middle throws?" — all stages destroyed (one catch — descriptors freed). "Trailing bytes after frames?" — carried, never parsed (partial frames buffer — desync refused). "Sync at boot?" — allowed, bounded, commented (no loop exists — the only amnesty).

### 4) **Common confusion**

- "Interview streaming answers differ from real ones" — the pipeline *is* the implementation (whiteboard `pipeline` becomes shipped `pipeline` — same stages, same counts; designing "for the interview" separately doubles work). Answer in shippable shapes.
- "Bigger chunks always win" — chunks trade syscalls for burst memory (larger: fewer calls, bigger bursts; the optimum measured per workload — defaults sane, tuning evidenced). Throughput curves, not slogans.
- "Backpressure questions want the definition" — they want the *equation* (queued bytes as arithmetic — definitions recited, equations applied; follow-ups change the numbers, not the concept). Price it, don't prose it.
- "API-selection has one right answer per scenario" — selection has *priced* answers (streams for 2 KB defensible with a reason — ceremony cost named; readFile for uploads indefensible — OOM unnamed). Interviewers score pricing, not picks.

### 5) **Performance note**

Interview data-path answers price real costs: constant-memory streaming removes the RAM ceiling (10 GB on 512 MB — the headline number); backpressure compliance flattens RSS under any ratio (memory performance as protocol compliance); inline hashing verifies at streaming speed (no re-reads — correctness free); chunk sizing tunes throughput per workload (measured curves — the senior follow-up). Candidates connecting each answer to a number (bytes reconciled, RSS flat, hash prefix quoted) signal production ownership — the trait senior loops hire for. Mechanisms plus measurements, always.

### 6) **Mentor note**

Teach interview prep as incident prep ("every question here is a 3 AM page in a suit" — map each to its leaf: sizes→1.1, paths→1.2, pipelines→2.1, pressure→2.2, bytes→3.1). Drill the 10 GB design aloud with variants (binary frames instead of lines — length-prefix; gzipped input — gunzip stage; 100 MB RAM instead of 512 — smaller chunks, same shape; derivors adapt, reciters collapse). Drill the equation, not the definition ("450 MB/s gap, 10 minutes — how much queued?" — arithmetic under pressure). Watch for the whole-reader ("read it first" — fix with the RAM math: 10 GB vs 512 MB, divide aloud) and the RAM-buyer ("more memory" — fix with the ratio question: "10× traffic tomorrow?"). Review check: sizes routed, pipelines reconciled, pressure priced, bytes carried, juniors stream before reading.
