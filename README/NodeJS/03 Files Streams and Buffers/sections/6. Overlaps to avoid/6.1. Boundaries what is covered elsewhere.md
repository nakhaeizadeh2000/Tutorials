## 6.1. Boundaries: what is covered elsewhere

### 1) **Execution and packaging**

**Definition** — this domain owns the *data path* (bytes moving); *execution* and *arrival* live in Domains 01–02 and are assumed, never re-taught. Pool, loop, and phases (which box runs stream I/O, how timers schedule chunks) → [Domain 01](<../../../01 Runtime Fundamentals and Mental Model/README.md>) (backpressure and blocking diagnosed there). Manifests, installs, and resolution (how stream libraries arrive, where imports resolve) → [Domain 02](<../../../02 Packages Scripts and Project Layout/README.md>) (packaging discipline assumed throughout). Data-path questions stay here; runtime and packaging questions route in one line.

- **What problem it solves**: double-teaching (pool mechanics re-explained per stream leaf — copies drifting; resolution re-derived per import — contradictions accumulating). Single source of truth keeps every copy fresh (one definition, many links — updates land once). Readers navigate faster too (blocking confusion routes to 01/3.1 in one click — no stream leaf wastes pages re-deriving the loop).
- **Modern guidance** — when a question reduces to execution or packaging, link out in one line (never re-derive — "loop pricing: [01/3.1]" then continue with the data point). When a 01/02 reader arrives here, the prerequisites (domain index §0) tell them what's assumed — no surprise dependencies. Propose upstream corrections upstream (errors in 01/02 fixed there — never patched by local restatement).

### 2) **Language iteration mechanics**

**Definition** — this domain owns Node's stream *objects* (`Readable`/`Writable`/`Transform` as runtime APIs); the *iteration protocol* lives in the language tracks. AsyncIterable protocol and `for await` grammar → [TypeScript 18/3.2](<../../../../TypeScript/18 Async Types and Standard Library/sections/3. Standard Library in Practice/3.2. AsyncIterable generators and for-await.md>) (this domain consumes the protocol — leaf 2.1's `for await` — without redefining it). Iterables, generators, and async iteration as language mechanics → [JavaScript 10](<../../../../JavaScript/10 Iterables Generators and Async Iteration/README.md>) (generator-shaped thinking assumed, not taught). Protocol questions go there; object questions stay here.

- **Why it matters (maintainability)**: the protocol/object split prevents misplaced depth (generator semantics re-derived in a stream leaf — stale within a release; `for await` desugaring duplicated — two copies, one rots). Each side links the other (stream bugs rooted in protocol misunderstanding route precisely — "iteration protocol: [TS 18/3.2]" — instead of guessing). Boundaries make both sides shorter and both more accurate.
- **Modern guidance** — consume the protocol here, define it there (a stream question about *generator behavior* routes to JS 10/TS 18; about *stream objects* stays). Quote the boundary in reviews ("protocol-side" vs "object-side" — different tracks, different owners). Keep this domain's `for await` coverage consumer-shaped (pacing and backpressure — leaf 2.2; protocol definition — TS 18/3.2).

### 3) **Deeper Node topics**

**Definition** — this domain is the map's third page, not the remaining territory: each area below gets its full treatment in its own domain (planned, see LOG — full coverage lands with those domains). Events, networking, and HTTP → [Domain 04](<../../../04 Events Networking and HTTP/README.md>) (emitters, sockets, bare servers — streams over the network, same interface new venue). Child processes, workers, and clustering → [Domain 05](<../../../05 Child Processes Workers and Clustering/README.md>) (cores via processes — heavy transforms moved off the loop). Debugging, configuring, and shipping → [Domain 06](<../../../06 Debugging Configuring and Shipping/README.md>) (inspect, env, deploys — data-path observability in production). Production synthesis and interviews → [Domain 07](<../../../07 Production Node Use and Interview Mastery/README.md>) (the track's capstone).

- **Why it matters (operations)**: map-first learning prevents premature depth (sockets before streams — network backpressure without local backpressure is incantation; workers before buffers — threads without bytes is hazard). Each domain assumes 01–03 (runtime vocabulary + packaging discipline + data-path fluency — the language every later leaf speaks). Skipping ahead borrows confusion at interest; the map makes the territory cheap.
- **Modern guidance** — read in `NN` order (on-disk prefixes are curriculum order — 03 before 04, always). Treat textual forwards as promises, not placeholders (each names its owning domain — when the domain lands, links upgrade; until then, the name scopes the question). Record cross-domain fixes at the boundary (a stream error found while writing HTTP gets fixed in 03/2.2 and linked — never duplicated into 04).
