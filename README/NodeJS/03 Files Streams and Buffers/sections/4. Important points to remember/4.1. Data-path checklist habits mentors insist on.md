## 4.1. Data-path checklist (habits mentors insist on)

### 1) **Async files, pipelined streams**

**Definition** — the data-path boot discipline: no synchronous I/O past boot (leaf 1.1's rule — `*Sync` in a handler is a defect), no bare `.pipe` without lifecycle (leaf 2.1's rule — `pipeline` everywhere chains exist), size decides the API (leaf 1.1's comfort line — whole-read below, stream above). Three rules covering every byte's journey: how it's read, how it flows, how much memory it may claim. Violations fail loudly in review, never silently in production.

- **Why it matters (reliability)**: data-path gaps compound under load (sync reads fine at 10 rps, fatal at 10k — the loop serializes; bare pipes fine on happy paths, hanging on first failure — errors unpropagated; whole-reads fine in dev, OOM on attacker sizes — unbounded inputs). Each gap is load-activated (invisible in CI, total in incidents). The checklist front-loads the decisions CI can't load-test cheaply.
- **Modern guidance** — gate the three rules in review (sync-beyond-boot flagged; `.pipe(` flagged — pipeline suggested; unbounded `readFile` on untrusted paths flagged). Prove the pipeline once per service (a failing middle in staging — rejection observed, descriptors freed; the test earning every `pipeline`). Document the size policy (comfort line in the repo README — number with a reason, not folklore).

```javascript
// GOOD: the data-path gate in one pipeline — runs on node v20.20.2 (bytes equal, async throughout)
import { pipeline } from 'node:stream/promises'; import { createReadStream, createWriteStream } from 'node:fs';
import { readFile } from 'node:fs/promises'; import { createHash } from 'node:crypto';
await pipeline(createReadStream('/tmp/nodeprobe/hello.txt'), createWriteStream('/tmp/nodeprobe/gate-copy.txt')); // no bare pipe (lifecycle managed)
const [a, b] = await Promise.all(['/tmp/nodeprobe/hello.txt', '/tmp/nodeprobe/gate-copy.txt'].map((f) => readFile(f))); // async reads (loop free)
console.log('pipelined copy identical:', a.equals(b)); // true (bytes, not vibes)
// BAD: eyeballing data flow in review ("looks streamed") —
// eyes skip `.pipe(` in 400-line files; gates and grep don't: `grep -rn "\.pipe(" src/` in CI
```

### 2) **Backpressure honored, errors destroyed**

**Definition** — bounded memory by protocol (returns checked or machinery used — leaf 2.2; producer pace governed by consumer), teardown on every failure path (`pipeline` destroys all stages — leaf 2.1; manual topologies `destroy(err)` — leaf 2.2), truncation impossible by construction (checksums or atomic renames — consumers never read partials). The trio converts I/O from hopeful to engineered: memory flat under any speed ratio, resources freed on any failure, outputs complete or absent — never partial.

- **Why it matters (operations)**: unpressured flows OOM the steady state (not spikes — sustained ratio mismatch; the slow leak that kills at 3 AM). Untorn-down failures poison the aftermath (partial file served as complete — downstream decisions on garbage; leaked descriptors accumulating toward EMFILE — the outage after the outage). Unchecksummed outputs corrupt silently (truncation discovered by customers — the most expensive monitoring there is).
- **Modern guidance** — default to machinery (`pipeline`/`for await` — protocol automatic; manual loops justify themselves in comments). Destroy first on failure (teardown before logging — resources freed while the error is still hot). Checksum across trust boundaries (network, user input, cross-service — hash on bytes, verified before parsing; internal temp files may skip with a comment saying why).

```javascript
// GOOD: paced, torn down, checksummed — runs on node v20.20.2 (flat, rejected-clean, hashes match)
import { pipeline } from 'node:stream/promises'; import { Readable, Transform } from 'node:stream';
import { createHash } from 'node:crypto';
const items = Array.from({ length: 100 }, (_, i) => `row-${i}\n`); // paced source (for-await paced, memory flat)
let bytes = 0; const hash = createHash('sha256');
await pipeline(Readable.from(items), new Transform({ transform(c, _e, cb) { bytes += c.length; hash.update(c); cb(null, c); } }), async function* (src) { for await (const _ of src); });
console.log('pipelined bytes:', bytes, '| sha256:', hash.digest('hex').slice(0, 16)); // 690 bytes + hash prefix (measured, checksummed)
// BAD: "backpressure handled by Node automatically" (half-remembered truth — machinery honors it, manual loops don't) —
// automatic where pipelined, absent where hand-rolled; know which code you're standing in
```

### 3) **Bytes explicit, encodings named**

**Definition** — binary truth at every boundary (buffers carried through binary paths — leaf 3.1; encodings named at every conversion — both directions; no implicit string coercion anywhere data integrity matters). Text boundaries declare their view (`utf8` for display, `base64`/`hex` for transport); binary boundaries stay bytes (hash, encrypt, frame on octets). The rule fits in one review question: "where does this buffer become a string, and which encoding was named?"

- **Why it matters (correctness)**: unnamed conversions corrupt silently (protocol bytes through default `toString()` — mojibake checksums; chunk-seam emoji — replacement characters in stored data). Corruption compounds downstream (parsed records wrong — validations pass on garbage; hashes computed post-corruption — verify nothing). Each boundary unnamed is a future incident with the evidence already destroyed (original bytes gone — only the corrupted view stored).
- **Modern guidance** — name encodings at every crossing (both directions — the review grep is `toString()` without args and `Buffer.from(` with one arg). Carry bytes to the last responsible moment (decode for display, never for processing). Test boundaries with hostile fixtures (emoji, CJK, 0xFF bytes, split seams — every crossing tested with all four; ASCII-only tests bless corruption).

```javascript
// GOOD: crossings named, bytes carried — runs on node v20.20.2 (lossless, hashed on truth)
const raw = Buffer.from([0x68, 0x69, 0xff, 0x20, 0xf0, 0x9f, 0x8c, 0x8d]); // hostile fixture (0xFF + emoji bytes)
console.log('hex view:', raw.toString('hex')); // 6869ff20f09f8c8d (named — exact, reversible)
console.log('utf8 view lossy:', raw.toString('utf8').includes('�')); // true (proves the point: views lose, bytes keep)
import { createHash } from 'node:crypto';
console.log('hash on bytes:', createHash('sha256').update(raw).digest('hex').slice(0, 16)); // truth hashed (pre-view)
// BAD: `hash.update(buf.toString())` ("hash the content") —
// hashes the lossy view: two different byte sequences, one hash — verification theater
```

### 4) **Common confusion**

- "Checklists are for juniors" — checklists are for *load* (experts skip steps under pressure exactly when steps matter — the data path fails at 3 AM under page; ritual beats recall). Seniority writes the checklist; everyone runs it.
- "Small files need no discipline" — small files become large ones (logs grow, uploads scale, fixtures multiply — today's config is tomorrow's export; the size rule scales down freely, chaos doesn't scale up). Habits precede sizes.
- "The gate snippet is over-engineering" — ten lines preventing three incident classes (sync stalls, bare-pipe hangs, whole-read OOMs — each a past outage somewhere). Gates are the cheapest tests a repo owns.
- "Checksums double the I/O" — hashes stream inline (one pass — `hash.update` per chunk; no re-read; microseconds beside disk milliseconds). Verification costs nothing measurable; absence costs incidents.

### 5) **Performance note**

Checklist items are performance *enablers*: async files free the loop (concurrency without threads — the throughput bargain); pipelined streams bound memory (flat under any ratio — the OOM class retired); inline hashing verifies without re-reads (single pass — correctness at streaming speed); named encodings prevent re-processing (corrupt-then-repair cycles eliminated). Total runtime cost: one hash update per chunk, one buffer compare per copy (microseconds beside I/O). Total avoided cost: the stall/hang/OOM/corruption incidents this domain exists to prevent. Measure avoided classes (sync-in-handler findings/quarter, bare-pipe findings/quarter — both should read zero after the gate lands).

### 6) **Mentor note**

Teach the data path as pre-flight ("recite async-pipelined-bounded-named before first deploy" — ritual beats reminder; students chant it unprompted). Demo each gap once (sync stall via lag probe, bare-pipe hang via failing middle, whole-read OOM via capped container — three scars, permanent habits; all demonstrated live in leaves 1.1–2.2). Drill the gate as kata (break a fixture three ways — students' checks must name all three gaps). Watch for the eyeballer ("looks streamed" — fix with `grep \.pipe(`) and the ASCII-tester ("tests pass" — fix with the hostile fixture: 0xFF + emoji + seams). Review check: async past boot, pipelines managed, memory bounded, encodings named, juniors stat before reading and print resolutions before guessing.
