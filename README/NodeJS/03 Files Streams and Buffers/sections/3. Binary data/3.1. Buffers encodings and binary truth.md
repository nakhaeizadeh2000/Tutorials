## 3.1. Buffers, encodings, and binary truth

### 1) **Bytes before strings**

**Definition** — `Buffer` holds octets (fixed sequences of bytes — the wire truth), and strings are an *encoding view* over bytes (`utf8` — variable-width text; `hex`/`base64` — text-safe binary representations; `latin1` — byte-direct legacy). Conversion is explicit both ways (`Buffer.from(str, 'utf8')` — text to bytes; `buf.toString('hex')` — bytes to text). Implicit coercion corrupts (binary concatenated as utf8 — mojibake; multi-byte characters split across chunks — replacement characters). Bytes first, strings by declaration.

- **What problem it solves**: encoding-assumed corruption (binary protocol parsed as utf8 string — bytes ≥0x80 mangled; chunk-split emoji — half-characters at boundaries; base64 handled as opaque strings — padding stripped, decode fails). Each corruption is silent (no error — wrong data, confidently delivered). Explicit encodings make the view a decision (reviewed per boundary), and byte-level handling keeps binary exact.
- **Modern guidance** — carry `Buffer` through binary paths (parse, hash, encrypt on bytes — decode to string only for display/logging). Name the encoding at every conversion (both directions — `from(x, 'utf8')`, `toString('base64')`; unnamed conversions are review flags). Handle split multi-byte sequences at chunk seams (`StringDecoder` — stateful decode across chunks; or decode only complete frames — length-prefixes, point 3). Test with non-ASCII fixtures (emoji + CJK in every encoding test — ASCII-only tests bless corruption).

```javascript
// GOOD: bytes carried, encodings named — runs on node v20.20.2
const bytes = Buffer.from('hi 🌍', 'utf8'); // text → bytes (encoding named)
console.log('byte length:', bytes.length, '| chars:', 'hi 🌍'.length); // 7 bytes vs 5 chars (views differ)
console.log('hex view:', bytes.toString('hex').slice(0, 8)); // named view (exact, reversible)
console.log('round trip:', Buffer.from(bytes.toString('base64'), 'base64').toString('utf8') === 'hi 🌍'); // true (lossless)
// BAD: `chunk.toString()` on protocol bytes ("strings are easier") —
// 0xFF becomes U+FFFD silently; the checksum computed on garbage verifies nothing
```

### 2) **Alloc shapes compared**

**Definition** — three allocation shapes with priced trade-offs: `Buffer.alloc(n)` (zero-filled — safe by default; contents deterministic; slight init cost), `Buffer.allocUnsafe(n)` (pooled, uninitialized — fastest; contents are previous-pool garbage until overwritten — must fill fully before use), `Buffer.from(...)` (copies from string/array/buffer — owned data, no sharing). Pooling detail: small `allocUnsafe` draws from an 8 KB shared slab (fast, shared — slice references keep the whole slab alive; `slice()` shares memory, `subarray()` too — copy to detach). Safety default, speed deliberate.

- **Why it matters (correctness, security)**: uninitialized disclosure (unfilled `allocUnsafe` sent on the wire — previous request's data leaks to the next client; the Heartbleed-shaped bug, self-inflicted). Slab retention (a 10-byte `slice` of an 8 KB slab pins 8 KB — thousands of slices pin megabytes; retention invisible in heap snapshots of the slice). Copy-vs-share confusion (mutating a `slice` mutates the parent — aliasing bugs with no assignment in sight). Each shape is safe used as designed, hazardous used casually.
- **Modern guidance** — default `alloc` (zeroed — safe; init cost negligible beside I/O). Use `allocUnsafe` only when filling synchronously and fully (crypto nonces, protocol frames built immediately — fill-then-freeze in the same tick; review flags any other use). Copy to detach (`Buffer.from(slice)` — retention released; sub-slab slices never stored long-term). Treat `slice` as a view (document sharing at the boundary — mutation rights explicit).

```javascript
// GOOD: shapes priced and safe — runs on node v20.20.2
const safe = Buffer.alloc(8); // zeroed (deterministic — safe default)
console.log('alloc zeroed:', safe.every((b) => b === 0)); // true (nothing leaks, ever)
const fast = Buffer.allocUnsafe(8); fast.fill(0xAB); // pooled speed + immediate full fill (safe by discipline)
console.log('unsafe filled:', fast.toString('hex') === 'abababababababab'); // true (garbage overwritten before use)
const detached = Buffer.from(fast.subarray(0, 2)); // copy detaches (slab released — no retention)
console.log('detached:', detached.length === 2 && detached.toString('hex') === 'abab'); // true (owned bytes)
// BAD: `socket.write(Buffer.allocUnsafe(1024))` with partial fill ("fast path") —
// unfilled tail sends pool garbage: previous sessions' bytes on the wire — disclosure by optimization
```

### 3) **Binary protocols parsed, not guessed**

**Definition** — wire formats read by spec: fixed offsets (`readUInt16BE(0)` — field at byte 0, big-endian; endianness from the spec, never assumed), length-prefixed frames (length header → exactly N body bytes — framing before parsing; partial frames buffered across chunks), checksums over bytes (hash the octets, not the string view — verification on truth). Guessing (regex on binary, split on delimiters inside payloads, assumed endianness) corrupts at scale and opens parsing differentials (two parsers disagreeing — the smuggling class).

- **Why it matters (correctness, security)**: endian swaps (LE field read BE — values wrong by orders of magnitude; sensor data, money amounts — silent, confident, wrong). Frame desync (delimiter-split binary containing the delimiter — one split too many; every subsequent frame misaligned; the desync that never resynchronizes). Differential parsing (proxy and server framing differently — request smuggling's root; single spec, single parser, tested against vectors). Protocols are contracts — parse like one.
- **Modern guidance** — read the spec's endianness once, encode it in helpers (`readU16BE` wrappers named per protocol — no bare offsets at call sites). Frame by length-prefix (buffer until complete — partial frames held, never parsed; leftover bytes carried to the next frame). Verify checksums on bytes (hash pre-decode — truth verified, views untrusted). Test with vectors (spec examples + fuzzed splits — chunk seams at every offset; desync tests assert resync or loud failure).

```javascript
// GOOD: spec-shaped parsing — runs on node v20.20.2 (length 5, body exact, LE value 258)
const frame = Buffer.concat([Buffer.from([0x05, 0x00]), Buffer.from('hello')]); // len-prefix LE(5) + body
const len = frame.readUInt16LE(0); // endianness from spec (LE here — stated, not assumed)
const body = frame.subarray(2, 2 + len); // exact slice (framing before parsing)
console.log('framed:', len === 5 && body.toString('utf8') === 'hello'); // true (complete frame, verified length)
const num = Buffer.from([0x01, 0x02]); // endian demo: same bytes, two readings
console.log('BE:', num.readUInt16BE(0), '| LE:', num.readUInt16LE(0)); // BE: 258 | LE: 513 (spec decides)
// BAD: `data.toString().split('|')` on a binary stream ("delimiters are simple") —
// payloads contain 0x7C; one split too many; frames misalign forever — length-prefix or desync
```

### 4) **Common confusion**

- "`Buffer` is deprecated / legacy" — `Buffer` is the binary API (no replacement — `Uint8Array` interops but lacks encoding methods; modern code uses both, converting at boundaries). Bytes live here.
- "`allocUnsafe` is fine because GC clears" — GC frees, never wipes (freed memory retains contents until reused — unfilled buffers disclose on the wire; zeroing is a write, collection is bookkeeping). Safety is written, not collected.
- "UTF-8 handles all bytes round-trip" — UTF-8 maps *characters*, not octets (invalid sequences become U+FFFD — lossy; binary round-trips need `latin1`/raw bytes — views chosen per cargo). Text encodings carry text.
- "Endianness doesn't matter on one machine" — matters on the wire and in files (specs name it — x86 LE vs network BE; same-machine code reading foreign formats hits it immediately). Specs decide, hosts obey.

### 5) **Performance note**

Buffer costs are allocation + copy, priced per operation: `alloc` zeroing costs O(n) writes (negligible beside I/O; measurable only in hot numeric loops — pool there); `allocUnsafe` skips init (fastest — the gain realized only with immediate full fill; partial-fill bugs cost incidents, not nanoseconds). Copies (`from`, `concat`) cost bandwidth (avoid per-chunk copies in hot pipelines — slice views where lifetimes allow; copy at ownership boundaries). Slab retention costs RSS invisibly (slices pinning slabs — detach stored slices; the leak profilers misattribute). Optimize copies first (fewest bytes moved — the dominant cost), allocation shape second (pool for hot paths, zeroed elsewhere), retention always (detach stored views — free memory correctness).

### 6) **Mentor note**

Teach bytes-before-strings as worldview ("is this data text or octets? — answer before touching it" until binary-as-string *looks* corrupt). Demo the corruption live (binary through `toString()` and back — bytes changed; checksum fails; views indicted). Demo the disclosure (unfilled `allocUnsafe` printed twice — garbage differs; then filled — deterministic; safety felt). Drill framing (hand a chunk-split frame pair — "reassemble before parsing"; desync story for delimiters). Watch for the string-forcer ("easier" — fix with the mojibake demo) and the unsafe-optimizer ("fast" — fix with "show me the fill" — unfilled uses rejected). Review check: bytes carried through binary paths, encodings named both ways, allocs zeroed-or-filled, protocols framed by spec, juniors test with emoji fixtures.
