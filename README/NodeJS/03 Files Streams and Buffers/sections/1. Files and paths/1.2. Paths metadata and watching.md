## 1.2. Paths, metadata, and watching

### 1) **Paths joined, never concatenated**

**Definition** — the `node:path` module builds paths by rule, not by string gluing: `join()` normalizes segments (duplicate separators collapsed, `.`/`..` resolved lexically), `resolve()` anchors to cwd (right-to-left until absolute — the launch dir made explicit), `basename`/`dirname`/`extname` dissect (no regex surgery), and `sep`/`posix`/`win32` namespaces handle OS differences (`\` vs `/` — joined code runs on both). Concatenation (`dir + '/' + file`) breaks on Windows, doubles separators, and invites traversal (`../..` smuggled through unsanitized input — the path-traversal vulnerability class).

- **What problem it solves**: string-built paths fail across environments (works on Linux CI, breaks on a Windows laptop — separator assumed; `uploads/` + filename with `../` — traversal serving `/etc/passwd`; double slashes confusing route/file mapping — cosmetic until security-relevant). `path` moves these from vigilance (every concatenation reviewed) to construction (joined paths correct by default). Traversal especially: `join()` still resolves `..` — containment needs explicit checks, but concatenation doesn't even normalize.
- **Modern guidance** — join all multi-segment paths (`path.join(dir, file)` — never `+ '/' +`). Resolve launch-relative inputs once at the edge (`path.resolve()` at startup — absolute thereafter; leaf 2.1 of Domain 01's cwd lesson, applied). Contain untrusted segments (resolve, then verify `startsWith(root)` — traversal refused explicitly; `join` alone normalizes but doesn't contain). Prefer `node:path/posix` for wire formats (URLs, manifests — separators fixed regardless of host OS).

```javascript
// GOOD: joined, resolved, contained — runs on node v20.20.2
import path from 'node:path';
const root = path.resolve('/tmp/nodeprobe/safe'); // anchored once (absolute thereafter)
const joined = path.join(root, 'a', '..', 'b.txt'); // normalized lexically (.. resolved, no fs touch)
console.log('joined:', joined); // /tmp/nodeprobe/safe/b.txt (clean, no traversal residue)
const evil = path.join(root, '../../etc/passwd'); // normalized — but NOT contained (join resolves .. happily)
console.log('contained:', path.resolve(root, evil).startsWith(root) ? 'inside' : 'REFUSED'); // REFUSED (check stated)
// BAD: `fs.readFileSync(UPLOAD_DIR + '/' + req.query.f)` ("direct mapping") —
// `?f=../../etc/passwd` serves system files; concatenation is a vulnerability with a fast path
```

### 2) **Metadata before reads**

**Definition** — `stat()` (and `lstat`/`fstat` siblings) reports without reading: existence (`ENOENT` vs stats — probe, don't assume), size (the size-rule input — leaf 1.1), type (`isFile()`/`isDirectory()`/`isSymbolicLink()` — dispatch before opening), times (`mtimeMs` — caching and invalidation). Metadata-first code decides cheaply (bytes never touched for decisions stats answer) and fails precisely (missing vs unreadable vs wrong-type — three errors, three handlers).

- **Why it matters (correctness)**: blind reads misdiagnose (read a directory — `EISDIR` where `ENOENT` was expected; read a 50 GB "config" — OOM from skipping the size check; follow a symlink out of containment — `lstat` would have shown the link). TOCTOU caveat (stat-then-act races like all check-then-act — size policies tolerate it; exclusivity uses `wx` — leaf 1.1; stat informs, flags enforce). Metadata is reconnaissance — fast, cheap, and first.
- **Modern guidance** — stat before sizing decisions (the size rule needs `size` — no read without it for untrusted paths). Distinguish error codes (`ENOENT` → default/create path; `EACCES` → permission escalation; `EISDIR`/`ENOTDIR` → caller bug — each routed, never a generic 500). Prefer `lstat` for untrusted trees (symlinks reported, not followed — containment decisions on links, not targets). Cache metadata where loops demand it (directory scans per request — `readdir` with `withFileTypes` once, not `stat` per file per request).

```javascript
// GOOD: reconnaissance before bytes — runs on node v20.20.2
import { stat, lstat } from 'node:fs/promises';
const info = await stat('/tmp/nodeprobe/hello.txt').catch((err) => ({ error: err.code })); // probe, don't assume
console.log('size:', info.size, '| file:', info.isFile()); // decisions without reading
const link = await lstat('/tmp/nodeprobe/hello.txt'); // links reported (follow only deliberately)
console.log('symlink:', link.isSymbolicLink()); // false here (checked, not trusted)
const missing = await stat('/tmp/nodeprobe/nope.txt').catch((err) => err.code); // ENOENT (routed, not thrown)
console.log('missing routes to:', missing);
// BAD: `readFile(p)` then branching on catch-all errors ("fewer syscalls") —
// one syscall saved, three failure modes conflated; metadata is cheap, misdiagnosis is not
```

### 3) **Watching is notification, not truth**

**Definition** — `fs.watch` subscribes to OS file events (rename/change — delivered fast, coalesced aggressively: rapid writes collapse to one event; some platforms report `rename` for content edits; event storms truncate). Guarantees absent: no event means nothing (dropped under load), one event means ≥1 change (never exactly one), ordering loose. Correctness patterns built atop: poll-and-compare for state (mtime/hash checked on notification — events trigger verification, never embody it), checksums for content truth (hash after event — coalescing irrelevant), debounced rebuilds for tooling (dev servers wait out storms).

- **Why it hurts when missing (correctness)**: event-counting logic (two writes → two rebuilds assumed — coalescing delivers one; counter-based sync drifts). Missed-event staleness (dropped notification — cache never invalidates; config reload "sometimes works" — the flakiest class of production bug). Platform variance (macOS coalesces harder than Linux; network filesystems barely notify — code correct on dev, stale in prod). Treating hints as facts fails exactly where filesystems are busiest.
- **Modern guidance** — watch for hints, verify for truth (on event: re-stat/re-hash — the event says "look", the hash says "changed"). Debounce handlers (50–200 ms quiet windows — storms settle, rebuilds run once). Prefer polling where correctness demands it (`fs.watchFile` interval checks — slower, reliable; config hot-reload on network mounts). Test watchers with rapid bursts (ten writes in 10 ms — assert eventual consistency, never event counts).

```javascript
// GOOD: hint triggers verification — runs on node v20.20.2 (event arrives, hash decides)
import { watch } from 'node:fs'; import { readFile, writeFile } from 'node:fs/promises';
await writeFile('/tmp/nodeprobe/watched.txt', 'v1');
const seen = await new Promise((resolve) => {
  const w = watch('/tmp/nodeprobe/watched.txt', async (event) => { // hint (coalesced, unordered — a nudge)
    const content = await readFile('/tmp/nodeprobe/watched.txt', 'utf8'); // truth (read, don't count)
    w.close(); resolve(`${event} → content now: ${content.trim()}`);
  });
  setTimeout(() => writeFile('/tmp/nodeprobe/watched.txt', 'v2'), 50); // the change (after watcher armed)
});
console.log('watcher:', seen); // change → content now: v2 (event named the hint, read named the truth)
// BAD: `let writes = 0; watch(f, () => rebuild(writes++))` ("rebuild per change") —
// coalescing eats counts; rebuilds keyed on numbers drift from files; verify content, never count hints
```

### 4) **Common confusion**

- "`path.join` prevents traversal" — normalizes, doesn't contain (`join(root, '../../x')` resolves outward happily — containment is `resolve` + `startsWith`, a separate explicit check). Normalize then verify.
- "`stat` existence checks are racy, therefore useless" — races matter for exclusivity (use `wx` — leaf 1.1), not for reconnaissance (size/type decisions tolerate TOCTOU — worst case a retryable error). Different guarantees, different tools.
- "`fs.watch` recursive works everywhere" — recursive watching is macOS/Windows-only (Linux needs per-directory watchers or libraries — chokidar exists for this gap; know your platform's promises). Portability checked, not assumed.
- "`mtime` detects content change" — mtime has granularity limits (sub-millisecond writes share stamps; clock skew lies; `ctime`/`ino` help, hashes decide). Timestamps hint; checksums prove.

### 5) **Performance note**

Path/metadata/watch costs are syscall counts, priced per call: `join`/`resolve` are pure string ops (nanoseconds — the cheapest correctness in Node; never skipped for speed). `stat` is one syscall (microseconds local — cache in hot loops, never per-request-per-file scans; `readdir(withFileTypes)` batches whole directories in one pass). Watchers cost a file descriptor each (thousands of recursive watchers exhaust limits — scope watches narrowly; debounced rebuilds save orders of magnitude over per-event work). Optimize by batching (one scan over many stats), scoping (watch subtrees, not roots), and verifying cheaply (mtime first, hash on hint) — never by skipping containment (security) or metadata (correctness).

### 6) **Mentor note**

Teach paths as construction ("show me the `+ '/' +` — now break it with Windows and `..`" until concatenation *looks* hostile). Demo traversal live (the `?f=../../etc/passwd` request against a naive server — then the contained version refusing; security felt in one terminal). Drill metadata-first (hand an unknown path — "stat it, narrate the decision, then read"; TOCTOU discussed at the `wx` boundary). Demo coalescing (ten rapid writes, one event — counters embarrassed, verifiers vindicated). Watch for the concatenator ("readable" — fix with the traversal exploit) and the event-counter ("per change" — fix with the burst test). Review check: paths joined, untrusted contained, metadata before reads, watchers verifying, juniors print resolutions before touching trees.
