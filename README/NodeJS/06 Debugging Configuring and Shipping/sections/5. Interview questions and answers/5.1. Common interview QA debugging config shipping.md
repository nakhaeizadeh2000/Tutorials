## 5.1. Common interview QA: debugging, config, shipping

### 1) **"Production is slow" — walk me through it**

**Definition** — the triage screen: candidates narrate slow-service diagnosis in order. The expected sequence: metrics first (which route, when did p99 move, what deployed — scope the blast), layers second (bare-metal repro — runtime vs framework, leaf 1.1 of Domain 06's rule), profiles third (flame under production-shaped load — self-time boxes, leaf 1.2), change last (shape fix with before/after receipt). Numbers at every step (p99 values, deploy SHAs, flame percentages). The interviewer listens for order (metrics → layers → profiles → change) and for receipts (no step without evidence).

- **What problem it solves**: shotgun debugging (guesses deployed as fixes — profiler never opened; framework blamed without bare numbers; "optimized" without receipts). Unordered triage wastes the fix window (hours on the wrong layer; incidents extended by wandering). The ordered walk converges (each step eliminates a class; evidence compounds; the fix lands once, verified).
- **Modern guidance** — narrate by layer order ("metrics scope, bare metal assigns, flame locates, receipt proves" — mechanism per step, never vibes). State what each step eliminates ("metrics rule out deploy correlation; bare metal rules out framework; flame rules out guesswork"). Price the fix with before/after (same load, same procedure — committed story). Practice on the lag probe below (triage instrument in ten lines — loop vs workload separated live).

```javascript
// GOOD: triage instrument — loop vs workload separated — runs on node v20.20.2 (lag names the layer)
const t = Date.now(); // lag probe (leaf 3.1 of Domain 01's instrument — triage step zero)
setTimeout(() => { const lag = Date.now() - t - 100; // expected 100ms (excess is loop-blocked time)
  console.log('loop lag ms:', lag, lag > 50 ? '→ profile the loop (flame, leaf 1.2)' : '→ loop clean, look downstream (DB/network)');
  console.log('heap MB:', (process.memoryUsage().heapUsed / 1048576).toFixed(1), '(baseline for leak-watch — leaf 1.2 diffs)');
  console.log('narration: "metrics scoped, lag separated, flame next, receipt last"');
}, 100);
// BAD: "scale horizontally" as triage step one (capacity for a code problem — 2× boxes, same flame) —
// scale after diagnosis, never instead; triage converges, capacity postpones
```

### 2) **Memory climbs weekly: find it**

**Definition** — the leak trace: candidates narrate slow-burn OOM diagnosis. The expected shape: graph first (RSS slope per deploy — leak vs growth; slope starting at a release — suspect named), snapshot diff second (baseline vs +N iterations — retained paths convict; leaf 1.2's procedure), fix third (bounded cache, removed listener, cleared timer — the big three retainer classes), verify flat fourth (same procedure — zero slope; the receipt closing the incident). The interviewer escalates (native growth? — heap flat, RSS climbing → buffers/handles; intermittent? — report-on-fatal catches the one crash).

- **Why it matters (operations)**: restart-masked leaks (weekly restarts "fixing" memory — slope unexamined; growth unbounded underneath; OOM at the worst quarter). Misattributed growth (heap blamed for native leaks — snapshots innocent; `process.memoryUsage` splits heap/external/rss — different tools per side). Unverified fixes ("maybe fixed" deploys — slope re-measured or hope deployed).
- **Modern guidance** — answer with the procedure (graph → diff → fix → verify — four beats, told in order). Name the big three retainers (unbounded caches, unremoved listeners, uncleared timers — check in that order; 90% of leaks live there). Split heap vs native first (`memoryUsage` sides — snapshot the heap side, handle-trace the native). Verify flat (same iterations — zero growth; receipts, not restarts).

```javascript
// GOOD: growth isolated per iteration — runs on node v20.20.2 (delta printed, retainer named)
const leak = []; // suspect: unbounded array (the big-three class #1 — cache without bounds)
for (let i = 0; i < 1000; i++) leak.push({ i, data: 'x'.repeat(100) }); // exercise (N iterations — growth per cycle isolated)
const kb = process.memoryUsage().heapUsed / 1024;
console.log('heap after 1000 appends:', kb.toFixed(0), 'KB (slope = leak.length unbounded — retainer: the array itself)');
console.log('fix: Map with LRU bound (or TTL) — re-run: slope zero (receipt closes the incident)');
// narration: "graph slopes, snapshots diff, retainer convicted, fix verified flat"
// BAD: "restart weekly via cron" (leak scheduled, not fixed — growth unbounded underneath; OOM scheduled eventually) —
// restarts mask; diffs convict; bounds cure
```

### 3) **Deploy without dropping requests**

**Definition** — the rollout trace: candidates design zero-drop deploys. The expected shape: readiness gates (new pods serve only when ready — leaf 3.1; old pods die only after replacements ready — surge configured), drains implemented (SIGTERM → close → finish → flush → exit — leaf 3.1's sequence; grace sized from measured drains), telemetry complete (flush before exit — evidence preserved; rollout markers logged — version attribution). The interviewer escalates (DB migration? — expand/contract, backward-compatible; sticky sessions? — externalize first per leaf 3.1 of Domain 05; slow drainers? — budget kills, pages fire).

- **Why it matters (reliability)**: rollout mini-outages (every deploy severing in-flight — 500s with deploy SHAs; users feeling releases). Unready replacements (old dies first — traffic to warming pods; ready-first sequencing eliminates). Truncated evidence (exit before flush — deploy forensics blind). The trace is the release review in miniature — same sequence, smaller stakes.
- **Modern guidance** — answer with the sequence (ready-first → drain → flush → numbered exit — order fixed). Size grace from measurements (p99 drain × 2 — configured, not defaulted). Assert in staging (rollout under load — 500s counted, nonzero blocks). Name the escalations unprompted (migrations expand/contract; sessions externalized; budgets kill — seniority signaled).

```javascript
// GOOD: rollout asserted with all requests in-flight — runs on node v20.20.2 (10/10 served, 0 dropped, exit 0)
const http = require('node:http');
const server = http.createServer((req, res) => setTimeout(() => res.end('v2-slow'), 100)).listen(0, '127.0.0.1', async () => { // slow responses (in-flight window held open)
  const port = server.address().port; let served = 0, dropped = 0;
  const hit = () => new Promise((res) => http.get({ port, host: '127.0.0.1', headers: { connection: 'close' } }, (r) => { r.resume().on('end', () => { served++; res(); }); }).on('error', () => { dropped++; res(); }));
  const load = Promise.all(Array.from({ length: 10 }, () => hit())); // all concurrent (drain condition — staggered arrivals post-close refuse by design)
  setTimeout(() => process.emit('SIGTERM'), 20); // deploy speaks with all 10 outstanding (the assertion condition)
  await load; console.log(`served: ${served}/10, dropped: ${dropped} (zero-drop asserted — in-flight completes)`);
  process.exitCode = dropped === 0 ? 0 : 1; server.close();
});
process.on('SIGTERM', () => server.close(() => { process.exitCode = process.exitCode ?? 0; })); // drain (existing finish — sequence, exactly)
// BAD: "rolling update with defaults" (unsequenced hope — drains unimplemented, grace default, readiness shallow) —
// defaults drop; sequences deliver; assertions prove
```

Rapid-fire drills (one sentence each — mechanism named): "`--inspect` flag in prod?" — break-glass only (staging always; SIGUSR1 + disconnect discipline in prod). "Report on hang?" — SIGUSR2 autopsy (wedged state captured — then restart). "Flame widest box?" — read self-time (leaves, not trunks — children delegate blame). "One snapshot enough?" — never (deltas convict — baseline + exercised + diff). "Secret in git history?" — rotate immediately (history immutable — revoke, rotate, redeploy). "Unready pod gets traffic?" — never (readiness gates — shed, don't serve). "Grace exceeded?" — kill + page (budgets terminate; hangs don't negotiate).

### 4) **Common confusion**

- "Triage differs from debugging" — triage *orders* debugging (scope → assign → locate → prove; debugging without triage wanders; triage without debugging theorizes). Sequence, then substance.
- "Leak-finding needs special tools" — needs *snapshots + diffs* (built-in — `getHeapSnapshot`, DevTools compare; special tools help, procedure matters; trawling without deltas wastes). Procedure over product.
- "Zero-drop needs service mesh" — needs *sequence* (ready-first + drain + flush — platform-agnostic; mesh helps, discipline delivers; unsequenced mesh still drops). Sequence first, mesh optionally.
- "Interview answers differ from runbooks" — the trace *is* the runbook (triage order in incidents; leak procedure on-call; rollout sequence per deploy — every answer here executes). Study shippable shapes.

### 5) **Performance note**

Interview delivery answers price real costs: triage order saves incident-hours (convergence vs wandering — the expensive direction); leak procedure saves restarts-turned-outages (bounded caches cost memory policy, unbounded cost quarters); zero-drop sequencing costs seconds per deploy (grace budgets — reliability cheapest). Candidates connecting each answer to a number (lag ms, slope KB/iter, drops counted) signal production ownership — the trait senior loops hire for. Mechanisms plus measurements, always.

### 6) **Mentor note**

Teach interview prep as incident prep ("every question here is a 3 AM page in a suit" — map each to its leaf: triage→1.1, leaks→1.2, rollouts→3.1, config→2.1, logs→2.2). Drill triage aloud with variants (slow only on Tuesdays — deploy correlation; slow everywhere — downstream; derivors route, reciters freeze). Drill leak stories (graphed, diffed, bounded, verified — four beats in order). Watch for the scaler ("more boxes" first — fix with "diagnose before capacity") and the restarter ("cron restarts" — fix with "slope or hope?"). Review check: triage ordered, leaks storied, rollouts asserted, rapid-fire derived, juniors profile before parallelizing and gate before shipping.
