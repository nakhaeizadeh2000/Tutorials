## 4.1. Delivery checklist (habits mentors insist on)

### 1) **Observable by default**

**Definition** — every service ships with evidence plumbed: inspectable (localhost-only inspector path documented — leaf 1.1; fatal reports enabled — autopsies automatic), profiled on demand (cpu/heap procedure rehearsed — leaf 1.2; hypotheses before captures), logged with context (JSON + reqId + levels — leaf 2.2; boundaries loud, loops quiet). Observability is a boot feature (present before the first incident — not bolted on during it). Unobservable services fail mysteriously by construction (no choice involved — architecture decides).

- **Why it matters (operations)**: blind incidents (slow with no profile path — guessing; crashing with no autopsy — restarting; failing with no request ids — shrugging). Bolt-on observability (added mid-incident — untested, misconfigured, mistrusted; evidence systems need calm-weather shakedowns). Alert-less logging (lines nobody reads — dashboards unbuilt; the first audience for logs is a human rehearsing the incident).
- **Modern guidance** — enable reports + inspector path from day one (flags in the deploy spec — reviewed like code; runbook references them — practiced in game days). Rehearse profiles quarterly (staging flame + heap diff — procedure fresh; tooling versioned with the runtime). Dashboard the boundaries (request rates, durations, errors per route — built at launch; alerts on slope, not on catastrophe).

```javascript
// GOOD: observability asserted, not assumed — runs on node v20.20.2 (flags present, endpoint honest)
const flags = process.execArgv.join(' '); // launch flags (inspectable in-process — auditable at runtime)
console.log('fatal reports:', flags.includes('--report-on-fatalerror') ? 'on' : 'off (enable in production spec)');
console.log('inspect path:', 'SIGUSR1 documented (break-glass — localhost only, disconnect after)');
const http = require('node:http');
const server = http.createServer((req, res) => res.end(req.url === '/live' ? 'alive' : 'app')).listen(0, '127.0.0.1', async () => {
  const port = server.address().port;
  const live = await new Promise((res) => http.get({ port, host: '127.0.0.1', path: '/live' }, (r) => res(r.statusCode)).on('error', () => 0));
  console.log('liveness honest:', live === 200 ? '200 (probe answers)' : 'MISSING (gate fails)'); server.close(); // 200 (evidence, not hope)
});
// BAD: "we'll add monitoring after launch" (observability debt — first incident blind, second bolted-on, third trusted maybe) —
// evidence systems ship with the service or fail with it
```

### 2) **Configured explicitly**

**Definition** — every environment differs by values, never by code (single boundary — leaf 2.1; schema at boot — crash early; secrets injected + redacted — never stored, never logged). Explicit means reviewable (config diffs per deploy — values changed deliberately; `.env.example` current — onboarding copies shapes, not secrets). Implicit means mysterious (branch-coupled values — merges carry config; defaulted venues — production by accident; scattered reads — grep archaeology per incident).

- **Why it matters (deployments)**: venue confusion (staging values in production — wrong database written; code identical, values swapped; explicit venues prevent). Secret sprawl (keys in five places — rotation misses one; single injection path — rotate once, everywhere). Unreviewed drift (env edited in consoles — untracked changes; config-as-code reviewed per PR; console edits expire with memory).
- **Modern guidance** — one boundary module (all reads, validated, frozen — leaf 2.1's shape; no scattered access, ever). Values per venue in the platform (orchestrator env, secret mounts — code venue-agnostic; same artifact everywhere). Diff config per deploy (values reviewed beside code — changed deliberately; example file current — shapes documented). Crash on unknown (no venue default — explicit or refused; production never accidental).

```javascript
// GOOD: venue explicit, values injected — runs on node v20.20.2 (dev shaped, prod refused without values)
function venue(env = process.env.NODE_ENV) { if (!env) throw new Error('config: NODE_ENV unset (venue explicit — never defaulted)'); return env; } // explicit (crash beats accident)
console.log('venue:', venue('staging')); // staging (named — values follow from the platform)
try { venue(undefined); } catch (e) { console.log('refused:', e.message); } // config: NODE_ENV unset (production never accidental)
// BAD: `const isProd = process.env.NODE_ENV === 'production'` with behavior branches everywhere ("venue-aware code") —
// venue in values, not branches: same artifact, injected differences — branches multiply untested shapes
```

### 3) **Shipped gracefully**

**Definition** — delivery as a discipline: images layered (leaf 3.1 — cached, pinned, non-root), probes split (liveness vs readiness — shed vs restart), deploys draining (close → finish → flush → exit — zero 500s asserted under load). Each deploy rehearsed (staging rollout under traffic — drops counted, target zero; grace sized from measured drains — policy, not default). Graceful is a property of the sequence (implemented in code, granted time by platform, verified by test).

- **Why it matters (reliability)**: rollout incidents (every deploy a mini-outage — severed in-flight, unready replacements, truncated telemetry; users feeling releases). Untested sequences (drain code never exercised — first real SIGTERM discovers the bug; staging rollouts exercise quarterly at least). Default grace (platform defaults killing slow drainers — sized from SLOs, configured per service).
- **Modern guidance** — assert zero-drop rollouts (staging deploys under load — 500s counted; nonzero blocks promotion). Size grace per service (p99 drain × 2 + flush — configured, reviewed; defaults distrusted). Roll ready-first (replacements serving before predecessors die — surge budgeted; sequence verified). Keep images lean (layered, ignored, pinned — rebuilds seconds, rollbacks exact).

```javascript
// GOOD: graceful sequence, asserted — runs on node v20.20.2 (drained, numbered, no drops)
const http = require('node:http');
const server = http.createServer((req, res) => res.end('ok')).listen(0, '127.0.0.1', () => {
  const port = server.address().port;
  http.get(`http://127.0.0.1:${port}/`, (r) => r.resume().on('end', () => {
    process.emit('SIGTERM'); // rollout speaks (mid-service — the real condition)
    setTimeout(() => console.log('outcome:', process.exitCode === 0 ? 'drained, numbered (zero-drop sequence holds)' : 'NONZERO (sequence broken)'), 300);
  }));
});
process.on('SIGTERM', () => server.close(() => { process.exitCode = 0; })); // close → drain → numbered (the sequence, exactly)
// BAD: deploy-and-pray ("Kubernetes handles graceful") —
// platforms grant seconds; sequences use them; untested handlers waste them — pray later, verify now
```

### 4) **Common confusion**

- "Checklists slow down shipping" — checklists *accelerate* shipping (five minutes per review versus incident-hours per gap; the trio above runs as deploy gates — automated, not ceremonial). Slow is debugging at midnight; fast is gating at noon.
- "Small services don't need delivery discipline" — small services become load-bearing ones (every critical system was once a script; retrofitting drains/probes mid-incident costs 10×). Discipline scales down freely; chaos doesn't scale up.
- "Staging rollouts are overkill" — untested sequences fail (first real SIGTERM discovers the bug — in production, under users; staging under load discovers it under fixtures). Rehearse where failure is cheap.
- "Zero-drop is aspirational" — zero-drop is *asserted* (staging counts 500s per rollout — nonzero blocks; aspirational without assertion is wishful; asserted becomes normal within quarters). Assert, then normalize.

### 5) **Performance note**

Checklist items are performance *enablers*: observability finds hotspots (profiles guide optimization — unmeasured tuning wastes; evidence directs). Explicit config removes branch tax (venue values, not code shapes — fewer untested paths; single artifact deploys faster). Graceful delivery preserves throughput across rollouts (no drop dips — capacity steady; severed connections retry-thundering — drains prevent). Total runtime cost: probe requests (negligible), structured logs (microseconds), drain seconds per deploy (scheduled, off-peak). Total avoided cost: the blind/misconfigured/dropping incidents this domain exists to prevent. Measure avoided classes (blind incidents, config incidents, drop incidents — zero after the gates).

### 6) **Mentor note**

Teach delivery as pre-flight ("recite observable-configured-graceful before first deploy" — ritual beats reminder; students chant it unprompted). Demo each gap once (blind incident without profiles, misconfig serving-while-wrong, dropping rollout — three scars from leaves 1.1–3.1, permanent habits). Drill the sequence as kata (SIGTERM a fixture — watch close/drain/number; assert zero drops under load). Watch for the prayer ("platform handles it" — fix with "show me the handler") and the postponer ("monitoring later" — fix with "first incident blind — when's later?"). Review check: evidence plumbed, config gated, delivery sequenced, juniors rehearse rollouts before declaring done.
