## 1.1. Inspecting servers and workers

### 1) **Inspect without stopping the world**

**Definition** — `node:inspector` exposes the running process to DevTools (`--inspect` at launch — WebSocket URL printed; `SIGUSR1` to a running process — inspection enabled post-hoc, no restart; workers each open their own port — `inspectPort` option, primary on 9229, workers incrementing). Breakpoints pause threads, not truth (paused workers hold their work — timeouts elsewhere fire; inspect staging freely, production gingerly). Debugger mechanics (stepping, scopes, breakpoints) live in [JavaScript 15/5.1](<../../../../JavaScript/15 Error Handling and Debugging/sections/5. Debugging toolkit/5.1. Console toolkit debugger breakpoints and stepping.md>); this leaf owns *service* inspection — which process, which port, when.

- **What problem it solves**: printf-only production debugging (restart-with-logs cycles — hours per incident; state invisible — guesses deployed as fixes). Post-hoc inspection (SIGUSR1 into a hung process — stacks visible without restart; deadlocks named, not theorized). Worker blindness (multi-threaded bugs debugged single-threaded — the failing isolate never opened; per-worker ports end that).
- **Modern guidance** — run `--inspect` in staging always (breakpoints cheap there — production-like state, consequence-free pauses). SIGUSR1 hung production (inspect, capture stacks, disconnect — minutes, no restart; disconnect when done — inspector overhead ends). Open workers deliberately (`inspectPort` per worker — the failing isolate first; primary's view never substitutes). Prefer logs first (cheap evidence before pausing — point 3; debugger for state, logs for history).

```javascript
// GOOD: inspector opened programmatically, URL printed — runs on node v20.20.2 (ws URL, then closed)
const inspector = require('node:inspector');
inspector.open(0, '127.0.0.1'); // ephemeral port, localhost-only (never 0.0.0.0 — debugger as attack surface; no third arg — wait:true would block for a client)
console.log('inspect at:', inspector.url().startsWith('ws://127.0.0.1:') ? 'localhost ws (bound, quiet)' : inspector.url());
inspector.close(); // disconnect when done (overhead ends — inspect, capture, close)
// Production post-hoc: kill -USR1 <pid> (inspection enabled, no restart — stacks then, theory never)
// BAD: `--inspect=0.0.0.0:9229` in production ("debugging is easier") —
// unauthenticated debugger on the network: RCE with a DevTools client — convenience as vulnerability
```

### 2) **Diagnose with built-in reporters**

**Definition** — diagnostic reports (`--report-on-fatalerror` — crash autopsy: JS+ native stacks, heap stats, loaded libs, env; `--report-on-signal` — on-demand autopsy via SIGUSR2; `process.report.writeReport()` — programmatic: triggered on handled anomalies, not just death). Reports are JSON (machine-greppable — heap numbers, handle counts, component versions; attached to incidents, not transcribed). No dependencies, no agents — the runtime confesses by itself.

- **Why it matters (operations)**: crash forensics without repro (fatal error at 3 AM — report written at death; heap, handles, and stacks attached to the ticket; debugging starts from evidence, not from "restart and watch"). Hang autopsies (SIGUSR2 to a wedged process — event-loop state captured; deadlock named in the report). Heisenbug capture (intermittent failure with report-on-fatal — the one crash in a thousand caught with full context; unreproducible made diagnosable).
- **Modern guidance** — enable fatal reports everywhere (`--report-on-fatalerror` in production flags — autopsies automatic; report directory configured — writable, rotated, retained per incident policy). Signal reports for hangs (SIGUSR2 documented in runbooks — wedged-process procedure: signal, collect, then restart). Write reports programmatically at anomaly boundaries (suspicious state reached — `writeReport()` with custom filename; handled errors with forensic value — evidence kept, not just logged).

```javascript
// GOOD: report written on demand, content verified — runs on node v20.20.2 (file created, header parsed)
const { readFileSync } = require('node:fs');
const file = process.report.writeReport('/tmp/nodeprobe/report.json'); // programmatic autopsy (triggered, not fatal)
const header = JSON.parse(readFileSync(file, 'utf8')).header; // JSON (greppable — attached to tickets, not transcribed)
console.log('report:', header.event === 'JavaScript API' ? 'api-triggered' : header.event, '| node:', header.nodejsVersion.startsWith('v')); // api-triggered | true (evidence, structured)
// BAD: "restart and watch" as the crash procedure ("reports are noise") —
// unreproducible crashes without autopsies recur forever; reports convert recurrence into diagnosis
```

### 3) **Debug through the layers**

**Definition** — the layer-ordered debug: reproduce on bare metal first (strip frameworks — Domain 01/1.1's rule; persists → runtime/app, vanishes → framework config), logs before debugger (cheap history before expensive state — structured logs narrow to the failing exchange; debugger opens on the narrowed suspect), narrow by bisection (half the system disabled — still fails? — the half containing the bug; repeat to one stage). Each step cheaper than the next skipped (logs seconds, debugger minutes, bisect hours saved).

- **Why it matters (effectiveness)**: debugger-first debugging (pausing production for exploration — timeouts cascade; state without history — how did it get here unknown). Framework-first blame (slow route blamed on Express — actually blocked loop; bare-metal repro assigns correctly). Shotgun logging (dozens of lines added, deployed, removed — cycles per guess; bisected narrowing guesses once). Order converts debugging from wandering to converging.
- **Modern guidance** — reproduce minimal first (bare `node:http` + one client — framework stripped; still slow → deeper; fast → framework layer). Read logs before pausing (request ids trace the exchange — suspect identified; debugger confirms, never discovers). Bisect stateless halves first (disable half the middleware — binary search over suspects; stateful halves bisected with fixtures). Record the narrowing (incident notes name each eliminated half — the record teaching the next debug).

```javascript
// GOOD: layered narrowing as procedure — runs on node v20.20.2 (layer named per evidence)
// scenario: POST /upload slow. Step 1 (bare metal): time raw node:http echo — fast → not runtime. Step 2 (logs):
const slow = { route: 'POST /upload', p99: 2400, framework: 'express', bareMetalMs: 40 }; // evidence (numbers, not adjectives)
console.log('layer:', slow.bareMetalMs < 100 && slow.p99 > 1000 ? 'framework/app (bare fast, dressed slow — bisect middleware)' : 'runtime (bare slow too — profile, leaf 1.2)'); // framework/app (assigned by experiment)
// Step 3 (bisect): disable half the middleware — p99 halves? The slow half contains it. Repeat to one stage.
// BAD: pausing production under the debugger as step one ("see what's slow") —
// timeouts fire, users feel it, state without history misleads; layers first, pauses last
```

### 4) **Common confusion**

- "Inspector in production is normal" — inspector is *break-glass* (pauses threads — timeouts cascade; unauthenticated RCE surface; staging always, production via SIGUSR1 with disconnect discipline). Available ≠ advisable.
- "Reports replace logging" — reports autopsy moments (fatal/handled anomalies — deep, rare; logs narrate flows — shallow, constant; both kept, different jobs). Autopsy vs history.
- "Debugger shows the bug" — debugger shows *state* (how it got there needs history — logs, traces, bisect; state without narrative misleads as often as guides). Confirm with debugger; discover with logs.
- "`--inspect` slows everything" — overhead only when attached (unattached inspector idles — flag present, cost absent; attached pauses — cost real; open late, close early). Flag free, session priced.

### 5) **Performance note**

Debugging costs are pause time + overhead, priced per session: attached inspector pauses threads (breakpoints stop the world for that isolate — production pauses cascade to timeouts; staging pauses free). Reports cost a serialization burst (megabytes written at trigger — disk seconds, rare; fatal reports free by definition — process already dying). SIGUSR1 enabling costs nothing until connected (flag flip — zero overhead; the safe production shape). Optimize by narrowing first (logs + bisect before pauses — expensive tools on small suspects), disconnecting always (sessions closed — overhead ended), and autopsying automatically (fatal reports — evidence without presence).

### 6) **Mentor note**

Teach inspection as break-glass ("staging: open freely; production: SIGUSR1, capture, disconnect — recite the discipline" until `0.0.0.0:9229` *looks* hostile). Demo the report (trigger `writeReport`, parse the header — autopsy in ten lines; attach-to-ticket habit formed). Drill layering ("bare-metal first — time it" on every slow report; framework blame requires the bare number). Watch for the pauser (debugger as step one — fix with "show me the logs first") and the restarter ("restart and watch" — fix with "where's the autopsy?"). Review check: inspector localhost-only, reports enabled, logs before pauses, layers narrowed, juniors reproduce bare before blaming frameworks.
