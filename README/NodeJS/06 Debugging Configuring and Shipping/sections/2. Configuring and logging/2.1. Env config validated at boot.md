## 2.1. Env config validated at boot

### 1) **Twelve-factor config, Node-shaped**

**Definition** — configuration lives in the environment (values per deploy — dev/staging/prod differ by env, never by code branch); code declares shapes (names, types, defaults — the contract). Local development reads `.env` files (dotenv-loaded, gitignored — convenience without commitment); every other environment injects real env (containers, orchestrators, CI secrets — no files, no fallbacks to committed values). Committed `.env` is a secret leak with version history (unerasable — rotate, don't regret).

- **What problem it solves**: hardcoded environmentals (ports/URLs/keys in source — staging collides, secrets leak, every env runs the developer's laptop). Branch-per-environment (config in code branches — merges carry values; deploys couple to branches; twelve-factor violated structurally). `.env` committed "temporarily" (temporary lasting years — scanners find it in history; rotation the only remedy). Env-shaped config decouples code from venue (same artifact, all environments — the deployable unit).
- **Modern guidance** — read `process.env` at one module boundary (config.js owns all access — no scattered `process.env` reads; single choke point, validated once). Load `.env` locally only (dotenv in dev entry — production ignores files; missing-file tolerant locally, irrelevant remotely). Gitignore `.env*` except `.env.example` (example documents shapes with dummy values — onboarding copies, never credentials). Fail on unknown venue (no `NODE_ENV` → refuse boot — environments explicit, never defaulted into production).

```javascript
// GOOD: one boundary, shapes declared — runs on node v20.20.2 (parsed config, typed values)
// config.cjs: const raw = { port: process.env.PORT, url: process.env.DATABASE_URL, env: process.env.NODE_ENV };
function loadConfig(env) { const port = Number(env.PORT ?? '3000'); // boundary (all reads here — nowhere else)
  if (!Number.isInteger(port) || port < 1) throw new Error('config: PORT must be a port number'); // named (line 10, not 10,000)
  if (!env.DATABASE_URL) throw new Error('config: DATABASE_URL missing'); // required (fail fast — crash before listen)
  return { port, db: env.DATABASE_URL, env: env.NODE_ENV ?? 'development' }; }
console.log('valid:', JSON.stringify(loadConfig({ PORT: '4000', DATABASE_URL: 'postgres://x' }))); // typed (port number, not string)
try { loadConfig({}); } catch (e) { console.log('invalid:', e.message); } // config: DATABASE_URL missing (named, early)
// BAD: `const port = process.env.PORT || 3000` scattered across six files ("pragmatic") —
// typeless, unvalidated, duplicated: NaN ports listen surprisingly, missing secrets surface mid-request
```

### 2) **Validate once, crash early**

**Definition** — boot-time schema validation (every variable checked once at startup — presence, type, range, format; `zod`/`joi`/`yup` or hand-rolled guards — the library matters less than the timing). Invalid config crashes the process before listening (exit nonzero — orchestrators restart or block rollout; never serve with wrong config — degraded service worse than no service). Validated config frozen (`Object.freeze` — runtime mutation impossible; config read-only after boot; no request handler "adjusts" configuration).

- **Why it matters (operations)**: late-discovered misconfig (missing key surfacing mid-request — 500s for hours before anyone reads the right log; wrong type coercing silently — `"false"` truthy, port NaN listening on surprises). Serving-while-wrong (degraded responses cached downstream — bad data outliving the fix; crash-and-block beats serve-and-corrupt). Mutable config (request-scoped overrides leaking across requests — cross-tenant contamination; frozen config structurally impossible).
- **Modern guidance** — validate everything, default sparingly (required stays required — defaults only for truly optional with safe values; every default documented with why-safe). Name every failure (variable + expectation — `PORT must be 1-65535, got 'abc'`; operators fix from the message, not the source). Freeze after load (mutation attempts throw in strict mode — loud, immediate; config as constant). Gate deploys on boot (healthcheck fails on invalid config — rollout blocks before traffic; crash-early is deploy policy).

```javascript
// GOOD: schema at boot, frozen after — runs on node v20.20.2 (valid frozen, invalid named, mutation throws in strict)
'use strict';
function loadStrict(env) { const errors = []; // collected (all gaps named at once — one crash, full list)
  const port = Number(env.PORT ?? ''); if (!Number.isInteger(port) || port < 1 || port > 65535) errors.push(`PORT must be 1-65535, got ${JSON.stringify(env.PORT)}`);
  if (!/^postgres:\/\//.test(env.DATABASE_URL ?? '')) errors.push('DATABASE_URL must be a postgres:// URL');
  if (errors.length) throw new Error('config invalid:\n- ' + errors.join('\n- ')); // all named (operators fix from message)
  return Object.freeze({ port, db: env.DATABASE_URL }); } // frozen (read-only after boot)
const cfg = loadStrict({ PORT: '5433', DATABASE_URL: 'postgres://db/app' });
console.log('frozen port:', cfg.port, '| frozen:', Object.isFrozen(cfg)); // 5433 | true
try { cfg.port = 1; } catch { console.log('mutation refused (strict mode — config as constant)'); }
try { loadStrict({ PORT: 'abc' }); } catch (e) { console.log('named:\n' + e.message.split('\n').slice(0, 2).join(' | ')); }
// BAD: `if (!process.env.KEY) console.warn('KEY missing, continuing')` ("resilient boot") —
// resilience to misconfiguration is serving-while-wrong; warn-and-continue bills at 3 AM
```

### 3) **Secrets never in code or logs**

**Definition** — secret discipline: values injected (secret managers, mounted files, orchestrator env — never source, never `.env` committed, never chat); references logged, values never (log `db_host`, never the password — structured loggers with redaction lists; error messages scrubbed — connection strings with credentials masked); rotation planned (leak procedure documented — rotate, revoke, redeploy; "unleak" impossible — git history immutable, logs retained). A secret seen is a secret spent (viewed in a log — rotated; pasted in chat — rotated; committed — rotated immediately).

- **Why it hurts when missing (security)**: history-immortal leaks (committed secrets live in clones forever — scanners harvest GitHub; rotation the only fix, forensics the aftermath). Log-aggregated credentials (passwords in centralized logs — readable by every dashboard viewer; breach scope multiplied by retention). Chat-pasted tokens (screenshots, quotes, threads — searched by attackers, remembered by nobody). Each vector closed by one rule: values flow to processes, never to people or pages.
- **Modern guidance** — inject via platform (secret manager → env/file mount — code reads, never stores; local dev uses dummy values — production-shaped, credential-free). Redact at the logger (deny-list keys — `password`, `token`, `secret`, `authorization`; nested scrubbing — deep objects sanitized; redaction tested with hostile fixtures). Mask in errors (connection failures log host + port — never full URLs with credentials; stack traces scrubbed pre-ship). Rotate on exposure (procedure rehearsed — who rotates, what order, how verified; panic replaced by runbook).

```javascript
// GOOD: redaction at the boundary — runs on node v20.20.2 (secrets masked, shapes kept)
const SECRET_KEYS = /password|token|secret|authorization|api[-_]?key/i; // deny-list (tested with hostile fixtures)
function redact(obj) { if (Array.isArray(obj)) return obj.map(redact); if (obj && typeof obj === 'object') { const out = {}; for (const [k, v] of Object.entries(obj)) out[k] = SECRET_KEYS.test(k) ? '[REDACTED]' : redact(v); return out; } return obj; } // deep (nested scrubbed)
const logged = redact({ user: 'amy', password: 'hunter2', nested: { token: 'abc', port: 5432 } });
console.log('safe to log:', JSON.stringify(logged)); // {"user":"amy","password":"[REDACTED]","nested":{"token":"[REDACTED]","port":5432}} (shapes kept, values spent nowhere)
// equivalent hostile test: redact({ Authorization: 'Bearer x', deep: { deep: { api_key: 'y' } } }) — all masked (fixture in the test suite)
// BAD: `console.log('connecting with', connectionString)` ("debugging") —
// credentials in log aggregation, retained 90 days, readable org-wide — debugging as disclosure
```

### 4) **Common confusion**

- "`.env` works in production too" — files couple deploys to hosts (secret files on disk — rotation via redeploy; managers inject without files; `.env` local-only by convention and by `.gitignore`). Local convenience, production injection.
- "Defaults make config resilient" — defaults mask misconfiguration (wrong port defaulted — service runs wrong, healthchecks pass; required stays required — resilience serves traffic, defaults serve confusion). Default the safe, require the rest.
- "`NODE_ENV=production` secures everything" — a flag, not a fortress (perf/behavior switches keyed on it — security needs real controls; unset env defaulting to production — the inversion bug; explicit venue, never defaulted). Flags switch, controls protect.
- "Redaction hurts debugging" — redaction *focuses* debugging (shapes kept — field presence debuggable; values absent — credentials uncompromised; debug with shapes, rotate on exposure). Structure without secrets.

### 5) **Performance note**

Config validation costs once per boot (milliseconds — schema checks beside dependency loading; frozen objects optimize property access — V8 favors stable shapes; negligible beside first request). Redaction costs per log line (regex per key — microseconds; sampling debug logs in hot paths — signal preserved, overhead bounded; structured loggers amortize). Secret-manager fetches cost at boot (network round-trip — cached for process life; refresh on signal, not per request). Optimize validation coverage first (every variable — the incident class retired), redaction testing second (hostile fixtures — leaks caught pre-ship), fetch caching always (boot once — per-request secret reads are latency and cost bugs).

### 6) **Mentor note**

Teach config as a contract review ("read the loader aloud — every variable justified" until scattered `process.env` reads *look* feral). Demo the crash-early (invalid boot — named errors, nonzero exit, rollout blocked; then the warn-and-continue version's 3 AM bill). Demo redaction (hostile fixture through the logger — masked output observed; then the connection-string log — disclosure felt). Drill freeze ("mutate the config — strict throws; design accordingly"). Watch for the scatterer (`process.env` everywhere — fix with "one boundary") and the defaulter (required-with-fallback — fix with "who sets this in prod? — nobody? then crash"). Review check: single boundary, schema at boot, frozen after, secrets injected + redacted, juniors validate before listening.
