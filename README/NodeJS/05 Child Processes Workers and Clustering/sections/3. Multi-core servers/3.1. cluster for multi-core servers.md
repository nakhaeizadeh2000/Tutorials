## 3.1. cluster for multi-core servers

### 1) **One port, N workers**

**Definition** — `node:cluster` forks worker processes sharing one server port (primary opens/listens — accepts distributed by the OS round-robin; workers run the same code guarded by `cluster.isWorker` — each its own loop, heap, and evented capacity). Deaths reforked (`exit` → `fork()` — bounded like any supervision, leaf 1.2; rolling restarts disconnect-then-exit per worker — zero-downtime deploys). Throughput scales with cores (I/O-bound services near-linear to core count — each worker multiplexing independently).

- **What problem it solves**: single-loop ceilings (one process saturating one core while fifteen idle — 1/16th utilization; cluster fills the machine with one port and one codebase). Fork-per-service orchestration (N processes × N ports + a load balancer — operational sprawl; cluster shares the port — the OS balances). Crash-takes-all (uncaught exception killing the only process — all connections drop; worker death drops its share, primary reforks — blast radius divided by N).
- **Modern guidance** — size workers to cores (`availableParallelism()` — minus headroom for the primary; exact for dedicated boxes). Refork on exit, bounded (supervision loop — leaf 1.2; crash-looping workers paged, not infinitely reforked). Roll by disconnect (worker stops accepting, drains, exits — replacement forked first; zero-downtime by sequence, not by hope). Prefer orchestrators at fleet scale (K8s replicas vs in-process cluster — one scaling mechanism per deploy, not both).

```javascript
// GOOD: shared port, served requests, explicit refork, clean shutdown — runs on node v20.20.2
const cluster = require('node:cluster'); const http = require('node:http'); const os = require('node:os');
const PORT = 41234; const N = Math.min(2, os.availableParallelism()); // bounded by cores (production: PORT env)
if (cluster.isPrimary) {
  for (let i = 0; i < N; i++) cluster.fork(); // share the port (OS distributes accepts)
  const count = () => Object.keys(cluster.workers).length;
  setTimeout(async () => {
    console.log('workers sharing port:', count() === N); // structural fact (deterministic — distribution across both varies by load)
    const get = () => new Promise((res) => http.get(`http://127.0.0.1:${PORT}/`, (r) => { let b = ''; r.on('data', (c) => b += c); r.on('end', () => res(b)); }));
    const pids = new Set([await get(), await get(), await get(), await get()]);
    console.log('served 4/4 by workers:', [...pids].join(',')); // pids answer (shared port, OS balance)
    Object.values(cluster.workers)[0].kill('SIGTERM'); // kill one (crash simulation)
    await new Promise((res) => cluster.once('exit', res)); cluster.fork(); // explicit refork (bounded in production — leaf 1.2)
    await new Promise((res) => cluster.once('listening', res));
    console.log('reforked, workers again:', count() === N); // capacity restored (supervision observed)
    for (const w of Object.values(cluster.workers)) w.kill('SIGTERM'); // clean shutdown (no refork listener — none linger)
    setTimeout(() => process.exit(count() === 0 ? 0 : 1), 500); }, 800);
} else { http.createServer((req, res) => res.end(`${process.pid}`)).listen(PORT, '127.0.0.1'); } // workers serve (own loop each)
```

### 2) **Sticky state avoided**

**Definition** — cluster workers share nothing (separate heaps — in-memory sessions visible to one worker only; refork wipes — state dies with the process; requests route arbitrarily — no affinity without extra machinery). Consequence: workers stateless by design (sessions externalized — Redis/database/cookie; caches shared-nothing or external; uploads rendezvous via shared store, never worker memory). Sticky sessions (IP-hash routing) exist as escape hatch — complexity and imbalance priced; avoided unless protocol-bound (WebSocket affinity — even then, external pub/sub preferred).

- **Why it matters (correctness)**: login-then-logout mysteries (session in worker A, next request hits worker B — "random logouts"; in-memory sessions under cluster — the classic deploy-day bug). Refork amnesia (worker restarts — counters, caches, rate-limit buckets reset; limits enforced per worker drift collectively). Rolling-restart skew (old + new code simultaneously — in-memory formats differ; external state versioned, workers disposable).
- **Modern guidance** — externalize sessions first (store-backed — any worker serves any request; refork-safe by construction). Keep workers disposable (kill -9 any worker anytime — no loss beyond in-flight; the litmus test for statelessness). Share caches via external stores (or accept per-worker duplication with TTLs — duplicated-but-fresh beats shared-but-sticky). Sticky only with measured need (protocol affinity proven — priced imbalance accepted explicitly, revisited quarterly).

```javascript
// GOOD: stateless workers, external counter — runs on node v20.20.2 (total exact across workers)
const cluster = require('node:cluster'); const http = require('node:http'); const os = require('node:os'); const fs = require('node:fs');
const PORT = 41235; const COUNT = '/tmp/nodeprobe/cluster-count.txt'; // external state (any worker, any time)
if (cluster.isPrimary) { fs.writeFileSync(COUNT, '0');
  for (let i = 0; i < Math.min(2, os.availableParallelism()); i++) cluster.fork();
  setTimeout(async () => { for (let i = 0; i < 6; i++) await new Promise((res) => http.get(`http://127.0.0.1:${PORT}/hit`, (r) => r.resume().on('end', res)));
    console.log('external total:', fs.readFileSync(COUNT, 'utf8') === '6' ? '6 across workers (stateless — refork-safe)' : 'MISMATCH'); // 6 (no worker memory involved)
    for (const id in cluster.workers) cluster.workers[id].kill('SIGTERM'); setTimeout(() => process.exit(0), 300); }, 800);
} else { http.createServer((req, res) => { const n = Number(fs.readFileSync(COUNT, 'utf8')) + 1; fs.writeFileSync(COUNT, `${n}`); res.end('ok'); }).listen(PORT, '127.0.0.1'); } // read-modify-write (demo-simple; production: atomic store ops)
// BAD: `const sessions = new Map()` in a clustered server ("fast sessions") —
// fast, wrong, and randomly forgetful: affinity-free routing meets worker-local memory — logout roulette
```

### 3) **Cluster vs workers vs processes chosen**

**Definition** — the decision tree for parallelism beyond the loop: I/O fan-out with shared port → `cluster` (many connections, little per-request CPU — web servers; workers stateless, OS balances). CPU tasks with results → worker pool (heavy compute, bounded to cores — hashing, parsing,ML inference slices; leaf 2.1). Isolation/crash/policy boundaries → processes (untrusted code, native crashes, privilege separation — fork/spawn, leaves 1.1–1.2). Shared memory only with receipts (leaf 2.2's gate — measured gap, counted fields). Wrong tool per workload is the common production smell (threads for isolation — crash takes all; processes for CPU slices — fork overhead per task).

- **Why it matters (architecture)**: misrouted parallelism fails characteristically (cluster for CPU-heavy — every worker saturates its core, throughput flat; workers for crash-prone native — one segfault kills all threads; processes for chatty coordination — serialization overhead dominates). Each tool's failure mode names the misapplication (flat scaling → wrong parallel shape; total crashes → wrong isolation; slow coordination → wrong granularity). The tree routes by workload shape, not by familiarity.
- **Modern guidance** — default cluster for stateless HTTP (the common backend — fill cores, share nothing). Default worker pools for CPU tasks (bounded, supervised, messaged). Default processes for untrusted/crashy work (isolation first). Combine deliberately (clustered workers each with a thread pool — web-shaped front, compute-shaped back; complexity budgeted, measured). Revisit per scaling event (traffic shape changes — the tree re-run; yesterday's shape expires).

```javascript
// GOOD: the tree as code comments — decision procedure, runs on node v20.20.2 (prints the route)
function routeWorkload({ cpuMs, untrusted, connections }) {
  if (untrusted) return 'process (fork/spawn — isolation; crashes contained)'; // blast radius first
  if (cpuMs > 10) return 'worker pool (bounded to cores — loop stays free)'; // CPU off-loop
  if (connections > 100) return 'cluster (shared port — fill cores, stateless)'; // fan-out
  return 'single process (the loop suffices — simplest that works)'; // default: no parallelism at all
}
console.log(routeWorkload({ cpuMs: 200, untrusted: false, connections: 50 })); // worker pool (CPU-priced)
console.log(routeWorkload({ cpuMs: 1, untrusted: true, connections: 10 })); // process (trust-priced)
console.log(routeWorkload({ cpuMs: 1, untrusted: false, connections: 5000 })); // cluster (fan-out-priced)
// BAD: "we use workers for everything" (one hammer — crash-prone parsers share fate, chatty tasks serialize) —
// hammers pound screws; route per workload, measure per route
```

### 4) **Common confusion**

- "Cluster shares memory between workers" — separate processes (heaps isolated — like fork; shared port, not shared state; sticky bugs prove it). Share the port; externalize the state.
- "More workers than cores helps bursts" — workers past cores queue on CPU (I/O-bound absorbs some oversubscription — CPU-bound collapses; measure the knee, size to it). Cores bound compute; oversubscription borrows.
- "Primary should serve requests too" — primary supervises (accepts distributed to workers — primary handling requests risks supervision latency; dedicated primary stays responsive to deaths). Supervise, don't serve.
- "Sticky sessions solve state" — stickiness papers over statefulness (imbalance — hot clients pin workers; refork drops pinned state anyway; externalization solves, affinity postpones). Externalize first, affinitize never (almost).

### 5) **Performance note**

Cluster costs are per-worker processes, priced per core: memory × N (heaps per worker — 50 MB × 8 workers baseline; accounted in capacity math). Throughput near-linear for I/O-bound (each worker multiplexing — the C10K shape × N; CPU-bound flat past cores — expected, not failure). Refork costs a cold worker (JIT warmup per replacement — rolling restarts stagger to keep warm capacity; health gates before traffic). Load distribution OS-round-robins (even enough — hot-client skew possible; external LB for fine control). Optimize worker count first (cores ± headroom — measured knee), statelessness second (external state removes affinity costs), restart sequencing always (drain before exit — warm capacity preserved).

### 6) **Mentor note**

Teach cluster as "fork with a shared port" ("same supervision, plus OS balancing — draw primary vs workers" until statelessness follows unprompted). Demo distribution live (4 requests, 2 pids — shared port observed; then kill a worker — reforked, traffic continues; supervision felt). Demo statelessness (in-memory counter under cluster — counts diverge per worker; then external — exact; state lesson in two runs). Drill the tree ("CPU 200 ms, untrusted parser, 5k conns — route each" — three workloads, three tools). Watch for the multiplier (`cpus × 4` — fix with "measure the knee") and the session-mapper (in-memory sessions — fix with "kill -9 a worker mid-session"). Review check: workers bounded, state external, restarts rolling, tree routed, juniors externalize before clustering.
