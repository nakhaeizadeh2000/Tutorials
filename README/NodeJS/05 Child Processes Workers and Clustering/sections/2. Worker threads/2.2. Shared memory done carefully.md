## 2.2. Shared memory done carefully

### 1) **SharedArrayBuffer shares, Atomics synchronize**

**Definition** — `SharedArrayBuffer` is memory visible to multiple threads (one allocation, many accessors — no cloning, no transfer; same bytes, every worker), and `Atomics` is the discipline making sharing correct (`add`/`sub`/`or` — indivisible read-modify-write; `load`/`store` — tearing-free access; `wait`/`notify` — blocking coordination). Unsynchronized sharing races (`counter++` as read-add-write across threads — increments lost; torn reads on some architectures — garbage values, no errors). Sharing without Atomics is a data race with documentation.

- **What problem it solves**: clone-per-update overhead (counters messaged per increment — thousands of messages/sec for one number; shared counter — zero messages, atomic ops). Coordinated startup/shutdown (workers waiting on a shared flag — `Atomics.wait` sleeps efficiently; polling wastes a core per waiter). But each solution prices complexity (every shared byte needs a synchronization story — stories reviewed, stories tested, stories occasionally wrong).
- **Modern guidance** — Atomics for every shared access (no bare indexing on shared arrays — `Atomics.load` reads, `Atomics.add` mutates; bare access is the race). `wait`/`notify` for coordination (sleeping beats spinning — `Atomics.wait` parks the thread; timeouts on waits — deadlocks bounded). Keep the shared surface minimal (counters, flags, indexes — bulk data transferred, leaf 2.1; every shared field justified in a comment).

```javascript
// GOOD: shared counter, atomic discipline — runs on node v20.20.2 as ESM (200000 exactly, no lost updates)
import { Worker } from 'node:worker_threads'; import { writeFileSync } from 'node:fs';
writeFileSync('/tmp/nodeprobe/adder2.cjs', `const { parentPort, workerData } = require('node:worker_threads'); const c = new Int32Array(workerData); for (let i = 0; i < 100000; i++) Atomics.add(c, 0, 1); parentPort.postMessage('done');`); // atomic increments (indivisible — none lost)
const shared = new SharedArrayBuffer(4); // 4 bytes shared (one counter, two workers)
const run = () => new Promise((res, rej) => { const w = new Worker('/tmp/nodeprobe/adder2.cjs', { workerData: shared }); w.on('error', rej); w.on('message', async () => { await w.terminate(); res(); }); });
await Promise.all([run(), run()]); // 2 × 100000 atomic adds (parallel, synchronized)
console.log('shared total:', new Int32Array(shared)[0] === 200000); // true (races retired by Atomics)
// BAD: `shared[0]++` from two workers ("increment is atomic, right?") —
// read-add-write in three steps: interleavings lose updates; final < 200000, silently, sometimes
```

### 2) **Share little, message mostly**

**Definition** — the sharing budget: shared memory carries coordination state (counters, flags, work indexes — bytes both sides mutate with atomic discipline), messages carry everything else (tasks in, results out — cloned or transferred, leaf 2.1). Shared-everything architectures share bugs (every field a race candidate — review surface explodes; lock design for compound invariants — deadlock territory; debugging needs thread-aware tooling). Message-mostly keeps the concurrent surface tiny (the shared set fits in a comment; everything else flows through channels).

- **Why it matters (correctness)**: compound-invariant races (check-then-act across two shared fields — individually atomic, jointly racy; locks or redesign required — complexity compounding per field). Debugging opacity (thread interleavings unreproducible — heisenbugs; message logs replayable — determinism recoverable). Scaling ceilings (cache-line bouncing on hot shared words — false sharing slows all cores; per-worker state + messages scales linearly).
- **Modern guidance** — share scalars, message structures (numbers/flags shared — objects/arrays messaged; the line drawn by mutation scope). One writer per shared word where possible (single-writer principle — readers need no locks for monotonic data; writers serialized by construction). Document each shared field (what, who writes, sync primitive — the comment block reviewed like a lock specification). Default to channels (sharing proposed with measurements — point 3; messages the unmarked default).

```javascript
// GOOD: shared flag coordinates, messages carry — runs on node v20.20.2 as ESM (flag seen, payload messaged)
import { Worker } from 'node:worker_threads'; import { writeFileSync } from 'node:fs';
writeFileSync('/tmp/nodeprobe/flagger.cjs', `const { parentPort, workerData } = require('node:worker_threads'); const f = new Int32Array(workerData); let n = 0; const t = setInterval(() => { if (Atomics.load(f, 0) === 1) { clearInterval(t); parentPort.postMessage({ payload: 'saw-flag@' + (++n) }); } }, 5);`); // polls the flag (coordination state — shared)
const flag = new SharedArrayBuffer(4); // one word shared (the whole concurrent surface — auditable in a glance)
const w = new Worker('/tmp/nodeprobe/flagger.cjs', { workerData: flag }); w.on('error', () => {});
const got = new Promise((res) => w.once('message', async (m) => { await w.terminate(); res(m); }));
Atomics.store(new Int32Array(flag), 0, 1); // signal (atomic store — the flag, not the data)
console.log('coordinated:', (await got).payload.startsWith('saw-flag@')); // true (flag shared, payload messaged — each in its lane)
// BAD: shared object graph with ad-hoc locking ("faster than messages") —
// faster to write, necromancy to debug: races unreproducible, locks deadlocking, reviewers resigning
```

### 3) **Measure before sharing**

**Definition** — the sharing gate: profile the message path first (clone/transfer timings at production sizes — often fast enough; 10 MB structured-clone in milliseconds — sharing saves little), price the complexity (synchronization stories per field — review cost, test cost, heisenbug risk), share only with receipts (measured gap × traffic > complexity cost — arithmetic, not ambition). Most sharing proposals die at the gate (messages suffice — the common outcome; sharing earned rarely, celebrated never).

- **Why it matters (economics)**: premature sharing mortgages debugging (heisenbugs billed over quarters — the most expensive category per incident-hour; saved microseconds per message). Unmeasured "fast" (shared path assumed quicker — unprofiled; clone of small messages is nanoseconds — sharing saves nothing measurable). Complexity without receipts (locks added "for scale" pre-launch — scale never arrives; complexity stays forever).
- **Modern guidance** — benchmark clone vs share at real sizes (production payloads, production rates — the numbers that decide; sub-millisecond differences don't earn races). Count the shared fields (each needs story + test — budget explicit; past ~5 fields, redesign to messages). Revisit per scaling event (new core counts, new payload sizes — gates re-run; yesterday's verdict expires with today's traffic). Document the receipt (numbers in the commit — future readers see why sharing exists).

```javascript
// GOOD: the gate run before the sharing decision — runs on node v20.20.2 (clone timed, verdict stated)
const payload = Buffer.alloc(1024 * 1024, 9); // 1 MB production-shaped (the size that decides)
let t = process.hrtime.bigint(); const clone = Buffer.from(payload); // clone path (the default — timed)
console.log('1 MB clone ms:', Number(process.hrtime.bigint() - t) / 1e6, '(sub-millisecond — sharing would save ~nothing here)');
console.log('verdict: message it (receipts beat ambition — share only past measured pain)');
// BAD: SharedArrayBuffer on day one ("scale-ready architecture") —
// scale arriving never, races arriving quarterly; readiness without receipts is just risk
```

### 4) **Common confusion**

- "`Atomics` makes shared code safe" — Atomics makes *operations* indivisible (compound logic still races — check-then-act needs locks or redesign; safe words, unsafe sentences). Primitives, not proofs.
- "Shared memory is always faster" — faster past copy cost (small messages clone in nanoseconds — sharing saves nothing; complexity costs everything; threshold measured, never assumed). Sized, not dogmatic.
- "`wait` blocks the loop" — `wait` parks *worker* threads (`Atomics.wait` forbidden on the main thread — throws; coordination lives off-loop by construction). Parked workers, free loop.
- "`Buffer.from(shared)` shares the memory" — copies it (`from` duplicates — views via `new Uint8Array(sab)` share without copying; ownership explicit per construction). Views share; copies detach.

### 5) **Performance note**

Sharing costs are synchronization + coherence, priced per access: atomic ops cost cache-coherence traffic (uncontended — nanoseconds; hot shared words bounce cache lines across cores — false sharing slows *all* accessors; pad or partition hot words). `wait`/`notify` cost a futex round-trip (microseconds — cheaper than spin-waiting a core; timeouts bound the wait). Clone path costs bandwidth (GB/s — 1 MB in sub-milliseconds, measured above). Optimize access patterns first (partition hot words — coherence traffic dominates), sharing scope second (fewer fields — fewer stories), mechanism last (Atomics intrinsics already minimal — no lower level to reach for).

### 6) **Mentor note**

Teach sharing as danger with receipts ("show me the benchmark" before every SharedArrayBuffer — gatekeeping as care; students message by default). Demo the race live (bare `++` from two workers × 100k — final short of 200000, nondeterministically; then Atomics — exact; races felt). Demo detachment vs sharing (transferred buffer detached sender-side; shared word visible both sides — ownership models contrasted). Drill the budget ("list every shared field and its sync story" — past five, redesign demanded). Watch for the premature-sharer ("scale-ready" — fix with "show receipts") and the bare-indexer (`shared[0]++` — fix with the race demo: run it, count short). Review check: accesses atomic, fields few and documented, cargo messaged, gate run with numbers, juniors share last, not first.
