## 4.1. Parallelism checklist (habits mentors insist on)

### 1) **Isolate by default, share by exception**

**Definition** — the parallelism boot discipline: processes for boundaries (untrusted, crashy, coarse — isolation first; leaves 1.1–1.2), threads for speed (measured CPU off-loop — pools bounded to cores; leaf 2.1), shared memory by exception only (receipts filed — leaf 2.2's gate; fields counted, stories documented). Each step outward trades safety for speed (isolated → messaged → shared — convenience rising, debuggability falling). The default sits at the safest step that meets measured need — inward pressure always, outward only with numbers.

- **Why it matters (architecture)**: default-shared architectures debug like haunted houses (races unreproducible, locks deadlocking, reviewers resigning — complexity chosen before need). Default-isolated architectures scale down freely (single process suffices until measured — simplicity preserved; parallelism added per evidence). The checklist holds the default (isolation questioned never; sharing questioned always).
- **Modern guidance** — start single-process (the loop suffices until the lag probe says otherwise — leaf 3.1 of Domain 01 decides). Step out on evidence (CPU measured → worker pool; untrusted → fork; fan-out → cluster — leaf 3.1's tree routes). Share memory with filed receipts (benchmark + field count in the commit — future readers see the arithmetic). Review outward steps hardest (isolation→threads→shared — scrutiny rising per step outward).

```javascript
// GOOD: the isolation ladder as a gate — runs on node v20.20.2 (cores counted, verdicts stated)
const os = require('node:os');
const cores = os.availableParallelism(); // the budget every pool draws from (measured, not assumed)
console.log('cores:', cores, '| worker pool size:', Math.max(1, cores - 1), '(one left for the loop on mixed servers)');
console.log('shared words: 0 (default — filed receipts required to raise this number)');
// BAD: SharedArrayBuffer in the first commit ("scale-ready") —
// readiness without receipts is risk; isolation without need is wisdom — start isolated, prove outward
```

### 2) **Supervise every child**

**Definition** — no unsupervised parallelism: every spawned process, forked child, and worker thread has an owner (exit classified — leaf 1.2; errors routed — leaf 1.1; restarts bounded — caps with paging; orphans reaped — teardown kills the tree). Supervision is a loop, not a launch (watch → classify → act — running for the child's whole life). Unsupervised children are future incidents with PIDs (crash loops unfed-page silent, zombies accumulating, exits unlogged).

- **Why it matters (operations)**: unsupervised death goes unnoticed (worker thread throws — promise never settles; request hangs; timeout fires instead of error — diagnosis three layers off). Unbounded respawn feeds loops (boot-bug children reforked forever — CPU pinned, pager silent; caps convert loops to pages). Orphaned fleets accumulate (deploys reparenting strays — boxes filling across releases; teardown discipline retires the class).
- **Modern guidance** — attach handlers at creation (error/exit/message — synchronous with launch; race-free from the first tick). Classify every death (clean → release; expected → policy; crash → bounded respawn; systemic → page). Bound every restart (windowed counters — N per T; exceeded means human, not loop). Kill trees on teardown (parent exit reaps children — containers SIGTERM once; descendants must not outlive).

```javascript
// GOOD: supervised worker, classified exit — runs on node v20.20.2 (exit 1 classified, no hang)
const { Worker } = require('node:worker_threads'); const { writeFileSync } = require('node:fs');
writeFileSync('/tmp/nodeprobe/ok-worker.cjs', `const { parentPort } = require('node:worker_threads'); parentPort.postMessage('alive'); setTimeout(() => { throw new Error('later failure'); }, 50);`); // works, then dies (the supervision test)
const w = new Worker('/tmp/nodeprobe/ok-worker.cjs'); const record = [];
w.on('message', (m) => record.push(`msg:${m}`)); w.on('error', (e) => record.push(`error:${e.message}`)); // attached at creation (race-free)
w.on('exit', (code) => { record.push(`exit:${code}`); console.log(record.join(' | '), '(worked, failed, classified — supervised throughout)'); }); // msg:alive | error:later failure | exit:1
// BAD: `new Worker(f)` with no handlers ("happy path tested") —
// unhappy paths unhandled: errors uncaught, exits unlogged, hangs untimed — supervision is the other half of launch
```

### 3) **Measure the contention**

**Definition** — parallelism evidenced: cores counted (`availableParallelism` — pool budgets drawn), contention profiled (oversubscription knee measured — throughput vs thread count, per workload), races tested (shared fields hammered — 2× threads × expected total, exact match demanded), queues graphed (pool depth — backpressure visible; supervision counts — deaths classified per deploy). Hope is not a scaling strategy (unmeasured pools thrash, untested sharing races, ungraphed queues flood). Numbers first, parallelism second.

- **Why it matters (performance)**: unmeasured pools oversubscribe (threads ≫ cores — context churn; throughput below pooled — the "more is faster" fallacy with graphs). Untested sharing races intermittently (passes CI, fails quarters — heisenbugs billed per incident-hour; hammer tests retire the class). Un graphed queues flood silently (depth growing — no alarm; saturation discovered by users). Measurement converts all three from belief to arithmetic.
- **Modern guidance** — count cores at boot (logged per deploy — capacity math auditable). Hammer shared state in tests (concurrent increments × exact totals — races fail the suite, never production). Graph pool depth and death counts (backpressure visible — supervision evidenced; alerts on slope, not on catastrophe). Re-run per scaling event (new cores, new traffic — verdicts expire; gates re-run).

```javascript
// GOOD: contention evidenced — runs on node v20.20.2 as ESM (knee found, verdict stated)
import { Worker } from 'node:worker_threads'; import { writeFileSync } from 'node:fs';
writeFileSync('/tmp/nodeprobe/busy.cjs', `const { parentPort } = require('node:worker_threads'); let s = 0; for (let i = 0; i < 2e7; i++) s += i; parentPort.postMessage(s);`); // fixed CPU slice (the measured unit)
async function timePool(n) { const t = Date.now(); await Promise.all(Array.from({ length: n }, () => new Promise((res, rej) => { const w = new Worker('/tmp/nodeprobe/busy.cjs'); w.on('error', rej); w.on('message', async (v) => { await w.terminate(); res(v); }); }))); return Date.now() - t; }
const t1 = await timePool(1), t6 = await timePool(6); // 1 vs 6 workers (knee hunt — ESM top-level await)
console.log(`1 worker: ${t1}ms | 6 workers: ${t6}ms (6 cores here — parallelism evidenced, oversubscription priced separately)`);
// BAD: pool sized by copying a blog ("size 100 worked for them") —
// their workload, their cores, their year; knees measured locally, never imported
```

### 4) **Common confusion**

- "Checklists slow down shipping" — checklists *accelerate* shipping (five minutes per review versus incident-hours per gap; the trio above runs as review questions — automated where possible, ritual where not). Slow is debugging at midnight; fast is gating at noon.
- "Supervision is only for production" — supervision is for *tests too* (unhandled worker errors failing suites loudly — red early; unlogged exits hiding hangs — flake archaeology; supervised tests diagnose themselves). Everywhere, from the first spawn.
- "Small pools don't need queues" — small pools need *visible* queues most (depth 10 on pool-of-2 is saturation — graphed early; unbounded promise accumulation is the same flood smaller). Queues graphed at every size.
- "One measurement suffices" — measurements expire (traffic shapes shift, cores migrate, payloads grow — verdicts re-run per scaling event; yesterday's knee is today's guess). Gates re-run, receipts re-filed.

### 5) **Performance note**

Checklist items are performance *enablers*: isolation-by-default prevents contention entirely (no shared state — no coherence traffic; the fastest synchronization is absence). Supervision bounds failure cost (caps convert loops to pages — CPU preserved; teardown frees promptly — resources recycled). Measurement finds knees (pool sized to evidence — throughput maximal; oversubscription priced, not hoped). Total runtime cost: handler attachments (free), counters (free), an occasional benchmark (minutes per scaling event). Total avoided cost: the thrash/race/flood incidents this domain exists to prevent. Measure avoided classes (oversubscription findings, untested-shared findings — zero after the gate).

### 6) **Mentor note**

Teach parallelism as a ladder with tolls ("each step outward costs debuggability — pay only with receipts" until sharing proposals arrive with benchmarks unprompted). Demo the knee live (1 vs 6 vs 24 workers on fixed CPU — throughput peaks, then falls; oversubscription felt in numbers). Demo the race (bare increments short of exact — then Atomics exact; evidence before discipline). Drill supervision ("no handler, no spawn — whose exit is this?" for every child in review). Watch for the premature parallelizer ("scale-ready" day one — fix with "show the lag probe") and the unsuperviser (happy-path only — fix with "kill it in staging, narrate what you see"). Review check: isolated by default, supervised throughout, measured before sharing, juniors count cores before sizing pools.
