# 1.2. Health gating traffic

## 1. Probes splitting (live cheaping — ready deeping — traffic gating)

**Definition** — split health probes: cheap liveness with deep readiness gating traffic (live cheaping — processes answering (sockets opening — aliveness proving (cheaping proving — costing declining); ready deeping — dependencies checking (stores pinging — traffic deserving (deeping funding — shallowing declining); traffic gating — unready shedding (unlively restarting (verdicts acting — orchestrators deciding (gating owning — misrouting declining).

**What problem it solves** — the single-probe trio: *probes unmerged* (checks shallowing — dependencies dying (traffic routing — requests failing (unmerged billing — truth hiding); *restarts unlooping* (readiness unfailing — liveness unshared (orchestrators unkilling — boots uncrashing (unlooping charging — recovery failing); *traffic unmisrouting* (unready serving — requests failing (clients retrying — balancing blind (unmisrouting costing — truth untelling). Split probes converting merging to cheaping (processes answering — dependencies checking (unready shedding — verdicts acting); reviewers finding probe splits per service (splitting proving → verifiable; merging → returned).

**Modern guidance** — the splitting lines per service (review-enforced): *live cheaping* ([Fastify 05/2.2](<../../../../Fastify/05 Testing Deployment and Operations/sections/2. Delivery/2.2. Graceful shutdown and probes.md>) — processes answering (sockets opening — aliveness proving (cheaping proving — costing refusing (cheapness earning — restarts gating); *ready deeping* ([Fastify 05/2.2](<../../../../Fastify/05 Testing Deployment and Operations/sections/2. Delivery/2.2. Graceful shutdown and probes.md>) — dependencies checking (stores pinging — traffic deserving (deeping funding — shallowing refusing (depths owning — truth telling); *traffic gating* (unready shedding — unlively restarting (verdicts acting — orchestrators deciding (gating owning — misrouting refusing (verdicts funding — availability defending).

```typescript
// GOOD: probes splitting — cheap liveness with deep readiness (compiled + run live).
interface Probes { // live cheaping — processes answering, costing declining
  live: boolean;
  readyDeps: boolean[];
}
function verdict(p: Probes): string {
  if (!p.live) return 'RESTART'; // ready deeping — dependencies checking, shallowing declining
  if (p.readyDeps.some((d) => !d)) return 'SHED';
  return 'SERVE'; // traffic gating — unready shedding, misrouting declining
}
const healthy: Probes = { live: true, readyDeps: [true, true] };
const unready: Probes = { live: true, readyDeps: [true, false] };
const dead: Probes = { live: false, readyDeps: [false, false] };
console.log(verdict(healthy) === 'SERVE' && verdict(unready) === 'SHED' && verdict(dead) === 'RESTART' ? 'probes split' : 'health merges');
```

```typescript
// BAD: health merging — single shallow probe, restarts looping (real lie shape).
// app.get('/health', () => 'ok'); // checks shallowing — dependencies dying, truth hiding.
// // Ready shares live (orchestrators killing — boots crashing). Cheapen live; deepen ready; gate traffic.)
```

**Common confusion** — *"one probe suffices (checks simplifying)."* Simplifying merging verdicts (checks shallowing — restarts looping (traffic misrouting — truth hiding (simplifying charging — correctness failing); splitting cheapening live (processes answering — sockets opening (aliveness proving — restarts gating (splitting proving — merging declining). "Suffices" describing singularity (checks merging — verdicts lying); probes describing verdicts (live cheaping — ready deeping). Answer live cheaply (processes answering — restarts gating); ping ready deeply (dependencies checking — traffic deserving).

**Performance note** — splitting economics: cheaping costing nothing (processes answering — sockets opening (aliveness proving — restarts gating); deeping costing pings (dependencies checking — stores pinging (traffic deserving — serving proving); merged equivalents costing misroutes (unready serving — requests failing (clients retrying — trust eroding). Cheapen live (answers — nothing); deepen ready (pings — truth).

**Mentor note** — teach "live answers process, ready answers dependencies" (juniors splitting one probe pair per service design lie-proof health on first hearing; merged probes interrogated ("ready checks what?" — splitting demanding per service). Split one probe once (live cheaping — ready deeping tangible (merging ending — splitting proving permanently). Prove aliveness; earn traffic — splitting discipline in three habits, reviewed per service.

## 2. Drains landing (accepts stopping — inflight completing — exits timing)

**Definition** — landed drains: stopped accepts completing inflight timing exits (accepts stopping — sockets closing (connections draining — losses preventing (stopping proving — severing declining); inflight completing — requests finishing (writes landing — data preserving (completing funding — dropping declining); exits timing — graces capping (hangs abandoning (force ensuring — deadlocks ending (timing owning — lingering declining).

**What problem it solves** — the abrupt trio: *accepts unseversing* (sockets unclosing — connections unsevered (writes dropping — data losing (unseversing billing — grace failing); *inflight undropping* (requests unfinishing — writes unlanding (clients hanging — trust eroding (undropping charging — preservation failing); *exits untiming* (graces uncapping — hangs unabandoned (force unensured — deadlocks ruling (untiming costing — liveness bluffing). Landed drains converting severing to stopping (sockets closing — requests finishing (graces capping — data preserving); reviewers finding drain handlers per service (landing proving → verifiable; severing → returned).

**Modern guidance** — the landing lines per service (review-enforced): *accepts stopping* ([Express 05/2.2](<../../../../Express/05 Testing Deployment and Operations/sections/2. Delivery/2.2. Graceful shutdown and probes.md>) — sockets closing (connections draining — losses preventing (stopping proving — severing refusing (stops earning — data keeping); *inflight completing* (requests finishing — writes landing (data preserving — dropping declining (completing funding — hanging refusing (finishes keeping — trust earning); *exits timing* (graces capping — hangs abandoning (force ensuring — deadlocks ending (timing owning — lingering refusing (caps funding — liveness earning).

```typescript
// GOOD: drains landing — stopped accepts completing inflight (compiled + run live).
function drain(inflight: number, graceMs: number, elapsedMs: number): string {
  if (inflight === 0) return 'EXIT-CLEAN'; // accepts stopping — sockets closing, severing declining
  if (elapsedMs >= graceMs) return 'EXIT-FORCE'; // exits timing — graces capping, lingering declining
  return 'DRAINING'; // inflight completing — requests finishing, dropping declining
}
console.log(drain(0, 5000, 0) === 'EXIT-CLEAN' && drain(3, 5000, 1000) === 'DRAINING' && drain(3, 5000, 6000) === 'EXIT-FORCE' ? 'drains land' : 'terms sever');
```

```typescript
// BAD: terms severing — accepts unseversing, exits untiming (real cut shape).
// process.on('SIGTERM', () => process.exit(0)); // connections severing — writes dropping, data losing.
// // No grace (hangs lingering — deadlocks ruling). Stop accepts; finish inflight; time exits.)
```

**Common confusion** — *"drains delay deploys (graces stalling)."* Stalling postponing rollouts (waves waiting — fleets lingering (ships slowing — momentum dying (stalling charging — courage taxing); landing preserving data (sockets closing — requests finishing (graces capping — losses preventing (landing proving — severing declining). "Delaying" describing unbounded waits (graces uncapping — hangs lingering); drains describing bounds (accepts stopping — exits timing). Close sockets (accepts stopping — losses preventing); cap grace (hangs abandoning — deadlocks ending).

**Performance note** — landing economics: stopping costing handlers (sockets closing — requests finishing (graces capping — data preserving); severed equivalents costing loss (writes dropping — data losing (clients hanging — trust eroding). Stop cheaply (accepts — handlers); sever never (terms — connections).

**Mentor note** — teach "stop, finish, then exit — always bounded" (juniors landing one drain per service design sever-proof shutdowns on first hearing; handlerless terms interrogated ("drain?" — landing demanding per service). Land one drain once (sockets closing — requests finishing tangible (severing ending — landing proving permanently). Close accepts; bound grace — landing discipline in three habits, reviewed per service.

## 3. Verdicts acting (unready shedding — unlively restarting — orchestrators deciding)

**Definition** — acted verdicts: shed unready restarting unlively deciding orchestrators (unready shedding — routes updating (traffic rerouting — failures avoiding (shedding proving — serving declining); unlively restarting — corpses replacing (crashes recovering — capacity restoring (restarting owning — lingering declining); orchestrators deciding — platforms polling (verdicts reading — actions taking (deciding funding — hoping declining).

**What problem it solves** — the ignored-verdict trio: *unready unshedding* (routes unupdating — traffic unrerouted (failures arriving — users suffering (unshedding billing — gating theatering); *unlively unrestarting* (corpses unreplaced — crashes unrecovered (capacity leaking — availability dipping (unrestarting charging — healing missing); *orchestrators undeciding* (platforms unpolling — verdicts unread (actions untaken — automation absent (undeciding costing — toil ruling). Acted verdicts converting ignoring to shedding (routes updating — corpses replacing (platforms polling — verdicts working); reviewers finding verdict actions per probe (acting proving → verifiable; ignoring → returned).

**Modern guidance** — the acting lines per verdict (review-enforced): *unready shedding* (routes updating — traffic rerouting (failures avoiding — serving declining (shedding proving — updating refusing (updates earning — suffering ending); *unlively restarting* (corpses replacing — crashes recovering (capacity restoring — lingering declining (restarting owning — leaking refusing (replacements keeping — availability earning); *orchestrators deciding* (platforms polling — verdicts reading (actions taking — hoping declining (deciding funding — absenting refusing (decisions owning — toil ending).

```typescript
// GOOD: verdicts acting — shed unready restarting unlively (compiled + run live).
function act(live: boolean, ready: boolean): string {
  if (!live) return 'RESTART'; // unlively restarting — corpses replacing, lingering declining
  if (!ready) return 'SHED'; // unready shedding — routes updating, serving declining
  return 'ROUTE'; // orchestrators deciding — platforms polling, hoping declining
}
console.log(act(true, true) === 'ROUTE' && act(true, false) === 'SHED' && act(false, false) === 'RESTART' ? 'verdicts act' : 'probes ignored');
```

```typescript
// BAD: probes ignoring — unready unshedding, orchestrators undeciding (real theater shape).
// // Health endpoint exists (routes unupdating — actions untaken — automation absent).
// // Nobody polls (verdicts unread — toil ruling). Shed unready; restart unlively; let platforms decide.)
```

**Common confusion** — *"verdicts are informational (endpoints decorating)."* Decorating answering humans (dashboards greening — operators nodding (automation absenting — toil ruling (decorating charging — action failing); verdicts driving platforms (routes updating — corpses replacing (traffic rerouting — capacity restoring (driving proving — ignoring declining). "Informational" describing dashboards (endpoints answering — humans nodding); verdicts describing control (platforms polling — actions taking). Poll verdicts (platforms reading — toil ending); act automatically (routes updating — corpses replacing).

**Performance note** — acting economics: shedding costing updates (routes updating — corpses replacing (platforms polling — verdicts working); ignored equivalents costing theater (failures arriving — capacity leaking (automation absent — toil ruling). Act cheaply (verdicts — probes); ignore never (health — platforms).

**Mentor note** — teach "every verdict moves traffic or processes" (juniors acting one action per verdict design theater-proof health on first hearing; unactioned probes interrogated ("then what?" — acting demanding per verdict). Act one verdict once (routes updating — corpses replacing tangible (ignoring ending — acting proving permanently). Shed unready; replace corpses — acting discipline in three habits, reviewed per probe.
