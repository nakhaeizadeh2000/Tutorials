# 5.1. Common interview QA async events

## 1. Events live under pressure (facts, versions, delivery — diagnosed with fixes, priced)

**Definition** — the events answer interviewers grade: given a fact flow, name the event with keys ([1.1](<../../sections/1. Event thinking/1.1. Events streaming facts.md>)) — facts proving (past-tensing — payloads bounding (consumers trusting — commanding declining (proving owning — imperativing declining); versions proving (schemas numbering — readers tolerating (breaks dating — freezing declining (proving funding — ambushing declining); delivery proving (at-least-once owning — duplicates expecting (keys demanding — hoping declining (proving earning — doubling declining). "Live" means diagnosed fixes (tenses naming — versions tagging — keys requiring (proof stating — bluffing declining).

**What problem it solves** — the reciting trio: *facts reciting* (events naming — tenses unmentioned (payloads undescribed — consumers untrusted (reciting serving — hiring failing (knowledge hoping — depth doubting); *versions confusing* (schemas equating — readers unplaced (breaks unjudged — trust burning (conflating owning — clarity missing (confusion serving — confidence failing (placing hoping — precision doubting); *delivery hoping* (duplicates unassumed — keys undemanded (effects doubling — ledgers drifting (hoping serving — incidents inviting (judgment failing — experience doubting). Pressured events converting reciting to diagnosing (past-tensing — schemas numbering (duplicates expecting — answers holding); interviewers hearing facts with keys, not event names (diagnosing proving → hirable; reciting → passed) — drawing on [1.1](<../../sections/1. Event thinking/1.1. Events streaming facts.md>).

**Modern guidance** — the events lines (interview-enforced): *facts tensing* (past-naming — payloads bounding (consumers trusting — commanding declining (tensing proving — imperativing refusing); *versions tagging* (schemas numbering — readers tolerating (breaks dating — freezing declining (tagging funding — ambushing refusing); *delivery keying* (duplicates expecting — ids requiring (effects converging — doubling declining (keying owning — hoping refusing). Every claim carrying tense + version + key (judgment demonstrable — pressure survivable).

```typescript
// GOOD: events answers — tenses, versions, keys with diagnosed fixes (answer shape, hiring-grade).
// "order.placed past-tense with id+total (facts tensing — payloads bounding — consumers trusting).
//  v2 additive with tolerant readers (versions tagging — unknowns ignoring — breaks dating).
//  Handlers dedupe on event id (delivery keying — repeats converging — effects holding).")
```

```typescript
// BAD: events recitals — names without tenses, hopes without keys (real fail shape).
// // "We publish OrderCreated." (tenses unmentioned — payloads undescribed — knowledge hoping).
// // "Broker handles it." (keys undemanded — effects doubling). Tense facts; tag versions; demand keys.)
```

**Common confusion** — *"naming events answers messaging (topics stating)."* Stating listing topics (letters reciting — brokers naming (shapes describing — keys missing (stating serving — owning failing); answering proving delivery (past-tensing — versions tagging (duplicates expecting — effects converging (proving funding — reciting declining). "Answering" describing judgments (tenses naming — keys requiring); naming describing vocabulary (topics spelling — meaning missing). Tense facts (names past-tensing — histories appending); key handlers (ids requiring — replays converging).

**Performance note** — events-answer economics: diagnosing costing triples (tenses stating — versions tagging (keys requiring — answers holding); reciting equivalents costing doubt (names listing — judgments missing (depth doubting — hiring failing). State cheaply (triples — events); recite never (names — hopes).

**Mentor note** — drill "tense, version, key" (candidates answering per event with past names, schema tags, and dedup keys defend events on first hearing; name-only answers interrogated ("tensed? versioned? keyed?" — events demanding per claim). Rehearse one event story once (tense-version-key tangible (reciting ending — diagnosing proving permanently). Name pasts; require ids — events answers in three artifacts, reviewed per interview.

**Cross-links** — fact depth in [1.1](<../../sections/1. Event thinking/1.1. Events streaming facts.md>); emit proof in [3.1](<../../sections/3. Async vehicle/3.1. NestJS event slice emitting subscribing.md>); checklist in [4.1](<../../sections/4. Mentor checklist/4.1. Async checklist mentors insist on.md>).

## 2. Flows live under pressure (reactions, topology, traces — honesty stated, not hoped)

**Definition** — the flows answer interviewers grade: given an event flow, name the driver with traces ([1.2](<../../sections/1. Event thinking/1.2. Choreography scaling flow.md>)) — reactions proving (emitters firing — listeners subscribing (drivers absenting — centralizing declining (proving owning — bottlenecking declining); topology proving (steps counting — owners scattering (drivers placing — defaulting declining (proving funding — sprawling declining); traces proving (flows correlating — journeys narrating (debugs funding — blaming declining (proving earning — guessing declining). "Live" means honesty first (subscriptions stating — drivers placing — ids propagating (truth proving — defaulting declining).

**What problem it solves** — the hand-waving trio: *reactions waving* (subscriptions unstating — interests undeclared (drivers unabsented — bottlenecks forming (waving serving — hiring failing (numbers missing — judgment doubting); *topology forgetting* (steps uncounting — owners unscattering (drivers unplacing — sprawls scheduling (forgetting owning — judgment missing (silence serving — defaulting deciding); *traces missing* (ids unpropagated — journeys unnarrated (debugs unfunded — blames assigned (missing charging — archaeology requiring (hope serving — calibration failing). Pressured flows converting waving to stating (subscriptions declaring — steps counting (ids propagating — answers holding); interviewers hearing drivers with traces, not adjectives (stating proving → hirable; waving → passed) — drawing on [1.2](<../../sections/1. Event thinking/1.2. Choreography scaling flow.md>).

**Modern guidance** — the flows lines (interview-enforced): *reactions decoupling* (emitters firing — listeners subscribing (drivers absenting — centralizing declining (decoupling proving — bottlenecking refusing); *topology judging* (steps counting — owners scattering (drivers placing — defaulting declining (judging funding — sprawling refusing); *traces correlating* (ids propagating — journeys narrating (debugs funding — blaming declining (correlating owning — guessing refusing). Every claim carrying subscription + driver + trace (judgment demonstrable — pressure survivable).

```typescript
// GOOD: flows answers — subscriptions, drivers, traces with honest topologies (answer shape, hiring-grade).
// "Billing subscribes order.placed idempotently (reactions decoupling — effects converging).
//  Nine-step checkout carries an orders-saga driver (topology judging — visibility earning).
//  Every event carries t-ids end to end (traces correlating — debugs funding).")
```

```typescript
// BAD: flows waves — adjectives without subscriptions, comfort without drivers (real fail shape).
// // "Event-driven." (subscriptions unstating — interests undeclared — numbers missing).
// // "It scales." (drivers unplacing — traces missing). Declare subscriptions; place drivers; propagate ids.)
```

**Common confusion** — *"choreography answers flows (decoupling satisfying)."* Satisfying avoiding drivers (subscriptions listing — topologies unjudged (traces missing — debugs fumbling (satisfying serving — hiring failing (comfort owning — courage missing); flows judging topology (reactions decoupling — steps counting (traces correlating — sprawls declining (judging proving — waving declining). "Choreography" describing default (drivers unplacing — sizes unweighing); flows describing decisions (subscriptions declaring — drivers placing). Decouple reactions (emitters firing — listeners subscribing); trace journeys (ids propagating — debugs funding).

**Performance note** — flows-answer economics: stating costing topologies (subscriptions declaring — steps counting (ids propagating — answers holding); waving equivalents costing doubt (adjectives floating — numbers missing (judgment doubting — hiring failing). State cheaply (topologies — flows); wave never (adjectives — drivers).

**Mentor note** — drill "subscription, driver, trace" (candidates answering per flow with interests, driver choices, and correlation ids defend flows on first hearing; "event-driven" interrogated ("subscribed where? driver who? traced how?" — flows demanding per claim). Rehearse one flow story once (subscription-driver-trace tangible (waving ending — stating proving permanently). Declare interests; own traces — flows answers in three honesty, reviewed per interview.

## 3. Reliability live under pressure (fusing, relays, inverses — ownership stated, not hoped)

**Definition** — the reliability answer interviewers grade: given a failure, name the relay with inverses ([2.1](<../../sections/2. Reliability thinking/2.1. Outbox relaying atomically.md>)/[2.2](<../../sections/2. Reliability thinking/2.2. Sagas compensating stepwise.md>)) — fusing proving (rows pairing — commits atomicking (duals declining — partials ending (proving owning — splitting declining); relays proving (rows scanning — publishes retrying (lags alarming — rotting declining (proving funding — stalling declining); inverses proving (compensators naming — orders reversing (converges earning — stranding declining (proving earning — missing declining). "Live" means ownership stated (rows pairing — lags alarming — undos naming (proof stating — partialing declining).

**What problem it solves** — the claiming trio: *fusing claiming* (rows unpairing — commits half-succeeding (partials persisting — customers discovering (claiming serving — hiring failing (names missing — proof doubting); *relays missing* (rows unscanning — publishes stalling (lags unalarming — silence ruling (missing owning — reliability bluffing (silence serving — observability failing); *inverses hoping* (compensators unnamed — orders unreversed (halves persisting — consistency breaking (hoping serving — evidence failing). Pressured reliability converting claiming to pairing (rows coupling — unrelayed finding (undos owning — answers holding); interviewers hearing rows with inverses, not assurances (pairing proving → hirable; claiming → passed) — drawing on [2.1](<../../sections/2. Reliability thinking/2.1. Outbox relaying atomically.md>) and [2.2](<../../sections/2. Reliability thinking/2.2. Sagas compensating stepwise.md>).

**Modern guidance** — the reliability lines (interview-enforced): *fusing pairing* (rows coupling — commits succeeding (duals refusing — partials ending (pairing proving — splitting refusing); *relays polling* (rows scanning — publishes repeating (lags alarming — rotting declining (polling funding — stalling refusing); *inverses naming* (compensators owning — orders reversing (converges earning — stranding declining (naming owning — missing refusing). Every claim carrying row + lag + undo (judgment demonstrable — pressure survivable).

```typescript
// GOOD: reliability answers — rows, lags, undos with owned failures (answer shape, hiring-grade).
// "Order row pairs its relay row atomically (fusing pairing — partials ending).
//  Relay polls with 3s lag alarm (polls scanning — stalls surfacing).
//  Charge ships refund on ship-failure, reversed (inverses naming — convergence earning).")
```

```typescript
// BAD: reliability claiming — assurances without rows, sagas without undos (real fail shape).
// // "Reliable messaging." (rows unpairing — lags unalarming — names missing).
// // "Saga handles it." (compensators unnamed — halves persisting). Pair rows; alarm lags; name undos.)
```

**Common confusion** — *"brokers answer reliability (infrastructure owning)."* Owning offloading delivery (messages persisting — consumers scaling (redeliveries repeating — ordering bounding (offloading serving — callers thinning); reliability owning honesty (rows pairing — lags alarming (undos naming — partials ending (owning proving — claiming declining). "Brokers" describing transport (messages persisting — redeliveries repeating); reliability describing proof (fusing pairing — inverses naming). Pair intents (rows coupling — gaps closing); name undos (compensators owning — convergence earning).

**Performance note** — reliability-answer economics: pairing costing artifacts (rows coupling — lags alarming (undos naming — answers holding); claiming equivalents costing doubt (assurances floating — artifacts missing (proof doubting — hiring failing). Pair cheaply (artifacts — writes); claim never (assurances — reliability).

**Mentor note** — drill "row, lag, undo" (candidates answering per failure with paired rows, lag alarms, and named inverses defend reliability on first hearing; "reliable" interrogated ("relay row? lag cap? undo?" — reliability demanding per claim). Rehearse one failure story once (row-lag-undo tangible (claiming ending — pairing proving permanently). Fuse writes; unwind orders — reliability answers in three ownerships, reviewed per interview.
