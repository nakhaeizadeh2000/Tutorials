## 1. Writes fusing (rows pairing — commits atomicking — duals declining)

**Definition** — fused writes: business rows paired with relay rows committing atomically (rows pairing — intents coupling (payloads staging — publishes queueing (pairing proving — splitting declining); commits atomicking — units succeeding (all-or-neithering — partials refusing (atomicking owning — hoping declining); duals declining — double-writes refusing (brokers uncoordinating — gaps closing (declining funding — partialing ending).

**What problem it solves** — the dual-write trio: *rows unpairing* (intents uncoupling — payloads unstaging (publishes unqueued — relays missing (unpairing billing — atomicity hoping); *commits unatomicking* (units half-succeeding — partials persisting (customers discovering — support firefighting (unatomicking charging — integrity failing); *duals undeclining* (brokers coordinating — gaps opening (phantoms publishing — fictions acting (undeclining costing — honesty failing). Fused writes converting splitting to pairing (intents coupling — units succeeding (brokers uncoordinated — gaps closing); reviewers finding relay rows per write (fusing proving → verifiable; splitting → returned).

```typescript
// GOOD: writes fusing — paired rows committing atomically (compiled + run live).
interface Write { // rows pairing — intents coupling, splitting declining
  business: string;
  relay: string;
}
function split(writes: Write[]): string[] {
  const gaps: string[] = []; // commits atomicking — units succeeding, hoping declining
  for (const w of writes) {
    if (w.business.length === 0 || w.relay.length === 0) gaps.push('partial');
  }
  return gaps; // duals declining — double-writes refusing, partialing declining
}
const fused: Write[] = [{ business: 'order:o1', relay: 'order.placed:o1' }];
const splitWrite: Write[] = [{ business: 'order:o1', relay: '' }];
console.log(split(fused).length === 0 && split(splitWrite).join() === 'partial' ? 'writes fuse' : 'dials split');
```

**Performance note** — fusing economics: pairing costing rows (intents coupling — units succeeding (brokers uncoordinated — gaps closing); split equivalents costing partials (customers discovering — support firefighting (phantoms publishing — trust eroding). Pair cheaply (rows — writes); split never (dial — publishes).

## 2. Relays polling (rows scanning — publishes retrying — lags alarming)

**Definition** — polling relays: scanned rows with retried publishes alarming lags (rows scanning — unrelayed finding (cursors advancing — crashes resuming (scanning proving — forgetting declining); publishes retrying — delivers repeating (failures weathering (successes marking (retrying funding — dropping declining); lags alarming — ages watching (thresholds paging (stalls surfacing — silence declining (alarming owning — hiding declining).

**What problem it solves** — the relay-rot trio: *rows unscanning* (unrelayed unfound — cursors unadvanced (publishes stalling — events rotting (unscanning billing — delivery failing); *publishes unretrying* (delivers undelivered — failures dropping (marking missing — redeliveries duplicating-blindly (unretrying charging — reliability bluffing); *lags unalarming* (ages unwatched — thresholds unpaged (stalls hiding — silence ruling (unalarming costing — observability failing). Polling relays converting rotting to scanning (unrelayed finding — delivers repeating (ages watching — stalls surfacing); reviewers finding lag alarms per relay (polling proving → verifiable; rotting → returned).

**Modern guidance** — the polling lines per relay (review-enforced): *rows scanning* (unrelayed finding — cursors advancing (crashes resuming — forgetting declining (scanning proving — stalling refusing (scans earning — delivery resuming); *publishes retrying* (delivers repeating — failures weathering (successes marking — dropping declining (retrying funding — delivering refusing (repeats keeping — reliability earning); *lags alarming* (ages watching — thresholds paging (stalls surfacing — silence declining (alarming owning — hiding refusing (alarms funding — observability keeping).

```typescript
// GOOD: relays polling — scanned rows with alarmed lags (compiled + run live).
interface RelayRow { // rows scanning — unrelayed finding, forgetting declining
  id: string;
  relayed: boolean;
  ageMs: number;
}
function pending(rows: RelayRow[], lagCapMs: number): { todo: string[]; alarmed: boolean } {
  const todo: string[] = []; // publishes retrying — delivers repeating, dropping declining
  let oldest = 0;
  for (const r of rows) {
    if (!r.relayed) {
      todo.push(r.id);
      if (r.ageMs > oldest) oldest = r.ageMs;
    }
  }
  return { todo, alarmed: oldest > lagCapMs }; // lags alarming — ages watching, hiding declining
}
const rows: RelayRow[] = [
  { id: 'o1', relayed: true, ageMs: 9000 },
  { id: 'o2', relayed: false, ageMs: 4000 },
];
const out = pending(rows, 3000);
console.log(out.todo.join() === 'o2' && out.alarmed ? 'relays poll' : 'rows rot');
```

"Wasting" describing naive scans (queries repeating — capacity spending); relays describing resumption (cursors advancing — lags alarming). Scan indexed (unrelayed finding — delivery resuming); alarm ages (thresholds paging — stalls surfacing).

**Performance note** — polling economics: scanning costing indexed queries (rows finding — delivers repeating (ages watching — stalls surfacing); rotted equivalents costing silence (publishes stalling — events rotting (delivery failing — trust eroding). Scan cheaply (cursors — rows); rot never (relays — publishes).

**Mentor note** — teach "scan the unrelayed, alarm the aged" (juniors polling one relay per outbox design rot-proof delivery on first hearing; alarm-less relays interrogated ("lag cap?" — polling demanding per relay). ## 3. Consumers idempotenting (keys deduping — replays converging — storms absorbing)

**Definition** — idempotent consumers: deduped keys with converged replays absorbing storms (keys deduping — ids requiring (repeats detecting — effects holding (deduping proving — doubling declining); replays converging — retries short-circuiting (originals returning — ledgers steadying (converging funding — drifting declining); storms absorbing — bursts queueing (uniques recomputing-never (collapses declining — capacity surviving (absorbing owning — dying declining).

**What problem it solves** — the redelivery trio: *keys undeduping* (ids unrequired — repeats undetected (effects doubling — ledgers drifting (undeduping billing — safety failing); *replays unconverging* (retries reapplying — originals unreturned (ledgers unsteadying — consistency breaking (unconverging charging — correctness failing); *storms unabsorbing* (bursts unqueued — uniques recomputed (collapses scheduling — capacity dying (unabsorbing costing — survival bluffing). // GOOD: consumers idempotenting — deduped keys with converged replays (compiled + run live).
```typescript
class ConsumerInbox { // keys deduping — ids requiring, doubling declining
  private readonly seen = new Set<string>();
  handle(id: string): string {
    if (this.seen.has(id)) return 'replay-converged'; // replays converging — retries short-circuiting, drifting declining
    this.seen.add(id);
    return 'effect-applied'; // storms absorbing — bursts queueing, dying declining
```
