**Modern guidance** — the stating lines per event (review-enforced): *past-tensing* ([CA 04/3.1](<../../../../CleanArchitecture/04 DDD Tactical Modeling/sections/3. Domain events/3.1. interface Fact { // past-tensing — events naming-done, commanding declining
  name: string;
  payloadKeys: string[];
}
function commanding(facts: Fact[]): string[] {

  const present = /ed$/;

    if (!present.test(f.name) || f.payloadKeys.length === 0) gaps.push(f.name);
  }
  return gaps; // consumers trusting — shapes versioning, guessing declining
}

  { name: 'order.placed', payloadKeys: ['id', 'total'] },
  { name: 'payment.refunded', payloadKeys: ['id'] },

**Performance note** — stating economics: tensing costing names (events naming-done — fields minimizing (shapes versioning — consumers coding); commanding equivalents costing coupling (receivers obeying — flows owning (timing coupling — factoring failing). **Mentor note** — teach "name what happened, not what to do" (juniors past-tensing one event per fact design command-proof streams on first hearing; imperative events interrogated ("done what?" — stating demanding per event).
