# 1.2. Choreography scaling flow

## 1. Reactions decoupling (emitters firing — listeners subscribing — drivers absenting)

**Definition** — decoupled reactions: firing emitters with subscribing listeners and absent drivers (emitters firing — facts publishing (versions tagging — consumers ignoring (firing proving — commanding declining); listeners subscribing — interests declaring (handlers idempotenting — effects converging (subscribing funding — polling declining); drivers absenting — flows emerging (couples loosening — availability keeping (absenting owning — centralizing declining).

**What problem it solves** — the orchestrated-everything trio: *emitters unfiring* (facts unpublished — versions untagged (consumers unsubscribed — producers blocking (unfiring billing — events missing); *listeners unsubscribing* (interests undeclared — handlers doubling (effects diverging — ledgers drifting (unsubscribing charging — reaction failing); *drivers unabsenting* (flows centralized — couples tightening (availability coupling — bottlenecks forming (unabsenting costing — decoupling bluffing). Decoupled reactions converting centralizing to firing (facts publishing — interests declaring (flows emerging — couples loosening); reviewers finding subscriptions per event (decoupling proving → verifiable; centralizing → returned).

**Modern guidance** — the decoupling lines per event (review-enforced): *emitters firing* (facts publishing — versions tagging (consumers ignoring — commanding declining (firing proving — blocking refusing (emissions earning — throughput keeping); *listeners subscribing* (interests declaring — handlers idempotenting (effects converging — polling declining (subscribing funding — missing refusing (subscriptions owning — drift ending); *drivers absenting* (flows emerging — couples loosening (availability keeping — centralizing declining (absenting owning — bottlenecking refusing (emergence funding — autonomy earning).

```typescript
// GOOD: reactions decoupling — firing emitters with subscribing listeners (compiled + run live).
interface Subscription { // emitters firing — facts publishing, commanding declining
  event: string;
  listener: string;
  idempotent: boolean;
}
function driverless(subs: Subscription[]): string[] {
  const gaps: string[] = []; // listeners subscribing — interests declaring, polling declining
  for (const s of subs) {
    if (s.listener.length === 0 || !s.idempotent) gaps.push(s.event);
  }
  return gaps; // drivers absenting — flows emerging, centralizing declining
}
const loose: Subscription[] = [
  { event: 'order.placed', listener: 'billing', idempotent: true },
  { event: 'order.placed', listener: 'notify', idempotent: true },
];
const naive: Subscription[] = [{ event: 'order.placed', listener: 'billing', idempotent: false }];
console.log(driverless(loose).length === 0 && driverless(naive).join() === 'order.placed' ? 'reactions decouple' : 'flows centralize');
```

```typescript
// BAD: flows centralizing — emitters unfiring, drivers unabsenting (real bottleneck shape).
// // Orchestrator calls all (flows centralized — couples tightening — bottlenecks forming).
// // Non-idempotent listeners (effects diverging — ledgers drifting). Fire emitters; subscribe listeners; absent drivers.)
```

**Common confusion** — *"choreography means no design (events hoping)."* Hoping publishing wishes (facts unshaped — versions untagged (consumers guessing — contracts missing (hoping charging — design failing); choreography reacting deliberately (emitters firing — listeners subscribing (drivers absenting — couples loosening (reacting proving — centralizing declining). "Hoping" describing anarchy (facts unshaped — consumers guessing); reactions describing decoupling (interests declaring — flows emerging). Fire shaped events (facts publishing — versions tagging); subscribe idempotently (handlers deduping — effects converging).

**Performance note** — decoupling economics: firing costing subscriptions (emitters publishing — listeners subscribing (drivers absenting — couples loosening); centralized equivalents costing bottlenecks (flows centralizing — couples tightening (availability coupling — throughput capping). Fire cheaply (events — reactions); centralize never (flows — drivers).

**Mentor note** — teach "subscribe interests, never poll states" (juniors declaring one subscription per reaction design central-proof flows on first hearing; polling listeners interrogated ("subscribed where?" — decoupling demanding per reaction). Decouple one reaction once (emitters firing — listeners subscribing tangible (centralizing ending — decoupling proving permanently). Publish facts; deduplicate handlers — decoupling discipline in three habits, reviewed per event.

## 2. Topology judging (steps counting — owners scattering — drivers placing)

**Definition** — judged topology: counted steps with scattered owners placing drivers (steps counting — hops tallying (reactions chaining — paths visualizing (counting proving — sprawling declining); owners scattering — teams multiplying (deployables dividing — cognition bounding (scattering funding — balling declining); drivers placing — orchestrators assigning (flows owning — visibility earning (placing owning — emerging declining).

**What problem it solves** — the default-choreography trio: *steps uncounting* (hops untallying — reactions unchaining (paths unvisualized — flows sprawling (uncounting billing — topology missing); *owners unscattering* (teams unmultiplying — deployables undividing (ball forming — cognition overloading (unscattering charging — scaling failing); *drivers unplacing* (orchestrators unassigned — flows unowned (visibility missing — debugs fumbling (unplacing costing — emergence bluffing). Judged topology converting defaulting to counting (hops tallying — teams multiplying (orchestrators assigning — flows owning); reviewers finding driver decisions per flow (judging proving → verifiable; defaulting → returned).

**Modern guidance** — the judging lines per flow (review-enforced): *steps counting* (hops tallying — reactions chaining (paths visualizing — sprawling declining (counting proving — hiding refusing (tallies earning — blindness ending); *owners scattering* (teams multiplying — deployables dividing (cognition bounding — balling declining (scattering funding — overloading refusing (splits owning — scaling earning); *drivers placing* ([CA 02/2.1](<../../../../CleanArchitecture/02 Use Cases and Application Services/sections/2. Long flows/2.1. Sagas sequencing without distributed lockstep.md>) — orchestrators assigning (flows owning — visibility earning (placing owning — emerging refusing (placements funding — fumbling declining).

```typescript
// GOOD: topology judging — counted steps with placed drivers (compiled + run live).
interface Flow { // steps counting — hops tallying, sprawling declining
  name: string;
  steps: number;
  owners: number;
  driver: string;
}
function driverless(flows: Flow[], stepCap: number): string[] {
  const gaps: string[] = []; // owners scattering — teams multiplying, balling declining
  for (const f of flows) {
    if ((f.steps > stepCap || f.owners > 2) && f.driver.length === 0) gaps.push(f.name);
  }
  return gaps; // drivers placing — orchestrators assigning, emerging declining
}
const choreo: Flow[] = [{ name: 'notify', steps: 2, owners: 1, driver: '' }];
const sprawl: Flow[] = [{ name: 'checkout', steps: 9, owners: 4, driver: '' }];
const driven: Flow[] = [{ name: 'checkout', steps: 9, owners: 4, driver: 'orders-saga' }];
console.log(driverless(choreo, 5).length === 0 && driverless(sprawl, 5).join() === 'checkout' && driverless(driven, 5).length === 0 ? 'topology judges' : 'choreography defaults');
```

```typescript
// BAD: choreography defaulting — steps uncounting, drivers unplacing (real sprawl shape).
// // Nine-step checkout reacting (hops untallying — paths unvisualized — flows sprawling).
// // No driver (visibility missing — debugs fumbling). Count steps; scatter owners; place drivers.)
```

**Common confusion** — *"orchestrators are monoliths (drivers centralizing)."* Centralizing owning everything (logic concentrating — deploys singling (states sharing — autonomy ending (centralizing charging — distribution failing); placing owning flows (drivers deciding — steps commanding (visibility earning — debugs easing (placing proving — fumbling declining). "Monoliths" describing deployment (deploys singling — states sharing); drivers describing visibility (flows owning — steps commanding). Place drivers (orchestrators assigning — visibility earning); deploy separately (services scaling — autonomy keeping).

**Performance note** — judging economics: counting costing tallies (steps tallying — owners scattering (drivers placing — flows owning); defaulted equivalents costing sprawl (paths unvisualized — debugs fumbling (visibility missing — autonomy bluffing). Count cheaply (steps — flows); default never (choreography — topology).

**Mentor note** — teach "count steps, then choose the driver" (juniors judging one topology per flow design sprawl-proof choreography on first hearing; driverless sprawls interrogated ("steps? owners? driver?" — judging demanding per flow). Judge one flow once (hops tallying — drivers placing tangible (defaulting ending — judging proving permanently). Tally hops; assign drivers — judging discipline in three habits, reviewed per flow.

## 3. Traces owning (flows correlating — journeys narrating — debugs funding)

**Definition** — owned traces: correlated flows narrating journeys funding debugs (flows correlating — ids propagating (spans linking — causes chaining (correlating proving — blaming declining); journeys narrating — stories reconstructing (events ordering — states replaying (narrating funding — guessing declining); debugs funding — incidents explaining (roots locating — fixes verifying (funding owning — fumbling declining).

**What problem it solves** — the traceless trio: *flows uncorrelated* (ids unpropagated — spans unlinked (causes unchained — blames assigned (uncorrelated billing — debugging failing); *journeys unnarrated* (stories unreconstructed — events unordered (states unreplayed — guesses ruling (unnarrated charging — archaeology requiring); *debugs unfunded* (incidents unexplained — roots unlocated (fixes unverified — fumbling ruling (unfunded costing — trust eroding). Owned traces converting blaming to correlating (ids propagating — stories reconstructing (incidents explaining — debugs funding); reviewers finding correlation ids per flow (owning proving → verifiable; blaming → returned).

**Modern guidance** — the owning lines per flow (review-enforced): *flows correlating* (ids propagating — spans linking (causes chaining — blaming declining (correlating proving — dropping refusing (ids earning — archaeology ending); *journeys narrating* (stories reconstructing — events ordering (states replaying — guessing declining (narrating funding — hoping refusing (stories owning — confusion ending); *debugs funding* (incidents explaining — roots locating (fixes verifying — fumbling declining (funding owning — eroding refusing (explanations earning — trust keeping).

```typescript
// GOOD: traces owning — correlated flows narrating journeys (compiled + run live).
interface Span { // flows correlating — ids propagating, blaming declining
  traceId: string;
  step: string;
}
function orphans(spans: Span[]): string[] {
  const seen = new Set(spans.map((s) => s.traceId)); // journeys narrating — stories reconstructing, guessing declining
  const gaps: string[] = [];
  for (const s of spans) {
    if (!seen.has(s.traceId) || s.step.length === 0) gaps.push(s.step);
  }
  return gaps; // debugs funding — incidents explaining, fumbling declining
}
const traced: Span[] = [
  { traceId: 't-1', step: 'placed' },
  { traceId: 't-1', step: 'billed' },
];
const bare: Span[] = [{ traceId: 't-2', step: '' }];
console.log(orphans(traced).length === 0 && orphans(bare).join() === '' ? 'traces own' : 'flows blame');
```

```typescript
// BAD: flows blaming — ids unpropagated, journeys unnarrated (real blame shape).
// // "Billing failed." (causes unchained — blames assigned — debugging failing).
// // No trace id (stories unreconstructed — guesses ruling). Propagate ids; order events; explain incidents.)
```

**Common confusion** — *"tracing is observability (platforms owning)."* Platforms owning telemetry (spans collecting — dashboards rendering (metrics aggregating — alerts firing (owning serving — correlating missing); traces owning narrative (ids propagating — stories reconstructing (incidents explaining — debugs funding (owning proving — blaming declining). "Observability" describing plumbing (spans collecting — dashboards rendering); traces describing journeys (events ordering — causes chaining). Propagate correlation (ids flowing — causes linking); narrate journeys (stories reconstructing — confusion ending).

**Performance note** — owning economics: correlating costing ids (flows propagating — stories reconstructing (incidents explaining — debugs funding); traceless equivalents costing blame (causes unchained — guesses ruling (archaeology requiring — trust eroding). Correlate cheaply (ids — flows); blame never (outages — teams).

**Mentor note** — teach "no event without a trace id" (juniors propagating one correlation per flow design blame-proof choreography on first hearing; id-less events interrogated ("trace which?" — owning demanding per event). Own one trace once (ids propagating — stories reconstructing tangible (blaming ending — owning proving permanently). Link spans; fund debugs — owning discipline in three habits, reviewed per flow.
