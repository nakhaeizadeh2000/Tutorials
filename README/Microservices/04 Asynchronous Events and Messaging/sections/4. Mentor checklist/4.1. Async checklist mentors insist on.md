# 4.1. Async checklist mentors insist on

## 1. Every fact eventing (past-tensing — versions numbering — delivery admitting)

**Definition** — the fact line on every published event: facts proving (past-tensing — payloads bounding (consumers trusting — commanding declining (proving owning — imperativing declining); versions proving (schemas numbering — readers tolerating (breaks dating — freezing declining (proving funding — ambushing declining); delivery proving (at-least-once owning — duplicates expecting (keys demanding — hoping declining (proving earning — doubling declining).

**What problem it solves** — the unevented trio: *facts uncommanding* (events imperativing — payloads unbounding (consumers guessing — coupling timing (uncommanding billing — factoring failing); *versions unfreezing* (schemas unnumbering — readers crashing (breaks ambushing — trust burning (unfreezing charging — evolution missing); *delivery unhoping* (redeliveries unaccepted — keys undemanded (effects doubling — ledgers drifting (unhoping costing — honesty failing). Evented facts converting commanding to proving (past-tensing — schemas numbering (redeliveries accepting — consumers trusting); reviewers finding tense-version-key triples per event (eventing proving → verifiable; commanding → returned).

**Modern guidance** — the eventing lines per event (review-enforced): *facts proving* ([1.1](<../../sections/1. Event thinking/1.1. Events streaming facts.md>) — past-tensing (payloads bounding — consumers trusting (proving owning — commanding refusing); *versions proving* ([1.1](<../../sections/1. Event thinking/1.1. Events streaming facts.md>) — schemas numbering (readers tolerating — breaks dating (proving funding — freezing refusing); *delivery proving* ([1.1](<../../sections/1. Event thinking/1.1. Events streaming facts.md>) — at-least-once owning (duplicates expecting — keys demanding (proving earning — hoping refusing).

```typescript
// GOOD: every fact eventing — tense, versions, keys per event (process shape, reviewed).
// - Facts past-tensed with bounded payloads (events naming-done — fields minimizing — consumers trusting).
// - Versions numbered with tolerant readers (releases tagging — unknowns ignoring — breaks dating).
// - Delivery admitted with demanded keys (redeliveries accepting — repeats assuming — ids requiring.)
```

```typescript
// BAD: facts commanding — events imperativing, versions freezing, delivery hoping (real command shape).
// // 'doThis' event (states requesting — receivers obeying). Unversioned (readers crashing).
// // Keyless handler (effects doubling). Tense past; number schemas; demand keys.)
```

**Common confusion** — *"eventing is ceremony (facts decorating)."* Decorating renaming messages (labels changing — shapes unbounding (keys undemanded — duplicates doubling (decorating charging — design failing); eventing proving delivery (past-tensing — versions numbering (redeliveries accepting — effects converging (proving owning — hoping declining). "Ceremony" describing labels (names changing — shapes missing); eventing describing honesty (facts stating — keys demanding). Tense events (names past-tensing — histories appending); admit duplicates (repeats assuming — ids requiring).

**Performance note** — eventing-check economics: tensing costing names (past-tensing — versions numbering (redeliveries accepting — effects converging); commanding equivalents costing coupling (receivers obeying — readers crashing (effects doubling — trust eroding). Tense cheaply (facts — events); command never (messages — receivers).

**Mentor note** — teach "tense, version, key — every event" (juniors eventing per fact design command-proof streams on first hearing; untensed events interrogated ("done what? version? key?" — eventing demanding per event). Event one fact once (names past-tensing — schemas numbering tangible (commanding ending — eventing proving permanently). Bound payloads; converge replays — eventing discipline in three habits, reviewed per event.

## 2. Every flow judging (reactions decoupling — topology weighing — traces owning)

**Definition** — the flow line on every event flow: reactions proving (emitters firing — listeners subscribing (drivers absenting — centralizing declining (proving owning — bottlenecking declining); topology proving (steps counting — owners scattering (drivers placing — defaulting declining (proving funding — sprawling declining); traces proving (flows correlating — journeys narrating (debugs funding — blaming declining (proving earning — guessing declining).

**What problem it solves** — the unjudged trio: *reactions uncoupling* (emitters unfiring — listeners unsubscribing (drivers unabsenting — bottlenecks forming (uncoupling billing — decoupling failing); *topology unweighing* (steps uncounting — owners unscattering (drivers unplacing — sprawls scheduling (unweighing charging — judgment missing); *traces unowning* (flows uncorrelated — journeys unnarrated (debugs unfunded — blames assigned (unowning costing — archaeology requiring). Judged flows converting defaulting to proving (emitters firing — steps counting (flows correlating — couples loosening); reviewers finding driver decisions per flow (judging proving → verifiable; defaulting → returned).

**Modern guidance** — the judging lines per flow (review-enforced): *reactions proving* ([1.2](<../../sections/1. Event thinking/1.2. Choreography scaling flow.md>) — emitters firing (listeners subscribing — drivers absenting (proving owning — bottlenecking refusing); *topology proving* ([1.2](<../../sections/1. Event thinking/1.2. Choreography scaling flow.md>) — steps counting (owners scattering — drivers placing (proving funding — sprawling refusing); *traces proving* ([1.2](<../../sections/1. Event thinking/1.2. Choreography scaling flow.md>) — flows correlating (journeys narrating — debugs funding (proving earning — guessing refusing).

```typescript
// GOOD: every flow judging — reactions, sizes, traces per flow (process shape, reviewed).
// - Reactions decoupled with idempotent listeners (emitters firing — effects converging — drivers absenting).
// - Topology weighed with placed drivers (steps counting — owners scattering — flows owning).
// - Traces owned with propagated ids (flows correlating — journeys narrating — debugs funding.)
```

```typescript
// BAD: flows defaulting — reactions uncoupling, topology unweighing, traces unowning (real sprawl shape).
// // Default choreography (bottlenecks forming — sprawls scheduling). Driverless sprawl (debugs fumbling).
// // Traceless events (blames assigned). Decouple reactions; weigh topology; own traces.)
```

**Common confusion** — *"judging slows flows (decisions delaying)."* Delaying postponing reactions (choices waiting — events queueing (value missing — momentum dying (delaying charging — courage taxing); judging placing drivers (reactions decoupling — topology weighing (traces owning — sprawls declining (judging proving — defaulting declining). "Slowing" describing fear (decisions ducking — flows drifting); judging describing visibility (steps counting — drivers placing). Count steps (hops tallying — sprawls declining); propagate ids (flows correlating — blames ending).

**Performance note** — judging-check economics: decoupling costing subscriptions (emitters firing — steps counting (flows correlating — couples loosening); defaulted equivalents costing sprawl (bottlenecks forming — debugs fumbling (blames assigned — trust eroding). Judge cheaply (flows — topologies); default never (choreography — sizes).

**Mentor note** — teach "decouple, weigh, trace — every flow" (juniors judging per flow design sprawl-proof choreography on first hearing; unjudged flows interrogated ("driver? steps? trace?" — judging demanding per flow). Judge one flow once (reactions decoupling — topology weighing tangible (defaulting ending — judging proving permanently). Fire emitters; place drivers — judging discipline in three habits, reviewed per flow.

## 3. Every write relaying (fusing pairing — polls scanning — consumers idempotenting)

**Definition** — the relay line on every state-changing write: fusing proving (rows pairing — commits atomicking (duals declining — partials ending (proving owning — splitting declining); polls proving (rows scanning — publishes retrying (lags alarming — rotting declining (proving funding — stalling declining); consumers proving (keys deduping — replays converging (storms absorbing — doubling declining (proving earning — drifting declining).

**What problem it solves** — the unrelayed trio: *fusing unpairing* (rows uncoupling — commits half-succeeding (partials persisting — customers discovering (unpairing billing — atomicity hoping); *polls unscanning* (unrelayed unfound — publishes stalling (events rotting — delivery failing (unscanning charging — reliability bluffing); *consumers undoubling* (keys unrequired — replays reapplying (effects compounding — ledgers drifting (undoubling costing — safety failing). Relayed writes converting splitting to proving (rows pairing — unrelayed finding (keys deduping — honesty keeping); reviewers finding relay rows per write (relaying proving → verifiable; splitting → returned).

**Modern guidance** — the relaying lines per write (review-enforced): *fusing proving* ([2.1](<../../sections/2. Reliability thinking/2.1. Outbox relaying atomically.md>) — rows pairing (commits atomicking — duals declining (proving owning — splitting refusing); *polls proving* ([2.1](<../../sections/2. Reliability thinking/2.1. Outbox relaying atomically.md>) — rows scanning (publishes retrying — lags alarming (proving funding — stalling refusing); *consumers proving* ([2.1](<../../sections/2. Reliability thinking/2.1. Outbox relaying atomically.md>) — keys deduping (replays converging — storms absorbing (proving earning — drifting refusing).

```typescript
// GOOD: every write relaying — pairs, polls, keys per write (process shape, reviewed).
// - Writes fused with relay rows (intents coupling — units succeeding — duals declining).
// - Relays polled with lag alarms (unrelayed finding — delivers repeating — stalls surfacing).
// - Consumers keyed with converged replays (ids requiring — originals returning — storms surviving.)
```

```typescript
// BAD: writes splitting — fusing unpairing, polls unscanning, consumers undoubling (real partial shape).
// // Publish after commit (partials persisting — events rotting — delivery failing).
// // Keyless consumers (effects doubling — ledgers drifting). Fuse rows; poll relays; key consumers.)
```

**Common confusion** — *"relaying doubles work (rows duplicating)."* Duplicating copying payloads (rows cloning — relays doubling (stores growing — queries slowing (duplicating charging — value halving); relaying fusing honesty (intents coupling — publishes retrying (consumers converging — partials ending (relaying proving — splitting declining). "Doubling" describing copies (rows cloning — value halving); relaying describing atomicity (pairs coupling — units succeeding). Fuse intents (rows pairing — gaps closing); converge replays (keys deduping — effects holding).

**Performance note** — relaying-check economics: pairing costing rows (intents coupling — rows scanning (keys deduping — honesty keeping); split equivalents costing partials (customers discovering — events rotting (effects doubling — trust eroding). Pair cheaply (rows — writes); split never (publishes — commits).

**Mentor note** — convert this leaf into the team's async runbook: tenses, versions, keys, reactions, sizes, traces, pairs, polls, dedups — every event, every flow, every write. Quiz juniors on sight ("which tense? which driver? which relay row?") until answers are environmental. Watch for checklist decay (async discipline for a sprint, abandoned under deadline — fix with relay lag alarms as review-blocking) and ceremony-theater ("checklist completed" without artifacts — fix with drive demands per item: emits fired, flows traced, relays green). Review check: facts eventing, flows judging, writes relaying — and the mentor's own streams modeling all three visibly.
