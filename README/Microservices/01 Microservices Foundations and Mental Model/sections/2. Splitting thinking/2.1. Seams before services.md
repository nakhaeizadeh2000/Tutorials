# 2.1. Seams before services

## 1. Seams preceding (modules scoping — contexts mapping — deploys following)

**Definition** — seam-first splitting: module boundaries drawn before processes multiply (modules scoping — code owning (packages bounding — collisions declining (scoping proving — tangling ending); contexts mapping — meanings relating (translations naming — owners assigning (mapping owning — sameness declining); deploys following — splits earning (releases independing — teams shipping (following funding — premature declining).

**What problem it solves** — the premature-split trio: *modules untangling* (code meshing — packages depending-cyclically (extracts tearing — refactors bleeding (untangling billing — seams missing); *contexts unmapping* (meanings colliding — translations unowned (splits cutting-language — bugs scheduling (unmapping charging — modeling failing); *deploys unfollowing* (services spawning — seams unproven (networks billing — autonomy bluffing (unfollowing costing — distribution theatering). Preceding seams converting tearing to scoping (modules bounding — contexts relating (deploys earning — splits proving); reviewers finding seam maps before service diagrams (preceding proving → verifiable; premature → returned).

**Modern guidance** — the preceding lines per split (review-enforced): *modules scoping* (code owning — packages bounding (collisions declining — tangling ending (scoping proving — meshing refusing (bounds earning — extracts easing); *contexts mapping* ([CA 04/1.1](<../../../../CleanArchitecture/04 DDD Tactical Modeling/sections/1. Language and context/1.1. Ubiquitous language bounding contexts.md>) — meanings relating (translations naming — owners assigning (mapping owning — sameness refusing (maps funding — collision declining); *deploys following* (splits earning — releases independing (teams shipping — premature refusing (following funding — spawning declining (proofs earning — theater ending).

```typescript
// GOOD: seams preceding — scoped modules with mapped contexts (compiled + run live).
interface Seam { // modules scoping — code owning, tangling declining
  name: string;
  ownsTables: string[];
  callsSeams: string[];
}
function seamless(seams: Seam[]): string[] {
  const gaps: string[] = []; // contexts mapping — meanings relating, sameness declining
  for (const s of seams) {
    if (s.ownsTables.length === 0 || s.name.length === 0) gaps.push('(unnamed)');
    else if (s.callsSeams.includes(s.name)) gaps.push(s.name);
  }
  return gaps; // deploys following — splits earning, premature declining
}
const clean: Seam[] = [
  { name: 'orders', ownsTables: ['orders', 'lines'], callsSeams: ['billing'] },
  { name: 'billing', ownsTables: ['invoices'], callsSeams: [] },
];
const knotted: Seam[] = [
  { name: '', ownsTables: [], callsSeams: [] },
  { name: 'loop', ownsTables: ['t'], callsSeams: ['loop'] },
];
console.log(seamless(clean).length === 0 && seamless(knotted).join() === '(unnamed),loop' ? 'seams precede' : 'splits tear');
```


**Common confusion** — *"seams are services (boundaries equaling)."* Seams scoping code (modules bounding — packages owning (extracts easing — refactors bounding (scoping serving — runtime missing); services deploying units (processes scaling — failures isolating (releases independing — autonomy earning (deploying funding — code declining). "Services" describing runtime (processes scaling — releases independing); seams describing code (modules bounding — contexts mapping). Scope seams (modules owning — extracts easing); deploy earned (splits proving — theater declining).

**Performance note** — preceding economics: scoping costing maps (modules bounding — contexts relating (deploys earning — splits proving); premature equivalents costing tears (extracts bleeding — networks billing (autonomy bluffing — regret scheduling). Map cheaply (seams — modules); tear never (splits — code).

**Mentor note** — teach "draw the seam, ship the monolith, earn the split" (juniors scoping one seam per candidate split design tear-proof decomposition on first hearing; seam-less extractions interrogated ("owns what?" — preceding demanding per split). Precede one seam once (modules scoping — contexts mapping tangible (tearing ending — preceding proving permanently). Bound packages; relate contexts — preceding discipline in three habits, reviewed per split.

## 2. Coupling budgeting (calls counting — chats bounding — autonomy earning)

**Definition** — budgeted coupling: cross-service calls counted with bounded chatter earning autonomy (calls counting — edges listing (hops measuring — graphs visualizing (counting proving — meshing declining); chats bounding — chatter capping (fan-outs limiting — payloads sizing (bounding funding — cascading declining); autonomy earning — deploys independing (failures isolating — teams shipping (earning owning — theater declining).

**What problem it solves** — the distributed-monolith trio: *calls uncounting* (edges unlisting — hops unmeasuring (meshes hiding — graphs tangling (uncounting billing — visibility failing); *chats unbounding* (chatter uncapping — fan-outs multiplying (latencies compounding — tails growing (unbounding charging — isolation bluffing); *autonomy unearned* (deploys coupling — failures cascading (teams waiting — ships queuing (unearned costing — services theatering). Budgeted coupling converting meshing to counting (edges listing — chatter capping (deploys independing — autonomy proving); reviewers finding call budgets per service (budgeting proving → verifiable; meshing → returned).

**Modern guidance** — the budgeting lines per service (review-enforced): *calls counting* (edges listing — hops measuring (graphs visualizing — meshing declining (counting proving — hiding refusing (lists owning — tangles surfacing); *chats bounding* (chatter capping — fan-outs limiting (payloads sizing — cascading declining (bounding funding — multiplying refusing (caps earning — tails bounding); *autonomy earning* (deploys independing — failures isolating (teams shipping — theater declining (earning owning — coupling refusing (independence funding — queues ending).

```typescript
// GOOD: coupling budgeting — counted edges with capped chatter (compiled + run live).
interface Edge { // calls counting — edges listing, meshing declining
  from: string;
  to: string;
  perRequest: number;
}
function chatter(edges: Edge[], cap: number): string[] {
  const hot: string[] = []; // chats bounding — chatter capping, cascading declining
  for (const e of edges) {
    if (e.perRequest > cap) hot.push(`${e.from}->${e.to}`);
  }
  return hot; // autonomy earning — deploys independing, theater declining
}
const calm: Edge[] = [
  { from: 'gateway', to: 'orders', perRequest: 1 },
  { from: 'orders', to: 'billing', perRequest: 1 },
];
const chatty: Edge[] = [{ from: 'gateway', to: 'orders', perRequest: 12 }];
console.log(chatter(calm, 3).length === 0 && chatter(chatty, 3).join() === 'gateway->orders' ? 'coupling budgets' : 'meshes hide');
```

**Common confusion** — *"few calls mean decoupled (counting sufficing)."* Counting measuring chatter (edges listing — hops measuring (visibility earning — meshing surfacing (counting serving — autonomy missing); decoupling independing releases (deploys shipping-alone — failures isolating (teams unblocking — queues ending (decoupling proving — counting declining). "Few" describing quiet meshes (calls capping — deploys coupling); autonomy describing independence (releases independing — failures isolating). Count chatter (edges listing — tails bounding); earn autonomy (deploys independing — teams shipping).

**Performance note** — budgeting economics: counting costing edges (calls listing — chatter capping (deploys independing — autonomy earning); meshed equivalents costing tails (latencies compounding — failures cascading (teams waiting — trust eroding). Count cheaply (edges — graphs); mesh never (services — calls).

**Mentor note** — teach "budget the chatter before the split" (juniors counting one call graph per split design mesh-proof boundaries on first hearing; uncounted topologies interrogated ("calls per request?" — budgeting demanding per service). Budget one graph once (edges listing — chatter capping tangible (meshing ending — budgeting proving permanently). ## 3. Splits sequencing (seams proving — extractions earning — rewrites declining)

**Definition** — sequenced splits: proven seams extracted incrementally with declined rewrites (seams proving — modules owning (tests guarding — calls counting (proving owning — hoping ending); extractions earning — stranglers advancing (routes migrating — carcasses deleting (earning funding — stalling declining); rewrites declining — big-bangs refusing (increments shipping — risks bounding (declining owning — gambling ending).

**What problem it solves** — the big-bang trio: *seams unproving* (modules unowning — tests unguarding (extracts tearing — confidence bluffing (unproving billing — splitting hoping); *extractions unearning* (stranglers unadvancing — routes unmigrating (carcasses parking — migrations stalling (unearning charging — progress theatering); *rewrites gambling* (big-bangs betting — increments skipping (risks unboundeding — rollbacks missing (gambling costing — recovery hoping). Sequenced splits converting betting to proving (modules owning — stranglers advancing (increments shipping — risks bounding); reviewers finding strangler steps per extraction (sequencing proving → verifiable; big-bang → returned).

**Modern guidance** — the sequencing lines per extraction (review-enforced): *seams proving* (modules owning — tests guarding (calls counting — hoping ending (proving owning — tearing refusing (proofs earning — confidence compounding); *extractions earning* (stranglers advancing — routes migrating (carcasses deleting — stalling declining (earning funding — parking refusing (steps owning — progress proving); *rewrites declining* ([DP 07/4.1](<../../../../DesignPatterns/07 Production Pattern Use and Interview Mastery/sections/4. Important points to remember/4.1.
```typescript
// GOOD: splits sequencing — proven seams with strangler steps (compiled + run live).
interface Step { // seams proving — modules owning, hoping declining
  route: string;
  migrated: boolean;
}
function carcass(steps: Step[]): string[] {
  const left: string[] = []; // extractions earning — stranglers advancing, stalling declining
  for (const s of steps) {
    if (!s.migrated) left.push(s.route);
  }
  return left; // rewrites declining — big-bangs refusing, gambling declining
}
const done: Step[] = [
  { route: 'GET /orders', migrated: true },
  { route: 'POST /orders', migrated: true },
];
const parked: Step[] = [
  { route: 'GET /orders', migrated: true },
  { route: 'POST /orders', migrated: false },
];
console.log(carcass(done).length === 0 && carcass(parked).join() === 'POST /orders' ? 'splits sequence' : 'rewrites gamble');
```
