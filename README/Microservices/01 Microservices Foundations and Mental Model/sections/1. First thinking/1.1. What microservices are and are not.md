# 1.1. What microservices are and are not

## 1. Services deciding runtime (processes scaling — failures isolating — deploys decoupling)

**Definition** — runtime services: independently deployed processes scaling and failing alone (processes scaling — instances multiplying (loads splitting — bottlenecks isolating (scaling proving — sharing declining); failures isolating — blasts bounding (crashes containing — neighbors serving (isolating funding — cascading declining); deploys decoupling — releases independing (versions drifting — teams shipping (decoupling owning — locking declining).

**What problem it solves** — the coupled-runtime trio: *processes unscaling* (instances sharing — loads contending (bottlenecks spreading — scale coupling (unscaling billing — independence missing); *failures uncascading* (crashes propagating — neighbors falling (blasts widening — availability dying (uncascading charging — isolation missing); *deploys locking* (releases coupling — versions marching (teams waiting — ships queuing (locking costing — autonomy failing). Decided runtimes converting coupling to isolating (instances multiplying — blasts bounding (releases independing — autonomy earning); reviewers finding deploy units per service (deciding proving → verifiable; coupling → returned).

**Modern guidance** — the deciding lines per service (review-enforced): *processes scaling* (instances multiplying — loads splitting (bottlenecks isolating — sharing declining (scaling proving — coupling refusing (instances owning — contention ending); *failures isolating* (blasts bounding — crashes containing (neighbors serving — cascading declining (isolating funding — propagating refusing (bounds earning — availability keeping); *deploys decoupling* (releases independing — versions drifting (teams shipping — locking declining (decoupling owning — marching refusing (independence funding — queues ending).

```typescript
// GOOD: services deciding runtime — independent deploys with isolated blasts (compiled + run live).
interface Deployable { // processes scaling — instances multiplying, sharing declining
  name: string;
  version: string;
  deploysAlone: boolean;
}
function coupled(services: Deployable[]): string[] {
  const gaps: string[] = []; // deploys decoupling — releases independing, locking declining
  for (const s of services) {
    if (!s.deploysAlone || s.version.length === 0) gaps.push(s.name);
  }
  return gaps; // failures isolating — blasts bounding, cascading declining
}
const fleet: Deployable[] = [
  { name: 'orders', version: '1.4.0', deploysAlone: true },
  { name: 'billing', version: '2.0.1', deploysAlone: true },
];
const tangled: Deployable[] = [{ name: 'orders', version: '', deploysAlone: false }];
console.log(coupled(fleet).length === 0 && coupled(tangled).join() === 'orders' ? 'services decide' : 'runtimes couple');
```

```typescript
// BAD: runtimes coupling — processes unscaling, deploys locking (real ball shape).
// // One deploy for everything (releases coupling — teams waiting — ships queuing).
// // Shared crash (blasts widening — neighbors falling). Scale processes; isolate blasts; decouple deploys.)
```

**Common confusion** — *"services are smaller monoliths (size differing)."* Size differing code volume (lines counting — modules splitting (repos multiplying — builds quickening (differing serving — runtime missing); services deciding runtime (processes scaling — failures isolating (deploys decoupling — autonomy earning (deciding funding — coupling declining). "Smaller" describing code (lines counting — builds quickening); services describing deployment (processes scaling — releases independing). Split modules (code organizing — builds quickening); decide runtimes (processes scaling — deploys decoupling).

**Performance note** — deciding economics: scaling costing processes (instances multiplying — blasts bounding (releases independing — autonomy earning); coupled equivalents costing contention (loads contending — crashes propagating (teams waiting — ships queuing). Multiply cheaply (instances — services); couple never (runtimes — deploys).

**Mentor note** — teach "deploy alone or it is not a service" (juniors checking one independent release per service design coupling-proof runtimes on first hearing; lockstep releases interrogated ("ships alone?" — deciding demanding per service). Decide one runtime once (processes scaling — deploys decoupling tangible (coupling ending — deciding proving permanently). Scale instances; bound blasts — deciding discipline in three habits, reviewed per service.

## 2. Slices differing (features owning — contexts bounding — deployables scaling)

**Definition** — owning slices vs scaling deployables: features owned by teams, contexts bounded by language, services scaled by runtime (features owning — teams answering (changes routing — releases decoupling (owning proving — orphaning declining); contexts bounding — meanings scoping (models mapping — conflicts declining (bounding serving — merging breaking); deployables scaling — units deploying (processes multiplying — failures isolating (scaling funding — coupling declining).

**What problem it solves** — the conflated trio: *features unowning* (teams unanswering — changes unrouting (orphans accumulating — velocity dying (unowning billing — ownership missing); *contexts unmerging* (meanings colliding — models conflicting (translations missing — bugs scheduling (unmerging charging — language failing); *deployables uncoupling* (services sharing-tables — calls chattering (consistency distributing — transactions spanning (uncoupling billing — autonomy bluffing). Differed slices converting conflation to owning (teams answering — meanings scoping (units deploying — autonomy earning); reviewers naming owners, contexts, and deployables per feature (differing proving → verifiable; conflating → returned).

**Modern guidance** — the differing lines per feature (review-enforced): *features owning* (teams answering — changes routing (releases decoupling — orphaning declining (owning proving — sharing refusing (owners earning — velocity funding); *contexts bounding* ([CA 04/1.1](<../../../../CleanArchitecture/04 DDD Tactical Modeling/sections/1. Language and context/1.1. Ubiquitous language bounding contexts.md>) — meanings scoping (models mapping — conflicts declining (bounding serving — merging refusing (scopes owning — collision ending); *deployables scaling* (units deploying — processes multiplying (failures isolating — coupling declining (scaling funding — sharing refusing (units earning — autonomy keeping).

```typescript
// GOOD: slices differing — owners, contexts, deployables per feature (compiled + run live).
interface Slice { // features owning — teams answering, orphaning declining
  feature: string;
  owner: string;
  context: string;
  deployable: string;
}
function conflated(slices: Slice[]): string[] {
  const gaps: string[] = []; // contexts bounding — meanings scoping, merging declining
  for (const s of slices) {
    if (s.owner.length === 0 || s.context.length === 0 || s.deployable.length === 0) gaps.push(s.feature);
  }
  return gaps; // deployables scaling — units deploying, coupling declining
}
const mapped: Slice[] = [{ feature: 'checkout', owner: 'team-pay', context: 'billing', deployable: 'billing-svc' }];
const fuzzy: Slice[] = [{ feature: 'checkout', owner: '', context: 'billing', deployable: 'billing-svc' }];
console.log(conflated(mapped).length === 0 && conflated(fuzzy).join() === 'checkout' ? 'slices differ' : 'features blur');
```

```typescript
// BAD: features blurring — owners unanswering, deployables uncoupling (real mush shape).
// // "Everyone owns checkout." (orphans accumulating — velocity dying — accountability missing).
// // One table, five services (consistency distributing — transactions spanning). Name owners; bound contexts; deploy units.)
```

**Common confusion** — *"contexts are microservices (deployables equaling)."* Contexts bounding meanings (terms scoping — models mapping (language owning — conflicts declining (bounding serving — merging breaking); services deploying units (processes scaling — networks calling (operations owning — failures isolating (deploying funding — language declining). "Services" describing runtime (processes scaling — failures isolating); contexts describing language (meanings scoping — terms bounding). Bound meanings (contexts scoping — conflicts declining); deploy pragmatically (services scaling — operations owning).

**Performance note** — differing economics: owning costing maps (teams answering — contexts scoping (units deploying — autonomy earning); blurred equivalents costing orphans (velocity dying — conflicts scheduling (transactions spanning — consistency failing). Map cheaply (slices — features); blur never (ownership — contexts).

**Mentor note** — teach "owner, context, deployable — every feature" (juniors naming one triple per feature design mush-proof slices on first hearing; ownerless features interrogated ("whose pager?" — differing demanding per feature). Differ one slice once (teams answering — meanings scoping tangible (blurring ending — differing proving permanently). Assign owners; scope meanings — differing discipline in three habits, reviewed per feature.

## 3. Costs pricing honestly (networks billing — operations charging — judgment funding)

**Definition** — honest service pricing: network and operation costs stated per split (networks billing — calls costing (latencies adding — payloads sizing (billing proving — freeriding declining); operations charging — deploys multiplying (dashboards per-serviceing — on-calls staffing (charging funding — hoping declining); judgment funding — evidence buying (numbers justifying — splits earning (funding owning — fashion declining).

**What problem it solves** — the free-split trio: *networks unbilling* (calls assuming-free — latencies ignoring (chats chattering — tails growing (unbilling charging — physics declining); *operations uncharging* (deploys assuming-one — dashboards missing (pagers unstaffing — toil compounding (uncharging billing — reality failing); *splits unfunding* (services spawning — evidence missing (fashion deciding — regret scheduling (unfunding costing — engineering declining). Honest pricing converting freeness to billing (calls costing — deploys multiplying (evidence buying — fashion ending); reviewers finding network-plus-ops prices per split (pricing proving → verifiable; free → returned).

**Modern guidance** — the pricing lines per split (review-enforced): *networks billing* (calls costing — latencies adding (payloads sizing — freeriding declining (billing proving — assuming refusing (calls owning — tails bounding); *operations charging* (deploys multiplying — dashboards per-serviceing (on-calls staffing — hoping declining (charging funding — missing refusing (toil pricing — reality keeping); *judgment funding* (evidence buying — numbers justifying (splits earning — fashion declining (funding owning — spawning refusing (proofs earning — regret declining).

```typescript
// GOOD: costs pricing honestly — network plus operations per split (compiled + run live).
interface Split { // networks billing — calls costing, freeriding declining
  name: string;
  extraCalls: number;
  extraDeploys: number;
}
function priced(s: Split, perCall: number, perDeploy: number): number {
  return s.extraCalls * perCall + s.extraDeploys * perDeploy; // operations charging — deploys multiplying, hoping declining
}
const checkout: Split = { name: 'billing-out', extraCalls: 3, extraDeploys: 1 };
const bill = priced(checkout, 20, 100);
console.log(bill === 160 ? 'costs price' : 'splits free'); // judgment funding — evidence buying, fashion declining
```

```typescript
// BAD: splits freeing — networks unbilling, operations uncharging (real regret shape).
// // "Services are free." (calls assuming-free — deploys assuming-one — regret scheduling).
// // Fashion split (evidence missing — toil compounding). Bill networks; charge operations; fund judgment.)
```

**Common confusion** — *"pricing blocks decomposition (arithmetic vetoing)."* Arithmetic vetoing value (numbers refusing — splits blocking (judgment freezing — evolution stalling (vetoing charging — courage taxing); pricing funding judgment (calls costing — evidence buying (splits earning — fashion declining (funding proving — freeness declining). "Blocking" describing fear (numbers weaponizing — splits freezing); pricing describing honesty (costs stating — evidence buying). State costs (networks billing — operations charging); earn splits (evidence buying — regret declining).

**Performance note** — pricing economics: billing costing rows (calls costing — deploys multiplying (evidence buying — fashion ending); free equivalents costing regret (tails growing — toil compounding (surprises scheduling — trust eroding). Bill cheaply (splits — calls); free never (services — networks).

**Mentor note** — teach "every split carries its bill" (juniors pricing one network-plus-ops sum per split design regret-proof decomposition on first hearing; priceless splits interrogated ("billed where?" — pricing demanding per split). Price one split once (calls costing — deploys multiplying tangible (freeness ending — pricing proving permanently). Count calls; staff pagers — pricing discipline in three habits, reviewed per split.
