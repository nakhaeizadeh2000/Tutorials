# 2.2. Bulkheads isolating resources

## 1. Pools partitioning (threads dividing — queues bounding — contention isolating)

**Definition** — partitioned pools: divided threads bounding queues isolating contention (threads dividing — workers splitting (pools sizing — rivals separating (dividing proving — sharing declining); queues bounding — depths capping (waits limiting — overflows shedding (bounding funding — growing declining); contention isolating — locks localizing (cores freeing — neighbors serving (isolating owning — dragging declining).

**What problem it solves** — the shared-pool trio: *threads undividing* (workers unsharing — pools unsizing (rivals colliding — contention coupling (undividing billing — isolation failing); *queues unbounding* (depths uncapping — waits growing (overflows flooding — callers hanging (unbounding charging — liveness failing); *contention unisolating* (locks unlocalizing — cores undragged (neighbors starving — availability coupling (unisolating costing — bulkheads missing). Partitioned pools converting sharing to dividing (workers splitting — depths capping (locks localizing — contention ending); reviewers finding pool sizes per dependency (partitioning proving → verifiable; sharing → returned).

**Modern guidance** — the partitioning lines per dependency (review-enforced): *threads dividing* (workers splitting — pools sizing (rivals separating — sharing declining (dividing proving — colliding refusing (splits earning — contention ending); *queues bounding* (depths capping — waits limiting (overflows shedding — growing declining (bounding funding — flooding refusing (caps keeping — hangs ending); *contention isolating* (locks localizing — cores freeing (neighbors serving — dragging declining (isolating owning — coupling refusing (locals funding — availability keeping).

```typescript
// GOOD: pools partitioning — divided workers bounding queues (compiled + run live).
class Partition { // threads dividing — workers splitting, sharing declining
  private used = 0;
  constructor(
    readonly name: string,
    private readonly cap: number,
  ) {}
  take(): boolean {
    if (this.used >= this.cap) return false; // queues bounding — depths capping, growing declining
    this.used += 1;
    return true; // contention isolating — locks localizing, dragging declining
  }
  release(): void {
    this.used = Math.max(0, this.used - 1);
  }
}
const billing = new Partition('billing', 2);
const r1 = billing.take();
const r2 = billing.take();
const r3 = billing.take();
billing.release();
const r4 = billing.take();
console.log(r1 && r2 && !r3 && r4 ? 'pools partition' : 'threads share');
```

```typescript
// BAD: threads sharing — pools unsizing, contention unisolating (real coupling shape).
// // One pool for all (workers unsharing — rivals colliding — contention coupling).
// // Unbounded queue (waits growing — callers hanging). Divide workers; bound queues; isolate contention.)
```

**Common confusion** — *"partitions waste capacity (pools idling)."* Idling reserving headroom (workers waiting — bursts absorbing (spikes surviving — neighbors serving (idling serving — efficiency trading); sharing coupling fate (rivals colliding — locks contending (neighbors starving — availability dying (sharing charging — isolation failing). "Wasting" describing idle workers (pools waiting — efficiency trading); partitions describing survival (locks localizing — neighbors serving). Divide pools (workers splitting — contention ending); bound depths (queues capping — hangs ending).

**Performance note** — partitioning economics: dividing costing headroom (workers splitting — queues bounding (locks localizing — contention ending); shared equivalents costing coupling (rivals colliding — waits growing (neighbors starving — availability dying). Divide cheaply (pools — dependencies); share never (threads — rivals).

**Mentor note** — teach "one pool per dependency, sized on paper" (juniors partitioning one worker set per downstream design coupling-proof resources on first hearing; shared pools interrogated ("cap per dep?" — partitioning demanding per dependency). Partition one pool once (workers splitting — queues bounding tangible (sharing ending — partitioning proving permanently). Size pools; cap depths — partitioning discipline in three habits, reviewed per dependency.

## 2. Saturation shedding (full refusing — callers failing-fast — neighbors serving)

**Definition** — shed saturation: full pools refusing with fast-failed callers serving neighbors (full refusing — caps enforcing (overflows rejecting — queues protecting (refusing proving — accepting declining); callers failing-fast — errors returning-quickly (waits skipping — threads freeing (failing funding — hanging declining); neighbors serving — survivors answering (degrades declaring — users keeping (serving owning — drowning declining).

**What problem it solves** — the queue-forever trio: *fulls unrefusing* (caps unenforced — overflows accepted (queues drowning — latencies exploding (unrefusing billing — protection failing); *callers unfailing-fast* (errors unreturned — waits unskipped (threads held — pools exhausting (unfailing charging — survival bluffing); *neighbors unserving* (survivors unanswering — degrades undeclared (users losing — trust eroding (unserving costing — resilience failing). Shed saturation converting drowning to refusing (caps enforcing — errors returning-quickly (survivors answering — neighbors serving); reviewers finding shed policies per pool (shedding proving → verifiable; drowning → returned).

**Modern guidance** — the shedding lines per pool (review-enforced): *full refusing* (caps enforcing — overflows rejecting (queues protecting — accepting declining (refusing proving — drowning refusing (enforcements earning — explosions ending); *callers failing-fast* (errors returning-quickly — waits skipping (threads freeing — hanging declining (failing funding — holding refusing (fasts keeping — survival earning); *neighbors serving* (survivors answering — degrades declaring (users keeping — drowning declining (serving owning — losing refusing (answers funding — trust keeping).

```typescript
// GOOD: saturation shedding — refused full pools with fast failures (compiled + run live).
function shed(load: number, cap: number): string {
  if (load >= cap) return 'SHED-503'; // full refusing — caps enforcing, accepting declining
  return 'SERVE'; // callers failing-fast — errors returning-quickly, hanging declining
}
function neighborServed(shedCount: number, servedCount: number): boolean {
  return servedCount > 0; // neighbors serving — survivors answering, drowning declining
}
console.log(shed(99, 100) === 'SERVE' && shed(100, 100) === 'SHED-503' && neighborServed(40, 60) ? 'saturation sheds' : 'queues drown');
```

```typescript
// BAD: queues drowning — fulls unrefusing, neighbors unserving (real flood shape).
// // Accept all (caps unenforced — queues drowning — latencies exploding).
// // Slow fail (threads held — pools exhausting). Refuse full; fail fast; serve neighbors.)
```

**Common confusion** — *"shedding loses revenue (drops costing)."* Costing pricing survival (ranks ordering — critical serving (cores protecting — recovery bounding (costing proving — avalanching declining); drowning losing everything (queues flooding — latencies exploding (threads exhausting — availability zeroing (drowning charging — revenue failing). "Losing" describing unprotected collapse (all failing — recovery unbounded); shedding describing triage (caps enforcing — neighbors serving). Refuse overload (full rejecting — queues protecting); serve survivors (degrades declaring — users keeping).

**Performance note** — shedding economics: refusing costing rejections (caps enforcing — errors returning-quickly (survivors answering — neighbors serving); drowned equivalents costing floods (queues flooding — threads exhausting (availability zeroing — trust eroding). Refuse cheaply (caps — pools); drown never (queues — neighbors).

**Mentor note** — teach "full means 503, never a queue" (juniors refusing one overload per pool design drown-proof saturation on first hearing; queued overloads interrogated ("shed where?" — shedding demanding per pool). Shed one saturation once (caps enforcing — errors returning tangible (drowning ending — shedding proving permanently). Enforce caps; free threads — shedding discipline in three habits, reviewed per pool.

## 3. Blasts compartmenting (faults containing — ships floating — fleets surviving)

**Definition** — compartmented blasts: contained faults floating ships surviving fleets (faults containing — failures bulkheading (spreads stopping — neighbors serving (containing proving — hopping declining); ships floating — survivors sailing (degrades answering — users keeping (floating owning — sinking declining); fleets surviving — systems enduring (outages partialing — recoveries starting (surviving earning — totaling declining).

**What problem it solves** — the ship-sinking trio: *faults uncontaining* (failures unbulkheaded — spreads unstopped (neighbors drowning — outages totaling (uncontaining billing — compartment missing); *ships unsfloating* (survivors unsailing — degrades unanswering (users abandoning — trust eroding (unsfloating charging — resilience failing); *fleets unsurviving* (systems unenduring — outages totaling (recoveries unstarted — availability zeroing (unsurviving costing — survival bluffing). Compartmented blasts converting sinking to containing (failures bulkheading — survivors sailing (systems enduring — outages partialing); reviewers finding compartments per fault class (compartmenting proving → verifiable; sinking → returned).

**Modern guidance** — the compartmenting lines per fleet (review-enforced): *faults containing* (failures bulkheading — spreads stopping (neighbors serving — hopping declining (containing proving — sinking refusing (bulkheads earning — dominoes ending); *ships floating* (survivors sailing — degrades answering (users keeping — sinking declining (floating owning — abandoning refusing (sails keeping — trust holding); *fleets surviving* (systems enduring — outages partialing (recoveries starting — totaling declining (surviving earning — zeroing refusing (endurance funding — availability keeping).

```typescript
// GOOD: blasts compartmenting — contained faults floating ships (compiled + run live).
function compartments(total: number, failed: number): string {
  if (failed <= 0) return 'HEALTHY'; // faults containing — failures bulkheading, hopping declining
  if (failed >= total) return 'SUNK';
  return 'AFLOAT'; // ships floating — survivors sailing, sinking declining
  // fleets surviving — systems enduring, totaling declining (asserted below)
}
console.log(compartments(5, 0) === 'HEALTHY' && compartments(5, 2) === 'AFLOAT' && compartments(5, 5) === 'SUNK' ? 'blasts compartment' : 'ships sink');
```

// BAD: ships sinking — faults uncontaining, fleets unsurviving (real total shape).
// // Shared fate (failures unbulkheaded — spreads unstopped — outages totaling).
// // No compartments (recoveries unstarted — availability zeroing). Contain faults; float ships; survive fleets.)

**Common confusion** — *"compartments duplicate bulkheads (partitions repeating)."* Repeating redividing pools (workers resplitting — queues recapping (configs doubling — maintenance growing (repeating charging — value halving); compartmenting surviving fleets (faults containing — ships floating (systems enduring — outages partialing (compartmenting proving — sinking declining). "Duplicating" describing copies (pools redividing — value halving); compartments describing survival (blasts bounding — fleets enduring). Partition pools (workers splitting — contention ending); float ships (survivors sailing — trust holding).

**Performance note** — compartmenting economics: containing costing bulkheads (faults bulkheading — ships floating (systems enduring — outages partialing); sunk equivalents costing totals (spreads unstopped — recoveries unstarted (availability zeroing — trust eroding). Contain cheaply (faults — fleets); sink never (ships — systems).

**Mentor note** — teach "one fault sinks one compartment, never the fleet" (juniors containing one blast per fault class design sink-proof fleets on first hearing; uncompartmented fates interrogated ("survives what?" — compartmenting demanding per class).
