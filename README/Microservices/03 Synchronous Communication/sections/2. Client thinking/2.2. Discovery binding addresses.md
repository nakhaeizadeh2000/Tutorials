# 2.2. Discovery binding addresses

## 1. Registries listing (instances registering — health gating — rosters serving)

**Definition** — serving registries: registered instances gated by health listing rosters (instances registering — services announcing (addresses publishing — versions tagging (registering proving — hiding declining); health gating — checks passing (failures evicting — rosters pruning (gating funding — corpsing declining); rosters serving — lookups answering (lists versioning — callers resolving (serving owning — hardcoding declining).

**What problem it solves** — the hardcoded-address trio: *instances unlisting* (services unannouncing — addresses unpublished (callers hardcoding — deploys coupling (unlisting billing — discovery missing); *health ungating* (checks unpassing — corpses lingering (rosters rotting — calls failing (ungating charging — freshness failing); *rosters unserving* (lookups unanswering — lists unversioned (resolutions guessing — balances skewing (unserving costing — coordination missing). Listed registries converting hardcoding to registering (services announcing — checks passing (lookups answering — addresses binding); reviewers finding rosters per environment (listing proving → verifiable; hardcoding → returned).

**Modern guidance** — the listing lines per registry (review-enforced): *instances registering* (services announcing — addresses publishing (versions tagging — hiding declining (registering proving — hardcoding refusing (announcements owning — coupling ending); *health gating* (checks passing — failures evicting (rosters pruning — corpsing declining (gating funding — lingering refusing (gates earning — freshness keeping); *rosters serving* (lookups answering — lists versioning (callers resolving — hardcoding declining (serving owning — guessing refusing (rosters funding — balance enabling).

```typescript
// GOOD: registries listing — registered instances with health-gated rosters (compiled + run live).
interface Instance { // instances registering — services announcing, hiding declining
  addr: string;
  healthy: boolean;
}
function roster(instances: Instance[]): string[] {
  const out: string[] = []; // health gating — checks passing, corpsing declining
  for (const i of instances) {
    if (i.healthy) out.push(i.addr);
  }
  return out; // rosters serving — lookups answering, hardcoding declining
}
const fleet: Instance[] = [
  { addr: '10.0.0.1:80', healthy: true },
  { addr: '10.0.0.2:80', healthy: false },
  { addr: '10.0.0.3:80', healthy: true },
];
console.log(roster(fleet).join() === '10.0.0.1:80,10.0.0.3:80' ? 'registries list' : 'addresses hardcode');
```

"DNS" describing names (records answering — addresses mapping); discovery describing liveness (health gating — rosters pruning). Resolve names (DNS answering — addresses mapping); gate instances (checks passing — corpses evicting).

**Performance note** — listing economics: registering costing heartbeats (services announcing — checks passing (lookups answering — addresses binding); hardcoded equivalents costing coupling (deploys coupling — corpses lingering (calls failing — balance skewing). Register cheaply (rosters — instances); hardcode never (addresses — callers).

## 2. Clients resolving (lookups caching — refreshes scheduling — stale bounding)

**Definition** — resolving clients: cached lookups with scheduled refreshes bounding staleness (lookups caching — rosters memoizing (dials saving — latencies bounding (caching proving — refetching declining); refreshes scheduling — intervals timing (versions comparing — changes adopting (scheduling funding — rotting declining); stale bounding — ages capping (TTL enforcing — corpses expiring (bounding owning — lingering declining).

**What problem it solves** — the lookup-per-call trio: *lookups uncaching* (rosters unmemoized — dials repeating (latencies adding — registries hammering (uncaching billing — economy missing); *refreshes unscheduling* (intervals untimed — changes unadopted (rosters rotting — corpses lingering (unscheduling charging — freshness failing); *stales unbounding* (ages uncapping — TTL unenforced (corpses serving — calls failing (unbounding costing — liveness bluffing). Resolving clients converting refetching to caching (rosters memoizing — intervals timing (ages capping — freshness earning); reviewers finding TTLs per lookup (resolving proving → verifiable; refetching → returned).

**Modern guidance** — the resolving lines per client (review-enforced): *lookups caching* (rosters memoizing — dials saving (latencies bounding — refetching declining (caching proving — repeating refusing (memos earning — registries sparing); *refreshes scheduling* (intervals timing — versions comparing (changes adopting — rotting declining (scheduling funding — timing refusing (schedules owning — freshness keeping); *stale bounding* (ages capping — TTL enforcing (corpses expiring — lingering declining (bounding owning — serving refusing (caps funding — liveness earning).

```typescript
// GOOD: clients resolving — cached lookups with bounded staleness (compiled + run live).
interface Cached { // lookups caching — rosters memoizing, refetching declining
  roster: string[];
  atMs: number;
  ttlMs: number;
}
function fresh(c: Cached, nowMs: number): boolean {
  return nowMs - c.atMs <= c.ttlMs; // refreshes scheduling — intervals timing, rotting declining
}
function resolve(c: Cached, nowMs: number, refetch: () => Cached): string[] {
  if (fresh(c, nowMs)) return c.roster; // stale bounding — ages capping, lingering declining
  return refetch().roster;
}
const cached: Cached = { roster: ['a:80'], atMs: 1000, ttlMs: 5000 };
console.log(resolve(cached, 3000, () => ({ roster: ['b:80'], atMs: 3000, ttlMs: 5000 })).join() === 'a:80' && resolve(cached, 9000, () => ({ roster: ['b:80'], atMs: 9000, ttlMs: 5000 })).join() === 'b:80' ? 'clients resolve' : 'lookups refetch');
```

"Risking" describing unbounded memos (ages uncapping — corpses serving); resolving describing TTLs (caches memoizing — refreshes timing). **Performance note** — resolving economics: caching costing memos (rosters memoizing — intervals timing (ages capping — freshness earning); refetching equivalents costing hammers (dials repeating — registries hammering (latencies adding — economy missing). Memoize cheaply (rosters — TTLs); refetch never (lookups — calls).

**Mentor note** — teach "cache the roster, bound its age" (juniors caching one roster per client design hammer-proof resolution on first hearing; TTL-less caches interrogated ("stale how long?" — resolving demanding per lookup). ## 3. Servers routing (load balancing — instances hiding — callers simplifying)

**Definition** — routing servers: balanced loads with hidden instances simplifying callers (load balancing — traffic splitting (weights honoring — hotspots cooling (balancing proving — skewing declining); instances hiding — backends masking (topologies encapsulating — callers decoupling (hiding owning — hardcoding declining); callers simplifying — endpoints singling (policies centralizing — clients thinning (simplifying funding — meshing declining).

**What problem it solves** — the client-mesh trio: *loads unbalancing* (traffic un splitting — weights unhonored (hotspots burning — neighbors degrading (unbalancing billing — fairness failing); *instances unhiding* (backends unmasked — topologies leaking (callers coupling — refactors breaking (unhiding charging — encapsulation failing); *callers unmeshing* (endpoints multiplying — policies scattering (clients fattening — graphs tangling (unmeshing costing — simplicity failing). Routing servers converting meshing to balancing (traffic splitting — backends masking (endpoints singling — simplicity earning); reviewers finding balancers per entry (routing proving → verifiable; meshing → returned).

**Modern guidance** — the routing lines per entry (review-enforced): *load balancing* (traffic splitting — weights honoring (hotspots cooling — skewing declining (balancing proving — flooding refusing (splits earning — fairness serving); *instances hiding* (backends masking — topologies encapsulating (callers decoupling — hardcoding declining (hiding owning — leaking refusing (masks funding — refactors freeing); *callers simplifying* (endpoints singling — policies centralizing (clients thinning — meshing declining (simplifying funding — fattening refusing (singles earning — graphs untangling).

```typescript
// GOOD: servers routing — balanced loads with hidden instances (compiled + run live).
function pick(weights: number[], salt: number): number {
  const total = weights.reduce((a, b) => a + b, 0); // load balancing — traffic splitting, skewing declining
  if (total <= 0) return -1;
  let roll = salt % total; // instances hiding — backends masking, hardcoding declining
  for (let i = 0; i < weights.length; i++) {
    roll -= weights[i] ?? 0;
    if (roll < 0) return i;
  }
  return weights.length - 1; // callers simplifying — endpoints singling, meshing declining
}
console.log(pick([3, 1], 0) === 0 && pick([3, 1], 3) === 1 && pick([0, 0], 5) === -1 ? 'servers route' : 'clients mesh');
```
