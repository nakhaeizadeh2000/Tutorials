# 5.1. Common interview QA sync calls

## 1. Choosing live under pressure (sync, coupling, patience — diagnosed with fixes, priced)

**Definition** — the choosing answer interviewers grade: given a call, name the transport with gates ([1.1](<../../sections/1. Call thinking/1.1. Request reply choosing sync.md>)) — sync proving (answers gating — waits bounding (journeys completing — events deferring (proving owning — always declining); coupling proving (clocks aligning — nines compounding (SLOs tightening — surprises declining (proving funding — freeness declining); patience proving (answers unblocking — events streaming (independence earning — defaulting declining (proving earning — syncing declining). "Live" means diagnosed fixes (gates naming — products stating — patience routing (proof stating — bluffing declining).

**What problem it solves** — the reciting trio: *transports reciting* (sync naming — gates unmentioned (waits undescribed — budgets unpriced (reciting serving — hiring failing (knowledge hoping — depth doubting); *coupling confusing* (nines equating — products uncomputed (SLOs unstating — surprises scheduling (conflating owning — clarity missing (confusion serving — confidence failing (placing hoping — precision doubting); *patience hoping* (events unstreamed — independence unearned (threads wasted — autonomy bluffing (hoping serving — incidents inviting (judgment failing — experience doubting). Pressured choosing converting reciting to diagnosing (answers gating — nines compounding (patience routing — answers holding); interviewers hearing gates with products, not transport names (diagnosing proving → hirable; reciting → passed) — drawing on [1.1](<../../sections/1. Call thinking/1.1. Request reply choosing sync.md>).

**Modern guidance** — the choosing lines (interview-enforced): *sync gating* (answers needing — waits bounding (journeys completing — events deferring (gating proving — always refusing); *coupling timing* (nines compounding — downtimes unioning (SLOs tightening — surprises declining (timing funding — freeness refusing); *patience routing* (needs-answers deciding — events streaming (independence earning — defaulting refusing (routing owning — syncing declining). Every claim carrying gate + product + patience (judgment demonstrable — pressure survivable).

```typescript
// GOOD: choosing answers — gates, products, patience with diagnosed fixes (answer shape, hiring-grade).
// "Quote gates on its answer with 300ms (sync gating — waits bounding — journeys completing).
//  Chain nines multiply to 0.988 (coupling timing — SLOs tightening — surprises declining).
//  Receipts stream async (patience routing — independence earning — threads freeing).")
```

```typescript
// BAD: choosing recitals — names without gates, hopes without products (real fail shape).
// // "REST between services." (gates unmentioned — waits undescribed — knowledge hoping).
// // "Reliable." (products uncomputed — patience unjudged). Gate answers; multiply nines; route patience.)
```

**Common confusion** — *"naming transports answers choosing (protocols stating)."* Stating listing protocols (letters reciting — mechanics naming (shapes describing — gates missing (stating serving — owning failing); answering proving fit (answers gating — nines compounding (patience routing — independence earning (proving funding — reciting declining). "Answering" describing judgments (gates naming — products stating); naming describing vocabulary (protocols spelling — meaning missing). Gate sync (answers needing — waits bounding); time coupling (nines compounding — SLOs tightening).

**Performance note** — choosing-answer economics: diagnosing costing triples (gates stating — products compounding (patience routing — answers holding); reciting equivalents costing doubt (names listing — judgments missing (depth doubting — hiring failing). State cheaply (triples — transports); recite never (names — hopes).

**Mentor note** — drill "gate, product, patience" (candidates answering per call with answer-gates, nine-products, and patience routes defend choosing on first hearing; protocol-only answers interrogated ("gates what? nines product?" — choosing demanding per claim). Rehearse one routed call once (gate-product-patience tangible (reciting ending — diagnosing proving permanently). Need answers; stream patience — choosing answers in three artifacts, reviewed per interview.

## 2. Bounding live under pressure (budgets, overruns, clocks — honesty stated, not hoped)

**Definition** — the bounding answer interviewers grade: given a chain, name the budget with refusals ([1.2](<../../sections/1. Call thinking/1.2. Deadlines propagating budgets downstream.md>)) — budgets stating (remaining declaring — spends deducting (tails bounding — freshness declining (stating proving — refreshing declining); overruns refusing (expired rejecting — work shedding (cascades declining — zombie declining (refusing funding — working declining); clocks trusting (skews bounding — timeouts aligning (hangs ending — hoping declining (trusting owning — stalling declining). "Live" means honesty first (remains quoting — rejects asserting — skews capping (truth proving — freshness declining).

**What problem it solves** — the hand-waving trio: *budgets waving* (remains unstating — spends unaccounted (tails compounding — waits growing (waving serving — hiring failing (numbers missing — judgment doubting); *overruns forgetting* (expired unrejecting — zombies working (resources burning — cascades scheduling (forgetting owning — discipline missing (silence serving — freshness failing); *clocks missing* (skews unbounding — timeouts unaligning (hangs lingering — threads leaking (missing charging — liveness bluffing (hope serving — calibration failing). Pressured bounding converting waving to stating (remains declaring — expired rejecting (skews capping — answers holding); interviewers hearing remains with rejects, not adjectives (stating proving → hirable; waving → passed) — drawing on [1.2](<../../sections/1. Call thinking/1.2. Deadlines propagating budgets downstream.md>).

**Modern guidance** — the bounding lines (interview-enforced): *budgets forwarding* (remaining stating — spends deducting (tails bounding — freshness declining (forwarding proving — refreshing refusing); *overruns rejecting* (expired refusing — work shedding (cascades declining — zombie declining (rejecting funding — working refusing); *clocks capping* (skews bounding — timeouts aligning (hangs ending — hoping declining (capping owning — stalling refusing). Every claim carrying remain + reject + skew (judgment demonstrable — pressure survivable).

```typescript
// GOOD: bounding answers — remains, rejects, skews with quoted numbers (answer shape, hiring-grade).
// "500ms budget with 340 remaining after two hops (budgets forwarding — tails bounding).
//  Expired refused, thin shed at 50ms (overruns rejecting — cascades declining).
//  Skew capped at 100ms with aligned 500ms timeouts (clocks capping — hangs ending).")
```

```typescript
// BAD: bounding waves — adjectives without remains, comfort without rejects (real fail shape).
// // "We use timeouts." (remains unstating — spends unaccounted — numbers missing).
// // "Rarely expires." (rejects unasserting — zombies working). State remains; assert rejects; cap skews.)
```

**Common confusion** — *"timeouts answer bounding (clocks stating)."* Stating capping hops (waits bounding — tails trimming (hangs refusing — freshness serving (stating serving — propagation missing); bounding forwarding chains (remains declaring — expired rejecting (skews capping — tails ending (bounding proving — freshness declining). "Timeouts" describing singles (hops capping — chains hoping); bounding describing journeys (budgets forwarding — overruns refusing). Cap hops (timeouts stating — tails bounding); forward chains (remains declaring — ledgers balancing).

**Performance note** — bounding-answer economics: stating costing numbers (remains quoting — rejects asserting (skews capping — answers holding); waving equivalents costing doubt (adjectives floating — numbers missing (judgment doubting — hiring failing). State cheaply (budgets — hops); wave never (adjectives — overruns).

**Mentor note** — drill "remain, reject, skew" (candidates answering per chain with remaining budgets, refusal points, and skew caps defend bounding on first hearing; "we use timeouts" interrogated ("remaining? expired? skew?" — bounding demanding per chain). Rehearse one budgeted chain once (remain-reject-skew tangible (waving ending — stating proving permanently). Declare remains; cap skews — bounding answers in three numbers, reviewed per interview.

## 3. Calling live under pressure (proxies, discovery, proof — ownership stated, not hoped)

**Definition** — the calling answer interviewers grade: given a caller, name the pool with rosters ([2.1](<../../sections/2. Client thinking/2.1. Client proxies owning calls.md>)/[2.2](<../../sections/2. Client thinking/2.2. Discovery binding addresses.md>)) — proxies owning (connections pooling — channels sharing (handshakes amortizing — dialing declining (owning proving — rebuilding declining); discovery owning (rosters serving — lookups caching (routes balancing — hardcoding declining (owning earning — meshing declining); proof driving (patterns exercising — responses matching (faults surfacing — silence declining (driving owning — hoping declining). "Live" means ownership stated (pools naming — rosters bounding — patterns driving (proof stating — dialing declining).

**What problem it solves** — the claiming trio: *proxies claiming* (pools unnamed — connections uncounted (handshakes repeating — latencies adding (claiming serving — hiring failing (names missing — proof doubting); *discovery missing* (rosters unserving — lookups uncached (addresses hardcoding — meshes tangling (missing owning — coordination failing (silence serving — freshness bluffing); *proofs hoping* (patterns undriven — responses unawaited (faults unsurfaced — silence spreading (hoping serving — evidence failing). Pressured calling converting claiming to owning (connections pooling — rosters serving (patterns driving — answers holding); interviewers hearing pools with rosters, not assurances (owning proving → hirable; claiming → passed) — drawing on [2.1](<../../sections/2. Client thinking/2.1. Client proxies owning calls.md>) and [2.2](<../../sections/2. Client thinking/2.2. Discovery binding addresses.md>).

**Modern guidance** — the calling lines (interview-enforced): *proxies pooling* (connections caching — channels sharing (handshakes dividing — dials saving (pooling proving — rebuilding refusing); *discovery binding* (rosters serving — lookups caching (routes balancing — hardcoding declining (binding owning — meshing refusing); *proof driving* (patterns exercising — responses matching (faults surfacing — silence declining (driving owning — hoping refusing). Every claim carrying pool + roster + pattern (judgment demonstrable — pressure survivable).

```typescript
// GOOD: calling answers — pools, rosters, patterns with owned callers (answer shape, hiring-grade).
// "One proxy per address pooled (connections caching — handshakes dividing — calls cheapening).
//  Rosters cached with 5s TTL, server-side balanced (discovery binding — hardcodes ending).
//  Patterns driven with faults surfaced (proof driving — silence declining).")
```

```typescript
// BAD: calling claiming — assurances without pools, addresses without rosters (real fail shape).
// // "Efficient clients." (pools unnamed — connections uncounted — names missing).
// // "Service mesh handles it." (rosters unserving — proof undriven). Pool proxies; bind rosters; drive patterns.)
```

**Common confusion** — *"mesh answers calling (infrastructure owning)."* Owning offloading policy (proxies sidecarring — discovery centralizing (certificates rotating — observability uniforming (offloading serving — callers thinning); calling owning discipline (connections pooling — timeouts racing (rosters serving — patterns driving (owning proving — dialing declining). "Mesh" describing platform (policy offloading — callers thinning); calling describing ownership (pools naming — rosters bounding). Name pools (connections caching — dials saving); drive patterns (responses matching — faults surfacing).

**Performance note** — calling-answer economics: owning costing artifacts (pools naming — rosters bounding (patterns driving — answers holding); claiming equivalents costing doubt (assurances floating — artifacts missing (proof doubting — hiring failing). Own cheaply (artifacts — callers); claim never (assurances — calling).

**Mentor note** — drill "pool, roster, pattern" (candidates answering per caller with pooled proxies, bounded rosters, and driven patterns defend calling on first hearing; "efficient" interrogated ("pool? roster? fault?" — calling demanding per caller). Rehearse one owned caller once (pool-roster-pattern tangible (claiming ending — owning proving permanently). Cache proxies; surface faults — calling answers in three ownerships, reviewed per interview.
