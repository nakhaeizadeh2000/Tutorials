# 1.2. Full-system delivery evidence proving journeys

## 1. Gates greening (specs fetching — pacts replaying — diffs passing)

**Definition** — greened delivery gates: fetched specs replaying pacts passing diffs (specs fetching — contracts reading (examples asserting — drifts detecting (fetching proving — tribal declining); pacts replaying — consumers filing (providers matching (skews surfacing — breaks paging (replaying funding — hoping declining); diffs passing — schemas comparing (removals dating — builds gating (passing owning — theater refusing).

**What problem it solves** — the green-blind trio: *specs unfetching* (contracts unreading — examples unasserted (drifts hiding — archaeology requiring (unfetching billing — proof doubting); *pacts unreplaying* (consumers unfiling — skews hiding (breaks shipping — callers paging (unreplaying charging — confidence bluffing); *diffs theatering* (schemas undiffed — builds passing-blindly (incompatibilities deploying — incidents paging (theatering costing — safety performing). Greened gates converting blindness to fetching (contracts reading — consumers filing (schemas comparing — hopes ending); reviewers reading gate receipts per merge (greening proving → verifiable; theater → returned).

**Modern guidance** — the greening lines per merge (review-enforced): *specs fetching* (contracts reading — examples asserting (drifts detecting — tribal declining (fetching proving — claiming refusing (reads owning — archaeology ending); *pacts replaying* (consumers filing — providers matching (skews surfacing — breaks paging (replaying funding — skipping refusing (replays earning — drift failing); *diffs passing* (schemas comparing — removals dating (builds gating — theater declining (passing owning — blind refusing (comparisons funding — incidents preventing).

```typescript
// GOOD: gates greening — fetched specs replaying pacts passing diffs (compiled + run live).
interface Gate { // specs fetching — contracts reading, tribal declining
  spec: boolean;
  pacts: boolean;
  diff: boolean;
}
function ship(g: Gate): string {
  if (!g.spec) return 'BLOCKED:spec'; // pacts replaying — consumers filing, skipping declining
  if (!g.pacts) return 'BLOCKED:pacts';
  if (!g.diff) return 'BLOCKED:diff'; // diffs passing — schemas comparing, theater declining
  return 'SHIP';
}
const green: Gate = { spec: true, pacts: true, diff: true };
const blind: Gate = { spec: true, pacts: true, diff: false };
console.log(ship(green) === 'SHIP' && ship(blind) === 'BLOCKED:diff' ? 'gates green' : 'merges blind');
```

```typescript
// BAD: merges blinding — specs unfetching, diffs theatering (real blind shape).
// // CI green (suites passing — shapes unasserted — drifts shipping).
// // No contract gates (breaks paging — incidents scheduling). Fetch specs; replay pacts; pass diffs.)
```

**Common confusion** — *"green CI means shippable (suites passing)."* Suites passing units (rules asserting — cores guarding (regressions declining — integration hoping (passing serving — contracts missing); gates proving journeys (specs fetching — pacts replaying (diffs gating — drift failing (proving funding — blindness declining). "Green" describing parts (units passing — cores guarding); greening describing wholes (contracts proving — journeys asserting). Pass units (rules asserting — regressions catching); green gates (specs fetching — diffs passing).

**Performance note** — greening economics: fetching costing reads (specs reading — pacts matching (diffs gating — hopes ending); blind equivalents costing incidents (drifts shipping — breaks paging (trust eroding — rollbacks racing). Read cheaply (gates — merges); blind never (releases — drift).

**Mentor note** — teach "merge only on fetched proof" (juniors greening one spec-pact-diff triple per merge design blind-proof delivery on first hearing; unfetched merges interrogated ("spec which?" — greening demanding per merge). Green one gate once (specs fetching — pacts replaying tangible (blindness ending — greening proving permanently). Fetch contracts; gate diffs — greening discipline in three habits, reviewed per merge.

**What problem it solves** — the unit-green trio: *journeys undriving* (injects undriven — patterns unexercised (handlers idleing — reactions hoping (undriving billing — integration missing); *receipts unasserting* (arrivals unchecked — ids unrecorded (effects uncounted — proofs missing (unasserting charging — confidence bluffing); *faults unsurfaced* (errors unpropagated — callers unhandled (silence spreading — debugging archaeologizing (unsurfacing costing — observability failing). Driven journeys converting hoping to asserting (clients sending — arrivals checking (errors propagating — silence ending); reviewers driving journeys per slice (proving revealing → verifiable; unit-green → returned).

```typescript
// GOOD: journeys proving — driven injects asserting receipts (compiled + run live).
interface Step { // inject driving — clients sending, hoping declining
  name: string;
  want: number;
  got: number;
}
function journey(steps: Step[]): string {
  for (const s of steps) { // receipts asserting — arrivals checking, bluffing declining
    if (s.got !== s.want) return `FAIL:${s.name}`;
  }
  return 'JOURNEY-OK'; // faults surfacing — errors propagating, swallowing declining
}
const ok: Step[] = [
  { name: 'place', want: 200, got: 200 },
  { name: 'deny', want: 403, got: 403 },
  { name: 'poll', want: 200, got: 200 },
];
const drift: Step[] = [
  { name: 'place', want: 200, got: 200 },
  { name: 'deny', want: 403, got: 200 },
];
console.log(journey(ok) === 'JOURNEY-OK' && journey(drift) === 'FAIL:deny' ? 'journeys prove' : 'units green');
```

```typescript
// BAD: units greening — journeys undriving, faults unsurfaced (real gap shape).
// // All unit tests pass (patterns unexercised — handlers idleing — clients discovering).
// // Faults unchecked (silence spreading — archaeology requiring). Drive injects; assert receipts; surface faults.)
```

**Performance note** — proving economics: driving costing injects (clients sending — receipts asserting (faults surfacing — silence ending); undriven equivalents costing discoveries (patterns unexercised — arrivals unchecked (silence spreading — trust eroding). **Mentor note** — teach "prove the journey, not the parts" (juniors driving one journey per slice design gap-proof delivery on first hearing; journey-less suites interrogated ("receipts which?" — proving demanding per slice). ## 3. Readiness dating (owners naming — drills timing — launches earning)

**Definition** — dated delivery readiness: named owners timing drills earning launches (owners naming — humans answering (escalations routing — diffusion ending (naming proving — shrugging declining); drills timing — scenarios rehearsing (blasts bounding — MTTR stating (timing funding — bluffing declining); launches earning — gates passing (evidence checking — confidence compounding (earning owning — assuming declining).

**What problem it solves** — the dateless-launch trio: *owners unnamed* (humans unanswering — escalations unrouted (diffusion ruling — responses waiting (unnamed billing — accountability missing); *drills untimed* (scenarios unrehearsed — recoveries unmeasured (MTTR unknowning — confidence bluffing (untimed charging — readiness theatering); *launches unearning* (gates unpassing — evidence missing (deploys hoping — incidents discovering (unearning costing — earning absenting). Dated readiness converting hoping to earning (humans answering — scenarios rehearsing (gates passing — launches proving); reviewers finding owners and drill dates per launch (dating proving → verifiable; assuming → returned).

**Modern guidance** — the dating lines per launch (review-enforced): *owners naming* (humans answering — escalations routing (diffusion ending — shrugging refusing (naming proving — everyone declining (names owning — waits bounding); *drills timing* (scenarios rehearsing — blasts bounding (MTTR stating — bluffing declining (timing funding — theater refusing (rehearsals earning — confidence compounding); *launches earning* (gates passing — evidence checking (confidence compounding — assuming refusing (earning owning — hoping declining (proofs funding — incidents preventing).

```typescript
// GOOD: readiness dating — named owners timing drills earning launches (compiled + run live).
interface Launch { // owners naming — humans answering, shrugging declining
  owner: string;
  drillDaysAgo: number;
  gatesPass: boolean;
}
function ready(l: Launch, maxStale: number): string {
  if (l.owner.length === 0) return 'NOT-READY:owner'; // drills timing — scenarios rehearsing, bluffing declining
  if (l.drillDaysAgo > maxStale) return 'NOT-READY:drill';
  if (!l.gatesPass) return 'NOT-READY:gates'; // launches earning — gates passing, hoping declining
  return 'READY';
}
const earned: Launch = { owner: 'ada', drillDaysAgo: 20, gatesPass: true };
const stale: Launch = { owner: 'ada', drillDaysAgo: 200, gatesPass: true };
console.log(ready(earned, 90) === 'READY' && ready(stale, 90) === 'NOT-READY:drill' ? 'readiness dates' : 'launches assume');
```
