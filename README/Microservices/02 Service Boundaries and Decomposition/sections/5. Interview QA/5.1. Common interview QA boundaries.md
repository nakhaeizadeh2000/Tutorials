# 5.1. Common interview QA boundaries

## 1. Decomposition live under pressure (capabilities, data, cuts — diagnosed with fixes, priced)

**Definition** — the decomposition answer interviewers grade: given a monolith, name the cuts with tables ([1.1](<../../sections/1. Boundary thinking/1.1. Capabilities clustering contexts.md>)/[1.2](<../../sections/1. Boundary thinking/1.2. Data owning per service.md>)) — capabilities proving (behaviors grouping — teams aligning (services emerging — layers declining (proving owning — slicing declining); data proving (writes singling — reads serving (joins declining — sharing declining (proving funding — pooling declining); cuts pricing (calls counting — autonomy earning (bills attaching — theater declining (pricing earning — hoping declining). "Live" means diagnosed fixes (splits naming — remedies stating — prices attaching (proof stating — bluffing declining).

**What problem it solves** — the reciting trio: *capabilities reciting* (services naming — behaviors unmentioned (teams undescribed — tables unowned (reciting serving — hiring failing (knowledge hoping — depth doubting); *data confusing* (tables equating — writes unplaced (owners unassigned — joins sprawling (conflating owning — clarity missing (confusion serving — confidence failing (placing hoping — precision doubting); *cuts hoping* (calls uncounting — autonomy unproving (bills unstating — theater ruling (hoping serving — incidents inviting (judgment failing — experience doubting). Pressured decomposition converting reciting to diagnosing (behaviors grouping — writes singling (calls counting — answers holding); interviewers hearing capabilities with tables, not service names (diagnosing proving → hirable; reciting → passed) — drawing on [1.1](<../../sections/1. Boundary thinking/1.1. Capabilities clustering contexts.md>) and [1.2](<../../sections/1. Boundary thinking/1.2. Data owning per service.md>).

**Modern guidance** — the decomposition lines (interview-enforced): *capabilities grouping* (behaviors naming — teams aligning (services emerging — layers declining (grouping proving — slicing refusing); *data owning* (writes singling — reads serving (joins declining — sharing refusing (owning funding — pooling declining); *cuts validating* (calls counting — autonomy earning (bills attaching — theater declining (validating owning — hoping refusing). Every claim carrying capability + table + cut (judgment demonstrable — pressure survivable).

```typescript
// GOOD: decomposition answers — capabilities, tables, cuts with diagnosed fixes (answer shape, hiring-grade).
// "Checkout clusters cart-pay-confirm under team-pay (behaviors grouping — owners answering).
//  Orders table writes single in orders-svc, reads served (writes singling — joins declining).
//  Cut validated at 1 cross-call with zero shared tables (calls counting — autonomy earning).")
```

```typescript
// BAD: decomposition recitals — names without capabilities, hopes without tables (real fail shape).
// // "Orders, billing, notify." (behaviors unmentioned — teams undescribed — knowledge hoping).
// // "Split by entity." (tables unowned — cuts hoping). Group behaviors; own tables; validate cuts.)
```

**Common confusion** — *"naming services answers decomposition (topology stating)."* Stating listing deployables (names reciting — boundaries unmentioned (tables undescribed — cuts unjudged (stating serving — owning failing); answering proving cuts (behaviors grouping — writes singling (calls counting — autonomy earning (proving funding — reciting declining). "Answering" describing judgments (capabilities naming — tables owning); naming describing vocabulary (services spelling — meaning missing). Group capabilities (behaviors naming — teams aligning); own tables (writers singling — joins declining).

**Performance note** — decomposition-answer economics: diagnosing costing triples (capabilities stating — tables owning (cuts validating — answers holding); reciting equivalents costing doubt (names listing — judgments missing (depth doubting — hiring failing). State cheaply (triples — cuts); recite never (names — hopes).

**Mentor note** — drill "capability, table, cut" (candidates answering per split with behaviors, owners, and call counts defend decomposition on first hearing; service-list answers interrogated ("capability? tables? calls?" — decomposition demanding per claim). Rehearse one cut story once (behavior-table-cut tangible (reciting ending — diagnosing proving permanently). Name behaviors; count calls — decomposition answers in three artifacts, reviewed per interview.

Data owning per service.md>); checklist in [4.1](<../../sections/4. Mentor checklist/4.1. Decomposition checklist mentors insist on.md>).

## 2. Coupling live under pressure (edges, instability, kernels — honesty stated, not hoped)

**Definition** — the coupling answer interviewers grade: given a service graph, name the risks with ratios ([2.1](<../../sections/2. Coupling thinking/2.1. Afferent efferent measuring coupling.md>)/[2.2](<../../sections/2. Coupling thinking/2.2. Shared kernel versioning contracts.md>)) — edges stating (fan-ins tallying — fan-outs tallying (meshes surfacing — hiding declining (stating proving — burying declining); instability pricing (ratios computing — dependents warning (changes budgeting — vibing declining (pricing funding — surprising declining); kernels versioning (shares shrinking — ACLs owning (pacts replaying — drift failing (versioning owning — sprawling declining). "Live" means honesty first (ratios quoting — arrows correcting — kernels numbering (truth proving — hiding declining).

**What problem it solves** — the hand-waving trio: *edges waving* (counts unstating — dependents unlisting (meshes hiding — graphs tangling (waving serving — hiring failing (numbers missing — judgment doubting); *ratios forgetting* (instability uncomputing — dependents unwarning (surprises scheduling — calibration missing (forgetting owning — arithmetic failing (silence serving — vibing deciding); *kernels missing* (shares unversioning — ACLs unowning (corruption seeping — consumers stranding (missing charging — shielding absenting (hope serving — safety theatering). Pressured coupling converting waving to stating (edges tallying — ratios computing (kernels numbering — answers holding); interviewers hearing ratios with arrows, not adjectives (stating proving → hirable; waving → passed) — drawing on [2.1](<../../sections/2. Coupling thinking/2.1. Afferent efferent measuring coupling.md>) and [2.2](<../../sections/2. Coupling thinking/2.2. Shared kernel versioning contracts.md>).

**Modern guidance** — the coupling lines (interview-enforced): *edges counting* (fan-ins tallying — fan-outs tallying (meshes surfacing — hiding declining (counting proving — burying refusing); *ratios quoting* (instability computing — dependents warning (changes budgeting — vibing declining (quoting funding — surprising refusing); *kernels numbering* (shares shrinking — versions tagging (spreads bounding — sprawling declining (numbering owning — missing refusing). Every claim carrying edge + ratio + kernel (judgment demonstrable — pressure survivable).

```typescript
// GOOD: coupling answers — edges, ratios, kernels with quoted numbers (answer shape, hiring-grade).
// "Orders fans out twice, instability 0.2 with 4 dependents warned (edges tallying — ratios computing).
//  Money kernel v3 shared by 2 importers under cap (shares shrinking — spreads bounding).
//  Arrows point stable-ward, no cycles (directions correcting — builds ordering).")
```

```typescript
// BAD: coupling waves — adjectives without edges, comfort without ratios (real fail shape).
// // "Loosely coupled." (counts unstating — dependents unlisting — numbers missing).
// // "Shared library." (kernels unversioning — spreads unbounding). Tally edges; quote ratios; number kernels.)
```

**Common confusion** — *"low coupling answers everything (decoupling satisfying)."* Satisfying avoiding trade-offs (numbers missing — judgments absenting (splits unowned — autonomy unproved (satisfying serving — hiring failing (comfort owning — courage missing); coupling measuring risks (edges tallying — ratios computing (arrows correcting — kernels numbering (measuring proving — waving declining). "Low" describing comfort (adjectives floating — numbers missing); coupling describing arithmetic (ratios quoting — blasts stating). Tally fan-ins (dependents listing — pages preventing); correct arrows (stables depending — ripples ending).

**Performance note** — coupling-answer economics: stating costing numbers (edges tallying — ratios computing (kernels numbering — answers holding); waving equivalents costing doubt (adjectives floating — numbers missing (judgment doubting — hiring failing). State cheaply (ratios — edges); wave never (adjectives — hopes).

**Mentor note** — drill "edge, ratio, kernel" (candidates answering per graph with tallies, instability scores, and kernel versions defend coupling on first hearing; "loosely coupled" interrogated ("I value? kernel which?" — coupling demanding per claim). Rehearse one graph story once (edge-ratio-kernel tangible (waving ending — stating proving permanently). Quote instability; version shares — coupling answers in three numbers, reviewed per interview.

## 3. Ownership live under pressure (tables, versions, autonomy — ownership stated, not hoped)

**Definition** — the ownership answer interviewers grade: given shared state, name the owner with versions ([1.2](<../../sections/1. Boundary thinking/1.2. Data owning per service.md>)/[2.2](<../../sections/2. Coupling thinking/2.2. Shared kernel versioning contracts.md>)) — tables owning (writes singling — reads serving (joins declining — sharing declining (owning proving — pooling declining); versions numbering (releases tagging — breaks dating (consumers migrating — drifting declining (numbering owning — ambushing declining); autonomy proving (deploys independing — failures isolating (partitions driving — theater declining (proving earning — coupling declining). "Live" means ownership stated (writers naming — versions tagging — partitions driving (proof stating — sharing declining).

**What problem it solves** — the claiming trio: *tables claiming* (owners unnamed — writers unlisted (rows contending — locks escalating (claiming serving — hiring failing (names missing — proof doubting); *versions missing* (releases untagging — breaks ambushing (consumers discovering — production paging (missing owning — evolution failing (silence serving — drift hiding); *autonomy hoping* (partitions undriven — tables unaudited (deploys coupling — services theatering (hoping serving — evidence failing). Pressured ownership converting claiming to naming (writers singling — versions tagging (partitions driving — answers holding); interviewers hearing owners with versions, not assurances (naming proving → hirable; claiming → passed) — drawing on [1.2](<../../sections/1. Boundary thinking/1.2. Data owning per service.md>) and [2.2](<../../sections/2. Coupling thinking/2.2. Shared kernel versioning contracts.md>).

**Modern guidance** — the ownership lines (interview-enforced): *tables singling* (owners naming — writers listing (conflicts serializing — sharing declining (singling proving — pooling refusing); *versions tagging* (releases numbering — breaks dating (consumers migrating — drifting declining (tagging owning — ambushing refusing); *autonomy driving* (partitions exercising — edges asserting (deploys independing — theater declining (driving owning — hoping refusing). Every claim carrying writer + version + partition (judgment demonstrable — pressure survivable).

```typescript
// GOOD: ownership answers — writers, versions, partitions with named owners (answer shape, hiring-grade).
// "Orders table writes single in orders-svc (writers singling — conflicts serializing).
//  Money kernel v3 with pact green (versions tagging — drifts failing).
//  Partition driven over TCP with autonomy asserted (partitions driving — theater declining).")
```

```typescript
// BAD: ownership claiming — assurances without writers, shares without versions (real fail shape).
// // "We own our data." (owners unnamed — writers unlisted — names missing).
// // "Shared utils." (versions untagging — spreads unbounding). Name writers; tag versions; drive partitions.)
```

**Common confusion** — *"ownership is paperwork (rows assigning)."* Paperwork filing names (owners listing — writers naming (tables assigning — partitions ignoring (filing serving — autonomy missing); ownership proving partitions (writes singling — versions tagging (deploys driving — theater declining (proving funding — claiming declining). "Paperwork" describing rows (names filing — partitions ignoring); ownership describing proof (writers singling — versions tagging). Name writers (owners listing — conflicts serializing); drive partitions (clients sending — autonomy earning).

**Performance note** — ownership-answer economics: naming costing artifacts (writers singling — versions tagging (partitions driving — answers holding); claiming equivalents costing doubt (assurances floating — artifacts missing (proof doubting — hiring failing). Name cheaply (artifacts — tables); claim never (assurances — ownership).

**Mentor note** — drill "writer, version, partition" (candidates answering per share with singled writers, tagged kernels, and driven partitions defend ownership on first hearing; "we own it" interrogated ("writer? version? partition?" — ownership demanding per claim). Rehearse one ownership story once (writer-version-partition tangible (claiming ending — naming proving permanently). Single writers; tag kernels — ownership answers in three namings, reviewed per interview.
