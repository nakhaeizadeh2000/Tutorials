# 1.2. Data owning per service

## 1. Tables owning (writes singling — reads serving — joins declining)

**Definition** — owned tables: single writers serving reads with declined joins (writes singling — owners writing (contenders queueing — conflicts serializing (singling proving — sharing declining); reads serving — queries answering (caches bounding — replicas scaling (serving funding — starving declining); joins declining — spans refusing (aggregates bounding — cross-fetching pricing (declining owning — spanning declining).

**What problem it solves** — the shared-table trio: *writes unsharing* (services co-writing — rows contending (locks escalating — deadlocks scheduling (unsharing billing — ownership missing); *reads unstarving* (queries unserved — replicas missing (hotspots burning — neighbors degrading (unstarving charging — serving failing); *joins unspanning* (queries crossing — transactions distributing (consistency hoping — rollbacks missing (unspanning costing — atomicity bluffing). Owned tables converting sharing to singling (owners writing — queries answering (spans refusing — consistency bounding); reviewers finding owner tables per service (owning proving → verifiable; sharing → returned).

**Modern guidance** — the owning lines per table (review-enforced): *writes singling* (owners writing — contenders queueing (conflicts serializing — sharing declining (singling proving — co-writing refusing (owners earning — deadlock ending); *reads serving* (queries answering — caches bounding (replicas scaling — starving declining (serving funding — missing refusing (answers keeping — hotspots cooling); *joins declining* ([DatabaseDesign 07/6.1](<../../../../DatabaseDesign/07 Production Modeling and Interview Mastery/sections/6. Boundaries/6.1. Boundaries what is covered elsewhere.md>) — spans refusing (aggregates bounding — cross-fetching pricing (declining owning — spanning refusing (refusals funding — hope ending).

```typescript
// GOOD: tables owning — singled writers with served reads (compiled + run live).
interface Table { // writes singling — owners writing, sharing declining
  name: string;
  writers: string[];
}
function shared(tables: Table[]): string[] {
  const gaps: string[] = []; // reads serving — queries answering, starving declining
  for (const t of tables) {
    if (t.writers.length !== 1) gaps.push(t.name);
  }
  return gaps; // joins declining — spans refusing, spanning declining
}
const owned: Table[] = [
  { name: 'orders', writers: ['orders-svc'] },
  { name: 'invoices', writers: ['billing-svc'] },
];
const pooled: Table[] = [{ name: 'orders', writers: ['orders-svc', 'billing-svc'] }];
console.log(shared(owned).length === 0 && shared(pooled).join() === 'orders' ? 'tables own' : 'writes share');
```

```typescript
// BAD: writes sharing — tables pooling, joins spanning (real contention shape).
// // billing writes orders (rows contending — locks escalating — deadlocks scheduling).
// // Cross-service join (transactions distributing — rollbacks missing). Single writers; serve reads; decline joins.)
```

**Common confusion** — *"one database per service means one server per service (hosts multiplying)."* Hosts multiplying hardware (servers provisioning — instances isolating (failures bounding — bills growing (multiplying proving — sharing declining); owning scoping writes (owners writing — tables bounding (conflicts serializing — joins declining (owning funding — pooling declining). "Servers" describing infrastructure (hosts provisioning — failures bounding); owning describing access (writers singling — spans refusing). Isolate logically (owners writing — conflicts serializing); share hosts pragmatically (servers provisioning — bills bounding).

**Performance note** — owning economics: singling costing owners (writers writing — queries answering (spans refusing — consistency bounding); shared equivalents costing contention (locks escalating — deadlocks scheduling (transactions distributing — atomicity bluffing). Single cheaply (writers — tables); share never (rows — services).

**Mentor note** — teach "one writer per table, named on the table" (juniors singling one owner per table design contention-proof data on first hearing; multi-writer tables interrogated ("owner who?" — owning demanding per table). Own one table once (owners writing — spans refusing tangible (sharing ending — owning proving permanently). Single writes; serve reads — owning discipline in three habits, reviewed per table.

## 2. Access serving (APIs exposing — callers querying — tables hiding)

**Definition** — served access: table reads exposed as APIs with hidden storage (APIs exposing — endpoints listing (queries answering — callers coding (exposing proving — reaching declining); callers querying — contracts coding (shapes trusting — versions pinning (querying funding — assuming declining); tables hiding — storage encapsulating (schemas evolving — migrations freeing (hiding owning — coupling declining).

**What problem it solves** — the direct-access trio: *APIs unexposing* (reads unlisted — callers reaching-through (tables touching — schemas leaking (unexposing billing — encapsulation failing); *callers unquerying* (contracts unowned — shapes assuming (producers evolving — consumers breaking (unquerying charging — confidence bluffing); *tables unhiding* (storage exposing — schemas freezing (migrations dreading — evolution stalling (unhiding costing — coupling compounding). Served access converting reaching to exposing (endpoints listing — contracts coding (storage encapsulating — coupling declining); reviewers finding read APIs per table (serving proving → verifiable; reaching → returned).

**Modern guidance** — the serving lines per table (review-enforced): *APIs exposing* (endpoints listing — queries answering (callers coding — reaching declining (exposing proving — touching refusing (lists owning — leaks ending); *callers querying* ([01/3.1](<../../../01 Microservices Foundations and Mental Model/sections/3. First safety/3.1. Contracts between services.md>) — contracts coding (shapes trusting — versions pinning (querying funding — assuming refusing (codes earning — breaks declining); *tables hiding* (storage encapsulating — schemas evolving (migrations freeing — coupling declining (hiding owning — exposing refusing (capsules funding — freezes ending).

```typescript
// GOOD: access serving — exposed reads with hidden tables (compiled + run live).
interface ReadApi { // APIs exposing — endpoints listing, reaching declining
  table: string;
  endpoint: string;
}
function reaching(apis: ReadApi[]): string[] {
  const gaps: string[] = []; // callers querying — contracts coding, assuming declining
  for (const a of apis) {
    if (a.endpoint.length === 0) gaps.push(a.table);
  }
  return gaps; // tables hiding — storage encapsulating, coupling declining
}
const served: ReadApi[] = [
  { table: 'orders', endpoint: 'GET /orders/:id' },
  { table: 'invoices', endpoint: 'GET /invoices/:id' },
];
const direct: ReadApi[] = [{ table: 'orders', endpoint: '' }];
console.log(reaching(served).length === 0 && reaching(direct).join() === 'orders' ? 'access serves' : 'tables leak');
```

```typescript
// BAD: tables leaking — reads reaching-through, storage exposing (real reach shape).
// // SELECT * FROM orders (tables touching — schemas leaking — migrations dreading).
// // No read API (encapsulation failing — coupling compounding). Expose endpoints; code contracts; hide tables.)
```

**Common confusion** — *"read APIs slow consumers (hops adding)."* Hops adding latency (calls costing — tails growing (waits bounding — budgets pricing (adding proving — freeness declining); reaching coupling schemas (tables touching — migrations dreading (evolution stalling — changes fearing (coupling charging — freedom failing). "Slowing" describing nanoseconds-to-milliseconds (hops costing — tails growing); serving describing freedom (schemas evolving — migrations freeing). Expose reads (endpoints listing — callers coding); evolve storage (schemas migrating — coupling declining).

**Performance note** — serving economics: exposing costing endpoints (reads listing — contracts coding (storage hiding — coupling declining); reaching equivalents costing freezes (schemas freezing — migrations dreading (evolution stalling — changes fearing). Expose cheaply (APIs — tables); reach never (storage — callers).

**Mentor note** — teach "no table crossed without an endpoint" (juniors exposing one read API per shared table design leak-proof data on first hearing; direct table reads interrogated ("endpoint which?" — serving demanding per table). Serve one read once (endpoints listing — storage hiding tangible (reaching ending — serving proving permanently). List endpoints; encapsulate storage — serving discipline in three habits, reviewed per table.

## 3. Sharing refusing (databases decoupling — transactions bounding — consistency pricing)

**Definition** — refused sharing: decoupled databases with bounded transactions and priced consistency (databases decoupling — stores separating (failures isolating — deploys independing (decoupling proving — pooling declining); transactions bounding — scopes singling (spans refusing — sagas sequencing (bounding funding — distributing declining); consistency pricing — staleness stating (lags quoting — windows bounding (pricing owning — hoping declining).

**What problem it solves** — the shared-database trio: *databases unpooling* (stores sharing — failures coupling (deploys locking — blast widening (unpooling billing — isolation failing); *transactions undistributing* (scopes spanning — spans hoping (atomicity bluffing — rollbacks missing (undistributing charging — consistency theatering); *consistency unpricing* (staleness undeclared — lags unquoted (readers assuming — surprises scheduling (unpricing costing — honesty failing). Refused sharing converting pooling to decoupling (stores separating — scopes singling (staleness stating — consistency bounding); reviewers finding no shared stores per service (refusing proving → verifiable; pooling → returned).

**Modern guidance** — the refusing lines per service (review-enforced): *databases decoupling* (stores separating — failures isolating (deploys independing — pooling declining (decoupling proving — sharing refusing (separations earning — blasts bounding); *transactions bounding* (scopes singling — spans refusing (sagas sequencing — distributing declining (bounding funding — spanning refusing (bounds keeping — atomicity honesting); *consistency pricing* (staleness stating — lags quoting (windows bounding — hoping declining (pricing owning — assuming refusing (statements funding — surprise declining).

```typescript
// GOOD: sharing refusing — decoupled stores with priced consistency (compiled + run live).
interface Store { // databases decoupling — stores separating, pooling declining
  service: string;
  store: string;
  maxLagMs: number;
}
function pooled(stores: Store[]): string[] {
  const seen = new Map<string, string>(); // transactions bounding — scopes singling, spanning declining
  const gaps: string[] = [];
  for (const s of stores) {
    const prior = seen.get(s.store);
    if (prior !== undefined && prior !== s.service) gaps.push(s.store);
    seen.set(s.store, s.service);
  }
  return gaps; // consistency pricing — staleness stating, hoping declining
}
const split: Store[] = [
  { service: 'orders', store: 'orders-db', maxLagMs: 0 },
  { service: 'billing', store: 'billing-db', maxLagMs: 500 },
];
const shared: Store[] = [
  { service: 'orders', store: 'main-db', maxLagMs: 0 },
  { service: 'billing', store: 'main-db', maxLagMs: 0 },
];
console.log(pooled(split).length === 0 && pooled(shared).join() === 'main-db' ? 'sharing refuses' : 'databases pool');
```

```typescript
// BAD: databases pooling — stores sharing, consistency unpricing (real pool shape).
// // One main-db (failures coupling — deploys locking — blast widening).
// // Cross-service transaction (atomicity bluffing — rollbacks missing). Separate stores; bound scopes; price lags.)
```

**Common confusion** — *"separate databases waste resources (stores duplicating)."* Duplicating provisioning hosts (servers multiplying — bills growing (capacity splitting — utilization dipping (duplicating charging — frugality failing); refusing sharing access (stores separating — scopes singling (lags quoting — consistency bounding (refusing proving — pooling declining). "Wasting" describing hosts (servers multiplying — bills growing); sharing describing coupling (failures coupling — deploys locking). Separate logically (stores owning — blasts bounding); share hosts pragmatically (servers provisioning — bills bounding).

**Performance note** — refusing economics: separating costing stores (databases decoupling — scopes singling (lags quoting — consistency bounding); pooled equivalents costing coupling (failures coupling — atomicity bluffing (rollbacks missing — trust eroding). Separate cheaply (stores — services); pool never (databases — blast).

**Mentor note** — teach "share nothing that fails together" (juniors separating one store per service design pool-proof data on first hearing; shared stores interrogated ("blast what?" — refusing demanding per store). Refuse one share once (stores separating — scopes singling tangible (pooling ending — refusing proving permanently). Decouple databases; quote lags — refusing discipline in three habits, reviewed per store.
