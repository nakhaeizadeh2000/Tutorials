# 1.1. Capabilities clustering contexts

## 1. Capabilities clustering (behaviors grouping — teams aligning — services emerging)

**Definition** — capability clustering: business behaviors grouped with aligned teams emitting services (behaviors grouping — capabilities naming (cohesion maximizing — scatter minimizing (grouping proving — slicing declining); teams aligning — owners answering (cognition bounding — communication saturating (aligning funding — diffusion declining); services emerging — deployables crystallizing (releases independing — failures isolating (emerging owning — forcing declining).

**What problem it solves** — the technical-slice trio: *behaviors ungrouping* (layers owning — features scattering (changes shotgunning — cohesion failing (ungrouping billing — capability missing); *teams unaligning* (owners diffusing — cognition overloading (communication tangling — velocity dying (unaligning charging — alignment failing); *services unforcing* (tables dictating — entities grouping (deployments mirroring-schema (unforcing billing — domain missing). Clustered capabilities converting layering to grouping (behaviors naming — teams answering (deployables crystallizing — cohesion earning); reviewers finding capability maps per service (clustering proving → verifiable; layering → returned).

**Modern guidance** — the clustering lines per service (review-enforced): *behaviors grouping* (capabilities naming — cohesion maximizing (scatter minimizing — slicing declining (grouping proving — layering refusing (names owning — shotgun ending); *teams aligning* (owners answering — cognition bounding (communication saturating — diffusion declining (aligning funding — orphaning refusing (answers earning — velocity keeping); *services emerging* (deployables crystallizing — releases independing (failures isolating — forcing declining (emerging owning — tabling refusing (crystals funding — autonomy earning).

```typescript
// GOOD: capabilities clustering — grouped behaviors with aligned teams (compiled + run live).
interface Capability { // behaviors grouping — capabilities naming, slicing declining
  name: string;
  behaviors: string[];
  owner: string;
}
function scattered(caps: Capability[]): string[] {
  const gaps: string[] = []; // teams aligning — owners answering, diffusion declining
  for (const c of caps) {
    if (c.behaviors.length === 0 || c.owner.length === 0) gaps.push(c.name);
  }
  return gaps; // services emerging — deployables crystallizing, forcing declining
}
const clustered: Capability[] = [
  { name: 'checkout', behaviors: ['cart', 'pay', 'confirm'], owner: 'team-pay' },
  { name: 'catalog', behaviors: ['browse', 'search'], owner: 'team-shop' },
];
const layered: Capability[] = [{ name: 'controllers', behaviors: [], owner: '' }];
console.log(scattered(clustered).length === 0 && scattered(layered).join() === 'controllers' ? 'capabilities cluster' : 'layers slice');
```

```typescript
// GOOD: cuts validating — counted calls with owned tables (compiled + run live).
interface Cut { // calls counting — edges listing, meshing declining
  name: string;
  crossCalls: number;
  sharedTables: number;
  deploysAlone: boolean;
}
function hopeful(cuts: Cut[], callCap: number): string[] {
  const gaps: string[] = []; // tables owning — writes singling, sharing declining
  for (const c of cuts) {
    if (c.crossCalls > callCap || c.sharedTables > 0 || !c.deploysAlone) gaps.push(c.name);
  }
  return gaps; // autonomy proving — deploys independing, theater declining
}
const clean: Cut[] = [{ name: 'billing', crossCalls: 1, sharedTables: 0, deploysAlone: true }];
const hopefulCut: Cut[] = [{ name: 'billing', crossCalls: 9, sharedTables: 2, deploysAlone: false }];
console.log(hopeful(clean, 3).length === 0 && hopeful(hopefulCut, 3).join() === 'billing' ? 'cuts validate' : 'hopes cut');
```
