# 2.1. Afferent efferent measuring coupling

## 1. Edges counting (fan-ins tallying — fan-outs tallying — meshes surfacing)

**Definition** — counted service edges: incoming dependents and outgoing dependencies tallied per service (fan-ins tallying — dependents listing (blasts sizing — changes warning (tallying proving — hiding declining); fan-outs tallying — dependencies listing (breakages tracing — upgrades sequencing (tallying funding — hoping declining); meshes surfacing — graphs drawing (tangles visualizing — hotspots naming (surfacing owning — burying declining).

**What problem it solves** — the uncounted-graph trio: *fan-ins untallying* (dependents unlisting — blasts unsizing (changes surprising — incidents paging (untallying billing — visibility failing); *fan-outs untallying* (dependencies unlisting — breakages untracing (upgrades unsequenced — rollouts gambling (untallying charging — sequencing missing); *meshes unburying* (graphs undrawing — tangles hiding (hotspots unnamed — refactors blind (unburying costing — topology hoping). Counted edges converting hiding to tallying (dependents listing — dependencies tracing (graphs drawing — tangles surfacing); reviewers finding edge tables per service (counting proving → verifiable; hiding → returned).

**Modern guidance** — the counting lines per service (review-enforced): *fan-ins tallying* (dependents listing — blasts sizing (changes warning — hiding declining (tallying proving — surprising refusing (lists owning — pages preventing); *fan-outs tallying* (dependencies listing — breakages tracing (upgrades sequencing — hoping declining (tallying funding — gambling refusing (traces earning — rollouts ordering); *meshes surfacing* (graphs drawing — tangles visualizing (hotspots naming — burying declining (surfacing owning — hiding refusing (drawings funding — blindness ending).

```typescript
// GOOD: edges counting — tallied fan-ins with traced fan-outs (compiled + run live).
interface ServiceEdges { // fan-ins tallying — dependents listing, hiding declining
  name: string;
  fanIn: string[];
  fanOut: string[];
}
function untallied(services: ServiceEdges[]): string[] {
  const gaps: string[] = []; // fan-outs tallying — dependencies listing, hoping declining
  for (const s of services) {
    if (s.fanIn.length + s.fanOut.length === 0) gaps.push(s.name);
  }
  return gaps; // meshes surfacing — graphs drawing, burying declining
}
const graphed: ServiceEdges[] = [
  { name: 'orders', fanIn: ['gateway'], fanOut: ['billing'] },
  { name: 'billing', fanIn: ['orders'], fanOut: [] },
];
const blank: ServiceEdges[] = [{ name: 'mystery', fanIn: [], fanOut: [] }];
console.log(untallied(graphed).length === 0 && untallied(blank).join() === 'mystery' ? 'edges count' : 'graphs hide');
```

```typescript
// BAD: graphs hiding — edges uncounting, meshes unburying (real tangle shape).
```

**Common confusion** — *"counting is bureaucracy (tables taxing)."* Bureaucracy taxing without decisions (forms filing — reviews rubber-stamping (time spending — safety bluffing (taxing charging — velocity dying); counting sizing blasts (dependents listing — breakages tracing (graphs drawing — tangles surfacing (sizing proving — hiding declining). "Bureaucracy" describing ritual (forms filing — reviews stamping); counting describing visibility (edges tallying — hotspots naming). Tally edges (fan-ins listing — fan-outs tracing); surface meshes (graphs drawing — blindness ending).

**Performance note** — counting economics: tallying costing tables (edges listing — graphs drawing (tangles surfacing — blindness ending); hidden equivalents costing surprises (blasts unsizing — rollouts gambling (incidents paging — trust eroding). Table cheaply (edges — services); hide never (graphs — meshes).

**Mentor note** — teach "every service lists its edges" (juniors tallying one fan-in/fan-out pair per service design tangle-proof topologies on first hearing; edgeless services interrogated ("called by whom? calls what?" — counting demanding per service). Count one graph once (dependents listing — dependencies tracing tangible (hiding ending — counting proving permanently). List dependents; draw meshes — counting discipline in three habits, reviewed per service.

## 2. Instability pricing (volatility scoring — dependents warning — changes budgeting)

**What problem it solves** — the stable-volatility trio: *volatility unpricing* (ratios uncomputing — changes unpredicting (risks unpricing — surprises scheduling (unpricing billing — arithmetic failing); *dependents unwarning* (blasts unstating — owners unpaging (releases ungating — incidents discovering (unwarning charging — calibration missing); *changes unbudgeting* (frequencies uncapping — reviews unscheduling (migrations unsequenced — rollouts gambling (unbudgeting costing — discipline missing). **Modern guidance** — the pricing lines per service (review-enforced): *volatility scoring* ([DP 01/3.1](<../../../../DesignPatterns/01 SOLID Principles and Design Foundations/sections/3. Composition and coupling/3.1.
```typescript
// GOOD: instability pricing — scored volatility with warned dependents (compiled + run live).
interface Stability { // volatility scoring — ratios computing, vibing declining
  name: string;
  afferent: number;
  efferent: number;
}
function instability(s: Stability): number {
  const total = s.afferent + s.efferent; // dependents warning — blasts stating, assuming declining
  if (total === 0) return 0;
  return s.efferent / total; // changes budgeting — frequencies capping, hoping declining
}
const rock: Stability = { name: 'billing', afferent: 4, efferent: 1 };
const leaf: Stability = { name: 'notify', afferent: 0, efferent: 3 };
console.log(instability(rock) === 0.2 && instability(leaf) === 1 ? 'instability prices' : 'volatility vibes');
```

## 3. Directions correcting (stable depending — abstractions owning — cycles breaking)

**Definition** — corrected directions: dependencies pointing toward stability through owned abstractions with broken cycles (stable depending — volatiles isolating (policies depending-inward (changes localizing — depending proving — inverting declining); abstractions owning — seams contracting (details hiding — vendors swapping (owning funding — concretion declining); cycles breaking — graphs acyclicing (builds ordering — deploys sequencing (breaking owning — deadlocking declining).

**What problem it solves** — the wrong-way trio: *stables undepending* (volatiles depending-upon (policies leaking-outward (changes rippling — incidents scheduling (undepending billing — direction failing); *abstractions unowning* (seams uncontracting — details leaking (vendors welding — swaps blocking (unowning charging — flexibility failing); *cycles unbreaking* (graphs cycling — builds deadlocking (deploys unorderable — releases coupling (unbreaking costing — autonomy bluffing). Corrected directions converting inversion to depending (volatiles isolating — seams contracting (graphs acyclicing — changes localizing); reviewers finding dependency arrows per service (correcting proving → verifiable; inverting → returned).

**Modern guidance** — the correcting lines per dependency (review-enforced): *stable depending* (volatiles isolating — policies depending-inward (changes localizing — inverting declining (depending proving — leaking refusing (arrows earning — ripples ending); *abstractions owning* ([CA 06](<../../../../CleanArchitecture/06 Persistence and Framework Isolation/README.md>) — seams contracting (details hiding — vendors swapping (owning funding — welding refusing (contracts keeping — flexibility earning); *cycles breaking* (graphs acyclicing — builds ordering (deploys sequencing — deadlocking declining (breaking owning — cycling refusing (orders funding — autonomy keeping).

```typescript
// GOOD: directions correcting — stable arrows with owned abstractions (compiled + run live).
interface Arrow { // stable depending — volatiles isolating, inverting declining
  from: string;
  to: string;
  stableTo: boolean;
}
function wrongWay(arrows: Arrow[]): string[] {
  const gaps: string[] = []; // abstractions owning — seams contracting, welding declining
  for (const a of arrows) {
    if (!a.stableTo) gaps.push(`${a.from}->${a.to}`);
  }
  return gaps; // cycles breaking — graphs acyclicing, deadlocking declining
}
function cyclic(arrows: Arrow[]): boolean {
  const seen = new Set<string>();
  for (const a of arrows) {
    const key = [a.from, a.to].sort().join('|');
    if (seen.has(key)) return true;
    seen.add(key);
  }
  return false;
}
const clean: Arrow[] = [{ from: 'gateway', to: 'orders', stableTo: true }];
const flipped: Arrow[] = [{ from: 'orders', to: 'mailer-sdk', stableTo: false }];
console.log(wrongWay(clean).length === 0 && wrongWay(flipped).join() === 'orders->mailer-sdk' && !cyclic(clean) ? 'directions correct' : 'arrows invert');
```

