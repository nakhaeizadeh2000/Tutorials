## 6.1. Boundaries: what is covered elsewhere

### 1) **Joining and proposing**

**Definition** — this domain undoes and replays; it does not join lines or propose them. Joining (fast-forward vs true merge, conflict loops, `rerere`) lives in [Domain 03](<../../../03 Branching Merging and Conflicts/README.md>); moving commits between machines and through review (fetch/push, upstream, forks, PR flow, currency) lives in [Domain 04](<../../../04 Remotes GitHub and Pull Requests/README.md>). When this domain says "rebase onto the fresh base" or "lease-push to your PR branch," the *freshness* and the *proposal* are links, not paragraphs.

- **Why the boundary matters**: undo questions ("how do I take this back?") and join/propose questions ("how do two lines become one? how does code get reviewed?") share a keyboard but different models — replacement vs joining, visibility vs direction. Re-teaching joins inside rewrite leaves produces the classic confusion ("is rebase a kind of merge?") that leaf 2.2 spends a section correcting. Keep them split: join in 03, propose in 04, undo and replay here.
- **Modern guidance** — if a passage here needs more than one sentence of merge/conflict/PR mechanics, stop and link instead. The one-sentence versions: joins slide, record, or resolve (Domain 03); proposals branch, push, review, merge-delete (Domain 04). Everything else here is *replacement* (amend/rebase), *inversion* (revert), or *rescue* (reflog).

```bash
# GOOD: one line here, depth behind the link
git rebase origin/main   # the freshness underneath is Domain 04 §3.1 — only the replay is new
# BAD: re-explaining fetch/pull/push, PR flow, or conflict-marker anatomy in undo leaves
```

### 2) **Policy and releases**

**Definition** — which strategy mandates rebase vs merge, how tags mark releases, how stash shelves half-done work, and how trust is enforced (signing, secrets, hooks, protected branches) belong to Domains 06–07 — not here. This domain teaches the *operations* (how replay/undo/rescue work mechanically); 06–07 teach the *rules* (when the team requires, forbids, or gates them). The operation/policy split is the handshake: learn the tool here, obey the rule there.

- **Why the boundary matters**: operations without policy are trivia ("I know rebase flags"); policy without operations is unenforceable ("always rebase" from engineers who can't). Each side references the other once: this domain notes where policy will constrain the tool (lease-only pushes, no shared rewrites — with forwards), and Domains 06–07 assume the tool works as taught here. Duplicating either direction rots both.
- **Modern guidance** — memorize the two forwards used here and defer the rest: replay-vs-join mandates and release lines → [Domain 06](<../../../06 Workflows Tags Stash and Releases/README.md>); signing, secret response, branch protection, review gates → [Domain 07](<../../../07 Production Checklist Security and Collaboration Mastery/README.md>). When policy curiosity strikes mid-rebase ("but does my team even allow rebasing?"), follow the link — [Domain 06 answers with strategy shapes, not flag tables](<../../../06 Workflows Tags Stash and Releases/README.md>).

```bash
# GOOD: borrow the rule-slot, link the rulebook
git rebase main   # whether the team wants this or a merge is Domain 06 policy (live link below)
# BAD: strategy debates (trunk vs flow, squash vs merge) or GPG setup inside undo leaves
```

### 3) **Everyday composition and the model**

**Definition** — staging, messages, log archaeology (Domain 02), and the snapshot/DAG/three-area model (Domain 01) are assumed background, linked where undo touches them — never re-taught. Map-style stop-list: model → 01, composition → 02, joining → 03, proposing → 04, operations → here (05), policy → 06, trust → 07.

- **Why the boundary matters**: every boundary crossed here is duplication that rots — staging tutorials copied into unstage leaves, DAG diagrams copied into reflog leaves. Single source of truth (PROMPT §5): the concept gets its full treatment once, everywhere else one line plus a link. This leaf is the map that keeps those lines short.
- **Modern guidance** — when writing or reviewing Domain 05 content, ask "does a sibling domain own this sentence?" If yes, compress to a link. The domain stops at: uncompose (restore), invert (revert), replace (amend/rebase/cherry-pick), rescue (reflog) — everything about *what the commits contain*, *how they travel*, or *which rules govern them* lives elsewhere.

### 4) **Common confusion**

- "Undo is where advanced Git lives" — undo is *correction*; the advanced mechanics concentrate in replay (here), policy (06), and trust (07). This domain is the repair shop, not the whole factory.
- "Boundaries leaves are filler" — they are the DRY contract made visible: each states what this domain deliberately does *not* teach so neighbors can teach it once.

### 5) **Performance note**

No runtime cost to boundaries — the performance is editorial: one-line links instead of copied sections keep every leaf short, searchable, and single-sourced. When Domain 02 changes message conventions, one domain updates instead of five.

Use this leaf as the "where do I look?" map for juniors arriving with undo-adjacent questions: joining → 03, proposing → 04, policy → 06, trust → 07, staging → 02, model → 01. Quiz: "where does squash-vs-merge live?" (06), "where does signing live?" (07), "where does fetch-first live?" (04). Correct answers mean the track's architecture landed.
