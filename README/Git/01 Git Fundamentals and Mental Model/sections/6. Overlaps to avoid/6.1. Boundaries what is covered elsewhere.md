## 6.1. Boundaries: what is covered elsewhere

### 1) **Everyday commands and inspection depth**

This domain taught the *model* behind `add`, `commit`, `status`, `diff`, and `log` — one deliberate loop. Fluency lives in [Domain 02: Core Workflow](<../../../02 Core Workflow Add Commit and Inspect/README.md>): partial staging at scale, `log` filtering and formatting, `show`/`blame` archaeology, `.gitignore` patterns that keep `status` fast, and aliases that compress the daily loop. If you can explain *why* the index exists but still type every flag longhand, Domain 02 is your next stop — not more theory here.

- **Boundary rule**: Domain 01 answers "what is happening?" — Domain 02 answers "how do I do it fast every day?" Never expand command-flag catalogs here; link forward instead.

### 2) **Branching, merging, conflicts, remotes, GitHub, history rewrite, workflows**

The rest of the track, in order — each owns its mechanics fully, and this leaf stays a signpost:

1. **[Domain 03 — Branching, Merging, and Conflicts](<../../../03 Branching Merging and Conflicts/README.md>)**: creating and switching branches, fast-forward vs true merges, reading conflict markers, resolving without fear.
2. **[Domain 04 — Remotes, GitHub, and Pull Requests](<../../../04 Remotes GitHub and Pull Requests/README.md>)**: `fetch`/`pull`/`push`, tracking branches, forks, PR review flow, keeping a fork current.
3. **[Domain 05 — Undo, Fix, and Rewrite History](<../../../05 Undo Fix and Rewrite History/README.md>)**: `restore`, `reset`, `revert`, `rebase`, `cherry-pick`, `reflog` recovery — and the golden rule of never rewriting shared history.
4. **[Domain 06 — Workflows, Tags, Stash, and Releases](<../../../06 Workflows Tags Stash and Releases/README.md>)**: trunk-based vs GitFlow shapes, tagging releases, stashing half-done work, LFS for large assets.
5. **Domain 07 — Production Checklist, Security, and Collaboration Mastery**: signing commits, secret hygiene, protected branches, review etiquette, mentor-grade workflows.

### 3) **Word-level vocabulary**

What "repo", "branch", "commit", "merge", "pull request", or "conflict" *means in a meeting* — the naming level — belongs to [IT Vocabulary Domain 03 §1](<../../../../ITVocabulary/03 Software Development and Engineering Terms/sections/1. Change words/1.1. Repo branch commit and merge.md>) and [§1.2 on PRs and review](<../../../../ITVocabulary/03 Software Development and Engineering Terms/sections/1. Change words/1.2. Pull request review and conflicts.md>). This track never re-teaches definitions those leaves own; it links to them and teaches the commands and models underneath.

- **Boundary rule**: if a sentence explains what a word *means to a teammate*, it belongs in IT Vocabulary. If it explains what a command *does to the graph*, it belongs here. The one sanctioned overlap is deliberate: words point, mechanics operate.

### 4) **Common confusion**

- "I finished Domain 01, so I know Git" — you know the *model*. Fluency (Domain 02), collaboration (Domains 03–04), and rescue (Domain 05) are separate skills built on this foundation, not contained in it.
- "This boundary list will go stale" — it is maintained: each Domain 02–07 session upgrades the corresponding line here from "(planned, see LOG)" to a live link, the same placeholder-retirement discipline the IT Vocabulary track used across its 7 domains.
- "Overlaps mean duplication" — no: every cross-boundary mention in this track is one line plus a link (DRY single-source-of-truth). Full treatment lives in exactly one place.

### 5) **Mentor note**

Teach boundaries as a map, not a disclaimer: "you are here (model), fluency is east (Domain 02), teamwork is north (03–04), rescue is the hospital (05)". Juniors who see the map stop demanding advanced answers from fundamentals material — and stop feeling lost when a teammate mentions `rebase`. Review check for this domain: the learner can place any Git question they hear this week into exactly one domain bucket. Placement accuracy *is* fundamentals mastery.
