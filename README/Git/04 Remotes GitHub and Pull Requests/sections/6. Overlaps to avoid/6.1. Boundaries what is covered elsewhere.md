## 6.1. Boundaries: what is covered elsewhere

### 1) **Label theory and local joining**

**Definition** — this domain moves commits between machines and through review; it does not re-teach what a branch *is* or how two lines *join*. The branch-as-pointer model and the commit DAG live in [Domain 01 §1.2](<../../../01 Git Fundamentals and Mental Model/sections/1. Thinking in snapshots/1.2. The commit DAG history as a graph.md>); fast-forward slides vs true-merge joins vs conflict loops live in [Domain 03 §2](<../../../03 Branching Merging and Conflicts/sections/2. Joining lines/2.1. Fast-forward vs true merges.md>). When this domain says "merge after fetching," the *mechanics* of that merge are a link, not a paragraph.

- **Why the boundary matters**: sync questions ("their line moved, now what?") and join questions ("how do two lines become one?") feel like one question at the keyboard but are answered by different models — mirrors and divergence (here) vs graph shape and resolution loops (there). Merging the explanations produces the longest, least re-readable leaves in Git pedagogy: half network, half graph, fully confusing. Keep them split: learn the join locally (Domain 03), then apply it remotely (here).
- **Modern guidance** — if a passage here needs more than one sentence of DAG or merge theory, stop and link instead. The one-sentence versions: branches are movable labels on commits (Domain 01); joining is sliding, recording, or resolving (Domain 03). Everything else in this domain is *direction* (which remote) and *process* (which review).

```bash
# GOOD: one line here, depth behind the link
git merge origin/main   # the join itself works exactly like Domain 03 §2.1 — only the direction is new
# BAD: re-explaining two-parent commits, fast-forward slides, or marker anatomy in a remotes leaf
```

### 2) **Rewriting and rescue**

**Definition** — replaying commits (`rebase`, `amend`), unpublishing mistakes (`reset`, `restore`), undoing joins (`revert`), and recovering anything (`reflog`) belong to [Domain 05 (Undo, Fix, and Rewrite History)](<../../../05 Undo Fix and Rewrite History/README.md>) — not here. This domain *names* those tools at the exact points they apply (rebase private lines in leaf 3.1, lease-push after replay) and links; [Domain 05](<../../../05 Undo Fix and Rewrite History/README.md>) owns the spellings, the safety contracts, and the rescue drills.

- **Why the boundary matters**: rewrite tools are the sharpest in Git — every one of them can orphan colleagues' work when misapplied to shared lines. Teaching them inside a collaboration-flow leaf invites skimming ("I'll rebase later") without the safety model (private-vs-public, lease-vs-force, reflog-as-seatbelt). [Domain 05](<../../../05 Undo Fix and Rewrite History/README.md>) teaches them as a disciplined unit with verified failure outputs; this domain borrows only the conclusions.
- **Modern guidance** — memorize the two conclusions used here and defer the rest: rebase private / merge public (leaf 3.1), and `--force-with-lease` never bare `--force` (leaf 3.1). When curiosity strikes mid-PR ("but what does interactive rebase actually do?"), follow the forward link — [Domain 05 answers with scratch-repo drills, not prose](<../../../05 Undo Fix and Rewrite History/README.md>).

```bash
# GOOD: borrow the conclusion, link the discipline
git rebase main   # private line only — the full safety model lives in Domain 05 (live link below)
# BAD: full rebase/reset/reflog tutorials inside remotes leaves — duplicated, and read without the safety frame
```

### 3) **Merge policy, release lines, and trust**

**Definition** — three neighboring territories this domain touches but never owns: *which* join strategy teams mandate (squash vs merge vs rebase, protected branches — Domain 06 Workflows); *how* commits prove authorship and stay secret-safe (signing, secret hygiene, hooks/CI gates — Domain 07 Production Checklist); *how* messages and atomicity make review possible at all (Domains 02–03). Map-style stop-list: strategy → 06, trust → 07, composition → 02, branching → 03.

- **Why the boundary matters**: every boundary crossed here is duplication that rots — merge-policy advice copied into a PR-flow leaf goes stale when the team changes policy; signing instructions copied into a push leaf go stale when the forge changes key rules. Single source of truth (PROMPT §5): the concept gets its full treatment once, everywhere else one line plus a link. This leaf is the map that keeps those lines short.
- **Modern guidance** — when writing or reviewing Domain 04 content, ask "does a sibling domain own this sentence?" If yes, compress to a link. The domain stops at: commits moved (fetch/push), paired (upstream), proposed (PR), and refreshed (sync) — everything about *what the commits contain*, *which strategy joins them*, or *how they're trusted* lives elsewhere.

```bash
# GOOD: boundary as map — one line per neighbor, then stop

#  Trust (signing, secrets, hooks/CI gates)                  → Domain 07 (planned, see LOG)
#  Composition (atomic commits, messages)                    → Domain 02 (live links above)

```

### 4) **Common confusion**

- "Remotes are where the advanced Git lives" — remotes are *transport plus process*; the advanced mechanics (rewrite, rescue, policy) live in Domains 05–07. This domain is the bridge, not the destination.
- "Boundaries leaves are filler" — they are the DRY contract made visible: each states what this domain deliberately does *not* teach so the next domain can teach it once.

### 5) **Performance note**

No runtime cost to boundaries — the performance is editorial: one-line links instead of copied sections keep every leaf short, searchable, and single-sourced. When Domain 06 changes merge policy, one domain updates instead of four.

### 6) **Mentor note**

Use this leaf as the "where do I look?" map for juniors arriving with remotes-adjacent questions: joining → 03, rewriting → 05, policy → 06, trust → 07. Quiz: "where does amend live?" (05), "where does squash-vs-merge live?" (06), "where does signing live?" (07). Correct answers mean the track's architecture landed — the most valuable thing a boundaries leaf can teach.
