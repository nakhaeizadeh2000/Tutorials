## 4.1. Remotes checklist (habits mentors insist on)

### 1) **Fetch before you reason**

**Definition** — every remote question — "are we in sync?", "can I push?", "what did they change?" — starts with `git fetch --all` and a read (`status -sb`, `log --oneline HEAD..origin/<branch>`). Stale mirrors lie by omission (leaf 1.2): reasoning from yesterday's `origin/main` produces today's wrong join. The fetch costs seconds; the wrong join costs a rescue (Domain 05).

- **What problem it solves**: most sync incidents are stale-read incidents — merges against old bases, pushes refused by unseen commits, reviews of superseded tips. The ritual removes the entire class: fresh mirrors, counted gaps (ahead/behind), read incoming side, then act. Three lines, every time, no judgment required.
- **Modern guidance** — alias it if your fingers resist (`git config --global alias.fsa 'fetch --all'` is one team's whole sync policy in three letters). Pair with `pull.ff only` so even the pull half refuses surprise joins. Juniors should be able to recite "fetch, count, read, choose" before they can explain what a remote-tracking branch is — habit first, model second.

```bash
# GOOD: the ritual, verbatim — fetch, count, read, choose
git fetch --all          # Fetching origin / Fetching upstream
git status -sb           # ## feat/x...origin/feat/x [ahead 1, behind 2] — the situation in numbers
git log --oneline HEAD..origin/feat/x   # what they added — read before joining
# BAD: operating on mirrors you haven't refreshed since morning standup
```

### 2) **Upstream set once, trusted always**

**Definition** — `git push -u origin <branch>` on first push pairs the line forever; thereafter bare `push`/`pull`/`status` resolve through the pairing. Audit any clone with `git branch -vv`: every active branch shows its `[origin/...]` partner; bare entries are setup debt. The `push.autoSetupRemote true` global makes first-push pairing automatic — set it once per machine.

- **Why it matters (correctness)**: unpaired branches force full coordinates on every sync — and every coordinate is a wrong-target opportunity (`push origin HEAD:main` from a feature branch overwrites the release line). The pairing moves the destination decision to branch-creation time, when attention is highest, and removes it from the fifty daily syncs when attention is lowest. Fewer decisions per sync, fewer wrong destinations.
- **Modern guidance** — set `-u` reflexively; enable `autoSetupRemote` globally; audit with `branch -vv` in code-review-adjacent moments (pairing someone's environment, onboarding). Never normalize "just push with the full spelling" — the full spelling is the escape hatch, not the workflow.

```bash
# GOOD: pair on birth, audit occasionally
git push -u origin feat/x   # branch 'feat/x' set up to track 'origin/feat/x'.
git branch -vv              # feat/x c671bf6 [origin/feat/x] C — paired, bare push safe
# BAD: branches with no upstream weeks into their life — every sync a fresh chance to mistype
```

### 3) **Propose small, sync often**

**Definition** — the collaboration loop stays cheap when the gaps stay small: short-lived branches (Domain 03 §1.2, merged in days), weekly fork refreshes (leaf 3.1), PRs under ~400 lines (leaf 2.2). Each practice bounds one divergence — branch-vs-base, fork-vs-source, proposal-vs-attention — so no gap grows large enough to hurt.

- **Why it hurts when missing (correctness, maintainability)**: large gaps compound — a month-old branch on a month-old fork proposing 2,000 lines combines staleness, conflicts, dead-API CI, and unreviewable scope into one artifact nobody can merge and nobody wants to close. Each practice alone is mild hygiene; together they guarantee every collaboration act (push, propose, review, join) operates on a small, fresh, readable delta. Teams don't adopt "sync often" as culture — they adopt the three mechanics and culture follows.
- **Modern guidance** — make it checkable, not aspirational: no open PR older than two weeks without a freshness comment, no branch living past its second Friday, `fetch --all` in the morning ritual. Mentors audit gaps, not intentions — `status -sb` numbers, PR ages, branch lists. Small and fresh beats big and clever at every review table.

```bash
# GOOD: gaps small in all three dimensions
git branch --merged main | grep feat/    # merged labels awaiting deletion — prune them
git fetch --all && git status -sb       # freshness check: behind counts near zero is healthy
# BAD: month-old branches on month-old forks proposing thousand-line PRs —
# every dimension of the loop rotten at once, mergeable only by heroics
```

### 4) **Common confusion**

- "Checklists are for beginners" — checklists are for *load-bearing routines performed under distraction*. Pilots use them; push, propose, and sync qualify.
- "I fetch, so I'm current" — fetch refreshes mirrors; your branches join only when you merge or rebase. Fetching without joining is reading the weather and never dressing for it.
- "Small PRs mean more process overhead" — overhead per PR is roughly constant (open, CI, review, merge); total latency falls because small PRs wait less and fail less. Ten quick merges beat one slow one.

### 5) **Performance note**

The whole ritual (`fetch --all` + `status` + one `log`) runs in seconds with zero network beyond incremental objects — cheaper than one context switch. Its payoff is measured in avoided rescues: each prevented surprise-merge or stale-PR incident saves hours of history surgery (Domain 05) and re-review. The highest-leverage seconds in a Git workday.

### 6) **Mentor note**

Turn this leaf into a laminated card (literal or wiki): fetch-count-read-choose, pair-on-birth, small-and-fresh. Quiz juniors on the *responses*, not the commands — "ahead-only means?", "diverged means?", "behind-12 on a PR means?" — until the table is reflex. Watch for checklist decay (ritual performed for a week, then abandoned under deadline pressure — fix by making CI or branch protection enforce the outcomes: required fresh-base merges, required `-u`-paired pushes via `autoSetupRemote`). Review check: `branch -vv` clean, `status -sb` read before every join, no PR older than two weeks unfreshened.
