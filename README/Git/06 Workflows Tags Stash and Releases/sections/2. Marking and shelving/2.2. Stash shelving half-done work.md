## 2.2. Stash: shelving half-done work

### 1) **Stash is a pause button**

**Definition** — `git stash push -m "<message>"` shelves the uncommitted tree (working tree *and* index by default) onto a stack and restores `HEAD` cleanliness — switch contexts without committing half-ideas. `git stash pop` restores the newest entry and drops it from the stack. Verified on Git 2.53.0: after `push -m "wip experiment"`, `git stash list` shows `stash@{0}: On main: wip experiment` and `git status --short` is clean; after `pop`, the output reads `Dropped refs/stash@{0} (...)` and `status` shows ` M f.txt` again — shelved, then resumed, exactly.

- **What problem it solves**: interruptions don't wait for commit-shaped work — the incident call arrives mid-experiment, the review request lands mid-refactor. Without a pause button the choices are all bad: commit the half-idea (pollutes history, triggers CI on nonsense), discard it (loses the thread), or carry dirty state into the other task (cross-contamination — the fix touches the feature's files). Stash suspends the current thread safely: tree clean for the interruption, experiment intact for return.
- **Modern guidance** — stash for *interruptions* (incident, urgent review, context switch under an hour): `push -m`, handle the interruption on a clean tree, `pop`, continue. Apply-vs-pop deliberately: `pop` (restore + drop) when resuming now; `apply` (restore, keep entry) when testing whether the shelf still fits. Never `pop` onto a diverged line blindly — conflicting pops merge like any join (resolve per hunk, Domain 03 loop), and `--index` restores staged-vs-unstaged separation when the distinction matters.

```bash
# GOOD: pause, interrupt, resume — verified cycle
git stash push -m "wip experiment"
#  Saved working directory and index state On main: wip experiment
git stash list    # stash@{0}: On main: wip experiment
#  ... handle the interruption on a clean tree ...
git stash pop
#  Dropped refs/stash@{0} (...)   + status shows " M f.txt" — resumed exactly
# BAD: committing "WIP DO NOT MERGE" to switch contexts —
# half-ideas in history trigger CI, confuse blame, and need surgical removal later
```

### 2) **Name every stash**

**Definition** — the `-m` message is the difference between a shelf and a junk drawer: `stash@{0}: On main: wip experiment` tells future-you what sleeps there; bare `WIP on main` (the default) tells nothing, and three such entries are indistinguishable. `git stash list` reads the stack newest-first; `show -p stash@{n}` previews any entry's diff without restoring it. Discipline: message at push time (context is fresh), list before pop (confirm the right entry), drop what's dead.

- **Why it matters (correctness)**: unnamed stash stacks are where experiments go to die — weeks later `stash@{0..4}` all read `WIP on main`, nobody dares pop (which line does each belong to? does it still apply?), and the stack becomes write-only memory nobody trusts. Every such stack ends the same way: `clear` in frustration, or permanent residence nobody audits. Messages convert the stack from amnesia into inventory: pop with confidence, drop with certainty, audit in seconds.
- **Modern guidance** — `-m` on every push (branch + intent: `"feat/cart — halfway through guard refactor"`), `list` before every pop (pop the *named* entry you expect, `pop stash@{n}` when it's not the top), `show -p` before popping stale entries (does it still fit this line?), `drop` the moment an entry is obsolete. Cap the stack socially: more than three entries means something should have been a branch (next section) — stashes older than the week get branched or dropped, never curated indefinitely.

```bash
# GOOD: inventory, not amnesia — message, list, preview, drop
git stash push -m "feat/cart — halfway through guard refactor"
git stash list
#  stash@{0}: On main: feat/cart — halfway through guard refactor
git stash show -p stash@{0} | head   # preview before restoring — still fits?
git stash drop stash@{0}             # obsolete? drop explicitly — no mystery entries linger
# BAD: five bare `git stash` pushes ("WIP on main" × 5) —
# a write-only stack where popping is archaeology and dropping feels like deletion roulette
```

### 3) **Stash is local and short-lived**

**Definition** — stash entries live in your clone only (never pushed, never fetched — no teammate can see your shelf) and have no branch semantics (no upstream, no PR, no CI). The doctrine: shelf for *hours* (interruptions), branch for *days* (real lines of work), push for *durability* (anything that must survive the laptop). Stash covers the gap between "can't commit yet" and "must switch now" — nothing wider.

- **Why it hurts when missing (correctness, maintainability)**: stash-as-storage produces the two failure shapes teams recognize — the laptop-loss wipeout (weeks of "shelved" work in an unpushed, unreflogged stack dies with the disk) and the pop-onto-wrong-line merge (a month-old shelf applied to a moved base, conflicts resolved from faded memory, committed as one mystery blob). Both stem from using a pause button as a filing cabinet. Branches are cheap, pushed branches are durable, stash is neither — respect the tool's size.
- **Modern guidance** — time-box every stash: end-of-day rule — shelf becomes a WIP branch (`switch -c wip/...` + commit + push) before leaving, or it's dropped deliberately. For work worth keeping across machines, `commit --allow-empty`? No — commit honestly on a `wip/` branch and push (unpushed WIP commits are still local, but they're *labeled* and reflogged, unlike stash entries nobody listed). Include untracked files explicitly when the experiment needs them (`push -u` — default stash skips untracked; surprises await the popper who assumed otherwise). Audit weekly: `stash list` should be short or empty — a long list is branches waiting to be born.

```bash
# GOOD: pause-button scope — short, local, promoted or dropped daily
git stash push -m "spike — timing approach A"   # interrupt, handle, pop same day
#  end of day, still unpopped? → git switch -c wip/timing-A && git add -A && git commit -m ... && git push -u origin wip/timing-A
# BAD: month-old stash stacks as "my system" —
# unpushed, unlabeled-by-branch, invisible to teammates, one disk failure from gone
```

### 4) **Common confusion**

- "Stash push loses staged-vs-unstaged separation" — default pop restores everything unstaged, true; `--index` (on push) plus pop restores the separation. Know the flag when the distinction carries meaning (partially-staged careful compositions — Domain 02 §1.1).
- "Stash includes untracked files" — not by default (new files stay in the tree, which surprises during "clean tree" interruptions). `-u` includes untracked (not ignored — `-a` for those, rarely wise).
- "`pop` conflicts mean the stash broke" — pop conflicts are ordinary joins (shelf vs moved base) resolved by the Domain 03 loop. The stash entry *stays* on conflict (pop drops only on clean restore) — resolve, verify, then drop explicitly.
- "Stash is a backup tool" — stash is a *pause* tool. Backups are pushed branches (server-side, durable, visible). If losing the laptop would hurt, it shouldn't be a stash.

### 5) **Performance note**

Stash operations are local object writes (one commit-shaped entry per push) — instant at any scale; `list`/`show` read local refs. Untracked-file stashes (`-u`) copy file contents into the store (I/O proportional to the files — slow on `node_modules`-scale accidents, another reason `.gitignore` hygiene from Domain 02 §3.1 matters). The cost that counts is cognitive: unnamed stacks cost minutes per pop in archaeology; messages cost seconds at push. Highest-ROI flag in the interruption workflow.

### 6) **Mentor note**

Drill the verified cycle (push → list → clean tree → pop → resume) until it's faster than explaining it — interruptions are timed events, and fumbling the pause wastes the calm before the storm. Then drill the stale-pop: stash on Monday's base, advance the line ten commits, pop Friday (conflicts — resolve with the Domain 03 loop, drop explicitly). That pair teaches both halves: pausing is free, resuming has a price that grows with staleness. Watch for the stash-hoarder (stack as filing system — fix with the end-of-day branch-or-drop rule) and the WIP-committer (half-ideas in history — fix with push/pop fluency plus "branches are cheap" permission). Review check: `stash list` short or empty at week end, every entry messaged, no WIP commits on shared lines, juniors can pause-and-resume mid-sentence without losing either thread.
