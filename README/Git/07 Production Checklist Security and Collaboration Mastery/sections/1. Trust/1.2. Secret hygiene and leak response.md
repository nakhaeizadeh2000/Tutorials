## 1.2. Secret hygiene and leak response

### 1) **Prevention beats surgery**

**Definition** — three layers that keep secrets out of history: `.gitignore` first (`.env`, `*.pem`, credential files — never staged, per Domain 02 §3.1), pattern scanning in CI (secret-scanning on every push — the forge's native scanner plus a shape check), and pre-commit hooks locally (refuse the commit containing a key-shaped string before it exists). Verified shape-check on Git 2.53.0 scratch: planting `aws_secret = "AKIAIOSFODNN7EXAMPLE"` in `config.ini` trips `grep -rEn '(AKIA[0-9A-Z]{16}|ghp_[A-Za-z0-9]{36}|sk-[A-Za-z0-9]{20,}|-----BEGIN [A-Z ]*PRIVATE KEY-----)' --include='*.ini' …` on line 1 — the one-liner any hook or job wraps.

- **What problem it solves**: committed secrets are the highest-leverage mistakes in version control — one push publishes credentials to every clone, fork, CI log, and (public repos) the entire internet, where scanners harvest them in seconds. Removal afterward (next sections) is surgery with uncertain margins: you can delete the bytes from *your* history but never prove nobody copied them. Prevention is the only layer with a perfect record — the secret that never commits never leaks.
- **Modern guidance** — layer all three, in order: ignore files by pattern (`.env*`, `*.pem`, `credentials.*` — committed `.gitignore`, reviewed like code), enable the forge's secret scanning plus push protection (blocks the push containing a known-shaped secret — documented per GitHub docs), add the shape-check as a pre-commit hook and a CI job (the verified grep above, extended per stack — `*.py`, `*.js`, `*.yaml`, `Dockerfile`). Reference secrets, never embed them (`${VAR}` + manager lookup — Vault/AWS SM/age-encrypted files for repos that must carry ciphertext).

```bash
# GOOD: three layers — ignore, block, scan — verified shape-check
#  .gitignore:  .env*  *.pem  credentials.*  *secret*   (reviewed, committed)
#  pre-commit + CI job (verified pattern — trips on line 1 of the planted file):
grep -rEn '(AKIA[0-9A-Z]{16}|ghp_[A-Za-z0-9]{36}|sk-[A-Za-z0-9]{20,}|-----BEGIN [A-Z ]*PRIVATE KEY-----)' --include='*.ini' --include='*.py' --include='*.js' --include='*.ts' --include='*.env' --include='*.yaml' .
# BAD: "we'll remember not to commit .env" as the whole policy —
# memory is not a control; the secret lands the week the new hire onboards at midnight
```

### 2) **Pushed secrets are compromised**

**Definition** — the incident axiom: a secret that reached any remote (pushed, however briefly) is compromised — rotate it immediately, before any cleanup. Rationale: fetches, forks, CI checkouts, webhook mirrors, and (public) stranger scrapers copy remote objects within seconds-to-minutes; no audit can enumerate every copy. Rotation (revoke the credential at the issuer, mint a replacement, update consumers) is the only action that neutralizes all copies at once — history surgery (next section) cleans the record, never the exposure.

- **Why it matters (correctness)**: teams that clean first and rotate second (or never) leave live credentials in every copy made during the window — the cleaned history looks safe while the leaked key still authenticates. Attackers automate exactly this gap (scanning public pushes in real time; private mirrors exfiltrated later). Order is the whole incident: minute-zero rotation bounds the blast radius to the window; cleanup afterward restores hygiene. Any playbook that lists removal before rotation is wrong in its first line.
- **Modern guidance** — the minute-zero sequence: revoke at the issuer (AWS/GCP/GitHub/token vendor — kill the credential, not the commit), mint the replacement, update consumers (env managers, deploy systems — never the repo), confirm old credential dead (auth attempt fails), *then* clean history (next section) and retro the prevention gap (which layer failed? ignore? hook? review?). Time-box rotation to minutes — pre-write the runbook with issuer links and owners so midnight-you executes instead of researching.

```bash
# GOOD: incident order — rotate first (minutes), clean second (hours), prevent third (forever)
#  1. revoke AKIA... at the issuer → confirm dead → mint replacement → update consumers
#  2. history surgery (next section) + force-push coordination + notify cloners
#  3. retro: which prevention layer failed? (.gitignore? hook? review?) → fix that layer
# BAD: filter-repo first, rotation "later" —
# cleaned history, live credential, every copy made during the window still authenticating
```

### 3) **Surgery is a last resort**

**Definition** — `git filter-repo` (the supported history-rewriting tool — `filter-branch` is deprecated upstream) removes the secret from *every* commit, then every downstream copy must be replaced: force-push all rewritten lines, invalidate all clones (teammates re-clone — Domain 04 §2.1's re-clone warning inverted: here re-cloning is prescribed), rotate anyway (previous section — surgery never substitutes rotation), notify per policy. The operation is an incident with a comms plan, not a command — coordinate like one.

- **Why it hurts when missing (correctness, maintainability)**: casual surgery on shared history orphans every downstream copy (Domain 05's replacement semantics at maximum blast radius — every hash changes, every clone diverges, every PR retargets). Teams that "just filter-repo quickly" discover the coordination cost mid-operation: CI pinned to old hashes fails, teammates' pushes refuse, release tags point at abandoned objects. And the worst outcome: surgery performed *instead of* rotation, leaving the live credential working under a now-clean history — the appearance of safety with none of it.
- **Modern guidance** — reserve surgery for secrets and legal takedowns (the only cases where history itself is the hazard — ordinary mistakes get `revert`, Domain 05). Procedure: announce freeze (nobody fetch/push — Domain 05 §5.1's incident discipline), back up the pre-surgery tip (bookmark branch — Domain 05 §4.1), run `filter-repo` on a fresh clone (documented per tool docs — path/secret filters), verify the bytes are gone (`grep` the rewritten history + `rev-list` audit), force-push with team-wide coordination, have everyone re-clone, rotate credentials regardless, retro. If any step sounds disproportionate, that's the point — disproportion is what makes surgery rare.

```bash
# GOOD: surgery as coordinated incident (documented per filter-repo manual — shapes, not keystrokes)
#  freeze (announce) → backup tip → filter-repo fresh clone → verify bytes gone →
#  force-push coordinated → all re-clone → rotate anyway → retro prevention
# BAD: quiet filter-repo + force-push on a Friday afternoon —
# diverged teammates, failing CI, abandoned tags — and possibly still-live credentials
```

### 4) **Common confusion**

- "Removing the commit un-leaks the secret" — removal cleans *your* history; copies (fetches, forks, CI, scrapers) keep the bytes. Rotation neutralizes copies; removal restores hygiene. Both, in that order — neither alone suffices.
- "Private repos are safe to commit secrets to" — private means *access-controlled*, not *un copied*: every teammate clone, CI checkout, and future access grant widens the circle. Private delays exposure; it doesn't prevent it.
- "Encrypted secrets in-repo are the same risk" — age/SOPS-encrypted blobs are ciphertext (safe to commit *if* keys live elsewhere); plaintext is the hazard. Know which your file holds before relaxing.
- "Scanning finds all secret shapes" — scanners match known patterns (the verified grep covers four families); novel formats and split secrets evade them. Scanning is a net, not a proof — `.gitignore` plus manager references remain the primary control.

### 5) **Performance note**

Prevention costs seconds per commit (hook) plus one scan job per push (seconds, cacheable); rotation costs minutes per incident (runbooked); surgery costs hours-to-days per incident (coordination across every clone). The ratio is why the ordering is load-bearing: pennies of prevention, minutes of rotation, days of surgery. Teams that fund only surgery pay the maximum price at the maximum frequency.

### 6) **Mentor note**

Run the plant-and-trip drill in scratch: plant the verified `AKIA…` fixture, watch the shape-check fire, then walk the minute-zero sequence verbally (revoke → replace → verify-dead → clean → retro) without touching production. Quiz the order until rotation-first is reflex — then quiz the boundary ("CTO says just delete the commit quietly?" — the answer is rotation anyway plus honest notification; silence is how breaches become career events). Watch for the surgery-first responder (rewrites history before rotating — fix with the axiom: *pushed means compromised*) and the private-repo relaxer ("it's internal" — fix with the clone-count question: "how many copies exist, and who holds them?"). Review check: `.gitignore` covers secret patterns, push protection on, shape-check in hook + CI, runbook with issuer links current, juniors can recite rotate-clean-prevent in order.
