## 6.1. Boundaries: what is covered elsewhere

### 1) **Mental models**

Snapshots, the DAG, the three areas, first-commit mechanics — [Domain 01](<../../../01 Git Fundamentals and Mental Model/README.md>) owns the theory behind everything this domain practices. This domain linked back to it for every *why* and taught only the *how*; if a passage here starts explaining what the index *is* instead of how to *use* it fast, that passage belongs in Domain 01 — flag it in review.

- **Boundary rule**: Domain 01 answers "what is happening?" — Domain 02 answers "how do I do it fast every day?" Theory questions get a link backward, never a re-explanation forward.

### 2) **Branching, remotes, history rewrite, workflows, mastery**

The rest of the track, in order — each owns its mechanics fully, and this leaf stays a signpost:

1. **[Domain 03 — Branching, Merging, and Conflicts](<../../../03 Branching Merging and Conflicts/README.md>)**: branches as daily tools (not just labels), fast-forward vs true merges, conflict markers, `rerere`.
2. **[Domain 04 — Remotes, GitHub, and Pull Requests](<../../../04 Remotes GitHub and Pull Requests/README.md>)**: `fetch`/`pull`/`push`, tracking branches, forks, PR flow — where `pull.ff=only` meets its decision.
3. **[Domain 05 — Undo, Fix, and Rewrite History](<../../../05 Undo Fix and Rewrite History/README.md>)**: `restore`, `reset`, `revert`, `rebase`, `cherry-pick`, `reflog`, amending messages — and the golden rule of shared history.
4. **Domain 06 — Workflows, Tags, Stash, and Releases**: trunk-based vs GitFlow, tagging, stashing, `bisect` at scale, release automation consuming Conventional Commits.
5. **Domain 07 — Production Checklist, Security, and Collaboration Mastery**: signing commits, secret response, protected branches, review etiquette, mentor-grade workflows.

### 3) **Release automation from message conventions**

Conventional Commits as a *writing* contract lives here ([1.2](<../1. Composing commits/1.2. Commit messages reviewers thank you for.md>)); the *machinery* that consumes it — semantic-release, changelog generation, version-bump pipelines, commitlint enforcement in CI — belongs to Domain 06. This domain teaches hands to write parseable messages; Domain 06 teaches pipelines to parse them.

- **Boundary rule**: if the sentence is about what a human types, it lives here. If it is about what a pipeline derives, it lives in Domain 06. The contract is the handshake between the two — defined once, referenced from both sides.

### 4) **Common confusion**

- "I finished Domain 02, so my workflow is complete" — solo fluency is complete; team workflows (branches, remotes, PRs) and rescue (undo, rewrite) are separate skills in Domains 03–05. This domain made you fast alone; the track makes you safe together.
- "This boundary list will go stale" — it is maintained: each Domain 03–07 session upgrades the corresponding line here from "(planned, see LOG)" to a live link, continuing the placeholder-retirement discipline from Session 1.
- "Overlaps mean duplication" — no: every cross-boundary mention is one line plus a link (DRY single-source-of-truth). Full treatment lives in exactly one place.

### 5) **Mentor note**

Teach boundaries as a map, consistent with Domain 01's version: "you were here (model), now you are fast alone (workflow), next is branching (03), then the network (04), then rescue (05)." Learners who can place any Git question into exactly one domain bucket have internalized the track's architecture — and they stop demanding PR answers from workflow material. Review check: ask "where would you learn about force-pushing safely?" — the correct answer names Domain 05, not a page.
