## 3.2. Aliases and config that compress the daily loop

### 1) **Alias the graph and the sandwich**

**Definition** — `git config alias.<name> '<expansion>'` binds short names to full commands: `git st` for `status --short --branch`, `git lg` for the graph one-liner, `git unstage` for `restore --staged`. Aliases accept shell passthrough (`!`) for anything composite. The commands you type fifty times a day deserve two letters.

- **What problem it solves**: friction compounds — a 40-character graph command typed from memory (or worse, not typed at all) means the graph goes unread, the sandwich gets skipped, and Domain 01's disciplines decay under typing cost. Two-letter aliases turn "I should check the graph" into a reflex cheaper than the doubt.
- **Modern guidance** — standardize three aliases per repo-or-team minimum: `st` (status short + branch), `lg` (`log --graph --oneline --all -20`), `unstage` (`restore --staged`). Keep expansions read-only safe (no alias should destroy work — never alias anything to `reset --hard` or `push --force`; those stay long and deliberate). Document team aliases in `CONTRIBUTING.md` so pairing and onboarding share one vocabulary.

```bash
# GOOD: the daily loop in two-letter reflexes — set once, used fifty times a day
git config --global alias.st "status --short --branch"
git config --global alias.lg "log --graph --oneline --all -20"
git config --global alias.unstage "restore --staged"
git st && git lg   # orient in under a second — the sandwich and the shape
# BAD: aliasing destruction short — git plz-push --force is a footgun with a hair trigger
```

### 2) **Sane defaults, set once**

**Definition** — a handful of config values prevent entire bug classes: `init.defaultBranch main` (every new repo starts on the right branch), `pull.ff-only`/`pull --ff-only` discipline (never create surprise merge commits on pull — Domain 04 owns the full pull story), `rerere.enabled true` (reuse recorded conflict resolutions — Domain 03's payoff), `core.editor` + `commit.verbose` (write messages in your editor with the diff shown below).

- **Why it matters (correctness)**: defaults are the behavior you get when you are tired, rushed, or new — which is exactly when protection matters. `pull` creating an unplanned merge commit, `init` landing on a legacy branch name, an editor you cannot quit blocking a commit: each is a config line that eliminates a recurring support question.
- **Modern guidance** — set machine-level once (`--global`): identity fallback, default branch, editor, `rerere`, color/diff niceties (`diff.colorMoved` for readable moved-line diffs). Set repo-level deliberately (`CONTRIBUTING.md` documents which): anything the *project* needs uniform. Verify with `git config --list --show-origin` when behavior surprises you — the answer is always one scope away.

```bash
# GOOD: protection by default — set once per machine
git config --global init.defaultBranch main
git config --global pull.ff "only"          # fast-forward on pull, or refuse (never a surprise merge)
git config --global rerere.enabled true
git config --global commit.verbose true
git config --list --show-origin | grep -E "pull|rerere|defaultBranch"  # prove it stuck
# BAD: git config --global pull.ff only (unquoted space splits the key — quote the value)

### 3) **Dotfiles belong in version control**

**Definition** — your `~/.gitconfig`, aliases, ignore excludes, and commit-message template are engineering artifacts: store them in a dotfiles repo (or the team's shared config), review changes, and bootstrap new machines from them. Configuration that lives only on one laptop is a single disk failure from extinction — the same lesson as distributed history, applied to your tools.

- **What problem it solves**: new-machine setup decay — every fresh laptop starts with stock Git, stock (dangerous) defaults, and zero aliases, and the engineer "will configure it later" for months. Meanwhile pairing breaks ("what is `git lg`? command not found on your machine") and team disciplines diverge per workstation.
- **Modern guidance** — keep a minimal portable core: the three aliases, default branch, `rerere`, editor, global ignores for your OS/editor. Symlink or `include.path` them from the dotfiles repo. Separate machine-only secrets (signing keys, tokens — Domain 07 owns signing) from shareable config, and never commit the former. Review teammates' alias additions like code: the good ones graduate into the team recommendation.

```bash
# GOOD: config as code — shared, reviewed, bootstrapped
git config --global include.path "~/dotfiles/gitconfig-shared"  # team core, versioned
git config --global commit.template "~/dotfiles/gitmessage.txt" # message scaffold for every commit
# BAD: snowflake workstation — perfect setup, zero replicas, dies with the SSD
```

### 4) **Common confusion**

- "Aliases work everywhere automatically" — aliases live in *your* config, not the repo. Scripts, CI, hooks, and teammates' machines do not have them — write automation with full commands always, aliases for interactive use only.
- "`--global` vs `--system` vs repo-local" — precedence is repo > global > system, and `--list --show-origin` settles every dispute. Team-required behavior belongs documented (and enforced in CI), not assumed from anyone's global file.
- "`pull.ff=only` breaks legitimate merges" — it refuses exactly one case: pulls that would create a merge commit because the remote moved. That refusal *is* the feature — it forces you to look (fetch, graph, then decide) instead of recording a merge you never reviewed. Domain 04 covers the decision that follows.
- "More aliases means more speed" — beyond ~ten, recall costs exceed typing savings. Alias the daily five; leave the monthly commands long and discoverable via history search.

### 5) **Mentor note**

Pair on aliases the way you pair on code: watch a junior's fingers for a day and alias what they mistype or avoid. The highest-value coaching is subtracting keystrokes from disciplines (status, graph, staged-diff review) — every saved keystroke is a skipped excuse. Enforce the inverse rule in review: any alias that destroys or publishes (`reset --hard`, `push -f`, `clean -fd`) gets deleted on sight, no matter how senior the author. Speed toward safety, never away from it.
