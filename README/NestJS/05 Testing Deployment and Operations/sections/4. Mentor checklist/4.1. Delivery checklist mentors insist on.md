# 4.1. Delivery checklist mentors insist on

## 1. Every route tests headless (inject driving — servers skipping — contracts asserting)

**Definition** — the headless habit: inject driving requests, servers skipping binds, contracts asserting shapes — checked per route before merge (inject driving (adapters flowing — handlers executing (guards gating — pipes validating (full owning — partials declining (realism serving — confidence funding); servers skipping (sockets unopened — networks untouching (speed funding — flakes declining (quiet owning — determinism proving (control serving — isolation earning); contracts asserting (statuses checking — bodies shaping (codes branching — handling easing (explicit owning — guessing declining (verification proving — regressions catching). Routes headlining (inject driving — servers skipping (contracts asserting — routes reviewing).

**What problem it solves** — the untested trio: *routes hoping* (handlers assuming — contracts unproven (driving missing — verification failing (asserting absenting — catching failing (proving lacking — confidence doubting (full failing — partials hoping (flowing missing — mastery absenting); *servers binding* (ports opening — suites serializing (skipping absenting — speed dying (unopened failing — parallels blocking (quiet lacking — determinism failing (touching owning — flakes scheduling (unbinding missing — mastery missing); *contracts eyeballing* (logs reading — shapes unasserted (asserting missing — handling guessing (explicit failing — drift accepting (catching absenting — regressions shipping (verification failing — trust eroding (checking lacking — clients breaking). The headless habit converting hoping to driving (adapters flowing — servers silencing (contracts checking — routes holding); reviewers checking inject asserts, not run logs (headlining proving → verifiable; hoping → returned) — synthesizing [§1.1](<../../sections/1. Testing heads/1.1. Headless e2e with adapter inject.md>) and [§1.2](<../../sections/1. Testing heads/1.2. Unit vs integration balance.md>).

**Modern guidance** — the headless lines per review (review-enforced): *inject driving* (adapters flowing — full proving (realism owning — hoping declining); *servers skipping* (sockets unopened — flakes declining (quiet owning — determinism proving); *contracts asserting* (statuses checking — bodies shaping (verification owning — regressions catching).

**Common confusion** — *"headless misses real bugs (servers proving)."* Headless proving adapters (requests flowing — handlers executing (guards gating — pipes validating (full owning — partials declining (realism serving — confidence funding); servers adding sockets (ports binding — networks timing (overhead owning — flakes inviting (slowness serving — determinism failing (extra serving — value missing); conflating costing slow suites (binding demanding — proving missing). "Real" describing sockets (ports owning — overhead scheduling); headless describing adapters (requests proving — servers skipping). Drive inject (adapters owning — determinism earning); skip servers (sockets declining — speed serving).

**Performance note** — headless-review economics: driving costing boot milliseconds (adapters flowing — contracts checking (realism funding — confidence earning); binding costing sockets (ports opening — suites serializing). Drive cheaply (inject — boots); skip always (servers — suites).

**Mentor note** — teach "prove every route headless" (juniors driving per route design regression-proof suites on first hearing; unasserted routes interrogated ("inject where?" — driving demanding per route). Drive one route once (inject driving — contracts asserting tangible (hoping ending — holding staying permanently). Drive adapters; assert contracts — headless discipline in three checks, reviewed per route.
