# 4.1. NestJS checklist mentors insist on

## 1. Every controller stays thin (translating owning — deciding declining — services ruling)

**Definition** — the thin line on every controller: translation only, decisions in providers ([1.2](<../../sections/1. First app/1.2. Hello API with controllers.md>)) — translating owning (HTTP parsing — services calling (queries absenting — layers separating (requests flowing — logic declining (translation proving — layers respecting); deciding declining (rules refusing — outcomes unreturning (logic absenting — reuse preserving (handlers thinning — clarity earning (separation proving — drift ending); services ruling (use cases centralizing — transactions orchestrating (logic owning — reuse enabling (decisions owning — testing easing). Controllers thinning (translating owning — deciding declining (services ruling — layers separating).

**What problem it solves** — the fat-controller trio: *logic embedding* (handlers deciding — queries running (layers collapsing — reuse dying (testing aching — drift growing (separation missing — clarity eroding); *rules scattering* (decisions spreading — policies duplicating (ownership splitting — maintenance doubling (consistency failing — drift scheduling (testing doubling — clarity eroding); *services bypassing* (providers existing — handlers ignoring (reuse absenting — duplication growing (wiring wasting — graphs hollowing (structure feigning — chaos hiding). Thin controllers converting fat to translation (translating owning — deciding declining (services ruling — concerns separating); reviewers checking service calls, not handler brains (thinning proving → verifiable; fattening → returned).

**Modern guidance** — the thin lines per controller (review-enforced): *translating owning* (HTTP parsing — services calling (queries absenting — layers separating (requests flowing — logic declining (translation proving — layers respecting (surfaces bounding — breakage preventing); *deciding declining* (rules refusing — outcomes unreturning (logic absenting — reuse preserving (handlers thinning — clarity earning (separation proving — drift ending (restraint owning — mastery showing); *services ruling* (use cases centralizing — transactions orchestrating (logic owning — reuse enabling (decisions owning — testing easing (ownership proving — duplication ending).

```typescript
// GOOD: controllers thinning — translating owning, deciding declining, services ruling (shapes, gated).
// @Get(':id') getOne(@Param('id') id: string) { return this.cats.find(id); } (HTTP parsing — services calling — queries absenting, layers separating)
// No queries, no rules, no try/catch per handler (logic absenting — reuse preserving — handlers thinning, clarity earning)
// Decisions in providers (use cases centralizing — transactions orchestrating — logic owning, reuse enabling)
// BAD: controllers fattening — logic embedding, rules scattering, services bypassing (real big-ball shape).
// SQL + rules inline (layers collapsing — reuse dying — testing aching (drift growing — clarity eroding).
// Providers existing but unused (reuse absenting — duplication growing — wiring wasting). Translate; call services.)
```

**Common confusion** — *"thin means anemic (controllers doing nothing)."* Anemic fearing emptiness (handlers passing — logic elsewhere (delegation owning — translation serving (thinness proving — clarity earning); fat stuffing responsibilities (handlers deciding — queries running (layers collapsing — reuse dying (translation absenting — clarity eroding); conflating costing translation-shame (thin apologizing — logic smuggling (handlers fattening — layers collapsing). "Nothing" describing delegation (services ruling — translation serving); anemic describing missing logic-everywhere (decisions absenting — behavior missing). Translate thinly (services calling — layers separating); decide centrally (providers ruling — logic owning).

**Performance note** — thin economics: owning costing delegation lines (HTTP parsing — services calling (queries absenting — layers separating); declining saving duplication (logic absenting — reuse preserving (handlers thinning — clarity earning); fat equivalents costing drift (testing aching — clarity eroding). Delegate cheaply (calls — services); decline always (decisions — handlers).

**Mentor note** — teach "no logic past the service call" (juniors thinning per controller design translatable HTTP on first hearing; deciding handlers interrogated ("rule or route?" — thinning demanding per handler). Thin one controller once (translating owning — deciding declining tangible (clarity earning — fatness ending permanently). Translate HTTP; rule services — thin discipline in three habits, reviewed per controller.

## 2. Every provider injects (constructors receiving — globals absenting — tests faking)

**Definition** — the injection line on every provider: deps received, never imported ([2.1](<../../sections/2. Core pipeline/2.1. Providers injecting (constructors receiving — globals absenting (tests faking — order proving).

**What problem it solves** — the uninjecting trio: *news scattering* (constructors calling — graphs hand-building (order hoping — singletons duplicating (state forking — tests aching (container absenting — substitution missing); *globals sharing* (singletons importing — state bleeding (coupling rising — reasoning taxing (hygiene failing — discipline missing (clarity eroding — testing aching); *tests binding* (reals requiring — databases needing (setup heavying — suites crawling (isolation missing — determinism hoping (speed dying — feedback delaying). Injected providers converting manual to resolved (constructors receiving — globals absenting (tests faking — substitution proving); reviewers checking constructor params, not import constellations (injecting proving → verifiable; newsing → returned).

**Modern guidance** — the injection lines per provider (review-enforced): *constructors receiving* (params declaring — containers resolving (graphs walking — instances building (visibility owning — honesty serving (wiring proving — manual declining (automation owning — error declining); *globals absenting* (imports dropping — singletons unsharing (coupling declining — reasoning easing (hygiene owning — discipline proving (clarity keeping — testing enabling (decoupling owning — understanding aiding); *tests faking* (doubles injecting — overrides owning (units isolating — speed funding (substitution proving — determinism keeping (confidence earning — feedback tightening (tests owning — reality mocking).

// constructor(private readonly clock: Clock) {} (params declaring — containers resolving — graphs walking, instances building)
// No imported singletons (imports dropping — singletons unsharing — coupling declining, reasoning easing)
// Test.overrideProvider(Clock).useValue(fake) (doubles injecting — units isolating — speed funding, substitution proving)

**Common confusion** — *"injection hides wiring (graphs obscuring)."* Wiring declaring visibly (constructors listing — modules registering (graphs walking — instances building (visibility owning — honesty serving (structure proving — chaos declining); hiding describing globals (imports scattering — usage untracing (coupling hiding — reasoning taxing (obscurity owning — understanding declining); fearing costing manual graphs (order hoping — singletons duplicating (error inviting — testing aching). "Hiding" describing undeclared deps (usage untracing — coupling hiding); injection describing declarations (constructors listing — params reading). Declare visibly (constructors listing — graphs walking); resolve centrally (containers owning — order proving).

**Performance note** — injection-checklist economics: receiving costing param lines (params declaring — containers resolving (graphs walking — instances building); absenting saving coupling (imports dropping — singletons unsharing (coupling declining — reasoning easing); newsed equivalents costing singletons (state forking — tests aching). Receive cheaply (params — constructors); fake always (tests — doubles).

**Mentor note** — teach "receive everything, import nothing stateful" (juniors injecting per provider design testable services on first hearing; newsing interrogated ("who builds it?" — receiving demanding per instantiation). Inject one provider once (constructors receiving — globals absenting tangible (order proving — manual ending permanently). Receive constructors; fake tests — injection discipline in three habits, reviewed per provider.

## 3. Every input validates (pipes proving — handlers assuming — bad never entering)

**Definition** — the validation line on every input: proven at entry, assumed inside ([3.1](<../../sections/3. First safety/3.1. **What problem it solves** — the unvalidated trio: *bad entering* (inputs trusting — types assuming (handlers crashing — logic corrupting (proof missing — robustness hoping (validation absenting — integrity risking); *handlers guarding* (checks scattering — logic cluttering (validation duplicating — clarity eroding (ownership splitting — testing doubling (discipline dividing — consistency failing); *corruption spreading* (bad processing — state poisoning (errors cascading — recovery aching (rejection delaying — damage growing (economics inverting — attackers thanking). Validated inputs converting entering to refusing (pipes proving — handlers assuming (bad declining — integrity keeping); reviewers checking pipe coverage, not handler guards (validating proving → verifiable; trusting → returned).

**Modern guidance** — the validation lines per input (review-enforced): *pipes proving* (schemas checking — types converting (bad rejecting — handlers unreaching (validation owning — robustness earning (proof owning — hope ending (entry owning — corruption preventing); *handlers assuming* (types trusting — logic focusing (guards declining — checks skipping (clarity keeping — testing easing (assumption earning — proof preceding (trust owning — velocity funding); *bad declining* (entry refusing — corruption preventing (integrity keeping — damage avoiding (rejection owning — economics reversing (refusal owning — safety proving).

"Duplicating" describing static-dynamic confusion (compilers trusting — runtime hoping); validation describing proof (inputs checking — bad rejecting). Type statically (annotations declaring — misuse catching); prove runtime (pipes checking — bad rejecting).

**Performance note** — validation-checklist economics: proving costing pipe lines (schemas checking — types converting (bad rejecting — handlers unreaching); assuming saving guards (types trusting — logic focusing (guards declining — checks skipping); trusted equivalents costing corruption (handlers crashing — logic corrupting). Validate one input once (pipes proving — handlers assuming tangible (robustness earning — corruption ending permanently).
