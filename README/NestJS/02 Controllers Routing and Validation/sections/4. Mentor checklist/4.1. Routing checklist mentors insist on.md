## 1. Every route declares shape (verbs mapping — params contracting — responses stating)

**Definition** — the shape habit: verbs mapping semantics, params contracting types, responses stating codes — checked per route before merge (verbs mapping (GET reading — POST creating (semantics owning — clients predicting (contracts proving — surprises ending (meaning owning — guessing declining); params contracting (segments extracting — queries shaping (pipes proving — handlers assuming (types owning — garbage declining (trust earning — branches ending); responses stating (codes declaring — shapes structuring (clients branching — handling easing (explicit owning — defaulting declining (contracts holding — trust funding). Shapes declaring (verbs mapping — params contracting (responses stating — routes reviewing).

**What problem it solves** — the unshaped trio: *verbs defaulting* (POST returning 200 — creations hiding (semantics blurring — clients guessing (mapping missing — meaning hoping (reviewing absenting — discipline doubting); *params leaking* (strings staying strings — queries unshaped (contracts hoping — handlers branching (proving missing — trusting bluffing (hygiene failing — incidents inviting); *responses varying* (envelopes mixing — codes hiding (clients branching — handling aching (uniformity failing — trust eroding (stating missing — standards hoping). The shape habit converting defaulting to mapping (verbs declaring — params proving (responses stating — routes holding); reviewers checking three lines per route, not handler hopes (declaring proving → verifiable; defaulting → returned) — synthesizing [§1.1](<../../sections/1. Routing deep/1.1. Route shapes and parameter contracts.md>) and [§1.2](<../../sections/1. Routing deep/1.2. Versioning prefixes and composition.md>).

**Modern guidance** — the shape lines per review (review-enforced): *verbs mapping* (methods declaring — codes stating (semantics proving — clients trusting (contracts owning — surprises ending); *params contracting* (decorators extracting — pipes proving (types holding — handlers assuming (trust earning — branches ending); *responses stating* (codes declaring — shapes returning (handling easing — guessing ending).

// @Param/@Query with pipes, DTO per body (params contracting — handlers assuming). Synthesizes 1.1 + 1.2.)

**Common confusion** — *"checklists slow reviews (process taxing)."* Checklists speeding reviews (shapes stating — gates composing (inputs proving — decisions accelerating (three lines checking — hopes declining (velocity owning — tax ending (discipline serving — quality funding); slowness fearing (process assuming — value missing (tax hoping — skipping scheduling (haste owning — incidents inviting). "Slowing" describing bureaucracy (value missing — tax scheduling); checklists describing acceleration (decisions proving — incidents declining). Checklist routes (reviewing owning — velocity funding); never hope shapes (guessing declining — breaking ending).

**Performance note** — shape economics: declaring costing review lines (verbs mapping — params contracting (responses stating — routes holding); varying costing incidents (clients breaking — midnights debugging). Declare cheaply (reviews — lines); shape always (routes — contracts).

**Mentor note** — teach "shape first, logic second" (juniors declaring per route design reviewable APIs on first hearing; logic-first reviews interrogated ("shapes where?" — declaring demanding per route). Shape one route once (verbs mapping — responses stating tangible (varying ending — holding staying permanently). Map verbs; contract params — shape discipline in three checks, reviewed per route.
