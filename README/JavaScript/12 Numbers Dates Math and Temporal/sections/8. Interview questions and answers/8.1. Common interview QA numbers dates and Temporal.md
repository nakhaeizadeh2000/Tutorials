## 8.1. Common interview Q&A numbers dates and Temporal

### 1) **Twelve questions with mechanism-level answers**

**Q1. Why is `NaN !== NaN` and how do you test for it?**
**A:** IEEE-754 mandates `NaN` never equal to itself; spec `IsLooselyEqual`/`StrictlyEqual` both return false. Use `Number.isNaN(x)` (coercion-free). `x !== x` works but is obscure; global `isNaN` coerces (`isNaN("foo")→true`).

```js
console.log(NaN === NaN); // false
console.log(Number.isNaN(NaN), Number.isNaN("foo")); // true false
console.log(isNaN("foo")); // true — the trap (coercion)
```

**Q2. What is `-0` and where does it matter?**
**A:** IEEE-754 signed zero; `0 === -0` true but `Object.is(0,-0)` false and `1/0 → Infinity`, `1/-0 → -Infinity`. `Map`/`Set` SameValueZero collapse them; `JSON.stringify(-0) → "0"`.

```js
console.log(0 === -0); // true
console.log(Object.is(0, -0)); // false
console.log(1 / -0); // -Infinity
console.log(JSON.stringify(-0)); // "0"
```

**Q3. `EPSILON` and how to compare computed floats?**
**A:** `Number.EPSILON ≈2.22e-16` is gap at `1`, not global smallest difference. Never `a===b` on computed floats (`0.1+0.2!==0.3`); use `Math.abs(a-b) <= max(|a|,|b|)*EPSILON` (scaled). For money, use integer cents.

```js
console.log(0.1 + 0.2 === 0.3); // false
console.log(Math.abs(0.1 + 0.2 - 0.3) < Number.EPSILON); // true
```

**Q4. `MAX_SAFE_INTEGER` — what happens beyond it?**
**A:** `2^53-1` (`9007199254740991`) is last exactly representable integer; beyond, gaps (every 2, then 4…). `9007199254740992===9007199254740993` true. Use `Number.isSafeInteger` gate; IDs > `2^53-1` as `string`/`BigInt`.

```js
console.log(Number.MAX_SAFE_INTEGER); // 9007199254740991
console.log(9007199254740992 === 9007199254740993); // true
console.log(Number.isSafeInteger(9007199254740993)); // false
```

**Q5. `Number` vs `parseInt` vs `parseFloat` — when does `""→0` bite?**
**A:** `Number`/`+` strict (entire string, `""→0`, `"42px"→NaN`), `parseInt`/`parseFloat` lenient (prefix, `"42px"→42`, `""→NaN`). Empty-string poisoning: `["10","", "20"].map(Number) → [10,0,20]`.

```js
console.log(Number("42px")); // NaN
console.log(parseInt("42px", 10)); // 42
console.log(Number("")); // 0 — trap
console.log(parseFloat("")); // NaN
```

**Q6. Why `parseInt` without radix is flagged?**
**A:** Historically `parseInt("08")` → `0` (octal guess); today defaults to 10 but `parseInt("0x10")→16` (hex guess) and `["10","10","10"].map(parseInt) → [10,NaN,2]` (index as radix). Always `parseInt(s,10)`.

```js
console.log(["10", "10", "10"].map(parseInt)); // [10, NaN, 2]
console.log(["10", "10", "10"].map(s => parseInt(s, 10))); // [10, 10, 10]
```

**Q7. `toFixed`/`toPrecision` vs `Intl.NumberFormat` — which for locale/money?**
**A:** `toFixed`/`toPrecision` are locale-agnostic, round binary double (`(1.005).toFixed(2)→"1.00"`). `Intl.NumberFormat` is locale-aware (`de-DE` `"1.234,50"`), supports `currency`, `roundingMode`. Never manual grouping.

```js
console.log((1.005).toFixed(2)); // "1.00" — binary trap
console.log(new Intl.NumberFormat("de-DE", { minimumFractionDigits: 2 }).format(1234.5)); // "1.234,50"
```

**Q8. `Math.round(-0.5)` and `Math.pow(Infinity,0)`?**
**A:** `round` ties toward `+Infinity`: `round(-0.5) → -0`, `round(-1.5)→-1`. `pow(any,0)→1` per spec, even `Math.pow(Infinity,0)`. `Math.max()` no args → `-Infinity`.

```js
console.log(Object.is(Math.round(-0.5), -0)); // true
console.log(Math.pow(Infinity, 0)); // 1
console.log(Math.max()); // -Infinity
```

**Q9. `Math.random` vs `crypto.getRandomValues` — when to use which?**
**A:** `Math.random()` uniform `[0,1)` ~52-bit, predictable, not seedable — ok for jitter/sampling. `crypto.getRandomValues` CSPRNG, `node:crypto.randomInt` unbiased — required for tokens/shuffles. `sort(()=>Math.random()-0.5)` biased + weak.

```js
console.log(Math.random() >= 0 && Math.random() < 1); // true
const a = new Uint8Array(4); crypto.getRandomValues(a); console.log(a.length); // 4 CSPRNG
```

**Q10. `Date` month indexing and mutability?**
**A:** `Date` month `0–11`, mutable (`setMonth` mutates), stores UTC ms. `new Date(2026,0,15)` is local midnight, `new Date("2026-01-15")` is UTC midnight — different instants. `set*` returns `number` timestamp.

```js
console.log(new Date(2026, 0, 15).getMonth()); // 0
const d = new Date(2026, 0, 15); const t = d.setDate(20); console.log(typeof t); // "number"
```

**Q11. UTC vs local and DST — why `24*60*60*1000` is not "next day"?**
**A:** `Date` stores UTC but `getHours` is host local; DST gap (23h) and repeat (25h) make `24h` duration ≠ calendar day. `setDate(getDate()+1)` is host-local calendar +1, wrong for arbitrary zones. Use `Temporal.ZonedDateTime.add({days:1})` (23/25h real).

```js
const utc = new Date("2026-03-08T06:30:00.000Z");
console.log(new Date(utc.getTime() + 24 * 60 * 60 * 1000).toISOString()); // 24h later UTC
// Calendar day in NY on gap is 23h — needs Temporal (see 5.2)
```

**Q12. `Temporal` vs `Date` — what type for what?**
**A:** `Instant` (UTC ns, exact), `PlainDate`/`PlainTime`/`PlainDateTime` (wall-clock, no zone), `ZonedDateTime` (wall+zone+calendar, DST-correct). `PlainDate` for birthdays, `ZonedDateTime` for zoned arithmetic, `Instant` for storage. Feature-detect `typeof Temporal === "undefined"` on Node 22; polyfill via `@js-temporal/polyfill`.

```js
console.log(typeof Temporal); // "undefined" on Node 22 — guard
if (typeof Temporal !== "undefined") console.log(String(Temporal.PlainDate.from("2026-03-08")));
else console.log("use ISO string '2026-03-08' as wall date until polyfill");
```

### 2) **What interviewers actually probe for**

- Tracing `NaN`/`-0`/`isNaN` vs `Number.isNaN` and `Object.is` (do you reach for the coercion-free check?).
- Explaining `EPSILON` scaling and `MAX_SAFE_INTEGER` collapse narratively (not reciting constants).
- Contrasting strict `Number` vs lenient `parseInt` and the empty-string `0` trap.
- Distinguishing duration (`+24h`) vs calendar day (`+1 day` DST) and `Date` host-only vs `ZonedDateTime` zone-aware.

### 3) **Grading guidance**

| Signal | Junior | Mid | Senior |
|--------|--------|-----|--------|
| `NaN` | "check with `isNaN`" | "`Number.isNaN` after `Number()`" | "`NaN` is IEEE-754, `Object.is(NaN,NaN)` true, poison" |
| `EPSILON` | "use `EPSILON`" | "scaled `max*EPSILON`" | "money via cents/`BigInt`/`Decimal`, not epsilon" |
| `parseInt` | "converts to int" | "needs radix" | "map trap, `0x` guess, empty-string divergence" |
| `Date` | "`Date` handles zones" | "host vs UTC" | "DST gap/repeat, `24h`≠day, `Temporal` migration" |
| `Temporal` | "heard of it" | "wall vs instant" | "`ZonedDateTime` DST-correct, `Duration` calendar, `relativeTo`" |

**Red flags** — "`parseInt` correctly guesses radix", "`toFixed` is exact for decimals", "`Math.random` for tokens is fine", "`Date` handles DST", "`24h` is a day", "`Temporal` is in Node 22 by default".
