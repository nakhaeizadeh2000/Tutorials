## 5.1. Temporal overview Instant PlainDate PlainTime PlainDateTime

### 1) **`Temporal.Instant` — exact UTC time as nanoseconds since epoch (immutable, no timezone)**

**Definition** — `Temporal.Instant` is an immutable exact point on the UTC timeline, stored as *nanoseconds* since epoch (`epochNanoseconds` : `BigInt`, `epochMilliseconds` : `number`). Unlike `Date` (milliseconds, mutable), `Instant` is nanosecond-precision, immutable (methods return new instances), and has no timezone/calendar — it is the UTC anchor that other `Temporal` types convert through.

**What problem it solves / history** — `Date` conflates UTC ms with host-local accessors and mutability (see [4.1](<../4. Legacy Date/4.1. Legacy Date creation mutability and parsing pitfalls.md>)), and has millisecond ceiling. `Temporal` (Stage 3 as of ES2026 era, shipping behind flag/polyfill on Node 22 — `typeof Temporal === "undefined"` on v22.23.2) fixes all three: nanosecond precision, explicit types, immutable.

```js
// Feature detection — Temporal not yet on Node 22 without flag/polyfill
console.log(typeof Temporal); // "undefined" on Node 22.23.2 / v20 — guarded below
// On Node 24+ or with --harmony-temporal or @js-temporal/polyfill, this is "object"
if (typeof Temporal !== "undefined") {
  const now = Temporal.Now.instant(); // current instant (CSPRNG? no, clock)
  console.log(String(now)); // e.g., "2026-08-26T12:00:00.123456789Z"
  console.log(typeof now.epochNanoseconds, typeof now.epochMilliseconds); // "bigint" "number"
  console.log(now.epochMilliseconds === Math.floor(Number(now.epochNanoseconds / 1000000n))); // true
  // Immutable — add returns new Instant, original untouched
  const later = now.add({ nanoseconds: 1_000_000_000 }); // +1s
  console.log(later.epochNanoseconds - now.epochNanoseconds === 1_000_000_000n); // true
  console.log(now.epochNanoseconds === now.epochNanoseconds); // true — unchanged
} else {
  // Fallback on Node 22 — Date millisecond anchor (lossy vs nanoseconds) + polyfill note
  console.log("Temporal not available — use Date.now() ms fallback or @js-temporal/polyfill");
  const ms = Date.now();
  console.log(typeof ms, ms > 0); // "number" true
  console.log(new Date(ms).toISOString()); // UTC ISO — millisecond precision only
  // Polyfill path (install): npm i @js-temporal/polyfill  →  import { Temporal } from "@js-temporal/polyfill"
}

// Date vs Instant mapping table (when Temporal is available)
function dateToInstant(date) {
  // Date stores ms UTC → Instant stores ns UTC (ms * 1_000_000)
  if (typeof Temporal !== "undefined") return Temporal.Instant.fromEpochMilliseconds(date.getTime());
  return date; // fallback
}
console.log(dateToInstant(new Date("2026-01-15T12:00:00.000Z")) instanceof Date || typeof Temporal !== "undefined"); // true
// When Temporal lands: Temporal.Instant.fromEpochMilliseconds(Date.now()).toString() → UTC ISO with ns
```

### 2) **`PlainDate`/`PlainTime`/`PlainDateTime` — wall-clock without timezone or offset**

**Definition** — `PlainDate` (`2026-03-08`), `PlainTime` (`12:34:56.789`), `PlainDateTime` (`2026-03-08T12:34:56`) are *wall-clock* types: calendar date/time without timezone, offset, or instant. They are calendar-aware (know days in month, leap years), immutable, and compared/added via calendar (not 24h durations). Use them for birthdays, local opening hours, or any "wall time" not tied to an instant.

```js
if (typeof Temporal !== "undefined") {
  const date = Temporal.PlainDate.from("2026-03-08"); // YYYY-MM-DD
  console.log(String(date)); // "2026-03-08"
  console.log(date.year, date.month, date.day, date.dayOfWeek); // 2026 3 8 7 (Sunday = 7)
  console.log(date.daysInMonth, date.daysInYear, date.inLeapYear); // 31 365 false
  // Immutable add — calendar-aware (adds 1 calendar day, not 24h)
  const tomorrow = date.add({ days: 1 });
  console.log(String(tomorrow)); // "2026-03-09"
  console.log(String(date)); // "2026-03-08" — original unchanged

  const time = Temporal.PlainTime.from("12:34:56.789456789");
  console.log(String(time), time.hour, time.minute, time.second, time.millisecond); // "12:34:56.789456789" 12 34 56 789

  const dt = Temporal.PlainDateTime.from("2026-03-08T12:34:56");
  console.log(String(dt)); // "2026-03-08T12:34:56"
  console.log(dt.toPlainDate().toString(), dt.toPlainTime().toString()); // split

  // PlainDate comparison — calendar compare, not instant
  console.log(Temporal.PlainDate.from("2026-03-08").equals(Temporal.PlainDate.from("2026-03-08"))); // true
  console.log(Temporal.PlainDate.compare("2026-03-08", "2026-03-09")); // -1
  console.log(Temporal.PlainDate.from("2026-03-08").add({ months: 1 }).toString()); // "2026-04-08" — month-aware
  console.log(Temporal.PlainDate.from("2026-01-31").add({ months: 1 }).toString()); // "2026-02-28" — overflow convention (constrain)
} else {
  // Fallback — Date cannot represent PlainDate safely (host TZ leaks); keep as string and manual calendar
  const plainDateStr = "2026-03-08";
  console.log(plainDateStr, plainDateStr.split("-").map(Number)); // [2026, 3, 8] — wall-clock as string, no Date
  // Never do: new Date("2026-03-08") → UTC midnight (see 4.1) — not a wall date
  // Use string + Temporal polyfill or date-fns/luxon for calendar add until Temporal ships
  function addDaysPlainDate(isoDate, days) { // naive UTC add — only correct for UTC calendar, not DST-aware
    const [y, m, d] = isoDate.split("-").map(Number);
    const ms = Date.UTC(y, m - 1, d);
    const later = new Date(ms + days * 24 * 60 * 60 * 1000);
    return later.toISOString().slice(0, 10);
  }
  console.log(addDaysPlainDate("2026-03-08", 1)); // "2026-03-09" — UTC calendar fallback (not zone-aware)
}

// Why not Date for wall dates — host TZ leak
console.log(new Date("2026-03-08").toISOString()); // "2026-03-08T00:00:00.000Z" — UTC, not wall
console.log(new Date(2026, 2, 8).toISOString()); // local midnight → UTC offset (see 4.2) — wall time leaks host zone
```

### 3) **Feature detection — `typeof Temporal === "undefined"` on Node 22 and the polyfill path**

**Definition** — as of ES2026 era (Node 22 LTS, 24 Active), `Temporal` is not enabled by default (`typeof Temporal === "undefined"` on v22.23.2 verified). Detect before use; polyfill via `@js-temporal/polyfill` (`npm i @js-temporal/polyfill`, `import { Temporal } from "@js-temporal/polyfill"` or `require`), or flag `--harmony-temporal` on newer Node. Always guard: `if (typeof Temporal !== "undefined") { ... } else { /* Date fallback + polyfill note */ }`.

```js
// Canonical guard — works on Node 22, 24, and browsers with/without Temporal
function hasTemporal() { return typeof Temporal !== "undefined"; }
console.log(hasTemporal()); // false on Node 22.23.2 — true on Node 24 with flag or polyfill
if (!hasTemporal()) {
  console.log("Guard: Temporal not available — keep wall dates as ISO strings, instants as Date ms, and document polyfill path");
  // Polyfill install note (not executed here — offline):
  // npm i @js-temporal/polyfill
  // import { Temporal } from "@js-temporal/polyfill"; // or require("@js-temporal/polyfill")
  // After import, globalThis.Temporal is defined — re-check hasTemporal() → true
}

// Temporal.Now — wall-time factory (when available)
if (hasTemporal()) {
  console.log(String(Temporal.Now.plainDateISO())); // e.g., "2026-08-26" — host wall date
  console.log(String(Temporal.Now.zonedDateTimeISO())); // e.g., "2026-08-26T12:00:00+03:30[Asia/Tehran]"
  console.log(String(Temporal.Now.instant())); // UTC instant
} else {
  // Fallback equivalents via Date + Intl
  console.log(new Date().toISOString().slice(0, 10)); // wall date approximated via UTC (not host wall — use Intl for host)
  console.log(new Intl.DateTimeFormat("en-CA", { timeZone: "Asia/Tehran", year: "numeric", month: "2-digit", day: "2-digit" }).format(new Date())); // host wall date via Intl
  console.log(new Date().toISOString()); // instant-like UTC
}

// Calendar integration — PlainDate carries calendar (default iso8601)
if (hasTemporal()) {
  const plain = Temporal.PlainDate.from({ year: 2026, month: 3, day: 8, calendar: "iso8601" });
  console.log(plain.calendarId); // "iso8601"
  console.log(String(plain.withCalendar("persian"))); // Persian calendar — when calendar data available
}
```

### 4) **Common confusion**

- "`Temporal.PlainDate` is a `Date` without time" — no, it is a *wall-clock* date without timezone or instant; `new Date("2026-03-08")` is an *instant* (UTC midnight), not a wall date.
- "`Temporal.Instant` stores local time" — no, it stores UTC nanoseconds; local wall time is `ZonedDateTime` (see [5.2](<./5.2. Temporal ZonedDateTime Duration calendar and migration.md>)).
- "`Temporal` is available in Node 22" — no, `typeof Temporal === "undefined"` on Node 22.23.2; guard and polyfill.
- "`PlainDate.add({days:1})` is `+24h`" — no, it is +1 calendar day (DST-aware via zone when using `ZonedDateTime`; `PlainDate` is zone-free calendar add).
- "`Date` can be replaced by string ISO date for wall dates" — yes, that is the safe fallback until `Temporal` ships (keep `"2026-03-08"` as string, do not `new Date` it).

### 5) **Performance note**

`Temporal` instances are immutable — each `add`/`with` allocates a new object (like `Date` but without mutation). In hot loops of 1e6 calendar adds, allocation dominates — batch or reuse. Polyfill `Temporal` is JS-implemented (slower than native `Date`'s C++); native `Temporal` (when shipped) is expected to be C++ intrinsified and faster than polyfill but still heavier than raw timestamp arithmetic. For hot timestamp math (sorting, diffs), stay with `number` ms or `BigInt` ns.
