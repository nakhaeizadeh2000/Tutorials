## 3.1. Math object constants trigonometry logs and rounding

### 1) **`Math` is not a constructor — constants `PI`/`E`/`LN2` and the pure-function surface**

**Definition** — `Math` is a plain namespace object (`typeof Math === "object"`, no `new Math()`), hosting constants and pure functions. Constants: `Math.PI` (≈3.14159), `Math.E` (≈2.71828), `Math.LN2`/`LN10`, `Math.LOG2E`/`LOG10E`, `Math.SQRT1_2`/`SQRT2`. Functions are stateless: inputs → output, no mutation, no `this`.

```js
console.log(typeof Math); // "object"
try { new Math(); } catch (e) { console.log(e.name); } // TypeError — not a constructor
console.log(Math.PI, Math.E, Math.LN2, Math.SQRT2); // constants
console.log(Math.pow(2, 10)); // 1024 — exponentiation (prefer ** operator today)
console.log(2 ** 10); // 1024 — ** is the modern form
console.log(Math.sqrt(9), Math.cbrt(27), Math.hypot(3, 4)); // 3 3 5 — hypot is sqrt(x²+y²+...) without overflow

// Logs and exps
console.log(Math.log(Math.E)); // 1 — natural log
console.log(Math.log2(8), Math.log10(1000)); // 3 3
console.log(Math.exp(1) === Math.E); // true
console.log(Math.expm1(1e-10)); // ~1e-10 — exp(x)-1 accurate for tiny x (avoids catastrophic cancellation)
console.log(Math.log1p(1e-10)); // ~1e-10 — log(1+x) accurate for tiny x

// Absolute, sign, bit-level
console.log(Math.abs(-5), Math.abs(-0)); // 5 0 — abs(-0) → 0
console.log(Math.sign(-0), Math.sign(0), Math.sign(5), Math.sign(-5), Math.sign(NaN)); // -0 0 1 -1 NaN
console.log(Math.clz32(1)); // 31 — count leading zeros in 32-bit
console.log(Math.clz32(0)); // 32
console.log(Math.imul(0xffffffff, 5)); // -5 — 32-bit integer multiply (wraps like C int32)
console.log(0xffffffff * 5); // 21474836475 — double multiply (no wrap)

// NaN/Infinity flow through Math
console.log(Math.sqrt(-1)); // NaN
console.log(Math.log(-1)); // NaN
console.log(Math.pow(Infinity, 0)); // 1 — spec: any **0 is 1, even Infinity
console.log(Math.max()); // -Infinity — no args → -Infinity
console.log(Math.min()); // Infinity — no args → Infinity
console.log(Math.max(NaN, 1)); // NaN — NaN poisons max/min
```

### 2) **Trigonometry in radians and the `Math` vs `Intl` split**

**Definition** — all trig functions take *radians*, not degrees. No built-in degree helpers — convert manually (`rad = deg * PI/180`). Inverse functions return radians. `Math.atan2(y,x)` gives the full-circle angle (quadrant-aware) unlike `atan(y/x)`.

```js
// Degrees ↔ radians
const degToRad = d => d * Math.PI / 180;
const radToDeg = r => r * 180 / Math.PI;
console.log(degToRad(180) === Math.PI); // true
console.log(radToDeg(Math.PI)); // 180
console.log(Math.sin(Math.PI / 2)); // 1 — not exactly 1 due to PI approximation, but 1
console.log(Math.sin(Math.PI)); // 1.2246467991473532e-16 — not 0 (binary PI is not exact pi)
console.log(Math.abs(Math.sin(Math.PI)) < 1e-15); // true — within tolerance

// atan2 — correct quadrant, handles x=0 and signed zero
console.log(Math.atan2(1, 1) * 180 / Math.PI); // 45 — first quadrant
console.log(Math.atan2(1, -1) * 180 / Math.PI); // 135 — second quadrant
console.log(Math.atan2(-1, -1) * 180 / Math.PI); // -135 — third
console.log(Math.atan2(0, -1) * 180 / Math.PI); // 180 — along negative x
console.log(Math.atan2(0, -0) * 180 / Math.PI); // 180 — distinguishes -0 (see 1.1)
console.log(Math.atan2(0, 0) * 180 / Math.PI); // 0 — origin
console.log(Math.atan(1/1) * 180 / Math.PI); // 45 — same as atan2 for first quadrant, but loses quadrant for x<0

// Hyperbolic (rare — mentioned for completeness)
console.log(Math.sinh(0), Math.cosh(0), Math.tanh(0)); // 0 1 0
```

### 3) **Rounding — `round`/`floor`/`ceil`/`trunc`/`fround` and the `0.5` tie rule**

**Definition** — `floor` → greatest integer ≤ x, `ceil` → least integer ≥ x, `trunc` → toward zero (ES2015), `round` → half-up away from zero for positive `+0.5` → up, but `round(-0.5)` → `-0` (ties to `+Infinity`), `fround` → round to nearest float32 (quantize to 32-bit, useful for TypedArray/Asm.js interop).

```js
console.log(Math.floor(1.9), Math.floor(-1.9)); // 1 -2 — floor goes toward -Infinity
console.log(Math.ceil(1.1), Math.ceil(-1.1)); // 2 -1 — ceil toward +Infinity
console.log(Math.trunc(1.9), Math.trunc(-1.9)); // 1 -1 — toward zero (ES2015)
console.log(Math.round(1.5), Math.round(2.5)); // 2 3 — half-up
console.log(Math.round(-1.5)); // -1 — not -2 (round goes toward +Infinity on tie)
console.log(Object.is(Math.round(-0.5), -0)); // true — the special case
console.log(Math.round(1.005 * 100) / 100); // 1 — not 1.01 — same binary 1.005 trap as toFixed (see 2.2)
console.log(Math.fround(1.5)); // 1.5 — exactly representable in float32
console.log(Math.fround(1.337)); // 1.3370000123977661 — quantized to float32
console.log(new Float32Array([1.337])[0]); // 1.3370000123977661 — same as fround

// Practical rounding to N decimals — avoid round(N*100)/100 for money if N is decimal
function roundTo(n, decimals) {
  const p = 10 ** decimals;
  // Use EPSILON trick for binary tie — or better, use Intl or integer cents for money
  return Math.round((n + Number.EPSILON) * p) / p;
}
console.log(roundTo(1.005, 2)); // 1.01 — EPSILON nudges the binary tie upward
console.log((1.005).toFixed(2)); // "1.00" — toFixed does NOT nudge (direct rounding of stored value)

// Clamping via min/max — the idiomatic pattern
function clamp(v, lo, hi) { return Math.min(hi, Math.max(lo, v)); }
console.log(clamp(15, 0, 10)); // 10
console.log(clamp(-5, 0, 10)); // 0
console.log(clamp(NaN, 0, 10)); // NaN — max/min poison with NaN, so guard NaN before clamp
```

### 4) **Common confusion**

- "`Math` can be constructed" — no, `new Math()` throws `TypeError`; it is a namespace.
- "`Math.round` rounds half to even" — no, it rounds half toward `+Infinity` (`-1.5 → -1`, `1.5 → 2`); "banker's rounding" is not `Math.round` (use `Intl` or manual).
- "`Math.sin(π)` is `0`" — it is `1.22e-16` because `Math.PI` is not exact π (double approximation).
- "`Math.max()` with no args is `0`" — it is `-Infinity` (and `min()` is `Infinity`) — the identity elements for the comparison.
- "`Math.trunc` is same as `floor` for negatives" — no, `floor(-1.9) → -2` but `trunc(-1.9) → -1`.

### 5) **Performance note**

`Math` functions are JIT-intrinsified to single CPU instructions (`sqrt` → `sqrtsd`, trig → libm, `fround` → `cvtss2sd`). Calling `Math` in a tight loop is not a bottleneck; allocating the argument array for `Math.max(...arr)` is — spreading 1e6 elements into `max` creates a 1e6-arg call (stack overflow or deopt). Use `Math.max.apply(null, arr)` still allocates; prefer `arr.reduce((m,v)=> m>v?m:v, -Infinity)` or a loop for huge arrays. `**` vs `Math.pow`: `**` is syntax, no call overhead, and handles `BigInt` (`2n ** 10n`).

### 6) **Mentor note**

Have juniors predict `Math.round(-0.5)` (`-0` vs `0`) and `Math.sin(Math.PI)` (`0` vs tiny non-zero) before running — the two cement tie-rule and binary-PI reality. In review, flag any `new Math`, any `Math.max(...hugeArray)` (require loop/reduce), and any degree value passed directly to `sin`/`cos` (require `degToRad` conversion with a named helper). Require `Number.isNaN` guard before `Math.max`/`min` in user-input paths (NaN poisons silently).
