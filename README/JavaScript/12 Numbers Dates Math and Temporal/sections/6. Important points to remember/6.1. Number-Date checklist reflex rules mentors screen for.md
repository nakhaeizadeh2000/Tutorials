## 6.1. Number-Date checklist reflex rules mentors screen for

### 1) **The five reflexes before any `Number` claim — `NaN`/`±0`/`±Infinity`/`>MAX_SAFE_INTEGER`/`0.1+0.2`**

| Reflex | Question | Gate |
|--------|----------|------|
| `NaN` | "Could this be `NaN`? How is it detected?" | `Number.isNaN` (never `=== NaN`, never global `isNaN`) |
| `±0` | "Is `-0` possible and does `1/x` or `JSON` care?" | `Object.is(x,-0)` if sign matters; normalize to `0` before `JSON.stringify` |
| `±Infinity` | "Could this overflow to `Infinity` (`1e309`, `1/0`)?" | `Number.isFinite` guard at boundary |
| `>MAX_SAFE_INTEGER` | "Is this an ID/count that may exceed `2^53-1`?" | `Number.isSafeInteger`; keep IDs as `string`/`BigInt` |
| `0.1+0.2` | "Is this decimal arithmetic or money?" | integer cents / `BigInt` / `Decimal`; `EPSILON` scaled compare for floats |

```js
function assertFiniteNumber(n, label = "value") {
  if (!Number.isFinite(n)) throw new TypeError(`${label} must be finite, got ${String(n)}`);
  if (Object.is(n, -0)) return 0; // normalize for JSON
  return n;
}
console.log(assertFiniteNumber(42)); // 42
try { assertFiniteNumber(Infinity); } catch (e) { console.log(e.name); } // TypeError
console.log(assertFiniteNumber(-0) === 0 && !Object.is(assertFiniteNumber(-0), -0)); // true — normalized

function safeId(id) {
  // IDs from DB may be 64-bit — keep as string if > MAX_SAFE_INTEGER
  if (typeof id === "string" && BigInt(id) > BigInt(Number.MAX_SAFE_INTEGER)) return id; // keep string
  if (typeof id === "number" && !Number.isSafeInteger(id)) throw new RangeError(`ID ${id} exceeds safe integer`);
  return id;
}
console.log(safeId("9007199254740993")); // "9007199254740993" — kept as string
console.log(safeId(42)); // 42
try { safeId(9007199254740993); } catch (e) { console.log(e.name); } // RangeError

function approxEqualScaled(a, b) {
  const diff = Math.abs(a - b);
  const largest = Math.max(Math.abs(a), Math.abs(b));
  return diff <= largest * Number.EPSILON;
}
console.log(approxEqualScaled(0.1 + 0.2, 0.3)); // true
console.log(0.1 + 0.2 === 0.3); // false — the trap
```

### 2) **`Date` is UTC-stamped milliseconds but local-accessed — and DST breaks day arithmetic**

**Reflex — before any `Date` line, ask:**

1. "Is this instant or wall date?" — instant → store `getTime()` ms / `toISOString()` UTC; wall → ISO string `"YYYY-MM-DD"` or `Temporal.PlainDate` (see [5.1](<../5. Temporal/5.1. Temporal overview Instant PlainDate PlainTime PlainDateTime.md>)), never `new Date("YYYY-MM-DD")` as wall.
2. "Which timezone?" — `getHours` → host, `getUTCHours` → UTC, arbitrary zone → `Temporal`/`Intl` (see [4.2](<../4. Legacy Date/4.2. Date timezones UTC vs local DST and arithmetic traps.md>)).
3. "Is this '24h' or 'next calendar day'?" — 24h → `getTime()+86400000`; calendar day → `Temporal` (`add({days:1})`) or `setUTCDate` for UTC only.

```js
// Checklist applied — store UTC, display via Intl
const instant = new Date(Date.UTC(2026, 0, 15, 12, 0, 0));
console.log(instant.toISOString()); // UTC — storage
console.log(new Intl.DateTimeFormat("en-US", { timeZone: "Asia/Tehran", dateStyle: "medium" }).format(instant)); // wall — display

// Calendar day via UTC anchoring (legacy) — only correct for UTC calendar
function addCalendarDaysUTC(date, days) {
  const d = new Date(date);
  d.setUTCDate(d.getUTCDate() + days);
  return d;
}
console.log(addCalendarDaysUTC(new Date("2026-01-15T12:00:00.000Z"), 1).toISOString()); // "2026-01-16T12:00:00.000Z"

// 24h duration — always 86400000, not a calendar month
console.log(new Date("2026-01-15T00:00:00.000Z").getTime() + 30 * 24 * 60 * 60 * 1000); // 30 days in ms, not "1 month"
```

### 3) **The review grep list**

| Grep | Flag | Replacement |
|------|------|-------------|
| `parseInt(` without `, 10` or `, 16` | missing radix | `parseInt(s, 10)` or `Number(s)` with `isFinite` |
| `\bisNaN\b` / `\bisFinite\b` (global) | coercion bug | `Number.isNaN` / `Number.isFinite` after `Number()` |
| `Math\.random` in `auth|token|shuffle|password` | weak RNG | `crypto.getRandomValues` / `node:crypto.randomInt` |
| `new Date\(["']` with non-ISO slash | non-portable parse | `split("-")`+`Date.UTC` or `Temporal` |
| `getMonth\(\)` without `\+1` | month off-by-one | `getMonth()+1` with comment `// 0-indexed` |
| `\b24\s*\*\s*60\s*\*\s*60` labeled "day" | duration vs calendar | `Temporal` `add({days:1})` or UTC anchoring |
| `toFixed\(` on money without cents comment | binary rounding | integer cents + `Intl.NumberFormat` |
| `typeof.*=== "number"` without `isFinite` | misses `NaN`/`Infinity` | `Number.isFinite` gate |

```js
// Grep demo — these would be flagged:
console.log(parseInt("08")); // flagged — missing radix
console.log(isNaN("foo")); // flagged — global isNaN
console.log(Math.random()); // flagged only if in auth/token path — context-sensitive
console.log(new Date("01/02/2026")); // flagged — non-ISO
const d = new Date(2026, 0, 15);
console.log(d.getMonth()); // flagged if used as display without +1 → January shows 0
console.log(24 * 60 * 60 * 1000); // flagged if comment says "one day"
console.log((1.005).toFixed(2)); // flagged if money — use cents
console.log(typeof NaN === "number"); // true — but flagged if gate missing isFinite
```

**Mentor checklist — require in review:**

- [ ] `Number.isNaN`/`Number.isFinite`/`Object.is(x,-0)` at every numeric boundary.
- [ ] `Number.isSafeInteger` or `string`/`BigInt` for IDs > `2^53-1`.
- [ ] `parseInt` always has radix; empty-string `Number("")→0` guarded.
- [ ] `Temporal` feature-detected (`typeof Temporal`) or polyfill noted; `Date` wall dates kept as ISO string.
- [ ] `Intl` formatter hoisted, not constructed per iteration; locale-aware display via `Intl`/`Temporal.toLocaleString`.
- [ ] Randomness: `Math.random` never for secrets; `crypto` for tokens/shuffles; seedable PRNG for deterministic tests.
