## 2.1. Parsing numbers Number vs parseInt parseFloat and radix pitfalls

### 1) **Strict vs lenient parsing — `Number(str)`/`+str` vs `parseInt`/`parseFloat`**

**Definition** — `Number(value)` (and unary `+value`) uses `ToNumber` → `StringToNumber`: the *entire* trimmed string must be a valid numeric literal (optional sign, decimal, exponent, `Infinity`, `0x`/`0b`/`0o` prefixes, `""` → `0`, whitespace-only → `0`). `parseInt`/`parseFloat` (and `Number.parseInt`/`parseFloat` — same functions) are *lenient*: they read a *prefix* until the first non-numeric character, ignore trailing garbage, and return `NaN` if no prefix parses.

```js
// Strict — entire string must be numeric
console.log(Number("42")); // 42
console.log(+"42"); // 42 — unary plus is ToNumber
console.log(Number("  42  ")); // 42 — trims whitespace
console.log(Number("")); // 0 — empty string → 0 (surprise)
console.log(Number("   ")); // 0 — whitespace-only → 0
console.log(Number("42px")); // NaN — trailing garbage invalid
console.log(Number("0x10")); // 16 — hex prefix understood
console.log(Number("0b10")); // 2 — binary
console.log(Number("0o10")); // 8 — octal
console.log(Number(null)); // 0 — ToNumber(null) → +0
console.log(Number(undefined)); // NaN — ToNumber(undefined) → NaN
console.log(Number(true)); // 1
console.log(Number(false)); // 0

// Lenient — prefix only
console.log(parseInt("42px")); // 42 — stops at 'p'
console.log(parseFloat("42.5px")); // 42.5 — stops at 'p'
console.log(parseInt("  42px")); // 42 — leading whitespace ignored, then prefix
console.log(parseInt("")); // NaN — no prefix
console.log(parseInt("   ")); // NaN
console.log(parseInt("0x10")); // 16 — hex prefix (radix-guessing legacy — see §2)
console.log(Number.parseInt === parseInt); // true — same function on Number
console.log(Number.parseFloat === parseFloat); // true

// The empty-string trap in reducers
const fields = ["10", "20", "", "30"];
console.log(fields.map(Number)); // [10, 20, 0, 30] — "" → 0, not NaN
console.log(fields.map(x => x === "" ? NaN : Number(x))); // [10, 20, NaN, 30] — explicit empty guard
console.log(fields.map(parseFloat)); // [10, 20, NaN, 30] — parseFloat("" ) → NaN (lenient empty is NaN)
```

### 2) **`parseInt` radix — always pass it, and the legacy octal trap**

**Definition** — `parseInt(string, radix)` parses in base `radix` (2–36). If `radix` is `undefined`/`0`, legacy rules guessed: `0x` → 16, otherwise 10 (pre-ES5 guessed octal for leading `0`). ES5+ defaults to 10, but the hazard remains: `parseInt("08")` historically returned `0` (octal `8` invalid → stops). Today it returns `8`, but the *intent* is still ambiguous without explicit radix, and `parseInt("0x10")` still guesses 16.

```js
// Always pass radix 10 for decimal
console.log(parseInt("08", 10)); // 8 — explicit decimal
console.log(parseInt("08")); // 8 — modern engine gives 8, but intent unclear; reviewers flag missing radix
console.log(parseInt("010", 10)); // 10 — decimal ten, not octal eight
console.log(parseInt("010", 8)); // 8 — explicit octal
console.log(parseInt("0x10", 16)); // 16 — explicit hex
console.log(parseInt("0x10")); // 16 — guesses hex from prefix (radix 0 → 16)
console.log(parseInt("0x10", 10)); // 0 — radix 10 stops at 'x' → parses "0" → 0

// Radix range and digit validation
console.log(parseInt("101", 2)); // 5 — binary
console.log(parseInt("FF", 16)); // 255
console.log(parseInt("ff", 16)); // 255 — case-insensitive
console.log(parseInt("9", 8)); // NaN — '9' invalid in octal
console.log(parseInt("08", 8)); // NaN — '8' invalid
console.log(parseInt("10", 36)); // 36 — radix 36 max

// Array map trap — parseInt as callback receives index as radix
console.log(["10", "10", "10"].map(parseInt)); // [10, NaN, 2] — index 1 → radix 1 invalid → NaN; index 2 → radix 2 → binary "10" → 2
console.log(["10", "10", "10"].map(s => parseInt(s, 10))); // [10, 10, 10] — correct
console.log(["10", "10", "10"].map(Number)); // [10, 10, 10] — Number ignores second arg (but still: prefer explicit)

// Number() understands 0x/0b/0o prefixes without radix arg — parseInt needs radix or prefix
console.log(Number("0b101")); // 5
console.log(parseInt("0b101", 2)); // 0 — stops at 'b' when radix 2? Actually "0" valid, 'b' invalid → 0
console.log(parseInt("101", 2)); // 5 — strip prefix manually for parseInt binary
```

### 3) **Non-string coercion paths and the `Symbol`/`BigInt` throws**

**Definition** — `Number` coerces any value via `ToNumber` (object → `ToPrimitive` → `ToNumber`). `parseInt`/`parseFloat` first `ToString` the input, then parse the string prefix. `Symbol` cannot be coerced to number (throws `TypeError`); `BigInt` → `Number` works via value conversion (may lose precision); unary `+` on `BigInt` throws.

```js
// Object → ToPrimitive → ToNumber path (see Values 2.3 for full dance)
console.log(Number({ valueOf() { return 42; } })); // 42 — valueOf first (number hint)
console.log(Number({ toString() { return "42"; } })); // 42 — fallback to toString
console.log(Number([42])); // 42 — array → "42" → 42
console.log(Number([1, 2])); // NaN — "1,2" → NaN
console.log(Number([])); // 0 — "" → 0

// parseInt stringifies first — different path
console.log(parseInt({ toString() { return "42px"; } }, 10)); // 42 — ToString then prefix
console.log(parseInt([42], 10)); // 42 — [42] → "42"

// Symbol throws on any numeric coercion
try { console.log(Number(Symbol("s"))); } catch (e) { console.log(e.name); } // TypeError
try { console.log(+(Symbol("s"))); } catch (e) { console.log(e.name); } // TypeError
try { console.log(parseInt(Symbol("s"), 10)); } catch (e) { console.log(e.name); } // TypeError — ToString(Symbol) throws

// BigInt conversions
console.log(Number(10n)); // 10 — BigInt → Number allowed (may lose safe-integer)
console.log(Number(9007199254740993n)); // 9007199254740992 — loss beyond 53 bits
console.log(parseInt("10n", 10)); // 10 — string "10n" prefix "10"
try { console.log(+10n); } catch (e) { console.log(e.name); } // TypeError — unary + rejects BigInt
try { console.log(Number(10n) + 10n); } catch (e) { console.log(e.name); } // TypeError — already covered, but Number(10n) is number
console.log(typeof (10n + 20n)); // "bigint" — BigInt arithmetic stays BigInt

// null/undefined/boolean edge (ToNumber table — see Values 2.2)
console.log(Number(null)); // 0
console.log(Number(undefined)); // NaN
console.log(Number(true), Number(false)); // 1 0
console.log(parseInt(null, 10)); // NaN — String(null) → "null" → prefix 'n' invalid
console.log(parseInt(true, 10)); // NaN — "true" → invalid
```

### 4) **Common confusion**

- "`parseInt` is the integer converter" — no, it is a *string prefix parser*; for strict "is this string an integer?" use `Number(str)` + `Number.isInteger` gate.
- "`Number('')` should be `NaN`" — it is `0` (whitespace-only also `0`); guard empty strings before `Number` if you mean `NaN`.
- "`parseInt` guesses radix correctly" — it guesses only for `0x` prefix (→16); otherwise defaults to 10 since ES5 — but `0x10` with radix 10 gives `0`, not `16`.
- "`parseInt` and `Number.parseInt` differ" — they are the same function (`Number.parseInt === parseInt`).
- "`+bigint` coerces to number" — no, unary `+` throws `TypeError` on `BigInt`; use `Number(bigint)`.

### 5) **Performance note**

`Number(str)` is a single `StringToNumber` scan (no allocation beyond the result). `parseInt` does `ToString` + prefix scan (extra stringify if input is not already a string). In hot CSV parsing of 1e6 rows, `Number` on already-validated numeric strings is faster than `parseInt`+`radix`+`isNaN` chain because the latter does two passes. Avoid `parseInt(x, 10)` in tight numeric loops where `x` is already a number — it stringifies the number first (`parseInt(42,10) → ToString(42) → "42" → 42`).

### 6) **Mentor note**

Have juniors predict `Number("")`, `Number("  ")`, `parseInt("08")`, and `["10","10","10"].map(parseInt)` before running — the four reveals cement strict-vs-lenient and the radix-as-index trap. In review, flag any `parseInt(s)` without radix and any `Number` on unvalidated empty/whitespace user input (require empty-guard or `parseFloat` with `NaN` semantics). Require `Number.isFinite`/`Number.isNaN` after parsing, not global `isNaN`.
