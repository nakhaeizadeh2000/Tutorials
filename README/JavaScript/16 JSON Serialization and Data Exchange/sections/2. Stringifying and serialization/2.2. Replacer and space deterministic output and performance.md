## 2.2. Replacer and space deterministic output and performance

### 1) **Replacer array vs function — filter vs transform**

**Definition** — `JSON.stringify(value, replacer, space)` second arg shapes output: array replacer is an *allowlist* of string keys (order determines inclusion order, filtered before walk); function replacer `(key, value)` is called *per node* top-down (wrapper `""` first, then its properties depth-first; `this` is the holder object) — opposite of reviver which is bottom-up. Returning `undefined` omits a property (array case filters; function omits). Top wrapper call has `key = ""` and `this = {"": value}`.

```js
// Array replacer — only listed keys included, in list order (own enumeration order otherwise irrelevant)
console.log(JSON.stringify({ c: 3, a: 1, b: 2 }, ["a", "c"])); // {"a":1,"c":3} — b omitted, a before c per array order
console.log(JSON.stringify({ a: 1, b: { x: 1, y: 2 } }, ["a", "b", "x"])); // {"a":1,"b":{"x":1}} — nested allowlist needs keys at each depth

// Function replacer — transform values; wrapper call has key "" first (replacer walks top-down)
const seen = [];
console.log(JSON.stringify({ a: 1, b: 2 }, function(k, v) { seen.push(k); return v; }));
console.log(seen); // [ '', 'a', 'b' ] — wrapper then leaves (top-down walk; reviver is opposite bottom-up)
console.log(JSON.stringify({ secret: "x", ok: 1 }, (k, v) => k === "secret" ? undefined : v)); // {"ok":1} — omission via undefined

// BigInt guard via function replacer (canonical pattern)
console.log(JSON.stringify({ id: 9007199254740993n, n: 42 }, (k, v) => typeof v === "bigint" ? v.toString() : v)); // {"id":"9007199254740993","n":42}
```

- **Modern guidance** — use array replacer for *stable API allowlists* (document contract); use function replacer for `BigInt`→`string`, stripping `secret`, or date coercion — but keep replacer pure (no side effects on holder).

### 2) **Determinism illusion — order, space, and stable stringify**

**Definition** — Without replacer, `JSON.stringify` emits properties in ES2015 `OrdinaryOwnPropertyKeys` order (integers ascending, then strings insertion, symbols never). `space` (number 0–10 or string up to 10 chars) pretty-prints with indentation and newlines but does not change value. Deterministic output for signatures/hashing is *not* free — lexicographic sort needs a replacer or pre-sort.

```js
// Insertion order respected (but integers sorted)
const o = {}; o.b = 1; o["0"] = 2; o.a = 3;
console.log(JSON.stringify(o)); // {"0":2,"b":1,"a":3} — "0" integer first, then insertion b then a
console.log(JSON.stringify({ b: 1, a: 3 }, Object.keys({ b: 1, a: 3 }).sort())); // {"a":3,"b":1} — sorted via array replacer

// Ugly pitfall — delete + re-add moves insertion position (see Objects 2.3)
const u = { a: 1, b: 2, c: 3 }; delete u.b; u.b = 20;
console.log(JSON.stringify(u)); // {"a":1,"c":3,"b":20} — b at end, not original position
console.log(JSON.stringify(Object.fromEntries(Object.entries(u).sort()))); // {"a":1,"b":20,"c":3} — normalized

// space pretty-print — debugging only, not for wire (bloat + nondeterministic whitespace diffs)
console.log(JSON.stringify({ a: 1, b: 2 }, null, 2));
// {
//   "a": 1,
//   "b": 2
// }
console.log(JSON.stringify({ a: 1, b: 2 }, null, "\t")); // tab indented
console.log(JSON.stringify({ a: 1 }, null, 12).split("\n")[1].slice(0,12) === "          \"a\""); // true — clamped to 10 spaces
```

- **Modern guidance** — wire uses `space = undefined` (no whitespace). For hashing/signing, sort keys deterministically before stringify (e.g., `Object.keys(o).sort()` array replacer or `Object.fromEntries(sorted)`); do not rely on insertion order staying stable across deletes.

### 3) **Common transforms and anti-patterns**

**Definition** — Typical function replacers: strip `private`/`_` prefix, truncate long strings, convert `Date`→ISO via `toJSON` delegation (replacer sees ISO string already), mask PII.

```js
// Strip private _keys, coerce BigInt, guard circular via WeakSet (depth-first)
function safeStringify(obj) {
  const seen = new WeakSet();
  return JSON.stringify(obj, function(k, v) {
    if (typeof v === "bigint") return v.toString();
    if (typeof v === "object" && v !== null) {
      if (seen.has(v)) return "[Circular]"; // return string instead of throwing (alternative: undefined to omit)
      seen.add(v);
    }
    if (k.startsWith("_")) return undefined; // omit private
    return v;
  });
}
const c = { a: 1, _secret: 2, b: 10n };
c.self = c;
console.log(safeStringify(c)); // {"a":1,"b":"10","self":"[Circular]"} — private omitted, BigInt stringified, cycle guarded

// BAD: replacer that mutates holder or returns 0 for omitted — silent data loss
console.log(JSON.stringify({ a: 1, b: 2 }, (k, v) => (k === "b" ? 0 : v))); // {"a":1,"b":0} — was omission intended?
// BAD: array replacer that forgets nested keys
console.log(JSON.stringify({ a: { x: 1, y: 2 } }, ["a"])); // {"a":{}} — y hidden, x omitted because "x" not in list
```

### 4) **Common confusion**

- "`Replacer runs bottom-up like reviver`" — no: replacer walks top-down (wrapper `""` first, then leaves); reviver walks bottom-up (leaves first, wrapper `""` last) — do not mix the two (see [3.2](<../3. Parsing and revival/3.2. Reviver post-processing dates BigInts and key filtering.md>)).
- "`Array replacer sorts keys`" — no, it *filters* and respects *list order*; unsorted list does not sort insertion order.
- "`Returning null omits`" — `null` emits `null`; only `undefined` (or `symbol`/`function`) omits in objects and `null` in arrays (see [2.1](<./2.1. What JSON.stringify serializes and what it drops.md>)).
- "`space affects value`" — whitespace changes the string but not the parsed value; diffing pretty-printed JSON is brittle — canonicalize first.

### 5) **Performance note**

Replacer is invoked for *every* node — O(n) calls plus holder `this` binding overhead. Array replacer does an extra `includes` scan per property (V8 optimizes small arrays but still linear). `space` indentation builds a larger string (+20–40% bytes) and is slower — never enable it for wire production; measure with `Buffer.byteLength` vs pretty. Avoid allocating `WeakSet` inside hot loops unless circular is expected — `try { JSON.stringify } catch` may be faster for acyclic graphs.

### 6) **Mentor note**

Give trainees `JSON.stringify(obj, ["b","a"])` and ask order — answer: `{"b":…,"a":…}` (list order), not insertion. In review, flag `JSON.stringify(obj, null, 2)` in production paths (wire bloat); require `space` only in `prettyPrintForLog` helpers. Demand that every function replacer explicitly handle `typeof v === "bigint"` and optionally cycle, and document what "[Circular]" means for the consumer (or omit via `undefined` if contract expects omitted key).
