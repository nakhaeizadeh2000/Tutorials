## 2.1. What JSON.stringify serializes and what it drops

### 1) **The enumerable-string-own filter — only data surface goes on the wire**

**Definition** — `JSON.stringify(value)` serializes only *enumerable own string-key* properties (same surface as `Object.keys` + `...spread`; see [Objects 2.3](<../../../06 Objects in Depth/sections/2. Properties and descriptors/2.3. Enumerability enumeration order and for-in mechanics.md>)). Symbols, inherited, and non-enumerable properties are skipped. `null`-prototype objects serialize normally (no prototype pollution in output).

```js
console.log(JSON.stringify({ a: 1, b: 2 })); // {"a":1,"b":2}

// Symbols skipped
const s = Symbol("id");
console.log(JSON.stringify({ a: 1, [s]: 2 })); // {"a":1} — symbol omitted
console.log(JSON.stringify({ [s]: 1 })); // {} — only symbol → empty object

// Non-enumerable and inherited skipped
const obj = Object.create({ inherited: 1 });
Object.defineProperties(obj, {
  visible: { value: 1, enumerable: true, configurable: true, writable: true },
  hidden:  { value: 2, enumerable: false, configurable: true, writable: true },
});
obj.own = 3;
console.log(JSON.stringify(obj)); // {"visible":1,"own":3} — hidden + inherited absent
console.log(Object.keys(obj)); // [ 'visible', 'own' ] — same filter as stringify
console.log(Reflect.ownKeys(obj)); // [ 'visible', 'hidden', 'own' ] — own but filtered

// null-proto dict — serializes like a plain object (no __proto__ key suppression)
const dict = Object.create(null);
dict.a = 1; dict.__proto__ = "data"; // plain key, not prototype link
console.log(JSON.stringify(dict)); // {"a":1,"__proto__":"data"} — __proto__ is data here
```

- **Modern guidance** — put API data as enumerable own string keys; hide internal slots as non-enumerable or symbol-keyed (or `#private`) if you do not want them on the wire.

### 2) **Omission vs nullification — objects drop, arrays null**

**Definition** — ECMA-262 `JSON.stringify` rules: in *objects*, values `undefined`/`function`/`symbol` cause the *key* to be omitted (`{a: undefined}` → `{}`). In *arrays*, those values become `null` (`[1, undefined, 3]` → `[1,null,3]`). `Infinity`/`NaN` become `null` everywhere. `-0` becomes `"0"` (sign erased).

```js
// Object omission vs array null
console.log(JSON.stringify({ a: 1, b: undefined, c() {}, d: Symbol("x"), e: null })); // {"a":1,"e":null} — b,c,d gone
console.log(JSON.stringify([1, undefined, function(){}, Symbol("x"), null, Infinity, NaN])); // [1,null,null,null,null,null,null]
console.log(JSON.stringify({ x: NaN, y: Infinity, z: -Infinity })); // {"x":null,"y":null,"z":null}
console.log(JSON.stringify(-0)); // 0 — sign lost
console.log(JSON.stringify([0, -0])); // [0,0]
console.log(JSON.stringify({ a: -0 })); // {"a":0}

// Top-level undefined/function/symbol serialize to undefined (not "undefined" string)
console.log(JSON.stringify(undefined)); // undefined — not JSON text
console.log(JSON.stringify(function(){})); // undefined
console.log(JSON.stringify(Symbol("x"))); // undefined
console.log(String(JSON.stringify(undefined))); // undefined — String(undefined) is "undefined" but value is JS undefined

// Holes are null too
const sparse = [1, , 3]; // hole at 1
console.log(JSON.stringify(sparse)); // [1,null,3] — hole → null (see Arrays 2.1)
console.log(Object.hasOwn(sparse, "1")); // false — hole has no own property but stringify still emits null
```

- **Why it matters** — API shape loss: required field `payload.token = undefined` disappears from JSON and the server sees "missing" not `null`. Use explicit `null` for "no value".

### 3) **Hard fails — BigInt and circular**

**Definition** — `JSON.stringify(BigInt)` *throws* `TypeError: Do not know how to serialize a BigInt` (no implicit string coercion). Circular references throw `TypeError: Converting circular structure to JSON`. TypedArray/RegExp/Map/Set/Date custom cases are *not* throws but shape surprises (see §4/§5).

```js
try { console.log(JSON.stringify({ id: 10n })); } catch (e) { console.log("BigInt →", e.name, e.message.slice(0,40)); }
try { console.log(JSON.stringify(10n)); } catch (e) { console.log("top BigInt →", e.name); }

const a = {}; a.self = a;
try { JSON.stringify(a); } catch (e) { console.log("circular →", e.name, e.message.slice(0,30)); }

const b = { x: 1 }; b.y = b; // cycle via property
try { JSON.stringify({ a: b }); } catch (e) { console.log("nested cycle →", e.name); }

// TypedArray / Map / Set do not throw but lose shape (forward to §5 /pitfalls)
console.log(JSON.stringify(new Uint8Array([1,2]))); // {"0":1,"1":2} — looks like object
console.log(JSON.stringify(new Map([[1,2]]))); // {} — empty
console.log(JSON.stringify(/ab/g)); // {} — RegExp → {}
```

- **Modern guidance** — handle `BigInt`/circular at boundary with `replacer` (see [2.2](<./2.2. Replacer and space deterministic output and performance.md>)); never rely on `try/catch` alone for detection in hot paths — filter before stringify.

### 4) **Common confusion**

- "`JSON.stringify keeps undefined as null in objects`" — no: omitted in objects, `null` in arrays; this asymmetry is spec and breaks `Object.keys` length expectations.
- "`JSON.stringify preserves -Infinity/NaN`" — no: they become `null` (like `Infinity` stringifies `null`, not `"Infinity"`).
- "`JSON.stringify serializes symbols/functions`" — never; symbols as values are omitted/nullified; symbol-keyed properties are excluded entirely.
- "`JSON.stringify of a function returns \"{}\"`" — top-level function → `undefined`, not `"{}"`; only wrapping it in object/array yields `"{}"`/`[null]`.

### 5) **Performance note**

`JSON.stringify` walks the graph depth-first; replacer (if any) is called per node *before* serialization (see [2.2](<./2.2. Replacer and space deterministic output and performance.md>)). Avoid `JSON.parse(JSON.stringify(x))` as a clone in hot loops — it allocates a megastring + re-parses; `structuredClone(x)` is faster and preserves more types (see [5.1](<../5. Beyond JSON structuredClone and data exchange/5.1. structuredClone deep cloning and limitations.md>)). Never call `JSON.stringify` inside a `replacer` recursively without depth guard — it re-enters the walk.

### 6) **Mentor note**

Ask trainees to predict `JSON.stringify({a: undefined, b: null, c: NaN, d: [undefined]})` before running — checks omission vs nullification and `NaN→null`. In review, flag any API code that sets optional fields to `undefined` expecting the key to appear as `null` on the server; require explicit `field ?? null` or omission contract documented. Demand a `BigInt`/circular guard wherever `stringify` touches user-controlled graph (DB rows with `BigInt` IDs, session objects with cycles).
