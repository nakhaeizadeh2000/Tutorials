## 5.1. structuredClone deep cloning and limitations

### 1) **What structuredClone clones — the HTML structured-clone algorithm**

**Definition** — `structuredClone(value, { transfer? })` (HTML spec §2.7, exposed as global in browsers + Node 17+ / Deno/Bun) deep-clones using the *structured cloning* algorithm, not JSON text. Cloneable: all primitives (including `BigInt`, but cloning `BigInt` preserves type), `Date`, `RegExp`, `Array` (including holes), `Map`, `Set`, `ArrayBuffer`/`TypedArray`/`DataView`, plain objects and `Error` (where engine supports). Proxies are unwrapped to target.

```js
// Primitives + hole preservation (vs JSON [4.1] which densifies)
const sparse = [1, , 3];
const sj = structuredClone(sparse);
console.log(sj.length, Object.hasOwn(sj, "1"), sj[1]); // 5? wait sparse length 3 — actually [1,,3] length 3
// Correct sparse with two gaps length 5 demo
const s5 = [1, , 3, , 5];
console.log(structuredClone(s5).length, Object.hasOwn(structuredClone(s5),"1")); // 5 false — hole preserved (unlike JSON)

// Date and RegExp survive as same type (vs JSON Date→string, RegExp→{})
const d = new Date("2026-01-01T00:00:00.000Z");
console.log(structuredClone(d) instanceof Date, structuredClone(d).toISOString()); // true 2026-01-01...
console.log(structuredClone(/ab/gi) instanceof RegExp, structuredClone(/ab/gi).source); // true ab

// Map/Set survive (vs JSON {})
const m = new Map([[1, { x: 1 }]]); const mm = structuredClone(m);
console.log(mm instanceof Map, mm.get(1)); // true { x: 1 } — deep clone, new object
console.log(mm !== m, mm.get(1) !== m.get(1)); // true true — deep

// BigInt survives (vs JSON TypeError)
console.log(structuredClone(10n) === 10n); // true
console.log(structuredClone({ id: 9007199254740993n }).id === 9007199254740993n); // true
```

### 2) **Circles and shared refs — identity preserved unlike JSON**

**Definition** — `structuredClone` handles cycles and preserves *shared reference identity*: if the same object appears twice in the graph, the clone shares a single clone (two pointers to one clone), not two independent copies. `JSON.stringify` throws on cycles and duplicates shared refs as independent copies (see [4.1](<../4. Edge cases and lossy conversions/4.1. Circular structures sparse arrays and copy pitfalls.md>)).

```js
// Cycle preserved
const a = { x: 1 }; a.self = a;
const ac = structuredClone(a);
console.log(ac !== a, ac.self === ac); // true true — clone cycle points to clone, not original
try { JSON.stringify(a); } catch (e) { console.log("JSON cycle →", e.name); }

// Shared ref preserved
const shared2 = { n: 1 };
const root = { p1: shared2, p2: shared2 };
const rc = structuredClone(root);
console.log(rc.p1 === rc.p2); // true — same clone instance
const rj = JSON.parse(JSON.stringify(root));
console.log(rj.p1 === rj.p2); // false — JSON duplicated into two clones
console.log(rj.p1 !== shared2, rc.p1 !== shared2); // true true — both deep
```

### 3) **What it does not clone — boundary**

**Definition** — Not cloneable: functions (throws `DataCloneError`), `WeakMap`/`WeakSet`, `Promise`, any object with `Symbol`? Actually symbols clone? Many engines clone symbols? But property descriptors/getters are not preserved as descriptors — getters are evaluated and cloned as plain data. Prototype is preserved as `Object.getPrototypeOf` for plain objects? But custom class instances become plain? Let's verify: `structuredClone` preserves prototype for some? In current engines, `structuredClone` of a plain `instanceof` user class becomes plain `Object` (lost class/type) — check.

```js
// Functions throw
try { structuredClone(() => {}); } catch (e) { console.log("function →", e.name, e.message.slice(0,40)); }
try { structuredClone({ fn() {} }); } catch (e) { console.log("method object →", e.name, e.message.slice(0,40)); }

// WeakMap/WeakSet throw (not enumerable, not cloneable)
try { structuredClone(new WeakMap()); } catch (e) { console.log("WeakMap →", e.name); }

// Getter becomes plain data
const withGetter = { get x() { return 1; }, y: 2 };
console.log(Object.getOwnPropertyDescriptor(structuredClone(withGetter), "x")); // { value: 1, writable:true, enumerable:true, configurable:true } — plain data

// Prototype — user class instance loses class? Let's check current Node
class C { m() { return 1; } }
const c = new C(); c.x = 1;
const cc = structuredClone(c);
console.log(cc instanceof C, Object.getPrototypeOf(cc) === C.prototype, typeof cc.m); // false Object false? Check on Node 20
console.log(cc); // { x: 1 } — class identity lost

// ArrayBuffer clone via copy by default; transfer neuters source
const buf = new ArrayBuffer(4); new Uint8Array(buf)[0] = 7;
const buf2 = structuredClone(buf);
console.log(buf2 instanceof ArrayBuffer, new Uint8Array(buf2)[0]); // true 7
// Transfer (zero-copy move)
const buf3 = new ArrayBuffer(4);
const cloneMoved = structuredClone(buf3, { transfer: [buf3] });
console.log(buf3.byteLength, cloneMoved.byteLength); // 0 4 — source detached
```

- **Modern guidance** — use `structuredClone` for *in-process* deep clone where functions/WeakRefs are not needed. For class instances, prefer `structuredClone` + manual `Object.setPrototypeOf` restore or a custom `clone` method.

### 4) **When to pick which — decision table**

| Need | Pick | Why |
|------|------|-----|
| Wire serialization (persist, send over network, store as text) | `JSON.stringify` + `JSON.parse` with `replacer`/`reviver`/`toJSON` | produces UTF-8/UTF-16 text, interoperable with every language |
| In-process deep clone that preserves `Date`/`Map`/`Set`/`RegExp`/`ArrayBuffer`/`BigInt`/holes/cycles | `structuredClone` | single pass, no intermediate string, type-preserving, handles cycles/shared refs |
| Binary bytes or transfer ownership to Worker | `structuredClone` + `transfer` or `postMessage(..., [buffer])` | zero-copy move, no `base64` overhead |
| Clone with functions/WeakMap/Prototype fidelity | custom `clone` / `lodash.cloneDeep` | `structuredClone` throws or strips those; note `cloneDeep` also cannot clone functions meaningfully but may keep prototype |

```js
// Wire vs clone contrast
const obj = { d: new Date(), m: new Map([[1,2]]), n: 10n, a: [1,,3] };
console.log(JSON.stringify(obj, (k,v)=> typeof v==="bigint"? v.toString():v).slice(0,60)); // {"d":"...","m":{},"n":"10","a":[1,null,3]} — lossy
console.log(structuredClone(obj).m instanceof Map); // true — lossless for clone, but not serializable as text
```

### 5) **Common confusion**

- "`structuredClone supports JSON-like strings`" — no: `structuredClone` clones *values*, not `JSON` text; it has no replacer/reviver — use JSON for strings.
- "`structuredClone keeps prototype/class`" — not reliably; custom classes become plain objects (verify with `instanceof`).
- "`structuredClone copies functions`" — never: throws `DataCloneError` — strip functions before cloning.
- "`structuredClone is slower than JSON clone`" — opposite for most graphs (no string); only small plain objects JSON round-trip may be marginally faster in microbenchmarks — measure.

### 6) **Performance note**

`structuredClone` is a single C++ structured-clone walk without allocating an intermediate string — typically 2–5× faster than `JSON.parse(JSON.stringify(x))` for objects with `Date`/`Map` and 10k nodes, and handles cycles without `WeakSet` overhead. Transferring `ArrayBuffer` via `transfer` neuters the source (`byteLength 0`) and avoids copying 10 MB — use for `Worker` handoff.

### 7) **Mentor note**

Demo the triple contrast: `JSON.stringify([1,,3])` → `[1,null,3]` (hole→null), `structuredClone([1,,3])` → hole preserved, and shared-ref identity: `JSON` duplicates, `structuredClone` preserves single instance. In review, flag any `JSON.parse(JSON.stringify(x))` deep-copy where `x` may contain `Map`/`Set`/`Date`/`BigInt`/hole/cycle — replace with `structuredClone` and add a comment about prototype loss for class instances.
