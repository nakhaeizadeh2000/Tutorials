## 8.1. Common interview QA JSON serialization and data exchange

### 1) **Twelve questions — spot the trap answers**

**Q1. What values can JSON represent? List what `JSON.stringify` omits in objects vs arrays.**
> Seven values: `object`/`array`/`string`/`number`/`true`/`false`/`null`. In *objects* `undefined`/`function`/`symbol` values cause key omission (`{a: undefined}` → `{}`); in *arrays* they become `null` (`[undefined]` → `[null]`); `Infinity`/`NaN`→`null`; symbols as keys never included (see [2.1](<../2. Stringifying and serialization/2.1. What JSON.stringify serializes and what it drops.md>)).

```js
console.log(JSON.stringify({ a: undefined, b: null })); // {"b":null} — a omitted
console.log(JSON.stringify([undefined, null])); // [null,null]
```

**Q2. When does `JSON.stringify` throw?**
> `BigInt` anywhere (including nested) → `TypeError: Do not know how to serialize a BigInt`; circular/ancestral cycle → `TypeError: Converting circular structure to JSON` (duplicate sibling refs not cycles are fine) (see [2.1](<../2. Stringifying and serialization/2.1. What JSON.stringify serializes and what it drops.md>) / [4.1](<../4. Edge cases and lossy conversions/4.1. Circular structures sparse arrays and copy pitfalls.md>)).

```js
try { JSON.stringify({ x: 10n }); } catch (e) { console.log(e.name); } // TypeError
const o = {}; o.self = o; try { JSON.stringify(o); } catch (e) { console.log(e.name); } // TypeError
```

**Q3. `JSON.parse('{"a": undefined}')` — what happens?**
> `SyntaxError` — `undefined` is not a JSON value; `JSON.parse` is strict, not lenient. Contrast `JSON.stringify({a: undefined})` → `"{}"` (omission), not `"{"a": undefined}"`.

**Q4. Replacer order? Array replacer vs function replacer?**
> Array replacer is an *allowlist* and respects *list order* (not insertion): `JSON.stringify({c:3,a:1},["a","c"])` → `{"a":1,"c":3}`. Function replacer `(k,v)` walks *top-down* wrapper first (vs reviver bottom-up). Returning `undefined` omits (object) or holes (array); `null` emits `null` (see [2.2](<../2. Stringifying and serialization/2.2. Replacer and space deterministic output and performance.md>)).

```js
console.log(JSON.stringify({ c:3, a:1 }, ["a"])); // {"a":1} — c filtered
JSON.stringify({ a:1 }, (k,v)=> { console.log(k); return v; }); // "" then "a" — top-down
```

**Q5. Does `JSON.parse` evaluate code? Is `{"__proto__": {"x":1}}` dangerous?**
> `JSON.parse` never executes code — it builds data only. `{"__proto__":…}` parses as *own* data property `"__proto__"` (not wiring) on modern engines, but `Object.assign(target, parsed)` or `target[k]=v` *does* wire via `__proto__` setter → pollution if `parsed` is copied without filtering; filter via reviver `(k,v)=>k==="__proto__"?undefined:v` or null-proto target (see [3.2](<../3. Parsing and revival/3.2. Reviver post-processing dates BigInts and key filtering.md>)).

**Q6. `JSON.parse('{"a":1,"a":2}')` result?**
> `{a:2}` — last duplicate key wins; RFC allows duplicates, ECMA-262 parse produces last value; no error, no array (see [1.1](<../1. JSON as a format/1.1. JSON grammar vs JavaScript literals history and the JSON superset.md>)).

**Q7. How do you preserve 64-bit IDs through JSON?**
> Wire as *strings*, not numbers: `JSON.stringify(obj, (k,v)=> typeof v==="bigint"? v.toString():v)` outbound; `BigInt(string)` for known keys inbound via reviver; never pass `9007199254740993` as `number` (`==9007199254740992` collapse) (see [4.2](<../4. Edge cases and lossy conversions/4.2. Numbers beyond safe integer Infinity NaN and negative zero.md>)).

**Q8. What does `toJSON` do and when does it run before replacer?**
> If a value has `toJSON(key)` it is called (`this` = original, arg = holder key) and its return value is serialized instead; replacer sees the `toJSON` return, not raw object. `Date#toJSON` → `toISOString()` (hence date → ISO string); invalid date → `null` (see [2.3](<../2. Stringifying and serialization/2.3. toJSON protocol custom serialization and recursion.md>)).

**Q9. Holes vs null vs undefined after round-trip?**
> Sparse hole serializes as `null` and parses back as *own* `null` (dense, `Object.hasOwn(arr,"1")` flips `false→true`); `structuredClone` preserves holes as holes (see [4.1](<../4. Edge cases and lossy conversions/4.1. Circular structures sparse arrays and copy pitfalls.md>)).

```js
const s = [1,,3]; // hole at 1
console.log(JSON.parse(JSON.stringify(s))[1], structuredClone(s)[1], Object.hasOwn(JSON.parse(JSON.stringify(s)),"1")); // null undefined true — JSON vs clone
```

**Q10. `JSON.stringify([NaN, Infinity, -0])` output?**
> `[null,null,0]` — specials become `null`/`0` (see [4.2](<../4. Edge cases and lossy conversions/4.2. Numbers beyond safe integer Infinity NaN and negative zero.md>)).

**Q11. `JSON.parse(JSON.stringify({m: new Map()}))` — shape?**
> `{m:{}}` — `Map`/`Set` have no `toJSON` and serialize as `{}` (see [5.1](<../5. Beyond JSON structuredClone and data exchange/5.1. structuredClone deep cloning and limitations.md>)); for clone use `structuredClone`.

**Q12. `structuredClone` vs `JSON.parse(JSON.stringify)` — when to use which?**
> `structuredClone` for in-process clone: preserves `Date`/`Map`/`Set`/`ArrayBuffer`/`BigInt`/holes/cycles/shared refs as same-type, no string; `JSON` for wire text. `structuredClone` throws on `function`/`WeakMap` and loses class prototype; `JSON` omits/drops more (see [5.1](<../5. Beyond JSON structuredClone and data exchange/5.1. structuredClone deep cloning and limitations.md>)).

### 2) **What interviewers actually probe for**

- Tracing the `toJSON`→replacer→filter chain and direction (wrapper-first vs leaves-first) — not reciting "replacer filters keys".
- Narrating *why* `BigInt` throws and where the `__proto__` pollution window actually is (`assign` not `parse`).
- Naming the three lossy conversions: hole→null, `-0`→0, `NaN`/`Infinity`→null, `Date`→string, `MAX_SAFE` collapse.
- Choosing `structuredClone` vs JSON clone with performance/preservation trade-off.

### 3) **Grading guidance**

- *Junior signals* — can list seven JSON values, knows `JSON.parse` throws `SyntaxError`; maybe misses `-0`/`NaN` or `__proto__` filter. *Red flags* — "JSON supports comments/trailing commas / single quotes", "JSON.stringify keeps functions", "parse executes code", "duplicate keys error".
- *Mid signals* — explains object omission vs array null, BigInt TypeError, Date→string via `toJSON`, hole densify, `toJSON` before replacer. *Red flags* — "replacer runs bottom-up like reviver", "reviver runs top-down", "`structuredClone` is just faster JSON clone with same shape".
- *Senior signals* — walks replacer top-down vs reviver bottom-up with wrapper `""` detail, gives replacer `BigInt→string` + reviver `string→BigInt` allowlist, shows `__proto__` filter at `parse` time + `Object.create(null)` alternative, argues string IDs + size guard + NDJSON for streams. *Red flags* — "send 64-bit id as number", "clone with JSON handles Map/Set and cycles", "use `JSON.stringify(obj,null,2)` on wire".
