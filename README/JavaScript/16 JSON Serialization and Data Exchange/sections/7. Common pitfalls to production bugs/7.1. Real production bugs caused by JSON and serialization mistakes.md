## 7.1. Real production bugs caused by JSON and serialization mistakes

### 1) **ID collapse beyond safe integer — duplicate key join fails**

**Incident** — DB `BIGINT` `id = 9007199254740993` stored as JS `number` (`9007199254740992` after collapse) then `JSON.stringify`. API consumer joins by `id` — two distinct rows share collapsed id → duplicate map entry → wrong record displayed.

```js
// Reproduce collapse
const rowA = { id: 9007199254740992, name: "A" }; // already collapsed from DB driver as number
const rowB = { id: 9007199254740993, name: "B" }; // in JS heap both are 9007199254740992 (see 4.2)
console.log(rowA.id === rowB.id); // true — collapsed before wire
const wire = JSON.stringify([rowA, rowB]);
console.log(wire); // [{"id":9007199254740992,...},{"id":9007199254740992,...}] — duplicate ids on wire
const byId = new Map(JSON.parse(wire).map(r => [r.id, r]));
console.log(byId.size); // 1 — second overwrote first

// Fix — keep IDs as strings on wire (BigInt-aware replacer) and parse as BigInt
function stringifyIds(o) { return JSON.stringify(o, (k, v) => typeof v === "bigint" ? v.toString() : v); }
const safeA = { id: 9007199254740992n, name: "A" };
const safeB = { id: 9007199254740993n, name: "B" };
console.log(safeA.id !== safeB.id); // true
const safeWire = stringifyIds([safeA, safeB]);
console.log(safeWire); // [{"id":"9007199254740992",...},{"id":"9007199254740993",...}] — distinct
```

- **Why it was missed** — driver typed `id` as `number`; team assumed JSON is faithful; tests used small IDs `<2^53`.

### 2) **Clone via JSON makes Date logic break**

**Incident** — `const snap = JSON.parse(JSON.stringify(state)); if (snap.at instanceof Date) ...` → branch never taken because `at` is string after round-trip; scheduling logic skips → stale timer.

```js
// Reproduce
const state = { at: new Date("2026-01-01T00:00:00.000Z"), flag: true };
const snap = JSON.parse(JSON.stringify(state));
console.log(typeof snap.at, snap.at instanceof Date); // string false — Date became string via toJSON
console.log(snap.at === "2026-01-01T00:00:00.000Z"); // true — but code checked instanceof

// Fix — structuredClone for clone, or reviver pair
console.log(structuredClone(state).at instanceof Date); // true — clone preserves type
const revived = JSON.parse(JSON.stringify(state), (k, v) => k === "at" && typeof v === "string" ? new Date(v) : v);
console.log(revived.at instanceof Date); // true — JSON pair with reviver
```

- **Why it was missed** — `JSON.stringify` consults `Date#toJSON` silently; `instanceof` check after `parse` is string check in disguise.

### 3) **BigInt throw at runtime — payload with BigInt crashes stringify**

**Incident** — New field `amountCents: 1099n` added to order object; legacy `JSON.stringify(order)` path without replacer — production `TypeError: Do not know how to serialize a BigInt` → 500 on checkout.

```js
// Reproduce
const order = { id: "o1", amountCents: 1099n };
try { JSON.stringify(order); } catch (e) { console.log("without replacer →", e.name, e.message.slice(0,40)); }

// Fix — replacer that guards BigInt
console.log(JSON.stringify(order, (k, v) => typeof v === "bigint" ? v.toString() : v)); // {"id":"o1","amountCents":"1099"}
console.log(JSON.stringify({ top: 10n }, (k, v) => typeof v === "bigint" ? v.toString() : v)); // {"top":"10"} — wrapper also bigint
```

- **Why it was missed** — `BigInt` overview ([Values 5.2]) warned throw, but stringify call site was generic util without guard.

### 4) **Prototype pollution via JSON — __proto__ survives copy**

**Incident** — `const prefs = JSON.parse(body); Object.assign(user.prefs, prefs);` with body `{"__proto__": {"isAdmin": true}}` → pollutes `Object.prototype` → later `({}).isAdmin === true` → privilege escalation.

```js
// Reproduce with reviver filter (the fix) vs without
const malicious = '{"__proto__": {"polluted": true}, "theme": "dark"}';
const parsed = JSON.parse(malicious); // own "__proto__" data (not yet wired) but assign would wire on some engines
console.log(Object.hasOwn(parsed, "__proto__")); // true — dangerous key present
console.log({}.polluted); // undefined — not yet polluted globally (but would be after assign on vulnerable path)
const safeParsed = JSON.parse(malicious, (k, v) => k === "__proto__" ? undefined : v);
console.log(Object.hasOwn(safeParsed, "__proto__")); // false — removed at parse

// Null-proto alternative
const victim2 = Object.create(null);
Object.assign(victim2, JSON.parse(malicious)); // assign into null-proto cannot pollute (no prototype)
console.log(Object.getPrototypeOf(victim2) === null); // true
```

- **Why it was missed** — `JSON.parse` itself does not wire prototype (it creates plain object with own `"__proto__"`), but `assign`/spread/`merge` later does `target["__proto__"] = value` which *is* `Object.prototype` setter on ordinary targets.

### 5) **Silent omission of undefined/symbol/function — required field missing**

**Incident** — API client sends `{ name: "A", token: undefined }`; server expects `token` required but `JSON.stringify({name, token})` omits `token` → validation misses it (no key vs `null` confusion) → auth bypass/fallback to default.

```js
// Reproduce omission
console.log(JSON.stringify({ name: "A", token: undefined })); // {"name":"A"} — token missing
console.log(JSON.stringify({ name: "A", token: null })); // {"name":"A","token":null} — explicit null present
console.log(JSON.stringify({ arr: [1, undefined, 2] })); // {"arr":[1,null,2]} — array undefined→null contrast
console.log(JSON.stringify({ [Symbol("s")]: 1, a: 1 })); // {"a":1} — symbol key absent

// Fix — normalize undefined to null for required fields or document optional
function toWireStrict(o) { return JSON.stringify(o, (k, v) => v === undefined ? null : v); } // forces undefined→null (rare — usually omit is correct but contract must choose)
console.log(toWireStrict({ name: "A", token: undefined })); // {"name":"A","token":null} — now explicit
console.log(JSON.stringify({ name: "A", token: undefined }, (k, v) => v === undefined ? undefined : v)); // same as default omit
```

- **Why it was missed** — JS optional `token?: string` collapsed `undefined` vs absent vs `null` distinctions; JSON wire has only absent vs `null`.
