## 4.1. Circular structures sparse arrays and copy pitfalls

### 1) **Circular TypeError — depth-first cycle detection**

**Definition** — `JSON.stringify` maintains a stack of objects currently being serialized; encountering a previously-on-stack value throws `TypeError: Converting circular structure to JSON` with `property 'x' closes the circle` hint in Node. Duplicate *references* (same object at two non-ancestor positions) do *not* throw — the object is serialized twice.

```js
const a = { x: 1 }; a.self = a;
try { JSON.stringify(a); } catch (e) { console.log(e.name, e.message.slice(0,45)); }

const shared = { n: 1 };
console.log(JSON.stringify({ a: shared, b: shared })); // {"a":{"n":1},"b":{"n":1}} — duplicated, not circular (clone)

const deep = { a: { b: {} } }; deep.a.b.c = deep.a; // deep cycle via ancestor
try { JSON.stringify(deep); } catch (e) { console.log("deep:", e.message.slice(0,45)); }

// Manual guard that returns sentinel instead of throwing
function stringifyNoThrow(v) {
  const seen = new WeakSet();
  return JSON.stringify(v, function(k, val) {
    if (typeof val === "object" && val !== null) {
      if (seen.has(val)) return "[Circular]";
      seen.add(val);
    }
    return val;
  });
}
const c = { x: 1 }; c.c = c;
console.log(stringifyNoThrow(c)); // {"x":1,"c":"[Circular]"}
```

### 2) **Copy-by-JSON antics — what parse/stringify round-trip silently changes**

**Definition** — `JSON.parse(JSON.stringify(x))` omits non-enumerable/`undefined`/`function`/`symbol` keys, collapses holes to `null`, turns `Date`→ISO string, empty-represents `Map`/`Set`/`RegExp`, and collapses `Infinity`/`NaN`→`null` (see [2.1](<../2. Stringifying and serialization/2.1. What JSON.stringify serializes and what it drops.md>)). It also strips prototype and descriptors (accessors become data).

```js
const original = {
  keep: 1,
  gone1: undefined,
  gone2() {},
  [Symbol("s")]: 2,
};
Object.defineProperty(original, "hidden", { value: 3, enumerable: false });
original.arr = [1, , 3]; // hole
original.date = new Date("2026-01-01T00:00:00.000Z");
original.map = new Map([[1,2]]);
original.inf = Infinity;

const clone = JSON.parse(JSON.stringify(original));
console.log(clone); // { keep:1, arr:[1,null,3], date:"2026-01-01T00:00:00.000Z", map:{}, inf:null } — gone1/gone2/symbol/hidden absent
console.log(typeof clone.date); // string — not Date
console.log(original.arr.length, clone.arr.length, Object.hasOwn(clone.arr,"1")); // 3 3 true — hole became true
console.log(Object.getOwnPropertyDescriptor(clone, "hidden")); // undefined

// Getter becomes plain data
const withGetter = { get x() { return 1; }, y: 2 };
console.log(JSON.parse(JSON.stringify(withGetter))); // { x:1, y:2 } — accessor collapsed to data
```

- **Modern guidance** — never use JSON round-trip as a *general* deep clone; see [5.1](<../5. Beyond JSON structuredClone and data exchange/5.1. structuredClone deep cloning and limitations.md>) for `structuredClone` which preserves `Date`/`Map`/`Set`/holes/cycles correctly.

### 3) **Holes vs null — round-trip densifies sparse arrays**

**Definition** — Sparse holes `[,]` serialize as `null` (spec: hole → `null` via `undefined`→`null` array rule) and parse back as `null` values (dense, with own property `true`), so `Object.hasOwn(arr,"1")` flips from `false` to `true`.

```js
const sparse = [1, , 3, , 5]; // two holes
console.log(sparse.length, Object.hasOwn(sparse,"1"), Object.hasOwn(sparse,"3")); // 5 false false
console.log(JSON.stringify(sparse)); // [1,null,3,null,5]
const dense = JSON.parse(JSON.stringify(sparse));
console.log(dense.length, Object.hasOwn(dense,"1"), dense[1]); // 5 true null — now own property, not hole
console.log(dense); // [1, null, 3, null, 5] — dense

// Array with explicit undefined (same wire result but different source)
console.log(JSON.stringify([1, undefined, 3])); // [1,null,3] — same as hole

// structuredClone preserves holes distinctly (contrast)
const cloned = structuredClone(sparse);
console.log(cloned.length, Object.hasOwn(cloned,"1"), cloned[1]); // 5 false undefined — hole preserved
```

### 4) **Common confusion**

- "`Duplicate reference throws circular`" — no: only *ancestor* cycles throw; sibling duplicates are serialized twice (identity not preserved — two distinct clones).
- "`JSON clone preserves Dates`" — no: dates become strings; `instanceof Date` after round-trip is `false` without reviver.
- "`Holes survive JSON round-trip`" — no: holes become `null` and become own properties.
- "`Map/Set clone via JSON`" — `JSON.stringify(new Map)` → `"{}"` → `JSON.parse` → `{}` — map shape lost; use `structuredClone` or `[...map]` array.

### 5) **Performance note**

Round-trip `JSON.parse(JSON.stringify(x))` does two full traversals plus string allocation + parsing — O(n) with large constant; `structuredClone(x)` is a single structured-clone pass in C++ without intermediate string and preserves more types (see [5.1](<../5. Beyond JSON structuredClone and data exchange/5.1. structuredClone deep cloning and limitations.md>)). Avoid `JSON.stringify` for clone inside loops; measure with `performance.now` for 10k objects — `structuredClone` is typically 2–5× faster for medium graphs and supports cycles.

### 6) **Mentor note**

Have juniors predict `JSON.stringify([1,,3])` vs `JSON.stringify([1,undefined,3])` (both `[1,null,3]`) and `Object.hasOwn(JSON.parse(JSON.stringify([1,,3])),"1")` (`true`) vs `structuredClone([1,,3])` (`false`). In review, flag every `JSON.parse(JSON.stringify(x))` used as clone where `x` may contain `Map`/`Set`/`Date`/hole — require `structuredClone` with explicit fallback comment.
