## 9.1. Boundaries what is covered elsewhere

### 1) **Enumerable order, descriptors, and prototype pollution full treatment — Objects in Depth**

The complete story of *why* only enumerable own string keys serialize — `enumerable` vs non-enumerable, `configurable`/`writable`, `getOwnPropertyDescriptor`, `Object.keys` vs `Reflect.ownKeys`, `OrdinaryOwnPropertyKeys` order (integers ascending → strings insertion → symbols), and how `__proto__` wiring via `Object.create(null)` vs literal `__proto__` alias prevents pollution — lives in [Objects in Depth](<../../../06 Objects in Depth/README.md>) (specifically [enumerability and enumeration order](<../../../06 Objects in Depth/sections/2. Properties and descriptors/2.3. Enumerability enumeration order and for-in mechanics.md>) and [creation patterns literal vs Object.create](<../../../06 Objects in Depth/sections/1. Object creation and literals/1.2. Creation patterns literal Object create and constructors.md>)). This domain only applies that filter to `JSON.stringify`'s walk.

### 2) **BigInt/Symbol type gate, ToPrimitive, and coercion tables — Values Types and Coercion**

Why `BigInt` never coerces implicitly (`1n + 1` → `TypeError`) and why `Symbol` throws on `String` coercion, the exact `ToPrimitive`/`ToString`/`ToNumber` tables, and the `BigInt` literal/safe-integer boundary (`MAX_SAFE_INTEGER` 2^53−1) live in [Values Types and Coercion](<../../../03 Values Types and Coercion/README.md>) ([Eight types](<../../../03 Values Types and Coercion/sections/1. The value model/1.1. Eight types two families primitives vs objects.md>) and [BigInt](<../../../03 Values Types and Coercion/sections/5. The exotic primitives Symbol and BigInt/5.2. BigInt integers beyond MAX_SAFE_INTEGER.md>)). Here we only own the *JSON-specific* consequence: `BigInt` stringifies via `TypeError` (no implicit), `Symbol` is omitted.

### 3) **Array holes/sparse, length, TypedArray/ArrayBuffer — Arrays**

What a *hole* is (`Object.hasOwn(arr,"1") === false` vs `undefined` own), how `length` auto-grows/truncates, why `map`/`forEach` skip holes while `JSON.stringify` nullifies them, and why `TypedArray` serializes as plain objects (`{"0":1}`) vs `Array` — lives in [Arrays](<../../../08 Arrays/README.md>) ([Holes vs undefined](<../../../08 Arrays/sections/2. Holes sparsity and length/2.1. Holes vs undefined sparse arrays and empty slots.md>) and [ArrayBuffer TypedArray](<../../../08 Arrays/sections/5. Transforming ordering and typed preview/5.3. ArrayBuffer TypedArray and DataView how they differ from Array.md>)). `structuredClone` hole preservation is contrasted here; general hole mechanics are not re-taught.

### 4) **Numbers IEEE-754, safeInteger, Epsilon, Temporal/Intl — Numbers Dates Math and Temporal**

The IEEE-754 model (`-0` sign erasure vs `Object.is`, `NaN`/`Infinity`, `MAX_SAFE_INTEGER` collapse, `EPSILON`, `Math.fround`), `Date` legacy mutability/DST, and `Temporal` migration live in [Numbers Dates Math and Temporal](<../../../12 Numbers Dates Math and Temporal/README.md>) ([Number primitives](<../../../12 Numbers Dates Math and Temporal/sections/1. Number model/1.1. Number primitives IEEE-754 NaN Infinity and negative zero.md>) / [Safe integers](<../../../12 Numbers Dates Math and Temporal/sections/1. Number model/1.2. Safe integers BigInt boundary epsilon and precision.md>) / [Legacy Date](<../../../12 Numbers Dates Math and Temporal/sections/4. Legacy Date/4.1. Legacy Date creation mutability and parsing pitfalls.md>)). This domain only owns the JSON-visible residues: `-0`→`0`, `NaN`/`Infinity`→`null`, `Date#toJSON`→ISO.

### 5) **Strings UTF-16 well-formedness, iterables/async iteration, modules JSON import, error handling**

String UTF-16 well-formedness (`isWellFormed`/`toWellFormed`, lone surrogate `\uD800` → `"\ud800"`), template literal `String.raw` live in [Strings and Regular Expressions](<../../../11 Strings and Regular Expressions/README.md>). Iterator/Generator/async-iterable streaming that powers NDJSON `for await` lives in [Iterables Generators and Async Iteration](<../../../10 Iterables Generators and Async Iteration/README.md>) and [Async Event Loop and Promises](<../../../13 Async Event Loop and Promises/README.md>). Module-time JSON loading `import data from "./x.json" with {type:"json"}` (static, `with` vs deprecated `assert`) lives in [Modules and Code Organization 4.2](<../../../14 Modules and Code Organization/sections/4. Dynamic import and meta/4.2. import.meta import attributes and JSON modules.md>). `SyntaxError` taxonomy, `cause` chaining, and stack hygiene live in [Error Handling and Debugging](<../../../15 Error Handling and Debugging/README.md>). Collections `Map`/`Set`/`WeakRef` semantics not re-taught here — see [Collections](<../../../09 Collections Map Set and Weak References/README.md>).
