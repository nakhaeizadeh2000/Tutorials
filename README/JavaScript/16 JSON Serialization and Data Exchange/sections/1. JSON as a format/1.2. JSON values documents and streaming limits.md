## 1.2. JSON values documents and streaming limits

### 1) **Document rules — one value and UTF-8/UTF-16**

**Definition** — RFC 8259: a *JSON text* is a single JSON *value* (`object`/`array`/`string`/`number`/`true`/`false`/`null`). JSON text must be UTF-8 (on the wire) and `JSON.parse` accepts UTF-16 JS strings. Historically some parsers required top-level object/array; RFC now allows any value (`JSON.parse('"hi"')` and `JSON.parse('42')` are legal).

```js
// RFC-legal top-level values — not only objects/arrays since RFC 8259
console.log(JSON.parse('"hi"')); // hi — string document
console.log(JSON.parse('42')); // 42
console.log(JSON.parse('null')); // null — valid document
console.log(JSON.parse('true')); // true

// One value per parse — NDJSON (newline-delimited) is multiple JSON texts, not one
const ndjson = '{"id":1}\n{"id":2}\n';
console.log(ndjson.trim().split("\n").map(l => JSON.parse(l))); // [ {id:1}, {id:2} ]
try { JSON.parse(ndjson); } catch (e) { console.log("ndjson one-shot →", e.name); } // SyntaxError — extra data

// Wire must be UTF-8 — local JS string is UTF-16; lone surrogates round-trip via \uXXXX
console.log(JSON.stringify("\uD800")); // "\ud800" — lone surrogate escaped as code unit (well-formedness deferred)
console.log(JSON.parse('"\\ud800"').charCodeAt(0).toString(16)); // d800
```

- **Modern guidance** — emit one value per response body with `Content-Type: application/json; charset=utf-8`; for streams use NDJSON/JSONL (`Content-Type: application/x-ndjson`) and parse per line.

### 2) **String escapes — the seven escapes and `\uXXXX`**

**Definition** — JSON strings are double-quoted with escapes: `\"` `\\` `\/` `\b` `\f` `\n` `\r` `\t` and `\u` + 4 hex digits. `/` may be escaped (`\/`) but need not be. Bare control characters (`U+0000–U+001F`) must be escaped — raw newline in string is `SyntaxError`.

```js
console.log(JSON.parse('"\\" \\\\ \\/ \\b \\f \\n \\r \\t"')); // "\" \ / \b \f \n \r \t" — seven escapes
console.log(JSON.parse('"\\u0041"')); // A — \u hex escape
console.log(JSON.parse('"\\uD83D\\uDE00"')); // 😀 — surrogate pair via two \u escapes
// Raw control char is illegal
try { JSON.parse('"\n"'); } catch (e) { console.log("raw newline →", e.name); } // SyntaxError
try { JSON.parse('"\t"'); } catch (e) { console.log("raw tab →", e.name); } // SyntaxError — must be \t

// Stringify always escapes controls and quotes for valid round-trip
console.log(JSON.stringify("a\"b\nc\td")); // "a\"b\nc\td" — \n \t and \" escaped
console.log(JSON.stringify("x\u0000y")); // "x\u0000y" — U+0000 → \u0000
```

- **Why it matters** — hand-building JSON with string concat fails to escape `"`/`\`/controls → injection/`SyntaxError`. Use `JSON.stringify`.

### 3) **Size and shape trade-offs — text vs binary**

**Definition** — JSON is textual, human-readable, self-describing but verbose (keys repeat per object) and has no native binary/typed-array support. Large payloads (arrays of 100k objects) are memory heavy as both text + parsed graph. Compression (gzip/brotli) helps; binary supplements (base64 for bytes) add ~33% expand.

```js
// Verbosity — repeating keys
const rows = Array.from({ length: 3 }, (_, i) => ({ id: i, name: `n${i}`, active: true }));
console.log(JSON.stringify(rows).length); // ~78 chars for 3 rows — keys per object repeat
console.log(JSON.stringify(rows).slice(0, 50)); // [{"id":0,"name":"n0","active":true},{"id":1,"name":...

// Size check before buffering 100 MB
const big = { data: "x".repeat(50_000) }; // 50KB
console.log(Buffer.byteLength(JSON.stringify(big), "utf8")); // ~50011 bytes — measure wire size via byteLength

// Binary — raw bytes must be encoded; JSON cannot embed Uint8Array directly (see 5.2)
const bytes = new Uint8Array([0, 255, 1]);
console.log(JSON.stringify({ bytes })); // {"bytes":{"0":0,"1":255,"2":1}} — plain object surprise (index keys as strings)
console.log(JSON.stringify({ bytes: [...bytes] })); // {"bytes":[0,255,1]} — array form explicit
```

- **Modern guidance** — for >10 MB or 100k row datasets prefer NDJSON streaming or binary format (MessagePack/CBOR) — one-shot `JSON.parse` on 100 MB allocates a matching object graph and can OOM.

### 4) **When JSON is not enough — preview of §5**

**Definition** — JSON cannot natively represent: `undefined`/`function`/`Symbol` (dropped), `BigInt` (throws), circular graphs (throws), `Map`/`Set`/`Date` shapes (Date → string, Map/Set → `{}`), `ArrayBuffer` bytes, or precision beyond `2^53`. Those require a complement: `structuredClone` for in-process cloning, stringly-typed IDs for 64-bit, `base64` for bytes, or a schema’d format.

```js
// JSON coverage gaps (detail in §2.1 / §4.2 / §5.1)
console.log(JSON.stringify({ m: new Map([[1,2]]) })); // {"m":{}} — Map becomes {}
console.log(JSON.stringify({ s: new Set([1,2]) })); // {"s":{}} — Set becomes {}
console.log(JSON.stringify({ d: new Date("2026-01-01T00:00:00.000Z") })); // {"d":"2026-01-01T00:00:00.000Z"} — Date → ISO string
try { console.log(JSON.stringify({ b: 9007199254740993n, f() {}, s: Symbol("x") })); } catch (e) { console.log("BigInt+func+symbol →", e.name); }
try { JSON.stringify({ b: 9007199254740993n }); } catch (e) { console.log("BigInt →", e.name); } // TypeError
```

### 5) **Common confusion**

- "`JSON must be an object`" — outdated (RFC 4627); RFC 8259 and `JSON.parse` allow any value on top level.
- "`JSON can have comments/trailing commas like JS`" — never; use a different format for config (JSONC/JSON5) and strip before `parse`.
- "`NDJSON is valid JSON`" — no; it is *multiple* JSON values delimited by `\n`; `JSON.parse(manyLines)` throws — parse per line.
- "`\uXXXX` escapes preserve lone surrogates badly`" — `JSON.stringify("\uD800")` → `"\ud800"`; `JSON.parse` recovers the same code unit, but the result is an ill-formed string (`isWellFormed() === false`) — see [Strings 1.1](<../../../11 Strings and Regular Expressions/sections/1. String model/1.1. String primitives immutability UTF-16 and well-formedness.md>).

### 6) **Performance note**

Parsing NDJSON by `split("\n").map(JSON.parse)` allocates `lines.length + 1` arrays plus each object — for 1M lines that spikes GC. Stream: `readline` + per-line `parse` with backpressure (or `for await` over stream) keeps memory bounded. `JSON.stringify` of objects with many identical keys benefits from `replacer` filtering before serialization to avoid building a megastring then dropping it.

### 7) **Mentor note**

Have juniors hand-predict which strings are valid JSON: `'{a:1}'`, `'{"a":1,}'`, `'"\\uD800"'`, `'42'`. Review rule: any `JSON.parse` of network input must be `try/catch` + shape validation; raw NDJSON body `JSON.parse(body)` is a `SyntaxError` trap (split first).
