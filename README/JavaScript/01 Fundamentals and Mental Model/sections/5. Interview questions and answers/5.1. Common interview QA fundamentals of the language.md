## 5.1. Common interview Q&A: fundamentals of the language

### 1) **Q&A**

1. **Q: What's the difference between JavaScript and ECMAScript?**
   **A:** ECMAScript (ECMA-262) is the standardized language specification maintained by TC39; JavaScript is the trademarked name under which engines implement it. Hosts add platform APIs beyond the spec.

2. **Q: Is Node.js a framework or a language?**
   **A:** Neither — it's a runtime: V8 (engine) plus platform APIs (`fs`, `net`, `process`). The language executed is the same ECMAScript as in browsers.

3. **Q: Why does `typeof null === "object"`? Can it be fixed?**
   **A:** A first-version implementation artifact (type tags). It cannot change — web compatibility freezes observable behavior — so we avoid relying on `typeof` for null checks (`x === null`).

4. **Q: Is JavaScript single-threaded?**
   **A:** Your JS code runs on one thread per realm with run-to-completion semantics. Concurrency comes from the host's event loop and platform threads (I/O behind the scenes); real parallel JS requires Workers with no shared state.

5. **Q: Predict output: sync log, `setTimeout(fn, 0)` log, resolved-promise `.then` log — in source order?**
   **A:** Sync logs first; then the promise reaction (microtask queue drains after the current task); then the timer callback (next macrotask). Zero delay doesn't jump queues.

6. **Q: What does "dynamically typed" mean, and what risk does it create?**
   **A:** Types belong to values, not variables/bindings; mistakes surface at runtime. Mitigate with boundary validation, linting/type-checking tools, and tests.

7. **Q: What does strict mode actually change?**
   **A:** No implicit globals (throws instead), silent failures throw (`TypeError` on non-writable writes), bare-call `this` stays `undefined`, stricter syntax rules. Modules and classes are always strict.

8. **Q: When do you need Babel/polyfills today?**
   **A:** Only when your support matrix includes targets older than the features you ship — server-side on modern Node LTS needs neither; public web apps transpile down to a *written-down* baseline floor.

9. **Q: What is TC39 stage 3 vs stage 4?**
   **A:** Stage 3 = candidate: design done, awaiting implementation feedback — may still change or be dropped. Stage 4 = finished, merged into the next annual edition (each June).

10. **Q: Where do `setTimeout` and `fetch` come from if they're not in the language?**
    **A:** They're host APIs provided by the runtime/browser (with different guarantees per host). The language itself defines promises/async-await but no timers or networking.

### 2) **Grading guidance (mentor note)**

- Strong candidates separate *language / engine / runtime / host API* without prompting (questions 2, 10).
- Question 5 separates memorizers from understanders: ask "why?" and expect the words "microtask queue drains before macrotasks".
- Red flag: answering question 6 with "TypeScript fixes it" — TS is a compile-time layer (own track); the runtime stays dynamic either way.
