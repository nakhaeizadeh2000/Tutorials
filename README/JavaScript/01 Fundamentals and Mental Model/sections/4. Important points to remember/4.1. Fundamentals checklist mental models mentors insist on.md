## 4.1. Fundamentals checklist (mental models mentors insist on)

### 1) **The checklist**

1. **Name the layers correctly** (language = ECMAScript spec; engine = V8/SpiderMonkey/JSC; runtime = engine + platform APIs; host API ≠ language built-in). Misattribution here wastes debugging hours.
2. **Two different availability questions** (is it *standardized*? is it *shipped on our targets*?) — answer both before adopting any API ([1.3](<../1. What JavaScript is/1.3. The TC39 process stages and how to read MDN vs the spec.md>)).
3. **Quirks are permanent residents** (`typeof null`, sloppy-mode globals, ASI) — route around them with lint rules and strict contexts; never wait for removal ([1.1](<../1. What JavaScript is/1.1. From LiveScript to ECMAScript history editions and legacy quirks.md>)).
4. **One thread, run-to-completion** (nothing preempts synchronous code; long loops block everything) — responsiveness is a scheduling problem you solve by yielding ([2.1](<../../sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md>), [2.3](<../../sections/2. How JavaScript executes/2.3. Event loop overview tasks microtasks and scheduling preview.md>)).
5. **Microtasks drain before macrotasks** — the single most useful ordering fact for predicting logs and race conditions.
6. **Types ride values, errors arrive late** — dynamic typing moves failures from compile time to production time; boundary validation is mandatory, not optional polish ([2.2](<../../sections/2. How JavaScript executes/2.2. Dynamic typing late binding and their consequences.md>)).
7. **Strict mode by default** (modules/classes are always strict) — new sloppy code is a defect, full stop ([3.3](<../../sections/3. Running JavaScript today/3.3. Strict mode sloppy mode and modern defaults.md>)).
8. **Support matrix in writing** (which engines/runtimes, which floor) — transpilers and polyfills serve the matrix, never replace the decision ([3.4](<../../sections/3. Running JavaScript today/3.4. Transpilation polyfills and baseline strategy.md>)).
9. **Know your runtime version** (Node 24 active LTS era as of Aug 2026) — pin it, feature-detect around it, upgrade deliberately.

### 2) **How to use this list**

- Junior: memorize items 1, 5, 6 — they explain most early confusion.
- Senior: audit your team's repos against 7–9; these are cheap wins with outsized payoff.
- Mentor: use items as review questions when onboarding — each maps to a leaf that teaches it fully.
