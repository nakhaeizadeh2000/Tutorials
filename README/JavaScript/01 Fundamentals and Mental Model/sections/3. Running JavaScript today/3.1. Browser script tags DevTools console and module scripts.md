## 3.1. Browser script tags, DevTools console, and module scripts

*(Browser-host content: examples are HTML/console snippets, not Node-runnable — labeled as such.)*

### 1) **Classic vs module scripts**

| Form | Parsing | Execution timing | Order | Top-level scope |
|------|---------|------------------|-------|-----------------|
| `<script src="a.js">` | blocks parsing | immediately when fetched | guaranteed | global |
| `<script defer src="a.js">` | doesn't block | after parsing, before `DOMContentLoaded` | guaranteed | global |
| `<script async src="a.js">` | doesn't block | as soon as fetched | **not ordered** | global |
| `<script type="module" src="m.js">` | doesn't block | deferred | import order | module-local |

```html
<script src="legacy.js"></script>          <!-- blocks rendering -->
<script defer src="app.js"></script>       <!-- ordered, runs pre-DOMContentLoaded -->
<script type="module" src="main.js"></script> <!-- modern default choice -->
```

- Module scripts additionally get: strict mode always, one-time evaluation even if imported twice, and `import`/`export` syntax.

### 2) **DevTools console is a REPL with superpowers**

- Great for probing APIs live; supports multiline editing, `await` at top level (async console context).
- **Subtle traps vs real page code**: the console wraps evaluation (its own scope/realm quirks), auto-formats results, and history re-runs in current context. Confirm surprising findings by writing an actual script file.

### 3) **Placement still matters**

- End-of-body classic script ≈ defer for DOM availability, but defer/module also work in `<head>` and preserve order cleanly.
- `async` suits independent analytics/beacons; use it only when order truly doesn't matter.
- **Modern guidance**: default to `type="module"` for application code; reserve classic+defer for legacy glue.

### 4) **Common confusion**

- In modules, top-level `this` is `undefined` (not `window`) — classic scripts bind it to the global.
- Inline module scripts still defer — inline *classic* scripts run immediately.
- Two imports of the same module URL evaluate once; two classic `<script>` tags of the same URL evaluate twice.

### 5) **Mentor note**

Teach the table, then make students justify a choice for three scenarios: app entry point (module), third-party beacon (async), polyfill that must precede app code (classic blocking or module imported first). Placement decisions become trivial once timing/order/scope are explicit.
