## 2.3. Event loop overview (tasks, microtasks — scheduling preview)

### 1) **Run-to-completion tasks**

**Definition** — the event loop is the host's scheduler: it repeatedly picks a queued *task* (callback from timers, events, I/O completions…) and runs it to completion. Nothing preempts your synchronous code.

- While a task runs, no other task starts — an infinite loop in your code freezes the page/process.
- This single-threaded discipline is why you never need locks for ordinary shared state in JS.

### 2) **Microtasks drain after every task**

There are two kinds of scheduled work, and the difference explains almost every "why did this log here?" surprise:

- **Macrotasks (tasks)**: timer callbacks, I/O, UI events — one per loop turn.
- **Microtasks**: promise reactions, `queueMicrotask`, MutationObserver — **all of them drain** after the current task finishes (and between tasks), before timers/rendering get their turn.

```js
// Run me with node — predict the output before executing:
console.log("1 sync");

setTimeout(() => console.log("4 timer"), 0);

Promise.resolve().then(() => console.log("3 microtask"));

console.log("2 sync end");

// Output:
// 1 sync
// 2 sync end
// 3 microtask   ← microtask queue drains first
// 4 timer       ← then the next macrotask runs
```

- `setTimeout(fn, 0)` does not mean "immediately": it means "queue a macrotask, minimum delay 0" — every pending microtask and already-queued task may run first.

### 4) **Common confusion**

- "Zero timeout = zero wait" — no; delay is a *minimum*, and ordering vs other queues follows the rules above.
- "Promises run in parallel" — reactions run sequentially on this same thread; parallelism needs Workers/platform threads.
- "The async function before any `await` executes synchronously" — correct, and crucial for reasoning about the log order above.

### 5) **Mentor note**

Use the snippet above in interviews and teaching verbatim: candidates who can explain the three-step order understand the loop; those who say "it's random" reveal they've been guessing. Follow up with: "what happens if the microtask schedules another microtask?" (answer: it drains too — unbounded microtask chaining starves macrotasks).
