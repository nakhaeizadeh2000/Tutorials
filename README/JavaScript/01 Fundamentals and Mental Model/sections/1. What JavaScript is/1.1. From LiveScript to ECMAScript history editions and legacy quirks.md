## 1.1. From LiveScript to ECMAScript (history, editions, and why legacy quirks persist)

### 1) **JavaScript ≠ ECMAScript**

**Definition** — ECMAScript is the *language standard* published as ECMA-262 by Ecma International. JavaScript is the name under which engines (V8, SpiderMonkey, JavaScriptCore) implement that standard; it was a marketing decision, not a technical one.

- **History in one paragraph**: created in 1995 by Brendan Eich at Netscape in roughly ten days as "Mocha", shipped as LiveScript, renamed JavaScript to ride Java's hype. Microsoft reverse-engineered it as JScript; to stop the fragmentation, Netscape submitted the language to ECMA, producing the first ECMAScript edition in 1997.
- **What this means practically**: when you argue about "what JavaScript does", the arbiter is the ECMAScript specification — plus each host's documented extensions (the DOM spec, Node's API docs).

### 2) **Editions matter (annual cadence since ES2015)**

- ES1–ES3: 1997–1999. Then a decade-long freeze (the abandoned ES4 effort nearly killed the process).
- ES5 (2009): strict mode, JSON support, `Object.defineProperty`.
- ES2015 ("ES6"): the big bang — `let`/`const`, classes, modules, promises, generators, arrow functions.
- Since 2015: one edition per year, ratified each June (ES2026 was ratified June 30, 2026). Features are grouped by *calendar*, not by theme.

**Modern guidance** — refer to editions by year ("ES2024"), not by informal numbers above 6. When advice depends on a feature's arrival, label it like this track does: "as of ES2026 era".

### 3) **Quirks are contractual (web compatibility freezes mistakes)**

The web cannot break: billions of pages depend on exact behaviors, so bugs become features of the platform.

```js
// The most famous frozen bug:
console.log(typeof null); // "object" — a 1995 implementation artifact, never fixable

// Another survivor: implicit global creation only in sloppy mode (see 3.3)
function f() { undeclared = 42; }
f();
console.log(undeclared); // 42 — worked in 1996, must work forever in sloppy mode
```

- **Why not remove them?** Removing `typeof null === "object"` would break pages that (accidentally or deliberately) rely on it. The spec quarantines such behaviors in Annex B ("Web Legacy Compatibility") rather than pretending they don't exist.
- **Modern guidance**: don't wait for fixes that will never come — ban quirks mechanically with lint rules (`eqeqeq`, `no-implicit-globals`, `valid-typeof`) and prefer strict-mode contexts where several quirks simply don't exist.

### 4) **Common confusion**

- "ES6 and ES2015 are different things" — they are the same edition; the committee switched from ordinal to annual naming at that release.
- "JScript is Microsoft's dialect today" — irrelevant since ~IE11; all modern engines target ECMA-262 directly.
- "Annex B features are deprecated" — they are *legacy-required* for web hosts; some don't exist in non-browser hosts at all.

### 5) **Mentor note**

Teach history as *causation*, not trivia: students who know that `==` coercion rules predate any standardization, and that ASI exists because of 1995 error-tolerance goals, stop treating quirks as random hostility and start treating them as load-bearing decisions you route around deliberately.
