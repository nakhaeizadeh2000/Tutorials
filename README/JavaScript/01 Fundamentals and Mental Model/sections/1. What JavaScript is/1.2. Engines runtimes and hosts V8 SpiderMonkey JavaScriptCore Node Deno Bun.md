## 1.2. Engines, runtimes, and hosts (V8, SpiderMonkey, JavaScriptCore; browsers, Node.js, Deno, Bun)

### 1) **Engine executes the language**

**Definition** — a JavaScript *engine* is the virtual machine that implements ECMA-262: it parses your code, JIT-compiles it, manages memory, and provides the language's built-in objects (`Object`, `Array`, `JSON`, `Math`, …).

| Engine | Powers |
|--------|--------|
| V8 | Chrome, Edge, Node.js, Deno |
| SpiderMonkey | Firefox |
| JavaScriptCore (JSC) | Safari, Bun |

- Everything in this track's "language" domains behaves identically across engines — conformance is enforced by the test262 suite.

### 2) **Runtime adds the platform**

An engine alone can't read files or talk to networks. A *runtime* (or *host*) embeds an engine and adds platform APIs:

```js
// Language built-ins — same in every engine:
console.log(JSON.parse('{"a":1}').a); // 1

// Host APIs — exist only where the runtime provides them:
console.log(typeof window);  // browser: "object", Node.js: "undefined"
console.log(typeof process); // Node.js: "object",   browser: "undefined"
console.log(typeof fetch);   // modern browsers AND Node 18+: "function"
```

- Browsers add: DOM, `window`, events, storage, WebAssembly host bindings, etc.
- Node.js adds: `fs`, `net`, `http`, `process`, `Buffer`, etc.
- Deno/Bun re-pair engines and APIs differently (Deno: V8 with web-aligned APIs; Bun: JavaScriptCore).

### 3) **Separate language errors from host errors**

Debugging skill starts with attribution:

- `ReferenceError: foo is not defined`, `TypeError: Cannot read properties of undefined` → *your JavaScript* logic; identical on every platform.
- `ReferenceError: require is not defined` (in ESM), missing `document` in Node → you assumed a *host capability* that doesn't exist there.
- **Modern guidance**: feature-detect capabilities (`typeof fetch === "function"`), never sniff environments by name.

### 4) **Common confusion**

- "Node.js is a language / framework" — neither; it's a runtime embedding V8.
- "`setTimeout` is part of JavaScript" — no; it's a host API (browsers *and* Node provide one, with different guarantees). The language itself has no timers — scheduling enters via the event loop the host implements.
- "V8 features = JavaScript features" — flags like `--harmony-*` expose unfinished proposals; don't teach them as the language.

### 5) **Performance note**

For pure-language code, cross-engine performance differences are usually noise compared to algorithmic complexity. What differs dramatically between hosts is I/O and platform API cost (DOM operations vs syscalls) — optimize at that boundary first.

### 6) **Mentor note**

When a student reports "JavaScript is broken because X doesn't exist", make them classify X: language built-in (check their runtime version), host API (check which host they're in), or proposal (check TC39 stage). That classification habit prevents hours of misdirected debugging.
