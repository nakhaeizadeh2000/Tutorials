## 6.1. Boundaries: what is covered elsewhere

This domain is the *map* of the language world. It deliberately stops at these borders:

1. **DOM and browser platform APIs** (`document`, events, storage, Web APIs) — belong to a future **Web Platform track**; only script-tag loading mechanics appear here ([3.1](<../3. Running JavaScript today/3.1. Browser script tags DevTools console and module scripts.md>)).
2. **Node.js host APIs** (`fs`, `net`, `http`, streams, workers) — belong to a future **Node.js track**; only running files/version discipline appears here ([3.2](<../3. Running JavaScript today/3.2. Node.js essentials running files REPL and version discipline.md>)).
3. **TypeScript, JSDoc typing systems, bundler internals** — future **Tooling/TypeScript tracks**; only their conceptual role in compensating dynamic typing appears here ([2.2](<../2. How JavaScript executes/2.2. Dynamic typing late binding and their consequences.md>), [3.4](<../3. Running JavaScript today/3.4. Transpilation polyfills and baseline strategy.md>)).
4. **Async/promises deep dive** (await semantics, combinators, cancellation, Node loop phases, starvation) — [Async Event Loop and Promises](<../../../13 Async Event Loop and Promises/README.md>); this domain only previews queue ordering ([2.3](<../2. How JavaScript executes/2.3. Event loop overview tasks microtasks and scheduling preview.md>)).
5. **Values/types/coercion mechanics** (ToNumber/ToString algorithms, boxing wrappers, symbol/bigint details) — **Values, Types, and Coercion domain**; this domain stays at the mental-model level.
6. **JIT internals and performance methodology** (hidden classes, inline caches, profiling tools) — **Performance and JIT Mindset domain**; here only the pipeline exists so later advice has something to attach to.

If you find yourself writing DOM code examples, Node stream tutorials, or coercion tables inside this domain — stop; that content belongs to the neighbor, link instead.
