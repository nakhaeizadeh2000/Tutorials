## 7.1. Real production bugs caused by performance mistakes

### 1) **Polymorphic hot call — one helper fed three shapes drops 40 % throughput**

A request handler called `measure(item)` where `item` could be three literal orders from three factories. The `item.x` IC site became megamorphic; TurboFan never inlined `measure`, and p95 rose 35–45 % under load. Fix: normalize at the boundary (`makeItem` factory with one order) and split call sites per shape or add a fast-path `if (item.type === "a") measureA(item)` monomorphic dispatch.

```js
function makeItem(kind, v) { return { kind, v }; } // one shape
function measureA(o) { return o.v * 2; } // monomorphic site A
function measureB(o) { return o.v * 3; } // monomorphic site B
const items = [makeItem("a", 10), makeItem("b", 20)];
// GOOD: dispatch outside the hot loop keeps each site monomorphic.
function sumGood(arr) { let s = 0; for (const it of arr) s += it.kind === "a" ? measureA(it) : measureB(it); return s; }

// BAD: one helper sees two kinds' maps at same o.v read → polymorphic.
function measureAny(o) { return o.v * (o.kind === "a" ? 2 : 3); }
function sumBad(arr) { let s = 0; for (const it of arr) s += measureAny(it); return s; }
console.log(sumGood(items), sumBad(items)); // same math, different IC discipline
console.log("BAD polymorphic site at o.v + o.kind — profile shows IC miss");
```

### 2) **`delete` turning a hot map into dictionary mode — latency cliff after a feature flag**

A session cache stored `session.token` and `session.user` as offset slots. A new "logout cleanup" did `delete session.token` on every sign-out. Session objects went dictionary mode; subsequent `session.user` reads on the hot auth path became hash probes and latency jumped from 2 ms to 12 ms median. Fix: sentinel — `session.token = null` (or `session = { ...session, token: null }` to keep shape via new map copy) and document "never `delete` hot objects" in review guide.

```js
const session = { token: "tok", user: "ana" };
console.log(session.user); //  ana — offset load while fast mode
delete session.token;              // → dictionary mode (engine-hint)
console.log("token" in session, session.token); // false undefined — hash backed now
const fixed = { token: "tok", user: "ana" };
fixed.token = null; // stays offset, no deopt
console.log(fixed.token, fixed.user); // null ana — preferred sentinel
```

### 3) **Holey `PACKED` → `DICTIONARY` after sparse push — iteration regresses from vector to hash**

API pagination returned sparse pages stitched via `out[idx]=page[i]` with holes. Downstream `items.forEach` and `for...of` became holey/`DICTIONARY` iteration; throughput halved and `structuredClone` retained holes as `null` (vs `filter` densify) causing subtle data bugs. Fix: densify at producer (`Array.from({length: total}, (_,i)=>pages[i] ?? sentinel)` or push densely in order) and enforce dense `PACKED_SMI` for hot loops; use `TypedArray` where binary.

```js
const sparse = [];
sparse[0] = 1; sparse[100] = 2; // HOLEY + DICTIONARY widening — small but typed array would be dense
console.log(sparse.length, 1 in sparse); // 101 false — hole, not undefined value

// BAD downstream uses holey array directly
let sumSparseBad = 0;
for (const v of sparse) sumSparseBad += v ?? 0; // visits holes as undefined, branch per iter
console.log(sumSparseBad);

// GOOD: densify at the boundary — producer fixes hole, consumer stays PACKED
const dense = sparse.filter((v) => v !== undefined);
console.log(dense.length, dense); // 2 [1,2] — dense PACKED for hot loops
let sumSparseGood = 0;
for (const v of dense) sumSparseGood += v;
console.log(sumSparseGood);
```

### 4) **Unbounded `Promise.all` fan-out and queue starvation — latency spike and OOM under load**

A cron fetched 5k URLs via `Promise.all(urls.map(fetch))`. Under load it opened 5k sockets, blew file descriptors, and starved the event loop's timer rendering with a recursive `queueMicrotask` logger that never yielded. p95 spiked to 8 s and the process OOM'd. Fix: bounded pool (`p-limit` style, 5–20 concurrent) wired with `AbortSignal` for per-batch cancellation; chunked logging with `setTimeout(0)` yielding instead of `queueMicrotask`.

```js
// BAD starvation — microtask loop never yields to timers/render
let ticks = 0;
function starveBad(n) {
  function tick() {
    if (ticks++ < n) queueMicrotask(tick); // drains exhaustively — timers starve
  }
  queueMicrotask(tick);
}
starveBad(5);
setTimeout(() => console.log("timer after starve — delayed"), 0);
console.log("starveBad queued — microtasks block the timer until drained");

// GOOD: bounded concurrency + macrotask yield
async function fetchOne(i) { return i; }
async function pooledGood(urls, limit = 3) {
  const out = [];
  let idx = 0;
  async function worker() {
    while (idx < urls.length) {
      const cur = idx++;
      if (cur >= urls.length) return;
      out[cur] = await fetchOne(urls[cur]);
      await new Promise((res) => setTimeout(res, 0)); // yield per item
    }
  }
  await Promise.all(Array.from({ length: limit }, worker));
  return out;
}
pooledGood([1, 2, 3, 4, 5], 2).then((a) => console.log("pooled", a.length));
```

### 5) **Barrel + CJS kills tree-shaking — 200 kB extra parse on every route**

A shared `lib/index.js` re-exported 30 modules via `export *` and wrapped a CJS dep (`module.exports = ...`). Every route imported one helper from the barrel but still parsed all 30 modules; entry parse slice grew 80 ms. Fix: direct ESM paths (`import { onlyA } from "./lib/a.js"`), `sideEffects: false` on pure packages, per-route `import()` chunking, and `/* #__PURE__ */` on factory calls.

```js
// Illustrative before/after — measure via metafile, not hand-waving.
console.log("BEFORE: import { onlyA } from './lib/index.js'  — 30 modules parsed");
console.log("AFTER:  import { onlyA } from './lib/a.js'      — 1 module parsed");
console.log("Chunk:  const Admin = await import('./Admin.js') — parsed only on /admin");
// Tooling: esbuild --metafile=meta.json | webpack-bundle-analyzer | vite --profile
console.log("measure metafile parse bytes before/after — see §5.2");
```
