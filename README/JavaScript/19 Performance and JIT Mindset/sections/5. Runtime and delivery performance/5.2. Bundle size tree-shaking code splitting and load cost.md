## 5.2. Bundle size tree-shaking code splitting and load cost

### 1) **Definition — the three costs in one "bundle size"**

- *Network bytes* (transfer + gzip/brotli) — what the wire charges.
- *Parse/compile time* — V8 must parse text into bytecode and compile baseline (Sparkplug) before running; this dominates cold start even when gzip looks small.
- *Evaluate/execute time* — top-level `import` evaluation, side-effectful init, and global `__proto__` or `with` pollution that widens every access.

*Tree-shaking* removes unused ESM exports when the graph has no side effects; *code-splitting* breaks the graph into route-based `import()` chunks so only the needed chunk is parsed on first navigation.

### 2) **What problem it solves / history**

Monolithic `bundle.js` (2013 Browserify/Webpack) shipped every route's code to every user — parse time grew linearly with product size. ESM (ES2015) made static import/export analyzable; Rollup (2015) and Terser/esbuild proved real shaking needed purity hints (`sideEffects: false`, `/* #__PURE__ */`). Dynamic `import()` (ES2020) and `importmap`/`exports` (Node/browsers 2021–24) enabled chunked delivery; V8's Sparkplug/Maglev tiers made parse/compile visibly separate from optimize, so cold-start regressed even when runtime stayed fast.

### 3) **Modern guidance — parse cost first, then network, then runtime**

As of 2026, Node 24/26 + V8 12–13 era:

- Prefer ESM (`"type": "module"`, `.mjs`/`type: module`, named `export`) for shakeable code; CJS `module.exports` and `export *` with side-effectful re-exports shake poorly.
- Declare `sideEffects: false` in `package.json` per package that is truly side-effect free, or list side-effectful globs; annotate factory calls like `/* #__PURE__ */ createStore()` where the bundler needs a hint.
- Split by route/feature: `const Admin = () => import("./Admin.js")` not `import Admin from "./Admin.js"` on the entry chunk; avoid barrel `index.js` that `export * from "./a"; export * from "./b"; …` — it forces every importer to parse every barrel member.
- Measure chunks: `vite --profile`, `esbuild --metafile`, `webpack-bundle-analyzer`; profile cold start with `node --cpu-prof` on `node server.js` and Chrome Performance parse slices — not just `ls -lh`.

```js
// BAD: barrel + CJS kills shaking — importer parses everything, shake can't prove purity.
// file: lib/index.js
// export * from "./a.js"; export * from "./b.js"; export * from "./heavy.js"; // heavy always parsed
// import { onlyA } from "./lib/index.js" → still parses b + heavy

// GOOD: direct ESM import + route splitting — only needed chunk parses.
// [ESM illustration — in real code: export function onlyA() { return "a"; }]
// [ESM illustration — in real code: import { onlyA } from "./lib/a.js";]
function onlyA() { return "a"; }
function onlyB() { return "b"; }
// consumer: direct path → shakeable (ESM: import { onlyA } from "./lib/a.js")
console.log(onlyA()); // b.js never loaded — shaking can remove it
console.log(onlyB()); // keep both for CJS runner

// Route chunking — static vs dynamic cost
// static: import Admin from "./Admin.js"; // parsed on entry — pay even if user never visits Admin
async function loadAdminGood() {
  // In real code: const { Admin } = await import("./Admin.js"); // chunked — parsed only when navigated
  const { Admin } = await import("data:text/javascript,export const Admin=42");
  return Admin;
}
loadAdminGood().then((Admin) => console.log(typeof Admin));

// Side-effect hint — package.json and pure annotation (illustrated as comment)
// package.json excerpt (not runtime JS):
// { "sideEffects": false }  // tells bundler "import that only reads exports is pure"
// source: const store = /* #__PURE__ */ createStore(reducer); // hint for Terser/esbuild
console.log("sideEffects:false and #__PURE__ enable shaking — illustrated, not executed here");

// Measuring — the three numbers (pseudo, run in your toolchain)
// esbuild --bundle entry.js --metafile=meta.json && cat meta.json | grep bytes
// vite build --debug && node --cpu-prof server.js  # inspect parse slice in speedscope
console.log("measure parse + eval, not just gzip");
```

### 4) **Common confusion**

- "Gzip size is the performance budget" — gzip hides parse cost: 100 kB of minified JS may gzip to 30 kB but still costs 100 kB of parse. Cold start tracks *parse bytes*, not gzip bytes.
- "Tree-shaking fixes CJS" — CJS exports are dynamic (`module.exports = …` can run any code); ESM exports are static so the graph can prove dead code. CJS shake is best-effort, often none.
- "`import()` is always slower due to waterfall" — chunked `import()` adds one network round-trip but avoids parsing the chunk at all until needed; for rarely visited routes, that's a net cold-start win even if the chunk's RTT adds a later delay. Prefetch the chunk when idle.

### 5) **Performance note**

Parse cost scales with *character count* (and AST shape) not gzip count; a 200 kB barrel adds ~20–60 ms parse on a mid-tier phone even gzipped to 60 kB — visible as a wide "Parse Script" slice in Chrome Performance before any of your code runs. Re-profile cold (`Performance` panel → `Parse` + `Compile Script` slices) before vs after removing the barrel; re-profile hot (steady-state handler `performance.now()` loop) to confirm runtime didn't regress — shaking removes dead code but shouldn't remove hot paths.

### 6) **Mentor note**

In PRs that add a dependency, require: entry chunk delta (bytes + parse ms), per-route chunk delta, and shake proof (does `import { foo } from "lib"` pull `bar`/`baz` into the bundle? check metafile). Ban new `lib/index.js` barrels that re-export everything — they defeat shaking by construction. Teach side-effects declaration as a build-time contract: if you claim `sideEffects: false`, you warrant that `import "./polyfill"` isn't hidden inside the package.
