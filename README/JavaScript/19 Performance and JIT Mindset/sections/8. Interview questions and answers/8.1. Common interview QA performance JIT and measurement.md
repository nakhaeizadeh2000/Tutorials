## 8.1. Common interview Q&A performance JIT and measurement

### 1) **Twelve classics with mechanism-level answers**

**Q1. What does V8's tiered pipeline do and why does it have multiple tiers?**
*Junior:* bytecode runs cold code quickly, JIT optimizes hot code. *Senior:* parse → Ignition bytecode → Sparkplug baseline → Maglev mid-tier → TurboFan/Turboshaft optimizing tier; each trades compile latency for peak speed; feedback vectors collect IC/kind feedback to drive speculation; cold code stays bytecode to avoid wasted compile. *Flag:* "JIT compiles all functions" or conflating parse time with optimize time.

**Q2. What is deoptimization and when does it fire?**
*Junior:* guard fails, bails to bytecode, still correct. *Senior:* speculative optimized code inserts type/shape/bounds guards; failure reconstructs frame and resumes in unoptimized tier; common triggers: shape change, element-kind widening, `arguments` exotic, bounds miss; repeated deopt in a loop is the cliff, one cold deopt is noise; observe with `--trace-deopt` lab.

**Q3. Hidden class (map) vs property — what's the contract?**
*Junior:* objects with same creation recipe + property order share a map; offset loads then. *Senior:* map encodes layout and attributes; same order → same map → monomorphic IC (one compare + offset); different order/`delete` → polymorphic/dictionary → hash probe; element kinds are the array analogue (`PACKED_SMI → DICTIONARY` one-way). *Flag:* "order doesn't matter" or "`delete` cleans and stays fast".

**Q4. Monomorphic vs polymorphic vs megamorphic — where's the cost?**
*Junior:* one map vs 2–4 vs many; many → hash. *Senior:* cost is per call site, not global; first shape addition is polymorphic table, many is megamorphic hash + prototype walk; megamorphic inside a hot loop dominates; fix by normalizing shapes at factory boundary or splitting call sites. Thresholds are engine-hint (V8 12–13 polymorphic ~2–4 maps), don't assert numbers in tests.

**Q5. Element kinds — what widens an array and what's the cost?**
*Junior:* `PACKED_SMI → PACKED_DOUBLE → PACKED_ELEMENTS → HOLEY_* → DICTIONARY`; holes/`delete`/`arr[100]=v` widen, can't narrow without copy. *Senior:* widening is permanent for that array; `filter`/`Array.from` densify via new array; `TypedArray` stays dense for binary; iteration cost and inlining both regress on widened kind.

**Q6. Which clock do you use for a hot-path interval?**
*Junior:* not `Date.now()` (wall, coarse); use `performance.now()` (monotonic ms) or `process.hrtime.bigint()` (ns) on Node. *Senior:* `performance.now()` microseconds monotonic, `hrtime.bigint()` nanoseconds; both have call overhead so batch iterations; `Date.now()` skews with NTP and is coarse.

**Q7. Why is a microbenchmark that doesn't retain its result invalid?**
*Junior:* optimizer may eliminate dead code — loop disappears, you measured nothing. *Senior:* retain via `globalThis.__sink` side-effect or harness; warm up and discard tier-up window; many samples, median/p95 not mean; `global.gc()` only in `--expose-gc` lab, never prod.

**Q8. Sampling profiler vs allocation timeline — which question answers which?**
*Junior:* flame shows CPU time (width = time, height = depth); allocation timeline shows which stack churned nursery. *Senior:* sampling misses short calls and merges inlined frames; allocation timeline attributes surviving nursery objects to stacks (see Memory 5.1); use flame for compute hot spots, timeline for churn/GC pressure. Pair both with heap snapshot diff for retention.

**Q9. Why might inlining not happen even though the function is small?**
*Junior:* call site must be monomorphic; polymorphic/megamorphic and `eval`/`with`/`try/catch` around the call block it in some heuristics. *Senior:* inlining also bails on large callee, cross-script `Function` construction, and megamorphic receiver; confirm via `node --trace-ic` + `node --cpu-prof` self-time drop, not folklore.

**Q10. `+=` in a loop vs `join` — when does it matter?**
*Junior:* many chunks `+=` builds rope chain + flatten cost; `join` builds once contiguously; for few concats, `+=` is fine. *Senior:* rope internal, flatten is linear; win for `join` appears at *many* iterations on a hot path; otherwise don't rewrite cold code.

**Q11. `queueMicrotask` vs `setTimeout(0)` for yielding — which actually yields to rendering?**
*Junior:* `queueMicrotask` drains exhaustively and starves rendering; `setTimeout(0)`/`setImmediate`/`scheduler.yield` yield to rendering/timers. *Senior:* microtasks before next macrotask/render (Async §1.2); yielding chunked work needs macrotask queue; bounded concurrency (`p-limit` pool) plus macrotask yield keeps p95 low vs unbounded `Promise.all`.

**Q12. Tree-shaking and parse cost — why isn't gzip size the budget?**
*Junior:* gzip hides parse/compile time; 100 kB minified may gzip to 30 kB but still costs 100 kB parse. *Senior:* ESM static exports + `sideEffects: false` + `/* #__PURE__ */` enable shaking; CJS and barrel `index.js` `export *` defeat it; `import()` chunks parse only when needed — measure metafile parse bytes + cold `node --cpu-prof` parse slice, not just `ls -lh`.

### 2) **What interviewers actually probe for**

Senior candidates narrate "shape → IC → speculate → guard/deopt → measure → fix" with a before/after flame vs juniors reciting "V8 is fast" or "avoid `delete`". Mentors listen for the workflow: warmup vs measured, p95 vs mean, allocation vs compute vs parse, and the discipline to profile before patching. Bonus if they connect GC pressure (Memory 2.2) and bundle parse (Modules 5.3) as the same "pressure × throughput" triangle.

### 3) **Grading guidance**

*Junior/mid signals:* correct clocks, maps share on same order, holes widen kinds, `queueMicrotask` doesn't yield, `Date.now` not high-res. *Senior signals:* call-site monomorphism discipline, deopt as correctness, lattice one-way, retention via `__sink`, flame vs allocation lens, barrel vs direct import trade-off. *Red flags:* "`delete` frees memory and stays fast", "`Date.now` is high-res", "JIT guarantees speed", "one benchmark run proves a win", "gather p95 but compare means", "CJS tree-shakes fine", "`queueMicrotask` yields to rendering".
