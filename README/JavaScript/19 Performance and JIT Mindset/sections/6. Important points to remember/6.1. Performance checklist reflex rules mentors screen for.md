## 6.1. Performance checklist reflex rules mentors screen for

### 1) **The five reflexes — "IC? kind? allocation? yield? bundle?"**

| Reflex | Fires when | Ask | Fix lane |
|---|---|---|---|
| IC state | hot `o.prop` / `fn(obj)` called per request/frame | "How many maps does this call site see?" | Normalize shapes / split call sites → [§2.1](../2. Shapes inline caches and polymorphism/2.1. Hidden classes maps and inline cache states.md) + [§4.1](../4. Writing JIT-friendly code/4.1. Functions inlining and monomorphic call sites.md) |
| Element kind | hot array built/mutated then iterated | "Does it stay `PACKED_SMI/DOUBLE` and dense?" | Don't `delete`/holeify; densify at producer → [§4.2](../4. Writing JIT-friendly code/4.2. Objects arrays and strings shape stability and element kinds.md) |
| Allocation | profile shows GC/nursery or flame shallow but GC spikes | "Allocation rate × survival rate for this path?" | Reuse buffers / bounded caches → [Memory 2.2](<../../../18 Memory Management and GC/sections/2. GC engine and allocation/2.2. Allocation hidden classes inline caches and GC pressure.md>) |
| Yield | handler >16–50 ms or `for await` over user input | "What's the longest sync slice & which queue does it yield to?" | Chunk + `setTimeout`/`setImmediate`/`scheduler.yield` + `p-limit` → [§5.1](../5. Runtime and delivery performance/5.1. Event loop yielding responsiveness and scheduling.md) |
| Bundle | entry parse slice wide or route pulls heavy barrel | "Which chunk parses on cold start and can it be `import()` split?" | Direct ESM + `sideEffects:false` + route `import()` → [§5.2](../5. Runtime and delivery performance/5.2. Bundle size tree-shaking code splitting and load cost.md) |

```js
// Quick self-check harness — run before claiming a perf win.
const { performance } = require("node:perf_hooks");
function checkReflex(fn, label) {
  for (let i = 0; i < 500; i++) fn(); // warmup — tier-up, IC feedback
  const samples = [];
  let sink;
  for (let i = 0; i < 2000; i++) { const s = performance.now(); sink = fn(); samples.push(performance.now() - s); }
  globalThis.__sink = sink; // retain against dead-code elimination
  samples.sort((a,b)=>a-b);
  console.log(label, "p50", samples[(samples.length*0.5)|0].toFixed(4), "p95", samples[(samples.length*0.95)|0].toFixed(4));
}

function makeRect(w,h){ return {w,h}; }
const r = makeRect(2,3);
checkReflex(() => r.w * r.h, "IC monomorphic"); // narrow — JIT-friendly
checkReflex(() => { const a = [1,2,3]; return a.reduce((s,v)=>s+v,0); }, "PACKED_SMI loop");
console.log("profile found?", true);
```

### 2) **The review grep list**

Search these before approving a perf-sensitive PR (annotate fixes with a profile, not folklore):

- `delete\s+\w+\.\w+` — dictionary mode on hot shape; fix via sentinel `= null` or rebuild.
- `new\s+Array\(\s*\d+\s*\)` — holey array; confirm dense (`Array.from`/`of`) or justify hole.
- `for\s*\(\s*.*\s+in\s+` on an array — `for...in` is megamorphic; prefer `for...of`/`for`.
- `\.\s*push\(.*\{.*\}\)` inside a hot loop without bound — allocation churn; reuse or batch.
- `\+=\s*["'\w]` inside a `for` with many iterations — string rope chain; use `join`.
- `import\s+.*from\s+['"].*\/index\.js['"]` or `export\s+\*\s+from` barrel — forces parse; import direct path + `sideEffects:false`.
- `Promise\.all\(.*\.map\(async` without `p-limit` — unbounded fan-out; bound it.
- `queueMicrotask` loop without `setTimeout`/`setImmediate` yield — microtask starvation.
- `--trace-opt`/`--trace-deopt`/`--allow-natives-syntax` checked in — lab-only flags, never CI.
- `Date\.now\(\)` timing of a hot path — wrong clock; use `performance.now()`/`hrtime`.

### 3) **Boundary rule — profile first, shape second, micro last**

Never gate correctness on GC or deopt timing ("this won't deopt in prod" or "`gc()` guarantees collection"). Measure cold (parse) and hot (steady-state p50/p95) separately; narrow IC/kind before micro-tuning; and report both the harness numbers and the flame/ allocation delta in the PR. If the macro path's p95 doesn't move, the micro win is unproven.

### 4) **Mentor note — how to use this table**

Make it a PR template checklist: each row is a checkbox. Demand: which reflex fired, which link (§2.1/§4.2/§5.1 etc.) explains the fix, and the before/after `performance.now()` p50/p95 + `node --cpu-prof` (or DevTools Performance) screenshot. Teach newcomers that IC/element-kind fixes are *structural* (factories, creation order) not *local* tweaks inside the hot loop.
