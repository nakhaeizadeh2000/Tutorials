## 3.1. Clocks hrtime performance.now and benchmark harnesses

### 1) **Definition — which clock for which question**

- `Date.now()` — milliseconds since epoch, wall clock, affected by system clock adjustments and coarse (±1 ms). Good for "what time is it?" Bad for measuring a 50 µs function.
- `performance.now()` — monotonic, high-resolution (microseconds), not skewed by NTP. Good for interval measurement in both browser and Node (`perf_hooks.performance.now()`).
- `process.hrtime.bigint()` — nanosecond monotonic, best for Node micro-intervals. Returns `bigint` nanoseconds since arbitrary origin.
- A *benchmark harness* (Mitata, tinybench, Benchmark.js) wraps warmup, iterations, statistics, and isolation so you don't hand-roll them badly.

### 2) **What problem it solves / history**

Early JS benchmarks used `new Date()` diffs and hand-rolled loops, producing noisy, non-reproducible numbers (GC and tier-up happened inside the measured window). `performance.now()` (High Resolution Time, 2012) and `process.hrtime` (Node 0.7) gave monotonic high-res clocks; `perf_hooks` (Node 8.5) unified them. Harnesses added warmup, statistical reporting (median/p95), and side-effect retention to defeat dead-code elimination and variance.

### 3) **Modern guidance — measure correctly, or don't claim**

```js
const { performance } = require("node:perf_hooks");

// Right clock for the job
const wall = Date.now();                    // wall time — don't time intervals with this
const t0 = performance.now();               // monotonic ms with fractions
// simulate work
for (let i = 0; i < 100_000; i++) Math.sqrt(i);
const t1 = performance.now();
console.log("perf delta ms", (t1 - t0).toFixed(3)); // e.g., ~1.2 ms — stable enough for ms-scale

// Nanosecond clock for µs-scale hot paths
const h0 = process.hrtime.bigint();
for (let i = 0; i < 100_000; i++) Math.sqrt(i);
const h1 = process.hrtime.bigint();
console.log("hrtime ns per iter", Number(h1 - h0) / 100_000); // ns/iter

// Harness sketch — warmup, retention, statistics (tinybench/Mitata do this robustly)
function bench(fn, { warmup = 1000, runs = 10_000 } = {}) {
  for (let i = 0; i < warmup; i++) fn(); // tier-up, IC feedback, GC settle
  if (global.gc) global.gc();             // only with --expose-gc, lab only
  const samples = [];
  let sink; // retain result so optimizer can't eliminate the loop
  for (let r = 0; r < runs; r++) {
    const s = performance.now();
    sink = fn();
    samples.push(performance.now() - s);
  }
  // Prevent dead-code elimination: side-effect the sink
  if (sink && typeof sink === "object") globalThis.__benchSink = sink;
  samples.sort((a, b) => a - b);
  const sum = samples.reduce((a, b) => a + b, 0);
  const mean = sum / samples.length;
  const p50 = samples[(samples.length * 0.5) | 0];
  const p95 = samples[(samples.length * 0.95) | 0];
  console.log({ mean: mean.toFixed(4), p50: p50.toFixed(4), p95: p95.toFixed(4) });
  return { mean, p50, p95 };
}
function makeWork() {
  let s = 0;
  for (let i = 0; i < 1000; i++) s += i;
  return s;
}
bench(makeWork, { warmup: 500, runs: 2000 });

// BAD clock for intervals — Date.now jitter
const d0 = Date.now();
for (let i = 0; i < 100_000; i++) Math.sqrt(i);
const d1 = Date.now();
console.log("Date delta", d1 - d0, "— coarse, skewed, don't use for µs");
```

### 4) **Common confusion**

- "`performance.now()` is free" — it has call overhead (tens of ns). In nanosecond harnesses, hoist clock reads outside inner loops and batch iterations.
- "`Date.now()` is high-res if you call it often" — no, it is still wall time and may jump on NTP adjustments; monotonic clocks exist precisely to avoid that.
- "One run is enough" — variance from GC, CPU throttling, and background tasks dwarfs a 3 % micro win. Need hundreds–thousands of samples and p95.
- "`global.gc()` makes numbers deterministic" — forced GC is a lab tool (`node --expose-gc`), not prod; use it between runs in a lab to reduce noise, never gate correctness on it.

### 5) **Performance note**

Async and I/O change what "the harness" must include: if you `await` inside the measured loop, the microtask drain and timer phases are part of the cost (see Async §1.2). For I/O benchmarks, measure `await fn()` as the sample (including microtask → next-tick ordering) and warm the connection pool first. Don't compare `perf.now` samples across processes without calibrating overhead — run an empty `() => {}` baseline and subtract its median.

### 6) **Mentor note**

Require every perf claim in a PR to answer: "which clock, how many runs, warmup discarded, how was dead-code prevented, what's p50/p95?" If any answer is missing, the claim is unverified. Teach `bench` with `__benchSink` retention once; then mandate a real harness (Mitata/tinybench) for CI. Link harnesses → traps (§3.2) → profile (§3.3) as the workflow: correct clock → avoid traps → flame confirms.
