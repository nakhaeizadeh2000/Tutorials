## 3.2. Microbenchmark traps warmup dead code and variance

### 1) **Definition — the three traps by name**

- *Dead-code elimination:* the optimizer removes a loop whose result is unused — you measured nothing.
- *Warmup/tier-up noise:* the first thousands of iterations are still tiering and building IC feedback — measuring them mixes compile time with steady-state.
- *Variance:* GC, CPU frequency scaling, and background work inject noise that dwarfs a 2–3 % "win" if you only run once.

### 2) **What problem it solves / history**

The "benchmark that lies" is the oldest perf antipattern in JS. Early jsperf/benchmark.js users reported wins that vanished on real routes because they measured warmup or eliminated code. V8's profiler and `performance.now()` exposed the traps, but harnesses (Benchmark.js 2010, Mitata/tinybench 2022–) were needed to encode the discipline (warmup vs measured, retention, statistics). The fixes are boring — retention, warmup discard, many samples — but they turn anecdotes into data.

### 3) **Modern guidance — write a benchmark that survives review**

```js
const { performance } = require("node:perf_hooks");

// Trap 1 — dead-code eliminated (BAD vs GOOD)
function sumNoSink(n) {
  let s = 0;
  for (let i = 0; i < n; i++) s += i;
  // s unused → optimizer may eliminate the whole loop
  return s;
}
function sumWithSink(n) {
  let s = 0;
  for (let i = 0; i < n; i++) s += i;
  return s;
}
let sink;
sink = sumNoSink(1000);
console.log("noSink result dead?", sink === 499500); // true — but harness must RETAIN it
// GOOD harness retains sink globally so call can't be eliminated (see §3.1 bench)
globalThis.__sink = sumWithSink(1000);
console.log("with sink retained", globalThis.__sink); // 499500

// Trap 2 — warmup / tier-up
function smallHot(x) { return x * 2; }
const tCold = performance.now();
smallHot(3); // first call — bytecode, not optimized
const tWarm = performance.now();
for (let i = 0; i < 20000; i++) smallHot(i); // warm — feedback collected, optimized?
const tHot = performance.now();
smallHot(3);
const tAfter = performance.now();
console.log("cold first call ms", (tWarm - tCold).toFixed(4));
console.log("hot loop ms", (tHot - tWarm).toFixed(4));
console.log("after warm ms", (tAfter - tHot).toFixed(4), "— discard warmup, measure steady-state");

// Trap 3 — variance: one sample is not a measurement
function noisyWork() {
  const a = new Array(200).fill(0).map((_, i) => i);
  return a.reduce((s, v) => s + v, 0);
}
function quantifyVariance(fn, runs = 500) {
  const samples = [];
  for (let i = 0; i < runs; i++) {
    const s = performance.now();
    fn();
    samples.push(performance.now() - s);
  }
  samples.sort((a, b) => a - b);
  const mean = samples.reduce((a, b) => a + b, 0) / samples.length;
  const p50 = samples[(0.5 * runs) | 0];
  const p95 = samples[(0.95 * runs) | 0];
  console.log({ mean: mean.toFixed(4), p50: p50.toFixed(4), p95: p95.toFixed(4), max: samples.at(-1).toFixed(4) });
  console.log("variance trap: p50 vs p95 spread matters — don't compare single runs");
  return { mean, p50, p95 };
}
quantifyVariance(noisyWork);

// Harmless microbenchmark nosedive — optimizing away allocation vs real pipeline
// BAD comparison: array literal allocation measured in isolation
const aPack = [1, 2, 3];
const aSpread = [...aPack]; // densifies holes, allocates
console.log(aSpread.length); // 3 — micro says spread costs more; macro may be dominated by I/O
```

### 4) **Common confusion**

- "More iterations always reduces noise" — past a point you measure GC amortization, not steady-state. Use warmup discard + bounded measured window (e.g., 10k–100k) and report p95, not just mean.
- "Isolating the function is enough" — a micro that wins by avoiding an allocation may allocate elsewhere in the real handler (retaining `Map` growth). Measure the *user path* (route/handler/job) before tuning a leaf.
- "Async `await` inside a tight bench loop is free" — `await 1` yields to microtask queue; measuring `await fn()` without draining microtasks misattributes queue time.

### 5) **Performance note**

The honest microbenchmark workflow: warmup (discard), `if (global.gc) global.gc()` between *runs* only in a `--expose-gc` lab, retain result, many samples, report mean/median/p95 and effect size. If p95 overlaps with baseline's p95, the win is unproven. Pair the micro with a macro: request latency on a realistic fixture (JSON parse + handler + serialize) — if the macro doesn't move, the micro doesn't matter.

### 6) **Mentor note**

Gate perf PRs on a template: "harness (Mitata/tinybench), warmup, retention, runs, p50/p95, `--expose-gc` lab only, flame before/after". Reject any `Date.now()` micro or one-shot `console.time`. Pair the bench review with GC-pressure check (Memory §2.2) — many micro "wins" are just GC timing shifts. Make variance visible: show the p95 spread in the PR description.
