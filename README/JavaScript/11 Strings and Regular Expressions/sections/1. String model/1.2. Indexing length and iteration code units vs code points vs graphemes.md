## 1.2. Indexing length and iteration — code units vs code points vs graphemes

### 1) **`length` counts code units, not characters**

**Definition** — `String.prototype.length` is the count of UTF-16 *code units*. Characters outside the Basic Multilingual Plane (code points `> U+FFFF`) need two units (a surrogate pair) → `length` overcounts characters. `charAt(i)`/`charCodeAt(i)` return by unit; `codePointAt(i)` returns by point (and advances 1 unit for BMP, 2 for astral); `String.fromCodePoint` creates by point; `fromCharCode` creates by unit.

```js
const ascii = "A"; // U+0041 — 1 unit
const acute = "é"; // U+00E9 — 1 unit (BMP)
const smile = "😀"; // U+1F600 — 2 units (pair D83D DE00)
const flag = "🇫🇷"; // U+1F1EB U+1F1F7 — 4 units (two pairs)
console.log(ascii.length, acute.length, smile.length, flag.length); // 1 1 2 4

// charAt vs codePointAt on astral
console.log(smile.charAt(0) === "\uD83D", smile.charAt(1) === "\uDE00"); // true true — halves
console.log(smile.charCodeAt(0).toString(16), smile.charCodeAt(1).toString(16)); // d83d de00
console.log(smile.codePointAt(0).toString(16)); // 1f600 — full point
console.log(smile.codePointAt(1).toString(16)); // de00 — second half alone is lone trail (not the point)
console.log(String.fromCodePoint(0x1F600) === smile); // true
console.log(String.fromCharCode(0xD83D, 0xDE00) === smile); // true — but fromCharCode can make lone surrogates

// Bracket indexing is unit-indexed, same as charAt
console.log(smile[0] === smile.charAt(0), smile[1] === smile.charAt(1)); // true true
console.log(smile[2]); // undefined — past length

// Common lie: length is characters
function charCountWrong(s) { return s.length; }
function codePointCount(s) { return [...s].length; } // correct for points (see §2)
console.log(charCountWrong(smile), codePointCount(smile)); // 2 1
console.log(charCountWrong(flag), codePointCount(flag)); // 4 2 — even points overcount graphemes (flag is 1 grapheme, 2 points)
```

### 2) **Code-point iteration via `Symbol.iterator` and `for-of`**

**Definition** — strings are *iterable* by code points (ECMA-262 `StringIterator`): `for-of`, spread `[...s]`, and `Array.from(s)` yield one string per *code point*, not per unit. `s.split("")` splits by *units* and breaks astral characters. `s[Symbol.iterator]` is the protocol entry (see [Iterables 1.1](<../../../10 Iterables Generators and Async Iteration/sections/1. Iterable and iterator protocols/1.1. Iterable vs iterator vs array-like and Symbol.iterator.md>)).

**Modern guidance** — for character counts or loops, use `for-of`/`[...s]`/`Array.from` (point iteration). For byte/unit indexes, use `length`/`charCodeAt`. For user-perceived characters, use grapheme segmentation (see §3).

```js
const s = "A😀B"; // A + pair + B — length 4, 3 code points
console.log(s.length); // 4 — units
console.log([...s]); // [ 'A', '😀', 'B' ] — 3 points
console.log(Array.from(s)); // [ 'A', '😀', 'B' ]
console.log(s.split("")); // [ 'A', '\uD83D', '\uDE00', 'B' ] — 4 units — BROKEN for astral
console.log(s.split("").length, [...s].length); // 4 3

for (const ch of s) console.log(ch, ch.length); // "A"1 "😀"2 "B"1 — iteration yields point-strings

// Index walking must skip 2 units for astral
function countPoints(str) {
  let n = 0;
  for (let i = 0; i < str.length; ) {
    const cp = str.codePointAt(i);
    i += cp > 0xFFFF ? 2 : 1; // astral advances 2 units
    n += 1;
    console.log(cp.toString(16));
  }
  return n;
}
console.log(countPoints(s)); // 41 1f600 42 — count 3

// Reverse iterates points correctly only via points, not units
console.log([...s].reverse().join("")); // "B😀A" — correct
console.log(s.split("").reverse().join("")); // "B\uDE00\uD83DA" — pair reversed and broken

// at() is unit-indexed (like bracket) — negative counts from end by units, not points
console.log(s.at(0), s.at(-1)); // "A" "B"
console.log(s.at(1), s.at(2)); // lone halves — "�" fragments when sliced solo (see 1.1)
```

### 3) **Grapheme clusters, normalization, and `Intl.Segmenter`**

**Definition** — a *grapheme cluster* is what users perceive as one character (may be multiple code points: emoji with skin tone + ZWJ sequences). `Intl.Segmenter` (ES2022-ish, Baseline) segments strings into grapheme, word, or sentence units. *Normalization* (`String.prototype.normalize(form)`) canonicalizes different encodings of the same visual character: composed `é` (U+00E9) vs decomposed `e + ◌́` (U+0065 U+0301) — forms `NFC` (composed, default), `NFD` (decomposed), `NFKC`/`NFKD` (compatibility).

**Modern guidance** — normalize before comparing user input (`NFC` is the safe default for storage/comparison). Count user characters with `Intl.Segmenter` (`granularity: "grapheme"`), not `length` or even `[...s].length`.

```js
// Grapheme vs code points vs units — "👩‍🚀" astronaut
const astro = "👩‍🚀"; // U+1F469 ZWJ U+1F680 — 3 code points, 5 units, 1 grapheme
console.log(astro.length); // 5 — units
console.log([...astro].length); // 3 — points
// Grapheme count via Segmenter
const seg = new Intl.Segmenter("en", { granularity: "grapheme" });
console.log([...seg.segment(astro)].length); // 1 — grapheme
console.log([...seg.segment("🇫🇷")].length); // 1 — flag is 1 grapheme despite 2 points / 4 units

// Normalization
const composed = "\u00E9"; // é as one point
const decomposed = "e\u0301"; // e + combining acute
console.log(composed === decomposed); // false — different sequences
console.log(composed.normalize("NFC") === decomposed.normalize("NFC")); // true — both to NFC
console.log(composed.normalize("NFD") === decomposed.normalize("NFD")); // true — both to NFD
console.log(composed.length, decomposed.length); // 1 2 — even NFC vs NFD lengths differ

// Storage/comparison discipline — normalize on ingestion
function equalVisual(a, b) { return a.normalize("NFC") === b.normalize("NFC"); }
console.log(equalVisual(composed, decomposed)); // true

// Segmenting for truncation without breaking graphemes
function truncateGraphemes(str, max) {
  const parts = [...new Intl.Segmenter("en", { granularity: "grapheme" }).segment(str)].map(s => s.segment);
  return parts.slice(0, max).join("");
}
console.log(truncateGraphemes("👩‍🚀👩‍🚀👩‍🚀", 2)); // "👩‍🚀👩‍🚀" — 2 graphemes, not 2 units nor 2 points
// Bad truncation — slice by units breaks clusters
console.log("👩‍🚀".slice(0, 2)); // lone halves — broken, isWellFormed false

// Locale-aware case (see 2.3) still needs normalization after case fold for search
console.log("café".normalize("NFC").length, [..."café"].length); // 4 4 — but decomposed café would be 5 points
```

### 4) **Common confusion**

- "`split('')` is unicode-safe" — no, it splits units; `"😀".split("")` gives two lone surrogates. Use `[...s]` or `Array.from(s)`.
- "`length` with emoji tells characters" — no, use unit/point/grapheme awareness: `length` → units, `[...s].length` → points, `Segmenter` → graphemes.
- "`normalize` is optional sugar" — no, without it `é` composed vs decomposed are unequal — search, dedupe, and Map keys fail.
- "`charAt` returns a full character" — no, it returns one unit; `codePointAt` or `for-of` for points.
- "`at(-1)` counts characters from end" — no, it counts units (last unit, not last grapheme).

### 5) **Performance note**

Point iteration via `for-of`/`[...s]` is O(n) with one iterator object — negligible vs correctness. Counting graphemes via `Intl.Segmenter` is O(n) with locale data lookup — cache the `Segmenter` instance per locale outside loops; recreating per string is slow (ICU data load). `normalize` copies the string and is O(n); normalize once on ingestion/comparison, not inside hot loops that already hold NFC strings. Avoid `split("")` entirely on user text — correctness bug outweighs any micro win.
