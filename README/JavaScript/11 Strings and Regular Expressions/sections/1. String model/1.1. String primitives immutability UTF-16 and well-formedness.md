## 1.1. String primitives immutability UTF-16 and well-formedness

### 1) **Primitive strings are immutable UTF-16 code-unit sequences**

**Definition** — a JavaScript string is a *primitive value* (typeof `"hi"` is `"string"`) that stores an ordered sequence of 16-bit *code units* (UTF-16). The value is immutable: you cannot change a character in place; any "mutation" creates a new string. Assignment to an index is a no-op in sloppy and throws in strict; methods like `toUpperCase` return a new string.

**What problem it solves / history** — Java (1995) gave JavaScript UTF-16 because UCS-2 was "enough for all characters" then. Unicode grew beyond 65k, so UTF-16 became a variable-length encoding: most characters one unit, astral characters two units (a surrogate pair). ECMAScript kept UTF-16 storage (not code points) to preserve `length` and indexing semantics; correction APIs (`codePointAt`, iteration by code points, and ES2024 `isWellFormed`/`toWellFormed`) were layered on top.

**Modern guidance** — treat strings as values, not containers. To "change" one, build a new string (`slice`/`replace`/`+`/`join`). Never rely on indexed writes; use `at`/`slice` instead.

```js
// Immutability — indexed write does not mutate
let s = "hello";
s[0] = "H";
console.log(s); // "hello" — sloppy silent no-op
console.log(s.toUpperCase()); // "HELLO" — new string
console.log(s); // "hello" — original unchanged

// Strict indexed write throws (engine throws per spec for string exotic)
function strictWrite() { "use strict"; const t = "hi"; t[0] = "H"; return t; }
try { strictWrite(); } catch (e) { console.log(e.name); } // TypeError in strict

// Reassignment creates a new primitive — identity is by value
let a = "hi";
let b = "hi";
console.log(a === b); // true — same sequence, same value
a = a + "!";
console.log(a, b); // "hi!" "hi" — b unaffected

// String() coercion vs new String() wrapper (see §3)
console.log(typeof "hi", typeof String("hi")); // "string" "string"
console.log(typeof new String("hi")); // "object" — wrapper, truthy even for ""
console.log(new String("") ? "truthy" : "falsy"); // "truthy" — trap
```

### 2) **Surrogates, lone surrogates, and well-formedness**

**Definition** — UTF-16 encodes code points `U+0000..U+FFFF` as one unit, and `U+10000..U+10FFFF` as a *surrogate pair*: high (lead) `0xD800..0xDBFF` followed by low (trail) `0xDC00..0xDFFF`. A *lone surrogate* is an unpaired high or low unit (invalid Unicode scalar). A string is *well-formed* iff it contains no lone surrogates.

ES2024 added `String.prototype.isWellFormed()` (boolean) and `String.prototype.toWellFormed()` (replaces each lone surrogate with `U+FFFD` `�`).

**What problem it solves** — lone surrogates arise from manual `String.fromCharCode`, legacy data, or slicing a pair in half. They break `encodeURI` (throws `URIError`), confuse `TextEncoder`, and produce `�` on render. Well-formedness APIs let you validate/sanitize once instead of scattering regex.

```js
// Lone surrogates — unpaired halves
const loneHigh = "\uD800"; // high without low
const loneLow = "\uDC00"; // low without high
const pair = "\uD83D\uDE00"; // 😀 as two units — well-formed
console.log(loneHigh.length, pair.length); // 1 2
console.log([...loneHigh].length, [...pair].length); // 1 1 — iteration counts code points (see 1.2)

console.log(loneHigh.isWellFormed()); // false
console.log(pair.isWellFormed()); // true
console.log("".isWellFormed()); // true — empty is well-formed
console.log(loneHigh.toWellFormed()); // "�" — U+FFFD
console.log((loneHigh + "a").toWellFormed()); // "�a"

// encodeURI throws on lone surrogates — sanitize first
try { encodeURI(loneHigh); } catch (e) { console.log(e.name); } // URIError
console.log(encodeURI((loneHigh).toWellFormed())); // "%EF%BF%BD" — encoded replacement

// Slicing can create lone surrogates — the main source of ill-formedness
const emoji = "😀"; // length 2 — pair
console.log(emoji.length); // 2
const half = emoji.slice(0, 1); // cut the pair
console.log(half.length, half.isWellFormed()); // 1 false — lone high
console.log(half.toWellFormed()); // "�"

// From char codes can introduce lone surrogates; fromCodePoint cannot
console.log(String.fromCharCode(0xD800).isWellFormed()); // false
console.log(String.fromCodePoint(0x1F600).isWellFormed()); // true — 😀
// Surrogate-aware construction — prefer fromCodePoint when handling code points
```

### 3) **Boxing, `String()` vs `new String()`, and `valueOf`**

**Definition** — reading a property on a primitive string *autoboxes*: the engine temporarily wraps it as a `String` object (`new String(value)`) to look up `String.prototype` methods, then discards the wrapper. `String(x)` (call) coerces via `ToString`; `new String(x)` (construct) returns an *object* wrapper that boxes the primitive and is always truthy (even for `""`). `valueOf`/`toString` on the wrapper unwrap to the primitive.

**Modern guidance** — never use `new String`. It is legacy, truthy for empty, breaks strict equality, and confuses `typeof`. Use primitives everywhere; `String(value)` for coercion, or literal `"" + value` when the table is understood (see [Values 2.1](<../../../03 Values Types and Coercion/sections/2. The conversion algorithms/2.1. Explicit conversion toolbox Number String Boolean parseInt parseFloat and unary plus.md>)).

```js
// Autoboxing — reads work, writes don't stick (see 1.1)
const prim = "hi";
console.log(prim.length); // 2 — boxed to String object, then discarded
console.log(prim.toUpperCase()); // "HI"
// Writing a property to a primitive is boxed then lost
prim.custom = 42;
console.log(prim.custom); // undefined — wrapper was ephemeral

// String() vs new String()
console.log(typeof String(42), String(42)); // "string" "42" — coercion
console.log(typeof new String(42), new String(42) instanceof String); // "object" true
const wrapper = new String("hi");
console.log(wrapper === "hi"); // false — object !== primitive
console.log(wrapper == "hi"); // true — == coerces wrapper via ToPrimitive (ValueOf)
console.log(wrapper.valueOf() === "hi"); // true — unwrap
console.log(String(wrapper) === "hi"); // true — ToString unwraps

// The truthy trap
console.log(Boolean("")); // false
console.log(Boolean(new String(""))); // true — object is truthy!
if (new String("")) console.log("branch taken unexpectedly — empty wrapper is truthy");

// Brand check
console.log(Object.prototype.toString.call("hi")); // [object String] — via boxing spec path?
console.log(Object.prototype.toString.call(new String("hi"))); // [object String]
console.log(typeof "hi" === "string" && "hi".isWellFormed()); // true — works via autoboxing
```

### 4) **Common confusion**

- "`length` is characters" — no, `length` counts UTF-16 code units. `"😀".length === 2` but there is one character (1 grapheme, 1 code point, 2 units).
- "`isWellFormed` is about encoding validity" — yes — lone surrogates are the *only* way a JS string can be ill-formed; replacement is `U+FFFD`.
- "`new String('a') === 'a'`" — no, the wrapper is an object, never `===` to the primitive.
- "`encodeURI` handles lone surrogates" — no, it throws `URIError`; call `toWellFormed()` first.
- "Strings are mutable via index" — no, assignment silently fails (sloppy) or throws TypeError (strict); use `slice`/`replace`.

### 5) **Performance note**

String operations allocate new strings; repeated `+=` in a tight loop over large `n` copies O(n²) in naive builds (each `+` copies both sides). For hot concatenation of many pieces, collect into an array and `join("")` once. Engines can flatten rope/concat strings internally, but `join` is the explicit fast path and avoids intermediate garbage. `isWellFormed`/`toWellFormed` are implemented as a linear scan over internal storage — faster than a JS loop with `charCodeAt` (avoid hand-rolling the surrogate check). Autoboxing has no per-access allocation in optimized JIT — it folds the wrapper — but `new String` forces a heap object that defeats that fold.

### 6) **Mentor note**

Have juniors predict `"😀".length` and `"😀".slice(0,1).isWellFormed()` before running — the slice-to-lone-surrogate moment cements well-formedness. In review, flag any `new String` (require primitive + `String()` coercion) and any `str[i] =` write (replace with `slice`/`replace`). Require `isWellFormed` guard before `encodeURI`/`TextEncoder` on external input, and `toWellFormed()` on ingestion if you persist strings that may contain lone surrogates.
