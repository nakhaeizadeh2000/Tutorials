## 8.1. Common interview Q&A strings encoding and regular expressions

### 1) **Twelve questions with mechanism answers**

**Q1. What does `"😀".length` return, and why?**
`*A:* `2` — length counts UTF-16 code units, not characters. `U+1F600` needs a surrogate pair (2 units). `[...'😀'].length` is `1` (code points), `[...new Intl.Segmenter(...).segment('😀')].length` is `1` (grapheme).*

**Q2. `split("")` vs `[...s]` on `"😀"`?**
`*A:* `split("")` splits by units → `['\uD83D','\uDE00']` (two lone surrogates, `isWellFormed` false); `[...s]` iterates by points → `['😀']`.*

**Q3. Why does `"a\nb".match(/a.b/)` not match?**
`*A:* `.` without `s` flag is `[^\n]`. With `/a.b/s` or `/a[^]b` it matches newline.*

**Q4. `slice(4,10)` vs `substring(4,10)` vs `substr(4,6)` vs `slice(-6)` on `"JavaScript"`?**
`*A:* `slice` respects negatives and `start>end→""`; `substring` clamps negatives to 0 and swaps; `substr` second arg is length (deprecated). `slice(-6)` is last 6 units.*

**Q5. `includes` vs `indexOf` vs `search` for literal `"a.b"` in `"axb"`?**
`*A:* `includes`/`indexOf` do literal search (`"a.b"` not in `"axb"` → false/-1); `search("a.b")` converts to `new RegExp("a.b")` where `.` is wildcard → `0` (false positive). Use literal methods or `RegExp.escape`.*

**Q6. `match` with `/ab/` vs `/ab/g` vs `matchAll(/ab/g)`?**
`*A:* `/ab/` → one result with `index/groups`; `/ab/g` via `match` → array of substrings only (groups lost); `matchAll(/ab/g)` → iterator of full results (groups/indices preserved, requires `g`).*

**Q7. Why does a shared `/ab/g` validator alternate true/false?**
`*A:* `lastIndex` is mutable state with `g`/`y`. Each `test` advances it; second call starts beyond the match → false then reset. Fix: `lastIndex=0` or stateless `/ab/`.*

**Q8. `replace` vs `replaceAll` with `/ab/`?**
`*A:* `replace(/ab/,…)` replaces first only; `replace(/ab/g,…)` replaces all; `replaceAll("ab",…)` works literal; `replaceAll(/ab/,…)` throws `TypeError` without `g`.*

**Q9. `(ab)` vs `(?:ab)` vs `(?<name>ab)` and `$1` vs `\1`?**
`*A:* `(ab)` captures (numbered `$1` in replacement, `m[1]`); `(?:ab)` groups without capturing; `(?<name>ab)` named (`m.groups.name` and `$<name>`); `\1`/`\k<name>` is pattern backreference, `$1`/`$<name>` is replacement.*

**Q10. What does `d` flag give?**
`*A:* `hasIndices` — `match.indices` is `[[start,end], ...groups]` with `indices.groups` for named; undefined for non-participating optionals.*

**Q11. `u` vs `v` flag?**
`*A:* `u` enables code-point semantics (`\u{...}`, `\p{}`); `v` (ES2024) supersets `u` plus string properties (`\p{RGI_Emoji}`), set notation `--`/`&&`, `\q{foo|bar}`; they are exclusive.*

**Q12. Lookahead `(?=)` vs lookbehind `(?<=)` with variable length?**
`*A:* Both are zero-width assertions (don't consume). Lookbehind ES2018 allows variable-length inside (`(?<=foo.*)bar`), unlike the old fixed-length restriction.*

```js
// Smoke — answers Q3/Q7/Q6/Q8 together
console.log(/a.b/.test("a\nb"), /a.b/s.test("a\nb")); // false true
const q7 = /ab/g; console.log(q7.test("ab"), q7.lastIndex, q7.test("ab"), q7.lastIndex, q7.test("ab")); // true 2 false 0 true (reset cycle)
console.log("ab ab".match(/ab/), "ab ab".match(/ab/g), [... "ab ab".matchAll(/ab/g)].length); // single vs global vs iterator
console.log("fee".replace(/f(\w+)/, "[$&]"), "ab ab ab".replaceAll(/ab/g, "X")); // $& replace vs replaceAll g
console.log("2026-08-26".match(/(?<y>\d{4})-(\d{2})-(\d{2})/).groups.y, "2026-08-26".match(/(?<y>\d{4})-(?<m>\d{2})-(?<d>\d{2})/d).indices.groups.y); // named + indices
console.log(/[\p{Letter}--[aeiou]]/v ? /[\p{Letter}--[aeiou]]/v.test("b") : "v not in runtime"); // v sets if available
console.log("foobar".match(/foo(?=bar)/)[0], "foobaz".match(/foo(?!bar)/)[0], "$12".match(/(?<=\$)\d+/)[0]); // lookaround trio
```

### 2) **What interviewers actually probe for**

Senior signal is narrating *UTF-16 storage + well-formedness* (`isWellFormed`/`toWellFormed`, 4/2/1 ladder), `v` sets vs `u` (`--` subtraction, `&&` intersection, string props), and `lastIndex` state hazard — not reciting flag names or `substr` revival.

- Junior: can quote `length` lies; knows `includes` exists; can write `match` without explaining `g` shape.
- Mid: knows unit/point/grapheme via `Segmenter`/`normalize`; knows `matchAll` vs `exec`; knows `replaceAll` needs `g`.
- Senior: explains `isWellFormed` source (slice creates lone halves) + `encodeURI` throw; debugs shared `g` `lastIndex` alternation; explains `v` properties of strings and lookbehind variable length; flags `split("")` breakage.

### 3) **Grading guidance — red flags**

- "`length` is characters" — red; correct is units, `Segmenter` for graphemes.
- "`split('')` is unicode-safe" — red; only `[...s]`/`Segmenter` are.
- "`substr` is fine" — red; deprecated, use `slice`.
- "`v` and `u` combine" — red; they are exclusive.
- "`lookbehind` not supported" — stale (since ES2018 variable allowed).
- "`replace` replaces all" — red; only `replaceAll` with `g` (or `/g`).
- "`search` with `g` finds second" — red; `search` ignores `g`/`lastIndex`.
