## 6.1. String and RegExp checklist — reflex rules mentors screen for

### 1) **Units vs points vs graphemes — three counts before any "length" claim**

**Definition** — before truncating, counting, or indexing, ask: are you counting *code units* (`length`, `slice`, `charAt`, `split("")`), *code points* (`[...s].length`, `codePointAt`, `for-of`), or *graphemes* (`Intl.Segmenter`)? String storage is units; iteration by points; user characters are graphemes; normalization decides equality.

```js
const s = "café 😀 👩‍🚀"; // mix BMP, astral, ZWJ
console.log(s.length); // units — lies for emoji/ZWJ
console.log([...s].length); // points — still lies for ZWJ flag
console.log([...new Intl.Segmenter("en",{granularity:"grapheme"}).segment(s)].length); // graphemes — user characters
console.log("café".normalize("NFC") === "café".normalize("NFC")); // normalize before equal

// Review grep — any bare length/slice on user text is suspect until grapheme-aware
// Checklist prompt: "What does length count here, and what should it count?"
```

### 2) **`g`/`y` state, `lastIndex` reset, and `replaceAll` requiring `g`**

**Definition** — `g`/`y` make `RegExp` stateful. Reusing the same instance across `test`/`exec` flips results. `replaceAll` with regex throws without `g`. `search` ignores `lastIndex`; `match` with `g` loses indices/groups; `matchAll` is the global iterator that preserves them.

```js
const re = /ab/g;
console.log(re.test("ab"), re.lastIndex, re.test("ab"), re.lastIndex); // true 2 false 0 — alternates
re.lastIndex = 0; // reset before reuse
console.log(re.test("ab")); // true — stable when guarded

// Safe helpers — reset or clone
function safeTest(rx, s) { rx.lastIndex = 0; return rx.test(s); }
console.log(safeTest(/ab/g, "ab ab")); // true
try { console.log("ab ab".replaceAll(/ab/, "X")); } catch(e) { console.log(e.name); } // TypeError — needs g
console.log("ab ab".replaceAll(/ab/g, "X")); // "X X"
```

### 3) **The review grep list**

**Definition** — flags to search before approving string/regex PRs.

```js
// 1) split("") on emoji/user text — breaks astral → require [...s] or Segmenter
// Bad: "😀".split("") => ['\uD83D','\uDE00'] — ill-formed halves
console.log("😀".split("").length, [..."😀"].length); // 2 vs 1 — grep "split(\"\"\")"

// 2) substr legacy — deprecated → replace with slice
// Bad: s.substr(4, 6) — grep "substr("

// 3) search vs includes for literal — search("a.b") wildcard bug → use includes/indexOf literal or RegExp.escape
console.log("a.b".search("a.b")); // 0 — matches "axb", not literal — grep "\.search\(.*\".*\."

// 4) lastIndex reuse — global regex reused across requests → alternation bug — grep "const.*=.*\/.*\/g"
// Fix: reset lastIndex=0 or use literal per call / stateless test

// 5) RegExp constructor without RegExp.escape on user input — injection param
// Bad: new RegExp(user) — grep "new RegExp\(.*user"
// Fix: new RegExp(RegExp.escape(user))

// 6) Case insensitive without i, or locale compare without toLocale/Intl.Collator
console.log("i".toUpperCase(), "i".toLocaleUpperCase("tr-TR")); // "I" vs "İ" — grep "toUpperCase\(\)"

// 7) Dot not matching newline — need s flag
console.log(/a.b/.test("a\nb"), /a.b/s.test("a\nb")); // false vs true — grep "a\.b.*\n"

// Grep command family:
// rg -n "split\(\"\"\")" README/
// rg -n "substr\(" README/
// rg -n "lastIndex" README/
// rg -n "new RegExp\(" README/
// rg -n "replaceAll\(/" README/
```

### 4) **Common confusion**

- "`length` is enough for UI counters" — no, UI needs grapheme count (`Segmenter`); `length` caps will cut ZWJ sequences.
- "`lastIndex` bug is rare" — no, any shared `/.../g` in a validate function alternates per call in production traffic.
- "`replaceAll('a','b')` needs `g`" — string form doesn't; regex form does (`replaceAll(/a/g, ...)`) — mismatch throws.

### 5) **Performance note**

Normalize and segment once per input (O(n)), not per comparison. Cache `Intl.Segmenter` and `RegExp` literals outside loops. Prefer `includes` over `/literal/.test` for literal checks (no regex compile). For huge repeated `replaceAll` over large texts, benchmark string split/join vs regex — regex with `g` scans once.

### 6) **Mentor note**

Hand juniors a buggy validator that uses a shared `/code/g` and two sequential `test` calls returning different results; have them add `lastIndex=0` fix. Drill `"👩‍🚀".length` 5/3/1 ladder. In review, require `RegExp.escape` for any `new RegExp(user)` and `Segmenter` for any `slice` on user display strings.
