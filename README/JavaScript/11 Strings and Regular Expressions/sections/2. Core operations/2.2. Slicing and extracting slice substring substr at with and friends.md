## 2.2. Slicing and extracting — slice substring substr at with and friends

### 1) **`slice` vs `substring` vs legacy `substr` — signatures and negative-index handling**

**Definition** — `slice(start, end)` extracts `[start, end)` with *negative* indexes counting from `length` and `start > end` → `""`. `substring(start, end)` clamps negatives to `0` and swaps if `start > end`. `substr(start, length)` (deprecated, Annex B) takes a *length* not an end — avoid it.

**Modern guidance** — use `slice` everywhere. It matches `Array.prototype.slice`, handles negatives predictably, and is not legacy. `substring` survives only for `substring` swapping bug compatibility; `substr` is removed from modern style guides.

```js
const s = "JavaScript";
console.log(s.slice(0, 4)); // "Java"
console.log(s.slice(4)); // "Script"
console.log(s.slice(-6)); // "Script" — negative from end
console.log(s.slice(4, 10)); // "Script"
console.log(s.slice(10, 4)); // "" — no swap
console.log(s.slice(-6, -2)); // "Scri"

console.log(s.substring(0, 4)); // "Java" — same for positive
console.log(s.substring(4)); // "Script"
console.log(s.substring(-6)); // "JavaScript" — -6 clamped to 0! (surprise)
console.log(s.substring(10, 4)); // "Script" — swapped to (4,10)
console.log(s.substring(-6, 2)); // "Ja" — (-6->0, 2) vs slice(-6,2) ""

// substr (deprecated) — length, not end; negative start allowed but length negative -> ""
console.log(s.substr(4, 6)); // "Script" — legacy
console.log(s.substr(-6, 4)); // "Scri" — negative start counts from end
// Don't use — linters flag `substr` (unicorn/prefer-string-slice)

// Negative out-of-bounds clamping
console.log("abc".slice(10)); // "" — start beyond length
console.log("abc".slice(-10)); // "abc" — clamped to 0
console.log("abc".substring(-10, 10)); // "abc" — clamped both sides

// Slicing lone surrogates creates ill-formed halves (see 1.1)
const emoji = "😀"; // length 2
console.log(emoji.slice(0, 1).isWellFormed()); // false — lone high
console.log(emoji.slice(0, 1).toWellFormed()); // "�"
```

### 2) **Indexed access — `charAt`/`charCodeAt`/`codePointAt`/`at`/`with` and bracket `str[i]`**

**Definition** — `str[i]`/`charAt(i)` → one-unit string (or `""` past end for `charAt`; `undefined` for bracket). `charCodeAt(i)` → unit code (or `NaN` past end). `codePointAt(i)` → point code (or `undefined` past end; astral consumes two units at low index, lone half returns its unit). `at(i)` → one-unit string like `charAt` but supports *negative* index; `String.prototype` has no `with`? Actually `Array.prototype.with` is array-only — `String` doesn't have `with` (strings immutable — use `slice` + concat).

*Note:* checklist above listed `with` for arrays; strings have `at` but not `with` — convert via array if you need immutable unit replacement.

```js
const t = "hello";
console.log(t[1], t.charAt(1)); // "e" "e"
console.log(t[100], t.charAt(100)); // undefined "" — difference past end
console.log(t.charCodeAt(1), t.codePointAt(1)); // 101 101 — BMP same
console.log(t.charCodeAt(100), t.codePointAt(100)); // NaN undefined — past-end contracts differ

const z = "A😀B";
console.log(z[1], z.charAt(1)); // "\uD83D" — lone high half (length 5 but astral)
console.log(z.codePointAt(1).toString(16)); // 1f600 — full point at unit 1
console.log(z.codePointAt(2).toString(16)); // de00 — second half alone (lone trail)
console.log(z.at(1), z.at(-1)); // "\uD83D" "B" — at is unit-indexed
console.log(z.at(-2)); // "\uDE00"? actually second half of emoji vs last char depends
console.log("abc".at(-1), "abc".at(-10)); // "c" undefined — negative out-of-range undefined (like bracket)

// at() vs charAt() negative handling
console.log("abc".charAt(-1)); // "" — charAt does not support negative
console.log("abc".at(-1)); // "c" — at does
console.log("😀".at(-1), "😀".at(-2)); // halves — at is unit-based, not grapheme

// No String.with — use array conversion for "with" semantics
function stringWith(str, index, ch) {
  const units = [...str]; // points, but for unit-accurate use Array.from via units: str.split("").with? legacy — better slice
  // Simple unit-indexed with via slice (code-unit aware)
  const i = index < 0 ? str.length + index : index;
  return str.slice(0, i) + ch + str.slice(i + 1);
}
console.log(stringWith("hello", 1, "E")); // "hEllo"
console.log(stringWith("A😀B", 1, "X")); // breaks pair — demo of why grapheme-aware replacement needs Segmenter
```

### 3) **`substring`/`slice` vs `split("")` vs spread on lone surrogates**

**Definition** — `split("")` splits by units (breaks astral); `[...s]` splits by points; `slice` works on units (can split pairs). Normalizing before slicing avoids decomposing issues (see 1.2).

```js
const e = "😀";
console.log(e.split("")); // [ '\uD83D', '\uDE00' ] — 2 units — ill-formed halves
console.log([...e]); // [ '😀' ] — 1 point — correct
console.log(e.slice(0, 1), e.slice(0, 1).isWellFormed()); // lone high false
console.log([...e].slice(0, 1).join("")); // "😀" — point-level slice safe for astral (but not ZWJ)

const zwj = "👩‍🚀"; // 5 units, 3 points, 1 grapheme
console.log(zwj.split("").length, [...zwj].length, [...new Intl.Segmenter("en",{granularity:"grapheme"}).segment(zwj)].length); // 5 3 1
console.log(zwj.slice(0, 2).isWellFormed()); // false — sliced ZWJ clusters break
console.log([...new Intl.Segmenter("en",{granularity:"grapheme"}).segment(zwj)].map(s=>s.segment).slice(0,1).join("")); // "👩‍🚀" — grapheme-safe slice
```

### 4) **Common confusion**

- "`slice` and `substring` are aliases" — no; negative handling and swap differ (`slice(-6)` vs `substring(-6)` produce different results).
- "`substr` is the slice alias" — no; `substr(start, length)` deprecated — `slice(start, end)` differs in second arg.
- "`str[i]` and `charAt(i)` identical" — almost, but past-end: `str[100] === undefined`, `charAt(100) === ""`, `charCodeAt(100) === NaN`, `codePointAt(100) === undefined`.
- "`at(-1)` counts characters" — no, units — `"😀".at(-1)` is lone trail half, not the emoji.
- "`split('')` is safe for emoji" — no, use `[...s]` or `Segmenter`.

### 5) **Performance note**

`slice`/`substring` copy the specified range into a new string — O(k) for slice length k. Chaining many slices in a loop over large strings allocates O(n²) total if each copies overlapping ranges; prefer one-pass scan or `replace` with regex for bulk edits. `at`/`charAt`/`codePointAt` are O(1) unit lookups; `Segmenter` grapheme iteration is O(n) with ICU tables — cache the segmenter.

### 6) **Mentor note**

Give juniors `"😀".slice(0,1)` and ask if it's well-formed (no) then fix with `toWellFormed`. Have them predict `substring(-5,2)` vs `slice(-5,2)` on `"hello"` (first is `"he"`, second is `""`). Flag any `substr` in review (migrate to `slice`) and any `split("")` on user text (require `[...s]` or `Segmenter`).
