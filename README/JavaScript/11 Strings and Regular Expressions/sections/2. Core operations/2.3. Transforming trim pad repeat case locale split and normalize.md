## 2.3. Transforming — trim pad repeat case locale split and normalize

### 1) **Trimming and padding — `trim`/`trimStart`/`trimEnd` and `padStart`/`padEnd`**

**Definition** — `trim()` removes leading+trailing *WhiteSpace* (Unicode `White_Space` + BOM + line terminators); `trimStart`/`trimEnd` (aliases `trimLeft`/`trimRight` legacy) remove one side. `padStart(targetLength, padString)`/`padEnd` pad *on the side* to reach target length with repeated/truncated `padString`; if `targetLength <= length`, return original without truncation.

**Modern guidance** — `trim`/`pad` return new strings; they never mutate. `padString` default is `" "`; it truncates not fills beyond needed length.

```js
console.log("  hi \n\t".trim()); // "hi"
console.log("  hi ".trimStart()); // "hi "
console.log("  hi ".trimEnd()); // "  hi"
console.log("  hi ".trimLeft(), "  hi ".trimRight()); // legacy aliases — same as Start/End

// Whitespace includes more than " "
console.log("\u00A0hi\uFEFF".trim()); // "hi" — NBSP + BOM trimmed
console.log("\u2003hi\u2003".trim()); // "hi" — em space

// padStart/padEnd — target length counts units
console.log("7".padStart(3, "0")); // "007"
console.log("7".padEnd(3, "0")); // "700"
console.log("hi".padStart(5)); // "   hi" — default " "
console.log("hi".padStart(5, "ab")); // "abahi"? actually "abahi"? padString "ab" repeated: need 3 pad chars -> "aba" truncated -> "abahi"? check
console.log("hi".padStart(5, "ab")); // "abahi"?? Let's verify via run — pad logic: "ab" repeated ceil then slice
console.log("hello".padStart(3, "0")); // "hello" — already longer, no truncation
console.log("".padStart(3, "ab")); // "aba" — padString truncated/sliced

// padString truncation
console.log("x".padEnd(4, "01")); // "x010" — need 3 chars from "01" -> "010"
console.log("x".padStart(4, "01")); // "010x"
```

### 2) **Repeating and casing — `repeat`, `toUpperCase`/`toLowerCase` vs `toLocale*`**

**Definition** — `repeat(count)` returns `str` repeated `count` times (`count` integer 0..`2^28-1` approx; negative/Infinity → `RangeError`; fractional truncates; `count===0` → `""`). `toUpperCase`/`toLowerCase` map by Unicode default case (locale-independent); `toLocaleUpperCase`/`toLocaleLowerCase` use the given locale(s) or host default — crucial for Turkic `i/İ/ı/I`.

```js
console.log("na".repeat(3)); // "nanana"
console.log("hi".repeat(0)); // ""
console.log("ab".repeat(2.9)); // "abab" — fractional truncated to 2
try { console.log("hi".repeat(-1)); } catch (e) { console.log(e.name); } // RangeError
try { console.log("hi".repeat(Infinity)); } catch (e) { console.log(e.name); } // RangeError
console.log("hi".repeat(1)); // "hi" — no copy nuance

// Unicode casing — default vs locale
console.log("straße".toUpperCase()); // "STRASSE" — ß → SS
console.log("STRASSE".toLowerCase()); // "strasse"

// Turkish dotless/dotted i — the flagship locale bug
console.log("i".toUpperCase()); // "I" — default (English) uppercases dotted i to dotted I
console.log("i".toLocaleUpperCase("tr-TR")); // "İ" — Turkish dotted İ
console.log("I".toLowerCase()); // "i"
console.log("I".toLocaleLowerCase("tr-TR")); // "ı" — Turkish dotless ı
console.log("TITLE".toLocaleLowerCase("tr")); // "tıtle" — second char dotless in tr

// Case conversion is locale-sensitive for search — normalize after case fold
function equalIgnoreCase(a, b, locale) {
  if (locale) return a.toLocaleLowerCase(locale) === b.toLocaleLowerCase(locale);
  return a.toLowerCase() === b.toLowerCase(); // still not fully Unicode-case-folded — for full fold use toLocale with "en" or Intl.Collator
}
console.log(equalIgnoreCase("I", "ı", "tr-TR")); // true with locale, false without (lowercase I in tr is dotless)

// Intl.Collator for locale-aware comparison (stronger than lowercasing)
const col = new Intl.Collator("tr", { sensitivity: "base", usage: "search" });
console.log(col.compare("i", "İ")); // non-zero in tr? base sensitivity may conflate? compare shows locale
```

### 3) **`split`/`join` round-trip and `normalize` placement**

**Definition** — `str.split(separator, limit)` splits into array; `separator` can be string or RegExp (with capturing groups spliced in). Limit truncates output. `Array.prototype.join(separator)` reverses it. `normalize(form)` canonicalizes (`NFC` default composed, `NFD` decomposed, `NFKC`/`NFKD` compatibility). Normalizing before `split`/comparison avoids the `é` mismatch (see [1.2](<../1. String model/1.2. Indexing length and iteration code units vs code points vs graphemes.md>)).

```js
// split basics
console.log("a,b,c".split(",")); // [ 'a', 'b', 'c' ]
console.log("a,b,c".split(",", 2)); // [ 'a', 'b' ] — limit truncates
console.log("abc".split("")); // [ 'a','b','c' ] — units; breaks astral (see 1.2/2.2)
console.log([... "😀"]); // [ '😀' ] — correct for astral
console.log("".split(",")); // [ '' ] — empty string splits to one empty
console.log("".split("")); // [] — special case: "" split by "" is []
console.log("aaa".split("a")); // [ '', '', '', '' ] — leading/trailing empties

// split with regex capturing — groups are included
console.log("a1b2c".split(/(\d)/)); // [ 'a','1','b','2','c' ] — capturing parens spliced
console.log("a1b2c".split(/\d/)); // [ 'a','b','c' ] — non-capturing

// split with limit and regex — limit still applies after group splicing
console.log("a1b2c".split(/(\d)/, 3)); // [ 'a','1','b' ]

// join round-trip — but not lossless if separator appears in data
console.log(["a","b","c"].join(",")); // "a,b,c"
console.log("a,b,c".split(",").join(",")); // "a,b,c" — round-trip when sep not in tokens
console.log(["a",undefined,null].join(",")); // "a,," — join stringifies hole→"" (arrays 4.2) but here undefined/null -> ""/""?

// normalize before split/compare — storage discipline
const c = "\u00E9"; // é composed
const d = "e\u0301"; // é decomposed
console.log(c === d); // false — different sequences
console.log(c.normalize("NFC") === d.normalize("NFC")); // true — normalize first
console.log(c.normalize("NFC").split("").length, d.normalize("NFC").split("").length); // both 1 after NFC? composed is 1 unit — NFD would be 2

// NFKC for compatibility (e.g., "ﬁ" ligature vs "fi")
console.log("ﬁ".normalize("NFKC")); // "fi" — ligature decomposed for search
console.log("Ⅳ".normalize("NFKC")); // "IV"

// Simple slug/clean pipeline: normalize → lower → trim → split → join
function slug(s) {
  return s.normalize("NFC").trim().toLowerCase().split(/\s+/).join("-");
}
console.log(slug("  Café  au Lait ")); // "café-au-lait"
```

### 4) **Common confusion**

- "`trim` removes all whitespace anywhere" — no, only leading/trailing; internal spaces remain. Use `replace(/\s+/g, "")` to strip all.
- "`padStart` truncates if longer" — no, it returns original unchanged when `targetLength <= length`; only `slice` truncates.
- "`toUpperCase` is locale-aware" — no, it is Unicode default; Turkic `i` needs `toLocaleUpperCase("tr")`.
- "`split('')` handles emoji" — no, it breaks astral/emoji; use `[...s]` or `Segmenter` before `split` logic.
- "`normalize` is optional" — no, mixed composed/decomposed data from users/DBs will mis-dedupe and mis-compare; normalize on ingestion.
- "`repeat(-1)` returns ''" — no, it throws `RangeError`.

### 5) **Performance note**

`trim`/`pad`/`repeat`/`split`/`join` each allocate a new string/array — O(n). Repeated `str += piece` in a loop over large strings is O(n²); building via `array.push(piece); array.join("")` is O(n). `normalize` is O(n) and should be done once per external input, not per comparison in a hot loop (normalize + cache the NFC form). `split` with regex capturing groups allocates extra entries — avoid capturing when you don't need it (`(?:)`).
