## 5.2. Assertions lookaround boundaries and unicode flags

### 1) **Anchors and `m` multiline, word boundary `\b`**

**Definition** — `^` matches string start (or after `\n` with `m`); `$` matches string end (or before `\n` with `m`). `\b` matches *word boundary*: between `\w` (`[A-Za-z0-9_]`) and non-`\w` (or string edge); `\B` is inverse. `^`/`$` are zero-width (don't consume). With `m`, each line has its own `^`/`$`.

```js
console.log(/^ab/.test("ab xy")); // true — start
console.log(/^ab/.test("xy ab")); // false
console.log(/ab$/.test("xy ab")); // true — end
console.log(/ab$/m.test("ab\nxy")); // false? Actually "ab" at line start, but $ with m matches before \n — "ab\nxy" line1 "ab" then newline -> $ after ab before \n => true
console.log(/^b/m.test("a\nb")); // true — ^ after \n with m
console.log(/^b/.test("a\nb")); // false

// m on shared string
const lines = "first line\nsecond line\nthird";
console.log(lines.match(/^.*$/gm)); // [ 'first line','second line','third' ]

// \b word boundary
console.log(/\bcat\b/.test("the cat sat")); // true
console.log(/\bcat\b/.test("concatenated")); // false — c is inside word
console.log(/\bcat\b/.test("cat.=> ")); // true — punctuation is boundary
console.log(/\b\w+\b/g.test("hi there")); // \b anchors wordChars sequence
console.log("hi there".match(/\b\w+\b/g)); // [ 'hi','there' ]
console.log(/\Bcat\B/.test("concatenated")); //? cat inside word -> \B before/after not boundary => inside -> maybe true

// $ with trailing newline — $ matches before final \n as well?
console.log(/end$/.test("end\n")); // true? $ matches before trailing \n
console.log(/end$/m.test("end\n")); // true

// Combining anchors for whole-string
console.log(/^\w+$/.test("hello")); // true — entire string word
console.log(/^hello$/m.test("x\nhello\ny")); // false — ^hello$ per line with m would match middle line? Actually "^hello$" with m matches line hello
console.log(/^hello$/m.test("x\nhello\ny")); // true — line anchor
```

### 2) **Lookahead `(?=)`/`(?!` and lookbehind `(?<=)`/`(?<!` with variable length**

**Definition** — `(?=X)` *positive lookahead* asserts `X` follows without consuming; `(?!X)` negative. `(?<=X)` positive lookbehind asserts `X` precedes; `(?<!X)` negative. Since ES2018 lookbehind is supported and (since modern) allows variable-length quantifiers inside.

```js
// Lookahead — find "foo" only when followed by "bar"
console.log("foobar".match(/foo(?=bar)/)); // [ 'foo' ] — bar asserted not consumed
console.log("foobaz".match(/foo(?=bar)/)); // null
// Negative lookahead — "foo" not followed by bar
console.log("foobaz".match(/foo(?!bar)/)); // [ 'foo' ]
console.log("foobar".match(/foo(?!bar)/)); // null

// Lookbehind — find number preceded by "$"
console.log("$12 and €34".match(/(?<=\$)\d+/g)); // [ '12' ] — €34 not preceded by $
console.log("$12 and €34".match(/(?<!\$)\d+/g)); // [ '34' ] — negative

// Variable length lookbehind (ES2018+ allows quantifiers)
console.log("foobar foobarbaz".match(/(?<=foo.*)bar/g)); // [ 'bar','bar' ] — variable foo.*
console.log("xa yb za".match(/(?<=[a-z]\w*)\d/g)); // ? lookbehind variable

// Lookaround for password-like validation without consuming
const pwd = "Abc123!x";
console.log(/(?=.*\d)(?=.*[a-z])(?=.*[A-Z]).{6,}/.test(pwd)); // true — three lookaheads at start

// Overlapping matches via lookahead (m = "aa" with lookahead captures)
console.log([... "aaa".matchAll(/(?=(aa))/g)].map(m => [m[1], m.index])); // [ ['aa',0], ['aa',1] ] — overlapping via zero-width
```

### 3) **`u` vs `v` unicode sets, `s` dotAll, `y` sticky, `i` case folding, and inline modifiers `(?i:...)`**

**Definition** — `u` enables code-point semantics: `.{n}` counts points, `\u{...}`, `\p{...}`, `\p{Letter}`. `v` (ES2024) extends `u`: set operations `[A--[B]]` (subtraction), `[A&&B]` (intersection), `\q{foo|bar}` string literals, properties of strings `\p{RGI_Emoji}`. `s` makes `.` match `\n`. `y` sticky anchors at `lastIndex`. `i` case-insensitive with unicode folding under `u`/`v`. Inline modifiers `(?i:...)`/`(?-i:...)` toggle per-group (ES2025) without global flag flip.

```js
// u — code-point dot and \p
console.log(/./.test("😀")); // true — dot without u matches one unit (still true but length confusion)
console.log(/./u.test("😀")); // true — with u, . is one code point (still matches lone high? but consumes pair)
console.log("😀".match(/./g).length, "😀".match(/./gu).length); // 2 1 — g without u splits units (2 halves), with u one point
console.log(/\p{Letter}+/u.test("café")); // true — unicode property

// v — set notation and properties of strings
const hasV = (()=>{ try{ new RegExp(".","v"); return true;}catch{return false;}})();
if (hasV) {
  console.log(/[\p{Letter}--[aeiou]]/v.test("b")); // true — consonant via subtraction
  console.log(/[\p{Letter}--[AEIOUaeiou]]/v.test("a")); // false
  console.log(/[\p{Letter}&&[a-z]]/v.test("b")); // true — intersection with [a-z]
  console.log(/\p{RGI_Emoji}/v.test("👩‍🚀")); // true — emoji ZWJ string via v
  console.log(/[\q{foo|bar}]/v.test("foo")); //? \q string literal inside class via v — matches "foo" as string item? actual check
} else console.log("v flag not available");

// s — dotAll
console.log(/a.b/.test("a\nb")); // false
console.log(/a.b/s.test("a\nb")); // true — . includes newline

// y — sticky anchored at lastIndex, no forward search
const yre = /ab/y;
console.log(yre.test("ab ab")); // true at 0 lastIndex=2
console.log(yre.test("ab ab")); // false at 2 is " " (no search)
yre.lastIndex = 3;
console.log(yre.test("ab ab")); // true at 3 — manually moved
// contrast g which would forward-search to 3 and succeed without manual move
const gre = /ab/g;
gre.lastIndex = 2;
console.log(gre.test("ab ab"), gre.lastIndex); // true 5 — g forwarded

// i — case folding with u
console.log(/a/i.test("A")); // true
console.log(/ß/iu.test("SS")); //? ß case folding with i+u may match SS? ES handles — test shows

// Inline modifiers ES2025 — (?i:...) enables i locally, (?-i:...) disables
if ((()=>{ try{ new RegExp("(?i:foo)",""); return true;}catch{return false;}})()) {
  const inline = new RegExp("(?i:foo)-(?-i:bar)");
  console.log(inline.test("FOO-bar")); // true — foo case-insensitive via inline, bar sensitive
  console.log(new RegExp("(?i:foo)bar").test("FOObar")); // true — foo case-insensitive, bar sensitive
  console.log(new RegExp("(?i:foo)bar").test("FOOBAR")); // false — bar must be lower
} else console.log("inline modifiers not in this runtime — needs Node 24 / ES2025");

// Combining flags example — dotAll + unicode + global
console.log([... "a\nb 😀".matchAll(/./gsu)].map(m=>m[0])); // note v vs u
```

### 4) **Common confusion**

- "`^`/`$` always match string ends" — without `m` yes; with `m` they match line edges (after/before `\n`).
- "`(?<=...)` lookbehind consumes" — no, zero-width; `/(?<=\$)\d+/` matches digits without including `$` in match.
- "`v` is `u` plus sets" — yes, but `v` cannot combine with `u` (throws) — `v` implies `u` semantics.
- "`s` flag needed for `.` to match newline" — yes, otherwise `.` is `[^\\n]`.
- "`y` is just faster `g`" — no, `y` does not forward-search; it *must* match at `lastIndex` or fail.
- "`(?i:foo)` works everywhere" — ES2025 baseline; older runtimes need `/foo/i` globally.

### 5) **Performance note**

Lookahead/lookbehind can cause backtracking explosion on overlapping quantifiers (`(a+)*b`); avoid nested quantifiers before lookaround. `v` sets compile to broader automata but still linear for simple classes — simple `[a-z]` is faster than long subtraction chain. Sticky `y` is the fast tokenizer primitive — scanning a long string token-by-token with `y` plus `lastIndex++` is O(n) with no forward scan overhead vs `g`.

### 6) **Mentor note**

Have juniors write `/\b\w+\b/g` to tokenize then break it with `_` inclusion to reveal `\w` definition (`_` is word char). Demo variable-length `(?<=foo.*)bar` vs fixed `(?<=\$)` to show ES2018 freedom, then craft overlapping `/(?=(aa))/g` to show zero-width power. Flag any `a.b` without `s` that intended to span lines (add `s`), any `y` loop without `lastIndex` bump on empty (infinite), and any `v`-set logic attempted with `u` (require `v`).
