## 5.1. Groups named groups backreferences hasIndices and replacement patterns

### 1) **Capturing `()`, non-capturing `(?:)`, named `(?<name>)`, and numbered backreference `\1`**

**Definition** — `(...)` captures into `match[1]`; `(?:...)` groups without capturing; `(?<name>...)` captures into `match.groups.name` *and* `match[1]`; numbered captures are 1-based left-to-right by opening `(`; nested groups increment numbers. Inside the pattern `\1`/`\k<name>` refer to earlier capture (backreference). Outside (replacement), `$1`/`$<name>` refer.

**Modern guidance** — use named groups for readability when >1 group; use non-capturing for pure grouping to avoid polluting indices.

```js
// Numbered capturing
const m = "2026-08-26".match(/(\d{4})-(\d{2})-(\d{2})/);
console.log(m[1], m[2], m[3]); // "2026" "08" "26"
console.log(m[0]); // "2026-08-26" — full match

// Non-capturing for grouping without count
console.log("ab ab".match(/(?:ab) /g)); // [ 'ab ', 'ab ' ] but no capture in result — vs capturing would shift numbers

// Named groups
const nm = "2026-08-26".match(/(?<y>\d{4})-(?<m>\d{2})-(?<d>\d{2})/);
console.log(nm.groups); // { y:'2026', m:'08', d:'26' }
console.log(nm.groups.y, nm[1]); // both accessible — named also at numeric index

// Nested numbering
const nested = "abbbc".match(/(a(b+)(c))/);
console.log(nested[1], nested[2], nested[3]); // "abbbc" "bbb" "c" — outer 1, inner b+ is 2, c is 3
console.log(nested.groups); // undefined — no names

// Backreference inside pattern — match doubled word or repeated capture
console.log(/(ab)\1/.test("ab ab")); // false? "ab" + "\1" means "ab" again directly -> "abab" not "ab ab" with space
console.log(/(ab)\1/.test("abab")); // true — \1 repeats first group literally
console.log(/(?<w>\w+)-\k<w>/.test("foo-foo")); // true — named backreference via \k<name>

// Numbered backreference must follow its group
console.log(/(\w+) \1/.test("foo foo")); // true — group 1 then repeat
console.log(/(\w+) (\w+) \2 \1/.test("foo bar bar foo")); // true — \2 is second capture
```

### 2) **`hasIndices` `d` flag and `indices`/`indices.groups`**

**Definition** — `d` (hasIndices, ES2022) adds `match.indices` — array of `[start, end]` for whole match and each group (including named via `indices.groups`). `undefined` entry for non-participating optional group. Enables source mapping/highlighting without re-scanning.

```js
// Without d — no indices
console.log("2026-08-26".match(/(\d{4})-(\d{2})-(\d{2})/).indices); // undefined

// With d — indices per group
const withD = "2026-08-26".match(/(?<y>\d{4})-(?<m>\d{2})-(?<d>\d{2})/d);
console.log(withD.indices); // [ [0,10], [0,4], [5,7], [8,10] ] — group 0 outer, 1 y, 2 m, 3 d
console.log(withD.indices.groups); // { y:[0,4], m:[5,7], d:[8,10] } — same via names
console.log(withD.indices[0]); // [0,10] — whole match span

// Non-participating optional group -> undefined indices entry
const opt = "ac".match(/(a)(b)?(c)/d);
console.log(opt.indices); // [ [0,2], [0,1], undefined, [1,2] ] — middle group missing

// g + d with matchAll — each result carries indices
console.log([... "ab ab".matchAll(/(a)(b)/gd)].map(m => m.indices));
// [ [[0,2],[0,1],[1,2]], [[3,5],[3,4],[4,5]] ]

// Using indices to slice source for highlighting
function highlight(str, re) {
  const m = str.match(re);
  if (!m || !m.indices) return str;
  const [s,e] = m.indices[1]; // group 1 span
  return str.slice(0,s) + "[" + str.slice(s,e) + "]" + str.slice(e);
}
console.log(highlight("fee fi fo", /f(\w+)/d)); // "f[ee] fi fo" — highlights first capture

// indices with named and numbered both
const both = "12-34".match(/(?<a>\d+)-(?<b>\d+)/d);
console.log(both.indices.groups.a, both.indices[1]); // [0,2] [0,2] — same span via name vs number
```

### 3) **Replacement patterns — `$&` `$1` `$<name>` `$$` and replacer function `(match, ...groups, offset, str, groups)`**

**Definition** — replacement string interprets: `$&` whole match, `` $` `` before, `$'` after, `$n` nth capture (1-99), `$<name>` named, `$$` literal `$`. A replacer function `fn(match, p1, p2, ..., offset, string, groups)` receives the same and returns the replacement string — use it for conditional logic or escaping.

```js
// $ patterns in string replacement
console.log("2026-08-26".replace(/(\d{4})-(\d{2})-(\d{2})/, "$3/$2/$1")); // "26/08/2026" — reorder
console.log("2026-08-26".replace(/(?<y>\d{4})-(?<m>\d{2})-(?<d>\d{2})/, "$<d>/$<m>/$<y>")); // same via names
console.log("fee".replace(/f(\w+)/, "[$&]")); // "[fee]" — $& whole match
console.log("price $5".replace("$5", "$$5")); // "price $$5"? actually replace string "$5" literal needs $$ for $ sign — "$5" pattern is $5 not captured => "$5"? use $$
console.log("price is $5".replace("$", "$$")); // "price is $$5"? let's verify — "$$" -> literal $
console.log("hi".replace(/hi/, "$$")); // "$" — $$ escapes
console.log("hi".replace(/hi/, "$$$&")); // "$hi" — $$ + $&

// Function replacer — (match, ...captures, offset, string, groups)
console.log("a1 b2 c3".replace(/(\w)(\d)/g, (m, p1, p2, off, str, groups) => {
  console.log(`m=${m} p1=${p1} p2=${p2} off=${off}`);
  return `${p1.toUpperCase()}${Number(p2)*10}`;
}));
// "A10 B20 C30" — with logs per match

// Named groups in function — last arg is groups object
console.log("2026-08-26".replace(/(?<y>\d{4})-(?<m>\d{2})-(?<d>\d{2})/, (...args) => {
  const groups = args.at(-1); // last arg is groups
  return `${groups.d}-${groups.m}-${groups.y}`;
})); // "26-08-2026"

// replaceAll with function — same args but global guaranteed
console.log("ab1 ab2".replaceAll(/(ab)(\d)/g, (m, p1, p2) => `${p1.toUpperCase()}${p2}`)); // "AB1 AB2"

// Conditional replacement — function decides
console.log("a1 a2 a10".replaceAll(/a(\d+)/g, (m, n) => Number(n) > 5 ? `a[${n}]` : m)); // "a1 a2 a[10]"

// Escaping $ in replacement string — use $$ not single $
console.log("cost $5".replace("$", "$$")); // demo — single $ in replacement string not special for string pattern, but for regex replacement $$ needed
```

### 4) **Common confusion**

- "`(ab)` vs `(?:ab)` changes numbering" — yes, only capturing increments numbers; mixing unnamed capturing for grouping shifts later `$n`.
- "`$0` is whole match" — no, `$&` is whole; `$0` is not interpreted (treats as `$` + `0` or literal).
- "`\1` in replacement works" — no, `\1` is *pattern* backreference; in replacement use `$1`/`$<name>`.
- "`indices` exists without `d`" — no, `d` flag is required; without it `indices` is `undefined`.
- "`groups` is always present" — only when pattern has named groups; otherwise `undefined` (named) vs array index still works.
- "`replaceAll` with string pattern treats `$` specially" — no, string-pattern `replaceAll` is literal; `$` specials only when replacement is a regex result? Actually `$` patterns apply regardless of pattern type? Replacement string patterns apply for both string and regex search — `$$` still escapes.

### 5) **Performance note**

Named groups and `d` indices add per-match allocation (groups object + indices array). For high-throughput scanning over huge logs where you only need the substring, use non-capturing or plain `includes`/`search` instead. Replacer functions allocate per-match arguments; string replacement with `$` patterns is faster for pure reordering. If you only need spans, `d` is cheaper than slicing and re-searching to locate groups.

Have juniors capture a date with `(\d+)-(\d+)-(\d+)` then rewrite with `(?<y>...)` and `$<y>` — naming removes index brittleness. Show `$1` vs `\1` at the wrong side to cement pattern vs replacement distinction. Require `d` flag when the task says "highlight the captured range" (indices give exact start/end). Flag any `p1` counting that ignores non-capturing → off-by-one groups.
