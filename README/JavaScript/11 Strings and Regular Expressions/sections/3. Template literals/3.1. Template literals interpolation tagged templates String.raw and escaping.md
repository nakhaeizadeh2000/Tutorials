## 3.1. Template literals interpolation tagged templates String.raw and escaping

### 1) **Interpolation and multiline without `+`**

**Definition** — template literals `` `...${expr}...` `` evaluate each `${expr}` via `ToString` (unless tag handles it) and concatenate the literal chunks. They preserve newlines, allow nesting `` `${`a ${b}`}` ``, and respect escape sequences. Raw backticks build a single string — unlike `+` chains.

**What problem it solves / history** — pre-ES2015, multiline was `"a\n" + "b"` or `"a\\n\\\n b"` with error-prone `+` and manual `\n`. ES2015 templates unified interpolation, multiline, and tagging.

```js
const name = "Ada";
const score = 42;
console.log(`Hello ${name}, score is ${score}`); // "Hello Ada, score is 42"
console.log(`${1+2} ${String(42)} ${null} ${undefined} ${false} ${NaN}`); // "3 42 null undefined false NaN" — each via ToString

// Multiline — newlines are literal
console.log(`line one
line two is indented
  line three`);
// Note: leading spaces in template are preserved; use trim/pad to fix if needed (see 2.3)

// Nesting and expression power
console.log(`outer ${`inner ${score * 2}`}`); // "outer inner 84"
console.log(`sum ${[1,2,3].reduce((a,b)=>a+b,0)}`); // "sum 6"

// Tagged vs plain — escaping
console.log(`a\\n b`); // actual newline? "`a\\n b`" with \n => newline char
console.log(`a\n b`.length, `a\n b`.includes("\n")); // 4 true? actually `a\n b` newline between a and b
console.log(`a\\n b`.length); // uses \n as newline
// To preserve \n literally in source vs runtime, use String.raw (see §2) or "\\n"

// ToString nuance — objects use valueOf/toString
console.log(`${{a:1}}`); // "[object Object]"
console.log(`${[1,2]}`); // "1,2" — array ToString is join(",")
console.log(`${null} ${undefined}`); // "null undefined" — not empty
```

### 2) **Tagged templates — `tag(strings, ...values)` and `strings.raw`**

**Definition** — `tag` `` `a${x}b${y}c` `` calls `tag(strings, x, y)` where `strings` is a frozen array of literal chunks `["a","b","c"]` with `strings.raw` holding the *raw* (unescaped) chunks. The tag chooses how to interleave. `String.raw` is a built-in tag that returns the raw concatenation (no escape processing).

**Modern guidance** — use tags for DSLs that need custom escaping/interpolation: SQL parameters, HTML escaping, i18n. Never build SQL/HTML by plain `` `${user}` `` — use a tag that escapes.

```js
function tag(strings, ...values) {
  console.log(strings); // [ 'a', 'b', 'c' ] — literal pieces
  console.log(strings.raw); // [ 'a', 'b', 'c' ] — raw (differs when \ escapes present)
  return strings.reduce((acc, s, i) => acc + s + (i < values.length ? `⟦${values[i]}⟧` : ""), "");
}
const x = "X", y = "Y";
console.log(tag`a${x}b${y}c`); // "a⟦X⟧b⟦Y⟧c"

// strings.raw preserves backslashes — the core of String.raw
function showRaw(strings, ...vals) {
  return { cooked: strings[0], raw: strings.raw[0], vals };
}
console.log(showRaw`\n`); // { cooked: '\n', raw: '\\n', vals: [] } — cooked newline vs raw "\n"
console.log(String.raw`a\n b`); // "a\\n b" — literal backslash-n, not newline
console.log(`a\n b` === String.raw`a\n b`); // false — cooked vs raw
console.log(`a\n b`.length, String.raw`a\n b`.length); // 4 5 — raw has extra backslash

// Real-world: safe HTML escaping tag
function html(strings, ...values) {
  const esc = s => String(s).replaceAll(/[&<>"']/g, c => ({'&':'&amp;','<':'&lt;','>':'&gt;','"':'&quot;',"'": '&#39;'}[c]));
  return strings.reduce((a, s, i) => a + s + (i < values.length ? esc(values[i]) : ""), "");
}
const user = `<script>alert(1)</script>`;
console.log(html`<b>${user}</b>`); // "<b>&lt;script&gt;alert(1)&lt;/script&gt;</b>" — escaped

// Real-world: SQL parameterization (demo — not for prod without driver tagging)
function sql(strings, ...vals) {
  // Returns { text, params } for driver — prevents injection vs `${vals}` interpolation
  const text = strings.reduce((a, s, i) => a + s + (i < vals.length ? `$${i+1}` : ""), "");
  return { text, params: vals };
}
console.log(sql`SELECT * FROM users WHERE id=${42} AND name=${"O'Reilly"}`);
// { text: 'SELECT * FROM users WHERE id=$1 AND name=$2', params: [42, "O'Reilly"] }

// Tag call-site caching — template object is same per site (per spec) — can be used for memoization
let cache;
function memoTag(strings, ...vals) {
  if (cache === strings) console.log("same template object reused");
  cache = strings;
  return strings.join("|") + vals.join(",");
}
memoTag`a${1}b`; memoTag`a${2}b`; // second call prints reuse note
```

### 3) **When templates replace `replace`/`concat` and when they don't**

**Definition** — use plain templates for human-readable concatenation; use tagged templates (or explicit `replace`/`escape` helpers) when values come from untrusted input. Templates do not escape — `` `SELECT ... ${input}` `` interpolates `ToString(input)` verbatim.

**Good / bad patterns**

```js
// Bad — injection via plain interpolation (HTML, SQL, RegExp, shell)
const nameBad = "O'Reilly";
console.log(`SELECT * FROM t WHERE name='${nameBad}'`); // "SELECT ... 'O'Reilly'" — broke SQL quoting
const htmlBad = `<div>${user}</div>`; // user contains <script> — XSS

// Good — tag escapes per context (see §2)
console.log(html`<div>${user}</div>`); // escaped
console.log(sql`SELECT * FROM t WHERE name=${nameBad}`.text); // parameterized

// Bad — building RegExp via template without escaping (see 4.1)
const pat = "a.b";
console.log(new RegExp(`^${pat}$`).test("axb")); // true — dot acted as wildcard (bug)
const escaped = typeof RegExp.escape === "function" ? RegExp.escape(pat) : pat.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
console.log(new RegExp(`^${escaped}$`).test("axb")); // false — correct literal

// Good — templates for display strings where escaping is not needed
const item = "widget", qty = 3, price = 9.5;
console.log(`${qty} × ${item} @ $${price} = $${qty*price}`); // "3 × widget @ $9.5 = $28.5"

// Multiline generation — prefer templates over array join for readability
function mdTable(rows) {
  return `| a | b |
|---|---|
${rows.map(r=>`| ${r.a} | ${r.b} |`).join("\n")}`;
}
console.log(mdTable([{a:1,b:2},{a:3,b:4}]));
```

### 4) **Common confusion**

- "Templates escape values" — no, `` `...${user}` `` does `ToString(user)` verbatim; escaping must be explicit (tag or pre-escape).
- "`String.raw` is a string method" — no, it is a *tag* (also callable as `String.raw({raw:["..."]}, ...vals)`), not `"str".raw()`.
- "`strings.raw` equals `strings`" — no, they differ when escapes/`\u`/octals present: `` tag`\n` `` cooked=`\n` (newline), raw=`\n` (two chars).
- "Tagged templates run interpolation first" — no, the tag receives literal chunks + raw values and decides; un-tagged evaluates via `ToString`.
- "Multiline trims indentation" — no, spaces are preserved; use `String.raw` + dedent helper or `trim` if you want dedent.

### 5) **Performance note**

Template literals are syntactic sugar for concatenation — engines pre-concatenate at parse time where possible. No performance difference vs `+` for plain cases. Tagged templates allocate one `strings` array per call site (cached per site per spec — reuse is cheap); heavy tag logic (e.g. HTML escaping over large inputs) dominates. Prefer plain template + explicit escaping over a tag that reconstructs via `reduce` in the hottest path if the escaping can be done inline with `replaceAll`.

### 6) **Mentor note**

Give juniors `` `${"<"}` `` and ask what it renders (literal `<`), then show `html` tag escaping it — the gap cements "templates do not sanitize". Have them write `RegExp(`^${input}$`)` and break it with input `a.b` to teach `RegExp.escape` (see 4.1). In review, flag any `` `...${untrusted}` `` that flows to HTML/SQL/RegExp/shell without a tag/escape (require `html`/`sql`/`RegExp.escape`), and any `String.raw` used as method (require tag call).
