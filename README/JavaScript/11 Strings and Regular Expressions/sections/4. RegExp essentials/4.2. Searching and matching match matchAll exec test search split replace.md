## 4.2. Searching and matching — match matchAll exec test search split replace

### 1) **Match families — `String.prototype.match` vs `matchAll` vs `RegExp.prototype.exec` vs `test`**

**Definition** — `s.match(re)` with `re` *without* `g` returns one result like `exec` (index, input, groups, and `indices` if `d`); *with* `g` returns array of matched substrings only (no index/groups). `s.matchAll(re)` *requires* `g`, returns an *iterator* of full results (each like exec). `re.exec(s)` always returns one result and advances `lastIndex` if `g`/`y`; `re.test(s)` is `exec` boolean, also advances `lastIndex` with `g`/`y`.

**Modern guidance** — use `matchAll` for global captures/groups (replaces manual `exec` loop); use `match`/`exec` for single; use `test` only for boolean when you control `lastIndex=0`.

```js
// Without g — single result with index/groups
console.log("fee fi fo".match(/f\w+/)); // [ 'fee', index:0, input:'fee fi fo', groups:undefined ]
console.log(/f\w+/.exec("fee fi fo")); // same shape

// With g — match returns substring array only
console.log("fee fi fo".match(/f\w+/g)); // [ 'fee','fi','fo' ]
console.log("fee fi fo".match(/f(\w+)/g)); // [ 'fee','fi','fo' ] — groups lost

// matchAll requires g — iterator of full results (groups preserved)
console.log([... "fee fi fo".matchAll(/f(\w+)/g)].map(m => [m[0], m[1], m.index]));
// [ ['fee','ee',0], ['fi','i',4], ['fo','o',7] ]
try { console.log("fee".matchAll(/f\w+/)); } catch (e) { console.log(e.name); } // TypeError — needs g
console.log([... "fee fi fo".matchAll(/f\w+/g)][0].indices); // undefined without d — need d for indices

// exec loop is the manual alternative — advances lastIndex
const re = /f(\w+)/g;
let m;
while ((m = re.exec("fee fi fo")) !== null) {
  console.log(m[0], m[1], m.index, re.lastIndex);
  // zero-length guard (see §3) not needed here but pattern below shows
  // if (m[0].length === 0) re.lastIndex++;
}
console.log(re.lastIndex); // 0 after failure reset

// test with g advances — hazard (see 4.1)
const g = /ab/g;
console.log(g.test("ab ab"), g.lastIndex); // true 2
console.log(g.test("ab ab"), g.lastIndex); // true 5
console.log(g.test("ab ab"), g.lastIndex); // false 0

// Safe boolean helper
function hasPattern(str, re) { re.lastIndex = 0; return re.test(str); }
console.log(hasPattern("ab ab", /ab/g)); // true — stable
```

### 2) **`search`/`split`/`replace`/`replaceAll` delegation**

**Definition** — these are `String` methods that delegate to `RegExp` if passed a regex: `search` → index (ignores `g`), `split` → array (with capturing groups spliced, `limit` applies), `replace` → one replacement (with `g` replaces all; without `g` replaces first), `replaceAll` → all replacements (string or regex, but regex *must* have `g` — throws otherwise). `replace`/`replaceAll` accept either a replacement string with `$` patterns or a replacer function.

```js
// search — index only, g ignored
console.log("abc 123 def".search(/\d+/)); // 4
console.log("abc 123 def".search(/\d+/g)); // 4 — still 4

// split — string vs regex, capturing groups spliced
console.log("a,b,c".split(",")); // [ 'a','b','c' ]
console.log("a1b2c".split(/\d/)); // [ 'a','b','c' ]
console.log("a1b2c".split(/(\d)/)); // [ 'a','1','b','2','c' ] — capturing inserts
console.log("a1b2c".split(/(\d)/, 3)); // [ 'a','1','b' ] — limit still after splice
console.log("aaa".split("a")); // [ '', '', '', '' ]
console.log("".split(",")); // [ '' ] vs "".split("") => [] (see 2.3)
console.log("".split(/,/)); // [ '' ]
console.log("ab".split(/(?:)/)); // [ 'a','b' ] — non-capturing empty match splits by unit? edge

// split with limit — useful to cap parts
console.log("a,b,c,d".split(",", 2)); // [ 'a','b' ]

// replace — without g replaces first only
console.log("ab ab ab".replace(/ab/, "X")); // "X ab ab"
console.log("ab ab ab".replace(/ab/g, "X")); // "X X X"

// replaceAll — string form replaces all without regex
console.log("ab ab ab".replaceAll("ab", "X")); // "X X X" — string form global
console.log("ab ab ab".replaceAll(/ab/g, "X")); // "X X X"
try { console.log("ab ab".replaceAll(/ab/, "X")); } catch (e) { console.log(e.name); } // TypeError — regex needs g

// replacement patterns vs function (see 5.1 for detail)
console.log("a1 b2".replace(/(\w)(\d)/g, "$2$1")); // "1a 2b" — $ patterns
console.log("a1 b2".replace(/(\w)(\d)/g, (m, p1, p2, off, str) => `${p2}${p1}@${off}`)); // "1a@0 2b@3"
```

### 3) **`exec` loop vs `matchAll` iteration — `lastIndex` advancing and zero-length matches**

**Definition** — both iterate global matches by advancing `lastIndex` to `match.index + match[0].length` on success, `0` on failure. If a match is zero-length (`/^/gm`, `/a*/g`), `exec` auto-bumps `lastIndex` by one *code unit* (or one code point with `u`/`v`) to avoid infinite loop — but the match itself still has length 0. `matchAll` does the same internally.

```js
// Zero-length matches — g auto-bumps to avoid infinite loop
const reZero = /a*/g;
console.log("b".match(/a*/g)); // [ '','', ''? actually "b" => ['','', '']? Let's see
console.log([... "b".matchAll(/a*/g)].map(m => [m[0], m.index]));
// For "b", /a*/g matches "" at 0, "" at 1 — two empty

// Manual exec with zero-length guard (needed for y/sticky or custom loop not using g auto-bump detail)
const star = /a*/g;
const str = "aaab";
let mm;
while ((mm = star.exec(str)) !== null) {
  console.log(`match "${mm[0]}" at ${mm.index} lastIndex ${star.lastIndex}`);
  if (mm[0].length === 0) star.lastIndex++; // manual guard not needed for /g but kept for pattern
  if (star.lastIndex > str.length) break;
}

// y sticky zero-length stays at lastIndex — no forward search, so loop would stall without manual bump
const yStar = /a*/y;
yStar.lastIndex = 0;
console.log(yStar.exec("b"), yStar.lastIndex); // "" at 0, lastIndex 0 — y doesn't bump? Actually y with empty at 0 returns "" and lastIndex stays 0
// Hence y loops need explicit lastIndex++ for empty

// Practical — use matchAll over manual exec for simplicity and cloning safety
const text = "fee fi fo fum";
console.log([...text.matchAll(/\b\w+\b/g)].map(m => m[0])); // [ 'fee','fi','fo','fum' ]
// vs manual
const wordRe = /\b\w+\b/g;
let w;
const out = [];
while ((w = wordRe.exec(text)) !== null) out.push(w[0]);
console.log(out); // same
```

### 4) **Common confusion**

- "`match` with `g` returns groups" — no, groups/index are discarded; use `matchAll` or `exec` loop.
- "`matchAll` returns an array" — no, it returns an *iterator* (spread or `for-of` it).
- "`test` doesn't affect `lastIndex`" — it does with `g`/`y` — shared regex plus `test` causes alternating results.
- "`replace` replaces all" — no, without `g` only first; use `replaceAll` (needs `g` for regex) or `replace` with `/g`.
- "`split` with empty regex vs empty string same" — similar but empty string `""` splits by units (`".split("")"` breaks astral) vs regex empty split nuance.
- "`search` with `g` finds second occurrence" — no, `search` ignores `g` and always from 0.

### 5) **Performance note**

Global matching scans O(n) producing k matches — `matchAll` and `exec` loop are both O(n). Creating the regex inside the loop recompiles each time — hoist. `split` with capturing groups allocates extra entries (k more); avoid capturing `(...)` when you only need delimiter (use `(?:)`). For huge inputs, streaming via `exec` loop can be more memory-efficient than `match(.../g)` which materializes the full array at once.
