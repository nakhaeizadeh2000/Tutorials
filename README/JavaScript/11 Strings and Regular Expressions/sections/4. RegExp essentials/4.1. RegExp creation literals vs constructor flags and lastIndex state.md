## 4.1. RegExp creation literals vs constructor flags and lastIndex state

### 1) **Literal `/pattern/flags` vs `new RegExp(pattern, flags)` and escaping**

**Definition** — `/ab+c/gi` is a regex *literal* parsed at compile time (slash-delimited, escapes differ from string escapes). `new RegExp("ab+c", "gi")` constructs from a string at runtime — so string escaping (`"\\d"` for `\d`, `"\\n"` for newline class) matters. Use literals for static patterns, constructor for dynamic patterns. For user-supplied dynamic literal text, escape with `RegExp.escape` (ES2025 — Baseline 2025, Node 22+ may lack; polyfill otherwise).

```js
// Literal — slash syntax, flags after second slash
const lit = /ab+c/g;
console.log(lit.test("abbbc")); // true
console.log(lit.source, lit.flags); // "ab+c" "g"

// Constructor — string pattern needs double escaping
const cons = new RegExp("ab+c", "g");
console.log(cons.test("abbbc")); // true — same
// String escaping: \d in literal is /\d/ but in string is new RegExp("\\d")
console.log(new RegExp("\\d+").test("123")); // true
console.log(new RegExp("\d+").test("123")); // false — "\d" string is "d" (unknown escape dropped)

// Second arg flags vs inline pattern with flags
console.log(new RegExp(/ab+c/gi).flags); // "gi" — copies when no flags override
console.log(new RegExp(/ab+c/g, "i").flags); // "i" — second arg overrides literal's flags

// Escaping user input for literal use inside a pattern
const user = "a.b*c?d[e]";
const escaped = typeof RegExp.escape === "function"
  ? RegExp.escape(user)
  : user.replace(/[.*+?^${}()|[\]\\]/g, "\\$&"); // fallback — misses some ES2025 edge but close
console.log(escaped); // "a\.b\*c\?d\[e\]" (ES2025 form may use \x escapes for punctuation)
console.log(new RegExp(`^${escaped}$`).test("a.b*c?d[e]")); // true
console.log(new RegExp(`^${escaped}$`).test("axb")); // false

// Bad — without escape wildcard wins
console.log(new RegExp(`^${user}$`).test("axb")); // true — bug: "." wildcard matched "x"

// Literal shorthands vs constructor nuances — "/" must be escaped in literal but not in constructor string form via slash
console.log(/a\/b/.test("a/b")); // true — escaped slash in literal
console.log(new RegExp("a/b").test("a/b")); // true — slash not delimited in string form
```

### 2) **Flags `g` `i` `m` `s` `u` `v` `y` `d` — what each enables**

**Definition** — flags are per-`RegExp` toggles, visible via `flags`/`global`/`ignoreCase`/`multiline`/`dotAll`/`unicode`/`unicodeSets`/`sticky`/`hasIndices`.

| Flag | Name | Effect |
|------|------|--------|
| `g` | global | `exec`/`test` advance `lastIndex`; `match` returns all; `replaceAll` requires `g`; `matchAll` requires `g` |
| `i` | ignoreCase | case-insensitive (`a` matches `A`; unicode case folding with `u`/`v`) |
| `m` | multiline | `^`/`$` match at line boundaries (after `\n`), not just string ends |
| `s` | dotAll | `.` matches `\n` (otherwise `.` is `[^\n]`) — ES2018 |
| `u` | unicode | code-point semantics: `\u{...}`, `\p{}`, `.` = code point, quantifiers by points |
| `v` | unicodeSets | ES2024 superset of `u`: string properties, set notation `&&`/`--`, `\q{…}` string literals |
| `y` | sticky | anchored at `lastIndex` (no forward search) |
| `d` | hasIndices | expose `indices` on match (see [5.1](<../5. Advanced RegExp/5.1. Groups named groups backreferences hasIndices and replacement patterns.md>)) — ES2022 |

`v` and `u` are mutually exclusive (combining throws `SyntaxError`); `v` implies `u` semantics plus sets.

```js
// g global
console.log("ab ab".match(/ab/g)); // [ 'ab','ab' ]
console.log("ab ab".match(/ab/)); // [ 'ab' ] + groups — g changes shape (see 4.2)

// i ignoreCase
console.log(/a/i.test("A")); // true
console.log(/a/u.test("A")); // false — unicode flag alone doesn't imply i

// m multiline ^$
console.log(/^b/m.test("a\nb")); // true — ^ after \n with m
console.log(/^b/.test("a\nb")); // false — ^ only string start without m

// s dotAll
console.log(/a.b/.test("a\nb")); // false — dot misses newline
console.log(/a.b/s.test("a\nb")); // true — dot includes newline

// u unicode — \u{1F600} and \p{}
console.log(/\u{1F600}/u.test("😀")); // true — code-point escape with u
console.log(/^\p{Letter}+$/u.test("café")); // true — unicode property
console.log("😀".length, /./u.test("😀") ? [..."😀"].length : "u needed"); // length 2 but ./u is one point, [] 1

// v unicodeSets — set notation and properties of strings (see 5.2)
if ( (()=>{ try{ new RegExp("a","v"); return true; }catch{return false;}})() ) {
  console.log(/[\p{Letter}--[aeiou]]/v.test("b")); // true — letters minus vowels via v set notation
  console.log(/\p{RGI_Emoji}/v.test("👩‍🚀")); // true — string property via v
} else console.log("v flag not in this runtime (needs Node 20+)");

// y sticky
const sticky = /ab/y;
console.log(sticky.test("ab ab")); // true at 0, lastIndex=2
console.log(sticky.test("ab ab")); // false at 2 is " " not "ab"

// d hasIndices
const withD = /a(b)/d;
const m = withD.exec("ab");
console.log(m.indices); // [ [0,2], [1,2] ] — outer + group 1 start/end (see 5.1)

// Flags are own booleans plus .flags sorted string
const flagRe = /ab/gims; // valid combo without u/v clash — g i m s (dotAll); add y separately if needed
console.log(flagRe.flags); // "gims" — sorted
```

### 3) **`lastIndex` is mutable state — `g`/`y` advance it, others ignore it**

**Definition** — each `RegExp` instance has `lastIndex` (default `0`). With `g` or `y`, `exec`/`test` start at `lastIndex`, write the next start on success, reset to `0` on failure. Without them, `exec`/`test` always search from `0` and ignore `lastIndex`. `String` methods (`search`, `match` without `g`, `replace` without `g`/`y`) ignore `lastIndex`; `matchAll` creates a fresh `RegExp` copy so caller's `lastIndex` is preserved; `replaceAll` with regex requires `g`.

**What problem it solves / history** — `lastIndex` lets one regex iterate over a string (`while (m = re.exec(s))`). The cost is shared-state hazard when the same regex object is reused (see [7.1](<../7. Common pitfalls to production bugs/7.1. Real production bugs caused by string and RegExp mistakes.md>)).

```js
// g advances lastIndex
const gre = /ab/g;
console.log(gre.lastIndex); // 0
console.log(gre.test("ab ab"), gre.lastIndex); // true 2
console.log(gre.test("ab ab"), gre.lastIndex); // true 5
console.log(gre.test("ab ab"), gre.lastIndex); // false 0 — reset on failure
console.log(gre.test("ab ab"), gre.lastIndex); // true 2 — cycles

// Without g/y — lastIndex ignored
const nog = /ab/;
nog.lastIndex = 2;
console.log(nog.test("ab ab"), nog.lastIndex); // true 2 — still true from 0, not mutated

// y sticky — must start exactly at lastIndex
const yre = /ab/y;
yre.lastIndex = 3;
console.log(yre.test("ab ab"), yre.lastIndex); // false 0 — at 3 is " " → fail and reset
yre.lastIndex = 3;
console.log(yre.test("xxabxx")); // false — no forward search even though "ab" at 2

// String methods that ignore lastIndex
const gre2 = /a/g;
gre2.lastIndex = 1;
console.log("aaa".search(gre2), gre2.lastIndex); // 0 1 — search ignores, doesn't mutate
console.log("aaa".match(gre2), gre2.lastIndex); // [ 'a','a','a' ] 0 — match with g resets lastIndex to 0 (spec)
console.log(gre2.test("aaa"), gre2.lastIndex); // true 1 — test advances from 0 -> 1

// matchAll snapshots lastIndex
const mare = /ab/g;
mare.lastIndex = 100; // bogus
console.log([... "ab ab".matchAll(mare)].length, mare.lastIndex); // 2 100 — matchAll didn't mutate caller's lastIndex (spec clones)

// replaceAll requires g — otherwise throws TypeError
try { console.log("ab ab".replaceAll(/ab/, "X")); } catch (e) { console.log(e.name); } // TypeError — replaceAll needs g
console.log("ab ab".replaceAll(/ab/g, "X")); // "X X"

// Advice — reset before reuse or create fresh literal per call
function safeTest(re, s) { re.lastIndex = 0; return re.test(s); }
const shared = /ab/g;
console.log(safeTest(shared, "ab"), safeTest(shared, "ab")); // true true — stable
```

### 4) **Common confusion**

- "`new RegExp(pattern, flags)` needs no escaping" — no, string escapes (`"\d"` → `"d"`) bite; use `"\\d"` or literals.
- "`v` and `u` can combine" — no, they are mutually exclusive; `v` supersets `u`.
- "`lastIndex` is read-only state for `search`/`match`" — no, `search` ignores it; `match` without `g` ignores; `matchAll` clones.
- "`RegExp` literals are recreated each loop iteration" — not per spec: per evaluation, literals create a new `RegExp` object each time the code runs (not shared), but engines may cache shape — still always reset `lastIndex=0`.
- "`replaceAll` with `/ab/` works" — no, it throws without `g`.
- "`sticky` `y` is same as `^` with `g`" — no, `y` anchors at `lastIndex` sliding window; `^` anchors at string start (or line with `m`).

### 5) **Performance note**

Literal patterns are parsed at compile time (fast); constructor patterns parse at runtime (per `new`). Cache constructor `RegExp`s outside loops; reuse avoids recompilation but reintroduces `lastIndex` hazard — reset `lastIndex=0` before reuse or use `String` methods that copy. `v` flag set notation compiles to optimized automata in V8 but broader transitions cost more than simple `u`; measure for huge char classes.

### 6) **Mentor note**

Have juniors write `new RegExp(userInput)` without escape then break it with `a.b` to cement `RegExp.escape`. Show a shared `/ab/g` flipping `true/false` across two `test` calls to teach `lastIndex` state — then fix with `lastIndex=0` or stateless `/ab/`. Flag any `repeat` of `constructor` inside a hot loop (hoist or use literal) and any `replaceAll` with non-`g` regex (will throw).
