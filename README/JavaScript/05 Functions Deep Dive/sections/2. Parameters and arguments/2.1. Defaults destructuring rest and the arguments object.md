## 2.1. Defaults, destructuring, rest, and the arguments object

### 1) **Defaults are per-call expressions with their own scope**

**Definition** — a parameter with `= expr` gets that value *only when the argument is `undefined` (missing or explicitly `undefined`)*, and the expression evaluates fresh on every call with its own mini-scope between parameters:

```js
function greet(name = "world", punctuation = "!") {
  return `hi ${name}${punctuation}`;
}
console.log(greet());               // hi world!
console.log(greet("ada"));          // hi ada!
console.log(greet(undefined, "?")); // hi world? — undefined triggers default
console.log(greet(null, "?"));      // hi null? — null is a real value, no default

// Defaults are live expressions — evaluated per call, outermost-to-innermost
let nextId = 0;
function makeUser(name, id = ++nextId) { return { name, id }; }
console.log(makeUser("ada"), makeUser("grace")); // {name:'ada',id:1} {name:'grace',id:2}
console.log(makeUser("lin", 99));                // {name:'lin',id:99} — supplied value skips increment

// Defaults can see earlier params (but not later ones — TDZ, see [2.2](<./2.2. Arity length and edge cases.md>))
function withContext(a, b = a * 2) { return b; }
console.log(withContext(5), withContext(5, 7)); // 10 7

// Defaults that must throw on missing — idiomatic required marker
function required() { throw new Error("missing required argument"); }
function connect(host = required(), port = 80) { return `${host}:${port}`; }
console.log(connect("example.com")); // example.com:80
try { connect(); } catch (e) { console.log(e.message); } // missing required argument
```

- *History* — before defaults, every function body repeated `if (x === undefined) x = defaultValue;` — easy to mistype as `x || default` and clobber valid falsy values ([coercion pitfalls](<../../../03 Values Types and Coercion/sections/7. Common pitfalls to production bugs/7.1. Real production bugs caused by coercion.md>)).

### 2) **Destructuring and rest in parameter lists**

Parameters can destructure and collect — the parameter list is a pattern:

```js
// Object destructuring with defaults — note outer {} default to handle missing arg
function draw({ x = 0, y = 0, color = "black" } = {}) {
  return `${color} at ${x},${y}`;
}
console.log(draw({ x: 10 })); // black at 10,0
console.log(draw());          // black at 0,0 — outer ={} prevents "cannot destructure undefined"
try { draw(null); } catch (e) { console.log(e.name); } // TypeError — null not destructurable

// Required-field pattern via throw in default position
function createUser({ name = required(), role = "viewer" } = {}) { return { name, role }; }
console.log(createUser({ name: "ada" })); // { name: 'ada', role: 'viewer' }
try { createUser({}); } catch (e) { console.log(e.message); } // missing required argument

// Array destructuring
function head([first, ...rest]) { return { first, rest }; }
console.log(head([1, 2, 3])); // { first: 1, rest: [ 2, 3 ] }

// Rest parameter — must be last, collects remaining args into a true Array
function sum(...nums) { return nums.reduce((a, b) => a + b, 0); }
console.log(sum(1, 2, 3, 4)); // 10
console.log(sum());           // 0 — empty array, not undefined
function log(level, ...msgs) { console.log(level, msgs.join(" ")); }
log("info", "server", "ready", "on", "3000"); // info server ready on 3000

// Rest vs spread at call site — mirror operations
function join(a, b, c) { return [a, b, c].join("-"); }
const args = [1, 2, 3];
console.log(join(...args)); // 1-2-3 — spread expands, rest collects
```

- Outer default (`= {}` / `= []`) is not optional sugar — without it, `draw()` would throw on destructuring `undefined`; with it, missing argument falls back to an empty object that yields per-field defaults.

### 3) **`arguments` vs rest: the legacy exotic object**

`arguments` is array-like but not an Array, exists only in non-arrow functions, and in sloppy mode aliases named parameters — rest replaces it in modern code:

```js
// arguments: exotic object with indexed access + length, without array methods
function legacy() {
  console.log(arguments.length, arguments[0]);
  console.log(Array.isArray(arguments));     // false
  console.log(arguments instanceof Array);   // false
  // borrow array methods via spread or from
  const firstTwo = [...arguments].slice(0, 2);
  console.log(firstTwo);
}
legacy("a", "b", "c"); // 3 a [ 'a', 'b' ]

// Sloppy mode: arguments aliases params (writing one mutates the other) — bug source
function sloppyAlias(a) {
  arguments[0] = 99;
  console.log(a); // 99 — linked in sloppy mode
}
sloppyAlias(1);

function strictAlias(a) {
  "use strict";
  arguments[0] = 99;
  console.log(a); // 1 — not linked
}
strictAlias(1);

// Strict/rest mode removes the alias entirely
function withRest(a, ...rest) {
  console.log(rest, rest.length);
}
withRest(1, 2, 3); // [ 2, 3 ] 2

// Arrows have no own arguments — lexical lookup (intentionally absent)
function outerArrow() {
  const arrow = (...args) => args; // use rest instead
  return arrow(1, 2);
}
console.log(outerArrow(), typeof outerArrow); // [ 1, 2 ] function
```

### 4) **Common confusion**

- "`param = default` triggers on `null`/`0`/`""`" — no; only `undefined` (missing or explicit). Use `??` inside body for nullish coalescing if `null` should also default.
- "Destructured param already has a default, so `fn()` is safe" — not without `= {}` on the outer param; missing argument means destructure `undefined` → TypeError.
- "`arguments` is an array, just use `.map`" — it isn't; spread or `Array.from(arguments)` first, or use rest.
- "Arrows can read `arguments` of the call they are in" — they close over the *enclosing non-arrow's* `arguments`; in a top-level arrow there is none → ReferenceError.

### 5) **Performance note**

Defaults and destructuring add per-call setup (allocate the default object, evaluate expressions). In tight loops calling `f()` millions of times with no argument, the `= {}` allocation per call can show up — hoist a frozen sentinel (`const EMPTY = Object.freeze({})`) only if profiling shows it. Rest params allocate an array per call; for variadic hot paths, fixed-arity + indexed access is cheaper — [measure](<../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md>).

### 6) **Mentor note**

Review checklist: (a) does every destructured param have an outer `= {}` / `= []` if callers may omit it? (b) does any default reference a later param (TDZ — [2.2](<./2.2. Arity length and edge cases.md>))? (c) does any function still read `arguments` where rest would be clearer and arrow-safe? Enforce `prefer-rest-params` lint rule.
