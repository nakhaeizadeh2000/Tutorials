## 1.3. Methods, getters, setters, and the function object

### 1) **Method definitions vs function-valued properties**

**Definition** — an *object method* is a function that lives as a property and, when called through that object, receives the object as `this` ([call-site rules](<../3. this binding/3.1. Call-site rules default implicit explicit new and strict mode.md>)). ES2015 added *concise method* syntax whose sole super-power is allowing `super`:

```js
const base = { greet() { return "hi"; } };
const child = {
  // concise method — can use super
  greet() { return super.greet() + " there"; },
  // function-valued property — cannot use super (SyntaxError if you try)
  greetFn: function () { return "fn"; },
  // arrow as property — lexical this, never dynamic (see [1.2](<./1.2. Arrow functions syntax what they lack and when to use each.md>))
  arrow: () => "arrow",
};
Object.setPrototypeOf(child, base);
console.log(child.greet()); // hi there
console.log(child.greetFn()); // fn
console.log(typeof child.arrow); // function

// Computed method names — property keys computed at definition time
const key = "toString";
const obj = {
  [key]() { return "computed"; },
  ["_" + key]() { return "also computed"; },
};
console.log(obj.toString(), obj._toString()); // computed also computed

// Methods on classes behave the same — concise methods on the prototype
class Counter {
  count = 0;
  inc() { this.count += 1; return this.count; }
}
console.log(typeof Counter.prototype.inc, new Counter().inc()); // function 1
```

- *Why concise syntax matters* — it exists for one reason: `super` is only legal inside concise methods (and `get`/`set`/`class` methods). If you need `super`, you must use that shape; otherwise both spellings create a function-valued property whose call-site `this` is dynamic.
- `this` is not set at definition time — detaching a method loses it (→ [3.1](<../3. this binding/3.1. Call-site rules default implicit explicit new and strict mode.md>)):

```js
const c = new Counter();
const detached = c.inc;
try { console.log(detached()); } catch (e) { console.log(e.name); } // TypeError — class methods are strict: this is undefined
console.log(detached.call(c)); // 1 — explicit binding restores it
```

### 2) **`name`, `length`, `prototype`, and the `Function` constructor**

Every function object carries reflective metadata:

```js
// name — inferred from syntax or explicit NFE name; "anonymous" only when truly anonymous
function declaredFunc() {}
const viaConst = function () {};
const viaNFE   = function innerName() {};
const viaArrow = () => {};
console.log(declaredFunc.name, viaConst.name, viaNFE.name, viaArrow.name);
// declaredFunc viaConst innerName viaArrow  — inference from variable name (ES2015)

// length — number of params BEFORE first default/rest/destructuring (→ [2.2](<../2. Parameters and arguments/2.2. Arity length and edge cases.md>))
function arity(a, b, c = 1, d) {}
console.log(arity.length); // 2 — stops at first default c

// prototype — only functions with [[Construct]] have it (constructible functions)
// arrows and concise methods on objects that are not constructor-like may lack construct semantics
function Ctor() {}
const arrow = () => {};
console.log(typeof Ctor.prototype, typeof arrow.prototype); // object undefined
console.log(typeof Ctor.prototype.constructor); // function
try { new arrow(); } catch (e) { console.log(e.name); } // TypeError

// Function constructor — parses strings as function body; inherits global scope, NOT closure scope
const add = new Function("a", "b", "return a + b;");
console.log(add(2, 3)); // 5
function closureDemo() {
  const secret = 42;
  const fn = new Function("return secret;"); // no closure capture!
  try { console.log(fn()); } catch (e) { console.log(e.name); } // ReferenceError
}
closureDemo();
```

- `new Function` is `eval` in a trenchcoat: it parses at runtime, defeats JIT, and opens injection. Linters flag it; CSP may block it. Never use it for templating.

### 3) **Getters/setters are accessor descriptors, not methods**

Accessors look like methods but are *property descriptors* invoked on property access, not on call:

```js
const user = {
  _name: "Ada",
  get name() { console.log("get"); return this._name; },
  set name(v) { console.log("set", v); this._name = v; },
};
console.log(user.name); // get → Ada  (no parentheses!)
user.name = "Grace";    // set Grace
console.log(Object.getOwnPropertyDescriptor(user, "name"));
// { get: [Function: get name], set: [Function: set name], enumerable: true, configurable: true }

// Accessors on classes — same descriptor, on prototype
class Rect {
  constructor(w, h) { this.w = w; this.h = h; }
  get area() { return this.w * this.h; }
}
console.log(new Rect(3, 4).area); // 12 — no call needed
console.log(Object.getOwnPropertyDescriptor(Rect.prototype, "area").get !== undefined); // true

// Pitfall: getter that throws or has side effects — access is now computation
const risky = {
  get now() { return Date.now(); },
};
console.log(typeof risky.now, typeof risky.now); // number number — different each access
```

### 4) **Common confusion**

- "`obj.method` and `obj.prop = function(){}` are identical" — almost, but only concise methods allow `super`; otherwise identical creation semantics.
- "`fn.length` is the number of arguments passed" — no; it's the *declared* arity before first tricky param ([2.2](<../2. Parameters and arguments/2.2. Arity length and edge cases.md>)); `arguments.length` or rest array gives call-time count.
- "`Function('return x')` sees closure variables" — it doesn't; its scope chain is global only — closure capture is lexical, constructor parsing is not.
- "Getters are called like `obj.getter()`" — invoking with `()` would try to call the *return value*, not the getter; access is `obj.prop`.

### 5) **Performance note**

Method dispatch is a property lookup + call; engines inline monomorphic call sites. `name` and `length` are cheap reads (stored on the function object). Constructing functions via `new Function` forces a full parse per construction — orders of magnitude slower than a declaration and blocks optimization — avoid in hot paths entirely. For class instances, prototype methods are shared; per-instance arrow properties (`this.method = () =>`) allocate per instance — trade memory for lexical `this` as needed ([1.2](<./1.2. Arrow functions syntax what they lack and when to use each.md>)).

### 6) **Mentor note**

In review, ask "does this method use `super` or need `this` rebinding?" — if yes, it must be a concise method; an arrow class field there is a bug (lexical `this` = constructor instance, `super` illegal). Flag any `new Function(` or `Function(` with dynamic strings — propose a closure or lookup table.
