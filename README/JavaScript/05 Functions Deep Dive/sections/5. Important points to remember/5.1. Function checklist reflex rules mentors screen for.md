## 5.1. Function checklist: reflex rules mentors screen for

### 1) **The three reflexes that explain most function bugs**

1. **Defaults at the boundary, not `||` inside** — convert at function entry (`x = defaultValue` when `undefined`, or `x ?? defaultValue` when nullish); body sees clean values.
2. **`this` at call site, not definition site** — ask "how was it *called*?" (`obj.fn()` → `obj`, `fn()` → default, `fn.call(x)` → `x`, `new F` → fresh object, arrow → lexical).
3. **Arrows capture `this`, functions receive it** — callbacks inside methods that need outer `this` → arrows; methods that callers invoke as `obj.method()` → functions/concise methods.

```js
// Reflex demo — three questions, three answers
function defaultsDemo(x = 1) { return x; }
console.log(defaultsDemo(), defaultsDemo(undefined), defaultsDemo(null)); // 1 1 null — only undefined triggers default

function thisDemo() { return this; }
console.log(thisDemo.call({ id: 1 }).id); // 1 — explicit
console.log((() => this).call({ id: 1 }) === this); // true — arrow's this ignores call

const outer = { id: "outer", run() { return (() => this.id)(); } };
console.log(outer.run()); // outer — arrow healed
```

### 2) **The reflex answers — compressed**

| Prompt | Answer |
|--------|--------|
| `function f(a = b, b = 1)` called as `f()` | ReferenceError — `b` TDZ (later defaults not in scope) |
| `fn.length` for `(a, b=1, c)` | `1` — stops at first default; call-time count is `arguments.length` / rest |
| `obj.method` passed to `map` | loses `this` → `TypeError`; fix with `map(x => obj.method(x))` or `map(obj.method.bind(obj))` |
| `call(null)` on strict vs sloppy | strict `null` stays `null`; sloppy coerces to `globalThis` |
| `() => this` inside `method()` | `this` is method's `this`, not caller's; `call`/`bind` ignored |
| `bind` then `call` tries to rebind | ignored — first `bind` is permanent |
| `(x => {x: x})(1)` vs `(x => ({x}))` | first returns `undefined` (labeled block), second returns `{x}` |

### 3) **What to grep for in code review**

```
prefer-const / no-var                 — declaration hygiene (→ [Variables §1.1](<../../../04 Variables Scope and Closures/sections/1. Declarations and bindings/1.1. var let const mechanics and when each is still defensible.md>))
func-style (declaration vs expression) — top-level API = declaration, conditional = const expression
prefer-rest-params / no-arguments    — rest over arguments
arrow-body-style / no-confusing-arrow — concise-body object parens
no-invalid-this / no-arrow-as-method — method: () => this bug
max-params / complexity               — functions >4 params → object param with destructuring
```

- *Lint mapping:* `eqeqeq` already handled equality elsewhere; for functions enforce `prefer-arrow-callback` where lexical `this` is desired, but *disable* it for methods needing dynamic `this`.
- *Review signals:* detached method without `bind`/`arrow` wrapper; `bind` inside a loop (hoist); `arguments` in an arrow's lexical scope (should be rest); missing outer `= {}` on destructured params; recursion depth tied to user input length.

### 4) **When to prefer which form — the decision table**

| Need | Form | Why |
|------|------|-----|
| Stable top-level helper | `function name(){}` | hoisted, stack traces with name, `this` dynamic if method |
| Conditional / callback value | `const fn = (...) =>` or `function(){}` | expression timing, TDZ-controlled |
| Self-reference without outer pollution | `const f = function self(){}` NFE | inner name only inside |
| Lexical `this` callback | `() =>` | captures surrounding `this`, concise |
| Object/prototype method, constructor | `method(){}` / `function` | dynamic `this`, `super`, constructible |
| Bound callback stored in state | `fn.bind(obj)` once, or `(...args)=>fn.call(obj,...)` | permanent `this`, hoist allocation |
| One-off private scope | `{ ... }` block or ESM; IIFE only if async/once | narrower, no function allocation |
