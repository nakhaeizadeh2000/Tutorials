## 3.3. call, apply, bind, and bound functions

### 1) **`call`/`apply` invoke with explicit `this`**

**Definition** — `fn.call(thisArg, a, b)` and `fn.apply(thisArg, [a, b])` invoke `fn` *immediately* with `this` set to `thisArg` (coercion rules → [3.1](<./3.1. Call-site rules default implicit explicit new and strict mode.md>)). The only difference is how arguments are supplied:

```js
function greet(greeting, punctuation) { return `${greeting}, ${this.name}${punctuation}`; }
const user = { name: "Ada" };

console.log(greet.call(user, "hi", "!"));      // hi, Ada!
console.log(greet.apply(user, ["hey", "?"]));  // hey, Ada?

// Spread makes apply redundant in modern code — prefer call + spread
const args = ["yo", "."];
console.log(greet.call(user, ...args));        // yo, Ada.

// null/undefined this handling (strict vs sloppy → [3.1](<./3.1. Call-site rules default implicit explicit new and strict mode.md>))
function check() { "use strict"; return this; }
console.log(check.call(null) === null);        // true — strict preserves null
function sloppyCheck() { return this === globalThis; }
console.log(sloppyCheck.call(null));           // true — sloppy coerces to globalThis

// Boxing difference — primitives become objects only in sloppy call
function kind() { return this; }
console.log(typeof kind.call(42));                    // object — sloppy boxing
function strictKind() { "use strict"; return this; }
console.log(typeof strictKind.call(42));              // number — strict preserves primitive

// Borrowing methods — the classic use site
const hasOwn = (obj, key) => Object.prototype.hasOwnProperty.call(obj, key);
console.log(hasOwn({ a: 1 }, "a"), hasOwn({}, "a")); // true false
console.log(Array.prototype.slice.call({ 0: "x", 1: "y", length: 2 })); // [ 'x', 'y' ]
```

- *History* — `apply` existed to forward an unknown-arity argument array before spread; today `fn(...args)` plus `call` covers it with less indirection.

### 2) **`bind` creates a bound-function exotic object — permanent `this` plus partial application**

`bind` does *not* call; it returns a new function whose `this` parameter is fixed forever (arrows never, bound functions always):

```js
function log(msg) { return `${this.prefix}: ${msg}`; }
const svc = { prefix: "app" };
const boundLog = log.bind(svc);

console.log(boundLog("ready"));                // app: ready
console.log(boundLog.call({ prefix: "other" }, "hi")); // app: hi — call cannot override bound this
console.log(boundLog !== log);                 // true — a new exotic object

// Partial application — bind prepends arguments (currying lite)
function add(a, b, c) { return a + b + c; }
const add10 = add.bind(null, 10);
console.log(add10(5, 6));                      // 21 — 10 + 5 + 6
console.log(add10.length);                     // 2 — length reduced by bound arg count (original 3 - 1)
const add10_5 = add.bind(null, 10, 5);
console.log(add10_5(6), add10_5.length);       // 21 1

// length adjustment and name
function orig(a, b, c) {}
const bound = orig.bind(null, 1);
console.log(bound.length);                     // 2 — max(0, orig.length - boundArgs)
console.log(bound.name);                       // bound orig — name prefixed

// new with a bound function — bound this is ignored, but bound args still prepend
function Point(x, y) { this.x = x; this.y = y; }
const YAxisPoint = Point.bind(null, 0);       // first arg (x) fixed to 0
const p = new YAxisPoint(5);
console.log(p.x, p.y, p instanceof Point, p instanceof YAxisPoint); // 0 5 true true

// Arrow + bind interaction: bind cannot rebind an arrow (lexical this wins)
const arrow = () => this;
const boundArrow = arrow.bind({ id: "nope" });
console.log(boundArrow() === arrow());         // true — bind ignored on arrows
```

- Bound-function invariants: `this` parameter lost at creation; cannot be re-bound by `call`/`apply`; still constructible with `new` (when target is constructible) — spec `BoundFunctionCreate` step that creates a fresh `this` for `new` and ignores the bound `thisArg`.

### 3) **Choosing between three tools**

```js
// One-shot borrow → call
const nums = [3, 1, 4];
console.log(Math.max.call(null, ...nums));     // 4 — call + spread

// Dynamic arity forward → apply (legacy) or call + spread (modern)
function forward(fn, thisArg, args) {
  return fn.apply(thisArg, args);             // args is an array-like
}
function forwardModern(fn, thisArg, args) {
  return fn.call(thisArg, ...args);
}
console.log(forward(Math.max, null, [1, 2, 3]), forwardModern(Math.max, null, [1, 2, 3])); // 3 3

// Reusable callback → bind (but hoist outside hot loops — allocation per bind)
class Btn {
  constructor(label) { this.label = label; }
  click() { return this.label; }
}
const btn = new Btn("save");
const handlers = [btn.click.bind(btn), btn.click.bind(btn)];
console.log(handlers[0](), handlers[1]()); // save save — two distinct bound functions

// Avoiding bind in hot paths — prefer arrow wrapper hoisted
const boundOnce = btn.click.bind(btn);       // one allocation
console.log(boundOnce(), boundOnce());       // save save

// Alternatives to bind for partial application — arrow closure (clearer arity, no this side-effect)
const add2 = (b, c) => add(10, b, c);
console.log(add2(5, 6));                     // 21

// What bind cannot do — unbind
const onceBound = log.bind(svc);
const reBound = onceBound.bind({ prefix: "other" });
console.log(reBound("hi"));                  // app: hi — re-bind ignored, first bind is permanent
```

- *Guidance* — use `call` for one-off borrowing; `apply` only when you already hold an arguments array and can't spread (rare post-ES6); `bind` for durable callbacks stored in state (`addEventListener`, timers, promises) — but allocate once and reuse, and prefer arrow wrappers when `this` is not the point and you just need args currying (no `this` parameter to reason about).

### 4) **Common confusion**

- "`bind` mutates the original function" — no; it returns a *new* exotic function; `orig` is untouched.
- "`bind` then `call` re-binds" — never; first bound `this` is permanent; later `call` supplies only arguments.
- "`apply(null, args)` passes `null` as `this`" — strict preserves `null`, sloppy coerces to `globalThis` ([3.1](<./3.1. Call-site rules default implicit explicit new and strict mode.md>)); for `this`-agnostic functions prefer `call(undefined, ...args)` or just `fn(...args)`.
- "Arrows benefit from `bind` for `this`" — `bind` on arrows is silently ignored; use a wrapper or reconsider the shape.

### 5) **Performance note**

`bind` allocates a bound-function exotic (plus closure over args) — per-iteration `arr.map(fn.bind(this))` allocates N exotics, while `arr.map(x => fn.call(this, x))` allocates N arrows (similar). Allocation dominates; hoist `const bound = fn.bind(this)` out of loops. `call`/`apply` with primitive `this` trigger boxing only in sloppy functions — keep hot helpers strict — [measure](<../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md>).

### 6) **Mentor note**

In review, treat every `x.bind(y)` as a question: "does anyone ever `call`/`apply` that result expecting to override `this`?" If yes, it's a bug — bound `this` is permanent. Ask juniors to implement `bind` in 5 lines (`(...args) => fn.call(thisArg, ...boundArgs, ...args)`) to demystify it — then point out the missing `new` and `length`/`name` fidelity as why spec's exotic matters.
