## 3.1. Call-site rules: default, implicit, explicit, new — and strict mode

### 1) **Four rules and their precedence**

**Definition** — every non-arrow function receives `this` from its *call site*, not its definition site. Think of `this` as a hidden first parameter passed at call time; four rules decide its value, later rules win when multiple apply:

| Rule | Call shape | `this` value | Wins over |
|------|-----------|-------------|-----------|
| Default | `fn()` | `undefined` (strict) / `globalThis` (sloppy) | — |
| Implicit | `obj.fn()` | `obj` (the receiver before the `.`) | Default |
| Explicit | `fn.call(obj)`, `fn.apply(obj, [])`, `fn.bind(obj)()` | `obj` (first arg; sloppy boxes primitives & coerces `null`/`undefined` → globalThis; strict preserves as-is) | Implicit, Default |
| `new` | `new Fn()` | freshly allocated object linked to `Fn.prototype` | All others |

```js
function show() { return this; }

// 1) Default — sloppy vs strict diverge
function sloppy() { return this === globalThis; }
function strict() { "use strict"; return this === undefined; }
console.log(sloppy(), strict()); // true true — sloppy defaults to globalThis, strict to undefined

// 2) Implicit — receiver before the dot becomes this
const obj = { id: "obj", show };
console.log(obj.show().id); // obj — this is obj
const detached = obj.show;
console.log(detached() === globalThis || detached() === undefined); // true — default takes over

// 3) Explicit — call/apply/bind override implicit (→ [3.3](<./3.3. call apply bind and bound functions.md>))
console.log(show.call({ id: "explicit" }).id); // explicit

// 4) new — constructs a new object; explicit this is ignored on bound functions (→ [3.3](<./3.3. call apply bind and bound functions.md>))
function Ctor(name) { this.name = name; }
const inst = new Ctor("ada");
console.log(inst.name, inst instanceof Ctor); // ada true
console.log(Ctor === inst.constructor);       // true — via prototype link

// Precedence: new > explicit > implicit > default — even when spelled implicitly
const other = { id: "other" };
function Foo(val) { this.val = val; return this; }
const Bound = Foo.bind({ id: "bound" });
const viaNew = new Bound(42);
console.log(viaNew.val, viaNew.id); // 42 undefined — new wins over bound's this
```

- The single-model mental check: "which rule does *this particular `()`* use?" — dot before parens → implicit; `call`/`apply`/`bind` → explicit; `new` before call → new; naked `()` → default.

### 2) **Strict vs sloppy default divergence — and boxing**

```js
// Boxing: call()/apply() with a primitive boxes it; default with primitive via call uses the primitive wrapper
function kind() { return typeof this + ":" + String(this); }
console.log(kind.call(42).startsWith("object:"));        // true — boxed Number
console.log(kind.call("hi").startsWith("object:"));      // true — boxed String
console.log(kind.call(null) === kind.call(undefined));   // true-ish: both → globalThis/undefined per default rule
// Exact null/undefined handling:
function checkNull() { "use strict"; return this; }
console.log(checkNull.call(null) === null);              // true — strict: null stays null, not coerced
console.log(typeof checkNull.call(42) === "number");     // true — strict: primitives stay primitive (no boxing)
console.log(typeof checkNull.call("hi") === "string");   // true — strict preserves primitives
function checkSloppy() { return this; }
console.log(checkSloppy.call(null) === globalThis);      // true — sloppy: null → globalThis
console.log(checkSloppy.call(42) instanceof Number);     // true — sloppy boxes primitives

// Method borrowing only works when this-shape matches
const arrLike = { 0: "a", 1: "b", length: 2 };
console.log(Array.prototype.join.call(arrLike, "-")); // a-b — join borrows this as array-like

// Arrow as method property never participates — lexical this wins (→ [3.2](<./3.2. Arrow lexical this and why callbacks break or heal.md>))
const counter = {
  value: 0,
  inc: () => { return this; }, // top-level this (undefined in modules, globalThis in sloppy scripts)
};
console.log(counter.inc() === globalThis || counter.inc() === undefined); // true — arrow ignored implicit rule
```

- Why strict changed default: silent global mutation (`this.x = 1` creating `globalThis.x`) became the top bug class in early JS; strict makes it a TypeError/nop by binding `this` to `undefined`.

### 3) **Common "lost `this`" sites and the fix taxonomy**

Every lost-`this` is implicit → default when the receiver is dropped:

```js
class Service {
  constructor(prefix) { this.prefix = prefix; }
  log(msg) { return `${this.prefix}: ${msg}`; }
}
const svc = new Service("app");

// Site 1: detached method
const fn = svc.log;
try { console.log(fn("hi")); } catch (e) { console.log(e.name); } // TypeError — this is undefined

// Site 2: callback — Array iterator detaches
const names = ["a", "b"];
try { console.log(names.map(svc.log)); } catch (e) { console.log(e.name); } // TypeError on each

// Fixes — pick one:
console.log(names.map((n) => svc.log(n)));        // arrow closes over svc lexically
console.log(names.map(svc.log.bind(svc)));        // explicit permanent this (→ [3.3](<./3.3. call apply bind and bound functions.md>))
console.log(names.map(function (n) { return svc.log(n); }.bind(svc))); // manual wrapper
console.log(names.map(svc.log, svc));             // thisArg where API offers it (Array methods do)

// Site 3: nested function inside method — inner function's this is default, not outer's this
const obj2 = {
  id: "obj2",
  outer() {
    function inner() { return this; }
    const arrow = () => this;
    console.log(inner() === undefined || inner() === globalThis); // true — default
    console.log(arrow() === obj2); // true — arrow captured outer's this
  },
};
obj2.outer();
```

- Recognize the shape: `something.method` passed *without* `()` is a value, not a call — the call site that eventually adds `()` decides `this`. If that later site is naked (`fn()`), you get default.
- Fix hierarchy: arrow wrapper (lexical) > `bind` (explicit permanent) > `thisArg` param where available; avoid `var self = this` in modern code (arrow expresses it directly).

### 4) **Common confusion**

- "`this` is where the function is defined" — opposite: defined lexically (closure), `this` passed at call. Only arrows tie the two together.
- "`obj.fn()` always makes `this` = `obj`" — only for that call; `const f = obj.fn; f()` drops the receiver and falls to default.
- "`call(null)` makes `this` = `null`" — only in strict functions; sloppy substitutes `globalThis` (a classic bug when libraries mix modes).
- "`new` and `call` combine to let you pick `this` for constructors" — no; `new Bound(...)` ignores the bound `this` and constructs a fresh object (binding only supplies partial args).

### 5) **Performance note**

`this` binding itself is zero-cost (a register fill at call). Indirect via `call`/`apply` can inhibit inlining but is negligible off hot paths. Excessive `bind` in loops allocates a new bound-function exotic per iteration — hoist `const bound = fn.bind(obj)` outside loops. Prefer `thisArg` or arrow wrappers where micro-optimizing hot `map`/`forEach` — [measure](<../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md>).

### 6) **Mentor note**

Ask trainees to narrate each `()` with rule name + precedence: " `obj.fn()` → implicit; `fn()` → default; `fn.call(x)` → explicit beats implicit; `new Bound()` → new beats explicit". If they can name the winning rule before predicting the value, lost-`this` bugs vanish. In review, grep patterns `\.map\(.*\bthis\b` / bare method references `onClick={this.handle}` / `setTimeout(this.method` — flag each; require arrow, bind, or `thisArg`.
