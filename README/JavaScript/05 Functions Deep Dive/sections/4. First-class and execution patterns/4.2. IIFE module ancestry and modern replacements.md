## 4.2. IIFE, module ancestry, and modern replacements

### 1) **Why IIFE existed — three pre-ES2015 problems it solved**

**Definition** — an *Immediately Invoked Function Expression* `(function(){...})()` defines a function and calls it in one stroke, creating a fresh scope that runs exactly once and (optionally) returns a public API. Before `let`/`const` and ESM, this was the only way to get private state:

```js
// Problem 1: var leaks through blocks — IIFE gave a private scope
var count = 0; // would leak to globalThis in scripts; IIFE contained it
const counter = (function () {
  let privateCount = 0; // truly private — only closures inside see it
  return {
    inc() { return ++privateCount; },
    get() { return privateCount; },
  };
})();
console.log(counter.inc(), counter.inc(), counter.get()); // 1 2 2
console.log(typeof privateCount); // undefined — not leaked

// Problem 2: loop-capture fix before let (→ [Variables §3.2](<../../../04 Variables Scope and Closures/sections/3. Closures/3.2. Loops and closures var let and per iteration capture.md>))
const fns = [];
for (var i = 0; i < 3; i++) {
  fns.push((function (c) { return () => c; })(i)); // IIFE captures per-iteration copy
}
console.log(fns.map((f) => f())); // [ 0, 1, 2 ] — vs [ 3, 3, 3 ] without IIFE

// Problem 3: library namespace before modules — the "module pattern"
const MathUtils = (function () {
  const secretFactor = 1.5; // private
  function scale(n) { return n * secretFactor; }
  return { scale };
})();
console.log(MathUtils.scale(10)); // 15
console.log(typeof MathUtils.secretFactor); // undefined
```

- The shape generalized into UMD wrappers that sniffed `define`/`module.exports`/`global` — readable archaeology, not modern code.

### 2) **IIFE forms and the semicolon / ASI hazard**

IIFE requires the function to be parsed as an *expression*, not a declaration:

```js
// Two canonical paren placements — equivalent
const a = (function () { return 1; })();
const b = (function () { return 2; }());
console.log(a, b); // 1 2

// Unary-prefix tricks — also expressions, but obscure (avoid in modern style)
const c = !function () { return false; }(); // true — ! coerces return
console.log(c); // true

// Arrow IIFE — concise, lexical this (usually irrelevant)
const d = (() => 42)();
console.log(d); // 42

// ASI trap: a line starting with ( or [ continues the previous statement
const x = 1
// (function () { console.log("continuing"); })(); // ← parsed as call on `1`
// Fix: always semicolon-terminate the previous line, or prefix IIFE with ;
;(function () { console.log("safe with leading semicolon"); })();

// Named IIFE — name visible only inside, useful for stack traces
const e = (function namedIIFE() { return namedIIFE.name; })();
console.log(e); // namedIIFE

// Async IIFE — top-level await replacement where unavailable (→ Modules/Async domains, textual forward refs)
;(async () => {
  const v = await Promise.resolve(10);
  console.log(v); // 10
})();
```

### 3) **Modern replacements — block scope, ESM, and when an IIFE still earns its keep**

| Historical use | Modern spelling | Note |
|---------------|----------------|------|
| Private scope | `{ let x; ... }` block + `let`/`const` | block is the scoping unit now |
| Loop capture | `let`/`const` in `for` head | per-iteration binding guaranteed by spec |
| Module namespace | ES modules (`export`/`import`) | static, tree-shakeable, no runtime wrapper |
| Library UMD | `import`/`export` + bundler | bundler emits wrapper; author doesn't |
| One-off async work | top-level `await` in ESM (ES2022) | no wrapper needed |

```js
// Block replaces IIFE for one-off scoping — no function needed
{
  const tmp = 42;
  console.log(tmp); // 42
}
// console.log(tmp); // ReferenceError — block-scoped

// Module replaces IIFE for namespaces — file: utils.mjs (illustration)
// export const factor = 1.5;
// export function scale(n) { return n * factor; }
// import { scale } from "./utils.mjs";

// When an IIFE is still defensible:
 // 1) Computed default in a parameter that needs a fresh object per evaluation context
function withFreshMap(map = (() => new Map())()) { return map; }
console.log(withFreshMap() instanceof Map); // true

// 2) One-shot initialization that needs cleanup scoping without polluting outer
const singleton = (() => {
  const cache = new Map();
  return (k, v) => (cache.has(k) ? cache.get(k) : cache.set(k, v).get(k));
})();
console.log(singleton("a", 1), singleton("a", 99)); // 1 1 — cached
```

- Guidance: read IIFEs fluently (legacy code, minifiers), write blocks or modules instead; reserve the form for genuinely once-evaluated initialization or async IIFEs where top-level await isn't available.

### 4) **Common confusion**

- "`function(){...}()` at statement start is an IIFE" — no; `function` at statement level is a declaration and `()` is a SyntaxError — must be in expression position (`(` or `=` before it).
- "IIFEs are always better than blocks for privacy" — blocks are clearer and don't create a function object; use the narrower tool.
- "Missing semicolon before IIFE is harmless" — the following `(...)` continues the previous line as a call (ASI hazard); always terminate the line before or prefix IIFE with `;`.
- "Async IIFE is the only way to use `await` at top level" — ESM top-level await replaced it where supported (Node 14.8+, modern browsers).

### 5) **Performance note**

IIFE creation is one function allocation + immediate call — identical to any other function, freed after return unless closures escape. Legacy IIFE-based libraries paid this per-file; ESM has no wrapper overhead. Async IIFE adds a promise allocation — negligible for initialization but visible in microbenchmarks — [measure](<../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md>).

### 6) **Mentor note**

Ask a junior to explain why `for (var i ...)` + IIFE fixes loop capture — the answer must name "new environment per call". Then show `for (let i ...)` and ask what's gone — the IIFE. In review, flag any new IIFE that wraps a plain block (`(function(){ let x; })()` → `{ let x; }`) and any file starting with `(function(` that could be an ESM module.
