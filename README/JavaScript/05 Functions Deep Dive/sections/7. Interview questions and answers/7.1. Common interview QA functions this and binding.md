## 7.1. Common interview Q&A: functions, this, and binding

### 1) **Q&A**

1. **Q: What is `this` and when is it decided?**
   **A:** `this` is a hidden parameter set at *call time* by the call site (`obj.fn()` → `obj`, `fn()` → default, `fn.call(x)` → `x`, `new F()` → fresh object). Arrow functions are the exception — they have no own `this` and resolve it lexically like a variable ([3.1](<../3. this binding/3.1. Call-site rules default implicit explicit new and strict mode.md>) / [3.2](<../3. this binding/3.2. Arrow lexical this and why callbacks break or heal.md>)).

2. **Q: Trace the output:**
   ```js
   const obj = { value: 10, get() { return this.value; } };
   console.log(obj.get());
   const fn = obj.get;
   console.log(fn());
   console.log(fn.call({ value: 42 }));
   ```
   **A:** `10` (implicit), `TypeError` or `undefined` (default — strict `undefined` → cannot read `value` → TypeError; sloppy `globalThis.value` is `undefined`), `42` (explicit). Bonus: wrap with `() => obj.get()` → `10` lexically.

3. **Q: Why does `["1","2","3"].map(parseInt)` give `[1, NaN, NaN]`?**
   **A:** `map` calls `parseInt(value, index)` where index becomes radix (`parseInt("2",1)` → NaN, `parseInt("3",2)` → NaN). Fix: `.map(s => parseInt(s, 10))`. Tests HOF contract knowledge ([4.1](<../4. First-class and execution patterns/4.1. First-class functions callbacks higher-order functions and composition.md>)).

4. **Q: Arrow vs regular function — give three concrete differences.**
   **A:** (1) `this` lexical vs call-site; (2) no own `arguments`/`prototype`/`super`, not constructible; (3) `call`/`apply`/`bind` cannot rebind `this` ([1.2](<../1. Function forms and the function object/1.2. Arrow functions syntax what they lack and when to use each.md>)). Strong answers add "no `prototype` → `new` throws TypeError".

5. **Q: What does this print and why is the first call safe?**
   ```js
   console.log(declared()); // 1
   function declared() { return 1; }
   try { console.log(expr()); } catch (e) { console.log(e.name); } // ReferenceError
   const expr = () => 1;
   ```
   **A:** First prints `1` — function declarations are hoisted (creation phase). Second throws `ReferenceError` (TDZ) — `const expr` is uninitialized before its line ([1.1](<../1. Function forms and the function object/1.1. Function declarations expressions and hoisting.md>)).

6. **Q: What is `bind` and can you `bind` twice?**
   **A:** `bind` returns a new bound-function exotic with permanent `this` + optional prepended args; `call`/`apply` cannot override that `this`, and a second `bind` is ignored (first wins). `new` on a bound constructible ignores bound `this` but keeps bound args ([3.3](<../3. this binding/3.3. call apply bind and bound functions.md>)).

7. **Q: Rest vs `arguments` — when does each apply?**
   **A:** Rest (`...args`) collects into a true Array, works in any function including arrows, preferred. `arguments` is array-like, absent on arrows, and links to named params only in sloppy mode — legacy ([2.1](<../2. Parameters and arguments/2.1. Defaults destructuring rest and the arguments object.md>)).

8. **Q: What does `fn.length` mean? Trace:**
   ```js
   function f(a, b = 1, c) {}
   console.log(f.length);
   ```
   **A:** `1` — arity counts params *before* first default/rest. Call-time argument count is `arguments.length`/rest length. Destructuring without default still counts ([2.2](<../2. Parameters and arguments/2.2. Arity length and edge cases.md>)).

9. **Q: Why does this throw at call time, not parse time?**
   ```js
   function bad(a = b, b = 1) { return a; }
   try { bad(); } catch (e) { console.log(e.name); } // ReferenceError
   ```
   **A:** Defaults are evaluated per call in a param scope; `a`'s initializer reads later param `b` which is still in TDZ → `ReferenceError` ([2.2](<../2. Parameters and arguments/2.2. Arity length and edge cases.md>)).

10. **Q: Can you `new` an arrow function? What about a bound arrow?**
    **A:** No — arrows have no `[[Construct]]`/no `prototype`; `new arrow()` throws TypeError. `bind` on an arrow is ignored, so `new` on that still throws TypeError.

11. **Q: Explain IIFE and a modern replacement.**
    **A:** `(function(){...})()` or `(() => {...})()` creates a fresh scope and runs once — solved `var` leakage and loop-capture before `let`/`let` per-iteration binding, and gave library namespaces before ESM. Modern: block `{ let ... }` for one-off scope, `let` in `for` head for capture, ES modules for namespaces ([4.2](<../4. First-class and execution patterns/4.2. IIFE module ancestry and modern replacements.md>)).

12. **Q: Will tail recursion prevent stack overflow in Node?**
    **A:** No in V8/SpiderMonkey — PTC is spec but only JSC ships it; deep linear recursion throws RangeError regardless of tail position. Rewrite iteratively or via trampoline for depth tied to input size ([4.3](<../4. First-class and execution patterns/4.3. Recursion stacks and tail-call reality.md>)).

### 2) **Grading guidance (mentor note)**

- Q1–Q2 gate juniors: expect call-site vocabulary (implicit/default/explicit/`new`) not "depends"; detached `fn()` must name the winning rule, not just outcome.
- Mid signal: unprompted arrow lexical reasoning on Q4/Q10, TDZ ordering on Q9, `bind`-once permanence on Q6, `map(parseInt)` index-as-radix on Q3.
- Senior signal: Q8 corrected destructuring-without-default counting, Q6 mentions `length`/`name` after `bind` and `new` still works but ignores `this`, Q12 cites PTC engine reality and proposes trampoline/iteration with O-notation reasoning.
- Red flags: "`this` is where function is defined" (conflates closure), "`bind` mutates original", "`fn.length` is argument count", "`arrow this` can be rebound", "tail calls are optimized everywhere".
