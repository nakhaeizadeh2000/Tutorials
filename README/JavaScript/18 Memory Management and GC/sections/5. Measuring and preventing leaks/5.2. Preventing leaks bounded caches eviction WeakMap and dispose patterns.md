## 5.2. Preventing leaks bounded caches eviction WeakMap and dispose patterns

### 1) **Every unbounded graph needs a policy — bounded, time-limited, or weakly keyed**

In long-lived processes (Node 22/24 LTS, SPA lifetimes measured in hours) no `Map`/`Set`/`Array` should grow from user/request input without a rule that shrinks it. The three admissible policies are:

```js
// Policy 1 — bounded size (FIFO): evict the oldest entry past a limit.
function createBoundedMap(limit) {
  const store = new Map();
  return {
    get: (k) => store.get(k),
    set(k, v) {
      if (store.has(k)) store.delete(k);          // touch → reorder
      else if (store.size >= limit) store.delete(store.keys().next().value);
      store.set(k, v);
    },
    size: () => store.size, clear: () => store.clear(),
  };
}
const cache = createBoundedMap(2);
cache.set("a", 1); cache.set("b", 2); cache.set("c", 3);
console.log(cache.size(), cache.get("a")); // 2 undefined — bounded

// Policy 2 — time limited (TTL): lazily evict by timestamp (demo without timers).
function createTTLMap(ttlMs) {
  const store = new Map();
  return {
    set(k, v) { store.set(k, { v, exp: Date.now() + ttlMs }); },
    get(k) {
      const e = store.get(k);
      if (!e) return undefined;
      if (Date.now() > e.exp) { store.delete(k); return undefined; }
      return e.v;
    },
  };
}
const ttl = createTTLMap(50);
ttl.set("k", 42);
console.log(ttl.get("k")); // 42 — until 50ms elapses (TTL is observable, not GC)

// Policy 3 — weak key ownership: let aliveness of the key decide.
let user = { id: 1 };
const metaByUser = new WeakMap();
metaByUser.set(user, { createdAt: Date.now() });
console.log(metaByUser.has(user)); // true
user = null; // key eligible — entry evaporates when GC decides (no size to track)
```

If your cache keys are strings (ids) no weak keying applies — you must use bounded/size-or-TTL (see why GC can't treat string keys weakly in [WeakMap §4.1](<../4. Weak references and cleanup deep dive/4.1. WeakMap and WeakSet ephemeron semantics revisited deep.md>)).

### 2) **Choosing the right edge: strong → bounded vs weak**

| Keys | Eviction goal | Right table | What happens on key death |
|------|--------------|-------------|--------------------------|
| objects (instances, DOM-ish handles) | entry dies with the object | `WeakMap` / `WeakSet` | entry evaporates automatically (weak edge don't count toward reachability) |
| strings/numbers (ids) | history shouldn't live forever | bounded `Map`/`Set` with FIFO/LRU/TinyLFU | entry dies when policy says (TTL, size cap) — you choose |
| any as cached value (payload) | value should not pin if not currently needed | `WeakRef` wrapper on value + strong index if re-creation is cheap | de-ref may become `undefined` between uses — see [WeakRef §4.2](<../4. Weak references and cleanup deep dive/4.2. WeakRef deref hazards lifetime reality and resurrection ordering.md>) for the double-deref guard |

```js
// LRU sketch on Map: reuse insertion order as the policy.
// Real apps should use a tested library; the shape shown here is the interview-priced outline.
function createLRU(limit) {
  const m = new Map();
  return {
    get(k) { if (!m.has(k)) return undefined; const v = m.get(k); m.delete(k); m.set(k, v); return v; },
    set(k, v) { if (m.has(k)) m.delete(k); else if (m.size >= limit) m.delete(m.keys().next().value); m.set(k, v); },
    vals: () => [...m.values()],
  };
}
const lru = createLRU(2);
lru.set("a", 1); lru.set("b", 2); lru.get("a"); lru.set("c", 3); // bumps `a`
console.log(lru.vals()); // [1,3] — b evicted (oldest after bump)
```

### 3) **Explicit lifecycles — signals, `close`/`dispose`, and `using` as the ownership contract**

Retention rooted in host registries needs operation teardown, not GC policy: `clearInterval`/`removeEventListener`/`AbortSignal`. ES2024 explicit resource management (`Symbol.dispose`/`Symbol.asyncDispose` + `using` declaration) makes that corner enforceable by syntax — where unsupported, fall back to `close()` plus `try/finally`.

```js
// Modern teardown policy: `AbortSignal` composes across timers, fetches, and eventers.
function workWithSignal(controller, label) {
  const secret = { big: new Array(200).fill(label) };
  const id = setInterval(() => secret.big.length, 1_000_000);
  id.unref?.();
  const onAbort = () => { clearInterval(id); console.log("signal cleaned", label); };
  controller.signal.addEventListener("abort", onAbort, { once: true });
  return { stop: () => controller.abort() };
}
let ac2 = new AbortController();
let h = workWithSignal(ac2, "lease-a");
h.stop(); // deterministic — not "maybe next GC"
clearInterval; // keep linter happy
ac2 = null; h = null;

// Disposable protocol guarded for Node 20+ vs 22+ (polyfill instead of assert).
class Lease {
  constructor(name) { this.name = name; this._closed = false; }
  close() { this._closed = true; }
  [Symbol.dispose]() { this.close(); }
}
{
  const lease = new Lease("file");
  // In ES2025+ you would write `using lease = new Lease("file");` and drop the finally.
  console.log(lease.name, lease._closed); // file false
  lease.close();
  console.log(lease._closed); // true
}
```

Policy belongs beside the cache/handler line in code review, not in architecture docs: *"retained until `ac.abort()` / `cache.delete(k)` / `lease.close()`"* must be readable at the site that pins the graph.

### 4) **GC-powered supplements — when weak helps, and when it backfires**

- `WeakMap` for per-object metadata (see Session branding in [§4.1](<../4. Weak references and cleanup deep dive/4.1. WeakMap and WeakSet ephemeron semantics revisited deep.md>)) — perfect when the key *is* the lifetime boundary.
- `WeakRef` on cached *values* only when the value graph is recreatable and you accept `undefined` between turns — see double-deref hazard in [§4.2](<../4. Weak references and cleanup deep dive/4.2. WeakRef deref hazards lifetime reality and resurrection ordering.md>).
- `FinalizationRegistry` *only* for telemetry (metrics/log "leaked session cleaned") — never for closing file/socket/lock correctness; the true owner is `close`/`using` — see [§4.3](<../4. Weak references and cleanup deep dive/4.3. FinalizationRegistry cleanup never for correctness hosted discipline.md>).

```js
// BAD: global Set of listeners that grows per request
const listeners = new Set();
function onBad(type, fn) { listeners.add(fn); } // no cap, no key boundary, no weak — leak by design
onBad("data", () => {});
console.log(listeners.size); // 1 and grows

// GOOD: listener set owned by the connection via AbortSignal.
function onGood(target, type, fn, signal) {
  target.addEventListener?.(type, fn, { signal });
  // signal.abort() drains all composed listeners at connection teardown — bounded by connection lifetime
}
console.log("AbortSignal-scoped listeners leak less by ownership", true);
```

### 5) **Common confusion**

- "Bounded vs `WeakMap` — pick one and forget" — you almost always need both: bounded by count for id-keyed history, `WeakMap` for object-keyed meta. Neither replaces explicit `close`/`clear`.
- "`clear` frees immediately" — `clear`/`delete` cut edges deterministically; sweeping is later. Verification via `WeakRef`/`snapshot` delta needs the retry loop from [§2.3](<../2. GC engine and allocation/2.3. When GC runs determinism idle scheduling and --expose-gc.md>).
- "`WeakRef` means I don't need a size cap" — wrong for id-keyed caches: keys are strings and can't be weakly held; you still need a numeric/TTL cap.

### 6) **Performance note**

Every `Map` scan (`for (const [k,v] of map) …`) touches the entire live set; on a 50k-entry `Map` with many dead-valued entries the walk cost alone is significant. Mitigate by subspaces (`Map<string, Map>`) or smaller tables. For `WeakMap`/`WeakSet` mark-phase cost scales with number of registrations — don't create thousands per request cycle.

### 7) **Mentor note**

Require the retention-surface annotation on every PR that adds a live collection or registration: three columns — *Owner*, *Retained graph*, *Teardown line* — filled at the pin site. Anything that cannot fill row 3 ("until `___`") gets redesigned. Teach juniors the bounded-map one-liner first; teach seniors the `AbstractSignal` composition so the `clear*/abort/close/dispose` calls stay centralized rather than scattered across `finally`s.
