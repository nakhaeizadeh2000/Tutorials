## 4.2. WeakRef deref hazards lifetime reality and resurrection ordering

### 1) **Contract — a `WeakRef` does not keep its target alive**

`new WeakRef(target)` requires an object `target` and returns a wrapper whose only way to reach it again is `deref()`. That `deref()` returns the original object if it is still reachable through some other strong path; otherwise it returns `undefined`. The GC clears the internal `[[WeakRefTarget]]` the instant `ClearKeptObjects` decides the target is unreachable — the wrapper itself may stay live, but its target slot becomes `undefined`.

```js
let obj = { payload: new Array(100).fill("keep") };
const wr = new WeakRef(obj);
console.log(wr.deref() === obj); // true — strong edge via `obj` keeps target live

let guard = obj;                  // second strong edge
obj = null;
console.log(wr.deref() === guard); // true — guard still reaches it
guard = null;                     // last strong path cut — wr may clear after next major pass
console.log(wr.deref() === undefined || wr.deref() !== undefined); // either, deterministically irrelevant — never assume
```

Cost of lies: treating `WeakRef` as "alive if `deref()` was truthy a moment ago" makes resurrection bugs trivial, so this leaf focuses on the double-deref guard and ordering guarantees.

### 2) **The double-deref hazard — GC can run between your two uses**

```js
// BAD: cache the deref and use it after an await without re-checking.
async function badCache(wr) {
  const cached = wr.deref();       // may be live now ...
  await new Promise((r) => setTimeout(r, 0)); // ... GC may clear it here
  return cached?.payload;          // stale: you acted as if collection couldn't happen
}

// GOOD: deref at point of use, and handle undefined immediately.
async function goodCache(wr) {
  const live = wr.deref();
  if (live === undefined) return undefined;
  // Use `live` synchronously in this turn, not across an await without re-deref.
  return live.payload.length;
}
let o = { payload: new Array(5).fill(1) };
const w = new WeakRef(o);
goodCache(w).then((len) => console.log("good sync len", len)); // 5
o = null; // eligible — goodCache already consumed or correctly retried
```

Also avoid the symmetric mistake — comparing two `WeakRef`s for object identity. Each `WeakRef` allocates a distinct wrapper object; their wrappers are never `===` even if both point at the same target until clearance. Test `a.deref() === b.deref()` if both deref to the same live object, and expect `undefined` for at least one after collection.

### 3) **Ordering and `ClearKeptObjects` — when the slot clears**

ECMA-262 (ES2021) defines a host-cleanup pass `ClearKeptObjects` executed after marking and before job-queue drain: every unreachable-binding's slot in live `WeakRef`s and its entry in live `FinalizationRegistry`s is cleared atomically. Measurable correlates on V8 (Orinoco, as of 2026): clearing happens within the major collection's finalization step, not at a predictable wall-clock interval. Between minors, `deref()` may stay live even after you cut the last strong edge.

```js
// Resurrection revisited — a `deref()` can go undefined→value if another strong edge reappears.
let liveObj = { id: 1 };
const wr2 = new WeakRef(liveObj);
let ghost = null;
liveObj = null; // eligible
console.log(typeof wr2.deref()); // object or undefined — scheduling unknown, both correct
ghost = { id: 1 }; // unrelated new object must not be confused with the cleared original
console.log(ghost.id, wr2.deref()?.id !== ghost.id || wr2.deref() === undefined); // true
```

When a target becomes unreachable, V8 will (eventually) run a major trace that includes ephemeron sweeps; `WeakRef` slots that were marked-unreachable in that trace become `undefined` before the next script turn. You can't know which major will contain them.

### 4) **GC-powered caches done correctly — strong keys, weak values, explicit bounds**

```js
// Pattern: object-keyed memo with a WeakRef-valued cache layer + bounded strong index.
// This demonstrates the intended tool, not a replacement for Map vs WeakMap trade-offs (see Collections §5.1).
const strongIndex = new Map(); // holds weak wrappers for enumeration / fallback
function weakMemo(obj, compute) {
  const wr = strongIndex.get(obj);
  const live = wr?.deref();
  if (live !== undefined) return live;
  const fresh = compute(obj);
  strongIndex.set(obj, new WeakRef(fresh));
  return fresh;
}
let k = {};
console.log(weakMemo(k, () => ({ v: 1 })).v); // 1
console.log(weakMemo(k, () => ({ v: 999 })).v); // 1 — live wrapper reused
k = null; // key edge cut; wrappers become collectable like any heap node
console.log("weakMemo layer eligible for collection", true);
```

Reserve `WeakRef` for caches and observer lists where you truly need "keep if already live, don't pin if not." For ownership keyed by an object you control, `WeakMap` is simpler and cheaper to reason about — see [§4.1](<./4.1. WeakMap and WeakSet ephemeron semantics revisited deep.md>).

### 5) **Common confusion**

- "Double-deref with a guard variable is safe" — only for the turn you deref. After an `await`/`yield`/`then`, re-deref; the guard pattern from closures (§3.1) does not extend across GC windows.
- "`new WeakRef(42)` keeps numbers alive" — throws `TypeError` on primitives and symbols; only objects qualify.
- "`WeakRef` resurrection inside a marking pass" — possible only if another strong edge reappears *before* the `ClearKeptObjects` slot clear; after clearance the slot stays `undefined` until a fresh `WeakRef` is created.

### 6) **Performance note**

Each live `WeakRef` adds a traced slot the collector must check each major pass. Dozens are noise; thousands of short-lived `WeakRef`s in a tight loop cost mark time for negligible benefit. Don't wrap every `Map` value as `WeakRef` — wrap only those cache values whose retention you explicitly want to be conditional.

### 7) **Mentor note**

Have a mid-level trace the hazard: write a `let cached = wr.deref()` followed by `await sleep(0); use(cached);` and ask what lifetime guarantee that `cached` has. Correct answer is: none — the deref was live at capture; by `await` resume the target may be reclaimed and the only valid signal is a fresh `deref()` call returning `undefined`. Red flag phrases on review: *"cache hit is guaranteed if `deref()` was truthy last line."*
