## 1.2. Reachability roots retaining paths and object death

### 1) **Reachability: the only definition of aliveness**

An object is alive exactly when at least one chain of strong references leads from a *GC root* to it. An object is *dead* when every chain is broken — not when it "went out of scope", not when `delete` was called, not when a timer fired. The collector traces roots, marks every transitively reachable node, and reclaims the rest.

```js
// One object with two paths — cutting one is not enough.
const shared = { payload: new Array(200).fill("x") };
const a = { ref: shared };
const b = { ref: shared };

a.ref = null;                           // first path cut
console.log(b.ref === shared, !!shared.payload); // true true — still reachable via b
b.ref = null;                           // last path cut (assuming no other holder)
console.log(b.ref);                     // null — shared is now eligible if no closure/queue holds it
```

### 2) **The root set — where every retaining path starts**

```js
// Roots include: global object, the current stack, host queues/registries, and handles
// held by the embedder. Demonstrate one host root: a live interval pins its callback
function makePinned(payload) {
  const big = { payload };             // big is heap-allocated
  const id = setInterval(() => big.payload.length, 1_000_000); // interval registry → callback → big
  return () => clearInterval(id);       // caller must clear to break the host edge
}
const release = makePinned(new Array(500).fill("pin-me"));
console.log(typeof release === "function"); // true — the interval still pins `big`
release();                                  // host edge cut → big becomes collectable
```

- *Globals*:`globalThis` (`global` in Node, `window` in browsers) and its transitive fields — module-level `const cache = new Map()` lives here.
- *Stack*: active execution contexts' locals and arguments while a call is running.
- *Host queues/registries*: microtask/macrotask queues, timer registries (`setTimeout`/`setInterval`), listeners registered with `addEventListener`/`EventTarget` + `AbortSignal`, promise capability queues, and `MessagePort` queues.
- *Handles held by embedder*: open file/net handles, `ArrayBuffer` backing stores that the engine tracks as external.

A *retaining path* is a sequence `root → … → leakedObject`. In a heap snapshot you read it bottom-up: the leaking object at the bottom, its dominator above it, up to a root at the top — see [Measuring §5.1](<../5. Measuring and preventing leaks/5.1. Measuring memory heap snapshots allocation timeline and inspector.md>) for the workflow.

### 3) **Which edge-cut actually retires an object**

```js
// Cutting vs removing vs expiring — four ways to break a path.
const bag = { keep: { v: 42 }, alias: null };
bag.alias = bag.keep;                   // two edges to the same node
bag.keep = null;                        // one edge cut — still reachable via alias
console.log(bag.alias.v);               // 42
delete bag.alias;                       // remove the alias slot entirely
console.log("alias" in bag, bag.alias); // false undefined — outer {v:42} eligible if nothing else points at it

const m = new Map();
const key = {};
m.set(key, new Array(10).fill(1));
// m.delete(key) cuts the ephemeron edge — unlike Map.delete, deleting from WeakMap drops the entry entirely
m.delete(key);
console.log(m.size);                    // 0 — entry gone

// Block exit cuts stack-local edges, but not closure edges (see Lifetimes §3.1).
```

| Operation | Edge change | Heap-node effect |
|-----------|-------------|-----------------|
| `let x = null; x = null` / `x = other` | swings one reference edge to `null`/another node | node dies iff that was its last inbound edge |
| `delete obj.prop` | removes the property slot | same, plus may move object to dictionary mode (hidden-class deopt) |
| `{} ;` block exit | pops locals from the stack | removes all stack-local edges from that context |
| `Map.delete(k)` / `Map.clear()` | removes entry edges in that `Map` | entries die; `Map` size shrinks |
| `WeakMap` key death | engine removes entry automatically | entry dies with its key (ephemeron) |
| `clearTimeout(id)`/`signal.abort()` | removes host-registry edge | callback and its captures become collectable |

### 4) **Seeing death (or not) — `--expose-gc` and `WeakRef` as observers**

Never rely on timing for correctness, but an observer lets you prove a path is gone in a lab:

```js
// Lab-only: fails unless run with --expose-gc. Never gate production on this.
global.gc?.(); // warm up if available

async function pathGoneLab() {
  if (typeof WeakRef === "undefined" || typeof global.gc !== "function") {
    console.log("lab probe: WeakRef/--expose-gc not available — skipping (correct for prod)");
    return;
  }
  let obj = { x: 1 };
  const wr = new WeakRef(obj);
  let guard = obj;             // strong edge — keeps wr alive
  console.log("with guard:", wr.deref() !== undefined); // true
  guard = null;                // cut guard
  obj = null;                  // cut last user edge — now only wr remains (weak, not retaining)
  // Try hard to coax GC (host decides, but retry helps in labs)
  for (let i = 0; i < 5; i++) {
    global.gc();
    await new Promise((r) => setTimeout(r, 0));
    if (wr.deref() === undefined) break;
  }
  console.log("after cuts, deref is", wr.deref() === undefined ? "undefined (collected)" : "still live (GC hasn't run)");
}
pathGoneLab();

global.gc?.();
```

### 5) **Common confusion**

- "Scope exit freed it" — it freed the *stack* slot; the heap node lives as long as any other edge (closure, `Map`, host queue, module global) retains it. Show the bug with a live timer, not a closed-over variable that already died.
- "`obj.field = null` is pointless — the variable will go out of scope soon" — on hot paths with long-lived closures/intervals, that one line *is* the entire fix (see [Lifetimes §3.1](<../3. Lifetimes what stays alive/3.1. Closures timers listeners maps and the lifetime of a graph.md>) covering the same `bigData = null` pattern as [Variables §3.4](<../../../04 Variables Scope and Closures/sections/3. Closures/3.4. Closures and garbage collection what stays alive.md>)).
- "`WeakMap` entry died, so `WeakRef` must be dead too" — independent edges. A `WeakRef` may clear while another strong edge still exists, or stay alive while a `WeakMap` entry was already dropped. Each weak edge is evaluated atomically against reachability.

### 6) **Performance note**

Retaining-path length is a human cost, not a CPU cost: deep chains make snapshots harder to read but don't change mark cost much. What matters for pause and frequency is *mutation rate* around the roots (see [GC pressure §2.2](<../2. GC engine and allocation/2.2. Allocation hidden classes inline caches and GC pressure.md>)).

### 7) **Mentor note**

Have a junior trace the path on paper before opening DevTools: start at `globalThis`, `m`, `interval`, or argument list, chase edges property-by-property until the leaking class. Only then confirm with a snapshot. The habit of naming the root out loud ("*module cache → Map → entry value → Buffer*") catches unbounded-growth bugs at code review without tooling.
