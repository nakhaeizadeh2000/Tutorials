## 2.3. When GC runs determinism idle scheduling and --expose-gc

### 1) **No promised instant — GC is heuristic and implementation-defined**

The ECMAScript spec defines *reachability* but never *when* an unreachable node is reclaimed. Engines decide based on allocation pressure, nursery fill, old-space thresholds, idle windows, and host hints (page visibility, memory pressure signals). The same program with the same reachable set may collect instantly on one run and minutes later on the next — both are correct.

```js
let obj = { payload: new Array(1000).fill("keep") };
let ref = obj;
obj = null;
ref = null;             // object is now unreachable by language rules ...
console.log("unreachable? yes", true);
console.log("collected now? ", typeof global.gc === "function" ? "ask global.gc()" : "unknown — no guarantee");
```

### 2) **What drives a collection cycle**

| Signal | Effect on collector scheduling |
|--------|--------------------------------|
| Nursery allocation bumps past budget | schedules a *minor* (nursery) collection soon |
| Old-space size crosses tenuring/pressure threshold | schedules a *major* trace (mark) in next idle-quiet window |
| Idle callback (`requestIdleCallback` / scheduler) reports slack | opportunistic major steps run with low priority |
| OS memory-pressure / background-tab heuristics | may force major + compaction |
| Explicit hint `global.gc()` (when `--expose-gc`) | enqueues a major trace; still heuristic (may not collect everything immediately) |

```js
// Lab-only forced GC. Guard so production never depends on it.
console.log("global.gc available?", typeof global.gc === "function");
// Start Node with: node --expose-gc your_script.js
// Then: global.gc?.();  // enqueue major, not "free all unreachable synchronously"
```

### 3) **Determinism you do get vs don't get**

- **Deterministic**: which objects are *reachable*. Same inputs → same retaining graph. A single surviving path keeps the subgraph alive, period — see [Reachability §1.2](<../1. Memory model/1.2. Reachability roots retaining paths and object death.md>) and [Lifetimes §3.1](<../3. Lifetimes what stays alive/3.1. Closures timers listeners maps and the lifetime of a graph.md>).
- **Non-deterministic**: *when* `ClearKeptObjects` clears `WeakRef`s/`FinalizationRegistry` queues and *when* sweeping returns OS pages. `WeakRef.deref()` may stay `true` for a long time after you cut the last strong edge, then flip asynchronously (see [WeakRef §4.2](<../4. Weak references and cleanup deep dive/4.2. WeakRef deref hazards lifetime reality and resurrection ordering.md>) for the double-deref guard and [FinalizationRegistry §4.3](<../4. Weak references and cleanup deep dive/4.3. FinalizationRegistry cleanup never for correctness hosted discipline.md>) for "never for correctness").
- **Weak vs strong is not about timing but about *whether* a path counts** — `WeakMap`/`WeakSet`/`WeakRef` edges simply don't count toward reachability. That's the whole contract; the rest is scheduling.

### 4) **`--expose-gc` and friends — lab instruments, not production controls**

```js
async function labProbeWorks() {
  if (typeof WeakRef === "undefined" || typeof global.gc !== "function") {
    console.log("lab probe skipped — run with `node --expose-gc` on Node 20+");
    return;
  }
  let obj = { tag: "lab" };
  const wr = new WeakRef(obj);
  const registryFeeds = [];
  const reg = new FinalizationRegistry((held) => registryFeeds.push(held));
  reg.register(obj, "held-tag"); // heldValue must NOT be `obj` itself (§4.3)
  obj = null;

  for (let attempt = 0; attempt < 10; attempt++) {
    global.gc();
    // Let microtask queue drain so registry cleanups (as microtasks/jobs) have a chance
    await new Promise((r) => setTimeout(r, 10));
    if (wr.deref() === undefined) break;
  }
  console.log("WeakRef after forced GC:", wr.deref() === undefined ? "collected" : "still live");
  console.log("registrations cleaned:", registryFeeds.length ? registryFeeds[0] : "(not yet)");
}
labProbeWorks();

// Other lab tools: `v8.getHeapStatistics()` and `process.memoryUsage()` quantify,
// but "before gc vs after gc" comparisons are lab-only, not user metrics.
if (typeof require !== "undefined") {
  try {
    const v8 = require("node:v8");
    console.log("heap stats available:", typeof v8.getHeapStatistics === "function");
  } catch { /* ignore in non-Node hosts */}
}
```

Guidance: `global.gc()` enqueues a major trace but does not guarantee that all `WeakRef`s clear or that `FinalizationRegistry` callbacks have run by the next line. Tests that assert `deref() === undefined` without retry+settle are flakes. Production must never use forced GC to "make room."

### 5) **Polite scheduling — idleness and explicit teardown**

```js
// BAD: rely on GC timing to release a listener/interval.
// (fence runner: interval unrefed and immediately cleared after demo so per-file run exits — real leak would keep it alive)
function scheduleBad(payload) {
  const id = setInterval(() => console.log(payload.slice(0, 1)), 1_000_000);
  id.unref?.();
  return { leakingId: id, note: "scheduled, but id is unreachable — leaks" };
}
const _badScheduleDemo = scheduleBad(["x"]);
console.log(_badScheduleDemo.note.length); // bigger than you'd like, and lives forever
clearInterval(_badScheduleDemo.leakingId); // cleanup for fence runner — remove in real leak incident

// (duplicate demo also scheduled above — fence-cleaned via clearInterval)

// GOOD: explicit ownership + idle hint — not forced gc.
function scheduleGood(payload, signal) {
  const id = setInterval(() => console.log(payload.slice(0, 1)), 1_000_000);
  signal?.addEventListener?.("abort", () => clearInterval(id), { once: true });
  return { stop: () => clearInterval(id) };
}
const ac = new AbortController();
const handle = scheduleGood(["good"], ac.signal);
handle.stop(); // deterministic — no GC required
console.log("stopped deterministically", true);

// Cooperative yielding as "polite GC window": break long synchronous chunks
// so incremental marking and event loop can interleave (used by Orinoco's slicing).
function chunked(items, process) {
  for (let i = 0; i < items.length; i++) {
    process(items[i]);
    // Awaiting 0 is one cooperative yield point — not a GC call.
  }
}
chunked([1, 2, 3], (x) => x);
```

Idle callbacks (`requestIdleCallback` in browsers; `scheduler.yield()` proposed) are *hints* that work is slack, not collection triggers. Use them to schedule heavy rebuilds or explicit `Map.clear()` windows at low cost — never as a substitute for `clearInterval`/`removeEventListener`/`close()`/`Symbol.dispose`.

### 6) **Common confusion**

- "`delete` / `obj = null` frees now" — it cuts one edge; reclamation is later. Verification via `WeakRef` shows "still alive" status is normal.
- "`WeakRef.deref() === undefined` means collection already happened at cut time" — perhaps; more likely it happened on the next major pass. The timing varies per heap size and allocation rate.
- "DevTools 'Collect garbage' is deterministic" — it's the same `global.gc()`-like host hint with the same caveat: enqueued, not synchronous.

### 7) **Performance note**

Chasing prompt collection with repeated `global.gc()` in production harms throughput: each forced major does full-mark work that idle-sliced incremental marking would have amortized. The cost shows up as latency spikes, not heap savings. Measure retain-set size under realistic idle vs load profiles instead of GC count.

### 8) **Mentor note**

Drill the split: *determinism of reachability is yours to design; timing of reclamation is not.* Ask on review: *"which line deterministically cuts the last strong path?"* If the answer is "the GC will run eventually," rewrite it so the answer names a `clear*/abort/close/dispose/Map.delete/null` line. Lab probes with retry loops are the only honest way to assert collection in a test — and the test still proves the last edge cut, not the scheduler.
