## 8.1. Common interview Q&A memory GC weak references

### 1) **Twelve classics with mechanism-level answers**

**Q1 — Primitives on stack, objects on heap — accurate?**
No. The spec describes a reachable graph, not a layout split. V8 SMI tagging, escape analysis, and register allocation can keep objects stack-like and primitives pointer-like. Treat "stack vs heap" as a model for *edges* ([§1.1](<../1. Memory model/1.1. Heap stack execution contexts and references how values live.md>)), not a placement promise.

**Q2 — What decides whether an object dies?**
Reachability from a GC root via strong edges. One surviving strong path keeps the subgraph alive. Show one cut: `map.delete(key)` vs `key = null` alone. Roots enumerated in [§1.2](<../1. Memory model/1.2. Reachability roots retaining paths and object death.md>): globals, stack, host timer/queue registries.

**Q3 — Minor vs major GC, generational hypothesis, incremental/concurrent Orinoco. Draw the trace.**
Most objects die young → nursery evacuation (minor) is cheap semi-space style; old-space tracing (major) walks long-lived graphs and now runs incrementally + concurrently on Orinoco/Oilpan ([§2.1](<../2. GC engine and allocation/2.1. Mark-and-sweep incremental generational and concurrent V8 Orinoco.md>)).

**Q4 — When does GC run? Can you force it?**
Implementation-defined, heuristic: nursery fill, old-space thresholds, idle windows, allocation rate ([§2.3](<../2. GC engine and allocation/2.3. When GC runs determinism idle scheduling and --expose-gc.md>)). `global.gc()` with `--expose-gc` is a lab hint enqueuing a major, not "free now"; never gate correctness on it.

**Q5 — `delete obj.prop` vs `obj.prop = null` for memory — same?**
`null` swings one reference edge; `delete` removes the slot and may transition the object to dictionary mode, hurting inline caches ([§2.2](<../2. GC engine and allocation/2.2. Allocation hidden classes inline caches and GC pressure.md>)). For keyed collections use `Map.delete`; for fields prefer `null` unless you need shape removal.

**Q6 — Closure pinning: does referencing one variable keep the whole scope's big data?**
Per spec, the entire environment is retained by the closure edge ([§3.1](<../3. Lifetimes what stays alive/3.1. Closures timers listeners maps and the lifetime of a graph.md>) + [Variables §3.4](<../../../04 Variables Scope and Closures/sections/3. Closures/3.4. Closures and garbage collection what stays alive.md>)). V8 may prune unreachable slots as an optimization, but the spec promises nothing — fix explicitly with `big = null`.

**Q7 — `WeakMap` vs `Map` vs `WeakRef` — when to use each.**
`WeakMap` for per-object metadata where the key *is* the lifetime boundary (no `size`, self-referential value pins — see [§4.1](<../4. Weak references and cleanup deep dive/4.1. WeakMap and WeakSet ephemeron semantics revisited deep.md>)). `Map` + bounded/FIFO/LRU for id-keyed history ([§5.2](<../5. Measuring and preventing leaks/5.2. Preventing leaks bounded caches eviction WeakMap and dispose patterns.md>)). `WeakRef` only for "recreate if re-observed" caches with double-deref guard ([§4.2](<../4. Weak references and cleanup deep dive/4.2. WeakRef deref hazards lifetime reality and resurrection ordering.md>)).

**Q8 — `WeakRef.deref()` returned truthy, so the value is safely cached across `await`?**
No — double-deref hazard. GC may clear the slot between `let v = wr.deref()` and `await` resume. Re-deref synchronously in the `await`-free turn and treat `undefined` as missing.

**Q9 — Is `FinalizationRegistry` a destructor for file handles/sockets?**
Never. Enqueue is best-effort, batched, may never run, and drains as microtasks. Correctness is `close()`/`[Symbol.dispose]`/`using` — registry at most logs telemetry ([§4.3](<../4. Weak references and cleanup deep dive/4.3. FinalizationRegistry cleanup never for correctness hosted discipline.md>)).

**Q10 — What self-reference defeats weakness?**
`wm.set(key, { owner: key })` or `registry.register(obj, obj)` pins the target via its own value ([§4.1](<../4. Weak references and cleanup deep dive/4.1. WeakMap and WeakSet ephemeron semantics revisited deep.md>) / [§4.3](<../4. Weak references and cleanup deep dive/4.3. FinalizationRegistry cleanup never for correctness hosted discipline.md>)). Hold descriptors/strings, not the object.

**Q11 — "Scope exit freed memory" — why does the heap still grow after your function returns?**
Stack pop removed one edge; another root (module global `Map`, host `setInterval`, uncollected promise capability) still retains the graph. Trace the retaining path in a snapshot delta ([§5.1](<../5. Measuring and preventing leaks/5.1. Measuring memory heap snapshots allocation timeline and inspector.md>)).

**Q12 — How do you prove a leak in Node?**
Capture two heap snapshots around repeated equal work → compare retained size delta and follow the top retainer's path to its root (see [§5.1](<../5. Measuring and preventing leaks/5.1. Measuring memory heap snapshots allocation timeline and inspector.md>)). For targeted probes, use `WeakRef` + retry-loop forced GC lab hint only ([§2.3](<../2. GC engine and allocation/2.3. When GC runs determinism idle scheduling and --expose-gc.md>)); for buffers also watch `process.memoryUsage().arrayBuffers`/`external`.

```js
// Spot-check for mechanism answers (used in Q6/Q1 draws — all runnable as-shown).
const shallow = { a: { v: 1 } };
const copy = { ...shallow }; // new root, shared child
copy.a.v = 2;
console.log(shallow.a.v === 2, copy.a === shallow.a); // true false

let u = { id: 1 };
const wm = new WeakMap();
wm.set(u, { tag: "t" });
console.log(wm.has(u)); // true
u = null; // entry eligible, not immediately observable without GC hint
console.log("eligible without asserting collection", true);
```

### 2) **What interviewers actually probe for**

Senior signal is narrating one *full retaining path in words*: "module global `cache: Map` → entry with `req-*` key → `{ payload: Buffer }`." Weak answers stop at "JS has a GC so no leaks" or recite "WeakMap is weak." Strong answers enumerate the graph edge-by-edge, name the root, and say which single line would cut it.

### 3) **Grading guidance**

| Level | Signals | Red flags |
|-------|---------|-----------|
| Junior | draws a graph with nodes/edges and knows `Map` entries outlive scope unless `delete` | "`delete` frees memory" / "`gc()` guarantee" / "scope exit means free" |
| Mid | can state reachability, double-deref hazard, bounded-vs-weak choice, and signal/teardown ownership | "WeakMap leaks never happen" / treats `WeakRef` as ownership |
| Senior | traces ephemeron self-pin, `ClearKeptObjects` hook, Orinoco incremental vs concurrent, hidden-class & pressure trade, and snapshot delta + timeline split | "`FinalizationRegistry` closes resources" / "`WeakRef` resurrection re-enqueues" |
