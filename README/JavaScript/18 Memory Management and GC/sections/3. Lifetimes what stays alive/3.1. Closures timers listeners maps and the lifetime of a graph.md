## 3.1. Closures timers listeners maps and the lifetime of a graph

### 1) **The lifetime question is always "who can still reach this edge?"**

Scope exit removes the stack-local edge but never decides death alone: the graph stays alive as long as *any* strong path from a [GC root](<../1. Memory model/1.2. Reachability roots retaining paths and object death.md>) reaches it. In practice the four habitual roots that keep graphs alive longer than intended are closures that outlived their factory call, timers/intervals, registered listeners, and unbounded `Map`/`Array` captures. All four share one fix family — explicit, reviewable teardown of that last path.

```js
// Closure environment pinning — whole scope, not just the used variable (see Variables §3.4).
function attachStatsNaive(bigData) {
  const count = bigData.length;
  return { count: () => count }; // bigData lives in the same env, even if never read again
}
let report = attachStatsNaive(new Array(500).fill(0));
console.log(report.count()); // 500 — bigData's array still reachable via the closure env (spec)
report = null;               // last path cut (modulo engine slot-pruning optimizations)

// Robust pattern: cut the edge you don't need to carry.
function attachStatsFixed(bigData) {
  const count = bigData.length;
  bigData = null;            // one-line pin cut — explicitly narrow the env
  return { count: () => count };
}
let report2 = attachStatsFixed(new Array(500).fill(0));
console.log(report2.count()); // 500 — bigData edge no longer retained
report2 = null;
```

Engines *may* prune dead slots (V8 has improved this), but the spec promises nothing — never bet production memory on slot pruning. Narrow scopes (`{ let tmp = ...; }`) and the explicit `= null` line are the honest, reviewable contract.

### 2) **Timers and micro/macrotask queues as retaining roots**

```js
function startPolling(label) {
  const big = { label, buf: new Array(1000).fill(label) };
  let ticks = 0;
  const id = setInterval(() => { ticks += 1; console.log(big.label.slice(0, 1) + ticks); }, 50);
  return { stop: () => clearInterval(id), peek: () => ticks };
}
const poller = startPolling("heavy");
setTimeout(() => {
  poller.stop();             // host registry edge cut — graph becomes collectable
  console.log("stopped, ticks", poller.peek() > 0);
}, 120);

// Same root family: a queued microtask holds its closure until drained.
let microPinned = { tag: "micro" };
queueMicrotask?.(() => console.log("micro sees", microPinned?.tag));
microPinned = null;          // microtask still holds the first capture via its callback closure
```

The chain: `host timer registry → callback → [[Environment]] → big`. Forgetting `clearInterval`/`clearTimeout` leaks by design — the host root can't know you no longer care. `queueMicrotask`/`Promise.then` queues pin until they run; a never-resolving promise capability pins its handlers forever.

### 3) **Listeners, signals, and maps — the same edge story**

```js
// Map/Array retention: pushing to a module-global grows the live set monotonically.
const registry = new Map();
function cacheResponse(key, payload) { registry.set(key, payload); }
cacheResponse("req-1", new Array(200).fill("data"));
console.log(registry.size);  // 1 — grows until delete/clear or bound policy
registry.delete("req-1");
console.log(registry.size);  // 0

// Event listeners as edges: addEventListener pins handler (and its closure) until remove/abort.
function wire(signal) {
  const bigState = { notes: new Array(1000).fill("state") };
  const handler = () => console.log(bigState.notes.length);
  signal.addEventListener("abort", handler, { once: true }); // once + abort as one policy
  return handler;
}
const ac = new AbortController();
wire(ac.signal);
ac.abort();                  // host edge cut; handler + bigState collectable after
```

Browser `EventTarget` follows the same rule; `AbortSignal` is the modern, reviewable teardown handle — prefer `{ signal }` over ad-hoc `removeEventListener` everywhere.

### 4) **Breaking the graph — ownership, narrow scopes, and explicit teardown**

```js
// Narrow scope shrinks the env that a closure can retain.
function parseStrict(payload) {
  let parsed;
  { // intentional block scopes the large transient binding
    const text = JSON.stringify(payload); // text only needed here
    parsed = JSON.parse(text);
  } // text's stack slot dies here even though parsed's closure survived
  return parsed;
}
console.log(parseStrict({ a: 1 }).a); // 1

// Explicit dispose protocol (ES2024 `using`) makes "stop" non-optional.
// Fallback path shown first — both pass the same lab fences as CJS.
class Session {
  constructor(name) { this.name = name; this._closed = false; }
  [Symbol.dispose]() { this._closed = true; }
  close() { this._closed = true; }
}
let s = new Session("demo");
console.log(s._closed); // false
s.close();
console.log(s._closed); // true

// One more host-queue root to name: unhandled `on(event, handler)` registrations
// that grow per request without `off`. Same rule: root = registry, fix = off/signal.
```

***What problem it solves / history*** — before `WeakMap` (ES2015) and `AbortSignal` (DOM living std) the only remediation for leaked listeners was manual bookkeeping scattered across modules — exactly the codebase pattern that bred "mystery heap growth after a week." The graph mental model arrived to make that bookkeeping explicit.

***Modern guidance*** — as of ECMAScript 2026 era (Node 22/24 LTS): every growable container or registration site needs a documented eviction/teardown rule; unbounded (`Map`/`Set`/`Array` captures) + long-lived (module/global/singleton) = incident unless a policy caps it.

### 5) **Common confusion**

- "`setTimeout(..., 0)` frees after it fires" — it *does* drop the host edge after firing, but the closure graph may still be held by another edge (module `Map`, promise capability). Fire-and-forget still leaks if another edge exists.
- "Removing the DOM node frees listeners on it" — maybe, if the node is unreachable via any other path; if a `Map` or closure still references the handler, it stays alive — see why [Measuring §5.1](<../5. Measuring and preventing leaks/5.1. Measuring memory heap snapshots allocation timeline and inspector.md>) checks retaining paths, not "was the element removed."
- "Pruning dead slots will save me" — treat V8 slot pruning as a performance bonus, never a correctness argument. The reviewable fix remains the explicit pin cut.

### 6) **Performance note**

Closure environments are small per instance but catastrophic per *population*: a factory returning `n` closures over one shared big config pins one big graph `n` times until `n` teardowns all run. The pressure is `n × retainedSize` (see [GC pressure §2.2](<../2. GC engine and allocation/2.2. Allocation hidden classes inline caches and GC pressure.md>)) and typically shows up as old-space bloat, not nursery churn.

### 7) **Mentor note**

Review ritual: for each new registration or cache line added in a PR, the author must annotate *"retained until ___"* (signal/close/clear/delete/using). Approve only when that blank is filled with a reviewable line of code — not "GC will handle it." Demo the `bigData = null` one-liner to juniors (same lesson as [Variables §3.4](<../../../04 Variables Scope and Closures/sections/3. Closures/3.4. Closures and garbage collection what stays alive.md>)); make seniors trace one full *host registry → handler → captured graph* path before signing off on a long-lived feature flag.
