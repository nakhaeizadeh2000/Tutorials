## 7.1. Real production bugs caused by metaprogramming mistakes

### 1) **Non-configurable lie — `ownKeys` omitting a non-configurable prop crashes only on sealed objects**

**Incident** — a filter-proxy hides "internal" keys via `ownKeys() { return Reflect.ownKeys(t).filter(k => !String(k).startsWith("_")); }`. Works in dev with plain objects, crashes in prod where `Object.freeze` seals the config object with non-configurable `_secret`.

```js
// Repro — lie hidden until freeze in prod
function hidingProxy(obj){
  return new Proxy(obj, {
    ownKeys(t){ return Reflect.ownKeys(t).filter(k => !String(k).startsWith("_")); }
  });
}
const dev = { a: 1, _hidden: 2 };
console.log(Object.keys(hidingProxy(dev))); // ['a'] — ok because _hidden configurable

const prod = {};
Object.defineProperty(prod, "_hidden", { value: 2, configurable: false, enumerable: true });
prod.a = 1;
try { console.log(Object.keys(hidingProxy(prod))); } catch(e){ console.log("prod crash:", e.name, e.message.slice(0,50)); } // TypeError
// Fix — always include non-configurable keys (or avoid proxying frozen targets)
function safeProxy(obj){
  return new Proxy(obj, {
    ownKeys(t){
      const keys = Reflect.ownKeys(t);
      // keep non-configurable even if filtered prefix
      return keys.filter(k => {
        if (String(k).startsWith("_")){
          const d = Reflect.getOwnPropertyDescriptor(t, k);
          if (d && !d.configurable) return true;
        }
        return !String(k).startsWith("_");
      });
    }
  });
}
console.log(Object.keys(safeProxy(prod))); // ['a', '_hidden'] — invariant satisfied (still exposes, but correct)
```

- **Lesson** — test proxies against frozen/sealed targets; filter only configurable keys or forward behavior differs prod vs dev.

### 2) **Lost `receiver` breaking accessor `this` — double-wrapped `_value` mutates wrong object**

**Incident** — a logging proxy wraps a domain object with accessor `get value(){ return this._value; }`. Trap uses `t[k]` instead of `Reflect.get(t,k,receiver)`. Shadowing `_value` on the proxy still reads target's `_value`; audit log shows stale value, and a second wrapping doubles the divergence.

```js
// Lost receiver — broke membrane
const target = { _value: 1, get value(){ return this._value; } };
const broken = new Proxy(target, { get(t,k){ return t[k]; }, set(t,k,v){ t[k]=v; return true; } });
broken._value = 99; // writes to target, not proxy
console.log(target._value, broken.value, broken._value); // 99 99 99 — looks correct but leaked
// With identity-carrying accessor, leak is visible
const idTarget = { get self(){ return this; } };
const b = new Proxy(idTarget, { get(t,k){ return t[k]; } });
console.log(b.self === b); // false — should be true
console.log(b.self === idTarget); // true — leaked target

const good = new Proxy(idTarget, { get(t,k,r){ return Reflect.get(t,k,r); } });
console.log(good.self === good); // true — correct

// Setter variant — setter this leaks
const withSetter = { _x: 1, set x(v){ this._x = v; } };
const badSetter = new Proxy(withSetter, { set(t,k,v){ t[k]=v; return true; } });
badSetter.x = 9; // t[k]= calls setter with this=target, not proxy — _x still on target
console.log(withSetter._x); // 9 — leaked
```

- **Lesson** — `t[k]` in traps is a bug class; enforce `Reflect.*` with receiver via lint.

### 3) **Global registry collision — `Symbol.for("auth")` shared across bundles leaks one plugin's hook**

**Incident** — two bundles each use `Symbol.for("auth")` as a private protocol key to attach auth data to a shared object. They collide: one plugin overwrites the other's property, leaking a user's token to the wrong handler. Rare in dev (one bundle), frequent in prod with code-splitting.

```js
// Collision via global registry — same symbol across bundles
const pluginA = (obj, token) => { obj[Symbol.for("auth")] = token; console.log("A set", obj[Symbol.for("auth")]); };
const pluginB = (obj, token) => { obj[Symbol.for("auth")] = token; console.log("B set", obj[Symbol.for("auth")]); };
const shared = {};
pluginA(shared, "tokenA");
pluginB(shared, "tokenB");
console.log(shared[Symbol.for("auth")] === "tokenB"); // true — B overwrote A

// Fix — isolated symbols per plugin
const pluginAFixed = (() => { const AUTH = Symbol("auth"); return (obj, t) => { obj[AUTH] = t; }; })();
const pluginBFixed = (() => { const AUTH = Symbol("auth"); return (obj, t) => { obj[AUTH] = t; }; })();
const s1 = {}, s2 = {};
// They use distinct symbols, no collision — each sees its own key via closure
// Verification: global registry size check — Symbol.keyFor per-plugin is undefined (isolated)
console.log(Symbol.keyFor(Symbol("auth"))); // undefined — isolated, not global
console.log(Symbol.keyFor(Symbol.for("auth")) === "auth"); // true — global
```

- **Lesson** — use fresh `Symbol("name")` for module-private keys; reserve `Symbol.for` for intentionally shared cross-realm protocols.

### 4) **`@@toPrimitive` returning non-primitive throws late — coercion inside `Map` key surprises**

**Incident** — a `Money` class with `@@toPrimitive` returns an object in the `"string"` branch (forgot to handle `"default"`). Arithmetic `amount + 0` works (hint `"default"`→number branch), but template `${amount}` calls hint `"string"` → object → late `TypeError` in logging path only.

```js
// Late throw via @@toPrimitive returning non-primitive
const money = {
  cents: 100,
  [Symbol.toPrimitive](hint){
    if (hint === "number" || hint === "default") return this.cents;
    return {}; // bug — string hint returns object
  }
};
console.log(money + 0); // 100 — number/default path ok
try { console.log(`${money}`); } catch(e){ console.log("template throw:", e.name); } // TypeError — only logging path crashes
try { String(money); } catch(e){ console.log("String throw:", e.name); }

// Fix — every hint must return primitive
const fixedMoney = {
  cents: 100,
  [Symbol.toPrimitive](hint){
    if (hint === "string") return `$${(this.cents/100).toFixed(2)}`;
    return this.cents; // number/default
  }
};
console.log(`${fixedMoney}`, String(fixedMoney), fixedMoney + 0); // $1.00 $1.00 100
```

- **Lesson** — handle all hints explicitly; add a unit test per hint (`String(x)`, `Number(x)`, `x+""`, `x+0`, `` `${x}` ``).

### 5) **`@@species` surprise — subclass `map` returns base `Array` when `species` overridden, breaking `instanceof` checks downstream**

**Incident** — `class MyArr extends Array { static get [Symbol.species](){ return Array; } }` used to keep `map` plain for DB layer. Upstream code checks `result instanceof MyArr` to gate extra methods — after `map`, the check fails (only `Array.isArray` true), and a `.myMethod()` call throws `TypeError`.

```js
// Species plain vs subclass — instanceof divergence
class MyArr extends Array {
  static get [Symbol.species]() { return Array; }
  sum(){ return this.reduce((a,b)=>a+b,0); }
}
const a = new MyArr(1,2,3);
const plain = a.map(x => x*2);
console.log(plain instanceof MyArr); // false — species forced plain
console.log(plain instanceof Array); // true
console.log(Array.isArray(plain)); // true
try { plain.sum(); } catch(e){ console.log("sum on plain:", e.name); } // TypeError — method absent

// Fix — either keep species default when chaining methods needed, or check Array.isArray + duck-typing
class MyArrKeep extends Array {
  // no species override → map stays MyArr
}
console.log(new MyArrKeep(1,2).map(x=>x*2) instanceof MyArrKeep); // true

// Cross-realm note — instanceof fails cross-realm regardless of species (see Prototypes 5.1)
```

- **Lesson** — document species choice and gate with `Array.isArray` plus method-existence check, not `instanceof MyArr`.

### 6) **Performance note**

Each incident above costs zero until one environment flips (freeze, second bundle, string coercion in logging, species gate). The failure mode is *environment-coupled latency*: the bug hides in dev because that environment never hits the invariant/coercion/species path.
