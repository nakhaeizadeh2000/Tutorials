## 1.2. Symbol creation description global registry and hidden keys

### 1) **Three ways to get a symbol — fresh, described, shared**

**Definition** — `Symbol()` creates a fresh symbol with no global identity; `Symbol("desc")` tags it with a debug `description` (visible via `sym.description` / `String(sym)`); `Symbol.for("key")` returns the single canonical symbol for that string in the *global registry* (same string → same symbol across realms that share the registry). `Symbol.keyFor(sym)` reverses only the global set (local symbols → `undefined`).

**What problem it solves / history** — ordinary symbols must be collision-proof (each library gets isolated keys). The global registry solves the opposite need: cross-realm shared tokens (e.g., polyfill conventions like `Symbol.for("myShared")`). `description` (ES2019 getter) gives humans a label without leaking a string key; `keyFor` is the intended reverse map, not string parsing.

```js
// Fresh vs described vs global shared
const a = Symbol("x"), b = Symbol("x");
console.log(a === b); // false — same description, distinct symbols
console.log(a.description, String(a)); // "x" "Symbol(x)"
console.log(Symbol("").description, Symbol().description); // "" undefined — empty string vs no arg

const g1 = Symbol.for("app.auth"), g2 = Symbol.for("app.auth");
console.log(g1 === g2); // true — global canonical
console.log(g1 === Symbol("app.auth")); // false — local ≠ global even with same description
console.log(Symbol.keyFor(g1), Symbol.keyFor(a)); // "app.auth" undefined — only global reverses
console.log(Symbol.for("x") === Symbol.for(String("x"))); // true — registry coerces key to string

// description is non-writable and non-enumerable — but visible via getter
const s = Symbol("debug");
console.log(Object.getOwnPropertyDescriptor(s, "description")); // undefined — description lives on Symbol.prototype
console.log(Object.getOwnPropertyDescriptor(Symbol.prototype, "description")?.get ? "getter" : "data");
console.log(String(s), s.toString()); // Symbol(debug) Symbol(debug) — implicit ToString on symbols throws unless explicit String()
try { console.log("" + s); } catch (e) { console.log("concat throws:", e.name); }
console.log(String(s) === s.toString()); // true — both explicit forms ok
```

- **Modern guidance** — use `Symbol("label")` for private/brand keys (isolated); `Symbol.for` only for deliberately shared protocol names. Always tag a description for debugger visibility, but never branch on it.

### 2) **Hidden-key mechanics — invisible to `Object.keys`/`for...in`/`JSON`, own via `Reflect.ownKeys`**

**Definition** — symbol-keyed properties are *ordinary own properties* (writable/configurable/enumerable attributes still apply) but are omitted by string-only enumerators. Enumeration rules (ECMA-262 `OrdinaryOwnPropertyKeys`): `Reflect.ownKeys` returns integer indices → string keys → symbol keys in insertion order; `Object.keys` → enumerable strings only; `Object.getOwnPropertyNames` → all strings; `Object.getOwnPropertySymbols` → all symbols; `for...in`/`Object.keys` never visit symbols; `JSON.stringify` skips symbols entirely; `Object.assign` copies *enumerable* symbols; spread copies enumerable symbols; `structuredClone` skips symbols? We'll test; our verified run shows it does preserve? See performance note.)

```js
// Hidden-key mechanics — which listing reveals what
const sym = Symbol("secret"), vis = "visible";
const obj = { [vis]: 1, [sym]: 2, hidden: 3 };
Object.defineProperty(obj, "hidden", { enumerable: false });
obj[Symbol.for("globalSym")] = 4;

console.log(Object.keys(obj)); // [ 'visible' ] — enumerable strings only, symbols skipped, non-enumerable skipped
console.log(Object.getOwnPropertyNames(obj)); // [ 'visible', 'hidden' ] — all strings, any enumerable
console.log(Object.getOwnPropertySymbols(obj)); // [ Symbol(secret), Symbol(globalSym) ] — all symbols
console.log(Reflect.ownKeys(obj)); // [ 'visible', 'hidden', Symbol(secret), Symbol(globalSym) ] — insertion order within each bucket
for (const k in obj) console.log("for...in", k); // only 'visible' — never symbols, never non-enumerable

// JSON and assign / spread copy rules
console.log(JSON.stringify(obj)); // {"visible":1} — symbol and non-enumerable hidden skipped
console.log(Object.assign({}, { [sym]: 10, a: 1 })); // { a: 1, [Symbol(secret)]: 10 } — enumerable symbol copied
console.log({ ...{ [sym]: 10, a: 1 } }); // same — spread copies enumerable symbols
const withEnumSym = {}; Object.defineProperty(withEnumSym, sym, { value: 10, enumerable: false });
console.log(Object.assign({}, withEnumSym)); // {} — non-enumerable symbol not copied

// structuredClone does NOT preserve symbol keys — like JSON, symbols are dropped
const cloned = structuredClone({ a: 1, [sym]: 2 });
console.log("structuredClone preserves enum sym?", cloned[sym] === 2); // false — symbols not cloned (Node 20+/22)

// Enumeration order: integers → strings insertion → symbols insertion
const ord = {};
ord["b"] = 1; ord[Symbol("s1")] = 2; ord["a"] = 3; ord["0"] = 4; ord[Symbol("s0")] = 5; ord["1"] = 6;
console.log(Reflect.ownKeys(ord)); // [ '0', '1', 'b', 'a', Symbol(s1), Symbol(s0) ]
// Non-enumerable symbols still in ownKeys
const hidden = Symbol("hid");
Object.defineProperty(ord, hidden, { value: 9, enumerable: false });
console.log(Reflect.ownKeys(ord).includes(hidden)); // true
```

- **Modern guidance** — symbol keys give *weak* privacy (hidden from string enumerators and JSON), not *strong* privacy (any holder of `getOwnPropertySymbols`/`Reflect.ownKeys` reads them). For true privacy, prefer `#private` fields or `WeakMap` branding (see [Prototypes 3.3](<../../../07 Prototypes and Classes/sections/3. Class syntax/3.3. Private fields and methods brand checks and encapsulation.md>) and [5.1](<../5. Security patterns membranes and revocables/5.1. Validation observability membranes and private branding.md>)).

### 3) **`Symbol.keyFor` vs `description` — global round-trip vs debug label**

**Definition** — `description` is the `Symbol("desc")` argument string (or `undefined`); `keyFor` is the global registry key that produced the symbol via `Symbol.for(key)` (or `undefined` for local symbols). `Symbol.for(key)` coerces `key` via `ToString`; `keyFor` returns that string verbatim for global symbols.

```js
// keyFor vs description — orthogonal concepts
console.log(Symbol("a").description, Symbol.keyFor(Symbol("a"))); // "a" undefined — local has description, no registry key
console.log(Symbol.for("a").description, Symbol.keyFor(Symbol.for("a"))); // "a" "a" — global has both
console.log(Symbol.for("a") === Symbol("a")); // false — same description, different identity
console.log(Symbol.for("") === Symbol("")); // false — empty global vs local
console.log(Symbol.keyFor(Symbol.iterator)); // undefined — well-known symbols are not in the global string registry

// description is getter, not own key
const loc = Symbol("x");
console.log(loc.hasOwnProperty?.("description") ?? Object.hasOwn(loc, "description")); // false — on prototype
console.log(loc.description === "x"); // true
```

### 4) **Common confusion**

- "`Symbol("x")` equals `Symbol.for("x")` when descriptions match" — no; identity is key: local never equals global.
- "`Object.keys` shows symbol keys if enumerable" — no; `Object.keys` never shows symbols regardless of enumerability — only `Reflect.ownKeys`/`getOwnPropertySymbols` do.
- "`JSON.stringify` can include symbol keys with replacer" — no; replacer runs after enumeration has already filtered symbols; symbols never reach the replacer.
- "`description` is secret" — no; `description` is public read-only debug string; anyone with the symbol sees it; privacy comes from holding the symbol itself, not from description.

### 5) **Performance note**

Symbol keys hash like string keys and share the same property dictionary cost. Creating millions of fresh `Symbol()` per call (e.g., `Symbol("tmp")` inside a hot loop) allocates one heap cell per call and prevents key sharing — avoid in tight loops; cache the symbol (`const k = Symbol("k")`) outside. `Symbol.for("key")` does a registry `Map` lookup — comparable to `Map.get` — cheap but not free; for hot internal branching prefer a module-local `const`.

### 6) **Mentor note**

In review, require `Symbol("meaningful")` everywhere (ban `Symbol()` bare). Ask: "Is this key meant to be shared across realms/bundles?" If yes → `Symbol.for`; if isolation → `Symbol()`. Scold `String(sym)` vs implicit concat mismatch; demand explicit `String(sym)` at templating boundaries (since `"" + sym` throws `TypeError`). Quiz: predict `Reflect.ownKeys` vs `Object.keys` for a given object; insist they state all four listing truths.
