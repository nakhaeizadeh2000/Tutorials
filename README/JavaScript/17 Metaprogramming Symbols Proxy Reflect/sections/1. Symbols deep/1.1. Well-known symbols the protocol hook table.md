## 1.1. Well-known symbols the protocol hook table

### 1) **Well-known vs ordinary — a shared hook registry**

**Definition** — an *ordinary* symbol (`Symbol("desc")`) is a fresh key each call; a *well-known* symbol (`Symbol.iterator`, `Symbol.hasInstance`, …) is a single shared slot per realm installed on `Symbol` itself. Engines treat the well-known slots as protocol hooks: syntax like `for...of`, `instanceof`, `+`, or `Object.prototype.toString` performs `Get(O, @@hook)` by that well-known symbol.

**What problem it solves / history** — before ES2015 built-in behaviors were magic and uncustomizable. Well-known symbols expose the dispatch: user objects can define `[Symbol.iterator]` to be iterable, `[Symbol.hasInstance]` to intercept `instanceof`, `[Symbol.toPrimitive]` to control coercion, without monkey-patching syntax. Added ES2015 (ES2026 era: 14 well-known symbols, stable).

```js
// Ordinary vs well-known identity
console.log(Symbol("x") === Symbol("x")); // false — fresh each time
console.log(Symbol.for("x") === Symbol.for("x")); // true — global registry (see 1.2)
console.log(Symbol.iterator === Symbol.iterator); // true — well-known singleton
console.log(typeof Symbol.iterator, Symbol.iterator.toString()); // symbol Symbol(Symbol.iterator)

// Engine looks up the well-known slot, not a string name
const iter = { [Symbol.iterator]() { let i = 0; return { next() { return { value: i++, done: i > 3 }; } }; } };
console.log([...iter]); // [0, 1, 2]
console.log("iterator" in iter); // false — string key absent; protocol lives on the symbol
```

- **Modern guidance** — always use the named constant `Symbol.iterator` etc.; never `Symbol.for("Symbol.iterator")` (the global registry is unrelated to the well-known slot and would miss the engine hook).

### 2) **The hook table — which syntax hits which symbol**

**Definition** — each surface syntax maps to one well-known lookup. Missing hook → engine falls back to ordinary behavior (string keys, `valueOf`/`toString`, `OrdinaryHasInstance`).

| Syntax / API | Lookup `O[@@hook]` | Fallback |
|---|---|---|
| `for (const v of obj)` / `...obj` / `Array.from(obj)` | `obj[Symbol.iterator]` | `TypeError: not iterable` |
| `for await (const v of obj)` | `obj[Symbol.asyncIterator]` (probes `@@iterator` second) | awaits sync iterable |
| `a instanceof C` | `C[Symbol.hasInstance]` if present | walk `C.prototype` |
| `[].concat(obj)` spread? | `obj[Symbol.isConcatSpreadable]` | arrays spread, non-arrays appended |
| `Object.prototype.toString.call(obj)` | `obj[Symbol.toStringTag]` | `"Object"` |
| `String(obj)` / `Number(obj)` / `obj + ""` / `obj + 0` | `obj[Symbol.toPrimitive](hint)` | `OrdinaryToPrimitive` (`valueOf`→`toString`) — see [Values 2.3](<../../../03 Values Types and Coercion/sections/2. The conversion algorithms/2.3. ToPrimitive and the valueOf toString and Symbol.toPrimitive dance.md>) |
| `new C(); Array methods: map/filter` etc. | `C[Symbol.species]` | `this.constructor` (or `Array`) |
| `with (obj) { x }` | `obj[Symbol.unscopables]` | none — legacy |
| `str.match(re)` / `str.replace(re, …)` / `str.search` / `str.split` | `re[Symbol.match]` / `re[Symbol.replace]` etc. | `RegExp` internal algo |

```js
// Hook table demos — each syntax consults its symbol
// @@isConcatSpreadable
const bag = { 0: "a", 1: "b", length: 2, [Symbol.isConcatSpreadable]: true };
console.log([].concat(bag)); // ["a", "b"] — object spreads because hook true

// @@toStringTag
console.log(Object.prototype.toString.call({})); // [object Object]
console.log(Object.prototype.toString.call({ [Symbol.toStringTag]: "Widget" })); // [object Widget]

// @@hasInstance — see 4.1 for custom instanceof
class Even { static [Symbol.hasInstance](x) { return typeof x === "number" && x % 2 === 0; } }
console.log(4 instanceof Even, 3 instanceof Even); // true false

// @@toPrimitive — hint dispatched, see Values 2.3 for full dance
const temp = {
  c: 25,
  [Symbol.toPrimitive](hint) { return hint === "string" ? `${this.c}°C` : this.c + 273.15; }
};
console.log(String(temp), Number(temp), temp + 0); // 25°C 298.15 298.15 (default→number)
console.log(`${temp}`); // 25°C — template calls hint "string"

// @@species — which constructor derived objects use
class MyArr extends Array {
  static get [Symbol.species]() { return Array; } // map returns plain Array, not MyArr
}
console.log(new MyArr(1,2,3).map(x => x*2) instanceof MyArr); // false — species forced Array
console.log(new MyArr(1,2,3).map(x => x*2) instanceof Array); // true

// @@match family — String delegates to the pattern's symbol
const glob = {
  pattern: "*.js",
  [Symbol.match](str) { return str.endsWith(".js") ? [str] : null; }
};
console.log("app.js".match(glob)); // ["app.js"] — String called glob[@@match], not RegExp
```

- **Modern guidance** — well-known symbols customize *built-in* dispatch, not arbitrary app hooks. For app plugin keys, use an ordinary `Symbol("myHook")` not a well-known one.

### 3) **Lookup rules — symbol slot, not string key**

**Definition** — the engine does `GetMethod(O, @@hook)` by the symbol value itself. A string-named method `"toPrimitive"` is ignored for `+`; only `Symbol.toPrimitive` is consulted. In coercion, `@@toPrimitive` is tried *first*; missing → `OrdinaryToPrimitive` falls back to `valueOf`/`toString` in hint order. `@@iterator` is looked up on the object directly (including prototype chain via normal property lookup), not on primitives boxed — primitives never consulted for `@@iterator` except strings/arrays built-ins.

```js
// Only the symbol hook matters — string name ignored
const bad = { toPrimitive() { return 999; }, valueOf() { return 1; } };
console.log(Number(bad)); // 1 — valueOf, not toPrimitive string
const good = { [Symbol.toPrimitive](hint) { return hint === "number" ? 999 : "hi"; }, valueOf() { return 1; } };
console.log(Number(good), String(good)); // 999 hi — symbol wins and skips valueOf

// Missing @@toPrimitive → OrdinaryToPrimitive (hint order matters — see Values 2.3)
const both = { valueOf() { return 7; }, toString() { return "seven"; } };
console.log(String(both), both + ""); // "seven" "7" — hint determines order

// Iterator lookup is direct slot access
const weird = { "Symbol.iterator": () => ({ next: () => ({done:true}) }) };
console.log(typeof weird[Symbol.iterator]); // undefined — string key not the symbol
```

### 4) **Common confusion**

- "`Symbol.for("iterator")` equals `Symbol.iterator`" — no; `Symbol.for` touches the global string registry, `Symbol.iterator` is a well-known slot — same string different identity.
- "`[Symbol.toStringTag]` must be a symbol" — no, the slot name *is* a symbol; its *value* is consulted as string via `ToString(tag)`; non-string tag ignored.
- "`@@species` changes `instanceof`" — no; species only controls which constructor *creates* derived objects; `instanceof` consults `@@hasInstance`/prototype chain separately.
- "`@@unscopables` matters for normal code" — only inside `with` (strict code forbids `with`; `@@unscopables` is array-shaped legacy; ES2026 keeps it shipped as Array hides `keys/entries`).

### 5) **Performance note**

Well-known symbol lookup is a single hidden-class slot read (same cost as string slot). Defining an unused well-known symbol on a hot object adds one shape slot but no per-operation cost unless the dispatch actually consults it (e.g., `for...of` probes `@@iterator` once per iteration setup, not per element). Avoid defining `@@toPrimitive` on per-instance objects created millions of times — put it on the prototype instead.

### 6) **Mentor note**

In review, ask: "Which syntax triggers this symbol?" If the answer is vague, the hook is probably wrong. Drill the table until it is instant. Flag any `Symbol.for` used where an ordinary `Symbol()` was meant (global collision) and any string `"toPrimitive"` where `Symbol.toPrimitive` was meant. For `@@toPrimitive`, require handling both `"string"` and `"number"`/`"default"` branches explicitly — a single numeric return silently breaks template interpolation.
