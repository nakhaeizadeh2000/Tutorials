## 2.2. Proxy invariants non-configurable non-extensible and exotic constraints

### 1) **Why invariants exist — the engine relies on `[[GetOwnProperty]]` truthfulness**

**Definition** — a proxy cannot lie about the target's *non-configurable* or *non-extensible* reality. The spec enforces that certain traps return values consistent with the target's actual descriptor and extensibility; violations throw `TypeError` eagerly (even if the caller would not have noticed).

**What problem it solves / history** — without invariants, `Object.freeze` + proxy could fake an extensible object as frozen or hide a non-configurable prop, breaking `Array` length contracts, security membranes, and optimization assumptions. Introduced with `Proxy` in ES2015; invariants tightened in ES2016+ for `ownKeys`+`getOwnPropertyDescriptor` coherence.

```js
// Invariants protect freeze — a proxy that hides a non-configurable prop throws
const target = {};
Object.defineProperty(target, "id", { value: 1, configurable: false, writable: false, enumerable: true });
const lying = new Proxy(target, {
  ownKeys() { return []; }, // lie: hide id
});
try { Object.keys(lying); } catch (e) { console.log("ownKeys lie:", e.name); } // TypeError

try {
  const p2 = new Proxy(target, {
    getOwnPropertyDescriptor(tr, k) { if (k === "id") return undefined; return Reflect.getOwnPropertyDescriptor(tr, k); }
  });
  Object.getOwnPropertyDescriptor(p2, "id");
} catch (e) { console.log("gopd lie:", e.name); } // TypeError

// Non-extensible target: proxy cannot pretend extensible
const sealed = Object.preventExtensions({ a: 1 });
const sneaky = new Proxy(sealed, { isExtensible() { return true; } });
try { console.log(Object.isExtensible(sneaky)); } catch (e) { console.log("isExtensible lie:", e.name); } // TypeError

// Non-configurable descriptor mismatch — cannot report writable true when target is false
const frozen = {};
Object.defineProperty(frozen, "x", { value: 42, writable: false, configurable: false });
const mismatch = new Proxy(frozen, {
  getOwnPropertyDescriptor(tr, k) { return { value: 42, writable: true, configurable: true, enumerable: true }; }
});
try { Object.getOwnPropertyDescriptor(mismatch, "x"); } catch (e) { console.log("descriptor mismatch:", e.message.slice(0, 60)); }
```

- **Modern guidance** — if you `Object.freeze`/`seal`/`preventExtensions` the target, update traps to return truthful descriptors or forward via `Reflect.*` unchanged.

### 2) **The classic `TypeError` traps — which traps have invariant checks**

**Definition** — the spec lists invariant checks per trap (ECMA-262 §28.2 Table 8). Key ones:

| Trap | Must… otherwise `TypeError` |
|---|---|
| `ownKeys` | include every non-configurable own key; if target non-extensible, return exactly the target's keys (no extra, no missing) |
| `getOwnPropertyDescriptor` | if target has non-configurable descriptor for `k`, returned descriptor must be compatible (same `configurable:false`, `writable` not looser, etc.) or `undefined` only if target truly lacks `k` |
| `defineProperty` | cannot report success (`true`) for adding a prop when target non-extensible; cannot report success for changing a non-configurable descriptor incompatibly |
| `setPrototypeOf` | if target non-extensible, new proto must equal target's proto |
| `isExtensible`/`preventExtensions` | must agree with target's actual extensibility (`preventExtensions` must actually make target non-extensible if it returns true) |
| `get` | if target has non-configurable non-writable data prop `k`, must return that exact value (cannot fake) |
| `set` | if target has non-configurable non-writable prop, must not report success for a different value |
| `has` | if target has non-configurable prop, must return `true` |

```js
// get invariant — non-writable non-configurable must return real value
const t = {};
Object.defineProperty(t, "pin", { value: 7, writable: false, configurable: false });
const fakeGet = new Proxy(t, { get() { return 999; } });
try { console.log(fakeGet.pin); } catch (e) { console.log("get lie:", e.name, e.message.slice(0, 50)); }

// set invariant — cannot report success when frozen
const pSet = new Proxy(t, { set() { return true; } });
try { console.log(Reflect.set(pSet, "pin", 8)); } catch (e) { console.log("set lie Reflect:", e.name); }
try { pSet.pin = 8; } catch (e) { console.log("set lie assign:", e.name); } // strict module throws

// defineProperty cannot add when non-extensible
const locked = Object.preventExtensions({ a: 1 });
const pDef = new Proxy(locked, { defineProperty() { return true; } });
try { console.log(Reflect.defineProperty(pDef, "b", { value: 2 })); } catch (e) { console.log("defineProperty lie:", e.name); }

// Non-extensible ownKeys must match exactly — extra key lies
const base = Object.preventExtensions({ x: 1 });
const extra = new Proxy(base, { ownKeys(tr) { return [...Reflect.ownKeys(tr), "y"]; } });
try { Reflect.ownKeys(extra); } catch (e) { console.log("ownKeys extra:", e.name); }
```

- **Modern guidance** — default-forward (`return Reflect.*`) is always invariant-safe. Only hand-craft descriptors/keys when you first read the target's actual descriptor and echo its attributes.

### 3) **`apply` and `construct` belong only to callable/constructable targets**

**Definition** — `Proxy` checks at `[[Call]]`/`[[Construct]]` time that the target is callable/constructable. A non-function target with an `apply` trap still throws `TypeError: proxy target is not callable` at call time; similarly `new` on a non-constructable proxy throws.

```js
// Non-callable target cannot be called even with trap
const obj = {};
const withApply = new Proxy(obj, { apply(t, thisArg, args) { return 1; } });
try { withApply(); } catch (e) { console.log("apply non-callable:", e.name); } // TypeError

// Callable target + missing apply trap forwards normally
function add(a, b) { return a + b; }
const pAdd = new Proxy(add, {}); // no trap → forwards
console.log(pAdd(2, 3)); // 5

// Non-constructable (arrow) cannot be new'd even with construct trap
const arrow = () => {};
const withConstruct = new Proxy(arrow, { construct() { return {}; } });
try { new withConstruct(); } catch (e) { console.log("construct arrow:", e.name); } // TypeError
```

### 4) **Common confusion**

- "`Proxy` can hide `Object.freeze` to keep adding props" — no; invariants tie `isExtensible`/`defineProperty`/`ownKeys` to the target's real state; freeze the *target*, proxy respects it.
- "`ownKeys` can filter non-configurable props for a clean API" — no; including them is mandatory; filter only configurable props or keep the target extensible.
- "`get` can return anything for a frozen prop" — no; frozen data prop's value is pinned; `get` must return exactly that value.
- "`preventExtensions` trap alone freezes virtual properties" — no; `Object.preventExtensions(proxy)` forwards to target; you must also guard `defineProperty`/`set` separately.

### 5) **Performance note**

Invariant checks run on every trapped `ownKeys`/`getOwnPropertyDescriptor`/`isExtensible` call (one extra target descriptor fetch). This is cheap versus the trap call itself. The real cost is that proxies force the object to use the *slow path* dictionary mode; surrounding `Object.keys` on a proxied object cannot use the inline-cache fast path, even when invariants pass.

### 6) **Mentor note**

Require trainees to write the invariant line for each trap they implement: "ownKeys must include all non-configurable keys; get must return frozen value; isExtensible must match." In review, grep for any `ownKeys() { return this._keys; }` that ignores the target — this is a guaranteed crash once the target gets `Object.freeze`/`seal` (often only in prod). Recommend the safe pattern: `ownKeys(t) { const keys = Reflect.ownKeys(t); return keys.filter(k => shouldExpose(k)); }` *only* if non-configurable keys pass through — verify by freezing the target in the test.
