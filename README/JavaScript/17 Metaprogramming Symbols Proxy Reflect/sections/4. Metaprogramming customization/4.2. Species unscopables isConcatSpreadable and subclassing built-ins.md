## 4.2. Species unscopables isConcatSpreadable and subclassing built-ins

### 1) **`@@species` — which constructor built-ins use for derived objects**

**Definition** — when a built-in method creates a new instance (e.g., `Array.prototype.map`/`filter`/`slice`, `Promise.prototype.then`, `RegExp` copy), it consults `this.constructor[Symbol.species]`. If `species` is `null` or not a constructor, it falls back to the default (`Array`, `Promise`, etc.). Default value is the constructor itself.

**What problem it solves / history** — subclassing built-ins (ES2015) needed control over whether derived methods return the subclass or a plain built-in. Without species, `class MyArr extends Array {}` → `myArr.map(...)` returns `MyArr`; override species to `Array` to keep plain arrays, or to `null` for plain.

```js
// @@species controls derived constructor
class MyArr extends Array {
  static get [Symbol.species]() { return Array; } // derived map returns plain Array
}
const a = new MyArr(1,2,3);
console.log(a instanceof MyArr); // true
console.log(a.map(x => x*2) instanceof MyArr); // false — species forced Array
console.log(a.map(x => x*2) instanceof Array); // true
console.log(Array.isArray(a.map(x => x*2))); // true

class MyArr2 extends Array {
  // no species → default is this.constructor → MyArr2
}
console.log(new MyArr2(1,2).map(x => x) instanceof MyArr2); // true

// Species returning null → fallback to Array
class NullSpecies extends Array {
  static get [Symbol.species]() { return null; }
}
console.log(new NullSpecies(1,2).slice(0,1) instanceof Array); // true
console.log(new NullSpecies(1,2).slice(0,1) instanceof NullSpecies); // false

// Non-constructor throws — not a fallback (only null falls back)
class BadSpecies extends Array {
  static get [Symbol.species]() { return {}; }
}
try { console.log(new BadSpecies(1,2).map(x=>x)); } catch (e) { console.log("bad species:", e.name); } // TypeError

// Promise species — controls then chaining
class MyPromise extends Promise {
  static get [Symbol.species]() { return Promise; }
}
const mp = new MyPromise(res => res(1));
console.log(mp.then(x=>x*2) instanceof MyPromise); // false — plain Promise
console.log(mp.then(x=>x*2) instanceof Promise); // true

// Proxy can virtualize species
const arr = new MyArr(1,2);
const proxy = new Proxy(arr, {
  get(t,k,r){
    if (k === "constructor") return { [Symbol.species]: Array };
    return Reflect.get(t,k,r);
  }
});
// arr.map still consults arr.constructor[@@species] — proxy forwards correctly
```

- **Modern guidance** — override `species` only when the subclass adds invariants that derived plain data would violate; otherwise keep default so `map`/`filter` stay in subclass for chaining.

### 2) **`@@unscopables` — hiding from `with` (legacy) and why it still ships**

**Definition** — inside `with (obj) { ... }` (non-strict only), `obj[Symbol.unscopables]` is consulted as a set of keys that must be hidden from the `with` scope. Its value is an object with those keys set to `true`. ES2015 added `Array.prototype[Symbol.unscopables]` to hide new methods from legacy `with` code.

**What problem it solves / history** — adding `Array.prototype.values`/`entries`/`includes`/`flat` would have broken legacy `with (array) { values = 3 }` code that expected assignment to create a new scope variable, not to shadow the method. `unscopables` hides those names inside `with`. `with` is forbidden in strict mode (all modules are strict), so this hook is legacy but still shipped for compatibility. ES2026 keeps it.

```js
// @@unscopables hides keys inside with (sloppy only)
"use strict"; // with forbidden in strict — demo as sloppy via Function
const demo = Function(`
  const arr = [1,2];
  let result;
  with (arr) {
    // inside with, 'values' refers to arr.values unless unscopables hides it
    result = typeof values;
  }
  return result;
`);
console.log(demo()); // undefined — because Array.prototype[@@unscopables].values === true hides it
console.log(Array.prototype[Symbol.unscopables]); // { copyWithin:true, entries:true, fill:true, find:true, flat:true, ... }

const obj = { a: 1, b: 2 };
obj[Symbol.unscopables] = { b: true };
const fn = Function("obj", "with(obj){ return typeof b; }");
console.log(fn(obj)); // undefined — b hidden, returns outer undefined
console.log(fn({ a: 1, b: 2 })); // number? With without unscopables, returns number

// Proxy cannot hide unscopables lazily? It can, but trap must be ownKeys style — demo via get
const proxy2 = new Proxy({ x: 1 }, {
  get(t,k,r){
    if (k === Symbol.unscopables) return { x: true };
    return Reflect.get(t,k,r);
  }
});
console.log(Function("o","with(o){ return typeof x; }")(proxy2)); // undefined — proxy supplied unscopables
```

- **Modern guidance** — never use `with`; knowledge of `unscopables` is for reading specs and understanding `Array.prototype` shape, not for writing code. Do not add new unscopables.

### 3) **`@@isConcatSpreadable` — opt-in/out of `Array.prototype.concat` flattening**

**Definition** — `arr.concat(x)` flattens `x` one level only if `IsConcatSpreadable(x)` is true: `x` is array → true unless `x[Symbol.isConcatSpreadable] === false`; non-array → true only if `x[Symbol.isConcatSpreadable] === true` and `x.length` coercible. No symbol → array-status decides.

```js
// @@isConcatSpreadable controls concat flattening (see Arrays 4.2 for full contract)
console.log([1,2].concat([3,4])); // [1,2,3,4] — array spreads by default
const notSpread = [3,4]; notSpread[Symbol.isConcatSpreadable] = false;
console.log([1,2].concat(notSpread)); // [1,2, [3,4]] — array but opt-out

const spreadable = { 0: "a", 1: "b", length: 2, [Symbol.isConcatSpreadable]: true };
console.log([].concat(spreadable)); // ["a","b"] — non-array opt-in spreads
const notSpreadable = { 0: "a", length: 1 }; // no hook → treated as single element
console.log([].concat(notSpreadable)); // [{0:"a", length:1}]

console.log([].concat({ 0: "a", 1: "b", length: 2 })); // single object — no symbol

// Proxy virtualizing spreadable
const bag = new Proxy({ 0: "x", length: 1 }, {
  get(t,k,r){ if (k === Symbol.isConcatSpreadable) return true; return Reflect.get(t,k,r); }
});
console.log([].concat(bag)); // ["x"] — proxy hook consulted

// Invariants note: isConcatSpreadable is a normal data property lookup (no invariants beyond ordinary Get)
```

### 4) **Common confusion**

- "`species` changes `instanceof`" — no; `instanceof` consults `@@hasInstance`/prototype chain, not species. Species only affects *construction* of derived collections.
- "`species` default is `Array`" — for `Array` methods yes fallback is `Array`, but getter default is `this.constructor` — overriding to return `Array` explicitly forces plain.
- "`isConcatSpreadable: false` on non-array spreads it" — no; non-array needs `true` to spread; `false` on non-array still does not spread.
- "`unscopables` matters for normal code" — only inside `with` (strict code has none); outside `with`, the symbol is inert.

### 5) **Performance note**

`@@species` is looked up once per derived-method call (`map`/`then`/`slice`). Cost is one prototype-chain property fetch. Caching `const S = this.constructor[Symbol.species]` inside a hot custom method that creates derived arrays saves that lookup per iteration.

### 6) **Mentor note**

In review, ask: "Who calls `@@species` — the caller or the callee?" Answer: the *method* (`Array.prototype.map`) reads `this.constructor[Symbol.species]`. Quiz: predict `new MyArr(1,2).map(...).constructor.name` for each species variant. For `isConcatSpreadable`, require the truth table (array vs non-array × hook true/false/undefined → spread?).
