## 5.2. Revocable proxies and security boundaries

### 1) **`Proxy.revocable(target, handler) → {proxy, revoke}` — temporally scoped capability**

**Definition** — `Proxy.revocable` creates a proxy plus a `revoke` function. After `revoke()` is called, every trap invocation (`get`/`set`/`has`/…`apply`/`construct`) throws `TypeError: Cannot perform '...' on a proxy that has been revoked`. The target remains reachable directly (revocation does not mutate or freeze it); only the proxy capability is gone. `revoke()` is idempotent.

```js
// Revocable lifecycle — normal then revoked
const target = { a: 1, get b(){ return this.a * 2; } };
const { proxy, revoke } = Proxy.revocable(target, {
  get(t,k,r){ return Reflect.get(t,k,r); },
  set(t,k,v,r){ return Reflect.set(t,k,v,r); }
});
console.log(proxy.a, proxy.b); // 1 2 — normal
console.log(typeof revoke); // function
revoke();
try { console.log(proxy.a); } catch (e){ console.log("revoked get:", e.name); } // TypeError
try { proxy.a = 2; } catch (e){ console.log("revoked set:", e.name); }
try { "a" in proxy; } catch (e){ console.log("revoked has:", e.name); }
try { Object.keys(proxy); } catch (e){ console.log("revoked ownKeys:", e.name); }
console.log(target.a); // 1 — target direct access still works
revoke(); // idempotent — second revoke no throw
console.log("second revoke ok");

// Revocable function proxy — apply/construct also revoked
function fn(x){ return x*2; }
const { proxy: pFn, revoke: rFn } = Proxy.revocable(fn, {
  apply(t, thisArg, args){ return Reflect.apply(t, thisArg, args) + 1; }
});
console.log(pFn(3)); // 7 — 3*2 +1
rFn();
try { pFn(3); } catch(e){ console.log("revoked apply:", e.name); }
```

- **Modern guidance** — always `revoke()` in a `finally` (or `using`/`Symbol.dispose` in ES2024 tracks) to avoid leaked capabilities; never expose `target` alongside revocable `proxy` if the goal is sandboxing.

### 2) **Use cases — sandboxing, one-shot capabilities, test isolation, timeout-guarded APIs**

**Definition** — revocables suit any pattern where a reference must expire: untrusted code receives a membrane-wrapped global that is revoked after evaluation; a one-shot event handler capability; a test that must ensure no async retention after `t.teardown`; a `withTimeout` wrapper that revokes the API after `AbortSignal`.

```js
// Sandbox — give untrusted code a revocable global
function sandbox(code){
  const env = { log(...args){ console.log("[sandbox]", ...args); } };
  const { proxy, revoke } = Proxy.revocable(env, {});
  try {
    Function("global", code)(proxy);
  } finally { revoke(); }
  return proxy; // caller holds revoked proxy — further use throws
}
const p = sandbox(`global.log("hi");`);
try { p.log("after"); } catch(e){ console.log("after revoke:", e.name); }

// One-shot capability — handler usable once
function oneShot(fn){
  let live = true;
  const { proxy, revoke } = Proxy.revocable(fn, {
    apply(t, thisArg, args){
      if (!live) throw new TypeError("one-shot consumed");
      live = false; revoke(); return Reflect.apply(t, thisArg, args);
    }
  });
  return proxy;
}
const once = oneShot((x)=> x*3);
console.log(once(4)); // 12
try { once(4); } catch(e){ console.log("second call:", e.name, e.message.slice(0,30)); }

// Timeout-guarded API — revoke after signal aborts (see 5.1 membrane for wrapping graph)
function withTimeout(obj, ms){
  const { proxy, revoke } = Proxy.revocable(obj, {});
  const id = setTimeout(() => { revoke(); console.log("revoked after timeout"); }, ms);
  // caller clears timer and revokes explicitly when done — omitted for brevity
  return { proxy, revoke: () => { clearTimeout(id); revoke(); } };
}
const api = { fetch(x){ return `data:${x}`; } };
const gated = withTimeout(api, 50);
console.log(gated.proxy.fetch("ok")); // data:ok
setTimeout(()=> { try{ console.log(gated.proxy.fetch("late")); } catch(e){ console.log("late:", e.name); } }, 60);
```

### 3) **Composition gotchas — revoking an inner proxy does not revoke its membrane wrapper**

**Definition** — membranes and revocables compose but revocation does not transitively propagate. If `m = membrane(target)` then `r = Proxy.revocable(m, h)`, revoking `r` revokes only `r`; `m` remains live. If `m` wraps `target` and you revoke `target`'s proxy, already-vended nested proxies (e.g., `m.nested`) remain live unless the membrane tracks them.

```js
// Revoking inner does not revoke outer — design revoke graph explicitly
const inner = { x: 1 };
const { proxy: innerP, revoke: revokeInner } = Proxy.revocable(inner, {});
const outer = new Proxy(innerP, { get(t,k,r){ return Reflect.get(t,k,r); } });

revokeInner();
try { console.log(outer.x); } catch (e){ console.log("outer after inner revoke:", e.name); } // TypeError — outer forwards to revoked inner

// Reverse — outer revoke does not revoke inner
const inner2 = { x: 1 };
const outer2 = { inner: inner2 };
const { proxy: outerP2, revoke: revokeOuter } = Proxy.revocable(outer2, {
  get(t,k,r){
    const v = Reflect.get(t,k,r);
    // naive membrane without revoke tracking: nested stays live
    return v && typeof v === "object" ? new Proxy(v, {}) : v;
  }
});
const nested = outerP2.inner; // vended nested proxy (not revocable, not tracked)
revokeOuter();
console.log("nested after outer revoke:", nested.x); // 1 — leaked! membrane did not revoke nested
// Fix: membrane must track every vended proxy plus its revoke in a Set and revoke all together

// Revocable membrane pattern — track revokes
function revocableMembrane(root){
  const revokes = new Set();
  const cache = new WeakMap();
  function wrap(obj){
    if (obj === null || typeof obj !== "object") return obj;
    if (cache.has(obj)) return cache.get(obj);
    const { proxy, revoke } = Proxy.revocable(obj, {
      get(t,k,r){
        const v = Reflect.get(t,k,r);
        return v && typeof v === "object" ? wrap(v) : v;
      }
    });
    cache.set(obj, proxy);
    revokes.add(revoke);
    return proxy;
  }
  return {
    proxy: wrap(root),
    revokeAll(){ for (const r of revokes) r(); revokes.clear(); }
  };
}
const root = { a: { b: 1 } };
const rm = revocableMembrane(root);
const aProxy = rm.proxy.a;
console.log(aProxy.b); // 1
rm.revokeAll();
try { console.log(aProxy.b); } catch(e){ console.log("aProxy after revokeAll:", e.name); }
try { console.log(rm.proxy.a); } catch(e){ console.log("root proxy after revokeAll:", e.name); }
```

- **Modern guidance** — for revocable membranes, keep a `Set<revoke>` of every vended proxy's revoke and a `WeakMap` for identity; `revokeAll()` iterates the set. Never vendor a non-revocable nested proxy from a revocable root.

### 4) **Common confusion**

- "`revoke()` destroys the target" — no; target stays reachable via direct reference; only the proxy capability throws.
- "`Proxy.revocable` is a constructor" — no; it is a static factory returning `{proxy, revoke}` — not `new Proxy.revocable`.
- "`revoke()` throws if already revoked" — no; idempotent — second call is no-op.
- "`Proxy` is a security boundary by itself" — only with correct handler (trap invariants) plus revocation/membrane composition; a plain `new Proxy(target, {})` is transparent, not a boundary.

### 5) **Performance note**

Each `Proxy.revocable` allocates one extra closure for `revoke` plus the proxy exotic. Trapped operations cost same as non-revocable proxy. `revoke()` itself is cheap (flips an internal `[[Revoked]]` slot). Keeping a `Set` of revokes for membranes adds O(n) on `revokeAll()` where n is number of vended proxies.

### 6) **Mentor note**

Require any sandbox/membrane doc to include a revocation diagram: which nested proxies are revoked by which call. Scold leaking `target` alongside `proxy` ("you revoked the door but left the window open"). Whiteboard the double-Wrap gotcha (`outer` vs `inner` revocation) — most juniors miss it.
