## 3.1. Reflect API vs operator and Object equivalents

### 1) **One API, two contracts — `Reflect.*` returns boolean where operators throw**

**Definition** — `Reflect` is a plain object (`typeof Reflect === "object"`) whose nine static methods mirror the Proxy traps. Where `Object.defineProperty` throws on failure, `Reflect.defineProperty` returns `false`; where `obj[k]=v` may throw in strict mode, `Reflect.set` returns `boolean` indicating success without throwing (strictness still surfaces via invariant `TypeError`).

**What problem it solves / history** — traps need a composable forwarding call that does not itself throw on soft failures (so the trap can decide). `Reflect` provides that: `return Reflect.set(...)` gives the correct boolean contract for the trap without duplicating error branching. Absent before ES2015; now the idiomatic forwarding target.

```js
// Return contract difference — Object throws, Reflect returns boolean
"use strict";
const frozen = {};
Object.defineProperty(frozen, "x", { value: 1, writable: false, configurable: false, enumerable: true });

try { Object.defineProperty(frozen, "x", { value: 2 }); } catch (e) { console.log("Object.defineProperty throws:", e.name); }
console.log(Reflect.defineProperty(frozen, "x", { value: 2 })); // false — same failure, no throw

// Reflect.set boolean vs assignment throw
const p = new Proxy(frozen, { set(t,k,v,recv){ return Reflect.set(t,k,v,recv); } });
console.log(Reflect.set(p, "x", 99)); // throws TypeError due to invariant (frozen) — not silent false
// Non-frozen soft failure
const soft = Object.preventExtensions({ a: 1 });
console.log(Reflect.defineProperty(soft, "b", { value: 2 })); // false
try { Object.defineProperty(soft, "b", { value: 2 }); } catch (e) { console.log("defineProperty throws:", e.name); }

// Why this matters in traps — trap must return boolean, Reflect gives it
const validator = new Proxy({ count: 0 }, {
  set(t,k,v,recv) {
    if (k === "count" && typeof v !== "number") return false; // signal failure → caller gets false / strict throws
    return Reflect.set(t,k,v,recv);
  }
});
console.log(Reflect.set(validator, "count", "bad")); // false — trap returned false
try { validator.count = "bad"; } catch (e) { console.log("strict assign throws:", e.name); }
console.log(Reflect.set(validator, "count", 5), validator.count); // true 5
```

### 2) **The twin table — operator/`Object.*` vs `Reflect.*`**

**Definition** — each surface operation maps to both a trap and a `Reflect` twin:

| Surface | `Object.*` / operator | `Reflect.*` |
|---|---|---|
| `obj[k]` | — (`Get`) | `Reflect.get(target, k, receiver)` |
| `obj[k]=v` | — (`Set`) | `Reflect.set(target, k, v, receiver)` |
| `k in obj` | — | `Reflect.has(target, k)` |
| `delete obj[k]` | — | `Reflect.deleteProperty(target, k)` |
| `Object.getOwnPropertyDescriptor(obj,k)` | same | `Reflect.getOwnPropertyDescriptor(target,k)` |
| `Object.defineProperty(obj,k,d)` | throws | `Reflect.defineProperty(target,k,d)` → boolean |
| `Object.getOwnPropertyNames/Symbols` / `Object.keys` internal `ownKeys` | `Reflect.ownKeys(target)` | same list (strings+symbols) |
| `Object.getPrototypeOf(obj)` | same | `Reflect.getPrototypeOf(target)` |
| `Object.setPrototypeOf(obj,proto)` | throws | `Reflect.setPrototypeOf(target,proto)` → boolean |
| `Object.isExtensible(obj)` / `Object.preventExtensions(obj)` | — | `Reflect.isExtensible` / `Reflect.preventExtensions` |
| `fn(...args)` | `fn.apply(thisArg,args)` / `fn.call` | `Reflect.apply(target, thisArg, args)` |
| `new C(...args)` | — | `Reflect.construct(target, args, newTarget)` |

```js
// Twin table demos — same value, different throwing contract
const t = { a: 1, get b() { return this.a; } };
console.log(Reflect.get(t, "a"), t["a"]); // 1 1
console.log(Reflect.get(t, "b", { a: 99 })); // 99 — receiver forwarding (see 3.2)
console.log(Reflect.has(t, "a"), "a" in t); // true true
console.log(Reflect.deleteProperty(t, "a"), delete t["a"]); // false? t still has a? Actually deleted true now

const ar = [1,2]; console.log(Reflect.ownKeys(ar)); // [ '0','1','length' ] vs Object.keys → [ '0','1' ]
console.log(Reflect.ownKeys({ [Symbol("s")]: 1, b: 2 })); // [ 'b', Symbol(s) ]

// apply/construct with correct this / newTarget
function Ctor(x){ this.x = x; }
const inst = Reflect.construct(Ctor, [5]);
console.log(inst.x); // 5
console.log(Reflect.apply(Math.max, null, [3,9,2])); // 9

// defineProperty twin — boolean vs throw (shown in §1)
```

### 3) **`Reflect.ownKeys` is the truthful listing — strings + symbols + non-enumerable**

**Definition** — `Reflect.ownKeys` returns `OwnPropertyKeys` = integer indices → string keys → symbol keys in creation order, including non-enumerable and non-configurable. `Object.keys` is `ownKeys` filtered to enumerable strings; `Object.getOwnPropertyNames` is strings only; `getOwnPropertySymbols` is symbols only. No other listing reveals the full truth.

```js
// Truthful listing — which API hides what
const obj = { b: 1, a: 2 };
obj[Symbol("s")] = 3;
Object.defineProperty(obj, "hidden", { value: 4, enumerable: false });
obj[1] = 5; obj[0] = 6; // integer indices sort first

console.log(Object.keys(obj)); // [ 'b', 'a', '0', '1' ]? Actually ints first: [ '0','1','b','a' ] — enumerable strings only
console.log(Object.getOwnPropertyNames(obj)); // [ '0','1','b','a','hidden' ] — all strings
console.log(Object.getOwnPropertySymbols(obj)); // [ Symbol(s) ]
console.log(Reflect.ownKeys(obj)); // [ '0','1','b','a','hidden', Symbol(s) ] — full truth

// Sparse arrays — ownKeys excludes holes
const sparse = [1,,3]; // hole at 1
console.log(Reflect.ownKeys(sparse)); // [ '0','2','length' ] — hole absent
console.log(sparse.length); // 3 — length not the key count
```

### 4) **Common confusion**

- "`Reflect.defineProperty` is same as `Object.defineProperty`" — no; `Object` throws `TypeError` on soft failure (non-extensible, frozen), `Reflect` returns `false` — traps must return boolean, so always use `Reflect`.
- "`Reflect.set` equals `target[key]=value`" — no; assignment coerces to `Set` internal method with default receiver `target`, losing the proxy receiver chain — see 3.2.
- "`Reflect.ownKeys` equals `Object.keys`" — no; keys excludes symbols, non-enumerable, and sorts but hides them; `ownKeys` is the superset.
- "`Reflect.apply` equals `Function.prototype.apply`" — mostly yes, but `Reflect.apply` works even when `target` is a Proxy exotic function, and it validates `target` callable centrally.

### 5) **Performance note**

`Reflect.*` is a single C++ builtin call — comparable to the operator itself. Using `Reflect.get` instead of `target[key]` inside a trap adds no measurable overhead beyond the indirection already paid for the proxy. Prefer `Reflect.*` universally inside handlers; the cost is the proxy, not the `Reflect` forwarding.

### 6) **Mentor note**

Lint rule: inside any `get/set/has/deleteProperty/ownKeys/*` trap, forbid `target[prop]`, `delete target[prop]`, `Object.*` — require `Reflect.*`. In review, ask: "What does this trap return when the target is non-extensible?" — if answer is `true` unconditionally, invariant fails in prod. Drill the twin table until mapping is instant.
