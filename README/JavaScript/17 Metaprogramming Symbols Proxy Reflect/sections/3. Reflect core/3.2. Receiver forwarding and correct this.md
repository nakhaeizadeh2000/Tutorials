## 3.2. Receiver forwarding and correct this

### 1) **Why `receiver` exists — accessor `this` must be the proxy, not the target**

**Definition** — internal methods `[[Get]](P, Receiver)` and `[[Set]](P, V, Receiver)` receive the original object that was accessed (`proxy` in `proxy[prop]`). If `P` resolves to an accessor on `target`, the getter/setter's `this` parameter must be `Receiver`, not `target`. `Reflect.get(target, key, receiver)` and `Reflect.set(target, key, value, receiver)` thread that value through exactly.

**What problem it solves / history** — without `receiver`, a proxy getter like `get value() { return this._value; }` would read `target._value` even when the proxy has its own shadowing `_value`. Correct forwarding makes membranes, validation, and private-state proxies work: the `this` inside accessors tracks the outermost proxy. Added with `Proxy`/`Reflect` in ES2015.

```js
// Receiver ties accessor this to the proxy chain
const target = {
  _v: 1,
  get v() { return this._v; },
  set v(x) { this._v = x; }
};
const proxy = new Proxy(target, {
  get(t, k, recv) { return Reflect.get(t, k, recv); },
  set(t, k, v, recv) { return Reflect.set(t, k, v, recv); }
});

const base = { get self() { return this; } };
const p = new Proxy(base, { get(t,k,r){ return Reflect.get(t,k,r); } });
console.log(p.self === p); // true — getter this is proxy
console.log(Reflect.get(base, "self", base) === base); // true
console.log(Reflect.get(base, "self", {}) === base); // false — this is the passed receiver
```

- **Modern guidance** — inside any `get`/`set`, always forward via `Reflect.get(target, prop, receiver)` / `Reflect.set(target, prop, value, receiver)` — never via `target[prop]`.

### 2) **The broken pattern — `target[key]` loses proxy `this` and breaks membranes**

**Definition** — `target[key]` performs `[[Get]](key, target)` with `Receiver = target`, so any accessor's `this` is fixed to `target`. The proxy's own shadowing keys or private branding via `WeakMap` then leak.

```js
// Broken forwarding — accessor this leaks to target
const vault = {
  _secret: "target-secret",
  get secret() { return this._secret; },
  set secret(v) { this._secret = v; }
};
const broken = new Proxy(vault, {
  get(t, k) { return t[k]; },          // ← broken
  set(t, k, v) { t[k] = v; return true; }
});
broken._secret = "proxy-secret"; // t[k]= sets on target, not proxy
console.log(vault._secret); // proxy-secret — leaked to target
console.log(broken.secret); // proxy-secret — getter this was target, still reads target's mutated _secret
// looks correct but mutation hit wrong object; membrane isolation broken

// Correct forwarding isolates via receiver
const vault2 = { _secret: "target-secret", get secret(){ return this._secret; }, set secret(v){ this._secret = v; } };
const fixed = new Proxy(vault2, {
  get(t,k,r){ return Reflect.get(t,k,r); },
  set(t,k,v,r){ return Reflect.set(t,k,v,r); }
});
// Demonstrate getter identity separation (set still writes through chain — see note below)
const selfTarget = { get self(){ return this; } };
const badSelf = new Proxy(selfTarget, { get(t,k){ return t[k]; } });
console.log(badSelf.self === badSelf); // false — broken returns target
console.log(badSelf.self === selfTarget); // true — leaked
const goodSelf = new Proxy(selfTarget, { get(t,k,r){ return Reflect.get(t,k,r); } });
console.log(goodSelf.self === goodSelf); // true — correct

// Setter receiver write-through: Reflect.set sets where [[Set]] says, which for existing data prop _secret on target writes to target (not receiver)
// To isolate private state, keep confidential data in WeakMap keyed by proxy instead (see 5.1)
```

- **Modern guidance** — `target[key]` inside a trap is almost always a bug. Lint for it. The exception is when you intentionally want target-anchored `this` (rare, documented).

### 3) **Writing with receiver — `Reflect.set(target, key, value, receiver)` respects setter `this`**

**Definition** — `Reflect.set` returns `boolean` and respects `[[Set]]` semantics: if property is an accessor, it calls the setter with `this = receiver`; if data property is writable, it defines/assigns on `receiver` when appropriate; otherwise returns `false`.

```js
// Setter this is receiver
const proto = { set x(v){ this._x = v; } };
const obj = Object.create(proto);
obj._x = 1;
const pr = new Proxy(obj, { set(t,k,v,r){ return Reflect.set(t,k,v,r); } });
pr.x = 9;
console.log(pr._x, obj._x); // 9 1 — setter this was proxy (receiver), created own _x on proxy
console.log(Object.hasOwn(pr, "_x")); // true
console.log(Object.hasOwn(obj, "_x")); // true — preserved original

// Without receiver forwarding, setter mutates target
const prBroken = new Proxy(obj, { set(t,k,v){ t[k]=v; return true; } });
prBroken.x = 7;
console.log(obj._x); // 7 — leaked

// Return contract — strict failure
"use strict";
const frozen = {};
Object.defineProperty(frozen, "ro", { value: 1, writable: false, configurable: false });
const pFrozen = new Proxy(frozen, { set(t,k,v,r){ return Reflect.set(t,k,v,r); } });
console.log(Reflect.set(pFrozen, "ro", 2)); // false (non-strict soft)
try { pFrozen.ro = 2; } catch (e) { console.log("strict:", e.name); } // TypeError in strict
```

### 4) **Common confusion**

- "`Reflect.get` without `receiver` equals `target[key]`" — almost, but default receiver is `target` so it still loses proxy identity; always pass the trap's `receiver` param.
- "`Reflect.set` creates the key on the proxy" — only when the `[[Set]]` semantics say so (no inherited non-writable, respects extensibility); for existing writable data prop on target, it mutates target's descriptor storage even with proxy receiver — to keep per-proxy private state, use `WeakMap` (see [5.1](<../5. Security patterns membranes and revocables/5.1. Validation observability membranes and private branding.md>)).
- "`receiver` is always the proxy" — yes for direct `proxy.prop`; for `Reflect.get(proto, key, receiver)` walking, receiver is still the original proxy from the entry point; prototype chain copies it forward.

### 5) **Performance note**

Passing `receiver` does not add extra allocation beyond the trap call's existing args. The engine already passes `Receiver` internally; `Reflect.get` just reuses it. Cost is identical to `target[key]` plus correctness.

### 6) **Mentor note**

In review, reject any `get(t,k){ return t[k]; }` or `set(t,k,v){ t[k]=v; return true; }`. Require `Reflect.get(t,k,receiver)` / `Reflect.set(t,k,v,receiver)`. Ask: "What does `this` inside this accessor resolve to?" If answer is `target`, challenge why the membrane exists. Show the `self` identity test (`proxy.self === proxy`) as the canonical litmus.
