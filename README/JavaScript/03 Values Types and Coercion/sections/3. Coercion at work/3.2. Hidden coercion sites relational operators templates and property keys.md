## 3.2. Hidden coercion sites: relational operators, templates, and property keys

### 1) **Relational operators always take the numeric path — unless both operands end up strings**

**Definition** — `<`, `>`, `<=`, `>=` run ToPrimitive with the *number* hint on both operands. Then: if both results are strings, comparison is **lexical (character by character)**; otherwise it's numeric:

```js
console.log("10" < "9");      // true! — both strings → "1" < "9" lexically
console.log(10 < 9);          // false — numeric
console.log("abc" < "abd");   // true  — c < d
console.log(["8"] < 9);       // true  — ["8"]→"8", but other side is number → numeric path
```

- This is why unsorted string arrays "sort wrong" and why numeric-looking strings from inputs misbehave in ranges — convert to numbers before comparing ([sort pitfalls](<../7. Common pitfalls to production bugs/7.1. Real production bugs caused by coercion.md>)).
- `NaN` poisons all four operators: any comparison where a side converts to NaN is `false` — including `undefined <= 1` and `undefined >= 1` being false simultaneously.
- `null` is the special case: `null >= 0` is `true` (ToNumber(null)=0) while `null == 0` is `false` (loose equality never numerically converts null). Two algorithms, two answers, both spec-correct.

### 2) **Property access stringifies keys**

Bracket access applies ToPropertyKey → ToString to whatever you pass; only symbols bypass conversion:

```js
const obj = {};
obj[1] = "a";
obj["1"] = "b";
console.log(obj[1]);                        // b — SAME key: 1 became "1"

const arr = ["x"];
arr[1.0] = "y";                             // 1.0 → "1"
console.log(arr["1"], Object.keys(arr));    // y [ '0', '1' ]

const keyed = {
  toString() { return "tsKey"; },
};
keyed[keyed] = "v";                         // object key → toString → "tsKey"
console.log(keyed.tsKey);                   // v

console.log(1 in ["a", "b"]);               // true — even `in` stringifies
```

- Practical consequences: numeric map-like behavior on plain objects silently merges integer and string keys; float indices collapse (`arr[1.5]` becomes an ordinary *property* named "1.5"); objects as keys stringify away their identity (`{}`-as-key always hits "[object Object]") — that's what `Map` exists for (Collections, Map, Set, and Weak References domain).

### 3) **Template interpolation calls ToString**

`${x}` inserts ToString(x) — with symbol as the one throwing exception:

```js
console.log(`n=${42}, arr=${[1,2]}, obj=${{}}`);  // n=42, arr=1,2, obj=[object Object]
try { `${Symbol("s")}` } catch { console.log("symbols throw in templates"); }
console.log(`sym=${String(Symbol("s"))}`);        // sym=Symbol(s) — explicit form OK
```

- Ternary conditions, `if`, loop conditions, and logical-operator operand tests coerce via ToBoolean ([falsy list](<../2. The conversion algorithms/2.4. ToBoolean the complete falsy list.md>)) — but `&&`/`||` *return the original operand*, not a boolean.

### 4) **Common confusion**

- "`"10" < "9"` must be false" — lexical comparison of equal-length digit strings compares first characters; leading zeros/variable widths break numeric intuition.
- "`switch` coerces cases" — no: switch uses strict-equality semantics ([02 §2.1](<../../../02 Language Basics/sections/2. Control flow/2.1. Conditionals if switch ternary and fallthrough traps.md>)); coercion surprises live in `<`/`>` and arithmetic, not switch.
- "`obj[{...}]` throws" — it doesn't unless conversion fails; the object just stringifies (usually uselessly).

### 5) **Performance note**

String-keyed access on shapes (hidden classes) is heavily optimized; converting a non-string key per access adds a canonicalization step each time. Pre-stringify hot-loop keys or use Map when keys are genuinely non-string values.

### 6) **Mentor note**

These sites matter because they're invisible at review time: `"10" < "9"` reads like math, `obj[id]` looks type-safe. Teach juniors to ask "what's the *type* of every operand here?" whenever they see relational operators or bracket access near input boundaries. Grep-worthy patterns: `<`/`>` applied to values that came from `dataset.*`, `querySelectorAll` results, or JSON without validation.
