## 6.1. Coercion checklist: reflex rules mentors screen for

### 1) **Convert at boundaries, compute inside**

The single habit that prevents most coercion bugs — validate/normalize data when it *enters* your code (form input, API payloads, query params), then trust types internally:

```js
function applyDiscount(rawPrice, rawPercent) {
  const price = Number(rawPrice);        // boundary: explicit conversion
  const percent = Number(rawPercent);
  if (!Number.isFinite(price) || !Number.isFinite(percent)) {
    throw new TypeError("price and percent must be finite numbers");
  }
  return price * (1 - percent / 100);    // inside: pure numeric math
}

console.log(applyDiscount("100", "25"));  // 75   — string inputs normalized once
try {
  applyDiscount("100px", "25");
} catch (e) {
  console.log(e.message);                 // loud failure beats silent nonsense
}
```

- Contrast with the bug this replaces: `"100" * "25"` happens to work while `"100" + "25"` yields `"10025"` — the `+` overload waits months for its moment ([pitfall](<../7. Common pitfalls to production bugs/7.1. Real production bugs caused by coercion.md>)).

### 3) **Review checklist items (grep before ship)**

1. **Arithmetic on possibly-string data** — anything from DOM (`dataset`, `.value`), URL params, JSON without validation.
2. **Bare `parseInt(` without radix**, and `parseInt/parseFloat` where validity mattered more than extraction.
3. **Global `isNaN`/`isFinite`** — should usually be `Number.`-prefixed.
4. **`||` defaults on values that may legitimately be `0`/`""`/`false`** — needs `??`.
5. **`new String|Number|Boolean(`** — always a defect ([4.1](<../4. Boxing and wrapper objects/4.1. Wrapper objects vs primitives boxing demystified.md>)).
6. **Relational operators near unvalidated strings** — `"10" < "9"` territory ([3.2](<../3. Coercion at work/3.2. Hidden coercion sites relational operators templates and property keys.md>)).
7. **IDs > 2^53 handled as Numbers** — must be strings or BigInt end-to-end ([5.2](<../5. The exotic primitives Symbol and BigInt/5.2. BigInt integers beyond MAX_SAFE_INTEGER.md>)).

### 4) **Common confusion**

- "Checklists replace understanding" — backwards: these reflexes exist so you *don't* need to run the algorithms mentally per line; when a result surprises you anyway, drop into the linked leaf and narrate the chain.
- "TypeScript makes this domain obsolete" — it moves type errors to compile time at boundaries you still write; runtime inputs (API responses, user input) still cross into typed land somewhere.

### 5) **Mentor note**

Use section 2's table as a verbal screening: candidates who can produce all five reflexes unprompted are safe to leave unsupervised around legacy JS. For teaching juniors, drill the boundary-conversion habit first — one week of writing `Number(...)` + `Number.isFinite` guards at every entry point builds the instinct that makes everything else in this domain feel like archaeology rather than survival.
