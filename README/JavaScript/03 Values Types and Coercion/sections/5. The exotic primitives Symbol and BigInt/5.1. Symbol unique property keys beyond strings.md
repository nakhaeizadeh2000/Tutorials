## 5.1. Symbol: unique property keys beyond strings

### 1) **Every symbol is unique; descriptions are labels, not identities**

**Definition** — `Symbol` (ES2015) is the seventh primitive: an immutable, guaranteed-unique value usable as a property key. The optional argument is a *description* for debugging — two symbols with equal descriptions are still different values:

```js
const id1 = Symbol("id");
const id2 = Symbol("id");
console.log(id1 === id2);        // false — uniqueness is the whole point
console.log(id1.description);    // "id"  — label, not identity
console.log(typeof id1);         // "symbol" — its own primitive type
```

- Use cases: collision-proof keys on shared/extensible objects ("my library attaches this"), enum-like constants, and protocol extension points ([well-known symbols](#3-well-known-symbols-are-the-languages-hook-registry)).
- Need cross-realm/cross-module identity? That's what the global registry is for:

```js
const role1 = Symbol.for("role");     // registry lookup-or-create
const role2 = Symbol.for("role");
console.log(role1 === role2);          // true — same registry key, same symbol
console.log(Symbol.keyFor(role1));     // "role"
console.log(Symbol.keyFor(Symbol("x")));// undefined — plain symbols aren't registered
```

### 2) **Symbols hide from the usual key listings**

Symbol-keyed properties exist but stay invisible to string-key tooling:

```js
const internal = Symbol("cache");
const obj = { visible: 1, [internal]: 2 };

console.log(Object.keys(obj));              // [ "visible" ]
for (const key in obj) console.log(key);    // visible only
console.log(JSON.stringify(obj));           // {"visible":1}

// But they're real keys — not private:
console.log(internal in obj);               // true
obj[internal] = 99;
console.log(Object.getOwnPropertySymbols(obj).length); // 1 — findable when you look
```

- This is *namespacing*, **not privacy**: anything holding the symbol can read/write the property. True encapsulation needs closures or `#private` class fields.
- Serialization skips them (JSON), which makes symbol keys a decent way to attach metadata that shouldn't leak into payloads.

### 3) **Well-known symbols are the language's hook registry**

`Symbol.iterator`, `Symbol.toPrimitive`, `Symbol.hasInstance`, `Symbol.toStringTag`, `Symbol.species`… let your objects plug into core behaviors:

```js
class Even {
  static [Symbol.hasInstance](x) {
    return typeof x === "number" && x % 2 === 0;
  }
}
console.log(4 instanceof Even);   // true — instanceof now calls YOUR method

class Wallet {
  get [Symbol.toStringTag]() { return "Wallet"; }   // instance getter, not static!
}
console.log(`${new Wallet()}`);   // [object Wallet]
```

- Deep dives live in their own domains (iteration → Iterables/Generators; conversion hooks → [2.3](<../2. The conversion algorithms/2.3. ToPrimitive and the valueOf toString and Symbol.toPrimitive dance.md>); Proxy/Reflect interplay → Metaprogramming domain).

### 4) **They refuse string contexts**

Implicit coercion can't leak a symbol into a string — deliberate design:

```js
const sym = Symbol("s");
try { "" + sym; } catch { console.log("+ throws TypeError"); }
try { `${sym}`; } catch { console.log("templates throw TypeError"); }
console.log(String(sym));   // Symbol(s) — explicit String() is allowed
```

- Contrast with every other primitive: numbers, booleans, null, undefined all stringify implicitly. Symbols alone throw — so a typo'd concatenation fails loudly instead of silently corrupting keys.

### 5) **Common confusion**

- "`Object.keys` didn't show it, so it's private" — no; `Object.getOwnPropertySymbols` and `Reflect.ownKeys` list them. Never store secrets in symbol keys.
- "`Symbol.for` vs `Symbol` is style" — different semantics: registry shares globally; plain literals are unique everywhere. Mixing them up creates subtle identity bugs.
- "`typeof sym === "symbol"` but `sym instanceof Symbol` works" — instanceof is false for primitives (wrappers only, [4.1](<../4. Boxing and wrapper objects/4.1. Wrapper objects vs primitives boxing demystified.md>)).

### 6) **Performance note**

Symbol-keyed access is as fast as string-keyed (engines treat both as first-class keys in hidden classes). Uniqueness means engines can't always share shapes across objects using *different* symbols for the same conceptual slot — keep symbol keys per-concept consistent within a codebase.

### 7) **Mentor note**

Frame symbols as "the fix for stringly-typed extensibility": before ES2015 libraries patched objects with string keys and collided. Review checklist: prefer module-scoped `const s = Symbol("desc")`; reserve `Symbol.for` for genuine cross-realm needs; never claim privacy from symbols.
