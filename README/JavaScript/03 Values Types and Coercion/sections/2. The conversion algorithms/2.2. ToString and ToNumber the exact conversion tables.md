## 2.2. ToString and ToNumber: the exact conversion tables

### 1) **ToNumber's asymmetric null/undefined row**

**Definition** — ToNumber is the abstract operation behind every "make this a number" moment (arithmetic, `Number()`, `==` with strings). Its table has one row pair every JS developer should memorize:

| Input | Result | Why it matters |
|-------|--------|----------------|
| `undefined` | `NaN` | missing data poisons arithmetic |
| `null` | `+0` | "deliberately empty" counts as zero |
| `true` / `false` | `1` / `+0` | legacy boolean-arithmetic |
| string | parse whole literal; empty/whitespace → `0`; else `NaN` | see row 2 below |
| symbol | **TypeError** | symbols refuse numeric context |
| bigint | TypeError via implicit paths (`+10n` throws); `Number(10n)` works explicitly | constructor takes a special branch |
| object | ToPrimitive(number hint) then re-apply this table | [2.3](<./2.3. ToPrimitive and the valueOf toString and Symbol.toPrimitive dance.md>) |

```js
console.log(Number(null), Number(undefined));  // 0 NaN — the asymmetry
console.log(null + 1, undefined + 1);          // 1 NaN — same asymmetry through operators
```

### 2) **String parsing accepts full numeric literals only**

```js
console.log(Number("42"), Number(" 42 "), Number(""));       // 42 42 0
console.log(Number("0x10"), Number("0b101"), Number("0o17"));// 16 5 15 — prefixes OK
console.log(Number("+5"), Number("-Infinity"));              // 5 -Infinity — signs OK
console.log(Number("1_000"));                                // NaN — separators NOT valid here
console.log(Number("12px"));                                 // NaN — partial parse never happens
```

- Whitespace-only becomes `0`, not NaN — the source of many silent-zero bugs from empty form fields.
- No underscores, no commas, no units, no partial matches. Anything unparseable is NaN — which then *propagates* through every further operation ([pitfall](<../7. Common pitfalls to production bugs/7.1. Real production bugs caused by coercion.md>)).

### 3) **ToString has surprises too**

ToString runs for template interpolation, `String()`, string concatenation, and property keys:

```js
console.log(`${null} ${undefined}`);   // null undefined
console.log(String(-0));               // "0" — sign vanishes in print!
console.log(Object.is(-0, 0));         // false — the values still differ internally
console.log(String(1e21));             // "1e+21" — huge numbers switch to exponential
console.log([1, 2] + "");              // "1,2" — arrays join elements
console.log([null, undefined] + "");   // ","   — null/undefined join as EMPTY strings
console.log({} + "");                  // "[object Object]"
const sym = Symbol("s");
try { `${sym}`; } catch { console.log("symbol interpolation: TypeError"); }
console.log(String(sym));              // Symbol(s) — but explicit String() is allowed
console.log(String(10n));              // "10"
```

- Array-to-string joins *one level deep with commas*, mapping null/undefined to `""` — rarely what you want in output code.
- `-0` prints as `"0"` while remaining distinct inside the engine — logging hides sign bugs (numeric formatting deep dive belongs to the Numbers, Dates, Math, Temporal domain).
- Symbols throw on implicit conversion but pass explicit `String()` — the one deliberate asymmetry in the toolbox.

### 4) **Common confusion**

- "`Number("") === 0` must be a bug" — spec'd behavior: empty string parses to zero. Guard empty inputs *before* converting.
- "`String(obj)` shows me the data" — default objects have no interesting ToString; you get `[object Object]`. Use `JSON.stringify` for inspection (with its own caveats → JSON domain).
- "Arrays stringify like JSON" — no: `[1,"a"] + ""` gives `1,a`, not `[1,"a"]`.

### 5) **Performance note**

Number↔string conversions are common enough that engines fast-path them heavily, but each crossing still allocates or reparses. Hot loops that interleave parsing and math per iteration pay measurable cost — convert once at the edge ([JIT shape stability](<../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md>)).

### 6) **Mentor note**

Don't make juniors memorize full tables — make them memorize *three* rows: `null→0`, `undefined→NaN`, `""→0`. Everything else they can look up; those three explain most real incidents. In review, treat bare arithmetic on possibly-string data as a defect regardless of whether today's test passes.
