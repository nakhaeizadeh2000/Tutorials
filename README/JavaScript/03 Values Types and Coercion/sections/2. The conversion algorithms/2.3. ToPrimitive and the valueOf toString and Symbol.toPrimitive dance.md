## 2.3. ToPrimitive and the valueOf/toString/Symbol.toPrimitive dance

### 1) **Objects convert via a hint-driven method search**

**Definition** — ToPrimitive is the gate every object passes through when a context demands a primitive (arithmetic, comparison, concatenation, template strings, property keys). It takes a **hint**: `"number"` (arithmetic, comparisons, unary `+`), `"string"` (`String()`, template literals, property keys), or `"default"` (loose equality and the `+` operator). For ordinary objects:

- hint `"number"` → try `valueOf()`, then `toString()`
- hint `"string"` → try `toString()`, then `valueOf()`
- hint `"default"` → same order as `"number"` for ordinary objects
- The first call returning a *primitive* wins; if neither does, TypeError.

```js
const both = {
  valueOf()  { return 10; },
  toString() { return "ten"; },
};
console.log(both * 2);      // 20    — number hint: valueOf first
console.log(`${both}`);     // ten   — string hint: toString first
console.log(both + "");     // "10"  — DEFAULT hint: valueOf STILL first!
```

### 2) **The default-hint surprise: `+ ""` is not `String()`**

That last line breaks a widespread assumption. Concatenating with `""` uses ToPrimitive's *default* hint, so `valueOf` runs before `toString` even though the final result becomes a string:

```js
console.log(String(both));   // "ten" — explicit String() really uses the string hint
console.log(`${both}`);      // "ten" — templates too
console.log(both + "");      // "10"  — + uses default hint → valueOf wins
```

- Practical rule: to stringify, use `String(x)`/templates; don't rely on `x + ""` unless you know x's conversion methods.
- `Date` is the built-in that exploits this hook: its `Symbol.toPrimitive` treats `"default"` as `"string"`, which is why dates concatenate as text but subtract as numbers:

```js
const d = new Date(0);
console.log(typeof (d - d));   // number — numeric hint → milliseconds
console.log(typeof (d + ""));  // string — default hint → date string
```

### 3) **`Symbol.toPrimitive` overrides everything**

A `Symbol.toPrimitive` method replaces the whole search — it receives the hint and must return a primitive:

```js
const money = {
  cents: 1999,
  [Symbol.toPrimitive](hint) {
    return hint === "string" ? "$19.99" : this.cents / 100;
  },
};
console.log(money * 2);        // 39.98 — number hint
console.log(`${money}`);       // $19.99 — string hint
console.log(money + 0);        // 19.99 — default hint
```

- This hook is how well-behaved domain objects participate in coercion without exposing `valueOf`'s number-only bias. Protocol/metaprogramming details → Metaprogramming domain (forward reference).

### 4) **Why `[] + {}` works — narrated**

```js
// [] + {}
// 1. ToPrimitive([], default): [].valueOf() → itself (not primitive)
//    → [].toString() → join(",") of [] → ""
// 2. ToPrimitive({}, default): {}.valueOf() → itself → {}.toString() → "[object Object]"
// 3. + overload rule: left operand "" is a string → concatenate
console.log([] + {});          // "[object Object]"
console.log([1,2] + [3]);      // "1,23"  — "1,2" + "3"
console.log([] + []);          // ""      — two empty joins
```

- No mystery once narrated: arrays stringify by joining; plain objects always say `[object Object]`; `+` concatenates when either side ended up a string ([overload detail](<../../../02 Language Basics/sections/3. Operators/3.1. Arithmetic operators precedence associativity and coercion side effects.md>)).
- Objects with `null` prototype have no `valueOf`/`toString` at all — coercing them throws `TypeError: Cannot convert object to primitive value`.

### 5) **Common confusion**

- "`valueOf` is for math, `toString` is for display" — right idea, but remember the default-hint order means `+` prefers `valueOf` even in concatenation.
- "`String(obj)` calls obj.toString()" — it goes through ToPrimitive(string hint), which tries `Symbol.toPrimitive` first, then `toString`, then `valueOf`.
- Returning an *object* from these methods doesn't throw immediately — the algorithm just moves on to the next method (or throws only when nothing primitive emerged).
- `Symbol.toStringTag` can change what plain objects report (`[object MyType]`) — cosmetic tagging, not conversion control.

### 6) **Performance note**

Every object→primitive crossing walks a method chain (possibly user code). Hot numeric code should hold primitives, not wrappers-with-valueOf — engines can't inline through arbitrary user hooks as cheaply. Profile before assuming it matters ([measure-don't-guess](<../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md>)).

### 7) **Mentor note**

Have mid-level devs narrate `[] + {}` and `[1,2] + [3]` cold; seniors should also predict `both + ""` from section 2 without running it — the default-hint ordering separates algorithm-knowers from party-trick-knowers. When reviewing classes you own: implement `Symbol.toPrimitive` deliberately or nothing at all; a stray `valueOf` invites accidental arithmetic.
