## 2.4. ToBoolean: the complete falsy list

### 1) **Eight falsy values, nothing else**

**Definition** — ToBoolean is the only conversion with no object involvement and no failure modes: it answers "would `if (x)` take the branch?" The answer is `false` for exactly these eight values:

| # | Value | Notes |
|---|-------|-------|
| 1 | `false` | |
| 2 | `0` | includes `-0` (same numeric zero) |
| 3 | `-0` | distinct value, same truthiness |
| 4 | `0n` | BigInt zero — but any *nonzero* bigint is truthy |
| 5 | `""` | empty string only |
| 6 | `null` | |
| 7 | `undefined` | |
| 8 | `NaN` | |

```js
const falsy = [false, 0, -0, 0n, "", null, undefined, NaN];
console.log(falsy.map(v => Boolean(v)));   // [false × 8]

// Everything else is truthy — including these recurring surprises:
console.log(!!"0", !!"false", !!" ");      // true true true — ANY non-empty string
console.log(!![], !!{}, !!new Date());     // true true true — ALL objects, even empty
```

- No coercion happens *within* ToBoolean: no trimming (`" "` is truthy), no parsing ("0" isn't a number here), no emptiness checks on arrays/objects.
- Missing values from APIs arrive as `undefined`/`null` → falsy; that's why truthiness guards work for them — until a legitimate `0` or `""` walks in ([pitfall](<../7. Common pitfalls to production bugs/7.1. Real production bugs caused by coercion.md>)).

### 2) **Boolean contexts never coerce objects**

Every object is truthy — always. Arrays, empty or not; dates; regexes; class instances:

```js
if (new Date(0)) console.log("dates are objects → truthy");
console.log(Boolean([]), Boolean({}), Boolean(/x/));   // true true true
// Checking "is this array non-empty?" needs .length:
const items = [];
if (items) console.log("runs! array EXISTS");          // not what was meant
if (items.length > 0) console.log("actually has items");
```

- One browser-legacy exception exists: `document.all` is an object that behaves as falsy (special-cased in engines for ancient IE-detection code). It's the *only* such value ever shipped; don't rely on the mechanism.
- Truthiness drives every boolean context: `if`, loop conditions, ternary condition, `!`, and which operand `&&`/`||` short-circuit to ([operator behavior](<../../../02 Language Basics/sections/3. Operators/3.3. Logical operators short circuit nullish and compound assignment.md>)).

### 3) **Loose equality does NOT use ToBoolean**

The most common misread of `==`: it never asks "are these both truthy?" — booleans convert to *numbers* first ([algorithm](<../3. Coercion at work/3.1. Loose equality the abstract equality algorithm walkthrough.md>)):

```js
console.log("0" == false);    // true — false→0, then "0"→0
console.log("" == false);     // true — same chain via ""
console.log([2] == true);     // false! true→1, "[2]"→NaN — NOT a truthiness check
console.log("0" == 0);        // true — the real rule: string vs number
if ("0") console.log("but if(\"0\") still runs");   // truthiness ≠ loose equality
```

- Consequence: `x == true` is not "is x truthy" — drop it; write `if (x)` for truthiness or an explicit comparison for logic.

### 4) **Common confusion**

- `"false"` is truthy (non-empty string!) — bites people parsing query params into booleans.
- Empty array/object truthiness: `[]` is truthy while `[] == false` is also true — different algorithms (ToBoolean says yes; loose equality converts to `""`→`0`). Both correct, neither contradicts the other.
- `Boolean(x)` vs `!!x`: identical results; `!!` wins for inline idiom, `Boolean(...)` reads better in `.map(Boolean)` pipelines.

### 5) **Performance note**

ToBoolean is free — a type/value test, no allocation. There is zero performance reason to avoid truthiness checks; choose explicit comparisons purely for *meaning* (`count !== 0` documents intent better than `count` when count could be `-1`).

### 6) **Mentor note**

Drill juniors on the eight-item list until they can recite it; then immediately teach the two follow-up reflexes ("any object is truthy", "`==` doesn't ask ToBoolean"). Review red flags: `if (arr)` for emptiness, `x == true/false`, and boolean-from-string parsing without an allowlist.
