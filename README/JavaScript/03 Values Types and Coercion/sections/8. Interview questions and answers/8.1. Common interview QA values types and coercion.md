## 8.1. Common interview Q&A: values, types, and coercion

### 1) **Q&A**

1. **Q: Why does `typeof null` return `"object"`, and how do you check for null?**
   **A:** Frozen 1995 implementation artifact — the type tag for null collided with objects; web compatibility prevents fixing it. Check with `x === null`. Bonus signal: mention `typeof` never throws, even on undeclared identifiers.

2. **Q: Explain `[] == ![]` — why is it `true`?**
   **A:** Narrate the chain: unary `![]` → ToBoolean says objects are truthy → `false`; now `[] == false`; boolean converts to number → `[] == 0`; object converts to primitive → `"" == 0`; string converts to number → `0 == 0` → true. Mechanism-narration is the graded skill, not the answer.

3. **Q: What is `[1,2] + [3]` and why?**
   **A:** `"1,23"` — both arrays convert via toString (join with commas) to "1,2" and "3"; `+` concatenates because a side ended up a string.

4. **Q: `Number(null)` vs `Number(undefined)`?**
   **A:** `0` vs `NaN` — deliberate asymmetry: null means "deliberately empty" (counts as zero), undefined means "missing" (poisons math). Same asymmetry flows through operators: `null + 1 === 1`, `undefined + 1 === NaN`.

5. **Q: Name the falsy values.**
   **A:** Exactly eight: `false`, `0`, `-0`, `0n`, `""`, `null`, `undefined`, `NaN`. Everything else — including `"0"`, `"false"`, `[]`, `{}` — is truthy. Follow-up probe: why does `if ([])` run but `[] == false` is also true? Different algorithms (ToBoolean vs loose equality); neither contradicts the other.

6. **Q: `Object.is` vs `===`?**
   **A:** Identical except exactly two cases: `Object.is(NaN, NaN)` is true, and `Object.is(0, -0)` is false. Use for NaN/sign-sensitive checks; otherwise `===`.

7. **Q: Why can `(2**53 + 1) === (2**53)` be true? What's the fix?**
   **A:** Numbers are IEEE-754 doubles; integers above `Number.MAX_SAFE_INTEGER` (2^53 − 1) lose precision and distinct integers collapse. Fix: BigInt or string IDs end-to-end (`9007199254740992n !== 9007199254740993n`).

8. **Q: What does `new Boolean(false)` evaluate to in an if-statement?**
   **A:** It's truthy — a wrapper *object*, and all objects are truthy. This is why explicit wrapper constructors are banned; `Boolean(false)` (function form) returns the primitive false.

9. **Q: Why does `"" + Symbol("s")` throw while `` `${Symbol("s")}` `` also throws but `String(Symbol("s"))` works?**
   **A:** Symbols deliberately refuse implicit conversion to strings (TypeError on ToString paths); only explicit `String()`/`.description` access them — so key typos fail loudly instead of silently corrupting data.

10. **Q: Predict `parseInt("08")` and `parseInt("42px")`. Any pitfalls left?**
    **A:** `8` and `42` — modern engines have no octal legacy; prefix scanning stops at junk. Remaining pitfalls: omitting the radix (reader ambiguity), and prefix scanning turning corrupted data into plausible numbers where whole-string `Number()` would have failed.

11. **Q: Is `{} + {}` always `"[object Object][object Object]"`?**
    **A:** Not at statement position! Leading `{}` parses as an empty block, leaving `+{}` → `NaN`. As expressions (`x = {} + {}`) you get the concatenated string. Position-dependent parsing — a favorite senior-level gotcha.

12. **Q: When do relational comparisons go lexical instead of numeric?**
    **A:** `<`/`>` coerce both sides via ToPrimitive(number hint), but if BOTH results are strings they compare character-by-character — so `"10" < "9"` is true. Mixed types take the numeric path.

### 2) **Grading guidance (mentor note)**

- Q1–Q5 separate practiced developers from framework tourists; expect *mechanism* narration on Q2/Q5, not memorized outcomes.
- Mid-level signal: unprompted mention of `eqeqeq` policy after Q2, and `??` after falsy-list discussions.
- Senior signal: Q7 tied to real-world ID incidents, Q11 answered without hesitation, Q10 reframed as "which contract do I actually need".
- Red flags: "`==` is random", "JavaScript has no types", claiming `typeof` throws on undeclared variables.
