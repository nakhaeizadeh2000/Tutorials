## 1.2. Immutability, identity, and copying: how primitives and objects differ

### 1) **Primitives are immutable**

**Definition** — a primitive value can never be modified in place. String methods *return new strings*; "writing" to an index or property of one silently does nothing (strict mode: throws):

```js
let s = "abc";
s[0] = "z";                    // sloppy mode: ignored; strict: TypeError
console.log(s);                // abc — unchanged
console.log(s.toUpperCase());  // ABC — a NEW string was returned
console.log(s);                // abc — original untouched

const n = 10;
console.log(n + 1, n);         // 11 10 — arithmetic produces values, never mutates
```

- Numbers, bigints, booleans have no mutable state to even talk about — the immutability rule matters most for strings, where C/Java-trained instincts expect in-place indexing.
- Immutability is why string-building in a loop with `+=` allocates repeatedly (usually fine; engines optimize — [performance note](#5-performance-note)).

### 2) **Variables hold references to objects, copies of primitives**

Assignment copies the primitive value but only the object reference:

```js
// Primitives: independent after assignment
let a = 10;
const b = a;
a = 20;
console.log(b);                       // 10

// Objects: two names, ONE object (aliasing)
const config = { retries: 3 };
const ref = config;
ref.retries = 99;
console.log(config.retries);          // 99 — the same object mutated

// Function arguments behave identically (pass-by-value OF the reference):
function bump(list) { list.push(1); }
const nums = [];
bump(nums);
console.log(nums.length);             // 1 — caller sees it
```

- The aliasing model explains most "who changed my object?" bugs. Reassignment inside a function (`list = []`) affects only the local binding; mutation (`list.length = 0`) affects every holder of the reference.
- Shallow vs deep copy strategy (`{...obj}`, `structuredClone`) → Objects in Depth domain — here remember only that spread copies *one level*.

### 3) **Equality follows family lines**

Primitives compare by value; objects compare by reference identity:

```js
console.log(5 === 5, "x" === "x");    // true true — value identity
console.log({} === {}, [] === []);    // false false — distinct objects
const arr = [];
console.log(arr === arr);             // true — SAME reference

// Edge cases handled by Object.is (SameValue):
console.log(NaN === NaN);             // false — IEEE 754 inheritance
console.log(Object.is(NaN, NaN));     // true
console.log(0 === -0);                // true — sign collapses under ===
console.log(Object.is(0, -0));        // false — distinguishes signs
```

- `===` uses strict equality for primitives and reference identity for objects; `Object.is` differs exactly twice: NaN pairs as equal, signed zeros pair as different ([operator-level comparison](<../../../02 Language Basics/sections/3. Operators/3.2. Equality loose vs strict and when either is safe.md>)).

### 4) **Common confusion**

- "Strings are arrays of chars" — strings are immutable primitives with index access; `Array` methods don't exist on them and writes vanish as shown above.
- "`const` makes objects immutable" — `const` freezes the *binding*, not the object: `const x = {}; x.y = 1` works. Actual immutability needs `Object.freeze` (shallow!) or disciplined design.
- "Pass-by-reference!" — JS is always pass-by-value; for objects the value IS a reference. The distinction matters when you reassign parameters.
- Copying a primitive-typed field then mutating the source proves nothing about deep copy — nested objects stay aliased until explicitly cloned.

### 5) **Performance note**

Immutable primitives let engines share/copy cheaply (small strings and integers are often pointer-copies or inline values). Object identity semantics mean defensive copies (`{...obj}`) cost real allocations per call — copy at trust boundaries, not habitually. As always: measure before micro-optimizing ([JIT mindset](<../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md>)).

### 6) **Mentor note**

Teach juniors one diagram early: *boxes with arrows*. Primitive boxes get duplicated on assignment; object boxes get new arrows pointed at them. Most aliasing bugs disappear once people stop saying "the variable contains the object". In review: flag any function that both mutates its argument AND returns something — ambiguous contracts breed aliasing surprises.
