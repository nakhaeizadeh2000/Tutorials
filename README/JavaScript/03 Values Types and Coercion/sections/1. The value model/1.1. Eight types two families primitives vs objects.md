## 1.1. Eight types, two families: primitives vs objects

### 1) **Seven primitive kinds plus object**

**Definition** — ECMA-262 defines exactly eight language types. Seven are **primitives**: `undefined`, `null`, boolean, string, symbol, number, bigint. The eighth is **object** — and *everything* that isn't a primitive is one: arrays, dates, regexes, maps, functions, class instances, plain `{}`.

```js
const kinds = [undefined, null, true, "s", Symbol("k"), 42, 10n];
for (const v of kinds) console.log(typeof v);
// undefined object boolean string symbol number bigint
// (null → "object" is the frozen bug — see the table below)

console.log(typeof [], typeof new Date(), typeof /r/, typeof (() => {}));
// object object object function — all objects; callables get their own tag
```

- There is no "array type", no "date type", no "class type" at the language level: `Array.isArray` and friends work because of object internals ([brand checks](<../../../02 Language Basics/sections/3. Operators/3.5. Inspection operators typeof instanceof in delete void spread rest.md>)), not because arrays are a primitive kind.
- The full `typeof` result table with its two quirks (`null → "object"`, functions → `"function"`) lives in the operators domain — this leaf uses it only as the tag reader.

### 2) **`typeof` reads the tag, imperfectly**

The operator answers "which broad category", not "which exact type":

| Value | `typeof` | Note |
|-------|----------|------|
| `undefined` | `"undefined"` | |
| `null` | `"object"` | 1995 artifact; check with `x === null` |
| boolean / number / string | `"boolean"` / `"number"` / `"string"` | |
| symbol / bigint | `"symbol"` / `"bigint"` | added with ES2015 / ES2020 |
| function | `"function"` | callable objects get special treatment |
| every other object | `"object"` | arrays, dates, plain objects, wrappers |

- `typeof x` never throws — even on undeclared identifiers — which makes it safe for feature detection where property access would crash.

### 3) **Two families behave differently in three ways**

Everything that follows in this domain hangs on the family split:

1. **Copying** — assigning a primitive copies the value; assigning an object copies the reference.
2. **Mutation** — primitives can't be mutated at all ("changing" a string produces a new string); objects mutate freely.
3. **Identity** — two equal-looking primitives *are* equal (`1 === 1`); two equal-looking objects usually aren't (`{} !== {}`).

```js
// Copying:
let a = 10;
let b = a; b = 20;
console.log(a, b);              // 10 20 — independent

const objA = { n: 10 };
const ref = objA; ref.n = 99;
console.log(objA.n);            // 99 — same object behind both names

// Identity:
console.log("hi" === "hi");     // true — value identity for primitives
console.log({} === {});         // false — reference identity for objects
```

- Full treatment of copying/mutation/identity consequences → [1.2](<./1.2. Immutability identity and copying how primitives and objects differ.md>).

### 4) **Common confusion**

- "`typeof null === "object"` means null IS an object" — no; it's a tagged-type bug from the first engine, kept forever because early web pages depended on it ([history](<../../../01 Fundamentals and Mental Model/sections/1. What JavaScript is/1.1. From LiveScript to ECMAScript history editions and legacy quirks.md>)). Detect null with `x === null`.
- "Strings should behave like objects since they have methods" — they get method access via temporary boxing ([4.1](<../4. Boxing and wrapper objects/4.1. Wrapper objects vs primitives boxing demystified.md>)); the value itself stays a primitive.
- "JavaScript has no types" — it has no *static* types on variables; values are always exactly one of eight well-defined types ([dynamic typing](<../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.2. Dynamic typing late binding and their consequences.md>)).

### 5) **Mentor note**

Screening question: "name the JS types". Weak candidates say string/number/array/object. Strong ones give the seven-plus-object split unprompted, and excellent ones immediately flag the family behavioral differences — because those three differences explain aliasing bugs, equality surprises, *and* why coercion exists (operators need same-family operands). Teach the split before teaching any conversion table.
