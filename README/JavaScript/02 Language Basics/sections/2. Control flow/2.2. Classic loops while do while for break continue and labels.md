## 2.2. Classic loops: while, do-while, for (break, continue, labels)

### 1) **for when the count is known**

**Definition** — the C-style `for` bundles init/test/update; use it when iterations are counted or index-driven.

```js
// Counted iteration with correct bounds: [0, len)
const names = ["ada", "grace", "linus"];
for (let i = 0; i < names.length; i++) {
  console.log(i, names[i]);
}
// Stepping and index math live naturally here:
for (let i = names.length - 1; i >= 0; i -= 2) {
  console.log("reverse step:", names[i]);
}
```

- Off-by-one discipline: decide inclusivity *before* writing (`<` + `length` is the default safe shape).
- `let i` scopes the counter to the loop — `var i` leaks it into function scope and breaks closures-per-iteration (full story: [Variables §3.2](<../../../04 Variables Scope and Closures/sections/3. Closures/3.2. Loops and closures var let and per iteration capture.md>)).

### 2) **while / do-while when only the condition matters**

```js
// while: zero-or-more executions
function isReady() { return true; }

let retries = 0;
while (!isReady() && retries < 3) {
  retries++; // condition checked first — may run zero times
}
console.log(retries); // 0

// do-while: one-or-more — retry prompts, polling menus:
let attempt = { ok: false };
do {
  attempt = tryConnect(); // body ALWAYS runs before the first test
} while (!attempt.ok);

function tryConnect() { return { ok: true }; }
console.log("connected");
```

- Infinite `while (true)` is legitimate for servers/event pumps but must contain a real exit path (`break`, throw, shutdown flag).

### 3) **break, continue, and labeled statements**

```js
// break exits the loop; continue skips to next round:
for (const n of [1, -2, 3]) {
  if (n < 0) continue; // skip negatives
  if (n > 2) break;    // stop entirely at 3
  console.log(n);      // prints 1 only
}

// Labels address OUTER loops from inner control flow:
outer:
for (const row of [[0, 9], [4, 4], [7, 8]]) {
  for (const cell of row) {
    if (cell === 9) continue outer; // abandon THIS row mid-way
    if (cell === 8) break outer;    // abandon ALL rows
    console.log(cell);
  }
}
// Trace: row1 logs 0, hits 9 → next row.
//        row2 logs 4, 4.
//        row3 logs 7, hits 8 → everything stops.
// Output: 0, 4, 4, 7
```

- Labels are rare and jarring to readers; more than one nested level usually means "extract a function with early `return`" instead.

### 4) **Common confusion**

- `do { } while (cond)` executes body before first test — forgetting this causes double-processing bugs.
- `continue` inside `while` still evaluates the update-less condition — manual-update loops risk skipping their increment.
- Modifying an array while looping over it by index shifts elements under your feet (splice patterns need reverse iteration).

### 5) **Performance note**

For arrays, prefer `for-of`/array methods for readability — JITs optimize them comparably in warm code ([fundamentals: measure](<../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md>)). Reach for classic `for` when you need the index anyway or must skip elements cheaply without allocating callbacks.

### 6) **Mentor note**

Interview probe: "loop over an array removing matching items" — candidates who splice forward corrupt the traversal; those who filter-then-reassign or iterate backwards demonstrate the mental model that matters more than syntax.
