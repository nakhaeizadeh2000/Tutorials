## 2.3. for-of vs for-in (iteration semantics and traps)

### 1) **for-of iterates values of iterables**

**Definition** — `for...of` consumes the *iteration protocol*: anything with `Symbol.iterator` (arrays, strings, `Map`, `Set`, `TypedArray`, generators, `NodeList`).

```js
const langs = ["js", "ts", "wasm"];
for (const lang of langs) console.log(lang);        // js ts wasm
for (const ch of "ab→") console.log(ch);            // a b →  (code points, not units!)
for (const [key, value] of new Map([["a", 1]])) {   // destructures entries
  console.log(key, value);                          // a 1
}
```

- Strings iterate by Unicode code points — `for-of` handles emoji/astral chars correctly where index loops don't.
- Works on any iterable, including lazy/infinite ones from generators (protocol details → Iterables domain).

### 2) **for-in iterates string keys of enumerable properties — including inherited ones**

```js
const base = { inherited: true };
const obj = Object.create(base);
obj.a = 1;
obj.b = 2;

for (const key in obj) {
  console.log(key, obj[key]);
}
// a 1
// b 2
// inherited true   ← prototype property walked too!
```

- Designed for object inspection; on arrays it yields string indices (`"0"`, `"1"`) in a spec-defined but surprising order (integer-like keys ascending first), and walks prototypes — three ways to be wrong at once.
- **Never use for-in on arrays**; lint rule `no-for-in-array` / guard with `Object.hasOwn(obj, key)` where for-in is truly required.

### 3) **Guard rails replace raw for-in**

```js
const settings = { theme: "dark", retries: 3 };

for (const key of Object.keys(settings)) console.log(key);            // own keys only
for (const value of Object.values(settings)) console.log(value);      // dark 3
for (const [k, v] of Object.entries(settings)) console.log(k, v);     // pairs
```

- Own-enumerable-only by construction — no `hasOwnProperty` dance needed.
- Non-enumerables (like built-in methods) stay invisible; that's usually exactly what you want.

### 4) **Common confusion**

- "for-of works on plain objects" — no: `{...}` isn't iterable; you'll get `TypeError: obj is not iterable`. That's the protocol telling you objects aren't sequences.
- "for-in gives array elements" — it gives *keys as strings*; `"0" + 1 === "01"` bugs follow.
- Order guarantees differ: for-of follows iteration definition; for-in's non-integer-key ordering is insertion-based per spec but historically engine-dependent folklore — another reason to prefer explicit APIs.

### 5) **Performance note**

for-of over arrays compiles comparably to indexed loops in hot code (engines special-case it); callback methods (`forEach`) allocate a closure per call — measurable only in tight loops over huge data. Choose by semantics first ([measure, don't guess](<../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md>)).

### 6) **Mentor note**

The fastest interview filter for JS experience: "what does for-in do on an array?" Correct answers mention string keys + prototype walking; great ones also say "and I'd never use it there". Teach juniors one rule — *of for data, keys/values/entries for objects* — before explaining why.
