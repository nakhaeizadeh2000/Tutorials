## 4.1. Basics checklist (correctness traps mentors screen for)

### 1) **The checklist**

1. **ASI hazard lines** (leading `(` `[` `` ` `` `+` `-` `/`, `return⏎value`) — solved permanently by formatter policy, not vigilance ([1.1](<../1. Program structure and syntax/1.1. Statements expressions and semicolons ASI reality.md>)).
2. **for-in never touches arrays** (string keys + prototype walk) — `for-of` for data, `Object.keys/values/entries` for objects ([2.3](<../2. Control flow/2.3. for-of vs for-in iteration semantics and traps.md>)).
3. **switch cases need break or a comment** — accidental fall-through is silent and always in production ([2.1](<../2. Control flow/2.1. Conditionals if switch ternary and fallthrough traps.md>)).
4. **`+` concatenates when strings appear**; every other arithmetic op coerces to numbers — convert at boundaries, compute inside ([3.1](<../3. Operators/3.1. Arithmetic operators precedence associativity and coercion side effects.md>)).
5. **Ban `==` except `x == null`** — enforced by `eqeqeq`; know `NaN !== NaN` and use `Number.isNaN`/`Object.is` deliberately ([3.2](<../3. Operators/3.2. Equality loose vs strict and when either is safe.md>)).
6. **Defaults for optional values use `??`, not `||`** — `0`, `""`, `false` are valid values that `||` destroys ([3.3](<../3. Operators/3.3. Logical operators short circuit nullish and compound assignment.md>)).
7. **`?.` guards exactly two values** (`null`/`undefined`) — chains of five are design smells, not safety ([3.4](<../3. Operators/3.4. Property access dot brackets and optional chaining.md>)).
8. **Spread copies one level** — nested mutation still aliases; deep copies need explicit strategy ([3.5](<../3. Operators/3.5. Inspection operators typeof instanceof in delete void spread rest.md>)).
9. **`typeof null === "object"` forever** — check null before typeof; remember `Array.isArray` beats `instanceof Array` across realms.
10. **`delete arr[i]` makes holes** (length unchanged) — removing array elements is `splice`/`filter` territory, not `delete`.

### 2) **How to use this list**

- Junior: items 2, 5, 6 prevent the three most common first-year bugs — internalize before touching frameworks.
- Senior: codify as lint config (`no-for-in-array`, `eqeqeq`, `prefer-nullish-coalescing`, `no-fallthrough`) so the checklist runs itself.
- Mentor: each item maps to a leaf with the full why; use them as review vocabulary ("this looks like checklist item 6").
