## 1.2. Identifiers, keywords, and naming conventions

### 1) **Identifier rules**

**Definition** — identifiers name variables, functions, classes, labels. Rules: start with a letter, `$`, or `_`; continue with those plus digits; Unicode letters are legal (`let café = 1;`); reserved words cannot be used as identifiers.

```js
let _privateThing = 1;
let $element = 2;
let café = 3;          // valid Unicode identifier

// const class = 1;    // SyntaxError — reserved word

const obj = { if: 1, delete: 2 }; // reserved words ARE fine as property names
console.log(obj.if, obj.delete);  // 1 2  — also obj.if works post-ES5
```

- Property-name lenience matters for consuming JSON APIs with awkward keys.

### 2) **Conventions carry meaning**

Not enforced by the language — enforced by teams reading your code:

| Convention | Signals | Example |
|-----------|---------|---------|
| `camelCase` | variables/functions | `retryCount`, `parseConfig` |
| `PascalCase` | classes/constructors/types | `HttpClient`, `OrderItem` |
| `SCREAMING_SNAKE` | module-level constants with fixed values | `MAX_RETRIES` |
| `_prefix` / trailing `_` | intentionally internal/unused | `_cache`, `(err, _res)` |
| verb-first functions, noun-first data | intent | `fetchUser()` vs `userList` |

- Consistency inside a codebase outranks any external style guide.

### 3) **Names are API design**

```js
// Bad: forces readers to reverse-engineer meaning
function proc(d, f) { /* ... */ }

// Good: signature documents itself
function processOrders(orders, { validatePrices } = {}) { /* ... */ }
```

- Renaming exported names later breaks every consumer — cheap to get right now, expensive forever after.
- Boolean names should read as predicates: `isActive`, `hasChildren`, not `activeFlag`.

### 4) **Common confusion**

- `$` has no language meaning — it's just a letter (jQuery/Lodash made it look special).
- Reserved words list includes contextual ones (`async`, `of`, `get`) usable as variable names in some positions — don't try; pick clearer names.
- Unicode identifiers compile fine but break some tooling/pipelines — prefer ASCII in shared code.

### 5) **Mentor note**

In review, flag names that require reading the body to understand ("what does `d` hold?"). Naming quality predicts defect density better than almost any other surface signal — treat naming nitpicks as substantive review, not style policing.
