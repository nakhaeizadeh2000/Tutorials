## 3.1. Arithmetic operators (precedence, associativity, and coercion side effects)

### 1) **Precedence then associativity decide order**

**Definition** — precedence ranks operators; associativity (`left`/`right`) breaks ties within the same rank.

```js
console.log(2 + 3 * 4);      // 14 — * before +
console.log((2 + 3) * 4);    // 20 — parentheses win, always legal, free documentation
console.log(2 ** 3 ** 2);    // 512 — exponent is RIGHT-associative: 2 ** (3 ** 2)
console.log(10 - 4 - 3);     // 3 — subtraction is LEFT-associative: (10 - 4) - 3
```

- Unary operators outrank binary arithmetic: `-2 ** 2` is a SyntaxError in JS (unary minus can't combine with `**` without parens: `(-2) ** 2 === 4`).
- When in doubt about a reader's mental model, add parentheses — zero runtime cost, real clarity gain.

### 2) **Arithmetic coerces operands to numbers**

```js
console.log("3" * "4");   // 12  — both sides ToNumber'd
console.log("3" + "4");   // "34" — + is special: string wins → concatenation
console.log("3" + 4 + 5); // "345"
console.log(1 + 2 + "3"); // "33" — left-to-right: (1+2)=3 then "3"+"3"
console.log(+"42", +" 7 ", +"");  // 42 7 0 — unary plus is explicit ToNumber
console.log(5 - true);    // 4  — boolean coerces to 1
```

- `+` overload rule: if either operand is a string after ToPrimitive, concatenate; otherwise numeric addition. Every other arithmetic operator always goes numeric.
- Full coercion algorithm (ToNumber/ToPrimitive details, object valueOf/toString interplay) lives in the **Values, Types, and Coercion domain** — here, internalize only the practical rule: *arithmetic lies unless inputs are numbers*.

### 3) **NaN poisons, Infinity saturates — and `%` is remainder, not modulo**

```js
console.log(NaN + 1, NaN * 0);        // NaN NaN — any NaN operand infects the result
console.log(1 / 0, -1 / 0, 0 / 0);    // Infinity -Infinity NaN — no exceptions thrown
console.log(0.1 + 0.2);               // 0.30000000000000004 — IEEE-754 doubles, all engines
console.log(-7 % 3, 7 % -3);          // -1 1 — remainder takes the DIVIDEND's sign
// True modulo (result follows divisor):
const mod = (n, m) => ((n % m) + m) % m;
console.log(mod(-7, 3));              // 2
```

- Numeric formatting/precision deep dive (BigInt, Number.EPSILON, decimal strategies) belongs to the Numbers/Dates/Math domain.

### 4) **Common confusion**

- `parseInt("08")` folklore — with radix argument or `Number()` there was never an octal problem in modern JS.
- `"b" + "a" + +"a" + "a"` party tricks — they only demonstrate that `+` coerces; nobody should write such code.
- Integer division truncation doesn't exist: `7 / 2 === 3.5`; truncate explicitly with `Math.trunc` if needed.

### 5) **Performance note**

Numeric ops on actual numbers are JIT-friendly (SMI/double representations). Mixed-type operands force conversion checks per operation — another reason hot loops keep their data uniformly typed ([shape stability](<../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md>)).

### 6) **Mentor note**

Teach juniors one defensive habit early: convert at the boundary (`Number(input)`), compute inside, format at the edge. Most "JavaScript math is broken" complaints are unvalidated string inputs meeting the `+` overload.
