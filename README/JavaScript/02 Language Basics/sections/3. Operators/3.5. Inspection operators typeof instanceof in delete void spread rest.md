## 3.5. Inspection and structural operators: typeof, instanceof, in, delete, void, spread/rest

### 1) **typeof answers a narrow question**

**Definition** — `typeof x` returns one of eight strings describing the value's broad category:

| Operand | Result |
|---------|--------|
| `undefined` | `"undefined"` |
| `null` | **`"object"`** — frozen 1995 bug ([history](<../../../01 Fundamentals and Mental Model/sections/1. What JavaScript is/1.1. From LiveScript to ECMAScript history editions and legacy quirks.md>)) |
| booleans / numbers / strings | `"boolean"` / `"number"` / `"string"` |
| functions | `"function"` (callable objects get special treatment) |
| other objects, arrays, dates… | `"object"` |
| symbols / bigints | `"symbol"` / `"bigint"` |

```js
console.log(typeof undefined, typeof null);        // undefined object
console.log(typeof [], typeof {}, typeof Date);    // object object function
console.log(typeof (() => 1), typeof 10n);         // function bigint
console.log(typeof notDeclaredAtAll);              // "undefined" — safe on undeclared names!
```

- That last line is `typeof`'s unique superpower: it never throws on undeclared identifiers — the only operator that won't.

### 2) **instanceof walks prototypes**

```js
class Err {}
const e = new Err();
console.log(e instanceof Err);       // true
console.log([] instanceof Array);    // true
console.log("x" instanceof String);  // false — primitives aren't wrapper objects
const s = new String("x");
console.log(s instanceof String, typeof s); // true object — boxed wrapper (avoid)

// Cross-realm trap:
console.log({} instanceof Object);   // true here...
// ...but an object created in another iframe/vm has a different Object.prototype
// → instanceof fails across realms. Use Array.isArray for arrays:
console.log(Array.isArray([]));      // true — realm-safe
```

- Use for class hierarchies you own; use `Array.isArray`, duck typing, or brand checks elsewhere.

### 3) **in tests keys; delete mutates; void forces undefined**

```js
const obj = { a: 1, b: 2 };
console.log("a" in obj, "toString" in obj); // true true — inherited keys count!
console.log(Object.hasOwn(obj, "toString")); // false — own-keys check instead

delete obj.b;
console.log(obj.b, "b" in obj); // undefined false — property removed

const arr = [1, 2, 3];
delete arr[1];                  // removes the SLOT, not the position
console.log(arr.length, arr[1], 1 in arr); // 3 undefined false — a "hole"

console.log(void 0);            // undefined — historical "safe undefined" idiom
```

### 4) **Spread and rest: same syntax, opposite jobs**

```js
// Spread EXPANDS (calls, literals):
const base = { a: 1, nested: { x: 1 } };
const copy = { ...base, b: 2 };         // shallow copy + extension
console.log(copy.nested === base.nested); // true — only ONE level copied!

const merged = [...[1, 2], ...[3]];     // [1,2,3]
Math.max(...[5, 9, 2]);                 // 9

// REST COLLECTS (destructuring, params):
function sum(first, ...others) { return first + others.reduce((s, n) => s + n, 0); }
console.log(sum(1, 2, 3));              // 6

const { a, ...flags } = { a: 1, debug: true, trace: false };
console.log(flags);                     // { debug: true, trace: false }
```

- Shallow-copy semantics bite nested structures — deep needs `structuredClone` or explicit traversal (full copy-strategy treatment → Objects in Depth domain).

### 5) **Common confusion**

- `typeof` cannot distinguish arrays/plain objects/nulls — combine with `Array.isArray`.
- `in` ≠ truthiness: `"key" in obj` is about *existence*, even if the value is `undefined`.
- `void` in `href="javascript:void(0)"` is legacy folklore; modern code almost never needs `void`.

### 6) **Mentor note**

These operators dominate junior interview rejections because they look trivial. Drill the three tables (typeof results, instanceof limits, spread-vs-rest) until answers are reflexive — then teach when *not* to type-check at all (validate data contracts instead).
