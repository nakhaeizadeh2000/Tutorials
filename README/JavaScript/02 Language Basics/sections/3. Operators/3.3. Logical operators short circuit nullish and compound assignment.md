## 3.3. Logical operators: short-circuit, nullish, compound assignment

### 1) **&& and || return operands, not booleans**

**Definition** — logical operators evaluate left-to-right and *short-circuit*: `&&` stops at the first falsy operand; `||` stops at the first truthy one. The result is the operand itself.

```js
console.log(0 || "fallback");        // "fallback"
console.log("first" && "second");    // "second" — both had to be truthy
console.log(null && anything());     // null — right side never evaluated!

function anything() { throw new Error("never runs"); }
```

- That last property makes them control-flow tools, not just boolean math:

```js
const user = null;
user && console.log("runs only if user exists");   // guard
const name = user?.name ?? "anonymous";            // modern default (see ??)
console.log(name);

// Classic pre-optional-chaining guard:
if (user && user.profile && user.profile.email) { /* ... */ }
```

### 2) **?? treats only null/undefined as missing**

The `||` default has a famous bug class: it discards valid falsy values.

```js
// BAD — 0 is a legitimate volume level:
const volume1 = 0 || 50;
console.log(volume1); // 50 — silently replaced a valid zero!

// GOOD — nullish coalescing:
const volume2 = 0 ?? 50;
console.log(volume2); // 0

const text = "" ?? "placeholder";
console.log(text);    // "" — empty string survives too

const missing = null ?? 50;
console.log(missing); // 50
```

- Rule: **defaults for optional values → `??`; feature-detection/guard chains → `&&`/`?.`**.
- Mixing `??` directly with `&&`/`||` requires parentheses (SyntaxError otherwise) — deliberate friction against ambiguous intent: `(a ?? b) || c`.

### 3) **Compound logical assignment (`||=`, `&&=`, `??=`)**

```js
const config = { retries: 0, label: undefined };

config.retries ||= 5;   // assign if current value is FALSY   → stays 0? No:
console.log(config.retries); // 5 ← falsy 0 was replaced! know which op checks what

config.label ??= "default"; // assign if null/undefined ONLY
console.log(config.label);   // "default"

config.retries &&= config.retries + 1; // assign if currently TRUTHY
console.log(config.retries); // 6
```

| Operator | Assigns when current value is… |
|----------|-------------------------------|
| `\|\|=` | falsy |
| `&&=` | truthy |
| `??=` | `null` or `undefined` |

### 4) **Common confusion**

- "`a || b` returns true/false" — no; it returns an operand. `console.log(7 || 9)` prints 7.
- Short-circuiting as side-effect hiding: `setup() && start()` reads like boolean logic but is conditional execution — reviewers may miss it; prefer explicit `if` for actions.
- `??=` vs `||=` on numeric configs is exactly where the two differ (`0`, `""`, `false` survive `??=`, die under `||=`).

### 5) **Mentor note**

Code-review rule of thumb: any `||` whose left side can legitimately be `0`/`""`/`false` gets challenged in review — usually should be `??`. Teach the table above as flashcards; the three assignment operators are trivial once the emptiness definitions are distinct.
