## 3.4. Property access: dot, brackets, and optional chaining

### 1) **Dot for identifier-safe names, brackets for everything else**

**Definition** — `obj.key` requires `key` to be a valid identifier; `obj["key"]` accepts any string expression — computed at runtime.

```js
const user = { name: "Ada", "home city": "London", 42: "answer" };

console.log(user.name);        // Ada — the common case
// console.log(user.home city); // SyntaxError — not an identifier
console.log(user["home city"]); // London
console.log(user[42]);          // "answer" — numeric keys stringify

const field = "name";
console.log(user[field]);       // Ada — dynamic access; user.field would look up literally
```

- Bracket content is a *string coercion boundary*: numbers become strings (`arr[0]` is really `arr["0"]`) — one more reason object keys are always strings/symbols.

### 2) **?. short-circuits the whole chain on null/undefined**

```js
const profile = {
  address: { street: "Main St" },
  greet() { return "hi"; },
};

console.log(profile.address?.street);   // Main St
console.log(profile.phone?.street);     // undefined — no throw
console.log(profile.greet?.());         // hi — guarded call
console.log(profile.bye?.());           // undefined — method missing, no throw

const list = [[10, 20]];
console.log(list?.[0]?.[1]);            // 20 — guarded index access
```

- Short-circuiting is *transitive*: once `?.` yields `undefined`, the rest of the chain (including further accesses/calls) is skipped.
- Three forms: `a?.b`, `a?.[expr]`, `a?.fn()` — plus assignment targets since ES2021: `obj?.prop = value` only writes when `obj` exists.

### 3) **?. is null-guarding, not error-proofing**

```js
const broken = { greet: "not a function" };

try {
  broken.greet?.();   // property exists → call proceeds → TypeError anyway
} catch (e) {
  console.log(e.name); // TypeError
}

try {
  profile.address.x.y.z; // ?. absent here — deep throw propagates normally
} catch (e) {
  console.log(e.name); // TypeError
}
```

- It guards exactly two values: `null` and `undefined`. It does not catch wrong types, earlier throws in the same expression, or validate shapes — that's schema validation's job (boundary discipline from [fundamentals](<../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.2. Dynamic typing late binding and their consequences.md>)).

### 4) **Common confusion**

- "`a?.b.c` protects everything" — it protects up to `.b`; if `b` exists but lacks `c`, you still throw.
- Overuse as band-aids: chains of five `?.` usually mean your data contract is undefined — fix the contract or validate at entry, don't sprinkle guards deeper every sprint.
- `delete obj?.prop` and other operator interactions follow short-circuit rules — evaluate carefully before relying on them.

### 5) **Performance note**

Each `?.` adds a null-check branch; engines handle this well, so readability wins over micro-costs. The real cost is architectural: optional-everything hides missing invariants until runtime — measure *bugs*, not nanoseconds.

### 6) **Mentor note**

Review heuristic: count `?.` per expression. Zero on untrusted input = suspicious; three-plus = design smell asking for validation or defaults at the boundary. One to two with clear ownership = idiomatic modern JS.
