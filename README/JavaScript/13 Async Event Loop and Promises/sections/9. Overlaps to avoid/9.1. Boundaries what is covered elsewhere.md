## 9.1. Boundaries what is covered elsewhere

### 1) **Generators and async generators / async iteration — [Iterables Generators and Async Iteration](<../../../10 Iterables Generators and Async Iteration/README.md>)**

This domain treats promises as values and the loop that runs their jobs; generator-based iteration (including `async function*`, `yield*`, `for await...of` closing) lives in Iterables §3–§4. That domain owns `Symbol.iterator`/`Symbol.asyncIterator`, iterator closing (`return`/`throw`), and backpressure via pull.

### 2) **Function forms, `this`, and closures — [Functions Deep Dive](<../../../05 Functions Deep Dive/README.md>) and [Variables Scope and Closures](<../../../04 Variables Scope and Closures/README.md>)**

`this` binding rules, arrow lexical `this`, `call`/`apply`/`bind`, closure capture, and first-class/HOF contracts remain where they are. Here only how `then`/`await` use those closures and `this`-less arrow handlers.

### 3) **Error classes, `try/catch/finally`, and debugging async stacks — Error Handling and Debugging domain (when it lands)**

`Error` hierarchy, `cause`, `AggregateError`, `stack`/`async stack traces` (`--async-stack-traces` / `Error.stackTraceLimit`), `unhandledrejection` vs `uncaughtException`, and source-map aware debugging. This domain only covers how rejection propagates via `catch`/`finally` and when `unhandledrejection` fires.

### 4) **Modules, `import`/`export`, top-level `await` bundling — [Modules and Code Organization](<../../../14 Modules and Code Organization/README.md>)**

`import`/`export`, live bindings ([2.2](<../../../14 Modules and Code Organization/sections/2. Exports and live bindings/2.2. Live bindings why imports are not copies.md>)), dynamic `import()` ([4.1](<../../../14 Modules and Code Organization/sections/4. Dynamic import and meta/4.1. Dynamic import async loading and code splitting.md>)), CJS/ESM interop ([5.2](<../../../14 Modules and Code Organization/sections/5. CommonJS interop and resolution/5.2. ESM and CJS interop dual packages and migration.md>)), and how bundlers order TLA modules. This domain only covers TLA's blocking effect on importers.

### 5) **JSON serialization of async data and `structuredClone` — JSON Serialization domain (when it lands)**

`JSON.stringify` is synchronous and cannot serialize promises; `structuredClone` clones values but not promise capabilities.

### 6) **Memory of async work — WeakRef/FinalizationRegistry and GC pressure — [Collections](<../../../09 Collections Map Set and Weak References/README.md>) and Memory Management domain (when it lands)**

`WeakMap`/`WeakSet` ephemeron patterns for async caches, `WeakRef`+`FinalizationRegistry` timing non-determinism, and GC pressure from unbounded promise accumulation.

### 7) **Numbers, `Intl`, and `Temporal` timing concerns — [Numbers Dates Math and Temporal](<../../../12 Numbers Dates Math and Temporal/README.md>)**

`Date`/`Temporal` clock concerns and numeric precision remain there; scheduling delays use `Number` milliseconds and are subject to clamping, not `Temporal` duration semantics.
