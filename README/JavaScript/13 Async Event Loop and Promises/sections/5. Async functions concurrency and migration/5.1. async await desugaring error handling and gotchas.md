## 5.1. async await desugaring error handling and gotchas

### 1) **`async` always returns a Promise; `await` suspends and resumes via jobs**

**Definition** — `async function` (declaration, expression, arrow, method) returns a `Promise` that fulfills with the function's return value (or rejects if it throws). `await expr` pauses the function, schedules resumption as a microtask job after `expr` settles, and resumes with `expr`'s fulfillment value or throws its rejection at the `await` site. Code *before* the first `await` runs synchronously in the same task.

**What problem it solves / history** — manual `then` chains scramble `try`/`catch`/`finally` and `for`/`if`; `async`/`await` (ES2017) restore normal control flow while staying asynchronous underneath — desugared to promise jobs by the engine.

**Modern guidance** — lint `forEach(async ...)` and bare `Array.map(async ...)` without `all`; require `try`/`catch` around `await` where rejection is expected.

```js
// async always returns Promise — even for plain values
async function returnsPrimitive() { return 42; }
console.log(returnsPrimitive() instanceof Promise); // true → not 42
console.log(await returnsPrimitive()); // 42 — unwrap via await

// Sync preamble before first await — crucial for ordering
async function withPreamble(x) {
  console.log("preamble", x); // synchronous
  await Promise.resolve(); // suspend, resume as job
  console.log("resumed", x);
}
console.log("A");
withPreamble(1);
console.log("B");
// Order: A → preamble 1 → B → resumed 1
// B runs before resumed because await yields to microtask queue

// await non-promise — wraps via Promise.resolve
console.log(await 10); // 10 — equivalent to await Promise.resolve(10)
// but still deferred by one job:
let order = [];
async function checkWrap() { order.push("before"); await 1; order.push("after"); }
order = [];
await checkWrap();
console.log(order); // [ 'before', 'after' ] — after is deferred even for 1 (one microtask hop)

// Desugaring sketch — what the engine roughly does
// async function foo(a){ const b = await bar(a); return b*2; }
// ≈ function foo(a){ return Promise.resolve(bar(a)).then(b => b*2); } (plus try/catch→reject)
async function bar(a) { return a + 1; }
async function foo(a) { const b = await bar(a); return b * 2; }
console.log(await foo(5)); // 12 — same as then chain
```

### 2) **Error handling — `try/catch` around `await`, rethrow, and `finally` timing**

**Definition** — `await rejectedPromise` throws the rejection reason at that site, caught by the nearest enclosing `try/catch` inside the same `async` function (or rejected to the function's promise if uncaptured). `finally` runs after `try` or `catch` before the `async` promise settles.

```js
// try/catch around await — normal throw/catch
async function guarded(x) {
  try {
    const v = await Promise.reject(new Error(`bad ${x}`));
    return v;
  } catch (e) {
    console.log("caught inside", e.message);
    return "recovered";
  } finally {
    console.log("finally runs regardless");
  }
}
console.log(await guarded(1)); // caught inside bad 1 → finally runs regardless → recovered

// Rethrow and downstream catch
async function rethrow() {
  try { await Promise.reject(new Error("inner")); }
  catch (e) { console.log("inner catch", e.message); throw e; }
}
try { await rethrow(); } catch (e) { console.log("outer catch", e.message); }

// Mixing await + .catch vs try — both handle, different shape
async function viaThenCatch() { return Promise.reject(new Error("e1")).catch((e) => `viaCatch ${e.message}`); }
console.log(await viaThenCatch()); // viaCatch e1
async function viaTry() { try { await Promise.reject(new Error("e2")); } catch (e) { return `viaTry ${e.message}`; } }
console.log(await viaTry()); // viaTry e2

// return await vs return inside try/finally — return await defers until finally completes
async function returnAwaitVsReturn(p) {
  async function inner() {
    try { return await p; }
    finally { console.log("finally after inner settle"); }
  }
  try { return await inner(); } finally { console.log("outer finally"); }
}
console.log(await returnAwaitVsReturn(Promise.resolve("v"))); // finally after inner settle → outer finally → v
// Anti-pattern: return await is required only inside try/catch/finally to let catch/finally see the rejection;
// otherwise `return p` is cheaper (one less promise).
```

### 3) **Common gotchas — `await` in loops, `Array.map(async...)` without `all`, and `forEach(async...)` fire-and-forget**

**Definition** — `forEach` ignores returned promises; `Array.map(asyncFn)` builds an array of promises that must be `await Promise.all`'d. `await` inside `for...of` is sequential (each iteration waits), while `Promise.all(items.map(asyncFn))` runs in parallel.

```js
// BAD — forEach(async) fire-and-forget (no await, no handling)
async function badForEach(items) {
  items.forEach(async (x) => {
    await new Promise((r) => setTimeout(r, 2));
    console.log("bad side effect", x);
  });
  console.log("after forEach — work NOT awaited"); // fires before per-item logs
}
await badForEach([1, 2, 3]);
await new Promise((r) => setTimeout(r, 10)); // wait for stray side effects

// BAD — map without all — promises created but not observed
async function badMap(items) {
  const promises = items.map(async (x) => { await new Promise((r) => setTimeout(r, 2)); return x * 2; });
  console.log("promises length", promises.length, promises[0] instanceof Promise); // 2 true — not values
  // missing await Promise.all — downstream sees promises, not numbers
}
await badMap([1, 2]);

// GOOD — sequential for...of when order/rate matters
async function goodSequential(items) {
  const out = [];
  for (const x of items) {
    // sequential — each iteration awaits before next starts
    const v = await new Promise((r) => setTimeout(() => r(x * 2), 5));
    out.push(v);
  }
  return out;
}
console.log(await goodSequential([1, 2, 3])); // [2,4,6] — 3 sequential hops

// GOOD — parallel when independent
async function goodParallel(items) {
  return Promise.all(items.map(async (x) => { await new Promise((r) => setTimeout(r, 5)); return x * 2; }));
}
console.log(await goodParallel([1, 2, 3])); // [2,4,6] — 1 fan-out hop, concurrent

// Gotcha — await inside map's mapping still serial per element only if awaited sequentially
// Use 5.2 for choice guidance: dependent→sequential, independent→parallel (see 5.2).
```

### 4) **Common confusion**

- "`await` is a new way to make JavaScript multi-threaded" — no; it suspends one `async` function (queues its continuation), the thread returns to the loop — single-threaded.
- "`async` return value is unwrapped synchronously" — no; even `async () => 1` returns a promise that fulfills on the next job — caller must `await` or `then`.
- "`return await` is redundant" — usually yes, but required inside `try`/`catch`/`finally` so catch/finally see the rejection; lint rules flag only the non-try case.
- "`await Promise.all(map)` is sequential" — no; mapping starts all promises eagerly before `all` waits — concurrent.

### 5) **Performance note**

Each `await` costs one promise + one job for the resumption (even `await 1` does). A loop `for (const x of large) await f(x)` sequences jobs linearly; for 10k items that's 10k serial microtask hops. For independent items, `Promise.all(items.map(f))` costs N parallel hops but one await point — fewer scheduler steps than serial when I/O-dominated.

### 6) **Mentor note**

Give juniors `items.forEach(async x => await save(x))` with `await bad()` and ask how many saves finished before the next line — those who think `forEach` awaits learn the "ignores return" contract. In review, flag any `forEach`/`map(async` not followed by `all`/`allSettled`, any `async` without a `try/catch` at an API boundary, and any `return await` outside `try` that adds overhead — require a comment or remove `await`.
