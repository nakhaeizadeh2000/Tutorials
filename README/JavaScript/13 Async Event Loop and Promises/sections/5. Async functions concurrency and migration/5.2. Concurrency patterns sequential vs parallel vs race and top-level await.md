## 5.2. Concurrency patterns sequential vs parallel vs race and top-level await

### 1) **Sequential `for await` vs parallel `all` vs racing `race`/`any` — choosing by dependency**

**Definition** — when steps depend on prior results, run sequentially (`for...of` + `await` per step); when independent, start all early and `await Promise.all`/`allSettled` (concurrent fan-out); when first answer wins, use `race` (first settlement) or `any` (first fulfillment) with `AbortSignal` to cancel losers.

```js
function delay(v, ms) { return new Promise((r) => setTimeout(() => r(v), ms)); }

// Sequential — order matters, each step needs prior result
async function sequential(ids) {
  const out = [];
  for (const id of ids) {
    // fetch depends on prior transform (contrived)
    const v = await delay(id * 2, 5);
    out.push(v);
  }
  return out;
}
console.log(await sequential([1, 2, 3])); // [2,4,6] — 3 sequential sleeps

// Parallel — independent, start before await
async function parallel(ids) {
  const promises = ids.map((id) => delay(id * 2, 5)); // all start now
  return Promise.all(promises); // one await for all
}
console.log(await parallel([1, 2, 3])); // [2,4,6] — concurrent, faster wall-clock

// Race with signal-aware cancel — first wins, others aborted (Node 15+/browsers 22+ for AbortSignal.timeout)
async function raceFirst(promises) {
  // raw race — losers keep running (waste)
  return Promise.race(promises);
}
console.log(await raceFirst([delay("a", 20), delay("b", 5)])); // b

// Bounded concurrency helper reused from 4.1 idea — cap parallel work
async function mapLimit(items, fn, limit = 2) {
  const out = new Array(items.length);
  let next = 0;
  const workers = Array.from({ length: Math.min(limit, items.length) }, async () => {
    while (next < items.length) {
      const idx = next++;
      out[idx] = await fn(items[idx], idx);
    }
  });
  await Promise.all(workers);
  return out;
}
console.log(await mapLimit([1, 2, 3, 4], async (x) => { await delay(null, 3); return x * 10; }, 2)); // [10,20,30,40]
```

### 2) **Throttling and timeout — `AbortSignal.timeout`, `Promise.race` timeout leak, and `AbortController` wiring**

**Definition** — timeout via `Promise.race([work, timeoutReject])` leaks the loser (work continues). Wire `AbortSignal` into the underlying operation so timeout actually aborts work (frees connections, timers, file handles). `AbortSignal.timeout(ms)` creates a signal that aborts after `ms`; combine with `addEventListener("abort")` or pass `signal` to `fetch`/`fs`.

```js
// Leak-free timeout — signal aborts the work, not just the race
function delayWithSignal(v, ms, { signal } = {}) {
  return new Promise((resolve, reject) => {
    if (signal?.aborted) return reject(signal.reason ?? new Error("aborted"));
    const id = setTimeout(() => resolve(v), ms);
    signal?.addEventListener("abort", () => { clearTimeout(id); reject(signal.reason ?? new Error("abort")); }, { once: true });
  });
}
async function withTimeout(promiseFactory, ms) {
  const ac = new AbortController();
  const timeout = setTimeout(() => ac.abort(new Error("timeout")), ms);
  try {
    // work receives the signal and will reject + clear its timer when aborted
    return await promiseFactory(ac.signal);
  } finally { clearTimeout(timeout); }
}
console.log(await withTimeout((sig) => delayWithSignal("ok", 5, { signal: sig }), 20)); // ok
try { await withTimeout((sig) => delayWithSignal("slow", 30, { signal: sig }), 10); } catch (e) { console.log(e.message); } // timeout

// Signal-aware fetch pattern — cancels the network, not just the waiter
async function fetchLike(url, { signal } = {}) {
  // simulated fetch honoring abort — real fetch(url,{signal}) does this natively
  return delayWithSignal(`data:${url}`, 20, { signal });
}
const ac = new AbortController();
setTimeout(() => ac.abort(new Error("user abort")), 8);
try { await fetchLike("https://example.com", { signal: ac.signal }); } catch (e) { console.log(e.message); } // user abort

// AbortSignal.any / timeout statics (ES2025 / Node 20+)
if (typeof AbortSignal !== "undefined" && typeof AbortSignal.timeout === "function") {
  const sig = AbortSignal.timeout(5);
  try { await delayWithSignal("x", 20, { signal: sig }); } catch (e) { console.log(e.name); } // TimeoutError/AbortError
} else {
  console.log("AbortSignal.timeout not available — polyfill with setTimeout abort");
}
```

### 3) **Top-level `await` — module-only, blocks dependents, and how it differs from bare `await` in scripts**

**Definition** — `await` at top level works only inside ECMAScript modules (`.mjs`, `"type":"module"`, or `import()`ed ESM). A module with TLA suspends evaluation of importers until its awaited promise settles; sibling branches that don't depend on it may still evaluate up to their own awaits. Bare `await` in classic scripts/CommonJS throws `SyntaxError`.

```js
// Illustrations labeled — actual top-level await requires a module file

// Module A (module-with-tla.mjs) — conceptual content:
//   const config = await fetchConfig();
//   export const ready = true;
// Consumers: import { ready } from "./module-with-tla.mjs" — whole dependency graph waits for fetchConfig
// Side effect: parallel import branches that don't depend on A can run, but importers of A block.

// CJS cannot top-level await — SyntaxError (guarded):
try {
  // This string is not evaluated as CJS TLA — just shows the error shape
  // In real CJS: `await 1` at top level → SyntaxError: await is only valid in async functions and the top level bodies of modules
  const src = "async () => { await 1; }"; // must wrap in async
  console.log("CJS needs async wrapper:", await eval(`(${src})`)()); // 1? actually returns promise → await unwraps
} catch (e) { console.log(e.name); }

// ESM dynamic import with await — works inside async
const mod = await import("node:fs/promises").catch(() => null);
console.log(typeof mod?.readFile); // function (in Node 22)

// Anti-pattern — TLA that fetches sequentially when parallel would do
// BAD in a module: const a = await fetchA(); const b = await fetchB(); // serial TLA
// GOOD:           const [a,b] = await Promise.all([fetchA(), fetchB()]); // one await point, concurrent
console.log("TLA guidance: prefer Promise.all for independent awaited modules");
```

### 4) **Common confusion**

- "`Promise.all` runs promises in parallel like threads" — no; the promises' underlying operations (fetch, timers) may run concurrently via host threads/callbacks, but JS reactions still run one-at-a-time; concurrency is scheduling, not parallelism.
- "`race` timeout cancels the work" — no; without `AbortSignal`, the loser continues in the background leaking resources.
- "Top-level `await` works in any file" — ESM only; scripts and CJS must wrap in `async` IIFE.
- "More concurrency is always faster" — cap fan-out; beyond host limits (file descriptors, DB pool, rate limit), adding concurrency hurts throughput.

### 5) **Performance note**

Unbounded `ids.map(async id => fetchOne(id))` with `all` over 5k ids bursts 5k sockets → throttling and GC pressure from 5k response bodies held until `all` settles. Pool of 5–10 (host-dependent) saturates I/O without queue starvation. TLA adds startup latency for the whole app (importers wait) — defer slow TLA to lazy `import()` rather than static `import`.
