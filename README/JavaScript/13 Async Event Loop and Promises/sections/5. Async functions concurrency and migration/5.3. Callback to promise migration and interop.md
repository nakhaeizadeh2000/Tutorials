## 5.3. Callback to promise migration and interop

### 1) **From error-first callbacks to promises — `util.promisify` and manual wrapping**

**Definition** — Node's error-first convention is `cb(err, ...values)` — `err` non-null signals failure, otherwise values succeed. `util.promisify(fn)` returns a promisified wrapper that settles based on `err`; promisify assumes `fn` takes `(...args, callback)` and the callback is last, with `this` preserved.

**What problem it solves / history** — migrating callback APIs (`fs.readFile`, `db.query`) to `await` without rewriting the underlying implementation.

**Modern guidance** — prefer the promise-native module path (`fs/promises`) or the `*WithResolvers`/`once` helpers over manual wrapping when available; when wrapping, handle the multi-value and `this` cases explicitly.

```js
import { promisify } from "node:util";
import fs from "node:fs";

// Auto-promisify — single-value err-first
const readFileP = promisify(fs.readFile);
const data = await readFileP(import.meta?.filename ?? __filename, "utf8").catch(() => "");
console.log(typeof data); // string

// Preserves this — set thisArg via bind if needed
const obj = {
  prefix: "hi:",
  get(prefixLike, cb) { cb(null, this.prefix + prefixLike); },
};
const getP = promisify(obj.get);
// Wrong without bind: getP("a") loses this → prefix undefined
try { console.log(await getP.call(obj, "a")); } catch (e) { console.log(e.name); } // hi:a
// Alternative: const getBound = promisify(obj.get.bind(obj));

// Manual wrap — multi-value callback (needs custom wrapper, promisify returns only first value)
function multiArgWork(x, cb) { cb(null, x, x * 2); }
function multiPromisified(x) {
  return new Promise((resolve, reject) => {
    multiArgWork(x, (err, a, b) => err ? reject(err) : resolve([a, b]));
  });
}
console.log(await multiPromisified(3)); // [3,6]

// Error propagation — callback throw vs promise reject
function throwingCb(cb) { try { throw new Error("from sync"); } catch (e) { cb(e); } }
const throwingP = promisify(throwingCb);
try { await throwingP(); } catch (e) { console.log(e.message); } // from sync
```

### 2) **Interop — promisifying event emitters, streams, and resolvers**

**Definition** — events and streams are multi-shot (many callbacks); promises are one-shot. Bridge once per event with `events.once`, `stream.finished`, or `Promise.withResolvers`; for repeated events, use async iteration (`on` → async iterator) instead of a single promise.

```js
import { once, EventEmitter } from "node:events";
import { finished } from "node:stream/promises";

// once — one-shot event as a promise (with AbortSignal)
const ee = new EventEmitter();
setTimeout(() => ee.emit("data", "payload"), 5);
const [payload] = await once(ee, "data");
console.log(payload); // payload

// Abortable once — rejects on signal
const ac = new AbortController();
setTimeout(() => ac.abort(new Error("abort once")), 5);
try { await once(new EventEmitter(), "never", { signal: ac.signal }); } catch (e) { console.log(e.message); } // abort once

// finished — stream completion as a promise (Node streams)
import { Readable } from "node:stream";
const rs = Readable.from([1, 2, 3]);
let chunks = [];
rs.on("data", (c) => chunks.push(c));
await finished(rs).catch(() => {}); // resolves when readable ends (or rejects on error)
console.log(chunks); // [1,2,3]

// Promisified setTimeout
const delay = promisify(setTimeout);
await delay(5);
console.log("delay done");

// Custom once with withResolvers — zero-copy bridge
function onceResolver(emitter, event) {
  const d = typeof Promise.withResolvers === "function" ? Promise.withResolvers() : (() => { let r, j; const p = new Promise((res, rej) => { r = res; j = rej; }); return { promise: p, resolve: r, reject: j }; })();
  const on = (v) => { cleanup(); d.resolve(v); };
  const onErr = (e) => { cleanup(); d.reject(e); };
  function cleanup() { emitter.off?.(event, on); emitter.off?.("error", onErr); }
  emitter.on?.(event, on); emitter.on?.("error", onErr);
  return d.promise;
}
const ee2 = new EventEmitter();
setTimeout(() => ee2.emit("ready", 42), 5);
console.log(await onceResolver(ee2, "ready")); // 42
```

### 3) **When not to promisify — callback may be called many times vs promise settles once**

**Definition** — promises settle once; event emitters/streams call back many times. Wrapping a fan-out API in a single promise hides repeated emissions and backpressure. Use async iterables/generators for pull-based multi-shot sources; keep callbacks where push frequency is the contract.

```js
import { on } from "node:events";

// BAD — single promise captures only first data event, discards rest and backpressure
function badSingle(emitter) {
  return new Promise((resolve) => emitter.once("data", resolve)); // second data lost
}
const eeBad = new EventEmitter();
setTimeout(() => { eeBad.emit("data", 1); eeBad.emit("data", 2); }, 2);
console.log(await badSingle(eeBad)); // 1 — 2 vanished

// GOOD — async iteration over events (pull with backpressure, abort-aware)
const eeGood = new EventEmitter();
setTimeout(() => { eeGood.emit("data", 1); eeGood.emit("data", 2); eeGood.emit("data", 3); setTimeout(() => eeGood.emit("close"), 5); }, 2);
// Prefer `on` as async iterable for event streams
(async () => {
  const ac2 = new AbortController();
  // after close, break — on() would otherwise hang waiting for next data
  const iter = on(eeGood, "data", { signal: ac2.signal });
  let seen = [];
  const timer = setTimeout(() => ac2.abort(), 20);
  try {
    for await (const [v] of iter) {
      seen.push(v);
      if (v === 3) ac2.abort();
    }
  } catch (e) { if (e.code !== "ABORT_ERR") throw e; }
  finally { clearTimeout(timer); }
  console.log(seen); // [1,2,3]
})();

// Rule of thumb — one-shot: promisify; multi-shot / backpressure: async iterable; fire-and-forget callback: keep callback + signal
// Also see 10 Iterables 4.2 for async generator queue patterns for stream bridging.
await new Promise((r) => setTimeout(r, 25)); // settle async on() demo
```

### 4) **Common confusion**

- "Promisify works for any callback shape" — only `(...args, (err,val)=>{})` with `this`-preserving call; multi-value callbacks need manual wrapper returning `[a,b]` or `{}`.
- "Promisifying an event hides later events harmlessly" — it drops them and hides backpressure; use `events.on` as async iterable instead.
- "Repeated `promisify` per call is cheap" — wrap once outside the hot path; recreating the wrapper per iteration allocates extra promises.
- "`once` automatically cleans up" — only for that one event; `on` needs explicit `AbortSignal` to stop listening.

### 5) **Performance note**

Each `promisify` wrapper allocates one `Promise` + executor + bound function per call. For high-throughput APIs (per-row DB fetch), batch via `mapLimit` + one promise path rather than per-row promisify overhead. Multi-event streams bridged via `on` allocate per-iteration jobs as usual (see [1.2](<../1. Event loop and the job queue/1.2. Microtasks vs macrotasks queueMicrotask and starvation.md>)) — again, chunk or buffer.

### 6) **Mentor note**

Give juniors a callback `readFile` and ask them to `await` it without `promisify` — those who wrap correctly must decide where `this` goes and whether the callback may return multiple values. In review, flag any `new Promise((resolve)=> once(emitter,"x").then(resolve))` double-wrapping — use `once` directly — and any multi-shot promise that only captures the first event silently.
