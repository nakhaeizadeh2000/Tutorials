## 4.2. Promise.race any and withResolvers first-wins and deferred

### 1) **`Promise.race` — first settlement wins, including first rejection**

**Definition** — `Promise.race(iterable)` returns a promise that settles (fulfills *or* rejects) as soon as the first input settles. Non-promises are wrapped. Empty iterable stays pending forever. Use it for timeouts and first-response patterns, but remember the losers still run.

**What problem it solves / history** — racing a fetch against a timeout without manual bookkeeping.

**Modern guidance** — never use bare `race` for timeout without `AbortSignal` wired to the loser — the fetch still consumes the network and may resolve later as an unhandled fulfillment.

```js
function delay(v, ms) { return new Promise((r) => setTimeout(() => r(v), ms)); }
function failAfter(msg, ms) { return new Promise((_, rej) => setTimeout(() => rej(new Error(msg)), ms)); }

// First settlement wins — fulfillment beats later fulfillment
console.log(await Promise.race([delay("slow", 20), delay("fast", 5)])); // fast

// First rejection also wins — race rejects even though a later fulfillment exists
try { await Promise.race([failAfter("boom", 5), delay("ok", 20)]); } catch (e) { console.log(e.message); } // boom

// Timeout pattern — BAD without abort (loser fetch still runs)
async function fetchWithTimeoutBad(url, ms) {
  return Promise.race([delay(`data:${url}`, ms + 10), failAfter("timeout", ms)]);
}
try { await fetchWithTimeoutBad("x", 10); } catch (e) { console.log(e.message); } // timeout — but delay work still fires at ms+10 (waste)

// Empty race never settles — hang trap
const never = Promise.race([]);
console.log(never instanceof Promise, typeof never.then); // true function — but never settles
// Guard empty: if (iterable.length===0) throw / resolve default
```

### 2) **`Promise.any` — first fulfillment wins; rejects only with `AggregateError` when all reject**

**Definition** — `Promise.any(iterable)` (ES2021) fulfills as soon as the first input fulfills; it rejects only if *all* inputs reject, with an `AggregateError` whose `errors` holds the per-input reasons. Empty iterable rejects immediately with `AggregateError`. Use it when you have redundant providers and only need one success.

```js
// First fulfillment wins — rejections ignored until all reject
console.log(await Promise.any([failAfter("a", 5), failAfter("b", 6), delay("winner", 7)])); // winner

// All reject → AggregateError
try { await Promise.any([failAfter("a", 5), failAfter("b", 6)]); } catch (e) {
  console.log(e.name, e.errors.length, e.errors.map((er) => er.message)); // AggregateError 2 ["a","b"]
}
console.log(typeof AggregateError); // function — has .errors

// Empty any rejects immediately
try { await Promise.any([]); } catch (e) { console.log(e.name); } // AggregateError

// any vs race vs all vs allSettled — choose by "how many failures matter"
//  race: first settlement (fulfill OR reject) wins — for timeouts
//  any:  first fulfillment wins, all-reject → AggregateError — for redundant fetches
//  all:  all fulfill order-preserved, first rejection kills — for fan-out that must all succeed
//  allSettled: always fulfills with outcome records — for batch reporting

// Redundant providers — first good wins
async function redundantFetch(providers) {
  const attempts = providers.map((p) => delay(p.data, p.ms));
  return Promise.any(attempts);
}
console.log(await redundantFetch([{ data: "A", ms: 20 }, { data: "B", ms: 5 }])); // B
```

### 3) **`Promise.withResolvers` — the deferred pattern without the executor anti-pattern**

**Definition** — `Promise.withResolvers()` (ES2024, Node 22+) returns `{ promise, resolve, reject }`. The capability is split so non-promise code (events, callbacks) can settle a promise without capturing an executor closure. Use it to bridge non-promise sources to async/await.

```js
// withResolvers — clean deferred (ES2024)
if (typeof Promise.withResolvers === "function") {
  const { promise, resolve, reject } = Promise.withResolvers();
  console.log(typeof promise, typeof resolve); // object function
  promise.then((v) => console.log("withResolvers", v));
  resolve("hello");
  console.log(await promise); // hello
}

// Fallback for older Node — tiny polyfill shape
function withResolversFallback() {
  let resolve, reject;
  const promise = new Promise((res, rej) => { resolve = res; reject = rej; });
  return { promise, resolve, reject };
}
const f = withResolversFallback();
f.promise.then((v) => console.log("fallback", v));
f.resolve("ok");
console.log(await f.promise); // ok

// Bridging callback API — many-times callback → one-time promise
function onceEvent(target, event) {
  const d = typeof Promise.withResolvers === "function" ? Promise.withResolvers() : withResolversFallback();
  const on = (data) => { cleanup(); d.resolve(data); };
  const onErr = (err) => { cleanup(); d.reject(err); };
  function cleanup() { target.removeEventListener?.(event, on); target.removeEventListener?.("error", onErr); }
  target.addEventListener?.(event, on, { once: true });
  target.addEventListener?.("error", onErr, { once: true });
  return d.promise;
}
// No real EventTarget needed — demo with manual resolver
{
  const { promise, resolve } = typeof Promise.withResolvers === "function" ? Promise.withResolvers() : withResolversFallback();
  setTimeout(() => resolve("event"), 5);
  console.log(await promise); // event
}

// Anti-pattern replaced
// BAD: let resolve; const p = new Promise(r => resolve = r); // captured across scope, easy to leak
// GOOD: const { promise, resolve } = Promise.withResolvers(); // explicit triple, no executor scope capture
```

### 4) **Common confusion**

- "`race` picks first fulfillment" — no; first *settlement* (rejection also wins). Use `any` for first fulfillment.
- "`any([])` fulfills" — no; empty `any` rejects `AggregateError`; empty `race` hangs; empty `all` fulfills `[]`.
- "`Promise.any` has no error info" — `AggregateError.errors` holds each rejection reason in input order.
- "`withResolvers` makes promises cancellable" — no; it just exposes `resolve`/`reject`; cancel still needs `AbortSignal` wired to the work.

### 5) **Performance note**

`race` and `any` still allocate promises/reactions for each input up-front; at 10k inputs the allocation and queue cost is similar to `all`. The loser work runs unless aborted — a 10k `race` timeout without aborts leaves 10k timers/callbacks pending. Prefer bounded attempts (first 3 providers, not 10k).

### 6) **Mentor note**

Have candidates enumerate `all`/`allSettled`/`race`/`any` on `[]` and on `[[reject, fulfill]]` — the four edge cases reveal whether they've read the contracts or just recall the names. In review, flag any `race` timeout without an `AbortSignal` to the loser; any `Promise.reject` holder named `errors` that is not `AggregateError`; and any manual `let resolve` deferred — require `withResolvers` (or the fallback with a comment).
