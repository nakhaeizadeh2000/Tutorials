## 4.1. Promise.all and allSettled parallel aggregation

### 1) **`Promise.all` — all fulfilled or first rejection wins; preserves input order**

**Definition** — `Promise.all(iterable)` takes an iterable of *values* (non-promises are `Promise.resolve`-wrapped). It returns a promise that fulfills with an array of fulfillment values in *input order* once all settle fulfilled, or rejects with the *first* rejection's reason as soon as any input rejects — remaining inputs are not cancelled, they just stop being waited for.

**What problem it solves / history** — fan-out of independent async work without callback nesting: `Promise.all([fetchA(), fetchB()])` instead of manual counters. Order preservation lets `all` behave like `map` over async values.

**Modern guidance** — use `all` only when failure of any input should abort the whole group; otherwise use `allSettled` (next). Cap concurrency (see §3) instead of `all` over unbounded `Array.map(async => ...)`.

```js
// Order preserved regardless of settlement timing
function delay(v, ms) { return new Promise((r) => setTimeout(() => r(v), ms)); }
await Promise.all([delay("a", 20), delay("b", 5), delay("c", 10)]).then((a) => console.log(a)); // ["a","b","c"] — not b,c,a

// Non-promise values are wrapped
console.log(await Promise.all([1, Promise.resolve(2), Promise.resolve(3)])); // [1,2,3]

// Empty iterable resolves immediately
console.log(await Promise.all([])); // [] — no work → [] not pending

// First rejection wins — remaining results discarded (but their work still runs)
function failAfter(msg, ms) { return new Promise((_, rej) => setTimeout(() => rej(new Error(msg)), ms)); }
try {
  await Promise.all([delay("ok", 5), failAfter("boom", 2), delay("late", 10)]);
} catch (e) { console.log(e.message); } // boom — fastest rejection, not awaited "late"

// Unbounded fan-out anti-pattern
const ids = Array.from({ length: 20 }, (_, i) => i);
let concurrent = 0, max = 0;
async function boundedAll(items, fn, limit = 5) {
  for (let i = 0; i < items.length; i += limit) {
    const chunk = items.slice(i, i + limit);
    await Promise.all(chunk.map((x) => { concurrent++; max = Math.max(max, concurrent); return fn(x).finally(() => concurrent--); }));
  }
}
await boundedAll(ids, (x) => delay(x, 1), 5);
console.log("pooled max", max); // 5 — not 20
```

### 2) **`Promise.allSettled` — never rejects; reports per-outcome `{status, value|reason}`**

**Definition** — `Promise.allSettled(iterable)` waits for every input to settle and fulfills with an array of *outcome records*: `{ status:"fulfilled", value }` or `{ status:"rejected", reason }` in input order. It never rejects (ES2020). Use it for batch reporting where partial failure is acceptable.

```js
// Batch where some succeed, some fail — collect both
function ok(v) { return Promise.resolve(v); }
function fail(msg) { return Promise.reject(new Error(msg)); }

const outcomes = await Promise.allSettled([ok(1), fail("x"), ok(3)]);
console.log(outcomes);
// [{status:"fulfilled",value:1},{status:"rejected",reason:Error:x},{status:"fulfilled",value:3}]
const values = outcomes.filter((o) => o.status === "fulfilled").map((o) => o.value);
const errors = outcomes.filter((o) => o.status === "rejected").map((o) => o.reason.message);
console.log(values, errors); // [1,3] ["x"]

// all vs allSettled contract table
//  all:        fulfilled array OR first rejection reason
//  allSettled: always fulfills with outcome records (never short-circuits)

// Using allSettled for a file batch (Node) — don't throw on first missing file
// const files = ["a.json","b.json","missing.json"];
// const results = await Promise.allSettled(files.map(f => readFile(f,"utf8")));
// results.forEach((r,i)=> { if(r.status==="rejected") console.log(files[i], r.reason.message); });
```

### 3) **Concurrency control — bounded `all` via pools and why unbounded `all` with 10k promises is a bug**

**Definition** — promises are already started by the time you pass them to `all` — `all` does not *start* work, it *observes* it. So `ids.map((id) => fetchOne(id))` starts all fetches eagerly and holds N pending promises + N response buffers until settlement. Bound it with a pool.

```js
// Unbounded: starts all 100 at once — thundering herd, rate-limit, FD exhaustion (simulated)
async function fetchOne(id) { await delay(null, 2); return id; }
// const herd = await Promise.all(Array.from({ length: 100 }, (_, i) => fetchOne(i))); // bursts 100

// Pool primitive — concurrency cap
async function mapLimit(items, fn, limit = 3) {
  const out = new Array(items.length);
  let next = 0;
  const workers = Array.from({ length: Math.min(limit, items.length) }, async () => {
    while (next < items.length) {
      const idx = next++;
      out[idx] = await fn(items[idx], idx);
    }
  });
  await Promise.all(workers);
  return out;
}
console.log(await mapLimit([1, 2, 3, 4, 5], async (x) => { await delay(null, 1); return x * 2; }, 2)); // [2,4,6,8,10]

// p-limit style around existing fn (when fn itself races under shared limit)
// withResolvers variant cleanly builds a task queue — see 4.2
```

### 4) **Common confusion**

- "`Promise.all` rejects and cancels the other promises" — no cancellation; other async work continues — you must wire `AbortSignal` to actually stop it.
- "`all` result order matches completion order" — no; input order, even if settlement was `b` before `a`.
- "`allSettled` rejects when any input rejects" — no; it never rejects — check `status` per element.
- "`all([])` hangs" — no; empty resolves to `[]` immediately.

### 5) **Performance note**

`Promise.all` over 5k unresolved promises holds 5k promise + 5k reaction allocations plus the queued job for each settlement (~µs each) — fine at 1k, heavy at 100k. At large scale, chunk or pool: `Promise.all` per 50 at a time costs 100 jobs for 5k vs 5k jobs at once, but more importantly caps concurrent I/O and memory for response bodies.

### 6) **Mentor note**

Give juniors `Promise.all([sleep("a",20), sleep("b",5)])` and ask which index holds `"a"` — those who answer "index 1 because b finished first" learn the order contract. In review, flag any `Array.map(async x => ...)` whose result is not immediately `await Promise.all(...)` or `allSettled(...)` — bare `map(async` creates fire-and-forget promises — and any `all` over a length derived from user input without an obvious limit.
