## 8.1. Common interview Q&A async event loop and promises

### 1) **The classics with mechanism-level answers**

**Q1 — What logs and why? `setTimeout`, `Promise.then`, `queueMicrotask` ordering.**

```js
console.log("A");
setTimeout(() => console.log("F"), 0);
console.log("B");
Promise.resolve().then(() => console.log("C"));
queueMicrotask(() => console.log("D"));
console.log("E");
// Answer: A → B → E → C → D → F — current task to completion (A,B,E), then drain microtasks queue order (C insert before D, but enqueue order here: C then D), then macrotask F.
```

**Q2 — `await` ordering: what after `await Promise.resolve()` vs before?**

```js
async function demo() { console.log("pre"); await Promise.resolve(); console.log("post"); }
console.log("1");
demo();
console.log("2");
// Answer: 1 → pre → 2 → post — preamble (pre) is sync; post is a promise job after current task.
```

**Q3 — `Promise.resolve(thenable)` vs `new Promise(resolve=>resolve(thenable))` — two jobs or one?**

```js
const thenable = { then(r){ r(1); } };
Promise.resolve(thenable).then(v=> console.log(v)); // 1 — two jobs: resolve unwrap + then callback
new Promise((res)=> res(thenable)).then(v=> console.log(v)); // same — resolver unwraps as a job too
// Mechanism: HostEnqueuePromiseJob + thenable assimilation — each unwrap is a job.
```

**Q4 — `Promise.all` vs `allSettled` vs `race` vs `any` on `[[reject, fulfill]]` and `[]`.**

```js
console.log(await Promise.all([Promise.resolve(1), Promise.resolve(2)])); // [1,2]
try{ await Promise.all([Promise.reject(new Error("x")), Promise.resolve(2)]); }catch(e){ console.log(e.message);} // x — short-circuits
console.log(await Promise.all([])); // [] — immediately fulfills
console.log(await Promise.allSettled([Promise.reject(new Error("x")), Promise.resolve(2)]));
// [{status:"rejected",reason:Error:x},{status:"fulfilled",value:2}] — never rejects
console.log(await Promise.race([Promise.resolve("a"), Promise.reject(new Error("b"))])); // a — first settlement (reject not racing here: a settled first)
try{ await Promise.race([Promise.reject(new Error("b")), new Promise(()=>{})]); }catch(e){ console.log(e.message);} // b — rejection wins when first
console.log(await Promise.any([Promise.reject(new Error("x")), Promise.resolve("ok")])); // ok — first fulfillment
try{ await Promise.any([Promise.reject(new Error("a")), Promise.reject(new Error("b"))]); }catch(e){ console.log(e.name, e.errors.length);} // AggregateError 2
try{ await Promise.any([]); }catch(e){ console.log(e.name);} // AggregateError — empty any rejects
console.log(Promise.race([]) instanceof Promise); // true — hangs (pending)
```

**Q5 — `Promise.all([])` vs `any([])` vs `race([])` — settle?**

Answer: `all([])` fulfills `[]` immediately; `allSettled([])` fulfills `[]`; `race([])` never settles (pending forever); `any([])` rejects `AggregateError` immediately. Empty check is the pitfall for `race`.

**Q6 — `then` vs `catch` vs `finally` return values.**

```js
console.log(await Promise.resolve("v").then(v=> v+"+t")); // v+t
console.log(await Promise.resolve("v").catch(()=> "caught")); // v — pass-through (no rejection), catch not invoked
console.log(await Promise.reject(new Error("e")).catch(e=> "caught "+e.message)); // caught e
console.log(await Promise.resolve("v").finally(()=> {})); // v — finally transparent
try{ await Promise.resolve("v").finally(()=> { throw new Error("f"); }); }catch(e){ console.log(e.message);} // f — throw overrides
```

**Q7 — `return await` vs `return` inside `try/finally`.**

```js
async function bad(p){ try{ return p; } finally{ console.log("finally"); } }
async function good(p){ try{ return await p; } finally{ console.log("finally"); } }
// good sees rejection inside try: await throws → catch/finally sees it; bad returns raw promise while finally still runs but rejection is not caught in that try
try{ await bad(Promise.reject(new Error("x"))); }catch(e){ console.log("bad", e.message); }
try{ await good(Promise.reject(new Error("x"))); }catch(e){ console.log("good", e.message); }
// Lint: require `return await` only inside try/catch/finally.
```

**Q8 — `Array.map(async...)` without `all` — what type is result?**

```js
async function mapper(x){ return x*2; }
const r = [1,2].map(mapper);
console.log(r[0] instanceof Promise, r.length); // true 2 — array of promises, not values
console.log(await Promise.all(r)); // [2,4] — observed
```

**Q9 — Starvation: recursive `queueMicrotask`/`then` vs timer?**

Answer: microtasks drain exhaustively before the next macrotask, so a self-queueing microtask loop starves `setTimeout`/render. Each recursion adds one microtask job; yielding via `setTimeout(0)` or `scheduler.yield` breaks it. Show the 5-step starve vs periodic `setTimeout` unblock (see [1.2](<../1. Event loop and the job queue/1.2. Microtasks vs macrotasks queueMicrotask and starvation.md>)).

**Q10 — `setTimeout(0)` vs `setImmediate` — order?**

Answer (Node): after I/O, `setImmediate` (check phase) runs before `setTimeout(0)` (next timers iteration). Outside I/O, order is nondeterministic — don't depend on it. Browsers have no `setImmediate` — use `queueMicrotask` vs `setTimeout`.

**Q11 — `Promise.withResolvers` vs manual deferred?**

```js
if(typeof Promise.withResolvers==="function"){
  const { promise, resolve } = Promise.withResolvers();
  resolve(42);
  console.log(await promise); // 42
} else { console.log("withResolvers fallback"); }
// Why: withResolvers avoids `let resolve; new Promise(r=> resolve=r)` scope capture and is explicit.
```

**Q12 — Top-level `await` — where does it work?**

Answer: ESM only (`.mjs`, `"type":"module"` or dynamic `import()`). It blocks importers; sibling imports that don't depend on the TLA module can still evaluate up to their own `await`. In CJS/scripts, top-level `await` is `SyntaxError` — wrap in `async` IIFE.

### 2) **What interviewers actually probe for**

- Tracing `sync → micro → macro` with `await` preamble (not just "micro before macro") — where `await Promise.resolve()` still yields.
- `all` order preservation (input order, not completion order) and `race` loser leak vs `AbortSignal`.
- `then` returning a new promise and `finally` transparency (doesn't change value unless it throws/returns rejected).
- `race([])` hang vs `any([])` `AggregateError` — contract detail, not folklore about "parallel".

### 3) **Grading guidance**

- Junior: names queues (sync/micro/macro) and can fix `map(async`→`await Promise.all` with help; may confuse `race` with `any`.
- Mid: predicts the six `A→F` traces without running; knows `return await` inside `try`; uses `allSettled` for batch reporting; explains why `race` timeout leaks.
- Senior: draws loop phases (browser render vs Node timers/poll/check), reasons about `nextTick` before microtasks, wires `AbortSignal` to loser work, uses `withResolvers` without scope capture, and names the starvation budget guard.
- Expert: narrates job vs task (HostEnqueuePromiseJob), thenable assimilation per-job layering, `unhandledrejection` timing, `AbortSignal.any`/`timeout` statics, and `scheduler.yield` for INP — without reciting timers as exact delays.
- Red flags: "`Promise` runs in parallel threads" or "`await` blocks the thread" or "`race([])` resolves `[]`" or "`finally` receives the value".
