## 6.1. Async checklist reflex rules mentors screen for

### 1) **The three queues before any "order" claim — stack, microtasks, macrotasks**

**Definition** — every ordering answer starts with: current task to completion → drain all microtasks (`Promise` jobs, `queueMicrotask`) → next macrotask (`setTimeout`/`setImmediate`/I/O) plus browser render between macrotasks. Node adds `nextTick` before microtasks; don't conflate.

```js
// Classify every scheduled call by queue — table doubles as review checklist
// Sync:    console.log, executor body, code before first await
// Micro:   Promise.then/catch/finally, queueMicrotask, await resumption, MutationObserver (browser)
// Macro:   setTimeout, setInterval, setImmediate (Node check), I/O poll callback, requestAnimationFrame (browser render)
console.log("A"); // sync

queueMicrotask(() => console.log("B micro"));
Promise.resolve().then(() => console.log("C micro via promise"));
if (typeof process !== "undefined" && process.nextTick) process.nextTick(() => console.log("D nextTick before micro"));
setTimeout(() => console.log("E macro"), 0);
console.log("F");
// Typical Node: A → F → D → B → C → E
// Typical browser: A → F → B → C → E

// Rule of thumb — before answering "which logs first?", point at each line and label queue
function labelQueue(fnName) {
  const table = { log: "sync", then: "micro", queueMicrotask: "micro", nextTick: "nextTick", setTimeout: "macro", setImmediate: "check" };
  return table[fnName] ?? "unknown";
}
console.log(labelQueue("then"), labelQueue("setTimeout")); // micro macro
```

### 2) **`await` always yields — even `await 1` defers to a microtask**

**Definition** — `await expr` always yields after `expr` settles — at least one microtask hop. The code before the first `await` in an `async` function is synchronous; everything after the first `await` is a job. Consequence: state mutations between `await`s are observable by interleaving tasks only when the `async` function yields.

```js
// Even await non-promise defers
let x = 0;
async function bump() { await 1; x++; }
async function bumpTwice() { bump(); bump(); console.log("between bumps, x=", x); await Promise.resolve(); console.log("after jobs, x=", x); }
await bumpTwice(); // between 0 → after 2 — interleaving is microtask-timed, not instant

// return await vs return — inside try, await is required to let catch see the rejection
async function needsAwait(p) {
  try { return await p; } catch (e) { return `caught ${e.message}`; }
}
console.log(await needsAwait(Promise.reject(new Error("boom")))); // caught boom
async function noNeed(p) { return p; } // no try — no extra await needed
console.log(await noNeed(Promise.resolve(42)).then((v) => v)); // 42

// Sequential vs parallel by await placement
async function sequentialFetch(arr, fetchLike) {
  const out = [];
  for (const id of arr) out.push(await fetchLike(id)); // one at a time
  return out;
}
async function parallelFetch(arr, fetchLike) {
  return Promise.all(arr.map(fetchLike)); // all before first await
}
function fakeFetch(id) { return new Promise((r) => setTimeout(() => r(id * 2), 5)); }
console.log(await sequentialFetch([1, 2], fakeFetch)); // [2,4] — serial
console.log(await parallelFetch([1, 2], fakeFetch)); // [2,4] — concurrent
```

### 3) **The review grep list**

**Definition** — six `grep` checks that catch most async bugs before they ship:

```js
// Checklist item → grep → fix
// 1) Fire-and-forget map(async —
//    grep: /\.map\s*\(\s*async/  → require immediate await Promise.all / allSettled or mapLimit
// 2) forEach(async —
//    grep: /\.forEach\s*\(\s*async/ → replace with for...of + await or Promise.all
// 3) setTimeout/setInterval without clear/AbortSignal
//    grep: /setTimeout\s*\(/     → nearby clearTimeout / AbortSignal wiring must be visible
// 4) Unbounded Promise.all over user-controlled length
//    grep: /Promise\.all\s*\(/   → verify input bounded or pool behind it
// 5) race without AbortSignal / loser leak
//    grep: /Promise\.race\s*\(/  → require signal wiring to loser work
// 6) return await outside try or needless await inside trivial async
//    grep: /return\s+await\s+/   → keep only inside try/catch/finally
// 7) withResolvers vs deferred anti-pattern
//    grep: /new Promise.*resolve.*=/ → replace with Promise.withResolvers
// 8) await in loop where independent
//    grep: /for.*await/ or await inside for — ask: dependent? if not, hoist to all

// Example — flag candidate
const suspects = [
  "items.forEach(async x => save(x))",
  "results = items.map(async x => fetch(x))", // missing all
  "Promise.race([work, timeout])", // missing abort
  "setTimeout(handler,0)", // missing clear on teardown
];
suspects.forEach((s) => console.log("review:", s));

// Bound fan-out helper — the approved "parallel but capped" answer
async function boundedAll(items, fn, limit = 5) {
  const out = new Array(items.length);
  let next = 0;
  const workers = Array.from({ length: Math.min(limit, items.length) }, async () => {
    while (next < items.length) {
      const i = next++;
      out[i] = await fn(items[i], i);
    }
  });
  await Promise.all(workers);
  return out;
}
console.log(await boundedAll([1, 2, 3], async (x) => x * 2, 2)); // [2,4,6]
```

### 4) **Common confusion**

- "Microtasks run after every line" — no; after the *current task* completes, the whole microtask queue drains — not per statement.
- "`await` in `for` is always bad" — dependent steps *should* be sequential; only independent fan-out should hoist to `all`.
- "Linter says `return await` is always slower" — outside `try` yes; inside `try`/`catch`/`finally` it is correctness, not style.

### 5) **Performance note**

The grep list is not style nit — each flagged pattern has a measured cost: unawaited `map(async)` leaks rejections and holds promises until GC; unbounded `all` over 10k items holds O(n) response bodies; `forEach(async)` doubles handler allocations vs a single `for...of`.

### 6) **Mentor note**

Hand juniors a snippet with `items.map(async...)`, `forEach(async...)`, and `race` without signal, and ask them to fix with `all`/`allSettled`/`on`/`AbortSignal` while narrating which queue each `await` lands in. In review, require the six grep checks to be visibly resolved; require every `Promise.all` over external input to show its limit or a comment explaining why unbounded is safe.
