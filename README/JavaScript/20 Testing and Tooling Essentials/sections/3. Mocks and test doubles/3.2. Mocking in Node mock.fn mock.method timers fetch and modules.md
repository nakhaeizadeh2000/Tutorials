## 3.2. Mocking in Node mock.fn mock.method timers fetch and modules

### 1) **`mock.fn` and `mock.method` — creating spies/mocks, `mock.calls`/`callCount`, `mock.restore`/`mock.reset`, and why every mock must be restored**

**Definition** — `node:test` ships `mock` (Node 20+). `mock.fn(original?, impl?)` creates a spy/mock function whose `mock.calls` is `Array<{arguments, result, error, target}>` and `mock.callCount()` is the length. `mock.method(object, methodName, impl?)` replaces `object[method]` with a mock that restores on `mock.restoreAll()` / `mock.reset()` or per-mock `mock.restore()`. `t.after(() => mock.restoreAll())` is the per-test cleanup contract.

**Modern guidance** — two rules: (1) every `mock.method` must be restored via `t.after` or `afterEach` — a leaked mock poisons the next test; (2) spy vs mock is just naming — `mock.fn()` without impl is a spy, with `implementation` stub that records, with expectation you call `assert.equal(mock.callCount(), 1)`.

```js
const assert = require("node:assert/strict");
const { mock } = require("node:test");

// mock.fn — spy with recording
{
  const spy = mock.fn((x) => x * 2);
  assert.equal(spy(3), 6);
  assert.equal(spy(4), 8);
  assert.equal(spy.mock.callCount(), 2);
  assert.deepEqual(spy.mock.calls[0].arguments, [3]);
  assert.equal(spy.mock.calls[1].result, 8);
  spy.mock.resetCalls();
  assert.equal(spy.mock.callCount(), 0);
}

// mock.method — replaces and restores
{
  const api = { fetchUser(id) { return { id, name: "real" }; } };
  const mocked = mock.method(api, "fetchUser", (id) => ({ id, name: "mocked" }));
  assert.equal(api.fetchUser("a").name, "mocked");
  assert.equal(mocked.mock.callCount(), 1);
  mock.restoreAll(); // must restore — otherwise next test sees "mocked"
  assert.equal(api.fetchUser("a").name, "real");
}

// t.after pattern — real suites use the TestContext; here simulate
{
  const api2 = { get: (id) => `real:${id}` };
  const t = { afters: [], after(fn){ this.afters.push(fn); }, flush(){ for(const f of this.afters) f(); } };
  mock.method(api2, "get", () => "mocked");
  t.after(() => mock.restoreAll());
  assert.equal(api2.get("x"), "mocked");
  t.flush();
  assert.equal(api2.get("x"), "real:x");
}
console.log("mock.fn ok");
```

**Common confusion** — "`mock.reset` restores." `mock.reset()` clears mocks registered via `mock.method` but `spy.mock.resetCalls()` only clears `calls`. To re-enable the original method, call `mock.restoreAll()` or `mockFn.mock.restore()`.

### 2) **Timers and I/O — `mock.timers.enable` / `tick` / `runAll` vs `setTimeout` in tests; stubbing `global.fetch` and `node:fs` without leaking**

**Definition** — `mock.timers` (Node 20+) fakes `setTimeout`/`setInterval`/`setImmediate`/`Date`. `mock.timers.enable({ apis: ["setTimeout","Date"], now: 1_700_000_000_000 })` installs fakes; `mock.timers.tick(ms)` advances virtual time; `mock.timers.runAll()` drains pending timers; `mock.timers.reset()` / `mock.timers.disable()` restores real timers.

**Modern guidance** — never `await sleep(100)` in a test (flaky, slow). Freeze time with `mock.timers` or a clock seam (see [1.2](../1. Testing foundations/1.2. Anatomy of a test AAA naming isolation and determinism.md)). For `fetch`/`fs`, prefer a tiny fake or a per-test `mock.method(global, "fetch", …)` that is restored with `t.after`; never assign `global.fetch = myMock` without restore.

```js
const assert = require("node:assert/strict");
const { mock } = require("node:test");

// mock.timers — deterministic time, no wall-clock sleep
{
  mock.timers.enable({ apis: ["setTimeout", "setInterval", "Date"], now: 1_000 });
  let fired = 0;
  setTimeout(() => { fired++; }, 1_000);
  assert.equal(fired, 0);
  mock.timers.tick(999);
  assert.equal(fired, 0);
  mock.timers.tick(1);
  assert.equal(fired, 1);
  mock.timers.tick(1_000); // no more timers
  (mock.timers.disable ?? mock.timers.reset).call(mock.timers); // Node 22 disable / Node 20 reset — restore real timers (must)
  assert.equal(typeof setTimeout, "function");
}

// fetch — per-test mock via mock.method on globalThis
{
  const original = globalThis.fetch; // may be undefined on older Node — guard in real code
  // In Node 18+ fetch exists; mock it, assert shape, then restore
  if (typeof globalThis.fetch === "function") {
    const fetchMock = mock.method(globalThis, "fetch", async (url) => ({ ok: true, url: String(url), json: async () => ({ mocked: true }) }));
    (async () => {
      const res = await fetch("https://example.com/api");
      assert.equal(res.ok, true);
      assert.equal(fetchMock.mock.callCount(), 1);
      mock.restoreAll();
      assert.equal(typeof globalThis.fetch, "function");
      console.log("fetch mock ok");
    })();
  } else {
    console.log("fetch not present — mock would be via mock.method(globalThis,'fetch', …) on Node 18+");
    mock.restoreAll();
  }
}

// anti-pattern: setTimeout sleep in a test — slow and flaky
// await new Promise(r => setTimeout(r, 100)); // don't — use mock.timers.tick(100) plus runAll()
console.log("timers ok");
```

**Common confusion** — "`tick` fires `setInterval` once." `tick(ms)` fires every timer whose deadline falls within the window, so `setInterval(fn, 10); tick(35)` fires `fn` three times (10,20,30). Use `tick` to assert *count*, not just "fired."

**Performance note** — `mock.timers.enable` replaces globals; forgetting `disable()` leaves the process in fake time and freezes `performance.now()` — see failure mode in [7.1](../7. Common pitfalls to production bugs/7.1. Real production bugs caused by testing and tooling mistakes.md).

### 3) **Module mocking — `mock.module` (experimental Node 22) vs manual `require.cache` seam vs dependency injection (which to prefer today)**

**Definition** — module mocking replaces an imported module's exports for the test. Node 22 ships `mock.module(specifier, { namedExports, defaultExport })` (experimental, behind `--experimental-vm-modules` in some flows) that installs before the next `import`. The stable alternatives are (a) a seam: the unit takes its collaborator as a parameter (`new Service(repo)` injected fake), or (b) `require.cache` shimming in CJS.

**Modern guidance** — prefer *dependency injection* (constructor/function arg) over module mocking. A seam `function createOrder(repo, id){ return repo.get(id); }` is explicit, works in CJS and ESM, and requires no experimental API. Use `mock.module("./dep.js", { namedExports: { getUser: mock.fn(() => ({id:"a"})) } })` only when the import graph is frozen and injection would require a large refactor; gate it with `if (typeof mock.module === "function")` and keep it as `t.after(() => mock.reset())` restore — it is still experimental as of Node 22 LTS.

```js
const assert = require("node:assert/strict");
const { mock } = require("node:test");

// Preferred: dependency injection — no mock.module needed
function service(repo, id) { return repo.get(id) ? `found:${id}` : "missing"; }
const fakeRepo = { get: (id) => id === "a" ? { id } : null };
assert.equal(service(fakeRepo, "a"), "found:a");
assert.equal(service(fakeRepo, "z"), "missing");

// CJS cache seam (stable) — swap require.cache entry for a fake
// [CJS seam — conceptual: require.cache[require.resolve('./dep')].exports = fake]
// illustrated without disk I/O:
{
  const registry = new Map(); // stand-in for require.cache
  registry.set("./dep", { get: (id) => `real:${id}` });
  const fakeDep = { get: (id) => `fake:${id}` };
  registry.set("./dep", fakeDep);
  assert.equal(registry.get("./dep").get("a"), "fake:a");
  registry.set("./dep", { get: (id) => `real:${id}` }); // restore
  assert.equal(registry.get("./dep").get("a"), "real:a");
}

// mock.module seam — experimental, guard before use (Node 22)
{
  if (typeof mock.module === "function") {
    // In a real ESM test file:
    // mock.module("./dep.js", { namedExports: { getUser: mock.fn(() => ({ id:"a", name:"Mocked" })) } });
    // const { getUser } = await import("./dep.js");
    // assert.equal(getUser("a").name, "Mocked");
    // mock.reset(); // restore — must
    mock.reset();
    console.log("mock.module present — would mock before import()");
  } else {
    console.log("mock.module not present on this Node — use DI seam");
  }
}
console.log("module mocking guidance ok");
```

**Mentor note** — make juniors defend a module mock vs injection choice in PR review: "why not a constructor arg?" is the first question. Injection keeps tests deterministic and discoverable; `mock.module` is a power tool with an experimental label for a reason.
