## 3.1. Test doubles taxonomy dummy stub spy mock fake and when each fits

### 1) **Five doubles — dummy (fill arity), stub (canned answer), spy (record call), mock (record + expect), fake (working in-memory impl)**

**Definition** — Gerard Meszaros' taxonomy (2007) — five kinds of stand-ins for a real collaborator:
- **Dummy** — value never used, only fills a required argument (`() => {}` as a callback you never invoke).
- **Stub** — returns a canned answer for a query (`getUser: () => ({ id: "a" })`).
- **Spy** — records calls/args (`calls.push(arg)`) so you can assert *interaction*.
- **Mock** — spy plus *pre-programmed expectations* (`expect(mock).toHaveBeenCalledWith("a")` fails the test if not called).
- **Fake** — a lightweight working implementation (`FakeClock`, `FakeFs`, `InMemoryQueue`) that behaves correctly but is cheap.

**Modern guidance** — prefer *state* assertions over interaction assertions when the state is observable. Use a dummy when the collaborator is not touched in this branch; stub when the unit queries it; spy when you must verify an effect (emitted event, queued job); mock rarely (protocol tests); fake when the real collaborator is heavy (clock/fs/DB).

```js
const assert = require("node:assert/strict");

// Dummy — fills a required param but is never called
function greet(name, _unusedLogger) { return `hi ${name}`; }
assert.equal(greet("Ada", () => {}), "hi Ada");

// Stub — canned answer for a query
function getGreeting(userRepo, id) {
  const u = userRepo.get(id);
  return u ? `hi ${u.name}` : "unknown";
}
const stubRepo = { get: (id) => (id === "a" ? { name: "Ada" } : null) };
assert.equal(getGreeting(stubRepo, "a"), "hi Ada");
assert.equal(getGreeting(stubRepo, "z"), "unknown");

// Spy — records so you can assert interaction
function makeSpy(fn = () => {}) {
  const calls = [];
  const spy = (...args) => { calls.push(args); return fn(...args); };
  spy.calls = calls;
  spy.callCount = () => calls.length;
  return spy;
}
function publish(queue, msg) { queue.send(msg); }
const spyQueue = { send: makeSpy() };
publish(spyQueue, "hello");
assert.equal(spyQueue.send.callCount(), 1);
assert.deepEqual(spyQueue.send.calls[0], ["hello"]);

// Fake — working in-memory impl (here an in-memory Map repo)
function makeFakeRepo(seed = new Map()) {
  const m = new Map(seed);
  return {
    get(id) { return m.get(id) ?? null; },
    set(id, v) { m.set(id, v); },
    size() { return m.size; }
  };
}
const fake = makeFakeRepo([["a", { name: "Ada" }]]);
assert.equal(fake.get("a").name, "Ada");
fake.set("b", { name: "Bob" });
assert.equal(fake.size(), 2);
console.log("five doubles ok");
```

**Common confusion** — "mock and stub are synonyms." A stub *answers*, a spy *records*, a mock *records and expects*. Over-mocking (verifying every internal call) couples tests to implementation; a rename of an internal helper breaks 30 tests.

### 2) **When each fits — stub for query replacement, spy for interaction probe, fake for `Fs`/`Clock`/`Queue` subsystem, mock rarely for protocol**

**Definition** — choose by *what you verify*:
- Result/state visible on `return` or reachable `state` → **stub/fake** + `assert.equal(state, …)`.
- Side effect only observable via call history (sent email, `fs.write`, `fetch`) → **spy/mock**.
- Expensive subsystem with contract (time, FS, DB, `fetch`) → **fake** that actually implements the contract in RAM.

**Modern guidance** — decision table:

| Situation | Double | Why |
|---|---|---|
| Unit computes `total = qty * price` | none / stub for `priceFeed` | pure state — stub the query |
| Must prove `queue.send` called with `id` | spy | interaction is the contract |
| Must prove exact `fetch` call shape + header | mock on `global.fetch` | protocol (rare) |
| Unit reads `Date.now()` / `setTimeout` | fake clock (`mock.timers`) | time is a subsystem — fake it |
| Unit writes `node:fs` | fake FS (`memfs` or inject) | I/O heavy — fake in RAM |
| Port / integration | real collaborator (no double) | confidence > speed |

```js
const assert = require("node:assert/strict");

// Stub fits: computation that queries a collaborator, result is state
function totalFor(order, priceOf) { return order.qty * priceOf(order.sku); }
const priceStub = (sku) => sku === "A" ? 9 : 1;
assert.equal(totalFor({ sku: "A", qty: 3 }, priceStub), 27);

// Spy fits: side effect whose result is not in return value
function notify(tracking, evt) { tracking.record(evt); }
function makeSpy() { const calls=[]; const fn=(...a)=>{calls.push(a);}; fn.calls=calls; return fn; }
const trackingSpy = { record: makeSpy() };
notify(trackingSpy, { type: "purchase", id: "a" });
assert.equal(trackingSpy.record.calls[0][0].type, "purchase");

// Fake fits: subsystem with contract (time) — illustrated via clock seam
function isExpired(expiryMs, clock = { now: () => Date.now() }) { return expiryMs < clock.now(); }
const fakeClock = { now: () => 1_700_000_000_000 };
assert.equal(isExpired(1_699_999_999_000, fakeClock), true);

// Anti-pattern: mocking a pure helper you own — couples to impl
function sum(arr){ return arr.reduce((a,b)=>a+b,0); }
// Don't: mock sum to return 10 — test now asserts your mock, not the unit
// Do: assert on the state (the sum)
assert.equal(sum([1,2,3]), 6);
console.log("when-each-fits ok");
```

**Mentor note** — in review, every mock/spy must answer "what *observable* outcome does this interaction prove that a state assertion cannot?" If the answer is "it was called," but the state already shows it, replace the spy with `deepStrictEqual` on state.

### 3) **Behaviour vs state — interaction testing (`calledWith`) vs state assertion (`assert.equal(state, …)`) and why over-mocking couples tests to impl**

**Definition** — *state* testing asserts on data after the Act (return value, DB row, `Map` size). *Behaviour* (interaction) testing asserts on *how* the Act called collaborators (`spy.callCount`, `mock.calls`). Behaviour tests break when you refactor internal calls even if the external contract still holds.

**Modern guidance** — default to state. Use behaviour only when the contract *is* the interaction (published event, HTTP request shape, analytics call). Two rules: (1) never assert internal helper calls (`expect(helper).toHaveBeenCalled`) — those helpers are not the public contract; (2) assert on the *narrowest* interaction (`calledWith(id)` not `calledTimes(1)` plus ordering).

```js
const assert = require("node:assert/strict");

// State testing — refactor-proof (rename internal helper, still passes)
function checkout(cart) {
  const total = cart.items.reduce((s,i)=>s+i.qty*i.price, 0);
  return { total, count: cart.items.length };
}
assert.deepEqual(checkout({ items: [{ qty:2, price:5 },{ qty:1, price:3 }] }), { total: 13, count: 2 });

// Behaviour testing — only when interaction IS the contract (emit)
function placeOrder(bus, order) { bus.emit("order.placed", order); }
function makeBus(){ const events=[]; return { emit(t,p){ events.push([t,p]); }, events }; }
{
  const bus = makeBus();
  placeOrder(bus, { id: "a" });
  assert.deepEqual(bus.events[0], ["order.placed", { id: "a" }]);
}

// Anti-pattern: over-mocking internal decomposition
function sumInternal(arr){
  function add(a,b){ return a+b; } // internal helper — not the contract
  return arr.reduce(add, 0);
}
// Bad: spy on add — renaming add to plus breaks 20 tests even though sum still works
// Good: assert on sum's state
assert.equal(sumInternal([1,2,3]), 6);
console.log("behaviour vs state ok");
```
