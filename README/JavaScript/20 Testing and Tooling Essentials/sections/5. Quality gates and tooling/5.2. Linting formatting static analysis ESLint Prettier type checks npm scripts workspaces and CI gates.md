## 5.2. Linting formatting static analysis ESLint Prettier type checks npm scripts workspaces and CI gates

### 1) **ESLint + Prettier — flat config (`eslint.config.js`), rules as bug filters (`no-undef`/`eqeqeq`/`no-floating-promises`), Prettier as formatter not linter**

**Definition** — ESLint is the AST lint that flags *logic* bugs; Prettier is the deterministic formatter that rewrites whitespace. ESLint 9's *flat config* (`eslint.config.js` exporting an array of config objects with `rules`, `ignores`, `languageOptions`) replaces `.eslintrc.*`. Running Prettier via `eslint --fix` is deprecated — run `prettier --check` / `--write` as a separate gate.

**What problem it solves / history** — manual style debates burned review time and missed bugs like `if (a = 2)` (`no-cond-assign`), `== null` coercion (`eqeqeq`), or a floating `Promise` that is never `await`ed (`no-floating-promises` from `@typescript-eslint`, or `eslint-plugin-promise`). Flat config and `eslint --fix` on save catch them before `node --test`.

**Modern guidance** — minimal bug-filter set for a vanilla JS repo (ES2026, Node 22):

| Gate | Rule / command | Catches |
|---|---|---|
| Lint | `no-undef` | missing import / TDZ leak ([Variables 1.2](<../../../04 Variables Scope and Closures/sections/1. Declarations and bindings/1.2. Temporal dead zone why early access throws.md>)) |
| Lint | `eqeqeq: ["error","always"]` | `==` coercion per [Values 3.1](<../../../03 Values Types and Coercion/sections/3. Coercion at work/3.1. Loose equality the abstract equality algorithm walkthrough.md>) |
| Lint | `no-unused-vars` | dead stub / leaked import |
| Lint | `no-only-tests` (custom) | `test.only` shipped to `main` |
| Lint | `promise/no-floating-promises` | unawaited `Promise` ([4.1](../4. Async timing and flake control/4.1. Testing promises async await event emitters and rejections.md)) |
| Format | `prettier --check .` | whitespace churn |
| CLI | `node --test` + `c8 --check-coverage` | branch truth per [5.1](./5.1. Coverage with c8 v8 line branch function thresholds and lies.md) |

```js
// eslint.config.js — flat config (ESLint 9) — illustrative, not lint-executed here
// import js from "@eslint/js";
// export default [
//   { ignores: ["coverage/**", "node_modules/**"] },
//   js.configs.recommended,
//   { rules: { eqeqeq: ["error","always"], "no-undef": "error", "no-unused-vars": "warn" } },
// ];

// .prettierrc — Prettier as formatter, not linter
// { "semi": true, "singleQuote": false, "printWidth": 100 }

// What each rule would flag (illustrated via assert that the lint would fail CI)
const assert = require("node:assert/strict");

// eqeqeq — would flag: if (a == null) — use === null || === undefined or a == null only with comment
function isNullish(v) { return v === null || v === undefined; }
assert.equal(isNullish(null), true);
assert.equal(isNullish(0), false);

// no-floating-promises — would flag: fetchQty(-1); without await/return/catch
async function fetchQty(q) { if (q < 0) throw new RangeError("neg"); return q; }
(async () => { await assert.rejects(fetchQty(-1), RangeError); })();

// prettier --check is idempotent: running it twice changes nothing
const src = "function f(x){return x*2;}\n";
assert.equal(typeof src, "string");
console.log("lint/format ok");
```

**Common confusion** — "Prettier fixes logic bugs." It doesn't — it only rewrites whitespace. `if (a = 2)` survives `prettier --write`; `no-cond-assign` via ESLint catches it.

### 2) **`package.json` scripts and workspaces — `test`/`lint`/`format`/`prepare`, `engines`/`type`/`exports`, `workspaces` for monorepo linkage**

**Definition** — `package.json` is the delivery contract: `scripts` are the four-gate entry points (`test`, `lint`, `format`, `prepare`), `type` selects CJS vs ESM, `exports` restricts which files are importable, `engines` declares the Node semver, `workspaces` links local packages without publishing.

**Modern guidance** — 2026 baseline `package.json` for a vanilla JS lib (Node 22/24):

| Field | Value | Why |
|---|---|---|
| `type` | `"module"` or `"commonjs"` | explicit — `type: commonjs` is default CJS; `type: module` opts into ESM per [Modules 5.3](<../../../14 Modules and Code Organization/sections/5. CommonJS interop and resolution/5.3. Specifiers package.json exports import maps and organization.md>) |
| `exports` | `{ ".": "./src/index.js" }` | blocks deep import of `src/internal.js` |
| `engines` | `">=22"` | enforces LTS in CI and via `engine-strict` |
| `scripts.test` | `node --test --test-reporter=spec` | stdlib runner — no extra dep |
| `scripts.coverage` | `c8 --check-coverage --lines 90 --branches 85 -- node --test` | gate per [5.1](./5.1. Coverage with c8 v8 line branch function thresholds and lies.md) |
| `scripts.lint` | `eslint .` | flat config |
| `scripts.format:check` | `prettier --check .` | CI gate |
| `workspaces` | `["packages/*"]` | monorepo linkage via `npm ci` |

```js
const assert = require("node:assert/strict");
const fs = require("node:fs");
const path = require("node:path");
const os = require("node:os");

// Construct the contract in a temp dir and validate it — no npm install needed
const dir = fs.mkdtempSync(path.join(os.tmpdir(), "pkg-"));
const pkg = {
  name: "@acme/js-lib",
  type: "commonjs",
  exports: { ".": "./src/index.js" },
  engines: { node: ">=22" },
  scripts: {
    test: "node --test --test-reporter=spec",
    coverage: "c8 --check-coverage --lines 90 --branches 85 -- node --test",
    lint: "eslint .",
    "format:check": "prettier --check .",
  },
  workspaces: ["packages/*"],
};
fs.writeFileSync(path.join(dir, "package.json"), JSON.stringify(pkg, null, 2));
const read = JSON.parse(fs.readFileSync(path.join(dir, "package.json"), "utf8"));
assert.equal(read.type, "commonjs");
assert.equal(read.scripts.test.includes("node --test"), true);
assert.equal(read.engines.node, ">=22");
assert.equal(Array.isArray(read.workspaces), true);

// exports blocks deep import — illustrate the shape, not enforcement
assert.equal(read.exports["."], "./src/index.js");
fs.rmSync(dir, { recursive: true, force: true });
console.log("package contract ok");

// Anti-pattern: "test": "jest" when you ship stdlib-only
// Your lockfile and CI should run one runner; adding jest + vitest + mocha triples flake surface
console.log("pkg ok");
```

**Mentor note** — in PR review, a `scripts` change that adds a new runner must delete the old one. Two runners in one repo means two mocks and two coverage maps.

### 3) **CI gates — `node --test` + `c8 --check-coverage` + `eslint` + `prettier --check` as the four-gate pipeline and why `npm ci` beats `npm install` in CI**

**Definition** — the four gates run in order on every PR: (1) `npm ci` — clean install from `package-lock.json`; (2) `eslint .` — logic lint; (3) `prettier --check .` — format; (4) `npm test` / `c8 --check-coverage` — tests + branch gate. Fail fast: lint/format before tests so a whitespace error doesn't waste a 60 s test run.

**Modern guidance** — GitHub Actions (or any CI) shape:

```yaml
# .github/workflows/ci.yml — four gates, Node 22 + 24 matrix
# name: ci
# on: [push, pull_request]
# jobs:
#   check:
#     strategy: { matrix: { node: [22, 24] } }
#     runs-on: ubuntu-latest
#     steps:
#       - uses: actions/checkout@v4
#       - uses: actions/setup-node@v4
#         with: { node-version: "${{ matrix.node }}", cache: "npm" }
#       - run: npm ci
#       - run: npm run lint        # eslint .
#       - run: npm run format:check # prettier --check .
#       - run: npm run coverage    # c8 --check-coverage -- node --test
```

And two invariants:
- **`npm ci` not `npm install`** — `ci` deletes `node_modules` and respects the lockfile byte-for-byte; `install` may patch it and produce a green CI that doesn't reproduce locally.
- **`engine-strict` or `engines` check** — set `npm config set engine-strict true` so Node 20 cannot silently run a Node 22 test that uses `mock.timers`.

```js
const assert = require("node:assert/strict");

// Gate order — lint/format before tests (fail fast)
const gates = ["npm ci", "eslint .", "prettier --check .", "c8 --check-coverage -- node --test"];
assert.equal(gates[0], "npm ci");
assert.equal(gates[1].includes("eslint"), true);
assert.equal(gates[3].includes("c8"), true);

// npm ci vs npm install — lockfile identity
const fakeLock = { name: "x", version: "1.0.0", lockfileVersion: 3 };
const fakePkg = { name: "x", version: "1.0.0" };
assert.equal(typeof fakeLock.lockfileVersion, "number");
assert.equal(fakePkg.version, "1.0.0");

// engines gate — don't run Node 22 tests on Node 20
const nodeMajor = Number(process.versions.node.split(".")[0]);
assert.equal(nodeMajor >= 18, true); // runner requires 18+
console.log(`CI gates ok on Node ${process.versions.node}`);
```

**Common confusion** — " `npm install` in CI is fine." It isn't — it mutates the lockfile and can introduce a new transitive dep that passes CI but breaks the next `npm ci` locally. `npm ci` is the determinism gate, just like a clock seam for tests.
