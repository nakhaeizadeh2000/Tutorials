## 2.2. node:assert strict deepStrictEqual throws rejects and assertion ergonomics

### 1) **`assert/strict` vs `assert` — strict poisoning of `==` and why `assert/strict` is the stdlib contract**

**Definition** — `node:assert` is the stdlib assertion module. `node:assert/strict` is the *strict* façade that maps every `equal`/`deepEqual` to its `Strict` variant (`strictEqual`/`deepStrictEqual`) using `===`/`Object.is`-like semantics instead of `==` and loose deep comparison. Since Node 9, new code should import from `node:assert/strict`; the loose façade exists only for legacy.

**What problem it solves / history** — `assert.equal(1, "1")` with loose `==` passes (`1 == "1"` true per [Values 2.2](<../../../03 Values Types and Coercion/sections/2. The conversion algorithms/2.2. ToString and ToNumber the exact conversion tables.md>)), hiding coercion bugs. `assert/strict` surfaces them: `assert.strictEqual(1, "1")` correctly fails, and `deepStrictEqual` checks `NaN`, `-0`, `Date` millis, `Buffer` bytes, not stringified coercion.

**Modern guidance** — always `const assert = require("node:assert/strict")` (or `import assert from "node:assert/strict"` in ESM). Prefer `assert.equal` (which is strict in `/strict`) and `assert.deepStrictEqual` for objects/arrays/Maps/Sets. Avoid `assert.deepEqual` in new code — it is loose and will be surprising on `NaN`.

```js
const strict = require("node:assert/strict");
const legacy = require("node:assert");

// Strict: 1 !== "1" — catches coercion
strict.throws(() => strict.equal(1, "1"), { name: "AssertionError" });

// Loose: passes with == — hides the bug (do not use)
legacy.equal(1, "1"); // would not throw — legacy footgun

// deepStrictEqual vs deepEqual: NaN and -0
strict.throws(() => strict.deepStrictEqual({ a: NaN }, { a: 0 }), /NaN/);
strict.deepStrictEqual({ a: NaN }, { a: NaN }); // strict knows NaN equals NaN at the leaf
// -0 vs 0: strict distinguishes via Object.is semantics
strict.throws(() => strict.deepStrictEqual({ a: -0 }, { a: 0 }));
legacy.deepEqual({ a: -0 }, { a: 0 }); // loose treats -0 and 0 as equal — surprising

// Buffer and Date are compared by value, not reference
strict.deepStrictEqual(Buffer.from("hi"), Buffer.from("hi"));
strict.deepStrictEqual(new Date("2026-01-01T00:00:00.000Z"), new Date("2026-01-01T00:00:00.000Z"));
console.log("assert/strict ok");
```

**Common confusion** — " `assert.equal` is loose." In `node:assert/strict`, `assert.equal` *is* `strictEqual` (the façade rewires it). In `node:assert`, `assert.equal` is loose. Always check the import path, not the method name, during review.

### 2) **The stdlib assertion palette — `ok` / `equal` / `deepStrictEqual` / `throws` / `rejects` / `match` / `doesNotThrow` and their async twins**

**Definition** — the palette: `ok(value)` — truthy; `equal`/`deepStrictEqual` — value vs structural equality; `throws(fn, expected)` — sync throws matching `expected`; `rejects(promise, expected)` — async rejection; `match(str, regex)` — `regex.test(str)`; `doesNotThrow`/`doesNotReject` — negative guards. Each async variant has `*` alias (`assert.rejects` vs `assert.throws` for promises).

**Modern guidance** — choose by *signal*:
- pure value → `equal` / `deepStrictEqual`
- error type + message → `throws(() => fn(), { name: "TypeError", message: /int/ })` (see [Error 1.1](<../../../15 Error Handling and Debugging/sections/1. Error taxonomy/1.1. Built-in Error types and when engines throw them.md>))
- promise rejection → `await assert.rejects(promise, { name: "RangeError" })`
- string pattern → `match`
- negative → `doesNotThrow` (avoid `assert.doesNotThrow(asyncFn)` — it doesn't await; use `await assert.doesNotReject`)

```js
const assert = require("node:assert/strict");

function parseQty(s) {
  const n = Number(s);
  if (Number.isNaN(n)) throw new TypeError("qty NaN");
  if (!Number.isInteger(n)) throw new RangeError("qty int");
  return n;
}

// ok / equal / deepStrictEqual
assert.ok(parseQty("3") === 3);
assert.equal(parseQty("3"), 3);
assert.deepStrictEqual({ a: [1, 2] }, { a: [1, 2] });

// throws — shape is { name, message?, cause?, code? }
assert.throws(() => parseQty("3.5"), { name: "RangeError", message: /int/ });
assert.throws(() => parseQty("hi"), { name: "TypeError" });
assert.doesNotThrow(() => parseQty("4"));

// rejects — must await
async function fetchQty(q) {
  if (q < 0) throw new RangeError("neg");
  return q;
}
(async () => {
  await assert.rejects(fetchQty(-1), { name: "RangeError" });
  await assert.doesNotReject(fetchQty(2));
  console.log("palette ok");
})();

// match — string vs regex
assert.match("Error: qty NaN at line 3", /qty NaN/);
```

**Common confusion** — "`assert.throws` works for promises." It doesn't. `throws` only observes *sync* `throw`. A `Promise` that rejects will pass `throws` silently; use `await assert.rejects(asyncFn())` or `await assert.rejects(fetchQty(-1))`.

### 3) **Messages and diffs — when an assertion prints a useful diff vs `false == true`**

**Definition** — when an assertion fails, Node prints an `AssertionError` with `actual`, `expected`, `operator`, and for `deepStrictEqual` a colorized diff (Node 20+ pretty diff). A bare `assert.ok(x === y)` with no message yields `false == true`; a `deepStrictEqual` with two objects yields a line-by-line diff pointing to the mismatched leaf.

**Modern guidance** — two rules:
1. **Prefer structural assertions** (`deepStrictEqual`, `equal`) over `ok(a === b)` — the runner can diff `actual` vs `expected` automatically.
2. **Add a message only for branch context** (`assert.equal(got.valid, true, "when id is exactly 3 chars")`) so filtering and TAP output tell you which `when` failed without reading the diff.

```js
const assert = require("node:assert/strict");

// Structural assertion gives a diff on failure (illustrated via try/catch)
try {
  assert.deepStrictEqual({ id: "a", qty: 3, tags: ["hi"] }, { id: "a", qty: 4, tags: ["hi"] });
} catch (e) {
  // Node 20+ prints: + actual - expected with the mismatched leaf highlighted
  assert.equal(e instanceof assert.AssertionError, true);
  assert.equal(e.actual.qty, 3);
  assert.equal(e.expected.qty, 4);
  assert.equal(typeof e.message, "string");
}

// Bare ok hides the diff — anti-pattern
try {
  const got = { id: "a", qty: 3 };
  const want = { id: "a", qty: 4 };
  assert.ok(got.qty === want.qty); // on fail: "The expression evaluated to a falsy value: ..."
} catch (e) {
  assert.equal(e.name, "AssertionError");
}

// Good: message names the scenario, structural assertion provides the diff
function clamp(n, lo, hi) { return Math.min(Math.max(n, lo), hi); }
assert.equal(clamp(-2, 0, 10), 0, "when n < lo then lo");
console.log("messages and diffs ok");

// Mentor tip: snapshot a failing diff once, keep it in the PR — the diff is the review.
```

**Performance note** — `deepStrictEqual` diffs walk the graph; on 10 k-element arrays the diff string is large. Gate large-object comparison behind a cheap `assert.equal(arr.length, want.length)` first so the fast failure avoids building a megabyte diff in hot loops — see [Performance 3.2](<../../../19 Performance and JIT Mindset/sections/3. Measuring performance correctly/3.2. Microbenchmark traps warmup dead code and variance.md>).

**Mentor note** — in review, flag `assert.ok(a === b)` as a diff ergonomics miss; require `equal`/`deepStrictEqual`. Require that every `throws`/`rejects` carries `{ name, message }` — bare `throws(fn)` passes even when the wrong subtype throws, hiding a [Type vs Range](<../../../15 Error Handling and Debugging/sections/1. Error taxonomy/1.1. Built-in Error types and when engines throw them.md>) bug.
