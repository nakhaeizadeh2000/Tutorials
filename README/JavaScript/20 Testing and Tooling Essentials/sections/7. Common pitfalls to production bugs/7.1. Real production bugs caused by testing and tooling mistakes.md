## 7.1. Real production bugs caused by testing and tooling mistakes

### 1) **Unawaited `Promise.all` fan-out that swallows rejections — CI green, prod crash on the third shard**

**Incident** — a service mapped `ids.map(async id => fetchUser(id))` and tested it by *calling* the mapper inside a test without `await Promise.all`. The test passed because the runner finished before any rejection settled. In prod, the third shard rejected with `TypeError` and the outer `Promise` leaked an `unhandledRejection` that crashed Node with `--unhandled-rejections=strict`.

```js
const assert = require("node:assert/strict");

async function fetchUser(id) { if (id === "bad") throw new TypeError("bad id"); return { id }; }

// Bad: unawaited fan-out — test "passes" but rejection is orphaned
async function badBatch(ids) {
  const ps = ids.map(async id => fetchUser(id)); // no await, no return
  // test wrote: badBatch(["a","bad","c"]); // "passes"
  return ps; // caller forgot Promise.all
}

// Good: await the fan-out and assert the rejection
async function goodBatch(ids) {
  return Promise.all(ids.map(id => fetchUser(id)));
}

(async () => {
  // Good test — await + assert.rejects
  await assert.rejects(goodBatch(["a","bad"]), { name: "TypeError" });
  assert.deepEqual(await goodBatch(["a","b"]), [{id:"a"},{id:"b"}]);
  // Bad test would need to swallow orphans to stay green — hide the bug
  const orphans = await badBatch(["a","b"]); // 2 promises
  // without Promise.all, the test suite would need PS.catch — anti-pattern
  orphans.forEach(p => p.catch(()=>{})); // don't ship — masks the bug
  console.log("unawaited fan-out demo ok");
})();
```

**Lesson** — every `map(async` must be `await Promise.all(map(async…))` and the test must `await assert.rejects` the aggregate. Search `\.map\(async` and require the `await` in review — see [4.1](../4. Async timing and flake control/4.1. Testing promises async await event emitters and rejections.md).

### 2) **Mock that leaks across tests (`mock.method` without `t.after` restore) — second test passes alone, fails in suite**

**Incident** — a test mocked `api.fetchUser` to return `{ mocked: true }` via `mock.method(api,"fetchUser", …)` without `t.after(() => mock.restoreAll())`. The next test, which expected the real implementation, ran after and got the mock, failing only when the two tests ran together — a classic order-dependent leak. Developers "fixed" it by reordering tests until CI flaked again.

```js
const assert = require("node:assert/strict");
const { mock } = require("node:test");

const api = { fetchUser(id){ return { id, source: "real" }; } };

// Simulate a suite without restore — second test sees the mock
(function suiteWithoutRestore(){
  mock.method(api, "fetchUser", () => ({ mocked: true }));
  assert.deepEqual(api.fetchUser("a"), { mocked: true }); // first test passes
  // missing: mock.restoreAll() — leak
  assert.deepEqual(api.fetchUser("b"), { mocked: true }); // second test "passes" on mock, would fail on real
  mock.restoreAll();
  assert.equal(api.fetchUser("c").source, "real"); // after manual restore, real is back
  console.log("leaked mock demo — second test saw mock");
})();

// Correct: t.after restore — each test is isolated
(function suiteWithRestore(){
  // test 1
  {
    const t = { cleanups: [], after(fn){this.cleanups.push(fn);}, flush(){for(const f of this.cleanups)f();}};
    mock.method(api, "fetchUser", () => ({ mocked: true }));
    t.after(() => mock.restoreAll());
    assert.deepEqual(api.fetchUser("x"), { mocked: true });
    t.flush();
  }
  // test 2 — now sees real, not mock
  assert.equal(api.fetchUser("y").source, "real");
  console.log("restored mock demo ok");
})();
```

**Lesson** — every `mock.method`/`mock.timers.enable` must be paired with `t.after(() => mock.restoreAll())` or `afterEach`. Lint with `mock\.method.*\n.*(?!t\.after)` in review — see [3.2](../3. Mocks and test doubles/3.2. Mocking in Node mock.fn mock.method timers fetch and modules.md).

### 3) **Snapshot that encodes time or id and flips every run — PRs drown in `--update` churn**

**Incident** — a snapshot captured `{ at: Date.now(), id: crypto.randomUUID() }`. Every `npm test` run produced a new snapshot, so every PR showed a 100-line diff that engineers auto-approved with `--update`. A real regression (wrong `total` field) hid in the noise and shipped.

```js
const assert = require("node:assert/strict");

// Bad: snapshot captures wall clock and random — never stable
function badReport(){ return { at: Date.now(), id: Math.random(), total: 42 }; }
const s1 = badReport(), s2 = badReport();
assert.equal(typeof s1.at, "number"); // wall clock — different runs produce different snapshots, always churns
assert.equal(typeof s1.id, "number");

// Good: snapshot on stable serialization with frozen clock and deterministic id
function goodReport(clock, idOf){ return { at: clock.now(), id: idOf(), total: 42 }; }
const frozen = { now: () => 1_700_000_000_000 };
let seq = 0; const seqId = () => `id-${++seq}`;
assert.deepEqual(goodReport(frozen, seqId), { at: 1_700_000_000_000, id: "id-1", total: 42 });
seq = 0; assert.deepEqual(goodReport(frozen, seqId), { at: 1_700_000_000_000, id: "id-1", total: 42 }); // stable

// Narrow the snapshot to the branch you care about — not the whole payload
function buildOrder(id, qty){ return { id, qty, total: qty * 9, meta: { v: 1, at: frozen.now() } }; }
const order = buildOrder("a", 3);
assert.deepEqual({ total: order.total, qty: order.qty }, { total: 27, qty: 3 }); // stable subset
console.log("snapshot churn demo ok");
```

**Lesson** — freeze the clock and seed the id, and narrow the snapshot to the *contract* fields. A snapshot diff larger than the code diff is a review red flag — see [2.3](../2. Node test runner and assertions/2.3. Matchers snapshots and assertion libraries expect style and custom matchers.md).

### 4) **Coverage gate on line % that hides an uncovered `catch` — error path never exercised**

**Incident** — a repo gated `lines 90` but not `branches`. A `try { JSON.parse } catch (e) { throw new SyntaxError(..., { cause: e }) }` had 100 % line coverage (the `catch` line was *present* but never *entered*), so the `cause` wiring was broken for months. On-call saw `SyntaxError: bad json` with no `cause` chain and mis-triaged for an hour.

```js
const assert = require("node:assert/strict");

function load(json) {
  try { return JSON.parse(json); } catch (e) { throw new SyntaxError("bad json", { cause: e }); }
}

// Bad gate: only lines — happy path covers every line except the catch body
assert.deepEqual(load('{"a":1}'), { a: 1 }); // lines "covered"

// Good gate: branches — requires catch branch
assert.throws(() => load("bad"), (e) => {
  assert.equal(e.name, "SyntaxError");
  assert.equal(e.cause instanceof SyntaxError, true);
  return true;
});
console.log("catch branch demo ok");

// CI gate that would have caught it (see 5.1):
// c8 --check-coverage --lines 90 --branches 85 -- node --test
// without the second test, branches ~50 % — fails the gate
```

**Lesson** — gate `branches 85` (or at least `branches` alongside `lines`) and require `assert.throws` with `{ cause }` for every `catch` that wraps `cause` — see [5.1](../5. Quality gates and tooling/5.1. Coverage with c8 v8 line branch function thresholds and lies.md) and [Error 3.1](<../../../15 Error Handling and Debugging/sections/3. Defensive patterns/3.1. Cause wrapping context preservation and suppressed errors.md>).

### 5) **ESLint `eqeqeq` off + `== null` coercion gate missed — data bug ships behind a passing suite**

**Incident** — a validation `if (value == null) return "anonymous"` was intentionally loose (`null` or `undefined` both count as anonymous per [Values 3.1](<../../../03 Values Types and Coercion/sections/3. Coercion at work/3.1. Loose equality the abstract equality algorithm walkthrough.md>)), but a teammate refactored it to `if (value == 0)` thinking `==` was universally "truthy check." With `eqeqeq` off, lint didn't flag it, tests used `0` as a valid id (no `null` fixture), and prod treated `0` as anonymous, dropping a paying customer `id: 0`.

```js
const assert = require("node:assert/strict");

// Intentional loose — documented (allowed by eqeqeq with "smart" exception for == null)
function labelOrAnonymous(v) {
  // eslint-disable-next-line eqeqeq -- == null is the idiomatic nullish check (null or undefined)
  if (v == null) return "anonymous";
  return String(v);
}
assert.equal(labelOrAnonymous(null), "anonymous");
assert.equal(labelOrAnonymous(undefined), "anonymous");
assert.equal(labelOrAnonymous(0), "0"); // 0 is a real id — must not be "anonymous"
assert.equal(labelOrAnonymous(""), ""); // empty string is not nullish

// Accidental loose — eqeqeq would have flagged this
function badZeroCheck(v) {
  // with eqeqeq off, this passes lint but is a coercion bug: 0 == "" and "" == 0 are true via ToNumber
  // eslint would flag: Unexpected use of ==.
  return v == 0 ? "zero" : "not zero";
}
assert.equal(badZeroCheck(0), "zero");
assert.equal(badZeroCheck("0"), "zero"); // coercion bug — "0" string is not number 0
assert.equal(badZeroCheck(""), "zero");  // "" == 0 is true — data bug

// Good: strict equality, explicit intent
function isZero(v){ return v === 0; }
assert.equal(isZero(0), true);
assert.equal(isZero("0"), false);
console.log("eqeqeq demo ok");
```

**Lesson** — keep `eqeqeq: ["error","always"]` on, allow `== null` only with an `eslint-disable` comment that states intent. And add a `null`/`0`/`""` fixture per [Values 7.1](<../../../03 Values Types and Coercion/sections/7. Common pitfalls to production bugs/7.1. Real production bugs caused by coercion.md) idiom — see [5.2](../5. Quality gates and tooling/5.2. Linting formatting static analysis ESLint Prettier type checks npm scripts workspaces and CI gates.md).
