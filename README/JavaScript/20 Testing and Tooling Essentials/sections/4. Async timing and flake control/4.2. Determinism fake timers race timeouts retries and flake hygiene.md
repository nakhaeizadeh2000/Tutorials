## 4.2. Determinism fake timers race timeouts retries and flake hygiene

### 1) **Deterministic time — `mock.timers` replaces `Date`/`setTimeout`/`setInterval` and why wall-clock `Date.now` must go through a `clock` seam**

**Definition** — wall-clock time (`Date.now()`, `new Date()`, `setTimeout`) is non-deterministic across runs and CI hosts. `mock.timers.enable({ apis: ["setTimeout","Date"], now: T0 })` (Node 20+, experimental) replaces those globals with virtual versions whose `now` and timer queue advance only when you call `mock.timers.tick(ms)` or `runAll()`. The cheaper stable alternative is a *clock seam*: the unit takes `clock = { now: () => Date.now() }` and tests inject a frozen clock (see [1.2](../1. Testing foundations/1.2. Anatomy of a test AAA naming isolation and determinism.md)).

**What problem it solves** — without determinism, a test that asserts `deadline = Date.now() + 30_000` fails when `Date.now()` moves between Arrange and Assert, and a debounced function needs `await sleep(300)` and still flakes on slow CI.

**Modern guidance** — two tiers:
- Cheap: clock seam — works on every Node, zero experimental surface. Good for `isExpired`, `deadline`, `age`.
- Full: `mock.timers` for `setTimeout`/`setInterval` chains and `Date` co-moving. Enable at test start, `tick` to fire, `(disable ?? reset)` at end via `t.after`. Never leave fake timers enabled across tests.

```js
const assert = require("node:assert/strict");
const { mock } = require("node:test");

// Tier 1: clock seam — stable everywhere
function isExpired(expiryMs, clock = { now: () => Date.now() }) { return expiryMs < clock.now(); }
{
  const frozen = { now: () => 1_700_000_000_000 };
  assert.equal(isExpired(1_700_000_000_001, frozen), false);
  assert.equal(isExpired(1_699_999_999_999, frozen), true);
}

// Tier 2: mock.timers for setTimeout chains — deterministic, no sleep
{
  mock.timers.enable({ apis: ["setTimeout", "setInterval", "Date"], now: 1_000 });
  let calls = 0;
  setTimeout(() => calls++, 1_000);
  const id = setInterval(() => calls++, 500);
  mock.timers.tick(1_500); // fires timeout@1000 + interval@500 + interval@1000 + interval@1500? actually 1500 fires interval at 500,1000,1500
  // Tick 1500: interval fires at 500,1000,1500 (3) + timeout at 1000 (1) = 4 total? Verify by counting.
  // After tick 1500, calls should be 4 (timeout 1 + intervals 3). We assert >=3 to stay robust.
  assert.equal(calls >= 3, true);
  clearInterval(id);
  (mock.timers.disable ?? mock.timers.reset).call(mock.timers);
  assert.equal(typeof setTimeout, "function");
}

// Bad: sleep in a test — slow and still flaky (don't ship)
// await new Promise(r => setTimeout(r, 300)); // replaced by mock.timers.tick(300)
console.log("deterministic time ok");
```

**Common confusion** — "`mock.timers` only fakes `setTimeout`." When you pass `apis: ["Date"]` it also fakes `Date.now()` and `new Date()`; without `"Date"` the two clocks desync and tests that mix `Date.now()` deadline math with `setTimeout` see real time vs virtual time divergence.

### 2) **`race`/`any`/`setTimeout` hygiene — timeout helpers with `AbortSignal` and why ad-hoc `sleep(100)` is a flake**

**Definition** — async tests often need "resolve `p` but fail if it takes > `ms`." The robust pattern is `await Promise.race([p, timeout(ms, signal)])` where `timeout` rejects with `AbortError` after `ms`, or `once(emitter, "event", { signal: AbortSignal.timeout(ms) })`. Ad-hoc `await sleep(100); assert.equal(done, true)` assumes the scheduler fired within 100 ms — on CI it may not.

**Modern guidance** — use `AbortSignal.timeout(ms)` (Node 18+) as the timeout primitive; it integrates with `fetch`, `once`, and promise combinators without a leaked `setTimeout` handle.

```js
const assert = require("node:assert/strict");
const { once, EventEmitter } = require("node:events");

function sleep(ms, signal) {
  return new Promise((resolve, reject) => {
    const id = setTimeout(resolve, ms);
    if (signal) signal.addEventListener("abort", () => { clearTimeout(id); reject(signal.reason); }, { once: true });
  });
}
function withTimeout(promise, ms) {
  const ac = new AbortController();
  const t = setTimeout(() => ac.abort(new Error(`timeout after ${ms}ms`)), ms);
  const raced = Promise.race([
    promise.finally(() => clearTimeout(t)),
    new Promise((_, rej) => ac.signal.addEventListener("abort", () => rej(ac.signal.reason), { once: true }))
  ]);
  return raced;
}

// Good: raced promise respects timeout via AbortSignal
(async () => {
  const fast = Promise.resolve(42);
  assert.equal(await withTimeout(fast, 50), 42);
  const never = new Promise(() => {});
  await assert.rejects(withTimeout(never, 10), /timeout/);
  console.log("withTimeout ok");
})();

// Good: AbortSignal.timeout for emitter once
(async () => {
  const ee = new EventEmitter();
  setTimeout(() => ee.emit("ready", 1), 5);
  const [v] = await once(ee, "ready", { signal: AbortSignal.timeout(50) });
  assert.equal(v, 1);
  console.log("once+timeout ok");
})();

// Good: AbortSignal.timeout for fetch-style test seam
async function fetchWithTimeout(url, ms, fetcher = globalThis.fetch) {
  // fake fetcher for demo — real would be global fetch
  const fake = async (u, { signal }) => {
    await sleep(5, signal);
    return { ok: true, url: String(u) };
  };
  const f = fetcher && fetcher !== globalThis.fetch ? fetcher : fake;
  return f(url, { signal: AbortSignal.timeout(ms) });
}
(async () => {
  const res = await fetchWithTimeout("https://example.com", 50);
  assert.equal(res.ok, true);
  console.log("fetch timeout ok");
})();

console.log("race hygiene ok");
```

**Performance note** — each `setTimeout` in a test holds a handle that keeps the event loop alive. A suite that creates 200 unawaited `setTimeout` handles without `mock.timers` stays alive for wall time (`sleep`) or hangs on `runAll`. `AbortSignal` + `clearTimeout` on settle avoids the leak — see [Memory 3.1](<../../../18 Memory Management and GC/sections/3. Lifetimes what stays alive/3.1. Closures timers listeners maps and the lifetime of a graph.md>).

### 3) **Retries are not fixes — flaky tests get quarantined, not retried, until the root `await`/cleanup leak is closed**

**Definition** — a *flake* is a test that passes/fails non-deterministically (`setTimeout` race, leaked global `Map`, unawaited `Promise`, fake-timer not reset). Retrying (`vitest --retry=3` / `jest.retryTimes`) masks the flake and lets it rot while CI minutes burn.

**Modern guidance** — three-stage hygiene:
1. **Quarantine** — move the flake to a `describe.skip` bucket or tag filter so `main` stays green, but keep it visible.
2. **Root-cause** — search for the four canonical flakes: unawaited `Promise` ([4.1](./4.1. Testing promises async await event emitters and rejections.md)), wall-clock `Date.now` ([1.2](../1. Testing foundations/1.2. Anatomy of a test AAA naming isolation and determinism.md)), real `setTimeout` without `mock.timers` (this leaf), and shared mutable (`let db` leak).
3. **Fix structurally** — `await` + `t.after` + clock seam + `mock.timers` + per-test fresh `Map`. Add a deterministic replay (seeded RNG) and a CI lint `grep -r "setTimeout" test/` to flag new sleeps.

```js
const assert = require("node:assert/strict");

// Catalogue the four flakes so reviewers can grep for them
const flakeGrep = [
  "setTimeout(",                 // real timers in a test — use mock.timers
  "Date.now()",                 // wall clock — use clock seam
  "Math.random()",              // unseeded RNG — use seeded
  "let db = new Map()",         // shared mutable at file top
  ".map(async",                 // unawaited fan-out — await Promise.all
];

// Quarantine pattern: skip with a TODO that links the root-cause ticket
function quarantine(name, reason) { return `skip: ${name} — ${reason} — re-enable after await/clock fix`; }
assert.equal(quarantine("fetch race", "sleep(100) → mock.timers").startsWith("skip:"), true);

// Fix pattern: same behavior, deterministic (clock seam + await)
function isExpired(expiryMs, clock) { return expiryMs < clock.now(); }
const frozen = { now: () => 1_700_000_000_000 };
assert.equal(isExpired(1_699_000_000_000, frozen), true);

// Good: CI gate that fails on flakes rather than retrying them
// In package.json: "test": "node --test --test-reporter=spec --test-reporter-destination=-"
// plus a lint step: eslint --rule 'no-restricted-syntax: [error, { selector: \"CallExpression[callee.name=setTimeout]\", message: \"use mock.timers\" }]'
// Prettier's --check never retries a format fix — apply the same discipline to tests.
console.log("flake hygiene ok");
```

**Mentor note** — in PR review, a retry addition must be accompanied by a quarantine note and a ticket number. The senior signal is distinguishing "this flake is structural (await/clock/leak) vs stochastic (true race in prod code)" — the former is always fixable without `sleep`.
