## 6.1. Module checklist reflex rules mentors screen for

### 1) **Three detections before any module claim — ESM vs CJS `type`/extension and resolved specifier map key**

**Definition** — before answering "what does `import` do?" detect: (1) *Which loader?* ESM (`type:module` + `.js` or `.mjs`) vs CJS (`type:commonjs` + `.js` or `.cjs`); (2) *Which wrapper/cache?* ESM module map (live bindings, `import.meta.url`) vs CJS wrapper (`module.exports`, `require.cache`, `__dirname`); (3) *Which resolved key?* absolute file URL / `exports` map entry for bare — not the literal string you typed. These three answer which semantics apply; skipping them is the root of dual-package and extension bugs.

```js
// Detection demo — no FS writes, just mapping logic:
const pkgTypes = { "commonjs": ".js→CJS", "module": ".js→ESM" };
console.log(JSON.stringify(pkgTypes));
console.log("Probe: package.json type + extension → loader");
console.log("  no type + .js → CJS");
console.log("  type:module + .js → ESM");
console.log("  .mjs → ESM always; .cjs → CJS always");
console.log("  bare 'pkg' → exports map condition import vs require (see 5.3)");

// Cache key difference — ESM map vs require.cache:
console.log("ESM map key: resolved specifier URL (file:///proj/lib.js or https://cdn/pkg.js)");
console.log("CJS key: resolved filename via require.resolve — similar but sync and filename-only, no URL");

// Verification: type detection via extension in Node:
console.log("Rule: if file has `import` and is .js under type:commonjs → SyntaxError at parse, not switching loader");
```

### 2) **The five reflexes — static structure single evaluation live vs object-share default binding trap `with` vs `assert`**

| Reflex | Trigger | Correct action |
|---|---|---|
| **Static structure** | `if`/`function`/`try` contains `import`/`export` | Hoist to top-level; use `await import()` for conditional/computed (1.2,4.1) |
| **Single evaluation** | Expecting re-`import` to re-run top-level | Module evaluates once; export `reset()` function instead (3.1) |
| **Live vs object-share** | `import {cfg} from` + `cfg.x=` vs `cfg=` | `export let cfg` live binding vs `cfg` object identity sharing are two layers — distinguish (2.2) |
| **Default binding trap** | `export default obj; obj = newObj` + importer held old `obj` | Don't rebind `default` holding object; mutate or use named export (2.2,7.1) |
| **`with` vs `assert`** | `assert {type:"json"}` | Use `with {type:"json"}` (ES2025); `assert` deprecated (4.2) |

```js
// Reflex checklist — runnable as mental gate, not branch logic:
const checklist = [
  "1. Is import/export static and top-level?",
  "2. Is evaluation once (no re-init via re-import)?",
  "3. Is imported binding live (getter) vs object handle (shared ref)?",
  "4. Is default rebind avoided?",
  "5. Is JSON with {type:\"json\"} via with, not assert?",
];
console.log(checklist.join("\n"));

// BAD vs GOOD quick table as code comments:
console.log("BAD: if(cond) import {a} from './a.js';");
console.log("GOOD: if(cond) { const {a}=await import('./a.js'); }");
console.log("BAD: import {cfg} from './cfg.js'; cfg = {};");
console.log("GOOD: import {cfg} from './cfg.js'; cfg.x = 1; // mutate, not rebind (or export setter)");
console.log("BAD: import data from './c.json' assert {type:'json'}");
console.log("GOOD: import data from './c.json' with {type:'json'}");
```

### 4) **Common confusion**

- "`package.json` type doesn't matter if I use `.mjs/.cjs`" — `type` still dictates bare `.js` — mixed `.js` without `type` is the most common surprise (see 1.1).
- "`sideEffects:false` makes tree-shaking automatic" — bundlers still evaluate modules with `import "./polyfill.js"` side effects; `sideEffects:false` only tells them named imports of pure modules can be dropped.

### 5) **Performance note**

Checklist keeps link-time cost low: every static `import` is one resolver entry; every barrel hop is extra link walk. Keeping relative specifiers explicit (with `.js`) saves resolver from filesystem `stat` probes (CJS fallback chain) — measurable in large ESM graphs.

### 6) **Mentor note**

Use the five-reflex table as gate at PR review: any diff touching `import`/`export` gets the checklist. Juniors who miss `with` vs `assert` or who `cfg = {}` against an import need the live-binding deep dive (2.2) before approval.
