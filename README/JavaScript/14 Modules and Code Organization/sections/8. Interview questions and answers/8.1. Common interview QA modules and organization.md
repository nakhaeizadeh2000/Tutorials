## 8.1. Common interview Q&A modules and organization

### 1) **Twelve classics with mechanism-level answers**

**Q1. Live binding or copy? `export let x = 1; x++; what does `import {x}` see?`**
A: Live getter. After `x++` importer's `x` becomes 2. Copy folklore fails. Snapshot requires `const local = x`.

**Q2. Can you `x = 2` inside the importer when `x` is `import {x}`?**
A: No — `TypeError: Assignment to constant variable.` Importer views are read-only; exporter may reassign.

**Q3. `export default obj; obj = {}` — does importer see new object?**
A: Live `default` binding does see new identity when read via `import def from`; but an importer that did `const local = def` at earlier moment holds stale old object. Avoid rebinding `default` object — mutate or use named export.

**Q4. `export * from "./m.js"` — does `default` re-export?**
A: No — `export *` skips `default`. Use `export {default} from` or `export * as ns from`.

**Q5. Does `export { x } from "./y.js"` create a local `x`?**
A: No — re-export without local binding. `x` not in scope in re-exporter; use `import {x} from` then `export {x}` if you need local.

**Q6. Evaluation order of `app → b,c → d` diamond where d shared?**
A: Depth-first post-order with dedup: `d, b, c, app` — `d` once, leaves first (see [3.1](<../3. Evaluation and circular dependencies/3.1. Evaluation order single evaluation and hoisting.md>)). `d` side effects run once.

**Q7. Cycle `a→b→a` where `b` does `console.log(x)` at top-level and `a` does `export let x = 1` — what happens?**
A: `ReferenceError: Cannot access 'x' before initialization` (TDZ across cycle — see [3.2](<../3. Evaluation and circular dependencies/3.2. Circular dependencies and temporal dead zone across cycles.md>)). `export function x(){}` would not throw (hoisted).

**Q8. Why `if(cond) import {a} from "./a.js"` SyntaxError?**
A: `import` static, top-level only, literal specifier. Use `if(cond) { const {a}=await import("./a.js"); }` (see [1.2](<../1. Module foundations and static imports/1.2. Static import forms and restrictions.md>)).

**Q9. `import()` return?**
A: Promise resolving to module namespace object (`{default, ...}`) — shared map, concurrent `import(sameURL)` coalesces, failures reject.

**Q10. `require("./esm.mjs")` in CJS?**
A: `ERR_REQUIRE_ESM`. Can't synchronously require ESM (TLA async). Use `await import("./esm.mjs")` inside CJS.

**Q11. Dual package duplicate singleton—symptom?**
A: `require("pkg").state !== (await import("pkg")).state` when package ships separate `lib/cjs` vs `lib/esm` with root `let state`. Tests using one loader pass; mixed prod splits.

**Q12. JSON module syntax?**
A: `import data from "./c.json" with {type:"json"}` (ES2025 `with`, not `assert`). Dynamic: `await import("./c.json", {with:{type:"json"}})`. Extension required.

### 2) **What interviewers actually probe for**

Senior interviewers narrate the *mechanism* — "linking creates live getters before evaluation, then depth-first post-order evaluates leaves before parents, so cycle reads before init throw TDZ rather than `undefined`" — vs reciting "imports are hoisted." They watch for distinction between *binding live* (imported name getter) and *object-identity live* (held handle), and for correct `with` vs `assert` discipline.

### 3) **Grading guidance**

| Signal | Level | Red flag |
|---|---|---|
| Names the six import forms and two export families correctly | junior | "import works inside if" |
| Distinguishes `export {x} from` vs local binding & `export *` skipping `default` | mid | "`export *` includes default" |
| Explains live getter, importer read-only, and default rebind stale-handle | mid-senior | "`import` makes a copy" or "`cfg = {}` propagates to importer assignment" |
| Predicts cycle TDZ vs function hoist and gives lazy/extract fix | senior | "cycles always work / always require refactor" |
| Diagnoses dual-package singleton split via `exports` conditions and gives `with` vs `assert` migration | senior | "`require` can load ESM sync" or "`assert` is current" |
| Designs checklist (`type`/extension, static hoisting, single evaluation, live vs handle, `with`) and barrel/tree-shake trade-off | expert/mentor | No review gate for `require` in ESM or extension-less relative |
