## 4.1. Dynamic import async loading and code splitting

### 1) **The `import(specifier)` operator — async function-like returns a Promise of the namespace**

**Definition** — `import(specifier)` is an operator (call-like) that accepts any expression for the specifier and returns a *Promise* fulfilling to the Module Namespace Object of the target. It can appear anywhere (inside `if`, functions, loops, `try`). Resolution still uses the host resolver; failure rejects the promise (not a sync throw, except for SyntaxError of malformed `import()` grammar). Success shares the module map — a later `await import("./x.js")` with the same resolved specifier returns the same namespace without re-evaluation (see [3.1](<../3. Evaluation and circular dependencies/3.1. Evaluation order single evaluation and hoisting.md>)).

**What problem it solves / history** — static `import` must be string literals at top level (see [1.2](<../1. Module foundations and static imports/1.2. Static import forms and restrictions.md>)) — impossible to choose a language file by `locale`, or lazily load a heavy chart library only on dashboard. ES2020 added `import()` to bridge conditional/computed loading while keeping static graph analyzable for the rest. Bundlers use it as the *code-splitting* signal: each `import()` target becomes a separate chunk.

**Modern guidance** — use `import()` for every non-static dependency; handle rejection (`catch`) — missing file is a promise rejection, not a crash proportionally easier to recover from than sync `require` throw. For parallel eager preload, issue `import()` without immediately awaiting.

```js
// Basic shape — returns Promise<Namespace>
console.log("import() is an operator, not a global — syntax only inside modules/bundled");
console.log("syntax: await import(\"./math.js\")        // static string");
console.log("syntax: await import(localePath)          // computed");
console.log("syntax: await import(`./lang/${locale}.js`) // template");

// Runnable: simulate via data URL (no file needed) — real Node ESM supports import() of data:
(async () => {
  const ns = await import("data:text/javascript,export const value = 42; export default 5;");
  console.log(ns.value, ns.default); // 42 5 — namespace with named + default

  // Computed specifier — locale-like switch
  const locale = "fr";
  const path = `data:text/javascript,export const greeting = "${locale === "fr" ? "bonjour" : "hello"}";`;
  const mod = await import(path);
  console.log(mod.greeting); // bonjour

  // Failure rejects — catch it
  try {
    await import("data:text/javascript,throw new Error(\"load boom\")");
  } catch (e) {
    console.log(e.message); // load boom — rejected promise, not sync throw
  }

  // Concurrent deduplication — two imports of same specifier share the map
  const url = "data:text/javascript,export const x = 1;";
  const p1 = import(url);
  const p2 = import(url);
  console.log(p1 === p2 ? "same promise?" : "separate promises?"); // separate promises but same pending evaluation
  const [a, b] = await Promise.all([p1, p2]);
  console.log(a === b, a.x); // true 1 — same namespace cached
})();
```

```js
// Conditional heavy dep — load only when needed (dashboard)
async function loadChartIfNeeded(needChart) {
  if (!needChart) return null;
  const { draw } = await import("data:text/javascript,export function draw(){ return \"chart\"; }");
  return draw();
}
loadChartIfNeeded(true).then(console.log); // chart
loadChartIfNeeded(false).then(v => console.log(v)); // null — no import triggered
```

### 2) **Code splitting patterns — route-level lazy conditional heavy dep parallel preload**

**Definition** — *code splitting* is producing multiple output chunks, each `import()` target becoming a lazy chunk. Patterns: (1) **route-level** (`if (route === "/dash") await import("./dash.js")`), (2) **conditional heavy** (PDF/Chart/Monaco on demand), (3) **parallel preload** (`const pMap = import("./map.js"); const pStats = import("./stats.js"); await Promise.all([pMap,pStats])`), (4) **prefetch warm** (`import("./heavy.js").catch(()=>{})` started without await to hide latency, awaited later).

**Bad vs Good:**

```js
// BAD — static import of huge dep paid on every page load
console.log("BAD: import { Monaco } from \"./monaco.js\"; // 3 MB always parsed");

// GOOD — dynamic import shaves initial chunk, loads on demand + cached
console.log("GOOD: const { Monaco } = await import(\"./monaco.js\"); // only when editor opens");

// Runnable: parallel vs sequential import via data URLs
(async () => {
  const start = Date.now();
  // Sequential (await each)
  const a = await import("data:text/javascript,export const v=1;");
  const b = await import("data:text/javascript,export const v=2;");
  console.log("seq", a.v, b.v, Date.now() - start + "ms");

  // Parallel — overlap resolution + evaluate
  const pa = import("data:text/javascript,export const v=1;");
  const pb = import("data:text/javascript,export const v=2;");
  const [va, vb] = await Promise.all([pa, pb]);
  console.log("par", va.v, vb.v);
})();

// Prefetch warm — start early, await later
let early;
early = import("data:text/javascript,export const heavy = \"warming\";");
console.log("started early import, not yet awaited — map entry created");
early.then(m => console.log(m.heavy)); // warming
```

### 3) **Error and caching — failed import rejects catch it successful loads share the module map**

**Definition** — a failing `import()` (missing file, syntax error, network error) rejects the promise — attach `.catch` or `try/catch` inside `async`. There is no retry on second `await import(sameBrokenSpecifier)` unless the host evicts the failed entry — Node caches the rejection so second import also rejects with same reason. Success loads are cached unanimously: after first `await import("./x.js")` finishes, any later static `import` or `import()` for same resolved specifier maps to the same namespace.

```js
(async () => {
  // Catch missing-file rejection — never leave import() bare in prod path
  try {
    await import("data:text/javascript,throw new Error(\"missing chunk\")");
  } catch (e) {
    console.log("caught missing", e.message);
    // Fallback — local stub
    const fallback = { draw: () => "fallback" };
    console.log(fallback.draw()); // fallback
  }

  // Successful namespace identity across callers:
  const url = "data:text/javascript,export let count=0; export function inc(){ return ++count; }";
  const ns1 = await import(url);
  ns1.inc();
  const ns2 = await import(url);
  console.log(ns1 === ns2, ns2.count); // true 1 — shared state, single evaluation (see 3.1)

  // Concurrent imports coalesce evaluation:
  const pA = import("data:text/javascript,export const q=10;");
  const pB = import("data:text/javascript,export const q=10;"); // separate URL string -> different key? (URL exact string)
  // Same exact URL string coalesces; different data URL contents are different keys
  console.log("same URL string => same module map key; different data contents => different key");

  // Retry discipline — log and fallback rather than retry loop
  console.log("For chunk-load failures (network), retry via new URL with ?cachebust or reload; bare retry of same specifier rejects again");
})();
```

### 4) **Common confusion**

- "`import()` is `require` but async" — resolution via host resolver diverges (extension required in Node ESM, bare specifiers need import map in browsers); `require` is sync and returns `module.exports` directly, `import()` is async and returns a namespace object with `default`.
- "`import()` inside a loop creates a new evaluation each iteration" — same resolved specifier maps to same namespace; loop `for (const p of paths) await import(p)` evaluates each unique `p` once.
- "Dynamic `import` is allowed wherever static `import` is" — opposite: `import()` is the *only* import allowed inside blocks/functions/conditions; static `import` is illegal there (SyntaxError).

### 5) **Performance note**

Each distinct specifier performs resolution + fetch + link + evaluate once; subsequent `import()` is map lookup (microseconds). Creating `import(`./lang/${locale}.js`)` per render with varying `locale` pollutes the map with many namespaces — cache by `locale` string separate from module map (your own Map keyed by locale). Bundlers split every `import()` into a chunk — over-splitting (a chunk per tiny utility) multiplies HTTP requests; bundle-time heuristics group chunks by route/entry.

### 6) **Mentor note**

Ask trainees to implement `async function withTimeout(promise, ms){ return Promise.race([promise, timeout(ms)]) }` using `import()` (`import("./heavy.js")` races against `AbortSignal.timeout`). Failure to `catch` the losing promise reveals missing abort/cancel discipline. In review, flag bare `import("./path.js")` without `.catch`/`try` (silent rejection swallowed if caller doesn't await), and flag sequential `await import(a); await import(b);` that should be `Promise.all([import(a), import(b)])` when `a`/`b` independent.
