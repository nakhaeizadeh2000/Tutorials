## 5.1. CommonJS require exports and the module cache

### 1) **The CJS wrapper — every file is `(exports, require, module, __filename, __dirname) => {}`**

**Definition** — when Node treats a file as CommonJS (`type: "commonjs"` or `.cjs`, or bare `.js` without `type: module`), it wraps the source in a function `function(exports, require, module, __filename, __dirname) { /* your code */ }` and calls it. `exports` starts as alias to `module.exports = {}`. `module.exports` is what `require("./file.js")` returns. `module.exports = ...` replaces the export object; `exports.x = ...` mutates the initial one — `exports` alias is *not* magic after `module.exports =`.

**What problem it solves / history** — Node needed modules before ESM existed; wrapping provided per-file scope (no globals), `require` for synchronous local resolution, and `__dirname` for file-relative FS. The alias `exports` was ergonomic shorthand for adding properties without `module.exports.x`. The wrapper remains the reason top-level `var` inside CJS does not leak to `globalThis` and top-level `this === module.exports`.

**Modern guidance** — use `module.exports = { ... }` for a single value or object export; use `exports.foo =` only when augmenting an existing `module.exports` object you do not reassign. Never reassign `exports =` (breaks alias) and never mix `module.exports =` after `exports.x =` without commenting why.

```js
// Wrapper conceptual — what Node actually generates:
// function(exports, require, module, __filename, __dirname) {
//   // your file starts here
//   const localVar = 1; // function-scoped, NOT globalThis
//   exports.add = (a,b)=>a+b;
//   module.exports.extra = 2;
// }

// Runnable: alias trap — exports vs module.exports
function simulateCJS() {
  let module = { exports: {} };
  let exports = module.exports; // alias at start
  exports.a = 1; // mutates module.exports => {a:1}
  console.log("after exports.a", JSON.stringify(module.exports)); // {"a":1}
  module.exports = { b: 2 }; // replace — exports alias now stale
  console.log("after module.exports=", JSON.stringify(module.exports), "exports alias", JSON.stringify(exports)); // {"b":2} {"a":1}
  exports.c = 3; // mutates old alias object — NOT visible via require
  console.log("after exports.c on stale alias", JSON.stringify(module.exports), JSON.stringify(exports)); // {"b":2} {"a":1,"c":3}
  return module.exports; // what require() would return => {"b":2}
}
console.log("require returns", simulateCJS());

// Runnable: top-level `this` in CJS wrapper
function cjsWrapper(exports, require, module) { console.log(this === module.exports, exports === module.exports); }
// When Node calls it with `this === module.exports`, so top-level `this` is module.exports, not globalThis
cjsWrapper.call({ exports: {} }, {}, () => {}, { exports: {} }); // demonstrate equivalence shape

// Verification: __filename / __dirname only inside CJS
console.log(typeof __filename !== "undefined" ? "CJS has __filename" : "__filename only in CJS wrapper");
console.log(typeof __dirname !== "undefined" ? "CJS has __dirname" : "__dirname only in CJS wrapper — ESM needs import.meta.url");
```

### 2) **The require cache — `require.cache` keyed by resolved filename; circular `require` returns a partially-filled object**

**Definition** — `require("./file.js")` resolves to an absolute filename, checks `require.cache[filename]` first — if present, returns `cachedModule.exports` *synchronously* without re-executing the file. On first load, it creates an entry with `module.exports = {}`, executes the wrapper, and fills `exports`. During cycles (`a.js` requires `b.js` which requires `a.js` back), the requesting `require("a.js")` inside `b.js` sees the *incomplete* `a.js` `module.exports` (the object created before `a.js` finished). Mutations to `exports.x` after the cycle entry become visible to the earlier requester (object identity shared); reassignment of `module.exports = newObj` is *not* visible to that earlier handle.

**Bad vs Good:**

```js
// Simulated circular exports vs module.exports reassignment — CJS semantics
function simulateCycle() {
  const cache = new Map();
  function requireSim(name) {
    if (cache.has(name)) {
      console.log(`cache hit ${name} =>`, JSON.stringify(cache.get(name).exports));
      return cache.get(name).exports;
    }
    const mod = { exports: {} };
    cache.set(name, mod); // inserted BEFORE execution — crucial for cycle detection (partially filled)
    if (name === "a.js") {
      // a.js body: `exports.x = 1; require("b.js"); module.exports = { x: 99 };` — reassignment after
      mod.exports.x = 1;
      requireSim("b.js");
      mod.exports = { x: 99 }; // reassign — cache entry's `.exports` replaced but earlier `b.js`'s `const a = require("a.js")` holds old {x:1} reference
      cache.set("a.js", mod); // update map to new object — but already-held handle stale
    } else if (name === "b.js") {
      const a = requireSim("a.js"); // circular — sees {x:1} partially
      console.log("b sees a.x", a.x); // 1 — not 99
      mod.exports.y = a.x + 10;
    }
    return mod.exports;
  }
  requireSim("a.js");
  console.log("final cache a.js exports", JSON.stringify(cache.get("a.js").exports)); // {"x":99}
  console.log("restore: mutation via exports.handle would be visible, reassignment not");
}
simulateCycle();

// CJS mutation-visible vs ESM TDZ contrast:
// CJS cycle: `exports.counter = 0; require("./b")` → b sees 0, later `exports.counter = 1` not seen by b's already-copied reference?
// Actually b holds reference to same object `exports` before reassignment? Wait reassignment breaks identity — above demo shows staleness
console.log("CJS: `exports.x = 1` mutation propagates via shared object; `module.exports = {...}` reassignment does NOT propagate to earlier cyclic holder");
console.log("ESM cycle (contrast): reading a live binding before init throws ReferenceError rather than returning stale undefined/old value");

// Runnable cache inspection — live Node cache
console.log("require.cache keys (first 2)", Object.keys(require.cache).slice(0,2));
console.log("Module._cache-like key is absolute filename — ./a.js vs ./src/../a.js resolves same");
```

### 3) **Globals absent in ESM — no `require`/`__dirname`/`__filename` by default (`createRequire`/`import.meta.url` replacements)**

**Definition** — ESM has no `require`, `module`, `exports`, `__filename`, `__dirname` bindings. `require is not defined` in `.mjs`. For interop, Node provides `import { createRequire } from "node:module"; const require = createRequire(import.meta.url);` (creates a CJS `require` inside ESM), and `new URL(..., import.meta.url)` for file-relative paths (see [4.2](<../4. Dynamic import and meta/4.2. import.meta import attributes and JSON modules.md>)). Using these inside ESM nests a CJS resolution context inside an ESM file — handle with care to avoid dual-instance hazards (see [5.2](<./5.2. ESM and CJS interop dual packages and migration.md>)).

```js
// No require in ESM — simulate error you'd see:
try {
  // This file is CJS, so `require` exists — simulate ESM context via Function lacking binding:
  Function('"use strict"; return require;')();
} catch (e) {
  console.log(e.name, e.message.slice(0, 40)); // ReferenceError require is not defined (if in true ESM)
  console.log("In true ESM, `typeof require` throws? actually `require is not defined` ReferenceError at top");
}

// createRequire bridge — runnable from this CJS file (ESM side simulation):
// In true ESM: `import { createRequire } from "node:module"; const require = createRequire(import.meta.url);`
console.log("In ESM, bridge is: import { createRequire } from 'node:module'; const require = createRequire(import.meta.url);");
let requireFromESM;
try {
  const { createRequire } = require("node:module");
  requireFromESM = createRequire("file:///tmp/fake.mjs");
} catch { requireFromESM = () => {}; }
console.log(typeof requireFromESM); // function — creates a CJS require inside an ESM file

// import.meta.url vs __dirname dance — show equivalence (CJS-runnable):
const _path = require("node:path");
const { fileURLToPath: _f2p } = require("node:url");
const fakeUrl = "file:///proj/app/main.mjs";
const __dirnameESM = _path.dirname(_f2p(fakeUrl));
console.log("__dirname via import.meta.url", __dirnameESM); // /proj/app
console.log(typeof __dirname !== "undefined" ? "__dirname CJS exists" : "no __dirname here without wrapper");

// BAD: using require directly in .mjs
console.log("BAD: require(\"./x.cjs\") inside .mjs without createRequire → ReferenceError");
// GOOD: explicit bridge
console.log("GOOD: import {createRequire} from 'node:module'; const require = createRequire(import.meta.url);");
```

### 4) **Common confusion**

- "`exports = {a:1}` works like `module.exports = {a:1}`" — `exports` is a local alias; reassigning it breaks the link — `require()` still sees `module.exports` (the old `{}`). Lint for `exports =` as error.
- "`require` inside a function behaves differently from top-level `require`" — both hit same cache; function wrapping only defers execution timing, not caching semantics. Order of first call still dictates evaluation order (like ESM post-order but imperative).
- "Clearing `require.cache` re-runs the file fresh for all importers" — deleting a cache entry affects only *future* `require()` calls; already-held `const m = require("./x.js")` still points to the old `module.exports` object.

### 5) **Performance note**

`require.cache` lookup is a filename hash lookup (fast), but each `require` triggers `fs.statSync` + resolution (`node_modules` walk) on first miss — not per-call after cached. Hot loops that `require` inside the loop pay repeated `require.cache` hash but not I/O — hoist `const dep = require("./dep.js")` above the loop. `require.cache` size equals number of distinct CJS files loaded — unbounded `require()` with dynamic `require(someExpr)` (non-literal) can leak filesystem handles and `Module` objects; prefer `import()` for computed.

### 6) **Mentor note**

Have trainees trace the `a.js↔b.js` cycle with `exports.x = 1` then `module.exports = {x:99}` and predict what `b.js`'s `const a = require("./a.js"); console.log(a.x)` prints (1, not 99). Those answering 99 carry post-reassignment expectation. In review, flag every `exports =` (should be `module.exports =`), every `require()` inside a loop or request handler that could be hoisted, and every use of `__dirname` in a `.mjs` file (must be `import.meta.url` dance).
