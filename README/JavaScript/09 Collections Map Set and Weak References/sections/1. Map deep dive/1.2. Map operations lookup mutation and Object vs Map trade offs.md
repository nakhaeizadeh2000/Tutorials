## 1.2. Map operations lookup mutation and Object vs Map trade offs

### 1) **`get`/`set`/`has`/`delete`/`clear`/`size` contracts**

**Definition** — `Map.prototype` exposes O(1) average operations: `set(k,v)` returns `this` (chainable), `get(k)` returns `v` or `undefined` (ambiguous with stored `undefined`), `has(k)` disambiguates, `delete(k)` returns boolean, `clear()` empties, `size` is a getter (not `length`, not a method).

```js
// set is chainable; get/has/delete contracts
const m = new Map();
console.log(m.set("a", 1) === m); // true — chainable
m.set("b", undefined);
console.log(m.get("b")); // undefined — but key exists!
console.log(m.has("b"), m.has("missing")); // true false — has disambiguates
console.log(m.get("missing")); // undefined — same value, different has
console.log(m.size); // 2 (getter, not function)
console.log(m.delete("b"), m.size); // true 1
console.log(m.delete("b")); // false — already gone
m.clear();
console.log(m.size); // 0

// has before get is the safe pattern when undefined is a valid value
function safeGet(map, key) {
  if (!map.has(key)) throw new Error(`missing ${String(key)}`);
  return map.get(key);
}
const m2 = new Map([["x", undefined]]);
console.log(safeGet(m2, "x")); // undefined — but present
try { safeGet(m2, "y"); } catch (e) { console.log(e.message); } // missing y

// NaN / -0 follow SameValueZero here too (see 1.1)
const m3 = new Map([[NaN, 1]]);
console.log(m3.has(NaN), m3.get(NaN)); // true 1
console.log(m3.has(-0) && m3.has(+0)); // depends on which zero was set — they are same key
m3.set(-0, "neg");
console.log(m3.get(+0)); // 'neg' — -0/+0 same entry
```

### 2) **Object keys identity — no stringification**

**Definition** — `Map` stores keys by identity (with SameValueZero for primitives). Any value — object, function, symbol, `NaN`, `-0` — is a distinct key without `ToPropertyKey` coercion. Plain objects always `ToString`/`ToPropertyKey` (`{}` → `"[object Object]"`) and conflate distinct objects.

```js
// Objects as keys — identity preserved
const alice = { id: 1 };
const bob = { id: 1 }; // same shape, different identity
const scores = new Map();
scores.set(alice, 10);
scores.set(bob, 20);
console.log(scores.get(alice), scores.get(bob)); // 10 20 — distinct
console.log(scores.get({ id: 1 })); // undefined — new object, new identity

// Plain object collapses all three to one string key
const objScores = {};
objScores[alice] = 10;
objScores[bob] = 20; // overwrites
console.log(objScores[alice]); // 20
console.log(objScores["[object Object]"]); // 20 — the string that both became
console.log(Object.keys(objScores)); // [ '[object Object]' ] — one key

// Primitive keys also stay typed in Map — "1" vs 1 are different; objects stringify numbers
const typed = new Map();
typed.set(1, "number one");
typed.set("1", "string one");
typed.set(true, "bool");
console.log(typed.get(1), typed.get("1"), typed.get(true)); // 'number one' 'string one' 'bool'
console.log(typed.size); // 3 — distinct

const coerced = {};
coerced[1] = "number one";
coerced["1"] = "string one"; // same property
console.log(coerced[1], coerced["1"]); // 'string one' 'string one'
console.log(Object.keys(coerced)); // [ '1' ] — one string key "1"

// Function and symbol keys work without extra ceremony
const fn = () => {};
const sym = Symbol("id");
const meta = new Map();
meta.set(fn, "handler");
meta.set(sym, "symbol value");
console.log(meta.get(fn), meta.get(sym)); // 'handler' 'symbol value'
```

### 3) **When to pick Map vs plain object vs null-proto dict**

| Concern | `Map` | Plain `{}` | `Object.create(null)` |
|---------|-------|------------|-----------------------|
| Non-string keys | identity — works | coerces to string — **bug** | coerces to string — **bug** |
| `NaN`/`-0` | SameValueZero correct | string `"NaN"`/`"0"` — conflated | same as `{}` |
| Untrusted string keys (`"__proto__"`, `"constructor"`) | safe — no prototype | **pollution** (`__proto__` wires prototype) | safe — no prototype |
| Iteration order | exact insertion order | integer-indices first, then strings insertion | same as `{}` |
| `size` / iteration | `size` O(1), `for-of` direct | `Object.keys().length` O(n), `for-in` walks chain | same as `{}` |
| JSON serialization | not serializable — needs manual `Array.from` | `JSON.stringify` native | `JSON.stringify` native |

**Modern guidance:**

- **Default to `Map`** when keys may be non-string, or string keys come from untrusted input, or you need exact insertion order without integer-index reordering.
- **Keep `{}`** for fixed-shape records with known string keys authored at compile time (user `{ name, id }`) — hidden-class fast, ergonomic literal.
- **`Object.create(null)`** is the historical "Map before Map" — still valid for string-only untrusted keys when you want `JSON` compatibility and no `Map` API, but `Map` is preferred for new code unless serialization demands an object.

```js
// Prototype pollution demo — Map is safe, {} is hazardous with naive deep merge / direct prototype access
// Modern engines: Object.assign({}, payload) creates an own data property "__proto__" (no wiring),
// but reading/writing via the __proto__ accessor still aliases Object.prototype — deep merges trip here.
const payload = JSON.parse('{"__proto__": {"polluted": true}, "a": 1}');

// Hazard path: accessing __proto__ as accessor reaches Object.prototype
const hazard = {};
// A naive deep-merge that walks keys and assigns via __proto__ accessor chain pollutes:
hazard["__proto__"]["polluted"] = true; // same as payload["__proto__"] → Object.prototype
console.log({}.polluted); // true — prototype polluted via accessor!
delete Object.prototype.polluted;

// Map is immune — "__proto__" is just a data entry, never an accessor
const safe = new Map(Object.entries(payload));
console.log(safe.get("__proto__")); // { polluted: true } — data, not prototype
console.log({}.polluted); // undefined — not polluted

// Null-proto alternative for string-only untrusted keys — no prototype to reach
const dict = Object.create(null);
dict["__proto__"] = payload["__proto__"];
console.log(dict["__proto__"]); // { polluted: true } — just a key
console.log(Object.getPrototypeOf(dict)); // null — no prototype
console.log({}.polluted); // undefined
// Shallow Object.assign also creates own "__proto__" data property on modern engines (verify):
const shallow = {};
Object.assign(shallow, payload);
console.log(Object.getOwnPropertyDescriptor(shallow, "__proto__")); // { value: { polluted:true }, ... } — data property
console.log({}.polluted); // undefined — shallow assign alone didn't pollute (but deep-merge / accessor path would)

// Choosing: known record → object is fine
function makeUser(name, id) { return { name, id }; } // fixed keys → object

// Choosing: dynamic key set or non-string keys → Map
function frequency(items) {
  const m = new Map();
  for (const x of items) m.set(x, (m.get(x) ?? 0) + 1);
  return m;
}
console.log(frequency(["a", "b", "a", NaN, NaN])); // Map { 'a' => 2, 'b' => 1, NaN => 2 }
```

### 4) **Common confusion**

- "`map.get(k)` returning `undefined` means missing" — no, value could be `undefined`; use `has` to distinguish. `??` and `if (!map.get(k))` mis-handle stored `0`/`""`/`false`/`undefined`.
- "`Object.keys(map).length` is size" — `Map` has no string keys; `Object.keys` sees only wrapper properties (none). Use `map.size` (getter, not method).
- "`delete map[k]` removes an entry" — bracket assignment writes a property on the `Map` object itself, not an entry. Use `map.delete(k)`.
- "`__proto__` in `Map` pollutes" — no; pollution is a plain-object `[[Prototype]]` hazard. `Map` entries never touch the prototype.

### 5) **Performance note**

`Map.set`/`get`/`has` are hash-probe O(1). For `n < ~50` with fixed string keys, an object literal can be faster due to inline-cache/hidden-class — but the crossover is workload-dependent. Iteration: `for (const [k,v] of map)` allocates an iterator; `map.forEach` avoids the iterator object on some engines. Deleting from the middle during iteration is supported (iterator skips deleted) — unlike object `delete` which can deoptimize hidden classes (see [Objects 5.1](<../../../06 Objects in Depth/sections/5. Integrity and immutability/5.1. Prevent extensions seal freeze and shallow immutability.md>)).

### 6) **Mentor note**

Have juniors write `frequency(items)` once with `{}` and once with `Map`, then feed `["__proto__","constructor","NaN",NaN,{}]` — the object version breaks visibly. In review, grep `obj[dynamic]` where `dynamic` may be object/`NaN`/untrusted-string and suggest `Map`; flag `if (!map.get(k))` where stored values may be falsy — suggest `map.has(k)`.
