## 7.1. Real production bugs caused by collection mistakes

### 1) **Unbounded `Map` cache that pins every object ever seen**

**Incident** — an API request transformer memoized `buildView(obj)` keyed by any object argument using a module-level `Map`. Overnight traffic growth OOM'd the service — heap snapshot showed millions of entries, each key object (request contexts) retained forever even though callers had dropped them.

```js
// BAD — Map holds keys strongly → unbounded growth
const viewCache = new Map();
function getViewBad(obj) {
  if (viewCache.has(obj)) return viewCache.get(obj);
  const view = { computed: JSON.stringify(obj).length };
  viewCache.set(obj, view);
  return view;
}
// Each distinct request object adds an entry that never leaves — leak
let tmp = { id: 1 };
getViewBad(tmp);
tmp = null; // caller done — but Map still holds { id:1 } strongly
console.log(viewCache.size); // 1 — grows forever with each request

// GOOD — WeakMap lets key death evict (or bounded LRU if primitives)
const weakViewCache = new WeakMap();
function getViewGood(obj) {
  if (typeof obj !== "object" || obj === null) throw new TypeError("WeakMap key must be object");
  if (weakViewCache.has(obj)) return weakViewCache.get(obj);
  const view = { computed: JSON.stringify(obj).length };
  weakViewCache.set(obj, view);
  return view;
}
let k = { id: 2 };
getViewGood(k);
console.log(weakViewCache.has(k)); // true — alive while k reachable
k = null; // now WeakMap entry is weak — no size to check, but will not appear in snapshot after GC
// No leak — GC can reclaim ({ id:2 }, its view) together via ephemeron

// If keys may be primitives or you need iteration, use bounded Map instead of WeakMap:
function createLRU(limit = 500) {
  const m = new Map();
  return {
    get(k) { const v = m.get(k); if (v !== undefined || m.has(k)) { m.delete(k); m.set(k, v); } return v; },
    set(k, v) { if (m.has(k)) m.delete(k); else if (m.size >= limit) m.delete(m.keys().next().value); m.set(k, v); },
    size: () => m.size
  };
}
const lru = createLRU(2);
lru.set("a", 1); lru.set("b", 2); lru.set("c", 3);
console.log(lru.size(), lru.get("a")); // 2 undefined — bounded

// Detection: heap snapshot growth + Map.size increasing monotonically — grep new Map( at module scope
```

- *Why it was missed* — `Map` ergonomics hide GC contract; "cache" sounds free but strong refs are ownership. Required review rule: any `new Map` at module scope keyed by objects needs eviction (WeakMap, LRU, TTL) or explicit `delete`.

### 2) **Finalizer relied on to close resources — runs too late or never**

**Incident** — a file-handle pool registered handles with `FinalizationRegistry` to close them on GC, without an explicit `close()` path. Under load, GC ran late and file descriptors exhausted before finalizers fired — `EMFILE` and dropped requests.

```js
// BAD — correctness depends on GC timing (best-effort, may never run before exit)
const fileReg = new FinalizationRegistry(fd => {
  // This may run much later, or never — fd leak until then
  console.log(`finalize close ${fd} — too late`);
});
function openBad(path) {
  const handle = { fd: Math.random(), path };
  fileReg.register(handle, handle.fd); // held is fd (good), but still best-effort
  return handle;
}
let h = openBad("/tmp/x");
h = null; // "closed"? — no, fd leaked until GC

// GOOD — explicit disposal; registry only for observability/metrics, not correctness
function openGood(path) {
  const handle = { fd: Math.random(), path, close() { console.log(`explicit close ${this.fd}`); } };
  return handle;
}
{
  const file = openGood("/tmp/y");
  try {
    console.log(`use fd ${file.fd}`);
  } finally {
    file.close(); // deterministic — never skip
  }
}
// Modern: using / Symbol.dispose when baseline supports it
{
  const res = { [Symbol.dispose]() { console.log("disposed via using"); }, fd: 42 };
  // using file = res; — when proposal lands, dispose runs deterministically at block exit
  try { console.log(`use ${res.fd}`); } finally { res[Symbol.dispose](); }
}

// Even explicit unregister must be paired with explicit close — don't schedule "cleanup later"
const metricsOnly = new FinalizationRegistry(id => console.log(`metric: ${id} collected — not a close`));
let tmp2 = { id: "tmp" };
metricsOnly.register(tmp2, tmp2.id);
tmp2 = null; // metric may eventually fire — but state was already cleaned explicitly elsewhere
```

- *Why it was missed* — `WeakRef`+`FinalizationRegistry` were introduced as "GC hooks" and misread as destructors. Required review rule: any `FinalizationRegistry` that closes/sends/releases must have a paired `try/finally`/`using` primary; registry callbacks should be metrics/best-effort only (flag with `grep FinalizationRegistry`).

### 3) **`-0` vs `+0` vs `NaN` membership surprise**

**Incident** — an analytics pipeline routed events by `event.value` (numeric), treating `-0` as distinct from `+0` for signed-zero temperature semantics, using `Map`. Deduplication via `Set` collapsed a third of the readings: `-0` and `+0` landed in one bucket, and downstream `NaN` sensor errors that should have been counted separately via `===` logic disappeared into one `NaN` entry.

```js
// Expectation via === mental model: 3 distinct (-0, +0, NaN per element) — reality via SameValueZero: 2
const temps = [-0, +0, NaN, NaN, 0];
const buckets = new Map();
for (const t of temps) buckets.set(t, (buckets.get(t) ?? 0) + 1);
console.log(buckets.size); // 2 —  { 0 => 3, NaN => 2 } — -0/+0/0 one entry, NaNs one entry
console.log(buckets.get(-0), buckets.get(+0), buckets.get(0)); // 3 3 3 — same count
console.log(buckets.get(NaN)); // 2 — NaN deduped (vs NaN===NaN false you'd expect 2 NaN entries)
console.log(NaN === NaN); // false — === would have said two distinct NaNs
console.log(Object.is(-0, +0)); // false — Object.is would have split zeros

// Fix: if signed zero matters, encode it before keying; if NaN-per-occurrence matters, key by occurrence id
function toSignedKey(n) {
  if (typeof n === "number" && n === 0) return 1 / n === -Infinity ? "-0" : "+0"; // distinguish -0
  if (Number.isNaN(n)) return `nan-${Math.random()}`; // or count occurrences, not dedupe NaN
  return n;
}
const accurate = new Map();
for (const t of temps) {
  const k = toSignedKey(t);
  accurate.set(k, (accurate.get(k) ?? 0) + 1);
}
console.log(accurate.size); // 4 — { '-0'=>1, '+0'=>1, 'nan-*'=>2 distinct, but 0 merged? adjust }
console.log([...accurate.keys()]); // distinguishable
// Simpler: handle -0/NaN branches explicitly before Map/Set
```

- *Why it was missed* — domain logic distinguished `-0` per API contract but collection didn't. Required review rule: any numeric `Map`/`Set` that tracks `-0`/`NaN` must pass the SameValueZero table test — ask "what does `has(NaN)` return?" in review; treat `-0 !== +0` requirements as encoding-before-keying.

### 4) **`JSON.stringify` on `Set`/`Map` silently loses data**

**Incident** — audit log serialized a `Set` of active ids with `JSON.stringify(payload)`; the `Set` became `{}` in storage, replay showed zero ids and the incident was invisible.

```js
// BAD — Set/Map stringify as {}
const audit = { ids: new Set([1, 2, 3]), meta: new Map([["a", 1]]) };
console.log(JSON.stringify(audit)); // {"ids":{},"meta":{}} — ids lost!

// GOOD — spread / Array.from before stringify
console.log(JSON.stringify({ ids: [...audit.ids] })); // {"ids":[1,2,3]}
console.log(JSON.stringify({ meta: [...audit.meta] })); // {"meta":[["a",1]]}

// Detection: snapshot after JSON round-trip shows empty — grep JSON.stringify.*Set|Map
```

### 5) **Mentor note**

Have juniors reproduce each incident with a heap-size probe (strong `Map` size growing) and a `Set` `NaN`/`-0` quiz — then fix with `WeakMap`/encoding/`...Set`. In review, flag any module-level `Map`/`Set` with no bound, any `FinalizationRegistry` without explicit `close`, and any `JSON.stringify(setOrMap)` without prior spread.
