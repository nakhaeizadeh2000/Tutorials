## 2.2. Set operations and Array vs Set trade offs

### 1) **Set as deduplication and O(1) membership engine**

**Definition** — `Set`'s only contract beyond membership is fast `has`. Building a `Set` once turns repeated `Array.includes` O(n) scans into O(1) probes — the classic dedupe and filter-by-existence patterns.

```js
// Deduplication — preserves insertion order, SameValueZero dedupes NaN/-0
const raw = ["a", "b", "a", NaN, NaN, -0, +0];
console.log([...new Set(raw)]); // [ 'a', 'b', NaN, 0 ]

// Membership engine — build once, probe many
const allowed = new Set(["ada", "bob", "cara"]);
function isAllowed(user) { return allowed.has(user); } // O(1) vs allowedArray.includes(user) O(n)
console.log(isAllowed("bob"), isAllowed("dave")); // true false

// Filter by existence — Set-powered filter is O(n + m) not O(n*m)
const users = [{ id: 1 }, { id: 2 }, { id: 3 }];
const blockedIds = new Set([2]);
const filtered = users.filter(u => !blockedIds.has(u.id));
console.log(filtered); // [ { id:1 }, { id:3 } ]

// Bad vs good: indexOf dedupe is O(n²) and breaks on NaN
const arr = [1, NaN, 2, NaN];
const bad = arr.filter((v, i, a) => a.indexOf(v) === i); // NaN never found → duplicates kept
console.log(bad); // [ 1, NaN, 2, NaN ] — wrong (indexOf can't find NaN)
const good = [...new Set(arr)];
console.log(good); // [ 1, NaN, 2 ] — correct via SameValueZero
```

### 2) **Set algebra without language sugar**

**Definition** — the language provides no built-in `union`/`intersection`/`difference` on `Set` (proposal "Set methods" Stage 3 as of 2026, shipping in some engines — check `Set.prototype.intersection`). Today you compose via iteration.

```js
// Today (ES2026 baseline) — compose via iteration/spread
function union(a, b) { return new Set([...a, ...b]); }
function intersection(a, b) { const bSet = b instanceof Set ? b : new Set(b); return new Set([...a].filter(x => bSet.has(x))); }
function difference(a, b) { const bSet = b instanceof Set ? b : new Set(b); return new Set([...a].filter(x => !bSet.has(x))); }
function isSubset(a, b) { const bSet = b instanceof Set ? b : new Set(b); return [...a].every(x => bSet.has(x)); }

const A = new Set([1, 2, 3, NaN]);
const B = new Set([3, 4, NaN]);
console.log([...union(A, B)]); // [ 1, 2, 3, NaN, 4 ] — NaN once
console.log([...intersection(A, B)]); // [ 3, NaN ] — 3 and NaN common
console.log([...difference(A, B)]); // [ 1, 2 ] — in A not B
console.log(isSubset(new Set([3, NaN]), A)); // true

// Future (Set methods proposal) — if available, prefer native
if (typeof Set.prototype.intersection === "function") {
  // Native proposal: A.intersection(B) etc. — O(n) engine-optimized
  console.log([...A.intersection(B)]); // [ 3, NaN ] when proposal ships
} else {
  console.log("native Set algebra not yet in this engine — using helper above");
}

// Symmetric difference (in either but not both) — compose from difference+union
function symDiff(a, b) { return union(difference(a,b), difference(b,a)); }
console.log([...symDiff(A,B)]); // [ 1, 2, 4 ]
```

- *Modern guidance* — don't hand-roll `O(n²)` dedupe with `indexOf`/`includes` in loops. Build a `Set` for membership, or a `Map` if you need associated values. For algebra, use helpers today; adopt native `Set.prototype.{union,intersection,difference}` when your baseline supports it (check `typeof`).

### 3) **When to pick Set vs Array vs Map**

| Concern | `Set` | `Array` | `Map` |
|---------|-------|---------|-------|
| Uniqueness invariant | yes — insertion guards uniqueness | no — must enforce manually | keys unique; values not |
| Membership test | `has` O(1) | `includes` O(n), `indexOf` O(n) + NaN miss | `has` O(1) for keys |
| Order | insertion order | insertion order (+ exotic length) | insertion order |
| Value identity | SameValueZero; objects by identity | by index position | key identity SameValueZero |
| Associated value per entry | no — membership only | no (value is at index) | yes — `k → v` mapping |
| JSON serialization | not native — `[...set]` array | `JSON.stringify` native | not native — `Array.from(map)` |
| Object members / GC | strong refs — members kept alive | strong refs — elements alive | strong refs — both alive |
| Weak / GC-ephemeron | use `WeakSet` (object-only, non-iterable) | — | use `WeakMap` for keyed |

```js
// Choosing: ordered list with dupes allowed → Array
const timeline = ["login", "view", "view", "logout"]; // duplicates meaningful

// Choosing: uniqueness matters, membership tested often → Set
const seen = new Set();
function visit(id) {
  if (seen.has(id)) return "already";
  seen.add(id);
  return "new";
}
console.log(visit("a"), visit("a")); // 'new' 'already'

// Choosing: need value per key → Map (Set has no value)
const roleByUser = new Map([["ada", "admin"], ["bob", "viewer"]]);
console.log(roleByUser.get("ada")); // 'admin'

// Choosing: object members long-lived tracking that shouldn't leak → WeakSet (see 3.2)
const transient = { id: 1 };
const live = new WeakSet([transient]);
console.log(live.has(transient)); // true — but won't prevent GC (see 3.2)

// Serialization: Set/Map need manual array step
const s = new Set([1, 2, 3]);
console.log(JSON.stringify(s)); // {} — not an array!
console.log(JSON.stringify([...s])); // [1,2,3] — spread first
const m = new Map([["a", 1]]);
console.log(JSON.stringify([...m])); // [["a",1]] — pairs
```

### 4) **Common confusion**

- "`Set` is `Map` with values ignored" — behaviorally close but `Set` stores values directly; `Map` stores `k→v` pairs. `Set.has(NaN)` vs `Map.has(NaN)` same comparator, but `Set` has no `get`.
- "`Array` dedupe via `filter`+`indexOf` is fine" — O(n²) and `NaN` blind; use `Set`.
- "`Set` members are automatically GC'd" — no, `Set` holds strong references. For GC-ephemeron tagging use `WeakSet` (3.2).
- "`Set` JSON.stringify's as array" — no, `Set` stringifies as `{}`; spread to array first.

### 5) **Performance note**

`Set.add`/`has` are hash O(1). Deduplicating an array of `n` via `new Set(arr)` is O(n) — versus `filter`+`indexOf` O(n²). For tiny `n` (< ~20) and one-off checks, building a `Set` may be slower than a linear scan — measure. Iteration cost: `for (const v of set)` allocates iterator; `set.forEach` can be cheaper. `Set` does not have index access — random access by position requires `Array.from(set)[i]` O(n).

### 6) **Mentor note**

Have juniors replace a `blocked.includes(id)` hot path with `new Set(blocked).has(id)` and measure with `n=1e5`. Then ask "why does `Object.keys(new Set(...))` return `[]`?" (`Set` entries aren't own string properties — iteration protocol). In review, flag any `array.filter((v,i,a)=>a.indexOf(v)===i)` dedupe and any `has` check that should be `Set` but uses `Array.includes` in a loop.
