## 5.1. Choosing the right collection Map vs Object vs Set vs Array and Weak variants

### 1) **Key-type and identity matrix**

**Definition** — the choice is driven by key type and what "equality" means. `Object`/`null-proto` coerce keys via `ToPropertyKey` (stringify); `Map`/`Set` keep identity via SameValueZero; `WeakMap`/`WeakSet` restrict to objects and are ephemeron.

| Question | Answer → Pick |
|----------|---------------|
| Keys are non-string/symbol/object/`NaN`/`-0` | → `Map` (or `Set` for membership) — object would coerce/collapse |
| Keys are untrusted strings (`"__proto__"`, user input) | → `Map` or `Object.create(null)` — plain `{}` risks pollution / prototype chain |
| Need dedup/membership O(1) | → `Set` (or `Map` if you need value per key) |
| Ordered list with dupes and index access / holes semantics | → `Array` (exotic `length`) |
| Object-keyed cache whose lifetime follows the key | → `WeakMap` — key death evicts without manual delete |
| Tagging/branding transient objects without pinning | → `WeakSet` |
| Need non-owning handle to an object | → `WeakRef` (check `deref()`) |
| Need best-effort cleanup after GC | → `FinalizationRegistry` (never for correctness) |

```js
// Object coerces — Map preserves
const k1 = { id: 1 };
const k2 = { id: 1 };
const map = new Map([[k1, "k1"], [k2, "k2"]]);
console.log(map.size, map.get(k1), map.get(k2)); // 2 'k1' 'k2'

const obj = {};
obj[k1] = "k1";
obj[k2] = "k2"; // same string key
console.log(Object.keys(obj), obj[k1]); // [ '[object Object]' ] 'k2'

// -0 / NaN
const m = new Map([[-0, "neg-zero"], [NaN, "nan"]]);
console.log(m.get(+0), m.get(NaN), m.has(NaN)); // 'neg-zero' 'nan' true
const o = { [-0]: "a", [NaN]: "b" }; // -0→"0", NaN→"NaN"
console.log(o["0"], o["NaN"], Object.keys(o)); // 'a' 'b' [ '0', 'NaN' ]

// Untrusted keys
const payload = { "__proto__": 1, "constructor": 2 };
const safe = new Map(Object.entries(payload));
console.log(safe.get("__proto__"), safe.get("constructor")); // 1 2 — data
console.log({}.polluted); // undefined
```

### 2) **Mutation and iteration surface matrix**

| Collection | Mutates original? | Iterable? | `size`? | `clear`? | GC keeps entries? |
|------------|-------------------|-----------|---------|----------|-------------------|
| `Map` | `set`/`delete`/`clear` mutate in place; copy via `new Map(other)` | `entries`/`keys`/`values`, `for-of` → entries | `size` O(1) | yes | **yes** — strong |
| `Set` | `add`/`delete`/`clear` mutate | `values` / `entries` `[v,v]`, `for-of` → values | `size` O(1) | yes | **yes** — strong |
| `Array` | `push`/`pop`/`splice` mutate; `toReversed`/`toSorted` copy (ES2023) | `for-of` values, indexed + `length` exotic | `length` (exotic) | `length=0` | **yes** — strong |
| `Object` / `null-proto` | assignment/`delete` mutate | `Object.keys`/`entries`/`Reflect.ownKeys` | `Object.keys().length` O(n) | manual loop | **yes** — strong |
| `WeakMap` | `set`/`delete` mutate | **no** — no iteration | no | no | **no** — ephemeron |
| `WeakSet` | `add`/`delete` mutate | **no** | no | no | **no** — ephemeron |
| `WeakRef` | `deref` read-only view | no | — | — | **no** — weak |
| `FinalizationRegistry` | `register`/`unregister` | no | — | — | — |

```js
// Iteration shapes
const mapIter = new Map([["a", 1], ["b", 2]]);
console.log([...mapIter]); // [ [ 'a',1 ], [ 'b',2 ] ] — entries
console.log([...mapIter.keys()], [...mapIter.values()]); // [ 'a','b' ] [ 1,2 ]

const setIter = new Set(["a", "b"]);
console.log([...setIter]); // [ 'a','b' ] — values
console.log([...setIter.entries()]); // [ [ 'a','a' ], [ 'b','b' ] ]

const arr = [10, 20];
console.log([...arr], arr.length); // [ 10,20 ] 2

// Weak collections are not iterable — must not try
const wm = new WeakMap([[{id:1}, "v"]]);
console.log(typeof wm[Symbol.iterator]); // undefined
const ws = new WeakSet([{id:1}]);
console.log(typeof ws.size); // undefined
```

### 3) **Decision table with migration notes**

**Migrate object-as-map → `Map`: if keys may collide via stringification or pollution, switch.**

```js
// Before: object as frequency map — breaks on "__proto__", objects, NaN
function freqBad(items) {
  const acc = {};
  for (const x of items) acc[x] = (acc[x] ?? 0) + 1; // x coerced via ToPropertyKey
  return acc;
}
console.log(freqBad(["__proto__", "a", {}])); // { a:1, '[object Object]':1 } — "__proto__" polluted chain or lost

// After: Map frequency — preserves all key types
function freqGood(items) {
  const m = new Map();
  for (const x of items) m.set(x, (m.get(x) ?? 0) + 1);
  return m;
}
console.log(freqGood(["a","a", {}, {}, NaN, NaN])); // Map { 'a'=>2, {}=>1, {}=>1, NaN=>2 }
```

**Array-unique → `Set`: if you test membership or dedupe, use `Set`.**

```js
// Before: O(n²) dedupe + NaN bug
const a = [1, NaN, 2, NaN];
const bad = a.filter((v,i,arr) => arr.indexOf(v) === i);
console.log(bad); // [ 1, NaN, 2, NaN ] — NaN duplicated

// After: Set dedupe O(n), correct
console.log([...new Set(a)]); // [ 1, NaN, 2 ]
```

**Object-keyed memo → `WeakMap`: lifetime should follow the key.**

```js
// Before: Map memo leaks — every key object ever seen stays alive
const legendLeak = new Map();
function viewBad(obj) { if (!legendLeak.has(obj)) legendLeak.set(obj, { v: Math.random() }); return legendLeak.get(obj); }

// After: WeakMap memo — key death evicts
const legendLive = new WeakMap();
function viewGood(obj) { if (!legendLive.has(obj)) legendLive.set(obj, { v: Math.random() }); return legendLive.get(obj); }
```

**Tagging/capability → `WeakSet` vs `Set`: transient tagging → `WeakSet`, enumerable tagging → `Set`.**

```js
const longLived = new Set(); // strong — enumerate, persist, but leaks transients
const transient = new WeakSet(); // weak — no enumerate, but no leak
let n = { id: 1 };
transient.add(n);
longLived.add(n);
n = null; // transient lets GC reclaim; longLived pins (see 7.1)
```

### 4) **Common confusion**

- "`Object` and `Map` are interchangeable" — no, key-type, SameValueZero, pollution, iteration cost all differ.
- "`WeakMap` is a weak `Map`" — similar API shape but keys must be objects, no enumeration, no `size`/`clear`, different GC contract.
- "`Array` is the set primitive" — no, `Array` allows dupes and has exotic `length`; `Set` enforces uniqueness and `SameValueZero`.
- "`WeakRef` replaces `WeakMap`" — no, `WeakRef` is a single weak handle; `WeakMap` is an ephemeron table.

### 5) **Performance note (measured trade-offs)**

`Map`/`Set` hash O(1) vs `Array` linear scan O(n) — break-even at `n ≈ 10–50` for string keys depending on engine/hit-rate. `Object` literal with fixed shape benefits from hidden class inline caches; `Map` with many distinct keys doesn't. `WeakMap`/`WeakSet` scan cost is GC-time, not operation-time; prefer them for object-keyed caches even though per-op similar to `Map` — the GC win (no manual eviction) outweighs micro-cost. For serialization or cross-worker clone (`structuredClone`), `Object`/`Array` transfer directly; `Map`/`Set` need conversion.

### 6) **Mentor note**

Give juniors a mixed-key exercise: build a registry keyed by `["__proto__", 1, NaN, -0, {}]` and ask what the key set looks like under `Object` vs `Map` (answer: 3 collapsed string keys vs 5 distinct entries). Then ask "which collection leaks if you never `delete`?" (`Map`/`Set`/`Array` pin; weak variants don't). In review, flag any `obj[nonString]` where `nonString` may be object/`NaN`/user input — suggest `Map`/`Set`; flag any `Map` keyed by objects with no eviction — suggest `WeakMap` or bounded LRU.
