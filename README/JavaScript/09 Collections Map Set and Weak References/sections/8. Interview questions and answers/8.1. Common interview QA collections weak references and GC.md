## 8.1. Common interview Q&A: collections, weak references, and GC

### 1) **The classics with mechanism-level answers**

**Q1 — Does `Map` use `===` for keys?**
No — SameValueZero: `NaN` equals `NaN`, `-0` equals `+0` (single entry). `===` misses `NaN`; `Object.is` splits `-0`. Demonstrate: `new Map([[NaN,1]]).has(NaN)` → true, `new Map([[-0,1]]).get(+0)` → 1.

**Q2 — What is iteration order for `Map`/`Set`?**
Insertion order, exactly. `Map` iterates `entries` (`for-of` → entries); `Set` iterates values (`entries` are `[v,v]`). Updating an existing key's value doesn't move it; delete+re-add moves to end. Deleting during iteration skips entry; adding after current position may be visited (live walk).

**Q3 — Why does `Object[{}]` collide but `Map.set({},1)` not?**
Objects `ToPropertyKey` stringify: both `{}` become `"[object Object]"`. `Map` stores by identity (with SameValueZero for primitives) — different objects are distinct keys; `map.get({})` only hits same reference.

**Q4 — `Set` vs `Array` for dedupe — what's wrong with `filter`+`indexOf`?**
`O(n²)` and `NaN`-blind (`indexOf(NaN)` → -1, so duplicate `NaN`s kept). Correct is `[...new Set(arr)]` — O(n), SameValueZero correct (`NaN` once, `-0`/`+0` collapse).

**Q5 — What is a `WeakMap` and how does it differ from `Map`?**
`WeakMap` maps object keys → values ephemerally: key alive → value alive; key dead → entry vanishes after GC. Keys must be objects (primitives throw). No `size`, no iteration, no `clear` — enumeration would expose GC timing. `Map` holds keys strongly (pins).

**Q6 — `WeakSet` — what's allowed?**
Object values only; no primitives (`add(1)` throws); no `size`/iteration/`clear`/`values` — only `has`/`add`/`delete`. Ephemeron membership: member death vanishes after GC.

**Q7 — What does `WeakRef` do and when does `deref()` become `undefined`?**
Non-owning handle: `new WeakRef(obj)` (obj only), `deref()` returns object if still alive else `undefined`. Timing is non-deterministic — GC decides. Never assert prompt clearing; always `const t = ref.deref(); if (t !== undefined) { use(t); }` (single deref).

**Q8 — When does `FinalizationRegistry` callback run, and what does it receive?**
Best-effort callback enqueued asynchronously after a registered target is collected; may never run (exit, no collection). Receives only the held value (e.g., an id), not the target. Registration doesn't keep target alive. Held value must not reference target (would pin). Unregister via `unregister(token)` where token is the third arg to `register`.

**Q9 — Is it correct to close files/sockets in a finalizer?**
No. Finalizers are best-effort fallback/metrics only — use explicit `try/finally`, `close()`, or `using`/`Symbol.dispose`. If non-running breaks invariants, you have a correctness bug.

**Q10 — Does `WeakMap` keep its values alive?**
Gated by key: value is strongly reachable only via entry; entry lives only while key is reachable elsewhere. If value holds a strong ref back to key, it doesn't alone keep key alive via ephemeron edge (but an external strong ref to value that reaches key does keep chain alive — see private-field vs `WeakMap` discussion).

**Q11 — `Set` `entries()` shape?**
`[v,v]` pairs — mirrors `Map.entries` for `Map`-`Set` symmetry. `keys()` alias for `values()` — historical symmetry, not separate.

**Q12 — How do you serialize `Map`/`Set`?**
`JSON.stringify(map)` → `{}`, `JSON.stringify(set)` → `{}` — not serializable. Use `[...map]`/`[...set]`/`Array.from(map)` to array of pairs/values, then `JSON.stringify` that; reconstruct with `new Map(pairs)`/`new Set(values)`.

### 2) **What interviewers actually probe for**

- Narrating SameValueZero vs `===` vs `Object.is` and when it matters (`NaN`, `-0`), not reciting `Map` method names.
- Explaining insertion-order and live-mutation semantics (update vs delete+re-add, added-during-iteration visited).
- Identity vs stringification: why `obj[{}]` collapses and `Map` doesn't — and why `WeakMap` restricts to objects.
- Ephemeron vs strong: when `Map` leaks and `WeakMap`/`WeakSet` don't, and why non-iterability is intentional.
- `WeakRef` resurrection hazard: single `deref()` + `undefined` check vs double deref, and why timing is non-deterministic.
- `FinalizationRegistry` safety: held-value not target, token/unregister, never for resource correctness.

### 3) **Grading guidance**

- *Junior signals* — can create `Map`/`Set`, use `has`/`add`/`delete`, знает that `Map` preserves object keys unlike `{}`. *Red flags* — "Map uses `===`", "`WeakMap` has `size`", "`WeakSet` stores primitives", "`JSON.stringify(new Set([1]))` is `[1]`".
- *Mid signals* — explains SameValueZero table (`NaN` in `1`, `-0/+0` `1`), insertion-order rules (update stays, delete+re-add moves), dedupe via `Set` O(n) vs `filter`+`indexOf` O(n²)+NaN-bug, explicit `has` disambiguation for stored `undefined`. *Red flags* — "adding existing member moves it", "`Set` entries are `[index, value]` like `Array`", "`WeakRef` keeps target alive".
- *Senior signals* — narrates ephemeron table (key death evicts value, GC scanning), `WeakRef` single-deref + `undefined` branching, `FinalizationRegistry` held-vs-target and token discipline plus "never for correctness" principle, bounded LRU/bounded `Map` vs `WeakMap` trade-off, GC nondeterminism in tests (`--expose-gc`). *Red flags* — "finalizer runs synchronously after last ref drops", "held value can be target itself", "Unbounded `Map` keyed by objects is safe", "`WeakMap` iteration lists entries".
- *Expert/Mentor signals* — designs a `WeakMap`-backed memo/intern pool vs `Map` LRU vs `WeakRef` cache with explicit eviction and `FinalizationRegistry` metrics-only, articulates `Map` vs `Object` hidden-class trade-off at size thresholds, and explains why `WeakMap` has no `size`/`clear` (GC timing leak into semantics). Probes with heap snapshot narrative.
