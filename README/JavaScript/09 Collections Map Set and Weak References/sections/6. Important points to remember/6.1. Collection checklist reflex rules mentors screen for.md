## 6.1. Collection checklist: reflex rules mentors screen for

### 1) **SameValueZero before any `Map`/`Set` membership claim**

| Check | `===` | `Object.is` | SameValueZero (`Map`/`Set`) | Use `has`? |
|-------|-------|-------------|------------------------------|-------------|
| `NaN` in collection | misses (`NaN===NaN` false) | hits | **hits** — single `NaN` entry | `has(NaN)` true |
| `-0` vs `+0` | treats as same (`-0===+0` true) | distinct | same — single entry | `has(-0)` ≡ `has(+0)` |
| `0` vs `"0"` | distinct | distinct | distinct | `has(0)` ≠ `has("0")` |
| Object identity | identity | identity | identity | `has({})` only same ref |

```js
// Reflex: before any membership claim, ask "SameValueZero or ===?"
const m = new Map([[NaN, 1], [-0, 2]]);
console.log(m.has(NaN), m.get(NaN)); // true 1 — NaN hits
console.log(m.get(+0), m.get(-0)); // 2 2 — -0/+0 same
const s = new Set([NaN, NaN, -0, +0]);
console.log(s.size); // 2 — { NaN, 0 }
```

**Reflex rule:** if you or your reviewer reasons about `Map`/`Set` as "`===`", you predict `NaN` wrong. Say "SameValueZero" out loud and pass the `NaN` test.

### 2) **No stringification vs property-key coercion — know which container you're in**

```js
// Map — identity preserved (any value type, no coercion)
const idMap = new Map();
const k = { id: 1 };
idMap.set(k, "k");
idMap.set(1, "one");
idMap.set("1", "string-one");
console.log(idMap.size); // 3 — distinct

// Object — ToPropertyKey coercion (all keys become string/symbol)
const container = {};
container[k] = "k"; // k→"[object Object]"
container[1] = "one"; // 1→"1"
container["1"] = "string-one"; // same "1"
console.log(Object.keys(container)); // [ '1', '[object Object]' ] — 2, not 3
console.log(container["[object Object]"]); // 'k' — collapsed
```
**Reflex rule:** before writing `table[key]` ask "can `key` be object/`NaN`/`-0`/untrusted string?" → if yes, `Map`. If keys are fixed known strings at author time, `{}` is fine.

### 3) **Weak means non-enumerable and non-deterministic**

```js
// WeakMap/WeakSet — no size, no iteration, no clear
const wm = new WeakMap();
console.log(typeof wm.size, typeof wm[Symbol.iterator]); // 'undefined' 'undefined'
// Can't list entries — GC nondeterminism would leak into semantics

// WeakRef — deref may be undefined
const target = { id: 1 };
const ref = new WeakRef(target);
const deref = ref.deref(); // single deref, then check
if (deref !== undefined) console.log("alive", deref.id);
else console.log("collected");

// FinalizationRegistry — callback may run late or never; never for correctness
const reg = new FinalizationRegistry(id => console.log(`cleanup ${id} — metric only`));
let tmp = { id: "tmp" };
reg.register(tmp, tmp.id); // held is id, not target
tmp = null; // don't assert when callback runs
```
**Reflex rule:** if you need `size`/iteration/persistence, you don't want a weak collection. If you need prompt cleanup, you don't want a finalizer — use `try/finally`/`using`/`close()`.

### 4) **Choosing and mutation reflexes**

| Reflex | Wrong | Correct |
|--------|-------|---------|
| Unbounded cache keyed by objects | `Map` pins forever → OOM | `WeakMap` or bounded `Map` LRU |
| Frequent `has` on growing set | `Array.includes` O(n) in loop | `Set` O(1) |
| Need value per key | `Set` (no value) | `Map` |
| Transient visited set | `Set` pins | `WeakSet` |
| Resource cleanup | `FinalizationRegistry` alone | explicit `close/using`; registry only for metrics |
| `map.get(k) === undefined` means missing | misses stored `undefined` | `map.has(k)` |

### 5) **The review grep list**

```js
// 1) Object used as map with dynamic keys — should be Map
// grep: \[[^"]*\b(obj|map|dict)\[.*\]  — inspect every `obj[dynamic]` where dynamic may be object/NaN/untrusted
// replace with: new Map() + map.get/has/set

// 2) Array.includes / indexOf in hot path or for NaN — should be Set
// grep: \.includes\(|\.indexOf\(  — in loops or dedupe filters
// replace with: Set.has / new Set(arr)

// 3) Dedupe via filter+indexOf — O(n²) and NaN-blind — should be Set
// grep: filter\(.*indexOf  — replace with [...new Set(arr)]

// 4) Map/Object get without has disambiguation when undefined valid — should check has
// grep: \.get\(.*\) !== undefined|\.get\(.*\) === undefined  — replace with has check before get

// 5) delete on object in hot path — deoptimizes hidden class — prefer Map delete
// grep: delete\s+\w+\[  — flag for hot paths (see Objects 5.1)

// 6) WeakMap/WeakSet/WeakRef with primitive keys — throws — must guard
// grep: Weak(Map|Set|Ref)\(.*\) — ensure arg is object (not string/symbol/number)

// 7) WeakRef double deref or deref().prop without undefined check — race with GC
// grep: WeakRef|\.deref\(\)  — ensure single const target = ref.deref(); if (target !== undefined)

// 8) FinalizationRegistry used for correctness (close handle, release lock) — must have explicit path
// grep: FinalizationRegistry  — require paired try/finally / using alongside registry
```

### 6) **Mentor note**

Have juniors recite the three checks before any collection claim: "SameValueZero? stringification? weak?" If they answer `NaN` in `Map` size, object-key collapse, and `WeakMap.size === undefined` without hesitation, the reflex is landed. In review, ask "which collection would you pick and why?" not "which method name?" — rationale is the signal. Flag silent `Object.keys(new Set(...))` (`[]`) and `JSON.stringify(new Set(...))` (`{}`) surprises.
