## 9.1. Boundaries what is covered elsewhere

### 1) **Event loop queues, promise states, and combinators — [Async Event Loop and Promises](<../../../13 Async Event Loop and Promises/README.md>)**

This domain owns *which* `Error` to throw and how to preserve its chain/stack. The *scheduling* of rejections as microtasks (`Jobs` queue), the `Promise` state machine (pending → fulfilled/rejected, thenable assimilation, `then` always a job), and the combinator contracts (`all` fail-fast vs `allSettled` always-fulfill vs `any` aggregates vs `race` first-settled vs `withResolvers`) remain in [Async Event Loop and Promises](<../../../13 Async Event Loop and Promises/README.md>) — see [promise states](<../../../13 Async Event Loop and Promises/sections/3. Promises core/3.1. Promise states executor thenable assimilation and the job queue.md>) and [chaining](<../../../13 Async Event Loop and Promises/sections/3. Promises core/3.2. Chaining then catch finally and error propagation.md>) there.

### 2) **Generators `yield throw`/`return`, async generators, and iteration closing — [Iterables Generators and Async Iteration](<../../../10 Iterables Generators and Async Iteration/README.md>)**

How `gen.throw(err)` injects into a `yield` pause and `gen.return()` closes, and how `for await...of` translates errors via `IteratorClose`, belong to [Iterables Generators and Async Iteration](<../../../10 Iterables Generators and Async Iteration/README.md>) ([communicating with generators](<../../../10 Iterables Generators and Async Iteration/sections/3. Generators/3.3. Communicating with generators next throw return.md>)). This domain only covers wrapping those injection sites with `cause` and aggregating fan-out (`AggregateError`).

### 3) **Scope/TDZ, closures, `this` parameter handling — [Variables Scope and Closures](<../../../04 Variables Scope and Closures/README.md>), [Functions Deep Dive](<../../../05 Functions Deep Dive/README.md>)**

`ReferenceError` from TDZ ([TDZ](<../../../04 Variables Scope and Closures/sections/1. Declarations and bindings/1.2. Temporal dead zone why early access throws.md>)), scope chain lookup ([scope chain](<../../../04 Variables Scope and Closures/sections/2. Scope and lookup/2.1. First-class and execution patterns/4.3. Recursion stacks and tail-call reality.md>)) define *why* the engine throws; this domain defines *how* to categorize and propagate those throws.

### 4) **Modules evaluation and circular `ReferenceError` — [Modules and Code Organization](<../../../14 Modules and Code Organization/README.md>)**

Static import linking, evaluation order, and the cross-cycle `ReferenceError: Cannot access 'X' before initialization` ([evaluation order](<../../../14 Modules and Code Organization/sections/3. This domain covers mapping those `ReferenceError`s into domain errors with `cause`.

### 5) **Testing assertions (`expect().toThrow`, `assert.throws`) and linting/tooling — Testing and Tooling domain (when it lands)**

How test runners assert on thrown errors (`expect(()=>fn()).toThrow(AppError)` / `assert.throws(() => fn(), {name:"AppError"})`) and how linters (`no-throw-literal`, `prefer-promise-reject-errors`) and formatters enforce error hygiene belong to the future `Testing and Tooling Essentials` domain (planned `20`). This domain stops at runtime handling and debugging; runner APIs are textual forward references until that domain lands.
