## 1.2. Custom errors cause chaining and AggregateError

### 1) **Custom `extends Error` — correct subclass discipline (call `super`, set `name`, preserve `cause`)**

**Definition** — subclassing `Error` creates a named domain error (`NotFoundError`, `ValidationError`) with its own `name` and optional `cause`. Engines capture `stack` at `super()` call; forgetting `super` leaves an uninitialized `this`, wrong `name` leaves `"Error"` in logs.

**What problem it solves / history** — before `cause` (ES2022), libraries passed `innerError` or mangled `message`. Subclasses without `super` broke `instanceof` and stack.

**Modern guidance** — `class MyError extends Error { constructor(msg, opts){ super(msg, opts); this.name = "MyError"; } }`. Pass `cause` via `super(msg, {cause})` not `this.cause =`. In V8, call `Error.captureStackTrace(this, MyError)` to trim constructor frame.

```js
// Correct custom error
class NotFoundError extends Error {
  constructor(id, opts = {}) {
    super(`not found: ${id}`, opts); // opts may contain {cause}
    this.name = "NotFoundError";
    this.id = id;
    if (Error.captureStackTrace) Error.captureStackTrace(this, NotFoundError);
  }
}
class ValidationError extends TypeError {
  constructor(field, msg, opts = {}) {
    super(`${field}: ${msg}`, opts);
    this.name = "ValidationError";
    this.field = field;
  }
}
const e1 = new NotFoundError("42", { cause: new Error("db miss") });
console.log(e1.name, e1.message, e1.cause.message, e1 instanceof Error, e1 instanceof NotFoundError);
console.log(e1.stack.split("\n")[0]);
console.log(new ValidationError("email","invalid").name);

// BAD — name stuck "Error", cause set late (still works but anti-pattern):
class BadError extends Error { constructor(m){ super(m); /* forgot name */ } }
console.log(new BadError("oops").name); // "Error" — worse triage

// GOOD: cause via super — preserves spec chain
const low = new URIError("bad %");
const high = new ValidationError("uri","cannot decode", { cause: low });
console.log(high.cause === low);
```

### 2) **`cause` chaining (ES2022) — the stdlib error chain**

**Definition** — `new Error(msg, {cause})` stores `error.cause` referencing the lower-level error that triggered this one. Chains walk `while (e) { log(e); e = e.cause }`. `stack` does not automatically include `cause` stacks; log both.

**Modern guidance** — wrap at boundary: catch low-level `TypeError` at API edge, rethrow domain error with `{cause: low}` preserving original location. Require `cause` in review for any rethrow that loses context.

```js
// cause chaining — high level wraps low level
function parseUser(json) {
  try { return JSON.parse(json); } catch (low) {
    throw new SyntaxError("invalid user payload", { cause: low });
  }
}
try { parseUser("{bad"); } catch (e) {
  console.log(e.name, e.message);
  console.log("cause:", e.cause.name, e.cause.message.slice(0, 30));
  // Walk chain
  for (let cur = e; cur; cur = cur.cause) console.log(" ->", cur.name, cur.message.slice(0, 25));
}
// Cause stacks are separate — log both
try { parseUser("{x"); } catch (e) {
  console.log("high stack head:", e.stack.split("\n")[0]);
  console.log("cause stack head:", e.cause.stack.split("\n")[0]);
}

// Nested causes — chain of 3
const c1 = new Error("disk full");
const c2 = new Error("write failed", { cause: c1 });
const c3 = new Error("save failed", { cause: c2 });
console.log(c3.cause.cause === c1);

```

### 3) **`AggregateError` (ES2021) — one error holding many (`errors` array)**

**Definition** — `AggregateError(errors, message, {cause})` stores `errors` (`Array`) of per-task errors plus a summary `message`. `Promise.any` rejects with one when *all* inputs reject; manual batch validation collects per-item failures.

**Modern guidance** — use for fan-out where `Promise.all` fail-fast discards the other rejections. Aggregate then branch `e instanceof AggregateError ? e.errors : [e]`. Log both summary and `errors[].stack`.

```js
// AggregateError manually — batch validation
function validateAll(items) {
  const errs = [];
  for (const [i, v] of items.entries()) if (v == null) errs.push(new ValidationError(String(i), "required"));
  if (errs.length) throw new AggregateError(errs, `${errs.length} item(s) invalid`);
  return true;
}
try { validateAll([1, null, 3, null]); } catch (e) {
  console.log(e.name, e.message, e.errors.length);
  for (const sub of e.errors) console.log(" -", sub.name, sub.message);
  console.log(e instanceof AggregateError, e instanceof Error);
}

// Promise.any rejection is AggregateError
(async () => {
  try { await Promise.any([Promise.reject(new Error("a")), Promise.reject(new Error("b"))]); }
  catch (e) { console.log(e.name, e.errors.length, e.errors.map(x=>x.message).join(",")); }
})();

// all vs allSettled vs any vs aggregate
console.log("all fail-fast loses 2nd error; allSettled keeps both; any aggregates when all fail");
const p1 = Promise.reject(new Error("p1"));
const p2 = Promise.reject(new Error("p2"));
Promise.all([p1, p2]).catch(e => console.log("all:", e.message)); // p1 only
Promise.allSettled([p1.catch(e=>{ throw e; }), p2.catch(e=>{ throw e; })]); // verbose — prefer AggregateError
```

### 4) **`SuppressedError` and `using` (ES2024) — disposing throws without losing the primary error**

**Definition** — `Explicit Resource Management` adds `using`/`await using` declarations that call `Symbol.dispose`/`Symbol.asyncDispose` on scope exit. If the body threw *and* disposal throws, the engine creates `SuppressedError` (`name "SuppressedError"`, `error`, `suppressed`) chaining both; `AggregateError` loses ordering, `SuppressedError` preserves primary vs suppressed.

**Modern guidance** — prefer `using` over `try/finally { close() }` where the cleanup itself may throw (file handles, locks, transactions). Without suppression, `finally` throw overwrites the original (see [2.2](<../2. Throwing and catching/2.2. try catch finally mechanics rethrow and nesting.md>)).

```js
// using with SuppressedError — Node 20+/24 needs --harmony or polyfill guard
console.log(typeof SuppressedError, typeof Symbol.dispose);

// Polyfill demonstration when engine lacks using/SuppressedError — manual pattern:
class Resource {
  constructor(name){ this.name = name; }
  [Symbol.dispose](){ console.log("dispose", this.name); /* throw to demo */ }
}
function demoSuppressed() {
  // Manual equivalent of `using r = new Resource("db")` where body and dispose both throw:
  const primary = new Error("primary");
  const suppressed = new Error("close failed");
  // Without SuppressedError, one is lost:
  let thrown = primary;
  try { throw primary; } catch (e) { thrown = e; }
  try { throw suppressed; } catch (sup) {
    // ES2024 SuppressedError preserves both:
    const Suppressed = globalThis.SuppressedError ?? class SuppressedError extends Error {
      constructor(error, suppressed, msg="suppressed"){ super(msg); this.name="SuppressedError"; this.error=error; this.suppressed=suppressed; }
    };
    thrown = new Suppressed(thrown, sup, "cleanup threw while handling primary");
  }
  console.log(thrown.name, thrown.error.message, thrown.suppressed.message);
}
demoSuppressed();

// Real using when available — guarded via Function to avoid SyntaxError on old Node
try {
  const hasUsing = (() => { try { Function("using x = null"); return true; } catch { return false; }})();
  console.log("engine supports `using`:", hasUsing);
  if (hasUsing) console.log("use: { using fh = openSync(...); ... } — exit calls [Symbol.dispose]");
} catch {}

// Cross-link: finally hygiene vs using → [2.2](../2. Throwing and catching/2.2. try catch finally mechanics rethrow and nesting.md), [3.1](../3. Defensive patterns/3.1. Cause wrapping context preservation and suppressed errors.md)
```

### 5) **Common confusion**

- "`cause` is printed in `stack`" — not automatically; V8/Node prints `cause` chain separately with `Caused by:` when logging via `console.error`. Serialize `err.stack + "\nCaused by: " + err.cause.stack` for bare loggers.
- "`AggregateError` extends `Error`" — it does, but `err.message` alone loses per-item messages; always read `err.errors`.
- "`SuppressedError` is `AggregateError`" — different: `SuppressedError` has `error` + `suppressed` (2 slots, ordered); `AggregateError` has `errors` array (many).
- "`Error.isError` is `instanceof`" — `instanceof` fails cross-realm; `Error.isError` (ES2025) correctly identifies errors from any realm.

### 6) **Performance note**

`captureStackTrace` walks the call stack; `Error.stackTraceLimit` defaults to 10 frames (Node). Raising the limit increases allocation per thrown error. In batch validation that throws `AggregateError` with 100 `ValidationError`s, each captures a stack — consider reusing a single stack or truncating `stackTraceLimit` temporarily.

### 7) **Mentor note**

Require `extends Error` + `super(msg, {cause})` + `this.name = ...` in every custom error PR. In review, flag `new Error(msg); err.cause = low` (late assignment misses engines that freeze `cause`). For batch APIs, require `AggregateError` over first-error-only; for resource APIs, require `using` or `try/finally` with `SuppressedError` handling.
