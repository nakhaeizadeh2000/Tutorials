## 4.2. Unhandled rejections AggregateError in combinators and async stack hygiene

### 1) **`unhandledrejection` vs `uncaughtException` — where orphaned rejects go (browser `window`, Node `process`; `rejectionHandled` late handler)**

**Definition** — an *unhandled rejection* is a `Promise` that rejected with no handler attached by the end of the microtask checkpoint. Hosts emit `unhandledrejection` (with `reason`) and `rejectionHandled` if later caught. An *uncaught exception* is a sync `throw` with no `catch`.

**Modern guidance** — every promise must be consumed (`await`/`then`/`catch`/`allSettled`). In Node, `process.on("unhandledRejection")` should log and, with `--unhandled-rejections=strict`, crash to prevent silent loss. Never swallow with empty `catch`.

```js
// Demo handlers — Node process vs window
if (typeof process !== "undefined" && process.on) {
  const onUnhandled = (reason, promise) => console.log("[process unhandledRejection]", reason?.message ?? String(reason));
  const onHandled = (promise) => console.log("[process rejectionHandled] late handler attached");
  process.on("unhandledRejection", onUnhandled);
  process.on("rejectionHandled", onHandled);

  // Orphaned reject triggers unhandledRejection
  const orphan = Promise.reject(new Error("orphan"));
  setTimeout(() => orphan.catch(()=> console.log("late catch — triggers rejectionHandled")), 10);
  setTimeout(() => { process.off("unhandledRejection", onUnhandled); process.off("rejectionHandled", onHandled); }, 50);

  // uncaughtException fires for sync throw with no catch
  process.on("uncaughtException", (e) => console.log("[uncaughtException]", e.message));
  setTimeout(() => process.removeAllListeners("uncaughtException"), 60);
}

// Browser equivalent (guarded):
if (typeof window !== "undefined") {
  // window.addEventListener("unhandledrejection", e => console.log(e.reason));
  console.log("browser path: window.addEventListener('unhandledrejection', ...)");
}

// Correct — always consume:
Promise.reject(new Error("consumed")).catch(e=>console.log("consumed:", e.message));
(async () => { try { await Promise.reject(new Error("awaited")); } catch(e){ console.log("await caught:", e.message); } })();
```

### 2) **Combinator error semantics — `all` fail-fast, `allSettled` never rejects, `any` aggregates, `race` first-settled**

**Definition** — combinators map a set of promises to one: `all` preserves order and rejects on first rejection; `allSettled` always fulfills with per-outcome objects; `any` fulfills on first success else rejects `AggregateError` over all reasons; `race` settles with the first settlement (fulfill or reject).

| Combinator | Resolves when | Rejects when | Per-item errors visible? |
|------------|---------------|--------------|--------------------------|
| `all` | all fulfill | first rejection wins | no — loses losers unless `cause` |
| `allSettled` | all settled | never rejects | yes — `{status:"rejected", reason}` per entry |
| `any` | first fulfill | `AggregateError` when all reject | yes — `errors` |
| `race` | first fulfill/reject wins | same as fulfill but rejection race | no — losers leak |
| `withResolvers` | manual resolve/reject | holds cause | caller controls |

**Modern guidance** — choose by intent: `any` when *any* success suffices; `allSettled` for batch reporting; `all` for fail-fast transaction; `race` for timeout pattern but always abort losers via `AbortSignal`.

```js
// all vs allSettled vs any vs race
const ok = (v,d=5) => new Promise(r=>setTimeout(()=>r(v), d));
const fail = (msg,d=5) => new Promise((_,r)=>setTimeout(()=>r(new Error(msg)), d));

Promise.all([ok("a"), fail("p1"), ok("c")]).catch(e=>console.log("all:", e.message)); // fail fast — p1 only
Promise.allSettled([ok("a"), fail("p1"), fail("p2")]).then(v=>console.log("allSettled:", v.map(x=> x.status + ":" + (x.reason?.message ?? x.value))));
Promise.any([fail("p1"), fail("p2")]).catch(e=>console.log("any AggregateError?", e instanceof AggregateError, e.errors.map(x=>x.message)));
Promise.any([fail("p1"), ok("b")]).then(v=>console.log("any first success:", v));
Promise.race([fail("fast"), ok("slow", 20)]).catch(e=>console.log("race fast reject:", e.message));

// Leak hazard — losing losers without abort:
async function withTimeoutRace(task, ms){
  // BAD — loser still runs leaked
  // const r = await Promise.race([task, new Promise((_,rj)=> setTimeout(()=>rj(new Error("timeout")), ms))]);
  // GOOD — abort losers:
  const ac = new AbortController();
  const timeout = new Promise((_,rj)=> setTimeout(()=> { ac.abort(); rj(new Error("timeout")); }, ms));
  try { return await Promise.race([task, timeout]); }
  finally { clearTimeout(timeout._id); }
}
console.log("combinators + abort hygiene above");

// withResolvers — deferred without executor anti-pattern:
const { promise, reject } = Promise.withResolvers();
promise.catch(e=>console.log("withResolvers reject:", e.message));
reject(new Error("deferred"));
```

### 3) **Async stack hygiene — `await` preserves cause chains; parallel `Promise.all` loses per-task stacks without `cause`**

**Definition** — V8 `async` stacks stitch `await` suspension points; `Promise.all([...])` without per-task `cause` loses which task failed. Attaching `cause` per item + aggregating preserves triage: `throw new AppError("batch", {cause: low})` per task then `AggregateError`.

**Modern guidance** — for fan-out batches, map each task to `catch (e) { throw new AppError("task "+i, {cause:e}) }` before `all`, or prefer `allSettled` and aggregate manually. Always walk `cause` + `aggregate` in logs.

```js
class TaskError extends Error { constructor(id, opts){ super(`task ${id} failed`, opts); this.name="TaskError"; this.id=id; } }

// BAD — all loses which task's stack mattered:
async function badBatch(ids){
  const tasks = ids.map(id => (async ()=>{ if(id===2) throw new Error("db 2"); return id; })());
  return Promise.all(tasks); // rejects with Error("db 2") but no id context
}
badBatch([1,2,3]).catch(e=>console.log("badBatch lost context:", e.message));

// GOOD — attach cause per task, aggregate
async function goodBatch(ids){
  const tasks = ids.map(async id => {
    try { if(id===2) throw new Error("db miss "+id); return id; }
    catch (low){ throw new TaskError(id, { cause: low }); }
  });
  const settled = await Promise.allSettled(tasks);
  const errs = settled.filter(x=>x.status==="rejected").map(x=>x.reason);
  if(errs.length) throw new AggregateError(errs, `${errs.length} task(s) failed`);
  return settled.filter(x=>x.status==="fulfilled").map(x=>x.value);
}
goodBatch([1,2,3]).catch(e=>{
  console.log("goodBatch", e.name, e.message, e.errors.map(x=> x.name+":"+x.cause.message));
  for(const sub of e.errors) console.log(" stack:", sub.stack.split("\n")[0], "caused by", sub.cause.stack.split("\n")[0]);
});

// await vs .then stack note — await stitches:
async function a(){ await b(); }
async function b(){ throw new Error("from b"); }
a().catch(e=> console.log("await stitched stack includes b and a?\n", e.stack.split("\n").slice(0,4).join("\n")));
// With then without await, caller frame missing — prefer await for hygiene:
Promise.resolve().then(()=>{ throw new Error("then throw"); }).catch(e=> console.log("then stack head:", e.stack.split("\n")[0]));

// Cross-link: try/catch mechanics vs using — see 2.2 try catch finally mechanics (link verified via python checker)
```

### 4) **Common confusion**

- "`unhandledRejection` means crash" — in Node default (`warn`) it logs; with `--unhandled-rejections=strict` it throws (`uncaughtException`). Browser fires `unhandledrejection` event but does not crash.
- "`allSettled` rejects" — it never rejects; it always fulfills with `{status,value/reason}`.
- "`any` and `race` are same" — `race` settles on first *any* settlement (including rejection); `any` settles on first *fulfillment* and rejects `AggregateError` only when all reject.
- "Rejection reason is always `Error`" — `Promise.reject("string")` works, but breaks `cause`/`stack` hygiene; always `reject(new Error(...))`.

### 5) **Performance note**

`allSettled` on 10k items allocates 10k result objects plus stacks for each rejected item. Prefer bounded concurrency (`p-limit`) or streaming to keep heap bounded. Each unhandled rejection emits an event and may retain the promise graph until handled — handle immediately.

### 6) **Mentor note**

Require every `Promise` branch to have a consumer (`await`/`catch`/`allSettled`/`return`). In review, flag `map(async ...)` without `await Promise.all|allSettled` — that leaves orphans. For timeouts, require `AbortSignal` wired through. For batches, require per-task `cause` + `AggregateError` or `allSettled` reporting; ban bare `all` for user-visible bulk jobs.
