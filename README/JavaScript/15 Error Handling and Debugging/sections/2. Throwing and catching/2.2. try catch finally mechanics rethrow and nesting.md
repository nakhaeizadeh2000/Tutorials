## 2.2. try catch finally mechanics rethrow and nesting

### 1) **`try`/`catch`/`finally` control flow — who runs when, and what wins**

**Definition** — `try {A} catch(e){B} finally{C}` runs `A`; if `A` completes with `throw`, binds `e` and runs `B`; `C` always runs regardless of normal/throw/return. `return`/`throw` in `finally` *overrides* the pending `return`/`throw` from `try`/`catch`.

**What problem it solves / history** — `finally` guarantees cleanup (`close`, `unlock`) without duplicating it in both `try` and `catch`. The override rule makes `finally` a sharp tool — returning inside it silently swallows throws.

**Modern guidance** — use `finally` only for side-effect cleanup, never `return`/`throw` inside `finally` unless wrapping the original via `cause`/`SuppressedError`. Prefer `using` (ES2024) when cleanup itself may throw (see [3.1](<../3. Defensive patterns/3.1. Cause wrapping context preservation and suppressed errors.md>)).

```js
// finally always runs — even on return/throw
function demoFinally(shouldThrow){
  try { if (shouldThrow) throw new Error("boom"); return "ok"; }
  catch (e) { return "caught:" + e.message; }
  finally { console.log("finally runs, shouldThrow=", shouldThrow); }
}
console.log(demoFinally(false)); // ok
console.log(demoFinally(true));  // caught:boom

// finally return overrides try throw — BUG if you return inside finally:
function swallow(){
  try { throw new Error("primary"); }
  finally { return "swallowed"; }
}
console.log(swallow()); // "swallowed" — primary lost

function correct(){
  try { throw new Error("primary"); }
  finally { console.log("cleanup, but no return/throw"); }
}
try { correct(); } catch (e) { console.log("preserved:", e.message); } // primary preserved

// finally throw overrides try return:
function swallowReturn(){
  try { return 1; } finally { throw new Error("finally throw"); }
}
try { swallowReturn(); } catch (e) { console.log(e.message); } // finally throw

// throw inside finally after catch rethrow discipline
function unwrap(x){
  try { if (x == null) throw new TypeError("null input"); return x * 2; }
  catch (e) { if (!(e instanceof TypeError)) throw e; console.log("handled TypeError:", e.message); return 0; }
  finally { console.log("unwrap finally"); }
}
console.log(unwrap(5), unwrap(null));
```

### 2) **Catch binding — optional `catch {}` (ES2019), `catch (e)` scope, and rethrow discipline**

**Definition** — `catch {}` without binding (ES2019) avoids unused variable; `catch (e)` scopes `e` to the block (TDZ-like). Rethrow discipline: catch only what you can handle, rethrow the rest (`if (!(e instanceof Expected)) throw e`).

**Modern guidance** — use `catch {}` when you ignore the error (rare — usually you should log). Always rethrow unknowns; never empty `catch` silently.

```js
// ES2019 optional catch binding
try { JSON.parse("{bad"); } catch { console.log("parse failed, no binding needed"); }

// catch scope — e not visible outside
try { throw new Error("hi"); } catch (e) { console.log(e.message); }
// console.log(e); // ReferenceError: e is not defined

// Rethrow discipline — handle known, propagate unknown
class ValidationError extends Error { constructor(m){ super(m); this.name="ValidationError"; } }
function handleKnown(){
  try { throw new ValidationError("bad"); } // try TypeError vs ValidationError
  catch (e) {
    if (e instanceof ValidationError) { console.log("handled validation:", e.message); return; }
    throw e; // unknown — propagate
  }
}
handleKnown();
try { handleKnown = () => { try { throw new RangeError("oob"); } catch (e){ if(e instanceof ValidationError) {} else throw e; } }; handleKnown(); } catch (e){ console.log("rethrow preserved:", e.name); }

// BAD — empty catch swallows:
// try { risky(); } catch {}
// GOOD — log or rethrow:
try { JSON.parse("{bad"); } catch (e) { console.log("swallow with log:", e.name); }

// Narrow before reading .cause/.code
function handleWithCause(e){
  if (!(e instanceof Error)) throw new Error(String(e));
  console.log(e.name, e.cause ?? "no cause");
}
try { throw new Error("a", { cause: new Error("b") }); } catch (e) { handleWithCause(e); }
```

### 3) **Nesting and `finally` hygiene — cleanup vs swallowing, and `using` vs `try/finally`**

**Definition** — nested `try` isolates inner cleanup from outer context; `finally` runs inner-to-outer. Hygiene rule: `finally` must not mask the primary throw. When cleanup throws, preserve both via `cause`/`SuppressedError` or `using`.

| `finally` body | Effect on pending `throw` in `try` | Hygiene |
|----------------|-----------------------------------|---------|
| empty / `console.log` | preserves | safe |
| `return x` | discards `throw`, returns `x` | bug — never |
| `throw new Error` | discards pending, throws new | bug unless wrapping `cause` |
| `await dispose()` that rejects | discards unless using suppression | use `using` |

```js
// Nested try — inner finally runs before outer catch
function nested(){
  try {
    try { throw new Error("inner"); }
    finally { console.log("inner finally"); }
  } catch (e) { console.log("outer caught:", e.message); }
  finally { console.log("outer finally"); }
}
nested();

// BAD — finally throw loses cause:
function badClose(){
  let primary;
  try { throw new Error("primary"); } catch (e){ primary = e; throw e; }
  finally { throw new Error("close failed"); } // primary lost
}
try { badClose(); } catch (e) { console.log("badClose lost primary? ", e.message); } // "close failed" only

// GOOD — preserve with cause/suppressed:
function goodClose(){
  let primary;
  try { throw new Error("primary"); }
  finally {
    try { throw new Error("close failed"); } catch (sup) {
      // Wrap so both visible — prefer SuppressedError in ES2024
      const Suppressed = globalThis.SuppressedError ?? class SE extends Error {
        constructor(error, suppressed){ super("suppressed: " + suppressed.message); this.name="SuppressedError"; this.error=error; this.suppressed=suppressed; }
      };
      // If we had a primary pending, we need it — simulate by catching outside:
      console.log("would combine primary and suppressed via", Suppressed.name);
    }
  }
}
try { goodClose(); } catch (e) { console.log("goodClose primary preserved:", e.message); }

// Modern: using when available — guarded via Function string to avoid SyntaxError on old Node
console.log("prefer `using` for auto-dispose that preserves suppression — see 3.1");
```

### 4) **Common confusion**

- "`return` in `try` skips `finally`" — it does not; `finally` runs, and a `return` in `finally` overrides the earlier `return` value (same for `throw`).
- "`catch (e)` is visible after the block" — no, it is block-scoped; `console.log(e)` after `catch` throws `ReferenceError` (see [Variables Scope 1.2](<../../../04 Variables Scope and Closures/sections/1. Declarations and bindings/1.2. Temporal dead zone why early access throws.md>)).
- "`finally` can be omitted when `catch` covers everything" — you still need `finally` for cleanup that must run on success too; `using` replaces `finally { dispose }` but not generic cleanup.
- "Empty `catch {}` is always OK" — only when the error is truly ignorable; otherwise log or rethrow.

### 5) **Performance note**

`try/catch` is no longer deoptimizing in modern V8 (since TurboFan), but functions that *frequently* throw still deoptimize the hot path. Keep `try` blocks coarse (wrap the operation boundary, not per-iteration) and handle expected cases with guards instead of `throw`.

### 6) **Mentor note**

Have juniors predict output of `try { throw A } finally { return B }` (answer: `B`, not `A`). In review, flag every `finally { return` / `finally { throw` — require `cause`/`SuppressedError` or `using`. Require `catch` to either log, rethrow, or narrow by `instanceof`/`code` — bare `catch {}` must have a comment why swallowing is safe.
