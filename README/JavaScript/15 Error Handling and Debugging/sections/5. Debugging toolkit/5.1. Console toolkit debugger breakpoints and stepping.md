## 5.1. Console toolkit debugger breakpoints and stepping

### 1) **Console levels — `log`/`info`/`warn`/`error`/`debug`/`trace`/`table`/`group`/`time`/`count`**

**Definition** — `console` is host-provided (browser DevTools + Node `node:console`) with levels that map to filtered streams: `debug` (verbose), `log`/`info` (stdout), `warn`/`error` (stderr), plus diagnostics `trace` (stack), `table` (tabular), `group`/`groupEnd` (nesting), `time`/`timeEnd` (timer), `count`/`countReset` (counter), `assert` (non-throwing).

**Modern guidance** — emit at correct level: `error` for failures, `warn` for degraded, `debug` for dev-only breadcrumbs. Gate `debug` via `DEBUG=*` or `process.env.NODE_ENV`. Use `trace`/`table` for triage not decoration.

```js
console.log("log — stdout");
console.info("info — alias of log in Node");
console.warn("warn — stderr + yellow");
console.error("error — stderr + red");
console.debug("debug — filtered unless verbose (Node shows when --trace-warnings or DEBUG)");

// trace prints a stack without throwing
function a(){ b(); }
function b(){ console.trace("trace from b"); }
a();

// table for arrays/objects
console.table([{ id:1, err:"ENOENT" }, { id:2, err:"EACCES" }]);

// group + count + time
console.group("batch");
console.count("item");
console.count("item");
console.time("work");
for(let i=0;i<1e6;i++){}
console.timeEnd("work");
console.groupEnd();

// assert logs but does not throw — see 3.2 for invariant throws
console.assert(1===2, "this logs Assertion failed but continues — not a throw");

// Node: console is not synchronous — for crash logs, use console.error (stderr flushed faster)
console.error("stderr flush demo");
```

### 2) **`debugger` statement, `break`/`conditional` breakpoints, and `step` vs `stepOver`**

**Definition** — `debugger;` is a statement that pauses when an inspector is attached, otherwise a no-op. DevTools/Node inspector breakpoints are metadata (`break` at line/col, conditional `expr`, `logpoint` `console.log` without pausing). `step` enters callees, `stepOver` stays in current frame, `stepOut` returns to caller.

**Modern guidance** — leave `debugger;` during development behind a guard (`if (process.env.DEBUG) debugger;`) and strip or gate in CI via lint (`no-debugger`). For production postmortem, prefer logging + stacks over pausing.

```js
function sum(arr){
  let s=0;
  for(const x of arr){
    // Conditional breakpoint equivalent — pause when x > 10
    if (x > 10) { debugger; } // no-op unless --inspect
    s += x;
  }
  return s;
}
console.log(sum([1, 12, 3])); // when attached, pauses at x=12

// Logpoint alternative without pausing (DevTools sets `console.log(x)` at this line):
function work(n){ console.log("work", n); }
for(let i=0;i<3;i++) work(i);

// Step semantics (describe — not executable without UI):
console.log("step — into sum -> into loop body");
console.log("stepOver — over sum call, stays at caller");
console.log("stepOut — from loop body back to caller");

// Blackboxing — skip library frames (e.g., node_modules) to focus on your code
console.log("Node --inspect: DevTools > Settings > Ignore List > add node_modules");

// Guarded debugger for programmatic use:
const DEBUG = false;
function maybeDebug(v){ if(DEBUG) debugger; return v; }
console.log(maybeDebug(42));
```

### 3) **Watch, scope, and evaluate — call stack, closure scope, `watch` expressions, and live edit**

**Definition** — when paused, inspectors show *call stack* (frames with `function (file:line:col)`), *scope chain* (local → closure → module/global), and evaluated `watch` expressions that re-evaluate per pause. Hosts support live edit (hot patch) for the current session.

**What to look at / history** — TDZ bindings show `<uninitialized>` until their initializer runs ([Variables Scope 1.2](<../../../04 Variables Scope and Closures/sections/1. Declarations and bindings/1.2. Temporal dead zone why early access throws.md>)); closure variables show the birth environment ([Variables Scope 3.1](<../../../04 Variables Scope and Closures/sections/3. Closures/3.1. Closures functions that remember their birth environment.md>)) not the caller.

```js
function outer(secret){
  let count = 0;
  return function inner(x){
    debugger; // inspect: closure {secret, count}, local {x}
    count += x;
    return secret + count;
  };
}
const fn = outer("hi-");
console.log(fn(5));
console.log(fn(3));

// Scope illustration — TDZ vs closure vs local
function scopeDemo(){
  // console.log(tdz); // ReferenceError — TDZ before let
  let tdz = 1;
  let a = tdz + 1; // watch: a === 2, tdz initialized
  debugger;
  console.log(a);
}
scopeDemo();

// Watch expressions evaluate in paused frame — can call functions:
function add(a,b){ return a+b; }
function watched(){
  const x = 10;
  debugger; // watch: add(x, 5) === 15
  console.log(add(x, 5));
}
watched();

// Live edit note — inspector can patch function body during pause without restart
console.log("DevTools Sources > file > edit > Cmd+S — hot patch for triage");
```

### 4) **Common confusion**

- "`console.log` is synchronous and flushed before crash" — not guaranteed; `stdout` buffers. `console.error` (stderr) flushes sooner; for crash dumps, log to `stderr` or `process.stderr.write`.
- "`debugger;` pauses always" — only when inspector attached (`node --inspect`, `chrome://inspect`). Otherwise it is a no-op (mint linter sees dead code — gate behind `if (DEBUG)`).
- "`debugger;` vs breakpoint is same cost" — `debugger` is source-resident and ships, breakpoints are session metadata and do not ship. Prefer breakpoints for local triage, `debugger` for reproducing in attached runs.
- "`stepOver` skips errors" — it still stops on `throw` in the stepped line; the error bubbles to `catch` before next pause.

### 5) **Performance note**

Excessive `console.log` in hot loops allocates strings and serializes objects (e.g., `console.table` on 10k rows). Gate with `if (DEBUG)` or use `debug` npm package (no-op unless enabled). `console.trace` allocates a stack — avoid in hot paths.

### 6) **Mentor note**

Have juniors use `console.trace` to explain where a shared helper was called from (teaches stack reading). In review, flag `console.log(err)` without `console.error` + `err.stack` — raw `err` may coerce to `[object Object]`. Require `logpoint` over `debugger` for no-pause production triage notes.
