## 1.1. Object literals: shorthand, computed properties, concise methods, and spread

### 1) **Shorthand and computed keys**

**Definition** — an object literal `{ ... }` builds an ordinary object. Inside it you can use three syntactic shortcuts: *shorthand* (`{ x }` means `{ x: x }`), *computed keys* (`{ [expr]: value }` evaluates `expr` at creation time), and mixing both with regular `key: value` pairs. Keys are always strings or symbols — non-string expressions are coerced via [ToPropertyKey](<../../../03 Values Types and Coercion/sections/2. The conversion algorithms/2.3. ToPrimitive and the valueOf toString and Symbol.toPrimitive dance.md>) (which stringifies via [ToString](<../../../03 Values Types and Coercion/sections/2. The conversion algorithms/2.2. ToString and ToNumber the exact conversion tables.md>)).

*What problem it solves* — before ES2015 you repeated the variable name on both sides (`{ x: x, y: y }`) and needed a temporary variable to build a dynamic key (`obj[key] = value` after creation). Shorthand removes the duplication; computed keys let the dynamic name live inside the literal where it belongs.

```js
// Shorthand: identifier name becomes both key and value
const x = 10, y = 20;
const p1 = { x, y };
console.log(p1); // { x: 10, y: 20 }
console.log(p1.x === x && p1.y === y); // true

// Computed keys: expression in brackets is evaluated NOW, left-to-right, insertion-ordered
const key = "port";
const id = 7;
const config = {
  [key]: 3000,           // → { port: 3000 }
  ["id-" + id]: true,    // expression — runs at creation
  [Symbol("hidden")]: 42 // symbol key — exempt from string coercion
};
console.log(config.port); // 3000
console.log(config["id-7"]); // true
console.log(Object.keys(config)); // [ 'port', 'id-7' ] — symbol hidden (→ [2.3](../2. Properties and descriptors/2.3. Enumerability enumeration order and for-in mechanics.md))

// Computed keys coerce via ToPropertyKey — objects become "[object Object]"
const objKey = {};
const weird = { [objKey]: 1, [42]: 2, [null]: 3 };
console.log(weird); // { '42': 2, '[object Object]': 1, null: '3'? } — order is integer indices first (→ [2.3](../2. Properties and descriptors/2.3. Enumerability enumeration order and for-in mechanics.md))
console.log(weird["42"] === weird[42]); // true — numeric keys are strings
console.log(weird["[object Object]"]); // 1

// Duplicate keys: last wins (no error even in strict mode), evaluated left to right
const dup = { a: 1, a: 2, ["a"]: 3 };
console.log(dup.a); // 3 — last definition wins; linter usually warns
```

- Modern guidance: use shorthand everywhere the variable name *is* the API name; prefer computed keys over post-creation `obj[k]=v` when the key is known at construction — the literal shows the full shape in one place. Keep computed expressions pure (no side effects besides the key string) so reading the literal tells you the shape.

### 2) **Concise methods vs function properties**

**Definition** — `{ method() {} }` defines a *concise method*; `{ method: function() {} }` and `{ method: () => {} }` define function-valued data properties. They look similar but differ in `super`, `name`, `enumerable`, and constructibility — see [Methods](<../../../05 Functions Deep Dive/sections/1. Function forms and the function object/1.3. Methods getters setters and the function object.md>) for the function side, [Descriptors](<../2. Properties and descriptors/2.1. Data vs accessor descriptors and attribute defaults.md>) for `enumerable`.

```js
const base = { greet() { return "hi"; } };

const obj = {
  // Concise method — has [[HomeObject]] for super, not constructible as data property is
  hello() { return super.greet() + " from obj"; },
  // Longhand — ordinary function property; super is SyntaxError here
  longhand: function () { return "long"; },
  // Arrow — captures surrounding this, no prototype, no super
  arrow: () => "arrow",
  // Accessor pair — needs literal form (→ [2.1](../2. Properties and descriptors/2.1. Data vs accessor descriptors and attribute defaults.md))
  get answer() { return 42; },
  set answer(v) { console.log("set to", v); }
};
Object.setPrototypeOf(obj, base);
console.log(obj.hello()); // hi from obj — super walks [[HomeObject]] → base
console.log(obj.longhand()); // long
console.log(Object.getOwnPropertyDescriptor(obj, "hello").enumerable); // true — concise methods are enumerable
console.log(typeof obj.arrow.prototype); // undefined — arrows have no prototype
console.log(obj.answer); // 42 — getter invokes on access
obj.answer = 99; // set to 99

// Name inference
console.log(obj.hello.name); // hello — concise method infers key as name
console.log(obj.longhand.name); // longhand — same inference for function expression
console.log(obj.arrow.name); // arrow

// Common mistake: arrow as method needing dynamic this
const counter = { count: 0, inc: () => { return this; } }; // top-level this
console.log(counter.inc() === globalThis || counter.inc() === undefined); // true — arrow ignores receiver (→ [3.1](../../../05 Functions Deep Dive/sections/3. this binding/3.1. Call-site rules default implicit explicit new and strict mode.md))
```

- *History* — ES2015 introduced all three literal upgrades together (shorthand, computed, concise). Before them, every object shape required `key: value` and `method: function` noise, and computed keys needed mutation after creation.
- Modern guidance: default to **concise methods** for behavior that needs `super` or dynamic `this`; use arrow properties only for lexically-bound callbacks (and prefer class fields for that pattern — see Prototypes domain forward ref). Use `get`/`set` only when access must compute/validate — otherwise keep a plain data property (simpler descriptor, faster path).

### 3) **Spread in literals is shallow copy with last-wins overwrite**

**Definition** — `{ ...a, ...b, x: 1 }` copies *enumerable own* properties (string and symbol) from each source, shallowly, left-to-right; later sources overwrite earlier keys. It is syntax for [Object.assign](<./1.2. Creation patterns literal Object create and constructors.md>) without the setter/getter invocation asymmetry of `assign` (spread never invokes accessors on the source — it reads the value; on the target it defines a data property).

```js
// Shallow, enumerable-own only, last wins
const defaults = { port: 3000, host: "localhost", nested: { a: 1 } };
const overrides = { port: 8080 };
const merged = { ...defaults, ...overrides, extra: true };
console.log(merged); // { port: 8080, host: 'localhost', nested: { a: 1 }, extra: true }
console.log(merged.nested === defaults.nested); // true — SHALLOW: nested is shared

// Non-enumerable and inherited skipped
const source = Object.defineProperties({}, {
  visible: { value: 1, enumerable: true },
  hidden:  { value: 2, enumerable: false }
});
Object.setPrototypeOf(source, { inherited: 3 });
console.log({ ...source }); // { visible: 1 } — hidden non-enumerable, inherited ignored

// Spread does NOT preserve descriptors — always creates plain data properties
const withGetter = { get x() { console.log("getter ran"); return 1; } };
console.log(Object.getOwnPropertyDescriptor(withGetter, "x")); // accessor
const copied = { ...withGetter };
console.log(Object.getOwnPropertyDescriptor(copied, "x")); // { value: 1, writable: true, ... } — getter invoked once, copied as data
console.log(copied.x); // 1 — no getter anymore

// Throws on null/undefined sources (like assign) but null/undefined literal keys are fine
console.log({ ...null, ...undefined, a: 1 }); // { a: 1 } — spec skips null/undefined spreads (ES2018 fix)
try { Object.assign({}, null); } catch (e) { console.log(e.name); } // actually assign also skips null/undefined — both safe since ES2015
console.log({ ...{ a: 1 }, a: 2 }); // { a: 2 } — later literal wins over spread

// Array spread into object creates index keys (rare — usually a bug)
console.log({ ...["a", "b"] }); // { '0': 'a', '1': 'b' }
```

- *Bad vs good* — `const clone = Object.assign({}, obj)` and `const clone = { ...obj }` are equivalent for shallow cloning of enumerable own data; prefer spread for literals (shorter, no target mutation), `assign` when the target already exists or when you need its "invoke setters" semantics. Both are shallow — deep clone needs `structuredClone` (→ JSON domain forward ref) or a recursive walk.

### 4) **Common confusion**

- "`{ [k]: v }` keeps `k` as an object key" — no; keys are always string or symbol. Objects stringify to `"[object Object]"`; numbers stringify; only symbols survive as symbols.
- "`{ ...obj }` deep-clones" — no; nested objects, arrays, and functions are shared by reference. Mutating `clone.nested.x` mutates `obj.nested.x`.
- "`{ method() {} }` is just sugar for `method: function() {}`" — close but not identical: concise methods have `[[HomeObject]]` for `super`, are not `constructible` the same way in class contexts, and share the same `enumerable: true` but their `prototype` handling mirrors method semantics.
- "`...null` throws" — no; spreading `null`/`undefined` into a literal is a no-op (since ES2018). Older transpilers polyfilled this differently — check baseline if targeting pre-2018.

### 5) **Performance note**

Literal shape dictates hidden-class (V8 `Map`) creation. One literal with a stable key set compiles to a single map; spreading many small objects into one literal still creates one result map but reads each source. Prefer adding properties in the literal over `obj[k]=v` after birth — out-of-order adds can transition the map and deoptimize. Computed keys evaluated at creation are cheaper than post-creation `defineProperty` (which always takes the slow path). As ever, [measure](<../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md>) — object-create cost dominates only in tight loops that allocate thousands per frame.

### 6) **Mentor note**

Have juniors predict `Object.keys({ ...source })` for a source with non-enumerable/hidden/inherited keys — if they answer "only `visible`", the enumerable-own model is solid. Review checklist: flag `{ [obj]: 1 }` (likely `obj` mistaken for a Map key — use `Map` instead), arrow methods needing `this`, and deep-mutation after spread (`clone.nested.x = 2` intended as isolated but aliasing the original).
