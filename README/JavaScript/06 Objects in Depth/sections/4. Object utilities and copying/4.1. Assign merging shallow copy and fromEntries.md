## 4.1. Assign, merging, shallow copy, and fromEntries

### 1) **Object.assign copies enumerable own string+symbol properties shallowly**

**Definition** — `Object.assign(target, ...sources)` iterates each source's enumerable own string and symbol keys in `Reflect.ownKeys` order (integers ascending → strings insertion → symbols insertion), and for each key does `target[key] = source[key]` (a plain assignment — getters on source run, setters on target run). It returns the mutated `target`. The operation is **shallow**: non-enumerable keys are ignored, accessors are unwrapped to values, nested objects are shared by reference, and later sources overwrite earlier keys (last wins).

```js
// Basic shallow merge — later sources win
const defaults = { port: 3000, host: "localhost", nested: { retries: 3 } };
const env = { port: 8080 };
const merged = Object.assign({}, defaults, env, { extra: 1 });
console.log(merged); // { port: 8080, host: 'localhost', nested: { retries: 3 }, extra: 1 }
console.log(merged.nested === defaults.nested); // true — shallow share, not clone

// Enumerable-own only: non-enumerable and inherited ignored; symbols copied
const source = Object.defineProperties(Object.create({ inherited: 2 }), {
  visible:  { value: 1, enumerable: true },
  hidden:   { value: 2, enumerable: false },
  [Symbol("s")]: { value: 3, enumerable: true }
});
console.log(Object.assign({}, source)); // { visible: 1, [Symbol(s)]: 3 } — hidden non-enumerable + inherited excluded

// Getters and setters are invoked, not copied as descriptors
const src = { get x() { console.log("getter"); return 42; } };
const tgt = { set x(v) { console.log("setter", v); this._x = v; } };
Object.assign(tgt, src); // logs getter then setter — value 42 transferred
console.log(Object.getOwnPropertyDescriptor(tgt, "x")); // { value: 42, ... }? No — setter consumed, tgt has _x
console.log(tgt._x); // 42
console.log(Object.getOwnPropertyDescriptor(src, "x")); // accessor — source untouched

// Null/undefined sources are skipped (since ES2015); non-object target throws; primitives are boxed then skipped for non-keys
console.log(Object.assign({}, null, undefined, { a: 1 })); // { a: 1 } — safe skip
console.log(Object.assign({}, "hi")); // { '0': 'h', '1': 'i' } — string boxes to array-like enumerable indices

// Return value is the target identity — often the "extend this" pattern
const obj = { a: 1 };
const ret = Object.assign(obj, { b: 2 });
console.log(ret === obj); // true — mutated in place
```

- *Spread vs assign* — `{ ...a, ...b }` (→ [1.1](../1. Object creation and literals/1.1. Object literals shorthand computed properties and spread.md>)) copies the same enumerable-own set but **defines** data properties (`DefineOwnProperty`) instead of assigning — it does not trigger setters on the result and does not invoke getters twice. For plain data bags they are equivalent; prefer spread when creating a fresh object, `assign` when mutating an existing target.

### 2) **Spread and assign share the same shallow-copy contract**

Both operations copy **references** for nested structures. Mutating a nested object after the copy mutates both views — the classic shallow-clone bug (→ [6.1](../6. Important points to remember/6.1. Object checklist reflex rules mentors screen for.md>) / [7.1](../7. Common pitfalls to production bugs/7.1. Real production bugs caused by object mistakes.md>)).

```js
// Shallow sharing surprise
const original = { outer: 1, inner: { x: 1 }, arr: [1, 2] };
const cloneAssign = Object.assign({}, original);
const cloneSpread = { ...original };
console.log(cloneAssign.inner === original.inner); // true — shared
console.log(cloneSpread.arr === original.arr); // true — shared
cloneAssign.inner.x = 99;
console.log(original.inner.x); // 99 — mutation leaked to source

// Deep clone needs recursion or structuredClone (forward ref to JSON domain) — not assign/spread
const deep = typeof structuredClone === "function" ? structuredClone(original) : JSON.parse(JSON.stringify(original));
console.log(deep.inner === original.inner); // false — deep copies nested
console.log(deep.inner.x); // 99 — current snapshot includes mutated 99; fresh clone after fix would be 1 with a proper deep utility

// Getter invocation count differs subtly
let getCalls = 0;
const withGetter2 = { get n() { getCalls += 1; return 1; } };
getCalls = 0; Object.assign({}, withGetter2); console.log(getCalls); // 1
getCalls = 0; const _ = { ...withGetter2 }; console.log(getCalls); // 1 — both invoke once; difference is on TARGET side (setter vs define)

// Primitive target boxing then property copy (rare — usually a lint target)
console.log(Object.assign({}, 42)); // {} — Number(42) has no enumerable keys
```

- *History* — `Object.assign` is ES2015; object spread is ES2018. Both now baseline "widely available". Older code manually looped `for (k in src) if (hasOwn(src,k)) target[k]=src[k]` — same shallow semantics but skipped symbols.

### 3) **Object.fromEntries reverses entries → object**

**Definition** — `Object.fromEntries(iterable)` takes an iterable of `[key, value]` pairs (usually `Object.entries` output, `Map` entries, or a generator) and **defines** enumerable data properties in insertion order, coercing keys via `ToPropertyKey`. Duplicate keys last-wins; symbol keys round-trip if the pairs carry them.

```js
// Round-trip: entries → transform → fromEntries
const srcObj = { a: 1, b: 2, c: 3 };
const filtered = Object.fromEntries(
  Object.entries(srcObj).filter(([k, v]) => v > 1)
);
console.log(filtered); // { b: 2, c: 3 }

// Key coercion: non-string/symbol keys become strings (objects → "[object Object]")
const pairs = [[42, "num"], [null, "nil"], [{}, "obj"]];
console.log(Object.fromEntries(pairs)); // { '42': 'num', null: 'nil', '[object Object]': 'obj' }

// Duplicate keys: last wins (same as assign/spread)
console.log(Object.fromEntries([["a", 1], ["a", 2]])); // { a: 2 }

// Map → object (but Map supports object keys; plain object cannot — use Map directly)
const map = new Map([[1, "one"], [2, "two"], ["a", "A"]]);
console.log(Object.fromEntries(map)); // { '1': 'one', '2': 'two', a: 'A' } — numeric keys become integer-index strings
console.log(typeof Object.keys(Object.fromEntries(map))[0]); // string — "1" even though Map key was number 1

// Symbol round-trip
const sym = Symbol("id");
const withSym = Object.fromEntries([[sym, 99], ["plain", 1]]);
console.log(withSym[sym]); // 99 — symbol key preserved
console.log(Object.getOwnPropertySymbols(withSym)); // [ Symbol(id) ]

// Framework pattern: correct merge with fromEntries vs naive concat
function zipMerge(keys, values) {
  return Object.fromEntries(keys.map((k, i) => [k, values[i]]));
}
console.log(zipMerge(["x", "y"], [10, 20])); // { x: 10, y: 20 }
```

- Edge case — `Object.fromEntries` always defines data properties with `writable/enumerable/configurable: true`, regardless of source descriptor. It cannot reconstruct non-enumerable or accessor descriptors; for descriptor-preserving reconstruction use `Object.getOwnPropertyDescriptors` + `Object.defineProperties` (→ [2.2](../2. Properties and descriptors/2.2. Defining observing and configuring properties.md>)).

### 4) **Common confusion**

- "`assign` deep-clones" — never; nested structures stay shared. Use `structuredClone` for deep acyclic snapshots.
- "`assign` copies descriptors" — no; it reads values (invoking getters) and writes via assignment (invoking setters). To copy descriptors, use `Object.defineProperties(target, Object.getOwnPropertyDescriptors(source))`.
- "`fromEntries` keeps numeric keys as numbers" — no; property keys are always string or symbol. Map numeric keys become string integer indices (`"1"`).
- "Spread and assign are identical" — almost, but target handling differs: `Object.assign(tgt, src)` triggers setters on `tgt`; `{ ...src }` defines. For plain objects the result is equivalent; for setter-bearing targets it is not.

### 5) **Performance note**

`Object.assign` and spread on large objects both enumerate `Reflect.ownKeys` and process per-key — linear cost. Reassigning many small objects in a hot loop (`Object.assign({}, a, b, c)` per request) allocates per iteration; keep `Object.assign` out of inner loops or reuse a target and overwrite. `Object.fromEntries` that iterates `Object.entries` double-allocates (entries array + result object) — fine for startup/config, heavy for per-frame transforms. As ever, [measure](<../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md>).

### 6) **Mentor note**

Ask trainees to predict `Object.assign({ nested: { a: 1 } })` then mutate `clone.nested.a` — if they spot the shared reference before running, the shallow model is solid. In review, flag `Object.assign(target, source)` where `source` has a getter with side effects (it will fire), and `fromEntries` used to "clone" an object with non-enumerable/accessor keys (it will flatten them).
