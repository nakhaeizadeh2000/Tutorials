## 4.3. Destructuring, rest, and spread patterns for objects

### 1) **Shorthand destructuring with defaults and renames**

**Definition** — object destructuring (`const { a, b: x, c = 1 } = obj`) binds local variables by matching source *keys* (always strings/symbols via [ToPropertyKey](<../../../03 Values Types and Coercion/sections/2. The conversion algorithms/2.3. ToPrimitive and the valueOf toString and Symbol.toPrimitive dance.md>)). Features: **rename** (`b: x` binds `x` not `b`), **defaults** (`c = 1` triggers only when value is `undefined`), **shorthand** (`{ a }` is `{ a: a }`). Reads respect the prototype chain (inherited values resolve), but aliasing semantics follow [variable scope](<../../../04 Variables Scope and Closures/sections/2. Scope and lookup/2.1. Lexical scope and the scope chain how name lookup works.md>) — each pattern declares a fresh `let`/`const` binding.

```js
// Shorthand, rename, default, combined
const src = { a: 1, b: 2, nested: { x: 10 } };
const { a, b: renamed, c = 99, d: renamedWithDefault = 5 } = src;
console.log(a, renamed, c, renamedWithDefault); // 1 2 99 5 — c defaulted because src lacked key (value undefined)

// Defaults trigger only on undefined — null/0/"" keep their values (unlike ||)
const withNull = { val: null, zero: 0, undef: undefined };
const { val = 1 } = withNull;
const { zero = 1 } = withNull;
const { undef = 1 } = withNull;
console.log(val, zero, undef); // null 0 1 — only undef fell through; use ?? for null-aware defaults at call sites

// Computed key in pattern
const key = "b";
const { [key]: computed } = src;
console.log(computed); // 2 — [key] evaluated at destructuring time

// Inherited keys destructure too (walk via prototype)
const proto = { inherited: 7 };
const child = Object.create(proto);
child.a = 1;
const { a: av, inherited } = child;
console.log(av, inherited); // 1 7 — inherited via chain (→ [3.1](../3. Prototype linkage intro/3.1. The prototype chain getPrototypeOf setPrototypeOf and Object.create.md>))

// Defaults can reference earlier bindings in the same pattern (TDZ still applies left-to-right)
const { p = 1, q = p + 1 } = {};
console.log(p, q); // 1 2
// const { x = y, y = 1 } = {}; // ReferenceError: y is TDZ — sequential evaluation

// Nested destructuring
const { nested: { x: nestedX } } = src;
console.log(nestedX); // 10 — binds nestedX from src.nested.x; nested binding itself NOT created (only nestedX exists)
const { nested: nestedRef } = src;
console.log(nestedRef === src.nested); // true — sibling form binds the nested object itself

// Function parameter destructuring — defaults need the outer = {}
function greet({ name = "guest", id } = {}) {
  return `${name}#${id ?? "?"}`;
}
console.log(greet({ id: 5 })); // guest#5
console.log(greet()); // guest#?  — outer = {} default guards destructuring of undefined
try { function bad({ a } ) {} ; bad(); } catch (e) { console.log(e.name); } // TypeError — destructuring undefined without outer default
```

- Modern guidance: prefer destructuring for stable API objects (options bags, response shapes) where the key set is known; stick to direct `obj.prop` when the access is conditional or the key is computed from untrusted input.

### 2) **Rest collects own enumerable leftovers; spread collects into a new object**

**Definition** — `const { a, ...rest } = obj` collects **enumerable own string+symbol leftover keys** into a fresh plain object (with `Object.prototype` as prototype, never `null`-proto). `const copy = { ...obj, extra: 1 }` copies the same leftover set plus any explicit keys, last-wins. Both **skip non-enumerable** and **inherited** properties; both are **shallow** (nested objects shared). Rest must be last in the pattern.

```js
const full = { a: 1, b: 2, c: 3 };
const { a: a2, ...rest } = full;
console.log(rest); // { b: 2, c: 3 } — a excluded, b/c collected shallow
console.log(Object.getPrototypeOf(rest) === Object.prototype); // true — always plain, not null-proto even if source was null-proto

// Non-enumerable and inherited are ignored by rest/spread
const base = { inherited: 10 };
const withHidden = Object.create(base);
withHidden.x = 1;
withHidden.y = 2;
Object.defineProperty(withHidden, "hidden", { value: 3, enumerable: false });
withHidden[Symbol("s")] = 4; // enumerable symbol IS collected
const { x: x2, ...left } = withHidden;
console.log(left); // { y: 2, [Symbol(s)]: 4 } — hidden non-enumerable + inherited omitted, symbol kept

// Spread shallow — same contract as assign (→ [4.1](./4.1. Assign merging shallow copy and fromEntries.md>))
const orig = { inner: { n: 1 } };
const copy = { ...orig };
console.log(copy.inner === orig.inner); // true — shared reference
copy.inner.n = 99;
console.log(orig.inner.n); // 99 — leaked

// Rest useful for omit; spread for merge with override
function omit(obj, ...keys) {
  const keySet = new Set(keys);
  return Object.fromEntries(Object.entries(obj).filter(([k]) => !keySet.has(k)));
  // rest alternative for known keys: const { a, b, ...keep } = obj; return keep;
}
console.log(omit({ a: 1, b: 2, c: 3 }, "a")); // { b:2, c:3 }
const merged2 = { ...{ a: 1 }, b: 2, ...{ a: 9, c: 3 } };
console.log(merged2); // { a: 9, b: 2, c: 3 } — later wins, explicit b survives

// Source null/undefined handling — destructuring throws, spread skips
console.log({ ...null, ...undefined, a: 1 }); // { a: 1 } — spread safe
try { const { x: xr } = null; } catch (e) { console.log(e.name); } // TypeError — destructuring null throws
// Guard at function boundary: function f({ a } = {}) — outer = {} fixes undefined; callers must not pass null
```

### 3) **Nested and computed-pattern destructuring — when a pattern helps vs when straight access is clearer**

```js
// Nested pattern with defaults at each level — verbose but precise control
const resp = { user: { name: "ada" } }; // no email
const { user: { name, email = "no-email@example.com" } = {} } = resp;
console.log(name, email); // ada no-email@example.com
// Without the = {} guard, const { user: { name } } = {} would TypeError (user undefined not destructurable)
// Contrast direct access + optional chaining for the same data
console.log(resp.user?.email ?? "no-email@example.com"); // same — often clearer than a four-level pattern

// Array-inside-object and object-inside-array
const mixed = { list: [10, 20, 30], meta: { tag: "hi" } };
const { list: [first, , third], meta: { tag } } = mixed;
console.log(first, third, tag); // 10 30 hi

// Alias + default + computed in one line
const config = { port: 8080 };
const { port: p3 = 3000, [ "host-" + 1 ]: h = "localhost" } = config;
console.log(p3, h); // 8080 localhost

// When to avoid a pattern: deep nesting that obscures the guard
const bad = { a: { b: { c: { d: 1 } } } };
const { a: { b: { c: { d } } } } = bad; // binds only d — reader must trace four levels
console.log(d); // 1 — but a/b/c bindings don't exist (only d)
console.log(typeof a); // ReferenceError or outer a — pattern didn't bind a/b/c
// Clearer: const d2 = bad.a?.b?.c?.d ?? defaultD — single optional chain expresses the same walk

// Renamed nested collect
const src2 = { id: 7, flags: { active: true, verbose: false }, extra: "x" };
const { flags: { active }, ...other } = src2;
console.log(active, other); // true { id:7, extra:'x' } — flags consumed, rest collects id+extra (not flags)
```

- *History* — object destructuring/rest/spread is ES2018 for rest/spread; earlier only array destructuring existed. Prefer explicit `=` guard for nested optionals; team convention should fix whether destructuring params use `= {}` outer default or require callers never pass `undefined`.

### 4) **Common confusion**

- "Defaults trigger on `null`" — no; only `undefined`. Pattern `({ a = 1 } = { a: null })` keeps `null`; normalize with `??` if null should also default.
- "Destructuring throws on missing nested key" — only if the *intermediate* value is `null`/`undefined`. `{ a: { b } } = { a: undefined }` throws; guard with `= {}`.
- "Rest keeps prototype and non-enumerable" — no; plain object with `Object.prototype`, enumerable own only, shallow.
- "Spread on `null` throws" — no; spread skips `null`/`undefined`; destructuring `const { a } = null` throws.

### 5) **Performance note**

Destructuring compiles to property reads — same cost as `const a = obj.a`. Heavy nested patterns that default often still read each level. Avoid destructuring + rest that allocates a fresh object per call on hot paths — prefer a single `obj.prop` read. As ever, [measure](<../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md>).

### 6) **Mentor note**

Give juniors an options bag `{ port?, host?, retries? }` and have them write both a default-param destructuring `function serve({ port=3000, host="0.0.0.0", retries=3 } = {})` and an `options.port ?? 3000` version — discuss when defaults belong in the pattern vs at use. In review, flag unguarded nested destructuring `const { a: { b } } = maybeNull` (add `= {}`), and `...rest` that silently drops inherited/non-enumerable keys the caller expected.
