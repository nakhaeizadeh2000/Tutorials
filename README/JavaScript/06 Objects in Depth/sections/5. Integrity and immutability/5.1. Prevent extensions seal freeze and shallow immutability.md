## 5.1. Prevent extensions, seal, freeze — and the shallow reality

### 1) **Three levels: preventExtensions < seal < freeze**

**Definition** — three `Object.*` primitives lock objects at increasing strictness. All operate **per-object, shallow**, and fail-loud in strict mode (throw `TypeError`) or fail-silent in sloppy mode (return same value). Each has a predicate (`isExtensible`/`isSealed`/`isFrozen`) to test state before mutating.

| Operation | Adds disallowed | Deletes | Reconfigures descriptor (incl. `enumerable` flip, data↔accessor) | Data `writable: true → false` still allowed? | Values mutable? | Nested objects? |
|-----------|-----------------|---------|---------------------------------------------------------------|---------------------------------------------|----------------|-----------------|
| `preventExtensions(obj)` | yes (`[[Extensible]] = false`) | allowed | allowed (if `configurable: true`) | allowed | yes | untouched |
| `seal(obj)` = preventExtensions + mark all own props `configurable: false` | yes | blocked | blocked | allowed (data remains `writable: true`) | yes (data properties still writable) | untouched |
| `freeze(obj)` = seal + mark all own data props `writable: false` + accessor props `[[Set]]` stays but define fails | yes | blocked | blocked | **no** — all data become read-only | **no** | **still untouched — shallow** |

```js
// Level 1 — preventExtensions: no new keys, existing keys still fully mutable
const a = { x: 1 };
Object.preventExtensions(a);
console.log(Object.isExtensible(a)); // false
a.x = 2;
console.log(a.x); // 2 — writable
delete a.x;
console.log(a.x); // undefined — configurable true, so delete succeeded
a.y = 3;
console.log(a.y); // undefined — extension blocked (sloppy silent); strict: TypeError
console.log(Object.isSealed(a)); // false — sealing requires configurable:false on each prop

// Level 2 — seal: no add, no delete, no reconfigure — but still writable values
const b = { x: 1, get y() { return 2; } };
Object.seal(b);
console.log(Object.isSealed(b), Object.isFrozen(b)); // true, false — y accessor still "writable" via setter absence? Data prop x still writable
b.x = 9;
console.log(b.x); // 9 — writable true so mutation allowed even though sealed
try { Object.defineProperty(b, "x", { enumerable: false }); } catch (e) { console.log(e.name); } // TypeError — reconfigure denied
console.log(delete b.x); // false — sealed blocks delete (strict TypeError)
b.z = 3;
console.log(b.z); // undefined — extensible false

// Level 3 — freeze: seal plus all data writable→false (accessors keep get/set but retyping blocked)
const c = { x: 1, y: { nested: 2 }, get z() { return this.x + 1; } };
Object.freeze(c);
console.log(Object.isFrozen(c)); // true
c.x = 99;
console.log(c.x); // 1 — write ignored in sloppy (strict TypeError)
console.log(delete c.x); // false — still blocked
console.log(c.z); // 2 — getter still runs (accessor not "frozen" in value sense, but descriptor retype is blocked)
c.y.nested = 99;
console.log(c.y.nested); // 99 — SHALLOW: nested object stays mutable (the central surprise)
try { Object.defineProperty(c, "x", { value: 2 }); } catch (e) { console.log(e.name); } // TypeError

// Predicates work even before locking
const d = {};
console.log(Object.isExtensible(d), Object.isSealed(d), Object.isFrozen(d)); // true false false — empty-extensible is not sealed/frozen per spec (needs extensible false)
Object.preventExtensions(d);
console.log(Object.isExtensible(d), Object.isSealed(d), Object.isFrozen(d)); // false true true — empty + non-extensible counts as both sealed and frozen
```

- *Modern guidance* — use `freeze` for truly constant enumerations/constants exported from a module; use `seal` when you want to prevent extension/deletion but still allow value updates (e.g., state bag shape locked, values flowing); use `preventExtensions` only when you want to block new keys but keep configurability for later cleanup. For data payloads that flow through pipelines, freezing the *shape* often matters more than freezing values.

### 2) **All three are shallow — nested objects stay mutable**

Freezing an object never walks into nested arrays/objects/maps — `freeze({ a: { b: 1 } })` still lets `o.a.b = 2`. A "deep" freeze must recurse and choose a cycle/symbol strategy.

```js
const shallow = { inner: { x: 1 }, arr: [1, 2], now: new Date() };
Object.freeze(shallow);
console.log(Object.isFrozen(shallow)); // true — outer is frozen
console.log(Object.isFrozen(shallow.inner)); // false — nested NOT frozen
shallow.inner.x = 99; // mutates — no error in sloppy
console.log(shallow.inner.x); // 99
shallow.arr.push(3);
console.log(shallow.arr); // [ 3, 4? wait ] actually [1,2,3] — push mutated nested array
console.log(shallow.now.setFullYear(2020)); // mutates Date object

// Minimal deep freeze — recursive, handles cycles via WeakSet, includes symbols
function deepFreeze(obj, seen = new WeakSet()) {
  if (obj === null || typeof obj !== "object" || seen.has(obj) || Object.isFrozen(obj)) return obj;
  seen.add(obj);
  for (const key of Reflect.ownKeys(obj)) { // include symbols + non-enumerable (→ [2.3](../2. Properties and descriptors/2.3. Enumerability enumeration order and for-in mechanics.md))
    const val = obj[key];
    if (val !== null && typeof val === "object") deepFreeze(val, seen);
  }
  return Object.freeze(obj);
}

const cyclic = { a: 1 };
cyclic.self = cyclic; // cycle
deepFreeze(cyclic);
console.log(Object.isFrozen(cyclic) && Object.isFrozen(cyclic.self)); // true true — cycle handled via WeakSet
try { cyclic.a = 2; } catch (e) { console.log(e.name); } // sloppy silent / strict TypeError — write blocked
console.log(cyclic.a); // 1 — unchanged
cyclic.self.extra = 9; // adding on frozen nested self also blocked (sloppy undefined)
console.log("extra" in cyclic); // false

// When to deep-freeze: almost never on hot data — on API boundaries (config, enum maps) at module load
const CONFIG = deepFreeze({ port: 3000, host: "localhost", nested: { retries: 3 } });
console.log(Object.isFrozen(CONFIG.nested)); // true — nested now locked too
```

- *Trade-off* — deep freeze costs startup linearization and permanently disables later shape edits. For Redux-like state bags, alternatives include `immer` (structural sharing) or `Object.freeze` in dev-only and trust production (perf-sensitive — freeze checks per mutation add branch cost).

### 3) **Fail-loud in strict mode, fail-silent in sloppy — plus is* guards**

The mismatch is historical (strict = ES5 fix). Every mutating site below throws `TypeError` under `"use strict"` and returns the value/false/undefined otherwise — making sloppy bugs silent data corruption that surfaces later.

```js
function sloppy(obj) { // no "use strict"
  obj.newKey = 1;    // addition on non-extensible: ignored => undefined (no error)
  obj.x = 99;        // write on read-only: ignored => keeps old
  delete obj.x;      // delete on non-configurable: returns false
  Object.defineProperty(obj, "x", { value: 99 }); // reconfigure on frozen: throws TypeError even in sloppy (defineProperty always throws)
  return obj;
}
function strict(obj) { "use strict";
  try { obj.newKey = 1; } catch (e) { console.log("strict add", e.name); }
  try { obj.x = 99; } catch (e) { console.log("strict write", e.name); }
  try { delete obj.x; } catch (e) { console.log("strict delete", e.name); }
}

const frozen2 = Object.freeze({ x: 1 });
console.log(sloppy({ ...frozen2 }) === undefined ? "sloppy define throws" : ""); // defineProperty throws even sloppy
console.log(frozen2.x); // 1 — sloppy writes didn't change it
console.assert(delete frozen2.x === false, "sloppy delete false");
strict(frozen2); // logs three TypeErrors

// Guards before mutating
function ensureExtensible(obj, key, value) {
  if (!Object.isExtensible(obj)) throw new TypeError("object not extensible");
  obj[key] = value;
}
console.log(Object.isExtensible(frozen2)); // false — guard catches it
console.log(Object.isSealed({ a: 1 })); // false — plain extensible is not sealed
console.log(Object.isSealed(Object.preventExtensions({ a: 1 })) ? "preventExtensions may already be sealed if no configurable flip needed" : "");

// Module-level constants pattern — freeze at export
const HTTP_METHODS = Object.freeze({ GET: "GET", POST: "POST", PUT: "PUT", DELETE: "DELETE" });
console.log(HTTP_METHODS.GET); // GET
HTTP_METHODS.GET = "get";
console.log(HTTP_METHODS.GET); // GET — still upper (sloppy ignored, strict would TypeError)
```

- *Lint rule* — enable ESLint `no-extend-native` and freeze only your own objects; freezing built-in prototypes (`Object.freeze(Object.prototype)`) breaks libraries that polyfill and is almost never what you want.

### 4) **Common confusion**

- "`freeze` is deep" — no; one level only. Nested objects/arrays need explicit recursive walk (and symbol keys + cycles).
- "`seal` makes it read-only" — no; `seal` keeps `writable: true`. Only `freeze` makes data read-only.
- "Frozen objects can't have getters that recompute" — getters still run; `freeze` doesn't freeze the returned value, just the descriptor linkage.
- "Strict vs sloppy difference is cosmetic" — sloppy frozen assignments/deletes silently produce stale data that propagates through pipelines — use strict modules (which default strict) and treat silent `false` returns as bugs.

### 5) **Performance note**

Frozen objects let engines optimize property reads under the assumption shape never changes (no extensibility, no configurability). However, freezing a hot object that will be updated frequently pessimize writes (each write checks `IsFrozen` → branch). Freeze constants, device config, and enum maps — not per-request state bags. Deep-freezing large graphs at startup is linear and often justified; deep-freezing per-request clones is not.
