## 6.1. Object checklist: reflex rules mentors screen for

### 1) **Literal defaults vs defineProperty defaults — never mix them by accident**

The single most frequent object bug in this codebase history: a library adds a helper via `Object.defineProperty(o, "help", { value: fn })`, later `Object.keys(o)` "loses" it and `JSON.stringify` drops it, because `enumerable` defaulted to `false`. Literals (`{ help: fn }`) give `enumerable/writable/configurable: true`; `defineProperty` gives `false/false/false`. The reflex:

- When you write `defineProperty`, spell **all four** booleans or the omission *is* the bug.
- When you need a hidden internal, keep `enumerable: false` explicitly and document why (`// hidden from serialization`).

```js
// Bug: defineProperty with bare value — later spread/keys/JSON lose the key
const user = {};
Object.defineProperty(user, "id", { value: 42 }); // defaults false/false/false
console.log(Object.keys(user)); // [] — lost
console.log({ ...user }); // {} — lost
console.log(JSON.stringify(user)); // {} — lost

// Fix: literal for data; explicit true/true/true when defineProperty is required
const ok = { id: 42 };
console.log(Object.keys(ok)); // [ 'id' ]
const explicit = {};
Object.defineProperty(explicit, "id", { value: 42, writable: true, enumerable: true, configurable: true });
console.log(Object.keys(explicit)); // [ 'id' ]

// Intentional hidden: spell false and annotate
const withMethod = { data: 1 };
Object.defineProperty(withMethod, "helper", { value() { return this.data * 2; }, writable: true, enumerable: false, configurable: true });
console.log(Object.keys(withMethod)); // [ 'data' ] — helper hidden on purpose
console.log(withMethod.helper()); // 2 — still reachable directly
```

### 2) **Shallow copy vs deep copy; enumerable vs non-enumerable; own vs inherited — three dichotomies that explain most object bugs**

Each `Object.*` helper chooses one side of each dichotomy:

| Helper | Own vs inherited | Enumerable only? | Shallow vs descriptor |
|--------|------------------|------------------|-----------------------|
| `Object.keys/values/entries` | own only | yes (strings) | — |
| `for-in` | own + inherited | yes (strings) | — |
| `Reflect.ownKeys / getOwnPropertyNames` | own only | no | — |
| `Object.assign / ...spread` | own only | yes (strings+symbols) | shallow value copy (getters run) |
| `Object.getOwnPropertyDescriptors + defineProperties` | own only | no | **descriptor copy** (preserves) |
| `structuredClone` | own + nested deep | — | deep value clone |

```js
// 1) Shallow vs deep
const base = { inner: { x: 1 } };
const shallow = { ...base };
shallow.inner.x = 99;
console.log(base.inner.x); // 99 — shallow shared leaked
const deep = typeof structuredClone === "function" ? structuredClone(base) : JSON.parse(JSON.stringify(base));
deep.inner.x = 1; // reset via deep clone for next demo
console.log(deep.inner === base.inner); // false — deep isolated

// 2) Enumerable vs non-enumerable
const mixed = {};
Object.defineProperties(mixed, {
  visible: { value: 1, enumerable: true },
  hidden: { value: 2, enumerable: false }
});
console.log(Object.keys(mixed)); // [ 'visible' ]
console.log(Reflect.ownKeys(mixed)); // [ 'visible', 'hidden' ]

// 3) Own vs inherited
const proto = { inherited: 99 };
const obj = Object.create(proto);
obj.own = 1;
console.log("inherited" in obj); // true — walks chain
console.log(Object.hasOwn(obj, "inherited")); // false — own only
console.log(Object.keys(obj)); // [ 'own' ] — own only, inherited excluded; for-in would include inherited
```

- Quick self-test before review: ask "which of enumerable/non-enumerable, own/inherited, shallow/descriptor does this call respect?" If the answer isn't instant, the helper is likely wrong.

### 3) **The review grep list**

| Grep pattern | What it catches | Fix |
|--------------|-----------------|-----|
| `Object\.defineProperty\(.*\{ value:` without `enumerable`/`writable` | default-false trap | spell all three booleans |
| `\{ ...` on maybe-`null`/`undefined` without guard | spread on nullish is forgiving now but destructuring isn't — pair with guard | `const { a } = maybeObj ?? {}` or keep spread |
| `delete\s+.*\.` inside hot loop | deopt + observable `configurable: false` breakage | tombstone or `Reflect.deleteProperty` with strict check; prefer seal discipline |
| `__proto__\s*=` or `setPrototypeOf` outside `Object.create` site | prototype mutation deopt | set `__proto__` in literal or `Object.create` at birth |
| `Object\.hasOwnProperty` | null-proto breakage | replace with `Object.hasOwn` |
| `for\s*\(.*\s+in\s+` without `hasOwn` guard | inherited leakage / prototype pollution reading | replace with `for (k of Object.keys(obj))` |
| `Object\.freeze(` on state bag later written | sloppy silent no-op | keep constants frozen, state bags unsealed; ensure caller is strict so mutation throws |

```js
// Example review hits
let miss; // simulated grep findings
const obj2 = { a: 1 };
// Hit: for (k in obj2) console.log(k); // flagged — inherited risk
for (const k of Object.keys(obj2)) console.log(k); // fix

// Hit: Object.prototype.hasOwnProperty.call(mapLike, k) // legacy
console.log(Object.hasOwn(obj2, "a")); // fix — ES2022 direct

// Hit: delete inside loop on configurable: true hot object
const cache = {};
Object.defineProperty(cache, "permanent", { value: 1, configurable: false });
console.log(delete cache.permanent); // false — would break after freeze/seal; lint catches
```

### 4) **Decision table for common tasks**

| Task | Reach for | Avoid |
|------|-----------|-------|
| Create data record | `{ a, b }` literal | `new Object()` |
| Dictionary keyed by untrusted strings | `Object.create(null)` | `{}` then `in` checks |
| Hide helper from `JSON`/`keys`/`spread` | `defineProperty(..., { enumerable: false })` | underscore prefix only |
| Shallow merge two data bags | `{ ...a, ...b }` or `Object.assign({}, a, b)` | manual `for-in` copy (skips symbols inconsistently) |
| Copy preserving descriptors/accessors | `Object.defineProperties({}, getOwnPropertyDescriptors(src))` | `assign` / spread (flatten to data) |
| Deep clone isolated snapshot | `structuredClone(src)` | `assign`/spread (shallow) |
| Lock constants | `Object.freeze({...})` or `deepFreeze` | freezing per-request state |
| Test own key existence | `Object.hasOwn(obj,k)` | `k in obj` or `obj.hasOwnProperty` |
| Iterate data surface | `Object.entries(obj)` + `for-of` | bare `for-in` |

### 5) **Mentor checklist (screen in every review)**

- [ ] Every `defineProperty` spells `enumerable`/`writable`/`configurable` explicitly.
- [ ] Every shallow clone (`assign`/spread) is shallow by intent; nested mutation can't corrupt caller (otherwise deep clone or `deepFreeze`).
- [ ] Own vs inherited choice is explicit (`hasOwn` vs `in`; `keys` vs `for-in`).
- [ ] No `setPrototypeOf`/`__proto__=` outside construction; no `delete` in hot paths on sealed/frozen shapes.
- [ ] No raw `for-in` without justification; no `hasOwnProperty` on unknown-proto objects.
