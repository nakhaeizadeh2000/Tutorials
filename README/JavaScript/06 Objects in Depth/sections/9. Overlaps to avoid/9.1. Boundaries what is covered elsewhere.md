## 9.1. Boundaries: what is covered elsewhere

### 1) **Prototype inheritance, class syntax, private fields, and super dispatch — Prototypes and Classes (planned 07)**

Full `class`, `extends`, `super`, private `#fields`, static blocks, and `instanceof`/`isPrototypeOf` chains live in the Prototypes and Classes domain (textual forward reference). This domain covers prototype wiring at birth (`Object.create`, literal `__proto__`, `getPrototypeOf`/`setPrototypeOf` as intro → [3.1](../3. Prototype linkage intro/3.1. The prototype chain getPrototypeOf setPrototypeOf and Object.create.md>)) and the difference between `[[Prototype]]` and `Function.prototype`, but not dispatch, inheritance patterns, or `super` in class bodies.

### 2) **Collections, WeakRef/FinalizationRegistry, and identity semantics — Collections / Memory (planned 09, 18)**

`Map`/`Set`/`WeakMap`/`WeakSet`/`WeakRef` keying (object identity vs stringification), `Map` vs `Object.create(null)` for untrusted keys, and GC/heap implications of holding object refs belong to the Collections and Memory domains (textual forward references). This domain notes the `Map`-vs-object trade-off on pollution and string-key coercion ([1.2](../1. Object creation and literals/1.2. Creation patterns literal Object create and constructors.md>) / [7.1](../7. Common pitfalls to production bugs/7.1. Real production bugs caused by object mistakes.md>)) but does not teach `Map` APIs or lifetime.

### 3) **Iterator protocol, generators, and async generators — Iterables (planned 10)**

`Symbol.iterator`/`Symbol.asyncIterator`, generator `function*`/`yield`, and iterable consumption (`for-of`, spread on iterables) have a dedicated domain. This domain covers own-key enumeration (`for-in`, `keys`, `Reflect.ownKeys` → [2.3](../2. Properties and descriptors/2.3. Enumerability enumeration order and for-in mechanics.md>), [4.2](../4. Object utilities and copying/4.2. Keys values entries hasOwn and reflection APIs.md>)) as the sync property-visit mechanism, but not the iterator protocol.

### 4) **JSON, serialization, and modules — JSON / Modules (planned 14, 16)**

`JSON.stringify`/`parse` (replacer/reviver, `toJSON`, symbol omission), `structuredClone`, `Object.groupBy` (ES2024), and `import`/`export` live bindings belong to the JSON and Modules domains. This domain stays with in-memory shape and `Object.*` utilities; `JSON.stringify` is mentioned only for its enumerable-string-own filtering ([4.2](../4. Object utilities and copying/4.2. Keys values entries hasOwn and reflection APIs.md>)).

### 5) **Values, coercion, language operators, and scope — Values / Language Basics / Variables**

Property-key coercion (`ToPropertyKey`/`ToPrimitive`/`ToString`) is owned by [Values, Types, and Coercion](<../../../03 Values Types and Coercion/README.md>) (this domain links there from [1.1](../1. Object creation and literals/1.1. Object literals shorthand computed properties and spread.md>)); operator syntax (`delete`, `in`, `instanceof`, spread/rest) is owned by [Language Basics](<../../../02 Language Basics/README.md>); declaration scope/TDZ/closure capture is owned by [Variables, Scope, and Closures](<../../../04 Variables Scope and Closures/README.md>); `this` binding/receiver for accessors/methods is owned by [Functions Deep Dive](<../../../05 Functions Deep Dive/README.md>).

### 6) **Stop-list for this domain (what not to add here)**

- Do not re-derive `class` inheritance, `extends`/`super` dispatch, or private field semantics — link to domain 07.
- Do not teach `Map`/`WeakMap` APIs, `WeakRef` resurrection facts, or heap-snapshot debugging — link to domains 09/18.
- Do not teach `Symbol.iterator`, `Generator.prototype`, `Promise` combinators, or `async` generators — link to domains 10/13.
- Do not duplicate `ToPrimitive`/`ToString`/`ToNumber` coercion tables or `instanceof` realm caveats — link to domain 03/02.
- Do not expand `Object.groupBy` (`Array` iteration belongs elsewhere) beyond a one-line forward ref.
