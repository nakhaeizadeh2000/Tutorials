## 2.2. Defining, observing, and configuring properties

### 1) **defineProperty / defineProperties — surgical installation**

**Definition** — `Object.defineProperty(obj, key, desc)` and `Object.defineProperties(obj, descs)` install or reconfigure own properties *via descriptors*. Unlike `obj[key] = value` (which triggers setters and respects `writable`), `defineProperty` writes the descriptor directly: it can create non-enumerable/non-writable/non-configurable or accessor properties, and it throws `TypeError` instead of silently failing when the change is illegal. On extensible objects it adds missing keys; on non-extensible objects it can only reconfigure within allowed limits.

```js
const user = {};

// Data property: non-enumerable internal id (won't JSON-serialize or spread)
Object.defineProperty(user, "id", {
  value: 42,
  writable: false,
  enumerable: false,  // hide from keys/JSON/spread
  configurable: false // permanent — cannot be deleted or retyped
});
console.log(Object.getOwnPropertyDescriptor(user, "id"));
// { value: 42, writable: false, enumerable: false, configurable: false }
console.log(Object.keys(user)); // [] — id hidden
console.log(JSON.stringify(user)); // {} — also hidden
console.log(user.id); // 42 — direct access still works

// Accessor that validates and stores elsewhere
let _score = 0;
Object.defineProperty(user, "score", {
  get() { return _score; },
  set(v) {
    if (typeof v !== "number" || v < 0) throw new TypeError("score must be number >= 0");
    _score = v;
  },
  enumerable: true,
  configurable: true
});
user.score = 10;
console.log(user.score); // 10
try { user.score = -1; } catch (e) { console.log(e.name); } // TypeError

// defineProperties batches — one shape transition instead of many
const point = {};
Object.defineProperties(point, {
  x: { value: 3, writable: true, enumerable: true, configurable: true },
  y: { value: 4, writable: true, enumerable: true, configurable: true }
});
console.log(point.x, point.y); // 3 4

// Mixing value+get in a single descriptor throws — e.g. { value: 1, get() {} } is illegal
try {
  Object.defineProperty(point, "bad", { value: 1, get() { return 1; } });
} catch (e) { console.log(e.name); } // TypeError
```
Add accessor separately:

```js
const point2 = {};
Object.defineProperties(point2, {
  x: { value: 3, writable: true, enumerable: true, configurable: true },
  y: { value: 4, writable: true, enumerable: true, configurable: true },
  length: { get() { return Math.hypot(this.x, this.y); }, enumerable: true, configurable: true }
});
console.log(point2.length); // 5 — accessor computed from data siblings
console.log(typeof point2.length === "number" && point2.x === 3); // true

// Assignment vs defineProperty — setter treatment (critical for copying — → [4.1](../4. Object utilities and copying/4.1. Assign merging shallow copy and fromEntries.md>))
const target = {
  set v(x) { console.log("setter", x); this._v = x; },
  get v() { return this._v; }
};
target.v = 1; // setter runs
Object.defineProperty(target, "v", { value: 2, writable: true, enumerable: true, configurable: true });
console.log(target.v); // 2 — defineProperty REPLACED the accessor with a data property (not "called the setter")
console.log(Object.getOwnPropertyDescriptor(target, "v")); // { value: 2, ... } — accessor gone
```

- *Why not just use literals?* Literals cannot create non-enumerable/non-writable properties, cannot make an accessor whose setter validates, and cannot batch shape transitions. Libraries and framework internals use `defineProperty` to add hidden plumbing without polluting `keys`/`JSON`.

### 2) **getOwnPropertyDescriptor / getOwnPropertyDescriptors — inspection without invocation**

Reading `obj.x` triggers a getter and coerces via the receiver (`this` — see [this binding](<../../../05 Functions Deep Dive/sections/3. this binding/3.1. Call-site rules default implicit explicit new and strict mode.md>)); `getOwnPropertyDescriptor` returns the descriptor object without calling `get`, and only for *own* keys (inherited descriptors return `undefined` — you must walk with `getPrototypeOf` if you need the chain).

```js
const base = { get n() { console.log("getter ran"); return 1; } };
const child = Object.create(base);
child.own = 2;

console.log(Object.getOwnPropertyDescriptor(child, "n")); // undefined — n is inherited, not own
console.log(Object.getOwnPropertyDescriptor(base, "n")); // { get: ..., enumerable: true, ... } — no invocation yet
console.log(child.n); // 1 — NOW getter runs, logs "getter ran"

let calls = 0;
const spy = { get x() { calls += 1; return 1; } };
const desc = Object.getOwnPropertyDescriptor(spy, "x");
console.log(calls); // 0 — descriptor fetch didn't call getter
console.log(typeof desc.get); // function
console.log(spy.x, calls); // 1 1 — direct read did

// ES2017 bulk: getOwnPropertyDescriptors returns map of all own descriptors without invoking any getter
const multi = {
  a: 1,
  get b() { return this.a * 2; }
};
Object.defineProperty(multi, "hidden", { value: 3, enumerable: false });
console.log(Object.getOwnPropertyDescriptors(multi));
// { a: { value:1, writable:true... }, b: { get: ..., enumerable:true... }, hidden: { value:3, enumerable:false... } }
console.log(Object.keys(multi)); // [ 'a', 'b' ] — hidden omitted

// Walk the chain to find where a property lives
function findDescriptor(obj, key) {
  for (let cur = obj; cur !== null; cur = Object.getPrototypeOf(cur)) {
    const d = Object.getOwnPropertyDescriptor(cur, key);
    if (d) return { owner: cur, desc: d };
  }
  return undefined;
}
console.log(findDescriptor(child, "n").owner === base); // true
console.log(findDescriptor({ a: 1 }, "toString").owner === Object.prototype); // true
```

### 3) **Configurability is one-way — once false, forever false**

A property with `configurable: false` can no longer be deleted, retargeted between data ↔ accessor, or have its `enumerable`/`configurable` flipped. For data properties, `writable` can still transition from `true → false` (soft lock), but never `false → true`. This is the primitive that `seal`/`freeze` compose from (→ [5.1](../5. Integrity and immutability/5.1. Prevent extensions seal freeze and shallow immutability.md>)).

```js
const obj = {};
Object.defineProperty(obj, "fixed", {
  value: 1,
  writable: true,
  enumerable: true,
  configurable: false // one-way latch
});
console.log(Object.getOwnPropertyDescriptor(obj, "fixed").configurable); // false

// These all throw TypeError (strict) or return false silently (sloppy delete)
try { Object.defineProperty(obj, "fixed", { enumerable: false }); } catch (e) { console.log(e.name); } // TypeError
try { Object.defineProperty(obj, "fixed", { get() { return 1; } }); } catch (e) { console.log(e.name); } // TypeError — data→accessor flip denied
console.log(delete obj.fixed); // false — delete fails when configurable: false (strict: TypeError, sloppy: false)
console.log(obj.fixed); // 1 — still present

// Writable may still go true→false
Object.defineProperty(obj, "fixed", { writable: false });
console.log(Object.getOwnPropertyDescriptor(obj, "fixed").writable); // false
obj.fixed = 2; // sloppy silent no-op
console.log(obj.fixed); // 1 — write ignored (strict would TypeError)
try { Object.defineProperty(obj, "fixed", { writable: true }); } catch (e) { console.log(e.name); } // TypeError — cannot flip back

// Non-configurable accessor: you can replace the getter implementation only if configurable: true
const acc = {};
Object.defineProperty(acc, "x", { get() { return 1; }, enumerable: true, configurable: false });
try { Object.defineProperty(acc, "x", { get() { return 2; } }); } catch (e) { console.log(e.name); } // TypeError — retyping denied

// Extensibility is object-level; configurability is per-property — both handled together by seal/freeze helpers
console.log(Object.isExtensible(obj)); // true — still extensible (new keys allowed)
Object.preventExtensions(obj);
console.log(Object.isExtensible(obj)); // false — new keys now disallowed, but existing configurable props still removable until sealed
```

| State to state | Allowed? |
|----------------|----------|
| `configurable: true → false` | yes |
| `configurable: false → true` | **never** |
| `enumerable: true ↔ false` when `configurable: false` | **never** |
| `writable: true → false` when `configurable: false` | yes |
| `writable: false → true` when `configurable: false` | **never** |
| data ↔ accessor when `configurable: false` | **never** |
| delete when `configurable: false` | **never** |

- Modern guidance: use `configurable: false` only when you intend permanence. Most application objects should keep `configurable: true` so mocks and tests can patch (`jest.spyOn` relies on it). Reserve locking for library-owned objects or deliberate integrity boundaries (`seal`/`freeze`).

### 4) **Common confusion**

- "`defineProperty` calls setters" — opposite. `obj.x = 1` calls the setter; `defineProperty(obj, "x", { value: 1 })` *replaces* the accessor descriptor with a data descriptor and the old setter is gone.
- "`getOwnPropertyDescriptor` finds inherited properties" — no; returns `undefined` for inherited keys. You must walk `getPrototypeOf` or use the `findDescriptor` helper above.
- "`configurable: false` makes it read-only" — only half true; you still need `writable: false` (data) or absence of `set` (accessor). `configurable: false` alone prevents shape changes but `writable: true` still allows value mutation.

### 5) **Performance note**

Every `defineProperty` that changes shape is a megamorphic transition — the JIT mirrors in [2.1](<./2.1. Data vs accessor descriptors and attribute defaults.md>). Batch with `defineProperties` when creating an object; define once at construction rather than mutating hot objects per request.
