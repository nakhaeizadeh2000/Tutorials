## 6.1. Real production bugs caused by scoping mistakes

### 1) **Incident: one missing `let` corrupts state across requests**

A sloppy-mode file (no `'use strict'`, classic script or old CJS module) turns an undeclared assignment into an implicit **global** — shared by every caller, forever:

```js
// Sloppy classic-script semantics simulated via indirect eval ([4.1](<../4. Top level scopes scripts modules and eval/4.1. Script vs module top level globalThis and the declarative record.md>)):
(0, eval)(`
  function processOrder(qty) {
    total = qty * 10;           // ← forgot \`let\`: writes a global in sloppy mode
    return total;
  }
  processOrder(2);
`);
console.log(total);             // 20 — leaked onto the world stage

// Strict code refuses at the same line instead:
(function () {
  "use strict";
  try { otherTotal = 5; }
  catch (e) { console.log(e.name, "|", e.message); } // ReferenceError | otherTotal is not defined
})();
```

- On a server this is the nightmare shape: request A sets `total`, awaits I/O, request B overwrites it, A resumes and bills B's numbers ([why top-level sharing is structural](<../4. Top level scopes scripts modules and eval/4.1. Script vs module top level globalThis and the declarative record.md>)).
- Fix layers: modules (strict by default) + `no-undef` lint + declaring at first use.

### 2) **Incident: async fan-out ships everyone the wrong data**

The [loop-capture bug](<../3. Closures/3.2. Loops and closures var let and per iteration capture.md>) wearing production clothes — batch emails, payouts, notifications:

```js
const users = ["ada", "grace", "linus"];
const jobs = [];
for (var i = 0; i < users.length; i++) {
  jobs.push(() => `mail#${i} → ${users[i]}`);   // one shared binding
}
console.log(jobs.map((j) => j()));
// [ 'mail#3 → undefined', 'mail#3 → undefined', 'mail#3 → undefined' ]
```

- Double whammy: the index is past-the-end AND element lookup follows it into `undefined`. With real sends, user A gets user C's invoice — or nothing, silently.
- Fix: `for (const [i, user] of users.entries())` — fresh bindings per iteration, index included.

### 3) **Incident: module-level cache grows until the OOM killer visits**

```js
const responseCache = new Map();     // module scope = lives as long as the process

function cached(key, compute) {
  if (!responseCache.has(key)) responseCache.set(key, compute());
  return responseCache.get(key);
}
```

- Every unique key pins its value permanently; keys containing IDs/timestamps/URLs are unbounded by construction. Memory climbs for days, heap snapshots show a giant Map, nobody wrote a bound.
- Retention mechanics → [3.4](<../3. Closures/3.4. Closures and garbage collection what stays alive.md>); the fix is a *bounded* cache (size cap with eviction, TTL, or WeakMap keyed by objects that die naturally). Decide the policy when writing the cache, not during the incident.

### 4) **Incident: metrics interval pins every job's payload**

```js
const report = (x) => x;                       // (demo stub for a real reporter)

function startMetrics(job) {
  const snapshot = { size: job.payload.length };
  const id = setInterval(() => report(snapshot.size), 1_000);
  return () => clearInterval(id);          // the ONLY path to release
}
// caller: startMetrics(bigJob);   ← stop function discarded → payload pinned forever
const stopNeverStored = startMetrics({ payload: new Array(100).fill("x") });
console.log(typeof stopNeverStored);      // function — existed, but nobody kept it
stopNeverStored();                        // cleanup that almost never happened
```

- The interval callback closes over `snapshot`; the registry keeps the callback alive; therefore every job processed since startup still holds megabytes. Same chain applies to listeners.
- Review reflex: every `setInterval`/`addEventListener` must have an owner responsible for teardown ([checklist](<../5. Important points to remember/5.1. Scope checklist reflex rules mentors screen for.md>)).

### 5) **Incident: conditional function declarations behave differently per mode**

Legacy sloppy-mode page code relying on Annex-B hoisting diverges once moved into strict/module contexts (bundlers, tests):

```js
function strictBuild(takeBeta) {
  "use strict";
  if (takeBeta) { function helper() { return "beta"; } }
  try { return helper(); } catch (e) { return `${e.name} (strict)`; }
}
function sloppyBuild(takeBeta) {
  if (takeBeta) { function helper() { return "beta"; } }
  try { return helper(); } catch (e) { return `${e.name}: ${e.message}`; }
}
console.log(strictBuild(true));   // ReferenceError (strict) — block-scoped, gone
console.log(strictBuild(false));  // ReferenceError (strict)
console.log(sloppyBuild(true));   // beta — Annex-B leaks it out of the block
console.log(sloppyBuild(false));  // TypeError: helper is not a function
```

- Four behaviors from two flags — the definition of a minefield ([mechanics](<../2. Scope and lookup/2.2. Hoisting the reality creation phase not magic.md>)). Rule: functions are declared at function/module level or expressed via `const fn = () => …`; never conditionally declared.

### 6) **Mentor note**

Each incident maps to exactly one checklist row — teach them paired so review becomes pattern-matching rather than memory: implicit globals ↔ bare assignments; fan-out ↔ loop heads; OOM ↔ unbounded caches; pinned payloads ↔ uncleared timers; mode divergence ↔ in-block declarations. Post-mortems should end with the lint rule or runtime guard that makes recurrence impossible, not with "be careful".
