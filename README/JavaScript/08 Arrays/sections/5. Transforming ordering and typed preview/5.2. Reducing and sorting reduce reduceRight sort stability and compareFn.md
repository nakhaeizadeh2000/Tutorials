## 5.2. Reducing and sorting: reduce, reduceRight, sort stability and compareFn

### 1) **`reduce` without initial value throws on empty and skips holes**

**Definition** — `reduce(callback(acc, cur, i, arr), initialValue?)` folds left-to-right; `reduceRight` folds right-to-left. Without `initialValue`, the first *present* element becomes `acc` and iteration starts at the next present index. Empty array without initial → `TypeError`. Holes are skipped (like `forEach`/`map`).

```js
console.log([1, 2, 3].reduce((acc, x) => acc + x, 0)); // 6 — with initial
console.log([1, 2, 3].reduce((acc, x) => acc + x)); // 6 — first element as initial (1 +2+3)
console.log([1].reduce((acc, x) => acc + x)); // 1 — single-element, callback never called, returns it
try { console.log([].reduce((a, x) => a + x)); } catch (e) { console.log(e.name); } // TypeError — empty no initial
console.log([].reduce((a, x) => a + x, 0)); // 0 — empty with initial returns initial

// Holes skipped — not visited as undefined
console.log([1, , 3].reduce((acc, x) => acc + x, 0)); // 4 — hole skipped, not 0+undefined
let reduceCalls = 0; [1, , 3].reduce((acc, x) => { reduceCalls++; return acc + x; }, 0);
console.log(reduceCalls); // 2 — hole skipped
console.log([, , 3].reduce((acc, x) => acc + x)); // 3 — first present is index 2 → acc=3, no further
console.log([, , ].reduce((a, x) => a + x, 0)); // 0 — holes skipped, initial returned

// reduceRight — same but reverse
console.log([1, 2, 3].reduceRight((acc, x) => acc + x, 0)); // 6
console.log([[1], [2], [3]].reduceRight((acc, cur) => acc.concat(cur))); // [3,2,1] concat reverse

// Bad — reduce without initial on sparse where first slot is hole
console.log([, 1, 2].reduce((a, x) => a + x)); // 3 — finds first present at 1 → 1+2
try { console.log([, , ].reduce((a, x) => a + x)); } catch (e) { console.log(e.name); } // TypeError — no present element to seed

// Good — always provide initial when folding to a different type or when empty possible
function sum(arr) { return arr.reduce((a, x) => a + x, 0); } // safe for [] and sparse
console.log(sum([]), sum([1, , 3])); // 0 4

// Common patterns — counting, grouping (note: Object.groupBy ES2024 as alternative)
const words = ["a", "b", "a", "c", "b", "a"];
console.log(words.reduce((m, w) => { m[w] = (m[w] ?? 0) + 1; return m; }, {})); // {a:3,b:2,c:1}
console.log([1, 2, 3].reduce((acc, x) => acc * x, 1)); // 6 — product

// NaN poisoning if you reduce string inputs without boundary conversion
console.log(["10", "20", "foo"].map(Number).reduce((a, x) => a + x, 0)); // NaN — Number("foo") NaN poisons
```

### 2) **`sort` without `compareFn` stringifies — numbers sort lexicographically**

**Definition** — `sort(compareFn?)` sorts in place (mutating) and returns `this`; `toSorted(compareFn?)` is the copy-era twin. Without `compareFn`, elements are coerced via `ToString` and compared lexicographically by UTF-16 code units. With `compareFn(a,b)`, return negative → `a` before `b`, `0` → keep order (stable), positive → `b` before `a`.

```js
// Default — string sort (the bug factory)
console.log([10, 9, 20].sort()); // [10, 20, 9] — "10" < "20" < "9" lexicographically
console.log(["10", "9", "20"].sort()); // ["10","20","9"] — same lexical
console.log([1, 2, 10].sort()); // [1,10,2] — lexical

// Numeric fix
console.log([10, 9, 20].sort((a, b) => a - b)); // [9,10,20] — ascending numeric
console.log([10, 9, 20].sort((a, b) => b - a)); // [20,10,9] — descending
console.log([10, 9, 20].toSorted((a, b) => a - b)); // [9,10,20] — without mutating original

// compareFn contract — negative/0/positive (not boolean)
console.log([3, 1, 2].sort((a, b) => a > b ? 1 : a < b ? -1 : 0)); // [1,2,3] — explicit
console.log([3, 1, 2].sort((a,  b) => +(a > b) || -(a < b))); // same via coercion

// Don't return boolean — unstable
console.log([10, 9, 20].sort((a, b) => a > b)); // [9,10,20]? May appear correct but violates contract (true→1, false→0 never negative) — don't!

// String locale-aware vs code-unit
console.log(["ä", "a", "z"].sort()); // code-unit order — "a","z","ä" maybe? locale-unsensitive
console.log(["ä", "a", "z"].sort((a, b) => a.localeCompare(b))); // locale-aware

// Holes and undefined sorting — spec: holes go to end, undefined also at end but before holes
console.log([1, , 3, undefined, 2].sort()); // [1,2,3,undefined, <hole>] — holes last
console.log([1, , 3].sort((a, b) => a - b)); // [1,3, <empty>]? Actually hole densified? Let's check
console.log([3, undefined, 1, , 2].toSorted((a, b) => a - b)); // sort moves holes last

// Verify hole sort placement
console.log([, 3, 1].sort()); // [1,3, <empty>] — holes to end
console.log([, 3, 1].sort((a, b) => a - b)); // [1,3, <empty>]

// Stability check — equal keys keep input order (guaranteed since ES2019)
const users = [{ name: "b", age: 20 }, { name: "a", age: 20 }, { name: "c", age: 10 }];
console.log(users.sort((a, b) => a.age - b.age).map(u => u.name)); // ['c','b','a']? Actually b and a both 20, stable keeps b before a
console.log(users.toSorted((a, b) => a.age - b.age).map(u => u.name)); // same stable

// Object sort — comparator must project
const people = [{ age: 30 }, { age: 20 }];
console.log(people.sort((a, b) => a.age - b.age)); // [{20},{30}] — note mutates!

// Good — numeric strings via projection with Number
console.log(["10", "9", "20"].sort((a, b) => Number(a) - Number(b))); // ["9","10","20"]
```

- *Bad practice* — `arr.sort()` on numbers without comparator → lexical. *Why it hurts* — leaderboards, prices silently wrong; tests with single-digit numbers pass (`[1,2,3].sort()` lexical equals numeric). *Instead* — `arr.toSorted((a,b)=>a-b)` for numbers and add lint `require-compare` analogue.

### 3) **`sort` is stable since ES2019; `compareFn` contract with `ToString` coercion pitfalls**

- **Stable** — equal elements (compareFn returns 0) retain original order; this holds for V8/SpiderMonkey/JavaScriptCore since ES2019 (needed for predictable multi-key sorts via sequential sorts).
- **Coercion** — default sort calls `ToString` on each element, so `null → "null"`, `undefined` stays `undefined` (sorted to end), numbers stringified. Custom `compareFn` receives raw values — no coercion.

```js
// Stable sort enables chaining: sort by name, then by age — age groups keep name order
const data = [
  { age: 20, name: "b" },
  { age: 10, name: "a" },
  { age: 20, name: "a" },
];
data.sort((a, b) => a.name.localeCompare(b.name)); // sort by name first
data.sort((a, b) => a.age - b.age); // then by age — stable keeps name order within same age
console.log(data.map(d => `${d.age}:${d.name}`)); // 10:a, 20:a, 20:b — b and a(20) kept name order

// Coercion pitfall — default sort stringifies objects via toString
console.log([{ x: 1 }, { x: 10 }].sort()); // "[object Object]" vs same → original order (0) — meaningless
console.log([{ x: 10 }, { x: 2 }].sort((a, b) => a.x - b.x)); // [{2},{10}] — project then compare

// compareFn must be consistent — inconsistent returns break TimSort and give nondeterministic output
const badCmp = (a, b) => Math.random() - 0.5;
console.log([1, 2, 3].sort(badCmp) + " — random order each run, violates transitivity");
```

### 4) **Common confusion**

- "`reduce` without initial on empty returns `undefined`" — no, throws `TypeError`; on single-element returns that element without calling callback.
- "`sort` is numeric by default" — no, lexicographic; add `(a,b)=>a-b` for numbers, `a.localeCompare(b)` for strings.
- "`sort` is unstable" — was true pre-ES2019, but now stable in all modern engines; still don't rely on unstable fallback in old hosts.
- "`toSorted` sorts differently" — no, same algorithm, just non-mutating and densifies holes to `undefined` before sorting.

### 5) **Performance note**

`reduce` is single-pass O(n) with no allocation beyond accumulator. `sort` is O(n log n) TimSort with temporary runs; for `n=1e6` numbers, sort dominates. Copy-era `toSorted` adds O(n) allocation + copy before sort — negligible vs log factor. For huge arrays, ensure `compareFn` is monomorphic (same type) so JIT can inline; mixed-type comparators deopt. Holes make `sort` scan for present elements first, adding branch.

### 6) **Mentor note**

Quiz: "What does `[].reduce((a,x)=>a+x)` throw?" (`TypeError`). Then "What does `[10,9].sort()` return?" (`[10,9]` lexical). Finally "Is `arr.sort()` stable?" (yes since ES2019 — demo with equal keys). In review, flag every `sort()`/`toSorted()` without `compareFn` on numeric data and every `reduce` without initial where input may be empty.
