## 5.1. Mapping, filtering, flat and flatMap pipelines

### 1) **`map` preserves holes — callback not called for holes, result keeps holes**

**Definition** — `map(callback, thisArg?)` returns a new dense-length array where `result[i] = callback(arr[i], i, arr)` for each *present* index `i`; holes are copied as holes (callback never invoked, result slot stays empty). `filter` and `flat` skip holes entirely, producing dense output.

```js
// map preserves holes (the classic "still holey" surprise)
const sparse = [1, , 3];
let mapCalls = 0;
const mapped = sparse.map(x => { mapCalls++; return x * 2; });
console.log(mapped); // [2, <empty>, 6] — hole preserved
console.log(Object.hasOwn(mapped, "1"), mapCalls); // false 2 — callback not called for hole
console.log(mapped.length); // 3 — length preserved

// Contrast: Array.from / spread densify while map preserves
console.log(Array.from(sparse, x => (x ?? -1) * 2)); // [2, -2, 6] — hole visited as undefined via Array.from
console.log([...sparse].map(x => (x ?? -1) * 2)); // [2, -2, 6] — spread densified first

// new Array(n).map trap — never called
console.log(new Array(3).map(() => 1)); // [ <3 empty> ] — still holes
console.log(Array.from({ length: 3 }, () => 1)); // [1,1,1] — fix

// filter skips holes and compacts to dense
console.log(sparse.filter(x => true)); // [1,3] — holes removed, length 2
console.log(sparse.filter(x => x > 1)); // [3] — holes skipped, not tested
console.log([1, , 3].filter(() => true).length); // 2 — compacted
console.log(Object.hasOwn([1, , 3].filter(() => true), "1")); // true? Actually [1,3] has index 1 → true dense

// forEach also skips; for-of densifies (via iterator)
let fe = 0; sparse.forEach(() => fe++);
console.log(fe); // 2 — hole skipped
for (const v of sparse) console.log(v); // 1, undefined, 3 — for-of visits hole as undefined

// map index still counts holes — callback index reflects original index
console.log(sparse.map((x, i) => `${i}:${x}`)); // ['0:1', <empty>, '2:3'] — hole index preserved as hole
```

### 2) **`filter` skips holes; `flat`/`flatMap` flatten one level (or `depth`) and skip holes**

```js
// flat — depth 1 by default, holes removed
console.log([1, [2, 3]].flat()); // [1,2,3]
console.log([1, [2, [3]]].flat()); // [1,2,[3]] — one level only
console.log([1, [2, [3]]].flat(2)); // [1,2,3] — depth 2
console.log([1, [2, [3]]].flat(Infinity)); // [1,2,3] — deep
console.log([1, , 3].flat()); // [1,3] — holes skipped
console.log([1, , [2, , 3]].flat()); // [1,2,3] — holes in both levels skipped
console.log([].flat()); // [] — empty safe

// flat vs concat flattening — same depth 1, but concat preserves holes from outer
console.log([1, , 3].concat([4, 5])); // [1, hole, 3,4,5] — hole preserved
console.log([1, , [2, 3]].flat()); // [1,2,3] — hole removed (not just flattened)

// flatMap — map then flat depth 1 in one pass (more efficient than map+flat, handles holes via map's skip)
console.log([1, 2, 3].flatMap(x => [x, x * 2])); // [1,2,2,4,3,6]
console.log([1, 2].flatMap(x => x === 1 ? [] : [x])); // [2] — filtering via empty array
console.log([1, , 3].flatMap(x => [x, x * 2])); // [1,2,3,6] — hole's map skipped, so no entry for hole
console.log(["a b", "c"].flatMap(s => s.split(" "))); // ['a','b','c'] — classic split+flatten

// flatMap depth is fixed 1 — for deeper need flat(depth)
console.log([1, 2].flatMap(x => [[x * 2]])); // [[2],[4]] — one level flat leaves inner array

// Callback signature — flatMap also receives index
console.log([1, 2, 3].flatMap((x, i) => [x, i])); // [1,0,2,1,3,2]
```

### 3) **Pipeline shape and the `parseInt` trap**

Array methods compose as pipelines: `arr.filter(pred).map(fn).sort(cmp).join(sep)` — each allocates a new array (intermediate). For large `n`, consider single-pass `for-of` accumulation if allocation pressure matters; otherwise pipelines win on readability.

```js
// Idiomatic pipeline — filter invalid, map to view, sort numerically
const nums = [3, 1, 4, 1, 5, 9, null, 2];
const result = nums
  .filter(x => typeof x === "number")
  .map(x => x * 2)
  .toSorted((a, b) => a - b)
  .join(" | ");
console.log(result); // 2 | 2 | 4 | 6 | 8 | 10 | 18

// The parseInt trap — map passes (value, index) but parseInt takes (string, radix)
console.log(["10", "10", "10"].map(parseInt)); // [10, NaN, 2] — index becomes radix!
 // 0:"10" radix 0 → 10, 1:"10" radix 1 → NaN (invalid), 2:"10" radix 2 → 2
// Fix — unary or Number
console.log(["10", "10", "10"].map(x => parseInt(x, 10))); // [10,10,10]
console.log(["10", "10", "10"].map(Number)); // [10,10,10]
console.log(["10", "10", "10"].map(x => +x)); // [10,10,10]

// Other callback-arity traps — same shape
console.log(["1", "2", "3"].map(parseInt)); // [1, NaN, NaN] — radix 1/2 invalid

// Sparse pipeline — map preserves holes, filter removes
const piped = [1, , 2, , 3].map(x => x * 2).filter(x => x > 2);
console.log(piped); // [4,6] — holes preserved through map then removed by filter

// Dense pipeline start — normalize if holes possible
const raw = [1, , 3];
console.log(raw.map(x => x ?? 0)); // [1, <hole>, 3] — ?? not reached for hole (callback skipped)
console.log(Array.from(raw, x => (x ?? 0) * 2)); // [2,0,6] — Array.from visits holes as undefined, so ?? works
```

### 4) **Common confusion**

- "`map` will call for every index" — no, holes skipped; result holey. `Array.from` visits holes.
- "`filter` keeps holes as `undefined`" — no, holes removed; result dense and shorter.
- "`flat` deep-flattens" — no, `depth` defaults to 1; use `Infinity`.
- "`flatMap` is just `map(...).flat()`" — similar but `flatMap` is one allocation vs two, and only depth 1.

### 5) **Performance note**

Each `map`/`filter`/`flat` allocates a new array and iterates dense length. Chaining `filter().map().flat()` scans three times. For hot paths over 1e6 elements, a single `for-of` that pushes to result is ~2–3× faster (one pass, one allocation, holes handled explicitly). For typical UI data (`n<1e4`) pipeline clarity outweighs. `flatMap` saves one intermediate vs `map().flat()` — use it when mapping to arrays.
