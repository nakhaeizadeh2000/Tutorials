## 8.1. Common interview Q&A: arrays, holes, sorting, and typed arrays

### 1) **Twelve Q&As with mechanism answers**

**Q1. Are arrays a separate type? What is `typeof []` and `Array.isArray` vs `instanceof`?**

*Answer* — `typeof [] === "object"`; arrays are exotic objects, not a fourth type family ([Values 1.1](<../../../03 Values Types and Coercion/sections/1. The value model/1.1. Eight types two families primitives vs objects.md>)). `Array.isArray` checks brand, works cross-realm; `instanceof Array` walks `Array.prototype` and fails across realms ([Prototypes 5.1](<../../../07 Prototypes and Classes/sections/5. Type checks and reflection/5.1. instanceof isPrototypeOf Symbol.hasInstance and cross-realm failures.md>)). Red flag: "arrays are a type like string".

```js
console.log(typeof []); // object
console.log(Array.isArray([]), [] instanceof Array); // true true (same realm)
const vm = require("node:vm");
console.log(vm.runInNewContext("[]") instanceof Array); // false — different realm
console.log(Array.isArray(vm.runInNewContext("[]"))); // true
```

**Q2. What's the difference between a hole and `undefined`? How do you test?**

*Answer* — Hole = no property; `undefined` value = property exists with `undefined`. `arr[i] === undefined` true for both; `Object.hasOwn(arr,i)` false for hole, true for `undefined`. Holes skip `map`/`filter`/`forEach`/`every`/`some` but are visited by `find`/`findIndex`/`includes`/`for-of`/`spread` as `undefined` (see [2.1](<../2. Holes sparsity and length/2.1. Holes vs undefined sparse arrays and empty slots.md>)). Red flag: "holes are `undefined`".

```js
const h = [1, , 3], d = [1, undefined, 3];
console.log(Object.hasOwn(h, "1"), Object.hasOwn(d, "1")); // false true
console.log(h.includes(undefined), h.indexOf(undefined)); // true -1
console.log(h.map(x => x*2), Object.hasOwn(h.map(x=>x*2),"1")); // [2, hole,6] false
```

**Q3. What does `new Array(3)`, `Array.of(3)`, `Array(3)`, `[3]` do?**

*Answer* — `new Array(3)` / `Array(3)` → 3 holes, `length`3; `Array.of(3)` → `[3]` dense, length1; `[3]` → `[3]` literal. Trap: single numeric arg creates holes, not element (see [1.2](<../1. Arrays are exotic objects/1.2. Creating arrays literals the Array constructor trap Array.of and Array.from.md>)). Red flag: "`new Array(3)` is `[undefined,undefined,undefined]`".

```js
console.log(new Array(3), new Array(3).map(()=>1)); // holes, still holes
console.log(Array.of(3)); // [3]
console.log(Array.from({length:3},()=>1)); // [1,1,1] — fix
```

**Q4. How does `length` interact with indices? What happens on `arr.length = 0` vs `arr = []` vs `delete arr[0]`?**

*Answer* — Index `i` is exotic iff `ToString(ToUint32(key))===key && value<4294967295`; writing index `i>=length` grows `length=i+1` with holes; writing `length=n<old` deletes `n..old-1`; `delete arr[0]` creates hole, length unchanged; `arr.length=0` truncates indices but keeps non-index props; `arr=[]` rebinds (see [2.2](<../2. Holes sparsity and length/2.2. Length invariants and the array index contract.md>)).

```js
const a=[1,2,3]; a["01"]="x"; a.foo="keep";
a.length=1; console.log(a, a["01"], a.foo); // [1] "x" "keep" — non-indices survive
delete a[0]; console.log(a.length, Object.hasOwn(a,"0")); // 1 false — hole
```

**Q5. `indexOf` vs `includes` — when does `NaN` matter, holes matter?**

*Answer* — `indexOf` uses Strict Equality (holes skipped, `NaN` not found); `includes` uses SameValueZero (holes visited as `undefined`, `NaN` found). `lastIndexOf` same as `indexOf` reverse (see [4.1](<../4. Searching slicing and joining/4.1. Searching and testing indexOf lastIndexOf includes find findLast every some.md>)). Red flag: "they're the same except return type".

```js
console.log([NaN].indexOf(NaN), [NaN].includes(NaN)); // -1 true
console.log([,].includes(undefined), [,].indexOf(undefined)); // true -1
```

**Q6. `find` vs `filter` vs `some` vs `every` — return types and hole handling?**

*Answer* — `find`→element/undefined (visits holes); `findIndex`→index/-1 (visits); `filter`→dense array (skips holes); `some`/`every`→boolean (skip holes, vacuous `every` true on empty). Don't use `find` existential check when `find` may return falsy — use `some`/`findIndex` (see [4.1](<../4. Searching slicing and joining/4.1. Searching and testing indexOf lastIndexOf includes find findLast every some.md>)).

```js
console.log([1,0].find(x=>x===0)); // 0 — falsy but found! if(!found) would mis-fire
console.log([1,0].some(x=>x===0)); // true — use some for existence
```

**Q7. `slice` vs `splice` vs `toSpliced` — which mutates, which preserves holes?**

*Answer* — `slice` copies, never mutates, preserves holes; `splice` mutates, compacts; `toSpliced` is copy-era `splice` (densifies holes to `undefined` in the copy, unlike `slice`). `concat` preserves holes one level (see [4.2](<../4. Searching slicing and joining/4.2. Slicing concatenating and joining slice concat join at with.md>) / [3.2](<../3. Mutation and its copy-era alternative/3.2. Non-mutating copies toReversed toSorted toSpliced and with ES2023.md>)).

```js
const a7=[1,,3]; console.log(a7.slice(), Object.hasOwn(a7.slice(),"1")); // preserves false
console.log([...a7], Object.hasOwn([...a7],"1")); // densifies true
console.log(a7.toReversed(), Object.hasOwn(a7.toReversed(),"1")); // densifies true
```

**Q8. `map` vs `forEach` vs `for-of` vs `Array.from` for holes?**

*Answer* — `map`/`forEach`/`filter` skip holes, `map` preserves holes in result; `for-of`/`Array.from`/`spread` densify (visit holes as `undefined`); `reduce` skips holes (see [2.1](<../2. Holes sparsity and length/2.1. Holes vs undefined sparse arrays and empty slots.md>) / [5.1](<../5. Transforming ordering and typed preview/5.1. Mapping filtering flat and flatMap pipelines.md>)). Red flag: "`map` densifies".

```js
console.log([1,,3].map(x=>x*2), [...[1,,3]].map(x=>(x??-1)*2)); // [2,hole,6] vs [2,-2,6]
```

**Q9. Why does `["10","10","10"].map(parseInt)` give `[10, NaN, 2]`?**

*Answer* — `map` passes `(value, index)`; `parseInt` takes `(string, radix)`, so index becomes radix: `parseInt("10",0)→10, parseInt("10",1)→NaN, parseInt("10",2)→2`. Fix `x=>parseInt(x,10)` or `Number(x)` (see [5.1](<../5. Transforming ordering and typed preview/5.1. Mapping filtering flat and flatMap pipelines.md>)). Red flag: mysterious NaN blamed on `parseInt` bug.

**Q10. What does `reduce` do without initial on empty, sparse, or single-element?**

*Answer* — Empty without initial → `TypeError`; single present element without initial → returns it without calling callback; sparse without initial uses first present as `acc` (see [5.2](<../5. Transforming ordering and typed preview/5.2. Reducing and sorting reduce reduceRight sort stability and compareFn.md>)). Always provide initial when folding to different type or empty possible.

```js
try{ [].reduce((a,x)=>a+x)}catch(e){console.log(e.name)} // TypeError
console.log([1].reduce((a,x)=>a+x)); // 1 — callback not called
console.log([, ,3].reduce((a,x)=>a+x,0)); // 3 — holes skipped, initial 0
```

**Q11. How does `sort` work without `compareFn`? Is it stable? What about `toSorted`?**

*Answer* — Without `compareFn`, elements `ToString` then lexicographic UTF-16; numbers sort wrong: `[10,9].sort()`→`[10,9]` lexical. Fix `(a,b)=>a-b`. `sort` mutates, `toSorted` is copy-era densifies then same algorithm. Stable since ES2019 (needed for multi-key). Holes sort to end (see [5.2](<../5. Transforming ordering and typed preview/5.2. Reducing and sorting reduce reduceRight sort stability and compareFn.md>)). Red flag: "sort is numeric by default".

```js
console.log([10,9].sort(), [10,9].toSorted((a,b)=>a-b)); // [10,9] wrong vs [9,10] correct
console.log([1,,3,undefined].sort()); // [1,3,undefined, hole] — holes last
```

**Q12. How do `Array`, `TypedArray`, `ArrayBuffer`, `DataView` differ? When to use which?**

*Answer* — `Array` exotic, growable, holes, `Array.isArray` true, mix types; `ArrayBuffer` fixed bytes; `TypedArray` dense numeric view (fixed length, no push, wrap/clamp, `Array.isArray` false, `ArrayBuffer.isView` true); `DataView` untyped offset+endian accessor for mixed packets. Use `Array` for data pipelines, `TypedArray` for binary/canvas/WASM, `DataView` for endian-sensitive parsing (see [5.3](<../5. Transforming ordering and typed preview/5.3. ArrayBuffer TypedArray and DataView how they differ from Array.md>)). Red flag: "`TypedArray` is `Array` subclass".

```js
console.log(Array.isArray(new Uint8Array([1]))); // false
console.log(ArrayBuffer.isView(new Uint8Array([1]))); // true
console.log(new Uint8Array(2).map(x=>1)); // Uint8Array [1,1] — stays typed
```

### 2) **What interviewers actually probe for**

Tracing exotic `length` invariants and hole visitation per method (not just naming methods); knowing which methods skip vs densify; narrating `sort` comparator contract and stability; distinguishing mutable vs copy-era ownership for state; reading `ArrayBuffer` vs `Array` density/wrap semantics.

### 3) **Grading guidance**

Junior — answers Q1–Q3 without conflating holes/`undefined`/`Array(n)`; knows `Array.isArray` and `sort` lexical trap.
Mid — correctly states per-method hole table (map preserves, find/includes visit, every/some skip) and `toSorted` copy-era; fixes `reduce` empty case and `parseInt` trap.
Senior/Expert — traces cross-realm `instanceof` failure, `length` exotic on truncation + non-index survival, stable sort multi-key use, TypedArray fixed/wrap vs `Array` exotic, and anticipates state mutation bugs with shallow alias after `toReversed`.
