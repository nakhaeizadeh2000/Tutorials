## 6.1. Array checklist: reflex rules mentors screen for

### 1) **Holes vs `undefined` vs `length` truncation — three checks before any index claim**

Every array bug stems from conflating "no property" (hole) with "property whose value is `undefined`" and from forgetting `length` is `highestIndex+1`, not present count.

```js
// Reflex 1 — holes are not undefined
const a = [1, , 3]; // hole at 1
console.log(a[1] === undefined); // true — but misleading
console.log(Object.hasOwn(a, "1")); // false — the test that matters
console.log(a.includes(undefined), a.indexOf(undefined) !== -1); // true vs false — includes visits holes, indexOf skips (see §4.1)
console.log(a.slice().hasOwnProperty("1")); // false — slice preserves hole
console.log([...a].hasOwnProperty("1")); // true — spread densifies to undefined

// Reflex 2 — length is highestIndex+1, not count
console.log([1, , 3].length, Object.keys([1, , 3]).length); // 3 vs 2 — length includes holes
console.log([1, 2, 3].length); // 3 vs present 3 — dense equality hides the difference
// Present count when needed:
function presentCount(arr) { return arr.reduce((n, _, i) => n + (Object.hasOwn(arr, i) ? 0 : 0), 0); } // trivial? Use keys:
console.log(Object.keys([1, , 3]).length); // 2 — present string indices

// Reflex 3 — length write truncates, delete creates hole
const b = [1, 2, 3];
delete b[1]; // hole, length 3
console.log(b.length, Object.hasOwn(b, "1")); // 3 false
b.length = 2; // delete 2
console.log(b, b.length); // [1, <empty>] 2 — hole + truncated? Actually [1, empty] hole at1 + length2
b.length = 0;
console.log(b.length, b); // 0 [] — truly empty; non-index props survive length=0 (see §2.2)
```

### 2) **Mutating vs copy-era choice and `compareFn` discipline**

| Decision | Rule |
|----------|------|
| Mutate in place (`sort`, `reverse`, `splice`, `push`, `fill`) | only when you own the array (local variable, not shared state/param) |
| Copy-era (`toSorted`, `toReversed`, `toSpliced`, `with`) | default at state/API boundaries, reducers, props |
| `sort` without `compareFn` | never on numbers — use `(a,b)=>a-b` or `localeCompare` for strings |
| `reduce` without initial | never when empty possible — always pass initial for folds to different type |

```js
// Bad — mutating shared param
function addScores(scores, bonus) { scores.push(bonus); return scores.sort(); } // mutates input + lexical sort bug
console.log(addScores([10, 9], 20)); // [10,10,9]? Wait 9,10,20 lexical? Let's verify: [9,10,20].sort() → [10,20,9] wrong

// Good — copy-era + numeric compare + no mutation of param
function addScoresGood(scores, bonus) {
  return [...scores, bonus].toSorted((a, b) => a - b);
}
console.log(addScoresGood([10, 9], 20)); // [9,10,20]
console.log(addScoresGood([], 5)); // [5] — handles empty

// reduce without initial — only when non-empty guaranteed and same-type fold
console.log([1, 2, 3].reduce((a, x) => a + x)); // 6 — ok, non-empty numbers → number
console.log([].reduce((a, x) => a + x, 0)); // 0 — empty needs initial
// Safer always provide initial:
function sum(arr) { return arr.reduce((a, x) => a + x, 0); }
```

### 3) **The review grep list**

Use these greps in code review / lint:

| Pattern | Flag | Fix |
|---------|------|-----|
| `new Array\(\s*\d` | single-arg Array constructor → holes | `Array.from({length:n}, fn)` or `Array(n).fill(0)` then map |
| `\.sort\(\)` / `\.toSorted\(\)` without comparator on numbers | lexical sort bug | add `(a,b)=>a-b` or `localeCompare` |
| `\.reduce\(` without second arg and input may be empty | TypeError on empty | add initial value |
| `\.map\(parseInt` / `\.map\(Number\.parseInt` | radix trap | `x => parseInt(x,10)` |
| `for\s*\(.*;\s*.*\.length` with `splice` inside body | index-shift skip bug | reverse iteration or `filter` |
| `delete\s+\w+\[` | array hole creation | `splice` to compact or document hole intent |
| `Array\(\d+\)\.fill\(\[\]\)` | aliased inner arrays | `Array.from({length:n}, () => [])` |

### 4) **Mentor note**

Run a 5-minute live quiz: 1) `new Array(3).map(()=>1)` length and holes? 2) `[10,9].sort()` vs `[10,9].toSorted((a,b)=>a-b)`? 3) `[].reduce((a,x)=>a+x)` throws? 4) `[1,,3].includes(undefined)` vs `indexOf`? Expect `true` vs `-1`. Candidates who answer from exotic/hole invariants, not memorized outcomes, show the mental model that prevents prod bugs.
