## 4.1. Searching and testing: indexOf, lastIndexOf, includes, find, findLast, every, some

### 1) **`indexOf` vs `includes` — Strict Equality vs SameValueZero**

**Definition** — `indexOf(searchElement, fromIndex?)` returns first index where `arr[i] === searchElement` for *present* elements only (holes skipped, so `undefined` in a hole never matches), else `-1`; `NaN` never matches. `includes(searchElement, fromIndex?)` returns `boolean` via `SameValueZero` (`x === y || (x !== x && y !== y)`), so `NaN` matches `NaN`, and holes are visited as `undefined` (so `[,].includes(undefined)` is `true`).

```js
console.log([1, 2, NaN].indexOf(NaN)); // -1 — strict never finds NaN
console.log([1, 2, NaN].includes(NaN)); // true — SameValueZero finds NaN
console.log([1, 2, 3].includes(2, 2)); // false — fromIndex 2 starts after 2
console.log([1, , 3].includes(undefined)); // true — hole visited as undefined
console.log(Array(3).includes(undefined)); // true — 3 holes → includes sees 3 undefineds
console.log([1, , 3].indexOf(undefined)); // -1 — holes skipped, no actual undefined value
console.log([1, undefined, 3].includes(undefined)); // true — real undefined value
console.log([1, undefined, 3].indexOf(undefined)); // 1 — real value found (not hole)

// Same hole/value distinction for indexOf vs includes
console.log([, , ,].includes(undefined)); // true
console.log([, , ,].indexOf(undefined)); // -1

// -0 vs 0 — both treat as same
console.log([0].includes(-0)); // true
console.log([0].indexOf(-0)); // 0
console.log([NaN].indexOf(NaN)); // -1
console.log([NaN].includes(NaN)); // true

// fromIndex negative clamps to length+fromIndex
console.log([1, 2, 3, 2].indexOf(2, -2)); // 3 — fromIndex 2
console.log([1, 2, 3].includes(1, -10)); // true — clamped to 0
console.log([1, 2, 3].indexOf(1, 10)); // -1 — beyond length

// lastIndexOf — reverse scan, same hole/NaN rules as indexOf (holes skipped, NaN not found)
console.log([1, 2, 3, 2].lastIndexOf(2)); // 3
console.log([1, 2, 3].lastIndexOf(2, 1)); // 1 — fromIndex 1
console.log([1, , 3].lastIndexOf(undefined)); // -1 — hole skipped, same as indexOf
console.log([1, undefined, 3].lastIndexOf(undefined)); // 1 — real value
console.log([1, NaN, 2].lastIndexOf(NaN)); // -1 — NaN not found
```

- *Modern guidance* — prefer `includes` for existence (`if (arr.includes(x))`) over `indexOf(x) !== -1`; it communicates boolean intent and handles `NaN` and holes-as-`undefined`. Use `indexOf` when you need the index for `splice`/`with` and you treat holes as absent.

### 2) **`find`/`findIndex`/`findLast`/`findLastIndex` — predicate first match**

All four take `predicate(element, index, array)` and optional `thisArg`. They differ in direction and return type:

- `find` → first `element` where predicate truthy, else `undefined` (ambiguous with stored `undefined`).
- `findIndex` → first `index`, else `-1`.
- `findLast` / `findLastIndex` (ES2023) → scan from end.

Unlike `forEach`/`map`/`filter`/`every`/`some`, these **visit holes** — the predicate is called with `undefined` for each hole (like `for-of` densifies). `indexOf`/`lastIndexOf` skip holes; `includes`/`find*` densify.

```js
const users = [{ id: 1, active: false }, { id: 2, active: true }, { id: 3, active: true }];

console.log(users.find(u => u.active)); // {id:2,...} — first match
console.log(users.findIndex(u => u.active)); // 1
console.log(users.find(u => u.id === 99)); // undefined — not found (ambiguous)
console.log(users.findIndex(u => u.id === 99)); // -1 — use findIndex when undefined is valid value

// findLast walks reverse (ES2023, Node 20+)
console.log(users.findLast(u => u.active)); // {id:3,...}
console.log(users.findLastIndex(u => u.active)); // 2
console.log([1, 2, 3, 2].findLast(x => x === 2)); // 2 — last occurrence
console.log([1, 2, 3].findLast(x => x === 99)); // undefined

// Holes ARE visited — predicate called for hole as undefined
let calls = 0;
[1, , 3].find((x, i) => { calls++; return x === 3; });
console.log(calls); // 3 — index 1 hole visited (x===undefined)
console.log([1, , 3].find(x => x === undefined)); // undefined — hole found
console.log([1, , 3].findIndex(x => x === undefined)); // 1 — hole index
console.log([1, , 3].findLast(x => x === undefined)); // 1 — hole visited reverse too

// By contrast, every/some/forEach skip holes — same array, different visitation
let someCalls = 0; [1, , 3].some(x => { someCalls++; return false; });
console.log(someCalls); // 2 — hole skipped

// thisArg binding (rare; arrow captures lexically instead)
const checker = { target: 2 };
console.log([1, 2, 3].find(function (x) { return x === this.target; }, checker)); // 2

// Bad — find returns undefined both for "found undefined" and "not found"
const arr = [1, undefined, 3];
console.log(arr.find(x => x === undefined)); // undefined — did we find it or not?
console.log(arr.findIndex(x => x === undefined) !== -1 ? "found" : "not found"); // found — use findIndex to disambiguate
// Good — if undefined is a valid search value, use includes or findIndex
console.log(arr.includes(undefined)); // true — if you just need existence

// Predicate receives index and array
console.log([10, 20, 30].find((x, i) => i === 1)); // 20
console.log([1, 2, 3].find((_, i, a) => i === a.length - 1)); // 3
```

### 3) **`every`/`some` — short-circuit all/any with the same predicate shape**

- `every(pred)` → true iff predicate returns truthy for *every* present element (holes **skipped**, not visited — so `[1,,3].every(x=> typeof x==="number")` is true). Vacuously true for empty: `[].every(() => false) === true`.
- `some(pred)` → true iff predicate returns truthy for *some* present element (holes skipped). Vacuously false for empty: `[].some(() => true) === false`.
- Both skip holes like `forEach`/`map`/`filter` (unlike `find`/`includes`).

```js
console.log([1, 2, 3].every(x => x > 0)); // true
console.log([1, 2, 3].every(x => x > 1)); // false — short-circuits at 1
console.log([].every(x => x > 100)); // true — vacuous! Every of empty is true
console.log([].some(x => x > 0)); // false — some of empty is false

// Short-circuiting — predicate not called after decision
let everyCalls = 0, someCalls2 = 0;
[1, 2, 3].every(x => { everyCalls++; return x < 2; });
console.log(everyCalls); // 2 — stopped at 2 (false)
[1, 2, 3].some(x => { someCalls2++; return x === 2; });
console.log(someCalls2); // 2 — stopped at 2 (true)

// Holes skipped (unlike find/includes)
let holeCalls = 0;
[1, , 3].every(x => { holeCalls++; return true; });
console.log(holeCalls); // 2 — hole not visited
console.log([1, , 3].every(x => typeof x === "number")); // true — holes ignored, passes present elements
console.log([1, , 3].some(x => x === undefined)); // false — holes skipped, no undefined visited
console.log([1, undefined, 3].some(x => x === undefined)); // true — real undefined visited
console.log([1, , 3].find(x => x === undefined) !== undefined || [1, , 3].findIndex(x => x === undefined) !== -1 ? "hole found via find" : ""); // hole found via find — find DOES visit

// Common use — field validation
const rows = [{ age: 20 }, { age: 30 }, { age: 17 }];
console.log(rows.every(r => r.age >= 18)); // false
console.log(rows.some(r => r.age >= 18)); // true

// includes vs some for NaN
console.log([1, NaN, 3].includes(NaN)); // true
console.log([1, NaN, 3].some(x => Number.isNaN(x))); // true — explicit NaN check via some
```

- *Bad practice* — `if (arr.find(x => pred))` to test existence when `find` may return falsy like `0` or `""` → false negative. *Instead* — `arr.some(pred)` for boolean or `arr.findIndex(pred) !== -1` when value needed.

### 4) **Common confusion**

- "`includes` skips holes, `indexOf` finds them" — opposite: `includes` visits holes as `undefined` (`true` for `[,].includes(undefined)`), `indexOf` skips (`-1`).
- "`find` skips holes" — no, `find`/`findIndex`/`findLast` visit holes as `undefined` (3 calls for `[1,,3]`); `every`/`some`/`forEach`/`map` skip (2 calls).
- "`find` returns `null` when not found" — no, `undefined`; `findIndex` returns `-1`. Guard with `findIndex` if `undefined` is a valid element.
- "`every` on empty is false" — wrong; mathematically vacuous truth → `true`. Same surprise causes validation `if (!rows.every(valid))` to pass when `rows` is empty — often a bug; guard `rows.length && rows.every(valid)` if empty should fail.

### 5) **Performance note**

All linear searches are O(n) with early exit for `find`/`every`/`some` vs full scan for `indexOf`/`includes` without early hint. For sorted arrays, `includes` is still O(n); if `n > 1e4` and repeated lookups, convert to `Set` (O(1) — see Collections). `findLast` is O(n) reverse scan — no binary search. Provide `fromIndex` to skip known prefix. Holes add branch per index for skip-vs-visit methods.
