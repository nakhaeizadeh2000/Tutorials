## 4.2. Slicing, concatenating, and joining: slice, concat, join, at, with

### 1) **`slice` copies shallowly with clamping; never mutates**

`slice(start?, end?)` returns a new array copying `start..end-1` (negative indices mean `length+index`, clamped to `0..length`). It *preserves* holes (like `map`), shallow-copies elements, and never mutates the original.

```js
console.log([1, 2, 3, 4].slice(1, 3)); // [2,3]
console.log([1, 2, 3].slice(1)); // [2,3] — end defaults to length
console.log([1, 2, 3].slice()); // [1,2,3] — shallow copy idiom (preserves holes)
console.log([1, 2, 3].slice(-2)); // [2,3] — negative start = 1
console.log([1, 2, 3].slice(-10, 2)); // [1,2] — clamped
console.log([1, 2, 3].slice(10)); // [] — beyond length

// Holes preserved (unlike spread/Array.from/toReversed)
const sparse = [1, , 3];
console.log(sparse.slice()); // [1, <1 empty>, 3] — hole preserved
console.log(Object.hasOwn(sparse.slice(), "1")); // false — still hole
console.log([...sparse]); // [1, undefined, 3] — spread densifies (contrast)
console.log(sparse.slice(0, 2)); // [1, <empty>] — hole preserved in sub-slice

// Negative handling
console.log([1, 2, 3, 4].slice(-3, -1)); // [2,3] — -3→1, -1→3
console.log([1, 2].slice(1, 0)); // [] — start > end clamped empty

// Shallow — nested refs shared
const nested = [[1], [2]];
const copy = nested.slice();
console.log(copy !== nested); // true — new outer
console.log(copy[0] === nested[0]); // true — same inner array
copy[0].push(99);
console.log(nested[0]); // [1,99] — leaked

// Classic clone patterns — subtle differences with holes
const a = [1, , 3];
console.log(a.slice()); // [1, hole, 3] preserve
console.log([...a]); // [1, undefined, 3] densify
console.log(Array.from(a)); // [1, undefined, 3] densify
console.log(a.toReversed().toReversed()); // [1, undefined, 3] — double-reverse densifies once
```

- *Modern guidance* — use `slice` when you need a shallow copy that *preserves* sparsity for later hole-aware logic; use `Array.from`/`spread` when you want to normalize to dense `undefined`s.

### 2) **`concat` flattens one level — and respects `Symbol.isConcatSpreadable`**

`concat(...values)` returns a new array: if `value` is an array (or spreadable object), its elements are spread one level; otherwise `value` is appended as a single element. Respects `Symbol.isConcatSpreadable`.

```js
console.log([1, 2].concat([3, 4])); // [1,2,3,4] — one level flatten
console.log([1, 2].concat(3, 4)); // [1,2,3,4] — non-arrays appended
console.log([1].concat([[2]])); // [1, [2]] — only one level, nested stays
console.log([1, 2].concat()); // [1,2] — copy

// Holes preserved through concat
const s = [1, , 3];
console.log(s.concat([4])); // [1, <hole>, 3, 4] — hole from s preserved
console.log(Object.hasOwn(s.concat([4]), "1")); // false — hole preserved
console.log([1, 2].concat(s)); // [1,2,1, <hole>, 3] — hole preserved via concat too

// Symbol.isConcatSpreadable — controls flattening
const spreadable = { 0: "a", 1: "b", length: 2, [Symbol.isConcatSpreadable]: true };
console.log([1].concat(spreadable)); // [1, "a", "b"] — array-like spread as array
const notSpreadable = [1, 2];
notSpreadable[Symbol.isConcatSpreadable] = false;
console.log([0].concat(notSpreadable)); // [0, [1,2]] — array NOT spread, appended as single

// concat vs spread for merging
const left = [1, 2], right = [3, 4];
console.log(left.concat(right)); // [1,2,3,4]
console.log([...left, ...right]); // [1,2,3,4] — spread equivalent but holes densify (see above)

// Shallow as well
const obj = { x: 1 };
console.log([obj].concat([obj])[0] === obj); // true
```

### 3) **`join` stringifies via `ToString` with hole→`""` and `toString` alias; `at`/`with` handle negative indices**

- `join(separator=",")` — builds string by `ToString` each present element; holes and `undefined`/`null` become `""` (empty). `toString()` is alias for `join(",")`. `Array.isArray`? Join never visits holes separately.
- `at(index)` (ES2022) — reads `arr.at(-1)` as `arr[length-1]` without `length` math, handles negative. Same for string.
- `with` (ES2023) — immutable `arr.with(index, value)` (see §3.2).

```js
// join — hole and undefined/null all become ""
console.log([1, , 3].join("-")); // 1--3 — hole → ""
console.log([1, undefined, 3].join("-")); // 1--3 — undefined → ""
console.log([1, null, 3].join("-")); // 1--3 — null → ""
console.log([1, 2, 3].join()); // 1,2,3 — default comma
console.log([1, 2, 3].toString()); // 1,2,3 — alias
console.log([].join("-")); // "" — empty join is ""
console.log([1, , [2, 3]].join("-")); // 1--2,3 — nested array toString via join comma

// Custom toString via join
console.log([1, 2].join(" | ")); // 1 | 2

// at — negative without length math, out-of-bounds → undefined
const arr = [10, 20, 30];
console.log(arr.at(0)); // 10
console.log(arr.at(-1)); // 30
console.log(arr.at(-2)); // 20
console.log(arr.at(10)); // undefined — not RangeError (contrast with with)
console.log(arr.at(-10)); // undefined
// Verbose old way:
console.log(arr[arr.length - 1]); // 30 — at(-1) is ergonomic

// with — immutable at with value (ES2023)
console.log(arr.with(1, 99)); // [10,99,30]
console.log(arr.with(-1, 99)); // [10,20,99] — negative like at
try { console.log(arr.with(10, 99)); } catch (e) { console.log(e.name); } // RangeError — bounds checked

// join edge — non-string separator coerced via ToString
console.log([1, 2, 3].join(null)); // 1null2null3 — separator "null"
console.log([1, 2, 3].join(undefined)); // 1,2,3 — undefined → default comma (special)
```

### 4) **Common confusion**

- "`concat` deep-flattens" — no, one level only (`[1].concat([[2]])` → `[1,[2]]`; use `flat(Infinity)` to deep-flatten).
- "`slice` densifies holes" — no, `slice` preserves (use `Array.from` to densify). `toReversed`/`with`/`spread` densify (see §2.1 table).
- "`join` skips holes" — no, hole → `""` with separator on both sides, so `[1,,3].join("-")` has double separator, not single.
- "`at` throws on out-of-bounds" — no, returns `undefined`; `with` throws `RangeError`.

### 5) **Performance note**

`slice` and `concat` are memmove-fast for dense arrays; for `n=1e6` they allocate one new backing store and copy. `join` is O(n) string build; repeated `+=` in a loop is slower (creates intermediate strings). For large CSV generation, `arr.join(",")` is the fast path; `arr.toString()` identical. `at(-1)` is bounds-checked property access — same cost as `arr[length-1]`.

### 6) **Mentor note**

Have juniors predict `Object.hasOwn([...[1,,3]], "1")` vs `Object.hasOwn([1,,3].slice(), "1")` (true vs false). In review, flag any `arr[arr.length-1]` where `at(-1)` reads clearer, and any `arr.concat(x)` where `[...arr, ...x]` densifies holes unintentionally.
