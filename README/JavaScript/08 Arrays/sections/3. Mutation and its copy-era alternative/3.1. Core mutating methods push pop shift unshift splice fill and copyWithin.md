## 3.1. Core mutating methods: push pop shift unshift splice fill and copyWithin

### 1) **Stack/queue ends: `push`/`pop` are fast, `shift`/`unshift` re-index**

**Definition** — `push(...xs)` appends and returns new `length`; `pop()` removes last and returns it; `shift()` removes first and re-indexes `0..length-2` down by one; `unshift(...xs)` inserts at 0 and re-indexes up. All mutate `this` and return length or the removed element.

```js
// push/pop — O(1) amortized (backing store grows by factor, rarely reallocs)
const a = [1, 2];
console.log(a.push(3, 4)); // 4 — new length
console.log(a); // [1,2,3,4]
console.log(a.pop()); // 4
console.log(a); // [1,2,3]
console.log([].pop()); // undefined — empty pop is safe

// shift/unshift — O(n) re-index (moves every element)
const b = [1, 2, 3];
console.log(b.shift()); // 1 — removes index 0, shifts 1→0, 2→1
console.log(b); // [2,3]
console.log(b.unshift(0, 1)); // 4 — inserts at 0, shifts existing up
console.log(b); // [0,1,2,3]
console.log([].shift()); // undefined — safe on empty

// Holes move with re-index
const c = [1, , 3]; // hole at 1
c.unshift(0);
console.log(c); // [0,1,<empty>,3] — hole moved to index 2
c.shift();
console.log(c); // [1,<empty>,3] — back

// Return values matter for chaining discipline
const d = [1];
const len = d.push(2); // len is number, not array — chaining must be d.push(2); d
console.log(Array.isArray(len)); // false — common bug: const x = arr.push(1).map(...) TypeError

// Performance probe — push vs unshift at scale (measure, don't guess)
function bench(fn) { const t0 = performance.now(); fn(); return performance.now() - t0; }
const N = 20000;
console.log("push", bench(() => { const arr = []; for (let i = 0; i < N; i++) arr.push(i); }).toFixed(1) + "ms");
console.log("unshift", bench(() => { const arr = []; for (let i = 0; i < N; i++) arr.unshift(i); }).toFixed(1) + "ms");
// Expect unshift ~ 10-100× slower for N=20000 due to O(n²) re-index; use push + reverse or deque (→ Collections)
```

- *Modern guidance* — `push`/`pop` are the hot-path primitives; avoid `shift`/`unshift` inside loops over large arrays (use index queue or `Array.prototype` + `reverse` trick, or `Map`/`Deque` pattern). For many prepends, accumulate then `reverse` once.

### 2) **`splice` is the Swiss knife — delete, insert, replace**

`splice(start, deleteCount, ...items)` at `start` (clamped, negative means `length+start`) deletes `deleteCount` elements (if omitted, deletes to end) and inserts `...items`. Returns array of deleted elements; mutates original; truncates or grows `length`.

```js
// Delete
const e = [1, 2, 3, 4];
console.log(e.splice(1, 2)); // [2,3] — deleted
console.log(e); // [1,4] — mutated

// Insert (deleteCount 0)
const f = [1, 4];
f.splice(1, 0, 2, 3);
console.log(f); // [1,2,3,4]

// Replace
const g = [1, 2, 3];
g.splice(1, 1, 99);
console.log(g); // [1,99,3]

// Negative start
const h = [1, 2, 3, 4];
h.splice(-2, 1); // start = 4-2 =2
console.log(h); // [1,2,4]

// deleteCount omitted → to end
const i = [1, 2, 3, 4];
console.log(i.splice(2)); // [3,4]
console.log(i); // [1,2]

// Beyond bounds clamping
const j = [1, 2];
j.splice(10, 1, 3); // start clamped to 2
console.log(j); // [1,2,3]
j.splice(0, 10); // deleteCount clamped
console.log(j); // []

// Holes and splice
const k = [1, , 3, 4];
console.log(k.splice(1, 1)); // [<1 empty>] — deleted hole as hole, not undefined
console.log(k); // [1,3,4] — compacted, now dense

// Bad — splicing while iterating forward corrupts indices
const bad = [1, 2, 3, 4];
for (let idx = 0; idx < bad.length; idx++) {
  if (bad[idx] % 2 === 0) bad.splice(idx, 1); // removes 2 at idx1, now 3 shifts to idx1 but idx++ skips it
}
console.log(bad); // [1,3,4] — 3 skipped, 4 remains! Bug
// Good — filter (non-mutating) or reverse iteration
const good = [1, 2, 3, 4].filter(x => x % 2 !== 0);
console.log(good); // [1,3]
const good2 = [1, 2, 3, 4];
for (let idx = good2.length - 1; idx >= 0; idx--) if (good2[idx] % 2 === 0) good2.splice(idx, 1);
console.log(good2); // [1,3] — reverse avoids shift-skip

// Splice return is always array, even for 1 element
console.log([1, 2, 3].splice(0, 1)); // [1] — not 1
```

### 3) **`fill` and `copyWithin` write in place with overlapping semantics**

Both mutate, return `this` (chainable), handle negative indices, holes preserved as written.

- `fill(value, start=0, end=length)` — writes `value` to `start..end-1` (same object reference — `fill([])` shares one array).
- `copyWithin(target, start, end=length)` — copies slice `start..end` to `target` within same array, correctly handling overlap as if via temp copy (memmove semantics).

```js
// fill — range clamping, same-value sharing gotcha
const a1 = Array(3).fill(0);
console.log(a1); // [0,0,0]
console.log(a1.fill(9, 1, 2)); // [0,9,0] — range [1,2)
console.log(a1.fill(7, -2)); // [0,7,7] — negative start = length-2

const shared = Array(3).fill([]);
console.log(shared); // [ [], [], [] ] — same array object!
shared[0].push(1);
console.log(shared); // [ [1], [1], [1] ] — all share! Bug
// Fix — map after fill or from
console.log(Array.from({ length: 3 }, () => [])); // [ [], [], [] ] distinct

// fill on holey
const holey = [1, , 3];
holey.fill(99, 1, 2);
console.log(holey, Object.hasOwn(holey, "1")); // [1,99,3] true — hole filled

// copyWithin — in-place memmove
console.log([1, 2, 3, 4, 5].copyWithin(0, 3)); // [4,5,3,4,5] — copy slice [4,5] (indices 3..5) to 0
console.log([1, 2, 3, 4, 5].copyWithin(0, 3, 4)); // [4,2,3,4,5] — end 4 → slice [4] → write at 0
console.log([1, 2, 3, 4, 5].copyWithin(1, 0, 3)); // [1,1,2,3,5] — copy [1,2,3] to index 1
console.log([1, 2, 3, 4, 5].copyWithin(-2, 0, 2)); // [1,2,3,1,2] — negative target 3

// Overlapping correctly (forward copy doesn't clobber source)
console.log([1, 2, 3].copyWithin(1, 0, 2)); // [1,1,2] — correctly handles overlap via temp

// Returns this (chainable)
const c1 = [1, 2, 3];
console.log(c1.fill(0) === c1); // true
console.log(c1.copyWithin(0, 1) === c1); // true

// Holes preserved through copyWithin
const s2 = [1, , 3, 4];
s2.copyWithin(0, 2);
console.log(s2, Object.hasOwn(s2, "1")); // [3,4,3,4]?? Actually copyWithin(0,2) on [1,hole,3,4] → slice [3,4] → [3,4,3,4] dense
```

### 4) **Common confusion**

- "`push` returns the array" — no, returns `length`. `splice`/`copyWithin`/`fill` return array/self; `pop`/`shift` return element.
- "`splice` is like `slice`" — `splice` mutates, `slice` copies (see §4.2).
- "`fill([])` gives distinct arrays" — no, one object shared. Use `Array.from`.

### 5) **Performance note**

`push` is amortized O(1); `shift`/`unshift`/`splice(0, …)` are O(n) per call due to re-index. Batch prepends via `unshift` in a loop is O(n²); buffer with `push` then `reverse` or use linked structure. `fill`/`copyWithin` are memmove-fast and preserve `PACKED` kind when filling with same-type values.
