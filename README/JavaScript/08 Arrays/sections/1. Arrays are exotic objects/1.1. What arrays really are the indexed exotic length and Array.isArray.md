## 1.1. What arrays really are: the indexed exotic, length, and Array.isArray

### 1) **Indexed exotic, not plain object**

**Definition** — an Array is an *exotic object* whose indexed properties (`"0"`, `"1"`, …) and `length` obey extra invariants defined in ECMA-262 §10.4.2. An index `i` is exotic iff `ToString(ToUint32(i)) === key` and `ToUint32(i) < 2³²−1` (so `0` to `4294967294`). Keys like `"01"`, `"4294967295"`, `"-0"` are ordinary string keys, not indices.

**What problem it solves / history** — JavaScript needed ordered collections with a fast `length` before engines had hidden classes. The exotic gives `length` magic: `arr[5] = x` auto-grows `length` to `6`; `arr.length = 2` deletes the tail. Without it, every `push` would be `obj[obj.length] = x; obj.length++` manually.

```js
// Exotic indices vs ordinary keys
const a = ["a", "b"];
console.log(Object.getOwnPropertyDescriptor(a, "0")); // { value: 'a', writable:true, enumerable:true, configurable:true }
console.log(Object.getOwnPropertyDescriptor(a, "length")); // { value:2, writable:true, enumerable:false, configurable:false }

a["01"] = "not an index"; // string key, not exotic
a["4294967295"] = "also not index"; // 2^32-1 excluded
a[4294967294] = "max index"; // highest legal index
console.log(a.length); // 4294967295 — grew to maxIndex+1 (sparse, don't actually allocate this in prod!)
console.log(Object.hasOwn(a, "01"), Object.hasOwn(a, "4294967295")); // true true — ordinary keys
// Reset for sanity
a.length = 2;
console.log(a.length, "01" in a, "4294967295" in a); // 2 true true — truncation didn't delete non-indices

// Arrays still accept non-index properties without affecting length
const b = [1, 2];
b.foo = "bar";
b["01"] = "weird";
console.log(b.length, b.foo, b["01"]); // 2 'bar' 'weird'

// Holes are missing indexed properties, not undefined values
const sparse = [1, , 3]; // hole at 1
console.log(sparse.length); // 3
console.log(Object.hasOwn(sparse, "1")); // false — no property
console.log(sparse[1]); // undefined — read of missing key returns undefined, same as obj.foo
console.log("1" in sparse); // false vs sparse[1] === undefined true — use hasOwn/in to distinguish
```

- *Modern guidance* — treat arrays as ordered maps from `0..length-1` with holes allowed. Don't rely on non-index keys counting toward `length`; don't use `"01"` as index. For "is this an array?" never use `instanceof` or `typeof`.

### 2) **`length` is an own data property with side effects**

`length` is own, non-enumerable, non-configurable, writable by default — but writes *trigger* the exotic invariant (ECMA-262 `ArraySetLength`). Two directions:

- **Index write grows length:** `arr[10] = x` where `10 >= length` sets `length = 11` (fills gap with holes, not `undefined`).
- **Length write truncates/grows:** `arr.length = n` where `n < length` deletes properties `"n"`…`"length-1"`; where `n > length` it extends with holes (no values created).

```js
// Growing via index
const c = [1, 2];
c[5] = 99;
console.log(c); // [ 1, 2, <3 empty items>, 99 ]
console.log(c.length); // 6
console.log(Object.hasOwn(c, "3"), Object.hasOwn(c, "4")); // false false — holes, not undefined

// Truncating via length
c.length = 2;
console.log(c); // [ 1, 2 ]
console.log(Object.hasOwn(c, "5")); // false — deleted

// Extending via length creates holes, not undefined slots
c.length = 5;
console.log(c); // [ 1, 2, <3 empty items> ]
console.log(Object.hasOwn(c, "2"), c[2]); // false undefined — hole, not "3" property

// Non-writable length blocks growth
const d = [1, 2, 3];
Object.defineProperty(d, "length", { writable: false });
console.log(Object.getOwnPropertyDescriptor(d, "length").writable); // false
try { d.push(4); } catch (e) { console.log(e.name); } // TypeError in strict/module
console.log(d.length); // 3 — push failed
try { d[3] = 4; } catch (e) { console.log(e.name); } // TypeError — index >= length needs length bump
console.log(d[3]); // undefined
// Cannot restore writable true once flipped when configurable false — must create new array
try { Object.defineProperty(d, "length", { writable: true }); } catch (e) { console.log(e.name); } // TypeError — non-configurable
console.log(Object.getOwnPropertyDescriptor(d, "length").writable); // still false
const d2 = [...d, 4]; // copy to new array to grow instead
console.log(d2); // [ 1, 2, 3, 4 ]

// length is non-configurable — cannot delete it
console.log(delete d.length); // false (strict: TypeError)
```

- *History* — pre-ES5, `length` quirks were underspecified; ES5.1 locked the exotic semantics and added `Array.isArray` to fix realm issues. Engines now optimize dense arrays as contiguous backing stores; holes/sparse switch to dictionary mode (deopt — see [1.2 performance] and §2.1).

### 3) **`Array.isArray` is the only reliable test**

```js
// typeof lies, instanceof breaks across realms
console.log(typeof [1, 2]); // 'object' — useless
console.log([1, 2] instanceof Array); // true in same realm, false across iframe/vm realm (different Array copy)

// The reliable test — works across realms, returns false for array-likes
console.log(Array.isArray([1, 2])); // true
console.log(Array.isArray({ 0: "a", length: 1 })); // false — array-like, not array
console.log(Array.isArray(new Uint8Array([1]))); // false — typed array is not Array
console.log(Array.isArray(Array.prototype)); // true — spec says Array.prototype is an array exotic

// Cross-realm demo via vm (node) — shows instanceof failure
const vm = require("node:vm");
const otherArray = vm.runInNewContext("[1,2,3]");
console.log(otherArray instanceof Array); // false — different realm's Array
console.log(Array.isArray(otherArray)); // true — brand check, not prototype walk
console.log(Object.prototype.toString.call(otherArray)); // [object Array] — legacy brand

// Array.isArray is intentionally not on TypedArray — use ArrayBuffer.isView
console.log(ArrayBuffer.isView(new Uint8Array([1]))); // true
console.log(Array.isArray(globalThis.document?.all)); // safe — Array.isArray never throws; globalThis.document is undefined in Node, optional chaining safe
```

- *Bad practice* — `if (x instanceof Array)` in library code that may receive cross-frame messages or `vm` sandboxed values → false negative. *Why it hurts* — silently takes the non-array branch, corrupts data pipeline. *Instead* — `Array.isArray(x)` everywhere; lint with `unicorn/prefer-array-is-array` if available.

### 4) **Common confusion**

- "`length` counts elements" — no, `length` is `highestIndex + 1`, not count of present values. `[1,,3].length === 3` but only 2 elements exist. Use `arr.filter(() => true).length` or manual hasOwn count if you need "number of present slots".
- "`delete arr[1]` shortens the array" — no, `delete` creates a hole and leaves `length` unchanged. Use `splice` or `length=` to actually shorten.
- "Arrays are a separate type" — no, `typeof [] === "object"` and `Array` values are objects; the exotic is a behavioral subtype, not a fourth type family (see [Values 1.1](<../../../03 Values Types and Coercion/sections/1. The value model/1.1. Eight types two families primitives vs objects.md>)).
- "`Array.isArray` checks prototype" — no, it checks internal `[[Class]]`/`isArray` brand, not prototype walk (which is why cross-realm works unlike `instanceof` — see [Prototypes 5.1](<../../../07 Prototypes and Classes/sections/5. Type checks and reflection/5.1. instanceof isPrototypeOf Symbol.hasInstance and cross-realm failures.md>)).

### 5) **Performance note**

Dense arrays (contiguous indices `0..length-1` without holes) get a packed backing store in V8/SpiderMonkey/JavaScriptCore — indexed access is bounds-checked pointer arithmetic. Sparse/holey arrays switch to dictionary/hash mode: lookups hash, iteration must check `hasOwn` per index, and `sort`/`map` pay per-hole branches. Measure: creating a 1e6 dense array and summing is ~10× faster than the same with every second slot a hole (verify with `node --allow-natives-syntax` + `%HasDictionaryElements` if available). Guidance: initialize with `Array(n).fill` or `Array.from({length:n})` and avoid mid-array holes in hot paths; if sparsity is inherent (index = id), use `Map` instead (→ [Collections domain](../../../09 Collections Map Set and Weak References/README.md) when it lands).
