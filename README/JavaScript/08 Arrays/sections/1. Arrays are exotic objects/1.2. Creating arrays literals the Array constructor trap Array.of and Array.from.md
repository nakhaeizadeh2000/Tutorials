## 1.2. Creating arrays: literals, the Array constructor trap, Array.of and Array.from

### 1) **Literals are the default; `new Array(n)` is the trap**

**Definition** — a literal `[1,2,3]` always creates indexed properties `0,1,2` and `length=3`. The `Array` constructor is overloaded: `new Array(3)` means "length 3 with holes", `new Array(1,2,3)` means `[1,2,3]`. One numeric argument → sparse; ≥2 args or non-number → elements.

**What problem it solves / history** — `Array` was added in ES1 as a function, before literals dominated. The single-arg form exists to pre-size arrays in an era before `length` growth was obvious. It survives for backward compatibility and is the #1 array bug factory.

```js
// Literals — always what you mean
console.log([3]); // [ 3 ] — one element
console.log([3].length); // 1
console.log(Object.hasOwn([3], "0")); // true

// Constructor — variadic trap
console.log(new Array(3)); // [ <3 empty items> ] — holes, not [3]
console.log(new Array(3).length); // 3
console.log(Object.hasOwn(new Array(3), "0")); // false — no element
console.log(new Array(1, 2, 3)); // [ 1, 2, 3 ] — ≥2 args → elements
console.log(new Array("3")); // [ '3' ] — non-number single arg → element
console.log(Array(3)); // same trap without new — Array is not class-required (unlike class constructors)

// Good vs bad
const bad = new Array(5); // sparse with 5 holes — map will skip them (see §5.1)
console.log(bad.map(x => x * 2)); // [ <5 empty items> ] — callback never ran!

const good = Array.from({ length: 5 }, (_, i) => i * 2); // dense [0,2,4,6,8]
console.log(good);
// Or fill pattern for pre-size
const filled = new Array(3).fill(0); // now dense [0,0,0]
console.log(filled, Object.hasOwn(filled, "0")); // [0,0,0] true
console.log(Array(3).fill(null).map((_, i) => i)); // [0,1,2] — fill before map

// Array() without args — empty, not [undefined]
console.log(Array().length, Array(0).length); // 0 0
console.log([undefined].length, [undefined][0]); // 1 undefined — literal with explicit undefined is dense
```

- *Modern guidance* — never use `new Array(n)` to mean "array with one number". Lint with `no-array-constructor` (ESLint). Prefer literals; use `Array(n).fill` + `map` or `Array.from` when you need a pre-sized dense array. Teach `new Array(n)` only as "how to create holes intentionally" — and then don't.

### 2) **`Array.of` fixes the constructor variadic bug**

`Array.of(...items)` (ES2015) always treats every argument as an element — no special single-number case. It's the safe variadic constructor.

```js
console.log(Array.of(3)); // [ 3 ] — fixed!
console.log(Array.of(1, 2, 3)); // [ 1, 2, 3 ]
console.log(Array.of()); // []
console.log(Array.of(undefined)); // [ undefined ] — one element, not holes

// Implementing Array.of mentally — trivial
function of(...items) { return items; }
console.log(of(3)); // [ 3 ]

// Rarely, people use Array.of to subclass correctly (species)
// Array.of respects the this-constructor (like Array.from)
class MyArray extends Array {}
console.log(MyArray.of(1, 2, 3) instanceof MyArray); // true — species-aware
```

- *When to use* — factory functions that forward `...args` to an array: `function f(...args) { return Array.of(...args); }` is redundant; just `return [...args]`. `Array.of` shines in generic code where `this` is an array subclass.

### 3) **`Array.from` builds from any iterable or array-like**

`Array.from(source, mapFn?, thisArg?)` (ES2015) creates a dense array from:
- any *iterable* (Array, Set, Map, string, generator, TypedArray), or
- any *array-like* (`{ 0:"a", 1:"b", length:2 }`, `arguments`, `NodeList`).

Steps: reads `length` (for array-likes) or iterates (for iterables), maps with `mapFn` if supplied, and *always* produces a dense result (holes become `undefined` only if the source had actual `undefined` values; holes in sparse source become `undefined` in result — densified).

```js
// From iterable
console.log(Array.from("abc")); // [ 'a', 'b', 'c' ]
console.log(Array.from(new Set([1, 2, 2, 3]))); // [ 1, 2, 3 ]
console.log(Array.from([1, , 3])); // [ 1, undefined, 3 ] — hole densified to undefined!

// From array-like (the arguments / DOM case)
function toArray() {
  console.log(Array.from(arguments)); // true array, not exotic arguments
  console.log([...arguments]); // also works if iterable (arguments is iterable since ES2015)
}
toArray(1, 2, 3);

const arrayLike = { 0: "a", 1: "b", length: 2 };
console.log(Array.from(arrayLike)); // [ 'a', 'b' ]
console.log(Array.from({ length: 3 })); // [ undefined, undefined, undefined ] — dense undefineds, not holes

// Mapping in one pass (no intermediate array)
console.log(Array.from({ length: 5 }, (_, i) => i * i)); // [ 0, 1, 4, 9, 16 ]
console.log(Array.from([1, 2, 3], x => x * 2)); // [ 2, 4, 6 ]
console.log(Array.from([1, 2, 3], function (x) { return x + this.offset; }, { offset: 10 })); // [11,12,13] — thisArg

// Shallow copy idiom — dense copy
const orig = [1, 2, 3];
console.log(Array.from(orig) !== orig && Array.from(orig).join() === orig.join()); // true true
console.log([...orig]); // spread also shallow-copies iterables, but Array.from also handles array-likes

// Gotcha: Array.from on sparse preserves length but densifies
const sparse = [1, , 3, , 5]; // holes at 1,3
const dense = Array.from(sparse);
console.log(dense); // [ 1, undefined, 3, undefined, 5 ]
console.log(Object.hasOwn(dense, "1"), Object.hasOwn(sparse, "1")); // true false — densified
console.log(dense.map(x => x ?? -1)); // [1,-1,3,-1,5] — now mappable

// Species: subclass preservation
class MyArr extends Array {}
const m = MyArr.from([1, 2, 3], x => x * 2);
console.log(m instanceof MyArr, m); // true MyArr(3) [ 2, 4, 6 ]
```

- *Bad vs good* — `Array.from` vs spread: spread `[...iterable]` only works for iterables, not for plain array-likes without `Symbol.iterator`. `Array.from({0:"a", length:1})` works; `[...{0:"a", length:1}]` throws `TypeError: not iterable`. Use `Array.from` when the source might be array-like.

### 4) **Common confusion**

- "`new Array(3)` gives `[undefined, undefined, undefined]`" — no, it gives 3 holes (no properties). `hasOwn` is false, `map` skips, `join` treats holes as `""`. Use `Array.from({length:3})` for 3 `undefined`s or `Array(3).fill(0)` for 3 zeros.
- "`Array.from` preserves holes" — no, it densifies (hole → `undefined`). `slice` and `toSpliced` preserve holes; `Array.from`/`...spread` densify (see §2.1 for full table).
- "`Array.of` is just `[].of`" — `Array.of` is static; think of it as `function of(...xs){ return xs; }` with species support.

### 5) **Performance note**

Literal and `Array.from({length:n}, fn)` keep dense packed backing stores. `new Array(n)` creates a holey/dictionary mode backing store in V8; subsequent `fill` densifies but costs a second pass. For `n < 1e5` the difference is negligible; for hot allocation of millions of small arrays, `Array.from` + mapper avoids the intermediate holey state. When copying large arrays, `Array.from` and `[...arr]` are branch-predicted dense loops — identical speed; `arr.slice()` is the classic dense copy and often inlined fastest.

### 6) **Mentor note**

Give juniors the one-line quiz: "What does `new Array(3).map(() => 1)` return?" (holes → never calls → still holes). Then show `Array.from({length: 3}, () => 1)` → `[1,1,1]`. In review, flag every `new Array(` with a single numeric arg — replace with `Array.from` or `.fill`.
