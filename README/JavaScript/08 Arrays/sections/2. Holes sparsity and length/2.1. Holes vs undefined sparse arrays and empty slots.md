## 2.1. Holes vs undefined: sparse arrays and empty slots

### 1) **Hole means no property; `undefined` means a property whose value is `undefined`**

**Definition** — a hole (empty slot) is an indexed position `i < length` where no property `"i"` exists. `arr[i] === undefined` is true for both holes and explicit `undefined` values — only `Object.hasOwn(arr, i)` / `i in arr` distinguishes them. The literal `[1, , 3]` has length 3 but no `"1"` key.

**What problem it solves / history** — holes arise from `new Array(n)`, `delete arr[i]`, `arr.length = larger`, and elided commas in literals (the oldest sparse pattern). They model "no value" vs "value is undefined" — e.g., sparse matrices, pre-sized buffers. The distinction matters because ES5–ES6 iteration methods were defined to *skip* holes, not treat them as `undefined`.

```js
const a = [1, , 3]; // elided comma → hole at 1
console.log(a.length); // 3
console.log(a[1]); // undefined — same as missing property
console.log(Object.hasOwn(a, "1")); // false — no property
console.log("1" in a); // false
console.log(Object.hasOwn(a, "0"), Object.hasOwn(a, "2")); // true true

const b = [1, undefined, 3]; // explicit undefined — dense
console.log(b[1]); // undefined — same read
console.log(Object.hasOwn(b, "1")); // true — property exists
console.log("1" in b); // true

// delete creates a hole without changing length
const c = [1, 2, 3];
delete c[1];
console.log(c); // [ 1, <1 empty item>, 3 ]
console.log(c.length); // 3 — unchanged
console.log(Object.hasOwn(c, "1")); // false

// Array(n) is n holes
const holes = new Array(3);
console.log(holes.length, Object.hasOwn(holes, "0"), holes[0]); // 3 false undefined

// Dense undefineds
const dense = Array.from({ length: 3 }); // [undefined, undefined, undefined] — dense
console.log(Object.hasOwn(dense, "0"), dense[0]); // true undefined
```

### 2) **Sparse arrays are objects with missing indices — holes included**

An array is dense iff every `i < length` has an own property; sparse otherwise. Engines store dense packed arrays and holey/dictionary arrays differently, but semantically holes are just missing keys.

```js
// Object.keys / entries skip holes; length does not
const sparse = [1, , 3, , 5];
console.log(Object.keys(sparse)); // [ '0', '2', '4' ] — holes omitted
console.log(Object.entries(sparse)); // [ ['0',1], ['2',3], ['4',5] ]
console.log(sparse.length); // 5 — includes holes in count

// Reflect.ownKeys includes holes? No — ownKeys lists keys that exist, so holes absent
console.log(Reflect.ownKeys(sparse)); // [ '0', '2', '4', 'length' ]

// Counting present elements vs length
function presentCount(arr) {
  let n = 0;
  for (let i = 0; i < arr.length; i++) if (Object.hasOwn(arr, i)) n++;
  return n;
}
console.log(presentCount(sparse), sparse.length); // 3 5

// JSON skips holes as null? Actually JSON.stringify treats holes as null
console.log(JSON.stringify([1, , 3])); // [1,null,3] — hole densified to null for JSON
console.log(JSON.stringify([1, undefined, 3])); // [1,null,3] — same wire shape! Distinction lost over JSON
```

### 3) **Modern syntax treats holes differently — the table you must memorize**

| Operation | Hole behavior |
|-----------|---------------|
| `for (let i=0; i<l; i++) arr[i]` | reads `undefined` (both holes and `undefined` values) — no skip |
| `for-of` / `Array.prototype.values` | **densifies** — visits every index `0..length-1`, holes yield `undefined` |
| `forEach`, `map`, `filter`, `every`, `some`, `flat`, `flatMap` | **skip** holes — callback not called; `map` preserves holes, `filter`/`flat` produce dense |
| `find`, `findIndex`, `findLast`, `findLastIndex`, `includes` | **densify** — visit holes as `undefined` (includes finds `undefined` in holes; indexOf does not — see §4.1) |
| `...spread`, `Array.from`, `for-of`, `toReversed`, `toSorted`, `toSpliced`, `with` | **densify** holes → `undefined` (copy fills holes with `undefined`) |
| `slice`, `concat`, `map` | **preserve** holes — copy keeps empty slots as holes |
| `join`, `toString` | hole → `""` (empty string) between commas: `[1,,3].join("-")` → `"1--3"` |
| `Object.keys/entries`, `for-in` | skip holes (only existing keys enumerated) |
| `in` / `hasOwn` | hole → `false`; `undefined` value → `true` |

```js
const s = [1, , 3, , 5];

// for vs for-of: for reads holes as undefined via Get; for-of densifies via iterator
for (let i = 0; i < s.length; i++) console.log(i, s[i], Object.hasOwn(s, i)); // 0 true, 1 false, 2 true...
console.log([...s]); // [1, undefined, 3, undefined, 5] — spread densifies
console.log(Array.from(s)); // [1, undefined, 3, undefined, 5] — densifies
console.log(s.slice()); // [1, <1 empty>, 3, <1 empty>, 5] — preserves holes!
console.log(Object.hasOwn(s.slice(), "1")); // false — hole preserved

// forEach / map skip holes; map preserves holes in result
let calls = 0;
s.forEach(() => calls++);
console.log(calls); // 3 — holes skipped (present count)
console.log(s.map(x => x * 2)); // [2, <1 empty>, 6, <1 empty>, 10] — holes preserved, callback not called for holes
console.log(s.filter(x => x > 0)); // [1,3,5] — holes skipped, result dense

// find/findIndex/includes visit holes as undefined (see §4.1)
console.log([1, , 3].includes(undefined)); // true — hole counts as undefined for includes
console.log([1, , 3].indexOf(undefined)); // -1 — but indexOf skips holes (Uses Strict Equality on present only)
console.log([1, , 3].find(x => x === undefined)); // undefined — hole visited as undefined
console.log([1, , 3].findIndex(x => x === undefined)); // 1 — hole index
console.log([1, , 3].find(() => true)); // 1 — first element; hole not skipped for find
let findCalls = 0; [1, , 3].find(() => { findCalls++; return false; });
console.log(findCalls); // 3 — visited all including hole

// flat skips holes
console.log([1, , [2, , 3]].flat()); // [1, 2, 3] — holes removed

// join treats hole as ""
console.log([1, , 3].join("-")); // 1--3
console.log([1, undefined, 3].join("-")); // 1--3 — same visual! hole vs undefined indistinguishable in join

// for-of iterator densifies
for (const v of s) console.log(v); // 1, undefined, 3, undefined, 5 — iterator visits holes as undefined

// Deleting vs splicing
const d = [1, 2, 3];
delete d[1];
console.log(d, Object.hasOwn(d, "1")); // [1, empty, 3] false — delete = hole, length unchanged
d.splice(1, 1); // splice compacts
console.log(d, d.length); // [1, 3] 2 — splice removes hole and shifts
```

- *Modern guidance* — prefer dense arrays. Create dense with `Array.from({length:n}, fn)` or `fill`. When you receive possibly-sparse data (external API stitched pages), normalize via `Array.from(arr)` or `arr.filter(() => true)`? Actually `filter` skips holes and densifies anyway. Be explicit: `Array.from(sparse, x => x ?? defaultVal)` densifies and fills.

### 4) **Common confusion**

- "`[1,,3].length === 2`" — no, length is `2`? Actually `[1,,3]` → `0:1, 2:3, length 3` — the highest index +1. Count holes by `Object.keys(arr).length` if you need present count.
- "`map` will fill holes with `undefined`" — no, `map` preserves holes (result holey). `Array.from` and spread densify to `undefined`. This split causes the classic `new Array(3).map(() => 1)` still-holey bug (see [1.2](../1. Arrays are exotic objects/1.2. Creating arrays literals the Array constructor trap Array.of and Array.from.md)).
- "`for-in` on arrays lists holes" — no, `for-in` enumerates existing keys only, so it skips holes but also walks prototype and non-index keys — never use `for-in` for array data (use `for-of`).

### 5) **Performance note**

V8 tracks an array's `elementsKind`: `PACKED_SMI`, `PACKED_DOUBLE`, `PACKED`, `HOLEY_SMI`, `HOLEY_DOUBLE`, `HOLEY`, `DICTIONARY`. Transitioning from `PACKED` → `HOLEY` (by creating a hole) is one-way and permanent — the backing store switches to a slower hole-checking loop for every index op. A hot array that becomes holey in a loop pays per-iteration hasOwn checks. If you must delete, use `splice` to keep packed; if you must pre-size, `Array.from({length:n}, ...)` stays `PACKED` from birth.

### 6) **Mentor note**

Demo: `const a = new Array(3); console.log(0 in a, a.map(() => 1))` — two surprises. Then `Array.from(a, () => 1)` fix. In review, ask "where do holes come from here?" for any `delete arr[i]` or `arr.length = big`. Flag `for-in` on arrays as bug.
