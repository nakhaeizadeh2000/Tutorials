## 4.2. Async generators async yield and composition

### 1) **`async function*` returns an AsyncGenerator (async iterator + async iterable)**

**Definition** — `async function*` defines an AsyncGeneratorFunction; calling it returns an AsyncGenerator that is both an async iterator (`next()` → `Promise<{value,done}>`) and an async iterable (`[Symbol.asyncIterator](){return this}`). Inside you can `await` promises and `yield` values (which may be promises or plain values — both are wrapped). The consumer `await`s each `next()` or uses `for await...of`.

```js
// Basic async generator — await inside, yield out
async function* countTo3(delay=5){
  console.log("start");
  await new Promise(r=> setTimeout(r, delay));
  yield 1;
  console.log("after 1");
  await new Promise(r=> setTimeout(r, delay));
  yield 2;
  console.log("after 2");
  yield 3;
  console.log("end");
  return "done";
}
console.log(typeof countTo3); // 'function'
console.log(countTo3.constructor.name); // 'AsyncGeneratorFunction'

(async () => {
  const g = countTo3(1);
  console.log(typeof g.next, typeof g[Symbol.asyncIterator]); // 'function' 'function'
  console.log(g[Symbol.asyncIterator]() === g); // true
  console.log(await g.next()); // logs start, {value:1,done:false}
  console.log(await g.next()); // logs after 1, {value:2,done:false}
  console.log(await g.next()); // {value:3,done:false}
  console.log(await g.next()); // logs end, {value:"done",done:true}
  console.log(await g.next()); // {value:undefined,done:true}
})();

// Yielding promises — for await awaits their resolution order, but next() yields promise value
async function* yieldPromises(){
  yield Promise.resolve(10); // yielded value is 10, not the promise, after await by consumer
  yield await Promise.resolve(20); // same
}
(async () => {
  for await (const v of yieldPromises()) console.log("yielded", v); // 10 20
  // Manual next shows same
  const g2 = yieldPromises();
  console.log(await g2.next()); // {value:10,done:false}
})();

// Async generator method syntax
const obj = {
  async *gen(){ yield await Promise.resolve("a"); yield "b"; }
};
(async () => { for await (const v of obj.gen()) console.log("obj",v); })();

// Class
class Stream{
  async *items(){ for(const v of [1,2,3]) yield await Promise.resolve(v); }
}
(async () => { for await (const v of new Stream().items()) console.log("class",v); })();
```

### 2) **`yield*` and `await` composition across async/sync boundaries**

**Definition** — inside `async function*`, `yield* iterable` delegates: if `iterable` is async iterable, it awaits each step; if it's sync iterable, it wraps each `next()` result with `Promise.resolve` and yields values. You can delegate to both `async` and sync iterables and capture the inner done value, forwarding `return()`/`throw()`.

```js
// Delegating to async and sync
async function* innerAsync(){ yield await Promise.resolve(1); yield 2; return "inner done"; }
function* innerSync(){ yield 10; yield 20; }
async function* outer(){
  const r1 = yield* innerAsync(); // awaits async steps
  console.log("innerAsync returned", r1); // "inner done"
  const r2 = yield* innerSync(); // also works inside async generator
  console.log("innerSync returned", r2); // undefined
  yield 30;
}

(async () => {
  console.log(await outer()[Symbol.asyncIterator]().next()); // but simpler for await
  for await (const v of outer()) console.log("outer", v); // 1 2 10 20 30
})();

// yield* propagates close — async finally
async function* innerClose(){
  try{ yield 1; yield 2; yield 3; }
  finally{ console.log("inner async finally"); }
}
async function* outerClose(){ try{ yield* innerClose(); } finally{ console.log("outer async finally"); } }

(async () => {
  const g = outerClose();
  console.log(await g.next()); // 1
  console.log(await g.return("stop")); // inner async finally, outer async finally, {value:"stop",done:true}
})();

(async () => {
  for await (const v of outerClose()){ console.log("loop",v); break; } // loop 1 + finallys
})();

// Await composition — paginated fetch pattern (async queue)
async function fetchPage(n){ // simulated
  await new Promise(r=> setTimeout(r, 2));
  return n<3 ? { items: [n*10, n*10+1], next: n+1 } : { items: [30], next: null };
}
async function* paginated(){
  let n=1;
  while(true){
    const page = await fetchPage(n);
    for(const item of page.items) yield item;
    if(page.next==null) return;
    n = page.next;
  }
}
(async () => { console.log(await (async()=>{ const out=[]; for await(const v of paginated()) out.push(v); return out; })()); })(); // [10,11,20,21,30]

// Mixing await and yield* — inner may also await
async function* withAwaitAndYield(){
  await new Promise(r=> setTimeout(r, 2));
  yield* [1,2,3]; // sync iterable inside async generator — also valid
}
(async () => { for await (const v of withAwaitAndYield()) console.log("mixed",v); })(); // 1 2 3
```

### 3) **Patterns — async queue/stream, paginated fetch, and cancellation via `return()`**

**Definition** — async generators model pull-based streams with backpressure: consumer `next()` pulls, producer `await`s. Patterns include async queue (push via `next()`-like API), paginated fetch with early `break`, and cancellation via `return()` → `finally`. Bridge with `AbortSignal` for external abort.

```js
// Async queue — push vs pull bridge
function createQueue(){
  const queue=[]; let resolveNext=null;
  return {
    push(v){
      if(resolveNext){ const r=resolveNext; resolveNext=null; r({value:v,done:false}); }
      else queue.push(v);
    },
    close(){ if(resolveNext) resolveNext({value:undefined,done:true}); },
    [Symbol.asyncIterator](){
      return {
        next(){
          if(queue.length) return Promise.resolve({value:queue.shift(),done:false});
          return new Promise(r=> { resolveNext=r; });
        },
        [Symbol.asyncIterator](){ return this; }
      };
    }
  };
}
(async () => {
  const q = createQueue();
  setTimeout(()=>{ q.push("a"); q.push("b"); q.close(); }, 10);
  for await (const v of q) console.log("queue",v); // a b then done
})();

// Paginated fetch with early break — finally releases
async function* fetchStream(pages){
  console.log("open stream");
  try{
    for(const page of pages){
      await new Promise(r=> setTimeout(r, 2));
      for(const item of page) yield item;
    }
  } finally{ console.log("close stream"); }
}
(async () => {
  for await (const v of fetchStream([[1,2],[3,4],[5,6]])){
    console.log("fetch",v);
    if(v===3) break; // close stream via return()
  }
  console.log("after break");
})(); // open, fetch 1 2 3, close, after break

// Cancellation via return() — manual
async function* longStream(){
  try{ for(let i=0;i<5;i++){ await new Promise(r=>setTimeout(r,2)); yield i; } }
  finally{ console.log("longStream cleanup"); }
}
(async () => {
  const g = longStream();
  console.log(await g.next()); // 0
  console.log(await g.next()); // 1
  console.log(await g.return("cancelled")); // cleanup, {value:"cancelled",done:true}
})();

// AbortSignal bridge — external cancel
async function* withSignal(signal, src){
  try{
    for await (const v of src){
      if(signal.aborted) { console.log("aborted"); return; }
      yield v;
    }
  } finally{ console.log("signal finally"); }
}
(async () => {
  const ac = new AbortController();
  const src = async function*(){ yield 1; yield 2; yield 3; }();
  setTimeout(()=> ac.abort(), 5);
  for await (const v of withSignal(ac.signal, src)) console.log("signal v",v);
})();

// Anti-pattern — using yield without await for promises that must be awaited before yield? Both work, but `yield await p` makes ordering explicit
```

### 4) **Common confusion**

- "`async function*` vs `async function` returning iterable" — `async function` returns `Promise`; `async function*` returns `AsyncGenerator` with `next()` returning `Promise<{value,done}>`. Use `for await` on the latter.
- "`yield` awaits promises" — no, `yield` just yields the value (even if it's a `Promise` object); `for await` awaits the iterator result. To await inside the generator, use `yield await p`.
- "`yield*` on sync iterable inside async generator fails" — no, it works — sync `next()` is wrapped via `Promise.resolve`.
- "Async generators are push-based" — no, they're pull-based (consumer demands next value; producer resumes). For push with buffering, use the queue pattern.

### 5) **Performance note**

Async generators add a promise per `next()` + microtask per `await`/`yield`. For hot numeric loops without IO, they are ~10× slower than sync generators or arrays. Use them only when the source is genuinely asynchronous (IO, timers, streams). Paginated fetch that `await`s per page but yields per item sequentially is correct and IO-dominated — not a perf concern. Don't use `for await...of` to iterate a plain sync array expecting parallelism — it's serial.

### 6) **Mentor note**

Have juniors trace `async function*` vs `function*` with `await` inside: ask whether `yield Promise.resolve(10)` vs `yield await Promise.resolve(10)` differ for `for await` (they don't — `for await` awaits both, but manual `await g.next()` shows promise vs value). Demo `break` over `async function*` with `finally` to teach async closing. In review, flag any `async function` that was intended as `async function*` (missing `*` means not iterable) and any `for-of` over an async generator (should be `for await`).
