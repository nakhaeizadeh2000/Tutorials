## 4.1. Async iterables Symbol.asyncIterator and for await...of

### 1) **`[Symbol.asyncIterator]` returns a promise-of-`{value,done}` async iterator**

**Definition** — an *async iterable* has `[Symbol.asyncIterator]() → asyncIterator`; the async iterator has `next() → Promise<{value,done}>` (optionally `return()`/`throw()` returning promises). An object may be both sync (`Symbol.iterator`) and async iterable — `for await...of` probes async first, then sync. `Symbol.asyncIterator` is a well-known symbol like `Symbol.iterator`.

**What problem it solves / history** — sync iteration cannot represent streams where each value arrives asynchronously (network chunks, DB cursor next, `ReadableStream`). ES2018 added async iteration so `for await (const chunk of stream)` works with backpressure and async cleanup.

```js
// Minimal async iterable — delays each value
const asyncCounter = {
  [Symbol.asyncIterator](){
    let i=0;
    return {
      next(){
        if(i<3) return Promise.resolve({ value: i++, done: false });
        return Promise.resolve({ value: undefined, done: true });
      },
      return(v){
        console.log("async return");
        return Promise.resolve({ value: v, done: true });
      },
      [Symbol.asyncIterator](){ return this; }
    };
  }
};
// Manual drive via next() — inside async context
(async () => {
  const ait = asyncCounter[Symbol.asyncIterator]();
  console.log(await ait.next()); // {value:0,done:false}
  console.log(await ait.next()); // {value:1,done:false}

  // Dual iterable — both sync and async
  const dual = {
    [Symbol.iterator](){ let i=0; return { next(){return i<2?{value:i++,done:false}:{value:undefined,done:true}}, [Symbol.iterator](){return this}}; },
    [Symbol.asyncIterator](){ let i=0; return { next(){return Promise.resolve(i<2?{value:100 + i++,done:false}:{value:undefined,done:true})}, [Symbol.asyncIterator](){return this}}; }
  };
  console.log([...dual]); // [0,1] — sync
  for await (const v of dual) console.log("async dual",v); // 100 101 — async preferred
  console.log("done dual");
})();

// Detecting async iterable (sync — runnable anywhere)
function isAsyncIterable(x){ return x!=null && typeof x[Symbol.asyncIterator]==="function"; }
function isSyncIterable(x){ return x!=null && typeof x[Symbol.iterator]==="function"; }
console.log(isAsyncIterable(asyncCounter)); // true
console.log(isAsyncIterable([1,2])); // false
console.log(isSyncIterable(asyncCounter)); // false — only async
console.log(isAsyncIterable(asyncCounter), isSyncIterable(asyncCounter));

// Dual iterable sync log already above; pageGen helper
async function *pageGen(pages){ for(const p of pages) yield await Promise.resolve(p); }
```

### 2) **`for await...of` works on both sync and async iterables — awaiting each step**

**Definition** — `for await (const v of iterable)` gets an iterator: prefers `Symbol.asyncIterator`, falls back to `Symbol.iterator` (sync values are wrapped with `Promise.resolve` and awaited — so it works on arrays). Each iteration does `await step = await iter.next()`, then `await step.value`? Actually `for await` awaits the iterator result and the value if needed for proper ordering. Loop body runs after each `await`. Closing (`break`/`throw`/`return`) awaits `iter.return()` if present.

```js
// for await on async iterable
async function demoAsyncFor(){
  const src = {
    [Symbol.asyncIterator](){
      let i=0;
      return {
        next(){ return new Promise(res=> setTimeout(()=> res(i<3?{value:i++,done:false}:{value:undefined,done:true}), 5)); },
        [Symbol.asyncIterator](){ return this; }
      };
    }
  };
  for await (const v of src) console.log("async v", v); // 0 1 2 — each delayed
}

// for await on SYNC iterable — also works (await wraps)
async function demoSyncWithAwait(){
  for await (const v of [10,20,30]) console.log("sync via for-await", v); // 10 20 30 — each await Promise.resolve
  for await (const v of "hi👋") console.log("string via for-await", v); // h i 👋
}

// Cannot use plain for-of on async iterator — next returns promise, not {value,done}
{
  const ait2 = asyncCounter[Symbol.asyncIterator]();
  // for (const v of ait2) ... // TypeError or wrong — ait2 is not sync iterable
  // for await must be inside async function (CJS needs async IIFE; modules allow top-level await)
}

// Bridging Array.from / spread — NOT async aware: spread/for-of use sync protocol only; for async must iterate
// [...asyncCounter] // TypeError: asyncCounter is not iterable
// Array.from(asyncCounter) // [] — not async iterable
// To collect async iterables: use for await loop
async function toArrayAsync(asyncIterable){
  const out=[];
  for await (const v of asyncIterable) out.push(v);
  return out;
}

(async () => {
  await demoAsyncFor();
  await demoSyncWithAwait();
  console.log(await toArrayAsync(asyncCounter)); // [0,1,2]
})();

// Promise per element is sequential — not parallel (see performance)
```

### 3) **Closing semantics and error propagation for async iteration**

**Definition** — `for await...of` uses `AsyncIteratorClose` (mirrors IteratorClose but awaited): on `break`/`throw`/`return` before done, it awaits `iter.return()` if present (or `iter.return` from sync fallback wrapped). Rejections from `next()` or `return()` propagate as throws caught by `try/catch`. `try/finally` inside async generators runs on close (awaits finally).

```js
async function* asyncCursor(rows){
  console.log("open async cursor");
  try{ for(const r of rows) yield await Promise.resolve(r); }
  finally{ console.log("close async cursor"); }
}

// break triggers async return() → finally
async function demoClose(){
  for await (const row of asyncCursor(["a","b","c"])){
    console.log("process", row);
    if(row==="b") break; // await return() → finally
  }
  console.log("after break");
}

// throw triggers close then propagates
async function demoThrow(){
  try{
    for await (const v of asyncCursor([1,2,3])){
      console.log(v);
      throw new Error("abort");
    }
  } catch(e){ console.log("caught", e.message); }
}

// Manual async return() with promise
const manualAsync = {
  [Symbol.asyncIterator](){
    let i=0;
    return {
      next(){
        if(i<3) return Promise.resolve({value:i++,done:false});
        return Promise.resolve({value:undefined,done:true});
      },
      return(v){
        console.log("manual async return");
        return new Promise(res=> setTimeout(()=> res({value:v,done:true}), 5));
      },
      [Symbol.asyncIterator](){ return this; }
    };
  }
};
async function demoManual(){
  for await (const v of manualAsync){ console.log(v); break; }
}

// Return that throws/rejects — error replaces original completion
const badAsyncReturn = {
  [Symbol.asyncIterator](){
    return {
      next(){ return Promise.resolve({value:1,done:false}); },
      return(){ return Promise.reject(new Error("return failed")); },
      [Symbol.asyncIterator](){ return this; }
    };
  }
};
async function demoBad(){
  try{ for await (const v of badAsyncReturn){ console.log(v); break; } }
  catch(e){ console.log("return threw", e.message); }
}

(async () => {
  await demoClose(); // open, process a, process b, close, after break
  await demoThrow(); // close still runs before catch
  await demoManual(); // v 0, manual async return
  await demoBad();
})();
// In CJS files `for await` must be inside an async function (async IIFE); modules allow top-level await
```

### 4) **Common confusion**

- "`for-of` works on async iterables" — no. Use `for await...of`; `for-of` sees `Symbol.asyncIterator` but not `Symbol.iterator` and throws `TypeError`.
- "`for await...of` only works on async iterables" — no, it also works on sync iterables (arrays, strings, Maps, sync generators) — sync `next()` result is awaited.
- "`for await...of` runs in parallel" — no, it awaits each `next()` sequentially (backpressure). For parallel, collect promises first (`Promise.all`).
- "`AsyncIteratorClose` is sync" — no, it awaits `return()` — cleanup may be async; don't treat `break` as instant.

### 5) **Performance note**

`for await...of` awaits one promise per element → serial. If each element's `next()` does no real IO (already resolved promise), the per-tick `await` still enqueues a microtask (see [Functions Deep Dive async when it lands] / Event Loop preview) — 1M iterations is cadence-limited vs sync loop (~hundreds of µs extra). For true async sources (stream chunks), the IO dominates; for sync sources use `for-of`. Collecting an async iterator into an array via `for await` is O(n) serial — for fetch-`k` pages in parallel, use `Promise.all` not iteration.
