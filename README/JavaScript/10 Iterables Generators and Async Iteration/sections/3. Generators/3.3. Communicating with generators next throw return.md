## 3.3. Communicating with generators next throw return

### 1) **`gen.next(v)` sends `v` as the value of the paused `yield`**

**Definition** — `yield expr` evaluates to the argument of the next `next(v)` call that resumes the generator. The generator's caller drives the paused `yield` result. First `next()` argument is ignored (no prior `yield` to receive it) — pass initial state via generator params instead.

```js
// Two-way channel — yield yields out, next injects in
function* ask(){
  const name = yield "what is your name?"; // yielded to caller, next(arg) becomes value
  console.log("received name", name);
  const age = yield `hello ${name}, age?`;
  console.log("received age", age);
  return `${name} is ${age}`;
}
const g = ask();
console.log(g.next()); // {value:'what is your name?',done:false}
console.log(g.next("Alice")); // logs received name Alice, yields "hello Alice, age?"
console.log(g.next(30)); // logs received age 30, {value:'Alice is 30',done:true}

console.log(ask().next("ignored")); // {value:'what is your name?',done:false} — ignored, no yield yet

// Pattern — pass initial state via params, not first next(arg)
function* counter(start=0){
  let i = start;
  while(true){
    const step = yield i; // step from next(step)
    i += step ?? 1; // default 1 if caller sends undefined
  }
}
const c = counter(10);
console.log(c.next()); // {value:10,done:false}
console.log(c.next(5)); // {value:15,done:false}
console.log(c.next()); // {value:16,done:false} — undefined → 1
console.log(c.next(0)); // {value:16,done:false} — step 0 stays

// next() after done stays done, arg ignored
console.log(c.return()); console.log(c.next(999)); // done, ignored
```

### 2) **`gen.throw(err)` injects at the pause point; `gen.return(v)` closes early**

**Definition** — `throw(err)` resumes the generator by throwing `err` at the current `yield` point; if the generator has `try/catch` there it recovers and yields again, otherwise the error propagates and the generator becomes `done`. `return(v)` resumes via `IteratorClose`: runs `finally` blocks, jumps to `done:true` with `value:v` (overriding any pending yield).

```js
// throw() — error injection
function* resilient(){
  try{
    yield 1;
    yield 2; // <- thrown here
  } catch(e){
    console.log("caught", e.message);
    yield 99; // recovery yields
  }
  yield 3;
}
const r = resilient();
console.log(r.next()); // 1
console.log(r.throw(new Error("boom"))); // caught boom → {value:99,done:false}
console.log(r.next()); // 3
console.log(r.next()); // done

// throw without catch — propagates and closes
function* fragile(){ yield 1; yield 2; yield 3; }
const f = fragile();
console.log(f.next()); // 1
try{ console.log(f.throw(new Error("unhandled"))); }catch(e){ console.log("propagated", e.message); }
console.log(f.next()); // {value:undefined,done:true} — closed

// return() — early termination with finally
function* resource(){
  console.log("open");
  try{ yield 1; yield 2; yield 3; }
  finally{ console.log("finally cleanup"); }
}
const res = resource();
console.log(res.next()); // open, 1
console.log(res.return("early")); // finally cleanup, {value:"early",done:true}
console.log(res.next()); // done

// return() inside for-of is implicit via break
for(const v of resource()){
  console.log("loop", v);
  break; // implicit return() → finally
}

// return() value is the done value — not yielded
function* withReturn(){ yield 1; return 100; }
const w = withReturn();
console.log(w.next()); // 1
console.log(w.return(999)); // {value:999,done:true} — 100 discarded, 999 is done value
console.log([...withReturn()]); // [1] — return value never yielded

// Generators as state machines — throw for validation
function* validator(){
  while(true){
    try{
      const v = yield "send number";
      if(typeof v !== "number") throw new Error("not a number");
      yield `got ${v}`;
    } catch(e){
      yield `error: ${e.message}`;
    }
  }
}
const val = validator();
console.log(val.next()); // send number
console.log(val.next("oops")); // error: not a number
console.log(val.next()); // send number (loop)
console.log(val.next(42)); // got 42
```

### 3) **Control-flow patterns — two-way channel, error injection, cooperative cancellation**

**Definition** — use `next()` to push values, `throw()` to push errors, `return()` for cancellation. This makes generators usable as coroutines, parsers, and cooperative task runners before `async/await` existed; today it's mainly for pipelines that need bidirectional communication.

```js
// Two-way parser — consumer pushes tokens, generator yields AST nodes
function* tokenizer(){
  let buffer = "";
  while(true){
    const ch = yield buffer || "ready";
    if(ch === null) return buffer; // signal end
    if(ch === ","){ const out = buffer; buffer=""; yield out; }
    else buffer += ch;
  }
}
const tok = tokenizer();
console.log(tok.next()); // ready
console.log(tok.next("a")); // ready? actually next("a") sends "a" as prev yield result — trace:
const tok2 = tokenizer();
tok2.next(); // prime to first yield
console.log(tok2.next("a").value); // "a"? need correct flow — simpler: show stepwise
function* simpleEcho(){
  let v = yield "start";
  while(v !== null){
    v = yield `echo:${v}`;
  }
  return "end";
}
const se = simpleEcho();
console.log(se.next()); // start
console.log(se.next("hi")); // echo:hi
console.log(se.next("bye")); // echo:bye
console.log(se.next(null)); // end

// Cancellation via return() from consumer
function* longTask(){
  try{ for(let i=0;i<5;i++){ console.log("work",i); yield i; } }
  finally{ console.log("cancel cleanup"); }
}
const task = longTask();
console.log(task.next()); // work 0
console.log(task.next()); // work 1
console.log(task.return("cancelled")); // cancel cleanup, {value:"cancelled",done:true}

// throw for cooperative error — consumer validates, generator recovers
function* pipeline(){
  try{ while(true){ const v = yield; console.log("pipeline processed", v*2); } }
  catch(e){ console.log("pipeline error", e.message); }
}
const p = pipeline();
p.next(); // prime
p.next(10); // processed 20
console.log(p.throw(new Error("invalid input"))); // pipeline error, done

// Anti-pattern — using throw for normal control flow
// Bad: consumer throw to skip elements → confusion vs truly exceptional cases
// Good: use next(arg) with sentinel (null/undefined) or return() for cancellation; reserve throw for real errors
```

### 4) **Common confusion**

- "`next(arg)` on first call sets `yield` value" — no, first `next()` has no suspended `yield` to receive — arg ignored. Pass initial via params: `function* gen(init){ yield init; }` → `gen(10).next()`.
- "`throw()` always crashes the generator" — only if uncaught inside; with `try/catch` at the `yield` point it recovers.
- "`return()` yields its argument" — no, its argument becomes the `done:true` value, not yielded. `for-of`/spread discard it.
- "Generators are two-way async" — only via manual driving; `yield` does not await promises (see [4.2](<../4. Async iteration/4.2. Async generators async yield and composition.md>)). Use `async function*`.

### 5) **Performance note**

Driving a generator via repeated `next(arg)` allocates a result object per step (`{value,done}`). For hot 1M-step numeric transforms, manual function closures or array pipelines are ~4× faster. Use generator communication patterns when you need suspendable control flow or lazy validation, not for raw throughput. Avoid calling `throw()` in hot paths for normal branching — exceptions deoptimize JIT fast paths (throw → deopt).

### 6) **Mentor note**

The off-by-one confuses everyone once. Then show `return()` running `finally` vs manual `next()` leak.
