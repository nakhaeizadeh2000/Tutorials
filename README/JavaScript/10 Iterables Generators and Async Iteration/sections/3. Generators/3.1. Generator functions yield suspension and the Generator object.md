## 3.1. Generator functions yield suspension and the Generator object

### 1) **`function*` creates a GeneratorFunction that returns a Generator (iterator + iterable)**

**Definition** — `function*` (any star position: `function* foo()`, `function *foo()`, `*method()`) defines a GeneratorFunction. Calling it does **not** run the body; it returns a Generator object that is both an iterator (`next`/`return`/`throw`) and an iterable (`[Symbol.iterator](){return this}`). The body runs only when `next()` is called, pausing at each `yield`.

```js
// Declaration — body not yet executed
function* countTo3(){
  console.log("start");
  yield 1;
  console.log("after 1");
  yield 2;
  console.log("after 2");
  yield 3;
  console.log("end");
  return "done";
}
console.log(typeof countTo3); // 'function'
console.log(countTo3.constructor.name); // 'GeneratorFunction'
const g = countTo3();
console.log("g created, not started yet");
console.log(typeof g.next, typeof g[Symbol.iterator]); // 'function' 'function'
console.log(g[Symbol.iterator]() === g); // true — self-iterable

// Lazy — nothing logged until next()
console.log(g.next()); // logs "start", returns {value:1,done:false}
console.log(g.next()); // logs "after 1", returns {value:2,done:false}
console.log(g.next()); // logs "after 2", returns {value:3,done:false}
console.log(g.next()); // logs "end", returns {value:"done",done:true} — return value
console.log(g.next()); // {value:undefined,done:true} — sticky done

// Other forms — same semantics
const expr = function* (n){ yield n; };
const arrowStar = function* (){ yield 10; }; // no arrow generator — `*` only on function/method
const obj = {
  *genMethod(){ yield 1; },
  * [Symbol.iterator](){ yield "iterable object"; }
};
console.log([...obj]); // ['iterable object'] — object itself iterable via generator method
console.log([...obj.genMethod()]); // [1]
class C { *items(){ yield "a"; yield "b"; } }
console.log([...new C().items()]); // ['a','b']
```

### 2) **Execution is suspend-and-resume, not run-to-completion**

**Definition** — each `yield expr` evaluates `expr`, suspends the generator (preserving locals, params, try-blocks, and stack), returns `{value: expr, done:false}` to the caller. The next `next(arg)` resumes at that `yield` point with `arg` as the value of the `yield` expression (see 3.3). This makes generators lazy producers — values computed only on demand.

```js
// Lazy computation — expensive work only on demand
function* lazyMap(iterable, fn){
  for(const v of iterable){
    console.log("mapping", v);
    yield fn(v);
  }
}
const mapped = lazyMap([1,2,3,4], x=>x*10);
console.log("mapped created — no logs yet");
console.log(mapped.next()); // mapping 1 → {value:10,done:false}
console.log(mapped.next()); // mapping 2 → {value:20,done:false}
// not yet mapped 3,4 — only when consumed
console.log([...mapped]); // mapping 3, mapping 4 → remaining consumed via spread

// Locals frozen between yields
function* withLocals(n){
  let acc = 0;
  for(let i=0;i<n;i++){
    acc += i;
    yield acc; // acc preserved
  }
  return acc;
}
const w = withLocals(4);
console.log(w.next()); // {value:0,done:false} — acc 0
console.log(w.next()); // {value:1,done:false} — acc 1
console.log(w.next()); // {value:3,done:false} — acc 3
console.log(w.next()); // {value:6,done:false} — acc 6
console.log(w.next()); // {value:6,done:true} — final return

// try-blocks preserved across suspension
function* withTry(){
  try{
    yield 1;
    yield 2;
  } finally {
    console.log("finally on close or completion");
  }
}
const t = withTry();
console.log(t.next()); // 1
console.log(t.return("early")); // finally, {value:"early",done:true} — early close runs finally
console.log(t.next()); // {value:undefined,done:true}

// yield cannot appear in all contexts — needs generator function; plain function throws SyntaxError
// function plain(){ yield 1; } // SyntaxError: yield outside generator
```

### 3) **Generator object protocol — `next`/`return`/`throw` and `Symbol.iterator` self**

**Definition** — Generator instances expose `next(arg)`, `return(value)`, `throw(err)` all returning `{value,done}`. `next(arg)` resumes; `return(value)` forces `done:true` with `value` after running `finally` blocks; `throw(err)` injects at the pause point (catchable inside). `yield` as an expression gets the value passed to the next `next()`; first `next()` argument is ignored (generator not yet paused on a `yield`).

```js
// next(arg) becomes yield's value
function* echo(){
  const first = yield "first yield";
  console.log("first yield gave", first);
  const second = yield "second yield";
  console.log("second yield gave", second);
  return "done";
}
const e = echo();
console.log(e.next()); // {value:'first yield',done:false} — no arg yet
console.log(e.next("A")); // logs "first yield gave A", {value:'second yield',done:false}
console.log(e.next("B")); // logs "second yield gave B", {value:'done',done:true}

console.log(echo().next("ignored")); // {value:'first yield',done:false} — arg ignored, gen not yet paused

// return() closes early — triggers finally, discards remaining yields
function* numbered(){ try{ yield 1; yield 2; yield 3; } finally{ console.log("numbered finally"); } }
const n = numbered();
console.log(n.next()); // 1
console.log(n.return(99)); // numbered finally, {value:99,done:true}
console.log(n.next()); // {value:undefined,done:true} — no more values

// throw() injects — catch inside can recover, otherwise propagates and closes
function* mayFail(){
  try{ yield 1; yield 2; }
  catch(err){ console.log("caught",err.message); yield 999; }
}
const mf = mayFail();
console.log(mf.next()); // 1
console.log(mf.throw(new Error("boom"))); // caught boom, {value:999,done:false}
console.log(mf.next()); // {value:undefined,done:true}

function* noCatch(){ yield 1; yield 2; }
const nc = noCatch();
console.log(nc.next()); // 1
try{ console.log(nc.throw(new Error("unhandled"))); }catch(err){ console.log("propagated",err.message); }
console.log(nc.next()); // {value:undefined,done:true} — generator closed after uncaught throw

// Generator is iterable — for-of, spread, destructuring all work
function* seq(){ yield 10; yield 20; }
console.log([...seq()]); // [10,20]
for(const v of seq()) console.log(v); // 10 20
const [a,b] = seq(); console.log(a,b); // 10 20
// But a Generator *instance* is consumed once
const once = seq();
console.log([...once]); // [10,20]
console.log([...once]); // [] — exhausted
```

### 4) **Common confusion**

- "Calling `function*` runs its body" — no. It returns a Generator; body runs only on `next()`. If you forget to iterate, nothing happens — a silent bug.
- "`yield` and `yield*` are the same" — no. `yield expr` yields one value; `yield* iterable` delegates to that iterable's iterator (see [3.2](<3.2. yield delegation and composition.md>)).
- "`next(arg)` sends to the previous yield on the first call" — no. The first `next()` starts the generator up to the first `yield`; that `yield` hasn't yet produced a value to replace. Its argument is ignored per spec.
- "Generators are `async`" — no. Regular `function*` is sync; for async you need `async function*` (→ [4.2](<../4. Async iteration/4.2. Async generators async yield and composition.md>)). `yield` does not await promises — a yielded promise is just a value until the consumer `await`s.

### 5) **Performance note**

Creating a generator allocates a Generator object plus a suspended stack frame. Yielding 1M integers via `function*` is ~3–5× slower and more GC pressure than a simple array or index loop (engine allocates per-yield result object). Generators win when the sequence is lazy/infinite or resource-guarded (no need to preallocate), not when you need maximum throughput on a known `n`. Prefer `Array.from({length:n}, fn)` or `for` index loop for hot dense numeric pipelines; use generators for pipelines that may short-circuit (`take`/`find`) or represent infinite/IO-backed sources.
