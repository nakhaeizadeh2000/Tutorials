## 1.2. The iterator protocol next done value return throw and closing

### 1) **The three methods and their contracts**

**Definition** — an *iterator* must have `next()` returning `{value, done}`. It may optionally have `return(value)` (early close) and `throw(err)` (error injection), each also returning `{value, done}`. `next()` drives iteration forward; `return()` tells the producer "consumer stopped early, clean up"; `throw()` injects an exception at the producer's current pause point.

**What problem it solves / history** — without `return()`, a generator holding a resource (file/DB cursor/lock) would never run its `finally` on `break`/`throw`, leaking it. ES2015 added `IteratorClose` so `for-of`/`spread`/`destructuring` automatically call `return()` on abrupt completion. `throw()` enables two-way error channels for generators as coroutines.

**Modern guidance** — implement `return()` on any custom iterator that holds state requiring cleanup (try/finally or explicit release). Make it idempotent and return `{done:true}`.

```js
// Minimal iterator — only next()
const onlyNext = (() => {
  let i = 0;
  return {
    next() { return i < 2 ? { value: i++, done: false } : { value: undefined, done: true }; },
    [Symbol.iterator]() { return this; }
  };
})();
console.log(onlyNext.next()); // { value: 0, done: false }
console.log(onlyNext.next()); // { value: 1, done: false }
console.log(onlyNext.next()); // { value: undefined, done: true } — value on done is ignored by for-of

// With return() — called on early exit
function* withFinally() {
  try { yield 1; yield 2; yield 3; }
  finally { console.log("finally: cleanup"); }
}
for (const v of withFinally()) {
  console.log(v);
  break; // triggers IteratorClose → return() → finally
}
// 1 then "finally: cleanup"

// Without return(), finally would not run on break in a manual iterator
const manualNoReturn = {
  [Symbol.iterator]() {
    let i = 0;
    return {
      next() { return i < 3 ? { value: i++, done: false } : { value: undefined, done: true }; },
      [Symbol.iterator]() { return this; }
      // no return() → break leaks if this held a resource
    };
  }
};
// for-of on this still breaks without error, but no cleanup hook runs — bad for resource iterables

// return() contract — may supply a value, but for-of ignores it
const withReturn = {
  [Symbol.iterator]() {
    let i = 0;
    let closed = false;
    return {
      next() {
        if (closed) return { value: undefined, done: true };
        return i < 3 ? { value: i++, done: false } : { value: undefined, done: true };
      },
      return(val) { closed = true; console.log("return called with", val); return { value: val, done: true }; },
      [Symbol.iterator]() { return this; }
    };
  }
};
for (const v of withReturn) { if (v === 1) break; console.log(v); }
// return called with undefined → cleanup

// throw() — only generators meaningfully implement it; plain iterators rarely do
function* canThrow() {
  try { yield 1; yield 2; }
  catch (e) { console.log("caught inside", e.message); yield 99; }
}
const g = canThrow();
console.log(g.next()); // { value:1, done:false }
console.log(g.throw(new Error("boom"))); // caught inside boom → { value:99, done:false }
console.log(g.next()); // { value: undefined, done:true }
```

### 2) **Completion record and `done:true` semantics**

**Definition** — `{value, done}` is a completion record. When `done` is `false`, `value` is the next yielded value consumed by `for-of`/spread/destructuring. When `done` is `true`, `value` is the *return value* of the iterator/generator (from `return x` or `yield*`'s final value), and `for-of`/spread *discard* it. Only an explicit `next()` call observes the done value.

```js
// done:true value is invisible to for-of/spread
function* genReturn() { yield 1; yield 2; return 999; }
console.log([...genReturn()]); // [ 1, 2 ] — 999 discarded
for (const v of genReturn()) console.log(v); // 1, 2 — no 999

// Explicit next() reveals it
const g2 = genReturn();
console.log(g2.next()); // { value:1, done:false }
console.log(g2.next()); // { value:2, done:false }
console.log(g2.next()); // { value:999, done:true } — the return value
console.log(g2.next()); // { value:undefined, done:true } — sticky done

// yield* captures the done value
function* inner() { yield 10; return "inner done"; }
function* outer() { const v = yield* inner(); console.log("inner returned", v); yield 20; }
console.log([...outer()]); // yields 10, 20 — "inner done" logged, not yielded

// Array iterators never return a meaningful done value — always undefined
const arr = [1,2];
const it = arr[Symbol.iterator]();
console.log(it.next()); // { value:1, done:false }
console.log(it.next()); // { value:2, done:false }
console.log(it.next()); // { value:undefined, done:true }

// Destructuring also discards done value
const [a, b] = genReturn();
console.log(a, b); // 1 2 — 999 not assigned

// To capture done value you must drive manually, not via for-of/...
function captureDone(iterable) {
  const it2 = iterable[Symbol.iterator]();
  let step;
  while (!(step = it2.next()).done) { /* consume */ }
  return step.value; // done value
}
console.log(captureDone(genReturn())); // 999
```

### 3) **IteratorClose — how break/throw/return trigger `return()` for cleanup**

**Definition** — `IteratorClose` (ECMA-262 §7.4.6) runs when `for-of`, `for await...of`, spread, destructuring, `Array.from`, `yield*`, or `new Map/Set` encounter an abrupt completion (break/continue-with-label/throw/return) before the iterator is done. If the iterator has a `return()` method, it is called with no value (or the completion value for some paths), and any error from `return()` replaces the original completion if it throws.

**What problem it solves** — ensures `try/finally` inside generators and resource iterables runs even on early exit, mirroring `using`/`Symbol.dispose` discipline for synchronous resources. Without it, a `break` in `for-of` over a DB cursor would orphan the cursor.

**Modern guidance** — put resource release in `try/finally` inside the generator/iterable, not in the consumer. The consumer just breaks/throws; the producer's `return()` → `finally` does cleanup. Test that your iterable's `return()` is idempotent.

```js
// For-of triggers return() on break
function* cursor() {
  console.log("open cursor");
  try {
    yield "row1"; yield "row2"; yield "row3";
  } finally {
    console.log("close cursor — finally runs");
  }
}
for (const row of cursor()) {
  console.log(row);
  if (row === "row1") break;
}
// open cursor, row1, close cursor — finally runs via IteratorClose

// Throw also triggers close
try {
  for (const v of cursor()) {
    console.log(v);
    throw new Error("abort");
  }
} catch (e) { console.log("caught", e.message); }
// close cursor still runs before catch

// Manual iterator with return() — Array.from closes on abrupt
let closed = false;
const resourceIter = {
  [Symbol.iterator]() {
    let i = 0;
    return {
      next() { if (i < 3) return { value: i++, done: false }; return { value: undefined, done: true }; },
      return() { closed = true; console.log("IteratorClose: return()"); return { value: undefined, done: true }; },
      [Symbol.iterator]() { return this; }
    };
  }
};
// Destructuring with early exit closes
const [first] = resourceIter;
console.log(first, closed); // 0 true — destructuring closes after taking what it needs
// Break case also closes (fresh iterator instance)
closed = false;
for (const v of resourceIter) { console.log(v); break; }
console.log("after break closed?", closed); // true

// yield* propagates close to inner
function* inner2() { try { yield 1; yield 2; } finally { console.log("inner finally"); } }
function* outer2() { try { yield* inner2(); } finally { console.log("outer finally"); } }
for (const v of outer2()) { console.log(v); break; }
// inner finally, outer finally — both run

// If return() throws, iteration throws that instead
const badClose = {
  [Symbol.iterator]() {
    return {
      next() { return { value: 1, done: false }; },
      return() { throw new Error("return failed"); },
      [Symbol.iterator]() { return this; }
    };
  }
};
try { for (const v of badClose) { break; } } catch (e) { console.log("return threw:", e.message); }
```

### 4) **Common confusion**

- "`return()` value is yielded" — no. `for-of`/spread discard the done value; only manual `next()` reveals it.
- "`next()` after done stays done" — yes, sticky `done:true` (subsequent calls return `{done:true}`).
- "iterators must have `return`/`throw`" — no, they are optional. But without `return`, early exits cannot clean up resources — a bug for resource iterables.
- "`break` leaks resources" — not if the iterable implements `return()` correctly (generators do automatically via `finally`). Test with a `try/finally` + `break`.

### 5) **Performance note**

Calling `return()` on close is one extra method call per early exit, negligible. The real cost is forgetting it: a leaked DB cursor/file handle pays orders of magnitude more. For non-resource iterables over plain arrays, the engine inlines `ArrayIterator.next` and elides `return` entirely — no cost difference vs index loop.

### 6) **Mentor note**

Ask juniors to predict the output of `for (const v of gen()) break` where `gen` has `try/finally` — most miss that `finally` runs. Demo the opposite manual iterator without `return()` to show the leak. In review, flag any custom iterator holding a resource without a `return()` method and `try/finally` guard.
