## 7.1. Common interview Q&A iterables generators and async iteration

### 1) **The classics with mechanism-level answers**

**Q1. What is the difference between iterable, iterator, and array-like?**
Iterable has `Symbol.iterator` returning an iterator; iterator has `next()` returning `{value,done}` (optionally `return`/`throw`) and is iterable via `return this`; array-like has `length` + indices but not necessarily `Symbol.iterator`. `Array`/`string`/`Set`/`Map` are both. `{0:"a",length:1}` is array-like only; `[...it]` needs iterable, `Array.from` handles both.

**Q2. What does `for-of` actually do (desugar)?**
`iter = GetIterator(iterable)`, loop `step=iter.next()`, `if(done) break`, bind `value`, body; on abrupt (break/throw/return) call `IteratorClose` → `iter.return()` if exists, so `try/finally` inside generators runs. Per-iteration environment (closure captures correctly).

**Q3. Spread `...` vs `Array.from` — are they identical?**
No. `...` consumes only iterables (throws on array-like non-iterable/null). `Array.from` handles both iterables and array-likes, accepts `mapFn`/`thisArg`, and preserves holes differently? Actually both yield `undefined` for holes on arrays; but `Array.from({0:"a",length:1})` works where `...` throws.

**Q4. What happens when you `break` inside `for-of` over a generator?**
`IteratorClose` → `generator.return()` → runs any `finally` blocks → done. If generator holds a resource, that's the cleanup hook. Manual `while(next().done)` without `return()` leaks.

**Q5. Calling `function*` — when does the body run?**
Never on call — returns a Generator. Body runs only on `next()`, suspending at each `yield`. If you never iterate, nothing executes — a silent bug.

**Q6. First `next(arg)` argument? `yield` vs `yield*`? Done value?**
First `next(arg)` arg is ignored (no `yield` yet); later `next(arg)` becomes the paused `yield`'s value. `yield expr` yields one value; `yield* iterable` delegates to that iterable's iterator (forwards `next`/`return`/`throw`, captures done value). `for-of`/spread discard `done:true` value; `yield*`'s expression value is that done value.

**Q7. How does `yield*` propagate closing?**
`yield*` forwards outer `return()`/`throw()` to inner iterator's methods, so inner `finally` runs, then outer. Manual `for-of`+`yield` loses this unless you duplicate forwarding.

**Q8. Custom iterable — how to make it safely reusable vs one-shot?**
Return a fresh iterator object each `Symbol.iterator` call, with its own state closure. Don't return `this` as the iterator when the iterable is meant to be re-iterated — that makes it one-shot (second spread empty).

**Q9. Why does `for-of` over `[1,,3]` yield `undefined` at hole vs `forEach` skipping?**
Array iterator spec yields `undefined` for missing indices (`for-of`/`spread`/`Array.from` yield `undefined`); `forEach`/`map`/`filter` callbacks are not called for holes; `for-in` skips holes because no key.

**Q10. `for await...of` on a plain `Array` — does it work?**
Yes. `for await` prefers `Symbol.asyncIterator`, falls back to `Symbol.iterator` (sync result wrapped via `Promise.resolve` and awaited). Use it when you have mixed sync/async sources; otherwise plain `for-of`.

**Q11. Infinite generator — how to avoid hang?**
Never spread unbounded infinite (`[... naturals()]` hangs). Bound with `take(k)` or `break`/`return`. Generators are lazy — only compute on demand.

**Q12. Async generator vs async function returning Promise — difference?**
`async function` returns `Promise`; `async function*` returns `AsyncGenerator` (async iterator). First needs `await`; second needs `for await`/`await next()`.

```js
// Q6 demo
function* ask(){ const v = yield 1; return v; }
const g=ask();
console.log(g.next()); // {value:1,done:false}
console.log(g.next("A")); // {value:"A",done:true} — "A" became yield result
console.log(ask().next("ignored")); // {value:1,done:false} — first arg ignored

// Q6 yield* done capture
function* inner(){ yield 1; return "done"; }
function* outer(){ const v=yield* inner(); console.log(v); }
console.log([...outer()]); // 1, logs "done" — not yielded

// Q9
const a=[1,,3];
for(const v of a) console.log("for-of",v); // 1 undefined 3
a.forEach(v=> console.log("forEach",v)); // 1 3 — skip

// Q10
(async()=>{ for await(const v of [1,2]) console.log("for-await sync",v); })();

// Q12
async function* ag(){ yield await Promise.resolve(1); }
(async()=>{ for await(const v of ag()) console.log("ag",v); })();
```

### 2) **What interviewers actually probe for**

Senior probes narrate IteratorClose/AsyncIteratorClose and suspend/resume, not syntax. Expect: "break calls `return()` → `finally`" , "`for-of` vs `for-in` protocol difference", "`yield*` propagates `return`/`throw` and captures done", "`Symbol.iterator` factory vs shared `this`", "code points vs code units for strings". Red flags: "generator runs on call", "`for-of` uses `Object.keys`", "`...` works on array-like", "done value is yielded", "`for await` runs parallel".

### 3) **Grading guidance**

| Signal | Level |
|--------|-------|
| Recites `Symbol.iterator`/`next`/`done` table, knows array-like distinction | junior → mid |
| Explains `IteratorClose`/`return()`/`finally` and per-iteration environment | mid → senior |
| Contrasts `yield` vs `yield*` closing/done-value and async `for await` fallback vs serial | senior |
| Predicts `[1,,3]` for-of vs forEach, `split` vs spread, `first next(arg)` ignored, custom iterator `return this` bug | senior → mentor |
| Red flags | "generators are async", "`...` on `{0:'a',length:1}` works", "`for-of` uses `for-in`", "done value yielded", "infinite spread is fine" |

```js
// Grading snippet — predicts all before running
function* gGrade(){ try{ yield 1; yield 2; } finally{ console.log("finally"); } }
for(const v of gGrade()){ console.log(v); break; } // 1, finally — tests close
console.log([...[1,,3]]); // [1, undefined, 3] — tests hole understanding
console.log("A👋".length, [..."A👋"].length); // 3, 2 — tests unit vs point
console.log((function*(){ yield* [1,2]; return 99; })().next()); // {value:1} — yield* not done

// Follow-up: "write take()"
function* take(iter, n){ let i=0; for(const v of iter){ if(i++>=n) return; yield v; } }
console.log([...take([1,2,3,4], 2)]); // [1,2]

// Async follow-up: "when does for await need for await vs for of?"
// Answer: async iterables, otherwise for-of is fine — for-await also handles sync but serializes.
```

### 4) **Common confusion**

- "Iterator `return` value is yielded" — no, discarded by `for-of`/spread; only `yield*` captures and manual `return()` reveals.
- "`for await...of` parallelizes" — no, serial `await` per element; for parallel `Promise.all`.

### 5) **Performance note**

Grading expects measure-don't-guess framing: iteration allocations (IteratorResult) dominate tight loops — mention but don't prematurely optimize; emphasize correctness and closing contracts first.

### 6) **Mentor note**

Use the Q1→Q12 ladder in interviews: start with classification (Q1), push to closing (Q4/Q7), then emoji/string (Q9+split), then async (Q10/Q12). Stop when they miss a mechanism — that's the ceiling.
