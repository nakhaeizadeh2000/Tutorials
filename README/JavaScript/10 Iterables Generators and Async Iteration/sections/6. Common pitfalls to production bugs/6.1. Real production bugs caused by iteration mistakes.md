## 6.1. Real production bugs caused by iteration mistakes

### 1) **Spreading/destructuring a non-iterable or null — TypeError ships**

**Incident** — API returns `maybeItems` that is `null` on empty or an array-like without `Symbol.iterator` (e.g. `{0:"a", length:1}` from a legacy serializer). Code does `const items=[...maybeItems]` or `const [first]=maybeItems` and crashes: `TypeError: Found non-callable @@iterator`. Crash in prod because path only hit on empty/legacy payload.

```js
// BAD — assumes iterable, crashes on null/array-like
function badSpread(maybeItems){
  return [...maybeItems]; // throws if maybeItems is null or {0:"a",length:1}
}
try{ console.log(badSpread(null)); }catch(e){ console.log("badSpread null",e.name, e.message.includes("not iterable")); }
try{ console.log(badSpread({0:"a",length:1})); }catch(e){ console.log("badSpread array-like",e.name); }

// GOOD — guard + fallback
function goodSpread(maybeItems){
  if(maybeItems==null) return [];
  if(typeof maybeItems[Symbol.iterator]==="function") return [...maybeItems];
  if(typeof maybeItems.length==="number") return Array.from(maybeItems); // array-like
  throw new TypeError("unexpected items type");
}
console.log(goodSpread(null)); // [] — safe
console.log(goodSpread([1,2])); // [1,2]
console.log(goodSpread({0:"a",length:1})); // ["a"] — fallback works
console.log(goodSpread(new Set([1,2]))); // [1,2]
console.log(goodSpread("hi")); // ["h","i"]

// Same for destructuring — implicit iteration
function badFirst(x){ const [first]=x; return first; } // throws if x not iterable
function goodFirst(x){
  if(x==null) return undefined;
  if(typeof x[Symbol.iterator]!=="function") x = Array.from(x); // try array-like
  const [first]=x; return first;
}
console.log(goodFirst(null)); // undefined
console.log(goodFirst({0:"x",length:1})); // "x"
```

### 2) **Infinite generator without closing — memory/CPU leak or un-released handle**

**Incident** — `function* naturals(){while(true) yield n++;}` consumed via `Array.from(naturals())` or `for(const v of naturals())` without bound — hangs CPU, OOM, or iterator never closed so inner `finally` (file/DB) never runs. Also: filtering infinite without `take` yields no termination.

```js
// BAD — unbounded consumption of infinite
function* naturals(){
  let n=0; while(true) yield n++;
}
// [...naturals()] // DON'T — infinite hang/OOM

// BAD — infinite filter without take (never terminates)
function* filter(iter, pred){ for(const v of iter) if(pred(v)) yield v; }
function* take(iter, k){ let i=0; for(const v of iter){ if(i++>=k) return; yield v; } }
// console.log([...filter(naturals(), n=>n%2===0)]); // infinite — no bound

// GOOD — always bound infinite with take/break + close propagates
console.log([...take(naturals(), 5)]); // [0,1,2,3,4]
console.log([...take(filter(naturals(), n=>n%2===0), 4)]); // [0,2,4,6]

// Resource leak without close — BAD manual drive without return()
function* cursor(rows){
  console.log("open cursor");
  try{ for(const r of rows) yield r; }
  finally{ console.log("close cursor"); }
}
{
  const it = cursor(["a","b","c"])[Symbol.iterator]();
  console.log(it.next().value); // a — open, but no close yet
  // break without return() → leak (finally never runs)
  console.log("leak — finally not yet run");
  // FIX: use for-of or call return()
  console.log(it.return()); // now close
}

// GOOD — for-of auto-closes
for(const v of cursor(["a","b","c"])){ console.log(v); break; } // close via return() — safe

// GOOD — yield* composition auto-propagates close
function* outer(){ yield* cursor(["x","y","z"]); }
for(const v of outer()){ console.log(v); break; } // inner close propagated
```

### 3) **Using `for-in` on arrays and `split("")` on strings — wrong protocol**

**Incident** — `for-in` on an array iterates string indices + all enumerable extras (`arr.extra`, prototype additions) → double-processing or TypeErrors. `str.split("")` breaks emoji into halves → wrong length, wrong search, corrupted user display names. Both ship silent correctness bugs, not crashes.

```js
// BAD — for-in on Array (includes extras, string keys)
const arr=[1,2]; arr.extra="leak";
const keys=[]; for(const k in arr) keys.push(k);
console.log(keys); // ["0","1","extra"] — extra is not an index
const valsForIn=[]; for(const k in arr) valsForIn.push(arr[k]);
console.log(valsForIn); // [1,2,"leak"] — polluted
delete arr.extra;

// GOOD — for-of or classic for
const vals=[]; for(const v of [1,2]) vals.push(v);
console.log(vals); // [1,2] — clean, uses iterable protocol

// BAD — split("") for string iteration (code units)
const name="A👩‍🚀B";
console.log(name.length); // 7 — units, not 5 code points
console.log(name.split("")); // ["A","\uD83D","\uDC69","\u200D","\uD83D","\uDE80","B"] — halves of emoji
console.log(name.split("").length); // 7 — wrong
console.log([...name]); // ["A","👩","\u200D","🚀","B"] — code points (correct protocol)
console.log([...name].length); // 5
for(const ch of name) console.log(ch); // for-of via Symbol.iterator — code points
console.log(Array.from(name).length); // 5 — also code points
console.log([...name].join("")); // reconstructs correctly? ZWJ remains separate — grapheme needs Intl.Segmenter (see Strings domain)

// BAD — yields swapped? same class: yield without star
function* badYieldArray(){ yield [1,2]; } // yields one array value
console.log([...badYieldArray()]); // [[1,2]] — likely bug if caller expected [1,2]
function* goodYieldStar(){ yield* [1,2]; } // delegates
console.log([...goodYieldStar()]); // [1,2] — correct delegation

// GOOD — take via yield* not manual loop that loses close
function* badDelegate(it){ for(const v of it) yield v; } // loses inner return propagation nuance
function* goodDelegate(it){ yield* it; } // correct
```

### 4) **`for-await` on sync iterable without await handling and swallowed async close**

**Incident** — `for await (const v of asyncGen()) { break; }` but async generator's `finally` contains `await` cleanup (e.g. `await db.close()`). If the caller is not `async` or forgets to `await` the loop completion, the loop returns a promise that is never awaited → cleanup's `await` never completes before process exits, handle leak. Similarly, `Array.from(asyncIterable)` silently produces empty array (sync protocol only) → missing data.

```js
// BAD — sync consumer on async iterable (silent empty)
const asyncIter = {
  [Symbol.asyncIterator](){ let i=0; return { next(){return Promise.resolve(i<2?{value:i++,done:false}:{value:undefined,done:true})}, [Symbol.asyncIterator](){return this}}; }
};
console.log(Array.from(asyncIter)); // [] — Array.from uses sync protocol only, async values lost
try{ console.log([...asyncIter]); }catch(e){ console.log("spread async",e.name); } // TypeError

// GOOD — for await
(async () => {
  const out=[]; for await(const v of asyncIter) out.push(v);
  console.log(out); // [0,1]
})();

// BAD — not awaiting the for await loop's promise (cleanup never finishes)
async function* streamWithCleanup(){
  console.log("open");
  try{ yield await Promise.resolve(1); yield 2; }
  finally{ await new Promise(r=> setTimeout(()=>{ console.log("async close"); r(); },5)); }
}
async function badCaller(){
  // for await inside async but caller doesn't await the outer async function
  (async ()=>{ for await(const v of streamWithCleanup()){ console.log("bad",v); break; } })(); // fire-and-forget
  console.log("badCaller done before cleanup");
}
badCaller(); // logs bad, badCaller done — async close may still pending (race)

// GOOD — await the loop
async function goodCaller(){
  for await(const v of streamWithCleanup()){ console.log("good",v); break; } // awaited
  console.log("goodCaller after cleanup — close already ran");
}
setTimeout(()=> goodCaller(), 20);

// Rule: keep async iteration inside awaited async context; never fire-and-forget a loop whose generator has async finally
```

### 5) **Common confusion**

- "`break` leaks resources" — only if you manually drive `next()` and forget `return()`; `for-of`/`for await...of`/`yield*`/destructuring auto-close.
- "Infinite is safe if you spread after filter" — no, any unbounded pull of an infinite source hangs; always insert `take(n)` or `break`.
- "`split('')` equals spread for strings" — never for emoji; `split` yields UTF-16 units, `[...str]`/`for-of`/ `Array.from` yield code points.

### 6) **Performance note**

Fire-and-forgetting `for await` loops leaks not just resources but microtask queues (pending `return()` promises). Under load, that queue growth is O(n) and shows as RSS climb. Always `await` async iteration when `return()` is meaningful; measure with `--trace-async-hooks` if you suspect leak.

### 7) **Mentor note**

Reproduce in review: `[...maybeNull]` on `null` (TypeError), `[...naturals()]` hanging Node (kill after 1s to show), `for-in` on `Array` with `extra` (extra iteration), `split("")` on `"A👋"` (surrogate halves). Those four demos cover 80% of iteration bugs caught in interviews. Demand `Array.from` fallback for array-like, `take` for infinite, `for-of` for arrays, spread/`Array.from` for strings, and `for await` for async iterables — no exceptions.
