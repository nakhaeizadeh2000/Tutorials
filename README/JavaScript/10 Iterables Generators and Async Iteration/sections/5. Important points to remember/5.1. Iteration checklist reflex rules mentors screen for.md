## 5.1. Iteration checklist reflex rules mentors screen for

### 1) **Iterable vs iterator vs array-like — three questions before any consumer**

Before spreading/destructuring/`for-of`/`Array.from`/`new Map(Set)`, ask: is `x` iterable (`Symbol.iterator`)? Is it an iterator (`next`)? Is it array-like (`length`)? The answer dictates which consumer works and whether you need a fallback. Never assume `[...x]` works until you've proven iterable; prefer `Array.from(x)` if both paths are possible.

```js
// Checklist reflex
function describe(x){
  const it = x!=null && typeof x[Symbol.iterator]==="function";
  const ail = x!=null && typeof x.length==="number" && x.length>=0;
  const itr = x!=null && typeof x.next==="function";
  return { iterable: it, arrayLike: ail, iterator: itr };
}
console.log(describe([1,2])); // { iterable: true, arrayLike: true, iterator: false } — but iterator is per call, not array itself
console.log(describe({0:"a",length:1})); // { iterable: false, arrayLike: true, iterator: false }
console.log(describe((function*(){})())); // { iterable: true, arrayLike: false, iterator: true } — generators are both
console.log(describe(new Map())); // { iterable: true, arrayLike: false, iterator: false }
console.log(describe("hi")); // { iterable: true, arrayLike: true, iterator: false } — string is both
console.log(describe(null)); // defensive guard needed

// Safe consumer selection
function safeToArray(x){
  if(x==null) return [];
  if(typeof x[Symbol.iterator]==="function") return [...x];
  if(typeof x.length==="number") return Array.from(x); // array-like
  throw new TypeError("not iterable or array-like");
}
console.log(safeToArray([1,2])); // [1,2]
console.log(safeToArray({0:"a",length:1})); // ["a"]
try{ console.log(safeToArray({})); }catch(e){ console.log(e.name); } // TypeError

// Iterator vs iterable reuse
function* gen(){ yield 1; }
const it = gen();
console.log([...it]); // [1] — consumes
console.log([...it]); // [] — bug if you reused `it` thinking it's re-iterable — use gen() factory
```

### 2) **Completion `done` value is not yielded; `return()` must clean up**

`for-of`/`spread`/`Array.from` discard the `done:true` value; only manual `next()` reveals it. `yield*` captures it as the expression value. Any resource iterable must implement `return()` → `try/finally` cleanup; `for-of`/`for await...of`/`yield*`/`destructuring` automatically call `return()` on early exit.

```js
// done value not yielded
function* withReturn(){ yield 1; return 99; }
console.log([...withReturn()]); // [1] — 99 discarded
const g = withReturn();
g.next(); console.log(g.next()); // {value:99,done:true} — only manual sees it

// yield* captures
function* inner(){ yield 1; return "done"; }
function* outer(){ const v = yield* inner(); console.log("captured",v); }
console.log([...outer()]); // captured done, yields [1]

// Closing contract — try/finally
function* resource(){
  console.log("open");
  try{ yield 1; yield 2; }
  finally{ console.log("close"); }
}
for(const v of resource()){ console.log(v); break; } // open, 1, close — not leaked
const r = resource()[Symbol.iterator]();
console.log(r.next()); // open, 1 — manual drive without close would leak until return()
console.log(r.return()); // close — must call

// Checklist question: "does this iterable hold a resource? → does it have return()/finally?"
function hasReturn(iterable){ const it=iterable[Symbol.iterator](); return typeof it.return==="function"; }
console.log(hasReturn(resource())); // true — generators do
console.log(hasReturn({[Symbol.iterator](){return{next(){return{value:1,done:false}},[Symbol.iterator](){return this}}}})); // false — missing
```

### 3) **The review grep list**

| Grep | Flag | Why |
|------|------|-----|
| `for\s*\(\s*(var\|let\|const).+in\s` on `Array\|Map\|Set` | `for-in` on iterable | `for-in` enumerates keys (+ extras), `for-of` yields values; `for-in` on Map yields nothing |
| `\[...` on unknown `x` | non-iterable spread | throws if `x` is array-like non-iterable or null — guard or `Array.from` |
| `yield` outside `function*` / missing `*` | `yield` syntax error / `async function` not `async function*` | `yield` only in `function*`/`async function*`; missing `*` means not iterable |
| `gen\.next\(value` on first call | ignored first arg | first `next()` arg is discarded — pass initial via params |
| `yield\s` vs `yield*` | manual `for-of`+`yield` vs `yield*` | manual loses `return()`/`throw()` propagation and done value |
| `Array\.from\(async` / `\[...async` | sync consumer on async iterable | async iterable needs `for await...of` not `Array.from`/`...` |

```js
// 1. for-in vs for-of
const arr=[1,2]; arr.extra="x";
for(const k in arr) console.log("bad for-in",k); // 0 1 extra — likely bug
for(const v of arr) console.log("good for-of",v); // 1 2 — correct

// 2. [...x] guard
try{ const maybe=null; console.log([...maybe]); }catch(e){ console.log("spread null",e.name); } // TypeError — guard
console.log(Array.from({0:"a",length:1})); // Array.from works when spread wouldn't

// 3. yield star
function* bad(){ const it=[1,2][Symbol.iterator](); for(const v of {[Symbol.iterator](){return it}}) yield v; } // loses close — use yield*
function* good(){ yield* [1,2]; }

// 4. async vs sync
async function* ag(){ yield 1; }
console.log(typeof ag()[Symbol.iterator]); // undefined — not sync iterable
console.log(typeof ag()[Symbol.asyncIterator]); // function — async iterable
// for(const v of ag()) {} // SyntaxError/TypeError — need for await
(async()=>{ for await(const v of ag()) console.log("for-await",v); })();
```

### 4) **Common confusion**

- "Spread on array-like preserves holes" — array iteration yields `undefined` for holes; spread densifies behavior uniformly.
- "Done value matters for `for-of`" — never; if you need the return value, drive manually or use `yield*` capture.
- "`for-of` `continue` closes" — only `break`/`throw`/`return`/labeled exit; `continue` stays in loop.

### 5) **Performance note**

Use checklist framing: iteration overhead is one allocation per value (IteratorResult). Keep hot numeric loops on arrays as index/`for-of` (inlined); keep generator/async-generator chains only when you benefit from laziness/short-circuit or async backpressure. For `Array.from(iterable, mapFn)` vs `[...iterable].map(fn)`, the former avoids an intermediate array — one allocation less, but both iterate once.

### 6) **Mentor note**

Give mentees the three-question card: "iterable? iterator? array-like?" and make them classify 8 examples (`[]`, `{0:"a",length:1}`, `Map`, `Set`, `"hi"`, `function*`, `arguments`, `null`) before any iteration debate. Then quiz done-value vs yielded: `yield* inner()` — what's yielded vs captured? Then live code `break` inside `for-of` over a `try/finally` generator to show closing — the single most missed interview mechanism.
