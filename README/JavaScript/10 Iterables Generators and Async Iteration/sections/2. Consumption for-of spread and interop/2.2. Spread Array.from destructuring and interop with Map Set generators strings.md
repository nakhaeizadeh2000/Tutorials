## 2.2. Spread Array.from destructuring and interop with Map Set generators strings

### 1) **Spread `...iterable` and `Array.from(iterable, mapFn)` are iterable consumers**

**Definition** — spread in `[...iterable]` and in function calls `fn(...iterable)` iterates the iterable via `GetIterator` and collects/spreads each `value` until `done:true`, triggering `IteratorClose` on abrupt completion. `Array.from(x, mapFn, thisArg)` does the same but accepts both iterables and array-likes (array-like fallback uses `length`), and applies `mapFn` per element if provided.

```js
// Spread — iterable → array
console.log([...[1,2,3]]); // [1,2,3]
console.log([...new Set([3,1,2])]); // [3,1,2] — insertion order
console.log([...new Map([["a",1],["b",2]])]); // [['a',1],['b',2]] — entries
console.log([..."abc"]); // ['a','b','c'] — string code points
console.log([...(function*(){yield 10; yield 20;})()]); // [10,20]

// Array.from — iterable OR array-like, with optional map
console.log(Array.from(new Set([1,2,3]))); // [1,2,3]
console.log(Array.from({0:"a",1:"b",length:2})); // ['a','b'] — array-like path
console.log(Array.from([1,2,3], x=>x*2)); // [2,4,6] — map without intermediate array
console.log(Array.from("hi👋")); // ['h','i','👋'] — string as iterable
console.log(Array.from({length:3}, (_,i)=>i)); // [0,1,2] — length + map builds range

// Spread vs Array.from on holes — subtle difference (see Arrays 2.1/3.2)
console.log([...[1,,3]]); // [1, undefined, 3] — array iterator yields undefined for hole
console.log(Array.from([1,,3])); // [1, undefined, 3] — same for iterable path
// But Array.from on array-like preserves vs iterable path both densify via undefined — slice preserves holes instead
console.log(Array.from({0:1,2:3,length:3})); // [1, undefined, 3] — array-like hole

// thisArg
console.log(Array.from([1,2], function(x){ return x*this.m; }, {m:10})); // [10,20]

// Spread throws on non-iterable — Array.from has fallback
try{ console.log([...{0:"a",length:1}]); }catch(e){ console.log(e.name); } // TypeError
console.log(Array.from({0:"a",length:1})); // ['a'] — fallback works

// Function call spread
function sum(a,b,c){ return a+b+c; }
console.log(sum(...[1,2,3])); // 6
console.log(sum(...new Set([1,2,3]))); // 6
```

### 2) **Destructuring `[a,b,...rest]` and `new Map(iterable)`/`new Set(iterable)` consume iteration**

**Definition** — array destructuring `const [a,b,...rest]=iterable` iterates the iterable: takes first two values for `a`/`b`, collects the rest into `rest` (partial consume → `IteratorClose` via `return()`). `new Map(iterable)` expects `[k,v]` pairs; `new Set(iterable)` expects values — both iterate once and close on abrupt.

```js
// Array destructuring — iterable consumer with closing
const [first, second] = new Set([10,20,30]);
console.log(first, second); // 10 20
const [a, b, ...rest] = [1,2,3,4,5];
console.log(a,b,rest); // 1 2 [3,4,5]
const [x, y] = "hi👋"; // string iterable
console.log(x,y); // 'h' 'i' — code points, not units

// Early close — remaining values discarded via return()
function* gen(){ try{ yield 1; yield 2; yield 3; } finally{ console.log("gen finally on destruct close"); } }
const [onlyFirst] = gen();
console.log(onlyFirst); // 1 — generator closed after taking 1, finally runs

// Map/Set constructors iterate
const m = new Map([["a",1],["b",2]]);
console.log(m.get("a")); // 1
console.log([...new Map(m)]); // [['a',1],['b',2]] — Map is iterable via entries
console.log([...new Set([1,2,2,3])]); // [1,2,3] — deduplicated insertion order

// Map entries destructuring
for(const [k,v] of m) console.log(k,v); // a 1, b 2
const entries = [[1,"one"],[2,"two"]];
const m2 = new Map(entries);
console.log(m2.get(1)); // 'one'

// String destructuring counts code points
const [p, q] = "A👋B";
console.log(p, q); // 'A' '👋' — not half-surrogate

// Object destructuring does NOT use iteration — it uses property keys (covered in Objects 4.3)
const {length} = [1,2,3];
console.log(length); // 3 — not iteration

// Rest in destructuring collects via iteration
function* nums(){ yield 1; yield 2; yield 3; yield 4; }
const [n1, ...remaining] = nums();
console.log(n1, remaining); // 1 [2,3,4] — consumed all remaining
```

### 3) **String iteration is code-point not code-unit; generators and Map/Set are iterable factories**

**Definition** — `String.prototype[Symbol.iterator]` yields *code points* (Unicode scalar values), not UTF-16 code units. Surrogate pairs (e.g. `👋` = `\uD83D\uDC4B`) and ZWJ sequences emit one or more code points correctly vs `str[i]` which returns units. Generators, Map, Set, and custom iterables are all iterable factories — spread/`for-of`/`Array.from` treat them uniformly.

```js
// String — code points vs code units
const s = "A👩‍🚀B"; // woman astronaut = 👩 + ZWJ + 🚀 — multiple code points, one grapheme
console.log(s.length); // 7 — UTF-16 units (A=1, 👩=2, ZWJ=1, 🚀=2, B=1)
console.log([...s]); // ['A','👩','\u200D','🚀','B'] — 5 code points (ZWJ separate)
console.log(Array.from(s)); // same
console.log(s.split("")); // ['A','\uD83D','\uDC69','\u200D','\uD83D','\uDE80','B'] — units — WRONG for iteration
for(const ch of s) console.log(ch); // A, 👩, ZWJ, 🚀, B

// Correct code-unit access vs code-point iteration
console.log(s[1], s[2]); // '\uD83D' '\uDC69' — halves of 👩
console.log([...s][1]); // '👩' — whole code point

// Map/Set interop
const set = new Set(["a","b","a"]);
console.log(set.size); // 2
console.log([...set]); // ['a','b']
const map = new Map([["k", set]]);
console.log([...map]); // [['k', Set(2)]]
console.log(map.get("k") === set); // true — identity preserved

// Generator interop — same protocol
function* range(n){ for(let i=0;i<n;i++) yield i; }
console.log([...range(5)]); // [0,1,2,3,4]
console.log(Array.from(range(3), x=>x*10)); // [0,10,20]
console.log(new Set(range(3))); // Set(3) {0,1,2}
for(const v of range(2)) console.log("range",v); // 0 1

// Custom iterable interop — all consumers work uniformly
const counter = {
  n: 4,
  *[Symbol.iterator](){ for(let i=0;i<this.n;i++) yield i; }
};
console.log([...counter]); // [0,1,2,3]
console.log(Array.from(counter, x=>x*x)); // [0,1,4,9]
for(const v of counter) console.log("counter",v);

// Non-iterable throws on spread — use Array.from fallback if needed
const arrayLike = {0:"x",1:"y",length:2};
console.log(Array.from(arrayLike)); // ['x','y'] — fallback works for array-like
try{ console.log([...arrayLike]); }catch(e){ console.log("spread failed",e.name); } // TypeError

// Bad practice — using Object.keys to iterate Map/Set (loses protocol, includes extras)
const bad = new Map([["a",1]]); bad.extra="leak";
console.log(Object.keys(bad)); // [] — Maps have no enumerable own keys for entries
console.log([...bad]); // [['a',1]] — correct via iterator; extra not in iteration
```

### 4) **Common confusion**

- "`[...iterable]` preserves holes" — no, iterables yield values; holes in arrays become `undefined` when iterated (array iterator yields `undefined` for missing indices). To preserve holes as holes, use `slice()` (see [Arrays 3.2](<../../../08 Arrays/sections/3. Mutation and its copy-era alternative/3.2. Non-mutating copies toReversed toSorted toSpliced and with ES2023.md>)).
- "`str.length` equals iterable length" — no, `length` counts UTF-16 units (2 for emoji like 👋), `[...str].length` counts code points (1 for 👋). Grapheme clusters (emoji families with ZWJ) are multiple code points — segment with `Intl.Segmenter` (→ Strings domain when it lands).
- "`Array.from` and `[...]` are identical" — no, `Array.from` accepts array-likes and takes a `mapFn`; spread only iterables.
- "Destructuring a generator consumes all" — only up to what you bind; `const [a] = gen()` closes early via `return()` and runs `finally`; `const arr=[...gen()]` consumes all.

### 5) **Performance note**

`Array.from(iterable, mapFn)` is preferred over `[...iterable].map(mapFn)` — one pass, one allocation. Spread `[...largeSet]` copies the whole collection into an array — O(n) memory; iterate lazily with `for-of` if you only need to scan once. String iteration produces one string per code point — for huge strings, streaming via iterator avoids the intermediate array that `[...huge]` allocates.
