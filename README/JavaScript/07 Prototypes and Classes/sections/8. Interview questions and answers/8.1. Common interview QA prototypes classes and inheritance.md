## 8.1. Common interview Q&A: prototypes, classes, and inheritance

### 1) **The classics with mechanism-level answers**

**Q1. What does `new C()` do step-by-step?**
A — 1) `OrdinaryCreateFromConstructor(new.target, C.prototype)` → plain object with `[[Prototype]] = C.prototype`; 2) call `C` with `this` = that object, `new.target` = `C`, `this` parameterizes delegation; 3) if constructor returns an object, that object wins; else `this`. If `C` is `class`, bare `C()` throws `TypeError` (→ [2.1](../2. Constructors and new/2.1. The new operator prototype property new.target and return override.md)).

**Q2. `__proto__` vs `.prototype` vs `[[Prototype]]`?**
A — `[[Prototype]]` is per-object internal link (`getPrototypeOf`); `.prototype` is per-function template `new` stamps (→ [2.1](../2. Constructors and new/2.1. The new operator prototype property new.target and return override.md)); `__proto__` is legacy accessor on `Object.prototype` reflecting `[[Prototype]]` (slow mutation path → [1.2](../1. Prototype delegation/1.2. Creation mutation and performance costs.md)). Plain objects have no `.prototype`.

**Q3. Why does `d instanceof C` become `false` after `C.prototype = {}`?**
A — `instanceof` checks *current* `C.prototype` in `d`'s chain, not birth prototype. `d` holds old `C.prototype` link; after reassignment old not found → `false`. `Object.getPrototypeOf(d) !== C.prototype` then (→ [2.1](../2. Constructors and new/2.1. The new operator prototype property new.target and return override.md) / [5.1](../5. Type checks and reflection/5.1. instanceof isPrototypeOf Symbol.hasInstance and cross-realm failures.md)).

**Q4. Where does assignment `obj.x = 1` put the value when a prototype accessor `set x` exists?**
A — not own `x`; calls prototype setter with `this` = `obj` (see delegation shadowing). If prototype has data `writable: false`, strict `obj.x = 1` throws `TypeError` (sloppy silent no-op) — no shadow created; `defineProperty` would still create own (→ [1.1](../1. Prototype delegation/1.1. Delegation mechanics lookup shadowing and dynamic updates.md)).

**Q5. `class` hoisted like `function`?**
A — no; TDZ like `let`. `new C()` before `class C {}` throws `ReferenceError` (→ [3.1](../3. Class syntax/3.1. Class basics declarations hoisting methods accessors and fields.md)). Function declarations hoist (→ [Variables §2.2](../../../04 Variables Scope and Closures/sections/2. Scope and lookup/2.2. Hoisting the reality creation phase not magic.md)).

**Q6. What does `super()` vs `super.method()` do?**
A — `super()` in derived constructor calls parent constructor allocating `this` (must be before touching `this` — ReferenceError otherwise). `super.method()` inside a method follows `[[HomeObject]].[[Prototype]]` lexically, not `this`'s chain (→ [3.2](../3. Class syntax/3.2. Extends and super chain wiring and obligations.md)).

**Q7. Private `#x` vs `_x`?**
A — `#x` is per-instance truly private, non-enumerable/serializable, brand-checked (`#x in obj` tests brand); `_x` is conventional string key, enumerable, mutable from anywhere (→ [3.3](../3. Class syntax/3.3. Private fields and methods brand checks and encapsulation.md)). Each class's `#x` is distinct even with same spelling; subclass `#x` is new slot, not inheritance.

**Q8. Static `#count` shared with subclass?**
A — no; static private is per-class brand. `class Parent { static #c=0; static inc(){this.#c++} }` `Child.inc()` with `this===Child` fails brand (TypeError) because `Child` lacks `Parent`'s static `#c` brand (→ [3.4](../3. Class syntax/3.4. Static members static blocks and class field order.md)).

**Q9. Why does `arr instanceof Array` fail across iframes?**
A — each realm has its own `Array` and `Array.prototype`; `arr` chain holds `realmA.Array.prototype`, not `realmB.Array.prototype` → walk misses. Use `Array.isArray(arr)` (realm-safe) or `Array.prototype.isPrototypeOf` still realm-fragile (→ [5.1](../5. Type checks and reflection/5.1. instanceof isPrototypeOf Symbol.hasInstance and cross-realm failures.md)).

**Q10. How does `Symbol.hasInstance` customize `instanceof`?**
A — `static [Symbol.hasInstance](v)` on the right-hand constructor overrides `instanceof`; `value instanceof C` calls `C[Symbol.hasInstance](value)`. `isPrototypeOf` ignores the hook (→ [5.1](../5. Type checks and reflection/5.1. instanceof isPrototypeOf Symbol.hasInstance and cross-realm failures.md)).

**Q11. Instance field `x = 1` on prototype?**
A — no; own per instance, enumerable. Prototype method `method()` is shared, non-enumerable (→ [3.1](../3. Class syntax/3.1. Class basics declarations hoisting methods accessors and fields.md)). Field `method = () => {}` shadows same-named prototype method (silent bug).

**Q12. `Object.assign(Proto, trait)` vs descriptor copy?**
A — `assign` reads trait getters (getter fires on Trait, value flattened) and writes data; descriptor copy `defineProperties(Target.prototype, getOwnPropertyDescriptors(trait))` preserves accessors and enumerability (→ [4.1](../4. Composition and mixins/4.1. Mixins and composition patterns.md)).

### 2) **What interviewers actually probe for**

- Tracing chain walks: `d instanceof C` after `C.prototype` replacement or `Object.setPrototypeOf`; they expect "current `C.prototype` not birth".
- `[[HomeObject]]` vs receiver: `super.method()` not following `this.__proto__` but method's home.
- Brand vs `instanceof`: `#field in obj` vs `instanceof` after prototype mutation; they expect brand persists while `instanceof` breaks.
- Class TDZ and `new` enforcement vs function hoisting.

### 3) **Grading guidance**

| Signal | Junior | Mid | Senior |
|--------|--------|-----|--------|
| Enumerates `new` steps and `prototype` vs `getPrototypeOf` | ✓ | ✓ | ✓ |
| Explains shadowing vs setter call and why `Object.assign` flattens accessors | — | ✓ | ✓ |
| Traces `extends` wiring two chains and `super()` pre-`this` TDZ | — | ✓ | ✓ |
| Contrasts private `in` brand vs `instanceof` cross-realm vs `Symbol.hasInstance` | — | — | ✓ |

Red flags: "`__proto__` is the prototype template", "`class` hoists", "`instanceof` tests birth class", "private `#x` is inherited", "`static` fields on prototype".
