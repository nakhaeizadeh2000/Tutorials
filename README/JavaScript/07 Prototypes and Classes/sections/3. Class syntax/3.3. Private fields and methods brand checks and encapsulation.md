## 3.3. Private fields and methods: brand checks and encapsulation

### 1) **#field is per-instance, name-based, and truly private**

**Definition** — syntax `#name` (ES2022) declares a *private* field/method/accessor/getter/setter. Private names are lexical to the class body: `#x` inside `class A` and `#x` inside `class B` are distinct storage slots. Private fields are per-instance (not on prototype), not enumerable, not string-accessible, and not reachable via `Object.keys`/`Reflect.ownKeys`/`getOwnPropertyDescriptor`. Private methods/accessors live on the class's brand slot table (not as prototype properties).

```js
class Counter {
  #n = 0; // per-instance private data
  #step = 1; // another
  get value() { return this.#n; }
  inc() { this.#n += this.#step; return this.#n; }
  setStep(n) { this.#step = n; }
  #double() { this.#n *= 2; } // private method
  doubleAndInc() { this.#double(); return this.inc(); }
}

const c1 = new Counter(), c2 = new Counter();
console.log(c1.inc(), c1.value); // 1 1
console.log(c2.value); // 0 — per-instance, not shared
console.log(Object.keys(c1)); // [] — private not enumerable or string-keyed
console.log(Object.getOwnPropertyNames(c1)); // [] — still invisible (private names are not string keys)
console.log(Reflect.ownKeys(c1)); // [] — same
console.log(c1["#n"]); // undefined — #name not accessible via bracket string
c2.setStep(10); console.log(c2.inc(), c1.value); // 10, 1 — isolated

// Private methods also brand-checked — can't be borrowed without brand
try { Counter.prototype.doubleAndInc.call({}); } catch (e) { console.log(e.name); } // TypeError — lacks brand

// Private fields must be declared in class body; assignment outside without declaration is SyntaxError
// class Bad { method() { this.#missing = 1; } } // SyntaxError — #missing not declared

// Subclass cannot reach parent's #field even with same name — distinct slots
class Base { #x = 1; get x() { return this.#x; } }
class Derived extends Base { #x = 2; get y() { return this.#x; } }
const d = new Derived();
console.log(d.x, d.y); // 1 2 — two distinct #x slots, no collision
```

- *Why not `WeakMap`*: `WeakMap` was the pre-ES2022 privacy pattern (`const store = new WeakMap(); store.set(this, data)`). It leaks via `store` reference if captured, isn't ergonomic, and isn't brand-checked. `#field` is engine-enforced privacy with brand table — safer and faster.

### 2) **Access outside the declaring class always throws — the brand check**

**Definition** — reading/writing/calling a private member requires that `this` (or the object after `#field in obj`) has the *brand* of the class that declared the name. Access on an unbranded object throws `TypeError: Cannot read private member from an object whose class did not declare it`. ` #field in obj` (ES2022, the `in` private brand check) tests brand without throwing or accessing.

```js
class Secret {
  #value = 42;
  static hasSecret(obj) { return #value in obj; } // brand check, no throw
  reveal(other) { return other.#value; } // throws if other lacks brand
}

const s = new Secret();
console.log(Secret.hasSecret(s)); // true — s branded as Secret
// { #value: 1 } as literal outside class would be SyntaxError — private names only inside class body; test plain object instead
console.log(Secret.hasSecret({})); // false — not branded
console.log(s instanceof Secret); // true
try { new Secret().reveal({}); } catch (e) { console.log(e.name); } // TypeError — brand check fails
try { new Secret().reveal(s); console.log("same brand ok"); } catch (e) { console.log(e.name); }
// Subclass instance is not branded as base's private? Actually subclass instance *does* carry base's private slots if constructed via base
class Sub extends Secret {}
const sub = new Sub();
console.log(Secret.hasSecret(sub)); // true — subclass instance has base brand (constructed via Base)

// Detached method loses this brand — classic function bug revisited (→ [Functions §3.1](../../../05 Functions Deep Dive/sections/3. this binding/3.1. Call-site rules default implicit explicit new and strict mode.md))
class Guard {
  #secret = 1;
  method() { return this.#secret; } // needs this brand == Guard
}
const g = new Guard();
const detached = g.method;
try { detached(); } catch (e) { console.log(e.name); } // TypeError — this is undefined/window, not Guard-branded
console.log(detached.call(g)); // 1 — explicit brand works

// Private brand vs instanceof: brand check is stricter than instanceof chain
console.log(g instanceof Guard); // true → brand also true; instanceof walks current Guard.prototype (→ [5.1](../5. Type checks and reflection/5.1. instanceof isPrototypeOf Symbol.hasInstance and cross-realm failures.md))
// Note: reassigning Guard.prototype after instances exist would break instanceof for earlier instances but brand persists — avoid prototype replacement after birth
console.log(Guard.hasSecret ? "hasSecret exists" : "no hasSecret"); // brand example would survive prototype mutation
```

- Modern guidance: expose `static hasBrand(obj) { return #field in obj; }` for duck checks without throwing. Never expose a private field via getter that returns a mutable object — copy or freeze.

### 3) **Private is not WeakMap and not enumerable — performance and serialization consequences**

Private fields are internal slots, not property descriptors. Consequences: `Object.keys`, `for-in`, spread, `Object.assign`, `JSON.stringify`, `Reflect.ownKeys` all skip them; `structuredClone` clones them if present on source instance (they're instance state). Descriptors work differently: you cannot `defineProperty` a `#field` like a string key; access is via lexical name only.

```js
class Account {
  #balance = 0;
  #id = Math.random();
  deposit(n) { this.#balance += n; }
  get balance() { return this.#balance; }
  toJSON() { return { balance: this.#balance }; } // must explicitly surface if you want JSON
}

const acc = new Account(); acc.deposit(10);
console.log(JSON.stringify(acc)); // {} — private skipped; toJSON not defined → still {}? Actually JSON calls toJSON if present
console.log(JSON.stringify(acc)); // {} — our toJSON returns balance but JSON.stringify calls it? Let's verify: with toJSON defined, JSON.stringify will use it
console.log(acc.toJSON()); // { balance: 10 }
console.log(JSON.stringify(acc, null, 2)); // {"balance":10} — via toJSON

const acc2 = new Account(); acc2.deposit(5);
console.log({ ...acc2 }); // {} — spread copies enumerable string own only (→ [Objects §4.1](../../../06 Objects in Depth/sections/4. Object utilities and copying/4.1. Assign merging shallow copy and fromEntries.md)) — private skipped
console.log(Object.assign({}, acc2)); // {} — same

// Where private wins over # prefix convention (_private): true encapsulation, no string access, no accidental serialization
// But private is not inherited by name — subclass redeclares distinct slot; if you need shared protected, use package-private WeakMap or public accessor
```

### 4) **Common confusion**

- "`#field` is just `_field` with syntactic sugar" — no; `#` is name-based, not string-based, truly unreachable outside class, not enumerable/serializable, distinct per class even with same spelling.
- "`#field in obj` throws if not private" — no; it returns boolean (no throw), even on null/undefined? `null`/`undefined` throws TypeError on `in` generally.
- "Private methods are on prototype" — accessible only with brand, not via `obj["#method"]`; `getOwnPropertyDescriptor` on prototype won't find `#method`.
- "Subclass can access parent's `#field` with `super.#x`" — no; `super` doesn't grant private access across lexical class bodies; each class only sees its own `#` names.

### 5) **Performance note**

Private fields are stored as internal slots indexed by class — faster than `WeakMap` and avoids per-instance `defineProperty` costs. They don't participate in hidden-class transitions for string keys, so they don't pollute inline caches for public property reads. As ever, [measure](../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md).

### 6) **Mentor note**

Have trainees write a class with `#balance` and `static hasBalance(obj) { return #balance in obj; }`, then try `obj.#balance` from outside and detached method call — first is SyntaxError, second is brand TypeError. If they distinguish the two errors, encapsulation is solid. In review, flag any private field returned as mutable object (e.g., `get data() { return this.#data; }` where `#data` is object) — suggest defensive copy.
