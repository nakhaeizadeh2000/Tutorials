## 2.1. The new operator: prototype property, new.target, and return override

### 1) **new F() allocates, links, calls, then chooses the return**

**Definition** — `new C(...args)` does four steps per ECMA-262 `Construct` (`new.target` is `C`): 1) allocate plain object with `[[Prototype]] = C.prototype` (via `OrdinaryCreateFromConstructor`), 2) call `C` with `this` = that object and `new.target` bound, 3) if constructor returns an *object* (including array/function/proxy), return that object; otherwise return `this`. If `C` is a class, calling without `new` throws `TypeError` (class has internal `[[IsClassConstructor]]`).

```js
// Step trace with observable prototype link
function Counter(start) { this.n = start; }
Counter.prototype.inc = function () { this.n += 1; return this.n; };

const c = new Counter(5);
console.log(Object.getPrototypeOf(c) === Counter.prototype); // true — step 1
console.log(c.n); // 5 — step 2 assigned this.n
console.log(c.inc()); // 6 — delegated to prototype
console.log(c instanceof Counter); // true — walks prototype at call time (→ [5.1](../5. Type checks and reflection/5.1. instanceof isPrototypeOf Symbol.hasInstance and cross-realm failures.md))

// Return override: object return replaces this; primitive return is ignored
function MaybeObject(flag) {
  this.a = 1;
  if (flag) return { hijacked: true }; // object wins
  if (!flag) return 42; // primitive ignored
}
console.log(new MaybeObject(true)); // { hijacked: true } — this discarded
console.log(new MaybeObject(false)); // MaybeObject { a: 1 } — primitive ignored, this returned

// Class vs function constructor: class must be new-invoked, function may be called with or without new (behavior differs)
class Klass {
  constructor(x) { this.x = x; }
  method() { return this.x; }
}
console.log(typeof Klass); // function — but with IsClassConstructor internal slot
try { Klass(1); } catch (e) { console.log(e.name); } // TypeError — class constructor must be invoked with new
console.log(typeof new Klass(1)); // object

// Ordinary function called without new: this is undefined (strict) or globalThis (sloppy) — bug source
function SloppyCtor(x) { this.x = x; } // no "use strict" header → sloppy when called bare
const bare = SloppyCtor(10); // without new, this === globalThis → global pollution
console.log(bare); // undefined — no new, no object return, result is undefined
console.log(globalThis.x); // 10 — leaked to global (strict mode prevents this — → [Variables §1.2](../../../04 Variables Scope and Closures/sections/1. Declarations and bindings/1.2. Temporal dead zone why early access throws.md) for strict defaults; classes are always strict)
delete globalThis.x; // cleanup
```

- Modern guidance: prefer `class` for shared-behavior types — it enforces `new`, is always strict, and throws early. Use function constructors only when interoperating with legacy or when returning a different object (factory disguised as constructor) is required — document that exception heavily.

### 2) **.prototype is the template, not the function's own prototype**

Three distinct prototype-related values per constructor `F`:

| Expression | What it is | Used for |
|------------|------------|----------|
| `F.prototype` | plain object serving as template for `new F()` instances' `[[Prototype]]` | instance chain: `Object.getPrototypeOf(new F()) === F.prototype` |
| `Object.getPrototypeOf(F)` | `F`'s own `[[Prototype]]` (usually `Function.prototype`) | function-object delegation (methods like `call`/`bind`) |
| `Object.getPrototypeOf(new F())` | instance's `[[Prototype]]` | delegation for instance methods |

```js
function Dog(name) { this.name = name; }
Dog.prototype.bark = function () { return `${this.name} woofs`; };

const d = new Dog("rex");
console.log(Object.getPrototypeOf(d) === Dog.prototype); // true — instance delegates to Dog.prototype
console.log(Dog.prototype === d.__proto__); // true-ish (accessor)
console.log(Object.getPrototypeOf(Dog) === Function.prototype); // true — Dog itself is a function object
console.log(Object.getPrototypeOf(Dog.prototype) === Object.prototype); // true — template itself delegates to Object.prototype

// Reassigning F.prototype after instances exist breaks instanceof for earlier instances (live check)
const oldProto = Dog.prototype;
Dog.prototype = { howl() { return "howl"; } };
const d2 = new Dog("bob");
console.log(Object.getPrototypeOf(d) === oldProto); // true — d still linked to old
console.log(Object.getPrototypeOf(d2) === Dog.prototype); // true — d2 linked to new
console.log(d instanceof Dog); // false — instanceof walks current Dog.prototype, not old → fails for earlier instances
console.log(d2 instanceof Dog); // true
console.log(Dog.prototype.howl.call(d)); // TypeError? No — deliberate: Dog.prototype as object has howl, calling with d works but semantically disconnected

// Hence never replace .prototype after first new; mutate the existing object or create a fresh constructor
Dog.prototype = oldProto; // restore for next demos

// Arrow functions have no .prototype (and no [[Construct]]) — cannot be new-target
const Arrow = () => {};
console.log(Arrow.prototype); // undefined
try { new Arrow(); } catch (e) { console.log(e.name); } // TypeError — not a constructor
```

### 3) **new.target reveals the actual constructor called**

**Definition** — inside any function invoked via `new` (or via `super()` in derived class), `new.target` is the constructor that was *directly* `new`-invoked; inside a plain call it's `undefined`. It enables abstract bases, enforced `new`, and correct subclass `instanceof` wiring without relying on `this.constructor`.

```js
// Abstract base via new.target
function Base() {
  if (new.target === Base) throw new TypeError("Base is abstract — extend it");
  this.kind = "base";
}
function Derived() { Base.call(this); this.extra = 1; }
Object.setPrototypeOf(Derived.prototype, Base.prototype);
Object.setPrototypeOf(Derived, Base); // static chain too
const ok = new Derived();
console.log(ok.kind, ok.extra); // base 1
try { new Base(); } catch (e) { console.log(e.name); } // TypeError

// Enforcing new without class (alternative to class's automatic enforcement)
function StrictCtor(x) {
  if (!new.target) throw new TypeError("call with new");
  this.x = x;
}
console.log(new StrictCtor(1).x); // 1
try { StrictCtor(1); } catch (e) { console.log(e.name); } // TypeError — caught

// Subclass sees original new.target, not intermediate
class Parent { constructor() { console.log("Parent new.target", new.target.name); } }
class Child extends Parent { constructor() { super(); console.log("Child new.target", new.target.name); } }
new Child(); // Parent new.target === Child, Child new.target === Child (both see Child)

// new.target also distinguishes function called via new vs factory
function Flex(...args) {
  if (new.target) { this.args = args; } else { return new Flex(...args); }
}
console.log(Flex(1, 2).args); // [1,2] — bare call delegated to new
console.log(new Flex(3).args); // [3]
```

### 4) **Common confusion**

- "`F.prototype` is `F`'s prototype" — no; `F.prototype` is the template for instances; `Object.getPrototypeOf(F)` is `F`'s own delegation.
- "Constructor's return is always `this`" — only when return is non-object; object return hijacks.
- "Arrow can be a constructor if you set `.prototype`" — no; arrows lack `[[Construct]]` entirely, `new` always throws.
- "`new C` without `()` is different" — `new C` and `new C()` are equivalent; `new C` without args calls with zero args.

### 5) **Performance note**

`new` allocation is V8 fast-path when `C.prototype` is stable and constructor doesn't return an object. Returning a different object per call forces megamorphic re-allocation. Keeping `C.prototype` shape stable (no post-birth replacement) keeps `instanceof` and inline caches monomorphic. As ever, [measure](../../../01 Fundamentals and Mental Model/sections/2. How JavaScript executes/2.1. Parse bytecode JIT pipeline and single-threaded execution.md).

### 6) **Mentor note**

Ask trainees to enumerate the four steps of `new C(args)` and predict what `new MaybeObject(true/false)` returns — then diagram why `Dog.prototype` replacement breaks `instanceof` for earlier instances. If they name `new.target` as the guard for abstract bases, the constructor model is solid. In review, flag any function `Ctor` called bare without `new` — suggest `class` or a `!new.target` guard.
