# 2.2. Authoring a load hook

Writing the `load` stage: source shapes, envelope discipline, and where text transforms end and compiler transforms begin. Junior read: fetch via `nextLoad`, decode, replace, return. Expert read: the Buffer trap, the envelope-spread rule, and why AST transforms belong to ts-node options rather than string surgery.

## 1) Source arrives in many shapes

### 1) **Definition** (the source union)

`nextLoad(url, context)` returns `{ source, format, ... }` where `source` may be a `string`, `ArrayBuffer`, `TypedArray` (`Uint8Array`), or `null`/`undefined` (formats carrying no source: builtins, addons). Node's accepted-types table lists them all — and the *actual* shape varies by Node major, format, and upstream link. Text manipulation demands a string; the hook must *convert*, never assume.

### What problem it solves (history)

Early load hooks assumed strings (the documented happy path), worked on their author's Node, and crashed on `result.source.replace is not a function` one major later when the default loader started handing Buffers for the same URLs. The union type exists because I/O layers disagree about representation; the decode-first discipline exists because hooks sit on top of all of them.

### Modern guidance

Decode defensively at every hook entry: `null` → delegate immediately (nothing to transform); `string` → use directly; otherwise `Buffer.from(source).toString('utf8')`. Return a `string` (universally accepted for text formats — normalization is safe downstream). Never mutate in place (Buffers may be shared/cached — build the new string, spread the envelope, return fresh).

### Runnable example (good — the trap, then the fix, both verified)

```javascript
// bad first attempt: assumes string (works nowhere on this floor)
export async function load(url, context, nextLoad) {
  const result = await nextLoad(url, context);
  if (url.endsWith('/tagged.mjs') && typeof result.source === 'string') {
    return { ...result, source: result.source.replaceAll('__BUILD_TAG__', 'v26.10-docs') };
  }
  return result;
}
// diagnostic probe reveals why it silently no-ops:
// [hook:load] file:///tmp/tsprobe/hks/tagged.mjs source-type=object ctor=Buffer
```

```javascript
// good: decode-first, null-safe, envelope-preserving
export async function load(url, context, nextLoad) {
  const result = await nextLoad(url, context);
  if (!url.endsWith('/tagged.mjs') || result.source == null) return result;
  const text = typeof result.source === 'string' ? result.source : Buffer.from(result.source).toString('utf8');
  return { ...result, source: text.replaceAll('__BUILD_TAG__', 'v26.10-docs') };
}
```

```bash
node --loader ./hks/transform.mjs ./hks/tagged.mjs
# tag: v26.10-docs
```

Verified on Node v20.20.2: the string-assuming version printed the raw token (guard skipped — silent no-op, the worst failure mode); the diagnostic line exposed `ctor=Buffer`; the decode-first version prints the replacement. This session's own probe authored the bug, diagnosed it, and fixed it — the sequence preserved deliberately as the teaching path.

### Common confusion

- **"source is always a string for text formats"** — the contract promises the *union*, and implementations choose per version (v20 default load hands Buffers here; other majors/threads differ). Code to the union, test on the floor, re-verify per major — the shape is environmental, not logical.
- **"null source means error"** — null/undefined source is *valid* for sourceless formats (builtin/addon passthrough). Treating null as failure breaks builtin imports passing through your hook — delegate nulls, transform texts, never conflate the two.

### Performance note

Decode cost per module: one Buffer→string conversion for non-string sources (microseconds, once per load — cached thereafter by the module system). The alternative (assuming strings) costs a silent no-op per module — infinite cost/benefit ratio against. Decode-first is free correctness; assumption is expensive silence.

### Mentor note

Require the diagnostic line (`source-type=` + constructor name) in every load hook during development — it makes representation visible before it bites. Mentees who log shapes first debug transforms in minutes; mentees who assume strings debug phantoms for hours. Representation awareness is the load-stage equivalent of `--showConfig` evidence discipline.

## 2) Transform the text, keep the envelope

### 2) **Definition** (the spread rule)

A load hook returns `{ ...result, source: newText }` — every field of the downstream result preserved (`format`, caching hints, metadata), only `source` replaced. Changing `format` declares a new module kind (`.ts`→compiled JS keeps its negotiated format; only genuinely re-typed sources rename it). The envelope is the chain's shared state; the source is your property.

### What problem it solves (history)

Early transforms rebuilt return objects by hand (`{ format: 'module', source }`), dropping fields downstream links (and Node itself) depended on — cache keys, import attributes, shortCircuit propagation — producing order-dependent breakage that vanished when flags were reordered. The spread rule (pass through everything, change one thing) made transforms order-tolerant by construction.

### Modern guidance

Spread-then-replace always; set `format` only when re-typing (yaml→module, css→module — the documented use case); set `shortCircuit: true` only when *not* calling `nextLoad` (self-sourced modules, like the docs' `special-module` example). Transform idempotently where possible (double-application harmless — hooks re-run on cache misses and HMR paths); keep transforms pure functions of source text (no I/O, no clocks — determinism makes caching sound).

### Runnable example (good — token replacement, envelope intact)

```javascript
// hks/transform.mjs (verified): only source changes, format/caching flow through
return { ...result, source: text.replaceAll('__BUILD_TAG__', 'v26.10-docs') };
```

```bash
node --loader ./hks/transform.mjs ./hks/tagged.mjs
# tag: v26.10-docs
```

The untouched `tagged.mjs` on disk still contains `__BUILD_TAG__` (verify: `grep` it) — transformation is load-time, never write-time. Every process boot re-applies; editors and checkers see the original. That ephemerality is the feature (build metadata injected without dirtying sources) and the warning (never transform *semantics* you can't see in the file).

### Runnable example (bad — the rebuilt envelope)

```javascript
// bad: hand-built return drops the chain's shared state
return { format: 'module', source: newText };
// caching hints gone, import attributes gone, downstream metadata gone —
// works in isolation, breaks in composition (order-dependent, untestable alone)
```

Why it hurts: composition failure (the exact links the chain exists to compose — ts-node's hints, tracer metadata — silently dropped), order dependence (works solo, breaks chained — the worst testability profile), and silent cache corruption (wrong cache keys → stale modules served fresh). Fix: spread first (`...result`), change one field, justify any second.

### Common confusion

- **"format must be re-declared"** — only when *changing* kinds. Re-declaring the same format is harmless but noisy; dropping a *changed* format (returning TS source as `module`) is a evaluate-time `SyntaxError` with no chain evidence. Rule: touch format iff you changed what the bytes *are*.
- **"transforms persist"** — load transforms evaporate with the process (module cache is in-memory; disk artifacts untouched). Persistent transformation is *emission* (tsc, bundlers — Domain 06) — confusing the two produces "fixed it in the hook, reverted on reboot" incidents.

### Performance note

String replace per module (linear in file size, once per load) — negligible against parse/compile. Regex transforms on hot paths (thousands of modules) deserve one measurement (`console.time` around the replace during development) — pathological patterns (catastrophic backtracking on generated code) are the only realistic cost, and measurement finds them in seconds.

### Mentor note

Review load hooks with two questions: "what changes?" (exactly one field — source) and "what proves the rest flows through?" (the spread, first token of the return). Any second changed field needs a paragraph of justification; any missing spread fails review outright. Envelope discipline is to load hooks what `shortCircuit` discipline is to resolve.

## 3) Compile-stage transforms live in ts-node options

### 3) **Definition** (text vs AST transformation)

Load hooks transform *text* (string in, string out — tokens, banners, polyfill prefixes). Compiler transforms operate on the *AST* (ts-node `transformers` programs, `transpiler` engines like SWC/esbuild — type-directed rewrites, decorator lowering, import elision). Text is universal and shallow; AST is powerful and compiler-bound. Different tools, different stages, composed deliberately — never substituted casually.

### What problem it solves (history)

Token replacement can't do type-directed work (strip this decorator, elide that import, rewrite by type query) — attempts produce regexes that break on formatting. Compiler transformers can — at the cost of compiler API surface (program instances, transformer factories, version coupling). ts-node exposes both doors: `transpiler` for engine swaps (SWC verified in [01/2.1](<../../../01 Execution Foundations and Mental Model/sections/2. Modes and configuration/2.1. Transpile-only versus full typechecking.md>): 0.427s → 0.228s), `transformers` for programmatic AST plugins, load hooks for everything textual.

### Modern guidance

Textual need (build tags, env injection, banner comments, `foo`→`bar` rewrites) → load hook (this leaf, verified). Engine need (startup speed) → `transpiler`/`--swc` (measured ladder decides). AST need (custom decorator semantics, macro expansion, import surgery) → ts-node `transformers` (programmatic API + `tsconfig` `"ts-node"` object — documented in ts-node API docs, linked not re-taught). Never regex what the AST owns (decorators, types, imports) — and never spin the compiler for what a string replace does.

### Runnable example (good — choosing by need)

```bash
# textual (verified this session): token → release string, load hook, microseconds
node --loader ./hks/transform.mjs ./hks/tagged.mjs
# tag: v26.10-docs

# engine (verified S1): same tree, faster transpiler, --swc flag
./node_modules/.bin/ts-node --swc --project big/tsconfig.json ./big/src/main.ts
# real 0m0.228s (vs 0.427s TypeScript transpile)

# AST (documented, ts-node API docs): transformers: [myTransformerProgram]
# — programmatic registration only; version-coupled to the TS compiler API;
# justified iff the rewrite needs type information (decorators, elision)
```

### Runnable example (bad — regexing the AST's job)

```javascript
// bad: stripping decorators with a regular expression in a load hook
source.replace(/@\w+\([^)]*\)\s*/g, '');
// breaks on: multiline decorators, nested parens, decorator factories with
// objects, commented-out code resembling decorators — i.e., real codebases
```

Why it hurts: silent semantic corruption (valid programs rewritten into different valid programs — no error, wrong behavior), formatter-dependence (prettier upgrades change what matches), and untestability (the failure needs the exact source shape that breaks the pattern). Fix: compiler transformer (parses, decides by AST node, emits) — the tool that understands code as code.

### Common confusion

- **"ts-node transformers work in transpile-only"** — transformers are *checker-program* plugins (need type information → need the full program → full mode). Transpile-only (isolated modules, no program) cannot run them — another entry in the mode trade-off ledger from [01/2.1](<../../../01 Execution Foundations and Mental Model/sections/2. Modes and configuration/2.1. Transpile-only versus full typechecking.md>). AST power costs the checker; price it knowingly.
- **"SWC/esbuild replace transformers"** — engines replace the *transpiler* (speed), not the *transform* (custom semantics). `--swc` plus a custom decorator lowering is a contradiction (SWC doesn't run TS transformer plugins) — engine choice and transform choice are independent axes that occasionally collide; the collision is documented, not discovered, by reading both option pages first.

### Performance note

Text transform: linear, once per load, negligible. Engine swap: measured ladder (S1 numbers quoted above — re-measure per repo). AST transformer: program-construction cost (full typecheck — the mode decision from [01/2.1](<../../../01 Execution Foundations and Mental Model/sections/2. Modes and configuration/2.1. Transpile-only versus full typechecking.md>) dominates). Three mechanisms, three cost profiles, one selection rule: cheapest mechanism that understands the input (text < engine < AST).

### Mentor note

Teach transform selection as a ladder question: "does the rewrite need to *parse*?" (no → string; yes → "does it need *types*?" no → engine/syntactic plugin; yes → full transformer + full mode). Two questions, three destinations, zero regex-on-AST incidents. The ladder belongs on the team wiki next to the runner matrix from [01/5.1](<../../../01 Execution Foundations and Mental Model/sections/5. Interview questions and answers/5.1. Common interview QA execution foundations.md>).
