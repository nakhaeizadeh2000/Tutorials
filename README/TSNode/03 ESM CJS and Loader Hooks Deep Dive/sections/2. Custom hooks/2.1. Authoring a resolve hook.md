# 2.1. Authoring a resolve hook

Writing the `resolve` stage: match, map, delegate-or-end — plus the chain-violation guardrail, the trace discipline, and the eager-link ordering it all serves. Junior read: copy the shape, fill the mapping. Expert read: why the guardrail error is good news, and what "delegate everything you don't own" costs you (nothing) versus saves you (everything).

## 1) Match, map, delegate-or-end

### 1) **Definition** (the three-line contract)

A resolve hook inspects each specifier, rewrites the ones it owns into URLs, and delegates the rest: `if (mine) return { url, shortCircuit: true }; return nextResolve(specifier, context)`. Modified delegation (`nextResolve(rewritten, context)`) routes through downstream resolvers instead of terminating — chaining rather than ending. Three lines, total contract, no fourth option.

### What problem it solves (history)

Before user hooks, specifier shapes were fixed by Node (relative, bare, builtin — nothing else). Aliases, virtual modules, extension mappings, and origin redirects each needed platform support; now each needs three lines. The contract's rigidity (delegate or terminate, nothing between) is what makes independently-authored links compose without coordination.

### Modern guidance

Match narrowly (prefix, exact set, or tested regex — never "everything except node:"), map to absolute `file:` URLs (relative URLs re-enter resolution ambiguously), delegate the remainder untouched (same specifier, same context — no "helpful" normalization). Rewritten-but-delegated specifiers (`nextResolve(mapped)`) suit mappings the default resolver finishes (extension completion, directory indexes); `shortCircuit` suits terminal mappings (alias → exact file, verified below).

### Runnable example (good — the recipe's hook, annotated)

```javascript
// hks/hooks.mjs — the mapping hook behind every probe in this domain
import { pathToFileURL, fileURLToPath } from 'node:url';
import path from 'node:path';
const LIB = fileURLToPath(new URL('./src/lib/', import.meta.url)); // anchor: hook's own dir
export async function resolve(specifier, context, nextResolve) {
  if (specifier.startsWith('@app/')) {                              // 1. match narrowly
    const file = path.join(LIB, specifier.slice('@app/'.length) + '.ts'); // 2. map absolutely
    console.error(`[hook:resolve] ${specifier} -> ${file}`);        // 3. trace the mapping
    return { url: pathToFileURL(file).href, shortCircuit: true };   // 4. terminate deliberately
  }
  return nextResolve(specifier, context);                           // 5. delegate the rest
}
```

```bash
TS_NODE_PROJECT=hks/tsconfig.json node --loader ts-node/esm --loader ./hks/hooks.mjs ./hks/src/main.ts
# [hook:resolve] @app/util -> /tmp/tsprobe/hks/src/lib/util.ts
# hks: hooked-paths
```

Verified: match (prefix gate), map (absolute file URL with anchored base — immune to CWD), trace (one stderr line per mapping), terminate (`shortCircuit`), delegate (everything else flows to ts-node then default). Anchor the base to `import.meta.url`, never `process.cwd()` — hooks run under whatever CWD launched the process.

### Common confusion

- **"return the mapped specifier string"** — resolve returns `{ url }` (an object with a URL), not a string. Returning a bare string fails the chain's shape check — the contract is structural, and structures have field names.
- **"map to a relative path"** — relative URLs resolve against murky bases inside the chain (parentURL semantics per link). Absolute `file:` URLs mean exactly one file — the debuggability difference between a trace that names the target and one that gestures at it.

### Performance note

Prefix-match cost per specifier: one `startsWith` (nanoseconds) for the 99% delegated — the hook is free for everything it doesn't own. Mapping cost: string concat + `pathToFileURL` (microseconds, no I/O — mapping without probing keeps resolve I/O-free, per [1.1](<../1. Hook pipeline/1.1. resolve and load the two-stage pipeline.md>)). Never `existsSync` in resolve (that's load's job, or nobody's — probe lazily or not at all).

### Mentor note

Code-review every resolve hook against the five numbered lines above (match/map/trace/terminate/delegate). Missing trace → unobservable in production; missing delegation → swallows the ecosystem (`node:` imports dying inside an app hook is the classic symptom); unanchored base → CWD-dependent behavior. Five lines, five checks, two minutes.

## 2) Never break the chain by accident

### 2) **Definition** (the `ERR_LOADER_CHAIN_INCOMPLETE` guardrail)

A resolve hook returning a value without calling `nextResolve` and without `shortCircuit: true` throws `ERR_LOADER_CHAIN_INCOMPLETE` — Node refusing to guess whether termination was intended. The error message even prescribes the fix ("If this is intentional, include `shortCircuit: true`"). The chain treats ambiguity as failure, loudly, at boot — the kindest possible moment.

### What problem it solves (history)

Silent chain breaks (a link returning early, downstream links starved, modules loading half-customized) were the original loader debugging nightmare — behavior varying with flag order, no error anywhere. The guardrail (hard error on ambiguous return) converted an entire class of silent corruption into a loud, self-diagnosing boot failure. Loaders got *stricter* so applications could be *looser*.

### Modern guidance

Read the guardrail error as an instruction, not an incident: add `shortCircuit: true` (meant it) or `return nextResolve(...)` (didn't). In review, grep hook files for `return {` without adjacent `shortCircuit` — each hit is either a bug or a missing declaration. Test hooks with a non-matching specifier (must delegate: run an entry importing only `node:` + relative and assert zero interference) alongside matching ones.

### Runnable example (good — the violation, reproduced verbatim)

```javascript
// bad: URL without shortCircuit (chain violation)
export async function resolve(specifier, context, nextResolve) {
  if (specifier.startsWith('@app/')) {
    return { url: pathToFileURL('/tmp/tsprobe/hks/src/lib/util.ts').href };
  }
  return nextResolve(specifier, context);
}
```

```bash
TS_NODE_PROJECT=hks/tsconfig.json node --loader ts-node/esm --loader ./hks/nosc.mjs ./hks/src/main.ts
# Error: "./hks/nosc.mjs 'resolve'" did not call the next hook in its chain
# and did not explicitly signal a short circuit. If this is intentional,
# include `shortCircuit: true` in the hook's return.
#   code: 'ERR_LOADER_CHAIN_INCOMPLETE'
```

Verified verbatim on Node v20.20.2 (probe file removed after): the error names the hook file, the stage, the omission, *and* the remedy — four facts, zero debugging. This is the guardrail working exactly as designed; the lesson is to welcome it, never to work around it (there is no workaround — that *is* the point).

### Common confusion

- **"the error means my URL is wrong"** — the URL is never evaluated (the chain aborts before using it). Debugging the mapping when the error is structural wastes the cycle the message tried to save — read to the `code:` line first, always.
- **"shortCircuit: false silences it"** — `false` is the default (omitted ≡ false); only `true` declares termination, only delegation continues the chain. There is no third state and no escape hatch — by platform design.

### Performance note

Zero runtime dimension (boot-time structural validation, once per link per stage). The cost axis is authoring: one `shortCircuit: true` per terminal mapping versus one `ERR_LOADER_CHAIN_INCOMPLETE` per omission — the guardrail prices the declaration at three words and the omission at a failed boot. Cheap either way; declared is cheaper.

### Mentor note

Celebrate this error with mentees the first time it fires: "the platform just caught a bug your tests hadn't reached." Engineers who welcome guardrail errors write bolder hooks; engineers who fear them write defensive mush around a three-line contract. The error message is documentation — quote it in the team's hook guide verbatim.

## 3) Log the mapping, not the world

### 3) **Definition** (targeted hook tracing)

Resolve hooks log *their mappings* (one stderr line per rewritten specifier: original → target) and stay silent for delegated traffic. Full-chain resolve logging (every specifier, every link) is a development-only firehose; targeted traces are production-tolerable evidence that bug reports can quote.

### What problem it solves (history)

Untraced hooks fail opaquely ("the alias doesn't work" — which link? which mapping? did it even run?), while fully-traced hooks drown the evidence (thousands of `node:`/relative resolutions per boot burying the three mapped lines). Targeted tracing splits the difference: silence proves delegation, lines prove mapping — the absence *and* presence both informative.

### Modern guidance

`console.error` (stderr — never stdout, which belongs to the program) with a namespaced prefix (`[hook:resolve]`, `[hook:load]` — greppable, attributable per link), gated by env for verbosity (`if (process.env.HOOK_TRACE) console.error(...)` — full delegation logging behind the flag, mappings always). Every "my hook doesn't fire" report must include the trace output; no trace lines for a specifier means the link never saw it (order problem — [1.1](<../1. Hook pipeline/1.1. resolve and load the two-stage pipeline.md>) part 3), not that mapping failed.

### Runnable example (good — the trace that diagnosed ordering)

```bash
# working order: trace present, output follows
TS_NODE_PROJECT=hks/tsconfig.json node --loader ts-node/esm --loader ./hks/hooks.mjs ./hks/src/main.ts
# [hook:resolve] @app/util -> /tmp/tsprobe/hks/src/lib/util.ts
# hks: hooked-paths

# broken order: NO trace line — the mapper never saw the specifier
TS_NODE_PROJECT=hks/tsconfig.json node --loader ./hks/hooks.mjs --loader ts-node/esm ./hks/src/main.ts
# Error: Cannot find package '@app/util' ...
```

Verified both: the trace's *presence* proves mapping; its *absence* proves the specifier died upstream (eager ts-node link first). The debugging conversation becomes "show me the trace" instead of "describe your flags" — evidence over narrative, again.

### Common confusion

- **"`console.log` in hooks is fine"** — stdout interleaves with program output (and breaks protocols piping stdout: JSON-RPC test reporters, `--experimental-strip-types` consumers). stderr is the diagnostics channel by Unix contract — hooks are diagnostics, so stderr, always.
- **"remove traces before committing"** — remove *verbose* traces; keep *mapping* traces (one line per rewrite, stderr, namespaced). Committed mapping traces are the cheapest production observability hooks have — deleting them saves bytes and costs nights.

### Performance note

One stderr write per mapped import (microseconds, unbuffered) — invisible against compilation. Delegation silence costs nothing. Full-trace mode (`HOOK_TRACE` dumping every specifier) costs readability, not speed — gate it behind env and default it off outside development.

### Mentor note

Make "paste the hook trace" the first response to every loader bug report — before asking about configs, versions, or flags. Mentees learn within a week that traces answer 80% of loader questions unaided; the habit compounds across every hook they will ever write or debug.
