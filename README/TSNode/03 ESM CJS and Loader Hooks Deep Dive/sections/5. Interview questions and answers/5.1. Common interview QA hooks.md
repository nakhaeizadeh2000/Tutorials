# 5.1. Common interview QA: hooks

Canonical answers for the three hooks questions every loaders-adjacent interview asks, plus rapid-fire drills. Junior read: memorize the autopsy sentences. Expert read: each answer contains a *verified reproduction* (both orders, both families, all three closings) — mechanism first, output as confirmation.

## 1) "Alias resolves in tsc but not at runtime" — autopsy it

### 1) **Definition** (the three-closings screen)

Green checker, red boot on an aliased import — screens for the two-resolver model plus the closings menu: hires name the split (checker reads `paths`, Node doesn't) *and* price all three closings (bridge package, erasure to relatives, custom resolve-hook recipe) with the trade that selects among them. Single-closing answers pass the mechanism, fail the judgment.

### What problem it solves (hiring signal)

Alias incidents are the most common TypeScript-on-Node production shape (green CI vouching for unrunnable code), and the fix choice is architectural (dependency vs spelling vs authorship). Candidates reciting one fix will misapply it where another fits; candidates pricing three will match fix to context — the question predicts operational judgment, not recall.

### Modern guidance

Answer in pipeline order with the verified triple: reproduce (`Cannot find module '@app/util'` under the hook — evidence), explain (two resolvers, one mapping — mechanism), close by context (many alias families → `tsconfig-paths` bridge; unjustified alias → erase to relatives; locked installs/hook shop → [3.1](<../3. Runtime recipes/3.1. The runtime paths recipe.md>) recipe — judgment). ESM-checker footnote included unprompted (explicit-extension mappings — the `TS2307` even experts miss): precision signals.

### Runnable example (good — the triple, quoted)

```bash
./node_modules/.bin/tsc --noEmit --project hks/tsconfig.json && echo CHECK-OK
# CHECK-OK
./node_modules/.bin/ts-node --transpile-only --project hks/tsconfig.json ./hks/src/main.ts
# Error: Cannot find module '@app/util'   (no runtime half — any closing absent)
TS_NODE_PROJECT=hks/tsconfig.json node --loader ts-node/esm --loader ./hks/hooks.mjs ./hks/src/main.ts
# [hook:resolve] @app/util -> /tmp/tsprobe/hks/src/lib/util.ts
# hks: hooked-paths                        (recipe closing — verified)
```

(CJS-bridge twin verified in [02/3.1](<../../../02 Configuration and tsconfig for Execution/sections/3. Paths runtime/3.1. paths and baseUrl that run.md>): `PATHS-CHECK-OK` → `MODULE_NOT_FOUND` → `pw: paths` via `-r tsconfig-paths/register`.) A hire narrates each line's *verdict* before running; the interviewer scores prediction, not output. Follow-up ("workers spawn bare?"): preload via `NODE_OPTIONS=--import` or erase — per-door wiring leaks where processes multiply.

### Common confusion (in candidates)

- **"add the paths to more configs"** — red flag: the mapping exists (checker proves it); runtime support is missing. More mapping fixes nothing — the candidate debugs the informed resolver instead of the ignorant one.
- **"the hook didn't run"** — yellow flag without the trace question: strong candidates ask "what does the `[hook:resolve]` trace show?" before theorizing (absent trace = order/scope; present trace + wrong output = mapping). Evidence-first is itself a hiring signal.

### Performance note

All three closings cost microseconds per import (pattern match, relative probe, prefix join) — performance never selects among them. Candidates citing speed here reveal premature-optimization instincts; the priced answer is surface-vs-spelling-vs-authorship (package, relatives, recipe). Economics, not benchmarks — again.

### Mentor note

Mock with the three commands unrun, demanding verdicts first ("green? red? which error?"). Graduates predict 3/3; near-misses get the stage-ordering remedial ([1.1](<../1. Hook pipeline/1.1. resolve and load the two-stage pipeline.md>)). The predictions *are* the model — outputs merely confirm it.

## 2) "Reversed loader flags break it" — explain the chain

### 2) **Definition** (the order-as-semantics screen)

Same files, same flags, reversed sequence: one prints, one throws `Cannot find package` — screens for chain-order reasoning: hires derive last-listed-runs-first from the pair (LIFO nesting), name the eager link (ts-node/esm resolving instead of delegating), and prescribe the pin (comment + gate + no-tidy rule). Intuition-answerers ("list mine first") fail the pair they could have derived.

### What problem it solves (hiring signal)

Flag order is load-bearing configuration disguised as cosmetic arrangement — the exact class of knowledge that separates engineers who've *operated* loaders from those who've *read about* them. The question is ungoogleable in the interview moment (no docs open, ten seconds); the answer must be derived from the model, which is precisely what it tests.

### Modern guidance

Answer by derivation, not recitation: "the mapper must see the original specifier; ts-node's resolve attempts it eagerly instead of delegating; therefore the mapper runs first; with `--loader` flags last-listed runs first (verified pair); therefore list the compiler first, mappers after, and pin it with a comment." Each clause checkable, the chain auditable — and the version caveat volunteered (v20 derivation; re-verify per major).

### Runnable example (good — the pair, quoted with trace)

```bash
# mapper runs first (listed last): trace present, output follows
TS_NODE_PROJECT=hks/tsconfig.json node --loader ts-node/esm --loader ./hks/hooks.mjs ./hks/src/main.ts
# [hook:resolve] @app/util -> /tmp/tsprobe/hks/src/lib/util.ts
# hks: hooked-paths

# mapper runs last (listed first): NO trace — died upstream of the mapper
TS_NODE_PROJECT=hks/tsconfig.json node --loader ./hks/hooks.mjs --loader ts-node/esm ./hks/src/main.ts
# Error: Cannot find package '@app/util' imported from /tmp/tsprobe/hks/src/main.ts
```

Verified both (this session): the trace's presence/absence *is* the order evidence — the candidate who cites it answers from data; the candidate describing flag aesthetics answers from hope. Follow-up ("how do you prevent regression?"): order comment + gate stage 30 + never-tidy list ([4.1](<../4. Important points to remember/4.1. Hooks checklist habits mentors insist on.md>)).

### Common confusion (in candidates)

- **"LIFO means last flag wins"** — links don't compete (nesting, not contest): every link runs unless short-circuited upstream. "Wins" talk reveals memorized vocabulary without the model — probe with "which links run in the working order?" (all of them: mapper maps, ts-node compiles, default loads).
- **"programmatic registration avoids this"** — same LIFO rule (`register()` order nests identically) — candidates claiming escape reveal they never composed programmatically. One rule, all forms ([1.2](<../1. Hook pipeline/1.2. register versus loader flags versus registerHooks.md>)).

### Performance note

Order has zero performance content (same links, same work) — candidates mentioning speed here are filling air. The priced dimension is diagnostic misdirection (package-blaming for sequence causes) and its prevention (one comment). Say exactly that; stop.

### Mentor note

Run the swap live in mocks: both arrangements, predictions demanded before each ("trace? output?"). Mentees graduate when both predictions land two sessions running — derived LIFO survives pressure; memorized LIFO gets "tidied" under it. The exercise doubles as the onboarding order lesson.

## 3) "`register()` vs `registerHooks()`" — which and why (plus rapid-fire)

### 3) **Definition** (the family-choice screen)

Two hook families — async loader-thread `register()` vs sync in-thread `registerHooks()` — screens for platform currency plus constraint reasoning: hires state availability (async ≤ everywhere; sync ≥22.15/23.5), the thread tax (globals, CJS gaps, message ports), the deprecation (Stability 0, DEP0205 in v26), and the decision rule (sync-first with async fallback, logic shared, floor-detected).

### What problem it solves (hiring signal)

The platform is mid-migration (deprecation warnings accumulating on new floors, ecosystem still async) — teams need engineers who write code correct on *both* sides of the transition, not partisans of either family. The answer predicts migration competence: feature-detect, branch registration, share logic, ticket the fallback's removal.

### Modern guidance

As of September 2026: new hooks `registerHooks()`-first (sync, deregisterable, testable as functions) with async fallback below floor 22.15; hook *logic* family-agnostic (match/map/transform pure functions shared); fallback removal ticketed per Node floor (`// remove when floor ≥ 22.15`); ts-node/esm's async nature accepted as ecosystem reality (compose around it — mapper first). Floor check quoted from memory: `registerHooks: undefined | register: function` on v20 (verified); both functions on modern floors.

### Runnable example (good — the floor check as the answer's evidence)

```bash
node -e "const m = require('node:module'); console.log('registerHooks:', typeof m.registerHooks, '| register:', typeof m.register)"
# registerHooks: undefined | register: function   (Node v20.20.2 — async only)
```

Candidates who run (or quote) the floor check before choosing demonstrate the decision procedure, not just the decision. The sync branch itself: written against documented contract, honestly labeled unverifiable-below-floor, re-verified on migration ([1.2](<../1. Hook pipeline/1.2. register versus loader flags versus registerHooks.md>) part 3 models the honesty).

### Rapid-fire drills (with answers)

1. **`ERR_LOADER_CHAIN_INCOMPLETE` — cause and fix?** Returned without `nextX` or `shortCircuit` — add the flag (meant it) or delegate (didn't) ([2.1](<../2. Custom hooks/2.1. Authoring a resolve hook.md>)).
2. **Load transform silently no-ops — first suspicion?** Source shape (Buffer, not string — decode-first; diagnostic: log constructor) ([2.2](<../2. Custom hooks/2.2. Authoring a load hook.md>)).
3. **Hook file imports app modules — verdict?** Topology bug (chain-under-construction circularity) — self-contained hook files, `initialize` data for dynamics ([4.1](<../4. Important points to remember/4.1. Hooks checklist habits mentors insist on.md>)).
4. **Gate exits 30 vs 31 — meaning?** 30: trace absent (order/scope — mapper never saw it); 31: trace present, output wrong (mapping bug) ([4.1](<../4. Important points to remember/4.1. Hooks checklist habits mentors insist on.md>)).
5. **Stripping-era Node + custom resolve hook — compatible?** Resolve hooks compose with stripping (specifier mapping is runner-agnostic); *load* transforms of TS sources don't apply (nothing to compile — strip pipeline owns load). Stage-aware answer ([1.1](<../1. Hook pipeline/1.1. resolve and load the two-stage pipeline.md>)). Reasoned from stage architecture, not executed (no stripping-capable Node on this session's v20 floor — re-verify where stripping runs).
6. **ts-node transformer plugin vs load hook for decorator lowering — pick?** Transformer (AST-owned work — regex can't parse) — plus full mode required (no program in transpile-only) ([2.2](<../2. Custom hooks/2.2. Authoring a load hook.md>) part 3).

### Common confusion (in candidates)

- **"deprecated means I must migrate today"** — deprecated means warned-into-planning (warnings ∝ urgency; quarters, not panics). Candidates demanding immediate migration reveal anxiety governance; candidates with dated tickets reveal platform citizenship ([1.2](<../1. Hook pipeline/1.2. register versus loader flags versus registerHooks.md>) part 3).
- **"sync hooks fix CJS gaps automatically"** — they *can* (in-thread interception reaches `require()` paths) — but coverage must still be asserted by test (previously-bypassed children named explicitly). Capability cited without verification plan is half an answer.

### Performance note

Thread-tax removal (sync migration dividend) is microseconds × graph size — real but rarely dominant beside compilation. Candidates leading with migration-for-speed oversell; candidates pricing it as "correctness + testability first, microseconds second" calibrate correctly. Measure with boot profiles before/after; keep the printout.

### Mentor note

Timed rapid-fire (ten seconds each, autopsy misses against this domain): six-for-six is graduation — and the quarterly team health-check. Drill 5 separates stage-thinkers (resolve-composes/load-differs) from tool-thinkers; drill 4 separates gate-users from gate-tourists. Ask both first.
