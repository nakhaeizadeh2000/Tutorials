# 6.1. Boundaries: what is covered elsewhere

Where this domain stops and who owns the rest — the DRY map for workflow. Junior read: if your question isn't answered here, this page names the page that answers it. Expert read: the loop-vs-mechanism split that keeps primitives in exactly one place per question.

## 1) Restart primitives and runner mechanics (JS track owns the mechanism)

### 1) **Definition** (the loop/mechanism split)

*How watchers observe, how the inspector protocol works, how `node:test` discovers and reports, how `tsc --watch` scales* are mechanism knowledge — owned by neighboring tracks, assumed here, never restated. This domain owns ts-node *inside* those mechanisms: hook flags in watch commands, REPL operation, launch wiring, suite deltas. Mechanism questions go outward; composition questions stay here.

### The assignments (with the exact targets)

- Watch/REPL/version primitives (`node --watch`, interactive REPL, version discipline) → [JS 01/3.2. Node.js essentials](<../../../../JavaScript/01 Fundamentals and Mental Model/sections/3. Running JavaScript today/3.2. Node.js essentials running files REPL and version discipline.md>). [1.1](<../1. Watch and restart/1.1. Watch mode that restarts right.md>) composes the hook onto these primitives; the primitives live there.
- Inspector/breakpoint/sourcemap mechanics → [JS 15/5.3. Source maps workflow](<../../../../JavaScript/15 Error Handling and Debugging/sections/5. Debugging toolkit/5.3. Source maps Node inspector DevTools workflow and flags.md>). [2.2](<../2. REPL and editors/2.2. Editor and debugger integration.md>) wires entries to the protocol; the protocol lives there.
- Test runner mechanics (`describe`/`it`/mocks/coverage) → [JS 20: Testing Essentials](<../../../../JavaScript/20 Testing and Tooling Essentials/README.md>). [3.1](<../3. Test wiring/3.1. Test runners executing TypeScript.md>) executes suites through the hook; the runner lives there.
- Watch/incremental/build modes (`tsc --watch`, `--incremental`, `-b`) → [TS 19: Performance and Scaling](<../../../../TypeScript/19 Performance Project References and Scaling/README.md>). This domain runs the *execution* loop; the *checking* loop's modes live there.
- Execution foundations (modes, doors, clocks) → [01 Execution Foundations](<../../../01 Execution Foundations and Mental Model/README.md>) (this track). Every loop command in this domain assumes all of it.

### Common confusion

- **"this domain should explain node:test"** — explaining it here duplicates JS 20 in a second place, and duplicates drift (runner flags move yearly; the copy wouldn't). One-line mention plus link is the policy — DRY is correctness, not tidiness.
- **"composition without mechanics is shallow"** — composition is where workflow lives: the same primitives composed six ways produce six different loops, and choosing among them (restarter rule, wiring trace, gate stages) is deeper than any flag reference. Depth here is measured in decisions, not definitions.

### Mentor note

Teach mentees to read this page as a router: "mechanism" questions go outward (JS 20/15/01, TS 19), "composition" questions stay here. The distinction resolves half of all workflow debates before they start — most are mechanism-questions asked in composition-rooms ("how does --watch work?" during a "which restarter?" decision), or the reverse.

## 3) Config and hook mechanics (neighbor domains own the ends)

### 3) **Definition** (the loop-around boundary)

Loops wrap *configured hooks* (Domains 01–02: modes, doors, scopes, pairs) executing through *composed loaders* (Domain 03: doors, order, recipes). This domain owns neither end — it owns the repetition: restarting, re-probing, re-running, re-wiring. Questions about what repeats go here; questions about what's repeated go to 01–03.

### The assignments (with the exact targets)

- Modes, doors, clocks, gates → [01 Execution Foundations](<../../../01 Execution Foundations and Mental Model/README.md>). Every loop command here assumes transpile-only-by-default and the three clocks; their construction lives there.
- Config architecture, scoping, pairs, bridges → [02 Configuration](<../../../02 Configuration and tsconfig for Execution/README.md>). Loop commands consume scoped pairs; pair construction lives there.
- Hook doors, order, recipes → [03 Loader Hooks](<../../../03 ESM CJS and Loader Hooks Deep Dive/README.md>). Watch/test/debug commands compose loader flags; flag-order rules live there.

### Common confusion

- **"a loop bug is a hook bug"** — loops fail in restart vocabulary (no bounce, stale output, watcher silence); hooks fail in chain vocabulary (`ERR_LOADER_CHAIN_INCOMPLETE`, missing traces, order throws). Debug the loop first (rite: edit → bounce?), the hook second (trace present?) — the layer that failed names the half, per the stage-ordering habit from [03/1.1](<../../../03 ESM CJS and Loader Hooks Deep Dive/sections/1. Hook pipeline/1.1. resolve and load the two-stage pipeline.md>).
- **"this track replaces the JavaScript track"** — it assumes it (declared in every domain's `## 0. Prerequisites`). Loops customize runners the JS track owns; understanding runners precedes looping them — readers without `node --watch`/`node:test` basics read JS 01/20 first.

### Mentor note

The one-sentence router for workflow: "Mechanism questions go outward (JS/TS tracks), configured-hook questions go back (01–03), *repetition* questions stay here." Watch/REPL/wire/suite — the loop layer with its own craft, its own checklist, its own interview.
