# 3.1. One request, every layer

Tracing one unit of work cradle to grave through every TS-execution layer — flags to hook to config to loader to compile to execute to map to log — with budgets per layer and cold narration. Junior read: follow the request, name each layer. Expert read: where budgets bind layers together, and why narration skill predicts incident skill.

## 1) Trace cradle to grave

### 1) **Definition** (the full-passage inventory)

One request (or one boot, one test, one deploy — any unit of work) inventoried per layer it traverses: invocation flags (which doors opened) → hook registration (which links installed) → config resolution (which file won) → loader chain (resolve order, compile) → execution (artifact or hook, mode) → maps (trace attribution) → logs/profiles (evidence landed). Each layer named with its owning domain (01–06); no layer skipped, none hand-waved.

### What problem it solves (history)

Layer-blind debugging (tuning flags for map failures, re-reading configs for loader-order breaks, profiling for typos) wasted incidents layer-hopping at random — every layer *can* explain any symptom vaguely, so undisciplined triage picks familiar layers over indicted ones. The cradle-to-grave trace disciplines passage thinking: evidence per layer, in traversal order, skipping none — the indicted layer identified by elimination, not familiarity.

### Modern guidance

Trace per incident (write the layer list before theorizing — seven lines, two minutes); trace per design (new services narrate their request path in the design doc — layers named, owners linked); trace per interview (cold narration — part 3's skill, rehearsed here). Layer lists live beside triage ([05/3.1](<../../../05 Debugging Sourcemaps and Profiling TypeScript/sections/3. Production triage/3.1. Triage order for TS services.md>)'s order is the trace compressed to three stages).

### Runnable example (good — the boot trace, budgeted, verified shape)

```bash
node -e "
const spans=[['flag/hook',12],['config/resolve',3],['loader/compile',38],['execute',4],['map/log',2]];
const total=spans.reduce((a,s)=>a+s[1],0);
for (const [n,ms] of spans) console.log(n+':', ms+'ms');
console.log('total:', total+'ms', '| slowest:', spans.reduce((a,b)=>a[1]>b[1]?a:b)[0]);"
# flag/hook: 12ms
# config/resolve: 3ms
# loader/compile: 38ms
# execute: 4ms
# map/log: 2ms
# total: 59ms | slowest: loader/compile
```

Verified this session (illustrative budgets on the probe tree — shape, not benchmark): compile dominates the boot passage (38/59ms — the ladder's verdict in trace form), flags/config/maps cost single digits. The trace's value isn't the numbers (per-tree) but the *inventory* (per-incident): slowest layer named first, optimization aimed once.

### Common confusion

- **"tracing means distributed tracing"** — distributed tracing (spans across services — OpenTelemetry, Jaeger) tracks *requests across systems*; this trace tracks *work through layers* (flags to logs within one process). Complementary instruments (request journey vs layer passage); different questions (where slow across services? vs which layer misbehaves here?). Both, never either/or — the layer trace locates, the distributed trace correlates.
- **"one trace covers all failures"** — traces cover *passages* (boot, request, test, deploy — each with its layer list); failures select passages (boot failure → boot trace; request failure → request trace). Wrong-passage traces mislead (request layers blamed for boot-config faults). Match the trace to the failing unit of work first — passage selection precedes layer analysis.

### Performance note

Trace-inventory cost per incident: minutes (seven lines) against layer-hopping hours (familiar-layer bias per responder). Budgeted traces compound (per-layer numbers accumulate into capacity math — [1.2](<../1. Production judgment/1.2. Capacity and graceful degradation.md>) part 1 consumes them). Inventory is triage performance wearing a documentation costume.

### Mentor note

Whiteboard the trace cold with mentees (no notes, seven layers, owners named): hesitation points reveal knowledge gaps precisely (stumble at loader order → re-teach [03/1.1](<../../../03 ESM CJS and Loader Hooks Deep Dive/sections/1. Hook pipeline/1.1. resolve and load the two-stage pipeline.md>); stumble at maps → [05/1.1](<../../../05 Debugging Sourcemaps and Profiling TypeScript/sections/1. Sourcemaps/1.1. Sourcemaps under ts-node.md>)). The whiteboard is a diagnostic instrument for the engineer, not just the system.

## 2) Budgets per layer

### 2) **Definition** (time and bytes accounted)

Each layer carries a budget: cold-boot seconds (artifact vs hook — measured), per-request ms (route handlers — profiled), memory per layer (RSS deltas — snapshotted), map bytes (artifacts — inventoried), gate seconds (pipeline stages — timed). Totals reconcile (sum of layers ≈ observed — unaccounted remainder is the next investigation, never rounding error). Budgets live in ADRs ([1.1](<../1. Production judgment/1.1. Selecting architectures under constraints.md>) part 3); violations page with the layer named.

### What problem it solves (history)

Unbudgeted layers hid regressions (compile creep per dependency added, map bytes doubling per emit change, gate stages slowing per test added — each invisible until the total broke an SLO with no attributable cause). Per-layer budgets convert total-breaks into layer-breaks (which budget blew? — named owner, named fix, measured receipt). Attribution precedes optimization, always.

### Modern guidance

Budget the passage, not just the request (boot, test suite, pipeline, deploy — every repeated unit of work gets per-layer numbers); reconcile totals per quarter (sum vs observed — drift investigated, budgets refreshed); alarm per layer (thresholds at 80% — pages name layers, responders arrive oriented). Budget reviews ride release trains (numbers refreshed with traffic deltas — stale budgets mislead like stale maps).

### Runnable example (good — reconciliation, verified arithmetic)

```bash
# from the trace above: 12+3+38+4+2 = 59ms accounted; wall-clock boot measured 61ms
# remainder: 2ms (3% — runtime noise, not a hidden layer). Reconciled: totals agree.
# anti-example: wall-clock 400ms vs 59ms accounted → 341ms unaccounted = the investigation
# (profiler on boot, per [05/2.2] — hidden layer found, budgeted, owned).
```

### Common confusion

- **"budgets constrain optimization"** — budgets *direct* it (slowest budgeted layer optimized first — guaranteed highest ROI; unbudgeted optimization wanders). Constraint enables focus: the budget names the target, the profile confirms, the fix lands measured. Unfocused optimization polishes fast layers while slow ones bill.
- **"byte budgets are premature"** — byte budgets gate transfers (image layers, map files, declaration packs — registry/deploy costs scale linearly with bytes). Premature for prototypes (unmeasured, unshipped); mandatory for production (measured, shipped, billed per byte per deploy). Budget at the shipping boundary ([06/2.1](<../../../06 Shipping Builds Dist and Containers/sections/2. Dist and containers/2.1. dist layout that deploys.md>)'s minimal set is a byte budget in disguise).

### Performance note

Budgeting costs measurement sessions (profiled runs per layer — the [05/2.2](<../../../05 Debugging Sourcemaps and Profiling TypeScript/sections/2. Inspector and profiles/2.2. CPU and memory profiles of TS services.md>) discipline, applied per layer) against unbudgeted drift (slow creep discovered at SLO breach — quarters of незаметное slowing, one painful reckoning). Budgets are performance memory — teams with them improve monotonically; teams without oscillate.

### Mentor note

Assign budget ownership per layer (boot→shipping team, request→service team, gates→platform team — named humans, not "the team"): owners measure, alarm, and defend their numbers in reviews. Ownership converts abstract budgets into defended territory — unowned budgets rot (nobody re-measures, nobody alarms, everybody assumes).

## 3) Narrate it cold

### 3) **Definition** (narration as mastery proof)

Whiteboard the full passage — flags to logs, seven layers, owners and budgets named — from memory, aloud, in five minutes, fielding interruptions ("what if the map drops here?" — answered with the drop-point diagnosis, not deflection). Cold narration proves compiled judgment: knowledge retrievable under pressure, organized by traversal, priced per layer. Interviewers hire narrators; incidents obey them.

### What problem it solves (history)

Reference-dependent engineers (fluent with docs open, helpless paged) bottleneck incidents on search speed (grep the runbook while the system burns — minutes lost per lookup, confidence draining per pause). Narrators carry the model internally (layers ordered, owners known, budgets approximate — precise enough to act, honest about approximations). Incidents need actors with models, not readers with bookmarks.

### Modern guidance

Rehearse monthly (five-minute whiteboard, peer-interrupted — the [5.1](<../5. Interview questions and answers/5.1. Common interview QA judgment synthesis.md>) drill doubles as incident training); narrate per incident (timeline spoken in layer terms — responders synchronize on shared vocabulary); teach per quarter (narrate to juniors — transfer proves retention, per [4.1](<../4. Important points to remember/4.1. Mastery checklist habits mentors insist on.md>) part 3).

### Runnable example (good — the narration outline, memorizable)

```markdown
# cold narration (seven beats, five minutes):
# 1. flags open doors (CLI/-r/loader — [01/1.2])
# 2. config wins per entry (walk + pins — [02/1.2])
# 3. loaders chain LIFO, mapper first ([03/1.1])
# 4. modes split clocks (transpile-only loop, tsc gates — [01/2.1])
# 5. loops repeat (watch/test/debug — [04])
# 6. maps name sources (traces/profiles attributed — [05/1.1])
# 7. artifacts ship (dist + maps + smoke — [06])
# interruptions welcome — each beat routes to its domain on demand.
```

### Common confusion

- **"narration is performance, not skill"** — narration *demonstrates* compiled judgment (retrieval under pressure with organization intact — the closest observable to incident competence). Memorized scripts shatter on interruption (first "what if" breaks them); modeled understanding routes (every interruption answered from structure). Interviewers interrupt deliberately — they're testing the model, not the recitation.
- **"diagrams replace narration"** — diagrams aid narration (drawn *while* speaking — evidence of generation, not recall); pre-made diagrams substitute poorly (pointing at boxes isn't traversing layers — passive orientation, not active command). Draw live, narrate live, invite interruption — the live trio proves ownership.

### Performance note

Narration practice costs five minutes monthly per engineer (whiteboard + peer) against incident command quality (narrators direct multi-responder incidents coherently — shared vocabulary, ordered stages, no duplicated work). Teams that narrate resolve faster with fewer responders — narration is organizational performance (parallel machine, orchestrated by voice).

### Mentor note

The narration gauntlet graduates seniors (five minutes, three interruptions, all routed — pass/fail with feedback, retake monthly): ceremony creates the skill (deadline + audience + interruption pressure simulate incidents safely). Celebrate first passes publicly (narrator status is team infrastructure — recognize it as such). Re-gauntlet yearly (models decay — refresh or retire).
