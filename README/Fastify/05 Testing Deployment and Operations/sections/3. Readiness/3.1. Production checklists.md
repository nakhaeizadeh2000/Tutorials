# 3.1. Production checklists

## 1. Checklists gate releases (tests proving — config gating — probes answering)

**Definition** — the release gate: three proofs blocking every deploy ([1.1 inject suites](<../../sections/1. Tests/1.1. Handler tests via inject.md>)/[2.1 boot gates](<../../sections/2. Delivery/2.1. Config gating at deploy.md>)/[2.2 probes](<../../sections/2. Delivery/2.2. Graceful shutdown and probes.md>)) — tests proving (suites executing — contracts asserting (regressions catching — merges blocking (quality defending — evidence owning); config gating (schemas declaring — boot crashing (bad serving never — rollouts blocking (correctness starting — chaos preventing); probes answering (live cheaping — ready deeping (verdicts acting — traffic gating (health evidencing — orchestration trusting). Releases gating (tests proving — config gating (probes answering — quality defending).

**What problem it solves** — the ungated-release trio: *tests hoping* (suites missing — contracts unproving (regressions shipping — confidence feigning (coverage theatering — quality assuming (evidence absenting — trust eroding); *config gambling* (env unvalidating — boot hoping (bad serving — rollbacks scrambling (correctness assuming — chaos scheduling (gates absenting — merges unblocking); *probes merging* (endpoints lying — verdicts confusing (traffic misrouting — restarts looping (depth missing — truth hiding (checks theatering — automation flailing). Gated checklists converting hoping to blocking (tests proving — config gating (probes answering — releases guarding); reviewers checking gate evidence, not confidence (proof dating → verifiable; assuming → returned).

**Modern guidance** — the gate lines per release (review-enforced): *tests proving* (suites executing — contracts asserting (regressions catching — merges blocking (quality defending — evidence owning (behavior proving — confidence building); *config gating* (schemas declaring — boot crashing (bad serving never — rollouts blocking (correctness starting — chaos preventing (validation owning — degradation declining); *probes answering* (live cheaping — ready deeping (verdicts acting — traffic gating (health evidencing — orchestration trusting (verdicts proving — automation deciding).

```javascript
// GOOD: releases gating — tests proving, config gating, probes answering (release evidence, dated).
// "node --test: 42 pass, 0 fail (suites executing — contracts asserting — regressions catching, merges blocking)."
// "Boot gate: DATABASE_URL/PORT proven (schemas declaring — boot crashing — bad serving never, rollouts blocking)."
// "Probes: /live 200 + /ready 200 pre-traffic (live cheaping — ready deeping — verdicts acting, traffic gating)."
// BAD: releases hoping — tests missing, config gambling, probes merging (real outage shape).
// Deploy on green vibes (suites missing — contracts unproving — regressions shipping (confidence feigning — trust eroding).
// Unvalidated env to prod (boot hoping — bad serving — rollbacks scrambling). Gate releases; date evidence.)
```

**Common confusion** — *"checklists slow shipping (gates taxing velocity)."* Gates costing minutes (suites executing — schemas proving (evidence dating — releases guarding (quality defending — confidence building); outages costing quarters (regressions shipping — bad serving — traffic misrouting (rollbacks scrambling — users churning (trust eroding — revenue dipping); velocity needing safety (gates guarding — confidence funding (shipping sustaining — speed compounding (discipline proving — trust earning). "Slowing" describing theater gates (checks performing — evidence missing); release gates describing proof (tests proving — config gating). Gate releases (minutes spending — quarters saving); date evidence (proof owning — confidence building).

**Performance note** — gate economics: proving costing suite minutes (tests executing — contracts asserting (regressions catching — merges blocking); gating costing boot seconds (schemas declaring — boot crashing (bad serving never — rollouts blocking); answering costing probe calls (live cheaping — ready deeping (verdicts acting — traffic gating); hoped equivalents costing outages (regressions shipping — rollbacks scrambling). Spend minutes (suites — gates); save quarters (outages — churn).

**Mentor note** — teach "prove, gate, answer — every release" (juniors gating per release design evidence-dated deploys on first hearing; vibe-deploys interrogated ("evidence dated when?" — gates demanding per release). Gate one release once (tests proving — config gating tangible (outages preventing — hope ending permanently). Prove tests; gate config — release discipline in three habits, reviewed per deploy.

**What problem it solves** — the unrehearsed trio: *recovery fictional* (backups existing — restores never running (corruption hiding — honesty absenting — incidents discovering (failures mid-outage — recovery hoping (procedures unowned — panic directing); *failovers theoretical* (promotions never observing — succession hoping (automation assuming — toil hiding (elections untesting — recovery unproving (evidence missing — confidence feigning); *kills surprising* (SIGTERM never testing — drains hoping (losses unbounding — totals unverifying (honesty claiming — evidence absenting (calibration unproving — confidence hoping). **Modern guidance** — the drill lines per quarter (review-enforced): *kills measuring* (SIGTERM testing — drains verifying (losses bounding — totals proving (honesty earning — hope ending (discipline owning — confidence building (practice pricing — improvisation declining); *failovers observing* (primaries dying — replicas promoting (succession timing — automation proving (elections realing — evidence freshing (recovery completing — panic ending (toil absenting — succession directing); *restores timing* (backups loading — procedures owning (incidents executable — practice pricing (improvisation declining — recovery proving (times budgeting — availability pricing).

## 3. Ownership names humans (responders designating — pages routing, never hoping)

**Definition** — the ownership line: every release naming its responders (responders designating (humans owning — services mapping (pages routing — incidents directing (accountability owning — diffusion ending (bystanders declining — action starting); pages routing (alerts directing — owners waking (responses timing — escalations ordering (severity owning — noise declining (signal proving — fatigue ending); hoping ending (owners named — procedures written (drills dated — evidence fresh (confidence grounding — panic declining). Releases owning (responders designating — pages routing (hoping ending — accountability owning).

**What problem it solves** — the ownerless trio: *responders hoping* (teams assuming — humans unnamed (pages broadcasting — action diffusing (bystanders watching — incidents lingering (ownership missing — accountability absenting (response slowing — damage growing); *pages misrouting* (alerts spamming — owners missing (fatigue building — signals drowning (noise growing — response dying (severity unowning — escalation breaking); *handoffs dropping* (shifts changing — context losing (incidents relearning — procedures restarting (knowledge walking — continuity breaking (ownership transferring never — accountability gaping). Named ownership converting diffusion to direction (responders designating — pages routing (hoping ending — action starting); reviewers checking responder names, not team vibes (ownership proving → verifiable; hoping → returned).

**Modern guidance** — the ownership lines per service (review-enforced): *responders designating* (humans owning — services mapping (pages routing — incidents directing (accountability owning — diffusion ending (bystanders declining — action starting (ownership proving — response quickening); *pages routing* (alerts directing — owners waking (responses timing — escalations ordering (severity owning — noise declining (signal proving — fatigue ending (routing owning — attention spending); *hoping ending* (owners named — procedures written (drills dated — evidence fresh (confidence grounding — panic declining (discipline proving — trust earning).

```javascript
// GOOD: ownership naming — responders designating, pages routing, hoping ending (names, not vibes).
// "Service payments: responder @sara, backup @reza (humans owning — services mapping — pages routing, incidents directing)."
// "Severity routing: SEV1 pages responder, SEV3 files ticket (alerts directing — owners waking — escalations ordering)."
// "Handoff: shift log names next owner (context keeping — continuity holding — accountability gapless)."
// BAD: ownership hoping — responders assuming, pages misrouting, handoffs dropping (real 3am page-storm shape).
// "Team owns it" unnamed (humans missing — pages broadcasting — action diffusing (bystanders watching — incidents lingering).
// Alerts to all (signals drowning — fatigue building — response dying). Name humans; route pages.)
```

**Common confusion** — *"ownership blames humans (accountability punishing)."* Ownership directing response (humans owning — pages routing (action starting — incidents directing (accountability owning — diffusion ending); blame punishing outcomes (humans faulting — learning stopping (fear growing — honesty dying (culture rotting — incidents hiding); blameless owning systems (procedures fixing — drills dating (evidence stacking — learning compounding (culture healing — honesty funding). "Blaming" describing punishment (fault finding — honesty dying); ownership describing direction (pages routing — action starting). Name responders (direction owning — diffusion ending); fix systems (procedures owning — learning compounding).

**Performance note** — ownership economics: designating costing names (humans owning — services mapping (pages routing — incidents directing); routing costing severity rules (alerts directing — owners waking (responses timing — escalations ordering); hoped equivalents costing lingering incidents (bystanders watching — damage growing (response slowing — accountability absenting). Name cheaply (humans — services); route always (pages — severity).

**Mentor note** — teach "name, route, handoff — every service" (juniors owning per service design responder-named operations on first hearing; team-vibe ownership interrogated ("who wakes?" — names demanding per service). Name one responder once (humans owning — pages routing tangible (diffusion ending — action starting permanently). Designate humans; route pages — ownership discipline in three habits, reviewed per service.
