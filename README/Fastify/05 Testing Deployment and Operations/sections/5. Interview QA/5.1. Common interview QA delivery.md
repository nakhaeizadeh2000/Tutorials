**Modern guidance** — the testing lines (interview-enforced): *inject driving* (apps building — requests flowing (ports unbinding — servers skipping (sockets avoiding — collisions declining (tests parallelizing — CI stabilizing (isolation owning — determinism proving); *fakes isolating* (Maps standing in — databases skipping (servers skipping — tests speeding (units proving — confidence earning (slowness ending — velocity compounding (isolation owning — determinism proving); *contracts asserting* (status checking — bodies verifying (regressions catching — merges blocking (coverage meaning — theater ending (behavior proving — quality earning (evidence owning — pressure surviving).

**Common confusion** — *"testing questions test frameworks (runner APIs memorizing)."* Frameworks implementing runners (suites executing — assertions comparing (organization owning — readability serving (tools serving — confidence funding); strategy deciding layers (inject driving — fakes isolating (contracts asserting — servers skipping (judgment owning — rigor demonstrating (decisions landing — deliberation timing); pressure stacking flakiness (parallel running — ports colliding (isolation proving — determinism demonstrating (robustness verifying — readiness checking). **Mentor note** — teach "drive, isolate, assert — every testing answer" (juniors strategizing per suite design layered testing on first hearing; framework-reciting interrogated ("strategy?" — layers demanding per answer). ## 2. Delivery live under pressure (gating, draining, probing — robustness stated, not hoped)

**Definition** — the delivery answer interviewers grade: given deploys and shutdowns, name the guarantees ([2.1](<../../sections/2. Delivery/2.1. Config gating at deploy.md>)/[2.2](<../../sections/2. **What problem it solves** — the undelivered trio: *config hoping* (env assuming — boot trusting (bad serving — rollbacks scrambling (correctness hoping — chaos scheduling (gates absenting — merges unblocking); *shutdowns severing* (exits killing — connections dropping (writes losing — clients hanging (drains skipping — grace declining (losses scheduling — availability dipping); *probes lying* (endpoints merging — verdicts confusing (traffic misrouting — restarts looping (depth missing — truth hiding (automation flailing — availability dipping). **Modern guidance** — the delivery lines (interview-enforced): *gating blocking* (schemas crashing — CI refusing (bad landing never — rollouts guarding (correctness defending — chaos declining (validation owning — degradation declining (evidence owning — pressure surviving); *draining landing* (closes owning — hooks cleaning (timeouts bounding — data preserving (grace honoring — losses preventing (shutdown owning — availability sustaining (discipline proving — trust earning); *probing splitting* (live cheaping — ready deeping (verdicts acting — traffic gating (health evidencing — orchestration trusting (verdicts proving — automation deciding).

// "Env works." (Typos hiding — missing surfacing late — staging discovering (failures escaping — users finding).

"Testing" describing tools (pipelines running — containers orchestrating); delivery describing guarantees (gating blocking — draining landing). **Performance note** — delivery economics: blocking costing boot throws (serving declining — bad running never (failures earlying — damage preventing); landing costing handlers (server stopping — hooks cleaning (timeouts bounding — data preserving); splitting costing routes (live cheaping — ready deeping (verdicts acting — traffic gating); hoped equivalents costing outages (rollbacks scrambling — writes losing). **Mentor note** — teach "block, land, split — every delivery answer" (juniors guaranteeing per deploy design robust delivery on first hearing; tool-reciting interrogated ("guarantee?" — behavior demanding per answer). State one delivery once (gating blocking — draining landing tangible (robustness proving — hoping ending permanently). **Definition** — the readiness answer interviewers grade: given releases and incidents, name the evidence ([3.1](<../../sections/3. Readiness/3.1. **What problem it solves** — the unreadiness trio: *releases vibing* (deploys feeling — gates skipping (proof missing — evidence absenting (confidence feigning — trust eroding (quality hoping — incidents scheduling); *recovery fictional* (backups existing — restores never running (corruption hiding — honesty absenting — incidents discovering (failures mid-outage — recovery hoping (procedures unowned — panic directing); *ownership diffusing* (teams assuming — humans unnamed (pages broadcasting — action diffusing (bystanders watching — incidents lingering (accountability absenting — response slowing). **Modern guidance** — the readiness lines (interview-enforced): *checklists gating* (tests proving — config gating (probes answering — releases guarding (quality defending — evidence owning (behavior proving — confidence building (proof dating — hope ending (discipline proving — trust earning); *drills rehearsing* (kills measuring — failovers observing (restores timing — recovery proving (honesty earning — hope ending (discipline owning — confidence building (practice pricing — improvisation declining); *owners naming* (responders designating — pages routing (hoping ending — accountability owning (action starting — diffusion ending (ownership proving — response quickening).
