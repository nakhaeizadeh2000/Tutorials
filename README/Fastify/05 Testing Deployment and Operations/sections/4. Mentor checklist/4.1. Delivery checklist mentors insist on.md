## 1. Every handler tests headless (inject/mocks proving — servers skipping, never binding)

**Definition** — the headless line on every handler: tests proving without listening ([1.1](<../../sections/1. Tests/1.1. **What problem it solves** — the bound-test trio: *servers per suite* (listens binding — ports colliding (suites flaking — parallel failing (setup heavying — feedback slowing (isolation missing — determinism hoping); *logic unproving* (handlers untesting — branches uncovering (regressions shipping — confidence hoping (coverage missing — quality assuming (evidence absenting — trust eroding); *contracts hoping* (assertions missing — statuses unchecking (bodies unshaping — regressions merging (coverage theatering — quality feigning (discipline absenting — merges unblocking). Headless tests converting binds to proof (inject driving — mocks isolating (contracts asserting — servers skipping); reviewers checking headless suites, not ports (testing proving → verifiable; binding → returned).

**Modern guidance** — the headless lines per handler (review-enforced): *inject driving* (apps building — requests flowing (ports unbinding — servers skipping (sockets avoiding — collisions declining (tests parallelizing — CI stabilizing (isolation owning — determinism proving); *mocks isolating* (services faking — units proving (servers skipping — tests running (deps unimporting — suites executing (inputs controlling — outputs predicting (logic proving — confidence earning); *contracts asserting* (status checking — bodies verifying (regressions catching — merges blocking (coverage meaning — theater ending (behavior proving — quality earning).

// fastify.inject({ method: 'GET', url: '/x' }).then(r => assert(r.statusCode === 200)) (apps building — requests flowing — ports unbinding, servers skipping)
// makeUsers(new Map()) per suite (services faking — units proving — servers skipping, tests running)

**Common confusion** — *"headless tests miss integration (units insufficient)."* Units proving logic (inputs controlling — outputs predicting (branches covering — regressions catching (isolation owning — speed funding (confidence earning — feedback quickening); integration proving composition (inject asserting — contracts verifying (drift detecting — wholes proving (layers stacking — confidence completing (reality checking — units composing); headless covering both (mocks isolating — inject driving (servers skipping — ports freeing (proof composing — hope ending (discipline doubling — quality compounding). **Mentor note** — teach "no listen in tests — ever" (juniors testing per handler design headless suites on first hearing; listen-calling suites interrogated ("which port in parallel?" — headless demanding per suite). Headless one suite once (listen deleting — inject asserting tangible (flakes ending — speed compounding permanently). ## 2. Every deploy gates config (schemas crashing early — bad serving never, rollouts blocking)

**What problem it solves** — the ungated-deploy trio: *env hoping* (vars assuming — typos hiding (missing surfacing late — staging discovering (failures escaping — users finding (config trusting — verification skipping); *merges unblocking* (configs landing — gates absenting (bad shipping — staging discovering (quality hoping — evidence missing (proof partialing — trust capping); *rollouts gambling* (deploys shipping — gates skipping (bad serving — rollbacks scrambling (correctness assuming — chaos scheduling (procedures missing — panic directing). Gated deploys converting hoping to blocking (schemas crashing — CI blocking (rollouts guarding — damage preventing); reviewers checking gate evidence, not deploy speed (gating proving → verifiable; gambling → returned).

**Modern guidance** — the gate lines per deploy (review-enforced): *schemas crashing* (fields requiring — boot refusing (serving declining — bad running never (failures earlying — damage preventing (honesty owning — hope ending (correctness starting — chaos preventing); *CI blocking* (gates running — merges refusing (bad landing never — staging protecting (evidence owning — confidence building (proof completing — hope ending); *rollouts guarding* (deploys sequencing — predecessors dying (traffic shifting — procedures owning (releases protecting — users sparing (discipline enforcing — confidence earning).

**Performance note** — gate economics: crashing costing boot throws (serving declining — bad running never (failures earlying — damage preventing); blocking costing CI seconds (merges refusing — bad landing never (staging protecting — evidence owning); guarding saving rollbacks (releases protecting — users sparing (discipline enforcing — confidence earning); gambled equivalents costing incidents (staging discovering — rollbacks scrambling). **Mentor note** — teach "gate every deploy, especially hotfixes" (juniors gating per deploy design blocked-bad deploys on first hearing; bypassed gates interrogated ("who approved skip?" — gates demanding per deploy). Gate one deploy once (schemas crashing — CI blocking tangible (incidents preventing — gambling ending permanently). Crash boot; block merges — gate discipline in three habits, reviewed per deploy.

## 3. Every process drains (closes owning — probes answering — improvisation ending)

**Modern guidance** — the drain lines per process (review-enforced): *closes owning* (fastify.close stopping — accepts declining (sockets draining — in-flight landing (requests completing — data preserving (grace honoring — losses preventing (shutdown owning — availability sustaining (discipline proving — trust earning); *probes answering* (live cheaping — ready deeping (verdicts acting — traffic gating (health evidencing — orchestration trusting (automation deciding — availability defending (verdicts proving — confidence building); *improvisation ending* (procedures owning — drills dating (evidence stacking — panic declining (discipline proving — confidence building (ownership naming — responders designating (accountability owning — diffusion ending).
