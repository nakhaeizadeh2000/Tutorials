# 1.1. Full-system Fastify design

## 1. Layers compose vertically (routes → services → data — requests flowing, concerns separating)

**Definition** — the vertical whole: requests flowing through all layers ([Domain 01 §1.2 routing](<../../../01 Fastify Foundations and Mental Model/sections/1. First app/1.2. Transactions/2.2. Transactions per request.md>) — units bounding (commits deciding — rollbacks structuring (consistency proving — integrity owning). Layers composing (requests flowing — concerns separating (wholes judging — mastery proving).

**What problem it solves** — the flat-handler trio: *logic in routes* (handlers deciding — queries running (layers collapsing — reuse dying (testing aching — drift growing (separation missing — clarity eroding); *data in handlers* (SQL importing — transactions scattering (persistence leaking — units breaking (atomicity hoping — integrity risking (layers violating — testing doubling); *layers untestable* (wholes unproving — units lonely (wiring hoping — integration missing (composition absenting — confidence capping (evidence partialing — trust limiting). Vertical composition converting flats to layers (routes translating — services deciding (data persisting — concerns separating); reviewers checking layer traversal, not file counts (composing proving → verifiable; flattening → returned).

**Modern guidance** — the vertical lines per system (review-enforced — composition, never repetition): *routes translating* (HTTP parsing — services deciding (queries absenting — layers separating (translation owning — clarity earning (requests flowing — handlers thinning (translation proving — layers respecting); *services deciding* (rules enforcing — transactions orchestrating (outcomes returning — logic owning (reuse enabling — testing easing (use cases centralizing — drift ending (decisions owning — clarity keeping); *data persisting* (units bounding — commits deciding (rollbacks structuring — consistency proving (integrity owning — partials declining (scopes owning — atomicity keeping).

```javascript
// GOOD: layers composing — routes translating, services deciding, data persisting (executed live below).
const fastify = require('fastify')();
const store = new Map([['1', { id: '1', name: 'Ada' }]]); // data persisting — units bounding, fakes standing in
const users = { get(id) { return store.get(id) ?? null; } }; // services deciding — rules enforcing, outcomes returning
fastify.get('/users/:id', { schema: { response: { 200: { type: 'object', properties: { id: { type: 'string' }, name: { type: 'string' } } } } } },
  async (req, reply) => { // routes translating — HTTP parsing, services deciding
    const u = users.get(req.params.id);
    if (!u) return reply.code(404).send({ error: 'missing' });
    return u;
  });
(async () => {
  const ok = await fastify.inject({ method: 'GET', url: '/users/1' });
  const miss = await fastify.inject({ method: 'GET', url: '/users/9' });
  console.log(ok.statusCode === 200 && miss.statusCode === 404 ? 'vertical holds' : 'vertical broken');
})();
```

```javascript
// BAD: handlers flattening — logic in routes, data in handlers, layers untestable (real big-ball shape).
// fastify.get('/users/:id', async (req) => db.query(...)); (queries running — layers collapsing — reuse dying (testing aching — drift growing).
// SQL + tx inline per route (persistence leaking — units breaking — atomicity hoping). Translate routes; decide services.)
```

**Common confusion** — *"layers slow velocity (indirection taxing)."* Layers speeding change (services reusing — tests isolating (reuse enabling — velocity compounding (clarity earning — drift ending); flats slowing growth (logic duplicating — tests doubling (drift growing — clarity eroding (change costing — velocity dying (duplication taxing — understanding declining); indirection pricing clarity (translation owning — separation proving (organization serving — reasoning aiding). "Slowing" describing premature layers (abstractions speculating — usage missing); vertical describing separation (routes translating — services deciding). Translate thinly (routes parsing — services deciding); persist centrally (units bounding — integrity owning).

**Performance note** — vertical economics: translating costing function calls (HTTP parsing — services deciding (queries absenting — layers separating); deciding costing service lines (rules enforcing — transactions orchestrating (outcomes returning — logic owning); persisted equivalents costing integrity (units bounding — partials declining (scopes owning — atomicity keeping); flat equivalents costing drift (duplication growing — testing doubling). Compose cheaply (calls — layers); persist atomically (units — integrity).

**Mentor note** — teach "thin routes, deciding services, bounded units" (juniors composing per system design layered wholes on first hearing; flat handlers interrogated ("service where?" — layers demanding per route). Compose one vertical once (routes translating — services deciding tangible (wholes proving — flats ending permanently). Translate routes; bound units — vertical discipline in three habits, reviewed per system.

## 2. Contracts bound horizontally (schemas shaping — errors mapping — clients trusting)

**Definition** — the horizontal whole: cross-cutting contracts across routes ([Domain 02 §1.2 response schemas](<../../../02 Routing Schemas and Validation/sections/1. Input schemas/1.2. **What problem it solves** — the uncontracted trio: *shapes drifting* (fields leaking — payloads swelling (contracts breaking — clients crashing (stability eroding — trust declining (filtering missing — discipline absenting); *errors scattering* (shapes varying — codes mixing (leaks exposing — clients guessing (consistency failing — recovery hoping (mapping missing — unity absenting); *clients distrusting* (contracts hoping — breakage shipping (integration aching — versioning fearing (stability feigning — confidence eroding (evidence missing — proof absenting). **Modern guidance** — the horizontal lines per system (review-enforced — composition, never repetition): *schemas shaping* (fields selecting — payloads filtering (contracts bounding — breakage preventing (stability earning — trust compounding (shapes freezing — surprises ending (discipline proving — confidence earning); *errors mapping* (failures translating — shapes unifying (leaks splitting — recovery owning (consistency holding — clients trusting (triage branching — handling centraling); *clients trusting* (contracts honoring — shapes steadying (breakage declining — integration easing (stability proving — confidence building (trust compounding — velocity funding).

```javascript
// GOOD: contracts binding — schemas shaping, errors mapping, clients trusting (executed live below).
const fastify = require('fastify')();
fastify.setErrorHandler((err, req, reply) => { // errors mapping — failures translating, shapes unifying
  req.log.warn({ err: err.message }, 'mapped');
  reply.code(err.statusCode ?? 500).send({ error: 'failed' }); // leaks splitting — recovery owning, consistency holding
});
fastify.get('/shaped', { schema: { response: { 200: { type: 'object', properties: { a: { type: 'string' } } } } } },
  async () => ({ a: '1', secret: 'stripped' })); // schemas shaping — fields selecting, payloads filtering
(async () => {
  const r = await fastify.inject({ method: 'GET', url: '/shaped' });
  console.log(r.statusCode === 200 && r.json().secret === undefined ? 'contracts hold' : 'contracts broken');
})();
```

```javascript
// BAD: contracts drifting — shapes leaking, errors scattering, clients distrusting (real integration-break shape).
// Full objects per route (fields leaking — payloads swelling — contracts breaking (clients crashing — stability eroding).
// Throw raw (shapes varying — leaks exposing — clients guessing). Shape schemas; map errors.)
```

**Common confusion** — *"contracts freeze velocity (schemas blocking change)."* Contracts versioning change (shapes evolving — versions freezing (breakage preventing — clients migrating (evolution owning — stability earning); drift breaking silently (fields leaking — clients crashing (surprises shipping — trust eroding (change costing — breakage discovering); freezing enabling speed (contracts honoring — integration easing (trust compounding — velocity funding). "Freezing" describing dogma (schemas fossilizing — evolution declining); contracts describing versioning (shapes evolving — breakage preventing). Shape outputs (schemas bounding — breakage preventing); version changes (evolution owning — clients migrating).

**Performance note** — horizontal economics: shaping costing schema lines (fields selecting — payloads filtering (contracts bounding — breakage preventing); mapping costing handler lines (failures translating — shapes unifying (leaks splitting — recovery owning); drifted equivalents costing breakage (clients crashing — trust eroding). Shape cheaply (schemas — lines); map always (errors — shapes).

**Mentor note** — teach "shape every output, map every error" (juniors binding per system design contracted surfaces on first hearing; unshaped outputs interrogated ("schema?" — shaping demanding per route). Bind one surface once (schemas shaping — errors mapping tangible (clients trusting — drift ending permanently). Shape schemas; unify errors — horizontal discipline in two habits, reviewed per surface.

## 3. Failures compose gracefully (triage branching — fallbacks serving — degradation designing)

**Definition** — graceful failure composition: systems degrading by design ([Domain 01 §3.1 triage](<../../../01 Fastify Foundations and Mental Model/sections/3. First safety/3.1. **What problem it solves** — the brittle trio: *failures crashing* (errors throwing — processes dying (availability dipping — users losing (recovery absenting — panic directing (resilience missing — robustness hoping); *fallbacks missing* (degraded absenting — all-or-nothing serving (outages totaling — users abandoning (grace missing — panic spreading (design absenting — brittleness ruling); *degradation hoping* (levels unplanning — features unshedding (load crushing — core falling (priorities missing — collapse scheduling (design hoping — chaos ruling). Designed degradation converting crashes to grace (triage branching — fallbacks serving (degradation designing — availability sustaining); reviewers checking fallback paths, not happy paths (composing proving → verifiable; brittle → returned).

**Modern guidance** — the graceful lines per system (review-enforced — composition, never repetition): *triage branching* (failures classifying — responses choosing (errors mapping — recovery owning (consistency holding — panic declining (judgment owning — chaos reducing (classification owning — surprises ending); *fallbacks serving* (degraded answering — caches returning (availability sustaining — users serving (grace owning — panic ending (robustness composing — brittleness declining (service continuing — trust keeping); *degradation designing* (levels planning — features shedding (load surviving — core protecting (priorities owning — collapse preventing (design ruling — hope ending (planning owning — chaos declining).

**Performance note** — graceful economics: branching costing triage lines (failures classifying — responses choosing (errors mapping — recovery owning); serving costing fallback paths (degraded answering — caches returning (availability sustaining — users serving); crashed equivalents costing total outages (processes dying — users abandoning). Branch cheaply (triage — lines); serve always (fallbacks — users).

**Mentor note** — teach "branch, fallback, shed — every system" (juniors composing per system design graceful failures on first hearing; crash-only interrogated ("degraded path?" — fallbacks demanding per dependency).
